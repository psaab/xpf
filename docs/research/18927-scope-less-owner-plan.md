# #18927 child 2 — scope-less session imports and owner judgment

**Status:** DRAFT v2 — bounded-fix design for three-seat plan review; no production change in this commit.
**Base:** `origin/master` / assigned branch base `6c27f54cf24107758d522e4b2d7203bea9f32f92` (2026-11-05).
**Self-assessment:** **PLAN-READY** for the three plan seats. The bounded fix separates the provable, scope-invariant empty-rule case from genuinely ambiguous ingress cases; it does not infer a missing scope.

## Decision

Recommend a bounded fix, not PLAN-KILL. Preserve #15176 for ambiguous rows, but do not preserve a dynamic source-NAT translation when the owner can prove that **the live dynamic source-NAT rule list is empty**. An empty list cannot authorize the stored translation under any ingress interface, routing instance, or historical logical unit. This is the only candidate-invariant rule chosen for child 2; do not infer a rule withdrawal from evaluating an identity-less row against an invented empty scope.

The deliberate #15176 decline is in `userspace-dp/src/afxdp/poll_descriptor/policy_revalidation.rs:1523-1549`: `scope_dependent && identity_absent && nat_scope_ifindex.is_none()` returns `None` before source-NAT rule inspection. It is pinned by `imported_scopeless_snat_kept_without_recorded_scope_15176` (`policy_revalidation_tests.rs:5757-5765`) and the identity-less VLAN control `imported_reth_vlan_scopeless_kept_16826` (`:8404-8466`). The rule matcher scans live rules in order and returns false when none match (`userspace-dp/src/nat/source/mod.rs:1711-1831`); with an empty slice the result is false for every possible scope. The direct policy hit nevertheless declines at `:1547-1549` before reaching that proof.

### Exact proposed rule and placement

Implementation files for the policy change are `userspace-dp/src/afxdp/poll_descriptor/policy_revalidation.rs` and `userspace-dp/src/afxdp/poll_descriptor/policy_revalidation_tests.rs`. The source-NAT matcher and wire format need no change.

1. Replace the unconditional #15176 early return with a named “scope unavailable” condition. This covers fabric/zero ingress and a positive imported `(ifindex,VLAN)` whose local Rust logical-unit mapping is absent; the latter must not be judged against `resolve_ingress_logical_ifindex(...).unwrap_or(raw_ifindex)` when a tagged unit cannot be resolved (`afxdp/forwarding/nat.rs:24-61`).
2. Preserve the early keep for every ambiguous case except this strict subset: **scope unavailable, `nat_scope_ifindex == None`, explicit dynamic provenance `source_nat_static == Some(false)`, a source rewrite, neither NAT64 nor NPTv6, and `forwarding.source_nat_rules.is_empty()`**. The explicit provenance is required because the wire translation alone does not distinguish dynamic from static SNAT; `None` is not proof of a dynamic rule (`policy_revalidation.rs:858-903`). A non-empty list, unknown provenance, or any other translation class stays on the current #15176 keep.
3. For that strict subset, continue through the existing owner/resolution declines and `source_nat_translation_still_valid`; after it returns invalid, return `StaleSourceNat` **before** the reverse-hit unjudged-epoch exemption at `:1755-1792`. Do not revoke a terminal/FabricRedirect/HAInactive or otherwise non-owner row merely because the global rule list is empty; those existing ownership declines remain authoritative (`:1550-1579,1671-1720`).
4. Keep mapped identity-bearing scope-less rows on the existing validator path. For reverse hits with the forward companion present, narrow the `:1773-1792` unjudged-epoch keep so it applies only when no truthful scope evidence exists. A recorded `nat_scope_ifindex` or a locally resolved logical ingress mapping is sufficient scope evidence; otherwise the missing `forward_ingress_vlan_id` must not mask a valid/withdrawn rule verdict. The separate companion-less `NoLocalEntry` arm at `:1371-1397` is a named sibling and remains unchanged in this child.

The empty-list proof has no configured-interface candidate set: it is universal over all possible current and historical ingress names/RIs, because zero live dynamic rules make every candidate false. For a non-empty list there is no sound finite historical candidate inventory in the identity-less row; current configured logical units alone are not a complete set. Therefore child 2 does not enumerate candidates or generalize beyond `is_empty()`. This avoids false revocation from an unrecorded/removed ingress or first-match successor rule.

### Cost bound

The ambiguous non-empty-list case retains the current O(1) early decline and adds no per-packet rule scan. The invariant subset adds an O(1) `source_nat_rules.is_empty()` test; an eligible stale hit then runs the existing validation once (empty dynamic-rule scan plus the existing static/destination checks), with no allocation, copy, interface census, or Cartesian candidate sweep. On a valid judgment the current-generation stamp prevents another judgment until the next config epoch; on an invalid judgment the first owner stale hit revokes the row. The identity/mapping check is a map lookup. The reverse-hit adjustment adds no work beyond that lookup.

## Owner-hit verdict matrix

“Judged” is not synonymous with a bare `None`: a valid judgment stamps the current source-NAT revalidation epoch; an invalid judgment returns `StaleSourceNat`; a conservative keep has neither revocation nor a new judgment stamp. The Rust tests must assert these distinctions.

| Scope / ingress evidence on imported forward row | Rule state | Forward first owner hit | Reverse first owner hit, forward companion present |
|---|---|---|---|
| Scope-less, identity-less (fabric/zero/unresolved), explicit dynamic SNAT provenance | Non-empty live rules; scope remains ambiguous, including a scoped successor | Keep under #15176; no stamp | Keep under #15176; no stamp; reverse unjudged epoch cannot invent scope |
| Same | Empty live dynamic source-NAT list | Revoke `StaleSourceNat` after owner-resolution checks | Revoke `StaleSourceNat` before the `:1773-1792` unjudged-epoch keep |
| Scope-less, identity-less, provenance `None` or not plain dynamic SNAT | Empty list or non-empty | Keep under existing conservative rule; no new conclusion from the dynamic-rule-empty proof | Same; do not misclassify unknown/static/NAT64/NPTv6 provenance as dynamic SNAT |
| Scope-less, non-fabric positive ingress, current logical `(ifindex,VLAN)` mapping present | Matching live rule / translated tuple valid | Judge and survive; stamp | Judge and survive; stamp despite missing forward-VLAN provenance |
| Same | Withdrawn/rescoped rule | Judge and revoke `StaleSourceNat` | Judge and revoke `StaleSourceNat`; do not let an unjudged imported epoch mask known-scope evidence |
| Scope-less, positive ingress but current logical VLAN mapping missing | Non-empty live rules | Keep as unresolved; do not fall back to a guessed parent scope | Keep as unresolved; do not bypass the unjudged-epoch guard |
| Same | Empty live dynamic source-NAT list with `Some(false)` provenance | Revoke by the invariant rule | Revoke by the invariant rule before the epoch guard |
| Scope present (`nat_scope_ifindex` resolved), identity-bearing or identity-less | Valid live rule | Judge and survive; stamp | Judge and survive; recorded scope is sufficient for judgment |
| Same | Withdrawn/rescoped rule | Judge and revoke `StaleSourceNat` | Judge and revoke `StaleSourceNat`; recorded scope bypasses the unjudged-epoch keep |

The identity-less-plus-withdrawn default remains **keep** when any live rules remain: the owner cannot know whether an unknown ingress could select one of them. The empty-list row is the narrow exception because there is no possible source-NAT successor for any ingress. Scope-present controls remain the existing `:820-903` validation behavior. The companion-less reverse `NoLocalEntry` path is not covered by this matrix’s “reverse first hit” column; it remains a separately identified sibling at `:1371-1397` and must retain its existing behavior.

## Rejected alternative: PLAN-KILL / blanket #15176 reaffirmation

Reaffirming the early decline for every scope-less row would preserve a dynamic translation even when the live dynamic source-NAT list is empty, a fact independent of the unknown ingress and of first-match order. That is a false equivalence between “no matching rule under a fabricated empty scope” and “no live rule exists anywhere.” Conversely, blanket judgment against egress, zone, routing-domain, or only the current configured interfaces is unsound: `source_nat_translation_matches` uses ingress interface/RI selectors and first-match ordering (`nat/source/mod.rs:1247-1264,1711-1831`), while egress describes the opposite side of the flow. The selected bounded fix handles only the universal proof and keeps every ambiguous non-empty successor on #15176.

## Wire and legacy-peer compatibility

`NatScopeFold` is already additive for current peers: V4/V6 senders stamp it at `pkg/cluster/sync_conn_gen.go:821,835`; `sync_protocol.go:631` appends it to the metadata tail and the decoder reads the full extension at `:729-739`. A legacy five-byte handshake/egress tail has no `NatScopeFold`, so the new decoder receives zero; an old decoder ignores the added tail. The Go request field resolves scope independently from ingress (`manager_sessionsync_request.go:314-327`), and Rust receives the logical scope when it can be named locally.

No new wire field or compatibility shim is proposed. A legacy peer without `NatScopeFold` but with a resolved ingress fold enters the identity-bearing, scope-less path and is judged only when the local logical mapping is available. A peer with absent/unresolved ingress identity remains ambiguous except for the empty-live-dynamic-rule invariant. The identity is a currently resolved receiver-local ifindex/VLAN, **not proof of the original device**: sender folding occurs against current config, and `manager_sessionsync_request.go:331-335` documents that an ifindex recycled onto a sibling between install and sync may resolve to that sibling. The existing snapshot-presence fence (`:780-795`) and the required Rust logical-map check bound the new behavior to a currently named mapping; the residual recycle-before-sync false-judgment risk remains and is not solved here. Install-time identity/generation on the wire would be a separate cross-language follow-up, not an open prerequisite for this bounded plan.

## Retention risk and operational bound

The finite per-application timeout is clamped to 86,400 seconds, but Junos `inactivity-timeout never` is a real supported value: wire seconds `86401` maps to `u64::MAX` (`userspace-dp/src/session/mod.rs:525-551`; session timeout selection at `:8115-8160`). Established active flows refresh their idle deadline on traffic (`session/lookup.rs:1192-1204`). Thus an ambiguous identity-less row with a non-empty live ruleset can survive indefinitely when explicitly configured `never`; this is not bounded by an ordinary finite timeout. The plan accepts that residue to avoid revoking a potentially valid first-match translation against invented ingress data, while eliminating the provably-invalid empty-rule case on the first eligible owner stale hit. Finite global timeout inputs saturate at `MAX_SESSION_TIMEOUT_NS` (`session/mod.rs:501-522`), and ordinary app overrides are separately capped; neither changes the `never` sentinel.

Other risks: the identity-derived path can be wrong after a sender-side ifindex recycle (residual above); reverse-hit judgment must remain gated on a local owner/forward decision and known scope/provenance; source-NAT rule withdrawal to a non-empty but unrelated ruleset remains conservatively unjudged for identity-less rows. The empty-list check is O(1), and no candidate enumeration or new wire compatibility risk is introduced.
