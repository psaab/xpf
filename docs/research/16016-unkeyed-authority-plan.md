## 2. The plan (numbered, file-anchored)

**Bootstrap-identity answer, stated explicitly:** an unkeyed node has no cryptographic identity to verify a first-key push against — that part of the fork is a genuine impossibility. The design's answer is that the *only* accepted first-key channel is a conjunction no attacker without the peer's transport position can satisfy for long: **within a persisted, operator-visible, wire-non-rearmable provisioning window** AND (on literal-IP deployments, the reference shape) **from the configured peer's address only** (install pin, landed). After the window, first-keying is exclusively a **local operator act** (day-0 drive / console commit per the README "Recovery" enumeration) — which is already the repo's recorded eventual posture (README:3524+). A "legitimate first-key push" is thereby distinguished by *time-bounded operator provisioning context + transport pin*, not by a credential; pushes that meet the conjunction are indistinguishable from hostile ones by construction and are carried as a documented, bounded residual.

1. **New `pkg/cluster/unkeyed_authority_grace_16016.go`** — persisted unkeyed-authority anchor, patterned on `fabric_auth_grace.go`:
   - `var unkeyedAuthorityGrace = 7 * 24 * time.Hour` (var for tests; 7d matches `controlLinkRotationStaleAfter` operator-window precedent — the grace is the migration window, during which posture equals today's, already alarm-visible).
   - State file `/var/lib/xpf/unkeyed-authority-grace` (`unkeyedAuthorityGraceStatePath` package var + `Set…ForTesting`, mirroring :65-76, :202-211). Record: single wall-clock unix-nanos stamp. Load semantics per #15262/#16027: missing/corrupt → treat as fresh stamp at first observation; **future-dated stamp clamped to now** (never extends); across restarts take the **earliest** observed anchor (a rollback cannot extend, a crash loop cannot reset).
   - `Manager.UnkeyedAuthorityExpired() bool` — cheap atomic read; true iff anchor present and `now ≥ anchor+grace` and accepted-key set empty.
   - Fail-closed directions: refusal is the default at expiry; nothing on the wire can create, move, or delete the anchor.

2. **Hook: `pkg/cluster/group_state.go` `UpdateConfig`, at the `keyConfigured :=` computation (:230 region, beside the #16029 rotation stamp :215-229 and #15262 fabric-grace anchor :231+)**:
   - `keyConfigured == true` → **delete** the anchor and zero the field (mirrors `deleteFabricAuthGraceAnchor`; deliberately re-opens a fresh grace if the operator later clears the key — a local act, same semantics as #15262's delete-on-clear).
   - `keyConfigured == false` **and** cluster enabled → **stamp-if-absent** (set-once; no later event moves it). This is requirement-3 (crash-loop survival) and half of requirement-2: the stamp is immutable from the wire because post-grace config frames never reach SyncApply (step 3) and within-grace frames cannot touch it.

3. **Extend the frame gate: `pkg/cluster/sync_conn_read.go:244-246`** — replace `if !s.authConfigured() { return false }` with: if `!authConfigured()` and the wired provider reports `UnkeyedAuthorityExpired()` → **reject every frame type** (empty allow-set; not even `syncMsgHeartbeat` or the `AuthUpgrade*` quartet — an unkeyed post-grace node has nothing to upgrade and must not gain liveness/readiness authority from an untrusted source). Probe via an optional interface on the existing `authProvider` box (pattern `syncAuthConfiguredProvider`, `sync_auth.go:214-219`), implemented by `*Manager`; a SessionSync with **no provider at all** (hermetic legacy fixtures) keeps today's behavior — production has a single construction site that unconditionally wires `d.cluster` (`daemon_ha_comms_wiring.go:221` `ss.SetAuthProvider(d.cluster)`), so no production path is unwired; the daemon RED cell (step 8) pins the wired behavior. Because the check is **per-frame at dispatch**, it bounds an admitted connection's authority for its whole lifetime regardless of when it was admitted — requirement-1, stronger than #10717's per-conn eviction and needing no teardown machinery.

4. **Heartbeat: `pkg/cluster/heartbeat.go` `admitFrame` (:1316+, at the `keys := r.mgr.controlLinkAcceptedKeys()` site)** — if the accepted set is empty and `mgr.UnkeyedAuthorityExpired()`, refuse **before** any liveness/election effect, with a dedicated reason string ("unkeyed authority grace expired (#16016); key the cluster"), mirroring the #6669 reason-override pattern. ## 4. Strongest attack trace against my own design, and dispositions

**A. Forge the first key during grace (the indistinguishability core).** On a hostname-only cluster (or via DNS rebinding, or IP-spoofing the peer on segment), the attacker's connection installs (no literal pin) and pushes `set chassis cluster authentication-key <attacker>` within the 7-day window; tolerant SyncApply installs it (#1960/16858 by design); the attacker completes Noise; the genuine primary is locked out. **Disposition: not closable — this is the true impossibility and it is *bounded*: within-grace only, alarm-visible from the first stamp, and on literal-IP deployments (the reference shape) the install pin closes the unrelated-host path entirely, leaving only the strictly-harder IP-spoof/on-path actor. Residual accepted by the issue's own scope ("grace-bound"); the class dies entirely under the eventual posture (day-0-keyed provisioning). Extending the pin to resolved hostnames was considered and rejected: `resolveConfiguredPeerIPs` already resolves hostnames, but pinning on them turns an unresolvable/transient DNS failure at construction into refusal of the *genuine* peer (availability fail-closed on a misconfig), a trade the #18916 review already declined — documented, revisit with the eventual posture.**

**B. Expiry-boundary race.** Push at T−ε accepted into `configApplyCh`; applied at T+δ when the cluster gate would refuse. **Disposition: covered — step 5 re-checks the grace predicate at apply time in the daemon, so a pre-expiry-queued frame is refused post-expiry; the cluster-side gate is per-frame so no window exists there.**

**C. Crash-loop / clock-rollback the anchor** (#6628 requirement 3). **Disposition: persisted state file; set-once; future-clamp + earliest-wins. Wiping `/var/lib/xpf` resets the grace — residual identical to #15262's wiped-state residual (indistinguishable from re-provisioning; requires root/disk, which is game over independently).**

**D. Split-brain at expiry — the strongest counter-design argument.** At grace expiry both nodes of a still-unkeyed pair refuse each other's heartbeats → both declare peer dead → both take over RGs → dual-active with duplicate VIPs (the exact scenario `control_key_rotation.go:8-13` describes), i.e., the fix manufactures an availability cliff an attacker can *time* (anchor date is in the status alarm). **Disposition: accepted product trade, and it is the same trade the issue's own acceptance makes ("grace-bound" is in the issue's Fix line; a third host must not drive election, and an unauthed heartbeat cannot both be trusted for liveness and untrusted for election — the election inputs *are* the heartbeat body, so no liveness/election split exists). Mitigations: 7 days of escalating, timestamped alarm; the posture equals what a keyed cluster already does to an unverifiable peer; new deploys cannot boot unkeyed at all (strict day-0 gate). Risk wording for the PR's Risk section: "a cluster still unkeyed at grace expiry fails closed — peer-dead takeover on both nodes — after N days of alarmed notice."**

**E. Downgrade via lenient load / key-clear re-arm.** Local attacker loads a keyless config leniently or clears the key → anchor re-stamps → 7 more days of unkeyed authority. **Disposition: clearing the key already disables all cluster auth wholesale today (a strictly worse state); the re-stamp is a local operator-equivalent act consistent with #15262 delete-on-clear. Documented residual, not a regression.**

**F. Weaponize the landed once-keyed upgrade-frame allowance.** Post-#18916, the #6628 quartet is the only unauthenticated frame class left on a keyed node; a pre-key-admitted hostile conn can forge upgrade Requests. **Disposition: harmless-and-bounded — the attacker holds no key so its msg1 fails psk0 AEAD ("never drops", worst case strands one in-flight round), and #10717 evicts the conn 10 s after keying. Doc-only note: the #6628 header's "the attacker can already send syncMsgFence" comparison is now stale (Fence is refused since #18916) — implementer should refresh that sentence.**

**Residuals after this plan (named, not blockers):** within-grace hostile first-key from a pin-passing source (A); hostname-only install supersession as DoS (availability only, post-grade frames refused); wiped-state anchor reset (C); dual-active cliff at expiry for clusters that ignore a 7-day alarm (D). All are outside the issue's post-grace acceptance or explicitly scoped by it.

**Why not PLAN-KILL:** the impossibility argument holds only for *within-grace, pin-passing* pushes; the issue's decisive check is explicitly post-grace ("on an unkeyed-after-grace node…"), the repo has shipped the persisted-grace pattern twice (#15262, #10717), the #6628 header's three anti-timer requirements are each answered by construction (per-dispatch lifetime bounding; wire-immutability of a set-once persisted anchor; crash-loop-safe persistence), and the README itself records that no legitimate flow requires unkeyed authority past provisioning. PLAN-KILL would require a legitimate post-grace unkeyed-authority consumer to exist; none does in source.

## §1a — REPLACES v1 step 1's record/persistence half (M3 + M4)

**Two-clock algorithm.** In-process authority is a **set-once CLOCK_MONOTONIC deadline** (the #10717 discipline, `sync_auth_strict_7441.go:9-12`): `anchorMono = MonotonicNanos()` at the first observation of (cluster enabled ∧ accepted set empty) in each process; expiry fires at `anchorMono + grace` **regardless of wall clock** — a backward live step cannot extend it, a forward step cannot accelerate a false expiry, and no in-process event ever moves it. The persisted record exists **only for restart recovery** and cannot grant what the wall record doesn't support:

`/var/lib/xpf/unkeyed-authority-grace`, one line:
```
v1 <earliestWallUnixNano> <highWaterWallUnixNano> <reAnchored>
```

- **Stamp** (file absent): `earliest = wallNow`, `highWater = wallNow`, `reAnchored = 0`.
- **Every touch** (boot load, each `UpdateConfig`): `highWater = max(highWater, wallNow)` — monotone ratchet, never lowers, survives restarts. This is the field that makes earliest-wins real: expiry-by-wall is `max(wallNow, highWater) ≥ earliest + grace`, so a run's observed wall time is never refundable by a later rollback+restart.
- **Future-dated load** (`earliest > wallNow`): clamp `earliest := wallNow` at load, recompute against `highWater` — the clamp direction is *shorten* (same direction as #16027); unlike the fabric clamp we do **not** leave the future stamp on disk as authority — the touch rewrites the clamped `earliest`, because here the stamp *is* the deadline's base and an honored future stamp extends the window, the exact thing #16027's on-disk retention was acceptable because it *never* did there.
- **Single re-anchor (wrong-initial-clock recovery)**: on a *fresh process* whose in-process monotonic elapsed `< grace`, if the loaded record already tests expired, conclude the record's wall domain was stamped under a wrong clock → `earliest := wallNow`, set `reAnchored = 1`, persist. Once per record ever (key-commit deletes the record and resets the flag). Repeat-restart re-anchoring is thereby impossible; the fresh-migration-with-bad-RTC case gets its full window exactly once.
- **Invariant**: no sequence of clock steps, crashes, or restarts extends the window beyond `max(grace from first correctly stamped observation, one re-anchor's grace)`; only a local key commit (deletes the record, v1 step 2 unchanged) or root-owned state manipulation (file wipe/edit — same residual class #15262 accepts) re-opens one.

**M4 posture — fail-closed for the grant, fail-open for the daemon:**
- **File absent** → fresh stamp (day-0/reimage path; wipe residual documented, root-equivalent).
- **File present but corrupt/unparseable** → **expired-at-boot**: authority refused, status/alarm name the corrupt anchor; recovery = key the cluster. Defense: presence is evidence of a prior in-grace node; corruption ≠ absence; false-expiry costs the (already alarmed, 72h-noticed) fail-closed posture, false-fresh costs 7… 72h more of the original vulnerability.
- **Persist write failure** → the in-process monotonic deadline still arms and expires (authority bounded this process); log one `slog.Error`, status suffix "anchor not persisted; restart re-opens grace"; opportunistic re-persist on next touch. Never fail a config apply or boot over the auxiliary file (#15262 posture, `fabric_auth_grace.go:35-39`).

Cells (`pkg/cluster/unkeyed_authority_grace_16016_test.go`): `TestUnkeyedGraceBackwardWallStepCannotExtend16016` (live step; monotonic arm fires on schedule) · `TestUnkeyedGraceRestartAfterBackwardStepCannotExtend16016` (highWater rule) · `TestUnkeyedGraceWrongInitialClockReanchorsOnce16016` (1999-clock boot → NTP forward → one re-anchor; second occurrence refused via `reAnchored`) · `TestUnkeyedGraceFutureDatedStampClampedShort16016` (earliest clamped down; highWater never lowered) · `TestUnkeyedAnchorWriteFailureStillExpiresInProcess16016` · `TestUnkeyedAnchorCorruptFailsClosed16016`.

## §9 — NEW: expired-cluster election policy (H2)

**Policy: HOLD roles, suppress acquisition. Refuse unauthenticated liveness (it is spoofable); the election policy owns the consequence.**

- At the expiry instant a node keeps its current `NodeState`.
