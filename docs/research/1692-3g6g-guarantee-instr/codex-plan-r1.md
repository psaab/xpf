PLAN-NEEDS-MAJOR

**Findings**

1. **CRITICAL: §4’s L1-by-design discriminator is code-false.**  
   The table claims `Σshare_i < class_rate` because “idle-worker shares (0 flows → 0 share) leave the rate undistributed” ([plan.md](/home/ps/git/bpfrx/docs/research/1692-3g6g-guarantee-instr/plan.md:223)). But the code does not reserve shares for idle workers. It computes `total_flows` by summing active buckets and then allocates each worker from that denominator: `worker_active_flow_buckets.iter().map(...).sum::<u64>().max(1)` and `my_share = new_cap * my_count / total_flows` ([rotate_epoch_v8.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/types/shared_cos_lease/rotate_epoch_v8.rs:207), [rotate_epoch_v8.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/types/shared_cos_lease/rotate_epoch_v8.rs:306)). Therefore zero-flow workers get zero share and do not make `Σshare` materially less than cap. This breaks the main L1-by-design vs L1-fixable decision rule.

2. **HIGH: `share_i` is an epoch gauge, but the plan compares it to window counters.**  
   §4 defines `delivered_i` as `drain_sent_bytes` and `granted_i` as granted bytes, both naturally pre/post deltas, but `share_i` is a “v8 my_share snapshot” ([plan.md](/home/ps/git/bpfrx/docs/research/1692-3g6g-guarantee-instr/plan.md:215)). The code recomputes share every v8 epoch, with `EPOCH_DURATION_NS = 200_000` ([mod.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/types/shared_cos_lease/mod.rs:241)) and stores a new per-worker value during rotation ([rotate_epoch_v8.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/types/shared_cos_lease/rotate_epoch_v8.rs:293)). A single post-run gauge cannot be compared to 30s `delivered`/`granted` deltas unless the plan also integrates share over the same window or records enough epoch/cap timing to normalize it. As written, the table can produce arbitrary false “delivered < share” or “delivered ≈ share” outcomes.

3. **HIGH: Option B’s proposed `my_share` read is not race-free as specified.**  
   The plan says to sample `worker_fair_share[worker_id]` with “a single Relaxed load” ([plan.md](/home/ps/git/bpfrx/docs/research/1692-3g6g-guarantee-instr/plan.md:286)). The actual safe reader pattern is seqlock-based: it reads `epoch_seq`, loads `cap/share/grace`, executes an Acquire fence, then re-reads `epoch_seq` before accepting the snapshot ([mod.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/types/shared_cos_lease/mod.rs:1561)). The code explicitly documents why the fence exists to avoid torn cross-epoch data ([mod.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/types/shared_cos_lease/mod.rs:1574)). A diagnostic accessor can be added, but the plan’s “single Relaxed load” claim is unsafe.

4. **HIGH: L2 cannot be “hidden by the SUM” when the summed counter is zero.**  
   The plan keeps L2 alive because a per-worker `drain_park_root_tokens` split “could still reveal a single worker hitting root starvation that the SUM hides” ([plan.md](/home/ps/git/bpfrx/docs/research/1692-3g6g-guarantee-instr/plan.md:139)). That is impossible for these monotonic nonnegative counters: coordinator aggregation uses `saturating_add` for `root_token_starvation_parks` ([coordinator/mod.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/coordinator/mod.rs:1039)), and queue rows add `drain_park_root_tokens` the same way ([queue_row.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/worker/cos/queue_row.rs:228)). If aggregate `park_root=0`, every contributing worker row is zero. Either L2 is already killed by existing telemetry, or the plan needs a different root-FCFS ordering counter.

5. **MAJOR: The L1-fixable row is internally contradictory, so §4 is not a distinct-signature proof.**  
   The row says `delivered_i ≈ share_i` and `granted_i ≈ share_i`, while also saying `Σshare_i ≈ class_rate` but “`delivered < Σshare`” ([plan.md](/home/ps/git/bpfrx/docs/research/1692-3g6g-guarantee-instr/plan.md:224)). For the workers the table scopes itself to, “worker `i` that has ≥1 active 3g flow” ([plan.md](/home/ps/git/bpfrx/docs/research/1692-3g6g-guarantee-instr/plan.md:213)), those predicates cannot all hold. If workers leave granted tokens unspent, then `delivered_i ≈ share_i` is false on those workers. This is exactly the kind of identical/undecidable L1-vs-L3 region the consumer criterion forbids.

**Verified Claims**

Claims 1, 2, and 3 are mostly verified: the ≥2.5G shared-exact routing gate is real ([worker/cos/mod.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/worker/cos/mod.rs:31), [worker/cos/mod.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/worker/cos/mod.rs:168), [cross_binding.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/cos/cross_binding.rs:69)); `acquire_v8` primary is capped by `my_effective_share` and surplus requires bypass ([mod.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/types/shared_cos_lease/mod.rs:1203), [mod.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/types/shared_cos_lease/mod.rs:1320)); current counters are indeed summed or too coarse for per-class/per-worker v8 attribution ([coordinator/mod.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/coordinator/mod.rs:1048), [coordinator/status.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/coordinator/status.rs:382), [worker/mod.rs](/home/ps/git/bpfrx/userspace-dp/src/afxdp/worker/mod.rs:1031)).

The plan is not ready because §4 and §7 do not yet meet the consumer bar: the proposed counter signatures do not actually distinguish L1-by-design, L1-fixable, L2, and L3.
