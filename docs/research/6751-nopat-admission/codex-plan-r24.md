# PLAN-NEEDS-REVISION

1. **BLOCKER — lifecycle mutation commits remain check-then-store, not generation-atomic.** The plan requires an abort-generation/slot check “at the store,” but the validation and daemon atomic write are separate operations. Detach can occur after validation and before `syncPeerConnected.Store(true)`, recreating the exact connect-after-disconnect race. The same problem applies to epoch, suppression, priming, readiness, timer, and retry mutations. Additionally, the asynchronously launched disconnect callback is not symmetrically generation-guarded and can store `false` after a newer connection stores `true`. 2. **BLOCKER — abort envelopes do not cover all work that can cross the abort boundary.** `QueueDeleteV4/V6` journals only when `queueMessage` fails; successful deltas enter `sendCh` directly as raw `[]byte`. `sendLoop` can dequeue one, wait indefinitely for any active connection, and later send it over a replacement connection. Such a pre-abort zero-generation delete bypasses the proposed “journal envelope discarded at queue-drain,” so the plan’s claim that the abort-adjacent kill/resurrection “never travels” is false. The same issue exists for a journal item after it is transferred into—or dequeued from—the raw send queue. Evidence: [plan.md:808](/home/ps/git/kimi-xpf/.claude/worktrees/6751-research-nopat-admission/docs/research/6751-nopat-admission/plan.md:808), [plan.md:837](/home/ps/git/kimi-xpf/.claude/worktrees/6751-research-nopat-admission/docs/research/6751-nopat-admission/plan.md:837), [sync_conn_write.go:36](/home/ps/git/kimi-xpf/.claude/worktrees/6751-research-nopat-admission/pkg/cluster/sync_conn_write.go:36), [sync_conn_write.go:77](/home/ps/git/kimi-xpf/.claude/worktrees/6751-research-nopat-admission/pkg/cluster/sync_conn_write.go:77), [sync_conn_write.go:135](/home/ps/git/kimi-xpf/.claude/worktrees/6751-research-nopat-admission/pkg/cluster/sync_conn_write.go:135), [sync_conn_write.go:268](/home/ps/git/kimi-xpf/.claude/worktrees/6751-research-nopat-admission/pkg/cluster/sync_conn_write.go:268). The existing resync pattern consumes its Boolean before starting the bulk, allowing exactly this re-arm cycle. With the active one-second sweep cadence, persistent saturation can produce back-to-back 200k-session bulks indefinitely. “One bulk per trigger edge” is insufficient because each bulk creates a new edge.
