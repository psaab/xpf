## 2. Measurement methodology (anchored to the project's own tool)

There are **two** LOC definitions in play; the plan uses the project's
authoritative one and notes where the issue's differs:

- **Project audit tool** (`scripts/refactoring-audit.sh`, `make audit-check`):
  metric is **total `wc -l`**, excluding test-named *files* (`tests.rs`,
  `*_tests.rs`, `*_test.go`) and generated code (`*.pb.go`, `*_bpfel.go`,
  `zz_generated_*`). It deliberately does **NOT** strip inline
  `#[cfg(test)] mod tests` blocks (the awk stripper was fragile — Gemini
  round-1 of #1208 found it silently erased prod code after a test block).
  **This is the gate a split PR must satisfy.**
- **Issue's "prod-LOC"**: total minus the inline `#[cfg(test)] mod tests`
  block. For our set this only matters for `wg/engine.rs` (~809 inline test
  lines) and `poll_descriptor/mod.rs` (~232 inline test lines). For all the
  other files the two definitions agree (their tests already live in external
  `tests.rs`/`*_test.go`).

Both numbers are reported per file below so the dispositions are unambiguous.

**Hard CI consequence:** every split PR in this plan MUST regenerate
`docs/refactoring-audit-current.txt` (`bash scripts/refactoring-audit.sh >
docs/refactoring-audit-current.txt`) and pass `make audit-check`, or the
drift guard fails. Document this as a required PR step.

## 4. The established split patterns (precedent)

The 18-PR refactor stream that drove the tree under 2000 (#985/#988/#986/
#1034/#1035/#957, plus #1046) established two concrete, repeatable patterns.
This plan reuses them verbatim.

### 4.1 Go — same-package file split (trivial, lowest risk)
Go has no inline tests (they live in `*_test.go`) and no module-wiring step:
move a cohesive group of funcs/types from `store.go` into a new `store_<x>.go`
in the **same package** (`package configstore`). No import changes inside the
package, no API change, no declaration order constraint (Go has no file-level
`init()` ordering across one package beyond source-name order — see §8 risk).
This is essentially `git mv`-of-functions. **Verify: `go build ./... && go vet
./... && go test ./<pkg>/...` unchanged.**

### 4.2 Rust — sibling-file submodule (the `mod x;` pattern)
The `userspace-dp/src/afxdp/{cos,tx,frame,...}` decomposition is the template.
A module-directory `mod.rs` declares sibling files with plain `mod drain;`
(file = `drain.rs` in the same dir); the sibling opens with `use super::*;`
and carries either **free functions** (the common case — most of these files
are free `fn`/`pub(in crate::afxdp) fn`, not methods) or its own
`impl Type { … }` block (multiple `impl` blocks for one type across files is
legal Rust).

- **Free-function move** (queue_service, forwarding): trivial — `use super::*;`
  re-exposes everything; no visibility change needed.
- **`impl`-method / private-helper move** (shared_cos_lease): the moved method
  stays in an `impl SharedCoSQueueLease` block in the new file, BUT any
  **private field or private free helper it reaches across the new file
  boundary must widen from inherent-private to `pub(super)`**. This is exactly
  what the *already-extracted* `rotate_epoch_v8.rs` / `publish_equal_flow_epoch_v8.rs`
  did (PR #1588): their header comments document "visibility widens from
  inherent-private to `pub(super)` … `#[inline]` hints the single-call-site
  inlining decision the compiler made implicitly on master." **This is still
  pure code-motion under the project's definition, but it is NOT a
  zero-visibility-change move** — that distinction is the central SMR finding
  (see r1 SMR doc).

### 4.3 Rust — inline-test relocation (PR #1046 pattern)
`engine.rs`'s 2086 LOC is **mostly inline tests** (~809 lines,
`mod engine_internal_tests`, lines 1278–EOF). PR #1046 P1 (`039a021af`)
relocated `frame/mod.rs`'s inline tests (6435→1995 LOC) using:
```rust
#[cfg(test)]
#[path = "engine_tests.rs"]   // sibling file holds the moved block
mod engine_internal_tests;    // name preserved; #[path] nests it as a child
```
`#[path]` keeps the module a *child* of the parent, so `use super::*;` still
reaches the prod file's private items — no test edits needed. **This alone
drops engine.rs to ~1277 LOC, off the REFACTOR list entirely**, and is the
single cheapest, lowest-risk win in the whole issue.

## 6. Codegen / hot-path note (Rust files)

`userspace-dp/Cargo.toml` has **no `[profile.release]` section** (verified) —
so release inherits Cargo defaults: `opt-level = 3`, **`lto = false`**,
`codegen-units = 16`. (Correction: an earlier analysis claimed `lto = true`
default — that is wrong; Cargo's release default does not enable LTO.)

Implication for the hot-path Rust splits (shared_cos_lease; and the deferred
queue_service/forwarding): with `codegen-units = 16` and no LTO, moving a
function across module files *can* change which codegen unit it lands in and
thus the inlining decision. Mitigations (all established precedent):
1. Carry the `#[inline]` hint with any moved hot helper that had it, and add
   `#[inline]` to any moved private helper the compiler was inlining
   implicitly at its single call site (the `publish_equal_flow_epoch_v8.rs`
   precedent did exactly this).
2. **Required per the issue:** `make build-userspace-dp` + a **loss userspace
   cluster** smoke (sustained iperf3 both directions, per the smoke doctrine)
   for any hot-path split; confirm throughput/CPU show no regression vs the
   pre-split baseline.
3. The largest moved function (`acquire_v8`, ~550 LOC) is too big to inline
   regardless, so its move is codegen-neutral; the small helpers are the only
   inlining-sensitive pieces — keep their `#[inline]`.

Go files have no codegen-regression concern (single compilation unit per
package; file boundaries are invisible to the Go compiler).

## 8. Behavior-preservation checklist (per PR — the code-motion bar)

The whole risk of code-motion is an *accidental* behavior change. Every PR
must demonstrate, before merge:

1. **Build clean.** Go: `go build ./... && go vet ./...`. Rust:
   `make build-userspace-dp` (the pinned-toolchain build).
2. **Full test suite unchanged.** Go: `go test ./...` (or at least the
   touched package + dependents) — same pass set, no new skips. Rust:
   `cargo test` for the touched crate — same pass set.
3. **No public-API diff.** Go: `go doc`/exported-symbol diff of the package
   is empty (no exported identifier added/removed/moved-out-of-package).
   Rust: no change to the `pub`/`pub(crate)` surface; only `pub(super)`
   widening *within* the module is allowed (and only where the compiler
   forces it). `cargo public-api` or a manual `pub ` grep diff confirms.
4. **No receiver/visibility drift.** A moved Go method keeps its exact
   receiver (`(s *Store)` stays `(s *Store)`). A moved Rust method stays in an
   `impl <SameType>` block. No function silently becomes free-standing or
   loses a receiver.
5. **No init-order change (Go-specific).** Go runs package-level `var`
   initializers and `init()` funcs in *source-file-name order* within a
   package. If a split moves a `var x = f()` or an `init()` into a new file
   whose name sorts differently, init order can change. **Check:** none of the
   target files move a package-level `var` with a side-effecting initializer
   or an `init()` across a name-sort boundary. (manager.go has an `init()` at
   line 108 and `Boot()` registration — keep `init()` in `manager.go`, do not
   move it.) For store.go/compiler.go/cli_show_security.go: confirm no
   package-level `var` with cross-file initialization dependency before
   choosing file names.
6. **No import-cycle / unused-import.** Go: `goimports`/`go vet` catches
   stray imports. Rust: `cargo build` warns on unused `use super::*;` items.
7. **Diff is move-only.** Reviewers verify the PR diff is exclusively cut/paste
   (a `git diff -M -C` should show high rename/copy similarity; the only
   non-move lines are the new `mod x;`/`#[path]` wiring, the `pub(super)`
   widenings, and `#[inline]` hints — each individually justified in the PR
   body).
8. **Hot-path only:** `make build-userspace-dp` + loss-cluster smoke for
   #2158-E/-F (§6).
9. **Audit drift guard:** `make audit-check` green after regenerating the
   heatmap.
