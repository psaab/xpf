# #16488 — Round-robin NAT64 BIB leases excluded from persistent-NAT show, clear, and HA idle export

- **Timestamp**: 2026-10-24
- **Context**: Every round-robin NAT64 flow mints a persistent
  `AnyRemoteHost` BIB lease with a 300 s timeout (#13946,
  `allocate_nat64_pool_port`). The coordinator's
  `export_idle_persistent_leases`, `export_display_persistent_leases`
  and `clear_persistent_nat_leases` in
  `userspace-dp/src/afxdp/coordinator/idle_lease_sync_8121.rs` iterated
  NAT64 prefixes only when `deterministic_v6` was set (#14676/#14091
  scoped only deterministic NAT64). Round-robin BIBs were therefore
  invisible to `show security nat source persistent-nat-table`, were
  not revoked by `clear security nat source persistent-nat-table`, and
  were never exported to the HA peer while idle — after a failover an
  idle v6 socket got a different mapping, breaking EIM continuity
  (bounded by the 300 s idle timeout; no collision).
- **Fix**: drop the `deterministic_v6` gate in all three loops.
  Deterministic prefixes keep `nat64-deterministic-{idx}`; round-robin
  prefixes export/display under `nat64-{idx}` without stamping a
  deterministic identity. `clear_persistent_nat_leases` now clears
  every NAT64 prefix allocator, so the clear fence applies to
  round-robin BIBs too. On import, `nat64-{idx}` records route to a
  new round-robin branch: the prefix must exist and be round-robin,
  the record must be non-deterministic and `permit_any_remote` (the
  NAT64 BIB shape), the source must be v6 and the translated address
  must be a v4 pool member at its local index, and the port must lie
  in the allocator's live range (`port_low..=port_high`, honouring
  #15283 narrowing). Static ownership
  (`static_owns_wire_identity`) and peer/interface live ownership
  (`nat64_peer_or_interface_owns_idle_import`,
  `iface_peer_idle_any_contended` — PAT occupancy plus live
  address-only/PAT owners at the translated base, the ANY-remote
  query) are checked before the claim and again after it, with
  `nat64_rollback_idle_import` rolling the claim back on a racing
  owner, mirroring the SNAT import posture. Installation goes through
  `import_idle_lease_at` /
  `import_idle_lease_at_after_generation_permit_any`, so the clear
  fence (`SkippedClearFenced`) applies unchanged. A new
  `PortAllocator::peer_import_idle_any_contended` exposes the
  base-index contention query for peer/interface allocators.

- **Validation**: new `round_robin_nat64_*_16488` cells: display 1 and
  exported 1 under `nat64-0`, standby import installs 1, clear
  returns 1 and empties export/display, and a stale pre-clear record
  is clear-fenced (`skipped_clear_fenced == 1`); import validation
  rejects out-of-pool addresses (`skipped_unknown_address`), out-of-range
  ports and deterministic-shaped records under the round-robin name.
  Deterministic 14676/14091 cells stay green (see PR for counts).
- **Residual**: component level only, matching the finding's evidence
  (CLI/gRPC plumbing to these coordinator functions was not driven).
  The interface-registry check covers live address-only/PAT owners at
  the translated base; interface allocators claim no bitmap bit, so
  there is no PAT-occupancy leg for that domain.
