# Issue #16134: validate u8 protocol carriers against poison and version bump first

- **Timestamp**: 2026-10-24
- **Action**: validation-first cells for the three string protocol carriers
  (filter `FirewallTermSnapshot.Protocols`, app
  `PolicyApplicationSnapshot.Protocol`, DNAT
  `DestinationNATRuleSnapshot.Protocol`). No carrier is retyped and no Rust
  mirror table is deleted, per the issue's narrowed form. Go cells
  (`protocol_carrier_validation_16134_test.go`) prove per carrier: (a) every
  poison path — unrepresentable term, partial-drop DENY, lenient-dropped
  policy, undefined-scheduler DENY/REJECT — atomically replaces the rule's
  terms with the `__unsupported__` sentinel alone, reaches the wire, is
  named by the `PolicyContentRejectionReasons` mirror, and keeps the helper
  armed; the undefined-scheduler PERMIT control stays unpoisoned. (b) The
  unconditional required-protocol orchestrator refuses both skew orders
  (older/newer helper, plus the historical pre-v5 literal) before apply,
  so a future `ProtocolVersion` bump has a proven rejection cell in each
  direction. (c) Protocol-0 semantics: `appid.ProtocolNumber("0")=(0,true)`
  distinct from unknown `(0,false)`; the filter emits `"0"` verbatim as a
  one-element constraint vs the empty unconstrained list; DNAT keeps
  explicit `"0"` as one exact-HOPOPT row, fans `""`+port out to tcp+udp,
  and keeps `""` without a port as the single any-protocol row; Junos
  aliases resolve through the SSOT. Rust cells pin the mirror halves
  (policy whole-snapshot reject, filter scoped HOPOPT, DNAT exact-vs-
  wildcard, both version orders in `main_tests.rs`).
- **Defect found and fixed while validating**: the Rust numeric fallbacks
  (`ip_proto::proto_number` and `policy::parse_protocol`, both bare
  `parse::<u8>()`) accepted non-canonical numerics such as `"+6"` that the
  Go SSOT (`ParseCanonicalUint`, #9899) rejects — a corrupt/non-Go snapshot
  carrying `"+6"` decoded to TCP while the Go mirror reported it
  unrepresentable (commit/apply drift on a security leaf). `proto_number`
  now accepts digit-only numerics, and `parse_protocol` delegates to
  `proto_number`, which also closes the policy carrier's missing Junos
  aliases (`junos-ping`, `junos-ospf`, `junos-ip-in-ip`, …). `"0"` still
  resolves to `Some(0)`; unknown tokens stay `None`.
