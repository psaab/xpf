## Defect, re-verified at e09f425dd

`runShutdownSequence` picks `hitless := !haMode`, which an HA node overrides only with `hitless-restart`. So an HA stop is non-hitless by default. That branch:
- clears `rg_active`;
- stops the subsystems;
- calls `rt.Teardown()`, which detaches every XDP program and removes the pins.

Nothing on the path lowers `ip_forward` or `conf.all.forwarding`, or installs the #7191 barrier. The only writers are the transit-gate helpers in `daemon_transit_gate.go`, and shutdown called none of them. The node therefore ended with kernel forwarding open and nothing adjudicating transit. The unit has no `ExecStop`/`ExecStopPost`, and FRR keeps its routes.

## Change

- **`daemon_run_shutdown.go`:** right after `hitless` is decided, `if !hitless { d.markDataplaneNotArmed("shutdown", ...) }`. That is the not-armed transition bootstrap and `--no-dataplane` already use:
  - install the #7191 barrier;
  - write both sysctls to 0;
  - drop the #7178 arm-track.
- **Placement.** It runs after `stop(); wg.Wait()`, so no reconcile goroutine can re-drive arming. It runs before the `rg_active` clear, the Kea stop and every blocking teardown, and so strictly before `Teardown`.
- **Condition.** It keys on `hitless` alone and not on a published runtime, because forwarding can be open from an earlier arm either way.
- **Arm-track.** `applyDataplaneArmTrack` does not block: it short-circuits on a nil cluster and otherwise sets a monitor weight.
- **Hitless stops** keep the dataplane attached with the shim dropping transit, so they leave forwarding untouched.

## Cells

- **`TestFailClosedHAStopClosesTransitBeforeTheDetach9686`** drives the real `runShutdownSequence`, with the sysctls on temp files and a fake nftables installer.
  - Its fake dataplane records, AT THE MOMENT `Close` or `Teardown` runs, what both sysctls held and which barrier calls had happened. This is the ordering witness: a close placed after `Teardown` leaves the same end state and would pass an end-state check.
  - **HA fail-closed:** `Teardown` sees both sysctls at 0 and barrier `install`, and the node is recorded not armed.
  - **HA `hitless-restart` and standalone:** `Close` sees both sysctls at 1 and no barrier call.
  - In all three cases the end state still matches after the stop returns.
- **`TestFailClosedShutdownActionsPrecedeBlockingTeardowns9035`** now counts `markDataplaneNotArmed()` as a third fail-closed site, so moving it below a blocking teardown, or dropping it, reds the guard.
- **Seams in older tests.** #6928's HA case and #6787's cluster fixture drive the same non-hitless shutdown. Both now go through `seamTransitClose9686` (temp sysctls, fake installer). Without it they would write the host's `/proc` sysctls and program a real nftables barrier, which under `sudo make test-root` would disable the test machine's forwarding.
