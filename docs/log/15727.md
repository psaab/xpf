# Issue #15727 — fix unsatisfiable ct-state predicate disabling RST suppression

- **Issue:** `rstDropExprs` (`pkg/nftables/rst_suppress.go`) matched
  `ct state & (invalid|established|related|new|untracked) == 0`
  (mask `0x4f`, compared to 0). Linux `nft_ct_get_eval`
  (`net/netfilter/nft_ct.c`, `NFT_CT_STATE`, verified at v6.12) never
  writes 0: it writes `NF_CT_STATE_BIT(ctinfo)` for a tracked packet,
  `NF_CT_STATE_UNTRACKED_BIT` (0x40) when `ctinfo == IP_CT_UNTRACKED`,
  and `NF_CT_STATE_INVALID_BIT` (0x01) otherwise. The predicate was
  therefore unsatisfiable and SNAT/interface-NAT TCP RST suppression
  never fired. The #14949 unit test pinned the broken shape and passed
  anyway (false-green oracle).
- **Fix (two parts, both load-bearing):**
  1. `rstDropExprs` now matches `ct state invalid` exactly
     (mask == value == `CtStateBitINVALID`), the kernel's
     no-conntrack-entry signature. UNTRACKED is deliberately not
     matched: it requires a NOTRACK (ingress raw-table) decision the
     kernel's own locally generated RST never carries, so it cannot
     occur on this path.
  2. The `xpf_dp_rst` output chain moves from filter priority (0) to
     raw priority (-300). Live probing (below) showed the predicate
     fix alone is insufficient at filter priority: the OUTPUT
     conntrack hook (-200) attaches an entry (`ctinfo` NEW) to the
     locally generated RST before a priority-0 chain evaluates, so
     the packet reads `new`, never `invalid`. At raw priority the
     RST is still entry-less and reports INVALID (pre-conntrack-hook
     probe: `ct state invalid` counted 2/2 RSTs; at filter priority,
     0). This is the smallest change that makes the accepted fix
     actually fire; without it the live test stays red.
- **Why tracked RSTs still survive:** a local socket RST carries its
  socket conntrack entry into OUTPUT and reports its tracked bit at
  raw priority too; an nft `reject with tcp reset` RST is synthesized
  from the ingress hook for the rejected packet and is not emitted
  from a dataplane-owned interface-NAT source address. Neither class
  is INVALID-at-OUTPUT from a protected SNAT source.
- **Files:** `pkg/nftables/rst_suppress.go` (predicate + chain
  priority), `pkg/nftables/rst_suppress_14949_test.go` (corrected
  oracle), `pkg/nftables/rst_suppress_live_15727_test.go` (new live
  netns test), `pkg/nftables/README.md`,
  `docs/afxdp-packet-processing.md`, `docs/log/15727.md`.

## Kernel-semantics evidence

- Linux v6.12 `nft_ct_get_eval` (`NFT_CT_STATE`): `ct` →
  `NF_CT_STATE_BIT(ctinfo)`; `ctinfo == IP_CT_UNTRACKED` →
  `NF_CT_STATE_UNTRACKED_BIT` (1<<6); else
  `NF_CT_STATE_INVALID_BIT` (1<<0). State is never 0.
- Live probe in a private netns (kernel 7.2.8, `nf_conntrack_tcp_loose=1`,
  the host default): SYNs to a closed port on the protected address
  produced RSTs counted by a catch-all rule (3/3) but by neither
  `ct state invalid` nor `ct state untracked` rules at filter priority
  (0/3 each); at raw priority, `ct state invalid` counted 2/2 and
  dropping there prevented the RSTs reaching a downstream counter
  (dial timed out instead of refused — the suppression working
  end-to-end).

## Residual

- With `nf_conntrack_tcp_loose=1` (host default) a bare non-RST
  segment may be picked up mid-stream on ingress
  (`nf_conntrack_proto_tcp.c: tcp_new` loose branch). It cannot
  attach to the locally generated RST — `nf_reset_ct` detaches any
  ingress entry before `tcp_v4_send_reset`, and a lone RST creates no
  entry (RST in `TCP_CONNTRACK_NONE` → `TCP_CONNTRACK_MAX`, hook
  drops it and reports invalid) — so the INVALID signature at raw
  priority holds. No sysctl change is made: the loose default is the
  tested configuration, not a defect to work around.
