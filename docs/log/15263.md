# Issue #15263 — daemon: fix cohort — #11086 stale-ifindex residuals (B05-02)

## Why

`buildIngressFoldResolver` and `buildIngressFoldFn` (pkg/daemon/ingress_fold_7095.go)
capture `net.Interfaces()` once per config apply and were never rebuilt by the
#11086/#14133 link-refresh path. `Manager.RefreshInterfaceRowsForLink`
(pkg/dataplane/userspace/manager_link_refresh.go) rebuilds `lastSnapshot`'s
interface rows when a member netdev is recreated without a commit (VF reset,
re-probe), so the snapshot carries the NEW ifindex — but the daemon fold
closures still name the dead one:

- Receive side (Manager.ingressFoldResolver, installed at
  daemon_apply_dataplane.go `SetIngressFoldResolver`): `resolveEgressFoldLocked`
  / `resolveIngressFoldLocked` returned ok=true with the stale ifindex, then
  `sessionSyncEgressLocked` (manager_sessionsync_request.go) missed the row in
  the current snapshot and returned `(fibIfindex, fibIfindex, 0)` — the
  importer installed the session with the dead ifindex and owner RG 0.
- Send side (SessionSync.ingressFoldFn, installed via `SetZoneOwnership`):
  degraded to fold 0 until the next commit (documented, but needlessly long).

`buildZoneFoldRGMap` is derived from config alone (no ifindex state), so it
cannot go stale; it is reinstalled with the rebuilt fold fn so the
SessionSync ownership snapshot stays one coherent generation.

## What

- `pkg/dataplane/userspace/manager_sessionsync_request.go` —
  `resolveIngressFoldLocked` now fences the resolver's answer against the
  CURRENT snapshot: when the resolved ifindex is absent from `lastSnapshot`
  (checked with the snapshot's own `findUserspaceEgressInterfaceSnapshot`
  identity, including its parent/VLAN-unit and parent-fallback semantics),
  it returns ok=false and the import fails closed to the #4792 zone
  approximation instead of naming the dead device. A nil snapshot keeps the
  pre-existing passthrough (nothing published to fence against). This is
  the issue's mandated minimum and covers every caller (ingress + egress
  folds, v4 + v6) even if a stale closure is ever installed again.
- `pkg/daemon/daemon_interface_link_refresh.go` — new
  `refreshIngressFoldClosures`, called from `refreshInterfaceRowsForLink`
  after `RefreshInterfaceRowsForLink` succeeds (publish or hash-dedup) and
  before the FIB-generation bump: it rebuilds and reinstalls both closures
  from the live `net.Interfaces()` table (`Manager.SetIngressFoldResolver`
  + `SessionSync.SetZoneOwnership` with a rebuilt `buildZoneFoldRGMap`).
  Builders are parameters (nil = production builders) so tests inject the
  same builder code over a fake device list. The caller holds applySem, so
  the reinstall cannot interleave with a commit's own installation.
- Test seams (production files, test-only callers): 
  `Manager.ResolveIngressFoldForTesting` (userspace test_seams.go) and
  `SessionSync.StampIngressFoldForTesting` (cluster test_seams.go) expose
  the installed closures to cross-package cells.
- Header comments in ingress_fold_7095.go and Manager.ingressFoldResolver
  updated: the snapshot is now per-apply AND per-link-refresh.

NOT changed: wire formats, `buildIngressFoldResolverWithIfaces` /
`buildIngressFoldFn` internals, the #11086 helper-row rebuild, the #14133
attach reconcile, or any Rust code. The recycled-ifindex hazard (#6987,
same number re-owned by a different device, which IS present in the
snapshot) is untouched and remains tracked separately.

## Risk

The fence adds one snapshot scan per resolved fold on the import hot path;
it reuses the existing egress-identity lookup already run for every such
session (`sessionSyncEgressLocked`), so the added cost is one extra linear
pass over the interface rows (small, bounded by the configured interface
count) only for sessions carrying a non-zero fold. The link-refresh rebuild
takes one `net.Interfaces()` sample per debounced link event — the same
cost class as the apply path it mirrors. Sessions whose fold legitimately
resolves through a snapshot row keep resolving identically (control cells).
