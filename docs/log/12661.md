# Issue #12661 — repeated interface family blocks

## Contract and change

The interface compiler visits every `family inet` / `family inet6` block in authored order. Filter directions are scalar last-wins values, while sampling flags union across their family nodes. Before this change the editor's schema walk descended into the first matching family node, so a set could change a shadowed filter while leaving the later filter active, and delete/deactivate operations left compiler-visible family siblings untouched.

`pkg/config/ast_edit.go` now scopes family sibling selection and mutation to the interface-unit `family` schema:

- Set selects the last active matching family node, including split `family { inet { ... } }` children. If all matching nodes are inactive, set edits the inactive sibling exposed by activation. Under `groups`, repeated family siblings are refused atomically rather than applying the filter/sampling first-wins rule to a family compiler path.
- Delete and deactivate/activate traverse every matching structured family sibling, in both compound and split shapes. Before committing, they refuse atomically if a matching elided/packed family sibling is present; the editor cannot safely determine or split its statements. The operation otherwise applies to the requested family subtree, including filter and sampling children, so a later sibling cannot keep a removed/deactivated binding effective.
- Inet and inet6 remain independently keyed. Matching elided/packed family representations fail closed with a re-author-with-braces diagnostic.

No compiler or schema behavior changed; repeated family inputs retain the compiler's existing semantics.

## Regression coverage and RED evidence

`pkg/config/repeated_family_editor_12661_test.go` tests repeated compound, split, and mixed-shape family blocks (including compound-last and split-last order, repeated address-family children inside one split node, and an inactive split parent following an active compound block) for both inet and inet6. It checks effective filter and sampling behavior, atomic packed-split refusal, and exact preservation of distinct inet/inet6 families.

`TestElidedPackedFamilySiblingRefuses12661` covers packed family leaves in both sibling orders and checks that delete-family, delete-filter-input, set-filter-input, and deactivate operations refuse without mutation. `TestSplitElidedPackedFamilySiblingRefuses12661` repeats these operations with the packed `inet ...` leaf inside a split `family` node; it also verifies an `inet6` packed sibling does not block an `inet` set. `TestGroupsRepeatedFamilySetRefuses12661` locks in fail-closed handling for repeated family nodes under groups rather than assuming the filter/sampling first-wins rule.

The new blocker tests failed before the changes: compound and split B1 mutations returned success despite the packed sibling, and groups set returned success after editing one of the repeated family siblings. The post-fix blocker tests pass.

## Risk

Editor operations affect every structured repeated interface family sibling rather than only the first, matching compiler traversal. Under groups, repeated family paths are refused instead of guessing expansion precedence. Elided/packed siblings also refuse atomically; inet and inet6 remain separate.
