# #15660 - global policy match from-zone/to-zone short-circuit bypasses unsupported-leaf gate

- **Timestamp**: 2026-10-19
- **Cause**: `policyUnsupportedMatchLeafFindings` executed `if isGlobal && globalOnlyPolicyMatchLeaves[leaf] { continue }` before scanning the leaf's collapsed tail. Global `from-zone`/`to-zone` are `multi:true` leaves, so `match from-zone any dynamic-application junos:FTP` (flat set) collapses the unsupported criterion onto the zone leaf, and a hierarchical missing semicolon / bracket list (`from-zone any` + `to-zone untrust;`, `from-zone [ any to-zone untrust ]`) fuses the sibling zone keyword onto it. Strict commit then misdiagnosed the tokens as undefined/mixed zones (#4626/#3402 wording), and tolerant load published an unscoped permit with `LenientContentDropped=false`. Probe-verified on origin/master: flat-set fused forms do NOT collapse (SetPath stops at the registered sibling and compiles correctly as separate leaves); the fused shape is hierarchical-only, while the collapsed unsupported keyword reproduces in both forms.
- **Change**: `pkg/config/compiler_policy_match.go` — scan `firewallMatchValues(m)` for global-only leaves exactly like supported leaves (`supportedPolicyMatchLeaves[leaf] || (isGlobal && globalOnlyPolicyMatchLeaves[leaf])`): unsupported keywords (`dynamic-application`, `url-category`, `source-identity`, `dynamic-application-group`, `source-end-user-profile`) are flagged as unsupported leaves (#3113) and a fused `from-zone`/`to-zone` keyword as a swallowed structural token (#3673), so strict rejects with the correct diagnostic and tolerant load warns + sets `LenientContentDropped` (#5575 poison). Corrected the now-false "cannot arise in global scope" comment and the swallowed-token message wording. Legitimate zone lists (including a lone `any`) are never those keywords and still commit.
- **Not changed (deliberate)**: the report's second hunk — making `unresolvableScopeElement` / Rust `build_global_zone_scope` reject a scope mixing `any` with unresolvable tokens — is NOT implemented. The contains-`any` wildcard is documented design in three places (Rust `policy.rs` tolerant backstop for corrupt/mixed-version snapshots, Go `IsWildcardZoneSet`, #9410 mirror contract): the strict gate already rejects mixing `any` with concrete zones at commit (#4626), changing only the Go mirror would make `show security match-policies` diverge from the helper it mirrors (the inverse #9410 defect), and changing the Rust runtime would break its documented corrupt-snapshot degradation plus pinned tests (`["any","ghost"]` accepted in `policies_reject_zone_9410_test.go`). With the compiler fix, collapsed bogus tokens can no longer reach the snapshot as a clean scope; a hand-built/mixed-version `["any","ghost"]` snapshot remains the intentional wildcard backstop. `TestPolicyZoneRejectionMixedAnyScopeIsWildcard15660` pins this.
- **Regression coverage**: `pkg/config/compiler_policy_match_15660_test.go` — strict #3113 rejection (4 collapsed-unsupported cases, RED pre-fix with wrong-reason #4626/#3402 errors), strict swallowed-token rejection (3 hierarchical fused cases, RED pre-fix: silently committed), lenient warn + `LenientContentDropped` (flat + hierarchical), and legit-scope controls (explicit `any`, bracketed list, separate leaves — pass pre- and post-fix). `pkg/dataplane/userspace/policies_reject_zone_9410_test.go` gains the mixed-`any` mirror pin with a `[ghost]` control. Docs: `docs/config-schema.md` #15660 paragraph.
- **Validation**: RED on pristine origin/master (9 failing subtests, legit controls green); GREEN post-fix. `go test ./pkg/config/ -run 'TestPolicyMatch|TestGlobalPolicy|TestPolicyZone|Test.*3148|Test.*3142|Test.*3673|Test.*3113|Test.*11078|Test.*15200'` and `go test ./pkg/dataplane/userspace/ -run 'TestPolicyZoneRejection'` pass; full `pkg/config` + `pkg/dataplane/userspace` suites run by reviewer.
- **Risk**: Fail-closed only. Strict commit now rejects with the correct reason configs that previously committed silently (hierarchical fused) or with a misleading zone error; tolerant load still boots them with a warning but poisons the rule instead of publishing an unscoped permit. No wire, Rust, or wildcard-semantics change.
