# #9413: REST GET /api/v1/dhcp/leases omitted IA_PD delegated prefixes that gRPC reports

- **Timestamp**: 2026-09-11T02:25Z
- **Action**: Routed the REST lease table through the same aggregation the gRPC RPC uses, and added a field-parity contract.
- **File(s)**:
  - `pkg/api/dhcp.go`, `pkg/api/types.go`, `pkg/api/dhcp_leases_pd_9413_test.go` (new)
  - `pkg/grpcapi/server_dhcp.go`
  - `pkg/grpcapi/dhcp_leases_pd_only_5382_test.go` (rename only)

## Mechanism (origin/master `1820ffac3`)

REST `dhcpLeasesHandler` built its rows from `s.dhcp.Leases()` alone, and `DHCPLeaseInfo` had no delegated-prefix field. gRPC `GetDHCPLeases` aggregates `Leases()` with `DelegatedPrefixes()`. It attaches each IA_PD to the interface's inet6 lease, or synthesises a standalone inet6 row for a PD-only interface (#5382). So a DHCPv6 prefix-delegation-only WAN interface, a normal dual-stack deployment, showed an empty lease table over REST while gRPC and the CLI showed the delegation. The report's RFC 3442 classless-routes half was narrowed away in the issue, because gRPC and the CLI omit those too.

## Change

- **Shared builder.** `grpcapi.buildDHCPLeasesResponse` is exported as `BuildDHCPLeasesResponse`, with its doc saying it is the single aggregation behind both surfaces. `pkg/api` already imports `pkg/grpcapi`, and nothing imports the other way.
- **REST handler.** It now calls a pure `restDHCPLeases(leases, pds)`, which maps that response onto the REST types instead of keeping its own loop. That separate loop is what let the two surfaces diverge.
- **REST types.** `DHCPLeaseInfo` gains `delegated_prefixes` (omitempty), and a new `DHCPDelegatedPrefixInfo` carries `interface`, `prefix`, `preferred_lifetime`, `valid_lifetime` and `obtained`, mirroring the proto.
- **Unchanged output.** Pre-existing rows are identical. Address, gateway (only when valid), DNS (with `[]` for none), lease time and obtained were already formatted the same way on both surfaces, and an empty table still serialises as `[]`.

No docs change is needed: no REST API doc describes the leases JSON. `pkg/api/README.md` has no lease section, and `docs/phases.md` only records the protobuf fields.
