# #17258 — six-reader TPID canary and source census

- **Timestamp:** 2026-11-07
- **Branch:** `fix/17258-tpid-canary`
- **File(s):** `userspace-dp/src/afxdp/{ethernet.rs,mod.rs,parser.rs,parser_tests.rs,icmp.rs,icmp_ptb.rs}`, `userspace-dp/src/afxdp/cos/{ecn.rs,mod.rs}`, `userspace-dp/src/afxdp/frame/{README.md,headers.rs,inspect.rs,mod.rs}`, `userspace-dp/src/afxdp/mirror/{fast_path.rs,mod.rs}`, `userspace-dp/src/nat64/{frames.rs,mod.rs}`, `userspace-dp/src/test_support/source_scan.rs`, `docs/log/17258.md`

## Why

The userspace dataplane had seven TPID-read sites before this change because `icmp_ptb.rs` duplicated the byte-identical `icmp.rs::ingress_reply_l2` reader. The unified canary and source census need to cover every distinct reader, including the ICMP and mirror paths that were not in the old table, while retaining QinQ as a separate parser-shape contract.

## What

- Deleted the duplicate `icmp_ptb.rs` helper and routed its callers through `super::icmp::ingress_reply_l2`. The PTB builders use the same ICMP L2 reader as other local replies; there are now six reader implementations.
- Retired the duplicate TPID constants and re-export from `frame/headers.rs` / `frame/mod.rs`. `ethernet.rs` remains the canonical 802.1Q / 802.1ad constant pair; the serializer's no-tag/default path uses the canonical 802.1Q constant. No remaining users of `TPID_8021Q` or `TPID_8021AD` were found in `userspace-dp`.
- Added test-only `L2View` adapters and root re-exports for all six readers. `l2_offset_canary_all_parsers_agree` compares untagged, 0x8100, and 0x88a8 outer tags for IPv4 and IPv6 across:
  1. `afxdp/parser.rs::parse_eth_offsets`
  2. `afxdp/frame/inspect.rs::frame_l3_offset`
  3. `afxdp/cos/ecn.rs::ethernet_l3`
  4. `nat64/frames.rs::frame_l3_offset`
  5. `afxdp/icmp.rs::ingress_reply_l2`
  6. `afxdp/mirror/fast_path.rs::mirror_output_frame`

  `icmp_ptb.rs` has no separate reader row after deduplication; its callers route through the canaried ICMP reader in row 5. The existing `nat64_l2_offset_canary` remains, and NAT64 is also registered in the unified table. `l2_qinq_shape_contract_9888` remains outside that table: offset readers single-unwrap to 18 while `ethernet_l3` rejects nested tags.
- Added the six-entry source census registry and TPID-read counter. The counter binds each read to its containing function; every registered function must contain exactly one, so a sibling reader cannot satisfy a missing registry entry. It ignores test-only source (including `#[cfg(all(test, not(miri)))]` property-test modules) and fails when production source contains an unregistered seventh read.
- Updated `frame/README.md`: the canary, not parser unification, is the contract; the NAT64 path is `nat64/frames.rs`; no PR-2 parser-unification follow-up is required. The XDP shim drops 0x88a8-tagged frames today, so those canary rows preserve a latent contract if steering changes.

## Risk

No parser unification or forwarding behavior change is intended. The change removes an identical helper copy, routes PTB calls through the existing ICMP helper, and consolidates duplicate constant declarations. 0x88a8 is currently shim-dropped; its canary rows pin the latent 14/18-byte contract without changing current steering. QinQ remains a separate contract.
