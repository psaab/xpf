# DHCP relay statistics survive configuration restarts (#13277)

`Manager.Apply` and the DHCPv6 manager restarted per-interface relay objects
when a relay specification changed. Although the restart preserved pending
request bindings, the new relay objects reset all per-interface monotonic
counters and the pending table's eviction count.

The replacements now adopt every DHCPv4 and DHCPv6 per-interface atomic
counter after the prior relay has stopped, and carry cumulative pending-table
evictions alongside live request bindings. This applies only to a relay that
remains configured with a changed specification; removing an interface still
removes its statistics.

Regression coverage seeds all v4/v6 per-interface counters and pending
Evicted, changes the relay specification, and verifies the resulting stats.
The v4 regression failed against the unmodified implementation with each
counter reported as zero. `go test ./pkg/dhcprelay/...` passes after the fix.
