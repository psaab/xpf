# Issue #16566: DHCP lease persistence across graceful restart

- **Timestamp**: 2026-10-24
- **Action**: persisted every committed DHCP lease durably (`pkg/dhcp/lease_persist.go`: address, gateway, classless routes, DNS/domain-search, server-id/DUID, Obtained/LeaseTime, Renew/Rebind, delegated PDs; DurableState via `fsatomic.WriteFileDurable`, state file `dhcp-lease-<iface>-v4|v6`). `commitLease` and RA-state commits persist after the in-memory store; expiry/NAK/finishClient/inline teardown delete the file.
- **Action**: re-adoption at startup — `Manager.AdoptPersistedLeases` (one-shot latch, called from daemon `reconcileDHCPClients` before the first apply renders FRR/DNS/RA) plus a per-client backstop in `Start`. Adoption requires an unexpired lease and, for addressed leases, the kernel still holding the address (netlink AddrList, #15071 lifetime may have expired it); otherwise the file is discarded.
- **Action**: run loops resume in the renewal cycle — extracted `runV4RenewalCycle` / `runV6RenewalCycle` verbatim from `runDHCPv4` / `runDHCPv6` so an adopted lease's first wire message is a RENEWING REQUEST (v4) / RENEW (v6), falling back to DISCOVER/SOLICIT on expiry/NAK/NoBinding/refusal through the existing arms. `force-discover` v4 opts out of the resume RENEW.
- **Action**: corrected the false restart contract in `pkg/dhcp/README.md` (was: "no DHCP renew at startup", lease reuse unimplemented).
