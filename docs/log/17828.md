# 17828 — evict retired system syslog clients before reuse on revert

- **Timestamp**: 2026-10-28
- **Action**: A successful system-syslog client could remain cached when a
  changed same-endpoint configuration failed to construct. The preserving
  handler install then retired and closed that old client; reverting to its
  prior fingerprint reused the closed pointer and incorrectly cleared retry
  debt. The constructor-failure path now evicts the key regardless of the old
  fingerprint, forcing a fresh dial on revert. Added a regression cell for
  successful A → failed B at the same endpoint → revert A, including a send
  assertion and unchanged-apply zero-dial control.
- **File(s)**: `pkg/daemon/daemon_system.go`,
  `pkg/daemon/syslog_system_idempotent_16767_test.go`, `docs/log/17828.md`
- **Validation**: Regression RED/GREEN and neighboring named syslog-cell
  results are recorded in the PR body.
- **Risk**: A failed changed build no longer retains a cached client that is
  omitted from the preserving install and closed; the next healthy apply dials
  a fresh client. Successful healthy-host reuse and complete-build latching
  remain unchanged.
