# 17828 — evict retired system syslog cache entries before reuse

- **Timestamp**: 2026-10-28
- **Action**: A successful system-syslog client could remain cached after
  retirement. A failed same-endpoint configuration change closed the old
  client but left its prior fingerprint cached; reverting then reused the
  closed pointer and incorrectly cleared retry debt. A foreign handler swap
  or shutdown drain could likewise close a cached client while making the
  identity gate fail open into per-host reuse. Failed construction now evicts
  the key regardless of fingerprint, and cache entries whose client identity
  is no longer installed are removed before reuse. Added regression cells for
  successful A → failed B → revert A and external `SetClients(nil)`, including
  send assertions and unchanged-apply zero-dial controls.
- **File(s)**: `pkg/daemon/daemon_system.go`,
  `pkg/daemon/syslog_system_idempotent_16767_test.go`, `docs/log/17828.md`
- **Validation**: Regression RED/GREEN and neighboring named syslog-cell
  results are recorded in the PR body.
- **Risk**: A failed build no longer retains a cached client that the
  preserving install closes, and cache entries absent from the handler's
  installed set are discarded before reuse. Healthy clients still installed
  for successful host builds retain per-host reuse.
