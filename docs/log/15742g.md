## Root cause

Split-RG flow-backed miss on the LAN node (fw1):

1. FIB has no forwarding default, so resolution stays
   `ClusterTerminalHAInactive` through the miss arm.
2. The HAInactive redirect arm (poll_descriptor ~7083) does not match
   it; `should_seed_fabric_punt` (fabric.rs) required the
   post-redirect `FabricRedirect` spelling, so **no punt seed** was
   installed for the flow.
3. The safety net (poll_descriptor ~8612) converted only `HAInactive`
   (and required `egress_rg > 0`, which a cluster-terminal resolution
   cannot satisfy — its egress is zeroed), so the request only left via
   TX-time handling without any local authorisation for the return.
4. fw0 adjudicates, forwards, NATs, replies over fabric in ~ms; fw1 has
   no session (HA sync ~200 ms) and no seed, so the reply is a
   session-less `wan -> lan` packet → default-deny / local drop.
   Every flow, indefinitely, for as long as the split lasts.

## Fix

- `forwarding/fabric.rs`: `should_seed_fabric_punt` accepts
  `ClusterTerminalHAInactive` alongside `FabricRedirect` (unchanged
  `!fabric_ingress` and no-ingress-NAT gates — the seed stays
  unforgeable and tuple-exact).
- `poll_descriptor/mod.rs` (flow-backed miss): the HAInactive redirect
  arm now also matches `ClusterTerminalHAInactive`, captures seed
  eligibility on the pre-redirect disposition, and installs the punt
  seed after converting to FabricRedirect (the seed else-if is
  unreachable after that arm by else-if construction).
- `poll_descriptor/mod.rs` (tail safety net): also converts
  `ClusterTerminalHAInactive`, attributing egress RG via
  `source_ifindex` (the disposition zeroes egress by construction).
- Note: the live cluster's LAN→WAN flow carries interface SNAT, so the
  NAT-free seed gate still refuses that exact shape; the redirect
  conversion is what restores the request path live, and the seed
  covers NAT-free split flows. Live acceptance will confirm.
- No wire/protocol change (no v59 bump): seed is local session state,
  the redirect frame is byte-identical.
