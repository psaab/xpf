# Issue #12225 — keep AppID-on/off labels aligned for unreferenced overlaps

## Why

When AppID was disabled, the tuple fallback considered every configured user app, but `appNames` contained only policy-referenced names. An unreferenced app whose natural ID collided with another app therefore fell back to its natural hash instead of the ID assigned from the full AppID-on catalog. For the `svc-217`/`svc-396` collision, this could select a different app than AppID-on; with the pair alone, strict `<` also left equal-ID ties dependent on Go map iteration order.

## What changed

- On a same-specificity tie involving a natural-ID collision, resolve candidates using `config.AssignStableAppIDsQuiet` over the full predefined-plus-user-application universe, matching AppID-on catalog assignment without emitting a catalog-build warning for each session.
- Keep the existing fast path for non-colliding names and single matches; add an explicit name tiebreak when IDs compare equal so any unresolved equal-ID case is deterministic.
- Added a regression for the colliding pair and triple behind an `application any` permit. It verifies AppID-off catalogs no referenced names, AppID-on selects `svc-396` at ID 1, and the off-mode label agrees repeatedly.
