# #16518: paged owner-RG export applied stale per-page helper status over a disarm

- **Timestamp**: 2026-10-24
- **Action**: `ExportOwnerRGSessionsPaged`
  (`pkg/dataplane/userspace/owner_rg_export_paging_9344.go`) dropped
  `m.mu` for each page RPC and applied the page's attached helper status
  on re-lock behind only a proc/procGen/generation/socket fence. A disarm
  queued behind the page on `controlReqMu` applied its fresh DISARMED
  status first, and the pager then overwrote it with the older ARMED page
  status — `userspace_ctrl.Enabled=1` and
  `lastStatus.ForwardingArmed=true` while the helper was disarmed, until
  the next page reply or the 1 Hz poll. Both production callers
  (`pkg/daemon/daemon_ha_userspace_export.go:72,133`) discard the returned
  status, so every page request now sets `SuppressStatus: true` and the
  pager never applies an attached page status; it re-reads the cached
  `m.lastStatus` after the generation fence instead. Helper truth keeps
  flowing in RPC order through the 1 Hz poll and the explicit state
  verbs, keeping `applyHelperStatusLocked` the single writer.
  NOT changed: the unpaged `ExportOwnerRGSessions` still applies its
  single response's status while holding `m.mu` across the RPC, so no
  ordering gap exists there.
