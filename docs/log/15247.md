# #15247 - userspace-dp neighbor-cache learn hygiene (A66-03, A66-04)

- **Timestamp**: 2026-10-19
- **Action**: (A66-03) XSK ARP/NDP learns in `poll_stages.rs` (`outline_arp_reply_learn_and_program` / `outline_ndp_na_learn_and_program`) now gate the advertised sender/target with `src_ip_on_link_for_ingress` (link-local `169.254/16` / `fe80::/10` excepted) so an off-link advert is no longer learned (ARP still recycled, NA still transits), and the learn installs through new `insert_arp_reply_if_solicited_allows_at` / `insert_ndp_na_if_override_allows_at` in `sharded_neighbor.rs`, which stamp the record with an RX-style lease (`NeighborRecord::xsk_learned`). Same-MAC re-adverts refresh the lease monotonically; kernel-monitor inserts keep the authoritative (lease-free) form and `mark_kernel_backed_if_same` still promotes a matching XSK entry to kernel-backed, so only un-backed XSK learns drain via the existing `age_rx_learned_neighbors` sweep instead of pinning the per-shard learn cap forever. (A66-04) `KernelNeighborProgramLimiter` gains a single newest-wins `owed` slot: when every way of a bucket is hot and a genuine change is refused, the binding is recorded (no way timestamp touched, so the #5288 aggregate cap is preserved) and the next exact same-binding advert retries it as owed even though the userspace map reports `map_changed == false`; a different binding for the same key supersedes it, and the limiter module doc no longer claims the false "retried on a later advert" behaviour for the dropped case.
