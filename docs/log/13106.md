# Issue #13106 — reject nested host-inbound value blocks (D1-01)

- **Issue:** The compiler's `hostInboundExceptParts` skipped non-`except`
  children below a `system-services` or `protocols` value. For an authored
  `all { ssh except; }`, it discarded the nested `ssh except` and retained
  `all`, silently widening host-inbound admission. The schema also modeled
  both leaves as childless value tails and did not inspect nested descendants.
- **Source:** Deep-review D1-01, High severity, EXECUTED/MATERIAL; three-way
  adversarial research validated the finding. Source report:
  `/var/tmp/deep-review-reports/gemini-4-argon-high-review-zone-enforcement-001.md`
  §2. The issue's source report confirmed the defect remained on master at
  `ba3ba7dd949763046d136f309d469127c3c6c26e`; the fix worktree started at
  `aea7b2b64`.
- **What:** The shared host-inbound parser now reports unsupported nested
  children into `UnknownChildren` and clears the affected service/protocol
  admission dimension during tolerant compilation, rather than retaining an
  unqualified parent such as `all`. Schema validation rejects unsupported
  nested value blocks while preserving supported `X { except; }` syntax.
  Strict compilation checks unknown children on both zone and per-interface
  stanzas. Added regression coverage for services, protocols, malformed
  `except` children, per-interface overrides, and valid existing exclusion
  syntax.

## Scope and impact

- Invalid nested syntax now fails strict schema/compile validation. On tolerant
  load, the affected `system-services` or `protocols` dimension is removed,
  while the diagnostic is retained; this preserves bootability without
  accidentally admitting services through a discarded exclusion.
- Supported flat-tail and `X { except; }` exclusions retain their existing
  behavior. No runtime wire format or dataplane changes.
