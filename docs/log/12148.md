# #12148 — include address family in stable exporter IDs

- **Issue**: #12148 — family-split NetFlow v9 groups can share SourceID and expose independent sequence streams as one collector stream.
- **Branch**: `fix/12148-exporter-id`
- **Worktree**: `/var/worktrees/12148-exporter-id`
- **Base**: `1c384b9a47ff7d6e567fa50632faa75c3995ae87`

## Why

#6811 split a sampling instance's collectors into per-family groups but left the address family out of `stableExporterID`. #3740 had made the stable ID depend on protocol/instance/template only. A same-instance, same-template inet/inet6 pair targeting one collector therefore had identical IDs. For NetFlow v9, collectors commonly identify streams by exporter source IP plus SourceID, so the groups' independent sequence counters could be reported as loss or restarts. IPFIX over UDP has a Transport Session including ports; distinct family ODIDs are still used consistently, without claiming a conforming collector would merge those IPFIX sessions.

## What

- Extended `stableExporterID` with `GroupIsV6`; inet hashes retain the prior input (`protocol|instance|template`), while inet6 hashes add `|v6`.
- Plumbed the family bit through the NetFlow v9 and IPFIX constructors. The unnamed inet default remains ID `1`; an inet6 group receives a family-specific ID even when the hand-built config identity is empty.
- Added loopback-wire regression cells for both protocols, including the real resolver path with one instance, one template, and the same collector address configured under both families. Added a migration pin for unchanged inet IDs and deterministic, distinct inet6 IDs.
- Updated `pkg/flowexport/README.md` and the source comments to document the family identity and migration.

## Risk / remaining acceptance

Only inet6 SourceID/ODID values change; existing inet exporter IDs stay stable. Collector dashboards or filters keyed on an inet6 ID may need updating; templates are re-announced automatically. No live cluster was mutated. IPFIX UDP sessions remain distinguishable by their transport ports; the ODID change is a consistent family-specific identity, not a claim of an IPFIX collision under RFC 7011.
