# Bound the global Basic lockout with a successful-verify probe (#16068)

- **Issue**: #16068 (A8-08, split from #15987). Validated Low.
- **Cause**: The REST Basic throttle reserved against the global per-username
  bucket before verification (5 failures/10 min → 5 min lockout doubling to
  1 h). Anyone who could reach an off-loopback web-mgmt leg and knew a
  username could keep that user locked out of REST Basic auth indefinitely
  by re-spraying after each expiry, even though the legitimate user knew the
  correct password.
- **Change**: When ONLY the global Basic bucket is locked (the caller's
  per-source+account pair and source-prefix buckets are clean), the attempt
  is admitted as a bounded probe: at most one concurrent credential verify
  per locked username (`authThrottleGlobalBasicProbes = 1`), still paying
  the full bcrypt cost. A successful probe clears-then-admits the global
  bucket (and its own pair), exactly like a normal clean success. A failed
  probe is charged to its pair/source buckets like any other attempt, but
  `chargeLocked` drops the failure while the global bucket is still locked,
  so wrong-password probes never extend the existing lockout deadline.
  Pair and source lockouts remain hard pre-verification refusals: a correct
  credential from a locked pair/source can never rescue it, so the #11492
  anti-spray and #10825 bcrypt-CPU caps are preserved.
- **Regression coverage** (`pkg/api/auth_throttle_10825_test.go`):
  `TestRESTAuthGlobalBasicAccountBudgetAcrossSources11492` now expects the
  decisive #16068 check — 5 bad `operator` passwords from distinct sources,
  then the correct password from a new source returns 204 instead of 429;
  `TestRESTAuthGlobalBasicProbeWrongPasswordKeepsLockout16068` pins that a
  wrong-password probe is admitted, charged, and never extends the lockout;
  `TestRESTAuthGlobalBasicProbeCapAndPairLockout16068` pins the single
  concurrent-probe cap, the pair-lockout pre-verification refusal (verifier
  never runs), and that a successful probe clears the global bucket.
- **Blast radius / risk**: Only requests whose sole locked bucket is the
  global Basic bucket change path: they now pay one bounded verify instead
  of an immediate 429. All other lockouts, the 4096-entry bound, escalation,
  and the API-key/Bearer/malformed namespaces are unchanged.
