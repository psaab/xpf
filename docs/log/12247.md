# 12247 — use the three-view union for tolerant zone quarantine

- **Issue:** #12247 — tolerant quarantine must use the same main-plus-node zone-name union as strict collision validation.
- **Base:** `a714c90d472a3c3d98a3799831cfef3ec311a61c`
- **Branch:** `fix/12247-quarantine-union`

## Why

Strict zone-ID collision validation sees the main configuration and both node views, but tolerant quarantine previously recomputed the collision set from each node snapshot independently. When a colliding name existed only in the peer node's view, the other snapshot could retain a conflicting zone rather than applying the same deterministic survivor decision.

## What changed

- Preserve the sorted three-view zone-name union in compiled config metadata, including tolerant compilation.
- Use that union when deriving quarantine exclusions and when sanitizing node snapshots, so all node views agree on the collision winner.
- Add an isolated two-node regression: `z174` exists only in node0 and `z214` only in node1; both collide by stable zone ID. The test checks the union is retained by both compiled views, config exclusions drop only `z214`, and the peer snapshot records `z174` as survivor and removes `z214`.
- Update runtime consumers of quarantine-derived exclusions to use the same config union.
