# #13978 — prevent WireGuard outer dst-MAC adjacency borrowing

The WireGuard transit encapsulator resolved the peer endpoint's underlay
route for source MAC, VLAN, and source IP, but fell back to the session's
stored neighbor MAC when the selected peer route had no neighbor entry. In a
multi-underlay or on-link-peer case this could transmit a frame on the peer's
physical egress addressed to a different adjacency.

The encap builder now requires a neighbor MAC from the selected peer's outer
route. A missing neighbor fails closed (`None`) instead of borrowing the
session adjacency. The regression omits the selected peer next-hop neighbor
while supplying a distinct session adjacency, and asserts no frame is emitted.

Validation: the regression passed with the fix and failed when the old fallback
was restored. The full `afxdp::frame::wg::tests::` module passed (28 passed,
0 failed), including the existing physical-WAN test whose `#[test]` attribute
is retained. Existing tests expecting a frame now seed the peer underlay
neighbor explicitly. Production `cargo check --bin xpf-userspace-dp` completed
with existing warnings. The repository's current coordinator fixture has an
unrelated type error (`maps.local.insert(inner_dst)` passes an `IpAddr` to a
`HashSet<(u32, IpAddr)>`); for local test execution only, the expression was
temporarily changed to `(lo, inner_dst)` and restored afterward. No live lab
capture was performed.
