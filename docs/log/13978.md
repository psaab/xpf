# #13978 — prevent WireGuard outer dst-MAC adjacency borrowing

The WireGuard transit encapsulator resolved the peer endpoint's underlay
route for source MAC, VLAN, and source IP, but fell back to the session's
stored neighbor MAC when the selected peer route had no neighbor entry. In a
multi-underlay or on-link-peer case this could transmit a frame on the peer's
physical egress addressed to a different adjacency.

The regression was RED on revert: restoring the old `.or(decision.resolution.neighbor_mac)?` fallback caused the test to panic because it emitted a frame. With the fix, the regression passes. The full `afxdp::frame::wg::tests::` module passed (27 passed, 0 failed) after adding explicit peer-next-hop neighbors to fixtures whose expected output includes an encapsulated frame. The repository's current coordinator test fixture has an unrelated compile error (`maps.local.insert(inner_dst)` passes an `IpAddr` to a `HashSet<(u32, IpAddr)>`); for local test execution only, that expression was temporarily changed to `(lo, inner_dst)` and restored afterward. Production `cargo check --bin xpf-userspace-dp` completed with warnings only. No live lab capture was performed.
