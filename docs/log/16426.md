# #16426 — vrrp: keep VID-0 priority-tagged native adverts on untagged parent

- **Timestamp**: 2026-10-24
- **Investigation**: Confirmed at `origin/master@ce4445ddcb`.
  `receiverAfPacket` (`pkg/vrrp/instance_receive.go`) dropped any frame
  whose `PACKET_AUXDATA` carried `TP_STATUS_VLAN_VALID` on a non-VLAN
  netdev, without testing the VID — a #15049 regression. A peer advert
  priority-tagged on the wire (VID 0, PCP 6 => TCI `0xC000`) is stripped
  into skb metadata with `VLAN_VALID` set exactly like a VLAN-100 advert,
  so the backup never heard the master, its master-down timer expired,
  and both nodes held the VIP (dual MASTER). Linux treats VID 0 as
  native: only a non-zero VID marks a frame for a VLAN sub-interface.
  The #15049 harness also could not express the case: `auxdataOOB`
  returned nil for TCI 0, conflating "no auxdata" with "VLAN_VALID, VID 0".
- **File(s)**: none (investigation only)

- **Timestamp**: 2026-10-24
- **Action**: Fix in worktree `/var/worktrees/wt-16426` (branch
  `fix/16426-vrrp-vid0-priority-tag`): (1) the parent drop now requires
  a non-zero VID — `tagged && tci&0x0fff != 0` — masking off the PCP/DEI
  bits, so VID-0 priority-tagged native adverts are enqueued while
  stripped VLAN-N sibling adverts still drop; (2) the
  `vlan_tag_present_15049_test.go` harness gains `hasAuxdata` on
  `vlanDelivery` and `auxdataOOB` now always encodes `VLAN_VALID` (for
  any TCI including 0), so a VID-0 delivery is expressible; a native
  untagged delivery is modelled as no cmsg. New acceptance test
  `TestReceiverAfPacketParentKeepsVID0PriorityTaggedAdvert_16426`
  covers PCP6/VID0 (`0xC000`), TCI 0 with `VLAN_VALID`, and the
  VLAN-100 reference (still drops). NOT changed: the optional
  "only when the parent actually has tagged VRRP siblings" refinement —
  the VID mask alone restores the #15049 contract, and sibling
  enumeration would add config coupling for no behavioural gain on
  VID-N frames (they still drop unconditionally).
