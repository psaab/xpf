# Issue #14690 — Case-sensitive WireGuard peer public-key comparison

## Finding

`isWireguardKeyHex` accepts both hex cases and Rust `decode_wg_key_hex`
decodes both to identical `[u8;32]`, yet Go maps keyed on raw
`PublicKeyHex`: `seen`/`prefixOwner` in `validateOneWireguardTunnel`,
`inherited`/`owners`/`mergedPubkeys`/`prefixOwner` in
`validateMergedWireguardUnitPeers`, and `seen` in
`mergeWireguardUnitPeers` (`tunnelemit.go`). Typed configs that bypass
parser lowercasing (`parseTunnelWireguardPeer` already lowercases the
authored path, as do group-merge canonical identities) could pass commit
with mixed-case duplicates, emit both spellings, then violate Rust
`reconcile_peers`' duplicate-pubkey invariant (debug panic; release
AllowedIPs mis-index / `AllowedIpsViolation` blackhole).

Note on authored path: `CompileConfig` with lower in one place and upper
in another was already rejected on current master because the parser
lowercases both before validation — verified: the strict-compile test
passed pre-fix. The decisive RED is the direct/typed paths above.

## Fix

Add `canonicalWireguardPubkeyHex` (`strings.ToLower`) in
`compiler_validate_wireguard.go` and key every pubkey uniqueness,
ownership, and merge map/comparison on it, in both validators and
`mergeWireguardUnitPeers`. `prefixOwner` values are also stored canonical
so a case-variant of the owning peer is not a distinct prefix owner.
Authored `PublicKeyHex` and error rendering are unchanged.

  authored peer compiles to one lowercase peer.
