# #17270 — Unify AST redaction site traversal

- **Timestamp**: 2026-11-07
- **Why**: At base `99cb6b34ec` (`origin/master` for this lane), five recursive walks and three embedded-payload locators repeated the same security-sensitive path decisions. #14413 added embedded redaction to display and compare, while #15209 later had to add an independent ingest-guard mirror. The two masking consumers with no failing `pkg/config` test were also mutation-tested: deleting embedded handling from the scoped walker (R1) and skipping embedded block children in compare (R4) both left the focused redaction selection green.
- **What**: Added one `walkSecretSites(nodes, base, visit)` that computes each flattened path, secret indices, URL indices, and embedded payload sites once for that traversal. Masking, fingerprint compare, and the ingest guard consume that same per-node inventory. Replaced the three embedded locators and their per-child handlers with `forEachEmbeddedPayload` plus one payload processor; scoped display now calls `redactNodes` with its actual ancestor prefix. Added a site-class regression matrix spanning direct secret/URL leaves and quoted, joined-tail, and block payloads across clone, scoped, inheritance, compare, and ingest-guard consumers.
- **File(s)**: `pkg/config/ast_redact.go`, `pkg/config/ast_redact_test.go`, `pkg/config/node_key_invariant_17263_test.go`, `pkg/config/ast_redact_embedded_ingest_15209_test.go`, `pkg/config/ast_redact_rpm_target_14379_test.go`, `pkg/config/redacted_inheritance_15979_test.go`, `pkg/config/schema_walk_entry.go`, `pkg/config/schema_walk_secret_echo_8434_test.go`, `docs/log/17270.md`.

**Master checks and behavior choices.** At `99cb6b34ec`, the #14413 embedded mask and compare calls are present and the #15209 guard already scans embedded secret placeholders and URL sentinels; these are historical fixes, not new redaction decisions in this refactor. The report's joined-tail provenance discrepancy (mask conditional vs compare unconditional clearing of `KeysQuoted`) is also absent at this base: both current joined-tail paths call `replaceKeys(..., nil, nil, false)`. The shared `embeddedPayloadSite.replace` keeps that behavior: changed joined tails are re-tokenized and stale positional quote provenance is cleared. No current output-level decision mismatch was found between the masking copies. Differences that remain are intentional mode differences: secret masking vs compare fingerprint metadata vs guard detection; the guard keeps secret-placeholder priority over URL errors, and secret wins any overlap with a URL site. URL-bearing tails that cannot be judged still use the existing whole-payload fail-closed mask.
