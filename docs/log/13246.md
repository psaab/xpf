# 13246 — Correct NAT display and interface-pool statistics

## Diagnosis

Four copied NAT output paths had drifted from their corrected siblings. The
CLI's short source-pool view printed an invented default `1024-65535` range
for `port no-translation`; the default destination view omitted plural and
named destination-address matches and did not show the actionless/off action;
the destination rule-set and all-rules views labeled actionless DNAT as `off`.
REST and gRPC interface-pool statistics emitted one identical `<from>-><to>`
row per interface rule, repeating the full zone-pair session count. The gRPC
rule-statistics action field had the same actionless-as-off drift.

## Changes

- The short source-pool view now explicitly identifies `no-translation` and
  only prints the defaulted port range for PAT pools.
- Destination CLI views use the shared destination-address matcher and shared
  `natshow.DestRuleAction` spelling. Actionless rules display `none`, explicit
  `off` remains `off`, and pool actions preserve their established output.
- The shared destination action renderer is used by detailed text output and
  gRPC destination rule statistics, preventing their action spellings from
  drifting.
- REST and gRPC pool-statistics handlers deduplicate interface pools by their
  from/to zone pair, preserving the one-row summary contract and the correct
  per-pair `UsedPorts` count.
- Added regression tests for the four display/statistics defects, including
  pool/action controls, destination gRPC action parity, and duplicate-row
  checks on REST and gRPC.
