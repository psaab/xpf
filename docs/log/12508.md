# Issue #12508 — interface filter/sampling editor follows compiler

## Contract and change

Issue #12093 made the inet/inet6 interface compiler read every `filter`
sibling in authored order. Repeated filter leaves therefore resolve to the
last value. Interface-family `sampling` siblings are unioned. Before this fix,
`SetPath`, `DeletePath`, and deactivate/activate descended into or changed only
the first matching sibling, so editing a repeated configuration could leave the
compiled binding unchanged or leave a later binding active.

The editor behavior is now scoped to the `filter` and `sampling` schema nodes
under interface-family `inet` and `inet6` in `pkg/config/ast_edit.go`:

- `set` reuses the last active matching sibling. If the last active sibling is
  a compact leaf, it appends a compiler-visible container. With no active
  sibling and an existing eligible inactive statement, it edits that statement
  rather than creating an active copy. Under `groups`, it keeps first-match
  editing because apply-groups expansion reads the first scalar sibling.
- Bare `delete` removes all matching siblings. A targeted filter direction or
  sampling direction removes matching bindings from every sibling and compact
  leaf. If the targeted value exists only in a later sibling, its deletion can
  expose an earlier sibling's value; bare delete removes every copy. Missing
  deletes still wrap `config.ErrPathNotFound`.
- Bare `deactivate`/`activate` toggles every matching sibling; targeted
  operations toggle the matching binding in every sibling. The existing
  deactivate not-found error shape is unchanged.

This does not change the compiler, schemas, filter value validation, or the
forwarding-options sampling schema. Last-sibling set remains scoped to
interface-family `inet` and `inet6`; delete and toggle cover all matching
siblings at those sites.

## Regression coverage

`pkg/config/interface_filter_editor_12508_test.go` covers four filter shapes
for both `inet` and `inet6`: hierarchical repeats, compact repeats,
compact-then-block, and block-then-compact. It verifies last-value set behavior
and filter/sampling bare and targeted delete/deactivate operations. A
value-naming filter delete also pins the Junos-visible behavior that deleting
later value `B` can expose earlier sibling value `A`. Group-body tests pin set,
delete, and deactivate results for hierarchical and block-then-compact repeats.
Other cases cover set-into-inactive filter and sampling statements, including
compact leaves; targeted filter activate; and refusal of packed filter/sampling
deletes without mutation.

The lo0 regression starts with repeated inet and inet6 filter blocks, deletes
the binding container, verifies the compiled lo0 binding is empty, then sets
`input C`. It asserts the AST has exactly one filter sibling and the compiled
`System.Lo0FilterInputV4/V6` is `C`.

## lo0 upgrade path

This is an active control-plane path, not merely a config display concern:
`compileInterfaces` iterates interface children without a lo0 exclusion
(`pkg/config/compiler_interfaces.go:67-82`); `resolveDerivedConfig` hoists
unit-0 lo0 filter inputs into `System.Lo0FilterInputV4/V6`
(`pkg/config/compiler_derivations.go:103-107`); and `applyLo0Filter` consumes
those fields (`pkg/daemon/daemon_nft.go:144-157`). The userspace filter
compiler maps an empty lo0 filter name to `Ok(None)`
(`userspace-dp/src/filter/compiler.rs:447-453`). The regression proves the
editor's delete-then-set consolidation reaches the values used by those
runtime paths. No live-cluster or packet-path validation was performed.

## Fail-on-revert evidence

With the first-sibling `SetPath` descend restored as a source-only mutant,
`go test ./pkg/config -run '12508|12093'` failed the #12508 matrix:

- hierarchical repeats and block-then-compact compiled `B`, wanted `C`;
- the sampling editor test found `output` was not placed in the last sibling.

The same mutant left both compiler pins green: `go test ./pkg/config -run
'12093'` and `go test ./pkg/configstore -run '12093'` passed. Restoring the
last-sibling editor behavior made the #12508 tests pass. The test files were
unchanged during the mutant run.

Additional source-only mutants were killed by the focused regressions:

- `set-first`: `TestInterfaceFilterEditorLastWins12508` failed hierarchical
  and block-then-compact inet/inet6 cases (`B`, wanted `C`).
- `groups-last-sibling`: `TestInterfaceFilterGroupsEditorPreservesFirstCompilerSibling12508`
  failed set cases for both shapes (effective `A`, wanted `C`).
- `del-off`: `TestInterfaceFilterEditorDeleteAndDeactivate12508` retained
  older filter and sampling bindings across the inet/inet6 shape matrix.
- `toggle-off`: the same matrix plus `TestInterfaceSamplingDeactivateAllSiblings12508`
  and `TestInterfaceSamplingDeactivateTargetedSibling12508` retained bindings
  or failed to locate later bindings.
- `no-inet6`: `TestInterfaceFilterEditorLastWins12508` failed both inet6
  shapes (`B`, wanted `C`).
- `set-no-inactive-guard`: the hierarchical filter, compact filter, and
  inactive sampling tests found newly-created active siblings instead of
  updating the sole inactive statement.
- `packed-guard-off`: `TestInterfaceFilterSamplingDeleteRejectsPackedStatements12508`
  received no refusal for either packed filter or sampling delete.

The strengthened lo0 regression is red on base `4a17e0d29`: running
`TestInterfaceFilterLo0Consolidation12508` there leaves compiled lo0 filter
`B` after delete for both inet and inet6, where the test requires empty.
