# #14960 - HA bulk export preserves fabric flag, session_id, and failover sessions (D26-04)

- **Timestamp**: 2026-10-18
- **Action**: `Coordinator::snapshot_all_sessions_export` (`userspace-dp/src/afxdp/ha/export.rs`) now mirrors the owner-RG export admission set (`SessionTable::iter_export_budgeted`) instead of its own narrower ad-hoc filter. (1) `fabric_redirect_sync` is derived from the row's disposition instead of hardcoded `true`, so a plain `ForwardCandidate` is no longer encoded with `FLAG_FABRIC_REDIRECT` (both encoder legs OR the field with `disposition == FabricRedirect`, and the Go side routes flagged, non-fabric-ingress deltas through the fabric-redirect ownership branch). (2) `session_id: entry.session_id` replaces the hardcoded `0` — the shared entry has carried the originating node's stable #5212 id since the import threading, so the peer adopts it instead of minting a divergent RT_FLOW id. (3) The `is_peer_synced` and `fabric_ingress` skips are removed and the disposition allowlist gains `NoRoute`/`MissingNeighbor` (#10790): after a demotion `demote_shared_owner_rgs` retags surviving rows `SyncImport`, so the old filter dropped exactly the failover/fabric/unresolved population this peer-connect export exists to serve. (4) Node-local rows that must never cross HA are now excluded — `TunOrigin` (#10038) and transient seeds (#7770) previously leaked, and `WorkerLocalImport` replicas are skipped as in the owner-RG walk. Neighbouring behaviour preserved: reverse companions, terminal `PolicyDenied` rows, and inactive-RG rows stay excluded; the RG-active gate, PPTP pair, close/handshake stamps, and the #6654 poison-recovering lock are untouched. No wire-format change.
- **Validation**: New regression `bulk_export_preserves_fabric_flag_session_id_and_failover_sessions_14960` (`afxdp/ha_tests.rs`) seeds ten shared rows (plain RG-0 control, SyncImport failover, fabric-ingress, NoRoute, MissingNeighbor, FabricRedirect, TunOrigin, FabricPuntSeed, reverse, PolicyDenied) and asserts the exported set plus per-delta `session_id`/fabric-flag stamps. RED on `origin/master` (`b8f1ff7ac9`): exported ports `[55101, 55106, 55107, 55108]` vs expected 6 — failover/fabric/unresolved dropped, TunOrigin+seed leaked. GREEN after the fix. Controls: `cargo test --bin xpf-userspace-dp -- bulk_export` (11 passed, incl. #14303 PPTP pair and #6654 poisoned-mutex), `owner_export_retains_imported_noroute_and_missing_neighbor_sessions_10790` (1 passed), full `afxdp::ha::tests::` module (167 passed).
- **Risk**: The bulk export now sends more rows on peer connect (peer-synced, fabric-ingress, unresolved). This is the owner-RG export's already-shipped set, so the peer's import path has handled these shapes; volume grows only by rows the old filter wrongly suppressed. `session_id` remains 0 for local-origin publishes that never stamped the shared entry (documented alloc-fallback sentinel, rolling-upgrade safe). No Go changes.
