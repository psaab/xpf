# #17052: consolidate failover announcement engines

- **Timestamp**: 2026-10-27
- **Action**: Failover announcement ran on two mode-selected engines —
  `pkg/vrrp` `sendGARPReservedMode` (VIP-only, per-instance epoch dedup /
  500 ms dampener / `vipMu` + `markGARPAnnouncedLocked` bookkeeping) and
  daemon `directSendGARPs` (VIP + router-LL NA + pool GARP/NA) — with the
  #5695 clamp duplicated in both. Fixes landed in one engine only in both
  directions (#2377→#3922, #2867→#2898), and the router-LL NA (#15684)
  and IPv6 pool NA (#12172) existed only in direct mode, so legacy VRRP
  mode never sent them. Consolidated onto one shared engine while
  preserving each mode's semantics/timing:
  - `pkg/cluster/announce.go` (new): `AnnounceTarget{Iface, IP,
    Kind(VIP|RouterLL|PoolV4|PoolV6), Burst, ProbeIP}`,
    `AnnounceTargets(cfg, rgID, probeDerive)` (VIPs via the #17140
    single walk `Config.RethVIPsForRG`, router LL via the #17049
    placement `Config.RouterLinkLocalPlacements`, pool via the #17086
    SSOT `Config.RefRG`), `NonVIPAnnounceTargets`,
    `PoolAnnounceTargets`, `AnnounceTargetsFromVIPMap`, and
    `SendAnnounceTargets(targets, stillValid, sender)` which holds the
    frame sequence (VIP v4 GARP burst + gateway probe — probe fires
    even on GARP error, as both engines did, and never counts as
    announced; VIP v6/router-LL NA burst; pool single-frame with the
    #8405 64-attempted bound and mid-sweep `stillValid` fence) and the
    single announce-path `ClampGratuitousARPCount` call
    (`AnnounceBurstCount`/`EffectiveAnnounceBurstCount`).
    `GatewayProbeTarget` stays in `pkg/vrrp` (no import cycle) and is
    passed in as `probeDerive`. Package placement is `pkg/cluster` per
    the issue's fix direction; the leaf-package placement proposed by
    the still-open sibling #17325 is its own later move.
  - `pkg/daemon/daemon_ha_vip.go`: `directSendGARPs` is now a wrapper —
    #2898 fence (`directBurstStillValid`) + per-RG clamp warn-once,
    then `SendAnnounceTargets(AnnounceTargets(...))` through the
    existing `direct*Fn` seams. New `sendVRRPModeNonVIPAnnounce` sends
    the non-VIP half in legacy mode, gated on `rgState.IsActive()`.
    `announceProxyARPPoolAddresses` delegates to
    `PoolAnnounceTargets`+sender (kept for the #8405/#12172 tests);
    pool-truncation warn-once split into `poolTruncWarned` so a clamp
    warning no longer suppresses the distinct truncation warning.
  - `pkg/daemon/daemon_ha.go`: VRRP MASTER arm
    (`tr.Changed && tr.Active`) now calls
    `sendVRRPModeNonVIPAnnounce(rgID)` after `addStableRethLinkLocal`,
    before `applyRethServicesForRG` — ordering preserved, announce
    added where none existed.
  - `pkg/vrrp/instance_garp.go`: `reserveGARPBurstGateLocked` takes
    its count from `cluster.EffectiveAnnounceBurstCount` (per-instance
    warn-once kept); `sendGARPReservedMode` builds one VIP
    `AnnounceTarget` per VIP and sends it via `SendAnnounceTargets`
    under `vipMu`, so epoch dedup, dampener, #14155 pending tracking
    and the mid-burst ownership fence are unchanged. NOT changed: the
    VRRP bookkeeping stays in `pkg/vrrp` (per the issue's adversarial
    analysis, only the target set + frame sequence needed sharing);
    the redundant `added` GARP in `reconcileProxyARP` is kept — it
    fires on config-commit adds, a different trigger than failover
    ownership, so folding it in would change commit-path timing.
  - `pkg/daemon/announce_parity_17052_test.go` (new): mode-parity test
    asserting the (iface, IP, kind) set announced on activation is
    identical in direct mode and legacy VRRP mode (VIP leg by the
    shared walk, non-VIP leg captured through the seams). RED with the
    legacy leg disabled (missing router-ll + pool-v4/v6), GREEN with
    the fix.
