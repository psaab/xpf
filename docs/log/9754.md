- **Timestamp**: 2026-09-12
- **Action**: FIX ORDERING, which the issue asks about explicitly. Measured
  rather than argued — the bind set and the default-instance next-table ingress
  set stay disjoint in all three spellings:

  | member | bind targets | `DefaultInstanceIngressIfaces` |
  |---|---|---|
  | `ge-0/0/0` (stanza spelling) | base + both children | `[]` |
  | `ge-0-0-0` (linux spelling) | base only | both children |
  | `ge-0/0/0.1` (unit reference) | `ge-0-0-0.50` | `ge-0-0-0.10` |

  So `DefaultInstanceIngressIfaces` needs no paired change: this fan-down is
  spelling-dependent in exactly the way that keeps the two aligned. The issue's
  warning was conditional on a fix that resolved members INDEPENDENTLY of
  spelling, and this one does not.

  **RESIDUAL, recorded not fixed.** The middle row is a pre-existing split: with
  the linux spelling the base lands in the VRF while the tagged units keep
  default-instance rules, so untagged traffic on the port routes in the VRF and
  tagged traffic does not. Both spellings commit (measured). Repairing it means
  making the linux spelling fan down too, which is exactly the
  "spelling-independent" path that requires the next-table set moved in the same
  change — a wider blast radius than this fix, and `InterfaceUnitRefKeys` is
  shared with zones and host-inbound.
