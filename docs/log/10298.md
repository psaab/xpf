# 10298 — Config archival host-key trust

## Boundary

Config archival previously invoked `scp` with `StrictHostKeyChecking=no`. The daemon already rendered `security ssh-known-hosts` to `/etc/ssh/ssh_known_hosts`, but the archival consumer ignored that trust file and accepted a presented key without verification. Because the archive is a cleartext copy of the active configuration, a man-in-the-middle endpoint could receive the full configuration, including secret leaves.

## Fix

- `scpArchiveTransfer` now fails closed when the rendered SSH trust file is absent or empty.
- Archival invokes `scp` with `StrictHostKeyChecking=yes`, `UserKnownHostsFile=<rendered ssh-known_hosts>`, `GlobalKnownHostsFile=/dev/null`, and `BatchMode=yes`; it omits the `scp --` separator (functional end-of-options, replaced by the guards below). Archive-site values beginning with `-` are rejected at both the existing commit-time compiler guard and the runtime transport boundary.
- A wrong endpoint key is rejected, while a key present in the rendered trust file succeeds. The daemon logs the transfer failure and never reports that archive as successful.
- Host-key rotation flow: configure the replacement key under `security ssh-known-hosts` for the archive host and commit it. The daemon rewrites its managed trust file before the next archival transfer. Remove the old key after the intended endpoints have moved to the replacement key; until the new key is trusted, `BatchMode` makes archival fail rather than prompt or accept it.

## RED then GREEN evidence

- Before the fix, `go test ./pkg/daemon -run 'TestScpArchiveTransfer10298' -count=1 -v` failed 4 tests: wrong-key transfer, missing-trust transfer, leading-dash destination, and real OpenSSH loopback transfer all unexpectedly succeeded.
- After the fix, the same issue-focused command passed: 4 tests, 0 failures. The real OpenSSH cell used `/usr/sbin/sshd` and `/usr/bin/scp`; the wrong rendered key was refused, then the rotated trusted key transferred the file successfully.
- The archival daemon slice (`go test ./pkg/daemon -run 'Archive|ScpArchive' -count=1`) passed 11 tests, 0 failures.
- The full daemon suite (`go test ./pkg/daemon -count=1`) passed 3,017 tests, 0 failures.
- An extra full configstore check (`go test ./pkg/configstore -count=1`) had 1,086 passing tests and one pre-existing failure, `TestUnknownSecurityStanzaIsStillAccepted8296` (#10078 fallout, owned by #10337); this lane changed no configstore source.
