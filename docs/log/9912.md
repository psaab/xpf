## Finding and boundary

`pkg/feeds/feeds.go` previously constructed `http.Client{Timeout: ...}`
without `CheckRedirect` or `Transport`. The standard client therefore followed
provider-selected cross-origin redirects and applied ambient `HTTP_PROXY`,
`HTTPS_PROXY`, and `ALL_PROXY`. The feeds package has no metrics registry or
counter for redirect drops, so the refusal is logged at WARN with the configured
origin URL redacted.

## Change

- `pkg/feeds/feeds.go:102-158` defines an origin predicate over scheme,
  hostname, and effective port; permits same-origin redirects; refuses
  cross-origin redirects; preserves net/http's ten-request redirect bound; and
  logs the refusal without rendering the provider-selected target.
- The redirect callback returns `http.ErrUseLastResponse`, so `readFeed` closes
  the retained 302 and reports only `unexpected status 302`; a provider-supplied
  Location cannot be copied into `url.Error` and then into feed failure logs.
- `pkg/feeds/feeds.go:246-252` supplies `&http.Transport{Proxy: nil}` so feed
  egress is direct regardless of ambient proxy variables.
- `pkg/feeds/feed_fetch_policy_9912_test.go` contains permanent cells for
  cross-origin refusal, ambient proxy bypass, same-origin redirect support, and
  direct fetch support. The proxy cell uses a fresh subprocess and the
  non-loopback synthetic origin `feed.invalid`; localhost proxy bypass cannot
  make it pass.
