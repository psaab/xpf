# #18863 — refresh the shared FRR CLI/daemon fixture contract

- **Timestamp**: 2026-11-02 (`wt-17474`, base `fed39c4bc1`)

## Why

The byte-exact shared fixture predates FRR output changes from #16620/#17699
(static and protocol distance 5), #17735 (RIP cannot share a routing table with
IS-IS), and #17893 (per-protocol redistribution guards). Both daemon cells and
both legacy CLI parity cells therefore failed against current renderer output.
The tenant fixture also placed RIP beside IS-IS in one routing instance, which
is no longer a legal input shape.

## What

- Keep IS-IS in the tenant RIB and move RIP out of that tenant fixture; retain
global RIP in the separate default RIB and remove global IS-IS there.
- Refresh the shared exact-byte expectations to current output, including
static distance 5 and per-protocol redistribution route-map guards. CLI and
daemon still compare against the same constants; no assertion was weakened.
- No production renderer behavior changed.

## Validation

- The original daemon parity cells were red before the fixture correction.
- Focused daemon tests passed:
  `go test ./pkg/daemon -run
  '^(TestAssembleFRRConfigInstanceProtocolsAndIPv6Statics11393|TestAssembleFRRGlobalFallback11455)$' -count=1`.
- Focused CLI parity tests passed:
  `go test ./pkg/cli -run
  '^(TestApplyToDataplaneGlobalFRRParity11455|TestApplyToDataplaneInstanceProtocolsAndIPv6Statics11393)$' -count=1`.
- Both commands were included in the final named regression-slice run with
  `TMPDIR=/tmp` and inherited `GOTMPDIR` unset.

## Risk

Only test input and expected output changed. The byte-exact CLI/daemon contract
continues to fail if either renderer diverges or if a stale/illegal protocol
combination returns.
