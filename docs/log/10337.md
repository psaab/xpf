# #10337: closedWorld post-arm false-reject cohort

## Change

The #10078 security-root closed-world arm exposed three compiler-read/test
shapes that had not been covered by the pre-merge audit:

- `security { flooby { ... } }` is now a strict operator-path reject, but the
  tolerant load/peer-sync paths continue to warn and load it. The former
  #8296 cell was rescoped to assert that lenient contract, and a separate cell
  pins the strict reject and token naming.
- A flat `set security dynamic-address feed-server office url ... feed-name ...`
  line is a supported compiler-read shape. `feed-server` now opts into the
  existing `packedFlatRun` schema-walk expansion, which hoists the nested
  `feed-name` sibling for strict validation without broadening any other
  closed-world boundary. The same boundary still rejects `feed-nam`.
- The golden fixture's `security ipsec vpn-monitor` line was not a modeled
  Junos path: it omitted the required `vpn <name>` instance. It now uses the
  modeled `security ipsec vpn v1 vpn-monitor optimized` spelling rather than
  carving an exception into the security arm.

The full config sweep also reached a stale #6812 axis registration: the
fixture-constant `Pool.UnknownLeaves` diagnostic columns were added to the
honest exemption table, parallel to the existing rule diagnostic columns. No
production behavior or closed-world reject was weakened.
