# #12092 — reject nameless firewall terms

- **Issue**: #12092 — nameless hierarchical firewall terms can compile as
  empty-action fall-through terms.
- **Branch**: `fix/12092-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12092`
- **Base**: `83b5c9553` (PR merge-base)
- **Reviewed head**: `da5bfb3c3` (Opus R3)

## Why

A one-key hierarchical `term` container has no term name. `namedInstances`
interprets each child as an instance, so `term { then discard; }` becomes an
instance named `then` with keys `[then, discard]`; the #10294 gate missed the
`discard` value tail. Bare `term { foo; }` also had no tail to inspect. The
no-catch-all advisory printed this nameless form as its remedy.

The review found a more severe variant: a multi-key child block such as
`term { T from destination-port 22 { then { accept; } } }` was consumed by
lowering as a term named `from`, dropping the match and allowing the term to
accept all traffic without a diagnostic.

## What

- Inspect term instance tails using `instanceValueTail` for named term
  nodes.
- Mark children of a one-key `term` container nameless unless they are
  single-key nested-name blocks. Multi-key children otherwise let lowering
  consume a tail token as the term name.
- Strict commit rejects nameless terms; tolerant compile warns.
- Reword the no-catch-all advisory to recommend
  `term <name> { then discard; }`.
- Add strict regressions for the original nameless spellings, P05, five
  compact-tail probes, N07/N17, lenient warnings, and named controls.
- Pin P05 through configstore's `LoadOverride` + `CommitCheck` path.

## GLM independent-review MINOR: `LoadMerge` flattening

This was pre-existing at base `83b5c9553`, not a regression from this PR.
The earlier store pin covers `LoadOverride` only. Hierarchical `LoadMerge`
instead flattens through `FormatSetForLoadMerge` and replays `set` lines
before `CommitCheck`, erasing the nameless-term marker. On the reviewed head,
`LoadMerge` + `CommitCheck` accepts `filter F { term { foo; } }` and
`term { T then discard { } }` after normalizing them to named set paths;
`LoadOverride` rejects both. The same path accepts
`term { T then accept { } }`.
The P05 and protocol/action controls still REJECT: their validators see
`then` as a destination-port or protocol value.
H1, `term { T from is-fragment { then { discard; } } }`, is another
pre-existing fail-open: LoadMerge commits T with `IsFragment=true` and
`Action=""`, silently dropping discard; LoadOverride rejects the nameless
form. The analogous `flexible-match-range range R` form also passes
LoadMerge with `FlexMatch` populated and `Action=""`; named LoadOverride
with the fused `then discard` inside range R does as well.
The same is-fragment loss occurs for reject, the compact leaf spelling, and
inet6 and any families. Named packed N1 keeps `Action="discard"` under
LoadOverride but loses it on a LoadMerge / `display set` → `load set` round
trip. Follow-up #12528 tracks fused-tail swallowing by both leaves; the new
pin records H1's current fail-open outcome. The full #12528 matrix also
covers flat load-set, interactive `set`, and named-override N3-N4;
ShowCandidateSet / `display set` still prints the dropped action.
The fold's store pin verifies the exact flattened paths and current
`CommitCheck` outcomes for the two reviewed shapes, populated controls, and
H1:

```sh
go test ./pkg/configstore -run \
  '^TestLoadMergeNamelessTermFlatteningIsPinned12092$' -count=1 -v
```

The two reviewed nameless shapes ACCEPT after flattening; the P05 and

nested-name compact spelling that previously dropped its match/action tail.

H1's is-fragment discard and the analogous flexible-match-range discard are
silently dropped, leaving an empty action that falls through to Accept.
Named packed N1 also loses its discard on the LoadMerge round-trip. See the
GLM independent-review note, nameless-shape follow-up #12526, and #12528,
which tracks both swallowing leaves.
Nested-name block controls and named compact terms remain covered by the
9875/9899 and 12092 tests. Tolerant loading warns on the direct AST path,
consistent with the existing #10294/#1960 path. No live cluster or lab was
mutated.
