# #12092 — reject nameless firewall terms

- **Issue**: #12092 — nameless hierarchical firewall terms can compile as empty-action fall-through terms.
- **Branch**: `fix/12092-nameless-term`
- **Worktree**: `/var/worktrees/12092-nameless-term`
- **Base**: `1c384b9a47ff7d6e567fa50632faa75c3995ae87`

## Why

A one-key hierarchical `term` container has no term name. `namedInstances` interprets each child as an instance, so `term { then discard; }` becomes an instance named `then` with node keys `[then, discard]`; the #10294 gate previously inspected only `Keys[2]` and direct children, missing the `discard` instance-value tail. Bare `term { foo; }` also had no tail for the gate to inspect. The no-catch-all advisory printed the nameless form as its suggested remedy.

## What

- Inspect term instance tails using `instanceValueTail`, which handles the node shapes returned by `namedInstances`.
- Record one-key nameless `term` containers separately, so even a single child such as `foo;` is rejected by the strict gate and warned on tolerant compile.
- Reword the no-catch-all advisory to recommend `term <name> { then discard; }`.
- Add regressions for all four hierarchical nameless spellings, flat/compact tail handling, named controls, tolerant warnings, and the advisory remedy.
