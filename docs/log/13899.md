# #13899 — atomically reserve WireGuard transmit nonces

- **Issue**: #13899 — remove per-session encryption serialization while preserving nonce uniqueness.
- **Branch**: `fix/13899-atomic-nonce-reservation`
- **Worktree**: `/var/worktrees/campaign-zero/wt-13899`

## Why

`WgEngine::encap_inner` acquired `WgSession::tx_lock` before loading the counter and held it over stack staging and `StatelessTransportState::write_message`. This serialized every sender for a session through the full AEAD operation. The existing `WgSession::next_tx_counter` already uses atomic `fetch_update` with the WireGuard reject-after-messages bound, so the lock was redundant for uniqueness.

## What

- Use `next_tx_counter()` to atomically reserve each nonce after input/output bounds checks and before encoding/encryption.
- Remove the per-session `tx_lock`, including its constructor initialization. An encryption error after reservation can leave a nonce gap; the next encryption uses the next value, so the nonce is never reused. Existing output-size validation still occurs before reservation.
- Add concurrent reservation tests for a large contiguous unique range and for contention at the WireGuard counter ceiling.

## Validation

- `cargo test --release --manifest-path userspace-dp/Cargo.toml afxdp::wg:: -- --test-threads=1`: 290 passed, 8,008 filtered out.
- Repeated `cargo test --release --manifest-path userspace-dp/Cargo.toml concurrent_reserve -- --test-threads=1` 20 times: both concurrent-reservation tests passed on every run.
- `rustfmt --edition 2024 --config skip_children=true --check userspace-dp/src/afxdp/wg/engine.rs userspace-dp/src/afxdp/wg/session.rs` and `git diff --check` passed.
- No deterministic pre-fix functional RED is available for this performance-only regression: the lock-based implementation also produced unique nonce values. The updated tests pin atomic reservation's uniqueness and reject-after-messages ceiling; removal of the lock is verified by the source path and the successful WG suite.

## Risk

An AEAD failure now consumes its reserved counter, creating a permissible nonce gap. Reusing a nonce would be unsafe; gaps do not compromise uniqueness. Buffer/staging bound failures remain pre-reservation.
