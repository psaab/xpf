# #11429 — reject conflicting CoS aliases for logical units

- **Timestamp**: 2026-10-01
- **Action**: The forwarding builder now rejects a snapshot when logical-unit
  rows sharing a Linux `ifindex` materialize different CoS interface settings,
  including configured/unconfigured mismatches, or different loss-priority
  rewrite tables. Identical per-unit state remains valid, and structural
  base-interface rows are excluded from the sibling check. This prevents the
  later row from silently replacing an earlier entry in the ifindex-keyed
  runtime maps.
- **Validation**: The differing-shaping regression failed before the fix and
  passes after it. All six focused duplicate-ifindex tests pass, and scoped
  `cargo check --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp`,
  Rust formatting, and `go test -count=1 ./pkg/refactoraudit` pass. The full
  forwarding-builder module has 229 passing tests and one pre-existing failure:
  `next_table_target_uses_table_lpm_without_rule_restart_9955` reports
  `NoRoute` instead of `MissingNeighbor`; the same failure reproduces on clean
  master at `9db7fb848`.
