# Issue #17161 — R4-Q50-06: share the security-policy zone-pair walk across the eight strict gates

- **Issue:** Eight strict policy gates in `compiler_policy_{match,missing_match,then}.go`
  each pasted the same `security → policies → global / from-zone` pair enumeration
  (`type zonePair struct` ×8, keyed-context arm `len(tzNode.Keys) >= 2` ×8). #3562 and
  #12782 each had to patch every copy, and the #12782 regression test pinned the keyed
  arm for only four gates (#3044, #6526, #3113, #3114): deleting it in the then-deny
  (#3374) or unsupported-then-sibling (#11013) copy let a keyed
  `from-zone { A { to-zone B { … } } }` policy carrying the gated construct commit
  strict while every test stayed green — a fail-open direction in fail-open gates.
  STEP-0 re-check on current `origin/master` (3abae28d24): defect live — 8 copies
  confirmed at the issue's anchors (compiler_policy_match.go:360,
  compiler_policy_missing_match.go:309, compiler_policy_then.go:163/315/440/646/732/825).

- **What:** Added `pkg/config/security_policy_walk.go` with
  `forEachSecurityPolicy(nodes []*Node, fn func(scope, name string, pol *Node, isGlobal bool) error) error`,
  containing the #3562 every-root iteration (`forEachChild` at security/policies),
  the global arm, and compilePolicies' two zone-pair AST shapes exactly once —
  the hierarchical combined spelling (`Keys >= 4`) and the flat/nested spelling
  including the #12782 keyed destination arm (`len(tzNode.Keys) >= 2` carries the
  pair body; only a keyless `to-zone` enumerates destination-named child containers).
  Ported all eight gates (validatePolicyMatchLeavesStrict #3113,
  validatePolicyRequiredMatchStrict #3044/#6526, validatePolicyThenPermitStrict #3114,
  validatePolicyThenRejectStrict #3115, validatePolicyThenCountAlarmStrict #11342,
  validatePolicyThenDenyStrict #3141/#3374, validatePolicyUnsupportedThenSiblings
  #11013/#11023, validatePolicyEnforcementSubtrees #11014/#12234/#12634) to pass only
  their `checkPolicy`; each gate's messages, strict-first-error / lenient-collect
  doctrine, and per-policy logic are unchanged. compilePolicies keeps its richer
  ninth enumeration (malformed-shape recording / poisoning) — the optional later
  step in the issue; the gates' enumeration remains its superset by construction
  (same two shape arms, no filters). Net: −418/+23 lines across the three gate files
  plus the new walker.

- **Acceptance:** `grep -c 'type zonePair struct' pkg/config/compiler_policy_*.go` = 0
  for every file (verified; the sole remaining copy is compilePolicies' own in
  compiler_security_policy.go and the shared one inside security_policy_walk.go).

## Risk

Behavior-preserving refactor: the shared walk is a verbatim merge of the eight
identical copies (scope strings, pair order, error propagation unchanged), proven
by the existing per-gate named tests plus the new 8×4 table. Residual: gate-pair ⊇
compiled-pair parity for future compilePolicies shapes is now a one-place change
in the walker rather than nine, but compilePolicies itself was intentionally not
re-derived from the enumerator (issue lists it as an optional later step).
