# #12825 — preserve pre-ID policy bits and validate system-wide policy statistics

- **Timestamp**: 2026-10-13 (`fix/12825-campaign-pub`)

## Why

`compileSecurity` allocated a new `PreIDDefaultPolicy` for every stanza, so a later stanza erased session logging modes set earlier (including stanzas under a later `security` root). The `policy-stats system-wide` reader inspected only the first leaf and recognized only `enable`; other spellings silently disabled statistics, unknown values committed, and duplicate leaves/blocks could select an order-dependent value.

## What

- Allocate `PreIDDefaultPolicy` only when absent, then accumulate all logging mode bits across repeated stanzas and roots; a stanza without modes does not clear prior bits.
- Model system-wide policy statistics as a schema enum: `enable`/`enabled` turn statistics on and `disable`/`disabled` turn them off. Read every leaf. Strict compilation rejects unknown values and conflicting enabled/disabled values; tolerant compilation warns and disables policy statistics. Identical repeated values are allowed.
- Add regressions for repeated pre-ID blocks and security roots, flat-set forms, absence/single-block controls, unknown and contradictory stats leaves/blocks, enum spellings, and strict/tolerant paths. Update config-schema docs.
