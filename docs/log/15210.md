# #15210 - dampen "local interface missing" monitor warning to once per absence

- **Timestamp**: 2026-10-19
- **Action**: `pollInterfaceMonitors` in `pkg/cluster/monitor.go` emitted `slog.Warn("cluster monitor: local interface missing, treating as down")` on every 1s poll tick for each absent local monitor (A21-02), flooding the journal. Added per-`(rg, interface)` episode state (`Monitor.missingWarned`, guarded by `mon.mu` in the existing dampening critical section): the warning now fires once when an absence episode starts, is cleared when the interface is seen again (so a later absence warns once more) and dropped by `UpdateGroups` for monitors no longer configured. The warning is emitted after `mon.mu` is released. Missing still counts as down through the same dampening machinery, so the #5080 RG demotion is unchanged; peer-slot interfaces are still skipped before the missing path.
- **Validation**: New `pkg/cluster/monitor_missing_warn_15210_test.go` drives the real `mon.poll()` with a missing link: RED on pristine master (5 polls produced 5 warnings, want 1), GREEN post-fix (5 polls = 1 warning, return clears the episode, second absence = 2 total, weight demoted to 155 while missing and restored to 255 on return); present-interface control emits 0 warnings. Existing `TestMonitor_InterfaceStateChange` / `TestMonitor_AllInterfacesDown` / `TestMonitor_NoChangeNoCall` remain green; full `pkg/cluster` suite has one pre-existing failure `TestInstallTableProducerToResendEndToEnd9752` also failing on pristine base (golden drift, unrelated); `go vet ./pkg/cluster/` clean and `gofmt` clean.
- **Risk**: Operator-visible delta only in log volume: a persistently missing local monitor now logs once per absence episode instead of once per second; enforcement (weight demotion) is unchanged. A flapping delete/recreate interface re-warns once per absence, which is the intended episode semantics.
