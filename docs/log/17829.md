# #17829 — Resolve credential history mutations against edit context

- **Base**: `85ee385d1e` (`origin/master` at branch start)
- **Branch**: `fix/17829`

## Why

`IsSensitiveHistoryLineAt` resolved `editPath` only for `set` and `edit`;
other config mutation verbs were judged as cursor-free tokens. Thus after
`edit snmp`, `delete community <s>` and the equivalent activate/deactivate,
copy, rename, insert, or annotate spellings omitted the `snmp` ancestor that
the secret SSOT needs to recognize the community string. The cleartext value
could be appended to either CLI's persistent history file.

Legacy history can still contain a secret written before this fix. The
`~/.xpf_cli_history` file is shared by concurrent CLI processes with separate
edit cursors, but its lines have no session markers. Linear seed replay can
therefore judge a line at a different session's cursor and miss a context
gate. Since seeded history is recall convenience rather than executable
configuration, seed replay must not expose context-gated secrets under an
unprovable cursor.

## What

- `pkg/cliterm/terminal.go`: use the shared mutation-verb set and resolve
  each mutation's actual path(s) against the edit cursor. Copy/rename source
  and destinations use the canonical endpoint parsers/resolver; insert checks
  its element and reference separately; annotate checks its target path only.
  `top` / `up` recurse with the parser's raw inner line to preserve quoted
  separators. Malformed mutation lines fail closed; operational lines remain
  cursor-free.
- `pkg/config/config_command_split_14147.go`: expose the existing mutation
  verb set for already-lexed callers, avoiding another lex of every submitted
  history line.
- `pkg/cliterm/history_secret_mutations_17829_test.go`: exercise each config
  mutation verb against the real history recorder, including destination-only
  credentials, insert references, quoted `to` separators, prefixed navigation,
  cursor-free paths, and benign controls.
- `ReadHistorySeed` applies a stricter seed-only policy: in addition to replaying
  known cursor states, it suppresses mutations and edit commands with values
  after keywords from config's context-sensitive secret set. This option (c)
  is deliberate: seed files cannot identify which process supplied
  navigation, while new submissions are still checked against their live
  cursor by the recorder.
- `pkg/cliterm/history_seed_interleaved_17829_test.go`: pin the exact
  two-session `configure / edit snmp / configure / edit system / delete
  community OldSecret` interleaving and an interleaved `edit community
  OldSecret` variant, retain benign history, and ensure live-recorder decisions
  do not inherit the seed-only policy.

## Risk

The seed policy may omit benign values that follow generic context-sensitive
keywords, such as a GRE `key` or policy-options `community`, because replay
cannot prove their originating cursor. They remain available in the live
session's in-memory history; existing history files are not rewritten by this
change.
