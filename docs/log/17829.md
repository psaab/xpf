# #17829 — Resolve credential history mutations against edit context

- **Base**: `85ee385d1e` (`origin/master` at branch start)
- **Branch**: `fix/17829`

## Why

`IsSensitiveHistoryLineAt` resolved `editPath` only for `set` and `edit`;
other config mutation verbs were judged as cursor-free tokens. Thus after
`edit snmp`, `delete community <s>` and the equivalent activate/deactivate,
copy, rename, insert, or annotate spellings omitted the `snmp` ancestor that
the secret SSOT needs to recognize the community string. The cleartext value
could be appended to either CLI's persistent history file.

## What

- `pkg/cliterm/terminal.go`: use the shared mutation-verb set and resolve
  each mutation's actual path(s) against the edit cursor. Copy/rename source
  and destinations use the canonical endpoint parsers/resolver; insert checks
  its element and reference separately; annotate checks its target path only.
  `top` / `up` recurse with the parser's raw inner line to preserve quoted
  separators. Malformed mutation lines fail closed; operational lines remain
  cursor-free.
- `pkg/config/config_command_split_14147.go`: expose the existing mutation
  verb set for already-lexed callers, avoiding another lex of every submitted
  history line.
- `pkg/cliterm/history_secret_mutations_17829_test.go`: exercise each config
  mutation verb against the real history recorder, including destination-only
  credentials, insert references, quoted `to` separators, prefixed navigation,
  cursor-free paths, and benign controls.

## Risk

Malformed config mutation lines are conservatively omitted from persisted
history rather than risk persisting a credential from an unlexed tail. Lines
remain available in readline's in-memory history; existing history files are
not rewritten by this change.
