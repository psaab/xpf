## Timestamp: 2026-09-10 — reading before writing

- **The issue named a function that no longer exists.** Its body cites
  `reuse_persistent_lease_locked`. On `origin/master` the port-bearing arm is
  `reuse_existing_lease_locked` (`nat/allocator.rs`). I located it by the
  CONDITION the issue quotes, not by name.
- **The #9158 trap is present here too.** When the reuse function tears the lease
  down and returns `None`, its single caller claims a port and INSERTS a new
  `PersistentLease` over the same key. So keeping the lease inside the reuse
  function alone would change nothing; the caller must also skip that insert.
- **Unpinned is leak-free, verified rather than assumed.**
  `unlink_live_allocation_locked` frees a port exactly when
  `persistent_key.is_none() && !address_only`. An unpinned PAT flow's bit is
  therefore released with the flow.
- **Blast radius:** `reuse_existing_lease_locked` has exactly one caller in the
  tree, tests included.

## Timestamp: 2026-09-10 — the fix

- **A three-state result.** `LeaseReuse` is `Reused` / `NoLease` /
  `LiveModeMismatch`. A bare `Option` could not tell "no usable lease, mint one"
  from "a live other-mode lease exists, do not insert over it".
- **The missing middle arm.** An ADDRESS-ONLY lease with `active_flows > 0` is
  left standing. An idle one still falls to tear-down, so the source re-pins in
  PAT mode once it drains.
- **The caller.** `LiveModeMismatch` becomes `persistent_key = None`. The PAT
  flow still CLAIMS its own occupancy bit (#8597 K10), inserts no lease and joins
  none.
- **Docs.** The allocator doc comments carry the contract, and the K10 comment
  was corrected: only an IDLE disagreeing lease is torn down now. No module
  README describes the persistent-lease lifecycle; the #9158 change found the
  same, since no `.md` outside review archives mentions it.
