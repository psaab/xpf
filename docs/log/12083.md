# #12083 — bind GRE keepalive probes to the transport VRF

- **Issue**: #12083 — a GRE keepalive source held in the transport routing instance cannot be bound by the global-context ICMP socket, leaving liveness structurally unknown.
- **Branch**: `fix/12083-gre-ka-vrf`
- **Worktree**: `/var/worktrees/12083-gre-ka-vrf`
- **Base**: `1c384b9a47ff7d6e567fa50632faa75c3995ae87`

## Why

A GRE underlay can be routed in a configured transport instance. The keepalive runner previously carried only source and peer addresses, so its datagram ICMP socket used the process-global FIB. Binding a source configured only on a VRF-held interface then returned `EADDRNOTAVAIL`; `ProbeUnsupported/UnsupportedStructural` made the runner hold unknown indefinitely. The socket must follow the same transport instance as the tunnel's outer traffic.

## What

- Threaded `TunnelConfig.RoutingInstance` through all keepalive start sites and the runner to the prober. The transport instance is part of runner identity, so changing it restarts the probe.
- For a non-empty transport instance, create the datagram ICMP socket with `SO_BINDTODEVICE=vrf-<instance>` before binding the tunnel source. The empty-instance path continues to use the existing global-context `icmp.ListenPacket` behavior.
- Updated the prober contract comments and added a transport-scope/classification test, a real scoped-socket loopback round trip, and a private-netns VRF-held source/peer cell.

## Validation

### RED before the fix

The #12083 netns cell was run with the transport instance omitted (the base/global socket path) in a private network namespace. It failed as expected: `ProbeUnsupported/UnsupportedStructural`, `bind: cannot assign requested address`, although the source was local on an interface enslaved to `vrf-ka12083`.

### GREEN after the fix

- `go test ./pkg/routing/... -count=1` — PASS.
- `go build ./pkg/routing` — PASS.
- `gofmt -l` on all changed Go files — no output.
- The classification test verifies the runner records a known Alive result for a VRF-local source and requests `vrf-ka12083`; the scoped-socket loopback round trip exercises the actual `SO_BINDTODEVICE` socket setup and ICMP exchange.
- The netns cell passed in a private network namespace with a `vrf-ka12083` device, two VRF-held veth endpoints, and the prober's scoped transport instance. The test process was run under `sudo -n unshare -n`; `ping_group_range` was widened only inside that disposable namespace so the unprivileged ICMP datagram socket could be opened. Output included `NETNS-CHILD-PASSED-12083`.

The ordinary unprivileged suite invocation skips the netns cell when the environment denies ICMP datagram sockets; the isolated privileged run above exercised it. No broader project-wide test suite was run in this lane; project-wide validation and any same-base attribution of broader failures remain with the main validation pass.
