# #12083 — bind GRE keepalive probes to the transport VRF

- **Issue**: #12083 — a GRE keepalive source held in the transport routing instance cannot be bound by the global-context ICMP socket, leaving liveness structurally unknown.
- **Branch**: `fix/12083-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12083`
- **Base**: `83b5c9553`

## Why

A userspace GRE anchor can carry outer traffic in a configured transport routing instance. Its keepalive runner previously carried only source and peer addresses, so its datagram ICMP socket used the process-global FIB. Binding a source configured only on a VRF-held interface then returned `EADDRNOTAVAIL`; `ProbeUnsupported/UnsupportedStructural` made the runner hold unknown indefinitely. The anchor's probe must use its transport instance. Legacy kernel GRE/IPIP tunnels are different: with no lower-link selector, their outer route uses the main FIB even if the tunnel interface is VRF-bound, so their keepalive runner must stay global.

## What

- Anchor-only keepalive runners carry `TunnelConfig.RoutingInstance` to the prober and include the effective transport instance in runner identity.
- Legacy kernel GRE/IPIP keepalive start sites pass an empty transport instance to match the kernel outer-route lookup; an interface VRF does not imply a VRF-scoped probe.
- For a non-empty transport instance, create the datagram ICMP socket with `SO_BINDTODEVICE=vrf-<instance>` before binding the tunnel source. The empty-instance path continues to use the existing global-context `icmp.ListenPacket` behavior.
- Updated the prober contract comments and added a transport-scope/classification test, a real scoped-socket loopback round trip, and a private-netns VRF-held source/peer cell.
