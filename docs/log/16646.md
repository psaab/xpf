- **Issue**: #16646 — `ReadInterfaceCounters` resolves a VLAN child's ifindex to its parent binding and returns the parent's full traffic as the unit's own counters
- **Change**: `Manager.ReadInterfaceCounters` no longer resolves a logical child to its parent binding. A new `childBindingRow` predicate identifies any retained snapshot row whose `ParentIfindex > 0` and differs from its own `Ifindex` — VLAN-tagged or not, disabled or unzoned included (the unfiled H5-03 cohort folds into the same predicate) — and such a read fails closed with `userspace interface counters unavailable: no per-interface counters for logical child <name> (ifindex N, parent ifindex M)` before any direct-binding shortcut, so a stray binding for the child ifindex cannot resurrect the lie. The now-dead `resolvedBindingIfindex` parent-resolution helper is removed. Directly bound interfaces (including unit-0 rows collapsed onto the parent netdev, `ParentIfindex == Ifindex`) still return their real counters. No consumer change is needed: all consumers already handle the error contract (#3464) — REST flags `Unavailable`, gRPC mirrors it, Prometheus omits the sample and bumps `xpf_interface_counter_read_errors_total` (so the family sum now equals real traffic, emitted once under the parent), CLI extensive prints a warning, and monitor propagates the error. Per-VLAN counters remain unavailable until the helper exports per-`(ifindex,vlan)` counters.
