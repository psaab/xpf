# Issue #10429: fabric HMAC method replay

## Disposition

Fabric authentication tokens now bind the canonical full gRPC method in the
HMAC input (`domain || method-length || method || window`). The server verifies
that method-bound digest on both unary and streaming interceptor paths. The
client per-RPC credential receives the method through client interceptors; the
daemon and CLI fabric dialers install those interceptors for every RPC. A
credential invoked without a method emits no metadata rather than falling back
to the vulnerable unbound token form.

Same-method retries remain stateless and succeed while the existing current/±1
window remains valid. Tokens outside that band are rejected. Rotation and skew
diagnostics use the same method-bound input.

## RED-then-GREEN regression evidence

The original defect was reproduced before the fix with a temporary RED probe.
The probe minted one current-window token and sent it first to `GetSessions` and
then to `ClearSessions`; the second call was accepted by the unbound verifier:

```text
go test ./pkg/grpcapi -run '^TestRED10429CrossMethodReplay$' -count=1
--- FAIL: TestRED10429CrossMethodReplay
    red_10429_probe_test.go:31: RED PROOF: GetSessions token ACCEPTED on ClearSessions (err=<nil>) — cross-method replay verifies
FAIL
```

That throwaway probe was removed. The permanent cells are fail-on-revert tests;
the cross-method cell composes the auth interceptor before the fabric allowlist,
so a reverted method binding reaches the allowlisted `ClearSessions` handler.
The retry and expiry cells are control invariants: the old implementation
already accepted same-method retries and enforced the ±1 window, and they must
remain green while the method binding changes.

| Cell | RED evidence | GREEN evidence |
| --- | --- | --- |
| `TestFabricAuth10429_CrossMethodReplayRejected` | The temporary unbound verifier accepted the captured `GetSessions` token on `ClearSessions` (output above). | `PASS`; the captured token is rejected `Unauthenticated` before the allowlist/handler. |
| `TestFabricAuth10429_SameMethodRetryAccepted` | Control invariant: no pre-fix defect; a same-method retry is required to remain accepted. | `PASS`; two uses of one method-bound token reached the handler. |
| `TestFabricAuth10429_WindowExpiryEnforced` | Control invariant: no pre-fix defect; ±1-window expiry behavior is retained. | `PASS`; a token three windows in the past is rejected `Unauthenticated`. |

The permanent cells were run together:

```text
go test ./pkg/grpcapi -run '^TestFabricAuth10429_' -count=1 -v
=== RUN   TestFabricAuth10429_CrossMethodReplayRejected
--- PASS: TestFabricAuth10429_CrossMethodReplayRejected (0.00s)
=== RUN   TestFabricAuth10429_SameMethodRetryAccepted
--- PASS: TestFabricAuth10429_SameMethodRetryAccepted (0.00s)
=== RUN   TestFabricAuth10429_WindowExpiryEnforced
--- PASS: TestFabricAuth10429_WindowExpiryEnforced (0.00s)
PASS
ok  	github.com/psaab/xpf/pkg/grpcapi	0.008s
```

## Verification

```text
go test ./pkg/grpcapi/... -count=1
ok  	github.com/psaab/xpf/pkg/grpcapi	20.312s
?   	github.com/psaab/xpf/pkg/grpcapi/xpfv1	[no test files]

go test ./pkg/cli -count=1
ok  	github.com/psaab/xpf/pkg/cli	8.389s
```

The CLI fabric credential parity test now evaluates the method-bound credential
with the same method context as the production client interceptor. Rotation
(#6630), skew diagnostics (#6708), auth/allowlist ordering (#4107/#4122), and
unkeyed dual-accept behavior remain covered by the existing suites.

## Scope

Product changes are limited to the fabric auth token primitive, skew diagnostic
call path, fabric client interceptor chain, and the daemon/CLI fabric dial
options that install the chain. Tests cover the corresponding auth, rotation,
skew, and client-dial behavior.
