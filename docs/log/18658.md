- **Timestamp**: 2026-11-01 ~09:30Z
  - **Action**: Identified the inversion from the stack captures.
    - **Captures.**
      - tcp fw0, 03:16Z:
        `/var/tmp/fz/r-18655/master-deadlock-stacks.txt`.
      - loss fw0, 07:41Z:
        `/var/tmp/fz/r-18655/loss2-cell/fw0-deadlock-stacks.txt`.
      - Both were on master 0050ac4172, after a 16000-session burst.
    - **Method.** The futex address of each blocked thread was read from
      `/proc/<tid>/syscall`, and the return addresses on its stack were
      symbolized against the binary.
    - **Wait-for graph (loss).**
      - Worker 2782 is in `publish_shared_session`, blocked in
        `lock_shared_publish` on the forward-wire map. It already holds
        `wire_ambiguities`.
      - Worker 2781 is in `remove_shared_session`, holding
        `shared_sessions` and the forward-wire map, blocked on
        `wire_ambiguities`.
      - Behind them: one more publish and the coordinator wait on
        `wire_ambiguities`; the ct-slice threads and the GRE thread wait
        on `shared_sessions`.
      - tcp shows the same shape: 39170 publish waits on the map, 39165
        removal waits on the index.
      - Treating that futex as `wire_ambiguities` is the only reading that
        closes a cycle, and it matches the only nested inversion in the
        source. Mapping futex addresses to struct fields by allocation
        order is not reliable, so the graph decides.
    - **The two paths** (origin/master 04aa378209,
      `userspace-dp/src/afxdp/shared_ops/store.rs`):
      - publish: `lock_wire_ambiguities_for_publish` at :865, THEN
        `lock_shared_publish(shared_forward_wire_sessions)` at :871.
      - removal (`remove_shared_session_if`): `shared_sessions` at :1108,
        then `lock_shared_recover(shared_forward_wire_sessions)` at
        :1188, THEN `lock_shared_recover(&...wire_ambiguities)` at :1190.

      The publish takes index then map; the removal takes map then index.

- **Timestamp**: 2026-11-01
  - **Action**: Fix. One order: `shared_sessions` → forward-wire map →
    `wire_ambiguities` → owner-RG index. The publish now takes the map
    before the index.
    - The #14383 reader guarantee still holds. The owner is recorded
      after both locks are taken and before the alias insert, and
      readers take the map first and never nest.
    - The NAT pair was checked and has no nested inversion: the publish
      takes `nat_ambiguities` then the map, the removal releases the map
      before `nat_ambiguities`, and readers are unnested.
    - The order is documented in `afxdp/README.md` under "Shared-session
      lock order (#18658)".
    - The cell `publish_and_removal_take_the_wire_locks_in_one_order_18658`
      forces the deadlock interleaving through cfg(test) pause points
      between each path's two wire locks. Its verdict is a bounded
      `recv_timeout`.
