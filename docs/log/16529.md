# #16529: resumed auto-rollback re-restored the cut-boundary DB over post-rollback commits

- **Timestamp**: 2026-10-24
- **Action**: A non-operator `ROLLINGBACK` journal preserved by the
  #14721 health gate (old daemon started, helper unconfirmed, daemon
  left running) was resumed by the next `xpfd upgrade` through
  `rollback()` with no record that its DB restore had already run.
  The resume STOPped the healthy rolled-back daemon, re-restored the
  cut-boundary snapshot over every commit made since the rollback,
  and deleted `<ConfigDBDir>.old` with no copy — durable config loss
  including configstore history. Fixed for both rollback flavours:
  - `pkg/upgrade/state.go`: new `Journal.AutoRollbackDBRestored`
    (`auto_rollback_db_restored,omitempty`), the auto-path twin of the
    operator-only `RollbackDBRestored`.
  - `pkg/upgrade/flip.go` (`rollback()`): persists the bit BEFORE the
    swap and again after `StartUnit` (so the health-preserved journal
    carries it); on entry it adopts the bit from legacy residue — a
    surviving `.old`, a live DB byte-identical to the snapshot, or,
    for a `ROLLINGBACK` journal with `AdvancedStateFloor`, `current`
    already naming `PreviousVersion` (which proves the mandatory
    restore-before-flip order already ran, since the completed swap
    deletes `.old` and post-rollback commits diverge byte-identity).
    With the bit set, the restore is skipped; and if `current` already
    names the destination and the daemon re-proves healthy, the
    rollback completes WITHOUT stopping the daemon or touching its DB.
    A first attempt (bit unset, `current` still the failed target)
    never takes either shortcut, so a needed restore still runs.
    `restoreDBSnapshotWithRetention`'s byte-identity guard (live ==
    snapshot with `.old` present ⇒ already installed, keep `.old`) now
    applies to both flavours instead of `retainOld`-only.
  - `pkg/upgrade/rollback.go` (`executeRollback`): same fast path for a
    resumed operator rollback (destination running + healthy, or
    `SkipHealthCheck`, completes without STOP); the restored bit is
    persisted before the swap (cleared again if the swap errors);
    `validateOperatorRollbackJournal` heals a lost bit-save from
    `.old` + byte-identity instead of refusing/re-rotating.
  - `pkg/upgrade/cutover.go`: resume comment updated to name the
    invariant.
  NOT changed: the forward cut, the snapshot/retention semantics of a
  first restore (`.old` is still rotated and cleaned exactly as
  before when no prior restore is proved), and the #14721 outcome
  contract (a completed resumed rollback still returns the non-nil
  rolled-back error; `Run`'s resume branch is untouched).
- **File(s)**: `pkg/upgrade/state.go`, `pkg/upgrade/flip.go`,
  `pkg/upgrade/rollback.go`, `pkg/upgrade/cutover.go`,
  `pkg/upgrade/rollback_rerestore_16529_test.go` (new),
  `docs/in-place-upgrade.md`, `docs/log/16529.md`
- **Validation**: new tests in
  `rollback_rerestore_16529_test.go` drive the exact reported trace
  (1.0.0 → cut 2.0.0 unhealthy → auto-rollback → helper timeout →
  journal preserved with daemon running → operator commit → re-run):
  `TestResumePreservedAutoRollbackKeepsCommit16529_Legacy` (journal
  with no bit, commit diverged from snapshot) and `..._Bitted` (fixed
  binary's preserved journal) both assert the commit survives in the
  live DB and no `stop` call occurs; `TestControlHealthyRollbackThenCommitUnaffected16529`
  is the unchanged healthy-first-time control;
  `TestRestoreDBSnapshotIdentityKeepsOld16529` pins the identity guard
  keeping `.old`; `TestResumeOperatorRollbackRunningHealthyKeepsCommit16529`
  pins the operator flavour. RED-on-revert: with only the logic files
  (`flip.go`/`rollback.go`/`cutover.go`) reverted and the field kept,
  the legacy cell fails with `operator commit destroyed by resume` +
  `resume STOPPED the already-running rolled-back daemon`, the
  identity cell fails with `.old destroyed`, and the operator cell
  fails with a STOP — matching the reported probe output
  (`calls: [stop dropin daemon-reload start health:1.0.0]`). Full
  `go test ./pkg/upgrade/ -count=1` passes; `go vet ./pkg/upgrade/`
  clean; gofmt clean.
