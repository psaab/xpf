# #10112 — CLI link speed display preserves fractional Gbps

- **Timestamp**: 2026-09-17
- **Base**: `18a5e90ce` on `fix/10112-fmt-speed`

## Fix

`pkg/cli/link.go` `formatSpeed` now follows the #9917 F-138
`formatLinkSpeed` rule on the CLI surface: exact multiples of 1000 Mbps
render as integer `Gbps`, while other gigabit-plus speeds render one decimal
truncated with integer division. The existing `Mbps` branch and CLI casing are
unchanged. Thus 2500 Mbps renders `2.5Gbps` rather than `2Gbps`, and the rule
also remains correct at 10 Gbps and above (for example, 10500 Mbps renders
`10.5Gbps`). `pkg/monitoriface` is untouched.

## RED then GREEN

The new `pkg/cli/linkspeed_10112_test.go` table was run against the base
formatter before the implementation:

- `go test ./pkg/cli -run '^TestFormatSpeed10112$' -count=1` — **RED**;
  the base `mbps/1000` implementation failed all 11 fractional rows:
  1001, 1049, 1050, 1100, 1150, 1250, 1500, 1999, 2500, 2599, and 10500
  Mbps (including `2500 = "2Gbps", want "2.5Gbps"`).
- After the change, the same command — **GREEN**.

The table pins the sub-1000/1000 boundary, exact multiples, first fractional
values, truncation boundaries, the reported 2500-Mbps case, and a fractional
value above 10 Gbps.
