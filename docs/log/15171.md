# Issue #15171: tcp-mss commit gate enforces Junos floor 64 (B19-01)

- **Timestamp**: 2026-10-19
- **Action**: `checkTCPMSSKind` in
  `pkg/config/compiler_security_flow.go` range-checked the
  compiler-selected tcp-mss token with `ValidateInteger(0, maxWireU16)` —
  only the Layer-A wire bound [0,65535], not the Junos range 64..65535.
  `mss 0` therefore committed clean and `compileFlow`'s `v > 0` guard
  stored nothing, so the clamp the operator configured silently did not
  happen (PMTU black-holing on the tunnel/WAN path it was meant for),
  and 1..63 were written into SYN MSS options by the userspace
  `clamp_tcp_mss` (which has no floor), collapsing throughput. The gate
  now uses `ValidateInteger(MinTCPMSS, maxWireU16)` with the new
  `MinTCPMSS = 64` constant in `pkg/config/schema_validators.go`:
  strict commit/commit-check rejects 0..63 naming
  `integer out of range [64..65535]`, and 64/1350/65535 compile. The
  lenient load/peer-sync path warn-loads with a suffix tailored to the
  value: 0/non-integer/negative is `treated as unset/0`, 1..63 is
  `kept; values below 64 collapse throughput`, >65535 keeps the Layer-A
  coercion wording. `ipsec-vpn` still rejects on any value before this
  gate (unchanged). NOT changed: Layer A `coerceWireU16` in
  `pkg/dataplane/userspace/flow.go` (still [0,65535] wire safety — the
  strict/lenient doctrines are independent), `parseMSSValue`/
  `selectMSSToken` precedence, Rust `clamp_tcp_mss`, schema opacity.
  The `flow_numwidth_agreement_test.go` tcp-mss entry now models the
  documented exception (Layer B stricter than Layer A for 0..63, like
  the collector-port field) — first-principles: Layer B must never
  reject a value Layer A needs, but rejecting operator-invalid values
  Layer A would pass through unchanged is exactly the commit gate's job.
  `docs/config-schema.md` #1979 Tier-3 paragraph updated from
  `[0, 65535]` to `[64, 65535]`.

## Risk

Bounded to `security flow tcp-mss` commit-time validation. A legacy
persisted/peer config carrying 0..63 now warn-loads instead of silently
loading (0 stays unset; 1..63 stays in effect with a throughput
warning); strict commit rejects it, matching Junos. No dataplane,
