# #18634 — constrain primary-not-held warnings to RETH units

- **Why**: The primary-not-held warning diagnoses a RETH failover state: this node is primary for a redundancy group, but the kernel holds no address on one of that RETH's prefixes. Non-RETH units have no such RG ownership signal. If `isReth` is dropped from the plan's `primaryNotHeld` gate (surviving W5 from #18625), a non-RETH unit with no held address is incorrectly recorded and later warned.
- **What**: Added `TestWarmPrimaryNotHeldExcludesNonRethUnit_18634` to the existing neighbor warm visibility tests. It removes the management unit's local address, verifies the non-RETH unit contributes no `primaryNotHeld` key, calls health after the grace and verifies no warning, and verifies the warm-pass count stays zero. No production code changed.
