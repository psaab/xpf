# #15725 — REST GET /api/v1/show-text drops SNMPv3 USM users, nested address-sets, dynamic-address bindings & shrink-guard state, and flow acceleration knobs

## Issue

- `GET /api/v1/show-text` (pkg/api/show_text.go) rendered from config maps but omitted state the gRPC `ShowText` renderers carry:
  - `topic=snmp`: Location/Contact/Description/Communities/TrapGroups only — no SNMPv3 USM users.
  - `topic=address-book`: address-sets printed only `as.Addresses`, so a set grouping other sets (nested `AddressSets`) read as `members: ` (empty).
  - `topic=dynamic-address`: FeedServers only — no dynamic-address bindings, no shrink-guard / content-churn guard lines.
  - Flow acceleration knobs: cited in the claim, but already fixed on master via #15649 (`RenderFlowTimeouts` SSOT shared by CLI/gRPC/REST renders `GREPerformanceAcceleration` / `PowerModeDisable`). The regression test pins them so they cannot silently drop again.
- Note: the issue fixture's flow legs used the non-existent spelling `power-mode-ipsec-disable` and the non-gRPC strings `GRE performance acceleration: enabled` / `Power mode IPsec: disabled`. The real knobs are `gre-performance-acceleration` and `power-mode-disable`; rendering the issue's literal strings would re-diverge REST from gRPC, so the test asserts the shared SSOT wording instead.

## Root cause

- REST hand-rolled its own per-topic renderers instead of mirroring the gRPC renderers (`showSNMP`, `showAddressBook`, `showDynamicAddress`); each gRPC-side addition (#12903 nested sets & bindings, shrink guard) landed on one surface only.

## Fix

- `pkg/api/show_text.go`:
  - `snmp`: after Trap groups, render `SNMPv3 USM users:` with `  <name>: auth=<proto|none> priv=<proto|none>` in sorted order, matching gRPC `showSNMP` / local CLI wording exactly; nil slots skipped (#10439); passwords (config.Secret) never rendered.
  - `address-book`: address-set members now append nested sets as `set:<name>` after direct addresses, matching gRPC `showAddressBook` (#12903).
  - `dynamic-address`: per feed-server, render the hold-interval default line (`none (last-good set retained indefinitely)`), `Shrink guard:` and `Content churn guard:` lines with effective thresholds (config values, overridden by positive runtime `FeedInfo` values, clamped to the same defaults/ranges as gRPC); then a `Dynamic Address Bindings:` section (`  <name>: feeds <list>, fail-mode <mode|retain>` + `    Enforced: <feeds.BindingEnforcement verdict>`) using the same runtime snapshot (`s.feedsFn`) as gRPC. The REST-only compact `Feed runtime status:` summary is retained after the config sections. New helper `dynamicAddressRuntimeName15725` mirrors gRPC `dynamicAddressRuntimeNames` (first FeedEntries name, else FeedName, else server name).
  - `flow-timeouts`: unchanged (already the #15649 SSOT); pinned by the regression test.
