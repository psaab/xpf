# Issue #16475 — `PeerPrimaryRGs` nested `m.mu.RLock` wedges cluster manager

- **Issue:** `Manager.PeerPrimaryRGs` took `m.mu.RLock` and then called
  `DataGroupIDs`, which takes `m.mu.RLock` again. Go's `sync.RWMutex`
  prohibits recursive read locking: a writer (`handlePeerHeartbeat`'s
  `m.mu.Lock`) queued between the two RLocks blocks the inner RLock,
  while the writer can never acquire because the outer RLock is never
  released. `cluster.Manager.m.mu` wedges for good — heartbeat receive
  and build, election, and status all freeze until xpfd restarts.
  Trigger: a forwarded `request chassis cluster failover data node
  <peer>` whose proxy leg times out, reaching `peerclient.Reconcile` →
  `PeerPrimaryRGs` while a peer heartbeat arrives.

## Fix

- `pkg/cluster/group_state.go`: extracted `dataGroupIDsLocked()` (the
  `*Locked` convention already used in this package, e.g.
  `controlLinkAcceptedKeysLocked`) holding the group-ID iteration and
  sort. `DataGroupIDs()` now takes the RLock and delegates;
  `PeerPrimaryRGs()` calls `dataGroupIDsLocked()` under its single
  outer RLock. No behaviour change: same ascending order, RG0 excluded.

## Tests

- New `pkg/cluster/peerprimary_nested_rlock_16475_test.go`:
  `TestPeerPrimaryRGsNoNestedRLock16475` runs the real `PeerPrimaryRGs`
  against a churning `m.mu.Lock` writer for the 5s acceptance window,
  samples progress in both halves, requires both reader and writer
  iteration counters to strictly advance, requires clean shutdown, and
  re-checks the returned value (`[1]`, alive, RG0 excluded).

RED → GREEN proof: with `PeerPrimaryRGs` temporarily reverted to call
`DataGroupIDs()` (nested RLock), the new test fails at 10s with
"PeerPrimaryRGs/writer goroutines did not exit after stop: m.mu is
wedged"; with the fix it passes in 5.0s.

```text
go vet ./pkg/cluster/ → clean
go test ./pkg/cluster/ -run 'TestPeerPrimaryRGsNoNestedRLock16475|TestPeerPrimaryRGs15081|TestFailoverProxyBudgetMatchesAckTimeout15081' -count=1 → PASS
go test ./pkg/peerclient/ -count=1 → PASS
```

Main should run the full neighbouring suites:
`go test ./pkg/cluster/ ./pkg/peerclient/ -count=1`.

## Risk

- None expected: the change removes one RLock/RUnlock pair from
  `PeerPrimaryRGs` and routes both accessors through one lock-free
  helper; ordering, RG0 exclusion, and peer-liveness semantics are
  unchanged (pinned by `TestPeerPrimaryRGs15081` and the new test's
  post-churn value check).
- Census: `PeerPrimaryRGs` was the only in-package nested self-locking
  accessor call on `m.mu` (grep for `.DataGroupIDs()` / `.PeerPrimaryRGs()`
  inside `pkg/cluster` now shows only the test's external calls); a
  broader audit test was not added.
