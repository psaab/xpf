# #13966 — meter and classify flowless transit on ingress

Flowless transit packets (including non-first fragments and ICMP control
traffic) were excluded from the TX-selection ingress input-filter walk.
The earlier input-filter enforcement path evaluates policy without metering,
so input policers did not charge these packets and filter-assigned forwarding
class / DSCP rewrites were lost. A peer could evade an input rate limit by
fragmenting traffic, while fragments of one datagram could use inconsistent
queues or markings.

The fresh flowless TX-selection path now re-walks the ingress filter against
the pre-NAT L3 metadata, with ports marked unknown, metering policers and
propagating the filter forwarding class and DSCP rewrite. The cached flowless
sibling captures the same L3 class/rewrite and policer handles for replay.
Port-constrained terms continue to fail closed for flowless packets.

Regression evidence: on pristine master `baaba213a`,
`h18_13966_flowless_fresh_arm_is_policed_and_classified` failed at the
assertion that the flowless packet must be dropped by the input policer.
After the fix, all four `h18_13966` tests passed (flow-keyed control, fresh
flowless behavior, cached-flowless parity, and port-term exclusion). The full
CoS-classification test module passed: 96 passed, 0 failed.
