## Why

#18616 makes the standby refuse a synced change to its own control-link
address. The primary's local commit could still promote the peer's new address
and report success, leaving the standby on its old text and nacking every
re-push. The runtime heartbeat already has the authoritative address it dials;
peer-effective validation in the config registry cannot see that running
endpoint.

## What

`commitWithGenBinding` passes the bound candidate generation to its
preflight callback. It retries the new gate's marked stale-sample conflict;
unrelated preflight conflicts, such as the DNS-refresh fence, remain fail-fast.
`CandidateGateSample` provides private active and candidate tree copies together
with the candidate generation. The gate applies the peer-sync retired-dataplane
rewrite to the active tree and compiles the running peer view; the running
heartbeat address must occur in its rendered static control addresses.
DHCP-derived or foreign addresses abstain. The gate rewrites the sampled
candidate tree in the same way and compiles the candidate peer view. The
#18623 composition also compares fresh-bind selection when the candidate keeps
that static IP but changes selectors or the ordered CIDR list. Running and
candidate picks use their respective compiled peer views'
`Chassis.Cluster.PeerAddress` to select the address family, not this node's
dialed peer address.

A missing running heartbeat endpoint, or one not statically rendered by the
running peer view, is an abstention. A statically configured running endpoint
missing from the candidate view is rejected; #18623 also rejects a
selector/order/prefix change when the peer's next fresh bind would select a
different address. Both refusals happen before promotion with the BOTH-nodes /
offline xpfd restart procedure. The gate is wired only in `commitAndApply` and
`commitConfirmedAndApply`; peer-synced apply is unchanged.

## Risk and gaps

gate is to verify that a peer-address renumber is refused over TCP without a
nack storm; this work does not claim that acceptance. A running peer-view compile
failure abstains because the gate cannot prove the heartbeat address was static;
a candidate peer compile failure still rejects the commit.
