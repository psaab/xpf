# #16517: native-GRE anchor kept kernel TUN MTU 1500; adoption reset it to 1500

- **Timestamp**: 2026-10-24
- **Action**: Default the native-GRE AnchorOnly TUN MTU from the
  underlay minus GRE overhead when no MTU is configured, mirroring
  `wgTunMTUForEndpoint` (#2300) and the Rust `native_gre_inner_mtu`
  SSOT (transport MTU minus outer IP 20/40 minus GRE 4, +4 keyed).
  New `anchorDesiredMTU` in `pkg/routing/tunnel.go` returns the
  operator MTU verbatim when configured, otherwise 1476/1472
  (IPv4 outer unkeyed/keyed) or 1456/1452 (IPv6 outer) for GRE /
  ip6gre / unset-mode anchors, with the outer family derived from
  the endpoints exactly as the snapshot emitter derives
  `OuterFamily` (destination first, then source). It returns
  `ok=false` for IPIP or unparseable/missing endpoints, preserving
  the pre-fix ownership behaviour there byte-for-byte.
  `applyAnchorLocked` now writes that MTU on create (previously only
  a configured MTU was written, so a fresh anchor kept the kernel
  TUN default 1500). `reconcileAnchorMTULocked` now normalizes an
  adopted GRE anchor to the derived value instead of a literal 1500
  (which reset a correctly reduced 1476 device back into the
  silent-drop band), and on owned reuse lowers a stale above-budget
  GRE anchor (e.g. a pre-fix 1500) once to the derived value —
  lower-only, so a smaller hand-set MTU is never raised and there is
  no per-commit fighting. Non-GRE owned reuse remains untouched, so
  the existing #1884 tests (`TestTunnelApplySecondApplyNoChurn`,
  `TestTunnelAnchorRestartAdoptionNormalizesMTU` with its
  endpoint-less anchor, the EEXIST owned-name cell) pass unchanged.
  No Rust change: with the anchor at the derived MTU the kernel no
  longer hands the local-origin path packets in the 1477-1500 /
  1457-1500 band, and the #2331 encap guard plus the #2330 transit
  PTB remain the backstop for a non-1500 underlay. No gate was
  weakened (fail-open check: the encap guard is untouched).
- **File(s)**: `pkg/routing/tunnel.go`,
  `pkg/routing/tunnel_gre_anchor_mtu_16517_test.go`,
  `pkg/config/types_routing.go` (MTU field comment),
  `pkg/routing/README.md`, `debian/changelog`, `docs/log/16517.md`
- **Validation**:
  - RED (pre-fix behaviour pinned by the new cells' expectations):
    create wrote no MTU, adoption wrote `[1500]`, owned reuse never
    lowered a stale 1500 — each new test names that failure mode.
  - `GOCACHE=/var/worktrees/.cache go test ./pkg/routing/ -run
    'TestAnchorDesiredMTU16517|TestGREAnchor|TestTunnelAnchorRestartAdoptionNormalizesMTU|TestTunnelApplySecondApplyNoChurn|TestTunnelAnchorEEXISTRace' -count=1 -v`
    passed (10 `anchorDesiredMTU` subtests + create v4/v6 +
    configured-1400 control + adoption + owned-lower + 3 legacy
    cells).
  - `GOCACHE=/var/worktrees/.cache go test ./pkg/routing/ -count=1`
    passed (full package).
  - Residual: the derived default assumes a 1500 underlay (same
    model as `wgDefaultOuterMTU` / the Rust 1500 fallback). On a
    smaller real underlay the Rust encap guard still drops
    oversize local-origin packets without a PTB into the TUN; an
    operator `mtu` remains the workaround there, exactly as for
    WireGuard. Adding a local-origin PTB reinject was not needed to
    meet the acceptance (the 1457-1500 rows now succeed because the
    kernel never emits them) and is left as a possible follow-up.
