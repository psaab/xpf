# #18606 — refuse a live renumber of this node's control-link address

- **Branch:** `fix/18606-control-addr-refusal` (worktree `/var/worktrees/fix-18606`,
  from origin/master `960e6397a4`). Refs #18606; the local-node re-bind half is
  in PR 18601.

## Why

PR 18601 (issue 18597) made the heartbeat restart conditional. Before it, a
commit that renumbered this node's control address (same interface, same
peer) failed loudly by accident: the per-apply `RestartHeartbeat` could not
bind the stale `hbLocalAddr` and the commit failed through #9751 — after it
had already been applied. After it, the commit succeeded and the pair
partitioned silently. A live renumber cannot work from one end: the peer's
matching `peer-address` change is refused by #8965 on whichever node it is
local to. This change refuses it before promotion, in #8965's words.

## Census

- **Preflight callers.** `clusterControlEndpointCommitPreflight` (#8965) is
  called at exactly three sites in `pkg/daemon/daemon_apply_commit.go`:
  `commitAndApply` (local commit), `syncAndApplyWithAncestry` (peer-synced
  apply) and `commitConfirmedAndApply`. The new gate is wired beside it at all
  three.
- **Promotion paths.** Every production promotion reaches one of the three:
  the CLI, API and event-engine commits route through `commitFn`, which is
  `commitAndApply` in the daemon (the `commitFn == nil` store-only fallbacks are
  test/standalone paths); `rollback N` stages a candidate that then commits
  through the same path; the confirm-timeout rollback restores the ACTIVE
  config (the address the heartbeat already runs on); boot applies run no
  preflights and run before comms start.
- **Lab flows.** No script under `test/incus/` or `scripts/` changes em0 or a
  control address live (grep for `set|delete ... interfaces em0`,
  `control-interface`, and the loaded `.set` snippets: no match; positive
  control: the same grep finds em0 in every `docs/ha-cluster*.conf`). Lab
  deploys push `xpf.conf`, clear the config DB and restart xpfd (boot path).
  All five lab cluster configs (`docs/ha-cluster{,-loss,-tcp,-udp,-userspace}.conf`)
  keep em0's address inside `groups node0`/`node1`, so a peer-synced text
  compiles to this node's own address.
- **#18575** was the tcp/udp WAN v4 renumber (`lab: renumber tcp/udp WAN v4 off
  foreign-held addresses`), not the control link.

## Predicate

Refuse when the address the running heartbeat is bound to
(`cluster.Manager.HeartbeatLocalAddr`) is no longer a configured static
address of the candidate's control-link unit. Membership, not equality with a
selected address (two addresses can resolve in a different order). Abstain
when no heartbeat is running (boot, first cluster commit, fabric-transport
epochs, node-id changes via #6192), when the candidate has no control link, and
when the unit carries no static address (DHCP). Ordered after #8965 and #8987,
so a peer-address or interface change gets their more specific refusal.

`HeartbeatLocalAddr` is the identical hunk PR 18601 adds to
`pkg/cluster/manager.go`, applied verbatim so the two branches merge cleanly.
