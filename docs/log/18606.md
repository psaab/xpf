# #18606 — refuse a live renumber of this node's control-link address

- **Branch:** `fix/18606-control-addr-refusal` (worktree `/var/worktrees/fix-18606`,
  from origin/master `960e6397a4`). Refs #18606; the local-node re-bind half is
  in PR 18601.

## Why

PR 18601 (issue 18597) made the heartbeat restart conditional. Before it, a
commit that renumbered this node's control address (same interface, same
peer) failed loudly by accident: the per-apply `RestartHeartbeat` could not
bind the stale `hbLocalAddr` and the commit failed through #9751 — after it
had already been applied. After it, the commit succeeded and the pair
partitioned silently. A live renumber cannot work from one end: the peer's
matching `peer-address` change is refused by #8965 on whichever node it is
local to. This change refuses it before promotion, in #8965's words.

## Predicate

Refuse iff this commit removes the address the running heartbeat is bound to:
the bound address (`cluster.Manager.HeartbeatLocalAddr`) is a configured static
address of the RUNNING config's control-link unit, and the candidate's unit no
longer carries it.

- Membership in the candidate, not equality with one selected address: two
  configured addresses can resolve in a different order.
- Membership in the RUNNING config (review): a unit with `dhcp` and a static
  address binds the DHCP lease (networkd renders no static IPv4 for a DHCPv4
  row), and a foreign address listed first can win the bind. Neither is a
  configured address, so no commit removes it; the first revision compared the
  candidate alone and would have refused every commit on such a node.
- A candidate that drops every static address (static -> DHCP) and so strands
  the bound one is refused like any renumber.
- Abstains when no heartbeat is running (boot, first cluster commit, fabric
  epochs, node-id changes via #6192) and when the candidate has no control
  link. Ordered after #8965 and #8987.
- The commit paths pass the pre-promotion `store.ActiveConfig()` as the running
  config; the synced path passes `oldActive`, captured before `SyncApply`.

`HeartbeatLocalAddr` is the identical hunk PR 18601 carried in
`pkg/cluster/manager.go` (since dropped there), so the branches merge cleanly.

## Review fold: refuse the synced renumber BEFORE promotion (seat AH)

AH blocked 79d317d5b3: `syncAndApplyWithAncestry` ran `SyncApply` (which
promotes the pushed text) and only then the #18606 gate. After one refusal the
store's active config named the new address while the heartbeat stayed on the
old one, so the gate's running-config arm abstained from then on: the identical
re-push after the nack, any later push and any later local commit all passed,
and every background applier (DHCP callback, feeds, config poll, apply-debt
retry) applied the promoted text with no preflight. The partition arrived
silently within one reconcile cadence.

Fix: `configstore.Store.SyncApplyGated(content, preserve, gate)` runs `gate` on
the compiled peer config under the store lock, after compile and BEFORE the
history push, the active swap and persistence; a refusing gate leaves the store
untouched. `SyncApply` is `SyncApplyGated(..., nil)`. The synced path runs the
#18606 gate inside it, so the standby keeps its config and nacks, and every
re-push is refused identically. The refusal and its Error log now say how to
renumber: offline, by putting the new address in each node's boot
configuration and starting both nodes.

Cells: (a) the identical re-push is still refused, (b) a later push carrying
the renumber is still refused, (c) a later local commit is still refused,
(d) the active config a background applier would apply is unchanged; and
`TestSyncApplyGatedRefusalPromotesNothing18606` in pkg/configstore. Mutants:
refuse-after-promotion (killed by (a), (c) and (d)), the store never calling
the gate (daemon and configstore cells), the synced site unwired (census) —
all killed.

## Review fold: rendered addresses and residuals (seat AE)

- The gate now compares the address set networkd RENDERS: a family whose DHCP
  client is on renders none of its static addresses (`pkg/networkd`
  generateNetwork, #2986; IPv4 under `dhcp`, IPv6 under `dhcpv6` /
  DHCPv6Client). So adding `dhcp` to the control unit while keeping the bound
  static address — which suppresses that address and strands the heartbeat —
  is refused (`TestAddingDHCPToTheControlUnitIsARenumber18606`).
- Residual, documented rather than fixed: deleting `dhcp` from a dhcp+static
  unit while the heartbeat is on the LEASE. The lease is in no config, so the
  running-config arm abstains. It needs a DHCP control link that a static
  `peer-address` targets, which is impractical.
- Residual: a reboot-recovered pending `commit confirmed`. If the unconfirmed
  commit moved the address while comms were down and the box reboots, the
  recovered rollback runs no cluster gates — the same as #8965.
- Cell (d) now drives a real background applier: the #9811 retry operation
  (`configApplyReassertFn`) after a refused push, captured at
  `applyBodyForTest`, applies the unchanged em0 address.
- `TestActiveSnapshotPublishCoversEverySwap9905` (pkg/configstore) fails on
  pristine origin/master too (10 compiled swaps against the expected 9); not
  this change, which adds no swap.
