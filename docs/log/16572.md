# #16572: Junos `disable` under routing protocols modelled

- **Timestamp**: 2026-10-24
- **Action**: Modelled `disable` at protocol level (`ospf`, `ospf3`,
  `bgp`, `isis`, `rip`) and interface/neighbor level (OSPF/OSPFv3/IS-IS
  interfaces, BGP group inherited by its neighbors, BGP neighbor) in
  `pkg/config/schema_routing.go` (schema leaves, so the statements stop
  drawing the #10707 open-world advisory), `pkg/config/types_routing.go`
  (`Disable` fields), `pkg/config/compiler_protocols.go` +
  `compiler_bgp_neighbor_merge_9192.go` (compiler arms for braced, flat
  and packed spellings; any fragment's disable wins via the find-or-create
  merge and the OSPF union in `ospf_interface_union_12186.go`). The FRR
  renderers (`pkg/frr/protocols_render*.go`) emit nothing for a disabled
  protocol and no activation for a disabled interface/neighbor (including
  no passive-interface directive and no BFD peer). The #11571
  managed-routing host-inbound collector
  (`compiler_validate_warn_host_inbound.go`) skips disabled protocols and
  interfaces, so the gate no longer demands `ospf` on an excluded
  segment's zone; disabled BGP is exempt from the router-AS and peer-as
  strict gates (`compiler_validate_strict_routing.go`). Previously
  `interface ge-0/0/1.0 { disable; }` compiled to an active OSPF
  interface that rendered `ip ospf area`, and a whole-protocol
  `ospf disable`/`bgp disable` left the protocol running.
