# #12095 — mark excluded static routes in REST

- **Issue**: #12095 — REST `GET /api/v1/routes` lists configured static routes dropped by the snapshot builder without explaining why they are not installed.
- **Branch**: `fix/12095-rest-marker`
- **Worktree**: `/var/worktrees/12095-rest-marker`
- **Base**: `1c384b9a47ff7d6e567fa50632faa75c3995ae87`

## Why

`routesHandler` renders configured static routes, including routes excluded from the installed snapshot. Without a marker, the REST inventory suggests those routes are active, unlike the gRPC/CLI show-route text that labels them with the shared `config.StaticRouteExclusions` verdict.

## What

- Added optional `RouteInfo.not_installed_reason` and compute the whole-config exclusion map once in `routesHandler`, preserving the order-dependent next-table-window verdict.
- Copy each excluded route's shared reason to every REST row across the global IPv4/IPv6 tables and per-routing-instance IPv4/IPv6 tables. Installable rows omit the field and keep their existing JSON shape.
- Added `routes_notinstalled_red_12095_test.go`, covering four excluded route sources/reasons and a non-excluded next-hop control; documented the REST contract in `pkg/api/README.md`.
