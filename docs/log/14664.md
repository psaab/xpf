# #14664 — `tcp-mss all-tcp` is not a ceiling on tunnel egress when no `gre-out` is set

## Defect

`select_tcp_mss` (userspace-dp/src/afxdp/forwarding/mss.rs) resolved
tunnel egress as: return the tunnel value if > 0, else `all-tcp`.
`native_gre_tcp_mss` min-ed an explicit `gre-out` with the MTU-derived
value but never min-ed `all-tcp` in, and the WireGuard arm in
`tunnel_tcp_mss` returned the purely MTU-derived WG value uncapped.
So with `all-tcp 1200`, no `gre-out`, and a derived GRE MSS of 1416
(or WG 1365), a tunnel-bound SYN advertised 1416/1365 — contradicting
the header contract (`mss.rs:6-19`, "applies to every forwarded TCP
SYN regardless of tunnel context") and `docs/feature-gaps.md`
("all-tcp — clamps every forwarded TCP SYN"). Operators set `all-tcp`
below the tunnel budget precisely when a downstream link is smaller;
those flows then depended on PMTUD, the blackhole the knob exists to
prevent. Scoped to tunnel-bound flows with no `gre-out`; all callers
(frame/build, tx/dispatch, flow_cache_hit, neighbor_dispatch) go
through `select_tcp_mss`, so the gap was uniform.

## Fix

Min only the implicit MTU-derived tunnel value with `all-tcp`; keep an
explicit `gre-out` as `min(gre-out, derived)` irrespective of `all-tcp`
(Junos: a GRE-specific value overrides `all-tcp` only when configured;
no precedence is given to an implicit MTU-derived value).

- `native_gre_tcp_mss`: the `gre-out > 0` branch is unchanged
  (`min(gre-out, derived)`); the no-`gre-out` branch now returns
  `min(derived, all-tcp)` when `all-tcp > 0`, else the derived value.
- `tunnel_tcp_mss` WireGuard arm: the WG value is purely MTU-derived
  (`gre-out` is a GRE-only knob and never consulted there), so it is
  capped by `all-tcp` when set.
- `select_tcp_mss` itself is unchanged: a tunnel value of 0 still
  falls back to `all-tcp`, non-tunnel and `gre-in` paths untouched.
- Header doc on `effective_tcp_mss`, the `select_tcp_mss` priority
  doc, and `docs/feature-gaps.md` now agree: `all-tcp` is a ceiling
  only on the implicit derived value on tunnel egress; explicit
  `gre-out` stays `min(gre-out, derived)` irrespective of `all-tcp`.

NOT changed: the derived-value formulas, the `gre-in` arm, the plain
forward arm, and any caller — the fix is confined to the two derived
returns inside `mss.rs`.

## Regression tests

Five cells in `userspace-dp/src/afxdp/tunnel_tests.rs`, all through
the public selector `select_tcp_mss`:

- `select_tcp_mss_gre_all_tcp_caps_mtu_derived_value_14664` — GRE,
  all-tcp 1200, no gre-out, derived 1416 → 1200 (decisive RED cell).
- `select_tcp_mss_wg_all_tcp_caps_mtu_derived_value_14664` — WG arm,
  all-tcp 1200, derived 1365 → 1200 (decisive RED cell); controls pin
  the uncapped 1365 with all-tcp unset and with gre-out set (gre-out
  must not affect WG).
- `select_tcp_mss_gre_all_tcp_zero_keeps_derived_value_14664` —
  all-tcp 0 → derived 1416.
- `select_tcp_mss_gre_explicit_gre_out_ignores_all_tcp_14664` —
  gre-out 1300 with all-tcp 1200 → 1300; gre-out 1100 → 1100
  (explicit gre-out pinned irrespective of all-tcp).
- `select_tcp_mss_gre_all_tcp_above_derived_keeps_derived_14664` —
  all-tcp 1460 → 1416 (ceiling, not a floor).
