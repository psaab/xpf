## Design (the issue's recommended direction)

- **Boot.** `checkRecoveredConfirmTarget` runs after manager-init. It alarms (slog error, journal entry, CLI pending-window line) and never un-arms.
- **Fire.** `confirmRollbackTargetHandledAtFire` checks the pending target before promotion:
  - feed-only refusal: defer via `DeferConfirmTimer`, same generation, 5 s, at most 24 times;
  - any other refusal, or the cap reached: `PromoteRollback` (persisted as committed), `enterBootstrapMode`, `reconcileManagementAfterPromotion`; no apply;
  - appliable target: unchanged.
- **Feed-only classification.** The refusal disappears when every dynamic-address binding is given a resolved overlay.

## Not changed

- The remote CLI's `ConfirmPending` flag does not carry the alarm text; the local CLI, journal and syslog do.
- The refused-target safe state follows the existing nil-target branch, which does not re-sync the rolled-back config to a cluster peer.
