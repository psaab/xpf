# Per-instance direct `interface-routes rib-group` silently dropped (#15659)

## Why

`routing-instances <name> interface-routes rib-group inet|inet6 <group>`
is the Junos-canonical placement and was admitted by the schema
(`schemaRoutingInstances` declares `interface-routes` directly under the
instance wildcard) and by the #9323 closed-world gate, and shipped tests
(`compiler_ribgroup_ref_2226_test.go`) even wrote that spelling — but
`compileRoutingInstances` had no `case "interface-routes"`. It only copied
`InterfaceRoutesRibGroup{,V6}` out of the nested `routing-options`
sub-block (`ro.InterfaceRoutesRibGroup` at the `case "routing-options"`
arm). A direct selector therefore compiled to `""`, generated no leak
prefixes via `RibGroupConnectedPrefixes`, installed no leak in
`pkg/routing/rules.go`, and was invisible to the strict undefined-group
gate (`validatePerInstanceInterfaceRoutesRibGroupStrict`), so a typo'd
group name committed clean.

## What

- `pkg/config/compiler_routing.go`: extract
  `compileInterfaceRoutesRibGroup` (routing-options parent) and
  `compileInterfaceRoutesRibGroupFromNode` (an `interface-routes` node
  itself) from the former inline block in `compileRoutingOptions`,
  preserving the #8939 packed-run split and inline `rib-group inet NAME`
  handling. Both now write only non-empty values.
- `compileRoutingInstances`: add `case "interface-routes"` invoking the
  FromNode helper seeded with the already-compiled selectors, and guard
  the `routing-options` copy with non-empty checks — so direct and nested
  selectors compose per-family regardless of stanza order and neither
  erases the other with an empty slot.
- Regression: `pkg/config/compiler_per_instance_direct_interface_routes_15659_test.go`
  `TestPerInstanceDirectInterfaceRoutesRibGroupCompiledAndValidated` —
  flat-set direct inet+inet6 compile to `dmz-leak-v4`/`dmz-leak-v6` and
  generate both leak prefixes, hierarchical direct inet compiles and
  leaks, undefined direct group is strict-rejected (and lenient-warned)
  for both families, and direct/nested selectors do not overwrite each
  other in either order.

NOT changed: schema declarations, the #9323 gate, strict/lenient gate
wiring (they already key off `ri.InterfaceRoutesRibGroup{,V6}`, so a
compiled direct selector is validated with no gate change), or any
renderer/applier.

## Validation

- RED (test only, on origin/master d316277cb4):
  `TestPerInstanceDirectInterfaceRoutesRibGroupCompiledAndValidated`
  FAILS — `InterfaceRoutesRibGroup = ""` (flat and hierarchical), strict
  compile accepted undefined `missing-group` for inet and inet6, and
  direct inet was lost beside a nested selector.
- GREEN (fix applied): same test PASSES all subtests.
- Related suites and spelling-gate ratchets: see PR body.
- Spelling gate: `TestSpellingGateMembersAreRecorded7484` measured the
  two direct `routing-instances <*> interface-routes rib-group
  inet|inet6` leaves reclassified `unreachable` -> `COMPARED`; the
  member registry rows and ratchets (floor 801 -> 803, unreachable
  164 -> 162) are updated. That run also showed six unrelated vrrp
  drift reclassifications against the recorded registry — not touched.

## Risk

Configs that today carry a direct selector plus a conflicting nested
selector for the same family now resolve last-non-empty-in-source-order
instead of nested-always-wins; same-family duplicates were previously
half-dropped silently, so no working config changes behaviour.
