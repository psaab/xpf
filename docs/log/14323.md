# #14323 — Little-endian vs big-endian IPv4 map-key mismatch breaks GRE-inner and WG kernel-path local/NAT lookups

## Defect

Go writes the `userspace_local_v4` / `userspace_interface_nat_v4` /
`dnat_table` BPF map keys with `binary.BigEndian.Uint32`
(`pkg/dataplane/userspace/maps_sync.go`), and the XDP shim's healthy
path reads them via `parse_ipv4`'s `u32::from_be_bytes`
(`userspace-xdp/src/lib.rs`). Two sites used `u32::from_ne_bytes`
instead, under comments falsely claiming Go uses native endian:

- `classify_native_gre_inner_ipv4` (`userspace-xdp/src/lib.rs`) — inner
  IPv4 DNAT / interface-NAT / local probes.
- `shim_v4_key` (`userspace-dp/.../wg_control/kernel_path.rs`) — WG
  kernel-path `destination_is_local` probes.

On little-endian hosts every non-palindromic address byte-reverses:
real local destinations missed (management over WireGuard lost on
uncovered/degraded ingress), transit destinations whose reversal is
local falsely claimed, interface-NAT VIPs not excluded when the
reversal is local. Palindromic addresses and established-session
traffic (byte-array session key, probed first) were unaffected.

The `#9594` test seam compounded it: `TestShimMaps9594` stored
`IpAddr` and compared directly, bypassing `shim_v4_key` entirely, and
the pinning test asserted `shim_v4_key == from_ne_bytes` against
itself.

## Fix

- New `core`-only `userspace-xdp/src/ipv4_key.rs::ipv4_map_key`
  (`u32::from_be_bytes`), host-compilable like `early_filter` /
  `ipv4_len_gate`. Both `parse_ipv4` and
  `classify_native_gre_inner_ipv4` route through it, so the two shim
  sites cannot drift again.
- `shim_v4_key` now `u32::from_be_bytes`; false comments corrected.
- `TestShimMaps9594` stores encoded keys (`local_v4: (domain, u32)`,
  `interface_nat_v4: u32`, v6 octets) populated via
  `insert_local` / `insert_interface_nat`, which route through
  `shim_v4_key`; the test branch of `destination_is_local` probes with
  the same encoded keys as the bpffs branch.

NOT changed: the `dnat_table` IP field semantics — its Rust writer
(`checksum.rs::dnat_v4_key_bytes`) copies raw octets and the Go writer
carries `SessionValue.NATSrcIP` in native order, so in-memory key bytes
are wire order on both sides and agree with the fixed BE reader; the
port field was already host-order per #2406. IPv6 paths (byte arrays)
were never affected.

- `kernel_path::tests::test_seam_destination_is_local_uses_encoded_keys_14323`
  — reversed local entry must not claim the real destination.
- `frame::tests_shim_ipv4_key_14323` — executed parity: shim
  `ipv4_key` (by source) vs production `shim_v4_key` vs Go BigEndian
  writer, non-palindromic + palindromic + reversed-transit cells.
