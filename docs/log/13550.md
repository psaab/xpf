# Issue #13550: chunk combined NFQUEUE submissions and account early refusal

- **Root cause:** `eligibleLocked` caps the selected heads per owner, but the
  flattened owner batches can exceed `reinjectMaxFrames` (64). The single
  socket submission then rejected all frames, and the shared admission-failure
  path retired every flow. D11 admission refusal also ignored a completion
  recorded before the refusal, despite that ordering being uncertain.
- **Change:** `submitAdmitted` now submits ordered chunks no larger than the
  socket cap and applies each chunk's responses to the matching pending items.
  D11 refusal with an early completion increments `Uncertain` and retires the
  flow after terminalizing the refused head. No wire protocol or cap changed.
- **Regression:** `TestCombinedBatchOverWireCapIsChunked13550` creates 64 eligible
  frames for each of two owners; it failed on the pristine base because the
  combined 128-frame call was rejected (`submitted = 0, want 128`) and passes
  after chunking. `TestEarlyCompletionThenRefusalCountsUncertainAndRetires13550`
  failed on the pristine base (`Uncertain=0`) and passes after accounting and
  retirement were added.
- **Validation:** Both focused regressions pass with and without `-race`; `go
  build ./...` passed, and `gofmt -l` reported no touched-file formatting
  differences. The complete `go test ./pkg/nfqueue -count=1` run was attempted
  but failed in environment-dependent measurements (`TestMeasureMemory9506`
  UDP send timeout; `TestMeasureStages9506` bounded verdict timeout) and
  Unix-socket tests (`bind: invalid argument` on generated socket paths).
  Repeated package-suite attempts also reached the same environment failures.
- **Files:** `pkg/nfqueue/pipeline.go`, `pkg/nfqueue/pipeline_attest_10484.go`,
  `pkg/nfqueue/pipeline_batchcap_13550_test.go`.
