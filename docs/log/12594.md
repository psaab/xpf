# 12594 — make the DSCP 7796 range cell load-bearing

- **Timestamp**: 2026-10-13
- **Action**: strengthened the out-of-range DSCP regression assertion to identify the encoder's own error rather than accept the kernel's `ERANGE`
- **Base**: `c49e22437` (`build: pin CLI linker flags (#12546)`)
- **Files**:
  - `pkg/routing/rule_dscp_kernel_7796_test.go`

## Why

`TestRuleAddDSCPRejectsOutOfRange7796` only checked for the substring `out of range`. With the production pre-flight range check removed, `RuleAddDSCP` passed the invalid value to the kernel; under `unshare -rn` the kernel returned `numerical result out of range`, so the test passed without exercising its intended guard.

## What

The cell now compares the complete error string with `dscp rule: dscp 64 out of range (0-63)`, the message emitted by the encoder's check. A kernel-generated errno (or another rejection) cannot masquerade as the pre-flight validation.

## Validation

- Mutant-kill after the change: with the guard disabled, the same command fails because the actual error is `numerical result out of range`, not the expected encoder message.
- Intact cell passed under `unshare -rn` and plainly.
- `unshare -rn go test ./pkg/routing -run '7796' -count=1`: passed.
- `go test ./pkg/routing -count=1`: passed.
