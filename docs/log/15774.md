# Issue #15774 — `show route` multi-surface parity (G47-03)

- **Timestamp**: 2026-10-19
- **Action**: Fixed G47-03 `show route` parity across local CLI, gRPC/remote
  CLI, `pkg/routing` formatters, and FRR detail:
  - gRPC `showRouteProtocol` now threads the active config, applies
    `routing.NormalizeRouteProtocol`/`RouteProtocolMatches` (the #15236
    normalization the local CLI already had), scans all tables via
    `GetAllTableRoutes` (main + routing instances), and returns
    `codes.InvalidArgument` for unknown protocols instead of `(no routes)`
    for an alias. The dispatcher in `server_show.go` passes `cfg` through.
  - `show route terse` (CLI + gRPC) reads `GetAllTableRoutes` and flattens
    via `routing.FormatRouteEntriesTerse`, so VRF tables are no longer
    omitted; `FormatRouteTerse` emits one row per ECMP leg.
  - `show route detail` (CLI + gRPC, shared `frr.GetRouteDetailJSON`) now
    queries `show ip/ipv6 route vrf all json`; `parseRouteJSON` accepts
    both the nested per-VRF shape and the flat legacy shape, stamps
    `FRRRouteDetail.VRF`, and `FormatRouteDetail` renders the VRF plus
    `Discard`/`Reject` for blackhole/unreachable nexthop types.
  - `show route instance` (CLI + gRPC) uses `GetInstanceRoutes` (configured
    table ID, else VRF-device lookup) instead of `GetRoutesForTable(tableID)`
    with a possibly-zero table ID, and renders via the shared ECMP-aware
    `routing.FormatRouteEntryRows`.
  - `FormatRouteDestination`: a bare CIDR with no modifier now matches
    routes contained within or equal to the prefix per
    `docs/junos-cli-reference.md:2821` (previously it returned covering
    supernets such as `0.0.0.0/0`); a bare IP keeps LPM covering-route
    semantics; `exact`/`longer`/`orlonger` are unchanged.
  - `formatTableJunos`: `discard`/`reject` next-hops render as Junos
    `Discard`/`Reject` lines (previously `>  to discard via ` with a
    dangling blank interface), and a gateway without an interface no
    longer emits a dangling `via`.
  - `show route table <name>` behaviour is unchanged.
- **Demonstration (pre-fix, base 320c26c08c)**: probe of
