# #12054 — reject inert `except` under `any-service`

- **Timestamp**: 2026-10-08
  - **Why**: `system-services any-service` is a packet-wide full-admit, not a subtractable union. The compiler kept `any-service` after `ssh except`, and strict compilation accepted the stanza while the generic breadth advisory omitted the discarded exclusion.
  - **What**: Strict host-inbound validation now rejects `any-service` with retained system-service exclusions and names the excluded token(s). The existing tolerant-path gate downgrades that diagnostic to a warning; the compiled service set remains `[any-service]` for persisted-config compatibility. Updated the host-inbound service matrix to document this distinction from `all` exclusions.
  - **File(s)**: `pkg/config/compiler_validate_strict_zones.go`, `pkg/config/compiler_host_inbound_except_12054_test.go`, `docs/host-inbound-service-matrix.md`.
  - **Validation**:

    - RED before fix: `go test ./pkg/config -run '^TestHostInboundExcept12054' -count=1 -v` failed both assertions: strict compile returned nil and lenient warnings omitted `ssh`.
    - GREEN after fix: the same command passed strict-fail and lenient-warn tests for hierarchical zone, flat-set zone, and per-interface cases; all preserved `[any-service]` on the tolerant path.
    - `go build ./pkg/config` passed; `go test ./pkg/config -run '^TestHostInboundExcept(12054|10292)' -count=1` passed, covering the complete #12054 regression file and existing #10292 exception suite.
