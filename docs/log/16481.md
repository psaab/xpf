# Deterministic NAPT64 pool append/shrink dropped live port reservations (#16481)

## Why

After any commit that changes the length of a deterministic NAPT64 pool
(adding or removing an address), `Nat64State::from_snapshots_with_previous`
builds a fresh port allocator (`host_count` changed, so `reuse_allocator`
misses) and — since #15178 — skipped the #6765 retained-address reseed for
every deterministic prefix. Session-hit revalidation keeps every session
whose subscriber's (pool index, block) did not move, i.e. exactly the
retained subscribers. The fresh allocator therefore re-minted the lowest
port of each subscriber's block, which is the port the subscriber's oldest
surviving session still holds. A second flow to the same remote endpoint
then shared the live reverse tuple (RFC 6146 BIB uniqueness violation;
v4→v6 replies could be demuxed to the wrong host/socket until the older
session ended).

#15178's premise — "deterministic on either side starts fresh; the
session-hit revalidation tears the old session down" — holds only when
the new geometry invalidates the tuple. A pool-length change does not
move a retained subscriber's block, so `deterministic_v6_tuple_matches`
still validates its tuple under the NEW params and revalidation keeps it.

## What

- `userspace-dp/src/nat/allocator/mod.rs`:
  - New `PortAllocator::reseed_retained_deterministic_v6_from`: for each
    live deterministic flow in the previous allocator whose translated
    address is retained and whose tuple still satisfies
    `deterministic_v6_tuple_matches` under the NEW params/pool, re-reserve
    the port bit in the fresh allocator and join/rebuild its BIB lease
    with the NEW `DeterministicPortedIdentity::V6(new_params)` (via
    `reserve_flow_maybe_persistent_with_identity`, so sibling flows share
    one lease and holder masks are preserved). Tuples that no longer
    validate are not carried and are counted
    (`skipped_deterministic_invalid`, `dropped_persistent_on_*`).
  - `ReseedOutcome` gains `reseeded_deterministic` and
    `skipped_deterministic_invalid`, classified in the exhaustive
    `needs_report()` destructure (invalid tuples gate the report; carried
    ones do not, like `reseeded`).
- `userspace-dp/src/nat64/state.rs`: on a fresh-allocator build, when
  both the previous and new prefix are deterministic, run the new
  deterministic carry; round-robin→round-robin keeps the #6765 generic
  `reseed_retained_from`; a mode flip (either direction) carries nothing
  and starts fresh exactly as #15178 required. Removes the now-dead
  `prev_prefix_is_deterministic` helper (and its line in the nat64 split
  visibility bill in `nat64/mod.rs`).

Idle BIB leases (no live flow) are intentionally not carried: they hold
no session, and a later same-socket flow re-derives the identical tuple
deterministically from the new geometry.

## Validation

- `r3n05_det_pool_append_reissues_live_tuple` (nat64): pool `[A]`→`[A,B]`,
  F1=(198.51.100.1,1184) is carried (live_flow_count 1), still validates,
  F2 to the same remote differs from F1, same-socket new-remote joins F1.
- `vn05_det_pool_shrink_reissues_live_tuple_and_tears_down_removed`:
  pool `[A,B]`→`[A]` carries only the retained subscriber; the
  removed-address subscriber fails validation; F2 differs from F1.
- Allocator-level cells in `nat/tests_det_reseed_16481.rs`: append carry
  blocks reissue and rebuilds the lease with the new identity; shrink
  carries retained/drops removed; block-size change (the #15178 case)
  carries nothing and the new flow mints in the new block.
- Controls unchanged: no-op re-apply reuses the allocator
  (`nat64_15178_noop_reapply_reuses_allocator_and_eim`), block-size /
  host-base / mode changes do not reuse (`nat64_15178_*`), round-robin
  reseed path unchanged.
- Rebase onto #16484 (scoped reseed selector): the reseed now selects
  the previous prefix via `find_previous_prefix` (rule identity), and
  #16484's `nat64_16484_rr_first_does_not_reseed_det_second` cell —
  which pinned "deterministic pool-grow starts fresh", the exact
  behaviour this issue fixes — is updated to the carried expectation
  while keeping its scoped-selection intent (tenant-b carries its own
  flow, never tenant-a's). All other #16484 cells pass unchanged.

## Risk

Commit-time work only; no per-packet cost. Deterministic sessions whose
tuple falls outside the new geometry are still torn down by revalidation
exactly as #15178 intended — they are simply no longer also counted as
carried. Round-robin NAT64 and no-op re-applies are behaviour-identical.
