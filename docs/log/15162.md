# #15162 — ListSessionsByPolicy turns every incomplete helper READ into an error with an empty result (B16-02)

- **Timestamp**: 2026-10-19
- **Action**: `ListSessionsByPolicy`
  (`pkg/dataplane/userspace/manager_sessions.go`) discarded the gathered
  aggregate on a terminal incomplete page
  (`SessionPolicyContinuation == "" && !SessionPolicyComplete`), returning
  `ControlResponse{}` plus a hard error. Every helper incomplete cause —
  dead worker, queue-full, worker-ack-timeout,
  shared-synced-map-uncovered, legacy-before-secs-missing, and
  capture-limit truncation to 262,144 rows
  (`userspace-dp/src/afxdp/ha/session_domain.rs`) — therefore lost the
  whole eager commit-time revocation: the daemon's "partial beats zero"
  arms in `daemon_policy_invalidate_capture.go` and
  `daemon_policy_invalidate.go` (`clearSessionsForPolicyIDs`) were
  unreachable through the real Manager, and zero sessions were deleted.
  Fixed by returning the aggregate with `SessionPolicyComplete=false`,
  the per-worker errors, and a nil error on a terminal incomplete page
  that gathered at least one row, so both daemon producers revoke the
  partial capture while still surfacing the gap via `readErr` /
  `enumFailed`. NOT changed: a stranded incomplete READ with zero rows,
  a repeated continuation token, and the 30s deadline remain hard errors
  with an empty result (fail closed — no authoritative empty, no partial
  to revoke); complete pages, authority refusal
  (`ErrPolicyReadAuthority`), page/aggregate caps, and all Rust helper
  behaviour are byte-identical.
- **File(s)**: `pkg/dataplane/userspace/manager_sessions.go`
  (terminal-incomplete arm of `ListSessionsByPolicy`),
  `pkg/dataplane/userspace/policy_read_verb_10512_test.go` (partial +
  paged-partial cells; zero-row cell retained as control),
  `pkg/daemon/policy_snapshot_recovery_joint_12072_test.go` (real-Manager
  daemon cell over a scripted socket), `docs/log/15162.md`

## Risk

Only the terminal-incomplete-with-rows arm changes: it now returns rows
the daemon already knew how to revoke partially. A zero-row incomplete
READ still fails closed, so no new fail-open direction is introduced;
the incompleteness remains visible via `SessionPolicyComplete=false`,
per-worker errors, `readErr`, and `enumFailed`, and HA-sync covers the
partial exactly as the pre-existing daemon contract specifies.
