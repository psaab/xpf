# Issue #12240 — retry rejected hold-drop publication

## Why

A hold-expiry drop updated manager state to empty before publishing it. When `onUpdate` rejected that apply, the old published hash remained and publication debt was visible, but later failed fetches skipped the drop transition because the feed no longer had a snapshot. The dataplane could therefore retain stale contents while the manager reported the feed dropped.

## What

The shared failure transition now recognizes a hold-dropped feed with pending publication debt and retries its empty-state publication on the next failed fetch. Retries use the existing refresh cadence, remain bounded to one callback attempt per failed fetch, and retain debt until a callback succeeds. The wall-clock hold-expiry path and ordinary fetch-failure drop path share the same publication handling. Added a regression that exercises #12241's wall-clock expiry, verifies debt after a rejected callback, retries on a subsequent failed fetch, and confirms debt clears only after the empty-set apply is accepted. Updated the feeds publication-debt documentation.
