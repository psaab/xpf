# Issue #15766 — Multi-address IKE gateways dropped, rejected, and pinned to the first peer address

## Claim (narrowed, verified at origin/master 320c26c08c)

1. `security ike gateway` / `security ipsec gateway` `address` lacked
   `multi: true` in the schema, and both compilers assigned
   `gw.Address = v` (last-wins), so repeated `address` leaves kept only
   the last peer and a bracket list `address [ ip1 ip2 ]` kept only the
   first.
2. A comma-separated `address ip1,ip2` (today's only spelling that
   survives into the compiled field whole) failed
   `validateIPsecEndpointsStrict` because the joined string is neither
   an IP nor a hostname; `addressFamilyHint` likewise failed
   `net.ParseIP` on the joined string and silently returned the
   family-agnostic hint.
3. `defaultRemoteID` pinned swanctl `remote.id` to the FIRST address
   of a multi-address list; `remote.id` is single-valued, so the same
   peer presenting from any other configured address would be
   rejected. The inline-endpoint arm (`gc.remoteAddr`) had the same
   first-only pin.

## Live verification (pre-fix, this worktree)

RED `TestIKEGatewayMultiAddressCompileValidateAndRender` on base:

- repeated: `gw.Address = "198.51.100.2"` (first peer dropped) on both
  gateway containers;
- bracket: `gw.Address = "198.51.100.1"` (second peer dropped);
- comma: strict compile rejected `address "198.51.100.1,198.51.100.2"
  is not a valid IP address or hostname`;
- comma-space (`address 198.51.100.1, 198.51.100.2`): accumulated
  value `"198.51.100.1,"` rejected the same way;
- direct multi-address gateway rendered `remote { id =
  "203.0.113.1" }` (first-only pin);
- inline multi-address endpoint (`vpn gateway 203.0.113.1,203.0.113.2`)
  was skipped by the renderer entirely (`IsUsableIPsecEndpoint`
  rejected the joined string), so it rendered no connection at all.

Single-address gateways worked (control arm passed pre- and post-fix).

## Fix

- `pkg/config/schema_security.go`: `multi: true` on gateway `address`
  in both the `security ike` and `security ipsec` containers.
- `pkg/config/compiler_ipsec.go`:
  - `SplitIPsecEndpointList` — the shared per-element splitter
    (exported for `pkg/ipsec`); drops empty elements, preserves order.
  - `gatewayAddressValues` — reads every endpoint from one `address`
    leaf across shapes (`Keys[1:]` + child tokens, comma-split per
    token; mirrors `firewallMatchValues`).
  - `accumulateGatewayAddresses` — appends distinct endpoints in
    authored order; deduplicates so compileIKE+compileIPsec both
    reading one gateway cannot duplicate entries. Both `address`
    compiler sites use it.
  - `IsUsableIPsecEndpointList` — per-element usability; used by the
    strict gateway-reference gate so an inline multi-address VPN
    endpoint commits, while any malformed element still fails closed.
- `pkg/config/compiler_validate_strict_ipsec.go`:
  `validateIPsecEndpointsStrict` validates every element of
  `gw.Address` and names the malformed element.
- `pkg/ipsec/policy_addr.go`: `addressFamilyHint` takes the family of
  the first literal element (hostname elements skipped).
- `pkg/config/compiler_validate_ipsec_gateway_routing_instance_12089.go`:
  `ipsecGatewayRemoteFamilies12089` collects each element's family
  (same joined-string defect on the routing-instance surface).
- `pkg/ipsec/policy.go`:
  - `defaultRemoteID` returns the address only for a single-address
    gateway; multi-address yields `""` so no `remote.id` is pinned.
    PSK scoping is unaffected: `pskIDSelectorsLocal` already emits one
    selector per peer address (#14139), so the secret never becomes
    unscoped.
  - Inline-endpoint arm likewise pins only a single-address endpoint.
  - `resolveRemoteAddr` accepts an inline multi-address list via
    `IsUsableIPsecEndpointList`.
- `pkg/config/types_security.go`: `Address` documents the
  comma-joined-list form.
- `pkg/ipsec/policy_initiator_identity_15193_test.go`: the multi-address
  subtest's remote.id expectation updated from the #15193 first-address
  pin to the #15766 no-pin contract (selectors unchanged).

## Regression

- `pkg/ipsec/policy_multiaddress_gateway_15766_test.go`:
  `TestIKEGatewayMultiAddressCompileValidateAndRender` — repeated,
  bracket, comma, and comma-space spellings on BOTH gateway
  containers; compiled `gw.Address`, `remote_addrs`, no pinned
  `remote.id`, per-address PSK selectors; single-address control
  (keeps the #15193 pin); malformed-second-address rejection;
  direct-constructed and inline multi-address render arms.
  `TestAddressFamilyHintMultiAddress15766` — v4/v6/mixed list hints

## Risk

- `remote.id` omission for multi-address PSK gateways relies on
  charon's default address identity; the PSK remains scoped per peer
  address, so cross-peer secret selection (#3952/#14591) is unchanged.
  Pubkey, dynamic-hostname, responder-only, explicit remote-identity,
  and single-address shapes render byte-identically to before.
- Compiled `gw.Address` for a repeated single address (`address a` +
  `address a`) now deduplicates to `a`; no consumer depended on the
  old last-wins duplication-free-by-accident form beyond equality.
