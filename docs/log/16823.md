## Change

- `recheckHostKernelTruth15264` host-inbound drift arm: after `noteHostInboundApplyFailed`, `hostInboundEnforced.Store(false)`, `hostInboundCoveredAddrs = nil`, `hostInboundDHCPRetainedAddrs = nil`; when `hostInboundGapFenceActive` is set, probe `TableEnforcing(xpf_hostinbound_gap)` and clear the marker + `hostInboundGapFenceSpec`/`hostInboundPreActivationFence` only when the gap table is also proven gone (a standing or unreadable gap fence stays reported/mergeable — unreadable proves nothing). The cold-boot fence replaces the main table, so it shares the main table's fate and needs no separate probe.
- New `hostInboundEstablished15264 atomic.Bool`: the sticky historical establishment bit. Armed at every production `hostInboundEnforced.Store(true)` site (real-install success paths, barrier-handoff-stale path, scoped cold-boot fence) and in `noteHostInboundApplySucceeded`; cleared only by a successful no-enforcement teardown (same site as the existing `hostInboundEnforced.Store(false)`). `HostInboundApplied().Established` reads `enforced || established` (the OR keeps direct-latch test fixtures and any missed arming site rendering exactly as before; the bit is what survives the drift clear).
- Recheck probe gate switched from `hostInboundEnforced` to the sticky bit: after the drift clear, a latch-gated probe would go blind (never observe a heal, never warn on a second flush, and the `hostDriftNoticed15264` re-arm tail would never run). Never-established daemons still probe nothing (both bits false), preserving the zero-netlink-cost property.
