# #16773 - Standalone DHCPv6-PD same-lifetime renewal never re-applies RA (R3-A26-01)

- **Timestamp**: 2026-10-25
- **Action**: Since #15057 the RA desired set carries the absolute expiry
  (`RAPrefix.ValidExpiresAt` = Obtained+granted) and `pkg/ra` decays it at
  send time. On a fixed-lifetime server a Renew Reply stores Obtained=T1
  with identical granted lifetimes, so `delegatedPrefixesChanged` (which
  excludes Obtained) stayed false and `commitLease` fired only the
  unchanged-lease hook — no full recompile (#1777) and, standalone having
  no periodic RA applier, no `ra.Apply` at all. The live sender kept
  `T0+valid`, deprecated the LAN PIO at `T0+preferred` and omitted it at
  `T0+valid` while the delegation was still held; downstream hosts lost
  SLAAC global IPv6 until an unrelated commit or restart. Fix gives
  standalone mode an RA-scoped change signal on PD renewal, not a full
  recompile: `Daemon.onDHCPUnchangedLease` now also nudges a depth-1
  coalescing wake channel (`raRenewWakeCh`, non-blocking — the hook runs
  on the DHCP client goroutine and an inline apply parks on `applySem`
  and deadlocks, #16559); the new `standaloneRARenewLoop` owner started
  unconditionally in `Run` runs `reconcileStandaloneRAOnce` under
  `applySem`, which runs the digest-gated `reconcileStandaloneRAServices`.
  A renewal that moves only Obtained moves the digest (`ValidExpiresAt`)
  and re-applies with the renewed expiry through the existing `raApplyFn`
  seam; a v4 or non-PD renewal leaves the digest unchanged and restarts
  nothing. `lastStandaloneRAHash` is a separate digest from the cluster
  `lastRAReconcileHash`, kept in sync by `applyServicesReconcile` on every
  successful standalone apply (and cleared on bootstrap withdraw), so the
  two modes never poison each other's gate; cluster mode is a no-op in the
  new reconcile and remains owned solely by `reconcileClusterRAServices`
  (#15057 no-churn cell stays green). Test-only seams:
  `Manager.CommitLeaseWithPDsForTesting` /
  `ReplaceDelegatedPrefixesForTesting` drive the real `commitLease`
  predicates from daemon tests. NOT changed: `delegatedPrefixesChanged` /
  `leaseContentChanged` semantics, the debounced full-recompile path, or
  any `pkg/ra` wire behaviour.

- **Validation**: New daemon cells pin the acceptance shape end to end:
  a standalone daemon seeded with a PD (pref 3600/valid 7200, Obtained T0)
  converges once, then a same-lifetime renewal (fresh Obtained T1,
  identical lifetimes) — driven both via the unchanged-lease hook and via
  the real `commitLease` through `CommitLeaseWithPDsForTesting` — must
  re-apply RA carrying `ValidExpiresAt=T1+7200s` (and
  `PreferredExpiresAt=T1+3600s`), a further no-move wake must NOT
  re-apply (digest gate), the wake loop must tick and stop on cancel,
  and the standalone reconcile must apply nothing in cluster mode. RED on
  the pre-fix tree by construction: `onDHCPUnchangedLease` nudged no RA
  owner, so the post-renewal apply count stayed at the initial converge.
  Existing #15057 hash/expiry cells and the #6793 dead-sender cells stay
  green in the targeted run; full suites are the parent's gate.
- **Risk**: An extra `buildRAConfigs` per content-identical lease renewal
  (v4 included) on standalone boxes — one map walk, digest-gated, no
  sender restart when nothing moved. A failed renew-reconcile apply is
  logged at Warn and retried on the next renewal rather than latched.
  The renew loop holds `applySem` while reconciling, so it serializes
  with commits exactly like the dead-sender reassert (#4001 discipline);
  a commit landing first syncs the digest and the queued pass no-ops.
