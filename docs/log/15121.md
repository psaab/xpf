# #15121 — RETH member base row keeps domain 0 on a VRF-owned shared netdev (A86-03)

## Defect

#14331 fixed the case where an interface's own untagged unit `.0` collapses
onto its base netdev: the base row now inherits unit `.0`'s routing domain.
The residual (A86-03, validated MATERIAL 3-way in research run
`research-work.AdQvt1jMKw`) is the primary HA RETH topology: `reth0` and
`reth0.0` both resolve through `RethToPhysical`/`snapshotLinuxName` onto the
member `ge-0/0/1` (`ge-0-0-1`), so the RETH base row, the `reth0.0` unit row,
and the member's base row all share one ifindex and the same live kernel
addresses. The member interface typically has no units, so the #14331
own-unit-0 lookup found nothing and the member base row kept
`RoutingDomain: 0` while republishing the VRF unit's addresses:

- `buildLocalAddressEntriesWithExclusions` emitted `(Domain: 0, addr)` for
  every VRF local address → VRF addresses published as inet.0 locals.
- `localAddressRoutingDomain` saw domains {0, VRF} for one ifindex and
  returned `(0, false)`, so the `userspace_ingress_domains` entry for the
  RETH ifindex was deleted (fail-closed, but kills correct classification).

## Fix

`buildInterfaceSnapshotsFrom` (`pkg/dataplane/userspace/interfaces.go`) now
derives the base-row domain from the netdev, per the issue's fix direction:

1. Before the row loop, collect routing-domain claims of unit rows keyed by
   the netdev each unit actually lands on (`snapshotLinuxName` equality).
   Only explicitly claimed (routing-instance member) or quarantined units
   publish a claim; disabled interfaces/units own nothing (mirroring
   `buildUserspaceIngressDomainEntries`). Two different domains claiming
   one netdev mark it ambiguous and publish no claim.
2. After the existing #14331 own-unit-0 inheritance, a base row whose own
   resolution left it in domain 0 (and which is not admin-disabled)
   inherits the single unambiguous claim on its netdev — instance and
   domain together, quarantine sentinel included. A base row with any
   nonzero domain of its own (explicit bare-key membership, own unit 0,
   quarantine sentinel) is never overridden.

No changes to `localAddressRoutingDomain`,
`buildLocalAddressEntriesWithExclusions`, or
`buildUserspaceIngressDomainEntries` — the fail-closed ambiguity guards
stay for genuinely contested ifindexes.

## Regression

`TestBuildSnapshotRethMemberBaseRowInheritsRethUnitDomain15121`
(`pkg/dataplane/userspace/base_row_vrf_domain_15121_test.go`) builds the
snapshot for `ge-0/0/1` as `reth0` member, `reth0.0` in `vrf1`, with stubbed
live addresses on `ge-0-0-1`, and asserts the member base row inherits
`(vrf1, StableRoutingInstanceTableID("vrf1"))`,
`localAddressRoutingDomain` returns `(748221, true)`, no local entry lands
in Domain 0, and the ingress-domain map keeps the single VRF untagged entry
for the shared ifindex. The adjacent control
`TestBuildSnapshotRethMemberBaseRowDefaultDomainControl15121` pins that a
default-instance RETH member keeps domain 0.
