# Issue #12822 — preserve daily scheduler exclusions

## Why

`schedulerWindowFromNode` already parsed `exclude` from a daily arm, but
`compileSchedulers` copied only the time bounds and `all-day` flag into the
compiled scheduler. The compiled daily interval therefore remained active
instead of being suppressed. A policy using `daily { exclude; start-time;
stop-time; }` could enforce during a window Junos explicitly excludes.

## What

- Added `SchedulerConfig.DailyExclude`, populated it from each compiled daily
  window, included it in runtime daily-window resolution and the policy
  scheduler config hash, and recognized it as an effective window for
  validation warnings.
- Added compile regressions for braced, packed, and flat-set exclude forms,
  plus runtime regressions proving excluded windows stay inactive and
  ordinary daily windows remain active.
- Documented daily exclusion and its interaction with scheduler activity.

## Validation

- RED before the fix: `go test ./pkg/config -run
  '^TestSchedulerDailyExcludeCompiled12822$' -count=1` failed because daily
  exclusions were not represented in the compiled config.
- RED before the fix: `go test ./pkg/scheduler -run
  '^TestIsWithinWindow_DailyExclude12822$' -count=1` showed ordinary,
  all-day, and weekday-fallback windows active despite the daily exclusion.
- GREEN: `go test ./pkg/config -run
  'Test(CompileScheduler|SchedulerDaily|SchedulerWindow|SchedulerWeekday|SchedulerFlat|SchedulerEqualWindow)' -count=1`
  passed the focused scheduler compiler/validation suite.
- `go test ./pkg/scheduler ./pkg/daemon -count=1` passed both complete
  package suites, including the daily-exclusion policy-hash regression.
- `go test ./pkg/config ./pkg/scheduler ./pkg/daemon` passed scheduler and
  daemon packages, but the config suite hit its 10-minute timeout after
  reporting unrelated schema-spelling, inventory, API-auth, and slot-escape
  gate failures.
- `gofmt -l` on all changed Go files produced no output; `git diff --check`
  passed.

## Risk

A daily exclusion affects all daily windows, but an explicit weekday override
continues to take precedence as before. No live configuration or traffic was
changed.
