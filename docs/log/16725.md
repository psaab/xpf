# #16725 — `show system boot-messages` returned the whole system journal to view-only classes

- **Timestamp**: 2026-10-25
  - **Action**: `GetSystemInfo{boot-messages}` (PermView,
    `pkg/grpcapi/server_show_status.go`) and its local CLI twin
    `showSystemBootMessages` (`pkg/cli/cli_show_system.go`) both forked
    `journalctl --boot -n 100 --no-pager` as root with no kernel
    filter. `--boot` alone returns every journald unit of the current
    boot — sshd logins with source addresses, sudo command lines,
    other daemons' logs — to any login class holding only `view`,
    contradicting the #4860 allowlist policy ("the daemon never
    returns a host log the CLI account was not explicitly granted")
    and the Junos contract for this command (kernel boot messages,
    `/var/run/dmesg.boot`, privilege view). Fix: add `-k`
    (`--dmesg` equivalent) to both argv vectors so only kernel
    ring-buffer messages are rendered; the existing #6584
    `SanitizeBlockForDisplay` handling, the 100-line bound, and the
    `--boot` current-boot filter are unchanged. NOT changed:
    `ShowText{log}` (`journalctl -u xpfd`), the #4860
    `show log <name>` allowlist, or the PermView price of
    `GetSystemInfo` — kernel boot messages are view-tier on Junos,
    so no re-pricing is needed once the output is kernel-only.
    `docs/phases.md:697` updated to record the corrected argv.
  - **File(s)**: `pkg/grpcapi/server_show_status.go`,
    `pkg/grpcapi/boot_messages_16725_test.go` (new),
    `pkg/cli/cli_show_system.go`,
    `pkg/cli/boot_messages_16725_test.go` (new),
    `docs/phases.md`, `docs/log/16725.md`
  - **Validation**: RED pre-fix — both new recording-fake-journalctl
    cells failed with recorded argv
    `[--boot -n 100 --no-pager]` (missing `-k`/`--dmesg`). Post-fix
    targeted run (grpcapi + cli): the two new cells pass and the
    adjacent controls stay green (`#6552` diag-limiter boot-messages
    cell, ShowText{log} bound cell, non-forking negative control).
    `go vet` and `gofmt` on touched files to be confirmed at commit.
  - **Residual**: End-to-end SSH as a read-only user on a live VM
    was not run (matches the issue's stated verification gap);
    kernel-only output was verified at the argv level, which fully
    determines journalctl's output scope. If a full-journal view is
    ever wanted it must be a separately priced, non-view tier —
    deliberately not added here.
