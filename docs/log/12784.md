# Issue #12784 — teardown test fake panics on link pin

## Root cause

`TestManagerTeardownClearsLinkMembership` supplied an `armedGateFakeLink` that embedded a nil link but did not implement `Pin`. `Manager.Close` runs `ensureXDPLinkPinned`, which calls `Pin` after `Unpin`; the promoted call dereferenced the nil embedded link. The fake therefore failed before the membership cleanup behavior could be asserted.

The privileged userspace failures also included stale harness expectations: helper-first imported session writes were being treated as Go-local BPF writes, reverse imports were expected not to reach the helper, and delete fixtures did not model successful helper-owned map effects. Some fixtures also had a non-nil `exec.Cmd` with a nil `Process`, causing the production helper-availability guard to skip the RPC.

## What changed

- Implemented `Pin` on `armedGateFakeLink` and isolated the teardown test's pin directory in a temporary directory.
- Updated stale helper-first session tests and fixtures to validate helper request tuples/values, model Rust-owned shared-map effects, and assert the current exact `mirror_delete` / `mirror_delete_batch` wire contracts.
- Kept #10512 helper-first production semantics. No Go-side BPF transaction or rollback was restored: helper RPC failure/timeout can be observed after the Rust helper has committed shared authority, and Go rollback could erase that committed state; the Go mutex also does not serialize Rust map writes.
- No environment-only privileged failures remained in the final privileged userspace package run, so no environmental follow-up issues were filed.

## Risk

The production helper remains the authority for imported session map writes and deletes. Test fakes now model that contract; no dataplane runtime behavior was changed for this issue.
