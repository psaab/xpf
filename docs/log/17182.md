- **Timestamp**: 2026-10-27
- **Defect (re-verified live on origin/master `d12802a6c5`)**: `bfd-liveness-detection` was five identical `schemaNode` literals in `pkg/config/schema_routing.go` (OSPF, OSPFv3, BGP group, BGP neighbor, IS-IS) and five identical 17-line readers (`compiler_protocols.go` ×4, `compiler_bgp_neighbor_merge_9192.go` ×1). `TestEveryBFDSiteIsTyped9012` guarded only the numeric typing, so any other grammar change (e.g. accepting the packed spelling) had to be made five times in each layer. The FRR renderer arms are per-daemon syntax, not copies, and are left alone.

## What

- Added `pkg/config/bfd_liveness_17182.go`:
  - `bfdLivenessSchema17182()` — factory returning a **fresh** `*schemaNode` per call (mirroring `bgpMultihopSchema16679`), so the five sites do not share fate and `TestEveryBFDSiteIsTyped9012` still counts five sites. Bounds unchanged: `minimum-interval` (10-60000), `multiplier` (2-255), both `ValueInteger`.
  - `parseBFDLiveness17182(prop *Node) bfdLiveness17182` — the single reader: presence → `enabled=true`, `minimum-interval`/`multiplier` via `nodeVal`+`strconv.Atoi`, unparseable/unset → 0 (the tolerant-drop behaviour of the five former copies). Packed tails reach it already expanded by the callers' `packedBodyChildren`/`expandFlatRun` passes, exactly as before.
  - `bfdLiveness17182` struct is only the reader's return value; the four model types (`OSPFInterface`, `OSPFv3Interface`, `ISISInterface`, `BGPNeighbor`) keep their flat `BFD`/`BFDInterval`/`BFDMultiplier` fields for renderer compatibility.
- Replaced all five schema literals in `schema_routing.go` with `bfdLivenessSchema17182()` (gofmt realigned the OSPFv3 auth-key block).
- Replaced all five readers with a two-line dispatch through `parseBFDLiveness17182`.
