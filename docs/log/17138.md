# #17138 — single-source SyncedDeleteOutcome contract and drop dead refusal predicate

- **Timestamp:** 2026-10-27T14:21:15-07:00
- **Branch:** `fix/17138-campaign`

## Why

Finding R4-Q05-05: `SyncedDeleteOutcome`'s doc (`ha/session_import.rs`) said "Four states … only the first of them permits any further teardown" over nine variants; `PartialCompanion` also permits teardown (it is counted as removal by the policy-batch `shared_removed`), and `RefusedMirrorDelete` had no doc line at all. The compatibility predicate `is_refused_local_owned()` had zero production callers and eight test callers, and is true for only one of the five `keeps_caller_rows()` variants — so tests asserting `!is_refused_local_owned()` passed for outcomes (e.g. `RefusedMirrorDelete` after a shared removal, `RefusedGateBusy`, `RefusedIdentity`) where Go actually keeps mirror/DNAT rows or the helper removed the shared row. Defect confirmed live on origin/master (`e27167e463`): stale doc, predicate definition, and all eight test call sites present.

## What

- `userspace-dp/src/afxdp/ha/session_import.rs`: rewrite the enum doc as a per-variant table (variant / shared removed / Go keeps rows / wire token) with no variant-count sentence; add a doc line for `RefusedMirrorDelete` (shared removed, mirror delete then failed, handler surfaces bare `mirror-write-failed`); delete `is_refused_local_owned()`; add `SyncedDeleteOutcome::shared_removed()` (`Applied | PartialCompanion | RefusedMirrorDelete`) and `SyncedDeleteOutcome::ALL` (all nine variants) as the single source of truth for the "shared forward row removed" axis. Wire-token column reflects the handlers in `server/handlers/sync_session.rs`: row-keeping peer deletes → `synced-delete-refused:peer-delete-local-owned`, strict-mirror failure → bare `mirror-write-failed`, policy-batch per-match tokens (`applied`/`stale_forward`/`partial_companion`/`refused_identity`/`batch_failed`).
- `userspace-dp/src/afxdp/ha/session_domain.rs`: the policy-batch `shared_removed` closure now delegates to `outcome.shared_removed()` instead of re-listing variants (it previously omitted `RefusedMirrorDelete`, which that path cannot produce — `remove_shared_policy_item` returns only Applied/StaleForward/PartialCompanion/RefusedIdentity — so behaviour there is unchanged).
- `userspace-dp/src/afxdp/ha_tests.rs`: all eight `is_refused_local_owned()` sites replaced with exact-variant assertions — `RefusedLocalOwned` for the three refusal cells (unresolved owner, live local, reverse key) and `assert_eq!(outcome, SyncedDeleteOutcome::Applied)` for the five applied cells (no active group, owner RG inactive, peer-synced entry, forward-only, ordinary delete) — preserving the original assertion messages. Add guard cell `synced_delete_outcome_contract_table_17138` enumerating `ALL` and asserting `(shared_removed, keeps_caller_rows, mirror_delete_failed)` per variant, so adding a variant or flipping a predicate without a table row fails the test.

## Risk

No production behaviour change: the deleted predicate had no production callers; `shared_removed()` is used only where the policy-batch closure already computed the same set for its reachable variants, plus the new guard test. Test assertions are strictly stronger (exact variant instead of a one-of-five predicate). The doc table's wire-token column is documentation of the existing handler mapping in `sync_session.rs`, not a wire change.
