# #16801 — second SIGTERM/SIGINT during shutdown killed xpfd before the fail-closed block

- **Timestamp**: 2026-10-25
  - **Action**: `runShutdownSequence` called the signal context's
    `stop()` before `wg.Wait()` and the fail-closed block.
    `signal.Stop` restores the default disposition, so a second
    SIGTERM/SIGINT in that window (a deliberate second stop from
    root during a slow stop) killed xpfd before
    `markDataplaneNotArmed` closed kernel transit, before
    `rg_active` was cleared and (HA) before Kea stopped — the
    #10643/#6787 fail-open hazard. The sequence now installs
    `guardShutdownSignals()` (a buffered `signal.Notify` sink over
    `daemonSignals(isInteractive())` that logs "shutdown already
    in progress") BEFORE `stop()` and releases it on return, so
    SIGKILL (`TimeoutStopSec`) remains the only hard stop.
    Interactive mode's guard is SIGTERM-only, leaving SIGINT with
    the CLI's Ctrl-C handling. Added
    `shutdown_second_signal_16801_test.go`: a re-executed child
    drives the real `runShutdownSequence` with a blocked wg,
    delivers a second SIGTERM+SIGINT during `wg.Wait`, and must
    still print `completed-fail-closed=true` (SIGHUP control
    unchanged, #15084); a second child proves the released guard
    restores the default disposition. RED evidence: removing the
    `guardShutdownSignals()` install from `runShutdownSequence`
    kills the child with `signal: interrupt` before the
    fail-closed marker prints.
