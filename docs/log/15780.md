# Issue #15780 — `system backup-router destination` multi-prefix list (G21-01)

- **Timestamp**: 2026-10-19
- **Action**: Fixed G21-01: `system backup-router <address> destination`
  modelled a single scalar prefix, silently dropping multi-destination
  lists, bypassing `validateBackupRouterDst` on additional prefixes, and
  misreporting IPv6 default destinations.
  - `pkg/config/types_system.go`: added `SystemConfig.BackupRouterDsts
    []string` holding every explicit destination in authored order;
    `BackupRouterDst` is retained as the scalar first prefix
    (`BackupRouterDsts[0]`) for existing single-prefix consumers.
  - `pkg/config/schema_system.go`: the `destination` leaf is now
    `multi: true` with `ValidateRouteDestination` (family-agnostic CIDR)
    and `allChildKeysAreValues: true`, so SetPath keeps repeated leaves
    as siblings and the schema walk validates every prefix in flat,
    bracketed, and hierarchical-block spellings.
  - `pkg/config/compiler_system.go`: the `backup-router` compiler reads
    the packed `destination` tail plus every `destination` child via
    `firewallMatchValues` (which covers Keys tails and bracket children),
    deduplicates exact repeats, and syncs the scalar; 
    `validateBackupRouterDst` now loops over every destination —
    strict commit rejects the first malformed or family-mismatched
    prefix (naming it), lenient load warns per offending prefix.
  - `pkg/daemon/mgmtvrf_static_routes.go`: `mgmtStaticRoutesDesired`
    builds one table-999 route per destination (metric 250, same
    gateway/link resolution as before), falling back to the scalar and
    then to the single family-aware default when no destination is
    explicit.
  - `pkg/cli/cli_show_system.go`: `show system backup-router` lists
    every destination and labels the empty-destination default by
    next-hop family (`::/0` for IPv6 instead of the previous hard-coded
    `0.0.0.0/0`).
  - `pkg/config/testdata/golden_4406.json`: surgically added the new
    `"BackupRouterDsts": null` field next to each of the 27 existing
    `"BackupRouterDst": ""` entries (the file's remaining diffs versus
    `origin/master` are pre-existing on master itself — see Validation).
- **Demonstration (pre-fix)**: probe on the pre-fix tree showed
  `set system backup-router 192.0.2.1 destination [ 0.0.0.0/1 128.0.0.0/1 ]`
  compiling to `BackupRouterDst="0.0.0.0/1"` only (the second prefix
  landed on an un-read child node), two flat `destination` sets
  collapsing to the last prefix only, and hierarchical repeated leaves
  keeping only the first. New RED tests
  (`backup_router_multi_15780_test.go`,
  `mgmtvrf_backup_multi_15780_test.go`) failed on the pre-fix
  compiler/schema/daemon and pass after the fix.
- **Validation**:
  - `go test ./pkg/config/ -run 'TestBackupRouter|TestSystemConfigExtended'`
    — PASS (including the new 15780 bracket/repeated/invalid-second/
    lenient/IPv6 cells and all pre-existing 2911/4808/9820 cells).
  - `go test ./pkg/daemon/ -run 'TestBackupRouter|TestMgmt'` — PASS
    (including the new per-destination desired-route cells).
  - `go vet ./pkg/config/ ./pkg/daemon/ ./pkg/cli/` — clean;
    `gofmt` applied to all touched files.
  - `go test ./pkg/config/ -run 'TestCompileGolden|TestGolden'` — still
    FAILs, identically on a pristine `origin/master` worktree
    (pre-existing drift: `PreferredAddressV6`/`PrimaryAddressV6`/
    `PPTPDisable`/`SourceAddress` fields, tcp-mss range text, and
    warning text present on master but not in the baseline). After the
    surgical `BackupRouterDsts` insertion above, no remaining golden
    diff leaf names `BackupRouter*` — the change adds no new golden
    drift beyond the new field itself.
- **Risk**: compiled-config JSON gains a `BackupRouterDsts` field
  (additive; `BackupRouterDst` unchanged). Configs that previously
  committed with a silently-dropped invalid second prefix now fail
  strict commit naming that prefix — intended, and lenient
  load/peer-sync still boots with a warning. Duplicate identical
  prefixes deduplicate to one route. No dataplane or wire-protocol
  change; table-999 routes keep protocol 0x58 / realm / metric 250.
