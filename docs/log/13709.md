# #13709 — Revalidate synced session upserts under tuple lease

- **Action**: Validate synced entry generation, capacity, and local ownership against the shared session state while holding the tuple lease.
- **Base**: `origin/master` `52e29404e`
- **Files**: `userspace-dp/src/afxdp/ha/session_import.rs`, `userspace-dp/src/afxdp/ha_tests.rs`, `docs/log/13709.md`

## Symptom

`upsert_synced_session_with_policy` read `previous_entry` before acquiring the global tuple lease. A delayed stale peer import could therefore validate against an absent or older snapshot, then overwrite a newer generation or locally owned session published before the lease was acquired.

## Fix

Treat the pre-lease entry only as a candidate for preparing lease keys. Once the tuple lease is held, re-read the current entry and map length under the recovered shared-map lock, then make generation, capacity, local-ownership, and preservation decisions against that authoritative state. If the current companion tuple is not covered by the prepared lease, refuse safely. Deterministic race regressions cover a newer generation and local-origin replacement landing in the pre-lease window.
