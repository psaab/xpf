# Issue 9984: bind event remediation to planting class

## Why

`event-options` change-configuration commands are persisted as data and later
executed by the daemon. Before this change, a payload could lose the identity
of the operator who planted it and execute with the daemon's internal authority.

## What changed

- Event policy records now persist a `plant-class` marker.
- Config mutations stamp the marker atomically with effective event policy
  changes, including set/delete, load, copy/rename, insert, rollback, and
  group-derived policy changes. Flat `set` trees, block-tail command nodes,
  and child-value marker shapes are covered; grouped policies are stamped on
  their owning policy rather than by creating a duplicate top-level stanza.
- Marker edits cannot launder legacy data: metadata-only writes to an
  unmarked policy, and marker deletion, leave the policy unmarked and
  quarantined. Existing attributed policies may be rebound only to the
  authenticated caller's class.
- REST, gRPC, and CLI mutation paths pass the authenticated login class into
  the config store. Trusted root/system paths use the explicit `super-user`
  marker.
- The event engine re-evaluates every set/delete target at fire time against
  the currently active login policy before touching the candidate. Missing,
  deleted, or denied classes quarantine the payload and increment a visible
  fault counter. Snapshot authorization is based on the supplied config
  rather than ambient active state.
- Legacy payloads without a marker remain loadable but are fail-closed when
  they reach the event engine; they never silently execute as root.
- The raw-shape fallback includes quoted/bracketed token provenance, so an
  otherwise uncompileable command change cannot retain stale attribution.
- The API metrics collector exports
  `xpf_event_plant_class_invalid_total` for quarantined payloads.

## Verification

Scoped package suites cover compiler/render persistence, store reload and
rollback, REST transport attribution, gRPC mutation routing, strict fire-time
authorization, mixed-batch pre-mutation denial, grouped and flat policy
stamping, metadata-only legacy/delete quarantine, uncompileable command
provenance, divergent authorization snapshots, unknown/deleted/nil class
quarantine, group-derived firing, and the existing event-engine behavior.
The #2419 compact-block inventory, #7484 spelling-gate member list, #8939
flat-set loser count, and #8690 permanent-exclusion register record the new
schema leaf as measured inventory rather than silently dropping it.
