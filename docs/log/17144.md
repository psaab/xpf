# #17144 — Typed HA delete/import outcomes are not #[must_use]; tunnel purge discards SyncedDeleteOutcome (R4-Q05-07)

- **Timestamp**: 2026-10-27
- **Issue**: #17144 (R4-Q05-07)
- **Base**: `origin/master be463f60e7`

## Defect (STEP-0, verified at base)

Live on `be463f60e7`. `SyncedDeleteOutcome` (`session_import.rs:17-18`) and `SyncedImportOutcome` (`:139-140`) had no `#[must_use]`. `tunnel_purge.rs:115-117` discarded the delete outcome as a bare statement, then unconditionally emitted Close deltas, released reservations and returned `keys.len()` as purged. `RefusedGateBusy` is reachable on the purge path (no clear fence / external lease; `acquire_lease` at `session_import.rs:2199-2201`), so a refused delete was reported as purged, peer/Go were told Close, and an un-adopted `NatHolder::Untracked` reservation could be released while the session survived. `SessionDomain::delete_synced_session_gen` (`:2050-2062`) discarded its marked outcome and returned `()`, its doc truncated mid-sentence; both `Coordinator` wrappers (`coordinator/mod.rs:1009-1022`) returned `()`.

## Fix

- `session_import.rs`: `#[must_use]` on both outcomes; `delete_synced_session_gen` returns `SyncedDeleteOutcome` with the truncated doc finished; the sole production `let _ = delete_synced_session_gen_marked` (clear-fence site in `clear_mirror_with_batch`) and the stale-reverse-companion cleanup carry one-line justifications.
- `coordinator/mod.rs`: both delete wrappers return `SyncedDeleteOutcome`.
- `tunnel_purge.rs`: purge candidates carry key+Close+reservation together; only `Applied | PartialCompanion` emit Close, release and count; refusals bump new per-instance `tunnel_purge_delete_refused` counter (surfaced Rust `ProcessStatus` → Go `ProcessStatus` → Prometheus `xpf_userspace_tunnel_purge_delete_refused_total`), log retained sessions, and are retried by the next purge. Return value is now the actual purged count.
- `#[must_use]` fallout in test modules is allowed at the three test-module declarations and the inline `rejected_mirror_reservation_10790_tests` module (fixture setup discards; dedicated cells assert outcomes); no non-test discard remains except the two justified sites above. `cargo check --tests` reports 0 `unused_must_use` for either outcome.

Purge return/log now exclude refused keys (previously overstated); callers ignore the return except tests, so no control-flow change beyond honest counting and retained sessions being retried/GC'd. New status field is additive/defaulted. The adopted-reservation over-release direction is unchanged: refusal now skips release entirely, which is strictly safer.
