# #16513: `primary` on a non-string-first address of a zoned untagged unit 0 refused every snapshot

- **Timestamp**: 2026-10-24
- **Action**: Fixed the #15155 regression where a `primary` designation
  on any address of a zoned untagged unit 0 other than the string-first
  one made the helper refuse every snapshot with
  `InterfaceSharedIfindexAttributeConflict{primary_v4|primary_v6}`, and
  on non-consistently-zoned shared-ifindex shapes silently ignored the
  designation. Two halves, matching the issue's fix direction (both
  were needed — each alone leaves a reachable bad shape):
  - Go (`pkg/dataplane/userspace/interfaces.go`): when unit 0 collapses
    onto the base netdev (`snapshotLinuxName(unit0) == linuxName`, the
    #14331 predicate already used for routing-domain inheritance), the
    base row now merges the unit's configured addresses (carrying the
    `primary` marker) over its kernel listing, exactly as the unit row
    does. Previously the base row was built from the kernel listing
    alone and never carried the marker, so its order-based pick
    disagreed with the unit row's designated pick.
  - Rust (`userspace-dp/src/afxdp/forwarding_build/interfaces.rs`,
    `types/forwarding/state.rs`): the shared-ifindex merge in
    `populate_egress` now distinguishes a DESIGNATED primary (new
    `designated_interface_v4/v6` helpers, no fallback) from an
    order-based pick. A designated pick wins the merge in either row
    order and on non-consistently-zoned shapes; only two different
    designated picks on one consistently-zoned non-tunnel ifindex keep
    the #13181 fail-closed conflict, and tunnel rows keep their
    exemption. Build-time bookkeeping lives in two new
    `ForwardingState` sets (`egress_primary_{v4,v6}_designated`),
    default-empty and unread after the build.
