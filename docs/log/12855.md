# #12855 WireGuard trunk fan-up zone attribution — engineering history

Issue: psaab/xpf#12855. Branch: `fix/12855-d4-10`. Base: `e3961c0bf` (`origin/master` at worktree creation).

## RED (before production edits)

Added a direct `buildUserspaceWGZoneMaps` regression for a trunk where the base row carries the zone fanned up from unit 100, while unit 0 is the actual untagged owner on the same ifindex and has the WireGuard endpoint address. Before the fix:

```text
go test ./pkg/dataplane/userspace -run 'TestBuildUserspaceWGZoneMaps(FanUp|Standalone|Native)' -count=1
```

failed in two issue cells. The untagged key `{10, 0xffff}` resolved to zone 0 rather than unit 0's `wan` zone (the base-row `lan` claim conflicted); with the shared base address included, the address owner became ambiguous and WG admission was empty. This confirms both issue mechanisms at the starting revision.

## Change

- Preserve Go-only `wgFanUpBaseRows` provenance on the in-memory `ConfigSnapshot`, excluded from JSON/content hashing. The builder derives it where both `InterfaceZoneMap` and literal `authoredZoneRefs` are available: a base row with a zone but no authored base reference is fan-up-derived.
- In WG ingress-zone construction, omit that base row as a direct untagged owner; a genuine unit-0 row or the existing native-VLAN ownership loop still decides the untagged key. Tagged parent/VID ownership is unchanged.
- In WG address ownership, omit the same derived base row so its inherited zone cannot conflict with the real unit's endpoint address. Explicitly authored base ownership remains eligible.
- Add tests for the exact trunk collision, duplicate base/unit address, standalone base, native VLAN, explicitly authored base, and legacy snapshots without provenance.
- No Rust/helper wire changes or protocol-version bump; the new metadata does not cross the wire.
