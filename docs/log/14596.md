# #14596 — `system ntp server <addr> key <n>` renders chrony `key n` with no key material

## Defect
`renderChronySources` (`pkg/daemon/daemon_system.go`) emitted
` key <id>` for any compiled `NTPServerOption.Key > 0`, but xpf writes
no chrony keyfile anywhere (no `chrony.keys`/`keyfile`/`trusted-key`
writer in pkg/cmd/scripts). Chrony logs "Key <id> is missing" and
never polls that source. The bare form
(`set system ntp server 192.0.2.1 key 5`) compiled with zero warnings;
the full Junos form warned "NTP authentication accepted but NOT
enforced" while still rendering `key 5` — contradicting the documented
contract that unenforced auth implies unauthenticated polling keeps
working. Verified on base: compiled opts `map[192.0.2.1:{Key:5}]`,
warnings `[]`, rendered `server 192.0.2.1 iburst key 5`.

## Fix (strip-and-warn; keyfile implementation NOT chosen)
Implementing real NTP auth would require modelling
`authentication-key <id> type <t> value <secret>` + `trusted-key <id>`
as typed secret config, writing a 0600 chrony keyfile, and wiring its
lifecycle into `applySystemNTP` — a larger change than this defect
needs. The issue's acceptance explicitly allows the strip half.

- `pkg/config/compiler_system.go` (`compileSystem` ntp arm): after
  merging per-server options, strip every `Key > 0` into the new
  `SystemConfig.NTPServerKeyIDs` (sorted, deduplicated) and zero the
  option's `Key`. Runs per `ntp` block, so sibling blocks accumulate.
- `pkg/config/compiler_system.go` (`systemInertKnobWarnings`): one
  warning per stripped id, naming it:
  `system ntp server key 5: NTP authentication accepted but NOT enforced (key 5 stripped; no chrony keyfile is written, so the source is polled without authentication)`.
  Fires for the bare form too, not only when an `authentication-key`
  block exists. The existing `authentication-key ... NOT enforced`
  advisory is unchanged; no secret value is ever echoed.
- `pkg/config/types_system.go`: new `NTPServerKeyIDs []int`;
  `NTPServerOption.Key` documented as stripped-to-zero by the compiler.
- `pkg/daemon/daemon_system.go` (`renderChronySources`): never render
  `key` — the render belt for leniently-loaded / peer-synced options
  that bypass the compiler strip (the #4902 belt shape). `version` /
  `prefer` rendering unchanged.
- `pkg/config/schema_system.go`: `key` leaf comment records the strip.
- Existing #8436/#7132 tests updated: the merged/authored key id now
  lands in `NTPServerKeyIDs` with `Key == 0` on the option; the #7132
  spelling-equivalence comparison and non-vacuity check follow it.
- `pkg/config/testdata/golden_4406.json` regenerated
  (`GOLDEN_4406_UPDATE=1`): only delta is the new
  `"NTPServerKeyIDs": null` field in every case.

NOT changed: the `authentication-key` inert advisory wording, NTP
threshold rendering, `routing-instance` advisory, chrony reload/debt
machinery. No keyfile is written — sources poll unauthenticated,
exactly as the "NOT enforced" contract states.
