# #16867 — FRR prefix-list name length bound (R3-B07-04)

- **Issue**: `ValidateFRRObjectName` (the #9493 commit validator) had no
  length bound and `frrName` passed operator names through unchanged. A
  prefix-list name over FRR's 128-byte YANG `list-name` limit committed
  strict-clean; FRR rejected the leaf with "Unsatisfied length" but left
  a half-built match-condition node, and the next `show running-config`
  (first step of every frr-reload.py run) SIGABRT'd five routing daemons
  (BGP/OSPF/OSPFv3/IS-IS/mgmtd) on every reload until the name shortened.
- **Change**:
  - `pkg/config/schema_validators_frr_operand_9493.go`: new
    `config.FRRNameMaxLen = 128` and `ValidateFRRPrefixListName`
    (single-token gate + strict error over 128 bytes naming the bound).
    `ValidateFRRObjectName` stays unbounded — route-map and
    community-list names were measured NOT length-bounded by FRR, so
    bounding them would refuse names the product already accepts.
    AS-path definition names are likewise unbounded, but `match as-path`
    references land in the YANG `filter:access-list-name` leaf
    (length 1..128); that reference bound is enforced by the render belt
    below, which aliases every class over the bound at match sites too.
    YANG `length` counts characters, not bytes; the 128 cap is enforced
    in BYTES — the conservative direction (a 128-rune multi-byte name
    YANG would admit is refused/aliased rather than risking the
    byte-oriented path behind the measured 129-byte rejection).
  - `pkg/config/schema_routing.go`: only the `prefix-list` definition
    leaf switches to `ValidateFRRPrefixListName`; policy-statement,
    term, community and as-path leaves keep `ValidateFRRObjectName`.
  - `pkg/frr/operand_belt_9493.go` (`frrName`): a single-token name over
    128 bytes now takes the same deterministic hashed alias as an unsafe
    name (fragment truncated so fragment + `-xpfesc-` + 8 hex ≤ 128;
    hash over the FULL name keeps long names sharing the truncated
    fragment apart). Names ≤128 bytes render byte-identically, so every
    existing render is unchanged. This covers the tolerant path: a long
    name persisted/peer-synced before the gate existed (SchemaValidate
    runs on commit/commit-check only, #1960) still renders as one
    bounded token, and definition/reference sites agree by construction
    since both call `frrName`. Every yang-bounded FRR emission
    (`ip|ipv6 prefix-list`, `match ... prefix-list`, `access-list`,
    `ipv6 access-list`) already routes operator names through `frrName`
    or the already-bounded (≤96) generated-name helpers
    (`routeFilterACLName`, `inlinePrefixListName`,
    `qnhMetricPrefixListName11447`, `ripGroupListName16625`,
    `communityChainListName16835`, `communityDeleteListName`), so no
    operator-name emission site bypasses the bound.
  - Docs: `pkg/frr/README.md` #9493 alias bullet records the #16867
    bound, its commit-gate scope, and the daemon-abort mechanism.

- **Gate fold (PR #17819, Kimi/Opus/Astra)**: the alias map was
  non-injective against operator names — an overlong raw name L and the
  literal A = frrName(L) both committed/rendered as A and would merge
  in FRR. Fixed in final-emitted-identity space: (a) the alias marker
  `-xpfesc-` (`config.FRRNameEscapeMarker`) is reserved —
  `ValidateFRRObjectName` strictly rejects any name carrying it, so a
  literal alias can never be committed; (b) a compiled-config pair gate
  (`validateFRRNameAliasCollisionStrict`, strict reject / lenient warn
  per #1960) refuses any same-class pair whose rendered names coincide;
  (c) the render belt `frrNameAliasCollision` (wired into `ApplyFull`)
  fails the apply closed for persisted/peer-synced pairs; (d)
  `bgpComposedChainCollision` now compares composed names AFTER
  `frrName`. Also corrected: AS-path `match` references ARE bounded
  (YANG `filter:access-list-name` 1..128; definitions are not) — the
  belt's every-class aliasing at match sites is what enforces it; and
  the 128 cap is a BYTE bound (YANG counts characters) — conservative
  against the measured 129-byte wire rejection, documented at
  `FRRNameMaxLen`.

- **Rebase union (Gate4)**: rebased onto master `dfa6d152c5`; the two
  textual conflicts were union-resolved, dropping NEITHER side —
  `compiler_uniformgates_log_feed_routing.go` keeps master's #16871
  `validateBGPComposedChainReservedNameStrict` gate AND the #16867
