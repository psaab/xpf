# #19017 — `make deb` fails misleadingly inside a lock cell

- **Timestamp**: 2026-11-08
  - **Action**: Added a `deb-cell-guard` prerequisite before `deb-changelog-check`. It detects when PATH resolves `dpkg` from a directory carrying the #18038 `refuse-host-tool` marker and exits with a named `build outside the lock cell` refusal before `dpkg-buildpackage`; it reports the shim-free host dpkg from `deploy_host_dpkg` when available. `prepare-deb` rebuild branches already delegate to `deb`, so they inherit the guard. Normal PATH proceeds unchanged.

Existing `prepare-deb` reuse/rebuild wiring cells also passed. No full package build was run.
  - **Risk**: Only packaging through the `make deb` target is affected, and only when PATH-selected `dpkg` is in a testguard shim directory. Clean PATH behavior is preserved; no Go code or in-VM dpkg operations changed.
