# #12175 — fail back rolling demotion after pre-STOP refusal

- **Issue**: #12175 — rolling upgrade can leave a healthy daemon held at weight 0 when the cut refuses before STOP.
- **Branch**: `fix/12175-campaign-pub`
- **Base**: `83b5c9553` (merge-base; the log originally recorded the lane base `1c384b9a4`)

## Why

The rolling driver forced the local node secondary before `Runner.Run`. Verifier, envelope, and rollback-target refusals return before STOP, but the forward driver returned that error without clearing the ISSU hold. The rollback twin already gates refusal checks before demotion; the forward drain-timeout path already fails back and verifies rejoin.

## What

- Mark `Runner.Run` errors that occur before any STOP attempt, preserving the original error text and unwrap chain. Errors from a resumed stopped journal or an attempted STOP are not marked. (Fold correction: the original text also listed an already-stopped unit, but the classifier overwrote that seed — MINOR-1 fixed it to preserve the seed.)
- On a marked rolling-cut error, call `ResetFailover` and read back `LocalRejoinComplete` for all configured RGs before returning. Preserve the refusal as the primary error and join/report reset failures; retain the passive hold for errors at or after STOP.
- Add two-node loopback Manager coverage for verifier REJECT and envelope-reader refusal, asserting the accurate refusal error and no residual manual/weight-zero hold. Add a STOP-attempt failure boundary cell proving post-boundary failures retain the hold.
