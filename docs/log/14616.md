# `protocols lldp interface X disable;` compiled to Disable:false, trailing junk ignored (#14616)

## Why

`compileProtocols` read only `child.FindChild("disable")` for an LLDP
interface. The one-line spelling `interface ge-0/0/0 disable;` packs
`disable` onto the interface node's own Keys (`[interface ge-0/0/0
disable]`, no children), so it compiled to `Disable:false` while the
block form (`interface ge-0/0/0 { disable; }`) and the flat `set
protocols lldp interface ge-0/0/0 disable` both compiled to
`Disable:true`. LLDP therefore transmitted and learned neighbours on a
segment the operator explicitly silenced. Any trailing token
(`interface ge-0/0/0 frobnicate;`) was likewise silently ignored by both
`SchemaValidate` and `CompileConfig`.

## What

- `pkg/config/compiler_protocols.go`: new
  `validateLLDPInterfacePackedTokens` — only the optional `disable`
  flag may follow the LLDP interface name, packed onto Keys or nested
  as a child (braced / flat-set shapes); a duplicate `disable` is also
  rejected. `compileProtocols` now reads a packed `disable` from
  `Keys[2:]`, calls the validator on strict compile (hard error naming
  the token), and on the tolerant path warns and drops only the unknown
  token while keeping a valid `disable`.
- `pkg/config/schema_routing.go`: the `protocols lldp interface` schema
  node sets `packedTail: true` with that `nodeValidator`, pairing the
  commit gate with the compiler reader (#6821 discipline) so
  `SchemaValidate` rejects the packed junk spellings the same way.
- `pkg/config/compiler_opts.go`: `lenientLLDPInterfaceTokens14616`
  downgrades the compiler gate to a warning on `CompileConfigLenient` /
  peer-sync paths (#1960 no-brick).
- Tests: `pkg/config/lldp_packed_disable_14616_test.go`.

NOT changed: the global `protocols lldp disable` flag, transmit-interval
/ hold-multiplier handling, the compact-normalizer scope table, or the
LLDP runtime/daemon (they already honour a correctly compiled
`Disable:true`).

## Validation

- GREEN targeted: `go test ./pkg/config/ -run
  'TestLLDPInterfacePackedDisable14616|TestLLDP' -count=1 -v` passes,
  including the pre-existing `TestLLDPSetSyntax`,
  `TestLLDPHierarchicalSyntax`, `TestLLDPDisableSetSyntax`, and
  per-interface disable tests. `go vet ./pkg/config/` is clean.
- `TestCompactNormalizeScopePreservesCompiledResult8690` fails with the
  identical signature (4 NEW policy-statement `from` sites) on a clean
  `origin/master` worktree — base-attributed, not caused by this change.

## Risk

Strict commits carrying a previously-accepted junk LLDP interface token
(or a duplicate `disable`) now reject naming the token — intended.
Tolerant loads still boot with a warning. No dataplane, wire, or daemon
behaviour changes beyond honouring the operator's `disable`.
