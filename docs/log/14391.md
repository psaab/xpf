# #14391 - Lenient DNAT rule-set `to` scope silently ignored

- **Timestamp**: 2026-10-16
- **Action**: On the lenient load / peer-sync path a DNAT rule-set carrying a `to` scope was warned about (#3444) but still installed scope-less, so its translation applied regardless of the authored egress context (the wire struct `DestinationNATRuleSnapshot` and the Rust DNAT runtime model only `from` — the scope had nowhere to go). `compileNATDestination` (`pkg/config/compiler_nat_destination.go`) now omits any rule-set for which the new shared helper `natRuleSetHasToScope` (`pkg/config/compiler_nat_dnat_to.go`) reports a `to` scope — the `lenientNATEmptyScope` posture: a rule-set whose scope cannot be enforced is omitted, never widened. The helper detects both spellings — a nested `to` child and a `to` packed onto the rule-set header (`rule-set RD to zone trust { ... }`, R15-01, via `instanceValueTail`) — and is shared with `validateDNATRuleSetToScopeAST`, so the packed spelling is now also strict-rejected / lenient-warned (previously the `FindChild("to")`-only gate missed it entirely) and gate and builder cannot drift. Strict behaviour, source-NAT `to`, and from-only DNAT are unchanged; the #3444 warning still fires exactly once per offending rule-set. The `strict-violations` golden cells (`testdata/golden_4406.json`) were regenerated: the only delta is the lenient omission of the #3444-violating `rs1` rule-set (strict cells and errors byte-identical).
- **Validation**: `TestDNATRuleSetToScopeLenientWarns` rewritten to assert zero `RD` emissions + exactly one #3444 warning + sibling `OK` survival for all three scope kinds (zone/interface/routing-instance), plus new packed-header strict-reject and lenient-omit tests — all RED on master (`lenient load installed DNAT rule-set RD with its "to zone trust" scope silently dropped`; packed strict accepted, packed lenient unwarned), GREEN post-fix; fail-on-revert verified by mutating the builder `continue` off (both lenient tests RED again). `go test ./pkg/config/ -run 'TestDNAT|TestNAT|TestCompileGolden4406|TestDestinationNAT'` green including `TestCompileGolden4406`.
- **Risk**: A persisted DNAT rule-set with a `to` scope no longer installs any translation on tolerant load (previously it installed unscoped) — this is the intended fail-closed change; the #3444 warning names the rule-set so the operator can remove the `to` clause. Packed-header detection scans the rule-set Keys tail for a `to` token anchored on the instance name, so a rule-set literally named `to` is not a false positive.
