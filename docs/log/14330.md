# Issue #14330 — PolicyResolvedFingerprints / PolicyIDsByStableKey omit quarantine scrub

- **Issue:** `PolicyResolvedFingerprints`, `PolicyResolvedIdentityStrippedFingerprints`, `PolicyIDsByStableKey`, and `PoliciesByStableKey` did not apply `scrubPoliciesForQuarantinedZones` / `policySnapshotAfterZoneQuarantine`. A commit whose only enforcement change is a zone becoming quarantined (StableZoneID collision or poisoned `DroppedEnforcementChild`) produced identical fingerprints/ID maps while the published snapshot dropped or narrowed the global rule, so `daemon_policy_invalidate` never flagged live sessions for policy-rematch re-evaluation.
- **Context read:** Full issue body (both blinded research lanes, narrowed MATERIAL verdict). No comments to read. Checked adjacent prior work: #13168 already filters quarantined zone-pair sets in `walkPolicyRuleSlots` (kept survivor `policySetID` advancement), #12857 zone-scope stripping in identity-stripped fingerprints, #12851 feed-overlay fingerprints, #12249 defined-`any` poison, #13099 poisoned-zone quarantine.
- **What:**
  - `PolicyResolvedFingerprints` and `PolicyResolvedIdentityStrippedFingerprints` (`policies_resolved_fingerprint.go`) now run `rules, _ = policySnapshotAfterZoneQuarantine(cfg, rules)` on the `buildPolicySnapshotsWithAddressBook` output before hashing — exactly the scrub the publish path and `policies_reject.go` already apply. Partial quarantine prunes the scope (fingerprint changes, key retained); sole-zone quarantine drops the rule (key removed). Identity-stripped fingerprints keep their #12857 zone-scope erasure for survivors (rename continuity), but a dropped rule's key is now absent there too.
  - `walkPolicyRuleSlots` (`policies.go`) now skips a global policy whose `Match.FromZones` or `Match.ToZones` is non-empty and fully quarantined, using `quarantinedZoneNamesForConfig(cfg)` — the same collision+poison set `quarantineCollidingZones` uses for policies (reserved sentinels excluded, so defined-`any`/`junos-host` scope handling stays with its own poison paths; `""`/`"any"` wildcards are never members). Skipped globals consume no slot, do not count toward `MaxRulesPerPolicy`/total caps, and are absent from `PolicyIDsByStableKey`/`PoliciesByStableKey`/`RuntimePolicyIDs` (all three derive from the walk, as does the snapshot builder — so published `PolicyID`s now match the post-quarantine snapshot exactly, extending the #13168 zone-pair invariant to globals). Partially quarantined globals keep their slot/ID; their narrowing is signalled via the fingerprint change (extensive rematch) — `PoliciesByStableKey` still returns the raw policy, which is correct because `policyMatchOrActionChanged` compares authored match text.
- **Layer choice:** Fingerprints must hash "exactly what ships" (the file's own stated invariant), so the scrub belongs at the fingerprint site via the existing `policySnapshotAfterZoneQuarantine` SSOT rather than a second scrub implementation. ID-map exclusion belongs in the shared `walkPolicyRuleSlots` SSOT (the #13168 precedent) so builder, ID maps, and counter resolver cannot drift; filtering only in `PolicyIDsByStableKey`/`PoliciesByStableKey` would have left `RuntimePolicyIDs` and published IDs divergent.
