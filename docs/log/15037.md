# #15037 interface-monitor names never validated — engineering history

Issue: psaab/xpf#15037 (A15-03). Lane branch: `fix/15037-campaign`, base
`origin/master` b20a2b5afa.

## Defect (present at base)

`chassis cluster redundancy-group <n> interface-monitor <name>` was never
checked against the interfaces the config defines. The cluster monitor
(`pkg/cluster/monitor.go` `pollInterfaceMonitors`) resolves the name with
`LinuxIfName` + `LinkByName` and skips only a name whose FPC slot belongs
to the peer; every other miss counts DOWN. A RETH name (`reth0`, slot -1,
bondless — no netdev ever carries it) or a name defined nowhere therefore
counts down on BOTH nodes: both redundancy-group weights reach 0 and
`election.go`'s weight<=0 -> secondary leaves the group owned by NEITHER
node, from one clean-committed line. `validateChassisClusterStrict` only
range-checked the monitor WEIGHT (#6549).

## Fix

- `validateChassisClusterStrict` now also rejects a monitor name that is
  not a physical interface attributable from the config
  (`interfaceMonitorNameAttributable`): physical-shaped (FPC slot parses,
  slash or dash spelling #8829; not dotted, not a RETH) AND declared —
  an `interfaces` stanza on any node view, or a fabric
  member-interfaces entry (a bare physical NIC may exist only there,
  #8444). A physical-shaped name declared nowhere while other physical
  interfaces ARE declared is refused (the `ge-0/0/99` typo class); when
  nothing physical is declared anywhere it stays attributable (the
  stanza-less splitter fixtures; a monitor on a not-yet-stanza'd slot is
  counted down, the #5080 fail-closed direction). Keyword-shaped names
  (`interface-monitor preempt`, the #6665/#6672 splitter reservation)
  are exempt. Strict-reject at commit; the existing `lenientChassisRG`
  downgrade warns on the tolerant load/peer-sync paths (#1960) and the
  monitor compiles verbatim there.
  The group-aware wrapper also has one narrow peer exception for
  single-node effective configs (notably
  `test/incus/xpf-cluster-fw{0,1}.conf`): a peer-slot monitor is
  attributable only if that same redundancy group owns a declared
  `reth*` interface and one of that RETH's declared members is on the
  opposite node slot with the candidate's exact device/PIC/port tail.
  Thus fw1's `ge-0/0/1` is attributable beside its declared
  `ge-7/0/1 -> reth0` in RG 1, while `ge-0/0/99`, `ge-7/0/99`, and a
  tail whose twin belongs to a different RETH group remain rejected.
- Attribution needs the any-node union: one shared cluster config
  monitors both nodes' members, each declared only in its own node's
  group, and `ExpandGroups` removes the `groups` stanza. Both compile
  wrappers therefore compute the set from the pre-expansion tree
  (`physicalInterfacesInTree`: top level + interfaces stanzas at any
  depth beneath a top-level `groups` block + fabric members, so nested
  `interfaces` REFERENCES such as class-of-service do not mint
  attribution), thread it via
  `compileOpts.physicalInterfaces` (the #13095 `zoneQuarantineNames`
  precedent), and stamp it as `Config.PhysicalInterfaces` (`json:"-"`,
  compile-time only). The exported field name is required because
  `dual_ast_differential_test.go` reflects over Config fields, and the
  field is excluded from that comparison (it derives from tree shape,
  not compiled behaviour).

## Residuals

- Keyword-shaped monitor names remain exempt (splitter reservation).
- A physical-shaped name with NO physical interface declared anywhere
  is attributable (Junos likewise accepts a monitor on a slot with no
  stanza; runtime counts it down). The both-nodes-down consequence then
  requires an operator to monitor an undeclared slot in an otherwise
  interface-less cluster config.
- `docs/config-schema.md` documents the gate beside #6549.
