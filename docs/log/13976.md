# IPv6 capture classifier missed Fragment headers behind extension headers (#13976)

- **Issue**: #13976 (deep-review H21-02) — ClassifyCapturePayload
  recognised a Fragment header only when it immediately followed the
  IPv6 base header. A fragment behind Hop-by-Hop, Destination Options,
  Routing, or AH was classified as a whole packet (IsFragment=false,
  no FragmentKey), so the IPsec capture pipeline enqueued it for
  ordinary adjudication instead of the documented fragment refusal
  (docs/userspace-dataplane-gaps.md: "every other frame - INPUT,
  fragments, and every refusal - is terminally dropped").

- **Fix** (pkg/nfqueue/classify.go, classifyIPv6): walk the IPv6
  extension chain with the same type set, advance arithmetic, and bound
  as the sibling Rust walker walk_ipv6_ext_chain
  (userspace-dp/src/afxdp/frame/inspect.rs, MAX_IPV6_EXT_HEADERS = 8):
  generic length-prefixed headers (0/43/60/135/139/140/253/254) advance
  (HdrExtLen+1)*8, AH (51) advances (len+2)*4, Fragment (44) advances
  a fixed 8 bytes, and any other protocol (including ESP 50 and
  No-Next-Header 59) is the terminal protocol. A Fragment header
  anywhere in the walked chain sets IsFragment/FragMore/FragOffset/
  FragID and stops the walk, so payloadOffset/payloadLength and first-
  fragment port extraction see exactly the fragment-carried transport
  header, byte-identical to the previous immediate-Fragment path.
  Truncated headers, declared lengths overrunning the IP-declared end,
  and chains still on a traversable header after 8 iterations are
  rejected (fail closed) instead of adjudicated unresolved. The
  extended set matches the Rust traversable set exactly: before this
  the classifier terminated at the first extension header, so e.g. a
  Mobility-led chain yielded Proto=135 and never found a Fragment
  behind it; leaving the Go set at 0/43/60/51 would have kept that
  hole for 135/139/140/253/254.

- **Boundary**: with 8 walk iterations, a Fragment as the 7th header
  (six preceding extension headers) resolves; a Fragment declared as
  the 8th header is over the adjudication bound and is rejected. The
  Rust walker records that sighting but returns OverLimit (non-fragment
  consumers fail closed); the capture classifier likewise fails closed
  and never emits a non-fragment verdict for it.

- **Regression**: TestClassifyV6FragmentBehindExtChain13976 covers
  HBH/Routing/DstOpts/AH/Mobility/HIP/Shim6/exp253/exp254-led and
  multi-hop chains to a Fragment (first and non-first, with FragmentKey
  and FragmentPiece), a no-Fragment chain negative (ports preserved),
  truncated/overrun chains, the over-limit chain, and both sides of
  the walk bound. TestClassifyV6NonTransportProtocols10897 now drives
  HBH/DstOpts as real walked headers terminating in No-Next-Header
  (previously it asserted the header type itself as the protocol,
  encoding the unparsed behaviour). RED on the unfixed classifier:
  every behind-chain subtest fails with IsFragment=false (e.g.
  classification = {Proto:0 IsFragment:false} for HBH-first), and the
  two 10897 rows fail; GREEN after: all TestClassify* tests and the
  full pkg/nfqueue package pass.

- **Validation**: GOCACHE=/var/worktrees/.cache/go-build go test
  ./pkg/nfqueue/ -run TestClassify -count=1 passes; full package
  go test ./pkg/nfqueue/ -count=1 passes on a quiet run. Under the
  heavily loaded shared box (load >12 from sibling lanes) the
  unrelated timing-sensitive TestMeasureStages9506 (a netns stage
  benchmark gate that never calls the classifier) intermittently
  fails in this worktree while passing 4/4 standalone runs in a
  pristine origin/master worktree and passing in-package between
  loaded runs; it is not affected by this change. gofmt clean,
  go vet clean, git diff --check clean. RED verified by stashing only
  classify.go and re-running the two tests against the unfixed code.
  After rebase onto origin/master 46672678b the classify suite and
  pkg/daemon capture tests pass.

- **Risk**: behaviour change is confined to IPv6 capture
  classification. Chains behind extension headers now resolve their
  real terminal protocol (e.g. HBH->UDP now yields ports and a
  per-flow key instead of an HBH-protocol endpoint key), which is the
  Rust-walker verdict for the same bytes; malformed chains that
  previously passed as endpoint-classified packets are now rejected
  at classification (terminal drop, the documented disposition).
