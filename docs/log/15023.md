# #15023 — Rollback-metadata rebind hashes whatever bytes are on disk (A19-01)

## Defect
`rebindRollbackMetadataLocked` (`pkg/configstore/rollback_metadata.go`,
introduced by #14578 / e6d2645537) rewrote `rollback-meta.json` after
active-only rewrites (`PromoteRollback`, boot recovery, persist-retry heal)
but derived each slot's hash/identity from the bytes currently on disk:

- Live entry: `if b, err := ReadBoundedFile(path, MaxConfigSize); err == nil { data = b }`
  replaced the in-memory `entry.Config.Format()` bytes before hashing, so a
  stale slot left by a prior slot-write failure (ENOSPC/EIO) or a crash during
  a commit-confirmed slot shift was blessed as the current generation.
- Tombstone entry: the same disk read replaced the tombstone marker, so a slot
  whose marker write had previously failed kept its old generation's config
  bytes and hash.
- On success the rebind unconditionally cleared `rollbackPersistDegraded`.

After restart, `loadRollbackHistory` verified the stale bytes against the
blessed hash/identity and admitted them: `rollback N` returned a different
generation's config with no warning and health green.

## Fix
`pkg/configstore/rollback_metadata.go` — `rebindRollbackMetadataLocked` only;
callers unchanged:

- Live entry: expected bytes are always `entry.Config.Format()`. The slot
  file is rewritten durably (`rbWriteFileDurable`) whenever its on-disk bytes
  diverge (including missing, unreadable, or oversized reads); only the
  identity captured after a verified match or successful rewrite is recorded.
- Tombstone entry: the marker is always the recorded bytes. If the slot file
  still parses as a real config (a prior generation's bytes whose marker
  write previously failed, or bytes tombstoned at load by the #10723
  generation check), the marker is restored durably; bytes that already
  refuse at load (marker/empty/parse error — the trailing tombstones of a
  healthy #14578 boot-recovery ladder) keep their existing identity so that
  neighbouring legitimate behaviour is unchanged.
- A slot that cannot be made to match its in-memory entry records an invalid
  (zero) identity so the next load tombstones it (fail-closed), and the
  rebind stays degraded; `rollbackPersistDegraded` clears only when every
  slot was verified or rewritten and the sidecar write succeeded.
- Healthy ladders are untouched: matching slots keep their existing
  device/inode/mtime (no rewrite), preserving neighbouring behaviour.

## Tests
`pkg/configstore/rollback_rebind_15023_test.go`:

- `TestRebindDoesNotBlessStaleLiveSlot_15023`: slot 3 holds `hostStale` on
  disk, `hostC` in memory → rebind rewrites it; restart gives rb1=hostA,
  rb2=hostB, rb3=hostC, degraded cleared only after the rewrite.
- `TestRebindStaysDegradedWhenStaleSlotRewriteFails_15023`: injected ENOSPC
  on the slot-3 rewrite → degraded stays true; restart keeps hostA/hostB and
  tombstones slot 3 (REFUSED, never the stale generation).
- `TestRebindDoesNotBlessTombstonedSlot_15023`: tombstone entry whose file
  still holds `hostB` bytes → file becomes the marker; restart keeps the
  tombstone at slot 2 with hostA/hostC intact.
- `TestRebindHealthyLadderUnchanged_15023` (control): a matching ladder is
  rebound with all slot identities unchanged and stays healthy after restart.
