# #16710: unscoped IPsec re-initiation belt flaps tunnels on later RG edges

- **Timestamp**: 2026-10-25
- **Action**: Scoped every IPsec SA re-initiation pass to the transitioning
  redundancy group. `reinitiateIPsecSAs` became
  `reinitiateIPsecSAsForRG(rg)` with a new decision helper
  `ipsecSAsToReinitiateForRG(names, rg)` that requires every candidate RG
  of a name (the `ipsecConnRedundancyGroups` all-candidates rule already
  used by `ipsecSAsForRG`) to equal the edge's RG, on top of the existing
  `ownsIPsecConn` ownership check. The RG0 edge
  (`applyRG0OwnershipTransition`) now passes 0 (only RG0/unanchored
  names) and the data-RG edge (`applyRethServicesForRG`) passes its
  `rgID`. The #15194 stale-duplicate belt inherits the scope, so a later
  edge of a takeover wave can no longer `--terminate --ike --force` the
  healthy tunnels an earlier edge just raised. The unscoped
  `ipsecSAsToReinitiate` decision helper is retained for the existing
  decision-only tests (#9139/#9511/#9641). Added
  `pkg/daemon/ipsec_reinitiate_wave_16710_test.go` driving the va35
  shape-A wave (progressive RG1-then-RG2 ownership, live view growing
  with each initiate): 0 terminates and exactly one initiate per name
  across the wave, RG0-edge and data-RG-edge scoping cells, a
  belt-only-own-RG cell, and a production `applyRethServicesForRG` wiring
  cell. Updated the two shipped #15194 belt cells to the scoped call
  (RG1 edge) and renamed their RG0-anchored fixture name from
  `vpn-plain` to `vpn-rg0` so the scoped RG1 belt cells measure RG
  attribution rather than the RG0 fallback (production behaviour for
  plain/unanchored names is unchanged: they belong to the RG0 edge).
- **File(s)**: `pkg/daemon/daemon_ha.go`,
  `pkg/daemon/ipsec_reinitiate_wave_16710_test.go`,
  `pkg/daemon/ipsec_demote_terminate_15194_test.go`,
  `docs/log/16710.md` (this file).
- **Validation**: See the PR body for the exact commands and counts
  (targeted 16710/15194/9139/9511/9641 daemon tests).
- **Residual**: A name whose candidate VPNs span several RGs is raised
  by no single-RG edge until an edge for one of its groups fires while
  this node owns every candidate (the pre-existing `ownsIPsecConn`
  rule); the old code belt-terminated such a name on every edge, so
  this is strictly narrower, but a full-wave crash takeover where no
  later edge fires could leave a multi-RG name for the remote peer or
  traffic (`trap`) to raise. Lab verification of real edge spacing on
  the loss cluster was not run by this lane.
