# #14992 — upgrade: preserve kernel-roll leases and rejoin on transient fence loss instead of stranding a drained node (D38-04)

- **Timestamp**: 2026-10-18
- **Action**: `cmd_kernel_roll` in `scripts/deploy/xpf-deploy.py` no longer strands a drained node on a transient fence loss. (1) `_fence_before_mutate` gains an `on_unreachable` callback invoked only when a lease is UNCONFIRMABLE after retries (transport failure, never a proven `LOST`); `on_lost` keeps its legacy both-outcomes behaviour when `on_unreachable` is not supplied, so the fence itself stays fail-closed and no other caller changes behaviour. `cmd_kernel_roll` passes `on_unreachable=_note_unconfirmable`, so only a PROVEN loss (fence `LOST` or keepalive) sets `lost_lease` and suppresses the finally restore rejoin (#5816 preserved). (2) The `finally` lease disposition now PRESERVES both leases whenever the roll drained the node and did not complete (mirroring `image-roll`'s never-both-down stance, whose leases name the same file and whose drained node — unlike kernel-roll's wiped recreate — is still drained); clean success, pre-drain aborts, dry-run, and drained-but-rebooted rolls still release. A preserved lease expires on its TTL, after which the Go `KernelSelfRecovery` fingerprint (EXPIRED lease naming the node; a deleted lease reads `leaseNone`, a permanent no-op in `Tick`) can rejoin the drained node.
- **Validation**: New `KernelRollTransientFenceLossTests` + `FenceUnreachableCallbackTests` in `scripts/deploy/test_xpf_deploy_lease_renew_fence.py` with a lease-state-tracking backend: RED on `origin/master` (finally skipped the rejoin — `verbs == [('fw0','drain')]` — and deleted both leases; `on_unreachable` unsupported), GREEN after the fix (drain + restore rejoin, `clears == []`, both leases present; proven-loss control keeps the #5816 no-rejoin; arm-failure control rejoins and preserves). Adjacent suites `test_xpf_deploy_lease_renew_fence`, `test_xpf_deploy_kernel_roll`, `test_xpf_deploy_correctness` green (49 tests).
- **Risk**: Fail-closed preserved — the fence still refuses every forward mutation (drain/arm/rejoin) on an unconfirmable lease; only the restore rejoin (which undoes this orchestrator's own drain and confirms peer-alive+sync in-guest) and lease preservation change. Preserved leases block a successor only until TTL expiry (default 1800s), the same operator-gated stance `image-roll` already takes on a half-rolled pair.
- **Scope**: `scripts/deploy` only, per the issue's binding scope narrowing. The cited Go symbols (`KernelSelfRecovery.readLeaseState`/`Tick`, `KernelRunner.restoreKnownGood`) required no change: the defect was the Python finally destroying the lease state the Go machine correctly keys on.
