# #13912 — Detect missing remote generation in legacy NAT state test

- **Timestamp**: 2026-10-16
- **Action**: Use a nonzero remote generation and assert map-key presence.
- **Base**: `origin/master` `5aa9179e4`
- **Files**: `pkg/dataplane/userspace/persistent_nat_generation_11486_test.go`,

## Why

The legacy-state compatibility test used generation zero and indexed the
remote-generation map directly. A missing key also indexes to zero, so a
loader that discarded all remote-generation entries would still pass. This
made the test unable to catch loss of durable peer-generation state.

## What

The fixture now stores remote generation 7. The assertion checks both the
map's `ok` result and the exact generation value, so an absent entry fails.
No production behavior changed.
