# #17131 — Cross-language goldens for every event-stream encoder body (R4-Q15-03)

## Defect (live on origin/master 784d53a6cf)

Of the Rust event-frame encoder bodies, only `encode_session_record`
(OPEN/UPDATE) was pinned by an artifact the real encoder produced
(`testdata/session_update_frame_9412.hex`, #9412). SESSION_CLOSE (type 2,
v4/v6), RT_FLOW close/create, and the dataplane-event payload had no
cross-language check. The two Go tests calling themselves cross-language
anchors built frames from Go's own layout (`binary_test.go` #2465,
`daemon_flowexport_session_close_test.go` #2460 sizing from
`unsafe.Sizeof(dataplane.Event{})`), so they could not fail on Rust drift.
Nine live references pointed at `event_stream/codec.rs`, split away in #4651.

## Fix

- `userspace-dp/src/event_stream/codec/goldens.rs` (test-only): a table of
  six specimens, one per encoder body — `session_update`,
  `session_close_v4`, `session_close_v6`, `rt_flow_close`, `rt_flow_create`,
  `dataplane_event` — each produced by the real encoder. Written slots
  carry non-default specimen values except the intentional zero/unwritten
  slots enumerated in the `goldens.rs` header (dataplane NAT None/0,
  session NAT64/snat zero, PolicyDeny rule_id/term_id unwritten). Written
  to `pkg/dataplane/userspace/testdata/event_frames/<name>.hex` under
  `XPF_WRITE_GOLDEN=1`, otherwise compared byte-for-byte.
- `pkg/dataplane/userspace/event_frame_goldens_17131_test.go`:
  `TestEventFrameGoldensDecode17131` decodes each golden through the
  production decoders (`decodeSessionEvent`, `decodeSessionCloseEvent`,
  `decodeDataplaneEventPayload` → `logging.DecodeRawEventRecord`) and
  asserts the specimen values field-by-field, byte-pinning slots with no
  decoded field (RT_FLOW AppID [132:134], syslog gate [135], GEN1 marker
  [140:144] + generation, session disposition [31] and next-hop
  [60:64]). Moving any one offset in `encode_session_close_rt_flow`
  (with Rust pins updated) now reds Go.
- The #2460/#2465 Go "anchors" are re-labelled as Go-side decode fixtures
  (their bytes never came from Rust); the Rust-produced anchor is named.
- All 9 `event_stream/codec.rs` references replaced with the post-#4651
  symbol locations (`codec/session_sync.rs`, `codec/rt_flow.rs`,
  `codec/wire.rs`): `pkg/config`, `pkg/daemon`, `pkg/dataplane/userspace`
  (×2 files), `pkg/logging`, `userspace-dp/src/session/README.md`.
  Acceptance grep now returns 0 in `pkg` + `userspace-dp/src`.

The #9412 golden/mechanism is untouched and still passes.

## Validation (named hermetic tests only)

- Rust: `cargo test -- --exact event_stream::codec::goldens::test_event_frame_goldens_match_go_testdata_17131` — pass (compare mode; generated once with `XPF_WRITE_GOLDEN=1`).
- Go: `go test ./pkg/dataplane/userspace/ -run '^TestEventFrameGoldensDecode17131$'` — pass, all 6 subtests.
- Mutant proofs (golden hex mutated, Go reds, then restored): clearing
  RT_FLOW AppID [132:134], moving/flipping generation [160:168],
  flipping session disposition byte [31], flipping next-hop [60:64],
  and corrupting GEN1 marker / deny generation [56:64] each red Go.
- `ls pkg/dataplane/userspace/testdata/event_frames/*.hex | wc -l` = 6 (≥5).
- `grep -rn 'event_stream/codec\.rs' pkg userspace-dp/src` = 0 hits.
- `gofmt -l` on touched Go files: clean.

## Residual / uncovered risks

- Session sync frames (`session_update`, `session_close_*`): the Go
  decoder's zone fields are u16 while `SessionMetadata.ingress_zone` is
  u32 in Rust (the encoder itself writes `as u16`); the encoder-set
  `FLAG_FABRIC_REDIRECT`-only disposition has no Go bool. Every other
  written slot is field-asserted or byte-pinned in Go (disposition [31]
  via LocalDelivery, next-hop [60:64]).
- RT_FLOW/dataplane frames: AppID, the syslog gate, the GEN1 marker and
  the paired generation have no `EventRecord` field, so they are
  byte-pinned in Go from the payload; `EventRecord.Reason` DOES have a
  Go surface (`pkg/logging/eventbuf.go:23`, mapped from [134]) and is
  asserted for the deny specimen. Filter/screen slots on
  PolicyDeny specimens are unwritten by that kind's encoder.
