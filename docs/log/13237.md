# Issue #13237 — reject CPU windows spanning helper counter resets

## Why

`computeCPUWindows` checked only the first and last cumulative counter values.
If `userspace-dp` restarted inside a 1m or 5m window, its reset could be
missed when the new counter had already overtaken the old start value. The
result mixed two helper lifetimes and displayed impossible worker CPU, such
as 4000%. The same endpoint-only check could report daemon CPU across a
mid-window decrease. On a cache miss, `Sampler.sample` could also read saved
worker counters before a blocking cache lookup, then overwrite newer counters
committed by another sample.

## What

- Reject daemon and worker windows when their cumulative counters decrease
  anywhere in the sampled interval; held worker telemetry remains invalid.
- On cache misses, select the saved worker counter pair under the same
  `Sampler.mu` lock that appends the sample, preventing rollback after a blocked
  cache lookup.
- Clamp worker CPU rows to 100%, retaining unbounded per-core daemon values.
- Remove the unused exported `UMEMBufferFollowup` function.
- Add regression coverage for mid-window worker and daemon resets, row bounds,
  and concurrent sampling.

## Validation

- RED on pristine branch: `go test ./pkg/fwdstatus -run
  'TestComputeCPUWindows_MidWindow(Counter|Daemon)Reset' -count=1` failed:
  worker 1m was valid at 4000%, and daemon 1m was valid at 50% across an
  intermediate reset.
- GREEN: `go test ./pkg/fwdstatus -count=1` passed.
- GREEN: `go test -race ./pkg/fwdstatus -run
  'TestSamplerConcurrentSampleRaceFree|TestComputeCPUWindows_MidWindow' -count=1`
  passed.
- A deterministic interleaving regression failed before the lock-gap fix:
  a cache-miss sample delayed in `CachedStatus()` appended and saved 0/0 after
  another sample committed 700/900. It passed after selecting held counters
  under the final lock.
- Final verification: full `go test ./pkg/fwdstatus -count=1`, targeted
  `go test -race` for the concurrent sample and reset tests, and
  `go vet ./pkg/fwdstatus` passed; `gofmt` applied to changed Go files.

## Risk

Windows containing a counter reset now display invalid data until the window
ages past that reset, rather than an invalid cross-lifetime percentage. Worker
rows are capped at 100%; daemon per-core rows retain values above 100%. No
runtime forwarding behavior changes.
