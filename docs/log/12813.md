# #12813 — reject malformed packed qualified-next-hop tails

## Red before

The packed static-route form

```text
next-hop interface ge-0/0/1.0 qualified-next-hop preference 250
```

was left fused by the #12648 normalizer because the QNH clause had no gateway.
The #12790 compile gate only recognized residual QNH tokens on the interface
child. The compiler then read the fused `next-hop` tail as gateway values and
accepted garbage hops (`qualified-next-hop`, `preference`, `250`). A QNH gateway
followed by an unsupported token such as `bogus 5` was similarly compiled with
the trailing values as hops. The direct schema path already rejected the issue
reproductions; the regression was on `CompileConfig`.

## Change

Expanded the shared static-route QNH tail validator used by strict compilation,
tolerant compilation, and `SchemaValidateWithDefinitions`. It now rejects any
residual QNH marker still fused onto a `next-hop` key sequence and rejects
unsupported/incomplete trailing tokens on a qualified-next-hop node. Valid
normalized clauses continue through the existing route compiler path; the
quoted/dangling interface-child shapes are reported by the generic next-hop scan above (the interface-specific branch was unreachable and removed on review).

Added regression cases for the reported missing-gateway preference tail, a QNH
gateway followed by unknown tokens, and the packed interface-child variant.
The valid packed interface/QNH form asserts both compiled next-hop entries and
the exact preference metadata.
