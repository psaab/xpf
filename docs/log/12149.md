# #12149 — include loopback in the SNMP IF-MIB inventory

- **Base**: `a714c90d472a3c3d98a3799831cfef3ec311a61c` (`origin/master` at STEP-0).
- **Why**: `buildSNMPIfData` omitted the kernel's `lo` interface, so the SNMP ifTable/ifXTable had no loopback row and `ifNumber` (the length of the shared interface snapshot) undercounted present interfaces.
- **Change**: Keep `lo` in the shared interface data, report its IF-MIB `ifType` as `24` (`softwareLoopback`), and document that value in `snmp.IfData`. Other interface types and rows are unchanged. The regression fixture checks the loopback's ifIndex, ifDescr/ifName, ifType, total count, and an ordinary Ethernet control.
- **RED-before**: On the untouched base, `go test ./pkg/daemon -run '^TestBuildSNMPIfDataIncludesLoopback12149$' -count=1 -v` failed: `ifNumber/ifTable count = 1, want 2`; the only row was `test0` (lo was omitted).
- **GREEN-after**: The same focused command passed on the final tree. `go build ./pkg/daemon ./pkg/snmp` passed; `gofmt -l` was empty for the three Go files; `go test ./pkg/daemon ./pkg/snmp -count=1` passed (`daemon`: 178.749s, `snmp`: 10.479s). No broader scoped-test reds required base attribution.
- **Risk / residual**: No live-cluster SNMP query was run. The advertised `lo` counters remain Linux kernel loopback counters and are not claimed to have Junos lo0 routing-engine counter semantics.
- **Files**: `pkg/daemon/daemon_snmp_reconcile.go`, `pkg/daemon/daemon_snmp_ifdata_loopback_12149_test.go`, `pkg/snmp/agent.go`, `docs/log/12149.md`.
