- **Timestamp:** 2026-10-27
- **Branch:** `fix/17081-campaign`

## Why

`policymatch.Query` encoded "port omitted" as `0`, colliding with literal L4 port 0. Against a `0-N` application term the simulator therefore returned the inverse of the enforced verdict in both directions (deny reported as default-permit, permit as default-deny) — the exact traffic class of #13920, whose simulator fix was reverted in 6bd30008fd because the encoding could not distinguish the two. The same proto message already used `optional` for ICMP type/code, so presence was representable.

## What

- `Query.SrcPort/DstPort` and `SelectorArgs.SrcPort/DstPort` are now `*uint16` (nil = omitted, `PortPtr(0)` = literal 0), mirroring `ICMPType/ICMPCode`. `ParsePort` returns `(*uint16, error)`: empty = `(nil, nil)`, explicit `"0"` = present 0. The matcher gate is `!l4Present || port == nil || !portMatches(spec, *port)` for both destination (#3330) and source (#3415); non-first fragments still fail closed via `l4Present`. No `Port <= 0` sentinel remains (`grep -n 'Port <= 0' pkg/policymatch/*.go` is empty).
- Proto `MatchPoliciesRequest.source_port/destination_port` become `optional int32` (regenerated with pinned protoc 3.21.12 / protoc-gen-go v1.36.11); gRPC converts via `grpcPortValue`, REST treats an absent key as omitted and a present `dst_port=0` as literal, the remote CLI forwards presence, and the `test-policy:` text topic now forwards `port=0`/`srcport=0` (previously dropped by `> 0` guards).
- Session-tuple builders (daemon rename/invalidate) always carry concrete ports, so they wrap with `PortPtr`; `networkPort` returns `*uint16`.
- Shared corpus gains case `port-zero-range-17081` (`udp dport 0` and `53` against a `0-1023` deny, `2000` control): the Go reader now builds present ports, the Rust reader already passed literal u16 ports, so both halves assert `deny d` for port 0. Fold (Rev18131 B1): the snapshots JSON is regenerated (`UPDATE_9167=1`) and committed, so `port-zero-range-17081` exists in both halves; the first data refresh also absorbs the pre-existing #16557 u32 zone-id / #16560 contiguous policy-id drift the committed file had gone stale on.
- Restored the deleted #13920 Go coverage as `port_zero_literal_17081_test.go`: both rule directions, omitted-still-fails-closed, source-port sibling, and selector-grammar presence.

## Risk

Simulator/diagnostic surfaces only; dataplane enforcement unchanged. Wire change is additive presence: old clients omitting the proto fields get the previous omitted semantics, but an old client explicitly sending `0` previously meant omitted and now (against a new daemon) means literal 0 — the intended #17081 semantics. `Query` is a Go API break for out-of-tree builders (compile error, not silent change). Host-inbound classification receives `-1`/not-present for an omitted dst port, preserving its previous unspecified behavior; a present literal 0 is now threaded as present (fold, Rev18131) so the classifier decides it against the token ranges - no host-inbound token admits port 0, so it reports denied rather than indeterminate. REST present-but-empty port (`?dst_port=`) now 400s instead of silently degrading to omitted, matching the CLI/topic surfaces, and the gRPC authz canonical form now emits a present literal port 0 (pointer-presence gate mirroring the ICMP fields).
