# #14338 — validateZoneScreenReferences omits quarantine exclusions

## Defect
- `validateZoneScreenReferences` (`pkg/dataplane/compiler_iface.go`) skipped only nil / empty-screen / `DroppedEnforcementChild` zones, while `programZoneMaps` (same file) and `userspace/screens.go:buildScreenSnapshots` also skip zones in `config.ZoneQuarantineExclusionsForConfig(cfg)` (StableZoneID collision losers, reserved names, poisoned zones).
- The validator is the first row of the #4960 pre-mutation `validationPhases` table (`compiler_validate_4960.go`) and the first call in `compileZones`, so a quarantined collision-loser zone referencing an undefined screen profile aborted `CompileUserspaceShim`/`CompileConfig` before any programming, even though that zone would never be installed. Previous-good config was retained (fail-closed, availability only).

## Fix
- `pkg/dataplane/compiler_iface.go:validateZoneScreenReferences`: compute `excludedZones := config.ZoneQuarantineExclusionsForConfig(cfg)` once before the sorted sweep and `continue` for excluded zone names, mirroring `programZoneMaps`. No other behavior changed; non-quarantined zones with missing profiles still reject with the same error.

## Tests
- New `TestValidateZoneScreenReferences_SkipsQuarantinedCollisionLoser` in `pkg/dataplane/compiler_test.go`: uses the verified frozen-fold pair `z174`/`z214` (later-sorting `z214` quarantined), asserts `ZoneQuarantineExclusionsForConfig` membership as fixture premise, quarantined `z214` with `missing-screen` is skipped, and a fail-closed control (same missing profile on survivor `z174`) still rejects.
