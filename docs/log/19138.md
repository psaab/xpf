# #19138: the 10038 no-session cell witnesses through counters, not a consumable edge

- **Timestamp**: 2026-11-16
- **Action**: Investigated the flake ("the NoSession encap must request a
  handshake", 1 of 24 runs, udp:xpf-testrunner3).
  - **First hypothesis, FALSIFIED by experiment.** I thought the control
    loop's 1 s attempt tick consumes the edge in the <=20 ms before the test
    polls it. But master's cell with a 1.2 s stall between the write and the
    first poll PASSED 5/5 (filter verified to select the one cell). Reason:
    before its main loop, `run_wg_control_loop` starts a BringUp handshake
    attempt for every peer with an endpoint (`mod.rs`). While an attempt is
    active (`REKEY_ATTEMPT_TIME`, 90 s; nothing answers on 127.0.0.1:9),
    `drive_attempt_machine` returns before the code that takes edges.
  - **Current hypothesis (NOT proven).** A VM pause longer than 90 s jumps
    the guest's monotonic clock (#19142's live observation). At the next timer
    pass the BringUp attempt GIVES UP, and give-up drains the NoSession edge
    (`attempt.rs`, `take_handshake_request`). With no attempt active, later
    ticks also take any new edge. Either way a cell that polls the edge can
    miss it.
    - Evidence for: F2's lab gate log shows udp:xpf-testrunner3 paused at
      01:15:13-01:16:59Z (106 s) and 01:20:21-01:21:55Z (94 s), inside the
      failing run (01:13:28-01:23:13Z). That suite took 218.8 s against 122.9
      s for the identical canonical run on the same runner: 95.9 s extra,
      about the 94 s pause plus the failing cell's 2 s poll. Every gate pause
      measured so far is longer than 90 s.
    - Not shown: that the pause overlapped THIS cell. There are no per-test
      timestamps, and the drain needs the pause in a sub-second window. G6's,
      H2's and the other lanes' wlib logs have no pause of that runner then;
      F2's does.
- **Action**: `wg_tun_burst_skips_publish_without_session_10038` no longer
  depends on the mechanism:
  - it witnesses the burst through COUNTERS the loop never consumes:
    `encap_drops_no_session` (bumped per NoSession packet) and
    `hs_requests_armed` (the edge was raised), not the consume-once edge;
  - a second inner packet replaces the 200 ms settle sleep. The burst is
    single-threaded, so once the second packet has reached encap, the first
    packet's iteration, including any publish a missing gate would make
    after `encap_and_send` returns, is over;
  - the hang guard counts ITERATIONS (12000 x 5 ms), not elapsed time, so a
    pause cannot use up the budget. The previous loop was also iteration
    counted; an Instant deadline would have failed across a 91 s pause.
  The gate assertion ("a non-Sent encap must publish nothing") is unchanged.
- **Validation** (tcp:xpf-testrunner2 via `scripts/vm-test-run.sh`; a pass
  counts only with `test result: ok. 1 passed`, a fail only with the expected
  text):
  - fixed cell: 30/30 debug, 20/20 release.
  - Injection, the deterministic RED/GREEN that does not depend on the
    mechanism: the edge is drained in the cell after the burst, as give-up
    would drain it. Master's cell FAILS 5/5 ("must request a handshake"); the
    fixed cell PASSES 5/5.
  - Gate mutant (`matches!(encap_outcome, Sent | NoSession)`): both the fixed
    and master's cell FAIL 3/3 on "a non-Sent encap must publish nothing".
    The fixed cell still catches a missing gate, now without a sleep.
  - An earlier mutant run was VOID: `if tun_origin_due` alone did not build
    (an unused variable). It was replaced by the form above.
  - That runner was paused for 1761 s in total during the validation run
    (`paused-for=1761s`). Every pass was a real one-test pass and every
    failure carried its expected text.

- **Timestamp**: 2026-11-16 (fold cycle 1, Codex review of b7c)
- **Action**: Verified the P2. `encap_drops_no_session` and
  `hs_requests_armed` are separate atomics bumped and read with
  `Ordering::Relaxed`. Seeing the first reach 2 creates no happens-before edge
  to the other's increment, so the `hs_requests_armed >= 1` read could legally
  see 0 under correct processing.
- **Action**: the cell waits for `encap_drops_no_session >= 2`, then STOPS and
  JOINS the control thread, and only then reads both counters and the maps.
  `join` makes every write the thread made visible, so the reads are exact.
  The bounded wait is unchanged (iteration counted).
- **Validation** (tcp:xpf-testrunner2 via `scripts/vm-test-run.sh`; a pass
  needs "1 passed", a fail needs its expected text):
  - folded cell 30/30 debug and 20/20 release;
  - edge drained after the burst: master's cell FAILS 5/5, the folded cell
    PASSES 5/5;
  - gate mutant (`Sent | NoSession`): the folded cell FAILS 3/3 on "must
    publish nothing".
