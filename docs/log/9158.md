# #9158 — a PAT→address-only flip orphans the lease's port, and tears down a live lease

## Defect, re-verified at the base commit (`62db2e1c7`)

The issue's evidence was an out-of-tree probe cell, so there was nothing to
re-run. Both comments on #9158 and #9159 asked the fixer to land it in-tree;
that is done, and it is what produced the measurement below.

Reading first. `reserve_address_only_persistent`'s mode gate
(`userspace-dp/src/nat/allocator.rs`) sent a mode-mismatched lease to the
`expired` arm **regardless of `active_flows`**, and that arm carried only
`(addr_index, expires_at_ns)`:

```rust
let mut expired: Option<(usize, u64)> = None;
...
} else {
    expired = Some((lease.addr_index, lease.expires_at_ns));
}
...
if let Some((addr_index, expires_at_ns)) = expired {
    // "Idle + past its inactivity window: drop it (an address-only lease
    //  holds NO port bit to free)"            <- false for the mismatch case
    Self::remove_lease_expiration_locked(&mut live, addr_index, expires_at_ns, key);
    live.persistent_by_source.remove(&key);
}
```

The in-file positive control is the port-bearing mirror
`reuse_persistent_lease_locked`, whose `expired` tuple carries `address_only` and
which calls `free_translated_port` when `!address_only`.

## The bound, MEASURED — the orphan never recovers

This is the question the remedy turns on: a leak that recovers on release is a
different defect with a different fix. Both recovery paths were read, then
driven:

| Path | Why it cannot reach the bit |
|---|---|
| `reclaim_expired_lease_locked` (the only GC site that frees a lease's port) | begins `persistent_by_source.get(&key)` — the flip removed that record |
| `unlink_live_allocation_locked` (flow release) | frees a port only when `persistent_key.is_none()`; a persistent flow's port belongs to the LEASE |

The cell drives it: flip, then a GC sweep **10 000 s** past every inactivity
timeout (300 s), then release the live PAT flow, then a second sweep. Result at
the base commit:

```
LEAK: port 40000 is still marked occupied ... referenced_by_a_pat_lease=false
```

So it is **monotonic and never recovers** inside the allocator's lifetime
(pool rebuild is the only escape). Repeated flips leak without bound.

**A finding the issue did not state.** The idle-flip cell ALSO failed at the base
commit. The arm freed nothing in *either* case, so the port orphan was never
conditional on liveness — liveness only adds the second harm, a live translation
torn down. The remedy therefore has to fix the free unconditionally, not only
under the live guard.

## Remedy, and why the obvious one is wrong

The issue's fix direction — carry `address_only` and gate on idle — is right for
the idle case and **incomplete for the live one**. Naively mirroring the free
under a live lease is an **over-release**: a live PAT flow is still forwarding on
that `(address, port)`, and freeing the bit lets `claim()` hand the same identity
to a second flow — the duplicate this allocator exists to prevent. And merely
"retaining" the lease is not enough either, because the tail of the function does
`persistent_by_source.insert(key, ...)`, which would overwrite the retained
record and orphan the bit by a second route.

So the arm is split three ways:

1. **Same mode, still valid** → reuse (unchanged).
2. **Mode-mismatched and IDLE** → tear down AND free the bit when
   `!address_only`, exactly as the port-bearing mirror does.
3. **Mode-mismatched and LIVE** → leave the lease STANDING and serve this flow
   **without persistence** (`persistent_key: None`, no lease insert, no
   refcount, `allocations_total` not bumped, lease-table pressure cap not
   applied). The lease keeps owning its bit until its own flows drain, at which
   point `complete_persistent_lease_locked` takes `active_flows` to 0, the lease
   enters `lease_expirations`, and `reclaim_expired_lease_locked` frees the port
   correctly.

Case 3 costs this flow its ADDRESS PINNING until the stale lease drains. It is
not dropped, nothing is over-released, and the state converges with no operator
action. Refusing the flow instead would turn a supported config edit into an
outage.

`persistent_key: None` on that record is load-bearing rather than tidy: with
`Some(key)` its release would run `complete_persistent_lease_locked` against the
SURVIVING lease and decrement a refcount it never incremented — driving
`active_flows` to 0 while that lease's own PAT flows are still forwarding, which
hands the lease to GC and frees a port in use. That is the over-release again,
one release later.

## Not fixed, filed separately

The MIRROR direction has the same live-lease teardown: the port-bearing
`expired` arm fires for an ADDRESS-ONLY lease with `active_flows > 0` and removes
it. No port is orphaned (an address-only lease holds no bit) and nothing is
over-released, so the harm is strictly smaller — the subscriber's pinned address
is forgotten and a later flow may land elsewhere. It is a different arm with its
own reviewed invariants, #9158 names the address-only direction, and a landed
partial fix removes the reason anyone looks again — so it is filed rather than
folded in silently.

### Two mutants that were first scored VOID / WRONG, and what each taught

**N1 -> N1b.** The first anchor matched BOTH free-sites: the port-bearing mirror
and this arm are byte-identical

```rust
            if !address_only {
                self.free_translated_port(addr_index, translated.port, true);
            }
            live.persistent_by_source.remove(&key);
```

so the applied-check's `count == 1` assertion refused and scored VOID rather than
mutating the wrong arm. Re-anchored on the unique preceding comment: 2 -> 1,
KILLED. The repair is a better anchor, not a looser assert.

**N5 -> N5b: a signal about the CELL, not the mutant.** N5 (let the degraded path
fall through to the lease insert) FAILED — but via the live-flip cell, not via
`a_flow_served_around_...`, whose subject it is. Being killed by the wrong cell
reads as a working guard and is not one.

Cause: one `PersistentSourceKey` holds one lease and `insert` **replaces**, so
`persistent_by_source.len() == 1` is true before AND after an overwrite. The
assertion was weaker than designed. It now asserts the survivor's IDENTITY — the
lease is still the PAT one (`!address_only`) and still owns `port` — and N5b is
killed by the intended cell. The verdict was re-measured, not re-labelled.
