## Why

Three hardenings each added a stricter entry point, moved known callers, and kept the pre-fix form compiling under the plainer name with docs describing it as operative: (1) `SendGratuitousARPBurst`/`SendGratuitousIPv6Burst` passed a nil abdication predicate — #2867 kept them and #2898 shipped re-poisoning through them a day later; (2) `computeFabricAuthToken` signed the empty request digest with an optional method while its doc claimed request-digest binding — #10709 moved every verifier off it; (3) `AuthorizeConfigShowCompareAtPath`/`RollbackAtPath` skipped the rendered-descendant pricing #15995 added while claiming adjudication. The replacements also made the strengthening input optional (nil `BurstStillValid`, empty variadic `trees ...*ConfigTree`), so even the new name could silently reproduce the weak behaviour.

## What

- **GARP:** deleted the ungated twins; the gated senders (`SendGratuitousARPBurstGated` / `SendGratuitousIPv6BurstGated` / `SendProxyGratuitousIPv6BurstGated`, internal `sendUnsolicitedIPv6NABurstGated` likewise — the issue allowed retaining the Gated name, and keeping it keeps the acceptance grep literal) are retained under their `*BurstGated` names and return an error on a nil predicate before any socket/interface work. `runARPBurstFollowups`/`runNABurstFollowups` refuse nil (send nothing). `pkg/daemon.announceProxyARPPoolAddresses` refuses nil once up front instead of failing per address; its test callers now pass an always-valid predicate (production passes `directBurstStillValid`). VRRP/daemon seams repointed.
- **Fabric auth:** deleted `computeFabricAuthToken`; `computeFabricAuthTokenForDigest(key, window, method, reqDigest)` is the only token form. `fabricAuthTokenHex`, `verifyFabricAuthToken`, `measureFabricAuthSkew`, `noteFabricAuthSkew` and the test helper `tokenAtOffset` now take `method string` as a required parameter (callers with no request body pass the empty digest explicitly via the surviving helpers). Added `TestWithFabricAuthRequestBindsManualClient17158` covering the documented manual-client API the issue left to test-or-delete: exact method+request admitted, changed arguments and request-unbound tokens refused, non-protobuf request fails closed.
- **Config authz:** deleted `AuthorizeConfigShowCompareAtPath` / `AuthorizeConfigShowRollbackAtPath`. All eleven `*Rendered`/`WholeAtTree` authorizers now take `trees []*ConfigTree` as a required slice parameter (was `trees ...*ConfigTree`); every production caller (gRPC/REST/CLI, incl. single-tree `[]*ConfigTree{snaps.Primary}` wrappers) and every test call site converted — no shim/alias. New `requireRenderedTreeSlice17158`: for a non-empty path (whole-tree forms pass a synthetic scope) with a configuration-restricted class, an empty slice refuses as unpriced; nil entries inside a non-empty slice still mean "renders nothing"; unrestricted/empty classes pay nothing.

## Risk

- Exported GARP signatures change (predicate parameter): all in-tree callers converted; the only external contract is compile-time, and a missed caller now fails to compile instead of silently running ungated — the intended #17158 behaviour. Nil-predicate callers that previously ran to completion now get an error / no follow-ups.
- Config authorizers: signature change is likewise compile-enforced. Behaviour change is fail-closed only for restricted classes with a non-empty path and no trees (previously admitted unpriced); production surfaces always pass the priced snapshot slice, so no live read changes verdict. Whole-tree restricted reads with no tree now refuse earlier with the #17158 message instead of the whole-tree refusal — both are refusals.
- Fabric token bytes are unchanged for every surviving call shape (same domain/method/digest/window framing); only the ability to omit method/digest at compile time is removed.
