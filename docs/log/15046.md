# Issue #15046 — vrrp-group Junos track container, no-preempt, unknown children (A05-04)

## Why

`vrrp-group` was open-world at the compiler level. The Junos
`track { interface <if> { priority-cost <n>; } }` container and
`no-preempt` passed strict commit with zero warnings and were silently
dropped by `parseVRRPGroups`' switch, so interface tracking was absent:
when the tracked uplink failed, the master kept the VIP and blackholed
the segment, with no error, warning, or alarm. Any other unknown child
(`zzbogus`) did the same.

## What

- Schema (`vrrpGroupSchemaNode`): declare `track { interface <if> {
  priority-cost <n>; } }` (both families, `interface` closed-world like
  `track-interface`) and `no-preempt`.
- Compiler (`parseVRRPGroups`): `track` feeds the same single-track
  slot as `track-interface` in Keys-packed, child-node, and flat-set
  spellings (`parseJunosTrackContainer15046`); `no-preempt` compiles
  explicitly to `Preempt=false` with the new `VRRPGroup.PreemptSet`
  marker (statement-order last-wins against `preempt`), so the
  statement is distinguishable from the unset default.
- Gate (`validateVRRPGroupChildrenAST15046`, pre-walk): any
  vrrp-group child not declared in the schema — read from the schema,
  not hardcoded — is strict-rejected / lenient-warned, across braced,
  flat-set, Keys-packed, and `track`-inner spellings. Deliberately not
  `closedWorld` on the group node (it inherits and cannot see
  Keys-packed runs). The #1814 track-shape gate now counts and
  range-validates the Junos spelling in the shared single-track slot.
- Ratchets: `track/interface` joins the armed census (#9091);
  Junos `priority-cost` (advisory, same class as
  `track-interface priority-cost`) joins the spelling-gate members
  and advisory ceiling (#7484). The two `no-preempt` flag rows were
  already recorded by #15047 and are not double-counted.
- Rebase note: since filing, #15047 landed the `Preempt=true`
  default plus a first `no-preempt` parse, and #15048 landed the
  strict track-interface declared-reference gate. Conflicts were
  resolved by keeping #15047's default and schema wording, keeping
  this change's `PreemptSet` marker on top, and retargeting test
  fixtures to declared interfaces (`reth1`, declared `ge-0/0/1`) so
  Junos-track groups pass the #15048 gate. The golden failure, the
  #15047 flat-set fixture failure, and the cross-group unit failure
  reproduce identically on pristine current master (base-attributed).

## Validation

- RED on origin/master: Junos track row compiled `Track=""/0`;
  `zzbogus` committed clean (probe test, pre-fix run).
- GREEN: `go test ./pkg/config/ -run 'TestVRRP(Junos|NoPreempt|UnknownChild|KnownChildren)'`
  passes (hierarchical/flat-set/inet6/Keys-packed Junos rows,
  no-preempt explicit + last-wins + unset controls, unknown-child
  strict/lenient in four spellings, duplicate and cost-range gates,
  known-children control, SchemaValidate acceptance, FormatSet
  round-trip).
- `TestCompileGolden4406` fails identically on pristine current
  master (intervening #15034/#15047/#15048 changes without a golden
  regen), so it is base-attributed, not a regression of this change.

## Risk

`PreemptSet` is a new exported field on `VRRPGroup` (JSON-marshalled
configs gain `"PreemptSet": false` where absent before). Runtime VRRP
behaviour is unchanged: `Preempt` semantics are identical, and the
Junos track spelling now reaches the existing tracked-interface
runtime that `track-interface` already used.
