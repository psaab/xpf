# #15053 — plain-text-password-value under root/login authentication is inert and disclosed (A20-05)

## Defect

`system root-authentication plain-text-password-value <v>` and
`system login user <u> authentication plain-text-password-value <v>` (and the
`plain-text-password` spelling) committed clean, were silently ignored by the
compiler (`compiler_system.go` has no case for them), and rendered in
cleartext on every redacted surface: `secretIndices` (`ast_redact.go`) had no
case for them, so `RedactedClone` (REST/gRPC `show configuration`) disclosed
the intended root/user password to every view-class reader while the
credential was never applied — root kept its old password or none, with zero
warnings.

## Fix

- `pkg/config/schema_system.go`: both authentication subtrees are now
  `closedWorld: true` (leaf-complete: only `encrypted-password` + `ssh-*`
  are valid Junos leaves there), and both plaintext spellings are modeled
  only so strict validation refuses them — see
  `pkg/config/schema_plain_password_15053.go` (`plainTextPasswordLeaf15053`,
  following the #7971 unimplemented-leaf pattern: a non-`ValueAny` typed leaf
  whose validator always rejects with a hint to use `encrypted-password`
  with a `$6$` crypt hash). Strict commit/commit-check rejects; the tolerant
  Load/SyncApply path downgrades schema violations to warnings (#1960), so a
  persisted or peer-synced config carrying the leaf does not brick the node,
  and the compiler still ignores it exactly as before.
- `pkg/config/ast_redact.go`: `plain-text-password` and
  `plain-text-password-value` added to the distinctive-secret case of
  `secretIndices`, so any tolerant tree carrying the leaf is masked with
  `##SECRET-DATA##` by `RedactedClone` on all render formats.
- `pkg/config/secret.go`: both spellings added to `secretLeafKeywords`, so
  commit-error and control-character diagnostics redact the value instead of
  echoing it (keeps `secretIndices` and `secretLeafKeywords` in agreement,
  #7395).
- `pkg/config/multi_leaf_absorption_population_9206_test.go`: census updated
  98/58 -> 110/64 — arming the two authentication subtrees brings their six
  `ssh-*` multi leaves inside a closed world. NOT changed: compiler behaviour
  for the plaintext leaves (still ignored on tolerant paths, deliberately —
  strict rejection is at the operator boundary), and no other `system`
  subtree's open-world posture.

## Tests

- `pkg/config/plain_password_15053_test.go`:
  - `TestPlainTextPasswordStrictRejects15053` — all four cells (both
    spellings x root/user) are rejected by `SchemaValidate` with an
    `encrypted-password` hint and without echoing the canary. RED pre-fix:
    `SchemaValidate` accepted every cell.
  - `TestPlainTextPasswordNeverInRedactedClone15053` — canary never appears
    in hierarchical/flat-set/JSON renders of `RedactedClone`. RED pre-fix:
    canary rendered in cleartext in all three formats.
  - `TestPlainTextPasswordControls15053` — legitimate neighbours
    (`encrypted-password` with a valid `$6$` hash, `ssh-ed25519`, `class`,
    `uid`) still validate clean.

## Validation

- `go test ./pkg/config/ -run 'TestPlainTextPassword|TestMultiLeafAbsorptionPopulation9206|TestBothSecretResolutionsAgree|TestSecretLeafKeywords'`
- Full `pkg/config` suite (see PR).

## Risk

- A stored config (pre-fix) containing the plaintext leaf now warns on
  tolerant load instead of silently loading; strict commit of such a config
  is refused until the operator replaces it with `encrypted-password`. That
  is the intended fail-closed posture: the leaf never took effect, so no
  working credential is lost.
