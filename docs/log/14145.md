# 14145 — classifier disagreement and load authorization

`ClassifyLoadContent` tokenized load bodies with its own scanner, and
that scanner disagreed with the real config lexer. The classifier reset
`inToken` on `[` and `]`, so in `set system host-name a[/*` it dropped
out of the token at `[` and read the following `/*` as a block-comment
opener. The real lexer does the opposite: `readIdentifier` consumes
`[`, `]`, `/` and `*` as ordinary identifier characters once a token has
begun (mid-token bracket at bracket depth 0 is literal, #8453), and its
comment openers are recognized only in the gap scanner between tokens.
On an unclosed fictitious comment the classifier errored and
`LoadMutationLines` mapped the error to `nil`, so `AuthorizeConfigLoad`
adjudicated zero lines and allowed a restricted `load set`; on a closed
fictitious comment the denied lines were blanked as comment prose and
again allowed. `Store.LoadSetAsPlantClass` compounded it by replaying
the raw lines without calling the classifier, applying exactly the
lines the gate had hidden from itself.

Fix: the classifier's token model now mirrors the real lexer — `[`/`]`
met mid-token leave `inToken` set (the token continues, so a following
`/*` is identifier text), while a bracket that begins a token stays
list sugar at a token boundary (so a following `/*` is still a genuine
comment). `LoadMutationLines` now returns `(lines, error)` and
`AuthorizeConfigLoad` refuses on a classifier error instead of
adjudicating an empty mutation set (fail-closed); hierarchical content
is parsed from the comment-free form so gate and store reach the same
statements. `LoadSetAsPlantClass` routes through the same shared
classifier (`config.ClassifyLoadContent`) as LoadMerge/LoadOverride
already did, so the store applies exactly the adjudicated
representation and refuses unclassifiable bodies atomically.
`LoadMutationLines` keeps exactly one declaration (the #9892 renderer
census); its test callers were migrated to the two-value form.

Regression (`pkg/config/authz_config_load_14145_test.go`, RED-verified
pre-fix: allowed/`nil` where denial is now required):
`TestLoadSetMidTokenBracketFakeCommentIsDenied14145` covers the issue's
decisive shape for `set` and `merge`, unclosed and `# */`-closed;
`TestLoadMutationLinesSeesPastMidTokenBracket14145` pins that the
denied line reaches the adjudicator;
`TestLoadWithUnterminatedCommentIsDenied14145` pins fail-closed on a
genuine unterminated comment; allowed-body controls (real comments,
mid-token bracket values, slashes inside tokens, comments between
tokens, bracket-boundary comments) pin narrowness. Store side
(`pkg/configstore/loadset_classifier_14145_test.go`): the store applies
the classifier-visible body including the mid-token bracket value,
refuses an unterminated comment with the candidate byte-identical, and
still skips genuine comment prose.

Validation: `go test ./pkg/config/ -run '14145|9892|10305|10734'`
passes (RED pre-fix on the five new denial/classifier cells);
`go test ./pkg/configstore/ -run '14145|5187|10305'` passes; full
`pkg/config`, `pkg/configstore` and dependent `pkg/cli`, `pkg/api`,
`pkg/grpcapi` suites run before the PR.

Risk: `load set` bodies that relied on the old raw replay to silently
ignore `/* ... */` prose spanning lines, or to partially apply a body
with an unterminated comment (earlier lines landed before the failure),
now fail with a parse error and apply nothing — the same contract
`load merge`/`load override` already had. No verb, regex, or class
semantics changed.
