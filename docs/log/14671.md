# #14671 — same-allocator address-only source-NAT admission ignores idle persistent leases

## Defect

The three same-allocator address-only admission paths in
`userspace-dp/src/nat/allocator.rs` consulted only LIVE ownership:

- `reserve_address_only_persistent` (fresh + pinned arms): `address_only_owners` + `pat_owns_wire_identity`
- `reserve_address_only_roundrobin`: same
- `reserve_address_only_maybe_persistent` (synced, via `reserve_address_only`): same

None consulted the idle persistent address-only lease index
(`persistent_address_only_owner_counts`, maintained for imported-lease
contention by #11496). After subscriber H1's only flow releases, its
address-only persistent lease stays idle for its 300 s timeout:
`persistent_by_translated` still maps `(proto, A1, P) -> H1` and
`persistent_inbound_lookup` permits inbound from the recorded remote.
A second subscriber H2 with the same preserved source port to the same
remote was then minted the same `(A1, P)`. `persistent_by_translated`
held two source keys for one wire identity and
`persistent_inbound_lookup` returned `Denied` for both — an
availability blackhole for inbound persistent-NAT traffic, fail-closed
(not a hijack).

PAT, deterministic, peer-pool and idle-import paths already consulted
`address_only_owns_wire_identity`; only the same-allocator
address-only paths did not.

## Fix

`userspace-dp/src/nat/allocator.rs`:

- New `PortAllocatorLiveState::persistent_address_only_contended_except(flow, translated, candidate_key)`:
  true when a DIFFERENT address-only persistent lease (live or idle,
  not revoked) holds `translated` and its recorded permit grants
  (`PersistentPermissions::permits`, unscoped union across egress
  scopes — admission has no single egress scope here, matching the
  Any/Host/Exact owner-key semantics) cover the candidate flow's
  remote endpoint. Leases with no recorded grants fall back to the
  `persistent_by_translated` index (grant-less leases block, as the
  base `Any` owner key does). The candidate's own lease never blocks
  its rejoin.
- All three admission paths now refuse (or, for round-robin/fresh
  persistent, probe the next pool address) when the helper reports
  contention, alongside the existing live-token and PAT checks.
  Deliberately NOT used: `address_only_owns_wire_identity`, whose
  persistent-owner counts include the unconditional `Any(base)` key
  inserted for every address-only lease — it would block a same-port
  flow to an unpermitted remote and the subscriber's own lease
  rejoin (controls below pin both).

NOT changed: `persistent_inbound_lookup` (its Denied on true
contention is correct fail-closed behaviour), PAT/deterministic/
import paths (already guarded), lease lifecycle/GC.

## Validation

New tests in `userspace-dp/src/nat/tests_addr_only_persistent_idle_14671.rs`
(registered in `nat/mod.rs`):

- `idle_persistent_address_only_blocks_duplicate_wire_single_addr_14671` —
  decisive cell: single-address pool, H1 idle after release, H2 same
  port/same remote must be refused; H1 inbound stays Permitted.
  RED on pre-fix master: H2 was minted `(203.0.113.1, 4000)`.
- `idle_persistent_address_only_blocks_duplicate_wire_persistent_14671` —
  two-address pool: H2 gets a distinct tuple or refusal; H1 inbound
  stays Permitted(H1), not Denied.
- `idle_persistent_address_only_blocks_roundrobin_and_synced_14671` —
  `reserve_address_only_roundrobin` and synced `reserve_address_only`
  refuse the idle identity on a single-address pool. RED pre-fix:
  roundrobin returned `Ok((203.0.113.1, 4000))`.
- `idle_persistent_address_only_controls_stay_admissible_14671` —
  controls: different preserved port admissible; same port to a remote
  the idle `TargetHostPort` lease does not permit admissible; same
  subscriber rejoins its own idle lease with the same tuple.
RED evidence (pre-fix, base `a801922911`): 2 failed / 2 passed —
single-address and roundrobin/synced cells failed as above.
GREEN after fix: 4 passed. Full `nat::` module suite: 667 passed,
0 failed, 1 ignored (includes the #9131 sibling-fallback cells, which
pin that a LIVE lease's broad grants must not block flows to remotes
it holds no live token for — the helper therefore contends only on
idle leases, live contention staying with the exact live-token check).

## Risk

- Behaviour delta: a second subscriber whose preserved port collides
  with an idle persistent lease's permitted remote is now refused (or
  rotated to a sibling pool address) for up to the lease's idle
  timeout instead of silently blackholing both. This is the Junos
  persistent-NAT capacity posture and matches the PAT-path precedent.
- The contender scan is O(leases on this allocator) per address-only
  admission probe — the same order as existing lease-table work on
  this cold path; no per-packet cost.
