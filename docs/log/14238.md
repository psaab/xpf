# #14238 — Pin stage-9 stamp → `fabric_ingress_ifindex` population

## Why

PR #14099 (#13967) made `ba_ingress_trust_for_packet` prefer
`meta.fabric_ingress_ifindex`, populated only by stage 9
(`stage_classify_fabric_ingress`) from a validated V2 stamp
(`ZoneEncodedFabricStamp::ValidScoped`). Its sole regression
(`fabric_scoped_ingress_preserves_ba_queue_and_rewrite_across_selection_paths_13967`)
hand-constructs `UserspaceDpMeta { fabric_ingress_ifindex: 999, .. }` and
calls the selection functions directly. No test drove
`stage_classify_fabric_ingress` / `parse_zone_encoded_fabric_ingress_from_frame`
producing the field from an actual V2-stamped frame, nor pinned that V1
`Valid`, `Absent`, and `Invalid` stamps leave it 0. If stage 9 stopped
populating the field (or populated it from an unvalidated stamp), every
merged regression would still pass while peer BA parity silently reverted
to the zone-only fallback — or unvalidated trust were admitted.

## What

- `userspace-dp/src/afxdp/poll_stages_tests.rs`: new test
  `stage9_fabric_ingress_populates_scoped_ifindex_only_from_validated_v2_stamp_14238`.
  It builds the `nat_snapshot_with_fabric` forwarding state, mints a V2
  stamp with the production producer helper
  (`resolve_fabric_redirect_for_ingress_identity` for the LAN ingress
  identity, logical ifindex 24), and drives `stage_classify_fabric_ingress`
  (via the existing `with_neighbor_learn_ctx` harness, empty `ha_state` so
  the claimed zone's RG is peer-owned) asserting:
  - validated V2: `meta.fabric_ingress_ifindex == 24` (the scope identity's
    logical ifindex), zone override + `ingress_nat_scope_ifindex` set,
    `FABRIC_INGRESS_FLAG` set, not invalid;
  - V1 `Valid` (same zone): field stays 0, zone override set, no scope;
  - `Absent` (ordinary source MAC): field 0, no override, not invalid;
  - `Invalid` (V2 marker with unknown scope id `0xffffff`): field 0,
    `invalid_zone_stamp == true` — fail-closed.
  Precondition asserts pin that the fixture's scope identity exists and
  resolves to ifindex 24 / `TEST_LAN_ZONE_ID`, so the positive cell cannot
  be vacuous.
- Existing #13967 selection-path regression untouched. No production code
  changed.

## Validation

- GREEN: `cargo test --bin xpf-userspace-dp stage9_fabric` — new test ok;
  `fabric_scoped_ingress_preserves_ba_queue_and_rewrite_across_selection_paths_13967`
  still ok.
- RED (semantic, mutation in the fix worktree, restored after): replacing
  stage 9's `meta.fabric_ingress_ifindex = ingress_nat_scope_ifindex...`
  with `= 0` makes the new test FAIL at the V2 assertion
  (`poll_stages_tests.rs:6069`); making the V1 `Valid` arm yield
  `Some(4242)` makes it FAIL at the V1 assertion (`:6088`). Both mutations
  reverted; `git diff` shows only the test file.
- `rustfmt --edition 2024 --check` on the touched file: no diffs in the
  new code (pre-existing diffs elsewhere in the file are untouched).

## Risk

- Test-only change; no production behavior delta. The test depends on the
  `nat_snapshot_with_fabric` fixture's deterministic scope-id derivation —
  pinned by precondition asserts that fail loudly if the fixture drifts.
