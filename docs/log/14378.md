# #14378 — Static next-hop `ip@interface` / `@interface` split

## Mechanism (re-anchored at origin/master 2b6268063)

- Validator `ValidateStaticNextHop` (pkg/config/schema_validators_routing.go:431)
  accepts `10.0.0.1@eth0` and `@eth0`.
- Compiler `staticNextHopEntry` (pkg/config/compiler_routing.go:266-271)
  never splits scalar `@`: stores `Address: "10.0.0.1@eth0"` / `"@eth0"`.
  Comment even says "IP and ip@interface values remain address-form".
- FRR `generateStaticRouteInTable` (pkg/frr/config_render.go:526-528)
  drops any `nh.Address` failing `validFRRNextHopAddress` (netip.ParseAddr)
  — `@` fails → silent `continue`, no route line.
- Userspace snapshot (pkg/dataplane/userspace/routes.go:380-385) emits
  `Address` verbatim when Interface empty, so `"10.0.0.1@eth0"` string is
  installed; `routeNextHopMeaningOf` (:1389) splits `@` and installs with
  interface. Two FIBs disagree.

## Fix choice: option (a) split in compiler (spec-recommended)

Preserves validator contract + userspace behaviour; FRR structured form
`Address+Interface` already renders `ip route <dst> <ip> <iface>`
(config_render.go:534-535). No validator/renderer/userspace change.

## Bypass paths to cover (caveat in spec)

`NextHopEntry{Address:}` constructions in compiler_routing.go:
1. `staticNextHopEntry` (plain next-hop, both inline :834 and hier :956) — main fix.
2. Fully-inline QNH :844 `NextHopEntry{Address: Keys[i]}` then modifiers — bypasses staticNextHopEntry.
3. Hierarchical QNH :979-980 `nh.Address = nodeVal(prop)` — bypasses.
QNH paths go through `mergeQualifiedNextHop12308` + `finalizeQualifiedNextHops12308`.
Finalize already promotes interface-only QNH gateways. Cleanest: split `@`
in finalize for qualified entries (after merge, so split statements for same
gateway still merge on raw scalar — but note: if one stmt is `10.0.0.1@eth0`
and another is `10.0.0.1` with preference, they have different Address keys
pre-split and would NOT merge; that is arguably correct—different interface
scope—or edge. Alternative: split at QNH construction sites (2+3) before merge.
Splitting at construction: `10.0.0.1@eth0` -> Address 10.0.0.1 Interface eth0;
then a later `interface` modifier overwrites Interface (authoritative structured
modifier wins) — reasonable. `@eth0` -> Interface eth0, Address "".
But merge key: two stmts `qualified-next-hop 10.0.0.1@eth0` and
`qualified-next-hop 10.0.0.1 preference 250` would then have same Address
10.0.0.1 and merge, second not authoring interface so keeps eth0 — plausible.
If split only in finalize, they'd stay separate entries (duplicate gateway diff iface).
Construction split is more consistent. For plain path, staticNextHopEntry split.

Also check structured explicit iface precedence: `staticNextHopEntry(raw, iface)`
with iface!="" must NOT split (spec: iface != "" path untouched). E.g.
`next-hop 10.0.0.1@eth0 interface ge-0/0/1.0` — explicit wins, but then Address
retains @... validator? The gateway token validated, structured iface separate.
If we leave Address raw, FRR still drops. Hmm. But spec says iface!="" untouched.
Consider: when iface explicitly given, dropping @ part? That would be changing.
Probably such double-spec config is contradictory; keep spec: only split when iface=="".
For QNH: if nh already has Interface from modifier and Address contains @,
finalize/construction... At construction, modifiers parsed after Address assignment,
so split-if-no-interface check cannot be done at assignment time. Do split in
finalize for qualified entries respecting existing Interface: if Interface=="" split;
if Interface!="" and Address contains @, strip @suffix? Need decide.

Simpler unified approach: helper `splitAtNextHop(raw) (addr, iface, hasAt)` and:
- staticNextHopEntry: if iface=="" and hasAt -> split (empty ip -> interface-only).
- finalizeQualifiedNextHops12308: for qualified entries, if Address contains @:
  split; if entry.Interface=="" set to ifPart; Address=ipPart (may become ""

## Implementation
- `splitAtNextHopValue` (compiler_routing.go): validator-mirroring split;
  malformed '@' (empty/implausible iface, bad IP) returns ok=false so
  tolerant raw scalars keep prior FRR-belt drop behaviour.
- `staticNextHopEntry`: split only when no explicit structured iface.
- `finalizeQualifiedNextHops12308`: QNH bypass paths (inline :872 and
  hierarchical :1007 constructions) split at merge-window close; authored
  structured interface stays authoritative, '@' suffix stripped.
  All route lists reach finalize via canonicalizeStaticRoutesAcrossTables
  (global + every routing instance).
- Validator, FRR renderer belt, userspace splitter unchanged per spec.
