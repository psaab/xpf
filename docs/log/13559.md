# Issue #13559: DHCPv6 invalidation teardown notifications

## Why

When a DHCPv6 RENEW or REBIND explicitly invalidates its held IA_NA
address, the run loop deleted the lease and delegated prefixes but omitted
the same notifications used for lease expiry. The gateway overlay and
compiled DHCP routes / RA prefix could therefore remain stale after the
server withdrew the address.

## What

Route both explicit-invalidation branches through `abandonLeaseAfterExpiry`,
then clear the run-loop committed lease, committed delegated prefixes, and
expiry-pending state before re-acquiring. This performs identity-checked
lease/PD removal and invokes the gateway-change and recompile hooks outside
the manager lock. Regression tests cover both RENEW and REBIND invalidation
and check that the lease/PDs are gone, the gateway hook fired, and recompile
was scheduled.

## Validation

The new RENEW and REBIND regressions failed on pristine master: both reported
no additional gateway-change hook and no armed recompile after invalidation.
`GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/var/worktrees/.cache/go-tmp
go test ./pkg/dhcp -count=1` passed. `go vet ./pkg/dhcp` passed, and
`gofmt -l pkg/dhcp/dhcpv6.go
pkg/dhcp/dhcpv6_invalidate_teardown_13559_test.go` produced no output.

## Risk

The invalidation behavior remains deconfigure-and-reacquire; transient absent
IA_NA replies retain their existing keep-and-retry behavior. The teardown now
uses the same lease identity guard and notification path as expiry.
