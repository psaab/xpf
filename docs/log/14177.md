## Why

Two independent feed defects (deep-review D8-08). (1) `feedDestinationBlocked`
relied on stdlib `IsGlobalUnicast`/`IsPrivate`, which classify IPv6
transition addresses as global: NAT64 `64:ff9b::/96` (embedded IPv4 can name
169.254.169.254 / 10.0.0.1), NAT64 local-use, 6to4 `2002::/16`, Teredo inside
`2001::/23`, discard/dummy/SRv6/documentation ranges all passed, so a feed
hostname resolving to a translator address would be dialled to an internal
target — conditional SSRF. (2) `Manager.Apply` built per-feed URLs by string
concatenation `baseURL + path`; a documented query-bearing base
(`https://feed.example/base?token=abc`, feeds README #7406) became
`.../base?token=abc/malware.txt` — path `/base`, mangled token, feed never
fetched.

## What

- `pkg/feeds/feeds.go`: extend `blockedFeedDestinationPrefixes` with the IPv6
  special-purpose set mirroring `specialPurposeV6` in `pkg/ddns/checkip.go`
  (64:ff9b::/96, 64:ff9b:1::/48, 100::/64, 100:0:0:1::/64, 2001::/23 incl.
  Teredo, 2001:db8::/32, 2002::/16, 3fff::/20, 5f00::/16, fc00::/7). The
  explicit lab allowlist (`SetPrivateFeedAllowlist`) still overrides, as for
  IPv4. NOT changed: compiler strict gate — it already accepts well-formed
  query URLs, which are now joined correctly at runtime; the defect was the
  runtime join, not validation.
- Add `joinFeedURL(base, path)`: parses both, appends the per-feed path to
  the base path (preserving pre-existing query-free concatenation semantics),
  drops any scheme/authority in the path so it cannot escape the origin, a
  path-carried query supersedes the base query, otherwise the base query is
  inherited; parse failure returns the base unchanged (fail-closed via
  readFeed / strict gate). `Apply` uses it for every FeedEntry.
- Regression `pkg/feeds/feed_url_join_transition_14177_test.go`: destination
  table (transition blocked, public allowed), controlled-resolver NAT64
  refusal through `readFeed` (no live traffic), join table, and an
  httptest-handler Apply test asserting path `/base/malware.txt` + token.

## Validation

- RED on pristine `origin/master` (805ac16cd, separate base worktree with a
  master-behaviour concatenation stub so assertions, not the compiler,
  fail): NAT64/6to4/Teredo/etc. "was NOT blocked"; NAT64 fetch dials instead
  of refusing; joined URL `.../base?token=abc/malware.txt`.
- GREEN with fix: all four tests pass.
- Full package: `go test ./pkg/feeds/ -count=1` passes; `go vet` clean;
  `go test ./pkg/config/ -run 'TestFeedServer|TestValidateDynamicAddress|TestDynamicAddress'`
  passes.

## Risk

- A feed intentionally served from a NAT64/6to4-translated public server is
  now refused unless the lab allowlist covers it — the intended fail-closed
  direction, matching the existing private-destination policy.
- Per-feed path query superseding the base query is a deliberate, documented
  choice (the #7406 shape puts the token on the path leaf); query-free and
  query-on-base-only configs are unchanged in effect except the path now
  lands before the query as operators expect.
