## Channels

Not a config-channel defect. Every corpus config is operator-committable and
compiles on strict `config.CompileConfig`. The two things compared are the
`show security match-policies` simulator (`policymatch.Match`, fed by
`config.CompileConfig`) and the enforcer (`userspace-dp/src/policy.rs`, fed by the
`ConfigSnapshot` JSON the Go control plane puts on the wire).

## The issue's account of the mechanism, corrected

The issue names three sub-verdicts that call `pkg/dataplane/userspace` helpers
(`RuntimePolicyIDs`, `ClassifyHostInboundForInterface`,
`PolicyContentRejectionReasons`) as an oracle that cannot disagree with the
implementation. Those calls share code with the Go WRITE path, and that sharing is
correct: the simulator must report what the write path computes. The gap is one
layer out: the write path and the simulator are both mirrors of `policy.rs`, and
nothing compared either one to the enforcer. The measurement is #6505's file list:
`policy.rs`, `policy_snapshot_error.rs`, `policy_tests.rs`, `_Log.md`,
`docs/feature-gaps.md`, no Go at all. The simulator kept reporting PERMIT for a
host-bound fragment the box drops until #6576 wrote a second hand mirror.

**Shared root with #9410** (merged `c31b248ae`): that fix added a Go-side mirror of
the enforcer's zone-resolution fail-closed rule, which is the mechanism this issue
says drifts. The corpus does NOT carry a row for #9410's arm: an unresolvable zone
is reachable only through `CompileConfigLenient`, and corpus configs compile strict.

## Production cannot emit `null` for these slices — measured

The first generated fixture carried `"address_books": null` and the Rust decoder
refused it. Before touching the fixture, the producer was measured:
`ConfigSnapshot.Zones`, `.Policies` and `.AddressBooks` are `,omitempty`, as is
every slice field of `PolicyRuleSnapshot`, `AddressBookSnapshot` and
`ZoneSnapshot`, and the Rust decoder marks each `#[serde(default)]`. Production
sends an ABSENT key, never `null`, so neither the decoder nor the producer needed a
change. The `null` came from the generator's own wrapper, which lacked
`,omitempty`. Normalising `nil` to `[]` there (the first attempt, withdrawn) would
have made the fixture more well-formed than production and could hide the very
mismatch this differential exists to catch. The wrapper now carries the same tags,
pinned to `ConfigSnapshot`'s by reflection. The null-tolerant class does exist in
the tree (#2214 `null_tolerant_vec`, for NAT64 `pool_addresses` and filter `terms`,
which carry no `,omitempty`); none of those fields is in this snapshot.

## Honest bound

The snapshot handed to Rust is built by Go's snapshot BUILDER, so the builder is
shared input. That is not a blind spot for the tier walk, because the simulator
reads the config rather than the snapshot, so a builder that drops or mangles a rule
makes the halves disagree. What stays invisible is a builder defect that the
expectation column was ALSO written to match, which is why the column is authored
from the Junos semantics rather than transcribed from a run.
