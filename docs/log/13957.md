# Issue #13957: Allow IPv4 tunnel outers to fragment downstream

## Why

Native GRE and userspace WireGuard outer IPv4 headers carried DF=1, but the
userspace tunnel endpoints do not consume ICMP Frag-Needed feedback and learn
an underlay path MTU. If a downstream path is smaller than the local egress,
large packets are silently lost. The local egress MTU guard cannot detect this
path-only reduction.

## What

GRE and WireGuard now build IPv4 tunnel outers with DF clear, allowing an
underlay router to fragment when necessary. The new header writer assigns an
advancing IPv4 Identification and recomputes the header checksum. IPv6 outer
headers and generated ICMP headers are unchanged. No PMTU cache, reassembly,
configuration knob, or additional packet allocation was introduced.

`cargo check --bin xpf-userspace-dp` passed. Both new end-to-end DF-clear
regressions failed before the fix (GRE and WireGuard each observed `DF=1`)
and passed after it. Full focused suites passed:

- `cargo test --bin xpf-userspace-dp afxdp::frame::headers::tests::` — 27 passed.
- `cargo test --bin xpf-userspace-dp afxdp::frame::tests_nat_rewrite::` — 35 passed.
- `cargo test --bin xpf-userspace-dp afxdp::frame::wg::tests::` — 27 passed.

The full binary test suite was attempted but did not pass. Pristine master has
an unrelated test compile error at `coordinator/tests.rs:11773`
(`maps.local.insert(inner_dst)` supplies `IpAddr` where `(u32, IpAddr)` is
required); the fixture was corrected temporarily in the worktree to execute
tests, then reverted. The resulting full run exposed additional failures
outside the tunnel/header tests, so the full-suite status remains red.

## Risk

IPv4 tunnel outers may be fragmented by intermediate routers; this matches
kernel WireGuard's fragmentation behavior. IPv6 outer packets remain subject
to IPv6 Packet Too Big behavior and are not changed here. A two-hop underlay
lab verification with reduced path MTU remains outstanding.
