# Issue #12076 — resolve routing-instance table names by configured table ID

## Why

`show route table <ri>.inet.0` and `test routing ... instance <ri>` treated every non-main routing instance as a Linux VRF device named `vrf-<ri>`. An `instance-type forwarding` routing instance has a configured kernel table ID but deliberately has no VRF device, so both reads failed with `VRF "<ri>" not found` even when its table contained routes.

## What

Route reads now resolve a configured routing-instance name to its positive `TableID` before trying the legacy VRF-device lookup. `GetTableRoutes` and a new `GetInstanceRoutes` path receive configured instances; CLI route-table display and CLI/gRPC test-routing lookups pass the active config, and gRPC route-table display passes its request config. Instances without a configured table ID retain VRF lookup behavior.
