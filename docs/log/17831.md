# Issue 17831 — pending interrupt aborts before persisted journal read (cutover.go)

- **Timestamp:** 2026-10-27
- **Action:** Retro-finding on merged PR #17599 (astra lane F1, MED). `Runner.Run`'s entry-time #16796 check consulted `SignalGuard.MayAbort` with `stopAttempted` seeded only from `opts.UnitAlreadyStopped`, before the persisted journal was loaded. A signal captured during pre-Run CLI work (`cmd/xpfd/upgrade.go` installs the guard for the whole verb and calls `Run` with only `SignalGuard`) therefore aborted a STOPPED/ROLLINGBACK resume with "aborted … before STOP; the daemon was not stopped" while the unit sat down — the resume neither finished START nor rolled back, and the correct post-journal defer predicate was unreachable. Fix: removed the entry-time abort; the journal-backed post-journal boundary (which classifies `StateRollingBack`/`StateStopped`+ from the persisted journal, read under the upgrade lock after the cluster gate) is now the ONLY pre-STOP abort point. A signal pending at entry on a fresh/pre-STOP journal still aborts there before any phase runs; on a STOPPED/ROLLINGBACK resume it defers and the run completes START/rollback before honouring it. `RollbackTo` already used this journal-aware shape; `Run` now matches it.
- **File(s):** `pkg/upgrade/cutover.go` (entry check removed, boundary comment updated, gofmt of a pre-existing double blank line), `pkg/upgrade/signal_defer_17831_test.go` (new).
- **Validation:** `go test ./pkg/upgrade/ -run 17831` — GREEN on fix; fail-on-revert RED (cutover.go change stashed, tests kept): `TestRunnerSignalPendingAtEntryStoppedJournalDefers17831` FAIL and `TestRunnerSignalPendingAtEntryRollingBackJournalDefers17831` FAIL with the exact defect message `upgrade: aborted by terminated before STOP; the daemon was not stopped (#16796)`; control `TestRunnerSignalPendingAtEntryPreStopJournalStillAborts17831` PASSes both with and without the fix (pre-STOP abort preserved). Full `go test ./pkg/upgrade/ -count=1` green at head 6bcba3d2e2 + change. All tests hermetic (fakeSystem, class U); run unprivileged.
- **Risk:** Low. The only behavior change: an entry-pending signal no longer pre-empts the cluster-gate refusal / lock acquisition / journal-parse errors (those now surface first — both fail-closed, unit untouched), and a fresh-cut abort now happens after lock acquisition + `beginStatusGeneration` (durable fence advance on every locked invocation by design) instead of before any work. Rolling driver semantics unchanged: its inner-cut pre-STOP abort still yields `cutBeforeStopError` via the same defer wrap, so failback classification is identical.
