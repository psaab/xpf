# #14824 — TestWebMgmtRebindsOnAddressReplacement14582 racy stale-close assert

## Defect
`TestWebMgmtRebindsOnAddressReplacement14582`
(`pkg/daemon/webmgmt_rebind_14582_test.go`) asserted synchronously,
immediately after `reassertMgmtListenersOnce`, that the stale
`10.0.0.1:443` fake listener was closed. Listener retirement is
asynchronous by design: `stopLegLocked` (`pkg/api/listener.go`) only
pins the leg's auth slot and closes its `stopCh`; the serve goroutine
then drains in the background (`drainLeg`, up to `legDrainTimeout`)
before `http.Server.Shutdown` closes the socket. The synchronous
`isOpen()` check therefore raced the drain goroutine.

## Fix
Test-only. Capture the stale listener before the tick (asserting it is
open, so the cell cannot pass vacuously if setup never bound it),
keep the post-tick Listening/`10.0.0.9:443` assertions, and replace the
synchronous stale-close assert with the existing `waitClosed` helper
(`management_5866_test.go`, 3s deadline, 5ms poll) — the same pattern
every other retired-leg cell in the package already uses.

## Tests
- RED/GREEN note: on this head the original synchronous assert is
  timing-dependent — it passed 1/1 in an isolated re-run under load
  (the drain goroutine won the race) while the issue reports 3/3
  failures on merged master; the race is in the assertion, not the
  production path. The fix removes the race structurally: `waitClosed`
  fails only if the socket never closes within 3s.
- Fail-on-revert: reverting (removing the `stopLegLocked` retirement
  of the old leg) leaves the stale socket open, so `waitClosed` times
  out and the cell reds — coverage is not test-only-green.
