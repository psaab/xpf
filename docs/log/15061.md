- **Timestamp**: 2026-10-18
  - **Action**: #15061 (A37-02) — a standalone `vrrp-group` VIP was
    foreign to systemd-networkd and stripped by xpf's own reconfigure
    while VRRP stayed MASTER. `pkg/vrrp.CollectInstances` builds an
    instance from any unit's `VRRPGroups` and `becomeMaster` installs
    each VIP as a genuine kernel address, but
    `pkg/dataplane buildInterfaceNetworkdModels` set `KeepAddresses`
    only for VRRP-backed RETH rows (`isVRRPReth`, which requires a
    redundant-parent), so a plain interface carrying
    `vrrp-group 1 virtual-address 10.0.1.1` rendered no static keep.
    `pkg/vrrp.ReconcileVIPs` has one production caller gated on a RETH
    link cycle, so nothing re-added the VIP: the elected MASTER kept
    advertising from its real address, the BACKUP never took over, and
    hosts lost the gateway. A second, latent gap made `KeepAddresses`
    alone insufficient: `pkg/networkd keepConfigurationValue` required
    a rendered `Address=` line for the static class, which a foreign
    VIP never has. Fix: `pkg/dataplane` helpers
    `unitCarriesStandaloneVRRP` / `interfaceCarriesStandaloneVRRP`
    (new `compiler_iface_vrrp_keep.go`) report a unit carrying a group
    with at least one virtual address; the non-VLAN, VLAN
    sub-interface, and VLAN-parent arms compose it with the RETH keep
    (`(isVRRPReth || standalone) && !disabled`, parent:
    `len(parentAddrs) > 0 || standalone`) and set the new
    `networkd.InterfaceConfig.KeepForeignStatic`, which
    `keepConfigurationValue` treats as the static class (composing to
    `yes` with a DHCP lease). Groups with no virtual address,
    unit-disabled units, and plain rows keep neither flag.
    Regression tests: `pkg/dataplane/standalone_vrrp_keep_15061_test.go`
    (model rows report `KeepAddresses`/`KeepForeignStatic` for
    non-VLAN, tagged, and untagged-parent standalone shapes; plain /
    empty-VIP / disabled controls carry neither) and
    `pkg/networkd/standalone_vrrp_keep_15061_test.go` (foreign-only →
    `static`, foreign+DHCP → `yes`, rendered-static and no-keep
    controls unchanged). The issue's netns `vr` criterion (keep
    10.0.1.1/32 after reconfigure) remains operator/lab verification.
