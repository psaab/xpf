# Issue #12047 — reject redundant leading-zero CIDR masks

- **Timestamp**: 2026-10-03
- **Change**: Strict compilation rejects valid Go CIDRs whose prefix masks contain redundant leading-zero digits, for both inline policy literals and global or zone-local address-book entries. Tolerant loads warn, and `PolicyContentRejectionReasons` prevents snapshots retaining the raw spelling from being published to the userspace helper. Canonical decimal masks remain accepted.
- **Files**: `pkg/config/cidr_mask_ipnet.go`, `pkg/config/compiler_validate_strict_addrbook_mask.go`, `pkg/config/compiler_validate_strict_policy.go`, `pkg/config/compiler_earlystrict.go`, `pkg/config/compiler_opts.go`, `pkg/dataplane/userspace/policies_reject.go`, `pkg/config/cidr_mask_leading_zeros_12047_test.go`, `pkg/dataplane/userspace/policies_cidr_mask_12047_test.go`.
- **Validation**: `go build ./pkg/config ./pkg/dataplane/userspace` passed. The complete issue regression files passed five runs: `go test ./pkg/config/ -run 'TestCIDRMask' -count=5` and `go test ./pkg/dataplane/userspace/ -run 'TestPolicySnapshot' -count=5`.
