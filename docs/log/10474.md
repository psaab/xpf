# Issue #10474 — NAT-T forceencaps rejected by strongSwan 6

## Scope

`pkg/ipsec/policy.go` generated both `encap = yes` and the legacy
`forceencaps = yes` line for `nat-traversal force`. The renderer writes
`swanctl.conf`, so `forceencaps` is the wrong configuration-backend keyword;
strongSwan 6.0.1 rejects it and discards the forced-NAT-T connection.

The fix **drops** `forceencaps`; it does not version-gate it. `encap = yes` is
the swanctl-native force mechanism. This preserves the force contract without
requiring runtime version detection. Compatibility evidence:

- The upstream strongSwan [*Migration from ipsec.conf to swanctl.conf*](https://wiki.strongswan.org/projects/strongswan/wiki/Fromipsecconf)
  table maps `forceencaps=no|yes` to `connections.<conn>.encap=no|yes`.
- The upstream [`swanctl.conf` reference](https://docs.strongswan.org/docs/latest/swanctl/swanctlConf.html)
  documents `connections.<conn>.encap` as the setting that fakes NAT
  detection and enforces UDP encapsulation.
- The upstream [strongSwan 5.2.0 `swanctl.opt`](https://raw.githubusercontent.com/strongswan/strongswan/5.2.0/src/swanctl/swanctl.opt)
  documents `connections.<conn>.encap`; the corresponding [VICI parser
  rule](https://github.com/strongswan/strongswan/blob/5.2.0/src/libcharon/plugins/vici/vici_config.c#L1291)
  accepts it as `{ "encap", parse_bool, &peer->encap }`. This pins the
  swanctl/VICI compatibility floor at strongSwan 5.2.0.
- The native key is therefore available well before the repository's deployed
  strongSwan 6.0.5 fixture environment. No older swanctl version supported by
  this repository is known to require the legacy starter keyword, and xpf
  invokes `swanctl`, not `ipsec`/starter.

No live-cluster or lab work was used. `swanctl`, `ipsec`, and `strongswan` are
not installed in this hermetic workstation, so no parser load was attempted.

permanent regression assertion remains in `pkg/ipsec/ipsec_test.go`.

## Implementation

- `pkg/ipsec/policy.go`: the `nat-traversal force` branch emits only
  `encap = yes`; the comment records why `forceencaps` must not be emitted.
- `pkg/ipsec/ipsec_test.go`: pins the corrected forced-NAT-T render and keeps
  the existing mode coverage.
- `docs/config-schema.md`: updates the renderer mapping and records the
  swanctl/starter distinction.
