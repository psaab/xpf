# Issue #12533 — scoped per-client IA_PD pin mechanism

- **Timestamp**: 2026-10-24
- **Action**: Added the explicit pin mechanism the #10856 guard deferred.
  Config: `interfaces <if> unit <n> family inet6 dhcpv6-client
  prefix-delegating pinned-prefix <ipv6-prefix>` (multi leaf,
  `ValidateIPv6CIDR`). Compiled into `DHCPv6ClientConfig.PinnedPrefixes`
  masked/sorted/deduped, so `ConfigFingerprint` changes iff pins change
  (golden `golden_4406.json` gains only `Pinned`/`PinnedPrefixes: null`).
  Semantics: exact/covering only — a delegation is exempt iff a pin on
  THE SAME client contains or equals it (`config.PinnedDelegatedPrefixCovers`);
  a narrower pin never authorizes a wider delegation, disjoint/other-client
  pins authorize nothing. Pins are in the DHCPv6 client fingerprint, so
  adding/removing a pin restarts that client and the next exchange
  re-decodes against the new set.
  Provenance: `DelegatedPrefix.Pinned` (separate from `RAPrefix.Delegated`)
  is set only when a pin was the reason for acceptance, carried through
  `reconcileDelegatedPDs` (compared in `delegatedPrefixesChanged`) into
  `buildRAConfigs` (`RAPrefix.Pinned` + per-RA-interface
  `RAInterfaceConfig.PinnedPrefixes`, union of that interface's PD clients).
  Decoder (`extractDelegatedPrefixesPinned`): covered delegations bypass
  class + configured-overlap refusals; degenerate-mask refusal never
  bypassed; valid-lifetime-0 covered prefixes still withdraw, uncovered
  refused prefixes are never synthesized into withdrawals. RA sink:
  only `Delegated && Pinned && covered-by-this-RA's-pins` bypasses the
  same refusals (both lifetime branches); `configEqual` treats `Pinned`
  and the pin set as wire-affecting. Unpinned behavior is unchanged.
  Renewal/removal: renewals re-validate against current pins/protected
  set; removing a pin restarts the client, the re-decoded delegation is
  refused, and a PD-only reply with nothing usable fails so the held set
  clears via the existing pdRefused path. IA_NA selection is unchanged
  (pins scope to IA_PD only).
  Migration: no config exists to migrate — deployments that were refused
  ULA/overlap delegations gain them only by adding an explicit
  `pinned-prefix` covering the delegated space on the WAN client that
  receives it; all other deployments see no change.
