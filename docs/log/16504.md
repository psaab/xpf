# #16504: RST teardown drain dropped scratch capacities and collected per batch

- **Timestamp**: 2026-10-24
- **Action**: #15947 (H29-01) left `poll_binding` taking
  `scratch_rst_teardowns`, building `rst_trigger_keeps` with a per-batch
  `collect`, draining, and dropping both `Vec`s, so every later RX batch
  carrying an accepted RST with `rst-invalidate-session` set reallocated
  both buffers from capacity 0. Extracted the drain into
  `drain_rst_teardowns` in `worker/lifecycle.rs` (mirroring the
  `drain_revoked_flow_cache_keys` take/drain/restore pattern), added the
  pre-sized reusable `scratch_rst_trigger_keeps` buffer to
  `WorkerScratch` (capacity 16, beside `scratch_rst_teardowns`), filled
  it via `clear` + `extend` instead of `collect`, and returned both
  buffers to the binding after the drain so their capacities survive.
  The #15947 batch cross-cancel semantics are unchanged: every teardown
  in a batch still receives the batch's full trigger set. Added
  `lifecycle_rst_scratch_16504_tests.rs` driving the production drain:
  one cell asserts both buffers come back emptied with their pre-take
  capacities (the issue's acceptance assertion, which the poll function
  itself cannot host because it needs live XSK rings), and one drives
  two same-session RSTs with three pending forwards to pin that both
  triggers survive and the non-trigger sibling is recycled.
