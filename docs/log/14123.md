# Issue #14123 — NAT64 error policy source and undelivered budget

Two defects in the NAT64 flowless ICMP-error arm
(`poll_descriptor/nat64_icmp_error.rs`), both after the F-077 budget
charge in `icmp_embed/nat64_match.rs`:

1. **Undelivered budget.** The matcher charges
   `note_icmp_error_delivered` on a successful session match, but the
   NAT64 arm then returned `NotHandled` on a missing neighbor MAC,
   capacity overflow, or a failed RFC 7915 frame build without
   refunding. The same-family arm refunds on every post-match
   non-delivery terminal (TTL-expire, CoS drop, policy-refuse — #10667);
   the NAT64 arm did not. 64 transient failures (e.g. an unresolved
   neighbor, or hop-limit-1 errors the translator refuses) exhausted
   the per-session burst and starved later valid errors until refill.

2. **Policy source.** For V6→V4, the builder writes the translator's
   pool address (`pool_v4`, RFC 7915 §5.2) as the translated frame's
   outer source, and the arm returned `policy_src_ip: None`, so the
   queued-prebuilt zone-policy gate
   (`embedded_icmp::enforce_queued_embedded_icmp_policy`) judged the
   rewritten pool source. A source-specific rule naming the original
   IPv6 error sender could never match, and a deny on that sender was
   bypassed by any broader pool permit — the #13649 defect class,
   cross-family. The policy layer already defines this tuple:
   `rule_l3_matches`'s #2358 arm matches a (V6 src, V4 dst) NAT64 tuple
   with the source in the rule's IPv6 set and the destination in its
   IPv4 set.

## Change

- `nat64_icmp_error.rs`: refund the charged token on every post-match
  `NotHandled` terminal in both arms (missing/short outer source,
  missing neighbor MACs, capacity overflow, frame-build failure).
- `nat64_icmp_error.rs` V6→V4 arm: capture the original IPv6 outer
  source from the arriving frame before translation and carry it as
  `policy_src_ip`, so the queued gate evaluates the (original sender →
  v4 server) tuple through the existing #2358 cross-family arm. If the
  original source cannot be read, refund and drop (`Dropped`) — never
  fall back to judging the pool source. The transmitted frame keeps
  the pool source on the wire. The V4→V6 arm is unchanged: its
  translated source is the stateless Pref64 mapping of the actual v4
  sender, which the same #2358 arm already expresses.
- `embedded_icmp.rs`: `queued_embedded_icmp_identity` is now
  `pub(super)` so the NAT64 arm reads the original sender with the
  same helper the same-family arm uses (#13649 precedent). The
  queued gate's policy protocol follows the override's family for a
  cross-family tuple (ICMPv6 for a V6 sender -> V4 destination), so
  ICMPv6-application rules can match the original sender; without it
  the translated frame's ICMPv4 protocol made every such rule miss.

## Regression

- `poll_descriptor_nat64_v6_to_v4_policy_judges_original_sender_14123`:
  deny-original-sender/permit-other-sender must refuse; mirror
  deny-other-sender/permit-original-sender must queue. The error is
  Time-Exceeded (not PMTUD), so no RELATED bypass applies. Rules use
  `icmpv6` applications: the gate supplies the original sender, and
  (with the fix) its ICMPv6 protocol, for the cross-family tuple.
- `poll_descriptor_nat64_undelivered_errors_refund_budget_14123`:
  64 hop-limit-1 errors (match + charge, translator refuses) queue
  nothing; the 65th deliverable error queues exactly one prebuilt.

## Risk

- Policy-visible identity for V6->V4 NAT64 errors changes from the pool
  address to the original IPv6 sender. An operator rule that permitted
  these errors only via the pool source (with a default deny) will now
  deny them unless it names the sender or `any-ipv6`; a rule denying
  the pool source alone no longer refuses them. This matches the
  #13649 pre-translation doctrine and the #2358 cross-family policy
  contract. Fail-closed posture is preserved: unreadable original
  source drops, and non-PMTUD errors without a matching permit still
  hit default deny.
