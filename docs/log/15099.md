## Mechanism (verified at base f524416374)

`mix_cos_flow_bucket` (`flow_hash.rs:16-21`) is
`*seed ^= value + C + (seed<<6) + (seed>>2)` — it carries only upward.
`exact_cos_flow_bucket` mixed the IPv4 addresses and ports whole
(`:57-73` pre-fix), applied `mix_u32_halves_for_cos_bucket` only to
`routing_domain` and the tunnel discriminator (`:89-111` pre-fix,
the #9645 fix), and truncated with `seed as u16` (`:112` pre-fix);
`cos_flow_bucket_index` then masks with `COS_FLOW_FAIR_BUCKET_MASK`
(4095). A later mix can carry a difference upward into the kept low
bits only by the few positions the remaining mixes shift it, so whole
bit ranges never reach the bucket.

Reproduced offline (Python re-implementation of the exact mix,
256 seeds scanned per pair, base tuple `test_session_key(9000, 5201)`):
keys differing only in IPv4 src bit 31, src bit 18, dst bit 31, dst
bit 16, sport bit 14, sport bit 15, dport bit 15, dport bit 12, or a
high bit of any IPv6 64-bit chunk have **0 separating seeds** — they
share one flow-fair bucket for every seed, exactly as the issue
states (src bits 18-31, dst bits 16-31, sport bits 14-15, dport bits
12-15 dead; adjacent live bits 17/15/11 separate on all 256 seeds).
Per-flow fairness and admission isolation inside a shaped class is
lost by construction for such structured flow sets, and an outside
sender can compute the collisions offline whatever the seed. This is
the #9645 defect residual: #9645 fixed the tag fields only.

## Fix

- `finalize_cos_flow_bucket`: the splitmix64 finalizer (same shape as
  `forwarding::fib::ecmp_hash_bytes` — xor-shift/multiply rounds),
  applied to the accumulated seed before `(… & 0xffff) as u16`. Every
  mixed bit now avalanches into the low 12 bucket bits. Cost: two
  multiplies + three xor-shifts once per bucket lookup.
- The mix sequence itself is untouched: field order, the conditional
  #9645 tag mixing, the keyless-lane reservation, and
  `cos_queue_prospective_active_flows` are unchanged. NOT changed:
  mixing IPs/ports as 16-bit halves instead — the finalizer alone
  makes every bit live, and re-chunking the fields would add mixes
  on the hot path for no extra separation.
- This deliberately moves **every** bucket, default-domain flows
  included. The #9645 invariant "a default flow keeps the pre-#9645
  bucket" cannot survive any avalanche fix — the pre-#15099 mapping
  is the defect — so the seed-0 pins move 410 → 2649 (v4) and
  1284 → 127 (v6), and the #9645 unchanged cell now pins the
  surviving half of the invariant: a default-domain key with no
  discriminator mixes no tag fields, i.e. its bucket is exactly the
  legacy field sequence passed through the finalizer. Per the pin
  comment's standing instruction, the new baselines need live
  re-validation of 5201 fairness on the loss HA cluster (parent /
  merge-time step; recorded here as the outstanding lab item — the
  code change is complete without it).

## Risk

- Operator-visible delta: the flow→bucket assignment inside every
  shaped CoS queue changes for all flows (same seed, new mapping).
  SFQ fairness properties are preserved (the distribution cells stay
  green), but the specific 5201 fairness baseline numbers from the
  loss cluster predate this mapping and should be re-validated live
  after merge — the only outstanding item, lab-bound by design.
- No fail-open/fail-closed surface changes: bucket choice only steers
  SFQ lanes; admission gates, the keyless reservation, forwarding,
  policy, and session identity are untouched.
