# #17692 — lldp: consume RX error readiness before polling again

- **Timestamp**: 2026-10-28
- **Action**: `PpollRecv.Recv` treated only `POLLIN` on the RX fd as readiness; `POLLERR`/`POLLHUP`/`POLLNVAL` (AF_PACKET `ENETDOWN` on interface down/delete) fell into the spurious-wakeup loop and busy-spun without ever calling `Recvfrom`, so the lldp `rxLoop` receive-error backoff was unreachable. Error readiness now breaks to `Recvfrom`, consuming the pending socket error and surfacing it to the caller's backoff. Added `AttachPollFnForTest` seam and a bounded fake-poll regression.
- **File(s)**: `pkg/linuxsock/ppoll.go`, `pkg/linuxsock/ppoll_test.go`, `docs/log/17692.md`.
- **Validation**: `TestPpollRecvConsumesRXErrorReadiness17692` PASS (exactly one ppoll call, error surfaced, no spin); `TestPpollRecvWakesOnSignalStop17231` PASS.
- **Risk**: wake-fd semantics unchanged; frame-ready still wins over the wake.
