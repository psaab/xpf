# 17102 — merge the four hand-copied failover request/ack skeletons into one registry, one round trip, one ack-frame sender

The failover request/ack RPC in `pkg/cluster/sync_failover.go` was four
hand-copied skeletons (`SendFailover`, `SendFailoverBatch`,
`SendFailoverCommit`, `SendFailoverCommitBatch`), each re-implementing
validate → `getActiveConn` → waiter registration under `failoverWaitMu`
with the cross-map in-use check → `writeMsg` → complete+disconnect on
error → `time.NewTimer(failoverAckTimeout)` → double-select drain →
reqID/ch-matched delete, plus four copy-pasted completers
(`completeFailover{,Batch,Commit,BatchCommit}Wait`), two result senders
(`sendFailoverResult`, `sendFailoverBatchResult`) and four drain loops in
`handleDisconnect`. The 14160 twin divergence (`sendFailoverBatchResult`
failed to disconnect a broken `ackConn` that `sendFailoverResult`
disconnected) was fixed by mirroring the twin and adding a guard test,
keeping the duplication.

Fix — clean cutover, no shims:

- `type failoverWaiterRegistry map[failoverWaitKey]failoverWaiter` is the
  single non-test waiter-map declaration. The key is
  `{partition, key, single}`: a request/commit phase partition (so an ack
  never completes the other phase), the `failoverBatchKey` rendering of
  the sorted normalised RG set, and a single flag preserved only so
  `handleDisconnect` keeps its per-shape cleared counts. `SessionSync`
  keeps one field, `failoverWaiters failoverWaiterRegistry`, replacing the
  four maps; `failoverWaitMu` is unchanged.
- `failoverRoundTrip` is the one skeleton: conn check, reqID draw (or
  caller-supplied commit reqID), canonical-key registration with the
  unified overlap refusal (`failoverRGInUseLocked` now walks the single
  registry), one `writeMsg`, the `time.NewTimer(failoverAckTimeout)`
  double-select drain, and the reqID/ch-matched delete on timeout. It
  returns a `failoverTripResult` (`Ack` / `ReqID` / `Outcome` / `Err` /
  `UsedConn`) so callers never string-match: acked / rejected /
  send-failed / timed-out drive the exact legacy error strings, warns,
  `stats.Errors` and `handleDisconnect` arms. The four public methods keep their signatures and wire payloads
  (single: `encodeFailoverSingleReqPayload`; batch: the existing batch
  encoder; `len==1` batch still delegates to the single path). Send
  failures return reqID 0 for both single and batch, pinning the unified
  #17102 contract. Pre-fix both arms already returned 0 on send failure
  (verified in the origin/master `SendFailover`/`SendFailoverBatch`
  send-error arms); the merge preserves that, it does not change it.
  Consumers discard it per `failover.go`, so this is contract hygiene,
  not a wire change.
- `sendFailoverAckFrame(conn, msgType, rgIDs, reqID, status, detail)`
  picks the single or batch encoding and owns the 14160 two-conn write
  protocol: a broken active conn is disconnected even when the fallback
  delivers, dual failure disconnects both conns with one error counted,
  the single success Info log and the batch oversized refusal are
  preserved. The sole production caller deleted `sendFailoverResult` /
  `sendFailoverBatchResult`; the 14160 tests call the new name directly.
- `drainAllFailoverWaits` swaps out the registry (preserving the
  per-shape cleared counts for the disconnect log); `handleDisconnect`
  delivers `failoverAckDisconnected` and closes every waiter in one loop,
  replacing the four loops.
- Test fixtures are migrated, not dual-pathed: `registerFailoverWaitForTest`
  inserts through the canonical key, the 16041 and stale-ack tests use it /
  the canonical delete, and the 14160 twin-guard test now exercises the
  merged sender through both payload shapes.

Risk: the waiter registry is internal (no wire-format change); the
reqID-on-send-failure contract (0 for single and batch, both discarded
by Manager callers, unchanged from pre-fix) and the already-shared
skeleton semantics mean a future waiter change lands in one place
instead of four. Fail-closed direction is preserved: broken conns are
still torn down, overlapping failovers are still refused, and timeouts
still return the allocated reqID for reqID-scoped aborts (#16592).
