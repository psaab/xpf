# Precheck MIXED_PORT in mixed-CoS mode and reap the harness process group on wrapper abort (#13068)

- **Issue**: #13068 (research finding D10-13, deep-review source report
  `gemini-4-argon-high-review-performance-cos-fairness-100e100m-and-code-quality-modularity-001.md`,
  three-way research-validated). TEST-ONLY reachability: both files live in
  `test/incus/`.
- **Cause**: Two independent leak/mis-gate mechanisms in the fairness gate
  tooling.
  1. `fairness-harness.sh` ran the #8040 `target-services.sh check` gate at
     the top of positional-argument parsing, probing only `"$PORT"` — before
     `MIXED_PORT=${MIXED_PORT:-5205}` was initialized at all, and never
     probing it even under `--mixed-cos`/`--mixed-cos-isolated`. A dead
     `MIXED_PORT` listener therefore passed the preflight, ran the full
     traffic window (default 120 s), and only failed at the end — after the
     build, deploy, and exclusive harness lock were already spent.
  2. `fairness_multi_sample.py` launches each `fairness-harness.sh` sample
     with `start_new_session=True`, so the harness (and its `iperf3` loads
     plus the `while true; do curl /metrics; done` scraper) lives in a
     process group terminal signals never reach. Cleanup ran only inside
     `except subprocess.TimeoutExpired`; a `SIGINT` (Ctrl-C,
     `KeyboardInterrupt`) or `SIGTERM` (outer `timeout`) killed the wrapper
     mid-`communicate()` and orphaned the whole group — contaminating
     subsequent benchmark runs and holding `/tmp/xpf-fairness-harness.lock`.
     `SIGTERM`'s default disposition does not even unwind the stack, so no
     `finally` could have fired without an explicit handler.
- **Change**:
  1. `fairness-harness.sh`: the precheck block moved after the env-defaults
     and `IPERF_CMD_PREFIX` deprecation check (still before the work dir,
     harness lock, and any traffic), and its predicate is now exactly the
     ports this run sends to: `("$PORT")`, plus `"$MIXED_PORT"` when
     `MIXED_COS=1`. `SKIP_TARGET_PRECHECK=1` keeps bypassing the gate for
     hermetic runs (#11769), and single-class runs still probe one port
     only — no over-rejection, the #8040 doctrine.
  2. `fairness_multi_sample.py`: the per-sample `communicate()` block is
     wrapped so ANY abort unwinds through `_kill_process_group(pgid)` —
     `except BaseException: _kill_process_group(pgid); raise` — followed by
     a `finally` that reaps the leader (`proc.wait`, bounded by
     `POST_KILL_COMMUNICATE_TIMEOUT_SEC`). The kill is unconditional on the
     abort path rather than guarded by `proc.poll()`, because the group can
     hold live descendants even after the shell leader itself has exited (a
     child keeping the stdout pipe open). `main()` installs
     `_sigterm_system_exit`, which converts `SIGTERM` into
     `SystemExit(128 + signum)`: the interpreter now unwinds through the
     cleanup AND the shell-visible exit status stays the death-by-signal
     convention (143) that callers like `fairness-cos-class-sweep.sh`
     already see for a signal-killed wrapper. `SIGINT` needs no handler —
     its `KeyboardInterrupt` already unwinds through the same cleanup.
- **Regression coverage** (`test/incus/fairness_multi_sample_test.py`):
  - `test_fairness_harness_mixed_cos_precheck_includes_mixed_port` — a
    temp-dir copy of the real harness with a recording
    `target-services.sh` stub (hermetic; the stub fails the check so the
    harness aborts at the gate) must invoke `check 5202 5205` under
    `--mixed-cos`.
  - `test_fairness_harness_precheck_honors_mixed_port_override` — same,
    with `MIXED_PORT=6205` in the environment: `check 5202 6205`.
  - `test_fairness_harness_single_class_precheck_checks_only_primary_port`
    — single-class mode still probes `check 5210` alone (over-rejection
    guard; passes on master too).
  - `test_cli_sigint_kills_harness_process_group` /
    `test_cli_sigterm_exits_143_and_kills_harness_process_group` — run the
    wrapper as a subprocess against a fake harness that records its pgid
    (`start_new_session=True` makes `$$` the group id) and leaves a
    sentinel-writing descendant; send `SIGINT`/`SIGTERM` mid-sample and
    assert the wrapper exits non-zero / exactly 143 without a traceback
    and that `os.killpg(pgid, 0)` raises `ProcessLookupError` (plus the
    sentinel never appears). A cleanup hook SIGKILLs any surviving group
    so a RED run does not itself leak the fixture.
- **RED evidence**: On pristine origin/master (`ac4dcdfc1`) with only the
  test-file change applied (fresh worktree), exactly the four
  defect-specific tests fail for the defect's own mechanisms:
  `AssertionError: Lists differ: ['check', '5202'] != ['check', '5202', '5205']`
  (and the `6205` variant), `AssertionError: harness process group NNNN
  survived the wrapper abort` (SIGINT), and `AssertionError: -15 != 143`
  (SIGTERM: default kill, no cleanup, no 128+15 status). The two guard
  tests (`single_class_precheck`, `test_cli_timeout_kills_process_group`)
  pass on master.
- **GREEN evidence**: With the fix, all six new tests pass;
  `python3 -m unittest discover -s test/incus -p fairness_multi_sample_test.py`
  is 49/49 OK; `cos_port_grid_test.py` 8/8 OK (its static harness pins are
  untouched); `target-services-selftest.sh` passes; `bash -n`, `python3 -m
  py_compile`, `git diff --check`, and `shellcheck` on the touched shell
  file are clean (the four shellcheck warnings and the
  `harness-census-selftest.sh` `failed=1` positive control are byte-identical
  on pristine master — pre-existing, unrelated).
- **Blast radius / risk**: `fairness-harness.sh` operators now see an
  immediate exit-1 abort when the mixed listener is down instead of a late
  failure — that is the intended gate; hermetic callers already set
  `SKIP_TARGET_PRECHECK=1` and are unaffected (the existing hermetic
  harness tests pass unchanged). For the wrapper, normal, timeout, and
  error paths are byte-for-byte the previous behavior (same artifacts,
  same exit codes 0/1/2); only abort-by-signal now cleans up, and the
  shell-visible status for a SIGTERM'd wrapper is still 143. Sweep callers
  read `$?` and treat any non-{0,1} as infra failure — unchanged. Residual
  (out of scope, separate finding D10-14/#13070's area): the
  `fairness-cos-class-sweep.sh`/`fairness-cos-throughput-headroom.sh`
  wrappers' own trap coverage for their background captures.
