# #15259 — config: group-merge conflict-gate consistency (A90-02)

## Mechanism (re-anchored at origin/master 49b5be6f6d)

- #14425 adoption (`group_routing_term_then_14425.go`:
  `isRoutingTermThenAction14425` / `routingThenNodeAction14425` /
  `routingPackedTermThenAction14425`, wired in `pkg/config/ast_groups.go`
  mergeNodes) matches only `accept`/`reject`. A group-supplied
  `then next policy` beside an inline `then accept` therefore fell
  through to the generic inline-wins override and was silently dropped,
  while the mirror (group accept beside inline `then next policy`)
  materialised and strict-rejected via #11780
  (`validatePolicyNextPolicyActions11780`: NextPolicy + Action conflicts,
  malformed `then next <value>` rejects). One conflict class, two
  verdicts depending on which side the group supplied.
- Measured failing shape on base: group term container
  `term t1 { then next policy; }` merging into an inline term whose
  `then` is a leaf/container (`then accept;` / `then { accept; }`).
  The container-container merge recurses into the inline term and
  merges the group's `then` node as a leaf child; the group
  `then next policy` leaf (Keys `[then next policy]`) met the inline
  `then accept` leaf as its keyword peer and took the override, so
  `NextPolicy` never materialised and the #11780 gate never saw the
  conflict. Leaf-spelling group `then` nodes, packed tails, and the
  `then { next policy; }` container spelling already reached the gate
  (probe-verified); `then next term` alone is malformed in routing and
  was likewise dropped when group-supplied beside a terminal.

## Fix

- `pkg/config/group_routing_term_then_14425.go`: new
  `isRoutingTermThenNextPolicy15259` (+ `routingTermThenNextPolicy15259`,
  `routingPackedTermThenNextPolicy15259`) mirroring the #14425
  predicate for `then next ...` in leaf, container-child, and
  then-first packed spellings. Any `next` value qualifies so malformed
  `then next term` materialises for the #11780 malformed gate too.
- `pkg/config/ast_groups.go`: mergeNodes adopts a group routing-term
  `then next ...` beside any peer (same arm as #14425), and the #4325
  single-key container guard exempts it, so the compiler gate decides.
- `pkg/config/group_merge_container_leaf_14418.go`: the #14418
  cross-shape drop keeps a group `next` beside an inline terminal (and
  a group terminal beside an inline `next`) instead of dropping it as
  a conflicting terminal, so that path also reaches #11780.
- No compiler gate changes: #11780 already rejects next+terminal and
  malformed next, warns on tolerant loads, and retains both authored
  actions there. `next policy` itself is NOT reclassified as a
  terminal in `TerminalActions`.

## Regression (RED → GREEN)

`pkg/config/group_routing_term_next_policy_15259_test.go`:

- RED on base: group-next (container `then`) vs inline accept and vs
  inline reject compiled clean (inline terminal silently won);
  malformed group `next term` vs inline accept compiled clean;
  lenient lost `NextPolicy` with no warning. Mirror cells
  (group accept/reject vs inline next) already rejected and stay so.

  both sides stays legal without gaining `NextPolicy`.
