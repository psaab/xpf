# #13404 — expand stale-reply guards across VRF scopes

- **Issue**: #13404
- **Branch**: `fix/13404-campaign-pub`
- **Base**: `dd607606a` (`origin/master`)
- **PR**: #13439

## Disposition

Both stale-reply guard renderers treated `IngressVRFScopes` as conjunctive
predicates on one rule. With multiple scopes, a packet cannot simultaneously
arrive through distinct VRF masters, leaving each denied-reply guard
unsatisfiable. The daemon text oracle and netlink emitter now expand a
multi-scope guard into one rule per VRF scope, keeping each master paired with
its own member-`sdifname` predicate. Scope-less guards and single-scope behavior
retain their previous output.

- `TestHostInboundStaleReplyNetlinkMultiScope13404` failed on pristine base
  `dd607606a`: the netlink emitter produced one rule for a two-scope guard.
- `GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/var/worktrees/.cache/t go test ./pkg/nftables -count=1`: passed.
- `GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/var/worktrees/.cache/t go test ./pkg/daemon -run 'StaleReply' -count=1`: passed, including the text multi-scope regression.
- The full `go test ./pkg/nftables ./pkg/daemon -count=1` run passed `pkg/nftables` but failed `pkg/daemon` on environment-sensitive Unix socket `bind: invalid argument` errors and `TestFirstCommitRollbackRootPasswordRepairHeldCommit12169` timing out before reaching its held apply body.

## Risk

Expanding guards increases generated rule count in proportion to the number of
VRF scopes carried by a guard. Existing catalog construction produces one
scope per rule; the expansion protects other valid multi-scope constructions.
