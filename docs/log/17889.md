# #17889 — Clear stale auth grace after successful upgrade

- **Timestamp**: 2026-10-26
  - **Action**: Completed in-place authentication now clears a pre-key or
    retired-key grace when the proved PSK is still accepted, so a later key
    retirement starts its own grace. If an exchange that was already in flight
    completes under a key that became retired, its authenticated completion
    starts a fresh grace for the follow-up current-key rekey. Reconcile and
    enforcement clear any stale anchor once the connection is authenticated
    under an accepted key; failed/incomplete exchanges do not move the anchor.
  - **File(s)**: `pkg/cluster/sync_auth.go`,
    `pkg/cluster/sync_auth_strict_7441.go`,
    `pkg/cluster/sync_auth_upgrade.go`,
    `pkg/cluster/sync_auth_grace_17889_test.go`, `docs/log/17889.md`.
  - **Validation**: The fail-on-revert test failed when the completed-upgrade
    grace update was removed (`successful pre-key upgrade retained its old
    grace anchor`, `retired=false`). The focused auth regression and existing
    retired-key/cooperating-peer tests passed:
    `go test ./pkg/cluster -run '17889|TestCooperatingPeerRekeysWithinGrace16857|TestRetiredKey' -count=1`.
    Full affected package suite passed: `go test ./pkg/cluster -count=1`.
  - **Risk**: A successfully authenticated round that completes under a key
    which became retired while it was in flight receives a fresh retirement
    window for the next rekey attempt. Failed, incomplete, malformed, and
    unauthenticated attempts retain the original deadline and remain subject
    to eviction.
