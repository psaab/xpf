# #16758 — IPsec SA full set over 4096 names refused whole, sender silent

- **Timestamp**: 2026-10-25
  - **Action**: Chunked over-bound IPsec SA full sets as #15160 does for
    DHCP leases. `QueueIPsecSA` now keeps the legacy `syncMsgIPsecSA`
    single frame for sets at or under `maxIPsecSANames` (4096) and splits
    larger sets across additive `syncMsgIPsecSAChunk = 49` frames
    (`{generation, index, total, totalNames}` + newline-joined names,
    <=4096 per chunk, each with its own increasing full-set seq). The
    receiver (`handleIPsecSAChunk`) assembles by (incarnation, generation)
    under `ipsecApplyMu` and commits atomically only when every chunk
    arrives; unclosed/inconsistent generations never commit and the prior
    set is retained, and a committed legacy set discards pending
    assemblies. A 5000-name set now round-trips to the standby. The sender
    latches `IPsecSAOversizeAlarmLatched`, counts `IPsecSAOverCapSets`,
    and warns on the primary (rendered as a Warning in `FormatStatus` and
    as an `IPsec SA malformed/over-cap` row in the services tables); it
    refuses, counted, a set with a name over `maxIPsecSANameLen` or a total
    over 1<<20 before any frame is written. The receiver counts every
    malformed legacy (#9061) or chunk refusal in the new
    `IPsecSAMalformedIgnored` stat, also rendered when nonzero. A
    pre-#16758 peer ignores type 49, so a mixed pair loses only
    over-bound pushes until both sides upgrade.
