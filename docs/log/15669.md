# #15669: `Manager.UpdateConfig` latches deleted heartbeat/control/GARP values

- **Timestamp**: 2026-10-19
- **Action**: Read the issue and the code at origin/master (6a1ea38498).
  - `pkg/cluster/group_state.go:152-160`: `hbInterval` written only when the
    converted duration is > 0, `hbThreshold` only when > 0, `controlInterface`
    only when non-empty — deleting any of the three stanzas latched the last
    committed value. `pkg/cluster/group_state.go:226-230`: `garpCounts[rg.ID]`
    written only for a positive `GratuitousARPCount`, so deleting
    `gratuitous-arp-count` from a still-present RG latched the old burst count
    (the #6027 purge only covered whole-RG removal).
  - The timer half of the original report is already fixed: `ApplyCommittedHeartbeatTiming`
    (#7164, `heartbeat_manager.go:334-369`) restarts a running heartbeat when
    committed timing diverges from live timing, and the daemon apply path calls
    it (`pkg/daemon/daemon_apply_tail.go:342`). Not re-filed, not re-implemented.
  - Neighbouring knobs already revert on unset and set the pattern:
    `takeoverHoldTime` resets to `DefaultTakeoverHoldTime`, and both
    control-link auth keys clear on empty.
- **File(s)**: none

- **Timestamp**: 2026-10-19
- **Action**: Fix in `Manager.UpdateConfig`.
  - `hbInterval`: else-branch resets to `DefaultHeartbeatInterval` (also covers
    the #8642 wrapped/out-of-range fallback, which previously kept the prior
    value instead of the documented default).
  - `hbThreshold`: else-branch resets to `DefaultHeartbeatThreshold`.
  - `controlInterface`: assigned unconditionally from the config.
  - `garpCounts`: else-branch `delete(m.garpCounts, rg.ID)` for an RG that no
    longer authors a positive count.
  - Existing tests that preset `m.controlInterface` directly before an
    `UpdateConfig` whose config did not author it encoded the latch; they now
    author `ControlInterface` on the config instead (`election_test.go`
    readiness-gate cell — with `takeoverHoldTime` set after the apply, as
    `manager_stop_test.go` already did — `heartbeat_duplicate_nodeid_10772_test.go`,
    and the three `manager_stop_test.go` hold-timer cells). Authoring the
    interface also arms the dataplane monitor debt on a new RG, so
    `TestHoldTimer_StillPromotesWhenRunning` clears it via `SetMonitorWeight`,
    mirroring `election_test.go`'s status cell.
