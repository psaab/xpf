# #16837 — `then static-nat prefix-name` resolves multi-value / dns-name objects to their first host (R3-F13-01)

- **Timestamp**: 2026-10-25
  - **Action**: `resolveStaticNATThenPrefixName` (`pkg/config/compiler_nat_static.go`) used the singular `Address.UsableValue()`, which returns `ExpandedPrefixes[0]` / `DNSAddresses[0]`. A `range-address 10.0.0.5 to 10.0.0.8` target therefore committed as 1:1 NAT to `10.0.0.5/32` (also through a 1-member address-set), and a `dns-name` target was frozen at its compile-time answer while the daemon's DNS refresh kept moving the address book. Fixed by routing both the direct and the 1-member-set branches through a new `staticNATScalarPrefix` helper that requires exactly one `UsableValues()` entry and `DNSName == ""` (a dynamic dns-name object is never a static 1:1 target, even with a single current answer). Refused references leave `Then==""`, so strict commit rejects via the existing #4290 gate and the lenient load / peer-sync path downgrades to the same warning; no validator or dataplane change was needed.
  - **File(s)**: `pkg/config/compiler_nat_static.go`, `pkg/config/static_nat_prefix_name_multi_16837_test.go`, `docs/log/16837.md`
  - **Validation**: New `TestStaticNATPrefixNameMultiValueUnit16837` (9 subtests: direct range, 1-member set of range, direct multi/single-answer dns, set of dns refused; single prefix, single-host range, wildcard, 1-member set controls resolve) and `TestStaticNATPrefixNameMultiValueCompile16837` (range / set-of-range / dns / set-of-dns rejected strict with a `prefix-name` error and warned with `Then==""` lenient; single-prefix control resolves strict+lenient; single-host range control resolves) — all PASS. Neighbouring suites `TestStaticNAT*|TestCrossKind*|TestRangeAddress*|TestDNSNameModelled*|TestSoleAddress*|TestWildcardAddress*` PASS. `TestWildcardTypedLeafKeyValidatorInventory_6844` fails identically on pristine origin/master (pre-existing, unrelated).
  - **Risk**: Fail direction closed: previously-silent first-host installs now reject/warn. Behaviour change is limited to prefix-name targets that denote zero-or-many values or a dns-name — exactly the objects that cannot name a scalar 1:1 target; single-prefix, single-host-range, single-prefix-wildcard and 1-member-set-of-single-prefix targets resolve byte-identically to before. Wildcard/range entries whose expansion is a single CIDR remain valid targets.
