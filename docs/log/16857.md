# #16857 — Retired-key session-sync connection survives finalize

- **Issue**: R3-B04-01. The #10717 eviction and the #9717 "unauthenticated"
  list both keyed on `len(authPSK)==0`. A connection whose `authPSK` is a
  key that has left the accepted set (finalized rotation:
  `delete chassis cluster additional-authentication-key`) was therefore
  never evicted or listed. Its frames kept verifying under retired-key-
  derived connection keys for as long as the peer declined the #6628 rekey,
  contradicting the documented "the retired key stops authenticating". A
  holder of the retired key with an installed connection kept full sync
  authority (session installs/deletes, `syncMsgFence`, failover, config
  payloads), and `show chassis cluster statistics` showed no unauthenticated
  connection.
- **Change**:
  - Treat `authPSK not in authAcceptedKeys()` as the same stale population
    as never-authenticated (`connAuthStaleLocked` in
    `sync_auth_strict_7441.go`). The pre-key population is unchanged.
  - Anchor a set-once monotonic grace at the reconcile where the
    connection's key leaves the accepted set
    (`noteRetiredKeyGraceStartLocked`, called from
    `ReconcileConnectionAuth` before `beginAuthUpgrade` prompts the
    rekey). The anchor is tagged `strictGraceRetired` so it can be told
    apart from a pre-key anchor.
  - `enforceStrictSessionAuth` re-reads the accepted set live: a
    connection that rekeys to an accepted key, or whose key is
    re-accepted (re-added as additional), has its retired anchor cleared
    and is never evicted. At expiry a retired-key connection is closed
    with a distinct log line; the existing `PreKeyAuthEvictions` counter
    is incremented (same eviction event).
  - `UnauthenticatedSessionConns` now includes the retired population;
    new `RetiredKeySessionConns` returns the retired subset.
    `SyncStatsProvider` gains `RetiredKeySessionConns()` (fakes in
    `pkg/cli`/`pkg/grpcapi` tests updated) and `Manager` gains
    `retiredKeySessionConns()`.
  - `controlLinkAuthStatus` splits the stale population: never-
    authenticated connections render as before ("NOT authenticated,
    frames still accepted without HMAC"); retired-key connections render
    distinctly ("authenticated under a RETIRED key, frames still verify
    under retired-key-derived keys"). No key bytes are rendered.
  - A connection still inside an open rotation window (old key still in
    the accepted set as additional) is not stale: no anchor, no listing,
    no eviction.

## Verification

- **New cells** (`go test ./pkg/cluster/ -run 16857 -count=1`): PASS, 7
  tests — defect arm (anchor/list/evict after finalize + grace),
  status lists retired connection without leaking keys, re-acceptance
  within grace clears anchor and a second finalize re-anchors, grace
  anchor set-once across reconciles, cooperating peer rekeys A→B within
  grace and is never evicted (end-to-end #6628 exchange), rotation-window
  control (old key still accepted → untouched), current-key negative
  control. The tests do not compile pre-fix (`strictGraceRetired` /
  `RetiredKeySessionConns` undefined), which is the RED evidence; the
  defect assertion itself (`evicted=1`) is unreachable pre-fix because
  both predicates skipped `len(authPSK)>0`.

  `TestUpgradeRotationWaitsForAnOutstandingRoundAndHealsOnTheRequest7163`,
  all #7441/#9717/#10717 cells, and
  `TestSessionSyncHitlessKeyRotationAcceptRing` PASS in the same run.

## Residuals
