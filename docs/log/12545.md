# #12545 — keep multiport PCI enumeration stable across renames

- **Opened**: 2026-10-10.
- **PR branch**: `fix/12545-campaign-pub`.
- **Action**: order NICs sharing a PCI bus address by stable hardware port metadata (`dev_port`, then `phys_port_name`) before falling back to interface name.

## Defect

For multiport PCI functions, several netdevs can share `busAddr`. Enumeration previously sorted those ties by current interface name. After bootstrap renamed port 0 to `fxp0`, a following enumeration could put the still-kernel-named sibling (`enp1s0d1`) first, moving the claimed interface to index 1. Bootstrap refuses its management lifeline remedy unless it is PCI enumeration index 0, so the remedy told operators to re-wire to the sibling port and could never settle. This affects multiport drivers such as mlx4, cxgb4, and switchdev representors.

## Change

`enumeratePCINICs` now reads each interface's `dev_port` and `phys_port_name` from sysfs and sorts by `(sortKey, busAddr, dev_port, phys_port_name, name)`. Missing or invalid `dev_port` sorts after known values; missing `phys_port_name` sorts after known values; the name remains a deterministic last fallback. Numeric digit runs in `phys_port_name` are compared numerically (e.g. `pf0vf2` before `pf0vf10`). A private sysfs-root variable allows the real enumeration walk to be exercised against temporary multiport fixtures.

Regression tests cover the reported renamed-port case, rename-invariant index 0, numeric and missing/unparseable/duplicate port metadata, switchdev `phys_port_name`, and unchanged ordering across distinct PCI functions.

## Risk

When both hardware port attributes are unavailable, same-function ordering necessarily falls back to interface name; such devices cannot provide a stable port identity through these sysfs attributes. No bootstrap refusal or naming policy was otherwise changed.
