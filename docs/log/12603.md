# Issue #12603 — key attacker-indexed placement against FxHasher deltas

## Root cause

`FxHasher::with_seed` adds its seed to the polynomial accumulator. The seed therefore contributes the same key-independent constant to keys with equal word layouts, leaving key-pair deltas unchanged. IPv6 keys can vary selected 16-bit address words to construct large single-set flow-cache cliques across every seed; session-index bucket placement had the same additive-seed weakness.

## What changed

- Replaced flow-cache set placement and session-map `FxSeededState` with a process-seeded keyed SipHash-2-4 BuildHasher. The shared builder is used for all attacker-keyed session maps; map state remains a small copyable seed, stable for the process lifetime.
- Added v6 s3-clique regression coverage for flow-cache set spread and session-index bucket spread across pinned seeds.
- Preserved flow-cache set masking/layout, session map lookup equality, and existing flow/session-key semantics.

## Validation

- Mutant: restoring `FxHasher::with_seed` makes the flow-cache regression fail with a single-set clique.
- Mutant: changing the shared BuildHasher back to seeded FxHasher makes the session-index regression fail with a single-bucket clique.
- `cargo test --bin xpf-userspace-dp afxdp::flow_cache::tests` passed (67 tests).
- `cargo test --bin xpf-userspace-dp session::tests` passed (239 tests).
- `cargo build --bin xpf-userspace-dp` passed.

## Risk

SipHash-2-4 costs more per placement hash than FxHasher. It remains allocation-free and only changes the private hash/bucket mapping; keys, equality checks, and stable-per-process placement are unchanged. Session sync carries explicit keys, not hash values, so peers independently rebuild their maps.
