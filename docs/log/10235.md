# Issue #10235 — per-instance IPv6 static routes on CLI/gRPC show surfaces

- **Issue:** `ri.Inet6StaticRoutes` is populated by `compileRoutingInstances` and classified by `config.StaticRouteExclusions`, but `routing-instances detail` on both the local CLI and gRPC show surface rendered only `ri.StaticRoutes` (the inet.0 sibling). The complete #10235 body and comments were read before implementation; it had no comments. The complete #10001 follow-up body and comments were also read; it had no comments.
- **What changed:** Added an inet6.0 sibling block to each existing per-instance renderer. It uses the same discard, reject, next-table, next-hop, and `StaticRouteExclusions` arms as the existing inet.0 path. The existing v4 block is unchanged, so v4 output remains byte-identical; configured v6 rows are appended in a labeled `Static routes (inet6.0): N` block.
- **Tests:** Added a direct gRPC renderer regression and a real tolerant `Store.SyncApply` CLI/gRPC agreement regression. Both include v4 negative controls, v6 next-hop/discard/next-table rows, and the next-table refusal reason.
