# Issue #12077 — reject malformed test-routing selectors

## Why

Both the local `test routing` handler and the remote `cli` test-routing handler silently dropped unrecognized tokens and selectors without values. A typo such as `instnace dmz` or a trailing `instance` therefore became a main-table lookup instead of an input error.

## What

Both parsers now reject unknown selector tokens with `unknown selector "X"` and reject absent or empty values for `destination` and `instance` with `selector "X" requires a value`. These errors return before route-manager access or a remote `ShowText` lookup. Valid destination/instance routing remains supported.

## Validation

- **RED before** (STEP-0 `a16d32e69d28848ae7fdb3057b481bb42e0dc030`): temporary local and remote repros failed on the misspelled `instnace`, valueless `instance`, and `bogus` inputs. The local handler printed a main-table lookup; the remote handler returned nil and sent `test-routing:dest=10.1.2.3` for each malformed query.
- **GREEN after**: permanent regressions for both parsers pass. They cover misspelled/unknown selectors, absent and empty destination/instance values, and assert that malformed inputs cause zero route-manager calls / zero lookup RPCs. The remote valid-instance topic regression also passes.
- `go build ./pkg/cli ./cmd/cli` passed.
- `gofmt -l` on all four changed Go files produced no output.
- `go test ./pkg/cli/... ./cmd/cli/... -count=1`: `pkg/cli` passed; `cmd/cli` failed only at the repository-wide `TestTreeIsGofmtClean` guard, which reports an existing formatting backlog including untouched `pkg/cli/cleartext_sync_alarm_11773_test.go`. `TestTreeIsGofmtClean` was run at the same STEP-0 base and reproduced the failure there.

## Risk / residual

No server parser or lookup behavior changed. No live gRPC server or cluster was exercised; remote no-lookup behavior is verified with a recording client, and the local path with a route-manager recorder.
