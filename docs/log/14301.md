# Issue #14301 — #6538 fail-closed fixture superseded by #14286 normalization

- **Issue:** PR #14286 (#14168) added `normalizePendingConfirmTree` in
  `pkg/configstore/store_persist.go`, applying `Store.Load`'s tolerant
  repairs (`rewriteRetiredDataplaneType` + `SanitizeTreeControlChars`) to
  the pending-confirm `PrevTree` before lenient compile/promotion. The
  pre-existing #6538 fixture `uncompilableTree()` in
  `pkg/configstore/confirm_recovery_uncompilable_target_6538_test.go`
  used exactly `system dataplane-type ebpf` — a retired dataplane-type
  leaf — as its "uncompilable rollback target". After #14286 that leaf
  is repaired by normalization, compiles leniently, and no longer stands
  in for an uncompilable target. The expired sentinel failed on its
  premise check; the two in-window sentinels passed silently without
  ever exercising a nil `confirmPrevCfg` from a failed compile. No
  production regression: the normalization is #14286's intended
  behaviour; this is test-coverage debt.
- **What:** `uncompilableTree()` now builds
  `apply-groups xpf6538-undefined-group` + `system host-name Prev` — an
  `apply-groups` reference to a group not defined under `groups`. Group
  expansion fails with `apply-groups references undefined group` on
  every compile path, and neither tolerant repair touches it, so it
  remains genuinely uncompilable after `normalizePendingConfirmTree`.
  Same trigger family as `brokenActiveTree9884` /
  `TestLoadCommittedConfigCompileFailureFailsClosed`. The fixture now
  also asserts the premise AFTER applying `normalizePendingConfirmTree`
  to a clone, so a future repair that subsumes this trigger fails the
  premise loudly instead of silently vacating the sentinels. Both #6538
  fail-closed assertions are unchanged and unweakened: expired recovery
  returns an `ErrConfigCompile`-tagged error with the reverted tree
  reachable; in-window rollback persists the target as committed (never
  `committed=0`) and keeps `everCommitted`. Stale comments claiming
  `PrevTree` is never repaired (test header, `store_persist.go`
  recovery doc, `pkg/configstore/README.md` #6538 section) updated to
  state the #14168 normalization and the new genuinely-uncompilable
  example. No production code changed.
