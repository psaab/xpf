# #15139 — Bare value leaves wrongly declined by the #14343 braced-body gate (A83-05)

## Defect

`normalizeCompactNodes` (#14343) declines the compact fold when the single
packed statement the braced body would land on resolves to a leaf
(`children == nil && wildcard == nil`). That also caught value leaves
authored as the bare keyword, where the braced body IS the value:

- `host-inbound-traffic system-services { ssh; }` / `protocols { ospf; }`
  (the partially-elided spelling admitted by #8850) failed strict commit
  and silently lost its services/protocols on tolerant load (boot,
  HA SyncApply), because the declined tree leaves the body where the
  host-inbound reader does not read it.
- `then loss-priority { high; }` failed commit with
  "`then loss-priority` requires a value".

A box whose persisted config used the #8850 spelling (admitted
2026-09-05 to 2026-10-16) therefore booted after upgrade with
host-inbound ssh/ospf denied. The change fails closed, but it is a
regression of #8850 (7373d4db74) introduced by be0f5f9e58 (#14343).

## Fix

- `pkg/config/compact_normalize_8662.go`: decline only when the packed
  statement already consumed its own value —
  `len(stmts[0]) >= 1+refined.args` after `consumeNodeKeys`. A bare
  keyword statement (`system-services`, `loss-priority`, any value leaf
  with no value token yet) now folds, and the body becomes the leaf's
  value children exactly as the braced spelling parses. Flag leaves
  (`args == 0`, already complete as the bare keyword, e.g. `discard`)
  and valued leaves (`screen my-screen { ... }`,
  `description x { ... }`) still decline, so #14343 is unchanged.

Deliberate scope cut: no other decline, scope, or splitter behaviour
changes; multi-statement tails (`len(stmts) > 1`) still decline as before.

## Tests

- New `TestCompactLeafBareValueBody15139` in
  `pkg/config/compact_leaf_bare_value_15139_test.go`: partially-elided
  `system-services { ssh; }` and `protocols { ospf; }` compile to
  `[ssh]` / `[ospf]` on both strict (`CompileConfig`) and lenient
  (`CompileConfigLenient`) paths against a non-vacuous braced reference;
  policer `then loss-priority { high; }` commits with
  `ThenAction = "loss-priority high"` on both paths; valued
  `screen`/`description` controls still strict-reject (#14343).

## RED/GREEN

- RED on origin/master `ead49325b9` (fix withheld, test kept): the three
  value-leaf subtests fail — strict rejects the elided host-inbound
  spellings as unknown child keywords and the policer spelling as a
  missing value; the two #14343 controls pass. Pre-existing
  `TestElidedDepthCoverage8850` also fails on master
  (partially-elided system-services compiles to `[]`, protocols to 0)
  and `TestPolicerThenNonLeafTail_9882` (pkg/configstore) fails with the
  missing-value error.
- GREEN with fix: `TestCompactLeafBareValueBody15139`,
  `TestElidedDepthCoverage8850`,
  `TestSecurityZoneCompactLeafWithBracedBodyAndUnbracketedHeaderTokens`
  and the `TestPolicerThen*` set in pkg/configstore (including
  `TestPolicerThenNonLeafTail_9882`) all pass; `gofmt`/`go vet` clean.

## Risk

Only bare-keyword value leaves change disposition: a spelling that was
rejected/dropped now compiles to its braced meaning. Valued and flag
leaves, containers, wildcards, and multi-statement tails are untouched.
Residual: a bare flag leaf carrying a body (e.g. `discard { ...; }`)
still declines and is rejected downstream as before — pre-existing,
out of scope.
