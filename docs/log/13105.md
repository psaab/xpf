# #13105 — Count ingress-deny addresses in tightening advisories

## Why

The transition-only host-inbound tightening warning must not be suppressed when the newly compiled generation contains a lifeline-shared address only in `IngressDenyV4`/`IngressDenyV6`. In that same-commit address-and-policy transition, the old view has no copy of the address and the new empty-admit view intentionally withholds it from `V4Addrs`/`V6Addrs`.

## What

- Count `IngressDenyV4` and `IngressDenyV6` as zone address evidence in `tightenedScopesHaveAddrs10752`.
- Add regression coverage for new-generation-only IPv4 and IPv6 ingress-deny evidence, preserving zone isolation and addressless negative controls. Use the sampled live interface addresses to attribute DHCP-leased addresses to their owning unit when identical effective policies group overridden and zone-default members into one view.
- Update the #12845 transition-matcher regression: an ingress-deny-only new generation must also count as evidence; the address-only conntrack flush remains unchanged and continues to exclude these lifeline-shared addresses.

## Validation

- RED on pristine `origin/master` (`aea7b2b64455747d605faa5737ede88f50509145`): `go test ./pkg/daemon/ -run '^TestTightenedScopesIngressDenyNewGeneration13105$' -count=1` failed because the matcher ignored the deny-only address.
- GREEN after the fix: `go test ./pkg/daemon/ -run 'TestTightenedScopesIngressDenyNewGeneration13105|TestHostInboundScopesForDHCPLeaseAttribution13105|TestTightenedScopeMatcherUsesBothTransitionGenerations12845' -count=1` passed.
- `go test ./pkg/daemon/ -count=1` passed (`ok`, 378.607s).
- `go build ./...` and `go vet ./pkg/daemon/` passed.

## Risk

The change affects only whether the commit response includes a transition advisory. It does not add these addresses to the destination-only conntrack flush filter, preserving management sessions to lifeline-shared addresses.
