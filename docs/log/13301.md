# Issue #13301 — HA takeover readiness and session-mirror telemetry

Finding D5-12 (source report `review-work.AYgyxCmMxC`, audited master
`4a02183dfb009b84feb6a73cd71e05e98cb0e654`) identified that Go-side userspace
HA readiness gates and session-socket RPC failures were absent from Prometheus.
Operators could therefore miss a standby whose session mirror or recovery debt
made `TakeoverReady()` false.

The implementation exposes `Manager.HATakeoverReadiness()` as a bounded,
scrape-safe snapshot; adds explicit blockers for pending HA-state clear/replay;
and emits takeover readiness, fixed-enum blocker gauges, synced-import refusal
count, and session-socket request/error/timeout counters. Session-socket
accounting wraps the existing RPC function so all callers retain the same
socket deadline and transport behavior. The API collector obtains the snapshot
through the published dataplane backend and emits the readiness family even
when the dataplane is not loaded (when a Manager is available).

## Production adapter follow-up

The production `Boot()` path publishes `*LegacyDataPlaneAdapter`, not the
Manager directly. The first implementation's metrics probe therefore missed
the capability on the actual runtime type. `LegacyDataPlaneAdapter` now
forwards `HATakeoverReadiness()`, and a full collector regression exercises
`Collect()` through `NewLegacyDataPlaneAdapter`.

- RED before forwarding: `TestMetricsHATakeoverReadinessUsesPublishedAdapter13301`
  omitted `xpf_userspace_ha_takeover_ready`.
- GREEN after forwarding:
  `go test ./pkg/api -run
  '^TestMetricsHATakeoverReadinessUsesPublishedAdapter13301$' -count=1`.
- Full `pkg/api` package suite after this adapter fix passed.
- The full `pkg/dataplane/userspace` suite was also rerun; its pre-existing
  fixture and wire-contract failures remain outside this adapter change.

Risk: session-socket activity counters increment once at the common request
entry point. The current transport opens one connection per request, so a
separate reconnect metric is not meaningful for this implementation; no
reconnection lifecycle is maintained by the manager. Free-text diagnostic
reasons remain available from `TakeoverReady()` but are intentionally excluded
from metric labels to bound cardinality.
