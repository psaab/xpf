# #17756 — skip the root lock probe when temp ancestors are not traversable

- **Timestamp**: 2026-10-29
  - **Action**: `TestUnprivilegedCannotFlockUpgradeLock16050` now checks
    pre-existing ancestor traversal as the actual nobody identity before
    loosening any lock modes. It uses `t.Skipf` for only the root/cross-UID
    probe arm when nobody cannot reach the test root; the pre-existing
    ancestor mode assertions and chmod confinement remain. Added
    `TestSkipRootProbeForUntraversableAncestor17756`, which launches the
    actual #16050 test in a child process with a private temp root so
    removing the root-arm skip call fails the regression.
  - **File(s)**: `pkg/upgrade/lock/lock_test.go`, `debian/changelog`,
    `docs/log/17756.md`
  - **Validation**:
    - Regression RED: temporarily removed the root-arm skip call and ran
      `TestSkipRootProbeForUntraversableAncestor17756`. Its child ran the
      actual `TestUnprivilegedCannotFlockUpgradeLock16050` and failed in the
      permissive control probe with `Permission denied` under a root-owned
      0700 ancestor.
    - Regression GREEN: restored the guard; the regression passed after
      observing the child's named skip reason and confirming the 0700
      ancestor remained unchanged. The standalone target test also skipped
      with that reason under the same setup.
    - Root named tests for the new guard, the #16050 probe, and its portable
      mode checks passed with a traversable `/tmp` path.
    - `go test ./pkg/upgrade/lock -count=1` passed; `go vet
      ./pkg/upgrade/lock` and `gofmt` were clean.
  - **Risk**: Only the root/nobody probe is skipped when its pre-existing
    path cannot be traversed by nobody; the portable lock-mode checks still
    run, and the full chmod-confinement/security probes remain in traversable
    environments. Production lock code is unchanged.
