# #16514: configured `interfaces gr-… [unit N] mtu` was not used on userspace transit

- **Timestamp**: 2026-10-24
- **Issue**: #16514 (R3-A68-01)
- **Cause**: `native_gre_inner_mtu` — the single SSOT for the PTB
  decision, the GRE MSS clamp and TCP re-segmentation — derived the
  inner budget only from the physical transport MTU
  (`tunnel_outer_mtu` − outer IP − GRE header). The gr- logical MTU
  was accepted by the config compiler and applied to the kernel
  anchor, and the Go snapshot already carried it
  (`TunnelEndpointSnapshot.MTU = iface.MTU`, where the interface row
  MTU is the configured unit MTU else the kernel anchor MTU), but
  `forwarding_build/tunnels.rs` never consumed `endpoint.mtu` and
  the runtime `TunnelEndpoint` had no MTU field. DF IPv4/IPv6 flows
  larger than the configured MTU were encapsulated instead of
  answered with Frag-Needed/PTB, and TCP SYNs were clamped to the
  physical-derived MSS (1436 rather than 1360 for MTU 1400) — a
  PMTUD black hole on a smaller downstream underlay path.
- **Action**: carried `TunnelEndpointSnapshot.mtu` into
  `TunnelEndpoint.mtu` (validated by a new `TunnelMtu` newtype:
  negative fails the snapshot closed via `InterfaceMtuInvalid`,
  0 stays the non-limiting "unknown" sentinel) and capped the
  physical-derived budget in `native_gre_inner_mtu` with
  `min_nonzero_mtu(physical_inner, endpoint.mtu)`. GRE only — the
  helper is never called for WireGuard (#2680/#2684 derive WG from
  the physical underlay). The #2331 encap drop guard in `gre.rs`
  stays physical-only (it refuses outer frames the NIC cannot
  transmit); inner packets between the logical MTU and the physical
  budget are PTB'd / MSS-clamped / re-segmented before reaching it.
  An unconfigured GRE anchor defaults to 1500, so
  `min(1476, 1500)` keeps the historical value bit-for-bit.
