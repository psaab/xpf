# #15115: fix the #9727 jumbo-MTU advisory budget (kernel XDP_PACKET_HEADROOM)

## Reproduction and fix

The #9727 commit advisory computed the single-frame receive budget as
`4096 - 256 - 14 - 4 = 3822`, counting only the configured UMEM headroom.
The kernel adds its own fixed `XDP_PACKET_HEADROOM` (256) on top:
`xsk_pool_get_headroom` returns `XDP_PACKET_HEADROOM + pool->headroom`, and
`xsk_pool_get_rx_frame_size` is therefore `4096 - 512 = 3584`. Without
multi-buffer (`XDP_USE_SG` appears nowhere in the AF_XDP bind), a frame
longer than that is dropped by the kernel (`rx_dropped`, surfaced as
`kernel_rx_dropped`) in copy mode, or a zero-copy driver refuses the bind.
The Rust side already documents this (`UMEM_HEADROOM` comment in
`userspace-dp/src/afxdp/mod.rs`: "native RX descriptors land at frame
base + 512"). MTUs 3567..3822 therefore committed silently while
full-size frames never reached a worker.

The budget is now `4096 - (256 + 256) - 14 - 4 = 3566`, with a named
`userspaceXDPacketHeadroom` constant, and the warning text names both
headroom terms. The advisory stays a warning, not an error, for the
#9727 reason (copy vs zero-copy cannot be distinguished at commit, and a
jumbo MTU remains correct for kernel-forwarded traffic). Interfaces the
dataplane does not bind, unit-MTU override, and tolerant-path suppression
are unchanged — those paths just compare against the corrected budget.

## Regression

`pkg/config/userspace_rx_mtu_advisory_15115_test.go`:

- `TestRxMTUBudgetIncludesKernelXDPHeadroom15115` parses `UMEM_FRAME_SIZE`
  and `UMEM_HEADROOM` from the Rust source and derives the budget
  independently as `frame - (256 + UMEM_HEADROOM) - 14 - 4 = 3566`; it
  never reads the boundary from `userspaceRxMTUBudget`, so reverting the
  Go budget to 3822 fails instead of silently moving the boundary.
- `TestRxMTUAdvisoryWarnsInsideFormerSilentWindow15115` pins the exact
  boundary: 3566 does not warn; 3567, 3700 and 3822 (the former silent
  window) warn; 3823 still warns; 1500 control stays silent. Warnings
  must name `3566`, `XDP_PACKET_HEADROOM` and `UMEM headroom`.

RED on `origin/master` (before the fix): budget derived 3566 vs actual
3822, and 3567/3700/3822 produced no warning. GREEN after the fix.

## Validation

- `go test ./pkg/config/ -run 'TestRxMTUBudgetIncludesKernelXDPHeadroom15115|TestRxMTUAdvisoryWarnsInsideFormerSilentWindow15115|9727' -count=1`: PASS.
- `go test ./pkg/config/ -run 'TestJumboMTU|TestRxMTU|TestUserspaceUMEM' -count=1 -v`: PASS (existing #9727 neighbour controls — boundary/unit override, per-exclusion silence, mgmt/control data-NIC warns, tolerant suppression, UMEM drift guard, compiled-config wiring — all green; the boundary cell derives from `userspaceRxMTUBudget` so it now exercises 3566/3567).
- `go vet ./pkg/config/`: clean.

## Risk

Operators with a zoned interface MTU in 3567..3822 now get a commit
warning that previously did not fire; that is the bug fix — those MTUs
were already dropping full-size frames. No commit is newly rejected,
and no behaviour changes outside this advisory.
