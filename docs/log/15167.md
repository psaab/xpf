# Issue #15167 — Unicode-space desync between config gate and local CLI executor (V47-S1)

## Defect

Local on-box CLI (`pkg/cli/cli_dispatch.go:dispatchConfig`) gated the raw
line with the config lexer (`checkConfigRegex` →
`config.AuthorizeConfigMutation` → `lexConfigMutationLine9938`) but executed
`set`/`delete`/`deactivate`/`activate` from `strings.Fields(line)` tokens,
joining them with ASCII spaces into the store input.

The config lexer (`pkg/config/lexer.go`) treats only ASCII
`' '`/`'\t'`/`'\n'`/`'\r'` as whitespace and stops at a non-ASCII byte with
`TokenError`; `lexConfigMutationLine9938` returned only the tokens lexed so
far (a prefix). `strings.Fields` is unicode-aware. So, for a restricted
login class:

- `set<NBSP>system login class limited permissions all` — the gate lexed
  only `set` (not gated, no path) while Fields executed the full
  `system login ...` path: self-escalation to rewriting the operator's own
  login class, with no raw-gRPC client needed.
- `set system<NBSP>login ...` (also EM SPACE U+2003, VT, FF, NEL U+0085,
  LINE SEPARATOR U+2028, ...) — the gate judged `system` alone, which a
  deny on `system login` does not match, while Fields executed the denied
  path.

Same mechanism for `delete`, `deactivate`, and `activate`. #14716 covered
only the `edit` cursor; #14717 covered local `annotate`; #14147 covered
copy/rename/insert. No owner covered the flat verbs on the local CLI.

## Fix

Execute what was adjudicated, and fail closed where adjudication is
impossible (`pkg/config/authz_config_mutation_9154.go`,
`pkg/cli/cli_dispatch.go`):

- `lexConfigMutationLineStrict15167` is the strict form of the gate lexer:
  it additionally reports whether the whole line lexed cleanly (false on a
  `TokenError` — non-ASCII byte, unterminated string/comment — or a
  structural `{ } ; |` token). `lexConfigMutationLine9938` now delegates
  to it, discarding the flag, so every existing lenient caller is
  byte-identical.
- `AuthorizeConfigMutation` (the shared decision, B23-01) fails closed on
  `!ok` when the line's prefix carries a gated verb AND the class actually
  configured `*-configuration` regexes: `permission denied: login class
  %q denies %s under %q (the line does not lex cleanly, ...)`. Unrestricted
  classes (no regexes, or the empty-class legacy bypass) return before
  this arm, so their malformed lines keep the executor's ordinary error.
  This also covers the gRPC/REST/eventengine callers of the same decision
  for a line they would act on.
- `config.ParseConfigMutationLine` exports the strict parse. The local
  CLI's `set`/`delete`/`deactivate`/`activate` arms now derive their path
  from it (verb token included, checked against the dispatched verb) and
  refuse a non-lexing line with `<verb>: invalid path` for every class,
  instead of re-splitting with `strings.Fields`. Quoted elements, comments,
  tabs, and bracket lists therefore execute exactly as the gate judged
  them; a quoted path element containing spaces now executes as the single
  element the gate saw instead of being re-split by the store's re-parse
  of a Fields-joined string (the A53-07 value-corruption direction on
  these arms).

NOT changed: the store's `*FromInputAsPlantClass` parsers, the gRPC/REST
handlers' own input handling (their gate call now fails closed on
non-lexing lines for restricted classes; their executors were already
lexer-based via `ParseSetVerbGroupedClosed`), navigation verbs, or any
neighbouring behaviour for clean ASCII lines.

- `pkg/cli`: `TestDispatchConfigUnicodeSpaceDenied15167` — NBSP/EM-space
  after the verb and inside the path, VT/FF after the verb, NEL and LINE
  SEPARATOR inside the path, across `set`/`delete`/`deactivate`/`activate`,
  plus the own-class self-escalation spelling, driving the real
  `dispatchConfig` against a committed `deny-configuration "system login"`
  class; each cell asserts a deny refusal and a byte-identical candidate.
- `pkg/cli`: `TestDispatchConfigUnicodeSpaceControls15167` — plain-ASCII
  denied `set system login ...` still denied; `set system services telnet`
  still allowed (issue-named control, under an allow-configuration class);
  allowed host-name, quoted-element, and tab-separated spellings still
  allowed and reach the candidate.

candidate mutated (e.g. `delete<NBSP>system login class limited` removed
the class; `set<NBSP>system login ...` planted `permissions all`). GREEN
after the fix (all denied cells + all controls).
