# Issue #12220 — diagnose predefined application-set shadowing

## Why

A user `application-set junos-http` shadows the predefined `junos-http` application through two resolution paths: a direct policy reference resolves application-first to predefined tcp/80, while a nested reference through a parent application-set resolves user-set-first to the user set's tcp/8443 member. The strict collision gate did not diagnose this cross-kind pair, so one token silently acquired different enforced meanings.

## What

The application-name AST gate now rejects a user application-set whose name matches a predefined application on strict commit and warns on lenient load. The lenient path records the colliding name in compiler metadata so direct and nested policy references are refused rather than using an arbitrary winner. The existing permitted user-application shadow of a predefined application remains unchanged. Added strict/lenient regression coverage with direct and nested policy references and updated the gate documentation.

## Validation

- **STEP-0** (`a714c90d472a3c3d98a3799831cfef3ec311a61c`): temporary repro on the clean base showed `CompileConfig` accepted the configuration with no warnings; direct `junos-http` resolved to tcp/80, while `parent` expanded to `custom8443` (tcp/8443). The lenient path also emitted no warning. The throwaway repro file was removed.
- **RED before:** `go test ./pkg/config -run '^TestApplicationSetShadowsPredefinedApplication' -v` failed because strict compile accepted the shadow and the lenient path returned no #12220 warning.
- **GREEN after:** all 20 tests in `compiler_applications_collision_3339_test.go`, including the strict reject, lenient warning/quarantine, and existing collision controls, passed with `-count=1`.
- `go build ./pkg/config/... ./pkg/dataplane/userspace/...` passed.
- `gofmt -l` on all four changed Go files produced no output.
- Broader `go test ./pkg/config ./pkg/dataplane/userspace` failed on unrelated config fixture/gate assertions and timed out after 10 minutes in `TestSchemaSpellingDifferentialGate`; the userspace package also had three existing failures (`TestNilUnitSlotCastsNoTrunkZoneVote_6722`, `TestRetainedLiveXfrmiLeavesTheAdjudicatedSets/untracked_after_daemon_restart`, and `TestSnapshotShapeIsPinnedToProtocolVersion8892`). A clean-base run with `-count=1` reproduced the same config failures, timeout, and userspace failures at `a714c90d4`.

## Risk / residual

Strict commits now reject this previously silent application-set/predefined-application shadow. Lenient loads still boot with a warning, while affected policy references fail closed. The broader package-suite failures and timeout reproduce on the base; no live-cluster mutation or validation was performed.
