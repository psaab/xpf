# #12903 - gRPC ShowText security handlers: nil-map hardening and omitted fields

- **Timestamp**: 2026-10-14
- **Action**: The five gRPC `ShowText` security handlers in `pkg/grpcapi/server_show_security_text.go` dereferenced present-but-nil pointer-valued map entries without guards — `showSchedulers` (`sched.StartTime`), `showApplications` (`app.Protocol`), `showDynamicAddress` (`feed.URL`), `showAddressBook` (`addr.Value`, `as.Addresses`), and `showIKE` (`gw.Address`, `pol.Mode`, `p.AuthMethod`). Such slots are admitted by the tolerant-load / peer-sync path (#1960) — the same nil-tolerant class the application-set guard (#5221) and the local CLI's address-book guards (#7197) already skip — so one poisoned slot panicked the RPC display path (D9-13). Every handler now skips the nil slot and still renders the real siblings. Three omissions are also closed: `showApplications` renders `ICMPType`/`ICMPCode` (`icmp-type=8 icmp-code=0`, #11340) so a constrained ICMP application no longer presents as matching every type/code; `showAddressBook` renders nested `AddressSets` members with the same `set:` prefix the local CLI uses, so a grouping set no longer under-counts what it matches; and `showDynamicAddress` renders the entire `Dynamic Address Bindings:` section with per-binding fail-mode and `Enforced:` verdicts. The verdict sentence moved from the CLI's private `dynamicAddressBindingEnforcement` to the shared `feeds.BindingEnforcement` (`pkg/feeds/binding_enforcement.go`) and both surfaces call it, so the local and remote `show security dynamic-address` cannot drift from each other or from `feeds.Manager.SnapshotForBindings` (#5645/#9689 fail-closed doctrine: unresolved ⇒ policies referencing the name are rejected and the previous-good policy set stays enforced).
- **Validation**: New regressions in `pkg/grpcapi/server_show_security_text_nil_12903_test.go`, RED on pristine master `39a53bda3` (origin/master) and GREEN post-fix: `TestShowSecurityTextNilMapValuesNoPanic12903` (bounded table, one nil value per distinct pointer-valued map — schedulers, applications, application-sets [control row for the pre-existing #5221 guard], feed-servers, address-bindings, address-book addresses, address-book sets, IKE gateways, IKE policies, IKE proposals; 8 rows fail by panic on master), `TestShowApplicationsRendersICMPTypeCode12903`, `TestShowAddressBookRendersNestedAddressSets12903`, `TestShowDynamicAddressRendersBindingsEnforced12903` (retain/drop rows, `current prefixes` and the unresolved fail-closed verdict), and `TestShowTextDynamicAddressBindingsTopic12903` (full `ShowText` topic dispatch against a really committed config). Full `pkg/grpcapi`, `pkg/cli`, and `pkg/feeds` suites ok; `go vet` clean on all three; `gofmt` clean.
- **Risk**: Show-path rendering only — no matcher, wire, compiler, or dataplane change. Nil slots that previously panicked the handler are now skipped (fail-closed display: the slot is omitted, the rest of the table still renders). The bindings section is additive output on the `dynamic-address` topic; existing feed rows are byte-identical. The CLI's `Enforced` sentences are unchanged byte-for-byte (same code, new home). A consumer diffing the full `show security dynamic-address`/`applications`/`address-book` output will see the new sections/fields — that is the fix.
