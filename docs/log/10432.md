# #10432 — NAT64 embedded ICMP preserves original inner length

## Change

`userspace-dp/src/nat64.rs` now keeps the RFC 7915 advertised length separate from the bytes physically present in an ICMP quote:

- v6→v4 advertises `20 + (IPv6 Payload Length - stripped extension-header bytes)` while copying only the quoted L4 bytes.
- v4→v6 advertises `IPv4 Total Length - IHL`, plus a generated IPv6 Fragment Header when required, while copying only the quoted L4 bytes.
- Both paths retain fixed-scratch bounds and fail closed on malformed or unrepresentable lengths.

The regression fixtures use a truncated quote of an original 1500-byte datagram: v6→v4 receives 48 bytes (IPv6 header + 8 L4 bytes) and emits 28 bytes; v4→v6 receives 28 bytes (IPv4 header + 8 L4 bytes) and emits 48 bytes. The advertised embedded length is 1480 in both directions.
