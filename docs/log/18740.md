# #18740: no XDP transition on em0/fxp0 per commit

Per-issue log (see `docs/log/README.md`).

- **Timestamp**: 2026-11-01
  - **Action**: Kept the control-plane netdevs (`fxp*` management, `em*`
    cluster control link) out of the shim's attach set.
  - **Why they should not get the shim at all**: the userspace dataplane
    never adjudicates them.
    - Its ingress set excludes them by name (`ingress_exclusions.go`).
    - The shim's verdict for an ifindex outside that set is
      `cpumap_or_pass` (the #8279 gate in `userspace-xdp/src/lib.rs`), so
      host traffic reaches the kernel exactly as with no program.
    - `syncInterfaceAttachments` detaches them at every acceptance point.
    - The attach existed only because `compileZones` queues every zoned
      netdev. The forward fence (#10302) governs transit, which these do not
      carry.
    - So the fix is at the source, not a smarter detach.
  - **Change**:
    - `dataplane.ControlPlaneNetdevNameClass` names the `fxp`/`em` classes.
    - `compileZones` leaves those netdevs, and VLAN children of them, out of
      `pendingXDP`/`pendingTC`, and records each as a SKIPPED unarmed
      surface.
    - The userspace "fxp name"/"em name" ingress classes now call the same
      predicate, so the two halves cannot disagree.
    - `fab*` stays shimmable: `fab0` resolves to its member's parent, which
      carries the fabric redirect path.
    - Test seam: `SetXDPTransitionSeamForTest`, consulted at the top of
      `AttachXDP`/`DetachXDP`, so the #7547 call-site census is unchanged.
  - **Cells**:
    - `pkg/dataplane/controlplane_netdev_18740_test.go`:
      - the attach-set wiring with an arm-proof check;
      - 20 unchanged commits make exactly one transition (the first attach
        of the dataplane link), and AttachXDP's real "already attached"
        path runs on every later commit;
      - a zone-change twin attaches exactly the new link;
      - a control-plane VLAN child is skipped, not uncovered;
      - the name classes.
    - `pkg/dataplane/userspace/controlplane_detach_18740_test.go`:
      - 20 unchanged acceptance passes detach nothing;
      - controls: a stale em0 link is still cleaned up, and a zone change
        still detaches;
      - the attach exclusion is always an ingress exclusion.
  - **Mutants**: all killed.
    - no attach-set gate;
    - no VLAN-child gate;
    - record marked StillForwarding;
    - `fab` added to the class;
    - the userspace em class diverging.
  - **File(s)**:

      `pkg/dataplane/compiler_iface.go`, `pkg/dataplane/loader.go`,
