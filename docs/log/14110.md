# Issue #14110 — compileNAT persistent-NAT pool registration ignores pool.Address / CIDR expansion

- **Issue:** `compileNAT` registered persistent-NAT pool IPs from only `pool.Addresses`, and for a CIDR member only its parsed network/base IP. The userspace SNAT allocator uses `config.SourceNATPoolMembers(pool)` (singular `pool.Address` plus `Addresses`) with every CIDR member expanded over its full masked prefix (`expand_pool_address`, cap `MAX_POOL_PREFIX_HOSTS=65536` per member). `preservePersistentNATV4/V6` (`pkg/dataplane/session_store.go`) looks up the translated IP in the persistent table before saving, so any binding allocated to a non-base CIDR member — or to a singular-`address` pool — was silently not preserved on Go-side session deletion.
- **What:** Added `config.SourceNATPoolExpandedAddresses` (`pkg/config/nat_pool_capacity.go`): the unique expanded address set the dataplane installs, reusing `SourceNATPoolMembers`, the all-or-nothing `SourceNATPoolUnusableReason`, and the existing masked-interval expansion (`sourceNATPoolAddressIntervalOf`), deduped first-occurrence like the Rust allocator. `compileNAT` (`pkg/dataplane/compiler_nat.go`) now registers exactly that set via `RegisterNATIP`. Fail-closed: an unusable pool (unparseable/malformed/over-capacity member, `%zone` member, invalid port range, empty) or a pool over the aggregate budget (`SourceNATAggregateOverBudgetPools`, the same verdict the snapshot builder poisons with) registers nothing — not a narrowed subset — and logs a warning instead of `persistent NAT pool registered`. No new persistent-table method was added, so the #4960 pre-pass exemption (exact pnat method count) is unchanged; `ClearPoolConfigs` at compile top still clears stale registrations before re-registration.
- **Regression:** `TestPersistentNATPoolRegistrationExpandsMembers14110` (`pkg/dataplane/compiler_nat_persistent_pool_14110_test.go`) compiles a `/29` + `/126` persistent pool, a singular-`address` pool, an invalid-member pool, and an over-capacity `/15` pool; asserts every expanded member resolves via `LookupPool`, unusable pools register nothing, the set survives recompile, and `preservePersistentNATV4` saves a binding for non-base member `192.0.2.5`.

## RED -> GREEN proof

- **RED:** On the pre-fix code, `go test ./pkg/dataplane/ -run TestPersistentNATPoolRegistrationExpandsMembers14110 -count=1` failed: `LookupPool` missed `192.0.2.1/.5/.7`, `2001:db8:1::2/::3` and the singular `198.51.100.7`; the invalid-member and over-cap pools wrongly registered their base IPs (`203.0.113.0`, `10.0.0.0`); recompile lost `192.0.2.6`; and `preservePersistentNATV4` saved no binding for `192.0.2.5`.
- **GREEN:** Same command passes with the fix. `go vet ./pkg/config/ ./pkg/dataplane/` clean, `gofmt` clean.
