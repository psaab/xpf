# #14366 — IPsec-inner zone-policy passes packet_icmp=None, defeating type-constrained ICMP DENY

## Why

`d14_zone_gate` in `userspace-dp/src/afxdp/ipsec_inner.rs` called
`evaluate_policy_result_l3_aware` with a literal `None` for the
`packet_icmp` argument. In `policy.rs`, an ICMP type-constrained term
(`junos-icmp-ping` = type 8) matches only when `packet_icmp` is `Some`
and equals the constraint; with `None` the term never matches. An
authenticated IPsec peer (or any host behind it admitted by the tunnel
selectors) therefore did not get the configured type-constrained
verdict on the one zone-policy enforcement that runs on this path; no
compensating check exists downstream (the Go NFQUEUE side performs no
zone-policy/ICMP check here, and the packet is not re-queued after the
Rust `WouldPermit` adjudication).

Measured nuance: on this path `l4_present` is `false` for ICMP (ports
are only parsed for TCP/UDP), so the evaluator's #4569
fragment-association override (`has_l4_constrained_term` treats
`packet_icmp=None` plus a type-constrained DENY as L4-need) happened to
deny the deny-above-permit type-8 cell anyway — but it cannot
distinguish type 8 from type 3 with the type unknown, so it over-denied
the type-3 fall-through and permit-ping type-8 cells. The override is
a fragment safety net, not ICMP-type enforcement.

## What

- In `d14_zone_gate`, parse the real ICMP type/code from the already
  built owned logical-ingress frame with the existing helper
  `crate::afxdp::poll_descriptor::policy_packet_icmp(&owned, meta)`
  (re-exported `pub(in crate::afxdp)`, the same helper the main transit
  path uses) and pass it to `evaluate_policy_result_l3_aware` instead
  of `None`.
- The helper returns `None` for non-ICMP protocols (`meta.protocol` on
  this frame is `input.protocol`, including the native-fragment
  sentinel value 255) and for truncated / non-first-fragment frames
  (via the declared-length-bounded `term_match_extra_from_frame`), so
  fail-closed behaviour there is unchanged. TCP/UDP verdicts are
  bit-identical: the argument stays `None` for them.
- NOT changed: the deny arm (stage `d15_zone_policy`, reason
  `LEGACY_POLICY_DENY`), port parsing, fragment handling, and the
  selector/route/zone gates above the policy call. The evaluator keeps
  receiving `effective_protocol` (AH-sighted IPv6 stays protocol 51);
  `packet_icmp` additionally stays `None` on AH/fragment frames, which
  is the pre-existing fail-closed posture for constrained terms.
- Regression cells in `ipsec_inner.rs` `mod tests`, mirroring the
  existing `port_term_policy`/`v4_l4_packet` helpers: four
  `d14_icmp_*_14366` cells over `adjudicate_ipsec_inner` with rules
  carrying explicit `policy_id`s (101 deny / 102 permit) so the verdict
  attribution is asserted, not just the deny bit.

## Risk

ICMP/ICMPv6 inner frames now have their real type/code honoured by the
one zone-policy enforcement on this path, so a configured
type-constrained DENY (or PERMIT) takes effect as configured — this
also removes the spurious #4569-override denies of legitimately
permitted ICMP types. Frames whose type/code cannot be read
(non-first fragments, truncated, AH-sighted) keep the previous `None`
behaviour. ICMPv6 flows through the same helper via `PROTO_ICMPV6`;
the regression cells exercise IPv4 ICMP per the issue's decisive
criterion.
