# #14679 - NAT64 singular pool, persistent-NAT atomic swap, DNAT stamp

- **Timestamp**: 2026-10-17
- **Action**: `compileNAT64` auto-assign now uses
  `config.NAT64PoolHostAddresses` (new in
  `pkg/config/compiler_validate_strict_nat.go`): members via
  `SourceNATPoolMembers` (singular `Address` plus `Addresses`), each must be a
  bare IPv4 or `/32` host mirroring Rust `parse_pool_v4`; any non-host/IPv6/bad
  member poisons the whole pool and returns the existing
  `has no valid addresses` hard error. Valid NAT64-only pools with
  `PersistentNAT` are staged for registration. `compileNAT`/`compileNAT64`
  now stage all persistent registrations in `natPersistentStaging` and swap
  them atomically via `PersistentNATTable.ReplacePoolConfigs` only after both
  phases succeed in `CompileConfig` (and after a standalone wrapper
  succeeds); a failed compile therefore leaves prior `poolConfigs`/
  `natIPToPool` intact, while a successful empty recompile removes stale
  pools. Destination NAT now checks `HasNATFromScopeStamp()` like source NAT.
  Pre-pass guards updated for the `WithStaging` call names and the single
  staged `ReplacePoolConfigs` call.
- **Validation**: RED on `origin/master` 08f11138a5: new
  `compiler_nat_14679_test.go` cells failed as predicted (singular NAT64 pool
  rejected, poisoned pools accepted, NAT64 persistent pool not registered,
  failed compile wiped pools, unstamped DNAT passed). GREEN after fix:
  `go test ./pkg/dataplane/ -run 'TestCompileNAT64|TestCompileNATFailure|TestCompileNATSuccess|TestCompileNATRejectsUnstamped|TestPersistentNATPoolRegistration|TestPrePassPersistentNAT|TestPrePassRowOrder'` passes;
  `pkg/config` NAT64/source-pool tests pass. Pre-existing base failure
  `TestValidationPassRecordCensus6903` ("invalid pool address" disappeared)
  reproduced on stashed base at the same head, not caused by this change.
- **Risk**: NAT64 pools referenced only by NAT64 now hard-fail in the
  pre-pass when any member is not an IPv4 host (previously silently skipped
  members); this matches the Rust all-or-nothing skip. SNAT prefix pools keep
  their expanded SNAT semantics, not NAT64 host semantics.
