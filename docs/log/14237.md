# Issue #14237 — route-reject regression now covers the call-site ifindex defect

## Why

Hostile review of merged PR #14108 (issue #14021, `93da244c4b20`) found its
regression `route_reject_suppresses_synthetic_fabric_source_14021` passes on
pristine `7a4cc2ccdf10`: it calls `enqueue_route_reject_reply(..., 21, ...)`
directly with the post-fix argument, so it exercises only the already-correct
helper/gate and never the production call site in
`poll_descriptor/mod.rs`, the only place the defect lived (the arm resolved
the VLAN logical unit, e.g. 5, and passed it to the synthetic-fabric-source
gate, which keys `ingress_is_fabric` on the physical parent/overlay, e.g.
21 — the lookup missed the fabric link and an ICMP unreachable reflecting
the synthetic V2 stamp MAC was emitted and counted as sent).

## What

- `reject_reply.rs`: extract the `RejectRoute` disposition arm into
  `handle_route_reject_disposition` (cold, `#[inline(never)]`, mirroring
  the `deny_reply_and_emit` #3615 seam rationale: the poll-loop body is
  un-callable). The seam forwards its `binding_ifindex` argument verbatim
  to `enqueue_route_reject_reply` and guards on the disposition, so
  non-`RejectRoute` dispositions stay silent through it.
- `poll_descriptor/mod.rs`: the `RejectRoute` arm now calls the seam with
  `binding.ifindex` (unchanged value, unchanged telemetry).
- `reject_reply_tests.rs`: new
  `route_reject_disposition_arm_uses_physical_binding_ifindex_14237` drives
  the seam exactly as the poll arm does — physical binding 21 with fixture
  logical unit 5 via `ingress_logical_ifindex (21, 0) -> 5` — against a
  producer-minted V2 stamp. Premise asserts pin that 21 is fabric / 5 is
  not, that `(21, 0)` resolves to 5, and that the gate suppresses under 21
  but not under 5. Controls: `DiscardRoute` through the seam stays silent;
  an unstamped `RejectRoute` through the seam still enqueues `[3, 1]`
  (host-unreachable). The existing direct-helper test is kept as the gate
  unit test. Stamped + unstamped legs use the reserved-budget pipeline
  sizing (`SYN_COOKIE_REPLY_PENDING_RESERVE * 2 / +1`) so `tx_pipeline(64, 64)`
  budget suppression cannot pass/fail the cell for a fixture reason.
  NOT changed: `enqueue_route_reject_reply` / shared gate behavior,
  counters, wire formats; no FIB change (scope is the disposition→reply
  seam the acceptance allows).

## Validation

- GREEN (head): `cargo test -p xpf-userspace-dp --bin xpf-userspace-dp -- route_reject`
  → 5 passed (incl. the new cell and the kept #14021 cells).
- RED (mutant): with the seam temporarily mutated to the pre-fix body
  (resolve logical from `meta` and pass it — the pristine arm's logic),
  the new cell FAILS at "stamped fabric RejectRoute via the disposition
  arm must not enqueue" while the old direct-helper cell still passes —
  exactly the discrimination #14237 requires. Mutant restored from backup.
- RED (pristine transplant): tests-only transplant onto a separate
  `7a4cc2ccdf10` worktree fails to compile (`handle_route_reject_disposition`
  does not exist pre-fix, 3 × E0425) — the regression cannot pass on
  pristine. The behavioral pristine-equivalent RED is the mutant above,
  whose body is byte-identical to the pristine arm's computation.
- Full `reject_reply` module suite on head: see PR.

## Risk

Pure extraction + test: the production arm passes the same `binding.ifindex`
it passed after #14108; the seam adds one cold `#[inline(never)]` call on
the already-cold reject exception path. No counters or wire formats changed.
