- **Timestamp**: 2026-10-16
  - **Action**: #14594 — xpf's own `networkctl reconfigure` stripped the
    daemon DHCP lease address from non-RETH DHCP interfaces. The lease is
    written only by `pkg/dhcp` `applyAddress` (`AddrReplace`, no
    lifetimes), so it is foreign to systemd-networkd; the generated
    `.network` carried `KeepConfiguration=static` only for VRRP RETH
    rows, and `Apply` reconfigures every managed interface on any file
    change, so an ordinary commit removed a DHCP WAN / DHCP fxp0 address
    until at least T1 while reporting success. Fix: `pkg/networkd`
    `keepConfigurationValue` composes the single systemd value from the
    address classes actually present — `static` (KeepAddresses with a
    rendered static address), `dhcp` (DHCPv4, or stateful DHCPv6
    requesting IA_NA), `yes` when both — and `generateNetwork` emits it.
    `pkg/dataplane` now populates `DHCPv6Stateless`/`DHCPv6IATypes` on
    every DHCP-bearing model (secure-tunnel, VLAN sub-interface, and
    merged non-VLAN, where stateless survives only if every DHCPv6 unit
    is stateless and IA types union) so stateless and PD-only DHCPv6,
    which own no address on the interface, do not widen the keep.
    Regression tests: `pkg/networkd/dhcp_keep_configuration_14594_test.go`
    (RED on master: unknown-field build failure; value cells fail
    without the emit) and `pkg/dataplane/dhcp_keep_model_14594_test.go`
    (model flags per unit shape). Lab criterion from the issue (commit a
    description change with `family inet dhcp` and confirm the lease
    survives) remains operator/lab verification.
