# 12585 — snapshot reclaimer wait budget

- **Timestamp**: 2026-10-13
- **Action**: snapshot the claim wait timeout before launching the detached reclaimer
- **Base**: `33c04c376` (`config: canonicalize padded route and IPsec masks (#12507)`)
- **Files**:
  - `pkg/ra/ra.go`

## Why

The detached tombstone reclaimer read the package-global `claimWaitTimeout` only after the draining owner stopped. Tests shorten that package-var seam and restore it at teardown; the detached read could race the restore after `Apply` returned.

## What

Capture the configured timeout synchronously when arming the reclaimer and pass the captured duration to its replacement readiness wait. This makes the reclaimer use the budget in effect when it was armed and removes its asynchronous read of the mutable package variable. Test assertions and timeout durations are unchanged.

- `go vet ./pkg/ra`: passed.

## Risk

The reclaimer's bounded readiness wait now uses the duration captured at launch, rather than a later value of the package test seam. Production configuration and sender/drain behavior are unchanged.
