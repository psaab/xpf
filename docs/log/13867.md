# Issue #13867

## Change

Persist a per-peer generation floor captured when a local persistent-NAT
clear revokes the helper's entire lease table. Equal or older lease batches
from those known peers are discarded before helper IPC, so delayed equal-
generation snapshots cannot restore leases for keys that had no per-key
allocator tombstone. A forwarded peer clear exempts that peer only when its
clear generation advances the known generation; its genuinely post-clear
batch remains importable. Existing old-generation rejection remains in place.

The new state field is optional on disk and defaults to an empty map when
loading older state files. The floor is stored with the existing durable
lease-generation state before the clear, so it survives daemon restart and
shares the existing atomic persistence behavior.

## Validation

- Regression on unchanged behavior failed as expected: delayed generation-8
  batch reached the helper as `import_idle_leases` after local clear.
- Focused regression after the fix passed, including restart persistence,
  older-generation rejection, and generation-9 post-clear import followed by
  same-generation additive import.
- `cargo test --bin xpf-userspace-dp idle_lease` passed: 72 tests (8,078
  filtered).
- Full `go test ./pkg/dataplane/userspace -count=1` was attempted twice. It
  did not pass due failures in untouched tests, including snapshot
  golden/shape drift, unrelated userspace/zone assertions, and Unix socket
  path-length failures. The focused #13867 test passed with a short test name
  and `/var/worktrees/go-tmp`.
- `cargo test --lib idle_lease` could not run because the crate has no library
  target; the binary-target idle-lease test above was used instead.

## Risk

A peer origin first observed only after a local clear has no prior generation
floor to capture; it remains governed by the existing generation protocol.
The per-peer map is bounded by the existing remote-peer limit. Rust allocator
fences and their per-key policy are unchanged: the new batch-wide freshness
rule is enforced at the durable Go admission boundary before validated helper
imports.
