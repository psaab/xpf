- **Timestamp**: 2026-10-25
  - **Action**: Fix `xpfd upgrade` installing no signal disposition
    (#16796, R3-A54-01), so SIGINT/SIGHUP during the STOP window killed
    the runner after `systemctl stop xpfd` and left a standalone daemon
    down until a human re-ran the verb. New
    `pkg/upgrade/signal_defer_16796.go`: `SignalGuard` captures
    SIGINT/SIGHUP/SIGTERM via `signal.Notify` (seamed for the
    production-wiring test), records the first signal, and logs it as
    deferred. `Runner.Run` and `Runner.RollbackTo` consult the guard
    (plumbed via `Options.SignalGuard` / `RollbackOptions.SignalGuard`)
    at entry, post-journal, and immediately-before-STOP boundaries:
    before STOP a pending signal aborts cleanly (daemon live, no
    StopUnit); at/after STOP it is logged as deferred at FLIP/rollback
    and honoured only after COMMIT/rollback completes with the unit
    running (returned as an error so the CLI exits non-zero — the cut
    itself committed, and `LastCommittedCut`/status supersession were
    already recorded). A ROLLINGBACK/STOPPED journal resume never
    aborts on a pending signal. `RunRolling`/`RunRollingRollback`
    install the guard for the drain+cut window and forward it through
    `RollingConfig.SignalGuard` to the inner cut/rollback.
    `cmd/xpfd` `runUpgradeSubcommand` installs the guard for the whole
    verb (binary cut, `--rollback`, `--rolling`, and the `upgrade
    kernel` sub-verb, whose mutating verbs now also survive a terminal
    drop instead of dying mid-BootOrder/drain) and threads it into the
    standalone Run/RollbackTo calls; the read-only `upgrade status`
    verb installs no capture. Second interrupts after STOP are
    deliberately still deferred; SIGKILL/power loss remain covered
    only by the existing journal resume.
