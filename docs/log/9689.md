## Decision

The issue asks for a per-binding fail mode, `retain` (today) versus `drop`, and for the show surface to agree with enforcement. Both are taken.

The decision is additive:
- the default is `retain`, so a config without the leaf behaves exactly as before;
- `drop` is an explicit per-binding operator choice, in the direction the issue describes;
- **no dataplane change was needed.** `addrRepresentable` in `policies_lower.go` already treats a binding PRESENT in the feed overlay with no prefixes as match-none (#2049), and only an ABSENT declared binding as unrepresentable. So `drop` is entirely a feeds-side decision about whether to publish.

## Change

- **config:** `AddressBinding.FailMode`, compiled from `address-name <n> profile fail-mode`. The schema leaf is `ValidateEnum(retain, drop)`.
- **feeds:**
  - `feedState.holdDropped` is set in `recordFailure`'s drop branch and cleared in `installSnapshot`;
  - `FeedInfo.HoldDropped` exposes it;
  - `SnapshotForBindings` still omits a binding with an unready constituent, EXCEPT when its fail mode is `drop` and every unready constituent was hold-dropped. Then it publishes the union of the remaining feeds' prefixes, possibly none.
  - A never-fetched or unknown feed still omits the binding (#5645).
- **show:** `showDynamicAddress` became a thin wrapper over `renderDynamicAddress(w, cfg, runtime)`, which prints:
  - the hold interval as applied: an omitted `hold-interval` retains indefinitely (the old show printed a 7200s default that nothing enforced);
  - `HOLD-DROPPED` or `STALE` per feed;
  - a bindings section with each binding's fail mode and enforced state, mirroring `SnapshotForBindings`.

## Cells

- **feeds:**
  - retain (and the empty default) omits a hold-dropped binding;
  - drop publishes a present empty slice;
  - drop still omits a never-fetched feed, an unknown feed, and a mix of hold-dropped plus never-fetched;
  - drop publishes the live feed's prefixes alongside a dropped one;
  - a successful fetch clears the marker in both the state and `AllFeeds`.
- **config:** `fail-mode drop` compiles and the omitted leaf stays default; `SchemaValidate` accepts retain and drop and refuses `sometimes`.
- **userspace** (policy lowering with the overlay drop mode produces):
  - the referencing rule and an unrelated rule both build with no unsupported-address sentinel;
  - the retain control (binding omitted) still carries the sentinel.
- **CLI:** the rendered output carries the applied hold interval, HOLD-DROPPED, both bindings' enforced states, and no 7200.
