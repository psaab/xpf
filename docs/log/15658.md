# Issue #15658: `routing-options generate route` destination/CIDR-mask validation and same-prefix merge

- **Timestamp**: 2026-10-19
- **Action**: typed the `generate route <destination>` identity arg in `schemaRoutingOptions` with `keyValueType: ValueCIDR` + `keyValidator: ValidateRouteDestination` (the #2448 static-route destination validator, reused — no second grammar). The per-instance `routing-options` node shares the same `generate` pointer (#9351), so global and routing-instance generate routes are both gated. `999.999.0.0/99`, `/99` masks, bare IPs, garbage, and `/129` now fail `SchemaValidate` and strict compile.
- **Action**: added compiler-layer strict gates (`compiler_validate_strict_generate_route.go`): `generateRouteInvalidPrefixes` re-runs `ValidateRouteDestination` on every compiled generate route (global + per-instance), and `generateRouteHelperRefusedMaskSpellings` mirrors the #12507 static-route gate for helper-refused padded masks (`/008`, `/0032`), including folded aliases. Both are wired in `runUniformGatesRoutingRibRPM` beside the static-route mask gate, downgraded to warnings on the tolerant load/peer-sync path via the new `lenientGenerateRoutePrefix` opt (route preserved, so a published malformed prefix still fails the helper snapshot closed instead of silently losing a blackhole).
- **Action**: hierarchical same-prefix merge. `compileRoutingOptions` now folds every `generate` container and merges each route via `mergeGenerateRoute` (masked-prefix identity via the existing `staticRouteMergeKey`: first spelling wins, `Discard` latches, first non-empty `Policy` wins); `canonicalizeGenerateRoutesAcrossScopes` (called from `canonicalizeStaticRoutesAcrossTables`) folds routes that arrived from separate routing-options roots and canonicalises helper-supported padded masks (`/08` → `/8`) exactly like static routes (#12507), keeping helper-refused spellings for the strict gate unless a parseable folded alias exists. Folded spellings are retained on the compiler-only `GenerateRoute.prefixAliases` (`json:"-"`, mirroring `StaticRoute.destinationAliases`). One route per prefix now reaches both consumers, so FRR (`renderGenerateRoutes`, one `ip route <p> blackhole`) and userspace (`buildRouteSnapshots`, one Discard snapshot) render identically.
- **Action**: updated two pre-existing tests (`routing_instance_routing_options_11782_test.go`, `routing_instance_routing_options_flat_15065_test.go`) to compare `GenerateRoute` with `reflect.DeepEqual` — required because the struct gained the unexported slice field (same reason `DeepEqual` is used for the sibling `RibGroup` assertion).
