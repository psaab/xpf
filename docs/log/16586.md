# #16586: reth LAG (multi-child reth) commits strict-clean, extra children zoneless

- **Timestamp**: 2026-10-24
- **Action**: A Junos reth LAG — two or more child interfaces per node
  on one reth (`ge-0/0/1` + `ge-0/0/2` both `redundant-parent reth1`,
  mirrored on node 1) — committed strict-clean. `RethToPhysical`
  binds only the lexically-first local child, so the VIP, virtual MAC
  and security zone landed on `ge-0/0/1` while `ge-0/0/2` came up
  managed UP zoneless with a duplicate `169.254.<rg>.<node>` link-local
  and its physical MAC: the configured intra-node redundancy/bandwidth
  was silently lost, contrary to the accepted-only doctrine
  (#2078/#4231/#5804, ae in #6544). Until reth LAG exists,
  `validateRethMultiChildAST` strict-rejects the shape, naming the
  reth, the node, the bound child and the ignored children; the
  tolerant load / peer-sync path downgrades to a warning
  (`lenientRethMultiChild`, #1960 no-brick). The gate runs
  pre-expansion and unions the authored view (top level + every
  `groups` block) with the node0/node1 group expansions, so both
  cluster nodes verdict identically even when children live only in
  per-node groups. Locality is the FPC slot via
  `InterfaceSlot`/`SlotToNodeID` (the canonical `ge-0/...` +
  `ge-7/...` one-per-node spelling is unchanged); slash/dash
  spellings of one port count as one child. NOT changed: the
  dataplane rendering of extra children on the tolerant path —
  `RethToPhysical`'s single binding remains the bound there, and
  the warning makes the ignored children operator-visible.
- **File(s)**: `pkg/config/compiler_validate_strict_reth_lag.go` (new),
  `pkg/config/compiler.go`, `pkg/config/compiler_opts.go`,
  `pkg/config/reth_lag_16586_test.go` (new),
  `docs/config-schema.md`, `docs/feature-gaps.md`,
  `docs/vsrx-gaps.md`, `docs/log/16586.md`.
- **Validation**: New tests cover flat 2+2, single-node, three-child
  and node1-only arms rejecting at strict `CompileConfig` (naming
  `ge-0/0/2`), warning on `CompileConfigLenient`, grouped per-node
  children rejecting on generic + both `CompileConfigForNode` views,
  and one-child-per-node controls (flat, grouped, dash-alias)
  committing unchanged — see PR body for counts. Pre-fix probe at
  base `974cf32582`: the 2+2 config compiled with `err=nil` and no
  reth warning, `RethToPhysical={reth1: ge-0/0/1}`.
- **Residual**: Reth LAG itself (bonding the extra children, virtual
  MAC / RG takeover across them) remains unimplemented and is now
  tracked as rejected-until-implemented in `docs/vsrx-gaps.md`;
  switch-side LAG traffic behaviour was not lab-tested (impact
  sizing only, per the issue).
