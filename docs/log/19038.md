# Issue #19038: UDP probe Session ID query read a 100-row-capped listing

## Why

- **Timestamp**: 2026-11-08 20:05 PST
- **Action**: G1 ran H11 (`test-rg-move-soak`, `SOAK_FORM=untargeted-away`,
  harness b8ac0494f6) on loss at #18559 product head 3380701f5f. With
  #19022's echo in place, the UDP probe answered for the first time since
  #18679, and moves VOIDed with "UDP sequence probe flow was absent on
  synced standby nodeN".
- **File(s)**: `/var/worktrees/gate-18559-logs/loss-pr-1794194752/h11-untargeted-away-s{2,5}-from{0,1}.log`

## Diagnosis

- **Timestamp**: 2026-11-08 20:20 PST
- **Action**: Read the artefacts. The result is constant within a run (20/20
  per direction), and the four runs take all four combinations:

  | run | to node1 (query node1) | to node0 (query node0) | Session ID |
  |---|---|---|---|
  | s5-from0 | VOID | VOID | n/a |
  | s5-from1 | SURVIVED | SURVIVED | 562949953421493 |
  | s2-from0 | SURVIVED | VOID | 281474976710958 |
  | s2-from1 | VOID | SURVIVED | 370 |

  The issuer is not an input to the query.
  `Soak.udp_probe_before_move(target)` calls
  `IncusCluster.udp_probe_session_id(target)`, which runs
  `cli -c "show security flow session"` on the target. The parser
  `session_id_for_probe` reads the first `nodeN:` section, which is the
  queried node's own (cmd/cli prints the local section first). With the
  issuer fixed at node0, node1's result flips between s5 and s2.
- **Cause**: `cmd/cli/show_flow.go:58` defaults the request to
  `Limit: 100`. `pkg/grpcapi/server_sessions.go` `getSessionsLegacy`
  returns the first 100 forward sessions in BPF HASH iteration order, which
  depends on each node's map seed, and counts every match into
  `Total sessions:`. Each run opens a new probe socket, and with it a new
  tuple and a new bucket position on each node. The parser then took
  "not in the first 100" for "absent".
- **Classification**: HARNESS defect. It is not issuer-relative naming, and
  it is not a #18559 transfer-semantics expectation. Master's harness has
  the identical query, and so does H1 Group 1c (`ha_udp_probe_session_id`).
- **Product side**: the remote CLI's silent 100-row cap is filed as #19039
  and is not fixed here.

## What

- **Timestamp**: 2026-11-08 20:30 PST
- **Action**: The soak and H1 now query the probe's exact tuple with an
  explicit limit, and absence must come from a complete listing.
- **File(s)**:
  - `test/incus/udp_session_probe.py`: `session_query_for_probe()` builds
    `show security flow session source-prefix <c>/32 source-port <p>
    destination-prefix <t>/32 destination-port <p> protocol udp limit 10000`.
    It is also exposed as the `session-query` subcommand for the shell
    caller. `session_id_for_probe()` now returns None (absent) only when
    the local section has its `Total sessions: N` terminator and N equals
    the rows shown. A truncated section, or one without a terminator,
    raises, so the caller VOIDs with that reason.
  - `test/incus/rg_move_soak.py`: `IncusCluster.udp_probe_session_id` sends
    that query.
  - `test/incus/ha-assurance-lib.sh`: `ha_udp_probe_session_id` sends the
    same query, via `session-query`.
  - `test/incus/rg_move_soak_test.py`: new class `SessionListingCap19038`.
    `CappedFlowSessionCLI` models cmd/cli plus getSessionsLegacy (default
    limit 100, hash order, Total counts every match, filters and limit
    honoured). `CappedCLICluster` runs the REAL
    `IncusCluster.udp_probe_session_id` against that model. The cells:
    - the four H11 artefact shapes, using each run's issuer and sleep;
    - the exact query string;
    - under the bare query, the probe at row >= 100 is unreadable, not
      absent;
    - absence needs the local terminator, and the peer's terminator does
      not count.
  - `test/incus/ha-assurance-selftest.sh`: an `incus` stub that answers
    `cli -c` from the same model (151 sessions, probe at row 121 locally

    must send the tuple query. The parser must exit 2 ("shows 100 rows but
    reports 'Total sessions: 151'") on the bare listing.
  - `docs/ha-rg-move-correctness.md`: the soak's UDP probe, its query, and
    two rows in "Reading a failure".
  - `docs/userspace-ha-validation.md`: Group 1c and its query rule. This

## Risk

Harness only. The tuple filter selects exactly the flow the parser already
matched by tuple, so a run that previously found the probe now finds the
same Session ID. The parser change can only turn a former "absent" into an
"unreadable" VOID, and only when the listing cannot prove absence. It
cannot turn a VOID into a PASS. The #18559 branch's harness has the same
`udp_probe_session_id`, the same `udp_session_probe.py` and the same
`ha-assurance-lib.sh` as master, so this commit cherry-picks onto it with
no change.
