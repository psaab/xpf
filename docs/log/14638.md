# Issue #14638 — cluster idle-lease codec drops the seven `Deterministic*` fields

- **Issue:** The Go cluster codec in
  `pkg/cluster/sync_persistent_nat_lease_8121.go` encoded only the 14
  non-deterministic `IdleLeaseWire` fields. Rust export stamps
  `deterministic=true` plus a V6 identity for deterministic NAPT64 BIBs
  (`afxdp/coordinator/idle_lease_sync_8121.rs`,
  `server/handlers/idle_leases.rs`), and Rust import refuses a
  `nat64-deterministic-*` record when `!deterministic` or the identity
  mismatches (`skipped_identity_busy`). Every idle deterministic BIB was
  therefore lost across failover, and the counter misled operators toward
  "identity busy" instead of the codec.
- **What:**
  - `pkg/cluster/sync_persistent_nat_lease_8121.go`: new message type
    `syncMsgPersistentNatLeaseDeterministic = 43` (next free post-install
    value; 42 is `syncMsgBulkRequest`). Its record layout is the legacy
    layout plus, after `TimeoutNs`: `Deterministic` (u8), `DeterministicMode`
    (u8), `DeterministicBlockSize` (u16 LE), `DeterministicBlocksPerIP`
    (u16 LE), `DeterministicHostPrefixLen` (u8), `DeterministicHostBase`
    (uint16-length string), `DeterministicHostCount` (u32 LE). The legacy
    type 41 layout is byte-identical to before. Layout-aware
    encode/decode helpers (`*Layout`, `*Deterministic` wrappers);
    `persistentNatLeaseBatchIsDeterministic` selects the layout;
    `QueuePersistentNatLeaseBatch` stamps type 43 on every chunk frame
    iff the batch contains a deterministic lease, else type 41.
    The legacy encoder now refuses a deterministic lease instead of
    silently stripping it; the deterministic decoder validates the
    identity (mode 1 ⇒ IPv4 base, mode 2 ⇒ IPv6 base, non-zero
    block/blocks/count when `Deterministic`, all-zero identity when not)
    and still demands exact consumption (`off == len(buf)`).
  - `pkg/cluster/sync_conn_read.go`: types 41 and 43 share the
    generation/sequence/apply handler; only the batch decoder differs.
  - `pkg/cluster/sync_capabilities_6650_test.go`: census gains
    `PersistentNatLeaseDeterministic`.
  - `userspace-dp/src/afxdp/coordinator/idle_lease_sync_8121.rs`: the
    generic source-NAT import path now refuses a deterministic-shaped
    lease (`deterministic` or identity present) as
    `skipped_identity_busy` instead of installing it as dynamic — the
    issue's remaining-validation item. Only the `nat64-deterministic-*`
    branch may install a deterministic lease, after its gates.
  - NOT changed: `SessionSyncWireVersion` / `CurrentHAProtocolVersion`
    (additive type on the #2239/#6650 precedent — an old peer ignores
    type 43 and session sync across a mixed pair is not refused; the
    safe degradation is loss of deterministic idle leases until both
    sides are new, never a mis-install), the Go↔Rust control-socket
    `IdleLeaseWire` JSON (already carries the fields), chunking
    (#14607), or generation/replay semantics.

## Risks / residuals

- Mixed-version: a new sender emits type 43 only for batches containing
  a deterministic lease; an old receiver ignores the unknown type, so
  deterministic idle BIBs are lost until upgrade completes — the same
  safe degradation the pre-fix code imposed permanently, never a
  dynamic mis-install. Non-deterministic batches keep type 41 and are
  unaffected in both directions.
- A batch mixing deterministic and dynamic leases rides type 43 as a
  whole; dynamic records in it carry an all-zero deterministic tail,
  which the new decoder validates as non-deterministic.
