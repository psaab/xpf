# #18753 — pin the scoped deadcode check to a compatible Go toolchain

- **Timestamp**: 2026-11-07
- **Issue**: #18753
- **Base**: `d8305e128f606aa9e92641cde4024c52487931e6`

## Defect

The scoped `make check-nft-deadcode` target invoked `$(GO) tool deadcode`,
which followed go.mod's x/tools v0.40.0 tool directive. On go1.27.2 the SSA
builder panics with `unexpected expr: *ast.KeyValueExpr`. At the clean base,
`make check-nft-deadcode` reproduced that panic (the make process exited 2).
The module-wide `scripts/go-deadcode-gate.sh` already selected a go1.26 toolchain
and pinned x/tools v0.38.0, but carried its resolver inline.

## Fix

- Added `scripts/resolve-deadcode-go.sh` as the shared resolver for both
  deadcode gates. It searches `$DEADCODE_GO`, `$GO`, PATH `go`, and standard
  go1.26 install locations, prints only the selected binary path, and reports
  missing toolchains as NOT-EXAMINED / exit 77. `XPF_DEADCODE_REQUIRE=1`
  converts missing-toolchain skip into exit 1.
- Refactored `scripts/go-deadcode-gate.sh` to use that resolver and removed the
  duplicate candidate-selection logic.
- Reworked the scoped Makefile target to run
  `golang.org/x/tools/cmd/deadcode@v0.38.0` using the resolved toolchain.
  Filtered findings are recipe exit 1; analyser failure prints
  `analyser crashed` and is recipe exit 2; resolver statuses 77/1 are
  preserved. The existing package/file filter is unchanged.
- `.github/workflows/test.yml` keeps the job's main go.mod toolchain at
  go1.24.9, provisions go1.26.9 only for the scoped deadcode step with
  `XPF_DEADCODE_REQUIRE=1`, then restores the main toolchain before affected
  Go tests.
- Extended `make test-go-deadcode-gate-lib` coverage with resolver success,
  missing-toolchain/REQUIRE exits, a crashing analyser, and filtered findings.
  Added the resolver to the pinned shellcheck file list and documented the CI
  toolchain exception in `docs/ci-gate-contract.md`.

## Validation

- Before the fix, `make check-nft-deadcode` on the clean base and host go1.27.2
  reproduced the v0.40.0 SSA panic (`unexpected expr: *ast.KeyValueExpr`).
- After the fix, `make check-nft-deadcode` passed on the same go1.27.2 host,
  selecting installed go1.26.9 and reporting no filtered findings.
- `make test-go-deadcode-gate-lib`: **21 passed, 0 failed**. This includes
  resolver exit 77 / NOT-EXAMINED and REQUIRE exit 1, propagation of both
  statuses through the scoped target, analyser-crash recipe exit 2, filtered
  finding recipe exit 1, and all existing gate fixture controls.
- `sh -n scripts/resolve-deadcode-go.sh scripts/go-deadcode-gate.sh` and
  `bash -n scripts/go-deadcode-gate-selftest.sh`: passed.
- `shellcheck -S warning` on the resolver, gate, and self-test; workflow YAML
  parsing; and `git diff --check`: passed.
- `make go-deadcode-gate` exited 1 with 12 unallowlisted and 25 stale
  allowlist rows (177 measured rows). The exact gate script from
  `d8305e128f606aa9e92641cde4024c52487931e6` produced the same failure

  mismatch is present on the master base and is not caused by this change.
- The full Go affected-package suite was not run; the issue changes the scoped
  deadcode check, its gate self-test, and workflow provisioning only.
