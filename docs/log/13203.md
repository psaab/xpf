# Issue #13203: fail closed on ignored xpfd arguments

`xpfd version`, `protocol-versions`, `verify-dataplane`, and `shim-manifest`
previously allowed extra positional arguments to be silently ignored. In
particular, an operator passing a candidate object path to `verify-dataplane`
received a verifier result for the embedded object instead. The kernel upgrade
command also discarded `--unit` when wiring the promotion health check, and its
usage advertised flags after the arm version even though Go's flag parser stops
at the first positional operand.

The commands now reject unexpected positionals before doing work;
`protocol-versions` preserves the existing machine-readable output; the kernel
promotion config receives the selected unit; and kernel usage places flags
before the arm version. Removed the unused `readBounded` forwarding wrapper and
updated its test to exercise `configstore.ReadBounded` directly.

Regression: the tests were added on the pristine `origin/master` worktree and
the focused `go test ./cmd/xpfd -run 'Test(ParseNoOperandArgsRejectsExtras_13203|ParseProtocolVersionsOutput_13203|ParseVerifyDataplaneArgs_13203|ParseKernelVerbArgsFlagsBeforeVersion_13203|NewKernelConfigUsesUnit_13203)$'`
failed to compile because the new argument guards and four-argument kernel
config did not exist. Reverting the production changes likewise made the new
tests fail to compile (missing `run`, the argument guards, `kernelUsage`, and
the extra kernel-config parameter). Restoring the fix made both suites pass:

- `go test ./cmd/xpfd ./cmd/shim-manifest`
- `go vet ./cmd/xpfd ./cmd/shim-manifest`
- `go build ./cmd/xpfd ./cmd/shim-manifest`
- `git diff --check`
