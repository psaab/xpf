# Issue #9998: WireGuard identity-override private-key hex case

- **Timestamp**: 2026-09-17
- **Why**: `unitWireguardIdentityOverride` compared the interface and unit `WgLocalPrivkeyHex` values as exact strings. A unit restating the same 32-byte private key with upper- or mixed-case hex was falsely rejected even though hex spelling is case-insensitive.
- **What**: Compare the revealed private-key strings with `strings.EqualFold` in the identity-override gate. The listen-port gate, different-key rejection, and single-unit path are unchanged. Diagnostics still do not include key material.
- **Regression**: `TestUnitWireguardIdentityOverrideCaseVariantAccepted9998` covers upper- and mixed-case restatements of the stored key. `TestUnitWireguardIdentityOverrideDifferentKeyStillRejected9998` proves a genuinely different key remains rejected and the error does not echo either private key.

The exact string comparison reported `unit overrides the WireGuard private-key` for the upper-case and mixed-case restatements.
- **GREEN**: after the comparison change, the same targeted command passed: 2 case-variant subtests and 1 different-key rejection test, 3 exercised cases total, 0 failed.
- **Affected suite**: `go test ./pkg/config -count=1` passed (`github.com/psaab/xpf/pkg/config`, 208.618s).
