# Issue #14165 — pruning a running candidate kernel

- **Timestamp**: 2026-10-16
  - **Action**: Deferred the destructive candidate prune while the candidate is the running kernel. `verifyAndPromote` is entered only after Gate 2 positively confirms `running == CandidateVersion`; its binary-mismatch, verify-dataplane, forward-beacon and BootOrder failures all route through `revert` → `restoreKnownGood`, which previously called `PruneInactiveSlot` unconditionally BEFORE the attempt-cap decision. The real prune writes the known-good selector, then `apt-get purge linux-image-<candidate>` (+ modules/headers) and, on confirmed dpkg removal or when no candidate package is installed, sweeps `/lib/modules/<candidate>` and `/boot/*-<candidate>`. Running that against the live kernel orphans it (no modules for late loads, no boot files), and on the attempt-cap path the box stays up in that state instead of rebooting to known-good. Fix: `restoreKnownGood` (pkg/upgrade/kernel_run.go) now always performs the non-destructive restore (BootOrder known-good front, watchdog disarm, new `RestoreInactiveSlotSelector` selector rewrite) and prunes ONLY on positive evidence of a non-candidate running kernel — equal or unreadable defers with a log line. `PruneInactiveSlot` (pkg/upgrade/kernel_linux.go) re-checks `uname -r` itself as an independent fail-closed layer: running == candidate or unreadable refuses before the selector write, purge, or sweep. No per-packet cost; the check is one `uname -r` on the revert/cleanup path only. Existing prune tests that model an off-candidate prune now pin `runningKernelFn` to the known-good version (their subject is purge/dpkg behaviour, unchanged).
  - **File(s)**: pkg/upgrade/kernel_run.go, pkg/upgrade/kernel_linux.go, pkg/upgrade/kernel.go (new `RestoreInactiveSlotSelector` on `KernelSystem`), pkg/upgrade/kernel_test.go (fake + corrected revert assertion), pkg/upgrade/kernel_prune_running_14165_test.go (new), pkg/upgrade/kernel_purge_5076_test.go, pkg/upgrade/kernel_pkgquery_5428_test.go (pin off-candidate running kernel), pkg/daemon/kernel_upgrade_status_6495_test.go (fake gains the new interface method)
