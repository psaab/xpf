# Drain SYN-ACK session-miss SYN alarms (#12872)

- **Issue**: #12872, research D7-04 (Medium; origin report High).
- **Cause**: `syn_ack_flood_drop_on_new_flow` can set the worker-local `syn_alarm_pending` flag for an admitted warning-band SYN-ACK miss or a per-source drop. The session-miss caller in `poll_descriptor` handled the drop reason but did not drain that flag. The usual flow-backed screen poll stage does drain it, so a subsequent packet on the same worker could emit the SYN-ACK's stale alarm against its own tuple and ingress zone.
- **Change**: The session-miss caller now drains the SYN alarm immediately after its screening decision and emits it as a log-only `syn-flood-alarm` with the current SYN-ACK tuple and `from_zone_id`. The verdict/drop handling remains unchanged. The drain API documentation now covers both consumers.
- **Regression coverage** (`userspace-dp/src/screen/tests.rs`): warning-band Admit and DropSrc alarm cases verify the pending event is drained exactly once; a source guard fails if the session-miss caller stops draining or emitting it against `screen_pkt`/`from_zone_id`. `userspace-dp/src/afxdp/event_emit_tests.rs` verifies `syn-flood-alarm` emits a PERMIT event with its zone and packet tuple.
- **RED evidence**: Before the caller drain, `cargo test --manifest-path userspace-dp/Cargo.toml syn_ack_miss_ -- --nocapture` failed both Admit and DropSrc probes because `syn_alarm_pending` remained set after the SYN-ACK miss hook. Removing the production drain also made `syn_ack_miss_alarm_drain_is_wired_to_its_packet_12872` fail at `session-miss path drains pending SYN alarm`.
- **GREEN evidence**: After restoring the drain, `cargo test --manifest-path userspace-dp/Cargo.toml syn_ack_miss_ -- --nocapture` passed both alarm-path tests; `cargo test --manifest-path userspace-dp/Cargo.toml syn_ack_miss_alarm_drain_is_wired_to_its_packet_12872 -- --nocapture` passed; `cargo test --manifest-path userspace-dp/Cargo.toml screen::tests -- --nocapture` passed 259 tests. The `screen_alarm_event_is_permit_not_deny` event-emitter test also passed with the SYN alarm assertions.
- **Validation**: The full `screen::tests` suite passed on the rebased branch (`259 passed`). One earlier post-rebase run had an unrelated `icmp_flood_secondary_zone_ceiling_still_fires` failure; that test passed alone and the full suite passed on rerun. `git diff --check` passed.
- **Blast radius / risk**: Only the cold session-miss alarm path changes; alarm cadence and fail-closed drop decisions are unchanged. The alarm event now identifies its source packet/zone rather than being misattributed or lost. Fabric-ingress packets continue to skip miss-time screen accounting as before.
