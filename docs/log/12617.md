# 12617 — bound recursive static-route lookup cost

- **Timestamp**: 2026-10-13
- **Action**: replace recursive table-wide candidate scans with a prefix-keyed index
- **Base**: `28550b1c8` (`ra: snapshot reclaimer wait budget (#12585)`)
- **Files**:
  - `userspace-dp/src/afxdp/forwarding_build/fib.rs`

## Why

Recursive resolution selected the longest matching static route by scanning every route in its table twice for each gateway probe. The route index was sorted but not searchable by prefix, so an unresolved next-hop in a large learned table incurred a full-table scan. Issue measurements at 8,000 / 16,000 / 32,000 / 65,000 rows showed 480 ms / 981 ms / 8.75 s / 21.7 s, versus recursion-off baselines of 6.7 / 13.8 / 84 / 62 ms.

## What

The recursive index now groups static routes by canonical table, masked network, and prefix length. Longest-prefix selection probes only the address family's possible prefix lengths (at most 33 IPv4 or 129 IPv6 hash lookups), then visits routes tied at the winning prefix in ascending preference and snapshot order. The existing recursive depth and per-next-hop work limits, family separation, and fail-closed behavior remain in place.

Coverage includes a 65,536-row IPv4 index, bounded /32 hit and IPv4 miss counts, IPv6 hit and miss bounds, LPM/default/same-prefix preference order, and exhaustion at exactly 512 recursive probes with a reachable terminal route placed beyond the budget.
