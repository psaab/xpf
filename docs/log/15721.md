# Issue #15721: OperationalTree selector subtrees (match-policies / test policy / policies policy-name+hit-count / NAT pool / BGP neighbor)

- **Timestamp**: 2026-10-19
- **Action**: modelled the five selector families in `pkg/cmdtree/tree.go` `OperationalTree` so `cmdtree.Canonicalize` resolves them instead of returning `CanonicalUnknown` (which `evaluateCommandRegex` in `pkg/cli/permissions_regex.go` fails closed on for every regex-restricted login class):
  - `show security match-policies` and `test policy` are now `Options: true` nodes sharing `policySelectorChildren()`, mirroring `policymatch.ParseSelectorArgs`: `from-zone`/`to-zone` (dynamic zone names), `source-ip`/`destination-ip` (`ValueIPAddress`), `source-port`/`destination-port`/`icmp-type`/`icmp-code` (`ValueInteger`), `protocol` (`ValueIdentifier`), `ingress-interface` (dynamic interface names), and valueless `non-first-fragment`. This replaces the old fixed-order `test policy` chain whose value slots had no placeholder/typed leaf, and the bare `match-policies` leaf. Dynamic selectors carry `RequiresValue` so a dangling selector stays refused.
  - `show security policies policy-name` takes one `ValueIdentifier` value; `hit-count` is an `Options: true` node with `from-zone`/`to-zone` dynamic children (plus a self child so the leading spelling stays completable), and `hit-count` is also a child of the canonical `from-zone … to-zone …` chain — `parsePolicyShowQuery` is position-independent, so `from-zone X to-zone Y hit-count` selects the same view. Note: the dispatchers (`parsePolicyShowQuery` in both CLIs) reject `policy-name <name>` today; the tree entry models the Junos spelling for canonicalization/completion only and changes no dispatcher behaviour.
  - `show security nat source pool` / `destination pool` take an optional pool name via `sourceNATPoolNames` / the new `destNATPoolNames` (bare `pool` still lists all pools; the handlers treat `""`/`all` as list-all).
  - `show [protocols] bgp neighbor` nests `received-routes`/`advertised-routes` under a `<ip>` placeholder (`bgpNeighborNode()`), matching both dispatchers (`neighbor <ip> [received-routes|advertised-routes]`); the bare form still lists all neighbors.
- **Action**: taught `cmdtree.EveryWordIsAKeyword` (`pkg/cmdtree/pure_path.go`) to descend through a placeholder-with-children: the word filling the slot is operator data, its children are still keyword-checked. This keeps the gRPC charge strings `show protocols bgp neighbor advertised-routes` / `received-routes` valid pure keyword paths now that the route keywords sit under `<ip>`, while `show protocols bgp neighbor received-routes` (no IP) stays rejected. A literal `<…>` word still never passes.
- **Action**: recorded the new dynamic value slots in the remote-CLI binding census (`cmd/cli/value_slot_binding_census_9478_test.go`): match-policies/test-policy selectors bind via the shared `policymatch.ParseSelectorArgs`, NAT pool names bind at fixed position in `cmd/cli/show_nat.go`, and hit-count zones bind via the position-independent `parsePolicyShowQuery` walk. The stale `test policy from-zone to-zone` entry was replaced by the flattened `test policy to-zone` / `ingress-interface` slots.
- **Scope note**: `clear dhcp client-identifier interface` was already undeclared in the census on `origin/master` (pre-existing failure, verified identical there); it is not part of this issue and is left for its owner.
