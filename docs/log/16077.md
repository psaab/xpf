# #16077 - Tolerant AAA warning is transient only; no persistent alarm for local-only auth

- **Timestamp**: 2026-10-24
- **Issue**: MGMT-16 from #15987 (validated Low, unanimous MATERIAL). Strict commit rejects unimplemented AAA leaves (`radius-server`, `tacplus-server`, `authentication-order`, `accounting`) naming local-only authentication, but on the lenient path the warning lived only in the transient compiled `cfg.Warnings`, whose sole post-compile consumer is one boot-time `slog.Warn` loop (`pkg/daemon/daemon_apply.go`). `show system alarms` recomputes from `ValidateConfig` + tolerated-stanza helpers and never re-derived the AAA condition — so a legacy persisted/peer-synced AAA-looking tree ran local-only auth with no persistent signal after boot.
- **Change**:
  - `pkg/config`: `Config.UnimplementedAAALeaves []string` (`json:"-"`, compile-time only) records the deduped leaf names admitted by the tolerant path. `compileSystem` populates it only when `opts.lenientSystemAAA10831` is set — the strict path still returns the refusal and retains nothing. Leaf names only, never values, so no AAA secret can leak through the record (the #15019 concern). `config.UnimplementedAAAWarnings(cfg)` re-derives one alarm line per leaf from the marker (`local-only authentication is the only supported mode; Junos system <leaf> is not implemented … (unsupported AAA admitted on the tolerant path; local-only authentication is in effect until the stanza is removed)`).
  - Review fold (Opus): duplicate `system` roots merge in author order, and each root's `compileSystem` appended its leaves straight to the marker, so the same leaf under two roots produced duplicate alarms. `compileSections` now stages per-root leaves in a held slice (`compileSystem` takes an optional `heldAAA` out-param) and merges them into the marker once — deduped across roots, in author order, and only after the whole dispatch succeeds, so a failed compile publishes no marker. Pinned by `TestUnimplementedAAALeavesDedupedAcrossDuplicateSystemRoots16077` (verified RED with the dedupe neutered: `[radius-server tacplus-server radius-server]`).
  - Alarm surfaces: all four established renderers append `UnimplementedAAAWarnings` alongside the existing `ToleratedTypedLeafWarnings` / `ToleratedUnknownTopLevelStanzaWarnings` — local `show system alarms` and `show security alarms` (`pkg/cli`), gRPC `show system alarms` and `show security alarms` (`pkg/grpcapi`). No new dedicated callback, daemon state, or persistence format. The marker is rebuilt per compile, so the alarm persists across daemon restarts (boot recompiles the persisted tree leniently) and clears when the stanza is removed.
  - `pkg/dataplane/userspace` (snapshot shape guard): `ConfigSnapshot` embeds `Config`, so the reflection digest moves by one walked line. The field is `json:"-"`, absent from snapshot JSON, and Rust keeps `config` opaque — no helper of any vintage can observe it, so ProtocolVersion stays (v70 STANDS entry in `snapshot_shape_version_8892_test.go`). Master's pin was already drifted (base digest `29de2603…` at ProtocolVersion 70 vs pin `68`/`cf98a6a5…` — the shape test was red on unmodified master); the fold re-pins version+golden to the measured post-change digest `b7f65ae8…` and says so in the ledger entry rather than blaming the drift on this change.
- **Validation**:
  - RED-on-revert pins: `pkg/config/aaa_alarm_16077_test.go` (marker retained/deduped, strict+clean empty, secret never in marker or alarm), `pkg/configstore/aaa_alarm_16077_test.go` (SyncApply → restart `Load` keeps the alarm, stanza removal clears it, clean restart stays clear), `pkg/cli/aaa_alarm_16077_test.go` and `pkg/grpcapi/aaa_alarm_16077_test.go` (both system+security surfaces list it, counted; non-detail security surface counts without leaking detail text).
  - Pre-existing AAA suites still pass (`TestJunosAAA*`, `TestSystemAccounting*`, `TestAAASecret*`), as do the typed-leaf/unknown-stanza alarm suites on all four surfaces.
  - `TestSnapshotShapeIsPinnedToProtocolVersion8892` passes after the re-pin; it was already failing on unmodified master (verified via `git stash`).
- **Risk**: Fail-safe only. A strict commit still rejects AAA outright; a tolerant load still boots (#1960 no-brick) and now also alarms until the stanza is removed. The only new surface text is one WARNING line per retained leaf on the four alarm renderers; nothing is serialized, synced, or sent to the dataplane helper.
