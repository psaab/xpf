# #13634: preserve IPv6 AH packets during TCP segmentation

## Trace and finding

`segment_forwarded_tcp_frames_from_frame` admitted oversized IPv6 TCP packets
whose extension chain contained Authentication Header (AH). It then copied the
AH header to each segment while changing the authenticated IPv6 payload length
and TCP sequence, flags, ports, and checksum. Those segments cannot validate
against the original AH integrity check. The routine also resolved L4 against
the full backing frame rather than the IP-declared packet slice, permitting an
extension-header walk to consume bytes outside the declared datagram.

The prepared-TX twin had the same AH and L4-boundary omission. Both builders
must agree because the TX dispatcher tries the prepared-TX path before the
copy path.

## Fix

Both segmentation builders prefer the Ethernet wire-derived L3 offset, with
the dispatcher's nibble-checked metadata-stamp fallback, and decline a packet
when `ipv6_ah_sighted` finds AH, preserving the packet for the normal forwarding
or PTB path. Wire-first resolution also avoids trusting a VLAN-stale metadata
stamp whose TCI byte happens to resemble an IP version nibble. After clamping
to the IP-declared datagram, both builders resolve L4 with
`packet_rel_l4_offset` on that bounded slice rather than walking the full
backing frame. Existing TCP/header checks continue to fail closed on truncated
declarations.

## Regression

`segment_forwarded_tcp_declines_ipv6_ah_authenticated_packet_13634` builds an
oversized IPv6 packet with AH immediately before TCP and asserts that
segmentation declines it. Existing IPv6 segmentation tests exercise the
positive, non-AH path and declared-length bounds. Three property tests were
updated to treat AH-bearing packets as non-segmentable cases.

## Validation
The new regression failed when the AH guard was temporarily removed, then
passed with the fix. The TCP segmentation module passed (14 tests). The full
`xpf-userspace-dp` suite passed 7,959 tests, with one existing failure and 8
ignored: `afxdp::tests_9950::f035_parked_fragment_overlap_is_rechecked_on_retry_10659`.
The same test fails on pristine base `761931ff6` with the same assertion
(`parked-head: the sibling must pass before the parked frame is retried`).
