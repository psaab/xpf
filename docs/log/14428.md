# Issue #14428 — RA prefix `no-autonomous` / `no-onlink` first: PIO flags dropped

## Why

The RA `prefix` case in `pkg/config/compiler_protocols.go` read only
`prop.Children` (via `expandRunChildren9235`). The brace-elided spelling

```text
protocols {
    router-advertisement {
        interface ge-0/0/0.0 {
            prefix 2001:db8::/64 no-autonomous no-onlink valid-lifetime 100;
        }
    }
}
```

packs the whole tail onto the prefix node's own `Keys` with no
`Children`. `("prefix","no-autonomous")` and `("prefix","no-onlink")`
are not in `compactNormalizeInScope` (only `preferred-lifetime` /
`valid-lifetime` are), so the #8662 fold never delivers them, and
`expandRunChildren9235` applied to the empty `Children` never sees the
flags or the lifetimes after them. `RAPrefix` defaults `OnLink: true,
Autonomous: true` make the drop read exactly like the operator never
wrote the flags: `pkg/ra` copies them verbatim onto the wire, so hosts
SLAAC-configure addresses from a prefix marked no-autonomous and treat
a no-onlink prefix as on-link (L=1), resolving destinations directly
instead of via the router — fail-open host addressing/policy bypass on
a strict commit reporting success, and on lenient load / HA sync /
restore.

This is DR16-H7, distinct from DR15-H5 (#14420, RA top loop
`managed-configuration`) — a different fix site and a different
rendered artifact (PIO flags, not the M flag).

## What

- `pkg/config/compiler_protocols.go` (RA `prefix` case): expand the
  prefix node's own packed body with
  `packedBodyChildren(prop, raPrefixSchema9235())` — the existing
  schema resolver for the RA prefix — before the existing
  `expandRunChildren9235`. `packedBodyChildren` returns `Children`
  unchanged when there is no tail, so braced and flat-`set` shapes are
  untouched. The `len(prop.Keys) < 2` flat-set special case
  (`prop.Children[0].Children`) is preserved when the expansion
  declines / is a no-op. Mixed packed-tail-plus-braced-body
  (`prefix 2001:db8::/64 no-autonomous no-onlink { valid-lifetime 100; }`):
  when `packedBodyChildren` declines (same slice returned — tail ending
  in a leaf beside a braced body), expand the tail from a childless
  view and read both halves, mirroring the IS-IS interface reader
  (#14410). No other RA leaf handling changes.
- Census: removed the two now-equivalent sites
  (`protocols router-advertisement interface xpfarg prefix xpfarg
  no-autonomous` / `no-onlink`) from
  `pkg/config/testdata/compact_block_divergences_2419.txt` and added
  them to `filedFixed` in
  `pkg/config/compact_block_equivalence_2419_test.go` so the instrument
  keeps checking them in both directions.
- New regression `pkg/config/ra_prefix_packed_flags_14428_test.go`
  (`TestRAPrefixPackedFlagsDR16H7`): braced control, both flag orders
  first, only-`no-autonomous` packed, each flag alone, mixed
  packed-tail-plus-braced-body, flat-`set` control — strict and lenient
  compiles asserted identical to the braced twin.

  `OnLink:true Autonomous:true ValidLifetime:0` while the braced
  control carries `OnLink:false Autonomous:false ValidLifetime:100`.
- GREEN after the fix: `TestRAPrefixPackedFlagsDR16H7` passes;
  `TestCompactBlockEquivalenceInventory2419`,
  `TestCompactBlockCensusReport2419`, flat-run residue and RA
  interface neighbours pass; `go vet ./pkg/config/` and
  `git diff --check` are clean.

## Risk

- Behaviour delta: packed RA prefix lines now install the PIO flags
  and lifetimes the operator wrote (previously silently dropped). No
  previously-working spelling changes: braced and flat-`set` configs
  compile identically, and an unmodelled packed tail still yields no
  expansion rather than a guessed shape.
