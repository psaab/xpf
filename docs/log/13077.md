# #13077 - FlowCache active-flow telemetry reads seed-time queue instead of BA-reclassified queue (D5-01)

- **Timestamp**: 2026-10-14
- **Finding**: `FlowCache::active_flow_debug_entries` attributed every active
  flow to `descriptor.tx_selection.queue_id` frozen at seed time. A
  `ba_reclassify` flow deliberately serves successive packets on different
  CoS queues (per-packet DSCP/PCP), so per-queue `cos_counts` and the
  per-flow debug rows permanently credited the seed queue, corrupting
  `xpf_userspace_cos_active_flow_count` and the v8 equal-flow estimator.
- **Fix**: Added `RewriteDescriptor::last_queue_id` (the one deliberately
  non-constant descriptor field, read only by the debug scan). `insert`
  seeds it from `tx_selection.queue_id`; `stage_flow_cache_hit` stamps the
  effective (BA-reclassified or pinned) queue through the entry borrow it
  already holds (raw-pointer store, documented unsafe, matching the
  mutation `lookup` already performs). The scan reports `last_queue_id`
  with the seed as fallback only when never stamped, so queue-less entries
  stay unattributed.
- **Validation**: New unit tests in `flow_cache_tests.rs`
  (`active_flow_debug_entries_use_last_served_queue_after_ba_reclassify`,
  `active_flow_debug_entries_seed_stamp_and_queueless_entries`) fail with
  the scan reverted to the seed queue (RED: queue 0 reported instead of 3)
  and pass with the fix (GREEN); `flow_cache::` suite 121 passed. Full
  `--bins` suite 7887 passed, 1 failed
  (`wire_invariant_default_specimens`, also failing on pristine master).
- **Risk**: Single `Option<u8>` store on the forwarded cache-hit path; no
  extra cache scan, allocation, or atomic. Dropped, TTL-expired, and
  rejected hits never reach the stamp and retain the prior attribution;
  flows serving on multiple queues within one window report their most
  recent queue.
