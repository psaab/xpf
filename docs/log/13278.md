# Issue #13278 — deduplicate source-NAT pool metrics and export allocator scans

## Contract and change

The userspace helper reports one `SourceNATPoolStatus` per compiled SNAT rule,
even where several rules share one pool allocator. The Prometheus collector had
emitted every row using `{pool, rule}` labels. Equal rule names in separate
rule-sets therefore produced duplicate series and broke `/metrics` gathering;
distinct rule names multiplied the same allocator's pool occupancy and counters.

The collector now uses `SourceNATPoolOccupancy` to select the canonical
constructed allocator row, and emits each pool once. The existing label schema
is retained: the selected status row supplies the `rule` label. It also exports
the helper's `recycle_scan_pops_total` and `recycle_scan_walks_total` counters
as Prometheus counter families, keeping the pair used to assess recycled-port
allocator work.

## Regression coverage

`pkg/api/metrics_test.go` covers duplicate `{pool, rule}` status rows, multiple
rules sharing a pool (one metric set and the selected allocator's occupancy),
and exact export of all 14 per-pool metrics including both recycle-scan values.
The duplicate-label regression was run on the unmodified production code and
failed on the second identical `xpf_userspace_source_nat_pool_live_flows`
series.

## Risk and residuals

Per-pool exporter series now use the canonical row's rule name rather than
producing one series per referencing rule. This is intentional: the values
are shared allocator state, not rule-local measurements. Dashboards grouping
these metrics by `rule` will see one series per pool instead of duplicated or
multiplied measurements.
