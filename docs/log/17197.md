# #17197 — R4-Q51-02: Stage-11 IKE transit-DNAT discriminator calls production DNAT

- **Timestamp**: 2026-10-27
  - **Action**: Deleted the hand-kept Stage-11 mirror
    (`ipsec_destination_matches_transit_dnat`) and extracted the
    production pre-routing DNAT decision into a single pure verdict
    both the poll loop and Stage 11 call.

    Defect was live on `origin/master` (8064ca090e):
    `poll_stages.rs:2267-2332` re-derived the pre-routing ingress
    scope, read the raw `meta.fabric_ingress_ifindex`, and consulted
    only the dynamic DNAT tier via the collapsing
    `lookup_with_counter_scoped`. Production (`poll_descriptor/mod.rs`)
    had since gained static-first ordering (#6473), the persistent
    tier, `Poisoned` drops (#14947) and ambiguous-provenance
    fail-closed handling (#16045), none of which the copy modelled.

    Fix:
    - New `poll_descriptor/prerouting_dnat.rs`:
      `prerouting_dnat_verdict(forwarding, meta, flow, scope,
      packet_icmp, suppress, now_ns) -> PreroutingDnatVerdict
      { Static | Persistent | Dynamic | Poisoned | Denied | None }`.
      Pure, `#[inline]`, allocation-free; hit counters and the
      persistent lease key are returned, never applied.
    - The session-miss poll loop calls the verdict and applies the
      side effects at its existing sites (counter charged at
      committed install / at the poisoned drop, lease held in
      `persistent_lease_hold_outer`).
    - Stage 11 builds the scope with the same
      `prerouting_ingress_scope{,_ambiguous}` (ambiguous arrivals via
      the ambiguous constructor, validated V2 scope ifindex
      otherwise), claims only on `None` or a translate-to-self
      verdict, and never claims `Poisoned`/`Denied`.
    - `PreroutingIngressScope` and the scope constructors widened
      `pub(super)` -> `pub(in crate::afxdp)`; no other visibility
      change.

    Fold (Rev18271Opus NEEDS-FOLD on e1f04742bf): the "pure verdict"
    claim was false for the persistent tier — the verdict called
    `persistent_inbound_lookup_for_rule`, which takes `lock_live()`
    unconditionally, `fetch_add`-ing `live_write_lock_acquisitions`
    (+contended) exported in NAT status. Stage 11 therefore charged
    allocator lock telemetry and took a write lock on the IPsec
    claim path, where the deleted mirror never touched the
    allocator. Fix: split the scoped lookup in
    `nat/allocator/mod.rs` into a guard-taking core
    (`persistent_inbound_lookup_scoped_for_rule_locked`); the
    existing entry point keeps `lock_live()` (poll-loop
    committed-install telemetry unchanged) and a new
    `persistent_inbound_peek_for_rule` runs the same body under
    `read_live()` — a deliberately uncounted shared guard (the body
    only reads `persistent_by_translated` / `persistent_by_source` /
    `persistent_permissions`). `prerouting_dnat_verdict` keeps the
    counting lookup; new `prerouting_dnat_verdict_peek` (same inner
    function, `persistent_peek=true`) uses the peek, and Stage 11
    (`ipsec_destination_claimed_local`) calls only the peek. A stale
    peek can race a concurrent mint/revoke like any read snapshot;
    the poll loop re-evaluates with the counting verdict before
    installing, so it never installs state. Contract corrected in
    `prerouting_dnat.rs:13-17,96-97`: no NAT rule counters charged
    and no lease holds taken by either entry point; allocator lock
    telemetry is charged only by the counting entry point.
    New regression
    `prerouting_dnat_stage11_peek_no_lock_telemetry_17197` pins the
    Stage-11 persistent row's snapshot invariance with the counting
    verdict as positive control.

    Residual risk (Finding 2, acknowledged): the parity matrix
    calls the real Stage-11 entry and the real verdict but
    reconstructs the prod verdict's scope/meta arguments in the
    test harness, so a future call-site wiring drift (wrong scope
    constructor, wrong ifindex argument) at either production call
    site would not be caught by the matrix alone; the telemetry
    regression above pins the Stage-11 call site's allocator
    argument indirectly (it exercises the real claim path), and
    call-site argument drift remains review-covered.

    Acceptance: `grep -n 'fn ipsec_destination_matches_transit_dnat\|dnat_table\.'
    userspace-dp/src/afxdp/poll_stages.rs` → 0.
