# Issue #15017 — RIP (and OSPFv3) top level: packed authentication tail beside a braced body dropped (A12-05)

## Why

The RIP and OSPFv3 top loops in `pkg/config/compiler_protocols.go`
iterated only the top node's `Children`. The hierarchical spelling
that packs a leaf tail beside a braced body therefore dropped the
tail on a commit reporting success:

```text
protocols { rip authentication-key secret authentication-type md5 { neighbor ge-0/0/0.0; } }
    -> AuthKey="" AuthType="" while the braced neighbor survived:
       RIP runs unauthenticated, and any LAN speaker can inject routes.

protocols { ospf3 router-id 1.1.1.1 export connected { area 0.0.0.0 { interface ge-0/0/0.0; } } }
    -> RouterID="" Export=[] while the area survived.
```

The OSPF top (#14427) and IS-IS top (#14426) already read this shape
through `packedBodyChildren` plus the tail-only fallback; RIP and
OSPFv3 were the residual tops. The plain packed line with no braced
body (`rip authentication-key secret authentication-type md5;`) was
already rescued before the compiler by the #8662 compact normalizer,
so the surviving leg is exactly the mixed tail+braced shape, where
`packedBodyChildren` declines (its deepest packed node is a leaf) and
returns the braced children alone. `compileProtocols` is shared by
`routing-instances … protocols`, so the same drop applied there.

Refinement vs the original claim: on current `origin/master` the
no-brace packed line already yields type md5 / key length 6 (the
issue's oracle values, with key `secret`), so the RED that survives
is the mixed shape above; the regression pins both, with the plain
line as a control.

## What

- `pkg/config/compiler_protocols_packed_top_15017.go` (new):
  `packedTopChildren` — the shared tail-only expansion the OSPF
  (#14427) and IS-IS (#14426) loops open-code: `packedBodyChildren`,
  plus, when the node carries both a packed tail and a braced body
  and the expansion declined, the tail expanded from a childless view
  followed by the braced children. An unmodelled tail still expands
  to nothing rather than a guessed shape. The existing OSPF/IS-IS
  inline copies are left untouched (no behaviour change there).
- `pkg/config/compiler_protocols.go`:
  - RIP top: read `expandFlatRun(packedTopChildren(ripNode,
    ripLeafSchema8939()), …)` instead of `ripNode.Children`. The
    `group` case additionally expands a group whose own tail is
    packed (`rip group g1 neighbor I;` synthesized by the top
    expansion), reading the same neighbor/export multi leaves.
  - OSPFv3 top: read `packedTopChildren(ospf3Node, ospf3Schema)`
    before the existing `flattenChainedChildren` + `expandFlatRun`.
- Census (issue direction): `TestProtocolsPackedTopCensus15017`
  exercises every `protocols <p>` top that carries top-level leaves
  in the mixed shape — OSPF and IS-IS as already-fixed controls,
  RIP and OSPFv3 as this fix. BGP/LLDP tops are NOT widened: their
  divergent census rows are flat-set heads already covered by the
  expandFlatRun / flattenChainedChildren chain readers, and no
  mixed-shape drop exists there today; router-advertisement's top
  node carries no leaves of its own. (Their pre-existing #2419
  inventory drift — `security log report`, `protocols lldp interface
  xpfarg disable` — fails identically on unmodified master and is
  not touched.)

## Validation

- RED on `origin/master` (3a10a520d5) with only the test present:
  RIP packed+braced, packed-key+braced-type, packed-tail-ending-in-
  group, packed-equals-braced and routing-instance cells fail with
  `AuthKey = ""` / `AuthType = ""`; OSPFv3 cells fail with
  `RouterID = ""` / `Export = []`; braced controls and the plain
  packed-line / nested flat-run controls pass in both states.
- GREEN after the fix: `go test ./pkg/config/ -run
  'TestRIPPackedTopAuth15017|TestOSPF3PackedTop15017|
  TestProtocolsPackedTopCensus15017'` passes; the packed cases yield
  type `md5` with the 6-rune key `secret` (the issue oracle) and the
  braced control is unchanged.
- Adjacent suites green: #14426/#14427 packed-top tests,
  `TestProtocolAuthFlatRunKeepsEveryLeaf8939`, #13531 flat chains,
  #9351 routing-instance grammar, #14616 LLDP packed disable, and
  the protocol-family run (`TestRIP|TestOSPF3|TestOSPF|TestISIS|
  TestProtocols|TestProtocol|TestRoutingInstance|TestLLDP|TestBGP`).
  `go vet ./pkg/config/` clean; `gofmt` clean.
- The full `pkg/config` suite does not terminate within 15–25 min
  on this loaded shared box (it times out inside the schema
  spelling/slot-escape differential gates, which compile the whole
  schema corpus); this is recorded as not-exercised rather than
  claimed, and the main agent should run it on a quieter box.
- `TestCompactBlockEquivalenceInventory2419` fails identically
  before and after this change on this base (pre-existing drift:
  `security log report` new site, `protocols lldp interface xpfarg
  disable` stale row) — base-attributed, unrelated to RIP/OSPFv3.

## Risk

- Behaviour delta: mixed packed-tail+braced-body lines at the RIP
  and OSPFv3 tops now install the credentials/router-id/export the
  operator wrote (previously silently dropped). Braced and plain
  packed spellings compile identically to before; an unmodelled
  packed tail still yields no expansion. No change outside the
  cited tops.
