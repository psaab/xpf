# #15176 — userspace-dp: persist validated NAT scope for session-hit revalidation (C07-01)

- **Timestamp**: 2026-10-19
- **Mechanism**: Session-hit NAT revalidation (`source_nat_translation_still_valid`,
  `destination_nat_translation_still_valid`, `nptv6_destination_still_valid` in
  `afxdp/poll_descriptor/policy_revalidation.rs`) rebuilt the ingress
  interface/routing-instance scope from the session's stored identity, passing
  `None` for the fabric scope. For fabric-ingress sessions
  `stamped_ingress_identity` records `(0, 0)` (#7096: the fabric stamp carries
  only a zone id), and identity-less HA imports (legacy peer, unfoldable name,
  fabric-redirected) also import `0`. The scope therefore resolved to
  `""`/`""`, so every interface- or RI-scoped SNAT/DNAT/static-NAT rule failed
  to match and the established session was revoked at the first config/FIB
  generation change (#11600 revalidation; #11337 fixed admission only). On the
  fabric-punt path (split-RG active/active) that is every cross-chassis flow;
  for synced sessions it hit after takeover.
- **Action**: `SessionMetadata` gains `nat_scope_ifindex: Option<i32>` — the
  validated NAT-scope logical ingress ifindex at admission (the V2 fabric
  scope identity from `stage_classify_fabric_ingress`, else the locally
  resolved logical unit; `None` for V1/unstamped fabric). The transit install
  in `poll_descriptor/mod.rs` records it on the forward row and the reverse
  companion inherits it (`shared_ops/reverse_synth.rs` also inherits it for
  materialized/synthesized companions). All three revalidators thread it as
  `fabric_ingress_scope_ifindex` into `nat_scope_ctx_for_flow` /
  `prerouting_ingress_scope`. When a judged forward row carries a translation
  but records no scope, `source_nat_revocation_on_session_hit_with_ingress`
  declines to revoke on scope grounds (keep) — including the reverse
  companion-less sessionless arm — rather than evaluate an empty scope; rows
  with a recorded scope are judged normally, so a withdrawn or rescoped rule
  still revokes. The scope crosses the HA wire as a cluster-stable fold:
  helper delta (binary trailing i32 after the PPTP pair + JSON
  `nat_scope_ifindex`, single-sourced via `SessionSyncAttribution`) → Go
  `SessionValue{,V6}.NatScopeIfindex` → cluster wire `NatScopeFold`
  (length-gated tail after the egress fold) → Go resolves the fold to its own
  logical ifindex in `buildSessionSyncRequest{V4,V6}`
  (`SessionSyncRequest.nat_scope_ifindex`) → Rust import stamps it on the
  imported metadata. NOT changed: admission scope selection, zone-policy
  revalidation, the `(0,0)` ingress-identity recording (#7096), or any
  scope-independent translation check.

- **Validation**: New cells in `policy_revalidation_tests.rs`:
  `fabric_scoped_snat_survives_with_recorded_scope_15176` and
  `imported_scopeless_snat_kept_without_recorded_scope_15176` exercise the
  exact mechanism (interface+RI-scoped pool SNAT, fabric / identity-less
  rows) and fail on unmodified `origin/master`;
  `recorded_scope_snat_revoked_when_rule_withdrawn_15176` and
  `recorded_scope_snat_revoked_when_rescoped_15176` are the anti-mutants
  (a recorded scope still revokes on withdrawal/rescope);
  `local_scoped_snat_survives_unchanged_15176` is the local control.
  Adjacent suites are the parent's gate.
- **Risk**: A scope-less translated session now survives a generation change
  even if its (unrecordable) scoped rule was withdrawn — the documented
  keep-over-empty-scope trade the issue prescribes; it still dies on idle
  timeout and on any scope-independent check. The binary delta frame grows
  by 4 bytes (length-gated; old Go decoders skip it) and the cluster tail by
  4 bytes when a scope fold is present (old decoders stop after the egress
  fold). Rolling-upgrade peers import `nat_scope_ifindex = 0` and keep the
  pre-fix keep behaviour via the no-scope decline.
