# Commit descriptions accepted control characters; commit history printed them raw (#15144, B01-03)

## Why

`CommitWithDescription` bounded only the length of the operator commit
description (`maxCommitDescriptionBytes`, #4891) and recorded it verbatim
in the in-memory history entry and the durable JSONL audit journal. Both
`show system commit history` renderers — the in-process CLI
(`pkg/cli/cli_show_system.go`) and the gRPC ShowText renderer that feeds
the remote `cli` (`pkg/grpcapi/server_show_system.go`) — printed
`e.Detail` raw. A principal with commit authority could therefore embed
a newline to forge an extra history row, or ESC/C1 bytes for OSC/CSI
terminal injection into a viewer's terminal. Enforcement was unchanged;
the impact is audit-display forgery plus terminal-escape injection.

## What

- `pkg/configstore/store_commit.go`
  (`commitWithDescriptionLocked`, shared by every
  CommitWithDescription* variant including the gRPC commit path via
  `commitFn` → `req.Comment`): reject any description that is not
  `termsafe.DisplaySafe` — C0/DEL/C1 controls, U+2028/U+2029, invalid
  UTF-8 — with a clear error, beside the existing #4891 length cap and
  before anything is persisted or promoted. `DisplaySafe` is exactly
  the predicate `SanitizeForDisplay` escapes on, so admitted
  descriptions are stored identical to their rendered form. No journal
  or history sanitization was added: the journal keeps the verbatim
  audit record for admitted (now display-safe) descriptions.
- `pkg/cli/cli_show_system.go` and `pkg/grpcapi/server_show_system.go`:
  render `termsafe.SanitizeForDisplay(e.Detail)` instead of raw
  `e.Detail`, so a legacy journal line written before the rejection
  renders as one escaped line (`\x0a`, `\x1b`, …) instead of forged
  rows. Clean details are returned unchanged by the sanitizer's fast
  path, so normal output is byte-identical.

NOT changed: `CommitConfirmed*` (carries no description), the journal
format or its #4891 truncation belt, `HistoryEntry.Comment` handling in
`ListHistory` (timestamp/index only on the wire), principal
normalization (already covered by #10301), or any other Detail sink.

## Validation

- RED (pre-fix, tests copied onto a detached `origin/master` worktree):
  `TestCommitWithDescriptionRejectsControlChars15144` fails with
  `CommitWithDescription("ok\n  9  … forged row") accepted`;
  both renderer tests fail with the raw output
  `"  0  2026-01-02 03:04:05  commit  ok\n  9  forged\x1b[31m\n"`
  (raw ESC + forged second line).
- GREEN targeted:
  `go test ./pkg/configstore/ -run
  'TestCommitWithDescriptionRejectsControlChars15144|TestCommitWithDescription_RejectsOversized|TestCommitWithDescription$' -count=1` PASS;
  `go test ./pkg/grpcapi/ -run
  TestShowCommitHistoryEscapesLegacyDetail15144 -count=1` PASS;
  `go test ./pkg/cli/ -run
  TestShowSystemCommitHistoryEscapesLegacyDetail15144 -count=1` PASS.
  Full `pkg/configstore`, `pkg/cli`, `pkg/grpcapi` suites run before push.
- Controls: a legitimate multibyte/punctuation description commits and
  is journaled verbatim; clean legacy details render verbatim in both
  renderers; the #4891 over-cap rejection is untouched.
- FAIL-ON-REVERT: dropping the `DisplaySafe` check re-admits every
  hostile description; printing raw `e.Detail` reintroduces the raw
  newline/ESC in both renderer tests (the RED evidence above is that
  revert, measured on unmodified master).
## Risk

Operators can no longer use tabs/newlines in commit comments (they
were never renderable safely in a single-line history row); the error
names the reason. Legacy hostile journal lines remain on disk
verbatim but now display escaped. No wire, journal-format, or
dataplane behaviour change.
