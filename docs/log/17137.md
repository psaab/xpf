# #17137 — R4-Q48-02: the #7194 session-delta schema gate's production Go fingerprint was unguarded

- **Timestamp**: 2026-10-27
- **Defect (live on origin/master 5849894)**: The production Go half of
  the #7194 fail-closed fingerprint gate,
  `pkg/daemon.sessionDeltaWireNames`, was a separate copy that no test
  compared with anything. The cross-language cells compared two
  test-only extractors (`goWireNames7194` over Go tags vs
  `rustWireNames7194` over Rust source), while
  `localSessionDeltaSchemaFingerprint()` was only ever compared with
  itself (or itself XOR a constant). A one-token drift (e.g. keeping
  `,omitempty` in the extracted name) flips
  `CompareSessionDeltaSchema(advertised, local)` to
  `SessionDeltaSchemaMismatch`, `userspaceDeltaSchemaAdmits` then
  withholds every HA session-open delta batch, and every pkg/daemon
  test stays green — the measured mutant in the issue
  (`0xd1c44663dacefabb` → `0xee921ad6d564dc2b`, 84/84 PASS). The two
  copies had also already diverged in semantics: for a
  `json:"-,omitempty"` tag the production copy emitted `-` (as
  encoding/json does) and the test copy dropped it.

## What

- Added `pkg/wireschema.WireNamesOf(sample any) []string`: the single
  production Go extractor of JSON wire names (json tags; flat
  tag-name semantics: unexported skipped, bare `-` excluded, `-,…`
  emitted as `-`, empty name falls back to the field name). The
  package doc deliberately does NOT claim to mirror encoding/json
  exactly: embedded-field promotion and duplicate-name dominance
  are out of scope because the sole consumer, `SessionDeltaInfo`,
  is flat, and `TestWireNamesOfTagSemantics17137` pins the
  narrowed contract (structure inputs included).
  - Placement: NOT `pkg/dataplane/userspace/wireschema`. The #1476
    canary `TestUserspaceManagerDoesNotImportReflectOrUnsafe`
    recursively walks `pkg/dataplane/userspace` (subpackages included,
    confirmed by running it against a first cut under that tree — it
    flagged the new subpackage) and forbids `reflect`/`unsafe` there,
    so the extractor lives in the tiny top-level `pkg/wireschema`,
    outside that tree. It is generic over the sample value rather than
    importing `pkg/dataplane/userspace`, because the parent package's
    own internal tests must consume it without an import cycle —
    otherwise the tests would keep a private copy, which is the defect.
- `pkg/daemon`: deleted `sessionDeltaWireNames`; the gate's fingerprint
  and its mismatch log now derive from
  `wireschema.WireNamesOf(dpuserspace.SessionDeltaInfo{})`.
- `pkg/dataplane/userspace` tests: `goWireNames7194` now delegates to
  the same production extractor (the last test-only Go copy is gone).
  `grep -rn 'func .*WireNames' pkg` shows one production Go extractor
  (`wireschema.WireNamesOf`), one test adapter over it, and the Rust
  source-text extractor.
- New acceptance cell
  `pkg/daemon.TestProductionDeltaSchemaMatchesRustFixture17137`:
  asserts `localSessionDeltaSchemaFingerprint() ==
  SessionDeltaSchemaFingerprintOf(names)` where `names` are the keys
  of the #16132 fixture's `session_delta_info` specimen — serde-emitted
  production Rust output — with a 35-name anti-vacuity floor and
  no-skip-on-missing fixture load.

## Fixture staleness found by the new cell (fixed in-PR)

The new cell initially **failed** on this branch: the Go schema carries
`stream_seq` (#16627) but the checked-in #16132 fixture's
`session_delta_info` specimen did not — the fixture had not been
regenerated since that field landed (the #16132 completeness cell was
already red on origin/master for the same gap, among others).
Regenerated with
`XPF_PROTOCOL_WIRE_REGEN=1 cargo test --bin xpf-userspace-dp wire_invariant_default_specimens`
(substring filter; `-- --exact` matches 0 tests because the test lives
in the bin target's `protocol::tests` module). The regen also swept in
other pending Rust-side specimen drift on master
(`flow_shard_lock_*` / `live_write_lock_*` counters, `zone_snapshot.functional`,
key-order normalisation). After the regen the #16132 cell's remaining
failure is only the pre-existing `next_table_route` population gap
(Rust `skip_serializing_if = "bool_is_false"` on a default-`false`
populated specimen; unrelated, on master too) — down from five missing
keys on baseline to that one.

## Risk

Low. The extractor's semantics are byte-identical to the deleted
production copy for the current struct (same tag split, same `-`
handling, same fallback), so the daemon fingerprint — and thus gate
behaviour against running helpers — is unchanged; the regenerated
default specimens are additive keys a `default`-decoding consumer
already tolerates. The only behavioural surface is that the gate's
input is now shared with, and pinned against, the Rust-emitted fixture.
