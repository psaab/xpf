# #12147 — bound v3 SET error responses by msgMaxSize

- **Timestamp**: 2026-10-07
- **Action**: Bound the echoed SNMPv3 SET `notWritable` response by the manager's effective `msgMaxSize`; return `tooBig` with an empty varbind list when it overflows.
- **Base**: `1c384b9a47ff7d6e567fa50632faa75c3995ae87`
- **Files**:
  - `pkg/snmp/v3.go` — size-check the v3 SET error response and use the existing `tooBig` fallback.
  - `pkg/snmp/v3_set_size_12147_test.go` — oversized and small SET response regression coverage.
  - `docs/log/12147.md`

## Why

The v3 SET handler echoes each requested OID in its `notWritable` response without checking the manager's advertised receive limit. A request advertising the RFC minimum of 484 bytes could therefore receive an oversized response, unlike the existing bounded GET/GETNEXT and GETBULK paths.

## What

The SET branch now builds its normal `notWritable` response, compares its encoded length to `effectiveMaxSize(msgMaxSize)`, and replaces an oversized result with `tooBig`, error-index 0, and no varbinds. Responses that fit retain the existing `notWritable` status and echoed OIDs. The regression tests exercise an authenticated 48-OID request that remains below the local 4096-byte request ceiling and a small two-OID request.

## Risk

Only oversized SET error responses change to the RFC 3416 §4.2.5 `tooBig` form; small SET requests retain `notWritable`. No push or PR was created.
