# #9810 — next-table window counted per leak, spent per ingress; lo0 leaks in

Cohort: SYN-WIN-01 + SYN-LO0-02 (material) with LEAD-O4, SYN-C-NET-06,
SYN-C-LEAK-05.

## What was wrong

Since #9420 the applier installs one ip rule per default-instance ingress
interface per leak (N slots per leak, drawn leak-atomically), but the strict
commit gate and `StaticRouteExclusions` still counted one slot per leak. With
L leaks and L <= 100 < L*N the gate passed, the FIB and `show` published all
L, and the kernel installed floor(100/N). Separately, unclaimed `lo0` units
entered the scoping set (resolving detached as `lo0`), inflating N and adding
a detached rule per leak per unit — while a literal `lo` unit collapses to
kernel `lo`, the live #9420 cross-VRF hijack.

## Decisions (2 hostile plan reviews, both approve-with-changes; adjudicated)

- N==0 rejects (gate) / excludes all (verdict): the applier installs nothing
  then (#9420 fail-closed), so fail fast. Cost-1 fallback was rejected by both
  reviewers — it preserves the split.
- Shared resolver lives in pkg/config (`default_instance_ingress.go`);
  `pkg/routing` delegates (no import cycle; daemon untouched). Tunnel-name map
  hoisted once per call (A10).
- LEAD-O4 drops loopback PBR attachments LOUD in the builder (fail-safe
  under-steer; build errors are warn-level per #5844, so no commit-behavior
  change). Asymmetry is deliberate: the next-table loopback skip is silent
  (removes detached garbage), the PBR drop is loud (discards intended
  steering).
- LEAK-05 rolls back the partial leak and continues (break-inner, rollback,
  continue-outer). Reviewers split on prio when a rollback del FAILS;
  adopted advance-by-survivors: orphans occupy kernel slots until the next
  clear, and not advancing risks programming beyond the scanned window, which
  clear() could never remove (permanent leak). Transient desync under active
  faults is unavoidable either way; the joined error + #9693 retry heals it.
- EEXIST counts as installed (new `isRuleAlreadyPresent`, mirroring
  `isRuleAlreadyGone`): the desired content is already in the kernel, and the
  clear failure that left it is already loud via clearErr. Rolling back on
  EEXIST would delete good siblings.
- Loopback predicate is `lo<N>` + bare `lo`, suffix-stripped
  (`IsLoopbackIngress`), loopback-ONLY — `IsTunnelOrLoopbackIfName` reuse
  explicitly forbidden (would drop tunnel ingress). Bare-`lo` divergence from
  the DHCP predicate documented at the site.
- In scope per review: parsed-CIDR v4-first partition in exclusions (mixed
  lists are legal per #9820; otherwise truncation survivors differ from the
  kernel). N==0 shadowing of the #5633 disposition gate documented as
  accepted; gate reorder forbidden.
