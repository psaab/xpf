# #16739 — Preempt election scaled priority by weight, failing over on partial monitor loss

- **Timestamp**: 2026-10-25
  - **Action**: Under `preempt`, `electRG` compared
    `EffectivePriority = base * weight / 255` on both nodes, so a
    partial interface-monitor loss (e.g. priorities 200/150, monitor
    weight 100 down → weight 155 → effective 121 < 150) failed the RG
    over and then back on recovery — two ownership moves, GARP churn,
    and session loss per tolerated link flap. Junos fails over only
    when the redundancy-group threshold reaches zero. Fix:
    `electRG`'s preempt arm now compares RAW base priority via the new
    `preemptEffectivePriority` helper while both weights are above
    zero; weight 0 keeps its existing unconditional arms (local
    weight 0 → secondary, peer weight 0 → primary). The scaled
    `EffectivePriority` ordering is retained exactly where it is
    load-bearing: the #12164 dataplane-arm-debt yield / committed-pin
    release (a fresh node at the weight-1 arm floor must lose), and
    the unmanaged cold-start / dual-active arms. A new preempt
    arm-debt yield (positive arm debt + greater peer raw weight +
    scaled receiver ordering + live echo lease, RG0 excluded) plus a
    symmetric peer-yielded-at-floor takeover keep an unready primary
    from blackholing the RG under the raw-priority rule.
    `docs/phases.md` CC-4 updated to describe both orderings.
  - **File(s)**: `pkg/cluster/election.go`,
    `pkg/cluster/preempt_weight_threshold_16739_test.go` (new),
    `docs/phases.md`, `docs/log/16739.md`
  - **Validation**: New two-manager cells: partial loss (weight 155)
    keeps node0 primary with zero failover-count delta and no failback
    on recovery; weight-0 loss still fails over; peer-side partial
    loss control; direct `electRG` raw-priority cells; preempt
    arm-debt floor (weight 1) still yields to the healthy peer
    (#12164). Existing #12164 suites
    (`TestNonPreempt*12164`, `TestCommitted*12164`, `TestBothFloor*`,
    `TestArmDebt*`) re-run green. Full `pkg/cluster` suite run before
    commit.
  - **Residual**: Cold-start / dual-active arms still order by scaled
    `EffectivePriority`, so a both-secondary cold start with partial
    debt on the higher-priority node can still elect the lower-raw-
    priority peer — pre-existing behaviour, outside the issue's
    preempt-failover acceptance, and changing it would perturb the
    #12164 receiver-ordering pins. No live-VM failover timing was
    measured; the fix is verified at the election level the issue's
    probe used.
