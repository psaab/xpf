# #16503: split-RG fabric punt keeps the FBF/PBR steer on the receiver

- **Timestamp**: 2026-10-24
- **Action**: `ingress_route_table_override_with_mode` in
  `userspace-dp/src/afxdp/forwarding/pbr.rs` derived the route-lookup-affecting
  filter's ifindex only from the raw `meta.ingress_ifindex` (+ VLAN logical
  resolution). For a validated V2 fabric punt that raw ifindex is the fabric
  link, which carries no customer FBF filter, so the receiver fell back to the
  native table and dropped the sender's `then routing-instance X` steer —
  steered new flows were denied under the fabric zone or left via the native
  uplink for the duration of an RG split. Now, when
  `meta.fabric_ingress_ifindex != 0`, the filter is evaluated on that scope
  ifindex (mirroring `effective_ingress_ifindex` in `tx/cos_classify.rs`,
  #14663), and the resulting `RouteOverride::Table` stamps
  `install_table_identity(instance)` via the existing `pbr_table_target` path.
  Stage 9 populates the scope field only for a `ValidScoped` stamp and the
  poll path clears it when the owner-RG gate withholds the zone, so an
  ambiguous stamp never consults the scope's filter. V1-only punts keep the
  fabric-link lookup as a documented limitation (no scoped identity).
