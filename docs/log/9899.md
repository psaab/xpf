## Behavior

- Tunnel keys accept unsigned decimal **0..4294967295**, TTL **1..255**, and
  VLAN/inner-VLAN IDs **0..4094**. Schema and compilation share the scoped parser.
  An omitted TTL retains the default-64 sentinel; explicit zero is rejected.
  Empty operands, signs, whitespace, non-digits and overflow are not defaults.
  Strict compilation rejects invalid values. Tolerant compilation warns with
  the path/token and quarantines an invalid interface tunnel's whole interface,
  or skips the affected unit for unit tunnel/VLAN errors. Valid siblings remain.
  This prevents unkeyed, inherited-key and untagged fallback. The existing
  strict QinQ presence refusal remains in force, including inner VLAN 0.
- Hierarchical EOF requires a leaf terminator. Existing before-right-brace
  tolerance and the separate flat-set command grammar remain unchanged.
- Non-nil provenance masks must match the path length before an editor mutates
  the tree. Nil still means unknown provenance. Copy/rename behavior is unchanged.
- Numeric protocol tokens use the raw canonical decimal spelling and the
  existing 0..255 range across application, firewall, host-projection and DNAT
  readers. Named aliases retain their previous case/whitespace behavior and
  DNAT retains its intentional name exclusions. Historical hash compatibility
  parsing is not changed.
- Both classifier completion positions include configured inet-precedence names,
  including entryless classifiers. Quoted firewall self-keyword operands remain
  values, so existing validators can reject them instead of silently dropping
  refusal evidence.

## F-107: the Junos dissent was correct

[Juniper's firewall configuration guidelines](https://www.juniper.net/documentation/us/en/software/junos/routing-policy/topics/concept/firewall-filter-stateless-guidelines-for-configuring.html)
state that `family inet` is optional and that `[edit firewall]` and
`[edit firewall family inet]` are equivalent. Refusing this spelling would reject
valid Junos configuration. The fix compiles it as IPv4 instead.

The root `filter` schema is a deep copy, not a shared schema identity. Compact
stanzas fold first; implicit filters are then wrapped as inet on the cloned
compiler/validation view, before expansion and gates. The source candidate and
family spelling in display output are not rewritten. Same-family duplicates
still hit #8426 and `family any` collisions still hit #3884; normalization does
not merge away these guards. Explicit inet6 remains separate.

The initial ordering was caught by the existing `TestElidedFirewallFamily8850`
and an actual `xpfd check-config` run: a packed `firewall filter F { ... }` with
an interface reference failed with undefined filter F while its braced twin
passed. Admitting `(firewall, filter)` and folding before alias relocation made
that exact CLI input pass, without regressing explicit-family compact roots.
The internal test-only `skipCompactNormalize` option still deliberately bypasses
compact folds; it is not a production entry point.
