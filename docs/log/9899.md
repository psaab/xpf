## Behavior

- Tunnel keys accept unsigned decimal **0..4294967295**, TTL **1..255**, and
  VLAN/inner-VLAN IDs **0..4094**. Schema and compilation share the scoped parser.
  An omitted TTL retains the default-64 sentinel; explicit zero is rejected.
  Empty operands, signs, whitespace, non-digits and overflow are not defaults.
  Strict compilation rejects invalid values. Tolerant compilation warns with
  the path/token and quarantines an invalid interface tunnel's whole interface,
  or skips the affected unit for unit tunnel/VLAN errors. Valid siblings remain.
  This prevents unkeyed, inherited-key and untagged fallback. The existing
  strict QinQ presence refusal remains in force, including inner VLAN 0.
- Hierarchical EOF requires a leaf terminator. Existing before-right-brace
  tolerance and the separate flat-set command grammar remain unchanged.
- Non-nil provenance masks must match the path length before an editor mutates
  the tree. Nil still means unknown provenance. Copy/rename behavior is unchanged.
- Numeric protocol tokens use the raw canonical decimal spelling and the
  existing 0..255 range across application, firewall, host-projection and DNAT
  readers. Named aliases retain their previous case/whitespace behavior and
  DNAT retains its intentional name exclusions. Historical hash compatibility
  parsing is not changed.
- Both classifier completion positions include configured inet-precedence names,
  including entryless classifiers. Quoted firewall self-keyword operands remain
  values, so existing validators can reject them instead of silently dropping
  refusal evidence.

## F-107: the Junos dissent was correct

[Juniper's firewall configuration guidelines](https://www.juniper.net/documentation/us/en/software/junos/routing-policy/topics/concept/firewall-filter-stateless-guidelines-for-configuring.html)
state that `family inet` is optional and that `[edit firewall]` and
`[edit firewall family inet]` are equivalent. Refusing this spelling would reject
valid Junos configuration. The fix compiles it as IPv4 instead.

The root `filter` schema is a deep copy, not a shared schema identity. Compact
stanzas fold first; implicit filters are then wrapped as inet on the cloned
compiler/validation view, before expansion and gates. The source candidate and
family spelling in display output are not rewritten. Same-family duplicates
still hit #8426 and `family any` collisions still hit #3884; normalization does
not merge away these guards. Explicit inet6 remains separate.

The initial ordering was caught by the existing `TestElidedFirewallFamily8850`
and an actual `xpfd check-config` run: a packed `firewall filter F { ... }` with
an interface reference failed with undefined filter F while its braced twin
passed. Admitting `(firewall, filter)` and folding before alias relocation made
that exact CLI input pass, without regressing explicit-family compact roots.
The internal test-only `skipCompactNormalize` option still deliberately bypasses
compact folds; it is not a production entry point.

## Parent-review follow-up (three findings, all folded)

The parent split PR #10106 (GPT NEEDS-MAJOR, three findings) and verified the

### P1 — shared implicit-inet family scope (was per-filter wrappers)

The first F-107 normalization wrapped EACH implicit filter in its own
synthetic `family inet` node. `walkGroupToContext` returns the FIRST matching
scope only, so with two implicit filters in a group body a nested
apply-groups lookup found F's scope for both filters and G's inherited
template silently vanished. `TestImplicitInetNestedGroupMultiFilter9899`
demonstrated exactly that pre-fix: both group-implicit nested cases RED
(G kept only its inline term), while group-explicit and top-level cases
stayed GREEN, isolating the cause to the group-side wrapper split.

The fix re-homes every implicit filter in one firewall scope under a SINGLE
navigable scope: the first explicit hierarchical `family inet` node when one
exists (implicit definitions keep document order around its children), else
one synthetic wrapper at the first implicit's position. Nothing is merged
away — each filter node survives — so the #8426 same-family duplicate and
#3884 cross-family gates see identical evidence, and the set-command
`family { inet { ... } }` shape is untouched (the compiler already reads both
shapes per family node). All four nested/top-level inheritance cases GREEN;
all pre-existing F-107 spellings and gates unchanged.

### P2 — quote/bracket provenance through packed bodies (F-105)

`packedBodyChildren` synthesized nodes from the packed tail's STRINGS only,
dropping `KeysQuoted`/`KeysBracketed`. The F-105 `KeyQuoted` check then read a
synthesized `protocol "protocol"` node as bare and dropped the value.
`TestQuotedSelfMatchValuesPackedTerm9899` (`term T from protocol "protocol"
then discard;`) RED pre-fix: strict accepted the vanished value and lenient
kept nothing with no warning. The fix slices the tail's provenance alongside
its tokens (absent stays absent — unknown, not bare — via the existing
`setKeysQuoted`/`setKeysBracketed` normalizers). Single value isolates the
quote bit; multi-value packed runs remain the pre-existing `consumeNodeKeys`
arity behavior, unchanged. GREEN post-fix; the hierarchical and flat F-105
cells are unaffected.

### P2 — final-unit quarantine suppresses the unitless fallback

Lenient quarantine drops an invalid unit from `Units` but kept the
interface-level tunnel, so when the FINAL unit went the emitter's
`len(iface.Units) == 0` arm published the parent tunnel under the bare
interface name — a fallback endpoint for an interface that authored units.
`TestInterfaceFinalUnitQuarantineSuppressesFallback9899` RED pre-fix (one
spurious `gr-0/0/0` endpoint). The fix records `AuthoredUnits` on
`InterfaceConfig` before the quarantine loop and the emitter skips the
fallback when units were authored but none survived. A truly unitless
control still emits. No other `len(Units) == 0` site emits (the two
dataplane userspace sites skip), so the guard is singular.
