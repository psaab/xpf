# #13221 — release sibling failover barriers after batch failure

- **Timestamp**: 2026-10-15 (`fix/13221-campaign-pub`)
- **Action**: release every unconsumed sibling barrier when a batch wait returns its first failure.

## Red before

On clean `origin/master` (`4b3a2b004`), added `TestFailoverActuationBarrier_BatchFailureConsumesSiblingBarriers` to arm RG 1 and RG 2, fail RG 1, actuate RG 2, and wait on the batch. The test failed because one barrier remained in `failoverActuateWait` after the early return (`armed barriers after failed batch (resolved sibling) = 1, want 0`). The test also covers an unresolved sibling and ensures cleanup does not wait out that sibling's timeout.

## Change

`waitFailoverActuatedBatch` retains the first error, then identity-check-disarms every later RG barrier before returning. It does not wait for a sibling after the batch has already failed: resolved siblings are removed and unresolved siblings cannot leak or delay the failed response. The identity check prevents cleanup from removing a newer request's replacement barrier. The regression checks both resolved and unresolved siblings and confirms the existing batch-success / first-failure coverage remains.
