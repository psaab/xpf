# Export forwarding health and separate idle UMEM gauges (#13299)

- **Issue/source**: #13299, deep-review finding D5-10. Prometheus did not
  expose the canonical `fwdstatus` signals, sampler `/proc/self/stat` failures
  silently discarded samples, and per-binding frame inventory was not exposed
  separately from the existing in-flight utilization ratio.
- **Change**: `Sampler.sample` now increments a synchronized cumulative read
  error count on `/proc/self/stat` failures and publishes it through
  `SamplerSnapshot` and `ForwardingStatus`. The canonical buffer ratio keeps
  its existing in-flight semantics: idle pending-fill inventory does not
  falsely report saturation. New per-binding gauges expose total/in-flight
  UMEM frames and pending fill/prepared-TX/local-TX inventories separately.
  REST Prometheus reuses the one userspace `ProcessStatus` snapshot already
  fetched for the rest of the scrape, so a live daemon wrapper cannot be
  mistaken for eBPF and no extra status RPC or userspace map-stat scan occurs.
  That fetched status is shared with the forwarding summary; the CPU sampler
  is shared between CLI, gRPC, and REST.
- **Regression tests**: `pkg/fwdstatus/forwarding_health_13299_test.go`
  preserves the distinction between idle fill inventory and in-flight
  utilization and checks sampler error counting;
  `pkg/api/metrics_fwdstatus_13299_test.go` covers shared snapshot reuse and
  separate pending-fill gauge export.
- **RED evidence**: On pristine `origin/master` (`0de5182`), the API regression
  `TestPendingFillFramesAreExportedSeparately13299` failed because the
  pending-fill inventory had no Prometheus series. The test drains the
  collector asynchronously, so the failure is the missing gauge rather than
  a blocked metric channel. The earlier attempted BufferPercent regression
  exposed a false alarm; it was replaced after confirming fill-queue frames
  are intentionally idle and excluded from in-flight utilization.
- **GREEN evidence**: `go test ./pkg/fwdstatus/ ./pkg/api/ -count=1` passed.
  `go build ./...` and `go vet ./pkg/fwdstatus/ ./pkg/api/ ./pkg/daemon/`
  passed. Focused daemon startup call-site tests passed; `gofmt -l` and
  `git diff --check` were clean. A full daemon-package test run exceeded the
  360s command deadline before completion.
- **Risk**: Prometheus forwarding health uses the existing canonical `Build`
  calculation at scrape time. Binding occupancy is clamped to 100% by the
  established formatter/build contract. Metrics are omitted where the source
  reports unknown rather than publishing a false zero.
