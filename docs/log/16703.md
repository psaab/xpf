# #16703 — Guarded IPsec transition retired the old actor without verifying a quarantine guard exists

- **Timestamp**: 2026-10-25
  - **Action**: The bridge-family `meta sdifname` EOPNOTSUPP half of this
    issue was already fixed on master by #16618 (`18f97d29b7`): the
    lifeline `sdifname` accept is emitted only on the inet family, and
    its kernel cell installs a lifeline-carrying QuarantineAll through
    `InstallIpsecQuarantineGuard`, `InstallIpsecDivert` and a failed-drain
    `InstallIpsecDivertWithDrain`. This change closes the remaining
    acceptance: the daemon's guarded-failure path assumed the guarded
    installer retained a two-family DROP guard on every post-ACK
    failure, so it retired the old actor unconditionally — when the
    guard install itself had failed, no guard existed and the old
    divert table stayed in the kernel pointing at stopped NFQUEUE
    listeners. `pkg/nftables` now exports the guard readback as
    `VerifyIpsecQuarantineGuard` on the `Installer` interface
    (forwarded by the daemon's `guardedNftInstaller14969` wrapper and
    the test fakes). On a failed guarded transition,
    `commitIpsecCaptureStage` re-verifies the guard before retiring
    the old actor; when no guard verifies it attempts one explicit
    lifeline-carrying guard install
    (`installIpsecQuarantineForDaemon16618`) and, if that also fails,
    returns the transition error annotated `(no quarantine guard
    verified)` — the failure is reported, never silent, and the orphan
    flag is still set so removal is retried. New kernel cell
    `TestIpsecQuarantineGuardVerify16703` and daemon cells
    `TestGuardedFailure*16703` cover the verifier and the three
    guarded-failure arms (guard present, guard installed on retry,
    guard unverifiable).

    the absence explicit in the returned error instead of silent.
