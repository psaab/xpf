# Issue #13197: reject stale FIB bumps against published state

## Why

During disarmed/deferred worker operation, `Coordinator::validation.fib_generation`
can lag `guard.status.last_fib_generation`. A stale FIB bump compared only to
the coordinator state and could lower the published status and stored snapshot.
The bump also changed the stored snapshot's P-MECH authority while retaining a
content digest that identified the pre-bump contents.

## What

- Reject a bump below either the published status generation or coordinator
  generation before publishing any state.
- Clear the stored snapshot's `content_digest` when an accepted bump updates
  its generation/P-MECH authority.
- Restrict the coordinator-only bump method to tests; production uses the
  snapshot-coupled publishing method.
- Add regression coverage for a disarmed rollback and accepted-bump digest
  invalidation.

## Validation

  `rollback against published status must be rejected (#13197)`.
- `CARGO_TARGET_DIR=/var/worktrees/.cache/cargo-13197 cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp server::tests::` — 172 passed.
- `CARGO_TARGET_DIR=/var/worktrees/.cache/cargo-13197 cargo check --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp` — passed.

## Risk

Accepted route-only bumps invalidate the prior content digest, so a later
same-generation full apply cannot rely on that old digest and must provide a
valid identity under the existing content-integrity gate. No wire format or
operator-facing contract changed.
