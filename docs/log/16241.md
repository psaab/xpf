# #16241 — XDP double adjudication: branch hit counts + fail-closed analysis

## Ask (narrowed)

1. Fallback-reason/branch hit counts for plain TCP hit-forwards.
2. Per-arm fail-closed analysis.
3. Remove ONLY arms proven disposition-identical (tests proving identical
   disposition per packet class: local/WG/GRE/NAT-miss/early-filter).
4. If no arm is safely removable: instrumentation + analysis only.
5. Perf claim must be structural (branches removed), not measured.

This change delivers (1) and (2), proves no arm is safely removable today,
and therefore removes nothing. The structural perf claim is: zero branches
removed, because the analysis below shows every arm owns a distinct
disposition. No throughput number is claimed.

## What shipped

A new per-CPU BPF map `userspace_branch_stats` (27 slots) counts hits per
dispatch arm in `try_xdp_userspace`. A separate map — not new indices in
`userspace_fallback_stats` — because the degraded map's indices are a
pinned operator ABI (Go `degradedPathReasonNames`, the Rust debug reader,
and the #8258 index-agreement test join the sides by index), and a
hit-forward is not a degraded disposition. Counting is gated on the TRACE
ctrl flag inside the single outlined `incr_branch_stat` callee (the
`record_trace_packed` precedent, #4113 F7): with tracing off, the hot path
pays one flag test in one subprogram, not a map touch per arm.

Surfaces:

- Shim: `USERSPACE_BRANCH_ARM_*` constants (index order = dispatch order),
  `userspace_branch_stats` map, `incr_branch_stat` outlined callee.
- Go: `xdpBranchArmNames` + `readXDPBranchStatsLocked` (sums per-CPU,
  omits zero arms), projected as `ProcessStatus.XDPBranchCounters`
  (`xdp_branch_counters`) on every status publication.
- Loader: `userspace_branch_stats` added to `userspacePinnedShimMaps`
  (disposable counter map, like `userspace_fallback_stats`).
- Rust helper: `XDP_BRANCH_ARM_NAMES` + `read_xdp_branch_stats`, dumped as
  `XDP_BRANCH:` beside `XDP_DEGRADED:` in the debug report.
- Tests: `TestXDPBranchArmNamesAgreeWithTheShim16241` (Go↔shim index
  agreement, self-enrolling), `TestXDPBranchArmsAreAllCounted16241`
  (every arm has a call site), `xdp_branch_arm_names_agree_with_the_shim_16241`
  (Rust↔shim agreement), the disposition matrix below executed via
  BPF_PROG_TEST_RUN, the WG steer pair, and a TRACE-off control proving the
  gate (dispositions unchanged, zero branch counts, degraded counters still
  fire).

## Per-arm fail-closed analysis

Disposition = (XDP action, metadata/queue effect, which kernel-pass fence
applies, session/NAT consequences). Two arms are disposition-identical only
if all four agree for every packet class. Verdict per arm (`try_xdp_userspace`
unless noted):

| Arm (branch counter) | Disposition | Fail-closed role | Identical to another arm? |
| --- | --- | --- | --- |
| `l2_parse_fail` | cpumap-or-PASS, no metadata | Frame too short to classify; never DROP | No — only arm reachable before ethertype exists |
| `non_ip_pass` | XDP_PASS direct | ARP/LLDP must drive the local L2 state machine (#11387 confines bridge flood) | No — cpumap would break neighbor resolution |
| `qinq_drop` | DROP + `qinq_drop`/`transit_drop` | Nested/legacy TPID is unadjudicable (#9888); PASS would forward by MAC with no zone verdict | No — PASS arms differ by action |
| `stag_drop` | DROP + `stag_drop` | Single S-tag has no kernel identity; PASS aliases (parent,VID) zones (#10655) | No — distinct reason + guard ordering vs QinQ |
| `non_adjudicated_pass` | cpumap-or-PASS | Ifindex outside the adjudicated set must never reach the parser (#8279 raw-L3 hole) | No — the only pre-parse authority gate |
| `l3_parse_fail` | DROP + `parse_fail` | Malformed IP on an adjudicated interface fails closed | No — `l2_parse_fail` passes; merging re-opens drops on non-adjudicated ifaces |
| `tagged_only_local_drop` | DROP | VID-0 to firewall-owned dst on a tagged-only bind (#12055) | No — action differs from `session_miss_local` |
| `land_drop` | DROP + `land_drop` | Profile-gated LAND screen; absent zone row fails closed (#15789) | No — per-zone byte decides; ALARM variant already counted via degraded `land_alarm` |
| `binding_not_ready` | local-pass or DROP by degraded-local check | Missing/stale binding: transit fails closed, local/control survives (#15854) | No — four degraded reasons share this slot; the branch slot counts the arm, reasons count the cause |
| `wg_steer` | cpumap-or-PASS | WG handshake/cookie to the kernel control socket; exact listener tuple only (#1432) | No — `session_miss_local` would also claim transport-data-adjacent UDP; session-hit pre-check prevents SNAT-reply theft |
| `early_filter` | cpumap-or-PASS + `early_filter` | Multicast/broadcast control traffic pre-session (#10640) | No — runs BEFORE session lookup; moving it after changes WG/GRE pre-emption |
| `session_hit_redirect` | fallthrough to XSK redirect | Established flow stays on the worker path | No — `session_miss_redirect` pays full miss adjudication; the hit skips it |
| `session_hit_pass_kernel` | cpumap-or-PASS + `pass_to_kernel` | Live session marked local delivery | No — session ownership beats the miss arms' destination checks |
| `session_miss_nat_ndp` | cpumap-or-PASS | On-link NDP to a NAT external belongs to kernel proxy-NDP (#15117) | No — type+hop-limit+destination qualified; `early_filter` is destination-blind multicast |
| `session_miss_icmp_nat_local` | cpumap-or-PASS | ICMP echo to an interface-NAT local address | No — protocol/type qualified subset of local delivery |
| `session_miss_local` | cpumap-or-PASS | Exact local-destination ownership (map hit) | No — WG worker claim declines it for transport data (#8274) |
| `session_miss_ifnat_kernel_tunnel` | cpumap-or-PASS | ESP/non-native-GRE to an interface-NAT dst terminates in-kernel (#304-qualified) | No — protocol-qualified; generic ifnat arm redirects instead |
| `session_miss_ifnat_redirect` | fallthrough + `interface_nat_no_session` | SNAT-reply repair needs the worker (#290) | No — only arm that counts a degraded reason AND redirects |
| `session_miss_redirect` | fallthrough to XSK redirect | New flow adjudicated by the worker (policy create/deny) | This is the measured hit-forward's sibling, not its twin: hit skips miss checks |
| `gre_inner_pass_kernel` | cpumap-or-PASS + `pass_to_kernel` | Native-GRE inner PASS only when the OUTER is local (#10651) | No — inner classifier + outer-local gate; no other arm decapsulates |
| `fragment_redirect` | fallthrough to XSK redirect | GRE/WG fragments stay for reassembly (#14645/#15102) | No — deliberately bypasses every kernel-pass arm |
| `redirect` | XSK redirect (success) | Residual: WG worker claim, GRE-inner REDIRECT/miss | No — partitions redirects not claimed by hit/miss/ifnat origins |
| `redirect_err` | DROP (+ degraded) | XSK redirect failure fails closed | No — error path, not a disposition peer of `redirect` |
| `adjust_meta_fail` / `meta_bounds_fail` | DROP + degraded | Metadata write failure fails closed | No — distinct failure points, distinct reasons already |
| `ctrl_disabled_drop` / `ctrl_disabled_local` | DROP / cpumap-or-PASS (`degraded_ctrl_disabled_action`) | Ctrl-disabled twin: transit fails closed, local/control survives | No — healthy arms unreachable when ctrl is disabled |

## Plain-TCP hit-forward path (the measured class)

L2 parse → non-adjudicated gate → L3 parse → tagged-only/LAND gates →
binding readiness → (WG_RX flag off: no WG work) → early-filter test
(multicast-only; unicast TCP falls through) → session lookup HIT
(`session_hit_redirect`) → metadata write → XSK redirect (`redirect` slot
stays 0 for this class; the four redirect slots partition every success).
Every check on this path that looks removable owns a row above: the early
filter pre-empts session/WG/GRE, the session hit pre-empts the miss arms,
and the local/NAT arms never run for a hit. The recoverable share of the
8.6% BPF self time remains unproven until the counters run on the rig
(pending-main check below); the source proves the work exists, not its
weight.

## Conclusion

No arm is disposition-identical to another, so this PR removes nothing.
A future removal candidate must first show, from these counters on a real
rig, that an arm's hit count is zero (or wholly subsumed) for the named
packet classes AND that its row above collapses into the surviving arm's
disposition for every class — the matrix in
`xdp_branch_stats_16241_test.go` is the executable form of that proof.

## Verifier cost (measured, structural — not a perf claim)

Fresh pinned build (nightly-2026-05-23, bpf-linker 0.10.2,
`MAX_INTERFACES=65536`, scrubbed codegen env) via `cmd/shimverify` on this
host (kernel 7.2.8): master object 815623 processed insns (18.44% headroom,
PASS) → branch-counters object 862896 (13.71%, below the 15% #4555 floor).
The +47k is the verifier re-walking the outlined counter callee under the
dispatch's calling states; the object LOADS (it is not a kernel reject).
Because the floor is not met, the tracked object was installed with
`XPF_SHIM_ALLOW_LOW_HEADROOM=1` and the gate verdict records
`override_consumed: true` — the same disclosed posture #15854 found the
shim in, not a silent pass. Retiring the override needs the entry-path
restructure deferred since #14954 (packed subprograms for the dispatch
arms) or a cheaper counting shape; that restructure is out of scope here
because it must not ride along with an instrumentation-only change.
