# #16854 — DHCP-less RG edge must not quiesce/restart the live Kea or import stale peer rows

- **Issue**: R3-B03-01. On the canonical topology (reth0 in RG1 with no DHCP,
  reth1 in RG2 with `dhcp-local-server`), a MASTER edge for RG1 on the node
  already serving RG2 ran the full takeover pre-seed: its live Kea was
  `dhcp-disable`d and force-restarted, and the peer's stale memfile-fallback
  rows (pushed while the peer mastered only RG1 with its Kea stopped) were
  merged into its memfile and lease4-added. Released addresses were re-bound
  to departed clients on every such edge.
- **Change**:
  - `applyRethServicesForRG` now runs the pre-seed and the post-start peer
    seed only when `dhcpTakeoverWorkNeeded` proves the edge changes the
    DHCP-served scope set. The decision is fail-open: work is skipped only
    when rgID owns no attributable DHCP scope, the attributable served set
    is non-empty, and the served set is identical with/without rgID. The
    Kea apply enqueue itself still runs (config-gated inside the Manager;
    the #6535 converger relies on the edge to re-drive failed applies).
  - Sender: `pushDHCPLeasesOnce` reads via the new
    `GetSyncLeases{4,6}WithSource`; only a live control-socket read is
    pushed. A memfile-fallback read pushes an explicit empty set whose
    scopes stay `Served:false`/`Applied:false` (no `LeaseAuthorityResult`
    adoption for a non-live read in `makeDHCPLeaseSnapshot`).
  - Receiver: a peer scope explicitly reported `Served:false` at the
    snapshot generation with an exact CIDR+RG match is negative proof
    (#16854). `mergeLeasesByAuthority` and `PeerLeasesForAuthority` exclude
    peer rows in such scopes even without positive `Served&&Applied`
    proof, so an older peer binary that still pushes stale rows cannot
    re-import them. `Served:true` without `Applied` keeps the #10170
    conservative whole union.

## Verification

- **New dhcpserver cells**: `go test ./pkg/dhcpserver/ -run '16854|10170'
  -count=1`: PASS — memfile source reporting, Served:false exclusion in
  both the memfile merge and the post-start filter, unknown-scope rows
  retained, Served:true/Applied:false union control, plus all #10170
  authority cells.
- **New daemon cells**: `go test ./pkg/daemon/ -run '16854|9853|10170'
  -count=1`: PASS — canonical two-RG RG1 edge records no pre-seed (and
  still enqueues the apply), RG2 edge control records the pre-seed,
  per-RG gate table, `pushableLeases`, and the empty Served:false fallback
  snapshot; #9853 staggered-takeover cells unchanged.
- **Full affected suites**: `go test ./pkg/dhcpserver -count=1` PASS;
  `go test ./pkg/cluster -run 'DHCP|Lease' -count=1` PASS. The
  DHCP/Lease daemon subset shows 9 failures both with this change and at
  the base commit with it stashed (identical count, all commit-gate
  environment failures of the form "private-rg-election ... neither
  control-interface nor peer-address is set"), so they are
  base-attributed. A full `go test ./pkg/daemon -count=1` does not
  complete at base either (pre-existing panics/hangs below).
- **RED evidence**: pre-fix, the same daemon scenario (RG2-serving node
  taking RG1 with a held peer snapshot) ran the pre-seed — the base run of
  the #9853 staggered cell shows `pre-seeded into memfile ... count=1` on
  the MASTER edge — and `mergeLeasesByAuthority` retained a
  `Served:false` peer row because only `Served&&Applied` scopes were
  consulted (the new 16854 cells fail on that logic by construction:
  exclusion exists only in the added negative-proof branch).
