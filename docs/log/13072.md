# Return refused cross-worker prepared-redirect buffers to the redirect pool (#13072)

- **Issue**: #13072 (`[research D2-11] userspace-dp/src/afxdp/cos/cross_binding.rs:L202`), source
  finding D2-11 from the deep-review run
  `review-work.2e4cldwkh1` (`gemini-4-argon-high`, validated by the three-way research gate).
- **Cause**: Both cross-binding prepared-redirect sites materialize the UMEM frame into an owned
  `Vec<u8>` via `crate::afxdp::cos::redirect_pool::checkout(slice)` (#6310's per-worker
  thread-local copy-buffer pool) and move it into the `TxRequest` handed to the owner. On the
  happy path the owner worker recycles the committed buffer back into its own pool at
  exact-Local settle (`settle_exact_local_fifo_submission` /
  `settle_exact_local_scratch_submission_flow_fair`). But the `Err(mut local_req)` recovery arms —
  reached when the owner's redirect inbox refuses the request (`try_enqueue_tx_owned`, full
  inbox/admission cap) or the worker-command arm refuses at the queue bound
  (`push_shaped_local_bounded`, #10310) — restored only `overlap_admissions` and then dropped
  `local_req`, freeing `local_req.bytes` to the OS heap instead of returning it via
  `redirect_pool::recycle`. Every refused redirect therefore permanently drained one pooled
  buffer from the SOURCE worker's thread-local pool; a burst of refused redirects exhausted the
  pool and pushed the warmed cross-worker redirect copy back onto per-packet `alloc`/`free`
  (~50–150 ns plus allocator contention), violating the engineering-standards §6
  "no allocation in the poll loop" contract that #6310 introduced the pool to satisfy.
- **Change**: Both post-checkout `Err` arms in `redirect_prepared_cos_request_to_owner` and
  `redirect_prepared_cos_request_to_owner_binding` now call
  `crate::afxdp::cos::redirect_pool::recycle(local_req.bytes)` after taking the overlap
  admissions and before returning `Err(req)`. The buffer returns to the redirect SOURCE
  worker's own thread-local pool (the same thread that performed the checkout), so no
  cross-thread hazard is introduced. Error semantics are unchanged: the `PreparedTxRequest` is
  still handed back to the caller's drain cascade with `overlap_admissions` restored, and
  `recycle`'s `MAX_POOLED_BUFFERS` cap keeps excess buffers freed exactly like the production
  settle sites. Pre-checkout bail-outs (fast-path miss, shared-exact-on-TX-binding,
  self-ownership, owner-absent) never checked a buffer out and are untouched.
- **Regression coverage** (`userspace-dp/src/afxdp/cos/cross_binding_tests.rs`):
  `redirect_prepared_cos_request_to_owner_binding_err_recycles_pool_buffer_13072` (owner-live
  arm: fills the owner redirect inbox to its hard cap so `try_enqueue_tx_owned` refuses) and
  `redirect_prepared_cos_request_to_owner_err_recycles_pool_buffer_13072` (worker-command arm:
  fills the owner command queue to `MAX_PENDING_WORKER_COMMANDS` so `push_shaped_local_bounded`
  refuses). Both warm the pool through a REAL successful redirect whose committed buffer is
  recycled (mirroring the owner settle replenish), then assert the refused redirect leaves
  `redirect_pool::len_for_test()` unchanged at 1 — checkout pops to 0, the fix must push back.
  Together they gate BOTH post-checkout `Err` arms; pre-checkout `Err` paths cannot drain the
  pool and need no gate.
- **RED evidence**: On pristine origin/master (`1eb8a44cf`) with only the test file applied,
  both tests FAILED at the pool-length assertion (`0 != 1`): the checked-out buffer was freed
  to the heap. The warm passes and the refusal plumbing (inbox fill, command-queue fill) all
  succeeded on master, so the RED is attributable to the missing recycle alone.
- **GREEN evidence**: With the fix, both new tests pass; `afxdp::cos::cross_binding::tests`
  30/30 pass, including the #6310 allocation-free merge gates and the #10310
  refused-at-capacity guard. Full `--bin xpf-userspace-dp` suite and `cargo fmt --check` /
  `git diff --check` clean on the final tree.
- **Residuals**: None in scope. The pool's cross-worker migration semantics (source-worker
  recycle on refusal, owner-worker recycle on settle) are now symmetric with the drain
  direction; an asymmetric workload still self-heals by allocating on the depleted side, as
  documented in `redirect_pool.rs`.
