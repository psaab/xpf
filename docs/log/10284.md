# #10284 bulk generation decision-time and tombstone preservation

## Finding verified at current master

`doBulkSync` captures the table-truth snapshot before `bulkSyncWindow` writes `BulkStart`, while `bulkSyncWindow` previously called `stampInstallGenV4/V6` only while iterating rows for the wire. A close/delete that landed after the snapshot but before row serialization therefore received a generation before the stale snapshot row. The receiver's per-key install/delete guards correctly compare generations, but the send-time stamp made the snapshot row win that comparison.

`resetRecvGen` previously rebuilt `recvGenV4/V6` and reset `recvTombV4/V6` together on every accepted `BulkStart`. That erased applied non-zero delete tombstones. A same-boot re-prime or a reset landing between a post-fence delete and its stale snapshot row then reopened the install window and could resurrect the closed session.

## Fix

Table-truth snapshots are copied and stamped immediately at the snapshot/decision boundary, before the test/production gap and before `BulkStart`. The bulk wire loop no longer re-stamps those rows; mirror-sourced walks continue to stamp at their per-row decision point. The v4 and v6 paths use the same decision marker.

`resetRecvGen()` still performs the historical full reset for an un-incarnated legacy prime or a known boot-incarnation switch, because those namespaces are incomparable and the #2198 lower-generation re-prime must remain admissible. A same known incarnation calls `reclaimRecvLiveGen`, which reclaims only live session high-waters, preserves delete tombstones, and leaves comparable config/full-set generations untouched. The retained map recomputes the smallest cap tier that contains its tombstones; a sparse map returns to the default tier.

### Preserved tombstone cap

The cap regression seeds a small overridden tombstone map, re-primes the same namespace, and requires the effective cap metadata to survive with the preserved map. The override is a scaled effective-cap model for a grown production tier without allocating 200k rows. It verifies that a new live key evicts one tombstone while keeping map/order at the cap, and that a sparse map reclaims the default tier; a proven namespace reset clears the map and starts a new epoch.
