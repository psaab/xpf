# #17149 — shared-UMEM `mode` leaf untyped; Rust 11-spelling match silently maps typos to Off (R4-Q48-05)

- **Timestamp**: 2026-10-27
- **Issue**: #17149 (R4-Q48-05)
- **Base**: `origin/master be463f60e7`

## Defect (STEP-0, verified at base)

Live on `be463f60e7`. `pkg/config/schema_system.go:505` declared
`"mode": {args: 1, desc: "Shared UMEM mode override (auto|off|same-device-debug|cross-nic)", children: nil}`
with no `valueType`/`validator`, beside the typed `poll-mode` / `rss-indirection` /
`claim-host-tunables` siblings typed in #1319 PR3. `compiler_system.go`
(`compileSharedUMEMConfig`, `case "mode": cfg.Mode = nodeVal(child)`) copies the
operator token verbatim. `userspace-dp/src/afxdp/shared_umem.rs:283-291`
(`parse_shared_umem_mode`) accepted 11 spellings
(`auto|on|enable|enabled`, `cross-nic|cross_nic`, `same-device-debug|same_device_debug`,
`off|disable|disabled`) and mapped everything else via `_ => Off`. So
`set system dataplane shared-umem mode cross-nick` committed clean and silently
disabled shared UMEM (private UMEM + copy path) — the opposite of the absent-key
default (`SharedUmemPolicy::auto` / `unwrap_or(CrossNic)`).

Stored-config alias check before narrowing: grep for `shared-umem mode
(on|enabled|enable|disable|disabled|cross_nic|same_device_debug)` and JSON
`"mode": "<alias>"` across `pkg/` and `userspace-dp/src/afxdp` found no in-tree
stored config or test using a Rust-only alias; the only non-canonical in-tree
value is the #8939 packed-run fixture's dummy `mode shared`, which compiles via
`CompileConfig` (no schema gate) and still passes. The aliases are therefore
removed, not grandfathered into the validator.

## Fix

- `pkg/config/schema_system.go`: the `mode` leaf is now typed —
  `valueType: ValueEnumOf`, `valueDesc`, `valueExamples` and
  `validator: ValidateEnum([]string{"auto","off","same-device-debug","cross-nic"})`,
  mirroring the adjacent `poll-mode` leaf. `set system dataplane shared-umem mode
  cross-nick` (and every former Rust alias, case variant and typo) now fails
  `SchemaValidate` at commit, naming the bad value and the expected set.
- `userspace-dp/src/afxdp/shared_umem.rs`: `parse_shared_umem_mode` accepts
  exactly the four canonical spellings (`auto|cross-nic` → CrossNic,
  `same-device-debug` → SameDeviceDebug, `off` → Off). The silent `_ => Off`
  arm is replaced by an explicit `other =>` arm that keeps the Off fallback for
  fail-safety (a handcrafted or pre-#17149 persisted snapshot must not brick the
  helper) but logs once per process via a function-local `AtomicBool` swap
  (`xpf-userspace-dp: unknown shared-umem mode … falling back to Off (#17149)`).
  No alias spellings remain; there is one vocabulary across both languages.
  (The issue's "once R4-Q48-01's typed UserspaceSnapshot exists, carry as serde
  enum" step is out of scope here — that prerequisite has not landed; the
  string leaf + parity test below pin the contract until it does.)

## Risk

Stored configs using a Rust-only alias (`on`, `enabled`, `cross_nic`, …) will
now fail strict commit where they previously committed and silently selected a
mode. No such config exists in-tree (grep above); an operator with one gets a
commit error naming the value and the four canonical spellings — the intended
fail-closed direction. The Rust Off fallback is unchanged for snapshots that
bypass the Go gate, but is now logged once instead of silent.
