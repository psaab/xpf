# Issue #13124 — IPsec selector-fence render parity

## Defect

`renderConfig` skips a VPN with an unresolved `external-interface` because
omitting its local bind would let strongSwan bind all local addresses. The
userspace bindless-selector snapshot instead called `RenderedVPNSet` with the
config-only render, which deliberately retained unresolved candidates for
`ExpectedLoadedConns`. That mismatch emitted selector-fence rows for a VPN
strongSwan did not load, dropping cleartext that could never form an SA.

Separately, `prepareConfigFromConfig` checked only the peer's preferred address
family. When an interface had only the other family, production
`resolveInterfaceAddress` fell back to it but the replay projection marked the
connection runtime-dependent. Generation validation then returned
`ErrGenerationUnvalidatable` despite the configured address being sufficient.

## Fix

- `RenderedVPNSet` now accepts the full config, prepares its runtime-resolved
  IPsec view, and uses the same fail-closed `renderConfig` path as production.
  Its caller in the userspace snapshot builder now passes the full config.
- `prepareConfigFromConfig` mirrors production's configured-address fallback
  from the remote's family to either family before declaring the result
  runtime-dependent.
- Added a regression that checks the unresolved VPN is excluded from the
  selector set, the healthy IPv6-peer/IPv4-interface VPN is retained, and
  config-only generation replay finds the IPv4 address.

## Evidence

- Regression RED on pristine `origin/master` at `55ab81ef080daef6caa7a94ce6b38ea7b98c5551`:
  `go test ./pkg/ipsec -run '^TestRenderedVPNSetMatchesProductionRenderAndReplayFallback_13124$' -count=1`
  failed because both raw and prepared selector sets included `vpn-unres`,
  while replay omitted `192.0.2.10` and `ExpectedLoadedConns` returned
  `ErrGenerationUnvalidatable` for `vpn-fallback`.
- Regression GREEN after the fix with the same targeted command.
- Full IPsec package: `go test ./pkg/ipsec -count=1` passed.
- Go vet: `go vet ./pkg/ipsec ./pkg/dataplane/userspace` passed.
- Full `pkg/dataplane/userspace` tests were attempted twice (once with a shorter
  `TMPDIR`); both failed on tests outside the touched code, including
  `TestContractSnapshotGolden9821` (golden size drift), `TestCapFlagIsWiredEndToEnd9054`,
  `TestBareZoneBindOnlyTunnelHostInbound13100`, `TestSnapshotShapeIsPinnedToProtocolVersion8892`,
  plus environment socket-path `bind: invalid argument` failures. The targeted
  fence integration test `TestBindlessFenceSkipsUnrenderedVPN11083` passed.
  These failures were not verified against pristine master and are not claimed
  as base-attributed.

## Risk

`RenderedVPNSet` now uses `PrepareConfig`, matching the production render's
interface and family resolution, including its bounded dynamic-hostname family
lookup. A nil config or render error still returns nil, retaining the snapshot
builder's prior fail-closed fallback behavior. No dataplane wire format or
traffic-selector matching rules changed.
