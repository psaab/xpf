- **Timestamp**: 2026-10-19
  - **Action**: Added a low-rate (30s) kernel-truth recheck that marks the host-inbound applied state stale (and clears the lo0 real-filter latch) with a one-per-episode Warn when an established `xpf_hostinbound` / `xpf_lo0` table is provably missing from the kernel, so the operator probe no longer reports Current over flushed tables. ## Mechanism (origin/master `b29c191961`)

- `applyHostInboundFilter`/`applyLo0Filter` run only from the apply tail (`daemon_apply_tail.go:149,156`) and the host-auth closeout (`daemon_apply_hostauth.go` owners). Between applies nothing re-reads the kernel.
- `HostInboundApplied()` is a pure latch over `hostInboundEnforced`/`hostInboundLastApplyFailed` (`host_inbound_applied_7181.go`): sticky-true after any successful load, cleared only by a successful teardown the daemon itself performs. An out-of-band flush is invisible to it.
- `scripts/image/xpf-input-closed.service:22-26` documents a post-handoff `nft flush ruleset` as an accepted operator action that "also wipes the real tables" and needs a re-apply — so until that re-apply, REST/gRPC/CLI reported `current` while no host-inbound (or lo0) enforcement existed. Contrast `reassertTransitGate` (`transit_gate_tick_9725.go`), which re-derives its gate from kernel truth every tick.

## Change

- `recheckHostKernelTruth15264` (30s loop started in `Run` beside the other reassert owners):
  - Host-inbound, only when `hostInboundEnforced`: `TableDropsInput(xpf_hostinbound)`. Dropping ⇒ stands. Not dropping ⇒ `TableEnforcing` separates a flushed/absent/empty-shell table (drift: `noteHostInboundApplyFailed(now)`, so `Current()==false` and the tri-state renders `stale`) from a legitimate junos-host program-only generation whose DROPs live in subchains (enforcing by shape ⇒ stays Current — the documented `TableDropsInput` base-chain residual must not false-flag it).
  - lo0, only when `lo0Enforced`: `TableEnforcing(xpf_lo0)` (a real lo0 filter need carry no DROP verdict — accept/reject terms govern — so enforcing shape is the right predicate). Vanished ⇒ clear `lo0Enforced` (the "real filter loaded" premise is kernel-false, so the next failed install takes the #6476 cold-boot fence path, not day-2 retention) and set `lo0LastFailed`.
  - Read errors prove nothing and never mark stale (cf. `runInputBarrierEnsure`). Never-established surfaces are not probed at all — zero netlink cost and no stale claim on a cold/no-enforcement daemon.
  - One Warn per drift episode (`hostDriftNoticed15264`, mirroring `mgmtReassertNoticed` #6803), re-armed when a pass observes no drift.
- NOT changed: no auto-re-drive of the apply (the service file documents re-apply as the operator convergence step; an auto-reapply would fight an intentional flush and needs applySem/config the tick does not hold), no `Current()` semantics, no install/delete paths, no new REST/gRPC fields — the existing tri-state already renders the new staleness. A successful apply heals exactly as before (`noteHostInboundApplySucceeded`, real `InstallLo0` re-sets `lo0Enforced`).

## Risk

- A flushed box now reports `stale` (REST/gRPC tri-state) within ≤30s instead of `current` until the next apply; traffic behaviour is unchanged (the daemon installs/deletes nothing on the tick). Residual: a host-inbound generation whose base chain has rules but all DROPs were individually deleted out-of-band (table still enforcing by shape) reads Current — same accepted base-chain/subchain residual class as `TableDropsInput`; full ruleset comparison remains out of scope.
