# 11503 — Export unzoned policy-denial cause counters

## Summary

Unzoned ingress and egress denials already had distinct process-local counters, but operators could not read them from `ProcessStatus`, policy-counter snapshots, or Prometheus. The two cause counters are now exposed end to end without changing the denial behavior or counting policy re-derivations.

## What changed

- Rust `ProcessStatus` publishes `unzoned_ingress_denied_total` and `unzoned_egress_denied_total`; zero-valued fields remain omitted and older status payloads decode with zero defaults.
- `PolicyState::counter_snapshots` adds stable `unzoned-ingress-denied` and `unzoned-egress-denied` rows, with packet totals and zero byte counts.
- The Go status collector emits `xpf_userspace_unzoned_ingress_denied_total` and `xpf_userspace_unzoned_egress_denied_total` from the Rust status values.
- The protocol version advances from 41 to 42. The ConfigSnapshot shape digest remains unchanged because `ProcessStatus` is outside that shape; the version lockstep and shape pin are updated accordingly.
- The shared Rust-to-Go fixture includes distinct populated status counters and their policy snapshot rows. Existing `without_counting_does_not_bump_unzoned_cause_counters_9385` coverage continues to verify that side-effect-free policy re-derivation increments neither direction.

## RED-then-GREEN proof

The new coordinator status/snapshot regression was run with the two unzoned rows temporarily removed from `counter_snapshots`; it failed because the policy snapshot lacked the unzoned-ingress cause row. Restoring the rows made the same regression pass, including the separate ingress/egress deltas, refreshed status fields, and serialized snapshot assertions. The status projection regression also passed five consecutive runs. The existing side-effect-free re-derivation regression passed.
