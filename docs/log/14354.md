# Issue #14354 — validateHostInboundManagedRoutingMismatch false-rejects strict commits on bare zoned interfaces with unit overrides and across routing-instance boundaries for `interface all`

- **Issue:** `validateHostInboundManagedRoutingMismatch`
  (`pkg/config/compiler_validate_warn_host_inbound.go`) false-rejected strict
  commits in two shapes: (1) a security zone listing a bare interface
  (`interfaces ge-0/0/0;`) with a per-unit override admitting `ospf` on
  `ge-0/0/0.0` was rejected on the synthetic bare parent key `"ge-0/0/0"`
  when `protocols ospf area 0.0.0.0 interface all` was configured, because
  the bare key's effective host-inbound set ignores the `.0` override; and
  (2) `interface all` expanded across the global zone-interface map with no
  routing-instance scoping, so a tenant-VRF `interface all` demanded `ospf`
  admission on MAIN-zone interfaces (and vice versa), pressuring operators
  toward over-admission on unrelated zones. Strict promotion is at
  `pkg/config/compiler_tailgates.go` (`lenientHostInboundManagedMulticast`
  off → first warning becomes the commit error).
- **Source:** Deep-review zone-enforcement-policy-100, finding D8-07
  (Gemini 4 Argon High), research-validated MATERIAL (narrowed, Medium) by
  two blinded adversarial passes (Opus SMR + Muse-Spark) at
  origin/master `5b122dda`.
- **What:** Each collected `managedRP` now carries its owning routing
  instance (`""` for the global `protocols` stanza, `ri.Name` for
  routing-instances). The `interface all` expansion skips bare parent keys
  that fan down onto configured units (`InterfaceUnitRefKeys` returns more
  than the key itself — no daemon runs on the parent key, and the unit
  checks carry the per-unit overrides) and checks only zone interfaces
  owned by the statement's routing instance. Ownership is resolved lazily
  (only a wildcard triggers it) via `fabricZoneRoutingInstanceByInterface`
  / `ForEachRoutingInstanceInterfaceMembership` — the same membership
  traversal (RI interface lists, tunnel `routing-instance` stanzas,
  dual-claim omission, forwarding-instance exclusion) the dataplane
  snapshots use, so validation agrees with enforcement. Explicit
  (non-`all`) interface refs, the bare-ref→unit-0 resolution, lifeline
  exemptions, zone quarantine/conflict handling, and the fail-closed
  missing-token error are unchanged: an unadmitted unit in the statement's
  own instance still rejects/warns, now named by its logical unit instead
  of the bare parent. No test inputs are special-cased.
- **Regression:** `TestManagedRoutingMismatchUnitOverrideAndVRFAllScoping`
  in `pkg/config/host_inbound_managed_routing_14354_test.go` covers the
  bare-member + unit-override + global `all` case (helper and strict
  compile), the fail-closed bare-member case naming the logical unit, VRF
  `all` scoping in both directions (own unadmitted interface still warns),
  VRF `all` through strict compile, and explicit RI refs.
