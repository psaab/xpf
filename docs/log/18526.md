  - **Finding**: `ReserveConfigGen` advances `configGenCounter` with `Add(1)`
    independently of a write. In the daemon reconcile path the reservation is
    taken before the already-pushed no-op check. The guarded queue can also
    withdraw a reservation: after payload preparation,
    `writeConfigWithPeerSnapshotGuard` can return unauthorized before
    `writeMsg`, and the reservation is not reused. Both facts confirm
    acceptance 1.
  - **Existing fix**: The stale threshold is already fixed by merged PR #18646
    for #18636: once this peer incarnation has a config-send mark,
    `authorityConfigEpochThreshold` compares against its
    `peerIncarnationState.lastSentConfigGen`, not the reservation counter.
    A guarded withdrawal is rejected before it records that mark, so it cannot
    advance the threshold past a generation actually sent in the incarnation.
    The reservation-counter fallback before the first send remains
    fail-closed, as specified by #18636's reviewed design.
