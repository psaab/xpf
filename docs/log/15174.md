# #15174 (B18-03): local-CLI DDNS renderers print update-server raw

- **Timestamp**: 2026-10-19
  - **Action**: Wrapped both local-CLI `update-server` fields in `config.RedactURL`, matching the gRPC twins / `show configuration` / `String()` / `MarshalJSON` (#9497). Added RED/GREEN regression driving both CLI renderers in normal and detail mode.
  - **File(s)**: `pkg/cli/show_services_ddns.go`, `pkg/cli/cli_show_ddns_update_server_redact_15174_test.go` (new), `docs/log/15174.md` (this file)

## Mechanism (origin/master `e487b1ee7c`)

Two local-CLI PermView renderers in `pkg/cli/show_services_ddns.go` printed `update-server` verbatim:

- `showServicesDynamicDNS` line 33: `update-server=%s` with `p.UpdateServer` (Surface A provider catalog)
- `showDHCPDynamicDNS` line 143: `Update server: %s` with `ddns.UpdateServer` (DHCP-server DDNS)

Both are dispatched from the interactive CLI (`show services dynamic-dns`, `show dhcp-server dynamic-dns`), so a userinfo-bearing value (`user:secret@host`) reached every view-class console/SSH login and any captured command output.

Every sibling surface already redacts the same field through `config.RedactURL`:

- gRPC twins in `pkg/grpcapi/server_show_dhcp_lldp_snmp.go:281,366` (#9497)
- `DDNSProvider.String()`/`MarshalJSON` and `DHCPDynamicDNSConfig.String()`/`MarshalJSON` in `pkg/config/types_system.go`
- `show configuration` via `ConfigTree.RedactedClone()` (`update-server` in `urlLeafIndices`)

#9497 fixed only `pkg/grpcapi` + `pkg/config`; the local-CLI pair was the residual (B18-03).

## Change

- `showServicesDynamicDNS`: `config.RedactURL(p.UpdateServer)`
- `showDHCPDynamicDNS`: `config.RedactURL(ddns.UpdateServer)` (with #15174 comment citing the contract)

No other behaviour changes. `RedactURL` is a no-op on a clean `host[:port]`, so legitimate output is byte-identical.
