# #16751: heartbeat receiver never starts, nothing confirms peer absence

- **Timestamp**: 2026-10-25
- **Action**: Moved ownership of the never-seen clock into `pkg/cluster.Manager` so peer absence is confirmed after the cold-boot floor whether or not a heartbeat receiver ever started. `UpdateConfig` arms the clock while a control interface is configured and no peer has been seen; after `heartbeatStartupGrace` it drives the existing `handlePeerNeverSeen` (including the #11566 fresh-sync-proof suppression, re-probed every 1s), a peer heartbeat / control-interface removal / `Stop` disarms it, and routine re-applies keep the original arming stamp. No receiver, daemon, or networkd change: the receiver's own never-seen arm is unchanged and both paths funnel into the at-most-once `handlePeerNeverSeen`.
- **File(s)**: `pkg/cluster/manager.go` (`neverSeenSince`/`neverSeenTimer`/`neverSeenTimerGen` fields, `Stop` teardown), `pkg/cluster/group_state.go` (`UpdateConfig` arm), `pkg/cluster/heartbeat_manager.go` (`armNeverSeenClockLocked`/`disarmNeverSeenClockLocked`/`confirmNeverSeenIfDue`, heartbeat disarm, `neverSeenGrace` test seam), `pkg/cluster/heartbeat_neverseen_noreceiver_16751_test.go` (new), `pkg/cluster/README.md` (Manager-owned clock paragraph).

## Mechanism

`peerConfirmedAbsent` was written true only by `handlePeerNeverSeen`, whose only production caller was the heartbeat receiver's `checkTimeout`. If the heartbeat could not start at all — the control interface has no address (a direct back-to-back control cable to a powered-off peer has no carrier, and networkd's `ConfigureWithoutCarrier=false` default then never configures it, so the daemon's 60s `startHeartbeatWithRetryForEpoch` exhausts) — no receiver existed, absence was never confirmed, and every non-preempt RG stayed secondary indefinitely. The hold precedes the readiness gate in election, so not even the 2-minute degraded fallback ever armed. The surviving node of a dead pair forwarded nothing for as long as the peer stayed down, surviving only a peer return, a manual preempt, or a cable/bridge workaround.

## Fix

The Manager now owns the floor, as the issue's primary fix direction specifies ("armed at UpdateConfig when a control link is configured, so absence is confirmed after the floor whether or not a receiver started"). Key properties, each pinned by a test:

- Same floor as the receiver (`heartbeatStartupGrace`, 30s), because the #4386 simultaneous-cold-boot hazard it guards is identical whichever component confirms.
- Same confirmation path (`handlePeerNeverSeen`), so the #11566 fresh-sync-proof suppression and the #10697 readiness-gated/degraded shape are preserved by construction, not re-implemented. While sync proof stays fresh the Manager re-probes every 1s with no fixed cap, matching the receiver's per-tick recheck.
- Disarm on peer heartbeat, control-interface removal (standalone reconfiguration owes no absence confirmation), and `Stop`; a generation counter invalidates a callback already parked on `m.mu`.
- Re-applying config keeps the first arming stamp, so routine commits cannot push the floor out indefinitely.

## Deliberate scope cuts

- **networkd `ConfigureWithoutCarrier=yes`/`IgnoreCarrierLoss=yes` NOT changed.** The Manager clock bounds the outage to floor (+ degraded timeout when unready) regardless of why the address is missing, which makes the networkd change unnecessary for this defect; and emitting it would alter address behaviour on every cluster control/fabric interface (a separate, behaviour-changing decision). The carrier trigger remains a possible operator-side improvement, not a prerequisite.
- **Daemon heartbeat retry NOT changed.** "Treat heartbeat-could-not-start as never-seen evidence" (the issue's alternative) would couple the daemon's retry exhaustion to election and confirm absence at ~60s even while a receiver might still start; the Manager clock subsumes it from inside the package that owns the invariant.

## Validation

- New `pkg/cluster/heartbeat_neverseen_noreceiver_16751_test.go`: 6 tests / 8 cells (ready promotes, unready promotes degraded, floor holds, sync-fresh suppresses then silent confirms, heartbeat/removal/Stop disarm, re-apply keeps floor), all with **no receiver ever created**.
- RED evidence: removing the single `armNeverSeenClockLocked()` call from `UpdateConfig` makes all three promotion cells fail by timeout (peer never confirmed absent), restoring it passes.
- Existing never-seen family unchanged and green: `#4386` floor, `#11566` sync suppression (receiver path), `#10697` readiness gate, `#11682` idle-ACK cadence.
- Full `pkg/cluster` suite and `-race` on the never-seen family: see PR body.
