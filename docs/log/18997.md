# Issue #18997 — URL credentials echoed by redaction-guard locations

## Root cause

The archive-sites fixture
`set system archival configuration archive-sites "scp://user:pw@host/dir" password "##SECRET-DATA##"`
contains both a URL-classified value and a secret placeholder. `checkRedactionPlaceholder` (via the `walkSecretSites` + `site.secrets` scan in ast_redact.go)
correctly selects the secret leaf, then `redactedLocName` keeps the flattened path
through the `password` keyword. That location renderer called `redactSecretPath`,
which only applied `secretIndices`; the preceding `archive-sites` URL therefore
remained `scp://user:pw@host/dir` in the guard error. The schema exit scrub had the
same classification gap: `collectSecretValues` did not collect direct URL values,
so an error containing the candidate URL kept its userinfo.

## Change

- `pkg/config/secret.go:redactSecretPath` now applies both existing classifiers:
  secret-indexed tokens become `SecretRedacted`, and URL-classified tokens are
  transformed by `RedactURL`. The URL classification and guard rejection
  predicates are unchanged; this is only a diagnostic-rendering change.
- `pkg/config/ast_redact.go:redactedLocName` and every embedded guard location
  already use `redactSecretPath`, so their kept prefixes now redact classified
  URL components as well as secret operands. Its comment now describes the safe
  rendered path rather than claiming it contains only names.
- `pkg/config/schema_walk_errors.go:collectSecretValues` now collects direct
  `urlLeafIndices` values only when `RedactURL(value)` changes the token, alongside
  `secretIndices`; embedded-command URL values use the same check. `urlLeafIndices`
  can also span structural siblings (for example, `feed-name` after a `url`), so
  no-op URL spellings must not become scrub needles. The exit scrub now catches
  credential-bearing URLs without rewriting ordinary child names. The internal
  argument marker was renamed from `nameOnlyArg` to `redactedPathArg` because a
  safely rendered path can retain a non-secret URL scheme/host/path.
- No classifier, placeholder/URL detection condition, or config rejection rule
  changed.

## Error-surface census

- `redactedLocName` call sites in `pkg/config/ast_redact.go`: direct placeholder
  hits (the `checkRedactionPlaceholder` secret arm), direct redacted-URL hits
  (`findRedactedURL`), and the quoted-token/joined-tail forms in both
  `embeddedRedactionHit15209` and `embeddedChildRedactionHit15209`. Each uses the
  same `redactSecretPath` renderer. No second flattened-path guard renderer exists.
- The only direct guard `(at %s)` location producers in `pkg/config` are the
  placeholder and redacted-URL arms in `checkRedactionPlaceholder`; both receive
  the safe location above. The two corresponding `scrubSchemaErrorSecrets`
  wrapper arms re-wrap that location through `neutralizeLoc`, now backed by the
  expanded `collectSecretValues`. The other production `(at ...)` match is
  `compiler_validate_strict_routing.go`'s numeric byte offset; it is not a
  flattened config path. Test-only sentinel formatting is not another surface.
- Other flattened schema-error paths using `redactSecretPath` are in
  `schema_bgp_flatrun_16749.go`, `schema_walk.go`, `schema_walk_errors.go`, and
  `schema_walk_leaf.go`; all inherit URL classification from the shared renderer.
  The schema exit scrub independently catches URL values embedded in error text.

## Risk

The change reuses `urlLeafIndices` and `RedactURL`, so it does not introduce a
second URL policy or broaden which leaves are considered URL-bearing. URL-bearing
paths and schema error text redact credentials only where RedactURL transforms
the token; the exit collector excludes no-op structural tokens. Guard
classification, accepted/rejected configurations, and diagnostics unrelated to
classified secret/URL values remain unchanged.
