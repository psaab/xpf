# Issue #13688 — include every address in scoped NAT prefix views

## Why

Both scoped NAT address extractors added the prefix base and then used
`ipnet::hosts()` for the rest. IPv4 `hosts()` excludes both network and
broadcast addresses, so every bounded IPv4 prefix of `/30` or wider omitted
the final address that the NAT match still translates. For IPv6 and IPv4
`/31`, `hosts()` includes the base, so the separate base push duplicated it.
This made local-address/proxy-ARP registration disagree with the NAT match.

## What

`DnatTable::destination_ips_scoped` and
`StaticNatTable::external_ips_scoped` now enumerate numeric offsets from the
masked network base under their existing shared `MAX_LOCAL_PREFIX_HOSTS`
bound. Both preserve the existing base registration, skip it during the
remaining-address loop, and include the last address. Large prefixes still
register only their base; unspecified-address, shadowing, and static remapping
behavior remain unchanged. The regression tests assert exact `/30` IPv4 and
`/126` IPv6 scoped results, including no duplicate base, and DNAT's deduped
view parity.

## Risk

For a bounded prefix the enumeration is still capped at 4096 addresses and
uses integer offsets whose maximum is within the already-validated IPv4/IPv6
prefix range. Unbounded prefixes retain base-only behavior.
