# #16447 — the #812 "Rc not Arc" cell could not fail on the migration it named

## Defect

`tx_submit_ns_sidecar_single_writer_ownership_is_rc_not_arc`
(`userspace-dp/src/afxdp/binding_state/tests/tx_submit_latency.rs`)
coerced `WorkerUmem::shares_allocation_with`,
`WorkerUmem::allocation_ptr` and `WorkerUmem::as_raw_umem_ptr` to
fn pointers and contained no assertion. None of the three
signatures mentions `Rc`, so migrating `WorkerUmem.inner` from
`Rc<WorkerUmemInner>` to `Arc<WorkerUmemInner>` (with
`Rc::ptr_eq`/`Rc::as_ptr` changed to their `Arc::` forms in
`umem/mod.rs`) left every probe valid and the cell green.

Its comment also claimed "at runtime we assert that two `Clone`s
of the same WorkerUmem share allocation" — no such assertion
existed in the body.

Narrowing (from the issue): the invariant the cell named is not
unguarded in production. `WorkerUmemInner` holds
`RefCell<Umem>` (`!Sync`), so even `Arc<WorkerUmemInner>` would
remain `!Send`/`!Sync`, and the `tx_submit_ns: Box<[u64]>` sidecar
is a field of the TX pipeline written only through `&mut`
ownership, not through `WorkerUmem`. The defect was a dead cell
with a false comment, bounded to test hygiene.

## Fix

Replace the cell in place (same file, renamed to
`tx_submit_ns_sidecar_single_writer_worker_umem_is_not_send_nor_sync_16447`):

- Two module-level ambiguous-trait compile-time proofs (the
  `CounterExempt` shape from `counter_test_lock.rs`; this crate
  has no `static_assertions` dependency, so no new dependency is
  added): inference resolves `<WorkerUmem as AmbiguousIfSend<_>>`
  and `<WorkerUmem as AmbiguousIfSync<_>>` only while
  `WorkerUmem` stays `!Send`/`!Sync`. Because they are
  module-level `const`s, the proof is checked whenever the test
  binary compiles, not only when the cell runs. Acceptance from
  the issue — "making `WorkerUmem` `Send` fails to compile the
  test" — is met for both `Send` and `Sync`.
- The runtime half the old comment claimed but never made, now
  real: `WorkerUmem::new_for_test` (hermetic, no CAP_NET_ADMIN)
  clones share the allocation (`shares_allocation_with` and
  `allocation_ptr` equality) and an independently built
  `WorkerUmem` does not.
- The new comment states what actually confines `WorkerUmem`
  today (the `RefCell`, not the `Rc` spelling) and no longer
  claims an `Rc`-vs-`Arc` pin.

NOT changed: any production code. `WorkerUmem` stays
`Rc<WorkerUmemInner>`; an `Rc`→`Arc` migration that keeps the
`RefCell` still compiles — deliberately, since that migration
alone does not break thread confinement. What now fails to
compile is the load-bearing consequence: making `WorkerUmem`
itself `Send` or `Sync`.

## Tests

- Targeted (pinned toolchain, `GOCACHE`/`CARGO_TARGET_DIR` under
  `/var/worktrees/.cache`):
  `cargo test --bin xpf-userspace-dp afxdp::binding_state::tests::tx_submit_latency::tx_submit_ns_sidecar_single_writer_worker_umem_is_not_send_nor_sync_16447 -- --exact --test-threads=1`
  — 1 passed, 0 failed.
- Mutant / acceptance: adding
  `unsafe impl Send for WorkerUmem {}` and
  `unsafe impl Sync for WorkerUmem {}` to `umem/mod.rs` makes the
  test binary fail to compile with E0283 (type annotations needed
  / ambiguous inference) at both proofs — 2 errors, no test runs.
  Reverting the mutant restores the 1-passed baseline above.

## Risk

Test-only. No production artifact changes; the test binary gains
two zero-cost compile-time proofs and one hermetic cell that
allocates two 4-frame test UMEMs. Renaming or deleting the cell
does not weaken the guard, because the `const` proofs are
module-level rather than inside the `#[test]` body.
