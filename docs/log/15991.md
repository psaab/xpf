# #15991 — ASCII `0x…` PSK rendered as raw hex bytes

- **Timestamp**: 2026-10-22
- **Action**: an `ascii-text` PSK that literally reads `0x<hex digits>`
  (e.g. `pre-shared-key ascii-text 0x61626364`) lost its ASCII
  provenance in `pkg/ipsec/policy.go`: the gateway-group fold encoded
  each member PSK as a bare string (prefixing hex values with `0x`),
  and the lone-value secret emission treated any `0x`-prefixed string
  as a hex key, rendering `secret = 0x61626364` unquoted — so
  strongSwan hex-decoded the credential instead of using the literal
  ASCII string the operator authored. The fold also collapsed an
  ASCII `0x<digits>` and a hexadecimal `<digits>` member on the same
  gateway into one raw-hex element. The fold now carries
  `pskValue{value, hex}` provenance (#15024/#15027 encoding) through
  dedupe, and emission decides solely on the hex flag: a lone hex
  value renders `secret = 0x<hex>`, any lone ASCII value renders
  quoted (including `0x…` and `0X…`), and a grouped secret comma-joins
  each element by its own provenance (hex keeps its `0x` token,
  ASCII keeps its literal bytes) inside the existing single quoted
  string — byte-identical to the prior grouped render, with the
  ASCII/hex same-digit pair now surviving as two distinct elements.
  No compiler, schema, or strict-gate change: `PSKHex` already carried
  provenance to the renderer; only the renderer's fold/emission
  discarded it.
- **Files**: `pkg/ipsec/policy.go`,
  `pkg/ipsec/policy_psk_ascii_hex_15991_test.go` (new),
  `pkg/ipsec/README.md`, `debian/changelog`, `docs/log/15991.md`.
- **Validation**: probe at base `30638bcad3` (temporary test, removed):
  `PSK="0x61626364", PSKHex=false` rendered `secret = 0x61626364`
  while the hex control rendered identically — indistinguishable.
  New `TestASCIIHexPrefixedPSK15991` (lone ascii-0x quoted vs lone hex
  raw, policy-fallback ascii-0x quoted, grouped ascii-0x+hex distinct,
  grouped dedupe + plain, non-hex `0xzzzz` quoted) and
  `TestASCIIHexPrefixedPSKEndToEnd15991` (authored
  `ascii-text 0x61626364` through `CompileConfig` → render) are GREEN
  with the fix and RED with `policy.go` stashed (4 of 5 direct cells +
  end-to-end; the grouped ascii-0x+plain cell passed pre-fix as a
  control). Existing `TestPSKHexadecimal*15027` and
  `TestGatewayGroup*15024` unchanged and GREEN; full
  `go test ./pkg/ipsec/ -count=1` GREEN; `go vet`/`gofmt` clean.
- **Risk**: only lone ASCII values that start with `0x` change render
  (deliberately): they now authenticate as the literal string and stop
  matching a peer that had compensated by configuring the hex-decoded
  bytes. Hex, plain-ASCII, grouped-plain, and malformed-hex skip
  renders are byte-identical. No real-charon verification (no charon
  binary in this worktree); the swanctl render contract is the
  pinned substitute, as in #15027.
