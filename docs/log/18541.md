# #18541 — session-sync bulk installs paced at ~51 sessions/s by the helper's accept loop

- **Timestamp**: 2026-10-30
  - **Action**: Diagnosed the ~20 ms per bulk session seen on loss fw0 at the
    2026-10-30 06:17 restart (512 sessions in 10.28 s). Each bulk session is
    installed with two synchronous session-socket round trips
    (`PutClusterSyncedV4` -> `SetClusterSyncedSessionV4` for the forward
    `mirror_upsert` and the reverse `mirror_publish_only`), each a fresh dial
    (`requestSessionSyncResponseLocked`). The helper's `run_accept_loop`
    answered `WouldBlock` with `thread::sleep(poll)` (10 ms on the session
    socket), and Go dials each request just after the previous response, so
    every request waited out ~the whole sleep. The `sync_session` handler
    queues to workers without waiting; no fsync, no `ServerState` lock.

    to base `09a2b664be`): 20.34-20.37 ms per session over three runs of 522
    sessions (10.62 s each), p50 20.37 ms — quantized at 2 x 10 ms.

  - **Action**: A locked mutant run held the shared cargo lock for 226+ s and

    `timeout 120`: the RM1 mutant binary (loop sleeps its idle interval) kept

    unbuffered `UnixStream` issues one `write(2)` per JSON token, each charged
    a full skb; against a loop that is not reading, the send buffer fills and,
    with no write timeout, the client blocks forever. The fixed tree never
    reaches this (its targeted run passed 16/16 in 0.60 s), and Go's client

    a mutant's red into a hang. The client now serializes first, writes once,
    and bounds the write with the same budget; a write failure scores as "no
    response". Every cargo invocation under the shared lock is now wrapped in
    `timeout -k 30 <n>`, with a timeout recorded as a failure naming the test
    still running. Also from the RM1 run: the in-process measurement through
    the real dispatcher printed 21.5 ms per session with the loop sleeping,
    against 1.07 ms on the fixed tree.

- **Timestamp**: 2026-10-30
  - **Action**: Wake the shared accept loop on listener readiness.
    `accept_step` returns `AcceptStep::Idle(poll)` for `WouldBlock`;
    `run_accept_loop` serves it with `wait_for_pending_connection`
    (`poll(2)` for `POLLIN`, the old interval as the timeout), so an arriving
    connection is accepted at once and the interval only bounds how long the
    loop goes without re-checking `running`. Timeout/EINTR return false; a
    poll error or readiness without `POLLIN` sleeps the interval first (the
    review-round refinement below extends that to `POLLIN` with a hang-up or
    error bit). Failure backoff (`AcceptStep::Sleep`) stays a plain
    sleep (EMFILE leaves the listener readable). Named the session idle wait
    `SESSION_SOCKET_IDLE_WAIT`. All four sockets share the loop; no caller
    sends more requests.
