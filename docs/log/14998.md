# Issue #14998: DHCPv6 co-held IA_NA invalidation orphans WAN address and resets T1/T2

## Why

D40-04 (Path A only). On a co-held IA_NA+IA_PD renewal, a Reply carrying an
IA_NA whose IAADDR(s) are all valid-lifetime 0 (RFC 8415 §18.2.10.1 explicit
invalidation) together with a live IA_PD prefix bypassed the
`errV6AddrInvalidated` sentinel: the parse guard only fired when there was
also no live PD, so it returned a success lease with an invalid `Address`
and `LeaseTime` taken from the PD lifetime (or the 3600s floor).
`commitLease` then stored that address-less lease without removing the
previously installed kernel WAN address (its remove-old only fired when the
new lease had an address) and renewal timers re-derived from the bogus
lease — the WAN address was orphaned. Separately, a delegated-prefix expiry
interrupting the T1/T2 wait (`waitOutcomePDExpired`) looped back to a fresh
full `m.after(t1)` / `m.after(t2Remaining)`, so each PD prune restarted the
whole tier wait and could push RENEW/REBIND arbitrarily late.

## What

- `pkg/dhcp/dhcpv6.go` (`parseV6ReplyChecked`): fire
  `errV6AddrInvalidated` whenever the IA_NA is explicitly invalidated,
  regardless of co-held live IA_PD prefixes. The run-loop invalidation
  branch (`abandonLeaseAfterExpiry`) then removes the kernel address,
  lease record, and PDs and re-acquires, as for the non-co-held case.
- `pkg/dhcp/commit.go` (`commitLease`): remove the previous address
  whenever it differs from the committed lease's address — including an
  address-less successor — so no path can orphan the old kernel address.
  The old address is removed before applying the new one so a failed apply
  cannot leave a stale address installed alongside the error.
- `pkg/dhcp/dhcpv6.go` (`runDHCPv6`) + `pkg/dhcp/commit.go`
  (`remainingTimer`): anchor T1/T2 to absolute instants
  (`t1At = Obtained.Add(t1)`, `t2At = t1At.Add(t2Remaining)`) and resume
  after a PD prune with `remainingTimer(t1At/t2At, now)`. NOT changed:
  Path B past-expiry behaviour (bounded by the lease deadline via
  `leaseCtx`) and the `abandonLeaseAfterExpiry` trigger schedule.
- Tests: `pkg/dhcp/dhcpv6_coheld_invalidate_14998_test.go` — parse-layer
  co-held invalidation sentinel + positive control, commit-layer
  address-less removal + same-address control, run-loop co-held
  invalidation removing the WAN address, and a PD-prune test proving the
  post-prune T1 wait is the ~1s remaining time (lease 40s obtained 19s
  ago) rather than a full 20s restart, plus a no-expiry control.

## Risk
Neighbours preserved: stateless commits (prev == nil) are unaffected —
the remove fires only when a previous address exists and differs; a
same-address renewal removes nothing. `TestCommitLeaseStatelessNoAddress`
and the absent/transient keep-and-retry tests (#5927, #14598) stay green.
Residual: `remainingTimer` on a zero `Obtained` (test-seeded leases)
yields a near-zero wait; production leases always carry a real `Obtained`.
