# Issue #12745 — reject daily all-day plus a complete time window

## Root cause

The strict scheduler-window validator added by #12643 covered weekday overrides but did not inspect the effective daily window. `scheduler.isWithinWindow` checks `AllDay` before parsing or applying start/stop bounds, so a daily all-day flag combined with a complete time window commits while the time restriction is silently ineffective.

## What changed

- Extended `validateSchedulerWindowPairs11358` to aggregate effective daily scalar values using the compiler's existing composition rules and reject a daily all-day plus complete start/stop pair as #12745.
- Kept tolerant load and peer-sync behavior: warn and retain the compiled union. Separate daily statements still use existing last-wins all-day semantics.
- Added compiler cells for authored, flat-set, load-merged, group-inherited, peer-group, and legacy direct daily representations; controls pin all-day-only, window-only, partial bounds, `exclude`, weekday separation, and daily last-wins behavior.
- Added a configstore `CommitCheck` regression and updated the scheduler schema reference.

## Risk

Existing configs with daily all-day and a complete time window continue to load tolerantly with a warning and retain their union; strict commit validation refuses them until the contradictory daily bounds or all-day flag is removed. Separate daily statements that compile to an unambiguous last-wins window remain accepted.
