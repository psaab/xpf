# #14208 D11 draining fallback forwards attestation probes — engineering history

Issue: psaab/xpf#14208 ([research D4-02] `dispatchAttestEligible` falls
back to `submitEligible` (ordinary FORWARD) during `D11Draining`;
`d11RevokedPermitEpoch` latched). Lane branch: `fix/14208-campaign`,
base `origin/master` 7d6ac3b2b.

## Defect (present at base)

`D11AttestationArmer.Matches` returns false once the armer leaves
`D11Armed`, and `dispatchAttestEligible`
(`pkg/nfqueue/pipeline_attest_10484.go`) delegated *all* frames to
`submitEligible` whenever `State() != D11Armed`. A selector-matching
(ICMP marker) frame dispatched during the `D11Draining` window —
between `BeginDrain()` and pipeline teardown in
`rollbackD11` (`pkg/daemon/ipsec_capture_wiring_9506.go`), while
ordinary capture keeps running via `Poll`/`dispatchEligible` — was
therefore reclassified as ordinary traffic and, if zone-pass FORWARD,
submitted with `ReinjectSubmitFlagForward` instead of hitting the
deny-only attestation terminal.

Second half: `CancelForD11Drain` sent one `CancelReinject` whose
queue scopes were derived only from `p.pending`. On the Rust side
(`userspace-dp/src/slowpath_reinject_9506.rs` `ReinjectCore::cancel`)
a non-empty queue-scope set tombstones only those queues; the whole
permit is closed only when the scope set is empty. With pending work
on queue A alone, queue B stayed authorized, so a fresh ordinary
FORWARD lease minted on B during the drain could still be admitted
and TUN-written.

The `d11RevokedPermitEpoch` permanent-latch half was investigated and
not changed: the field lives on the per-runtime `CapturePipeline`,
pipelines are staged fresh per capture generation
(`newIpsecCapturePipeline`), and `attestSubmit`'s `!= 0` check is
intentionally fail-closed within that single-use lifetime. No
production path re-arms a drained pipeline instance.

## Fix

- `pkg/nfqueue/pipeline_attest_10484.go`: new
  `D11AttestationArmer.MatchesDraining` (marker match gated on
  `D11Draining` instead of `D11Armed`; the selector is retained until
  `Disarm`). `dispatchAttestEligible` now partitions frames in
  `D11Draining`: marker frames go to the deny-only `attestSubmit`
  (refused via the latched `d11RevokedPermitEpoch`, or via
  `attestLease` requiring `D11Armed` in the narrow pre-latch window),
  non-marker frames keep the ordinary path so unrelated capture stays
  live during rollback. All other states keep prior behavior exactly.
- `pkg/nfqueue/pipeline.go`: `CancelForD11Drain` now issues the
  scoped fence first and, when that fence carried queue scopes, a
  second `CancelReinject(nil, permitEpoch, nil)` whose empty scope
  set closes the whole Rust permit. The already-correct no-pending
  case (first fence already closes the permit) is not duplicated.
  Both sends travel on the ordered submit stream under
  `submitGate.Lock`, so the close cannot be overtaken by a submit.

NOT changed: Rust cancel semantics (empty-scope = close permit is
the intended wire contract), `Matches` (armed-only selection stays
the attestation admission gate), the `d11RevokedPermitEpoch` latch
(single-use pipeline lifetime; see above), and the 500 ms
`DrainD11` bound.
