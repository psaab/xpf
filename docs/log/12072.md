# Issue #12072 — Resolve stable policy IDs for prepublish session reads

## Why

Runtime policy IDs are positional. Prepublish reads must resolve bound sessions through their stable rule handle at the helper's known applied snapshot, or a deleted rule's old number can select an unrelated surviving session. An incomplete READ creates a second risk: a missed deleted-rule session can become an orphan after publication and resolve to the default-policy sentinel in later snapshots.

## What

The daemon now distinguishes authority refusal from enumeration failure. Unknown authority blocks publication and preserves the retry plan. A known applied predecessor permits safe re-anchoring when it differs from both the stale stored predecessor and target; if the helper already holds the target, the lost old positional namespace cannot be reconstructed, so publication is refused. Publication generations continue to reject stale callbacks. Rename ancestry is retained only across the immediate config pair.

An incomplete scan surfaces one commit error and one ERROR-level alarm. Confirmed delete outcomes are pruned from retained candidates, so settled retries do not resend rows or repeat the error. Independent later commits still revoke their own affected sessions. A later complete scan clears scan debt when it proves the same old authority is still active; the target may differ if the incomplete target never published. A published incomplete target advances the authority, so later scans cannot certify its missed identities.

## Risk

The LIST reply contains only the resolved positional ID, not the original stable rule identity. After a partial scan has published, a missed deleted-rule session is indistinguishable from a legitimate default-policy session at the sentinel; sweeping all sentinel rows would over-delete valid sessions. The daemon retains scan debt and keeps `ActiveApplied` false while those identities remain unresolved. If publication did not land, retry under the original authority; a complete scan at that same authority also clears debt when a superseding target replaces the unpublished one. If the incomplete scan published, the current wire cannot recover missing identities automatically: perform a full session clear with `clear security flow session`, then a later successful apply can mark the configuration applied. Later independent revocations remain enabled, and the original error does not loop on status ticks.
