# Issue #12072 — Resolve stable policy IDs for prepublish session reads

## Why

Runtime policy IDs are positional. Prepublish reads must resolve bound sessions through their stable rule handle at the helper's known applied snapshot, or a deleted rule's old number can select an unrelated surviving session. An incomplete READ creates a second risk: a missed deleted-rule session can become an orphan after publication and resolve to the default-policy sentinel in later snapshots.

## What

The daemon now distinguishes authority refusal from enumeration failure. Unknown or mismatched helper authority blocks publication and preserves the retry plan; a known applied config permits safe re-anchoring, while publication generations continue to reject stale callbacks. Rename ancestry is retained only across the immediate config pair.

An incomplete scan surfaces one commit error and one ERROR-level alarm. Confirmed delete outcomes are pruned from retained candidates, so settled retries do not resend rows or repeat the error. Independent later commits still revoke their own affected sessions, but their complete scans cannot certify an earlier incomplete scan in a different policy namespace. Only a complete same-pair retry while the original authority remains active clears that scan debt.

## Risk

The LIST reply contains only the resolved positional ID, not the original stable rule identity. After a partial scan has published, a missed deleted-rule session is indistinguishable from a legitimate default-policy session at the sentinel; sweeping all sentinel rows would over-delete valid sessions. The daemon therefore retains scan debt and keeps `ActiveApplied` false rather than claiming convergence. If publication did not land, re-commit the same pair after helper recovery while its old authority is still active. If the incomplete scan was already published, the current wire cannot safely repair missed identities automatically; operator remediation is required. Later independent revocations remain enabled, and the original error does not loop on status ticks.
