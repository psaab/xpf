# Issue #12072 — Resolve stable policy IDs for prepublish session reads

## Why

A session stores the policy ID from admission, but that numeric ID is positional and can change when the policy snapshot is reordered. During a three-config commit, a prepublish read for a newly deleted rule could therefore return an unrelated older session that inherited the same number. Unbound peer-synced rows have no stable rule identity with which to disambiguate that read.

## What

Prepublish worker reads now resolve bound sessions through their stable policy-rule handle against the active forwarding snapshot, and return the resolved ID. Unbound peer-synced rows are excluded from prepublish ID-keyed reads. The shared-map completeness check applies the same resolution and exclusion, while legacy timestamp-fenced reads retain their scalar behavior. Added worker regressions for reorder, renamed aliases, and unbound peer rows, plus a three-config daemon invalidation regression; updated the HA coverage expectation and invalidation comments to document the current contract.
