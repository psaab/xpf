# Issue #12827 — validate daemon-materialized zone logical units

## Why

`validateZoneInterfaceDefinedStrict` admitted the `lo0` and IPsec-bound `st0` bases, but its logical-unit check consulted only `cfg.Interfaces.Interfaces[base].Units`. When an explicit base stanza omitted the unit, a zone referencing bound `st0.N` or materialized `lo0.0` was rejected despite the unit existing at runtime. When the base was referenceable only through the dynamic-base allowance and had no stanza, every unit skipped the existence check, so an unbound `st0.N` (or `lo0.N`) was accepted.

## What

- Check logical-unit existence against an authored interface unit, the existing implicit unit-zero tunnel exception, or a precisely materialized dynamic unit: `lo0.0` or the exact non-colliding IPsec-bound secure-tunnel reference.
- Keep base-name referenceability separate from unit existence; unrelated/unbound units remain rejected, including when the base is only dynamically materialized.
- Add strict-commit regressions for bound and unbound tunnel units, loopback units, canonical unit aliases, and configured physical/WireGuard controls; also pin tolerant-load warning behavior.

## Validation

- RED before the fix: `go test ./pkg/config -run 'TestZoneInterface(DynamicUnit(FailsCommit|Commits|WarnsOnLenientLoad)12827)$' -count=1` failed because bound `st0.0` and `lo0.0` were rejected while unbound `st0.99` and `lo0.1` were accepted.
- Focused GREEN after fix and after mutation restoration: the same command passed.
- Mutation check: restoring the original configured-Units-only logical-unit check made the new regressions fail: the unbound `st0.99` and `lo0.1` cases were accepted, while bound `st0.0` and `lo0.0` were rejected. The production fix was restored and the focused suite passed again.
- `go build ./...` and `go vet ./pkg/config` passed.
- `go test ./pkg/config -count=1` ran for 10 minutes, reported unrelated existing failures in #8939 (flat-set chain census), #8662 (inventory census), #9027/#9029/#8921 and #10826 (API-auth expiry/self-repeat), #8787/#11312 (forwarding-instance membership), and schema slot-escape coverage, then timed out in `TestSchemaSpellingDifferentialGate` while bcrypt-hashing API-auth fixtures. No #12827 test failed.

## Risk

Strict commit now rejects unit references which the dynamic-base check previously let pass despite no corresponding runtime unit. Correctly configured bound secure-tunnel units and loopback unit zero are accepted; tolerant compilation continues to warn rather than reject invalid persisted references. No dataplane behavior or live configuration was changed.
