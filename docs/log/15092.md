# #15092 — userspace-dp: configured_zone_pairs() materialises every concrete zone pair per wildcard/global rule (A63-01)

- **Timestamp**: 2026-10-18 (`fix/15092-campaign`)

## Why

`PolicyState::configured_zone_pairs()` (`userspace-dp/src/policy.rs`)
expanded every wildcard/global scope into a `BTreeSet` of concrete
`(from, to)` pairs: both-any inserted `|concrete|²` pairs, and each
unscoped `junos-global` rule cloned the concrete universe and inserted
another full cross product. At 8000 zones one Any×Any scope is 64M
pairs (~1 GB of set nodes), repeated per unscoped global, inside the
snapshot build that runs 2–3 times per commit — a control-plane stall
of seconds per build. The consumer (`ColdPathSlotMap::build`) can only
assign 255 slots, so all but the first 255 pairs were discarded work.

## What

- `userspace-dp/src/policy.rs`: `configured_zone_pairs()` is now the
  bounded form's small-config oracle. New
  `configured_zone_pairs_bounded(limit) -> ConfiguredZonePairs { pairs,
  overflow }` (limit clamped to `COLD_PATH_ASSIGNABLE_SLOTS`):
  - exact `zone_pair_index` pairs first (unchanged slot priority);
  - the wildcard/global tier is generated as sorted per-scope
    cross-product streams merged k-way with dedup, emitting at most
    the slots left after the exact tier, plus one probe pair to set
    `overflow`. No cross product is materialised; an Any×Any scope
    (both-any or unscoped global) subsumes all other wildcard/global
    scopes and becomes the sole stream. Pairs already in the exact
    tier are skipped without consuming budget.
  - `ConfiguredZonePairs.overflow` is true exactly when distinct
    wildcard/global pairs beyond the exact tier exceed the remaining
    budget.
- `userspace-dp/src/afxdp/forwarding_build/mod.rs`: the snapshot build
  now calls `configured_zone_pairs_bounded(COLD_PATH_ASSIGNABLE_SLOTS)`
  and ORs `overflow` into `ColdPathSlotMap::overflow_active` — without
  it, a capped 255-pair input is indistinguishable from an exact fit
  and the operator starvation flag would never fire for this tier.
- `userspace-dp/src/afxdp/cold_path_hist.rs`:
  `COLD_PATH_ASSIGNABLE_SLOTS` widened `pub(in crate::afxdp)` →
  `pub(crate)` so `policy.rs` clamps to the same constant;
  `overflow_active` doc notes the build-side OR.

NOT changed: slot assignment, retention, and zeroing in
`ColdPathSlotMap::build`; the exact-tier set and its priority; policy
evaluation tiers. Small configs (union ≤ limit) return byte-identical
pair vectors to the pre-fix function.

## Validation

- **RED (pre-fix)**: the test-only patch (the three `*_15092` policy
  tests) applied to a clean `origin/master` worktree
  (`d85a1c085a`) fails to compile with E0599 `no method named
  configured_zone_pairs_bounded` at every call site — the bounded
  entry point does not exist pre-fix, and the unbounded path it
  replaces materialises 64M pairs per Any×Any scope at the
  8000-zone acceptance shape, so the <50 ms bound cannot be met.
- **GREEN (this branch)**: `cargo test --bins configured_zone_pairs`
  7/7 (4 pre-existing #3783 + 3 new `*_15092`); `cargo test --bins
  cold_path` 49/49 (incl. `bounded_pairs_overflow_reaches_slot_map_15092`);
  `cargo test --bins policy::` 268/268. The 8000-zone test completes
  its bounded call in the suite's 0.06 s total for all 7 tests.
- **Neighbouring suite**: `cargo test --bins forwarding_build`
  305 passed, 1 failed
  (`wg_live_endpoint_survives_one_peer_edit_rebuild_14640`, panics

- Pre-existing clippy `mut_from_ref` deny at
  `afxdp/umem/mmap.rs:241` is untouched base state, not introduced
  here.

## Risk

- Behaviour delta is confined to over-capacity configs: which
  wildcard pairs win slots is still the ascending `(from, to)` order
  the pre-fix `BTreeSet` produced, and exact pairs still win first.
  At-capacity and under-capacity configs are byte-identical.
- `overflow_active` now also fires when the wildcard/global tier alone
  exceeds capacity (previously it fired only when the materialised
  union did — same configs, same flag, reached without the stall).
- Residual: per-scope stream count is bounded by distinct wildcard
  keys + global rules; a config with thousands of distinct scoped
  globals pays O(emitted × scopes) merge probes (≤255 × scopes),
  trivial next to the removed cross products.
