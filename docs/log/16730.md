# #16730 — `xpf_userspace_ha_takeover_blocker` drops fabric blockers; unpublished snapshot mislabelled

## Defect

`pkg/api/metrics_ha_takeover_13301.go` emitted one series per name in a
hard-coded 14-name list ending at `event_stream_unbound`. The producer
(`Manager.HATakeoverReadiness` in `pkg/dataplane/userspace/manager_ha.go`)
had since (#15918) learned to return `fabric_not_converged` /
`fabric_peer_unresolved`, so in exactly the fabric-gate states those
blockers were silently discarded: Prometheus showed `ready=0` with no
cause. The mapper's `default:` arm also sent every unrecognised reason —
including `userspace snapshot generation N unpublished` — to
`forwarding_unsupported`, pointing operators at the wrong subsystem.

## Fix

- Single shared vocabulary in `pkg/dataplane/userspace`:
  `HATakeoverBlocker*` constants, `HATakeoverBlockers` (emit list,
  including `fabric_not_converged`, `fabric_peer_unresolved`,
  new `snapshot_unpublished`, and catch-all `other`), `IsHATakeoverBlocker`,
  and `MapHATakeoverBlocker` (extracted mapper). Both mapper and emitter
  consume it, so they cannot drift.
- Mapper: the snapshot generation-unpublished reason is matched before
  the forwarding default and maps to `snapshot_unpublished`;
  snapshot-retry-debt keeps its own name (checked first, since its text
  also contains "unpublished"); verbatim capability `UnsupportedReasons`
  (`userspace ...`) still map to `forwarding_unsupported`; any other
  unrecognised reason maps to `other`, never to a specific subsystem.
- Emitter (`pkg/api`): iterates `dpuserspace.HATakeoverBlockers` instead
  of the local 14-name array (deleted); a blocker value outside the
  vocabulary folds into `blocker="other"` at 1 instead of vanishing.
- `LegacyDataPlaneAdapter` nil-manager fallback uses the constant.

No gate behaviour changes: `ready` computation in `takeoverReadyLocked`
is untouched; only the machine-readable blocker naming/emit surface.

## Residuals

- New Prometheus series (`fabric_*`, `snapshot_unpublished`, `other`)
  appear at 0 on nodes that never hit them — expected for a bounded
  gauge family; dashboards keyed on absence should switch to `== 1`.
