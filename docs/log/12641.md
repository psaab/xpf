# #12641 — withhold applied stamp after a failed deferred tail

## Why

A peer config apply can defer its userspace snapshot, then fail while reconciling the local tail. The peer receives a NACK, but the later status-loop catch-up previously treated publication as proof of a complete apply and stamped the active digest. A retry could then take the #4957 shortcut and ACK a partially converged config.

## What

Added `tailFailed` to policy-invalidation debt. `applyConfigLocked` records it only when a failed apply still has a matching deferred snapshot; a successful same-target retry clears it. Debt recaptures preserve the state for that same target, and catch-up no longer fills an empty `appliedDigest` while the tail is known to have failed. Added regression coverage for the failed-tail catch-up, status-loop recapture, same-target recovery, lost-response catch-up, and a mismatched active target.

## Validation

- RED-on-guard-removal: `go test ./pkg/daemon -run '^TestR50BaseFailedTailDeferredNeverStamped$' -count=1` failed because catch-up stamped the failed-tail config as applied.
- GREEN: `go test ./pkg/daemon -run '^(TestR50BaseFailedTailDeferredNeverStamped|TestSameTargetRetryClearsFailedTail12641|TestLostResponseDeferredCatchupStillStamps12641|TestCatchupDoesNotStampMismatchedActiveConfig12641)$' -count=1` — passed.
- `go vet ./pkg/daemon` — passed with no diagnostics.
- The first `go test ./pkg/daemon -count=1` run reached the default 10-minute Go timeout. A 45-minute run completed with `TestFeedShrinkHighWaterSurvivesColdDaemonRestart11755` failing to observe its audit warning; its isolated rerun passed.
- Final full-suite rerun: `go test ./pkg/daemon -count=1 -timeout=45m` — passed (`800.468s`).

## Risk

When a deferred apply's tail fails, status publication alone no longer advances the applied marker. The marker remains withheld until a successful same-target apply or another valid convergence path; the failed config therefore cannot be falsely ACKed by the peer re-push shortcut.
