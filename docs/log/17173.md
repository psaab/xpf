# Issue #17173 — R4-Q06-04: CoS scheduler constants stranded in tx/drain

- **Issue:** `COS_GUARANTEE_VISIT_NS`, `COS_GUARANTEE_QUANTUM_{MIN,MAX}_BYTES`
  and `COS_SURPLUS_ROUND_QUANTUM_BYTES` were defined in
  `userspace-dp/src/afxdp/tx/drain/mod.rs` and re-exported via `tx/mod.rs`,
  but their only production consumers are in `cos/queue_service`
  (`settle.rs`, `waterfill.rs`), which imported them back through
  `crate::afxdp::tx` — contradicting the queue_service back-edge comment
  that limits that import to XSK-ring / worker-binding / prepared-frame
  primitives. STEP-0 re-check on `origin/master` (47a93d76fd): defect live
  (definitions drain/mod.rs:563-566, re-export tx/mod.rs:21-24, import
  cos/queue_service/mod.rs:123-125).

- **What:** Moved the four constants verbatim (same names, values and
  `pub(in crate::afxdp)` visibility: 200_000 / 1500 / 512*1024 / 1500)
  into `cos/queue_service/settle.rs`, immediately above
  `cos_guarantee_quantum_bytes` / `cos_surplus_quantum_bytes` — the
  helpers that consume them. `waterfill.rs` and the `queue_service`
  tests reach them unchanged via `use super::*`. Removed the
  definitions from `tx/drain/mod.rs`, the re-export from `tx/mod.rs`,
  and the four names from the `crate::afxdp::tx` import in
  `cos/queue_service/mod.rs` (they are now imported from `settle`).
  Updated the `tx/README.md` `drain.rs` row that claimed drain owns
  them. No other file referenced the constants (repo-wide grep);
  `types/cos.rs` doc comments name them only as prose and remain
  accurate. Historical plan docs (#956 / P2c) that deferred this move
  are left as history.
