# #18832 — session-delta test walks the sync encoder layout

- **Mechanism**: The #9412 session-delta cell read `frame.len() - 22` to find
  the TCP close class. Session-sync records are append-only; later trailers
  (including the NAT-scope field, packet counters, and the stated-pair marker)
  move that byte without changing its offset from the payload start.
- **Action**: Replace the tail-relative read with a named-width walk in the
  `encode_session_record` field order for this IPv4 fixture, then assert the
  close class at that wire offset. Cite append commits c65a353e8b, a936a6f802,
  and aab4483e1a alongside the test. No encoder or production code changes.
- **File(s)**: `userspace-dp/src/afxdp/session_glue/tests.rs`,
  `docs/log/18832.md`.
- **Validation**: The original exact cell was RED at the fixed-tail assertion
  (`left: 0`, `right: 2`). After the walk, the exact cell passed; the 9
  `flush_session_deltas` cells passed. The close-class-zero mutant failed at
  the walked offset (`left: 0`, `right: 2`). The full
  `afxdp::session_glue::tests::` module ran 293 passed / 1 ignored / 1 failed;
  the separate `purge_translated_synced_hit_releases_nat64_reservation_5295`
  failure also reproduced when run alone.
- **Risk**: The walk is intentionally tied to the IPv4 fixture used here; if
  its address family changes, the address widths must follow the encoder's
  `is_v6` layout. Later append-only fields follow this offset and do not move
  it.
