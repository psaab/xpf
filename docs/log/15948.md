# #15948 — NAT allocator/scope defects

Fixes the validated claims from the deep-review triage (verification
rev 61c7d45603), Go-side premise closed first:

- H36-03: Go already emits `reject` distinctly
  (`TestRouteSnapshotRejectSurvivesForRecursiveExpansion15948` pins it);
  Rust `recursive_static_target_v4/v6` now treat `discard || reject`
  as terminal instead of falling through to a less-specific route.
- H31-01: `restore_displaced` no longer requires the replacement to
  still be present after a sole-holder `rollback_flow` unlink; the
  non-persistent tail restores the incumbent tuple/port/owners.
- H31-02: idle-lease existing-lease merge now checks contention and
  diffs owner keys, incrementing `persistent_address_only_owner_counts`
  for newly merged scopes/remotes.
- H31-03: fresh deterministic NAT64 BIBs (active) are no longer
  inserted into the idle-expiry indexes, and an already-active join
  no longer overwrites expiry without re-keying.
- H32-04: fabric NAT64/NPTv6 rows are judged by their geometry
  validators instead of the scope exemption; MissingNeighbor seeds
  thread `ingress_nat_scope_ifindex` instead of hardcoded `None`.
  Non-fabric legacy rows keep their exemption (NPTv6 bit does not
  survive the HA wire).
- H33-03: NAT64 forwarded builders and the slow-path builder clamp
  TCP MSS via `select_tcp_mss`, both directions.
- H36-02: the NAT64 MissingNeighbor fail-closed drop now fires a
  throttled kernel probe + resolver enqueue for the v4 egress hop.

(runtime already treats `discard || reject` as terminal).
