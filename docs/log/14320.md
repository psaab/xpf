# #14320 — Zone rebind helpers leave stale ingress/egress zone vintage checks

## Defect
`SessionTable::rebind_policy_pair`, `SessionTable::rebind_zones_pair`, and
`restamp_shared_policy_entries` updated `ingress_zone`/`egress_zone` on the
forward entry and reverse companion (and shared aliases) but never restamped
the #10620 `ingress_zone_check`/`egress_zone_check` vintage hashes. After a
legitimate rebind to a differently-named zone, the (id, check) pair was
inconsistent, so `synced_entry_is_stale_replay` could false-positive and evict
a live session on shared promotion / prewarm / BPF republish.

## Fix
- `userspace-dp/src/session/mod.rs`: `rebind_policy_pair` and
  `rebind_zones_pair` now take `ingress_zone_check: u32` and
  `egress_zone_check: u32` alongside the zone ids and restamp both halves
  (forward: ingress/egress checks as passed; companion: swapped, mirroring
  the zone-id swap). Checks are `u32` — the issue text's `u16` was stale;
  `SessionMetadata` fields and `zone_identity_check` are `u32` on master.
- `userspace-dp/src/afxdp/shared_ops/store.rs`: `restamp_shared_policy_entries::apply`
  now also copies `ingress_zone_check`/`egress_zone_check` from the rebound
  `PolicyRebindEntry` metadata into every shared alias.
- `userspace-dp/src/afxdp/worker/loop_body/reconcile.rs`: both production
  callers compute the checks via `zone_vintage_check_for_id` from the NEW
  forwarding view (`new_forwarding` for the rematch path, `forwarding` for
  the snapshot rebind path) and pass them in; the declined-rematch path also
  restamps its local `metadata` copy so downstream teardown/publish uses the
  consistent pair.
- Existing test callsites in `session/tests.rs` migrated to the new
  signatures (checks `0` = unknown, preserving their prior zone-limit /
  LocalDelivery semantics).

Scope note: `revalidate_forwarding_resolution_with_egress_zone` (#14318)
already clears the moved leg's check to 0 (fail-open unstamped) rather than
leaving a stale hash, so it cannot false-positive the fence and is out of
scope for this issue.

## Regression
- `session::tests::rebind_zones_pair_restamps_zone_vintage_checks_14320` —
  the decisive regression from the issue: pair in (lan, wan) stamped with
  `zone_identity_check("lan")`/`("wan")`, `rebind_zones_pair` to
  (dmz, wan), asserts forward `ingress_zone_check == zone_identity_check("dmz")`
  and reverse companion `egress_zone_check == zone_identity_check("dmz")`
  (plus the unchanged wan legs).
- `session::tests::rebind_policy_pair_restamps_zone_vintage_checks_14320` —
  same invariant through the policy-rebind path.
