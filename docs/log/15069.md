# Issue #15069: DHCPv6 missing IA_PD is never re-requested while IA_NA renews (A39-01)

## Why

`buildV6RenewMessage` (`pkg/dhcp/renew.go`) only added an IA_PD when
`len(prevPDs) > 0` — echoing the held prefixes — and `doDHCPv6`
(`pkg/dhcp/dhcpv6.go`) passed only the held set plus the client-id/ORO
renew modifiers. After a boot-time `NoPrefixAvail`, a refusal, a
withdrawal, or a #14598 per-prefix expiry prune, the committed PD set
is empty, so every subsequent RENEW/REBIND carried no IA_PD at all.
The IA_NA renewed successfully forever, the client never fell back to
a fresh Solicit, and the LAN IPv6 (RA prefix/SLAAC fed by the
delegation) stayed absent indefinitely, until manual
`request dhcp renew` or restart. The renew builders also had no way
to re-emit the acquisition prefix-length hint.

## What

- `pkg/dhcp/renew.go` (`buildV6RenewMessage`): takes the configured IA
  types and the acquisition hint (`pdHint *dhcpv6.OptIAPrefix`,
  built by the caller through the existing bounded
  `pdHintPrefixLength`, #8597). When no PD is held but `ia-pd` is
  configured (`v6WantsPD`, the same membership parse
  `parseV6ReplyChecked` applies), the Renew/Rebind carries an empty
  IA_PD with IAID `{0,0,0,1}` and the hint — exactly the acquisition
  shape — so the server can grant a prefix on that cycle. The held-PD
  echo and the not-configured shape are byte-for-byte unchanged.
- `pkg/dhcp/dhcpv6.go` (`doDHCPv6`): splits the renew modifiers from
  the IA construction and passes `v6opts.IATypes` plus the bounded
  hint into the builder; the comment on `buildDHCPv6RenewModifiers`
  records the split. The three in-tree builder callers in tests
  (`renew_test.go`, `dhcpv6_rebind_teardown_14997_test.go`,
  `duid_stability_5711_test.go`) pass `nil, nil`.
- No matcher, parser, reconcile, commit, or run-loop change: the
  requested empty IA_PD makes `v6HasSuccessfulRequestedIA` accept a
  grant reply, `v6ReplyTearsDownHeldBinding` treats a renewed
  `NoPrefixAvail` as teardown content (still bound to the granting
  server on REBIND, #14997), and the existing reconcile/commit arms
  store a live prefix from a Renew/Rebind reply immediately.
- Tests: `pkg/dhcp/dhcpv6_missing_pd_15069_test.go` — builder cells
  proving Renew and Rebind both carry the IA_PD (with the /56 hint read
  off the serialised wire bytes, and empty without one) when `ia-pd`
  is configured and nothing is held; controls proving no IA_PD is
  emitted when `ia-pd` is not configured and that a held PD still
  echoes the held /48 rather than the hint; and a run-loop test where
  acquisition commits IA_NA only and the first Renew reply's live PD
  is committed (visible in `DelegatedPrefixes()` during the next
  cycle, IA_NA preserved) without waiting for IA_NA expiry.
- `pkg/dhcp/README.md`: renewal-semantics bullet recording the
  re-request behaviour and the matcher/commit interaction.

## Validation

- RED on base builder (revert of `renew.go`/`dhcpv6.go` only, tests
  kept): `pkg/dhcp/dhcpv6_missing_pd_15069_test.go` fails to compile —
  `too many arguments in call to buildV6RenewMessage ... want
  (net.HardwareAddr, *Lease, []DelegatedPrefix, bool,
  []dhcpv6.Modifier)` — the pre-fix builder has no re-request arm, so
  the defect cells cannot pass. (The run-loop test alone is
  green-by-construction pre/post fix because the exchange seam injects
  replies; the wire-shape cells above are the RED evidence.)
- GREEN: `go test ./pkg/dhcp/ -run '15069' -count=1` — all 4 builder
  cells, both controls, and the run-loop test pass.
  `go test ./pkg/dhcp/ -count=1` — full package passes.
  `go vet ./pkg/dhcp/` clean; `gofmt -l` on touched files empty.

## Risk

Neighbours preserved: a client without `ia-pd` configured sends no
IA_PD on renew (control test); a held delegation still echoes exactly
the held prefixes; stateless mode, DHCPv4, acquisition, and the
#14997 non-granting-teardown gate are untouched. A granting server
that keeps answering `NoPrefixAvail` now gets one IA_PD per
Renew/Rebind cycle (the normal T1/T2 cadence, no extra traffic): the
run loop's existing refusal arm clears the (already empty) set and
the cycle repeats at the next T1, which is the desired retry.
Residual: none known; lab verification on a real upstream that
withholds then grants a prefix rides the normal cluster smoke.
