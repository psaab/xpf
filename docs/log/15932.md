# #15932 — NAT64 zone-list truncation, cross-generation session revocation, deny double-charge, U1

Retro findings (Codex cfg C2, Codex DP 3–4, Opus DP F5/U1) against the
#15678 NAT64 scoping work, all on `origin/master` 9e94cf62ab.

## (1) Zone-list truncation (cfg C2)

`compileNAT64` read every `from zone` value via `collectNATScopes` but
stamped them onto one typed rule-set, last value winning, so
`from zone [ trust untrust ]` silently became untrust-only. The strict
scope gate only inspected the surviving singular field, so an undefined
second zone also passed.

Fix: `compileNAT64` Cartesian-expands the from-scope list into one
`NAT64RuleSet` per value (union), exactly as source/destination/static
NAT do. `NAT64RuleSet.FromZones` carries the authored list on
hand-built/unexpanded values; `validateNAT64ScopeStrict` checks every
effective zone. The Go snapshot folds singular+plural into
`NAT64RuleSnapshot.from_zones` and Rust `Nat64Prefix.from_zones` unions
it in `prefix_scope_matches` (singular fallback for old snapshots).
Snapshot protocol v61→v62 (Go `ProtocolVersion`, Rust
`CONFIG_SNAPSHOT_PROTOCOL_VERSION`, shape golden) fences a v61 helper
that would ignore the list.

Allocator ownership: the dataplane keys a NAT64 allocator by
(prefix, pool), so expanded siblings are one logical owner.
`nat64PrefixOwnerKeyScoped` stays the name-free shadow key (#9555);
a new `nat64AllocatorKey` (prefix+name+pool) dedupes siblings in the
#5144 owner enumeration so a bracket list sharing one pool compiles
clean while two different rule-sets sharing a pool still reject.
`validateNATRuleSetMixedScopeAST` now also walks `nat64` rule-sets: a
mixed zone+RI clause previously expanded into two one-axis members and
escaped the typed mixed gate entirely.

## (2) Cross-generation revocation (DP3 / F5)

Mint selects the NAT64 owner scoped (`classify_ipv6_packet_scoped`:
zone/RI/source), but `nat64_deterministic_translation_mismatch`
re-selected destination-only (`match_ipv6_dest`, first /96). With A
(first, deterministic, pool .1) and B (second, other zone, disjoint
pool .2), a valid B session revoked as `StaleSourceNat` on the first
generation-stale hit.

Fix: revalidation carries the admitting provenance into the check.
`source_nat_translation_still_valid` re-derives the ingress scope from
the session's recorded identity via `prerouting_ingress_scope`
(recorded `nat_scope_ifindex`, VLAN, fabric zone override — the same
resolver admission used) and calls the new scoped predicates
(`nat64_revalidation_still_valid` /
`nat64_deterministic_translation_mismatch_scoped`), which re-select
through `match_ipv6_dest_scoped(src, dst, zone, RI)`. No wire/session
field was added: the provenance already rides the session metadata.

## (3) U1 — validated, then scoped

U1 asked whether existing sessions keep translations after scope
tightening. They did: only a positive deterministic geometry mismatch
revoked, so a round-robin session (or a deterministic one whose rule
was rescoped away) survived indefinitely. The product contract is the
#8356/#15178 one — a commit that withdraws the admitting rule revokes
on the next stale hit — so this is a defect, not grandfathering.

Fix: under a recorded scope, `nat64_revalidation_still_valid` returns
invalid when no live prefix matches the recorded scope+source, or the
matching owner no longer holds the translated tuple (pool/geometry
edit), for round-robin and deterministic owners alike. Rows with NO
recorded scope (legacy peer, identity-less import) keep the
pre-#15932 destination-only deterministic-mismatch exemption and are
never judged against an invented empty scope (#15176 discipline).

## (4) Deny double-charge (DP4)

The #15664 bound-counter charge ran unconditionally at the top of the
LocalDelivery hit arm; the host gates below (host-inbound, lo0,
junos-host re-check) could then deny the same packet and charge the
denying rule — one dropped packet charged both permit and deny.

Fix: the LocalDelivery bound charge is deferred in
`poll_descriptor/mod.rs` until after every host gate (input filter,
NAT/policy revalidation, host-inbound, lo0, junos-host) has passed.
Denied hits `continue` before the deferred site, charging only the
denying rule; permitted hits charge the admitting rule exactly once.
Transit charging is unchanged; foreign arrivals still never charge.
