# #15095 — GRE outer-fragment reassembler captured transit GRE/PPTP fragments

## Defect
The #14645 native-GRE outer-fragment reassembler buffered every
fragmented proto-47 datagram that reached `stage_native_gre_decap`,
with no check that the outer destination was a native-GRE endpoint.
A transit GRE (or PPTP, proto 47) datagram fragmented upstream was
consumed fragment-by-fragment; when it completed, decap missed (no
configured endpoint), the stage mapped the result to `Buffered`, and
`poll_descriptor` recycled the descriptor with no counter. Fragmented
transit GRE/PPTP was therefore never forwarded (it never reached the
ordinary flowless / fragment-association path), and the final drop
had no operator-visible counter. It failed closed — no decap or
policy bypass — but a supported transit service was silently lost
whenever the outer datagram was fragmented upstream.

Source: `claude-opus-5-5-review-full-firewall-hostile-r2-002.md`
claim A68-01, validated MATERIAL 3-way in research run
`research-work.AdQvt1jMKw` (base `27b8cba22d`).

## Fix
- `userspace-dp/src/afxdp/poll_stages.rs` (`stage_native_gre_decap`):
  the fragment branch now additionally requires
  `gre::outer_frame_targets_gre_endpoint(raw_frame, meta, forwarding)`.
  Otherwise the stage falls through to the ordinary decap attempt,
  which returns `NotGre` for a fragment (head: truncated inner / no
  endpoint; tail: protocol sentinel), so transit fragments take the
  ordinary flowless and fragment-association path.
- `userspace-dp/src/afxdp/gre.rs`: new
  `outer_frame_targets_gre_endpoint` probe. It builds the index key
  exactly as the decap lookup does — `(addr_family, outer_dst,
  outer_src)` parsed from the frame bytes — and checks
  `gre_decap_index` presence. It is deliberately weaker than
  `match_tunnel_endpoint`: GRE key, transport-domain, egress and
  host-inbound checks still run at decap on the reassembled datagram.
  A malformed outer header returns `false` (no buffering; the
  ordinary path owns malformed-fragment disposition).
- Counted refusal: when a buffered datagram completes but decap then
  returns `None`, the stage increments the new
  `GreDecapCounters::reassembled_decap_refusals` before returning
  `Buffered`. The fragments were consumed by the pool, so this is a
  real drop and must not be silent. Surfaced end-to-end as
  `gre_reassembled_decap_refusals_total` (Rust `ProcessStatus`) →
  `GreReassembledDecapRefusalsTotal` (Go) →
  `xpf_userspace_gre_reassembled_decap_refusals_total` (Prometheus),
  carried across config applies with the sibling GRE counters.

## Deliberately NOT changed
- XDP shim steering (`native_gre_fragment_stays_on_helper`): the shim
  has only the global native-GRE-armed bit, no per-endpoint table;
  narrowing it would strand GRE-to-self tails. Fragments still reach
  the helper, which now declines non-endpoint ones immediately.
- Per-source pool quota: the endpoint gate removes the non-peer flood
  vector entirely (non-peer fragments never enter the pool), so a
  quota would only police configured peers against each other — a
  separate concern, not filed.
- Shim-side buffered recycle counters: the `Buffered` recycle in
  `poll_descriptor` covers both still-incomplete fragments (routine)
  and the counted refusal above; adding a second counter there would
  double-report.

## Tests
`tests_gre_transit_frag_15095` (stage-level, through
`stage_native_gre_decap`):
- `transit_gre_fragment_head_and_tail_return_not_gre_15095` — no
  tunnel endpoints: head and tail both return `NotGre`.
- `gre_fragment_to_different_pair_returns_not_gre_15095` — a tunnel
  bound to a different outer pair: head and tail return `NotGre`.
- `gre_to_self_fragments_still_reassemble_and_decap_15095` — named
  control: tail buffers, head completes, decapped inner is
  byte-identical, refusal counter stays 0.
- `non_peer_head_flood_cannot_block_peer_reassembly_15095` — 65
  distinct transit heads (pool cap is 64) all return `NotGre`; the
  peer's fragmented datagram still reassembles and decaps.
- `reassembled_but_decap_refused_is_counted_15095` — keyed GRE to an
  unkeyed endpoint: fragments buffer (tuple indexed), completion
  refuses at the key check, counter increments exactly once.

Plus wire/metrics lockstep: Rust `ProcessStatus` round-trip
(`process_status_gre_reassembled_decap_refusals_roundtrip`), Go
wire-key lockstep
(`TestGreReassembledDecapRefusalsWireKeyLockstepWithRust`), and the
Prometheus descriptor/coverage/emit entries with a distinct fixture
value (15).
