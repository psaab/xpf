# #15057 - Decaying DHCPv6-PD lifetimes restart the cluster RA sender on every 2s reconcile pass (A26-01)

- **Timestamp**: 2026-10-18
- **Action**: `buildRAConfigs` baked the decayed remaining lifetimes
  (`RemainingLifetimes(now)`, whole-second granularity) into
  `RAPrefix.ValidLifetime`/`PreferredLife`. The cluster reconcile runs
  every ~2s (`daemon_ha.go` -> `reconcileClusterRAServices`), and both
  its `raDesiredHash` gate (JSON marshal including lifetimes) and
  `pkg/ra` `configEqual` saw a new value every pass, so `ra.Apply`
  hard-restarted the sender continuously: 3-RA startup burst, new NDP
  socket, and two Info lines every 2s on any cluster advertising a PD
  prefix.
  Fix carries the absolute expiry instead: `DelegatedPrefixesForRA`
  now returns the granted lifetimes with the original `Obtained`
  (prune/skip of expired entries unchanged); `DelegatedPrefix` gains
  `PreferredExpiresAt()` beside `ExpiresAt()`; `buildRAConfigs` stamps
  `RAPrefix.ValidExpiresAt`/`PreferredExpiresAt` (Unix-nano,
  Obtained+granted) plus the granted lifetimes with `PreferredLifeSet`
  (an already-expired valid lifetime is still skipped at build time).
  `pkg/ra` `buildRA` computes the remaining lifetime at send time from
  the expiry under `timeNowForRA`: whole seconds, never more than
  remains (RFC 9096 L-15), preferred 0 past its expiry, PIO omitted past
  valid expiry; prefixes without an expiry (operator, infinite,
  zero-obtained/legacy) keep the granted/default path verbatim.
  `configEqual` and the cluster `sortRAPrefixes` total order compare the
  expiries, so time advancing is a no-op and a renewal moving the expiry
  restarts the sender. Golden compile fixture regenerated (the two new
  zero fields on operator prefixes).
  NOT changed: `RemainingLifetimes` decay semantics and its callers
  outside the RA desired set; the sender startup/restart machinery;
  operator-prefix lifetime defaults.

- **Validation**: RED-on-master semantics: the new daemon hash test
  builds the desired set at five 2s-apart fake-clock instants and
  requires one `raDesiredHash`; pre-fix the decayed lifetimes differ
  every pass. New `pkg/ra` send-time cells pin remaining 7200->7140,
  preferred-expired 3200/0, and PIO omitted at/past valid expiry, with
  no-expiry controls byte-identical. `configEqual` expiry-identity cells
  pin renewal-restarts vs decay-no-restart. Existing 6531/14606/14598
  daemon cells updated only where they asserted the old decayed
  producer shape (decay is now asserted at the wire). Targeted
  `pkg/daemon`, `pkg/ra`, `pkg/dhcp`, `pkg/config` golden tests run by
  the parent; full suites are the parent's gate.
- **Risk**: A running sender whose prefix expires validly between the
  last `DelegatedPrefixesForRA` prune and the next RA now omits the PIO
  at send time instead of advertising the last decayed value; the next
  reconcile/build (prune + recompile hook) removes the prefix from the
  desired set as before. Clock steps move the computed remaining
  lifetime with the wall clock, matching the pre-fix decay clock.
