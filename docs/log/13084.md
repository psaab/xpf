# Issue #13084: Gate IPv6 WireGuard classification on declared payload

- **Finding**: D6-08. `parse_ipv6` parses L4 against the capture bound to
  preserve verifier state, then checks only `payload_offset > declared_end`.
  For IPv6 `payload_len == 8`, the UDP header is valid but has no payload;
  `payload_offset == declared_end` passes while the 9-byte UDP read can take
  byte 8 from Ethernet padding. A pad byte equal to WireGuard type 4 could
  incorrectly claim the packet for worker decapsulation instead of retaining
  kernel handling of a zero-length UDP datagram.
- **Change**: Added a core-only declared-payload predicate and applied it only
  to `parse_ipv6`'s WireGuard transport-data claim. The capture-bound L4 read,
  parsed ports, and packet behavior remain unchanged; the claim clears unless
  the IPv6 declared end covers the first UDP payload byte. Added a host test
  for the 62-byte declared Ethernet/IPv6/UDP frame padded to the 64-byte
  Ethernet minimum, plus a parser-callsite pin.
