# 16813 — BFD default-valued lines (and the OSPFv3 profile-only line) are a perpetual `frr-reload.py --test` diff, so the #15203 benign-reload re-check can never certify convergence

## Summary

The #15203 re-check certifies a benign primary `--reload` failure only
when `frr-reload.py --test` shows an empty diff. Two renders made that
impossible on any box with a BFD-timed IGP interface at FRR-default
timers (or any OSPFv3 BFD profile):

- `bfdSection.render()` emitted `detect-multiplier`,
  `receive-interval`, and `transmit-interval` for every profile and
  BGP peer, substituting FRR defaults (3 / 300 / 300) for unset
  values. bfdd is northbound/YANG-backed: `frr-bfdd.yang` declares
  `detection-multiplier` default 3 and the interval leaves default
  300000us, and a leaf set to its YANG default is elided from
  `show running-config`. Every `--test` therefore listed those lines
  as "Lines To Add" forever.
- The OSPFv3 interface loop rendered only
  ` ipv6 ospf6 bfd profile <name>`. ospf6d's
  `ospf6_bfd_write_config` always prints the bare
  ` ipv6 ospf6 bfd` enable line first and the profile line second, so
  every `--test` listed `no ipv6 ospf6 bfd` as a deletion.

On the routine IS-IS-interface removal #15203 was filed for, the
primary reload failed benignly, the re-check still saw a diff, the
additive `vtysh -f` ran, and `applyFRRFull` failed the commit with
`ErrFRRReloadDegraded` ("did not fully converge") on a converged end
state.

## Live verification (FRR 10.7.1, this host)

Isolated netns + pathspace (`zebra mgmtd bfdd ospfd ospf6d isisd`,
dummy interface), daemons loaded via `vtysh -f` with the pre-fix
render (profile/peer at 300/3 plus the OSPFv3 profile-only line):

- `show running-config` held `profile xpf-300-3` and
  `peer 192.0.2.1` with NO timer lines, and the interface held both
  ` ipv6 ospf6 bfd` and ` ipv6 ospf6 bfd profile xpf-300-3`.
- `frr-reload.py --test` against the identical file listed all six
  default timer lines under "Lines To Add" and
  `interface dum0 / no ipv6 ospf6 bfd` under "Lines To Delete".
- With the post-fix render (bare default profile/peer, OSPFv3 pair),
  `--test` showed no BFD/interface diff at all (only the probe's
  unrelated hostname line, an artifact of the host name baked into
  the isolated instance).
- Controls: a 500/4 profile keeps all three lines in running-config;
  a mixed 500/3 profile keeps only the two interval lines; a peer at
  interval 100 / default multiplier keeps only the interval lines.
  Per-line elision (not whole-stanza) is therefore required, and an
  omitted-but-default leaf still yields the authored session timers
  because bfdd applies the same defaults.

## Fix

- `pkg/frr/bfd.go`: new `renderBFDTimers16813` emits each timer line
  only when its (default-substituted) value differs from the FRR
  default (multiplier 3, interval 300). Used for both profile and
  peer stanzas; an all-default stanza is the bare header. Profile
  naming (`xpf-<interval>-<multiplier>`, `bfdProfileName`) is
  unchanged, so bindings and dedup are byte-identical.
- `pkg/frr/protocols_render_ospfv3.go`: the profile branch now emits
  ` ipv6 ospf6 bfd` immediately before
  ` ipv6 ospf6 bfd profile <name>`, mirroring
  `ospf6_bfd_write_config` (and the #15015 OSPFv2/IS-IS shape). The
  command remains single and self-enabling in FRR; this only matches
  the running-config form so `--test` is stable. Bare-BFD branch
  unchanged.
- Golden corpus (`testdata/golden16125/*.golden`): regenerated; the
  only drift is removal of default-valued timer lines from five BFD
  fixtures (ospfv3-full is untouched because its BFD interface is
  bare — the profile-pair case is pinned by the new unit test).
- `pkg/frr/frr_test.go` (`TestGenerateProtocols_BGPBFD`): the peer at
  interval 100 with unset multiplier no longer expects a
  `detect-multiplier 3` line; asserts its absence instead.

No change to `reloadTestHasDiff15203` / the #15203 certification
logic: the re-check stays fail-closed (any remaining diff still
degrades), it can now simply reach an empty diff.

## Risk

Rendered `frr.conf` loses only lines FRR itself never stores; BFD
session timers are unchanged because bfdd applies the identical
defaults (profile lookup by name is untouched, and a profile that
exists with default leaves applies 300/3 exactly as before). A commit
that changes timers from a non-default value back to the default now
renders fewer lines, and `frr-reload.py` deletes the old non-default
lines from running-config as before — the deletion direction was
already diff-stable. The OSPFv3 interface gains the bare enable line
FRR already held in running-config, so no session is recreated beyond
the reload's normal interface re-apply.
