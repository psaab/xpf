# Issue #15267 — synced deterministic-v4 imports admitted out-of-block tuples (B10-03)

- **Timestamp**: 2026-10-19
  - **Action**: Closed the B10-03 HA synced-import domain gap. The NAT64
    twin (`reserve_synced_nat64_port_unless_peer_owns` in `nat64.rs`)
    already requires `deterministic_v6_tuple_matches` before booking a
    synced deterministic reservation, but the v4 source-NAT arms in
    `nat/source/synced.rs::reserve_synced_on_first_pool_owner` passed
    only `rule.deterministic_v4.is_some()` as a tag to
    `reserve_flow_maybe_persistent` — `deterministic_v4_tuple_matches`
    (and the `deterministic_tuple_matches` wrapper) had no production
    caller. A synced deterministic-v4 (CGNAT mode 1) import whose
    translated `(pool address, port)` lay outside the subscriber's
    deterministic block was therefore booked on the standby while the
    nodes disagreed on the deterministic map (config-sync window, or a
    peer bug); once configs converge the active's port is in-block
    under the shared map, so no legitimate import changes behaviour.
    Both synced v4 arms now check the domain before reserving and
    return `Refused` otherwise (`may_publish() == false`, counted as
    `RejectedReserve`): the port-bearing arm requires the full
    `deterministic_v4_tuple_matches(det, src, pool_addresses_v4,
    addr_index, translated, port)`; the address-only arm (the wire
    preserves the source port, so there is no translated port to
    check) requires the address half only — `deterministic_indices_v4`
    must assign exactly the translated pool address. Non-V4 sources
    cannot satisfy a V4 deterministic map and refuse. Placement is
    after `saw_candidate` is set (mirroring the pool-failure arm), so
    PASS 2 degrades to `Refused` rather than leaking the tuple into
    the interface domain, and PASS 1 stops at the first owner as
    before. Regression coverage in
    `userspace-dp/src/nat/tests_synced_det_v4_15267.rs`: three
    fail-on-revert cells (out-of-block port, wrong pool address on the
    port-bearing arm via PASS 2; wrong pool address on the
    address-only arm via PASS 1) plus two in-domain controls
    (in-block port reserved; address-only on the subscriber's address
    reserves its token). RED on `origin/master` (51c40e851f): the
    three mechanism cells fail, both controls pass; GREEN after the
    fix, with the adjacent deterministic cells
    (`synced_deterministic_reservation_recycled_5178_14625` and the
    `tests_deterministic_bib_14091` suite) still passing.
    (the expected enclosing-function name was updated to
    `reserve_flow_maybe_persistent_inner` — the shared body behind
    `reserve_flow_maybe_persistent` — with the same #7360 sync route;
    the pre-existing mismatch was present on master before this
    change). Rebased onto `origin/master` 4ddf6c68ab; the full
    `nat::` suite passes there (696 passed, 0 failed, 1 ignored,
    including the census cell).
