# #17846 — Preserve interleaved IPsec SA chunk generations

- **Timestamp**: 2026-10-25
  - **Action**: Changed the IPsec SA chunk receiver's bounded pending table to
    retain up to five incomplete generations and evict only the oldest one
    when a new generation arrives over capacity. Insertion order is tracked
    explicitly; the incoming generation is added after eviction, so it cannot
    evict its own first chunk. All assembly removals and legacy supersedes
    keep the order metadata synchronized.
  - **File(s)**: `pkg/cluster/sync_ipsec_chunk_16758.go`,
    `pkg/cluster/ipsec_sa_chunk_16758_test.go`, `docs/log/17846.md`.
  - **Validation**: RED — `go test ./pkg/cluster/ -run
    'TestIPsecSAChunkInterleavedGenerationsSurvive17846' -count=1 -v`
    failed before the fix: opening generation 106 left 1 pending assembly,
    expected 5 after evicting only generation 101. GREEN — the same test
    passed after the fix. `go test ./pkg/cluster/ -run 'IPsecSAChunk'
    -count=1 -v` passed all matching cells; `go vet ./pkg/cluster/` passed.
  - **Risk**: Pending state remains bounded at five assemblies. A new
    generation can still evict an incomplete oldest generation by design,
    but no longer discards unrelated newer interleaved assemblies.
