## Why

The #7717 egress matcher deliberately over-approximates to avoid missed
warnings. Reusing it for forwarding registration could put management, HA,
fabric, loopback, ifindex-zero, and unzoned addresses into `interface_nat_v*`
and RST suppression. Bare physical interface names could also select a
different logical unit than runtime `scope_matches`. The unzoned registration
disarmed the #5659 fail-closed host-inbound sentinel.

The independent review also found that `compileNAT` rejects the three
non-zone to-side scope rows before either builder can run. That defect is
tracked separately as #12525 and is intentionally not changed here; this PR
is re-scoped to **Refs #12085**, not a claim that those rows can currently be
applied.

## Change

Forwarding registration now requires positive ifindex, an enabled, zoned
interface, and excludes the fxp/em/fab/lo0 lifeline classes while retaining
tunnels. `to-interface` uses the full logical unit name exactly; routing
instance and egress-zone scopes are conjunctive, with empty fields as
wildcards. Go and Rust build candidate addresses once per interface, index
them under the distinct exact/wildcard scope tuples, and skip duplicate rule
scopes instead of copying snapshots and reparsing addresses for every
rule/interface pair. The #7717 detection matcher remains unchanged and
detection-only.

The #5837 config mirror applies the same config-visible eligibility guards,
including exact logical-name matching and leaving unzoned units out. It cannot
observe live ifindex, which remains a dataplane gate. The shared Go/Rust matrix
covers lifelines, ifindex-zero lo0, unzoned interfaces, tunnel retention,
bare-name mismatch, off rules, and non-matching scopes. Rust tests exercise
the `off` guard, exact-name behavior, the installed forwarding map, and the
#5659 sentinel. The builder and design docs clarify that interface-NAT map
membership takes precedence even if kernel enumeration later adds an address
to `userspace_local_v*`.

The #3182 ownership comment again states why using `local_v*` alone could
leave the router's own SNAT/WAN address poisonable.

## Residual

The non-zone source-NAT rows remain unappliable until #12525 fixes `compileNAT`.
The address-keyed interface-NAT map does not encode routing instance, so
identical addresses used in multiple VRFs remain a pre-existing scope hazard.
The lab ICMP frag-needed capture was not run. Registration changes the
interface-NAT/RST set, so incorrectly classifying a lifeline could suppress
kernel RSTs or disrupt degraded/XSK-failure delivery; this patch explicitly
excludes the named lifelines and keeps the unzoned #5659 sentinel armed.
