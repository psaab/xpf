## Why

Interface-mode SNAT translates onto its egress interface address. The config
matrix and Rust `scope_matches` treat each unset to-side scope as a wildcard;
`to-zone`, `to-interface`, `to-routing-instance`, and unscoped rules can all
select egress addresses. The Go exclusion builder and Rust twin instead only
collected `ToZone`/`to_zone`. For the other three matrix rows, the egress
address stayed in local delivery and was absent from the interface-NAT address
registry, so a session-miss ICMP error could reach the kernel before the
helper's embedded-ICMP reverse-NAT path.

## Change

The Go builder now applies the existing snapshot egress-scope matcher to every
live interface-mode source-NAT rule, using the same AND-of-non-empty-scopes and
empty-wildcard semantics as the config derivation. Its resulting IPv4/IPv6 set
continues to drive both LOCAL removal and interface-NAT entries. The Rust twin
mirrors the same interface / routing-instance / zone comparisons, including
bare-interface matching and unscoped interfaces. The `to-interface` Rust probe
builds forwarding state and verifies that the egress address is in
`interface_nat_v4`, not `local_v4`.

The Go and Rust tests both consume `userspace-dp/tests/fixtures/nat_iface_scope_12085.json`.
Its four rows assert exact IPv4/IPv6 address sets for to-zone, to-interface,
to-routing-instance, and unscoped rules; the unscoped vector also includes an
interface with no zone. The config derivation comment and Rust ownership notes
now describe the full matrix rather than a zone-only exclusion.
