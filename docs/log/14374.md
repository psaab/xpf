# Issue #14374 — [DR4-H2] Reverse-NAT match returns first candidate; shared-egress overlapping tenants indistinguishable

- **Issue:** `find_forward_nat_match_expiry` and `find_forward_nat_match_inner` in `userspace-dp/src/session/lookup.rs` returned the first reverse-index candidate passing tuple + egress-domain checks. The reverse index is domain-agnostic (`reverse_wire_key` zeroes `routing_domain`); the only tenant check is the forward egress-interface domain. Two tenants (domains A/B) with identical tuples egressing through the SAME shared uplink (domain W) are therefore indistinguishable — the first candidate won and `install_reverse_session_from_forward_match` durably minted a reverse session from the wrong tenant's decision.
- **Fix (both matchers):** track the first passing candidate; a second passing candidate with a different forward key **in a different routing domain** returns no match (`None` / `ForwardNatExpiryProbe::Absent`) and bumps the new process-global `NAT_REVERSE_AMBIGUOUS_TOTAL` counter (surfaced as `xpf_userspace_nat_reverse_ambiguous_total` through Rust `ProcessStatus` → Go `ProcessStatus` → Prometheus, following the `embedded_error_per_session_suppressed_total` pattern). Same-key duplicate handles are not ambiguity. Cross-domain scoping preserves the established same-domain 1:N first-wins behavior (`nat_reverse_1n_collision_preserves_displaced_return_path`, interface-SNAT distinct-source collisions in one domain) — DR4-H3 owns the same-domain quote-matcher sibling, out of scope here.
- **Tests:** `shared_egress_overlapping_tenants_are_ambiguous_14374` (both matchers fail closed + counter increments) and `shared_egress_single_candidate_control_still_matches_14374` in `reverse_egress_domain_11298_tests.rs`; existing asymmetric-egress demux test unchanged and green. Go census in `TestEmitUserspaceDynamicBufferMetrics` re-anchored 108→109 with the new series asserted (value 71).
