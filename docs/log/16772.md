# Issue #16772: `resolveSyslogSource` warns when the source-interface is empty (R3-A47-03)

## Why

`resolveSyslogSource` (`pkg/config/syslog_source.go`) trimmed the
source-interface but had no early return for `""`. `net.InterfaceByName("")`
fails, so an IP-literal collector reached the #15078 WARN
("leaving the syslog source unbound"). The daemon fingerprint helpers
call the resolver unconditionally — `syslogClientFingerprint`
(`rsi=` per stream, daemon_system.go) and
`syslogStreamFingerprint15231` (`rsi=` and `gsrc=` terms) — so every
default-shaped stream (no per-stream or global `source-interface`)
logged a false audit-loss WARN on every apply, and twice more per
rebuild. The warning is forwarded to `system syslog host` collectors
and makes the genuine #15078 IPv6 audit-loss warning (a configured
interface with no address of the collector's family) indistinguishable
by message. The actual bind was always correct: the build arms guard
`!= ""`.

## What

- `pkg/config/syslog_source.go`: `resolveSyslogSource` returns `""`
  silently when the trimmed source-interface is empty. The #15078 WARN
  now fires only for a configured interface with no address of the
  collector's family. Fixing at the shared resolver (rather than only
  guarding the fingerprint callers) covers every present and future
  unconditional caller, including the whitespace-only shape the
  existing trim already normalises. Return value is unchanged (`""`
  already meant unbound).
- `pkg/logging/README.md`: note the empty-interface silent-unbound rule
  on the #15078 source-resolution bullet.
- Tests: `pkg/config/syslog_source_empty_warn_16772_test.go` (empty /
  whitespace / hostname defect cells capture 0 WARNs; configured
  v4-only→IPv6-collector, v6-only→IPv4-collector, and nonexistent-iface
  positive controls capture exactly 1 WARN each),
  `pkg/daemon/syslog_empty_source_warn_16772_test.go` (real
  `applySyslogConfig` on a default-shaped IPv6 stream captures 0 WARNs
  and binds unbound; direct fingerprint probe also 0; configured
  v4-only source-interface with IPv6 collector still warns through the
  apply path).

## Validation

- RED (pre-fix, fix stashed via file revert): config and daemon 16772
  tests fail capturing the #15078 WARN for empty source-interface.
- GREEN: `go test ./pkg/config/ -run '16772|15078|Syslog'`,
  `go test ./pkg/daemon/ -run '16772|15078|Syslog'` — pass, including
  #15078/#6942/#6875 neighbours. `go vet` on both packages clean;
  `gofmt -l` empty.

## Risk

Neighbours preserved: configured-interface resolution, family
filtering, kernel fallback, and the genuine #15078 WARN are byte-for-
byte unchanged; the only delta is silence for the unconfigured case,
whose return value (`""`, unbound) is identical. No fail-open change:
an empty source-interface never bound a source before either.
Residual: unrelated unconditional resolver callers with a non-empty
but unresolvable interface still warn per call (by design — that is
the genuine #15078 signal).
