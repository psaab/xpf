# Issue #15265: FRR VRF-name status surfaces (B08-03, B08-04)

## Why

- **B08-03:** HA routing readiness (`haRoutingRequirementsForRG`) stores
  the bare routing-instance name (`tenant`) in `haRoutingRequirement.vrf`
  and passed it verbatim to `GetBGPSummaryVRF`/`GetOSPFNeighborsVRF`/
  `GetOSPFv3NeighborsVRF`/`GetISISAdjacencyVRF`. `vrfShowCommand`
  interpolated it, asking FRR for `show bgp vrf tenant summary json` —
  a VRF that does not exist (the daemon creates `vrf-tenant`,
  `daemon_ipmon.go: "vrf-" + ri.Name`). FRR answers `{}`, and
  `parseBGPSummaryJSON` returned zero peers with no error, so the
  adjacency arm could never satisfy an instance requirement and a
  healthy transfer was refused with a misleading reason (only when the
  instance had an adjacency but no learned route).
- **B08-04:** `GetBGPSummary` (CLI `cli_show_routing.go`, REST
  `api/routing.go`, gRPC `server_routing.go`) queried only the default
  VRF (`show bgp summary json`), so a VRF-only box printed
  "No BGP peers" and tenant peers (including down ones) were invisible.

## What

- `pkg/frr/status_parse.go`: new `frrVRFName` (shared
  `diagcmd.VRFDeviceName`, prefix applied exactly once — already-prefixed
  names are not doubled) applied inside `vrfShowCommand`, so all four
  VRF status queries address `vrf-<instance>`. `GetBGPSummaryVRF` treats
  `{}`/empty/non-JSON for a configured (non-empty) instance as a status
  error (fail closed); the queried instance is stamped on returned peers.
  `parseBGPSummaryJSON` now returns a nil slice for "no usable summary"
  vs a non-nil empty slice for an explicitly peerless family, and handles
  both the flat shape and the per-VRF nested shape of
  `show bgp vrf all summary json`, stamping the new
  `BGPPeerSummary.Instance` (bare instance name, `""` for default) from
  `vrfName`/the enclosing VRF key. `GetBGPSummary` now queries
  `show bgp vrf all summary json`; exported `ParseBGPSummaryAllJSON`
  wraps the parser. `GetBGPSummaryVRF(ctx, "")` delegates to it.
- `pkg/cli/cli_show_routing.go`, `pkg/api/routing.go`,
  `pkg/grpcapi/server_routing.go`: BGP summary tables gain an
  `Instance` column (sanitized at the existing display sites).
- Existing fixtures updated to the new command spelling / prefixed VRF
  (`bgp_summary_3942_test.go`, `ha_vrf_status_test.go`, the #6468 escape
  executors in `pkg/cli`/`pkg/grpcapi`).
- `pkg/frr/README.md`: #15265 note under the #3942 JSON-summary entry.

## Risk

The global summary command changed spelling; older FRR without
`vrf all` support would return no peers on the show path (no error) —
accepted per the issue's fix direction. HA readiness now surfaces a
real status error for a missing instance instead of a misleading
"no learned route or established adjacency" reason; readiness itself
still fails closed.
