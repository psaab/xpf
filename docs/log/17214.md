# #17214 — R4-Q07-04: #16131 dual-carry interning adds seven ForwardingState fields and a re-export with no reader, guarded by an assert! whose documented failure mode is false

- **Timestamp**: 2026-10-27
- **Defect (live on origin/master 9bfb2516fd)**: `ForwardingState` carried
  seven dead dual-carry fields (`local_table_ids_v4/v6`,
  `interface_nat_table_ids_v4/v6`, `interface_nat_ids_v4/v6`,
  `route_table_interning_complete`), `forwarding_build/intern.rs`
  (~510 lines incl. tests) derived six interned maps on every build, and
  `forwarding_build/mod.rs` re-exported `route_table_dual_carry_agrees`
  with no reader outside `intern.rs`. Docs at `intern.rs:34-37` and
  `state.rs:120-123` claimed a disagreement makes the reconcile preflight
  keep the previous live state; in fact the `assert!` in
  `intern_route_tables` panics, is caught by the server unwind guard, and
  quarantines/restarts the helper. `route_table_identities` itself has
  real readers (`forwarding/fib.rs`, runtime view) and is kept.

## What

- Acceptance (a) from the issue: delete the seven fields, the production
  half of `intern.rs` (whole file — its tests only exercised the deleted
  subsystem), and the `pub(in crate::afxdp) use
  intern::route_table_dual_carry_agrees;` re-export.
- `userspace-dp/src/afxdp/types/forwarding/state.rs`: removed the six
  interned maps + `route_table_interning_complete` and their stale
  `#16131` doc paragraphs; the authoritative string forms
  (`local_tables_v[46]`, `interface_nat_v[46]`,
  `interface_nat_tables_v[46]`) and `route_table_identities` /
  `route_table_identity_map_complete` are unchanged.
- `userspace-dp/src/afxdp/forwarding_build/mod.rs`: removed `mod intern;`,
  the re-export, and the `intern::intern_route_tables(&mut state);` call
  after `build_route_table_identity_map`.
- `userspace-dp/src/afxdp/forwarding_build/intern.rs`: deleted entirely
  (548 deleted lines across the three files, 0 additions in production
  code). No packet-path code read the twins, so probe counts and lookup
  behaviour are unchanged by construction.
- Acceptance grep: `grep -rn 'local_table_ids_v4\|interface_nat_ids_v4\|route_table_interning_complete' userspace-dp/src` → 0 (also 0 for the
  v6/table-id variants, `route_table_dual_carry_agrees`, and
  `intern_route_tables`). The divergence can no longer recur: there is
  no second carry to disagree, and no `assert!`-guarded publish path in
  a deleted module.
