# Issue 17773 — keep the 50k-line commit summary under 10 MiB

## Why

`CommitDiffSummary` deep-cloned the active and candidate trees while holding the store lock, rendered each whole tree to a string, then split both strings into line slices. The 50k-line end-to-end regression measured 113,522,736 allocated bytes before the fix, despite the isolated line-diff helper passing its own 10 MiB bound.

## What changed

- Add `ConfigTree.FormatSetLines`, using the existing flat-set traversal and canonical ordering to emit individual formatted lines through one reusable byte buffer.
- Reuse equal active-side line strings at matching candidate positions, avoiding a second copy of the unchanged majority while retaining independently owned line slices for the diff.
- Render both trees under the store read lock, then release it before the unchanged order-aware sequence diff; remove the deep clones, whole formatted strings, and split-line copies from `CommitDiffSummary`.
- Add an end-to-end 50k one-line-edit allocation gate (<10 MiB, 1 added/1 removed), identical 50k control, 12k control, and line-render parity coverage for ordering, quotes, bracket groups, annotations, and UTF-8. Existing helper, reorder, duplicate, and 12k gates are unchanged.

## Reproduction and validation

On base `3c49ffd7a4`, the new regression went RED:

```text
go test ./pkg/configstore -run '^TestCommitDiffSummary17773EndToEnd50K$' -count=1
FAIL: CommitDiffSummary 50k allocated 113522736 bytes, want < 10485760
```

The final named configstore regressions passed. `CommitDiffSummary` allocated 4,808,936 bytes for the 50k one-line edit, 4,806,400 bytes for identical 50k trees, and 1,164,688 bytes for the 12k control. The pre-existing 12k end-to-end gate allocated 780,328 bytes; the isolated 50k helper still allocated 0 bytes. Formatter parity (including quoted UTF-8), the config `FormatSet` compatibility cases, reorder, duplicate-line, and baseline commit-summary cases passed; `go vet ./pkg/config ./pkg/configstore` was clean.

## Risk

The store read lock now covers formatting as well as tree access so the trees can be read without cloning; it is released before LCS work. Equal-line reuse is positional only and does not affect ordering or equality: reordered lines still flow through the existing order-aware diff unchanged.
