# Issue #12642 — pin WireGuard local-arm equality

Base: `ab6ab9f7a24e6689d335a57431aaf031fc264aed`.

## Root cause and reachable shape

`poll_descriptor/filter.rs::revalidate_static_pbr_route_on_session_hit` has two separate local-resolution equality fences. The closure-level `local_arm_unchanged` fence compares the ordered ingress-local/interface-NAT helper result to the stored `ForwardingResolution`; only a complete match with an unchanged install-table identity may return before the #12592 resolution tail. The tail independently requires its fresh interface-NAT/FIB resolution and route identity to equal the stored decision. Existing WG decap and #7212 cells did not distinguish the closure equality from M2's weaker “helper resolved, therefore pin” mutation.

The shape is reachable in production. `forwarding_build/interfaces.rs` classifies configured addresses into `interface_nat_v4/v6` when they are excluded from ordinary local delivery and records the owning connected table; this path is not restricted to physical interfaces. `forwarding/nat.rs::interface_nat_local_resolution` is table-scoped and builds `LocalDelivery` from the selected owner ifindex and its `tunnel_endpoint_by_ifindex` tag. Thus a WG/interface-NAT address can still resolve locally while its owner/endpoint/full resolution differs from the stored decision under the same route identity. The regression moves the test address owner from ifindex 12 to WG ifindex 400 (endpoint id 1) inside `blue.inet.0`, asserts the fresh helper still returns `LocalDelivery` with a different complete resolution, then drives the production revalidation helper. This exercises the divergent closure arm that must fall through to the separate tail check.

## Coverage added

`filter_revalidation_7212_tests.rs` adds two discriminators:

- `pbr_revalidation_rejects_changed_wg_local_arm_with_same_identity_12642`: local helper succeeds but its WG-local resolution differs from the stored one under unchanged `blue` identity. The closure must decline to pin; full tail revalidation returns the changed local resolution.
- `pbr_revalidation_rejects_removed_local_address_with_same_identity_12642`: the closure helper misses and the tail returns `NoRoute` despite unchanged table identity.

Existing `unchanged_ri_local_miss_arms_keep_sessions_for_v4_v6_tcp_udp_12056` is the identical-resolution positive control: stable ingress-local and interface-NAT resolutions under matching identities remain pinned.

No production behavior change was necessary. The closure equality at `filter.rs:967–968` and tail equality at `:1015–1016` already implement the required independent fences; this change makes both contractual.
