# Issue #10171 — bridge nf_tables kernel floor

## Scope and choice

Issue #10171 follows the non-blocking Rev10164 review of #9852/#7191. The
`xpf-transit-closed.service` boot command retains #7191's warn-and-proceed
behavior when inet nftables installs but the bridge family is unsupported. That
is required tolerance for foreign or trimmed kernels, but an appliance bake
must not silently ship an image whose kernel lacks the L2 fence.

This lane chooses the **bake-time kernel-floor assertion** requested by #10171,
with a live-boot mirror in image validation. The assertion checks the target
kernel configuration, not the build host: both `CONFIG_BRIDGE=(m|y)` and
`CONFIG_NF_TABLES_BRIDGE=(m|y)` must be present in the surviving target
kernel's `/boot/config-*`. The check runs after the bake's exactly-one-kernel
assert. Scenario A repeats the same predicate against `uname -r` after boot.
The production snippets have no environment override; test-only fixture seams
are opt-in and are not used by `bake.py` or `validate.py`.

The #7191 degraded-success branch is unchanged. Appliance kernels with the
Debian 14 configuration (`CONFIG_BRIDGE=m` and `CONFIG_NF_TABLES_BRIDGE=m`,
with module autoload) pass; a trimmed or foreign kernel fails the bake or live
validation gate with a `FATAL: #10171` diagnostic naming the missing symbol.

## Implementation

- `scripts/image/bridge_floor_10171.py` owns the shared offline/live shell
  snippets so bake and validation cannot drift.
- `scripts/image/bake.py` runs the offline predicate inside `virt-customize`
  after the single-kernel check and before kernel hold setup.
- `scripts/image/validate.py` runs the live predicate in scenario A and
  surfaces stderr/stdout in the validation failure.
- `scripts/image/test_bake_bridge_floor_10171.py` covers both snippets with
  appliance-like module configs, built-in (`=y`) configs, missing/trimmed
  configs, a `CONFIG_BRIDGE_NETFILTER` distractor, target-kernel discovery,
  wiring order, production no-override checks, and the real host kernel.

The behavior cells prove the floor violation is surfaced rather than silently
accepted: trimmed and missing configs return nonzero and include `FATAL`,
while appliance-like and built-in configurations return zero. The live host
cell passed against the current Debian 14 kernel configuration.
