# Issue #12595 — read repeated sampling and DHCP siblings

## Why

Three config readers used `FindChild` and silently compiled only the first repeated sibling: `forwarding-options sampling`, `family inet dhcp`, and `family inet6 dhcpv6-client`. Distinct sampling instances in a later `sampling` container disappeared; options in later DHCP client blocks were lost.

## What

- `compileForwardingOptionsWithOpts` now visits every `sampling` child, and `compileSampling` accumulates compiled instances in the shared sampling config.
- The `inet` and `inet6` interface readers now visit every corresponding DHCP client block and preserve options read from earlier blocks while compiling later ones.
- `TestRepeatedSamplingContainers12595`, `TestRepeatedDHCPBlocks12595`, and `TestRepeatedDHCPv6ClientBlocks12595` cover first and later siblings with distinct values.

## Validation

- RED before the fix: the focused regression command failed: second sampling instance `i2` was absent; the `inet` second-block retransmission-attempt and force-discover were false; and the `inet6` second-block client IA and request options were absent.
- GREEN after the fix: `go test ./pkg/config -run 'Test(RepeatedSamplingContainers|RepeatedDHCPBlocks|RepeatedDHCPv6ClientBlocks)12595' -count=1` passed.
- `go test ./pkg/config -count=1` did not pass. It reported inventory-drop, API-auth-expiry, routing-instance, and slot-escape gate failures, then timed out after 10 minutes in `TestSchemaSpellingDifferentialGate`. The output contains no failure from the new regression tests.

## Risk

Persisted repeated blocks that previously lost their later siblings will now compile their settings. For repeated DHCP scalar properties, later valid values overwrite earlier ones; distinct settings accumulate. No schema or runtime wiring changed.
