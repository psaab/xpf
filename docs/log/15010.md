# #15010 — frr: BGP prefix-limit maximum renders warning-only by default; teardown modelled

- **Timestamp**: 2026-10-18
- **Base**: `origin/master bd2081b128`
- **Mechanism**: Junos `prefix-limit { maximum N; }` without `teardown` is
  log-only (Juniper prefix-limit statement: "If the teardown statement is
  not configured, a message is logged when the number of prefixes exceeds
  the value configured for the maximum option"). xpf modelled only
  `maximum` (`pkg/config/schema_routing.go`, typed `PrefixLimitInet/Inet6`)
  and `pkg/frr/protocols_render.go:writeBGPMaximumPrefix11793` emitted a
  bare FRR `neighbor <peer> maximum-prefix N`. In FRR 10.6 bgpd
  (`bgp_route.c:bgp_maximum_prefix_overflow`), exceeding the limit in
  non-warning mode sends CEASE/max-prefix, sets
  `PEER_STATUS_PREFIX_OVERFLOW`, and — with no `pmax_restart` timer —
  `bgp_start` refuses with `PEER_DOWN_PFX_COUNT` until
  `clear bgp neighbor` (`peer_clear` → `peer_maximum_prefix_clear_overflow`).
  A peer one prefix over the Junos log-only limit thus went
  Idle(PfxCt) with no automatic restart; on a default-route uplink that
  is a routing outage from a log-only alarm.
- **Fix**:
  - Typed model (#15010): per-family `PrefixLimitTeardown{Inet,Inet6}`,
    `PrefixLimitTeardownPct*` (1..100), `PrefixLimitIdleTimeout*`
    (minutes 1..2400), `PrefixLimitIdleForever*` on `BGPNeighbor`
    (`pkg/config/types_routing.go`).
  - Schema: `teardown [pct] [idle-timeout (forever|minutes)]` added at
    all four sites (group+neighbor × inet+inet6, shared with
    routing-instances) with a `tailValidator`
    (`ValidateBGPPrefixLimitTeardownTail15010`) enforcing pct 1..100 and
    idle-timeout 1..2400|forever. `drop-excess`/`hide-excess` declared
    only to be rejected (see below).
  - Compiler: `parsePrefixLimitFull15010` / `applyPrefixLimitFull15010`
    (`pkg/config/compiler_bgp_prefix_limit_teardown_15010.go`) parse the
    whole prefix-limit node (maximum + teardown atomically); group scope
    stamps the full model, a neighbor prefix-limit replaces it wholesale
    (most-specific level wins), and the tolerant path warns and preserves
    the entire inherited model on a malformed override. Both group
    (`compiler_protocols.go`) and neighbor
    (`compiler_bgp_neighbor_merge_9192.go`) paths use it.
  - Renderer: `writeBGPMaximumPrefix15010`
    (`pkg/frr/protocols_render.go`) maps — no teardown:
    `maximum-prefix N warning-only`; teardown: `maximum-prefix N [pct]`;
    teardown+idle minutes: `... [pct] restart M`; teardown+forever:
    `maximum-prefix N [pct]` (FRR no-restart = manual clear). Out-of-range
    pct (>100) / restart (>65535) operands from tolerant construction are
    omitted with a warning, never passed verbatim to vtysh. The old
    maximum-only helper and its call sites are replaced (no shim).
  - `drop-excess`/`hide-excess`: **rejected** at schema/compiler (FRR
    10.6 has no equivalent — bgpd either warns or CEASEs; it cannot drop
    or hide only the excess). Accepting them silently would be the same
    fail-open class; operators use an import policy/prefix-list instead.
  - Documented divergence: Junos re-establishes a torn-down session "in
    a short time" without idle-timeout, but FRR `restart` is whole
    minutes (1..65535), so bare `teardown` maps to the no-restart shape
    (down until `clear bgp neighbor`, like `forever`). Timed
    re-establishment requires authored `idle-timeout <minutes>`.
    Recorded in `docs/config-schema.md` and the renderer comment.

- **Risk**: Behaviour change only for configs using `prefix-limit`:
  previously-hard teardown becomes Junos-correct log-only unless
  `teardown` is authored — this is the fix; an operator who relied on
  the old hard kill must add `teardown`. Neighbouring BGP rendering
  (activation, route-maps, BFD, default-originate) is untouched.
  Residual: bare-`teardown` short-re-establish divergence above;
  `accepted-prefix-limit` is a separate Junos statement and remains
  unmodelled (pre-existing, out of scope).
