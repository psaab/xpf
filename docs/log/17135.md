# #17135 — Collapse handle_stream's triplicated post-wait status attach into `attach_status_after_wait` + `enum Deferred`

- **Timestamp**: 2026-10-27
- **STEP-0**: Defect live on current `origin/master` (303ae6adfa at dispatch; re-verified after origin advanced to 855e6b6d02 — `handlers/mod.rs` unchanged there, the three settle handlers changed by #17126 in a way documented under Risk). `grep -c 'quarantined_after_panic' userspace-dp/src/server/handlers/mod.rs` gave 5: the initial refusal (L358), the three byte-identical relock/quarantine/refresh/attach blocks after the settle wait, the owner-RG export and the all-sessions export (L640/667/685), and the delta-loss arm (L738). The in-lock attach was gated by a hand-kept boolean over three of the four deferred `Option`s (`export_wait`, `all_export`, `settle_wait`; `counter_query_wait` excluded).

## Action

- Added `fn attach_status_after_wait(state, running, response)` in `userspace-dp/src/server/handlers/mod.rs`: relock via `lock_server_state_recover`, on `quarantined_after_panic` store `running=false` and attach nothing, otherwise `refresh_status` + `response.status = Some(guard.status.clone())`. All three post-wait blocks now call it.
- Added `enum Deferred { Settle(Duration), OwnerRgExport(OwnerRgExportWait), AllSessionsExport(AllSessionsExport), CounterQuery(SessionCounterQueryWait) }` with `status_after_wait()` (`true` for Settle/OwnerRgExport/AllSessionsExport, `false` for CounterQuery). The four `Option<…>` locals collapse to one `Option<Deferred>`; the in-lock predicate is now `deferred.as_ref().is_none_or(|d| !d.status_after_wait()) && !suppress_status` — one call instead of the hand-kept boolean.
- The off-lock tail is a single `match deferred`: Settle → `wait_for_binding_settle` + attach; CounterQuery → `session_counters::collect` (status already attached in-lock; its only production sender, Go `QuerySessionCounters`, sets `SuppressStatus: true`, so the asymmetry is latent — preserved, not "fixed"); OwnerRgExport → `owner_rg_collect` + attach; AllSessionsExport → `all_push` + attach. Waits stay off-lock and unmerged (payloads differ, #2962/#4054/#5862/#7919); arm order (settle, counter, owner-RG, all-sessions) preserved; at most one variant is ever set (one verb per request).
- `forwarding::set` / `binding::set` / `queue::set` now take `deferred: &mut Option<Deferred>`; on the merged tree they delegate their reconcile/settle/persist tail to #17126's `finish_binding_reconcile`, whose settle slot was retargeted from `&mut Option<Duration>` to `&mut Option<Deferred>` (recording `Deferred::Settle(Duration::from_secs(2))` on success only). `Deferred` is `pub(crate)` so `helpers::status` can name it. Settle rules re-verified on the merged tree: forwarding settles only when arming (`settle=forwarding_req.armed`), binding/queue settle only on registration change (the helper is reached only inside that branch, `settle=true`), and a reconcile error returns before any settle/persist.
- New hermetic cells in `mod deferred_17135_tests` (same file): `attach_status_after_wait_attaches_refreshed_status_17135` (healthy: status attached with refreshed pid, `running` stays true), `attach_status_after_wait_quarantined_yields_no_status_17135` (quarantined: no status, `running` cleared), `deferred_status_after_wait_classifies_each_variant_17135` (all four variants pinned via real kicks on an empty coordinator: Settle/OwnerRgExport/AllSessionsExport -> true, CounterQuery -> false — the load-bearing direction, since CounterQuery alone attaches in-lock).
