# Issue #13214 — three-color policer lenient compilation

## Finding

Deep-review finding D3-08 identified that `compileFirewall` read raw children
from three-color policer `single-rate` and `two-rate` blocks. Legacy flat-set
runs nest later leaf statements beneath the first leaf; the compiler therefore
lost the required burst/rate values, and `CompileConfigLenient` failed its
three-color policer completeness check. It also used only the first
`policer if-exceeding` block, dropping values from sibling blocks. These shapes
can reach the tolerant path from persisted or peer-synced configuration.

## Fix

Compile all sibling `if-exceeding` blocks and expand flat runs in single-rate
and two-rate containers using their schema definitions before reading leaves.
Existing last-authored-value behavior remains intact.
