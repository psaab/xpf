# Issue #14209 — prepareSnapshotForApply revalidates Interfaces without rebuilding derived sections

## Why

`prepareSnapshotForApply` (pkg/dataplane/userspace/apply_snapshot_identity_9520.go) cloned and revalidated only `snap.Interfaces` via `revalidateSnapshotIfindexes` (#11086): a link recreated between snapshot build and apply got a fresh ifindex (or was dropped), but `TunnelEndpoints`, `MirrorConfigs`/`MirrorExclusions`, `Routes` and `Fabrics` — all built from the OLD interface rows at build time — kept the stale ifindexes. Rust consumes the tunnel endpoint's own ifindex (`userspace-dp/src/afxdp/forwarding_build/tunnels.rs`), so the published snapshot carried a current ingress row joined to a stale tunnel/mirror egress: wrong join, dropped traffic, or misleading attribution. The link-event path (`RefreshInterfaceRowsForLink`, manager_link_refresh.go) already rebuilt the derived sections after revalidating; the normal apply did not.

## What

- `prepareSnapshotForApply` is now a `Manager` method. When revalidation actually refreshed or dropped a row AND the snapshot carries its `Config`, it calls the new `rebuildDerivedSectionsAfterRevalidate`, which re-derives — from the same builders the full build and the link refresh use — `Routes` (with `LearnedRouteImportCapped`), `Fabrics` (against one fresh xfrm sample, also stamping `xfrmDumpFailed`), `TunnelEndpoints`, and `MirrorConfigs`/`MirrorExclusions` against the revalidated rows, then re-applies `quarantineCollidingZones` and recomputes `ZoneSetValidated` (plus summary counts when quarantined), exactly as `RefreshInterfaceRowsForLink` does. A route-build error keeps the previously derived routes (same config; the apply is not failed over a transient kernel enumeration error).
- Routes are rebuilt with the overlay the snapshot was actually built with: new `Manager.routeOverlayForSnapshot` returns `m.routeOverlay` only when the snapshot's Config is the retained applied config; a fresh Compile build (whose builder already applied its overlay, and `m.routeOverlay` may have moved since) is rebuilt with no overlay re-application rather than a moved one.
- Fabrics use a fresh build, not the #9684 plan-preserving resample: every caller computes the binding plan key AFTER `prepareSnapshotForApply`, so a moved fabric parent ifindex moves the plan key and both planes replan together.
- All production and test call sites updated to the method form (`m.` / `h.m.`). No Rust changes; no wire changes.

Regression tests in `snapshot_derived_revalidate_14209_test.go`:
- `TestPrepareSnapshotForApplyRebuildsDerivedIfindexes14209` — recreated ingress (17→29) and vanished interface (18): mirror follows to 29, vanished mirror excluded and recorded, vanished connected route gone.
- `TestPrepareSnapshotForApplyRebuildsTunnelIfindex14209` — recreated tunnel netdev (42→77): endpoint ifindex rebuilt to 77.

## Validation

- RED on pristine origin/master (separate base worktree, test file adapted only to the base free-function spelling): both tests fail — `mirror configs = [{17 19} {18 19}], want one mirror 29 -> 19`; `tunnel endpoints ... Ifindex:42, want endpoint ifindex rebuilt to 77`.
- GREEN with the fix: both tests pass, plus `TestRevalidateSnapshotIfindexes11086` / logical-only revalidation tests.
- Full `pkg/dataplane/userspace` run: failures are pre-existing on base (verified on the base worktree: `TestSecureTunnelGate*` #14139 PSK gate, unix-socket `bind: invalid argument` under the shared GOTMPDIR, `TestPartialRepublishRefusesQuarantineOnlySkew12247`, `TestRouteOverlayRepublishRefreshesTunnelLiveness11423` — all fail identically on origin/master without this change).
- Targeted affected suites (`TestInterfaceLinkRefresh*`, overlay/scheduler/worker-arm/sync/apply families) pass except the base-attributed failures above.

## Risk

The rebuild runs only when revalidation moved a row (link churn between build and apply) and the snapshot has a Config, so the common apply path is unchanged. It performs the same kernel sampling the builders already do (route enumeration, fabric peer resolution, one xfrm dump) under `m.mu`, bounded like the existing apply-time sampling. Snapshots with `Config == nil` (hand-built, tests) keep their authored derived rows. No fail-open direction: dropped interfaces lose their derived rows; quarantined zones stay quarantined.
