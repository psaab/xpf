# Issue #12879 — fail-closed reauthorization under the captured identity

## Root cause

`reauthorizePolicyCandidates` discharged a rollback deletion candidate whenever
`policymatch.Match(restored, query).Action == PolicyPermit`, without requiring
that the verdict be issued by the candidate's captured identity
(`pkg/daemon/daemon_policy_invalidate_capture.go`). Three fail-open directions:

- **Unmatched `junos-host` sessions.** For a `to-zone junos-host` query that no
  host policy matches, the matcher returns `HostInboundUnmatched` with
  `Matched=false`, `DefaultUsed=false`, and `Action` unset — the zero value,
  which IS `PolicyPermit` — so the raw Action test read "not governed by any
  policy" as a permit and discharged the debt.
- **Cross-rule matches.** The restored config still holds the captured key as a
  permit policy that no longer matches the tuple, but a sibling rule (or a
  scheduler-reordered winner) permits it: another rule's permit was accepted as
  authorization under the old identity, without rebinding the session's policy
  ID/counter.
- **Default-policy substitute.** With `default-policy permit-all` restored, the
  implicit default's permit discharged candidates captured under a named rule
  (and a concrete rule's permit discharged default-policy candidates).

The rename path (`permittedRenameResult`) already required
`Matched && Action == PolicyPermit && RuleID != ""`; the reauthorization
verdict lacked the same discipline.

## What changed

- `isPermitted` inside `reauthorizePolicyCandidates`
  (`pkg/daemon/daemon_policy_invalidate_capture.go`) now requires the verdict's
  identity:
  - a named captured key is discharged only by `result.Matched &&
    result.RuleID == key && result.Action == PolicyPermit`;
  - a `DefaultPolicyName` (sentinel-attributed orphan) candidate is discharged
    only by `result.DefaultUsed && result.Action == PolicyPermit` — the
    restored default-policy's own verdict, never a concrete rule's.
- Unknown provenance, zone-ID collisions, malformed tuples, and
  `preserveDefaultRematch` handling are unchanged and stay fail-closed.
- Migrated ten rollback fixtures (#12323/#12532/#12780 suites) that seeded
  sessions under one rule of a catch-all `application any` stanza: their
  discharge had been granted by the first-match sibling, i.e. by the very
  fail-open this fix removes. The fixtures now use the #12686 per-rule
  application variants (distinct ports per rule) so each session's recorded
  provenance and the restored config's first-match agree; every test's pinned
  property (convergence, over-/under-deletion bounds, debt re-owing, zone-ID
  collision refusal, non-aliasing) is unchanged.

## Validation

- New `pkg/daemon/policy_reauth_identity_12879_test.go`:
  - unit table with all fail-open arms RED on pristine master
    (`cross_rule_permit_keeps_candidate`,
    `default_policy_substitute_keeps_candidate`,
    `host_unmatched_zero_action_keeps_candidate`,
    `default_key_cross_rule_keeps_candidate`) plus positive pins proving the
    captured identity still discharges (named transit, named host rule,
    default-key default verdict);
  - a matcher-premise test pinning that an unmatched host query's `Action` is
    the meaningless zero value;
  - two end-to-end rollback regressions (`executeConfirmedRollback` flow):
    cross-rule permit and default-policy permit must leave the widened-rule
    tcp/80 session as deletion debt while the tcp/22 session still discharges.
    Both were RED on pristine master, GREEN after the fix.
- The ten migrated fixtures were verified GREEN on pristine master before the
  migration (i.e. they fail only through the removed fail-open, not for any
  pre-existing reason).
- `go test ./pkg/daemon/ -count=1` — passed.
- `go test ./pkg/policymatch/ ./pkg/dataplane/userspace/ -count=1` — passed.
- `go vet ./pkg/daemon` and `gofmt` on the changed files — clean.

## Risk

Narrower discharge set only: candidates the restored config permits through a
different identity than the one that admitted them now stay deletion debt and
are deleted when the rollback target lands (the flow can re-establish under
the new authority). The positive paths — restored rule with the same key
matching the tuple, and the restored default-policy for sentinel orphans —
are covered by pins and the existing #12532/#12686/#12880 suites.
