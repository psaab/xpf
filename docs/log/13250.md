# #13250 - Remove dead authz helpers and fall-through guidance

- **Timestamp**: 2026-10-15
- **Action**: Removed unused `Principal.Resolved` and `UsernameForUID` APIs,
  deleted tests that only exercised the dead helper, and migrated REST tests
  to the canonical `pkg/osident` resolver. Updated authz comments to state
  explicitly that a peer UID without a configured class is terminal and must
  not fall through to api-auth credentials. Added source and authorization
  regression coverage for the removal and fail-closed rule.
- **Validation**: The regression failed on pristine `origin/master` because
  it detected the obsolete method, fall-through guidance, and helper; it
  passes on the fix. `gofmt -l` reported no files; `go vet ./pkg/authz
  ./pkg/api ./pkg/grpcapi`, `go build ./...`, and `go test ./pkg/authz
  -count=1` pass. `go test ./pkg/api -skip
  '^TestVRFOverlapAdmittedEmittedWhenDataplaneUnloaded_7991$' -count=1`
  passes. In `go test ./pkg/authz ./pkg/api ./pkg/grpcapi -count=1`, authz
  and grpcapi passed; API failed only the excluded test, which fails
  unchanged on pristine `origin/master` with duplicate metric samples.
- **Risk**: No intended runtime behavior change. Removing exported helpers is
  source-incompatible for out-of-repository callers; repository callers were
  migrated to the shared resolver or direct principal properties.
