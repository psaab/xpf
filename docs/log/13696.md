# Issue #13696: reject zero-checksum IPv6 UDP first fragments

A real first IPv6 UDP fragment with checksum `0x0000` is invalid under RFC
8200 §8.1. Unlike a complete UDP datagram, a first fragment cannot have its
checksum recomputed because the remainder is absent. `write_v6_to_v4_translate`
previously treated the zero field as an incremental-checksum baseline and
emitted an IPv4 fragment with a meaningless adjusted checksum.

The translator now rejects this case before writing to the caller's output
buffer, mirroring the existing v4-to-v6 zero-checksum fragment guard. The
v6-to-v4 fragment-drop predicate and output-length preflight classify the same
packets as drops. Complete atomic fragments retain the full-recompute path;
nonzero UDP checksums and TCP fragments continue to use incremental adjustment.

Regression coverage verifies the failure on pristine master, rejection through
the allocating and caller-buffer APIs, no partial output writes, drop
attribution and output-length parity, atomic-datagram recomputation, valid UDP
checksums including the computed-zero `0xFFFF` representation, TCP checksum
parity, and the existing v4-to-v6 guarded twin.

## Risk

Illegal real first-fragment IPv6 UDP packets with checksum zero are now dropped
instead of translated. Atomic fragments contain the full datagram and are
recomputed; valid UDP and TCP fragment behavior is unchanged.
