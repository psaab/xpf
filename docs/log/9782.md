# #9782 — post-NAT port enforcement clobbered every PAT translation

## Symptom

Pool-mode source NAT never completed a connection on the loss userspace
cluster while interface SNAT on the same path worked. Discriminator (issue):
interface 3/3 CONNECT-OK, pool 3/3 CONNECT-FAILED (client-side `In:` leg
only, SYN retransmits), pool+persistent 3/3 FAILED with the binding minted.

## Diagnosis (STEP-0/1/2 + master discriminator, all lock-celled)

- Reproduced on master (9c5c610cb, then 18f5f9a78 after #10032 merged):
  interface 3/3 OK, pool 3/3 FAILED, pool+persistent fails with binding.
- Forward sessions store in-range PAT (`.7:30000+`, cursor advancing);
  the wire carries the PRESERVED client port (server replies to
  `.7:<client-port>`, denied as new flows `wan->wan default-policy`).
  State-vs-wire split, deterministic, first SYN already split.
- Interface-PAT collider fails identically (second flow PAT'd, replies
  misdelivered into the first flow's preserved session, zero denies):
  the bug is port-rewrite-general, not pool-specific. Preserving flows work.
- Proxy-ARP healthy on primary; sfmix egress = background rate; standby
  stale parent-dev proxy entry is a wart, not the cause (denies land on
  the primary). tcpdump-on-FW is blind (XDP bypass); client pcaps +
  deny records + sessions were the instruments. fw0 clock lags ~127s.

## Root cause

`enforce_expected_ports` repairs DMA-race-torn arrival bytes against the
PRE-NAT expected tuple (`authoritative_forward_ports` prefers the session
flow tuple). In the generic (`rewrite_apply_v4/v6`), copy
(`build/ipv4|v6.rs`) and TCP-segmentation (both twins, both AF arms) TX
paths it ran AFTER `apply_nat_*`, overwriting just-written PAT/DNAT port
translations with the original ports — with an incremental checksum repair,
so packets were valid-checksum but unmatchable by the reverse index
(keyed on the translated tuple). The descriptor fast path was already
correct (pre-NAT validate-only decline). Preserve flows no-op under
enforce (equal), which is why only port-changing flows broke. Pure SYNs
are never flow-cached, so every retransmit took the clobbering path.

## Fix

Repair-then-translate: enforce moved BEFORE apply_nat at all 8 sites
(immediately before `if apply_nat`, after all `None` gates — preflight
contract preserved), plus:
- `post_nat_expected_ports` helper + 3 debug-log dispatch checks made
  NAT-aware (fabric gate honored, None/fallback/layer semantics defined);
- stale contract comments updated (#4041 set, P-N3/P-T4 prop notes);
- prop-test P-T4 + twin migrated to pre-NAT expected inputs.
Same reorder fixes DNAT port-changing flows and every reverse leg.
No new derivation, no perf change (identical call counts, reordered).

Reviews: MEDIUM tier, brief + 2 rounds (Astra NEEDS-MAJOR→NEEDS-MAJOR,
GLM NEEDS-MINOR→NEEDS-MINOR — same two residuals, severity split),
parent ruled PROCEED folding F1 (fabric gate) + F2 (debug-log dispatch
tests) + all nits, no r3. Raw reviews in docs/pr/9782/reviews/ (never
committed). GLM's r2 session overwrote round2-astra.md; Astra bytes were
restored verbatim from its session transcript (provenance noted there).
