# #15181 — Kernel self-recovery re-fires on stale expired leases (C11-01)

- **Timestamp**: 2026-10-19
- **Action**: Kernel self-recovery treated ANY expired lease naming this
  node as a crashed-roll fingerprint, with no age bound, and never removed
  the lease after acting. A lease left by a crashed or transport-lost roll
  persisted on `/var/lib/xpf`, and about 2 minutes (30s settle + 30s tick +
  90s grace) after every later ForceSecondary (ISSU) or rolling drain of
  that node it ran `ResetAllFailover` against the operator's intent — a
  drained node re-entered election and, with preempt, could reclaim
  primary during a maintenance window.
  Fixed on all three legs the issue names:
  - **Drain-start gate**: `Tick` now requires the expired lease to
    postdate the current drain. The orchestrator acquires the lease
    before draining, so a crashed roll that caused this drain wrote a
    lease expiring after the drain began
    (`ExpiresAt > earliest ManualFailoverAt`). A lease that already
    expired before the drain began belongs to an earlier, unrelated roll
    and no longer authorizes recovery; an unknown drain start (zero)
    fails closed. New surface: `Manager.LocalDrainedSince()` in
    `pkg/cluster` (earliest `ManualFailoverAt` over the drained RGs,
    zero when not fully drained or any start is unknown), exposed through
    `SelfRecoveryCluster.LocalDrainedSince` and the daemon adapter.
  - **Consume on act**: before `ResetFailover`, `Tick` consumes exactly
    the lease that authorized recovery — removed under the orchestrator's
    `kernel-roll.lock` flock (non-blocking; contention means a live
    orchestrator is mid-mutation, so the tick does not act), and only
    when the on-disk lease still names this node with the same
    `ExpiresAt` (a successor's renewed/re-acquired lease is left
    untouched and the tick does not act). Consuming before the reset
    means a failed reset does not re-fire.
  - **PROMOTE clears the lease**: `verifyAndPromote` now calls
    `ClearRollLease` (best-effort) alongside the promotion marker, as
    REVERT/discard already did via `restoreKnownGood`; a completed roll
    no longer leaves its lease behind as a future fingerprint. The
    deploy driver's holder-guarded clear on success is unchanged.
  NOT changed: the crashed-roll recovery cell (lease postdates the drain,
  drained, healthy peer, past grace) recovers exactly as before; active /
  other-node / missing / zero-expiry leases remain no-ops; the ARMED gate
  and observation-error grace resets are untouched.
- **File(s)**: `pkg/upgrade/kernel_selfrecover.go` (drain-start gate,
  `consumeLease`, `leaseExpiresAt`), `pkg/cluster/kernel_selfrecover.go`
  (`LocalDrainedSince`), `pkg/daemon/kernel_selfrecover.go` (adapter),
  `pkg/upgrade/kernel_run.go` (promote clears lease),
  `pkg/upgrade/kernel_selfrecover_15181_test.go` (new),
  `pkg/cluster/kernel_selfrecover_15181_test.go` (new),
  `pkg/upgrade/kernel_promote_lease_15181_test.go` (new),
  `pkg/upgrade/kernel_selfrecover_test.go` + `pkg/upgrade/kernel_test.go`
  (fake surface), `docs/log/15181.md`

## Risk

A crashed roll whose drain was applied by a path that never stamps
`ManualFailoverAt` now fails closed (no auto-recovery) instead of
recovering — the safe direction: the node stays drained for the operator
rather than rejoining against a later drain's intent. All current drain
setters stamp the timestamp. Lease consumption takes the orchestrator
flock non-blockingly, so it can never block or delete a live successor's
lease.
