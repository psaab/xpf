# #16764 — VRRP address-owner shape (VIP == own unit address) rejected at commit

- **Timestamp**: 2026-10-25
  - **Action**: An RFC 5798 address owner — `virtual-address` equal to an
    address configured on the same unit, textbook priority 255 — committed
    strict-clean, then `pkg/vrrp` sent no IPv4 advertisements (the advert
    source selector excludes every VIP, and for an owner that is its only
    address) and deleted its own unit address at run start, on BACKUP and
    on shutdown (every VIP is `AddrDel`'d unconditionally). Took the
    issue's bounded acceptance option — reject at commit with a named
    error — rather than implementing RFC 5798 §6.4.1 owner semantics in
    the runtime. Added `validateVRRPVIPOwnerStrict`
    (`pkg/config/compiler_validate_strict_vrrp_vipowner.go`): an explicit
    `vrrp-group` whose parsed VIP host IP equals any parsed address of its
    own unit is a hard error on strict commit / commit-check, naming the
    interface, unit, group, VIP and matched unit address. The comparison
    is priority-independent (the source-exclusion and address-stripping
    mechanism does not depend on 255) and spelling-independent (parsed
    host IP, so bare and CIDR spellings collide; bare VIPs are normalized
    to the enclosing prefix before the gate). Wired into the uniform gates
    beside the #14407 cross-group gate with the standard #1960 doctrine:
    tolerant load / peer-sync downgrades to a warning via the new
    `lenientVRRPVIPOwner` opt, so a persisted owner config still boots.
    Explicit groups only — RETH-derived instances carry unit addresses as
    VIPs by construction, never run at priority 255, and stay untouched.
    Tests: `pkg/config/vrrp_vip_owner_16764_test.go` — subject row
    (10.0.1.1/24 == unit address, priority 255, named error), any-priority,
    second-address-of-unit, bare spelling, IPv6, hierarchical spelling,
    the issue's control row (VIP 10.0.1.254 on unit 10.0.1.1 commits
    clean), different-interface control, lenient-warns + lenient-opt
    registration, and plain-RETH control. FAIL-ON-REVERT: dropping the
    uniform-gate dispatch turns every strict-reject cell green on the bad
  - **File(s)**: `pkg/config/compiler_validate_strict_vrrp_vipowner.go`
    (new), `pkg/config/compiler_uniformgates_cluster_zone.go`,
    `pkg/config/compiler_opts.go`,

    never delete an owned address, straight to MASTER) remain
    unimplemented by design; deleting this gate is the entry point if
    they are ever built. A leniently loaded owner config keeps today's
    runtime behaviour until corrected (warned, not seated differently).
