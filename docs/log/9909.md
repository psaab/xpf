# #9909 — WireGuard routing-instance outer transport scope

- **Issue**: https://github.com/psaab/xpf/issues/9909
- **Decision**: commit-time refusal (the issue's branch (b)); the outer UDP socket remains unbound to a routing-instance until the VRF-fd mechanism from #1434 S6 exists.
- **Base**: `900771b134d2b5a85f6659a32f2779c01e09bc00` (`origin/master` at the start of this lane).

## STEP-0 baseline RED proof

The issue was live on the clean base before the gate was added.

- A temporary config harness exercised interface-level and per-unit `tunnel routing-instance` declarations plus bare and unit-qualified `routing-instances <name> interface <member>` declarations. The strict forms committed without an error and the tolerant form produced no #9909 warning. The four baseline cells were therefore RED. The temporary harness was removed; the permanent cells below retain the same shapes and fail if the gate is reverted.
- A temporary Rust test called the real production `bind_wg_socket(0)`, read `SO_BINDTODEVICE`, and ran `ip route get 198.51.100.1`. It intentionally asserted that a device binding must exist. The baseline test failed with `SO_BINDTODEVICE=""`; the route resolved through the host's main-table `ix0` path (`via 172.16.100.1 dev ix0`). This is executable socket evidence, not a source-only inference.
- The host has no `CAP_NET_ADMIN`, so creating an isolated kernel VRF/netns to observe the positive bind case was unavailable. No Rust production code was changed for this disposition.

The #1434 audit found the S2a gap still explicitly documented in `userspace-dp/src/afxdp/coordinator/wg_control/sock.rs`: socket creation binds a wildcard address and says VRF/routing-instance socket binding is deferred to S6. The completed multi-peer work in #1434 did not land a WireGuard VRF-fd or `SO_BINDTODEVICE` path. Implementing the bind therefore requires the deferred #1434 design rather than a guessed socket shortcut.

## Implementation

- `pkg/config/compiler_opts.go` adds the dedicated `lenientWireguardRoutingInstance` option. It is separate from `lenientWireguardPeers` because this gate must quarantine a half-scoped tunnel rather than merely downgrade a peer-shape diagnostic.
- `pkg/config/compiler_validate_wireguard_routing_instance_9909.go` is called from `runTailGates` in `pkg/config/compiler_tailgates.go`. Strict compilation rejects both `TunnelConfig.RoutingInstance` and routing-instance interface-list membership, including the runtime-normalized `TunnelConfig.RIListMember` field. The walk is deterministic, gates every declared routing-instance type, and expands bare members through the same unit/device primitives used by the daemon.
- Tolerant compile/load emits a #9909 warning naming the tunnel and instance, removes every WireGuard record sharing an affected persistent device, and removes matching RI-list members before routing or userspace snapshot consumers can act. A bare member that also names surviving non-WireGuard units is narrowed to explicit surviving unit references; unrelated members remain.

## Hostile review fold (RED → GREEN)

The four hostile-review reproductions were run against the pre-fold validator before implementation. A temporary config harness produced four intentional failures: (P1-1) `interface wg1.1` was refused but bare `interface wg1` was accepted for a per-unit WG; (P1-2) tolerant load left the shared interface-level `wg0` endpoint alive; (P1-3) tolerant bare-member quarantine deleted a surviving GRE sibling; and (P2) undeclared `wg0.99` falsely matched parent `wg0`. The temporary harness was removed after the same cases passed with the fixed validator.

The fold fixes the matcher by expanding declared bare members to every configured unit/device, quarantines the full affected persistent-device set, narrows partially surviving bare memberships, and leaves undeclared nonzero unit references untouched. `TunnelNameMap` is hoisted once per validation so the expansion does not rebuild the map per member.

## Permanent regression cells

- strict interface-level and per-unit tunnel-stanza rejection;
- strict interface-level bare/unit-ref, per-unit bare and unit-ref, slash/dash alias, and forwarding-type RI-list rejection;
- strict rejection of the runtime-normalized `RIListMember` field;
- tolerant tunnel-stanza warning plus per-tunnel skip with a clean sibling preserved;
- tolerant RI-list warning plus tunnel removal, matching-member quarantine, and unrelated-member preservation;
- tolerant shared-device endpoint quarantine;
- tolerant bare-member narrowing that preserves a GRE sibling;
- tolerant forwarding-instance quarantine;
- strict and tolerant controls proving an undeclared nonzero unit reference does not match its parent WG;
- clean plain WireGuard and GRE-with-routing-instance controls.
