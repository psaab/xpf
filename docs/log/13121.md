# Issue #13121: release stale VRF bindings from persistent TUNs

## Why

`appliedRI` is volatile manager state, so it is empty after a daemon restart or
`Clear()`. The old unbind helper treated an empty claim as proof that no master
was ours; untracked persistent TUNs and configured tunnels moved back to `main`
therefore stayed enslaved to an old `vrf-*`. The orphan path also kept TUNs up,
leaving their link-local connected routes active.

## What

For a tunnel without an in-memory claim, identify its current master by index
from `LinkList` and detach it only when it is a `netlink.Vrf` named `vrf-*`.
Keep foreign masters attached, and retry on a failed link-list lookup. Bring
orphan TUNs down before pruning their owned addresses. Add regressions for
restart/Clear recovery, orphan state, and foreign-master preservation.

## Risk

If `LinkList` fails while reconstructing an unclaimed master, the binding is
left untouched on that apply and retried during the next reconcile. If bringing
an orphan TUN down fails, the failure is logged and the orphan sweep attempts
again on a subsequent Apply.
