# #12526 — reject nameless firewall terms before LoadMerge flattening

- **Issue**: #12526 — hierarchical `LoadMerge` launders nameless firewall terms into named set paths before `CommitCheck`.
- **Branch**: `fix/12526-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12526`

## Why

The strict firewall compiler gate correctly rejects nameless hierarchical terms, but hierarchical `LoadMerge` renders its parsed tree through `FormatSetForLoadMerge` and replays the resulting commands before `CommitCheck`. The renderer erases the original term-body shape, so a nameless body such as `term { foo; }` or `term { T then discard { } }` becomes an ordinary named set path and escapes the compiler's nameless marker. This also hides the nameless is-fragment shape from the naming gate; the separate named is-fragment action-loss finding remains tracked by #12528.

## What

- Add a pre-flatten AST scan for firewall terms in literal hierarchical `LoadMerge` input. It clones and splits packed heads only up to the term node, retaining the full term body for classification.
- Reject body statements and empty one-key term containers without an authored term name, reporting the family (when the filter has one), filter, and first body token. Named term blocks, packed named terms, and explicit nested named terms remain mergeable.
- Include firewall filters inside literal group bodies; do not expand group references. Flat-set `LoadMerge` semantics are unchanged.
- Preserve the existing tolerant compile path: firewall nameless-term findings remain warnings under `CompileConfigLenient` rather than becoming strict errors.
- Replace the old #12092 behavior pin that asserted nameless `LoadMerge` success with assertions that these shapes reject before candidate mutation.
