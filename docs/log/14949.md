# Issue #14949 — scope interface-NAT RST suppression to conntrack-less drops

- **Issue:** `InstallRSTSuppression` (`xpf_dp_rst`) dropped ALL outgoing TCP RSTs from interface-NAT addresses with no conntrack-state scoping, suppressing policy `reject with tcp reset`, `ident-reset`, and local control-plane socket RSTs (D12-05).
- **Fix:** `rstDropExprs` in `pkg/nftables/rst_suppress.go` now inserts a conntrack-less predicate — `ct state & (invalid|established|related|new|untracked) == 0` (`expr.Ct{STATE}` + `Bitwise` native-endian mask of all five known state bits + `Cmp Eq 0`) — between the saddr match and the TCP/RST match in every drop rule. Only packets with no conntrack entry are dropped.
- **Why this scope:** The spurious RSTs the table exists to suppress (#450) belong to userspace-owned flows the kernel never tracked, so they arrive conntrack-less. Legitimate RSTs from the same addresses are tracked: an nft `reject with tcp reset` creates a conntrack entry for the rejected connection before its synthesized RST traverses OUTPUT (ct state `new`), and a local socket RST belongs to a tracked connection. The full-state mask ensures any tracked packet, whatever its single state, is excluded; narrowing the mask (e.g. established|related only) would re-break reject RSTs.
- **Direction (fail-closed preserved):** The suppression itself is unchanged for its target class — conntrack-less RSTs from NAT addresses are still counter+dropped, and the atomic delete+create install is untouched. The change only narrows which RSTs are suppressed; it never widens the drop.
- **Files:** `pkg/nftables/rst_suppress.go`, `pkg/nftables/rst_suppress_14949_test.go` (new), `pkg/nftables/rst_suppress_shape_7171_test.go` (index shift + ct-presence check), `pkg/nftables/README.md`, `docs/afxdp-packet-processing.md`, `docs/log/14949.md`.
