# #16868 — reject-only chain members dropped out of redistribute composition (R3-B07-05)

- **Timestamp**: 2026-10-25
- **Action**: `redistChainForSource15156` admitted a chain member only
  if that member's own #14698 enrolment included the source, so a
  reject-only guard policy, a protocol-less reject guard, or a policy
  whose only terminal for a source is its policy-level `then reject`
  silently dropped out of an `export [ GUARD ACceptor ]` chain: the
  single surviving policy's per-source map was attached instead of the
  composed map and the rejected statics/connected subnets were exported
  into OSPF/OSPFv3/RIP/IS-IS/BGP. Fixed by composing over the whole
  defined chain whenever any member enrols the source: every defined
  member's applicable per-source terms and terminal `DefaultAction`
  run in chain order, whether or not that member enrols the source by
  itself. The named chain truncates at the first terminal default
  (mirroring #5277/renderRedistComposedMapVariant16864), extended only
  through the first enrollee when a sole terminal guard would
  otherwise collapse the attachment to its own per-source map; the
  composed renderer's sequence bound now counts only members that
  actually render. Enrolment is probed via `redistProtocolsForNode`
  (`redistChainEnrols15156`) instead of rendering entries. BGP
  origination is grouped by distinct effective export chain
  (`bgpEffectiveExportChains14586`): a guard composes only with its
  own chain's acceptors, neighbours exporting disjoint single policies
  keep their per-source maps (#14586), and a source several chains
  produce attaches a cross-chain OR map
  (`renderRedistOrComposedMap16868`): each producing chain renders
  first-terminal-wins internally, then deny sequences of non-final
  chains demote to match-all `permit ... on-match goto <next chain>`
  so a reject in one chain cannot veto another chain's accept
  (review fold: the first flattened-union render let peer A's guard
  suppress peer B's routes, order-dependently). NOT changed: single-policy and
  bare-token renders, #14698 single-policy enrolment (a reject-only
  policy alone still enrols nothing), per-peer `route-map out`
  composition (#5277), and QNH metric maps.
- **File(s)**: `pkg/frr/redistribute.go` (whole-chain composition,
  terminal truncation, per-chain BGP grouping + cross-chain merge,
  grouped entry resolvers), `pkg/frr/protocols_render_bgp.go` (BGP

  `pkg/frr/redistribute_chain_16868_test.go` (new),

## Risk

Composed maps for guard-first chains are new generated route-maps in
FRR's global namespace; the existing collision guard fails the apply
closed rather than merging. Single-policy configs see no change. The
BGP cross-chain OR names follow first-seen chain order; they are
generated names, not an operator interface. The OR splice renames
scratch prefix-list definitions onto the real map name and counts
sequences against the same FRR ceiling (oversize renders the
quarantine deny). QNH metric overlay for composed chains remains
deferred as under #15156.
