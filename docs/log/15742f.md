## Root cause

`populate_zone_to_rgs` (forwarding_build/interfaces.rs) first pass:
any row with `zone=""` on a shared ifindex inserted a `None` claim,
vetoing the whole ifindex. On the live cluster every RETH netdev is
shared with its physical member row (`ge-0/0/1`, zone="",
egress_zone="lan" Go-stamped) beside `reth1`/`reth1.0` (zone="lan").
The Go zone map fans a bare RETH ref DOWN to its unit, never UP to the
member, so the member is legitimately blank — but the veto zeroed
ifindex 5, `lan` never entered `zone_to_rgs`, and
`zone_encoded_fabric_stamp_valid` (fabric.rs V1b: zone must have an
RG-bound member) rejected every punt. Same for WAN ifindex 6 (only
reth0.50/.80's distinct ifindexes 13/14 saved wan=[1]).

## Fix

`populate_zone_to_rgs`: a blank row vetoes only when it aliases a unit
on the same ifindex (its name is that unit's base, e.g. `st0` beside
`st0.0` — the #13181 unzoned-alias shape, whose regression cell stays
green); a blank physical member with no unit bearing its name does not
vote. Conflicting nonzero zones still zero the claim;
`ifindex_unambiguous_zone_id` (Go `egress_zone` ledger) still gates
pass 2. No wire/protocol change (no v59 bump needed).
