# Issue #13644: constrain post-admission neighbor learning

## Why

An admitted routed packet carries the remote L3 source address alongside the
upstream router's Ethernet source MAC. Learning that pair creates off-link
neighbor entries until bounded shards fill. A permitted packet that spoofs an
on-link source could also replace an existing dynamic neighbor MAC, redirecting
return traffic without winning an ARP/NDP race.

## What

Post-admission source-MAC learning now requires the claimed source IP to belong
to a connected prefix on the VLAN-resolved ingress interface. Per-ifindex
connected-prefix indexes keep this check bounded to the ingress interface on
flow-cache hits. The post-admission learn is create/refresh-only: a data-plane
L3 packet cannot replace an existing dynamic neighbor. The existing ARP/NDP
control paths remain responsible for legitimate neighbor moves.

Regression coverage exercises off-link IPv4/IPv6 refusal, fabric-ingress
refusal, on-link first learning, refusal to replace an existing neighbor, and
the admitted packet path's original source-MAC behavior.

## Risk

Plain L3 traffic can no longer announce a host MAC change; legitimate updates
must arrive through ARP/NDP learning. No live cluster smoke was run: the
available HA cluster had unresolved clock/fabric qualification warnings, and
cluster gates were not authorized.
