# #15716 — Packed group `ssh root-login` leaves and header-packed `system services` bypass #14447

## Mechanism
At `origin/master` (report base `f214fac`):

- Case A: `groups { G1 { system services ssh root-login allow; } G2 { system services ssh root-login deny; } }` with `apply-groups [G1 G2]` compiled with `err=nil`, no warnings, `RootLogin=""` (both values lost). `isRootLoginLeaf14447` only matched a braced `root-login` leaf under `system/services/ssh`, so the packed `system …` leaf was never marked in `groupRootLoginLeaves14447`, never adopted beside a group peer, and `walkGroupToContext`/`mergeNodes` dropped it at the top level.
- Case A variants `services ssh root-login …` (ancestor `system`) and `ssh root-login …` (ancestor `system/services`) likewise were not recognised as root-login leaves.
- Case B: `system services ssh root-login deny { services { ssh { root-login allow; } } }` compiled `RootLogin="allow"` with no gate error. Both `collectRootLoginValues14447` and `compileSystem` only unpacked the header-packed system node when `len(serviceChildren)==0`, so the header `deny` was skipped whenever braced `services` children existed.

## Fix
- `pkg/config/group_root_login_14447.go`: `isRootLoginLeaf14447` now also matches packed leaves (`ssh root-login <val>`, `services ssh root-login <val>`, `system services ssh root-login <val>`). New `markGroupRootLoginLeaves14447` recursively marks root-login leaves in a group-originating subtree (mirroring `markDefaultPolicyGroupBlocks12823`), called from `expandLevelRefs15033` on cloned/memoised bodies. New `propagatePackedGroupRootLogin14447` marks the synthesised `root-login` child when `promoteLeafPeerForPackedGroup9855` promotes a group-adopted peer carrying a packed root-login tail. New `synthesizePackedSystemRootLogin15716` builds the braced shape from a packed system leaf.
- `pkg/config/ast_groups.go`: call the subtree marker in `expandLevelRefs15033`; call the propagation helper at the `promoteLeafPeerForPackedGroup9855` call site; synthesise-and-merge a packed system leaf in the leaf branch of `mergeNodes`; `walkGroupToContext` unpacks a packed system leaf so a nested `apply-groups` inside `system { … }` can descend into the group body (previously the leaf was skipped and the memoised body was empty).
- `pkg/config/compiler_validate_duplicate_scalar_14447.go`: `collectRootLoginValues14447` now pools via `unpackSystemRootLogin15716`, which unpacks header-packed system, packed services, and packed ssh spellings (including packed `ssh root-login allow root-login deny` runs) alongside braced children, without the `len(serviceChildren)==0` guard.
- `pkg/config/compiler_system.go`: drop the `len(serviceChildren)==0` guard and prepend the header-packed ssh value (deduplicated) so lenient last-wins sees header-then-braced order.

Scope: only the `root-login` mechanism named in the issue. No other scalar gates changed.

## Regression
New `pkg/config/compiler_validate_duplicate_scalar_15716_test.go`:
- Strict rejects: packed-system groups, packed-services groups, packed-ssh groups, header-packed system + braced child (error names root-login/allow/deny/14447).
- Lenient: packed groups warn + last-wins `deny`; header-packed warns + last-wins `allow`.
- Controls stay green: single packed group, identical packed groups, single header-packed, identical header+braced, inline-braced wins over single group packed.
