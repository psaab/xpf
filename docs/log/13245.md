# Issue #13245 — Align system show output across gRPC and CLI

## Why

The gRPC `show system core-dumps` renderer printed a filename from
systemd-coredump without the terminal sanitizer already used by the local CLI.
The gRPC chassis-environment path separately formatted signed millidegrees
with Go's negative remainder, producing malformed values such as `0.-5 C`.
The local alarm renderer omitted the daemon's fabric-auth downgrade alarm, and
the CLI and gRPC service summaries left complementary configuration rows out.
Operators using the remote CLI could therefore receive terminal control bytes
or incomplete, contradictory system status.

## What

- Added injectable filesystem paths to the gRPC core-dump and thermal renderers
  so tests exercise their real rendering paths. gRPC core-dump names and
  thermal-zone names now pass through `termsafe.SanitizeForDisplay`; the
  temperature formatter preserves the sign of sub-zero readings.
- Added SNMP (with unconditional gRPC community masking), DHCP/DHCPv6, and
  per-stream syslog detail to gRPC `show system services`; stream rows are
  sorted deterministically.
- Brought the CLI service summary into parity for SSH root-login state, Web
  HTTP/HTTPS, DNS enabled state, security-log mode, and deterministic syslog
  row ordering. Wired the gRPC server's fabric-auth alarm state into local
  `show system alarms`.
- Added real-renderer regressions for hostile core names, thermal formatting and
  names, gRPC service rows, local fabric-auth alarms, and local service rows.

## Risk

The local CLI now reports the configured SSH root-login mode even when root
login is denied, matching the remote gRPC view; this is a display-only change.
The CLI continues to apply its login-class SNMP community redaction policy,
while gRPC remains unconditionally redacted because it has no local login
class. No configuration or wire format changed.
