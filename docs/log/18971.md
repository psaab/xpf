## Decision rule

Thread the arm whenever the existing immediate dispatcher already holds and
branches on a lenient flag; use outcome-neutral wording only when obtaining the
arm would cross a schema/validator boundary or otherwise add a new arm-plumbing
layer. Every producer in this issue meets the first condition, so all eight
builder functions use per-arm outcomes. Their existing dispatchers pass the
exact flag used for the return-versus-warning decision. The four direct
peer-effective NAT calls pass `false`, preserving strict wording there. No
schema boundary is crossed and no behavior or gate decision changes.

For each builder, the strict outcome is the literal `the commit is refused`.
The tolerant outcome retains the original commit-succeeds/runtime-consequence
clause. Diagnostic heads, offending values, remediation, warning envelopes, and
compiled output remain unchanged.

`compiler_strict_refusal_outcomes_18971_test.go` exercises the real strict and
tolerant compile reaches with literal, test-owned head/outcome constants. The
three policy builders, NAT empty-application-set builder, NAT pool-reference

shared stanza builder directly on both arms; a separate public-pipeline token
case pins dispatcher arm threading. `TestNATPeerEffectiveStrictOutcomes18971`
adds strict-wording pins for all four direct peer-effective NAT consumers.
Existing quoted heads remain valid.

The outcome-swap mutant is run separately for each of the eight builders:
`policyMatchApplicationError`, `policyMatchEmptyAppSetError`,
`policyMatchAddressSetError`, `natMatchEmptyAppSetError`,
`validateNATPoolReferencesStrict`, `validateSourceNATPoolAddressGrammarStrict`,
`validateSourceNATPoolAddressScopeStrict`, and
`validateHostInboundStanzaStrict`. Each swap must red that builder's named pin
on both arms; the mutant is immediately reverted before the next builder.

## Implementation

- `compiler_validate_strict_policy.go`: the two policy-application builders and
  the policy-address builder take the validator's `lenient` arm. Each retains
  its original tolerant consequence and emits `the commit is refused` strictly.
- `compiler_validate_strict_nat.go`: the NAT empty-application-set,
  pool-reference, two pool-grammar, and scoped-pool-address producers use the
  same per-arm rule. The two grammar producers have separate literal pins.
- `compiler_validate_strict_zones.go`: one outcome in
  `validateHostInboundStanzaStrict` covers all four retained/compiled
  service/protocol branches without changing scope or token selection.
- `compiler_uniformgates_sampling_appset.go`,
  `compiler_uniformgates_nat_registry_16145.go`, and
  `compiler_uniformgates_cluster_zone.go` pass the exact flag their surrounding
  branch uses. `compiler_peer_effective_snat.go` passes `false` at all four
  direct strict peer calls.
- `compiler_strict_refusal_outcomes_18971_test.go` adds the twelve literal
  head/outcome pins, dispatcher coverage, and four peer-effective strict pins.
  Comments in `strict_gate_wiring_canary_test.go`,
  `strict_nat_pool_grammar_5627_test.go`, and
  `compiler_zone_scoped_snat_pool_5875_test.go` were updated for the new
  signatures. No gate predicate, warning envelope, compiled configuration, or
  runtime dataplane code changed.
