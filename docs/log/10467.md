# Issue #10467 — userspace FBF routing-instance steer must stay enforced

## Defect and confirmed root cause

The live defect was not a missing XDP/AF_XDP ingress hand-off and was not the
trailing `NoRoute` slow-path reinject. The exact fixed-leg probe reached the
userspace dataplane and hit an already-established helper session whose cached
decision still used `MAIN`.

Two independent gaps made that possible:

1. **The helper session was not reliably evicted.** A destination/port-scoped
   clear removed the BPF mirror row before the userspace helper delete had
   succeeded, and helper-delete errors were not retained for retry. A transient
   helper/XDP session therefore remained authoritative while the control-plane
   census reported no row.
2. **The established-session HIT path declined RI/PBR revalidation.** When a
   commit added a matching `routing-instance` term after the session was
   installed, the HIT path reused the cached `MAIN` decision. It did not derive
   the desired PBR/native-RI table or perform a table-scoped lookup, so the
   empty `wire-10136` table was never consulted.

The decisive diagnostic journal (archive
`/var/tmp/xpf-wire-routing-separation-1789820284`, ledger
`a4619d12e498da67`) records the exact sequence:

```text

12:18:17  TRACE10467 SESSION_HIT tuple=10.0.61.102:57017 -> 172.16.80.201:57017
```

There was no route-evaluator/`ROUTE_OVERRIDE` trace for that hit. The empty
selected table was therefore not reached; the stale cached `MAIN` resolution
forwarded the probe. Temporary trace instrumentation was removed before the

## Fix

The Go userspace manager now deletes the authoritative helper session first
and deletes the BPF mirror only after the helper accepts both the forward and
reverse deletes. Any helper IPC/refusal error is returned while the mirror row
remains retryable. IPv4 and IPv6 use the same transactional ordering.

On an established HIT, userspace now revalidates only a stale
`(configuration generation, logical ingress)` stamp, while per-packet PBR
predicates are evaluated on every HIT. It derives the desired PBR or native-RI
install identity and performs the lookup in that explicit family table. Fresh
translated NAT aliases resolve the canonical session key before any teardown;
they never hand the wire tuple to pair deletion. An unchanged identity
preserves #8114's no-flap behavior. A changed identity, a removed steer, or an
unresolvable RI produces a fail-closed route-transition discard, clears the
stale stamp, tears down the canonical forward/reverse pair, and evicts the
corresponding flow-cache keys. A sessionless matching steer derives and drops
the packet without inventing a revocation key, while a sessionless PBR
nonmatch keeps native MAIN handling. The next packet takes the ordinary
session-miss path and recomputes both halves. If that explicit table still has
no route, the terminal poll gate drops the NoRoute instead of delegating the
original frame to MAIN. Native-RI fallback remains aligned with #10312 when no
PBR term matches.
