# Issue #12532 — re-authorize nested rollback invalidation debt

## Why

A commit-confirmed rollback restores the original confirmed configuration even when several nested confirmed transitions have landed. Policy-invalidation debt retained a single landed predecessor and a capture merged across transitions. On rollback to the root, the exact-predecessor check therefore missed, and the carry path deleted candidates that the restored root permits.

## What

Commit-confirmed rollback plans are now explicitly marked. If an applied target rolls back beyond its immediate predecessor, retained helper candidates are evaluated against the actual restored configuration instead of inferring candidate authority from the bounded predecessor link. Each captured helper candidate keeps its stable rule identity separately from positional runtime policy IDs; merging debt preserves the original identity. The shared `policymatch` evaluator applies the restored config to the candidate's tuple and zones. Permitted candidates (and their v4/v6 captured keys) are discharged; denied, unknown, or malformed candidates remain in debt. The exact one-level undo path remains unchanged, as does scan-failure debt's fail-closed marker.

Permanent regressions cover C0→C1→C2→C0, a depth-three C0→C1→C2→C3→C0 rollback, a root-denied candidate retained through nested rollback, and the existing one-level intermediate rollback controls. The nested tests force candidate deletes to fail at each confirmed commit so rollback exercises retained debt rather than freshly deleted rows.

## Validation

- **RED before:** `go test ./pkg/daemon -run '^TestPolicyInvalidationNestedConfirmedRollbackToRootDischargesPermitted12532$' -count=1` failed because rollback deleted C0-permitted session 1.
- **GREEN:** The depth-two, depth-three, root-denied-candidate, and existing `TestPolicyInvalidationUndoRestoresEarlierLandedDebt12323` controls passed. `go test ./pkg/daemon -run '12072|12323|12532|TestPolicyInvalidation' -count=1` passed.
- `go test ./pkg/daemon -count=1`, `go vet ./pkg/daemon`, and `go build ./...` passed.

## Risk

Re-authorization requires sufficient candidate provenance and a well-formed helper tuple with known stable rule and zones. Unknown provenance or malformed tuples are retained rather than treated as permitted. The helper-capture candidate path is covered; legacy store-only capture has no helper match tuple provenance and is not reinterpreted by this change.
