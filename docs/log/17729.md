# #17729 — isolate shim Cargo config discovery

- **Timestamp**: 2026-10-29
- **Action**: Isolate the userspace XDP shim Cargo invocation from configs above the checkout and register temporary-directory cleanup before Cargo starts.
- **File(s)**: `pkg/dataplane/build-userspace-xdp.sh`, `pkg/dataplane/userspace_xdp_build_provenance_15218_test.go`, `pkg/dataplane/userspace_xdp_manifest.go`, `debian/changelog`, `docs/log/17729.md`

## Why

A fresh `CARGO_HOME` and `env -i` did not prevent Cargo from discovering `.cargo/config.toml` in the working directory's ancestors. The recipe ran from `userspace-xdp`, so an untracked ancestor could select `rustc`, a wrapper, or rustflags without entering the recorded codegen environment digest. Separately, `set -e` let a failed Cargo invocation exit before the old line-160 EXIT trap was installed, leaking the newly created Cargo home.

## What

- Run Cargo from a fresh temporary working directory with `--manifest-path` pointing at the shim crate. Canonicalize that directory and fail closed if `.cargo/config.toml` or legacy `.cargo/config` exists at that directory or any ancestor through `/`. Cargo's config hierarchy follows its cwd, not the manifest path; a real-Cargo fixture confirmed that an ancestor wrapper/rustflags take effect from the crate cwd but not from the isolated cwd. Explicit `--config` values preserve the crate's `build.target`, `unstable.build-std`, release profile, and linker settings, which Cargo no longer discovers from the crate-local config.
- Keep the codegen environment digest unchanged: no hierarchical Cargo config can affect the build after the isolated-cwd ancestor check, the fresh `CARGO_HOME` has no global config, and the remaining build settings are explicit command-line values already represented by the hashed build recipe. The root and crate Cargo config files remain conservatively hashed as freshness inputs, not effective recipe configuration.
- Install an EXIT trap immediately after creating the fresh `CARGO_HOME`, before further setup and Cargo. The trap cleans both temporary directories and preserves the triggering exit status.
- Add real-Cargo control/treatment coverage for ancestor wrapper and rustflags, plus a script-level failure-path probe that checks the isolated cwd/manifest argv, preserved Cargo exit status, and removal of both temporary paths. The script probe supplies its own pinned-version bpf-linker stub, so it does not skip when host tooling is absent.
- Update the manifest input comment to describe the Cargo config files as conservative freshness coverage, not settings loaded by the isolated recipe.
