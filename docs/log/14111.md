# #14111 — SSH keys, directory ownership, algorithm fallback (D5-09)

## Defects fixed (all in `pkg/daemon/daemon_hostauth_apply.go`)

1. **Key-type validation rejected valid OpenSSH keys.**
   `validateAuthorizedSSHKeys` required an `ssh-` prefix, so a valid
   `ecdsa-sha2-nistp256 …` / `sk-*` key value (the full
   `"<type> <base64> <comment>"` string Junos operators store under any
   `ssh-*` leaf) was rejected at apply and `applySystemLogin` skipped
   *all* provisioning for that user. Fixed with a fail-closed allowlist of
   the OpenSSH `authorized_keys` key-type vocabulary
   (`ssh-ed25519/rsa/dss`, `ecdsa-sha2-nistp{256,384,521}`,
   `sk-ssh-ed25519@openssh.com`, `sk-ecdsa-sha2-nistp256@openssh.com`, and
   the `*-cert-v01@openssh.com` family) plus a required base64-ish blob.
   Option-prefixed lines (`command="..." …`), bare blobs, unknown types,
   type-without-blob, empty, and CR/LF values stay rejected (#10725
   doctrine preserved; `TestApplyRejectsMalformedAuthorizedKeys10725`
   still green).

2. **Name-based recursive `.ssh` chown failed for non-eponymous groups.**
   `chown -R -- <name>:<name> <sshDir>` fails for any existing account
   whose primary group is not named after the user, stranding the user
   outside a freshly created root-owned 0700 `.ssh`; the error was
   aggregated yet key installation continued and the ownership marker had
   already been claimed. Fixed by owning the directory with the
   already-resolved numeric `(uid, gid)` via `os.Chown` (through the
   `chownSSHDir` seam so fake-uid test fixtures can observe it), only the
   directory itself (the key file is installed with the same owner by
   `fsatomic.WithOwner`), and aborting that user's key install with
   marker rollback when the chown fails instead of reporting convergence
   over an untraversable directory. Numeric operands also subsume the
   #5005 `--` option-injection concern for this exec (it no longer
   exists).

3. **All-invalid SSH algorithm lists silently reverted to sshd defaults.**
   `buildSSHDConfig` omitted a `KexAlgorithms`/`Ciphers`/`MACs` line
   whenever a nonempty operator-specified list filtered to nothing, so a
   leniently loaded malformed restriction silently reverted sshd to its
   built-in defaults. Fixed with `buildSSHDConfigErr` /
   `filterSSHAlgorithmsErr`: a nonempty list that filters to empty is an
   error. `applySSHConfig` returns that error *before* touching the
   drop-in (no write, no removal, no reload), leaving the previously
   installed restriction in force. Partial filtering still renders the
   survivors (#4902 belt). The string-only `buildSSHDConfig` is kept for
   the many pure render/compare/live-check callers; its all-invalid
   result is now `""`.

   Scope note: with (3), every `applySSHConfig` error is already joined
   into the commit result by the apply tail (#6790), so the fail-closed
   signal reaches the operator without new plumbing.
