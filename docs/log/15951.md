# Host-inbound: fail closed on local-session install failure; credit junos-host denies (#15951)

- **Issue**: #15951 (claims H41-01, H41-02 from the vsrx parity research cohort).
- **Cause (H41-01)**: On a cacheable LocalDelivery session-miss, the local
  session install was conditional and failure was non-terminal. When
  `local_session_capacity_available` was false the code only called
  `note_admission_refused()` and fell through; when
  `install_helper_local_session_on_miss` returned false the same fallthrough
  happened. The disposition stayed `LocalDelivery` with
  `host_inbound_gate_proof` set, so the slow-path tail selected
  `SlowPathOutlet::Trusted` and reinjected the packet to the kernel with no
  installed session, no conntrack publication, and no revalidation anchor.
  Separately, `local_metadata` hardcoded `fabric_ingress: false` and the raw
  `meta.ingress_ifindex`, unlike the transit install's (#7096) stamped
  identity, so a fabric-arrived host-bound session claimed the local fabric
  NIC as its ingress interface.
- **Cause (H41-02)**: No `junos-host` deny path credited the global
  `policy_denied_packets` counter (`xpf_policy_denies_total`): the flow-backed
  wrapper and the flowless arm emitted the deny RT_FLOW and set
  `counters.touched` but never incremented the counter, so host policy denies
  were invisible in flow statistics. The deny event also unconditionally
  passed `NatDecision::default()`, zeroing `nat_dst_ip`/`nat_dst_port` even
  though the policy had been judged on the post-translation destination
  (#9529).
- **Change**:
  - `poll_descriptor/mod.rs`: the LocalMiss install result is now captured;
    on capacity refusal or install-helper failure the packet is counted via
    `note_admission_refused()`, recycled, and `continue`d — it never reaches
    the Trusted reinject. Non-cacheable LocalDelivery (non-SYN TCP and other
    deliberately sessionless traffic) is untouched and still delivers.
    `local_metadata` now stamps `fabric_ingress: packet_fabric_ingress` and
    the (#7096) `stamped_ingress_identity` (0,0 for fabric arrivals).
  - `host_inbound_policy.rs`: `junos_host_local_policy` credits
    `counters.policy_denied_packets` once per deny/reject (all three
    flow-backed call sites funnel through it; the per-rule hit counter is
    already credited by evaluation and is not double-counted), and
    `emit_junos_host_deny` takes the packet's `NatDecision` so the deny
    record carries the translated destination tuple. Callers pass
    `decision.nat` (miss/hit) and `NatDecision::default()` for the Stage-11
    passthrough (no translation).
  - `flowless_verdict.rs`: the flowless `junos-host` deny credits the same
    counter once; a lo0-filter `Filtered` verdict does not (it is not a
    policy deny). Fold (#16293 review): the caller threads the actual
    `flowless_nat` decision plus the post-translation flow
    (`post_nat_l3_flow`, built from address-only DNAT/NPTv6
    `rewrite_dst`) into `flowless_local_delivery_verdict`. The host-inbound
    service gate and the `junos-host` evaluation now judge the
    post-translation destination (#9529 parity; the lo0 filter stays on the
    wire flow, pre-NAT), while the deny record retains the WIRE 5-tuple in
    `dst_ip`/`dst_port` and carries the translation in `nat_dst_*`.
    Previously this arm passed a default decision and judged the wire
    destination, so a flowless DNAT-to-local deny lost `nat_dst` and a deny
    naming only the local address did not match.
- **Scope note**: The enrichment's fabric `nat_scope_ifindex` /
  `StaleDestinationNat` arm does not exist at this head — `SessionMetadata`
  has no such field and zone-policy revalidation declines LocalDelivery
  sessions outright (#9563), so there is no DNAT revalidation of host-bound
  sessions to falsely revoke. The fabric metadata residue at this head is
  the ingress-identity/`fabric_ingress` stamp fixed above. Arm 3 of H41-02
  (raw fabric ifindex in deny events) was NEEDS_VALIDATION in the research
  and is not changed.
- **Regression coverage**:
  - `userspace-dp/src/afxdp/tests_host_inbound_15951.rs` (new): capacity-0
    DNAT-to-local SYN is dropped with `admission_refused == 1` and no
    delivery/session (control cell with capacity delivers + installs);
    `junos-host` deny on miss, deny on established hit, and reject on miss
    each credit `batch.policy_denied_packets == 1`; a DNAT deny event
    carries `nat_dst_ip = 10.0.61.1`, `nat_dst_port = 8080` with the wire
    tuple retained.
  - `flowless_verdict_tests.rs`: the flowless `junos-host` deny asserts
    `counters.policy_denied_packets == 1` and empty `nat_dst_*` without
    translation; `flowless_dnat_junos_host_deny_carries_translated_tuple_15951`
    asserts a deny naming only the translated local address matches and the
    record keeps wire `dst_ip` with `nat_dst_ip` = translated address.
  - `tests_policy_deny_app_10981.rs`: the DNAT `junos-host` deny cell now
    asserts the translated `nat_dst_*` tuple instead of the previous
    no-NAT shape.
- **Validation**: `cargo test --bin xpf-userspace-dp 15951` (6 passed),
  `10981` (3 passed), `9529` (12 passed), `flowless` (133 passed incl. the
  fold cell); full `--bin xpf-userspace-dp` suite run before push (see PR body).
- **Blast radius / risk**: Cacheable host-bound SYNs under session-table
  pressure are now dropped instead of delivered sessionless — the intended
  fail-closed change; operators watching `session_install_admission_refused`
  will see the refusals that were previously silent deliveries. Sessionless
  by-design LocalDelivery (non-SYN TCP, WG listener tuples) still delivers.
  `xpf_policy_denies_total` now includes `junos-host` denies, so dashboards
  summing policy denies will count host denies they previously missed.
