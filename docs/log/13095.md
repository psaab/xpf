# Honor peer-node zone quarantine in membership and advisory gates (#13095)

- **Issue**: #13095 (research finding D1-10, deep-review source report
  `gemini-4-argon-high-review-zone-enforcement-001.md`, three-way
  research-validated). Go config compiler:
  `pkg/config/compiler_validate_strict_zones.go`,
  `pkg/config/compiler.go`, `pkg/config/compiler_opts.go`.
- **Cause**: `zoneInterfaceMembershipConflicts`,
  `ZoneAuthoredBoundSecureTunnelUnitRefs`, and
  `appendUserspaceMgmtZoneAdvisoryLocked` derived quarantine exclusions
  from the local zone map only (`ZoneQuarantineExclusions(zoneNames)`),
  ignoring the recorded three-view runtime zone-name union
  `cfg.ZoneQuarantineNames` (#10248) — and the compile wrappers stamped
  that union onto `cfg` only AFTER `compileExpanded` had already run the
  gates. When a peer-node-only zone's `StableZoneID` collides with a
  local zone (e.g. node1-only `a177301` vs local `mgmt`, both 49514),
  the collidee was quarantined cluster-wide yet kept contesting its
  interfaces inside `QuarantinedZoneInterfaceKeys`, stripping the same
  interface out of an unrelated healthy zone (`trust`) on the local
  node and blackholing its traffic.
- **Change**: thread the pre-expansion union through `compileOpts`
  (`zoneQuarantineNames`) so `compileExpanded` stamps
  `cfg.ZoneQuarantineNames` BEFORE any zone-membership / secure-tunnel /
  advisory gate reads the quarantine set; both wrappers drop their late
  post-return stamp. All five local-only call sites now resolve the
  union-aware `ZoneQuarantineExclusionsForConfig(cfg)`:
  `zoneInterfaceMembershipConflicts`,
  `ZoneAuthoredBoundSecureTunnelUnitRefs` (cited pair), plus the same
  residual local-only derivations in `appendUserspaceMgmtZoneAdvisoryLocked`
  (`userspace_mgmt_zone_advisory_10308.go`, cited),
  `validateHostInboundManagedRoutingMismatch` and
  `buildZoneInterfaceMapLocal` (same derivation, same cascade class).
  NOT changed: the strict commit path still rejects colliding configs
  outright, and tolerant duplicate membership without a StableZoneID
  collision still quarantines the interface (fail closed). A direct
  `compileExpanded` caller that supplies no union stamps the empty set
  and falls back to the pre-fix local behavior.
- **Regression coverage**
  (`pkg/config/zone_quarantine_union_membership_13095_test.go`):
  `TestPeerNodeZoneQuarantineStopsMembershipCascade13095` (decisive
  cell: node1-only `a177301` quarantines local `mgmt`;
  `QuarantinedZoneInterfaceKeys` must be empty so healthy `trust` keeps
  `ge-0/0/0.0`, no false membership warning, strict compile still
  rejects), `TestZoneAuthoredBoundSecureTunnelUnitRefsSkipUnionQuarantined13095`,
  `TestMgmtZoneAdvisorySkipsUnionQuarantined13095`,
  `TestBuildZoneInterfaceMapLocalSkipsUnionQuarantined13095`, and the
  doctrine guard
  `TestZoneMembershipConflictStillDetectedWithoutCollision13095`
  (genuinely local duplicate membership is still rejected strict /
  quarantined tolerant).

- **Blast radius / risk**: compile-time enforcement selection only; a
  cluster-quarantined zone now stops poisoning healthy zones at compile
  time (matching the runtime builders that already consumed
  `ZoneQuarantineExclusionsForConfig`), so healthy zones recover their
  interfaces on the peer-quarantined node's compile. No wire, schema,
  or persisted-format changes. The identical exclusion replacement also
  fixes stale management/advisory and resolved-zone-map views. The
  upstream-zone-mixin `NOT-covered` hunk in
  `host_inbound_resolved_unit_key_11060.go` remains out of scope; it does
