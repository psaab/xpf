# #18687: cap synced imports at the replicated node ceiling

- **Timestamp**: 2026-11-08
  - **Action**: Replaced worker-count-scaled HA import capacity and status aggregation with one replicated-node ceiling; updated protocol, CLI, metrics, and operator documentation.
  - **File(s)**: `userspace-dp/src/session/mod.rs`, `userspace-dp/src/afxdp/ha/session_import.rs`, `userspace-dp/src/server/helpers/status.rs`, related status/protocol/CLI docs and tests.

## Why

Worker session tables are replicas, so `records.len()` does not multiply the local per-table ceiling. The old shared-map cap admitted imports in proportion to worker count, and summing each worker's `max_sessions` reported the same node capacity multiple times.

## What

Defined `REPLICATED_NODE_SESSION_CEILING` once from `DEFAULT_MAX_SESSIONS`. The shared-map cap is `3N`: up to N local rows plus 2N rows for N imported peer forwards and their synthesized reverses. Admission checks projected net pair growth, including local occupancy and NAT-changing replacements; one shared admission gate serializes concurrent imports. The cap applies before worker registration, and admitted early-boot authority remains available for replay. Status reports the largest worker table and one node ceiling. Go bulk receive uses the exact helper-reported node ceiling; generation-guard maps retain their separate 200k minimum. Updated formula/refusal and status regression cells, Go response fixtures, protocol comments, CLI/metrics descriptions, and current architecture/status docs. Captured historical artifacts remain unchanged.
