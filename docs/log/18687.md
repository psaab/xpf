# #18687: cap synced imports at the replicated node ceiling

- **Timestamp**: 2026-11-08
  - **Action**: Replaced worker-count-scaled HA import capacity and status aggregation with one replicated-node ceiling; updated protocol, CLI, metrics, and operator documentation.
  - **File(s)**: `userspace-dp/src/session/mod.rs`, `userspace-dp/src/afxdp/ha/session_import.rs`, `userspace-dp/src/server/helpers/status.rs`, related status/protocol/CLI docs and tests.

## Why

Worker session tables are replicas, so `records.len()` does not multiply the local per-table ceiling. The old shared-map cap admitted imports in proportion to worker count, and summing each worker's `max_sessions` reported the same node capacity multiple times.

## What

Defined `REPLICATED_NODE_SESSION_CEILING` once from `DEFAULT_MAX_SESSIONS`. The shared-map cap is `3N`: up to N local rows plus 2N rows for N imported peer forwards and their synthesized reverses. Admission checks projected pair growth, including pre-existing local rows. Status reports the largest worker table and one node ceiling. Updated formula/refusal and status regression cells, Go response fixtures, protocol comments, CLI/metrics descriptions, and current architecture/status docs. Captured historical artifacts remain unchanged.

## Risk

`max_sessions` now exposes the truthful per-table node ceiling, so operators will see a lower value than the prior worker-count sum. Mixed-version nodes may still publish the old inflated status until upgraded. The wire schema is unchanged.
