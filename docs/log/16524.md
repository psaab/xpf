# #16524: failback leaves gateway-routed sessions fabric-redirected

- **Timestamp**: 2026-10-24
- **Action**: `rehome_or_retain_fabric_redirect_scoped_15958b`
  required the fresh candidate to egress the connected interface
  serving the destination before re-homing a stored FabricRedirect.
  For a gateway-routed destination (e.g. 8.8.8.8 via the default
  gateway) no connected prefix serves the target, so
  `connected_ifindex == 0` and the redirect was retained forever
  after failback, blackholing every surviving Internet-bound
  session at the now-standby peer. Added
  `rehome_or_retain_fabric_redirect_16524`, which carries the
  explicit `dest_rg == 0` (unknown connected owner) bit from all
  five callers (resolve hit, resolve reverse, RefreshOwnerRGS,
  DemoteOwnerRGS, reverse synthesis): an unknown-owner, non-fabric,
  positive-egress ForwardCandidate now re-homes unconditionally,
  while a known connected owner keeps the connected-interface
  equality test so the #15958b transient-mixed-state (split FIB
  answering via WAN) still retains the redirect instead of
  laundering onto WAN egress. The legacy boolean-only wrapper is
  preserved for compatibility and encodes unknown as
  `active && target.is_some()`.
