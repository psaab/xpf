- **Date**: 2026-10-15
- **Issue**: #13714
- **Why**: When a candidate's initial ifindex lookup failed, the planner minted it unregistered and unarmed but still stamped `last_change`. A later replan with the resolved ifindex treated that timestamp as proof of an existing registration and skipped the registration/arm initialization; unchanged forwarding state meant no later arm RPC repaired it, leaving the whole dataplane disabled.
- **What**: `replan_bindings_from_candidates` now considers a prior binding an existing registration only when its previous ifindex was positive. An unresolved prior row is re-registered on recovery and inherits the current global arm state, while still-unresolved rows remain fail-closed. Added tests for armed recovery and double-replan stability, disarmed recovery, and a sibling that remains unresolved.
