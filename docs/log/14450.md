# 14450 — Duplicate interface/unit `tunnel` blocks: second block's WireGuard config dropped → plaintext tunnel (DR20-H5)

- **Timestamp**: 2026-10-17
- **Action**: Merge (Junos-merge) duplicate `tunnel` blocks in
  `compileInterfaces` (`pkg/config/compiler_interfaces.go`): both the
  interface-level and unit-level readers used `FindChild("tunnel")`
  (first-only), so a second `tunnel { ... }` sibling was never read.
  `interfaces gr-0/0/0 { tunnel { mode gre; destination 10.0.0.1; }
  tunnel { mode wireguard; wireguard { ... } } }` therefore installed
  plaintext GRE with no WireGuard peers. Both sites now iterate
  `FindChildren("tunnel")` in order, running the existing per-block
  loops (interface: the raw braced-scalar loop plus
  `tunnelRunChildren9156`; unit: `tunnelRunChildren9156` only — the
  raw-loop asymmetry is preserved) into one `TunnelConfig`: scalars
  are last-wins across blocks (same rule as within one block; the
  #14440 braced-scalar pre-pass runs per block),
  `wireguard` peers accumulate via `parseTunnelWireguard`'s append,
  and the 9899 numeric quarantine keeps its semantics (any block's
  bad key/ttl quarantines the interface/unit in lenient mode, hard
  error strict). `ifc.Tunnel`/`unit.Tunnel` are assigned after the
  loop. For the unit `unitSharesInterfaceWireguardDevice` decision
  (#6941), which reads ONE node's mode, the call site now supplies
  `lastModeTunnelNode14450` (`pkg/config/tunnel_dup_merge_14450.go`):
  the latest block authoring a non-empty `mode`, or nil (= inherits,
  the helper's documented contract) when none does — so a last block
  with no `mode` leaf cannot hide an earlier block's merged mode.
  The tunnel-endpoint collision gate's pre-expansion view
  (`collectTunnelEndpointNamesAST` in `pkg/config/tunnelid.go`) made
  the same first-only assumption for the WireGuard single-endpoint
  selection, so it now evaluates the merged mode over all blocks
  (`astTunnelModeWireguardMerged14450`); View 2/3 ride the compiler
  and inherit the fix (braced `mode { wireguard; }` honoured via
  nodeVal, per #14440). The #5618 plaintext advisory keeps its
  any-block semantics (a warning only — it never gates).
  NOT changed: `routing-instance { destination ... }` first-wins
  reads, the #10654 cross-tunnel GRE-dup gate, and
  `validateWireguardPeers` — duplicate peer pubkeys across merged
  blocks are deliberately NOT deduped in the merge and are rejected
  fail-closed by that existing gate; peers are not cleared when a
  later block sets `mode gre` (inert under a non-wireguard mode).
  The rejected alternative (strict-reject duplicate blocks) would
  break configs that compile today and diverge from the file's
  last-wins prop loops.
