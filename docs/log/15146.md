# #15146 — HA synced NAT64 / pool / interface reserves skip the #14367 interface-domain cross-check

- **Timestamp**: 2026-10-19
- **Action**: Added the #14367 interface-domain cross-check to the three
  HA synced-reserve arms that skipped it. A local interface-SNAT flow
  owns its wire identity only in `InterfaceNatAllocators`
  (address-only tokens, remote-specific); a local pool/NAT64 flow owns
  its identity only in its `PortAllocator` (PAT bitmap, remote-agnostic).
  Before this fix a standby could import a peer-synced translation onto
  an identity a local flow in another domain already held: two live
  flows share one wire identity and the reverse (1:N) index misdelivers
  replies to whichever installed first.
- **File(s)**: `userspace-dp/src/nat64.rs`,
  `userspace-dp/src/nat/source/synced.rs`,
  `userspace-dp/src/afxdp/tests_synced_iface_15146.rs`,
  `userspace-dp/src/afxdp/mod.rs`.

## Fix

- `nat64.rs` (`reserve_synced_nat64_port_unless_peer_owns`): after a
  successful reserve, call `nat64_refuse_if_interface_owns` with the
  prefix's build-synced `iface_allocs` and the combined
  `iface_overlap_owners` (falling back to `overlap_owners`) — the same
  call and the same owners the local mint makes in
  `allocate_source_with_holder`, placed FIRST so its rollback runs
  before the static/peer refusals. Covers both the narrowed and the
  fallback-scan route, since both funnel through this one helper. A
  prefix whose pool shares no egress address keeps `iface_allocs: None`
  and pays nothing.
- `synced.rs` (`reserve_synced_on_first_pool_owner`, PASS 1 only —
  `stop_at_first_owner`): both the address-only and the port-bearing arm
  now also ask `iface_owns_for_pool` (the direct interface-registry
  query) alongside `peer_owns_wire_identity` / statics, rolling back
  into the existing `Refused` outcome. PASS 2 stays byte-identical for
  the same reason #8115 R2 left it alone: before any snapshot resolves
  the zone pair, refusing there rejects every import on the node. The
  caller already threads `iface_allocs` into this function, so the
  registry is the node's live one.
- `synced.rs` (`reserve_synced_interface_identity`): before booking in
  `iface_allocs`, ask `peer_owns_for_interface` over the combined
  `iface_overlap_owners` (with the shipped `r.overlap_owners` fallback
  the local mint uses) and refuse with
  `INTERFACE_SNAT_SYNC_IDENTITY_CONFLICT_DROPS` when a pool/NAT64 peer
  owns the candidate. `rules` is threaded from both call sites (the
  #14674 interface-first route and the PASS 2 `NothingToReserve`
  fall-through). This mirrors the local interface mint's peer check,
  including its precision: PAT occupancy is remote-agnostic,
  address-only tokens are remote-specific.

NOT changed: the local mint paths (#14367 unchanged), PASS 2
semantics, the worker/coordinator bool contracts, release/rollback
keying (a refused synced reserve uses the same `rollback_flow` the
peer/static refusals already use, so nothing is stranded).

## Risk

- A synced import that collides with a local interface/pool/NAT64
  identity is now refused (`RejectedReserve` /
  `INTERFACE_SNAT_SYNC_IDENTITY_CONFLICT_DROPS`) where it previously
  published a duplicate — that session will not survive a failover onto
  this node, which is the observable, fail-closed trade the synced
  refusal machinery (#6600/#8101) already makes for peer-pool
  collisions. No legitimate import is affected: every unowned,
  disjoint, different-port, and different-remote address-only case
  still reserves.
