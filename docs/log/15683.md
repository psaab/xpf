# Issue #15683 — Secondary Fabric (fab1) Omits Physical-Parent ARP/NDP and IPv6 Link-Local Neighbor Fallbacks in refreshFabricFwd1 and Is Excluded from reconcileRGState Takeover Readiness

- **Issue:** `refreshFabricFwd1` (secondary fabric, slot 1) resolved the peer MAC only from the fab1 overlay's address-matched neighbour table. fab0's `refreshFabricFwd` additionally falls back to the physical parent's ARP/NDP (address-matched) and, failing that, to the parent's IPv6 link-local NDP table constrained by `selectFabricPeerLinkLocalMAC` (#6554). After crash recovery or VRF isolation where the IPVLAN overlay cannot resolve but the parent NIC can, fab1 never populated. Separately, `reconcileRGState` computed `fabricReady` from `fabricPopulated` (fab0) only, so fab0-down/fab1-up blocked RG takeover even though fab1 could forward.
- **Context read:** Read the complete #15683 body. Acceptance (report §V35-01 / §2.1.6) names two regression tests: `TestRefreshFabricFwd1ParentARPAndLinkLocalFallback` in `pkg/daemon/daemon_ha_fabric_peer_identity_6554_test.go` using `d.linkByNameFn`/`d.neighListFn` with an empty fab1 overlay table and (a) an address-matched neighbour on `parentIdx`, then (b) a sole `fe80::/10` neighbour on `parentIdx`, asserting `refreshFabricFwd1` returns `true`, sets `d.fabric1Populated = true`, and installs `dataplane.FabricID(1)`; and `TestReconcileRGStateFabricReadyWithFab1Only` verifying `fabricPopulated == false && fabric1Populated == true && PeerAlive() == true` yields `fabricReady = true` in `takeoverReadinessForRG` and marks the RG ready. Synthesis verdict MATERIAL at `f214fac`; spark lane noted the readiness leg is the fab0-only gate in `daemon_ha.go:1482-1490`.
- **What:**
  - `pkg/daemon/daemon_ha_fabric.go` `refreshFabricFwd1`: after the overlay address-matched lookup (which still records slot-1 identity via `rememberFabricPeerMAC(1, …)`), added the slot-0-mirrored fallback: parent-index resolution (`neighLink.ParentIndex`, falling back to the parent link index), parent address-matched ARP/NDP lookup in the peer's family (records identity, logs "fabric1 peer MAC resolved via parent ARP"), then parent IPv6 NDP via `selectFabricPeerLinkLocalMAC(v6Neighs, localMAC, d.fabricPeerMACHint(1))` (logs resolution, throttled refusal via `logFabricRefreshFailure(1, …)` when candidates exist but none is attributable). Fallback results never promote themselves into identity, matching #6554. Removed the stale "fab1 has no link-local fallback leg" comment.
  - `pkg/daemon/daemon_ha.go` `reconcileRGState`: `fabricReady` now reads `fabricPopulated || fabric1Populated`. Single-fabric nodes never set `fabric1Populated`, so the gate is bit-identical there; peer-dead case unchanged (`fabricReady` stays true and `PeerAlive()==false` skips the block).
  - Tests in `pkg/daemon/daemon_ha_fabric_peer_identity_6554_test.go`: `fabricProgramRecorder.programmedIDs()` helper; `fab1PeerTestDaemon` synthetic parent (ge-0-0-1, idx 21) + fab1 overlay (idx 22, ParentIndex 21) with empty overlay table; `TestRefreshFabricFwd1ParentARPAndLinkLocalFallback` with parent-ARP, sole-link-local, and ambiguous-segment-refused subtests; `TestReconcileRGStateFabricReadyWithFab1Only` driving the real `reconcileRGState` (noRethHoldDaemon fixture, peer alive via `HandlePeerHeartbeatForTesting`) with fab1-only ready, neither-populated not-ready control, and fab0-only ready controls.
- **Layer choice:** The fallback belongs in `refreshFabricFwd1` itself, mirroring slot 0, reusing the existing slot-generic identity helpers (`fabricPeerMACHint`/`rememberFabricPeerMAC` slot 1, `selectFabricPeerLinkLocalMAC`, `retainFabricFwdOnNeighborMiss`, `logFabricRefreshFailure`) — no new abstraction. Readiness belongs at the single `fabricReady` computation in `reconcileRGState`, the only caller of `takeoverReadinessForRG` with a fabric term, rather than inside `takeoverReadinessForRG` (whose signature/tests are shared).
