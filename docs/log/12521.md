# #12521 — reject nameless policy-statement terms

- **Issue**: #12521 — nameless routing-policy terms can lose their match
  and action during compilation.
- **Branch**: `fix/12521-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12521`
- **Base**: `bbbbf9dee` (campaign branch base)
- **PR**: #12590

## Why

The base compiler skipped a one-key hierarchical `term` container because it
had no authored term-name token. Strict validation therefore saw an empty
policy, accepted the config, and discarded the body's matches and action;
downstream FRR applied the policy's fallback instead. The gate must reject the
malformed shape before `LoadMerge` lowers it to set paths, including when
packed AST key runs or a candidate-applied group hide the logical path.

## What

- Scan literal `LoadMerge` input before set-path lowering. On a clone, unpack
  multi-key AST heads into logical paths while preserving term-body key runs
  for shape classification. Scan root `policy-options` and every
  `policy-options` subtree under `groups`; do not expand groups because
  references can resolve in the candidate or use `${node}`. Inactive nodes
  remain included.
- Strict compilation and `CommitCheck` reject nameless bodies. Tolerant loads
  warn for every occurrence in stable policy-name and term order, then replace
  each malformed container with one neutral placeholder. A named child in a
  mixed malformed container is not compiled.
- Explicit nested terms inside a one-key `term` container now compile; tolerant
  loads warn with the policy and term names. An explicitly empty `term ""`
  remains base behavior.
- **Not changed**: direct flat-set term semantics and firewall term handling.
  Explicitly named flat-set terms remain supported.

## Risk

Tolerant startup/peer-sync now applies explicitly named nested terms in a
one-key container that the base compiler dropped. Its #12521 warning names
the policy and term so operators can review the changed route behavior.
`LoadMerge` scans literal policy trees before flattening, including inactive
and unapplied group bodies, but does not resolve group references.

Residual parser-shape behavior remains: `term { to { then accept; } }` is
accepted by strict compilation and warns on the tolerant path as nested term
`to`; this unsupported shape is unchanged. A mixed malformed container is
neutralized as a whole, but its warning reports only the first body token
(`then` in the `T` plus `then` probe), not the suppressed nested term name.
Group names are not included in nameless diagnostics, and an empty body is
reported as `starting with ""`; both are cosmetic diagnostic limitations.
No live FRR daemon was exercised; tests inspect generated renderer output.
