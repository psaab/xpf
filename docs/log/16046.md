# #16046 — fsatomic preserve lifts 0644 wholesale; frr.conf secrets stay world-readable

## Defect

`fsatomic.WithPreserveExisting` lifted the existing file mode wholesale
(`mode = fi.Mode().Perm()`), replacing the caller-requested perm. The FRR
writer requests 0640 for `frr.conf` (which carries BGP TCP-MD5 / OSPF /
IS-IS keys, #4484) but always passes `WithPreserveExisting`, so a legacy
0644 `frr.conf` stayed 0644 after every managed apply and routing keys
remained world-readable to any local account. Preserving owner/group is
legitimate (operator ownership must not be overridden); widening mode
past the caller perm is not.

## Fix

In `pkg/fsatomic` `writeFile`, cap the preserved mode at the caller's
perm: `mode = fi.Mode().Perm() & perm`. Preserve can keep a stricter
mode (0600 under a 0640 request stays 0600) but never installs a mode
wider than the caller asked for (0644 & 0640 = 0640). Ownership
preservation is unchanged. `WithPreserveExisting` is called in
production only by `pkg/frr`'s `atomicWriteFile`, so the tightening is
scoped to `frr.conf` writes on the normal apply and zeroize-strip paths.
Docs (`fsatomic.go`, READMEs, `docs/engineering-style.md`, FRR manager
comments) updated to state the capped-mode contract.

Perf: not a dataplane/hot path — config-apply file write only; the fix
is a single bitwise AND on the existing stat result.

## Validation

- `TestPreserveExistingNeverWidensBeyondCallerPerm` (fsatomic): seeded
  0644/0600/0640/0777 rows under narrower perms; wider rows capped,
  stricter kept. RED on revert (0644 and 0777 rows fail).
- `TestFRRConfLegacy0644TightenedTo0640` (frr, decisive regression):
  seed a pre-existing 0644 `frr.conf` with a routing-auth leaf, run the
  next `writeManagedSection` apply → file lands 0640 (group read kept,
  world read stripped). RED on revert (stays 0644).
- Existing `TestPreserveExistingMode`, `TestFRRConfPreservesOperatorMode`
  (0600 kept), fresh-create 0640, and owner-opt decision tests still pass.
- `go vet ./pkg/fsatomic/ ./pkg/frr/` clean; `gofmt` clean.
- Full package runs show only pre-existing failures identical on
  unmodified `origin/master` (fsatomic canary, FRR vtysh-dependent BGP
  tests).

## Risk

Only caller is `frr.conf`; tightening 0644→0640 keeps owner and preserved
group read (0640 root:frr on fresh, preserved group on existing), so
FRR daemons keep reading the file. An operator who deliberately chose a
mode wider than 0640 loses the extra bits on the next apply — intended,
since the managed section carries secrets the operator did not author.
