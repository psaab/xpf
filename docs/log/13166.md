# #13166 - fail closed on RX-VLAN errors for RETH members

- **Timestamp**: 2026-10-15
- **Action**: Extend the #5268 VLAN-subinterface predicate to inspect the logical RETH parent for a physical interface with `RedundantParent`. Physical members disable RX-VLAN offload; their VLAN units may exist only on the parent RETH. The existing `mapZoneInterface` path runs this check once per physical ifindex and latches `st.attached`, so a missed member-level VLAN condition suppresses a later check from a RETH unit.
- **Validation**: `go test -run '^TestParentHasVlanSubinterfaceRethMember_13166$' ./pkg/dataplane -count=1` failed before the fix on pristine `origin/master` `ab0498643` with `RETH member must inherit reth0 VLAN subinterfaces via RedundantParent`; it passed after the fix. `go test ./pkg/dataplane/ -count=1` passed (`ok`, 110.371s). `go vet ./pkg/dataplane/` passed.
- **Risk**: An RX-VLAN offload failure now fails activation closed on physical RETH members whenever their logical RETH parent contains a configured VLAN unit. Plain RETH members without VLAN units retain the existing tolerant behavior.
