# #16689 — userspace_ingress_domains_vlan sync wrote new rows before deleting stale ones

## Defect
`syncIngressDomainMapLocked`
(`pkg/dataplane/userspace/maps_sync.go`) updated every desired row
into the pinned `userspace_ingress_domains_vlan` hash (8192 entries,
`userspace-xdp/src/lib.rs`) and only then deleted stale rows, so peak
occupancy was `len(current ∪ desired)`, not `len(desired)`.
`checkIngressDomainCapacity` preflights only `len(desired)`, so an
accepted VLAN re-plan (about 2 rows per VLAN unit; roughly 2,050+
units renumbered at once, or a near-capacity plan plus a modest
change) whose union with the pinned plan exceeded 8192 hit E2BIG on
a new-key insert. On the same-plan path the error was not the
capacity-preflight message, so
`syncUserspaceClassifierMapsFailClosedLocked` drove ctrl to
Enabled=0: all transit dropped until the ~1 s status tick re-synced
the old plan, and the commit stayed in the store unapplied. On the
bootstrap path (`programBootstrapMapsLocked`, every non-same-plan
apply and daemon restart) ctrl was already written Enabled=0 before
the sync, so the pinned over-union plan wedged the box at the next
restart until rollback, reboot or a manual unpin. This broke the
#13724/#14842 contract: a plan the preflight accepts must be
programmable, and a plan that cannot be programmed must leave the
old plan forwarding.

## Fix
- `syncIngressDomainMapLocked` now routes through the #13724
  prune-first `reconcileAddressMapKeys`: stale rows (present in the
  live map, absent from desired) are deleted before any desired row
  is written, so peak occupancy is
  `max(len(current), len(desired))`.
- `syncIngressIfaceMapLocked` prunes stale
  `userspace_ingress_ifaces` rows before installing any new ingress
  row, so that bounded hash likewise never needs union occupancy
  during a re-plan. If the prune fails before any install, the
  #6537 retry-debt inventory (`retainDebt`) is preserved; rows
  installed before a later domain-sync failure are still recorded
  first (#13929).
- No capacity, preflight, or fail-closed gate was weakened: an
  over-capacity desired plan is still refused before any write with
  ctrl left unchanged, and non-capacity sync errors still fail
  closed.

## Risk
The only behaviour delta is ordering inside one apply: during a
re-plan, stale domain/iface rows disappear a few map operations
earlier than before. Rows that remain in the desired plan are
rewritten with the same values, and a mid-sync failure still leaves
the caller to fail closed (same-plan) or abort bring-up before the
helper starts (bootstrap) exactly as before — no fail-open
direction is introduced.
