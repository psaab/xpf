# #12215 — set-form named address-book collision quarantine

- **Timestamp**: 2026-10-07 (`fix/12215-addrbook-quarantine`)

## Why

`SetPath` stores an unsupported named address-book set-form entry such as `set security address-book red address shared 10.0.0.0/8` as one packed leaf. The tolerant collision recorder only walked `address` and `address-set` children, so it missed that definition; a policy reference then resolved to the unrelated global `shared` entry instead of being refused.

## What

The recorder now recognizes a packed named-book leaf whose second key is `address` or `address-set` and quarantines only the defined name (the third key). Trailing address values and address-set member references are not mistaken for entry names. Added regression coverage for both set-form address and address-set collisions; it checks `CollidingNames`, sentinel refusal in both source policy fields, and the rejection mirror. The existing braced #12049 control remains unchanged.
