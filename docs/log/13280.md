# #13280 — Preserve Rust operational counters through Go status and Prometheus

Source: deep-review `D3-01`, run `review-work.AYgyxCmMxC`, report
`gemini-4-argon-high-review-monitoring-telemetry-prometheus-missing-stats-001.md`.
The three-way research gate validated the defect.

## Root cause

Rust `ProcessStatus` emitted fifteen operational/HA status fields that were
absent from Go's `ProcessStatus`. `encoding/json` ignores unknown object keys,
so every Go status poll silently discarded the values. The missing payload
included CoS ownerless drops, io_uring write refusals, route-change failures,
owner-RG filing declines, HA transition queue outcomes, session/NAT reservation
release guards, synced-reverse derivation, and the S5 reinject status block.

## Change

- Add the fourteen scalar counters and the typed S5 reinject object (including
  its provenance rows) to Go `ProcessStatus` with matching JSON tags.
- Add `TestProcessStatusD301OperationalCountersDecode`, which decodes distinct
  Rust-shaped counter values and the S5 provenance's array-valued byte digest.
- Export the scalar counters as unconditional Prometheus counters, with `op`
  labels for HA transition drops and stale skips. Export S5 reinjections only
  when the helper supplies the S5 status object.
- Add `TestUserspaceOperationalAndHACountersEmit13280` to verify distinct
  metric values and the HA labels.
