# #14405 - SNMPv3 #9155 gate evaded by ancestor-packed `v3/usm` and descendant flat-chain protocol keywords

- **Timestamp**: 2026-10-16
- **Action**: `validateSNMPv3SecurityKeywordStrict` in `pkg/config/compiler_validate_strict_snmpv3_level_9155.go` walked a fixed direct-child chain (`snmp -> v3 -> usm -> local-engine -> user`) and `checkSNMPv3UserKeywords9155` inspected only a user's `Keys[2:]` tail plus direct children's Keys. The compiler expands packed ancestors with `packedBodyChildren` (`compileSNMPv3`, `pkg/config/compiler_system.go`) and hoists descendant flat-chain statements with `hoistAndSplitRun8939`, so `snmp { v3 usm { local-engine { user alice { authentication-sha512 ... } } } }`, `snmp { v3 { usm local-engine { user alice { authentication-sha512 ... } } } }`, and `set snmp v3 usm local-engine user alice authentication-sha256 authentication-password A privacy-foo privacy-password P` (privacy keyword a grandchild of the user) all committed while the unknown protocol was dropped, serving the user below its configured level. The gate now expands each level with `packedBodyChildren` using the compiler's schema paths (`snmp`, `snmp/v3`, `snmp/v3/usm`, plus the engine level for fully-packed tails), and the per-user check hoists children with `hoistAndSplitRun8939` and additionally scans every descendant token — unknown `authentication-*`/`privacy-*` heads do not resolve as user-schema leaves, so the hoist alone leaves them nested. `rejectUnknownSNMPv3Keyword9155`, the known-keyword tables, error text, the password-leaf exemption, and the lenient warn dispatch are unchanged.
- **Validation**: New `pkg/config/snmpv3_ancestor_packed_14405_test.go`: three evasion spellings (ancestor-packed unknown auth, usm-packed unknown auth, ancestor-packed unknown privacy) + fully-nested control + descendant flat-chain unknown privacy/auth variants + known auth+privacy controls (flat-set and ancestor-packed) + lenient-warn cell. RED on master: evasions committed clean, lenient warnings empty. GREEN post-fix; fail-on-revert verified by stashing the gate fix (all new tests RED again). Existing #9155 suite (`TestSNMPv3SecurityLevelCommitTable9155`, flat-set, tolerant-ingress) and all SNMP-pattern tests green; `go vet` and `gofmt` clean.
- **Risk**: Reject-only gate widened to shapes the compiler already creates users from; a false rejection would be loud and is covered by known-protocol controls in both packed and flat spellings. Descendant scan only fires on `authentication-*`/`privacy-*` prefixed tokens (password leaves exempted), so authored values cannot trip it.
