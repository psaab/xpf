# Issue #15202 — BGP `remove-private` renders the all-private-only FRR spelling (A11-05)

## Why

Junos `remove-private` strips private AS numbers from the advertised
AS path starting at the head (most-recently-prepended end) and stops
at the first non-private AS — so on a mixed path such as
`65000 3356` the private `65000` is removed even though a public AS
follows it. `renderBGPRemovePrivate14585`
(`pkg/frr/bgp_cross_field_14585.go`) emitted the bare FRR spelling
`neighbor X remove-private-AS`, which strips private ASNs only when
the entire AS path is private. A mixed private-then-public path
therefore leaked the private ASN upstream; upstreams that filter
private ASNs drop the route, so the loss is reachability only (no
enforcement or isolation loss on the firewall).

## What

- `renderBGPRemovePrivate14585` now emits
  `neighbor X remove-private-AS all`, the FRR spelling that removes
  private ASNs from anywhere in the path. The renderer comment and
  `pkg/frr/README.md` document the residual differences, neither of
  which is expressible in FRR's CLI: FRR `all` also strips a private
  run that is not at the head of the path (Junos stops at the first
  non-private or peer AS), and Junos withholds stripping when the
  path contains the eBGP peer's own AS.
- New regression `pkg/frr/bgp_remove_private_all_15202_test.go`:
  IPv4 and IPv6 eBGP neighbors must render `remove-private-AS all`,
  the bare spelling must never appear, the #14585 iBGP omission and
  a neighbor without the flag stay unchanged, and the rendered
  config passes the local `vtysh -C` grammar check with an
  invalid-keyword negative control.
- Updated the two pre-existing exact-spelling expectations
  (`bgp_cross_field_14585_test.go`, `frr_test.go`) to the `all`
  spelling.
- NOT changed: the Junos config model (no new knob — the issue's
  "model `remove-private all`" is realised as this render, since
  `remove-private` in Junos already means the head-run strip), the
  #14585 iBGP cross-field gate, or any other neighbor attribute.

## Validation

- RED on `origin/master` (64947247d1): the new test failed with
  `neighbor 10.0.0.4 remove-private-AS` (no `all`) in the IPv4 block
  and `neighbor 2001:db8::4 remove-private-AS` in the IPv6 block.
- GREEN after the fix: `go test ./pkg/frr -run
  'TestRenderBGPRemovePrivateAll15202|TestRenderCrossField14585|TestGenerateProtocols_BGPRemovePrivateAS|TestGenerateProtocols_BGPNeighborAttributesAreAddressFamilyScoped11460|TestBGPKeywordNamedPolicyRendersRouteMap15137'
  -count=1` passes, including the `vtysh -C` leg (the local FRR 10.6
  grammar accepts `remove-private-AS all` and rejects the invalid
  control; verified independently with `vtysh -C -f` probes).
- Full `go test ./pkg/frr -count=1`: 4 failures
  (`TestBGPNoExportNeighborGetsDefaultExport15157`,
  `TestFamilylessIPv6NeighborWithoutPolicyIsV6Only11564`,
  `TestFRRLoadInet6OnlyNeighborIPv4Deactivation11374`,
  `TestFRRLoadBGPClasslessRIBSuppression11426`) that fail
  identically with the fix stashed on the base tip — base-attributed
  (VTY/socket environment), untouched here.
- `gofmt -l` on the changed Go files is empty; `go vet ./pkg/frr`
  is clean.

## Risk

Behaviour changes only for eBGP neighbors carrying `remove-private`:
advertised paths now lose private ASNs in mixed paths, matching
Junos. The residual differences above are documented; no config
syntax or schema changes, so no stored config is invalidated.
