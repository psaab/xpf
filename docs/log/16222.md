# Issue #16222 — split-RG FabricRedirect evicted per-packet on fw0

## Finding

On PR #16217 head `573a6087f0`, the split posture (RG1/WAN primary
fw0, RG2/LAN primary fw1) starved pre-failover: sender collapsed to
0.00 bits/sec for all 4 P4 streams after ~22 s, with
`fabric_local_wins` (different-owner) flow-cache evictions churning
~25k/s on fw0 (276,547 → 532,108, then freezing exactly as tuples
died). The both-RGs-on-fw0 arm was healthy (18.3 Gbps, 0 evictions).
Fabric pcaps carried zero data frames: starved packets never entered
the fabric.

Mechanism: fw0 fabric-ingress cache hits revalidated the cached
`FabricRedirect` in `cached_flow_decision_invalid_reason`
(`forwarding/ha.rs`) with a destination-only FIB lookup, while the
session path resolves per-flow (`lookup_..._for_flow` /
`lookup_..._for_nat_flow`, per-flow ECMP hash in `fib.rs`). The cached
stamp owner comes from stored session metadata (the LAN/ingress leg),
the local candidate's owner from the WAN egress leg — different-owner
by construction — so every hit evicted as `FabricLocalWins`, re-seeded
via the session-hit slow path, and evicted again.

## Fix

- `cached_flow_decision_invalid_reason_for_flow` (new per-flow entry
  point): the local candidate is resolved with the per-flow ECMP hash
  over the packet's 5-tuple (`lookup_forwarding_resolution_with_dynamic_for_flow[_in_table]`),
  with `target_ip` already the NAT-translated target
  (`resolution_target_for_session` at the caller) — the same resolution
  the session path produces for that flow.
- On fabric ingress, a local candidate owned by a DIFFERENT RG than
  the cached stamp does not supersede the redirect: the stamp names
  the ingress/LAN leg, the candidate the WAN egress leg; they are not
  alternatives for this packet. Same-owner fabric ingress still
  re-resolves (`OwnerActiveRedirect` / `FabricLocalWinsSameOwner`
  semantics preserved), and direct-ingress different-owner supersession
  is unchanged.
- The generic `FabricIngressLocalWins` prefer-local probe no longer
  re-judges a `FabricRedirect` the redirect arm already retained
  (it re-derived the same candidate and evicted under a second name).
  A per-flow twin `prefer_local_forward_candidate_for_fabric_ingress_for_flow`
  serves the remaining fabric-ingress revalidation.
- Production wiring: `stage_flow_cache_hit` now calls the per-flow
  entry point with `flow.forward_key`.

Regression coverage: `fabric_ingress_redirect_per_flow_revalidation_keeps_split_rg_16222`
(ECMP legs on different RGs; destination-only vs per-flow selection
diverge; per-flow revalidation serves the redirect),
`fabric_ingress_different_owner_does_not_evict_16222` (different-owner
retention + same-owner failback control), and
`fabric_stamp_ingress_serves_cached_redirect_16222` (stage-level:
second packet Consumed, `PostHitFabricLocalWins` arm at 0).

## Round 2 (option B + DISC observability)

Round 1 (per-flow revalidation + fabric-ingress retention) was a correct
half: live split-posture still starved (all streams 0.00 from 21 s,
`fabric_local_wins` 0 → 337,705 on fw0). The evicting entries on fw0 are
locally-seeded `FabricRedirect` stamps (owner != WAN RG1) served on
LAN/WAN members — not fabric-ingress arrivals — so the fabric-ingress
retention never engaged.

- DISC observability: `stage_flow_cache_hit` emits a debug-log
  `DISC16222` per-tuple line (tuple-gated on
  `10.0.61.102 -> 172.16.80.200:5211`): seeded decision kind, stamp
  owner RG, stored resolution, local candidate owner, invalid reason,
  and cache outcome (serve/evict) per packet. `debug-log` builds only
  (the production deb builds with `--features debug-log`).
- Option B fix: a cached `FabricRedirect` is judged against its stored
  resolution context. A different-owner local candidate supersedes it
  ONLY if it serves the flow locally — i.e. the per-flow session
  resolution for this flow is that ForwardCandidate with a local egress
  — never merely for being local/different-owner. Direct-ingress
  different-owner eviction of a cached redirect is retired; same-owner
  failback (`OwnerActiveRedirect` / `FabricLocalWinsSameOwner`) and the
  fabric-ingress retention are preserved.
- Regression: `direct_member_fabric_redirect_owner_mismatch_kept_16222`
  (decision level: direct member ingress, FabricRedirect stamp, owner
  mismatch RG2 vs WAN RG1) and
  `direct_member_ingress_serves_cached_redirect_owner_mismatch_16222`
  (stage level: second packet Consumed, `PostHitFabricLocalWins` arm 0).
