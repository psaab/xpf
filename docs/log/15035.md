# #15035 — `vlan-tags outer N` accepted as a tag but never compiled; unit becomes untagged

## Defect

A unit carrying `vlan-tags outer N` (N > 0, no inner tag) was counted as a
positive tag by both gates — the #5879 QinQ gate treats an outer-only
`vlan-tags` as a single S-tag (`compiler_interfaces_qinq.go`
`unitVLANStack`), and the #14574 gate requires `vlan-tagging` /
`flexible-vlan-tagging` for it (`compiler_interfaces_vlan_tagging.go`
`positiveTagStmts` / `vlanTagsOuterPositive`) — but `compileInterfaces`
only read the `vlan-id` leaf. The outer value had no compiler consumer,
so the unit compiled with `VlanID=0` (untagged) on a green commit.

Consequence: tagged traffic for the unit is lost (the address answers on
the untagged wire instead of `<parent>.N`), and on unit 0 untagged frames
gain the unit's zone — a posture the operator never configured.

Probe on base: `vlan-tags outer 100` flat, hierarchical (`vlan-tags outer
100;`), and block (`vlan-tags { outer 100; }`) shapes all compiled
`VlanID=0`; the `vlan-id 100` control compiled `VlanID=100`.

## Fix

`compileInterfaces` (`pkg/config/compiler_interfaces.go`) now compiles an
outer-only `vlan-tags` into `VlanID`, mirroring the `vlan-id` reader:

- New helpers `vlanTagsOuterValue15035` (extracts the value after the
  `outer` keyword across packed-Keys, hierarchical-child, and
  one-deeper `outer { 100; }` shapes) and `parseVlanTagsOuter15035`
  (TPID-prefix reject + the shared #9899 canonical-digits 0..4094 parse).
- Every `vlan-tags` sibling is walked; a node carrying an `inner` keyword
  is skipped (strict compile never reaches it — the #5879 gate rejects
  first; the lenient path keeps its historical shape, outer dropped with
  the #5879 warning only).
- TPID-prefixed values (`0x88a8.100`, `0x8100.100` — the Junos TPID.VID
  form) are rejected: the single-tag dataplane cannot represent a
  non-802.1Q tag protocol, and silently compiling the bare VID would
  claim a tag protocol that is not enforced. The message names
  `vlan-tags` and `#15035` with the remedy.
- Malformed / out-of-range / missing outer values fail closed with the
  same bounds contract as `vlan-id`; on the lenient path they warn and
  quarantine the unit (shared `skipUnit9899`, now declared at unit scope)
  exactly as a malformed `vlan-id` does (#1960 no-brick: the unit is
  skipped, siblings survive — never silently untagged).
- `vlan-id` on the same unit wins over a later `vlan-tags outer`
  (first-spelling-wins, tracked via `vlanTagsSeen` so `outer 0` counts);
  repeated outer-only statements are first-wins likewise.

NOT changed: the gates (#5879/#14574 already counted the spelling
correctly), the schema (`vlan-tags` stays intentionally unadvertised),
and the dataplane writers (they already honour `VlanID`).

## Risk

Strict commits that previously (silently, wrongly) accepted a
TPID-prefixed or malformed `vlan-tags outer` now fail with a remedy
message. Outer-only configs that were silently untagged now compile to
their authored tag — the behaviour the gates already promised. Lenient
loads keep booting: valid outer values now take effect, malformed ones
quarantine the unit with a warning instead of silently untagging it.
