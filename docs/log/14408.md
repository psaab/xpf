# Issue #14408 — CLI `show security match-policies` priced PermView, gRPC/REST price PermControl

## Why

The local CLI priced every `show` at `PermView` (`requiredPermission`,
`pkg/cli/permissions.go`), with the rollback-compare `PermConfig`
elevation as the only `show` special case. `show security
match-policies` therefore reached the shared `policymatch.Match`
simulator (`cli_show_security_dispatch.go`: `case "match-policies"`)
with no further permission check, so a `read-only` / `config-viewer`
(PermView-only) console user could probe arbitrary 5-tuples and learn
the matched policy name/ID, addresses, applications, description and
action. The same simulator is priced `PermControl` on gRPC
(`methodPermissions["MatchPolicies"]`, #11077, "policy reconnaissance
gated from read-only classes") and REST
(`restReadPermissions["GET /api/v1/security/match"]`, #11674), and the
gRPC command table maps the RPC to the same canonical command string
`"show security match-policies"` — only the CLI coarse tier differed.

## What

- `pkg/cli/permissions.go`: new `showSecurityMatchPolicies(args)`
  helper resolving `args[0]`→`security`, `args[1]`→`match-policies`
  through `operationalTree["show"]` via `resolveCommand` (same shape
  as `showSystemRollbackCompare` / `requestSubcommandIsConfig`), so
  unambiguous abbreviations (`show sec match-p`, `show security m`)
  gate identically and unresolvable/ambiguous tokens return false.
  `requiredPermission` returns `config.PermControl` for that command
  before the `show → PermView` arm.
- New regression `pkg/cli/permissions_matchpolicies_14408_test.go`:
  price table (full/bare/abbreviated spellings = PermControl; sibling
  `show security policies|zones`, `show version`, bare/unknown
  `show security` = PermView), per-class `checkPermission` (read-only
  and config-viewer denied; operator and super-user admitted; unset
  class keeps legacy allow-everything), and an end-to-end
  `dispatchOperational` cell (read-only/config-viewer denied with no
  verdict leak; operator reaches the simulator and gets the matched
  `recon-canary-14408` verdict; read-only `show security policies`
  control still served). The three-surface parity is anchored by the
  existing gRPC `TestSimulatorCostsControlOnBothSurfaces_11077` and
  REST `TestMatchPoliciesRESTCostsControl_11674` tests, both re-run
  green; the CLI price now equals both (PermControl).
- NOT changed: every other `show` stays PermView; `test policy` stays
  PermControl via the `test` arm; the dispatcher in
  `cli_show_security_dispatch.go` needs no change (the gate is the
  price); `checkCommandRegex` is untouched (it only evaluates when a
  class configures allow/deny regexes, which the built-in classes do
  not, so the coarse price is the whole gate).

## Risk

Only `show security match-policies` (and its unambiguous
abbreviations, which the dispatcher resolves to the same handler)
moves from PermView to PermControl. PermView-only classes lose console
access to the simulator — the intended #11077/#11674 posture already
enforced on gRPC/REST; operator, super-user and the unset-class legacy
mode are unaffected, and all other `show` commands keep their price.
