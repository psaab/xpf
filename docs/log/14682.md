# #14682 - validateFirewallFilterFamilyAnyMatchesAST walks raw AST, bypassing #4296/#4426 under family any

- **Timestamp**: 2026-10-17
- **Action**: `validateFirewallFilterFamilyAnyMatchesAST`
  (pkg/config/compiler_firewall.go) now finds `from` statements with
  `firewallTermFromNodes` and lowers each with `packedBody` under the
  from-schema — the same readers compileFirewall, the #8480 gate and the
  #12528 gate use — instead of the raw
  `termInst.node.FindChildren("from")` + `fromNode.Children` walk. The
  compact normalizer deliberately excludes `(term,from)` and omits the
  prefix-list leaves from its `from` fold list, so compact term bodies
  (`term t from icmp-type echo-request then discard;`) and one-line
  `from` statements (`from source-prefix-list v4only;`) presented zero
  children to the validator and the #4296/#4426 gates never fired under
  `family any`, while dual-compilation installed the v4-only match into
  both pools where it can never match v6. Schemas resolve from `af`
  with the inet fallback the sibling gates use. Removed the four
  `firewall family any ... from {source,destination}-address/icmp-{type,code}`
  entries from `knownFixtureLimited8690`: they are now measurable
  (rejected identically with the compact pass off and on, because the
  validator itself packed-reads), so the #8690 equality assertion
  requires the list to shrink.
- **Validation**: RED on `origin/master` 91d5ccc48c — new
  `TestFirewallFamilyAnyCompactAndPackedFromRejected` (compact icmp-type,
  one-line source-prefix-list, compact source-prefix-list) all compiled
  clean and the lenient-warn cell found no #4296 warning. GREEN after
  the fix: the named test (4 cells incl. one-line source-address),
  `TestFirewallFamilyAnyCompactICMPLenientWarns14682`,
  `TestFirewallFamilyAnyCompactControlsCommit14682` (compact protocol and
  mixed prefix-list still commit and dual-install), plus the #4296/#4426/
  #13209/#14446 family suites,
  `TestCompactNormalizeScopePreservesCompiledResult8690` and
  `TestSlotEscapeCoverage` — all pass on the final rebased head.
  Full `pkg/config` runs exceed the 25m package timeout under campaign
  CPU contention; the failures observed there
  (`TestCompactBlockEquivalenceInventory2419`, IPsec/plaintext/auth-key
  cells) reproduce identically on unmodified `origin/master`
  a65ab30b55, i.e. base-attributed, not this change.
- **Risk**: Only the validator's view changes; compileFirewall's output
  is untouched. Terms whose packed `from` was previously invisible now
  reject (strict) / warn (lenient) exactly as their braced spellings
