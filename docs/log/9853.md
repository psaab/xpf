# #9853 — takeover pre-seed re-injected stale backup memfile rows

- **PR**: https://github.com/psaab/xpf/pull/10148

## Defect

`PreSeedMemfileMerged4` and `PreSeedMemfileMerged6` preserve the local-plus-peer
union needed by #5040's active-active takeover path. On a pure backup, however,
Kea is stopped and the local read falls back to its persisted memfile. That file
is only the last lease set this node served. The former primary can have released
rows since then, but the fallback rows were unconditionally merged and written
back into the promoted Kea memfile.

The stale binding kept a released address unavailable until its old valid
lifetime expired and could let the old client identity reclaim the address.

## Prior-lane evidence

The untracked `.9853-evidence/` bundle was read before implementation. Its
`9853-authority-probe.go` measured the existing fallback/LFC behavior with a
missing Kea socket: active rows in `.1` and `.2` remained in the effective set
when the current file was header-only, for both v4 and v6. It also confirmed
that the public peer-family accessor did not distinguish never-received from
received-empty snapshots. The bundle's earlier unscoped RG-subtraction plan
was plan-killed because the current wire/API has no served-scope authority.
The scratch bundle is intentionally not committed.

## Change

- `getSyncLeasesWithSource` retains the existing socket-first/memfile-fallback
  behavior while reporting whether the socket supplied the set.
- Merged takeover pre-seed preserves the local-plus-peer union for the live
  `lease_cmds` socket path and for a guarded fallback when another RG remains
  MASTER. Only a pure-backup fallback excludes persisted local rows.
  When Kea is down during a staggered active-active transition, the fallback
  union is preserved and LFC generations are left intact; only a pure-backup
  takeover may exclude fallback rows and remove stale `.1`, `.2`, and
  `.completed` generations.
- When the socket is unavailable on a pure backup, the fallback memfile is
  still parsed so a corrupt/untrusted source retains the existing fail-closed
  error, but valid fallback rows are not merged; the peer set is written.
- Fallback-only replacement removes `.2`, `.1`, and `.completed` after the
  durable current-file replacement, then fsyncs the directory. All removal
  errors are joined after every attempt, so one failure cannot hide cleanup
  errors or prevent later attempts.
- Upstream Kea `memfile_lease_mgr.cc::loadLeasesFromFiles` loads the
  lease-bearing `.completed` output before `.2`/`.1`; `lfc_controller.cc`
  `fileRotate` removes `.2` and `.1` before renaming `.completed` to `.2`.
  This source-backed crash window is why pure-backup cleanup removes the
  orphan even though the in-tree display/DDNS reader still skips it.
- The live-socket union path keeps the normal LFC lifecycle and does not remove
  its generations.

## Regression guard

`TestPreSeedMemfileMerged_DropsFallbackMemfileLeases9853` covers v4 and v6,
with the stale row placed in `.1`, `.2`, and `.completed` in separate
subtests. That is `2 families × 3 generations = six` leaves. Each assertion
requires the released address to be absent, the valid peer address to be
present, and the stale generation file to be removed.

`TestPreSeedMemfileMerged4_PreservesLocalLeases` and
`TestPreSeedMemfileMerged6_PreservesLocalLeases` are the live-socket
active-active guards: a valid local RG-X row and a valid peer RG-Y row both
survive the merge in each family.

`TestPreSeedMemfileMerged_StaggeredFailoverPreservesStillMastered9853` adds
two F1 leaves (v4 and v6). While Kea is down for an earlier RG restart, the
fallback union preserves the already-MASTER RG-X row and leaves `.1` intact
while adding the later RG's peer row. The daemon-level
`TestMasterEdgePassesStillMasteringToPreSeed9853` asserts both family calls
receive the state that selects this preservation path. Thus the stale-row
and staggered family matrix has eight leaves total: six pure-backup leaves plus
two still-mastering leaves.

`TestRemoveLFCGenerationsAttemptsBoth` proves cleanup attempts `.2`, `.1`, and
`.completed` and joins all removal errors instead of returning after the first
failure. `TestRemoveLFCGenerationsRemovesCompleted9853` proves the helper
deletes a lease-bearing orphan, while the expanded pure-backup matrix exercises
that deletion through `PreSeedMemfileMerged{4,6}`.

The verified trigger path is source-backed: VRRP marks the transitioning RG
active before calling `applyRethServicesForRG` (`daemon_ha.go:1022-1044`);
that function computes the sibling-master state and pre-seeds synchronously
(`daemon_ha.go:1761-1792`) before enqueueing `ApplyAsync` at line 1798.

Mutation proof for the guards:

1. Replacing fallback exclusion with unconditional local-plus-peer merging
   made the four `.1`/`.2` pure-backup leaves fail because stale rows were
   re-injected; the two `.completed` leaves still exercised cleanup.
2. Removing pure-backup `.1`/`.2`/`.completed` replacement made all six
   pure-backup leaves fail because stale generations remained or survived.
3. Removing the manager still-mastering preservation branch made both
   staggered family leaves fail. Separately forcing the daemon argument to
   false made the daemon wiring assertion fail.
4. Removing `.completed` cleanup made
   `TestRemoveLFCGenerationsRemovesCompleted9853` fail.
5. Early-returning after the first LFC unlink omitted `.1`; restoring all
   guards made every affected test pass.

## Known limitation

The daemon now closes the identified Kea-down staggered-failover race by
preserving the fallback union whenever another RG is still MASTER. The
remaining authority limitation is granularity: `stillMastering` is bounded
node-level state, while the fallback memfile and peer snapshot carry no
served-scope/RG ownership mapping. The preservation path therefore keeps all
fallback rows conservatively, including a row another RG may have released,
and pure-backup exclusion can address only the whole fallback set.

There is also a reader gap outside this fold. The in-tree display/DDNS parser
intentionally omits `.completed`; upstream Kea startup loads that file in
preference to `.2`/`.1`. If Kea removes `.2` and `.1` then crashes before
renaming `.completed` to `.2`, the reader can miss leases that exist only in
`.completed`. This PR removes the orphan during pure-backup replacement before
promoted Kea starts; parser recovery remains follow-up work.

Pre-seed is gated on a non-empty peer snapshot. The daemon's `len(leases)>0`
gate cannot distinguish never-received from received-empty authority, so an
empty authoritative peer set does not invoke peer-only cleanup. This fold
makes no claim to clean or replace the current/LFC memfile for that case.

## Follow-up draft (parent-owned at merge)

The deeper fix should add served-scope/RG authority to lease-sync state and
carry an ownership generation with each peer snapshot. The daemon can then
prove which local rows belong to RGs that remain MASTER, compare that
authority with the peer generation, and allow negative stale-row exclusion
only after a successful Kea apply for the affected scope. The reader should
also recover an orphaned lease-bearing `.completed` or coordinate its source
selection with Kea's startup precedence. A received-empty snapshot should
carry an explicit generation/authority marker rather than being conflated
with never-received. Until that contract exists, this PR keeps conservative
whole-union behavior whenever any other RG remains MASTER.

No real Kea restart or cluster failover was performed for this PR; the measured
reproduction and post-fix proof are temporary Go probes plus package tests.
