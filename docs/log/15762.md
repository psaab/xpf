# #15762 — `vrrp-inet6-group` bypasses VRRP authentication / collection / misplaced-auth / track gates

- **Issue**: #15762 — the Junos `vrrp-inet6-group` alias compiled (via `parseVRRPGroups`) but bypassed `validateVRRPAuthenticationAST`, `collectVRRPGroups`, `vrrpMisplacedAuth`, and `validateVRRPTrackInterfaceAST`, all keyed only on `vrrp-group` (#15199 residual, G5-01).
- **Files**: `pkg/config/compiler_interfaces.go`, `pkg/config/vrrp_inet6_alias_gates_15762_test.go`, `debian/changelog`, `docs/log/15762.md`.

## Why

`parseVRRPGroups` merges `vrrp-group` and `vrrp-inet6-group` into the same keyed `VRRPGroup`, and `validateVRRPGroupChildrenAST15046` already handled the alias — but the four gates above matched `n.Name() == "vrrp-group"` only. So `vrrp-inet6-group 1 authentication-type md5` / `authentication-key <k>` escaped the #4288 strict reject and the #5834 lenient fail-closed drop (the group activated and claimed the VIP with unauthenticated RFC 5798 adverts — the false-security class), misplaced auth on an ancestor of an inet6-only group escaped #14403 (its collector never collected the inet6 group), and duplicate `track-interface` under the alias escaped the #1814 single-track gate.

## What

- Added `isVRRPGroupNodeName(name string) bool` (`vrrp-group` || `vrrp-inet6-group`) in `pkg/config/compiler_interfaces.go` beside `parseVRRPGroups`, per the report's fix direction.
- Used it at the four cited sites: `validateVRRPTrackInterfaceAST`, the direct-child scan in `validateVRRPAuthenticationAST`, `collectVRRPGroups`, and the self-guard in `vrrpMisplacedAuth`. No other behaviour changes; the already-alias-aware `#15046` children gate is untouched.

## Validation

- RED (pre-fix): `go test ./pkg/config -run '15762' -count=1` — 4 of 5 behavioural tests fail on the unmodified tree (strict auth accepted, lenient auth silent, misplaced-auth group left active, duplicate track accepted); the clean-group control passes both ways.
- GREEN: same command passes all 15762 tests (strict reject flat+hierarchical without leaking the key, lenient drop+warn, misplaced strict/lenient, duplicate-track strict/lenient first-wins, helper pin).
- Neighbours: `go test ./pkg/config -run '15762|VRRP|15199' -count=1` — only two pre-existing failures remain, both verified identical on pristine `origin/master` (`TestRethRedundancyGroupIDOverflowSkippedUnderNoRethVRRP`, `TestVRRPCrossGroupDifferentInterfacesCommits`); all VRRP/15199/15762 tests otherwise pass.

## Risk

Strict commits now reject inet6-spelled auth / duplicate track statements that previously committed silently; tolerant load / peer-sync drops the auth-carrying inet6 group with a warning and prunes duplicate tracks first-wins, matching the existing `vrrp-group` posture (#1960 no-brick: base address survives). Clean `vrrp-inet6-group` configs are unaffected (pinned by `TestVRRPInet6CleanGroupCommits15762` and the existing #15199 suite).
