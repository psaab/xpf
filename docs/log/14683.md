# #14683 — QinQ gate misses two-level `unit { 0 { inner-vlan-id } }` and apply-groups forms

The #5879 canonical QinQ gate (`validateQinQVLANStackAST`) iterated only
direct `unit` children of each interface and read only direct vlan leaves
of each unit. The compiler instead enumerates units with
`namedInstances(FindChildren("unit"))`, which descends into the two-level
hierarchical form `unit { 0 { vlan-id 100; inner-vlan-id 200; } }`, and
unpacks packed unit tails with `packedBody`, which hoists a vlan leaf
nested under a packed child (flat `unit 0 point-to-point inner-vlan-id
200`). Both forms therefore compiled both tags (probe on base:
two-level lenient `VlanID=100 InnerVlanID=200` with no QinQ warning;
flat-nested lenient compiled the inner tag likewise) while the gate saw
an empty stack — a committed double-tagged unit the AF_XDP dataplane
cannot firewall (`parse_l2` peels one tag; the frame `XDP_PASS`es). The
apply-groups variant missed for the same reason via the shared
per-node collector.

## Fix

- `collectQinQFromInterfacesNode` now enumerates units with
  `namedInstances(ifaceBody.FindChildren("unit"))` — the same helper
  `compileInterfaces` and the sibling vlan-map gate use — and merges
  duplicate-unit findings instead of dropping later statements.
- `unitVLANStack` now recurses through unit children so a vlan leaf
  nested under a packed-tail child is seen exactly as `packedBody`
  hoists it for the compiler. Leaves inside `input-vlan-map` /
  `output-vlan-map` subtrees stay excluded from the stack: they are
  vlan-map rewrite arguments owned by the #6178 gate, not the unit's
  receive tag stack.
- NOT changed: the compiler, the #6178 vlan-map gate, the #14574
  vlan-tagging gate, and the unsupported-stanza walker — they share the
  `namedInstances` pattern already; only the QinQ collector diverged.

## Risk

Strict commits carrying a two-level or flat-nested inner tag now reject
where they previously committed silently — the intended honesty change,
matching the single-level spelling's existing rejection. Lenient load /
peer-sync only gains a warning and still compiles both tags, so persisted
configs do not brick. Single-tag two-level units are unaffected.
