# #17155 — pkg/conntrack GC sweep cannot run on the only remaining dataplane (R4-Q36-04)

- **Timestamp**: 2026-10-27
- **Issue**: #17155 (R4-Q36-04)
- **Base**: `origin/master 2dce74b744`

## Defect (STEP-0, verified at base)

Live on `2dce74b744`. `go list -deps ./cmd/xpfd | grep pkg/conntrack`
printed `github.com/psaab/xpf/pkg/conntrack`. Chain re-verified:
`pkg/dataplane/dataplane.go` returns `ErrEBPFBackendRetired` /
`ErrDPDKBackendRetired` for every non-userspace type; the userspace
runtime implements `DrainSessionDeltas`, so `daemon_run.go:334-336` set
`gc.SkipSweep = func() bool { return true }` and `gc.go:272` returned at
the sweep's first statement. The daemon still constructed/ran the GC
every 10 s, every commit fed it `SetAgingConfig`/`SetSessionLimitEnabled`
(`daemon_apply_dataplane.go:318-334`, a sink that does nothing), and
`pkg/api` exported eight constant families (`xpf_gc_sweep_duration_seconds`,
`xpf_conntrack_gc_last_sweep_timestamp_seconds`, `xpf_conntrack_gc_sweeps_total`,
`xpf_conntrack_gc_expired_deleted_total`,
`xpf_conntrack_gc_deadlines_saturated_total`,
`xpf_conntrack_gc_persistent_nat_expired_total`,
`xpf_conntrack_gc_errors_total{iterate,delete,session_count_sync}`,
`xpf_conntrack_gc_aggressive_aging_active`) from `gc.Stats()`, written
only inside the dead body. `pkg/conntrack/README.md` described BPF-map
expiry that no production build performs.

## Fix

- (1) `MaxSessions` moved to `pkg/dataplane` (`constants.go`, untyped
  `10_000_000`, in sync with `userspaceShimMaxSessions`); users updated:
  `pkg/cluster/sync_conn_gen.go` (`genGuardMapCap`) and
  `pkg/daemon/daemon_ha_sync.go` (`genGuardCapacityForRuntime` fallback),
  plus their `#9915` tests.
- (2) Daemon no longer constructs/runs the GC: `daemon_run.go` GC block
  (SkipSweep, IsLocalPrimary, OnDeleteV4/V6, `gc.Run` goroutine) removed,
  `d.gc` field and `daemon_gc.go`/`newConntrackGC` deleted, and the
  `SetAgingConfig`/`SetSessionLimitEnabled` commit sink in
  `daemon_apply_dataplane.go` removed. The #3440 advisory is kept: it
  lives in `pkg/config/compiler_validate_warn.go` ("aging configured but
  accepted-only — inert on userspace") and is untouched. Session expiry
  remains owned by the helper's per-worker GC; HA deletes flow via the
  session delta/event paths (`userspaceSessionDeltaDrainer`,
  `SESSION_OPEN` event callback), not GC callbacks — the GC callbacks
  only ever fired inside the unreachable sweep.
- (3) The eight GC metric families are **deleted** (not re-sourced):
  descriptors (`metrics_descriptors_session.go`), collector fields,
  `collectorDescSession` entries, `collectConntrackGCMetrics`, and the
  `gc` plumbing through `api.Config`/`grpcapi.Config`/`collectorDeps`
  are removed. No helper expiry counters with equivalent semantics
  exist to re-source from. Dashboards lose always-zero series — noted
  under Risk.
- (4) `pkg/conntrack` deleted outright (production + tests + README).
  Its legacy-`DataPlane` canary is folded away: the
  `legacyDataplaneImportAllowlist` entry and
  `TestConntrackGCConstructorDoesNotAcceptLegacyDataPlane` in
  `pkg/dataplane/retirement_boundary_canary_test.go` are removed (the
  repo-level retirement canary remains and now has one fewer legacy
  importer to police), and `docs/pr/1373-retire-ebpf-dataplane/README.md`
  marks the row RETIRED. Test fixtures that only fabricated a GC to
  satisfy a struct field (`pkg/api`, `pkg/grpcapi` status test) drop
  the field; `TestDaemonConntrackGCPreservesLegacyDomains` is deleted
  with the GC it exercised.

## Risk

Dashboards/alerts referencing the eight deleted families lose those
(absent, not zero) series — they were constant 0 on every production
build, so no real signal is lost; release notes should call this out.
The `MaxSessions` value is unchanged (`10_000_000`), only its home
moved, so HA guard caps (`genGuardMapCap`, `genGuardCapacityForRuntime`
fallback) are bit-identical. No config, wire, or forwarding behaviour
changes; the #3440 "aging is inert" commit advisory still fires.
