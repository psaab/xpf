# #13294: Restore XDP degraded-path status sampling

## Finding

The pinned `userspace_fallback_stats` map is read by `Manager.readDegradedPathStatsLocked`, and `ProcessStatus.DegradedPathCounters` plus the Prometheus `xpf_dataplane_degraded_path_total` collector remain implemented. However, current `recordHelperStatusLocked` no longer assigns the manager-owned map snapshot to the status. The historical removal occurred in #9642 alongside removal of `EntryPrograms`, while that change focused on snapshot retry debt; it left the status field empty, so the existing metrics emitter sees no reasons. This makes real XDP shim drop/fallback events invisible to status and Prometheus.

The Rust reader in `afxdp/bpf_map/pin.rs` is separately gated for the debug-only stderr report; the supported Go dataplane manager already owns the production map reader and reason-name table. The narrow, compatible repair is to restore the status projection at the manager's status-publication boundary, not to add a second Rust protocol/export path. Keep sparse reason labels and existing compatibility map/JSON names unchanged.

Origin: deep-review D4-11 (`review-work.AYgyxCmMxC`), Gemini 4 Argon High; validated by three-way research. The finding's proposed Rust-to-Go implementation path is stale relative to current master: `readDegradedPathStatsLocked`, `DegradedPathCounters`, and the collector already exist, but their manager projection was removed by #9642.

- The BPF-backed companion test was discovered but skipped because this environment cannot create BPF maps (`operation not permitted`); the source-level fail-on-revert assertion provides the unprivileged RED evidence.

## Change

Implemented by restoring `status.DegradedPathCounters = m.readDegradedPathStatsLocked()` in `recordHelperStatusLocked`. The existing Go reader sums all possible CPUs, omits zero-valued reasons, and the pre-existing status/Prometheus consumers now receive that live snapshot. No duplicate Rust protocol field, additional metric family, or compatibility shim was needed.
