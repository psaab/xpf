# Issue #13627 — restore remote `show system storage` dispatch

The remote `cli` command `show system storage` fell through to the unknown-target
error because `handleShowSystem` lacked its storage dispatch, while the server's
storage ShowText topic and the embedded CLI implementation remained intact.

## Change

- Restored `storage` dispatch through `showCommand("show system storage")` in
  `cmd/cli/show_system.go`.
- Added a dispatch-parity regression in
  `cmd/cli/dispatch_parity_13551_test.go`, asserting the `storage` ShowText topic
  and rendered output.

## Validation

- RED on pristine `origin/master` (`b99ed2bce`):
  `go test ./cmd/cli -run 'TestDispatchParity13551_SystemStorage$' -count=1`
  failed with `unknown show system target: storage`.
- GREEN: the focused test passed after the dispatch was restored.
- `go test ./cmd/cli -skip '^TestTreeIsGofmtClean$' -count=1` passed.
- `go vet ./cmd/cli`, `go build ./cmd/cli`, and gofmt cleanliness checks for
  both changed Go files passed.
- The complete `go test ./cmd/cli -count=1` run is blocked by the existing
  `TestTreeIsGofmtClean` finding 14 pre-existing files, including
  `cmd/cli/show_flow.go`; neither that file nor those unrelated files were
  changed.
