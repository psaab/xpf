# #17815 — remember rejected flow-export opens

The daemon retained state only for flows selected at `SESSION_OPEN`. A
sampling-rejected open therefore looked like a missing open to the close
fallback, which made a second decision and could export traffic that had
already been rejected. The HA delta walker also replayed open/update records
through the same non-idempotent path, and synthesized events without names
for resolvable interface indexes.

The exporter now retains rejected open decisions as per-flow state. A matching
close consumes and clears that decision without another sampling slot; genuine
orphan closes still use the existing close-time fallback. Repeated local/sync
opens are idempotent for each protocol instance, and exporter replacement
carries rejected decisions alongside selected/tracked state. Sync-generated
events resolve ingress and egress names through the EventReader's current
ifindex map, preserving per-interface filtering when identity is known.
