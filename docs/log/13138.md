# Issue #13138 — align junos-host warnings with tolerant RI quarantine

- **Issue:** `ValidateConfig` ran before tolerant routing-instance quarantine. Its `#4146` direct-delivery warning therefore projected authored, pre-quarantine ingress ownership, while the returned config and the daemon's `BuildJunosHostDenyProjection` observed post-quarantine ownership. This produced a warning claiming a `to-zone junos-host` deny was not covered even when the deny was rendered after quarantine.
- **What:** Added an internal `validateConfig` option so compilation can defer only the junos-host direct-delivery advisory while retaining all other `ValidateConfig` warnings in the existing tail-gate phase/order. `compileExpanded` now appends that advisory after tolerant tunnel-target, WireGuard, dual-claim, role-member, and dropped-zone-binding quarantines complete. Public `ValidateConfig` behavior remains unchanged for show/diagnostic callers. Added `TestJunosHostWarningsMatchPostQuarantineProjection13138` covering #12520 tunnel-target clearing, #9909 WireGuard membership quarantine, #11060 dual claims, and #11392 management-role/lifeline handling.
