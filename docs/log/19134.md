# #19134: a reused vm-test-run.sh lane must not re-test a previous binary

- **Timestamp**: 2026-11-16
- **Action**: History. A first design ran for three review rounds on
  `fix/19134-vm-test-run-stale-target` (4c4be7bd2d, 27088b34e9, 894d35b6e5).
  It RESTAMPED the synced sources, so cargo's mtime rule would rebuild what
  changed. Each Codex round found the same root cause in a new place: an
  mtime cannot prove freshness. Round 1: a runner-side edit, build, then
  restore. Round 2: a clock stepped back after the build. Round 3:
  build-script artefacts outside `deps`, an unconfined `rmtree`, and an
  unreadable scan. team-lead split #19134 out of integ b6 and escalated.
  The user chose "clean on any doubt", so this branch removes the mechanism
  instead of patching it a fourth time.
- **Action**: `scripts/vm-test-run.sh` (stacked on #19139):
  - No restamping. The sync keeps tar's archive mtimes, as before #19134,
    and extracts into `src.new`.
  - Decision-only ledger, format 3 (`/work/<lane>/.xpf-src-ledger.json`):
    the synced tree's identity (sha256 over every path, its content hash and
    mode) plus, per path, the content hash, mtime (ns) and mode the sync
    wrote. The next sync deletes the lane's target dir when ANY of these
    holds:
    - the identity differs;
    - a file of the previous tree differs from what the sync wrote, was
      deleted, or was created on the runner (`__pycache__/` ignored: no
      build reads it);
    - the ledger is missing, unreadable, or in an older format;
    - scanning either tree hit an error.
    Clocks never enter the decision. The sync prints which one fired, or
    "kept the lane's build".
  - Confined clean. Before anything touches the lane, a check step opens
    `/work/<lane>` from `/work` with `O_NOFOLLOW` (`open_lane`). It requires
    a directory on `/work`'s `st_dev`, and refuses when
    `/proc/self/mountinfo` lists a mount point at or under the lane. The sync
    step repeats that check, then deletes the target dir's contents through
    directory fds (`purge`):
    - every directory is opened with `O_NOFOLLOW` and checked against its
      `lstat` identity;
    - a directory on another `st_dev` is refused;
    - an unreadable directory the runner owns is made readable first.
    Any doubt about the path exits 3, and the script refuses with exit 2.
    The old source tree is removed the same way before `src.new` is renamed
    into place.
  - Cost: any change to the tree, or any runner-side change, costs a full
    rebuild of the lane. Only an unchanged re-sync keeps the incremental
    build. Residual: a runner-side change that restores both a file's bytes
    AND its exact mtime cannot be told from no change.
- **Action**: `scripts/vm-test-run-sync-selftest.sh` (registered in
  `scripts/run-selftests.sh`; `make test-vm-test-run-sync-lib`) uses real
  cargo on small crates under a mock incus.
  - Every stale-binary case from the three rounds must rebuild and print
    the NEW value: older tree, runner-side edit, restored after build,
    deleted after build, build-script-only partial build (a build script
    that failed at run time, then a changed build script), artefacts ahead of
    the clock, unreadable `target/debug/deps`, unbuilt middle sync, no ledger,
    and an older-format ledger.
  - An unchanged re-sync must KEEP the build.
  - A symlinked lane (`x-alias -> x-other`) and a bind mount under the lane
    (in a private `unshare -Urm` namespace) must be refused, with an outside
    sentinel intact.
  - Mutants, each KILLED only when its cell runs the stale binary or loses
    its sentinel:
    - no identity check (the older tree runs value=1);
    - no runner-change check (restored after build runs value=9);
    - following a symlinked lane (the alias sentinel is deleted);
    - no mount check (the bind-mount sentinel is deleted).
  - **File(s)**: `scripts/vm-test-run.sh`, `scripts/vm-test-run-sync-selftest.sh`,
    `scripts/run-selftests.sh`, `Makefile`, `docs/testing.md`,
    `docs/log/19134.md`

- **Timestamp**: 2026-11-16 (fold cycle 1 of the new design; Codex review of
  e1c81a70ab, team-lead's decisions)
- **Action**: Verified both P2s against the code.
  - **`__pycache__`:** the blanket exclusion dropped such paths from both
    scans. A TRACKED `__pycache__/value.txt` read by `include_str!` could
    change with an older mtime and the build was kept. Reproduced below as
    RED.
  - **Confinement:** the preflight released its fds before a separate root
    shell ran path-based `rm -rf`/`mkdir`/`chown`. The permission repair
    called `os.chmod(dir_fd=)`, which follows a final symlink. The target
    root's `st_dev` was not compared before traversal.
- **Action**: `scripts/vm-test-run.sh`:
  - Every synced path counts, and directories are scanned (existence and
    mode, not mtime). The only exemption: an entry the RUNNER created inside
    a `__pycache__` directory. A synced `__pycache__` path is in the identity
    like any other.
  - Threat model, written into the header and docs/testing.md: one tenant,
    our own lanes, accidental aliasing present at sync start. A concurrent
    adversary is out of scope, including a same-filesystem bind mount added
    mid-traversal.
  - ONE Python process, run as root, holding the lane's dirfd, now does
    every destructive step: the lane check, removing and creating
    `src.new`/`target`/`tmp`, the fd-relative chown walk, the extraction
    (`tar -x` with `fchdir` to `src.new`, as runner via `setuid`), the
    decision, the purge, the swap and the ledger. The path-based root shell
    is gone. Files are handed to runner only when the process is root in the
    initial user namespace.
  - The target root's `st_dev` is compared before the purge. Permission
    repair goes through an `O_PATH|O_NOFOLLOW` handle, `fstat`-checked as a
    directory with the expected identity, then chmod and reopen via
    `/proc/self/fd/<n>`.
  - Ledger format 4 (directories are now in it), so each lane cleans once.
- **Action**: `scripts/vm-test-run-sync-selftest.sh` gains these cells:
  - a tracked `__pycache__/value.txt` (force-added past a `.gitignore`)
    changed with an older mtime must print the new value;
  - runner-created bytecode under `__pycache__/` must KEEP the build;
  - a runner-created file, or an empty directory, elsewhere must clean;
  - an unscannable previous tree (a mode-000 file) must clean.
  New mutants: the blanket exclusion restored (the tracked input runs
  value=1), and no bytecode exemption (runner bytecode cleans the build).
- **Validation** (tcp:xpf-testrunner2 via `scripts/vm-test-run.sh`):

  - RED with e1c81a70ab's script: the tracked `__pycache__` input KEEPS the
    build and prints the stale value=1 (Codex's counterexample), and a
