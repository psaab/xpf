# #19134: a reused vm-test-run.sh lane never re-tests the previous cargo binary

- **Timestamp**: 2026-11-16
- **Action**: `scripts/vm-test-run.sh` no longer keeps the workstation's
  mtimes on sync. cargo calls a crate fresh when no source file is newer than
  its artefacts, and `/work/<name>/target` outlives every sync. A tree whose
  files carried OLDER mtimes than the lane's last build (another worktree, an
  older commit) therefore re-ran the previous binary in "Finished ... in
  0.0s". A first-bad-commit attribution once caught this only by that
  timing. The sync now extracts into `src.new`, then a python3 step on the
  runner restamps every file from a per-lane ledger
  (`/work/<name>/.xpf-src-ledger.json`: path -> [content hash, the time the
  lane first saw that content]) and swaps the tree in:
  - a file whose content the ledger knows gets that time back, so an
    unchanged tree keeps its incremental build;
  - a new or changed file gets the sync time, newer than every artefact;
  - a file the previous run modified on the runner (its pre-sync content
    differs from the ledger) is restamped even when the synced content matches
    the ledger, because the target may hold a build of the modified file;
  - a missing or unreadable ledger restamps everything once.
  A failed restamp refuses the run (exit 2) rather than test a possibly stale
  build. Stacked on #19139 (both edit this script).
- **Design note**: restamping only files changed since the LAST sync is not
  enough. If A is built, then B is synced and not built, then C (B's content,
  older mtimes) arrives, C looks unchanged against B while the target holds
  A's build. The ledger keeps the time content was first seen, so C keeps the
  sync-time stamp B got, which is newer than A's build.
- **Action**: `scripts/vm-test-run-sync-selftest.sh` (registered in
  `scripts/run-selftests.sh`; `make test-vm-test-run-sync-lib`) uses real
  cargo on a one-file crate under a mock incus that runs the runner side
  locally. Cells:
  - control: the trap is real on this toolchain;
  - fresh lane;
  - unchanged re-sync rebuilds nothing;
  - older-mtime tree under the same lane recompiles and prints its value
    (the issue's case);
  - runner-side edit;
  - unbuilt middle sync;
  - no ledger;
  - mutation: dropping the dirty-file check fails the runner-side-edit cell.
  It SKIPs (77) without cargo.
- **Validation** (runner VMs via `scripts/vm-test-run.sh`; tcp:xpf-testrunner):
  - GREEN on the branch: the sync selftest 8/8 and the #19139 selftest 14/14
    (`--no-sync`, unaffected); shellcheck clean.
  - RED at the base (#19139's script copied in on the runner): the older
    tree, runner-side edit, unbuilt middle sync and no-ledger cells fail. The
    older tree reruns the stale binary in "Finished ... in 0.0s", exactly the
    issue. The mutation anchor is absent. The control and the fresh-lane and
    unchanged cells pass on both.
  - Cost: a full-worktree sync (19,319 files) went from about 2.2 s to
    3.8-4.1 s (hashing the old and new trees); an unchanged re-sync restamps 0
    files.
  - **File(s)**: `scripts/vm-test-run.sh`, `scripts/vm-test-run-sync-selftest.sh`,
    `scripts/run-selftests.sh`, `Makefile`, `docs/testing.md`,
    `docs/log/19134.md`

- **Timestamp**: 2026-11-16 (fold cycle 1, Codex integ3 review P1)
- **Action**: Verified the P1 against the code before folding. The dirty
  check compared content only. A run that edits a file, builds it, and writes
  the original bytes back leaves content the ledger knows, so the next sync
  gave the file its old stamp, older than the edit's build, and cargo reused
  the edit's binary. `scripts/mutate-9546.py` does exactly this: `restore()`
  writes the backups back after each mutant run.
- **Action**: `scripts/vm-test-run.sh` ledger format 2:
  `{"v": 2, "files": {path: [hash, applied mtime ns]}}`. A runner file is
  dirty (restamped to the sync time, whatever its content) when its content
  OR its `st_mtime_ns` differs from what the sync applied, or when it was
  deleted. Stamps are applied with `os.utime(ns=...)`. A format-1 ledger
  counts as none, so each existing lane restamps everything once.
- **Action**: `scripts/vm-test-run-sync-selftest.sh` gains two cells:
  - restored after build: edit to value=9, build, write B's original bytes
    back (checked by sha256), re-sync. It must recompile to value=2.
  - deleted after build: a `build.rs` bakes in whether `flag.txt` exists; the
    run deletes it and builds (flag=0), and the next sync must re-run the
    script (flag=1).
  The mutants now count as KILLED only when their cell actually RUNS the
  stale binary, not on any failure:
  - no dirty check runs value=9;
  - content-only dirty check (the pre-review shape) runs value=9;
  - no deleted-file check runs flag=0.

- **Timestamp**: 2026-11-16 (fold cycle 2, Codex b4 review P2)
- **Action**: Verified the finding. Every dirty or new file was stamped with
  `time.time_ns()`, with nothing checking that the stamp is newer than the
  retained build. A clock that steps backward between a build and the next
  sync, or a filesystem coarse enough to put source and artefact in the same
  tick, could leave a changed source older than (or equal to) the artefact,
  and cargo reuses the build.
- **Action**: `scripts/vm-test-run.sh`:
  - a fresh stamp is `max(now, newest artefact + 1 s)`. The newest artefact
    is found with one readdir+stat of each `target/*/deps` and
    `target/*/*/deps`, not a recursive walk; with no target, plain now;
  - the ledger keeps `last_sync_ns`. If the clock is behind it, the sync
    prints so, deletes the lane's target dir, and restamps everything (a
    fail-closed backstop for artefacts the deps scan does not see);
  - when the stamp lands ahead of the clock, the summary line says how far.
- **Action**: `scripts/vm-test-run-sync-selftest.sh` gains two cells:
  - artefacts ahead of the clock: every file in the lane's target dir is
    moved a day into the future, then a changed tree must recompile;
  - clock behind the previous sync: `last_sync_ns` is set a day ahead, and
    the sync must say so, clean, and rebuild.
  New mutants: plain now-stamping (KILLED: runs the stale value=1) and no
  backstop (KILLED: the old build is kept, nothing recompiles).
- **Action**: docs/testing.md states the conditions, replacing the old
  unconditional "never". It lists what is NOT covered: a restore of both the
  bytes and the exact mtime; an artefact outside `*/deps` written with a
  future mtime while the clock runs forward; concurrent writers of the target
  dir. A stamp placed ahead of the clock makes its crates rebuild on every
  run until the clock passes it (the safe direction).
