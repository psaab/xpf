# Issue #14659: PBR input terms bypass three-color policers, forwarding-class, and dscp-rewrite

- **Timestamp**: 2026-10-17
  - **Action**: fixed the three mutually reinforcing sites from D3-01. (1) The runtime TX-selection walk (`tx_selection.rs`) no longer returns before `merge_matched_tx_modifiers` on a matched `routing-instance` term — the term is terminal, so its three-color policer now meters and its forwarding-class/dscp-rewrite/log apply on the transit TX-selection leg, the sole enforcer; the now-dead `routing_bearing` plumbing and the tunnel gate's unconditional meter were removed (the tunnel outer gate meters through the PBR term only for a firewall-local outer destination, transit decap defers to its TX-selection leg). (2) The host-bound session replay capture (`cache_sensitive.rs`) extends a PBR term's three-color policer handle before stopping, mirroring the #14121 counter capture, so session hits enforce it. (3) The non-routing walk (`eval.rs`) returns its accumulated `next term` modifiers (policer drop/log/FC/DSCP) instead of `FilterResult::default()` when deferring at a PBR term; inline paths run the routing-bearing remainder only when that walk stayed green so a fall-through policer is never double-charged. Loss-priority stays a documented meter-only no-op (#9503) — `ThreeColorPolicerAction` carries no loss-priority field, so nothing was lost there beyond the already-enforced drop/DSCP.
  - **File(s)**: `userspace-dp/src/filter/engine/tx_selection.rs`, `userspace-dp/src/filter/engine/cache_sensitive.rs`, `userspace-dp/src/filter/engine/eval.rs`, `userspace-dp/src/filter/engine/mod.rs`, `userspace-dp/src/afxdp/poll_descriptor/filter.rs`, `userspace-dp/src/filter/tests.rs`, `userspace-dp/src/filter/README.md`, `docs/log/14659.md`
