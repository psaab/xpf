# Issue #15232: SNMP provider residuals (A48-02, A48-03, A48-04)

## Why

- **A48-02:** `ifTableColumns = {1,2,3,4,5,7,8,10,16}` and `IfData`
  carried no error/discard, Counter32 unicast, or ifLastChange fields.
  `deriveIfCounters` ignored `RxErrors/RxDropped/TxErrors/TxDropped`.
  NMS error/discard alarms and flap detection could not work; v1
  managers had no packet counter.
- **A48-03:** `snmpEnabled` required a community or v3 user, so a
  trap-group-only config committed clean but never started the agent
  or link monitor — configured linkUp/linkDown traps were silently
  never sent.
- **A48-04:** `buildSNMPIfData` built rows only from netlink links.
  Bondless reths have no kernel device, so they had no IF-MIB row and
  no stable ifIndex across failover.

## What

- `pkg/snmp/agent.go`: serve ifTable cols 9,11-15,17-20 (ifLastChange
  TimeTicks; ifIn/ifOut Ucast/NUcast, Errors, Discards, UnknownProtos
  Counter32) from new `IfData` fields; walk order stays sorted by
  construction (column-major, ascending ifIndex).
- `pkg/daemon/daemon_snmp_reconcile.go`:
  - `deriveIfCounters` fills the new fields from `rtnl_link_stats`
    (RxErrors/RxDropped/TxErrors/TxDropped; IN unicast =
    RxPackets-Multicast clamped, IN non-unicast = Multicast; OUT
    unicast = TxPackets upper-bound, OUT non-unicast = 0 — the kernel
    exposes no TX breakdown or unknown-proto count, honest zeros).
  - `ifLastChange`: a process-wide tracker records per-ifIndex oper
    transitions as TimeTicks (hundredths since daemon start); 0 until
    the first observed change.
  - `snmpEnabled` also enables on `len(TrapGroups) > 0`; the existing
    start path then starts the monitor (already gated on trap groups).
  - Bondless reth synthesis: `daemonSNMPRethInfos` resolves configured
    reths via `RethToPhysical` + each reth's `RedundancyGroup` +
    `cluster.IsLocalPrimary`; `synthesizeRethRows` appends a row with
    stable synthetic ifIndex `1<<24 + rethN`, owning-member counters,
    and oper = primary && member-up. Standalone (no cluster) = primary.
    NOT changed: kernel rows, ifXTable, link-trap ifIndex keying (a
    reth synthesizes no kernel link event; member traps unchanged).

## Validation

- RED on `origin/master` (5552c6ef59): new tests reference the missing
  columns/fields/gate (`ifTableColumns` lacks 9/11-20, `snmpEnabled`
  false for trap-only, no reth row) and fail.
- GREEN: `go test ./pkg/snmp/ -run 15232` and
  `go test ./pkg/daemon/ -run 15232` pass (typed GET per new column,
  sorted walk, counters, lastChange transition/stability, trap-only
  enable + agent/monitor start + trap enqueue, reth row/index/counters
  /oper primary+secondary). Full `go test ./pkg/snmp/ ./pkg/daemon/`
  and `go vet` on both packages: see PR.

## Risk

Synthetic reth ifIndexes (`>= 1<<24`) appear in ifTable/ifXTable and
ifNumber; managers keyed only on kernel ifIndexes see additional rows
(the intended parity). ifLastChange epoch is daemon start, not agent
(restart) start, so after a day-2 agent restart values are a lower
bound — still monotonic for flap detection.
