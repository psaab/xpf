- **Timestamp**: 08:06
- **Action**: Found the sender-side signal.
  - `QueueConfig` writes directly: a write failure disconnects, and the reconnect re-pushes. `lastSentConfigGen` is stored only on a successful write.
  - A standby still on the older config either failed to apply the newest push or dropped it from a full apply queue. Both send a config-apply nack for that generation (#7328), and the sender already accepts only a nack matching `lastSentConfigGen`.
  - So "the last nack matches the newest generation sent" is exactly the stale peer. A newer push supersedes it, and an in-flight apply sends no nack and is safe.
