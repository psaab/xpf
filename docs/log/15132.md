# #15132 — WireGuard small-order denylist exact-byte match: bit-255 twins bypass (#14373 residual, A91-06)

## Defect
- The #14373 small-order denylist compared exact bytes in both gates:
  Go `isDegenerateWireguardKeyHex` matched the candidate hex string
  against `wgSmallOrderKeyHex`, and Rust `is_small_order_wg_peer_key`
  did `WG_SMALL_ORDER_KEYS.contains(key)`.
- X25519 masks bit 255 (the top bit of byte 31) of the u-coordinate
  per RFC 7748, so each of the seven listed keys has a bit-255 twin —
  the same small-order point with a one-bit-different encoding — that
  passed the Go commit gate, the Rust hydrate gate
  (`hydrate_wg_identity`), and the engine reconcile gate. A twin peer
  key yields the identical all-zero static-static DH secret, so the
  peer identity offered no authentication beyond an optional PSK —
  the exact consequence #14373 fixed, reachable with a one-bit edit.

## Fix
- `pkg/config/compiler_validate_wireguard.go`:
  `isDegenerateWireguardKeyHex` now decodes the shape-validated hex,
  masks byte 31 (`raw[31] &= 0x7f`), re-encodes, and compares against
  the canonical (bit-255-clear) denylist. The repeated-byte leg is
  unchanged and still runs on the authored spelling. All three call
  sites (local private key, peer public key, explicit PSK) inherit
  the fix through the single predicate.
- `userspace-dp/src/afxdp/wg/mod.rs`: `is_small_order_wg_peer_key`
  masks byte 31 of a copy of the candidate before the table lookup.
  `is_degenerate_wg_key_bytes` (hydrate: local private key, peer key,
  explicit PSK) and the engine's `reconcile_peers` admission gate
  both route through it, so every Rust gate inherits the fix.
- No table entries added: the seven canonical entries plus masking
  cover all fourteen encodings (7 canonical + 7 twins). A legitimate
  key with bit 255 set is a different genuine point and stays
  admissible — masking only affects the denylist comparison.

## Tests
- `pkg/config/compiler_validate_wireguard_twin_15132_test.go`: all
  seven bit-255 twin peer keys refused at the predicate and at strict
  commit (plus upper-case twin spelling), twin private key and twin
  explicit PSK refused (errors never echo key material), and controls
  (canonical keys stay refused, bit-255-set variants of valid random
  keys commit, repeated-byte and near-miss keys unchanged).
- `userspace-dp/src/afxdp/wg/engine_tests.rs`:
  `bit255_twins_are_small_order_15132` (each twin yields an all-zero
  DH under a clamped scalar — the executable pin that the twin is the
  same point — and is refused by both predicates; valid bit-255-set
  and near-miss controls stay admissible) and
  `reconcile_refuses_bit255_twin_peers_15132` (all seven twin peers
  refused and counted at engine reconcile; valid peer and its
  bit-255-set variant installed).
- `userspace-dp/src/afxdp/forwarding_build/tests.rs`:
  `wg_endpoint_with_bit255_twin_key_is_dropped_15132` (twin peer,
  twin local private key, and twin explicit PSK each drop the row at
  hydrate; valid fixture and bit-255-set valid peer still hydrate).

## RED/GREEN
- RED on origin/master (tests present, fix absent): Go twin cells
  fail ("bit-255 twin … must be degenerate" / "strict commit must
  refuse bit-255 twin peer public key …" for all seven twins, plus
  the twin private-key cells); all three Rust twin tests fail
  (engine reconcile installed 9 peers instead of 2). Verified both
  by the initial pre-fix run and by reverting only the production
  files with the tests in place.
- GREEN with fix: Go `TestWireguardBit255*` (3 tests) plus the full
  #14373 degenerate suite pass; Rust `bit255` (3 tests), `14373`
  (3 tests), and `wg_endpoint` (9 tests) pass. The six pre-existing
  `pkg/config` WireGuard failures on this base (stale `1111…`
  repeated-byte fixtures vs the #14373 gate) are byte-identical
  with and without the fix — base-attributed, untouched.

## Deliberate scope notes
- Only the cited comparison mechanism changed; no new denylist
  entries, no DH-output hook (snow still computes DH opaquely — the
  masked denylist is provably the same enforcement: clamped scalar
  ⇒ zero DH iff the masked point is small-order).
- Neighbouring behaviour preserved: canonical spellings still
  refused, repeated-byte leg untouched, valid keys (including
  bit-255-set valid keys) still commit/hydrate/install, absent PSK
  still means "no PSK", lenient-load warn posture unchanged.
