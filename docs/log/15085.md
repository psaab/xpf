# #15085 — daemon: bare xpfd boots a second full daemon (A54-02)

- **Timestamp**: 2026-10-18
  - **Investigation**: Confirmed at `origin/master@4e9e42e494`.
    `classifyCommand` (`cmd/xpfd/main.go`) routes empty argv / a leading
    `-flag` to `cmdDaemon`. The cmdUnknown error text said "use the 'cli'
    binary for remote commands, or run xpfd on a TTY" — recommending the
    bare invocation that boots a daemon. `daemon.New` created the config
    store (creating/migrating `.configdb`) with no singleton, and
    `Daemon.Run` called `clearHostInboundFirstApplyMarker()`
    unconditionally as its first act, so a duplicate deleted a LIVE
    owner's marker, then proceeded through compile / transit-gate /
    XDP attach. The #8233 management-port refusal only fires at the
    late server-bind phase, after those mutations.
  - **File(s)**: none (investigation only)

- **Timestamp**: 2026-10-18
  - **Action**: Fix in worktree `/var/worktrees/wt-15085` (branch
    `fix/15085-campaign`): (1) new `pkg/daemon/daemon_singleton_15085.go`
    — a host-wide singleton: `DaemonLockPath=/run/xpf/xpfd.lock`,
    non-blocking exclusive flock (0600, never unlinked), owner pid
    recorded under the lock; busy returns `ErrDaemonAlreadyRunning`
    naming the pid plus the safe alternatives. (2) `daemon.New`
    acquires it BEFORE `configstore.New`, releases it if store
    construction fails, and stores it on the Daemon; `Daemon.Run`
    refuses any lease-less Daemon before ANY startup mutation and
    releases the lease on return. (3)
    `clearHostInboundFirstApplyMarker` refuses to remove a marker
    live-held by another process (`HostInboundFirstApplyLive`),
    respecting live ownership even if a future caller reaches it
    without the lock. (4) The cmdUnknown text no longer suggests
    running `xpfd` directly; it names `cli` and `systemctl restart
    xpfd`. Tests: package test init redirects DaemonLockPath into its
    temp root; the one struct-literal `Run` chain test acquires a
    throwaway lease. NOT changed: `classifyCommand` routing (bare
    `xpfd` must still start the daemon under systemd — the singleton,
    not argv shape, is the duplicate gate); one-shot subcommands stay
    lock-free; no pidfile polling or blocking wait (systemd's
    `TimeoutStopSec` already bounds predecessor exit, and flock
    release on fd close makes the successor's acquire immediate).
