# #14431 — Interface `family inet/inet6 filter` packed run drops the SECOND direction

## Mechanism

`interfaces ge-0/0/0 { unit 0 { family inet { filter input F-IN output F-OUT; } } }`
packs both directions onto the filter node's Keys
(`[filter input F-IN output F-OUT]`, no Children). `compileInterfaces`
(`compiler_interfaces.go`) reads only
`filterNode.FindChildren("input"/"output")`, which sees nothing in that
shape. The compact normalizer admitted `(filter, input)` / `(filter, output)`
(`compact_normalize_scope.go`), so it folded the run to a single child
`filter { [input F-IN output F-OUT] }`; `nodeVal` then read only the first
value. Measured on master: strict rejected the run via the #10293 gate
(below), lenient compiled `FilterInputV4="F-IN"` with `FilterOutputV4=""`
(input-first) or the mirror (output-first) — the second direction silently
dropped, the interface forwarding unfiltered in that direction. The braced
twin (`filter { input F-IN; output F-OUT; }`) compiled both, and the flat-set
spelling compiled both (separate `set` statements).

The #10293 gate compounded it: `unsupportedInterfaceFilterKnobs` counted
every token after a direction keyword as an extra authored value, so the
two-direction run was misread as a multi-value singular binding and
strict-rejected (`filter input is not supported … (#10293)`) naming only
the first direction.

## Fix

- `pkg/config/schema_interfaces.go`: the interface-family `filter`
  container (inet and inet6) opts into `packedStatements`, so
  `splitBracedPackedChildren8886` / `splitPackedStatements8768` lower a
  packed run to one `[input F-IN]` / `[output F-OUT]` statement per
  direction (both orders, family-braced and family-packed spellings).
  This reuses the existing opt-in the family containers (`inet`/`inet6`)
  already carry; no new splitter.
- `pkg/config/compiler_interfaces_unsupported.go`:
  `unsupportedInterfaceFilterKnobs` treats a direction keyword as a
  statement boundary, not an extra value — a direction followed by
  exactly one value and then another direction keyword is a well-formed
  single-value statement. A genuinely multi-value singular binding
  (`filter input f1 f2`, bracket/block forms) still rejects #10293.

NOT changed: `compileInterfaces` itself — after normalization the packed
run arrives in the braced shape it already reads; single-direction,
braced, and flat-set spellings are byte-identical to before.
