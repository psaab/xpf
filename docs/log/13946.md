# #13946 — preserve endpoint-independent NAT64 bindings

- **PRs**: #14025 (initial merge), #14050 (round-robin BIB follow-up); #14091 tracks deterministic NAPT64.
- **Branch**: `fix/13946-campaign`
- **Files**: round-robin NAT64 allocator and HA import paths, their regression tests, and this log.

## Behavior

The standard round-robin NAT64 path now allocates each IPv6 transport
address's binding with the persistent `AnyRemoteHost` key, so changing only
the remote IPv4 endpoint reuses the same translated IPv4 address and port.
The 300-second idle timeout retains the BIB after its final active flow
reference is released. HA imports reserve through the same persistent key;
separate synchronized flows sharing the binding join its active-reference
count rather than creating endpoint-specific leases.

The separate deterministic NAPT64 path still allocates per full flow and is
not covered by this fix. Follow-up issue #14091 tracks its block-constrained
BIB lifecycle, HA idle-lease synchronization, and regression coverage.

A strict HA mirror publication refusal is different from normal flow teardown:
the imported entry was never accepted or published. Its speculative NAT64
reservation is rolled back, removing a newly created lease instead of leaving
an idle BIB for an unaccepted import.

## Test expectation changes

- NAT64 release, purge, transaction cleanup, and GC tests now distinguish
  releasing an active flow from freeing its BIB. They assert zero live flow
  references while the idle binding remains allocated, and that another source
  receives the next pool port. Immediate reuse was the old non-persistent
  behavior and would contradict the new endpoint-independent binding contract.
- The synchronized-flow test now expects two flows with the same IPv6
  transport endpoint but different remote endpoints to share one translated
  tuple, track two active references, and release them independently.
- HA strict-mirror rejection tests that exercise BPF publication failure now
  resync the prior translated tuple. An incompatible changed tuple is rejected
  by the allocator before mirror publication because an active AnyRemoteHost
  binding cannot be changed; those old fixtures no longer reached the mirror
  failure behavior their assertions described. The strict-refusal cleanup test
  verifies speculative rollback rather than normal idle-lease retention.
- The deterministic NAPT64 block-placement test remains unchanged; the distinct
  allocation behavior it currently exercises is the separate residual tracked
  by #14091.
