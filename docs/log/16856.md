# #16856 — Declined (state=1) leases dropped by HA lease sync and live pre-seed

- **Issue**: R3-B03-03. Kea records a DHCPDECLINE as a state=1 lease held for
  `decline-probation-period` (RFC 2131 §4.3.3: the address MUST be marked not
  available). Lease sync filtered to state=0 only, both memfile writers
  hard-coded state 0, and the cluster identity filter required a client
  identity declined rows do not carry. A live pre-seed therefore erased the
  declined row locally (and deleted its LFC generations), a push never
  carried it to the peer, and after failover/restart the conflicting address
  returned to the free pool.
- **Change**:
  - `readSyncLeasesViaSocket`: carry state 0 and 1, keep dropping state 2
    and expired rows.
  - Memfile fallback: new `parseSyncLeases{,4,6}` / `parseLeases(...,
    includeDeclined=true)` in `ddns_leases.go` retains declined rows with
    `State`/`ValidLifetime` on `ddnsLease`; `parseActiveLeases` (DDNS) is
    unchanged and still tombstones declined rows, so no DNS is published
    for them. Rotation seam (`parseLeaseFileFn`) preserved for the active
    path.
  - Wire already carries `State` (byte in `encodeOneLease`); receiver
    `SanitizeSyncLeaseForFamily` now accepts only states 0/1 (unknown
    states drop) and `validLeaseIdentityForFamily` exempts declined rows
    from the HW/ClientID/DUID requirement.
  - Merge: `IdentityKey` is address-only for declined rows; declined
    occupancy beats an active row for the same address unless the active
    row is provably a later grant (both ValidLife present, strictly smaller
    grant age).
  - Writers: `writeMemfile4/6` and `syncLeaseToKea` emit the row's actual
    `State`; `dhcpLeaseSetFingerprint` includes `State` so an
    active→declined transition triggers the change push.

## Verification

- **New cells**: `go test ./pkg/dhcpserver/ -run 16856 -count=1` PASS
  (socket+memfile carry, live pre-seed retains `10.0.61.66,state=1`, peer
  pre-seed, socket seed state=1, sanitize state gate, merge arbitration);
  `go test ./pkg/cluster/ -run 16856 -count=1` PASS (identity carve-out,
  wire round-trip, semantic/identity filters, held set).
- **RED evidence**: reverting only the socket filter to state=0-only makes
  `TestDeclined16856_SocketAndMemfileCarry` fail with "declined not carried
  via socket" (only the active row returned); restoring passes.
- **Suites**: `go test ./pkg/dhcpserver/ -count=1` PASS;
  `go test ./pkg/cluster/ -run 'DHCP|Lease|16856|10893|9915' -count=1` PASS;
  `go test ./pkg/daemon/ -run 'DHCPLease|Fingerprint' -count=1` PASS.
  Full `pkg/cluster -count=1` shows pre-existing config-compile failures
  (private-rg-election control-interface/peer-address) unrelated to this
  change.

## Residuals

- Kea's actual re-offer behaviour after restart with a state=1 memfile row
  and real `lease4-add` acceptance of state=1 were not exercised against a
  live Kea (stub-Kea level, matching the source report). Declined
  probation uses the row's `expire`/`valid_lifetime` as Kea writes it;
  if a Kea version encodes probation differently, the remaining lifetime
  follows that expire.
- v6 declined rows follow the same path; Kea DHCPv6 has no DECLINE
  probation analogue in normal operation, so this is defensive parity.
