# #15758: scoped `show <path> | compare` silently returned `[no changes]` for leaf statements, container `Inactive` toggles, and empty containers, and flattened bare-keyword multi-match containers

- **Timestamp**: 2026-10-19
  - **Action**: Fixed `FormatCompareAtPath` to diff the matched nodes themselves (old matches vs new matches at the parent prefix) instead of unwrapping only their children.
  - **File(s)**: `pkg/config/ast_format.go` (`FormatCompareAtPath`), `pkg/config/compare_at_path_15758_test.go` (regression tests), `docs/log/15758.md` (this log).

## Mechanism (origin/master 320c26c08c)

- `FormatCompareAtPath` (`pkg/config/ast_format.go`) navigated both trees to `path` and appended only `m.Children...` for matches with `!m.IsLeaf`, then ran `diffNodes` on the flattened child lists at `[edit <path>]`.
- A leaf match (`show system host-name | compare`) was skipped entirely: both sides contributed nothing, so a leaf value change rendered `[no changes]`.
- A container's own `Inactive` flag lives on the matched node, which was discarded — only its (unchanged) children were compared — so a pure activate/deactivate toggle at the scoped path rendered `[no changes]`.
- An empty added/deleted container likewise produced an empty child list, indistinguishable from a missing path.
- A bare-keyword terminal path (e.g. `system ntp server`) matches every same-leading-keyword sibling (#3980); unwrapping all of them flattened their children into one shared list where duplicate `KeyPath`s could pair across siblings instead of diffing each matched node at its parent.

## Change

- `FormatCompareAtPath` now uses `navigatePathWidth` on both sides — the same contract `FormatPathSet` and `FormatPathJSON` already use — and diffs the matched node slice `oldMatches` vs `newMatches` with `diffNodes` at the parent prefix `path[:len(path)-width]`. The parent prefix uses the true consumed width returned by `navigatePathWidth` (the matching side's width when only one side matches), so an ancestor value that repeats the terminal node's keys cannot over-strip the prefix (#5717).
- All downstream surfaces (`FormatCompareRedactedAtPath`, the configstore `ShowCompare*AtPath` family, and through them local CLI / gRPC / remote CLI) inherit the fix unchanged: they already route scoped compares through `FormatCompareAtPath` and render `[no changes]` only when it returns `""`.
- NOT changed: empty-path (global) compare, absent-on-both-sides scoped compare (still `""`), child edits within a scoped container, `diffNodes` / `alignSiblings` semantics, authorization pricing.

## Validation

- RED on origin/master (new test, pre-fix): `TestFormatCompareAtPathLeafAndContainerInactive` failed with `expected leaf compare at [system host-name] to show new-fw diff, got ""`; `TestFormatCompareAtPathEmptyContainerAndMultiMatch15758` failed with `expected empty-container add at [protocols ospf area] to render + area 0.0.0.0, got ""`.
- GREEN post-fix: both regression tests pass, including the container `Inactive` toggle leg, the empty-container add and delete legs, the bare-keyword multi-match value change (with the unchanged sibling not rendered as changed), and the identical-tree / absent-path / child-edit controls.
- Neighboring suites: `TestFormatCompare*` (#15168), `TestCompare*15169`, `TestInactive_*`, and the configstore `TestShowCompare*` / `TestShowCompareAtPath15272` / redacted compare tests all pass. The full `pkg/config` + `pkg/configstore` run exceeded the 600s lane shell timeout before reporting; targeted compare/inactive/redacted/store suites were run individually and pass.
- `gofmt` clean on the changed files.

## Risk

- Scoped compares to a container path now render the matched node itself under its parent `[edit]` header (e.g. the stanza as a -/+ pair on an `Inactive` toggle, `+ area 0.0.0.0 { }` for an empty-container add) instead of only its children under `[edit <path>]`; this matches the global compare's node-level rendering of the same change and Junos behavior, but operator scripts scraping the exact scoped-compare layout for changed containers may see the added stanza line. Unchanged subtrees, absent paths, and the global compare are byte-identical to before.
