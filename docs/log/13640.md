# Issue #13640 — reverse-translated session aliases stay live

## Contract and change

A flow-cache hit on a reverse-translated NAT alias must resolve to the same live session as an ordinary session-table hit. The flow-cache seed and later cache hit use the translated wire tuple, while the session table stores the reverse entry under its canonical primary key. Before this fix, `record_by_key` and its mutable counterpart probed only the primary-key index, so liveness, ingress-zone, keepalive, and accounting probes missed the alias and the cache evicted an otherwise-live entry on every packet.

Both lookup helpers now use the session table's existing primary/alias handle resolver and validate the resolved record against the primary tuple or reverse-translated alias. A primary handle that is stale remains terminal; it does not fall through to an unrelated alias. Keepalive refreshes resolve aliases but put the canonical record key on the expiry wheel, never the wire alias.

Terminal `LocalDelivery` deletion now canonicalizes an alias hit before deriving the companion and releasing the canonical session. Shared-only entries retain their previous wire-key behavior.

## Regression coverage

`userspace-dp/src/session/tests.rs::reverse_translated_alias_flow_cache_probes_resolve_13640` verifies reverse-translated alias liveness, ingress-zone matches, keepalive refresh, packet accounting, and that alias hits do not add lookup misses. The expiry-wheel check confirms keepalive refresh advances the canonical record.

`userspace-dp/src/afxdp/session_glue/tests.rs::delete_terminal_filtered_session_releases_companion_and_allocator_5622` now covers forward, canonical reverse, and reverse-translated alias terminal hits, asserting both session halves are removed and the source-NAT pool reservation is released.

## Risk and residuals

No flow-cache key format or session expiry policy changed. The alias path performs the existing reverse-alias lookup and translates the canonical record only when a keepalive refresh is due; no per-packet heap allocation was added. No live-cluster or packet-path validation was performed.
