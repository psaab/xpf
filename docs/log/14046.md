## Why

The #13945 inbound persistent-NAT gate used a one-to-one reverse index keyed only by `(protocol, translated IP, translated port)`. PAT and address-only leases can own that same translated base while granting different remote permissions. Insertion of the second lease displaced the first, so inbound admission could deny a permitted remote or select the wrong internal endpoint; removing either lease could also erase the other's index entry.

## What

Store all persistent lease owners in a reverse-base bucket and resolve inbound traffic against each owner's live state and remote permissions. A unique permitted owner resolves normally; if multiple distinct internal endpoints permit the same remote, deny the ambiguous packet. Removing or replacing one lease removes only its own bucket membership. Added a regression covering colliding PAT/address-only leases, different remote grants, and removal of one owner.

## Validation

The same full command on the issue branch ran 8,239 tests: 8,206 passed, 25 failed, 8 ignored; the new collision regression passed. The extra failure was the unrelated `afxdp::flow_cache::tests::tunnel_flow_cache_keys_mac_change_shard_on_outer_neighbor_not_logical_ifindex` fixture precondition. In the 54-test `nat::tests_idle_lease_sync_8121` module, 51 passed and the same three failures reproduced on both parent PR #13945 commit `64c56d7` and the issue branch: `address_only_idle_owner_index_tracks_import_and_rollback_11496`, `an_address_only_import_refuses_live_reverse_identity_contention_11475`, and `expired_idle_lease_does_not_block_import_13692`.
