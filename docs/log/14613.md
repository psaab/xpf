# Issue #14613 — With a source-address, UDP syslog resolves the collector hostname outside the #9326 5 s bound

- **Timestamp**: 2026-10-16
  - **Action**: Bounded the source-address branch of `dialUDP`
    (`pkg/logging/syslog.go`). It resolved both the source and the
    collector with `net.ResolveUDPAddr` and dialed with `net.DialUDP` —
    neither carries a context or a deadline — so a hostname collector
    with a `source-address` stalled for resolver timeout × attempts ×
    servers on every apply, while the no-source branch carried the
    #9326 5 s `net.Dialer`. Both `security log stream` (daemon
    `applySyslogConfig` + CLI `buildSyslogClients`, via
    `NewSyslogClientTransport`) and `system syslog host` (daemon
    `applySystemSyslog`, via `NewSyslogClientWithSource`) funnel into
    this one branch, so the single fix covers every commit-path
    consumer; no caller changes were needed.
    The branch now resolves under one `syslogDialTimeout` (5 s)
    context and dials the resolved literal with the same bound.
    `resolveUDPAddrBounded` mirrors flowexport #9913: the bare-literal
    and empty-host cases take the `net.ResolveUDPAddr` parser fast
    path, IP literals (including `%zone` scoped forms) parse directly,
    and hostnames go through the `lookupSyslogIPAddr` seam
    (`net.DefaultResolver.LookupIPAddr` under the caller's context),
    preferring the first IPv4 result (net's `forResolve` order for the
    family-agnostic `udp` network) and falling back to the first
    result. The `resolve source` / `resolve remote` error taxonomy is
    preserved verbatim. The no-source branch now reads the same
    `syslogDialTimeout` var instead of a literal, so the two branches
    cannot drift apart again. Scope cuts, deliberately: TCP/TLS source
    resolution (`dialTCP`/`dialTLS` also call `net.ResolveTCPAddr`
    unbounded) is unchanged — it is outside this issue's validated
    mechanism, and those clients are constructed deferred (no dial on
    the commit path), so the residual is a first-Send reconnect stall,
    not a commit stall; single-address selection loses the stdlib
    candidate-list fallback only on the source-bound branch, matching
    flowexport #10182's accepted trade.
    Regression tests in `syslog_udp_srcaddr_bound_14613_test.go`: a
    resolver seam that blocks until its context is cancelled (the
    black-holed-DNS shape) proves both the remote and the source
    resolution return a `context.DeadlineExceeded`-wrapping error
    under the bound with taxonomy intact; a literal source+collector
    control proves the client still binds 127.0.0.1 and delivers to a
    real collector; a hostname-success control proves bounded
    resolution still dials the resolved address. README's #9326
    section documents the branch.
  - **File(s)**: pkg/logging/syslog.go,
    pkg/logging/syslog_udp_srcaddr_bound_14613_test.go,
    pkg/logging/README.md, docs/log/14613.md

## Risk

- Behaviour delta: a source-bound UDP syslog client whose collector
  hostname cannot resolve within 5 s now fails construction at apply
  (client skipped with the existing warning) instead of stalling the
  apply for the resolver's full timeout × attempts × servers and
  then failing the same way. On fast-failing DNS (NXDOMAIN/refused)
  nothing changes. A hostname that resolves only after 5 s of
  resolver latency — pathological, but previously tolerated on this
  branch alone — now fails closed like its no-source and TCP/TLS
  siblings.
- NOT changed: TCP/TLS `ResolveTCPAddr` source resolution (deferred
  construction keeps it off the commit path; see Action), the
  no-source UDP dial semantics (same 5 s bound, now via the shared
  var), UDP write deadlines, and every caller.
- No live-cluster syslog smoke was run; the decisive check is the
  in-package bounded-resolver regression above, matching the issue's
  acceptance (black-holed resolver returns within ≤5 s, control row
  unchanged).
