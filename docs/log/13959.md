# Issue #13959 — stop IPv6 extension walks after non-first fragments

## Why

The XDP shim continued following the Fragment header's Next Header after a
non-first fragment. Those bytes are fragment payload, not necessarily the
extension header they resemble. An AH or Destination Options payload beginning
with a length that exceeds the packet therefore made the shim reject a
legitimate fragment.

## What

The shim now stops its extension walk immediately after reading a non-first
Fragment header. It preserves the Fragment header's next-header value and marks
the walk as non-first-fragment; the existing caller then uses the no-L4
sentinel instead of interpreting payload as transport data. First fragments
(including offset-zero fragments) continue through the extension walk.

The parity test module now covers non-first fragment payloads mimicking
oversized AH and Destination Options headers, valid first-fragment AH and
Destination Options headers, and truncated real headers retaining fail-closed
behavior.

## Validation

- For standalone RED/GREEN, write this identical source to
  `userspace-dp/ipv6_frag_13959_repro.rs` in each worktree. Its relative module
  path intentionally selects that checkout's production walker:

  ```rust
  #[path = "../userspace-xdp/src/ipv6_ext_walk.rs"]
  mod ipv6_ext_walk;

  const TCP: u8 = 6;
  const FRAGMENT: u8 = 44;
  const DEST_OPTS: u8 = 60;
  const AH: u8 = 51;

  fn packet(next: u8, fragment_field: u16, body: &[u8]) -> Vec<u8> {
      let mut bytes = vec![0u8; 40];
      bytes[0] = 0x60;
      bytes[6] = FRAGMENT;
      bytes.extend_from_slice(&[
          next,
          0,
          (fragment_field >> 8) as u8,
          fragment_field as u8,
          0xde,
          0xad,
          0xbe,
          0xef,
      ]);
      bytes.extend_from_slice(body);
      let payload_len = (bytes.len() - 40) as u16;
      bytes[4..6].copy_from_slice(&payload_len.to_be_bytes());
      bytes
  }

  fn walk(bytes: &[u8]) -> Option<ipv6_ext_walk::ExtWalk> {
      let data = bytes.as_ptr() as usize;
      ipv6_ext_walk::walk_ipv6_ext_headers(data, data + bytes.len(), 0, bytes[6], 40)
  }

  #[test]
  fn nonfirst_destopts_payload_does_not_drop() {
      let p = packet(DEST_OPTS, 8, &[TCP, 0xff]);
      let w = walk(&p).expect("non-first DestOpts-looking payload must not drop");
      assert_eq!((w.offset, w.protocol, w.non_first_fragment), (48, DEST_OPTS, true));
  }

  #[test]
  fn nonfirst_ah_payload_does_not_drop() {
      let p = packet(AH, 8, &[TCP, 0xff]);
      let w = walk(&p).expect("non-first AH-looking payload must not drop");
      assert_eq!((w.offset, w.protocol, w.non_first_fragment), (48, AH, true));
  }

  #[test]
  fn first_fragment_real_destopts_and_ah_are_parsed() {
      let mut dest = vec![TCP, 0];
      dest.extend_from_slice(&[0; 6]);
      let w = walk(&packet(DEST_OPTS, 1, &dest)).expect("valid DestOpts must parse");
      assert_eq!((w.offset, w.protocol, w.non_first_fragment), (56, TCP, false));
      let mut ah = vec![TCP, 1];
      ah.extend_from_slice(&[0; 10]);
      let w = walk(&packet(AH, 1, &ah)).expect("valid AH must parse");
      assert_eq!((w.offset, w.protocol, w.non_first_fragment), (60, TCP, false));
  }

  #[test]
  fn truncated_first_fragment_destopts_and_ah_still_drop() {
      assert!(walk(&packet(DEST_OPTS, 1, &[TCP, 0])).is_none());
      assert!(walk(&packet(AH, 1, &[TCP, 0])).is_none());
  }
  ```

## Risk

Non-first fragments still cannot yield an L4 tuple from the shim; this is
intentional and matches the existing no-L4 handling. First-fragment parsing
and extension-header bounds checks are unchanged. The full userspace-dp Cargo
test suite remains unverified because of the unrelated compile error above.
