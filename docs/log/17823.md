# #17823 — Preserve complete prefix identity and empty longest-match boundaries

- **Timestamp**: 2026-10-28
  - **Action**: The longest-match layout now retains valid max-length `longer` filters as empty-match boundaries. They still emit no permit, but when a broader renderable permit contains the boundary, the layout emits a stop covering that base: `deny P le <family-max>` normally, or bare `deny P` when P is /32 or /128 because `le max` on a /32 or /128 base is redundant (the bare deny is the same match set); FRR 10.7.1 accepts `le == plen` under `mask <= ge <= le`. An isolated empty `longer` still produces no prefix-list definition and keeps the undefined-list NOMATCH behavior. Invalid or unrenderable entries remain excluded. Prefix containment ordering is applied only when bases overlap by containment; a wholly disjoint list keeps authored order and byte-identical sequence numbers even when prefix lengths differ. `sameRouteFilterBase16762` already compares normalized `netip.Prefix` values (address and prefix length) on `origin/master` from #16866; IPv4 and IPv6 regressions now pin that complete identity so a same-address/different-length pair cannot suppress its stop. The pre-existing single-family disjoint golden was updated to assert authored /8 then /12 order. The `orlonger` arm intentionally emits `permit X/32 le 32`, which is valid FRR 10.7.1 syntax under `mask <= ge <= le`; do not remove `le` as invalid.
  - **File(s)**: `pkg/frr/prefix_list_render.go`, `pkg/frr/policy_render.go`, `pkg/frr/frr_test.go`, `pkg/frr/policy_routefilter_longest_17823_test.go`, `docs/log/17823.md`
  - **Validation**: Before the renderer change, `go test ./pkg/frr -run '^TestRouteFilterLongest17823' -count=1` failed the IPv4 and IPv6 empty-boundary cases because only the broader permit was rendered. Mutating the base comparison back to address-only made both same-address/different-length identity cases fail (two entries instead of the required permit, stop, broader permit); forcing longest-prefix sorting on a disjoint list made the unequal-length byte-identity golden fail with /12 moved ahead of the authored /8. The stale `TestPolicySingleFamilyRouteFilterUnchanged` order assertion initially failed against the new authored-order behavior; its assertions/comments now pin /8 seq 5 followed by /12 seq 10 and the test passes. The complete #17823 regression file and existing #16762 longest-match, nested-chain, root, same-base, and disjoint controls pass through named hermetic renderer tests. `go vet ./pkg/frr/` is clean, and `gofmt -l` plus `git diff --check` reported no issues. The full package suite was not run: it contains live tests that execute `ip netns` and start FRR daemons, outside the named hermetic test scope.
  - **Risk**: Nested route-filter lists retain their intended longest-match sequence changes. A valid empty max-length `longer` now contributes only a stop when a broader permit could otherwise accept its route; it is not widened into a permit or a deny-all list. Disjoint lists retain their authored order and bytes. No schema or validation behavior changed.
