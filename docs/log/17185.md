# #17185 — R4-Q16-05: `OverlapTracker` compiled six test-only check/record wrappers into production

- **Timestamp**: 2026-10-27
- **Defect (live on origin/master 59e7f8b74b)**: Of eight
  `OverlapTracker` check/record entry points in
  `userspace-dp/src/fragment_overlap/mod.rs`, production called only
  `check_overlap_fragment_detailed` and
  `check_and_record_fragment_detailed`. The six short wrappers were
  `pub(crate)` production methods, so `cargo check --bin
  xpf-userspace-dp` warned `methods check_overlap,
  check_overlap_fragment, check_overlap_detailed, check_and_record,
  check_and_record_fragment, and check_and_record_detailed are never
  used`. Census on current master: `check_overlap` 22 callers,
  `check_overlap_fragment` 2, `check_and_record` 54 (+2 in
  `afxdp/tests_9950.rs`, +2 in
  `afxdp/frame/tests_10661_atomic_chain.rs`),
  `check_and_record_fragment` 1 (+1 in `tests_9950.rs`),
  `check_and_record_detailed` 1 — every one inside `#[cfg(test)]`
  code — and `check_overlap_detailed` zero callers anywhere. The
  bool wrappers also hid the two-phase production contract (record,
  then `commit_admission`/`fail_admission` at TX accept) by settling
  immediately with `is_last = false`.

## What

- Deleted `check_overlap_detailed` (no caller at all).
- Moved the five wanted conveniences under `#[cfg(test)]` in the
  same `impl OverlapTracker` — the in-file precedent is
  `#[cfg(test)] release_completed` / `len` — so production compiles
  exactly two non-test check/record methods:
  `check_overlap_fragment_detailed` and
  `check_and_record_fragment_detailed`.
- Renamed the three `check_and_record*` conveniences so the name
  encodes the immediate settle the old name hid:
  `record_and_settle_non_terminal` (`is_last = false`, admission
  committed at once), `record_fragment_and_settle` (explicit
  `is_last`), and `record_non_terminal_detailed` (returns the
  unsettled `OverlapCheckResult` for explicit settling). All 58
  test call sites renamed (54 + 2 in `tests_9950.rs`, 2 in
  `tests_10661_atomic_chain.rs`, plus the `check_and_record_fragment`
  site in `tests_9950.rs` → `record_fragment_and_settle`, and the
  sole `check_and_record_detailed` site →
  `record_non_terminal_detailed`). `check_overlap` /
  `check_overlap_fragment` keep their names — a pure check has no
  hidden settle — now `#[cfg(test)]` with docs pointing production
  readers at `check_overlap_fragment_detailed`; the `merge_ranges`
  doc links and two stale test comments updated to the surviving
  names.

## Validation

- `cargo check --bin xpf-userspace-dp`: no diagnostic references
  `fragment_overlap/mod.rs`'s check/record methods; the six
  never-used warnings are gone. (A pre-existing, unrelated
  never-used warning for the `OVERLAP_CAP_PER_DOMAIN_PER_SHARD`
  alias at `mod.rs:207` remains — untouched by this change, out of
  scope.)
- Named hermetic tests only (`cargo test --bin xpf-userspace-dp --
  --exact <name>`), each exercising a renamed wrapper:
  `fragment_overlap::tests::adjacent_ranges_do_not_overlap_9950`
  (record+settle), `fragment_overlap::tests::
  check_is_pure_and_agrees_with_record_9950` (pure check vs record),
  `fragment_overlap::tests::
  terminal_end_conflicts_match_pure_and_record_checks_13680`
  (fragment check), `fragment_overlap::tests::
  seeded_index_defeats_targeted_single_shard_fill_12189` (detailed
  record), `afxdp::tests_9950::
  f035_shard_full_drop_is_not_forward_accounted_10285` (fragment
  record+settle), `afxdp::frame::tests_10661_atomic_chain::
  overlap_tail_dropped_like_plain_control_10661` (record+settle).

## Risk

- None to production behavior: the two production methods and every
  production caller are byte-identical; the removed/renamed methods
  existed only for tests. Test semantics are unchanged — each helper
  keeps its exact body (same `is_last`, same immediate
  `commit_admission` settle).
