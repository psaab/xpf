# #15065 — flat RI routing-options generate / forwarding-table export are silently dropped (A01-04)

- **Timestamp**: 2026-10-18
- **Action**: Pointed `routing-instances <name> routing-options` at a new shared node `schemaRoutingInstanceRoutingOptions` whose carried subtrees (`static`, `rib`, `autonomous-system`, `rib-groups`, `interface-routes`, `generate`, `forwarding-table`) are the global `schemaRoutingOptions` children by pointer, mirroring #9351's `schemaRoutingInstanceProtocols`. Previously the per-instance schema declared only `static`/`rib`/`interface-routes`, so `SetPath` packed a flat-set `generate`/`forwarding-table` tail where no compiler reads it: a VRF's generated routes and FIB export policy vanished in the flat spelling and on every `display set` restore of a working hierarchical VRF, on a clean commit. `router-id` stays global-only because `compileRoutingOptions` reads it only when `instanceName` is empty and no per-instance slot carries it.
- **Base**: `origin/master` `162fc049e2`.
- **Files**: `pkg/config/schema_routing.go`, `pkg/config/routing_instance_routing_options_flat_15065_test.go`, `pkg/config/testdata/spelling_gate_members_7484.txt` (6 new `routing-instances <*> routing-options …` rows from the regenerated census, unrelated on-master drift trimmed), `docs/config-schema.md`, `docs/log/15065.md`.
- **Scope**: Compiler unchanged — `compileRoutingOptions` already parsed `generate`/`forwarding-table` and `compileRoutingInstances` (#11782) already copied them; only the schema walk that shapes the flat-set AST was missing the keywords. NOT changed: `compileRoutingOptions`' `expandFlatRun(node.Children, schemaRoutingOptions)` (hierarchical trees already shape these; flat chains are handled by `SetPath` via the schema, and routing-options flat chains are pre-split by that walk for the global case).
