## Change

`hostInboundFilterExcept` now resolves known protocol exclusions through `HostInboundProtocolMatch` for IPv4 and IPv6 and removes any surviving protocol token whose match intersects an excluded tuple. Exact-name subtraction remains in place. The implementation shares the existing family-scoped intersection path with system services; meta-tokens have no tuple and are not expanded as exclusions. The protocol catalog audit found one overlapping family-scoped pair: `igmp` and `dvmrp`, both `(ip, IP protocol 2)`.

Added exhaustive protocol-catalog subtraction coverage, hierarchical and flat `igmp except` cases, the reverse `dvmrp except` case, unexcluded-all and unrelated-protocol controls, and a repeated-stanza re-admission regression. A Go compiler-emission fixture is consumed by the Rust host-inbound classifier parity test. Updated the host-inbound matrix and corrected the earlier #12053 log's historical divergence note.

## Risk and residual

Subtraction is token-granular: when any tuple of a token intersects an excluded tuple, that whole token is removed; independently named, non-overlapping protocols remain. Family matching prevents an IPv4 exclusion from removing a distinct IPv6-only protocol that happens to share a number. `all` remains the authored positive meta-token when there are no exclusions; with a concrete exclusion it is expanded before tuple subtraction. No live cluster or network configuration was changed.
