## Change

The userspace manager now keeps two scheduler-state maps:

- `policySchedulerDesired` is staged by the daemon before a full compile or scheduler/route-overlay republish and is used as snapshot-build input.
- `policySchedulerActive` remains the applied/show view and advances only after the helper accepts the snapshot.

The snapshot carries an unexported scheduler-state stamp between build, XSK deferral, and publish. Because the stamp is unexported, `encoding/json` omits it from the helper wire representation; `snapshotContentHash` hashes that JSON representation and therefore excludes the stamp too. `TestConfigSnapshot10005_SchedulerStampIsLocalOnly` pins both properties.

Applied-state commits now occur only at successful full apply, scheduler republish, route-overlay publish, deferred-snapshot synchronization, and deferred worker-arm retry boundaries. Protocol mismatch, rebuild, disarm, bootstrap, apply, and deferred-publication failures retain the prior applied/show state while leaving the desired state available for retry. The existing adapter and no-helper tests were updated to assert the new desired/applied distinction.
