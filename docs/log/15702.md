# Issue #15702: rpmConfigHash redaction collision skips RPM re-apply

- **Timestamp**: 2026-10-19
- **Problem**: `rpmConfigHash` (`pkg/daemon/daemon_rpm.go`) fingerprinted the effective RPM stanza with `json.Marshal`. `RPMTest.MarshalJSON` (`pkg/config/types_system.go`, #6733) rewrites `Target` through `config.RedactURL` (`pkg/config/secret.go`), which strips query, fragment, and userinfo. An `http-get` target edit touching only those probe-effective parts (e.g. `http://host/health?a=1` → `?a=2`, a fragment change, or a credential rotation in userinfo) therefore produced an identical hash, `reconcileRPMMode` took the hash-gated no-op path, and `d.rpm.Apply` was skipped — the running probe kept the stale target.
- **Fix**: `rpmConfigHash` still hashes the JSON payload (all other fields, RETH map, determinism preserved), then mixes the raw unredacted `Target` strings into the same SHA-256 digest in sorted probe/test order with length-prefixed `probeName`/`testName`/`Target` entries, matching the raw-field rationale in `snmpConfigHash` (`pkg/daemon/daemon_snmp_reconcile.go`). The hash is in-memory only and never logged or persisted, so hashing the unredacted target leaks nothing. Marshal failure still falls back to the zero hash (forces re-apply).
- **Regression check**: `TestRPMConfigHashRedactedTargetFields15702` covers query, fragment, and userinfo-only differences plus identical-target hash equality.

## RED -> GREEN proof

- **RED** (pre-fix, test present on `origin/master` `9e04c0d989`): `go test ./pkg/daemon/ -run 'TestRPMConfigHashRedactedTargetFields15702' -count=1 -v` failed all three subtests — `targets differing only in query/fragment/userinfo must hash differently`.
- **GREEN**: Same command passes after the fix; neighbouring `TestRPMConfigHashSensitivity` and `TestReconcileRPMConfigHashGating` also pass.
