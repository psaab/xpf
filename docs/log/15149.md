# #15149 — Dead-worker sweep never retires the D11 IPsec-inner worker (B12-01)

## Defect

The 1 Hz dead-worker sweep (`retire_selected_worker_holders` in
`userspace-dp/src/afxdp/coordinator/status.rs`, driven from
`refresh_status`) reclaimed NAT holder bits, steering claims, and CoS
V_min slots for a panicked worker, but never called
`IpsecInnerWorkerTransport::retire_worker`. The router kept hashing
IPsec-inner flows to the dead worker; its 128-deep queue accepted admits
that nothing drains, then refused them as WORKER_QUEUE_FULL, and
requests already admitted completed only by Go ack timeout
(`pkg/nfqueue/pipeline.go` deadline). Conditional on a worker panic (the
#925 "degraded but forwarding" posture), a deterministic share of
IPsec-inner flows was blackholed persistently.

## Fix

- `userspace-dp/src/afxdp/coordinator/status.rs`: in the dead branch of
  `retire_selected_worker_holders`, call
  `slow_path.ipsec_inner_transport().retire_worker(id)` then
  `join_worker_after_termination(id)` (the thread has exited — the same
  quiescence witness the full-stop path in `coordinator/mod.rs` uses),
  then deliver the reaped requests' terminal Deny verdicts to the
  Go-facing completion core via `complete_ipsec_inner_verdict`.
- `userspace-dp/src/afxdp/ipsec_inner_queue.rs`: `retire_worker` /
  `join_worker_after_termination` now record a terminal
  `IpsecInnerVerdict::Deny` (stage `d11_worker_dead`, reason
  `SUBMIT_UNAVAILABLE`) for every descriptor they terminalize — enqueued
  descriptors in `reap_closed_queue`, worker-owned descriptors in the
  join — but only when the tombstone stale-claim wins, so a request
  whose worker verdict was already posted keeps that single terminal.
  The coordinator drains them via the new
  `take_reaped_terminal_verdicts`. Reaped verdicts bypass
  `drain_verdicts_into`, whose active-entry requirement would discard
  them (the join already removed the active entries).

Deliberate scope cut: the teardown path (`stop_inner`) already
retire+joins every worker; it now also accumulates `reaped_verdicts`,
but no consumer drains them there — the daemon is stopping and Go-facing
completions are moot. Drain cost is bounded by the slab cap (512).

## Tests

- New `dead_worker_sweep_retires_ipsec_inner_worker_15149` in
  `userspace-dp/src/afxdp/coordinator/ipsec_inner_dead_worker_15149_tests.rs`:
  two requests admitted to workers 0/1 via the real transport, worker 0
  marked dead, then the production sweep entry
  (`retire_dead_worker_holders`) runs. Asserts the survivor is the sole
  route for every flow, the dead worker's reaped request completes as
  `Denied` in the `ReinjectCore` while the survivor's stays pending, and
  the dead worker's slab returns to the pool. A live-worker control
  sweep first asserts D11 routing is untouched.
- Existing transport cells (`worker_transport_*`) and coordinator
  V_min/NAT sweep cells stay green; the new `reaped_verdicts` Vec is
  empty on their paths.
