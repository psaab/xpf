peer is down, every session delta on a primary answered not-ready

identical storm. Lane branch: `fix/9631-delta-queue`, base `origin/master`

## Fix part 1: delta fall-through (not early-drop)

`handleEventStreamDelta`: while the peer is down, deltas run the normal
conversion/queue path and report handled. Opens/updates counted as shed
(pre-filter frames) with a dampened WARN (first + 1/min); closes fall
through uncounted and journal for replay; schema gate + sync filter keep
running. Nil-store guard + cfg-nil-down `true` (connected cfg-nil stays
`false`). Connected path executes identical statements.

Why fall-through (gen-0 KILL folded with base evidence): `QueueSessionV4`
stamps the #2170 install gen BEFORE its disconnected send no-op
(`sync_conn_write.go:56-60` vs `:37-39`), so a later close draws a fresh
#2221 gen and journals (`:137-146`, 10k cap → `DeletesDropped` +
`forceResync`); early-dropping opens leaves no stamp, so closes draw gen 0
(`sync_conn_gen.go:250-258`), which the receiver applies UNCONDITIONALLY
even over newer installs (`:396-400`, `:424`) — racing the reconnect bulk
unordered and wiping same-key reopens. Fall-through reuses the proven drain
discipline exactly; no new seam, no new API. Pinned by the same-key
reopen cell, the cluster stamp→journal-gen cell, and the
10001-closes → `DeletesDropped==1` overflow cell.

Counter home: daemon atomics mirroring #7194 (`userspaceDeltaPeerDownDropped`
+ `userspaceDeltaPeerDownWarnAt`, accessor
`UserspaceDeltaPeerDownDroppedCount`), NOT SyncStats: the count must be
cumulative across reconnects (SessionSync objects are recreated), wire stats
describe the wire while drops are a daemon-side decision, and #7194 sets the
accessor-only precedent. This also avoided a 9915b SyncStats collision.

Drain-timing correction (KILL F5 half-adopted): both fallback arms gate on
`IsConnected`, so no drain runs DURING the outage — RPC clones accumulate
(4096/binding, overflow → `delta_loss` latch → #2442 resync) and drain
post-reconnect. Buffer independence itself holds in helper source
(`session_delta.rs:362-369` fan-out to RPC + stream handles), which also
makes stream-path close journaling the ONLY while-down close preservation.

## Fix part 2: barrier co-flip + owed-export re-drive

`handleEventStreamFullResync`: while down, shed (handled) + count +
latch `userspaceFullResyncOwedWhileDown` instead of wedging the flush head;
entry Warn moved below the gates (no WARN churn while down).
`repayOwedFullResyncIfDue` repays post-reconnect by re-running the normal
FullResync path (whose export delivers the live table the barrier asked
for), called once per fallback-loop tick ABOVE the helper-stream branch:
repayment is gated on HA sync connectivity, never helper-stream state, so an
HA reconnect while the helper stream is down still repays (a `!hasDrainer`
early-continue or connected-arm-only hook would strand it).

No-bulk-shape closure without new API: `forceResync`/`needColdPrime` are
private with no exported arm, and the daemon reconnect hook runs no session
export — so a daemon-contained latch repaid by direct export (which delivers
on any connected peer, bulk or not) closes the ReviewA no-bulk hole with
zero cross-package API. The debt is a boolean for "export the live table":
every successful export supersedes all barriers.

Consume hardening (advisory-folded): the debt is CAS-claimed BEFORE
attempting; a barrier shed concurrently with the export (peer flap) re-arms
the latch and survives the success — clearing after success would erase it
(proven RED by the `during`-hook fresh-shed cell, which fails on
Store-after-success). Re-arm on the single failure path; a flap-down
mid-export takes the shed arm, which self-re-arms; a concurrent second
repay loses the CAS safely. A generation counter was considered and
rejected: claim-before needs no post-success write, so a bool suffices.
Process restart abandons the latch, covered by the cold-start bulk (same
content). Callback-vs-repay double export is idempotent installs.

Churn acceptance: 5000 shed opens + 5 shed barriers emit exactly one WARN
(the first-drop dampened line) and zero ERRORs (log-capture cell);
refusal-triggered direct resyncs share the shed counter (scoped as
"resyncs shed").
