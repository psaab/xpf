# #13980 - Gate tunnel TX on the outer-egress redundancy group

- **Timestamp**: 2026-10-16
- **Action**: Tunnel HA enforcement now checks both the endpoint RG and the outer L3 egress RETH RG before forwarding GRE/ip6gre encapsulation. It checks the existing outer-route resolver's L3 `egress_ifindex` (not the VLAN parent `tx_ifindex`); WireGuard's per-peer resolution re-resolves its materialized next-hop in the endpoint transport table. An inactive, absent, or unresolved outer RETH RG becomes `HAInactive`; non-RETH egresses remain ungated. Regression cells cover GRE peer-owned outer RG2 with endpoint RG1 active, both-active forwarding, endpoint-inactive gating, non-RETH egress, and WireGuard per-peer outer RG ownership.
- **Validation**: `cargo check --bin xpf-userspace-dp` passed. All 189 `afxdp::forwarding::tests` passed after a temporary, reverted correction to the unrelated baseline test fixture at `coordinator/tests.rs:11773` (`maps.local.insert((0, inner_dst))`); without it the test target does not compile (`HashSet<(u32, IpAddr)>` receives `IpAddr`). Red-on-revert failed at the intended assertion: tunnel resolution remained `ForwardCandidate` while the outer RG2 was inactive.
- **Risk**: Tunnel HA enforcement re-resolves the outer route on candidate tunnel packets; ordinary non-tunnel forwarding is unchanged. The existing local-origin GRE caller also uses this enforcement function.
