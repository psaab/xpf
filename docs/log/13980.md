# #13980 - Gate tunnel TX on the outer-egress redundancy group

- **Timestamp**: 2026-10-16
- **Action**: Tunnel HA enforcement checks both the endpoint RG and the outer L3 egress RETH RG before forwarding GRE/ip6gre encapsulation. The snapshot builder caches fixed GRE/ip6gre outer-route RGs and configured WireGuard peer outer-route RGs using the existing resolver's L3 `egress_ifindex` (not VLAN parent `tx_ifindex`). Runtime-learned WireGuard endpoints resolve their materialized next-hop in the endpoint transport table. An inactive, absent, or unresolved outer RETH RG becomes `HAInactive`; non-RETH egresses remain ungated. Fabric-ingress finalization preserves its legacy plain-flow exception, but does not restore tunnel forwarding when the endpoint owner is active and the outer RG is inactive.
- **Validation**: `cargo check --bin xpf-userspace-dp` passed before the follow-up changes; the 190 `afxdp::forwarding::tests` passed with the follow-up code active after temporarily correcting the unrelated baseline test fixture at `coordinator/tests.rs:11773` (`maps.local.insert((0, inner_dst))`) to compile the target. The fixture change was reverted. Red-on-revert of the fabric-ingress regression failed as intended: `ForwardCandidate` was restored instead of `HAInactive` when the outer RG2 was inactive.
- **Risk**: Runtime-learned WireGuard endpoints still require an outer-route lookup at enforcement time; fixed GRE/ip6gre and configured WireGuard routes use snapshot-derived RGs. The existing local-origin GRE caller also uses this enforcement function.
