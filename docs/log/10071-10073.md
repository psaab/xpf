# Filter trio #10071–#10073

## Scope

- **#10071**: packed unknown `from` leaves (`term T from ttl 64;` and the
  from-level packed form) were discarded before `UnknownFrom` validation.
- **#10072**: the term-level packed valueless form (`term T from protocol;`)
  escaped the #8480 strict gate and the #9875 marker view.
- **#10073**: from-level prefix-list one-liners lacked `args:1/multi`, so their
  values vanished from compiled references; the immutable fix is
  `a1683db15`.

## Fixes

#10071 keeps the firewall fallback local to the compiler. A term-level packed
`from` tail is reconstructed, and the unknown scanner records the leaf in
`UnknownFrom` before the existing strict gate runs. The scanner follows the
same open-schema levels as `packedBody`, so known descendants such as
`flexible-match-range range r` are not misreported as root unknown leaves. The
mixed known/unknown packed form is also pinned: `UnknownFrom == [ttl]`.

#10072 makes the #8480/#9875 helper use the same raw packed-segment lowering as
the compiler, so a later `from` marker cannot become the previous leaf's value.
Strict compilation rejects `protocol` by name, while the lenient path records
`ValuelessFrom == [protocol]`; the existing from-level rejection remains
covered.

#10073's schema declarations now consume one prefix-list argument and preserve
multi-valued references for `any`, `inet`, and `inet6`, both source and
destination directions. Its six valued and six valueless cells remain green.

## Follow-up regression correction

The original issue commits remain separate and `a1683db15` is immutable. Full
suite triage then exposed a #10071 false-positive scanner on #6818's nested
`range`, plus #10073's intentional census reach shift. The transparent
follow-up commit `b14119630` recovers every packed `from` segment, preserves
quote/bracket provenance, refreshes the #8939 fixture (`ac6a41943`), and
restores the #8480 validation header. Commit `27f88df81` then shares that raw
segment lowering between compilation and validation, covering multiple packed
segments without turning a later `from` marker into a prior leaf value. Commit
`091b91646` also gates raw segment boundaries on bracket provenance, so a
keyword-shaped bracketed value such as `source-prefix-list [ from ]` remains
a reference. These fixes are not hidden in the documentation commit.
