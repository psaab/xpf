# #15151 — userspace-dp: D11 admit refuses WORKER_QUEUE_FULL on lock contention; idle drains serialize every worker (B12-03)

- **Timestamp**: 2026-10-19
- **Action**: Split D11 contention (Busy) from genuine queue-full (Full)
  end-to-end, publish the worker-queue/active/uncertain tables as
  `ArcSwap` snapshots with atomic pending counters, and gate the worker
  poll D11 block on those counters so an idle iteration takes zero
  shared locks.
- **File(s)**:
  - `userspace-dp/src/afxdp/ipsec_inner_queue.rs` (Busy/Full errors,
    pending counters, ArcSwap transport, gated drains, regression tests)
  - `userspace-dp/src/afxdp/worker/loop_body/mod.rs` (idle D11 gate)
  - `userspace-dp/src/slowpath.rs` (BUSY → same fail-closed ADMIT_FULL)
  - `userspace-dp/src/afxdp/ipsec_inner.rs`, `src/protocol/status.rs`,
    `src/server/helpers/status.rs` (busy counters in status snapshot)

## Mechanism (verified at base f3c63400be)

`admit_descriptor` resolved the target queue via
`self.queues.try_lock()` (ipsec_inner_queue.rs:1793-1805 pre-fix): any
worker holding the shared `queues` mutex — every worker's
`drain_worker` took `queues.lock()`, then `active.lock()`, on every
poll iteration (loop_body/mod.rs:719-838 via
`refresh_runtime_view`), and verdict drains took `verdicts` +
`uncertain` + `active` (drain_verdicts_into:1942-1960 pre-fix) — made
the producer's `try_lock` fail and the frame was refused
`WORKER_QUEUE_FULL` (E23) and dropped in Go, with empty ingress queues.
The same conflation existed one level down: `try_enqueue` /
`try_post` counted a contended `try_lock` as FULL. There was no
emptiness gate anywhere: the transport is always present
(loop_body:369-371), so the locks were taken every iteration, IPsec
or not, also serializing all workers against each other.

## Fix

- **Busy ≠ Full**: new `IpsecInnerEnqueueError::{Busy,Full}` and
  `IpsecInnerPostError::{Busy,Full}`. Contention counts
  `IPSEC_INNER_WORKER_QUEUE_BUSY_TOTAL` /
  `IPSEC_INNER_VERDICT_QUEUE_BUSY_TOTAL` and returns the distinct
  Rust-internal reason `WORKER_QUEUE_BUSY` (61, deliberately outside
  the closed §4.1 wire set {5,6}∪{32..=60}); only genuine depth
  exhaustion / closed queues count FULL/E23. `slowpath.rs` maps BUSY
  to the same fail-closed `ADMIT_FULL` drop as FULL, so Go-visible
  behaviour is unchanged (drop, never fail-open) while Rust callers
  and tests can distinguish retryable busy from full.
- **Lock-free tables**: `queues`, `active`, `uncertain` are now
  `Arc<ArcSwap<…>>` snapshots (the tree's existing `wg_uncovered_queues`
  idiom). `admit_descriptor` loads the queue `Arc` lock-free — the
  `queues.try_lock()` refusal leg is gone. Lifecycle writes
  (prepare/publish/retire/join, verdict post/requeue, active joins)
  are serialized by a cold `lifecycle_lock` and publish fresh
  snapshots; per-worker queue `Arc`s survive snapshots, so closed
  queues stay closed and worker-ID reuse still installs a fresh `Arc`.
- **Atomic pending counters**: each ingress/verdict queue maintains
  an exact `pending_count` under its mutex (synced on every mutation,
  including `drain_expired` re-queue); the transport mirrors
  `uncertain`/`active` depths. `drain_worker`, `drain_verdicts_into`
  and both queue `drain_into`s return on atomic gates when empty, and
  the worker loop skips the whole D11 block via
  `transport.has_pending_work(worker_id)` — an idle iteration takes
  zero shared locks.
- NOT changed: queue depths, drain budgets, slab/tombstone/router
  semantics, verdict wire values, Go code. Producer still never blocks.

## Risk

- Operator-visible delta: two new additive status counters
  (`ipsec_inner_worker_queue_busy_total`,
  `ipsec_inner_verdict_queue_busy_total`, defaulted JSON fields, no
  wire bump); frames previously mislabelled FULL under contention are
  still dropped fail-closed, now counted as busy.
- Residual: per-queue enqueue still `try_lock`s (single-producer
  contention is momentary and now correctly classified); a full
  lock-free MPSC swap was not needed to remove the cross-worker
  serialization, which was the shared tables.
