# Issue #13158: Include all unzoned VRRP VIPs in host-inbound denies

D3-12 found that the production `BuildUnzonedHostInboundAddrs` path included configured VRRP virtual addresses only for units in quarantined membership sets. Unlike `buildFenceAddrSetsFromSnaps`, it therefore omitted VIPs on ordinary unzoned interfaces, interfaces in `DroppedEnforcementChild` zones, and quarantined units authored using Linux interface spelling. On an HA backup, those VIPs are absent from kernel snapshots; the live `xpf_hostinbound` catch-all then fails to drop traffic addressed to them, despite the cold-boot fence including them.

The builder now enumerates configured VRRP VIPs for every enabled configured unit not claimed by a surviving zone view. Its existing address deduplication, lifeline exclusions, and zoned-address subtraction remain in force. The regression test covers an unzoned unit, a poisoned/unbound zone, and a Linux-spelled quarantined member, and checks the cold-boot fence as a positive control.
