# #12071 — gate QNH metric rules by daemon match capability

- **Timestamp**: 2026-10-08 (stacked on #12067 / `faaa1adc8`)
- **Action**: emit QNH metric rules only where the consuming daemon can evaluate both destination and configured next-hop discriminators, and omit QNH map attachments from incapable IGPs.

## Why

The generated static route-map is shared by all IGP renderers. FRR 10.6 `ospfd` and `ripd` support IPv4 destination and next-hop prefix-list matches, but not IPv6 redistribution; `ospf6d` supports IPv6 destination/interface matches but no next-hop match; `isisd` supports IPv4/IPv6 destination matches but no next-hop or interface match. The prior shared map included both address families and was attached without daemon gating. Unsupported clauses can be discarded while the metric-setting action survives, broadening the metric to routes that did not match the QNH backup.

## What

- Added an FRR 10.6 per-daemon match-capability table and filter in `buildQNHMetricScope11447`. Since the generated map is shared by `ospfd` and `ripd`, only rules that both can evaluate are emitted; in the current FRR 10.6 tables these are fully discriminated IPv4 rules.
- Gated QNH scope passing at the OSPF, OSPFv3, RIP, and IS-IS redistribution call sites. OSPFv3 and IS-IS receive no QNH scope, so their ordinary static redistribution remains unattached to the QNH map.
- Updated the prior IPv6 pin to assert that OSPFv3 does not receive an unsupported metric map, and added a mixed-family regression covering capable attachments and the emitted map contents.
- No prior-stack hunks were modified; `debian/changelog` was not touched.

## Risk / residual

QNH metric export is intentionally no longer emitted to OSPFv3 or IS-IS, and IPv6 QNH metrics are not exported through the current shared OSPF/RIP map because FRR 10.6 provides no daemon that evaluates both IPv6 destination and next-hop prefix-list discriminators. No live FRR 10.6 LSDB/LSP metric proof or cluster/hardware mutation was performed; the LSDB/LSP metric acceptance check remains outstanding.
