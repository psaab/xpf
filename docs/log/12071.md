# #12071 — keep QNH metric actions daemon-scoped

- **Timestamp**: 2026-10-08 (stacked on #12067 / `faaa1adc8`)
- **Action**: keep generated shared QNH route-maps metric-free; apply QNH metric actions only to `ospfd` and `ripd` after each integrated reload, fallback, and retry.

## Why

FRR receives shared `frr.conf` route-map definitions in multiple routing daemons. The prior generated map copied QNH `set metric` actions everywhere even when a daemon could not preserve the complete destination + next-hop match. Unsupported match clauses could be discarded while the metric action remained, so gating route-map attachments alone did not remove the unsafe action from those daemon copies. The review found no active unsupported-daemon attachment or current traffic leak, but the installed shared map remained unsafe.

## What

- The integrated `frr.conf` now contains QNH destination/next-hop match sequences and `on-match next`, without generated QNH `set metric` actions. Manager-owned metric-only overlays target only `ospfd` and `ripd`, whose redistribution hooks preserve both IPv4 discriminators.
- Authored policy `then metric` actions remain in the integrated policy map and are not copied into QNH overlays or cleanup identities; later authored policy terms can still override the QNH metric.
- Before every integrated reload, the manager clears `no set metric` only for known previous generated QNH sequences on `ospfd`, `ospf6d`, `ripd`, `isisd`, and `bgpd`. It derives identities from prior manager overlays and the prior marked config, avoiding blind route-map wipes and making the additive `vtysh -f` fallback safe.
- Full-diff reload, additive fallback, and degraded retry all replay positive overlays only to `ospfd`/`ripd`. Partial overlay failure keeps sequence identities pending so retry clears any partial installation first.
- Overlays are temporary and memory-only. A FRR daemon restart loads the metric-free integrated config and remains fail-closed until the next Apply.

## Risk / residual

QNH export metric actions are intentionally available only to OSPFv2 and RIP; the current shared IPv4 map excludes IPv6 because no supported target daemon preserves both IPv6 destination and next-hop discriminators. FRR restarts do not persist manager overlays, so QNH metrics remain absent until Apply replays them. Authored policy metric actions are unaffected.
