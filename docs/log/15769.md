# #15769 - XSK neighbor lease demotion / self-promotion (G35-02)

- **Timestamp**: 2026-10-19
- **Action**: Fixed both halves of the #15247/#15624 XSK neighbor-lease defect in `userspace-dp/src/afxdp/`. (1) Demotion: the same-MAC arm of `insert_ndp_na_if_override_allows_inner` in `sharded_neighbor.rs` stamped `last_rx_learned_ns = Some(now)` via `map_or` even on a lease-free kernel-backed (authoritative) record, demoting it to a 60s RX lease that `age_rx_learned_neighbors` then evicted with no kernel reprogram (the arm returns `Some(false)`). It now refreshes only an already-`Some(_)` lease, mirroring `refresh_rx_learned_pair`. (2) Self-promotion: the monitor socket in `neigh_monitor_thread` binds `RTNLGRP_NEIGH` (`sa.nl_groups = 1 << (RTNLGRP_NEIGH - 1)`), and `add_kernel_neighbor` sends its `RTM_NEWNEIGH`/`NUD_STALE` request on a separate unbound socket, so the kernel multicast notification of the dataplane's own install is delivered back to the monitor — the socket check smr-c required confirms the echo path. `parse_neighbor_msg_with_reassert` now computes `kernel_confirmed = (state & !NUD_STALE) != 0` and promotes via the new `ShardedNeighborMap::mark_kernel_backed_if_confirmed`, which clears a live lease only on independent confirmation (REACHABLE/DELAY/PROBE/PERMANENT, or a kernel-originated changed binding); a pure `NUD_STALE` event on an already-leased entry leaves the lease intact. STALE stays in `USABLE_NUD` and kernel-originated STALE first-learns / same-MAC refreshes of lease-free entries keep their prior kernel-backed behavior (the insert path never stamps a lease), so dump/re-dump imports and solicited/kernel-confirmed acquisition do not regress. `update_dynamic_neighbor` (no production callers; test/shared-ops helper with no NUD state) keeps the unconditional `mark_kernel_backed_if_same`.
- **Validation**: New fail-on-revert tests, all RED on pre-fix code and GREEN after: `same_mac_xsk_refresh_preserves_kernel_backed_lease_free_15769` (sharded: kernel-backed ARP+NA keys survive a same-MAC XSK re-advert past the 60s+grace expiry while a leased control ages out), `stale_echo_does_not_promote_xsk_learn_but_reachable_does_15769` (monitor: unsolicited v4 ARP / v6 NA XSK learn echoed as `NUD_STALE` stays leased and ages out; REACHABLE / PERMANENT positive controls still promote), `kernel_stale_first_learn_stays_kernel_backed_15769` (kernel-originated STALE first-learn acquires no lease). `cargo test --bins 15769` = 3 passed. Neighbor regression filter (`cargo test --bins -- neighbor`): 324 passed, 1 failed — `poll_descriptor_stamps_neighbor_mac_epoch_from_outer_neighbor_shard_not_logical_6075`, which fails identically on pristine `origin/master` (verified by stashing the fix and re-running; pre-existing, unrelated GRE epoch test). Neighboring lease/monitor suites (15247/11406/10704/13660/15097/13661/13898/10690/11457 cells) are within the 324 passing.
- **Notes**: Scope is the narrowed live form only: no change to `USABLE_NUD`, the solicited/Override gates, `NUD_PROBE` handling, or the aging sweep itself. Residual: a leased entry whose genuine binding sits in kernel STALE past the lease still ages out and re-resolves via the existing probe path (unchanged pre-fix behavior for kernel-originated STALE refreshes of leased entries is intentionally preserved as the anti-poisoning bound from #15247).
