# Issue #15789 — XDP shim LAND disposition follows ScreenProfile.land

## Claim (narrowed, verified at origin/master f7c921ce29)

- The shim dropped every equal source/destination packet unconditionally
  at three sites in `userspace-xdp/src/lib.rs`: the healthy gate after
  the tagged-only VID-0 drop (:733), the established
  `PASS_TO_KERNEL` arm (:961, dead code behind the first gate), and the
  control-disabled path (:1620). The ingress zone's
  `ScreenProfile.land` and profile-wide `alarm-without-drop` could not
  decide that drop, so a LAND-disabled zone still lost the packet and an
  audit-mode zone lost it with no alarm accounting.
- The worker's profile-gated `check_land`
  (`userspace-dp/src/screen/stateless.rs`) never sees terminal
  kernel-pass packets, so no other screen compensates.

## Change

- `userspace-xdp/src/land.rs`: `is_land` unchanged; new
  `land_disposition(zone_known, screen_byte)` — PASS (0), DROP (1),
  ALARM (2); an unresolved zone or an unrecognised byte fails closed
  to DROP.
- `userspace-xdp/src/lib.rs`: new `userspace_land_screen` map
  (`HashMap<u16, u8>`, StableZoneID key); both live gates (healthy +
  ctrl-disabled) resolve the ingress zone through the existing WG
  ingress-zone (ifindex, VLAN) resolver and honour the byte — DROP
  drops with `land_drop`, ALARM counts the new `land_alarm` degraded
  reason (20, `MAX` 21) and falls through, PASS proceeds unscreened.
  The redundant PASS_TO_KERNEL-arm check is deleted (it was dead code
  behind the healthy gate). Unresolved zones drop, preserving #13953
  for unscreened zones and pre-#15789 control planes.
- Go (`pkg/dataplane/userspace/land_screen.go`): the classifier sync
  now reconciles `userspace_land_screen` from the snapshot's resolved
  screen state — published snapshots publish DROP/ALARM or an explicit
  PASS row per screened zone; missing-profile zones publish DROP (the
  worker's substituted `conservative_default` has LAND on); inert
  zones publish DROP/ALARM per the inert ref's audit flag. Keyed by
  `config.StableZoneID`; collisions poison to DROP. Map name pinned in
  `maps.go`, the loader pin inventory, and the retirement canary.
  `degradedPathReasonNames` gains slot 20 `land_alarm` (cap test
  20 → 21); the Rust debug reader's table gains the same slot.
- Regenerated `userspace_xdp_bpfel.o` + manifest + gate verdict:
  963340 processed insns (3.67% headroom, OVERRIDDEN — master was
  already OVERRIDDEN at 7.93% / 920733; the gate cost is recorded in
  the PR body, not hidden).
- `docs/afxdp-packet-processing.md`: the LAND backstop section now
  describes the profile-gated disposition.

## Risk

- Tunnel-decapsulated and pre-routing-NAT `LocalDelivery` packets are
  adjudicated by the worker, whose `check_land` is already
  profile-gated — no shim change needed there; the issue's tunnel arm
  is therefore not separately modified.
- A screened zone whose WG ingress-zone row is absent (WG map not yet
  synced, or a non-WG interface shape the WG builder does not cover)
  resolves as unknown and drops LAND packets even if its profile
  disables LAND — fail-closed, matching #13953, until the zone
  resolver covers that interface.
- Verifier headroom regressed 7.93% → 3.67% (still loads; verdict
  OVERRIDDEN as on master). Follow-up to recover headroom is an
  optimisation, not a correctness gate.
