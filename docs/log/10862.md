# 10862 — fragment pool deadlines and counts stay consistent

FragPool and pipeline-held fragments now share the first-seen absolute deadline, so a late fragment cannot keep a set alive after its held frames expire. IPv6 conflicting terminal fragments are rejected before retention, and fragment counts stay correct when a set is dropped alongside other live sets.

Regression coverage exercises the refreshed-pool expiry race and multi-set `Stats().Fragments` accounting.
