# #17074 — derive scheduler generation hash from the config struct (Fingerprint beside the types)

- **Timestamp:** 2026-10-27
- **Branch:** `fix/17074-campaign`
- **File(s):** `pkg/config/scheduler_fingerprint.go` (new), `pkg/config/scheduler_fingerprint_test.go` (new), `pkg/daemon/daemon_scheduler.go`

## Action

- Moved the scheduler-generation fingerprint beside the types it hashes: `(*SchedulerConfig).Fingerprint(w io.Writer)` and `(*SchedulerDayWindow).Fingerprint(w io.Writer)` in `pkg/config/scheduler_fingerprint.go`, writing every content field in declaration order (strings length-prefixed 8-byte LE, bools one 0/1 byte, `Days` in sorted key order, nil receivers/windows as the `"<nil>"` marker). Exported `config.WriteSchedulerHashString` for the two strings outside the structs (map key, `System.TimeZone`) so all digest strings share one framing.
- `policySchedulerConfigHash` in `pkg/daemon/daemon_scheduler.go` now hashes timezone + sorted names and delegates each scheduler to `Fingerprint`; deleted `writePolicySchedulerHashString`/`writePolicySchedulerHashBool`. Acceptance: `grep -c writePolicySchedulerHash pkg/daemon/daemon_scheduler.go` → 0.
- Added a reflection completeness guard (class U, hermetic): for each struct, flipping every non-excluded field to a non-zero value must change the fingerprint. The exclusion allowlist `schedulerFingerprintExcludedFields17074` is explicitly empty today.

- `go vet ./pkg/config/ ./pkg/daemon/`: clean. `gofmt -l` on touched files: clean.

## Risk

- Production fingerprint stays explicit field writes (no reflection on the apply path; reflection is test-only). Hash bytes are unchanged, so no scheduler re-prime churn on upgrade and no HA peer divergence.
- The daemon hash helper names are gone; the only new exported symbol is `config.WriteSchedulerHashString` (needed because Go cannot share the unexported framing helper across packages).
- No cluster gate: hermetic (class U) cells only per campaign assignment; throughput NOT-EXAMINED (no dataplane change).
