## Mechanism (origin/master b745b7e835)

- **B24-03**: `pkg/cli/cli_config.go` returned from the `| compare` branch before `displayPath` (edit path + typed path) was built, so `show security | compare` printed the global candidate-vs-active diff. `ShowCompare`/`ShowCompareRollback` (and redacted twins) took no path. The remote CLI (`cmd/cli/show.go`) rejected an explicit path outright because `ShowCompareRequest` had no path field — the two CLIs disagreed.
- **B24-04**: `valueProvider` in both `pkg/cli/completion.go` and `pkg/grpcapi/server_cluster.go` read `ActiveConfig()` only. In config mode a candidate-created zone was never offered and a candidate-deleted zone was still offered; before the first commit `ActiveConfig()` is nil and completion returned nothing for configured values.

## Change

- `FormatCompareAtPath(old, new, path)` navigates both trees to `path` (a side missing the path contributes no children, so added/deleted subtrees render as +/-), then runs the existing `diffNodes` with `path` as the `[edit …]` context. Empty path is byte-identical to `FormatCompare`. Redacted twin reuses the fingerprint clone.
- Store: `ShowCompareAtPath`, `ShowCompareRollbackAtPath`, `ShowCompareRedactedAtPath`, `ShowCompareRollbackRedactedAtPath`; the old no-path methods delegate with nil path. Local CLI builds `comparePath = editPath + typed path` for both compare arms.
- Wire: `ShowCompareRequest.path` (field 2, additive). gRPC `ShowCompare` passes it through; REST compare handler is unchanged (no path parameter — global only, as before). Remote CLI sends `editPath + typed path` instead of rejecting it.
- Authorization: a scoped compare discloses only its subtree, so it is priced as a path read (`AuthorizeConfigShowCompareAtPath` → `AuthorizeConfigShowPath`); a bare compare keeps the whole-tree refusal for `*-configuration`-restricted classes. Local gate computes the same effective path.
- **B24-04**: `Store.CandidateConfigForCompletion()` strict-compiles the candidate, cached by `candidateGen` (guarded by a dedicated `completionMu` since the compile runs under `s.mu.RLock`). Both `valueProvider`s and both operational `treeConfig` paths (unrestricted callers only) draw from the candidate in config mode; restricted classes keep the active-config gate (fail closed, no new disclosure). An uncompilable candidate falls back to the active config (commit-time validation is the backstop).
- The predefined application catalogue (`junos-*`, `any`) stays suppressed until the first commit, preserving the #5763 pre-commit contract: the suppression key is `EverCommitted`, not candidate presence, so `default-catalog` and `configured-shadows` phases still see the catalogue after a commit (including while editing a further candidate).
- NOT changed: REST compare shape, rollback slot semantics, `ShowCompareRequest.rollback_n` validation, secret redaction/fingerprints (#11819), completion authz roots, commit path.
