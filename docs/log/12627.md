# #12627 — NAT address-name quarantine

- **Base**: `30b1ce9ff` (PR base)

## Change

Direct feed-bound NAT address-name references preserve the policy path's additive behavior when the same-named static closure resolves: live feed prefixes and usable static prefixes are both enforced. If that static closure is poisoned, a ready direct feed is authoritative and NAT uses its prefixes alone instead of publishing a partial static subset. A present-empty feed with no usable static closure uses an unparseable match-none token, including for CIDR-shaped names.

SNAT address-name resolution distinguishes poisoned closures from valid empty feeds. Any poisoned SNAT source- or destination-address-name taints the whole NAT rule: the builder clears the affected selector side and sets the existing `LenientMatchDropped` marker. Clearing that side lets the rule match within its remaining zone, L4, and selector constraints; the marker then drops and stops the flow instead of publishing a surviving subset or letting a poisoned `off` rule fall through.

DNAT retains its existing per-name behavior. Its snapshot does not have a whole-rule poison/tombstone field; adding one changes snapshot shape and is a separate contract decision. Nested feed members in static sets continue to use the shared recursive expander.

## Residual / risk

SNAT quarantine is intentionally broader than the named set: clearing a poisoned selector side means the marker can drop any flow matching the rule's remaining scope and constraints, not just flows that would have matched one of the set's resolvable members. DNAT bracket-list references can still publish the resolvable per-name subset when another name is poisoned. Whole-side fail-closed DNAT quarantine requires a snapshot poison/tombstone field (or equivalent wire-contract change), intentionally not introduced here. NAT's unresolved-name fallback uses the fixed prefixed token from #12626 so CIDR-shaped names cannot become literal matches.
