# 9862 — `apply-groups-except H` ignored when H is inherited through another group

## The defect

`expandGroupsRecursive` (`pkg/config/ast_groups.go:332`) expands G's own
`apply-groups H` into G's cloned body BEFORE merging that body into the
destination, and the outer `mergeNodes` call carries `group = "G"`
(`ast_groups.go:351`). Both except checks — the entry check and the
same-keyed-sibling check — matched that single outer name only, so a
destination carrying `apply-groups-except H` inherited H's content anyway
whenever H arrived through G.

Measured on base `68a4ec6fd` through `CompileConfigLenient`:

```junos
groups { H { security { zones { security-zone zgh; } } } G { apply-groups H; } }
apply-groups G;
security { zones { apply-groups-except H; security-zone trust { } } }
```

compiled `[trust zgh]` in both inline spellings; the direct-`apply-groups H`
rows compiled `[trust]`. When the excluded content carried a reserved zone
name (`security-zone any;`), strict commit was refused with no documented
suppression.

## The fix (shape)

Hybrid outer-veto plus leaf-provenance filtering, after two plan reviews
killed the leaf-only shape (review B, executable counterexample) and approved
the hybrid with changes (review A):

1. **Leaf provenance.** New unexported `Node.fromGroups`: the groups whose
   body literally contains the node. Each group's context-walked clone is
   tagged with its resolved name before its nested references expand, so
   nested-adopted nodes keep the nested name. Tags are chain-independent and
   flow through the #4474 memo verbatim via `cloneNodes` (deep-copied, never
   aliased; nil-preserving so untagged nodes allocate nothing). The
   inactive-strip clone copies it too (B5; latent today, #6673-class if any
   flow ever strips second). Gated by a `haveExcept` pre-scan: except-free
   commits tag nothing and behave bit-identically (B7).
2. **Accumulated exclusion set.** `mergeNodes` threads the vars-resolved
   except names from its level plus ancestors ("here and below"), each call
   descending on its own copy. Fresh applications start from nil, so an
   explicitly re-applied group below an exclusion still applies, as #9422.
3. **Outer veto preserved exactly.** Entry vetoes iff the outer name is in
   the set (equivalent to the old per-level check: a veto prunes the
   descent); the siblings check becomes a same-keyed except-union plus
   veto-if-outer. No charge line moved: per-node charges stay before the
   filter, vetoes stay uncharged as the #9422 vetoes (B2/A3, verified by
   diff: zero charge lines touched).
4. **Per-node nested filtering.** Leaves filter atomically; containers route
   or adopt as shells when a descendant survives; wholesale adoption prunes
   recursively after the wildcard prune and before the emptiness check and
   landed-size charge (B3/A4); #9802 routing threads the sibling union
   (same-keyed twins are ONE level — B4 over A8, which would have broken the
   pinned AcrossDuplicateBlocks union rule); the #9801 leaf-to-container
   flip waits for an adoption when filtering is active (A5); #7648
   packed-leaf bodies inherit source provenance (A6).
5. **Union conservatism.** `mergeLeafListInto` clears the tag on a tagged
   destination: cross-group unions mix members under one node, so provenance
   is uncertain and the filter falls back to keep (never over-excludes;
   under-exclusion stays status-quo with a follow-up). Scalar/zone override
   needs no such rule — the survivor's tag is the survivor's value.

Semantics, all pinned: except-H drops H's statements wherever applied;
G's own content survives except-H; except-G vetoes the whole application
(B's counterexample, no-regression); a middle-group except drops that
group's own statements while deeper-nested statements survive (today's
outcome, Junos-unknown, documented); except-inside-group-def order
dependence is pre-existing, unchanged, and documented (B8).

## Considered and rejected

- **Leaf-only (no outer veto):** killed in plan review — excluding the sole
  applied group would still inherit its nested content, a silent
  keeping-direction change from today.
- **Chain provenance:** destination-side-faithful for middle-group excepts,
  but needs relative/absolute tag translation across memo hits (chain in the
  memo key reintroduces the #4474 exponential) plus strip/prepend walks and
  dst-group subtraction at inner merges — double the machinery for an
  undocumented Junos corner. The required direction ("check against ANY
  contributor, not just the outer name") describes the hybrid literally.
- **Destination-side expansion (leave nested refs for the destination
  levels):** inverts precedence between nested-group content and authored
  deep apply-groups, and needs per-ref ancestry stacks threaded through tree
  descent to keep cycle detection. Rejected on blast radius.
- **Per-member leaf-list filtering now:** correct but LARGE (collapsed
  members have no node to tag; block-vs-collapsed would diverge). Follow-up.
