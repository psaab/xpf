# #15185 — frr: family-less `protocols bgp damping` renders at router level (C04-03)

- **Timestamp**: 2026-10-19
- **Action**: In `generateProtocolsCluster15158`
  (`pkg/frr/protocols_render.go`), stopped emitting
  ` bgp dampening H R S M` directly under `router bgp`. The line is now
  computed once (same defaults 15/750/2000/60 and the same #14585
  suppress<=reuse omission belt) and emitted as
  `  bgp dampening H R S M` inside each rendered unicast
  address-family block — `address-family ipv4 unicast` and
  `address-family ipv6 unicast` — in the default instance and in every
  routing-instance (`router bgp <as> vrf <name>`) stanza, since both go
  through the same renderer. A valid dampening line also opens both AF
  blocks when nothing else would (no neighbors, no multipath, no IPv6
  redistribute), mirroring the #9667 IPv6-redistribute-alone precedent,
  so damping reaches a family before its first peer exists.
- **File(s)**: `pkg/frr/protocols_render.go`,
  `pkg/frr/bgp_dampening_af_15185_test.go` (new),
  `pkg/frr/README.md`, `docs/log/15185.md`

## Mechanism (verified at base 902b448a10)

Pre-fix, `protocols_render.go` wrote the dampening line in the
router-level block before any `address-family`:

```text
router bgp 65001
 no bgp ebgp-requires-policy
 bgp router-id 1.1.1.1
 bgp dampening 10 500 3000 45      <- router level
 neighbor 192.0.2.1 remote-as 65002
 neighbor 2001:db8::1 remote-as 65002
 !
 address-family ipv4 unicast
  no neighbor 2001:db8::1 activate
 exit-address-family
 !
 address-family ipv6 unicast
  neighbor 2001:db8::1 activate
 exit-address-family
```

`bgp dampening` is an address-family command in bgpd: a router-level
occurrence is filed under `address-family ipv4 unicast` only. IPv6
unicast therefore never got route-flap damping — silently: the config
loads, `show bgp ipv4 unicast dampening parameters` reports the values,
and IPv6 flaps churn CPU with no damping. Grep of `dampening` in
`pkg/frr` found only the router-level site, confirming no AF block
emitted it.

## Fix

- Compute `dampeningLine` once where the router-level line was written,
  preserving defaults and the #14585 belt exactly (suppress <= reuse
  still warns once and renders nothing, in either family).
- Emit it as the first line of each unicast AF block; extend both AF
  block-open conditions with `dampeningLine != ""`.
- NOT changed: the Junos-side knob (`protocols bgp damping` stays
  family-less — one knob, both families, matching Junos where damping
  applies per address family from the single statement), the strict
  commit gate (#14585/#9012), neighbor classification, multipath,
  redistribute, and every other router-level line. When dampening is
  off or belt-omitted, rendering is byte-identical to before (no AF
  block opens for dampening alone).

## Risk

One-time config churn on first apply after upgrade: the dampening line
moves from router level into both AF blocks, so `frr-reload.py` sees a
delete+two-adds in the managed section (no session reset — dampening
parameters are not session-negotiated). IPv6 unicast gains the damping
the operator already configured; that is the fix, and it can suppress
flapping IPv6 routes that previously always propagated.
