# #13657 — Keep drained workers out of V_min

- **Timestamp**: 2026-10-15
- **Action**: Guarded the post-settle V_min publish with the worker's
  `active_flow_buckets` state. The last-bucket dequeue already vacates the
  worker slot; an unconditional commit-boundary publish could overwrite the
  `NOT_PARTICIPATING` sentinel with frozen `queue_vtime`, making an idle worker
  participate in peer minimum reductions. Retained the publish when a bucket
  is active. Evaluated and adapted the unmerged guard/test from old
  `wt-13657`; it applied cleanly to current master and aligns with the
  dequeue-side vacate contract.
- **Validation**: Regression `vmin_publish_after_settle_keeps_vacated_slot_empty`
  passes with the guard. Reversing only the production guard makes it fail at
  the assertion that the drained slot stays `NOT_PARTICIPATING`. Full V_min
  module: `cargo test --bins afxdp::cos::queue_ops::v_min::tests::` — 36
  passed, 0 failed.
