## Change

`rg-move-soak.sh` passes `MOUSE_TARGET_REF` to `rg_move_soak.py`; `IncusCluster` keeps that target handle. Before traffic, the soak resets only an iperf family whose configured destination belongs to this mouse host: v4 must exactly match `MOUSE_TARGET_V4` or its pinned `TARGET_ALIAS_V4`; v6 must match `MOUSE_TARGET_V6`, with `IPERF_TARGET_V4_V6_SAME_HOST=no` or an unknown value disabling the v6 reset. It counts `ESTABLISHED` sockets, restarts only the affected `mouse-iperf3@<port>.service`, then waits for LISTEN with zero established sockets. Inspection/restart/readiness errors and a 10-second readiness timeout become a named `VoidRun` before generators or RG moves start.

The shared lock serializes test cells, and the check precedes this soak's generators; established sockets on a managed family's port are treated as leftover sessions. In loss, the v6 target is the external split holder, so even with IPv6 enabled the mouse-host 5210 unit is not touched.

The systemd template was not changed. A gate-local stale-socket check plus readiness wait directly addresses stale test clients and the observed restart/listen race, without changing idle behavior for all per-class servers. Accordingly, no `--idle-timeout` template assertion was added.

The mouse-target selftest's Incus stub now returns the array-with-name shape required by the existing `vm-target-guard.sh` `list --format json` decoder; this keeps the requested selftest hermetic and lets it reach the setup assertions.

## Risk

When an established connection is present, restarting that managed port's unit drops its current clients. The soak does this only before its own traffic begins and only for families resolved to the managed mouse target; ambiguous/unmanaged families are left untouched.
