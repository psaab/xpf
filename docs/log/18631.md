## Change

`rg-move-soak.sh` passes `MOUSE_TARGET_REF` to `rg_move_soak.py`; `IncusCluster` keeps that target handle. Before starting traffic, the soak counts `ESTABLISHED` sockets only on ports used by `families()` (v4 always, v6 only when enabled). It restarts only the corresponding `mouse-iperf3@<port>.service` units that have established sockets, then waits for each affected port to be `LISTEN` with zero established sockets. Inspection/restart/readiness errors and a 10-second readiness timeout become a named `VoidRun`, before any traffic generator or RG move starts.

The lock serializes competing test cells, and this check precedes this soak's generators; ESTABLISHED sockets on its active ports are therefore treated as leftover test sessions. An unused port such as 5210 is not touched when IPv6 is disabled (it may be an external v6 target).

The systemd template was not changed. A gate-local stale-socket check plus readiness wait directly addresses stale test clients and the observed restart/listen race, without changing idle behavior for all per-class servers. Accordingly, no `--idle-timeout` template assertion was added.

The mouse-target selftest's Incus stub now returns the array-with-name shape required by the existing `vm-target-guard.sh` `list --format json` decoder; this keeps the requested selftest hermetic and lets it reach the setup assertions.

## Risk

When an established connection is present, restarting that port's unit drops its current clients. The soak does this only before its own traffic begins, and only for ports with established sockets; it does not restart unaffected units.
