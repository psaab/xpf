## Change

`rg-move-soak.sh` passes `MOUSE_TARGET_REF` to `rg_move_soak.py`; `cluster-env.sh` exports the split-target flags and `IncusCluster` keeps the target handle. Before traffic, the soak resets only families mapped to this mouse host: v4 matches `MOUSE_TARGET_V4` or pinned `TARGET_ALIAS_V4`; v6 must match `MOUSE_TARGET_V6` and have positive same-host evidence. An explicit `no` or unknown flag vetoes; with no flag, v6 is managed only when the v4 target also exactly matches the mouse's primary (the tcp/udp default). It counts `ESTABLISHED` sockets, restarts only affected `mouse-iperf3@<port>.service` units, and rechecks every reset port on every readiness poll until all are simultaneously LISTEN with zero established sockets.

The shared lock serializes test cells, and the check precedes this soak's generators; established sockets on a managed family's port are treated as leftover sessions. The exported loss flag is `no`, so a split-host v6 target remains external even if stale configuration makes its address equal `MOUSE_TARGET_V6`; tcp/udp's exact primary-address equality still identifies their same-host targets when the flag is absent.

The systemd template was not changed. A gate-local stale-socket check plus readiness wait directly addresses stale test clients and the observed restart/listen race, without changing idle behavior for all per-class servers. Accordingly, no `--idle-timeout` template assertion was added.

The mouse-target selftest's Incus stub now returns the array-with-name shape required by the existing `vm-target-guard.sh` `list --format json` decoder; this keeps the requested selftest hermetic and lets it reach the setup assertions.

## Risk

An established connection on a managed family is dropped when its server unit restarts. This happens only before this soak's traffic starts and only for families positively mapped to the managed mouse target. If a failover command was issued or a tracked owner is known to differ, the run attempts node0 restoration even if no `MoveRecord` was appended. An unreadable owner gets one 200 ms retry; persistent unknown state is logged but not treated as changed. Restoration rereads ownership, and a VOID result records the restore outcome.
