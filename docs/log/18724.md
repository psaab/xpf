# #18724: keep the lab cluster authentication keys out of the repository

Per-issue log (see `docs/log/README.md`).

- **Timestamp**: 2026-11-01
  - **Action**: The lab confs carry a non-secret token in place of
    `chassis cluster authentication-key`. `cluster-setup.sh`'s raw deploy
    renders the key from `$CLUSTER_AUTH_KEY_FILE`, set per cluster in the env
    file.
    - The rendering is `deploy_render_cluster_conf`, `deploy_ensure_cluster_key`
      and `deploy_cluster_key_problem` in `test/incus/deploy-lib.sh`.
    - The key file is generated if absent and never rewritten when present.
    - The rendered copy is 0600 and removed after the push.
    - A conf carrying the token fails closed when no usable key is available.
    - Nothing prints the key.
  - **Why**: loss used the published placeholder `…-CHANGE-ME`, and tcp and
    udp used random keys that were committed. All three were forgeable by
    anyone who had read the repository. The raw deploy pushed `$CLUSTER_CONF`
    verbatim, so a re-setup would have restored the published key after a
    live rotation.
  - **Keys**: generated with `openssl rand -base64 32` into
    `/var/worktrees/.cache/cluster-keys/{loss,tcp,udp}.key`. Mode 0600, the
    directory 0700, three distinct values, never committed.
  - **Harness**: nothing parses the `authentication-key` line: `test-connectivity`
    reads `peer-address` / `fabric-peer-address`, `test-failover` reads
    `pool-snat`, `ha-assurance-lib` reads the WAN prefix, and
    `test-private-rg.sh` toggles `no-private-rg-election` and redeploys through
    the raw path, which now renders. The env-name leak guard
    (`cluster-env.sh`) lists `CLUSTER_AUTH_KEY_FILE`.
  - **Validation**:
    - `make test-deploy-lib`: 210/0, including 8 new "cluster key" cells.
    - Mutants, each killed by a named cell:
      - no substitution;
      - the key regenerated on every deploy;
      - no placeholder check;
      - `deploy_vm` pushing `$CLUSTER_CONF` raw;
      - the output written without `umask 077`.

      The last mutant first escaped because the caller's umask was already
      077, so the cells now run the render under `umask 022`.
    - The survived-token check is defence in depth. No input reaches it once
      the substitution runs, so no mutant targets it.
    - `make test-cluster-env-lib`: 91/0 (census: 46 guarded names).
    - `make harness-census`: OK.
    - `go test ./pkg/config -run '6611|16456|Shipped|Placeholder'`: ok. The
      golden harness fails the same 33 cases on pristine master
      `dc528b5611`, and it records the key as `<redacted>`, so the token
      changes nothing there.
  - **Live rotation**: not part of this commit. Each cluster is rotated to
    its key file through the #6630 rolling procedure in its own slot, and
    the evidence is appended here. Merge this after the rotations, or a raw
    deploy from master in between would push the old key back.

  - **Correction**: "a raw deploy from master in between would push the old

    - The default deb deploy pushes no config, so it keeps the rotated key.
    - A raw deploy (`XPF_DEPLOY_FAST=1`, or `make test-private-rg`, which
      forces it) from a branch without this change pushes the old committed
      key.
    - `deploy all` is rolling. The restarted secondary rejects the primary's
      heartbeats and, after its 30 s startup grace, takes the redundancy
      groups, so both nodes can be primary until the primary's daemon
      stops. `test/incus/README.md` now states the window and its parts.
  - **Folds**:
    - `deploy_cluster_key_mode_problem` refuses a key file or key directory
      that has any group or other permission bit, and names the `chmod` that
      fixes it. Generating a key now fails when the directory cannot be set
      to 0700, where it used to ignore the error.
    - `deploy_push_cluster_conf` renders and pushes in a subshell. Its EXIT
      trap removes the temp dir, and HUP, INT and TERM exit through that
      trap, so an interrupted push does not leave the rendered copy (which
      holds the key) in `$TMPDIR`. `deploy_vm` calls it.
    - The lab-conf cell walks every `docs/ha-cluster*.conf` and no longer
      skips a conf without the token. `ha-cluster.conf` and
      `ha-cluster-loss.conf` are exempt by name and may carry only a

      those legacy regression clusters during their next rolling raw deploy.
    - Env-file comments now say "key file" where they meant it.
    - `test/incus/README.md` adds a known-state note. The config DB is
      authoritative, and `/etc/xpf/xpf.conf` on the loss and udp nodes is
      mode 0664 and holds the retired key. The daemon re-imports that file
      only when there is no active DB and no rollback slot survives (#10297),
      and in practice that happens only after a raw deploy, which pushes a
      fresh render. No product change is proposed. Writing the committed
      config back to the text file would put live secrets in a second file,

- **Timestamp**: 2026-11-01 09:30 PST
  - **Action**: Review folds from seat AG at `8f8e39a509`.
  - **A deploy never mints a key.** A missing key file was silently
    regenerated on deploy. If `cluster-keys/` disappeared (a cache cleanup,
    or another host), the next deploy to a live cluster would split the
    pair. Now:
    - `deploy_ensure_cluster_key` refuses a missing file, and its message
      points at restoring it or at the rotation.
    - Generation needs an explicit opt-in: `cluster-setup.sh create` passes
      `generate` after `create_vm` (which dies on an existing VM), or the
      operator sets `XPF_CLUSTER_KEY_GENERATE=1`.
    - The campaign skill's never-prune list now names `cluster-keys/`.
  - **Symlinks**: a symlink at the key path is refused, live or dangling.
    Before this, a dangling one counted as absent.
  - **Byte-exact rendering**:
    - A conf without the token is copied with `install -m 0600`.
    - A tokenised conf is substituted in python3, which reads the key from
      the file, so the key never reaches an argv or the environment.
    - Final newlines and NUL bytes survive; the old `$(<)` / `printf`
      round trip normalised them.
    - The dead `${key%$'\n'}` strips are gone.
  - **The explicit HUP/INT/TERM traps in `deploy_push_cluster_conf` are
    removed.** bash runs the EXIT trap when those signals kill it (measured
    on bash 5.3), so the three trap-removal mutants were equivalent and
    survived. The signal cell, which sends all three, is the guard.
  - **README**: the skew window. The wait loop exits as soon as the
    restarted node answers, which under a key split can be while it already
    reports itself primary, so 65 s bounds the window in neither direction.
    The two nodes reject each other. After the 30 s startup grace the
    restarted node takes every RG while the old primary still serves: two
    primaries and duplicate VIPs.
  - **Validation**: `make test-deploy-lib` 219/0.
    - New cells: a missing key file refused on deploy with nothing
      generated; symlinks refused; a key dir that cannot be set to 0700
      refuses generation; `create` mints after `create_vm`; byte-exact
      rendering (no final newline, two trailing newlines, an embedded NUL,
      and a tokenised conf without a final newline); each userspace env
      names its own `<cluster>.key`.
    - The substitution cell now compares with `cmp`.
    - Mutants killed: generation without opt-in, symlink allowed, the
      no-token copy via `$(<)`, the token path normalising its final
      newline, `create` without `generate`, no mode check, no dir check,
      no EXIT trap, and the chmod error ignored.
  - The conf and env-file comments that said the key file is "generated if
    absent" now say only `create` mints it.
