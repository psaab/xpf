# #12183 — resolve mixed-static recursive backup routes

- **Issue**: #12183 — mixed direct/recursive static ECMP rows retain a bare recursive next hop, leaving the live backup without an egress.
- **Branch**: `fix/12183-mixed-static`
- **Worktree**: `/var/worktrees/12183-mixed-static`
- **Base**: `1c384b9a47ff7d6e567fa50632faa75c3995ae87`

## Why

The Go snapshot preserves a mixed static row containing a direct member and a recursive member. The Rust userspace FIB previously treated the recursive gateway as connected-only, leaving its next hop bare with ifindex zero. As a result, the live terminal route behind that second static was not available as a usable ECMP member.

## What

- Build a family- and canonical-table-scoped route index before populating the FIB, so recursive static resolution is independent of snapshot ordering.
- Resolve bare recursive gateways through the longest matching in-table route to a terminal gateway and egress, with cycle/depth guards. Discard, next-table, cross-table, self-recursive, and unresolved cases do not fabricate an egress.
- Preserve the mixed route row and direct member, while baking the terminal gateway into the recursive member for neighbor lookup and transmission. Keep the existing connected-only resolver API behavior for its callers.
- Add Go regression coverage for mixed-row preservation, terminal kernel-path preference, and all-bare unresolved fallback, plus Rust v4/v6 FIB coverage including route-order permutations, a connected direct member without a neighbor, and recursion controls. Retain the #11317 pin.

## Risk / remaining acceptance

Resolution is constrained to same-family routes in the same canonical table and stops on cycles or the bounded recursion depth. Unresolved and non-forwarding routes retain the existing fallback behavior. No live cluster or hardware was mutated.
