# #10152: keep the MTU digest stability fixture parseable

## Root cause

`TestCommittedDigestStableAcrossMTUSync9841` was red before reaching its digest
assertion because `promote9175` passed the flat leaf
`system host-name mtu-test\n` to `Store.SyncApply`. The #9841 test was added in
`6df4d4790` (2026-09-14). Later, parser change `fcfdafcb5` (#9899, F-099)
changed a missing semicolon at EOF from tolerated implicit-leaf recovery to a
parse error. `SyncApply` therefore correctly returned
`expected ';', got EOF` at line 2. This is a stale test fixture, not a product
digest-instability bug: the failure occurs during promotion, before the MTU
warning projection or digest assertion executes.

## Fix

The fixture now uses the same flat leaf with its required terminator:
`system host-name mtu-test;\n`. No production code or test assertion was
changed; the test still proves that response-only MTU warning projection leaves
the active config's digest unchanged.
