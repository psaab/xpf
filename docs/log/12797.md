# Issue #12797 — detach all-kept rollback candidates

## Root cause

`reauthorizePolicyCandidates` returned its input capture directly when every retained candidate remained denied by the rollback target. The capture is also `rollbackSource`; a later `pruneCapturedPolicyRows` compacts `policy`, `v4`, and `v6` slices in place after partial conditional deletes. This mutated the rollback source's backing arrays and could leave stale tail rows for same-target retries.

## What changed

- Return a detached capture for all-kept outcomes, including fail-closed zone-ID collisions and a nil restored config; `clonePolicyInvalidationCapture` clones each candidate slice and provenance map.
- Added a regression test that reauthorizes all candidates as kept, runs the real partial-delete pruning helper, and verifies the original capture retains every row unchanged.

## Validation

- `go test ./pkg/daemon -count=1` — passed.
- `go vet ./pkg/daemon` — passed; `gofmt -d` on both changed Go files produced no output.

## Risk

The change copies candidate slices only on all-kept returns; permitted-result behavior and caller policy remain unchanged.
