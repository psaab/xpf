# #15179 — stamp deterministic identity on synced-first NAPT64 BIB (C06-02)

- **Timestamp**: 2026-10-19
- **Issue**: C06-02 — when the standby imports a deterministic NAPT64
  session and no BIB exists yet, `reserve_flow_maybe_persistent` created an
  endpoint-independent BIB tagged `deterministic: true` but with
  `deterministic_identity: None`. The local deterministic allocator joins
  only leases whose identity matches the current params, so after failover
  every same-socket flow to a new remote was dropped with
  `AllocatorExhausted` while any synced flow on that socket was active and
  for 300 s after. When the BIB finally expired, the socket got a
  DIFFERENT port.
- **Base**: `origin/master` `64947247d1` at implementation (rebased from
  `b689632817`).

## Mechanism (verified at base)

- `nat/source/nat64_ports.rs:147-149` built
  `persistent = Some((flow.persistent_source_key(AnyRemoteHost), 300s))`
  and passed only `deterministic: bool` into the allocator.
- `nat/allocator.rs` minted the lease with
  `deterministic, deterministic_identity: None, imported: true`.
- `allocate_deterministic_v6_at` joins an existing BIB only when
  `lease.deterministic_identity == Some(V6(params))` (both the full-block
  and claimed-port branches); otherwise it frees the claimed port and
  returns `AllocatorExhausted`.
- The only non-test stamps of `Some(V6(params))` were the local mint in
  `allocate_deterministic_v6_at` and the idle-lease export/import path
  (`idle_lease_sync_8121.rs`, coordinator `idle_lease_sync_8121.rs:111`) —
  never the synced-session reserve.

## Fix

- `PortAllocator::reserve_flow_maybe_persistent_with_identity` (new
  `pub(super)` entry) threads an optional
  `DeterministicPortedIdentity` into the minted lease; the existing
  `reserve_flow_maybe_persistent` delegates with `None`, so every other
  caller (source-NAT synced reserve in `synced.rs`, reseed in
  `reseed_retained_from`) is byte-identical. The identity is stamped only
  when `deterministic` is true.
- `reserve_nat64_pool_port{,_capture_and_replace}` now take
  `deterministic: Option<DeterministicV6>` instead of `bool` and map it to
  `Some(V6(params))`. Production caller
  `reserve_synced_nat64_port_unless_peer_owns` (`nat64.rs`) passes
  `prefix.deterministic_v6` directly; it already validated the tuple with
  `deterministic_v6_tuple_matches` before reserving, so a mismatched
  identity cannot be stamped. Round-robin prefixes pass `None` and mint
  `deterministic: false, identity: None` exactly as before.
- Corrected the stale comment claiming production constructs `persistent`
  solely in `reserve_synced_on_first_pool_owner` — the NAT64 synced
  reserve is the second constructor.

NOT changed: the deterministic allocator's join predicate (it stays
strict — an identity-None or mismatched lease still fails closed with
`AllocatorExhausted` rather than being adopted, because adopting would
trust a tuple that was never validated against the current params);
source-NAT (v4) synced reserves, which have no BIB-join consumer;
idle-lease import, which already carried the identity.

`deterministic_napt64_synced_first_bib_joins_local_15179` in
`nat/tests_deterministic_bib_14091.rs`:

- Synced-first: reserve a deterministic tuple (port 1030, inside the

- Control: local-first on a fresh allocator still shares one BIB across

## RED -> GREEN proof

- **RED** (base prod code + test adapted to the old `bool` signature):
  `deterministic_napt64_synced_first_bib_joins_local_15179` FAILED —
  `assertion left == right failed: synced-first lease must carry the
  prefix deterministic identity, left: None, right: Some(V6(...))`.
  (The identity assertion fires first; with it removed the local join
  would hit the `AllocatorExhausted` arm — same root cause.)
- **GREEN** (this head): `cargo test deterministic_napt64` — 9 passed
  (the new cell plus all `14091`/`14670` neighbours and the two
  `tests_pool` deterministic cells). `cargo test nat64_` — 329 passed,
  covering the round-robin reserve controls (`nat64_13946_*`,
  `nat64_4512_*`, `nat64_6892_*`, `nat64_6876_*`) whose callers were
  migrated from `false` to `None`.

## Risk

Bounded to the NAT64 deterministic synced reserve: a standby that
imports a mode-2 session before any local BIB now records the identity
the active node's config already implies (validated by
`deterministic_v6_tuple_matches` at the same call site). No wire,
config, or round-robin behaviour change. Residual: none known; the
adopt-on-None alternative from the issue was deliberately not taken
(see NOT changed).
