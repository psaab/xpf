# #13120 — fail closed on VRF miss-terminator installation failure

- **Timestamp**: 2026-10-14
- **Source finding**: Deep-review D10-02, `pkg/routing/vrf.go:72-104`; issue #13120.

## Red before

On pristine `origin/master` `55ab81ef0`, added `pkg/routing/vrf_create_reconcile_failclosed_13120_test.go` and ran:

`go test ./pkg/routing/ -run 'TestVRF(CreateTerminatorFailureFailsClosed13120|ReconcileTerminatorFailureFailsClosed13120|CreateExistingLinkChecks13120)'`

The test failed because `Create` and `Reconcile` materialized VRFs after `setVRFMissTerminator` failed, and `Create` accepted foreign or wrong-table existing links, swallowed `LinkSetUp` errors, failed to adopt valid existing VRFs, and treated transient lookup errors as absence.

## Change

`Create` and `Reconcile` now return immediately when the VRF miss terminator cannot be installed; they do not alter VRF links or tracked ownership without the barrier. `createLocked` now distinguishes absent links from transient lookup errors, rejects foreign links, recreates wrong-table VRFs to match reconciliation behavior, propagates setup errors, and adopts existing VRFs into the tracked set. Existing #9819 failure coverage now asserts no VRF is created. New regression tests cover both public lifecycle paths and the existing-link cases.

## Validation

- **After fix**: `go test ./pkg/routing/...` passed.
- The regression test above failed on pristine master before the fix.

## Risk

A failed barrier install intentionally leaves desired VRF changes unapplied for that call; the returned error permits the apply pipeline to retry. Existing links are left untouched on terminator failure. No live-kernel mutation was performed.
