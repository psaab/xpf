# #17227 — parseVRRPGroups single reader: packed/braced/flat VRRP spellings can no longer diverge on track-cost

- **Issue**: #17227 (R4-Q23-02)
- **Timestamp**: 2026-10-27
- **STEP-0 (defect live on origin/master f06afe753d)**: `parseVRRPGroups`
  (`pkg/config/compiler_interfaces.go`) still carried two independent
  readers — a Keys-packed switch over `Keys[2:]` and a child-node
  switch — with `grep -c 'case "track-priority-cost"'` == 2. The Keys
  copy diverged twice: `track-priority-cost` overwrote via
  `vg.TrackPriorityDelta, _ = parseTrackCost(...)` (swallow, no
  keep-prior-value, #4573 missed this copy), and a packed nested
  `priority-cost` only wrote `if vg.TrackPriorityDelta == 0`, so a
  later legacy sibling won by source order — while the child arm
  applies the nested cost last regardless of order (#1814).
- **Action**: normalize first, read once. New `vrrpGroupStatements(inst)`
  splits the packed tail `Keys[skip:]` into synthetic child nodes
  (arity-aware via `vrrpGroupStatementArity` + `vrrpTrackPending`, so a
  value token spelling a keyword cannot re-arm the splitter, #6665;
  multi-value `virtual-address` absorbs to the next keyword, #1813;
  short `track interface <if>` releases the next keyword instead of
  swallowing it) and appends `expandFlatRun(inst.Children, …)` for
  flat-set chains. The 120-line Keys arm is deleted; the single
  remaining switch keeps the #1814 post-loop precedence (sibling
  applied, nested last) and the #4573 clean-parse-only rule for every
  property. Track statements are first-wins within one instance
  (packed duplicates no longer last-win behind the pre-walk prune),
  a packed nested cost on `track-interface <if> priority-cost <n>`
  Keys is now read (it was silently dropped pre-fix), and empty
  packed values for `virtual-link-local-address` / `authentication-*`
  stay unset instead of overwriting with "".
