# #9898 — configstore/journal/fsatomic: eight store-boundary properties moved to their boundaries

- **Timestamp**: 2026-09-15
- **Action**: enforce each cohort property at the boundary that owns it (key-set gate, unencrypted header binding, Log byte bound, perm-repair degraded state, bounded full-scan, atomic key publish, durable deletes, write-count assertion); one already-fixed half documented, rest implemented.
- **File(s)**: `pkg/configstore/db.go`, `pkg/configstore/envelope.go`, `pkg/configstore/crypto.go`, `pkg/configstore/store_persist.go`, `pkg/configstore/journal/journal.go`, `pkg/fsatomic/fsatomic.go`, `store_boundary_9898_test.go`, `journal_boundary_9898_test.go`, `fsatomic_boundary_9898_test.go`, `docs/log/9898.md`.

## Defect

Eight sites where a boundary property was enforced one layer up or not at all; each fails accept/lose/expose rather than refusing:

- F-001 `readTreeMeta` (`db.go`): `requireJSONObject` tests the leading byte only and plain `json.Unmarshal` into single-field `ConfigTree` drops unknown keys — `{"bogus":{}}` boots as empty policy.
- F-035 envelope (`db.go`): `aad` set only when encrypted, so on the DEFAULT unencrypted path a one-byte `committed=` flip silently changes the boot class.
- F-110 `Journal.Log` (`journal.go`): marshals+appends with no size bound; only cap is the `Store.journalLog` 4 KiB Detail belt — direct callers get nil error while the tail scanner later drops the poisoned line.
- F-113 `migratePermsLocked` (`journal.go`): `migrated=true` unconditional; chmod/lstat failures warn-only; no retry, no health signal; rotation's re-assert (`maybeRotateLocked`) equally silent.
- F-114 `readAllLocked` (`journal.go`): `io.ReadAll` per segment, no byte cap, plus `bytes.Split` descriptor amplification (~384 MiB for 16 MiB of blank lines). O_NOFOLLOW half ALREADY FIXED on base by #9897 (`openSegmentNoFollow`); only the cap half remained.
- F-111 `readOrCreateMasterKey` (`crypto.go`): check-then-act across processes (read miss → generate → temp+rename) — racing creators seal with divergent keys; loser's ciphertext permanently undecryptable. Base additionally misclassified a key dir-sync failure as `*PostRenameSyncError`, which Commit reads as "new active visible, converge" though the active write never ran.
- F-112 `DeleteCandidate`/`DeleteRollback` (`db.go`): bare `os.Remove`, no dir sync, no seams — a power cut replays the deleted slot; `DeleteConfirm` shows the durable shape. (Zero production callers; kept for the seam inconsistency per the issue.)
- F-115 `writeFile` (`fsatomic.go`): write count discarded (`if _, err :=`), four error paths use bare `tmp.Close` vs the `closeTemp` seam. (`os.File.Write` already errors short, so the count is defense-in-depth, not a reachable truncation.)

STEP-0: every member reproduced RED on base `138d37396` before implementing (reject/tamper/race/seam/oversized/short-write cells fail; accept/legacy/ordinary guards pass), except F-113 (structural — no retry/signal exists; revert-checked instead) and F-114's O_NOFOLLOW half (already fixed by #9897, documented with present code).

## Change

- F-001: `requireKnownTopLevelKeys` on the final plaintext body (post-strip, post-decrypt): decode to a key map, reject any key not case-folding to `Children`, else fall through to the typed decode (which keeps nested leniency and owns malformed-JSON errors). `{}` deliberately accepted (#5474); top-level-only by design (Node evolves additively; a future new ROOT field needs its own compat decision).
- F-035: writer stamps additive `body-sha256=<64 hex>` = SHA-256 over (header line with hash slot zeroed + body) on UNENCRYPTED envelopes only (encrypted headers already key-bound via AAD; stamping those would break the seal, which covers the final stored header); reader verifies when present over the stored bytes, reads on when absent (no flag day, downgrades safe). Tamper-EVIDENCE, not proof: unkeyed, so a field rewrite/recompute/strip bypasses like any wholesale rewrite — naive edits and corruption fail closed.
- F-110: `Log` refuses a marshaled entry past `maxJournalEntryBytes = 64 KiB` before `appendLocked` (appends and rotates nothing); ~15x typical / ~2.6x worst-escaping headroom over the belted path, 256x under the scanner cap.
- F-113: `chmodOwnerOnly` returns errors (skips stay nil); `migratePermsLocked` sets `migrated` only on full success (retry every use, each retry re-warns); failures latch `permsDegraded`, cleared only by a clean pass; rotation re-assert failure latches + re-arms; `Journal.PermRepairDegraded()` + `Store.JournalPermsDegraded()` poll-through. Parent-review fold: the latch reaches operators as a NON-FATAL `/health` field (`journal_perms_degraded`, stays 200) + `xpf_config_journal_perms_degraded` gauge + daemon wiring, mirroring `RollbackHistoryDegraded` exactly (non-503 ≠ no visibility). Appends continue while degraded. Lstat→chmod TOCTOU noted as pre-existing residual.
- F-114: per-segment `maxReadAllSegmentBytes = 16 MiB` (Stat fast-path + `LimitReader(cap+1)` belt), nil history + loud error on overflow including later-segment overflow; incremental line iteration replaces `bytes.Split` (kills descriptor amplification; per-valid-entry output remains inherent). Aggregate `(maxSegments+1)×cap`, scoped in the comment.
- F-111: atomic publish via `link(2)` — complete temp (0600, synced, close-checked) linked into place; exactly one winner, losers adopt the complete file. Parent-review fold: EVERY acquisition returns a DURABLE key — the fast path adopt-syncs (file fsync + dir sync) instead of returning directly, because ciphertext is rename-published before any dir sync covers the key entry (selective-loss strand without the barrier; the earlier same-dir-coverage argument reversed the ordering). EIO-leave heals on next acquisition (re-sync, no double-EIO residual). Winner dir-sync EIO leaves the file ("first key wins forever", no remove race) with a PLAIN error — never `*PostRenameSyncError` (fixes the base Commit-converge misclassification). ENOENT (concurrent-NewDB sweep) recreates bounded (3x). Seams: `masterKeyLink` + `syncMasterKeyFile` + reused `rbSyncDir`. Residuals: mixed-version racers (upgrade window), dangling-symlink fail-closed (was heal-by-replace). Subprocess test strengthened (ready/go barrier + Link delay + direct `&DB{}`, no per-child NewDB); deterministic parked-winner interleaving cell on the encrypted write path.
- F-112: both deletes through `rbRemove`/`rbSyncDir` with the #5835 absent-fallthrough (absent retry still syncs; only a successful sync returns nil).
- F-115: `n == len(data)` assertion (short count fails pre-rename, target untouched, temp swept) + all closes through `closeTemp`.
- Reviews: MEDIUM tier — brief posted to the issue; Codex hostile (3 KEEP / 1 protocol-KILL on F-111 with sweep + durability executables / 4 NARROW, all adopted: F-035 unencrypted-only + field spec + discriminator residual, F-113 rotation wiring + exposure, F-114 incremental iteration + valid fixture + nil-history, F-115 narrowed claim + faithful fixture + empty/target cases, F-112 sequence tests, F-001 encrypted leg, F-110 boundary/escaping tests) + AGY second (8 APPROVE); F-111 protocol reworked to link-with-LEAVE/ENOENT-retry per Codex's executables (both reviewers preferred link over flock), adjudication posted.
