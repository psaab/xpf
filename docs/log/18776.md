# #18776: keep gauge maxima independent of monotonic counters

- **Timestamp**: 2026-11-02
  - **Action**: Added a gauge-specific sampled maximum reducer and routed the
    report-only `Pending TX local` and `Outstanding TX` rows through it. The
    existing monotonic reducer remains in use for counters and interface
    counters.
  - **Why**: `Pending TX local` is a queue depth and `Outstanding TX` is a
    transient in-flight TX gauge; both can decrease normally. A decrease must
    not turn report-only telemetry into a VOID that voids the whole failover
    run. Counter rewinds remain evidence of helper restarts and still VOID
    their rows.
  - **Cells**: The assurance selftest covers both falling gauge rows
    (14→6, maximum 14, no VOID), all-zero samples with a higher phase-pre
    baseline (sample maximum 0), and a counter rewind (still VOID).
  - **Source trace**: `pending_tx_local` is a queue-depth gauge
    (`worker/loop_body/debug_report.rs` reads its queue length). However,
    `BindingLiveState.debug_pending_tx_local` has no `.store()` writer in the
    current `userspace-dp/src` tree; that publication gap is not changed here.
  - **Validation**: Before the fix, a window with `Outstanding TX` samples
    `14, 6` returned status 2 with `counter rewound from 14 to 6 at
    sample-02`. `make test-ha-assurance-lib` passes: falling gauges report 14,
    all-zero samples report 0 despite a higher baseline, and counter rewind
    still VOIDs. `bash -n` on all three changed shell files and
    `git diff --check` pass.
  - **File(s)**: `test/incus/ha-assurance-lib.sh`,
    `test/incus/test-failover.sh`, `test/incus/ha-assurance-selftest.sh`,
    `docs/log/18776.md`
