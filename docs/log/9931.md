- **Timestamp**: 2026-09-17 10:59 UTC
  - **Action**: Implemented version discovery and private snapshots for the three host-supplied static libraries.
    - `build.rs` queries `libelf`, `zlib` and `libzstd` with `pkg-config --modversion`, `--variable=libdir`, `--variable=includedir` and `--libs --static`, then selects the static archive from the pkg-config library directories and compares any discovered header version to pkg-config's version.
    - If a static-only installation has no `.pc` file, the script falls back to `_ELFUTILS_VERSION`, zlib's numeric version defines or zstd's numeric version defines, plus `C_INCLUDE_PATH`/`CPATH` and `LIBRARY_PATH`/standard library directories. It requires the selected header and archive to canonicalize to the same installation prefix; a mismatched prefix fails before the C compile with both paths and prefixes named.
    - The validated lower bounds are libelf 0.195, zlib 1.3 and zstd 1.5.7. There is no upper bound for these stable-ABI transitive libraries; `debian/control` declares `libelf-dev (>= 0.195)`, `zlib1g-dev (>= 1:1.3)` and `libzstd-dev (>= 1.5.7)`.
    - Each selected archive is copied into the build's private OUT_DIR under a unique link name (`libxpfelf.a`, `libxpfz.a`, `libxpfzstd.a`). The build emits only those names, so an ordinary system, SDK, dependency or `-L` path cannot satisfy the snapshot names.
    - Before linking, the guard requires the selected source archive to be the first candidate in the ordered linker search set. A candidate from an earlier `LIBRARY_PATH`, `RUSTFLAGS`, target-RUSTFLAGS or libbpf-sys path fails the build as an unexpected shadow.
    - After each snapshot write, the same `.pc`/header version source is re-read, its bound is checked again, and the source archive is re-read. A version or archive change during the copy fails the build instead of pairing stale metadata with new bytes.
  - **File(s)**: `userspace-dp/build.rs`, `userspace-dp/build_support/libversions.rs`, `debian/control`
