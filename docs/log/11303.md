# Issue 11303 — match security-policy reject protocol replies to Junos

## Why

The policy-reject reply wrapper reused the filter-reject default for every non-TCP protocol. That emitted admin-prohibited for UDP and even answered ICMP echo, while Junos policy `then reject` uses UDP port-unreachable and silently drops other non-TCP protocols. Firewall-filter `then reject` has distinct configured-message semantics and must retain its default admin-prohibited response.

## What changed

- Limited policy rejects to TCP RST and UDP ICMP/ICMPv6 port-unreachable; unsupported protocols now fail closed before reply synthesis.
- Kept firewall-filter rejects on their configured message type, including default admin-prohibited.
- Added IPv4 and IPv6 UDP code checks, silent-drop coverage for ICMP echo/GRE/ESP, and a filter-default parity assertion. Updated policy reply comments and `userspace-dp/src/filter/README.md`.
