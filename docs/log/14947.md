# #14947 — NAT address-name poison for DNAT and SNAT `off` exemptions

- **Base**: `b8f1ff7ac9` (PR base)

## Change

Destination-NAT previously retained per-name filtering (#12627): a poisoned
address-name closure published its resolvable subset, and a poisoned `off`
exemption could exempt that subset while the rest fell through. SNAT already
poisoned poisoned closures whole-rule, but a present-but-empty (unready)
dynamic feed left an `off` exemption matching unconditionally in its
remaining scope.

- `pkg/dataplane/userspace/nat.go`: DNAT source/destination name helpers now
  report poison (`appendNAT{Source,Destination}AddressNamePoisoned`). A
  poisoned closure poisons, and an empty resolution from a declared
  present-but-empty non-drop feed poisons via `natAddressNameEmptyPoisons`.
  A fail-mode-drop present-empty feed stays intentional match-none (#12965).
- `nat_destination.go`: any poisoned DNAT name marks every emitted entry
  `LenientMatchDropped`. Entries are still emitted (keyed by destination)
  so the Rust table can claim and drop the flow.
- `protocol_nat.go` / Rust `protocol/nat.rs`: `DestinationNATRuleSnapshot`
  gains `lenient_match_dropped`; protocol version 50 -> 51 (Go
  `ProtocolVersion`, Rust `CONFIG_SNAPSHOT_PROTOCOL_VERSION`, #8892 golden).
- Rust `nat/destination.rs`: `DnatEntry.lenient_match_dropped`; poison wins
  over `off` in `to_outcome`. New tri-state `DnatLookup` /
  `lookup_result_with_counter_scoped` distinguishes `Poisoned` (drop) from
  `NoMatch` (healthy `off` / no match, forward untranslated). The production
  pre-routing caller in `poll_descriptor/mod.rs` drops on `Poisoned`.
  Poisoned entries register no local VIP address.
- `nat_source.go`: a SNAT `off` rule referencing a present-but-empty
  non-drop feed is marked `LenientMatchDropped` (the existing Rust SNAT
  drop-before-`off` path then drops claimed flows). Translate rules are
  unchanged (already match-none via the fallback token).

RED/GREEN: the new Go tests fail on master (no `LenientMatchDropped` field /
no marking) and the Rust tests fail without the marker handling (poisoned
`off` would exempt / translate); healthy, fail-mode-drop, and ready-feed
controls stay green.

## Residual / risk

- Cross-tier DNAT precedence is unchanged: a more-specific healthy translate
  in an earlier tier still beats a broader poisoned entry (same as healthy
  `off` vs translate precedence today).
- Other DNAT lookup consumers (IPsec locality probe, fragment association,
  policy revalidation) still use the Option surface, where `Poisoned` reads
  as no-translation — conservative (no translation is applied); only the
  production pre-routing path drops.
- Established sessions are unaffected; poison applies at new-flow lookup.
