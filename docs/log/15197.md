# #15197 — `display inheritance` silently fell back to raw config on `${node}` HA configs (A03-01)

- **Timestamp**: 2026-10-19
- **Issue**: A03-01 — `show configuration | display inheritance` silently
  fell back to the raw config on every `${node}` HA config, and path views
  omitted node-group-inherited leaves. `pkg/config/ast_format.go`
  `FormatInheritance`/`FormatPathInheritance` called `ExpandGroupsTagged()`
  with no vars, so `apply-groups "${node}"` failed with
  `undefined group "${node}"` and the error arm returned `t.Format()` /
  `t.FormatPath(path)` — the raw, unexpanded tree — with no diagnostic.
  The raw `groups`/`apply-groups` were still printed, but inherited leaves
  vanished. `pkg/configstore/store_format.go` passed no node id either,
  even though the Store holds `s.nodeID` (from `/etc/xpf/node-id` via
  `SetNodeID`).

## Fix

- `pkg/config`: new `expandForInheritance(nodeID)` prepares the display
  clone (strip inactive → normalize compact stanzas, as before) and then
  expands exactly once: `ExpandGroupsWithVarsTagged({node: node<N>})` for
  `nodeID >= 0`, `ExpandGroupsNodeFallback15031(true)` (the #15031 generic
  node0 fallback) for the standalone view. New error-returning entries
  `FormatInheritanceForNode(nodeID)` and
  `FormatPathInheritanceForNode(path, nodeID)` return the expansion error
  instead of hiding it. The legacy `FormatInheritance()` /
  `FormatPathInheritance(path)` keep their signatures for secret-redaction
  test callers and now render the standalone view, surfacing a failure as
  an explicit `% display inheritance failed: …` line rather than the raw
  tree.
- `pkg/configstore`: `ShowCandidateInheritance`,
  `ShowCandidatePathInheritance`, `ShowActiveInheritance`,
  `ShowActivePathInheritance`, `ShowActiveInheritanceRedacted`, and
  `ShowCandidateInheritanceRedacted` now thread `s.nodeID` into the
  node-aware formatters and return `(string, error)`.
- Callers updated: CLI `show configuration | display inheritance`
  (`pkg/cli/cli_show.go`) and config-mode `show | display inheritance`
  (`pkg/cli/cli_config.go`) print `% display inheritance failed: …` on
  error; gRPC `ShowConfig` (`pkg/grpcapi/server_config.go`) returns the
  error. REST has no inheritance render path (verified: no matches in
  `pkg/api`).

NOT changed: group-expansion semantics, compilation, any other display
format, and the redaction split (cleartext Show* still back HA sync / DR
archive / on-box CLI; redacted variants still mask via `RedactedClone`).

## Regression

- `pkg/config/inheritance_node_15197_test.go` — node0/node1 whole-tree and
  path views show `## 'host-name' was inherited from group 'node<N>'` with
  only that node's leaf; standalone view falls back to node0; undefined
  group errors (whole + path); plain-group control byte-equal to the
  legacy entry; display does not mutate the caller's tree.
- `pkg/configstore/inheritance_node_15197_test.go` — a Store with
  `SetNodeID(1)` renders candidate/path/redacted views from group `node1`
  and the active view from `node0`; undefined group errors.

## RED -> GREEN proof

- **RED (current `origin/master` behaviour)**: probe on base showed
  `FormatInheritance` on the `${node}` fixture produced no
  `inherited from group 'node1'` annotation and the path view omitted
  `host-name fw1`; the new tests fail to compile on base because
  `FormatInheritanceForNode`/`FormatPathInheritanceForNode` and the
  `(string, error)` store signatures do not exist.
- **GREEN (this head)**: see Validation in the PR/commit body.

## Risk

Operator-visible output delta only: `${node}` configs now show the
inherited leaves the selected node actually applies (previously hidden),
and a broken `apply-groups` now fails the display with an explicit error
instead of masquerading as a plain config. Standalone display of a
`${node}` config resolves to node0, matching the generic compile (#15031);
a cluster node's display resolves to its own node. No config, wire, or
enforcement change.
