# #16108 — Packed-tail credential gate accepts misplaced `authentication-key` (OSPF `passive` fixture)

## Verify at master (0976d8be74)

Reproduced: `TestPackedTailCredentialStrictReject14412/ospf_interface_misplaced_after_passive`
and `TestPackedTailCredentialWarns10707_14412/ospf_interface_misplaced_after_passive`
fail on clean `origin/master`; `SchemaValidate` accepts
`interface ge-0/0/0.0 passive authentication-key SECRET;` and `CompileConfig`
emits no #10707 warning. The other four packed fixtures pass.

## Root cause

`authentication-key` under an OSPF interface is not merely misplaced in the
packed spelling — it is a modelled refusal stub (`unmodeledOSPFAuthKeyLeaf`,
#14402: `ValueEnumOf` with empty examples + unconditional `rejectOSPFAuthKey`
validator), because OSPF has no direct key leaf. But
`packedTailCredential14412` exempted any token whose exact-case form resolves
as a child of the descendent schema. Packed tails never reach the typed-leaf
validator (the interface node does not opt into `packedTail`), and the
compiler's `packedBodyChildren` declines the tail once `passive` (a childless
leaf) precedes it — so the packed refusal-stub is dropped unauthenticated,
while its braced twin is rejected. `simple-password` after `passive` already
rejected because no such child exists at interface level.

Two sibling control cells in the same file were also unsatisfiable on master
(pre-existing, not this defect):
- OSPF braced child: exact-case children resolve, so #10707 never warns; the
  intended gate is the #14402 `SchemaValidate` rejection.
- IS-IS case-variant child: strict compile rejects via #14399
  (`authentication-type` without a case-exact key); lenient compile warns.

## Fold (review): value positions are not heads

Review found the first fix scanned every tail token against the node's own
grammar, so a credential-spelled VALUE was rejected: the bare MD5 key in
`interface ge-0/0/0.0 authentication md5 1 key authentication-key` compiled
to `AuthKey="authentication-key"` yet `SchemaValidate` rejected it.
`packedTailCredential14412` now walks the tail through the grammar's open
levels (deepest-declaring level owns each head, consuming its 1+args span —
the `packedBodyChildren` model), so only statement-head positions are
judged: a head is dropped iff it resolves at no open level (misplaced /
case-variant) or resolves only to a refusal stub. Regression:
`TestPackedTailCredentialValuePosition16108` asserts strict acceptance, no
#10707 warning, and verbatim compiled `AuthKey` for both the MD5 `key` and
`simple-password` value positions; the `passive authentication-key SECRET`
head rejection is retained.

## Fix

- `pkg/config/packed_tail_credential_14412.go`: new
  `packedTailCredentialDropped14412` — a resolving credential child counts as
  dropped when it is a refusal stub (typed leaf, empty enum set, validator
  rejects a sentinel value). `packedTailCredential14412` now reports it on
  both channels (strict reject in `schema_walk.go`, #10707 warning in
  `compiler_openworld_10707.go` — both already call this predicate).
  Non-stub resolving credentials (IS-IS/RIP/BGP real keys) stay exempt.
- `pkg/config/schema_walk_packed_tail_credential_dr13h5_test.go`:
  `TestPackedTailCredentialChildControlsKeep10707_14412` replaced by
  `TestPackedTailCredentialChildControls16108` asserting the actual intended
  gates (OSPF braced: SchemaValidate rejects naming the token without echoing
  the secret; IS-IS case-variant: lenient compile warns, never echoes).

## Validation

- GREEN after fix: `go test ./pkg/config/ -run TestPackedTailCredential` passes.

## Risk

Strict commit now rejects the packed OSPF `authentication-key` spelling
(previously silently dropped); tolerant paths warn via #10707. No valid
spelling changes: real packed credentials resolving to non-stub leaves,
`packedTail` containers, and quoted/bracketed values are untouched. Hot-path:
none — schema validation only, no dataplane change; the probe runs one
validator call per candidate credential token at validation time.
