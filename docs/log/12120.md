- **Issue / PR**: #12120 / #12345.

- **Disposition**: Expand the existing PR; keep its `Closes #12120` relation.

## Why

At `afb932ee1`, repeated unnamed routing containers were silently first-only or
last-root-wins on both strict and tolerant compilation. The missing shapes were
global and per-instance `protocols ospf3`, global `protocols rip`,
`protocols isis`, `protocols lldp`, and `protocols router-advertisement`,
plus per-instance `routing-options static`.
Separate RIP and IS-IS MD5 authentication settings were split across
protocol containers. The global static site was already covered by
#12043 and is now folded into the broader registration.

## What

- Expanded the explicit #12120 registry to 12 sites: `routing-options
  {generate, interface-routes, static}`, `rib ... static`, `protocols
  {ospf, ospf3, bgp, rip, isis, lldp, router-advertisement}`, and top-level
  `protocols`. The `any` static row covers global and instance scope and
  subsumes #12043's former global-static row; #12043 retains its two
  instance-only rows. The retained three-case #12043 test and #12120 site
  census both remain covered.
- Added strict/tolerant merged-control fixtures for every registered site,
  with populated-state and warning checks, including the split RIP/IS-IS MD5
  authentication cases. Updated the routing README's supported-scope and
  protocol list.
- Added structured diagnostic scope for global, routing-instance, and group
  contexts. The formatter uses the structured merge record introduced by
  #12123/#12348; it does not parse rendered warning text. Group warnings now
  depend on merge-site markers surviving actual expansion: unapplied, inactive,
  excepted, and non-selected `${node}` bodies stay quiet, while direct and
  transitive effective applications are named.
- Made root folding deterministic: merge only duplicate top-level `protocols`
  roots there, then fold each registered nested protocol site explicitly.
  Global/instance OSPFv3 and instance static now conserve state and diagnose
  independently of unrelated root stanzas.
- Updated the configstore compatibility assertion: global static now expects
  its #12120 diagnostic; the two retained instance cases still expect #12043.

## Validation

### RED at the original head

The round-1 differential probe at `afb932ee1` logged `DIVERGED` in strict and
tolerant modes for all seven missing shapes: OSPFv3 in a global root, OSPFv3
inside an instance, RIP, IS-IS, LLDP, router-advertisement, and instance static.
The two split-auth probes also diverged: the later RIP/IS-IS protocol block
compiled without its MD5 key/type. The probe harness itself completed; the
cell-level divergence logs are the failing evidence.

### Effective group-warning follow-up

The initial registry fold emitted a group warning for this excluded body even
though the compiled OSPF state was absent:

```text
groups { G { protocols {
  ospf { area 0.0.0.0 { interface ge-0/0/0.0; } }
  ospf { area 0.0.0.1 { interface ge-0/0/1.0; } }
} } }
apply-groups G;
apply-groups-except G;
```

The fix tags each registered group merge site with temporary AST metadata,
propagates it through group expansion, then keeps its warning only if the
marker survives in the effective expanded tree. Metadata is stripped before
typed compilation. Regression coverage checks the excluded shape against the
same body without an exclusion, plus partial exclusion, inactive application,
direct/transitive application, and node-specific `${node}` selection.

## Risk / remaining acceptance

Restoring the previously dropped second block exposes four existing strict
gates that were bypassed by silent loss: a generate-route policy unsupported
in #11456, duplicate BGP neighbors across groups, an IPv6 static route with an
IPv4 next hop, and global interface-routes unsupported by #11314. Strict
duplicate and pre-merged inputs now reject consistently; tolerant compilation
remains non-fatal in all four shapes and preserves the supported state.
