# #17782 - Resolve DNS before serialized apply finalization

- **Timestamp**: 2026-10-28
- **Why**: A cold DNS cache miss looked like a successful empty answer, and live resolver work in promoted finalization held `applySem`. That could reject a resolvable policy, stall unrelated apply transactions, misclassify a recovered rollback target, and retain resolved-config markers. Userspace lowering also treated `DNSUnresolved` as a successful-zero address, poisoning the whole snapshot instead of preserving per-rule DNS match-none behavior.
- **What**: Track cold-cache names with `DNSUnresolved`, keeping `DNSLookupFailed` reserved for resolver errors. Preserve both flags when zone-local addresses fold into the global book. Userspace lowers unresolved or failed DNS entries with no usable prefixes as per-rule match-none (permits match none; deny and excluded-address rules remain fail-closed without the address sentinel). Refresh commit, peer-sync, and rollback DNS before acquiring `applySem`; node-aware prepasses expand `${node}` with the local node identity. Finalization uses prepared/cached DNS only. Bind commit pre-resolution to the sampled candidate generation, reject a changed DNS-bearing candidate, and consume refresher markers on ordinary apply, admission refusal, and superseded-generation exits.
- **Validation**: **RED** on pristine production commit `3c49ffd7a4` with the six new daemon lifecycle tests overlaid (cold-state-only assertions were omitted because `DNSUnresolved` did not exist there): cold-cache commit and changed-candidate commit returned before lookup with the strict `no configured prefix` error; node-1 grouped commit failed the same cold-cache gate; node-1 grouped sync resolved `node0-17782.example.invalid` instead of node 1; sync resolver blocked another `applySem` acquisition; rollback returned before refreshing its target. Fold regressions also failed before their fixes: zone-local copies lost both DNS flags, unresolved policy lowering emitted the unsupported-address sentinel for deny/permit/excluded rules, and a superseded refresh left one resolved-config marker. **GREEN**: all 7 named tests in the config DNS regression file, all 5 in the userspace DNS regression file, the 16-test named daemon issue suite, all 10 DNS refresher/publish tests, and all 8 rollback-preflight tests passed. `go build` and `go vet` passed for `./pkg/config`, `./pkg/daemon`, `./pkg/policymatch`, and `./pkg/dataplane/userspace`; `gofmt -l` reported no PR-touched files.
- **Risk**: Successful-empty DNS remains distinct from unresolved and resolver failure; stale-while-error answers remain concrete. A DNS-bearing candidate changed during resolver prepass still returns a generation conflict, requiring a retry against the new candidate.
