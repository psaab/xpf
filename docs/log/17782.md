# #17782 - Resolve DNS before serialized apply finalization

- **Timestamp**: 2026-10-28
- **Why**: A cold DNS cache miss looked like a successful empty answer, and live resolver work in promoted finalization held `applySem`. That could reject a resolvable policy, stall unrelated apply transactions, misclassify a recovered rollback target, and retain resolved-config markers.
- **What**: Track cold-cache names with `DNSUnresolved`, keeping `DNSLookupFailed` reserved for resolver errors. Refresh commit, peer-sync, and rollback DNS before acquiring `applySem`; node-aware prepasses expand `${node}` with the local node identity. Finalization uses prepared/cached DNS only. Bind commit pre-resolution to the sampled candidate generation, reject a changed DNS-bearing candidate, and consume resolved-config markers on ordinary apply exits. Document the lifecycle and add regression coverage.
