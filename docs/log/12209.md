# Issue #12209 — require the full bake validation scenario set

## Why

The bake's in-guest validation gate correctly passes `all`, but the ordering tests checked only the command prefix and artifact paths. Since `validate.py` also accepts `a` as a successful single-scenario selection, changing the gate's final argument from `all` to `a` escaped the existing tests.

## What

Added a hermetic gate-boundary fixture that runs the real `bake.validation_gate_step` and `validate.main()`, replacing only the hypervisor harness with a recorder. The fixture observes selected scenarios and the scenario methods actually dispatched by the validator, and lets the real manifest-provenance writer set `validated: true` only after the full required set succeeds; narrowed or failed selections leave the sidecar `validated: false`. Tests cover full success, the successful `a`-only narrowing, and a failed full selection. No production code changed.
