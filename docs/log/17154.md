- **Timestamp**: 2026-10-27
- **Issue**: #17154 (R4-Q49-01)
- **Base**: `origin/master 2dce74b744`

## Defect (STEP-0, verified at base)

Live on `2dce74b744`. `grep -n -i 'deadcode\|staticcheck\|U1000\|golangci' Makefile`
found only the scoped #17008 `check-nft-deadcode` leg (pkg/nftables +
pkg/daemon `daemon_nft*.go`); no module-wide reachability gate, no
`.golangci*`, and `docs/deadcode-allowlist.txt` did not exist.

Measured census at base (go1.26.9, `go run golang.org/x/tools/cmd/deadcode@v0.38.0 -test ./...`,
the issue's pinned analyser): **196 unreachable rows = 165 in non-test
files + 31 in `_test.go` files**. The issue counted 154+30=184 at
`0ce804221f` (go1.26.8); the delta is tree drift since, not a
contradiction — the defect class is unchanged and slightly larger.
Production roots are out of scope for phase 1 by the issue's own
phasing (the 529 test-only-reachable functions are phase 2).

Toolchain finding (new at this base): the pinned analyser **panics**
under the ambient go1.27.2 — `panic: unexpected expr: *ast.KeyValueExpr`
in `golang.org/x/tools/go/ssa` — reproduced with both v0.38.0 (`go run
...@v0.38.0`) and v0.40.0 (`go tool deadcode`, go.mod's tool directive)
on `./pkg/config`, `./pkg/cli`, `./pkg/api`, `./pkg/cluster` and
`./cmd/...`. go1.26.9 (`/usr/lib/go-1.26/bin/go`) runs it cleanly. The
existing CI `check-nft-deadcode` leg inherits this exposure when CI's
toolchain (go.mod `go 1.24.9` via setup-go today) moves to 1.27.

## Fix (phase 1 of the issue's fix direction; (3) deletions and (4) phase 2 are per-package follow-ups)

- `scripts/go-deadcode-gate.sh`: runs the pinned
  `go run golang.org/x/tools/cmd/deadcode@v0.38.0 -test ./...` (never
  `go tool deadcode` — go.mod pins x/tools v0.40.0, a different
  analyser) with a resolved go1.26.* toolchain (`$DEADCODE_GO`, `$GO`,
  PATH, `/usr/lib/go-1.26*/bin`, …); diffs the (path, symbol) set
  against `docs/deadcode-allowlist.txt`. New dead function reds,
  stale row reds (allowlist only shrinks), malformed row (not 5 TAB
  columns / bad class / empty reason / empty expiry-or-issue /
  duplicate) reds naming the line. No usable toolchain → exit 77 SKIP
  (named, not silent green); `XPF_DEADCODE_REQUIRE=1` makes that a hard
  failure where set, but it is wired nowhere today — CI uses go 1.24.9
  via `go-version-file` (go.mod) and never runs `make test-go`, so
  today the gate enforces only on `make test-go` hosts with a go1.26
  toolchain. REQUIRE hardening in CI is pending until the workflow
  installs go1.26 and sets `XPF_DEADCODE_REQUIRE=1`. `DEADCODE_OUTPUT=`
  feeds recorded analyser output for hermetic tests.
- `docs/deadcode-allowlist.txt`: seeded exactly from the measured
  base census — 5 `LEGITIMATE` rows (the three `var _` compile-guard
  asserts `pkg/dataplane/{peer_synced_session_delete_published_9714,
  scoped_batch_delete_published_9364,scoped_singular_delete_published_14965}.go`,
  `pkg/api` `authFailureTracker.setClockForTest`, `pkg/authz`
  `SetLookupListenerOwnerForTest`) and 191 `LEGACY-DEBT` rows (160
  production + 31 test helpers) marked as the phase-1 baseline to be
  deleted per-package together with their rows. Adding a LEGACY-DEBT
  row for post-landing code is forbidden by the file header.
- `scripts/go-deadcode-gate-selftest.sh`: hermetic fixture self-test
  (14 cells): exact match green + denominator published; **positive
  controls** — a new dead function (the #17154 acceptance mutation
  shape: a re-added orphan wrapper) reds named, a stale row reds
  named, line-number moves stay green, five malformed-row shapes red,
  unparseable analyser output reds, empty output reds as stale.
  Registered in `scripts/run-selftests.sh` (the `make selftest` suite); it is NOT registered in any CI workflow job — adding it to `.github/workflows/test.yml` awaits the landing change noted below.
- `Makefile`: `make test-go` gains the gate as an unconditional leg
  beside the build-tag census (77 = named skip, other nonzero reds);
  convenience leaves `make go-deadcode-gate` /
  `make test-go-deadcode-gate-lib`.
- `docs/engineering-style.md`: reachability bullet beside the vet-gate
  contract; `scripts/ci_tooling_check.sh`: both new scripts join the
  pinned shellcheck list.
- CI: the hermetic self-test is registered in `make selftest`
  (`scripts/run-selftests.sh`); adding it to
  `.github/workflows/test.yml` needs a token with `workflow` scope and
  is left to the landing change. The live gate runs in `make test-go`.

## Risk

- A host with only go1.27 gets a named SKIP from `make test-go`, not a
  red — deliberate (the analyser panics there; a panic is not a
  finding), with `XPF_DEADCODE_REQUIRE=1` available to make a setting host hard (not wired in CI today; see Fix above). When the tree's toolchain settles on a release where the pinned
  analyser runs, the resolver should be widened in the same change.
- LEGACY-DEBT rows could be gamed by adding one for new dead code;
  the header forbids it and review sees the allowlist diff — the same
  trust model as the #9590 vet carve-outs.
- deadcode false positives (reflection/registration-only entry points)
  go on the allowlist as LEGITIMATE with a reason, per the issue.
