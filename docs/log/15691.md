# Issue #15691: DHCP pool leaf keywords and range spellings

- **Timestamp**: 2026-10-19
- **Problem**: `dhcpLocalServerGroupSchema` declared only `dns-server` and `static-binding` under `system services dhcp-local-server` / `dhcpv6-local-server group <g> pool <p>`, omitting `subnet`, `address-range`, `router`, `lease-time` and `domain-name`. With no schema for those keywords, `SetPath` inserted a two-line Junos pair (`address-range low <ip>` then `address-range high <ip>`) as two separate 3-token leaves, and `compileDHCPLocalServer` only accepted a packed 5-token `low <ip> high <ip>` leaf — so the two-line pair and a braced `address-range { low ...; high ...; }` block compiled with `RangeLow`/`RangeHigh` empty and rendered a Kea config with no dynamic pool. A compact `pool p1 subnet ... router ...;` line likewise split, and re-setting a scalar pool leaf appended a duplicate instead of replacing it.
- **Fix (schema)**: Declared all five leaves under `pool` in `dhcpLocalServerGroupSchema` (`pkg/config/schema_system.go`) with typed validators: `subnet` (ValueCIDR / ValidateRouteDestination, family-agnostic like the pool gate), `address-range` (`args: 4` packed tail owned by a `tailValidator`, plus typed `low`/`high` child leaves for the braced/two-line shapes), `router` (ValueIPAddress), `lease-time` (ValueInteger, ValidateIntegerMin(1)) and `domain-name` (ValueHostname / ValidateDNSDomain). `SetPath` now groups the flat range onto one node and replaces re-set scalar leaves; `SchemaValidate` now checks every leaf instead of accepting it silently.
- **Fix (compiler)**: `compileDHCPLocalServer` (`pkg/config/compiler_services.go`) now find-or-creates the `*DHCPPool` by name (repeated pool blocks and per-leaf nodes merge into one pool), expands a compact pool tail with the live pool schema (`packedBodyChildren` / `expandRunChildren9235` via `dhcpPoolSchema15691`), and folds every `address-range` shape through `applyDHCPAddressRange15691` — packed pairs in either keyword order, one bound per node, and braced child leaves. The shared tail parser/validator lives in `pkg/config/dhcp_pool_range_15691.go` so the schema walk and the compiler read one token stream.
- **Fix (strict gate)**: `validateDHCPPoolValuesStrict` now refuses a one-sided range (`haveLow != haveHigh`): Kea renders no pool for it, so the committed bound would silently serve nothing until its sibling was added.
- **Fix (compact scope)**: The pool node gained `packedStatements: true` so the compact normalizer splits a compact pool tail into sibling leaves. The `compactNormalizeInScope` pair list was NOT widened: a measured widening attempt showed the new pairs only change census buckets the fixture cannot grade, while the compiler's own `packedBodyChildren`/`expandRunChildren9235` expansion already merges the compact spelling on both compile paths. Two census bookkeeping rows were updated for sites this change made gradeable: the stale `benign` entry for `... pool xpfarg static-binding xpfarg fixed-address` (both spellings are now refused earlier by the #15029 missing-subnet gate, so it disarms nothing) was deleted, and a hand-measured `knownFixtureLimited8690` entry for the same site was added (with a subnet present, the elided spelling is refused without the pass and compiles with it).
- **Residual limbs (G50-02, scope-checked)**: The dhcpv6 group-merge omission was the clear residual not in the V37-01 title: registered `{"dhcpv6-local-server", "group"}` and `{"group", "pool"}` in `dupBlockMergeSites9023` so repeated group/pool blocks merge for both families (previously a repeated v6 group overwrote the first in the compiler's map assignment). Multi-block `dhcp-local-server`/`dhcpv6-local-server` stanzas themselves were not reworked: `FindChild` first-only there was not reproduced as losing a distinct server block in this lane's tests, and the compiler's find-or-create covers the repeated group/pool case the comment cited. Removed the now-conserved `system services dhcpv6-local-server group` divergent row and the two stale `... group xpfname pool` skip rows from the #8436 inventory.
- **Not changed**: `dns-server` / `static-binding` handling, the Kea renderers, and the #14601 family/containment checks are untouched; the schema validators run on the strict commit path only, so an already-persisted config still boots (#1960).
