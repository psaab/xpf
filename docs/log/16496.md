# #16496 — live TX-selection walks cloned counter/policer handles they discard

- **Timestamp**: 2026-10-24
- **Context**: `merge_matched_tx_modifiers`
  (`userspace-dp/src/filter/engine/tx_selection.rs`) pushed an
  `Arc::clone` of every matched term's three-color policer and, for
  `then count` terms, its counter into `TxSelectionFilterResult` on
  every walk. The metered and counted live transit walks
  (`evaluate_filter_ref_tx_selection_runtime_counted` /
  `_counted`, reached from `resolve_cos_tx_selection_internal` on the
  non-flow-cache path) immediately dropped those handles: the only
  consumers keep them under `defer_side_effects`. Each matched counted
  term therefore cost a strong-count `fetch_add`/`fetch_sub` on the
  counter shared by all workers per packet, and >=3 handles spilled
  the inline-2 `SmallVec` to the heap — re-adding the cross-worker
  line traffic #3073/#14656 removed. No enforcement or accounting
  effect; per-packet CPU/cache-line cost only, magnitude unmeasured.
- **Fix**: thread a `collect_deferred: bool` through the
  TX-selection walk (`evaluate_filter_ref_tx_selection_runtime` →
  `_inner` → `_counted_family`/`_v4`/`_v6` →
  `merge_matched_tx_modifiers`). Handles are pushed only when it is
  true. The sole collecting walk is the new
  `evaluate_filter_ref_tx_selection_deferred` entry point
  (`count_terms == false`, `now_ns == None`, `collect_deferred ==
  true`), which preserves the #15268 deferred semantics exactly:
  no inline count, no inline meter, handles retained for the
  admission replay. All live entries (`_counted`, `_uncounted`,
  `_runtime_counted`, `_runtime_uncounted`, routing-bearing and its
  remainder) pass `false` and now return empty handle sets.
  `resolve_cos_tx_selection_internal` switches its four
  `defer_side_effects` branches (flowless/flow-keyed × output/ingress)
  from `_uncounted` to `_deferred`; the non-deferred branches are
  unchanged, so transit counting/metering, policer drop, DSCP/FC/log
  folding, and every fail-closed gate are untouched. The cached
  TX-selection walk (`cache_sensitive.rs`) already collects into the
  separate `CachedTxSelectionFilterResult` for flow-cache replay and
  is not changed.
- **File(s)**: `userspace-dp/src/filter/engine/tx_selection.rs`,
  `userspace-dp/src/filter/engine/mod.rs`,
  `userspace-dp/src/filter/mod.rs`,
  `userspace-dp/src/afxdp/tx/cos_classify.rs`,
  `userspace-dp/src/filter/tests.rs`, `docs/log/16496.md`,
  `debian/changelog`
- **Validation**: new
  `live_tx_selection_walks_do_not_clone_handles_16496` cell in
  `filter/tests.rs` (3 fall-through counted+policed terms +
  terminal): metered, unmetered-counted, and counter-suppressed live
  walks return empty handle sets with every counter/policer
  `Arc::strong_count` unchanged while the result is alive (accounting
  for the coalescer's single pending handle; RED pre-fix and RED
  under a `collect_deferred → true` mutant: non-empty sets), the
  metered counted walk still charges each counter inline (positive
  control), and the deferred walk collects 3+3 deduped handles at +1
  strong count, charges nothing inline, and replays exactly once on
  settlement. Existing `*_15268` deferred-replay cells and
  `cached_three_color_replay_latest_policer_dscp_wins_15793` stay
  green; the full `filter::tests` run is 225 passed / 1 failed, the
  one failure (`cached_tx_selection_records_all_fallthrough_count_terms`,
  a coalescer-flush cell on the untouched cached walk) reproduced
  identically on pristine `origin/master` (4232693e10) and is
  base-attributed, not caused by this change. The `cos_classify`
  suite is 110/110 green.
- **Residual**: component level only, matching the finding's
  evidence; no release perf/NUMA measurement was taken, so the
  throughput magnitude remains unquantified. The deferred walk
  still clones (by design — it is off the live transit path and
  runs once per generated reply, not per transit packet).
