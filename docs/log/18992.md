# Issue #18992 — correct the RETH VLAN test gate premise

## Why

At base `1348368e5c`, `TestRethUnitNumberVsVlanIDStrictReject14573` failed because its assertion expected the #14573 collision to name `reth1.200`, but strict compile refused the untagged non-zero `reth1 unit 100` first under #15034/#16583. The old migration comment incorrectly claimed `vlan-tagging` on the parent made the unit exercise the collision check.

## What

Renamed the cell to `TestRethUnitNumberVsVlanIDUnitGatePrecedesCollision14573`. It retains the original untagged unit-number / unit-200-vlan-id fixture and now asserts the actual first refusal names #15034, `reth1 unit 100`, and the non-zero-unit gate. The sibling `TestRethDuplicateVlanIDStrictReject14573` remains the #14573 collision pin and now logs the full collision message; its acceptance assertions remain unchanged. No production gate or ordering changed.

The #15034/#16583 predicate (`untaggedNonzeroUnit15034`) requires a positive tag for a non-zero unit unless its interface name is `irb`, a loopback (`lo<N>`), or a secure tunnel (`st<N>`), or a tunnel stanza is present on that interface/unit. `reth1` has no class exemption, unit 100 is not unit 0, and `vlan-tagging` on the parent does not supply the unit's positive tag. `vlan-id 0` is the untagged sentinel and is not positive; a candidate using it also fails first at #15034. Existing `TestUntaggedNonzeroUnitRejected15034` already pins both the `vlan-id 0` case and an untagged reth unit, so no duplicate gate test was added.

Tunnel experiments did not provide a lawful way to retain the original device derivation. A source-less interface `tunnel mode gre` only bypasses the AST predicate: `TunnelNameMap` does not treat it as an interface tunnel (no source or WireGuard mode), and GRE endpoint emission requires both endpoints, so this is not a real device owner. A complete interface GRE tunnel makes `TunnelNameMap` resolve both refs to `reth1`; the collision diagnostic then concerns the shared tunnel device, not `ge-0-0-1.100`. A unit-level tunnel is skipped by the sub-interface collision pass. Accordingly, the full strict pipeline cannot reach the original untagged unit-number-vs-vlan-id collision under current gate order; the parent is filing a separate gate-order follow-up. The current change records that fact without reordering production gates.
