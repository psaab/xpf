# #12861 — resolve VLAN ingress for source-NAT revalidation

- **Timestamp**: 2026-10-13 (`fix/12861-snat-revalidation-vlan`)
- **Action**: Resolve the stored `(physical ingress ifindex, VLAN)` to its logical interface before source-NAT revalidation derives the live ingress zone.

## Why

`source_nat_translation_still_valid` already used the stored VLAN identity when building NAT scope, but derived its source zone from the raw physical ingress ifindex. On a trunk, the parent ifindex can inherit the first sub-interface's zone while the session arrived on a different VLAN unit. A valid SNAT mapping may then appear to have no matching `from-zone` rule and be revoked when the SNAT generation changes.

## Change

Resolve the logical ingress ifindex with the forwarding state's existing `resolve_ingress_logical_ifindex` helper before `zone_pair_ids_for_flow_with_override`. Preserve recorded zones for fabric/zero-ifindex sessions and retain the resolver's physical-ifindex fallback for ordinary untagged ingress. Add regression coverage for a VLAN unit distinct from its physical parent's zone, untagged ingress, a physical non-VLAN unit, fabric recorded-zone handling, and a VLAN whose live zone must still fail SNAT revalidation.

## Risk

VLAN sessions now use their stored VLAN's live logical unit; fabric/zero-ifindex sessions continue to use recorded zones, and unmapped VLAN identities continue using the pre-existing physical fallback. Existing fail-closed behavior for mappings absent from current SNAT rules is unchanged.
