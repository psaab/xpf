# Issue #12826 — preserve daily all-day across duplicate scheduler stanzas

## Why

`compileSchedulers` composed repeated `daily` windows by replacing the
`AllDay` flag each time. Thus an earlier `daily all-day` followed by a timed
`daily` window lost the all-day contribution, so the existing #12745 validator
could not reject the contradictory union. The scheduler's runtime evaluates
`AllDay` before the time bounds, so the accepted representation would not
express the intended bounded schedule.

The #11358/#12745 window collector repeated that overwrite, independently
hiding the same contradiction during validation. Its boundary scanner also
needed to account for a `stop-time` modifier nested under or packed onto a
`start-time` leaf, matching the existing inline-modifier compiler helper.

## What

Daily `AllDay` is now accumulated with sticky OR in both `compileSchedulers`
and `collectSchedulerWindowPairFindings11358`, matching the existing weekday
merge behavior. Scalar time boundaries continue to compose as before. The
collector records nested/packed `stop-time` modifiers for root legacy windows
and for daily and weekday leaves, so repeated-boundary validation sees them.

Regression coverage exercises all-day then timed and timed then all-day
stanzas, repeated scheduler instances, split boundary composition, group
inheritance, flat-set shape, duplicate all-day controls, identical-window
controls, and nested stop-time modifiers in root/daily/weekday forms.
- **RED before fix:** the new duplicate-stanza tests failed on the base at
  strict compilation accepting the all-day-then-window case, duplicate
  scheduler instances, split boundaries, and group-merged contradiction.
  The all-day union assertion did not run when strict compile unexpectedly
  accepted.

- **GREEN:** `go test ./pkg/config/ -run 'TestScheduler(DailyDuplicate|NestedStopTime)' -count=1` passed after the implementation changes.

The complete `pkg/config` suite and revert-only-source check remain for the main verification gate.

## Risk / residual

Previously accepted duplicate daily statements that combine all-day with a complete
time window now fail strict validation with the existing #12745 diagnostic;
lenient compilation warns and retains the union. All-day-only repetitions,
identical timed windows, distinct weekdays, and partial daily windows remain
valid. Daily exclude composition and scheduler runtime behavior are unchanged.
