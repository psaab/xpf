# #14710 — REST annotate deny-configuration bypass + missing plant class

## Defect
`POST /api/v1/config/annotate` was adjudicated and executed with two
different tokenizations, and planted with no login-class attribution:

- Gate (`authorizeRESTConfigMutation`, `pathFromPath`): built
  `annotate ` + `strings.TrimSpace(req.Path)` and lexed it with the
  config lexer (`lexConfigMutationLine9938`). The lexer stops at
  non-ASCII / vertical-tab / form-feed whitespace (`TokenError`, only
  `' ' \t \n \r` skipped) and treats a quoted final token as the
  annotate *comment* (`configMutationPaths` annotate arm). So
  `system<NBSP>login`, `system<VT>login`, `system<FF>login` were judged
  as `system` only, and `system "login"` was judged as `system` with
  `login` dropped as the comment — a `deny-configuration "system login"`
  never matched.
- Handler (`configAnnotateHandler`): split with `strings.Fields`
  (unicode-aware) and annotated the full `system login` node.
- Handler also called `store.AnnotateAs` (plantClass `""` → superuser
  attribution via `EventPlantClassForMutation`), while every sibling
  REST mutation handler resolves `mutationPlantClass(r)` and calls the
  `*AsPlantClass` variant, and the gRPC annotate path uses
  `AnnotateAsPlantClass`. The #9939/#9984 embedded-command recheck
  provenance was defeated for REST annotations.

Impact is annotation-only (attach a comment to a denied subtree, dirty
the candidate) — not value change or privilege escalation — but the
deny bypass + missing attribution is exactly what #9154/#9892/#9984
exist to prevent.

## Fix
- `pkg/api/authz_config_regex_9154.go` (`pathFromPath` arm): adjudicate
  exactly the path the handler acts on — `strings.Join(strings.Fields(req.Path), " ")`
  plus a synthetic empty quoted comment (`""`). Every handler token
  becomes a bare lexer token (NBSP/VT/FF already split by `Fields`), and
  the synthetic comment is the token the annotate arm drops, so a real
  quoted final token (`"login"`, kept by `Fields` and lexed as a quoted
  string) is adjudicated as part of the path. Empty `Fields` returns
  early (handler's own 400 applies), preserving the #9890
  gate-reads-only-the-handler's-field property.
- `pkg/api/config.go` (`configAnnotateHandler`): resolve
  `mutationPlantClass(r)` (400 via `writeConfigMutationError` when no
  admitted principal/class) and call
  `store.AnnotateAsPlantClass(sessionID, plantClass, pathParts, comment)`,
  matching sibling handlers and the gRPC twin. NOT changed: the store,
  the lexer, `configMutationPaths`, and the gRPC surface (already
  correct).

## Tests
New `pkg/api/authz_config_regex_14710_test.go`:
- `TestRESTAnnotateDenyTokenizerMismatch14710` — real REST server,
  class `limited` with `deny-configuration "system login"`:
  controls first (plain `system login` → 403, `system host-name` → 200),
  then NBSP / VT / FF / `system "login"` bodies must 403; quoted
  allowed leaf must not 403.
- `TestRESTAnnotateHandlerPlantClass14710` — direct handler: annotate
  with no admitted principal must fail and plant nothing; with class
  `limited` it succeeds and applies. (A pure annotate does not change an
  event policy's execution signature — `writeNodeSignature9984`
  excludes `plant-class`, `Annotation` is not in `Keys` — so no
  compiled `PlantClass` delta is observable for a pure annotate; the
  handler-principal gate is the decisive observable, documented in the
  test.)

RED on base (`cbe1027c5e`, fix reverted): NBSP/VT/FF returned 200,
quoted leaf returned 400 (handler path-not-found, gate passed it),
no-principal annotate returned 200. GREEN after fix: all cells pass.

## Risk
Restricted classes now get 403 (not 200/400) for annotate paths whose
`Fields` tokens match a deny — intended. Annotate without an admitted
mutation principal now fails via `mutationPlantClass` like sibling
handlers (the authz guard always injects the principal in production;
only direct handler calls without admission are affected). No wire,
store, or lexer change.
