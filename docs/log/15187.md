# #15187 — shaped non-exact flow-fair CoS queue with mixed Local/Prepared heads wedges permanently (C08-01)

- **Timestamp**: 2026-10-19
- **Action**: `build_cos_batch_from_queue`
  (`userspace-dp/src/afxdp/cos/queue_service/settle.rs`) chose its
  Local/Prepared batch arm from `cos_queue_front` (the uncapped
  min-finish head, `cos_queue_min_finish_bucket(ff, u64::MAX)`) but
  then popped through the cap-aware `cos_queue_peek_min_bucket(queue,
  target_bps)` with an arm-mismatch break. On a shaped
  (`transmit_rate_bytes > 0`) flow-fair queue — a shaped best-effort
  class included, via the forwarding fallback — whose uncapped
  lowest-finish bucket is over the #1229 v7 per-bucket fair-share cap
  while a bucket of the other item kind is under it, the chosen arm's
  first capped peek returned the other kind, the break left the
  scratch empty, and the build returned `None` with every item
  resident. `flow_bucket_observed_bps` only decays on TX accounting,
  so no later pass could progress: the whole class, including
  newcomers into under-cap buckets, stopped transmitting until a CoS
  config change, and stuck Prepared items kept their UMEM frames.
  Fixed by choosing the arm from the same capped selection the pop
  will use: `cos_queue_peek_min_bucket(queue,
  compute_drain_target_bps(queue))` sampled once per build. The
  capped peek falls back to the lowest-finish bucket when every
  bucket is over-cap, so its head is byte-identical to the uncapped
  head for unshaped, all-over-cap, and single-kind queues; only the
  mixed-kind capped case that wedged changes. NOT changed: the exact
  Local/Prepared drains and the exact/waterfill selectors already
  preflight through the capped selection
  (`cos_queue_front_with_cap` / `cos_queue_peek_min_bucket`), so the
  exact paths already fall back to the other arm instead of wedging;
  neighbouring legitimate behaviour is preserved.
- **File(s)**: `userspace-dp/src/afxdp/cos/queue_service/settle.rs`
  (arm selection in `build_cos_batch_from_queue`),
  `userspace-dp/src/afxdp/cos/queue_service/tests/fairness.rs`
  (mixed-head regressions + mirror), `docs/log/15187.md`

## Regression

- `nonexact_mixed_local_prepared_capped_head_does_not_wedge`: shaped
  non-exact queue, over-cap Local bucket (500 B, lower finish) plus
  under-cap Prepared bucket (1500 B); the first build must return the
  Prepared batch (1500 B, under-cap flow), not `None`.
- `nonexact_mixed_prepared_local_capped_head_does_not_wedge`: mirror
  — over-cap Prepared bucket plus under-cap Local bucket; the first
  build must return the Local batch.
- Controls staying green: `nonexact_flow_fair_build_applies_v7_bucket_cap`
  (#13062 all-Local cap deferral) and
  `shared_exact_surplus_build_is_v_min_throttled` (#13062 V_min brake).

RED on the pre-fix builder (uncapped arm choice): both mixed builds
return `None`. GREEN after the fix.

## Verification

- `cargo test --manifest-path userspace-dp/Cargo.toml --bins nonexact_mixed` — see PR.
- Neighbouring `queue_service` fairness/cap cells — see PR.

## Risk

Only the arm choice in the non-exact/surplus batch builder changes,
and only when capped and uncapped selection disagree on item kind —
a case that previously delivered zero bytes on every pass. Unshaped,
all-over-cap-fallback, and single-kind queues select byte-identically
to before (#13062 cap cells stay green). No new fail-open direction:
an empty capped peek still returns `None` exactly as an empty
uncapped front did.
