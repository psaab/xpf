# #12214 — Reject deep/cyclic address sets at commit

- **Timestamp**: 2026-10-08 (`fix/12214-addrset-depth`)

## Red before

At base `a714c90d4`, `CompileConfig` accepted both an address-set chain with six nested edges and a mutual cycle, each carrying concrete address `a0`. The shared dataplane validation prepass then failed on the same configs: the chain returned `address-set nesting too deep (max 5): s0`; the cycle returned `cycle detected in address-set "cycA"`. The live userspace path reaches this shared prepass before applying its snapshot.

`TestAddressSetDepthAndCycleRejectedAtCommit12214` was added before the fix. Its first run failed because both malformed books committed with `err=<nil>`; the five-edge boundary control passed.

## Change

The strict address-set members gate now checks nesting depth and cycles for every address-set in the compiled book, including sets no policy references. Its traversal shares the max-depth constant and path-local lookup/cycle rules with `ExpandAddressSet`, but does not allocate a flattened member result. Errors name the set being checked. Five nested edges remain admissible; deeper chains and mutual cycles are refused at strict commit.

The regression covers the six-edge chain, mutual cycle with concrete members, and valid five-edge boundary.
