# #16001 — family-specific prefix-list `except` under `family any` match-alls the uncovered family on tolerant load (EX-4)

- **Timestamp**: 2026-10-23
- **Defect**: `validateFirewallFilterFamilyAnyMatchesAST` (#4426) strict-rejects
  a single-family prefix-list under `family any` (and, #14446, a wrong-family-only
  list under `family inet`/`inet6`), but on the tolerant load / peer-sync path it
  only warned and the dual-compiled term installed verbatim. For a sole-`except`
  scope — `from source-prefix-list mgmt-v4 except; then accept` — the uncovered
  pool (inet6) holds zero v6 prefixes, so `nets_match` / `nftAddrPredicate` /
  `lo0AddrScope` evaluate `except` over an empty set and match EVERY packet of
  that family: a fail-open over-accept (an over-block on `then discard`). The
  positive single-family case only under-blocks (arm matches nothing, falls
  through) and is not poisoned.
- **Fix**:
  - Go (`pkg/config/compiler_firewall.go`): the gate now also returns the
    uncovered (pool, filter, term) sites for the sole-`except` cases;
    `runPreWalkGates` threads them to `compileExpanded`, which calls
    `markUncoveredFamilyExcept16001` after section compilation to stamp
    `FirewallFilterTerm.UncoveredFamilyExcept16001` on exactly the uncovered
    pool's term. `compileFirewall` now clones a `family any` filter per pool
    (`cloneFirewallFilter16001`) — the two pools previously shared one
    `*FirewallFilter`, so a per-pool mark would have leaked to the covered arm.
    The field joins `effectiveTermProjection15997` (census-pinned).
  - Userspace builder (`pkg/dataplane/userspace/filters.go`): a marked term
    sets `FromUnrepresentable`, so the Rust compiler rejects the candidate
    snapshot whole and reconcile retains prior-good state.
  - lo0 mirrors (`pkg/daemon/daemon_nft_term_lower.go`,
    `daemon_nft_netlink.go`): the text oracle emits the constant refusal
    bareword and the netlink DTO carries `FromUnrepresentable`, refusing the
    whole lo0 candidate the same way.
  - No wire or Rust change: the compiled snapshot is rejected on the
    existing `from_unrepresentable` marker before the matcher runs, and a
    defined-empty `except` list (authored match-all) keeps its semantics.
- **Tests**: `compiler_firewall_family_any_except_16001_test.go` (lenient marks
  inet6-only / inet-only / single-family pool; positive, mixed, and matched
  controls unmarked; strict still rejects),
  `filters_uncovered_except_16001_test.go` (marked inet6 refuses, covered inet
  installs, unmarked control installs), `lo0_uncovered_except_16001_test.go`
  (both renderers refuse; covered control renders).
- **Validation**: focused Go suites (`pkg/config` 16001/4426/4296/15997,
  `pkg/dataplane/userspace` 16001, `pkg/daemon` 16001); full-package results
  in the PR body.
- **Fold (PR #16342, Opus)**: the gate over-refused a term carrying a
  SPECIFIC positive literal alongside an opposite-family sole-`except`
  list. The resolver is positive-wins there (#3359) — the literal is
  preserved as the scope and the `except` list is dropped, so no
  empty-except match-all forms. The gate now tracks specific literals per
  direction (`filterLiteralSpecific16001`, mirroring #3359/#4338) and
  exempts those directions from the marker; a match-any literal
  (0.0.0.0/0, ::/0, any) composes into the sole-except form (#4338) and
  stays marked. Fixture:
  `TestUncoveredFamilyExceptSpecificLiteralExempt16001` (specific v4
  literal + v6-only except unmarked on both arms with the literal intact;
  0.0.0.0/0 control stays marked on the uncovered inet arm).
