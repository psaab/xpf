# #17239 — `system ntp` arm enumerates children two ways; chained `server`/`trusted-key`/`threshold` silently dropped

- **Timestamp**: 2026-10-27
- **Issue**: #17239 (R4-Q23-05, deep-review)
- **Base**: `origin/master 7af3047cda` (worktree `fix/17239-campaign`)

## Defect (STEP-0, verified live on master)

In `pkg/config/compiler_system.go` `case "ntp":` (master lines 325–473), only the
`peer` reader used the #15709 run-normalised list
`hoistAndSplitRun8939(packedBodyChildren(child, refSystemNTP.resolve()), ...)`
(master :402); `server` (:360 `child.FindChildren("server")`), `trusted-key`
(:439) and `threshold` (:456 `child.FindChild`) walked raw direct children.
Measured on master with strict `CompileConfig` (scratch probe, since removed):

- `set system ntp boot-server 3.3.3.3 server 1.1.1.1` → `NTPServers=[]`
  (AST `[system] > [ntp] > [boot-server 3.3.3.3] > [server 1.1.1.1]`, so the raw
  walk cannot see `server`); the only warning blamed the inert `boot-server`.
- Same chain with `peer 2.2.2.2` → `NTPPeers=[2.2.2.2]` (peer alone compiled);
  with `trusted-key 7` → `[]`; with `threshold 400` → `0`.
- Braced `ntp { boot-server 3.3.3.3 server 1.1.1.1; }` and compact
  `ntp boot-server 3.3.3.3 server 1.1.1.1 trusted-key 7 threshold 400;` → all empty.
- Controls: braced direct children and separate `set` lines compiled correctly;
  `set system ntp server 1.1.1.1 peer 2.2.2.2 trusted-key 7 threshold 400`
  compiled all four (followers nest as children, not packed Keys).

## Fix

- Extracted `compileSystemNTP(child, sys, cfg, span)` in
  `pkg/config/compiler_system.go`; the `case "ntp":` arm is now a 3-line call.
  The function computes
  `stmts := hoistAndSplitRun8939(packedBodyChildren(child, refSystemNTP.resolve()), refSystemNTP.resolve())`
  once and dispatches `server`/`peer`/`trusted-key`/`threshold` through a
  single `switch s.Name()`. Acceptance: no `child.FindChild*` walk remains in
  the extracted function (only `thresholdNode.FindChild("action")` on the
  already-normalised threshold statement, plus a comment mentioning the old
  `FindChild` semantics). The old `ntpChildren15709` single-reader list is gone.
- Preserved invariants: #6690 multi-value/block/bracket server reads, #8436
  per-address dedupe + option merge, #14596 server/peer `key` stripping into
  `NTPServerKeyIDs`, threshold first-occurrence (`FindChild`) semantics, and
  the `cfg == nil` guard before `&cfg.Warnings` (parseIntLeaf tolerates nil).
- `multi` boundary kept: `server`/`peer` are `multi` leaves, so
  `hoistAndSplitRun8939`/`expandFlatRun` refuse to cut their packed value run
  (#2419) — a compact `ntp server A peer B;` still projects the packed tail as
  server values exactly as pre-fix, rather than inventing statements from an
  ambiguous bracket-list shape. Only chain links nested as CHILDREN (the
  boot-server-headed flat/braced chain) are promoted, which is the defect.
- Added `ntpSpan17239` (call-site span in `compileSystem`, reset on any
  non-`ntp` sibling, mirroring the `loginUserByName` pattern) with a
  first-occurrence gate for options within a span/group, so a chained
  duplicate in one connected run does not double-merge options.
- Regression guard: `pkg/config/ntp_chain_17239_test.go` —
  `TestNTPChainParity17239` is the table over
  {server, peer, trusted-key, threshold} × {braced, braced-run, compact,
  compact-boot-server-head, flat-boot-server chain, flat-server-head chain},
  asserting the full tuple
  (`NTPServers/NTPPeers/NTPTrustedKeyIDs/NTPThreshold/NTPThresholdAction`);
  `TestNTPChainSeparateSetLinesUnaffected17239` pins the separate-set-lines
  control. Issue-named values: flat-bs-server `[1.1.1.1]`, flat-bs-trusted
  `[7]`, flat-bs-threshold `400`.

## Risk

Bounded to `system ntp` compilation. Behaviour changes only for chains that
previously silently dropped statements (they now compile); braced, compact
(single-statement), bracket-list, block and separate-set spellings compile
identically to master, pinned by the retained #6690/#7132/#8436/#14596/#15709
named tests. The `multi` packed-tail projection is deliberately unchanged.
