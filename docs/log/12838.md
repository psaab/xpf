# Same-netdev unit-0 host-inbound exemption projection (#12838)

- **Issue**: #12838, research D3-01 (High, MATERIAL).
- **Cause**: `junosHostZoneExemptNetdevs` projected a bare physical row and a unit-0 row independently, merging their IKE, ident-reset, and full-admit bits onto one Linux netdev. Unit 0 can collapse onto the physical device, but its effective host-inbound set can differ from the bare ref's under zone-replacing interface override semantics. This made the coarse IKE/ident metadata diverge from enforcement: IKE could be spuriously exempted, TCP/113 reset could be suppressed, or reset scope could be absent.
- **Change**: On an actual same-netdev unit-0 collapse within the target zone, omit the redundant physical-row contribution; unit 0 supplies the effective set. Retain the physical row when unit 0 resolves to a distinct VLAN/tunnel netdev, and when unit 0 is not owned by the target zone. No enforcement path or override semantics changed.
- **Regression coverage** (`pkg/config/junos_host_deny_collapse_12838_test.go`): zone-level IKE/ident-reset replaced by unit-0 `ssh` is not leaked; unit-0 narrowing from zone `any-service` to `ssh, ident-reset` retains the TCP/113 reset; zone full-admit does not suppress unit-0 ident-reset; distinct VLAN unit-0 keeps physical exemptions; unit grants and zone-only controls continue to work.
- **Mutation evidence**:
  - Defective unconditional physical-row contribution: targeted tests failed `TestJunosHostCollapse12838BaseGrantDoesNotLeak`, `TestJunosHostCollapse12838NarrowFromAnyServiceResetsIdent`, and `TestJunosHostCollapse12838BaseFullAdmitDoesNotSuppress`, exposing leaked IKE/ident-reset or missing reset.
  - Inverted same-netdev boundary (`==` instead of `!=`): `TestJunosHostCollapse12838VlanUnit0BaseRowKept` failed because physical-netdev exemptions disappeared when unit 0 resolved to a distinct VLAN device.
  - Both mutations were reverted. Final `go test ./pkg/config -run '^TestJunosHostCollapse12838' -count=1` passed (`ok`, 0.022s).
