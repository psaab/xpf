# 15147 — foreign never-committed host loses all forwarding to the boot transit barrier (B06-01)

- **Timestamp**: 2026-10-19
- **Defect**: `xpf-transit-closed.service` runs `xpfd transit-barrier close`
  before `systemd-networkd` on every boot with no ownership predicate, so a
  foreign host that merely did `apt install xpf` (Docker/libvirt bridges, a
  router being evaluated) got the inet+bridge forward-hook DROP from the
  first reboot onward. #10733 gated the daemon's own writers
  (`shouldManageTransitGate`), but on a never-committed host the daemon
  never actuates — so nothing ever removed the boot-installed barrier and
  routed + bridged forwarding stayed dropped for the whole uptime.
- **Fix (daemon side, the acceptance leg)**: `pkg/daemon/daemon_transit_gate.go`
  gains `removeUnownedBootTransitBarrier15147`, called once in
  `initManagers` (`pkg/daemon/daemon_run_bringup.go`) before
  `applyBootTransitPolicy`. It removes the barrier only when
  `shouldManageTransitGate()` is false AND the new read-only probe
  `configstore.TransitGateOwnedOnDisk` also reads unowned. Removal failure
  is logged (Warn), never fatal (#1960 no-brick).
- **Fix (probe)**: `configstore.TransitGateOwnedOnDisk`
  (`pkg/configstore/store_persist.go`) inspects durable state WITHOUT
  `New`/`NewDB` side effects (which create+chmod `.configdb` and sweep
  temps — the early-boot no-mutation contract): the appliance-visible
  committed bit of `.configdb/active.json` via its envelope header only
  (no decrypt/parse), surviving recovery history (`rollback.*.json`,
  `confirm.json`, api-auth staging, numbered text slots), the
  FIRST-rollback teardown marker, and the #14620 record at
  `configstore.TransitOwnershipRecordPath` (`/var/lib/xpf/transit-gate-owned`).
  Absent reads unowned; present-but-unreadable reads owned (fail-closed,
  mirroring `Load`).
- **Why not gate the boot command**: `xpfd transit-barrier close` must
  stay config-free and lock-free before networkd (#9852); reading the
  store there would need the side-effecting constructor and would stall
  `RequiredBy=systemd-networkd` on a foreign host. The unit file is
  unchanged apart from documenting the ownership contract.
- **Regression**: `pkg/daemon/transit_boot_barrier_foreign_15147_test.go` —
  `TestForeignHostRemovesBootInstalledBarrier15147` pre-seeds a
  boot-installed barrier (the #10733 cell extended per the issue) on an
  unmarked never-committed store and requires a `remove` at bring-up with
  sysctls left at 1. RED on pre-fix `origin/master` (no removal call site
  exists). Controls: appliance marker keeps the barrier, committed store
  keeps it, the durable #14620 record alone keeps it, and
  `TestTransitGateProbeIsReadOnly15147` pins that the probe creates no
  `.configdb`. Adjacent #10733/#14620 suites stay green.
- **Residual (stated)**: if xpfd is disabled/never starts on a foreign
  host, the boot barrier stays until package removal (`postrm` already
  removes it). That is the owned-box fail-closed direction and the only
  remaining foreign-host exposure; it is documented in the unit file and
  `pkg/daemon/README.md`.
