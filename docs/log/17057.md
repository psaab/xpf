# #17057 — consolidate NetFlow v9/IPFIX daemon twins into one parameterized flowFamily

- **Timestamp:** 2026-10-27
- **Branch:** `fix/17057-campaign`
- **File(s):** `pkg/daemon/daemon_flowexport.go`, `pkg/daemon/daemon.go`, `pkg/daemon/daemon_flow.go`, `pkg/daemon/daemon_flowexport_visibility_9166.go`, `pkg/daemon/daemon_flowexport_family_parity_17057_test.go` (new), migrated `daemon_flowexport_*_test.go` / `shutdown_failclosed_order_9035_test.go` / `flowexport_excluded_stats_13307_test.go`

## Why

`daemon_flowexport.go` kept a NetFlow-v9/IPFIX twin for every reconcile, retain, teardown, error accessor and close-callback body plus 14 twin `Daemon` field pairs. The split already caused the IPFIX-only SESSION_OPEN outage fixed by #15946, and 11 of the file's 25 commits had to edit both twins.

## What

- Declare `flowExporter` interface (shared `exporterCore` method set) in `pkg/daemon`, with thin `v9Exporter`/`ipfixExporter` adapters for the typed `TransferFlowStateTo`/`AbsorbSampledInto`. Stateful encoders in `pkg/flowexport` unchanged — wire bytes untouched. `CollectDueExports`/`SetMaskResolver`/`TransferFlowStateTo`/`ExportSessionClose` on the interface are documented in one comment as test surface (production sets the mask resolver inside the `pkg/flowexport` constructors, carries state via `AbsorbSampledInto`, and exports closes via `ExportSessionCloseRemainder`); they are kept on the interface so hermetic cells can drive group exporters through `firstExp()` without concrete-type switches.
- Replace twins with one `flowFamily{name, buildConfigs, newExporter, mu, bundle, hash, cbOnce, err, exporters, configured/excluded/handoff, failedGroups}`; `Daemon.flowFamilies [2]*flowFamily` (netflow-v9, ipfix), initialized eagerly in `New` (Rev18098 fold: the previous lazy `flowFamiliesOrNil` write was unsynchronized; a `sync.Once`-guarded lazy fallback plus nil-family guards remain only for `&Daemon{}` fixtures, proven by `TestFlowFamiliesConcurrentFirstUse17057` under `-race`). Exactly one `reconcile`, `retainedLocked`, `teardownLocked`/`teardownGroupsLocked`, `retireGroups`, `carryFlowStateLocked`, `closeCallback`, `trackOpenLocked` body.
- Keep exported wrappers `FlowExportError`/`IPFIXExportError`, `FlowExportSamplingStats`, `FlowCollectorHealth`, `FlowExportBatchStats`, `FlowExportHandoffDropped`, `FlowExportBuildStates`, `FlowExportFailedGroups` as family loops; keep `stopFlowExporter`/`stopIPFIXExporter` names for shutdown/AST canary (now one-line wrappers).
- Preserve v9 latch semantics in the single close callback (Direction computed once per instance) — previously IPFIX recomputed per group; `FlowDirectionIface` is pure so this is byte-identical.
- Close-callback registration is unchanged in kind: each family's `cbOnce` registers its `closeCallback` method value on first reconcile. (Fold correction: the pre-change twins had no family object that could be nil — their `sync.Once` closures referenced zero-value `Daemon` fields directly; an earlier draft of this log falsely claimed a nil-family capture was fixed. No such race existed.)
- Disclosure: the single `stateCarryTestHook` seam (previously the v9-only `flowStateCarryTestHook`, invoked only from the v9 reconcile) now lives on `flowFamily` and therefore also fires on IPFIX reconciles. It is a test-only hook (nil in production); the 17815 linearizable test sets it on the v9 family only, so its assertions are unchanged.
- New hermetic (class U) parity test drives v9-only and IPFIX-only configs through the same open→close sequence and asserts identical tracker/export behaviour; existing golden tests in `pkg/flowexport` pin byte-identical templates/records.
