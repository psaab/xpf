# #14965 — Session-store batch retry / peer partial-batch scope loss (D28-02)

## Defect (surviving legs only; RoutingDomain retry leg refuted per #9146)

1. **Non-peer per-key retry dropped the scoped key.**
   `batchDeleteExactV4/V6` (`pkg/dataplane/session_store.go`) stops a chunk
   at the first missing key (`ErrKeyNotExist`) and retries the tail per key.
   The retry called bare `DeleteSession`/`DeleteSessionV6`, discarding
   `ScopedSessionKey.RoutingDomain` and `PurgeTunnelVariants`. On the
   userspace backend the bare delete re-derives the domain from the
   surviving BPF mirror row (#9146 self-scope: wrong tenant when the tuple
   collides, nothing when the row is gone) and can never carry
   `PurgeTunnelVariants`, so a GRE0 policy-invalidation row deleted on the
   recovery path exact-matched and leaked.

2. **Peer batch dropped `PurgeTunnelVariants`.**
   `deletePeerBatchKnownExactV4/V6` built forward AND reverse
   `ScopedSessionKey`s from `entry.Value.RoutingDomain` only, dropping
   `entry.PurgeTunnelVariants` — so a peer (cluster-stale) delete of a GRE0
   row exact-matched on both halves.

3. **Peer partial batch orphaned companions/DNAT.**
   On `err != nil` from `BatchDeletePeerSyncedSessionsExactScoped[V6]`
   (helper applied some keys, then failed), the function returned early,
   skipping reverse-companion retirement and dynamic `dnat_table` deletion
   for the forwards the helper DID apply. Refused/unapplied forwards were
   correctly untouched; applied ones leaked their companions.

The RoutingDomain-on-retry limb from the original claim is excluded:
`Manager.DeleteSession` fetches the row's own value and names its domain
(#9146), so no scope was lost there for domain alone — only the
`PurgeTunnelVariants` flag (which has no mirror carrier) was. The fix below
carries both fields anyway via an explicit scoped singular delete, which
also removes the mirror-probe dependence.

## Fix

- `pkg/dataplane/session_store.go`:
  - New optional capability `sessionScopedDeleter`
    (`DeleteSessionScoped`/`DeleteSessionScopedV6`), mirroring the
    `sessionDomainBatchDeleter` shape. `deleteSessionScopedV4/V6` prefer
    it and fall back to bare `DeleteSession[V6]` for dataplanes without it.
  - `batchDeleteExactV4/V6` per-key retry now calls
    `deleteSessionScopedV4/V6(sk)` with the full scoped key.
  - `deletePeerBatchKnownExactV4/V6`: forward and reverse scoped keys now
    carry `PurgeTunnelVariants` (and set-matching uses the full scoped
    key); on a partial-batch error the applied entries still get their
    reverse companions retired and dynamic DNAT entries deleted (best
    effort — the original peer error is returned), while unapplied entries
    stay untouched.
- `pkg/dataplane/userspace/manager_sessions.go`: `Manager.DeleteSessionScoped[V6]`
  builds a `mirror_delete` request with `deleteScopeVal(domain)` scope and
  `PurgeTunnelVariants` from the scoped key — never probes the mirror.
- `pkg/dataplane/userspace/legacy_dataplane.go`: adapter forwarders.
- Compile-time belts (the #9364/#9482 pattern):
  `pkg/dataplane/scoped_singular_delete_published_14965.go` and
  `pkg/dataplane/userspace/scoped_singular_delete_adapter_14965.go` pin the
  capability shape and that both published types (`*Manager`,
  `*LegacyDataPlaneAdapter`) implement it.

## Tests (RED → GREEN)

- `pkg/dataplane/session_store_batch_retry_scoped_14965_test.go`:
  - `TestBatchRetryCarriesScopedKeyV4/V6_14965`: batch stops at a missing
    GRE key; retry must be scoped (tenant domain + purge flag), never bare;
    exact set excludes the missing key, keeps the tail. RED on base
    (exact included the missing key via bare retry, peer/forward purge
    lost).
  - `TestPeerPartialBatchRetiresAppliedCompanionsAndDNAT{,V6}_14965`:
    helper applies fwd0 then errors; fwd0's companion + DNAT retired,
    fwd1's untouched, error preserved, forward keys carry the purge flag.
    RED on base (purge lost, companion orphaned, 0 DNAT deletes).
  - Controls: bare-fallback without the capability still deletes the tail;
    healthy peer batch unchanged.
- `pkg/dataplane/userspace/scoped_singular_delete_14965_test.go`:
  wire-level: scoped singular delete reaches the helper with
  `routing_domain=100007/100008` + `purge_tunnel_variants=true`
  (`mirror_delete`); default-instance control stays `{0,false}`.
