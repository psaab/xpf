# Issue #13236: conntrack GC reports pre-deletion occupancy

`GC.sweep` counted expired entries before deleting them and then reused that
count for `lastTotal`, aggressive-aging watermarks, adaptive sweep cadence, and
`GCStats`. A sweep that drained the table therefore left a false nonzero
occupancy and could trigger aggressive aging against an empty table.

The sweep now adjusts scanned occupancy and established counts using the exact
expired rows removed (including reverse companions), before publishing
watermarks, next delay, statistics, and `lastTotal`. Empty V4/V6 delete batches
are skipped, duplicate callback branches are unified, and telemetry baselines
are updated only when both counter reads succeed.

Regression: `TestGCSweepPostDeletionCounts13236` reproduces the false occupancy
and aging activation with nine expired established sessions. It failed on the
unmodified master with `TotalEntries=18`, `EstablishedSessions=9`, and
`lastTotal=18`; it passes after the fix with all counts zero.
