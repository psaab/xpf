# Issue #13236: conntrack GC reports pre-deletion occupancy

`GC.sweep` counted expired entries before deleting them and then reused that
count for `lastTotal`, aggressive-aging watermarks, adaptive sweep cadence, and
`GCStats`. A sweep that drained the table therefore left a false nonzero
occupancy and could trigger aggressive aging against an empty table.

The sweep adjusts scanned occupancy and established counts from exact forward
rows deleted plus pre-existing reverse companions. Successful deletes use the
batch operation's success contract without another lookup; only failed batch
deletes probe companions to discover partial removals. These post-delete counts
drive watermarks, next delay, statistics, and `lastTotal`. Empty V4/V6 batches
are skipped, duplicate callback branches are unified, and telemetry baselines
update only after successful reads.

Regression tests cover a fully drained paired table, mixed live and expired
rows with an absent companion, and V4/V6 partial deletes where reverse removal
succeeds but forward deletion fails. The original probe failed on pristine
master with `TotalEntries=18`, `EstablishedSessions=9`, and `lastTotal=18`;
all affected tests pass with the corrected accounting.
