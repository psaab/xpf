# #18854 — full-pipe-chain allow no longer admits that chain (class A)

- **Timestamp**: 2026-11-06
  - **Action**: Closed #18854 as class A. The issue asked whether
    #14922 (`4e46f2c854`, "judge login regex forms per-spelling not
    pooled", implementing #14686) intended allow regexes to be judged
    per command spelling, or whether the loss of full-chain allow
    matching was a regression that locks operators out. The answer is
    that it was intended. Since that commit, every spelling (full
    piped line, argument-free prefix, pipe-less core) is judged on
    its own and no length is compared across spellings. With a pipe
    present, `EvaluateFormsWithPipe` in
    `pkg/config/login_regex.go` (wired in by `evaluateCommandRegex`
    in `pkg/cli/command_regex_leaf_16158.go` only when pipe words are
    present) requires the pipe-less command core to affirmatively
    allow; an allow that matches only inside operator-controlled
    pipe filter text authorizes nothing (#14686: pipe-text-only
    allows and wildcard allows measured on the long piped form were
    RBAC bypasses). It follows that an allow anchored on the whole
    chain, `^show version \| no-more \| count$`, by itself no longer
    admits `show version | no-more | count`: the chain's pipe-less
    core `show version` is affirmed by no allow, so the allowlist
    denies it (`login class "piped" denies "show version"`). The
    fix is the test re-pin that already landed plus this
    documentation; no production code, evaluator, or test changes
    here.

  - **Risk**: Behaviour delta (already shipped by #14922, documented
    here, not introduced by this change): an operator class whose
    only allow for a command is pipe-bearing now denies that piped
    command until the pipe-less core is also allowed — see the
    operator note in docs/system-login.md. There is no way to
    express "this exact chain and no other spelling" with
    `allow-commands` alone; the pipe-less core must be admitted too.
    Residual risk is documentation-only: if `EvaluateFormsWithPipe`
