# Issue #16021 — policy: NoRoute skips zone tiers, default permit delegates to kernel FIB despite explicit deny (ZP-07)

- **Issue:** A NoRoute flow (no userspace FIB egress, `to_id == 0`) skipped the whole policy tier walk in `evaluate_policy_result_counted`, so under `default-policy permit-all` the packet was delegated to the kernel FIB — which may still have a route during a flap / FIB-not-loaded / capped learned-route import — and an explicit deny was never evaluated.
- **Fix:** The unresolved-egress (`egress_resolved == false`, `to_id == 0`) evaluation now adjudicates, in normal precedence with the usual first-match, hit-count, and #4569 flowless fragment-association semantics: the known ingress's exact-pair DENY/REJECT rules deny-only (fold: a `trust->untrust deny` covers exactly the kernel-routable destination being delegated; an exact-pair permit names an egress the flow does not have, so permits are skipped uncounted and never rescue — #7480), then the egress-unconstrained tiers `from-zone <from> to-zone any`, `from-zone any to-zone any`, and `junos-global` rules whose to-zone scope is `Any` (from-zone scope still applies). Deny-only exact pairs are indexed per from-zone at snapshot build (`exact_pair_deny_by_from`, host-scoped pairs excluded). `from-zone any to-zone <z>` and to-zone-scoped globals stay ineligible; an eligible explicit PERMIT still delegates, and only an unmatched NoRoute flow reaches the default policy. Resolved zone-0 egress and zone-0 ingress still deny unchanged.
- **Tests:** `tests_noroute_unresolved_16021` — decisive default-permit + explicit-deny cells (exact-pair lan->wan deny/reject incl. the fold cell `noroute_exact_pair_deny_from_known_ingress_denies_16021`, to-any / both-any / unscoped + from-scoped global), deny-only asymmetry (`noroute_exact_pair_permit_stays_delegated_16021`: permit never rescues, never counted, never shadows a lower-tier deny), egress-constrained ineligibility, eligible-tier precedence, and L3/L4 gating incl. flowless fail-closed. The #12906 owner-RG availability sub-cell now expects the known-ingress translated deny to fire deny-only on a base NoRoute. Dual-FIB live experiment (userspace route withdrawn, kernel route retained) remains the cluster-level decisive check.
