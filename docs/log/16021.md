# Issue #16021 — policy: NoRoute skips zone tiers, default permit delegates to kernel FIB despite explicit deny (ZP-07)

- **Issue:** A NoRoute flow (no userspace FIB egress, `to_id == 0`) skipped the whole policy tier walk in `evaluate_policy_result_counted`, so under `default-policy permit-all` the packet was delegated to the kernel FIB — which may still have a route during a flap / FIB-not-loaded / capped learned-route import — and an explicit deny was never evaluated.
- **Fix:** The unresolved-egress (`egress_resolved == false`, `to_id == 0`) evaluation now walks the egress-unconstrained tiers in normal precedence — `from-zone <from> to-zone any`, `from-zone any to-zone any`, then `junos-global` rules whose to-zone scope is `Any` (from-zone scope still applies) — with the usual first-match, hit-count, and #4569 flowless fragment-association semantics. The exact pair, `from-zone any to-zone <z>`, and to-zone-scoped globals stay ineligible (they name an egress the flow does not have); an eligible explicit PERMIT still delegates, and only an unmatched NoRoute flow reaches the default policy. Resolved zone-0 egress and zone-0 ingress still deny unchanged.
- **Tests:** `tests_noroute_unresolved_16021` — decisive default-permit + explicit-deny cells (to-any / both-any / unscoped + from-scoped global / reject), egress-constrained ineligibility in both directions, eligible-tier precedence, and L3/L4 gating incl. flowless fail-closed. The #7480 operator-surprise doc now scopes its "only the DEFAULT decides" claim to egress-constrained rules. Dual-FIB live experiment (userspace route withdrawn, kernel route retained) remains the cluster-level decisive check.
