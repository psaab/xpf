# #18623 — refuse a deferred fresh-bind control-address swap

- **Branch:** `fix/18623-drive`, originally based on `281739b000` and rebased onto current master `ce71b75385`.
- **Why:** The #18606 preflight only checked that the bound address remained configured. A candidate could keep that address while changing its primary/preferred selection, causing networkd and `selectClusterBindAddr` to choose a different address after a fresh bind. The documented boot-abstention window also lacked an explicit operator-risk/procedure note.

## Change

The preflight carries the resolved control-link netdev's rendered CIDRs in order and its family-specific primary/preferred selections. It recomputes fresh-bind selection when any effective input changes, including address membership/order and prefixes that change preferred-subnet grouping. It refuses when the running bound static address remains configured but the candidate would select a different address from both the bound address and the running selection; changes that preserve the actual selection remain admitted. The #18630 peer gate applies the same comparison to the compiled running/candidate peer views, using each view's own `PeerAddress` family; its running-static qualification still lets DHCP-derived and foreign heartbeat addresses abstain. All callers use the state accessor directly.

Added local primary/preferred, membership/order-only and subnet-changing prefix refusals; planned VLAN-parent DHCP filtering in local and peer views; the lenient non-tagging `vlan-id` rendered-address case; and peer-only selector-swap, per-view-family, and unchanged DHCP/foreign controls. The HA restart guidance documents boot-window abstention and the paired offline procedure; boot behavior is unchanged.

## Review fold — resolved-netdev identity and parity boundaries

For exact declared interface refs, `controlLinkState18606` folds enabled
untagged units in numeric order. It includes units with no tunnel and tunnel
units whose `Tunnel.Name` equals `config.LinuxIfName(ifc.Name)`; it excludes
only tunnel devices with a different name and tagged child units. This includes
unit 0's base-device tunnel and a nonzero unit that shares an interface-level
WireGuard device. Non-tagged rows keep the first primary/preferred selector per
family and apply the renderer's DHCP-family static-address filtering.

VLAN-parent DHCP filtering is plan-dependent. With no address plan, the renderer
keeps configured untagged statics even if another unit requests DHCP, and the
preflight retains them too. For a direct, non-excluded, non-quarantined zone
ref that plans a tagged parent, the preflight mirrors the renderer's
`skipAddrs`-driven family suppression, so a DHCP-hidden static is not treated
as a rendered running bind.

The tagged-parent accessor now limits addresses to the selected zone plan when
that plan contributes addresses or DHCP/static suppression. The compact
address-only projection uses the existing config resolver for RETH identity,
IRB bridge mappings, fabric-member identity, and tunnels; it normalizes an
ordinary untagged numbered ref to the parent netdev while retaining separate
unit-tunnel devices, and includes only the selected config/unit addresses. It
does not duplicate `planPhysDesired`'s full planner or introduce a shared plan
API. With no address-bearing or skip-address plan, the accessor follows the
legacy unzoned fallback except for the quarantined-only edge recorded below.
Non-rendered sibling statics and plan-membership changes are pinned by daemon
cells below.

The unit-0 GRE cell uses configured `gr-0/0/0`, whose Linux spelling is
`gr-0-0-0`. The compiler assigns that bare name to `unit 0`'s `Tunnel.Name` and
copies its addresses into the tunnel config; `routing/tunnel.go` reconciles
those addresses on the named kernel link. The preflight includes the address
because that is the bind device. This does not claim a networkd row owns tunnel
addresses: the dataplane skips rows with an empty hardware address.

An undeclared `.0` ref such as `hb.1.0` resolves to the same parent netdev as
`hb.1`, so it now uses the aggregate state; nonzero unit refs remain single
unit states. Secure-tunnel `st0` and `st0.0` retain their unit-0 per-unit
carve-out. Tests pin the unit-7 swap through `hb.1.0`, secure-tunnel addresses,
tagged-child exclusion, no-plan and planned VLAN-parent DHCP behavior, and a
lenient non-tagging `vlan-id` primary swap.

The renderer's non-VLAN fold also iterates numeric unit order, preserving stable
address append and first-per-family selectors. A two-primary unit-0/unit-7
fixture pins the rendered model across repeated compiles and the preflight:
changing only unit 7's selector passes while unit 0 remains the winner, and
changing unit 0's winning selector refuses.
