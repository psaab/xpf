# #15279 — ipsec: TerminateAllSAs swallows per-SA terminate failures (D04-03)

- **Timestamp**: 2026-10-19
- **Action**: `TerminateAllSAs` (`pkg/ipsec/ike.go`) now attempts every
  live IKE SA, counts the successful terminates, and returns
  `errors.Join` of one `swanctl --terminate --ike <name>: <err>:
  <sanitized output>` error per failed connection instead of logging
  the failure and returning `(count, nil)`. It also lists and
  terminates through the Manager seams (`listSAsForTerminate` / `m.sc`),
  like `TerminateConnection` (#15194), instead of the package-level
  `GetSAStatus` / `runSwanctl` that ignored the Manager's exec seams.
- **File(s)**: `pkg/ipsec/ike.go`,
  `pkg/ipsec/terminate_all_sas_15279_test.go` (new),
  `pkg/ipsec/README.md`, `docs/log/15279.md`

## Mechanism (verified at base 223f053150, rebased onto 99b37e805c)

`TerminateAllSAs` looped `terminateIKENames(sas)`, logged
`swanctl terminate failed` at Warn for each failed
`runSwanctl("--terminate", "--ike", ikeName)`, incremented the count
only on success, and unconditionally returned `(count, nil)`. Both
consumers already fail-closed on a non-nil error — the CLI
(`pkg/cli/cli_request_security.go`: `if err != nil { return err }`,
otherwise printing `Cleared %d IPsec SA(s)`) and the gRPC
`ipsec-sa-clear` action (`pkg/grpcapi/server_diag_system_action.go`:
`status.Errorf(codes.Internal, "%v", err)`, otherwise a success
`SystemActionResponse`) — so the swallowed error was the only reason
a failed teardown reported success while the SA kept forwarding.
Scripted callers checking exit/RPC status saw success.

## Fix

- Every live IKE SA is still attempted (a failure does not stop the
  sweep); the count keeps only the successes.
- Failures are collected and returned as a joined error naming each
  failed connection, with the swanctl output sanitized via
  `termsafe.SanitizeForDisplay` (the `InitiateConnection` /
  `TerminateConnection` convention) because the string reaches a
  terminal through both renderers. The Warn log is kept.
- Listing/terminating now go through the Manager seams
  (`listSAsForTerminate`, whose doc already notes the seam routing
  exists "so test doubles that inject swanctl observe the read", and
  `m.sc`) — the same paths `TerminateConnection` uses. Production
  behaviour is identical when no double is installed (the seams fall
  back to `runSwanctlSplit` / `runSwanctl`); `GetSAStatus` itself is
  unchanged and still serves the show/HA paths.
- NOT changed: the consumers (they already propagate a non-nil error
  correctly, so the CLI now returns the error and gRPC now returns
  `Internal` on partial failure with no consumer edit), the success
  arm (`(count, nil)`, same `Cleared N IPsec SA(s)` message), the
  no-SA arm (`(0, nil)`), the failed-list arm (`(0, err)`),
  `terminateIKENames` selection, and `--force` (only
  `TerminateConnection` uses it; `TerminateAllSAs` keeps its
  historical non-force terminate).

## Risk

Operator-visible delta only on the failure path: `request security
ipsec sa clear` and the `ipsec-sa-clear` gRPC action now report an
error (naming the connections that failed to terminate) instead of
`Cleared N` / success when some or all terminates fail. The count in
the success message is unchanged when everything succeeds.
