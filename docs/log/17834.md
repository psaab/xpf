# #17834 — Carry sampled-idle markers across exporter rebuild

- **Timestamp**: 2026-10-27
  - **Action**: `exporterCore.TransferFlowStateTo` now transfers a
    flow's sampled-idle marker (#16747) to the replacement exporter,
    not just live tracker entries. `FlowTracker` gains
    `CloneIdleMarker`/`AdoptIdleMarker` mirroring `Clone`/`Adopt`
    (state already present in the destination wins; the
    `idleMarkerMax` bound applies on adopt). Previously a flowexport
    config rebuild that landed inside a flow's idle window silently
    dropped its marker: the replacement's `TrackedKeys` no longer
    listed the key, so the daemon live feed never observed resumed
    traffic (the #16747 defect again), and the real SESSION_CLOSE hit
    the #16742 close-time fallback — either consuming a second
    sampling slot and exporting the FULL lifetime counters with zero
    baselines (double-counting the span the inactive final already
    emitted) or, deciding out, dropping the post-expiry remainder.
  - **File(s)**: `pkg/flowexport/tracker_15655.go`,
    `pkg/flowexport/exporter_core.go`,
    `pkg/flowexport/idle_marker_transfer_17834_test.go`,
    `pkg/flowexport/README.md`, `docs/log/17834.md`.
  - **Validation**: New regressions RED on pre-fix master
    (`markers=0` / replacement not Tracked) and GREEN post-fix:
    rebuild-then-resume (marker polled, re-arm on the replacement,
    close remainder 7/700 fwd + 3/300 rev, zero fallback decisions),
    rebuild-then-close-without-poll (close exports only the
    post-expiry 9/900, not the 59-packet lifetime), and a
    destination-wins control (live entry not shadowed, existing marker
    not overwritten — passes pre and post). Fail-on-revert re-proven:
    stripping the two source files re-fails the discriminators,
    re-applying passes. `go test ./pkg/flowexport/ -count=1` ok;
    `go test ./pkg/daemon/ -run 'TestFlowLiveFeed|TestSessionClose|TestFlowExport' -count=1` ok;
    `go test -race ./pkg/flowexport/ -run 'TestIdle|TestTransfer|TestClose|TestAbsorb'` ok;
    `gofmt`/`go vet` on flowexport + daemon clean.
  - **Risk**: None beyond the corrected transfer. The source exporter
    keeps its marker (retired without re-emitting tracker state, same
    as live entries), the destination-wins rule prevents any overwrite
    of state the replacement already holds, and adopted markers are
    subject to the same wholesale-clear `idleMarkerMax` cap as ordinary
    markers. Tracker-to-close-only-destination replacement keeps the
    pre-existing #16742 sampled-mark semantics.
  - **Scope note**: The issue body also quotes the retro lanes'
    rearm-side findings on PR #17543: the per-field maxima carry was
    already fixed by merged PR #17932 (#17851; verified at
    `tracker_15655.go` `Touch`/`TouchBidirectional` rearm branches on
    master 61aa231da6). The remaining sum-based rearm progress gate
    (`TouchBidirectional` fwd+rev sum comparison) is issue #17804's
    scope and is deliberately untouched here.
