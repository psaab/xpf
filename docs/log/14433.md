# #14433 — Routing policy-statement default action: merged statement-level `then` carries both `accept` + `reject`

- **Timestamp**: 2026-10-16 (`fix/14433-campaign`)

## Why

A statement-level `then accept` and `then reject` are mutually exclusive, but
every producer resolved them last-wins onto the single-valued
`PolicyStatement.DefaultAction`:

- a group `then accept` merged beside an inline `then reject` (group
  expansion dropped one arm as a scalar/container override, so only one
  action ever reached the compiler);
- hand-authored duplicate `then` blocks in one statement;
- packed/flat spellings (`set ... then accept` + `... then reject`, or
  `... then accept reject`).

The surviving action rendered as the trailing FRR route-map permit/deny, so
an explicit inline `then reject` could be silently inverted to permit
(fail-open), with no evidence of the losing arm anywhere downstream.

## What

- `PolicyStatement.DefaultActionsSeen` (compiler-only) records every distinct
  statement-level default in first-seen order, fed by all readers: the
  braced `then` children loop, the packed `then <action>` key, and
  `parsePolicyStatementInlineKeys11779` (statement-node / then-node /
  child-key tails). Repeated same-action defaults record once.
- Group expansion (`mergeNodes`, leaf and container branches) now adopts a
  group statement-level `then` arm beside an inline peer instead of
  dropping it as an override, mirroring the #12923 default-policy
  group-group handling, so both arms reach the compiler. Term-level
  `then` nodes are excluded by the policy-statement parent check.
- New strict gate `validateRoutingStatementDefaultConflictStrict` in the
  routing uniform-gate phase rejects any statement whose seen set contains
  both accept and reject, naming the statement and both actions. On
  tolerant loads (`lenientPolicyDefaultConflict14433`) it warns and
  `failClosedRoutingStatementDefaultConflicts14433` forces the default to
  `reject` (#1960 no-brick, fail-closed).
- Single default, repeated-same default, group-only default, same-action
  group+inline, no-default (implicit reject), and per-statement isolation
  are unchanged. Distinct from #14425/DR16-H3 (term-level `PolicyTerm.Action`,
  different field and fix site).

## Risk

Only statement-level routing-policy defaults gain a conflict gate; term
actions, BGP default-accept fallback (#2998), and the next-policy gate
(#11780) are untouched. Tolerant loads keep booting with the conflicting
statement failed closed to reject.
