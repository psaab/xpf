# #12121 — harden flow-cache GRE TTL fail-on-revert fixture

- **Issue**: #12121 — restore single-site discrimination for the flow-cache-hit `would_expire` frame argument.
- **Branch**: `fix/12121-ttl-id`
- **Worktree**: `/var/worktrees/12121-ttl-id`
- **Base**: `1c384b9a47ff7d6e567fa50632faa75c3995ae87`

## Why

The tagged GRE fixture's outer IPv4 ID was `0x0001`. With the `would_expire` call reverted from `packet_frame` to `raw_frame`, the inner-relative TTL offset read the outer ID high byte (`frame[22] == 0`), which still satisfied `<= 1`. The flow-cache-hit pin therefore passed under that single-site revert and did not guard the call-site contract.

## What

- Changed only pass 2 of `gre_decap_flow_cache_hit_ttl_expiry_reads_inner_ttl_5615` to set the tagged outer IPv4 ID high byte at `frame[22]` to `2`, greater than inner TTL `1`.
- Zeroed and recomputed the outer IPv4 header checksum over bytes `[18..38]` using the existing `checksum16` helper.
- Updated the fail-on-revert comment to describe the outer-ID byte read by a reverted `raw_frame` argument.
- No production source was changed.
