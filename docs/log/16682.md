# Issue #16682: failed fxp0 `.network` write laundered to `(false, nil)`, bootstrap still renames/cycles the management NIC

- **Timestamp**: 2026-10-25
  - **Action**: `writeBootstrapLifelineNetwork` turned a failed `fsatomic.WriteFileAtomic` into `(false, nil)` — the #5842 shape, since `(false, nil)` already means "already correct" — so `setupBootstrapLifeline` (which refuses only on a non-nil error) went on to write the `.link`, rename/cycle the management NIC to fxp0 and reload, with no fxp0 `.network` to re-address it: the name-keyed host config no longer matched and the link cycle flushed the default route on a bootstrap box with nothing committed to roll back to. The writer now returns the wrapped write error (`write fxp0 .network %s: %w`, mirroring `writeLinkFile`/`writeBootstrapFxp0Network`), so the existing caller refusal fires before the `.link` write, the rename and the reload; the caller log now names both error sources (observation or write). The refusal is unconditional — not scoped by provenance like #6789's observation refusal — because a failed write means no correct `.network` exists for either provenance.
  - **File(s)**: `pkg/daemon/bootstrap.go`, `pkg/daemon/lifeline_network_write_failclosed_16682_test.go` (new), `pkg/daemon/README.md`, `debian/changelog`, `docs/log/16682.md`
  - **Validation**: `go test ./pkg/daemon/ -run 'TestLifelineNetworkWriteFailureRefusesRename16682' -count=1 -v` — all 3 subtests pass (witness + 2 controls); the witness reds when the writer's `return false, nil` is restored (fail-on-revert verified). Regression sweep `go test ./pkg/daemon/ -run '16682|6789|7114|12152|12156|SetupBootstrapLifeline' -count=1` and `go vet ./pkg/daemon/` — see PR.
