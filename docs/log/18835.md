# #18835 — isolate process-wide fd exhaustion pressure tests

- **Timestamp**: 2026-11-05 (`wt-18835`, base `2a257bc944`)

- **Action**: Isolate the #15112 fd-pressure test bodies in child processes and bound the submit test's soft fd limit.
- **File(s)**: `userspace-dp/src/server/reinject_9506_tests.rs`; `docs/log/18835.md`.

## Why

The two #15112 pressure tests share libtest's process-wide fd table and `RLIMIT_NOFILE` with unrelated tests. Their mutex serializes only the pressure cells; the victim tests do not take it. The submit cell drained `/dev/null` descriptors up to the ambient soft limit (524288), while the complete cell already lowered the soft limit to `count_open_fds_15112() + 64`. Thus parallel sibling tests could fail with EMFILE even though both pressure tests passed. Raising the runner's ulimit would not bound the submit cell's drain.

## What

- Keep each pressure test's exact libtest name as a wrapper, but delegate its body to a child process via `current_exe`, exact filtering, and `--test-threads=1`. The child is identified by `XPF_18835_EMFILE_CHILD`; it runs the body inline. The wrapper waits for the child, requires a successful exit and `1 passed` in stdout, and includes both captured streams in assertion failures.
- Add the missing submit-body `RlimitGuard15112::lower_to((count_open_fds_15112() + 64) as u64)` after the pressure mutex, matching the complete cell.
- No production file, unsafe ceiling, or unsafe block changed.

## Risk

The test still exercises idle EMFILE in the accept loops, but the descriptor drain and temporary rlimit are now confined to a child test process. The parent waits for the child, so child failure remains a failure of the named test rather than a detached or ignored outcome. The submit test now uses the same bounded soft limit as the complete test.
