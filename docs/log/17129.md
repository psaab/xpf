# #17129: make heartbeatTimingDivergedLocked obey the *Locked contract

- **Timestamp**: 2026-10-27
- **Action**: Implemented the named fix (split form). STEP-0: defect was
  live on current `origin/master` (`105fbf836f`):
  `pkg/cluster/heartbeat_manager.go:420-422` —
  `heartbeatTimingDivergedLocked` opened with `m.mu.RLock()` /
  `defer m.mu.RUnlock()`, inverting the package convention that every
  other `*Locked` Manager method requires the caller to hold `m.mu`
  (e.g. `election.go` "Caller must hold m.mu"). Its only production
  caller, `ApplyCommittedHeartbeatTiming` (:398), and the four test
  calls worked only by ignoring the name; a future caller holding
  `m.mu` (as `UpdateConfig` does) would self-deadlock, because Go's
  `RWMutex` RLock is not re-entrant against a held write Lock.
- **Change**:
  - `pkg/cluster/heartbeat_manager.go`: removed the self-acquisition
    from `heartbeatTimingDivergedLocked` (now genuinely lock-free,
    documented "Caller must hold m.mu"), and gave
    `ApplyCommittedHeartbeatTiming` a single `m.mu.RLock` spanning
    both the divergence decision and the live/want values it logs —
    previously the decision and the logged values were taken under
    two separate acquisitions and could contradict each other.
  - `pkg/cluster/heartbeat_timing_apply_7164_test.go` and
    `pkg/cluster/updateconfig_delete_latch_15669_test.go`: the four
    existing test calls now hold `m.mu.RLock` around the predicate,
    as the name requires.
  - `pkg/cluster/heartbeat_timing_locked_17129_test.go` (new):
    `TestHeartbeatTimingDivergedLockedWithMuHeld17129` calls the
    predicate with `m.mu` write-held (via a goroutine + 5s timeout so
    a deadlock reports as a test failure, not a hung suite) and
    asserts the diverged verdict.
- **Acceptance**: a brace-scoped scan of every non-test
  `func (m *Manager) ...Locked(` body for `m.mu.(R)(Un)Lock()` now
  reports only `armDegradedTimerLocked` (lock inside its timer
  closure, correct) and the documented `awaitPeerFenceLocked`
  drop-and-reacquire wait — the exact acceptance scan from the issue.
- **Validation**: Named hermetic cells only (Go `-run '^Name$'`):
  - RED pre-fix: `TestHeartbeatTimingDivergedLockedWithMuHeld17129`
    FAILED (5.00s) with "deadlocked when called with m.mu held".
  - GREEN post-fix: same cell PASSED (0.00s).
  - Controls unchanged-green:
    `TestCommittedHeartbeatTimingIsAppliedToARunningHeartbeat7164`
    (all 4 subtests), `TestApplyCommittedHeartbeatTimingIsSafeWithNoHeartbeat7164`,
    and `TestUpdateConfigUnsetRevertsHeartbeatControlGARP15669` all PASSED.
  - `gofmt -l` clean on all touched files; `git diff --check` clean.
  No broad suite run.
- **Risk**: Low. Behaviour is unchanged for all current callers (same
  predicate, same restart decision); the only semantic change is that
  `ApplyCommittedHeartbeatTiming`'s logged live/want values are now
  read under the same RLock as the decision, so the log can no longer
  describe a different state than the one that triggered the restart.
  The predicate's new contract matches its name and the package
  convention, removing the latent deadlock for future locked callers.
