# #12965 — dropped-feed precedence in the simulator and NAT expansion

- **Issue**: https://github.com/psaab/xpf/issues/12965 (follow-up #12853)
- **Base**: `6372394b1` (`origin/master` at worktree creation)
- **Why**: #12961 taught the policy address-book resolver that a present-empty
  overlay from a declared `fail-mode drop` binding is the binding's match-none
  intent and must take precedence over a same-named static closure, but the two
  other expansion sites kept the old union: the in-process simulator's
  `expandBookNameWithMemo` skipped the empty overlay row and appended the static
  value (so `show security match-policies` / gRPC `MatchPolicies` reported
  static matching where the dataplane enforces match-none), and NAT lowering
  (`resolveNATAddressNamePrefixes` → `expandBookNameRecursive`) appended the
  static value after the present-empty overlay, while the `nat.go` doc still
  claimed book-row parity.

## Change

`expandBookNameWithMemo` (pkg/policymatch) and `expandBookNameRecursive`
(pkg/dataplane/userspace, the NAT-lowering traversal) now apply the same
predicate as #12961's resolver gate: when the overlay carries a present-empty
row for a name whose declared binding has `FailMode == "drop"`, expansion
returns that empty row and does not descend into same-named static
addresses/sets — directly or as members nested inside an address-set. A ready
feed still unions with static content, an absent overlay row keeps the
existing fail-closed quarantine for declared-but-unready bindings, and a
present-empty row for a non-drop binding keeps static content (predicate
parity with `addressBookExpansionResolver.expand`). The `nat.go` doc comment
now states the drop exception instead of the stale unconditional parity claim.

## Validation

- **Base RED**: `go test ./pkg/policymatch ./pkg/dataplane/userspace -run '12965' -count=1`
  failed as expected on pristine `6372394b1` with only the new test files
  present: the simulator resolved `denylist` to `[10.0.0.0/8]` (direct and
  nested) and matched the deny on the destination side; NAT resolved the
  drop+alias name and its enclosing set to `[10.0.0.0/8]`.
- **Focused regression**: the same command passed post-fix (direct, nested,
  and destination simulator cases; NAT direct + nested + source/destination
  fallback tokens).
- **Controls (pre-existing doctrine, unchanged)**: ready feed unions with the
  static alias (simulator verdict + NAT union); a declared binding absent from
  the overlay is quarantined fail-closed (NAT fallback token, simulator
  content rejection); a pure static name with no binding keeps resolving;
  a present-empty overlay for a retain binding keeps static content.
- **Full packages**: `go test ./pkg/policymatch ./pkg/dataplane/userspace
  ./pkg/config -count=1` — policymatch and config pass; userspace passes
  except the pre-existing unrelated `TestCapFlagIsWiredEndToEnd9054`
  (route-cap socket wiring), which fails identically on a pristine
  origin/master worktree and is untouched by this diff. Neighbor doctrine
  suites (`12853|12050|12216|4925|3294`) pass in both packages.

## Risk

A NAT `match {source,destination}-address-name <drop+alias>` now resolves to
the unparseable fallback token (match-none) instead of the static prefix, and
the simulator stops reporting the static alias as matching for a hold-dropped
binding — both now agree with the #12961 dataplane row. Configs without
declared fail-mode drop bindings, or with ready feeds, are unchanged.
