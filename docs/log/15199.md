# #15199 — commit-validation reference/open-world gaps (A05-03, A05-06, A05-07)

- **Timestamp**: 2026-10-19
- **Branch**: `fix/15199-campaign`

## Why

Three strict-commit gaps let operator intent silently vanish:

- **A05-03**: `reth5 redundant-ether-options redundancy-group 5` with members
  committed cleanly when no `chassis cluster redundancy-group 5` existed.
  The cluster manager builds elections only from the configured list, so
  the group can never be primary on either node and the reth is dark.
- **A05-06**: unknown interface keywords (`ether-options 802.3ad ae0`,
  `family bridge`, arbitrary tokens, and the fail-open typo
  `family inet filtr input f1`, which leaves `FilterInputV4=""`)
  committed with zero warnings and compiled to nothing.
- **A05-07**: the Junos IPv6 spelling `vrrp-inet6-group 1
  virtual-inet6-address …` was rejected by the #9424 address-list gate as
  "not a valid address", with no pointer to the supported spelling.

## What

- `compiler_validate_strict_reth_rg.go`: `validateRethRedundancyGroupStrict`
  now also requires a reth's RG id to be a configured
  `chassis cluster redundancy-group` (new `validateRethRGDefined15199`).
  Strict rejects; the tolerant path warns via the existing
  `lenientRethRGOwnership` downgrade. Standalone (no cluster stanza)
  configs are exempt. Fixtures that strict-compiled cluster configs
  without RG definitions gained the definitions (4329, 6781, 14573,
  7795, 6779, cross-group); the #6782 "undeclared positive group" scope
  test now pins the #15199 strict reject + lenient verbatim compile, and
  the 255 token boundary is exercised leniently (RG 255 cannot be a
  configured group under the #8317 cap of 15).
- `compiler_openworld_10707.go`: the #10707 open-world advisory walk now
  also covers the `interfaces` subtree, warning on both commit and
  tolerant paths for unmodelled interface/unit/family keywords.
  `filter`/`simple-filter` (owned by #12090) and `vrrp-group` children
  (owned by #15046) are skipped to preserve single-diagnostic contracts.
- `schema_interfaces.go`, `compiler_interfaces.go`,
  `compiler_vrrp_children_15046.go`, `group_merge_named_leaf_9859.go`:
  `vrrp-inet6-group` / `virtual-inet6-address` are declared (inet6 only)
  and parsed into the same keyed `VRRPGroup` as `vrrp-group` /
  `virtual-address`, in flat-set, Keys-packed, and hierarchical shapes;
  the #15046 unknown-child gate covers the alias, and the group-merge
  canonical-identity registry includes it. Census/ratchet rows updated
  (spelling-gate members + ceilings, compact-block inventory, arity
  adjudication, instance-name ratchet).

## Risk

- A05-03 is a new strict rejection: a cluster config that references an
  undefined data RG now fails commit (lenient load still boots with a
  warning). This is the issue's prescribed fail-closed direction.
- A05-06 is warn-only; no previously accepted config is rejected.
- A05-07 only adds an alias; the xpf spelling is unchanged.
