# #16530: `Format()` drops unquoted-bracket as-path flag

- **Timestamp**: 2026-10-24
- **Problem**: `ASPathDef.RegexUnquotedBracket` is derived only from the
  bracket provenance persisted in the JSON DB. `ConfigTree.Format()`,
  which produces the HA config-sync payload (`ShowActive()` →
  `SyncApply` re-parses it) and the rollback slots, rendered leaf keys
  without `[ ]`, so after `Format`→`Parse` the flag was false. The peer,
  or a `rollback N`, then strict-accepted and rendered the mangled regex
  (`[0-9]+` joined to `0-9 +`) that the primary's lenient compile omits,
  so HA nodes could disagree on BGP import/export filtering until the
  next successful strict commit forced the operator to quote the regex.
  Reach is narrow: an active tree carries the flag only if it was loaded
  from a JSON DB written between #6668 and #9881.
- **Fix**: `Node.QuotedKeyPath` (the hierarchical renderer behind
  `Format`, `FormatPath`, the inheritance and redacted hierarchical
  renders, and `FormatCompare`) now re-emits `[ ... ]` around each
  maximal run of keys carrying bracket provenance on a LEAF, mirroring
  what `FormatSetForLoadMerge` already does for flat replay (#10084).
  Authored-quoted keys inside a group stay quoted (so `[ "65000" ]`
  stays faithful and accepted); unquoted keys are emitted verbatim
  (so a gap-loss survivor such as `0-9]+` is not quote-wrapped into
  faithfulness it never had). This is the issue's primary acceptance
  direction ("Have `Format()` keep `[ ... ]` on leaves that carry
  bracket or gap-loss provenance, as `FormatSetForLoadMerge` already
  does"): the generic provenance rule covers both, since a gap-loss
  mark rides the same `KeysBracketed` bit on the adjacent token.
  Containers are unchanged (their grouping is carried by the flat
  renderer; a container's keys are followed by `{`), and `FormatSet`
  keeps the #6668 zero-churn rule — public `display set` output is
  byte-identical. NOT changed: JSON/XML renderers (they do not
  round-trip through the Junos text parser) and the alternative
  refuse/quarantine direction (rejected: tolerant `SyncApply` exists
  so the peer runs the same config as the primary, #1960).

  (flag, payload identity, strict-diagnostic identity) and a rollback
