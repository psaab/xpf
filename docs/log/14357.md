# #14357 — Multi-RG zone session ownership loses IngressIfaceFold on peer-synced sessions

## Defect
- `IngressIfaceFold` is HA-wire-only: `toBPF()`/`sessionValue()` in
  `pkg/dataplane/bpf_session_value.go` drop it, and `ScrubNodeLocal()`
  zeroes `IngressIfindex`/`IngressVlanID` on peer installs. A peer session
  read back from the BPF map therefore has `fold==0 && ifindex==0`.
- `ShouldSyncSessionV4/V6` (`pkg/cluster/sync_zone_rg.go`) and
  `zoneOwnershipSnapshot.shouldSyncV4/V6` then fell back to
  `zoneSetSyncs(ingressZone)` / `z.shouldSync(ingressZone)` — true whenever
  ANY RG in a multi-RG zone is locally primary. An RG1-primary node judged
  peer RG2 rows locally owned:
  1. `ReconcileClusterBulk` never purged stale RG2 rows at `BulkEnd`;
  2. sweep/`storeBulkWalk` re-exported them (echo / split-brain).

## Fix (direction 2 of the issue; direction 1 receiver fold memo not taken)
- `pkg/cluster/sync_zone_rg.go`: when `resolveSessionRG` cannot attribute a
  row, `Flags&SessFlagClusterSynced != 0`, and the ingress zone maps to
  more than one RG, `ShouldSyncSessionV4/V6` and snapshot
  `shouldSyncV4/V6` return `false` (not locally owned) instead of the zone
  approximation. Local unattributable rows, single-RG zones, and unmapped
  zones keep the existing zone fallback (fail-closed: never delete/keep on
  a guess beyond the peer-origin signal). The snapshot gains
  `zoneRGsByZone` (bulk-start RG sets, copied in `snapshotZoneOwnership`).
- `pkg/dataplane/session_store.go`: `ReconcileClusterBulk` no longer lets
  the mapped/unmapped origin guard resurrect a cluster-synced row the
  per-row predicate judged not-owned; absent from the received set it is
  stale and deleted. Local rows and zone-only callers unchanged.

## Deliberate scope cut
- Issue fix direction 1 (receiver-side `(IngressIfaceFold,EgressIfaceFold)`
  memo keyed by `(SessionKey, SessionID)`) NOT implemented: it restores
  full per-RG attribution for mirror rows, but the fail-closed origin-bit
  guard already yields correct sync/reconcile ownership for the
  unattributable population, without new memo lifecycle state. Attributable
  rows (wire path, fold present) resolve exactly as before.
