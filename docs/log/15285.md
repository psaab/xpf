# #15285 — publish rx_ring_full XSK statistic per binding/queue

## Defect, re-verified at base `e480baa5a4`

Kernel XDP ABI distinguishes `rx_ring_full` from `rx_dropped`
(`if_xdp.h`); `userspace-dp/csrc/xsk_bridge.c:365-385` reads all six socket
stats and `xsk_ffi.rs` carries them in `XdpStatisticsV2`, but
`afxdp/binding_state/kernel_stats.rs` destructured `rx_ring_full: _` and
discarded it (listed in `UNPLUMBED_KERNEL_STAT_FIELDS`). No atomic, snapshot
field, wire field, Go decode, status line, monitor line, or Prometheus metric
existed for it. Sampling errors already retain the last value (caller simply
does not call the publisher on `Err`), so that contract needed no change.

Consequence: `Kernel RX dropped: 0` could not establish zero ring-full loss —
the suspected silent micro-drop point for `-P12` retransmit bursts from
#14300. [INFERENCE] Whether ring-full is the burst source can only be
confirmed/refuted on loss hardware with this counter now visible; this change
supplies the instrument, not the verdict.

## Fix — following the existing kernel-stats patterns (#9168/#802)

Producer (Rust, exhaustive destructure preserved):
- `kernel_stats.rs`: bind `rx_ring_full` and `store()` it (absolute per
  socket, never `fetch_add`) into new `kernel_rx_ring_full` atomic;
  `UNPLUMBED_KERNEL_STAT_FIELDS` shrinks to
  `["tx_invalid_descs", "tx_ring_empty_descs"]`.
- `binding_state/mod.rs`: `kernel_rx_ring_full: AtomicU64` + constructor
  init; layout offset pins advance by 8 (2480→2488, 2609→2617), size
  unchanged (2624).
- `binding_state/snapshot.rs` + `worker/mod.rs`: `kernel_rx_ring_full` on
  `BindingLiveSnapshot`.
- `coordinator/refresh_bindings.rs`: copy snapshot → `BindingStatus`, and
  zero it in `zero_unbound_slot`; `coordinator/reconcile/reset.rs`: zero in
  `reset_binding_counters`.
- `protocol/binding.rs`: wire field `kernel_rx_ring_full` (serde `default`,
  wire-additive); fixture `tests/fixtures/protocol_wire_v1.json` gains
  `"kernel_rx_ring_full": 0`.

Consumer (Go):
- `protocol_binding.go`: `KernelRXRingFull uint64 json:"kernel_rx_ring_full,omitempty"`.
- Status: `format/status_sections.go` aggregates per-binding values and
  renders `Kernel RX ring full: %d` beside the existing kernel lines.
- Monitor: `monitoriface/monitor.go` sums it into `UserspaceSnapshot`,
  computes the rebase delta/reset, renders `Kernel RX ring full:`.
- Metric: `xpf_userspace_binding_kernel_rx_ring_full_total` counter with
  labels `{binding_slot, queue_id, worker_id, iface}`, emitted
  unconditionally per binding (0 = no ring-full loss, not absent series) —
  descriptor in `metrics_descriptors_binding.go`, emitter
  `emitBindingKernelRXRingFull` in `metrics_userspace_binding.go`, wired in
  `metrics_userspace.go` / `metrics.go` Describe.
