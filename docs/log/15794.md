# Issue #15794 — session-hit `then count` suppressed on policer-only arms

- **Timestamp**: 2026-10-19
- **Action**: Fixed `evaluate_input_filter_on_session_hit` in
  `userspace-dp/src/afxdp/poll_descriptor/filter.rs` reporting
  `counted=true` on meter-only LocalDelivery policer replays. Those arms
  call `apply_cached_three_color_policers`, which meters token buckets
  only and never charges a `FilterTermCounter`, yet the caller in
  `poll_descriptor/mod.rs` skipped its
  `evaluate_non_pbr_input_filter_counters_cached` charge whenever
  `already_counted` was true — so `then count` never incremented on:
  - NoLocalEntry LocalDelivery, conforming (was `(None, true)`)
  - NoLocalEntry LocalDelivery, red-policed (was `(Some(Discard), true)`)
  - Fresh LocalDelivery, red-policed via stored handles (was `true`)
  - Stale LocalDelivery, red-policed via newly captured handles (was `true`)
  All four now return `counted=false`, so the caller charges the term
  counter exactly once per packet. No behaviour change for transit
  (DeferToTxSelection) hits, per-packet counted walks, or static DENY
  arms, which already ran a counted evaluator. The stale-conforming
  fall-through already returned `result` with `counted=false`, so the
  Fresh/Stale conforming asymmetry is preserved (Fresh conforming also
  already returned `false`).
- **Demonstration (pre-fix)**: new tests
  `no_local_entry_local_delivery_count_increments_with_policer_15794`,
  `fresh_local_delivery_red_policer_reports_uncounted_15794`, and
  `stale_local_delivery_red_policer_reports_uncounted_15794` in
  `filter_revalidation_7212_tests.rs` failed pre-fix with
  "must report counted=false so the caller charges then count (#15794)"
  on all three arms (RED, 0 passed / 3 failed). The NoLocalEntry cell also
  drives the caller-side cached-counter charge and asserts the term
  counter reaches 1 after the conforming packet and 2 after the
  red-policed packet.
- **Validation**:
  - `cargo test --bins -- 15794` — GREEN after fix (see PR).
  - Existing `#14120`/`#14317` policer cells
    (`local_delivery_hit_replays_input_policer_14120`,
    `no_local_entry_local_delivery_meters_input_policer_inline_14317`,
    `stale_local_delivery_policer_captures_with_packet_extra_14317`,
    `transit_hit_defers_input_policer_to_tx_selection_14120`) unchanged
    and passing — they ignore the counted flag, and policer metering
    itself is untouched.
- **Risk**: `then count` on policed host-bound terms now increments on
  red/conforming session hits where it was previously suppressed — the
  intended operator-visible correction. No double-charge: the changed
  arms never ran a counted walk. Transit paths unchanged.
