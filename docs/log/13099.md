# #13099 — DroppedEnforcementChild-poisoned zone quarantined (D3-08)

## Why

A security zone poisoned in lenient compilation (`zone.DroppedEnforcementChild`,
#11575/#12623 — an unrecognized child under `security-zone`) is unbound by
`compileZones` (interfaces / interface host-inbound / screen cleared, "the zone
is unbound"), but the userspace quarantine never consulted the flag. The
poisoned zone still claimed its `StableZoneID`, so it could win the collision
tournament and quarantine a healthy peer, still seeded a
`BuildZoneHostInboundViews` view, and `ClassifyHostInbound` returned
`HostInboundTokenAdmit` for it — a classifier/dataplane split-brain plus a
false quarantine of healthy traffic.

## What

- `pkg/config/zoneid.go`:
  - `ZoneQuarantineExclusionsForConfig` now also excludes every effective zone
    with `DroppedEnforcementChild`, via `poisonedZoneNamesForConfig` /
    `zoneQuarantineExclusionsForNames` / `quarantinedZoneNamesExcluding`.
    Poisoned zones are barred from claiming a `StableZoneID` (they `continue`
    before the owner map is written), so a healthy colliding peer survives.
    This single SSOT propagates to every existing consumer:
    `InterfaceZoneMap`, `ResolveInterfaceHostInbound`,
    `buildZoneHostInboundViewsFromSnaps`, `BuildUnzonedHostInboundIngressNetdevs*`,
    DHCP backstops, addressless-zone observability, `junos-host` deny
    projection, `ClassifyHostInbound(ForInterface)` (via
    `quarantinedZoneNames`), interface snapshots / egress stamping, and all
    `ZoneQuarantineExcludedReason` display surfaces.
  - `ZoneQuarantineExcludedReason` reports the poisoned/unbound cause.
  - New `CollisionSurvivorForConfig` / `StableZoneIDOwnerForConfig`: poisoned
    zones never resolve as the installed owner of a collided ID.
- `pkg/dataplane/userspace/zones_quarantine.go`:
  - `quarantineCollidingZones` computes the quarantine set from
    `ZoneQuarantineExclusionsForConfig(snap.Config)` (name-only fallback for
    hand-built snapshots without config), records poisoned drops with
    `ZoneIDCollision.Poisoned=true` and the healthy survivor, and scrubs
    policies for the full quarantined set (collision losers + reserved +
    poisoned) instead of the name-only collision set.
  - `quarantinedZoneNamesForConfig` (partial scheduler/route-overlay
    republish) uses the same config-aware set.
- Regression: `pkg/dataplane/userspace/zones_poisoned_13099_test.go` —
  poisoned `z174` vs healthy `z214` (verified `StableZoneID` collision),
  lone-poisoned-zone, and healthy-unaffected cases.

Strict path unchanged: `validateUnknownSecurityZoneChild11575` still rejects
poisoned zones at commit; this fixes the tolerant/HA-sync path only.
Fail-closed: poisoned zone's interfaces stay unzoned (compileZones already
cleared them), its addresses fall into the unzoned deny set, and no policy
referencing it survives the scrub.

## Validation

- RED on pristine master: `TestPoisonedZoneDoesNotQuarantineHealthyCollisionPeer13099`
  (healthy `z214` quarantined, poisoned `z174` not) and
  `TestPoisonedZoneAloneIsQuarantined13099` fail; healthy control passes.
- GREEN with fix: all three tests pass.
- `gofmt` clean, `go vet` clean on touched packages; affected package suites
  run by the main agent / CI.

## Risk

- `ZoneQuarantineExclusionsForConfig` is widely consumed; adding poisoned
  zones to it is the intended semantic (they are already unbound), but any
  surface that previously annotated a poisoned zone as merely colliding now
  shows the poisoned reason. Hand-built `Config` values that set
  `DroppedEnforcementChild` manually now quarantine too — consistent with
  `screens.go` / `programZoneMaps`, which already honor the flag.
- `ZoneIDCollision.Poisoned` is a new exported field (zero value = old
  behavior); `String()` output for poisoned records is new wording.
