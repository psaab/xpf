# #14091 — deterministic NAPT64 endpoint-independent BIB

- **Base**: `origin/master` `77260f9e2`
- **Branch**: `fix/14091-campaign`
- **Action**: Key deterministic NAPT64 allocations by the endpoint-independent BIB identity, retain remote-specific sessions, preserve deterministic block placement, and synchronise idle deterministic BIBs with configuration identity validation.

## Why

Deterministic NAPT64 allocated one external port per complete remote-specific flow. That contradicted RFC 6146 BIB semantics and could exhaust a subscriber's deterministic port block merely by contacting multiple destinations.

## What changed

- Added an allocator-integrated persistent lease keyed by protocol, IPv6 subscriber, source port/ICMP identifier, and routing scope, with a 300-second idle lifetime.
- Reused the BIB tuple across remote endpoints while retaining each session's full remote-specific flow key and active-flow reference.
- Kept fresh allocations inside the subscriber's deterministic IPv4/port block; the lock-free block probe still runs before the allocator mutex (#9130), with BIB reuse/expired-lease reclaim handled in the post-probe and probe-exhausted critical sections.
- Carried deterministic configuration identity (`DeterministicPortedIdentity::{V4,V6}`) on persistent leases and idle/display lease records; joining requires matching identity, pool address/index, in-block port, and live/idle validity.
- Freed deterministic ports with no-recycle semantics on GC, expiry, rollback, revoked-lease cleanup, idle-import rollback, and lease replacement paths.
- HA synced-session reservations join the same BIB and are rejected when the translated tuple is outside the subscriber's deterministic block.
- Idle deterministic NAT64 BIBs are exported/imported per NAT64 prefix (`nat64-deterministic-<index>`); import rejects unknown prefixes, mismatched deterministic configuration, wrong address families, unknown translated addresses, and out-of-block tuples without stealing a live tuple.
- Carried the deterministic identity on the Rust and Go idle/display lease wires and regenerated the protocol wire fixture (deterministic fields only; unrelated fixture drift removed).

## RED-GREEN proof

- RED on the pristine deterministic allocator: two remotes for one subscriber transport received ports 1024 and 1025 (recorded in the original investigation).
- GREEN: `deterministic_napt64_same_transport_to_two_remotes_shares_bib_14091` now shares one tuple, tracks both sessions independently, retains the BIB through partial teardown, joins an HA reserve, and reuses the port after idle GC at 300 seconds.
- `deterministic_napt64_bib_identity_teardown_and_idle_import_14091` covers protocol/scope separation, rollback no-recycle, idle export/import, post-failover join, and block/config-identity guards.
- `deterministic_napt64_destinations_racing_share_one_bib_14091` covers concurrent destinations converging on one BIB.
- Fail-on-revert: reverting the BIB key to the full flow key makes the sharing tests allocate distinct ports again; removing deterministic tuple/identity validation makes the coordinator out-of-block import test install the stale record.
