# #15140 — Replayed Noise_NNpsk0 msg1 installed as authenticated (B04-01)

- **Timestamp**: 2026-10-19
- **Action**: The session-sync connect handshake (`Noise_NNpsk0`,
  `pkg/cluster/sync_auth_noise_7163.go` / `sync_auth.go`) authenticated the
  responder after msg2 alone. Under NNpsk0 a msg1 is AEAD-tagged only over
  the prologue and the initiator's ephemeral, neither of which changes on a
  replay, so a passively captured 60-byte `syncMsgAuthHello` re-verified at
  a fresh responder connection with no PSK: the responder wrote msg2, split
  keys, `recordAuthenticatedPeer()` fired, and `handleNewConnection`
  installed the attacker's connection (closing the legitimate conn in the
  slot), sent clock-sync/capabilities/config-key-exchange, and drove a
  cold-prime bulk the attacker could read. Fixed by requiring initiator
  key confirmation before `installConn`, `recordAuthenticatedPeer`, or any
  transmit: after msg2 the initiator must send `syncMsgAuthConfirm`
  (type 44) = HMAC-SHA256 under the initiator→responder frame key over
  `syncAuthConfirmTag || Noise channel binding`. The responder now returns
  a PENDING result (`syncNoisePending`) after msg2 and only promotes via
  `awaitInitiatorConfirm`; silence, a wrong frame type, or a bad MAC fail
  closed under the existing handshake deadline. A replay attacker never
  holds the msg1 ephemeral private key, so it cannot derive the i2r key and
  the connection is never installed. `SessionSyncWireVersion` bumped
  2 → 3 (flag day, same discipline as #7163) so a mixed pair is refused up
  front instead of failing every handshake. Unkeyed (dual-accept) behaviour
  is unchanged. NOT changed: the #6628 in-place upgrade (already carries an
  equivalent confirm) and the config AEAD binding (A24-03, separate issue).

## Risk

Keyed session-sync is a flag day across the pair (wire version 2 → 3):
both nodes must run the new build, matching the existing #7163 posture —
`GateMixedBaseSwap` refuses the mixed pair up front. The responder holds
a pending connection only until the existing 3s handshake deadline. No
behaviour change for unkeyed clusters or for the #6628 upgrade path.
