# #15650 — Repeated `forwarding-options` / `port-mirroring` / `instance` / `input` / `output` stanzas merge instead of overwriting

- **Issue**: #15650 (V18-01, deep-review at f214fac62b).
- **Files**: `pkg/config/compiler_services.go`, `pkg/config/compiler.go`,
  `pkg/config/dup_block_merge_9023.go`,
  `pkg/config/port_mirroring_merge_15650_test.go` (new), `docs/log/15650.md`.

## Defect

Three overwriting layers dropped repeated stanzas:

1. `compileForwardingOptionsWithOpts` used `FindChild("port-mirroring")` — only the
   first `port-mirroring` block under a `forwarding-options` root was compiled.
2. `compilePortMirroring` allocated a fresh `PortMirroringConfig` and assigned
   `fo.PortMirroring = pm` — a second block (or a second `forwarding-options`
   root, dispatched separately by `compileSections`) discarded the first.
3. Inside one instance, `FindChild("input")` / `FindChild("output")` read only
   the first repeated child; repeated `instance span1` blocks each built a fresh
   `mi` and `pm.Instances[mi.Name] = mi` overwrote the previous one. The split
   `instance span1 {input}` + `instance span1 {output}` form then strict-failed
   with the misleading `no ingress interfaces` (second block's empty instance won),
   and on lenient load the first stanza was silently lost.

## Fix

- `compileForwardingOptionsWithOpts` iterates `FindChildren("port-mirroring")`.
- `compilePortMirroring` reuses/merges `fo.PortMirroring` (find-or-create per
  instance name), iterates all `input`/`output` children, and seeds the duplicate-
  ingress owner map from already-merged instances so cross-block duplicates are
  still hard-rejected. Later scalar values (rate, output) win, matching Junos
  merge semantics; ingress interfaces accumulate.
- The #15256 zero-ingress shape error is deferred to
  `validatePortMirroringZeroIngress15650`, run in `compileExpanded` after
  `compileSections` on the fully merged table — otherwise an output-only
  fragment in an earlier `forwarding-options` root (ingress in a later root)
  false-fires before the merge completes. Strict still rejects a genuinely
  zero-ingress final instance; lenient still warns (#1960).
- `{"port-mirroring", "instance"}` registered in `dupBlockMergeSites9023`
  (`dup_block_merge_9023.go`) so same-named `instance` blocks under one
  `port-mirroring` stanza are folded at the AST level on both strict and
  tolerant paths (with the standard #9023 merge warning), in addition to the
  compiler-level merging which also covers repeated blocks/roots that the AST
  fold cannot see (separate `port-mirroring` siblings / `forwarding-options`
  roots are not folded by the named-instance site).

No change to the rest of the #15256 shape gate vocabulary, the #3972 hard
rejects (negative/non-numeric rate, duplicate ingress), or the flat-set
Keys-packed ingress reading.
