# #15083 — SetPath single-value-leaf replacement dropped Inactive/Annotation (A53-05)

## Defect

`setPath` in `pkg/config/ast_edit.go` (single-value-leaf arm, `childSchema.args > 0 && !childSchema.multi && childSchema.children == nil`) replaced the first matching leaf with a fresh node:

```go
repl := &Node{
    Keys:   append([]string(nil), nodeKeys...),
    IsLeaf: true,
}
repl.setKeysQuoted(...)
repl.setKeysBracketed(...)
```

Only quote/bracket provenance was carried. `Inactive` and `Annotation` from the replaced node were lost, so re-setting a leaf — even to the same value — silently re-activated it and dropped its comment at the next commit. In the credential case, a deactivated `authentication encrypted-password` (or `root-authentication encrypted-password`) rotated by `set` re-enabled password login with no operator notice: `WithoutInactive` no longer pruned the leaf, so the compiler treated the new hash as an active credential.

The adjacent flag/multi arm (`:679-686` pre-fix) already kept the existing node on an exact duplicate via `refreshDupKeysProvenance`, which is why only the single-value replacement leg was affected.

## Fix

Carry `Inactive` and `Annotation` from the first replaced node into `repl`:

```go
repl := &Node{
    Keys:       append([]string(nil), nodeKeys...),
    IsLeaf:     true,
    Inactive:   n.Inactive,
    Annotation: n.Annotation,
}
```

Only the cited mechanism changes. Duplicate-collapse (first match replaced, subsequent duplicates skipped), quote/bracket provenance refresh, value replacement, and the flag/multi exact-duplicate arm are unchanged. NOT changed: fresh-leaf creation when no prior leaf exists (nothing to carry), and multi/flag leaves (they already keep the node).

## Risk

Behaviour changes only when re-setting an existing single-value leaf that was inactive and/or annotated: it now stays inactive/annotated instead of silently activating. Active unannotated re-sets are byte-identical. Operators who relied on `set` to re-activate must now use `activate`, which is the documented Junos distinction between the two commands.
