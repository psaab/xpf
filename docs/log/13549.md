# VLAN RETH replacement retains stale primary/preferred metadata (#13549)

- **Issue**: #13549 — tagged VLAN sub-interfaces on a VRRP-backed RETH replace
  VIP addresses with a `169.254.<rg>.<node>/32` advert source but retain the
  old primary/preferred VIP metadata.
- **Cause**: `buildInterfaceNetworkdModels` in the VLAN path forwarded
  `unit.PrimaryAddress` and `unit.PreferredAddress` unchanged when it replaced
  `unit.Addresses`. The non-VLAN VRRP replacement path already cleared both
  metadata fields. This left networkd's primary ordering and preferred lifetime
  directives referring to an address no longer present in `Addresses`.
- **Change** (`pkg/dataplane/compiler_iface.go`): carry the unit primary and
  preferred values into locals, and clear both only when VRRP replaces the
  addresses. Ordinary VLAN interfaces preserve their authored metadata. Added
  `compiler_iface_vlan_primary_preferred_13549_test.go`, covering both the
  replacement and non-replacement control.
- **RED evidence**: on pristine `origin/master` (`d7fe769aa`), the new focused
  test failed with both `PrimaryAddress` and `PreferredAddress` unexpectedly
  equal to `192.0.2.1/24` while the only address was `169.254.1.1/32`.
- **GREEN evidence**: focused new regression and sibling #9721 tests passed:
  `go test ./pkg/dataplane -run
  'TestVRRPRethVLANReplacementClearsStalePrimaryPreferred_13549|TestVRRPRethVLANParentCarriesTheAdvertSourceForAnUntaggedUnit_9721|TestVLANParentSourceIsOnlyForAnAddressedUntaggedUnitOfAVRRPReth_9721' -count=1`.
  `go build ./...` passed; `gofmt -d` on both changed Go files was empty.
  Full `go test ./pkg/dataplane -count=1` completed with unrelated failures:
  `TestUserspaceXDPShimObjectMatchesSourceManifest` (tracked BPF manifest
  differs for `bpf/headers/xpf_common.h`), `TestManager_PreArmMethodMatrix`
  (method count 149 vs 146), and the two retirement-boundary canaries
  (unexpected `pkg/conntrack/gc.go` ebpf import and four unexpected
  `pkg/api/metrics_*` dataplane imports). These areas are outside this diff.
- **Risk**: none beyond intendedly dropping obsolete primary/preferred
  metadata for addresses not configured on the VRRP-backed VLAN device.
