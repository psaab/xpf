# Issue #15697: Structured RT_FLOW untranslated NAT fields mirror the effective tuple

- **Timestamp**: 2026-10-19
- **Problem**: `formatStructuredMsg` (`pkg/logging/format_rtflow.go`) rendered the wire NAT slots verbatim in `RT_FLOW_SESSION_CREATE` / `RT_FLOW_SESSION_CLOSE`. The decoders (`logEvent`, `DecodeRawEventRecord` via `formatNATAddr12890`) encode an absent rewrite as `0.0.0.0:0` (v4) or `[::]:0` (v6), so a non-NAT session emitted `nat-source-address="0.0.0.0" nat-source-port="0" nat-destination-address="0.0.0.0" …`, and an IP-only SNAT emitted `nat-source-port="0"` instead of the effective source port. Junos vSRX reports the effective post-NAT tuple, which for an untranslated component equals the pre-NAT address/port; SIEM/forensic correlation read the zero placeholders as a distinct bogus tuple.
- **Fix**: In `formatStructuredMsg`, NAT fields are resolved through new `resolveNATAddrPort(natAddrPort, origIP, origPort)`: each component (IP, port) falls back to the original `srcIP`/`srcPort` (resp. `dstIP`/`dstPort`) independently when the NAT component is empty, a zero IP (`0.0.0.0` or any spelling of `::`, via `net.ParseIP(...).IsUnspecified()` in `isZeroIP15697`), or port `0`. A translated IP with an untranslated port keeps the IP and mirrors the original port; a port-only rewrite keeps the translated port and mirrors the original IP; a fully translated tuple (including a NAT64 IPv4 address under an IPv6 flow) is unchanged. No decoder, wire format, or Rust change: `EventRecord.NATSrcAddr`/`NATDstAddr` keep their raw post-NAT-slot meaning for other consumers.
- **Not changed**: `POLICY_DENY` carries no NAT params in the Junos SD shape and is untouched; the standard (non-structured) formatter never carried NAT fields; `formatNATAddr12890`'s rendering is pinned by #12890 and untouched.

## RED -> GREEN proof

- **RED** (pre-fix, behavioral tests with the helper-only unit test temporarily neutralized): `go test ./pkg/logging/ -run '15697'` failed, e.g. a wire-decoded non-NAT `SESSION_OPEN` rendered `nat-source-address="0.0.0.0" nat-source-port="0" nat-destination-address="0.0.0.0" nat-destination-port="0"`, the v6 case rendered `nat-source-address="::"`, and the SNAT-IP-only wire case rendered `nat-source-port="0"` instead of `12345`. (The helper unit test additionally fails to compile pre-fix: `undefined: resolveNATAddrPort`.)
- **GREEN**: Same command passes after the fix — direct `EventRecord` fixtures (empty, `0.0.0.0:0`, `[::]:0` NAT slots; SNAT-IP-only; DNAT-port-only; fully translated) and end-to-end `DecodeRawEventRecord` wire frames (v4 no-NAT create/close, SNAT-IP-only, v6 no-NAT) all render the effective tuple for both `SESSION_OPEN` and `SESSION_CLOSE`. Full `go test ./pkg/logging/ -count=1` passes, including the #9321 SD-escape goldens (ordinary translated records byte-identical).
