# Issue #13216: Preserve sibling service configuration and deterministic validation

D3-10 identified first-sibling-only reads in service compilation and
non-deterministic map traversal in strict ip-monitoring validation. In tolerant
compilation, repeated hierarchical `rpm`, `ip-monitoring`, `flow-monitoring`,
`version9`, `version-ipfix`, and DHCP `dynamic-dns` siblings could silently
lose settings; strict diagnostics could select different policies across runs.

The compiler now accumulates those sibling containers and orders ip-monitoring
policy validation by name. Regressions cover sibling blocks, repeated flow
versions, DHCP dynamic-DNS field merging, deterministic errors, and applied
groups. The obsolete duplicate-container gate for services was removed because
the compiler now preserves the blocks instead of rejecting valid sibling
configuration.

Validation: regression tests failed on pristine master, reproducing lost RPM,
flow-monitoring, and DHCP dynamic-DNS settings and a non-deterministic
ip-monitoring error. `go test ./pkg/config -run '13216|DuplicateContainer'
-count=1` passed. `go build ./...` and `go vet ./pkg/config/` passed. Full
`go test ./pkg/config -count=1` and serial `go test -p 1 ./pkg/config -count=1`
runs timed out in `TestSchemaSpellingDifferentialGate`; the concurrent run also
reported an IPv6-prefix-order assertion in `TestConfiguredIPv6Prefixes10856`.
