# #14601 — DHCP pool subnet/range/router/dns-server values unvalidated at commit

- **Timestamp**: 2026-10-16
- **Action**: refuse Kea-refused DHCP pool values at commit, warn on the tolerant path.
- **File(s)**: listed under Change.

## Defect

The compiler copied pool leaves as raw tokens (`compiler_services.go`:
`pool.RangeLow = pp.Keys[2]`, `pool.Subnet = nodeVal(pp)`,
`pool.Router = nodeVal(pp)`) and the Kea generators emitted them verbatim
(`dhcpserver.go`: `Pool: fmt.Sprintf("%s - %s", ...)`, `routers`,
`domain-name-servers` / `dns-servers`). The only subnet gate was #9785's
duplicate check, which `continue`s on an unparseable subnet, and the only
dns-server schema validator (`ValidateIPAddress`) accepts either family.
So a subnet without `/len`, a range outside the subnet or inverted, a v6
router or dns-server in a v4 pool (and mirrors) all committed with
`commit complete`; Kea then refused the whole rendered file
("Invalid subnet syntax (prefix/len expected)", `Subnet::addPool`
BadValue → DhcpConfigError, "Failed to parse pool"; Kea source cited in
the issue) and every pool of that family on the node stopped — the #9785
outage through four more leaves.

## Change

- `pkg/config/compiler_validate_strict_dhcp_pool_14601.go` (new):
  `validateDHCPPoolValuesStrict`. Per pool, in sorted group order, naming
  server/group/pool/leaf: subnet must `ParsePrefix` (bare address =
  no-/len refusal) and match the server family; each present range bound
  must parse, match the family, lie inside the masked subnet, and low
  must not exceed high; a v4 `router` must be a valid IPv4 address; every
  `dns-server` element must parse and match the family.
- `pkg/config/compiler_uniformgates_dhcp_app.go`: gate registered after
  the #9785 duplicate-subnet gate; tolerant path warns.
- `pkg/config/compiler_opts.go`: `lenientDHCPPoolValues`, set in
  `lenientCompileOpts()`.
- Cells: `pkg/config/dhcp_pool_values_14601_test.go` (23 commit cases +
  lenient gate), `pkg/configstore/dhcp_pool_values_14601_test.go` (the
  same refusal through `CheckText`, the Store.Commit composition).
- `pkg/dhcpserver/README.md`: "Pool subnet / range / router / dns-server
  values — #14601".

## Design notes

- **Router is v4-only.** The v6 generator emits no router option (DHCPv6
  has none; routers come from RA), so a v6 pool's `router` leaf never
  renders and is not gated. Gating it would refuse a config Kea accepts.
- **One-sided range bounds are still checked** for parse/family (and
  containment when a subnet exists). The generators render a pool only
  with both bounds, but the issue acceptance names each bound as a leaf
  and the bound would render the moment its sibling is added.
- **No subnet → no containment, everything else still applies.** Mirrors
  `validateDHCPStaticBindingsStrict`'s posture for a subnet-less pool.
- **Family via `Is4`/`Is6`.** A 4-in-6 literal (`::ffff:10.0.0.1`) is
  `Is6`, not `Is4`, so it is refused under dhcp-local-server — Kea's
  subnet4/option parsers would not accept it as IPv4 data either.
- **No render belt.** Unlike the duplicate subnet there is no safe
  kept-pool arbitration for a mistyped value; dropping the pool would
  silently unserve its clients. Commit is the gate, renderer unchanged.
  Tolerant-path configs therefore reach Kea exactly as before (Kea's
  refusal is the signal there) — noted as the residual risk.
- **Not gated:** `domain-name` (the issue dropped the comma claim as
  unverified against Kea), lease-time, group interface (different
  mechanisms, other issues).
