# Issue #15694: show dhcp server detail pool parity (V37-04)

- **Timestamp**: 2026-10-19
- **Problem**: Both `show dhcp server detail` renderers (`pkg/cli`
  `showDHCPServer`, `pkg/grpcapi` `showDHCPServerDetail`) omitted compiled
  pool fields Kea serves: DHCPv4 pools printed no `domain-name` and no
  `static-binding`; DHCPv6 pools printed only subnet/range (no
  `dns-server`, `domain-name`, `lease-time`, `static-binding`, so a
  reservation-only pool looked empty). Groups iterated in Go map order,
  and the pool section never showed the Kea subnet-id the lease table's
  `Subnet` column refers to.
- **Fix**: Both renderers now iterate groups in sorted order (existing
  `sortedDHCPRelayKeys` / `sortedMapKeys` helpers), print every compiled
  pool field (v4 gains `Domain` + static bindings; v6 gains `DNS`,
  `Domain`, `Lease time` + static bindings; binding hostnames via
  `termsafe.SanitizeForDisplay` per the fix direction), and print
  `Subnet ID: <id>` under each pool subnet. The id comes from the new
  exported `dhcpserver.SubnetIDAssignments15694`, which replays the Kea
  generators' stable walk (sorted groups/pools, subnet-less /
  interface-less / duplicate-masked-prefix skips, then
  `resolveSubnetID`) so the displayed id is exactly the id
  `generateKea4Config`/`generateKea6Config` write. Pools the generators
  skip (and duplicate respellings) take no id and print no `Subnet ID`
  line. Nil group/pool/binding entries are skipped instead of panicking.
- **Docs**: `pkg/dhcpserver/README.md` gains a `show dhcp server detail`
  pool-display section; this log.
- **Not changed**: Kea config generation, lease rendering, and the
  non-detail `show dhcp server` output are untouched. The v6
  multi-interface render refusal is not reproduced in the assignment
  helper (it aborts the whole render, so no Kea config exists to
  correlate against); duplicate-subnet pools keep the first pool's id.
