# #16855 — post-start lease-add backstop unordered with Kea restart (R3-B03-02)

- **Timestamp**: 2026-10-25
  - **Action**: On an active/active takeover whose memfile pre-seed failed, the post-start `lease{4,6}-add` backstop raced the queued Kea restart: it dialed the still-running pre-restart Kea (which has no subnet for the newly taken RG), got `Invalid subnet-id`, and was never retried, leaving the promoted RG without the peer's bindings until clients renew. Fix orders the seed after the takeover apply: `enqueueDHCPApplyWithAuthorityState` now returns its lease-authority generation, `applyRethServicesForRG` passes it to `seedDHCPLeasesFromPeerGen`, which waits (bounded 20s, fail-open on timeout/ctx) for `Manager.AppliedGeneration(family)` to reach that generation — published only by the apply body that actually loaded the config — before waiting for the control socket. Re-anchoring now uses the post-wait clock. Alongside, the v6 seed wire form `keaLeaseJSON.IAID` became `*uint32` so an IAID-0 binding still emits `"iaid":0` instead of being dropped by `omitempty` (read side unwraps via `IAIDVal()`, absent ⇒ 0).
  - **File(s)**: `pkg/daemon/daemon_dhcp_lease_sync.go`, `pkg/daemon/daemon_ha.go`, `pkg/daemon/dhcp_applier_9349.go`, `pkg/daemon/dhcp_seed_order_16855_test.go`, `pkg/daemon/dhcp_apply_wiring_9349_test.go`, `pkg/daemon/dhcp_lease_authority_10170_test.go`, `pkg/dhcpserver/lease_sync.go`, `pkg/dhcpserver/lease_sync_test.go`, `pkg/dhcpserver/README.md`, `debian/changelog`, `docs/log/16855.md`
  - **Validation**: `go test ./pkg/daemon/ -run 'TestSeedWaitsForTakeoverApply16855|TestSeedIAIDZeroEmitted16855'` PASS — modelled old Kea rejects with `Invalid subnet-id`, restart completes mid-seed-wait, seed lands `oldAdds=0 newAdds=1` (pre-fix / wait-removed: `1/0`); IAID-0 lease6-add carries `"iaid":0` (RED when IAID 0 is dropped again). Adjacent: `go test ./pkg/daemon/ -run 'TestSeed|TestDHCPLease|TestMasterEdgePasses|TestFirstMasterEdge'` PASS; `go test ./pkg/dhcpserver/` PASS. Pre-existing unrelated `TestMasterEdgeNudgesProxyARP9087` failure (cluster election config check) observed on this head; not touched by this change.
  - **Risk**: Fail-open preserved: a takeover apply that never marks the generation applied still seeds after the 20s bound (logged), and ctx cancellation aborts the wait. Direct/legacy seed callers use generation 0 and seed immediately as before. The generation wait requires both wanted families to reach the generation; a family whose apply failed stays unapplied, so the seed proceeds on timeout rather than seeding the wrong process early — strictly better than the pre-fix race. IAID pointer changes only the seed/get wire struct; memfile paths unchanged.
