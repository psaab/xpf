# #15276 — ha: RETH L2-identity announce gap on live MAC change (C10-01)

## Mechanism (re-anchored at origin/master ef317aaa14)

- `pkg/daemon/daemon_reth.go` `programRethMAC`: a live `setHardwareAddr`
  success logged "RETH MAC set without link cycle" and returned
  `linkCycled=false`. A commit that moves a RETH to another redundancy group
  the same node also owns changes the member's virtual MAC exactly this way.
- `pkg/daemon/daemon_apply_dataplane.go` step 2.6b
  (`reconcileAfterRethLinkCycle`) ran `scheduleDirectAnnounce` /
  `vrrpMgr.ReconcileVIPs()` only `if needLinkCycleRecovery`, so the live
  change produced no announce. The 2 s direct-VIP reconcile does not announce
  either: `daemon_ha_vip.go` `applyDirectVIPOwnership` announces on
  `!prev || added > 0`, and the VIPs are already present (non-EEXIST adds
  only). Neighbours kept the old MAC until their own ARP/ND ageing
  re-resolved it — inbound traffic to that RETH's VIPs black-holed meanwhile.

## Fix

- `programRethMAC` now reports `macChanged` separately from `linkCycled`:
  true only where the target MAC was written (live set succeeded, or the
  cycled set succeeded — including a following link-up failure); a failed
  MAC write leaves it false. Threaded through
  `programRethMACWithWorkerJoin` → `programRethMemberMAC` → step 2.6, which
  folds changed members into a per-RG `macChangedRGs` set.
- Step 2.6b (`reconcileAfterRethLinkCycle`): the address reconcile
  (VIP/link-local re-add) stays gated on `needLinkCycleRecovery`; the
  announce is owed whenever a member MAC changed. Direct mode:
  `scheduleDirectAnnounce(rg, "reth-mac-change")` for changed RGs the local
  node is primary for (the cycled control keeps its single
  `"link-cycle-recovery"` announce). VRRP mode: new RG-scoped
  `vrrp.Manager.ReconcileVIPsForRG` sends the forced GARP/NA for exactly
  that RG's MASTER instances; an out-of-range RG ID reconciles nothing.
- Existing `programRethMAC*` call sites and the #5103 canary were updated for
  the added results; no behaviour change outside the cited mechanism.

## Regression (RED → GREEN)

- RED on base: `go test ./pkg/daemon/ -run TestC10LiveMACChangeNoAnnounce`
  failed to build (`programRethMemberMAC` returned 3 values, no
  `macChanged`); `go test ./pkg/vrrp/ -run 'TestReconcileVIPsForRG.*15276'`
  failed to build (`ReconcileVIPsForRG undefined`).
- GREEN after fix: `TestC10LiveMACChangeNoAnnounce` passes all four cells —
  live MAC change announces exactly once for the owning RG, no-MAC-change
  apply announces nothing, the cycled control announces exactly once via
  link-cycle-recovery, and VRRP mode fires no direct announce. The VRRP leg
  is bound in `pkg/vrrp` by `TestReconcileVIPsForRGAnnouncesOnlyThatRG_15276`
  (RG1 forced GARP advances, RG2 untouched) and
  `TestReconcileVIPsForRGOutOfRangeIsNoop_15276`.
