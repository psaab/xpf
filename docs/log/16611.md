# #16611 - bind the #14981 commit gate verdict to the candidate it priced

- **Timestamp**: 2026-10-25
- **Action**: The #14981 commit-time expanded deny-configuration gate priced the candidate at the gRPC interceptor / REST middleware, but the daemon promoted whatever candidate existed after the `applySem` wait and re-adopted a changed one on generation conflict (`commitWithGenBinding`), so a same-holder `copy`/`rename`/`apply-groups` landing in between was committed unadjudicated. Fixed by binding authorization to what is promoted: the interceptor/middleware now stash the priced snapshot (admitted config, class, candidate generation, active tree) in the request context; `Server.Commit`/`CommitConfirmed` (gRPC) and `configCommitHandler`/`configCommitConfirmedHandler` (REST) stamp it into the `CommitAuthority` via `CommitAuthority.WithCommitGate`; `configstore.verifyCommitAuthorityLocked` re-prices a changed candidate for the committing class under the store lock and refuses promotion (gate's permission-denied, or `ErrCommitCandidateChanged` for an allowed-but-changed candidate — deliberately not `ErrCandidateGenerationConflict`, so the daemon's adopt-on-conflict retry cannot automate the substitution; `commitWithGenBinding` also refuses that sentinel explicitly). Unchanged candidates commit as before; unrestricted classes (no `*-configuration` restriction and no #16080 credential surcharge) and internal/system committers are never bound.
- **File(s)**: `pkg/configstore/commit_authority.go`, `pkg/grpcapi/authz_config_regex_9154.go`, `pkg/grpcapi/authz.go`, `pkg/grpcapi/server_config.go`, `pkg/api/authz_config_regex_9154.go`, `pkg/api/authz.go`, `pkg/api/config.go`, `pkg/daemon/daemon_apply_commit.go`; tests `pkg/configstore/commit_gate_16611_test.go`, `pkg/grpcapi/commit_gate_16611_test.go`, `pkg/api/commit_gate_16611_test.go`; `docs/system-login.md`, `debian/changelog`.
- **Validation**: New 16611 cells RED with `verifyGateBindingLocked` neutered (denied candidate promoted), GREEN post-fix: configstore (copy-between refused for Commit and CommitConfirmed, allowed-change refused as changed then commits when re-priced, unchanged commits, before-commit copy still refused at the gate, internal/unbound authorities unaffected), gRPC and REST wiring cells (gate → interleaved apply-groups → handler Commit refused and active unchanged; unchanged twin commits with a gate-bound authority). Adjacent 14981/6808/15208/14990 suites still pass.
- **Risk**: A restricted class whose candidate changes for any reason between the gate and promotion must re-issue the commit (fail-closed, intended). The priced snapshot retains a copy of the login-class rules and the active tree per in-flight restricted commit; bounded by concurrent commit count. CLI commits are single-process (gate and commit in one call path) and are not bound; the residual is the gRPC/REST concurrent-stream window this issue documents.
