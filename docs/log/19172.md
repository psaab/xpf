# #19172: master's tree-wide go vet gate is red on pkg/wireschema

- **Timestamp**: 2026-11-16 (G5, b7g)
- **Action**: Measured on master `ebb32e817b` (udp:xpf-testrunner2, go1.24.9).
  `go vet ./...` returns rc=1 with exactly two diagnostics, both in
  `TestWireNamesOfTagSemantics17137`'s fixture (#17137):
  - `DashString repeats json tag "-"`;
  - `unexportedTagged has json tag but is not exported`.
  The tags are deliberate: they pin `-,string`/`-,omitempty` (the name
  "-", not an exclusion) and a tagged unexported field. `go test` runs only
  a subset of the vet analyzers, without `structtag`, so the package's own
  tests stayed green.
- **Action**: The fixture is now built with `reflect.StructOf`, carrying the
  same nine fields in the same order with the same names and tags. The two
  unexported ones get the package's `PkgPath` through a named anchor type,
  as a literal's unexported fields would. go1.24.9 accepts unexported
  StructOf fields with a PkgPath (probed on a runner first). Two fixture
  checks fail the cell if the built type ever loses the `-,string` tag or
  exports `unexportedTagged`. The tree-wide vet gate is not touched.
- **Validation** (tcp:xpf-testrunner3 via `scripts/vm-test-run.sh`):
  - `go vet ./...` on b7g: rc=0;
  - the cell passes (10 subtests); gofmt clean;
  - the same five WireNamesOf mutants against BOTH fixtures, identical
    results. Each is KILLED in 4 subtests (struct value, pointer, double
    pointer, nil pointer):
    - `-`-prefix excludes;
    - `-,string` excluded;
    - no name split;
    - no unexported skip;
    - no empty-name fallback.
