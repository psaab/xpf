- **Timestamp**: 2026-10-25
  - **Action**: Close R3-A56-02 (#16809): ARMING was classified everywhere
    as "firmware one-shot never set", but two paths reach a boot with
    BootNext actually queued while the journal still says ARMING:
    (a) process death between `SetBootNext` (`kernel_run.go`) and the
    ARMED rename, and (b) a `SetBootNext` error after the write landed
    (the 10 s NVRAM kill timeout / non-zero exit after `SetVariable`),
    whose error branch never cleared BootNext. The candidate then booted
    unverified while `Promote`, the outer `xpf-kernel-promote` hop, the
    daemon election hold and `kernel status` all treated it as an
    ordinary boot.
  - **Fix**:
    1. The `SetBootNext` error branch now clears BootNext via
       `disarmAfterArmFailure` (the #6758 helper), unconditionally:
       clearing an absent BootNext is already a success, and a clear
       failure is reported loudly with the manual
       `efibootmgr --delete-bootnext` command.
    2. New `KernelRunner.UnconfirmedTrial`: an ARMING journal whose boot
       evidence — `BootCurrent == entries[InactiveSlot]` AND
       `uname -r == CandidateVersion` — convicts the boot as a genuine
       trial. Fail-closed: unreadable entries/BootCurrent/uname, a
       vanished candidate slot, or an empty candidate/slot returns an
       error, never a bare "not a trial". `TrialInFlight` =
       verified-ARMED (short-circuit, no boot-evidence reads) OR an
       unconfirmed trial.
    3. `Promote` gates an unconfirmed trial exactly like ARMED
       (verify-dataplane + beacon; promote or attempt-capped revert);
       unreadable evidence goes indeterminate (no prune, no reboot,
       journal kept). `IsArmed` stays state-only by design (Arm re-arm,
       offline reads).
    4. Daemon: `holdSecondaryIfKernelCandidateArmed`, the fail-closed
       hold reconcile, and the self-recovery `Armed` gate now classify
       on `TrialInFlight`, so an unconfirmed trial is held SECONDARY and
       suppresses expired-lease failback like ARMED; an ordinary ARMING
       boot (positively known-good) still rejoins (#5847 preserved).
    5. `xpf-kernel-promote`: `journal_state` returns a new `arming`
       value for ARMING **with the arm record present** (the record is
       written before the ARMED transition, so its presence is the
       shell-provable half of the shape); the record-present path runs
       the recorded binary and the Go half convicts on
       BootCurrent + uname -r. ARMING without a record stays the quiet
       `not-armed`. Both state tokens are pinned by the
       `TestPromoteScriptJournalMatchesGo` drift canary.
    6. Status: `ChannelStatus.UnconfirmedTrial` /
       `TrialClassificationErr`; the renderer names an unconfirmed
       trial in flight, refuses the known-good assumption on
       unclassifiable evidence, and grounds the ordinary-ARMING note
       in this boot's positive evidence instead of asserting the next
       boot is known-good from the state alone.
