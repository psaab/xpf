# Issue #11411: preserve selected-route MTU in the userspace FIB

The kernel/FRR route importer now carries `RTAX_MTU` from `netlink.Route.MTU` into the Go `RouteSnapshot` and Rust selected-route resolution. Snapshot protocol v38 fences helpers that would otherwise ignore the new constraint. Missing/zero MTU remains unknown and adds no constraint; negative snapshot values are rejected.

Plain forwarding and its flow-cache gate use the minimum known egress-interface and selected-route MTUs. Native GRE and WireGuard keep overlay and outer transport route MTUs separate: transport route MTU is combined with the physical interface MTU before tunnel overhead/padding is converted into an inner budget, and the encap guard and PTB path use the same outer-route resolution.

Regression coverage includes a 1450-byte IPv4 DF packet with interface MTU 1500: selected route MTU 1400 emits a Frag-Needed advertising 1400 and drops the original; with no route MTU the same packet forwards without a PTB. Go import/snapshot and Rust selected-FIB-resolution coverage also pin propagation and the zero/unknown case.
