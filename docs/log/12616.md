# #12616 — preserve terminal reset after failed retry

- **Action**: Keep a daemon fenced after a completed factory reset, even if a subsequent reset attempt fails.

## Red before

A successful `factoryReset` left `resetting` true, but the next failed invocation's `resetFailed` unconditionally called `exitResetGeneration` and resumed configstore archival/rescue writes. The new regression performed a successful wipe followed by a failed retry and observed `isResetting()` become false.

## Change

- Added a daemon-lifetime atomic latch set only after post-wipe verification and the reset handoff clean transition succeed.
- `resetFailed` now performs restoration, resumes feed-history/archive/rescue persistence, and clears the reset generation only if no invocation has already completed successfully. Failures before reset completion retain their existing recoverable behavior.
- Added regressions for successful-reset/failed-retry terminal retention (including archive and rescue fences), first-attempt failure followed by success, and first-attempt verification-failure recovery.

## Risk

The latch is per-Daemon and sticky only after the handoff is verified clean and `factoryReset` can report success. Earlier failures retain the existing cleanup/recovery behavior. Later failed retries preserve the terminal reset and persistence fences until process shutdown.
