# Issue #14319 — Inter-VRF leak precheck omits interface-NAT / anycast ownership and terminates on tunnel NoRoute

- **Issue:** psaab/xpf#14319 (deep-review D2-10, research-validated
  MATERIAL narrowed). Lane branch: `fix/14319-campaign` off
  `origin/master` `5b122dda5`.
- **Scope:** `userspace-dp/src/afxdp/forwarding/fib.rs` leak precheck /
  leak walk only, plus regression tests. No other consumer changes.

## Defect (present at base)

`table_has_v4_route` / `table_has_v6_route` (`fib.rs`) gate both the
inter-VRF leak walk and `leak_incarnation_for_resolution`, but they
admitted only ordinary routes, connected prefixes, and
`local_*_owned_by_table`. They omitted:

1. `interface_nat_tables_v4`/`v6` — yet `local_delivery_resolution_v[46]`
   honours interface-NAT ownership for leak-target walks
   (`include_interface_nat_owner`, gated on `!evaluate_leaks`). A leak
   target owning the destination *only* via interface-NAT therefore
   failed the precheck, the leak was skipped, return traffic to the NAT
   address misrouted out a fallback transit route, and no
   `leak_incarnation` was stamped.
2. IPv6 subnet-router anycast ownership (#10692) — the network address of
   a target-table connected prefix, which `local_delivery_resolution_v6`
   local-delivers via its else-arm. Same precheck rejection. (The lane
   notes marked this arm "NEG pending reading `local_v6_owned_by_table`";
   reading it confirms it checks only `local_v6` membership, so the
   anycast arm is real.)
3. Tunnel filtering: the precheck counted tunnel routes even when the
   caller passed `allow_tunnels == false`, and the leak loops
   (`lookup_forwarding_resolution_v[46]_inner`) returned the recursive
   result unconditionally. A target whose best/only route was a tunnel
   route thus resolved `NoRoute` inside the target and terminated the
   whole walk — blackholing outer tunnel endpoint resolution
   (`resolve_tunnel_outer` passes `allow_tunnels == false`) and causing
   false `noroute_policy_adjudication` drops, contradicting #9955's own
   contract that a target with no route "is a miss, not a terminal
   NoRoute" (that miss-continue logic existed only at the precheck).

`local_v4/v6_owned_by_table` do NOT already include interface-NAT
addresses: interface-build puts SNAT-excluded addresses into
`interface_nat_*` *instead of* `local_*` (`forwarding_build/interfaces.rs`),
so the omission is not moot.

## What

- `table_has_v4_route` / `table_has_v6_route` gain an `allow_tunnels: bool`
  parameter (per the issue's fix direction):
  - admit `interface_nat_tables_v[46]` ownership for the target table;
  - v6 also admits subnet-router-anycast ownership via a new
    `subnet_router_anycast_v6_owned_by_table` helper mirroring the
    #10692 else-arm (prefix-len `1..127`, `prefix.addr() == ip`,
    table-scoped);
  - a route entry counts only when `route_entry_usable_v[46]` — it has a
    non-tunnel next-hop, or no next-hops (connected marker, backed by the
    connected scan), or tunnels are allowed; connected rows count only
    when non-tunnel or tunnels are allowed.
- Leak loops pass the caller's `allow_tunnels` into the precheck and, if
  the recursive target lookup returns `ForwardingDisposition::NoRoute`,
  `continue` to the next leak / the source table's own LPM instead of
  returning it. Every other disposition (LocalDelivery, ForwardCandidate,
  MissingNeighbor, DiscardRoute, NextTableUnsupported, …) still returns
  immediately — fail-closed behaviour is preserved.
- `leak_incarnation_for_resolution` passes `allow_tunnels = true`: it has
  no tunnel-forbidding caller context, and provenance stamping must not
  turn tunnel-reached destinations unstamped (its own #9951 contract).
  It inherits the interface-NAT/anycast admission, so NAT/anycast-only
  leak targets now stamp their incarnation.
- NOT changed: single-table `allow_tunnels == false` → `NoRoute`
  semantics (#9955), `local_delivery_resolution_*`, route selection,
  tunnel resolution. No test-input special-casing.

## Risk

- The leak walk now does strictly more work only when a leak target
  resolves `NoRoute` (continues scanning); the common hit path is
  unchanged. Precheck scans remain linear over the same small vecs/maps
  as before, plus two map probes.
- Behaviour delta is confined to destinations that previously
  blackholed or misrouted: interface-NAT/anycast-only leak targets now
  local-deliver, and tunnel-forbidden leak walks fall through like
  kernel ip-rule misses. Fail-closed dispositions other than `NoRoute`
  remain terminal.
