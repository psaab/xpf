# #13658 — preserve the observed-vs-trimmed fairness contract

- **Base**: `5e8c92302` (`origin/master` at branch start)
- **Branch**: `fix/13658-observed-contract`

## Why

Issue #13658 identified a real split-view defect: Gate 2 reports the selected fail-closed `cstruct`, but the `cstruct-max` RSS expectation compared against `cstruct_raw`. The deliberate commit `66bd82e28` ("Preserve observed RSS expectation input") is also correct: distribution-based RSS expectations such as `max-worker-flow-share`, and report fields `n_active` / `max_worker_flow_share`, must describe actual RSS placement rather than a stale-count-normalized copy. The adjudication is therefore intentionally narrow: preserve observed distribution semantics, while making `cstruct-max` compare against the same selected Cstruct Gate 2 and the report expose.

For `[4,4,4,3,0,0]`, the stale-count correction selects `[3,3,3,3,0,0]` and Cstruct 0 for Gate 2, while actual maximum worker share remains 4/15. An RSS `cstruct-max:1%` must pass against reported Cstruct 0; `max-worker-flow-share:25%` must still fail against the observed 4/15. This reconciles the issue with the deliberate 66bd82e28 test instead of discarding either contract.

## What

- Pass the selected `cstruct` to `evaluate_rss_expectation`; keep the observed distribution input unchanged so only the `cstruct-max` leg uses the Gate-2 Cstruct while distribution-based RSS expectation legs retain observed data.
- Strengthened the existing observed-distribution black-box test to pin the exact `4/15` max-worker share and added a regression proving `cstruct-max` uses the selected Gate-2 Cstruct.
