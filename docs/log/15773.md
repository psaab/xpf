# #15773 — NAT `<rule-name>` selector silently ignored on both CLIs; remote CLI dropped NotInstalled/PortNoTranslation and hid unreferenced DNAT pools

- **Timestamp**: 2026-10-19
- **Verification (pre-fix)**: local `showNATSource(cfg, ["rule","r-disarmed"])`
  printed all 3 rules (`Total source NAT rules: 3`), destination printed both
  rules, unknown names returned nil error. Remote `handleShowNAT` sent
  `showNATRuleStats("")` / `showNATDNATRuleStats("")` regardless of `args[2]`,
  and its renderers never read `NotInstalled`/`NotInstalledReason` (fields
  exist on `NATRuleStats`, `NATDestInfo`, `NATPoolStats` since #7473).
  Confirmed limbs: (1) rule-name ignored — MATERIAL, both CLIs. (2) Remote
  NotInstalled/PortNoTranslation rendering — VERIFIED: proto carries
  NotInstalled, remote dropped it; PortNoTranslation had NO wire field, so a
  source rule's no-translation pool state was invisible remotely. (3)
  Unreferenced DNAT pools — VERIFIED defect, not intentional installed-only:
  remote summary/pool derived pools solely from rule rows
  (`GetNATDestinationResponse.rules`), so a configured pool referenced by no
  rule could not be named; local CLI iterates `dnat.Pools` and shows it.
- **Fix**:
  - Local (`pkg/cli/cli_show_nat.go`): `rule [<name>|all|detail]` dispatch for
    source+destination; `showNATSourceRuleAll`/`showNATDestinationRuleAll`
    take a name filter, count only matches, error `... NAT rule %q not found`
    on zero matches; source rows for armed `port no-translation` pools print
    `Port translation: no-translation (source port preserved)`.
  - Proto (additive): `GetNATRuleStatsRequest.rule` (3),
    `NATRuleStats.port_no_translation` (16),
    `GetNATDestinationResponse.pools` (4, new `NATDestPoolInfo`). Regenerated
    via `make proto`.
  - Server (`pkg/grpcapi/server_nat.go`): honours `req.Rule` in both
    families, sets `PortNoTranslation` from the referenced source pool,
    populates `resp.Pools` from every configured destination pool.
  - Remote (`cmd/cli/show_nat.go`): parses `rule <name>`, sends it on the
    wire AND filters client-side (older daemon ignoring the field cannot
    silently widen), errors on unmatched name; renders NotInstalled in rule,
    default, summary and pool views, `no-translation` line for source rules;
    destination summary/pool seed from `resp.Pools` so unreferenced pools
    appear (named-pool lookup for an unreferenced pool now succeeds).
  - cmdtree: `rule` gains `all` + `<name>` (DynamicFn over configured rule
    names) children for completion parity.
- **Regression**: `pkg/cli/cli_show_nat_rulename_15773_test.go`,
  `cmd/cli/show_nat_rulename_15773_test.go`,
  `pkg/grpcapi/nat_rule_filter_15773_test.go` — ≥2-rule fixtures including a
  disarmed (empty/addressless pool) rule and a `port no-translation` rule;
  RED on pre-fix (all rules printed, unknown name nil error, remote request
  carried no rule), GREEN after. Bare/`all` listings asserted unchanged.
- **Validation**: `go vet` clean on touched packages; targeted + neighboring
  suites run (see PR).
- **Risk**: additive proto only (old peers decode new fields as zero/empty;
  remote client-side filter keeps the selector honest against old daemons).
  A rule literally named `all`/`detail` is shadowed by those keywords —
  pre-existing `detail` shadowing, extended to `all` matching Junos.
