# Issue #18858 — record bounded liveness cadence multiplies

- **Timestamp**: 2026-11-05
  - **Action**: Pinned duration-census verdict site counts and added gain/loss discrimination controls
  - **File(s)**: pkg/durationaudit/duration_overflow_census_8642_test.go, docs/log/18858.md

## Why

The primary-liveness sweep cadence from `0cd8e58d0b` (#17900) is runtime
state, not a raw config duration. Its two `time.Second` multiplies in
`pkg/cluster/sync_conn_sweep.go` use scan seconds bounded to [1,10]: the
per-session timeout helper clamps to that range, while the initial value is 1
and the enumerated minimum is the minimum of clamped session values, 10, and
pending values that are themselves clamped or initial. The duration census
cannot infer this end-to-end provenance from the multiply sites alone.

## What

- Recorded `pkg/cluster/sync_conn_sweep.go` in the census's `knownUnbounded`
  verdict map, explaining the [1,10] bound and CAS-min wake behavior for both
  reported multiplies; pinned the 2 sites in `StartSyncSweep` and
  `capSweepIntervalForLiveness`.
- Pinned exact unbounded site counts for every existing census verdict,
  including zero-site files, with synthetic gain/loss discrimination checks.
- No production code or runtime behavior changed.
