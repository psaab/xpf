# #18610 — an RG0 primary that refused a peer push stays "standby config stale"

- **Timestamp**: 2026-10-31 05:05 PDT
- **Action**: Root cause from the loss journals (fw0, 0.0.26312). fw0 became
  RG0 primary at 10:45:10 with applied gen ...851. At 10:46:46 fw1, which
  briefly believed itself primary after a false peer-loss, pushed gen ...853.
  fw0 logged `rejecting config sync (this node is RG0 primary)` and nacked.
  The receive edge had raised the received mark to ...853 (#5563); the
  refusal kept applied at ...851 (M-2/#4151) and armed the #6387 CF grace.
  `ConfigStale()` (received > applied) stayed true while fw0 stayed primary,
  so every local RG read `Transfer ready: no (standby config stale ...)`,
  node0 carried `CF`, and `xpfd upgrade --rolling` aborted twice with "peer
  is NOT takeover-ready". It cleared only at 10:58:30, during the later
  mixed-version soak (fw0 still on 0.0.26312, fw1 already on 0.0.26314), when
  fw0 was briefly secondary and applied fw1's config. The restart "already
  matches" skip path, first suspected, is not involved: it returns nil and the
  applied mark advances.
- **Dedup**: closed siblings #4151, #7328, #6387, #9569, #6908 and #6778. #4151
  pinned the high-water on the premise that this node will settle into
  secondary and receive the peer's re-push; that premise fails when this node
  wins the dual-active and stays primary.
- **Action**: Fix. `cluster.ErrConfigSyncRejectedAuthority` (the daemon's
  `errConfigSyncRejectedPrimary` is now that sentinel). On it,
  `configApplyLoop` records `rejectedAsAuthorityConfigGen` instead of arming
  CF, still nacks, and still pins the applied mark. `ConfigStale` ignores
  received generations up to that mark while `IsPrimaryFn()` is true (sampled
  into the snapshot as `LocalConfigAuthority`). `resetRecvGen` clears it.
- **Tests**: `pkg/cluster/sync_config_authority_stale_18610_test.go`, all
  driving the real `configApplyLoop`:
  - the defect cell (primary refuses, then is not stale, has no CF streak,
    keeps the applied mark and eligibility; after demotion it is stale again);
  - the twin (an ordinary failure on a primary or a standby still arms CF and
    reads stale);
  - the restart cell (a restarted standby with an identical config, i.e. the
    nil skip path, is transfer-ready);
  - the namespace reset.

  Daemon: `TestRG0PrimaryRefusalIsTheClusterAuthoritySentinel18610`.
