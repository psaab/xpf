# #15260 — test-harness: bind symmetric CoS reverse leg to reth1 and guard base+overlay (A92-02)

- **Timestamp**: 2026-10-19 (`fix/15260-campaign`, base `52955165ac`)
- **File(s)**: `test/incus/cos-iperf-symmetric.set`,
  `test/incus/apply-cos-config.sh`,
  `pkg/config/parser_class_of_service_test.go`,
  `pkg/configstore/cos_fixture_overlay_15260_test.go` (new)

## Why

`cos-iperf-symmetric.set` bound its reverse shaper/filter to the
dash-form `ge-0-0-1`. The documented lab base
(`docs/ha-cluster-userspace.conf:23-25`) authors `ge-0/0/1` as the
reth1 member on node0, and `LinuxIfName` folds both spellings onto
the same kernel device, so the #5832 strict ifname-collision gate
rejects every `--symmetric` commit-check on node0 — every symmetric
CoS cell was dead. The Go guard
(`TestCoSIperfSymmetricFixtureCompilesReverseSourcePortOutputFilter`)
compiled the fixture on an empty tree, so it stayed green and read
as protection. Measured on base: base+overlay `CompileConfigForNode`
node0 fails with the #5832 collision; node1 compiles (its member is
`ge-7/0/1`).

## What

- Fixture: reverse CoS shaper, reverse output-filter bindings, and
  the fixture's own delete lines now target `reth1 unit 0` — the LAN
  RETH that actually egresses reverse traffic (member `ge-0/0/1` on
  node0, `ge-7/0/1` on node1). Header comment records the collision
  rationale. Forward leg (`reth0.80`) untouched.
- `apply-cos-config.sh`: both delete preambles now delete the
  `reth1 unit 0` reverse bindings (and keep the legacy `ge-0-0-1`
  deletes so a config applied by the old fixture is still cleaned
  up idempotently; deleting a non-existent path is swallowed inside
  the candidate session by design).
- Guards: new `pkg/configstore/cos_fixture_overlay_15260_test.go`
  compiles base+overlay through the real strict commit pipeline
  (`compileTreeStrict`: schema gate + strict compile incl. peer
  views) for nodes 0 and 1 — `TestA92Overlay` — and pins the reverse
  binding on `reth1.0` with the forward leg as control. Neighbour
  fixtures (`cos-iperf-config.set`, `cos-iperf-same-class.set`) get
  the same base+overlay treatment as named controls. The empty-tree
  guard in `pkg/config` is rebound to `reth1` and explicitly
  demoted to fixture-internal wiring, not the commit guard.

## Validation

- RED (pre-fix fixture, new guard): `TestA92OverlaySymmetricFixtureOnLabBase15260`
  fails node0 with the exact #5832 collision error above.
- GREEN (post-fix): `go test ./pkg/configstore/ -run TestA92Overlay`
  passes (symmetric + both neighbour fixtures, nodes 0 and 1).
- `python3 -m unittest discover -s test/incus -p cos_port_grid_test.py`:
  8 tests OK. `bash -n test/incus/apply-cos-config.sh` OK.
- Pre-existing, not introduced: the empty-tree
  `TestCoSIperfSymmetricFixtureCompilesReverseSourcePortOutputFilter`
  is red on current master because the #15034 untagged-unit gate
  rejects the fixture's `reth0 unit 80` without the base's
  `vlan-tagging`/`vlan-id 80` — recorded on the issue; it passes
  only in the base+overlay composition this issue makes the guard.

## Risk

- Reverse CoS counters/shaping now attach to `reth1.0` instead of
  the (uncommittable) `ge-0-0-1.0`; harnesses keying on ifindex
  (`COS_IFINDEX`) are unaffected. Lab `--symmetric` applies need a
  one-time re-apply; the kept legacy deletes make that idempotent.
- The #15034 empty-tree red of the old guard remains until that
  fixture-composition question is dispositioned separately.
