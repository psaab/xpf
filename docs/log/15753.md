# Issue #15753 — TCP-session fidelity knobs (G29-03, G29-04)

## Defect
- `rst-sequence-check`/`maximum-window`/`time-wait-state` rejected by closed-world schema; `SessionEntry` tracked no seq/window, so blind off-path RST/FIN (seq=0) on admitted 5-tuple closed/demoted live session.
- `rst-invalidate-session` + `no-syn-check-in-tunnel` compiled (`types_security.go:352-353`, compiler 711-715) but dropped by `buildFlowSnapshot`; Rust `should_teardown_tcp_rst` hardcoded `false`; tunnel mid-stream TCP dropped. Warned-but-inert in `compiler_validate_warn.go`.

## Fix
- Go: schema+compiler for `rst-sequence-check`, `maximum-window`, `time-wait-state{session-timeout,session-ageout,apply-to-half-closed-state}`; `TCPSessionConfig` fields; `buildFlowSnapshot` threads `TCPNoSynCheckInTunnel/TCPRstInvalidate/TCPNoSequenceCheck/TCPRstSequenceCheck/TCPMaximumWindow` (+ time-wait-state timeout override); ProtocolVersion 58→59 (Rust lockstep); removed #2078 accepted-only warnings for these knobs.
- Rust: `FlowSnapshot`/`ForwardingState` carry knobs; `SessionEntry.tcp_rcv_nxt/tcp_rcv_wnd/tcp_seq_seen` + `note_tcp_seq`/`tcp_closing_seq_verdict` (wrapping serial arithmetic); poll slow path drops Invalid blind RST/FIN (before resolve mutates close) and notes seq, unless `no-sequence-check`; `strict_syn_check_drops_new_flow_tunnel` admits tunnel-decapped (`TUNNEL_DECAP_INGRESS_FLAG`) mid-stream ACK when `no-syn-check-in-tunnel`, strict overrides; `should_teardown_tcp_rst_with(forwarding.tcp_rst_invalidate_session)` — default OFF explicitly (HA stray-RST rationale in tx_cancel.rs retained, diverging from Junos default-on by documented decision).
- Flow-cache fast path (`probe_hit`) does not stamp close, so blind RST via cache cannot close; seq gate is on slow path.
