# #14634 — Sub-byte `flexible-match-range` takes the low bits of the byte window

## Defect

Junos `flexible-match-range`: `byte-offset` counts from match-start and
`bit-offset` (0..7, in-tree always the implicit 0 — there is no `bit-offset`
leaf in the schema) is the bit offset after that byte, so the field occupies
MSB-first bits from `byte-offset`. A `bit-length 4` field at `byte-offset 0`
is therefore the HIGH nibble of the first byte (e.g. the IPv4 version nibble
of `0x45` is 4, the IHL nibble is 5).

Every enforcement boundary instead right-aligned the field pair into the
ceil-byte window:

- `pkg/config/compiler_firewall.go` defaulted the mask to `(1<<bits)-1`
  (low bits) and stored the operator value field-aligned.
- `pkg/dataplane/userspace/filters.go` passed `Value & Mask` / `Mask`
  verbatim onto the wire; the Rust matcher
  (`userspace-dp/src/filter/engine/matching.rs` `flex_matches`) reads the
  window big-endian and compares `(val & mask) == value`, i.e. the LOW bits
  of the last window byte.
- The lo0 nft mirrors (`pkg/daemon/daemon_nft.go` `nftFlexMatchExpr`,
  `pkg/nftables/netlink_build.go` `flexMatchExprs`) rendered the same
  right-aligned pair (the netlink builder additionally truncates the
  big-endian pair to its low bytes).

Witness (executed pre-fix): `bit-length 4 range 0x4` compiled to
`{Offset:0 Length:1 Value:4 Mask:15}`; on wire byte `0x45` the version
nibble (4) missed and the IHL nibble (5) was what a `range 0x5` term
matched. An explicit Junos `match-mask 0xf` produced the identical wrong
snapshot (only a pre-shifted non-Junos mask `0xf0` avoided it). A clean
commit evaluated the wrong bits, so a discard term failed open and its
counter silently reflected the wrong field.

## Fix

Alignment is applied at each matcher boundary, shifting the field pair
left by `windowBits - bitLength` (`windowBits = ceil(bits/8)*8`), so the
pair occupies the TOP bits of the window the matcher actually reads:

- `pkg/dataplane/userspace/filters.go` (`buildFilterTermSnapshots`):
  emits `Value = (Value & Mask) << shift`, `Mask = Mask << shift`.
  Byte-aligned lengths shift by 0 (wire byte-identical); `BitLength 0`
  keeps the 32-bit default (shift 0); oversized widths keep the #3406
  uncapped-length behaviour.
- `pkg/daemon/daemon_nft.go` (`nftFlexMatchExpr`): same shift before the
  existing window truncation; renders `@nh,0,8 & 0xf0 == 0x40` for the
  4-bit case.
- `pkg/nftables/netlink_build.go` (`flexMatchExprs`): same shift before
  the big-endian low-byte truncation.
- `pkg/config/compiler_firewall.go`: comment only — the stored
  `FlexMatchConfig` pair stays field-aligned (authored value preserved
  for `show`/forensics); alignment is a boundary concern, so no consumer
  can double-shift.

The Rust matcher is unchanged: it already compares the full window, and
now receives the aligned pair. Its one stale fixture
(`flex_match_non_byte_aligned_12bit_field`, which pinned the
right-aligned `0x0ABC/0x0FFF` lowering) now uses the aligned
`0xABC0/0xFFF0` pair with hit/miss bytes in the TOP 12 bits.

NOT changed: `bit-offset` support (no such leaf exists in the schema
today; inside a range it is recorded on `UnknownFlexMatch` by the #14347
machinery and strict-rejected — implementing a non-zero bit offset is a
separate feature, and this issue owns alignment at the implicit
bit-offset 0 only), the retired eBPF compiler
(`pkg/dataplane/compiler_filter.go`, documented non-enforcement), and
any byte-aligned behaviour.
