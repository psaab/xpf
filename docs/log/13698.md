# Issue #13698 — align NAT64 MTU preflight with fragment translation

## Why

`v6_to_v4_output_len` is used by the AF_XDP NAT64 egress MTU decision before
building the translated packet. Its non-first fragment branch returned a
positive output length for fragmented ICMPv6, although the actual non-first
translator rejects ICMPv6 because its checksum spans the entire datagram.
That branch also computed the output length from the IPv6 header's declared
payload size without checking that the captured packet contained those bytes.
As a result, malformed or untranslatable fragments could be classified as
oversize and trigger an unsolicited ICMPv6 Packet Too Big response.

## What

The length-only preflight obtains the bounded L4 payload slice before its
non-first-fragment return, rejecting truncation, and accepts only TCP/UDP for
non-first fragments to match `write_v6_to_v4_nonfirst_into`. Regression tests
pin the ICMPv6 and truncated-fragment failures and retain an intact UDP
non-first-fragment positive control.

The egress MTU path also avoids falling back to generic IPv6 PTB logic for a
fragment that the NAT64 translator cannot handle; this prevents a rejected
fragment from generating an unrelated MTU response.

## Validation

- `cargo test --quiet --manifest-path userspace-dp/Cargo.toml --bin
  xpf-userspace-dp nat64_v6_to_v4_output_len_`: 4 passed. Reverting the
  fix made the ICMPv6 and truncated-UDP regressions fail with `Some(28)`
  and `Some(2012)` instead of `None`.
- `cargo test --quiet --manifest-path userspace-dp/Cargo.toml --bin
  xpf-userspace-dp nat64_`: 275 passed.
- Full binary suite: 8033 passed, 4 failed, 8 ignored. Each unrelated
  failure reproduced on baseline `1aea24f7b`: the parked-overlap test
  (0/1), the `gre_decap_` selection (48 passed, 2 failed), and the
  session-authority test (0/1). The GRE failures were
  `gre_decap_inner_icmp_echo_denied_by_host_inbound_reads_inner_type`
  and `gre_decap_session_hit_host_inbound_reads_inner_icmp_type_5615`.

## Risk

Malformed and fragmented ICMPv6 NAT64 packets now fail MTU preflight with
`None`, matching the existing translator's fail-closed behavior; no valid
TCP/UDP fragment behavior changes.
