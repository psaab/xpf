## The defect, measured live on base `363c21dc2`

`parse_l2` unwraps exactly ONE 0x8100/0x88a8 tag, so a double-tagged
frame leaves the inner TPID as `eth_proto`, which takes the non-IP arm
(`pass_non_ip_l2_direct` = XDP_PASS) above the ingress gate. Ran all five
QinQ shapes (8100/8100, 88a8/8100, 8100/88a8, 8100/9100, 9100-outer)
through the base object via BPF_PROG_TEST_RUN on a bound port: every one
returned XDP_PASS(2) with NO reason counter firing — the silent
unadjudicated handoff, armed and degraded alike (degraded: ret=2 with
ctrl_disabled + pass_to_kernel). The #5879 gate refuses QinQ configs, not
frames, and the nft transit barrier is unarmed-window-only by design, so
on a bridged port the kernel forwards by MAC with no zone policy.

## Drop-and-count is the forced arm, not a policy choice

Adjudication is impossible: #5879 refuses QinQ configs, so the dataplane
has no stacked-VLAN identity to steer a double tag by, and #2354 (real
QinQ transit) is out of scope. The fix is therefore an explicit
XDP_DROP with a dedicated `qinq_drop` counter — never the silent PASS
for frames with a complete L2 header. (A runt truncating inside the
tag takes `parse_l2`'s `None` path and carries no L3 payload, so no
transit rides that shape — out of contract, stated rather than
implied.) No unwrap loop: the predicate tests the POST-unwrap
ethertype against the three TPIDs (an 8100/88a8 there is provably an
inner tag since `parse_l2` already unwrapped any outer one; 9100 is
never unwrapped), three flat compares keeping verifier cost unchanged
in shape (measured: 565,984 processed insns, 43.40% headroom, floor
satisfied).

## A dedicated reason, appended — the 8258 workflow working as designed

Reusing PARSE_FAIL would mislabel a well-formed frame and conflate QinQ
policy drops with malformed-IP drops at the operator surface the 8258
agreement exists to protect. So `QINQ_DROP` is appended at index 16
(MAX 16→17, never inserted — no renumbering), the Go table carries
`qinq_drop` at 16, and the cap/agreement guards move 16→17 with their
prose. The Rust debug-log reader (`pin.rs`) is the THIRD copy of this
index and gets the same treatment: reason appended, coverage test
moved, plus a Rust-side shim↔table agreement test so the next append
enrols there automatically too. The disposable-map reconcile already
resets on a MaxEntries change, so the upgrade path drops counters, not
the load. The stale prose this renumbers (8258 failure-mode example,
eleven→twelve) is updated in the same change.

## The invariant is total across all three non-IP arms

The armed guard, its unreachable-by-construction match twin (whose
comment promises the SAME action as the guard — now including the drop,
so a future guard-weakening cannot silently re-PASS QinQ), and the
degraded-path arm all drop nested-VLAN. Degraded coverage matters for
the doc claim: with only the armed arm fixed, "the shim drops
double-tagged frames" would still be false in the degraded window.
Honest cost statement (parent review caught the first draft claiming
QinQ "is not ARP/LLDP", which is false for a 0x9100 outer hiding L2
the shim never unwraps): dropping single-0x9100 denies the kernel
that L2 on XDP-bound ports. Fail-closed on an opaque, unconfigurable
shape — defensible, disclosed in the code, the test header, and here.
