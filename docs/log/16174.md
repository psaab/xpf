# #16174 - routing: share the clear-rules skeleton between the two true twins only

- **Timestamp**: 2026-10-21
- **Root fix**: `nextTableManager.clear` and `ribGroupManager.clear` in
  `pkg/routing/rules.go` repeated the same 50-line skeleton (walk
  AF_INET/AF_INET6, `RuleList` per family, delete predicate-matched
  rules, swallow ENOENT, aggregate real failures with `errors.Join`).
  The #5118 "aggregate real RuleDel failures" fix had to be applied and
  re-justified three times because of this duplication. They now both
  delegate to `clearMatchingRules(ops, kind, match)`, keeping their own
  ownership predicates and kind strings (`next-table` / `rib-group`),
  from which the list/delete error text and log messages are formed, so
  error strings, `errors.Join` order, and per-family behavior are
  unchanged.
- **Explicitly not genericized**: `pbrManager.clear` (retries a delete
  under the other rule action on ENOENT — different failure semantics)
  and `probePinManager.clear` (Debug-only per-item deletes) stay
  bespoke, byte-untouched. No priority constants move; band asserts
  stay.
- **Regression**: new `rules_clear_skeleton_16174_test.go` parameterises
  the skeleton once (list-error aggregated with the other family still
  walked, both-family list errors in family order, ENOENT swallowed,
  real delete errors aggregated in walk order with exact text,
  non-matching rules never attempted, mixed partial delete). RED
  evidence (mutants on the skeleton): dropping the delete aggregation,
  dropping the ENOENT carve-out, and dropping the list-error
  aggregation each fail the new tests plus the pre-existing
  `TestNextTableRibGroupClear*` / `TestRulesClearListErrorSurfaced`
  guards. Mutating PBR's ENOENT second-action retry fails
  `TestPBRClearFallsBackToLegacyLookupAction`, proving it remains a
  distinct bespoke path.
- **Validation**: `go test ./pkg/routing/ -count=1` green (full
  package, including all `rules_*_test.go`, `probe_pin*_test.go`, and
  `rib_family_main_11395_test.go`); `go vet ./pkg/routing/` clean;
  `gofmt` clean.
- **Perf impact**: None. Cold config-apply path only; the skeleton adds
  one predicate closure call per listed rule during clear, no
  allocations or dataplane/hot-path changes.
- **Risk**: Log/error strings are byte-identical by construction (kind
  string substitution reproduces the previous literals, pinned by the
  new table's exact-text assertions and the existing Apply-level
  tests). Residual: none known.
