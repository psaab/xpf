# Issue #14197 — DNAT pool duplicate `address` statements silently overwrite / clear invalid marker

- **Issue:** Within one DNAT pool, a second `address` statement overwrote `pool.Address` and cleared a prior multi-token `AddressInvalidSpec` (`compiler_nat_destination.go` `parseDNATPoolAddress`), so `pool p1 { address 10.1.0.1 to 10.1.0.9; address 10.2.0.1; }` committed clean to the later backend and `address 10.0.0.1; address 10.0.0.2;` silently kept only the last host. No gate existed. Research gate: codex=NEG (pinned #10289 replacement), opus=MATERIAL-narrowed, spark=COHORT (reject >1 address statement per pool). Decisive fixture executed: on base, hierarchical duplicates compile clean (invalid-then-valid and valid-then-valid).
- **Contract decision:** Spark's bounded fix. A DNAT pool is a single-host wire field; two DISTINCT `address` statements are rejected at strict commit and excluded (fail-closed, not last-wins) on the tolerant path. This supersedes the intra-pool half of #10289's "later valid address clears range marker" pin: at compile time flat-set sequences and hierarchical duplicates are indistinguishable (both arrive as successive `address` leaves under one `pool p1` node; `address` is `multi: true`, and groupReplace governs only apply-groups merge), so no shape-based split exists. Identical repeated statements (a `load merge` re-stating the same pool/address) collapse to one effective statement and are not duplicates. Port-only statements (`address port <N>`) carry no address and neither count nor clear markers (#10289 port half unchanged).
- **What:** `NATPool.DuplicateAddressStatements` (`json:"-"`, `types_security.go`); `parseDNATPoolAddress` records every address-bearing statement and joins distinct repeats; `mergeDNATPoolAddressStatements` folds repeated pool blocks (identical restatement exempt); `validateDNATPoolStrict` rejects duplicates before the single-host checks; `DestinationNATRuleExcludedReason` excludes duplicate pools on the tolerant path (strict gate downgrades to a warning there, snapshot builder fails closed via the exclusion). NOT changed: single-statement range/bracket rejection (#10289), port handling, source-NAT pools (multi-address by design).
- **Regression:** `TestDNATPoolDuplicateAddressStatements14197` (invalid-then-valid / valid-then-valid / valid-then-invalid hierarchical: strict rejects, lenient warns + excluded), `TestDNATPoolSingleAddressPlusPortOnlyNotDuplicate14197`; #10289 cells updated: flat override cell now expects duplicate rejection, repeated-block cell now expects the recorded duplicate + strict rejection.
