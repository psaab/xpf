# #13725 — FullResync barriers must not retire behind an older scan

- **Base**: `origin/master` `07eeae9ed`
- **Files**: `pkg/dataplane/userspace/eventstream.go`,
  `pkg/dataplane/userspace/eventstream_fullresync_9630_test.go`,
  `pkg/dataplane/userspace/eventstream_fullresync_13725_test.go`

## Why

`ExportOwnerRGSessionsPaged` scans session shards incrementally rather than as
an atomic snapshot. A FullResync barrier arriving while a worker is running can
refer to drops in shards already visited by that worker. Treating the new
barrier as covered by the old worker can retire its sequence and cumulatively
ACK it without a post-barrier export, permanently losing sessions on the HA
peer.

## What

Each FullResync barrier now remains in FIFO order and starts its own worker
export. The reader still drains the helper stream while a worker runs, and the
barrier advances the applied/ACK watermark only after its export succeeds.
Removed the old coalesced-marker state and its eager retirement/failure-reset
paths. Added regressions for a barrier arriving during an in-flight scan and
for retrying failed barriers; updated the existing #9630 tests to assert one
export per barrier, including barriers queued before callback registration.

## Risk

Repeated barriers now each perform an export instead of sharing a scan. This
spends more export work during bursts, but preserves the snapshot/barrier
contract and prevents acknowledging a post-drop barrier before its own scan.
