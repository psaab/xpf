# #13526 — per-issue acceptance for missing-neighbor forwarding

- **Issue**: #13526 — ensure fragment/session admission side effects are handled when forwarding is parked for neighbor resolution.
- **Branch**: `fix/13526-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-13526`

## Why

A first fragment accepted into the missing-neighbor seed path commits its session before the neighbor is resolved, but that path did not publish the fragment association. Subsequent fragments therefore could not use the accepted session decision while neighbor resolution was pending. The path also refused new SYN seeds at capacity instead of applying the existing TCP-opening pressure-shed policy used by the regular forward-candidate admission path.

## What

- Install an eligible same-family/plain or same-family address-rewrite fragment association only after a missing-neighbor seed session is successfully committed. The association records the session identity and uses no resolved neighbor MAC.
- Apply existing TCP opening pressure shedding before refusing a missing-neighbor seed, including the normal session/BPF/NAT cleanup and replication behavior.
- Add regressions for first-fragment association publication and SYN admission via pressure shedding.

## Validation

- Pristine-master red comparison: both regressions failed independently at the expected assertions: fragment association length was 0, and the incomplete TCP opening was not pressure-shed before seed refusal.
- After the implementation, `cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp afxdp::tests_fragment:: -- --nocapture` passed (36 tests).

## Risk

NAT64 missing-neighbor refusal remains unchanged. The seed path only invokes the existing TCP SYN/opening pressure-shed policy; it does not add a new idle-session expiry/reaping mechanism.
