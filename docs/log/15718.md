# Issue #15718: Node.Annotation erased across format/load/sync surfaces

- **Timestamp**: 2026-10-19
- **Problem**: `Node.Annotation` (`/* comment */`, set via `annotate <path> "<comment>"`) was dropped or rejected by most round-trip surfaces: `FormatCompare`/`nodesEqual` ignored it (annotation-only change showed `[no changes]` while the store stayed dirty and `CommitDiffSummary` recorded nothing), `FormatSet`/`FormatPathSet`/`FormatSetForLoadMerge` never emitted `annotate` lines, flat `load set`/`load merge`/`load override` rejected `annotate` lines (`IsFlatLoadLine`/`applyEditLine` had no annotate verb), the hierarchical parser discarded `/* ... */` comments in the lexer gap scanner (so `LoadMerge`, `loadRollbackHistory`, `LoadRescue`, and HA `SyncApply` — all `Format()` → `NewParser` round trips — silently erased annotations), and `FormatPath`/`FormatPathInheritance` omitted the matched root node's own annotation.
- **Fix (parser)**: `pkg/config/lexer.go` now records the normalized text of block comments skipped in a gap (`pendingComment`, exposed via `LastGapComment()`, surviving `Peek` like `LastGapLoss`), and `parseStatement` attaches it as `Node.Annotation`. This single change preserves annotations across rollback files, rescue config, and HA sync, which all persist via `Format()` and re-parse.
- **Fix (compare)**: `nodesEqual` compares `Annotation`; `diffNodes` no longer recurses past an annotation change, renders `- /* old */` / `+ /* new */` via `formatAnnotationChange`, shows unchanged annotations collapsed, and `formatPrefixed` emits the annotation line on added/removed nodes.
- **Fix (display set)**: `formatSetNodesMode` and `FormatPathSet` emit `annotate <path> "<escaped>"` (via `EscapedAnnotation`, using the symmetric `keyEscaper`) after the node's `set` lines and before any `deactivate` line.
- **Fix (flat load)**: `IsFlatLoadLine` accepts `annotate` only with a trailing quoted comment (so the #10305 hierarchical trigger body `annotate system host-name "x";` + braces still routes hierarchical), and `applyEditLine` splits annotate lines with `ParseAnnotateCommand`, validates with `ValidateAnnotationText`, and applies `AnnotatePath` (now wrapping `ErrPathNotFound` so failures scrub to "path not found"). `LoadMerge`/`parseOverrideContent` hierarchical branches parse the raw body instead of the classifier's comment-stripped text so annotations survive; gate/store agreement is kept because `LoadMutationLines` renders the same leaf paths (plus annotate lines from `FormatSet`).
- **Fix (path display)**: `FormatPath` and `FormatPathInheritanceForNode` render the matched root node's `/* annotation */` line.
- **Tests updated**: `TestLoadFlatVerbGate` (annotate is now replayable, removed from the rejection list) and the #10305/#9892 verb-classification comment (annotate without a quoted comment still does not classify flat).
