## Premise measured before designing

| config | strict commit | defined | snapshots | unresolvedRefs | statusLines |
|---|---|---|---|---|---|
| `ids-option p alarm-without-drop` + zone ref | **accepted, no warning** | yes | **0** | **0** | **0** |
| zone ref with no profile | **REJECTED** | — | — | — | — |
| `ids-option p tcp land` + zone ref | accepted | yes | 1 | 0 | 0 |

Row 1 and row 3 are identical on every operator surface. Row 2 — the case the
shipped surfaces DO cover — is strict-rejected, so it is reachable only through
the tolerant paths. The uncovered state is the more reachable one.

## A hypothesis that measurement KILLED

The emit gate omits the syn-flood sub-thresholds (alarm/source/destination/
timeout), so a profile configured only with `syn-flood timeout 30` looked like it
would publish nothing while #3527 says the timeout is enforced — a runtime hole,
not just a reporting one. Measured instead of filed: the compiler defaults
`AttackThreshold` to 200 whenever ANY syn-flood leaf is set, so
`SYNFloodThreshold > 0` already covers every syn-flood shape and one snapshot is
published. No gap. `SYNCookie` is likewise correctly excluded — it reads a GLOBAL
flow setting, not a per-profile check. Both findings are recorded in
`enforcesAnyCheck`'s doc block so the next reader does not re-derive them.

## Design decisions

- **A distinct surface, not a widened one.** `xpf_screen_unresolved_profile_zones`'
  HELP says "not defined"; a zone in the new state resolves to a profile that IS
  defined. Folding them would make a shipped series' documented meaning false and
  silently change what existing alerts match.
- **The predicate asks the publisher.** `ScreenInertProfileRefs` derives from
  `buildScreenSnapshots`' actual output rather than re-deriving the emit gate.
  A copy of the gate could drift from the dataplane; a call to the publisher
  cannot. The gate was also extracted to `enforcesAnyCheck` so the publish
  decision has one name.
- **The shared half of the disposition is single-sourced.** Writing the second
  disposition as a full sentence reddened `TestScreenUnresolvedDispositionHasOneSource`
  — that guard working as designed. Fixed by sharing `screenNoEnforcementTail`,
  not by weakening the count.
- **The ordering helper's block name is parameterised**, so the inert caller does
  not report an "unresolved-reference" violation; a diagnostic naming the wrong
  condition sends the reader to the wrong code.

## Deliberately out of scope

The dataplane's runtime WARN still says "references undefined screen profile",
which would be factually WRONG for this state, so it is not extended here.
Correcting it needs a new wire field plus its skew test (mirroring
`screen_missing_profile_zones`). Stated in `docs/feature-coverage.md` rather than
left implicit.

## Red at the pre-fix behaviour

With the predicate forced empty, the three-state table reds on the MIDDLE row
only — the undefined and enforcing rows still pass, which is what makes the
middle row load-bearing. Removing just the two narrow-renderer emit blocks reds
both #7060 tests.
