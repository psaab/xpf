# #9698 — userspace: the helper-status binding index multiplies the helper-supplied ifindex in uint32 before the cap check

- **Timestamp**: 2026-09-10
  - **Action**: Bounded the ifindex dimension before the multiply at both
    helper-status sites, the issue's first fix direction.
    - `bindingIfindexInRange` (pkg/dataplane/userspace/binding_index_bounds_9698.go) admits
      `[1, MaxInterfaces)`. It compares in int64, so it catches the uint32
      wrap of `ifindex*16` at 2^28 and above, and also the truncation in
      `uint32(ifindex)` at 2^32 and above. The issue did not name the
      truncation; this bound catches it too.
    - Apply site (`applyPrimaryBindingRowsLocked`,
      pkg/dataplane/userspace/helper_status_apply.go): fails closed before
      the multiply. The message keeps "exceeds cap" and "MAX_INTERFACES",
      which the existing #814 cell asserts for MaxInterfaces+7, a value the
      new bound now catches first, and adds #9698.
    - Watchdog site: the per-binding decision of `verifyBindingsMapLocked`
      moved, unchanged, into `watchdogBindingIndex`: the #1666 liveness skip,
      the #4894 queue bound, the new #9698 bound, and the #814 cap. The
      watchdog logs and skips; it never unwinds.
  - **Action**: Why the extraction. The two existing #814 cells,
    TestApplyHelperStatusRejectsOverCapIfindex and
    TestVerifyBindingsWatchdogSkipsOverCapIfindex, need real BPF maps. In an
    unprivileged run they SKIP ("RemoveMemlock: operation not permitted").
    Measured here: neither ran. The watchdog reads its map as a concrete
    `*ebpf.Map`, so no fake can stand in. Making the decision a pure function
    is what lets the watchdog half of the acceptance run in `make test`.
  - **Action**: Cells, in pkg/dataplane/userspace/binding_ifindex_bound_9698_test.go.
    - The predicate table: 1, 2 and MaxInterfaces-1 are admitted; 0, -1,
      MaxInterfaces, 2^28+2 and 2^32+2 are refused.
    - Apply site: 2^28+2 and 2^32+2 (queue 3) are refused with NO row written,
      including row 35, which they would have aliased. Controls: MaxInterfaces
      is still refused with "exceeds cap" and "MAX_INTERFACES", and ifindex 2
      queue 3 is accepted and written at row 35.
    - Watchdog site: the same wrapping values and MaxInterfaces are skipped,
      and ifindex 2 queue 3 yields 35. The #4894 queue skip and the #1666
      liveness skip still hold in the extracted decision.
  - **Action**: Docs. No module doc describes the binding-index guards
    beyond the code comments, which now carry the #9698 bound, so no doc
    change is needed.
