# #17255 — Remove unused YAML redaction mirrors from config types

- **Why**: Config-specific YAML redaction methods have no production encoder or decoder and cover only some JSON redactors. The duplicate SNMP YAML projection also required manual synchronization with the JSON projection.
- **What**: Delete `SNMPConfig`, `SNMPCommunity`, `SNMPTrapGroup`, and `PKICAProfile` `MarshalYAML` mirrors, retaining `Secret.MarshalYAML`/`UnmarshalYAML` in `secret.go`. Keep a single `snmpAlias` definition for the JSON projection; add an AST guard against YAML marshaler methods outside `secret.go`, YAML struct tags in `types*.go`, or another `snmpAlias` definition. Remove only the YAML assertions from the PKI and trap-group tests, leave JSON assertions intact, and clarify JSON-only comments/tags.
- **Validation**:
  - RED at the base: the guard reports the four YAML mirrors, duplicate `snmpAlias`, and YAML tags. A temporary `SNMPCommunity.MarshalYAML` stub also makes it fail.
  - GREEN after deletion: the guard passes, as does the requested seven-test `pkg/config` regression selection.
  - `go test ./pkg/config -run '16728|16732|9416' -count=1` passes; `gofmt -l` reports no changed Go files.
  - Full `go test ./pkg/config -count=1` did not pass: it reports failures in `TestCompactNormalizeScopePreservesCompiledResult8690` and `TestSchemaSpellingDifferentialGate`, then hits the 10-minute test timeout in `TestSchemaSpellingGateCoverageIsGated_7484`.
- **Risk**: JSON marshaling behavior and the `Secret` YAML redaction/fail-closed behavior remain unchanged. No config-specific YAML redaction method remains for a future config YAML encoder; the AST guard prevents that partial surface from being silently reintroduced.
