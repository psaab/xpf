# #14703 — session-sync Noise handshakes accept the #6630 rotation ring

## Issue
`SyncAuthProvider` exposed only `ControlLinkAuthKey()` (the signing key). The Manager already maintained a verify-side ring (`controlLinkAcceptedKeys()` = signing key + `additional-authentication-key`) and the heartbeat (`admitFrame`) and fabric gRPC listener (`fabricAcceptedKeys`) verified against it, but session sync did not: `SessionSync.authKey()` returned only the primary, `performNoiseHandshake`'s responder built one Noise state from it, `handleAuthUpgradeHello` opened the upgrade msg1 with only it, and `wrapSyncConn` stamped `ac.authPSK = s.authKey()`. During #6630 step 3 (node0 signs B / accepts [B,A], node1 signs A / accepts [A,B] — the documented asymmetric intermediate state) a B-sealed initiator was rejected by an A-signing responder (`noise msg1 rejected`) and the in-place upgrade wedged, so the "hitless" rotation was not hitless for session-sync/config-sync/fence transport: any fabric reconnect in the window failed.

## Fix
- `pkg/cluster/sync_auth.go`: added `authAcceptedKeys()` resolving the accepted ring through an optional-interface probe (`syncAcceptedKeysProvider`, mirroring the existing `syncPeerAuthRecorder` probe). `*Manager` already satisfies it via `ControlLinkAcceptedKeys()`, so production widens with no wiring change and no new config leaf; providers implementing only `ControlLinkAuthKey()` (all pre-#14703 test fakes) fall back to exactly that one key. `SyncAuthProvider` itself is unchanged. Initiators keep sealing under `authKey()` (the signing key) alone — nothing is ever signed with the additional key. Added `syncNoiseKeysWithPSK{syncNoiseKeys, matchedPSK}` so the key a handshake actually authenticated under travels to the stamp. `performSyncHandshake` returns it; the initiator path refuses to initiate when there is an accepted ring but no signing key (alt-only, fail-closed). `wrapSyncConn` stamps `authPSK` from `matchedPSK`, not the local signing key.
- `pkg/cluster/sync_auth_noise_7163.go`: `performNoiseHandshake` is initiator-only (responder call is a loud error). New `performNoiseResponderHandshake` reads msg1 **once**, then tries each ring member against a fresh Noise state (Noise consumes msg1; re-reading the wire would allow substitution between attempts), writes exactly one msg2 for the first key that opens msg1, and returns that matched key. A peer holding no ring member is rejected after the ring is exhausted — still fail-closed.
- `pkg/cluster/sync_auth_upgrade.go`: `handleAuthUpgradeHello` verifies the Hello against the whole ring with a fresh state per candidate, leaves the existing round untouched until one candidate succeeds, and stamps the round's `forPSK` with the matched key.
- Deliberately unchanged: `beginAuthUpgrade` / `ReconcileConnectionAuth` / `handleAuthUpgradeRequest` still drive rounds under the local signing key (that is what this node *initiates* with — correct, since the peer's ring is what must contain it, and in step 3 it does); `enforceStrictSessionAuth` / `UnauthenticatedSessionConns` keyed-ness checks still use `authKey()` (an alt-only node signs nothing and is refused at config commit per `validateClusterAuthKeyStrict`, so the ring cannot be non-empty there while the signing key is empty in production).
