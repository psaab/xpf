# Issue #12184 — validate the qualified-next-hop metric

## Why

The qualified-next-hop `metric` leaf was untyped, unlike its sibling `preference`. Strict schema validation therefore let `-1`, `4294967296`, and non-numeric values such as `abc` reach compiler paths that ignore unparsable integers or treat out-of-u32 values as tier 0. That silently erased the authored failover order and omitted invalid FRR metric exports.

## What

- Typed the metric leaf as an integer in `0..4294967295`, matching the userspace tier and FRR export consumers. Zero is the primary metric tier and is explicitly valid; the u32 ceiling is the consumer boundary. This intentionally differs from preference's `1..254` range.
- Made strict schema walking use the existing #9235 QNH flat-run expansion for `qualified-next-hop` children, matching the compiler's view so the metric validator also covers accepted flat-set modifier chains.
- Added schema and Store.CommitCheck regressions across flat, flat modifier-chain, hierarchical braced, and hierarchical packed spellings; invalid values reject and `0`, `100`, and `4294967295` controls accept.

## Validation

- **RED before** on clean STEP-0 base `8dc3c5624f69535fe37af7ab90089a86d227ad58`: a throwaway `Store.CommitCheck` probe accepted `-1`, `4294967296`, and `abc` (nil error) for flat, flat-interface-chain, hierarchical-braced, and hierarchical-packed spellings. The same base accepted `0` and `100` controls.
- **GREEN after**: `go test ./pkg/config ./pkg/configstore -run '12184' -count=1 -v` — PASS.
- QNH sibling/caller checks: `go test ./pkg/config -run '^(TestFlatRunResidue.*|TestStaticRouteQualifiedNextHopPreference.*|TestStaticRouteQualifiedNextHopMetric.*)$' -count=1` — PASS; `go test ./pkg/configstore -run '^TestCommitCheckQualifiedNextHopMetric12184$' -count=1` — PASS.
- `go build ./pkg/config ./pkg/configstore` — PASS. `gofmt` completed on all changed Go files; `gofmt -l` returned no paths.
- `go test ./pkg/config ./pkg/configstore -count=1` — NOT GREEN. A clean-base run of the reported individual failures reproduced the unrelated #8662, #9027/#9029/#8921/#10826, #11312, and #1798/#11310 failures. The full run also timed out at 10 minutes while `TestSchemaSpellingDifferentialGate` was running. The added metric type makes the #8436/#8704 duplicate-block census synthesize valid metrics for repeated qualified-next-hop blocks and expose an unreported reduction; duplicate-block compilation was not changed in this issue, and the census test assets were left untouched per scope.

## Risk / residual

The strict metric gate now covers the accepted QNH spellings exercised above. Repeated hierarchical qualified-next-hop blocks can still lose metric data under the existing duplicate-block behavior; the newly observable census case is separate from invalid-value validation and is recorded for follow-up. No live cluster or hardware was mutated.
