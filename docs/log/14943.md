# #14943 — Flow-cache HA lease stamp frozen at insert (10s)

## Defect
`FlowCacheStamp::capture` copied `HAForwardingLease::ActiveUntil` into
`owner_rg_lease_until` at insert (`flow_cache.rs`), and hits validated
against that frozen copy but never refreshed it. The runtime lease is
receipt-anchored at 10s (`HA_WATCHDOG_STALE_AFTER_SECS`,
`HAGroupRuntime::active_lease_until`) and renewed every few seconds, so
every seeded entry self-evicted ≤~10s after seeding
(`lookup_with_observed_bytes`: `now_secs > stamp.owner_rg_lease_until`),
and before eviction the hit validator
(`cached_flow_decision_valid` → `enforce_ha_resolution_snapshot`)
could demote the cached resolution to `HAInactive` once the runtime
lease lapsed. Compounding it, `try_refresh_ha_leases`
(`ha/session_domain.rs`) refused to resurrect an expired stored-active
lease even on a matching fresh heartbeat (`incoming_active &&
!stored.is_forwarding_active → NeedsLock`), and the Go watchdog treats
`NeedsLock` as throttle-success with no control-socket retry — so one
lapse was permanent for the runtime lease and for every cache entry
stamped from it.

Live correlation (#14300): all flows cache-evict in a burst at session
age ~26–28s, session-hit burst, then no re-seed/refresh, ACKs dropped,
idle-timeout closes.

## Fix
- `flow_cache.rs`: extracted `FlowCacheStamp::current_lease_until`
  (the exact extraction `capture` uses). The hit path now takes the
  worker's current `ha_state` snapshot (threaded through
  `lookup_counted_with_scheduler_expiry` / `lookup_counted` /
  `lookup_with_observed_bytes` from `stage_flow_cache_hit`'s
  `worker_ctx.ha_state`) and validates a lease-carrying entry against
  the CURRENT runtime lease, re-stamping `owner_rg_lease_until` from
  it on every hit. Fail-closed is preserved: a genuinely expired
  current lease, or an owner vanished/inactivated on a provided
  (non-empty) runtime map, still misses + evicts. An empty map means
  no HA snapshot was provided (standalone / test seam) and is not
  gated — exactly the pre-fix behaviour for stamp-0/standalone
  entries; production always passes the live snapshot, and
  `cached_flow_decision_valid` re-checks HA against the same map.
- `ha/session_domain.rs`: a matching fresh heartbeat (incoming active)
  now resurrects an expired stored-active lease, minting from the
  incoming watchdog exactly as the locked `update_ha_state` path
  would. The mismatch (incoming-inactive) arm still never resurrects:
  Go overlays any demotion/removal intent as inactive
  (`haWatchdogGroupsLocked`, `manager_ha.go`), so a demotion can never
  arrive as matching-active — that overlay is what licenses the
  resurrection. `NeedsLock` is now reserved for CLEAR / membership /
  stored-empty / pure-no-op.
- `manager_ha.go` + `ha_session_refresh_9629_test.go`: comments updated
  to state the overlay→resurrection licence (no Go behaviour change;
  the oracle already modelled matching refresh as Served).

## Regression
- `hit_past_insert_lease_with_fresh_runtime_lease_stays_cached_14943`
  — insert stamp 50, hit at 100/150 with current lease 200: hits,
  re-stamps to 200, zero evictions.
- `hit_with_genuinely_expired_runtime_lease_still_fails_closed_14943`
  — current lease 80, hit at 100: miss + evict.
- `hit_with_vanished_runtime_lease_fails_closed_14943` — provided map
  without the owner: miss + evict.
- `expired_matching_active_resurrected_by_fresh_heartbeat_14943` —
  expired stored-active + matching active heartbeat: `Served(2)`,
  lease re-minted ≥ now+10, sibling RG published atomically.
- The two pre-existing expired-lease cells
  (`expired_owner_rg_lease_causes_miss_*`) were re-pinned to the
  current-lease gate (provided map, expired current lease) — same
  observable miss+evict.
- Preserved: `expired_stored_active_incoming_inactive_needs_lock_9629`
  (mismatch-expired never resurrects), `server::tests::update_ha_state_*`
  (13 passed), Go `9629|HARefresh|SessionHA` (passed).

## RED → GREEN
- RED (current-lease comparison reverted to the frozen stamp and the
  `NeedsLock` early-return restored, test seams intact): 3 of 4 new
  cells fail — `hit_past_insert_lease_...` evicted at the frozen
  stamp, `hit_with_vanished_...` not evicted, resurrection cell gets
  `NeedsLock` instead of `Served(2)`. The genuinely-expired cell
  passes in both worlds (fail-closed preserved).
- GREEN (fix applied): all 4 new cells pass; `flow_cache::tests` +
  `try_refresh_9629` + `flow_cache_hit` suites: 145 passed, 1
  pre-existing failure (`gre_decap_flow_cache_hit_ttl_expiry_reads_inner_ttl_5615`,
  verified failing identically on unmodified origin/master — its
  `txn_ha_state` fixture lease (watchdog 123) is genuinely expired at
  the harness's real-clock `now_secs`, unrelated to this change).
