# #19161: pkg/cluster root testguard run hangs

- **Timestamp**: 2026-11-16 (G5)
- **Root cause (measured; the issue's attribution was close but wrong).**
  - At the hung cell (`statusFor9177`, via
    `TestAbandonedBulkDisconnectStampsEnd15254`), the fresh Manager's
    `UnkeyedAuthorityExpired()` was true and it was unkeyed. So
    `electSingleNode` returned at `electionHoldActiveLocked()` and emitted
    no event, and the bare `<-m.Events()` hung the package.
  - The run-shared grace record read
    `v2 1793707200000000000 … 259200000000000`: earliest 2026-11-03T12:00Z,
    elapsed 72h. That earliest is the #16016 cells' FIXTURE clock.
  - The writer, caught by wrapping the persist hook in TestMain on the
    runner copy, with stacks: `time.AfterFunc` → `confirmNeverSeenIfDue`
    (heartbeat_manager.go) → `electSingleNode` → `UnkeyedAuthorityExpired`
    → `markUnkeyedAuthorityExpired` → persist.
    1. The #16016 cells configure `ControlInterface: "em0"`, which arms the
       never-seen timer, and never stopped their Managers (27
       `NewManager`, 0 `Stop`).
    2. The timer fired after the cell's `t.Cleanup` had restored the real
       clocks and the shared grace path.
    3. The fixture deadline lay in the fake monotonic domain (about 1 s +
       72 h). Against the REAL monotonic clock, which counts uptime, it
       had passed only on a runner up more than 72 h.
    4. So the leaked manager persisted its expired fixture grace into the
       shared record, and every later Manager loaded it and held its
       election.
  - Why it looked like a #19084 root-state problem: unprivileged legs could
    not write the shared path, so they were isolated by accident. udp1 (up
    89.7 h) hung and tcp3 (up 7.3 h) never did.
- **Fix** (test-only; no product change):
  - `newManager16016(t, …)` registers `t.Cleanup(m.Stop)`. Cleanup runs
    last-in-first-out, so Stop runs before the clock and path restores, and
    `Stop` disarms the never-seen clock. All 27 sites in
    `unkeyed_authority_grace_16016_test.go` use it.
  - `TestLeakedAuthorityManagerCannotWriteTheSharedRecord19161`: the fixture
    monotonic anchor sits 73 h behind the real clock, so a leaked timer
    finds the grace expired on ANY runner, whatever its uptime. The cell
    asserts that the outer ("shared") record is never written and that the
    subtest's manager is stopped.
  - TestMain `watchSharedGraceRecord19161`: a write of the run-shared record
    with an `earliest` before the run started can only come from a fixture
    clock. It fails the package and prints the writer's stack, so the next
    such leak is named at its source instead of surfacing as a hang far
    away. A unit cell pins the watch.
  - Kept from the first pass:
    - `TestMain` points every `/var/lib/xpf` state path at a per-run
      temporary directory, so root and unprivileged legs see the same
      directory and the host path is never used.
    - `recvEvent19161` bounds all 132 event waits at 2 minutes, naming the
      wait. `TestNoUnboundedEventsReceive19161`, with 11 fixture cells,
      reports a bare receive, an unbounded select, a range over `Events()`,
      and an `Events()` channel bound to a variable.
    - `TestStateDirForTestingCoversEveryStatePath19084` compares the
      restored path with its pre-call value.
- **Validation** (`scripts/vm-test-run.sh`, all `paused-for=0s` unless noted):
  - udp:xpf-testrunner, up 89.9 h, empty `/var/lib/xpf` (the issue's
    conditions):
    - full package, root: `ok` 241.5 s, 0 fails;
    - full package, unprivileged: `ok` 241.5 s, 0 fails;
    - CONTROL, the fix minus the Stop: FAIL at
      `TestAbandonedBulkDisconnectStampsEnd15254`, and the TestMain watch
      names the record, `earliest=2026-11-03T12:00:00Z` and the writer
      stack;
    - mutants KILLED: no Stop (by the regression cell), blind watch (by
      the watch cell). Census mutants (udp:xpf-testrunner2) KILLED: select
      always bounded, no range check, no variable check, no bare report,
      Done() not a bound.
  - Earlier evidence corrected:
    - My first "root ok" runs on tcp:xpf-testrunner3 did not discriminate.
      tcp3 had no `/var/lib/xpf` at all, and it is up only 7.3 h, so it
      cannot reproduce. With `/var/lib/xpf` created, both the redirect and
      the no-redirect arm PASS there.
    - On udp1 the redirect alone FAILS (57 fails, the same first cells as
      without it). The redirect is not the fix.
    - A udp1 control paused 632 s was VOID and is not used.
  - go vet clean; gofmt clean.

- **Timestamp**: 2026-11-17 (audit, team-lead: same leak in pkg/cli and
  pkg/daemon?)
- **Action**: Audited every cell outside pkg/cluster that injects the
  unkeyed-grace clocks (`SetUnkeyedAuthorityClocksForTesting`).
  - pkg/cli `cli_request_unkeyed_grace_16016_test.go`: two cells build
    `cluster.NewManager` with `ControlInterface: "em0"` (which arms the
    never-seen timer) under a fixture wall and mono, and never stop it.
  - pkg/daemon `config_sync_auth_authority_16016_test.go`: eight cells build
    `newClusterManager(false)`, which configures `control0`, and never stop
    it. Two of them install a FAKE monotonic clock (1 s) under the REAL
    wall. A leak from those would persist a real anchor with elapsed about
    72 h, which the first watch (anchor before the run) cannot see.
- **Action**: All ten now register `t.Cleanup(manager.Stop)` after the
  setup's restores (so it runs first). The watch judges `elapsed` too:
  `graceRecordLeakReason` flags an anchor from before the run OR more
  elapsed grace than the run has lasted. pkg/daemon's `TestMain` runs the
  same judgement on its run-shared record after its tests, through the new
  exported `cluster.UnkeyedGraceRecordLeakForTesting`. pkg/cli has no
  TestMain and no state redirect, so its cells get only the Stop.
- **Validation** (udp:xpf-testrunner, up 91.8 h; the run was paused 1031 s
  by gates, so timing results from it are VOID):
  - vet and gofmt clean; the 19161/16016 cells in pkg/cluster, pkg/cli
    and pkg/daemon pass; mutant no-elapsed-criterion KILLED by the watch
    cell and the new leak-check cell;
  - full pkg/cluster root: `ok`, no watch report;
  - full pkg/daemon root with the fix: no watch report. Nine failures are
    shared with the control (pre-existing runner reds, e.g.
    TestPCIAddrToEnp_Domain_6199, TestDaemonRGReadersUseTheSharedPredicate).
    The tenth, TestDualFabricSecondaryMissingKeepsPrimary12168 (a 236 s
    kernel-VRF cell with real-time waits), ran inside a frozen window. It
    is VOID, and re-ran clean twice on tcp:xpf-testrunner3 as root, `ok`;
  - CONTROL, pkg/daemon without the Stops: no watch report either. On
    this runner the pkg/daemon shape did NOT leak: those cells drive the
    grace to expiry inside the test, onto their own isolated path, so
    nothing is left to expire after the restores. So the pkg/cli and
    pkg/daemon Stops are hygiene against the same shape, not a measured
    fix, and the pkg/daemon check is a guard for the next one.
