# Issue #12659 — cluster deploy liveness priming

## Why

`deploy_reassert_prime_liveness` only primes traffic when `CLUSTER_LAN_HOST` and `IPERF_TARGET4` are set. `cluster-setup.sh` sourced the selected cluster env and deploy library, but cluster env files expose the LAN instance as `LAN_HOST`; unlike the HA smoke setup, the deploy path never bridged that name to the liveness variable. Consequently ordinary cluster deploys silently used the degraded fallback regime even when the LAN target was available.

## What

Added a deploy-library resolver that maps the explicit `CLUSTER_LAN_HOST` override or the env's `LAN_HOST` to an Incus instance reference using `INCUS_REMOTE` qualification, without double-prefixing already-qualified names. `cluster-setup.sh` now resolves this value during initialization, before either deploy path invokes liveness reassertion. If neither host variable is configured, it leaves the target empty so the existing safe fallback remains in effect. Added regression cells for local/remote resolution, explicit overrides, missing host, the primed ping target, and setup wiring.

## Validation

- RED-before: `./test/incus/deploy-lib-selftest.sh` reported 109 passed, 3 failed. The three new #12659 failures were missing LAN-host resolution, failure to prime from a LAN_HOST-only environment, and missing cluster-setup wiring.
- GREEN-after: `./test/incus/deploy-lib-selftest.sh` reported 112 passed, 0 failed, including all four #12659 regression cells.
- `./test/incus/cluster-env-selftest.sh` reported all 15 cases passed. `bash -n test/incus/deploy-lib.sh test/incus/cluster-setup.sh test/incus/deploy-lib-selftest.sh` passed. ShellCheck ran but returned existing informational findings (including SC2016 and SC1091) in these scripts.

## Risk

Only cluster deploy target resolution changes. Explicit target overrides retain precedence; missing target information does not invent a host and continues to use the existing fallback behavior. No live-cluster mutation was performed.
