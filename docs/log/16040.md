# Issue #16040 — in-window RST/FIN stamps teardown without exact seq==rcv_nxt (S2-03 leg2)

- **Timestamp**: 2026-10-23
- **Defect**: `tcp_closing_seq_verdict` returned Valid for any closing segment with `behind < wnd || seq == rcv_nxt`. An in-window (non-exact) RST therefore stamped session teardown for any of ~window (~65k) blind guesses. Leg1 (foreign/filter-dropped seq-note poisoning, #15947) was already fixed; this is leg2 only. Severity: Low residual.
- **Fix**: `tcp_closing_seq_verdict(key, seq, tcp_flags)` now requires exact seq when the RST bit is set (RST|FIN driven by the RST bit), per RFC 9293 §3.5.3 / RFC 5961 §3.2 (a non-matching RST draws a challenge ACK, never a close). FIN keeps in-window validity `[rcv_nxt - receiver_wnd, rcv_nxt]` (the #15947 receiver-window logic governs FIN only). Unknown still returned when no sequence state is tracked (mid-stream/HA pickup fail-open preserved). The poll slow-path caller passes `meta.tcp_flags`; the flow-cache fast path still never stamps close.
- **Fold (Opus review)**: the exact target is the ENDPOINT's receive-next, not the firewall-observed send-end. `entry.tcp_rcv_nxt` is the send-end (seq+payload high-water as transmitted, including segments later lost downstream), so exact-vs-send-end dropped a legitimate ACK-derived RST during downstream-loss recovery. New tracked state `tcp_peer_rcv_nxt`/`tcp_peer_rcv_nxt_seen` on the sender-direction entry, recorded high-water from the companion direction's ACK field in the `note_tcp_seq_scaled` table seam (SYN-ACK ack = ISN+1; bare SYN excluded). RST is Valid iff `seq == tcp_peer_rcv_nxt`; until any endpoint ACK is observed the RST verdict is Unknown (admitted) rather than a send-end guess.
- **Tests (decisive)**: `rst_requires_exact_seq_16040` (full-ACK: one-behind/in-window/one-ahead/RST|FIN RST Invalid, exact RST and exact RST|ACK Valid, in-window FIN Valid, FIN ahead of window Invalid); `rst_exact_uses_endpoint_rcv_nxt_not_send_end_16040` (downstream loss: 100 sent/50 ACKed — RST at endpoint 1051 Valid, RST at send-end 1101 Invalid; after retransmit-ACK advances, exact target moves and duplicate ACK does not rewind); `in_window_rst_valid_blind_rst_invalid_15753` updated (Unknown before endpoint ACK, exact after); `scaled_window_and_receiver_window_verdict_15947` re-driven with FIN flags so receiver-window coverage is preserved; `rst_seq_validation_in_window_vs_blind_15753` updated (single-entry table: RST Unknown, FIN window behaviour).
- **Validation**: `cargo test --bin xpf-userspace-dp -- rst_requires_exact_seq_16040 rst_exact_uses_endpoint in_window_rst_valid scaled_window_and_receiver rst_seq_validation seed_tcp_window_scale unilateral_wsopt` — 7/7 pass.
