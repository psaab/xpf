# Issue #16040 — in-window RST/FIN stamps teardown without exact seq==rcv_nxt (S2-03 leg2)

- **Timestamp**: 2026-10-23
- **Defect**: `tcp_closing_seq_verdict` returned Valid for any closing segment with `behind < wnd || seq == rcv_nxt`. An in-window (non-exact) RST therefore stamped session teardown for any of ~window (~65k) blind guesses. Leg1 (foreign/filter-dropped seq-note poisoning, #15947) was already fixed; this is leg2 only. Severity: Low residual.
- **Fix**: `tcp_closing_seq_verdict(key, seq, tcp_flags)` now requires exact `seq == entry.tcp_rcv_nxt` when the RST bit is set (RST|FIN driven by the RST bit), per RFC 9293 §3.5.3 / RFC 5961 §3.2 (a non-matching RST draws a challenge ACK, never a close). FIN keeps in-window validity `[rcv_nxt - receiver_wnd, rcv_nxt]` (the #15947 receiver-window logic governs FIN only). Unknown still returned when no sequence state is tracked (mid-stream/HA pickup fail-open preserved). The poll slow-path caller passes `meta.tcp_flags`; the flow-cache fast path still never stamps close.
- **Tests (decisive)**: `rst_requires_exact_seq_16040` (one-behind/in-window/one-ahead/RST|FIN RST Invalid, exact RST and exact RST|ACK Valid, in-window FIN Valid, FIN ahead of window Invalid); `in_window_rst_valid_blind_rst_invalid_15753` updated for exact-RST semantics; `scaled_window_and_receiver_window_verdict_15947` re-driven with FIN flags so receiver-window coverage is preserved; `rst_seq_validation_in_window_vs_blind_15753` updated likewise.
- **Validation**: `cargo test --bin xpf-userspace-dp -- rst_requires_exact_seq_16040 in_window_rst_valid scaled_window_and_receiver rst_seq_validation seed_tcp_window_scale unilateral_wsopt` — 6/6 pass. RED check: with the production change stashed (tests kept), `in_window_rst_valid_blind_rst_invalid_15753` + `rst_seq_validation_in_window_vs_blind_15753` fail (in-window RST Valid pre-fix); the new test is absent on the pristine tree. Unit level only; no live cluster run.
