  (`c616fd4bb1`). That change converted the three
  `#[cfg_attr(not(test), allow(dead_code))]` sites to `#[cfg(test)]`

  `grep -c 'cfg_attr(not(test), allow(dead_code))' forwarding/*.rs` was

## Fix

- Deleted `parse_neighbor_entries` (`forwarding/tunnel.rs`) and its
  test `parse_neighbor_entries_accepts_stale_ipv4_and_ipv6_rows`
  (`forwarding/tests.rs`); production neighbor discovery is netlink
  (`lookup_neighbor_entry` comment: hot path must not shell out to
  `ip neigh`). Removed it from the `neighbor_state_usable` consumer
  list in `forwarding/fabric.rs` and from `forwarding/README.md`
  (file table + M12 note).
- Made `zone_pair_for_flow_with_override` `#[cfg(test)]` and rewrote it
  as an adapter using `zone_pair_ids_for_flow_with_override` for the
  to-zone. Every `Some(zone)` returns `zone.to_string()` verbatim; it is
  never mapped through `zone_name_to_id`. With no override, the from-zone
  retains the deleted twin's direct `ifindex_to_zone_id` ->
  `zone_id_to_name` lookup, including a reverse name for id 0 in a
  hand-built test state. This preserves the to-zone's id-0 special-case
  while preventing the #6713 to-zone lockstep divergence.
- `match_source_nat_for_flow_result`: no change — already
  `#[cfg(test)]` via #17195.
