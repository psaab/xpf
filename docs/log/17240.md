## Fix

- Deleted `parse_neighbor_entries` (`forwarding/tunnel.rs`) and its
  test `parse_neighbor_entries_accepts_stale_ipv4_and_ipv6_rows`
  (`forwarding/tests.rs`); production neighbor discovery is netlink
  (`lookup_neighbor_entry` comment: hot path must not shell out to
  `ip neigh`). Removed it from the `neighbor_state_usable` consumer
  list in `forwarding/fabric.rs` and from `forwarding/README.md`
  (file table + M12 note).
- Made `zone_pair_for_flow_with_override` `#[cfg(test)]` and rewrote it
  as an adapter over `zone_pair_ids_for_flow_with_override`: the
  override name is mapped to its id via `zone_name_to_id`, ids are
  mapped back via `zone_id_to_name`, and an unmapped override name
  round-trips verbatim (preserving the old semantics). Resolution
  logic is now single-sourced in the production u32 resolver, so the
  #6713 lockstep divergence cannot recur.
- `match_source_nat_for_flow_result`: no change — already
  `#[cfg(test)]` via #17195.
