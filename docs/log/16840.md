# #16840 — `port no-translation` pools charged full PAT bitmap in Rust

- **Timestamp**: 2026-10-25
  - **Action**: #15675 made the Go aggregate budget charge 0 port slots for `port no-translation` pools (`SourceNATPoolPortRange` returns 0,0), but the Rust apply in `userspace-dp/src/nat/source/mod.rs` defaulted wire 0/0 to 1024-65535, charged 64,512 slots/address, built the full PAT bitmap, and refused later pools `OverBudget` on strict-clean configs (plus wasted ~64,512-slot bitmaps per address). Fixed Rust to agree: `PendingPoolAllocator` now carries `no_translation` (true only when every rule resolving under the same configured-range allocator key is no-translation — a PAT sibling downgrades the group so the #10190 shared allocator, its bitmap and charge are preserved). Pure no-translation pendings charge 0 port slots, are keyed and built with range 0/0 (no bitmap), and the first post-fix apply aliases a legacy port-bearing previous allocator under the 0/0 key so live address-only tokens are not orphaned. `PortAllocator::new` with range 0/0 now gets the global `MAX_SOURCE_NAT_POOL_TRACKED_FLOWS` cap instead of 0, since address-only flows are tracked by reverse identity, not port slots. Draining no-translation pools also charge 0. Go side unchanged (already 0).
  - **File(s)**: `userspace-dp/src/nat/source/mod.rs`, `userspace-dp/src/nat/allocator/mod.rs`, `userspace-dp/src/nat/tests_aggregate_budget.rs`, `docs/log/16840.md`
  - **Validation**: New Rust cells in `tests_aggregate_budget.rs`: `no_translation_pools_charge_zero_and_build_no_bitmap_16840` (three /29 no-translation pools at wire 0/0 under a 2-pool PAT budget all install, no bitmap, max_tracked_flows=262144; PAT control's third pool is OverBudget), `no_translation_reapply_reuses_zero_range_allocator_16840`, `mixed_notrans_and_pat_share_port_bearing_allocator_16840`. Targeted `cargo test --bin xpf-userspace-dp -- nat::` run by implementor; full suite deferred to main agent.
  - **Risk**: Mixed no-translation+PAT pools keep the previous port-bearing behaviour exactly (shared allocator, full charge). Pure pools lose only the unused bitmap; address counts and pool counts still charge, so address/pool budgets still bound them. Legacy reuse alias only fires when a 0/0 key is absent and the configured-range key exists.
