# #18574 — foreign-held standalone and legacy-local pools on shared VLAN 50

Branch `fix/18574-campaign`, worktree `/var/worktrees/campaign-drive/wt-18574`.

## Root cause

The standalone and legacy-local lab stacks proxy-ARPed and NATed through
172.16.50.14/.15 and .9/.12 respectively. The 2026-10-31 foreign-host census
found each address already answered by a non-xpf device, so each pool could
race that device for the upstream gateway's ARP entry.

## Changes

- Re-addressed legacy-local NAT64 `.9` → `.44` and SNAT `.12` → `.45` in
  `test/incus/xpf-cluster-fw0.conf`; both remain proxy-ARPed.
- Re-addressed standalone NAT64 `.14` → `.46` and SNAT `.15` → `.47` in
  `test/incus/xpf-test.conf`; both remain proxy-ARPed.
- Removed the #18558 exemption mechanism for these claims. The foreign list
  still records the measured old addresses, so any shipped claim there fails.
- Updated docs/incus-tcp-udp-plan.md §3.3, the Debian changelog, and this log.

## Same-day address evidence

At 2026-11-02 18:32 UTC, tcp `xpf-tcp-fw0` sent three RFC 5227 probes
(sender IP `0.0.0.0`) on `ge-0-0-2.50` for the old claims and `.44`-`.47`.
The old claims had replies: `.9` from `2a:dd:35:a2:96:97`, `.12` from
`ac:8b:a9:df:fd:f3`, `.14` from `f4:e2:c6:ea:d7:80`, and `.15` from
`9c:05:d6:e1:f2:0f`. The four replacements had no reply in any of the
three rounds. The probe also received replies from the gateway `.1`, tcp's
peer RETH `.43`, and a foreign host at `.51`, demonstrating the probe heard
the segment. `.44`-`.47` are absent from the #16473 xpf stack census.

The segment's DHCP/IPAM is outside this repo. A lab-owner reservation for
`.44`-`.47` is still recommended; no reservation was verified as part of this
change.
