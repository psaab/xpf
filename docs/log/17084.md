# #17084 — GRE and WG aux-thread lifecycles consolidated into one registry

- **Timestamp:** 2026-10-27
- **Branch:** `fix/17084-campaign`
- **File(s):** `userspace-dp/src/afxdp/coordinator/tunnel_registry.rs` (new), `userspace-dp/src/afxdp/coordinator/tunnel_supervision.rs`, `userspace-dp/src/afxdp/coordinator/mod.rs`, `userspace-dp/src/afxdp/coordinator/tests.rs`, `userspace-dp/src/afxdp/coordinator/README.md`

## Why

`tunnel_supervision.rs` held two hand-mirrored copies of the #1866/#1881 three-pass aux-thread lifecycle plus two inline copies in `stop_inner`. They had diverged: the GRE defer prune reaped same-id attachment drift (`b2f5560fa9`) while the WG defer prune only checked hydratable presence, so a defer-workers apply that moved a WG endpoint's attachment (or changed its crypto identity while staying hydratable) left the old TUN fd, listen socket and engine live until the deferred bring-up. Separately #1889 left dead `stop_remove_wg_control_entry` with a false doc claiming callers, and GRE kept the serial stop+join shape while WG used bulk signal-then-join.

## What

- New `coordinator/tunnel_registry.rs`: `TunnelThreadRegistry<E: TunnelThreadEntry>` owns the `BTreeMap<u16, E>` and provides the single `sweep_finished`, bulk `stop_remove` (signal-all then join, unpublish-before-join via caller exclusion), `stop_all`, `clear`, `deferred_stale_batch`, `live_deliveries_excluding` and `tombstone_ids`. `TunnelThreadEntry` is implemented for `LocalTunnelSourceEntry` (GRE) and `WgControlEntry` (WG); `snapshot_row_label` is the shared row-label helper. `stop_remove` takes a `before_join` hook carrying the #10553 test probe.
- `Coordinator::tunnel_sources` / `wg_control_threads` are now registries; `stop_inner` calls `registry.clear()` for both (deleting the two inline signal/join loops). All production/test call sites use the registry accessors (`get`/`get_mut`/`insert`/`contains_key`/`is_empty`/`iter`).
- Family-specific stale predicates and spawn bodies stay in `tunnel_supervision.rs`. The WG defer predicate now also returns `attachment_changed_deferred` (row ifindex/label vs spawned attachment) and `identity_changed_deferred` (`hydrate_wg_identity(row).matches_endpoint(forwarding endpoint)`), matching the GRE defer rule and the WG tombstone-coherence tuple. Dead `stop_remove_wg_control_entry`, both per-family sweeps and the GRE serial helper are deleted.
- Behaviour note: GRE stop paths now bulk signal-then-join (was serial). GRE handles carry an eventfd wake (`request_stop` signals it), so joins return promptly; ordering (unpublish before join) is preserved and probed.
- New parity cell `tunnel17084_defer_prune_parity_moved_attachment_and_identity` drives both families with same-id moved-attachment snapshots (and a WG identity change) and asserts identical prune outcomes, plus unchanged-snapshot retention. README "Aux tunnel threads" now lists the shared lifecycle and the WG defer-drift rule explicitly.

## Risk

Control-thread lifecycle only; no forwarding/dataplane change. Log wording for stopped/exited threads now uses the family label from the shared implementation but keeps the same `endpoint=`/`tun=`/`reason=` fields. The WG defer prune additionally stops a thread on same-id attachment/identity drift during a defer window (previously it survived until bring-up) — the intended parity behaviour, covered by the new cell. Bulk GRE joins are bounded by the eventfd wake as before.
