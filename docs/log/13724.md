# Issue 13724 verification

## Change

Local-address and interface-NAT map synchronization now removes stale entries before publishing replacements. The local-address path retains its non-authoritative-enumeration guard: incomplete netlink enumeration does not prune. Interface-NAT counts receive the same 8192-entry preflight as local-address counts before any classifier map is written. Kernel-enumerated interface-NAT addresses are filtered from the local-address maps, matching the existing config-address exclusion.

## Regression coverage

- Full-map stale-to-new replacement tests cover both local-address and interface-NAT maps.
- Kernel-enumerated IPv4/IPv6 exclusions are checked.
- Interface-NAT capacity checks cover both address families, including exact-capacity acceptance.

## Validation

- The in-memory capacity-limited local/NAT replacement, pure-delete and no-op
  tests pass; they exercise the shared delete-then-update helper used by both
  map families. The in-memory RED probe fails to compile on pristine master
  (`undefined: reconcileAddressMapKeys`).
- Kernel-backed local-address and interface-NAT replacement regressions are
  present, but skip because `setrlimit` returns `operation not permitted`.
- Focused exclusions and interface-NAT capacity preflight checks pass. The
  focused command reported five BPF-dependent tests skipped.
- `go test ./pkg/dataplane/userspace -count=1` fails on the branch and on
  pristine `origin/master` with the same unrelated failures: contract snapshot
  golden drift, Unix-socket `bind: invalid argument`, Junos-host parity, and
  several pre-existing policy/zone assertions.
