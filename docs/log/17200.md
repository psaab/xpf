# Issue #17200 — R4-Q17-03: make `cargo clippy` completable and gated

- **Issue:** `cargo clippy` exited 101 on the crate (deny-by-default `clippy::mut_from_ref` at `umem/mmap.rs` since the first commit, and `clippy::never_loop` in a 2026-10-23 #15950 test), yet 233+ `allow(clippy::…)` lines were maintained for a tool nothing ran. No recipe or CI job ran clippy.
- **STEP-0 (defect live on origin/master `eb4571c7ef38250a4b84c229d051fac14cf94e40`):** `cargo +1.98.1 clippy --manifest-path userspace-dp/Cargo.toml --all-targets` exited 101. The lib/bin error was `src/afxdp/umem/mmap.rs:241:17: error: mutable borrow from immutable input(s)` (`clippy::mut_from_ref`, deny-by-default). Census on this head: 246 `allow(clippy::` lines (242 `too_many_arguments` + 4 `type_complexity`), 0 `expect(clippy::`. The `--all-targets` run also surfaced a second, pre-existing blocker not in the original report: `src/afxdp/shared_umem_tests.rs:247:20: error[E0308]: mismatched types: expected UserspaceSnapshot, found Value` — #17134 typed `ConfigSnapshot.userspace` as `UserspaceSnapshot` but one test cell still passed a bare `json!` Value, so the test target did not compile at all and clippy could not reach the `never_loop` site. `grep -rn clippy Makefile .github/` returned nothing.

## What

1. **`mut_from_ref` recorded where clippy can read it (`userspace-dp/src/afxdp/umem/mmap.rs`):** added `#[expect(clippy::mut_from_ref, reason = "SAFETY: see # Safety above; AF_XDP single-writer")]` on `slice_mut_unchecked`. `expect` (not the issue's `allow` option) so a future refactor that stops triggering the lint (e.g. a `NonNull` return) reds as `unfulfilled_lint_expectations` instead of leaving a stale suppression. The documented `# Safety` contract (AF_XDP single-writer / owner-worker discipline) is unchanged; no signature or caller changed.
2. **`never_loop` test rewritten as a real bounded loop (`export_slice_batched_window_15950_tests.rs`):** the old `for _ in 0..16 { …; break; }` always broke on its first pass and re-cloned the window each pass. It now adopts the drained window on the first pass (`std::mem::take` of `export_window_sequences`/`export_owner_rgs`, `kick_epoch.take()`), then keeps driving the adopted in-flight `worker_export` with no fresh commands until it clears, at most 16 passes; the trailing assertions (only RG2 shipped under token 2, ack == 2, `worker_export.is_none()`) are unchanged and still fail (not hang) if clearing regresses. Comment rewritten to say exactly that.
3. **E0308 blocker fixed (`shared_umem_tests.rs`):** the snapshot-level cell in `shared_umem_mode_unknown_falls_back_off_17149` originally built `userspace` via `serde_json::from_value(json!({…}))` with `.expect(...)` (test-only; no production change). At the fold's master merge, master's #18234 `typed_userspace(SharedUmemSnapshot { … })` helper superseded that hunk, so the merge kept master's typed construction and dropped the `from_value` form.
4. **All 246 `allow(clippy::…)` converted to `#[expect(…)]` with a reason, then pruned by the oracle:** every `too_many_arguments`/`type_complexity` suppression now reads `#[expect(clippy::…, reason = "#17200: …; census in docs/log/17200.md")]`. Running clippy then reported 26 `unfulfilled_lint_expectations` — suppressions on functions that no longer (or never did, in the counted configuration) exceed the lint threshold — and those 26 attributes were **deleted** (the functions keep no suppression at all; e.g. `publish_conntrack.rs`'s doc-only helper, `reverse_snat_case_13652`'s return type). Final census: 0 `allow(clippy::`, 221 `expect(clippy::` (218 `too_many_arguments` + 2 `type_complexity` + 1 `mut_from_ref`). `unfulfilled_lint_expectations` is warn-level, so the gate denies it explicitly (`-D unfulfilled_lint_expectations` in leg 1; see item 6) — a stale expect anywhere now reds the gate, which is the falsifiability the issue asks for. (`-D warnings` is not used: leg 1 carries ~2.7k other warn-level warnings.)
5. **Deny-pass blockers fixed (so `-D clippy::correctness -D clippy::suspicious` is green, not just prescribed):**
   - 37× `empty_line_after_doc_comment` / `empty_line_after_outer_attribute`: removed the blank line detaching a doc comment or attribute from its item (docs merge onto the item they describe; no text changed). This is the doc-detachment class vq14 cited clippy as the sole detector for.
   - 1× `duplicated_attributes` (`nat/allocator/occupancy.rs`): removed the second `#[inline]` on `occupancy_next_probe` (the first, above its doc comment, remains).
   - 8× `drop_non_drop` (suspicious): removed no-op `drop()` calls on values with no `Drop` (`xsk_ffi::User` in `bind.rs` ×3 — the fd is closed by the socket delete, noted at each site; `InlineTxTarget` borrows in `flow_cache_hit.rs`; two `BarrierWaitResult`s → `let _ = …wait();` in `ipsec_sa.rs`; a closure and a `TelemetryContext` in tests), each with a comment stating the borrow/scope end it marks.
   - 1× `redundant_clone`-class redefinition (`nat/tests_pool.rs`): removed `let addrs2 = addrs2;` (array is `Copy`; the `move` closure captures it per iteration unchanged).
   - `clippy::duplicate_mod` is **allowed for the deny pass only** (`-A clippy::duplicate_mod` in the recipe, rationale in the Makefile comment): the shim-parity tests deliberately `#[path]`-load the same `userspace-xdp/src/*.rs` file from several test modules so each executes the real shim source on the host. That intentional multi-load is the parity harness, not a duplicate production module; converting it to `use` would delete executed parity coverage.
6. **Gate (`Makefile` + CI):** new `make clippy-rust` target (pinned toolchain via `dp-toolchain.sh` + linked-libs stamp, like `test-rust`): (a) leg 1 `cargo clippy --workspace --all-targets -- -D unfulfilled_lint_expectations` must exit 0 — the targeted deny is what makes a stale `#[expect]` gating, because that lint is otherwise warn-level and would stay green among ~2.7k warn-level warnings; (b) leg 2, the same run with `-D clippy::correctness -D clippy::suspicious -A clippy::duplicate_mod`. Fold proof on pinned 1.98.1 (see Validation): planting a stale `#[expect(clippy::too_many_arguments)]` on `slice_mut_unchecked` made `make clippy-rust` exit 101 (`error: this lint expectation is unfulfilled … requested on the command line with -D unfulfilled-lint-expectations`, `Makefile:595: clippy-rust Error 101`); removing it restored exit 0 (both legs). Not wired into `make test` (heavy cold clippy build). `.github/workflows/test.yml` rust job gains a `Clippy Rust workspace and all targets (#17200)` step running `make clippy-rust` beside the all-targets compile check (with `CARGO: cargo` so the runner's rustup shim, not `$HOME/.cargo/bin/cargo`, resolves the pin). `docs/ci-gate-contract.md`'s Rust row now names the clippy gate.

## Risk

Behavior-preserving. The only production-code edits are attribute conversions/deletions, doc-comment blank-line removals, one duplicate `#[inline]` removal, and no-op `drop()` removals on non-`Drop` values (each site's drop order/borrow end is preserved by scope exit and noted in a comment); `slice_mut_unchecked`'s signature and safety contract are untouched. Test-only edits: the #15950 loop rewrite (same assertions, now genuinely multi-pass capable), the `shared_umem` snapshot construction (master's `typed_userspace` after the fold merge), `let _ = barrier.wait()`, and the `addrs2` rebinding removal. Residual: clippy warn-level noise (~2.7k warnings) remains visible but non-gating by design except for the targeted `unfulfilled_lint_expectations` deny; a future lint-threshold or signature change that makes an `expect` stale will red `make clippy-rust` leg 1 — that is the intended falsifiability, and the fix then is to delete the stale attribute in the same change. `duplicate_mod` stays allowed only in the deny pass and only because the parity harness's multi-load is deliberate; a new production duplicate module would still surface as a plain-run warning. CI timeout note: the rust job's `timeout-minutes: 20` may be tight for the two-leg `make clippy-rust` (locally the two legs took ~28 min wall under heavy parallel load; a cold CI run could approach or exceed 20 min) — the Makefile has no timeout knob, so if CI times out the fix is raising `timeout-minutes` in `.github/workflows/test.yml`, not a Makefile change.
