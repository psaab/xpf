# #17184 — R4-Q37-03: `rpcArgumentForms` bare-charge fallback escapes argument-scoped denies

- **Timestamp**: 2026-10-27
- **Defect (live on origin/master 59e7f8b)**: `rpcArgumentForms`
  (`pkg/grpcapi/authz_command_args_16067.go`) returned the bare charge
  for every RPC not in its hand-enumerated switch, with no census.
  Four RPCs with operator-typed arguments escaped argument-scoped
  denies: `GetNATDeterministic{InternalHost}` under
  `^show security nat source deterministic-nat internal-host 10\.0\.0\.5`,
  `ClearDHCPClientIdentifier{ge-0/0/1}` under
  `^clear dhcp client-identifier interface ge-0/0/1$`,
  `MonitorPacketDrop{SourcePrefix 10.0.0.0/8}` under
  `^monitor security packet-drop source-prefix 10\.`, and
  `GetNATRuleStats{rs1}` under `^show security nat source rule-set rs1`
  — all ALLOWED pre-fix (measured with a temporary probe test, since
  removed). The REST twin (`pkg/api/authz_command_args_16067.go`) had
  the same default. The #16378 fold had already caught five more RPCs
  in the same default.

## What

- **gRPC (`pkg/grpcapi/authz_command_args_16067.go`)**: added arms for
  `GetNATDeterministic` (forward `internal-host`, reverse
  `nat-ip`/`nat-port`, optional `pool`; unspecified direction or
  missing/out-of-range selector is unnameable), `ClearDHCPClientIdentifier`
  (`interface <name>`; empty = clear-all bare charge),
  `MonitorPacketDrop` (all nine selectors in CLI field order;
  out-of-range port/count unnameable), and `GetNATRuleStats`
  (`rule-set` built from the family prefix — it is a sibling of the
  charge's `rule` leaf, not a suffix — plus `rule <name>` on the
  charge; both present judges both spellings). Removed the bare-charge
  default: the switch now ends in `return nil, false`, preceded by a
  `methodsWithoutArgumentForms` lookup. That new map names every other
  served method with a reason its fields carry no operator argument
  text (config-mode/plumbing/request-decoded/config-read families
  included), mirroring `methodsWithoutCanonicalCommand`.
- **Census**: `TestEveryRequestFieldIsReconstructedOrNamedAbsent17184`
  walks `pb.File_xpf_proto`'s BpfrxService methods; the switch's case
  labels are read from production source via go/ast (the #5278
  discipline). Every served method must be in exactly one of
  {switch case, named-absent map with non-empty reason}; stale entries
  in either direction fail; and a named-absent method with a FIXED
  charge whose request field is spelled as (or hyphenates to) an
  option keyword of its charge's cmdtree subtree fails — vocabulary
  harvested from the real tree, never hand-listed. Adapted from the
  issue's per-field sketch to per-method classification, because the
  descriptor cannot distinguish request-family fields (e.g. `Set.input`
  IS the adjudicated path) from argument text; the vocab sub-check
  restores the per-field tripwire where a mechanical oracle exists.
- **REST twin (`pkg/api/authz_command_args_16067.go`)**: same rule.
  Added arms for `GET /api/v1/security/nat/deterministic`,
  `GET /api/v1/security/nat/rules?rule_set=`,
  `POST /api/v1/dhcp/identifiers/clear` (body interface via the
  buffered-body decoder; empty body = clear-all), and
  `GET /api/v1/security/events` (zone/protocol/action filters execute
  `show security log ...`, the twin of GetEvents — found by the new
  REST census, which refused to let it sit in the bare-charge default).
  Every other charged route is named in
  `restRoutesWithoutArgumentForms`; the default ends in
  `return nil, false`. `TestEveryRESTRouteInputIsReconstructedOrNamedAbsent17184`
  censuses restRouteCommand against the switch (AST) and the map.
- Deleted the stale #15076 comment claiming rule-set "stays dropped";
  `natRuleStatsCanonicalCommand` now notes it prices only the family.
- Registered argument samples for the new shapes on both surfaces so
  the #7172/#9340 commit advisory can witness them (the issue's
  unwarned `ge-0/0/1` / `rs1` cross-command patterns now match
  reconstructed forms).

## Risk

- Fail-closed direction only: an unlisted/future RPC or route now
  DENIES for a regex-restricted class instead of silently allowing.
  Classes with no operational regexes are untouched (gate returns
  before this code). The census turns that runtime denial into a
  build-time failure naming the method.
- `GetNATRuleStats` with both selectors is judged on both CLI
  spellings (no on-box line carries both; the handler applies both
  server-side). Forms[0] is the rule-set spelling.
- REST events: `limit` is validated to the handler's exact contract
  (strict parse AND the >10000 cap, #4926) but not spelled (no on-box
  events command the gate reconstructs carries a count under the
  `show log` charge; GetEvents' limit is likewise unspelled).

## Fold (Rev18237Opus, post-review)

- **B1 (blocker)**: the new `(nil,false)` REST default also fired for
  request-decoded routes (`GET routing/bgp`, `system/info`,
  `POST system/action`, `security/nat/rules`), which are neither
  switch cases nor named-absent: `evaluateRESTForms9952` called
  `restArgumentForms` with the per-request resolved cmd and got
  unnameable, so restricted classes were denied even under their own
  allow (`TestBGPRoutesAndNATSelectorsChargedPerRequest15076` controls
  failed). Fix: `restArgumentForms` returns the bare, fully-resolved
  charge for `isRequestDecodedRoute9952` routes before the switch
  (show-text falls through to its packed-parameter arm; NAT
  `?rule_set=` is still spelled), and the REST census gains a
  request-decoded arm over `restRoutesNoCommand` (declared there, no
  fixed charge, not named-absent, no dead outer-switch case).
- **M1**: Ping `count`/`size` now spell at executed (clamped) values
  on both surfaces (`ping <host> count <N> size <N>`), with advisory
  samples registered.
- **M2**: handler-rejected ping/traceroute string fields
  (>diagcmd.MaxArgLen, #6904) are unnameable on both surfaces rather
  than spelled as a command that never runs.
- **M3**: REST events `limit` validation now includes the handler's
  >10000 cap (comment above corrected to the exact contract).
