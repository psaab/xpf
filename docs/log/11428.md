# #11428 — synthesize a lowest-priority CoS default

- **Timestamp**: 2026-10-01
- **Action**: A scheduler-map without best-effort gets a synthetic best-effort
  queue at an unused queue id (queue 0 when available). Default selection
  chooses the lowest-service-priority queue, preferring best-effort among ties.
  If every queue id is occupied and the map has neither best-effort nor any
  low-priority queue, snapshot construction fails closed instead of defaulting
  unclassified traffic to an expedited queue.
- **Validation**: The q5-EF/q7-NC default and unclassified-traffic cells failed
  before the fix (`default_queue` was 5; unclassified TX selected `Some(5)`); an
  explicit-priority conflict cell also failed (`0` instead of `7`). With the
  queue-id space full and no lower-priority queue, the builder also accepted
  the invalid map when its fail-closed guard was removed. All four cells pass
  with the fix. All 81 CoS classifier tests and 186 forwarding-builder tests
  passed; the latter excludes the pre-existing
  `next_table_target_uses_table_lpm_without_rule_restart_9955` failure, which
  also fails with the CoS change reverted to its baseline implementation.
  `cargo check`, `go build ./...`, `go test -count=1 ./pkg/refactoraudit/`, and
  scoped Rust formatting checks passed.
