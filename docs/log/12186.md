# #12186 — equivalent OSPF area interface deduplication

- **Timestamp**: 2026-10-08 (`fix/12186-ospf-area`, base `a714c90d472a3c3d98a3799831cfef3ec311a61c`)
- **Action**: render one FRR interface block when an interface is configured under equivalent integer and dotted-quad area IDs.

## Red before

The STEP-0 renderer repro on the clean base emitted two `interface eth0` blocks for both `0`/`0.0.0.0` orderings. The output repeated area activation and carried conflicting costs and simple-password keys in successive blocks. `TestOSPFAreaInterfaceReuseEquivalentIDsAccepted11400` also passed on base, confirming that strict validation accepted the equivalent IDs.

Added `TestOSPFAreaEquivalentIDInterfaceDedupe12186` before the implementation. Its OSPFv2 and OSPFv3 cases failed in both area-ID orderings: each rendered two interface blocks instead of one.

## Change

- OSPFv2 and OSPFv3 rendering now emit the first interface block only. Differing-area duplicates still warn and keep the first area; equivalent area IDs no longer produce repeated interface contexts.
- OSPFv2 passive directives remain a union across same-area fragments and are emitted once. OSPFv3 passive state is gathered across equivalent-area fragments before its single interface block is emitted.
- The regression covers both ID orderings, one interface block, first-fragment cost/auth selection, passive union, and the OSPFv3 mirror.

## Validation

- **RED before**: `go test ./pkg/frr -run '^TestOSPFAreaEquivalentIDInterfaceDedupe12186$' -count=1 -v` failed for both OSPF versions and both area-ID orderings, reporting two blocks each.
- **GREEN after**: `go test ./pkg/frr -run '^(TestOSPFAreaEquivalentIDInterfaceDedupe12186|TestOSPFInterfaceAreaReuseRendererKeepsFirst11400)$' -count=1 -v` passed all new cases and the existing cross-area keep-first renderer test.
- **Strict gate**: `go test ./pkg/config -run '^TestOSPFAreaInterfaceReuse' -count=1 -v` passed rejection of cross-area reuse, lenient warning, and equivalent-ID acceptance.
- `go build ./...` passed. `gofmt -l` on both touched Go files was empty, and `git diff --check` passed.
- Full `go test ./pkg/frr -count=1` was blocked by three FRR config-load tests failing with `privs_init: could not setgroups, Operation not permitted`. The same three tests on a clean `a714c90d4` worktree produced the identical errors; other tests in the package run passed.
- No live-cluster mutation or live FRR daemon acceptance was performed.

## Residual / risk

Equivalent area fragments now use the first fragment's interface settings (including cost/auth); OSPFv2/OSPFv3 passive state remains unioned. Live FRR daemon merge behavior was not exercised. The three privileged FRR test failures are environment limitations reproduced on the base revision.
