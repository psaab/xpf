# #15651 — Port-mirroring interface resolution uses raw `LinuxIfName` instead of `ResolveKernelIfName`

- **Timestamp**: 2026-10-19
- **Action**: resolve port-mirroring refs through the config kernel-name resolver on all three planes and reject aliased duplicate ingress at commit.

## Why

- `buildMirrorConfigSnapshots` (`pkg/dataplane/userspace/mirrors.go`) indexed only `iface.Name`/`iface.LinuxName`. A unit row's `LinuxName` is the kernel device (unit 0 collapses onto the parent; a VLAN unit is `<parent>.<vid>`), so the Linux unit spelling `ge-0-0-0.0` matched neither key and the mirror silently disappeared; Junos/VLAN/RETH spellings needed `cfg.ResolveKernelIfName` against the compiled interfaces.
- Legacy `pkg/dataplane/compiler.go:compilePortMirroring` used `config.LinuxIfName(inst.Output/Input)` — slash translation only — so a Junos unit ref `ge-0/0/0.0` named no kernel device and the input was warn-skipped.
- `compilePortMirroring` (`pkg/config/compiler_services.go`) deduped ingress on `LinuxIfName(v)` before interface stanzas exist, so `ge-0/0/0` (bare) vs `ge-0/0/0.0` (unit 0) — the same kernel device via `ResolveKernelIfName` — compiled as distinct sources in different instances and collided on one ifindex downstream (legacy `mirror_config` is keyed by bare ifindex, so the second write overwrites the first).

Narrowed scope (codex-b): the userspace builder's scoped key `(ifindex, VLAN, unitScoped)` (#15113) already distinguishes bare physical from logical unit 0 — this change preserves that (bare and unit-0 stay distinct userspace rows) while the commit gate rejects the alias, because the legacy plane cannot represent both.

## What

- `pkg/dataplane/userspace/mirrors.go`: index the Linux unit spelling `LinuxIfName(iface.Name)` for unit rows (with the row's own scope); fall back to `cfg.ResolveKernelIfName(ref)` for output and input when Name/LinuxName/LinuxIfName all miss.
- `pkg/dataplane/compiler.go`: new `mirrorKernelName` — `resolveInterfaceRef` physical base + VLAN child (`<phys>.<vid>`) for tagged units, `ResolveKernelIfName` for dotted unit/tunnel devices the base cannot express; `compilePortMirroring` uses it for output and input instead of `LinuxIfName`.
- `pkg/config/compiler_validate_strict_observability.go`: `validatePortMirroringIngressAliasStrict` — post-section gate normalizing every instance input through `ResolveKernelIfName`; duplicate across (or within) instances is an error naming both instances.
- `pkg/config/compiler_uniformgates_sampling_appset.go`, `compiler_opts.go` (`lenientPortMirroringIngressAlias15651`): wire the gate beside the sampling-rate gate; strict rejects, tolerant load/peer-sync warns (#1960 — the userspace scoped duplicate check still scope-drops at runtime).
- Tests: `pkg/dataplane/userspace/mirror_resolve_15651_test.go` (Linux unit spelling, VLAN unit, RETH unit resolve to correct ifindex/scope; bare vs unit-0 stay distinct), `pkg/config/mirror_alias_15651_test.go` (aliased bare vs unit-0 rejected naming both instances; distinct-unit control compiles), `pkg/dataplane/mirror_resolve_15651_test.go` (legacy compiler programs `lo.0`; `mirrorKernelName` table).

NOT changed: `compilePortMirroring`'s inline `LinuxIfName` dedup (still catches Junos-vs-Linux cross-spellings before interfaces exist), wire formats, Rust, the #15113 scoped-key semantics.

Resolution fallbacks only run when the previous lookups missed, so existing spellings resolve identically.
