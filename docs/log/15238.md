# #15238 — policy simulator / shadow-check fidelity cohort (A55-01, A55-02, A55-03)

- **Timestamp**: 2026-10-19
- **Action**: Fixed three advisory-fidelity defects in `pkg/policymatch`:
  (A55-01) the cross-tier shadow pass walked the single-wildcard tier in
  lexical pair order instead of config order, naming the wrong coverer
  and downgrading SHADOWED to REDUNDANT; (A55-02) `show security
  match-policies` reported a plain permit for flows the userspace helper
  drops at its transit source/destination martian gates before policy;
  (A55-03) `globalScopeSetMatches` tested raw `cfg.Security.Zones`
  membership, so a global scoped only to a quarantined zone matched in
  the simulator while the published snapshot contains zero such rules.
- **File(s)**: `pkg/policymatch/policy_shadowing.go`,
  `pkg/policymatch/policymatch.go`,
  `pkg/policymatch/cohort_15238_test.go` (new), `docs/log/15238.md`

## Mechanisms (verified at base c2b708b33c, origin/master)

- **A55-01**: `analyzeCrossTierGlobalShadowing`
  (`policy_shadowing.go`) received `pairs` lexically sorted by
  (FromZone, ToZone). Its tier loop (added by #12893) enforced exact →
  single-wildcard → both-any precedence, but *within* tier 1 it still
  iterated the sorted pairs and took the first superset coverer.
  `("any","untrust")` sorts before `("trust","any")`, so with
  `trust→any` deny authored first and `any→untrust` permit second, the
  permit was recorded and the scoped global reported REDUNDANT, while
  the runtime (Match tier 2, and the dataplane's two-pointer merge by
  global rule index) evaluates the deny first — SHADOWED is the true
  reading, and SHADOWED is the dangerous class the advisory exists to
  surface.
- **A55-02**: `Match` stamped the route-drop advisory only from
  `routeDropClass(cfg, q.DstIP)` — destination-only, and only
  multicast / limited broadcast / unspecified / loopback / connected
  directed broadcast. The helper's transit gates
  (`userspace-dp/src/afxdp/frame/addr_class.rs`
  `transit_src_is_martian` / `transit_dst_is_martian`, applied
  pre-policy for transit dispositions in
  `poll_descriptor/mod.rs` `transit_source_class_drop` /
  `transit_destination_class_drop`) additionally drop, on the source
  side: IPv4 0/8, 127/8, 169.254/16, 224/4, 240/4 (incl. broadcast) and
  connected directed broadcasts, IPv6 `::`, `::1`, ff00::/8, fe80::/10;
  and on the destination side the same plus IPv4 directed broadcasts.
  None of the source classes, and none of the destination
  this-network / link-local / reserved classes, carried any advisory —
  the simulator answered a plain permit for a flow the box drops.
- **A55-03**: the host-global tier in `matchJunosHostWithMemo` selects
  `match to-zone junos-host` globals, then gates the from-zone scope
  through `globalScopeSetMatches`, which accepted any element present
  in the raw `cfg.Security.Zones` map. A global scoped only to z214
  (the later-sorting StableZoneID collision loser vs z174, quarantined
  on lenient/HA loads) therefore matched, while the snapshot builder
  drops exactly that rule (`walkPolicyRuleSlots`
  `globalScopeFullyQuarantined`; `scrubPoliciesForQuarantinedZones`)
  and the published snapshot has zero rules for it. The simulator said
  the host-inbound deny governs; the runtime applies none — the unsafe
  reading direction. The transit global tier shares the helper and the
  same defect.

## Fix

- **A55-01** (`policy_shadowing.go`): the tier walk now iterates
  `cfg.Security.Policies` (authored order) instead of the sorted
  `pairs`. Runtime tier precedence is preserved (the `tierOf` gate is
  unchanged and exact/both-any occur in at most one wildcard shape per
  pair), and within tier 1 the first coverer is now the authored-first
  single-wildcard stanza, matching Match tier 2's config-order merge.
  `pairs` is still used for the within-pair and cross-tier passes as
  before.
- **A55-02** (`policymatch.go`): `routeDropClass` is replaced by one
  shared classifier, `transitMartianClass(cfg, ip)`, mirroring both
  Rust martian sets, plus `routeDropClassForQuery`, which tests the
  source side first (the helper's source gate precedes the destination
  gate on the new-flow path) and then the destination. New class
  spellings: `this-network` (0.0.0.0/8), `link-local` (169.254/16,
  fe80::/10), `reserved` (240/4 beyond the limited broadcast, which
  keeps `broadcast`). An unspecified destination keeps the established
  #4373 `unspecified` spelling (0.0.0.0 also satisfies the v4
  this-network arm, so the dst side special-cases it). Directed
  broadcasts keep `directed-broadcast` on either side via the existing
  domain-free static connected-prefix scan (the simulator has no
  routing domain; the Rust index is domain-scoped — a documented
  simulator approximation, unchanged from #11004). The stamp remains
  advisory-only (Matched/Action/DefaultUsed untouched), host-bound
  queries remain exempt, and nil src/dst (operator-omitted sides)
  remain unclassified. `RouteDropNote` now says "address is … transit
  traffic with this address" instead of "destination is …" so the one
  SSOT note is true for source-side stamps; the directed-broadcast
  sentence likewise says "address is".
- **A55-03** (`policymatch.go`): `globalScopeSetMatches` now skips
  scope elements in `quarantinedZoneNames(cfg)`
  (`config.ZoneQuarantineExclusionsForConfig` — the same exclusion set
  `zoneKnown` and the snapshot builder use). A fully-quarantined side
  therefore matches nothing; a mixed scope still matches on its
  surviving members. Wildcard scopes (empty / `any`) are unchanged.

Not changed: any Rust code, the snapshot builder, policy evaluation
order, verdicts (the martian stamp is advisory), or the cross-tier
pass's tier/partial-coverage logic beyond the tier-1 iteration order.

## Risk

Bounded to simulator/advisory fidelity. A55-01 changes only which
coverer the shadow advisory names (and the SHADOWED/REDUNDANT label
that follows from it) when two single-wildcard stanzas cover the same
scoped-global pair. A55-02 adds advisory stamps to previously
unstamped martian-source/destination verdicts; no verdict changes.
A55-03 narrows `globalScopeSetMatches` exactly by the runtime
quarantine set, so simulator and published snapshot agree; configs
without quarantined zones are byte-identical.
