# #10084 LoadMergeAs hierarchical leaf-bracket provenance — engineering history

Issue: psaab/xpf#10084 (`LoadMergeAs` hierarchical input drops leaf bracket
provenance through `FormatSet`, so `policy-options as-path AP1 [0-9]+`
becomes `0-9 +` and passes the #9881 strict gate). Lane branch:
`fix/10084-loadmerge`.

## Scope and precedent

Issue #10084 has no comments and remains open. Its mechanism and acceptance
follow #9881: the hierarchical parser records `Node.KeysBracketed`, but the
hierarchical `LoadMergeAs` branch renders through `FormatSet` and replays flat
lines through `applyEditLine`. `nodeKeyBracketMask` intentionally returns nil
for leaves, and the pinned single-key-run rule emits those keys bare. The
public `FormatSet` / `display set` path therefore remains unchanged; only the
merge replay needs a lossless internal spelling.

The #6668 pin (`TestBracketedValueLeavesRenderUnchanged_6668`) was not
re-scoped or broken. The issue's unaffected paths remain unaffected: raw
hierarchical `load override`, flat load paths, direct parser/sync paths, and
operator display rendering.

## Fix

`ConfigTree.FormatSetForLoadMerge` is a merge-only renderer. It keeps public
`FormatSet` on the #6668 zero-churn path while carrying positive leaf bracket
provenance into replay lines. A one-key leaf bracket is emitted as a singleton
`[ ... ]` group only for this internal renderer, for example:

```text
set policy-options as-path AP1 [ 0-9 ] +
```

`LoadMergeAsPlantClass` uses that renderer for its hierarchical branch. The
existing grouped parser/setter then restores `KeysBracketed` on the replayed
leaf, allowing the existing #9881 strict diagnostic to reject the mangled
regex. Bare leaves remain bare and the public display output remains exactly
unchanged.
