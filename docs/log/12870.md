# #12870 — preserve thresholds across repeated SYN-flood clauses

- **Issue**: https://github.com/psaab/xpf/issues/12870 (research D7-02, High)
- **Base**: `0f19ca45a` (`origin/master` when the assigned worktree was updated)
- **Why**: `compileScreen` allocated a new `SynFloodConfig` for each hierarchical `tcp syn-flood` child, then replaced the profile field. Sibling clauses defining disjoint thresholds therefore erased one another; depending on order, an omitted attack threshold could also leave only the default `200` rather than retain earlier configured attack/source thresholds.

## Change

`compileScreen` now reuses the profile's existing `SynFloodConfig` when processing another `syn-flood` clause, allocating a config only for the first one. Per-leaf last-authored precedence and the existing attack-threshold default remain intact. Added strict/lenient regressions covering multiple sibling blocks and lines, reverse order, empty enable clauses, defaults, repeated-leaf override, profile isolation, flat-set equivalence, and invalid/unknown leaf diagnostics.

## Validation

- **Base RED**: `GOCACHE=/tmp/go-12870-cache GOTMPDIR=/tmp go test ./pkg/config -run 'TestSynFloodRepeated12870' -count=1` failed before the fix with earlier thresholds lost in both strict and lenient compilation. For example, three sibling clauses produced `{AlarmThreshold:90 AttackThreshold:200 SourceThreshold:0 DestinationThreshold:0 Timeout:15}` instead of preserving the configured thresholds. The same expected loss occurred for reversed order and empty/default/repeated-leaf cases.
- **Focused regressions**: `GOCACHE=/tmp/go-12870-cache GOTMPDIR=/tmp go test ./pkg/config -run 'TestSynFloodRepeated12870' -count=1` passed after the fix; `GOCACHE=/tmp/go-12870-cache GOTMPDIR=/tmp go test ./pkg/config -run 'TestSynFloodRepeated(Diagnostics)?12870' -count=1` passed, covering strict rejection and lenient warning for invalid/unknown leaves while retaining valid thresholds. After formatting, `GOCACHE=/tmp/go-12870-cache GOTMPDIR=/tmp go test ./pkg/config -run 'TestSynFloodRepeated(12870|Diagnostics12870)' -count=1` passed.
- **Vet/build**: `GOCACHE=/tmp/go-12870-cache GOTMPDIR=/tmp go vet ./pkg/config` and `GOCACHE=/tmp/go-12870-cache GOTMPDIR=/tmp go build ./pkg/config` both passed.
- **Full config package**: `GOCACHE=/tmp/go-12870-cache GOTMPDIR=/tmp go test ./pkg/config` did not pass. It reported failures in existing unrelated inventory/parser/schema/routing-instance tests (including `TestFlatSetChainWalkRatchet8939`, `TestInventoryDropShapeMatchesTheLiveCensus8662`, `TestMultiLeafSelfRepeatIsRefused9027`, `TestSystemConfigWebManagementEnhanced`, and `TestPackedRoutingInstanceSurvives8787`), then hit the package's 10-minute test timeout in `TestSchemaSpellingDifferentialGate`. These failures were not investigated as part of this issue; only the focused repeated-SYN-flood tests passed.

## Risk

Only hierarchical sibling `syn-flood` clause accumulation changes. Each profile remains independently allocated, an explicit repeated threshold still takes the last authored value, invalid leaves continue to follow the existing strict/lenient diagnostic policy, and an unset attack threshold retains the existing default.
