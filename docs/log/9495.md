## Implementation (fix/9495-swanctl-section-name-gate)

### Decision

The issue's fix direction, grounded in the measurement above:
- **A commit ALLOWLIST** (`ipsecname.SectionSafe`: ASCII letters, digits, `-`, `_`), in the `ValidateInterfaceName` style. A denylist would have to anticipate every character strongSwan's parser or a later consumer treats specially.
- **A render belt** (`ipsecname.SectionBreaking`) that skips a name measured to break the file, with a warning, on the tolerant path. It is deliberately NARROWER than the allowlist: names that loaded verbatim (`/`, `@`, `+` ...) are refused at commit but keep rendering when persisted, so an upgrade does not take down a tunnel that works today.
- **`ipsecname.ChildBase` maps `.` to `-`.** A dotted selector name broke the whole file. Every other character was already mapped, so selector names need no commit gate.

### Prior decisions whose premises this removes

- **`TestIPsecVPNNameMustBeDisplaySafe9623`** accepted a VPN name containing U+202E at commit. It is display-safe, so #9623's property holds and #9623 stays silent. But the measurement shows strongSwan refuses a non-ASCII VPN name (exit 22), and the #9495 allowlist now refuses it. The cell now separates the COMMIT outcome (`reject`) from the #9623 warning (`displayUnsafe`); for that row alone they differ.
- **`TestSANameIndexKeysEligibilityByVPNNotSanitizedName9511`** needed connection `x y` to render beside a tab-named VPN that sanitises to the same string.
  - Two distinct names can only sanitise alike when a C0 byte becomes a space, and a space breaks the section. So the belt skips both, and neither is indexed or can borrow the other's eligibility.
  - The cell now asserts exactly that. Per-VPN keying stays pinned by the unrelated-render-error cell.

### Cells

- **`TestSectionNamePredicates9495`:** both predicates against every measured row, including the loads-today `a/b` and `a@b`.
- **`TestChildBaseMapsDot9495`:** `t.s` maps to `t-s`, and a safe name is unchanged.
- **`TestIPsecVPNNameMustBeSectionSafe9495`:** commit refuses each measured breaking name and `a/b`, with a message naming the VPN, and accepts `vpnplain` and `vpn-1_a`. The tolerant path warns and keeps the VPN.
- **`TestSectionBreakingNameIsSkippedAndTheFileStillLoads9495`:** for each hostile name beside `plain`, the rendered document parses, with connections exactly `[plain]`, secrets exactly `[ike-plain]`, and no `transport` value anywhere. It asserts through the parsed document, as #6824 requires.
- **`TestLoadsTodayNameStillRenders9495`:** a persisted `a/b` still renders its connection and secret.
