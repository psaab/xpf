# Issue #13145 — D2-14 host-inbound advisories

## Finding

The research-validated D2-14 report identified three inaccurate or missing host-inbound advisories in `pkg/config/compiler_validate_warn_host_inbound.go`:

- The #7374 application-gap check treated zone-pair `from-zone any` as a literal zone name, so the lookup returned nil and missed every applicable gap.
- Global `to-zone junos-host` application-gap checks scanned all zones regardless of the global policy's `match from-zone`, and included quarantined and lifeline-only zones where the ordinary direct host-bound path does not apply.
- The #6515 override advisory compared the interface replacement against raw zone-level services, even where #7490 withholds DHCP services from the effective zone-level set on a DHCP server interface.

These are advisory-only corrections. Valid Junos configurations remain accepted.

## Change

- Expand `from-zone any` across sorted, non-quarantined zones with ordinary host-inbound paths before checking application coverage.
- Restrict global-policy gap checks to matching `from-zone` scope and ordinary, non-quarantined source zones.
- Compare an interface override against `ZoneLevelSystemServicesFor(..., ref)`, preserving #7490's per-interface effective zone-level service set.
- Add fail-on-regression tests for wildcard zone-pairs, global scopes, lifeline-only zones, DHCP withholding, and a genuine override loss.
