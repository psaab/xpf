# Issue #18810 — pin both publish lock-count legs

- **Timestamp**: 2026-11-05
  - **Action**: Split the publish lock-count pin into no-NAT and NAT-ful legs; reproduce, validate and record mutant evidence.
  - **File(s)**: `userspace-dp/src/afxdp/session_glue/newflow_contention_tests.rs`, `docs/log/18810.md`

## Why

`publish_shared_session_counts_calls_and_lock_acquisitions` failed on master because its no-NAT fixture expected at least three counted acquisitions, but only two shared maps were locked. Commit `48b24754cc` (#14746, #14383) made the forward-wire map lock conditional on `forward_wire_key != entry.key`; the fixture did not exercise that NAT-specific leg. The test must preserve the three-lock guarantee for NAT-ful publishes while describing the two-lock no-NAT contract separately.

## What

- Reworked the named test into explicit no-NAT and NAT-ful legs.
- The no-NAT leg asserts exactly 2 acquisitions and one counted publish; the NAT-ful leg asserts exactly 3 acquisitions and one counted publish, with fixture assertions confirming whether a forward-wire alias exists.
- Kept the lock-count assertions local to each leg; no global `>= 3` assertion was weakened to `>= 2`.

## Validation

- Reproduced on unmodified master with `CARGO_TARGET_DIR=/var/worktrees/.cache/cargo-18810 cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp afxdp::session_glue::newflow_contention_tests::publish_shared_session_counts_calls_and_lock_acquisitions -- --exact --nocapture`: the cell failed, expecting `>= 3` acquisitions and seeing 2.
- `CARGO_TARGET_DIR=/var/worktrees/.cache/cargo-18810 cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp afxdp::session_glue::newflow_contention_tests::publish_shared_session -- --nocapture` passed all three adjacent publish tests after restructuring and again after restoring the mutant.
- Hoisting the counted `lock_shared_publish(shared_forward_wire_sessions)` outside the `wire_key != entry.key` condition made the no-NAT leg fail first: it saw 3 acquisitions, expected exactly 2. This confirms the lock is conditional, but does not prove the NAT-ful leg's third acquisition.

The no-NAT leg passed; the named cell then failed on the NAT-ful assertion: expected exactly 3 acquisitions, saw 2 (`left: 4`, `right: 5`).
- Restored the scratch source and removed the scratch worktree. The named cell passed after restoration.
