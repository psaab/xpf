# #17704 - Require alias rescues to outrank sibling denies

- **Timestamp**: 2026-10-28
- **Action**: Cross-spelling rescue for RPC aliases now requires an affirmative allow to match a strictly longer extent than each sibling tier-deny. A request-discriminated typed line remains eligible for the existing exact-execution exception; an ambiguous request no longer treats its fixed charge as proof of which spelling ran.
- **File(s)**: `pkg/config/login_regex_scope_7172.go`, `pkg/grpcapi/authz_alias_forms_16605.go`, `pkg/grpcapi/authz_command_gate_7172.go`, `pkg/grpcapi/authz_alias_forms_16605_test.go`, `docs/log/17704.md`
- **Validation**: The new `TestAliasRescueRequiresOutrankingAllow17704` failed against the pre-fix rescue in all three cells: a longer deny was rescued by a shorter allow, a longer sibling allow could not rescue a shorter charge deny, and an equal-extent allow rescued an equal-extent deny. With the fix, the complete alias test file passed via:
  `GOTMPDIR=/tmp GOCACHE=/var/worktrees/.cache/go-build go test ./pkg/grpcapi/ -run '^(TestTypedLineDenyFires16605|TestAliasRescueRequiresOutrankingAllow17704|TestTypedLineDenyControls16605|TestTypedLineAllowlist16605|TestAliasFormsAreCanonical16605|TestAliasCommandsInSurfaceSet16605|TestAliasCensusComplete16605)$' -count=1`
  The same regression failed again when only the production rescue logic was temporarily reverted; the three expected failures were observed. Existing allowlist-only alias admission and discriminated-interface rescue/deny controls passed with the fix.
- **Risk**: Ambiguous shared-RPC calls can no longer use an allow on a shorter/equal sibling spelling to erase a tier-deny; strictly longer allows still express cross-spelling exceptions. Request-discriminated execution behavior and unrelated RPC gates are unchanged.
