# Issue #17860 — deferred prune can restore an obsolete selector after its slot is reused; the installed boot script skipped the collector (PR #17617 retro)

- **Timestamp**: 2026-10-27
  - **Action**: Two separable defects from the retro-review of merged PR
    #17617, both still live on `origin/master` (`61aa231da6`):
    1. **Reused-slot corruption.** `settlePruneOwed` checked only that the
      running kernel differed from the recorded candidate, then called
      `PruneInactiveSlot(rec.Slot, rec.KnownGoodVersion,
      rec.CandidateVersion)`, whose first act is restoring the recorded
      slot's selector to the debt's known-good. A later roll can REUSE that
      slot (Arm writes the new candidate's selector into the same inactive
      slot) and even promote it, making the debt's slot the running
      default: fail B/K1 → debt `{B,K0,K1}` → arm and PROMOTE K2 into B →
      the next ordinary boot's collector rewrote B's selector to K0 and
      silently abandoned the promoted K2 on the following reboot. The fix
      proves the debt still OWNS the slot: `settlePruneOwed` reads the
      recorded slot's selector and takes the full prune only when it names
      one of the debt's own versions (the known-good the deferring revert
      left, or — repair case, #5076 ordering — the debt's own candidate
      the revert failed to restore). Any other version means a later roll
      owns the slot: the new purge-only seam
      (`PurgeCandidatePackages`, the package/file half of
      `PruneInactiveSlot` behind the same #5452 segment validation and
      #14165 running-kernel refusal) collects the obsolete packages
      WITHOUT touching any selector. An unreadable selector proves
      nothing: the record is retained for a later boot, like the
      running-kernel checks.
    2. **Collector bypass (test-only-green acceptance).** Revert clears
      both the journal and the arm record, so the next ordinary boot hit
      `scripts/image/xpf-kernel-promote`'s "nothing to promote" quiet
      exit and NEVER reached the `xpfd upgrade kernel promote` exec —
      the #16811 acceptance (exactly one prune on boot 2) was delivered
      only by tests calling `r.Promote()` directly. The quiet branch now
      runs the collector when the journal is ABSENT (exactly the
      post-revert boot), resolving the binary through the same
      UNAMBIGUOUS-OR-NOTHING systemd hops the cross-check uses (MainPID →
      /proc/\<pid\>/exe, else ExecStart; deliberately no filesystem
      fallback, #6601 r5) and dispatching through a shared `gate_result`
      rc handler. A present non-trial journal keeps the quiet exit (the
      Go half defers terminal states itself, and a record-less ARMING
      boot must not get a gate run manufactured from journal state alone,
      #16809 — its Gate 2b would revert a healthy candidate, #6601 r6).
      When no xpfd resolves, the skip is loud (WARNING + facts) and the
      debt retries next boot — skipping a destructive prune is the safe
      direction.

  - **Risk**: low. The full-prune path is unchanged for every debt that
    still owns its slot (selector at the debt's known-good — the normal
    post-revert state, pinned by the #16811 suite); only the
    slot-repurposed and selector-unreadable shapes change, both toward
    the less-destructive direction. The purge-only seam reuses the exact
    purge payload (held-package purge, fail-safe dpkg re-queries,
    orphan sweep) behind the same admission checks, so no
    #5452/#5428/#5076/#14165/#16807 property depends on the restore
    half. The script change adds one exec on absent-journal ordinary
    boots only; its rc handling is the same shared dispatcher the armed
    path uses (exit 0 on every path, reboot only on rc 3). Residual: a
    debt stranded behind a present terminal/mid-run journal is still
    collected only on the next absent-journal boot, and on a box where
    systemd resolves no xpfd the collector retries each boot with a
    WARNING — both availability, not safety, properties.
