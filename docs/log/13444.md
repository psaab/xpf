# Issue #13444: Guard lifeline-only VRF fallback masters

Review of merged PR #13442 found that the direct fallback's negated
`iifname` match still included a VRF master when the master had only lifeline
members. That master-level rule matched before the lifeline-aware `sdifname`
fallback and dropped shared-address management replies.

The shared-address-only direct fallback now excludes lifeline VRF masters.
Non-shared addresses retain the original direct fallback, and ordinary
VRF-scoped fallback rules are emitted only when there are actual covered data
slaves; the shared-address VRF fallback unions the data and lifeline member
sets. The regression exercises a lifeline-only master and ordinary-address
fallback behavior.

Validation: `go test ./pkg/nftables -count=1` passed; `gofmt -l` reported no
changed files.
