# #12829 — enumerate every sibling zones block

- **Timestamp**: 2026-10-13 (`fix/12829-campaign-pub`)

## Why

`collectZoneNamesAST` used `securityNode.FindChild("zones")`, which returns only the first `zones` child. `compileSecurity` instead compiles every sibling `zones` node. A pair of zone names whose stable IDs collide could therefore be split across two `zones` blocks and pass the strict collision gate, while the tolerant runtime quarantine name union also omitted the second-block zone. The strict gate's purpose is to reject this ambiguity; tolerant handling must warn and include both runtime names so the later-sorting zone is quarantined.

## What

- Iterate every `zones` child under the supplied `security` node in `collectZoneNamesAST`, preserving the existing `bracketedGroupInstances8794` enumeration and set semantics.
- Add regression coverage for second-block enumeration, strict rejection of the frozen `z174`/`z214` colliding pair across sibling blocks, lenient warning and quarantine of `z214`, distinct-name sibling blocks, a single block, and nil/empty security roots.
- Scope cuts: no changes to `StableZoneID`, compiler zone aggregation, or dataplane quarantine behavior; only the name-collection input now matches the compiler's all-sibling behavior.
