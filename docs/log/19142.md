# #19142: vm-test-run.sh discloses runner pauses and the VM proof

- **Timestamp**: 2026-11-16
- **Action**: Scope, from team-lead: the `vm-test-run.sh` side of the issue,
  in the same branch as #19134 (same script, one bounded check).
  - Not done here: the host-side freeze ledger (ask 1) lives in the gate
    library's `runner_freeze`/`runner_resume`, outside this repo. The
    boot-time re-marking of runners (comment ask 2) is provisioning. Treating
    a SKIPPED kill target as VOID (comment ask 3) belongs to the mutation

- **Action**: `scripts/vm-test-run.sh`:
  - Every run ends with
    `vm-test-run: paused-for=<s>s (workstation <s>s, runner monotonic <s>s,
    heartbeat gaps <s>s)` on stderr. The issue's own evidence does not say
    whether the guest's monotonic clock stops or jumps across `incus pause`,
    so two clocks are read:
    - a 1 Hz heartbeat on the runner sums CLOCK_MONOTONIC gaps over 2 s (a
      jumping clock);
    - the workstation's `/proc/uptime` elapsed time minus the runner's
      monotonic elapsed time, less 2 s of exec overhead (a stopped clock).
    `paused-for` is the larger of the two. A nonzero value adds a VOID line;
    no clock record gives `paused-for=unknown`.
  - The heartbeat runs in the background of the command's shell, with its
    fds on /dev/null. It exits 0 on SIGTERM, so bash prints no job notice
    into the output, and it stops if its shell goes away. The command waits
    for the heartbeat's first record (up to 3 s), then runs in a subshell
    between newlines, so its own `exit` and a trailing `# comment` behave as
    before; its status is the run's.
  - The post-command read waits out a freeze in a soft mode that never
    replaces the command's status with 75.
  - `--root` prints `vm-proof=present|absent|unknown`, using
    testguard-run.sh's own test: `/run/xpf-testguard-vm-boot-id`, regular,
    not a symlink, `0 444`, holding the current boot ID. A root run without
    the proof is refused (exit 2) unless `--allow-unproven-root`.
- **Action**: `scripts/vm-test-run-selftest.sh` (the #19139 selftest) sets
  the script's own `vm-test-run:` lines aside before its byte comparisons,
  and adds:
  - disclosure on every earlier run (one `paused-for=0s`; `vm-proof=present`
    on root runs only);
  - a stall (the mock SIGSTOPs the command's process group for 5 s), which
    must report >= 4 s;
  - a frozen guest clock (the mock delays the start by 6 s), which must
    report >= 3 s;
  - a quiet control, which must report 0;
  - refusal for absent/unknown proof, and `--allow-unproven-root`;
  - the proof predicate under `unshare -Ur` (valid, stale boot ID, mode 644,
    symlink, missing, not root-owned).
  Mutants: the heartbeat term, the wall term, the refusal, the boot-ID check.

- **Action**: Semantics documented in the script header and
  docs/testing.md, as the review and team-lead set them out:
  - `paused-for=0` is below the detection threshold, not pause-free. A
    stopped-clock pause under about 2 s, or heartbeat gaps each under 2 s,
    read as 0.
  - A positive value is a possible stall, including exec and start-up
    overhead, not attributed to incus.
  - The selftest's "frozen guest clock" cell is a pre-command delay, so it is
    renamed "unseen time" and named as that false positive.
  - No real `incus pause` has been tested mid-run.
