# #18829 — flow-cache mirror clone for an untagged output

**Why:** The `live_flow_cache_callsite_selected_admitted_clone_reaches_target_6304` cell expected the mirror clone to retain the ingress VLAN-80 tag. #15114 (`c9b67eb743e14ac626666eeae2c31e947f39c2ee`) sends a mirror clone on its output unit's VLAN; this fixture's output is VID 0, so the clone's wire bytes must have the ingress tag stripped.

**What:** Re-pinned only `clone.bytes` to the original frame with bytes `[12..16]` removed. Kept the `mirrored_bytes == frame.len()` ingress-accounting assertion and all admission, sampler, egress, flag, and one-clone controls unchanged.

**Validation:** The original cell was RED on the stale expectation: the observed clone had the 54-byte untagged frame while the test expected the 58-byte VLAN-tagged ingress frame. After re-pinning, the exact cell passed (1 passed, 10,279 filtered). As a mutant proof, temporarily changed `mirror_output_frame`'s `(tagged, 0)` arm to return the tagged input frame unchanged; the exact cell failed at the clone-byte assertion with the tag present in actual bytes. The mutation was reverted. The 22 `live_flow_cache_callsite_` neighbours passed. The full `flow_cache_hit_tests` module ran 92 tests: 91 passed and the only failure was the independent `cached_filter_pinned_queue_refreshes_ingress_lp_rewrite_11679` (#18828), which expected `Some(17)` where the current resolver returns `None`; that sibling lane owns its re-pin.

**Risk:** This is test-only; production mirroring is unchanged. The corrected expectation specifically detects a regression that leaves the ingress tag on a clone for a VID-0 output, without changing the intentionally ingress-sized mirror-byte accounting.
