# #15241 — CI affected-Go selector coverage (A58-01..A58-06)

- **Timestamp**: 2026-10-19
- **Action**: closed six CI false-green holes in the affected-Go-test
  selector, the close-keyword lint, the race gate, the python self-test
  census, and the daemon real-kernel forcing.

  - **A58-01** (`scripts/ci_affected_go_tests.sh`): the selector seeded
    only the owning package and closed over reverse imports. A test that
    reads another package's Go source by relative path
    (`pkg/denyaudit` opening `../grpcapi/authz.go`) has no import edge to
    that package — grpcapi imports denyaudit, not the reverse — so a
    change to the read file never selected the reading package. The
    embedded Python now derives reads-source-of edges from every
    relative path literal (plain quoted literals and
    `filepath.Join("..", ...)` segment lists) in `*_test.go` files that
    resolves inside another Go package, and merges them into the same
    reverse-import closure.
  - **A58-02** (`scripts/close_keyword_lint_ci.sh`,
    `.github/workflows/close-keyword-lint.yml`): the lint checked the PR
    body and branch commits but not the PR title; the title becomes the
    squash-landed master commit's subject, so a negated close keyword
    there closed an issue unchecked. `PR_TITLE` is now passed via env
    (never interpolated) and linted as a third source; the workflow
    exports `github.event.pull_request.title`. A title-leg mutant was
    added to `scripts/mutate-9551.py`.
  - **A58-03** (`scripts/ci_affected_go_tests.sh`):
    `git diff --name-only` reported only the destination of a rename, so
    the source package (whose tests may no longer compile) was never
    selected. The diff now uses `--no-renames`.
  - **A58-04** (`Makefile` test-race-dp): the cluster `-run` alternative
    `HeartbeatStartSuperseded` matched no test — the real name is
    `TestStartHeartbeatSupersededByStopDoesNotPublish7257` — so the cell
    lost its only `-race` run silently. The alternative is corrected,
    the probe is added to the cluster canary's probe list
    (`pkg/cluster/monitor_poll_update_race_6550_test.go`), both
    Makefile-parsing canaries now skip the new `go test -list` guard
    lines, and each alternative of every leg is now selected with a
    non-empty `go test -list` check before the race run, so renaming a
    race-leg test fails the leg.
  - **A58-05** (`scripts/run-selftests.sh` §3,
    `scripts/selftest-census.sh` PY_GLOBS): the suffix-convention file
    `scripts/userspace_ha_validation_matrix_test.py` was invisible to
    both the runner and the census. `scripts/*_test.py` is now in both
    glob lists, and the census gained a §3b check that every tracked
    `scripts/*test*.py` is covered by the union of PY_GLOBS, so a new
    `scripts/foo_test.py` (or a test in an unlisted subdirectory) fails
    the census by name.
  - **A58-06** (`pkg/daemon` host-inbound cells, new
    `test/daemon/selftest-daemon-kernel_15241.sh`,
    `test/daemon/selftest-daemon-probes_15241.sh`, `Makefile`,
    `scripts/run-selftests.sh`, `scripts/selftest-census.sh`): the
    9637×2, 11409, 12034, 12229 and 12087 real-kernel cells honoured
    `XPF_REQUIRE_NETNS` only on the netns-start arm; the tool-absent
    arms (nft/unshare/ip/…) skipped first and no runner set the env for
    `pkg/daemon`. Those arms now fail with `t.Fatalf` under the env
    (skip messages byte-identical without it, following the
    `pkg/routing` convention so the go-skip census is unchanged), and a
    daemon forcing leg mirroring
    `test/routing/selftest-routing-kernel_9812.sh` (probes → 77,
    `XPF_REQUIRE_NETNS=1 unshare -rn go test`, six cells pinned BY
    NAME, SKIP-under-forcing fails) is registered in
    `run-selftests.sh`, the census (new `test/daemon/selftest*.sh`
    glob), and `make test` via `test-daemon-kernel` (77 →
    NOT-EXAMINED, or FAIL when `XPF_REQUIRE_NETNS` is set).
