# 13940 — Judge reverse ICMP requests against reverse policy

## Boundary

A reverse-direction ICMP request sharing a live outbound query's identifier can
match the query session's reverse companion. When no type-constrained ICMP rule
exists, the packet-scoped gate previously returned early, treating the request
as a reply and bypassing the reverse zone-pair policy (including default deny).

## Change

Reverse ICMP session hits now distinguish actual reply types from requests
independently of whether policy has type-constrained terms. Replies still coast
on the live query session; requests are evaluated against the companion's
recorded reverse zone pair and the packet's actual ICMP type/code. This applies
to both ICMP families and leaves forward-direction type-gated behavior intact.

- Fail-on-revert: with the new reverse request branch removed, the regression

  was `(1, 0)` instead of `(0, 1)`.
- `cargo test 10637 -- --nocapture` passed 3 tests, retaining typed reverse
  request denial and the reply-coasting control.
- The full `cargo test` run passed 8147 tests (8 ignored) and failed 3 existing

  `worker_loop_orders_expiry_teardown_before_poll_10419`, and
  `additive_wire_exhaustive_literals_only_ever_decrease_7689`.
