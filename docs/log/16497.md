# #16497 — #15149 residual: stale-generation survivor descriptors and stop_inner reaped verdicts get no delivered terminal

- **Timestamp**: 2026-10-24
- **Context**: #15149 taught the dead-worker sweep to record a terminal
  `Deny` (`d11_worker_dead`) for descriptors reaped from the DEAD worker's
  own queue/active set and to deliver them via
  `take_reaped_terminal_verdicts`. Two sets were left behind (R3-B12-02).
  (1) `WorkerSetAuthority::retire_worker` bumps the GLOBAL worker-set
  generation, so descriptors already queued on SURVIVING workers — stamped
  with the pre-retire generation — read stale at their next `drain_worker`
  (`IpsecInnerRouter::check_generation` fails). The stale branch claimed
  the tombstone, force-released the slab and released the router slot, but
  recorded no verdict: the Go-facing request stayed Queued in the
  `ReinjectCore` and completed only by the 5 ms Go ack deadline
  (`pkg/nfqueue/pipeline.go`), with the per-flow serialization delay and
  ack-timeout mis-accounting behind it. (2) `Coordinator::stop_inner`
  retires + joins every worker, so `reap_closed_queue` /
  `join_worker_after_termination` pushed a `d11_worker_dead` Deny per
  queued/owned descriptor into `reaped_verdicts`, but `stop_inner` never
  took them: every full reconcile with D11 work queued added ack-timeout
  drops that were really teardown denies, and the undelivered list grew by
  the reaped count on every stop until a later dead-worker sweep flushed
  it. Both legs are fail-closed (the frame drops either way); the defect
  is the missing prompt terminal, against the module invariant "every
  orphan descriptor terminalized exactly once (E34)" and the #15149
  acceptance "reaped requests complete as Denied rather than by ack
  timeout".
- **Fix**:
  - `userspace-dp/src/afxdp/ipsec_inner_queue.rs`: the `drain_worker`
    stale branch now, when `tombstones.claim_stale` wins, records
    `IpsecInnerVerdict::Deny { stage: "d11_stale_generation", reason:
    STALE_GENERATION }` via the new `push_reaped_verdict` helper (the
    claim-wins gate preserves exactly-once: a request whose worker
    verdict already posted keeps that single terminal). All three
    `reaped_verdicts` producers (stale drain, `reap_closed_queue`, join)
    now go through that helper, and a new `reaped_count: AtomicUsize`
    mirrors the Vec depth exactly (incremented on push, reset on take),
    following the `uncertain_count` precedent. `has_pending_work` gains
    the `reaped_count != 0` leg so the worker poll gate stays lock-free
    yet can never hide an undelivered reaped/stale terminal behind the
    idle gate; `has_reaped_verdicts()` exposes the same atomic check.
  - `userspace-dp/src/afxdp/worker/loop_body/mod.rs`: after
    `drain_verdicts_into`, the worker loop takes
    `take_reaped_terminal_verdicts` into the same completions buffer and
    completes them via `complete_ipsec_inner_verdict` on the same pass —
    so a survivor's stale request finishes as Denied immediately, not at
    the next sweep (a survivor is never swept). Reaped verdicts bypass
    `drain_verdicts_into` (no active entry remains), exactly as the
    coordinator sweep already relied on.
  - `userspace-dp/src/afxdp/coordinator/mod.rs`: `stop_inner`, right
    after the retire+join loops and while `self.slow_path` is still
    installed, drains `take_reaped_terminal_verdicts` into
    `complete_ipsec_inner_verdict`. This also flushes any
    stale-generation terminals a worker recorded just before joining.
    The slow path (and its `ReinjectCore`) survives reconciles, so the
    Denied completions stay valid across the stop; only the transport's
    undelivered list is emptied.
  - NOT changed: the generation model (a retire still invalidates the
    old generation fleet-wide — that fence is what keeps a dead worker's
    descriptors from ever reaching adjudication), the dead-worker sweep
    in `status.rs` (its `ipsec_inner_reaped > 0`-gated delivery is now
    redundant for verdicts a worker loop already took, and `take` is
    idempotent-empty in that case), and any Go-side deadline behaviour.

  (stale never adjudicated), records exactly one reaped terminal, and —
  after the worker-loop delivery pair (`take_reaped_terminal_verdicts` +
  `complete_ipsec_inner_verdict`) — the survivor's request 151492
  completes `Denied` with both slabs reclaimed and zero leftover

  queues one request per worker then calls the real
  `stop_inner(false)`: both requests complete `Denied`,

- **Residual**: component level only, matching the finding's evidence;

  between drain and delivery) is still flushed by the dead-worker sweep
  or by `stop_inner`, so no new stranding path is introduced.
