# #16024 — Alarm on peer-loss takeover without confirmed fencing

- **Base**: `fed39c4bc1` (`origin/master` at branch start)
- **Branch**: `fix/16024-campaign`

## Why

Two-node heartbeat loss can promote the surviving node without quorum or peer-fence confirmation. Existing degraded status did not raise an explicit dual-primary-risk alarm, so the default posture could be mistaken for a cleanly fenced takeover.

## What

- Keep the existing fail-open takeover policy, but expose an unconfirmed peer-loss takeover as `ALARM: dual-primary risk` in cluster status and information, `CRITICAL` in local and gRPC `show system alarms`, and a `slog.Warn` once per takeover.
- Clear the active alarm when a peer heartbeat returns. Do not raise a dual-primary-risk alarm for a cold-start single-node election or an aborted fence wait where the peer is alive.
- Add cluster, local CLI and gRPC alarm cells; document the operator-facing behavior in `pkg/cluster/README.md` and `docs/ha-failover-status.md`.

- GREEN: focused cluster tests passed for the four `TestUnconfirmedTakeoverAlarm16024_*` cells and adjacent #10701, #15211, and #7147 fencing/degraded-status regressions. Focused CLI tests passed for #16024, #10782 and #10025 alarm rendering; focused gRPC tests passed for #16024 and #10782 alarm rendering.

## Risk

Observability-only. No election, fencing, timeout, or takeover ordering changed; confirmed fencing and availability-preserving fail-open behavior remain unchanged.
