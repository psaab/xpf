# #16024 — Alarm on peer-loss takeover without confirmed fencing

- **Base**: `fed39c4bc1` (`origin/master` at branch start)
- **Branch**: `fix/16024-campaign`

## Why

A two-node partition can promote a node without quorum or peer-fence confirmation. Existing degraded status did not raise an explicit dual-primary-risk alarm, so the default posture could be mistaken for a cleanly fenced takeover. A never-seen peer is not proof of absence: both nodes can miss initial heartbeats during simultaneous startup.

## What

- Keep the existing fail-open takeover policy, but expose every unconfirmed takeover as `ALARM: dual-primary risk` in cluster status and information, `CRITICAL` in local and gRPC `show system alarms`, and a `slog.Warn` once per takeover.
- Clear the active alarm when a peer heartbeat returns. An aborted fence wait with a live peer does not raise the alarm.
- Add a decisive cluster cell with peer-primary/local-secondary preconditions, fresh connected sync, an initial suppressed timeout, and explicit expiry of the 5s suppression cap; it asserts the actual promotion and default-policy alarm. Add confirmed-fence, abort, configured cold-start, CLI, and gRPC alarm cells.
- Document the operator-facing behavior in `pkg/cluster/README.md` and `docs/ha-failover-status.md`.
