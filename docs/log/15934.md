# #15934 — IPv4 leak-rib recursive-NoRoute continue restored

## Problem

GLM DP retro F1 (HIGH, live at head): e59e745568 (PR #15839, #15768)
deleted #14319's recursive-NoRoute `continue` from the IPv4 leak walk
in `userspace-dp/src/afxdp/forwarding/fib.rs`. The v4 leak loop
returned the recursive result unconditionally while the v6 twin kept
`if NoRoute { continue }`, and the v4 comment still documented the
continue. A precheck-admitted leak target whose recursive LPM selects
only a tunnel route the caller forbids (`allow_tunnels == false`)
therefore produced a terminal `NoRoute` instead of falling through to
later leaks / the source table's own LPM — a silent IPv4 blackhole in
mixed tunnel/non-tunnel leak-rib VRF topologies. The precheck
(`any()` over usable entries / connected rows) and the recursive LPM
(longest-prefix tier selection) can disagree, so the continue is not
dead code.

Two ledger residuals on the same surfaces were folded in:

- `policy_revalidation.rs` forward_query (reverse-hit,
  companion-synthesized) arm passed only the stored
  `source_nat_icmp` to the DNAT revalidation, not
  `packet_icmp.or(stored)` as the primary arm does (#15791 residual):
  an ICMP-constrained DNAT entry with no stored selector fail-closed
  (revoked) despite a live packet selector.
- `hostInboundInterfaceAdminDisabled` (zones_observability.go) cut the
  ref on the first dot and ran `Atoi` on the remainder, so a
  VLAN-qualified ref (`ge-0/0/0.100:12`) failed to parse and a
  disabled unit parsed as enabled (#15763 edge).

## Fix

- `fib.rs`: restored the v4 `if resolved == NoRoute { continue }`
  guard, byte-mirroring the v6 twin. Terminal dispositions
  (Discard/Reject/LocalDelivery/ForwardCandidate/…) still return
  immediately; only `NoRoute` is a miss.
- `policy_revalidation.rs`: forward_query arm now passes
  `packet_icmp.or(forward_decision.nat.source_nat_icmp)`, identical to
  the primary arm's composition. Packet selector wins when present;
  the stored selector remains the fallback. Wrong/missing selectors
  still fail closed.
- `zones_observability.go`: `hostInboundInterfaceAdminDisabled` now
  strips a trailing `:<vlan>` numeric qualifier and resolves the ref
  through `cfg.SplitInterfaceUnitRef` + `CanonicalLogicalUnit` (the
  same declared-name-aware identity the zone mapper binds), instead
  of the first-dot `Cut` + `Atoi`. Malformed suffixes stay inert
  (enabled), exactly as before.

NOT changed: the precheck (`table_has_v4_route_suppressing`), v6 walk,
`select_v4_route`, admission DNAT lookup, DnatTable semantics, or any
zone-policy/host-inbound emission — only the three adjudication
inputs above.

## Risk

Fail direction stays closed everywhere: unknown ICMP selectors still
fail type-constrained DNAT entries, terminal FIB dispositions are
never skipped, and malformed interface refs remain enabled/inert as
before. Behaviour delta is confined to (a) v4 leak walks that
previously blackholed, (b) reverse-hit DNAT revalidation with a live
packet selector and no stored selector, (c) admin-disabled reporting
for VLAN-qualified zone refs.
