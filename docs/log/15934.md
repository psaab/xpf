# #15934 — IPv4 leak-rib recursive-NoRoute continue restored

## Problem

GLM DP retro F1 (HIGH, live at head): e59e745568 (PR #15839, #15768)
deleted #14319's recursive-NoRoute `continue` from the IPv4 leak walk
in `userspace-dp/src/afxdp/forwarding/fib.rs`. The v4 leak loop
returned the recursive result unconditionally while the v6 twin kept
`if NoRoute { continue }`, and the v4 comment still documented the
continue. A precheck-admitted leak target whose recursive LPM selects
only a tunnel route the caller forbids (`allow_tunnels == false`)
therefore produced a terminal `NoRoute` instead of falling through to
later leaks / the source table's own LPM — a silent IPv4 blackhole in
mixed tunnel/non-tunnel leak-rib VRF topologies. The precheck
(`any()` over usable entries / connected rows) and the recursive LPM
(longest-prefix tier selection) can disagree, so the continue is not
dead code.

Two ledger residuals on the same surfaces were folded in:

- #15791 residual (PR #15967 review history): DNAT
  revalidation judged the forward rule by the ARRIVING packet's
  ICMP selector on reverse hits and by a stored-only selector on
  the companion-synthesized arm. Settled semantics (below):
  direction-keyed selector composition plus a single tier-walk
  verdict for provenance-absent reverse hits.
- #15763 edge: `hostInboundInterfaceAdminDisabled`
  (zones_observability.go) cut the ref on the first dot and ran
  `Atoi` on the remainder, so a VLAN-qualified ref
  (`ge-0/0/0.100:12`) failed to parse and a disabled unit parsed as
  enabled.

## Fix

### FIB (fib.rs)

Restored the v4 `if resolved == NoRoute { continue }` guard,
byte-mirroring the v6 twin. Terminal dispositions
(Discard/Reject/LocalDelivery/ForwardCandidate/…) still return
immediately; only `NoRoute` is a miss. NOT changed: the precheck
(`table_has_v4_route_suppressing`), v6 walk, `select_v4_route`.

Leak-incarnation alignment (F1): `leak_incarnation_for_resolution`
still stamps the FIRST precheck-admitted leak while the walk can
forward via a later one. Deliberate, documented at the function: the
stamp is ABA revocation provenance ("which incarnation owns this
destination"), not packet provenance; deriving the packet's eventual
leak would require re-running the mutable neighbor/ECMP/tunnel
resolution the stamper avoids, and a stamp/current mismatch is
fail-closed (NoRoute in `resolve.rs`), never a permit. The doc no
longer claims the stamp names the exact packet-carrying leak.
`mixed_topology_stamp_is_first_leak_and_fails_closed_15934` pins the
contract. The same divergence pre-exists on v6.

### DNAT revalidation selector semantics (policy_revalidation.rs, nat/destination.rs)

The selector fed to FORWARD-rule revalidation must represent the
ORIGINAL forward packet (`forward_selector_for_hit`, keyed on hit
direction, not call site):

- forward-direction hit: live packet wins (`packet.or(stored)`);
- reverse-direction hit: stored forward selector wins
  (`stored.or(packet)`, #14128 — `NatDecision::reverse` preserves it
  as forward packet identity), at BOTH the companion-less
  synthesized arm and the primary arm when a reverse hit's forward
  companion is materialized.

Provenance-absent reverse hits: a DNAT-only flow mints no
stored selector (only a source-NAT rewrite records one;
`nat/destination.rs` writes None), so no packet can supply the
request's type. For those, ONLY the ICMP-selector sub-check is
waived (`ignore_icmp_selector`, computed by
`selector_provenance_absent`), and destination validity becomes ONE
tier-walk verdict in normal precedence order
(static → persistent → DNAT): the first tier with any
selector-relaxed match (including an `off`/Exempt) owns the verdict
and validates only if its winning/co-winning outcome reproduces the
stored `rewrite_dst`/`rewrite_dst_port` geometry. Within DNAT
buckets the deciding group is the best scope tier; its config-order
winner claims the group (a non-Translate winner revokes), and
Translate entries co-win in CONFIG ORDER until the first
non-Translate (off/Exempt ends the scan and revokes if it precedes
any reproducing Translate) — type-8→A + type-0→B, 8/13 with a reply
matching neither, off-before-translate revoking. Prefix-LPM decides at the winner's
(scope-tier, prefix-length) group. No cross-tier resurrection:
static-B over DNAT-A revokes. The walk
(`tier_walk_reproduces_ignoring_icmp_selector_scoped`) streams in
place with no allocation and runs only on the cold revalidation
path; the strict admission lookup is untouched (all relaxed matching
is gated on the waiver flag, strict first-winner semantics
unchanged). NPTv6 prefix validity and deterministic NAT64 geometry
never consulted the selector and still revoke as before.

### VLAN admin-disabled (zones_observability.go)

`hostInboundInterfaceAdminDisabled` strips only a canonical
`:<vlan>` qualifier (decimal digits, 0..=4094, `Itoa` round-trip;
`:-1`/`:+12`/`:4095` stay inert) and resolves the ref through
`cfg.SplitInterfaceUnitRef` + `CanonicalLogicalUnit` (the same
declared-name-aware identity the zone mapper binds), instead of the
first-dot `Cut` + `Atoi`. Malformed suffixes stay inert (enabled),
exactly as before. Observability-only; no forwarding change.

## Risk

Fail direction stays closed: with stored provenance, wrong/missing
selectors still fail type-constrained entries, replacement and
withdrawn rules revoke, and terminal FIB dispositions are never
skipped. The waiver can only keep a provenance-absent reverse ICMP
session whose live state — judged at the first deciding tier —
still reproduces its stored translation. Admission, DnatTable
strict semantics, and host-inbound emission are unchanged.
