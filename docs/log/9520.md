# #9520: a same-generation apply_snapshot was admitted content-blind

## Re-read at `origin/master` `6d930698c`

The issue has no comments, so its body is the spec. Every premise holds at this commit.

- The helper admits `generation > cur || (generation == cur && fib >= cur_fib)` in
  `userspace-dp/src/server/handlers/snapshot.rs::apply` and compares no content.
- `UpdatePolicyScheduleState`, `PublishRouteOverlaySnapshot` and
  `retryDeferredWorkerArmLocked` compute `m.generation + 1` and commit it only after
  `requestLocked` returns nil. The helper commits an apply before any response byte exists,
  and an apply body under 1 MiB gets exactly 3s (`controlRoundtripDeadline`, no verb
  floor). So a deadline error can follow a landed apply, and the retry rebuilds its content
  and re-sends the same generation.
- Flow-cache freshness is `(config_generation, fib_generation)` equality, and session policy
  stamps and the #8356 re-derivation are keyed on the config generation alone.
- `Compile` is not a reuse path: it calls `m.bumpGeneration()` inline at build time. It can
  still COLLIDE with a republish's landed-but-unobserved generation, because that republish
  never advanced `m.generation`. The helper comment listing `Compile` among the
  commit-on-success paths is stale.
