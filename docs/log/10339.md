# #10339 — ignore nested checkouts in the lease-site scan

- **Issue:** `TestLinkCycleLeaseHasExactlyOneAcquisitionSite_6871` walked the
  module root into `.claude/worktrees/*` linked worktrees and treated their
  copied `PrepareLinkCycle` sites as new production acquisitions.
- **Context read:** Read the complete issue body through the GitHub API and
  read the comments endpoint; the issue was open and had zero comments.
- **Files:** `pkg/dataplane/userspace/link_cycle_acquisition_site_6871_test.go`,
  `cmd/cli/gofmt_clean_tree_test.go`, and this evidence log.
- **Scope:** Test/enumeration code only. No production package was changed.

## Change

`isNestedCheckout` recognizes a directory below the scan root when it contains
`.git` as either a linked-worktree gitdir file or a full-clone git directory.
Both tree walks in the lease guard now return `filepath.SkipDir` for such a root
while leaving the scan root itself eligible, even when the scan root is a linked
worktree whose own `.git` is a file. The fixture cells cover both marker forms,
plus the proof-test walk used by marked allowlist entries.

The gofmt canary had the same unfiltered-checkout behavior within its explicit
`pkg/` and `cmd/` roots. Its walk is now factored into `walkGofmtSources`,
which applies the same `.git` boundary, with a fail-on-revert fixture cell.
No production package was changed.

## Repo-wide scan audit

The other module-root walkers called out by the issue were audited. The CLI and
osident canaries (`pkg/cli/userclass_entrypoint_canary_test.go` and
`pkg/osident/user_env_canary_test.go`) intentionally model `go list ./...`:
`.claude/worktrees/*` is excluded by their shared `skipCanaryDir` rule because
`.claude` is dot-prefixed, while a worktree outside a dot-prefixed directory
is excluded at its own `go.mod` module boundary by `isNestedModuleRoot`. The
CLI copy is byte-parity checked against the osident implementation, and the
osident fixture cross-checks the walk against the toolchain. Those two walkers
do not share the lease scan's unfiltered-checkout defect.

`cmd/cli/gofmt_clean_tree_test.go` DID share the defect within its explicit
`../../pkg` and `../../cmd` roots. A temporary nested checkout under `pkg/`
with `.git` and an unformatted `bad.go` raised its pre-fix finding from 33 to
34 and named `../../pkg/fixture_nested_checkout_10339/zz_unformatted.go`.
The permanent `TestGofmtWalkSkipsNestedCheckout_10339` first failed before the
boundary (`visited [.../nested/bad.go .../top.go], want only top-level`) and
passed after `walkGofmtSources` gained the same `.git` boundary. Its table now
covers both linked-worktree `.git` files and full-clone `.git` directories. The
temporary fixture was removed.

The focused audit commands both passed:

```text
go test ./pkg/osident -run 'Test(CanaryWalkRuleMatchesTheToolchain_6706|CanaryWalkFollowsASymlinkedRoot_6706|NoIdentityFromEnvironment_6701|UserEnvCanaryDetectsAViolation_6701)$' -count=1
go test ./pkg/cli -run 'Test(CanaryTraversalHelpersMatchTheOsidentCopy_6706|SetUserClassHasOneProductionCaller_6701|SetUserClassCallersResolveThroughTheSharedResolver_6701)$' -count=1
```

Both returned `ok` with zero failures.
