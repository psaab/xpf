# #17699 — render omitted static preference at Junos distance 5

- **Timestamp**: 2026-10-28
- **Branch**: `fix/17699-campaign`
- **Issue**: `frr: render omitted static preference at Junos distance 5`
- **File(s)**: `pkg/frr/config_render.go`, `pkg/frr/static_preference_range_12060_test.go`, `pkg/frr/README.md`

## Defect

A zero/omitted `StaticRoute.Preference` passed through the static distance clamp unchanged. Both ordinary and discard/reject static renderers therefore omitted the distance operand, leaving FRR's implicit distance 1 instead of Junos's default static preference 5. The helper used for DHCP arbitration also treated an omitted preference as distance 1.

## Change

Render an omitted preference as explicit FRR distance 5 for IPv4 and IPv6 ordinary statics and discard/reject statics. Align effective static distance used by DHCP arbitration with the same default. Explicit preferences continue to render unchanged; the existing upper-bound clamp and next-hop metric behavior are unchanged. Document the omitted-preference behavior in the FRR README.

The regression covers omitted IPv4/IPv6 ordinary routes, omitted discard/reject routes, an explicit preference control, and the effective-distance helper.

## Risk

Only a zero preference changes: it now renders as distance 5 rather than relying on FRR's implicit distance 1. This corrects Junos default semantics for omitted preferences. Nonzero preferences, the existing maximum-distance clamp, DHCP threshold behavior, and qualified-next-hop metrics are unchanged.
