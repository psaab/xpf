# #14686 — RBAC bypass via cross-form longest-match + pipe keyword smuggling

- **Timestamp**: 2026-10-17
  - **Action**: Reproduced RED on origin/master (1cc3d5f869) with a probe
    through `CompiledLoginRegexes.EvaluateForms` exactly as
    `pkg/cli.evaluateCommandRegex` calls it
    (`EvaluateForms(matched, canonicalPrefix, command)`):
    - `allow ^show.*` / `deny (^show version$)|(^show log$)`,
      `EvaluateForms("show version | match .","show version","show version")`
      -> ALLOWED (`allow matched a longer extent than deny (22 > 12)`).
    - `allow "show interfaces"` (allowlist, no deny),
      `EvaluateForms("show configuration | except show interfaces",...)`
      -> ALLOWED (`matched the class's allow regex`) via pipe filter text.
    - Control `^show log 100$` / `^show log$` over `show log 100` -> ALLOWED
      (documented exception, must stay green).
  - **Mechanism**: `EvaluateForms` pooled one global max per side across
    forms of different lengths (full+pipe, prefix, pipe-less). Tier-2 then
    compared a wildcard allow measured on the long piped form against an
    end-anchored deny that can only match the short form; and
    `longestMatchLen` matches anywhere, so an allow phrase inside
    user-controlled pipe text satisfied the allowlist.
  - **Fix**: per-form evaluation. Each form is judged alone under the
    ordinary tiers (`evaluateForm`); lengths are never compared across
    forms. A tier denial on any form vetoes, except the exact
    deny-with-exceptions geometry (`isAnchoredException`: vetoing deny
    matches only the truncated form, carrying allow matches only the full
    form — `^show log 100$`/`^show log$`). Allowlist-only misses do not
    veto, but with a pipe (`EvaluateFormsWithPipe`, wired in
    `evaluateCommandRegex` when `pipeWords` is non-empty) the pipe-less
    form must affirmatively allow — an allow matching only inside pipe
    text authorizes nothing. Deny-only pipe patterns (`display set`,
    `save`) still bite via the full form's tier denial.
  - **File(s)**: pkg/config/login_regex.go, pkg/cli/permissions_regex.go,
    docs/system-login.md
  - **Tests**: pkg/config/login_regex_14686_test.go
    (`TestEvaluateFormsPipeAndArgDoNotDefeatAnchoredDeny14686`, incl. the
    issue's decisive fixture + exception/tier controls),
    pkg/cli/permissions_regex_14686_test.go
    (`TestPipedWildcardAndSmuggledAllowDoNotBypassAnchoredDeny14686`,
    through the real gate). RED evidence above; GREEN + package suites
    recorded after the fix below.
