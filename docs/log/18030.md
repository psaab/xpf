# #18030 — Reject bare st0 NAT scope when both units exist only as bindings (no stanza)

Covers sibling issue #18031 (binding-derived nonzero siblings bypass the veto in
four shapes) with the same fix: the binding-derived sibling census is consulted
by BOTH the canonicalizer and the ambiguity gate, so one implementation closes
both issues. Multi-VPN sharing of the SAME unit stays legitimate.

- **Timestamp**: 2026-10-27
  - **Action**: Added `Config.secureTunnelBindingSiblingUnit(base)` (`pkg/config/xfrmi.go`): reports whether any authored VPN `bind-interface` materializes a NONZERO logical unit on the secure-tunnel base, keyed on the XFRM if_id family (stIndex) so padded spellings (`st00.1`) join the family they derive. `CanonicalNATInterfaceScopeRef` (`pkg/config/schema_validators.go`) no longer folds a stanza-less multi-binding bare ref onto `.0` before the gate (#18030), no longer folds a unitless-tunnel-stanza or authored-unit-0-only base when a binding sibling exists (#18031), and now folds a description-only stanza plus a BOUND unit 0 onto `.0` (was: accepted-but-inert bare). The #15278 gate `natInterfaceDefined15278` (`pkg/config/compiler_validate_strict_nat.go`) computes unit-0 presence (authored stanza, unitless tunnel stanza, or unit-0 binding) and sibling presence (authored units OR binding census) independently of any interface stanza existing, and rejects the ambiguous combination before the materialized-shortcut acceptance. Regression cells: `pkg/config/nat_bare_binding_sibling_18030_test.go` — stanza-less bindings st0.0+st0.1 (#18030), authored-unit-0 + binding sibling, unitless GRE tunnel stanza + bindings, bare `bind-interface st0` + st0.1 (#18031), each across all four NAT interface axes (source from/to, destination from, static from) with strict reject + lenient warn/record/stays-bare; same-unit multi-VPN sharing (disjoint selectors) and description-only + binding-only unit-0 controls keep folding to `st0.0`.
