# Issue #12235 — keep deferred startup snapshots pending until publication

## Why

A successful userspace apply can defer its full snapshot while XSK startup is unresolved. Treating that return as converged stamped the active digest, advanced HA config high-water/ACK, and advertised takeover readiness before the helper enforced the generation. In-band helper refusal on the deferred status-loop publish was not connected to the HA config apply result.

## What

Applied markers now remain invalidated until a synchronous or status-loop publish lands. Deferred configs retain their digest and a completion channel: HA config sync holds its generation fence until publication, NACKs an in-band refusal without advancing high-water, and ACKs only after successful landing. The userspace manager notifies the daemon on in-band refusal, and a pending full snapshot blocks takeover readiness with its generation in the reason. A failed apply tail retires its pending completion rather than acknowledging partial convergence.

## Validation

- **RED before:** On clean base `a714c90d472a3c3d98a3799831cfef3ec311a61c`, Go overlay regressions failed: daemon applied-marker gate reported “deferred publish was recorded as applied before the helper enforced it”; takeover gate reported `TakeoverReady() = true before deferred generation 9 publishes`.
- **GREEN after:** Targeted deferred marker, refusal-to-HA, HA ACK/high-water, manager refusal callback, and takeover-readiness regressions passed. `go build ./...` passed; `gofmt -l` on all touched Go files returned no files.
- Scoped `go test ./pkg/cluster ./pkg/dataplane/userspace ./pkg/daemon -count=1`: cluster and daemon passed. Userspace reported `TestNilUnitSlotCastsNoTrunkZoneVote_6722`, `TestRetainedLiveXfrmiLeavesTheAdjudicatedSets/untracked_after_daemon_restart`, and `TestSnapshotShapeIsPinnedToProtocolVersion8892`; the same three failures reproduce on clean base `a714c90d472a3c3d98a3799831cfef3ec311a61c`.
- No live-cluster mutation was performed.

## Risk

HA config sync remains fenced while a deferred snapshot is pending; helper refusal returns a NACK and allows the sender's existing retry cadence to re-send the generation. The session-invalidation behavior tracked separately by #12073 was not expanded here.
