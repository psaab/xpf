# Issue #12089 — refuse IKE gateways scoped to a non-default routing-instance

- **Issue**: #12089 — IKE gateway `external-interface` is in a routing-instance, but neither strongSwan nor the xfrmi is scoped to that instance.
- **Branch**: `fix/12089-ike-vrf`
- **Worktree**: `/var/worktrees/12089-ike-vrf`
- **Base**: `a714c90d472a3c3d98a3799831cfef3ec311a61c` (`origin/master`)

## Why

An IKE gateway can name an `external-interface` that belongs to a non-default routing-instance and commit without warning. The strongSwan IKE socket and xpf's parentless xfrmi are not scoped to that instance, so outer IKE/ESP traffic may use the wrong routing table.

## What

Added a commit-time gate for compiled IKE/IPsec gateways. It resolves each gateway's `external-interface` through the shared routing-instance device-owner resolver and refuses an instance-owned interface, naming the gateway and routing-instance. Tolerant load and peer-sync remain boot-compatible and warn; default-instance, absent, and unresolved external-interface values are unchanged.

## Risk / residual

This intentionally refuses unsupported IPsec-in-a-routing-instance scope rather than binding the IKE socket and xfrmi into the instance. Tolerant loads warn but do not change runtime scoping; operators must move the gateway's external interface to the default instance. No live cluster was mutated. Real strongSwan traffic behavior remains outside this compiler-gate validation.
