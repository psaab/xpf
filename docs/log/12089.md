# Issue #12089 — refuse IPsec VPNs sourced from non-default routing-instances

- **Issue**: #12089 — an IPsec VPN's effective local address can belong to a non-default routing-instance, but neither strongSwan nor the xfrmi is scoped to that instance.
- **Branch**: `fix/12089-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12089`
- **Base**: `83b5c955335f16d8c7835f206b210ce3ae1a5fe5` (`origin/master`)

## Why

An IPsec VPN can select its source from `vpn local-address`, then gateway `local-address`, then an address derived from `external-interface`. The prior gate inspected only the last spelling, so VR-owned addresses set by either `local-address` could still commit, and a default-instance source could be refused merely because the overridden external interface belonged to a VR. strongSwan's IKE socket and xpf's parentless xfrmi are not scoped to the source address's routing-instance, so outer IKE/ESP traffic may use the wrong routing table.

## What

The commit-time gate follows the renderer's per-VPN local-address precedence and maps an explicit address to its declared interface unit, kernel device, and routing-instance owner; when no local-address is configured, it keeps the external-interface-derived selection. The shared address-to-device index includes configured static addresses and VRRP virtual addresses (IPv4 and IPv6), is built once per validation, and gateway-scoped results are memoized across referencing VPNs. It refuses each VPN whose effective source is in a non-default VR, including VPNs using an inline peer endpoint, and tolerantly warns on load / peer-sync. Unused gateway objects retain the gateway-level check. Forwarding instances are not treated as VRF owners, and the gate runs after the routing-instance membership tail gates so #11060, #11312, #11392, and #11364 retain diagnostic priority.

## Validation

- **Strict / tolerant source matrix**: P1 (gateway `local-address` without `external-interface`), P2 (gateway `local-address` overrides default `external-interface`), and P21 (VPN `local-address` overrides a default gateway source) are refused with #12089 and produce a tolerant warning. P15 and P22 verify that a default-instance effective source is accepted even when `external-interface` points into a VR. Covered by `TestIKEGatewayRoutingInstanceRefused12089`, `TestIKEGatewayRoutingInstanceAccepted12089`, and `TestIKEGatewayRoutingInstanceEffectiveLocalAddressLenient12089`.
- **VRRP VIP sources**: strict compile refuses and tolerant load warns for IPv4 VIP gateway-local and VPN-local addresses (N4/N4b) and IPv6 VIP gateway-local and VPN-local addresses (C3/C3b). N4c verifies a VIP on a default-instance unit remains accepted; a plain-address P1-equivalent remains refused. These cases are rows in the same refused, accepted, and tolerant test tables.
- **RI priority / quarantine**: forwarding retains #11312, dual claim retains #11060, and a management-class member retains #11392; none produces a false #12089 tolerant warning. The management row kills M8, which moves the gate ahead of #11392. A shared gateway with default- and VR-sourced VPNs reports only the VR-sourced VPN, and an inline peer VPN's VR-owned `local-address` is checked. Covered by `TestIKEGatewayRoutingInstanceMembershipPriority12089`, `TestIKEGatewayRoutingInstanceChecksEachVPNSource12089`, and `TestIKEGatewayRoutingInstanceInlineVPNLocalAddress12089`.
- **Timing**: the R2 reviewer measured strict `CompileConfig` at 17.8, 14.8, and 18.2 s for 4,000 units / 2,000 gateways and VPNs, versus 4.1, 4.9, and 1.8 s with the gate disabled. The post-fix temporary harness on this worktree measured 0.970, 0.910, and 0.967 s for 40 interfaces × 100 units plus 2,000 gateway/VPN pairs, each with a gateway `local-address`. The old and new measurements were not paired on the same run; both use the reviewer timing shape.

## Risk / residual

This is a compiler-gate validation; no live strongSwan traffic or network-namespace run was performed. Tolerant loads warn but do not change runtime socket/XFRM scoping. An operator must configure the effective source address on an interface in the default routing-instance.
