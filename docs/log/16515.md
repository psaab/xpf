# Issue #16515: owner-RG export retention fails cold prime at 7-8+ workers

## Why

The #15161 fix charged actual decoded bytes (`unsafe.Sizeof` = 520 B plus
string payloads, ~646 B for a realistic IPv4+SNAT row) but kept the fixed
256 MiB retention bound (`ownerRGExportMaxAccumulatorBytes`).
`ExportOwnerRGSessionsPaged` appended every 8192-delta page to one
`[]SessionDeltaInfo`, so the bound trips at ~415k deltas (646 B rows) /
~516k deltas (520 B floor): below 7 workers' forward ceiling with
realistic rows and below 8 workers' ceiling at the struct floor alone
(8 × 65536 × 520 B = 272.6 MB > 256 MiB). Every cold prime
(`pkg/cluster/sync_conn_sweep.go`) and FullResync
(`daemon_ha_userspace_stream.go`) from such an owner then failed closed
with `ErrOwnerRGExportIncomplete` on every retry, and pre-existing
sessions never re-sent incrementally were lost at failover. The
`maxOwnerRGExportDataPages = 512` structural cap was never reached.

## What

Stream each page into the consumer instead of retaining the window
(the #15161 first-preference direction):

- `pkg/dataplane/userspace/owner_rg_export_paging_9344.go`:
  `ExportOwnerRGSessionsPagedStream(rgIDs, sink OwnerRGExportPageSink)`
  is the paging core. It keeps every fail-closed check (512 data pages +
  terminal probe, incarnation/sequence continuity, dropped-delta,
  oversized page, helper/config generation change, v1 refusal) and hands
  each decoded page (≤8192 deltas) to the sink before requesting the
  next. No window-wide slice and no byte accumulator remain: the deleted
  `ownerRGExportMaxAccumulatorBytes`, `ownerRGExportActualDeltaBytes`
  and `maxOwnerRGExportAccumulatorPages` are gone, so retention is one
  page plus whatever compact form the sink builds. A sink error aborts
  the window immediately. `ExportOwnerRGSessionsPaged` remains as a
  collecting wrapper for callers/tests that still need the whole slice.
- `pkg/dataplane/userspace/legacy_dataplane.go`: streaming forwarder on
  `LegacyDataPlaneAdapter` (the type `Boot()` publishes), so the
  compile-time binder in `bulk_snapshot_published_type_9482.go` keeps
  binding the real interface to both published types.
- `pkg/daemon/daemon_ha_userspace_export.go`: `userspaceSessionExporter`
  now names the streaming method. The bulk path streams pages into the
  `snapshotDeltaSink` (compact cluster rows; a failed window discards
  the unframed partial sink). The FullResync path streams pages into
  the shared paced sink via `queueUserspaceSessionDeltasCompleteStream`.
- `pkg/daemon/full_resync_transaction_9767.go`: the streaming queue
  checks the #7194 schema gate once before any page is streamed (never
  per page, so no partial queue under a withheld gate), walks every page
  into one `pacedQueueDeltaSink`, and reports any missed install across
  all pages before the FullResync frame may be acknowledged (#9767).
  The batch `queueUserspaceSessionDeltasComplete` is retained.

All daemon exporter fakes were migrated to the streaming signature.

NOT changed: the paging protocol, page size, structural 512-page bound,
terminal probe, or any Rust code.

## Validation

- New acceptance cell `TestOwnerRGExportStreamsSixteenWorkerWindow16515`:
  128 pages × 8192 = 1,048,576 deltas (16 × 65536) complete through the
  streaming API with a counting sink; `TestOwnerRGExportStreamSinkErrorAborts16515`
  pins sink-error abort after one request.
- Existing fail-closed cells still pass: the 513-page unterminated cell
  (`TestOwnerRGExportFailsClosedWhenTheHelperNeverStops9344`), dropped-delta
  (#9856), v1 refusal, incarnation-change, oversized-page and terminal-probe
  cells, plus the 48-page six-worker wrapper cell (#15161).
- `go vet ./pkg/dataplane/userspace/ ./pkg/daemon/` clean; targeted
  `go test` runs for the export and daemon bulk/FullResync suites (see PR).

## Risk

- Memory: a full 16-worker window is no longer retained as
  `[]SessionDeltaInfo` (~680 MB at realistic rows). The bulk path retains
  only the compact `BulkSnapshot` the wire framing requires; FullResync
  retains nothing beyond one page. The 512-page structural cap still
  bounds helper work.
- Mid-stream FullResync failure: installs queued from earlier pages ride
  the incremental stream (never a framed bulk window); the export error
  prevents the FullResync ACK, as before.
- Lab verify still outstanding: cold prime / FullResync on the loss
  cluster with an owner holding >415k forward sessions at 7+ workers.
