# Issue #14670 — Deterministic NAPT64 expired-BIB GC and activation-rollback bookkeeping

- **Issue:** psaab/xpf#14670 (`D5-01`, gemini-hostile deep-review). In
  `allocate_deterministic_v6_at` (`userspace-dp/src/nat/allocator.rs`):
  1. When `occupancy[ip_idx].claim_in_block` returned `None`, the only
     expired-lease handling consulted the candidate's own `bib_key`
     (`persistent_by_source.get(&bib_key).filter(expired)`). A subscriber
     block fully occupied by expired idle BIBs minted under *other* source
     ports therefore reported `AllocatorExhausted` indefinitely — no
     `gc_expired_for_addr_locked` sweep ran on this path (the helper was
     only called from the sibling PAT path), so ordinary browsing
     (block_size distinct ports over the 300 s BIB timeout) permanently
     exhausted the subscriber's port block until unrelated pressure GC
     happened to run.
  2. Both BIB-reuse branches (full-block and claimed-port) minted the
     joining flow's `LiveAllocation` with `promotion_timeout_ns: None` and
     never set the `0->1` activation snapshot (`activation_saw_completion`,
     `activation_previous_expires_at_ns`,
     `activation_previous_timeout_ns`, `activation_had_previous_lease`)
     that `reuse_existing_lease_locked` and the synced/address-only joins
     set. `rollback_flow` therefore treated a promoted/imported BIB as
     freshly minted (`activation_had_previous_lease == false`) and
     *deleted* the BIB on rollback — destroying an HA standby's imported
     BIB.
  3. Secondary: the full-block reuse branch skipped the
     `live_by_flow.len() >= max_tracked_flows` cap the claimed-port branch
     already enforced, so joining an existing BIB bypassed
     `max_tracked_flows`.

## Fix (`userspace-dp/src/nat/allocator.rs`, `allocate_deterministic_v6_at` only)

- **Expired-block GC:** in the `claim_in_block == None` arm, before the
  per-key expired fast-path, run
  `gc_expired_for_addr_locked(&mut live, ip_idx, now_ns, PRESSURE_GC_BUDGET)`
  (the same bounded per-address sweep the PAT pressure path uses at
  `allocate_translation_locked`). Expired entries are the earliest in the
  per-address expiration index, so one bounded pass reclaims this
  address's expired frontier; only when `reclaimed > 0` drop the guard and
  retry the lock-free block claim from `port_start`. No retry loop is
  added — a zero-reclaim sweep falls through to the existing
  own-key/reuse/exhaustion logic unchanged.
- **Activation-rollback bookkeeping (both reuse branches):** on a `0->1`
  join (`was_idle`), mirror `reuse_existing_lease_locked`: remove the
  stale expiration-index entry, snapshot
  `activation_previous_expires_at_ns`/`activation_previous_timeout_ns`,
  set `activation_had_previous_lease = true` and
  `activation_saw_completion = false`. For an *imported* lease (idle or
  already active), carry `promotion_timeout_ns =
  Some(DETERMINISTIC_NAT64_BIB_TIMEOUT_NS)` on the joining flow's
  `LiveAllocation` so timeout promotion/ownership transfer is deferred to
  a completing `release_flow`, exactly as the PAT/synced joins do; a
  rollback now restores the pre-join expiry/timeout instead of removing
  the lease. The full-block branch keeps its existing expiry refresh; the
  claimed-port branch deliberately keeps `expires_at_ns` unchanged (its
  historical behaviour — `release_flow` re-arms expiry on completion, and
  the snapshot captures the pre-join value for rollback).
- **Capacity cap:** the full-block reuse branch now enforces
  `live_by_flow.len() >= max_tracked_flows` -> `AllocatorExhausted`,
  matching the claimed-port branch (and every other join path).

No other allocator path, wire format, or HA sync record changes.

## Risk

Bounded to the deterministic NAPT64 allocation path. The GC sweep runs
only on the already-failed block claim (never on the fast path) and is
budget-capped (`PRESSURE_GC_BUDGET = 64`), matching the PAT pressure
fallback's cost model. Rollback of a genuinely fresh BIB is unchanged:
fresh mints still carry `activation_had_previous_lease: false`, so
rollback still removes them; only joins of pre-existing (imported or
locally idled) BIBs gain the restore-instead-of-remove behaviour, which
is the contract `rollback_flow` already implements for every other join
path.
