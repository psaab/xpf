# #15854 — userspace shim exceeds verifier 1M-insn cap; loss deploy blocked

## Defect

PR #15843 (b5660ce9d5, profile-gated LAND screen) grew the tracked
shim `pkg/dataplane/userspace_xdp_bpfel.o` 51816 -> 52560 bytes and
took the measured verifier cost from 920733 (7.93% headroom,
#15645) to 963340 processed insns (3.67% headroom, OVERRIDDEN).
On the loss-cluster guest kernel 7.0.0 the same object rejects at
the cap (`Processed 1000001 insns (limit 1000000)`), so
`verify-dataplane` refuses every current-master deploy. Reproduced
in-lane: the tracked object and a fresh pinned build
(nightly-2026-05-23, bpf-linker 0.10.2, scrubbed codegen env,
`MAX_INTERFACES=65536`) both measure 963340 on this host (7.2.8).

## Measured breakdown (fresh pinned builds, `cmd/shimverify`)

Diagnostic stubs / single-outline trials against the 963340
baseline (behaviour-breaking stubs, measurement only):

- LAND gate stubbed out: ~929k — the gate itself is only ~27-34k;
  outlining it alone (`land_gate`, below) measured WORSE in
  isolation (985899): the cost is state multiplication in the
  monolithic entry, not the gate's own instructions.
- Single `#[inline(never)]` trials that measured worse or REJECT:
  `drop_degraded_transit`, `degraded_ctrl_disabled_action`,
  `wg_steer_to_kernel`, `is_degraded_local_or_control`,
  tagged-only/owned/local destination helpers, `parse_l2`,
  GRE-arm wrapper, `binding_slot`, cpumap/pass helpers.
- Stubbing the trace recorder: 647189. Stubbing the four
  binding/heartbeat readiness failure traces individually:
  RECEIVED-only removal 786154; the four readiness traces 819769.
  Keeping the four readiness traces as separate calls while
  outlining the readiness checks measured 953428 — the traces, not
  the map reads, are the multiplier: each inline failure arm made
  the verifier re-walk the packed trace callee under its own
  calling state.
- WG zone resolver outlined (`wg_zone_admits_packet`): -7.4k on
  the baseline, -13.6k in the final stack.

## Fix

Three outlines, no behaviour change (all in
`userspace-xdp/src/lib.rs`):

- `land_gate` (`#[inline(never)]`): the whole LAND gate — address
  compare, WG ingress-zone resolution, land_screen read,
  disposition, LAND_ALARM counter — as one subprogram returning
  "must drop". Both call sites (healthy + ctrl-disabled) keep
  their exact ordering and `land_drop` counter; ALARM still counts
  and falls through; unresolved zone / unknown byte still fail
  closed to DROP. This is the issue-directed outline (the
  `record_trace_packed` #15645 shape) and shares the zone
  resolution in one place.
- `wg_zone_admits_packet` (`#[inline(never)]`): the WG admission
  resolver's key construction + two map reads were inlined at both
  call sites (WG steer, worker claim); now walked once.
- `binding_ready_slot` (`#[inline(never)]`): binding + heartbeat
  readiness (slot resolution, READY flag, heartbeat read, timeout
  with the #1864 guarded `wrapping_sub` spelling) returns the slot
  packed with a failure code (1 missing/flags-zero, 2 not-ready,
  3 heartbeat-missing, 4 heartbeat-stale). The caller maps the code
  to the exact original trace stage/reason/slot (u32::MAX for a
  missing binding, the resolved slot otherwise) and the same
  degraded-local pass/drop decision — but through ONE shared trace
  call instead of four. The pinned #5173 lookup statement
  (`let binding = binding_slot(ingress_ifindex, rx_queue)
  .and_then(|idx| USERSPACE_BINDINGS.get(idx));`) is retained
  verbatim inside the callee; the queue still travels as the
  `RawRxQueue` wrapper (parameter, no second construction).

Deliberate pin moves (each stated at the pin):

- #5173 `TRACE_CALL_SITES` 12 -> 9 (four readiness traces merge
  into one; every failure keeps its stage/reason/slot values).
- #5173 mention tally for lib.rs: ingress 38 -> 41, rx_queue
  3 -> 5 (callee parameter, its pinned lookup, one call site, one
  merged trace call; no rebinding — both single-`let` bounds
  unmoved); `RawRxQueue` mentions 8 -> 9 (the callee parameter).
- Headroom outline pin extended with `land_gate`,
  `wg_zone_admits_packet`, `binding_ready_slot`. The verdict test
  itself needed no count change: the regenerated verdict is a
  measured PASS above the floor, which the test already accepts.

## Result

- Tracked object, gate verdict and freshness manifest regenerated
  with `pkg/dataplane/build-userspace-xdp.sh` (verify-then-install,
  no override): **815623 processed insns, 18.44% headroom — PASS,
  above the 15% #4555 floor** (was 963340 / 3.67% OVERRIDDEN, and a
  guest-kernel reject). Static size 52560 -> 46816 bytes. Stack
  328/512 (was 360/512 on the #15645 object).
- The #14954/#15645 OVERRIDDEN exception is retired by this
  measurement: the shipped verdict is `PASS`,
  `override_consumed: false`.

## Residual

Guest-kernel 7.0.0 acceptance (shimverify on fw1, cluster deploy)
cannot be executed from this host and remains for the lab lane;
the in-lane evidence is the same pinned object loading under this
host's 7.2.8 verifier at 18.44% headroom where the pre-fix object
measured 3.67% and rejected on the guest. Headroom is above the
floor but not large: the entry-path restructure deferred since
#14954 (splitting `try_xdp_userspace`'s arms behind packed
subprograms) remains the durable fix if the shim grows again.
