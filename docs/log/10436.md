# Issue #10436: process-generation-scoped NAPI startup bootstrap

## Disposition

The delayed startup NAPI bootstrap now captures the helper process generation,
`*exec.Cmd`, and supervisor record while scheduling. After the delay it checks
all three identities under `m.mu` before submitting the startup callback. The
callback's second goroutine repeats the same identity check before recording a
bootstrap or issuing probes. Completion channels make the lifecycle cells wait
for both callback layers to finish. A callback left behind by helper generation
G1 therefore becomes a no-op after G1 stops or crashes, even when generation G2
is already running. Same-generation startup still schedules the bootstrap
normally.

## RED-then-GREEN regression evidence

The original stale-callback behavior was reproduced before the fix with a
throwaway probe that used the production callback shape and an accelerated delay
(20ms instead of 3s). The probe installed G1, replaced it with G2 before the
callback woke, and asserted that no bootstrap timestamp was recorded:

```text
go test ./pkg/dataplane/userspace -run '^TestRED10436StaleStartupBootstrapReachesReplacement$' -count=1 -v
=== RUN   TestRED10436StaleStartupBootstrapReachesReplacement
    red_10436_probe_test.go:45: RED PROOF: stale G1 callback bootstrapped replacement G2 (#10436)
--- FAIL: TestRED10436StaleStartupBootstrapReachesReplacement (0.03s)
FAIL
FAIL    github.com/psaab/xpf/pkg/dataplane/userspace    0.036s
```

The permanent inner-hop cell failed when its identity check was temporarily
reverted to the pre-fix `m.proc == nil` guard. The test holds `m.mu` while the
inner callback is launched, moves the crashed G1 to replacement G2 through the
actual crash-gap generation sequence (procGen 1 remains during the gap, then
restart publishes procGen 2), releases the lock, and waits for callback
completion. The old inner callback recorded a bootstrap for G2:

```text
go test ./pkg/dataplane/userspace -run '^TestStartupNAPIBootstrapInnerStaleGenerationNoops10436$' -count=1 -v
=== RUN   TestStartupNAPIBootstrapInnerStaleGenerationNoops10436
    process_napi_startup_10436_test.go:79: stale startup bootstrap fired against G2 (lastNAPIBootstrap=...); the delayed callback is not generation-scoped (#10436)
--- FAIL: TestStartupNAPIBootstrapInnerStaleGenerationNoops10436 (0.00s)
FAIL
FAIL    github.com/psaab/xpf/pkg/dataplane/userspace    0.007s
```

The throwaway probe was removed. The permanent cells are fail-on-revert tests;
each waits for its scheduler completion channel, so silence cannot make a cell
pass:

| Cell | RED evidence | GREEN evidence |
| --- | --- | --- |
| `TestStartupNAPIBootstrapStaleGenerationNoops10436` | The pre-fix delayed callback bootstrapped G2 after G1's callback woke; the throwaway probe above reproduces that behavior. | `PASS`; the delayed G1 callback runs to completion, observes the crash-gap replacement at procGen 2, and does not update `lastNAPIBootstrap`. |
| `TestStartupNAPIBootstrapInnerStaleGenerationNoops10436` | The old inner callback ran after a blocked lock hop and accepted G2; the deterministic cell failed under the old inner guard above. | `PASS`; the inner callback runs to completion and rejects G2 before recording a bootstrap. |
| `TestStartupNAPIBootstrapSameGenerationFires10436` | Control invariant: a same-generation callback must remain able to schedule startup bootstrap. | `PASS`; the delayed and inner callbacks complete and update `lastNAPIBootstrap` with the captured generation still current. |

The permanent cells passed after restoring both fences:


The same cells passed under the race detector:

## Scope

The source change is limited to the delayed startup NAPI bootstrap in
`pkg/dataplane/userspace/process.go`. The regression cells are in
`pkg/dataplane/userspace/process_napi_startup_10436_test.go`; no sibling
NAPI/bootstrap callers were changed.
