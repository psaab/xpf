# #14726 — Scheduler recovery pair and overnight weekday windows

## Defect

Three coupled claims in `pkg/scheduler/scheduler.go` (D19-04):

1. **Recovery fail-open pair.** `evaluate` forces `s.active` all-false while
   `republishFailClosed` is latched. On a successful latch republish,
   `recordRepublishResultLocked` cleared `republishFailClosed=false` but left
   `s.active` as that forced map until the next `evaluate`. Any consumer
   reading `ActiveStateWithFailClosed()` in between — route listener
   (`daemon_route_listener.go`), ipmon overlay (`daemon_ipmon.go`), apply
   seeding (`daemon_scheduler.go`, all via `policySchedulerPublicationState`)
   — saw `(inactive, failClosed=false)`, which compiles scheduled
   DENY/REJECT rules inactive: fail-open. An intervening
   `RecordRepublishResult(nil)` from the apply path
   (`recordPolicySchedulerInitialPublishResult`) cleared the same latch (and
   could clear `republishRecoveryPending`) with the same stale map.
2. **Accessor contract.** `ActiveStateWithFailClosed` returns only the
   republish latch; `zoneUnavailable`/`unsafeUntil` are covered only by
   `PolicyFailClosed(now)`. This leg is by-contract (daemon publication
   paths already OR the two via `policySchedulerPublicationState` /
   `PolicyFailClosed`), so it is pinned by documentation, not changed
   semantics: `IsActive` stays latch-only.
3. **Overnight weekday.** `isWithinWindow` used only `now.Weekday()` plus
   `withinTimeOfDay`'s wraparound `now < stop`, so a Friday-only
   22:00–06:00 window was active Fri 00:00–06:00 and inactive Sat
   00:00–06:00 — exactly inverted.

## Fix

- `pkg/scheduler/scheduler.go`:
  - `recordRepublishResultLocked`: when clearing a set latch, set
    `republishRecoveryPending` (unchanged: exactly one normal-disposition
    republish remains owed) and call new `recomputeActiveLocked`, which
    rebuilds `s.active` from the scheduler configs at `lastEval` (already
    converted to the committed zone by `evaluate`), still forcing inactive
    during a wall-clock recovery hold or with an unavailable zone. No
    reader can now observe `(inactive, false)` for an in-window scheduler
    after recovery.
  - `isWithinWindow`: an overnight window belongs to the weekday it starts
    on. Today's wraparound window contributes only its evening segment
    (`now >= start`); the post-midnight segment is tested by new
    `overnightTailActive` against *yesterday's* resolved window (per-day
    arm or daily fallback). A today `exclude` suppresses the inherited
    tail; a uniform daily window is unchanged because yesterday resolves
    to the same window. Normal (non-wraparound) windows also honour a
    yesterday overnight tail, so divergent per-day arms compose.
  - Documented the split contract on `IsActive` /
    `ActiveStateWithFailClosed`: the latch boolean is republish-only;
    policy compilation must OR it with `PolicyFailClosed(now)`.
- `pkg/scheduler/README.md`: overnight and recovery-pair sections rewritten
  to the starting-weekday and consistent-pair semantics.

## Risk

Bounded to the scheduler package plus docs. `evaluate`'s publish decision
is untouched: the recovery follow-up still fires exactly once because
`recomputeActiveLocked` does not clear `republishRecoveryPending`. The
recompute uses `lastEval`, not the wall-clock `now` passed to
`RecordRepublishResult`, so no new clock read can resurrect a permit whose
window closed between the last evaluate and the apply-path success; the
next tick corrects any residual drift within 60 s. Overnight behaviour for
uniform daily windows and for non-wraparound windows is preserved (control
cells green on base and with the fix).
