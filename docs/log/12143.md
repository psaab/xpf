# #12143 — persist and surface deferred binary upgrades

- **Issue**: #12143 — postinst could return success after a publish or cut failure without durable staged-versus-running status.
- **Branch**: `fix/12143-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12143`
- **Base**: `83b5c955335f16d8c7835f206b210ce3ae1a5fe5` (reviewed head: `630b24fba1c6421167f3153949ed2f8880c4ab38`)

## Why

The Debian postinst intentionally preserves exit 0 when binary-generation publish or cut-over fails, avoiding a half-configured package. Before this change, generic failures were log-only and lock-contention hints lived under `/run`; no binary-channel consumer could report after reboot whether the staged generation differed from the running daemon.

## What

- Atomically persist a mode-0600 `/var/lib/xpf/upgrade-deferred` record for publish/cut failures, including staged and live daemon versions (or `unknown` when no running executable can be proven), stable reason, recovery command, and UTC time. Keep the deliberate exit-0 contract when a durable record or unreadable marker is available; fail the record writer if neither can be made durable.
- If status persistence fails before rename, install a durable unreadable marker under `/var/lib/dpkg/info`; readers treat it as unreadable, never clean. A post-rename directory-sync failure reports that the record exists but its crash durability is uncertain. Successful record writes clear the fallback marker.
- Avoid false `cut-failed` state for a same-version reinstall when the live process proves staged and running versions are equal. Discover the live executable through systemd `MainPID` and `/proc/<pid>/exe`.
- Guard successful CLI status clearing under the upgrade lock: clear when the known staged version equals `versions/current`, or when this invocation supplies health-confirmed evidence for a strictly newer Debian version. Recheck the journal under the lock; in-progress cuts retain the record. `running_version` motion is not supersession evidence.
- Sweep only abandoned pid temp files older than 24 hours, use a reader-accepted epoch timestamp if `date` fails, and report directory-sync risk accurately.
- Purge removes the record, fallback marker, and orphan temps. `xpfd upgrade status` reports pending or unreadable durable state. Unauthenticated `/health` reports readable/pending state, stable reason, and timestamp, but withholds exact staged/running versions under #5031; exact versions remain local CLI data.
- Exercise the production status dispatch and daemon health-status closure, preserve the actual systemd-present postinst branch in hermetic tests, and document stage-only, rollback, privacy, first-rollout status behavior, and unreadable-marker recovery through postinst.

### Astra LV-M1 + LV-M2 re-confirmation

Supersession evidence now carries the durable invocation generation in the
managed `versions/` runtime tree, which existing purge cleanup removes.
Each lock-held `Run` and rollback entry advances the generation, including
failed cuts and automatic rollback; a saved
`CommittedCut` can supersede a status only while its generation still matches.
Missing or malformed counters read as generation zero; the require-validity
gate (MINOR-3 fold, superseding the original legacy-zero honor) retains
all evidence when no valid generation matches. Counter read errors fail
closed. Counter-write failures are logged and do not abort a
cut or rollback, but that invocation receives unusable supersession evidence.

The Debian writer remains lock-free. Before clearing, the locked Go gate
re-reads and compares the complete status record through a held-open fd
(pinning the inode against number-reuse ABA), then moves the name aside with
an atomic renameat2-NOREPLACE quarantine: the quarantined file must fstat-match
the pinned fd AND the live name must still be vacant, else the clear retains
(dropping the quarantined copy when a newer record owns the name, restoring
it when the name is vacant but the file mismatches). A concurrent writer
rename either lands before the quarantine move (fstat mismatch → restore and
retain) or repopulates the name after it (vacancy check → drop and retain);
a writer landing after the final vacancy check still yields cleared=true with
the newer record retained — inherent to any final check. (The writer itself
never loses a NOREPLACE race — its mv falls back to plain rename; only the
clear-side restore can lose with EEXIST.) Conditional resolution does not
remove an unreadable marker that could have been installed by a concurrent
writer; the marker is re-checked before the quarantine move.

## Risk

If status-file persistence fails, the durable fallback marker makes readers report unreadable state rather than clean; if neither the record nor marker can be made durable, the postinst failure writer returns nonzero. A directory-sync failure after rename leaves the visible record but cannot guarantee persistence across a crash. `/health` remains informational and does not mark an otherwise forwarding old generation unhealthy. Clustered rollout and crash/power-loss durability were not exercised against a live system.
