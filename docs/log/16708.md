## Mechanism

`pskIDSelectorsLocal` added a local owner to every non-responder secret: the configured `local-id`, else the pinned local address, else `%any` — all values every VPN on the box shares. strongSwan's credential set (`mem_cred.c` `shared_filter`) enumerates a secret when **any** of its owners matches **either** side of the `(me, other)` pair, and the IKEv2 PSK verifier (`psk_authenticator.c` `process`) tries **every** enumerated secret against the peer's AUTH. The peer selector therefore never discriminated verification: each secret was tried for each peer on the strength of the responder's own (shared local) side. Measured cases: (a) a peer at a fixed gateway's address holding a different VPN's PSK authenticated as that gateway's peer; (b) a peer at any address holding a fixed VPN's PSK and claiming a responder-only `dynamic hostname` VPN's identity authenticated into that VPN (reopening #14591). The in-tree claim that "%any as one owner AMONG peer selectors keeps isolation" was contradicted by measurement.

## Fix and why the #15193 initiator cells still work

Peer selectors only (`remote-id`, else `@dynamic-hostname`, else one per IP-literal gateway address). Dropping the local owner does not re-break #15193 because the connection render pins `remote.id` for fixed-address PSK gateways (`defaultRemoteID` / inline arm), so charon's initiator lookup carries the peer as `other_id`: IKEv2 `get_shared(my_id, other_id)` enumerates via the peer owner, IKEv1 phase1 uses the configured `other_id` and its address-fallback lookup is keyed by the peer socket address. Multi-address gateways pin no `remote.id` (#15766) but carry one selector per peer address, and the peer's negotiated address identity matches it.

## Operator-visible delta

A PSK VPN on a hostname-addressed gateway (`address <fqdn>`, or an inline hostname endpoint) with **no** `remote-identity` no longer loads: strict commit rejects it naming #16708, tolerant loads warn, and the renderer skips it (sibling VPNs still render). Configure `remote-identity` on the gateway (the #16680 workaround, now required for that shape) or address the gateway by IP literal. All other PSK shapes render byte-identical connections; only the secret `id-<n>` lines lose the local owner.
