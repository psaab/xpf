# Issue #13655: preserve declined ICMP sessions across zone renames

## Why

When first-policy rematching encounters a type-dependent ICMP verdict, it
must decline frame-independent policy reevaluation so packet-scoped ICMP
enforcement can decide the hit. That path retained the session but left its
old ingress/egress zone IDs in the local table, conntrack, and shared aliases.
A combined zone and policy rename therefore left stale zone identity attached
to the retained session and caused later packet processing to use outdated
zone metadata.

## What

Add a zone-only pair rebind that updates both session halves and transfers the
counted ingress zone/IP accounting without changing the admission policy ID or
counter. The declined ICMP path now skips the unnecessary policy walk, restamps
BPF/shared session metadata and republishes the worker map rows using the
validated ancestry-derived zone IDs. Missing ancestry and failed restamps remain
fail-closed. Add a worker-loop regression for a simultaneous zone/rule rename,
asserting that both ICMP pair halves use the new zone IDs while retaining the
original policy identity.

## Risk

Policy identity is deliberately unchanged for declined ICMP sessions; their
packet-scoped session-hit checks remain responsible for enforcing
type-dependent permit/deny terms.
