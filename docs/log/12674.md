# #12674 — fail closed on policy-level `from` clauses

## Red before

A policy statement without terms could carry `then accept` and `from` clauses in either order. The hierarchical compiler collected policy-level `from` into `PolicyStatement.UnknownFrom` only when it appeared as a child node; compact `policy-statement P then accept from ...` carried the whole run on the named node, so the compiler read `then accept` and silently ignored the remaining match. On SetPath replay, a then-first policy-level clause also landed below the `accept` action. These shapes committed with `DefaultAction=accept`, no unknown marker, and no typed match. A bare policy-level `from;` was similarly represented as no clause, allowing an explicit accept-all.

The same empty-node distinction affected a term-level bare `from;`: no match predicate existed in the typed term or `UnknownFrom`, so `then accept` committed as an unrestricted term.

## Change

- `SetPath` now recognizes the policy-level `then` schema node and splits an ensuing `from` into a sibling policy clause before replaying the default action. It retains quote/bracket provenance and does not match term-level `then` paths.
- Policy-statement compilation reads compact clause keys on the named instance node as well as ordinary `from` / `then` children. A policy-level match remains unsupported by the FRR compiler and is retained through `PolicyStatement.UnknownFrom`; the existing strict gate rejects it and tolerant compilation forces the policy default and terms to reject.
- Empty policy-level and term-level `from` nodes now retain an explicit missing-predicate marker, so they cannot be confused with an omitted optional clause.
- A policy containing only `then accept` remains valid. Supported term-level match compilation is unchanged.

## Coverage

`pkg/configstore/policy_level_from_12674_test.go` checks then-first and from-first policy-level route-filter clauses, from blocks, protocol clauses, compact node-key runs, policies with terms, and unsupported-neighbor controls through `LoadOverride`, `LoadMerge`, `LoadSet`, and direct `set`. Bare policy- and term-level `from` variants are covered on those same ingress paths and by `CheckText`. It also covers the valid default-accept / term-route-filter controls and tolerant `SyncApply` fail-closed behavior.
