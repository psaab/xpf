# #15271 — PBR kernel-mirror overflow degraded reporting (B21-02)

## What was wrong

`buildPBRFromFilter` returned `overflowed=true` for ANY single term whose
Cartesian product exceeded the remaining budget — even when the window
still had room (e.g. one 676-rule term against an empty 500-rule budget).
`BuildPBRRules` latched that into a closure-shared flag and skipped every
remaining term and attachment, including the whole inet6 build. The
degraded error and the `PBRBuildRulesAndStats` count named only the
oversized term, so the visible signal undercounted what was lost. Only
the kernel ip-rule mirror was affected (slow-path/XDP_PASS packets);
userspace FBF steering was intact.

## Fix

- `pkg/routing/rules.go` `buildPBRFromFilter`: on an over-budget term,
  skip only that term and keep building while `len(rules) < budget`;
  return `overflowed=true` only when the running total has actually
  reached the budget. Dropped terms were already appended to
  `precedingTerminating` before the drop, so first-match shadowing for
  later terms is preserved.
- `BuildPBRRules`: on genuine exhaustion, `accountPBRWindowExhausted`
  records one overflow degraded error per unbuilt routing-instance term
  across the remaining attachments and the other family (budget-0
  accounting pass — no Cartesian product is expanded), so the error and
  count name every skipped term. Deterministic output is preserved
  (attachment order is sorted; rebuilds are byte-identical in count).

Acceptance probe: one oversized steer4 term + one small steer6 term now
yields exactly 1 IPv6 rule plus one steer4 error (previously 0 rules).
