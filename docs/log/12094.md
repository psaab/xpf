# Issue #12094 — include enforced wildcard zone-pair stanzas in filtered policy views

## Why

Filtered `show security policies` views compared configured zone-pair names to the requested pair by exact string equality. That hid `any -> zone`, `zone -> any`, and `any -> any` stanzas even though the runtime evaluates them for the selected pair before globals. This made the displayed hit counts and policy inventory incomplete.

## What

Added `policymatch.ZonePairPolicyAppliesToFilterPair` as the shared applicability predicate, plus the matching exact/single-wildcard/both-wildcard tier classifier. The gRPC text hit-count/detail views, local CLI hit-count/detail and brief/standard views, and remote CLI filtered view now include applicable wildcard stanzas, render them in enforcement order, preserve counter IDs, and exclude unrelated concrete pairs. Global policy selection remains governed by the existing scoped-global predicate and appears after zone-pair tiers. The CLI reference now documents the filtered-view behavior.

## Validation

- **RED before:** `go test ./pkg/grpcapi -run '^TestGRPCHitCountFilteredKeepsWildcardPairs$' -count=1` failed before the implementation because the filtered hit-count omitted `wild-deny`.
- **GREEN after:** New hermetic tests pass for the shared predicate/tier, gRPC hit-count and detail, local CLI hit-count/detail/brief/standard, and remote CLI filtered output (including hit-count rows). They assert exact → single-wildcard → both-wildcard → global order and exclusion of `dmz -> untrust`.
- `go test ./pkg/grpcapi ./pkg/cli ./cmd/cli ./pkg/policymatch -count=1`: gRPC, local CLI, and policymatch suites passed. The full `cmd/cli` suite's `TestTreeIsGofmtClean` failed on 11 files outside this change, including `pkg/cli/cleartext_sync_alarm_11773_test.go`; the focused remote filtered-view tests passed.
- `go build ./...` passed. `gofmt -l` over all touched Go files returned no paths.
- No live-cluster or lab mutation was performed.

## Risk / residual

This changes display selection and order only; packet-policy enforcement and policy matching are unchanged. The lab acceptance remains unverified; the filtered behavior is covered by hermetic render tests.
