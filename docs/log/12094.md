# Issue #12094 — include enforced wildcard zone-pair stanzas in filtered policy views

## Why

Filtered `show security policies` views compared configured zone-pair names to the requested pair by exact string equality. That hid `any -> zone`, `zone -> any`, and `any -> any` stanzas even though the runtime evaluates them for the selected pair before globals. This made the displayed hit counts and policy inventory incomplete.

## What

Added `NewZonePairPolicyFilter` and `ZonePairPolicyAppliesToFilterPair` as the shared prepared selector and applicability predicate, plus the exact/single-wildcard/both-wildcard tier classifier. The gRPC hit-count/detail, local hit-count/detail/brief/standard, and remote filtered views include applicable wildcard stanzas in runtime order with stable counter IDs and detail Index values.
Transit wildcard expansion is limited to defined, non-quarantined concrete zone filters; explicit literal `any` filters do not expand transit tiers. The host-bound view excludes transit `to-zone any` and `any -> any`, retaining exact host pairs and the runtime `any -> junos-host` exception for unknown ingress. Quarantined filters retain exact authored pairs without expanding transit wildcard tiers.
Global selection remains governed by the scoped-global predicate and appears after zone-pair tiers. The unscoped-global host-view mismatch and remote brief filter omission are tracked in follow-ups #12523 and #12524. The CLI reference documents the filtered-view behavior.

## Validation

- **RED before:** `go test ./pkg/grpcapi -run '^TestGRPCHitCountFilteredKeepsWildcardPairs$' -count=1` failed before the implementation because the filtered hit-count omitted `wild-deny`.
- **GREEN after:** Focused regressions passed for the shared predicate/tier, gRPC hit-count/detail and host render, local hit-count/detail/brief/standard, and remote filtered output. They assert exact → single-wildcard → both-wildcard → global order and exclusion of `dmz -> untrust`.
- An 840-case single-stanza/filter-pair oracle against `policymatch.Match` reported zero over-matches and zero under-matches, including host, literal-any, undefined, and quarantined filters.
- Focused `go test` passed for predicate/quarantine cases; gRPC wildcard counter/detail, host-render, and quarantine regressions; local wildcard counter/detail and quarantine regressions; and all `cmd/cli` `TestShowPoliciesFiltered` tests.
- `gofmt -l` over touched Go files returned no paths.
- No live-cluster or lab mutation was performed.

## Risk / residual

This changes display selection and order only; packet-policy enforcement and policy matching are unchanged. The lab acceptance remains unverified; filtered behavior is covered by hermetic render tests. The unscoped-global host-view mismatch (#12523) and remote brief filter omission (#12524) remain separate follow-ups.
