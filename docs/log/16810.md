# Issue #16810: shared OSPF router-id in an active/active RG split

- **Timestamp**: 2026-10-25
  - **Action**: Rejected at strict commit (warn on tolerant load) a
    non-node-specific OSPF/OSPFv3 router-id or IS-IS NET whose enabled
    interfaces span RETHs of more than one data RG in cluster mode,
    and added a daemon single-participant render belt for tolerant
    loads. New gate
    `pkg/config/compiler_validate_cluster_igp_identity_16810.go`
    (`validateClusterIGPIdentityStrict`, wired beside
    `validateRouterIDStrict` in
    `compiler_uniformgates_log_feed_routing.go`, lenient flag
    `lenientClusterIGPIdentity16810`); the Junos `groups node0/node1`
    + `apply-groups "${node}"` remedy is excused via a pre-expansion
    both-node-views comparison
    (`igpIdentityNodeViewsDistinct16810`, result threaded through
    `opts.igpIdentityExcused16810` in `compiler.go`). Daemon belt in
    `pkg/daemon/daemon_frr_rg_shutdown_11415.go`
    (`enforceSingleIGPParticipant16810` in `filterProtocols`): only
    the owner of the lowest-numbered spanning data RG keeps a
    multi-RG-spanning OSPF/OSPFv3/IS-IS protocol. Docs:
    `docs/config-schema.md` (#16810 subsection). Tests:
    `pkg/config/cluster_igp_identity_16810_test.go`,
    `pkg/daemon/daemon_frr_igp_identity_16810_test.go`.
