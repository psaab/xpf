# #16782 — #15059 mgmt-DNS static refusal missed FRR statics (RTPROT_ZSTATIC)

- **Timestamp**: 2026-10-25
  - **Action**: `mgmtDNSRefusedNameserver` accepted only `RTPROT_KERNEL`
    (connected) and `RTPROT_STATIC` (4) as main-table coverage, but every
    operator `routing-options static` route is installed by FRR/staticd
    as `RTPROT_ZSTATIC` (196) — no Go writer installs main-table proto-4
    statics — so the static leg of the #15059 SECURITY refusal never
    fired live, and a mgmt-DHCP nameserver covered by an operator static
    was still steered into table 999 and published without warning.
    Fix: accept both static spellings (4 and 196) with an explicit
    non-default bound — a `/0` in either spelling never refuses, because
    FRR also renders the WAN DHCP default as 196 and refusing on it
    would disable all management DNS steering. Ordering: the commit
    path in `applyConfigLocked` ran `applyMgmtDNSRules` before
    `applyFRRFull`, so a static installed by the same commit was not yet
    in the kernel inventory; the reconcile now re-runs after FRR
    converges and its error joins the management-route commit error.
    NOT changed: connected/peer legs, rule priorities/proto/port scope,
    readiness/publication semantics, fail-closed behaviour on an
    unreadable main inventory.
  - **File(s)**: `pkg/daemon/daemon_mgmt_dns_rules.go`,
    `pkg/daemon/daemon_apply.go`,
    `pkg/daemon/mgmt_dns_refusal_15059_test.go`,
    `docs/dns-ownership.md`, `docs/log/16782.md`
  - **Validation**: new `TestMgmtDNSRefusesFRRZStaticCoveredNameserver16782`
    (proto-196 non-default v4/v6 refuses with steering+publication
    denial, proto-196 `/0` and proto-4 `/0` do not refuse a legit
    nameserver, table-999 196 does not refuse, manual proto-4
    non-default still refuses) and
    `TestMgmtDNSReconcileRerunsAfterFRR16782` (source-order pin for the
    post-FRR re-run); existing #15059 tests stay green. Targeted daemon
    tests and `go vet` in the commit body.
  - **Risk**: A mgmt nameserver under an operator static now resolves
    via main instead of table 999 — the intended #15059 behaviour, now
    live for the FRR spelling. The post-FRR re-run is idempotent; a
    failure there fails the commit via the existing mgmt-route error
    slot rather than silently leaving stale steering.
