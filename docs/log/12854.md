# Issue #12854 — exclude quarantined scopes from host-inbound pending status

The addressless zone reporter walked raw configured zone memberships after the
host-inbound view builder had excluded reserved and StableZoneID-collision
loser zones. Those scopes therefore appeared permanently addressless and kept
the daemon's early host-inbound barrier pending. The same raw-membership walk
could report zones whose only interface membership was contested and omitted
from the runtime interface map.

The reporter now applies the shared zone quarantine exclusions and only keeps
interface refs that resolve to the reporting zone through the canonical runtime
interface map. The per-interface reporter explicitly excludes quarantined zones
and contested logical-interface keys. Legitimate DHCP-pending scopes remain
reported; strict/tolerant configuration behavior and enforcement are unchanged.

Regression coverage includes a collision loser, a reserved zone, a contested
interface, a statically-addressed collision survivor, a pending-intent check,
and a legitimate DHCP-pending positive control.

Validation: The regression tests failed before the fix because `z214` and
`junos-host` were reported and pending intent remained true; the named
regression tests passed after the fix. `go test ./pkg/dataplane/userspace -count=1`
passed. `go build ./...`, `go vet ./...`, `gofmt -l` on the changed Go files,
and `git diff --check` passed. `go test ./...` did not pass: it hit a `/tmp`
space exhaustion and reported failures in unrelated CLI formatting, config,
dataplane, FRR, and other package checks; the userspace package passed within
that run.
