# Issue #15101 — endpoint resolver drops A answers on the dual-stack WG socket (A69-01)

- **Timestamp**: 2026-10-19
- **Action**: `endpoint_resolver.rs` filtered DNS answers with
  `find(|a| a.is_ipv6() == socket_is_v6)`, but `socket_is_v6 == true` is
  the DUAL-STACK socket (`sock.rs` clears `IPV6_V6ONLY` at bind, and
  `wg_send_to` maps IPv4 targets to their v4-mapped form), so every
  A-only DDNS answer was dropped as a "family mismatch" and the peer
  could only come up while the remote initiated. Replaced the equality
  filter with `choose_endpoint`: the dual-stack socket accepts A and
  AAAA, preferring the family of the interface's literal endpoints when
  it has any (`preferred_v6`, computed in `tunnel_supervision.rs` from
  the hydrated literal peers and threaded through `wg_control_loop`),
  otherwise AAAA then A; the v4-fallback socket keeps taking only A,
  and an AAAA-only answer there stays the counted/named
  `family_mismatch`. Corrected the false-premise #7158 test
  (`only_addresses_of_the_socket_family_are_adopted_7158` now pins
  dual-stack adoption plus v4-fallback rejection), added
  `dual_stack_answers_prefer_the_literal_family_then_aaaa_15101` and
  `v4_fallback_socket_still_prefers_a_15101`, a dual-stack delivery
  test (`wg_send_to_delivers_resolved_v4_on_dual_stack_socket_15101`),
  and the Go-side comment in `compiler_validate_wireguard.go`. The
  mixed-literal commit gate itself is unchanged (the dual-stack socket
  sends both, so it stays as the operator's pinned outer family).
