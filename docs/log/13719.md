# #13719 — exclude quarantined and missing-link interfaces from gateway resolution

- **Timestamp**: 2026-10-15
- **Action**: Reject quarantined and linkless interfaces when resolving forwarding-instance gateways; count a live unit-0/base netdev once for link-local resolution.
- **Base**: `origin/master` `2f1778ff9`
- **Files**: `pkg/dataplane/userspace/routes.go`, `pkg/dataplane/userspace/routes_gateway_quarantine_13719_test.go`, `pkg/dataplane/userspace/fbf_snapshot_test.go`, `docs/log/13719.md`

## Why

`forwardingGatewayInterface` admitted default-instance rows carrying the
quarantine sentinel `RoutingDomain == 2`, even though they are deliberately
outside any routing instance. It also used configured addresses from rows
with `Ifindex <= 0`, although the route builder already excludes those rows
from connected routes. Finally, a physical base row and its unit-0 row can
share the same live netdev; counting both made the link-local resolver treat
one egress as ambiguous and leave the forwarding-instance route unresolved.

## What

- Both global-gateway and link-local candidate paths now reject rows without
a positive ifindex. The global default-instance branch now mirrors the
link-local branch's `RoutingDomain == 0` guard.
- Link-local resolution skips a base row when its same-name `.0` unit row
shares the same LinuxName and ifindex, retaining the unit row as the interface
identity. Distinct links remain ambiguous.
- Added direct regression coverage for quarantine, missing links in both
families, unit-0/base deduplication, distinct-link ambiguity, and a valid
control; added an end-to-end route-snapshot quarantine regression. Existing
link-local tests now model live interfaces with positive ifindices.

## Risk

Only forwarding-instance bare-gateway qualification changes. Interfaces that
lack a kernel netdev or are explicitly quarantined no longer qualify as an
egress; link-local gateways resolve against one live netdev identity rather
than falsely treating its base/unit-0 aliases as separate links.
