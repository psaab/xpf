# Issue #17141 — split refresh_status into project_status + supervise_tunnels

- **Issue:** `refresh_status` was documented as a cold-path projection but ran WG/GRE tunnel-thread supervision (thread joins, respawns, worker-visible delivery-map publishes). Mutating non-suppressed handlers ran it and the dispatcher ran it again, so one `update_ha_state` ran two WG sweeps, two GRE sweeps and four delivery-map rebuild-and-store cycles under the `ServerState` mutex. The WG reconciler also republished unconditionally twice, while its GRE twin published only on change.
- **STEP-0 (live on origin/master `d37b4a1667`):** Verified in the worktree: `server/helpers/status.rs:26-47` embedded both `reconcile_*_liveness` calls in `refresh_status`; `handlers/ha.rs:43,49` + `handlers/mod.rs` post-match attach both called it for non-suppressed `update_ha_state`; Go `manager_ha.go` senders do not set `SuppressStatus`; `tunnel_supervision.rs` WG liveness published at both ends unconditionally while GRE published only `if swept > 0 || spawned`, and the WG sweep returned `()` vs GRE `usize`.
- **What:**
  - `server/helpers/status.rs`: split into `project_status` (pure projection, no `reconcile_*_liveness`), `supervise_tunnels` (bindings refresh + `should_run_afxdp` gate + both reconciles). Fold (Rev18195 F1): the `refresh_status` composite was deleted once every caller had migrated to `project_status` — no retention shim.
  - `server/handlers/mod.rs`: the dispatcher supervises once per locked request (including suppressed ones, preserving the 1 Hz self-heal cadence) inside its single `lock_server_state_recover` acquisition, before the match (fold Rev18195 F2: no separate supervision lock), and every status attach (post-match, settle, both export tails) now only projects.
  - All per-verb handlers, `finish_binding_reconcile`, `build_state_payload`, `wait_for_binding_settle`, and shutdown now call `project_status`; supervision is no longer a handler side effect.
  - `tunnel_supervision.rs`: on merged master (#17084 `TunnelThreadRegistry`), `wg_control_threads.sweep_finished()` returns the tombstoned count and `spawn_one_wg_control_thread` returns `bool`; `reconcile_wg_control_liveness` publishes only `if swept > 0 || spawned`, mirroring GRE (master's unconditional publish-on-entry was NOT retained). Added a `#[cfg(test)]` delivery-publish counter hook in `publish_local_tunnel_deliveries_excluding`.
  - Existing projection tests migrated from `refresh_status` to `project_status`; docs/comments updated (`helpers/mod.rs`, `server/README.md`, coordinator README, protocol/status comments).
- **Acceptance tests:**
  - `project_status_contains_no_tunnel_supervision_17141` (source gate in `status_wiring_tests`, with a vacuity guard that `supervise_tunnels` owns both reconciles).
  - `update_ha_state_publishes_delivery_map_at_most_once_17141` (dispatcher cell through `handle_stream`: armed + forwarding-supported state, counter armed, non-suppressed `update_ha_state`, asserts exactly 0 publishes — fold Rev18195 F3 tightened `<=1` to `==0`, since with no tunnel entries both reconciles publish only on change and supervision runs once; pre-fix shape would count 4).
  - Named existing cells rerun: `update_ha_state_populates_status_ha_groups`, `ping_returns_ok_and_attaches_status`, `suppress_status_omits_status_payload`, plus #1866/#1881 WG/GRE self-heal cells.
- **Risk:** Supervision now runs before the verb instead of interleaved with handler refreshes; the gate still reads freshly refreshed bindings, handlers still project after mutating. `refresh_status` is deleted (fold F1) — no caller retains combined behaviour. No wire change. Merged with current origin/master: master landed #17126 `finish_binding_reconcile` after this branch forked; its callers (forwarding/binding/queue via the shared tail) project only (`project_status` in both tail arms), settle semantics (`settle_wait`/`persist_state` set only on success) unchanged.
- **Fold (Rev18195Opus, merged origin/master `47a93d76fd`):** F1 delete dead `refresh_status`; F2 dispatcher single lock (supervise inside second/former lock before match); F3 publish-count cell `==0`; merge conflict in `tunnel_supervision.rs` resolved onto #17084 registry (sweep=`wg_control_threads.sweep_finished()`, tombstones=`tombstone_ids()`, spawn returns bool, publish-only-on-change retained over master's unconditional publish). 14 PR-named cells rerun on the merged tree.
