# One swanctl connection per IKE gateway (#15024)

- **Issue**: #15024 — two VPNs on one IKE gateway rendered as two independent
  swanctl connections; a peer that runs them as children of one IKE SA cannot
  bring up the second VPN (TS_UNACCEPTABLE).
- **Cause**: `renderConfigWithExternalInterfaceFailClosed` in
  `pkg/ipsec/policy.go` iterated VPNs and emitted one connection per VPN,
  each copying the gateway's addresses/auth/proposals. No grouping by
  `vpn.Gateway` existed anywhere in `pkg/ipsec`.
- **Change**:
  - `pkg/ipsec/policy.go`: surviving VPNs are collected into `gatewayConn`
    groups keyed by `gatewayKeyFor` — the sanitized gateway name when the
    VPN references a defined gateway, otherwise the sanitized VPN name
    (inline literal/hostname and empty endpoints keep per-VPN connections).
    The first sorted member supplies the shared IKE block (version,
    local/remote_addrs, encap, DPD delay/timeout, local/remote auth,
    proposals, rekey_time); every member contributes its children with
    per-child ESP proposals/lifetime, DF-bit, start_action, DPD action and
    if_id carried on `childSelector`. One `ike-<connection>` secret per
    connection comma-joins distinct member PSKs, scoped by the
    representative member's `pskIDSelectors` (#3952). A section-breaking
    gateway name skips its VPNs (#9495). The rendered set now holds
    connection names. `ConnectionNamesForVPN` (new) and `RenderedVPNSet`
    (now VPN-keyed via it) expose the mapping; `BuildSANameIndex` renders
    the whole config once and indexes the connection name to every member
    VPN, children unchanged.
  - `pkg/ipsec/generation.go`: `expectedLoadedConns` unions member children
    under the gateway connection.
  - `pkg/ipsec/manager.go`: `reinitiateChangedConnections` matches changed
    connections by gateway key (once per connection);
    `filterIPsecCfg14589` keeps every member of a kept connection.
  - `pkg/ipsec/README.md`: gateway-grouping gotcha and updated
    `SANameIndex` / `ExpectedLoadedConns` entries.
  - New regression: `pkg/ipsec/gateway_group_15024_test.go`.
- **Deliberately NOT changed**: child SA names (`<vpn>-<selector>`, `<vpn>`
  sole child) are byte-identical, so `ipsecname.SANames`, the #9624 commit
  gate and HA child initiation are unaffected; only the connection name
  (IKE SA name in `--list-sas`) changes from VPN name to gateway name for
  grouped VPNs. `pkg/config` validators continue to key by VPN.
- **RED**: before the fix, `go test ./pkg/ipsec -run '15024' -count=1`
  failed: `rendered = map[vpn1:true vpn2:true], want exactly {gw}`,
  `secrets = [ike-vpn1 ike-vpn2], want [ike-gw]`, and the distinct-gateway
  control rendered VPN names instead of gateway names.
- **GREEN**: after the fix the three `15024` cells pass. The full
  `pkg/ipsec` suite shows 65 pre-existing tests failing because they assert
  the old per-VPN connection/secret names for named-gateway fixtures
  (e.g. `connections/site-a`, `ike-vpn-a`); those assertions name the exact
  behaviour this issue removes and were left for the parent review to
  decide on updating — no other package was modified.
- **Risk / lab-bound**: the rendered shape (one connection, both children,
  combined PSK list) needs live charon proof that a peer establishing
  vpn1 then vpn2 (and the reverse order) negotiates both children under
  one IKE SA; unit render/index/generation cells are the gate here. On
  upgrade, previously loaded per-VPN connections depart the rendered set
  and their SAs are terminated once by the existing #5494/#3941 diff,
  then re-established under the gateway connection.
