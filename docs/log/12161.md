# #12161 — prevent a leaked kernel election hold on fallback boot

- **Issue**: #12161 — an ARMED journal on a known-good fallback boot must not be treated as a candidate trial.
- **Branch**: `fix/12161-kernel-hold`
- **Worktree**: `/var/worktrees/12161-kernel-hold`
- **Base**: `1c384b9a47ff7d6e567fa50632faa75c3995ae87`

## Why

With daemon-before-gate ordering, the daemon previously set the ordinary candidate election hold for every ARMED journal. If the host was already running the known-good kernel, the promotion gate discarded the candidate and cleared its journal/marker without rebooting, but ordinary-hold reconciliation waited for a promotion marker matching the running kernel. No such marker is written on discard, leaving a healthy node election-ineligible. A genuine candidate boot must still stay held through the revert window.

## What

- Compare the running kernel with `CandidateVersion` before setting the ARMED candidate hold. Skip that hold on a positively identified known-good fallback; retain it when the kernel cannot be identified or the candidate version is invalid.
- Apply the same distinction when an unreadable-journal fail-closed hold later discovers an ARMED journal: convert only on a running candidate, release on a known-good fallback, and keep holding if the running kernel is unreadable.
- Keep the existing promotion-marker-only release for a genuine candidate hold, preserving protection while a reverted candidate is still running.
- Add deterministic daemon-before-gate fallback coverage, a gate-before-daemon guard, fail-closed conversion coverage, and a running-candidate revert-window guard. No live cluster or hardware is mutated.
