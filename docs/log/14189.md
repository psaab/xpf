## Why

On a DHCP lease IP change, the DDNS two-pass reconcile deleted the old A record together with its RFC 4701 DHCID (Pass 1), then tried to re-add the new A (Pass 2). `dhcidSharedWithOther` scanned only the ownership store, so the not-yet-published replacement in the desired set was invisible and `KeepForwardDHCID` was false. With any co-resident RRset (e.g. TXT) at the name, Pass 2's `sendAddOwned` Attempt A failed YXDOMAIN and Attempt B failed NXRRSET because the DHCID proof had just been deleted — `errDDNSConflictRefused` on every reconcile, forever: a permanent forward blackhole after an ordinary IP change.

## What

- Hoist the reconcile `desired` struct to package-level `desiredRecord` so helpers can consult the desired set.
- Add `dhcidStillWanted(owned, want)`: true iff the desired set still wants a record with the same ClientID and canonical FQDN (hence the same DHCID) as the record being deleted.
- Pass 1 computes `keepDHCID := dhcidStillWanted(owned, want)` — the owned key embeds the address, so an IP change makes `stillWanted` false even though the name is still wanted; the want scan is the actual move test — and threads it into `deleteOwnedLocked(..., keepDHCIDForMove)`, which ORs it into `rec.KeepForwardDHCID`. Genuine expiries, withdraw-all, and factory-reset withdrawal all pass `false`, so expiration semantics (DHCID removed with the last record) are unchanged. The delete stays DHCID-match-guarded; only the DHCID's removal is suppressed. No test-input special-casing.
- Regression `TestIPChangeWithCoexistingTXTKeepsDHCID_14189` (stateful fake RFC 2136 server via production manager): publish A=10.0.0.10+DHCID, seed a foreign TXT at the same name, move the lease to 10.0.0.11, assert the new A and DHCID are present, the old A is gone, the TXT is untouched, and a later full release still removes A+DHCID and leaves the TXT.

## Validation

- RED on pristine `origin/master` (43ebebd38): `TestIPChangeWithCoexistingTXTKeepsDHCID_14189` fails — "new A 10.0.0.11 not published after IP change (permanent conflict refusal)".
- GREEN with the fix: the regression passes, including repeat-reconcile stability and full-teardown DHCID cleanup.
- Full package: `go test ./pkg/ddns/ -count=1` passes; `go vet ./pkg/ddns/` clean.
