## Gate verdict (adversarial review)

- **Strongest supported defect**: Inside a valid `range R { ... }`, `typo-match-value`, valueless `match-value;`, and `match-start layer-4 extra;` all compiled clean on strict `CompileConfig` with defaults Value 0 / Mask 0xFFFFFFFF / BitLength 32 and empty `UnknownFlexMatch` (probe on base worktree, hierarchical + flat). Direct leaves under `flexible-match-range { match-start ...; }` lost the whole predicate (FlexMatch nil, term became unconstrained). Nameless `range { match-value ... }` fabricated range name `match-value`. Empty `range R {}` defaulted.
- **Strongest refutation/alternative**: Direct leaves are outside schema grammar (`schema_cos.go` only declares `range` under flexible-match-range) — so for direct leaves the correct fix is strict-reject (record), not compiling an anonymous range. Empty range could be Junos defaults, but authoring an empty named range with no fields is indistinguishable from a typo'd body; fail-closed recording is consistent with #3203/#3307 doctrine. Existing controls that asserted direct leaves commit (`firewall_valueless_from_8480_test.go`, `firewall_from_unrepresentable_9875_test.go`) encoded the bug and were updated.
- **Gate**: MATERIAL (narrowed as in issue). Fix via existing `UnknownFlexMatch` → `validateFilterFlexMatchStrict` channel; no new gate, no new field. Tolerant path already downgrades to warning and userspace/lo0/PBR poison on `UnknownFlexMatch>0`, so lenient fail-closed is inherited.

## What

`pkg/config/compiler_firewall.go` (`compileFilterFrom`, flexible-match-range case):
- Expand a packed tail on the flex node via `packedBody` under the flex schema; if unresolvable, record `flexible-match-range <token>`.
- Inspect every child of the (expanded) flex node: direct field leaves (`match-start`/`byte-offset`/`bit-length`/`match-value`/`match-mask`) and unknown children (except fused `then`, owned by #12528 pre-walk) recorded on `UnknownFlexMatch`.
- Nameless/bare ranges recorded: `range;` (no name, no children) and `range { <field> ... }` (first child is a field, which `namedInstances` would fabricate as a name). Block-named `range { R { ... } }` preserved (first child is the name).
- Inside each range: new `recordFlexRangeChild14347` records unknown leaves, valueless leaves (`nodeVal==""`), trailing tokens (`len(Keys)>2`), and children-carrying leaves (`len(Children)>0`, covers `byte-offset { 9; }` and flat nested `extra` child). Empty ranges recorded (`range <name>`). Later distinct ranges still cardinality-rejected but their bodies are now inspected for malformed leaves.
- Valid paths unchanged: known leaves with exactly one value apply as before; `range 0xV/0xM` alias, bracket/packed runs via `expandResolvingRuns9792`, same-name merging (#9899), cardinality (#5823).
