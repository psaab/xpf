# #9054 — the learned-route cap composed with the NoRoute adjudication is a silent total FIB blackhole

## Summary

#8355 caps the learned-route import above ~65,000 routes and declines the whole
import, documenting the degradation as "traffic still forwards through the
kernel, just not on the fast path". #7480, closed separately, made a `NoRoute`
frame get adjudicated against the #3110 unzoned egress sentinel — which no
zone-pair or `junos-global` permit can match — so the verdict is the DEFAULT
action and a Junos-default deny box drops it. Composed, the cap black-holes the
entire dynamic FIB and the operator log states the opposite.

## The behaviour change, stated plainly

While the cap is tripped, a `NoRoute` frame is delegated to the kernel instead
of dropped. That is a real widening of the #6664 delegated set relative to
master, bounded to the capped state, and it is the trade this issue's own fix
direction sanctions ("an explicit `NoRoute`-permit disposition while capped").
The alternative on master is a total outage of the dynamic FIB. The kernel FIB
remains the authority, so a destination with no kernel route is still dropped.
Both the WARN line and `docs/multi-wan.md` now say so.
