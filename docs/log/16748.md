# #16748 — Session-sync pre-auth accept path logs INFO per connection and WARN per failed handshake

- **Timestamp**: 2026-10-25
  - **Action**: Demoted the pre-auth `cluster sync: peer connected`
    INFO in `acceptLoop` to Debug. It fired before the #5303
    admission check, so a PSK-less host on the sync segment drove one
    journal line per TCP connection. The post-auth
    `handling new connection` INFO (and, when keyed, the
    `connection authenticated` INFO from `wrapSyncConn`) remains the
    operator signal that a peer actually connected.
  - **File(s)**: `pkg/cluster/sync_conn.go`

- **Timestamp**: 2026-10-25
  - **Action**: Routed the `auth handshake failed` WARN in
    `handleNewConnection` through `notePreAuthHandshakeFailed`
    (`pkg/cluster/sync_admission.go`), which increments the new
    `PreAuthHandshakeFailed` sync-stats counter on every failure and
    emits the WARN at most ~1/sec via its own limiter
    (`preAuthHandshakeLogMono`, independent of the admission-cap
    `preAuthLogMono` so one flood class cannot starve the other's
    diagnostics), carrying the cumulative `failed_total`. The counter
    is surfaced in `SyncStatsSnapshot` via `Stats()`.
  - **File(s)**: `pkg/cluster/sync_conn.go`,
    `pkg/cluster/sync_admission.go`, `pkg/cluster/sync.go`,
    `docs/session-sync-architecture.md`

- **Timestamp**: 2026-10-25
  - **Action**: Regression tests in `pkg/cluster/sync_admission_test.go`:
    `TestPreAuthHandshakeFailureWarnRateLimited16748` (20 garbage
    handshakes through the real `handleNewConnection` → exactly 1
    WARN, `PreAuthHandshakeFailed == 20`, snapshot agrees) and
    `TestPreAuthPeerConnectedNotInfo16748` (5 garbage connections
    through the real `acceptLoop` → 0 INFO, at most 1 WARN, all 5
    counted). RED on surgical revert (counter kept, unconditional
    WARN + INFO restored): 20 WARNs and 5 INFOs respectively.
  - **File(s)**: `pkg/cluster/sync_admission_test.go`
