# #12904 — bindless IPsec selector fence ordering (before state publication; NoRoute gate)

## Problem

Issue #12904 (research D10-01, validated 3-way): the #10683 bind-less IPsec
selector fence ran only at the poll tail
(`userspace-dp/src/afxdp/poll_descriptor/mod.rs`, `bindless_selector_match`),
i.e. AFTER the session-miss path had already:

- allocated a pool-mode SNAT / NPTv6 / NAT64 translated identity
  (`source_nat_decision_for_flow` / `nat64.allocate_source_for_worker`),
- installed the forward+reverse session pair into the `SessionTable`,
- published the shared/BPF session entries, and
- replicated them (`replicate_session_upsert`).

Fenced transit therefore left ghost sessions (local + shared + peers) and held
NAT pool identities while every packet of the flow was dropped. Additionally
the `ForwardingDisposition::NoRoute` arm had NO selector fence at all: a
selector-covered frame that missed the FIB was reinjected to the kernel slow
path (delegated FIB forwarding with no zone policy/session/NAT/screen — the
steerable cleartext bypass the fence exists to close).

## Why

- **Why**: fence-before-publication restores the #10683 invariant — no state,
  no pool resource, no replication for traffic the immutable selector fence
  refuses; fail-closed for both tolerant/strict doctrines (fence is
  SA-independent and config-shape-driven).
- **What**:
  1. Pre-allocation fence in the permit/ForwardCandidate session-miss arm
     (before NAT64/NPTv6/SNAT allocation) — original+pre-routing-DNAT tuples.
  2. Post-allocation fence after the composed NAT tuple exists (SNAT/NPTv6/
     NAT64), gated on "an allocation actually happened", with the
     just-reserved translation rolled back
     (`rollback_source_nat_allocation_for_worker` +
     `rollback_nat64_allocation_for_worker`, the same pair the hop-limit
     ICMP-TE bounce uses) — before session install / BPF publication /
     replication.
  3. NoRoute arm: selector-covered frames are downgraded to `PolicyDenied`
     (#7480 downgrade shape) so the trailing #1913 chokepoint refuses them
     fail-closed instead of delegating to the kernel FIB.
  4. The poll-tail fence stays: it remains the gate for FabricRedirect,
     flowless, and fragment-consult paths that never pass through the
     install-time gates.
- **Validation**:
  - New `userspace-dp/src/afxdp/tests_bindless_fence_ordering_12904.rs`:
    - `fenced_miss_publishes_no_session_and_holds_no_pool_identity_12904`:
      original-tuple match (pre-allocation fence) AND post-SNAT-only match
      (post-allocation fence + rollback) against a one-port pool-mode SNAT
      fixture; asserts no session install, no shared-map publication, and —
      via the unfenced control flow — that the single pool identity is still
      committable afterwards (NAT-pool accounting unchanged).
    - `fenced_noroute_frame_is_never_delegated_to_kernel_slow_path_12904`:
      selector-covered permit-NoRoute frame (default-permit, no policies, no
      SNAT so nothing else can suppress the reinjection) never reaches the
      kernel slow path (`binding.live.slow_path_drops == 0`).
  - RED on pristine master (tests only, no fix): the publication test fails
    at `sessions.len() == 2` (the ghost forward/reverse pair) and the
    NoRoute test fails at `dbg.policy_deny == 0` (no fence on that path).
    GREEN post-fix.
  - Full `xpf-userspace-dp` bin unit-test suite on the fix: 7861 passed,
    0 failed (8 ignored), including the pre-existing #10683 fence tests,
    the neighbor-dispatch fence recheck, and the TX chokepoint backstop.
- **Risk**: behavior change is limited to flows that MATCH a configured
  bind-less selector pair (fence disabled ⇒ `matches_with_nat` short-circuits
  on `enabled == false`, hot path unchanged). Such flows are dropped earlier
  and without a flow-cache deny seed, mirroring the existing tail-fence
  accounting (`dbg.policy_deny`, `counters.touched`). The post-allocation
  re-check adds one fence evaluation per admitted miss when NAT allocated
  something.
