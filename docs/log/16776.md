# #16776: community-list regex lines containing `| ` refused by FRR's vty pipe hook

- **Timestamp**: 2026-10-25
- **Action**: FRR's vty pipe hook treats `| ` in any command line as an
  output pipe; a non-`include` token after it prints `% Unknown action`,
  the line never executes, and `frr-reload.py` exits 0. xpf spelled
  literal conjunction boundaries `(^| )` / `( |$)` (every multi-member
  conjunction with a literal member) and emitted operator regex members
  such as `^((56) | (78)):(.*)$` verbatim, so those community-lists were
  silently absent from bgpd and `from community X; then reject` terms
  over them failed open. Fixed with one shared pipe belt; during the
  rebase onto the #16788 per-community translation (since merged),
  the community-member half folded into that stricter mechanism —
  `TranslateCommunityMemberRegex` is pipe-free by construction and
  refuses any `| ` member — while the description gate, the belt,
  and the daemon oracle remain this issue's:
  - `pkg/frr/render_validate.go`: `rewriteFRRPipeSequences` drops
    grouping whitespace around an unescaped `|` outside bracket
    expressions and preserves bracket/escaped bytes (kept as the
    shared primitive; the community path no longer needs it).
  - Community members (folded, #16788): literal factors render
    pipe-free `(^|[ ])` boundaries via the translator/sequencer;
    any member carrying `| ` is untranslatable, so the definition
    emits nothing (`communityListRenderable` subsumes the original
    `communityListPipeRenderable16776`) and referencing reject
    terms lower to deny-all (#10822).
  - `pkg/config/community_member.go`: `ValidCommunityMemberPipe16776`
    delegates to the #16788 translator (every `| ` refuses, with a
    `[ ]`/space-free remedy); wired into
    `validatePolicyCommunityRegexStrict` (strict reject, tolerant
    warning under the existing community lenient flag).
  - `pkg/config` + `pkg/frr/protocols_render_bgp.go`: a neighbor
    description carrying `| ` is refused at commit
    (`validateBGPNeighborDescriptionPipeStrict16776`, lenient flag
    `lenientBGPNeighborDescriptionPipe16776`) and omitted at render
    with a warning on tolerant paths — the description installs or
    is refused, never silently dropped by bgpd.

- **Validation**: targeted Go tests (see PR for counts), including
  `TestCommunityPipeRender16776` (BOTH matches the denied route
  `65000:1 666:5` conjunctively with no `| ` in any rendered line;
  space-free grouped regex keeps 56/78 semantics; pipe-space and
  atom-space members fail closed to deny-all), strict/lenient
  compiler cells for both gates, and the root-only daemon oracle
  `TestCommunityListPipeLiveBgpd16776` (private netns/pathspace,
  production render loaded via `vtysh -f`, installed state asserted
  via `show bgp community-list` on the running bgpd).
- **Residual**: The live oracle requires root + FRR binaries and
  skips elsewhere (this lane runs it under sudo). Post-#16788, any
  `| ` in a community member refuses (stricter than the original
  grouping-only acceptance) with a documented remedy. Junos AS-path
  regexes normalize grouping whitespace in their grammar-aware
  translator; BGP descriptions use strict refusal and tolerant
  omission. The former generic rewrite helper was removed in #17799
  because it had no production caller. Future operands should use
  their grammar-aware translator or strict/tolerant gate rather than
  revive an unconnected render helper.
