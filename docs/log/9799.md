# #9799 — a later member of a bracketed group found no node

- **Timestamp**: 2026-09-11
- **Action**: resolve a later member of a `security-zone [ a b ]` group for a path-scoped `show`, and refuse delete, deactivate and activate of it with guidance.
- **File(s)**: listed under Change.

## Defect

`security-zone [ zga zgb ] { tcp-rst; }` is one node, `Keys [security-zone zga zgb]`, and every walk matched it by `Keys[1]`:
- `show ... security-zone zga` printed the group, and `... zgb` printed nothing;
- `delete` of `zga` was refused with #8992's guidance, and of `zgb` with `path not found: no node matching "security-zone zgb"`;
- `deactivate` of `zga` was refused by #9793, and of `zgb` the same "no node matching".

The zone is visible in `show configuration`, so the message was true of the walk and false of the tree (#9006 shape).

## Design notes

- **Bracket provenance decides membership, not key count.** `security-zone trust screen edge;` also carries keys past the name, but none was authored bracketed, so `edge` is never read as a zone. A node with no provenance, synthesized or loaded from a config DB written before #6668, answers false through `Node.KeyBracketed` and is never claimed.
- **A path into the shared body is refused too.** For example, `deactivate ... security-zone zgb tcp-rst`: the body belongs to every member.
