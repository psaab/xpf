# #13953 — drop LAND packets on every terminal shim kernel-pass arm

## Why

Host-bound session-miss traffic to a non-NAT firewall address bypassed all
worker screens. On a session miss the shim's `is_local_destination` arm (and
the ICMP-to-interface-NAT-local arm, the WireGuard steer fallthrough, the
early-filter pass, and the whole degraded control-disabled / binding /
heartbeat path) handed the packet to the kernel before any worker screen
ran. The #11087 LAND drop existed only on the established
`PASS_TO_KERNEL` arm. The Linux stack drops IPv4 LAND even with
`accept_local=1` but has no IPv6 LAND backstop (executed in a netns probe by
the deep-review gate), so an IPv6 `src == dst` packet to a firewall-local
address was delivered to local sockets on every one of those arms.

## What

The LAND verdict now lives in a new `core`-only module
`userspace-xdp/src/land.rs` (`is_land`, one 16-byte compare; `ParsedPacket`
stores IPv4 addresses in the first four bytes of a zeroed 16-byte field, so
one comparison is family-correct), and the shim drops equal
source/destination packets with the new `land_drop` degraded-path counter
(reason 19) at three sites: once in the healthy path after the tagged-only
VID-0 drop and the adjudicated-interface gate (covering the session-miss
local, interface-NAT-ICMP, WireGuard-steer, early-filter, native-GRE
inner-PASS and degraded binding/heartbeat arms), once in the
control-disabled path after its tagged-only check, and on the existing
established `PASS_TO_KERNEL` arm (refactored to the shared predicate).
Go's `degradedPathReasonNames` gains slot 19 `land_drop` (cap test updated
19 → 20; the #8258 agreement test auto-enrols it).
`docs/afxdp-packet-processing.md` now lists which screens apply to
host-bound traffic: LAND at the shim, flood screens via the
`xpf_hostinbound` input-chain mirror, and the remaining worker screens do
not run on terminal kernel passes.

NOT changed: the non-adjudicated-interface `cpumap_or_pass` (no authority —
passing is the documented #8279 behaviour and the packet is not delivered
to a screened zone's local stack by this shim), multicast/broadcast early
passes (a multicast destination can never equal a unicast source, so no
LAND packet exists there; left untouched to avoid hot-path churn), and
the worker's profile-gated `check_land` (unchanged; the shim check is
unconditional like #11087's).

## Validation

- RED (host): `cargo test --manifest-path userspace-dp/Cargo.toml --bin
  xpf-userspace-dp tests_shim_land_13953` — the equal-address cells fail
  without `is_land` (module absent on master).
- GREEN (host): same command passes after the fix.
- RED (BPF): `go test ./pkg/dataplane/userspace -run
  TestUserspaceXDPLandSessionMissDropped13953` on the pre-fix object —
  IPv6/IPv4 LAND to a local address on session miss returns XDP_PASS.
- GREEN (BPF): same command after `make generate-userspace-xdp` —
  LAND cells return XDP_DROP with `land_drop` + `transit_drop` and no
  `pass_to_kernel`; non-LAND controls still return XDP_PASS.
- Verifier: `make generate-userspace-xdp` (instruction count recorded in
  the PR body).

## Risk

The healthy-path gate adds one 16-byte compare after parsing; the
control-disabled gate adds the same on a cold path. A LAND packet that
previously reached the kernel only via a non-adjudicated interface still
does — that interface is outside the shim's authority by design (#8279).
No legitimate equal-address traffic traverses this XDP hook (loopback
never does).
