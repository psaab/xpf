# #12777 — reject nameless firewall terms in strict pre-walk

- **Issue**: #12777 — family-less packed firewall filters can silently drop nameless terms during strict compilation.
- **Branch**: `fix/12777-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12777`

## Why

The #12526 validator already detects nameless hierarchical firewall filter terms before `LoadMerge` flattens their bodies into set paths. Strict config compilation did not invoke it. In particular, the packed family-less spelling `firewall { filter { F term { then discard; } } }` compiles with no error while the filter term disappears, so its discard action is silently dropped.

## What

- Run `ValidateFirewallNamelessTermsAST12526` from `runPreWalkGates` on strict compilation, before section lowering can discard the term AST.
- Keep the gate disabled on tolerant load/peer-sync paths; those retain the existing #10294 warning behavior.
- Add strict compile regressions for the issue's packed family-less filter spelling, family-qualified forms, packed heads, and an applied group, plus named and lenient controls.
- Add a `CommitCheck` regression for the exact issue spelling and update the firewall gate documentation.

## Validation

- RED: before the pre-walk gate, `go test ./pkg/config -run 'TestStrictCompileRejectsFirewallFilterNamelessTerms12777/issue_shape_family-less_discard' -count=1` failed because `CompileConfig` accepted the malformed input.
- Mutant checks: removing the validator call made the same test fail by accepting the input; leaving the call but discarding its error also made it fail by accepting the input.
- Focused config regressions passed: `go test ./pkg/config -run 'TestStrictCompileRejectsFirewallFilterNamelessTerms12777|TestStrictCompileAcceptsNamedFirewallTerm12777|TestLenientCompileStillWarnsFirewallFilterNamelessTerm12777|FirewallNameless|NamelessTerm' -count=1`.
- Focused store regressions passed: `go test ./pkg/configstore -run 'TestCommitCheckRejectsPackedNamelessFirewallFilter12777|TestLoadMergeRejectsNamelessFirewallTermsBeforeFlattening12526|TestLoadMergeNamelessFirewallTermsControls12526' -count=1`.
- `go vet ./pkg/config ./pkg/configstore` and `go build ./...` passed.
- The full `go test ./pkg/config` run timed out after ten minutes. The first `go test ./pkg/configstore` run reached the new test and failed only because its assertion expected `firewall filter`; the actual established validator diagnostic includes the normalized `firewall family inet filter` prefix. After narrowing the assertion to the stable filter name and validator diagnostic, the full `go test ./pkg/configstore` suite passed.

## Risk

Strict compilation now rejects literal hierarchical firewall nameless terms before lowering; properly named terms remain accepted. Tolerant compilation behavior and flat-set semantics are unchanged. The strict pre-walk may make the #12526 diagnostic the first error when a config violates multiple gates.
