# DHCP reconciliation uses one config generation (#13546)

- **Issue**: #13546 — `applyMgmtVRFRoutesTo` read `ActiveConfig()` once for
  static routes and configured connected prefixes, then read it again for the
  cluster control/fabric interface inventory. A concurrent commit between the
  reads could mix configuration generations in classless-route security gates.
- **Change** (`pkg/daemon/daemon_flow.go`): capture the active config once at
  reconciliation entry and use that same pointer for static route planning,
  control/fabric inventory and connected-prefix checks. Added a regression in
  `pkg/daemon/mgmtvrf_single_snapshot_13546_test.go` that commits a new,
  cluster-free config while the pass is in progress and verifies the captured
  generation still fences DHCP classless routes into its control prefix.
- **RED evidence**: with the second `ActiveConfig()` read restored, the
  regression failed because `10.77.0.42/32` was installed after a concurrent
  commit removed the cluster configuration; the trust override allowed the
  ordinary connected-prefix path, so the independent control/fabric fence was
  load-bearing.
- **GREEN evidence**: `go test -race ./pkg/daemon -run
  '^TestMgmtVRFReconcileSingleConfigGeneration13546$' -count=5` passed;
  `go test ./pkg/daemon -count=1` passed (501.912s, with `GOTMPDIR` set to
  `/var/worktrees/t` to keep Unix socket paths under the platform limit);
  `go build ./...` and `go vet ./...` passed. The first full package attempt
  using the deeper cache temp path hit Unix-domain socket path-length errors
  in three existing event-stream tests; rerunning with the short path passed.
- **Risk**: no intended behavior change; route decisions in one reconciliation
  now consistently reflect the active config snapshot captured at its start.
