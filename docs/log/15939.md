# Issue #15939 — recursive m.mu deadlock in syncSnapshotLocked -> rgPrimaryNow

- **Timestamp**: 2026-10-20
- **Action**: Split rgPrimaryNow into locking / m.mu-held variants (the rgProviderWiredForLocked pattern from #15924); the apply-time derived-section rebuild now uses the held variant.
- **File(s)**: pkg/dataplane/userspace/manager.go, pkg/dataplane/userspace/apply_snapshot_identity_9520.go, pkg/dataplane/userspace/rgprimary_deadlock_15939_test.go, docs/log/15939.md

## Diagnosis (verified at origin/master 61c7d45603)

- `statusLoop` (process_status.go) holds `m.mu` across `syncSnapshotLocked`,
  which calls `prepareSnapshotForApply` (process_status.go:152).
- When link revalidation moved or dropped an interface row,
  `rebuildDerivedSectionsAfterRevalidate`
  (apply_snapshot_identity_9520.go:166,171) called `m.rgPrimaryNow()`,
  which takes `m.mu` (manager.go). Go mutexes are not reentrant, so the
  status tick deadlocked — no cluster needed. This is the recurring
  pkg/dataplane/userspace full-suite hang.
- Audit of every other `prepareSnapshotForApply` / `rgPrimaryNow` caller:
  - `applyCompiledSnapshot` (manager_compile.go:547), scheduler
    (manager_compile.go:1267 via requestApplySnapshotLocked),
    route-overlay (manager_overlay.go:232), capture-authority
    (manager_overlay.go:371), deferred worker-arm
    (manager_worker_arm_5134.go:88 via requestApplySnapshotLocked) — all
    run under `m.mu`, so all hit the same recursive lock through the
    rebuild, not just the status tick.
  - `Compile`'s two direct `rgPrimaryNow()` calls
    (manager_compile.go:322,377) run WITHOUT `m.mu` (snapshot build is
    off-lock), so they keep the locking variant.
  - `RefreshInterfaceRowsForLink` and the overlay route rebuild already
    read `m.rgPrimaryProvider` directly under `m.mu` — no change.
  - Inside the rebuild itself, `routeOverlayForSnapshot` is already the
    m.mu-held variant (its doc says so); `rgPrimaryNow` was the only
    lock-taking helper left in that chain.

## Fix

- `rgPrimaryNowLocked()` added next to `rgPrimaryNow()` in manager.go,
  mirroring `rgProviderWiredForLocked`: returns `m.rgPrimaryProvider`
  without taking the lock; `rgPrimaryNow()` delegates to it after
  locking. Single snapshot of the provider is taken once in
  `rebuildDerivedSectionsAfterRevalidate` and passed to both
  `buildRouteSnapshotsWithRGPrimary` and `markConnectedRGPeerOwned`
  (previously each call re-locked and could observe different providers
  if wiring changed between them).

NOT changed: provider semantics (nil provider still keeps RG>0 rows,
#15919), route building, Rust/wire, any publish bookkeeping.

## Regression

- `TestSyncSnapshotLockedMovedInterfaceRowNoDeadlock15939` drives
  `syncSnapshotLocked` under `m.mu` (as statusLoop does) with the
  #14209/#15043 moved+dropped interface fixture and a wired RG
  provider; asserts the tick completes (30s timeout guard reports the
  deadlock instead of hanging the suite), one apply_snapshot is sent,
  and the sent mirror rows are the rebuilt ones (recreated interface at
  ifindex 29).
- FAIL-ON-REVERT verified: restoring `m.rgPrimaryNow()` in the rebuild
  makes the test fail at the 30s guard with the deadlock message;
  restoring the fix passes in <1s.
