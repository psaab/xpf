# #18369 — fence stale DHCP chunk completions

- **Timestamp**: 2026-10-28
- **Action**: Added a per-family, per-incarnation `committedGen` watermark to the DHCP chunk receiver. Both legacy full-set commits and completed chunked sets advance it monotonically. A completed generation strictly older than the watermark is now dropped before the held lease snapshot is stored or `OnDHCPLeasesReceived` is called, and is counted in the existing `DHCPLeasesStaleIgnored` counter. Added the G/H interleaving regression: G's final lease is refused after sequence admission, H commits, and G's later-sequenced retry must not overwrite H or fire a callback.
- **File(s)**: `pkg/cluster/sync_dhcp_chunk_15160.go`, `pkg/cluster/sync_lease_recv.go`, `pkg/cluster/sync.go`, `pkg/cluster/dhcp_lease_chunk_15160_test.go`, `docs/log/18369.md`
- **Validation**: The new regression failed before the fence because G's completion was accepted after H committed. After the change, `gofmt -w` on the touched Go files, `GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/var/worktrees/.cache/go-tmp go test ./pkg/cluster -run '^TestDHCP' -count=1`, and `GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/var/worktrees/.cache/go-tmp go test ./pkg/cluster -run '^TestIPsecSA' -count=1` PASS.
- **Risk**: No wire-format changes. Only completed generations strictly older than the latest commit for the same sender incarnation and DHCP family are fenced; equal/newer generations retain existing behavior, and incarnation-zero traffic bypasses the fence.
