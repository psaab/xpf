# Issue #13653 — flush handled session deltas before requeueing a contended suffix

## Defect

The steady-state session-delta drain in `run_export_slice` calls
`purge_queued_flows_for_closed_deltas`, which returns the count of deltas
successfully processed before tuple-gate contention. On a partial result, the
caller requeued only `deltas[handled..]` and returned without flushing
`deltas[..handled]`. Those prefix deltas had already been removed from the
session ring and had their queued flows purged, so they were silently lost to
session-delta consumers.

## Fix

When the tuple gate blocks a later close, flush the successfully handled
prefix before requeueing the blocked suffix. This matches the existing
`drain_and_flush_all_impl` path and expiry-overflow drain. The normal complete
batch path and the bounded per-tick drain remain unchanged.

## Regression

`steady_state_contention_flushes_prefix_and_requeues_suffix` holds the global
tuple install permit for a second close delta, then drives the production
steady-state `run_export_slice` path. It requires the first delta to be
flushed exactly once and the blocked close to remain the sole requeued delta.

  flush (`left: []`).
- GREEN after the fix: the regression passes, including the prefix-flushed
  exactly-once and blocked-suffix retry assertions.
