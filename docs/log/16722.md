# #16722: every interactive candidate mutation runs two full lenient compiles (event plant-class stamping) under the store write lock

- **Timestamp**: 2026-10-25
- **Action**: `StampChangedEventPlantClasses` unconditionally ran
  `compiledEventPolicies9984` on both the before and after trees — two
  full `CompileConfigLenient` compiles — on every interactive candidate
  mutation (set/delete/deactivate/activate/copy/rename/insert/annotate),
  all under the config-store write lock, even when the config carried no
  event-options at all. The stamper now opens with a cheap raw gate,
  `treeMayHaveEventCommands9984`: when neither tree carries a
  `then change-configuration commands` payload with at least one value,
  no policy can gain, lose, or rebind commands, so the compiled
  comparison and the raw census are both provably no-ops and stamping
  returns immediately. The gate descends only into event-options
  subtrees (direct and one-key-container nested policies), group
  definition bodies (`groups { <name> { ... event-options ... } }`,
  including the flat-set spelling), and recognises policy-local
  `apply-groups` / `apply-groups-except`, any of which can materialise
  or suppress a commands payload via inheritance and therefore force
  the full path. Payload detection reuses the existing
  `eventPolicyHasCommands9984` predicate (tail values or children), so
  a bare `commands;` keyword and unrelated `then`/description
  lookalikes outside event-options never trip it. When either tree may
  carry commands, stamping is byte-for-byte the pre-fix behaviour
  (compiled diff plus raw census, including group-owned and
  uncompileable policies).
- **File(s)**: `pkg/config/event_plant_class_9984.go`,
  `pkg/config/event_plant_class_gate_16722_test.go`,
  `pkg/configstore/event_stamp_cost_16722_test.go`, `docs/log/16722.md`.
- **Validation**: New `TestTreeMayHaveEventCommands16722` (pkg/config)
  pins 18 gate rows: commandless configs (host-name only, policy
  without commands, plant-class without commands, bare `commands;`,
  unrelated firewall `then` lookalike, description mentioning
  "commands") must skip, while every payload shape (block, packed,
  flat child-shape, nested container, grouped hier/flat, policy-local
  apply-groups/-except, inactive policy) must not.
  `TestStampGateSkipsOnlyCommandless16722` proves a commandless stamp
  leaves the tree byte-identical and that commands appearing or
  disappearing across the mutation still stamp / never invent a
  policy. New `TestSetHostNameLargeConfigNoEventCompile16722`
  (pkg/configstore) drives `set system host-name` through
  `SetFromInput` on a 16k-line commandless candidate and requires the
  mutation to finish well under the seconds two compiles cost (5s
  ceiling on a loaded host; the decisive fail-on-revert signal is the
  gate unit tests). All pre-existing #9984/#14142 stamping tests stay
  green (`pkg/config` stamp suite, `pkg/eventengine` plant-class
  suite, `TestFlatSetCannotForgeSuperuserPlantClass9984`).
  `TestEventPlantClassPersistsReloadsAndRollback9984` fails identically
  on clean origin/master (pre-existing #14660 known-event rejection of
  its `link_down` fixture at CompileCandidate) and is unchanged by
  this fix.
- **Residual**: The O(config) `Clone` of the candidate that every
  mutator already performed before stamping is untouched — it is
  needed for the node-budget rollback path — so a mutation is now
  O(path)+O(clone) rather than O(path)+O(clone)+2×O(compile) under
  the lock. Event-options-bearing configs still pay the two compiles;
  compiling only the event-options subtree was not attempted because
  apply-groups expansion can pull commands from arbitrary group bodies,
  which the gate already forces onto the full path.
