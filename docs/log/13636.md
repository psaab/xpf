# Issue #13636: Preserve injected-frame ownership on PMech expiry

A reverse WireGuard packet can be held in `pending_pmech_reverse` while its
session owner is Pending. Injected plaintext uses a TX-pool UMEM frame, while
native packets use RX descriptors. When a token expires or changes generation,
the drain previously sent every descriptor to `scratch_recycle`, which feeds
the RX fill ring. This misrouted TX-owned UMEM frames and leaked them from the
TX free pool.

The replay drain now distinguishes injected descriptors: expired injected
frames return directly to the same binding's TX free-frame pool, while native
RX frames retain the existing RX recycle behavior. Live tokens continue to the
replay queue unchanged.

Regression coverage pins the injected-vs-native recycle routing in the PMech
replay stage. `cargo test --bin xpf-userspace-dp
poll_descriptor_structure_13081_tests -- --nocapture` passes (2 tests).
On pristine `origin/master`, the test's injected-origin predicate is false:
the old drain unconditionally pushes expired descriptors to
`scratch_recycle`.

`cargo test --bin xpf-userspace-dp pending_pmech -- --nocapture` passes
(1 test), and `cargo build --bin xpf-userspace-dp` succeeds. The focused
structural test command above passes (2 tests).
