# #13292 — Export io_uring state and retained-buffer telemetry

Source: deep-review D4-09, run `review-work.AYgyxCmMxC`, corroborated by
D2-10 and validated by the three-way research gate.

## Root cause

The Rust helper reports `io_uring_active`, `io_uring_retained_buffers_total`,
and `io_uring_retained_bytes_total` in `ProcessStatus`, but Go's userspace
Prometheus collector did not describe or emit these fields. Operators could
not observe the state writer's fallback to synchronous writes or the
kernel-pinned buffers retained after an unproven io_uring teardown.

## Change

- Added collector descriptors for `xpf_userspace_io_uring_active` (gauge),
  `xpf_userspace_io_uring_retained_buffers_total` (counter), and
  `xpf_userspace_io_uring_retained_bytes_total` (counter).
- Emit all three on each userspace status collection, including zero counters
  and an inactive gauge, and register the descriptors with `Describe`.
- Added a regression covering nonzero and zero values plus descriptor
  declaration. No Rust status protocol changes were needed because Go already
  decodes all three fields.
