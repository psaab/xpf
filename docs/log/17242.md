# #17242 — ctrl_disabled_action literal-false / dead inputs (R4-Q18-05)

- **Timestamp**: 2026-10-27

- **Action**: Deleted the dead inputs and renamed the helper with an honest doc (Option 2).
- **File(s)**: `userspace-xdp/src/degraded_ctrl_disabled.rs`,
  `userspace-xdp/src/lib.rs`, `userspace-dp/src/main_tests.rs`,

- **STEP-0 — defect live on origin/master?** Yes. At `a60e77bda3`
  (origin/master when the worktree was cut):
  `userspace-xdp/src/lib.rs:1750` called
  `degraded_ctrl_disabled::ctrl_disabled_action(ingress_iface_flags, false, local_or_control)`
  with a literal `false` for `tagged_only_vid0_local`, after the caller had
  already returned for unadjudicated ingress at `lib.rs:1704-1706`
  (`ingress_adjudicated`) and for the tagged-only VID-0 local case at
  `lib.rs:1738-1740` (`USERSPACE_FALLBACK_REASON_TAGGED_ONLY_LOCAL_DROP`).
  Both the module's flag re-check and its `tagged_only_vid0_local` input
  were therefore dead in production, its doc claimed it was the
  "Complete #13632 behavioral decision", and the host cell at
  `userspace-dp/src/main_tests.rs:6123-6127` asserted
  `ctrl_disabled_action(adjudicated, true, true) == DropTransit` — an input
  production never passes. No duplicate PR existed for 17242.

- **Fix direction chosen.** The issue offers two dispositions. Option (1)
  (module returns `{DropUnadjudicated, DropTaggedOnly, PassLocalControl,
  DropTransit}` from the real facts, called once, mapping each variant to
  its existing reason) would move the tagged-only and unadjudicated drops
  into the module. That was rejected: the steelman in the issue itself
  justifies the caller's early tagged-only return (its
  `TAGGED_ONLY_LOCAL_DROP` reason is one the two-way enum cannot express),
  and applying the same fact to the unadjudicated drop would force the
  module to own parse-failure/S-tag/QinQ/non-IP/LAND reasons it explicitly
  disclaims, churning far more than the dead-input defect. Option (2) —
  delete the dead inputs and rename with an honest doc — was implemented:
  - `userspace-xdp/src/degraded_ctrl_disabled.rs`: deleted
    `ctrl_disabled_action` (flag word + `tagged_only_vid0_local` inputs)
    and `ctrl_disabled_disposition` (only caller was the deleted fn).
    Their place is `local_control_or_drop(local_or_control: bool)`, whose
    doc states it is *not* the complete decision and lists the caller's
    earlier returns (unadjudicated, parse failures, S-tag/QinQ/non-IP,
    tagged-only VID-0, LAND) that it can never see. `ingress_adjudicated`
    and `INGRESS_IFACE_FLAG_ADJUDICATED` are unchanged.
  - `userspace-xdp/src/lib.rs:1750`: sole production call site now calls
    `local_control_or_drop(local_or_control)`. No other production
    behaviour changed: the unadjudicated early return, tagged-only early
    return, LAND gate, branch-stat counters, and reason counters are
    byte-identical.
  - `userspace-dp/src/main_tests.rs`
    (`shim_degraded_ctrl_disabled_decision_13632`): removed the
    unadjudicated-through-`ctrl_disabled_action` rows (production drops
    before the helper runs; the gate is still pinned at the bit level via
    `ingress_adjudicated` and by the unchanged source-order test
    `shim_degraded_ctrl_disabled_tests_adjudicated_before_parse_13632`)
    and the impossible `ctrl_disabled_action(adjudicated, true, true)`
    tagged-only row. Every remaining host-cell input (`true`/`false`
    `local_or_control` on adjudicated, parsed frames) is one production
    can pass. The test doc now says where the tagged-only drop is pinned.
