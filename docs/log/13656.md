# Issue #13656 — evaluate mirrored output filters once

## Why

The cross-worker mirror wrappers checked the analyzer output filter and then
called `enqueue_admitted_mirror_clone_to_live`, which evaluated the same filter
again. An accepting counted term therefore recorded two packet/byte hits for one
mirrored packet, and an attached policer consumed the packet's bandwidth twice.
A discard filter returned at the first check, so a regression using only a
filtered packet could not expose the duplicate evaluation.

## What

Keep the output-filter check at the cross-worker call sites, before admission
where possible, and remove it from the admitted-queue helper. The sampled live
wrappers and the flow-cache staged path now each evaluate the filter once before
they enqueue an admitted clone. Same-worker binding clones keep their existing
single evaluation.

The regression uses an accepting, counted analyzer output term so it exercises
both filter evaluations on the previously broken path. It asserts one counter
increment and successful enqueue for a cross-worker clone, then asserts one
additional increment for a same-worker clone.

## Validation

- RED on pristine `origin/master` at `6d33535`: `cargo test
afxdp::mirror::tests::mirror_output_filter_accept_counter_counts_once_13656
-- --nocapture` failed as intended; the cross-worker counter was 2 instead of 1.
- GREEN after the fix: the same test passed as part of `cargo test
afxdp::mirror:: -- --nocapture` (29 passed; 7,989 filtered out).

## Risk

This changes only duplicate filter side effects on cross-worker mirror clones.
Output-filter verdicts and same-worker behavior are unchanged; sampled or staged
clones rejected by the filter are not enqueued.
