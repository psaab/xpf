# #15128 — Commit-path partial clear promoted the empty set, forgetting VPNs charon still runs (A90-01)

- **Timestamp**: 2026-10-19
  - **Action**: Fixed the `ApplyGeneration` partial-clear promotion in `pkg/ipsec/manager.go`. On a partial clear, `clearConfig` rolls charon back to the prior file and returns `partialApplyError{names: priorSet, hashes: priorHashes, clear: true}` (the empty-set case is encoded as `names={}`). `Clear()` (factory reset) already promoted `pae.names`/`pae.hashes`, but `ApplyGeneration` — the commit path (`pkg/daemon/ipsec_sa_rg_9139.go:103`) — discarded them and promoted `{}`, so `prevConnNames` forgot VPNs charon still runs: their SAs were never terminated and the persisted record said none. `ApplyGeneration` now promotes `pae.names`/`pae.hashes` for the clear case too (the `pae.names == nil` empty encoding still promotes `{}`), matching `Clear()`. The `partialApplyError` doc comment now states that for `clearConfig`, `names` is the recovered set charon runs.
  - **File(s)**: `pkg/ipsec/manager.go`, `pkg/ipsec/partial_load_14589_test.go`, `pkg/ipsec/README.md`, `docs/log/15128.md`
