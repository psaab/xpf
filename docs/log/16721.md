# #16721 — `show system commit history` numbered rows oldest-first from 0, reversing `rollback N`, with no confirmation record or pending marker

## Defect
`ListCommitHistory` returns journal tail order ("most recent last") and
both renderers (`pkg/cli/cli_show_system.go`, `pkg/grpcapi/server_show_system.go`)
printed the loop index (`for i, e := range entries`), so row 0 was the
OLDEST commit while `rollback 0` means the active config and `rollback N`
addresses the Nth most recent generation. An operator mapping the row
label to `rollback N` (the Junos recovery reflex) staged the reverse
generation into the candidate — bounded only by `rollback` staging and
`show | compare`. Separately, `ConfirmCommitAs` /
`clearPendingConfirmLocked` wrote no journal entry, so the history could
not show that a commit-confirmed window had been confirmed or by whom,
and nothing rendered Junos' `<rollback pending>` while a window was armed.

## Fix
- `configstore.ListCommitHistoryRows(limit)` returns the same filtered
  journal tail (now including `commit_confirm`) plus a Junos rollback
  label per row: the live commit is 0 (`rollback 0` = active), and
  k>=1 labels the commit whose tree `rollback k` restores (slot k
  holds that commit's promoted tree), printed only while that tree
  is retained in the history ladder. `commit_confirm` and
  `auto_rollback` rows get no label. Positional (not ConfigHash)
  alignment is exact for duplicate-content commits.
  `ListCommitHistory` keeps its signature/order and delegates.
- Every confirmation path journals one `commit_confirm` row with its
  principal and the active config hash: explicit confirm (new
  `ConfirmCommitPrincipalAs`; `ConfirmCommitAs` records the `unknown`
  sentinel since its sessionID is a bearer token that must never be
  journaled), plain commit (`commitWithDescriptionLocked`, with the
  commit's principal), HA sync supersede (`system:cluster-sync`), and
  RG demotion (`system:rg-demotion`). CLI/gRPC/REST confirm handlers
  pass their already-derived redacted principal.
- Shared `configstore.RenderCommitHistory` renders most-recent-first,
  slot label (blank when none), timestamp, action, termsafe-escaped
  principal and detail, plus a trailing `<rollback pending>` line
  while `IsConfirmPending()`. Both the in-process CLI and gRPC
  ShowText call it, so the surfaces cannot diverge. This also lands
  the principal on every history row.

## Risk
Display/audit only: no commit, rollback, or confirm semantics change.
Known positional skew, documented at `ListCommitHistoryRows`: a
history-pushing commit cut off by the bounded Tail(50) window, or a
SyncApply that pushed history without a commit journal row, can shift
older rows' labels by a neighbouring generation; `rollback` only
stages and `show | compare` exposes the staged tree before commit.
Pre-#16721 journals simply lack `commit_confirm` rows (additive).
