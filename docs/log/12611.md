# #12611 — enable the global IPv6 proxy-NDP gate

- **Issue**: #12611 — forwarded unicast NUD probes for proxied IPv6 targets can be forwarded out the proxy interface without a Neighbor Advertisement when `net.ipv6.conf.all.proxy_ndp` is unset.
- **Branch**: `fix/12611-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12611`

## Why

The per-interface `net.ipv6.conf.<if>.proxy_ndp=1` setting and an installed
NTF_PROXY entry did not suffice for the reported forwarded-unicast NUD/default-
route topology. The two-namespace reproduction observed the NS leave with hop
limit 254 and no NA while `all.proxy_ndp=0`; setting the all-interface bit made
the proxy reply. The global bit is therefore required alongside the
per-interface bit for this recovery path.

## What

- Assert `net.ipv6.conf.all.proxy_ndp=1` once during proxy-responder enable when
  any configured interface has an IPv6 proxy entry, after per-interface values
  are applied. IPv4-only config does not touch the global NDP setting.
- Keep teardown per-interface. A per-interface removal diff cannot establish
  that no other proxy-NDP interface or system user requires the global gate, so
  it must not write `all.proxy_ndp=0`. With the global gate set, per-interface
  proxy-NDP state and the matching NTF_PROXY entry are still required; the
  global setting alone does not create proxy entries or make every interface
  answer.
- Add regression tests for the per-interface and global writes, multi-interface
  deduplication/order, IPv4-only config, global-write failure accounting, and
  non-destructive per-interface teardown. Update the existing proxy sysctl test
  and document the behavior in `docs/feature-gaps.md`.
