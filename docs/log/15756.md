# #15756: `clear dhcp client-identifier interface <name>` resolves operator spellings to lease keys

- **Timestamp**: 2026-10-19
  - **Action**: Resolved scoped DUID clears through the active config to the DHCP lease key(s) on the local CLI, gRPC (remote CLI forwards here), and REST surfaces; added `interface <name>` completion in the OperationalTree; kept bare clear-all and idempotent lease-key clears unchanged.

## Mechanism

- `pkg/cli/cli_clear.go`, `pkg/grpcapi/server_dhcp.go`, and `pkg/api/dhcp.go` passed the raw operator spelling to `dhcp.Manager.ClearDUID`, whose `duidPath` filename validator (`pkg/dhcp/duid.go`) rejects `/`, so `clear ... interface ge-0/0/0` always errored. Spellings whose lease key differs (`ge-0/0/0.0` → `ge-0-0-0`, `ge-0/0/3.7` → `ge-0-0-3.50` via vlan-id) hit `os.IsNotExist` on a non-existent file and reported success while the real unit DUID survived. The OperationalTree `clear dhcp client-identifier` node had `AcceptsArgs: true` with no `interface` child/completion (#15227 residual).

## Change

- `pkg/config/dhcp_renew_resolve.go`: `ResolveDHCPClientIdentifierTargets` accepts the same spellings as the #15227 renew resolver (Junos key, ifd.unit, Linux form, exact lease key). A bare interface yields every DHCP lease key on that interface (clearing is idempotent deletion); a unit-qualified name yields that unit's key via vlan-id. A dotted mismatch on a declared base (`ge-0-0-3.99`) and any unmatched slash name refuse fail-closed. A lease-key-shaped name with no declared base resolves to itself — idempotent on the exact key named (absent file = success), covering removed interfaces and config-less builds (the REST #4794 fixture contract). Nil config behaves the same (lease-key passthrough, slash refusal). `IsDHCPLeaseKeyName` mirrors the #4857 shape predicate. The renew resolver is shared via `ResolveDHCPLeaseTargetFor`; renew behavior/messages are unchanged.
- All three handlers resolve in a loop and clear each key; the CLI resolves via its store, gRPC reports `codes.NotFound` for resolution refusals, REST reports 400. No-store builds resolve lease-key shapes via a nil config and refuse Junos spellings.
- `pkg/cmdtree/tree.go`: `interface` child with `RequiresValue` and `DHCPClientIdentifierCompletionNames`, so completion offers resolvable config-key unit spellings and a dangling `interface` does not canonicalize.
- `pkg/dhcp/duid.go`: documented ClearDUID's lease-key input contract. NOT changed: `ClearDUID`/`ClearAllDUIDs` validation, traversal guard (#4857), idempotent absent-file semantics, bare clear-all, renew behavior, or completion for renew.
