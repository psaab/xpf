# #16609: PPTP permanent alias collision retained as unbounded self-retry

- **Timestamp**: 2026-10-25
- **Action**: A PPTP first-learn install refused by a permanent alias
  collision was recorded as a self-retry with no TTL/cap, so on a
  single-worker helper a hostile PPTP server reusing one call-id
  alias could grow `pending_call_installs` by up to 64/s for the
  control channel's lifetime and every retained entry was cloned,
  re-installed and re-counted (`allocator_collisions` +N/s) on the
  only forwarding worker every second. The refusal is now classified
  (`install_collision_is_transient` in `afxdp/pptp_broadcast.rs`,
  using the non-counting `PptpAssociations::install_error_for`
  probe): a self-retry is retained only when a queued/pending CDN or
  channel forget (in the inbox or as a not-yet-applied worker
  command) will retire the colliding association, or the owner was
  learned strictly before the retry (the #15251/#12133
  replacement-whose-CDN-is-in-flight shape); permanent refusals are
  dropped after their single counted attempt. The retry walk probes
  without counting and only calls the counting `install` once the
  alias has actually freed, so a retained retry never re-counts.
  The store gains a hard cap (`MAX_PENDING_CALL_INSTALLS = 256`,
  drop-newest, enforced before commitment in
  `record_call_install_at`) and an age bound
  (`CALL_INSTALL_RETRY_TTL_NS` = the association idle timeout,
  pruned under the inbox lock in `take_call_install_retries_at`), so
  retention and per-tick walk work are bounded even when a freeing
  event never lands. A peer's queued `InstallPptpCall` that collides
  on apply was and remains counted once and never re-attempted.
  Residual: same-drain-pass permanent collisions whose owner was
  learned strictly before them on an earlier pass are retained
  (indistinguishable locally from a queued-teardown replacement);
  they are bounded by the cap/TTL and never re-counted, and expire
  with the colliding association.
- **File(s)**: `userspace-dp/src/afxdp/pptp_broadcast.rs`,
  `userspace-dp/src/afxdp/worker_queue_tests.rs`,
  `userspace-dp/src/session/pptp.rs`,

- **Validation**: New
  `permanent_collision_self_retry_is_bounded_and_counted_once_16609`
  (64 same-alias replies, single worker: 1 learned, collisions stay
  63 across 6 ticks, retention within cap; pre-fix collisions grew
  63/tick) and `pending_call_installs_are_capped_and_age_pruned_16609`
  (320 records cap at 256; past-TTL retries pruned to 0). Guards:
  `own_retry_retains_allocator_collision_until_cdn_frees_alias_12133`
  and the full `12133` filter (16 passed) plus
  `first_learn_collision_backlog_learns_replacement_on_both_workers_15251`
  stay green. Broader `pptp` filter: 101 passed, 1 failed —
  `pptp_open_frame_carries_the_call_id_pair_13965` fails identically
  on a pristine origin/master build (pre-existing, untouched here).
