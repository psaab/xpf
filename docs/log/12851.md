# #12851 — preserve static sibling fingerprints beside dynamic feeds

## Why

The resolved fingerprint builders passed a nil feed overlay to both address-book and policy lowering. A policy side that referenced a declared `dynamic-address` binding therefore became `__unsupported_address__` as a whole, even when the same side also referenced a static address. That made a change to the static sibling invisible to `policy-rematch extensive`; the identity-stripped fingerprint used for rename ancestry had the same issue.

## What

- `PolicyResolvedFingerprints` and `PolicyResolvedIdentityStrippedFingerprints` now take a feed overlay and use it consistently for address-book construction and policy lowering.
- The daemon supplies overlays for both old and incoming configurations when computing extensive rematch fingerprints, in both ordinary modified-policy invalidation and the apply-capture path. Rename ancestry fingerprints use those same overlays.
- Added a dataplane regression covering a live feed in a mixed static/feed address-set, a static sibling CIDR change, identity-stripped fingerprint change, and determinism. Daemon regressions verify both nonzero-policy extensive rematch selection and pre-publication capture of an established session for reauthorization while a real feed manager serves a healthy feed.
- The test fixture retains a static alias of the feed name; declared binding precedence remains unchanged. The overlay's live feed prefixes are merged via existing address-book resolution, and unready bindings remain fail-closed.

## Validation

- **RED (before the fix):** `go test ./pkg/dataplane/userspace -run '^TestResolvedFingerprintsTrackStaticSiblingBesideAbsentFeed12851$' -count=1` failed because the static sibling change produced the same fingerprint (`de6d4a51…`), with the assertion identifying the sentinel collapse.
- **GREEN:** `go test ./pkg/dataplane/userspace -run '^TestResolvedFingerprintsTrackStaticSiblingBesideLiveFeed12851$' -count=1` passed.
- `go test ./pkg/dataplane/userspace ./pkg/daemon -count=1`: userspace passed; the daemon package hit its 10-minute test timeout while unrelated canary tests were blocked waiting for channels (including `TestCanarySyntheticBareIdentCallsite` and `TestManagementProbeCanaryAllowlistIsFileScoped`). No assertion failure from the new tests was reported.
- `go test ./pkg/daemon -run '^TestPolicyRematchExtensive' -count=1`: passed.
- `go test ./pkg/daemon -run '^TestCaptureExtensiveRematchIncludesLiveFeedStaticSibling12851$' -count=1`: passed.
- `go test ./pkg/daemon -run 'Test(PolicyRename|.*Rename|PolicyRematch|.*Rematch)' -count=1`: passed.

## Risk

The overlays represent feed state supplied by the daemon at invalidation time. A real feed refresh is not a configuration commit event; fingerprints continue to track the address content used for the old/new configuration comparison. If the feed manager cannot produce an overlay for a declared binding, the existing fail-closed lowering remains in effect. No fail-closed doctrine or policy-ID selection rule is changed.
