  - **Action**: Fix untagged unit 0 on a tagged non-RETH, non-VRRP parent
    losing its address to xpf's own networkd reconfigure tail (#16795,
    R3-A37-05, residual of #9721). `planPhysDesired` folds a `vlanID == 0`
    unit's addresses onto the parent plan and the netlink reconcile installs
    them there, but `buildInterfaceNetworkdModels` rendered the parent row
    with `VLANParentAddresses` only for the #9721 RETH-VRRP advert source
    and `KeepAddresses` only for that source or a standalone vrrp-group
    (#15061) — so the parent `.network` carried no `Address=` and no
    `KeepConfiguration`, and `networkd.Apply`'s reload + reconfigure tail
    stripped the address as foreign on every apply whose files changed.
    Fix (render-on-parent owner, not strict-reject): new
    `untaggedUnitAddresses` in `compiler_iface_vlan_parent.go` collects the
    real addresses of untagged (`VlanID <= 0`), non-disabled units of a
    non-RETH parent in ascending unit order, and `buildInterfaceNetworkdModels`
    appends them to the parent row's `VLANParentAddresses`, so they render
    as `Address=` lines and `KeepAddresses` (already keyed on
    `len(parentAddrs) > 0`) yields `KeepConfiguration=static`. Guards mirror
    the existing owners exactly: RETH members return nil (their untagged
    unit's address is a VIP VRRP owns; the parent keeps only the advert
    source), a unit carrying a standalone vrrp-group is excluded (its
    address stays VIP-foreign via `KeepForeignStatic`, never rendered —
    #15061), disabled units contribute nothing (#14575), and tagged-only
    parents render byte-identical to before. No renderer change: the
    existing `VLANParentAddresses` block in `pkg/networkd` already renders
    the field and `hasRenderedStaticAddress` already counts it. The #9721
    cell that asserted the non-RETH control carries nothing was updated:
    `ge-0/0/3` now carries exactly its untagged unit's real address
    (10.0.3.1/24) and no advert source.
