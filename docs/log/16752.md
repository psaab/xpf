# #16752 — mixed-generation flow exporters: retire replaced members per exporter

- **Timestamp**: 2026-10-25
- **Action**: give every flow exporter its own child context so a
  replaced member of a partially retained build is retired and closed
  instead of leaking to its old collector.
- **File(s)**: listed under Change.

## Defect

#15230 made flow-export reconcile build each template group
independently: healthy groups publish their new config even when a
sibling instance fails to build, and the failed instance keeps its
previously running exporter. But all exporters of one build shared a
single generation context (`v9Gen`/`ipfixGen`). When a later commit
moved the healthy instance while the sibling still failed, the
reconcile published the new healthy exporter plus the retained failed
one, then found the old generation "mixed" (one member published, one
replaced) and kept it tracked whole — it could not cancel the
generation without also cancelling the retained exporter. The
replaced healthy exporter therefore kept running, kept its SourceID,
and kept sending template refreshes (and any finals its tracker still
emitted) to the collector the operator had removed, until the failed
sibling built or the daemon stopped. At a shared collector the same
SourceID/template ID could carry two definitions.

## Change

- `pkg/daemon/daemon_flowexport.go`: `v9Group`/`ipfixGroup` now carry
  their own `cancel`/`wg`. Each newly built exporter runs under its
  own child of the daemon context. `retainedV9Locked`/
  `retainedIPFIXLocked` return only the retained groups/exporters
  (which keep their original per-exporter handles); after the new
  bundle is published, `retireV9Groups`/`retireIPFIXGroups` retire,
  cancel, bounded-join (`joinWithBudget`, #9035), and close exactly
  the old exporters that are no longer published — including a
  replaced healthy exporter whose sibling was retained. The
  generation types and the mixed-generation keep-whole arm are
  removed. Teardown (`teardownV9GroupsLocked`/
  `teardownIPFIXGroupsLocked`) captures the live bundle before
  unpublishing and retires each live group exactly once, with the
  prior exporter-list fallback preserved for hand-built state.
- `pkg/daemon/daemon_flow.go`: `stopFlowExporter`/
  `stopIPFIXExporter` capture the live groups before unpublishing,
  then call the groups teardown.
- `pkg/daemon/daemon.go`: drop the now-unused `flowGens`/`ipfixGens`
  fields.
- `pkg/flowexport/README.md`: generation-tracking note updated to
  the per-exporter-context shape.
- Regression cells:
  `pkg/daemon/daemon_flowexport_mixed_16752_test.go` —
  `TestMixedGenerationRetiresReplacedHealthyExporter16752` (v9:
  healthy boot with a's collector as a real UDP listener and a 1s
  template refresh; day-2 moves a while b fails; asserts live ==
  published, the old a exporter is gone from the live set, retained
  b stays live (control), and the old collector receives 0 datagrams
  across a full refresh cadence) and
  `TestMixedGenerationIPFIXMirror16752` (IPFIX mirror of the
  live-set invariant with b given an IPFIX server so its bad source
  fails its IPFIX build too).

## Validation

- `go test ./pkg/daemon/ -run 'TestMixedGeneration|TestPartialBuild'`
  plus the flow-export reconcile/session suites; RED evidence: with
  the per-exporter retirement reverted (generation keep-whole
  restored), the day-2 live set keeps the old a exporter and the old
  collector keeps receiving template datagrams. See PR body for
  counts.

## Risk

A replaced exporter now stops at the reconcile that replaces it
(previously it stopped only at daemon shutdown or when its whole
generation became unpublished). Retained exporters of a failed
instance are unaffected: they keep their context, SourceID, and
collector until their own replacement builds or flow export is
removed.
