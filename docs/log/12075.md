# #12075 — resolve HA session egress by stable interface fold

- **Issue**: #12075 — peer session-sync egress ifindices are node-local and can select the wrong local interface and redundancy group.
- **Branch**: `fix/12075-egress-fold`
- **Worktree**: `/var/worktrees/12075-egress-fold`
- **Base**: `a16d32e69d28848ae7fdb3057b481bb42e0dc030`

## Why

`FibIfindex` and `FibVlanID` describe the sender's local FIB result. Resolving those numbers directly on the receiving node can select an unrelated interface and owner RG. An egress-zone fallback is safe but imprecise when a zone spans multiple RGs. The shared RETH-relative interface fold provides a peer-stable identity while leaving the BPF conntrack ABI unchanged.

## What

- Added sync-only `EgressIfaceFold` metadata for v4/v6 and stamp it from the sender's local `{FibIfindex, FibVlanID}` on incremental and bulk install sends, using the existing direction-agnostic stable-name resolver.
- Extended the optional rule-ID/handshake wire tail append-only. Fold-zero values retain the exact legacy encoding; nonzero folds carry an explicit handshake byte followed by the fold, allowing old decoders to consume the handshake and ignore the extension. New decoders retain zero for legacy or truncated tails.
- Resolve nonzero peer folds to the receiving node's local egress unit, TX parent/VLAN, and owner RG. An unresolved peer fold never falls through to the sender's raw ifindex and does not seed the helper's cached fast path with sender-local MACs; it falls back to zone ownership. Fold-zero local values retain their existing FIB path.
- Preserve the fold through node-local scrubbing, clear it when synthesizing a reverse companion because it predicts only the forward route, update lossy BPF-mirror fixtures and field censuses, and regenerate the shared sync/install JSON goldens for the added zero-valued field.

## Review12304 P2 — fail closed on ambiguous Linux interface ownership

The shared #7095 resolver also supplies the #12075 egress stamp. A lenient-loaded
configuration can preserve two distinct member spellings that canonicalize to
one Linux interface but belong to different RETHs. The resolver iterates the
RETH map, so selecting the first match could send an arbitrary peer identity.
An ambiguous match now returns an empty stable name (fold 0); exactly one match
keeps the prior fold, and no match keeps its prior fallback. The cluster sync
consumer treats fold 0 as unattributable and uses the existing zone
approximation.
