## Design correction (a)→(b)→snapshot: lock-free active publication

My adjudicated design (a) kept per-delta `ActiveConfig()` as the generation
check (uncontended RLock, 0 allocs, `cachedIPsecSANameIndex` precedent).
Two blocker advisories + the issue's explicit "hoist `ActiveConfig()` out"
require the warm path to avoid the store lock entirely. Design (b),
approved by Main: a dedicated generation counter in `Store`. A further
seqlock advisory then forced the publication protocol choice (below);
final shape: atomic snapshot publication (no seqlock, no spinning).

- Store evidence: NO lock-free active-generation source existed —
  `candidateGen` is `s.mu`-guarded (`store.go:72-88`), `confirmGen`/
  `confirmArmGen` are commit-confirmed-scoped (`store.go:219-248`), no
  watcher/subscribe infrastructure; `ActiveConfig` = RLock + pointer
  (`store_format.go:56-59`).
- All 7 `s.compiled =` swaps enumerated by grep and verified under write
  lock: `store.go:878` (SyncApply), `store_commit.go:260` (commit),
  `:638` (commit-confirmed), `:1168` (`PromoteRollback`, explicit
  `s.mu.Lock` at :1157), `store_persist.go:128` (Load, explicit lock at
  :24), `:271`/`:295` (boot recovery, via `recoverPendingConfirmLocked`
  under Load's lock). Each immediately followed by
  `s.publishActiveLocked()` (swap-then-publish). The only other
  `compiled =` is white-box test manipulation
  (`confirm_first_commit_marker_7291_test.go:146`, no Daemon involved —
  zero cache impact, documented; bypass covers the snapshot too).
  Zero in-place `compiled.X` prod writes.
- Publication: `activeSnap atomic.Pointer[activeSnapshot{gen,cfg}]`
  (`store.go`, `store_gen.go`). One immutable pair per swap; a reader's
  single atomic load observes exactly one publication — never a mixed
  pair. `ActiveSnapshot() (uint64, *config.Config)` is the sole lock-free
  API (nil-safe → `(0,nil)` = withhold, matching `ActiveConfig`-nil
  semantics); the intermediate `ActiveGeneration` accessor was removed
  (zero consumers, single tight API). Daemon fast path compares gen AND
  cfg pointer (free backstop, also store-swap-safe); slow path builds
  from the snapshot cfg — NO `ActiveConfig` call anywhere on the delta
  path, not even on miss. Start-pair store discipline: a commit landing
  mid-build costs at most one redundant rebuild; publishing a reloaded
  generation with the build could pair an old map with a newer
  generation (permanent staleness) and is forbidden by comment.
- Seqlock REJECTED with cause: the stale-read window it closes is benign
  (`StableZoneID` is a pure function of name — stale maps differ in key
  SET only, never values; per-delta straddling is inherent to base with
  no batch atomicity; the window matches installed-dataplane lag since
  the compiler runs on apply, strictly after promotion), while odd/even
  marking doubles the bump sites (7→14, doubling the dominant
  missed-site risk) and makes readers spin on the ACK-pacing hot path.
  Snapshot publication closes the same window with the same site count
  and zero spinning.
- `ipsecSAIndex` precedent distinguished: its sources are daemon-driven
  single-point loads; active-config promotions are multi-path store
  operations with no airtight daemon choke point (tests/sync drive the
  store directly), so a daemon-side push hook was rejected as fragile.
