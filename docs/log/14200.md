# Issue #14200 — parseAddressBookEntries silently drops container-shaped address/address-set blocks

- **Issue:** A hierarchical `address { h1 10.0.0.1/32; }` / `address-set { s1 { address h1; } }` block carries no name on the entry node itself (`Keys==["address"]` / `["address-set"]`, name on the child). The schema's named-argument descent admits it, but `parseAddressBookEntries` silently `continue`d / skipped it: only unknown keywords reached `UnknownBookEntries`, so strict compile accepted the config with the entry missing and, worse, a zone-local policy reference could fall back to a broader same-name global twin (the #12622 hazard, bypassed for this shape).
- **Context read:** Issue body + deep-review D10-08 research (codex MATERIAL, opus NEEDS_VALIDATION, spark MATERIAL). Cited paths re-verified at origin/master 805ac16cd. Probed the real parser AST: `address { h1 10.0.0.1/32; }` → `Keys=["address"]` with child `["h1","10.0.0.1/32"]`; `address-set { s1 { address h1; } }` → `Keys=["address-set"]` with child `["s1"]`. Confirmed strict `CompileConfig` accepted both with empty book and no quarantine.
- **What:** In `parseAddressBookEntries` (pkg/config/compiler_security_addressbook.go), a nameless `address`/`address-set` node is now recorded via a shared `recordNameless` helper exactly like an unknown keyword: appended to `UnknownBookEntries` with names recovered from immediate children (`nested.Keys...`, covering both leaf `["h1",prefix]` and block `["s1"]`), and every recovered name added to `CollidingNames`. No new validator: the existing strict gate `validateAddressSetMembersDefinedStrict` rejects on `UnknownBookEntries`, the tolerant path warns, the zone-local fold qualifies the names into `zone-local/<zone>/<name>` collisions, and `compileZones` marks the zone `DroppedEnforcementChild` (interfaces unbound). A nameless leaf (`address;`) records an empty-name entry so strict still rejects. Valid shapes (`address h1 ...`, `address h1 { prefix; }`, `address-set s1 { ... }`) are untouched.
- **Layer choice:** Compiler recording, not schema rejection — same doctrine as #12622 unknown entries: strict rejects, tolerant loads boot with warning + quarantine instead of bricking (#1960).
