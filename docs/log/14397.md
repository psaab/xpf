# #14397 — OSPF `authentication md5` / `simple-password` with no key renders unauthenticated

## Mechanism

`set protocols ospf area 0.0.0.0 interface ge-0/0/1 authentication md5 1`
(no `key` child), `authentication md5 1 key ""`, and
`authentication simple-password ""` compiled cleanly on the strict path:

- `pkg/config/compiler_protocols.go` sets `AuthType = "md5"` unconditionally
  on seeing the `md5` child and appends `OSPFMD5Key12186{ID: 1, Key: ""}`
  even when the `key` child is absent; `simple-password ""` sets
  `AuthType = "simple"`, `AuthKey = ""`.
- No validator rejected the keyless selection:
  `validateOSPFMD5KeyIDs11794` checks key-IDs only, never `Key`;
  `validateFRRAuthValuesStrict`'s `checkKey` returns nil for `s == ""`.
- `pkg/frr/protocols_render.go` silently dropped every empty MD5 key
  (`if key.Key == "" { continue }`, no warning on the all-empty path) and
  the `simple` arm required a non-empty key, so the managed section
  contained `ip ospf area` with zero authentication lines. OSPFd fell back
  to no authentication: any LAN-adjacent peer could form an adjacency and
  inject LSAs area-wide, with no operator-visible signal.

Distinct from DR6-H4 / #14388 (tolerant-load omission of an out-of-range
key-ID, warned, lenient-only): this was strict-path acceptance of a
keyless selection, silent on both paths.

## Fix

- New strict gate `validateOSPFAuthKeyPresenceStrict`
  (`pkg/config/compiler_validate_strict_ospf_auth_key_14397.go`), wired in
  `runUniformGates` beside the #11794 key-ID gate (after existing gates, so
  first-error priority is unchanged): for every OSPF area interface in the
  global config and in each routing instance, `AuthType == "md5"` with no
  non-empty key (`AuthMD5Keys` all empty and `AuthKey` empty) rejects
  naming area/interface; `AuthType == "simple"` with `AuthKey == ""`
  rejects likewise. Rollover mixes with at least one non-empty key stay
  valid (at-least-one-non-empty-key rule).
- Lenient doctrine (#1960): new `lenientOSPFAuthKeyPresence14397` opt
  (set only by `lenientCompileOpts`) downgrades the rejection to a
  `cfg.Warnings` entry + `slog.Warn` naming the same scope, so a persisted
  or peer-synced config still boots.
- Renderer belt (`pkg/frr/protocols_render.go`): on the rebased master
  the #14388 MD5 pre-check already omits an interface whose MD5 keys
  are all empty/unrenderable; this change adds the same fail-closed
  omission for `simple` with an empty key (loud `slog.Warn`), so a
  keyless-auth interface is never activated unauthenticated. This
  covers tolerant loads and directly-constructed configs. No keyless
  `message-digest` line is emitted (FRR adjacency behaviour for that
  line is not established).

Keyed MD5, keyed simple, rollover mixes, and no-auth interfaces render
byte-identical to before. `validateOSPFMD5KeyIDs11794` and the DR6-H4
lenient key-ID behaviour are unchanged.
