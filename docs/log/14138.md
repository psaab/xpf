# #14138 — interface settings and OSPF

`assembleFRRConfig` collapsed every unit's `point-to-point` flag onto the
parent kernel name (`config.LinuxIfName(name)`): a p2p flag on a tagged
unit (`ge-0/0/1` unit 50, `vlan-id 50`) marked the untagged parent device
— where the broadcast unit 0 lives — and never marked the actual VLAN
netdev `ge-0-0-1.50` that FRR/OSPF binds. A RETH logical name (`reth1`)
was likewise emitted verbatim as an FRR `interface` operand instead of
its local physical member's device, and interface bandwidth shared the
verbatim/logical keying.

The daemon assembler (and its legacy standalone-CLI twin in
`pkg/cli/apply.go`, which duplicated the same collapsing loop) now keys
bandwidth on `cfg.ResolveKernelIfName(name)` — the interface's own
kernel device, RETH → local member — and each unit's `point-to-point` on
`cfg.ResolveKernelIfName("<name>.<unit>")`, the canonical resolver the
protocol operands already use (#9405): unit-0 collapse, `.<vlan-id>`
naming, per-unit tunnel names, and RETH→member resolution all come from
that one resolver rather than a second spelling rule.

Separately, `generateInterfaceSettings`' explicit-network-type
suppression inspected only the global OSPF config (fed as the resolved
`rOSPF`), so an explicit network type authored only under a
routing-instance (VRF) OSPF area never suppressed the generated
`ip ospf network point-to-point` line and one interface could carry both
lines. `buildManagedSection` now also feeds every instance's
name-resolved OSPF set, and the suppression unions network types across
the global config and all instances, keeping the existing per-config
first-area rule intact.

Regression: `TestAssembleFRRInterfaceSettingsPerUnit14138` and
`TestAssembleFRRInstanceOSPFNetworkTypeSuppressesP2P14138` in
`pkg/daemon/interface_p2p_ospf_14138_test.go` drive a config with
`ge-0/0/1` unit 50 p2p (unit 0 broadcast), a RETH tagged p2p unit, and a
VRF instance OSPF area with an explicit broadcast type through
`assembleFRRConfig` → `ApplyFull`, asserting the settings stanza lands on
`ge-0-0-1.50` / `ge-0-0-3.60` (never the parent or the logical `reth1`),
bandwidth lands on `ge-0-0-1` / the RETH member `ge-0-0-3`, and the
instance's explicit type suppresses only its own interface's fallback.
Both fail on pre-fix master and pass with the fix.
