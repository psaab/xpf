# #17071 — delete production-dead lease-change wrappers left by #14976

- **Timestamp**: 2026-10-27
- **Issue**: #17071 (R4-Q33-03)
- **Base**: `origin/master 8fdb112b3f`

## Defect (STEP-0, verified at base)

Commit 6e39e8c816 (#14976) moved the management-only lease path to
`managementOnlyLeaseRefresh` → `reapplyIPsecLocked` / `rebindWebMgmtLocked`,
removing the last production calls of `reapplyIPsecForLeaseChange` and
`rebindWebMgmtForLeaseChange`. The wrappers, their docs, `daemon.go`'s field
doc, both module READMEs and the #14976 commit message still named them as
the live path. Eleven-plus test call sites drove them, so negative controls
were satisfied by the wrappers' own pre-acquire gates and never exercised the
gate production runs (`reapplyIPsecLocked` / `rebindWebMgmtLocked`).

Proof at base: `grep -rn 'reapplyIPsecForLeaseChange\|rebindWebMgmtForLeaseChange' pkg cmd --include='*.go' | grep -v _test.go`
returned only definitions and comments — zero production callers. No
reflection, method-value or interface dispatch of either name exists.

## Fix

- Deleted both wrappers from `pkg/daemon/daemon_dhcp.go`; their substantive
  docs (scoping, #4899 recoverable/visible failure, non-fatal contract) moved
  onto `reapplyIPsecLocked` / `rebindWebMgmtLocked`, which now state they are
  driven by `managementOnlyLeaseRefresh` and that the caller MUST hold
  `applySem` with the gate evaluated on the fresh snapshot.
- Fixed stale references: `daemon.go` field doc, `daemon_ipsec_rebind.go`
  caller list, `daemon_dhcp_14976_test.go` RED comment, `pkg/daemon/README.md`,
  `pkg/ipsec/README.md`. Historical `docs/log/*.md`, issue/pr history and
  review archives are intentionally untouched (append-only record).
- No production behaviour change: the live path
  (`onDHCPAddressChange` → `managementOnlyLeaseRefresh` → `*Locked`) is
  byte-identical apart from the deleted dead code.
