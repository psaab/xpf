# Issue #13109 — preserve poisoned-zone claims through quarantine (D1-04)

- **Issue:** `compileZones` cleared a zone's interfaces in P4 as soon as an
  unknown child poisoned it. P6b then lost the poisoned claimant: a healthy
  zone could silently take a contested interface, the poisoned zone's local
  address-book entries were still folded into the global book, and the strict
  duplicate-interface diagnostic was hidden by the later unknown-child gate.
- **Source:** Deep-review finding D1-04, High severity,
  EXECUTED/MATERIAL; validated by three-way adversarial research. Source report:
  `/var/tmp/deep-review-reports/gemini-4-argon-high-review-zone-enforcement-001.md`
  §5. The source probe reproduced the missed conflict and address-book fold.
- **What:** Preserve authored memberships until all compiler gates have run.
  Strict compilation can now reject duplicate claims before the unknown-child
  diagnostic. Tolerant compilation quarantines conflicts using retained
  poisoned-zone interface claims, then clears the zone's interfaces,
  host-inbound state, screen binding, and TCP-RST state before returning.
  Poisoned zones' known local addresses are not folded; unknown address-book
  names remain collision-quarantined so they cannot fall back to unrelated
  global entries. Existing coverage verifies a poisoned/healthy contested
  interface stays unzoned and healthy duplicate behavior remains unchanged.

## Scope and impact

- Tolerant loads still return a bootable config; poisoned zones do not publish
  enforcement state. A contested interface is now unzoned and fails closed
  rather than silently inheriting another zone's policies.
- Peer-node zone exclusions retain their existing membership behavior; only
  locally poisoned zones preserve authored claims long enough to detect local
  contested interfaces. No dataplane wire format changed.
