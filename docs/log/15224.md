# Issue #15224: DHCPv6 PD lifetime/refusal residuals (A39-02, A39-08)

## Why

Two validated residuals from the #14598 cohort:

- **A39-02:** a PD-only client (`ia-pd` without `ia-na`) whose
  RENEW/REBIND Reply carried IA_PD `NoPrefixAvail` got the generic
  "no usable IA_NA address or live IA_PD prefix" error from
  `parseV6ReplyChecked`. The run loop treated it as transient
  (keep-and-wait-T2 / re-acquire) and never cleared the held
  delegation, so `DelegatedPrefixesForRA` kept advertising the refused
  prefix until its own valid lifetime ended. The mixed
  `ia-na`+`ia-pd` path already cleared via the `pdRefused` commit arm
  because parse succeeds there via the address; the PD-only path
  discarded the #14598 refusal.
- **A39-08:** `infiniteLifetime` was `1<<62` ns (~4.61e18), above the
  RFC 8415 wire infinite value decoded by the dhcpv6 library,
  `math.MaxUint32` seconds (~4.29e18 ns). Infinite PDs/leases were
  therefore treated as finite: decayed by `RemainingLifetimes`, given
  a finite `ExpiresAt` (feeding finite expiry into the RA path), and
  pruned after ~136 years. The documented infinite branch was dead.

## What

- `pkg/dhcp/dhcpv6.go`: new `errV6PDRefused` sentinel.
  `parseV6ReplyChecked` returns it (wrapped) when `pdRefused` is set
  and no usable address or live prefix was granted, before the generic
  guard. The run loop handles it at T1 RENEW (clear + re-acquire,
  lease-expiry pending preserved) and at T2 REBIND (clear, then the
  generic re-acquire below), via `clearDelegatedPDs`.
- `pkg/dhcp/dhcp.go`: `clearDelegatedPDs` drops only the stored PD
  set (guarded by the committed-lease pointer like
  `abandonLeaseAfterExpiry`) and arms a recompile; the lease record
  and any held IA_NA address are untouched. `infiniteLifetime` is now
  `time.Duration(math.MaxUint32) * time.Second`.
- `pkg/dhcp/dhcpv6_addressless_15071_test.go`: the infinite-lease
  fixture now constructs the wire value instead of the sentinel
  constant, per the issue's fix direction.
- `pkg/dhcp/README.md`: cohort note. NOT changed: the mixed-path
  `pdRefused` commit arm, silence/keep-and-retry (#1844), the
  REBIND-teardown server binding (#14997 — the matcher still gates
  which Replies reach parse), and DHCPv4 (no PD set).

## Validation

- RED on `origin/master` (bc72ad52db): the new
  `pkg/dhcp/dhcp_cohort_15224_test.go` fails to build
  (`undefined: errV6PDRefused`) — the typed refusal does not exist;
  with the sentinel stubbed the infinite-lifetime assertions fail
  against the `1<<62` threshold (decayed/finite expiry).
- GREEN: `go test ./pkg/dhcp/ -run '15224' -count=1` passes (wire
  infinite PD/lease never decays or expires, finite control still
  decays/expires; PD-only refusal typed at parse; silence stays
  generic; live PD-only grant succeeds; run loop clears
  `DelegatedPrefixesForRA` immediately at both RENEW and REBIND with
  recompile armed). Full `go test ./pkg/dhcp/ -count=1` passes.
  `go vet ./pkg/dhcp/` clean; gofmt clean on touched files.

## Risk

A refusal now triggers re-acquisition (Solicit) rather than waiting
for T2 on the PD-only path — the server has explicitly said it holds
no prefix, so re-requesting is the RFC 8415 recovery; the matcher
(#14997) still prevents a non-granting REBIND responder from reaching
this arm. Infinite lifetimes now report no expiry to RA/cluster
consumers, which is the intended RFC 8415/4861 infinity semantics
(0xffffffff on the wire).
