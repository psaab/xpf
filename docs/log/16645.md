# Issue #16645 — eventengine: cooldown park released e.mu mid-loop, pairing old commands with the new semantic revision

- **Defect:** `maybeDeferCooldownLocked` (`pkg/eventengine/evaluate.go`)
  released `e.mu` mid-loop to take `pendingMu`, then relocked. A concurrent
  `ApplyWithConfig` redefining a later same-event policy in that window made
  the still-running old loop stamp the OLD policy object (old `ThenCommands`,
  old `PlantClass`) with the NEW `e.semRev[name]` — both in the returned
  `triggeredPolicy` and in the parked cooldown edge. `staleReason` compares
  revisions only, so the retracted batch passed the #3750 "policy redefined"
  gate and committed once under the new definition, and its cooldown then
  throttled the new definition.
- **Fix:** evaluation never releases `e.mu`. `captureDeferCooldownLocked`
  builds the parked `plannedAction` under `e.mu` from the live policy and
  the current revision; `evaluateEventLocked` collects the parks and
  `evaluateEventMode` inserts them under `pendingMu` only after `e.mu` is
  released (`insertDeferredCooldownParks`, first park per (policy,event)
  wins, as before). The parked action therefore always carries the revision
  of the generation that produced it, and after a redefinition the existing
  commit-time `staleReason` backstop (and the drain-time revision check)
  reject it as "policy redefined". No lock-order change: `pendingMu` was
  already taken after `e.mu` on the budget path; evaluate now never nests
  the two at all.
- **Tests:** new `pkg/eventengine/engine_cooldown_unlock_16645_test.go`.
  `TestEvaluateCooldownUnlockRedefinition16645` holds `pendingMu` so the
  redefinition lands exactly in the old unlock window: RED on pre-fix code
  (`old p2 paired with new revision`, verified by stashing the fix), GREEN
  after; it also asserts the parked p2 action carries the old revision and
  `staleReason` returns "policy redefined". Control
  `TestEvaluateCooldownParkControl16645` restates the #15021 contract (a
  genuine in-cooldown crossing still parks and replays after the cooldown).
- **Validation:** `go vet ./pkg/eventengine/` clean; targeted
  `TestEvaluateCooldown|TestDeferred|TestStale_` suites PASS; the new tests
  and the #15945 deferred cells also PASS under `-race`. (The older #15021
  tests race on their own unsynchronized fake-clock variable under `-race`
  on pristine base too — pre-existing, unrelated.) Full `pkg/eventengine`
  suite shows only the 9 pre-existing `multivalue_leaf_runtime_6673`
  failures documented at #15945 (plus one flaky
  `TestNoopCommit_UnchangedBatchSkipsCommit_15022` pass on re-run,
  count=3). No cluster (per assignment).
