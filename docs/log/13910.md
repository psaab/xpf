# #13910 — fail closed on missing translated reverse provenance

Why: The companion-less reverse-hit fast return treated NAT64/NPTv6 like an
untranslated flow, skipping the missing-forward-VLAN fail-closed check. Their
source-NAT validator returns valid without checking translated state, so stale
translated reverse traffic could pass to zone-policy evaluation.

What: Preserve #13789's intended pass-through for a reconstructed forward
`rewrite_src == None` without NAT64/NPTv6, but let NAT64/NPTv6 reach the
forward-VLAN provenance check. Added missing-provenance drop-only regressions
for NAT64/NPTv6, a provenance-present control, and a no-rewrite policy-gate
pin. No protocol or wire-format changes.

Validation: RED on unpatched origin/master 5aa9179e4: the NAT64 missing-forward-
provenance regression received no revocation. GREEN after the fix:
`cargo test --bin xpf-userspace-dp policy_revalidation::tests -- --nocapture`
(38 passed). Full binary suite: 8,146 passed, 8 ignored, 3 failed. Each of the
three failures was reproduced individually on clean origin/master 5aa9179e4:
`fixture_pkt_len_is_the_full_frame_length_6883`,
`worker_loop_orders_expiry_teardown_before_poll_10419`, and
`additive_wire_exhaustive_literals_only_ever_decrease_7689`.

Risk: Missing forward VLAN provenance still drops companion-less translated
NAT64/NPTv6 reverse hits; untranslated reverse hits continue to the ordinary
policy gate.
