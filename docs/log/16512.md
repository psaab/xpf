# #16512 — sub-1280 tunnel inner budget: fragment outer below IPv6

- **Timestamp**: 2026-10-24
- **Action**: An IPv6 inner in (budget, 1280] over a GRE/WireGuard
  tunnel whose derived inner budget is below 1280 (GRE-1300 → 1276,
  WG-1350 class) previously got `EmitPacketTooBig{1280}` + drop —
  a PTB the sender can never act on (RFC 8201 §4) — permanently
  blackholing 1280-byte DNS-EDNS/QUIC. Now such packets are
  DELIVERED by link-specific fragmentation below IPv6 (RFC 8200
  §5): the dispatcher (`compute_forwarded_egress_ptb_with_dynamic`)
  diverts the band to `build_sub1280_tunnel_outer_fragments`, which
  builds the tunnel outer and splits it at the outer MTU via the
  new `outer_frag::fragment_outer_ipv4_frame` (single writer, shared
  Identification, 8-byte multiples, DF clear). GRE outers are built
  DF-clear for exactly this band (`gre.rs`); WireGuard transit
  admits the band past `encap_mtu_drops` (`frame/wg.rs`) and the
  dispatcher fragments; the WG TUN-origin path sends via the kernel
  UDP socket, whose IP stack fragments (`wg_control/dispatch.rs`).
  IPv6 outers (cannot be fragmented by a router), inners > 1280,
  already-fragmented inners, IPv4 inners, and plain sub-1280 links
  keep PTB+drop exactly as before. The tunnel peer reassembles
  before decap (#14645/#15102). 1400/1500 controls unchanged.
