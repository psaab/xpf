# #17812: failed VRF rebind must retain scope fingerprint

- **Timestamp**: 2026-10-28
- **Action**: `SetBindDevices` publishes the desired scopes before rebind, but `syncCurFromLiveLocked` previously copied that desired snapshot into the management fingerprint whenever any listener was serving. A same-address A-to-B rebind failure therefore left the old A-scoped listener in place while recording B as converged, suppressing later retries. The reconciler now advances the scope fingerprint only after every HTTP/HTTPS plane driven by that scope change succeeds; failed scope rebinds retain the prior fingerprint as retry debt. Address/TLS state still resynchronizes from live legs after partial reconciles.
- **File(s)**: `pkg/daemon/management.go`, `pkg/daemon/webmgmt_vrf_bind_16709_test.go`, `pkg/daemon/README.md`, `docs/log/17812.md`.
- **Validation**: RED before the fix: `go test ./pkg/daemon -run '^TestMgmtFailedVRFRebindKeepsFingerprintAndRetries17812$' -count=1 -v` failed because the failed rebind advanced the fingerprint to `vrf-b` instead of retaining `vrf-a`. GREEN after the fix: all nine named daemon VRF cells in `webmgmt_vrf_bind_16709_test.go` passed, including the A-to-B failure/retry regression and real-kernel netns acceptance; all four named API VRF cells in `listener_vrf_16709_test.go` passed. No broad package suite was run.
- **Risk**: A failed scope rebind keeps the old listener and scope fingerprint until a later reconcile succeeds, preserving the existing fail-safe behavior while ensuring retry debt remains visible.
