# #17812: failed VRF rebind must retain scope fingerprint

- **Timestamp**: 2026-10-28
- **Action**: `SetBindDevices` publishes the desired scopes before rebind, but `syncCurFromLiveLocked` previously copied that desired snapshot into the management fingerprint whenever any listener was serving. A same-address A-to-B rebind failure therefore left the old A-scoped listener in place while recording B as converged, suppressing later retries. The reconciler now advances the scope fingerprint only after every HTTP/HTTPS plane driven by that scope change succeeds; failed scope rebinds retain the prior fingerprint as retry debt. Address/TLS state still resynchronizes from live legs after partial reconciles. The API server also has one `legDevices` map shared by both planes: after a reconcile, pruning now retains records for every installed HTTP and HTTPS leg so one plane cannot make a correct sibling leg look unscoped on retry.
- **File(s)**: `pkg/daemon/management.go`, `pkg/daemon/webmgmt_vrf_bind_16709_test.go`, `pkg/daemon/README.md`, `pkg/api/listener.go`, `pkg/api/listener_vrf_16709_test.go`, `pkg/api/README.md`, `docs/log/17812.md`.
- **Validation**: RED before the daemon fix: `go test ./pkg/daemon -run '^TestMgmtFailedVRFRebindKeepsFingerprintAndRetries17812$' -count=1 -v` failed because the failed rebind advanced the fingerprint to `vrf-b` instead of retaining `vrf-a`. RED before the API fix: `TestReconcileHTTPPreservesHTTPSBindScope16709` failed because HTTP pruning erased the HTTPS scope. GREEN: all nine named daemon VRF cells and all five named API VRF cells passed, including the A-to-B retry regression, dual-plane adoption control, and real-kernel netns acceptance. No broad package suite was run.
- **Risk**: A failed scope rebind retains the old scope fingerprint until a later reconcile succeeds. Scope pruning now keeps both installed planes' records, so a retry does not force an unchanged sibling leg into a colliding bind.
