# #13675 — replay synced sessions through the worker kernel-local gate

- **Base**: rebased onto current `origin/master` at PR time
- **Branch**: `fix/13675-campaign`

## Why

`Coordinator::replay_synced_sessions` published every preserved session
through `publish_live_session_entry`, writing
`USERSPACE_SESSION_ACTION_REDIRECT` for both the forward row and the
reverse NAT wire rows under `SteeringHolder::Coordinator`. For an
active-RG `LocalDelivery` session (no `lo0` filter, no routing domains)
the correct disposition is `USERSPACE_SESSION_ACTION_PASS_TO_KERNEL`:
the unconditional publish mis-steered host-bound packets into userspace
until workers drained the queued `UpsertSynced`, and claimed the reverse
NAT wire row under the coordinator holder, which no worker teardown
releases if the session is deleted before the workers catch up.

## What

- Route the replay publish in `replay_synced_sessions`
  (`userspace-dp/src/afxdp/coordinator/mod.rs`) through
  `publish_worker_session_map_entry` — the same publisher workers use
  in `handle_upsert_synced` — passing the full `SessionDecision`,
  metadata and origin so the kernel-local / lo0-filter / routing-domain
  predicates decide REDIRECT vs PASS_TO_KERNEL.
- Derive `allow_replace_local` from
  `synced_entry_allows_local_replace(ha.rg_runtime, owner_rg_id,
  now_secs)`, mirroring the upsert/refresh arms: standby-owned entries
  keep the live REDIRECT via the force-live branch; active-owned
  entries take the kernel-local arm.
- Add `replay_synced_sessions_publishes_kernel_local_for_local_delivery_13675`
  in `userspace-dp/src/afxdp/tests_bind_forward.rs`: replays an
  active-RG LocalDelivery SNAT session through a recorder steering map
  and asserts PASS_TO_KERNEL on the forward row, no forward REDIRECT,
  and exactly one (SNAT reverse-wire) REDIRECT row.

NOT changed: `publish_worker_session_map_entry` itself, the worker
publish path, and the retire/delete ownership paths — the defect was
the replay's bypass of the existing guarded publisher.

## Validation

- RED on master code (test against pre-fix publish): fails with
  `replay must publish PASS_TO_KERNEL for active LocalDelivery`, the
  recorded writes being REDIRECT forward, forward-wire, and reverse
  rows under the coordinator holder.
- GREEN with fix: `cargo test --bins replay_synced_sessions` →
  2 passed (new 13675 regression + pre-existing replay requeue test).
- Fail-on-revert verified by restoring the pre-fix `coordinator/mod.rs`
  hunk (test RED) and re-applying the fix (test GREEN).
- Full `cargo test --bins`: 8009 passed, 1 failed
  (`f035_parked_fragment_overlap_is_rechecked_on_retry_10659`),
  base-attributed: the same cell fails identically on a clean
  `origin/master` worktree.

## Risk

Behavior change only for replayed sessions the guarded predicate
classifies as kernel-local: they now publish PASS_TO_KERNEL (forward
row) instead of REDIRECT, matching worker behavior after
`handle_upsert_synced`. Lo0-filtered and routing-domain sessions still
take the live REDIRECT arm inside the same publisher, and publish
failures remain counted via `SESSION_PUBLISH_ERRORS_SHARED` inside the
shared publisher. Loss-cluster verification remains the parent's post-merge gate.
