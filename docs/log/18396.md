# #18396 — index HelperMutationStore eviction

- **Issue**: #18396 — `HelperMutationLease::complete` scans the entire 16,384-record store to find an eviction candidate.
- **Branch**: `perf/helper-mutation-eviction`
- **Worktree**: `/var/worktrees/campaign-pub/wt-perf-mutation`

## Why

At capacity, each helper-mutation completion folded over every `HelperMutationStore::records` entry to choose the minimum `(epoch, last_used)` candidate, cloning its operation-id `String`. The submitted profile attributed 15.92% of samples to the hashbrown `RawIterRange` fold in this scan.

## What

- Add an ordered `BTreeMap<(epoch, last_used), (epoch, operation_id)>` alongside the existing record lookup map. `pop_first()` selects the same oldest-epoch-first, least-recently-used victim in `O(log n)` instead of scanning `O(n)` records.
- Index completed records only. `helper_mutation_begin` creates a lease only for an absent record; a completed record is replayed without becoming in-flight. Therefore no in-flight record can appear among eviction candidates. If the index is empty, completion inserts over capacity rather than evicting a live operation.
- Update the index when an exact-pair replay advances `last_used`; completion moves the lease key into the index and retains the existing record-map key clone, avoiding the per-eviction victim `String` clone.
- Add deterministic capacity-sized tests for epoch/LRU ordering, replay recency, in-flight protection, and the all-in-flight over-capacity case. The ignored timing harness was removed after measurement.

## Validation

The focused session-domain test modules passed after restoring the correct `pop_first()` selection:

```text

  cargo test --manifest-path userspace-dp/Cargo.toml 'afxdp::ha::session_domain::' -- --nocapture
26 passed; 0 failed
```

A broader `afxdp::ha::` run included the new tests and reported 227 passed, 1 failed. The failure was `afxdp::ha::tests::purge_release_against_defaulted_forwarding_frees_nothing_and_counts_nothing_8138` at `src/afxdp/ha/../ha_tests.rs:5860`, asserting that a release against defaulted forwarding has no allocators to free from. It is outside the changed session-domain module; the focused session-domain run above is green.

A fail-on-revert mutation probe changed `pop_first()` to `pop_last()`. `helper_mutation_eviction_prefers_oldest_epoch_then_lru_18396` went RED at the assertion that the oldest-epoch/LRU record had been removed. Restoring `pop_first()` returned all 26 focused tests to green.

A throwaway ignored microbenchmark seeded both paths with 16,384 records, then timed 500 completion operations in the test profile. The old scan was reproduced through the lease API using the prior `iter().filter().min_by_key()` selection and victim key clone; the indexed side used the actual new completion path:

```text
16,384 records, 500 completions: scan=936.513609ms, index=3.866597ms
```

That is 1.873 ms/completion versus 7.73 µs/completion (~242× faster) in this single test-profile run. The benchmark harness was temporary and is not committed; timings are supporting evidence, while the complexity change is the durable guarantee: candidate selection/removal is `O(log n)` and has no `records.iter()` fold.

## Risk

No helper mutation wire/API behavior changes. Exact-pair replay still returns the stored outcome and now refreshes recency in both structures. In-flight leases remain absent from completed records and therefore cannot be selected; an empty candidate index preserves the existing over-capacity fallback. The additional ordered index stores one operation-id key per completed record, while completion avoids the previous victim-key clone.
