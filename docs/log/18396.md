# #18396 — index HelperMutationStore eviction

- **Issue**: #18396 — `HelperMutationLease::complete` scans the entire 16,384-record store to find an eviction candidate.
- **Branch**: `perf/helper-mutation-eviction`
- **Worktree**: `/var/worktrees/campaign-pub/wt-18397-fold`

- **Timestamp**: 2026-10-28
  - **Action**: preserve HelperMutationStore eviction order across recency wrap and tie collisions.
  - **File(s)**: `userspace-dp/src/afxdp/ha/session_domain.rs`, `docs/log/18396.md`

## Why

At capacity, each helper-mutation completion folded over every `HelperMutationStore::records` entry to choose the minimum `(epoch, last_used)` candidate, cloning its operation-id `String`. The submitted profile attributed 15.92% of samples to the hashbrown `RawIterRange` fold in this scan. Separately, the `u64` recency sequence can wrap, so `(epoch, last_used)` is not a unique index key: replay or completion could silently replace another record's entry and later panic during replay.

## What

- Add an ordered `BTreeMap<(epoch, sequence_era, last_used, record_id), (epoch, operation_id)>` alongside the existing record lookup map. `pop_first()` selects the same oldest-epoch-first, least-recently-used victim in `O(log n)` instead of scanning `O(n)` records.
- Index completed records only. `helper_mutation_begin` creates a lease only for an absent record; a completed record is replayed without becoming in-flight. Therefore no in-flight record can appear among eviction candidates. If the index is empty, completion inserts over capacity rather than evicting a live operation.
- Advance the sequence era when the `u64` recency sequence wraps, preserving LRU order across wrap; a live-record-unique id breaks any remaining timestamp ties without replacing another record's index entry. Replay retains that id, while completion chooses a free one.
- Update the index when an exact-pair replay advances recency; completion moves the lease key into the index and retains the existing record-map key clone, avoiding the per-eviction victim `String` clone.
- Add deterministic capacity-sized tests for epoch/LRU ordering, replay recency, in-flight protection, and the all-in-flight over-capacity case, plus `u64::MAX` replay/completion wrap regressions and tied-timestamp victim ordering. The replay test runs the four-step C/C/A/C sequence at capacity, then completes once and proves B (the true LRU among equal raw `(epoch, last_used)` values) is evicted. The ignored timing harness was removed after measurement.

## Risk

No helper mutation wire/API behavior changes. Exact-pair replay still returns the stored outcome and refreshes recency in both structures. The sequence era preserves LRU ordering when the `u64` recency sequence wraps, and a live-record-unique tie-breaker prevents equal `(epoch, era, last_used)` timestamps from overwriting index entries. In-flight leases remain absent from completed records and therefore cannot be selected; an empty candidate index preserves the existing over-capacity fallback. The additional ordered index and id set store per-record bookkeeping, while completion avoids the previous victim-key clone.
