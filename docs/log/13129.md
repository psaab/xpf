# Issue #13129: count screen profiles outside the CLI pipe

- **Timestamp**: 2026-10-14
- **Action**: corrected `count_profile_on` in `test/incus/screen-probe.sh`.
  The xpf CLI's Junos `grep` pipe does not implement POSIX `grep -c`; placing
  `grep -c $PROFILE` inside `cli -c` made the entire `-c probe8336` operand
  a literal match string. The probe now asks the CLI only for `display set`
  output and counts matching lines with host-side fixed-string `grep -Fc`.
  It checks the `incus exec` status before counting so an unreadable node
  remains an empty count and makes cleanup verification fail, rather than
  being mistaken for a clean node.
- **Regression**: `test/incus/screen-probe-selftest.sh` extracts the live
  function and tests it with a fake `incus`: zero profile lines count as 0,
  two leaked profile lines count as 2, an Incus failure stays unreadable,
  and those counts feed the existing per-node cleanup verdict. It also
  checks the CLI argument never contains `grep -c`.

## RED -> GREEN proof

- **RED**: on pristine `origin/master` (`55ab81ef`) with only the new
  selftest inserted, `bash ./test/incus/screen-probe-selftest.sh` failed
  three checks and exited 1: clean count was empty, leaked-profile count
  became the command-string digits `83368336`, and the CLI argument still
  contained `grep -c`.
- **GREEN**: after the fix, `make test-screen-probe-lib` passed, including
  the clean, leaked, unreadable, and wiring checks. `bash -n
  test/incus/screen-probe.sh test/incus/screen-probe-selftest.sh`,
  `git diff --check`, `go test ./pkg/cliterm`,
  `go vet ./pkg/cliterm`, and `go build ./...` all passed.
