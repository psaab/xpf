# #13789 — preserve forward VLAN provenance for reverse SNAT checks

Why: Companion-less reverse SNAT validation used the reply-side arrival VLAN to
reconstruct forward interface identity. In asymmetric VLAN topologies, this
could reject a valid translated flow because the forward SNAT rule is scoped to
the original ingress VLAN.

What: Carry forward ingress VLAN provenance on session metadata through reverse
synthesis and established lookup clones. Reverse SNAT validation uses that
recorded forward VLAN, and fails closed when it is unavailable; reverse-side
VLAN is not treated as forward provenance. Added asymmetric VLAN regression and
symmetric control coverage.

Validation: Baseline RED on origin/master 162df41: the asymmetric VLAN test
failed as expected. The fixed reverse-without-companion regressions passed (5
tests). The `policy_revalidation::tests` module passed (35 tests).

Risk: This adds local session metadata only; no protocol or wire-format change.
Unknown forward VLAN provenance remains fail-closed.
