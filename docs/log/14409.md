# Issue #14409 — BGP per-neighbor `authentication-key` dropped on packed neighbor line

## Why

`applyBGPNeighborProps9192` (`pkg/config/compiler_bgp_neighbor_merge_9192.go`)
iterated only `child.Children`. A packed (brace-elided) neighbor line such as

```text
protocols { bgp { group G1 { peer-as 65001;
  neighbor 10.0.0.1 passive authentication-key NEIGHBORKEY; } } }
```

arrives with `Children == []`, so the reader installed nothing at all — no
`passive`, no `peer-as`, and in particular no `authentication-key`. Rescue
depended entirely on the #8662 normalizer fold, which never fires for
unscoped heads (`passive`, `route-reflector-client`, `default-originate`,
`family`, `bfd-liveness-detection`, `remove-private`) and is declined by
#8880 whenever the following group-level sibling shares a keyword with the
neighbor grammar (`export`, `peer-as`, `import`, `description`,
`authentication-key`, `hold-time`). With no group-level key the neighbor
compiled with `AuthPassword == ""`, the FRR renderer emitted no password
line (`if n.AuthPassword != ""`), and the session came up with no TCP-MD5
while `show configuration` still displayed the authored key — a clean
commit, silently unauthenticated.

## What

- `pkg/config/compiler_bgp_neighbor_merge_9192.go`: the neighbor reader now
  expands the neighbor node's own packed tail through
  `packedBodyChildren(child, bgpNeighborSchema9792())` — the same
  schema-driven reader the BGP group loop and the OSPF interface loop
  already use — before the existing `expandResolvingRuns9792` lenient-path
  expansion. With no tail, `packedBodyChildren` returns `Children`
  unchanged; a tail that leaves the modelled grammar also returns the
  children unchanged rather than guessing. When a node carries both a tail
  and braced children, the children are either attached under the deepest
  packed node (where the grammar permits a body) or returned unexpanded,
  so nothing is read twice or dropped by the substitution.
- Fused multi-value leaves: `packedBodyChildren` models `export`/`import`
  as multi leaves, so a following packed statement can be fused into the
  value span in two shapes — on the neighbor node's own Keys, and nested
  under the neighbor by the #8662 fold (`neighbor 10.0.0.1` >
  `export EP authentication-key K`). Without a split,
  `firewallMatchValues` would install the keyword and the key as two extra
  policies while the key never arrived. `splitFusedMultiLeaves14409`
  splits a fused multi leaf at a bare, unbracketed, unquoted
  neighbor-grammar keyword (a policy actually named that way must be
  quoted; bracketed lists are excluded), re-expanding the split tail so
  chains split fully. Braced children are unaffected: a braced
  `export { EP; }` carries `EP` as a child node, not in `Keys`, so it
  never matches the scan. The reader loop keeps its outer
  `expandFlatRun` as well, which splits any remaining packed run on a
  synthesized statement; it is a no-op for braced children, whose
  statements are already separate nodes.
- New regression `pkg/config/bgp_neighbor_packed_authkey_dr13h2_test.go`:
  fixture A (unscoped `passive` head), fixture B (scoped `peer-as` head +
  following group `export`), a head-keyword matrix (passive, peer-as,
  authentication-key, description, hold-time, route-reflector-client,
  default-originate, remove-private, local-address, family,
  bfd-liveness-detection, export) each compared field-by-field against its
  braced spelling with a braced positive control, a following-sibling
  matrix (export/import/peer-as/description/authentication-key/hold-time),
  a strict `CompileConfig` cell, a braced+packed multi-node union cell,
  and controls (no-key stays keyless, group key fallback, neighbor key
  overrides group key).
- Census bookkeeping that the fix invalidated, updated in the same change:
  `pkg/config/testdata/compact_block_divergences_2419.txt` drops the 8
  now-equivalent `neighbor ... {default-originate,passive,remove-private,
  route-reflector-client}` rows (global + routing-instance); 
  `pkg/config/compact_normalize_scope_8690_test.go` drops the 2 stale
  benign `neighbor ... peer-as` classifications and the 4 stale
  fixture-limited `neighbor ... export/import` entries, each replaced by a
  #14409 note. These registers fail on stale entries by design, and the
  entries were stale precisely because the reader now repairs the drop
  without the normalizer pass.
- NOT changed: group defaults on CREATE only, the #9192 (group,address)
  merge, the #5277 own-export/import flags, BFD sub-children handling, and
  `expandResolvingRuns9792` behaviour for braced nodes.

## Risk

The reader substitution is identity for every braced neighbor (the
overwhelmingly common path): `packedBodyChildren` returns `Children`
unchanged when there is no packed tail. The only new behaviour is for
packed tails, which previously installed nothing, so no previously-working
configuration changes meaning. The fused-multi split fires only on a bare,
unbracketed, unquoted neighbor-grammar keyword inside a multi leaf's key
span — the fused shape; a quoted policy named e.g. `"peer-as"` and a
bracketed `export [ A B ]` list are both preserved. Group-key fallback and
neighbor-over-group precedence are pinned by controls and unchanged.
