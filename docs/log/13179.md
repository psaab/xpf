# Issue #13179: fail closed for local GRE tunnel transmission

## Why

`build_local_origin_tunnel_tx_request` resolved GRE's outer route and then transmitted the inner packet without checking the GRE interface's security-zone identity. A zone-less or quarantined tunnel therefore transmitted as zone 0 and could mint `TunOrigin` forward/reverse sessions, whose origin exemption bypasses ingress policy and host-inbound enforcement. The same builder treated `owns_configured_ip` as proof of local origin even though that predicate intentionally spans all routing instances; a TUN packet sourced from another VRF's address could trigger IKE seeding and `TunOrigin` publication. Non-local TUN input was also encapsulated despite this path having no security-policy/screen adjudication.

## What

`userspace-dp/src/afxdp/tunnel.rs` now rejects a zero egress-zone before IKE seeding or encapsulation. It checks source ownership against both the configured-interface address set and the source address's local routing-table ledger for the tunnel's instance. Consequently, nonlocal and cross-VRF TUN input is rejected rather than sent through an unadjudicated path; only authorized local traffic seeds IKE and receives TunOrigin sessions. The existing table identity is reused for reverse-session synthesis. `userspace-dp/src/afxdp/frame/tests_native_gre_ecn.rs` covers unzoned GRE, cross-VRF ownership, nonlocal IPv4/IPv6 and IKE rejection, plus owned-source controls.

## Validation

- GREEN: `cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp afxdp::frame::tests_native_gre_ecn::` passes all 20 tests.
- Full suite: 7,910 passed, 1 failed, 8 ignored. The sole failure, `protocol::tests::wire_invariant_default_specimens`, was reproduced on pristine `origin/master` at `ab0498643` and is a pre-existing fixture drift; generated `.actual` output was removed.
- Build: `cargo build --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp` succeeds.

## Risk

Non-firewall-originated packets arriving through the local GRE TUN reader now drop instead of being encapsulated without policy adjudication. The expected local-firewall-originated GRE path remains enabled; the existing owned-source and IKE-seed controls pin it. This deliberately changes the prior #10518 transport-preservation behavior because that path has no policy/screen decision and violates the zone-enforcement boundary.
