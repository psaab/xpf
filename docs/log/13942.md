# #13942 — bind PPTP data refreshes to control peers

`PptpAssociations::resolve_and_touch_in_domain` now requires the outer source
and destination to be the two endpoints in the learned call association, in
addition to the destination/call-ID alias. A packet from any other source is
unassociated and cannot refresh the idle expiry clock. Both GRE data directions
remain valid because each is checked against the two learned peers.
