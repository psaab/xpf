# #15186 — upgrade: same-version re-run of already-live committed version performs a full cut (D05-01)

- **Timestamp**: 2026-10-19
- **Action**: Made a bare re-run of `xpfd upgrade` (and `--rolling`) when the
  staged version is already live and committed an idempotent no-op, refused
  different-bytes same-version re-runs with re-version guidance only, and
  hardened the commit stamp and VERIFY-failure cleanup so a same-version
  attempt can no longer corrupt rollback history or delete the live snapshot.
- **File(s)**: `pkg/upgrade/cutover.go`, `pkg/upgrade/rolling.go`,
  `pkg/upgrade/commit_stamp.go`,
  `pkg/upgrade/same_version_rerun_15186_test.go` (new),
  `pkg/upgrade/postinst_status_lv_12143_test.go`,
  `docs/in-place-upgrade.md`, `docs/log/15186.md`

## Mechanism (verified at base 25557e91bb)

`Runner.Run` INIT had no no-op for `stagedVer == prev` (live `current`): the
only same-version check refused solely when `existingGen != srcGen`. A bare
re-run therefore persisted a journal with `PreviousVersion == TargetVersion`,
took a PREFLIGHT snapshot replacing `.<ver>.dbsnap` with the current DB,
stopped/restarted xpfd, and at COMMIT stamped
`{version:<ver>, predecessor:<ver>}` — which `readCommittedStamp` rejects
(`Predecessor == ver`), so rollback to the real predecessor fell back to
mtime and could refuse. On VERIFY failure `cleanupFailedVerifyCopy` removed
`.<ver>.dbsnap` at its tail whenever no predecessor backup existed, while the
error claimed the live dataplane was untouched. The neighbouring refusal
advised `dpkg-reconfigure xpf` to realign, but that always mints a new
generation, so it was refused again every time. `--rolling` additionally ran
`ForceSecondary` before the inner cut.

## Fix

- `cutover.go` INIT: when `stagedVer == prev` and the live dir exists,
  require `.srcgen` equality with the pinned generation, a valid committed
  stamp, and byte-identical managed binaries (`mismatchedManagedBinary`).
  Then log `already at <ver>; nothing to do` and return before any journal
  or snapshot write and without STOP/START. Otherwise refuse
  pre-PREFLIGHT with re-version guidance only (`re-stage under a DISTINCT
  version tag`); a read error on the stamp/generation also refuses.
  Carve-out: a sanctioned first-cut retry (`AllowNoRollbackFirstCut` with a
  predecessor-less committed stamp and same generation) falls through to a
  real fresh cut, preserving `TestFlipFailure_FirstCutRestartsDaemon`.
  The no-op deliberately does NOT `recordCommittedCut`: it health-confirmed
  nothing and must not mint evidence that clears deferred status (#12143).
- `rolling.go`: `alreadyAtStagedVersion()` applies the same decision in
  `runRollingWith` before `ForceSecondary` (and before peer-takeover
  readiness); an in-flight journal is never treated as a no-op so resume
  still goes through the inner `Run`.
- `commit_stamp.go`: `stampCommittedVersion` never writes
  `Predecessor == Version` (omits it instead) — defence in depth.
- `cutover.go` `cleanupFailedVerifyCopy`: the tail dbsnap removal is now
  guarded by `ver != cur && ver != j.PreviousVersion` in addition to the
  existing predecessor-backup guard, so a VERIFY failure never deletes the
  live version's (or rollback target's) snapshot.
- Removed the `dpkg-reconfigure xpf` realign advice from both refusal sites
  in `cutover.go` (INIT and the `copyStaged` backstop) and from
  `docs/in-place-upgrade.md`; other legitimate `dpkg-reconfigure` mentions
  (publish recovery, unreadable-marker recovery) are unchanged.
- `postinst_status_lv_12143_test.go`: `TestPreflipFailedRunInvalidatesEarlierEvidence12143`
  now stages a new 5.0.0 for its verify-rejected run — re-running the
  already-live 4.0.0 is by design a no-op now, so the test's premise
  (a verify-rejected cut) requires a not-yet-live target. Its assertions
  (error, current stays 4.0.0, stale evidence does not clear) are unchanged.

## Risk

Only the `stagedVer == prev` INIT/rolling decision point, the commit-stamp
writer's self-predecessor case, and the VERIFY-cleanup snapshot guard
change. Normal cuts to a different version, resume of in-flight journals,
committed-predecessor re-staging (#14720/#12177), and first-cut sanction
paths are untouched except that a sanctioned first-cut retry explicitly
falls through. A legacy same-version live dir with a committed stamp but no
`.srcgen` under a pinned generation now refuses pre-PREFLIGHT (fail closed)
instead of proceeding to a same-version cut — re-versioning is the remedy.
