# #18846 — G58: NFQUEUE M2 sender buffer

- **Timestamp**: 2026-11-05 (`wt-18846g58`, base `3964e0ced7f2893c5c45005002726c10c3f76c5c`)
- **Files**: `pkg/nfqueue/harness_test.go`, `pkg/nfqueue/measure_memory_test.go`, `pkg/nfqueue/nfqueue.go`, `docs/log/18846.md`.

## Why

M2 holds 4096 unverdicted datagrams, whose queued skbs remain charged to the UDP sender until verdict. In the fresh network namespace, the default `SO_SNDBUF` stalls at datagram 141 before the memory assertions run. The production NFQUEUE fd's own buffers are unrelated.

## What

- Add a dedicated M2 sender that requests `min(4194304, net.core.wmem_max)` through `net.Dialer.Control` and `UDPConn.SetWriteBuffer`, then reads back and verifies effective `SO_SNDBUF`. Failure to read/parse `wmem_max` or set/read back the option is fatal; only a successful request/read-back with effective `SO_SNDBUF` below the tested 8388608-byte floor skips before traffic.
- Route only `TestMeasureMemory9506` through that sender. The `openTestSender` function stays unchanged for M1/M3, and all packet counts and measurement assertions remain unchanged.
- Document sender-side skb charging and the M2 buffer requirement in the package comment. No production behavior changed.

## Validation

Go version: `go version go1.26.9 linux/amd64`.

- Base RED, using `PATH=/usr/lib/go-1.26/bin:$PATH GOCACHE=/var/worktrees/.cache/go-build TMPDIR=/var/worktrees/.cache/tmpdir` with the sanctioned `scripts/testguard-run.sh` invocation: child output failed at `M2 cycle=1 send=141` with UDP `i/o timeout`, before the assertions.
- GREEN M2 with the same environment and guard: `go test ./pkg/nfqueue -run '^TestMeasureMemory9506$' -count=1 -v -timeout 5m`; child reported effective `SO_SNDBUF=8388608`, `wmem_max=4194304`, passed all three 4096-packet hold/drain cycles, and completed the 8448-send over-cap/recovery check (`held=8192`, `dropped_before_receive=256`).
- M1/M3 targeted with the guarded `^(TestMeasureStages9506|TestMeasureTeardown9506)$` selection: both passed.
- Plain-sender mutant (M2 routed through `openTestSender`) with the guarded M2 command: RED again at `send=141` with UDP `i/o timeout`; mutant was reverted.
- Full module after restoration: `PATH=/usr/lib/go-1.26/bin:$PATH GOCACHE=/var/worktrees/.cache/go-build TMPDIR=/var/worktrees/.cache/tmpdir bash ./scripts/testguard-run.sh go test ./pkg/nfqueue -count=1 -timeout=20m` passed (`ok github.com/psaab/xpf/pkg/nfqueue 9.723s`).
- After the read-failure classification change, the guarded M2 test again passed with effective `SO_SNDBUF=8388608`, all three 4096-packet cycles and 8448-send over-cap/recovery phase; the guarded M1/M3 selection passed.
- `make go-skip-census` exited 2 at this head: 676 total vs floor 612; priv-absent 139/122, priv-present 18/18, other 518/471, unparsed 1/1. The parent-verified unmodified-master count is 675 total (139 priv-absent, 517 other) against the prior 611/122/470 floors. The floor change banks only G58's +1 total/+1 other; pre-existing drift remains (+64 total, +17 priv-absent, +47 other).

## Risk

Test-harness behavior changes; the package source change is documentation only. M1 and M3 retain their original sender conditions. M2 skips only when a successfully requested/read-back effective buffer is below the tested floor; a missing or unreadable `wmem_max` remains a test failure.
