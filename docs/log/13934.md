# Issue #13934: Preserve L4 checksums on tunnel-egress fragments

- **Issue:** The copy builder's forced tunnel-egress L4 checksum recompute ran on offset-zero IPv4/IPv6 fragments because its guard only recognized non-first fragments. Recomputing from a first fragment, whose checksum covers the complete transport datagram, overwrote the sender's checksum with one computed over only the fragment; the reassembled TCP/UDP datagram then failed checksum validation.
- **Change:** Skip full inner L4 recomputation for any IP fragment in both IPv4 and IPv6 copy-build arms, using the existing `ipv4_is_any_fragment` / `ipv6_is_any_fragment` predicates. Keep the existing unfragmented forced-recompute behavior. Add fail-on-revert IPv4 and IPv6 first-fragment tests with checksums seeded from complete datagrams, an unfragmented recompute control, and retain non-first-fragment coverage.
- **Validation:** On pristine guard logic, the new IPv4 and IPv6 first-fragment cells failed because the builder rewrote their checksums (2 failed, 2 control tests passed). After the fix, the complete `tests_fragment_term_extra` module passed (35 tests). The full crate suite ran 8,160 tests and exited 101 with three unrelated failures: `afxdp::pkt_len_fixture_drift_6883_tests::fixture_pkt_len_is_the_full_frame_length_6883`, `afxdp::worker::loop_body::expiry_shared_retire_10419_tests::worker_loop_orders_expiry_teardown_before_poll_10419`, and `protocol::cos::cos_literal_guard_7689::additive_wire_exhaustive_literals_only_ever_decrease_7689`. The change compiled successfully as part of both test runs.
- **Risk:** Fragmented packets bypass this forced recompute; their L4 checksums are preserved as received, as required for fragmented datagrams. Unfragmented tunnel egress remains unchanged.
