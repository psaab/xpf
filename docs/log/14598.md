# Issue #14598: DHCPv6 delegated prefixes outlive their own valid lifetime

## Why

A delegated prefix was retained and re-advertised on the lease
(IA_NA) clock, not its own. Three stacked defects: the lease deadline
was keyed to the IA_NA valid lifetime (PD-only mode used only
`prefixes[0]`), `DelegatedPrefixesForRA` applied no expiry filter and
`buildRAConfigs` copied lifetimes verbatim, and a non-Success IA_PD
(e.g. NoPrefixAvail) on renew was treated as silence so the prior PD
was retained indefinitely. LAN hosts kept SLAAC addresses from a
prefix the ISP had reclaimed (RFC 8415 §6.3, §18.2.10.1; RFC 9096
L-15).

## What

- `pkg/dhcp/dhcp.go`: `DelegatedPrefix.ExpiresAt/Expired/
  RemainingLifetimes` (decayed remaining lifetimes, granted pref 0
  preserved, infinite sentinel untouched); `DelegatedPrefixes()` and
  `DelegatedPrefixesForRA()` prune expired PDs (scheduling a
  recompile) and `DelegatedPrefixesForRA` returns decayed lifetimes
  rebased to now.
- `pkg/dhcp/ra_state.go` + `dhcpv6.go`: the T1/T2 waits wake at the
  earliest PD expiry (`waitForIPv6TimerOrRAWithPD`), prune, and loop
  without abandoning a still-live IA_NA lease; PD-only lease deadline
  is the shortest delegated valid lifetime.
- `pkg/dhcp/dhcpv6.go`: `extractDelegatedPrefixes` returns `pdRefused`
  for a non-Success IA_PD; run-loop commit sites clear the held set
  instead of retaining it. Stray IAPREFIX under a refused IA is still
  ignored (#10858); matcher authentication is unchanged.
- `pkg/dhcp/commit.go`: retained (omitted) prefixes whose own valid
  lifetime elapsed are dropped in `reconcileDelegatedPDs`.
- `pkg/daemon/daemon_ra.go`: `buildRAConfigs` advertises decayed
  remaining lifetimes; fully-decayed preferred becomes explicit 0.
  NOT changed: `pkg/ra` sender and its 0=default sentinel (#14606 owns
  the deprecated-pref-0 wire distinction); IA_NA `LeaseTime` is not
  shortened by PD lifetimes when IA_NA is present.

## Validation

- RED on origin/master: `pkg/daemon` decay test failed with
  `advertised ValidLifetime = 100, want (0,40]`; `pkg/dhcp` new tests
  failed to build (no per-prefix expiry API).
- GREEN: `go test ./pkg/dhcp/ -count=1` passes (incl. -race PD-expiry
  subset); `TestBuildRAConfigs*` daemon tests pass; REST/gRPC/CLI
  DHCP consumer tests pass; `go vet ./pkg/dhcp/ ./pkg/daemon/`
  clean; gofmt clean on touched files. Full `pkg/daemon` suite was
  not run to completion (300s timeout in this lane, no failures
  observed in the RA-scoped runs).
- New tests: `pd_lifetime_14598_test.go` (per-prefix expiry with
  IA_NA 1h / PD 1s, decay at 60%, NoPrefixAvail withdrawal, run-loop
  prune before lease expiry) and `ra_pd_decay_14598_test.go`
  (60% → ≤40% advertised, fresh control, expired control).

## Risk

Seeded/test prefixes with zero `Obtained`/`ValidLifetime` keep the
historical no-clock behaviour so existing fixtures do not silently
drop. The RA sender still maps a 0 RAPrefix lifetime to its default;
a delegated prefix whose preferred lifetime fully decays is
advertised with `PreferredLife=0` through that same sentinel —
#14606 tracks making the delegated deprecated case explicit on the
wire.
