# Issue #14161: incarnation-scoped capability provenance

- **Timestamp**: 2026-10-16
  - **Action**: `applyPeerIncarnationSwitchLocked` (the boot-ID switch) restored
    only the priming connection's snapshot version, leaving the retired
    incarnation's `peerCapabilityFlags` and `peerSessionSyncWire` in the
    globals. A new boot whose priming connection sent no interpretable
    capability frame therefore inherited the old boot's positive bits:
    `InstallTableIdentityCapable()` released stamped installs to a peer
    that never advertised the decoder, and the wire version read as the
    dead peer's. Fixed by recording the full advertised set
    (snapshot, flags, wire) per connection in `authConn` and restoring
    exactly that set — zeros when the priming connection never
    advertised — in the switch, alongside the scoped-delete suppression
    latch reset the install/disconnect clears already perform. No
    outbound gate was weakened: unlearned stays default-deny for
    installs and deferred for deletes, unknown wire stays permitted.
  - **File(s)**: `pkg/cluster/sync_auth.go`, `pkg/cluster/sync_conn.go`,
    `pkg/cluster/sync_conn_read.go`,
    `pkg/cluster/incarnation_capability_provenance_14161_test.go`
