# Issue #15196 — config: fix cohort — validator-trims / consumer-reads-raw (A02-01)

- **Issue:** A padded GRE/IPIP `tunnel source`/`destination` passes
  ValidateIPAddress (which trims) and commits clean, but the tunnel
  manager parses the raw string and never creates the tunnel.
  Lane branch: `fix/15196-campaign` off `origin/master` `29a1c46b53`.
- **Anchors (re-anchored at current master):**
  `pkg/config/schema_validators_network.go` `ValidateIPAddress`,
  `pkg/config/schema_interfaces.go` `tunnelSchemaChildren()` source/
  destination leaves, `pkg/routing/tunnel.go:810-815`
  `applyKernelTunnelLocked`, `pkg/config/compiler_validate_tunnel_family.go:111-115`
  (returns nil on unparseable endpoint — by design, not changed).

## Defect (present at base)

`ValidateIPAddress` does `trimmed := strings.TrimSpace(raw)` then
`net.ParseIP(trimmed)`. Padding is authorable through ordinary ingress
(quoted strings preserve their contents verbatim, e.g.
`source " 192.0.2.1 "` — same class as #9820/#14377). The consumers read
the RAW string:

- `pkg/routing/tunnel.go` `applyKernelTunnelLocked`:
  `net.ParseIP(tc.Source)` / `net.ParseIP(tc.Destination)`; on nil it
  logs `invalid tunnel endpoints` and returns nil — no tunnel is created.
- `pkg/dataplane/userspace/tunnels.go`: same raw `net.ParseIP` family/
  endpoint handling; an unparseable endpoint never installs.

So `set interfaces gr-0/0/0 tunnel source " 192.0.2.1 "` commits GREEN
(SchemaValidate nil, and therefore `configstore.CheckText` nil) while
the tunnel is silently absent.

## What

- New `ValidateTunnelEndpoint` in `schema_validators_network.go`:
  refuses `raw != strings.TrimSpace(raw)` with a message naming the
  padded value (`leading or trailing whitespace is not allowed; use a
  bare IP address`), then delegates to `ValidateIPAddress`. Mirrors
  `ValidateBGPLocalAddress` (#14377).
- Wired into both tunnel leaves (`source`, `destination`) in
  `tunnelSchemaChildren()` (`schema_interfaces.go`), which is shared by
  the interface-level and unit-level tunnel stanzas — one wiring covers
  both positions.
- NOT changed: generic `ValidateIPAddress` (keeps trimmed leniency for
  its many non-tunnel leaves — DDNS, syslog, DHCP, DNS, etc.; tightening
  them is out of scope, exactly as #14377 scoped to BGP leaves),
  `compiler_validate_tunnel_family.go` (its nil-on-unparseable is
  correct: a malformed literal is a schema concern, not a family
  mismatch), `pkg/routing/tunnel.go`, any Rust/dataplane code.
- Strict path (SchemaValidate / CompileConfig via compileTreeStrict /
  CheckText) now rejects; the tolerant load/peer-sync path is unchanged
  (#1960 — SchemaValidate is not run there, and the runtime warn/skip
  behaviour for a legacy padded value is preserved).

## Risk

- Compatibility tightening only: a previously-committed padded spelling
  must now be re-entered bare. Such configs were already non-functional
  (tunnel silently absent), so no working deployment changes behaviour;
  strict commit now tells the operator, and lenient load still boots
  (#1960) with the existing runtime warn.
- No hot-path cost: one `TrimSpace` comparison on the commit path.
