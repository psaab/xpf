# #12528 — reject fused firewall `then` tails

- **Issue**: #12528 — `is-fragment` and `flexible-match-range` swallow fused `then` actions.
- **Branch**: `fix/12528-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12528`

## Why

The firewall compiler treats `is-fragment` as a presence-only flag and reads `flexible-match-range` only through its named `range` children. A missing statement separator can therefore leave `then discard` or `then reject` on a node the compiler does not read. The terminal action stays empty, so the term falls through rather than enforcing the requested action. The generic #8437 fused-sibling gate does not catch this case because `then` is a term-level sibling of the `from` leaf, not a child of `from`.

The syntax tree is not uniform across input paths: fused tokens can be additional `Keys` on a leaf/container, or an unexpected child node. Nameless hierarchical `term` forms also have their own tree shape. The gate therefore checks both token tails and child nodes and traverses the firewall AST independently of term-name lowering.

## What

- Added a firewall AST gate before strict schema validation and strict/tolerant compiler pre-walk. It rejects unconsumed tokens/children following `is-fragment`, and rejects `then` content in `flexible-match-range` / named `range` bodies. Strict paths return the error; the tolerant compiler keeps its legacy load behavior but records a warning.
- Added regressions for flat-set `discard`/`reject`, named packed and compact hierarchical forms, nested and child-node representations, nameless term shapes, inet/inet6/any, the `is-fragment foo` boundary, and flexible-range flat-set, hierarchical and nameless shapes. Positive controls pin valid flag/range forms, an ordinary protocol match, and their discard actions.
- Added `FormatSetForLoadMerge` replay and configstore `LoadSet` / `LoadOverride` / `LoadMerge` + `CommitCheck` regressions.
