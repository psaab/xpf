# #17095 — HA rolling/kernel-drain safety predicates scraped operator text (R4-Q46-04)

- **Timestamp**: 2026-10-27
  - **Action**: Replaced the ShowText scrape behind every HA rolling /
    kernel-drain safety predicate with a typed `GetClusterHAState` RPC.

    Before this change `pkg/upgrade/cluster_cli.go` derived PeerAlive,
    SyncEstablished, bulk-primed, drain-complete, HA/session-wire
    compatibility, peer protocol versions, takeover-ready, configured
    RGs/weights and rejoin from `show chassis cluster
    information|status` text (22 parse/verdict functions, 18
    strings.Split/Fields sites). A present-but-garbled value had
    already collapsed to 0 and permitted a drain (#14991); any
    operator-facing rewording could abort or permit a roll, and the
    renderer carried no machine-contract marker.

    Fix:
    - `proto/xpf/v1/xpf.proto`: `GetClusterHAState` RPC +
      `GetClusterHAStateResponse` / `ClusterRGState` / `RGNodeState`
      appended at end-of-file. Presence discipline mirrors
      ZoneCounterAvailability (#6895): `optional` HA/wire versions, a
      wire-present flag keeping the #7990 absent / unknown / version
      distinction, UNKNOWN=0 node states. Stubs regenerated with the
      pinned toolchain (`make proto`, `make proto-check`).
    - `pkg/cluster/ha_state.go`: `Manager.HAState()` / `HAState` /
      `HARGState` — the typed snapshot (peer/peer-group state,
      sync-established, bulk-primed, HA + wire versions with nil =
      absent, per-RG local/peer state, takeover readiness folding the
      hold window, weights, failover counts). Text renderers keep
      their operator formatting over the same manager fields; a parity
      test pins typed vs rendered agreement on every gate input.
    - `pkg/grpcapi/server_cluster_ha_state.go`: `GetClusterHAState`
      handler + `HAStateToProto`; a cluster-less node is
      FailedPrecondition, never a fabricated empty state.
    - `pkg/upgrade/cluster_cli.go`: `grpcCluster` now reads one typed
      state per predicate via `haState()`; all verdicts
      (drain-complete per-RG pairing, HA equality, wire verdict,
      takeover-ready, rejoin weights, RG enumeration) are single
      implementations over the typed response. No `strings.Split`
      remains in this file.
    - `pkg/upgrade/cluster_cli_text_fallback.go`: the ONLY remaining
      text scrape, confined to the one-release fallback taken solely
      on `codes.Unimplemented` (a pre-#17095 daemon); it converts both
      renders into the same typed response so verdicts are never
      duplicated. Non-Unimplemented errors refuse, never fall back.
      File header marks it for deletion after the window.

    Named cells (hermetic, class U):
    - `pkg/upgrade/cluster_ha_state_17095_test.go`:
      `TestHAStatePresenceDistinguishesAbsentZeroMalformed17095`

      unrepresentable), `TestDrainCompleteFromState17095`,
      `TestRejoinAndTakeoverFromState17095`,
      `TestHAStateFallbackOnlyOnUnimplemented17095` (typed used as-is,

    - `pkg/cluster/status_ha_state_17095_test.go`:
      `TestHAStateMatchesTextRender17095` (typed/render parity,
      presence flips with peer).
    - `pkg/grpcapi/server_cluster_ha_state_17095_test.go`:
      `TestGetClusterHAState17095` (presence carried, cluster-less

    - Adjacent named sets stay green: the fallback-era parser/verdict
      cells (#7990 absent-line, #14991 malformed, #10261 bulk-primed,
