# #18700 — Factory reset skipped the production helper stop

## Fix

- **Cause**: The reset path type-asserts its published runtime dataplane to
  `helperResetStopper`. Production publishes a `*LegacyDataPlaneAdapter`, which
  previously did not forward `StopHelperForReset` to its `Manager`.
- **Change**: Added a nil-safe adapter forwarder using `managerOrErr`, and a
  compile-time interface pin for the adapter beside the existing `Manager` pin.
- **Regression coverage**: `TestLegacyDataPlaneAdapterStopHelperForReset18700`
  starts a supervised child, stops it through the adapter, verifies it was
  reaped without scheduling a restart, covers a nil adapter, and calls the stop
  again to pin the Manager's idempotent/no-error behavior.
- **RED/GREEN**: With the adapter forwarder removed while retaining the new pin,
  the daemon package failed to compile because `*LegacyDataPlaneAdapter` did
  not implement `helperResetStopper` (missing `StopHelperForReset`). After
  restoring the forwarder, the focused daemon reset suite passed.
