## What changed

Single-source per operation; the production entry keeps the short name and
takes every context explicitly — the inverse of the old shape, where the
short name silently supplied `None`:

- `wg.rs`: `wg_encap_frame(.., dynamic_neighbors) -> (Vec, WgEncapCommit)`,
  `outer_physical_egress_{ifindex,resolution,mtu}(.., dynamic_neighbors)`,
  `wg_peer_outer_dst(.., table)`,
  `wg_selected_peer_outer` / `wg_transit_egress_physical_egress_ifindex`
  (all `.., dynamic_neighbors`). The redundant `wg_endpoint_physical_outer_mtu`
  helper was deleted; PTB uses the combined selected-peer family/MTU helper.
  `wg_encapped_size` overloads and `outer_physical_egress_ifindex` remain
  `#[cfg(test)]` test helpers whose cells pin the underlying verdicts.
- `frame/mod.rs`: `build_forwarded_frame_from_frame(.., dynamic_neighbors)`
  returns `(PooledBuffer, Option<WgEncapCommit>)`;
  `build_nat64_forwarded_frames(.., dynamic_neighbors)` returns the commit
  pairs. The single-frame NAT64 convenience is `#[cfg(test)]` (test-only;
  production uses the frames entry at tx/dispatch). Callers that discarded
  the commit now do so visibly (`.map(|(frame, _)| frame)`).
- `tcp_segmentation.rs`: one
  `segment_forwarded_tcp_frames_from_frame(.., dynamic_neighbors)` returning
  commit pairs; tx/dispatch and neighbor_dispatch already thread theirs.
- `addr_class.rs`: `dest_is_directed_broadcast` / `src_is_directed_broadcast`
  / `v4_addr_is_directed_broadcast` each take `table: Option<&str>`
  explicitly; icmp.rs / icmp_ptb.rs pass their `icmp_error_table_for_meta`
  result (the #14654 threading, unchanged).
- Same residue in the PTB helper the frame change touches:
  `icmp_ptb::post_transform_inner_mtu(.., dynamic_neighbors)` and its
  private `tunnel_inner_mtu(.., dynamic_neighbors)` single-sourced;
  ~30 test callers pass `None` explicitly.
- Re-exports pruned to surviving production names (`frame/mod.rs`,
  `frame/inspect.rs`); test-only parser/checksum/header/TCP imports are
  `#[cfg(test)]`, and unused aliases were removed. `TxVlanTag::from_parts` /
  `eth_header_len` are also `#[cfg(test)]` (2 of the 23 frame/ dead_code rows).
- Docs: frame/README wg.rs row and wg.rs encap comment name the
  production SSOTs `outer_physical_egress_resolution` and
  `wg_selected_peer_outer` (PTB's peer-specific physical route MTU),
  drop the pre-#13978 "`neighbor_mac` falls back to
  `decision.resolution.neighbor_mac`" / "lookup passes `None` for dynamic
  neighbors" text (#13978 removed that fallback; #14657 threads the map and
  fails closed). `wg_selected_peer_outer` is the PTB SSOT and single-sources
  peer selection plus physical route MTU.

No `BuildCtx` struct: each operation takes exactly the context it reads
(dynamic map / peer table / commit pair) — a shared 3-field struct would
force unrelated contexts (e.g. a WG table snapshot) onto callers that
never read them.

## Risk

Signature churn at tx/dispatch, neighbor_dispatch, forward_request and
icmp_ptb call sites is mechanical (same values threaded, `None` made
explicit in tests). Compile is the guard: any missed caller fails the
build; the #14657 cells fail closed visibly if the dynamic map stops
being threaded (they assert `None` → drop, map → build).
The pre-#18340 PTB mismatch was fixed by master commit `b8ffcdca37`
(#18340), which corrected the expected pin to 1340. The named PTB cell
passes on the rebased branch; this refactor does not leave that baseline
mismatch open.
