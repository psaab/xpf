  - **Re-measured first, because the last two audit-tier issues had moved.**
    #6870's premise had gone stale in the shrinking direction; this one moved
    the other way. Filed at 2060; measured **2597** at master `4328cee40`, i.e.
    +537 since filing and 30% past the tier. The issue's mitigating detail

  - **The seam is an ERROR CONTRACT, not a line count**, which is the property
    that decides whether a split holds. Every no-return handler (hostname,
    timezone, NTP, kernel tuning, syslog, aggregator) deliberately swallows its
    failures; every error-returning reconciler (login, sudoers, sshd, root auth)
    is a `hostAuthCloseoutOwners` member whose failures are load-bearing. #5874
    exists because five of those had their failures DISCARDED. Mixing the two
    categories in one file is what makes the contract invisible when someone
    adds the next handler.
  - **The codebase had already drawn this seam.** `hostAuthOwner` /
    `hostAuthCloseoutOwners` name the cluster and `daemon_apply_hostauth.go`
    already orchestrates it; only the implementations were left in
    `daemon_system.go`. That is why this is completing a seam rather than
    inventing one to hit a number — the #6870 lesson was that `a19ee7d4e` held
    because it argued from startup-ordering invisibility, not from LOC.
  - **The boundary was contiguous**: every error-returning apply sits between
    `applySystemLogin` and `applyRootAuth`. Nothing had to be reordered.
    2597 -> 1641, new file 1005.
