# #12846 — admit WireGuard outer packets to lifeline-shared addresses

- **Timestamp**: 2026-10-13 (`fix/12846-d3-12-wireguard-ingress-deny`)

## Why

Empty-admit zone views with a lifeline-shared address intentionally move that
address out of `V4Addrs` / `V6Addrs` and into `IngressDenyV4` / `IngressDenyV6`.
Those withheld addresses still participate in ingress-zone policy judgement,
so the empty-admit zone's catch-all drop applies to packets arriving there.
WireGuard listener ownership and its exact destination list previously
considered only `V4Addrs` / `V6Addrs`. A listener whose outer source was the
shared address therefore had no owner-zone port mapping or scoped accept, and
the ingress deny dropped its outer UDP handshake packets.

## What

- Include `IngressDenyV4` / `IngressDenyV6` when resolving the unique owner zone
  of configured WireGuard outer source addresses and when deriving the
  per-zone WG destination-address set.
- Keep the existing unique-owner rule: addresses claimed by more than one zone
  remain ambiguous and do not acquire a zone-scoped WireGuard accept. Unconfigured
  zones still gain no WG listener ports.
- Mirror the owner-address derivation in the netlink renderer and declare zone
  counters for any newly rendered WireGuard mismatch guard.
- Add v4/v6 owner-mapping, scoped-admission, ordering, no-listener, and
  cross-zone fail-closed regressions. Extend the netlink/text parity gate with
  an ingress-deny-only VRF address carrying a WireGuard listener port.

## Validation

- **Base / RED**: before the production fix,
  `go test ./pkg/daemon/ -run
  'TestWireGuard(SourceInIngressDenyResolvesOwner|IngressDenyAddressesAccepted|IngressDenyStaysFailClosed)12846'
  -count=1` failed because the text ruleset contained no WG accept for the
  `IngressDeny`-only destination.
- **Focused GREEN**: the same focused command passed after the change.
- **Full packages**: `go test ./pkg/daemon ./pkg/dataplane/userspace -count=1`
  passed (`pkg/daemon` 480.603s; `pkg/dataplane/userspace` 162.976s).
- **Text/netlink parity**: `go test ./pkg/daemon/ -run
  '^TestNftNetlinkParity$' -count=1 -v` passed. The host-inbound case covered
  the new VRF-scoped accept for an `IngressDeny`-only address and matched
  text-rendered and netlink-installed rules, including per-rule iifname scope.
- **Vet**: `go vet ./pkg/daemon ./pkg/dataplane/userspace` passed.
## Risk

There is no global port exception: unknown or ambiguous sources remain denied.
The selected port does not grant access to an unrelated zone or interface. The
lifeline interface itself remains outside the data-zone ingress scopes.
