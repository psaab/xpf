# frag_assoc census drift: production-caller assertions found 0 callers (#12941)

- **Issue**: #12941 — `cargo test --test frag_assoc_reverse_unreachable_9957`:
  `production_fragment_association_installs_keep_family_specific_reverse_info_9957`
  and `production_fragment_association_lookups_preserve_nat64_reverse_9957`
  assert 2 production callers each, found 0. Pre-existing on clean
  origin/master (confirmed twice during #12613 review; reconfirmed RED on the
  pristine wt-12941 worktree before this fix).
- **Cause (guard-side census drift, not a production defect)**: the guard froze
  the audited entrypoint names as `.frag_assoc.install(...)` /
  `.frag_assoc.lookup(...)`. #11359 (`ec59234a1`, "fragment-assoc: harden
  admission and session lifetime (#11058)") renamed the production entrypoints
  to `install_with_session` / `lookup_with_session`, leaving bare
  `install`/`lookup` as `#[cfg(test)]` wrappers
  (`userspace-dp/src/fragment_assoc/mod.rs:569/706`). The wiring the guard
  exists to pin is fully intact on master — exactly 2 installs
  (`afxdp/poll_descriptor/frag_assoc.rs:140` carrying the `nat64_reverse`
  third arg, `:250` passing `None`) and 2 lookups (`:183` bound as
  `let (decision, reverse)`, `:307` as `let (decision, _reverse)`) — but the
  frozen-name census matched none of them and demanded 2 of each.
- **Change** (`userspace-dp/tests/frag_assoc_reverse_unreachable_9957.rs`,
  test-only): the census now matches method FAMILIES — `install`/`lookup` plus
  any `_`-suffixed snake-case variant — via `in_method_family`
  (`method == family || method.starts_with(family + "_")`), and the parser
  (`method_after_receiver`) captures the called method name instead of
  comparing a frozen literal. `Site` records the method and the failure
  listings now show `file:line method` so the next drift is diagnosable from
  the panic alone. Same-prefix foreign identifiers (`installation`, `installed`)
  stay outside the census; a pinned parser test enforces that boundary. All
  FAIL-ON-REVERT assertions (caller count 2+2, all sites in
  `afxdp/poll_descriptor/frag_assoc.rs`, ordinary `None` third arg, NAT64
  `nat64_reverse` third arg, `let(decision,reverse)=` vs
  `let(decision,_reverse)=` bindings) are unchanged.
- **Why families and not the new frozen names**: re-freezing on
  `install_with_session`/`lookup_with_session` would leave the identical
  recurrence one parameter-growth rename away — the `_with_session` suffix is
  itself the residue of #11359 adding parameters. The family (admission verb /
  consult verb + `_` suffixes) is the stable identity of the audited boundary;
  every real revert direction still reds (see mutations below), while a pure
  rename no longer false-alarms.
- **Validation**:
  - RED on pristine origin/master (worktree wt-12941 before the change):
    2 failures, "found 0".
  - GREEN post-fix: 6/6 pass (`cargo test --test
    frag_assoc_reverse_unreachable_9957`), including 2 new/extended parser
    fixtures (`install_with_session` multiline receiver, bare `install` alias,
    same-prefix exclusion, `lookup_with_session` binding tie).
  - Mutation FAIL-ON-REVERT checks (each applied, run, reverted):
    (A) ordinary install third arg `None` → `Option::None` → RED
    "must retain reverse=None"; (B) lookup binding `_reverse` → `reverse`
    → RED "must continue discarding reverse info"; (C) an extra
    `lookup_with_session` caller added in `flowless_verdict.rs` → RED
    "caller set changed" listing the off-audit site; (D) full-tree rename
    `install_with_session`/`lookup_with_session` → `install_v2`/`lookup_v2`
    → all 6 GREEN (the #11359-class event that broke master no longer
    empties the census).
  - `rustfmt --edition 2024 --check` clean on the file (after restoring the
    two untouched helpers to their committed formatting; local rustfmt 1.9.0
    disagrees with the committed style on those lines, no repo fmt pin/gate
    exists); `cargo clippy --test frag_assoc_reverse_unreachable_9957` reports
    no lints in the file.
- **Risk**: low, test-only. The census is a source guard over production text,
  not runtime behavior; the widened matcher could over-count a future
  `install_<something>`/`lookup_<something>` helper added in production —
  which reds loudly (count assertion) and forces a deliberate audit, the same
  contract the guard already documents for new callers. A rename to a
  different verb entirely (e.g. `admit`) would still empty the census and RED
  (false alarm, not a silent pass) — inherent to name-based source guards.
