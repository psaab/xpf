# Issue #13767 — report retry-ring overflow from delta flush

## Why

When `flush_session_deltas` failed to acquire a tuple-gate permit, it treated
any available retry `SessionTable` as proof that the remaining delta suffix was
preserved. If that ring was full, `requeue_deltas_front` dropped the deltas,
while the flush return value suppressed `LossResync` and the worker-lossless
wedge signal.

## What

`requeue_deltas_front` now reports whether it retained every delta and
preserves the earliest prefix when only part of the drained batch fits. The
tuple-gate contention path uses the result when deciding whether the event
stream is out of sync. Full- and near-full-ring contention regressions verify
the return value, worker wedge, overflow counter/latch, and FIFO ordering of
retained deltas. Fully-retained requeue remains in sync.

## Risk

Requeue overflow still arms the `SessionTable` loss latch; this change also
makes `flush_session_deltas`'s return value and worker-lossless latch accurately
report that the suffix was not fully preserved.
