# #16673: LLDP binary Chassis/Port ID subtypes decoded canonically and keyed by raw MSAP

- **Timestamp**: 2026-10-25
- **Action**: `ParseTLVs` (`pkg/lldp/lldp.go`) now decodes Chassis/Port ID
  TLVs per subtype instead of storing every non-MAC-chassis value as
  lossy-sanitized text with the subtype byte discarded. Port subtype 3 /
  chassis subtype 4 (MAC) render colon-separated
  (`52:54:00:aa:bb:01`), chassis subtype 5 / port subtype 4
  (network address) render the IP literal for IANA family 1/2 at exact
  length and `iana-<family>:<hex>` otherwise, printable text keeps its
  sanitized verbatim form, and any other non-printable identifier
  renders lowercase hex — no byte is folded by control-to-space or
  U+FFFD sanitization. `Neighbor` gains `ChassisSubtype`/`PortSubtype`
  beside the canonical strings, and `neighborKey` now carries the full
  MSAP — interface, chassis subtype + raw post-subtype bytes, port
  subtype + raw post-subtype bytes — so display-equal but byte-distinct
  identities cannot collide; the key never derives from the display
  strings. Subtype-truncated binary IDs (MAC body < 6 bytes,
  network-address body < family+1 byte) are rejected under the existing
  #2551 mandatory-TLV gating. Hand-built neighbours keep keying on their
  declared subtype + display/raw identity, so existing learning,
  refresh, LRU-cap, and TTL=0 withdrawal call sites are unchanged in
  behaviour. One deliberate display change: a text-subtype identifier
  carrying control bytes (previously sanitized text, e.g. `host A `)
  now renders as hex of its raw bytes; `TestParseTLVs_SanitizesControlChars`
  was updated to pin the hex form while still asserting no control rune
  survives.
- **File(s)**: `pkg/lldp/lldp.go` (`decodeChassisID`/`decodePortID`,
  `canonicalNetworkAddr`, `canonicalTextOrHex`, raw+subtype
  `neighborKey`), `pkg/lldp/binary_subtype_16673_test.go` (acceptance:
  canonical MAC/IP display, distinct neighbours, scoped TTL=0
  withdrawal, subtype-in-key, raw-bytes-over-display, hex fallback,
  truncation), `pkg/lldp/lldp_test.go` (constant rename
  `portSubtypeIfName`→`portSubtypeInterfaceName`, hex expectation),
  `pkg/lldp/neighbor_key_collision_7176_test.go` (learn/withdraw now use
  one production-constructed key), `pkg/lldp/README.md`,
  `debian/changelog`, `docs/log/16673.md`.
- **Validation**: `go test ./pkg/lldp/ -count=1` PASS (full package,
  including the six new `16673` tests and the #7176/#5123/#10898 cells);
  `go test ./pkg/cli/ ./pkg/grpcapi/ -run LLDP -count=1` PASS;
  `go vet ./pkg/lldp/` clean; gofmt clean. RED evidence: the new tests
  adapted only to compile against the pre-fix API (literal subtype
  bytes) fail on the base `ParseTLVs` with the reported symptom —
  `PortID = "RT �� "`, want `52:54:00:aa:bb:01`; two MAC-port neighbours
  share one key; same text under two subtypes shares one key. Long
  canonical displays still pass through the renderers'
  `QuoteFieldForDisplay` width caps unchanged.
- **Residual**: None for the identity/display defect. The renderers keep
  their 20/16-char Chassis/Port column caps, so a full hex identifier
  longer than the column truncates in `show lldp neighbors` exactly as
  long text names did before; the stored value and key are byte-exact.
