# #12909 — qualified-next-hop `<ifname>` interface promotion + shared-bind selector union (D10-08)

- **Timestamp**: 2026-10-14
- **Action**: a qualified-next-hop whose gateway is a bare interface name
  (`qualified-next-hop st0.0`, inline, braced, and flat-set forms) compiled to
  `NextHopEntry{Address: "st0.0"}` — the tunnel name parked in the ADDRESS
  slot with no interface. FRR's operand belt discards a non-IP `nh.Address`
  (`validFRRNextHopAddress`, `pkg/frr/config_render.go`) instead of rendering
  an interface route; the userspace snapshot carried the bare non-IP token
  `st0.0` the Rust FIB cannot parse (and a route whose only gateway looked
  bare-unresolvable was dropped outright by the #11317 row gate); and the
  #11422 route-vs-selector validator only inspects next-hops with an
  interface set, so the floating backup bypassed the XFRM blackhole gate
  entirely. A plain `next-hop st0.0` was already promoted to
  `{Interface: "st0.0"}` by `staticNextHopEntry` (#12036) — the qualified
  clause was the unnormalized twin. Separately, that #11422 validator
  required ONE single VPN to cover the whole routed destination, falsely
  rejecting aggregates split across complementary VPNs sharing a bind
  interface — a topology #11380 explicitly supports (shared `st0.X` with
  provably disjoint selectors).
- **Fix**:
  1. `pkg/config/compiler_routing.go` — the #12036 interface-only predicate
     is extracted to `interfaceOnlyNextHopValue` so the qualified path can
     share the plain path's exact definition (not a route keyword, no `@`,
     not an IP, plausible interface name).
  2. `pkg/config/compiler_static_qnh_merge_12308.go` — the promotion is
     applied in `finalizeQualifiedNextHops12308`, which closes the #12308
     merge window after EVERY source (both parse sites, later
     same-spelling blocks, later roots) has folded: each still-qualified
     entry whose `Interface` is empty and whose gateway satisfies
     `interfaceOnlyNextHopValue` becomes `{Interface: <ifname>}`.
     Promoting there — not at parse time — is load-bearing: the #12308 fold
     keeps keying on the authored gateway scalar (`Address`), so split
     statements for one interface gateway merge exactly as before, an
     authored `interface` modifier stays authoritative (a promoted gateway
     can never overwrite it in a fold — the #8436 duplicate-block census
     caught that variant), and two DISTINCT tunnel backups (`st0.0` vs
     `st0.1`) can never fold. The finalize dedupe then also collapses a
     bare `qualified-next-hop st0.0` into an identical plain
     `next-hop st0.0`, which previously survived as a dead Address-form
     duplicate.
  3. `pkg/config/compiler_validate_ipsec_route_ts_11422.go` — coverage is
     now judged on the UNION of rendered remote selector pairs across every
     VPN bound to the route's device (same XFRM if_id + ref ownership, the
     existing candidate filter). The rejection names every sharing VPN, so
     an operator sees `VPN "site-a", "site-b"` instead of an arbitrary first
     owner.
- **Fail-closed direction**: the promotion adds no acceptance anywhere. It
  moves an interface-valued backup from invisible (dropped by both planes,
  unseen by the selector gate) to installed AND validated: a promoted
  `st0.X` backup over a real VPN bind now enters the #11422 gate, so a
  destination outside the rendered remote-selector union is refused at
  strict commit and warned on the tolerant path (same doctrine as before —
  strict rejects, tolerant boots with a warning). The union fix widens
  acceptance only for shared-bind topologies #11380 already proves disjoint,
  and the outside-the-union rejection still fires (now naming all sharers).
  Non-secure-tunnel interface backups (`ge-*`, `reth*`) gain nothing and
  lose nothing: `XFRMIfNameAndID` still disqualifies them.

  backup); the tolerant path keeps them booting with a #11422 warning. All
  other shapes compile byte-identically.
