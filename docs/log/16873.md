# #16873 — NAT64 shadow detection must honour the earlier rule-set's source scope

- **Issue**: R3-B09-01. `nat64ShadowedRuleSets` keyed shadowing by
  /96 + zone/RI only and explicitly ignored `match source-address`, so
  a source-scoped earlier rule-set (e.g. `2001:db8:1::/64`) was treated
  as covering every source. A reachable same-/96 sibling got a false
  `UNREACHABLE … never translates and its source-pool is never used`
  warning on every commit (advice that would break NAT64 for sources
  outside the earlier prefix), and the sibling was dropped from the
  #5144 pool-overlap owner set, so two source-scoped rule-sets sharing
  one pool committed clean while the zone-scoped twin was refused.
  The runtime peer-ownership check then dropped colliding new flows.
- **Change** (`pkg/config/compiler_validate_strict_nat.go`):
  - `nat64EffectiveSourcePrefixes` resolves a rule-set's effective
    IPv6 source set (literals + statically resolvable address-book
    names, wildcard/`::/0` lowering mirrors the snapshot builder) and
    reports whether it is unconstrained and whether it is provably
    complete. Feed/dns/poisoned/empty/unparseable selectors are
    unprovable: they never prove coverage and are never proven covered
    except by an unconstrained earlier source (no UNREACHABLE claim on
    a guess, #8667).
  - `nat64ScopeCover` generalises the zone/RI test from key equality /
    unscoped-first to per-axis superset (an unscoped axis covers any
    value; a scoped earlier axis does not cover an unscoped later).
  - `nat64ShadowedRuleSets` now marks a later rule-set shadowed only
    when an earlier definitely-built rule-set with the same canonical
    /96 provably covers it on zone/RI **and** source (unconstrained,
    or every later prefix contained in an earlier prefix). Order stays
    config order; skipped earlier rule-sets still shadow nothing.
  - `natPoolOverlapOwners` gains the effective source set in the
    NAT64 owner key (`nat64OwnerSourceKey`, mirroring Rust's
    `Nat64ScopeKey` #16484), so two both-reachable same-/96 rule-sets
    over one pool are distinct owners and the #5144 gate refuses them
    exactly as it refuses the zone-scoped twin. Identical effective
    sets still collapse to one owner (the later is shadowed anyway).

## Review fold (Astra NOT-READY on 5f3e562925)

- **F1 — wildcard before poison**: `nat64EffectiveSourcePrefixes`
  returned proven-unconstrained at the first `::/0`/v6 wildcard without
  resolving the remaining names. The builder resolves every name first
  and poison wins over wildcard, so `any` beside a defined dns-name
  with no answers matches NOTHING in Rust. Fix: record the wildcard,
  resolve every literal and name (any unknown returns unprovable),
  and only then report unconstrained.
- **F2 — empty nested set**: `nat64StaticNamePrefixes` flattened via
  `expandAddressSetLeaves`, so an empty nested set contributed zero
  leaves silently and a surviving sibling leaf proved coverage. The
  runtime closure poisons the parent instead. Fix: new
  `nat64ResolveNameValues` mirrors `expandBookNameRecursive` poison
  semantics (undefined/colliding/tainted/empty/unknown-member/any
  unknown member ⇒ unprovable; visited member contributes nothing).
- **F3 — vacuous unit matrix**: the 15-row unit table compared
  `shadowed != tc.shadowB` with an empty body. Now `t.Fatalf` with
  actual/expected and both rule-sets' selectors.

## Re-review fold (Astra NOT-READY on 8389d22cac)

- **F1 — non-injective unknown owner key**: the unprovable fallback
  comma-joined raw literals+names, so one binding named `left,right`
  collided with two bindings `left`+`right` (and literal/name
  namespace moves collided), dropping a live owner from #5144. Fix:
  `nat64OwnerSourceKey` returns `ok=false` for unprovable sets and
  `natPoolOverlapOwners` retains such a rule-set as an independent
  owner, never deduped. Regression:
  `TestNAT64UnknownOwnerKeyNoCollision16873` (comma-name witness
  through the real compiler: strict #5144 reject, lenient warn, both
  owners, no UNREACHABLE; identical-binding control still rejects).
- **F2 — zoned literals**: Go `ParseAddr` accepts `2001:db8::1%eth0`
  and `PrefixFrom` strips the zone; Rust drops the token, so it
  enforces nothing. Fix: `addr.Zone() != ""` (literal and resolved
  name value, prefix and bare forms) ⇒ unprovable. Regression:
  `TestNAT64ZonedLiteralNoCoverage16873` (two-host witness via
  compiler + lenient owners, unzoned control shadows, zoned name
  value unit).
- **F3 — warm-cache DNS**: `UsableValues` returns the mutable DNS
  snapshot; a refresh can move it without re-running tail gates, so
  warm answers were permanent proofs. Fix: any `DNSName != ""` entry
  is unprovable in `nat64ResolveNameValues` at any cache state,
  including through nested sets. Regression:
  `TestNAT64WarmDNSNoProof16873` (warm `::1` answer, direct + nested:
  no shadow, both owners over shared pool; unconditional-earlier
  control still shadows a dns-scoped later). RED vs `8389d22cac`
  production: all three new tests FAIL pre-fold, PASS post-fold.

## Gate fold (Opus NOT-READY on 0e49adee7c)

- **Scoped-key injectivity**: `nat64PrefixOwnerKeyScoped` comma-joined
  the zone/RI sets — the same defect class as re-review F1, one axis
  over. A zone literally named `x,y` (comma is a legal ident char,
  lexer.go `isIdentChar`) collided with zones `{x, y}`, and the owner
  dedup dropped the second live rule-set (executed witness: strict
  compiled clean, owners = [a] only). Fix: new `encodeKeyElements`
  length-prefixes every element (`<len>:<bytes>;`), injective for
  arbitrary element content; applied to the zone/RI sets, the proven
  source-prefix list, and the pool-name component of the dedup key —
  the whole assembled key is now injective. Regression:
  `TestNAT64CommaZoneOwnerKeyNoCollision16873` (zones `x,y`/`x`/`y`
  via the real compiler: strict #5144 reject, both owners, no
  UNREACHABLE; scoped-key unit pins for zones and RIs; identical
  `from zone x,y` control still shadows/dedups). RED vs `0e49adee7c`
  production, PASS post-fold. Also implemented the previously
  comment-only namespace-move witness in
  `TestNAT64UnknownOwnerKeyNoCollision16873` (same token as literal
  vs as feed-binding name: both owners, #5144 rejects).
