# Issue 10007 — forward helper crash history to CLI and gRPC

## Why

`fwdstatus.Build` already asserted the optional `HelperCrashHistory()` capability and rendered the #8397 summary row, but the production forwarding adapters exposed only `HelperCrashState()`. The published userspace value is a `*LegacyDataPlaneAdapter`, so the missing delegate meant both the local CLI and remote gRPC forwarding views silently lost history after a helper recovered and its current crash record was wiped.

## What changed

- Added the #8397 history capability to the gRPC and CLI userspace forwarding adapters, resolved from the same unwrapped backend used by the current-crash accessor.
- Added `LegacyDataPlaneAdapter.HelperCrashHistory()` so production `dpProbe()` reaches the manager's retained history ring; unavailable managers fail closed with an empty history.
- Added fail-on-revert adapter cells for both surfaces and a published-adapter cell covering oldest-first episodes, the monotonic total, and unavailable-manager behavior.
- Kept current-crash state wiring unchanged. The new surface tests explicitly use a healthy-after-recovery zero current record while requiring the history row to render.
