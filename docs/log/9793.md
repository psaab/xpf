# #9793 — deactivate of one zone in a group deactivated the whole group

- **Timestamp**: 2026-09-11
- **Action**: refuse `deactivate`/`activate` addressed to one member of a grouped or packed node, as `delete` already does (#8992).
- **File(s)**: listed under Change.

## Defect

`security-zone [ zga zgb ] { tcp-rst; }` is one node, `Keys [security-zone zga zgb]`, and `Inactive` is a node-level flag. `setInactiveAtPath` consumed `security-zone zga` at the schema arity, and `markMatchingNodeInactive` prefix-matched the grouped node, so `deactivate security zones security-zone zga` reported no error and marked the whole statement. Both zones left the compiled candidate. `delete` of the same path was already refused by `elidedPackedRunCarrying` (#8992). The leaf group `security-zone [ zga zgb ];` behaved the same.

## Change

- `pkg/config/deactivate_packed_member_9793.go` (new): `refusePackedMemberToggle` and `addressedSchema9793`.
- `pkg/config/ast_edit.go`: `setInactiveAtPath` calls it at every level where the schema is known, before the walk. The helper is shared by both verbs.
- Cells: `pkg/config/deactivate_packed_member_9793_test.go`, `pkg/configstore/zone_group_deactivate_9793_test.go`.
- `pkg/config/README.md`: the `inactive:` passage records the refusal.

## Design notes

- **Two addresses are deliberately not refused.** A path naming every key of the node is the line `show | display set` emits for an inactive group, and it must reload (#6668). A path ending at a statement whose own content is packed behind it (`security-zone trust screen edge tcp-rst;`) addresses exactly that zone, so the whole node is the right target. The distinguishing test is whether the next key after the path is a schema child of the addressed statement (its content) or not (another member's name).
- **Not the delete rule verbatim.** `deletePath` refuses any prefix of a packed run, including the second shape above. Copying that into the toggle verbs would have refused `deactivate security zones security-zone trust` on a compact zone that deactivates correctly today.
- **A later member is unchanged.** `deactivate ... security-zone zgb` never matched the node, so it already failed with `no node matching "security-zone zgb"` and changed nothing. The store cell requires only that it keep changing nothing. That message, `delete`'s identical one, and `show ... security-zone zgb` printing nothing are one addressing gap, filed as #9799.
