# #17226 — coalesce.Loop.Stop cancels the in-flight actuation (R4-Q53-01)

- **Issue**: #17226 (R4-Q53-01, Medium, validated-by:research)
- **Timestamp**: 2026-10-27
- **STEP-0 (defect live on origin/master 77fb7d5162)**: `pkg/coalesce/coalesce.go`
  `run()` created `context.WithCancel(context.Background())` with only a
  deferred cancel, `Stop()` did `close(l.stop); <-l.done` and never cancelled,
  and `Tick` derived the actuation context (30s `DefaultActuateTimeout`)
  from that Background context. `pkg/ipmon` carried the #3758 cancel privately
  (`actuateCancel()` before `<-e.done`) and never used `Loop.Start/Stop`; the
  only Start/Stop adopter, the daemon route listener
  (`loop.Start(); defer loop.Stop()`), parked in `applySem.Acquire(ctx,1)`
  on the Background-derived context, so shutdown's `wg.Wait()` could stall
  30s past `TimeoutStopSec=20`, skipping the #9035 fail-closed block.
  No open PR covered 17226/coalesce (checked `gh pr list --search`).
- **Action**: `Loop` now owns a cancellable context created in
  `StartWithContext(parent)` ( `Start()` = Background parent); `run()`
  hands `Loop.Context()` to `Tick`; `Stop()` calls `cancel()` before
  `<-l.done`, mirroring ipmon's #3758 order. Added `Loop.Context()` so
  ipmon drops its private context entirely: `pkg/ipmon` deletes the
  private ctx/cancel fields, `Start` calls
  `loop.StartWithContext(context.Background())`, `run` ticks with
  `loop.Context()`, and `Stop` closes `e.stop` then `loop.Stop()`
  (cancel-first) before waiting on `e.done` — the ipmon
  `TestStopAbortsBlockedActuation` (#3758) assertion is moved into
  `pkg/coalesce` as `TestCoalesceStopAbortsBlockedActuation17226`
  (held semaphore, default timeouts, Stop <100ms). The daemon route
  listener now calls `loop.StartWithContext(ctx)` so cancelling the
  daemon run ctx alone aborts a queued `applySem.Acquire`. Tick's
  throttle-before-actuate pacing and converged/dirtyGen semantics are
  unchanged; externally-driven `Tick` keeps its caller-supplied ctx
  (documented: pass `Context()`).

- **Risk**: control-plane lifecycle only, no packet path. No adopter relies
  on an actuation outliving Stop (only route listener uses Start/Stop;
  ipmon drives Tick). ipmon now also runs the loop's (previously absent)
  run goroutine — it sweeps the shared dirty state with the loop's
  Context, duplicate-sweeping with the engine's own Tick; actuations
  remain single-flighted by the loop's dirtyGen/throttle state, and the
  ipmon Stop/ timeout cells above pin the behaviour. A Stop before
  Start remains a no-op; Stop is idempotent. [INFERENCE] Live-cluster
  shutdown timing (SIGTERM → rg_active clear) is not measured here —
  hermetic cells bound the goroutine join instead.
