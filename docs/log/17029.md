# #17029 — Route-protocol vocabulary unified into one SSOT

- **Timestamp**: 2026-10-27
  - **Action**: Added `config.RouteProtocol` / `config.RouteProtocols()` /
    `config.RouteProtocolNames()` (`pkg/config/route_protocol.go`) as the
    single source of truth for the kernel route-protocol vocabulary, with
    fields {Internal, RTProtos, Tag, Junos, Aliases}. Derived all five former
    hand-maintained tables from it: `rtProtoName`
    (`pkg/routing/routes.go`, via a byte index built from the table),
    `protoTag`, `NormalizeRouteProtocol`, and `junosProtoName`
    (`pkg/routing/routeformat.go`), and the `show route protocol` completion
    (`pkg/cmdtree/tree.go`, now `config.RouteProtocolNames()`). The FRR
    ZSTATIC constant moved to `config.RouteProtocolZStatic`; the routing-local
    `rtprotZStatic` remains as an alias so `fibimport.go` and its tests are
    untouched. Fixed the misleading `NormalizeRouteProtocol` doc: completion
    no longer claims to offer Junos/display spellings.
  - **Decisions applied (parent, 2026-10-27)**: (1) redirect is EXEMPT from
    the round-trip tag criterion — its SSOT Tag is explicitly unassigned
    (empty) and `protoTag` keeps rendering "?" for it; no letter was
    invented. (2) Completion offers canonical Internal tokens ONLY
    (`redirect connected dhcp static bgp isis ospf rip`, table order);
    Junos spellings (`access-internal`, `is-is`, `direct`/`local`/`kernel`)
    and tolerances (`access_internal`, `access internal`) are accept-only
    Aliases that `NormalizeRouteProtocol` still maps to Internal but that
    are never offered. This intentionally changes the offered completion:
    it gains `dhcp` and `redirect` (previously undiscoverable) and drops
    the alias tokens `direct`/`local`/`kernel` (still accepted when typed).
    All other projections are pure code-motion: every rtproto byte, tag,
    Junos name, and accepted token maps exactly as before.
  - **File(s)**: `pkg/config/route_protocol.go`,
