# #16737 — Removing `system services ssh` left sshd serving with no visible signal

- **Timestamp**: 2026-10-25
  - **Action**: xpf does not own sshd enablement: removing the stanza only
    removed the xpf-managed drop-in, sshd kept serving under base-image
    defaults, and both `show system services` renderers dropped the SSH
    row entirely — a Junos-trained operator decommissioning SSH on a
    zone admitting `ssh`/`all` kept tcp/22 reachable with no signal.
    Fix (show + advisory + docs; enablement ownership deliberately not
    taken, since lifeline recovery depends on sshd existing outside
    xpf's config lifecycle): (1) both renderers
    (`pkg/cli/cli_show_system.go`, `pkg/grpcapi/server_show_system.go`)
    now always print an SSH row — `running (not managed — no system
    services ssh; sshd serves under base-image defaults)` when the
    stanza (or `System.Services` itself, on the gRPC path) is absent;
    the stanza-present row is byte-identical to before. (2) A commit
    whose zone `host-inbound-traffic` admits SSH (`ssh`, `all` via the
    #3226 expansion, or `any-service`; zone-level and per-interface)
    with no stanza carries a per-zone advisory naming the zone, the
    mechanism, and the remedy (`pkg/config/ssh_unmanaged_advisory_16737.go`),
    suppressed on the tolerant load/peer-sync paths via the new
    `suppressSSHUnmanagedAdvisory16737` opt (registered in the #16166
    lenient-completeness allowlist). (3) The divergence is documented
    in `docs/feature-gaps.md` (SSH Key Exchange row) and
    `pkg/daemon/README.md` (factory drop-in section). NOT changed: the
    drop-in lifecycle itself, `HostInboundServiceMatch` (the `all`
    expansion still admits tcp/22 — the fix makes that visible rather
    than silently narrowing admission), the stanza-present root-login
    display (cohort #16735's cell), and sshd start/stop.
  - **File(s)**: `pkg/config/ssh_unmanaged_advisory_16737.go` (new),
    `pkg/config/ssh_unmanaged_advisory_16737_test.go` (new),
    `pkg/config/compiler.go`, `pkg/config/compiler_opts.go`,
    `pkg/config/compiler_opts_lenient_completeness_16166_test.go`,
    `pkg/cli/cli_show_system.go`,
    `pkg/cli/cli_show_ssh_unmanaged_16737_test.go` (new),
    `pkg/grpcapi/server_show_system.go`,
    `pkg/grpcapi/server_show_ssh_unmanaged_16737_test.go` (new),
    `docs/feature-gaps.md`, `pkg/daemon/README.md`, `docs/log/16737.md`
  - **Validation**: RED on origin/master with only the new test files
    copied in — the advisory cells fail (`warnings=[]`) and both
    not-managed show cells fail (no SSH row), while the managed-row
    controls pass pre- and post-fix. Post-fix targeted runs pass:
    `pkg/config` `-run 'TestSSHUnmanagedAdvisory16737|TestLenientCompileOptsCompleteness16166'`
    (6 tests), `pkg/cli`/`pkg/grpcapi` `-run TestShowSystemServicesSSH`
    (2 + 3 tests), and the full adjacent `TestShowSystemServices`
    suites in both renderer packages. `go vet` clean on the three
    touched packages; `gofmt` clean on all touched Go files.
  - **Residual**: Live-VM proof that sshd listens after stanza removal
    was not re-run (the mechanism is structural: no stop/disable/mask
    exists in the tree, and the factory drop-in plus OpenSSH defaults
    keep it serving). Owning sshd enablement remains an owner decision;
    the acceptance's show-plus-advisory leg is implemented. Per-interface
    overrides that REPLACE (not union) the zone set are checked
    independently, so a zone whose override removes SSH while the zone
    set admits it still warns once — advisory-only over-warning, never
    a false negative.
