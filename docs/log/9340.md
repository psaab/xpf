# #9340 — system-login: the unenforceable-deny advisory is per-PATTERN, so one enforceable alternative silences the argument-text alternative beside it

- **Timestamp**: 2026-09-10
  - **Action**: Chose fix direction 1 (per-branch). The issue's acceptance
    decides it: its third control requires a wholly enforceable pattern
    (`^show route$`) to stay silent, and direction 2 (warn for every class
    with a deny pattern) fails that control.
  - **Action**: New `UnenforceableDenyAlternatives`
    (pkg/config/login_deny_alternatives_9340.go).
    - The pattern is split into alternatives over its PARSE TREE, never its
      text, which clears the bar the #7172 rejected-alternatives note sets.
      Parsing uses syntax.POSIX, the dialect CompileLoginRegexes compiles in,
      then Simplify.
    - Expansion rules: alternation becomes a union, `x?` becomes a union with
      the empty match, concatenation distributes over both, and capture is
      transparent. Repeats stay atomic, because `(a|b)*` is not a union.
    - Each alternative is rendered (Go Perl syntax) and compiled with
      Compile plus Longest(), the matcher CompilePOSIX builds.
    - Each alternative is judged with the class's real allow pattern and its
      ORIGINAL deny source, so EvaluateForms' precedence tiers decide exactly
      as for the whole pattern.
    - An alternative is reported only on surfaces where the whole pattern can
      fire; elsewhere the #8189 advisory already speaks. Past 64 alternatives,
      or on any parse or compile failure, the pattern is not split, which is
      the #8189 silence doctrine.
  - **Action**: Scratch experiment before writing it, over 11 spellings. The
    union of the alternatives gave the same match results and longest-match
    lengths as the whole POSIX pattern on 8 sample commands in every case.
    This covered per-branch anchors, a shared anchored group, unanchored text,
    an optional group, a factored prefix, `[[:alpha:]]`, single-character
    alternatives (the parser merges them into a class, which is harmless) and
    the empty pattern.
  - **Action**: The commit advisory (compiler_system.go) adds a separate "only
    partly enforceable" message naming the alternatives. The runtime gRPC log
    (warnUnenforceableDenyPatternsOnce) adds the matching record through the
    unenforceableDenyAlternatives delegate, so the two paths cannot disagree.
    - The runtime dedup is now checked BEFORE the answer is computed. Its key
      is the class, the allow source and presence, and the deny source,
      because the answer is a pure function of those; the registered command
      set is fixed at init.
    - Without that, the per-alternative analysis (a regexp parse plus one
      evaluation per alternative per command) would run on every restricted
      RPC. `CompiledLoginRegexes.AllowSource` was added for the key.
  - **Action**: Found while writing the allow-pattern cell: the same silence
    reached through the ALLOW list.
    - UnenforceableDenySurfaces counted any refusal (`!Allowed`) as the deny
      firing. A class with an allow pattern also refuses every command outside
      its allow list, so allow `^show` with deny `^show route table secret-vrf`
      reported nothing.
    - Both the whole-pattern and the per-alternative checks now use
      `denyPatternDecides`: the refusal must be decided by the deny pattern
      (`DecidedBy == LoginRegexDeny`).
    - It is in this change rather than a separate issue because the
      per-alternative answer is blind for every allow-bearing class without
      it, and the two checks must share one predicate or their messages
      contradict.
