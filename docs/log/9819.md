# #9819: a VRF table miss falls through to main and to rib-group leaked source tables

## Actions

- **Timestamp**: 2026-09-11T15:05Z
- **Action**: Measured the fix shapes in private user and network namespaces
  (kernel 7.0.13) before writing code.
  - `ip rule add pref 1001 l3mdev unreachable` is accepted for IPv4 and IPv6.
    It turns a VRF-slave miss, a VRF-bound socket miss and the v6 socket miss
    into `Network is unreachable`, while the VRF's connected route and a
    main-ingress lookup still resolve.
  - With the terminator alone, a rib-group leak source broke both ways: main
    to the leaked prefix failed its reverse-path check (`Invalid argument`),
    and the return lookup was unreachable. Adding `pref 1100 iif|oif vrfsrc
    lookup main` restored both. It also kept the source's own misses out of
    another source's table, because they resolve via main's default instead.
- **Action**: Chose the rule form over the per-table `unreachable default`
  route. The rule does not change the contents of any table, so none of these
  readers can see it: zebra's kernel-route import, systemd-networkd, the FBF
  harness's `ip route show table`, or the userspace snapshot's
  `rule.Dst != nil` ingest.
- **File(s)**: `pkg/routing/vrf_miss_terminator_9819.go` (new),
  `pkg/routing/rule_l3mdev_linux.go` (new),
  `pkg/routing/rib_group_return_9819.go` (new), `pkg/routing/vrf.go`,
  `pkg/routing/rules.go`, `pkg/routing/routing.go`,
  `pkg/routing/rule_dscp_linux.go`.
  - The terminator is `l3mdev unreachable` at pref 2000, installed before any
    VRF device and re-asserted on every reconcile (EEXIST is success). It is
    removed only when nothing is desired or still owned.
  - The rib-group return rules are at pref 1500 and cleared by the rib-group
    `clear()`.
  - The order 1000 < 1500 < 2000 < 30000 is checked at compile time.
