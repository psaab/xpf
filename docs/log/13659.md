# #13659: parse_rss_expectation replaced <=, >=, and = with : without validating the operator

- **Timestamp**: 2026-10-15
- **Action**: Replaced blind `<=`/`>=`/`=` -> `:` normalization in
  `fairness_eval::rss::parse_rss_expectation` and its Go twin
  `pkg/fairness.ParseRSSExpectation` with explicit operator parsing.
  Only operators matching each key's hardcoded semantics are accepted
  (`:` or `<=` for cstruct/cstruct-max, `:` or `>=` for
  at-least/active-workers, `:` only for max-worker-flow-share); bare
  `<`, `>`, `=`, and wrong-direction operators fail closed. Documented
  spellings (`cstruct<=25%`, `active-workers>=4`, `key:value`) unchanged.
- **File(s)**: `userspace-dp/src/fairness_eval/rss.rs`,
  `pkg/fairness/expectation.go`, both parser test files, and this log.
- **Red-before**: The new `rss_expectation_rejects_inverted_operators`
  test applied test-only to pristine master failed on
  `cstruct>=0.5`, which parsed as `CstructMax(0.5)` instead of rejecting
  the wrong-direction operator.
- **Green-after**: `CARGO_TARGET_DIR=/var/worktrees/.cache/cargo-13659
  cargo test --manifest-path userspace-dp/Cargo.toml --bin fairness-eval`
  passed all 65 tests. `go test ./pkg/fairness -count=1` and
  `go test ./pkg/fairness -run TestParseRSSExpectation -count=1` passed.
  The parser now validates a longest-first operator against the key's
  allowed operators before parsing the value; the Go twin has identical
  validation. Valid spellings remain covered by Rust and Go regression
  tests. Build warning: host libbpf 1.7.0 differs from vendored 1.6.3.
