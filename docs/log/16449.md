# Issue #16449: bootloader postinst prepends the Ubuntu EFI entry and strands LANE-1

- **Timestamp**: 2026-10-24
  - **Action**: `xpf-uefi-slots` now records the BootOrder front it leaves
    on every run in `/var/lib/xpf/uefi-bootorder-front` (`front=` /
    `slot=` / `order=`, temp+rename+dir-sync, best-effort). When the
    current front is the distributor entry (`\EFI\ubuntu\shimx64.efi`,
    the entry `grub-efi-amd64-signed` / `shim-signed` postinsts
    (re)create and prepend via `grub-install` with NVRAM writes) and
    the recorded front is an xpf slot, the registrar re-asserts the
    recorded slot front non-destructively — the distributor entry
    appeared after xpf's last write, so it is the postinst's rewrite,
    not an operator choice. A genuine operator front is still
    preserved: any non-distributor (PXE) front is never taken over,
    and a distributor front with no recorded slot front (fresh state,
    or an operator front recorded earlier) is preserved and recorded
    as the operator front. Missing/garbled state never takes over.
    The kernel arm gate (`pkg/upgrade/kernel_run.go`) is unchanged —
    no fail-open weakening; the registrar restores the invariant the
    arm requires. `bake.py` adds the state file to
    `SYSPREP_PURGE_PATHS` so a golden image never ships a recorded
    front. Docs: `docs/install-images.md` "BootOrder front after a
    bootloader update (#16449)".
