# Block-form IKE dynamic hostname gateways (#13540)

- **Issue**: #13540 — the IKE compiler failed to read the hostname carried by a nested `dynamic { hostname { fqdn; } }` block.
- **Cause**: `compileIKE` only accepted a hostname child when its FQDN was in `Keys[1]`. The nested hostname block carries its value as a child node instead, so the compiler left `DynamicHostname` empty and marked the gateway responder-only. `compileIPsec` already reads the child with `nodeVal`.
- **Change** (`pkg/config/compiler_ipsec.go`): use `nodeVal` when reading hostname children in the IKE path, matching the existing IPsec path. Added `pkg/config/compiler_ipsec_dynamic_block_13540_test.go` to compare compiled state across flat, block-leaf, and nested-block spellings, and retain bare-dynamic responder-only behavior.
- **RED**: on pristine `origin/master` (`d7fe769aa`), `go test ./pkg/config -run 'TestCompilerIPsecDynamic(HostnameBlock|BareResponderOnly)13540' -count=1` failed for the nested-block hostname forms: `DynamicHostname` was empty, `ResponderOnly` was true, and compiled state differed from the flat form. Reverting the fix and repeating the hostname regression reproduced the failure.
- **GREEN**: after the fix, the focused command passed. `go vet ./pkg/config` passed, and `gofmt -l` reported no formatting changes for the touched Go files. The first full `go test ./pkg/config -count=1` run hit Go's default 10-minute timeout in existing `TestSetRepeatedAPIKeys`; rerunning `go test ./pkg/config -count=1 -timeout=30m` passed (502.967s).
- **Risk**: no change to bare `dynamic` responder-only behavior; the regression test retains that case. The compiler now reads nested hostname values instead of silently dropping them.
