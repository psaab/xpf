# #12155 — Tear down takeover state after durable FIRST-window expiry

- **Issue**: #12155 — a FIRST commit-confirmed window expiring while xpfd is down reverted the store but left takeover artifacts behind.
- **Branch**: `fix/12155-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12155`
- **Base**: `ea8794944` (#12155) stacked on #12154 commit `49d8e39e`.

## Why

`Store.Load` durably rolls an expired FIRST window back to the empty bootstrap config, but unlike the live timer path it never entered `enterBootstrapMode`. Bootstrap suppresses normal config apply, so abandoned xpf `.network` files and the FRR managed section were not swept. A crash between store recovery and daemon teardown would also lose any in-memory-only cleanup signal.

## What

- Bind durable FIRST teardown debt to both the abandoned configuration generation and the rollback configuration hash. A later, confirmed replacement retires superseded debt; if marker publication fails or the process dies between the durable rollback write and marker publication, the retained `confirm.json` lets the next `Load` reconstruct debt before resolving the record.
- Preserve a generation-bound, validated bootstrap `fxp0.network` lifeline snapshot outside networkd's managed-file sweep. While durable teardown is owed, startup naming cannot rebrand candidate state as the lifeline. If the authentic snapshot is missing, keep candidate state untouched and remain degraded.
- Treat networkd reload as a separate teardown acknowledgement: removing files is not enough to clear durable debt. A failed reload leaves the marker owed, and a later startup retries reload even when its file scan finds nothing new.
- Latch transit-gate ownership from durable debt before config restore can drop `EverCommitted`; the fail-closed rollback therefore closes the forwarding barrier before teardown detaches the host-side path.
- Run both durable teardown phases through the actual `Daemon.Run` startup chain. The regression verifies managed networkd and FRR state are removed and the durable marker clears; deleting both startup callsites makes it fail.
- Keep day-0 import suppressed while cleanup is owed. Permanent configstore and daemon regressions cover marker gaps, supersession, reload acknowledgement, lifeline provenance, transit closure, and startup wiring.
