# #16619 — userspace-dp: inbound persistent-NAT sessions that are also source-NATed take the inbound hold

- **Timestamp**: 2026-10-25
- **Mechanism**: #15111's inbound hold was skipped whenever the final
  composed NAT decision carried `rewrite_src`
  (`acquire_persistent_inbound_hold` in
  `userspace-dp/src/afxdp/poll_descriptor/mod.rs`, and the HA twin
  `acquire_persistent_inbound_for_synced` in
  `userspace-dp/src/nat/source/synced.rs`), on the premise that "SNAT
  joined the lease via active_flows". That premise is false for an
  inbound persistent session: the poll loop composes SNAT with
  `nat_match_flow = flow.with_destination(...)`, whose source is still
  the *remote*, and the SNAT lease key is built from the flow's
  `src_ip`/`src_port` (`userspace-dp/src/nat/source/keys.rs`), so the
  SNAT allocation joins (or mints) the remote's lease — never the
  internal host's lease admitted by `persistent_inbound_lookup`. The
  binding therefore expired `inactivity-timeout` after the last
  outbound flow while an inbound session through it lived; its tuple
  was freed and could be minted for another host, and new remotes lost
  (or mis-reached) the mapping. Prerequisite is an operator config that
  source-NATs inbound traffic on the persistent-DNAT path (a common
  "make the server reply symmetric" pattern); policy is not bypassed.
- **Fix**:
  - Poll path: `acquire_persistent_inbound_hold` no longer gates on
    `rewrite_src.is_some()`. It takes the hold whenever the persistent
    lookup admitted the flow (stored `lease_key` present) and the final
    decision still carries that `rewrite_dst`. NAT64/NPTv6 exemptions
    are unchanged. The ForwardCandidate call-site comment is updated to
    state the corrected contract. Release needs no change:
    `release_persistent_inbound_for_session`
    (`userspace-dp/src/nat/source/release.rs`) already runs before the
    `rewrite_src` gate and re-derives the internal endpoint from the
    session's `rewrite_dst`, so a #16619 session's hold is dropped
    exactly once on every teardown path that already released a
    DNAT-only hold (its doc comment now records that the decision may
    also carry `rewrite_src`).
  - Synced twin: `acquire_persistent_inbound_for_synced` no longer
    returns early on `rewrite_src.is_some()`. Because `rewrite_dst` is
    also present on ordinary outbound synced decisions, the inbound arm
    is distinguished structurally: when the endpoint derived from
    `rewrite_dst` IS the session source, the host is outbound and the
    reserve body's persistent join (keyed by that same source) already
    holds the lease, so no second inbound hold is taken; otherwise the
    session is inbound and the hold is taken on the internal host's
    lease. NAT64/NPTv6 exemptions unchanged. The stored-key seam for
    exact release across routing domains is #16615's fix and is not
    folded in here.
  - `acquire_persistent_inbound_for_synced` is re-exported from
    `nat/mod.rs` for the regression tests (it was already
    `pub(crate)` via `source::*`).
- **RED/GREEN**:
  - `persistent_inbound_hold_with_snat_keeps_lease_past_expiry_16619`
    and `synced_inbound_hold_with_snat_16619`
    (`userspace-dp/src/nat/tests_pool.rs`): mint the internal host's
    lease, release the outbound flow, compose DNAT+SNAT exactly as the
    poll loop does, and assert the hold is taken, the lease survives
    past the outbound expiry, a second host cannot steal the tuple,
    and release re-arms expiry so GC reclaims it. The synced test also
    pins the outbound no-double-hold arm and the NAT64/NPTv6
    exemptions. Pre-fix the composed arm takes no hold.
  - `acquire_persistent_inbound_hold_with_snat_takes_hold_16619` and
    `acquire_persistent_inbound_hold_exemptions_unchanged_16619`
    (`userspace-dp/src/afxdp/poll_descriptor/persistent_inbound_hold_16619_tests.rs`):
    drive the production gate directly; the SNATed arm asserts
    `acquire_took_hold == true` (the issue's acceptance), the DNAT-only
    control is unchanged, and NAT64/NPTv6/no-`rewrite_dst`/no-key arms
    take no hold.
- **Validation**: targeted `cargo test -- 16619` plus the #15111
  regression (`persistent_inbound_hold_keeps_lease_past_expiry_15111`);
  see PR for counts. No full selftest per lane instructions.
- **Risk**: an inbound session now holds its persistent lease for its
  lifetime even when SNATed — the intended #15111 contract. If such a
  session leaks without teardown, its lease leaks with it, the same
  bounded failure mode as a leaked `active_flows` hold. The synced
  outbound discriminator compares the `rewrite_dst`-derived endpoint
  with the session source; an outbound flow whose post-DNAT destination
  coincidentally equals its own source endpoint would skip the inbound
  hold, but that lease is already held by the reserve body's join, so
  the binding stays alive either way.
