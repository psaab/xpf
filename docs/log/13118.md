# Issue #13118: Ignore quarantined zones in fabric routing warnings

`validateFabricZoneRoutingInstanceAmbiguityStrict` produced a tolerant-load
warning for zones or bindings already excluded by zone quarantine. This made
`cfg.Warnings` claim an inactive quarantined zone had active routing-domain
ambiguity.

The validator now filters `ZoneQuarantineExclusionsForConfig` and
`QuarantinedZoneInterfaceKeys` before building zone routing ownership. Normal,
non-quarantined cross-routing-instance zones still produce the existing strict
error / tolerant warning. Strict collision and membership gates are unchanged.

Regression coverage includes a zone-ID collision quarantine, a contested
interface quarantine, and a non-quarantined cross-RI must-warn control.
