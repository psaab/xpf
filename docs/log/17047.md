# #17047: consolidate stored-session re-resolution (R4-Q03-01)

- **Timestamp**: 2026-10-28
- **Action**: The stored-FabricRedirect re-resolution pipeline was
  spelled out four times in session_glue (RefreshOwnerRGS,
  DemoteOwnerRGS, the session-hit arm, and the reverse-synthesis
  arm in resolve.rs), each recomputing
  `install_table_name_for_session` up to three times and spelling
  the destination-owner boolean independently, so every
  #15958-class fix (including #16524) had to land at each copy.
  Added the single pipeline
  `reresolve_stored_session(forwarding, ha_state, neighbors,
  now_secs, stored, stored_metadata, target, looked_up, fabric)` in
  `session_glue/resolution.rs`: the caller supplies only the fresh
  lookup (hit arms keep their cached / synced / leak-revoked variant
  choice), and the helper runs
  `prefer_local_forward_candidate_for_fabric_ingress`, HA enforcement
  selected by `fabric`, the fabric re-redirect composition, and — for a
  stored FabricRedirect — the rehome-or-retain verdict, computing
  `DestinationOwner::{Unknown, Active(rg), Inactive(rg)}` from the
  installing table (evaluated once). `FabricArrival` is the single
  typed context: packet arms carry packet-time anti-loop, tunnel-bypass,
  and adoption inputs and use `enforce_session_ha_resolution` +
  adoption + `_at` DiscardRoute rescue on non-redirect decisions;
  command arms carry only `fabric_ingress` and use snapshot enforcement
  plus the plain redirect wrapper. Its `Packet` and `Command` variants
  make the former cross-pairings unrepresentable. The #16524 fix lives
  in the `Unknown` arm of the typed owner. Removed the boolean twins
  `rehome_or_retain_fabric_redirect_scoped_15958b` /
  `..._16524`; the single typed entry
  `rehome_or_retain_fabric_redirect(..., DestinationOwner, ...)`
  remains, called only from `reresolve_stored_session` and from
  reverse synthesis. In `shared_ops/reverse_synth.rs` (a different
  synthesis decision, not a pipeline copy) renamed the local to
  `destination_owner_known_active` and routed its retention call
  through the typed entry as `DestinationOwner::Inactive(dest_rg)`
  (the arm is gated on `dest_rg > 0 && !active`, so the verdict is
  bit-identical). Added the `DestinationOwner` x `FabricArrival`
  table cell and a source guard cell asserting the duplicated
  spelling cannot return (no removed-twin references, no
  `dest_rg == 0 ||` outside the helper, exactly the consolidated
  rehome callers).
  Fold (#18318): eliminated the independent `HaEnforce` parameter.
  `FabricArrival::Packet` is the only session-enforcement form and
  `FabricArrival::Command` is explicitly the snapshot-enforcement arm;
  therefore `Session`+`Command` and `Snapshot`+`Packet` cannot be
  constructed. The table still exercises both legal variants; existing
  #15958b behavior checks remain unchanged.
