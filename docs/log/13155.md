# #13155 — align host-inbound classification with zone enforcement

## Why

`ClassifyHostInbound` classified a lifeline-only zone's empty view as denied,
although lifeline interfaces are excluded from enforcement and are served
unconditionally. Interface-scoped classification read raw zone membership, so
it could report an SSH token admit for an interface quarantined because two
zones claimed it. For Shape B secure tunnels, where `st0` is synthesized from
`st0.0` and absent from declared interface config, the resolver also accepted
bare `st0`; the classifier then missed the unit override.

## What

The zone classifier reports `NotComputed` when every member is a lifeline,
consistent with the classifier contract that lifeline traffic is outside its
scope. Interface-scoped classification treats quarantined logical interface
keys as an empty view, and ingress resolution rejects those keys explicitly.
Bare physical selectors are now rejected when the effective zone map proves a
logical-unit binding, including synthesized Shape B tunnel units. Direct
interface classification also declines bare physical refs when logical units
are present, preventing fallback to a zone-wide token set.

Added focused #13155 regression coverage for the three source-finding cases,
including positive checks that `st0.0` remains valid and lifeline queries stay
outside the classifier.

## Risk / residual

Lifeline-only zone queries now return `NotComputed`, not an admission verdict,
so callers do not describe host-inbound tokens for traffic exempt from this
classifier. Explicit lifeline ingress-interface selectors continue to be
rejected with the existing explanatory error. No dataplane enforcement behavior
changes.
