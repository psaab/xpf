## Defect (present at base)

`flush_session_deltas` (`afxdp/session_delta.rs`) has two HA delivery
legs for a session delta:

1. The per-binding RPC-fallback buffer (`live.push_session_delta*`).
   For a `bulk_resync` delta it routes to
   `push_session_delta_bulk_export`, which counts a refusal but does
   not arm the loss latch (#8593). The resync's own export therefore
   cannot re-trigger itself on this leg.
2. The lossless event-stream producer (`es.push_delta_lossless_within`).
   It had no `bulk_resync` exemption: any failure — the immediate
   `!connected` early return in `send_lossless_encoded` while the
   helper→xpfd stream is down, or a bounded-timeout give-up — set
   `event_stream_out_of_sync`, so `flush_session_deltas_loop`
   (`worker/loop_body/mod.rs`) called `sessions.set_delta_loss()`.

The #2442 LossResync caller (`take_delta_loss` in
`worker/loop_body/delta_recovery.rs`) drains that latch, then
`chunked_drain_as_you_export!` re-emits an Open delta for every owned
forward session through leg 2. While the stream stays disconnected
every one of those lossless pushes fails instantly, the latch re-arms,
and the next worker pass re-exports the whole owned table again —
under EVERY worker, for the whole outage. The outage-time re-export
carries nothing new: reconnect already triggers a FullResync, and the
bulk deltas are Open-only snapshots whose contents are exactly what
the snapshot being shipped already contains. The effect is a
forwarding brownout (repeated whole-table candidate walks and flushes
competing with the RX/TX poll) bounded only by outage length. The
#5468 aggregate wedge did not bound it either: the wedge latch is
reset every pass (`worker_lossless_wedged = false` at loop top), and
every resync chunk's flush spends at most one budget — but the EXPORT
itself (candidate collection + per-chunk emit) repeats every pass.

## Change

Event-stream leg, per-kind gate in `flush_session_deltas`
(`session_delta.rs`):

- A `bulk_resync` delta whose lossless push fails now counts the drop
  (`es.record_dropped_frames(1)`) and sets a per-batch
  `bulk_loss_this_batch` flag instead of `event_stream_out_of_sync`.
  Neither the function's return value nor the `worker_lossless_wedged`
  aggregate is raised by a bulk failure, so `flush_session_deltas_loop`
  never calls `set_delta_loss` for the export's own deltas. The
  LossResync export therefore runs at most once per genuine trigger:
  with the stream disconnected for N passes, passes 1..N do not
  re-export.
- The lossless attempt gate is split per delta kind, so neither
  kind's failure suppresses the other kind's first attempt in the
  same batch:
  - bulk delta: attempted unless `bulk_loss_this_batch`;
  - incremental delta: attempted unless `event_stream_out_of_sync`
    (which also carries the seeded `#5468` wedge).
  A genuinely-new incremental drop — including one interleaved in the
  same drain after bulk failures — still latches
  `event_stream_out_of_sync`, sets the wedge, and re-arms a fresh
  resync, preserving the #2874/#2442 recovery. Attempts stop after
  the first failure of each kind in a drain, so the per-drain-cycle
  lossless wait stays ~1 budget (#5468): the remainder is superseded
  by the scheduled resync incrementals trigger, or by the reconnect
  FullResync for bulk-only loss.
- Successful bulk delivery is unchanged (#9630): LossResync deltas
  still take the full event-stream path (HA + RT_FLOW frames) when
  they can be queued; only failure attribution changes.
- Docs: `event_stream/README.md` gains the #14646 non-arming rule
  beside the #5290/#5468 bullets; `afxdp/binding_state/README.md`
  notes the same rule on the event-stream leg beside #8593.

## Local master compile-break workaround (not part of this fix)

`origin/master` does not compile at the lane base: #14793 extended
`PortAllocator::persistent_inbound_lookup` with
`from_zone: &str, ingress_zone: &str` and updated the admission call
site in `poll_descriptor/mod.rs`, but the revalidation mirror in
`policy_revalidation.rs` still calls it with 6 arguments (filed as
#14802). This lane threads `scope.zone_name` (the same resolved
ingress zone name `destination_nat_translation_still_valid` already
computes via `prerouting_ingress_scope`) plus `&rule.from_zone` into
that call so the lane's tests can build — mirroring the admission
loop's zone threading semantics (NOT the `", ""` unscoped stub, which
would re-open the #14322 cross-zone leak on the revalidation path).
That hunk is kept local to make this lane buildable; folding it into
a merged PR is #14802's owner's decision (this PR closes only
#14646; if the #14802 fix lands first, the hunk is dropped on rebase).

## Risk

Bounded to failure attribution on one flush leg. Enforcement,
session state, and the RPC-fallback leg are untouched; the only
behavior delta is that bulk deltas lost to a disconnected/wedged
stream no longer re-export the owned table per pass — a strictly
weaker recovery loop, fully superseded by the reconnect FullResync.
Real outage durations on the loss cluster were not measured (the
issue records them as the only outstanding validation).
