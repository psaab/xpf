# Kernel lo0 mirror drops `match-start layer-4`, renders flex-match at the L3 base (#14394)

- **Issue**: #14394 (DR8-H3, deep-review `muse-tbh-1015`). Validated MATERIAL/CONFIRM by both blinded research passes.
- **Cause**: The compiler has accepted `match-start layer-4` since #3232 and stores `FlexMatchConfig.MatchStart`; the userspace snapshot builder and Rust matcher honour it (`FlexMatchStart::Layer4`). The kernel lo0 mirror dropped the field at every boundary: `xnft.Lo0FlexMatch` had no `MatchStart` field, `lo0FlexMatch()` copied only ByteOffset/BitLength/Value/Mask and never set `FlexMatchUnrepresentable`, the netlink builder always loaded with `PayloadBaseNetworkHeader`, and the text oracle always rendered `@nh`. So a lo0 term authored at the L4 base was evaluated at the L3 base on the chain that is the PRIMARY enforcement for host-bound traffic: a `then discard` term essentially never matched (fail-open), a `then accept` term wrongly fell through. The netlink-vs-oracle parity test could not catch it because both renderers made the identical L3 error. The struct comment claiming "Only `layer-3` match-start is representable, which is exactly what the compiler accepts" was stale.
- **Change**:
  - `pkg/nftables/netlink_spec.go`: `Lo0FlexMatch` gains `MatchStart string` (`""`/`"layer-3"` = network header, `"layer-4"` = transport header, anything else unrepresentable); stale comments corrected.
  - `pkg/daemon/daemon_nft_netlink.go`: `lo0FlexMatch()` carries `MatchStart`; new `lo0FlexMatchStartUnrepresentable()` helper; `toNftLo0Term` ORs it into `FlexMatchUnrepresentable` so an unrepresentable start emits no rule for the term.
  - `pkg/nftables/netlink_build.go`: `flexMatchRepresentable()` rejects any match-start outside `{"", "layer-3", "layer-4"}` (primary enforcement — `netlink_lo0.go` then emits no rule, term matches nothing); `flexMatchExprs()` selects `PayloadBaseTransportHeader` for `layer-4`, `PayloadBaseNetworkHeader` otherwise. Width rule (1..4 bytes) unchanged.
  - `pkg/daemon/daemon_nft.go`: `nftFlexMatchExpr()` renders `@th` for `layer-4`, `@nh` otherwise; `lo0FlexMatchUnrepresentable()` gains the match-start arm so the oracle omits the predicate (term matches nothing) for an unrepresentable start.
  - `pkg/daemon/daemon_nft_term_lower.go`, `pkg/daemon/README.md`: stale "only layer-3" comments/docs corrected to name both bases.
  - Layer-3 and empty match-start terms render byte-identically in both renderers. Userspace snapshot builder and Rust matcher untouched.
- **Regression coverage**:
  - `pkg/nftables/netlink_flexmatch_layer4_14394_test.go` (new): `layer-4` → `PayloadBaseTransportHeader`; `""`/`layer-3` → `PayloadBaseNetworkHeader`; `payload`/`bogus`/`layer-5`/`Layer-4` → not representable, zero exprs, and the lo0 plan emits only the following deny term's rule.
  - `pkg/daemon/lo0_flexmatch_layer4_14394_test.go` (new): oracle renders `@th,0,8 & 0xff == 0x11` (and no `@nh`) for layer-4 and the netlink spec carries `MatchStart: "layer-4"`; layer-3/empty controls still render `@nh`; `payload`/`bogus` → `lo0FlexMatchUnrepresentable` true, oracle renders no rule, netlink spec marked unrepresentable; layer-4 is not marked.
  - `pkg/daemon/daemon_nft_netlink_parity_test.go`: new `layer-4-transport-base` row in `lo0_flexible_match_range` (guard now expects `@th` for layer-4 rows, `@nh` otherwise) and new `unrepresentable-match-start` row in `lo0_unrepresentable_flex_match_matches_nothing` (guard now also rejects `@th`).
- **RED evidence**: On pristine origin/master (f8a69b7a4) a behavioral probe of the oracle failed with `meta l4proto 6 @nh,0,8 & 0xff == 0x11 accept` for a `match-start layer-4` term (L3 base — wrong) and `payload` was not unrepresentable. The committed nftables test fails to build on master (`unknown field MatchStart in struct literal of type Lo0FlexMatch`) — the field did not exist.
- **GREEN evidence**: `TestFlexMatch.*14394` (pkg/nftables) pass; `TestLo0FlexMatch.*14394` + `TestNftRuleFromTermFlexMatchUnrepresentableMatchesNothing7722` (pkg/daemon) pass; full `pkg/nftables` suite pass; flex-focused `pkg/config` and `pkg/dataplane/userspace` suites pass. Parity subtests run where `nft`+netns are available (see PR body).
- **Blast radius / risk**: Zero for layer-3/empty terms (byte-identical). Layer-4 lo0 terms now enforce at the authored transport base on the kernel-primary host path — `then discard` terms that previously missed will now drop matching host-bound traffic, which is the authored intent; this is an operator-visible behavior correction, not a regression. Unrepresentable match-starts (only reachable via tolerant load / version drift, since strict commit rejects them) now match nothing instead of silently re-basing to L3.
