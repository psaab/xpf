# #16859 — Rotation line stays UNKNOWN in fabric-transport mode

- **Issue**: `notePeerControlKeyID` had a single producer, heartbeat
  `admitFrame`. With no `control-interface`/`peer-address` the heartbeat
  never starts, so in fabric-transport mode the rotation line reported
  `peer key UNKNOWN — no authenticated peer frame seen, do NOT finalize`
  forever while session sync authenticated the peer continuously. A
  fabric-transport operator following the documented finalize procedure
  was told never to finalize, leaving the retired key valid (#16029
  exposure). The rendered UNKNOWN text also contradicted the README
  table (`not the same as "not safe"`).
- **Change**:
  - `Manager.noteSyncPeerAuthenticated` now takes the matched PSK
    (variadic) and, in addition to the process-lifetime bit, feeds
    `notePeerControlKeyID(controlLinkKeyID(matched))`. Only the derived
    ID is stored; the raw key is never logged or retained.
  - `SessionSync.recordAuthenticatedPeer(matched ...[]byte)` threads the
    key through `syncPeerAuthRecorder`. Producers: the connect handshake
    passes `result.matchedPSK` (initiator: its signing key; responder:
    the ring key msg1 verified under — either way the peer's signing
    key); the #6628 upgrade responder passes its matched ring candidate;
    the upgrade initiator passes `st.forPSK`. The #15140 pending gate is
    untouched: the responder still records only after
    `awaitInitiatorConfirm` succeeds (that is where the connect path
    reaches `recordAuthenticatedPeer`), and the replay cells still assert
    zero recordings before confirmation.
  - UNKNOWN rendering aligned with the README: `peer key UNKNOWN — no
    authenticated peer frame seen; unknown, not known safe to finalize`.
    `ControlLinkRotationSafeToFinalize` still returns false for UNKNOWN
    (absence of evidence is not evidence the peer moved); only the
    wording changed. The `peer is still signing … — do NOT finalize`
    arm is unchanged.
  - README "Knowing when it is safe to finalize" documents that the
    observation is fed by heartbeat, connect handshake, and upgrade.
- **Tests**: new `pkg/cluster/control_key_rotation_16859_test.go` with
  three cells using real `Manager`s as sync auth providers, both nodes
  at step 4 (sign B, accept B+A) unless noted:
  `TestRotationLineFabricTransportConnect16859` (real connect handshake,
  both nodes report `PeerControlKeyID == id(B)`, `HeartbeatPeerAuthSeen`,
  and `safe to finalize`),
  `TestRotationLineFabricTransportPeerOnRetiredKey16859` (step-3 peer
  still signing A renders `still signing … do NOT finalize` — the feed
  carries which key matched),
  `TestRotationLineFabricTransportUpgrade16859` (real #6628 upgrade
  exchange feeds both ends). Updated the #6630 UNKNOWN expectation and
  the #15140 recorder signature for the variadic recorder.

  handshake proves the responder accepted that exact PSK), documented
  at the call site.
