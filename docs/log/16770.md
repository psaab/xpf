# #16770 — All-invalid ssh-known-hosts replacement kept the revoked key trusted

- **Timestamp**: 2026-10-25
  - **Action**: #14692's "no valid entries → leave the existing file
    untouched" kept a revoked/removed host key in
    `/etc/ssh/ssh_known_hosts` after a clean commit whenever every key in
    the replacement commit failed render-time validation (e.g. the
    OpenSSH spelling `ssh-ed25519` instead of the Junos `ssh-ed25519-key`),
    regressing the #5112 contract that applied trust must not outlive
    desired trust — the file governs the config-archive scp transfer
    (`StrictHostKeyChecking=yes`, #10298). Fix, two legs sharing one
    validator: (1) the #14692 validators (type table, host-field and
    key-blob checks) moved verbatim from `pkg/daemon/daemon_system.go`
    to `pkg/config/ssh_known_hosts_validate_16770.go` as exported
    `SSHKnownHostTypes` / `ValidSSHKnownHostField` /
    `ValidSSHKnownHostKey` plus `ValidateSSHKnownHostsStrict`, so the
    commit gate and the render belt cannot drift; the daemon now calls
    the shared validators. (2) `applySSHKnownHosts` on the all-invalid
    branch now calls the ownership-guarded, dir-fsynced
    `removeManagedSSHKnownHosts` instead of returning — stale trust is
    revoked however the bad input arrived (tolerant load, peer-sync, or
    a pre-#16770 persisted config); a foreign file without the managed
    header is still never touched. (3) A dead-last uniform gate in
    `runUniformGates` rejects any host/key the renderer would skip on
    strict commit, naming host and type (never key material), and
    downgrades to a warning on the tolerant paths via the new
    `lenientSSHKnownHosts16770` opt (set in `lenientCompileOpts`, so the
    #16166 completeness census passes). The strict gate checks every
    entry, so the truncated `AAAA...` shorthand in the pre-existing
    #4821/parser fixtures (never a valid renderable key — the #14692
    daemon test already notes it is skipped) is now rejected strict;
    those two fixtures were repaired to the full ecdsa blob already
    used in `parser_ast_test.go`. NOT changed: the #14694 sibling
    in `daemon_hostauth_apply.go` (authorized_keys suppression) — the
    issue scopes it as "needs the same review; not executed here"; the
    partial-validity path (valid entries still render, invalid siblings
    skipped); the empty-config removal; the opaque `host` schema body.
