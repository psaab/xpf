# #13305: Export flow-export data-quality counters to Prometheus

## Finding

NetFlow v9 and IPFIX count unresolved route-mask halves and close records
missing a creation timestamp, but those counts stop at exporter-local atomic
getters. The shared flow-export batch stats path and Prometheus collector omit
them, so `/metrics` cannot distinguish a real default-route `/0` from an
unresolved mask or report missing-start-time fallbacks. In addition,
`flowStartTime` clamps a future `Created` timestamp to the close time while
returning the same `false` flag as a valid measured timestamp; this means the
clock-skew event has no counter at all.

Origin: deep-review D6-04 (`review-work.AYgyxCmMxC`), Gemini 4 Argon High;
validated by three-way research.

- On pristine master `98d56af14`, installed only the Prometheus regression and

  GOTMPDIR=/var/worktrees/.cache/go-tmp go test ./pkg/api/ -run

  all three expected metric families were missing.
- Added exporter regression tests proving future timestamps are separately
  identified from missing timestamps and counted by both exporter protocols.

## Change

`flowStartTime` now reports the clock-skew clamp independently of the
missing-created signal. NetFlow and IPFIX retain a per-exporter atomic count
for those clamps. The daemon's existing per-exporter flow-export stats pass
now carries route-mask unresolved, missing-start-time, and clock-skew counts;
the Prometheus collector exposes them as bounded protocol/instance/template/
family counter series:

- `xpf_flow_export_route_mask_unresolved_total`
- `xpf_flow_export_missing_start_time_total`
- `xpf_flow_export_clock_skew_clamped_total`

Batch-stat metric emission is independent of the optional collector-health
callback; previously that callback's absent path returned before emitting
batch statistics. Existing exporter interfaces and flow timestamp values are
unchanged. No API, wire, or CLI surface was expanded.
