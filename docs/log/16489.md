# #16489 — closing_counters_keep_alive (#14937) had no baseline, retaining idle half-closed pairs one extra window

- **Timestamp**: 2026-10-24
- **Context**: The #14937 expiry belt-and-braces retains a CLOSING
  (single-FIN, non-RST) pair when its canonical forward packet total
  (`fwd+rev`, folded by `account_packet`) differs from
  `closing_counters_seen`. That field was initialised to 0 at both
  install sites and written only by the retention check itself, so on
  the first crossed expiry pass any pre-FIN traffic — and the FIN
  packet itself, accounted after its forwarding pass — read as
  "advanced since the last check". The check then manufactured
  freshness (`last_seen_ns = now_ns`) for a pair that had been silent
  since its FIN, granting one extra close window: ~60 s at the 30 s
  default, or a whole extra service timeout (e.g. 1800 s) under
  `time-wait-state apply-to-half-closed-state session-ageout` (#15946).
  Half-closed sessions are the population a misbehaving client mints
  cheaply, so each held its table slot and NAT pinhole twice as long.
- **Fix**: seed the baseline at the pair's first transition into
  CLOSING, in `userspace-dp/src/session/`. A new
  `seed_closing_counters_baseline` (expire.rs) copies the forward
  entry's current packet total into `closing_counters_seen`, resolving
  the forward entry exactly as the retention check does. It is called
  only on the `!closing -> closing` transition: from the session-hit
  path (`lookup_with_origin_inner`, including the deferred-owner
  replay that funnels through it), from `apply_deferred_owner_close`,
  and from the HA-promote path (`update_session`). A synced import
  that arrives CLOSING (`tcp_close_class` wire class present) seeds
  the field directly from the carried `fwd+rev` wire total in
  `upsert_synced_with_origin`; a non-closing import keeps 0 and is
  seeded by its later local transition. An entry installed by a
  closing packet already has zero local counters, so its zero
  baseline is the current total. The retention check itself is
  unchanged: genuine post-close advances still retain (the #14937
  active-pair cell), TIME_WAIT/RST keep their fixed fuse, and no gate
  is weakened — the change only stops historic volume from counting
  as activity.

- **Validation**: new `*_16489` cells in
  `close_refresh_gate_10885_tests.rs`: mode 0 (no counters, control),
  mode 1 (pre-FIN data only), and mode 2 (FIN packet only) each reap
  both halves at FIN+window+GC; modes 1–2 are RED pre-fix (the pair
  survives to a second window). A synced-import cell pins the baseline
  at the carried total and the one-window reap. The existing #14937
  active-pair cell stays green (see PR for exact counts).
- **Residual**: component level only, matching the finding's evidence
  (no wire observation). Post-close accounting that lands in the same
  GC interval as the FIN but before the first crossed expiry pass is
  indistinguishable from pre-close volume by design — it is at most
  one GC interval old when first observed, which is the bound the
  #14937 contract already accepts.
