- **Issue**: #15656 — `Manager.ReadInterfaceCounters` matches only exact `BindingStatus.Ifindex`, returning authoritative zero traffic for all VLAN subinterfaces (`ge-0/0/0.<vlan>`)
- **Change**: `ReadInterfaceCounters` now tracks whether any binding matched. On no direct match it consults the retained snapshot (`m.lastSnapshot.Interfaces`): a row whose `Ifindex` is the request and whose `ParentIfindex > 0` resolves the request to the parent physical binding, and the parent binding's aggregated RX/TX packets/bytes are returned (the helper binds only the parent netdev, so this is the traffic that carried the VLAN unit; sibling units share the parent aggregate until the helper exports per-`(ifindex,vlan_id)` counters). If neither a direct binding nor a bound snapshot parent covers the ifindex, it fails closed with `userspace interface counters unavailable: no binding covers ifindex %d` instead of `(0,0,0,0),nil`. A genuinely idle bound interface still matches directly and returns its real zero. All existing consumers already handle the error contract (#3464): REST `/interfaces` and `/stats/interfaces` flag the row `Unavailable`, gRPC mirrors that, Prometheus omits the sample and bumps `xpf_interface_counter_read_errors_total`, CLI prints a warning — so no consumer change was needed. The pre-#15656 #13273 expectation "unknown ifindex reads as zero with no error" is superseded and its test updated accordingly.
