# #17073 — encode delete caller contract once in DeleteOrigin guard

- **Timestamp**: 2026-10-27
- **Issue**: #17073 (R4-Q03-07)
- **Base**: `origin/master f681f07dd7`

## Defect (STEP-0, verified at base)

`handle_delete_synced_with_guard` (userspace-dp/src/afxdp/session_glue/commands/delete_synced.rs:271-296 at base) took 14 parameters including two positional bools `enforce_peer_owner: bool, remove_mirror: bool` plus a bare `deferred_redirects: &mut Vec<DeferredRedirectDelete>` out-param. Three real modes existed:

- peer sync: `(true, true, &mut Vec::new(), 0, None)` — handle_delete_synced :219 and handle_delete_synced_conditional :254
- local clear: `(false, true, &mut Vec::new(), 0, None)` — worker_commands.rs DeleteLocalControl :574
- policy batch: `(false, false, deferred, ..)` — handle_remove_policy_item :101/:120

The fourth combination `(true, false)` compiled but had no caller. Worse, delete_synced.rs:377-382 selected the operator-visible RT_FLOW close reason from `remove_mirror` (`if remove_mirror { CLEAR(7) } else { POLICY_DELETE(8) }`), so the close reason was a side effect of BPF-mirror timing: a future non-deferred policy delete would have logged CLEAR.

Proof at base: `git grep -n 'handle_delete_synced_with_guard\|remove_mirror\|enforce_peer_owner' origin/master -- userspace-dp/src/afxdp/session_glue/` returned the signature, four internal uses, and all call literals above. Defect live, not already fixed.

## Fix

- Added `DeleteOrigin` enum in delete_synced.rs (single source of truth, `pub(in crate::afxdp::session_glue)`): `PeerSync`, `LocalClear`, `PolicyBatch`. It carries the whole caller contract via `enforces_peer_owner()`, `close_reason() -> Option<u8>` (None=PeerSync silent, Some(CLEAR)=LocalClear, Some(POLICY_DELETE)=PolicyBatch), and `removes_mirror_immediately()` (false only for PolicyBatch).
- `handle_delete_synced_with_guard` now takes `origin: DeleteOrigin` instead of the two bools (13 params, no bool params). Guard body: peer-owner refusal via `origin.enforces_peer_owner()`; close via `match origin.close_reason()`; immediate vs deferred mirror via `origin.removes_mirror_immediately()`; companion recursion forwards `origin` unchanged.
- Call sites migrated, identical semantics per mode: handle_remove_policy_item (forward + companion) → PolicyBatch with the batch deferred vec; handle_delete_synced / handle_delete_synced_conditional → PeerSync with throwaway vec; worker DeleteLocalControl → LocalClear with throwaway vec.
- `commands/mod.rs` re-exports `DeleteOrigin` alongside the guard for worker commands and tests.
- NOT changed: coordinator-side ladders in ha/session_import.rs (separate issue R4-Q05-04), session table delete primitives, wire constants. No behaviour change: each variant reproduces exactly its old bool pair.

## Tests

- Migrated existing direct callers in tests.rs: `deferred_absent_branch_issues_no_bpf_10512` → PolicyBatch; `control_plane_delete_emits_harvested_close_13972` legs → LocalClear / PolicyBatch / PeerSync (unchanged assertions: CLEAR=7 harvested close, POLICY_DELETE=8 via policy item, peer legs silent).
- New hermetic cell (class U, recorder-only steering map, no kernel/BPF/netns): `delete_origin_close_reason_independent_of_mirror_mode_17073` drives each origin against a live locally-owned entry and asserts reason AND mirror timing together — LocalClear: immediate BPF deletes + CLEAR + no deferred; PolicyBatch: no BPF + one deferred intent + POLICY_DELETE; PeerSync: immediate BPF deletes + silent + no deferred. The old cross-pairing (immediate-mirror policy delete logging CLEAR) is now unrepresentable: no bool remains to flip.
- Acceptance grep: `grep -rn 'remove_mirror\|enforce_peer_owner' userspace-dp/src/afxdp/session_glue` returns 0 hits (methods renamed to `enforces_peer_owner` / `removes_mirror_immediately` on the enum; historical wording kept only as "mirror-timing bool" prose without the identifiers).

## Risk

Low. Pure API-shape refactor with identical delete semantics per mode; the three modes are exhaustively matched and the compiler rejects any fourth combination. Production/operator risk: none intended — close reasons 7/8, mirror timing, peer-owner refusal, PPTP forget, NAT releases, and deferred phase-2 intents are preserved per origin. Residual: param count drops only 14→13 (deferred vec retained because PolicyBatch phase-1 collects into a caller-owned batch vec under the abort fence); a follow-up could move it into the variant, but that would change batch ownership semantics.
