# Issue #16111 — in-VM tcpdump captures zero packets for AF_XDP fast-path flows

- **Issue:** Kernel `tcpdump` inside the firewall VMs captures zero packets for live multi-Gbps transit flows on every interface (AF_XDP-bound physical NICs, `.80` VLAN sub-interfaces, `xpf-usp0/1`), so "capture on both nodes" failover plays produce empty files that can be misread as "traffic never arrived".
- **Context read:** Read the complete #16111 body. It offers three fix shapes and prefers (1) documentation: state the blindness in `testing-docs/ha-failover-validation.md` (and the failover skills) and name the working observation points (LAN/WAN host captures, helper statistics deltas, exception/recent-exception records). Shapes (2) per-flow tap/counters export and (3) XDP-path capture are larger dataplane features; this change takes the preferred shape (1) only and does not claim them.
- **Evidence verified in-tree:** `testing-docs/ha-failover-validation.md` is a historical archive (March 2026) that points at `testing-docs/failover-testing.md` as the active runbook, so the warning went into the active runbook plus a pointer banner in the archive. Verified the named telemetry exists: `show chassis cluster data-plane statistics` renders `RX packets`, `Flow cache hits`, `Last resolution`, and `Recent exceptions` (`pkg/dataplane/userspace/format/status_sections.go`); `show chassis cluster data-plane flows` renders the flow-worker map (`pkg/dataplane/userspace/format/status.go`); `monitor interface` renders binding errors and recent exceptions (`pkg/monitoriface/monitor.go`). Verified `.codex/skills/iperf-grpc-tcpdump/scripts/capture_iperf.sh` runs in-VM `tcpdump` on the active firewall (`fw-lan.txt`/`fw-wan.txt`) beside the server-side gRPC capture, so its skill and summary output needed the blindness label. Grepped `testing-docs/`, `.claude/skills/`, `.codex/skills/`, and the HA scripts for `tcpdump`/`capture on both` — no other site instructed in-VM capture of fast-path flows (the security-matrix skill already captures on the destination host).
- **What:** `testing-docs/failover-testing.md` gains an "Observation points" section (mechanism: XDP `xdp_userspace_prog` redirect to the AF_XDP helper before any AF_PACKET tap; scope: `any`, physical NICs, `.80` sub-interfaces, fabric parents, `xpf-usp0`/`xpf-usp1`, `monitor traffic`; rule: `0 packets captured` does not prove the traffic never arrived) and its "When To Use Packet Capture" section no longer lists firewall parents as capture targets. Aggregate helper counters are qualified: they discriminate per flow only for an isolated or controlled workload or when corroborated by host/endpoint captures and `Last resolution`; busy-node per-flow proof requires per-flow counters or session deltas. `.claude/skills/failover-test/SKILL.md` Diagnostics and `testing-docs/ha-failover-validation.md` carry the warning; `.codex/skills/iperf-grpc-tcpdump/SKILL.md` reclassifies `fw-lan.txt`/`fw-wan.txt` as kernel-visible control only with `server-grpc.txt` as wire evidence and stats as corroboration (not standalone per-flow proof); `capture_iperf.sh` emits a `firewall_tcpdump_note=` line in `summary.txt`. `debian/changelog` updated. Docs/skills/script-label only; no dataplane or CLI behavior changes.
