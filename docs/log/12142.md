# 12142 — Validate and transactionally replace the archive keyring

- **Timestamp**: 2026-10-07
- **Branch**: `fix/12142-campaign-pub`
- **Issue**: `install.sh truncates live archive keyring in place without parse, atomic replace, or rollback`
- **Code commit**: this follow-up (`install: preserve package keyring on failed bootstrap (#12142)`)
- **Files**: `scripts/dist/install.sh`, `scripts/dist/test_install_keyring_atomic_12142.py`, `scripts/dist/test_install_url_validate_9921.py`, `scripts/dist/selftest.sh`, `docs/distribution.md`, `docs/log/12142.md`

## Why

`validate()` rejected only the placeholder marker, so a non-placeholder but
unparseable armored key reached installation. `install_keyring()` redirected
the key directly over the live Signed-By file, and failure cleanup had no
keyring rollback state. A later failed install could therefore leave the host
with a keyring that no longer verified the repository.

## What changed

- Validate non-placeholder archive material with `gpg --show-keys` in a fresh,
  private `GNUPGHOME`; require a parsed public-key record and reject secret-key
  material. Missing GnuPG or malformed key data fails before keyring
  installation. Placeholder dry-run behavior is retained.
- Refuse a symlink or non-regular live keyring. Write mode-0644 data to a
  same-directory temporary, sync it, copy any old keyring to a same-directory
  backup, then atomically rename the temporary and sync the containing
  directory.
- On failure, restore/remove the keyring only if the live bytes still match
  the installer's write. If dpkg replaced it with the package-owned keyring,
  leave that payload intact and discard the stale backup. Catch INT, TERM, and
  HUP through the EXIT cleanup. URL-validation and distribution-selftest
  fixtures use parseable throwaway public keys where they exercise a stamped
  installer.

## RED / GREEN proof

Before the implementation, the new transactional test module was run against
base (`python3 scripts/dist/test_install_keyring_atomic_12142.py`): all four
then-present tests failed. The valid-armor/non-key fixture passed `validate`,
the old keyring was overwritten, the rollback fixture retained the replacement,
and the atomic-rename observer saw no rename. A separate temporary probe also
reproduced invalid-key acceptance, overwrite, and missing rollback.

Before the F1 fold, an apt-get shim replaced the live keyring by renaming a
`.dpkg-new` package payload and then exited 100. The re-run case rolled back
over the package bytes; the first-install case removed the package keyring.
Both new cases now preserve the package payload.

After the implementation:

```text
python3 scripts/dist/test_install_keyring_atomic_12142.py  # 13 tests: OK
```

The module covers malformed and secret-key rejection, valid public-key
acceptance, fail-closed behavior without `gpg`, atomic replacement, rollback,
post-dpkg-unpack keyring preservation, refusal paths, failed rename cleanup,
and signal-triggered rollback.

## Risk / residual

Key parsing requires `gpg`; when it is unavailable, installation fails closed
before mutating the keyring, so Tier-A operators must install the documented
prerequisite. INT, TERM, and HUP are routed through EXIT rollback; SIGKILL and
power loss still bypass shell cleanup. The temporary keyring is synced before
rename and its parent directory afterward, but device/filesystem guarantees
beyond those sync calls cannot be promised. A temporary or backup may remain
after an uncatchable interruption. Existing source-list cleanup still removes
a source written by this run rather than restoring a pre-run source; that
behavior is unchanged by this keyring fold.
