# 12142 — Validate and transactionally replace the archive keyring

- **Timestamp**: 2026-10-07
- **Branch**: `fix/12142-keyring`
- **Issue**: `install.sh truncates live archive keyring in place without parse, atomic replace, or rollback`
- **Code commit**: this commit (`install: validate and atomically replace archive keyring (#12142)`)
- **Files**: `scripts/dist/install.sh`, `scripts/dist/test_install_keyring_atomic_12142.py`, `scripts/dist/test_install_url_validate_9921.py`, `scripts/dist/selftest.sh`

## Why

`validate()` rejected only the placeholder marker, so a non-placeholder but
unparseable armored key reached installation. `install_keyring()` redirected
the key directly over the live Signed-By file, and failure cleanup had no
keyring rollback state. A later failed install could therefore leave the host
with a keyring that no longer verified the repository.

## What changed

- Validate non-placeholder archive material with `gpg --show-keys` in a fresh,
  private `GNUPGHOME`; require at least one parsed public-key record and never
  import into the operator's keyring. Missing GnuPG or malformed key data
  fails before keyring installation. Placeholder dry-run behavior is retained.
- Refuse a symlink or non-regular live keyring. Write mode-0644 data to a
  same-directory temporary, copy any old keyring to a same-directory backup,
  and arm rollback before atomically renaming the temporary over the live path.
- On later failure, remove the temporary and restore the prior keyring
  byte-for-byte (or remove the new file on first install); successful cleanup
  removes the backup. The URL-validation and distribution-selftest fixtures
  now use parseable throwaway public keys where they exercise a stamped
  installer.

## RED / GREEN proof

Before the implementation, the new transactional test module was run against
base (`python3 scripts/dist/test_install_keyring_atomic_12142.py`): all four
then-present tests failed. The valid-armor/non-key fixture passed `validate`,
the old keyring was overwritten, the rollback fixture retained the replacement,
and the atomic-rename observer saw no rename. A separate temporary probe also
reproduced invalid-key acceptance, overwrite, and missing rollback.

After the implementation:

```text
python3 scripts/dist/test_install_keyring_atomic_12142.py  # 5 tests: OK
```

The module covers parse-fail without changing prior bytes, valid public-key
acceptance, fail-closed behavior without `gpg`, same-directory atomic rename
with successful cleanup, and byte/mode-preserving rollback after a later
failure.

## Risk / residual

Key parsing now requires `gpg`; when it is unavailable the installer fails
closed before mutating the keyring. An uncatchable termination such as
`SIGKILL` or power loss cannot run the EXIT rollback trap; same-directory
atomic replacement prevents a partially written live keyring, but a temporary
or backup may remain and automatic rollback cannot be guaranteed after such a
termination.
