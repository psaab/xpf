- **Timestamp**: 2026-10-16
  - **Action**: Closed DR5-H13 plaintext-HTTP dynamic-address feed hole (#14385). A plaintext `http://` feed-server body was fetched with no transport integrity and no per-feed signature/hash, so an on-path attacker (or DNS spoof) could substitute an arbitrary body that `installSnapshot` then enforced as policy; the #3934 warning did not prevent substitution. Fix follows the source work-package spec, picking the minimal fail-closed option (no new signature feature): (1) `pkg/config/compiler_validate_strict_observability.go` — `validateDynamicAddressFeedServerEndpointStrict` now rejects an explicit `http://` resolved base URL at strict commit (credential-redacted error; hostname-only servers resolve to `https://` and are unaffected); the shared lenient wrapper downgrades it to a warning so persisted/peer-synced configs still boot. (2) `pkg/feeds/feeds.go` — `Manager.Apply` independently skips a plaintext-http feed server (`isPlaintextFeedURL`, replacing `warnPlaintextFeed`): no worker, no snapshot, so bound address-names stay unresolvable and fail closed per #5645; this is the load-bearing half covering lenient load paths. All existing guards (caps, /0 and whole-space refusals, shrink/churn, pinned dialer, same-origin redirects) are unchanged, and `https://` feeds still install. Two strict fixtures that used `http://` feed URLs only as inert endpoints (`dynamic_address_fail_mode_9689`, `dynamic_address_interval_4879`, plus parser-only `flat_run_residue_9792` / `packed_optin_guard_8768`) were migrated to `https://`. Existing runtime `Apply` tests serving loopback `httptest` servers were converted to `httptest.NewTLSServer` with the fixture certificate trusted via the new lab-only `Manager.SetLabFeedTLSRoots` seam (the HTTPS counterpart of `SetPrivateFeedAllowlist`; production never calls it), since `Apply` deliberately refuses plaintext HTTP. Removed the obsoleted `TestWarnPlaintextFeedPredicate` (#3934 warning predicate).
