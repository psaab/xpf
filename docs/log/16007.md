# #16007 — tiny first fragment stamps flags=0, syn-frag misclassifies (A1-C1)

- **Timestamp**: 2026-10-23
- **Action**: Encode TCP flags-UNKNOWN for a first fragment whose declared
  datagram ends before the flags byte (L4+14) and fail closed in screen,
  session admission, and LocalDelivery caching.
- **File(s)**:
  - `userspace-xdp/src/lib.rs`: `UserspaceDpMeta.tcp_flags_unknown` reuses
    the former `reserved` byte (96B ABI unchanged); stamped in the outlined
    `write_userspace_meta` as `is_fragment && protocol==TCP &&
    payload_offset==l4_offset` — the exact shape `first_fragment_l4`
    returns for declared L4 <14 (every proven-flags TCP parse advances
    `payload_offset` past the header), so no new `ParsedPacket` state.
  - `userspace-dp/src/afxdp/types/mod.rs`: mirror field + offset assert.
  - `userspace-dp/src/afxdp/frame/inspect.rs`: `frame_l4_flags_unknown`
    frame-derived twin (verified L3, declared end, first-fragment walk)
    so slow-path / injected / replayed frames are covered too.
  - `userspace-dp/src/afxdp/icmp.rs`: `meta_l4_flags_unknown` (shim bit OR
    frame re-derivation), the single consumer predicate.
  - `userspace-dp/src/screen/packet.rs`: `ScreenPacketInfo.tcp_flags_unknown`
    + `ScreenParseError::TinyFirstFragmentFlagsUnknown` (`"syn-frag"`).
  - `userspace-dp/src/screen/extract.rs`: fail closed when a TCP first
    fragment's declared end (IPv4 total_len / IPv6 payload_len, never
    capture length) stops before L4+14. Zero declared length (synthetic
    metas with no declared bound) does not manufacture a verdict.
  - `userspace-dp/src/screen/stateless.rs`: defense in depth — unknown
    flags on a first fragment drop as `syn-frag`, never read as tf==0
    (which false-fired `tcp-no-flag` pre-fix).
  - `userspace-dp/src/afxdp/poll_descriptor/session_admission.rs`:
    `strict_syn_check_drops_new_flow[_tunnel]` take `tcp_flags_unknown`
    and drop in every mode, including `no-syn-check` and the tunnel
    opt-out (a stamped SYN is not proven either).
  - `userspace-dp/src/afxdp/poll_descriptor/mod.rs`: gate now also covers
    `LocalDelivery` when (and only when) flags are unknown; proven
    non-SYN LocalDelivery still reaches the local stack. The RST helper
    declines on an unknown-flags frame (its flags are payload bytes).
  - `userspace-dp/src/afxdp/forwarding/local_delivery.rs`:
    `should_cache_local_delivery_session_on_miss` declines to cache on
    unknown flags (packet still delivered; no helper-local session is
    seeded off unseen flags).

## Decisive regression (issue check)

8-byte first fragment (MF=1, offset=0, declared L4=8, SYN in capture
slack) must drop in (a) default, (b) `no-syn-check`, (c) LocalDelivery:

- Screen (a): `screen/tests_16007_tiny_frag.rs` — v4+v6 extractor fails
  closed `syn-frag`; live `stage_screen_check` drop in
  `poll_stages_tests::tiny_first_fragment_dropped_by_live_screen_stage_16007`
  with a legal offset-1 second-fragment control passing.
- Admission (a)+(b): `unknown_flags_drop_in_all_modes_16007` sweeps
  default / no-syn-check / strict / tunnel opt-out.
- LocalDelivery (c): admission gate covers LocalDelivery on unknown
  only + `unknown_flags_never_cache_local_delivery_16007`.
