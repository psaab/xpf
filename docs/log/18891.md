# #18891 — make the verified-original rename fixture non-canonical under RenderLink

- **Timestamp**: 2026-11-02 (`wt-18891`, base `5e65228f29`)

## Why

`TestRenamePositionalRecoversVerifiedOriginal12156` wrote a "non-canonical"
fixture that was byte-identical to the canonical rendering. #17042
(`4f45e4c6f3`) single-sourced `.link` rendering into `networkd.RenderLink`,
whose body (`renderLinkBody`, pkg/networkd/networkd.go:1875-1903)
`\n`-terminates every line including the last. The fixture already carried
that trailing newline, so `networkd.WriteUnitIfChanged` → `writeIfChanged`
(networkd.go:2254-2257) saw an identical file, skipped the rewrite, and the
cell failed at "a non-canonical verified .link must be rewritten, not
skipped". A second, latent fixture bug waited behind it: the `canonical`
literal omitted the very trailing newline `RenderLink` emits, so the
byte-exact comparison would have failed once the rewrite happened. Both are
fixture bugs; production is correct (the pre-`#17042` `writeLinkFile` body,
verified from `534645b1aa`, ended `Name=%s` with no trailing newline — the
old writer's stripped body is what a genuinely non-canonical on-disk file
looks like).

## What

- The `chained` fixture is now the exact pre-#17042 body: same minimal
  chain, no trailing newline — genuinely off-canonical, so the pass must
  rewrite it.
- The `canonical` literal gains the trailing newline `renderLinkBody`
  always emits.
- Byte-exact `!=` comparison kept; no `Contains`/`TrimSpace` weakening.
- Test-only change; no production code touched.

## Validation

- RED at base: `linksetup_originalname_12156_test.go:389` (in the pre-fix
  numbering) — rewrite skipped because fixture == canonical bytes.
- GREEN after: the named cell via
  `./scripts/testguard-run.sh go test ./pkg/daemon -run '^TestRenamePositionalRecoversVerifiedOriginal12156$' -count=1`,
  plus all 17 neighbouring cells in the same file (18/18 `--- PASS`).
- Mutant 1 (cell can still fail): making `renamePositional` skip
  `writeLinkFile` when the NIC already wears its final name reds the cell at
  "a non-canonical verified .link must be rewritten, not skipped".
- Mutant 2 (canonical literal is live): corrupting `renderLinkBody`'s
  `[Link]` skeleton reds the byte-exact compare; the failure text also
  shows the written bytes ending `Name=fxp0\n`.

## Risk

Test-only. The cell now fails if the positional pass stops rewriting a
verified-original `.link`, or if the rendered body drifts from the pinned
canonical bytes.
