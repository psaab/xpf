# #17198 — R4-Q38-02: REST/gRPC MatchPolicies hand-built validation, Query assembly, projection

- **Timestamp**: 2026-10-27
- **Defect (live on origin/master 8064ca090e)**: Five operator builders
  hand-assembled `policymatch.Query` and hand-projected `Result`.
  Divergence 1: gRPC `MatchPolicies` returned the cfg==nil default-deny
  before any grammar check (probe on master: no-config `{}`, bad src_ip,
  dst_port 70000, protocol tcpp all returned `deny (default)` err=nil),
  while REST rejected them 400 after #3709. Divergence 2: REST
  `MatchPoliciesResult` had no `unsupported_tuple_family` field (gRPC/CLI
  got the typed bit in #5720); REST clients had to string-match `action`.
  Publication-debt loop was copied in security.go, server_cluster.go,
  server_show_firewall.go (cli.go had the only helper).

## What

- `pkg/policymatch/request.go` (new): `Request` (decoded selectors),
  `(Request).Validate(cfg)` — config-independent checks (zones→IPs→
  protocol→ICMP range) first, ingress-interface only with live cfg;
  `Live{Feeds,FeedOverlay,PolicyInactiveForFn}` + `FeedInfos` adaptor +
  `Live.PublicationDebt()` (the one debt loop); `Assemble(cfg,Request,Live)`
  owning family threading (#6377) + debt; `Evaluate` (validate → nil-config
  default-deny → Match); flattened `Verdict` + `VerdictFrom(Result,…)`
  including `UnsupportedTupleFamily`/`ContentRejectionReasons` and the
  per-branch field selection. `policymatch.Match` untouched.
- `SelectorArgs.Query` retired as a hand builder: now `Request()` +
  `Assemble` (kept as test/offline shim over the shared path).
- REST: transport grammar (duplicate/unknown keys, present-empty ports,
  bool flag) decoded locally, then shared Validate (historical REST wording
  remapped), shared Assemble via `matchLive` (applied-scheduler latch),
  `verdictToREST(VerdictFrom(...))`; `MatchPoliciesResult` gains
  `unsupported_tuple_family`. JSON tags/order otherwise unchanged.
- gRPC MatchPolicies + showTestPolicy, local CLI show/test: same shared
  Validate/Assemble/Verdict path (`verdictToProto`, `matchLive`);
  showTestPolicy's deliberate cfg==nil-before-grammar text ordering and
  the ContentRejectionReasons REST/local-only asymmetry preserved.
- Acceptance greps: `policymatch.Query{` in pkg/api|grpcapi|cli = 0;
  `info.PublicationDebt` count in the three server files = 0.

## Risk

Low-medium. Simulator semantics unchanged (Match untouched); the only
behaviour changes are the two intended convergences: gRPC boot-window
malformed queries now InvalidArgument instead of default-deny, and REST
JSON gains `unsupported_tuple_family:true` on that verdict. Per-branch
projection field sets were preserved branch-for-branch in VerdictFrom;
pinned by the adjacent named cells above. CLI feedPublicationDebt now
returns the shared (possibly empty non-nil) map — callers only test
membership/len.
