# #15191 (D03-01) — synced static-NAT / NPTv6 sources booked into the interface registry

- **Timestamp**: 2026-10-19
- **Action**: A peer-synced session whose translated source no pool
  owns fell through to the interface-mode arm
  (`reserve_synced_interface_identity` via `allocator_for`), so every
  distinct static-NAT external or NPTv6 external address imported on
  the standby retained one interface allocator. Past the 256
  retained-allocator cap, further imports were refused and local
  interface-SNAT admissions failed with `InterfaceRegistryCap`.

## Fix

- `userspace-dp/src/nat/source/synced.rs`: new
  `SyncedSourceNatDomains` (the synced entry's `source_nat_static`
  provenance, the local static table's `StaticExternalIdentities`,
  and the local NPTv6 external prefixes), resolved by each caller
  from the same forwarding generation as the rules. The core reserve
  now returns `true` (nothing to reserve, nothing to refuse) when
  the translated source is an NPTv6 rewrite (`nat.nptv6`, or an
  address inside a local NPTv6 external prefix when the bit was not
  carried) or a static-NAT external (static provenance, or — for an
  unknown-provenance peer — an address the local static table owns).
  Threaded through the coordinator import, the worker
  `upsert_synced`, the rollback-restore path, and every test caller
  (`SyncedSourceNatDomains::default()` preserves prior behaviour
  there). Release/rollback need no twin change: nothing is booked,
  so the existing lookup-only release stays a no-op.
- NOT changed: pool reserves, the #14674 interface-first route, the
  #15146 cross-domain checks, PASS 2 drift fall-through for dynamic /
  unowned addresses (still books the interface identity), and the
  wire format (the `nptv6` bit already rides `NatDecision`; the
  prefix check covers peers/builds that did not carry it).

## Verification

- **RED** on base (test-only, signature adapted): the static and
  NPTv6 cells fail — imports retain interface allocators
  (`retained != 0`), imports past 256 are refused, and the local
  interface admission control flips from `Matched`.
- **GREEN** post-fix: `tests_synced_static_nptv6_15191` (7 cells:
  static single + 257-cap, NPTv6 single + 257-cap, interface control,
  unknown-provenance static control, dynamic-unowned control).
- **Neighbours**: `tests_synced_iface_15146`, `tests_pool`,
  `tests_iface`, `ha_tests` callers updated to the new signature with
  default domains; their semantics are unchanged.
- Note: `cargo test` on current master is blocked by a pre-existing
  E0063 in `afxdp/mirror/mod_tests.rs:1032` (tracked as #15520,
  `MirrorConfigSnapshot` literal missing `ingress_vlan_id` /
  `unit_scoped`); a one-line local literal fix unblocks the build
  and is NOT part of this change.

## Risk

- A synced import whose translated source is claimed static/NPTv6
  but is actually interface SNAT (provenance lying, or a static /
  NPTv6 rule deleted on the standby only) now books nothing instead
  of an interface identity — the same graceful-drift posture PASS 2
  already takes for pool drift, and the session still publishes.
  Dynamic-provenance and genuinely unowned addresses are untouched.
