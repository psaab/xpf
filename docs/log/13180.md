# #13180 — preserve retained-zone host-inbound policy

- **Timestamp**: 2026-10-15
- **Action**: Fix D6-06 shared-ifindex host-inbound sentinel clobber.
- **File(s)**: `userspace-dp/src/afxdp/forwarding_build/interfaces.rs`, `userspace-dp/src/afxdp/forwarding_build/tests.rs`
- **Validation**: New regression RED on pristine `origin/master`; focused and forwarding-build tests GREEN. Full crate suite has one protocol wire-fixture mismatch that also reproduces on pristine `origin/master`.
- **Risk**: Minimal; only removes an automatically-created deny sentinel when the final shared ifindex has a valid zone. An unzoned ifindex remains fail-closed, and explicit interface overrides remain untouched.

## Why

An unzoned tunnel base row can share its kernel ifindex with a zoned logical unit. While iterating snapshot rows, the base row installs a deny-all `ifindex_host_inbound` sentinel; the unit then establishes a valid `ifindex_to_zone_id` entry, but the sentinel used by `host_inbound_admits_iface` previously remained and shadowed the zone-level host-inbound policy.

## What

After the row walk, prune the automatically-created empty-zone sentinels for ifindexes that ultimately retained a valid zone, removing their deny-all map entry as well. Sentinels on indexes that remain unzoned are retained. Added shared tunnel base/unit coverage for both snapshot row orders (zone-level ping/BGP admitted, ssh denied), explicit interface-override precedence, and an unzoned tunnel control that must continue to deny host-bound ssh.

## Validation

- RED before the production fix, on the clean worktree at the original branch base `ab0498643`: `cargo test --manifest-path userspace-dp/Cargo.toml unzoned_tunnel -- --nocapture` failed the new regression because the empty sentinel remained on the retained-zone ifindex (1 failed, 4 passed).
- GREEN after the fix and expanded coverage: `cargo test --manifest-path userspace-dp/Cargo.toml unzoned_tunnel -- --nocapture` passed (5 tests).
- `cargo test --manifest-path userspace-dp/Cargo.toml afxdp::forwarding_build::` passed after the final test expansion (289 passed, 1 ignored).
- Full crate suite on the PR branch: 7910 passed, 1 failed (`protocol::tests::wire_invariant_default_specimens` reported wire-format drift against `protocol_wire_v1.json`), 8 ignored. The same test failed on a pristine worktree at the PR's actual base `ab0498643` (0 passed, 1 failed) and on clean later `origin/master` `7d49fff` (0 passed, 1 failed), with the same wire-format drift. This establishes the full-suite failure was present at the branch base, not introduced by this PR.

## Risk

The cleanup is limited to the sentinel-origin set, so it cannot remove a configured interface override. Existing contested/refused/unzoned-child sentinel paths run after the cleanup and retain their own final-zone guards.
