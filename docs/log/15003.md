# #15003 — memoise address-set graph gate and expansion (A04-02)

- **Timestamp**: 2026-10-19

## Red before

The #12832 address-set graph gate (`validateAddressSetGraphNode12832`) and the
pre-#15003 expansion recursion (`expandAddrSetMode`) enumerated every DAG
path with no memo, and the strict validator re-ran the gate once per root
set. With the depth cap at 5 nested edges and breadth B per tier the cost
grows as ~B^6 across all roots: a legal 741-line lattice (breadth 20, six
tiers, longest path exactly 5 edges) cost ~5.5s per compile on commit,
commit check (under the store read lock), boot load and SyncApply.

Fresh-binary reproduction on the unmodified worktree (test binary rebuilt
after the source edits were confirmed by mtime; earlier probe results in
this lane came from stale binaries and are superseded):

- `TestAddrSetGraphGateMemoised15003`: strict gate passed (41ms on the
  already-memoised gate) but leaf-mode expansion of the breadth-20 lattice
  did not finish within the 10s budget — `expandAddrSetMode is not
  memoised`.
- Two further defects were found in the partial memo implementation before
  it could be trusted (see Change): leaf-mode `address-set` edges were
  mis-classified, and memo-hit depth checks were missing.

## Change

One memoised DFS pass with per-node max-depth-below (height) recording,
applied to both walks. Cycle and depth diagnostics are unchanged: depth
errors still name the first over-deep node in DFS pre-order, and no result
computed under one ancestor path is served as a success under a deeper one.

- **Gate** (`addrset_graph_validate_12832.go`): `addrSetGraphMemo15003`
  records `heights[name]` (max nested edges below `name`) only after the
  subtree validates cleanly. Re-entry runs the node's own
  `addressSetForExpansion(depth)` entry check (depth/cycle vs. the live
  path) *before* consulting the memo, then decides the cap arithmetically
  (`depth+height`); on overflow `depthErrorBelow` reconstructs the exact
  first-node-wins error the naive walker would produce. The strict
  validator now validates every root against one shared memo
  (`validateAddressSetGraphForBook15003`) instead of re-walking per root.

- **Expansion** (`predefined.go`): `addrSetExpandMemo15003` records the
  deduped result **and subtree height per mode** (ID-graph vs.
  leaf/cross-kind), because the two modes give the same node different
  results and heights, and one top-level call can complete a node in both.
  Two bugs in the partial implementation were fixed:
  1. **Leaf-mode setEdges divergence (probe5's `[] bodies=1`, confirmed
     real on a fresh binary).** Edges were partitioned by the child's
     expansion mode (`crossKind` flag). In leaf mode *every* child is
     leaf-expanded, so `address-set` edges (constructed with
     `crossKind=resolveCrossKind=true`) were mis-bucketed as cross-kind
     edges; the member-position interleave then skipped them and the
     expansion returned only direct members. Edges now carry an explicit
     `viaAddr` kind tag and are partitioned by kind; child mode is tracked
     separately per edge.
  2. **Missing depth synthesis on memo hits.** On a memo hit the partial
     code returned the cached result after only the node's own entry
     check, so a subtree memoised via a short path was served into a
     deeper context where its deepest node exceeds the cap (naive rejects,
     memo admitted — reproduced by the `tradeoff` differential cell and
     the `top -> c1..c4 -> deep -> bottom` cell). Memo hits now compare
     `depth+entryHeight` against the cap and reconstruct the naive error
     via `depthErrorBelow` (longest-path-first descent in naive traversal
     order, reported through `addressSetForExpansion`). Heights are
     recorded incrementally from child entries at body completion — the
     previous recursive `heightOf` re-walk was removed.

- `expandAddrSetMode`/`expandAddrSet` are removed; `ExpandAddressSet` and
  `expandAddressSetLeaves` route through the memoised expander. The
  `bodies` counter on the memo exists so the guard asserts the linear
  curve (≤1 body per set per mode) rather than a wall-clock number alone.

- **Docs**: `pkg/config/README.md` records the memoised gate/expansion,
  the per-mode height recording, and that depth errors still name the
  first over-deep node in DFS pre-order.

## Validation

All runs on a freshly compiled test binary (`go test -c` after confirming
source mtimes precede the binary; `gofmt -l` clean, `go vet` clean):

- `TestAddrSetGraphGateMemoised15003|TestAddrSetMemoPreservesSemantics15003|TestAddrSetExpansionIsLinear15003`:
  all PASS. Breadth-20 lattice strict-validates in ~1ms (acceptance: <1s);
  leaf expansion returns `[leaf]` with 101 bodies for 121 sets (one body
  per set; naive executes ~B^5 — breadth 3: 16 memoised vs 364 naive
  bodies); ID-graph expansion bodies=1 (root returns the 20 tier-1 names
  without expanding children, matching the pre-fix ID-graph contract).
- Differential coverage (`TestAddrSetExpansionIsLinear15003`): memoised vs.
  an in-test naive recursion agree on results *and* error text for the
  lattice, a depth-tradeoff graph (same subtree entered shallow and via a
  detour), cross-kind/address-set mixes, and a shadowed set name.
  `TestAddrSetMemoPreservesSemantics15003` pins the exact cycle message
  (`cycle detected in address-set "spin"`) and depth message
  (`address-set nesting too deep (max 5): bottom`) through shared prefixes.
- Controls: `go test -run 'TestCrossKind'` — all PASS (12502 resolution,
  bounds, collision precedence, Junos-host deny rendering, static-NAT
  prefix-name; 12832 strict bounds). Address-set family
  (`TestAddrSet|TestCrossKind|TestAddressSet`) PASS.
- Full `pkg/config` suite: 113 unique failing tests on this branch, and
  the identical 113 (set-compared with `comm`) on a clean worktree of the
  branch base (`27920f2f8c`, same commit, no changes) — all pre-existing
  base failures (IPsec/tunnel/schema families), zero regressions and zero
  address-set failures. Note the suite must run from `pkg/config`
  (shipped-config fixtures use package-relative paths).

## Risk

Strict admission keeps exactly the pre-fix accept/reject answers and error
texts (differentially verified); the only behavioural change is wall-clock
on wide DAGs. Tolerant load retains its warning downgrade. No dataplane
ID-graph behaviour changed (`ExpandAddressSet` still returns direct member
names). Cached results are handed out as copies, so callers that dedupe
into their own slices cannot alias memo state. No live-cluster mutation
was performed.
