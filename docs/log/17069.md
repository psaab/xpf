# #17069 — Derive Tick.secs from ns via the single Tick::from_ns constructor

- **Timestamp**: 2026-10-27
  - **Action**: STEP-0 verified live on master (`8fdb112b3f`): the `Tick` doc in `session_glue/promote.rs` claimed "`ns` and `secs` travel together at every resolve/teardown site", but 13 production constructions zero-filled `secs` (6 in `poll_descriptor/mod.rs`, 1 in `session_glue/tx_cancel.rs`, 1 in `worker/loop_body/gc_teardown.rs` test seam, 3 in `worker/loop_body/mod.rs`, 2 in `worker/loop_body/reconcile.rs`) and `SharedSessionRefs::detached` used `Tick::default()`. Proved from consumers that `secs` is not dead: the sole reader is the resolve path (`resolve.rs` reads `shared.tick.secs` into `should_keep_synced_hit_transient` and the HA `is_forwarding_active` checks), while teardown/housekeeping consumers read only `tick.ns` — exactly the latent trap the issue describes (a future teardown `secs` reader would evaluate HA leases at time 0, fail-open). Removed `Default` from `Tick`, added `Tick::from_ns(ns)` as the only production constructor (`secs = ns / 1_000_000_000`, matching every existing `now_secs = now_ns / 1_000_000_000` derivation at the call sites), converted all 14 production literals (13 zero-filled + the deferred-promotion copy-forward in `promote.rs`, now deriving from `promotion.now_ns`) and the 2 correctly-paired poll sites to it, and made `detached` use `Tick::from_ns(0)`. The correctly-paired sites pass the same `now_ns` the caller already paired with `now_secs` (identical value, one less independently-sampled clock). Test literals were converted value-for-value: derived pairs to `from_ns`, deliberately decoupled HA-lease fixtures (e.g. `ns: 1_000_000, secs: 1_000` against a lease expiring at 500) to a `#[cfg(test)] Tick::from_parts` that production cannot call. Added `tick_from_ns_derives_secs_17069` (pins `from_ns(2_500_000_000).secs == 2` and the floor boundary) and `tick_no_literal_construction_17069` (structure guard over the six production files that construct `SharedSessionRefs` ticks: no `Tick {` literal, no `Tick::default`, no `secs: 0` outside doc prose), both in `shared_session_refs_16185_tests.rs` where the acceptance names it, plus the header note recording that no 16185 cell observes a `secs` consumer. Updated the `Tick` doc to the real semantics and the `session_glue/README.md` bundle description.
