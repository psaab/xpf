# #13275 — skip nil config slots in Prometheus metrics collectors

- **Issue**: #13275 — source finding D1-03 (`review-work.AYgyxCmMxC`).
- **Branch**: `fix/13275-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-13275`
- **Base**: `802eda508` (`origin/master`)
- **PR**: #13509.

## Why

Lenient config restore and HA peer-sync can leave present-but-nil map values
or slice slots in active config. `collectFilterCounters` dereferenced nil
filters and terms, and `collectNATPoolMetrics` dereferenced nil source pools.
A single slot therefore panicked a Prometheus scrape and hid all collected
metrics.

## What

- Skip nil firewall filter map entries and nil or unnamed term entries in the
  filter metrics collector, preserving sibling samples.
- Skip nil source NAT pool entries in the NAT metrics collector.
- Add regressions for nil `inet`/`inet6` filters, terms on both map-counter and
  userspace-counter paths, and NAT pools, each with valid sibling data.

- **GREEN**: the targeted command passes on the issue branch.

## Risk

Nil config slots are intentionally omitted because they have no meaningful
counter or pool data. Valid entries and their metric labels remain unchanged.
