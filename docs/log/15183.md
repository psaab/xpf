# #15183 — restore the QNH metric overlay after a failed FRR reload

- **Timestamp**: 2026-10-19
- **Action**: run the QNH metric reconcile on the two reload-failure
  returns that previously skipped it, so a failed `frr-reload.py
  --reload` no longer leaves the backup static exported at the default
  OSPF external cost.

## Why

The QNH `set metric N` action is a memory-only ospfd overlay: the
integrated `frr.conf` route-map is deliberately metric-free (#12071),
and the manager installs the metric into ospfd after a reload.
`frr-reload.py` computes a diff against the file and deletes running
lines that are absent from it — including that overlay — *before* it
applies the rest of the diff. When a later line is rejected, the reload
exits non-zero with the overlay already deleted.

Two return paths then skipped the restore:

- `reloadLocked`: when both `frr-reload.py` and the additive
  `vtysh -f` fallback failed, the hard-failure return ran before
  `reconcileQNHMetricOverlaysLocked`.
- `retryReloadOnce`: a failed degraded-retry attempt returned before
  its reconcile.

The backup static was therefore exported into OSPF at the default
external cost — tying with or beating the primary exporter
network-wide — for as long as the rejected line persisted.

## What

- `pkg/frr/manager.go` (`reloadLocked`): on the hard-failure return,
  still run `reconcileQNHMetricOverlaysLocked`. A reconcile error is
  joined to the original load error (`%w (... additionally ... %w)`),
  so both the vtysh and the underlying primary causes stay
  `errors.Is`-visible (the #9947 pytools-missing classification is
  preserved) and the hard failure still propagates — no degraded
  sentinel, no claimed convergence.
- `pkg/frr/manager.go` (`retryReloadOnce`): on a failed retry attempt,
  still run the reconcile; a reconcile failure is logged and the
  attempt still returns `(false, notFound)` — the episode stays
  degraded and keeps retrying, but the overlay is restored now rather
  than only after an eventual convergence.
- Corrected the stale lifecycle claims that said QNH cleanup/replay
  only runs after a successful load: `commitManagedSection` and
  `noteReloadOutcomeLocked` comments, the `applyFRRFull` comment in
  `pkg/daemon/daemon_apply_routing.go`, and the QNH lifecycle bullet in
  `pkg/frr/README.md`. No pre-clear was added — cleanup still never
  runs before a load; only the post-attempt reconcile now also covers
  the failure returns.
- `pkg/frr/qualified_nexthop_metric_failed_reload_15183_test.go`: a
  stateful executor models ospfd's route-map state, where a config
  load replaces daemon state with the metric-free file state (the
  delete-before-fail mechanism). Both defect arms assert ospfd keeps
  `set metric 10` after the failed reload; controls assert the
  fallback-success path still reconciles, a later successful retry
  still converges and clears the degraded gauge, and the original
  error causes stay visible.

NOT changed: the reconcile itself, the overlay rendering, the
degraded-retry cadence/classification, and the success/additive paths
(they already reconciled).

## Validation

- RED on `origin/master` (0020495f5f): both new tests fail with
  `ospfd route-map ... sequence 10 metric = 0, false; want 10, true
  (overlay lost on failed reload)` — one per defect arm.
- GREEN after the fix: `go test ./pkg/frr/ -run
  'TestQNHMetricSurvivesHardReloadFailure15183|TestQNHMetricSurvivesFailedDegradedRetry15183'
  -count=1` passes.
- Full `go test ./pkg/frr/ -count=1`: only the 4 pre-existing BGP
  failures (`TestBGPNoExportNeighborGetsDefaultExport15157`,
  `TestFamilylessIPv6NeighborWithoutPolicyIsV6Only11564`,
  `TestFRRLoadInet6OnlyNeighborIPv4Deactivation11374`,
  `TestFRRLoadBGPClasslessRIBSuppression11426`), each reproduced
  identically on pristine `origin/master` (0c468f7f4a) — base-attributed,
  unrelated to this change.

## Risk

- A reconcile that itself fails on the hard-failure path now surfaces
  in the returned error (joined, never replacing the original), so an
  operator sees both the reload rejection and the overlay-restore
  failure. On the retry path a reconcile failure only logs — the retry
  cadence and degraded signalling are unchanged.
- The real-FRR live criterion (a rejected line keeps `set metric` in
  `vtysh -d ospfd show route-map`) rides the existing root-gated live
  QNH harness; it is not exercised in this lane's unit runs.
