# #17816 — publish config generation and ACK capability as one debt

- **Timestamp**: 2026-10-28
- **Action**: The stale gate read `lastSentConfigGen` and the send-time ACK
  capability from separate atomics, so a handover could observe a new
  generation with the previous legacy capability. The generation also
  survived peer-incarnation retirement while its capability was cleared,
  causing an ACK-capable peer's outstanding debt to pass during reconnect.
  Replaced the split fields with one mutex-protected
  `lastSentConfigDebt16756` snapshot containing generation, whether
  capability was learned, and ACK support; the stale gate and ACK/NACK
  scope checks now read that snapshot. The debt intentionally survives
  disconnect until a successor ACKs or explicitly advertises a legacy
  capability set; an unknown capability state is not proof of a pre-ACK
  peer and stays fail-closed. Capability flags publish before the
  learned-incarnation marker so the gate cannot mistake an in-progress
  modern advertisement for a legacy peer. Added a fail-on-revert cell
  for publication interleaving, unknown capability, disconnect/reconnect
  persistence and the pre-ACK control arm.
