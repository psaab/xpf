# #17816 — publish config generation and ACK capability as one debt

- **Timestamp**: 2026-10-28
- **Action**: The stale gate originally read the sent generation and its
  send-time ACK capability separately, allowing a handover to observe a new
  generation with the previous legacy capability. The generation also
  survived peer-incarnation retirement while its capability was cleared,
  which could let an ACK-capable peer's outstanding debt pass after reconnect.
  Replaced the split fields with one mutex-protected
  `lastSentConfigDebt16756` snapshot containing generation, whether
  capability was learned, and ACK support; stale-gate and ACK/NACK scope
  consumers read that snapshot. The legacy NACK generation is also
  SessionSync-lifetime peer debt now, so retirement cannot erase a matching
  NACK while the generation survives.

  Ungated config sends now hold `peerSnapshotProtocolWriteMu` across capability
  sampling, debt publication, and the final socket write, matching the guarded
  send's serialization. `PeerConfigStale` honors a current ACK-capable
  successor even when the send-time snapshot was legacy, requiring a positive
  ACK instead of taking the NACK-only path. Unknown capability remains
  fail-closed; a proven legacy peer retains its NACK-only fallback.

  The publication hook parks after assigning the complete debt while its
  mutex is still held. A gate reader is started during that critical section
  and must wait to observe the complete snapshot after unlock. Because the
  snapshot is assigned as one struct value, this exercises the lock boundary
  rather than a partially-written in-memory struct. Regressions cover legacy
  NACK retirement and capability changes racing an ungated socket write.
