# #13703 — publish scheduler receipt before version

## Why

`SchedulerHeartbeatLease::apply` exposed a nonzero version with the prior
receipt timestamp because the successful version CAS came first. A worker
could then see an expired lease during a heartbeat update and fail-close a
scheduled permit.

## What

- Store `received_at_ns` before release-publishing `version`; a reader that
  acquires the published version also observes the preceding receipt stamp.
- Treat a `now_ns` sampled before a concurrent heartbeat's newer receipt stamp
  as fresh rather than expiring it. This avoids the inverse mixed snapshot
  (older time with newer stamp) failing closed spuriously.
- Preserve rejection of version zero and rollback. `ServerState` serializes
  control requests, so publication does not need a competing-writer CAS loop.
- Add concurrent publication-invariant and deterministic pre-heartbeat-time
  regressions.
- Not changed: other scheduler-policy paths; all use this lease object and
  share the same publication method.

## Validation

The first targeted attempt used `--exact` with an unqualified test name and
was blocked before execution by a master compile error: `afxdp/session_glue/mod.rs`
imported `purge_translated_synced_hit` outside its `#[cfg(test)]` definition.
After rebasing on `f4da6b3c8`, that import was fixed. The regression was
rerun without `--exact`, but the current tree failed to compile because
`src/afxdp/cos/mod.rs` is missing; Cargo also reported missing dependency
information from the isolated target directory. Neither the focused regression
nor the full crate suite executed successfully. RED/GREEN and reversion
evidence remain unavailable.

## Risk

No new timestamp/version atomic aggregate is introduced. The writer remains
serialized by the `ServerState` contract. Regression runtime and crate-suite
behavior remain unverified because unrelated master source is incomplete at
this head.
