# Issue #13287: Export NPTv6 translation telemetry

Source: deep-review monitoring/telemetry report D3-15, validated by the
three-way research gate. The NPTv6 datapath had no counters for successful
inbound/outbound translations or fail-closed `Untranslatable` drops, leaving
operators unable to observe normal translation volume or diagnose rejected
packets.

The helper now keeps shared atomic aggregate counters in `Nptv6State`, records
outcomes at actual packet-decision sites (including flowless and fragment retry
paths), carries the counters through forwarding-state replacement, and publishes
inbound, outbound, and untranslatable totals through `ProcessStatus`. Go exports
those fields as `xpf_userspace_nptv6_translations_total{direction=...}` and
`xpf_userspace_nptv6_untranslatable_drops_total`.

Validation: the regression failed to compile on pristine master because
`Nptv6State` lacked the counter API. Post-fix, `cargo test nptv6_` passed (24
tests) and `cargo test process_status_nptv6` passed (1 test); the focused Go
status/metric test passed. The combined Go package run was attempted but failed
in unrelated package tests, including `TestVRFOverlapAdmittedEmittedWhenDataplaneUnloaded_7991`
in `pkg/api` and multiple config/parity tests in `pkg/dataplane/userspace`.
