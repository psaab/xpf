# #13196 — preserve reinject state across target publication

- **Timestamp**: 2026-10-15
  - **Action**: confirmed D1-05 in the source: `xpf-reinject-target` polled `ServerState` every millisecond and transferred only authority to a replacement `ReinjectCore`, stranding admitted entries and losing ordering/tombstones/provenance/stats. A regression run against the unchanged production implementation failed as expected: the source core had one live entry but the replacement had zero.
  - **Change**: made `Coordinator` own the shared `ReinjectCore` and target slot. Slow-path construction receives that core; reconcile and teardown synchronously publish target changes. Removed the polling thread, cross-core authority copy from production, and the now-unneeded handoff mutex. Both socket listeners and every replacement target therefore refer to the same in-flight state.
  - **Validation**: added production-coordinator regression `coordinator_target_publication_preserves_live_reinject_state`, asserting that the coordinator-owned core with a live entry is the core used by its published slow-path target. It passes in this fix; on pristine master at `f7492bd5c`, the exact regression fails to compile because the coordinator has no `reinject_core`, `reinject_target`, or `publish_reinject_target` seam. The original regression had passed but did not catch that missing production integration. `cargo test reinject_9506` passed (77 tests); `cargo build` passed. Full `cargo test` ran 7,923 tests: 7,914 passed, 8 ignored, 1 failed (`protocol::tests::wire_invariant_default_specimens`). The same fixture-drift failure was reproduced on pristine `origin/master` at `722b85f`, so it is unrelated to this change.
