# #12913 — policy_scheduler_validate.py lacked an inactive-window traffic witness, coerced boolean counters, and skipped failover byte monotonicity (D10-12)

- **Timestamp**: 2026-10-14
- **Action**: `test/incus/policy_scheduler_validate.py` required active
  traffic, active→rebuild packet/byte monotonicity, exact
  inactive==rebuild counters, and a failover packet delta — but nothing
  proved traffic was *offered* during the inactive scheduler window, so an
  inactive-status.json copied verbatim from rebuild-status.json passed with
  zero probe traffic (the flat scheduled-rule counter was vacuous: the
  #1378 story is that the window closing moves the flow to the fall-through
  rule, which is only observable if a probe ran). `_as_int` coerced JSON
  `true` to `1`, so a boolean `packets` field satisfied
  `min-active-packets`, and it silently defaulted unparseable counter
  values to zero instead of failing closed. The failover leg required the
  packet count to advance on the new userspace owner but never checked
  bytes, so a bytes regression (counter loss across the failover) passed.
- **Fix**: the validator now consumes the inactive-window traffic witness
  that the #1378 live procedure already captures,
  `inactive-traffic.stdout` (default name, overridable via
  `--inactive-traffic`): exactly one ping statistics block, at least
  `--min-inactive-packets` (default 1) packets offered, and a decisive
  outcome — full success (`received == transmitted`, `0%` loss: traffic
  traversed the box while the scheduled rule stayed flat, i.e. the
  fall-through rule took it) or full deny (`0` received, `100%` loss:
  offered and denied while inactive); partial results fail closed as
  ambiguous. The parsed witness is echoed into the PASS summary as
  `inactive_traffic`. `policy_rule_counters` `packets`/`bytes` must now be
  non-negative JSON integers (`_counter_int`: rejects bool, string, float,
  negative — no coercion, no silent zero defaults), the failover leg
  additionally requires `failover.bytes >= rebuild.bytes`, and `_as_int`
  (now version-gate only) no longer coerces booleans.
- **Fail-closed direction**: every new check only rejects: a missing,
  empty, multi-summary, zero-offer, or partial-loss inactive witness now
  fails (previously ignored); boolean/string/float/negative counters now
  fail (previously coerced or zeroed); a failover byte regression now fails
  (previously ignored). No previously-failing artifact starts passing
  except none — the accepted live #1378 evidence set passes unchanged
  because it already contains the witness (3 transmitted / 3 received /
  0% loss, `scheduled-allow` flat at 5/490 while `lan->wan/allow-all`
  advanced 94→95).
- **Validation**: `python3 test/incus/policy_scheduler_validate_test.py` —
  15/15 GREEN on this head (6 pre-existing + 9 new/updated). New cells:
  witness missing, zero probe offer (`0 packets transmitted`), ambiguous
  partial loss (3/1, 66%), no statistics block, decisive-deny acceptance,
  boolean `packets`, string `bytes`, failover bytes regression, and the
  full-evidence summary assertions.
- **RED proof**: on pristine `origin/master 74efaaeb2` (master validator +
  new test file in a scratch dir) the suite reds exactly the 9 new/updated
  cells — 7 failures (`ValidationFailure not raised`: zero-offer,
  ambiguous, no-stats, witness-missing, boolean, string-bytes, failover
  bytes) + 2 errors (summary `inactive_traffic` KeyError in the two
  positive cells) — while the 6 pre-existing tests stay green. Live set
  re-validated on the fix head:
  `python3 test/incus/policy_scheduler_validate.py
  docs/pr/1373-retire-ebpf-dataplane/evidence-1378-policy-scheduler-live-20260519
  --rule-id 'lan->wan/scheduled-allow'` → `PASS` with
  `inactive_traffic: {transmitted: 3, received: 3, loss_pct: 0.0,
  outcome: allowed}`; `--min-inactive-packets 5` against the same set fails
  closed with exit 1.
- **Risk**: test-tooling only — no production dataplane change. Evidence
  sets captured without `inactive-traffic.stdout` now fail closed until
  the probe output is added (the accepted #1378 set already ships it).
  Residual: the witness proves the probe ran and was decisive, but cannot
  bind the ping runtime to the counter snapshot instants (no timestamps
  are cross-checked), and full-deny acceptance means a box that denies
  because forwarding broke would still pass the witness leg — the
  userspace-runtime checks on the inactive status remain the control for
  that.
