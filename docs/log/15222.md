# Preferred address inert for source selection (#15222, A37-03)

- **Issue**: #15222 — the interface `preferred` leaf did not select the
  source address for locally originated same-subnet traffic.
- **Cause**: `generateNetwork` in `pkg/networkd/networkd.go` ordered only
  `PrimaryAddress` first and rendered the preferred address as a plain
  `[Address]` section with `PreferredLifetime=forever`. That lifetime is
  an IPv6 valid/preferred-lifetime knob: it never chooses an IPv4 source
  and does not order same-subnet IPv6 either, so the kernel kept picking
  the first-added address in the subnet. The compiler also stored only
  one `PreferredAddress` per unit, with `family inet` last-wins while
  `family inet6` was first-wins.
- **Change**:
  - `pkg/networkd/networkd.go`: after primary ordering and the per-family
    DHCP gate, `orderPreferredFirstPerSubnet` moves the preferred address
    to the front of its own subnet group (keyed by the masked CIDR
    network via `subnetKey15222`), preserving every other address's
    relative order. A preferred in another subnet never jumps ahead of
    this subnet, distinct `/25` halves are not merged, and no
    `PreferredLifetime`/`[Address]` section is emitted any more — all
    addresses render as plain ordered `Address=` lines.
  - `pkg/config/compiler_interfaces.go`: `family inet` preferred is now
    first-wins (`&& unit.PreferredAddress == ""`), matching `inet6`, so
    the first authored `preferred` is not silently overwritten.
  - `pkg/networkd/networkd_test.go`: the two stale tests that pinned
    `PreferredLifetime=forever` now pin ordered plain `Address=` lines.
  - `docs/feature-gaps.md`: primary/preferred row now states networkd
    orders primary first overall and preferred first within its subnet.
- **RED evidence**: on base `8c05fba011` the new
  `pkg/networkd/preferred_subnet_15222_test.go` failed: preferred not
  first in its subnet (v4, v6, `/25` boundary, cross-subnet) and
  `PreferredLifetime` present. Re-verified by stashing only the fix
  files — the `15222` tests fail again; the DHCP-gate control passed
  both before and after.
- **GREEN evidence**: `go test ./pkg/networkd -run
  '15222|TestGenerateNetwork_Primary|TestGenerateNetwork_Preferred|TestOrderAddresses'`
  — all 10 pass; full `go test ./pkg/networkd -count=1` passes;
  targeted `pkg/config` preferred/primary tests pass; `go build ./...`
  passes. The #10718 sink inventory count was updated 3→2 for the
  removed `[Address]`-section sink.
- **Acceptance note**: `ip route get` reporting the preferred address as
  `src` is a live-kernel check and is lab-bound; the render-order
  contract that determines it (first-in-subnet `Address=` order fed to
  systemd-networkd) is what the regression pins.
- **Risk**: interfaces whose preferred differed from the first address
  in its subnet now get the Junos-documented source address; no other
  rendering changes. Multi-`preferred`-per-subnet (one per subnet in a
  unit) still collapses to the first — a pre-existing single-slot model
  shared with syslog/ipsec consumers, not widened here.
