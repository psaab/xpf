# #16532 — LocalMiss pressure-shed preflight: host-bound first packets shed embryos instead of refusing at a full table

## Scope and verified mechanism

At base `9dfad41542` (branch point):

- `userspace-dp/src/afxdp/poll_descriptor/mod.rs` LocalMiss arm:
  `local_session_capacity_available` was `true` unless an owner SYN-reuse
  closing pair could be credited (`can_admit_after_closing_tcp_pair_for_syn`).
  There was no pressure shed. The install through
  `install_helper_local_session_on_miss` (`afxdp/forwarding/local_delivery.rs`)
  reached the raw cap check in `session/install.rs`
  (`len + reserved >= max_sessions` → `create_drops`, return false), and on
  refusal the arm ran `note_admission_refused()`, recycled the descriptor and
  continued — fail-closed since #15951.
- The transit sibling (ForwardCandidate) and the MissingNeighbor seed site
  both run `can_admit_new_flow(needed, protocol, tcp_flags)` when the
  reuse-aware fit fails, shedding local unreplied (handshake-incomplete /
  never-replied) sessions at the 90% watermark (#10890/#16019), then release
  shed rows with the #12862 tuple-gate lease, reply-evidence retention,
  shared-row removal under the incarnation fence, BPF/conntrack/DNAT/live-row
  deletion, NAT/NAT64 hold release, and sibling delete replication.
- Consequence: a transit SYN flood holding a worker table at cap shed-and-
  replaced its own embryos while every new host-bound TCP SYN, SYN|ACK and
  UDP first packet (BGP, SSH, IKE, DNAT-to-self, firewall-originated SYN|ACK)
  was refused on the same table — remotely inducible host-plane denial for
  the flood's duration. Established cached host sessions were unaffected.

Probe (issue, vn07): DNAT-to-self fixture from `tests_host_inbound_15951`
(wan 198.51.100.10 → 203.0.113.9:443 → 10.0.61.1:8080), cap 16 filled with
ForwardFlow TCP-SYN embryos: control (15) delivered; defect (16) printed
`host local=0 create=0 refused=1 | transit-shaped can_admit_new_syn(2)=true shed=2`.

## Fix

LocalMiss admission parity, in `poll_descriptor/mod.rs` only:

- The LocalMiss arm now computes a reuse-aware fit
  (`can_admit_after_closing_tcp_pair_for_syn(1, ..)` with an owner reuse key,
  else `can_admit(1)`). When it fits, no shed runs (a fitting replacement
  never kills embryos gratuitously — same conservatism as transit, and the
  shed check does not re-credit the closing pair).
- When it does not fit, the arm calls
  `sessions.can_admit_new_flow(1, meta.protocol, meta.tcp_flags)` — the same
  preflight as the transit and MissingNeighbor sites. Qualifying newcomers
  (TCP initial SYN; any non-TCP first packet per #16019 protocol symmetry)
  shed local unreplied victims at the 90% watermark; established/replied and
  peer-owned sessions are never victims.
- Shed rows are released with the identical sequence as the transit site:
  one `global_tuple_gate` lease over every shed key; per-victim reply
  evidence (`session_replied` / `shared_session_replied`) retains a victim
  and cancels its pending Close; `remove_shared_session_if` under
  `is_pressure_shed_shared_unreplied` (Declined still releases this worker's
  NAT/NAT64 holds when the local row is gone); coordinator-row release,
  flow-cache invalidation, BPF conntrack deletion, DNAT table deletion
  (forward rows), live-session deletion, source-NAT and NAT64 hold release,
  and `replicate_session_delete_repairing`. On lease contention the external
  teardown is deferred via `defer_pressure_shed` for the housekeeping
  `retry_deferred_pressure_sheds` pass, exactly as transit does. The release
  runs even if the host install is later refused.
- Only a genuine remaining refusal (nothing sheddable, or a non-qualifying
  newcomer at cap) reaches the existing #15951 fail-closed arm:
  `note_admission_refused()`, persistent-hold rollback, recycle, continue.
- The owner SYN-reuse eviction (`evict_owner_closing_tcp_pair_for_syn`) is
  unchanged and still gated on the (now real) capacity result.

Deliberate scope cuts (recorded at the call site):

- No reserved host-local headroom. The issue offered it as a consideration
  ("consider a small reserved host-local headroom for non-TCP and SYN|ACK").
  Non-TCP newcomers already qualify for shedding under #16019, so headroom
  buys them nothing; a static reservation would strand transit slots on every
  worker and break the `can_admit` post-preflight infallibility contract
  shared by all install sites. SYN|ACK (TCP+ACK) is not an initial SYN, so
  `can_admit_new_flow`'s TCP arm retains the hard cap for it — mirroring the
  transit non-SYN rule (#10890). The proved asymmetry (initial SYN, plus
  non-TCP by symmetry) is closed; SYN|ACK at a table full of non-sheddable
  state still fails closed, as transit non-SYN does.

## Tests

New cells in `userspace-dp/src/afxdp/tests_host_inbound_15951.rs` (same
DNAT-to-self fixture, poll-path driven):

- `full_of_sheddable_embryos_admits_host_syn_16532` — cap 16, 8 embryo
  pairs; host SYN delivered + installed, `admission_refused == 0`, table
  16 → 15 (one pair shed, one LocalMiss installed). This is the vn07 defect
  cell; RED at base (`local=0 create=0 refused=1`).
- `one_free_slot_delivers_without_shed_16532` — 15/16; delivers, installs,
  no shed (table → 16), no refusal. The vn07 one-free-slot control.
- `full_of_established_still_refuses_host_syn_16532` — 16 established
  singles; still fail-closed, `admission_refused == 1`, nothing shed.
- `full_of_embryos_admits_host_udp_and_releases_shed_shared_row_16532` —
  host-bound UDP first packet sheds one pair; with a caller-provided shared
  map, exactly one victim forward shared row is removed (7 of 8 remain),
  proving the shed caused by a host packet releases shared authority exactly
  as the transit shed does. NAT-hold release on shed is pinned end-to-end by
  the existing transit cells (`txn_pressure_shed_releases_source_nat_pool_port_10890`,
  `txn_pressure_shed_gate_failure_keeps_shared_row_and_nat_hold_12862`), whose
  release sequence this arm now shares verbatim.

Unchanged pins: the #15951 cap-0 cell
(`capacity_refused_local_delivery_is_dropped_not_trusted_15951` — cap 0 has
nothing sheddable and `can_admit_new_flow` cannot admit, so it stays green),
the with-capacity control, and all `junos-host` credit cells.

## Residuals

- The transit steady-state claim (flood holds the table at/near cap via
  shed-and-replace) remains the issue's static inference; the fix removes
  the asymmetry regardless of the exact steady state.
- SYN|ACK for firewall-originated TCP at a genuinely full, non-sheddable
  table still fails closed (see scope cut above); each descriptor
  preflights independently, so a SYN|ACK is admitted whenever a slot is
  free at its own arrival.
- No lab (real XDP/BGP/SSH) run; decisive behaviour is pinned through the
  real poll path (`txn_run_descriptor_checked` /
  `txn_run_descriptor_with_shared_sessions`) on the #15951 fixture.
