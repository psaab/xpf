# #16436 — M4 duration-ratio kill gate in default suite, and requireNetNS reports passing netns child as SKIP

## Defect

Two verdict-soundness defects in `pkg/nfqueue`, both violating
`docs/engineering-style.md` "Time in tests (#8218)":

1. `TestMeasureFragments9506` (M4) ran `if loadedP99 > 5*maxInt64(baseP99, 1) { t.Fatalf(...) }`
   in the default `go test ./...` leg, with no retry, floor, or load guard — a
   pass criterion that is a ratio of durations (clause 1). The ratio is
   noise-driven (recorded range 0.56–4.65 at moderate load, 5.05–5.21 under
   contention), so the gate can red unrelated PRs under load and cannot tell a
   real head-of-line regression under ~5x from noise.
2. `requireNetNS` ended every successful netns child with
   `t.Skip("netns child completed")`, so a green netns cell (M1/M2/M3 and
   `TestProvenanceLiveNetns9506`) was reported as SKIP in every summary line
   and the skip census (clause 2).

## Fix

- `pkg/nfqueue/measure_fragments_test.go`: the p99 ratio is now logged but
  only fatal behind the opt-in measurement flag `XPF_NFQUEUE_MEASURE_HOL`,
  matching M1's "baseline data, not a performance kill gate" posture. The
  deterministic FragPool capacity checks (`ErrFragmentCapacity`,
  `CapacityDrops`, post-cap completion) remain the only verdict in the
  default suite. Doc comment rewritten accordingly.
- `pkg/nfqueue/harness_test.go`: `requireNetNS` now returns `bool` — `true`
  in the netns child (run the body), `false` in the parent (return at once).
  Every caller (`TestMeasureStages9506`, `TestMeasureMemory9506`,
  `TestMeasureTeardown9506`, `TestProvenanceLiveNetns9506`, and the #16436
  regression cell) was migrated to `if !requireNetNS(t) { return }`; the old
  void form let the parent fall through into the body in the host netns and
  fail at `Open` once the Skip-on-success was removed. A passing child now
  makes the parent return normally and report PASS; failure still
  `t.Fatalf`.
- `pkg/nfqueue/measure_gate_16436_test.go` (new): pins both clauses — the
  HOL fatal is guarded by the opt-in flag and the deterministic checks
  remain, and a trivially passing netns cell driven through the real
  `requireNetNS` parent reports PASS (not SKIP).

## Validation

- `TestMeasureFragmentsDefaultNoDurationGate16436` and
  `TestRequireNetNSParentReportsPass16436` PASS.
- `TestMeasureFragments9506 -count=10` PASS (ratios logged, never fatal).
- `TestRequireNetNSParentReportsPass16436` exercises the real parent path:
  child `--- PASS` and parent `--- PASS` (defective harness: parent `--- SKIP`).
- All `requireNetNS` callers verified together (M1, M2, M3,
  `TestProvenanceLiveNetns9506`, both #16436 cells): parent `--- PASS`,
  package `ok` — no host-netns fall-through remains.
- `go vet ./pkg/nfqueue/` clean; `gofmt` clean on changed files.

## Risk

Measurement-only: the M4 HOL ratio is available via
`XPF_NFQUEUE_MEASURE_HOL=1` for deliberate measurement runs and is no longer
a default-suite verdict. Passing netns cells now count as PASS in summaries
(the intended census change); failing children still fail the parent.
