# #17837 — bind policy simulation to applied scheduler state

## Why

Policy simulation on CLI/gRPC surfaces read staged desired scheduler state rather than the last snapshot accepted by the helper. REST security match used a name-only scheduler predicate under an inverted comment, allowing it to skip a scheduled DENY while the fail-closed latch kept that DENY eligible in the dataplane.

## What

- Added an applied scheduler state+latch pair to `Manager`; snapshot metadata carries both values locally, and the pair advances together only after helper acceptance. Direct compilation without staged scheduler input reuses the applied pair.
- Rewired CLI policy details, CLI `test policy`, and gRPC policy details to simulate with applied state and latch.
- Wired REST security match to the same applied pair and latch-aware inactivity predicate; corrected the response/comment description without changing fail-closed scheduler behavior.
- Added manager-level failed-publication coverage, divergent desired/applied CLI coverage, and a REST regression proving a latched scheduled DENY is matched before a later permit. Extended the snapshot-local metadata test and updated API/CLI/gRPC and protobuf descriptions.

## Risk

The simulation view now follows the helper-accepted scheduler state and its latch instead of pending intent.
