# Issue #12201 — pin the `becomeMaster` GARP/NA burst launch

## Why

The ordinary successful `becomeMaster` transition launches the asynchronous GARP/NA burst, but existing burst tests exercised `sendGARP` directly or covered other launch sites. Removing this transition-to-launch edge therefore left the VRRP suite green, so regression coverage did not protect the routine takeover path.

## What

Added dual-stack unit coverage that drives a successful `becomeMaster()` with fake VIP netlink seams and captures the IPv4 GARP and IPv6 NA burst callbacks. It asserts one burst for each VIP family, and separately asserts that `suppressGARP` still prevents both bursts while allowing ownership promotion. No production behavior changed.
