# #18883: packed-tail credential fixture exceeds the OSPF key-length bound

- **Timestamp**: 2026-11-02 (`wt-18883`, base `5e65228f29e113394a4e728357830b611286d61a`)

## Why

`TestPackedTailCredentialValuePosition16108` used the 18-byte value
`authentication-key` in both its OSPF MD5 and simple-password arms. The #16628
bounds are 16 bytes for MD5 and 8 bytes for simple-password, so strict compile
refused the fixture before either arm could prove that a credential-spelled
token in value position is consumed and preserved verbatim.

## What

Use `api-key` in both arms and in the verbatim-value and no-warning assertions.
It is a credential token recognized by `isPackedTailCredentialToken14412`, and
`printf %s api-key | wc -c` reports 7 bytes, within both OSPF bounds. The value
position assertions are otherwise unchanged; no validator or production code
was modified.

## Validation

All Go tests were run through `scripts/testguard-run.sh` with
`GOCACHE=/var/worktrees/.cache/go-build` and `GOTMPDIR=/wtgt`.

- **STEP-0 RED**: `./scripts/testguard-run.sh go test ./pkg/config -run '^TestPackedTailCredentialValuePosition16108$' -count=1` failed at the MD5 arm: `authentication md5 1 key is 18 bytes, exceeding the 16-byte maximum accepted by FRR ospfd` and cited #16628/#16108.
- **GREEN**: the same named command passed after the fixture-only change.
- **Neighbouring packed-tail credential cells**: `./scripts/testguard-run.sh go test ./pkg/config -run '^TestPackedTailCredential(StrictReject14412|Warns10707_14412|ChildControls16108|ValidPackedTails14412|QuotedValueNotFlagged14412)$' -count=1` passed. Together with the named GREEN cell, this exercised every test in `schema_walk_packed_tail_credential_dr13h5_test.go`:
  - `TestPackedTailCredentialStrictReject14412`
  - `TestPackedTailCredentialWarns10707_14412`
  - `TestPackedTailCredentialChildControls16108`
  - `TestPackedTailCredentialValidPackedTails14412`
  - `TestPackedTailCredentialValuePosition16108`
  - `TestPackedTailCredentialQuotedValueNotFlagged14412`
- **Over-length refusal proof**: `./scripts/testguard-run.sh go test ./pkg/config -run '^TestOSPFKeyLengthStrict16628$' -count=1` passed. Its existing mutant cells require strict refusal of 17-byte MD5 keys and 9-byte simple-passwords (and acceptance at 16/8 bytes), proving that shortening this fixture did not weaken or bypass the #16628 gate.

## Risk

Test fixture and documentation only. Both arms still require strict/schema
acceptance and byte-for-byte preservation of `api-key`; the MD5 arm also
requires absence of the packed-tail credential warning for the value token.
The neighbouring gate remains fail-closed for over-length credentials.
