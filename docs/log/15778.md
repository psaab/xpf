# #15778 — Canonical nested `routing-options instance-import/export` bypassed #11314, and compact open-world leaves escaped #10707

- **Timestamp**: 2026-10-19
  - **Action**: extended the #11314 routing-instance gate to the canonical
    nested `routing-instances <name> routing-options { instance-import/
    instance-export }` location, and made the #10707 open-world walker see
    packed (compact/elided) tails.
  - **File(s)**: `pkg/config/compiler_routing_children_9323.go`,
    `pkg/config/compiler_openworld_10707.go`,
    `pkg/config/routing_instance_nested_import15778_test.go` (new),
    `docs/log/15778.md`

  - **Arm 1 — nested instance-import/export (strict reject).** The #11314
    diagnostic in `routingInstanceUnknownKeywordMessage9323` was only
    reached for a keyword directly under the instance. Measured at master:
    braced and flat `VRF-A routing-options { instance-import policy-a; }`
    committed strict with only the generic #10707 warning; the elided
    `routing-options instance-import policy-a;` and the packed-instance
    `VRF-A routing-options instance-import policy-a;` committed with no
    warning at all. `routingInstanceNestedImportExport15778` now scans the
    instance's routing-options properties across braced, flat, elided and
    packed shapes (quoted/bracketed tokens are authored values, #9635) and
    the gate applies the same message and the same strict-reject /
    lenient-warn (#1960 no-brick) split as the direct form. Global
    `routing-options instance-import` is deliberately untouched: it stays
    on the #10707 warn-only path, pinned by a control in the new test.
    Instance-import/export has no compiler consumer, so this is inert
    acceptance / missing rejection, not an actual route leak — the issue's
    narrowed live form.

  - **Arm 2 — compact leaves escape #10707 (warn-only).** The #10707
    walker descended `node.Children` only, so a packed node carried its
    further statements invisibly on `Keys`. Measured at master: braced
    `route 10.0.0.0/24 { metric 5; }`, `{ resolve; }` and
    `{ bfd-liveness-detection { … } }` each drew the #10707 warning, while
    the compact `route 10.0.0.0/24 metric 5 next-hop …;` (and `resolve`,
    `bfd-liveness-detection`, a bogus token, an elided
    `routing-options frobnicate 7;`, and the routing-instance twins)
    drew none. `firstUnknownPackedKeyword15778` now walks the packed tail
    through the same schema resolution as the braced walk
    (`resolveSchemaChild` + `consumeNodeKeys`): resolving children consume
    their declared `1+args` span, a leaf with no children/wildcard owns the
    rest of the tail as values, wildcard slots consume their name without
    judging it, quoted/bracketed tokens are values (#9635), apply
    statements stop the scan, and only the first unresolvable token is
    warned on — everything after it is that unknown statement's own tail,
    mirroring the braced walk. Nested instance-import/export found this
    way is suppressed here because Arm 1 owns it (single diagnostic
    contract). Valid packed controls (OSPF BFD compact, valid static
    route, quoted `"metric"` description) draw no #10707 warning.

  - **Scope cuts**: no schema declarations added (instance-import/export
    stay undeclared keywords judged by the gate, as with the direct form);
    no compiler consumer implemented (xpf has no cross-RIB policy-leak
    engine); the #10707 extension is generic over the walker rather than
    a three-keyword list, because the measured escape was the packed-tail
    blindness itself, of which `bfd-liveness-detection`/`metric`/`resolve`
    under a static route are instances.

    `TestCompactUnknownRoutingLeavesWarn10707_15778`,
