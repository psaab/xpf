# #12906 — NoRoute policy adjudicates the post-translation tuple and gates the fabric stamp (D10-04)

- **Timestamp**: 2026-10-14
- **Action**: the `NoRoute` arm of `poll_binding_process_descriptor`
  (`userspace-dp/src/afxdp/poll_descriptor/mod.rs`) adjudicated the zone-pair
  / `junos-global` policy against the PRE-NAT wire destination
  (`adj_flow.dst_ip` + the wire ports) and took the RAW zone-encoded fabric
  stamp — diverging from every sibling policy site: the ForwardCandidate
  session-miss gate matches the #2345 POST-translation destination
  (`policy_dst_ip`/`policy_dst_port`) and applies the #6458 V2 owner-RG gate
  to the stamp, and the #5174/#10267 MissingNeighbor arm reconstructs the
  same post-translation tuple from `decision.nat` plus a dest-only NAT64
  re-classify. On a default-permit box a deny written for the translated
  (real/internal) destination MISSED on NoRoute, so the DNAT/static-DNAT/
  NPTv6-translated flow whose translated destination had no route kept its
  kernel delegation (`flowbacked_no_route_requires_nat_translation` does not
  fence an already-recorded destination translation) — the #2345 bypass of
  the title; a deny written for the wire (public/VIP) tuple instead MATCHED
  and cached the WRONG rule's denial id in the flow-cache deny seed. The
  ungated stamp let a fabric punt drive the from-zone even when the
  resolution's owner RG was not forwarding-active locally.
- **Fix**: the arm's adjudication is extracted to a pure function,
  `noroute_policy_adjudication`
  (`userspace-dp/src/afxdp/poll_descriptor/noroute_adjudication.rs`), which
  (a) runs `gate_fabric_zone_override_on_owner_rg` on the stamp before the
  zone-pair resolution — the same #6458 V2 binding as the session-miss gate
  and the MissingNeighbor arm — and (b) judges
  `nat.rewrite_dst`/`nat.rewrite_dst_port` (DNAT/static-DNAT/NPTv6, set at
  the decision build as `nptv6_nat.or(pre_routing_dnat)`) with a NAT64
  dest-only `classify_ipv6_dest` re-classify for a flow-backed NAT64 flow
  (its forward `NatDecision` is minted only in the ForwardCandidate Permit
  branch, so NoRoute arrives with a default `nat`) — exactly the
  MissingNeighbor arm's reconstruction. Both halves fall back to the wire
  tuple when no inbound destination translation applies, so an untranslated
  NoRoute flow adjudicates byte-identically to before (#7480 semantics
  preserved). The gated stamp shadows the raw one for the whole deny block —
  deny event zones, app-id (now resolved from the translated dst port),
  `stage_flow_cache_deny_seed`, and the #10679/#11066 NAT fences — the same
  shadow discipline the session-miss block and the MissingNeighbor arm use.
  The source stays the arm's own: `decision.resolution`, `decision.nat`,
  `flow`/`synthetic_l3`, unchanged.
- **Fail-closed direction**: every moved decision tightens, never loosens:
  the tuple moves pre-NAT → post-NAT (a deny that missed now fires; nothing
  that fired stops firing except the mis-attributed wire-tuple rule, which
  falls to the default — on a default-deny box that is still a deny), and
  the stamp moves raw → owner-RG-gated (an untrusted stamp loses the zone it
  never legitimately owned; the fabric interface's own zone/default decides).
  The #7480 availability cell is pinned unchanged: a zero-identity
  (`egress_ifindex: 0`) NoRoute keeps its default-policy decision, and a
  PERMITTED translated flow still reaches the #10679/#11066 fences that
  suppress kernel reinjection when a translation direction is outstanding.
- **Validation**: cells in
  `userspace-dp/src/afxdp/poll_descriptor/noroute_adjudication_12906_tests.rs`
  (the arm itself cannot be driven from this crate — #7480 note: live
  binding + UMEM + descriptor ring — so the wiring is held by the source
  shape: the arm passes the fences' own `decision` fields into the helper):
  - `translated_dnat_deny_is_judged_post_translation_12906` — the security
    cell: DNAT'd NoRoute denied by the translated-dst rule with that rule's
    id cached; ports view carries the translated port; untranslated
    refutation half proves the deny is tuple-dependent.
  - `wire_tuple_deny_is_not_cached_for_a_translated_flow_12906` — the
    mis-attribution cell: a pre-#2345 wire-VIP deny no longer fires (and
    therefore no longer caches the wrong id) for a DNAT'd flow; fires only
    untranslated.
  - `fabric_stamp_is_bound_to_the_owner_rg_12906` — owner-RG behavior:
    stamp dropped when the retained egress's RG is not locally active and
    for a base (zero-identity) NoRoute; honored (and denying on the stamped
    pair) when locally active.
  - `nat64_flow_is_judged_on_the_extracted_ipv4_destination_12906` — the
    (V6 src, V4 dst) mixed tuple matches the deny written for the real IPv4
    host (#2358); without the Pref64 the synthetic dst is ordinary IPv6.
  - `flowless_ports_stay_fail_closed_through_the_adjudication_12906` —
    `ports = None` (#3291) and L3-only adjudication preserved through the
    new path.

  transplanted into a detached master worktree with the pre-fix tuple
  selection and raw stamp restored — see `RED proof` below); GREEN on the

- **RED proof**: on a detached `39a53bda3` worktree (pristine
  origin/master), the transplanted module with `policy_dst_ip =
  adj_flow.dst_ip`, `policy_dst_port = adj_flow.forward_key.dst_port` and
  the ungated stamp (the master arm's exact inputs) reds exactly the four
  defect cells — `translated_dnat_deny...` (the deny misses: the bypass),
  `wire_tuple_deny...` (the wrong rule fires and would be cached),
  `fabric_stamp...` (the stamp drives the zone pair ungated),
  `nat64_flow...` (the synthetic v6 destination is judged) — 4 failed /
  1 passed, the one pass being the flowless-parity cell (unchanged by
  design).
- **Risk**: cold-path only (the NoRoute arm of the session-miss epilogue;
  once per NoRoute disposition, never per established-flow packet). No NAT
  fence, chokepoint, session, or counter logic is moved. Operators who
  authored denies against the PRE-translation destination for traffic that
  DNATs and then misses a route must rewrite them against the translated
  tuple — the same migration #2345 already required of the resolved path
  (and #2358 of NAT64), so NoRoute no longer diverges from it.
