# #16642 - RPM ErrProbeSetup WARN logged http-get credential URL verbatim

- **Timestamp**: 2026-10-25
- **Action**: Stop every http-get probe-setup error in `pkg/rpm` from carrying the credential-bearing target into the `RPM probe setup failed` WARN (which logs `err` verbatim). `canonicalizeHTTPTarget` now renders `config.RedactURL(target)` instead of the raw `%q` target on its no-host / unsupported-scheme arms, and renders the redacted target plus only the inner parse-error class (new `urlParseErrClass16642`, unwrapping `*url.Error`) instead of wrapping `url.Parse`'s `*url.Error`, which re-embeds the full raw URL. `probeHTTP` does the same for the `http.NewRequestWithContext` failure (full raw URL in the `*url.Error`), and for the local-bind (`EADDRNOTAVAIL`) re-wrap it scrubs the error text via new `scrubProbeURLError16642`/`scrubURLsInText16642` (mirroring feeds #9164/#12883): the raw target, net/http's password-masked spelling (`user:***@host`, which still left username + query token), and any other `scheme://` token are replaced through `config.RedactURL`, preserving the surrounding dial/errno diagnostic. The WARN site itself is unchanged — the error it logs is now credential-free by construction. Scheme, host and path remain visible; probing still uses the raw target and `errors.Is(err, ErrProbeSetup)` hold semantics are unchanged (sentinel still wrapped with `%w`).
- **File(s)**: `pkg/rpm/rpm.go`, `pkg/rpm/setup_warn_redact_16642_test.go` (new), `docs/log/16642.md`.
- **Validation**: New tests drive the real `probeHTTP` legs through `runSingleTest` with a captured slog handler. RED pre-fix: both legs' WARN lines contained `TOKEN-USERINFO`/`TOKEN-QUERY-16642` (NewRequest parse leg embedded the full raw URL; local-bind leg leaked the query token despite net/http's password masking; canonicalize and no-host arms also leaked in the returned error). GREEN post-fix: 5/5 `16642` tests pass, credential-free control unchanged (no `<redacted>` marker, host/path intact), full `go test ./pkg/rpm/ -count=1` passes, `go vet ./pkg/rpm/` clean.
- **Risk**: Display/log only — no probe, classification, or failover behaviour change. Error strings for http-get setup failures change shape (redacted target + error class instead of the wrapped `*url.Error` text); no in-tree consumer matches on those strings. The generic `HTTP GET failed` (non-setup) path is deliberately untouched: it is counted as path loss, not logged by the setup WARN.
