## Change

The JSON producer and binary encoder already carried the expected attribution. The regression was in the test-side binary-frame parser: it treated the variable rule-ID bytes as the end of the payload and used fixed offsets from that end, but the wire frame appends the #10888 handshake-state byte after the rule ID. Routing-domain and install-table assertions also parsed their fields independently using stale suffix offsets.

Updated the shared `binary_attribution` parser to locate the rule-ID length prefix and bytes immediately before the trailing handshake-state byte, validate the encoded length and ID contents, and decode the routing domain and installing-table pair from the resulting wire offsets. Both remaining parity cells now use this same parser. Updated the stale test comment to describe the actual wire-byte check.
