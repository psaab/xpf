- **Timestamp**: 2026-10-16
- **Action**: Fix. Rewrote `parseDNATPortList` around a shared
  `parseFlatPortTokens` closure: the no-children leaf parses
  `m.Keys[1:]` through it (unchanged semantics, incl. reversed-range and
  invalid-token recording); the braced branch now flattens `m.Keys[1:]`
  plus every `child.Keys` (recursively) through the same parser instead
  of reading only `Keys[1]`, returning early on the first `to` child,
  and reading only `child.Name()`. A `to <high>` child following a
  numeric token is rewritten in sequence as the `to` keyword
  (`8000 { to 8005; }` → `8000 to 8005`), never swallowed; sibling-node
  ranges (`{ 20000; to; 30000; }`) and per-child ranges (`20000 to
  30000;`) flatten to the same stream. Invalid tokens inside braces now
  reach `InvalidDestinationPorts`, so the strict gate
  (`compiler_validate_strict_nat.go:396`) sees them (fail-closed
  preserved); the bounded range expansion (`appendDNATPortRange`,
  #3449) is untouched.
