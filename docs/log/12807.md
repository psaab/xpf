# Issue #12807 — poison keyless and nested to-zone policy contexts

## Why

`compilePolicies` only checked the first direct `to-zone` child of a keyed
`from-zone` node, and required a direct `policy` child on that node. A policy
nested below the destination child (or under a later `to-zone` sibling) was
therefore absent from `MalformedZonePairs`. Strict validation rejects these
shapes, but tolerant compilation only warned; the missing poison carrier could
allow an authored deny to fall through to a permit-all default.

## What

- Inspect every `to-zone` child in declaration order and use the existing
  policy-intent predicate to detect nested policy-bearing content.
- Record each such malformed context in `MalformedZonePairs`, retaining the
  established #7523 diagnostic and tolerant snapshot poison path. Keyless
  destinations are named from their child node.
- Add regression cases for a keyless destination, a nested destination child,
  and a policy-bearing second `to-zone` child; each asserts strict rejection,
  tolerant malformed-context recording, and a non-empty poison locator.
- No valid combined zone-pair compilation or runtime behavior was changed.

## Validation

- RED before the fix:
  `go test ./pkg/config -run '^TestTolerantKeylessNestedZonePairShapesPoison12807$' -count=1`
  failed all three cases because `MalformedZonePairs` was empty.
- GREEN after the fix:
  `go test ./pkg/config -run '^(TestTolerantKeylessNestedZonePairShapesPoison12807|TestTolerantZonePairShapesPoison12633|TestDuplicateToZone.*12640)$' -count=1`
  passed.
- `go vet ./pkg/config` passed with no output; `gofmt -l` on both changed Go
  files and `git diff --check` produced no output.
- `go test ./pkg/config -count=1` ran for 10 minutes and failed: unrelated
  inventory census, API-auth expiry/self-repeat, packed routing-instance,
  schema spelling-gate coverage, and slot-escape census tests failed; the
  package then timed out in `TestSchemaSpellingDifferentialGate` while doing
  bcrypt work. No reported failure referenced this change. The complete
  failure output was consistent across two runs.

## Risk

Malformed nested policy-bearing `to-zone` contexts now poison tolerant snapshots
rather than merely warning. These configurations were already rejected on the
strict path; this closes the fail-open tolerant-path gap. The package-wide
verification remains blocked by the recorded unrelated failures and timeout.
