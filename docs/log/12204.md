# Issue #12204 — pin expired first-commit recovery markers

## Why

`recoverPendingConfirmLocked` has a `FirstCommit` recovery branch that must clear the in-memory ever-committed bit and persist `committed=false` when the confirm window expired during downtime. The existing branch-executing active-snapshot test asserted only the nil snapshot, so mutations of any of the three marker writes escaped that coverage. PromoteRollback and timer-path marker assertions exercise different code.

## What

Added an end-to-end configstore oracle for a genuine first `CommitConfirmed` whose deadline expires while the daemon is down. It asserts the immediate `ActiveConfig()==nil` and `EverCommitted()==false` state, reads `committed=false` from disk and after reopen, and forces a failed recovery write followed by a successful degraded retry to pin the persisted marker seed. Added a daemon-package consumer test that feeds the recovered store state to the real `computeBootClass` and requires `bootClassBootstrap`.

## Validation

- **STEP-0** (`a714c90d472a3c3d98a3799831cfef3ec311a61`): the FirstCommit recovery branch contained all three clearing writes; `TestActiveSnapshotRecoveryFirstCommitNil9905` asserted only the nil active snapshot. Its existing targeted test passed with each marker mutant.
- **RED before:** independently mutated `everCommitted=false` to true, `persistMarkerCommitted=false` to true, and the recovery `writeActiveMarker(..., false)` to true. Each mutant passed the existing branch-executing test (`go test ./pkg/configstore/ -run TestActiveSnapshotRecoveryFirstCommitNil9905 -count=1`).
- **GREEN after:** the new oracle fails each mutant at its corresponding consumer-visible assertion: M1 fails `EverCommitted`, M2 fails the healed disk marker, and M3 fails the reopened disk marker. All three mutated production edits were restored.
- `go test ./pkg/configstore/ -run 'TestFirstCommitRecoveryOracle12204|TestActiveSnapshotRecoveryFirstCommitNil9905|TestConfirmRollbackKeepsNeverCommittedAfterItem1bRestart' -count=1` and `go test ./pkg/daemon/ -run TestExpiredFirstCommitRecoveryBootClass12204 -count=1` passed.
- `go test ./pkg/configstore ./pkg/daemon -count=1`: `pkg/daemon` passed; `pkg/configstore` had four unrelated reds: `TestLoadBootsAndSanitizesPersistedNewlineDescription`, `TestSyncApplySanitizesNewlineDescription`, `TestISISInterfaceLevelTypedInRoutingInstanceCopy_8450`, and `TestElidedRoutingInstanceDoesNotStealTheOSPFInterface9055`.
- **Same-base attribution:** those exact four tests fail on a clean worktree at STEP-0 `a714c90d472a3c3d98a3799831cfef3ec311a61` with the same interface-ownership / routing-instance diagnostics. No broader test failure was introduced by this test-only change.

## Risk / residual

Test-only change; no production code or live cluster/hardware was changed. The daemon integration test edits only a temporary plaintext first-commit `confirm.json` deadline to deterministically model downtime.
