# #14577 — Closed-world `security` schema rejects three compiler-read leaves (Y03-02)

## Defect
#10078 armed `security` closed-world in `pkg/config/schema_security.go`, but
three compiler-read, documented leaves were never modelled:

- `security flow syn-flood-protection-mode syn-cookie` — read by
  `compileFlow` (`compiler_security_flow.go`) into
  `Flow.SynFloodProtectionMode`; honoured as `== "syn-cookie"` by
  `pkg/dataplane/userspace/screens.go` and `pkg/dataplane/compiler_iface.go`;
  documented in `docs/syn-cookie-flood-protection.md`.
- `security log report` — read by `compileLog`
  (`compiler_security_log.go`: `sec.Log.Report`) and used by
  `pkg/daemon/daemon_system.go` to arm session aggregation; documented in
  `docs/phases.md`.
- `security flow traceoptions file <name> size <s> files <n>` — read by
  `compileFlow` / `validateFlowTraceSizeFilesAST` via
  `flowTraceSizeFilesValues` (#3424) in flat, packed and braced shapes.
  `file` was modelled as `args:1, children:nil`, so `size`/`files` were
  unknown keywords under the closed-world arm.

Strict commit (`schemaValidateExpandedTree` in `pkg/configstore/store.go`)
therefore refused each line with `unknown configuration keyword ... under
closed-world subtree`. Lenient load / `SyncApply` only warned and compiled
the value, so a node carrying e.g. syn-cookie was commit-locked: the next
unrelated commit was refused until the operator deleted the defence.

RED on `origin/master` (`a615690ed`, worktree base): `SchemaValidate` of
each valid line returns the closed-world error above; census test fails
listing the three missing leaves.

## Fix
- `pkg/config/schema_security.go`:
  - `flow.syn-flood-protection-mode`: typed enum leaf, exactly
    `{syn-cookie}`. Junos `syn-proxy` is not implemented in xpf, so it
    (and any typo such as `syn-cokie`) is now an explicit commit reject
    naming the value, not a silent no-op.
  - `log.report`: presence flag leaf.
  - `traceoptions.file`: typed filename leaf (`ValueIdentifier`) with a
    whole-tail validator and `size`/`files` modifier children carrying
    the #3424 bounds (`FlowTraceMin/MaxFileSize`,
    `FlowTraceMin/MaxFileCount`). The tail validator is needed because
    the typed-leaf modifier walk stops after the first valued modifier
    and would reject `size ... files ...`; the #4228 tailValidator
    mechanism (as CoS `transmit-rate`) validates the full tail in any
    modifier order.
- `pkg/config/schema_flow_trace_file_14577.go` (new):
  `validateFlowTraceFileTail14577` — validates `[name] (size <s> |
  files <n>)*` against the same #3424 bounds; unknown modifiers and
  missing values reject naming the token.
- `pkg/config/compiler_security_flow.go`: `flowTraceSizeFilesValues`
  now also scans grandchildren. Once `file` declares modifier children,
  SetPath groups the flat tail as a chain (`size` -> `files`) instead of
  one collapsed child, so without this the second modifier's value was
  invisible to both the compiler and the #3424 gate (measured:
  flat `file f1 size 100000 files 3` compiled `FileCount=0` and the
  lenient gate emitted only the size warning). This restores the
  helper's SSOT contract ("gate checks exactly what is stored").

NOT changed: the #3424 prewalk gate, the #3420 filename gate, and the
lenient clamp in `NewTraceWriter` — they already enforce the same bounds
once the values are reachable.

## Tests
- `pkg/config/schema_closedworld_security_14577_test.go`:
  - `TestClosedWorldSecurity14577_AcceptsCompilerReadLeaves`: each leaf
    validates + compiles to its value (syn-cookie, Report, File/FileSize/
    FileCount).
  - `TestClosedWorldSecurity14577_HierarchicalShapes`: braced,
    single-line hierarchical and packed spellings, incl. braced
    `file f1 { size ...; files ...; }` compiled values.
  - `TestClosedWorldSecurity14577_RejectsInvalidValues`: typo
    `syn-flood-protection-mod`, `syn-proxy`, `syn-cokie`, out-of-range /
    non-integer size/files, bogus file modifier — all rejected by the
    strict SchemaValidate+CompileConfig composition naming the token.
  - `TestClosedWorldSecurity14577_CompilerReadCensus`: every keyword
    compileFlow/compileLog reads at flow/log level is schema-reachable;
    file size/files carry validators; syn leaf is a typed enum;
    completion offers all new leaves.
  - `TestClosedWorldSecurity14577_ControlsStillPass`:
    `allow-dns-reply`, `log mode stream`.
- `pkg/configstore/security_closedworld_14577_test.go`:
  - `TestCheckTextAcceptsSynCookie14577`: strict CheckText accepts all
    shapes + compiled values; typo and syn-proxy reject.
  - `TestSyncApplySynCookieThenUnrelatedCommit14577`: SyncApply of a
    syn-cookie config succeeds with `mode="syn-cookie"`, then an
    unrelated `system host-name b` CommitCheck/Commit succeeds (the
    lockout cell); allow-dns-reply control likewise.

## RED/GREEN
- RED (tests only on base): all acceptance cells fail with
  `unknown configuration keyword "syn-flood-protection-mode" / "report" /
  "size" under closed-world subtree`; census lists the missing leaves.
- GREEN with fix: `go test ./pkg/config/ -run TestClosedWorldSecurity14577`
  and `go test ./pkg/configstore/ -run 'TestCheckTextAcceptsSynCookie14577|
  TestSyncApplySynCookieThenUnrelatedCommit14577'` pass.
- Neighbours: `TestFlowTrace*`, `TestSchema3377`, closed-world security
  tests pass except `TestClosedWorldSecurity10078_DirectIPsecVPNLeaves`,
  which also fails on pristine `origin/master` (base-attributed,
  #14139 pre-shared-key gate, unrelated). The compact census tests
  (`TestCompactBlockEquivalenceInventory2419` etc.) panic on pristine
  master too (nil `nodeVal` in `validateRethRedundancyGroupTokensAST`),
  base-attributed and unrelated; full `pkg/config` run without them
  exceeds the local timeout in an unrelated policy-expansion test.

## Risk
- `syn-proxy` now rejects explicitly where it previously could only
  arrive leniently and compile to an inert string; no dataplane consumer
  ever honoured it.
- Flat-set `file ... size ... files ...` now compiles `FileCount`
  correctly (previously dropped); in-range configs change from
  default file count to the configured count — the documented intent.
