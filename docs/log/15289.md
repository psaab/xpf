# #15289 — AttachedXDPLinkCount and ProveArmCoverage ignore detachDebt

- **Issue**: #15289 (D8-04)
- **Branch**: `fix/15289-campaign`

## Defect

A link that DetachXDP intended to detach but failed to close (the
`IFACE_FLAG_XDP_ATTACHED` flag-clear arm or the substantive `Unpin`
arm, #10519) stays in `xdpLinks` with `detachDebt[ifindex]` set, and the
kernel program stays attached. The accepted snapshot has already dropped
that interface.

Two kernel-truth readers ignored the debt:

- `AttachedXDPLinkCount` (`attached_links_9725.go`): counted every
  kernel-attached tracked link. A debt-only box therefore reported
  `count > 0`, opening the daemon transit gate
  (`transit_gate_tick_9725.go`) and health probes that gate on the count —
  on an interface nothing adjudicates anymore.
- `attachedInstance` (`armproof.go`): returned the debt link's live
  program as proof, so `ProveArmCoverage` classified a dropped interface
  as `direct` (covered) and a VLAN child delegating through it as
  `delegated`. Arm proof could certify a dropped interface as armed.

Their sibling `AttachedXDPIfindexes` already excluded debt (#10519), so
the fence census and the count/proof disagreed about the same link.

## Fix

One shared fail-closed rule — *detach-debt members are not attached* —
consulted under the owning `m.mu` lock, in both remaining readers:

- `link_maps.go`: new `xdpLinkForAttached(ifindex)` — the debt-aware
  variant of `xdpLinkFor`. Membership and debt are read under the same
  `m.mu` hold. Detach/attach lifecycle paths keep using `xdpLinkFor`,
  which must still see debt links to retry their DetachXDP recovery
  (#10519). It fires the same `muAcquireProbeHook("xdpLinkFor")` pre-lock
  seam, so the #2114 A3 arrival proofs are unchanged.
- `attached_links_9725.go`: new `xdpLinksSnapshotAttached()` copies the
  tracked XDP links minus debt under one `m.mu` hold. Both
  `AttachedXDPLinkCount` and `AttachedXDPIfindexes` now consume it
  (Ifindexes was previously correct but open-coded the same exclusion);
  kernel `Info()` reads still run unlocked on the copied handles.
  `withAttachedXDPFence` already excluded debt and is unchanged.
- `armproof.go`: `attachedInstance` uses `xdpLinkForAttached`, so a debt
  surface reports `ok=false` → uncovered → WouldGate, and
  `coverDelegated` cannot resolve a VLAN child through a debt parent
  (the parent's direct entry is absent/uncovered).

### Deliberate scope cut — shim pins NOT changed

`shim_pins.go` keeps pins for every tracked link, including a debt link.
That is not a hole: the debt link's `Unpin`/`Close` already failed, so it
is still kernel-attached and its pin is the hitless-restart reference that
keeps it from detaching on handle close. Removing the pin would not
detach it; it would only strand it. The transit/fence/proof exclusion
above is the fix; `TestDetachDebtLinkPinKept15289` pins the keep decision.
