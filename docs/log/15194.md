# #15194 — RG demotion left VIP-anchored IKE/CHILD SAs in charon (D04-02)

- **Timestamp**: 2026-10-19
- **Issue**: D04-02 — On RG demotion xpf removes the VIP but never terminates
  the IKE/CHILD SAs anchored on it. The stale SAs survive in charon (MOBIKE
  defers teardown, and a non-MOBIKE peer generates no IKE traffic). When the
  RG fails back, `reinitiateIPsecSAs` → `swanctl --initiate --child` is
  refused with `not establishing CHILD_SA ... due to existing duplicate`,
  and the returning owner keeps encrypting with SPIs the peer has already
  deleted. The black hole is bounded only by DPD (if configured), the next
  rekey, or peer initiation.
- **Base**: `origin/master` `8c9f287c59` (re-anchored from the filing base
  `27b8cba22d`). Cited sites present: `clearRethServicesForRG`
  (`pkg/daemon/daemon_ha.go`, no IPsec step), the RG0 secondary arm of
  `applyRG0OwnershipTransition` (no IPsec step), `reinitiateIPsecSAs`
  (initiate-only), `ownsIPsecConn` attribution (`ipsec_sa_rg_9139.go`).

## Fix

- **Demotion sweep (primary)**: `clearRethServicesForRG` (data RG, VRRP
  BACKUP / direct-VIP loss) and the genuine-demotion arm of
  `applyRG0OwnershipTransition` (RG0 secondary/secondary-hold) now launch
  `terminateDemotedRGIPsecSAs(rg)` asynchronously. It reads this node's
  LIVE SA set (`ActiveConnectionNames`), keeps only names attributed to
  the lost RG (`ipsecSAsForRG`: every candidate group from
  `ipsecConnRedundancyGroups` must equal the lost RG — the #9139/#9511
  attribution, including the RG0 default for unanchored/plain names), and
  terminates each via `swanctl --terminate --ike <conn> --force`.
  - RG0 gating reuses the transition's existing `genuineDemotion` verdict
    (proven demotion, primary-in-this-incarnation, or peer takeover), so
    initial-secondary seating (#12171 shape) terminates nothing.
  - The data-RG sweep is deliberately NOT gated on `IPsecSASync`: that flag
    governs peer advertisement/re-initiation; the SAs killed here are local
    and exist regardless of the flag.
  - Fail-closed on identity, fail-safe on enumeration: a failed live-SA
    read terminates nothing (guessing a connection name could kill a
    tunnel another RG still owns); a failed terminate is logged and left
    to the takeover belt.
- **Takeover belt**: `reinitiateIPsecSAs` reads the local live set before
  initiating; a peer-advertised name that is also live locally is
  terminated first, so a demotion terminate that raced/failed cannot make
  charon refuse the initiate with "existing duplicate". Names with no
  local SA initiate directly, as before.
- **`ipsec.Manager.TerminateConnection(name)`** (new, `pkg/ipsec/ike.go`):
  resolves the IKE connection owning the named SA from `--list-sas` (the
  SA's `ConnectionName`, since #15024 gateway-named connections carry
  VPN/selector child names) and issues `--terminate --ike <conn> --force`
  (`--force`: no waiting for a peer delete ack that a MOBIKE/non-MOBIKE
  peer may never send promptly after the VIP left). No matching live SA is
  a no-op; a failed list is returned, never guessed. The list goes through
  the manager's `scSplit` seam, so test doubles observe it.
- Test seam `Daemon.ipsecTerminateFn` mirrors the existing
  `ipsecInitiateFn`/`ipsecActiveNamesFn` seams (#9139 rationale).
- NOT changed: advertise gate, `ownsIPsecConn` initiate scoping, SA-sync
  wire format, terminate-debt machinery (`terminateRemovedConns` is for
  config-departed connections; demotion SAs are still configured).

## Risk

- A demotion now issues forced IKE terminations for exactly the lost RG's
  connections. Attribution reuse means a multi-candidate (colliding) name
  is terminated only when every candidate is the lost RG — a colliding
  name spanning a surviving RG is left for the belt, which terminates by
  live-local presence at takeover instead.
- Terminate is `--force` (no delete-ack wait): intended on demotion, where
  the local VIP is gone; the peer re-initiates or accepts the takeover
  node's fresh IKE SA. DPD/rekey behaviour is unchanged for SAs that were
  already down (no-op).
- Async sweep: a failback that lands before the sweep runs is covered by
  the reinitiate belt, which terminates the same name before initiating.
