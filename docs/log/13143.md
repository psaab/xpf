# #13143 — resolve bare DHCP server refs as unit 0

- **Source**: deep-review finding D2-12, validated by three-way adversarial research.
- **Files**: `pkg/config/compiler_validate_warn_dhcp_hostinbound.go`,
  `pkg/config/dhcp_host_inbound_bypass_6460_test.go`.

## Why

The #6460 DHCP host-inbound advisory resolved only the raw/canonical spelling
of a DHCP group interface. A bare `dhcp-local-server` ref therefore failed to
find a zone that listed unit `ge-0/0/0.0`, suppressing a needed warning; when
the zone listed the bare interface plus a unit-0 override, it evaluated the
bare ref and could emit a false warning. It also warned about lifelines even
though host-inbound deny does not apply to them.

## What

Resolve bare DHCP server refs through unit 0 when that unit has an effective
zone claim, and use that resolved ref for zone-level policy and interface
override evaluation while retaining authored-spelling override probes. Skip
references identified as lifelines. Explicit-unit handling is unchanged. The
regression covers missing warning, false warning, unit-0 warning control,
lifeline exemption, and avoiding attribution through a sibling unit.

## Validation

- RED on pristine `origin/master` (`662ee842d`):
  `go test ./pkg/config -run TestDHCPServerHostInboundBypassWarningsBareRef13143 -count=1`
  failed because the bare group ref against unit-qualified zone membership
  returned no warning.
- GREEN focused regression: same command, passed.
- Full config package: `go test ./pkg/config -count=1`, passed.
- Whole Go build: `go build ./...`, passed.

## Risk

This changes only commit-time advisory attribution for bare DHCP server refs;
it does not change DHCP forwarding or host-inbound enforcement.
