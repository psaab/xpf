# Issue #15165 — legacy RG0 failover commit-ready (B22-03)

Worktree `/var/worktrees/wt-15165`, branch `fix/15165-campaign`, base
`origin/master b7e04e4fcc` (no drift in the touched files at
`origin/master 5fb52e42cf`).

## Mechanism (verified at base)

- `pkg/daemon/daemon_ha.go:676` (now shifted) clears
  `localFailoverCommitReady` on every cluster event. Its setters were:
  the two `noRethVRRP`-gated arms (cluster promotion and the accepted
  reconcile record) and the VRRP MASTER arm requiring
  `s.AllVRRPMaster()`.
- `pkg/daemon/rg_state.go:427-430`: `allMasterLocked` returns false with
  zero instances.
- `pkg/vrrp/vrrp.go:32-37,219-226`: `rethVRID` rejects `rgID <= 0` and
  `CollectRethInstances` skips `rgID <= 0`, so RG0 never gets a RETH
  VRRP instance.
- Under `no-private-rg-election`, `request chassis cluster failover
  redundancy-group 0 node <local>` therefore always timed out at
  `waitLocalFailoverCommitReady` (3s) and then aborted in
  `cluster.RequestPeerFailover`, even after this node became RG0
  primary and `rg_active` converged.

## Fix

- `pkg/daemon/rg_state.go`: `VRRPInstanceCount()` accessor. Zero is
  ambiguous alone (no instance expected vs not yet instantiated), so
  callers must combine it with the config-derived expected count.
- `pkg/daemon/daemon_ha.go`: `legacyNoRethVRRPCommitReady(rgID, s,
  noRethVRRP)` — true only when a committed cluster config is
  affirmatively legacy (neither `NoRethVRRP` nor
  `PrivateRGElection`), the node is cluster primary, `!NeedsApply()`,
  and the RG has zero known AND zero config-expected RETH VRRP
  instances (`expectedRethVRRPCounts`). The affirmative-config term
  matters: with no store, `isNoRethVRRP()` is also false, and a bare
  `!noRethVRRP` gate failed open for the storeless RG0 fixtures the
  #5250 cells pin (caught by the neighbouring run, now covered by
  `TestLegacyPredicateRequiresCommittedLegacyConfig15165`).
- The predicate is consulted at three sites: the cluster-promotion
  arm, inside the accepted reconcile record (so a refused record
  still cannot raise readiness, #6799), and by
  `waitLocalFailoverCommitReady` itself — the probe's legacy arm,
  which covers a dropped promotion event.
- NOT changed: `AllVRRPMaster` semantics, the VRRP MASTER/BACKUP arms,
  the direct-mode setters, `pkg/cluster` (the probe already polls the
  daemon flag; the batch probe shares the same hook), and any data-RG
  behaviour — an RG expecting an instance but with none known stays
  gated on `AllVRRPMaster`.
