# #17811 — scope source-NAT range validation to the range leaf

The API half of #17811 is already fixed on master by #17836: bare ping and
traceroute preflight defers non-final verdicts until request arguments are
available. The remaining NAT defect came from placing the source-pool tail
validator on the `port` container. A range-first `no-translation` sibling was
flattened into the range operands and rejected, while a modifier-first tree
returned early from that validator and skipped the port's child-schema checks.

The range validator now lives on `port range`, so it validates only range
operands. Sibling modifiers remain visible to their own schema validators,
and the compiler retains its existing authored-order behavior. Regression
coverage checks flat and hierarchical range-plus-`no-translation`, both flat
statement orders, and invalid deterministic child values in both orders. The
existing malformed-range and allocation-modifier controls remain in place.
