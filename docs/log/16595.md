# Keep the last DNS answer on a transient lookup failure (#16595)

- **Issue**: #16595 (R3-N09-01).
- **Cause**: `resolveDNSAddressEntry` set `DNSAddresses = nil` on any
  resolver error, conflating "resolver failed" with "name has no
  addresses". The empty entry then (1) lowered to the
  `__unsupported_address__` sentinel, so the Rust helper refused the whole
  policy snapshot (running node: all later feed/scheduler applies frozen;
  fresh boot: default-deny for all transit), (2) failed every strict
  commit via `validatePolicyMatchAddressSetMembersStrict`, and (3) made
  `junosHostNameUnrepresentable` withdraw the zone's whole kernel
  junos-host DENY program — including unrelated static denies — fail-open
  for host services.
- **Change**: Stale-while-error. `Address.DNSLookupFailed` (runtime-only)
  records a failed (re)resolution; on error the previous `DNSAddresses`
  are retained, on success (even empty) the answer replaces them and the
  flag clears. Consumers treat a runtime-empty lookup-failed entry as
  per-entry match-none, not a static shape: the strict gate exempts it
  (the existing "will match nothing until DNS resolves" warning remains),
  the userspace builder emits no address sentinel and no
  `PolicyContentRejected` for it (a positive permit takes the empty book
  row; a deny/reject or excluded side is poisoned per-rule via its
  application terms so it can never fall through or invert), and the
  junos-host projection keeps rendering sibling static terms (the failed
  entry contributes no prefixes; with a stale answer it renders that).
  A successful empty answer keeps every pre-existing fail-closed gate.
- **Regression coverage**: `pkg/config/dns_stale_16595_test.go` (stale
  retention + flag lifecycle, failed-vs-empty distinction incl. nested
  sets and clone, strict-warns-not-rejects, successful-empty still
  rejects) and `pkg/dataplane/userspace/dns_stale_16595_test.go` (SERVFAIL
  arm: `sentinelRules=0` with the stale prefix in the book row, sibling
  permit clean, junos-host program survives with the static rule,
  never-resolved deny/excluded per-rule fail-closed, positive permit
  match-none loads).
- **RED evidence**: Reverting stale retention (`DNSAddresses = nil` on
  error) fails `TestDNSStaleWhileError16595`; reverting the builder's
  DNS-match-none lowering fails the three never-resolved snapshot tests
  with the pre-fix `__unsupported_address__` sentinel; reverting the
  junos-host/strict exemptions fails their tests.
- **Risk / residuals**: No max-stale age is enforced — a name that stops
  resolving keeps its last answer indefinitely (the issue marks the age
  optional; the 5-minute refresh retries every tick). A never-resolved
  deny still makes the Rust helper retain previous-good (its application
  sentinel refuses that generation); that is the strongest per-rule
  fail-closed the current wire expresses, and unlike the pre-fix path it
  carries no Go-side whole-snapshot content rejection. NAT consumers of
  `UsableValues` inherit stale retention automatically.
