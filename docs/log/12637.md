# Issue #12637 — canonical Junos scheduler one-liners

## Why

Strict schema validation rejected canonical scheduler-level `start-time X stop-time Y` and `start-date X stop-date Y` statements as an unknown modifier. The typed start leaves declared no stop-leaf tail grammar, although the compiler already supported the same bounds as separate scheduler properties.

## What

The scheduler start-time and start-date leaves now use narrow typed-tail validators that accept either their ordinary value or the matching stop leaf plus its value. Existing time/date validators check both endpoints; unknown modifiers, excess tokens, missing values, and malformed endpoints remain errors. `compileSchedulers` reads both boundaries from the one-line AST. The schema's scheduler-level child paths remain unchanged.

## Validation

- **RED on base `ab2149bf32a8f6c7caba3bb6ea7765674b7a37e6`**: `go test ./pkg/config/ -run 'TestSchedulerLevelOneLinerRejectsBadTail12637' -count=1 -v` failed for an unknown token after a valid time pair (`unknown modifier "stop-time"` instead of `"bogus"`), invalid stop-time, and invalid stop-date diagnostics. Misspelled stop leaves and missing values passed.
- **GREEN**: after naming the first dropped token and scoping stop endpoint failures to `stop-time` / `stop-date`, `go test ./pkg/config -run '12637' -count=1 -timeout 30m` passed (`ok`, 0.014s).
- **Scheduler sweep**: `go test ./pkg/config -run 'Schedul' -count=1 -timeout 30m` passed (`ok`, 0.219s).
- The broader package suite and `go vet` were not run for this diagnostic fix.

## Risk

No runtime policy semantics changed; this accepts the canonical spelling of already-supported scheduler bounds. Unknown modifiers and malformed typed stop values remain strict errors. No live cluster was modified.
