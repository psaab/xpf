# Issue #16482 — `tcp_maximum_window` is the one FlowSnapshot integer `buildFlowSnapshot` does not coerce

- **Timestamp**: 2026-10-24
  - **Action**: `security flow tcp-session maximum-window` (#15753) reached
    the Rust u32 wire field `tcp_maximum_window` via
    `buildFlowSnapshot` with a raw `ts.MaximumWindow` assignment and no
    #1977 wire coercion. A value above 4294967295 arriving through a
    tolerant path (`Store.Load` of a hand-edited/foreign config DB or
    `SyncApply` from a peer with a wider range, where the strict
    `ValidateInteger(1024, 1048576)` schema check is only logged) made the
    helper's `serde_json` decode of the whole `apply_snapshot` fail, so
    the helper stayed unconfigured (the #1961/#1977 silent failure class).
  - **Fix**: Added `coerceWireTCPMaximumWindow` + `maxTCPMaximumWindow`
    (1048576) in `flow.go`: values above the schema ceiling cap to the
    ceiling with a `slog.Warn` (#16482); in-range values (65536 included)
    pass unchanged; non-positive values stay on the existing `> 0` guard
    (0 = Rust default 65535). Capping to the schema ceiling rather than
    `math.MaxUint32` keeps every emitted value also strict-commit-legal
    on this node. Tests: extended
    `TestBuildFlowSnapshotCoercesOutOfRange_1977` (overflow -> ceiling,
    65536 unchanged, helper table), added the field to the
    Layer A/B agreement table in `flow_numwidth_agreement_test.go`, and
    added `TestTCPMaximumWindowCoerced16482` (overflow cap + warn +
    u32-decodable wire JSON + in-range/unset behaviour).
  - **File(s)**: `pkg/dataplane/userspace/flow.go`,
    `pkg/dataplane/userspace/flow_wire_coerce_test.go`,
    `pkg/dataplane/userspace/flow_numwidth_agreement_test.go`,
    `pkg/dataplane/userspace/flow_tcp_maximum_window_16482_test.go` (new),
    `docs/log/16482.md` (new)
  - **Validation**: Targeted tests pass (see PR body); RED verified by
    reverting the one-line coercion (both overflow tests fail with the
    raw 5000000000 on the wire). Full-package counts in the PR body.
