# #14421 - Packed NAT rule-set header tail invisible to Children-only `collectNATScopes` and all three NAT gates

- **Timestamp**: 2026-10-16
- **Action**: A NAT rule-set whose `from`/`to` clause is packed onto the rule-set header (`rule-set RS from zone trust { rule ... }`) compiled with the header tail invisible to `collectNATScopes` (Children-only), so the rule-set installed with match-any scope (all scope fields empty, match-any stamped) in strict (no error) and lenient (no warning) modes, for source (`from` and `to`, each zone/interface/routing-instance), destination (`from`), and static (`from`) NAT; a packed `from`+`to` pair likewise lost both scopes. Fix: new shared helper `natRuleSetChildren` (`pkg/config/compiler_nat_helpers.go`) expands the packed header tail — consumed with the grammar's own arity (`from`/`to`, then a scope kind, then one synthesised clause child per scope value; empty bracket `from zone [ ]` synthesised as present-but-empty via bracket provenance) — and returns the real children unchanged for braced/unmodelled tails. `packedBodyChildren` cannot be used: the `from zone trust` tail runs through the multi-valued `zone` leaf whose terminal declares no body, so it returns the body unexpanded (#6818 guard). `collectNATScopes` and all three gates now read through this SSOT: the mixed-kind gate (`natClauseScopeKinds`, #4881), the empty-scope gate (`validateNATRuleSetEmptyScopesAST`, #7525), and the DNAT-`to` detection (`natRuleSetHasToScope`, #3444, also used by `compileNATDestination` to omit on lenient load). All three compiler call sites (`compiler_nat_source.go`, `compiler_nat_destination.go`, `compiler_nat_static.go`) pass their NAT kind. Regression: `compiler_nat_packed_header_14421_test.go` — packed-vs-braced typed equality for all clause/kind cells + packed pair + lenient capture, and gate cells (mixed packed+child, empty-bracket packed, DNAT-`to` packed+from-braced) in strict-reject and lenient-warn modes.
- **Validation**: RED on origin/master (`70702de41`): all 14 packed cells compiled match-any (`FromZone:""` etc.) with no error/warning, gate cells silently accepted. GREEN post-fix: `go test ./pkg/config/ -run 'TestPackedNATRuleSetHeader|TestDNATRuleSet|TestValidateNATRuleSetMixedScope|TestNATRuleSet|TestCompilerStamps'` all PASS; `go vet ./pkg/config/` clean; NAT neighbour suites (`TestDNAT|TestNAT|TestValidateNAT|TestCompilerStamps|TestCompileGolden`) green. Full `pkg/config` suite exceeds the 300s tool window in this worktree; `TestPackedOptInHoldsForEveryLeafPair8768` fails identically with the fix stashed (pre-existing on this base, unrelated — it enumerates schema leaf pairs, not NAT scopes).
- **Risk**: Low. Braced and flat-set spellings return `node.Children` unchanged (bit-identical); unmodelled packed tails also return the real children (never guess). The only behavioural change is that previously-invisible packed scopes/gate violations are now captured/rejected exactly as their braced twins.
