# #9807 — SSE slow-reader cell flaked under host load

- **Timestamp**: 2026-09-11
- **Action**: widen the wall-clock margins of `TestLargeEventSurvivesASlowButProgressingReader7632` without losing its fail-on-revert property.
- **File(s)**: `pkg/api/sse_slow_reader_pin_7632_test.go`, `pkg/api/README.md`, `docs/log/9807.md`.

## Defect

The cell set `sseWriteDeadline = 100ms` and paced its reader at 32 KiB per 40 ms, so each `sseWriteChunk` (32 KiB) needed 40 ms of a 100 ms window: a 60 ms wall-clock margin. Inside a loaded `make test` (other lanes' runs and a cluster build on the host), a scheduler stall longer than that inside one chunk expired the re-armed deadline. The client saw EOF, and the failure message asserted the #7654 defect, which that run did not show. At the same head, the cell passed 8/8 on its own.

## Change

- The deadline is 400 ms, so each 40 ms chunk has 360 ms of margin.
- The payload is 32 chunks (1 MiB, 1.28 s at the reader's rate), so a write under a single window still expires mid-payload. That is the property the cell exists for.
- The failure message names the per-chunk margin, so a load stall is not read as the #7654 defect.
- `pkg/api/README.md` records the new revert figure and the margins.
