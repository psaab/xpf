# #15011 — redistProtocolsFiltered adds explicit from-protocol tokens unfiltered

- **Timestamp**: 2026-10-18
- **Action**: `redistProtocolsFiltered` (`pkg/frr/redistribute.go`) gated explicit `from protocol` tokens only through the known-protocol allowlist, while the self drop and `redistSourceFitsNode` family check applied only to the no-from expansion. `redistributeEntriesAt` filters explicit tokens in its own loop but then merges `redistProtocolsForNode` whenever any term lacks `from protocol`, re-adding every dropped token. A common Junos BGP export shape — a `from protocol bgp` term plus a local route-filter (no-from) term — therefore rendered `redistribute bgp route-map EXP-bgp-xpf-redist` under `router bgp` (self-redistribution; FRR rejects it, "No such command") and explicit IPv6 sources such as `ospf6` under the IPv4 node. One rejected line fails the whole managed `frr-reload`, so later removals never leave FRR. Fix: explicit tokens in `redistProtocolsFiltered` now pass the same self + `redistSourceFitsNode` gates as the no-from expansion whenever a render node is in hand. The node-less explicit-only set (`redistProtocols`, self/node `""`, used for per-source map definitions and the collision guard) is unchanged, so unreferenced-node maps and legitimate explicit sources at fitting nodes render exactly as before.
- **File(s)**: `pkg/frr/redistribute.go`, `pkg/frr/redistribute_mixed_explicit_15011_test.go` (new), `docs/log/15011.md`

Adjacent controls stay green: no-from expansion still originates the whole node-fitting domain through filtered maps, fitting explicit `ospf6` still originates under `address-family ipv6 unicast`, and the node-less explicit set still contains both tokens. `go test ./pkg/frr/ -count=1`: only 3 pre-existing failures (`TestFamilylessIPv6NeighborWithoutPolicyIsV6Only11564`, `TestFRRLoadInet6OnlyNeighborIPv4Deactivation11374`, `TestFRRLoadBGPClasslessRIBSuppression11426`), all reproduced identically on pristine `origin/master` (2ed3b1cc71) — base-attributed, unrelated to redistribution. `gofmt` clean, `go vet ./pkg/frr/` clean.
- **Risk**: Narrowed to the cited merge: only mixed explicit+no-from policies at a render node change; explicit-only policies were already filtered by `redistributeEntriesAt`'s own loop, and node-less callers are untouched. Inert per-source map definitions for self/off-family explicit sources may still be emitted by the node-less set (as before); they are unreferenced at nodes where the source does not fit and cannot fail the reload. No behaviour change outside the cited mechanism.
