# #12224 — NAT application-list validation and DNAT fail-closed behavior

- **Timestamp**: 2026-10-08 (`fix/12224-nat-applist`)
- **Base**: `a714c90d472a3c3d98a3799831cfef3ec311a61c`

## Red before

At the verified base, three temporary overlay probes failed:

- A malformed second application in a destination-NAT list committed with AppID disabled.
- `CatalogNames` returned only the first application-list value.
- A protocol-less second application produced a DNAT snapshot with an empty protocol, which the Rust DNAT table treats as `PROTO_ANY`.

## Change

- The strict application-spec reference walk and disabled-AppID catalog now traverse every value returned by `NATMatch.ApplicationList()`, matching the existing all-value NAT definedness gate and snapshot builders.
- DNAT omits a resolved protocol-less application term instead of encoding it with an empty protocol. Valid terms in the same application list remain; a protocol-less-only application emits no row. SNAT keeps its existing `natProtoNever` behavior.
- Updated the appid package README to describe the plural NAT walk.
