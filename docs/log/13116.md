# Issue #13116 — Correct shared-device trunk advisories

The #7509 advisory has two related blind spots. `sharedDeviceUnzonedUnitsWithMaps`
reported unit 0 as affected even when `native-vlan-id` maps or rejects untagged
ingress before it can be attributed to unit 0. Separately,
`sharedUnitIsAddressedOrTunnel` treated DHCP/DHCPv6 units as address-less because
it only counted static addresses and interface-level tunnels. The result was a
misleading commit advisory about a path the dataplane does not take, or a wrong
host-inbound admission description.

The change applies the same native-ingress disambiguation predicate used by the
contested-parent advisory to the shared-device warning, and classifies DHCP,
DHCPv6, DHCPv6-client, and per-unit tunnel units as active L3/tunnel units. The
regressions cover native VLAN suppression and no-native control, plus DHCPv4,
DHCPv6, and DHCPv6-client advisory wording.
