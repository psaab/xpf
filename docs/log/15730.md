# Issue #15730 — userspace-dp: worker panic `single-owner umem` on shared-UMEM owner bind after zero-copy EINVAL

- **Timestamp**: 2026-10-19
- **Action**: Under the default `SharedUmemPolicy::auto` (CrossNic), the
  userspace helper's worker threads panicked deterministically at
  `src/afxdp/umem/mod.rs:106` (`Rc::get_mut(..).expect("single-owner umem")`),
  worker bring-up failed closed (`worker_bind_incomplete:0:timeout:planned=3`),
  the helper never armed, and the loss cluster had no forwarding primary.
  Live workaround was config-only (`set system dataplane shared-umem mode
  off`), which must stay until this fix ships; it is degraded (private UMEM +
  copy mode, v4 push 14.8G/3702 retr vs the 22–23G bar).
  Mechanism, re-anchored at `origin/master be68c567ec` (contains #15088 and
  #15244):
  - `WorkerUmem` is `Rc<WorkerUmemInner>` and `#[derive(Clone)]`
    (`umem/mod.rs:46-49`). `create_shared_binding_group`
    (`worker/mod.rs:1149-1190`) builds one `WorkerUmemPool` for the whole
    group and hands `BindingWorker::create` an `umem.clone()` per member
    binding, so the group's `Rc` strong count is > 1 before the first
    socket is created.
  - The first member is the OWNER (`created.is_empty()` →
    `XskSocketRole::SharedOwner`). Since #15088 it maps to
    `XskCreateMode::SharedOwnerUmem` → `create_xsk_binding_shared_owner(
    &mut Umem)`, and the private create likewise takes `&mut Umem`; both
    reached the UMEM through `WorkerUmem::umem_mut(&mut self)`, which was
    `Rc::get_mut(..).expect("single-owner umem")`. `Rc::get_mut` returns
    `Some` only when the strong count is exactly 1, so the very first
    owner create on a shared group panicked — before any `xsk_socket__create`
    ran. On the mlx5 loss cluster the journal showed the zero-copy bind
    report (EINVAL, flags `0x000c`) from an earlier private attempt, then
    copy-mode fallbacks binding OK with `shared_umem=false`; the remaining
    shared-group workers then hit this panic, so the copy fallback never
    rescued the owner. The private fallback path itself
    (`fallback_shared_group_to_private` → `create_private_binding_from_plan`)
    is the only unshared (`Rc` count 1) case and would have worked — the
    panic aborted the worker before it could be reached.
  - Stated plainly: #15088 (owner borrows the UMEM's `fill_save`/`comp_save`
    through NULL fill/comp) and #15244 (post-create ladder terminal)
    introduced the exclusive-borrow requirement into a type that is
    cloned by design. Neither touched the accessor. This is the residual
    precondition they left unsatisfied.
  Fix (`umem/mod.rs`, `bind.rs`; no C, no `xsk_ffi` change):
  - `WorkerUmemInner.umem` is now `std::cell::RefCell<Umem>` (field order
    unchanged, still before `area` — #5192). `umem_mut(&self) ->
    RefMut<'_, Umem>` replaces the `Rc::get_mut` gate; `umem()` returns
    `Ref<'_, Umem>` and `as_raw_umem_ptr()` borrows likewise. Private and
    shared-secondary behaviour is unchanged: borrows are confined to one
    socket create at a time on one worker thread, sequential flag-ladder
    attempts (zero-copy, then copy on the same UMEM) borrow and release in
    turn, and a genuinely overlapping borrow still panics loudly (RefCell)
    rather than aliasing the libxdp ring state — the overlap case is
    pinned by test.
  - `bind.rs` adapts the two exclusive call sites
    (`create_xsk_binding_private`, `create_xsk_binding_shared_owner`) to
    `&mut worker_umem.umem_mut()`. The now-obsolete "only `&mut
    WorkerUmemInner` escape hatch (`Rc::get_mut`)" contract text in
    `poll_descriptor/mod.rs` and `worker/lifecycle.rs` is updated to name
    the RefCell borrow; the contract itself (bind time only, never while
    polling) is unchanged.
  NOT changed: `Umem` (raw libxdp object, already uniquely owned inside
  the `RefCell`), the `Rc` sharing itself (cross-binding shared-group
  forwarding depends on `shares_allocation_with` identity), the bind
  ladder, roles, or fallbacks.
- **File(s)**: `userspace-dp/src/afxdp/umem/mod.rs`,
  `userspace-dp/src/afxdp/bind.rs`,
  `userspace-dp/src/afxdp/poll_descriptor/mod.rs` (comment),

- **Validation**: Hermetic regression cells (no CAP_NET_ADMIN / AF_XDP
  hardware needed; `new_for_test` builds a null-handle UMEM):
  `shared_clone_umem_mut_does_not_panic_15730` clones one UMEM three ways
  (the group builder's shape) and runs the bind-time borrow through every
  clone in sequence plus the `fill_comp_rings_mut` hand-off — this cell
  panics at the pre-fix `expect` and passes after. Control:
  `umem_mut_overlap_is_a_loud_panic_not_an_alias_15730` asserts a second
  live borrow still panics and a sequential borrow after release succeeds
  (the private zero-copy→copy ladder pattern). Drop-order controls
  (`worker_umem_inner_drops_umem_before_mmap_area`,
  `worker_umem_pool_preserves_the_same_drop_order`) still pass — the
  `RefCell<Umem>` destroys in the same field order. Source tripwire
  `userspace-dp/tests/shared_umem_owner_umem_mut_15730.rs` pins the
  production wiring (no single-owner gate, `&self` accessor, owner create
  reached through the shared handle) in the style of the #15088/#15244
  tripwires. Loss-cluster re-test with the `shared-umem mode off` stanza
  removed (mode auto) remains required operator validation; it needs the
  cluster and is not hermetically runnable.
- **Risk**: `RefCell` moves the exclusivity check from compile time
  (`Rc::get_mut`) to runtime; a future caller that holds `umem_mut()`
  across a re-entrant create would panic at bring-up (fail closed, loud)
  instead of silently aliasing — the pinned overlap cell keeps that
  honest. No hot-path change: `umem_mut` runs only at bind time; poll-path
  raw-pointer contracts are unchanged. Shared-secondary and private binds
  are behaviour-identical.
