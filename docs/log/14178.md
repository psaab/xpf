# Issue #14178 — HTTP RPM redirect abandons target boundary

- **Issue:** `probeHTTP` (`pkg/rpm/rpm.go`) scoped and validated only the
  operator-configured target (`scopeHTTPTargetZone12908` +
  `canonicalizeHTTPTarget`), then followed endpoint-supplied `Location`
  headers to any origin: `CheckRedirect` enforced only a 3-hop cap. A
  configured endpoint (or a plaintext-HTTP on-path actor) could redirect
  the probe's GET — dialed with the probe's source/interface/VRF-bound
  socket — to an internal address, and an internal 2xx was scored as this
  probe's pass and published through RPM transitions to ip-monitoring,
  suppressing WAN failover for a path never actually measured.
- **Context read:** Issue body + deep-review D8-09 research (codex,
  opus, spark all MATERIAL at `e0c8e9913`). Cited paths re-verified at
  origin/master `805ac16cd`. In-tree redirect precedents read:
  `pkg/feeds` same-origin rule (`checkFeedRedirect`, #9912) and
  `pkg/ddns` same-host + no-downgrade rule (`guardRedirect`, #6545/#4861).
- **What:** `probeHTTP`'s `CheckRedirect` now admits a hop only when it
  stays on the configured target's origin — scheme, hostname, and
  effective port all equal to `via[0]` (the operator-configured request)
  — via the new `sameOriginProbeURL`/`probeOriginPort` helpers in
  `pkg/rpm/rpm.go`, mirroring the feeds rule. The 3-hop cap is unchanged.
  A refused hop returns a plain error (deliberately NOT
  `http.ErrUseLastResponse`, which would score the 3xx as the probe's
  verdict) and never renders the endpoint-supplied target, so the probe
  fails as path loss rather than passing off another service's 2xx. The
  scheme equality also refuses https->http downgrades, and because a
  hop can never leave the configured origin, a redirect can no longer
  introduce an unscoped link-local or a different internal service.
  NOT changed: the initial target's own admission (operator-configured
  loopback/private/link-local targets remain legitimate and are still
  scoped by #12908), the transport/dialer binding, the hop cap, and
  body-drain semantics.
- **Layer choice:** Admission is enforced in `CheckRedirect` against
  `via[0]`, not per-hop against the previous request: every admitted hop
  must equal the configured origin, so by induction no hop in a chain
  can drift (the ddns `guardRedirect` induction, anchored at the
  operator's URL rather than the endpoint's last spelling).

## Notes

- Fail-on-revert: removing the origin check (or comparing against the
  previous hop's endpoint-chosen spelling instead of `via[0]`) reddens
  the cross-origin cell; refusing ALL redirects reddens the same-origin
  control; returning `ErrUseLastResponse` would turn the refusal into a
  scored 302 and redden the cross-origin cell's error assertion.
- Cross-host/cross-port health endpoints that genuinely redirect (e.g.
  to a CDN) will now fail the probe instead of passing: operators must
  point the RPM target at the final origin. This matches the feeds and
  ddns in-tree doctrine for endpoint-chosen redirects.
