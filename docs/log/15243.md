## Defect (A60-01)

`PendingPMechReversePacket` stored the outer XDP descriptor with the
post-decap INNER meta and discarded the owned inner frame
(`owned_packet_frame`). On replay the poll loop re-entered with
`(held.desc, Some(held.meta), held.is_injected, true)`, sliced the OUTER
UMEM frame at inner offsets, and re-ran `stage_native_gre_decap` /
`stage_wg_decap` against inner bytes — which returns `NotGre`/`NotWg`
(the inner protocol is not GRE/WG), so the held packet was never
delivered or forwarded. Fail-closed loss of a bounded number of held
packets (at most 4 per token, 512 per binding) during an IPsec install
window, limited to reverse packets that arrived decapsulated from
native GRE/WG.

## Fix

Issue-sanctioned refusal leg (the alternative — storing the owned frame
and replaying it — would additionally require copying inner bytes into a
TX-pool frame or extending every downstream `desc`-based consumer; the
refusal is the bounded, fail-closed option the issue lists first):

- `pmech_replay::pmech_hold_admissible(is_injected, owned_frame_is_some)`:
  a native packet with `owned_packet_frame.is_some()` is NOT admissible
  to the hold queue. The hold site in
  `poll_binding_process_descriptor_with_injection` now recycles the
  descriptor and counts the refusal (`pmech_decap_hold_refused`),
  exactly like the existing over-cap branch, instead of stranding the
  packet. Injected packets (whose TX-pool descriptor already holds their
  owned frame bytes) and native non-decapsulated packets are unchanged.
- `PendingPMechReversePacket` gains `owned_frame: Option<Vec<u8>>` so the
  hold/replay fidelity contract is explicit in the type. It is `None` at
  the (only) production hold site after the gate above; the replay pop
  threads it through (`replay_owned_frame`) and, when present, sources
  `raw_frame` from the owned bytes (`replay_scratch_frame`) instead of
  slicing the outer UMEM frame. This closes the replay half of the
  mechanism: any admissible owned-frame hold replays the inner packet
  once, from its own bytes, and the native descriptor is recycled by the
  ordinary epilogue.
- New counter `pmech_decap_hold_refused` plumbed like the sibling named
  pre-L3 drops (#10498): `BatchCounters` → `BindingLiveState` (size guard
  re-measured: 2624→2688, offsets 2488→2496 / 2617→2625) → snapshot →
  `BindingLiveSnapshot` → coordinator refresh/reset → protocol
  `BindingCountersSnapshot` (`pmech_decap_hold_refused`, serde default) →
  Go `BindingStatus.PMechDecapHoldRefused` → Prometheus
  `xpf_userspace_pmech_decap_hold_refused_total` (summed across bindings,
  emitted unconditionally).

NOT changed: the drain (`drain_pending_pmech_replays`), waiter
registration, token/generation handling, and the native non-decapsulated
hold/replay control path (#13642) are untouched; no behaviour change
outside the cited mechanism.

## Tests

In `poll_descriptor_structure_13081_tests.rs` (`pmech_hold_15243` +
structural pin):

- `native_decapped_reverse_packet_is_refused_at_hold_15243` — the exact
  A60-01 admission cell: `pmech_hold_admissible(false, true)` is false.
- `native_plain_and_injected_packets_stay_admissible_15243` — named
  controls: native non-decapped and both injected shapes stay admissible.
- `inner_frame_fed_back_through_gre_decap_is_not_gre_15243` — drives the
  real `stage_native_gre_decap` with inner (decapsulated) bytes and the
  inner meta, asserting `NotGre`: the drop the refused hold avoids.
- `pmech_replay_sources_owned_frame_for_held_packets_15243` — structural
  pin (same style as the #13081 sibling-stage pin) that the replay pop
  threads `held.owned_frame` and parses it as `raw_frame`, and that the
  hold site consults the gate and counts refusals. Removing either turns
  it RED.
- The #13766 drain helper gains `owned_frame: None`; all drain cells
  (injected→TX pool, native→scratch, both terminal reasons) unchanged.

## Validation

- RED pre-fix: on `origin/master` the new cells do not compile (no
  `pmech_hold_admissible`, no `owned_frame`, no
  `pmech_decap_hold_refused`), and the mechanism premise holds there —
  the hold site pushed `PendingPMechReversePacket { desc, meta, … }`
  with no frame field and no `owned_packet_frame.is_some()` refusal.
- Checks main agent should run: `cargo test --bins 15243` (new cells),
  `cargo test --bins 13766` + `13642` (drain + native control),
  full `cargo test --bins`, `go vet ./pkg/api/ ./pkg/dataplane/userspace/`,
  `gofmt -l` on touched Go files, and a RED-on-revert spot check (revert
  `pmech_hold_admissible` to `true` → the refusal cell fails; remove the
  `replay_owned_frame` threading → the structural pin fails).

## Risk

Bounded to the cited mechanism. A decapsulated reverse packet arriving
during the (short) IPsec install window is now dropped-and-counted at
hold time instead of held-and-stranded at replay time — same fail-closed
loss bound (≤4/token, ≤512/binding), now operator-visible via
`xpf_userspace_pmech_decap_hold_refused_total`. Retransmits after the
install goes Live are unaffected. All neighbouring legitimate behaviour
(native non-decapped holds, injected holds, drain recycling) is
unchanged.
