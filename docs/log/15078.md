# Issue #15078: syslog source resolution ignores the collector's address family (A47-01)

## Why

`ResolveSyslogSourceAddr` (`pkg/config/syslog_source.go`) took no
collector-family input. It returned the unit's `primary` address — inet
wins the single `PrimaryAddress` slot at compile time
(`compiler_interfaces.go`: inet sets it unconditionally, inet6 only when
empty) — or else the first IPv4 address on the kernel interface
(`ipn.IP.To4() != nil`). A `security log` stream to an IPv6 collector on
a dual-stack `source-interface` therefore bound an IPv4 source and
failed to dial for the life of the config; the #14597 retry re-derived
the same wrong-family address, so it could not recover the audit stream.

## What

- `pkg/config/syslog_source.go`: new
  `ResolveSyslogSourceAddrForCollector(cfg, srcIface, collectorHost)`.
  An IP-literal collector restricts eligibility to its own family:
  family primary, then family preferred, then the first configured
  address of the family, then the first kernel address of the family
  (`source-interface lo` → `::1` for an IPv6 collector). No address of
  the family returns `""` with a WARN — the caller leaves the bind
  unbound (`""` already means kernel-chosen source and skips the
  wrong-family pin) rather than dialing with a mismatched source. A
  hostname/empty collector carries no family and keeps the legacy
  resolution byte-for-byte. `ResolveSyslogSourceAddr` is unchanged
  (delegates with no family); its config arm also no longer panics on a
  nil `*Config` (previously `cfg.Interfaces` dereferenced unchecked).
- `pkg/daemon/daemon_system.go` (`applySyslogConfig`,
  `syslogClientFingerprint`): both interface arms (per-stream, then
  global) resolve per stream via `ResolveSyslogSourceAddrForCollector`;
  the family-blind `globalSourceAddr` fallback after them is removed
  (for a literal collector it would re-pin the wrong family; for a
  hostname collector the global arm already is the legacy resolution).
  The fingerprint's per-stream term resolves family-aware too, so a
  stream whose correct source changes family rebuilds.
- `pkg/cli/apply.go` (`buildSyslogClients`): the identical mirror, per
  the #5738/#6875 parity requirement.
- `pkg/logging/README.md`: family-aware source-resolution bullet.
- Tests: `pkg/config/syslog_source_family_15078_test.go` (unit config
  arm incl. no-matching-family and hostname control, kernel `lo` arm),
  `pkg/daemon/syslog_family_15078_test.go` (apply-path binding for both
  arms + v4 controls, and the acceptance probe: an IPv6 UDP stream with
  `source-interface lo` is installed, binds `::1`, and delivers; v4
  control unchanged), `pkg/cli/syslog_family_15078_test.go` (CLI parity).

## Validation

- RED (pre-fix tree, tests kept): `pkg/config` fails to build —
  `undefined: ResolveSyslogSourceAddrForCollector` — the pre-fix
  resolver has no family input. Behavioural RED via a family-blind
  mutant (`syslogIPMatchesFamily` ignoring its family argument, fix
  otherwise intact): config cells fail with
  `IPv6 collector: resolved source = "10.0.1.20", want "2001:db8:1::20"`
  and `kernel lo + IPv6 collector: resolved source = "127.0.0.1", want "::1"`.
- GREEN: `go test ./pkg/config/ -run 'Syslog|LogStream'`,
  `go test ./pkg/cli/ -run 'Syslog|15078|6875|5738'`,
  `go test ./pkg/daemon/ -run 'Syslog|15078|6875|5738|14597'` — all pass,
  including the #6942/#6875/#5738/#14597 neighbours. `go vet` on the
  three packages clean; `gofmt -l` empty. A full `pkg/config` run hit
  the 240 s test-timeout under heavy parallel campaign load (panic in
  the testing runner at the deadline, no assertion failure observed);
  the syslog subsets above are the exercised gate.

## Risk

Neighbours preserved: explicit `source-address` still wins untouched;
hostname collectors and the legacy resolver are byte-identical;
IPv4-collector controls bind the same addresses as before on both apply
paths. The one deliberate delta: a stream whose source-interface has no
address of an IP-literal collector's family now binds unbound + WARN
(previously it pinned the wrong-family primary and the stream was
skipped/dead on dial — for UDP — or installed reconnecting forever on
TCP/TLS). Unbound lets the kernel pick a routable source of the right
family, which is strictly more deliverable. Residual: hostname
collectors still resolve family-blind (DNS may return either family);
recorded here, out of the cited mechanism's scope.
