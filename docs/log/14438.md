# #14438 — DR18-H2 Surface A Pass-1 address-loss withdraw has NO endpoint (H03) guard

## Mechanism
`pkg/ddns/surface_a.go` Pass 2 (binding removed) classifies via
`classifyOwnedBackend`: provider-gone or fingerprint-mismatch → keep
ownership + `noteOrphan` alarm, never a wrong-endpoint delete.
Pass 1 address-loss (binding still configured, observed address gone)
in `reconcileScopeLocked` called `backendFor(sc)` — the CURRENT
provider's backend — and `withdrawScopeLocked` → `withdrawOwnedLocked`
with no comparison of `owned.BackendFingerprint` against
`backendFingerprint(sc.Provider)`. So an in-place provider endpoint
edit (Cloudflare zone, Route53 hosted-zone-id, RFC2136 update-server,
DuckDNS/dyndns2 server) + address loss before any republish at the new
endpoint issued the delete at the NEW endpoint: for DuckDNS
`clear=true`/dyndns2 `offline=YES` it clears/offlines the whole
hostname at the new endpoint; for Cloudflare/Route53/RFC2136 it deletes
any same-(name,content) record there. Ownership was dropped as if the
withdraw succeeded and the old-endpoint record was orphaned WITHOUT
the H03 alarm. `WithdrawForReset` and Pass 2 were already guarded;
`publishLocked` H02 alarm only fires when an address is present.

## Fix
`pkg/ddns/surface_a.go` `reconcileScopeLocked` address-loss branch:
after the withdraw-backoff and `withdrawUnsupported` checks (ordering
unchanged) and immediately before `backendFor(sc)`, compare
`backendFingerprint(sc.Provider)` with `owned.BackendFingerprint`
when both are non-empty and `m.backend == nil` (fixed test backend
mirrors `classifyOwnedBackend`'s ownedBackendOK). On mismatch:
`noteOrphan(owned, cur, orphanReasonEndpointChanged, now)` and
`return nil` (mirrors Pass 2 `continue` — keep ownership, idempotent
alarm, no wire delete, no backoff/error churn). Pass 2,
`WithdrawForReset`, `publishLocked`, `withdrawOwnedLocked` untouched;
no new persisted field (fingerprint is credential-free).
