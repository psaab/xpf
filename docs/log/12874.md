# Audit-mode SYN-cookie ACK forwarding (#12874)

- **Issue**: #12874, research D7-07 (High, MATERIAL).
- **Cause**: Session-miss SYN-cookie ACK validation ignored `alarm_without_drop`. A standby/peer-minted valid cookie could return `Validated`, which the poll caller answers with an `AckRst` and recycle; an inherited active window could also reject ACKs. Both violate the audit profile's forward-with-alarm behavior.
- **Change**: Return `NotApplicable` for an audit zone before epoch checks, ACK validation rate limiting, or cookie MAC work. Enforcement-mode active and standby validation are unchanged.
- **Regression coverage** (`userspace-dp/src/screen/tests.rs`): A real MAC-valid standby cookie ACK is forwarded in audit mode without consuming standby budget or populating the validated-client cache; an inherited active latch and closing ACK also remain non-enforcing. A non-audit positive control still validates the same standby cookie.
- **Validation**: The new regression failed before the fix (`Validated` instead of `NotApplicable`) and passed after it (`cargo test screen::tests::syn_cookie_audit_zone_does_not_validate_standby_ack_12874`). The full `userspace-dp` suite had one unrelated failure: `afxdp::session_glue::tests::apply_worker_commands_demote_dedup_is_linear_not_quadratic`.
- **Risk**: Session-miss cookie ACKs in audit-mode zones no longer trigger validation, whitelist insertion, reset, or drop; ordinary enforcement-mode cookie behavior is unchanged.
