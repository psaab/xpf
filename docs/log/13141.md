# Align DHCP host-inbound scope with interface units (#13141)

- **Issue**: #13141, source finding D2-10 from the zone-enforcement deep review.
- **Cause**: `stampZoneDHCPScopeWithheld` records the #7490 decision per
  configured unit, but the #6519 advisory inspected a bare `zone.Interfaces`
  reference as one interface. A physical with server unit 0 and client unit 50
  was therefore reported as retained in full while runtime withheld unit 0.
  Separately, the role matcher treated a bare DHCP server reference as matching
  every sibling unit, and included `dhcpv6-local-server` in the IPv4 server role.
- **Change**: Expand bare zone members into their configured unit refs before
  the warning classifies each entry; skip quarantined zones and interface keys.
  Bare ordinary physical refs now match unit 0 only, while declared dotted
  physical names retain their parent semantics. DHCPv6 local-server no longer
  contributes to the IPv4 DHCP/BOOTP role. The host-inbound matrix documents
  the per-unit advisory and v4-only classification.
- **Regression coverage** (`pkg/config/host_inbound_dhcp_scope_13141_test.go`):
  unit 0 server / unit 50 client warning parity, bare server scope limited to
  unit 0, v6-only local server not withholding IPv4, and quarantine exclusions.
  `TestHostInboundRolesDeclaredDotted9821` also now asserts that a bare
  ordinary physical server ref does not match sibling unit 1 (#13141).
- **RED evidence**: On pristine origin/master `662ee842d`, the new issue tests
  failed: the bare zone member was reported as retained instead of naming
  withheld unit 0 and retained unit 50; the DHCPv6-only interface was withheld
  from IPv4 DHCP; and a bare server ref matched sibling unit 50.
- **GREEN evidence**: The issue and adjacent DHCP scope regressions pass with
  `GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/var/worktrees/.cache/go-tmp
  go test ./pkg/config -run '(13141|SameInterfaceDoesNotCollapseSiblingUnits6519|ZoneLevelDHCP|Advisory|SiblingUnitIsNotWithheldFromByItsPhysical7490|WithholdsZoneLevelDHCPForDeclaredNames12841)' -count=1`.
  Reverting the unit-0 matcher condition made
  `TestBareDHCPServerRefMatchesOnlyUnitZero13141` fail on the sibling-unit
  withholding, server-role, and matcher assertions; restoring the fix returned
  the regression set to green. After the final assertion update,
  `go test -timeout=30m ./pkg/config/... -count=1` passed
  (`ok github.com/psaab/xpf/pkg/config 387.914s`, 0 failed). The initial
  default-timeout full-suite run hit Go's 10-minute limit in the pre-existing
  bcrypt-heavy `TestSchemaSpellingDifferentialGate`; the first extended run
  then identified and corrected the stale sibling-unit expectation described
  above. `go build ./pkg/config/...` and `git diff --check` passed.
- **Blast radius / risk**: This changes only config-derived DHCPv4 withholding
  classification and its commit-time advisory. DHCPv6 behavior is unchanged;
  bare zone-member fan-down remains per configured unit, and declared dotted
  interface names preserve their established semantics.
