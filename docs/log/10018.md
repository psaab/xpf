# #10018: scope persistent-NAT leases by routing domain

## Change
- Added `routing_scope` to `PersistentSourceKey`, allocator lease records, idle-lease/display records, helper control JSON, and cluster lease records. Lease reuse is now partitioned by routing domain while translated address/port occupancy remains shared.
- Added active/standby coverage for PAT, address-only pools, lease release, and idle-lease export/import. The existing #9131 address-only guard now pins same-scope lease reuse; cross-scope reuse is covered by the new #10018 cells.
- Bumped the shared helper protocol from v24 to v25. Manager export/import/display verbs require an observed v25 helper and reject missing scope; status failures and unknown helper versions fail closed rather than defaulting to routing domain 0.
- Retired cluster message type 38. Scoped lease sets use additive type 39; type 38 is ignored without advancing the scoped sequence guard, so a legacy high-water mark cannot suppress a later scoped set.
- Scoped full-set receive now checks sequence before decode and advances only after a complete set, under a lease apply mutex through the callback. Malformed high-sequence input cannot wedge a later valid set, and concurrent receive loops cannot regress callback order.
- Regenerated the Rust wire fixture and moved the Go snapshot-version marker to v25 (the #8892 shape golden itself is unchanged — RoutingScope rides the lease control wire, not ConfigSnapshot). The Rust fixture also records an existing `RouteSnapshot.rule_priority: 0` specimen emitted by the generator.
