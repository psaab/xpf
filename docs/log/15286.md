# #15286 — daemon: early input barrier admits zoned fxp1 via blanket vrf-mgmt iifname before handoff

- **Timestamp**: 2026-10-19
- **Investigation**: Confirmed at `origin/master@0e0d6bf781`.
  `resolveEarlyInputGuardLifelines`
  (`pkg/daemon/input_barrier_gate_10751.go`) unconditionally seeded
  `config.ManagementVRFDeviceName` (`vrf-mgmt`) into the lifeline admit
  set, and `emitEarlyInputBarrierAdmitsWithLifeline`
  (`pkg/nftables/input_barrier_10751.go`) rendered it as a single
  `iifname {lifelines} accept`. Linux VRF local delivery switches
  `skb->dev` to the master, so at LOCAL_IN an enslaved packet's `iifname`
  IS `vrf-mgmt`: the rule admitted every co-enslaved member, including a
  declared zoned `fxp1` bound to that VRF. A zoned fxp1 is NOT a
  host-inbound lifeline (only fxp0 is fixed; cluster control/fabric count
  only when configured — `pkg/config/lifeline.go`,
  `TestDHCPLeaseChangeRequiresRecompile_ZonedNonLifelineFxp1`), yet the
  bootstrap/pre-handoff barrier admitted host ingress from it for the
  whole early window. The opposite lockout leg does not hold: tenant
  gates already deny fxp1 in steady state, so the barrier was strictly
  wider than the posture it hands off to.
- **Action**: Scope the barrier admission to lifeline MEMBERS,
  sdifname-style (cf. the gap fence in `pkg/nftables/netlink_fence.go`
  and the IPsec quarantine input exception):
  (1) `resolveEarlyInputGuardLifelines` no longer seeds
  `ManagementVRFDeviceName`; the returned set is member names only and
  the doc comment records why the master must never re-enter it.
  (2) `emitEarlyInputBarrierAdmitsWithLifeline` emits the pair
  `iifname {lifelines} accept` + `meta sdifname {lifelines} accept`:
  iifname covers unenslaved lifelines, sdifname recovers an enslaved
  lifeline member behind the master without admitting the master or any
  co-enslaved non-lifeline member. Empty set still installs the base
  shape. Interface/installer docs and `cmd/xpfd/README.md` updated to
  the per-member contract. NOT changed: the config-free global barrier
  (`InstallEarlyInputBarrier`, no lifelines — the pre-networkd unit
  shape), the handoff/removal lifecycle, and the resolver's
  verified-identity narrowing (leaf/record/detected-fallback logic is
  untouched apart from the master seed).
  - **File(s)**: `pkg/daemon/input_barrier_gate_10751.go`,
    `pkg/nftables/input_barrier_10751.go`,
    `pkg/nftables/netlink_installer.go`, `cmd/xpfd/README.md`,
    `docs/log/15286.md`
