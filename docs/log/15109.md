# #15109 — Synthetic SourceNatFlowKey aliasing a real host in interface-SNAT forced PAT

- **Timestamp**: 2026-10-18
- **Action**: Replaced the #14367 Check-B synthetic dummy flow in
  `match_source_nat_result_for_tuple_inner` with a must-PAT variant of the
  interface allocator. `PortAllocator::allocate_interface_identity` now
  delegates to `allocate_interface_identity_excluding(flow, translated_ip,
  holder, must_pat, excluded)`; `must_pat` skips the preserve-first arm and
  the `excluded` predicate (the existing `peer_owns` closure over the
  combined pool/NAT64 overlap index) is consulted for every PAT candidate,
  so a peer-owned candidate is skipped rather than minted and rolled
  back. The caller computes `must_pat = peer_owns(flow.src_port)` and
  keeps the existing post-mint `peer_owns` verification + rollback of the
  real flow as a fail-closed backstop. No fixed-address
  `SourceNatFlowKey` literal remains in production code.
