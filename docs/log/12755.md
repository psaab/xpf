# #12755 — preserve QNH after a packed next-hop interface child

## Red before

The accepted packed route

```text
routing-options { static { route 10.20.0.0/16 next-hop 10.0.0.1 interface ge-0/0/1.0 qualified-next-hop 10.0.0.2 preference 250; } }
```

was normalized into a `next-hop` node whose `interface` child also carried
`qualified-next-hop 10.0.0.2 preference 250`. Static-route compilation read
the interface value but not the sibling clause fused onto that child. Commit
succeeded with only the primary next-hop. The equivalent expanded form retained
the qualified backup.

## Change

The scoped static-route compact normalizer now extracts a complete packed QNH
suffix when it follows a `next-hop` interface child. It moves the suffix to the
existing QNH parsing path while leaving the gateway and interface on the primary
entry. Existing modifier parsing retains QNH interface, preference, and metric.

The regression compares compiled next-hop entries for the packed spelling and
expanded control, pins the route-key/interface/QNH clause order, keeps an
interface-only route unchanged, and checks a QNH carrying its own interface,
preference, and metric. Earlier packed-QNH coverage also remains in place.
