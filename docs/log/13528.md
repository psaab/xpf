# #13528 reconcile preserved slow-path MTU on runtime snapshot refresh

Issue: psaab/xpf#13528. Branch: `fix/13528-campaign-pub`.

## Context

`Coordinator::refresh_runtime_snapshot_inner` handles the fast same-plan
refresh used by day-2 configuration changes. It publishes the rebuilt runtime
snapshot while retaining the existing slow-path reinjector. Unlike the full
`apply_snapshot` path, it did not call `reconcile_preserved_slow_path_mtu`, so
an MTU-only commit updated snapshot configuration without reprogramming the
live TUN. Re-injected packets larger than the old MTU could continue to drop
until restart.

## Fix

- The successful runtime-refresh path now reconciles the preserved slow-path
  reinjector to `snapshot.slow_path_mtu()` after publishing the new runtime
  view, matching the existing full-apply MTU reconcile.
- Coordinator slow-path status snapshots are refreshed after reconciliation, so
  status reflects a successful update or a failed/degraded TUN attempt.
- The existing helper is reused; desired-MTU deduplication and delegated-outlet
  retry semantics remain unchanged. No TUN is created when the refresh has no
  preserved slow-path reinjector.

## RED → GREEN

- **RED on pristine `origin/master` (`98d56af14`)**:
  `cargo test --manifest-path userspace-dp/Cargo.toml
  runtime_snapshot_refresh_reconciles_preserved_slow_path_mtu_13528` failed
  because `last_slow_path_mtu_reconciled` remained `0` instead of `9000`.
- **GREEN**: the same regression test passed after the refresh call was added.
  It uses a no-worker test reinjector with no real device name, asserts that
  refresh attempts the 9000-MTU reconcile, and confirms the failed test ioctl
  retains the live MTU and marks the path degraded.
- **GREEN**: `cargo test --manifest-path userspace-dp/Cargo.toml
  slow_path_mtu_tests` passed all 12 existing helper and full-apply wiring
  tests, including unchanged-desired-MTU deduplication and the actual
  `apply_snapshot` call site.
- Full `cargo test --manifest-path userspace-dp/Cargo.toml` ran the 7,952-test
  unit suite successfully (8 ignored), and preceding integration targets
  passed. The run stopped at `runtime_view_publish_and_read_sites_are_pinned`
  (30 passed, 1 failed), which reported six #6592 source-count violations.
  The identical test fails with the same six violations on pristine
  `origin/master` (`7e88a14`), so that failure is base-attributed and unrelated
  to the MTU change.

## Risk / scope

Only the same-plan refresh path changed. Snapshot validation, routing, TUN
creation, and the full-apply path are unchanged. The regression test deliberately
uses an empty device name to avoid issuing a privileged TUN ioctl; it verifies
that the refresh invokes the existing reconcile logic, while the helper tests
cover successful MTU programming deterministically.
