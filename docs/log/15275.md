# #15275 — deterministic-NAT /0 host silent fallback (C05-02)

- **Issue**: #15275 (C05-02)
- **Branch**: `fix/15275-campaign`

## Defect

A deterministic source pool with `port deterministic host address 0.0.0.0/0`
committed with neither a reject nor the #4559 not-enforced advisory, and
silently ran round-robin PAT — losing the deterministic (audit-reversible)
property without any operator signal.

Gate-vs-builder predicate split, three sites disagreed about `/0`:

- `pkg/config/compiler_validate_strict_nat.go`
  (`validateSourceNATDeterministicStrict`): computed
  `hostCount = 1 << (bits-ones) = 1<<32` in `uint64` and only rejected when
  `totalBlocks < hostCount`. Any pool with
  `poolHosts * blocksPerIP >= 2^32` (e.g. two `/16` members = 131072
  addresses at block-size 1 over the default 1024-65535 range) satisfied
  it and committed clean; smaller pools were rejected for the wrong
  reason ("insufficient capacity").
- `pkg/config/compiler_validate_warn.go` (`deterministicIPv4Enforced`):
  returned `bits == 32`, so `/0` counted as enforced and the #4559
  advisory was suppressed.
- The builders refuse `/0`: `deterministicSourceNATFields`
  (`pkg/dataplane/userspace/nat_source.go`, `hostBits >= 32` → mode 0) and
  `poolParams` (`pkg/nat/deterministic.go`, same guard → lookup error).

## Fix

Fail closed at the commit gate and align the advisory predicate with the
builder's exact predicate (`bits == 32 && hostBits < 32`):

- `compiler_validate_strict_nat.go`: in the IPv4 arm, reject `ones == 0`
  per se ("IPv4 deterministic host prefix /0 … is not enforceable …
  configure a /1 or narrower host prefix") before the capacity check.
  On the tolerant/lenient path this downgrades to a warning and retains
  the pool, per the existing uniform-gate wiring (#1960 no-brick).
- `compiler_validate_warn.go`: `deterministicIPv4Enforced` now requires
  `ones > 0`; the #4559 advisory text names "an IPv4 /0 host" among the
  not-enforced causes, so a leniently loaded `/0` pool (builder mode 0)
  is advised as well as warned.
- `docs/deterministic-nat-cgnat.md`: `/0` rejection documented next to
  the capacity validation description.

Behaviour outside the mechanism is unchanged: `/1` (hostBits 31) still
commits enforced with no advisory when capacity covers it, `/25` etc.
unchanged, IPv6 mode-2 arms untouched, deterministic capacity counting
(#15177) untouched. The builder and `pkg/nat` already failed closed and
needed no change.

  (`/1` commits, no advisory) and
  `TestDeterministicSlash25StillCommitsNoAdvisory15275` — both GREEN
