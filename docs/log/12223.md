# Issue #12223 — make application-list wildcard validation order-insensitive

## Why

The userspace application lowerer returned match-any as soon as it saw `any`, so a later defined application whose authored match was partly dropped by tolerant compilation escaped `ApplicationReferenceMatchDrops` validation. Reversing the same list reached the drop and poisoned the policy snapshot.

## What

Before returning match-any for a wildcard, the lowerer validates every later application reference with the same helper used for ordinary expansion. Dropped matches, unresolved references, unrepresentable protocols, and malformed ports poison the rule in either order. The legacy `compileApplications` prepass independently rejects undefined references.

## Validation

- **RED before** (STEP-0 base `a714c90d472a3c3d98a3799831cfef3ec311a61c`): a temporary snapshot repro on `[any, icmp-port]` produced no application terms and no rejection reasons (match-any); `[icmp-port, any]` produced the `__unsupported__` sentinel and a reason naming `icmp-port`. The regression also failed before the fix with match-any terms for the first order.
- **GREEN after the GLM R1 F1 fold**: per-reference validation now rejects undefined names, unexpandable sets, protocol-less apps, #2124 protocol/port failures, and dropped matches in either order. `go test ./pkg/dataplane/userspace -run '12223|9525' -count=1` and `go test ./pkg/dataplane -run '12223' -count=1` passed; adjacent #2124/#3323/#3727/#12048/#3227/#3298/#3372/#11341 userspace regressions passed as well.
- `go build ./pkg/dataplane ./pkg/dataplane/userspace` passed; `gofmt -l` on the three changed Go files produced no output.
- `go test ./pkg/dataplane ./pkg/dataplane/userspace -count=1` reported six unrelated failures: `TestMapZoneInterfaceDottedFakeLink9821`, `TestOperatorPackagesOnlyUseDocumentedLegacyDataplaneImports`, `TestHAWatchdogClaimsUseTheHelperLease10791`, `TestNilUnitSlotCastsNoTrunkZoneVote_6722`, `TestRetainedLiveXfrmiLeavesTheAdjudicatedSets/untracked_after_daemon_restart`, and `TestSnapshotShapeIsPinnedToProtocolVersion8892`. Running those six on a clean worktree at the same base reproduced the failures.

## Risk / residual

The wildcard short-circuit now uses the same per-reference validation as ordinary expansion, including reference resolution, match drops, empty/unrepresentable protocols, and port representability; all such failures poison either order. The legacy `compileApplications` prepass still independently rejects undefined names. The legacy eBPF/BPF compiler path has its own wildcard handling and is outside this userspace snapshot fix. No live dataplane or cluster was exercised; verification uses Go snapshot-lowering and compiler-prepass tests.
