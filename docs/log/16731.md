# #16731 — Unmodelled Junos credential leaves render in cleartext on redacted show surfaces

- **Timestamp**: 2026-10-25
  - **Action**: `secretIndices` (pkg/config/ast_redact.go) used a closed
    enumeration, so PPPoE `default-chap-secret`/`local-password`,
    outbound-ssh `secret`, SecIntel `auth-token`, SNMPv3
    `snmp-community … community-name`, dhcp-local-server (group/global/
    dhcpv6) `authentication password`, and dhcp-relay group
    `authentication password` committed clean on open-world/inert paths
    and rendered in cleartext via RedactedClone to PermView readers on
    CLI/gRPC/REST `show configuration`. Fail closed instead: a new
    credential-shape arm (`isCredentialShapedKeyword16731`) masks all
    trailing tokens for any keyword containing `secret`/`password` or
    exactly `auth-token`/`community-name` in any context, and bare
    `secret` gains the `outbound-ssh` ancestor gate. Exact exemptions
    (`secret` itself, `master-password`, `no-password-authentication`,
    `no-passwords`) and the deliberate non-masking of valued `*-key`
    public identifiers (trusted-key/tsig-key/aws-access-key, GRE/chassis
    `key`) keep security-name/access-profile/tls-profile and other
    non-secrets rendering. The same secretIndices set drives the
    placeholder-ingest guard and compare fingerprints, so redacted
    exports of the new rows are refused on re-apply. Registry test
    enumerates the accepted-unmodelled credential keywords.
