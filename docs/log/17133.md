# #17133 — single SyncedDeleteMode selection for synced deletes

- **Timestamp:** 2026-10-27
- **Branch:** `fix/17133-campaign`
- **File(s):** `userspace-dp/src/afxdp/ha/session_import.rs`, `userspace-dp/src/afxdp/ha/mod.rs`, `userspace-dp/src/afxdp/mod.rs`, `userspace-dp/src/server/handlers/sync_session.rs`, `userspace-dp/src/afxdp/ha_tests.rs`, `userspace-dp/src/afxdp/coordinator/tests.rs`

## Why

The (peer × strict-mirror × scoped) delete mode was chosen twice: a hand-written ladder in `server/handlers/sync_session.rs` and a second ladder inside `delete_synced_tunnel_variants`, over six public wrappers that differed only in the positional bools they forwarded to `delete_synced_session_gen_marked`. #12886 was a divergence between the two ladders (the variant path dropped `strict_mirror` and reported success on gate/mirror failure); the variant ladder also had no scoped arm, so a scoped mode's `expected_id` was silently dropped on the variant path (latent today — no production caller sends tunnel-variant purge with a scoped delete).

## What

- Introduce `#[derive(Clone, Copy)] pub(crate) struct SyncedDeleteMode { peer, strict_mirror, expected_id: Option<NonZeroU64> }` in `session_import.rs`, with named consts `LOCAL`, `LOCAL_MIRROR`, `PEER`, `PEER_MIRROR` and the fallible scoped constructor `peer_mirror_scoped(u64) -> Option<Self>` (zero is identity-missing and unconstructible).
- Add the single entry `SessionDomain::delete_synced(key, mode, forward_only) -> SyncedDeleteOutcome`; `delete_synced_tunnel_variants(key, mode, forward_only)` now calls it per variant — no second selection.
- Delete the six bool-forwarding wrappers (`delete_synced_session_mirror`, `delete_peer_synced_session`, `delete_peer_synced_session_mirror`, `delete_peer_synced_session_mirror_scoped`, and the ladder arms); `delete_synced_session` (helper-local purge) and `delete_synced_session_gen` (generation seam) remain, forwarding `LOCAL`/gen through the same inner call.
- Handler builds the mode once from `sync_req` (scoped via the constructor, guaranteed by the existing session_id==0 early return) and threads it through both the exact delete and the tunnel-variant purge.
- Migrate all test callers to `delete_synced(..., SyncedDeleteMode::...)`; the zero-identity scoped test now asserts the constructor refuses zero.
- Add parametrised parity test `synced_delete_mode_parity_exact_vs_tunnel_variants_17133`: every mode (LOCAL, LOCAL_MIRROR, PEER, PEER_MIRROR, scoped-mismatch) runs through both the exact and variant paths on identical GRE fixtures and asserts identical outcomes and survival, including the scoped identity refusal.

## Risk

Selection semantics are unchanged for every existing wire combination: the mode fields map 1:1 onto the bools the removed wrappers forwarded (`delete_gen=0`, `clear_fence=None`, `expected_reverse_owner=None`, `external_lease=None` throughout). The only behavioural delta is the previously-latent one: a scoped mode reaching the tunnel-variant purge now honours `expected_id` instead of dropping it — no production request does this today. The handler's `.expect` on the scoped constructor is unreachable because the `session_id == 0` scoped request returns `identity-missing` earlier in the same function.
