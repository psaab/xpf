# #16874 — Repeated `from zone` value on NPTv6 static rule-set wedged every apply

- **Issue**: R3-B09-02. `from zone [ untrust untrust ]` (or repeated
  `from zone untrust;` hierarchical statements) on an NPTv6 static
  rule-set committed clean, then every dataplane apply failed the
  #4960 NPTv6 overlap pre-pass with `rule "r1" overlaps rule "r1"`,
  keeping the previous snapshot forever.
- **Mechanism**: `collectNATScopes` concatenated scope tokens with no
  dedupe, so `compileNATStatic` emitted two identical
  `StaticNATRuleSet{R, untrust}` expansions. Strict
  `validateNPTv6Strict`'s #4339 self-skip is keyed only on
  (rule-set, rule) names, so the duplicate pair was never compared and
  the commit persisted; `NPTv6OverlapConflict` (and the Rust helper,
  which has no name-identity skip) rejected the self-overlap at apply.
- **Change**:
  - `pkg/config/compiler_nat_helpers.go`: new `dedupeNATScopes` drops
    exact `(kind, value)` repeats (first-seen order preserved);
    `collectNATScopes` applies it to both from- and to-scope lists, so
    every NAT kind (source / destination / static / nat64 via the same
    helper) collapses a repeated scope value to one expansion — the
    Junos reading (a repeated list value is one value). Distinct
    values, distinct kinds, and the match-any `{zone, ""}` default are
    untouched; the #4339 multi-scope shape (`[ untrust trust ]` still
    expands twice and commits via the self-skip + zone partition) is
    unchanged.
