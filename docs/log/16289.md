# #16289 — session-sync idle precondition compares absolute cumulative counters

- **Timestamp**: 2026-10-22
- **Action**: `ha_session_sync_idle_sample` required absolute
  `source sent == target received` for cumulative-since-daemon-start
  `Session create` counters. On the tcp cluster the epochs differ
  (evidence: source sent=15, target received=174, pending=0, static for
  the whole 30 s window, later 74 vs 233 — constant offset 159), so the
  precondition could never hold, the gate FAILed "session sync did not
  become idle", and every precondition-gated RG1 cell VOIDed.
  Made idle baseline-relative while preserving fail-closed semantics:
  the helper now takes an explicit `(baseline_sent, baseline_received)`
  pair; the first sample of a wait only establishes the baseline (never
  idle by itself); idle requires
  `sent - baseline_sent == received - baseline_received` with
  `pending == 0`. A counter rewind since baseline (daemon restart /
  epoch reset) is not idle and forces re-baselining rather than
  comparing across epochs; malformed or half-empty baselines are VOID
  (status 2). Both wait loops (`test-failover.sh`
  `ha_wait_for_session_sync_idle`, `scripts/userspace-ha-failover-validation.sh`
  `wait_for_session_sync_idle`) thread the baseline and re-baseline on
  every non-idle sample, so the existing 3-consecutive-idle rule now
  proves "nothing sent since the baseline is unreceived" over
  consecutive samples. NOT changed: parsers, the 3-sample/30 s policy,
  `pending`/`drained` requirements — a genuinely stuck sync (sends
  arriving unreceived, or pending nonzero) still never goes idle.
