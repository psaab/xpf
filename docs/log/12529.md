# #12529 — preserve inherited route-filter modifiers

- **Action**: Keep the optional route-filter range token attached while expanding a packed policy term inherited through `apply-groups`.

## Root cause

`groupPackedLeafBody` expands a packed group term before merging it with an inline term. Its shared `packedBodyChildren` walker consumed route-filter's schema-declared `route-filter <prefix> <match-type>` span but did not include the supported fourth token for `upto /N`, `prefix-length-range /N-/N`, or `through <prefix>`. The next token then fell outside every open schema level; the conservative walker returned the original empty children, and merge treated the group term as unexpandable. The inline `term T then accept` won, losing the inherited `from` clause.

## Change

- In `packedBodyChildren`, apply `packedRouteFilterWidth` to the positional two-argument route-filter leaf. This retains its recognized optional range modifier as part of the synthesized route-filter node; unrelated packed-tail parsing remains unchanged.
- Added group-expansion regressions for `upto`, `prefix-length-range`, `through`, protocol plus route-filter, and a braced main term; `exact` and `orlonger` provide unchanged controls.
- Added a `LoadOverride` + `Commit` assertion for the committed `RouteFilters` and a rendered route-map assertion for the inherited `match ip address prefix-list` and `le 24` clause.
