# Issue #15765 — `applyTunnelHostInbound` overwrites ZoneID/ScreenProfileID, ignores ip6gre

## Claim (narrowed, verified at origin/master 320c26c08c)

- `applyTunnelHostInbound` (`pkg/dataplane/compiler_iface.go`) built a fresh
  `ZoneConfig{HostInbound: merged}` (ZoneID=0, ScreenProfileID=0) and called
  `dp.SetZoneConfig(zid, zc)`; `Manager.SetZoneConfig` is a full-entry
  `UpdateAny` overwrite, so any GRE-transport zone lost the screen profile
  (and zone-id field) installed earlier by `programZoneMaps`/`buildZoneConfig`.
- It tested only `tun.Mode == "gre" || tun.Mode == ""`, so an explicit
  `mode ip6gre` tunnel never auto-added `HostInboundGRE`.
- The same incomplete mode check gated the `ip link set ... type ip6gre
  encaplimit none` exec in `applyKernelTunnelLocked`
  (`pkg/routing/tunnel.go:908`): codex-a correctly noted the exec *does*
  emit `ip6gre` for `gre`/`""`, but explicit `ip6gre` was skipped.
- `DroppedEnforcementChild` leg: the scan already skipped quarantined zones
  via `config.ZoneQuarantineExclusionsForConfig` (which includes poisoned
  zones, #13099) and `buildZoneConfig` already skipped the screen lookup for
  poisoned zones. The fix preserves both guards; the regression pins that a
  poisoned zone sharing the transport address is never programmed.

## Fix

- `pkg/dataplane/compiler_iface.go` (`applyTunnelHostInbound`):
  - Accept `ip6gre` alongside `gre`/`""` for `HostInboundGRE`.
  - Replace the manual host-inbound-only re-derivation with
    `buildZoneConfig(zone, zoneName, zid, result)` — the same builder
    `programZoneMaps` used — then OR in the auto flag and write only when
    the flag was missing. This preserves `ZoneID`, `ScreenProfileID`, and
    `TCPRst` exactly. An unresolvable screen profile now warns and skips
    that zone instead of silently zeroing it (programZoneMaps already
    fail-closed validated references earlier in `compileZones`).
- `pkg/routing/tunnel.go`: extracted `needsIP6GREEncapLimitNone(mode,
  isIPv6)` (`gre`/`ip6gre`/`""` + IPv6) and used it for the encaplimit exec,
  so explicit `ip6gre` creations get `encaplimit none`.

## Risk

- `applyTunnelHostInbound` now calls `buildZoneConfig`, which logs the
  screen assignment a second time for tunnel zones (cosmetic).
- If a hand-built config reaches this seam with an unresolvable screen
  profile (bypassing `compileZones` validation), the zone is skipped with
  a warning rather than written zeroed — fail-closed relative to before.
