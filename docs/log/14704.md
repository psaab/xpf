- **Timestamp**: 2026-10-17
  - **Action**: Fixed #14704 (D14-02) `uint8` truncation in `marshalHeartbeatBody`: a monitor interface name >255 bytes wrapped its `NameLen` byte (260→4) and >255 monitors wrapped the `NumMonitors` byte (260→4), while the full payload was still written. The receiver trusted both bytes, so it parsed monitor payload as the version trailer and never reached the `XPFE` echo trailer — poisoning `SoftwareVersion`/`HAProtocolVersion` and silently losing the echo lease. Added `maxHeartbeatMonitors=255` / `maxHeartbeatMonitorNameSize=255` caps mirroring the existing group (#4434) and software-version clamps: oversize names are skipped whole (not `break`, so later monitors survive) and the monitor count stops at 255. Both drops are reported by the existing `heartbeatMonitorTruncations` detector (`observe(len(pkt.Monitors), numMon)`), so the truncation is operator-visible. RED on origin/master: 260-byte name decoded as `aaaa` + garbage monitor, 256-byte name decoded as empty name, 260 monitors wrote count byte 4. GREEN after fix with boundary controls (255-byte name, 255 monitors) round-tripping verbatim, including groups, software version, HA protocol version, and both echo session/sequence pairs.
