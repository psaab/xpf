# Issue #16480 — Stage-11 IPsec pre-claim PBR `Drop` ends on the uncounted evaluation

- **Issue:** The #14314 Stage-11 pre-claim probe in
  `poll_descriptor/mod.rs` resolved the input-filter PBR route override
  with `ingress_route_table_override_uncounted` and, on
  `RouteOverride::Drop`, recycled and continued. That arm is terminal:
  the packet never reaches the claimed arm or the ordinary miss path
  where the counted evaluation (term counter, filter log, `PbrRejectSink`
  reject reply) and the #11061 `ambiguous_fabric_zone_drops` count run.
  An IPsec-class packet (UDP/500, UDP/4500; ESP/AH are flowless and do
  not reach this flow-backed probe) dropped by a
  `then { routing-instance X; reject|discard; }` term therefore moved no
  counter, emitted no log, and got no reject reply, and an
  Unresolvable-domain drop on a quarantined fabric domain missed the
  #11061 count. Enforcement was never lost — the packet was always
  dropped; only operator-visible accounting/reply semantics were.
- **What:** On the pre-claim `Drop` arm only, re-run
  `ingress_route_table_override` once — counted, with
  `worker_ctx.event_stream` and a `PbrRejectSink` over the binding TX
  pipeline — then apply the miss path's #11061 rule
  (`effective_routing_domain_for_flow(...) >= AMBIGUOUS_FABRIC_DOMAIN_BASE`
  → `record_ambiguous_fabric_zone_drop()`), then recycle. The
  `Table`/`None` arms stay on the single uncounted probe: those packets
  proceed to the claimed arm or miss path, whose counted evaluation
  fires exactly once, so counting the probe would double-count
  (#13760). The stale #14314 "Uncounted: the counted evaluation still
  runs exactly once..." comment is rewritten to state the terminal-Drop
  exception.
- **Tests:** New `stage11_pbr_drop_16480_tests.rs` driving the real
  descriptor path (`txn_run_descriptor_with_event_stream`) against a
  `nat_snapshot` fixture whose ingress interface carries a counted,
  logged PBR `routing-instance sfmix; reject|discard` term:
  UDP/500 subject counts exactly 1 and enqueues one reject reply;
  `discard` counts 1 with no reply; TCP SYN and UDP/53 controls count
  exactly 1 with one reply each (no double count); a claimed-passthrough
  IKE packet under an accept `routing-instance default` term counts
  exactly once; the PBR filter-log event fires exactly once with the
  PBR wire reason.
- **RED→GREEN:** With the Drop arm temporarily reverted to
  recycle-and-continue, 3 of 4 cells fail (counter 0 vs 1; no log); the
  claimed-passthrough control passes both ways. With the fix, 4/4 pass.
