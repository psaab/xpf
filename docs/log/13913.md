# #13913 — PPTP assignment guard ignores trailing-comment mentions

- **Action**: Require the resolver call to be the actual expression assigned to `flow`; strip line comments before matching.
- **Base**: `origin/master` `5aa9179e4e285c102f14e27f60c58f8fd9facc5a`
- **Files**: `userspace-dp/src/server/tests.rs`, `docs/log/13913.md`

## Why

The descriptor-loop source guard accepted `flow = None; // ...pptp_data_session_flow_in_domain(...)` because it checked that an assignment line contained the resolver needle. The comment could therefore keep the guard green after deleting the production call.

## What

The assignment matcher strips `//` comments before analyzing source lines, then requires the right-hand side of `flow =` to begin with the resolver call. Added an over-reach regression for the reported trailing-comment shape and retained checks for commented-out, prose-only, unassigned, wrapped, and inline real calls. The existing production-source guard continues to enforce that the resolver call occurs after flow parsing.

## Validation

- RED: the new trailing-comment regression failed against the original matcher.
- GREEN: the mention-control regression and production-source guard each passed.
- Fail-on-revert: replacing the production resolver with `flow = None; // ...resolver...` made the production-source guard fail as intended.
- Full `cargo test --manifest-path userspace-dp/Cargo.toml`: 8,142 passed, 8 ignored, 4 unrelated failures (`pkt_len_fixture_drift_6883`, `worker_loop_orders_expiry_teardown_before_poll_10419`, `additive_wire_exhaustive_literals_only_ever_decrease_7689`, and `syn_cookie_invalid_ack_flood_does_not_grow_validated_cache`). The resolver tests passed.

## Risk

The source matcher is intentionally limited to the call formatting used by rustfmt; stripping `//` is sufficient for this qualified resolver call, which contains no string literals.
