- **Issue**: #16671 — On a fail-closed boot of a committed firewall, the main-table default-route NIC (the WAN, since fxp0 lives in vrf-mgmt) becomes the management lifeline: the persisted lifeline record is overwritten, the bootstrap input guard admits the WAN NIC whole, and the live-address fence withholds the WAN addresses
- **Change**: `setupBootstrapLifeline` in `pkg/daemon/bootstrap.go` now returns early when `EverCommitted()` is true: on a committed box the main-table default is the WAN (fxp0 is in vrf-mgmt, rendered without a main-table gateway), so route detection must never overwrite the verified persisted lifeline record nor rename the WAN to fxp0; only never-committed boxes learn a lifeline from route detection (appliance factory fallback unchanged, already `!everCommitted`-gated). `installFailClosedBootHostFences` in `pkg/daemon/daemon_failclosed_boot.go` no longer adds the detected default-route NIC to `protected`: management is derived only from the persisted record plus the explicit management leaf (via `resolveProtectedInterfaces`) and management-class names (`fxp*/fab*/em*`, `config.IsManagementIfName`, #6731); the detected-route link-presence check is removed, while the route-error skip and the verified-form skip (detected management-class NIC that is not a verified identity) preserve the no-lockout discipline. The bootstrap input guard (`resolveEarlyInputGuardLifelines`) needed no change once the record can no longer be poisoned: its existing rule already excludes a detected NIC whenever a distinct record resolves.
- **RED→GREEN**: New `pkg/daemon/bootstrap_committed_wan_lifeline_16671_test.go`: `TestBootstrapCommittedDoesNotOverwriteLifeline16671` drives the real `setupBootstrapLifeline` on a committed store with the default route on eno3 (index 1) and a seeded eno2 record — record must survive byte-for-byte, no rename/reload/.network, and the guard must exclude eno3 while admitting eno2 (pre-fix the record is overwritten to eno3's PCI and the guard admits eno3). `TestFailClosedFenceFencesWANWhenRouteIsWAN16671` fences ge-0-0-0's 192.0.2.10/2001:db8::10 while sparing fxp0's 10.0.0.1 (pre-fix `protected[ge-0-0-0]=true` withheld the WAN, fenced=[]). `TestBootstrapNeverCommittedStillRecordsRouteLifeline16671` is the tightness control: never-committed route lifeline still writes the bootstrap .network.
