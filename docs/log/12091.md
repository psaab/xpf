# #12091 — warn on unenforced lo0 filter bindings

- **Issue**: #12091 — lo0 input filters on units other than 0, and lo0 output filters, were accepted without enforcement or advisory.
- **Branch**: `fix/12091-lo0-filter`
- **Worktree**: `/var/worktrees/12091-lo0-filter`
- **Base**: `1c384b9a47ff7d6e567fa50632faa75c3995ae87`

## Why

The compiler derives only `lo0` unit 0 `family inet[6] filter input` into `System.Lo0FilterInputV4/V6`. Both host planes consume only those system fields. Other lo0 unit input filters and every lo0 output filter therefore stayed in the interface model without being enforced, while strict commit accepted them silently.

## What

- Added a deterministic WARN-only validator for nonzero-unit lo0 input and all lo0 output bindings in both families. Each advisory names the unit, family, direction, filter, and states that only unit 0 input is enforced; it carries the stable `#12091` identifier and says “accepted but NOT enforced.”
- Wired the validator into `ValidateConfig`, which the strict tail-gate path appends to the returned config's `Warnings`.
- Kept unit-0 input derivation and enforcement unchanged.
- Added flat-set and hierarchical strict-compile coverage for unit-1 inet/inet6 input, unit-0 inet/inet6 output, and unit-1 output; controls assert unit-0 inet/inet6 input still populate the System fields without a #12091 advisory.
