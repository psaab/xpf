# #14152 — CLI `request` handlers: journal audit / reason sanitization / IsLocalPrimary guard

## Defect (3 sub-claims, at origin/master 7d6ac3b2b)
1. `handleRequestSystem` (pkg/cli/cli_request_system.go) executed `systemctl reboot|halt|poweroff` and `performConsoleZeroize()` with no `LogSystemActionAs`, unlike gRPC `logSystemAction` (server_diag_system_action.go, fsynced journal-before-acting #4108). No durable attributable record.
2. `handleRequestSecurityDynamicAddress` (cli_request_security.go) checked only reason length (512) and never rejected control chars, unlike remote CLI (cmd/cli/request.go) and gRPC twins. Decisive check: trace `AcknowledgeFeedShrink` — it validates actor/reason via `unicode.IsControl` (rejects), and downstream sinks DO exist: journal `reason=%q` in both handlers, `show ... reason: %q`, and `slog.Warn(... "reason", guardReason)` in feeds install path. So CLI pre-check was the missing parity gate (feeds layer would reject late with generic error after CLI's stale-tuple checks; twins reject early with specific message). Fixed at CLI layer for parity; reason can contain C1 controls (U+0085) that pass CLI `r<0x20||0x7f` but feeds `unicode.IsControl` rejects — CLI parity now matches twins exactly, feeds remains stricter backstop.
3. `KindRGFailoverNode` with `op.Node == NodeID()` called `RequestPeerFailover` unconditionally; gRPC short-circuits on `IsLocalPrimary` (server_diag_system_action.go:808). Console got raw `node is already primary` error from cluster layer instead of clean already-primary message / no-op.

## Fix
- pkg/cli/cli_request_system.go: added `consolePowerAction` seam (package var, `exec.Command("systemctl", arg)`), `confirmSystemAction()` helper (nil-safe `c.readLine()` seam, restores prompt), `logSystemAction()` helper (`store.LogSystemActionAs(action, journalPrincipal())`, nil-store safe). reboot/halt/power-off journal BEFORE `consolePowerAction`; zeroize journals BEFORE `performConsoleZeroize()`. Detail strings exactly `reboot`/`halt`/`power-off`/`zeroize` matching gRPC.
- pkg/cli/cli_request_security.go: reject `r < 0x20 || r == 0x7f` in reason with `reason must not contain control characters`, after length check, before any feed lookup/ack — identical to twins.
- pkg/cli/cli_request_chassis.go: `KindRGFailoverNode` local-target branch checks `IsLocalPrimary(op.RG)` first, prints `Redundancy group %d is already primary on node %d` and returns nil (gRPC message verbatim).
- pkg/cli/command_output_termsafe_6584_test.go: moved fork exemption from `handleRequestSystem` to `<package-scope>` (consolePowerAction) — the fork moved out of the handler; guard test flagged stale exemption.
