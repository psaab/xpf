# Issue #16081 — REST server has no connection-count bound (DOS-6)

- **Issue:** The REST (management HTTP/HTTPS) listeners built per-connection
  timeouts (#4150) but no bound on connection count. An attacker opening many
  idle/slow connections could exhaust file descriptors / listener capacity
  for legitimate management clients. Validated Low; existence of the missing
  bound confirmed at `c1b86e871b`, fd-collapse consequence leg NV.
- **What:** Added `pkg/api/conn_bound_16081.go`: a single per-Server
  `apiConnGate` (limit `apiMaxConnsTotal` = 256, var so tests can shrink it)
  shared across every HTTP and HTTPS leg on both planes — the protected
  resource (process fds/goroutines) is per-process, so the count is too.
  `serveLegLocked` wraps each leg's listener exactly once at serve time
  (Start + reconcile legs alike; `leg.ln` stays raw so `Addr()`/`Effective*`
  are unchanged), and `bindListeners` wraps the `Run`/`serveBound` path.
  Bare `&Server{}` fixtures have a nil gate and keep unwrapped listeners.
  At Accept, excess connections are closed immediately (never reaching
  http.Server, so no goroutine/buffer cost), counted, and rate-logged
  (~1/sec). Refusal returns a temporary `net.Error` so the serve loop backs
  off and retries instead of exiting — a fatal error would have turned the
  DoS bound into a self-DoS. Admitted connections are `gatedConn`s that
  release the slot exactly once on first Close; TLS connections are counted
  at the raw TCP layer so a stalled handshake holds exactly one slot, and
  hijacked connections release via the #7011 hijack-tracker drain.
  Observability: `xpf_rest_conn_refusals_total` and `xpf_rest_conn_active`
  exported always (even at zero, #3464) via the deferred pre-gate collector
  route shared with the #8312 admission refusals.
- **Docs:** `pkg/api/README.md` management DoS gotcha extended.

## Notes

- Perf: accept/close path only — one atomic CAS per accepted connection and
  one per close; no per-request cost. Not a dataplane/hot-path change, so no
  loss-cluster iperf gate applies; management-plane behavior only.
- Retiring legs keep draining held connections; slots release on close/drain
  and are never force-freed, preserving drain invariants.
