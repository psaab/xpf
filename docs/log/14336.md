# #14336 — compilePolicies omits zone-quarantine exclusions

## Defect
- `compilePolicies` (`pkg/dataplane/compiler.go`) iterated `cfg.Security.Policies` with no `config.ZoneQuarantineExclusionsForConfig` check, unlike `walkPolicyRuleSlots` (`pkg/dataplane/userspace/policies.go`) which skips quarantined stanzas while advancing `policySetID`.
- A quarantined collision-loser stanza with >256 expanded rules aborted `CompileConfig` in the #4960 pre-pass (`compiler_validate_4960.go` policies phase), so `CompileUserspaceShim` never published — defeating #13168 quarantine tolerance.
- A quarantined stanza sharing the survivor's StableZoneID wrote the same `ZonePairKey` via `SetZonePairPolicy`, clobbering the survivor's policy set, and leaked dead rules into `result.PolicyNames` / `result.PolicyScheduleRuleSlots`.

## Fix
- `pkg/dataplane/compiler.go:compilePolicies`: compute `quarantined := config.ZoneQuarantineExclusionsForConfig(cfg)`, unconditionally delete reserved sentinels (`junos-global`, `any`, `junos-host`) exactly as `walkPolicyRuleSlots` (#14329: dedicated poison paths govern those), then for each stanza: nil slot or quarantined From/To → `policySetID++; continue` before zone resolution, rule expansion, `SetZonePairPolicy`, or any PolicyNames/schedule recording. Skipped stanzas still consume their raw `policySetID` so survivor RuleIDs stay stable.
- Fail-closed preserved: unknown zones and non-quarantined >256 sets still error.

## Tests
- New `pkg/dataplane/compiler_quarantine_14336_test.go`: `TestCompilePolicies_SkipsQuarantinedZoneStanzas` — brute-forced genuine StableZoneID collider (`z-coll-141960` vs `trust`, ID 50675); quarantined stanza with 260 rules after survivor stanza on same pair: compiles, survivor set unclobbered (PolicySetID 0, 1 rule), following stanza keeps PolicySetID 2 / RuleID 512, no dead names/schedule slots, `PolicySets==2`; reserved `any`/`junos-host` policies still compile; unknown zone and non-quarantined 260-rule set still fail closed.
