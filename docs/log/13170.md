## Disposition

`HostInboundStaleReplyGuardRules` used the VRF master from `IngressNetdevs`
as a plain `iifname` predicate. That made a strict zone's stale-reply DROP
apply to sibling slaves in the same VRF. The same master in the uncovered
fallback exclusion exempted every VRF slave, including unzoned members.
The rules now pair VRF master `iifname` with each view's `meta sdifname`
slave set. Fallback rules negate only the set of covered VRF slaves, allowing
stale-reply protection to cover unzoned VRF members without a master-wide
exemption. Direct interfaces and destination-only fence behavior retain their
existing scopes.
