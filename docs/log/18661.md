# Clear session repair overflow after authoritative inventory replay (#18661)

- **Issue**: #18661. `sessionRepairOverflowErr` blocked HA takeover readiness permanently after a bounded worker-repair overflow, even after peer session inventory replay.
- **Change**: Overflow arms a generation-bound peer inventory request.
  `TakeoverReadyForPeer` snapshots the overflow state when firing the request.
  A matching completed replay clears the latch only if no overflow occurred
  during that replay; an overflow during replay leaves it latched and re-arms.
  `SessionSync` captures the requester-local `(helper generation, request
  token)` pair at the next accepted `BulkStart` and carries it through
  reconciliation and completion. The manager keeps that token stable across
  its 5s request retry while the replay is pending/active. Before a matching
  `BulkStart`, the requester resends the same empty-payload `BulkRequest` only
  after a bounded no-start window; this recovers a failed export without a
  reconnect and also covers an aborted receive window. The local receive-window
  serial accompanies start/abort diagnostics, so a delayed abort cannot demote
  a replacement replay. Once the pair is active, retries remain duplicate-free.
  A fresh token is minted only for a new or re-armed replay. Neither local value
  is sent on wire.
  Refusal text distinguishes `not-started`, `request-enqueue-failed`,
  `waiting-for-peer`, `replay-active`, `stale-completion-rejected`, and
  `overflow-rearmed`; rejected stale completions are warned.
