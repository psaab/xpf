# Issue #13131 — harden zone wire-gate evidence and restoration

- **Date**: 2026-10-14
- **Why**: `wire-zone-matrix.sh` only counted probe frames whose payload
  lengths were exactly 64 or 1400 bytes, so a leaked malformed/truncated UDP
  frame could be ignored. Its checksum parser missed tcpdump's `bad ip cksum`
  annotation. Its cleanup flags were armed before corresponding mutations,
  and restoring `reth0.50`/`reth0.80` as bare interface lines discarded
  interface-level host-inbound sub-stanzas. `wire-policy-deny.sh` sent the
  probe burst before its control witness, so a late-starting capture could
  miss a leak and observe only the subsequent control.
- **What**:
  - Count all captured probe frames in deny cells; count non-64/1400 lengths
    as deny leaks, and classify both UDP and IPv4 checksum annotations as
    corruption.
  - Arm route restoration only after the first successful route mutation.
    Arm config restoration immediately before the CLI mutation; cleanup first
    compares current snapshots to the baseline and avoids needless restore,
    then conditionally removes owned state and replays the exact saved
    `reth0.50`/`reth0.80` display-set lines, including nested configuration.
    Route cleanup tolerates a route that was never installed and still checks
    the final snapshot.
  - Interleave the policy-deny control before and after the probe in one
    sender invocation, preserving the 1000-frame probe and 1500-frame
    control floors. Start tcpdump line-buffered and require its explicit
    `listening on` readiness line before sending; otherwise exit VOID, so a
    missing pre-send capture witness can never PASS.
  - Added hermetic tests for nonstandard-length frames and `bad ip cksum`,
    interleaved offered-count aggregation, and capture-readiness gating.
- **RED evidence**: On the pristine `origin/master` expressions with a sample
  capture containing `UDP, length 100` and `bad ip cksum`, the old narrow
  length matcher returned `0` and the old checksum matcher returned `0`.
  The corrected frame matcher and checksum matcher returned `1` each. This
  assertion is now part of `wire-zone-matrix.sh --selftest`.
- **Validation**:
  - `bash test/incus/wire-zone-matrix.sh --selftest`: 24 passed, 0 failed.
  - `bash test/incus/wire-policy-deny.sh --selftest`: 14 passed, 0 failed.
    This includes 1000 probe / 1500 control offered counts and rejection of
    a capture log without tcpdump's ready line.
  - `bash -n test/incus/wire-zone-matrix.sh test/incus/wire-policy-deny.sh`:
    passed.
  - On pristine master the same suites had 23 and 11 passes, respectively,
    both with zero failures; the new assertions were exercised on the fixed
    code after direct RED probes against the old matchers.
- **Risk**: No live cluster run was performed; live config/route restoration
  and packet interleaving still require the scheduled Incus wire gate. Scope
  does not alter production zone or policy enforcement.
