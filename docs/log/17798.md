# #17798 — Filter cursor-sensitive secrets when seeding CLI history

- **Timestamp**: 2026-10-26
  - **Action**: Replayed persisted CLI navigation while filtering history seeds so edit-context credentials are not restored into live readline recall.
  - **Why**: `ReadHistorySeed` used the no-cursor `IsSensitiveHistoryLine` predicate. Legacy `set community <secret>` lines recorded under `edit snmp` therefore passed the seed filter because their flat spelling lacks the `snmp` context, and became recallable again after restart.
  - **What**: `pkg/cliterm/terminal.go` now filters each line with `IsSensitiveHistoryLineAt` at the cursor reconstructed from preceding `configure`, `edit`, `top`/`up`, and `exit`/`quit` commands. Operational-mode replay resolves the first token with the same unambiguous-prefix rule and candidate set as local dispatch, so `conf`/`config` enter config mode while ambiguous `c` does not. Config-mode navigation remains exact-token, matching `dispatchConfig`; since `configure`/`conf`/`config` are not config-mode verbs, replay keeps the cursor when those lines appear in config mode, matching dispatch's rejection. History has no session markers, so replay cannot distinguish rejected in-config configure from a later configure after an unrecorded EOF exit; it therefore fails closed and may over-filter benign lines after EOF+reconfigure, but will not reset to root and leak a context-sensitive secret. An explicit exit/quit path that leaves config mode (for example a root-level exit/quit or `top exit`) makes a following configure a genuine re-entry that resets the cursor. Replay repeatedly uses `SplitPipe` exactly as recursive dispatch does and checks top/up inner navigation against the raw verb, so pipe-decorated edits advance while quoted `top "exit"` preserves config context. Prefixed top/up exit/quit releases config mode at a root target and otherwise restores the original cursor after the target-level pop. Fail-on-revert coverage includes configure abbreviations, ambiguous-prefix, single/chained-pipe, quoted-exit, explicit-exit re-entry with benign GRE key, rejected in-config configure filtering, and up exit/quit controls.

Filtering otherwise uses the existing SSOT predicate, so secret recognition rules are unchanged.
