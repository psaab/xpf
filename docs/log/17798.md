# #17798 — Filter cursor-sensitive secrets when seeding CLI history

- **Timestamp**: 2026-10-26
  - **Action**: Replayed persisted CLI navigation while filtering history seeds so edit-context credentials are not restored into live readline recall.
  - **Why**: `ReadHistorySeed` used the no-cursor `IsSensitiveHistoryLine` predicate. Legacy `set community <secret>` lines recorded under `edit snmp` therefore passed the seed filter because their flat spelling lacks the `snmp` context, and became recallable again after restart.
  - **What**: `pkg/cliterm/terminal.go` now filters each line with `IsSensitiveHistoryLineAt` at the cursor reconstructed from preceding `configure`, `edit`, `top`/`up`, and `exit`/`quit` commands. Operational-mode replay resolves the first token with the same unambiguous-prefix rule and candidate set as local dispatch, so `conf`/`config` enter config mode while ambiguous `c` does not. Config-mode navigation remains exact-token, matching `dispatchConfig`; a new `configure` session resets the cursor to root. Replay repeatedly uses `SplitPipe` exactly as recursive dispatch does and checks top/up inner navigation against the raw verb, so pipe-decorated edits advance while quoted `top "exit"` preserves config context. Prefixed top/up exit/quit releases config mode at a root target and otherwise restores the original cursor after the target-level pop. Fail-on-revert coverage includes both configure abbreviations, ambiguous-prefix, single/chained-pipe, quoted-exit, session-reentry/GRE-key, and up exit/quit controls.
