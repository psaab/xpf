# #17798 — Filter cursor-sensitive secrets when seeding CLI history

- **Timestamp**: 2026-10-26
  - **Action**: Replayed persisted CLI navigation while filtering history seeds so edit-context credentials are not restored into live readline recall.
  - **Why**: `ReadHistorySeed` used the no-cursor `IsSensitiveHistoryLine` predicate. Legacy `set community <secret>` lines recorded under `edit snmp` therefore passed the seed filter because their flat spelling lacks the `snmp` context, and became recallable again after restart.
  - **What**: `ReadHistorySeed` now retains every cursor state compatible with persisted navigation and filters each line with `IsSensitiveHistoryLineAt` under every state. Operational replay keeps the existing unique-prefix behavior (`conf`/`config` enter config mode, ambiguous `c` does not), while config verbs remain exact and match dispatch. Because history has no session markers, a `configure`/`conf`/`config` line seen in config mode may be rejected or may follow unrecorded Ctrl-D/EOF and re-enter at root. Replay tracks both stale-prefix and root hypotheses, advancing their later `edit`, `top`/`up`, and `exit`/`quit` navigation independently; a line is filtered if either cursor interpretation marks it sensitive. Pipe handling and the existing secret-recognition SSOT remain unchanged. Regression coverage includes all six root-cursor credential forms (three re-entry verbs by two credential forms) and benign GRE `set key 4242` controls.
