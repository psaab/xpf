# 10307 — refresh upgrade rollback snapshot at the cut boundary

- **Date**: 2026-09-18
- **Base**: `bd47d09d49d711e2742a6fc6f68379da194796d2`
- **Fix**: `1a0439c27fd508076f5bb5edcf0afbcd93492e7f`
- **Files**: `pkg/upgrade/cutover.go`, `pkg/upgrade/flip.go`, `pkg/upgrade/state.go`, `pkg/upgrade/runner_test.go`, `pkg/upgrade/cut_boundary_snapshot_10307_test.go`

## Defect

The in-place upgrade took its only config-DB snapshot during PREFLIGHT, while COPY and VERIFY left the old daemon live and able to commit. A later START failure therefore rolled the live DB back to the older snapshot, discarding those commits and restoring a `confirm.json` that had already been deleted by confirmation.

## Change

The cut now stops the old daemon first and refreshes the rollback snapshot before journaling `STOPPED`. This is the first point at which the old daemon cannot accept another commit, and it remains before FLIP/START can migrate the DB envelope. If snapshot persistence fails before `STOPPED` is journaled, a daemon stopped by this run is restarted; caller-owned `UnitAlreadyStopped` state is left alone. Journal and rollback comments now describe the cut-boundary snapshot rather than a PREFLIGHT-only snapshot.
