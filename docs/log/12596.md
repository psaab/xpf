# #12596 — retain interface sampling in compact spellings

- **Timestamp**: 2026-10-13
- **Base**: `master` `c49e22437`
- **Action**: Normalize brace-elided and packed interface sampling heads and leaves before strict compilation.

## Red before

`CompileConfig` and `configstore.CheckText` accepted the braced control with `SamplingInput=true` and `SamplingOutput=true`, but silently compiled the issue spellings with their elided or packed flags false: `family inet sampling { input; }`, `family inet { sampling input; }`, and `family inet { sampling { input; } sampling output; }`. In the mixed form, in either sibling order, only the braced `sampling { input; }` compiled; the packed `sampling output;` was dropped. Inet6 had the same elided-head and packed-leaf losses. No strict error or diagnostic disclosed the missing configuration.

The AST showed the forms that the compiler reader could not see: the parser stores `family inet sampling` on the family node's own `Keys`, stores packed `sampling input`/`output` on the sampling node's `Keys`, and leaves a packed sampling sibling as a distinct family child. The compiler's `FindChildren("sampling")` loop only read braced sampling siblings. Strict CheckText and direct CompileConfig share `normalizeCompactStanzas` before compilation.

## Change

- Admit only the interface-family pairs `inet sampling`/`inet6 sampling` and sampling-direction pairs `sampling input`/`sampling output` in the existing schema-guided compact normalizer. This converts elided container/leaf keys into the child nodes the existing compiler union reader consumes; forwarding-options sampling is not in these interface-specific pairs.
- Add config-compiler and strict `CheckText` regressions for braced control, elided family, packed input/output, both mixed sibling orders, both address families, and unit-plus-family elision.
- Remove the four completed sampling rows from both the divergence inventory and the permanent-exclusion register. Update the family-only and packed-opt-in measurements plus the multisite/blind-pair ratchets for the newly admitted schema pairs.

## Risk

Persisted hierarchical text configurations using these spellings now set the sampling flags they already declared, rather than silently disabling them. An HA pair in a rolling upgrade compiles these spellings differently on its two nodes until both run this build. The compiler and schema are unchanged; normalization remains limited to these specific family and sampling pairs. No live dataplane traffic validation was performed.

Folding the packed tail also hands it to strict validation, which changes three kinds of strict-commit (`CheckText`, `commit check`) outcome. Measured on this branch and with master's `compact_normalize_scope.go` overlaid:

- **Newly rejected**: a fused direction run, `sampling input output;` or `sampling output input;`, packed (`family inet { sampling input output; }`) or family-elided (`family inet sampling input output;`), for inet and inet6. Master committed these with both flags off and no diagnostic. Strict commit now fails them on the #8437 fused-statement gate (the token `output` follows `input` but names a sibling statement), so persisted text with this spelling fails its first commit after upgrade until the missing `;` is added. Boot still succeeds: `Store.Load` logs the #1319 typed-leaf warning from its tolerant compile, which HA `SyncApply` shares, and enables only the first direction (`input` for `input output`, `output` for `output input`), as the lenient compile does.
- **Newly accepted**: family-elided packed runs that carry a filter binding: `family inet sampling input filter input f1;`, `family inet sampling input filter output f2;`, `family inet6 sampling output filter input f6;`, and `family inet6 sampling input filter output f6;`. Master rejected these with a false #12090 error that `filter input` (or `filter output`) is not supported. Strict commit now binds both the filter and the sampling direction, as the braced spelling does.
- **Newly correct**: `family inet sampling input address 10.0.0.1/24;`, `family inet sampling input mtu 1400;`, and `family inet sampling input dhcp;`. Master committed these and silently dropped the address, the MTU, or the DHCP client along with the sampling flag. They now compile completely.

Sampling now inherits the repeated-`family inet` editor gap that #12661 tracks for `filter`. The #12508 all-siblings `delete` and `deactivate` in `pkg/config/ast_edit.go` work inside the one `family inet` block the path walk descends into, so with two `family inet` blocks in one unit the operation reports success and the other block keeps sampling on:

- `family inet { sampling { input; } } family inet sampling input;`, and the same two blocks in reverse order: `deactivate … family inet sampling` and `deactivate … family inet sampling input`; for the braced-first order, `delete … family inet` as well.
- `family inet { address 10.0.0.1/24; } family inet sampling { input; }`, and the variant ending `family inet sampling input;`: `delete … family inet` and `deactivate … family inet`.

On master these cells ended with sampling off only because the elided block's sampling never compiled. Master already keeps `filter`, `address`, and `dhcp` bound in the same shapes; for example, `deactivate … family inet filter` over `family inet { filter { input f1; } } family inet filter input f2;` leaves `f2` bound. Across the review's 85-cell delete/deactivate matrix, operations that succeed while sampling stays on went from 5 with master's normalizer to 12 on this branch.

On the issue's own spelling, `family inet sampling { input; }`, `delete … family inet sampling input` fails with `path not found: container "family inet" does not exist`, and `deactivate … family inet sampling` fails with the same text, while `show | display set` prints `set … family inet sampling input` and sampling stays on. The delete error wraps `config.ErrPathNotFound`, which event-options deletes skip (`pkg/eventengine/engine.go`), so an automated delete of that leaf path silently does nothing. Master has the same gap for `family inet filter { input f1; }`. `delete … family inet sampling`, `delete` or `deactivate` of a packed `sampling input;` leaf, and `inactive:` on the elided spellings still turn sampling off.
