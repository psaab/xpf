# Issue #13183 — exclude skipped zones from counter slots

- **Finding:** Deep-review D6-09 found that zone population skips empty names and reserved IDs (`>= 65534`), while counter-slot attachment and committed pruning consumed raw snapshot IDs. A skipped row could take a slot, overflow valid configured zones, and keep invalid counter blocks alive.
- **Fix:** `attach_zone_counters` and `commit_zone_counter_prune` now derive their active/configured IDs from `ForwardingState.zone_id_to_name`, the admission result of `populate_zones`. Traffic and flood maps and stores therefore use the same admitted set.
- **Regression:** `attach_zone_counters_ignores_skipped_zone_rows_13183` includes 63 valid zones plus an empty-name ID and reserved ID. It failed before the fix because overflow became active, and passes after the fix; it also checks the last configured zone retains slots in both maps and skipped IDs remain unassigned.
