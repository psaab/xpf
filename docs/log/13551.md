# Issue #13551: CLI dispatch parity

## Why

The remote `cmd/cli` dispatchers accept less than the in-process CLI for
rescue configuration, process summaries, and static NAT rule detail. Operators
using the remote binary therefore cannot execute those advertised requests.

## What

Route `show system configuration rescue` to a redacted system-info response,
preserve the `summary` token and share its formatter across the embedded and
remote CLIs, and add static NAT rule/detail ShowText topics backed by the
shared `natshow` renderer. Map GetSystemInfo request types to their canonical
commands so `deny-commands` applies to the actual view (especially rescue).
Regressions cover dispatch, request-specific authorization, and output shape.

## Validation

`go test ./cmd/cli -run '^TestDispatchParity13551_' -count=1`,
`go test ./pkg/sysinfo`, `go test ./pkg/cli/...`, and focused gRPC
command/permission/audit and process-summary limiter tests passed.
`TestGetSystemInfoDenyCommandsUsesRequestedView13551`,
`TestGetSystemInfoRescueConfigurationRedactsAndFailsClosed13551`, and
`TestShowTextStaticNATRuleTopicsRenderRequestedDetail13551` passed.
`TestEveryPricedMethodIsMappedOrNamedAbsent7172` confirms dynamic command
attribution is documented outside the static method-command table.
`go build ./cmd/cli/... ./pkg/cli/... ./pkg/grpcapi/... ./pkg/cmdtree/...
./pkg/sysinfo/...`, `go vet` over those packages, and `git diff --check`
passed.

Full package runs were not clean: `cmd/cli` fails `TestTreeIsGofmtClean`
because 15 unrelated files are unformatted. Full `pkg/grpcapi` reports
`TestGetGlobalStatsScreenDropDetailKeysAreCanonical` expecting 15 entries
but finding 19. On pristine master, the three CLI regressions failed on
their reported missing dispatches.

## Risk

Remote process summary and the embedded CLI use one shared formatter with
caller-bounded `ps` execution. Rescue output remains redacted on the remote
RPC path; static rule topics use the shared renderer.
