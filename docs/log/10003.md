# 10003 — system host-name admission validator

## Summary

`system host-name` was a scalar leaf with no `valueType` or validator. The
nested/set spelling reached the compiler and the compact hierarchical spelling
was read directly from the `system` node's packed `Keys`, so neither spelling
had a syntax or length gate before the value reached `sethostname(2)` and
`/etc/hostname`.

The issue body and all comments were read before implementation. There were
no comments withdrawing, narrowing, contradicting, or marking the issue
shipped.

## Evidence and precedent

- `pkg/config/schema_system.go` had an untyped `host-name` beside typed
  `domain-name` and `time-zone` leaves.
- `pkg/config/compiler_system.go` reads the compact form from
  `Keys=["system", "host-name", value]` before walking children.
- `pkg/config/schema_validators_system.go` already has the shared
  `validateDNSNameShape` used by the DNS/domain, NTP, and syslog admission
  paths. DDNS has its own publish-specific `ValidateDDNSHostname`, but the
  package shares the established 63-octet label / 253-octet DNS constants and
  semantics. The system wrapper reuses the shared LDH shape and adds Linux's
  64-byte `HOST_NAME_MAX` cap because the kernel apply syscall is stricter.

## Change

- `system host-name` is now `ValueHostname` with `ValidateSystemHostname`.
  Empty is accepted as the unset form so the existing apply no-op remains
  valid. Non-empty values use the shared LDH/63-octet DNS shape, a 64-byte
  Linux kernel cap, and diagnostics naming `system host-name`.
- The compact `system host-name value;` compiler read applies the same check:
  strict compile rejects, while `CompileConfigLenient` records a warning and
  retains the value for tolerant Load/SyncApply no-brick behavior.
- `applyHostname` retains its empty and unchanged early returns, then adds a
  final tolerant-path belt: malformed retained values are warned and refused
  before `sethostname(2)` or `/etc/hostname`. Regression cells prove a valid
  FQDN reaches both kernel and durable-file seams, while empty, unchanged,
  malformed, and Linux-overlong values do not.
- The existing #8597 valueless census retains its host-name row, but expects
  the typed leaf's `missing value` diagnostic; generic untyped rows retain
  their legacy diagnostic. No generic schema walker change was made.

structured log warning without mutating the published config. Strict Store
CommitCheck/Commit covers the invalid classes and checks the naming
diagnostic; valid FQDN and empty/unchanged apply controls remain green.

## Controlled revert proofs

The package-wide pre-implementation build RED above proves the symbol was
missing. To prove that each behavioral cell fails when its admission control
is removed, the committed code was temporarily mutated, the relevant tests
were run, and the exact production code was restored before the final GREEN
run:

- Neutering `ValidateSystemHostname` to `return nil` made the config
  malformed-value matrix fail with `expected an error, got nil`, made strict
  schema/compact cases accept invalid values, and made
  `TestCommitCheckRejectsSystemHostname10003` accept malformed set values.
- Removing the compact compiler gate made
  `TestCompileConfig_SystemHostnameElided_10003` accept invalid compact values,
  made `TestCompileConfigLenient_SystemHostname_10003` report `warnings=[]`,
  and made all five configstore tolerant cases report `warnings=[]`.
- Disabling the Linux 64-byte cap made the direct validator and schema tests
  accept the 65-byte DNS-valid name, proving the syscall-specific boundary is
  covered rather than implied by the 63-byte label rule.
- Disabling the two existing `applyHostname` early returns made
  `TestApplyHostnameAdmissionControls10003` fail both the empty and unchanged
  subtests: each attempted `sethostname` instead of remaining a no-op.
- Disabling the new tolerant apply belt made the invalid-value subtest call
  `sethostname` (and would permit the durable write), proving the final
  boundary is load-bearing for retained bad names.

After restoring all mutations, the targeted config, configstore, and daemon
commands above passed again. No mutation was committed.
