  - **What**: Candidate 1 from the issue. `nextTableDynamicCarveoutRules` mints the same iif-scoped slot-0 main lookups (same priority slot, `suppress_prefixlen = prefixLen-1`) for live main rows from `ImportLearnedRoutes([]int{mainTableID})` — the same classifier the helper FIB import uses — strictly more specific than an admitted leak prefix, deduplicated against the static set. `reconcileMainCarveouts` is the single install path for Apply (commit) and `RefreshCarveouts` (churn): it recomputes the desired band, deletes carve-out-shaped rules, re-adds, and rolls back its own adds on error. A failed live dump aborts before any kernel mutation and surfaces an error instead of installing a statics-only subset. The daemon route listener calls `refreshNextTableCarveouts` (via the shared `nextTableApplyInputs` derivation) on its coalesced actuation before republishing, keeping the coalescer dirty on failure. `DesiredPolicyRulePriorityCounts` intentionally stays config-only: dynamic exceptions are runtime state, and the #18005 flush probe is a config-derived desired set (a false flush verdict there self-heals through the route listener and the next Apply). Connected (gateway-less) main routes remain excluded — the importer rejects them and their parity needs the RG-ownership-aware connected set (#15742).
