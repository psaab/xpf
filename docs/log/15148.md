# #15148 (B05-01): configured RETH link-local stripped on every apply

## Defect

`finishRethMemberLinkTail` ran on every apply for every RETH member and
called `removeAutoLinkLocal`, which deleted every link-local except the
auto stable pattern (`cluster.IsStableRethLinkLocal`). A configured
`fe80::1/64` router link-local — installed as an RG VIP on the primary —
was therefore deleted on every commit and only re-added by the 2s
direct-mode VIP reconcile, while `ensureRethLinkLocal` then added a
per-node EUI-64 that stayed on the owner. VLAN children got the same
strip via `rethSubIfaceLinkLocalRepair`.

## Fix

- `configuredRethLinkLocalIPs` collects a unit's configured IPv6
  link-local unicast addresses (config order, de-duplicated), reusing the
  same parse as `rethUnitHasConfiguredLinkLocal`.
- `removeAutoLinkLocalExcluding` preserves any live link-local that is
  either the stable pattern or one of the unit's configured addresses;
  `ensureRethLinkLocalExcluding` adds no EUI-64 when a configured
  link-local exists. Both delegate to the new `rethLinkAddrsFn` /
  `rethLinkAddrDelFn` / `rethLinkAddrAddFn` netlink seams so the decision
  is testable without a privileged netdev. The old
  `removeAutoLinkLocal` / `ensureRethLinkLocal` remain as nil-configured
  wrappers.
- `rethParentLinkLocalRepair` (new) wires unit 0 into the parent tail in
  `finishRethMemberLinkTail`, replacing the unconditional
  strip-then-ensure pair.
- `rethSubIfaceLinkLocalRepair` resolves the VLAN child's configured
  link-locals via `configuredRethLinkLocalIPsForVlan` (vlan-id -> all
  mapped units, mirroring `rethSubIfaceNeedsLinkLocal`) and passes them
  to both seam functions. The `removeAutoLinkLocalFn` /
  `ensureRethLinkLocalFn` spy seams now take the configured list.

NOT changed: the stable-pattern exemption, the #5107 vlan-id resolution,
DAD repair, RX-offload handling, and the VIP/stable-LL reconcile paths.
