# #16756 — config-stale gate: peer-capability fallback for pre-ACK peers

- **Timestamp**: 2026-10-25
  - **Action**: The #9569 gate (`SessionSync.PeerConfigStale`) required a
    type-40 config-apply ACK from every peer. A peer predating the ACK
    (28556c2b19) can never send one, so against a connected legacy peer
    the bare ISSU verb and untargeted/batch failover refused forever,
    blaming a config-apply failure that never happened. The peer now
    advertises ACK support as `capFlag2ConfigApplyAck` in a second
    capability byte appended after the identity tail of
    `syncMsgPeerCapabilities` (the first flags byte is full, bits 0..7;
    the byte cannot sit at a fixed offset because a #9818 peer's [5:21]
    is its boot id, so the receiver reads it at `len-1` only when the
    frame is longer than every pre-#16756 layout). `recordLastSentConfigGen`
    records the receiving incarnation's capability alongside the sent
    generation; `PeerConfigStale` judges a legacy send by pre-ACK
    semantics (stale iff the newest sent generation was NACKed, tracked
    in `peerConfigNackedGen16756`) and keeps the strict ACK gate for a
    peer that promised one — including re-judging under a downgraded
    current incarnation whose promised ACK can never arrive. The legacy
    refusal names the real cause ("peer predates config-apply ACK").
    The bit is incarnation-scoped exactly like the first byte: stored
    per-connection, restored on the boot-ID switch only from the priming
    connection, cleared on incarnation advance and full disconnect.
    Tests: `pkg/cluster/peer_config_stale_capability_16756_test.go` —
    legacy peer without NACK passes `PeerConfigStale` and the
    `ManualFailover`/`ForceSecondary` verbs, legacy peer with a newest-send
    NACK is refused (batch form) with the pre-ACK reason, straggler NACK
    ignored, ACK-capable peer silent or NACKing still refused until the
    matching ACK, downgrade-on-reconnect unblocks, local advertisement
    bit set, and the wire round-trip (pre-#16756 frame with a nonzero
    last identity byte does not read as capable). The #11070 fixture now
    models an ACK-capable incarnation, since its premise (silence is
    stale) only holds for one.
