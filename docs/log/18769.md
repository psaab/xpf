# #18769: sendVRRPModeNonVIPAnnounce dereferences a nil store

- **Timestamp**: 2026-11-01
- **Action**: `make test-go` triage. `TestReconcileDiscoversVRRPInstances` panics in `reconcileRGState -> convergeLegacyNonVIPAnnounce -> sendVRRPModeNonVIPAnnounce -> d.store.ActiveConfig()`. That aborts the pkg/daemon binary and hides 22 daemon failures in later files. First-bad `6523b79d46` (#17052): fails at it, passes at its parent `62a4b44a8f`.
- **Action**: guarded `d.store == nil` in `convergeLegacyNonVIPAnnounce`, before the activation claim so a later pass with a store still owns the announce, and in `sendVRRPModeNonVIPAnnounce` as defence. This matches the HA package's other nil-store guards. Added `pkg/daemon/vrrp_nonvip_announce_nil_store_18769_test.go`.
- **Mutants**: both KILLED.
  - Removing only the converge guard means the claim is taken, which the new cell catches.
  - Removing both (the master state) panics, which `TestReconcileDiscoversVRRPInstances` catches.
- **Docs**: none needed. Production always constructs a store, so runtime behaviour is unchanged; the guard only restores the package convention for store-less fixtures.
- **File(s)**: `pkg/daemon/daemon_ha_vip.go`, `pkg/daemon/vrrp_nonvip_announce_nil_store_18769_test.go`
