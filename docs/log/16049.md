# #16049 — NAT64 `from routing-instance [a b]` last-wins, dropped member invisible to strict

Split from #15985 (RN-03). Base re-verified at `c1b86e871b`;
implemented on current master, where #15678/#15932 have since landed.

## Mechanism

`compileNAT64` (pkg/config/compiler_nat_source.go) read every
`from routing-instance` value via `collectNATScopes` but stamped them
onto the single typed rule-set with `rs.FromRoutingInstance = s.value`,
so `from routing-instance [ blue red ]` silently became red-only
(last-wins — the exact defect #15932 fixed for `from zone`). The
strict gate `validateNAT64ScopeStrict` then checked only that
surviving singular, so a nonexistent FIRST member
(`[ nosuchri red ]`) committed clean: invisible to strict. The
snapshot carried only the singular, and Rust `prefix_scope_matches`
matched only it, so traffic from the dropped RI was never translated
(silent scope narrowing, not a policy bypass — zone-pair policy still
judged the traffic).

## Fix (union, mirroring #15932's zone fix)

Rejecting plural was rejected as the fix: Junos same-kind lists are a
legitimate union (as zones already are), and unioning preserves the
authored admission set instead of breaking working configs.

- Go config: `NAT64RuleSet` gains `FromRoutingInstances` (first RI also
  in singular `FromRoutingInstance`); `compileNAT64` unions/dedupes the
  RI list on the ONE authored rule-set — never Cartesian-expanded,
  because the dataplane owns one PortAllocator per (prefix, pool)
  snapshot and expansion would double-mint the shared pool.
  `validateNAT64ScopeStrict` checks EVERY member (mixed zone+RI still
  rejects; lenient warns per defect). `nat64EffectiveRoutingInstances`
  feeds the scope-aware owner/shadow keys (sorted RI set), so two
  rule-sets with different RI sets are distinct owners.
- Go snapshot: `NAT64RuleSnapshot` emits ONE snapshot per authored
  rule-set carrying `from_routing_instances` (singular folded in,
  deduped). Protocol 63→64 (Go + Rust lockstep, shape golden updated):
  a v63 helper ignores the plural and scopes to the singular only —
  the truncation — so exact-equality versioning fences it.
- Rust: `Nat64Prefix.from_routing_instances` unions in
  `prefix_scope_matches` (singular fallback for old snapshots).
- CLI: `show security nat nat64` renders the RI union.

Perf impact: none on the hot path — `prefix_scope_matches` iterates a
small authored list only when non-empty (config-sized, typically 1–2);
no allocation added per packet.
