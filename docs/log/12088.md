# Issue #12088 — reconcile RPM probe pins after kernel cleanup

## Why

Linux can remove the per-test route from table 7000 when the pinned egress link is bounced or its last address is removed, while leaving the fwmark rule in place. An unchanged RPM config hash therefore skipped re-installation and could leave `SO_MARK` probes without their pinned path.

## What

`Manager.VerifyProbePins` reads back each configured fwmark rule and exact host-route shape without mutating kernel state. Route verification uses the family default metric (IPv4 0, IPv6 1024); `DEAD|LINKDOWN` is a valid carrier-loss pin shape when `ignore_routes_with_linkdown=1`, although the kernel may skip that route for lookup. `SO_BINDTODEVICE` confines carrier-loss probes to the configured egress, so loss reaches RPM rather than an `ErrProbeSetup` hold. Pure DEAD and unresolved nexthops still fail. The daemon reads pins on unchanged-hash reconciles, relevant link/address notifications, and a 30-second fallback tick. With a routing manager, a missing pin is held only while the egress is administratively up; an admin-down egress remains probeable so `ENETUNREACH` advances RPM's loss threshold. With no installer, all pins stay held regardless of egress state, preventing an unbacked mark from false-passing after a later link-up. Closed subscriptions are resubscribed after backoff, then all pins are verified to resync the gap. Readback-only drift waits for the retry tick; still-failing installer errors retain immediate hash-gated retries.

## Risk / residual

The pin loop treats closed link/address subscriptions (including receive gaps such as ENOBUFS) as recoverable: it backs off, resubscribes, and verifies pins after the new subscription is active; the 30-second readback remains the fallback while a subscription is unavailable. For an installer-backed pin, there is still a narrow admin-up/event-to-hold race: a probe could send before link notification readback publishes drift, and a repair waits for the next retry tick. Without an installer, pins remain held even while the egress is down, so they cannot false-pass after a later link-up. Kernel cleanup and repair were exercised only inside private network namespaces; no live cluster was mutated.
