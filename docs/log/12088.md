# Issue #12088 — reconcile RPM probe pins after kernel cleanup

## Why

Linux can remove the per-test route from table 7000 when the pinned egress link is bounced or its last address is removed, while leaving the fwmark rule in place. An unchanged RPM config hash therefore skipped re-installation and could leave `SO_MARK` probes without their pinned path.

## What

`Manager.VerifyProbePins` reads back each configured fwmark rule and exact
host-route shape without mutating kernel state. It accepts the family default
route metric (IPv4 0, IPv6 1024) and valid `RTNH_F_LINKDOWN` carrier-loss
shapes; `SO_BINDTODEVICE` keeps carrier loss on the configured egress so RPM
can count it instead of holding state. The daemon verifies pins on unchanged-
hash reconciles, relevant link/address notifications, and a 30-second fallback
tick. A failed pin is held unless an installer-backed `LinkByName` succeeds
and confirms `IFF_UP` is clear; admin-down probes report `ENETUNREACH`, which
advances RPM's loss threshold. Missing or unreadable egress state remains
unknown and held; RPM returns `ErrProbeSetup` before opening a socket. If socket
setup is reached, `SO_BINDTODEVICE` fails with `ENODEV`.
The pin-failure gauge counts install/readback, missing-egress, no-installer,
and temporary pin-band reprogram holds. Without an installer, every pin stays
held regardless of egress state.
Event-detected readback drift is repaired on
the next retry tick, so link-recovery failback may be delayed by up to 30
seconds plus the normal probe cycle; installer errors may also retry on a
hash-gated reconcile. Closed subscriptions are resubscribed after backoff,
then all pins are verified to resync the gap.

## Risk / residual

The pin loop treats closed link/address subscriptions (including receive gaps such as ENOBUFS) as recoverable: it backs off, resubscribes, and verifies pins after the new subscription is active; the 30-second readback remains the fallback while a subscription is unavailable. For an installer-backed pin, there is still a narrow admin-up/event-to-hold race: a probe could send before link notification readback publishes drift, and a repair waits for the next retry tick. Without an installer, pins remain held even while the egress is down, so they cannot false-pass after a later link-up. Kernel cleanup and repair were exercised only inside private network namespaces; no live cluster was mutated.
