# Issue #14317 — post-#14120 input-filter policer bypass on non-cached / flowless LocalDelivery, NoLocalEntry, and Stale hits

- **Issue:** #14120 deferred input-filter policing (`DeferToTxSelection`) at the
  session-miss precheck, the flowless arms, and the fragment-association hit,
  but only metered LocalDelivery inside the
  `should_cache_local_delivery_session_on_miss && !is_wg_listener_tuple`
  install block. Host-bound traffic that declines to cache (non-SYN TCP
  ACK/RST/data-first, WireGuard listener tuples), flowless/fragment
  LocalDelivery, fragment-association LocalDelivery hits, and `NoLocalEntry`
  session hits were therefore delivered to the kernel unmetered on every
  packet. Separately, the `Stale` revalidation capture passed
  `TermMatchExtra::default()` instead of the packet's frame-derived extra, so
  tcp-flags/icmp-type/flex-scoped policer terms never matched after a config
  generation bump. (NoRoute/MissingNeighbor arms are moot — those packets
  drop anyway — and are excluded, per the research lanes.)
- **Context read:** Issue body + both blinded research lanes (Opus SMR +
  Muse-Spark, MATERIAL narrowed) at origin/master `5b122dda5`. Cited paths
  re-verified at that SHA: `poll_descriptor/mod.rs:3760,4636-4794,6805,7057`,
  `filter.rs:1482-1591`, `forwarding/local_delivery.rs:20-54`,
  `session/mod.rs:2282-2293`. Note (correcting the lanes): port matching reads
  ports from the flow, not `extra`, so port-scoped policer terms were never
  the Stale gap — the gap is the per-packet constraints (`tcp_flags`,
  `icmp_type/code`, flex, `is_fragment` gating) that `default()` fails closed.
- **What:**
  - `filter.rs` (`evaluate_input_filter_on_session_hit`): Stale capture now
    passes `term_match_extra_from_frame(frame, meta)`; the static *verdict*
    walk (`static_input_filter_deny_eval`) keeps `default()` deliberately —
    a port-gated term must not deny a flow on a fragment's absent L4.
    `NoLocalEntry` now meters inline when the disposition is LocalDelivery
    (no entry exists to store handles on): capture + `apply_cached_three_color_policers`,
    red folds to a silent `Discard` with `policer_drop: true`.
  - `mod.rs` LocalDelivery miss: hoisted the cache predicate into
    `cache_local_delivery`; every LocalDelivery miss that declines to cache
    meters inline (same capture + apply, red drops before reinjection). The
    cacheable arm is unchanged and never double-charges (disjoint gates).
  - `mod.rs` fragment-association hit: meter is `Inline` iff the stored
    decision is LocalDelivery, else `DeferToTxSelection`; `policer_drop`
    folds into the existing silent-drop check.
  - `mod.rs` flowless miss: `policer_drop` folds into the existing silent-drop
    check (inert today — the precheck still defers — kept as the chokepoint
    if the meter ever becomes inline there).
  - `flowless_verdict.rs` (`flowless_local_delivery_verdict`): after the
    host-inbound/lo0/junos-host gates, capture + meter the input policer
    (`ports_unknown = true`, mirroring the early walk); red returns
    `Filtered`. This is the flowless LocalDelivery meter — the early walk
    cannot meter because the disposition is not yet known there.
  - NOT changed: `evaluate_non_pbr_input_filter`'s meter contract, the
    cacheable install arm, transit deferral (charged exactly once in
    TX-selection), verdict semantics (Discard/Reject terms already applied
    on every arm; this closes only the metering evasion).
- **Layer choice:** Meter ownership follows whether a TX-selection leg will
  run — decided at each poll-descriptor site from the resolved disposition,
  not inside the filter walk, so transit cannot double-charge and captures
  stay side-effect-free. Sessionless arms meter inline because there is no
  entry to replay from.

## Notes

- Fail-on-revert: reverting the NoLocalEntry meter, the non-cached miss
  meter, or the flowless meter reddens its `_14317` cell on the policer
  status counter; reverting the frag-hit `policer_drop` fold leaves
  `input_eval.policer_drop` unconsumed (red packet forwarded).
- DSCP/color remarking on delivered host-bound frames remains unapplied
  (no frame-rewrite mechanism on local delivery), same posture as #5857 /
  #14120; only the drop + charge are enforced.
- WireGuard listener tuples are covered by the same `!cache_local_delivery`
  gate (it reuses `is_wg_listener_tuple`, the exact predicate that declines
  caching); no WG-specific harness exists for the poll loop, so that arm is
  pinned by construction + the protocol-scoped flowless/non-SYN cells rather
  than a dedicated WG frame test.
