# 10666 — Admit valid NAT PMTUD errors as RELATED

## Contract

A Fragmentation-Needed (ICMPv4 type 3/code 4) or Packet-Too-Big (ICMPv6 type 2/code 0) error quoting a live NAT, SNAT, or NAT64 session is RELATED only when its actual ingress zone matches the appropriate side of the quoted forward flow. Valid PMTUD may bypass reverse-zone policy for a locally forwardable `ForwardCandidate`. Wrong-zone errors, non-PMTUD NAT'd errors, and terminal route/HA dispositions retain their existing fail-closed or zone-policy behavior. The untranslated #10286 path is unchanged.

## Implementation

`EmbeddedIcmpReversal::Queued` carries `related_admit`. Same-family matching normalizes the session's `is_reverse` metadata and checks forward egress for inbound errors or forward ingress for outbound SNAT re-NAT. NAT64 v4-to-v6 checks forward egress; v6-to-v4 checks forward ingress. Only the two PMTUD type/code pairs qualify. The queued policy gate skips zone policy only for a validated RELATED `ForwardCandidate`; other dispositions remain authoritative.

## Coverage

- Same-family SNAT Frag-Needed passes under default deny from the matching zone; an otherwise matching error from an untrusted zone is denied.
- NAT64 v4-to-v6 and v6-to-v4 Packet-Too-Big pass under default deny from the matching session side; wrong-zone controls are denied in both directions.
- Existing Time-Exceeded / non-PMTUD policy-gate coverage and untranslated #10286 behavior remain covered by the embedded ICMP module.
