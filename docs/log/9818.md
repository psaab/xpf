# #9818 — retain replacement peer connections before retirement evidence

## 2026-09-17 — Implementation

- Added per-connection peer process identity attribution to session-sync capabilities:
  boot id, ordered daemon epoch, and Manager-scoped random process token.
- Stale-incarnation retirement now preserves connections that prove they belong to
  the replacement process, while unattributed and matching-identity connections
  remain genuine corpses and are evicted.
- Added bounded grace for a capability frame still in flight on another fabric;
  late replacement identity preserves/re-stamps the slot, while short/legacy
  frames and silent expiry resolve as corpses.
- Kept the process identity stable across heartbeat refinement and SessionSync
  recreation; local epoch sampling does not start heartbeat persistence; daemon
  wiring supplies epoch/token callbacks.
- Added RED-then-GREEN regression cells for full-disconnect, supersession,
  delayed capabilities, epoch-retirement, daemon-restart, same-boot/same-epoch
  token collision, same-process identity retention, corpse eviction,
  legacy/partial tails, wire fields, and comms recreation. Legacy classifier
  fixtures now deliver a real short capability frame; only the delayed-frame
  case intentionally leaves one in flight.
