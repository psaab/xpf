# Issue #15707 — `system internet-options no-ipv6-reject-zero-hop-limit` ignored by the userspace dataplane, inverted kernel sysctl, compact spelling dropped, show divergence

## Defect

Four coupled failures for one knob
(`system { internet-options { no-ipv6-reject-zero-hop-limit; } }`,
`InternetOptionsConfig.NoIPv6RejectZeroHopLimit`):

1. **Userspace dataplane ignored it.** No snapshot field carried the flag
   and `userspace-dp/src/afxdp/icmp.rs` generated ICMPv6 Time Exceeded
   unconditionally, so a hop-limit=0 packet still drew the rejection the
   operator configured off.
2. **Kernel handling was inverted and never rolled back.**
   `applyKernelTuning` (`pkg/daemon/daemon_system.go`) wrote `"0"` to
   `/proc/sys/net/ipv6/icmp/ratelimit` when the knob was set. In
   `icmpv6_xrlim_allow`, 0 means *unlimited* — that disables ICMPv6
   error rate-limiting entirely instead of suppressing one error class —
   and there was no else-branch, so deleting the stanza left the knob at
   0 for the daemon's lifetime.
3. **Compact spelling dropped.** `system internet-options
   no-ipv6-reject-zero-hop-limit;` packs the leaf onto the
   `internet-options` node's `Keys[1:]`; `compileSystem` only ran
   `FindChild`, so the flag compiled to false. The flat-set chain's
   packed tail (`... no-ipv6-reject-zero-hop-limit tcp-mss 1400`) was
   also invisible to `collectInternetOptionsExtras13089`, which never
   scanned `Keys[1:]`.
4. **Show divergence.** Local CLI `show system internet-options` printed
   the raw config text (`showActiveConfigPath`) while gRPC rendered the
   typed field (`showInternetOptions`), so the two surfaces disagreed.

## Fix

- **Wire (v60 → v61):** `ConfigSnapshot.no_ipv6_reject_zero_hop_limit`
  (Go `NoIPv6RejectZeroHopLimit`, `omitempty`; Rust `#[serde(default)]`),
  populated in `buildSnapshot` from the compiled config. Protocol
  version bumped on both sides with the exact-equality fence, since a
  v60 helper would silently ignore the field and keep rejecting.
- **Dataplane:** `ForwardingState.no_ipv6_reject_zero_hop_limit` is set
  from the snapshot in `forwarding_build`. `build_local_time_exceeded_v6`
  (and the `build_local_time_exceeded_request` fast path) return `None`
  when the flag is set and the packet arrived with hop limit **0**
  (new `packet_hop_limit_v6` helper). Hop-limit=1 packets still expire
  normally; IPv4 untouched; the trigger packet is dropped either way —
  only the generated error is suppressed.
- **Daemon:** the bogus `ratelimit=0` write is removed.
  `reconcileICMPv6Ratelimit` runs on every `applyKernelTuning`: if the
  knob is still at 0 (the state the old binary left), it restores the
  kernel default 1000 ms; any other value is left alone.
- **Compiler:** the `internet-options` arm now also scans `child.Keys[1:]`
  and `packedBodyChildren`, and `("internet-options",
  "no-ipv6-reject-zero-hop-limit")` is admitted to
  `compactNormalizeInScope`. `collectInternetOptionsExtras13089` scans
  the modelled leaf's `Keys[1:]` so a packed extra (`tcp-mss`) still
  earns the not-implemented advisory.
- **Show:** local CLI renders the same typed view as gRPC
  (`Internet options:\n  no-ipv6-reject-zero-hop-limit: enabled|disabled`,
  or `No internet-options configured`).
