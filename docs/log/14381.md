# #14381 — Family-less IPv4 BGP neighbor with only `default-originate` lands in no address-family set

## Mechanism

`pkg/frr/protocols_render.go` classifies each valid BGP neighbor into
`inet4Neighbors`, `inet4DisabledNeighbors`, and `inet6Neighbors`. A
family-less neighbor (`FamilyInet` and `FamilyInet6` both false) joins
the IPv4 set only when `policyDefault || hasAFNeighborAttributes`, where
`hasAFNeighborAttributes` covered `RouteReflectorClient`, `AllowASIn`,
and `RemovePrivateAS` — the per-neighbor attributes rendered inside the
address-family blocks. It omitted `DefaultOriginate`, even though
`default-originate` is rendered per-neighbor inside both AF blocks
(`neighbor <addr> default-originate`).

So `BGPNeighbor{Address: "192.0.2.1", PeerAS: 65002, DefaultOriginate: true}`
with no family flags and no policy landed in no set: no
`address-family ipv4 unicast` block was opened, and neither
`neighbor 192.0.2.1 activate` nor `neighbor 192.0.2.1 default-originate`
was rendered. The configured default route was silently never
advertised.

Scope guard: `PrefixLimitInet`/`PrefixLimitInet6` are deliberately not
independent activation triggers. The compiler only sets them together
with an explicit `family inet`/`inet6` declaration, so a family-less
prefix-limit-only neighbor is not an operator-reachable residual of
this mechanism; including it would widen behaviour beyond the issue.

## Fix

Add `n.DefaultOriginate` to `hasAFNeighborAttributes` in
`generateProtocols` (`pkg/frr/protocols_render.go`). Consequences by
peer shape:

- Family-less IPv4 + `default-originate`: now activates under
  `address-family ipv4 unicast` and renders `default-originate` there.
- Family-less IPv6 + `default-originate`: unchanged — the IPv4 branch
  is gated on `!isIPv6Peer`, and the neighbor still activates only
  under IPv6 unicast (with `default-originate` rendered there and
  `no neighbor … activate` in the IPv4 block when opened).
- `FamilyInet6`-pinned or unrenderable-family (`UnsupportedInetSAFI` /
  `UnsupportedInet6SAFI` / `CrossFamilyInet`) neighbors: unchanged —
  the `!n.FamilyInet6 && !hasUnrenderableFamily` guards still exclude
  them from the IPv4 fall-through.
- Family-less policyless IPv4 with no AF attributes: unchanged — no AF
  block is opened (FRR default-activation behaviour preserved).
