# #16510: IPv6 generated-error sources keyed by /64 made every host of one LAN /64 share a single 15/s budget

- **Timestamp**: 2026-10-24
- **Action**: #15248 keyed the generated-reply per-source tier SOLELY on the
  IPv6 /64 (`addr_fold` dropped the IID), so every host of one LAN /64 — the
  normal SLAAC shape, typically the whole zone — shared one 15/s + burst-15
  slot: the zone's IPv6 Time-Exceeded / Packet-Too-Big / reject budget fell
  from 1000/s (pre-#15248 per-/128) to 15/s and one host at ~15 pps
  suppressed its neighbours (trigger dropped either way; only the generated
  reply is lost). Restructured `ZoneLimiter` in
  `userspace-dp/src/afxdp/icmp_ratelimit.rs` into host -> /64 -> aggregate:
  `addr_fold` folds the full /128 again (v4-mapped v6 canonicalised to the
  v4 /32, WireGuard `source_bucket_key` precedent, so the mapped form takes
  no /64 tier and cannot alias all mapped hosts into `::ffff:0:0/96`), each
  host keeping the #15248 fair share (aggregate/65 = 15/s + burst 15); the
  new `addr_fold_64`/`prefix64_slots` outer tier gives each /64
  `HOSTS_PER_64` (32) host shares clamped to the aggregate
  (`prefix64_budget` = 480/s + burst 480 at production), so IID rotation
  still gains nothing and one /64 cannot take more than ~48% of the zone
  aggregate. Deny at any tier consumes nothing outward and bumps
  `*_rate_limited_total` exactly once; state stays fixed (64 host + 64 /64
  slots + overflow + aggregate, ~2.3KB/zone limiter, no growable map); the
  1000/s aggregate, per-zone/per-reason splits and all call sites are
  unchanged. Two #15248 cells were re-derived for the two-tier budgets:
  `rotating_..._15248` now asserts the /64 slot keying + >=95% trickle
  admission (16 IIDs at 10/s each are under every tier; the binding bound
  moved to the new saturating cell), and
  `victim_survives_sustained_distinct_floods_15248` probes the victim 1s
  after the flood (at t0+10s the aggregate TAT is ~7.4s ahead after ~2624
  fairly-shared admissions, so no fresh source can pass yet under any
  design with this aggregate).
