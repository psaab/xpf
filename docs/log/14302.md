## Why

Issue #14302: #14192 (commit d40f1f29e) registered every declared unit
as an explicit `false` key in `HostInboundLifelineSet` before the
cluster walk. For a dotted lifeline `hb.1`
(`control-interface hb.1`) whose only declared unit is 7, registration
set `hb.1.7=false`; the role==name arm re-marked only `hb.1=true`, and
the cluster walk's non-zero-unit guard treated `hb.1` as "role at unit
1 of bare parent hb" (naive `strings.Cut`) while
`SplitInterfaceUnitRef` resolves `hb.1` declared-name-first
(`HasUnit=false`), so nothing restored unit 7. Result:
`HostInboundLifelineInterface("hb.1.7", set) == false`, and the
userspace helper `HostInboundLifelineIngressNetdevs` — which enumerates
only declared-unit spellings (`hb.1.7`) — yielded `[fxp0]`, losing the
control link's host-inbound ingress exception. The pinned userspace
test `TestHostInboundLifelineIngressNetdevsDoesNotAddUnitParent12848`
failed on master.

## What

`pkg/config/lifeline.go` (`HostInboundLifelineSet`):

- When a role name equals a declared DECLARED interface name and that
  spelling is dotted (`hb.1`), the interface is an interface identity,
  not a unit of a shorter parent: its declared units are units OF the
  lifeline, so the registration arm now re-marks every declared unit
  (`hb.1.7`) true alongside the base key. A BARE designated name
  (`ge-0/0/0`, the #14192 case) gets no such re-mark — only its unit 0
  shares its netdev.
- The cluster walk precomputes `dottedLifelineBases` (dotted role
  spellings that are declared interfaces) and `markBaseLifeline`
  consults it: a declared dotted lifeline owns every declared unit,
  VLAN-tagged (`hb.1.3`) or not, instead of the #14192 VLAN demotion /
  unit==0 rule that targets bare parents reached by stripping a `.0`
  spelling.
- The naive-cut non-zero-unit demotion of the role's prefix (`hb`) is
  skipped when the role spelling itself is a declared interface, so a
  declared dotted lifeline is never re-read as a unit of its prefix.
  For undeclared-parent spellings (`ge-0/0/0.100` against declared bare
  `ge-0/0/0`) the #14192 demotion stands, as does the
  `SplitInterfaceUnitRef` declared-bare-parent demotion.

NOT changed: the userspace helper and other consumers already delegate
to this matcher; fixing the set restores `hb.1.7` without probing the
lifeline base in the helper and without adding the bare parent netdev
(#12848).

Preserved invariants, each pinned by a test below or an existing suite:

- #14192: bare lifeline parent `ge-0/0/0` does not cover declared
  transit VLAN unit `ge-0/0/0.100`
  (`TestLifelineBareParentDeclaredVLANUnit14192`, plus the
  `ge-0/0/0.100` control in `TestLifelineDottedUnitControls14302`).
- #13137: a role rooted only at a non-zero unit of a declared bare
  parent (`fabric-interface ge-0/0/1.100`) does not exempt the bare
  parent or unit 0 (`TestLifelineNonZeroUnitKeepsParentOrdinary13137`,
  plus controls in `TestLifelineDottedUnitControls14302`).
- #12848: dotted siblings `hb.2`/`hb.2.0` and the bare prefix `hb`/`hb.0`
  stay ordinary (`TestLifelineDottedDeclaredNames12848`,
  `TestLifelineDeclaredSiblingOverridesParent12848`, and the sibling
  assertions in `TestLifelineDottedDeclaredUnit14302`).

## Risk

Behavior delta is narrow: only declared units of a DECLARED dotted
lifeline interface change verdict (false -> true). Bare lifeline
parents keep the #14192 deny-scoping of their declared transit units
(fail-closed direction preserved); non-zero-unit role bindings keep
their bare parents ordinary (#13137). No consumer code changes, so the
config projection, userspace ingress helper, DHCP backstop, and
device-map warnings all see the corrected set through the one matcher.
