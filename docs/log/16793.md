# #16793 — Console Ctrl-D / double Ctrl-C released another session's config lock

- **Timestamp**: 2026-10-25
  - **Action**: The in-process console in `pkg/cli/cli.go:Run` handled
    Ctrl-D (`io.EOF`) and double Ctrl-C by checking the store-GLOBAL
    `InConfigMode()` flag and calling the unscoped
    `store.ExitConfigure()`. The single `configstore.Store` is shared
    by every surface (#14986), so a console Ctrl-D while a gRPC peer
    (`grpc-peer-1`) held the lock discarded that peer's staged
    candidate, freed its lock for a third session, and printed a
    false "Exiting configuration mode" while the daemon stayed up;
    double Ctrl-C did the same before closing the exit channel
    (daemon shutdown masked it). Fix: both paths now act only when
    this session itself acquired the lock (`c.configOwned`) and then
    only via `store.ExitConfigureSession(localConfigSessionID)`,
    clearing `configOwned`. On Ctrl-D a foreign-held mode is treated
    as an operational-mode exit (console exits, foreign holder
    untouched). The logic is factored into
    `releaseLocalConfigureOnEOF` / `releaseLocalConfigureOnInterrupt`
    so the regression tests drive the exact code `Run` calls.
    NOT changed: `exitConfigureTop` (dispatch `exit`/`quit`, already
    gated by #14986 routing so a foreign holder cannot reach it as a
    config verb), `ForceExitConfigure` stale-lock cleanup, the
    SIGINT commit/external-command cancellation priority, and
    `refreshPrompt`'s read-only prompt rendering.
  - **File(s)**: `pkg/cli/cli.go`, `pkg/cli/console_eof_scoped_16793_test.go`, `docs/log/16793.md`
  - **Validation**: new tests in `console_eof_scoped_16793_test.go` —
    `TestConsoleEOFPreservesForeignHolder16793` (foreign
    `grpc-peer-1` stays `locked=true`, candidate `staged-peer`
    survives, no exit banner, console exits; RED pre-fix),
    `TestConsoleEOFExitsOwnConfigMode16793` (console that entered
    `configure` itself still leaves config mode on Ctrl-D and stays
    in the loop), `TestConsoleDoubleCtrlCPreservesForeignHolder16793`
    and `TestConsoleDoubleCtrlCReleasesOwnLock16793` (the second
    site), and `TestConsoleEOFStaleOwnedForeignHolder16793`
    (stale-flag defense). Targeted `go test ./pkg/cli/ -run
    'TestConsoleEOF|TestConsoleDouble' -count=1` and `go vet
    ./pkg/cli/` results are in the commit body.
  - **Risk**: Minimal — the only behaviour delta is that Ctrl-D at a
    foreign-held global config mode now exits the console instead of
    stealing the release; double Ctrl-C still ends the console (and,
    via `Run` returning, the daemon) but no longer pre-discards a
    foreign session's candidate on the way out.
