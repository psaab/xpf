# #12154 — Restore bootstrap lifeline content on first-commit rollback

- **Issue**: #12154 — first-commit rollback kept the configured `10-xpf-fxp0.network` winner by filename instead of preserving the bootstrap lifeline content.
- **Branch**: `fix/12154-teardown-lifeline`
- **Worktree**: `/var/worktrees/12154-teardown-lifeline`
- **Base**: `a714c90d472a3c3d98a3799831cfef3ec311a61c`

## Why

A first non-empty config can cause `networkd.Apply` to overwrite the bootstrap lifeline's `10-xpf-fxp0.network` with candidate addressing. Rollback skipped that path solely by name, leaving the abandoned configuration in place while FRR and the dataplane were cleared.

## What

- Capture the exact pre-takeover `fxp0.network` bytes on successful bootstrap exit, but only when the bootstrap lifeline marker validates the content.
- On rollback, preserve unchanged bootstrap lifeline content or restore its exact snapshot when the configured networkd winner replaced it. Keep `.link` rename files and retire other xpf-written `.network` files.
- Reload networkd after successful file removal or lifeline restoration, including restoration as the only file change. If an unmarked `fxp0.network` remains without a validated snapshot, retain it rather than risk management reachability and report rollback as degraded.
- Update rollback logging and daemon documentation to describe the validated/restored lifeline behavior without claiming that the lifeline is always preserved.

## Risk / remaining acceptance

No live cluster was mutated. The regression exercises real config application, networkd file generation, and the first-confirmed rollback callback against temporary files; command execution is stubbed. It does not prove kernel address reassignment or a live networkd/next-boot observation on an appliance.
