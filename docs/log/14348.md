## Why

Issue #14348 (D8-01): `HostInboundLifelineSet`
(`pkg/config/lifeline.go`) built one merged `map[string]bool` with
unconditional overwrites, so later negative markers clobbered explicit
HA control/fabric lifeline roles and unconditional `.0` aliases
exempted VLAN-tagged transit netdevs:

- `control-interface ge-0/0/0.0` with `unit 0 { vlan-id 100; }`: the
  role set `ge-0/0/0.0=true`, then `markBaseLifeline`'s VLAN branch
  overwrote it with `false` and promoted the bare parent — the
  lifeline's own tagged netdev was exposed to `to-zone junos-host`
  deny / host-inbound blackholing while the wrong netdev was exempt.
- Bare `control-interface ge-0/0/0` with a VLAN-tagged unit 0:
  `set[name+".0"]=true` unconditionally, fail-open exempting the
  tagged unit's distinct netdev.
- Same-trunk multi-role (`control ge-0/0/0.0` + `fabric
  ge-0/0/0.100`): the fabric role's non-zero-unit demotion
  (`set[base]=false`) overwrote the control role's positive base
  entry, blackholing the untagged unit-0 lifeline.

## What

`pkg/config/lifeline.go` (`HostInboundLifelineSet`):

- Positive designations (`pos`) and negative transit exclusions
  (`neg`) are tracked separately per the issue's fix direction; `set`
  is the merged view and `markNegative` never overrides a positive,
  so no walk order (roles, declared interfaces, fabric members) can
  clobber an explicit lifeline. Every prior `set[k]=true/false` site
  now goes through `markPositive`/`markNegative`.
- `unit0SharesParent` centralizes the alias rule: unit 0 shares the
  bare parent netdev only when undeclared or untagged
  (`u.VlanID == 0`). The `name+".0"` alias, `markUnit0Parent` (parent
  of a `.0` role/member), and the fabric-aggregate `.0` alias consult
  it, so a VLAN-tagged unit 0 and its bare parent never alias.
- `markBaseLifeline` is split: `markBaseLifelineCore` classifies
  declared units without touching `base.0` (VLAN-tagged demoted,
  untagged unit 0 promoted, dotted-declared lifelines own all units);
  `markBaseLifeline` (base explicitly designated — bare role, bare
  fabric member) always keeps the base positive; `markUnit0Parent`
  (parent reached only via a `.0` spelling) promotes the parent only
  when unit 0 shares it.
- Bare fabric members with a VLAN-tagged unit 0 also exempt that
  tagged unit (the netdev carrying the fabric traffic), mirroring a
  bare role; unit-spelled members (`ge-0/0/2.0`) designate that unit
  and classify the parent via `markUnit0Parent`.

NOT changed: `HostInboundLifelineInterface` and every consumer
(`BuildJunosHostDenyProjection`, userspace ingress helper, DHCP
backstop, device-map warnings, show paths) — they all read the one
set, so the fix propagates without per-consumer edits.

Preserved invariants, each pinned by an existing or new test:
#14192 bare parent does not cover declared transit VLAN units;
#13137 non-zero-unit role does not exempt its parent/unit 0; #12848
dotted siblings stay ordinary; #14302 declared dotted lifelines own
their declared (including VLAN-tagged) units.

## Validation

New regression `TestHostInboundLifelineSetVlanUnit0AndMultiRoleTrunk`
(four subtests: dotted `.0` role + tagged unit 0, bare role + tagged
unit 0, same-trunk control `.0` + fabric `.100` with untagged and
with tagged unit 0) and
`TestHostInboundLifelineFabricMemberVlanUnit014348`
(`pkg/config/lifeline_vlan_unit0_multirole_14348_test.go`):

- RED on pristine `origin/master` d3e268141 (lifeline.go reverted,
  tests kept): all four subtests plus the member test fail —
  `ge-0/0/0.0=false` for the explicit `.0` role, `ge-0/0/0=true` for
  its parent, `ge-0/0/0.0=true` under the bare role, same-trunk base
  clobbered to false, member `ge-0/0/2.0=false`.
- GREEN with fix: all pass.
- Fail-on-revert verified by restoring pristine `lifeline.go` (RED
  above) and re-applying the fix (GREEN).

Targeted suites: `go test ./pkg/config/ -run
'Lifeline|HostInbound|JunosHost'` passes; `go test
./pkg/dataplane/userspace/ -run HostInboundLifeline` passes
(includes 10751/12848 ingress-netdev tests). Full `pkg/config`
package run exceeded the 300s lane timeout in this environment;
its result is recorded by the parent verification pass.

## Risk

Behavior deltas are confined to `HostInboundLifelineSet` verdicts:
VLAN-tagged unit 0 no longer aliases its bare parent in either
direction (tagged unit stays ordinary under a bare role — the
fail-closed direction; explicit `.0` role keeps its exemption), and
same-trunk roles can no longer demote each other's designated
entries. Ordinary declared interfaces/units keep their registered
`false` presence keys, so the matcher's declared-name precedence is
unchanged.
