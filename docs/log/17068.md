# #17068 — BestEffortKernelKnob lifecycle primitive

- **Timestamp**: 2026-10-27
- **Action**: Added the missing lifecycle primitive for the BestEffortKernelKnob class and migrated every pkg/daemon procfs writer onto it. `pkg/fsatomic/kernel_knob.go` provides `WriteKernelKnob`/`WriteKernelKnobVerified` (read-compare-write, newline-normalised, optional read-back) and the `KernelKnobs` owner registry (`Assert` captures the prior on first assert and refuses a second owner of the same path; a first assert whose capture read fails registers nothing and writes nothing; `Release` restores captured priors and retains failed restores as retry debt per the #5114 rule; assert/release writes and capture bookkeeping are serialized per path with a generation revalidation so a same-owner re-assert during a restore is never deleted by that release; daemon-lifetime posture is expressed by writing through `WriteKernelKnob` WITHOUT registering — the registry has no keep-forever policy). Daemon migrations: `fib_multipath_hash_policy` now asserts on `load-balance consistent-hash` and restores the captured prior on removal (was assert-only — the live instance); the knob decision is derived from the forwarding-table export policy itself (not only resolveECMP's render side effect, which ApplyFull skips for policy-only configs), and the restart contract is scoped below; RETH/VLAN IPv6 knobs, transit-gate ip_forward, host forwarding posture, and `realHostTunableFS.writeFile` go through `WriteKernelKnob` with warned (no longer silently discarded) errors; no-redirects assert/restore and the #15707 icmpv6 ratelimit repair use the shared writer while keeping their bespoke capture/cap semantics (#16779); transit cleanup uses the verified writer. The fsatomic canary allowlist now contains only the resolv.conf bind-mount fallback for pkg/daemon plus the primitive's own `realKnobFS.WriteFile`. NOT migrated: `reassertTCPloosePosture`'s injected seams (its fault-injection tests model module-load races through them; it is the single verified lifecycle owner of nf_conntrack_tcp_loose) and the non-daemon dataplane/networkd knob writers (outside the issue's daemon census; they keep their canary entries). Fold (Rev18111): deleted the speculative `AssertVerified`/`ReleaseAll`/`CapturedPrior`/`KeepOnDisable` surface and the four unused owner constants (only `knobOwnerFib` is wired); a same-owner policy change on a live capture is now refused rather than silently flipping what Release does. Restart design decision: the registry stays process-lifetime (no durable prior file — the fsatomic seam for one would be a /var/lib/xpf record like transit-gate-owned, rejected here as disproportionate for one knob); instead the daemon startup/first-apply path re-asserts the OPERATOR value: fib_multipath_hash_policy's operator value is the kernel default 0 (no shipped sysctl.d payload sets it; 1 is only ever written under a live consistent-hash config), so a first assert that finds the knob already at 1 seeds 0 as the restore target (`SeedPrior`) rather than capturing the previous daemon's asserted value as prior. Restore-on-unset is restart-safe except for an operator who set the knob to 1 themselves before first starting xpfd (the documented sysctl.d route for such a baseline).
