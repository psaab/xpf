# #16562: local `show interfaces detail|extensive` attributed a VLAN trunk's physical row to a VLAN unit's zone

- **Timestamp**: 2026-10-24
- **Action**: The local CLI detail/extensive presenters keyed the zone
  map by `baseIfName(member)`, collapsing every unit of a physical
  interface onto its base name, so a trunk whose units sit in different
  zones (e.g. `ge-0/0/2.50` in trust, `ge-0/0/2.80` in dmz) printed a
  map-order-random `Security zone:` — plus that zone's quarantine
  qualifier — on the physical row, disagreeing with the remote (gRPC)
  CLI. The gRPC twin had fixed this in #14364 with a private
  `physicalRowZoneKey` that attributes only a bare or unit-0 member to
  the physical row. Moved that predicate verbatim to
  `pkg/config.PhysicalRowZoneKey` (`pkg/config/interface_physical_row_zone.go`)
  as the single shared implementation and routed all four presenters
  through it: `pkg/cli` detail + extensive (replacing `baseIfName`
  keying) and `pkg/grpcapi` detail + extensive (replacing the deleted
  private helper, comments updated). `baseIfName` itself is retained —
  it still has legitimate reth-member callers. Also corrected the stale
  detail/extensive header comments that described stripping the unit to
  a base key as the intended join. Added
  `pkg/config/interface_physical_row_zone_16562_test.go` (bare/unit-0/
  ".00"-fold/non-zero/malformed/nil-config cells) and
  `pkg/cli/cli_show_interfaces_physical_zone_16562_test.go`
  (compiler-built fixtures over a real dash-named host interface: trunk
  units 50→trust / 80→dmz with unit 0→untrust must print exactly
  `Security zone: untrust` on the physical row across 20 runs in both
  presenters; a trunk-only fixture with no unit 0 must print no
  `Security zone:` line at all). The trunk-vs-gRPC security-zone
  agreement is asserted in both `pkg/cli` (local presenters) and the
  pre-existing `pkg/grpcapi` #14364 test (physical row prints no
  non-zero unit's zone, unit-0 zone resolves), which share the one
  predicate; full byte-equality between the two renderers is not
  possible because their non-zone lines already differ by design
  (authored vs kernel names, differing link/statistics fields).
- **File(s)**: `pkg/config/interface_physical_row_zone.go` (new),
  `pkg/config/interface_physical_row_zone_16562_test.go` (new),
  `pkg/cli/cli_show_interfaces_detail.go`,
  `pkg/cli/cli_show_interfaces_extensive.go`,
  `pkg/cli/cli_show_interfaces_physical_zone_16562_test.go` (new),
  `pkg/grpcapi/server_show_interfaces_text.go`, `docs/log/16562.md`
- **Validation**: Targeted tests for the new cells plus the existing
  `pkg/cli` interface-identity/reth tests and `pkg/grpcapi` #14364
  tests — see PR body for counts. On a host with no dash-named
  interface the local-CLI cells skip (same doctrine as #4984/#4328);
  the config cells are host-independent.
