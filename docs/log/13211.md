# Issue #13211 — reset NAT then metadata on replacement

## Why

`compileNATSource` and `compileNATDestination` implement #3850's last-`then`
block-wins behavior by resetting `rule.Then`, but retain `thenAuthored` and
(source NAT) `unknownThenLeaves` from earlier blocks. The strict NAT gates
therefore reject a valid winning action due to superseded malformed blocks;
tolerant source-NAT loads also warn about unknown leaves that no longer apply.

## What

Both NAT compilers now set `thenAuthored` from the current `thenNode` inside
the last-wins loop. Source NAT also clears `unknownThenLeaves` before recording
the current block. Added regressions for superseded packed contradictions,
multiple pools, and unknown leaves across source and destination NAT, plus
controls that winning malformed blocks remain rejected.

## Risk

The behavior change is limited to metadata belonging to superseded `then`
containers. Validation of the winning container remains unchanged; no dataplane
or configuration serialization fields change.
