# Issue #17219: R4-Q38-07 — false "Once still defers" comment and redundant dataplane-safety sync.Once

- **Timestamp**: 2026-10-27
- **STEP-0 (defect live on origin/master 49f6255317)**: re-verified at HEAD — `pkg/api/metrics_descriptors.go:7-10` claimed the dataplane-safety family's `sync.Once` "still defers the NewDesc calls to Describe/Collect time", but `newCollector` (same file :11-16) loops `fam.init(c)` over `collectorDescFamilies`, whose dataplane-safety row (`metrics_descriptor_table.go:121`) calls `initDataplaneSafetyDescriptors`, whose `dataplaneSafetyOnce.Do` (`metrics_dataplane_safety_13302.go:10`, field `metrics.go:153`) therefore runs inside `newCollector`. Probe (temporary test, since removed): `newCollector(nil)` left `dataplaneObsoleteRegistryAccesses` and `dataplaneXDPAttachModeSurfaces` non-nil (`nil=false` for both) — allocation is at construction, not Describe/Collect.
- **Action**: deleted the false comment sentences in `metrics_descriptors.go` and replaced them with the true statement (every family's init, dataplane-safety included, runs eagerly in `newCollector`). Took the issue's optional structural half too: dropped `dataplaneSafetyOnce` from `xpfCollector` (`metrics.go`), unwrapped the `sync.Once.Do` in `initDataplaneSafetyDescriptors` so it assigns the six descriptors directly, and removed the now-redundant emit-time `c.initDataplaneSafetyDescriptors()` call in `emitDataplaneSafety`. A literal-constructed `&xpfCollector{}` (tests only; production always uses `newCollector`) now reaches `emitConstMetric` with nil descriptors, which skips those samples and bumps `counterReadErrors` instead of lazily allocating — noted in a comment at the emit site. No other family used this idiom (grep: the Once was the only one).
- **Tests**: new `pkg/api/metrics_dataplane_safety_17219_test.go` — `TestDataplaneSafetyDescriptorsEagerNoOnce17219` asserts all six dataplane-safety descriptors are non-nil immediately after `newCollector(nil)` (before any Describe/Collect), and that a literal collector's `emitDataplaneSafety` emits nothing, does not panic, and does not lazily allocate. Existing cited cells re-run unchanged: `TestCollectorDescriptorTableAgreement16202` and `TestMetricsDataplaneSafetyAndDivergenceSeries13302`.
