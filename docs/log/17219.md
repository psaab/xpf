# Issue #17219: R4-Q38-07 — false "Once still defers" comment and redundant dataplane-safety sync.Once

- **Timestamp**: 2026-10-27
- **STEP-0 (defect live on origin/master 49f6255317)**: re-verified at HEAD — `pkg/api/metrics_descriptors.go:7-10` claimed the dataplane-safety family's `sync.Once` "still defers the NewDesc calls to Describe/Collect time", but `newCollector` (same file :11-16) loops `fam.init(c)` over `collectorDescFamilies`, whose dataplane-safety row (`metrics_descriptor_table.go:121`) calls `initDataplaneSafetyDescriptors`, whose `dataplaneSafetyOnce.Do` (`metrics_dataplane_safety_13302.go:10`, field `metrics.go:153`) therefore runs inside `newCollector`. Probe (temporary test, since removed): `newCollector(nil)` left `dataplaneObsoleteRegistryAccesses` and `dataplaneXDPAttachModeSurfaces` non-nil (`nil=false` for both) — allocation is at construction, not Describe/Collect.
- **Action**: deleted the false comment sentences in `metrics_descriptors.go` and replaced them with the true statement (every family's init, dataplane-safety included, runs eagerly in `newCollector`). Took the issue's optional structural half too: dropped `dataplaneSafetyOnce` from `xpfCollector` (`metrics.go`), unwrapped the `sync.Once.Do` in `initDataplaneSafetyDescriptors` so it assigns the six descriptors directly, and removed the emit-time `c.initDataplaneSafetyDescriptors()` call in `emitDataplaneSafety` (restoring it would resurrect the Once idiom; the literal-collector nil-Desc hazard it masked is handled by the fold-fix guard below, not by lazy allocation). No other family used this idiom (grep: the Once was the only one).
- **Tests**: new `pkg/api/metrics_dataplane_safety_17219_test.go` — `TestDataplaneSafetyDescriptorsEagerNoOnce17219` asserts all six dataplane-safety descriptors are non-nil immediately after `newCollector(nil)` (before any Describe/Collect), and that a literal collector wired to a REAL dataplane (`dataplane.New()`) emits nothing, does not panic, counts 3 skipped nil-Desc series in `counterReadErrors`, and does not lazily allocate. Existing cited cells re-run unchanged: `TestCollectorDescriptorTableAgreement16202` and `TestMetricsDataplaneSafetyAndDivergenceSeries13302`.
- **Fold fix (Rev18259Opus NOT READY on 94dfb3b754)**: the claim above that a literal collector "reaches `emitConstMetric` with nil descriptors, which skips those samples and bumps `counterReadErrors`" was FALSE — `emitConstMetric` (`metrics_emit_15086.go:99`) calls `prometheus.NewConstMetric(desc, ...)` unconditionally and client_golang dereferences `desc.err`, so a nil Desc PANICS; it does not skip or count. The old test cell was vacuous (`&xpfCollector{}` with nil dp: `Probe(nil)` returns nil and emit returns before any series). Proven firsthand on the unguarded head: a temporary test with `&xpfCollector{deps: collectorDeps{dp: dataplane.New()}}` panicked at `client_golang prometheus/value.go:106` via `metrics_emit_15086.go:99` ← `emitDataplaneSafety` (RED). Fix: `emitDataplaneSafety` now routes every series through a local guard that skips a nil Desc and bumps `counterReadErrors` (the sibling `emitSnapshotPolicyMismatch` / `emitInvalidLabelValues` nil-Desc pattern), and the emit-site comment states that truth. The `sync.Once` is NOT restored. The vacuous test cell was replaced with the real-dataplane literal collector above (temporary RED test removed).
