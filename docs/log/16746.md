# #16746 — cluster without a complete control link commits under private-RG election (R3-A22-02)

## Defect

Private-RG election is the compiler default: it elects redundancy
groups over the control link only and suppresses RETH VRRP. The
heartbeat — the sole peer detector in that mode — starts only when
BOTH `control-interface` and `peer-address` are set
(`pkg/daemon/daemon_ha_sync.go` `startClusterComms`). A cluster with
redundancy groups but an incomplete pair therefore committed cleanly
with no arbitration at all:

- no `control-interface` (the documented fabric-transport shape, or
  `peer-address` only): the election reads `controlInterface == ""`
  as standalone, so both nodes elect PRIMARY for every RG —
  dual-primary with duplicate VIPs, RETH MACs and NAT state, and two
  session-sync owners;
- `control-interface` set, no `peer-address`: the heartbeat never
  starts, `peerConfirmedAbsent` is never set, and the non-preempt
  never-seen hold keeps every RG SECONDARY with no timer — permanent
  no-primary.

## Fix

`pkg/config/compiler_validate_strict_chassis.go` only (plus docs):

- `validateChassisClusterStrict` now rejects, on the strict
  commit/commit-check path, a cluster that has at least one
  redundancy group and `PrivateRGElection` in effect but lacks a
  complete `control-interface` + `peer-address` pair. Each of the
  three incomplete arms (neither leaf, peer-address only,
  control-interface only) gets its own message naming the missing
  leaf, the consequence (dual-primary vs permanent no-primary), and
  the remedy: set the missing leaf, or set `no-private-rg-election`
  so RETH VRRP arbitrates (the fabric-transport migration path).
- No behaviour change for a complete pair, for
  `no-private-rg-election` clusters (VRRP arbitrates without a
  control link), or for RG-less clusters (nothing to mis-elect).
- The tolerant load / peer-sync paths keep the existing
  `lenientChassisRG` downgrade (#1960 no-brick): the same gate
  becomes a warning, so a config persisted by an older binary still
  boots. Arm (b) on such a config is additionally bounded at runtime
  by the Manager-owned never-seen clock (#16751).
- Deliberately NOT changed: the election itself. After this gate, a
  strict-committed two-node cluster always has a peer detector, so
  `controlInterface == ""` again means a genuinely standalone /
  RG-less node; changing election semantics for lenient-loaded
  configs is #16751's Manager-clock scope, not this commit gate.

## Regression tests

`pkg/config/compiler_validate_strict_chassis_controllink_16746_test.go` (new):

- `TestIncompleteControlLinkFailsCommit16746` — the three incomplete
  arms are strict-rejected, each message naming the missing leaf and
  the `no-private-rg-election` escape hatch.
- `TestIncompleteControlLinkTolerantWarns16746` — all three arms
  compile on the lenient path with a warning naming both leaves.
- `TestCompleteControlLinkControlsCommit16746` — controls: complete
  pair commits under default private-RG election; every incomplete
  arm commits with `no-private-rg-election`; RG-less cluster and
  standalone config commit.

FAIL-ON-REVERT: removing the #16746 block in
`validateChassisClusterStrict` makes the three reject subtests
compile clean again.
