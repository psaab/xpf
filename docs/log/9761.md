  - **Action**: Verified the defect and how the plan is actuated.
    - **The defect.** `planPhysDesired` (`pkg/dataplane/compiler_iface_desired.go`) skipped every tagged zone reference before it read the interface-level `mtu`. An interface whose zone references are all tagged units therefore got no plan.
    - **The write path already reaches the parent.** `mapZoneInterface` runs its per-phys setup for tagged references too, with the resolved phys being the parent netdev. That setup includes the single #8119/#8120 MTU write, so only the plan was missing.

  - **Action**: Codex round 1 on `77d8740fe` returned MERGE NO with one MED finding and one LOW.
    - **MED: a VLAN child's MTU was written before its parent's.**
      - **The failure.** `mapZoneInterface` wrote a tagged reference's unit MTU before the per-phys setup wrote the parent's. Linux refuses a VLAN child MTU above the parent's current MTU (`net/8021q/vlan_dev.c`). With the parent and the children at 1500 and all configured to 9000, the first child the zone order reached was refused with a warning. The parent was then raised, and the apply succeeded with that child at 1500 until the next apply.
      - **Fix.** `applyPhysMTU` writes a netdev's planned MTU at most once per apply. A VLAN reference calls it before its child's MTU write, and the per-phys setup calls it for untagged references. Lowering a parent clamps every child above the new value, and the child's own write then follows.
      - **Not changed here.** A unit MTU above its interface-level MTU still commits clean, and Linux refuses the child write on every apply. Filed as #9837 (LOW).
    - **LOW: the actuation cell never ran the child MTU path.** It cached only the parent link, so the child lookup fell through to real netlink and failed silently. Its fake also modelled no parent/child constraint.
      - **Fix.** `applyTaggedParent9761` caches all three links and applies Linux's VLAN MTU rules to every write (`kernelVLANMTU9761`).
      - The actuation cell now also requires unit 50 at its 1300, unit 80 clamped to 1400, and a single parent write from the two tagged references.
      - `TestAJumboParentIsRaisedBeforeItsVLANChildren_9761` raises the parent and both units to 9000 and requires all three there after one apply. Both units carry the MTU, so a child-first write fails the cell whichever zone comes first.
    - **Matrix round 1** at `77d8740fe`: 4 of 4 killed. Round 2 adds the parent-first, per-phys and once-per-apply mutants.
    - `go test -run '9761|8119|8120' ./pkg/dataplane/`: 11 tests pass, 6 of them #9761 cells. gofmt and vet are clean.
