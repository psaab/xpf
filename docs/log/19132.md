- **Action**:
  - `tests_support.rs`: the injected-packet driver becomes
    `txn_run_pass_19132`, an optional injected packet plus a list of RX
    descriptors in one pass. Each RX frame reserves its own UMEM frame from
    the BACK of the TX free list, because the mirror-test binding marks every
    frame free for TX and an injected packet takes the front one. A first
    draft wrote the RX frame at offset 128, inside TX frame 0, and the
    injected copy overwrote its metadata. The existing injected callers are
    unchanged.
  - New cell `source_nat_failure_lets_the_pass_finish_19132`: the failing SYN,
    then a valid SYN from a source the rule does not cover, in ONE RX batch.
    Both must be read (`rx` 2, `validated_packets` 2), the failure recorded
    once, the following packet forwarded, and only the failed frame recycled.
  - Why not an injected or a held packet, as suggested:
    - a held pass creates no session (#18560 `held_pass_creates_no_session`),
      so a SYN never reaches the composer there;
    - an injected SYN was driven and never reached the source-NAT composer
      (no failure recorded): injected packets are admitted on their own path.
    - A following RX descriptor is the reachable discriminator.
