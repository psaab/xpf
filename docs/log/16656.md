# #16656: Feed-server URL with internal IP literal passes strict commit but SSRF block refuses every fetch

- **Timestamp**: 2026-10-25
- **Branch**: `fix/16656-feed-dest-gate`
- **Action**: Moved the feed destination predicate (`FeedDestinationBlocked`,
  `FeedDestinationClass`, `FeedDestinationAllowed` + the blocked-prefix table)
  to `pkg/config/feed_destination.go` so the strict compiler gate and the
  `pkg/feeds` runtime guard share one predicate without an import cycle
  (pkg/feeds already imports pkg/config). `validateDynamicAddressFeedServerEndpointStrict`
  now rejects (strict) / warns (lenient, via the existing
  `lenientDynamicAddressFeedRef` wrapper) a feed-server whose resolved URL
  host or bare `hostname` leaf is an IP literal the predicate refuses and
  that no `allow-destination` prefix covers, naming the destination class.
  Added the per-server config leaf
  `security dynamic-address feed-server <s> allow-destination <prefix>`
  (repeatable, CIDR-validated): compiled into `FeedServer.AllowedDestinationPrefixes`,
  threaded through `feeds.Manager.Apply` into each feed's
  `destinationAllowlist`, unioned with the manager-level lab allowlist at
  fetch validation, and included in the daemon's `feedsConfigHash` so an
  override-only change restarts the producers. Documented the destination
  policy in `pkg/feeds/README.md`.
- **File(s)**: `pkg/config/feed_destination.go` (new),
  `pkg/config/compiler_validate_strict_observability.go`,
  `pkg/config/compiler_services.go`, `pkg/config/schema_security_dynamic_address.go`,
  `pkg/config/schema_validators_network.go`, `pkg/config/types_security.go`,
  `pkg/config/feed_destination_16656_test.go` (new),
  `pkg/feeds/fetch.go`, `pkg/feeds/feeds.go`,
  `pkg/feeds/feed_destination_override_16656_test.go` (new),
  `pkg/daemon/daemon_feeds.go`, `pkg/feeds/README.md`,
  `debian/changelog`, `docs/log/16656.md`.
- **Validation**: targeted `go test` for the two new tests plus full
  `pkg/config`, `pkg/feeds`, `pkg/daemon` suites (counts in PR body).
- **Risk**: an on-prem feed-server using a private literal that previously
  committed (and silently never fetched) now fails strict commit until the
  operator adds `allow-destination` covering it — the intended
  operator-visible behaviour. Hostname destinations are unchanged
  (runtime-enforced only).
