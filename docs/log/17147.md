# #17147 — additive-wire literal ratchet uses a hand-kept population with no completeness check (R4-Q15-06)

- **Timestamp**: 2026-10-27
- **Issue**: #17147 (R4-Q15-06)
- **Base**: `origin/master 60bba59e4b`

## Defect (STEP-0, verified at base)

Live on `60bba59e4b`. `ADDITIVE_WIRE_EXHAUSTIVE_CEILING`
(`userspace-dp/src/protocol/cos_literal_guard_7689.rs:236-270` at base) held 22
hand-kept rows while its header stated the population as "a Default impl, at
least one `#[serde(default)]` field, and >= 8 fields" — and nothing checked the
table against that rule. A mechanical census of `src/protocol/*.rs` applying
the stated rule (derive/manual `Default`, at least one serde-`default` field,
>= 8 named fields; comments/strings blanked) finds **47** qualifying structs
on this tree, so 25 qualifiers had no row, among them `ControlResponse`
(30 fields), `ControlRequest` (21), `RouteSnapshot` (13), `NeighborSnapshot`
(8), `IdleLeaseWire` (23) and `SessionPolicyTuple` (8) — confirming the
issue's census direction (its regex probe said 39/22-missing without
comment/string blanking; the crate's own detection confirms the class).
`ControlResponse`'s one exhaustive literal was the production dispatcher at
`userspace-dp/src/server/handlers/mod.rs:201-232`: a 30-field all-default
enumeration (`ok: true` plus every other field at its `Default`), so every
new `ControlResponse` field forced an edit to that shared literal.

## Fix

- `userspace-dp/src/server/handlers/mod.rs`: the dispatcher literal is now
  `ControlResponse { ok: true, ..Default::default() }`. Every dropped field
  was exactly the type's `Default` (`String::new()`/`Vec::new()`/`None`/
  `false`/`0`), so behaviour is identical; future additive fields no longer
  touch the dispatcher.
- `userspace-dp/src/protocol/cos_literal_guard_7689.rs`: the population is
  derived mechanically. New census code (`AdditiveWireStruct`,
  `qualifies_as_additive_wire`, `matching_brace`, `named_field_count`,
  `additive_wire_structs_in_source`, `qualifying_additive_wire_structs`)
  scans `src/protocol/*.rs` with the shared `blank_comments_and_strings`
  helper and applies the stated rule: `Default` from the struct's own
  attribute block or a manual `impl Default for Name`, at least one field
  whose `#[serde(...)]` carries the word `default`, and >= 8 named fields
  (angle-depth tracked so `Vec<A, B>` mints no phantom field; tuple/unit
  structs excluded). Scoping to `src/protocol` is the module's own contract
  (`protocol/mod.rs`: all wire types are `pub(crate)` there). Known
  limitations are stated at the derivation: generic parameters are not
  specially parsed (a simple `struct Wire<T> {` is counted; only a
  generic parameter containing `(` escapes) and renamed re-exports
  count under their definition name.
- The ratchet cell now asserts the derived population equals the ceiling
  table's row set in both directions — a qualifying struct with no row
  fails naming it; a stale row fails the other way — with non-vacuity
  floors on protocol-file count (>= 10) and derived population (>= 40,
  measured 47). `CoSSchedulerSnapshot` is folded into the table at its
  pinned 0 (its dedicated zero cell keeps its own literal-count floor).
  `ControlResponse` is listed at ceiling 0.
- Ceiling rows added for every previously-absent qualifier at the counts
  the ratchet measured on this tree (see Tests; provisional `usize::MAX`
  placeholders used during measurement were all tightened to the measured
  values in this same change — no placeholder remains in the table).
- New both-directions fixture `additive_wire_census_applies_the_stated_rule_17147`
  pins each rule leg independently (field floor, Default derivation,
  manual Default, serde-default presence, rename-is-not-default,
  `Vec<A, B>` comma, tuple exclusion), mirroring the #8537 fixture's
  discipline.

## Risk

Test-only guard plus one behaviour-identical production literal. The
dispatcher change drops only fields that were already at `Default`, so the
wire response is byte-identical. The widened ratchet can red on future
additive-wire structs until a ceiling row is added — that is the intended
completeness property, and the failure message names the struct and the
remedy.
