# Issue #19055: H11 landing poll ignored dual-active in the move's other RGs

## Why

- **Timestamp**: 2026-11-09 PST
- **Action**: The Codex seat (review of #19041 at 80c25a683d) reproduced
  it: with `SOAK_RG=all`, RG1 moves to node1 and lands. During RG2's
  landing poll, both reads show RG1 primary/active on both nodes. The move
  PASSed with `dual_samples=0`. `one_rg` scored `rg_ownership` only for
  the RG being moved, although every sample reads all RGs. This predates
  #19041.

## What

- **File(s)**: `test/incus/rg_move_soak.py`, `test/incus/rg_move_soak_test.py`,
  `docs/ha-rg-move-correctness.md`
- `Soak._score_other_rgs()` runs on every landing-poll sample and scores
  dual-active for every RG the run moves (`_scope_rgs`):
  - an RG already landed earlier in the move records it in its own result;
  - an RG not yet moved keeps the reading (`_early_dual`) until `one_rg`
    creates its result;
  - an earlier RG that did not land is skipped, since its handoff may still
    be in flight and it already FAILs.
- `one_rg(..., landed_before=results)`: `run()` passes the move's results
  so far.
- **Cells** (`OtherRgsDuringLandingPoll19055`):
  - Codex's reproduction (`Rg1DualDuringRg2Landing`) FAILs with "RG1
    dual-active ... during RG2's landing poll";
  - a later RG seen dual during an earlier RG's poll is kept, and FAILs;
  - a clean two-RG run has no dual sample.
- Docs: "Several RGs per move", and the known-gaps bullet marked fixed.

## Validation

See the commit message (runner RED/GREEN and mutants).

## Risk

Harness only. Multi-RG soaks can now FAIL on an overlap the old poll
missed. `SOAK_RG=2` (the per-PR and per-wave runs) is unchanged: its scope
holds one RG.
