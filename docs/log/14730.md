# #14730 — HA DHCP Lease Pre-Seed Resurrects Tombstoned Leases via Stale LFC Generations + Bare `\r` in `csvField`

## Mechanism

Leg 1 (LFC resurrection): `PreSeedMemfileMerged4/6` and
`PreSeedMemfileMerged4/6WithAuthority` called plain `writeMemfile4/6`
when `live || stillMastering`. Plain writers replace only the current
memfile with an active-only snapshot, erasing any `state=1/2` tombstone
rows it held. Older LFC generations (`.1`/`.2`/`.completed`) still on
disk carrying the pre-release `state=0` row are then replayed by Kea's
multi-file startup load and by `parseActiveLeases` (DDNS path, which
reads `.2 -> .1 -> current` or `.completed -> current` chronologically,
last-row-wins), resurrecting released/declined/peer-excluded leases.

Leg 2 (bare CR): `csvField` quoted only on `,"\n`. A client-controlled
hostname containing `\r` (Option 12/FQDN, replicated via Kea socket JSON
+ HA sync) was emitted raw. Go `encoding/csv` treats bare `\r` as a
record separator, producing a short/ragged row that trips the
`maxRequiredIdx` hard error in `parseActiveLeasesFileInto`, halting
DDNS reconciliation for the family. `SanitizeSyncLeaseForFamily` never
sanitized Hostname/HWAddress/ClientID/DUID.

## Fix

- All merged pre-seed branches (`PreSeedMemfileMerged{4,6}`,
  `...WithAuthority`, every `live`/`stillMastering` combination) now use
  `writeMemfile{4,6}ReplacingLFC`, which writes the merged active-only
  current file then removes `.2`/`.1`/`.completed` (dir-synced).
  Plain `PreSeedMemfile{4,6}` also switched to `ReplacingLFC` — it is the
  same peer-only active-only overwrite (extends beyond the issue's named
  merged functions; consistent with its documented overwrite contract,
  noted here deliberately).
- `SanitizeSyncLeaseForFamily` strips ASCII control chars (`<0x20`,
  `0x7f`, incl. CR/LF/TAB) from Hostname/HWAddress/ClientID/DUID. This
  shared boundary covers cluster receive, socket seed, and memfile
  pre-seed sinks, so all three cannot drift.
- `csvField` strips controls defensively at the sink and its quote set
  now includes `\r`.

Safety of removing generations on the live path: the merged set is read
under `withQuiescedPreSeed` (Kea `dhcp-disable`d, or verified stopped)
via the live socket or the LFC-aware fallback reader
(`readSyncLeasesViaMemfile` -> `parseActiveLeases`, which reads the full
generation set), so every still-valid local lease — including one living
only in `.1` — is captured into the merged current file before the
generations are removed. No lease is lost; the generations are purely
superseded. Kea restart is forced (`appliedConfig=nil` when quiesced),
so any kea-lfc rotation after the pre-seed operates only on the new
active-only current file and cannot recreate a tombstoned row.

Staggered-failover test semantic change: `TestPreSeedMemfileMerged_
StaggeredFailoverPreservesStillMastered9853` previously asserted the
`.1` generation survives. That is now inverted (generation removed);
its comment was updated — the still-mastered binding survives in the
merged current file, which the test still asserts. This is the intended
#14730 behavior change, not a regression.

## Residuals / uncovered risks

- Kea-written memfile bypass: Kea itself appends client hostnames to its
  memfile outside our writer. If Kea stores a bare-CR hostname, our
  readers (`parseActiveLeases`, display parser) fail closed (parse error
  -> family untrusted -> DDNS destructive diff skipped; pre-seed refuses)
  rather than silently corrupting. Fixing Kea's writer is out of scope;
  our ingress (socket JSON -> SyncLease -> sanitize) is covered.
- `removeLFCGenerations` failure after a successful current-file write
  returns a joined error; daemon logs a warning and the post-start
  lease-add seed is the backstop (same fail-open semantics as the prior
  pure-backup path).
- Unicode control characters beyond ASCII are not stripped; DHCP
  hostnames are ASCII-oriented and Go csv only splits on ASCII CR/LF.
