# #12836 — make global-policy zone errors actionable and hide internal book keys

- **Timestamp**: 2026-10-13 (`fix/12836-campaign-pub`)

## Why

`validatePolicyZoneReferencesStrict` checked global-policy zone references only
against `policyZoneSpecialTokens` and configured zones. `junos-global` is
intentionally not an exempt reference token, but it is also a reserved
context that cannot be configured as a security zone (#3055). The generic
undefined-zone error therefore advised defining a forbidden zone, despite the
configuration's rejection being correct.

The #3149 address-set resolver also runs after zone-local books are folded
into the global book. A policy reference to a zone-local empty set consequently
reported `zone-local/<zone>/<name>`, an internal compiler key, rather than the
operator-authored set and its zone.

## What

- Reject `junos-global` in either global-policy zone-scope list with a
  reserved-context diagnostic, before the ordinary undefined-zone check.
  Tolerant compilation preserves legacy configurations; the userspace snapshot
  integrity preflight remains the fail-closed boundary.
- Render zone-local keys as `<name> (security-zone <zone>)` in policy address
  resolution failures, including the outer match token and inner cause; reuse
  the same display helper in address-set member validation.
- Add regressions for from/to reserved scope, typo-zone and valid-zone controls,
  tolerant load preservation, and a zone-local empty-set diagnostic.

existing errors. Tolerant loading remains bootable; the userspace snapshot

remains fail-closed; only its diagnostic changes.
