# #18744: refuse introducing a published placeholder cluster key

Per-issue log (see `docs/log/README.md`). Split out of #18719 (its
"product side"), found while rotating the lab clusters off their published
keys for #18724.

- **Timestamp**: 2026-11-01
  - **Action**: Added `validateClusterAuthKeyPlaceholderStrict`. A strict
    commit over an active config refuses a published placeholder
    (`change-me` / `example-only`, matched without case) that it INTRODUCES
    into `authentication-key` or `additional-authentication-key`.
    "Introduces" is judged byte for byte against the active config's
    accepted set.
    - A pre-existing placeholder keeps committing with the warning,
      including every step of the #6630 rotation off it.
    - Fresh state (no active config: the bootstrap import, check-config,
      day-0, direct CompileConfig) warns only.
    - The tolerant paths downgrade the refusal to a warning (#1960).
  - **Plumbing**:
    - `currentConfigPresent18744` in `compileOpts`, set by
      `currentClusterOpts` whenever configstore supplies an active config,
      with or without a cluster stanza.
    - `clusterKeyIsPublishedPlaceholder` is now the one predicate behind
      the warning and the refusal.
    - The gate runs before the #16858 transition gate.
    - `currentConfigPresent18744` is allowlisted in the #16166
      completeness census. It is presence, not a downgrade.
