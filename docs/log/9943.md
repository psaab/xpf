# Issue #9943 — DHCP classless-route precedence

## Decision

Implemented option (a): enforce the documented learned `<` static contract rather than changing the contract. The FRR renderer and management-VRF netlink twin now suppress a DHCP-learned classless prefix when a same-table rendered/operator static route contains it. This is prefix containment, not a `/1` special case: a static `/8` suppresses learned `/9` routes, while a learned route broader than a more-specific static remains available for the uncovered address space.

The management-VRF inventory is scoped to `RTPROT_STATIC`; xpf-owned `RTPROT_DHCP` and connected/kernel routes are silently ignored as non-authority, while unexpected other protocols are warned and ignored. A DHCP default is also suppressed in the management twin when a static table default is present. Inventory failure refuses learned routes and returns an error.

For prefix sanity, an option-121 `/0` is folded into `Lease.Gateway` and follows the normal DHCP-default suppression contract. Classless `/1` routes and non-forwardable IPv4 martian ranges (`0/8`, `127/8`, `169.254/16`, `224/4`, `240/4`) are refused by default. RFC1918 private prefixes remain valid because enterprise DHCP deployments legitimately use them. The safety policy is shared by both route consumers through `dhcp.ClasslessRouteIsTooBroad` and `dhcp.ClasslessRouteIsMartian`.

`XPF_DHCP_TRUST_CLASSLESS_OVERRIDE=1` is the explicit operator escape hatch. It permits covered, broad, or martian classless routes, and each use site emits a `WARN` containing the environment name, learned destination, and covering static/operator destination when applicable. Dual-condition routes emit both the safety and covering warnings. The variable is unset by default; the exact DHCP default-route suppression contract remains unchanged.

No existing schema/config knob was a better fit: this is a deliberately process-local emergency trust override, and `pkg/config/*` is outside this issue's ownership. The environment knob avoids adding persistent configuration that could silently make a DHCP server trusted.
