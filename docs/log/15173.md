# #15173 — raw `show firewall` misstated term matches and termination (B18-02)

- **Timestamp**: 2026-10-19
- **Issue**: B18-02 — the default raw-config `show firewall` view on all
  three surfaces (local CLI, gRPC ShowText, REST show-text) dropped
  authored term fields and printed every empty-`Action` term as a
  terminating `accept`. A narrow discard (`tcp` except port 22, discard)
  read as "discard all TCP" because `destination-port-except` was never
  rendered, and an authored `then next term` fall-through (or a
  `then count` + `next term` term) read as an accept.
- **Base at filing/validation**: `origin/master` `27b8cba22d`; re-anchored
  at this lane's base `e487b1ee7c` — all four cited sites were present
  (`pkg/cli/cli_show_security_filters.go` x2, `pkg/grpcapi/server_show_firewall.go`
  x2, `pkg/api/show_text.go`).

## Fix

One shared raw term renderer, `pkg/firewallshow` (new), consumed by all
three surfaces:

- `WriteTerm` emits every authored `FirewallFilterTerm` field: dscp,
  protocol, source/destination addresses, prefix-lists (with `except`),
  source/destination ports, **source/destination-port-except**,
  icmp-type/code, **tcp-flags**, **is-fragment**, **flexible-match-range**,
  routing-instance, forwarding-class, loss-priority, dscp-rewrite (with
  the #7422 NOT-INSTALLED annotation, moved verbatim into
  `firewallshow.DSCPRewriteLine`), log, **syslog**, count, **policer**,
  and the terminating disposition.
- Termination is rendered honestly, mirroring the effective renderer's
  #14632/#10012 predicate: authored `next term` with no action and no
  routing-instance → `then next term`; modifier-only (empty action, no
  bit) → `then accept` (implicit accept, terminates); routing-instance
  terminates on its own line with no phantom accept; a contradictory
  `next term` beside a terminating action/routing-instance terminates and
  discloses `then next term (ignored — contradictory with terminating
  action)`; `then reject <type>` renders the message type.
- `WriteAllFilters` + `SortedFilterNames` give the all-filters view one
  sorted, nil-safe, suppressed-member-clone-hidden (#11589) name set.
  REST (`pkg/api/show_text.go` `firewall` topic) now calls
  `WriteAllFilters` and is byte-equal to the gRPC all-filters view (modulo
  gRPC-only hit-count/policer-status lines, which stay with the caller as
  dataplane state). CLI keeps its existing `(family %s)` heading and
  counter logic; only the term blocks delegate. The old REST-only
  capitalised `From:`/`Then:` format is replaced by the shared format —
  deliberate, mandated by the byte-equality acceptance.

NOT changed: the effective/compiled view (`show firewall effective`,
`dpuserspace.RenderFirewallFilterSnapshot`), counter/policer-status
surfacing, config compilation, and any dataplane behaviour. This is a
read-only rendering fix; no fail-open/closed enforcement direction moves.

## Risk

Operator-visible output delta only: raw `show firewall` gains the
previously hidden lines listed above and REST adopts the shared format.

see corrected text — that correction is the fix.
