# #14650: SteeringRowOwners action-blind PASS_TO_KERNEL overwrite + retire_workers coordinator wipe

## Re-read at origin/master 51d355c1d8 (rebased to 08f11138a5)

Issue body is the spec (validated-by:research, D1-03). Both arms verified in code:

- Row identity is the 40-byte shim key (`session_map_row`, bpf_map/mod.rs) — `routing_domain` and `discriminator` are dropped, so two distinct `SessionKey`s alias to one BPF row.
- `SteeringRowOwners` stored `(SessionKey, Claim)` with NO action byte. `write_and_claim` ran `write()?` (`BPF_ANY`) unconditionally; `release_locked` deleted only when outcome != `Remaining`. So a `PASS_TO_KERNEL` (2) publish overwrites a shared `REDIRECT` (1) row, and when the PASS owner releases, the surviving REDIRECT owner is left at 2 permanently (shim `cpumap_or_pass`, #9517/#304).
- `publish_session_map_entry_for_session_with_conntrack` publishes both actions for one entry (PASS forward + REDIRECT reverse-wire), proving mixed-action rows are designed-in.
- `retire_workers()` did `mem::take` on every rows+holdings shard, wiping `coordinator:true` claims #9560 round 3 added so coordinator rows survive, while `sync_session` runs without the `ServerState` mutex (#7209).

Controls staying green: all `*_9560` cells (43) and `*_9517` cells (7).
