# #12166 — withhold bulk ack on transient session-install failures

- **Timestamp**: 2026-10-08 (`fix/12166-bulk-ack`)
- **Stack**: `fix/12160-takeover-inventory` at `143753df17b14ee6e40df47c77558e0ccd93191c` (userspace: gate takeover until inventory replay completes).

## Why

The receive path added session keys to the authoritative bulk inventory before applying them. A transient helper transport failure could therefore leave rows missing while BulkEnd reconciled the incomplete snapshot, sent BulkAck, marked the bulk complete and released the HA hold. A later successful install cleared the helper warning but did not repair those missing rows. Semantic helper refusals remain an intentional-ACK path.

## What

- Track transient install failures per v4/v6 session for the active bulk, independently of the received-key set. A later successful install or semantic refusal clears only that key's marker; an unrelated successful install cannot erase other failures.
- Before stale reconciliation, BulkEnd now checks the failure sets. Any remaining transport failure withholds BulkAck and the completion/hold-release callbacks, skips reconciliation, and keeps the receive window open for the sender's existing bounded authoritative bulk-prime retry.
- Rebased the gate onto #12160's accepted-window serial and generation-keyed inventory contract. Failed windows do not enter reconciliation or discharge a pending inventory generation; successful retry retains the existing generation-checked completion path.
- Documented the receive behavior in `pkg/cluster/README.md`.
