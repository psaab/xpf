# #16594: interface `mtu` is a Junos media MTU but was applied verbatim as L3

- **Timestamp**: 2026-10-25
- **Issue:** `[edit interfaces <if>] mtu` is a Junos *media* MTU (GE
  default 1514 = IP protocol MTU 1500; the value counts the 14-byte
  Ethernet header, +4 per 802.1Q tag). xpf compiled it verbatim into
  `InterfaceConfig.MTU` and every writer — `planPhysDesired` →
  `LinkSetMTU`, networkd `MTUBytes=`, fabric/bond owners — programmed
  it as the Linux L3 MTU, giving a 14-byte (18 tagged) larger IP MTU
  than a Junos peer with the same configured value. DF packets in
  (N−14, N] toward such a peer drop as giants with no PTB. The
  deviation was undocumented; the userspace RX advisory already
  treated the value as an L3 frame budget inconsistently.
- **Fix (translate, the acceptance's first arm):** `compileInterfaces`
  — the single construction site for `InterfaceConfig` — now calls
  `translateInterfaceMediaMTU16594` (`pkg/config/media_mtu_16594.go`)
  after units/tagging/tunnel are final and before publishing:
  `ifc.MTU = media − 14` untagged, `− 18` when `vlan-tagging` or
  `flexible-vlan-tagging` is enabled (one admitted tag). The compiled
  field is therefore always the L3 value to programme, so the
  dataplane planner, networkd models, fabric floor, tunnel defaults
  and the strict gates (#9837 tagged-child, #13936 IPv6 floor,
  #16244 userspace budget) all judge the same value with no per-site
  conversion. `mtu 1514` yields netdev 1500 untagged / 1496 tagged.
  `family inet/inet6 mtu` (unit.MTU) is a protocol MTU and is never
  translated. Unset stays unset (1500 materialised downstream as
  before); a media value at/below the header size clamps to L3 1
  instead of collapsing into the 0 "unset" sentinel. Tunnel/loopback
  classes and `fab*`/`reth*`/`irb*` devices have no Ethernet media
  on the named device and pass through; their physical parents
  translate on their own stanzas. Aggregated Ethernet was originally
  exempted, but #17719 corrects it to use the Ethernet translation.
- **Not changed:** the dataplane/networkd actuators — they keep
  applying the compiled value verbatim (translation happens once, at
  compile; hand-built configs are unaffected). The #9727/#16244 frame
  budget itself stays netdev-L3. Default configs (no `mtu` leaf) are
  bit-identical.
- **Migration note:** a config that previously wrote `mtu 1500`
  meaning L3 1500 must now write `mtu 1514` (the Junos spelling of the
  same intent); `mtu 1500` now programmes 1486, matching Junos.
- **File(s)**: `pkg/config/media_mtu_16594.go` (new),
  `pkg/config/compiler_interfaces.go`, `pkg/config/types_interfaces.go`,
  `pkg/config/schema_interfaces.go` (leaf help: media vs protocol),
  `pkg/config/compiler_validate_strict_userspace_mtu_16244.go`
  (#16244 text names the translation),
  `pkg/config/media_mtu_16594_test.go` (new),
  `pkg/dataplane/media_mtu_16594_test.go` (new),
  `pkg/config/compiler_validate_strict_vlan_mtu_9837_test.go`,
  `pkg/config/compiler_validate_strict_userspace_mtu_16244_test.go`
  (authored fixtures re-spelled to the same L3 intents),
  `docs/config-schema.md`, `docs/feature-gaps.md`, `docs/log/16594.md`.
- **Validation**: new cells pin 1514→1500 untagged, 1514→1496
  tagged/flexible, family untranslated, jumbo 9014→9000 / 9018→9000,
  hierarchical+packed spellings, unset, tiny-clamp, exempt devices,
  and the #16244/#9837/#13936 gates judging the translated value;
  dataplane cells pin `planPhysDesired` and the networkd model
  carrying 1500/1496/1400 through the real compiler, plus a
  no-retranslation control. Existing MTU-expectation fixtures that
  asserted the old verbatim compile (9000/1500/1400 authored values)
  were updated to the authored media spelling of the same L3 intent.
  Pre-existing failure at base, unchanged: 
  `TestIPv6UnitMTULowReferencedSiblingRejected13936` (the #15034 gate
  fires first on current master; verified in a clean base worktree).
- **Residuals**: no live Junos-peer packet test (the mapping is pinned
  at compile/plan/model level); QinQ double-tag media overhead is not
  modelled beyond the single admitted tag; `show interfaces` protocol
  MTU display reads the same compiled/netdev values and inherits the
  correction without a separate change.
