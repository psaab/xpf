# #14444 — DR18-H9 `mergeNodes` container branch ignores `groupReplace`/range on block/block

## Mechanism
`isLeafListSchema` excludes `groupReplace` leaves, so a single-key group
block (`destination-port { 1000-2000; }`, NAT pool `address { ...; }`,
`community { ...; }`) fell through to the generic container child-merge
in `mergeNodes`, which adopts group members beside inline members — a
UNION even for ranges. The leaf path for the same statement drops the
group value (inline wins). Block/block hyphen-range pairs therefore
compiled to both ranges: positive range widened an accept term
(fail-open past a later discard), except range let discard-scoped
traffic escape. Leaf-path DR16-H1 cells were already correct and are
unchanged.

## Fix
- New `pkg/config/group_replace_block_14444.go`:
  - `groupReplaceLeafAt14444` — schema lookup via `schemaAtAncestorPath`
    + `resolveSchemaChild`, `groupReplace && children==nil`.
  - `isGroupReplacePortLeaf14444` — pointer-identity set built in
    `init()` from `schemaFirewall` (family inet/inet6 `from`
    destination/source-port + `-except`) and `schemaSecurity` NAT
    match `destination-port` (source + destination rule-sets). Not
    keyed on the bare keyword.
  - `groupReplaceBlockCarriesRange14444` — `leafListCarriesRange`
    ("to") plus hyphen-range regex `^\d+-\d+$` (the form the existing
    helper misses) plus multi-token child leaves.
  - `groupReplaceBlockHandled14444` — peer = `sameKeyedContainers9802`
    target or mixed-shape `leafListPeer`; ports union via
    `mergeLeafListInto` iff range-free on both sides, else override
    (drop group block); no peer → not handled (adoption unchanged).
- `pkg/config/ast_groups.go` `mergeNodes`: one call site immediately
  after the leaf-list-block branch, before the sibling-except scope
  and generic container merge.

No leaf-path, wildcard, `#9802`, `#12923`/`#12823`, or
`apply-groups-except` behaviour changed. Two-group fan-in works via
the standing-peer rule (G1 adopted, G2 decided against G1).
