# 14614 — SNMP link-trap monitor treated IF_OPER_UNKNOWN as down, silencing tunnel traps

- **Timestamp**: 2026-10-16
- **Issue**: #14614 (Y18-02, deep-review `claude-opus-5-5-review-full-firewall-hostile-001.md`)

## Defect

Two "operationally up" predicates classified the same `LinkAttrs`
differently inside `pkg/daemon`:

- the SNMP link-trap path — streamed netlink events
  (`daemon_flow.go` `runLinkStateSubscription`) and the boot-seed /
  post-ENOBUFS catch-up (`resyncLinkState`) — used
  `attrs.OperState == netlink.OperUp` only;
- `buildSNMPIfData` (ifTable `ifOperStatus`, `daemon_snmp_reconcile.go`)
  used `OperUp || OperUnknown`.

Tunnel devices (xfrm/gre/wg/ip6tnl) report `IF_OPER_UNKNOWN` when up.
So a seeded UNKNOWN tunnel was recorded down at boot and its later
DOWN/return transitions were no-changes (no linkDown/linkUp ever), a
post-boot-created UNKNOWN tunnel emitted a false `linkDown` that was
never cleared, and the trap contradicted ifTable, which read the same
interface as up. Tunnel up/down — including the GRE keepalive
down-action — was silent to trap receivers; forwarding unaffected.
Symmetrically, the ifTable rule reported an admin-down UNKNOWN link
(no `IFF_UP`) as up.

## Fix

One shared predicate, `linkOperUp` in `daemon_flow.go`, delegating to
the existing `cluster.LinkAttrsUp` (`OperUp`, or `OperUnknown` only
while admin-up via `IFF_UP`; everything else down — the same predicate
VIP readiness already uses). All three call sites classify through it:
stream, resync, and `buildSNMPIfData`. No shim or second convention:
the divergent inline predicates are deleted.

Side effect, deliberate: an admin-down UNKNOWN link now reads down in
ifTable (was: up), matching its trap classification and the RFC 2863
contract that a trap's `ifOperStatus` agree with ifTable.

## Regression (RED/GREEN)

`pkg/daemon/daemon_linkstate_operunknown_14614_test.go`:

- `TestSNMPOperClassificationAgrees14614` — for 7 oper/flag
  combinations, asserts the trap path (via `resyncLinkState`) and
  `buildSNMPIfData` classify identical attrs the same way, and to the
  expected value.
- `TestMonitorLinkStateOperUnknownTunnel14614` — decisive sequence: a
  seeded UNKNOWN+IFF_UP tunnel going DOWN emits exactly one linkDown
  and returning to UNKNOWN+IFF_UP exactly one linkUp; a new
  UNKNOWN+IFF_UP tunnel emits linkUp, never linkDown.

RED on `origin/master` (fix stashed): trap path classified
UNKNOWN+IFF_UP as `up=false`, ifTable reported admin-down UNKNOWN as
`OperStatus=1`, and the monitor emitted only the false
`{10 gr-0-0-1 false}`. GREEN with the fix; `TestMonitorLinkState*` /
`TestBuildSNMPIfData*` controls still pass; `go vet ./pkg/daemon/`
clean, `gofmt` clean.

## Risk

Only the SNMP monitoring plane changes. Interfaces reporting
`OperUp`/`OperDown` are classified exactly as before. The one behavior
delta beyond tunnel traps is the ifTable correction above for
admin-down UNKNOWN links.
