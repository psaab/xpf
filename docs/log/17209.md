# Issue #17209 — superseded REST auth paths deleted, regression cells retargeted at the production composition

- **Issue:** `authMiddleware`, `authCheck`, and the legacy throttle helpers (`recordFailure`/`recordSuccess`/`locked` plus the bucket accessors they alone used) were production-dead, yet carried the #4157/#4162/#5636/#16072 regression cells and still received fixes (#12182 R1). Two doc comments claimed a sharing with the live middleware that does not exist. A no-auth mutant of the production middleware demonstrated that the named cells could not fail for the path production ships.
- **STEP-0 (defect live on origin/master `c4e12aafc3`):** `/usr/lib/go-1.26/bin/go run golang.org/x/tools/cmd/deadcode@v0.38.0 -test=false ./cmd/xpfd ./cmd/cli` reports `pkg/api/auth.go:253 authMiddleware`, `auth.go:318 authCheck`, `auth_throttle_10825.go:148 locked`, `:534 recordFailure`, `:553 recordSuccess`, `:564/:579/:594 bucket helpers`, `:609 sweepIfFullLocked` (go1.27 panics in the pinned SSA builder, hence the go1.26 toolchain). `setClockForTest` was likewise unreachable even with `-test`.

## What

1. Deleted `authMiddleware` and `authCheck` from `pkg/api/auth.go`; deleted `recordFailure`, `recordSuccess`, `locked`, `accountBucketLocked`, `globalAccountBucketLocked`, `sourceBucketLocked`, `sweepIfFullLocked`, and `setClockForTest` from `pkg/api/auth_throttle_10825.go` (the bucket accessors' only callers were the legacy record path; `reserve` builds buckets inline). Removed the now-stale `authFailureTracker.setClockForTest` row from `docs/deadcode-allowlist.txt`.
2. Added `pkg/api/auth_handler_helper_test.go`: `productionAuthHandler`/`productionAuthHandlerOnly` build the production composition — a `Server` seeded with the config behind `dynamicAuthMiddleware` over a following `authSlot` (bind classification on the slot, `MetricsRequireAuth` folded into `Server.metricsGate` as `NewServer` does) — and `chargeFailures`/`clearPairSuccess`/`chargeAttempted` charge fixtures through `reserve`+`complete`, so fixtures only reach states production can reach; `probePairLocked` is the test-only lockout observer.
3. Retargeted all 14 handler call sites (auth_test, #4157, #5636 ×2, #16729, throttle 10825 ×5, #4162, #16072 ×3) and every legacy throttle call site (`auth_throttle_10825_test.go`, `auth_throttle_12182_test.go`, `auth_throttle_14711_test.go`) to the new helpers; the one `authCheck` test call now asserts on `authCheckCredential` directly. The #12182 saturation case is renamed in its comment to the production charge path; its locked-table fixture now builds chargeLocked's exact post-lock bucket shape directly (reserve/complete cannot drive 20 charges past a pair lockout at 5), and the fallback-charging cell seeds its two-failure pre-threshold state with an explicitly named, single-fixture seed helper.
4. Fixed the false sharing claims: `dynamicAuthMiddleware`'s doc, `authCheckCredential`'s doc, the throttle package comment, and every other `authMiddleware`/`authCheck` mention in production comments, `pkg/api/README.md`, and `docs/architecture.md` now name the real production gate.
5. #16729 (closed) is not re-opened; its test file header now names the production auth handler instead of the dead wrapper.

## Risk

Test-only blast radius for production behaviour: no production logic changed (deleted functions had no production caller, proved by deadcode), so runtime auth semantics, constant-time compares, and reserve/complete throttle accounting are untouched. The risk is fixture fidelity: `chargeFailures` reaches states only via production admission (failures during a live lockout are dropped, as in production), so two fixtures that relied on the reservation-free legacy path (the #12182 saturation fill and the fallback source totals) were rebuilt with the state justified in their comments; both cells pass and the mutant above proves the retargeted security-named cells now guard the shipping middleware.
