# 17797 — Adopt pre-installed system syslog clients by destination

- **Timestamp**: 2026-10-26
- **Action**: Replaced `systemSyslogSeedCacheIfEmpty`'s host-outer/client-inner assignment (which stored the last installed client under every host key) with per-host matching against each installed client's `RemoteAddr` and `SourceAddr`. Each configured host now adopts only a client with its own `net.JoinHostPort(address, effectivePort)` and source address. Nil and foreign-destination clients are not seeded. The cache remains empty-fingerprint on adoption; no construction or reuse policy changed.
- **Why**: The old inner loop mis-associated every pre-installed system-syslog client with every configured host, so the first seed could not represent per-host ownership.
- **What**: Added regression coverage for two distinct hosts installed in reverse order, exact per-host pointer adoption, empty seeded fingerprints, single-host adoption, foreign (wrong-port and wrong-source) clients, and duplicate host keys.
- **File(s)**: `pkg/daemon/daemon_system.go`, `pkg/daemon/syslog_system_seed_17797_test.go` (new), `docs/log/17797.md`

  - Independent clean-base RED at `870fd6e`: copied only the regression test into an unchanged detached worktree and ran the same command; it failed on the same per-host and foreign-client assertions.
