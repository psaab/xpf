# 10291 — Reject unimplemented source-NAT pool leaves

## Boundary

The source-NAT pool compiler handled five modeled leaves (`address`, `port`,
`persistent-nat`, `port-overloading-factor`, and `routing-instance`) but had no
default switch arm. Unsupported Junos leaves and misspellings therefore
committed successfully and were silently ignored.

## Fix

- Preserve every unmodeled source-pool child keyword in a compile-time
  diagnostic field on `NATPool`.
- Add a strict uniform gate that names the first unsupported pool leaf and
  rejects it with `#10291`; the tolerant load/peer-sync path downgrades the
  same error to a warning.
- Keep the diagnostic field out of JSON and dataplane serialization, and add
  RED-on-revert coverage for `overflow-pool`, `host-address-base`,
  `address-pooling`, and a misspelled `adress` leaf plus a control covering all
  five modeled leaves.

## RED then GREEN evidence

- Before the implementation, `go test ./pkg/config -run
  'TestSourceNATPool(UnsupportedLeavesRejected|SupportedLeavesCompileUnchanged)10291'
  -count=1 -v` failed all four unsupported-leaf cells because each committed
  cleanly.
- After the implementation, the same command passed: 5 tests/cells passed,
  0 failed.

## Verification

- Focused source-NAT regression set:
  `go test ./pkg/config -run 'Test(SourceNAT|SNAT|NATPool)' -count=1` —
  passed, 0 failed.
- Full NAT/config suites are run by the parent integration lane.
