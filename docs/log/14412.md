# Issue #14412 — Packed tails invisible to schema walker + #10707: misplaced / case-variant credential tokens silently dropped (DR13-H5)

## Why

At `83f69bf31` (campaign base `origin/master`), two walkers ignored
packed tails:

- `pkg/config/schema_walk.go`: the container branch consumed only the
  declared identity span and otherwise ignored leftover `Keys` unless the
  schema opted into `packedTail` (#6821). The #8437 fused-statement check
  fires only when a tail token names a SIBLING of the node in the
  enclosing container.
- `pkg/config/compiler_openworld_10707.go`: `warnUnknownRoutingLeaves10707`
  recursed only over `node.Children`; a packed node has no Children.

So a credential leaf packed after a non-scoped head, or spelled
case-variant, was consumed by no reader and reported by no gate:

```text
protocols { ospf { area 0.0.0.0 {
  interface ge-0/0/0.0 passive authentication-key SECRET; } } }
protocols { isis { net 49.0001.0000.0000.0001.00;
  interface ge-0/0/0.0 Authentication-Key SECRET authentication-type md5; } }
```

The first misplaces `authentication-key` at OSPF interface level (the
declared child is the `authentication` container, so it names neither a
child nor an area sibling); the second names nothing at any level. Both
committed clean, with no #10707 warning, and the OSPF/IS-IS adjacency
formed unauthenticated while `show configuration` displayed the
credential the operator wrote. The BGP neighbor `Authentication-Key`
packed spelling behaves the same. CHILD-node forms were already warned
by #10707; only the packed-tail form was silent.

## What

- `pkg/config/packed_tail_credential_14412.go` (new): shared predicate.
  `isPackedTailCredentialToken14412` matches case-insensitively against
  the distinctive credential keywords already known to the existing
  secret resolutions (`secretLeafKeywords` in `secret.go` plus the
  distinctive `secretIndices` keywords in `ast_redact.go`) — no new
  credential list. Generic dual-use keywords (`key`, `password`,
  `secret`, `community`) are excluded: without ancestor context they do
  not prove "credential" and gating on them would false-reject ordinary
  value tokens. `packedTailCredential14412` returns the first such token
  packed past a node's identity span whose exact-case form does not
  resolve as a child of the descendent schema (validly placed packed
  credentials stay silent) and that was not authored as a quoted or
  bracketed value (#9635).
- `pkg/config/schema_walk.go`: in the container branch, after the
  packed-tail walk is assembled, a non-`packedTail` node with leftover
  Keys now strict-rejects naming the dropped token and the redacted
  path (`redactSecretPath` — the keyword only, never its value), with
  the (#14412) tag. `packedTail` containers are exempt: a reader
  consumes their tails.
- `pkg/config/compiler_openworld_10707.go`: `walkChildren` applies the
  same predicate after `consumeNodeKeys` and emits the standard #10707
  warning naming the token, so the tolerant load/peer-sync paths surface
  it as a warning where the strict gate rejects.
- New regression `pkg/config/schema_walk_packed_tail_credential_dr13h5_test.go`:
  five packed fixtures (OSPF interface misplaced after `passive`, OSPF
  area-level misplaced, OSPF `simple-password` misplaced, IS-IS
  case-variant, BGP neighbor case-variant) asserted on both channels
  (strict `SchemaValidate` reject naming the token without echoing the
  secret; compile never silent — #10707 warning or token-naming error),
  CHILD-node controls keeping their existing #10707 warnings, valid
  packed tails (IS-IS validly packed key, OSPF packed `authentication
  md5 … key …` chain, non-credential packed tail) staying accepted with
  no credential warning, and a quoted-value (#9635) control.

## Validation

- RED on base `83f69bf31`: all five strict fixtures accepted by
  `SchemaValidate`; all five compile fixtures silent (BGP cell failed on
  an unrelated missing-AS error, fixed in the fixture); the lone valid
  control failure was the pre-existing #8437 sibling rule on a
  multi-statement IS-IS tail, so that control now authors the validly
  packed key alone.
- GREEN after the fix: `go test ./pkg/config/ -run TestPackedTailCredential`
  passes (strict, warn, child-control, valid-control, quoted-value).
- `go vet ./pkg/config/` and `gofmt` clean on the touched files.
- Collateral: `TestPackedOptInHoldsForEveryLeafPair8768` fails on the
  fixed tree with container-coverage complaints (`interfaces/*/unit/tunnel`,
  `interfaces/*/tunnel` `clear-dont-fragment-bit`) unrelated to credentials
  or routing; base attribution could not be completed because the test did
  not finish within a 90s bound on a pristine `origin/master` worktree
  (recorded as uncovered risk, not as confirmed pre-existing). The full
  `pkg/config` suite likewise did not complete within a 240s bound in
  this environment; its result is unobserved and left for the main
  agent's verification pass.

## Risk

- Behaviour delta: strict commit now rejects a misplaced or case-variant
  credential keyword packed onto a routing container line, naming the
  token; tolerant load warns via #10707 instead of dropping it silently.
  No previously-working spelling changes: exact-case credentials that
  resolve as children of their stanza, `packedTail` containers, and
  quoted/bracketed value tokens are untouched, and unmodelled
  non-credential packed knobs keep their existing warn-only behaviour.
