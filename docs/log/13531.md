# Issue #13531 — compile chained BGP and OSPFv3 protocol forms

## Why

Flat-set commands can chain one protocol setting after another. `SetPath`
represents the chain as nested nodes, but the compiler inspected only direct
children: a BGP `group` chained after `local-as` was never visited, and an
OSPFv3 `area` chained after `router-id` was omitted. Both loaded without an
error, silently removing configured peers or areas.

## What

The BGP and OSPFv3 compiler paths now flatten schema-declared chained siblings
and use the same expanded protocol children for both scalar leaves and named
containers. Packed group/area bodies are expanded through their schemas before
compiling neighbors, areas, and interfaces. Regression tests compare block,
flat chained, split-flat, and mixed block/flat configurations.

## Validation

- **RED on reported base `3c46632e3`:** the chained flat BGP command compiled
  with 0 neighbors and the chained flat OSPFv3 command compiled with 0 areas.
- **GREEN:** the focused chain, mixed-form, spelling-differential, and
  multi-leaf protocol tests pass with
  `go test ./pkg/config -run
  '^(TestBGPChainedGroupMatchesBlock13531|TestOSPFv3ChainedAreaMatchesBlock13531|TestSchemaSpellingDifferentialGate|TestProtocolsMultiLeaf.*)$'
  -count=1 -parallel=1`.
- `go test ./pkg/config -count=1 -parallel=1` — PASS.
- `go build ./...` — PASS.
- `gofmt -l` on the four changed Go files — no output.

## Risk

No wire or schema changes. The change affects tolerant compilation of chained
BGP and OSPFv3 configuration forms; hierarchical blocks and split flat commands
remain covered as equivalence controls.
