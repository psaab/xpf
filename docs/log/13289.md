# Issue #13289: surface WireGuard uncovered-forward counters

## Why

The eight #10597 `WG_UNCOVERED_*` process-global atomics counted enqueues,
queue-pressure and worker-lifecycle drops, malformed/stale/non-local packets,
and poison recoveries, but had no production readers. Operators therefore
could not see when cross-worker WireGuard forwarding was shedding packets.

## What

Added `Coordinator` read accessors, additive/defaulted `ProcessStatus` fields,
status refresh wiring, Go status decoding, and Prometheus series
`xpf_wg_uncovered_packets_total{outcome}` plus
`xpf_wg_uncovered_queue_poison_recoveries_total`. Added Rust source-wiring and
Go metric-emission regression tests.

## Validation

`wg_uncovered_counters_are_wired_into_process_status` failed on pristine
`f59c739af` with all eight accessor/status-field wiring triples absent, then
`status_wiring_tests` passed before rebase (3 tests); the full Rust suite
passed (7,949 passed, 8 ignored), and the full Go package command passed.
After rebasing onto `0de5182f4`, `status_wiring_tests` passed (4 tests),
`wire_invariant_default_specimens` passed, the focused WG/HA Go metrics and
wire tests passed, and `go test ./pkg/api -count=1` passed. The combined full
Go command on the rebased tree still fails in dataplane/userspace contract,
Junos-host scope, snapshot-shape, and quarantine tests; the focused WG wire
test passes.

## Risk

The additive status keys default to zero for older helpers. Counter values are
process-global monotonic atomics and use relaxed loads; no packet-path work was
added.
