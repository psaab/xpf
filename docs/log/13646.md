# #13646 — bound missing-neighbor probes and preserve throttle windows

- **Issue**: #13646 — prevent unbounded per-packet raw-socket probes and throttle resets on the MissingNeighbor path.
- **Branch**: `fix/13646-campaign`
- **Worktree**: `/var/worktrees/campaign-zero/wt-13646`

## Why

The MissingNeighbor poll path used `pending_neigh` membership to suppress
repeat probes for native traffic, but capacity-refused and NAT64 packets are
not retained there. Those packets could therefore clone an interface name and
perform a raw-socket probe on every RX descriptor. Tunnel-only throttling did
not cover those paths, and both throttle insertion sites cleared every active
window at capacity, allowing a key scan to reset unrelated probe limits.

## What

- Apply the per-(ifindex, next-hop) throttle to all MissingNeighbor probes,
  including capacity-refused native packets and NAT64 packets.
- Borrow the interface name in the poll loop rather than cloning a `String`.
- On bounded-map overflow, discard expired entries first, otherwise only the
  oldest entry; preserve the rest of the live throttle windows.
- Add focused throttle behavior and poll-path source regression tests.

## Risk

The 100 ms throttle intentionally suppresses repeat probe attempts for the same
unresolved key during the window, including after a failed raw-socket syscall.
Throttling remains worker-local, as before; no cross-worker coordination was
added.
