# Issue #14316 — NAT64 embedded ICMP policy gate: V4ToV6 dead PROTO_ICMP arm + V6ToV4 translated type/code

Post-#14123 residual in the NAT64 flowless ICMP-error arm. Two legs:

1. **V4ToV6 `policy_src_ip: None`.** `try_translate_nat64_icmp_error`
   returned `policy_src_ip: None` on the V4→V6 arm, so the queued gate's
   #14123 `Some(V4) if dst.is_ipv6() => PROTO_ICMP` arm could never fire
   for this producer. The gate fell back to the translated frame's
   ICMPv6 protocol and Pref64-mapped source, so an IPv4
   `source-address 198.51.100.254/32 protocol icmp icmp-type 11` deny
   never matched the arriving ICMPv4 Time-Exceeded.

2. **V6ToV4 translated type/code.** `enforce_queued_embedded_icmp_policy`
   read `(type, code)` via `policy_packet_icmp(queued_frame, …)` from the
   already-translated frame while forcing `PROTO_ICMPV6`. RFC 7915 §5.2
   rewrites the numbers (ICMPv6 DestUnreach 1/0 → ICMPv4 3/1; Time
   Exceeded 3/0 → 11/0), so an `icmpv6 icmp-type 3` term compared against
   11 (miss) and a translated DestUnreach spuriously matched type 3.

## Change

- `nat64_icmp_error.rs`: both arms capture the original ICMP type/code
  via `policy_packet_icmp(packet_frame, meta)` BEFORE translation and
  carry it as `policy_icmp`; V4→V6 also carries
  `policy_src_ip: Some(IpAddr::V4(outer_src_v4))` (the same `router_v4`
  bytes mapped into the Pref64 source). Unreadable original type/code
  refunds the F-077 token and drops (`Dropped`) — fail-closed, never
  judging the translated numbers. The wire frames are unchanged.
- `embedded_icmp.rs`: `EmbeddedIcmpReversal::Queued` gains
  `policy_icmp: Option<(u8, u8)>`; the same-family arm and the queue
  helper carry `None` (byte-identical). The queued gate evaluates
  `policy_icmp.or_else(|| policy_packet_icmp(queued_frame, policy_meta))`
  exactly as the issue's fix direction prescribes. The policy-deny
  RT_FLOW event keeps the queued (wire) identity (`wire_flow` clone);
  only the evaluation judges the original sender/type — preserving the
  #9948 event contract (`64:ff9b::ac10:5001` source) that the
  pre-existing zone-policy cells pin.
- `poll_descriptor/mod.rs`: both queued call sites destructure and
  forward `policy_icmp`.

Note on the issue's V4ToV6 acceptance tuple: with the carried
`(V4 src, V6 dst)`, `rule_l3_matches` returns `false` (its `_` arm —
(V4,V6) "never matches — fail closed", NAT46 unsupported). The deny in
the regression therefore lands via evaluation ordering: deny rule
first, then permit-any, default deny — the carried identity makes the
gate judge the original v4 sender/protocol/type (so a future
(V4,V6)-aware match arm, or a same-family re-expression, sees the true
tuple) and the error is refused rather than admitted under the
translated ICMPv6 identity. No `rule_l3_matches` arm was added: that
would change policy semantics for every (V4,V6) tuple, beyond this
issue's prescribed fix.

The three pre-existing V6ToV4 #14123 cells
(`poll_descriptor_nat64_v6_to_v4_policy_judges_original_sender_14123`,
budget refund, output-filter) pass unchanged: their `icmpv6`
applications are unconstrained on type, so carrying `(3,0)` is inert
there.

## Regression

- `pol14316_v4tov6_icmp_type_deny_refuses`: ICMPv4 Time-Exceeded from
  `198.51.100.254` quoting the NAT64 reverse session, `wan -> lan`
  deny(`198.51.100.254/32`, `protocol icmp icmp-type 11`) then
  permit-any. Must not queue.
- `pol14316_v6tov4_icmpv6_type_uses_original`: ICMPv6 Time Exceeded
  (3/0) must hit the `icmpv6 icmp-type 3` deny; ICMPv6 Destination
  Unreachable (1/0) must hit the `icmp-type 1` permit and not the
  type-3 deny.

Both drive the real flowless poll path (`stage_nat64_icmp_error` →
queue → `enforce_queued_embedded_icmp_policy`), Time-Exceeded is not
PMTUD so no RELATED bypass applies.

## Risk

- Policy-visible identity for V4→V6 NAT64 errors changes from the
  Pref64-mapped v6 source / ICMPv6 protocol to the original v4 sender /
  ICMP / original type-code. An operator rule that permitted these
  errors only via the mapped source will now see the v4 tuple (which
  `rule_l3_matches` currently fail-closes); non-PMTUD errors without a
  matching permit still hit default deny. Fail-closed posture is
  preserved: unreadable original type/code drops with a budget refund,
  and the transmitted wire frame is byte-identical.
