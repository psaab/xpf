# #9502: the #5286 wiring cell gated on a 50 ms wall-clock budget and blamed the wiring under load

- **Timestamp**: 2026-09-11T01:20Z
- **Action**:
  - Split the entangled cell.
  - Moved the wiring and healthy verdicts onto a budget that load cannot expire.
  - Added a deterministic stall control.
- **File(s)**: `cmd/xpfd/upgrade_helper_health_5286_test.go`

## Mechanism

`TestBuildUpgradeSystem_WiresHelperProbe_5286` asserted two properties inside one `HelperHealthy(target, 50ms)` call:
- (a) the production assembly consults the control-socket status seam;
- (b) it fails closed on an up-but-not-forwarding helper.

`HelperHealthProbe` bounds every step by one context deadline, and `checkHelperReady` calls `boundByDeadline` before the status query, failing fast with no remaining budget. So when 50 ms of wall time passed before the first evaluation, which happens under load, the status seam was never called. The cell then fired "NewSystemWithHelperHealth is not wired", a false claim about correct wiring. The sibling `ArmedForwardingTarget_Healthy` had the same shape at 200 ms.

**A premise in the issue body did not hold.** Its first option said a generous budget "does not slow the test", because the gate fails closed on the fake's `forwarding == false` answer. It does not: a not-ready evaluation is never a definitive exit. The loop records `last`, waits `PollInterval` (500 ms by default), and retries until the deadline. A multi-second budget on the not-forwarding case would cost that whole budget on every run. So this change takes the issue's second option and splits the cell.

## Change

- **`WiresHelperProbe_5286`, wiring only.** The fake reports armed+forwarding on the target, and the budget is `wiringBudget9502 = 10s`. A wired probe returns nil after one evaluation (0.00 s measured), so the budget costs nothing when the code is right. The cell asserts the status seam was consulted and the verdict is healthy. The failure message now says a missed query at this budget is the wiring, not latency.
- **`FailsClosedWhenNotForwarding_5286` (new).** Not-forwarding fake with a 50 ms budget, asserting only `err != nil`. That is monotone under load: a starved probe also errors. When the query did run, the refusal must name "helper not forwarding".
- **`WiringAbsorbsAStall_9502` (new).** A unit-active fake stalls 150 ms, three times the old budget, before the first evaluation. The status query must still be consulted within `wiringBudget9502`. This is the committed, deterministic form of the issue's "run under synthetic load" control.
- **`ArmedForwardingTarget_Healthy`.** The budget moves from 200 ms to `wiringBudget9502`; it is a healthy path that returns immediately.
- **Helper.** `installProbeSeams9502` installs all four seams with `t.Cleanup`.

No docs change is needed beyond this log. The #5808 "deadline is authoritative" property is pinned at the probe level in `pkg/upgrade/helper_health_deadline_5808_test.go`, which is unchanged.
