#13690: retain the selected address index for address-only round-robin SNAT

`reserve_address_only_roundrobin` now records the absolute pool index of the
address chosen by its collision-probing loop rather than hardcoding index 0.
When a pool is re-seeded after configuration changes, `reseed_retained_from`
uses that index to decide whether a live reverse-identity token remains on a
retained address. The stale index could therefore silently discard the #5269
collision guard even while the flow continued forwarding.

Added IPv4 and IPv6 regression cases that allocate at nonzero indices and bind
the stored index to the selected translation. Both failed on the original
implementation (v4: index 0 selected address mismatch; v6: index 0 instead of
absolute index 3) and passed after the fix. The production change is limited to
the round-robin record; the persistent sibling already stores the chosen
`family_offset + rel`, and the synced reservation already receives the pool
index from `pool_index_of`.
