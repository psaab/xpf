# #17243 — consolidate screen profile builders (`build_screen_missing_profiles` / `build_screen_inert_profiles`)

- **Timestamp**: 2026-10-27
- **Defect (verbatim twins, STEP-0 verified live on origin/master `a60e77bda3`)**: in
  `userspace-dp/src/afxdp/forwarding_build/mod.rs`, `build_screen_missing_profiles`
  and `build_screen_inert_profiles` had identical bodies differing only in the
  source slice (`snapshot.screen_missing_profile_zones` vs
  `snapshot.screen_inert_profile_zones`) and their comments. The inert copy
  carried the stale #9425 comment claiming `alarm_without_drop` was read "only
  here, on the INERT set" — false since #16006 added the identical read to the
  missing copy and updated the wire doc (`protocol/security.rs:109-125`). A
  reader trusting that sentence would conclude the missing arm never carries
  audit mode and might "fix" it by removing the #16006 read.
- **Fix**: single shared `fn unresolved_profile_refs(rows: &[ScreenMissingProfileRef]) -> FxHashMap<String, UnresolvedProfileRef>`
  in `forwarding_build/mod.rs`, called by both public builders for their
  respective slices. The two maps stay separate (runtime WARN names the right
  cause; `Pass` = "in neither map") — only the builder body is consolidated.
  The helper's doc records the unified #9425/#16006 rule replacing the stale
  sentence: the audit modifier travels with the reference on BOTH sets wherever
  the profile is defined (inert, or defined-but-unresolved on the missing arm);
  Go leaves it `false` for a truly undefined profile, so verbatim forwarding
  cannot manufacture audit mode. Acceptance grep
  `grep -n 'Reading it only here' userspace-dp/src/afxdp/forwarding_build/mod.rs` → 0.
- **Exact-parity preservation**: the helper keeps the twins' precise semantics —
  skip empty zone, forward `profile`/`alarm_without_drop` verbatim, later
  duplicate-zone row wins (`FxHashMap::insert`), map type and call sites
  (`build_forwarding_state` assignments) unchanged. No wire, Go, or runtime
  consumer change.
- **Parity guard**: `screen_unresolved_profile_builders_are_in_parity_17243` in
  `forwarding_build/tests.rs` feeds the identical row sequence (audit true/false,
  an empty-zone row, a duplicate-zone pair) through both wire sets via
  `build_forwarding_state` and asserts (a) the two maps are equal, (b) the exact
  expected map (empty skipped, last-wins `p-a2`, verbatim flags), and (c) each arm
  leaves the other state map empty. It is red if the arms ever diverge again.
  Existing decode cells (`inert_screen_profiles_reach_the_forwarding_state_7888`,
  `undefined_screen_profiles_do_not_leak_into_the_inert_map_7888`,
  `inert_screen_profile_audit_flag_survives_the_decode_9425`,
  `undefined_screen_profile_never_carries_an_audit_flag_9425`,
  `unresolved_screen_profile_audit_flag_survives_the_decode_16006`) still cover
  the individual arms; their stale references to the old twin names in comments
  were left as historical RED-on-revert notes except where they named the removed
  body (none required changing — they reference the forwarding-state wiring, which
  is unchanged).
