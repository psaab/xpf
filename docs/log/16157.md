# #16157 — collectorDeps seam for xpfCollector

- **Timestamp**: 2026-10-24
- **Issue**: #16157
- **Why**: `xpfCollector` held a whole `*Server` (`srv *Server`), so every
  scrape helper reached through `c.srv` for exactly the state it read, and
  driving one metric family in a test meant fabricating (or mutating) a
  Server. The wide dependency also made the collector's real inputs
  invisible at its type.
- **What**:
  - New `pkg/api/metrics_collector_deps.go`: `collectorDeps` value holding
    only what the collector reads — live objects (`store`, `dp`,
    `fwdSampler`, `eventBuf`, `gc`, `dhcp`, `startTime`), the two REST
    conn-gate accessors as closures (they keep reading the atomically
    loaded `connGate` installed after the Server literal), and every
    optional daemon hook copied verbatim from the Server field of the same
    name (nil = family omitted, unchanged). `collectorDepsFromServer`
    snapshots it once at construction; the copied pointers preserve the
    old visibility (live config via `store.ActiveConfig`, live sampler /
    gate state via the pointees), matching the lifetime the `c.srv` reads
    already had. `activeConfig()` collapses the repeated
    `srv == nil || srv.store == nil` guards (deps is a value, never nil).
  - `xpfCollector.srv` replaced by `deps collectorDeps`; zero `c.srv`
    accesses remain under `pkg/api` (prose in the new file's doc comment
    aside). `newCollector` bridges via `collectorDepsFromServer`;
    `NewServer` wiring is untouched.
  - Behaviour preserved at the edges the old guards encoded: zero deps
    still emits the REST-conn series at 0, still omits hook families, and
    `emitDataplaneSafety` no longer dereferences a nil dp through
    `dataplane.Unwrap` (typed-nil pre-change panicked; plain nil now
    returns no samples — the deferred pre-gate emit previously recovered
    only via the #15086 lane).
  - Test literals that built `&xpfCollector{srv: &Server{...}}` now build
    `deps: collectorDeps{...}` directly; the #15086 panic-recovery fixture
    forces its panic through a panicking deps hook instead of a nil srv.
- **Tests**:
  - New decisive file `pkg/api/metrics_collector_deps_16157_test.go`:
    reflection pin that no `srv`/`*Server` field returns to `xpfCollector`,
    nil-server → zero deps + nil `activeConfig`, and `newCollector`
    bridging of store/startTime/hooks/conn-gate accessors (incl. the
    bare-server 0 counts).
  - Targeted: the three 16157 tests, `TestMetricsLaneCollectRecoversPanic15086`,
    descriptor-coverage / FwdStatus / policy-counter families — pass.
  - Full `go test ./pkg/api/ -count=1`: failure set byte-identical to
    pristine base (23 pre-existing failures, NAT config-keyword / zone
    fixtures unrelated to metrics wiring); `go vet ./pkg/api/` and
    `gofmt -l pkg/api/` clean.
- **Risk**: Low. No metric name, help, label, or value changes; the only
  timing change is the one-time deps snapshot at collector construction
  (before serving), which is the lifetime the old field reads assumed.
