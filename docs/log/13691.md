# #13691 — preserve incumbents when synced NAT replacement is refused

- **Timestamp**: 2026-10-15
- **Action**: Defer stale PAT and address-only incumbent eviction until the
  replacement tuple passes its admission checks.
- **File(s)**: `userspace-dp/src/nat/allocator.rs`,
  `userspace-dp/src/nat/tests_idle_lease_sync_8121.rs`.

## Admission before teardown

Both synced reservation paths used to retire a flow's incumbent record before
checking whether its replacement could be admitted. A later refusal could
therefore discard the still-live flow's reservation: PAT could release the old
bitmap bit before a conflicting-port or persistent-lease refusal, while the
address-only twin could remove its reverse-identity owner before rejecting a
PAT identity collision, capacity limit, or incompatible lease.

The PAT path now checks reverse-identity conflicts, effective tracked-flow
capacity, persistent lease compatibility/capacity, and bitmap availability
before eviction. It recognizes the incumbent's own plain-PAT bitmap bit so a
replacement on the same address slot and port remains admissible. Only after
those checks succeed does it perform the existing mode-correct teardown and
install the replacement. The address-only twin similarly completes its
collision, capacity, and lease checks before removing the old token. Existing
idempotent refreshes and successful replacement semantics are unchanged.

Regression tests exercise conflicting-port refusal, persistent-lease tuple
mismatch, PAT-vs-address-only reverse-identity collision, and successful
replacement for both reservation modes.
