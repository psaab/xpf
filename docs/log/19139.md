# #19139: vm-test-run.sh keeps a command's stdout and stderr in write order

- **Timestamp**: 2026-11-16
- **Action**: `scripts/vm-test-run.sh` runs the lane command with `exec 2>&1`
  on the runner (both the runner-user `su - runner -c` leg and the `--root`
  `bash -lc` leg), so the command's stdout and stderr leave the VM as one
  stream in write order. Before, `incus exec` carried them as two streams that
  the workstation merged in arrival order. In a full release suite this
  spliced cargo's `error: test failed, to rerun pass ...` (stderr) into the
  middle of libtest's `test X ... FAILED` (stdout) for two master cells
  (`session_id_node_discriminator_is_plumbed_from_the_snapshot_6311`,
  `vrf_session_identity_doc_claims_still_match_the_code`), and moved
  `Running <target>` lines away from their tests, so a target-keyed parser
  attributed the unit binary's failures to `src/bin/fairness-eval.rs`. New
  opt-out `--separate-stderr` keeps the two apart for a caller that parses
  stdout alone (their relative order is then not preserved). The script's own
  diagnostics still go to the workstation's stderr.
- **Action**: `scripts/vm-test-run-selftest.sh` (registered in
  `scripts/run-selftests.sh`; `make test-vm-test-run-lib`) drives the script
  under a mock `incus` whose transport holds the command's stdout until it
  exits and passes stderr straight through, the worst case of the defect.
  Cells:
  - control: with `--separate-stderr` the stderr line arrives ahead of the
    stdout written before it, so the mock really reorders;
  - order: by default the output is the write order byte for byte, for the
    user and root legs, with nothing on stderr;
  - `--separate-stderr` separation;
  - exit status in both modes;
  - mutation: the script with its `exec 2>&1` removed fails the order cell.
  - **File(s)**: `scripts/vm-test-run.sh`, `scripts/vm-test-run-selftest.sh`,
    `scripts/run-selftests.sh`, `Makefile`, `docs/testing.md`,
    `docs/log/19139.md`
