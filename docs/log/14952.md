# #14952 ConfigMode Complete price / operational-gate bypass — engineering history

Issue: psaab/xpf#14952 (`Complete` RPC With `ConfigMode: true` Bypasses
`PermConfig` and Operational `deny-commands` / `allow-commands`, Allowing
`PermView` Principals Denied `show configuration` to Enumerate the Active
Configuration). Source claim `D15-02` (gemini-4-argon), validator run
`tpzkKgAuZL`, consensus MATERIAL. Lane branch: `fix/14952-campaign`,
base `origin/master` b8f1ff7ac9.

## Defect (present at base)

`Complete` was priced flat at `PermView` (`authz_methods.go`) and listed
in `configModeMethods9633`, so `authorizeRPCCommand` exempted it from the
operational `*-commands` regexes (`authz_command_gate_7172.go:109-111`
returned nil, verbatim, for every config-mode method).
`authorizeRPCConfigMutation` never saw it either
(`configMutationLineFor` returns ok=false). A `PermView` principal whose
class denies `show configuration` (`deny-commands "^show configuration"`)
— a principal `ShowConfig` correctly refuses — could send
`Complete{ConfigMode:true, Line:"set security zones security-zone "}`
and enumerate the active configuration one Tab press at a time.

#14144/#14708 (both closed/merged) fixed the DATA SOURCE: the handler
filters live candidates by `*-configuration` / `*-commands`. The
residual this issue owns is the ADMISSION price and gate: the RPC was
still admitted at the view price with no operational verdict at all, so
an `allow-commands` allowlist that permits no config-mode completion
line still received schema candidates for a command the class may not
run, and flipping the `ConfigMode` bit cost a view-only principal
nothing. Fix direction (binding): price ConfigMode completion at
PermConfig and apply op-command deny rules.

## Fix

In `pkg/grpcapi`, interceptor posture, fail-closed throughout:

- `authz_methods.go`: `methodPermission` now prices the `Complete`
  method from the decoded request — `ConfigMode=true` costs
  `config.PermConfig`, `ConfigMode=false` (and an unreadable request)
  stays at the `PermView` floor in `methodPermissions`. This mirrors
  #9324's candidate arm: the table entry is the floor, the decoded
  request selects the dearer arm. Operational completion keeps the view
  price, so read-only operators keep a usable operational CLI; only the
  config-mode arm — completing the configuration the caller could `set`
  — costs configure.
- `authz_command_gate_7172.go`: `authorizeRPCCommand` no longer exempts
  `Complete` via `configModeMethods9633`. It routes Complete to the new
  `authorizeCompleteRPCCommand`, which adjudicates the typed line under
  the class's operational regexes: the full line with `EvaluateForms`
  unanimity (full spelling + bare `show configuration` alternative, so
  `^show configuration$` denies its sub-paths and an allowlist exception
  against the full command admits the line), plus a deny-side typed-
  prefix walk so an anchored ancestor deny fires. Config-mode
  `run <line>` is adjudicated on the embedded operational line; text
  after `|` is dropped as pipe-filter text. An unreadable request
  denies for a restricted class. Classes with no operational regexes
  return before any of this, exactly as before.
- `authz_config_rpc_9633.go`: comment records the #14952 exception —
  `Complete` stays in the reviewed set (no canonical command exists for
  it) but is no longer operationally exempt.

Not changed: the handler's #14144/#14708 data-source filters
(`completionAuth`, `wrapProvider`, `treeConfig`), `Complete`'s
operational `PermView` price, the other ten config-mode RPCs' #9633
exemption, `valueProvider`/`CompleteSetPathWithValues`/cmdtree, and the
local `pkg/cli` completer (in-process for the session's own user, as in
#14144/#14708). No wire change: `ConfigMode` already exists on
`CompleteRequest`.

Behaviour delta (deliberate, the issue's ask): a view-only class loses
CONFIG-MODE completion (it could not read the configuration it was
completing); a class holding `view` + `configure` keeps it, still
subject to the #14144 `*-configuration` live-value filters and now to
`*-commands` on `show configuration …` lines in either mode.

## Residuals

- None known on the gRPC surface. The pipe-filter early return in
  `Complete` still serves public filter names without a regex verdict;
  filter names are public grammar (they disclose no configuration), and
  the interceptor now denies a restricted class's denied command line
  before the handler runs in production.
