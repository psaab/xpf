# Issue #15788 — `OverlapKey` identity guard (G27-03)

- **Timestamp**: 2026-10-19
- **Issue**: `OverlapKey` derives `PartialEq`/`Eq` over all fields including
  `fairness_origin`. Arrival (pre-translation) keys always carry
  `fairness_origin: None`, while every key returned by
  `translated_overlap_key` carries `Some(overlap_sender(pre))`. Both TX-site
  post-NAT guards — `poll_descriptor/mod.rs` (`post_key != pre_key`) and
  `neighbor_dispatch.rs` (`post_key != okey`) — therefore compared unequal
  even for an identity address rewrite (rewrite addrs == arrival addrs, same
  egress domain). The post-check then re-recorded the fragment's own range
  under the post key, found the pre-recorded entry via
  `overlap_same_datagram`, and dropped the packet against itself with
  `FRAG_OVERLAP_POST_NAT_DROPPED`.
- **Fix** (datagram identity, not derived equality):
  - `fragment_overlap::overlap_same_datagram` is now `pub(crate)` and
    documented as the required pre/post comparison: it excludes
    `fairness_origin` (quota-only, #14127) while including family, src, dst,
    ident, protocol, routing domain, and ingress zone. Derived `PartialEq`
    on `OverlapKey` is unchanged — it is still used deliberately in tests
    (e.g. asserting two arrival keys differ / parse-key equality).
  - `poll_descriptor/mod.rs`: guard is now
    `Key(post_key) if !overlap_same_datagram(&post_key, &pre_key)`.
  - `neighbor_dispatch.rs`: guard is now
    `Key(post_key) if !overlap_same_datagram(&post_key, &okey)`.
  - No other behavior changes: genuinely different post keys (changed
    src/dst/domain/protocol/zone) still run the post-check and record;
    NAT64 and domain-change keys are never same-datagram as their pre key.
- **Regression**: `translated_key_identity_rewrite_same_datagram_15788`
  builds an identity-rewrite fixture via `translated_overlap_key`, pins
  that derived `post != pre` (the defect trigger) while
  `overlap_same_datagram(post, pre)` holds, asserts changed-src and
  changed-domain post keys are not same-datagram, and proves the recorded
  consequence: pre key recorded once, identity post key guarded out,
  moved key recorded (disjoint passes, overlapping drops with exactly one
  `FRAG_OVERLAP_POST_NAT_DROPPED`).
- **RED → GREEN proof**:
  - RED (pre-fix worktree): the new test passed its guard-semantics
    assertions only because it calls `overlap_same_datagram` directly —
    the production guards still used `!=`, so the identity post-check ran.
    Verified by source inspection of both guards at base `f7c921ce29`
    (`post_key != pre_key`, `post_key != okey`) plus the fixture pin
    `assert_ne!(post, pre)` proving the guard could never skip.
  - GREEN: `cargo test --bin xpf-userspace-dp translated_key_` —
    3 passed (`translated_key_identity_rewrite_same_datagram_15788`,
    `translated_key_same_family_collision_9950`,
    `translated_key_nat64_truncation_collision_9950`), 0 failed.
    Full `fragment_overlap::` module: 43 passed, 0 failed.
- **Risk**: Guard narrows only the identity case (same datagram pre/post).
  Cross-tenant post-NAT collision detection (#9950/#14127) is untouched —
  keys that differ in any membership field still take the post-check.
  No allocation, wire, or config change; two call sites, one helper.
