    unshared mark in `unshared.json` now carries an optional `discarded`
    state: `recordSyncDivergenceLocked` writes it durably BEFORE
    `SyncApply`'s `writeActive`, and the record is not deleted there.
    While the replacement is not yet durable the record is pending

    the alarm and a re-sync re-classifies); once the replacement lands
    — SyncApply success or the persist-retry heal via
    `reconcilePersistedUnsharedLocked` — it is reduced to a bare form
    (`digest == discarded.adopted_digest`) that restores the alarm on
    `Load` but can never re-classify. Local promotions and a different
    synced config clear the persisted record with the in-memory alarm.
    Previously the mark was durably deleted before `writeActive`
    (which degrades without failing), and the alarm itself was
    process-memory only, so a restart after the heal silently lost the
    discarded partition commit.
