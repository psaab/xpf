# #18518 — V1 fabric zone stamps drop for widened zone ids

- **Timestamp**: 2026-10-29
- **Action**: Found by the hostile HA review of PR #18516 and confirmed in
  code: `parse_zone_encoded_fabric_ingress_from_frame` decoded the stamp as
  `u32::from(u16)` and required an exact `zone_id_to_name` hit, so a stamp
  for any zone id > 0xFFFF (every real zone since #16557) was Invalid and
  dropped. Every existing stamp test pinned zone ids 1/2, which fit.
- **Fix**: `zone_low16_to_id` index built in `populate_zones`;
  `ForwardingState::zone_id_for_stamp` resolves the 16 bits to the unique
  admitted zone (ambiguous -> None -> Invalid; hand-built test states scan
  `zone_id_to_name`).
