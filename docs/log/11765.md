# Issue #11765: HA executable attestation uses deployed image

## Disposition

Fixed HA executable attestation to compare live-node readbacks with a deploy-time artifact manifest rather than a fresh local rebuild. Cluster deploy invalidates any prior manifest before binary changes, then writes `dist-deb/xpf-deploy-manifest.json` after successful deployment: raw deploys record the verified local binaries, while package deploys hash the staged binaries inside the exact selected `.deb`. Cluster gates accept the record only when its checkout identity matches the current tree; missing, invalid, or stale provenance fails closed as unavailable, never falling back to a local rebuild. The userspace-helper gate and manual T12/G2 check use the same rules. Ledger schema 2 records the deploy-artifact meaning of `build_exe_sha256`; historical schema-1 rows keep their meaning.

No live loss-cluster deploy or gate was run for this change. Closure evidence is the hermetic red/green reproduction and the deploy, gate, and affected-suite selftests below.

## Red-before reproduction

At the same source revision, two `make build` invocations produced different `xpfd` bytes because `BUILD_TIME` is embedded:

- First build, `2026-10-02T04:46:44Z` (simulated deployed artifact): `3d05ccf32aed0cdf04c354638984a6895d2cf75fcac54905f22324a79b17e6fa`
- Second build, `2026-10-02T04:47:43Z` (fresh local rebuild): `93e957e24ca98b9b2ddf45ff3baca1ad949cc138db303ed287ca1010be50dc76`

A hermetic pre-fix harness invocation supplied the first hash as the live readback and the second binary as `--build-exe`. The wrapper returned `rc=0`, but its temporary ledger row was `verdict=VOID exe_check=MISMATCH`, reproducing the attestation void.

## Green hermetic proof

The updated harness selftest supplies a matching deploy manifest while the local rebuild differs, then returns that manifest image from both mocked node readbacks. It verifies `exe_check=MATCH` and records the manifest SHA as `build_exe_sha256`. Other cases verify helper attestation, fail-closed behavior for missing/corrupt/stale-checkout manifests, and schema 2; existing emitter refusal controls remain covered by the same suite.

The deploy library selftest creates both raw and `.deb` deployment fixtures. It verifies raw hashes, the actual staged `.deb` payload hash rather than a different local rebuild, atomic manifest metadata, and manifest-write ordering before cluster re-baselining.
