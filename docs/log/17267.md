# #17267 — Share the display and authz path walker

- **Timestamp**: 2026-11-06
- **Why**: At base `1348368e5c` (`origin/master` for this lane), `navigatePathWidth` and `navigateRenderedMatches` were separate implementations but their branches were equivalent. The current defect was a coverage gap, not a live behavior mismatch: `TestPricedEqualsRenderedPathSet15995` did not include a duplicate same-prefix context whose requested child exists only under the second sibling, so a pricing-only revert of #4562's union descent was unguarded.
- **What**: Replaced the two hand-copied traversals with `navigateWalk`. Display mode retains node-slice navigation and true consumed width without allocating rendered-path state; authz mode captures each terminal's rendered path and ancestors from the same branch decisions. Added a branch-complete wrapper parity table and a named authz denial witness for duplicate multi-key contexts. Updated `pkg/config/README.md` and the #4562 test comment to name both consumers.
- **File(s)**: `pkg/config/ast.go`, `pkg/config/rendered_paths_15995_test.go`, `pkg/config/show_config_dup_context_4562_test.go`, `pkg/config/README.md`, `docs/log/17267.md`.

## Branch table (both original walkers were checked at base `1348368e5c`)

The direct parity test also checks that the two wrappers return the same terminal node pointers and that the expected rendered paths and consumed widths remain stable. The named authz case selects `policy B` through a truncated selector under two identical `from-zone untrust to-zone trust` contexts. `deny-configuration` is anchored on the full context path, which the request does not spell: authz must resolve the second block and deny the rendered context. This is the missing #4562 pricing cell.
