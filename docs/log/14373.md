# #14373 — All-zero / degenerate X25519 static keys accepted: WireGuard peer authentication bypass

## Defect
- Every WireGuard key gate was shape-only: Go `isWireguardKeyHex`
  checked 64 hex chars (private key, peer public keys, PSKs), the Rust
  hydrate `decode_wg_key_hex` checked length + hex, and the engine
  derived/used keys with no strength check; snow's `dh()` never rejects
  a zero/low-order output.
- An all-zero local private key clamps to the publicly known scalar
  2^254, so anyone can complete a handshake as ANY configured peer. An
  all-zero / small-order peer public key makes the DH output zero or
  enumerable over ≤4 values, so a remote attacker who knows no secret
  completes the handshake as that peer (no PSK). An explicit all-zero
  PSK is likewise a known constant. Folded DR4-H1-ext scope: all-`0xFF`
  / repeated-byte private keys and the u=1 order-4 peer point are the
  same shape-only root cause in the same validator.

## Fix
- `pkg/config/compiler_validate_wireguard.go`: new
  `isDegenerateWireguardKeyHex` (repeated-byte keys + the complete
  small-order encoding list: u=0, u=1, both order-8 points, u=p-1, and
  the non-canonical encodings that reduce to them) enforced at all
  three sites — local private key, peer public key, explicit PSK.
  Strict commit rejects; lenient load warns (existing `emit` posture).
  Private/PSK errors never echo key material. Absent PSK still means
  "no PSK".
- `userspace-dp/src/afxdp/wg/mod.rs`: byte-mirror predicate
  `is_degenerate_wg_key_bytes` + `WG_SMALL_ORDER_KEYS` table (the
  contributory check snow's opaque DH makes un-hookable in-tree: with
  a clamped scalar the DH output is identity iff the peer point is
  small-order, and every such point is listed).
- `userspace-dp/src/afxdp/forwarding_build/tunnels.rs`:
  `hydrate_wg_identity` drops the row (fail-closed, logged) on a
  degenerate local private key, peer public key, or explicit PSK.
- `userspace-dp/src/afxdp/wg/engine.rs`: `WgEngine::new` refuses a
  degenerate local private key; `reconcile_peers` refuses degenerate
  peer pubkeys before any HandshakeState can be built (counted via
  new `hs_refused_degenerate_key` counter, plumbed through
  `status_wg` / `protocol/control.rs` / Go `protocol_tunnels.go`).

## Deliberate scope notes
- The engine's infallible `WgEngine::new` signature is unchanged (its
  ~35 test call sites use repeated-byte placeholder keys); production
  reaches it only via the hydrate, which drops degenerate rows. The
  engine still refuses a degenerate LOCAL key by assertion and refuses
  degenerate PEERS at reconcile, so no handshake can use them.
- No snow DH-output hook: snow computes DH opaquely inside
  HandshakeState; the complete small-order denylist is provably the
  same enforcement (clamped scalar ⇒ zero DH iff small-order point).
