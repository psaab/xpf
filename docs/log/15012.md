# #15012 Bare-host prefix-list entries omitted by FRR render belt — engineering history

Issue: psaab/xpf#15012 (A10-01). Lane branch: `fix/15012-campaign`, base
`origin/master` 966d3d9c3b.

## Defect (present at base)

A mask-less prefix-list entry (`10.0.0.1`, `2001:db8::1`) is commit-valid:
JunOS treats it as a host route, and the #7273 firewall classifier
(`classifyFilterAddrFamily`) accepts bare hosts as /32 or /128. But the
#10823 render belt required `net.ParseCIDR` at three sites —
`generatePolicyOptionsWithRefNodes14380` (top-level `ip|ipv6 prefix-list`
definitions, `pkg/frr/policy_render.go`), `renderFromPrefixListACL`
(inline ACLs, `pkg/frr/prefix_list_render.go`), and
`prefixListRefMissingAtRender` (`pkg/frr/policy_render.go`) — so a bare
host was warned as "malformed" and omitted. In a mixed list the host route
silently escaped a `then reject` import/export term (fail-open for that
entry); in an all-bare list the ref was treated as dangling, yielding
deny-all for a reject term / a dropped branch for accept.

## Fix

- New `config.NormalizePrefixListEntry` (`pkg/config/prefix_list_entry.go`):
  the one predicate shared by routing (FRR) and firewall consumers. It
  accepts a CIDR (canonicalised via `Masked()`, so host bits are masked
  off as FRR does) or a bare host (rendered `/32` v4, `/128` v6), and
  rejects zone-scoped literals and all other malformed values.
- The three #10823 sites now call it and render the normalised value:
  top-level prefix-list loop, `renderFromPrefixListACL`, and
  `prefixListRefMissingAtRender` (so a bare entry counts as rendered and
  an all-bare list is not missing). Genuinely malformed entries still
  warn-and-omit fail-closed, keeping their seq gaps.
- NOT changed: `renderRouteFilterEntry` / route-filters (a `route-filter`
  prefix requires an explicit length in Junos; bare is malformed there),
  the #7273 firewall gate and the userspace resolver (already accept bare
  hosts), and commit validation (bare was already accepted — rejecting it
  would have been the alternative fix direction and a behaviour break).

## Verification

- New `pkg/frr/policy_prefixlist_barehost_15012_test.go` (4 tests):
  RED on base (bare entries omitted; all-bare reject degraded to
  deny-all), GREEN with the fix. Covers bare_mixed through the real
  parser + strict/tolerant compile (`10.0.0.1/32`, `2001:db8::1/128`,
  inline ACL `exact-match`), bare_only v4+v6 (matching prefix-list, reject
  keeps its match), malformed-still-omitted controls (`999.0.0.0/8`,
  `/33`, `foo`, zone-scoped), and all-malformed-still-deny-all.
- Adjacent suites: `#10823`/`#14136` prefix-list tests pass unchanged;
  the full `pkg/frr` suite passes with the three FRR-binary load tests
  skipped (`TestFamilylessIPv6NeighborWithoutPolicyIsV6Only11564`,
  `TestFRRLoadInet6OnlyNeighborIPv4Deactivation11374`,
  `TestFRRLoadBGPClasslessRIBSuppression11426` — `privs_init`/`setgroups`
  sandbox failures, confirmed failing identically on pristine base);
  `go vet ./pkg/frr/ ./pkg/config/` and `gofmt -l` clean on touched files.

## Residuals

- A CIDR entry with host bits set (`10.0.0.1/24`) now renders masked
  (`10.0.0.0/24`) instead of verbatim. FRR canonicalises prefixes the
  same way, so the installed match is unchanged; only the rendered text
  is canonicalised.
