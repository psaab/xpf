# #14642 — ICMP Time Exceeded / PTB for GRE/WireGuard-decapped inner reflected unencapsulated to zero MAC

## Issue
GRE/WireGuard decap fabricates a synthetic Ethernet header with zero
MACs for the inner packet and marks it `TUNNEL_DECAP_INGRESS_FLAG`
(0x20). #12864 gated only `reject` (in `enqueue_reject_reply`) against
reflecting that fake L2. The Time Exceeded builder
(`build_local_time_exceeded_request` / `build_local_icmp_error_v4/v6`,
via `ingress_reply_l2`) and the PTB path (`ptb_reply_suppressed` /
`build_frag_needed_v4` / `build_packet_too_big_v6`) had no tunnel check,
so a TTL=1 or oversize-DF decapsulated inner queued an unencapsulated
ICMP error on the underlay binding with destination MAC
00:00:00:00:00:00 — flooded as unknown unicast, leaking cleartext inner
header + 8 L4 bytes (for WireGuard, encrypted-domain addresses/ports),
breaking traceroute/PMTUD across the tunnel.

## Fix
#12864 parity — suppress, do not encap-route (encap-routing the error
toward the inner source is the larger alternative the issue allows but
does not require; suppression matches the shipped reject contract):

- `userspace-dp/src/afxdp/icmp.rs`:
  - `can_generate_icmp_error_reply`: return `false` up front when
    `meta_flags & TUNNEL_DECAP_INGRESS_FLAG != 0`. This covers Time
    Exceeded at its call site and the reject builder's shared gate.
  - `build_local_icmp_error_v4` / `build_local_icmp_error_v6`: return
    `None` on the flag — defense in depth so no direct caller (TE
    wrappers or reject) can reflect the synthetic header even if a
    future call site bypasses the gate.
- `userspace-dp/src/afxdp/icmp_ptb.rs`:
  - `ptb_reply_suppressed`: return `true` on the flag (the dispatch
    caller still drops the oversize original via `mtu_signalled`, so
    this fails closed, never forwards the MTU-violating frame).
  - `build_frag_needed_v4` / `build_packet_too_big_v6`: return `None`
    on the flag, same defense-in-depth rationale.

The flag survives to the PTB dispatch because `ForwardPacketMeta`
carries `meta_flags` verbatim both ways. GRE sets the flag in
`gre.rs` (`GRE_DECAP_INGRESS_FLAG | TUNNEL_DECAP_INGRESS_FLAG`); WG
sets it in `wg/decap.rs` and the uncovered-forward injector — so both
tunnel legs named in the issue are covered by the same gate.

NOT changed: `poll_descriptor/mod.rs` session-miss handling. Suppressing
TE on this path makes the expiring-but-suppressed case reach the
session-install `else` arm (Y32-02, #14643); that fix is owned by
#14643's lane in the same file and is deliberately not duplicated here.
Until #14643 lands, a tunnel-decap TTL=1 packet on a session miss may
install a session and then drop at rewrite — the pre-existing Y32-02
behavior for every suppressed TE, not a regression introduced here
(pre-fix it queued the bogus TE instead). Flow-cache-hit and
session-hit arms already drop on suppressed TE.
