# #12227 — clarify omitted match-policies selector semantics

- **Timestamp**: 2026-10-07 (`fix/12227-policymatch`)
- **Action**: replace the blanket “omitted selector matches any” help claim with the simulator’s mixed omission semantics, and pin the partial-query contract.

## Red before

At base `a714c90d4`, a partly specified trust-to-untrust query omitting protocol returned the configured default deny for a `junos-http` permit policy, while its concrete `tcp`/80 completion matched that permit. A focused regression draft failed against the base help text for both `MatchPoliciesUsage` and `TestPolicyUsage`: neither explained why omitted IP widens while a missing protocol fails closed for a constrained application.

## Change

- The shared policymatch usage text now says omitted source/destination IP matches any address, while omitted protocol, port, or ICMP type/code fails closed for an application term constrained on that dimension; unconstrained terms may still match.
- Local and remote CLI usage-output tests pin that user-visible explanation. The matcher regression pairs the omitted-protocol default-deny result with its permitted `tcp`/80 completion.
- The Junos CLI reference and matcher comments now describe the same contract. Matching behavior is unchanged.
