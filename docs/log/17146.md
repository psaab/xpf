# #17146 — Three retired C headers (xpf_helpers.h, xpf_nat.h, xpf_trace.h; 3,292 LOC) have no compiler and no live reader, yet are still maintained as a live mirror (R4-Q48-04)

- **Timestamp**: 2026-10-27
- **Issue**: #17146 (R4-Q48-04)
- **Base**: `origin/master be463f60e7`

## Defect (STEP-0, verified at base)

Live on `be463f60e7`. `bpf/headers/` held six files (5,441 LOC).
No non-header file includes any `xpf_*.h`; readers outside `bpf/`:
`xpf_helpers.h` only `retirement_boundary_canary_test.go:711`
(retirement marker), `xpf_nat.h` only a comment at
`userspace-dp/src/nptv6.rs:232`, `xpf_trace.h` none. The shim build
reads one `#define` (`MAX_INTERFACES`, `build-userspace-xdp.sh:108`)
from `xpf_common.h`, yet `userspace_xdp_manifest.go` hashed the whole
934-line file, so edits to retired content staled the freshness gate
(#10561; 177fc11ad2→26003e3408). Normalized alphanumeric census over
all `.go`/`.rs`/`.sh` outside `bpf/` (comment-stripped on the corpus
side) found 35 dead defines + 4 dead structs in `xpf_common.h`, 3+3
in `xpf_maps.h`, 0 in `xpf_conntrack.h` beyond its guard.

## Fix

- `git rm bpf/headers/xpf_helpers.h xpf_nat.h xpf_trace.h` (3,292 LOC).
- `TestRetiredBPFWatchdogHeadersHaveNoLiveCallers10791`: the
  `xpf_helpers.h` arm is inverted to "file absent" (with
  `xpf_nat.h`/`xpf_trace.h`); `xpf_maps.h` keeps its marker arm.
- `nptv6.rs:232` comment now points at the deletion commit.
- `xpf_common.h` trimmed 934→~660 lines: removed the retired-only
  defines/structs the census proved readerless (HOST_INBOUND_* and
  NEXTHDR_* were **not** removed — they have live Go mirrors
  `HostInbound*` in `pkg/dataplane/types.go`, so the issue's
  "(2) strip HOST_INBOUND_*" clause would have broken the acceptance
  census it mandates; MAX_EXT_HDRS/the walker bounds, AF_INET/AF_INET6,
  ETH_ALEN, tail-call indices beyond PROG naming, META_FLAG_*,
  DSCP subset, FLOW_* field bits, BPF_FIB_* and the net-order header
  structs were removed). Sizing-only constants consumed solely inside
  the retained headers (MAX_LOGICAL_INTERFACES, MAX_APPLICATIONS,
  MAX_SCREEN_PROFILES, MAX_PORT_SCAN_TRACK, XDP/TC_PROG_MAX,
  DSCP_AF21, POLICER_ACTION_DISCARD, SESS_FLAG_COUNT/ALG/PREDICTED)
  were inlined as literals at their `xpf_maps.h` use sites or deleted.
  The shim-consumed define is unchanged at value 65536.
- `xpf_conntrack.h`: removed the never-compiled inline helpers
  (`ct_tcp_update_state`, `ct_get_timeout_default`, `ct_reverse_key*`);
  the four structs parsed by `bpf_conntrack_abi_6984_test.go` are
  byte-identical.
- `xpf_maps.h`: removed readerless `cpumap_val`/`cpu_map`,
  `validated_client*`, `nat64_fib_cache*`, `fabric_fwd_info` and their
  map declarations; inlined MAX_STATIC_NAT_ENTRIES/MAX_NPTV6_RULES.
- Extraction narrowing (#17146 part 2, consumed-content form):
  the recipe (`build-userspace-xdp.sh:108`) awk-extracts only the
  `#define MAX_INTERFACES …` value — the one text the shim build
  consumes. `ShimMaxInterfaces`/`WellKnownCodegenEnvDigest`
  behaviour is unchanged. A new `xpf_abi.h` was **not** created:
  moving the define would churn `build-userspace-xdp.sh:108`, the
  awk anchor, four `MAX_INTERFACES`-parsing tests and the shim
  codegen digest for the same invariant, so the consumed-content
  narrowing stays at the recipe's extraction point. The freshness
  manifest still hashes `xpf_common.h` whole-file (fail-closed, per
  the #4977 rationale in the file); re-stamping it requires
  `make generate`, which rebuilds the shim object — left to the
  parent, so `TestUserspaceXDPShimObjectMatchesSourceManifest` is
  expected red on this head until then (build-attestation boundary,
  not hand-edited).
- Fold (Rev18185 Finding 2): `ShimMaxInterfacesHeader` — an earlier
  Go helper that returned the extracted define line — had zero
  callers (the recipe awk-extracts; the freshness gate whole-file-
  hashes), yet comments claimed the extraction decoupled the gate
  from whole-file edits. Deleted the dead helper (+ unused `bytes`
  import) and corrected the comments to the true whole-file-hash
  contract: any `xpf_common.h` edit, including retained-ABI content
  the shim never reads, still churns the freshness hash and needs a
  `make generate` restamp.
- Noted, out of scope: the `verified_at` timestamp in
  `userspace_xdp_gate_verdict.json` de-churns on every
  build-script restamp (build-script behaviour, not this fold).
- New acceptance test `TestEveryHeaderIdentifierHasLiveReader17146`:
  every `#define`/named struct in the three retained headers must
  appear (comment-stripped, alphanumeric-normalized) in some
  `.go`/`.rs`/`.sh` outside `bpf/`; guards exempt. It caught 9 dead
  identifiers on its first run (DSCP_AF21, POLICER_ACTION_DISCARD,
  SESS_FLAG_ALG/COUNT/PREDICTED, XDP/TC_PROG_MAX,
  `iface_counter_value`, `validated_client_key`), all removed above.
- Docs: `bpf/headers/README.md` rewritten (no longer "every BPF
  program"; lists the three retained files, the deletion, and the
  live-reader rule); `docs/architecture.md` code-layout row and the
  `CLAUDE.md` code-layout row updated to "common, conntrack, maps".
  `docs/phases.md` / `docs/active-active-new-connections.md` helper
  line citations are historical records and were left as written
  (the deleted files remain in `git log` at this commit).

## Risk

- Shim freshness manifest/build digest go stale by design until the
  parent runs `make generate`; no hand-edit was made to launder them.
- Header trims are layout-preserving for every retained struct (the
  conntrack offset pin and `struct event` field pin both pass
  unchanged); removed items had no reader outside comments/internal
  sizing.
- Docs citing deleted helper line numbers become historical; they
  point at `git log` history, per the #1476 precedent.
