# 14416 — Group `route-filter` OR-branch dropped beside an inline `route-filter` (DR15-H1)

- **Timestamp**: 2026-10-17
- **Action**: Adopted a distinct group `route-filter` member beside an
  inline `route-filter` peer in `mergeNodes`' leaf branch
  (`pkg/config/ast_groups.go`), instead of dropping it to the
  inline-wins override. `route-filter` is schema `args:2, multi:true`
  (schema_routing.go: prefix-list / route-filter / community / as-path
  are documented OR-members and the compiler appends EVERY sibling
  into `term.RouteFilters`), but `leafListUnionEligible` requires
  `args <= 1` and the packed-peer promotions require a
  children-bearing schema node, so a group member beside an inline one
  fell through to `continue` and vanished. A reject term written in
  two halves matched only the inline half; the group half's prefixes
  fell through to the next term's accept. New helpers in
  `pkg/config/group_route_filter_or_14416.go`
  (`isRouteFilterORMember14416`, `routeFilterMemberIdentity14416`,
  `routeFilterMemberExists14416`) scope adoption to `route-filter` at
  a policy-statement term `from` (schema-resolved, with an exact
  policy-statement/term/from ancestor-tail fallback) and dedupe on the
  FULL member identity — prefix + match-type + trailing
  upto/prefix-length-range/through token, including the flat-set
  child-carried trailing shape. Duplicate members keep the existing
  drop; `mergeLeafListInto` is deliberately not reused (it unions
  `Keys[1:]` token streams and would mash two (prefix, match-type)
  pairs into one corrupt leaf). The generic `args >= 2` override is
  unchanged: scalars, `as-path` definitions (owned separately by
  #14419/DR15-H4), and address-book `address` keep existing behavior;
  inline-only configs compile unchanged.
- **Regression**: `pkg/config/route_filter_group_or_14416_test.go`
  (`TestGroupRouteFilterORBesideInline14416`): braced group beside
  braced inline, swapped group/inline prefixes, packed group
  route-filter leaf, split inline `from` blocks, flat-set group beside
  flat-set inline, distinct trailing `upto` members, duplicate-member
  dedup control, and inline-only control. RED on `origin/master`
  (5 cells failed with the group member missing, e.g.
  "route-filters = [10.0.0.0/8 orlonger], missing
  192.168.0.0/16 exact"; packed-leaf and controls passed, the packed
  shape already reaching the merge via the #7648 expansion), GREEN
  after the fix. Targeted group/routing suites (TestApplyGroups,
  TestExpandGroups, TestGroupKey, TestRouteFilter, TestPolicy) green;
  full `pkg/config` run shows 51 pre-existing IPsec/PSK failures
  (#14139 family) confirmed identical on stashed `origin/master`
  (base-attributed) before a 10m panic timeout under load.
