# Issue #12718: device-map MAC-form original-name handling

## Finding

The probe reproduced the reported path. `deviceMapOriginalNameFor` treated a current name as the kernel original whenever it differed from the new target, even when a matching name-only MAC-form `.link` showed udev had assigned that name. During a name collision, phase 1 temp-renamed that NIC; if the next owner's `.link` write then failed, the old MAC claim could survive phase-4 cleanup because the target remained desired.

## Fix

Treat a matching name-only link as an unknown original when the NIC changes target. Device-map phase 2 now handles unknown originals before known owners, removes the pre-temp/current and target `.link` claims before renaming, and carries the pre-temp name across collision breaking. The existing error path reports the missing persistence and failed owner write.

## Probe

`TestProbe12718DeviceMapDoesNotTreatMACNameAsKernelOriginal` covers same-target recovery, fresh names, a MAC-form current name changing target, and a simulated owner-link write failure after a collision temp rename. Before the fix it reported the MAC-assigned name as a known original; after the fix it passed and confirmed the old claim was removed before the failed write.
