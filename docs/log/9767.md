- **Timestamp**: 2026-09-11 08:40 PDT
- **Action**: Showed that the issue's minimal fix, "return false so the resync is
  retried", is unsafe on its own.
  - A false return queues the frame in `pendingCallbackFrames`.
  - `flushPendingCallbackFrames` then re-invokes `onFullResync` on every later frame's
    enqueue and on the 100 ms `ackLoop` tick. Each call re-runs the synchronous helper
    export.
  - `sendLoop` writes one message per `writeFull`, so an export burst larger than the
    4096-entry queue routinely outruns it.

  On an owned table bigger than the queue every retry would fail again, re-exporting on
  each incoming frame until `pendingCallbackFramesLimit` closes the stream. Reported to
  the lead with the chosen design (paced admission plus a retry backoff) and the heavier
  alternative (an acknowledged bulk re-drive, which overlaps #9630).

- **Timestamp**: 2026-09-11 08:50 PDT
- **Action**: Implemented the fix.
  - `QueueSessionV4Paced`/`V6Paced` (cluster) wait for room instead of dropping. A
    disconnect ends the wait; an expired wait makes a final lossy enqueue, so the drop is
    counted as before.
  - `queueUserspaceSessionDeltasComplete` (daemon) runs the same #7194 schema gate and
    the same walk, through a paced sink. It returns an error unless every install was
    queued. After one install times out, the rest are queued without waiting.
  - The export uses it, so a withheld batch, a missed install or a disconnect declines
    the frame.
  - A failed attempt holds the export off for 1 s, so the frame's retries stop
    re-running the helper export.
