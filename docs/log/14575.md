# #14575 — Logical-unit `disable` commits clean and is silently discarded

## Mechanism
`Disable` existed only on `InterfaceConfig` (`types_interfaces.go`),
was read only at interface level in `compileInterfaces`, and the
schema declared `disable` only at interface level. `unit 0 disable`
(flat `set ... unit 0 disable` and hierarchical `unit 0 { disable; }`)
therefore committed clean with no typed field, no snapshot flag, and
the unit keeping its addresses, zone and forwarding — a fail-open
operator-intent lie (Y02-03, probe: `ifaceDisable=false unit0
addrs=[10.0.1.1/24]` on both spellings, interface-level control true).

## Fix
Implement `InterfaceUnit.Disable` end to end (the issue's first
acceptance arm — snapshot `AdminDisabled=true` + no addresses — not
the reject-at-commit fallback, since Junos honours per-unit disable
and the userspace snapshot already carries the per-row flag):

- `pkg/config/types_interfaces.go`: `InterfaceUnit.Disable`.
- `pkg/config/schema_interfaces.go`: `disable` leaf under `unit`
  (flag, no args), so flat-set `set` validates and packed tails split.
- `pkg/config/compiler_interfaces.go`: read `disable` on the
  packedBody-expanded unit node (braced/packed/flat all land there);
  a disabled unit contributes no tunnel addresses.
- `pkg/dataplane/userspace/interfaces.go`: unit row
  `AdminDisabled = iface.Disable || unit.Disable` with addresses
  suppressed; a disabled unit 0 that collapses onto the base netdev
  also suppresses/marks the base row. Rust already fences
  `admin_disabled` rows out of FIB/local/egress derivation — no wire
  or Rust change, no new field.
- `pkg/dataplane/compiler_iface*.go`: legacy/networkd planners skip
  a disabled unit's addresses/DHCP (untagged plan, VLAN sub-interface
  with `Disable:true`, regular/ST/fabric/IRB collectors,
  VLAN-parent VRRP source); when every unit is disabled the base
  networkd row is `Disable:true`. Sibling enabled units unchanged.
- `pkg/cli`: `show interfaces` prints the unit admin-down line;
  `show interfaces terse` marks the logical row `down`.

Interface-level `disable` is unchanged (control in both tests).

## Regression
- `pkg/config/interface_unit_disable_14575_test.go`
  (`TestUnitDisable14575`): hier + flat + packed + lenient all set
  `Unit.Disable`; sibling unit 1 stays enabled; interface-level and
  no-disable controls pass. RED on pre-fix master: build fails
  (`InterfaceUnit has no field Disable`) — before that, the probe in
  the issue showed `Disable`-less compile with addresses retained.
- `pkg/dataplane/userspace/unit_disable_14575_test.go`
  (`TestUnitDisableSnapshot14575`): `ge-0/0/1.0` row is
  `AdminDisabled=true` with no addresses and no route/local leak;
  sibling `ge-0/0/1.1` keeps `10.0.2.1/24`; interface-disable control
  still suppresses the row.

Residual: DHCP/VRRP/RA/DDNS engines keyed off a disabled unit's
typed config are not separately gated — the snapshot fences the
forwarding/FIB surface, and networkd no longer installs its
addresses or DHCP flags. `show interfaces detail/extensive` do not
yet render the per-unit admin state (plain + terse do).
