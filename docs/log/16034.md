# Issue #16034 — nat: interface SNAT mint lacks static/NPTv6 runtime guard (A2-C8)

- **Issue:** Both interface-SNAT mint arms (address-only `:546-553`, PAT `:575-590` at the research base) consulted only pool/NAT64 peer overlap owners — never `static_owns_wire_identity`, unlike the pool arm. The strict Go gate covers the static/interface pair, so reachability is lenient-load / peer-synced configs only, where `emitNATOverlap` installs with a warning. The NPTv6 leg duplicates A2-C7.
- **Status at fix time:** The NPTv6 leg is already fixed by #16015 (PR #16357): pool, interface, and HA-synced mints refuse inside an installed NPTv6 external prefix. The static leg remained: `wire_static_overlap_peers` skipped `interface_mode` rules, and neither interface arm nor the synced interface import consulted the static view.
- **Fix (Rust only):** `wire_static_overlap_peers` builds a per-build memoized `InterfaceStaticView` (host externals indexed by address, block externals as prefixes, one pass over the table) and wires it onto `interface_mode` rules and touched pool-rule siblings. The mint helpers consult only that index — never a whole-table rescan per rule/mint. The address-only arm refuses when any static covers the egress address (it cannot move its port); the PAT arm folds the full `(address, port)` check into `peer_owns`, so a port-mapped static is PAT'd around (its one port excluded, post-mint recheck as backstop). Fold (PR #16377): a whole-address/block static is pre-checked via `owns_all_ports` BEFORE `allocator_for` / allocator entry, so it refuses in O(view) instead of walking the allocator's whole port range to exhaustion. HA: `reserve_synced_interface_identity` and the top-of-function guard refuse dynamic interface imports on a static external (via the same memoized view) before booking/success; genuine static and unknown-provenance imports keep #15191 success.
- **No Go change:** the strict gate already rejects static-on-interface-egress (whole-address via #6751 §5.7, port-mapped via #14368/#15258 pairing against `natPoolOverlapOwners` interface owners) and lenient load already warns — this is the runtime backstop for the tolerated population, mirroring the pool arm.
- **Tests:** Rust `tests_static_iface_overlap_16034.rs` via `build_forwarding_state` (13 cells: whole-address preserved + PAT-attempt refusals, fail-fast-before-allocator-entry with no allocator retained, address-only refusal, never-lands-on-port-mapped-port, PAT-around/outside/no-static controls, v6 static refusal, memoized-view index assertions, HA dynamic import refusal with outside and genuine-static controls).
