# Issue #16034 — nat: interface SNAT mint lacks static/NPTv6 runtime guard (A2-C8)

- **Issue:** Both interface-SNAT mint arms (address-only `:546-553`, PAT `:575-590` at the research base) consulted only pool/NAT64 peer overlap owners — never `static_owns_wire_identity`, unlike the pool arm. The strict Go gate covers the static/interface pair, so reachability is lenient-load / peer-synced configs only, where `emitNATOverlap` installs with a warning. The NPTv6 leg duplicates A2-C7.
- **Status at fix time:** The NPTv6 leg is already fixed by #16015 (PR #16357): pool, interface, and HA-synced mints refuse inside an installed NPTv6 external prefix. The static leg remained: `wire_static_overlap_peers` skipped `interface_mode` rules, and neither interface arm nor the synced interface import consulted the static view.
- **Fix (Rust only):** `wire_static_overlap_peers` now wires the shared `StaticExternalIdentities` view unconditionally onto `interface_mode` rules (egress is runtime-resolved; mirrors the #16015 NPTv6 interface wiring). New `interface_static_covers` / `interface_static_owns_at` helpers (own view, then sibling pool rules): the address-only arm refuses when any static covers the egress address (it cannot move its port); the PAT arm folds the full `(address, port)` check into `peer_owns`, so a whole-address static forces PAT then exhausts (refused), while a port-mapped static is PAT'd around (its one port excluded from candidates, post-mint recheck as backstop). HA: `reserve_synced_interface_identity` refuses a dynamic import whose `(address, translated port)` a static owns before booking, and a top-of-function guard in `reserve_synced_source_nat_allocation_with_holder` refuses dynamic interface-mode imports before the interface-first-match route / `owns_no_reservation` success. Genuine static-provenance imports (`source_nat_static == Some(true)`) keep the #15191 no-reservation success.
- **No Go change:** the strict gate already rejects static-on-interface-egress (whole-address via #6751 §5.7, port-mapped via #14368/#15258 pairing against `natPoolOverlapOwners` interface owners) and lenient load already warns — this is the runtime backstop for the tolerated population, mirroring the pool arm.
- **Tests:** Rust `tests_static_iface_overlap_16034.rs` via `build_forwarding_state` (whole-address preserved + PAT-attempt refusals, address-only refusal, never-lands-on-port-mapped-port, PAT-around/outside/no-static controls, v6 static refusal, HA dynamic import refusal with outside and genuine-static controls).
