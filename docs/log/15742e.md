# Issue #15742 fix lane E — live root causes of the v57 failure

Base: `origin/master@e0583615de` (#15746, protocol v57). Round-5 live
acceptance still fails: split placement RG2@node1 / RG1@node0, transit
0/3 both families, FIB renders `discard pref 200`
(`/var/worktrees/smoke/security-matrix-2026-10-19.md` round 5).

## Live diagnosis (this lane, working-20704, cluster restored after)

Reproduced the split on the healthy cluster, then dumped every layer:

1. **Kernel**: fw1 main table holds only
   `blackhole default proto static metric 20` (v4+v6). A scratch
   netlink binary (`RouteListFiltered`, vendored netlink v1.3.1)
   run on fw1 prints the row the importer actually sees:
   `type=6 (RTN_BLACKHOLE) proto=196 prio=20`. **`proto=196` is
   `RTPROT_ZSTATIC`, not `RTPROT_STATIC` (4)** — FRR's
   `zebra2proto()` stamps every staticd route ZSTATIC
   (`pkg/routing/routes.go:391` `rtprotZStatic`). `ip route` renders
   both spellings "proto static", which is how the v57 triple was
   mis-derived.
2. **Helper snapshot** (`/run/xpf/userspace-dp.json` on fw1, v57):
   `0.0.0.0/0 discard pref 200 cluster_terminal: false` and the v6
   twin. The import mark **never fired live** — hypothesis (a),
   with the priority right (20) and the protocol wrong.
3. **Helper FIB**: fw1 in split has **no pref-5 forwarding default
   at all** (HA-filtered), only the discard. fw0 keeps the real
   defaults. The v57 Rust test invented a forwarding sibling that
   live does not have.
4. **Counters**: fw1 `Last resolution: discard_route` (stale
   unrelated flow), split pings increment nothing attributable —
   consistent with a plain `DiscardRoute` drop, never reaching HA
   demote/fabric.

Two further defects behind the first, found by exact-live-shape
regression (no forwarding default; targets inside the peer-owned
WAN connected prefixes):

5. **Attribution**: `select_source_ifindex_*` looked the destination
   up only in `connected_v4/v6`, which #15745 suppresses for
   peer-owned prefixes. With no forwarding row it returned 0, so
   `cluster_terminal_peer_owned_egress_rg` was false and HA
   enforcement restored `DiscardRoute`. The prefix survives in
   `connected_*_by_ifindex`; that map is now consulted.
6. **Flowless bypass**: ICMP (the gate's probe) is flowless. The
   flowless arm in `poll_descriptor/mod.rs` fabric-redirects only
   `HAInactive`; `ClusterTerminalHAInactive` fell through to the
   terminal drop. Hypothesis (c) — the session path was fine, the
   flowless path was not.

## Fix

- Go import: `clusterStaticProtocol` accepts `RTPROT_STATIC` **or**
  `RTPROT_ZSTATIC` for the ClusterTerminal triple
  (`pkg/routing/fibimport.go`). Tests now use the live proto-196
  shape; near-misses (non-default, metric 99, BGP) stay unmarked.
- Rust attribution: `select_source_ifindex_v4/v6` fall back to
  `connected_*_by_ifindex` for the destination's connected owner.
- Rust flowless: the fabric-redirect gate matches
  `HAInactive | ClusterTerminalHAInactive`.
- Observability: `FibRouteWire.cluster_terminal` (Rust + Go) and
  the FIB dump renders `discard cluster-terminal` /
  `reject cluster-terminal`, so the next live run can prove the
  mark instead of inferring it.
- Protocol v57 → v58 (Go `ProtocolVersion`, Rust
  `CONFIG_SNAPSHOT_PROTOCOL_VERSION`): a v57 helper drops split-RG
  ICMP at the flowless gate and cannot report the mark.
