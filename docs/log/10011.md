## Change

`classifyFilterAddrFamily` now rejects any `%`-scoped address text before calling `netip.ParsePrefix` / `netip.ParseAddr`. Go's parsers accept IPv6 zones, but the Rust filter matcher has no zone model. The strict address gate reports the offending filter, term, token, and zone/scope cause. `recordFilterAddrTokens` already keys on this classifier, so the tolerant path now records the raw `%zone` token on `UnknownAddresses`; the existing snapshot builder emits `address_unrepresentable`, and the Rust preflight rejects the whole snapshot instead of silently dropping that token per-token.

The fix follows the #5875 SNAT-pool precedent: reject the unrepresentable representation rather than stripping `%zone`. No Rust production compiler change was needed; the Rust regression pins the existing marker fail-closed runtime path.
