# Issue #13100 — bind-only secure-tunnel bare-zone host-inbound

## Why

A security zone naming bare `st0` did not fan down to a `bind-interface`-only `st0.0` tunnel without an `interfaces st0` stanza. A dotted bind got no snapshot row; a bare bind got a base row that could not claim the ingress netdev or apply the `st0.0` host-inbound override. Strict commit also missed conflicts between bare and unit zone members.

## What

Include bound, noncolliding IPsec units in the shared bare-interface key expansion used by zone ownership, overrides, and strict conflict validation. Publish the logical-unit snapshot row instead of the base alias for stanza-less bare binds, preserving the authored Linux device name and inherited interface-level CoS. Contested tunnel units produce no zoned row on tolerant load; configurations with a declared `interfaces st0` stanza retain their existing base-row handling.

## Validation

The targeted regression failed on pristine master for both missing and base-only rows, override inheritance, and strict multi-zone conflict rejection; it passed after the fix alongside the existing bind-only tunnel tests. Full Go package runs were attempted. With `GOTMPDIR=/var/tmp`, `pkg/dataplane/userspace` failed only `TestCapFlagIsWiredEndToEnd9054` and `TestSnapshotShapeIsPinnedToProtocolVersion8892`; both also failed on the exact pristine base commit. The `pkg/config` suite failed two #7484 spelling-coverage ratchets, likewise reproduced on that base. A first combined run with a longer Go temp path additionally failed Unix-socket pathname limits, and one IPv6 prefix ordering test failed once but passed on the pristine targeted rerun.

## Risk

Bare-zoned bind-only tunnels now have a unit-identity row (`st0.0`) rather than a base-identity row (`st0`), so host-inbound enforcement can use the authored unit override and ingress netdev. No kernel/live tunnel probe was run.
