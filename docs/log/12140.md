# #12140 — attest helper identity on cluster gates

- **Issue**: #12140 — helper identity was required by only two of the helper-dependent cluster gate invocations.
- **Branch**: `fix/12140-attest`
- **Worktree**: `/var/worktrees/12140-attest`
- **Base**: `1c384b9a47ff7d6e567fa50632faa75c3995ae87`

## Why

A cluster gate can pass while forwarding through a stale or mixed `xpf-userspace-dp` helper unless the wrapper requests helper attestation. The hermetic `test-wire-properties` gate has no deployed helper and must remain outside this policy. Hard-crash gates may finish with a peer down, so their helper readback must preserve the existing partial `local-only` attestation when the peer's deploy-time helper slot is still valid.

## What

- Added `--require-helper-attestation` to the 21 remaining cluster gate invocations, retaining the two existing opted-in gates. Both rollback arms are covered; `test-wire-properties` remains hermetic and unflagged.
- Matched helper peer-down handling to xpfd provenance: `test-ha-crash`, `test-chained-crash`, and `test-double-failover` retain a matching local helper result with `helper_exe_scope=local-only` only when the peer's expected helper image is known. Missing peer provenance remains `UNAVAILABLE`, and readable helper mismatches remain `MISMATCH`.
- Added a Makefile census, a helper-MISMATCH-to-VOID fixture for every cluster gate invocation, and down-peer crash/non-crash scope cases to `harness-result-selftest.sh`.
