# Malformed IPsec frames poison sequence high-water (#13541)

- **Issue**: #13541 — the IPsec session-sync receiver advanced the
  `(incarnation, seq)` guard before decoding the full-set payload. A malformed
  frame therefore prevented the valid twin arriving on the other fabric from
  applying.
- **Change** (`pkg/cluster/sync_conn_read.go`, `pkg/cluster/sync.go`): check
  the current IPsec sequence before decode, but advance it only after successful
  decode, inside a serialized apply commit. The commit checks `recvEpoch` under
  `recvSeqMu`, then updates the held SA set; callback ordering follows the same
  apply lock. Malformed frames do not consume sequence numbers, while a
  well-formed replay remains rejected as stale. Added
  `TestIPsecSAMalformedFrameDoesNotPoisonSeq13541`.
- **RED evidence**: on pristine `origin/master` implementation, with only the
  new regression test added,

- **GREEN evidence**: focused regression
  `go test ./pkg/cluster -run '^TestIPsecSAMalformedFrameDoesNotPoisonSeq13541$' -count=1`
  passed. Full package `go test ./pkg/cluster -count=1` passed (126.759s).
- **Race**: `go test -race ./pkg/cluster -run
  'Test(IPsecSA|MalformedIPsecSA|FullSetSeq)' -count=1` passed. `go vet
  ./pkg/cluster` passed.
- **Risk**: IPsec apply callbacks are serialized with held-set commit ordering;
  no wire format or legacy-frame behavior changed.
