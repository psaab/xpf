# #9938 — the deny-configuration gate judged a string the dispatcher never acts on

Work log for issue #9938. See `docs/log/README.md` for why this lives here and
not in the repository-root `_Log.md`.

- **Timestamp**: 2026-09-12
- **Action**: The `*-configuration` gate now adjudicates the path the STORE acts
  on, lexed the way the store lexes it, once per acted-upon path. Three heads,
  one lever.
- **Reproduced first**, all three at `6112e580c`, through `AuthorizeConfigMutation`
  itself rather than by reading:

  | row | class | before |
  |---|---|---|
  | `delete security policies p1` (control) | plain deny | refused |
  | `security policies p1` (the gRPC `Set` wire shape) | plain deny | **ALLOWED** |
  | `deactivate security "policies" p1` | plain deny | **ALLOWED** |
  | `deactivate security policies p1` (control) | plain deny | refused |
  | `rename … p1 to … ok` | anchored deny | **ALLOWED** |
  | `rename … ok to … p1` | anchored deny | **ALLOWED** |
  | `copy … ok to … p1` | anchored deny | **ALLOWED** |

- **F-019** is fixed at the gRPC resolver, where `Delete` already supplied its
  verb — the asymmetry between the two was the defect. Guarded against the
  obvious over-fix: an input that already carries `set` must not become
  `set set …`, which would mangle a `load set` replay into a path matching no
  deny — silent, and in the same direction as the defect.
- **F-020** is fixed by using the LEXER rather than `strings.Fields`. A
  quote-stripping pass would have been smaller and is the same defect with a
  smaller diff: the problem is that the gate had its own idea of tokenization.
  The lexer also makes `annotate`'s comment one token, which is what lets the
  path be extracted without a second parse.
- **F-029** is fixed by resolving copy/rename to TWO paths and refusing on the
  first denial. Half a copy is still a mutation of a denied path.
- **The mistake I made inside the fix, and what caught it**: per-verb payload
  extraction made the gate more precise and, in its first version, LESS
  COVERING — a `copy` with no `to`, an `insert` with no `before`/`after` and an
  `annotate` with no quoted comment all became ungated, because "the dispatcher
  acts on nothing" is a true statement about the line and the wrong answer for
  the gate. Caught by `TestEveryFlatVerbIsTakenVerbatimNotReparsed9892` and
  `TestConfigurationDenyHoldsForEveryPathCarryingVerb9890` — cells written for
  OTHER issues whose fixtures happened to use those shapes, which is the
  argument for running full packages rather than `-run 9938`. A malformed
  payload now falls back to gating the whole remainder, keeping the pre-#9938
  behaviour as a floor.
- **Quote provenance is carried out of the lexer**, not inferred from position:
  trimming `annotate`'s last token unconditionally leaves `system` for
  `annotate system root-authentication`, and an anchored deny stops matching.
- **Validation**: a matrix over the verbs the pre-#9938 test file had zero cases
  for (copy, rename, insert, annotate) plus quoting and both endpoint
  directions; a gRPC resolver CENSUS asserting every resolved config line is
  verb-led, with an empty-sweep guard; and two narrowness controls — a class
  with no configuration regexes is untouched, and `edit`/`top`/`up`/`commit`/
  `rollback`/`show` stay ungated, which is the regression an "implicit set"
  reading of an unrecognised leading token would have introduced.
