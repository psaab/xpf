# #12693 — classify landed PROMOTED journal write

- **Action**: Treat a post-rename sync failure from `verifyAndPromote`'s terminal PROMOTED journal write as landed, then clear the terminal journal and report successful promotion.

## Root cause

`pkg/upgrade/kernel_run.go` writes the PROMOTED journal after candidate-first BootOrder, watchdog disarm, promotion marker, and last-roll outcome are already committed. Unlike ARMED and ARMING backstep/restore transitions, the PROMOTED transition returned every error directly. A post-rename directory-fsync error therefore made the promote oneshot exit as an infrastructure failure even though the visible journal was terminal PROMOTED and its external promotion side effects had succeeded.

## Change

- Classify only a typed `*fsatomic.PostRenameSyncError` using the existing `isPostRenameJournalError` (`errors.As`) helper. Log that power-loss durability is unknown, then continue to clear the terminal journal and return the promoted outcome.
- Preserve the existing error path for a failed rename: no typed post-rename error means return the error and do not report promotion success.
- Added `TestPromotePromotedPostRenameSyncProceedsToClear_12693` and `TestPromotePromotedRenameFailureSurfaces_12693`; they exercise the real durable journal write through the fsatomic sync and rename seams.

## Validation

- RED before fix: `go test ./pkg/upgrade/ -run '^TestPromotePromoted(PostRenameSyncProceedsToClear|RenameFailureSurfaces)_12693$' -count=1` failed because Promote returned the injected `PostRenameSyncError` from the visible PROMOTED journal.
- GREEN: `go test ./pkg/upgrade/ -count=1` passed.
- Wrapped-error mutant (replace the `errors.As` helper call with direct type assertion): `TestPromotePromotedPostRenameSyncProceedsToClear_12693` failed with the injected `persist kernel-upgrade journal` error; restoring the helper made the package suite pass. This proves the test detects loss of wrapped-error classification.
- The rename-failure regression passes and verifies the plain rename error is surfaced and the on-disk journal remains ARMED; the test also asserts the error is not `*PostRenameSyncError`.
- `go build ./...` passed.

## Risk

A post-rename error means the PROMOTED journal content is visible, but a power loss may lose the rename because its directory sync failed. The promotion gate passed and candidate-first BootOrder plus promotion marker/last-roll were already written; clearing the terminal journal avoids leaving a completed trial reported as an infra failure. A pre-rename failure remains an error, because PROMOTED was not published.
