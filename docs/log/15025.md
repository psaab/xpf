# #15025 — DPD threshold rendered as dpd_timeout has no effect on IKEv2 (A16-02)

- **Timestamp**: 2026-10-18
- **Issue**: DPD `threshold` (rendered as `dpd_timeout = interval × threshold`) has no effect on IKEv2, the default negotiated version; a dead peer is declared after ~165s regardless of interval × threshold (report A16-02, Medium, 3-way MATERIAL in `research-work.AdQvt1jMKw`).
- **Base**: `origin/master` `2c0e039020`.

## Mechanism (verified at base)

- `deriveDPD` (`pkg/ipsec/ike.go`) returns `Timeout: delay * threshold`; `pkg/ipsec/policy.go` emits `dpd_timeout = <timeout>s` beside `dpd_delay`. The `version` line is emitted only for `v1-only`/`v2-only`, so the dual default (no pin) lets charon initiate IKEv2.
- strongSwan honours `dpd_timeout` for IKEv1 only. Primary source on the validating host: `/etc/swanctl/swanctl.conf` (installed strongSwan) documents the generated setting verbatim as `# Timeout for DPD checks (IKEV1 only).` On IKEv2, DPD liveness (RFC 7296 §2.4) reuses charon's retransmission machinery: a peer is declared dead only after the global `charon.retransmit_timeout` (4.0s) × `retransmit_base` (1.8) ^ `retransmit_tries` (5) budget (≈165s; defaults in `/etc/strongswan.d/charon.conf`) is exhausted — independent of `dpd_delay`/`dpd_timeout` per-probe timing beyond probe spacing. The report's 169s vs configured 6s measurement matches this budget.

## Fix direction chosen

The issue offers two: (a) program charon's global retransmit_timeout/base/tries from the tightest configured DPD, or (b) emit a commit advisory that `threshold` applies to IKEv1 only and correct the README.

Chosen: **(b)**, because (a) is not implementable per-gateway in this codebase:

- `retransmit_*` are daemon-global strongSwan settings (`strongswan.conf`/`charon.conf`), not per-connection swanctl settings. xpf writes only a per-connection `swanctl.conf` snippet (`pkg/ipsec` `renderConfig` → `/etc/swanctl/conf.d/xpf.conf`); no code path writes `strongswan.conf`, and charon is a packaged system daemon whose global file xpf does not own.
- Programming the global budget from the tightest gateway would silently change retransmission for every IKE SA (and the initial IKE_SA_INIT exchange) on the box, and the tightest-of-N gateways would override the rest with no operator signal — a strictly worse silent-behaviour change than the inert knob it replaces.
- The advisory fires exactly where the operator types the inert knob, names the mechanism, and points at the working alternative (`version v1-only`).

## Fix

- `pkg/config/dpd_threshold_ikev2_advisory_15025.go` (new): `appendDPDThresholdIKEv2AdvisoryLocked` collects DPD-enabled gateways with an explicit threshold (`DPDThreshold > 0`, which `parseDeadPeerDetectionNode` only sets from the `threshold` leaf) whose `Version != "v1-only"` (dual default or `v2-only`), sorted for determinism, and appends ONE warning naming them.
- `pkg/config/compiler.go`: called from both compile entries (generic + node-aware), next to the #8357/#7509 advisories.
- `pkg/config/compiler_opts.go`: new `suppressDPDThresholdIKEv2Advisory` opt, set in `lenientCompileOpts()` so the tolerant paths (`Store.Load` boot, `Store.SyncApply` peer sync) stay silent (#8357 doctrine — a committed config must not re-warn on every boot).
- Advisory is a WARNING, never an error: the config is legal, and IKEv1 peers still honour the threshold.

NOT changed: `deriveDPD`/`policy.go` rendering (IKEv1 still needs `dpd_timeout`; rendering is byte-identical), DPD parsing/clamps, charon global config (see above), any dataplane path.

## RED -> GREEN proof

`TestDPDThresholdIKEv2Advisory15025` (`pkg/config/dpd_threshold_ikev2_advisory_15025_test.go`) compiles flat-set gateway stanzas through `CompileConfig`/`CompileConfigLenient` and asserts on `cfg.Warnings`:

- dual-default gateway + `threshold 3` → advisory fires;
- `v2-only` + `threshold 3` → advisory fires;
- controls stay silent: `v1-only` + threshold, dual gateway with interval only (no explicit threshold), gateway with no DPD stanza, and the same dual+threshold config on the lenient path.

- **RED (pristine `2c0e039020` + only the new test file)**: `go test ./pkg/config/ -run TestDPDThresholdIKEv2Advisory15025 -count=1` failed with `dual-default gateway with DPD threshold 3 must warn that threshold is IKEv1-only; warnings=[]` — no advisory on master.
- **GREEN (this head)**: same command passes, controls silent as asserted.

## Risk

- New commit warning for a previously silent (inert) knob: operators with dual/v2 DPD thresholds will see one advisory per commit naming the gateways. It never blocks a commit, is suppressed on boot/peer-sync, and does not fire for v1-only or threshold-less gateways.
- Residual (accepted by the issue's alternative): IKEv2 dead-peer detection still takes charon's global retransmission budget; per-gateway IKEv2 DPD timing would require owning charon's global `retransmit_*` settings, deliberately not done (see Fix direction).
