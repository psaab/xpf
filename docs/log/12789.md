# Issue #12789 — key SYN-rate and sticky SNAT placement

## Root cause

The SYN-rate count-min sketch mixed attacker-controlled keys with public row constants and a per-process seed using FxHasher. FxHash's additive state update makes the hash difference between chosen key pairs seed-independent, so address-word deltas can be selected offline to keep predictable collisions across restarts. The address-persistent SNAT selector used a fixed public salt with FxHasher, making its source-IP-to-pool-slot mapping predictable offline as well.

## What changed

- Replaced both SYN-rate hash paths (IP and IP+destination-port) with `HotPathSeededState` SipHash, preserving each row's independent domain, per-process stability, fixed sketch capacity, and index mask.
- Replaced address-persistent SNAT pool-index hashing with the process-keyed SipHash builder. The per-source selection remains deterministic within a process; existing allocated sessions/leases are unaffected. A new allocation after process restart or on another HA node can select a different pool address, unlike the prior public fixed mapping.
- Added deterministic keyed-hash bucket vectors for both SYN-rate key forms, seed-sensitive/stable mapping checks, pool bounds, and existing per-source stickiness / allocation selection.

## Validation

- `cargo test --bin xpf-userspace-dp screen::syn_rate` — passed (19 tests).
- `cargo test --bin xpf-userspace-dp nat::tests_pool` — passed before the keyed-vector test was added (252 passed, 1 ignored); `pool_snat_keyed_index_vector_12789` passed after it was added.
- Fx-revert mutation checks failed as expected: the SYN IP-cell mapping regression detected the reverted hash, and the NAT keyed-vector regression detected a seed-additive Fx implementation.
- Full crate suite, clippy, and rustfmt were not run by this worker.

## Risk

SipHash costs more per source selection than FxHash. The address-persistent fallback mapping is node-local and per-process; a failover's newly allocated source may choose another pool address. Existing active leases/sessions retain their explicitly selected translated address.
