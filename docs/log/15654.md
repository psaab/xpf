# #15654 — fail closed on L2 ethernet-switching/bridge interface families

- **Issue**: #15654 — `interfaces <if> unit <n> family ethernet-switching` (and `family bridge`) access/trunk VLAN configurations committed as warned no-ops and bypassed the #12090/#12656 filter/policer guards.
- **Files**: `pkg/config/compiler_interfaces_unsupported.go`, `pkg/config/compiler_interface_l2_family_15654_test.go`, `pkg/config/cohort_15199_test.go`, `pkg/config/silent_filter_12090_test.go`, `debian/changelog`, `docs/log/15654.md`.

## Why

`compileInterfaces` builds only `inet`/`inet6` unit families (its family switch has no other arm) and `InterfaceUnit` has no L2 fields; Transparent Mode / L2 bridging is listed Missing in `docs/feature-gaps.md`. Measured on the base: `family ethernet-switching { port-mode access; vlan { members 100; } }` and the trunk spelling strict-committed with only the generic #10707 advisory, braced `family bridge { }` committed with no warning at all, and `family ethernet-switching policer input p1` strict-committed with only #10707 — the #12656 policer arm named only `mpls`/`any` even though `isInterfaceFamilyAF12090` already admitted `bridge`, `ethernet-switching`, and the other unconsumed AFs (`ccc`, `tcc`, `vpls`, `evpn`, `iso`, `inet-vpn`, `inet6-vpn`). `filter` under those families was already rejected by the #12090 keyword walk; policer (and the Junos `sample` spelling) bypassed every guard. Implementing real L2 switching is a net-new dataplane subsystem, so the narrowed acceptance direction is fail-closed at commit.

## What

- In `validateUnsupportedInterfaceStanzasAST` (the existing strict-reject / lenient-warn interface gate, `lenientUnsupportedInterfaceStanzas` plumbing unchanged):
  - policer and `sample` bindings under every AF that `isInterfaceFamilyAF12090` admits but `compileInterfaces` does not build now emit the #15654 no-consumer diagnostic (strict error / lenient warning). `mpls`/`any` policer keeps its #12656 diagnostic; `filter` keeps its single #12090 diagnostic (the #15654 arm skips `filter ` bindings, and the lenient single-diagnostic count is pinned by test).
  - Authored L2 content under `family ethernet-switching` / `family bridge` — `interface-mode`, `port-mode`, `native-vlan-id`, `vlan` (members), `vlan-id` — is rejected with a #15654 diagnostic naming interface, unit, family, and the fixed keyword label. Detection (`l2FamilyContentLabel15654`) covers the flat-set packed Keys tail, hierarchical children, the split `family { ethernet-switching { ... } }` shape, and the packed-unit spelling; it never reports an operator-authored value (a VLAN member spelled `filter` is not named).
  - A bare `family bridge` / `family ethernet-switching` / other AF with no authored content keeps the #15199 warn-only #10707 posture — no new strict rejection and no #15654 warning — so the change is scoped to authored intent, not to the family token alone.
- Tests: `compiler_interface_l2_family_15654_test.go` covers the L2-content matrix (access/trunk, flat/hierarchical/split/packed shapes, both families), the binding matrix (policer flat+braced, `sample`, plus ccc/vpls alignment rows), the acceptance regression (trunk + members + filter/policer never strict-commits), the single-diagnostic filter contract, and controls (supported inet filter hook populated, bare families warn-only, member value never named, inactive stanza pruned).
- Neighbouring tests updated where the new posture supersedes them: `cohort_15199_test.go` replaces the warn-only `family bridge` row with an unknown-AF row (bare bridge stays warn-only, now pinned by the #15654 controls), and `silent_filter_12090_test.go` drops the four vlan-member rows that used real ethernet-switching VLAN content as the filter-as-value carrier (that content is now rejected); the value-vs-keyword contract remains covered by the memberless-range row and by the #15654 member-value control.

## Validation

- Probe on base (temporary test, removed): access/trunk configs strict-committed with only #10707 (or nothing for braced bridge); `policer input` under ethernet-switching strict-committed with only #10707; `filter` already rejected via #12090.
- GREEN: `go test ./pkg/config -run 'TestL2|TestInterfacesOpenWorldWarn15199|TestInterfaceUnsupportedFamily|TestInterfaceUnknownFamily' -count=1` passes (all #15654 cells, #15199, #12656).
- Related gates: the #12090 value-carrier suite (`TestFilterKeywordValuesRemainAccepted12090`, incl. memberless-range rows) passes.
- Known pre-existing failure, not caused by this change: `TestCompactFilterHeadsRejectAndWarn12090/unit-filter` fails identically on pristine `origin/master` with the #15034 untagged-unit error (its `unit 1 filter ...` fixture predates that gate); left untouched.
- Full `go test ./pkg/config -count=1` exceeds the local command window under shared-box load; the focused gate suites above are the exercised validation.

## Risk

Strict commits now reject authored L2 VLAN content and unconsumed policer/sample bindings that previously committed as no-ops; tolerant load / peer-sync still boots those configs with a #15654 warning (#1960 posture). No dataplane behaviour changes, no supported inet/inet6 binding changes, and bare family tokens without content are unaffected. Operators with real ethernet-switching/bridge intent must remove it (xpf has no L2 switching consumer; bridge-domains/IRB remain the supported bridging surface).
