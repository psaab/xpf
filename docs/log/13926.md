# Issue #13926 — deliver admitted interface-NAT UDP fragments

## Why

Non-first fragments of UDP datagrams addressed to a local interface-NAT address have no L4 ports. Without an association to the admitted first fragment, the flowless LocalDelivery path cannot recognize the prior host-inbound service admission and denies the tail.

## What

- Permit plain, same-family LocalDelivery decisions to create fragment associations, while retaining the existing constraints for NAT rewrites and forwarding candidates.
- Install the association from the committed LocalMiss LocalDelivery session so the first fragment's admission is available to later tails.
- Treat an authenticated live-session LocalDelivery association hit as proof of the first fragment's host-inbound admission; continue running per-packet interface input-filter, lo0, and PBR enforcement.
- Add an end-to-end regression using DNS/UDP 53 to avoid IPsec/IKE special handling. It checks admitted head and tail delivery, and fail-closed denial of an orphan tail.

## Validation

- GREEN after fix: the same focused test passed (1 passed, 8157 filtered).
- `git diff --check` passed.

## Risk

The new association is limited to same-family, unmodified LocalDelivery and is session-bound; an orphan or expired-session tail remains subject to the ordinary flowless host-inbound gate. Per-packet interface input filtering, lo0, and PBR remain active on association hits. Full package/build validation has not been run.
