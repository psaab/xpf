# `protocols lldp interface all` looked up as kernel device "all" (#14617)

## Why

`protocols lldp interface all` committed clean but the compiler stored
`Name:"all"` raw, `effectiveLLDPConfig` copied it verbatim, and
`lldp.Manager.Apply` handed `LinuxIfName("all")=="all"` to
`net.InterfaceByName`. No kernel device is named `all` (xpfd renames
managed NICs to `fxp0`/`em0`/`ge-*`), so the name landed in the #6794
unresolved set, was retried forever, and LLDP ran on no interface —
including when a per-interface `disable` entry (e.g. `fxp0`) was present.
The standard Junos stanza was silently dead with only a runtime Warn.

## What

- `pkg/lldp/lldp.go`: `Apply` now expands an enabled `all` entry via
  `expandAllInterfaces` — every kernel-enumerated (non-loopback)
  interface, minus per-interface `disable` entries (either authored
  spelling, compared after `LinuxIfName`) and minus explicitly enabled
  interfaces (kept once under their authored entry). Expansion is
  sorted/deduped. Enumeration failure reports `"all"` as unresolved
  (#6794 retry debt) while explicit entries still apply.
  `InterfaceResolvable("all")` now means "a managed interface exists";
  new helpers `IsAllInterface` (exact, case-sensitive), 
  `ExpandsAllInterfaces`, `AllInterfacesResolvable`, and
  `ManagedInterfaceNames`. Host enumeration is behind the
  `interfacesFn` seam (`SetInterfacesForTesting` in `test_seams.go`).
- `pkg/daemon/daemon_apply_tail.go` + `daemon.go`:
  `effectiveLLDPConfigChecked` refuses `interface all { disable; }`
  (warn + no service) instead of expanding it to silence; the authored
  `all` value is preserved (not rewritten) so config/show/sync fidelity
  holds. `reconcileLLDP` records the expanded inventory
  (`lldpManagedNames`) and `lldpRecoveryDue` re-applies on an unchanged
  `all` config when the inventory changes, so a late-appearing NIC joins
  LLDP; explicit configs never enumerate.
- `pkg/config/compiler_validate_warn_lldp_all_14617.go` (wired in
  `compiler_validate_warn.go`): commit-time advisory naming
  `interface all disable` (#14617), advisory not hard-reject per #1960.
- `pkg/lldp/README.md`: documents the wildcard semantics.

NOT changed: the compiler's stored `LLDPInterface{Name:"all"}` (expansion
lives only at apply time), the #6794 unresolved/recovery contract for
explicit names, or LLDP wire/socket behavior. `interface All` (capital)
is not the wildcard. Loopback is never expanded.

## Validation

- RED (behavioral, on pristine `origin/master` worktree): a probe using
  only pre-fix symbols (`interfaceByNameFn`/`newIfSessionFn` vars) with
  `all` + `fxp0 disable` failed with
  `RED #14617: 'all' reported unresolved (looked up as kernel device): [all]`
  and log `interface not found interface=all kernel=all`.
  The new-symbol test files also fail to build on master
  (`undefined: SetInterfacesForTesting`, `validateLLDPAllDisableWarning`).
- GREEN targeted:
  - `go test ./pkg/lldp/ -run 14617 -count=1 -v` — 3/3 pass

  - `go test ./pkg/daemon/ -run 14617 -count=1 -v` — 2/2 pass

  - `go test ./pkg/lldp/ -count=1` — pass.
  - `go test ./pkg/daemon/ -run 'LLDP|6794' -count=1` — pass
    (one pre-existing CAP_NET_RAW skip on `lo`).
  - `go test ./pkg/config/ -run 'LLDP|9405|TestProtocolInterface' -count=1` — pass.

## Risk

Expansion covers every non-loopback kernel interface present at apply
time (Junos `all` semantics); operators wanting a subset should list
interfaces explicitly or add per-interface `disable` entries. Sibling
#14616 (packed `disable` token) touches disjoint files; after it merges,
`interface all disable;` in packed form will also compile to
`Disable:true` and be refused/warned by this change.
