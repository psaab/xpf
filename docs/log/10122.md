# #10122 — DHCP lease failover gate green

## Scope

`test-dhcp-lease-failover` is a destructive, lab-only acceptance gate for DHCP
lease synchronization across an HA failover. It is intentionally not wired
into `make test`; the run uses the shared loss userspace cluster and must hold
the #1875 cluster lock for deployment and measurement together.

## Hardening

- Selftest mode is source-only (`BASH_SOURCE[0] == $0` for execution). The old
  `DHCP_LEASE_FAILOVER_SELFTEST=1` environment bypass was removed, so an
  inherited variable cannot suppress the live lock or gate.
- Early aborts emit one structured `ABORT_CAUSE=<value>` marker. `die()` and
  the guarded `ERR` trap record the first cause; cleanup records explicit
  restore causes, and the harness includes the marker in summary-less and
  return-code-disagreeing VOID rows. Older logs still use the last `FATAL:`
  line as a fallback.
- DHCP configuration restore now polls immediately and then to a bounded
  deadline, returning promptly when both snapshots match and emitting
  `cleanup:config-restore-timeout` on expiry.

- Namespace cleanup now uses a single sentinel probe: transport errors and
  unexpected output are `cleanup:client-namespace-unverifiable`, while only an
  explicit `ABSENT` result is accepted as clean.

The ten numbered acceptance cells retain their thresholds, ordering, and
pass/fail interpretation. `verify_dhcp_config` changed from a single-shot
check to deadline-bounded polling: this is a deliberate cleanup-path
acceptance relaxation, while a matching snapshot still returns immediately.
The recorded run already completed exact snapshot cleanup, so no locked cluster
rerun was required; the live PASS ledger remains valid.
