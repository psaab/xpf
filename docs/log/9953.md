# 9953 — a `th sport`/`th dport` match with no protocol predicate

## Reachability, settled first

The acceptance item was: *"first enumerate the host-bound paths that reach
`xpf_lo0` without a userspace lo0 gate (fxp0, em0, lo, XFRM, wgN) — if that set
is empty this degrades to a parity/robustness fix."*

**The set is not empty, and it is larger than the interface list suggests.**
Measured at `origin/master` before any code was written.

Native host-bound traffic is PASSED to the kernel on every AF_XDP-bound
interface. `userspace-xdp/src/lib.rs`, the shim's local-destination arm:

```rust
if is_local_destination(&parsed) && !wg_worker_claim {
    record_trace(..., USERSPACE_TRACE_STAGE_LOCAL_DESTINATION, ...);
    return Ok(cpumap_or_pass(ctrl));
}
```

The predicate is keyed on the DESTINATION being local, **not on protocol**, so
SCTP, GRE and ICMP to a firewall-local address take this arm exactly as TCP and
UDP do. The userspace lo0 gate is reached by decap / worker-claimed inner
packets — the complement of this path, not a superset of it.

Add the interfaces that are never AF_XDP-bound at all and are served on the
kernel path — the lifelines `fxp0` / `em0` / `fab*`, which
`forwarding/host_inbound.rs` describes as served "UNCONDITIONALLY (kernel path,
excluded from the AF_XDP deny sets)".

And the chain is global, not interface-scoped: `buildLo0FilterNetlink` fills the
`inet xpf_lo0` **input** chain at `nftLo0FilterPriority`, policy accept, and the
terms carry source/destination scopes but **no `iif` predicate** — so every
packet arriving at the kernel input hook is evaluated against them.

So this does not degrade to a parity/robustness fix. The Medium severity and the
stated fix direction stand as filed.

The issue's own correction to the source report is also confirmed:
`netlink_build.go` `l4Port` is the **guarded** helper; the unguarded pair is
`thPort` and `portMatch`, with the text oracle at `daemon_nft_term_lower.go`.

## The defect

`th sport` / `th dport` load two bytes at an offset into whatever the kernel
calls the transport header and compare them to a port number. Nothing in the
rule establishes that the packet has ports. An operator's `destination-port 22`
term is therefore evaluated against a GRE or ICMP packet, reading two arbitrary
header bytes as a port: an `accept` term fails OPEN when they happen to match, a
`discard` term drops traffic the operator never named.

## The fix

Both renderers emit `meta l4proto { tcp, udp }` alongside a port match carrying
no protocol predicate, driven from one SSOT
(`pkg/nftables/lo0_port_fallback_9953.go`) so the netlink builder and the nft
text oracle agree by construction rather than by the parity CI noticing
afterwards. Protocol numbers resolve through the shared `appid` SSOT rather than
being written as literals, and the text form is the numeric spelling #3436
requires.

Three scope rules, each a fail-open if inverted:

1. **Keys on the emitted predicate being empty, not on `len(term.Protocols)`.**
   An unresolvable protocol token is kept VERBATIM by #6806 so `nft -f -`
   rejects the whole ruleset and the prior generation is retained. That term HAS
   a protocol predicate; supplying a fallback would replace a deliberate
   fail-closed with a rule that loads and matches.
2. **A term with an `icmp-type`/`icmp-code` is left alone.** The ICMP lowering
   already supplies the protocol dependency. Adding `{tcp, udp}` makes the rule
   require the packet to be both ICMP and TCP/UDP — it matches nothing, which is
   merely dead for an `accept` term but a fail-OPEN for a `discard` term.
3. **A term comparing no port is not touched.** Otherwise a `discard` written to
   stop GRE would stop only tcp/udp.

## Evidence

**Reproduction first**, on unmodified master, both render paths.

Netlink builder — all six shapes rendered a bare transport-header load with no
`meta` guard:

```
r00: payload(base=2,off=2,len=2,reg=1) cmp(op=0,reg=1,0016) verdict(1)
r00: payload(base=2,off=0,len=2,reg=1) cmp(op=1,reg=1,0016) verdict(0)
r00: payload(base=2,off=2,len=2,reg=1) lookup(inv=false,set=[0016,00a1]) verdict(1)
r00: payload(base=2,off=2,len=2,reg=1) range(op=0,from=1388,to=1392) verdict(1)
```

Text oracle — `th dport 22 accept` with no protocol predicate.

Controls that pass **before and after**, which is what separates this fix from
"always emit tcp+udp": a term specifying `protocol tcp` keeps its own protocol
and does not acquire UDP; a term with no ports acquires no guard.

**A premise check earned its place.** The unresolvable-protocol cell first used
`junos-gre` as its token — the appid SSOT resolves that to 47, which is the
point of #3436, so the cell would have asserted against
`meta l4proto 47 th dport 22` and tested nothing about #6806. The premise
assertion caught it and the token was replaced with one measured to be
unresolvable.

**The T1 parity gate runs here and passes.** It re-execs under `unshare -rn`,
loads the oracle text with `nft -f -` and the netlink ruleset into the same
netns, and diffs. Its fixture already contains both relevant shapes —
`range-drop` carries ports with no protocol, `reject-term` carries ports with
ICMP types — so it confirms the fix renders bit-identically on both paths,
including the ICMP exclusion.

**But parity could not have found this defect**, and `pkg/daemon/README.md`
already says why in the #6806 entry directly above the one this change adds:
*"Before the fix both renderers dropped the token, so they agreed perfectly
while both were fail-open — an equality/parity check between them could never
have caught this, and the T1 parity CI did not."* #9953 is the second instance
of exactly that: both mirrors emitted the bare port match, so they agreed, and
parity was green throughout. A defect present in both mirrors is invisible to a
comparison between them.

Full touched packages green (`pkg/nftables`, `pkg/daemon`) — not just the
issue's own cells, which is what caught the sibling regression on #9946.

## Mutation matrix — 10 cells, 10 KILLED, 0 escaped, 0 void, 0 apply-failed

Baseline 0 failures; sandbox verified byte-identical to a pre-run snapshot after
every cell. Cells cover the emission on **both** render paths, each of the three
scope rules inverted, the port-presence predicate narrowed to destination-only
and to positive-only (the #3231 `except` shape), the fallback set narrowed and
widened, and the oracle hand-writing the expression instead of taking the SSOT.

**The first run had a genuine escape, and it is the useful part.** Adding `gre`
to the fallback set survived every cell: each one asked only whether a guard was
*present*, and the two render paths take the set from one SSOT so a change there
moves both together and the parity comparison stays green. A `{tcp, udp, gre}`
fallback puts the defect straight back — a `destination-port 22 discard` term
would again drop GRE packets whose header bytes read as 22 — now blessed by a
named constant.

The membership rule is not "protocols we like", it is **"protocols for which the
two bytes at the port offsets ARE ports"**, so the cell now asserts the set is
*exactly* `{6, 17}`. SCTP is the interesting near-miss: its first four header
bytes genuinely are source and destination ports, so the comparison would be
meaningful — it is excluded anyway, because adding it would silently widen every
existing operator rule to a protocol they never wrote. That is a scope change,
not a bug fix, and belongs in the config if it is ever wanted.

One instrument fault was found and fixed: the integrity check named its
snapshots with `tr / _` and reversed it with `tr _ /`, which is not a round trip
when the filenames already contain underscores —
`lo0_port_fallback_9953.go` came back as `lo0/port/fallback/9953.go` and three
non-existent "LEFTOVER MUTANT" lines were reported. The same mangling would
equally have *missed* a real leftover. Snapshots are now keyed by a hash of the
path with a manifest mapping back.
