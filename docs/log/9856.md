# #9856: owner-RG export control response capped at 4096 deltas

## 1. Problem and accepted design

The original issue was verified on the old issue base (`30c30ab6a` through
`e990f30fb`). `ExportOwnerRGSessions` could send an owner-RG session set through
a 4096-entry per-binding response buffer. Once that buffer dropped entries, the
control response could still look successful and the authoritative FullResync
could acknowledge a partial window. The peer then deleted sessions absent from
the incomplete window. The event-stream echo is not an authoritative repair.

The accepted design, preserved from the prior plan and adversarial review, is:

- write-once per-incarnation `install_epoch` predicates instead of an O(N) key
  snapshot;
- a resumable per-worker cursor and a dedicated bounded export FIFO;
- one global open-window token with `(helper incarnation, sequence)`
  continuation validation;
- protocol v2 fail-closed behavior in the Rust helper and Go caller;
- explicit `ExportProvenance` so a later #9630 suppression can distinguish
  command export from `LossResync`; and
- bounded tombstone retention, process-wide export-state accounting, and
  all-or-error FullResync conversion.

The final stack was rebased onto current `origin/master` at `4551d3957`
after the intervening #9842 merge (Go/cluster-only; no conflict with this
lane).

## 2. RED evidence

The current-master baseline was exercised in throwaway worktree
`/var/tmp/9856-red-base` before applying production changes. The three Go RED
cells failed as expected: helper-reported drops were ignored, a v1 helper was
accepted, and a mid-window helper-incarnation change was accepted. The Rust RED
run against that same base produced `10 failed; 0 passed; 6252 filtered` for the
9856 cells. These are the original fail-closed defects, not test-only changes.

The baseline also contains the open #10070 additive-wire ratchet failure. On
clean current `origin/master`, the exact guard reports:

- `DestinationNATRuleSnapshot`: 4 exhaustive literals, ceiling 3 (+1);
- `FabricSnapshot`: 8 exhaustive literals, ceiling 7 (+1); and
- `NeighborSnapshot`: 38 exhaustive literals, ceiling 26 (+12).

The final branch reports the identical three counts. #9856 adds no literals to
any of these structs (its v2 fields are export protocol/status fields), so this
is an evolved pre-existing baseline failure related to #10070; this lane does
not change the ceilings.

## 3. Implementation

- `userspace-dp/src/session/mod.rs`: `install_epoch` remains stable across
  refreshes, terminal removals are harvested only for export-visible entries,
  idle/pre-kick tombstones are discarded, and the tombstone log is capped at
  `MAX_TOMBSTONES_FOR_EXPORT = 8192`. Overflow increments a drop counter that
  the active export transfers into the dedicated buffer metric.
- `userspace-dp/src/session/lookup.rs`: export iteration retains the current
  master exclusion for local-TUN origins.
- `userspace-dp/src/afxdp/binding_state/export_buffer.rs` and
  `userspace-dp/src/afxdp/worker/loop_body/mod.rs`: export opens pause rather
  than drop on a full FIFO; tombstones count as fail-closed drops; each worker
  drains token-tagged entries while the worker remains nonblocking.
- `userspace-dp/src/afxdp/ha/export.rs` and coordinator/session-manager code:
  kick-time worker/ACK snapshots, one open window, continuation pages, ACK
  acquire ordering, terminal probing, and explicit incarnation/sequence
  metadata are wired end to end. Empty owner-RG sets retain the no-op behavior.
- `userspace-dp/src/protocol/control.rs`, `protocol/session.rs`, and the
  regenerated `userspace-dp/tests/fixtures/protocol_wire_v1.json` carry the
  additive v2 request/response metadata. `SessionDelta` carries explicit
  `ExportProvenance`; event-stream suppression behavior remains untouched for
  #9630.
- `pkg/dataplane/userspace/owner_rg_export_paging_9344.go`: the paged caller
  refuses helpers below v2, rejects drops/zero or changed continuation tokens,
  bounds data pages at 512 plus one terminal probe, and caps retained
  accumulator estimates at 256 MiB. The reflected worst-case current-schema
  delta is 1605 bytes, and the estimate is synchronized to that value.
- Paged Go requests use a dedicated export lease and release `m.mu` during
  helper I/O. A narrow, prominent exception to the normal file-scope rule is
  the minimal `requestDetailedAtSocket` seam in
  `pkg/dataplane/userspace/process_control.go`; it consumes an immutable
  socket-path snapshot so the unlocked round trip does not race `m.cfg`.
  `procGen`, config generation, and socket path are revalidated before status
  or page data is accepted. The legacy raw
  `ExportOwnerRGSessions` compatibility API is intentionally unchanged.
- `pkg/dataplane/userspace/owner_rg_export_all_or_error_9699_test.go` uses valid
  nonzero v2 metadata and keeps only the relevant paged/status error cases.

Raw forwarding adapters remain the compatibility surface at
`legacy_dataplane.go:724-729` and `runtime_delta.go:24-26`; daemon FullResync
production sites use the paged API (`daemon_ha_userspace_export.go:67,128`).

## 5. Plan-review history

The prior adversarial review recorded 13 findings before implementation,
including key-incarnation races, snapshot cost, producer/collector deadlock,
replacement and expiry semantics, both-direction protocol skew, provenance,
process-wide memory bounds, control-lock responsiveness, and end-to-end
all-or-error conversion. The revised epoch/cursor/token/provenance design above
is the implementation that addressed those findings. No event-stream
suppression change was folded into this issue.

## 6. Measurements and known gap

No full-cluster throughput, HA failover, or loss-userspace performance run was
performed in this lane. The bounded values proven here are the 8192-entry
per-worker tombstone/FIFO limits, the 1605-byte reflected delta estimate, the
256 MiB Go accumulator bound, the 512 data-page plus one-probe request bound,
and the 512 MiB Rust process export-state assertion. The current-master
#10070 guard remains an explicit baseline gap and is not owned by #9856.

## 7. #9630 handoff

`ExportProvenance::CommandExport(token)` is carried internally so #9630 can
key suppression without confusing it with #2442 `LossResync`. This lane does
not change event-stream suppression behavior. The raw compatibility API remains
available; complete authoritative windows use the paged API.
