# #16790 — Remote deactivate/activate and config-mode show built paths from strings.Fields

- **Timestamp**: 2026-10-25
  - **Action**: Remote `deactivate`/`activate` in `cmd/cli/shared.go` split
    the typed line with `strings.Fields`, so a quoted element
    (`policy "allow web"`) became `policy`, `"allow`, `web"` and
    `JoinConfigPathTokens` re-quoted those literal fragments; the daemon
    then looked up a path that does not exist (fail-closed: path not
    found), and comment words leaked into the wire path. The gRPC handler
    in `pkg/grpcapi/server_config.go` compounded it by re-joining the
    lexed path with `strings.Join`, so the store re-lex
    (`applyEditLine`) split a whitespace-bearing element into two tokens.
    Fix: the client arm now uses `config.ParseDeactivateActivateCommand`
    and refuses on `!ok`, exactly as the console (`pkg/cli`) does; the
    server re-joins with `config.JoinConfigPathTokens`. Folded leg
    (R3-A54-03): remote config-mode `show <path>` also handed
    `strings.Fields` tokens to `handleConfigShow`, splitting quoted
    elements and leaking comment words — it now lexes via
    `lexConfigShowArgs16790` (canonical lexer for the path, bare `|`
    recovered as the pipe token, quoted `"|"` stays data), and
    `splitShowPipe` no longer treats a token merely containing `|` as a
    malformed pipe. NOT changed: `handleConfigShow`'s RPC shape
    (path already travels as `[]string`), the `set`/`delete` raw-remainder
    arms, and the #15166 Unicode-space gate behaviour (a non-lexing line
    is still refused before any RPC).
  - **File(s)**: `cmd/cli/shared.go`, `cmd/cli/show.go`,
    `pkg/grpcapi/server_config.go`,
    `cmd/cli/deactivate_activate_show_lex_16790_test.go`,
    `pkg/grpcapi/server_config_deactivate_quoted_16790_test.go`,
    `docs/log/16790.md`
  - **Validation**: new `TestRemoteDeactivateActivateUsesLexedPath16790`
    and `TestRemoteConfigShowUsesLexedPath16790` (cmd/cli) plus
    `TestSetRPCDeactivateQuotedPolicy16790` (pkg/grpcapi: the store
    deactivates `policy "allow web"` and activate clears it). RED
    verified by stashing the production edits: client wire was
    `deactivate ... policy "\"allow" "web\""`, show path carried literal
    quote fragments, and the server returned `path not found: container
    "policy allow" does not exist`. Plain-path controls unchanged.
    Targeted suites pass post-fix; the full `cmd/cli` suite has 4
    failures that also fail on unmodified base (see commit body).
  - **Risk**: Lines that previously (mis)executed via `strings.Fields`
    but do not lex cleanly (unterminated quote/comment) are now refused
    with `invalid path` before any RPC — fail-closed, matching the
    console. No wire/proto change; the `strings` import dropped from
    `server_config.go` was only used by the replaced join.
