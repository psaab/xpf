## Why

OSPF interface `authentication-key` carried over from RIP/IS-IS/BGP was silently dropped: the OSPF interface schema had no such child and no `closedWorld`, and the compiler switch in `compiler_protocols.go` has no `authentication-key` case. `AuthType`/`AuthKey` stayed empty, the FRR renderer emitted `ip ospf area` with no auth lines, and the adjacency formed unauthenticated while `show configuration` echoed the key. #8443 had refused the sibling `authentication-type` leaf but not the key leaf.

## What

Model-and-refuse `authentication-key` under the OSPF interface node exactly as `authentication-type` is refused: `unmodeledOSPFAuthKeyLeaf()` / `rejectOSPFAuthKey` in `pkg/config/schema_ospf_authentication_8443.go` (shared by the top-level and routing-instance OSPF copies via the shared schema node), naming the nested `authentication { md5 ... }` / `authentication { simple-password ... }` grammar and never echoing the secret (the leaf is a secret leaf, so the typed-leaf diagnostic redacts its value). Strict commit rejects; the tolerant Load/SyncApply path downgrades the same typed-leaf violation to a named `[typed-leaf-tolerated]` warning via the existing #1319/#10515 machinery — not a generic #10707 advisory, since the leaf is now modeled. The OSPF `interface` world stays open (no `closedWorld` added); `authentication { md5 ... }` and `authentication { simple-password ... }` still compile and render, and the same leaf under RIP/IS-IS still compiles.

Spelling-gate registries updated for the two new refused leaves (top-level + routing-instance): `gateBlindUnreachable` 133→135 with justification, members file entries, and the compact-block inventory no-pair count (seven→nine sites).

Note: pristine master at the branch point (`50cc65860`) already fails `pkg/configstore` cells `TestPackedIPsecVPNRun*9088` / `TestPolicerThenNonLeafTail_9882` (unrelated gates, verified on a detached pristine worktree) — the same failures appear on this branch and are not caused by this change. It also carries unrecorded `interfaces ... tunnel clear-dont-fragment-bit` flag leaves in the spelling-gate enumeration (from #13957/#14198), so the spelling coverage/members gates are not green on master either; those unrelated leaves were not folded in (only the two OSPF `authentication-key` arrivals are recorded, and the coverage test's remaining delta vs master is those pre-existing flag leaves). Spelling gates take ~4-8 min each and the full `pkg/config` suite exceeded the 20-min tool window; targeted OSPF/#8443/compact suites were run instead.
