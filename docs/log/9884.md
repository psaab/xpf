## Fix

`Store.Load`'s compile-fail branch now calls
`s.recoverPendingConfirmLocked()` after `s.active = tree;
s.loadRollbackHistory()`, and always returns the original
`ErrConfigCompile`-tagged error joined with any recovery error:

```go
origErr := fmt.Errorf("compile config: %w: %w", ErrConfigCompile, err)
if recErr := s.recoverPendingConfirmLocked(); recErr != nil {
    return errors.Join(origErr, recErr)
}
return origErr
```

`errors.Join` preserves `errors.Is` for both members, so
`classifyLoadError` still yields `loadCompileFailed` and the daemon still
forces bootstrap (`daemon_run_bringup.go:380` passes
`configCompileFailed=true` regardless of `ActiveConfig()`), preserving the
#1960/#1922 fail-closed class even in the expired-healed arm where
`s.compiled` becomes non-nil.

Why reusing the primitive verbatim is safe: recovery never reads
`s.compiled` (expired arm only writes it; live arm only sets prev/timer
fields); the live arm's deferred `PromoteRollback` only assigns
`s.compiled = s.confirmPrevCfg`; no-record / stale / tombstone /
unreadable arms behave as on the success path, so the existing #1960 cells
(no confirm record) are unaffected. `loadUnsharedMarkLocked` (#9530) stays
success-path-only — unrelated, out of scope.

Also updated: the `recoverPendingConfirmLocked` doc comment (it no longer
runs only at the tail of a successful Load) and one accuracy sentence in
the `ErrConfigCompile` bullet of `pkg/configstore/README.md`.
