# Issue #12133 — retry refused PPTP installs

## Why

A successful local PPTP Call-Reply install broadcast to peer workers, but the drain discarded the broadcast result and had no retry record. A full peer queue therefore missed the install and resolved the call's GRE packets as unassociated for the association lifetime, losing the per-call discriminator (forwarded/counting continues; this is not a drop).

## What

`broadcast_pptp_install` now returns both its accepted count and the identities of refusing queues. The control inbox tracks those unsent recipients and retries the install on its periodic drain, without incrementing the local learned count again. A refused retry for the draining worker preserves FIFO order: it installs directly only while that worker's command queue is empty; otherwise it appends the install behind the queued commands, and a full queue leaves the retry pending. The emptiness check and direct install occur under the queue lock, so no producer can put an older queued command between them. A failed direct install is not acknowledged. `PptpInstallError` does not distinguish transient from permanent collisions, so every error retains the retry for the next rate-limited pass. A complete later broadcast supersedes pending retries. CDN and control-channel teardown cancel older pending installs so replay cannot resurrect a torn-down association.

## Risk / residual

No live NIC or cluster was exercised. Existing non-fold residuals remain: a detached retry snapshot can outlive a CDN cancellation (R1), persistent peer refusal has no lifetime/attempt cap but remains rate-limited (R2), and no production scheduling behavior was exercised on hardware (R3). For a refused own recipient, an install accepted into its FIFO queue is applied after older queued teardown commands; an empty-queue collision retains the pending obligation for a later interval. Other missed workers remain unassociated until a retry is accepted or a matching CDN/control-channel close cancels the record. The existing worker-command queue-drop counter records refused enqueue attempts.
