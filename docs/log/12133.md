# Issue #12133 — retry refused PPTP installs

## Why

A successful local PPTP Call-Reply install broadcast to peer workers, but the drain discarded the broadcast result and had no retry record. A full peer queue therefore missed the install and resolved the call's GRE packets as unassociated for the association lifetime, losing the per-call discriminator (forwarded/counting continues; this is not a drop).

## What

`broadcast_pptp_install` returns the accepted count and refusing queue identities. The control inbox tracks recipients still missing an install and retries them on its periodic drain without incrementing the local learned count again. A refused retry for the draining worker is applied directly only while that worker's queue is empty; otherwise it is appended behind the backlog under the queue lock, and a full queue leaves the retry pending. Teardown retries now run before install retries, and both call- and channel-forget retries can target the draining worker as well as peers. Thus when a 4096-command queue refuses both an older CDN and a replacement install, the CDN reaches Q before the install in own-nonempty, own-empty, and peer-drainer modes. For a CDN parsed in the same pass, Q's own time-fenced forget is appended to a non-empty own queue after earlier commands (including an enqueued install); it is applied directly only for an empty queue. Channel-close handling uses the same queue-position rule. Commands for other workers remain peers-only. This combines teardown-first retries with recipient-aware self delivery; install retries are not acknowledged on a local collision.

## Risk / residual

No live NIC or cluster was exercised. The retry gates remain separate timestamps, so a detached retry snapshot can outlive a concurrent CDN cancellation (R1). Refused commands remain rate-limited and have no lifetime/attempt cap (R2). An empty-queue direct install that collides remains pending; if repeated attempts are all direct collisions or full-queue refusals, it can remain pending indefinitely. Any accepted queue push—whether to Q's non-empty own queue or to Q by a peer—acknowledges the retry before command application. If the alias still collides when `apply_worker_commands` handles that queued install, the arm only logs and drops it, leaving no pending retry: retention can end at enqueue as a silent install loss for permanent foreign collisions. The now-covered same-control old-call teardown is delivered before its replacement, avoiding this collision in F-A's scenario. Production scheduling and live dataplane behavior were not exercised (R3). The worker-command queue-drop counter records refused enqueue attempts.
