# Issue #12133 — retry refused PPTP installs

## Why

A successful local PPTP Call-Reply install broadcast to peer workers, but the drain discarded the broadcast result and had no retry record. A full peer queue therefore missed the install and resolved the call's GRE packets as unassociated for the association lifetime, losing the per-call discriminator (forwarded/counting continues; this is not a drop).

## What

`broadcast_pptp_install` now returns both its accepted count and the identities of refusing queues. The control inbox tracks those unsent recipients and retries the install on its periodic drain, without incrementing the local learned count again. If the drainer is itself a refused recipient, it applies the retry directly to its own sessions table because its peer list excludes itself; it cannot consume the shared retry gate while skipping its own record. A complete later broadcast supersedes pending retries. CDN and control-channel teardown cancel older pending installs so replay cannot resurrect a torn-down association.

## Validation

- **RED before** (STEP-0 base `1c384b9a4`): `a_refused_pptp_install_reaches_the_worker_on_retry_12133` failed after the full queue was cleared; the refused worker never received the install.
- **GREEN after**: `cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp pptp` passed 74 tests (7,527 filtered).
- **F1**: `a_refused_worker_applies_its_install_retry_to_its_own_table_12133` models two workers whose peer lists exclude themselves. Q drains first after its queue clears and resolves both call aliases in its own table without counting a second local learn.
- **F2**: `a_cdn_cancels_only_its_call_and_the_next_call_still_retries_12133` verifies a CDN for A preserves B's retry on the same channel. Inbox cells pin older-reply/stale-ack protection and disconnect/channel-close timestamps; `a_complete_rebroadcast_clears_the_older_install_retry_12133` pins retry supersession.

## Risk / residual

No live cluster was exercised. A worker that was a refused recipient applies its pending install to its own table on a later drain; other missed workers learn when a drainer can enqueue the retry to their queues. If their queues continue refusing, they remain unassociated until a retry is accepted or a matching CDN/control-channel close cancels the record. The existing worker-command queue-drop counter records refused attempts.
