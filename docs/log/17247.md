# #17247 — Unify the NAT undefined-scope gate and remove its inert record

## Why

The NAT undefined-scope strict validator and `NATUndefinedScopeRuleSetNames` independently walked the same source, destination, and static NAT axes. The second walk rebuilt the predicate and encoded `{kind,name}` as `kind + "\x00" + name`. Its `Config` field had no readers, and `nat_cohort_15278_test.go` claimed the field was used for a dataplane skip that did not exist. Adding a new skip would change NAT rule/snapshot behavior; the validated finding is warning/maintenance-only, so #17247 removes the unused field rather than inventing a dataplane disposition.

## What

- Added `natUndefinedScopeFindings` as the single source/destination/static walk. Strict validation returns its first finding; tolerant warnings format the same per-axis findings, preserving their previous ordering and text.
- Removed `NATUndefinedScopeRuleSetNames` and `Config.LenientNATUndefinedScopeRuleSets`, including the kind-NUL-name encoding and stale test claim.
- Added a projection regression over all three NAT kinds, every source scope axis, strict-first-error behavior, warning strings, and structured rule-set references. Added a userspace snapshot test proving tolerant undefined-scope references remain present with their authored scope, alongside a healthy sibling.
- Updated the unit-less interface-scope documentation and snapshot-shape rationale. The compile-time-only field removal changed the pre-exemption Go reflection digest but not serialized snapshot JSON or `ProtocolVersion`; the merged post-exemption walk skips `ConfigSnapshot.Config`, so the removed field contributes no line to the current digest.
