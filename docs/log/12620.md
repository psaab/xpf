# 12620 — gate AppID conntrack restamps on catalog changes

- **Action:** eliminate the per-new-connection conntrack-map lookup when the compiled AppID catalog is unchanged.
- **Files:** userspace-dp `AppCatalog`, `SessionTable`, poll-descriptor revalidation, associated regression tests; this record.

## Why

#12191 correctly refreshed stored AppIDs after an allowed stale zone-policy hit, but every newly installed session starts with an unvalidated policy stamp. The first stale permit therefore entered the restamp path for every new connection. The equal-AppID optimization avoided the map write, not the lookup syscall, leaving the measured steady-state conntrack read per connection.

## What

- `AppCatalog` now has a nonzero content fingerprint (sorted catalog entries, excluding reserved AppID zero). Ordering-only snapshot changes preserve the fingerprint; catalog-content changes produce a new fingerprint.
- Each local session records the worker's current catalog fingerprint at install. Imported sessions start unvalidated (epoch zero), since peer-derived state has not been checked against the local catalog.
- The poll pass publishes the current catalog fingerprint to its worker-owned `SessionTable`. Forward and reverse stale-permit paths read and update the conntrack AppID only when the canonical session's label epoch differs. A successful/best-effort no-map operation records the fingerprint; a failed live-map read/update leaves it stale for a later retry. Zone-policy permit/revoke semantics and reverse-to-forward tuple resolution are unchanged.
- The regression drives two distinct newly installed connections under one unchanged catalog and asserts zero restamp lookups. The existing label-change path still proves a catalog change refreshes the forward row once, and reverse-DNAT/IPv6 cases pin canonical row and post-NAT resolution.

## RED / GREEN

- **RED / mutant:** removing the catalog-epoch condition from the reverse restamp gate made `new_pair_same_app_id_skips_restamp_write_and_later_restock_works_12191` fail: the second new connection performed one conntrack lookup where zero was expected.
- **GREEN:** the focused regression passed after restoring the epoch gate. The `policy_revalidation` filter passed 44 tests; `app_catalog` passed 16; the focused two-connection regression passed independently. The AppCatalog epoch test covers order independence, catalog change, and the zero default sentinel.

## Risk

The fingerprint is process-local and is only used for equality checks; it is not serialized or exposed as a protocol field. Catalog compilation is a config-apply operation and owns the fingerprint allocation/sort; packet processing remains allocation-free. Imported sessions deliberately pay one local reconciliation the first time a stale permitted hit reaches this path. No live-cluster mutation was performed.
