# Issue #17176 — R4-Q50-02: triplicated durable tree copy

- **Issue:** The crash-durable tree copy (`copyTree`/`copyTreeFsync` +
  `copyFileFsync` + `preservedMode` + deepest-first dir fsync) existed three
  times: `pkg/upgrade/runner.go`, `pkg/upgrade/runtime/seed.go`, and
  `pkg/upgrade/stagedgen/fsutil.go`. Only the `pkg/upgrade` copy had the
  `copyTreeSyncDir` test seam (52411be163), so deleting the directory-fsync
  loop in the seed or stagedgen copies failed no test. STEP-0 re-check on
  current `origin/master` (47a93d76fd): defect live — all three copies
  confirmed at the issue anchors.

- **What:** Added `pkg/fsatomic/copytree.go` with the single shared primitive:
  `CopyTreeDurable(src, dst string, opt CopyTreeOptions) error` with
  `CopyTreeOptions{Hash io.Writer; SyncDir func(string) error}`, plus
  exported `CopyFileDurable` and `PreservedMode`, and the unexported
  `fsyncDirsDeepestFirst` moved verbatim (deepest-first by separator count).
  `Hash` receives the sorted relpath+"\x00"+content stream (nil = no hash);
  `SyncDir` nil selects the package-default `copyTreeSyncDir` var
  (`= SyncDir`) so the fsync loop is test-pinnable in fsatomic.
  - `pkg/upgrade.copyTree` is now a wrapper passing a sha256 hash and the
    existing `copyTreeSyncDir` seam (retained: `runner_test.go` and
    `cut_boundary_snapshot_10307_test.go` drive it end-to-end); its checksum
    stream is byte-identical, so `copyTreeChecksum` parity is unchanged.
  - `runtime.copyStagedToVersion` and `stagedgen.Publish` now call
    `fsatomic.CopyTreeDurable(..., CopyTreeOptions{})` directly.
  - Deleted all three private `copyFileFsync`/`preservedMode` bodies, both
    private `copyTreeFsync` bodies, and the runner's private
    `fsyncDirsDeepestFirst`. No shims/aliases left. Error-prefix change:
    unsupported-type errors now read `CopyTreeDurable: unsupported file
    type…` (was `copyTree:`/`copyTreeFsync:`); grep found no test or caller
    asserting the old strings (callers wrap with their own context).

- **Acceptance:** `grep -rn 'func copyFileFsync\|func preservedMode\|func copyTreeFsync' pkg`
  = 0 (verified, exit 1). Call-graph grep: `CopyTreeDurable` is reached from
  `pkg/upgrade/runner.go` (snapshot), `pkg/upgrade/runtime/seed.go` (seed),
  and `pkg/upgrade/stagedgen/stagedgen.go` (generation publish).

## Risk

Behavior-preserving consolidation: the shared body is a verbatim merge of the
three identical copies (only the optional hash re-read and the error prefix
differ, both covered above). The retained `copyTreeSyncDir` seam in
pkg/upgrade preserves the cut-boundary test's timing hook. Residual: the two
moved fsync tests now pin the fsatomic copy; the upgrade wrapper is pinned
end-to-end by its own retained cells.
