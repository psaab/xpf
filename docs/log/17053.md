# #17053 — Delegate session_glue connected-prefix LPM to the canonical fib helper

- **Timestamp**: 2026-10-27
  - **Action**: Deleted the eight `len >= best_len` loops in
    `session_glue/resolution.rs` (owner + ifindex variants, V4/V6 ×
    rows/ledger), the family-blind `interface_in_table_scope`, and the
    dead `local_v4` early-return; promoted fib.rs
    `connected_lpm_ifindex_{v4,v6}` and `instance_owns_table_{v4,v6}` to
    `pub(in crate::afxdp)` and added one canonical dispatcher
    `connected_lpm_ifindex(state, ip, table: Option<&str>, sources:
    ConnectedSources)` (`LedgerOnly` for the #15917 terminal fallback,
    `RowsThenLedger` for the session_glue attribution: FIB rows first,
    ledger only on a rows miss). The per-family twins now delegate to
    the dispatcher; the ledger kernels keep the copied loop bodies
    verbatim. `connected_owner_rg_for_target_in_table` is
    `owner_rg_for_flow(connected_lpm_ifindex(..))` plus the
    interface-NAT tail, still probing the #16217 build-time index
    first when it is current; `connected_ifindex_for_target_in_table`
    is a thin `RowsThenLedger` delegate. The connected-owner index in
    `types/forwarding/state.rs` now shares the canonical tie rule:
    slots store `(table_key, ifindex, rg)` (ledger entries negated as
    `-ifindex - 1`), the rebuild keeps the LOWEST ifindex at equal
    (table, len, network), the probe is two-phase (FIB pass, then
    ledger only on a full FIB miss) preserving the FIB-beats-longer-
    ledger precedence pinned by #16217. Both no-table wrappers
    (`connected_owner_rg_for_target`, `connected_ifindex_for_target`)
    are `#[cfg(test)]` — their only callers are tests. Added
    `connected_tie_lowest_ifindex_both_orders_17053` (same /24 on
    ifindexes 5/RG2 and 24/RG1 in both insertion orders, in rows and
    ledger, asserting identical lowest-ifindex/RG from the
    session_glue helpers, the canonical LPM and the rebuilt index)
    and the `connected_lpm_single_source_structure_17053` guard.

  - **Risk**: Equal-length ties now resolve to the lowest ifindex
    where the legacy scan took the last-iterated row — the intended
    #17053/#15917 unification; a tie that previously (arbitrarily)
    named the higher ifindex will now name the lower one, so HA
    ownership attribution for genuinely tied prefixes changes to the
    deterministic canonical answer. The index slot encoding changed
    (u32 seq → i32 ifindex, ledger negated); the rebuild/probe pair
    is covered by the 16217 equivalence cells plus the new
    both-orders cell. No other behavior change: longest-prefix,
    table scoping, FIB-then-ledger precedence and the interface-NAT
    tail are preserved; the dead `local_v4` branch returned the same
    0 as the fallthrough.
- **Timestamp**: 2026-10-27 (fold, Rev18099Opus F1/F2)
  - **Action**: F1 — the canonical dispatcher
    `connected_lpm_ifindex` now returns `Option<i32>` (`Some` =
    matched, even when the winning ifindex is 0; `None` = no match)
    and `connected_owner_rg_for_target_in_table` returns
    `owner_rg_for_flow(winner)` on `Some` without the old
    `ifindex > 0` guard, so a matched RG-0 winner (missing egress row
    -> RG 0) is final exactly like the index's `Hit(0)` and never
    falls through to the interface-NAT tail; only `None` reaches
    Source 2. The per-family twins and
    `connected_ifindex_for_target_in_table` map `None` to 0 at the
    edge. Added
    `connected_winner_rg0_missing_egress_no_nat_tail_17053`
    (connected /24 winner on ifindex 0 with no egress row -> RG 0,
    same target as an RG1 interface-NAT entry: scan must answer 0,
    index must answer `Hit(0)`). F2 — the ledger slot negation in
    `rebuild_connected_owner_index` (v4+v6) is now
    `ifindex.checked_neg().map(|n| n - 1)`, skipping the unencodable
    `i32::MIN` key instead of wrapping it into a positive FIB-alias;
    the >0 kernel-ifindex invariant is documented at the slot-shape
    comment on the index fields.
