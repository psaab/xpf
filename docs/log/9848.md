## Kernel ordering

The running host reported `7.0.13+deb14-amd64`, and the matching Debian
`linux/7.0.13-1` source is available at:

<https://sources.debian.org/src/linux/7.0.13-1/net/core/dev.c/>

The ordering premise is **verified** against that source:

- `dev_xdp_uninstall` at `net/core/dev.c:10389-10416` clears an attached
  XDP link's device pointer (`link->dev = NULL`) under the
  `auto-detach link from net device` comment;
- `unregister_netdevice_many_notify` calls `dev_xdp_uninstall` before building
  the link notification, at `net/core/dev.c:12433-12454`; the
  `rtmsg_ifinfo_build_skb(RTM_DELLINK, ...)` call is later in that range;
- `bpf_xdp_link_fill_link_info` at `net/core/dev.c:10619-10631` reports the
  ifindex from the device pointer, therefore reports zero after the uninstall
  clears it.

The implementation remains defensive and does not trust the DELLINK payload:
every DELLINK wakes the existing coalescing gate path, which performs
`reassertTransitGate`, and every successful or failed subscribe attempt also
re-reads `AttachedXDPLinkCount`. Thus the live kernel count is authoritative
even if a future kernel changes the relative event ordering.

## Fix

- `pkg/daemon/daemon.go:135-142` adds a watcher-specific subscription seam and
  resubscribe backoff, separate from the SNMP monitor seam.
- `pkg/daemon/transit_gate_link_watch_9848.go:13-25` starts the watcher on the
  Run `WaitGroup`; `:27-50` owns cancellation and resubscribe backoff;
  `:53-98` owns one subscription, reasserts after success and failure, and
  wakes the coalescing gate path for `unix.RTM_DELLINK` only.
- `pkg/daemon/daemon_run.go:590-594` starts it beside the always-on proxy-ARP
  loop inside the dataplane-enabled Run path. It uses the Run context and the
  same WaitGroup, so shutdown closes the netlink `done` channel and joins the
  watcher before the fail-closed teardown. It is independent of SNMP and HA,
  and is not bootstrap-gated.
- The existing one-second gate tick remains as the completeness fallback for
  kernel changes that produce no observable event.

A closed netlink update channel (including vishvananda/netlink's ENOBUFS
receive-error path) is treated as recoverable. The watcher backs off,
resubscribes, and reasserts immediately after the replacement subscription;
this is the required lost-notification repair. DELLINK wakeups are coalesced
through `signalTransitGateWake`, so a burst of unregisters incurs one fresh
kernel-truth census rather than one synchronous census per event.
