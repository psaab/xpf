# #16523: `AnnotatePath` could not resolve a node with three or more keys and an odd count

- **Timestamp**: 2026-10-24
- **Action**: `AnnotatePath` in `pkg/config/ast.go` resolved its target
  only through `navigatePath`/`navigatePathWidth`, the pair-consuming
  display walker. For a 3-key leaf such as the address-book entry
  `address a1 10.0.0.1/32` the walker consumes the (`address`, `a1`)
  pair, then descends into the leaf's nil children looking for
  `10.0.0.1/32` and returns nil, so `AnnotatePath` returned
  `ErrPathNotFound`. `FormatSet` emits the full identity in its
  `annotate ... address a1 10.0.0.1/32 "<comment>"` line, so replaying
  the box's own `display set` output — and `load merge` of a commented
  Junos file — aborted atomically on the comment line. Fixed by
  resolving annotate targets by full identity first: the new
  `resolveExactPath` helper descends level by level, choosing the
  sibling `matchNodeKeysFull` matches against the remaining path
  (exact whole-key-list match preferred over a proper prefix, then the
  widest consumption), and resolving only when the WHOLE path is
  consumed exactly. When no exact walk consumes the whole path,
  `AnnotatePath` falls back to the existing `navigatePath` display walk,
  so prefix addressing is unchanged: name-only (`... address a1`),
  bare-keyword (`... address`, annotation on the FIRST sibling, #3980),
  and wider-node-by-leading-keys (`system host-name` for
  `[host-name fw1]`) all resolve exactly as before, and a non-matching
  path still fails closed with `ErrPathNotFound` and mutates nothing.
  Added `pkg/config/annotate_odd_arity_16523_test.go` (flat and
  hierarchical 3-key leaf resolution landing on exactly the addressed
  sibling, full FormatSet -> replay round-trip through
  `ParseAnnotateCommand` + `AnnotatePath`, prefix-fallback controls,
  and fail-closed/mutation-free not-found cells) and
  `pkg/configstore/annotate_odd_arity_16523_test.go` (export via
  `ShowCandidateSet`, replay through `LoadSet`, flat and hierarchical
  `LoadMerge`, re-export pinning the single a1 annotate line).
- **File(s)**: `pkg/config/ast.go`,
  `pkg/config/annotate_odd_arity_16523_test.go`,
  `pkg/configstore/annotate_odd_arity_16523_test.go`,

  TestAnnotate$'` (#4587 + store round-trips) pass. RED-verified by

  `LoadMerge` cells fail with the original
  `path not found: security address-book global address a1 10.0.0.1/32`,

  TestActivate|TestShow'`) passes (107s); the unfiltered package suite

  nodes beyond address-book is not enumerated — the exact walk is
  arity-agnostic, so any such node now resolves by full identity, but
  only the address-book shape is pinned by a cell.
  `load override` and HA sync were unaffected before and are untouched.
