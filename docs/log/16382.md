# #16382 — aged RG1 failover permanent-zero: activation-pending HA sets laundered by the session fast path

- **Timestamp**: 2026-10-24
- **Context**: filed from the FZCellsProof2 acceptance failure on PR
  #16217 head `be259c5596` (39 SUM zero intervals in both runs, first
  at FO+1 s, permanent through failback). fw1's Backup rows were
  Established (`Timeout: 1800`) and the WAN neighbor REACHABLE at
  d28, yet the fabric-adoption gate's last resolution for the wire
  tuples read `ha_inactive` pre- and post-FO and fw1 forward
  `Pkts: 0`. The issue prescribes a fw1 per-tuple gate trace
  discriminating which gate arm declines at the FO instant. That
  trace (D31, run on the #16217 lane) found the gate inputs
  themselves stale: the servicing workers' cached RG1 triple stuck
  at `(active=false, lease=Inactive)` with the fresh
  `forwarding_active_rgs` set EMPTY for seconds after RG1 already
  read active in the status view.
- **Root cause** (in `try_refresh_ha_leases`,
  `userspace-dp/src/afxdp/ha/session_domain.rs`, present verbatim on
  current master): for a mixed watchdog set — siblings matching, one
  RG activation-pending (stored inactive, incoming active) — the
  pending RG was kept inactive but the whole set still stored with
  `refreshed > 0` and returned `Served`. The fast path had therefore
  consumed the set: the locked path
  (`Coordinator::update_ha_state`, with epoch bump,
  `RefreshOwnerRGS`, prewarm, neighbor warm) never published the
  activation for that set, and a later tick could launder the pending
  activation into a match-arm lease mint without any locked
  transition. At the failover instant the gate correctly read its
  (stale) inputs and declined `ha_inactive`; the defect is the
  publication routing, not gate arithmetic.
- **Fix**: `try_refresh_ha_leases` now returns `NeedsLock` for the
  whole set whenever any RG is activation-pending (stored inactive,
  incoming active), regardless of sibling matches — exactly the
  routing the pure-activation case (`refreshed == 0`) already had.
  `NeedsLock` makes the session-socket handler answer
  `HA_REFRESH_NEEDS_CONTROL_SOCKET`, routing the set to the locked
  path whose retry publishes the transition with its side effects.
  Demotion arms are unchanged: stored-active mismatch still mints
  only while the stored lease is valid; an expired stored-active is
  never resurrected. The doc contract above the function is updated
  to state the activation-pending rule.
- **Scope note**: this lands the #16382 lease-publication fix on
  current master as a standalone change. The PR #16217
  fabric-adoption stack it was diagnosed alongside remains open and
  unmerged; the live aged-failover acceptance (ZERO zero intervals
  TWICE) was NOT re-run for this standalone commit and remains the
  #16217 lane's gate. On the #16217 lane the same fix plus Wire30
  still failed live (39 zeros), with the residual narrowed to the
  per-worker snapshot visibility race at the FO instant — this fix
  removes the fast-path laundering, it does not by itself claim the
  aged-failover cure.
