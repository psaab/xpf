# #12157 — Same-RG RETH member identity

## Why

The virtual RETH MAC previously keyed only on cluster, redundancy group, and node. RETHs sharing an RG therefore shared a MAC, while recovery renamed the first interface with that MAC. When a member name was missing, map iteration could select and cycle a healthy sibling. The networkd compiler used the same incomplete recovery key.

## What

- Add a RETH index to the final MAC octet, preserving the existing reth0 encoding and assigning distinct addresses to same-RG RETHs.
- Preserve canonical `rethN` suffixes and deterministically assign unused indexes to structurally valid noncanonical RETH owners; reject more than 128 configured owners at strict validation.
- Recover by the indexed MAC, excluding configured sibling names. During upgrade, accept the old shared MAC only when the remaining candidate is unique; ambiguous matches are left untouched. Apply the same indexed and legacy-safe lookup in the networkd compiler.
- Treat a successful recovery rename as an apply-wide link cycle so addresses and AF_XDP workers are repaired and the worker lease is released once after the RETH loop.

## Validation

- RED on that base: `go test ./pkg/daemon -run '^TestRenameRethMemberSelectsIndexedSameRGMember_12157$' -count=1 -v` failed for sibling-first ordering, leaving the recovering member as `enp8s1` and renaming the healthy sibling to the target name.
- `go test ./pkg/config ./pkg/cluster ./pkg/daemon ./pkg/dataplane ./pkg/ra -run 'Test(RethVirtualMAC|RethMAC|RenameRethMember|SameRGRETHRecoveryFullApply_12157|CompilerRethRecovery|DaemonPassesRenameRethMemberBeforeCycleHook_6911)' -count=1` passed; `go test ./pkg/config -run 'Test(RethIndex_12157|StrictRethOwnerLimitMatchesVirtualMACCapacity_12157)' -count=1` passed. The full-apply cases cover missing `reth0` and `reth1`, verify the healthy sibling is not cycled, and check one worker-lease acquire/release.
- `gofmt` completed for changed Go files; `go build ./...` passed.
- Broader `go test ./pkg/config ./pkg/cluster ./pkg/daemon ./pkg/dataplane ./pkg/ra` was not clean: cluster, daemon, and RA passed; config hit the 10-minute timeout and reported non-RETH inventory, auth/parser, routing-instance, and spelling-gate failures; dataplane reported non-RETH interface-map and retirement-canary failures. Focused RETH regressions passed independently.

## Risk

The complete live-cluster failover, forwarding, and throughput proof remains a residual runtime gate; no live cluster was mutated. On upgrade, a legacy shared-MAC candidate is accepted only when unique after configured sibling names are excluded; otherwise recovery safely declines to rename.
