# #12090 — reject unbound filter spellings

- **Issue**: #12090 — interface and forwarding-options filter spellings could commit clean while no compiler/dataplane consumer used them.
- **Branch**: `fix/12090-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12090`
- **Base**: `9185c248904a38e909212a246442fbe19604ed0e`

## Why

The existing interface reader consumes a single-name `filter input|output` below `unit <n> family inet|inet6`, in both compound `family inet` and split `family { inet { ... } }` AST forms. Unit-level `filter`, `simple-filter` aliases, and forwarding-options filters were accepted by open-world AST subtrees but had no hook, so strict commit gave a false impression that the requested filter was active.

## What

- Extended the interface unsupported-stanza AST gate to reject unsupported `filter`/`simple-filter` keyword heads outside the typed unit-family hook. Packed-tail inspection is limited to schema-resolved nodes and legacy family/AF shapes; apply statements and their authored value tails are not scanned.
- Accepted the split-family consumer path (`family { inet|inet6 { ... } }`) alongside compound family nodes, preserving the compiler's v4/v6 hooks.
- Added a forwarding-options AST gate that rejects unsupported `filter` and `simple-filter` keyword heads, including compact packed heads. A relay `filter` node is treated as an instance name only beneath an unnamed `server-group` or `group` container.
- Kept tolerant load / peer-sync behavior non-bricking: interface cases use the existing lenient interface gate, and forwarding-options cases warn through a dedicated lenient option.
- Expanded the population and keyword-values tests across flat-set, hierarchical, split-family, compact, and braced value slots. The supported family `filter input|output` control must compile to its non-empty v4/v6 unit hook; unbound filter keyword heads fail strict commit with identifying #10293/#12090 diagnostics.
