# #16429 — port-mirroring: Linux-spelled bare input installed as unit-0 VID-0-only row (R3-F06-01)

## Defect

`buildMirrorConfigSnapshots` (pkg/dataplane/userspace/mirrors.go) indexes
each interface row under its `Name` and its `LinuxName`. Production rows
are base-then-units (pkg/dataplane/userspace/interfaces.go), and an
untagged unit 0's `LinuxName` equals the base netdev name
(`snapshotLinuxName` collapses unit 0 onto the parent). The #16063
`nameKeyed` guard only protected keys equal to some row's `Name`
(`ge-0/0/1`), so the unit-0 row overwrote the base row's scope under the
Linux key `ge-0-0-1` with `{vlanID:0, unitScoped:true}`.

A mirror input written in Linux spelling, `input ingress interface
ge-0-0-1`, therefore installed as a unit-0 VID-0-only scoped row: Rust
stores scoped rows in `mirror_configs_scoped` only, a tagged sibling's
`(ifindex, VID 100, unit 1)` lookup misses, the bare fallback map holds
no row, and nothing is mirrored — while no exclusion is recorded, so
`show forwarding-options port-mirroring` reports the instance installed.
The Junos spelling `ge-0/0/1` resolved correctly to the base row. This
violates the #15113 contract: a bare physical input matches every unit
on the port; a unit input matches only its own VID.

## Fix

- `pkg/dataplane/userspace/mirrors.go`: track `baseLinuxKeyed`, the
  `LinuxName` keys written by non-unit (base) rows. A unit row no
  longer overwrites the ifindex/scope of such a key, so the bare Linux
  spelling resolves with the base row's unscoped scope. The guard is
  deliberately narrower than "never index a unit row under a shared
  netdev": the #15651 Linux unit spelling (`ge-0-0-1.0`) is a distinct
  key indexed in the same block and still resolves with the unit row's
  own scope, and a unit row that is the first writer of a `LinuxName`
  key no base row wrote (e.g. a VLAN child) still indexes it. Output
  resolution in the same function only reads `ifindexByName`, whose
  value for a shared netdev is identical for base and unit-0 rows, so
  it is unaffected.

Deliberately NOT done: keying scope by the denoted row at lookup time
(the issue's alternative). The index-time guard is the smaller change
and keeps every existing key's first-writer semantics; the lookup arms
(raw, `LinuxIfName`, `ResolveKernelIfName`) all read the one map.

## Risk

- Behaviour change is scoped to mirror inputs (and, value-identically,
  outputs) whose `LinuxName` key was written by a base row before a
  unit row on the same netdev: they now take the base scope instead of
  the unit-0 scope. That is exactly the bare-input contract; unit
  spellings (`ge-0-0-1.0`, `ge-0/0/1.0`, VLAN children, tunnel units)
  resolve as before, and the #16063 shared-tunnel refusal is untouched.
- No wire/protocol change: `MirrorConfigSnapshot` fields are unchanged;
  only the scope values the Go builder computes for one spelling class
  change. Rust needs no change — an unscoped row already lands in the
  bare map and matches every VID.
