# #17106 — screen extractor folds the shared IPv6 extension-header walk

- **Timestamp:** 2026-10-27
- **Branch:** `campaign/17106`
- **File(s):** `userspace-dp/src/afxdp/frame/inspect.rs`, `userspace-dp/src/screen/extract.rs`, `userspace-dp/src/screen/tests.rs`, `userspace-dp/src/screen/tests_9901_walker_parity.rs`, `userspace-dp/src/afxdp/frame/README.md`

## Action

- Extended the ONE shared walker (`walk_ipv6_ext_chain`) with the two screen-only sightings: `ExtChainWalk::rh_source_route_seen` (any readable Routing header with type 0/1, gated on the type byte at offset+2 being readable — a shorter Routing header is `Truncated`, matching the old screen `offset + 4` check) and `ExtChainWalk::second_non_atomic_seen` (latched by `record_fragment_sighting` on a SECOND readable non-ATOMIC Fragment header; ATOMIC repeats never set it).
- Deleted the screen's private walk (`screen/extract.rs` `for _ in 0..8` loop, local `NEXTHDR_*` consts, the release-compiled-out `debug_assert_eq!` against `ipv6_ext_header_is_traversable`, its own AH advance and Fragment logic) and the second AH walk (`ipv6_ah_sighted` at extract entry). `extract_screen_info` now calls `walk_ipv6_ext_chain(frame, l3_offset)` once in its IPv6 arm and folds: `is_fragment`/`is_first_fragment`/`ip_frag_off`/`frag_data_off` from `first_non_atomic_fragment` (header_offset for `frag_data_off`), `tcp_offset` from `L4(off, 6)`, AH from `ah_present`, source-route from `rh_source_route_seen`, the #9114 sentinel protocol recovery from the governing Fragment header's NextHdr byte on a non-first sighting, `Truncated` -> `Err(TruncatedIpv6ExtChain)`, duplicate -> `Err(MultipleIpv6FragmentHeaders)` (checked after the outcome mapping, so a truncated second header still reports Truncated).
- Explicit OverLimit decision: the old private walk returned `Ok` with `tcp_offset = None` on an 8+ chain; the screen now maps `OverLimit` to `Err(TruncatedIpv6ExtChain)` ("ip-malformed"), matching the forwarding path's fail-closed posture (`frame_l4_offset` -> None, `ipv6_ext_chain_over_limit` -> drop). An uninspectable chain no longer passes unscreened merely for being long rather than short.
- Acceptance greps: `for _ in 0..8` in `screen/extract.rs` == 0; `ipv6_ah_sighted` in `screen/extract.rs` == 0; the extractor calls the shared walk at its IPv6 arm (pinned code-only by `extractor_references_the_shared_ext_header_set_9901`, repinned from the deleted generic-arm guard).
- Updated the #6885 depth cell (only as the OverLimit decision requires): at n >= 8 it now asserts `Err(TruncatedIpv6ExtChain)` explicitly; the resolved-depth agreement vectors are unchanged. Updated the #9901 parity R1 to `Truncated|OverLimit` and the README's deliberate-keep-out wording (screen is no longer a keep-out; NAT64 translation-ineligibility remains the sole one).

## Risk

- Behaviour change is deliberately fail-closed only: over-limit (8+) IPv6 extension chains on screened zones now drop as `ip-malformed` instead of passing with `tcp_seq == 0` unscreened. Forwarding already dropped the same chains flowless, so no newly-forwarded traffic appears; screened legitimate traffic with <=7 extension headers is byte-identical (parity sweeps above).
- The shared walk gains two bool writes on ext-headered chains only (Routing type read, second-fragment latch); the no-extension-header fast exit is untouched, and `#[inline(always)]` folding is preserved. AH handling is now single-walk: an AH sighted only past a non-first Fragment stop is no longer sighted — matching the walker's documented stop semantics and the old screen walk's break, where the old entry AH pre-walk could sight it (that pre-walk disagreement was itself part of the duplication defect).
- No shim (userspace-xdp, no_std) change; its parity corpus compares against the same walker outcomes, which are unchanged for every pre-existing field.
