# Issue #13075 — split `worker/loop_body/mod.rs` below the [REFACTOR] ceiling

Source finding: deep-review `D4-12` (run `review-work.2e4cldwkh1`, worker
`d4`, `gemini-4-argon-high`), validated by the three-way research gate and
filed as #13075.

## Defect

`userspace-dp/src/afxdp/worker/loop_body/mod.rs` was a 4,667-LOC
`[REFACTOR]` monolith (2.3x the 2,000-LOC ceiling in
`docs/refactoring-audit.md`; `[REFACTOR] 2834` in the committed audit at
branch base, drifted since): cold snapshot-rotation session
reconciliation, per-tick expiry/GC housekeeping, the #9856 CommandExport
slice, delta-loss resync/sweeps, PPTP/CT control slices, the 2,357-line
`worker_loop` orchestrator, and 1,243 LOC of inline `#[cfg(test)]`
modules fused in one file. Any cold-path edit forced recompilation and
review of the whole file, and the hot loop shared a translation unit
with ~3,000 LOC of cold code (L1-i / branch-predictor pressure the
finding cites).

## Fix (pure code motion; no production logic changed)

- `reconcile.rs` (707 LOC): #10509 rebind discriminator + tests,
  zone-ancestry matchers, rematch/rebind walkers, the #6291/#6592
  `refresh_runtime_view` SINGLE-load seam (kept `#[inline]`, production
  `between` still a ZST no-op), #9856 `WorkerExportState`.
- `gc_teardown.rs` (329 LOC): seed retirement (#10419), expired-session
  reap (#3776/#4381/#6211), #10591 test seams, DeleteSynced flow-cache
  invalidation (#6457), expiry counter (#2428).
- `housekeeping.rs`: per-tick expiry/GC (HA context #2120, expiry walk,
  PPTP forget #11053, reap, #10309 overflow drain) as
  `#[inline(never)] run_session_housekeeping` returning the old
  `continue` signal; also hosts `drain_and_flush_all_impl`, the old
  loop-local `drain_and_flush_all!` macro as a fn.
- `export_slice.rs`: #9856 CommandExport slice + steady-state drain;
  returns `(skip_tick, did_work)`.
- `delta_recovery.rs`: #2442 resync, #5290 latch fold, #8586/#9327
  delete-drop sweep, #9752 purge.
- `pptp_drain.rs` / `ct_slice.rs`: PPTP inbox drain (#7699), conntrack
  slice (#5287) + fabric/WG drains.
- `tests.rs`: the five inline test modules, verbatim (audit-excluded by
  the `tests.rs` filename shape).
- The loop-local `flush_drained_session_deltas!` macro became
  `flush_session_deltas_loop` (one flush path incl. the #2874 latch);
  extracted fns flush through a closure over it. Moved items keep names
  via `pub(in crate::afxdp) use` re-exports in mod.rs, so
  `worker/mod.rs`, the #10591 window tests, and all callers are
  unchanged. `worker_loop` itself stays inline in mod.rs per #1776.

Result: mod.rs 4,667 -> 1,982 LOC (`[WATCH]`, below the 2,000 ceiling);
every sibling < 750 LOC. Existing source-reading guards that pinned
loop text (#10419 order, #10309 overflow, #10591 C6, #7699 PPTP) were
retargeted to the file now holding the pinned code, with the loop-side
call order (housekeeping -> drain -> poll) asserted in mod.rs — same
claims, one module boundary over. One pre-existing base breakage was
hit and minimally repaired in the moved tests: the
`flow_cache_invalidation_tests` fixture named `RewriteDescriptor::
last_queue_id`, a field already removed at branch base 8e26b24d8 (the
pristine-base test target does not compile for that fixture either);
the stale field line was dropped.

## Regression coverage

`loop_body_mod_stays_below_refactor_ceiling` (in tests.rs) reads
production mod.rs from disk and asserts < 2,000 LOC plus non-trivial
reconcile/gc_teardown siblings and their module declarations — RED on
the branch base (4,667 LOC), GREEN with the split. All 72 pre-existing
loop_body tests pass unchanged in behavior (5 moved suites + sibling
suites), as do the retargeted #10419/#10309/#10591/#7699 guards.

- rustfmt (edition 2024) applied to all new/edited Rust files.

## Risk

Pure code motion across sibling modules in one crate; hot path
(`poll_binding`, per-tick inline loop body) untouched. Extracted per-tick
helpers are `#[inline(never)]` control-path fns (never per packet); the
#6592 refresh seam keeps its no-symbol property. The flush/drain macros
became fns with identical bodies and latch semantics (#5468/#2874);
deferred-cleanup `continue` sites became explicit `return true`.
