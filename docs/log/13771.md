# #13771 — normalize sessionless reverse-SNAT validation

Why: A reverse row with no local forward companion reconstructed the forward
NAT tuple but retained the reverse-direction egress interface and the
reverse row's unobserved ingress sentinel. Interface-SNAT therefore compared
the stored translation against the client-side address, and synthesized
reverse results also discarded the forward session's local SNAT provenance.
Valid replies could be dropped after worker-local session loss.

What: Use the reverse packet's observed ingress and the reverse resolution's
client-facing egress to build forward-direction interface identities on
read-only validator copies. Carry SNAT provenance through reverse synthesis,
local reverse installation, shared reverse rows, and resolver results. Keep
missing provenance and withdrawn-rule paths fail-closed.

Validation: The three #13771 regression cases passed (unchanged interface
SNAT and interface-scoped pool, withdrawn-rule rejection, and missing
provenance fail-closed). Baseline RED observed on origin/master 8738dc25c:
unchanged interface-SNAT revoked while the withdrawn-rule control revoked
as expected. The `policy_revalidation::tests` module passed (33 tests).
Full `xpf-userspace-dp` suite ran 8,020 tests: 8,011 passed, 8 ignored, and
one unrelated failure in
`afxdp::tests_9950::f035_parked_fragment_overlap_is_rechecked_on_retry_10659`
(`parked-head` observed 0 instead of 1).

Risk: Reverse session metadata remains unchanged and continues to represent
only observed ingress; the observed packet interface is used only for the
sessionless NAT validation copy. No new state is added to the wire format.
