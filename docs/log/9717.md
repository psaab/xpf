- **Action**: research.
  - `controlLinkAuthStatus` (`status.go`) is built from the local key and the heartbeat's sticky
    peer-authenticated flag ONLY. Its own comment says it does not track the session-sync channel.
    It reads "engaged (peer authenticated; unauthenticated frames rejected)".
  - A session-sync connection established before the key and never upgraded (#6628 promotes only a
    peer that answers) is still accepted without HMAC.
  - #7441's `strict-session-auth` evicts such a connection after `strictSessionAuthGrace`, but the
    posture is off by default. With it off, nothing reports the connection.
  - The population already has a race-safe definition in `enforceStrictSessionAuth`:
    - an installed `*authConn` with `authPSK == nil`, on a keyed node;
    - connections read under `s.mu`, and `authPSK`/`strictGraceStart` under `s.writeMu`.
  - `ReconcileConnectionAuth` anchors `strictGraceStart` on the first keyed reconcile, in any
    posture.
  - `strictSessionAuthLoop` starts unconditionally in `Start()` and ticks every second.
  - `SyncStatsProvider`'s comment rejects optional type assertions for status data: a silently failed
    assertion renders nothing. Its only implementer is `*SessionSync`.
- **Action**: design.
  - A real interface method, `SyncStatsProvider.UnauthenticatedSessionConns() []string`. It is not
    folded into `Stats()`, because the BulkAck arm calls `Stats()` inline and must not take
    `writeMu`.
  - `controlLinkAuthStatus` names those connections instead of claiming rejection. With none, the
    engaged line is unchanged.
  - A warn-once per connection when all of these hold: keyed, posture off, never authenticated, and
    the grace elapsed. It runs on the strict-auth tick and is counted in
    `StrictAuthResidualWarnings`. The grace gate keeps a legitimate live keying quiet while its
    upgrade is in flight.
  - No wire change.
