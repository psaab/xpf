# #16691: expired-leases-processing knobs lack Kea's maxima; a clean commit stops every pool of the family

- **Timestamp**: 2026-10-25
- **Action**: The six `expired-leases-processing` leaves under
  `dhcp-local-server` / `dhcpv6-local-server` were validated min-only
  (`ValidateIntegerMin(1)` for reclaim-timer / flush-timer / hold-time,
  `ValidateIntegerMin(0)` for max-leases / max-time / unwarned-cycles),
  under a schema comment asserting Kea has no documented hard upper
  bound. The deployed Kea parser does enforce maxima and refuses the
  whole family file for a value above them, so
  `set ... expired-leases-processing max-time 30000` committed clean,
  rendered `"max-reclaim-time": 30000` verbatim, and the fail-closed
  Kea restart then took down every DHCPv4 segment on the node — and on
  both cluster nodes, because the block is synced and rendered on
  clustered nodes (#9348). The operator saw only a generic apply
  error. The schema now uses `ValidateInteger` with Kea's bounds on
  both families: reclaim-timer and flush-timer 1..65535,
  unwarned-cycles 0..65535, max-time 0..10000, hold-time
  1..4294967295, max-leases 0..4294967295 (`maxWireU32`), with the
  value descriptions updated to state the ranges and the stale
  min-only comment replaced. For the tolerant load / peer-sync path,
  where the schema gate only warns (invariant H7), the renderer
  (`keaExpiredLeasesMap`, now taking the manager's warn sink) bounds
  each knob through `clampKeaExpiredLeaseKnob` against the mirrored
  `maxKea*` constants: an out-of-range knob is omitted with a warning
  naming the leaf, value, and bounds, so Kea falls back to its default
  for that knob and the rest of the block and family keep serving,
  instead of the whole family file being refused. In-range rendering
  is unchanged, including the H2 `*Set`-bool discipline that renders
  an explicit 0 (unlimited) for the cap knobs; a stored timer of 0
  remains omitted exactly as before (0 == unset for the timer fields).
- **File(s)**: `pkg/config/schema_system.go`,
  `pkg/config/dhcp_expired_leases_test.go`,
  `pkg/dhcpserver/dhcpserver.go`,
  `pkg/dhcpserver/expired_leases_test.go`, `pkg/dhcpserver/README.md`,
  `docs/log/16691.md`.
- **Validation**: New `TestDHCPExpiredLeasesSchemaRejectsAboveKeaMax`
  (pkg/config): all six above-max probes (65536 for the 16-bit knobs,
  10001 for max-time, 4294967296 for the 32-bit knobs) are refused at
  `SchemaValidate` naming the leaf, on both families;
  `TestDHCPExpiredLeasesSchemaAcceptsKeaBoundary` confirms every leaf
  at its Kea maximum (and each floor) still commits on both families.
  New `TestKeaExpiredLeasesOutOfRangeKnobsOmittedWithWarning`
  (pkg/dhcpserver): a directly-built config with five out-of-range
  knobs (including the issue's `max-time 30000`) still applies, renders
  only the in-range flush-timer, and warns naming each omitted leaf;
  `TestKeaExpiredLeasesBoundaryKnobsRenderVerbatim` confirms all six
  knobs at Kea's maxima render exactly with no warning on both
  families. RED-on-revert: restoring the min-only validators makes
  every above-max schema row commit clean; restoring the verbatim
  renderer makes the out-of-range knobs render and the warnings
  disappear.
- **Residual**: The renderer bounds are untyped constants mirroring
  the schema ranges (Go cannot share one typed constant across the
  `int64` validator and `int` model without a conversion at every
  site); the two new test pairs pin both sides independently, so a
  one-sided drift fails a test. No Kea `-t` pre-check was added — the
  commit gate plus the tolerant renderer now cover both entry paths,
  and a live-Kea parse check remains a deploy-time confirmation as
  before (#1387 validation status).
