# #14166 - upgrade GC ignores indeterminate live-version lookup

- **Timestamp**: 2026-10-16
- **Action**: `gc` (flip.go) and `cleanupFailedVerifyCopy` (cutover.go) both resolved the live version with `cur, _ := r.readCurrentVersion()`, discarding every error — not just permitted absence (`readCurrentVersion` returns `("", nil)` only for ENOENT; EIO/EINVAL etc. return an error). An indeterminate lookup left the running dir unprotected: GC could `RemoveAll` it past the N=3 retention window, and verify-failure cleanup could delete the target when it equalled the live dir but differed from `PreviousVersion` (mirroring the fail-closed guard already in `copyStaged`). Fix: `gc` now returns a wrapped error and defers all version-dir deletion on a non-nil lookup error (callers already log GC failure as non-fatal to a committed cut, so a later GC retries); `cleanupFailedVerifyCopy` logs and SKIPs the delete on lookup error while still rewinding the journal to INIT for a clean retry. Added `readlinkCurrent = os.Readlink` seam (following `statVersionDir`/`statNodeID` precedents) so tests can inject a non-ENOENT failure without root-dependent chmod tricks.
- **Validation**: New `pkg/upgrade/gc_current_indeterminate_14166_test.go`: `TestGC_IndeterminateCurrentDefersDeletion_14166` (5 committed versions, live 1.0.0 past retention protected solely by `current`, journal names only 5.0.0/4.0.0; injected EIO => gc errors wrapping the injection and deletes nothing; healthy-read control GCs 2.0.0 and retains live 1.0.0), `TestVerifyFailCleanup_IndeterminateCurrentKeepsLiveTarget_14166` (target == live != PreviousVersion; injected EIO => live dir survives, skip logged, journal rewound and persisted at INIT), `TestGC_AbsentCurrentStillRuns_14166` (genuinely absent `current` still GCs normally — absent is not indeterminate). RED on pristine origin/master in a separate base worktree (seam+tests only: both defect tests FAIL — gc returned nil and removed live 1.0.0; cleanup removed live 3.0.0 — absent-current control passes), GREEN with the fix in the fix worktree. Full `go test ./pkg/upgrade/...` green.
- **Risk**: Fail-closed only — deletion is deferred/surfaced, never newly enabled; a persistently unreadable `current` will stall GC (repeated WARN) and retain stale verify-fail copies rather than risk deleting the running daemon's binaries. No hot dataplane path touched (upgrade-only filesystem work).
