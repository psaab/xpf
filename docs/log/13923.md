# 13923 — Revoke sessions after destination-NAT withdrawal

## Boundary

An established session records the destination translation chosen by its
port-forward rule. A later config generation can remove or change that rule,
but the cached session previously remained valid until its idle timeout. The
fix checks the stored destination mapping against the current static/DNAT
configuration on the existing generation-triggered NAT revalidation path; it
leaves untranslated and NAT64/NPTv6 sessions to their existing handling.

## Change

The established-hit NAT check now validates a stored destination rewrite before
it stamps the session's NAT generation as current. A missing rule or a changed
translated address/port fails the same predicate as withdrawn source NAT, so
the existing teardown path revokes the flow. The check uses the established
pre-routing ingress scope and applies to both static DNAT and destination-NAT
pool rules.
