# Issue #15040 — configuration-synchronize without RG0 commits cleanly and never pushes (A24-01)

- **Timestamp**: 2026-10-18
- **Why**: `rg0ConfigSyncAuthority` (`pkg/daemon/daemon_ha_sync.go`) is `cl.IsLocalPrimary(0)`, and `reconcileRG0ConfigOwnership` (`pkg/daemon/daemon_ha.go`) returns early when `GroupState(0)` is nil. With `configuration-synchronize` set but no `redundancy-group 0`, no node can ever be RG0 primary, so a commit succeeded, was never pushed to the peer, and neither node armed the standby read-only gate — both nodes stayed writable and silently diverged. Deleting RG0 from a running cluster is the same commit shape and left the standby read-only indefinitely with no push.
- **What**: `validateChassisClusterStrict` (`pkg/config/compiler_validate_strict_chassis.go`) now rejects, on the strict commit/commit-check path, a chassis-cluster config with `ConfigSync` enabled and no redundancy-group with ID 0. The error names RG0 and `configuration-synchronize` and tells the operator to add RG0 or remove the sync flag. The tolerant load/peer-sync paths downgrade via the existing `lenientChassisRG` mechanism to a warning (#1960 no-brick), so a config persisted by an older binary still boots. This also rejects a runtime RG0 delete at commit time, since that delete is a commit of a ConfigSync config without RG0. No daemon push-path change was needed: with the gate, the never-push state is unreachable by commit.
- **Files**: `pkg/config/compiler_validate_strict_chassis.go`, `pkg/config/compiler_validate_strict_chassis_rg0_15040_test.go`, `docs/log/15040.md`.
- **Red-before**: `TestConfigSyncWithoutRG0FailsCommit15040` on `origin/master` (pre-fix): RG1-only and RG-less `configuration-synchronize` configs compiled with nil error.
- **Green-after**: Same test passes after the fix; `TestConfigSyncWithoutRG0TolerantWarns15040` pins the lenient warning; `TestConfigSyncControlsCommit15040` pins that RG0+RG1 with sync, RG1-only without sync, and standalone configs still commit.
- **Validation**: `go test ./pkg/config/ -run '15040'` plus full `pkg/config` suite; `gofmt -l` on changed files.
- **Risk**: Only configs that could never sync are newly rejected at commit. RG1-only clusters without `configuration-synchronize` and all RG0-bearing clusters are unchanged. Tolerant ingress unchanged in behaviour except an added warning.
