# #17055 — consolidate SNMP varbind encoding to one encoder

- **Timestamp:** 2026-10-27
- **Branch:** `fix/17055-campaign`
- **File(s):** `pkg/snmp/agent_ber.go`, `pkg/snmp/agent.go`, `pkg/snmp/v3.go`, `pkg/snmp/traps.go`, `pkg/snmp/getbulk_order_5065_test.go`, `pkg/snmp/getbulk_work_bound_6551_test.go`, `pkg/snmp/varbind_encode_17055_test.go`

## Why

The per-varbind BER encoder existed as three identical loop bodies (`varbindEncodedLen`, `buildResponseVersion`, `buildV3Response`) plus ten hand-unrolled `berEncodeTLV(tagSequence, append(...))` trap/report wraps (6 v2c trap + 4 v1 trap; the brief counted eight trap wraps plus the two report-PDU double wraps). The size-model comment claimed `TestVarbindEncodedLenMatchesEncoder_6551` pinned the model to both response encoders, but it only exercised v2c `buildResponse` — a stray-element mutant inside every SNMPv3 varbind SEQUENCE passed the whole package.

## What

- Add `encodeVarbind(dst, vb)`, `encodeVarbindList(vbs)` and `encodePDU(tag, reqID, errStatus, errIndex, vbList)` in `agent_ber.go`; `encodeVarbind` is now the sole varbind SEQUENCE wrap and keeps the exception-tag nil-value behaviour.
- Re-point `buildResponseVersion`, `buildV3Response`, `buildReportPDU`, `buildV3Discovery` and both trap builders (`buildLinkTrap`, `buildLinkTrapV1WithUptime`, the latter via `buildLinkTrapV1`) at them; traps build a `[]varbind` first. `varbindEncodedLen` is now `len(encodeVarbind(nil, vb))`, so the GETBULK size model cannot drift from the encoder by construction.
- Tighten `decodeVarbindsFull` to require exactly two elements per varbind (value TLV must consume the remainder of the varbind body).
- Extend `TestVarbindEncodedLenMatchesEncoder_6551` so every case runs through both `buildResponse` and `buildV3Response` (noAuthNoPriv leg extracts the varbind list by TLV-walking and decodes it with the tightened decoder). Add `varbind_encode_17055_test.go` with byte-identical goldens captured from the pre-consolidation encoders before the change (deterministic trap entropy / engineTime / v1 uptime seams; the v2c trap uptime is wall-clock-derived, so that leg pins prefix/suffix bytes and the TimeTicks window) plus an exception-nil pin.

## Validation

- RED-on-mutant: appending a stray `0x05 0x00` element inside `encodeVarbind` fails `TestVarbindEncodedLenMatchesEncoder_6551` (v2c length leg and v3 exactly-two-elements leg), `TestTrapGoldenBytesUnchanged17055` and `TestResponseGoldenBytesUnchanged17055`; mutant removed and restored file verified.

- ACCEPTANCE grep: `grep -E 'berEncodeTLV\(tagSequence, append\(' pkg/snmp/*.go` on non-test files returns 0 matches; the only varbind SEQUENCE wrap is inside `encodeVarbind`.

## Risk

Byte-identical output is pinned by goldens at every re-pointed site, so wire behaviour is unchanged. `varbindEncodedLen` now allocates via the real encoder on the GETBULK budget path — a small per-varbind allocation during grid building, in exchange for a size model that cannot drift; `trimToFit` still bounds by real encoded bytes. Trap v1/v2c PDU bodies keep their distinct non-GetResponse shapes (only the varbind encoding is shared).
