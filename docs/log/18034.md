# #18034 — tolerate missing fabric interfaces during standby apply

- **Timestamp:** 2026-10-26
- **Branch:** `fix/18034-campaign`
- **File(s):** `pkg/daemon/daemon_apply_interfaces.go`, `pkg/daemon/fabric_mgmt_vrf_bootstrap_18034_test.go`

## Why

An empty-DB standby can reach the authoritative post-networkd management-VRF rebind before its local `fab0`/`fab1` IPVLAN exists. In userspace mode fabric creation is deferred until XSK binding, so the rebind used to return `interface fab0 not found` and reject config apply before that interface's existing creation/binding owner could converge it.

## What

- Limit the missing-link exception to confirmed absence of `fab*` interfaces in the applied chassis fabric-interface set. Other lookup/bind failures and missing non-fabric management interfaces remain commit-failing.
- Add a canonical node-1 HA bootstrap regression. applyFabricIPVLAN creates the local fab1 synchronously before the rebind; the rebind tolerates the absent remote fab0 and binds fab1 into vrf-mgmt. (Deferred creation/binding for later-appearing overlays is the pre-existing fabric_overlay_vrf_9813/daemon_fabric_reassert path, covered by its own suites.)
- Add a missing `fxp0` negative control proving the genuine non-fabric missing-interface error remains surfaced.

## Validation

- RED-on-revert: disabling the fabric-set exception makes `TestEmptyDatabaseStandbyFabricInterfacesConverge18034` fail with `re-bind fab0 to management VRF: interface fab0 not found`.
- GREEN: both issue-specific tests (TestEmptyDatabaseStandbyFabricInterfacesConverge18034, TestMissingNonFabricManagementInterfaceStillFails18034) pass with the fix restored.
- `gofmt -l` on the changed Go files: no output.
- `go vet ./pkg/daemon`: pass.
- `go test ./pkg/daemon -count=1`: FAIL. The run reported host permission-denied operations, DNS/feed/DHCP assertions, HA event-stream Unix-socket `bind: invalid argument`, `TestNftNetlinkParity` (`no buffer space available`), and a factory-reset nil-store panic. Neither new #18034 test appears among the failure output; both passed in the focused run above.

## Risk

Only a `netlink.LinkNotFoundError` for a configured chassis fabric link is tolerated at the rebind boundary. The apply's fabric creation error propagation and existing deferred/reassert bind owners remain responsible for creating and binding it. No broader missing-interface error is suppressed.
