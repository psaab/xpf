# #16819 — `clamp_tcp_mss` declined TCP-MD5 SYNs although the RFC 2385 digest excludes TCP options

- **Timestamp**: 2026-10-25
  - **Action**: `clamp_tcp_mss` (`userspace-dp/src/afxdp/frame/tcp.rs`)
    declined every SYN carrying a TCP-MD5 (kind 19) or TCP-AO (kind 29)
    option via the shared `tcp_header_has_auth_option` gate added by
    #15119. That is correct only for TCP-AO: RFC 5925 §5.1 MACs the TCP
    header including options, so an MSS rewrite invalidates the MAC.
    The RFC 2385 §2.0 MD5 digest covers the pseudo-header, the TCP
    header excluding options (checksum zeroed), and the segment data —
    none of which an MSS rewrite changes — so configured
    `security flow tcp-mss all-tcp|gre-in|gre-out` was silently skipped
    for MD5-authenticated flows (e.g. BGP-MD5 over GRE) with no counter
    or log. Split the option walk: `tcp_header_has_option_kind` is the
    shared walker; `tcp_header_has_auth_option` (kinds 19+29) still
    backs the segmentation gates (dispatch admission, both segmentation
    builders), which must keep declining both kinds, while
    `clamp_tcp_mss` now declines only kind 29 via the new
    `tcp_header_has_ao_option`. The IPv6 AH decline in `clamp_tcp_mss`
    is unchanged. Inverted the shipped #15119 cell
    `clamp_tcp_mss_no_op_on_tcp_md5_syn_15119` to
    `clamp_tcp_mss_clamps_tcp_md5_syn_16819`, asserting the clamp
    applies, the MD5 option bytes are untouched, and the post-clamp
    TCP checksum folds to 0xFFFF. The AO (`..._ao_syn_15119`), IPv6 AH
    (`..._ipv6_ah_syn_15119`), and NOP-control cells are unchanged and
    still pass, as does the #15119 segmentation cell proving MD5/AO
    datagrams still decline segmentation and reach PTB.
  - **File(s)**: `userspace-dp/src/afxdp/frame/tcp.rs`,
    `userspace-dp/src/afxdp/frame/tcp_tests.rs`, `docs/log/16819.md`
