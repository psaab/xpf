# Issue #14380 — IGP export of a policy-statement with no `from protocol` renders zero `redistribute` lines

- **Issue:** A defined policy-statement whose terms carry only `from route-filter` / `from prefix-list` / `from community` (or no `from` at all), exported under OSPF/OSPFv3/RIP/IS-IS (global or per-instance), rendered zero `redistribute` lines: the export silently advertised nothing. Mixed policies rendered only the explicit `from protocol` sources.
- **Mechanism:** `redistributeEntriesAt` (`pkg/frr/redistribute.go`, policy branch) enumerated source protocols only from explicit `term.FromProtocols`; a no-`from protocol` policy yielded `len(protocols) == 0`, `skipped == false` and fell into the skip-and-warn tail. The same file's `redistPolicyForProtocol` already treats `len(term.FromProtocols) == 0` as applying to EVERY protocol (Junos semantics agree), so enumeration and per-source map construction contradicted each other.
- **What:** In the policy branch, a term with no `FromProtocols` now contributes the whole `config.RedistributionSourceKeywords()` domain via `redistProtocolsForNode`, filtered exactly like an explicit term: self excluded, `redistSourceFitsNode(proto, node)` required; a mixed policy yields the union. `redistProtocols` itself stays explicit-only. The managed section threads `redistReferencedNodes14380` (OSPF/OSPFv3/RIP/IS-IS export references, global + per-instance) into `generatePolicyOptionsForSection`, so a referenced no-from policy gets exactly its referencing nodes' per-source maps defined — an unreferenced no-from policy renders no new maps and direct `generatePolicyOptions` callers are byte-unchanged. `ApplyFull` guards the expanded names via `redistProtocolMapCollisionForNodes`. File-header and tail comments updated; the #2223 invariant (never emit `redistribute <policy>`) is preserved.
- **Pinned tests updated (they encoded the bug):** `TestResolveRedistribute_ProtocolLessPolicy` and `TestGenerateProtocols_ProtocolLessPolicyExport` in `pkg/frr/frr_test.go` now assert the expanded lines instead of `""`.
- **New tests:** `pkg/frr/redistribute_nofrom_14380_test.go` — issue fixture (no-from route-filter policy under OSPF: six lines, all maps defined with the filter match), mixed explicit+no-from union (no-from term present in a non-static map), self-only control still `""`, and the no-from collision belt.
