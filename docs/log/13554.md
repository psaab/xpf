# Issue #13554: remote CLI annotate dispatch

## Why

The in-process CLI accepted `annotate <path> "comment"`, but `cmd/cli`
`dispatchConfig` had no matching arm. Remote operators therefore received an
unknown-command error for an advertised configuration mutation.

## What

Add remote CLI dispatch for annotate through the existing Set RPC route, retain
the annotation verb and quoted comment for server-side mutation authorization,
and handle it in `Server.Set` with the authenticated session and plant class.
Share the existing quote parsing semantics through `pkg/cliterm` so the
in-process and remote CLI paths peel the same syntactic quote layer. Tests cover
dispatch, edit-path expansion, malformed usage, verb-led authorization routing,
and persisted server-side annotation.

## Validation

Focused annotate regressions passed in `cmd/cli` and `pkg/grpcapi`. `go build
./cmd/cli/... ./pkg/cli/... ./pkg/cliterm/... ./pkg/configstore/...
./pkg/grpcapi/...` and `go vet` over the same modified packages passed.
`go test ./pkg/cli/...` passed. `go test ./cmd/cli/...` failed only
`TestTreeIsGofmtClean`, which reports 14 unrelated pre-existing files including
`pkg/api/metrics_userspace_screen_test.go`. Full `go test ./pkg/grpcapi` reports
two unrelated failures: `TestGetGlobalStatsScreenDropDetailKeysAreCanonical`
expects 15 keys but finds 19, and `TestUngatedFallbackErasesDerivedHelperState10769`
hits an overlong AF_UNIX path (115 octets versus the 107-octet limit).

The built CLI help command exited successfully. Running `cli -c configure`
without xpfd failed cleanly with a gRPC `Unavailable` / connection-refused
error at `127.0.0.1:50051`; the annotate dispatch itself is exercised by the
fake-client regression test.

## Risk

The annotation mutation uses the existing Set RPC without changing the protobuf
contract. Server-side parsing rejects missing path/comment input and retains
existing store validation and configuration-lock ownership enforcement.
