# Issue #11956: Rust CI native library versions

- **Timestamp**: 2026-10-08T11:23Z
- **Why**: The Rust PR job used unpinned Ubuntu 24.04 packages. Noble's libelf 0.190 is below build.rs's validated minimum 0.195; the same image also supplies libxdp and zstd below their validated floors, so the workspace check stops at its native-library gates.
- **What**: Run the Rust job in `debian:forky`, install its native build dependencies in the container, and preserve the Rust toolchain and workspace check command. The Ubuntu host remains the GitHub runner; only this job's container changes.

## RED -> GREEN proof

- **RED (before workflow edit)**: Ubuntu noble package records report libxdp 1.4.2, libelf 0.190, and libzstd 1.5.5. A throwaway Rust driver imported the repository's `userspace-dp/build_support/libversions.rs` gate functions and rejected all three against the actual validated floors (`libxdp >=1.6.3,<1.7`, libelf `>=0.195`, zstd `>=1.5.7`). The original workflow installed these unpinned packages on `ubuntu-latest`.
- **GREEN (after workflow edit)**: Debian testing/forky package records and `apt-cache policy` resolve libxdp 1.6.3-1, libelf 0.196-1, libzstd 1.5.7+dfsg-4, and zlib 1:1.3.dfsg+really1.3.2-3. `pkg-config --modversion` reported `1.6.3`, `0.196`, `1.5.7`, and `1.3.2`; the same repository gate driver accepted all four.
