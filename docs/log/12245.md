# #12245 — warn on undefined destination-NAT from-zone

- **Timestamp**: 2026-10-08 (`fix/12245-campaign-pub`)
- **Change**: `ValidateConfig` now warns when a destination-NAT rule-set's non-empty `from-zone` does not name a configured security zone, matching existing source/static NAT warnings. Nil destination config and nil rule-sets are skipped; empty and defined zones remain silent.
- **Files**: `pkg/config/compiler_validate_warn.go`, `pkg/config/destination_nat_zone_test.go`, `docs/log/12245.md`.

## Red before

On base `83b5c955335f16d8c7835f206b210ce3ae1a5fe5`, the STEP-0 repro printed undefined-zone warnings for the source/static controls but none for DNAT. The new `TestDestinationNATFromZoneUndefinedWarns12245` then failed before implementation: it reported the missing `destination-nat ruleset "dnat-typo"` warning while source/static warnings were present.

## Change and regression coverage

The DNAT warning loop checks each non-nil destination rule-set, skips an empty `FromZone`, and names the rule-set and undefined zone. The regression compiles a typo-scoped DNAT rule and checks the destination warning alongside source/static control warnings; defined-zone, global, interface-scoped, and routing-instance-scoped controls verify that valid or absent `FromZone` values stay silent.
