# #16849 — R3-F16-02: value-less flexible-match-range on discard poisons to match-nothing

- **Timestamp**: 2026-10-25
  - **Action**: Strict `CompileConfig`/`CompileConfigForNode`/`CompileConfigWithCurrentClusterPrimary`/`CompileConfigForNodeWithCurrentClusterPrimary` (and therefore `configstore.CheckText` via `compileTreeStrict`) carried `lenientFlexMatchValueMissing: true` (#16296 fold), so a value-less `flexible-match-range` on a `then discard`/`reject` term committed clean with a warning claiming it "fails closed". The dataplane poisoned the term to `FlexMatchStart::Unsupported` (match-nothing), so its traffic fell through to later terms or the implicit accept — the opposite of the warning. Fix removes the strict lenient flag (deleting `lenientFlexMatchValueMissing`), makes `validateFilterFlexMatchStrictOpts` hard-reject a value-less discard/reject term on the strict path while a value-less accept/next-term term stays strict-accepted for the packed/fused controls and is refused at the dataplane, corrects the warning to "refuses the candidate snapshot (prior-good retained)", and makes every builder refuse the whole candidate on any `FlexMatchValid` failure: userspace `buildFilterTermSnapshots` sets `FromUnrepresentable` (Rust preflight rejects, prior-good retained; sentinel kept as defense-in-depth), the lo0 text oracle emits `nftRefuseUnrepresentableFrom`, the netlink DTO carries `FromUnrepresentable`, and the Rust filter compiler refuses a hand-built `flex_match` whose `match_start` is outside {"",layer-3,layer-4} via the new `UnrepresentableFilterFlexMatchStart` error. Hand-built fixtures that omitted `ValueSet`/`MaskSet` were corrected so representable controls stay live.
