# #18752: failback refused "cold prime owed without pending outbound bulk"

- **Timestamp**: 2026-11-01
- **Action**: Root-caused the refused failbacks from #18717's udp gate. The
  cause is an owner-RG export window that the Go pager abandoned. It stayed
  open on the helper, so the cold-prime bulk could not run. Fixed by an
  explicit abandon.
- **Evidence** (fw1 journal, master control `0.0.29570+g5927babf0762`,
  test-failover after three burst+SIGKILL trials;
  `/var/tmp/fz/r-18752-fw1-control.log`):

  | fw1 time (UTC) | event |
  |---|---|
  | 17:02:57.93 | fw0 rejoins after its crash reboot; "driving authoritative cold-prime bulk" |
  | 17:02:58.09 | bulk fails: `owner-RG session export incomplete: helper/config generation changed during export window` |
  | 17:03:05 .. 17:03:58 | 7 re-drives (every ~7 s), every one `owner-RG export busy (window 2 open); retry with backoff` |
  | 17:03:55 .. 17:04:00 | manual failover RG1 refused 10×: `cold prime owed without pending outbound bulk` |
  | 17:04:00 .. 17:04:33 | window expired (60 s); re-drives now fail `tombstone dropped for seq=3..6` |
  | 17:04:22 .. 17:04:32 | RG0 and RG2 failbacks refused the same way |
  | 17:04:42 | `generation changed during export window` again, then BUSY (window 7) until 17:05:47 |
  | 17:06:36 | first bulk ack: `sessions_sent=51044`; the cold prime is finally paid |

  So the bulk was owed for 3 min 39 s after fw0 came back. Two of those
  minutes were the helper refusing BUSY on a window nobody would ever
  drain.
- **Stuck state**: `needColdPrime` armed and every `doBulkSync` failing at
  `bulk sync table-truth snapshot`, so no bulk is pending and
  `ColdPrimeOwedWithoutPendingBulk` is true. The barrier refuses every
  demotion. Nothing was deadlocked: the #82 sweep re-drive kept retrying.
  But `ExportOwnerRGSessionsPagedStream` returned its generation-change error
  without telling the helper. The helper's window (opened by page 1, held by
  `open_export` in `coordinator/session_manager.rs`) stayed open until
  `EXPORT_WINDOW_IDLE_EXPIRY_NS` = 60 s, and `open_export_busy` refused each
  re-drive's fresh kick for that whole minute.
- **Preconditions**:
  - The window must span pages: more than 8192 owner-RG deltas. The three
    17k-session bursts made ~51k. A small table exports in one terminal page
    and never holds a window. That is why #18701's runs and both of #18717's
    clean test-failovers (no bursts) settled their failback.
  - A config/FIB generation change must land inside the window. Peer-reboot
    churn supplies it.
  - The crash cycles in the title are NOT required. The burst-built session
    table is what mattered.
- **Fix**:
  - **Go**, `pkg/dataplane/userspace/owner_rg_export_paging_9344.go`: record
    the token as soon as a page reports `more`, BEFORE any abort check. On
    any error return, send `abandon_owner_rg_export` with that token while
    the export lease is still held.
  - **Rust**:
    - `abandon_owner_rg_export` verb in `server/handlers/{mod,export}.rs`;
    - `Coordinator::abandon_owner_rg_export` in `afxdp/ha/export.rs`, which
      validates the v2 marker and a nonzero token, and treats another
      incarnation as `Ok(false)`;
    - `SessionManager::open_export_abandon_if` clears iff the sequence is
      still the open window.
  - A helper without the verb answers "unknown request type", which leaves
    the pre-fix idle expiry as the backstop.
- **Not fixed here**: the `tombstone dropped` export failures under session
  churn. The helper clears its own window on those, so they cost one ~7 s
  re-drive each, not a minute. Nor are the frequent generation-change aborts
  themselves fixed: any FIB/neighbour publish bumps `m.generation` and aborts
  a multi-page export. Both remain as retry cost, with no window leak behind
  them.

## Review-input fold (before review)

- **Lost page-1 response.** The token used to come only from page 1's
  response. If the helper opened the window but that response was lost or
  timed out, the pager had no token and sent no abandon, and the window stayed
  BUSY for the full 60 s. Now:
  - the pager picks a nonzero `session_export_client_window` before sending
    page 1, and the helper stores it on the window;
  - the abandon carries that id plus the token when it has one;
  - the helper clears the window iff either names it.

  Cells:
  - Go: `TestLostPageOneResponseStillAbandonsTheWindow18752` (the fake helper
    opens the window, then drops the reply);
  - Go: `TestEachExportNamesItsWindow18752`;
  - Rust: `owner_rg_export_abandon_by_client_window_when_page1_was_lost_18752`;
  - the wire cell now also abandons by client id only.
- **The debt itself.** It has no automatic bound, by design: admitting a
  demotion before the peer is primed is what #10387 refuses. The refusal now
  names the debt's state, e.g. `demotion peer barrier failed: cold prime owed
  without pending outbound bulk (owed for 1m12s; it clears when a bulk
  re-drive (every sweep tick) is acked by the peer; last bulk error: …)`. This
  comes from `SessionSync.ColdPrimeDebtDetail`, which is display only.
  - Cells: `TestColdPrimeDebtDetailNamesAgeAndLastBulkError18752` (first-arm
    stamp kept across re-arms; cleared on discharge; a success does not erase
    the last failure) and `TestDoBulkSyncFailureIsRecordedForTheDebtDetail18752`.
  - I first tried adding the debt to `TransferReadinessSnapshot.ReadyForManualFailover`
    and reverted it. That predicate is also evaluated on the REQUESTING node
    (`failover.go` RequestPeerFailover). There it would refuse a failback
    because of the requester's own debt to its peer, which the demoting
    node's barrier never consults.
- **Mutants on the current code** (exact-once, scored by test name): 11 of 11
  killed.
  - Go (7): G1 never abandons; G3 terminal page does not close; G5 wrong
    token; G7 lost page 1 not treated as open; G8 client id not sent; G9
    client ids reused; G10 abandon omits the client id.
  - Cluster (4): D1 re-arm restamps; D2 discharge keeps the stamp; D3
    doBulkSync failure not recorded; D4 success clears the failure.
  - The first design's G2 (window recorded too late) and G6 (no token) were
    killed before this fold; G7 and G10 are their equivalents now.
  - "Abandon on success" is equivalent (success needs a terminal page) and
    was dropped.
- **No-crash twin and OOM control** (udp, `0.0.29586`, both nodes at 1440
  hugepages).
  - One 17k burst, NO helper crash, then test-failover. fw1 logged one
    generation-change abort, then 6 × `owner-RG export busy (window 1 open)`,
    and 30 failback refusals. The stuck state reproduces with no crash cycle.
  - That run was not OOM-free: fw1's helper was OOM-killed at 21:24:38,
    before the 21:26:59 abort. The bursts accumulate session-table entries
    (up to ~730k of 786k) faster than they expire.
  - The first master control run (17:02, `0.0.29570`) is the OOM-free case.
    fw1's kernel log since its Oct 22 boot shows OOM kills only at 20:49,
    21:12, 21:24 and 21:33. So fw1, the node whose window leaked, had no OOM
    then. fw0's pre-reboot kernel log is gone, but fw0 is the node being
    exported TO.
