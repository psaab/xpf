# #16573: percent-escaped DDNS template values are literals, not specifiers

- **Timestamp**: 2026-10-24
- **Action**: Both mirrored generic-template detectors
  (`pkg/config` `ddnsTemplateCarriesLiteralToken`, `pkg/ddns`
  `templateCarriesLiteralToken`) treated any value containing `%` as a
  specifier-only value, so a percent-escaped credential (`%2B`/`%2F`/`%3D`,
  e.g. a base64 token) over `http://` was neither commit-refused nor
  refused by the runtime construction/issuance belts, yet
  `renderGenericURL` transmits unknown `%x` verbatim — the credential went
  out in cleartext. Both detectors now strip only recognised specifiers
  (`%h`/`%i`/`%u`/`%p`/`%%`) and terminated `{{...}}` placeholders and
  count any remaining byte as literal; a percent-escaped keyless query
  component and a credential-named path pair with an escaped value count
  too (a plain keyless flag stays a pinned value-less control).
  Specifier-only (`?host=%h&ip=%i`), placeholder-only, empty/value-less,
  https and loopback http templates are unchanged.
- **File(s)**: `pkg/config/compiler_ddns_tls.go`,
  `pkg/ddns/backend_plaintext_14386.go`,
  `pkg/config/ddns_plaintext_16573_test.go` (new),
  `pkg/ddns/ddns_plaintext_16573_test.go` (new), `pkg/ddns/README.md`
- **Validation**: new `TestDDNS16573*` tests in both packages (escaped,
  mixed, trailing-`%`, unknown-specifier, unterminated-placeholder,
  keyless and escaped path-pair probes refused; specifier/placeholder/
  loopback controls accepted, including a loopback publish proving the
  escaped token is sent verbatim there). Adjacent DDNS suites re-run —
  see PR body for counts.
