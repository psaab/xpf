# #10253 — nft mirror must terminate on action plus `next term`

## Summary

- **Issue:** #10253 follows #10012 (Rev10252 observation). The snapshot
  renderer had already been corrected to mirror the Rust dataplane, but both
  nft lowerers still treated `(action + next_term)` as fall-through:
  `pkg/daemon/daemon_nft_term_lower.go:527` and
  `pkg/nftables/netlink_lo0.go:262`.
- **Issue context:** Read the complete #10253 body and all comments with
  `gh issue view 10253 --comments`; the issue was OPEN and had no comments,
  withdrawal, narrowing, shipped notice, or contradictory direction. Read the
  #10012 render fix and `docs/log/10012.md` as the Rev10252 context.
- **Rust contract:** `userspace-dp/src/filter/compiler.rs` computes
  `continue_term = snap.action.is_empty() && snap.routing_instance.is_empty()`
  (#5142). A non-empty action terminates even when a tolerant or peer-synced
  snapshot also carries `next_term=true`; an empty action falls through unless
  a routing-instance makes the term's decision terminating.
- **Decision:** Change both nft fall-through guards to test only
  `Action == "" && RoutingInstance == ""`. A real action now reaches the
  terminating verdict mapping (`accept`, `drop`, faithful `reject`, or
  fail-closed `drop` for an unknown action), and its log/count modifiers stay
  on that terminating rule. Actionless and routing-instance terms retain their
  existing behavior.
- **Files:**
  `pkg/daemon/daemon_nft_term_lower.go`,
  `pkg/nftables/netlink_lo0.go`,
  `pkg/daemon/lo0_action_nextterm_terminate_10253_test.go`,
  `pkg/nftables/lo0_action_nextterm_terminate_10253_test.go`, and the matching
  mirror-contract paragraph in `pkg/daemon/README.md`.

normally rejects but tolerant/peer-sync paths can preserve.
