## Measured at origin/master 580d959e0, before the fix

A census walks `setSchema` and finds 12 schema nodes that carry a wildcard name slot. At each one it SetPaths `<path> apply-groups g1` and `<path> apply-groups-except g1`:
- 18 of the 24 statements lost their name: SetPath stored Keys=["apply-groups"] with a child ["g1"].
- The slots include `routing-instances`, `interfaces`, `bridge-domains`, `routing-options rib-groups`, `security zones security-zone <z> interfaces`, `chassis cluster redundancy-group <n> ip-monitoring family inet`, `services rpm probe <p> test <t> target`, `system dataplane ports` and `system services web-management api-auth user`.

Issue rows:
- A: `set groups g1 routing-instances ri1 ...` + `set routing-instances apply-groups g1` compiled `[]`; the hierarchical control C compiled `[ri1]`.
- D: with a top-level `set apply-groups g1` plus `set routing-instances apply-groups-except g1`, the flat spelling compiled `[ri1]`, so the exclusion was not honoured. The phantom instance is gone since #9657.
- Render: the flat result rendered as `apply-groups { g1; }`.

## Fix

`schemaChildFor(schema, keyword)` returns a declared child first. At a wildcard slot it returns `applyStatementSchema` for an apply keyword, and the wildcard for anything else. `applyStatementSchema` is a multi-value leaf shaped like the top-level `apply-groups` declaration. Every walker that resolves a node's keyword now uses it:
- SetPath, delete and deactivate;
- the #8992 elided-delete guard, through `resolveSchemaChild`, which without this refused `delete routing-instances apply-groups g1` as a "packed run";
- the compact normalizer.

At a wildcard slot the multi-value absorber used to treat every trailing token as a sibling instance. After an apply statement it now absorbs the group names, so `[ g1 g2 ]` stays one statement.

Group expansion and the #9422 exclusion already read names from Keys[1:], and were right once the shape was.

Not changed: CLI completion (`schema_complete.go`) still offers only the wildcard placeholder at these slots. That is a completion gap, not a parse defect.

A declared child still wins. The top-level `apply-groups` keeps its own declaration, and a stanza that declares its own apply child is unaffected. `resolveSchemaChild` is also called by many compiler helpers, but always with literal non-apply keywords, so they see no change.

It asserted the defect deliberately and named this issue. It now asserts the fixed behaviour: the flat `apply-groups-except g1` excludes g1 like the braced spelling above it, the strict compile passes, and the tolerant compile keeps only ri7.

A braced one-key `apply-macro { instance-type virtual-router; }` row keeps the warning bound. The production comment in `compiler_routing_children_9323.go` is updated to match.
