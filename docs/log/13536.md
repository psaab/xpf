# Validate classes from every login block (#13536)

- **Issue**: #13536 — `SchemaValidate` rejected a custom login class defined
  only in a second sibling `system login` block, while `CompileConfig` merged
  both blocks and accepted the definition.
- **Cause**: `collectLoginClasses` used singular `FindChild("login")`, so its
  cross-reference set omitted classes from all but the first login block.
- **Change** (`pkg/config/schema_walk.go`): collect class definitions from
  every sibling login node with `FindChildren`, keeping the existing
  hierarchical-class handling and undefined-class rejection unchanged.
  Added `pkg/config/login_class_second_block_13536_test.go` to assert that a
  class defined in the second block validates and that an actually undefined
  class remains rejected.
- **RED evidence**: on pristine master `d7fe769aa`, the new positive
  regression failed because `SchemaValidate` reported `noc-second` was not
  defined. The negative undefined-class control passed.
- **GREEN evidence**: `go test ./pkg/config -count=1 -timeout=30m` passed
  (425.641s); focused positive/negative regression tests passed; `go build
  ./...` passed; `gofmt` and `git diff --check` passed. The RED-on-revert
  positive regression failed again on the original `FindChild` behavior.
- **Risk**: none known; validation only recognizes definitions the compiler
  already merges.
