# #9494: a raw fabric-bond / bridge-domain name reached filepath.Join and wrote outside /etc/systemd/network

- **Timestamp**: 2026-09-11T03:20Z
- **Action**: Closed the traversal at all three layers: the bond name the builder emits, commit-check admission of bridge-domain names, and a confinement belt in `networkd.Apply`.
- **File(s)**:
  - `pkg/dataplane/compiler_iface.go`
  - `pkg/networkd/networkd.go`
  - `pkg/config/schema_routing.go`
  - `pkg/config/schema_validators_bridge_domain_9494.go` (new)
  - tests in all three packages

## Mechanism (verified on origin/master `c83b52270`)

- **Two raw names.**
  - `buildFabricBondModels`: `bondName := ifName` was RAW, while its own member names use `config.LinuxIfName`.
  - `buildBridgeDomainModels`: `"br-" + bd.Name` was RAW.
- **The sink.** `networkd.Apply` builds `filepath.Join(m.networkDir, "10-xpf-"+ifc.Name+suffix)`. `Join` Cleans the path, so a `/../` component escaped the managed directory. xpfd, running as root, wrote a `.netdev`/`.network`/`.link` file elsewhere, and `Apply` returned nil.
- **Admission.** Bridge-domain names had NO key validator: `bridge-domains "x/../../pwnbd"` passed `configstore.CheckText`. Interface names allow `/` deliberately (Junos `ge-0/0/0`); only the IFNAMSIZ gate on the canonical form bounds their depth, and bridge names have no such bound.
- **Sweep immunity.** The stale-file sweep globs only `10-xpf-*` inside the directory, so the escaped files survived. The issue measured 4/4 surviving.
- **Severity.** Medium, per the issue. The suffix is forced and the content is generated INI. The realistic worst case is overwriting an operator's own `/etc/systemd/network/50-mgmt.network`.

## Change (the issue's three-part fix direction)

1. **Bond name.** `bondName := config.LinuxIfName(ifName)`, matching the member site. A name with no `/` (e.g. `fab0`) is unchanged.
2. **Bridge-domain names.** `ValidateBridgeDomainName` is the `keyValidator` on the `bridge-domains` wildcard. It rejects `/`, `\`, NUL and whitespace at strict commit (`SchemaValidate`). The `"br-" + bd.Name` sites are unchanged: with the gate plus the belt, no renaming of existing bridges is needed.
3. **Belt in `networkd.Apply`.** `confinedInterfaceName` refuses an empty name, or one containing a path separator or NUL. The refusal counts as a write failure: Apply fails, and nothing is written for that interface. This covers names that reach `Apply` without strict admission: tolerant boot load, HA peer sync, a rollback slot, or a day-0 config drive.

**Blast radius of the new commit gate.** The shipped and test configs carry 8 `bridge-domains` lines (positive control) and 0 names with a separator. `pkg/config`, `pkg/networkd` and `pkg/dataplane` pass unfiltered.

No module docs describe networkd file naming or bridge-domain name syntax, so no docs change is needed beyond this log. The validator's doc comment states the contract.
