# #17170 — Single derived RETH ownership mode (R4-Q36-07)

- **Timestamp**: 2026-10-27
- **Defect (re-verified live on origin/master `4f2aa8de35`)**: "Does this
  cluster run RETH VRRP?" was open-coded as
  `NoRethVRRP || PrivateRGElection` in 11 non-test sites — 7 in
  `pkg/config` (incl. the `(T,T)` redundancy warning's first conjunct),
  3 in `pkg/daemon`, 1 in `pkg/vrrp` — plus the negated spelling in
  `daemon_run_bringup.go:286`. The one named wrapper,
  `Daemon.isNoRethVRRP` (`daemon_ha_vip.go:88-94`), was documented
  "Default (no flag) uses VRRP for RETH failover", but the compiler sets
  `PrivateRGElection = true` by default
  (`compiler_chassis.go:501-506`), so it returns true with no flag — the
  doc inverted the mode switch it named.

## What

- Added `pkg/config/types_cluster_mode.go`:
  - `RethOwnershipMode` enum — `RethOwnershipUnknown` (0, nil receiver =
    no cluster stanza), `RethVRRP` (legacy, neither flag),
    `RethDirectNoVRRP` (no-reth-vrrp only), `RethPrivateRG`
    (private-RG election; wins when both are set, matching the compiler's
    "no-reth-vrrp is redundant" warning).
  - `(*ClusterConfig).RethOwnershipMode()` and
    `(*ClusterConfig).UsesRethVRRP()` — the single derived reading of the
    two persisted Junos booleans. The surface fields are unchanged.
  - Nil semantics are explicit: a nil config is `RethOwnershipUnknown`
    and `UsesRethVRRP() == false`, which is exactly the reading every
    former `cc != nil && (…)` suppression site needs. Consumers that must
    fail closed on an absent config keep their own nil check (see below).
- Replaced every open-coded copy with the helper:
  - `pkg/config`: `compiler_validate_strict_reth_vrrp.go`,
    `compiler_validate_strict_vrrp_identity.go`,
    `compiler_validate_strict_vrrp_vipcount.go`,
    `compiler_validate_strict_vrrp_vipcrossgroup.go`,
    `compiler_validate_warn.go` (strict-vip-ownership gate; the `(T,T)`
    warning now reads `RethOwnershipMode() == RethPrivateRG &&
    cc.NoRethVRRP`),
    `compiler_validate_warn_host_inbound.go`; plus
    `compiler_validate_strict_chassis.go`'s private-RG control-link gate
    now reads `RethOwnershipMode() == RethPrivateRG`.
  - `pkg/vrrp`: `CollectRethInstances` early return.
  - `pkg/daemon`: `isNoRethVRRP` delegates; `strictVIPOwnershipByDefault`
    and `legacyNoRethVRRPCommitReady` delegate; `daemon_run_bringup.go`'s
    negated copy is now `cc.UsesRethVRRP()` and its private-RG
    sync-timer arm reads `cc.RethOwnershipMode() == config.RethPrivateRG`.
- Fixed `isNoRethVRRP`'s doc: private-RG election is the compiler
  default, so a compiled config with no mode flag already returns true;
  `no-private-rg-election` (without `no-reth-vrrp`) restores legacy RETH
  VRRP and returns false.

## Invariants preserved

- The #15165 gate (`legacyNoRethVRRPCommitReady`) still rejects a nil
  committed config explicitly (`cc == nil || !cc.UsesRethVRRP()`), so an
  unconverged-mode RG0 cannot fail open as legacy-ready — the differing
  nil semantics the issue called out are kept, now stated on the enum.
- No behaviour change at any replaced site: each is a truth-table
  identity over the same two fields with the same nil guard.
- Acceptance grep now returns no code copy of the pair:
  `grep -rnE 'NoRethVRRP' --include='*.go' pkg cmd | grep -v _test.go |
  grep PrivateRGElection` matches only the enum's doc comment and the
  pre-existing #15165 explanatory comment in `daemon_ha.go`.
