# Record stale recovered commits and surface journal cleanup failures (#13543)

- **Issue**: #13543 — completing a healthy stale half-cut did not expose its
  committed-cut evidence to callers, and ignored journal removal failures.
- **Cause**: the stale recovery branch stamped the version commit record and
  collected garbage, then discarded `clearJournal`'s error without calling
  `recordCommittedCut`. Post-install downgrade-floor/status handling relies on
  the per-run commit evidence.
- **Change** (`pkg/upgrade/cutover.go`): return a contextual error if stale-cut
  journal cleanup fails; after successful cleanup, record the stale target as
  the committed cut before continuing into the superseding upgrade.
- **Regression coverage** (`pkg/upgrade/stale_halfcut_commit_13543_test.go`):
  prove a subsequent preflight failure leaves the stale 2.0.0 commit evidence
  available, and prove a deterministic journal removal failure surfaces and
  prevents the fresh cut from proceeding.
- **RED evidence**: on pristine master `d7fe769aa`, both focused tests failed:
  stale recovery left `LastCommittedCut` empty, and ignored the journal-clear
  failure until a later journal write failed.
- **GREEN evidence**: focused tests passed after restoring the fix
  (`go test ./pkg/upgrade -run
  'TestStaleHalfCutFinish(RecordsCommittedCut|ClearJournalErrorSurfaces)13543'
  -count=1`). The complete upgrade package suite passed
  (`go test ./pkg/upgrade -count=1`, 77.231s); `go vet ./pkg/upgrade`
  passed; `gofmt -l` reported no changed Go files.
