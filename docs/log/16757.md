# #16757 — Exact-match source canary for same-prefix renumbering (R3-A46-07)

## Summary

The #15073 "is my source still assigned" canary used prefix
containment, so a DHCP/SLAAC renumber within the same subnet was
invisible: IPv4 export parked on the dead socket until a commit or
restart, and IPv6 export was never re-dialed while health read healthy.

- Issue: psaab/xpf#16757 (R3-A46-07, 3-way MATERIAL). Base:
  `origin/master` at `7608d38cf2`.

## Defect (present at base)

- `pkg/flowexport/transport.go` `addrIsAssigned`: for a `*net.IPNet`
  entry it returned true when `pfx.Contains(needle)` (and when a
  host-mask prefix built from the assigned IP contained the needle).
  The real `net.InterfaceAddrs` view carries on-link masks
  (`192.0.2.2/24`, `2001:db8::2/64`), so after `192.0.2.1 -> 192.0.2.2`
  the dead source still "matched". The #15073 fixture built only host
  masks (`CIDRMask(bits,bits)`), which made containment equivalent to
  equality and hid the shape.

## Fix

`pkg/flowexport/transport.go` only:

- `addrIsAssigned` now counts a source as assigned only when an
  assigned address's IP exactly equals it (`addr.Unmap() == needle`,
  mask ignored), for both `*net.IPNet` and `*net.IPAddr`. Both
  containment arms are deleted. The 4-in-6 unmapping preserves the
  prior v4 comparison for a `::ffff:`-form `LocalAddr`.
- Enumeration/parse failures still conservatively report assigned
  (no churn on missing data); `sourceStale`, the canary, the
  write-failure redial, grace and backoff are unchanged.

NOT changed: optional netlink-event caching from the issue (the
per-flush enumeration already runs; exact equality fixes the
mechanism without a new event subsystem).

## Regression (RED → GREEN)

carrying real on-link masks (`net.ParseCIDR`):

- `TestAddrIsAssigned_SamePrefix16757` — predicate: exact under

  delivery from S2 on the same flush.
- `TestCollectorRedial_SamePrefixRenumberV6_16757` — v6 health
  unhealthy + canary redial onto S2.
- `TestCollectorRedial_ExactAddrOnLinkMaskNoChurn16757` — control:

RED evidence (production file restored to `origin/master`, tests kept):
the two same-prefix predicate cells fail (`= true, want false`), the
v4 leg fails on `writeAll = false`, the v6 leg fails on healthy-stale;
the exact-address control passes. GREEN post-fix: all 16757 tests pass.

## Risk

- A host that legitimately held only a containing prefix without the
  exact address was never a valid source for the dialed socket, so
  exact matching cannot park a live collector; the still-assigned
  controls (#15073 suite + the new exact-mask control) pin no-churn.
- Live netns renumbering was not run; the fakes model the exact
  `net.InterfaceAddrs` shape the report executed against.
