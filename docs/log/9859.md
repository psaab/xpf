# #9859 log

## Defect (verified on base)

A group leaf naming one named instance was overridden by an inline leaf that
shared only its keyword. At base `18a5e90ce254039b2eac40d53ab483c36f82e03d`:

- `host 10.0.0.1;` from a group plus inline `host 10.0.0.2;` compiled only
  `10.0.0.2`.
- `schedulers group-sched;` from a group plus inline
  `schedulers inline-sched;` compiled only `inline-sched`.
- The braced control, group `schedulers group-sched { }` beside inline
  `schedulers inline-sched;`, already compiled both instances.

The leaf branch selected peers with `leafListPeer`, whose identity was the
keyword alone. Strict validation accepted the affected configurations.

## Implementation

- Added `namedLeafPeer9859` in
  `pkg/config/group_merge_named_leaf_9859.go`. A schema child is admitted to
  identity matching only when it has children, is not a `valueList`, and the
  source has a keyword plus an identity span of at least two keys.
- The selector compares raw identity keys for ordinary sites. Bare
  identity-only and unexpandable-tail sources scan collapsed leaves and braced
  containers; only expandable packed tails defer braced peers to the existing
  #9855 fallback.
- Zones stay on the #9801/#9831 path. The explicit canonical-alias registry
  computes compiler-facing identities for chassis redundancy-group IDs,
  regular and CoS interface unit IDs, OSPF areas, VRRP group IDs, and
  WireGuard peer public keys. Equal aliases merge and retain inline precedence;
  unequal canonical identities remain separate instances.
- Value lists, scalar leaves, and unresolved schemas retain the legacy
  `leafListPeer` path.
- Interface-family `inet`/`inet6` `address` is the one named-container schema
  whose bracketed value tail is a list of ordinary address instances. A
  schema-gated member union accepts bracketed and single forms, validates each
  member, deduplicates overlap across all same-keyword nodes, and keeps both
  `KeysQuoted` and `KeysBracketed` aligned. Packed options such as `primary`,
  `preferred`, and `vrrp-group` remain on their existing path and are never
  treated as addresses.
- When uncertain contributors are unioned, `peer.fromGroups` and chained
  address-member provenance are cleared atomically; hierarchical and flat-set
  expansion therefore retain the same complete union under exclusions.
- Extended the #9855 successive-leaf guard so a qualified different instance is
  adopted after an earlier same-keyword promotion. The existing fallback marks
  synthesized packed terminals so an inline braced peer keeps the existing
  inline-wins behavior.

## Tests and RED-then-GREEN evidence
`pkg/config/group_merge_named_leaf_9859_test.go` covers:

- different syslog hosts (plain leaves in both group/inline orders and packed
  tails in both source orders);
- different CoS scheduler names, including the braced control;
- same-instance leaf override, same-instance leaf versus braced peer, and the
  conservative unexpandable-tail braced-peer case;
- NTP and DHCP `valueList` controls;
- OSPF area and VRRP canonical-alias controls, plus chassis redundancy-group,
  regular/CoS interface-unit, and interface/unit WireGuard peer aliases;
- packed different-instance adoption plus #10056 source-order parity;
- CoS shaping-rate scalar override at interface and unit levels, with and
  without the optional burst-size body, including ordered groups with and
  without an unrelated `apply-groups-except`;
- bracketed `inet`/`inet6` address overlap, disjoint members, mixed
  bracketed/single forms, quoted CIDRs in both collapsed and child shapes,
  packed-option guards, and quote/bracket mask alignment;
- hierarchical and flat-set H1/H2/W `apply-groups` plus `apply-groups-except`
  cases, which must produce the same complete atomic address union.

On baseline `ca61334fe`, the address cells were RED (`artifact://29966`): the
basic overlap compiled the duplicate
`[10.0.0.1/24 10.0.0.2/24 10.0.0.2/24]`, the nested exclusion cells lost
members, and both quoted-CIDR mask cells failed. The implementation is GREEN
for all address cells (`artifact://29960`).

Review ruling: one advisory said “container union still calls
`mergeBracketedAddressInto9859(..., s)` on unpruned `s`; implement clone +
`pruneExcluded9862`.” A later advisory ruled that “selective pruning is
shape-dependent; flat probe excluding H1 kept root address A but pruned chained
B; equivalent hierarchical leaf has both values in Keys; #9424 requires
dual-shape parity. Union-and-clear must treat address list atomically until
member-level provenance exists.” The decisive H1/H2 test reproduced that
prune-only returned `[A,C,D]` for flat syntax while hierarchical syntax kept
`[A,B,C,D]`; the implementation therefore retains atomic union, recursively
clears uncertain node/chain provenance, and does not selectively prune.
