# Issue 10458 — VRF terminator day-2 async-delete recovery

## Scope

Close the post-success async-delete window left by #10421. The existing
#9693 retry owner returned before taking `applySem` whenever no routing debt was
owed, so a networkd cleanup that deleted both managed pref-2000
`l3mdev unreachable` rules after a successful apply had no recovery owner.

The fix keeps policy-routing and route-leak retries debt-gated, but gives the
same 30-second owner an always-on VRF tail outside bootstrap. A no-debt tick
uses `TryAcquire` so it does not queue behind an active commit, then reads the
active config and reasserts the VRF terminator under `applySem`. Canceled ticks
return before that fast path. If the VRF callback fails, the failure latches
#9693 debt; an owed tick retries policy, route-leak, and VRF reconciliation
together. The existing config-aware ownership guard keeps an empty
configuration a no-op, and the kernel's idempotent `EEXIST` result keeps
repeated adds at one rule per family.

### Cell 2 — no duplicate-rule accumulation

`TestDay2TailNoDuplicateRulesAcrossTicks10458` models kernel state and its
`EEXIST` duplicate response. Three idle ticks and three delete/recovery cycles
end with exactly one installed rule in each family. The absent-to-present
install count is exactly eight: two initial installs plus two for each of the
three recovery cycles. Idle reassertions add no duplicate rule.

### Cell 4 — day-2 failure enters the retry owner

`TestDay2TailFailureLatchesRetryDebt10458` injects a terminator failure on a
no-debt tick. The failure is recorded with VRF context and latches one #9693
debt failure; policy and route-leak callbacks are not run on that first tick.
After the injected error is cleared, the owed tick runs all three callbacks and
discharges the debt.
