# #14358 — Scoped/bare generation tables cross-clean

## Defect
`#10512` stamped/recorded scoped generation entries on every install but
only reclaimed them on scoped policy deletes. Normal closes
(`takeDeleteGenV4/V6`, `deleteClusterSyncedV4/V6`) leaked
`genSentScoped*`/`recvGenScoped*` live entries to cap, and a scoped policy
delete never tombstoned the bare receiver space, so a delayed
same-generation install could resurrect a revoked session once the scoped
tombstone was evicted. The file header claimed all families are evicted
on delete — false for the scoped family.

## Fix (`pkg/cluster/sync_conn_gen.go`)
- `scopedKeysForTuple` helper (scan; a bare close names no domain, so it
  must cover every domain's entry for the tuple — same order as the bare
  map it scans).
- Sender: `takeDeleteGenV4/V6` delete every `genSentScoped*` entry naming
  the key (before early returns, like the other memo evictions).
- Receiver guards refactored onto `tombstoneBareLocked{,V6}` /
  `tombstoneScopedLocked{,V6}` record halves (no behavior change alone).
- `deleteGenGuardV4/V6`: a scoped tombstone for the tuple orders a bare
  delete; an applied bare delete cross-tombstones every scoped entry at
  the same generation (gen-0 evicts both spaces). Colliding tenants'
  *live* scoped entries never refuse a bare delete.
- `deleteGenGuardScopedV4/V6`: refused if it would regress an existing
  bare high-water; on apply it raise-only tombstones an *existing* bare
  entry. It never creates a bare entry for a never-bare-tracked tuple and
  never lowers one — preserving #10512 per-domain independence
  (`TestDeleteGenGuardScopedOrdersPerDomain10512`,
  `TestScopedGenCapEvictsOldestTombstone10512` unchanged in assertions).
- `deleteClusterSyncedScopedV4/V6`: evict `installTableRecv*` /
  `sourceNatICMPRecv*` after the guard, like the bare twins.
- Install guards/records unchanged (per-space); the resurrection defense
  is that the bare tombstone survives scoped-tombstone eviction. If both
  tombstones are evicted the bounded #9719 reorder window has closed —
  documented tradeoff, not silent.

## Deliberate scope cuts / notes
- Issue's `recvTablesAtCapLocked`/`evictSessionRecvOnOverflow` symbols do
  not exist on master; the memo-eviction half is the direct
  `delete(installTableRecv*/sourceNatICMPRecv*)` above.
- Issue's 262,144 cap / `DeleteTombstoneDrops` specifics were already
  refuted by research (cap is 200k default, 5M ceiling; overflow is
  `GenMapOverflow`) — not used.
- `TestInstallTableProducerToResendEndToEnd9752` fails identically on
  clean origin/master `be0f5f9e5` — base-attributed, unrelated.
