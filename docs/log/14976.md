# #14976 — management-only DHCP lease-change IPsec reapply: take applySem + fresh snapshot

- **Timestamp**: 2026-10-18
- **Issue**: #14976 (D33-04; validator research run `tpzkKgAuZL`, 3-way MATERIAL)
- **Base**: `origin/master 28a08b27f1`

## Defect (measured at the base)

`(*Daemon).onDHCPAddressChange`'s management-only branch (the branch taken
when `dhcpLeaseChangeRequiresRecompile` is false — a management-only
interface such as `fxp0` with DHCP):

1. called `applyMgmtVRFRoutes()` with **no `applySem` at all**, racing a
   concurrent commit's `applyMgmtVRFRoutes` inside `applyConfigLocked`
   (management routes reconciled unserialized), and
2. passed the `activeCfg` snapshot — captured at the top of the callback,
   **before** any semaphore wait — to both
   `reapplyIPsecForLeaseChange(activeCfg)` and
   `rebindWebMgmtForLeaseChange(activeCfg)`. Each helper acquired `applySem`
   per call, but the **gate + apply were already bound to the stale
   snapshot**: a commit landing in between that removed the DHCP-bound
   IPsec gateway (and its PSKs) was resurrected into swanctl by
   `ipsecApplyForLeaseChange(staleCfg)`; a just-added gateway was never
   re-bound. This is the #6716 inversion class on the one callback #6716
   did not cover (its full-recompile branch re-reads via
   `applyActiveConfig`).

`rebindWebMgmtForLeaseChange` already re-read under its own acquisition
(#14582); `reapplyIPsecForLeaseChange` did not re-read at all, and the
route reconcile never serialized.

## Fix (`pkg/daemon/daemon_dhcp.go`, `pkg/daemon/daemon.go` field removed)

- New `managementOnlyLeaseRefresh()` owns the whole management-only
  refresh: it acquires `applySem` **once**, runs the management-VRF route
  reconcile (via a new `mgmtRouteRefreshFn` seam mirroring
  `mgmtVRFRouteReconcileFn` / `webMgmtRebindApply`, so tests can observe
  it without netlink), re-reads `store.ActiveConfig()` **after**
  acquiring, and evaluates both gated rebinds against that fresh
  snapshot — all under the single hold. `onDHCPAddressChange`'s
  management-only branch now just calls it.
- `reapplyIPsecLocked` / `rebindWebMgmtLocked` hold the gate+apply body
  under a held semaphore; the gate lives in the Locked helpers so it is
  evaluated against the fresh snapshot. The legacy acquiring entry points
  `reapplyIPsecForLeaseChange` / `rebindWebMgmtForLeaseChange` are kept
  byte/behaviour-identical for their existing callers (the #4899 retry
  loop lifecycle tests and the #14582 wiring test): they still acquire
  and (for web-management) still re-read under the semaphore.
- DNS (`reconcileDNSFromDHCP`) keeps its own semaphore acquisition, so it
  runs **after** the refresh hold is released — nested `applySem` takes
  would deadlock. DNS merges the live lease set rather than the gated
  snapshot, so the split is ordering-immaterial.
- Config read nil under the semaphore → rebinds skipped (fail-closed:
  no stale apply); route reconcile still runs and still latches #11450
  debt on failure.
- An unused `applyHeldForTest` probe field briefly added during design
  was removed; no production path depends on test seams.

## Regression (`pkg/daemon/daemon_dhcp_14976_test.go`)

`TestMgmtOnlyLeaseRefreshUsesFreshSnapshotAndSerializesRoutes14976`
drives the **real** `onDHCPAddressChange` through the management-only
branch (fxp0.0 DHCP, unzoned, IPsec gateway dynamically bound). The
mgmt-route seam records whether it ran under `applySem` and lands a real
commit removing the gateway mid-refresh (deterministic interleaving, no
sleeps). Asserts: route reconcile ran under the semaphore, and **zero**

zero web-management rebinds. A 10s watchdog turns the nested-take
deadlock class into a failure instead of a hang.

`TestMgmtOnlyLeaseRefreshStillRebindsLiveGateway14976` is the adjacent
legitimate-behaviour control: no intervening commit → exactly one IPsec
rebind of the live gateway.

### RED/GREEN

- RED (`origin/master` + probes, route seam supplied by a test-only
  helper): FAILS — "management-VRF route reconcile ran WITHOUT applySem
  held" (on pristine code the route reconcile bypasses the seam, so the
  harder unconditional legs are the RED proof there; the IPsec stale-
  snapshot leg also fails pre-fix: swanctl re-rendered from the pre-wait
  snapshot).
- GREEN with the fix: both tests pass (`ok pkg/daemon 1.139s`).
