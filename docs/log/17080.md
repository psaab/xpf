# #17080 — local reverse-NAT finders preserve ForwardSessionMatch aux

Why: Six local finders in `session/lookup.rs` built
`ForwardSessionMatch` with a zeroed `SessionLookupAux`, so a reverse
companion installed from a local forward row lost its SNAT provenance
(`source_nat_static`), the #13771 residual. The same logical reverse
row got `Some(..)` when the forward was found in the shared map and
`None` when found locally (the common case), and the #13771 fixture
hand-built its match so it could not catch the divergence.

What: One constructor pair on `SessionTable` —
`lookup_snapshot_from(&SessionRecord) -> SessionLookup` and
`forward_match_from(&SessionRecord) -> ForwardSessionMatch` — now
builds every local snapshot: the six zeroed finders
(`lookup_ipsec_reply_alias_at`, `find_forward_nat_match_expiry`,
`find_forward_nat_quote_match_at`,
`find_unique_established_forward_nat_match_at`,
`find_forward_nat_match_inner`, `take_synced_local`) and the
previously hand-spelled populated twins (the probe family,
`find_forward_wire_match_expiry`, `find_forward_wire_match_inner`,
the mutable lookup result). `take_synced_local` captures the aux
before `remove_entry` drops the leak incarnation. `Default` is
removed from `SessionLookupAux`; deliberate synthesizers with no
matched entry (synced reverse synthesis) use the explicit
`SessionLookupAux::unknown()`. The embedded-ICMP fallback now
propagates the match's aux instead of zeroing it. The #13771 fixture
obtains its match from `find_forward_nat_match_expiry` on an
installed SNAT row instead of hand-building it.

Validation: `cargo check` clean. Named cells (`-- --exact`, 7 passed):
`local_reverse_nat_finders_preserve_aux_17080` and
`take_synced_local_preserves_aux_17080` pin session_id / `Some(false)` /
leak incarnation through every local finder;
`local_finder_reverse_install_preserves_snat_provenance_17080` is the
vq13_p01b shape asserting `Some(false)` on the local reverse row and
the shared reverse row; the #13771 trio (unchanged survives, withdrawn
revokes, missing-provenance fails closed) passes through the rewritten
real-finder fixture, plus the pre-existing
`take_synced_local_only_removes_helper_local_sessions`. RED proof: with
the finder aux temporarily zeroed again, all four new/rewritten cells
fail; restored, they pass.

Risk: The mutable packet lookup keeps its hand-spelled aux (its
record borrow ends before post-processing; routing it through the
constructor would need a second probe, which the #13079 guard
forbids). No wire format changes; `unknown()` is value-identical to
the old `default()`.
