# #15759 — `top`/`up`-prefixed commands strip quotes, bracket lists, and pipe modifiers

## Why

`ParseTopUpPrefix15082` lexed a `top`/`up` line into tokens and the
two dispatchers reconstituted the inner command with
`strings.Join(inner, " ")` (`pkg/cli/cli_dispatch.go`,
`cmd/cli/shared.go`):

- Quoted strings were unquoted by the lexer, so
  `top set system host-name "a b"` / `up set description "wan  uplink"`
  were re-dispatched as separate bare tokens with interior spacing
  collapsed — a different value than typed.
- The strict gate lexer stops at the first `|`/`{`/`}`/`;`, so
  `top show | compare` and `top show | display set` tokenized to a
  bare `show` and the pipe modifier never reached the renderer.
- Bracket lists survived only by accident (the store lexer strips
  `[`/`]` as sugar on re-parse); their raw grouping was lost, and
  the quote/pipe legs were code-proven broken by construction.

Plain unquoted commands were unaffected; the defect was confined
to quoted, bracketed, and piped inner commands under a prefix.

## What

- `pkg/config/authz_config_mutation_9154.go`:
  `ParseTopUpPrefix15082` now also returns `innerLine` — the
  unconsumed tail of the original line sliced at the lexer byte
  offset after the consumed prefix (`top`, or `up` plus an unquoted
  numeric count classified exactly as `ResolveTopUpPrefix15082`
  classifies it). A quoted `"top"`/`"up"` is never consumed as the
  prefix verb. Bare navigation yields `innerLine=""`; malformed
  prefixes fail closed as before. `inner`/`innerQuoted` token views
  are unchanged for gate/arity consumers.
- `pkg/config/lexer.go`: `Lexer.Position()` exposes the current
  byte offset so the tail can be sliced instead of re-joined.
- `pkg/cli/cli_dispatch.go` and `cmd/cli/shared.go`:
  `dispatchTopUp15082` dispatches `innerLine`, never
  `strings.Join(inner, " ")`. Both surfaces now execute exactly
  the un-prefixed command at the target cursor.

NOT changed: the gate (`configMutationPaths` /
`authorizeConfigMutationDepth9939` already unwrap via
`ResolveTopUpPrefix15082` on tokens), gRPC/REST handlers (they
receive already-resolved lines; no `top`/`up` surface), bare
navigation, and bracket handling in the store lexer.

## Validation

- RED pre-fix: the named regression
  `TestParseTopUpPrefixPreservesQuotesPipesAndBrackets` does not
  compile (4-value API absent); dispatch-level cells fail when the
  dispatch is reverted to `strings.Join(inner, " ")` with the new
  API kept — local quoted cell stores `wan uplink` (quotes and
  doubled space lost), pipe cell renders the hierarchical tree
  instead of a `[edit …]` diff, remote cells send
  `interfaces description wan  uplink` (unquoted) and a
  HIERARCHICAL ShowConfig instead of SET. The bracket cell passes
  under the join as well (noted: bracket grouping is re-derived
  by the store lexer, so it is a preservation guard, not RED).
- GREEN post-fix: `go test ./pkg/config/ -run
  'TestParseTopUpPrefixPreservesQuotesPipesAndBrackets|TestResolveTopUpPrefix15082|TestTopUpPrefixed|TestPopEditPathIdentity'`
  PASS; `go test ./pkg/cli/ -run 'TestTopUpQuotedValueSurvives15759|TestTopShowComparePipeSurvives15759|TestTopBracketListSurvives15759|TestTopDelete|TestUpDelete|TestTopUp'`
  PASS; `go test ./cmd/cli/ -run 'TestRemoteTop|TestRemoteUp'`
  PASS (quoted Set input byte-for-byte, SET format RPC, cursor
  restored); `go vet ./pkg/config/ ./pkg/cli/ ./cmd/cli/` clean;
  touched files gofmt-clean; `git diff --check` clean.

## Risk

- Behaviour delta is confined to `top`/`up`-prefixed lines whose
  inner command carries quotes, brackets, or a pipe: they now
  execute as typed instead of mangled. Malformed prefixes and
  nested `top`/`up`/`edit` still fail closed; the gate adjudicates
  the same token view as before, so no new fail-open direction.
- A quoted first inner token after `up` is not treated as a count
  (matching the resolver's `quoteAt` guard); a block comment
  spanning the `up`/count boundary is not peeled by the slicer —
  the inner dispatcher re-lexes the raw tail and its own lexer
  handles comments as it does for un-prefixed lines.
