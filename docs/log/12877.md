# #12877 — gate filter port terms on `has_l4_ports(protocol)`

- **Issue**: #12877 — [research D7-11] `port_terms_match` does not gate on
  `has_l4_ports(protocol)`, so protocol-unconstrained firewall filter port
  terms (`destination-port-except`, `source-port-except`, `source-port`)
  match ICMP and ICMPv6 query packets.
- **Branch**: `fix/12877-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12877`
- **Base**: `173014500` (`origin/master` when the worktree was created)

## Why

`parse_flow_ports` (#3067) gives ICMP/ICMPv6 query traffic the pair
`(identifier, 0)` as pseudo source/destination ports so echo traffic can hold
a session key, and those values flow into every `term_matches_v4/v6` caller —
cold frame walk, cached-flow re-walk, and #7212 static revalidation.
`port_terms_match` gated port predicates only on the fragment shape
(`is_fragment && !l4_present`) and the enforcement context (`ports_unknown`),
never on the protocol itself. A protocol-UNCONSTRAINED term — the legitimate
shape that `check_cross_field_satisfiability` deliberately passes (its
never-match reject only fires when a protocol IS declared) — therefore
evaluated those pseudo ports for real:

- `destination-port-except 80; then discard` matched every ICMP query (the
  pseudo dst "port" 0 is not 80, and `port_match` inverts membership for
  `except`), dropping ping or PBR-steering it into the wrong routing table;
- `source-port <id>` matched any echo whose identifier equaled the configured
  port;
- `source-port-except <n>` matched every query whose identifier differed from
  `n` — i.e. effectively every query.

(A positive `destination-port <n>` never matched ICMP even before: the pseudo
dst port is 0, and the parser fail-closes port 0 outright, so no real port
set can contain it.)

## What

- `userspace-dp/src/filter/engine/matching.rs`: `port_terms_match` now takes
  the evaluated `protocol` and, whenever the term carries ANY port
  constraint, requires `ip_proto::has_l4_ports(protocol)` (TCP/UDP only, the
  #3111 single source of truth) before evaluating a port predicate — in BOTH
  polarities (positive and `*-except`), fail-closed. The gate uses the RAW
  protocol argument, not the #11338 fragment-sentinel resolution: a packet
  whose protocol argument is the 255 sentinel has no usable L4 header, so it
  has no authoritative ports either — agreeing with the fragment half of the
  gate on every reachable shape. TCP/UDP behavior is unchanged.
- Contract notes updated: `filter/mod.rs` (the #7212/#11338/#12877 contract
  block), `filter/README.md` (the revalidation `Never` bullet), and
  `docs/config-schema.md` (the #3723 cross-field H01 entry).

## Regression coverage

Three tests in `userspace-dp/src/filter/tests.rs`, each a protocol-unconstrained
term exercised against ICMP/ICMPv6/GRE tuples and real TCP/UDP — the three
defect shapes the issue names (`destination-port-except`, `source-port`,
`source-port-except`); a positive `destination-port <n>` never matched ICMP
even before the fix (the pseudo dst port is 0 and 0 is never in a real port
set — the parser fail-closes port 0 outright, `parse_port_spec`):

- `destination_port_except_never_matches_portless_protocols_12877` — the
  issue's decisive fixture: `destination-port-except 80; then discard` must
  not match ICMP, ICMPv6 (identifier 0x1234, pseudo dst 0), or GRE (0, 0),
  while TCP/UDP ports keep their exact match/except behavior.
- `source_port_term_never_matches_icmp_identifier_12877` — a positive
  `source-port 4660` must not match an echo with identifier 0x1234 (numerically
  equal), while TCP 4660/4661 keep their verdicts.
- `source_port_except_never_matches_icmp_query_12877` — `source-port-except 80`
  must not match an ICMP query via its identifier; UDP 80/81 keep their
  verdicts.

## Risk

Narrow and fail-closed by construction: the only behavior change is that a
port-constrained term no longer matches packets whose protocol carries no
ports — the same verdict the explicit `from protocol gre; destination-port 80`
shape already gets from the commit gate and the compiler backstop, now
extended to the protocol-unconstrained term and to the ICMP/ICMPv6 query
pseudo-ports. Portless protocols fall through to the next term exactly as an
unsatisfied match always has; TCP/UDP matching is byte-identical. Operators
who (incorrectly) relied on `destination-port-except` dropping ICMP regain
ping passthrough, which is the Junos semantic.
