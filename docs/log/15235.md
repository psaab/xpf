# #15235 — cli: fix cohort — remote-cli diag (A51-02, A51-03, A51-04, A51-06)

- **Timestamp**: 2026-10-19
  - **Action**: Fix four validated diagnostic defects together: remote-CLI ping deadline, ping count/size narrowing, LLDP TX global tap, and sysinfo cumulative CPU ratio.
  - **File(s)**: `pkg/diagcmd/diagcmd.go`, `pkg/diagcmd/ping_clamp_timeout_15235_test.go`, `pkg/diagcmd/ping_timeout_15235_test.go`, `cmd/cli/main.go`, `cmd/cli/ping_timeout_15235_test.go`, `pkg/lldp/lldp.go`, `pkg/lldp/tx_protocol_15235_test.go`, `pkg/sysinfo/processes.go`, `pkg/sysinfo/processes_cpu_15235_test.go`, `pkg/sysinfo/processes_cpu_renderer_15235_test.go`, `docs/log/15235.md`

## Mechanisms (verified at base `fa3fae56a4`)

- **A51-02**: `cmd/cli/main.go` `handlePing` used `context.WithTimeout(..., 60s)` while the server (`pkg/grpcapi`/`pkg/api` `pingExecTimeout`) budgets `count*1s+15s` floored 30s capped 150s — 115s at the 100 clamp. A `count 100` remote ping lost its summary at 60s.
- **A51-03**: `ParsePingOptions` accepted any `int` and `cmd/cli` cast `int32(parsed.Count)`. `count 4294967297` wrapped to 1 probe remotely, while the local console clamped to 100. Same for `size` vs `MaxPingSize` (65507).
- **A51-04**: `pkg/lldp` `newIfSession` created the TX socket with `htons(ETH_P_ALL)` and never bound/read it — N global packet taps (one per LLDP port), every kernel-path frame cloned to each until buffers fill.
- **A51-06**: `pkg/sysinfo` `WriteProcessesSummary` read the cumulative `cpu ` jiffies once and printed since-boot ratios as current `CPU: x% user...`, unlike Junos/top interval figures.

## Change

- `pkg/diagcmd`: `ParsePingOptions` now clamps count via `ClampPingCount` and size to `MaxPingSize` before any narrowing; non-negative int-overflow tokens cap to the max (matching the local console), negative overflow still errors. New shared `PingExecTimeout`/`PingClientTimeout` (= server budget + 15s slack, count 100 → 130s).
- `cmd/cli`: `handlePing` deadline is `diagcmd.PingClientTimeout(parsed.Count)`.
- `pkg/lldp`: TX socket protocol is the new `txProtocol = 0` constant; `Sendto` still supplies LLDP ethertype/ifindex. No `/proc/net/packet` 0003 tap for LLDP TX.
- `pkg/sysinfo`: CPU% is a two-sample delta (500ms, all jiffy fields in denominator; guest/guestNice not double-counted). Both gRPC and local surfaces inherit it via the shared renderer; the command now takes ~0.5s longer.

NOT changed: server-side `pingExecTimeout` mirrors in `pkg/grpcapi`/`pkg/api` (values identical to the new shared formula), traceroute 60s, local-console ping argv pass-through for non-numeric/non-positive tokens (via `buildPingArgv`, not `ParsePingOptions` result), LLDP RX bind/recv, and any neighbouring behaviour.

## Risk

- `show system processes summary` (both surfaces) now takes +500ms for the sampling interval — deliberate, matches top/Junos interval semantics.
- Remote ping may now run to 130s at count 100 instead of being cut at 60s; server ceiling (150s) still bounds the handler.
