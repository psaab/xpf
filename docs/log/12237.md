# Issue #12237 — exclude quarantined zones from HA RG ownership

- **Timestamp**: 2026-10-08 (`fix/12237-zone-rg`)
- **Why**: Colliding zones `z174` and `z214` share stable zone ID 53547; `z214` is quarantined from dataplane enforcement. `buildZoneRGMap` nevertheless unioned their distinct RGs into the same ID entry. The unattributable-session fallback sync-owns on any primary RG in that entry, so a primary for the quarantined zone's RG could sync the survivor's session.
- **What**: Filter `config.ZoneQuarantineExclusions` while building the HA zone-to-RG map. Added a split-RG collision regression that asserts the survivor maps only to RG 1 and its unattributable session is not sync-owned by RG 2, but is owned by RG 1.
- **Files**: `pkg/daemon/daemon_ha_userspace.go`, `pkg/daemon/per_rg_test.go`, `docs/log/12237.md`.
- **RED-before**: On base `a714c90d472a3c3d98a3799831cfef3ec311a61c`, a throwaway `TestRepro12237QuarantinedRGContribution` observed `map[53547]=[1 2]` and failed because a survivor-zone session was sync-owned when only RG 2 was primary.
- **Validation**: `go build ./pkg/daemon ./pkg/cluster` passed; `gofmt -l` on touched Go files was empty; `TestBuildZoneRGMapSkipsQuarantinedCollisionLoser12237` passed after the change. Full scoped suites `go test ./pkg/daemon ./pkg/cluster -count=1` passed (daemon 171.967s; cluster 114.165s). No broader reds were observed.
- **Residual**: No live-cluster mutation or HA session-sync run was performed; acceptance was verified with the package-level session-ownership regression.
