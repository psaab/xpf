## Scope adjudication

- **In scope (issue acceptance, verbatim):** "Move the diag budget
  block (`PingExecTimeout`, traceroute timeout, ceiling clamp) and
  the shared exec constants into pkg/diagcmd. Make both servers call
  `diagcmd.PingExecTimeout`. Delete pkg/api/exec_timeout.go's budget
  half and grpcapi's duplicate. Update the
  `TestNoUnboundedForkOutsideTheDeclaredExemptions6552` allowlist in
  the same PR." All done.
- **Semantics preserved:** servers clamp count before the call and
  diagcmd clamps internally — identical results for every clamped
  input; the exported sever tables changed only for counts >100,
  which no handler can produce (`ClampPingCount` ≤100). Traceroute
  60s, ceiling 150s, floor 30s, slack 15s unchanged.
- **`runTimeout`/`Output`/`CombinedOutput`:** the issue names them
  verbatim duplicates; they moved as plain diagcmd helpers. The
  #6552 limiter acquisition did NOT move: grpcapi's wrappers still
  acquire `acquireDiagSlot()` first, and api's `diagRun` still sets
  `WaitDelay = diagcmd.RequestExecWaitDelay` inline (its fork is not
  one of the moved helpers). A diagcmd helper carrying the limiter
  would silently change api behaviour; none does.
- **NOT touched:** the local console CLI's local traceroute 120s
  (`pkg/cli/cli_request_ping.go`) — a local child bound, not the
  client-outlives-server contract; the factoryreset copy of the
  helpers (different package contract, uncapped-by-design wipe path,
  #16138); daemon's apply-path 15s (contract reference, import cycle).
