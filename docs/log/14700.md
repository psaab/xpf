# #14700 narrowed alias ghost bypass + mixed-family reject prefix-list — engineering history

Issue: psaab/xpf#14700 (D13-03). Lane branch: `fix/14700-campaign`,
base `origin/master` 7ac591cd84.

## Defect A (present at base)

`pkg/frr/policy_chain_narrowed_deny_10129.go`:
`narrowedAliasEligible10821` returned true for any fall-through/empty
survivor regardless of `GhostsAreSuffix`, short-circuiting the
`!GhostsAreSuffix && !narrowedGhostsAfterTerminator10821` refusal in
`narrowedAliasCollision10129`. The alias appends its deny after all
survivors; a ghost authored before/between survivors (the canonical
`[DENY-BOGONS, ACCEPT-CUSTOMER]` shape) was ordered to preempt the
survivor's permits, so trailing-deny cannot restore semantics — routes
the ghost would have rejected that match a survivor accept term are
accepted. Reachable only via tolerant load / HA peer-sync / rollback
(strict commit rejects undefined chain members).

## Fix A

`narrowedAliasEligible10821` now delegates to the suffix-safe
`narrowedAliasEligible10129` (requires `GhostsAreSuffix`). Non-suffix
fall-through/empty sites fall through to the existing refusal in
`narrowedAliasCollision10129` unless every ghost follows a provable
terminator (`narrowedGhostsAfterTerminator10821`, unchanged — its
`[MATCHALL, GHOST, B]` safe case and `[GHOST, MATCHALL]` unsafe case
stay green). Suffix aliases unchanged. Consumers updated:
`TestNarrowedGhostFirstMiddleAliasesDenyAcrossBGPContexts10821` →
`TestNarrowedGhostFirstMiddleRefusedAcrossBGPContexts14700` (same
8 BGP direction/AFI cells, now asserting refusal + no alias emitted);
README and narrowing/manager comments.

## Defect B (present at base)

`pkg/frr/policy_render.go`: `danglingPrefixList[plName]` was cleared if
any per-family ref rendered, and `emitVariants` then `continue`d past
the missing family's ref — a reject term over a mixed list with one
all-malformed family emitted only the other family's deny; routes of
the dropped family got `RMAP_NOMATCH` and fell through to later
accepts / BGP default. The in-code rationale ("deny-all would deny
routes its fine branch never rejected") is wrong for the dropped
family: the fine branch never matches those routes either.

## Fix B

Track per-family dangling refs (`prefixListDanglingFamilies`). Fully
dangling names keep the #14136 whole-term deny-all. For a partially
dangling reject term, `emitPartialPrefixListDeny14700` renders one
bare deny-all per dropped family after the fine families' deny
sequences (mirroring the #14137 split route-filter pattern). Bare
deny technically matches every family, but fine-family routes that
matched the term's other AND clauses already terminated at the fine
deny, and valid configs never reach here. Accept/non-terminating
terms keep subset behaviour (dropped ref does not emit). Suppressed
when the term has same-type route-filters (split there would widen).
`TestMixedPrefixListPartiallyMalformed_14136` updated to the new
contract (reject: v4 deny + dropped-family deny-all + trailing deny).

## Residuals / operator-visible delta

- Non-suffix narrowed chains on tolerant paths now fail the whole
  apply closed (FRR retains last-good) instead of attaching a
  survivors+trailing-deny alias. Operator must define the missing
  policy-statement or remove it from the chain. This is the intended
  fail-closed posture already used for non-suffix terminating shapes.
- Mixed reject with other AND match types: the dropped-family deny-all
  fires even for routes failing those other clauses (unknowable set;
  pre-existing fully-dangling deny-all has identical semantics).
