# #12082 — align GRE tunnel instance ownership across planes

## Why

At base `83b5c9553`, an interface-level GRE tunnel with only
`tunnel routing-instance destination blue` made the kernel bind target `blue`
(`TunnelConfig.RoutingInstance`), but the userspace interface-instance map was
empty and both the base and unit snapshot rows had `RoutingInstance=""` and
`RoutingDomain=0`.

The bare-list-only control assigned `blue` on both sides. Expanding the
cross-plane fixture to explicit list-only membership of `gr-0/0/0.0` exposed a
second gap: the kernel bound the device to `blue`, but its parent
`gr-0/0/0` snapshot row remained in the default instance. The expanded test
failed with `kernel bind target "blue" != InterfaceSnapshot ""` for that row.

## What

The effective interface-row owner is now resolved once by
`config.ForEachRoutingInstanceInterfaceMembership`; both userspace snapshots
and the strict #11061 fabric-zone gate consume it. It includes RI-list
membership, explicit tunnel stanzas, and tunnel-sibling rows, with the same
#11060 contested-device and active-instance filters in both paths. The gate now
rejects A1, where a stanza-owned tunnel shares a zone with a default-instance
link, and accepts A2, where stanza and list membership both resolve to `blue`.

Expansion is limited to tunnel devices so ordinary physical unit membership
remains exact and does not pull its parent row into a VRF (#9132).

The Junos-style `tunnel routing-instance destination` stanza now scopes the
tunnel's connected prefixes to `blue.inet.0` as well as selecting its outer
transport table (#10653). The zone host-inbound view likewise resolves stanza
ownership to `vrf-blue` and its tunnel slave, matching the kernel VRF bind.

The remaining strict-accepted tunnel-stanza targets (undefined, forwarding, or
reserved `mgmt`) are tracked separately in #12520.

## Risk

Stanza-owned tunnel snapshot rows change from default `RoutingDomain=0` to the
instance ID (observed `blue` domain 525590). Existing sessions over the tunnel
will not match across this change; during a rolling HA upgrade, nodes on
different versions can disagree about the session domain.

For Junos-style tunnel stanzas used as transport-only configuration, connected
tunnel prefixes move from `inet.0` to `blue.inet.0`. Default-instance static
routes via the tunnel will no longer resolve in the userspace FIB.

The host-inbound zone view changes from direct `gr-0-0-0` ingress to the
`vrf-blue` master with `gr-0-0-0` as its VRF member scope. This reflects the
kernel's VRF enslavement; live kernel/FRR/HA traffic was not validated. The
Rust wire structure is unchanged.

After upgrade, strict commit validation rejects existing zones that mix a
stanza-owned or sibling tunnel with default-instance members. The A1 snapshot
rows are observed at blue (domain 525590) and MAIN (domain 0); parent rows were
0/0. [INFERENCE from the Rust code path, not live-traffic verification]: tolerant
boot marks these mixed-owner zones fabric-ambiguous. [INFERENCE from the
routing-instance consumers]: stanza-owned tunnel traffic now also carries blue
into NAT from/to routing-instance scope, TUN-origin reverse-table selection, and
ICMP error routing. No live traffic was exercised. The PR body is parent-owned
and still needs this upgrade note.
