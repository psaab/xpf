# #17091 — the documented mixed-base protocol gate ran in no binary; three hand-kept copies (R4-Q46-03)

- **Timestamp**: 2026-10-27
  - **Action**: unified the triplicated mixed-base protocol gate into one
    Go rule with one shared cross-language fixture.

    STEP-0 finding: `upgrade.GateMixedBaseSwap`
    (pkg/upgrade/imageversions.go) had no non-test Go caller — the doc
    overclaimed. The live gates were two other copies:
    `targetWireVerdict` (pkg/upgrade/rolling.go, LANE-1) and
    `_gate_mixed_base` (scripts/deploy/xpf-deploy.py, LANE-2), pinned
    only by retyped vector tables. The Go function was spectrum-ware:
    seven code/doc sites named it as the executor.

    Fix:
    - New `upgrade.GateProtocolCompat(target, peerHA, peerWire,
      unknownWire UnknownWirePolicy) ProtocolCompatVerdict` is the
      single Go rule. `RefuseUnknownWire` / `PermitUnknownWire` encode
      the one deliberate lane difference (LANE-1 permits a pre-#7990
      unknown wire per #14991; LANE-2 refuses). The verdict carries
      `Err` for the cannot-run case (nil/missing target), so an
      unprovable target stays an error and never a peer refusal.
      `GateMixedBaseSwap` and `MixedBaseVerdict` are deleted (no shim).
    - `targetWireVerdict` is now a thin adapter passing
      `PermitUnknownWire`; its body no longer re-implements the window
      (`grep -c 'peerHA < target.HAProtocolMinCompat'
      pkg/upgrade/rolling.go` == 0).
    - New shared fixture
      `scripts/deploy/mixed_base_gate_fixture.json` (target, missing,
      peer HA/wire, policy, expected survive|refuse|error), consumed by
      `TestMixedBaseGateFixture17091` (Go, which also asserts the
      LANE-1 adapter agrees on permit rows) and
      `MixedBaseFixture17091Tests` (Python), following
      version_fixture_16190. The negative-peer-wire row is python_only
      (Go's uint16 cannot represent it; Go parse-side rejection stays
      pinned by TestParseImageVersions_NegativeSessionSync_FailsClosed).
    - `_gate_mixed_base` docstring and every citing comment/doc
      (pkg/cluster/sync.go, sync_auth.go, sync_wire_version_7990.go,
      sync_fence_ack_7147.go, pkg/upgrade/kernel_drain.go,
      pkg/cluster/README.md, docs/in-place-upgrade.md,
      docs/install-images.md, docs/ha-failover-status.md) now name the
      real executor (Python for LANE-2, GateProtocolCompat for LANE-1).
      Historical logs/reviews keep the old name as history.
    - Residual, stated not hidden: the Python executor keeps its own
      fail-closed body (it runs where no Go binary is present). What
      changed is that the boundary is now pinned: both languages run
      one fixture, so a rule change must edit one fixture plus both
      executors, and a one-sided edit reds that language's fixture test
      (mutation-verified below), instead of drifting silently.

    Named cells (hermetic, no broad suites):
