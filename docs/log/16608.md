# #16608: NormalizeEditPathTokens re-lexes the space-joined cursor, splitting a quoted whitespace element

- **Timestamp**: 2026-10-25
- **Action**: `NormalizeEditPathTokens`
  (`pkg/config/authz_config_mutation_9154.go`) re-lexed
  `strings.Join(editPath, " ")`, so a stored lexed token bearing interior
  whitespace (`lan in`, from `edit firewall family inet filter "lan in"`)
  split into two tokens. Every later set/delete/annotate/copy/insert under
  that cursor then landed on a new empty `filter lan`, commit check passed,
  and the applied filter `"lan in"` was unchanged — on both CLIs. The cursor
  is now kept as lexed tokens: when any stored token bears whitespace it is
  re-lexed from the quoted join (`JoinConfigPathTokens`), so it recovers as
  exactly one element; a cursor with no whitespace-bearing token keeps the
  raw joined lex #14716 requires, because raw decorated tokens
  (`"system"`, a `/*`…`*/` pair split across stored tokens) only collapse
  when re-lexed as typed and quoting them would turn them into inert data.
  The two spellings cannot coexist in one real cursor (a raw `strings.Fields`
  writer could never store a whitespace token; a lexing writer never stores
  comment/quote decoration), so the branch is unambiguous. The gate's
  split-comment re-lex (`normalizeEditPath14716`) now quotes only the line
  tokens and keeps its raw-cursor prefix guard, so a whitespace cursor falls
  back to the lexed cursor instead of a split spelling. `[edit …]` banners
  on both CLIs and `| compare` headers (`diffNodes` in
  `pkg/config/ast_format.go`, whose child paths now come from node `Keys`,
  never `strings.Fields(KeyPath())`) quote tokens via
  `JoinConfigPathTokens`, so `filter "lan in"` reads as one element. The
  local/remote `edit` arms normalize the existing cursor before appending
  the freshly lexed fragment, `top`/`up` resolve and restore against the
  normalized cursor, and the groups gate replays quote the cursor with the
  raw remainder instead of a `strings.Fields` re-join.
