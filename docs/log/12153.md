# #12153 — require active networkd before bootstrap lifeline changes

- **Timestamp**: 2026-10-08 (`fix/12153-netd-precheck`)
- **Action**: refuse bootstrap management-interface changes unless `systemd-networkd` is active, and make installer preflight require that prerequisite instead of claiming xpf enables or installs it.

## Red before

Added `TestBootstrapLifelineRefusesRenameWhenNetworkdInactive12153` and ran it on base `a714c90d4` before adding the guard:

- `go test ./pkg/daemon -run '^TestBootstrapLifelineRefusesRenameWhenNetworkdInactive12153$' -count=1 -v` failed as expected. It found both `10-xpf-fxp0.link` and `10-xpf-fxp0.network` written, and observed the rename and `networkctl reload` seams invoked despite injected inactive networkd.

## Change

- `setupBootstrapLifeline` probes `systemctl is-active systemd-networkd.service` before early-input setup, lifeline recording, network-file writes, or NIC changes. A failed/non-active probe logs a warning and leaves the host in bootstrap without changing the management interface.
- Added injectable command/state seams and regressions for inactive-state zero side effects plus exact active-state classification.
- Installer preflight now refuses unless networkd is active and explicitly says the xpf package does not install or enable it. Updated its top-level prerequisite description to match.
- Existing bootstrap-lifeline tests stub the active prerequisite so their behavior remains isolated from the host's actual systemd state.

## Validation

- **GREEN after**: the same regression passed; `systemdNetworkdActive` status-classification cases passed.
- `go build ./pkg/daemon` passed.
- `go test ./pkg/daemon -count=1` passed after the implementation and final regression tests (`ok`, 178.749s).
- `gofmt -l` on all touched Go files returned no files; `sh -n scripts/dist/install.sh` passed.
- `python3 -m unittest discover -s scripts/dist -p 'test_install*.py' -v` passed all 21 installer tests, including active/inactive networkd preflight cases.

## Residual / risk

No live systemd service transition or real NIC rename was exercised. The inactive path intentionally leaves the host in bootstrap with its management NIC unchanged; the operator must enable/start networkd and restart xpfd to retry. Installer preflight checks that networkd is active at install time; operators must also keep it enabled/configured for future boots because xpf does not do so.
