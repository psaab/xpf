# #16584 — drained session-delta batch lost on response-write failure now arms resync

- **Timestamp**: 2026-10-24
- **Action**: `drain_session_deltas` and the owner-RG collect destructively
  popped a batch into the control response; if encode/write/flush then
  failed (peer hit its 3 s deadline and closed, or the serial backlog
  stalled the round trip), the handler returned `Err`, the accept loop
  logged it, and the batch vanished — no re-queue, no `set_delta_loss`.
  The closes in the batch left stale standby rows until peer GC. Fixed
  deliver-or-resync (#2442/#2874/#5290):
  - `afxdp/session_delta.rs`: `drain_session_deltas_fair_tracked` records
    which bindings contributed; the old fair helper delegates to it.
  - `afxdp/coordinator/status.rs`: `drain_session_deltas_attributed`
    returns `(deltas, contributing slots)` (the plain drain delegates);
    `arm_delta_loss_for_slots` / `arm_delta_loss_for_workers` (the latter
    via slot→identity→live) arm the latch; cfg(test) seams seed a
    worker-bound binding and consume a slot's latch.
  - `afxdp/ha/export.rs` + `coordinator/session_manager.rs` +
    `binding_state/export_buffer.rs`: `OwnerRgExportWait` carries the
    worker ids parallel to its export buffers (threaded through the
    open-window adopt/begin), and `wait_and_collect_attributed` diffs each
    buffer's `export_drained` counter to report the workers that
    contributed to the page; `wait_and_collect` delegates.
  - `server/handlers/{session_deltas,export}.rs`: record the contributing
    slots/workers and flag a persist only for a non-empty drain/collect.
  - `server/handlers/mod.rs`: the tail encodes+flushes first; on any
    encode/write/flush failure with a non-empty batch it arms loss on
    every contributor (skipping quarantined state) before returning the
    error, and only then runs `write_state` (persist-after-flush; the
    #5294 deliver-then-surface ordering is preserved in effect).
  - `server/README.md`: documented the #16584 contract beside #5294.

- **Risk**: A failed write now triggers one owner-RG resync per
  contributing binding (debounced by the single-bool latch) — the
  intended recovery, bounded to episodes where a batch was actually
  lost. Empty drains no longer write the state file; the file is
  best-effort observability and self-corrects on the next periodic
  `write_state`. No wire change.
