# Issue #13647 — embedded ICMP fabric-zone propagation

Status: confirmed defect; fabric ingress-zone overrides are now carried through same-family and NAT64 embedded-ICMP NAT matching.

## Scope and evidence

- Tracking issue: https://github.com/psaab/xpf/issues/13647.
- Defect: the authenticated `ingress_zone_override` was dropped on embedded ICMP NAT matching paths. Each matcher passed `None` to `ingress_routing_domain`, losing the fabric zone's routing domain. The NPTv6 path also selected its ingress zone from the ifindex map without honoring the stamped override.
- Fix: add the override to `NatMatchCtx`, pass it from both same-family and NAT64 poll-descriptor paths, use it for the IPv4, IPv6, and NAT64 ingress routing-domain lookups, and prefer it for NPTv6 ingress-zone selection. Ordinary lookups retain their existing behavior when no override is present.
- Regression coverage: direct matcher tests cover same-family IPv4 ICMP, IPv6/NPTv6, and both NAT64 conversion directions with a fabric zone whose mapped routing domain differs from the default domain.

## Validation

- RED on unmodified behavior: `cargo test --manifest-path userspace-dp/Cargo.toml fabric_stamped_icmp -- --nocapture` demonstrated a failure for the NPTv6 fabric-zone case: the matcher resolved the default/incorrect routing domain and missed the session in the stamped zone. This established the cited mechanism before the fix.
- GREEN: `cargo test --manifest-path userspace-dp/Cargo.toml 13647 -- --nocapture` passed all three issue regressions.
- Full package test: `cargo test --manifest-path userspace-dp/Cargo.toml` ran 7,970 tests; 7,961 passed, 8 were ignored, and one unrelated existing test failed: `afxdp::tests_9950::f035_parked_fragment_overlap_is_rechecked_on_retry_10659` (`parked-head: the sibling must pass before the parked frame is retried`, left 0 / right 1).
- Production build succeeded: `cargo build --manifest-path userspace-dp/Cargo.toml` (existing warnings emitted).

## Risk and coverage

- The change only propagates existing zone authority into routing-domain matching; it does not change packet formats, ingress validation, or the no-override path.
- Regression tests exercise the common matchers directly, not live AF_XDP traffic or cluster behavior.
