# #14956: policy fails closed on fragment-no-L4 sentinel against protocol-only deny/reject rules (D24-02 leg 1)

- **Timestamp**: 2026-10-18
  - **Action**: Fixed the leg-1 fail-open validated in research run
    `tpzkKgAuZL` (3-way MATERIAL). A protocol-only application term (no
    port, no ICMP type/code constraint — e.g. `protocol udp`, compiled
    as an empty-range `range_terms` entry) matches on the known
    protocol alone, so for a known protocol the flowless path decides
    it via `CompiledApplications::matches`. For the
    `SHIM_PROTO_FRAGMENT_NO_L4` sentinel (255) the protocol is unknown:
    `matches()` missed (no `by_protocol[255]` entry) and
    `has_l4_constrained_term` also missed (empty ranges are not
    L4-constrained, and its 255 arm only scans port/ICMP constraints),
    so a protocol-only DENY/REJECT was never recorded as a skipped
    fragment deny in `try_match_rule`. The fragment then fell through
    to a later permit, a default-permit, or the junos-host
    deliver-on-no-match fall-through — fail open. Fixed by adding
    `CompiledApplications::has_any_protocol_term` (true iff some
    protocol carries an empty-range protocol-only term; `match_any`
    excluded so `application any` direct-matches the sentinel first,
    as today — an `any` deny evaluated for the sentinel direct-matches
    via `matches()` and never reaches this arm) and OR-ing it, gated
    on `protocol == SHIM_PROTO_FRAGMENT_NO_L4`, into the
    `FragmentDenyOverlap` classification in `try_match_rule`. The
    existing override machinery (`note_skipped_frag_deny`,
    `apply_frag_deny_override_and_count`, the transit default-permit
    override, and the junos-host fall-through override) then drops and
    attributes the fragment to the skipped deny/reject — transit
    (zone-pair/wildcard/global tiers), junos-host (exact/from-any/
    global tiers), Deny and Reject alike, with no other behaviour
    change: known protocols, port-bearing terms, ICMP-typed terms,
    permit rules, and `l4_present` paths are untouched (a DENY whose
    only term is ICMP-type-constrained is covered by the pre-existing
    `packet_icmp.is_none()` arm of `has_l4_constrained_term`, not by
    this change). Leg 2 (multi-zone junos-host scope) was refuted by
    the Go commit gate and is excluded, per the issue's binding scope
    narrowing.
