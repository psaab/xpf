# Issue #15679: `security flow traceoptions packet-filter protocol` validation, numeric/named matching, and show rendering

- **Timestamp**: 2026-10-19
- **Action**: validated `packet-filter ... protocol` at commit. `validateFlowTraceFlagsAndFiltersAST` now rejects (strict) / warns + marks `InvalidPrefix` (lenient) for empty (`protocol ""`), unknown (`bogus`), `0`, and out-of-range (`256`) values via `filterProtocolResolvable` (the in-package mirror of `appid.ProtocolNumber`; `pkg/config` cannot import `pkg/appid`), and for a `packet-filter` stanza specifying none of `source-prefix`/`destination-prefix`/`protocol`. The `protocol` leaf in `schema_security.go` is now a typed leaf (`ValueIdentifier` + `validateFlowTraceProtocol15679`) so `SchemaValidate` rejects the same set. `compileFlow` marks `InvalidPrefix=true` for an unresolvable/empty/0 protocol and for a selector-less filter, so a leniently-loaded value fails closed (match-none) in `NewTraceWriter` instead of widening to trace-everything. Deviation from the issue text, recorded: the issue says validate with `appid.ProtocolNumber(v) != 0`, but that function returns `(uint8, bool)` in this tree and `0` is a *resolvable* HOPOPT value; it is rejected here because the trace writer's presence-based selector cannot distinguish proto-0 from "any protocol", so accepting it would silently widen the filter.
- **Action**: `TraceWriter` now stores `protoNum uint8` + `hasProto bool` resolved via `appid.ProtocolNumber(pf.Protocol)` (unresolvable → filter invalid/match-none) and `matchFilters` compares against `rec.ProtocolNum` (falling back to resolving the rendered `rec.Protocol` only when `ProtocolNum==0`, mirroring `pkg/cli/monitor.go`). Deleted `normalizeTraceProto`, which only knew tcp/udp/icmp/icmpv6 numbers, so numeric `47` and named `ospf`/`gre` filters now match. Updated the two existing `trace_test.go` helpers that built `f.proto` directly.
- **Action**: `show security flow traceoptions` (both `pkg/cli/cli_show_flow.go` and `pkg/grpcapi/server_show_flow.go`) now appends ` proto=<value>` when `pf.Protocol != ""`.
