# Issue #14120 — input three-color policer on host/passthrough packets

- **Issue:** An interface `filter input` three-color policer was metered only in the TX-selection leg (`resolve_cos_tx_selection*`), which transit packets take at egress. Host-bound (LocalDelivery) and Stage-11 IPsec passthrough packets reinject to the host and never egress, so a burst matching the ingress policer bypassed its token charge and red discard/remarking. The lo0 filter had the same hole fixed in #5857; this is the interface-input twin.
- **Context read:** Issue body + deep-review D2-03 research (codex MATERIAL, opus COHORT). Cited paths re-verified at origin/master bfcf00f8f.
- **What:** Thread `InputPolicerMeter` through the non-routing input-filter walk. `Inline` (Stage-11; host-bound session hits via the stored disposition) meters in the walk plus a routing-bearing metered walk for policers on/past a `routing-instance` term; `DeferToTxSelection` (transit/flowless) keeps prior behavior so transit is charged exactly once. Session MISS captures policer handles at the LocalDelivery install site, meters the first packet, stores handles on `SessionEntry::input_policers`; LocalDelivery HITs replay them (Fresh directly, stale at capture). Red folds to silent `Discard` (`policer_drop_action`), never a reject reply. The tunnel outer gate meters its PBR-term policer only when the outer destination is firewall-local (interface primary / interface-NAT / FIB-local), preserving transit decap deferral.
- **Layer choice:** Meter ownership follows whether a TX-selection leg will run for the packet — decided at the poll-descriptor call sites (disposition/Stage-11/tunnel-locality), not inside the filter walk, so transit cannot double-charge and captures stay side-effect-free.
