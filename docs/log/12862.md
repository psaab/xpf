# #12862 — tear down SYN-pressure victims across session mirrors

- **Timestamp**: 2026-10-13 (`fix/12862-syn-pressure-shed-teardown`)

## Why

At the 90%-capacity pressure threshold, the packet path removed local half-open TCP session rows and returned the worker NAT allocations, but left shared session rows live until the worker flushed its bounded Close-delta queue after processing the current RX batch. A later descriptor in that same batch could materialize the stale shared row and forward the shed flow after its NAT allocation had been returned. The pressure path also needed to retire the BPF mirrors, flow-cache descriptors and peer NAT-holder claims as part of teardown.

## What

- Acquire the tuple-install lease before any destructive teardown; synchronously remove the shared row only while the lease is held, and decline cleanup if it no longer matches the shed opening.
- Release coordinator steering claims, invalidate the current binding's flow-cache slot, and delete the shed session's BPF steering, conntrack and reverse-NAT rows under that same lease.
- Release local NAT holds and replicate deletion to peer workers while the lease remains held, so new installs cannot race teardown or reuse a freed NAT allocation.
- Invalidate both directions' flow-cache slots across the worker's bindings at the existing close-delta barrier.
- Extend the transactional pressure regression to seed shared opening sessions, retain the surviving opening and new SYN, and reject a same-decision established replacement as a shed-opening match.

## Risk

Shed-session cleanup is cold-path work performed only under SYN pressure. Shared-row removal checks that the current row is still the same opening shape under the shared-map lock and all destructive state changes are fenced by the tuple-install permit. If that permit is contended or the row has changed, the code leaves NAT allocated rather than freeing it while stale dataplane authority may remain. The ordinary Close delta remains for worker-loop mirror/event cleanup.
- **Identity fence (review B1/B2)**: PressureShedSession carries the victim's install-stamped identity subset; the shared-row predicate compares it inside the removal lock. One tuple lease covers all shed keys. Gate-refusal regression: shared row and NAT hold retained when the lease is held.
