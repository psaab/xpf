# #9497: DDNS update-server rendered verbatim on two PermView show surfaces and in DHCPDynamicDNSConfig.String

- **Timestamp**: 2026-09-11T04:20Z
- **Action**: Routed `update-server` through `config.RedactURL` at the three sites that still printed it raw.

  - `pkg/grpcapi/server_show_dhcp_lldp_snmp.go`
  - `pkg/config/types_system.go`

## Mechanism (origin/master `35e43ba8c`)

`showDHCPDynamicDNS` (`Update server: %s`) and `showServicesDynamicDNS` (`update-server=%s`) printed the value raw. Their four topics (`dhcp-server-dynamic-dns[-detail]`, `services-dynamic-dns[-detail]`) are priced at **PermView** in `authz_methods.go`, and no post-render scrubber runs. `DHCPDynamicDNSConfig.String()` also printed it raw.

Every sibling surface redacts the same field:
- `DDNSProvider.String()` and `MarshalJSON()`, via `config.RedactURL`;
- `ConfigTree.RedactedClone()` (`update-server` is in `urlLeafIndices`), and therefore `show configuration`;
- the #5521 feed-URL render.

`validateDDNSBackendWarnings` only warns, and `net.SplitHostPort` accepts `user:token@host`, so a credential-bearing (quoted) value commits.

**Honest narrowing (the issue's own):** the leaf is documented as `<host[:port]>`, so an operator credential there is not established as normal. What IS established is that the repository's own redaction contract classifies the field as URL-bearing while these three renderers did not. `RedactURL` leaves a clean `host:port` unchanged, so the fix costs nothing.

## Change

- `showDHCPDynamicDNS`: `config.RedactURL(ddns.UpdateServer)`.
- `showServicesDynamicDNS`: `config.RedactURL(p.UpdateServer)`.
- `DHCPDynamicDNSConfig.String()`: `RedactURL(d.UpdateServer)`, the same redaction as `MarshalJSON`.

No module docs describe these show outputs' redaction, so no docs change is needed beyond this log.
