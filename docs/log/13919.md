# #13919 — Keep scheduled DENY/REJECT eligible when time is untrusted

- **Timestamp**: 2026-10-16
- **Base**: `origin/master` `ad0ded0df`
- **Files**: `pkg/scheduler/scheduler.go`, `pkg/scheduler/scheduler_hold_failclosed_13919_test.go`, `pkg/daemon/daemon_scheduler.go`, `pkg/daemon/daemon_scheduler_hold_12885_test.go`, `docs/log/13919.md`

## Why

When the scheduler detects a wall-clock discontinuity, it publishes an all-false active map for its two-minute recovery hold. The tick callback previously passed only the separate republish-failure latch to snapshot publication. Consequently, the userspace builder treated in-window scheduled DENY/REJECT rules as ordinarily inactive and skipped them, permitting fallthrough to a later permit while time was untrusted. An unloadable configured time zone had the same action-disposition gap, including on apply seeding.

## What

Added `Scheduler.PolicyFailClosed(now)` as the publication disposition: it combines the republish latch with a wall-clock recovery hold and an unavailable committed zone. The daemon's tick callback now passes this action-aware disposition. Apply seeding also marks an unavailable zone fail-closed, including when reusing an existing scheduler generation. The scheduler's authoritative active map remains all-false: scheduled permits stay inactive, while the existing action-aware builder keeps scheduled DENY/REJECT eligible. Added scheduler regressions for hold, unavailable-zone, and trusted-clock control states, plus apply-seed coverage for an unloadable zone. No changes to the fail-closed policy for unavailable scheduler names or ordinary out-of-window rules.

## Validation

- Regression on pristine `origin/master` `ad0ded0df`: `go test ./pkg/scheduler -run TestPolicyFailClosedCoversRecoveryHoldAndUnavailableZone13919 -count=1` failed to compile because `Scheduler.PolicyFailClosed` did not exist.
- Green: `go test ./pkg/scheduler -count=1`, focused daemon hold/time-zone apply-seed tests, and `go build ./...`. `gofmt -l` for touched Go files and `git diff --check` were clean.
- Full-suite result: `go test ./pkg/... -count=1 -p 4` failed when the pre-existing `pkg/config` `TestSchemaSpellingDifferentialGate` exceeded the package's 10-minute test timeout; other package results are in the command output.

## Risk

A time jump now causes scheduled DENY/REJECT rules to remain eligible during the recovery hold, matching the existing deny-first republish-latch and heartbeat-expiry doctrine. This is the intended fail-closed behavior; permits remain inactive. An unloadable configured zone similarly retains deny/reject eligibility until corrected.
