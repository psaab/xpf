# #13919 — Keep scheduled DENY/REJECT eligible when time is untrusted

- **Timestamp**: 2026-10-16
- **Base**: `origin/master` `b90ac49f7` (includes #14011 and #14026)
- **Files**: `pkg/scheduler/scheduler.go`, `pkg/scheduler/scheduler_hold_failclosed_13919_test.go`, `pkg/daemon/daemon_scheduler.go`, `pkg/daemon/daemon_scheduler_hold_12885_test.go`, `pkg/daemon/daemon_ipmon.go`, `pkg/daemon/daemon_route_listener.go`, `pkg/daemon/daemon_route_listener_bump_11565_test.go`, `docs/log/13919.md`

## Why

When the scheduler detects a wall-clock discontinuity, it publishes an all-false active map for its two-minute recovery hold. The tick callback previously passed only the separate republish-failure latch to snapshot publication. Consequently, the userspace builder treated in-window scheduled DENY/REJECT rules as ordinarily inactive and skipped them, permitting fallthrough to a later permit while time was untrusted. An unloadable configured time zone had the same action-disposition gap, including on apply seeding.

## What

Added `Scheduler.PolicyFailClosed(now)` as the publication disposition: it combines the republish latch with a wall-clock recovery hold and an unavailable committed zone. The daemon tick callback, route-listener partial republish, and IP-monitoring partial republish now use this action-aware disposition. Apply seeding carries republish failure and wall-clock hold across generations, but does not carry an old generation's unavailable-zone state into a corrected zone. Fail-closed maps are forced all-false. The evaluator republishes both entry into and expiry of a recovery hold even when the active map does not change. Scheduled permits stay inactive while the existing action-aware builder keeps scheduled DENY/REJECT eligible. Added scheduler, apply-seed, route-listener, and zone-recovery regressions.

## Validation

- Initial regression on pristine `origin/master` `ad0ded0df`: `go test ./pkg/scheduler -run TestPolicyFailClosedCoversRecoveryHoldAndUnavailableZone13919 -count=1` failed to compile because `Scheduler.PolicyFailClosed` did not exist.
- Follow-up regressions on pre-fold `origin/master` `19186da9d`: `TestRecoveryHoldExpiryPublishesNormalDispositionWithoutMapChange13919` failed because no publication occurred; `TestRouteListenerKeepsScheduledDenyEligibleDuringRecoveryHold13919` failed with `failClosed=false`.
- Zone-recovery regression on `origin/master` `b90ac49f7`: `TestApplySeedingRecoversFromUnavailableTimezone13919` failed, staging `workhours:false failClosed=true` after changing from an unloadable zone to UTC.
- Green on the current branch: zone-recovery/apply-seed tests and earlier scheduler/route-listener regressions; `TestBuildPolicySnapshotsFailClosedLatchKeepsDenyingActionsEligible`; `go build ./...`. `gofmt -l` and `git diff --check` were clean.
- Full-suite result from the initial implementation: `go test ./pkg/... -count=1 -p 4` failed when the existing `pkg/config` `TestSchemaSpellingDifferentialGate` exceeded its 10-minute timeout.

## Risk

A time jump now causes scheduled DENY/REJECT rules to remain eligible during the recovery hold, matching the existing deny-first republish-latch and heartbeat-expiry doctrine. This is the intended fail-closed behavior; permits remain inactive. An unloadable configured zone similarly retains deny/reject eligibility until corrected.
