# Issue #16644: `test_postinst_triggered_runs_refresh_and_exits_zero` never runs the refresh (R3-N06-04)

## Why

The cell built a stale-slot ESP fixture and ran `sh debian/xpf.postinst
triggered`, but asserted only `returncode == 0` — the same as its
no-helper control. The postinst gated on
`[ -x /usr/local/sbin/xpf-uefi-slots ]`, which is absent on the test
host, so the `triggered` arm never invoked the helper and the refresh
was never observed. A wrong or disabled helper invocation in the arm
(e.g. the probe mutant renaming the helper to
`xpf-uefi-slots.disabled`) still passed all cells, leaving the #15089
refresh-on-update wiring unguarded against future regressions
(bounded only by the boot-time `xpf-uefi-slots.service` sync backstop).

## What

- `debian/xpf.postinst` (`triggered` arm): the helper path is now
  `UEFI_SLOTS_BIN="${XPF_UEFI_SLOTS_BIN:-/usr/local/sbin/xpf-uefi-slots}"`,
  gated with `[ -x "$UEFI_SLOTS_BIN" ]` and invoked as
  `"$UEFI_SLOTS_BIN" --sync-only || true`. Production default and
  best-effort/no-fail contract unchanged; an empty override falls
  back to the default (`:-`) so a stray empty env var cannot disable
  the refresh. Same env-override pattern the helper itself uses for
  `XPF_UEFI_SLOTS_ESP`.
- `scripts/image/test_slot_refresh_15089.py`:
  - `test_postinst_triggered_runs_refresh_and_exits_zero` now sets
    `XPF_UEFI_SLOTS_BIN` to the real in-tree `scripts/image/xpf-uefi-slots`
    and `XPF_UEFI_SLOTS_ESP` to a stale-slot fixture (both slots on
    `*-v1`, `EFI/ubuntu` on `*-v2`), then asserts both slots are
    refreshed to v2 byte-equal and `xpf.selector` is untouched.
  - `test_postinst_triggered_branch_is_wired` additionally pins the
    exact production default
    `${XPF_UEFI_SLOTS_BIN:-/usr/local/sbin/xpf-uefi-slots}` plus the
    `-x` gate and `--sync-only` invocation, so renaming the default
    reds even though the hermetic cell overrides the path.
  - `test_postinst_triggered_without_helper_stays_green` is now a
    true control: it injects a nonexistent `XPF_UEFI_SLOTS_BIN`
    (hermetic even on a host with the real helper installed) and
    asserts rc 0 with both slots still on v1 (no perturbation).
  - `RealDpkgTriggerTests` now injects the sandbox helper via
    `XPF_UEFI_SLOTS_BIN` in the dpkg env and takes the `triggered`
    arm verbatim, instead of string-replacing the absolute path;
    behaviour (real dpkg trigger fires, slots refresh) unchanged.

Alternatives considered: rewriting the path with sed in the test as
`test/debian/postinst-test.sh` does for layout paths (rejected — the
sed rewrite would not pin the production default, and the extracted-
arm real-dpkg cell would keep silently rewriting whatever path the
arm contains; the env override exercises the arm verbatim).

## Validation

- Baseline (origin/master c40fe406d2): 20 tests OK, with
  `/usr/local/sbin/xpf-uefi-slots` absent — proving the old cell
  passed without running the refresh.
- GREEN after the fix: `python3 scripts/image/test_slot_refresh_15089.py`
  20 tests OK; `sh -n debian/xpf.postinst` and
  `shellcheck -S warning debian/xpf.postinst` clean.
- Acceptance mutant (the issue's probe, default renamed to
  `/usr/local/sbin/xpf-uefi-slots.disabled`): suite FAILED
  (2 failures — the branch-wired pin and the real-dpkg extraction).
  Reverted.
- Invocation-disabled mutant (`"$UEFI_SLOTS_BIN" --sync-only` replaced
  by `true`): FAILED (3 failures, incl. the refreshed-bytes asserts).
  Flag-dropped mutant (`--sync-only` removed): FAILED (3 failures).
  All reverted; suite green again after restore.

## Risk

- Production behaviour unchanged when `XPF_UEFI_SLOTS_BIN` is unset:
  same absolute path, same `-x` gate, same `|| true` best-effort
  semantics, same boot-time backstop. No fail-open weakening.
- Residual: a hostile environment that pre-sets `XPF_UEFI_SLOTS_BIN`
  for dpkg could redirect the triggered refresh; the variable is
  unset in normal dpkg operation (maintainer scripts run with a
  controlled environment), and an absent/non-executable target is
  still just the pre-existing no-helper no-op. The full baked-image
  VM witness was not run in this lane; the hermetic cells exercise
  the same postinst arm, helper, and real dpkg trigger machinery.
