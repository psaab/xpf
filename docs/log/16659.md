# #16659: DNAT goldens regenerated; #6534 census closes the source-NAT/interface-quarantine cell

- **Timestamp**: 2026-10-25
- **Problem**: Two destination-NAT rule-detail goldens in
  `pkg/natshow` still expected the pre-#15607 output without the
  `Source addresses:` row that `RenderDestRuleDetail` now prints
  (dataplane enforces match source-address, #15269 C09-01), so
  `go test ./pkg/natshow/` was red on correct code. In
  `pkg/showaudit`, the #6534 census for the #16556 family
  ("security zone interface (duplicate membership)") flagged
  `pkg/natshow/source.go:renderSourceRuleDetail`: the function ranges
  `Security.Zones`-derived zone IDs and renders a zone-pair session
  count, but never consulted the duplicate-membership verdict
  (`ZoneInterfaceQuarantineReason` / `Claimants` /
  `ClaimantsForRows` / `Exclusions`), so it fell outside both the
  annotated set and the exempt set. The exemption table also still
  named `pkg/grpcapi/server_cluster.go:valueProvider`, which #16138
  moved to `pkg/grpcapi/server_complete.go:valueProvider`, so
  `TestExemptionsNameRealRenderers6534` failed. While these gates are
  red on correct code, a real NOT-INSTALLED / display-lie regression
  in these renderers ships as "the known red".
- **Fix**: Regenerated the two DNAT goldens
  (`TestRenderDestRuleDetailGolden`,
  `TestRenderDestRuleDetailLoadedGolden`) to include
  `Source addresses:      0.0.0.0/0` between the destination-address
  and destination-port rows, matching the renderer. Made
  `renderSourceRuleDetail` genuinely consult the interface
  quarantine verdict inline: for a zone-scoped rule-set, each member
  of the from/to zones is checked with
  `config.ZoneInterfaceQuarantineReason`; if either zone claims a
  quarantined (duplicate-membership, bound-to-neither) interface,
  the rule-set renders
  `sessions for this zone pair: UNAVAILABLE (quarantined zone — live counters unavailable)`
  instead of the measured tally — sessions through that interface
  never carry the pair, so the tally would present an unmeasured
  pair as measured. The check is inline (not a helper ranging
  `Security.Zones`) so the renderer itself is the census member and
  no new unannotated helper is minted for the sibling
  `security_zone` (zone-ID) family. Repointed the stale exemption
  from `server_cluster.go:valueProvider` to
  `server_complete.go:valueProvider`. NOT changed:
  `interfaceZoneMap` in `pkg/api` and `pkg/grpcapi` — already
  exempted at current master as pure interface->zone map builders
  whose consumers annotate (#16556), and their zone-ID-family
  annotation via `natScopeLine` / `writeInterfacesDetail` is
  unchanged; runtime binding/forwarding behaviour is unchanged.
