# 14147 — config-path authz desync: lexer (gate) vs `strings.Fields` (handlers) on `copy`/`rename`/`insert`

The `*-configuration` authorization gate tokenized a config-mode
line with the config lexer (`lexConfigMutationLine9938`): quoted
strings were unquoted and `/* */` comments stripped, and
`configMutationPaths` split copy/rename at the first lexed `to`
(including a quoted `"to"`, whose lexed value is also `to`) and
insert at the first lexed `before`/`after`. Every executor split
differently — gRPC `handleCopyRename`/`handleInsert`
(`pkg/grpcapi/server_config.go`), the on-box CLI
`handleCopyRename`/`handleInsert` fed by
`dispatchConfig`'s `strings.Fields` (`pkg/cli`), and the remote CLI
in `cmd/cli/shared.go` all used `strings.Fields`, which keeps quote
characters (`"to"` != `to`) and keeps comment words as path tokens.
For `rename system services ssh "to" foo to system
root-authentication` the gate adjudicated src=`system services ssh`,
dst=`foo to system root-authentication`, while the executors split
at the second bare `to` and renamed into `system
root-authentication`, a path an `allow-configuration
"^system services"` class never covers. A quoted `"before"`
likewise truncated the gated insert element short of its real
(possibly denied) tail, and comment words acted as separators for
the executors while the lexer had already stripped them for the
gate. Routing compounded it: gRPC `Server.Set` and its gate
resolver routed on raw `strings.HasPrefix(input, "copy ")`, so a
tab after the verb fell through to a bare `set` path on both sides.

Fix: one canonical split in `pkg/config`
(`config_command_split_14147.go`) built on the same lexer the gate
uses. `ParseCopyRenameCommand`, `ParseInsertCommand`, and
`ParseInsertCommandTokens` split only at a BARE (unquoted) keyword
token — a quoted `"to"`/`"before"` is a path element whose value
happens to equal the keyword, exactly as the store's lexer treats
it — and strip comments. `configMutationPaths` now calls the same
token splitters, keeping its malformed-shape fallback to gating the
whole remainder (fail-closed floor from #9938).
`ConfigMutationVerb` exposes the lexed leading verb; gRPC
`Server.Set`, its `configMutationLineFor` resolver, the on-box
`dispatchConfig` handlers (now taking the raw line), and the remote
CLI (which re-joins the lexed tokens for the wire) all route and
split through these functions, so the paths adjudicated are the
paths acted on by construction. The local CLI keeps its distinct
"reference identifier is longer than element path" message by using
the tokens form and building the ref via `InsertRefPath` after the
edit-path prefix; gRPC keeps its single usage error. No other verb's
tokenization changed; annotate's existing rebuilt gate line is
untouched.

Regression (RED on base, GREEN with the fix; RED verified by
reverting the tracked handler/gate changes while keeping the new
tests): gate level, `TestParseCopyRenameCommand14147` /
`TestParseInsertCommand14147` pin the canonical split (quoted and
comment keywords are data; absent on base), and
`TestAuthorizeConfigMutationCopyRenameInsertAgreeWithExecutor14147`
/ `TestAuthorizeConfigMutationInsertQuotedKeyword14147` include
cells that fail on base — the quoted-`before` insert cell, where
the gate allowed an element whose real tail is the anchored deny.
Executor level: `TestGRPCQuotedToRenameDeniedAtGate14147` drives

`TestGRPCHandlerActsOnLexedEndpoints14147`,
`TestCLICopyRenameActsOnLexedEndpoints14147`,
