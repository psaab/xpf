- **Timestamp**: 2026-10-25
  - **Action**: Carry the caller's lifelines into every QuarantineAll the
    installer or daemon builds. In `pkg/nftables/ipsec_divert.go`,
    `normalizeIpsecQuarantineSpec` now preserves `LifelineNetdevs`
    (normalized sorted/unique) on a non-quarantine spec instead of
    clearing it, so the transition guard in
    `InstallIpsecDivertWithDrain` and the recovery guard in
    `installNormalUnderQuarantineGuard` — both copied from the already
    normalized normal spec — inherit `[fxp0 …]`; the daemon's queue-plan

    `HostInboundLifelineIngressNetdevs(cfg)` on normal plans (candidates
    are still cleared, #15066). Daemon fallbacks that build a guard from
    a lifeline-free staged/old/active spec now stamp lifelines via
    `Daemon.withIpsecQuarantineLifelines16618` /
    `installIpsecQuarantineForDaemon16618` (spec lifelines win, else the
    live config via `liveConfig12169`, else the always-present `fxp0`):
    the ambiguous-removal fallback, both actor-start fallbacks, and the
    shutdown fallback. Also fixes the prerequisite #16703 in the same
    emitter: the `meta sdifname` lifeline accept is now emitted only on
    the inet family — the kernel rejects `NFT_META_SDIFNAME` on bridge
    with EOPNOTSUPP, which previously failed every lifeline-carrying
    two-family guard install atomically; bridge input keeps the
    `iifname` accept. Updated the two tests that pinned the old
    lifeline-clearing normalize behaviour and the bridge render shape.
