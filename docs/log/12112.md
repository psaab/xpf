## Why

The SAFI gate retained only the first unsupported name. Its warning wording also used the current AST node's unicast bit rather than the final merged group/neighbor activation, so sibling or inherited unicast could be reported as inactive. Neighbor warnings were finalized before duplicate group blocks had finished merging the same peer. Strict mixed-SAFI errors reused the lenient wording and claimed unicast remained activated even though strict compilation rejects the family.

## What

- Collect distinct unsupported SAFI names in authored order; lenient compilation emits one warning per name, while strict errors name all unsupported SAFIs on the family.
- Reword strict errors to state that the configured family is rejected on strict compilation.
- Finalize lenient group warnings after sibling activation and neighbor warnings after every group block has contributed to the merged neighbor; retain AFI, SAFI, and scope as structured metadata rather than parsing rendered text.
- Add regression tests for flat/braced multi-SAFI families, sibling and inherited activation, duplicate group blocks, contrived AFI/SAFI names, and strict rejection.
