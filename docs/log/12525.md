# Issue #12525 — handle non-zone and present-empty NAT scopes safely

## Why

NAT scope parsing drops empty values. Before this amendment, a present clause
such as `to zone ""` therefore looked like an absent clause and could be
stamped as match-any. The production `Store.SetFromInput` → `CommitCheck` path
accepted the quoted-empty zone, interface, and routing-instance forms, a
deactivated scope leaf, and a one-sided empty scope; `to zone [ ]` was rejected
by strict schema validation (#1319), but Store's lenient compile path still
reached the dataplane pre-pass.

The F2 gap was separate: interface-mode rules scoped by interface,
routing-instance, or neither have no `ToZone`, but the compiler previously
assigned their counter IDs only after named-zone egress-address resolution.
Those rows were skipped before receiving Translation-hit identity and emitted
a misleading empty-zone warning.

## What

### F1 — distinguish absent from present-empty scopes

The config compiler records a match-any default only when a `from` or `to`
clause is absent. A present clause with no non-empty scope is rejected by
strict `CompileConfig` with #7525; lenient compilation warns and omits the
affected NAT rule-set rather than widening it. The check covers source-NAT
`from`/`to`, destination-NAT `from`, and static-NAT `from`.

The dataplane gate validates each source-NAT side independently: that side
needs a typed scope or its own private compiler stamp for an absent clause.
One side's stamp cannot authorize the other's empty scope. Named zone references
still require a registered zone. The stamps are not serialized, so a
JSON-round-tripped rule-set missing a required stamp fails closed.

### F2 — retain interface-mode translation-hit identity

Source-NAT counter IDs are assigned before interface-mode egress resolution.
The #12085 to-interface, to-routing-instance, and unscoped cells now retain
nonzero Translation-hit IDs in `NATCounterIDs` even though they have no
`ToZone`. Empty `ToZone` no longer produces the misleading
`to-zone has no interfaces` warning; the warning remains for a named zone with
no interfaces. This preserves counter identity, not proof of live forwarding.

### F3/F4 — evidence and handoff

The all-empty JSON-loss case still fails closed. Additional round-trip tests
lose only the absent `from` or `to` stamp while preserving the opposite side's
scope; an OR-collapsed gate mutant accepts both, and both tests fail against
that mutant. This supports the per-side claim without asserting an unrelated
behavior.

The PR body should reference, not close, #12525. The required #12085 lab capture
remains open on #12085: this PR provides software-level compile/counter
regressions only, and no live cluster forwarding test was run.

## Risk

Strict compilation now rejects authored present-empty NAT scopes; tolerant
loading warns and omits those rule-sets rather than silently widening them.
The fix does not create a synthetic zone ID or relax named-zone lookup. Existing
interface-mode egress-address resolution remains zone-based; non-zone scope
counter identity is verified, but live traffic behavior is not. #12085 remains
the owner of the outstanding lab-forwarding evidence.
