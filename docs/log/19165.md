# #19165: with-cluster.sh refuses a lock tuple and a cluster env that disagree

- **Timestamp**: 2026-11-16
- **Action**: The defect, which I hit myself:
  - `with-cluster.sh` takes the LOCK from `XPF_CLUSTER_LOCK/OWNER/EPOCH`,
    but the FIREWALLS its VM-target guard touches (shims, mark script,
    `systemctl daemon-reload`/`enable`) from `cluster-env.sh`, which defaults
    to loss.
  - My udp cell (creating udp:xpf-testrunner4) set only the udp tuple, so at
    15:43:51Z it guarded loss:xpf-userspace-fw0/fw1 without the loss lock,
    during G6's loss ctl cell. G6 found no disturbance in that sample.
- **Action**: `test/incus/with-cluster.sh`, before taking the lock:
  - map the lock's basename to its cluster: `xpf-cluster.lock` is loss,
    `-tcp` is tcp, `-udp` is udp, and a private path names none;
  - source `cluster-env.sh` early;
  - refuse (exit 2) when `INCUS_REMOTE` names a different cluster, naming
    both and the env to export. The legacy local cluster (no `INCUS_REMOTE`)
    is not compared.
  - `docs/engineering-style.md` now says to export `BPFRX_CLUSTER_ENV` with a
    tcp/udp tuple, and why.
- **Action**: `test/incus/with-cluster-selftest.sh`, cell (k):
  - a udp-named lock with the loss env is refused (2), the command does not
    run, and no owner file is written;
  - the same lock with the udp env runs.
- **Validation** (udp:xpf-testrunner4 via `scripts/vm-test-run.sh`):
  - the cluster-cell selftest (73 cases) and the build-identity selftest (11)
    pass;
  - mutant, the refusal condition replaced with `false`: cell (k) FAILS
    (KILLED: "expected refusal (2) with the command not run, got rc=0
    ran=yes");
  - `shellcheck -S warning` clean.
  - **File(s)**: `test/incus/with-cluster.sh`,
    `test/incus/with-cluster-selftest.sh`, `docs/engineering-style.md`,
    `docs/log/19165.md`

- **Timestamp**: 2026-11-16 (fold, Codex bounded check of b7g: N2)
- **Action**: Verified. The check compared only the env's `INCUS_REMOTE`
  label with the lock's cluster. `cluster-env.sh` keeps an
  already-qualified override (`_xpf_cluster_ref`), so the udp env and lock
  with `FW0=loss:xpf-userspace-fw0` passed, and the VM-target guard and the
  command then touched loss without the loss lock. The check also ran after
  the reentrant return, so a nested cell could change targets under its
  ancestor's lock.
- **Action**: `lock_target_mismatch` runs in a command substitution (so the
  caller's environment is untouched). It sources `cluster-env.sh`, then
  refuses the cell when the env label OR either RESOLVED `FW0`/`FW1`
  carries a remote other than the lock's cluster. It runs BEFORE the
  reentrant early return. A bare target (the legacy local cluster) has no
  remote to compare.
- **Action**: New cells:
  - (l) udp lock + udp env + `FW0=loss:…` is refused (2), the command is
    not run and no lock is taken; an explicit `udp:` override runs;
  - (m) a nested cell under the outer udp lock that overrides FW0 to loss
    is refused on the reentrant path.
  Mutants KILLED: no target check (by (l)); the check moved after the
  reentrant return (by (m)).

- **Timestamp**: 2026-11-17 (fold 2, Codex bounded check of b7h: N2)
- **Action**: Verified. `lock_target_mismatch` resolved targets only in its
  subshell. The reentrant branch then execs with the CALLER's environment.
  Codex's trace: an outer udp cell's command sources the loss env, which
  exports loss FW0/FW1 and its provenance, then runs a nested cell with
  `BPFRX_CLUSTER_ENV` back on udp. In the subshell, cluster-env.sh's
  cross-env reset discards the inherited loss targets and resolves udp, so
  validation passed, and the reentrant exec ran with `FW0=loss:…` under
  the udp lock.
- **Action**: The check records the inherited FW0/FW1 before sourcing. It
  refuses when an inherited target, qualified the way the env qualifies
  it, is not what the lock's cluster env resolves. So the targets a cell
  execs with are exactly the ones validated, and a bare same-cluster
  override still matches.
- **Action**: Cell (n), the resolver-reset shape: the nested cell is
  refused (2), nothing runs, and the refusal names the inherited target.
  Its control, a nested cell inheriting the udp targets, runs. Mutant
  no-inherited-check KILLED by (n).

- **Timestamp**: 2026-11-17 (redo, Codex bounded check of b7h-r2: N2, N7, N8;
  the fourth round on this guard, so #19165 was pulled from b7h and redone
  with one TOTAL rule instead of another resolution case)
- **Action**: Verified.
  - N2: a bare override (`FW1=xpf-fw1`) was validated after qualification
    but executed bare, so it addressed the default remote.
  - N7: `CLUSTER_LAN_HOST` was never checked, and `test-ha-crash.sh` kills
    iperf3 on that host.
  - N8: an inherited `INCUS_REMOTE=loss` survived re-entry, because the env
    file overwrote it only inside the validation subshell.
- **Action**: The rule (`test/incus/with-cluster.sh`):
  - TARGET SET (`XPF_CLUSTER_TARGET_VARS`): `INCUS_REMOTE`, `FW0`, `FW1`,
    `CLUSTER_LAN_HOST`, `DMZ_TARGET_REF`, `MOUSE_TARGET_REF` and their
    `*_NAME`s. It comes from a census of what cluster-env.sh exports with
    a remote-qualified value in the loss, tcp and udp envs.
  - Every invocation snapshots the inherited set, resolves it once (a
    subshell sourcing cluster-env.sh), and refuses unless `INCUS_REMOTE`
    and every resolved ref are on the lock's cluster. A ref that resolves
    bare under a remote env is refused.
  - The outer cell exports the resolved values and
    `XPF_CLUSTER_TARGETS_DIGEST` (sha256 of the resolved snapshot). A
    nested cell refuses unless its inherited snapshot's digest equals the
    exported one and equals its own resolution. A STRIPPED environment
    (cluster-setup.sh's sg re-exec forwards only `BPFRX_*`/`XPF_*`) must
    instead re-resolve to exactly the exported digest.
  - The command always runs with the resolved, exported values.
  - The refusal names the first differing target. Its `diff` pipeline is
    `|| true`: under `set -euo pipefail` a differing diff had killed the
    script with status 1 before it printed the refusal.
- **Action**: Cells.
  - (n) the resolver-reset shape;
  - (o) a bare override, which runs QUALIFIED when non-nested and is
    refused when nested;
  - (p) `CLUSTER_LAN_HOST` on loss, non-nested and nested;
  - (q) an inherited `INCUS_REMOTE=loss`;
  - (r) a bare `DMZ_TARGET_REF`;
  - (s) same-cluster controls;
  - (u) the stripped sg-shaped nesting, which runs, while its loss switch
    is refused;
  - (u2) the same switch under a private lock, refused by the digest alone;
  - (t) the census over all three envs.
  Cell (h), the sg forwarding re-exec, used a fake `BPFRX_CLUSTER_ENV` for
  the nested cell. A nested cell may not switch env now, so it forwards
  the enclosing cell's real env file. Its assertion that values survive
  the sg boundary is unchanged.
