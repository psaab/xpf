# #18213: planned xpfd shutdown must not mint helper crash debt

- **Timestamp**: 2026-10-28
- **Problem**: With systemd's default `KillMode=control-group`, stopping or
  restarting xpfd sends SIGTERM to xpfd and its `xpf-userspace-dp` child
  concurrently. The child can exit and reach `superviseHelper` before xpfd's
  orderly `Manager.Close` path retires the generation. That exit is then logged
  as unexpected, increments the daemon-lifetime crash counter and restart debt,
  and can leave FWDD degraded after an otherwise planned deploy restart.
- **STEP-0**: `issue://18213` was OPEN. The `origin/master` source still contained
  `handleUnexpectedHelperExitLocked` in the current-generation supervisor path;
  merged PR #7242's #5838 follow-up only retired the process generation on
  `stopLocked` and did not mark a generation intentional before daemon-wide
  shutdown.

## Fix

- `test/incus/xpfd.service`: use `KillMode=mixed`, which sends the initial
  systemd stop signal to xpfd alone; remaining cgroup processes receive SIGKILL
  only after xpfd exits or `TimeoutStopSec` expires.
- `pkg/daemon/daemon_run_shutdown.go`: immediately after bounding control I/O,
  dispatch an optional helper-stop-intent hook before later teardown waits.
- `pkg/dataplane/userspace/process_supervisor.go` and
  `pkg/dataplane/userspace/legacy_dataplane.go`: mark the active helper
  generation as intentionally stopping through the published runtime adapter.
- `pkg/dataplane/userspace/process.go`: `stopLocked` also marks its live helper
  generation before its shutdown request or SIGTERM escalation. The waiter
  checks that generation-specific bit before crash accounting, logging, or
  restart scheduling.
- New named cells cover the real daemon shutdown dispatch, shipped unit's
  `KillMode`, a marked helper SIGTERM, a daemon-initiated `stopLocked`, and a
  genuine SIGKILL on the next generation.

## RED evidence

Before the fix, the named daemon regressions failed:

- `TestRunShutdownSequenceMarksHelperIntentBeforeDataplaneTeardown18213`
  observed `[bound-control close]` rather than a helper-intent dispatch.
- `TestXPFDUnitUsesMixedKillModeForGracefulHelperShutdown18213` observed no
  `KillMode` directive.

## Risk

The intentional-stop mark is attached to one `helperGeneration`; it cannot
suppress a later helper's failure. Genuine SIGKILL after a planned stop remains
unexpected-exit accounting, including its crash record and restart debt. The
work does not alter crash handling for externally killed helpers.
