# 14411 — SNMPv3 USM security level silently downgraded (DR13-H4)

- **Timestamp**: 2026-10-17
- **Action**: loop the packed SNMPv3 user parser over both protocols; extend
  the #9155 strict gate to case-variant, wrapped, and ancestor-placed
  protocol keywords.
- **File(s)**: `pkg/config/compiler_system.go`,
  `pkg/config/compiler_validate_strict_snmpv3_level_9155.go`,
  `pkg/config/snmpv3_packed_protocols_14411_test.go` (new).

## The defect

Three hierarchical-text placements compiled to a weaker USM level than
written, commit-clean and warning-free (all measured on master):

1. Packed auth-first: `user alice authentication-sha256
   authentication-password A privacy-aes128 privacy-password P;` —
   `parseSNMPv3UserKeys` switched on `keys[0]` only and never looped, so
   the privacy half was dropped: written authPriv, served authNoPriv.
2. Case-variant: `Authentication-SHA256 { … }` failed both the gate's
   exact-lowercase prefix test and the parser's exact-case switch, so the
   user compiled bare (noAuthNoPriv).
3. Wrapped/ancestor: `user alice { authentication { authentication-sha256
   { … } } }`, or a protocol block under `local-engine` beside the user —
   the gate scanned only the user node's Keys and direct children's Keys,
   so the keyword was never seen and the user compiled bare.

## Why the existing gates could not catch it

#7530 fires only on a NAMED compiled protocol missing material; #9155's
tree gate inspected only exact-case tokens in direct positions. A keyword
the compiler discarded before either gate ran is invisible to both — the
same structural blindness as #9155-R02, one shape family over.

## Fix

- `parseSNMPv3UserKeys` walks the whole packed run one protocol pair
  (protocol, password-leaf, value) per step, at all three call sites (flat
  v3 line, hierarchical instance line, compact protocol child). A password
  value is consumed only as its pair's value slot and never re-parsed as
  a keyword. Priv-first packed now compiles authPriv too (previously only
  the privacy half was read and #7530 rejected it as privacy-without-auth).
- Wrapped protocol children under a user (`authentication { … }`) compile
  at the written level via `applySNMPv3ProtocolChildren14411`, so the
  tolerant path never serves a persisted wrapped config as a bare user.
- The #9155 gate: case-insensitive prefix test with exact-case known-set
  match; recursive user-subtree scan; recognised keywords placed outside
  the compiler-resolved user (ancestor braced blocks, wrappers, ancestor
  packed runs with no `user <name>` before them, bare password leaves
  under a user, `system { snmp { … } }` roots) are strict-rejected.
  Packed/elided runs that legitimately reach a user (flat line, elided
  chain, R02 SetPath chain — including the privacy half nested under the
  password node, which `hoistAndSplitRun8939` lifts) are recognised and
  left to the user-level checks, so no previously-valid spelling regresses.

Strict rejects; lenient downgrades to the existing
`snmpv3 security keyword` warning and compiles the written level where the
compiler can read it (#1960 no-brick).
