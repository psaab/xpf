  change), and each is enough on its own to VOID the group.
  1. **Wrong capture.** `test-failover.sh` handed
     `ha_rg_standby_status_verdict` the `show chassis cluster status` capture

     renderer (`pkg/dataplane/userspace/format/status_sections.go`) has always

     `HA groups: rg0 active=true watchdog=N; rg1 active=false watchdog=N; ...`.
     `ha_standby_status_verdict` now parses the `rg<N>` entry out of that
     line. It requires exactly one `HA groups:` line and exactly one entry
     whose id is the whole token (`rg10` is not `rg1`). Missing, ambiguous
     or malformed is VOID. A missing field in a file that looks like a
     cluster-status capture names the mistake in the VOID reason.

  `rg1 active=false` as its own line, the parser's shape, which the product
  never prints. The fixtures and the parser agreed with each other and not
  with the product. They are replaced by:

    with a PASS row for rg1 and a FAIL row for rg0 (the golden's rg0 is
    active);
  - the REAL capture from tcp run `test-failover-ha-2269141` (node1,
    `phase=mid`), copied byte-identical to
    `test/fixtures/ha-assurance/rg1-failback-mid-node1-18686.{stats,status}`
    (sha256 `172f1eff…` / `96ded06f…`).
- **Selftest rows**, each the real `.stats` with exactly ONE line changed

  - PASS: the capture as is, and with an extra `rg10` entry.
  - FAIL, one row each: `Enabled: false`, `Forwarding armed: false`,
    `rg1 active=true`, `Ready bindings: 0/30`.
