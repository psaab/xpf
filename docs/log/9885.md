# #9885 — a leading-dash interface name commits clean and poisons the reconfigure batch

- **Timestamp**: 2026-09-12
- **Action**: refuse a leading `-` in `ValidateInterfaceName` as a third
  actively-dangerous class; add `--` to the `networkctl reconfigure` argv.
- **File(s)**: `pkg/config/validate_interface_name.go`,
  `pkg/config/validate_interface_name_option_9885_test.go`,
  `pkg/networkd/networkd.go`,
  `pkg/networkd/reconfigure_end_of_options_9885_test.go`,
  `pkg/networkd/activation_tail_5718_test.go`, `pkg/networkd/README.md`,
  `docs/log/9885.md`.

## The damaging case is the one that does not error

`--help` and `--version` **exit 0 without acting**, so ONE badly named interface
leaves EVERY interface in the batch unconfigured while `Apply` reads success and
clears the #4954 retry debt. `-x` would fail loudly — which is why the
harmless-looking name is the dangerous one.

## Two halves, because they fail independently

The validator's allowlist is over CHARACTERS and `-` is on it (`ge-0-0-0` is the
normal spelling). The new class is the only one about POSITION, so it sits
outside the allowlist loop — no tightening of that loop could have caught it.

The argv gains `--`, the same belt the repo applies to scp (#4589), covering a
name that predates the validator or arrives from a path that does not run it.
**Verified against the real tool, not assumed:** on systemd 261
`networkctl list -- lo` and `networkctl list lo` produce identical output.

## The argv site was censused, not taken from the report

`git grep -n 'runNetworkctl(\|"networkctl"' -- pkg/ | grep -v _test` →
**exactly one** site builds names into argv (`networkd.go:567`). Every other
call, including `pkg/daemon/linksetup.go:690`, passes the literal `"reload"`.

## Mutation matrix — 6/6 KILLED by declared target, FULL-PACKAGE baseline

Three of the six are controls: over-refusing every dash (would reject
`ge-0-0-0`), keeping `--` while dropping the operands, and an operand helper
that always returns true.

## What this change got wrong first

The first version **broke three existing tests and I did not see it** —
`TestApplyTailSurvivesExternalDebtDischarge_5718`,
`TestApplyTailNotRepeatedOnceComplete_5718`,
`TestExternalReloadSuccessOwesTheTail_6912`, all comparing the exact argv
through the shared `wantActivationTailArgv`.

Cause: **both the cell run and the mutation-matrix baseline were filtered to
`-run 9885`.** A baseline filtered to your own cells cannot observe a regression
in anyone else's, so 6/6 was a perfect score over a smaller world. The
integration gate caught it; the gate being the FIRST thing that could catch it
was a hole in the local loop. Closed: the matrix baseline now runs the full
packages and refuses a `-run` filter outright.

The fix was one line because those tests had centralised the expectation. Its
doc comment says the subject is the INTERFACE SET, spelled out rather than
derived so it cannot be true by construction; the separator is spelled out for
the same reason, with a comment saying why, and `pkg/networkd/README.md` is
updated in the same change.
