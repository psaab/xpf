# #12141 — dirty source provenance

Backfill lane on base `a714c90d4` (new base). Same defect and same
provenance policy as the prior `fix/12141-provenance` lane: see that
lane's `docs/log/12141.md` for the full RED → GREEN transcript on base
`1c384b9a4`.

## Why

The Makefile and image bake compared the worktree only with the index. A staged
edit therefore looked clean, and an untracked source file compiled into the
package was invisible. The Debian package version and signed image provenance
could identify `HEAD` while the build consumed different bytes.

## What

- Added `scripts/image/build_provenance.py` as the single dirty-state probe used
  by both `Makefile` and `scripts/image/bake.py`. It compares tracked paths with
  `HEAD` (staged and unstaged), non-ignored untracked files under the package/
  image build-input roots, and ignored generated BPF Go sources consumed by Go.
  Git failures fail closed as dirty; unrelated notes and ignored build output
  do not mark the build dirty.
- Marked the three generated Debian kernel-unit staging copies ignored. They
  are outputs, not source inputs, and must not flip a clean pre-build identity
  during bake.py's post-build recheck.
- Kept the Debian `.dirty` version suffix in lockstep with the bake. `make deb`
  rejects `DEB_GIT_DIRTY`/`DEB_VERSION` overrides that misstate current source
  provenance before building. A normal bake refuses an explicit `--version`
  that differs from the current pre-build package identity, and rechecks that
  identity after `make deb`. `--skip-build --version` continues to bind the
  selected prebuilt package, rather than requiring the current checkout to
  match it.
- Added `source_dirty: true|false` to the image provenance sidecar, derived from
  the package version suffix. The sidecar is already included in the
  `SHA256SUMS` set signed by the image pipeline, so the new state is covered by
  that signature.

## Risk

A full appliance bake and a new minisign artifact were not produced. Scoped
signing tests ran; the new sidecar field is verified inside the checksum
payload that the existing bake pipeline signs. Dirty attribution deliberately
covers all tracked changes, non-ignored untracked paths in the defined
package/image roots, and ignored generated BPF Go sources under Go package
roots.
