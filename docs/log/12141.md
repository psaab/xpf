# #12141 — dirty source provenance

This backfill carries the original #12141 dirty-source policy onto the
`fix/12141-campaign-pub` lane. This follow-up folds Astra round-1 findings
F1–F5 from PR #12357 head `5529e069d5fc24585b86508a6337a9e720c06621`;
the original lane's RED → GREEN history is retained below.

## Why

The Makefile and image bake compared the worktree only with the index. A staged
edit therefore looked clean, and an untracked source file compiled into the
package was invisible. The Debian package version and signed image provenance
could identify `HEAD` while the build consumed different bytes.

## What

- `scripts/image/build_provenance.py` remains the single dirty-state probe used
  by both `Makefile` and `scripts/image/bake.py`. It compares tracked paths
  against `HEAD`, scans non-ignored untracked package/image inputs (including
  `vendor/`), and asks Go for the compiled sources of `./cmd/xpfd` and
  `./cmd/cli`. Ignored files in that compiled set are checked with Git, so
  `.git/info/exclude` and configured global ignore rules are covered without
  marking ignored files in unused packages dirty.
- The probe refuses unattestable source/compiler redirections in `GOFLAGS`
  (`-overlay`, `-modfile`, `-toolexec`, and `-pkgdir`) with a clear error.
  Git/Go enumeration errors or warnings fail closed as dirty/unknown.
- `make deb` still rejects a `DEB_VERSION` dirty suffix inconsistent with the
  current source before building. `DEB_VERSION` selects the expected package
  identity before build; the post-build check compares the requested identity
  with a fresh `deb_version_for_head()` result, so an exported override cannot
  hide source drift. `--skip-build --version` still uses the selected package's
  identity, but the current checkout is probed separately because its image
  scripts are copied into the image.
- The manifest's `source_dirty` field now describes the current checkout
  inputs copied into the image, independently of the prebuilt package version.
  For `--skip-build`, the existing shared probe covers the whole tracked
  checkout plus its defined untracked build-input roots; this conservative
  choice avoids duplicating a second dirty-state algorithm or maintaining a
  separate list that could drift from the `virt-customize --copy-in` inputs.
  The sidecar remains in the checksum set signed by the image pipeline.

## Risk

No full appliance bake, live cluster, or live traffic run was performed.
Focused F1 coverage exercises `bake.main` and the sidecar with libguestfs and
guest validation isolated; it does not replace the appliance validation gate.
The provenance helper's Git and Go subprocess calls currently have no timeout,
so a stalled repository/tool process can block the probe or image build.
Unattestable `GOFLAGS` redirects fail closed, and Go input enumeration errors
or Git warnings report dirty/unknown rather than clean. The `vendor/` root is
included among untracked build inputs; Go's compiled-source enumeration also
covers vendored files actually used by either command target.
