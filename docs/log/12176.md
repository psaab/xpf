# Issue #12176 — enforce harness census in CI

- **Timestamp**: 2026-10-07
- **Change**: Added a pull-request CI job that runs the fail-closed harness census and its hermetic self-test. The self-test now verifies the workflow invokes the census and confirms a fresh undeclared harness causes that exact CI command to fail.
- **Files**: `.github/workflows/test.yml`, `test/incus/harness-census-selftest.sh`.
- **Red-before**: At the pinned base, `.github/workflows/test.yml` had zero census references, so CI had no census invocation to reject a fresh undeclared harness. Running the existing census directly against an isolated fixture with one reached control and one fresh undeclared harness exited 1 and named the offender; the missing behavior was CI enforcement, not census detection.
- **Green-after**: The added self-test confirmed the CI command rejects `test/incus/fresh-undeclared-harness.sh`; the complete census self-test passed (30 passed, 0 failed), and the real-tree census passed (61 runnable harnesses: 31 reached, 30 declared unreached).
- **Validation**: `bash -n test/incus/harness-census-selftest.sh`, `sh -n scripts/harness-census.sh`, and `shellcheck --severity=warning` passed. PyYAML parsed `test.yml` and verified both census job commands; `yamllint`/`actionlint` were unavailable. Default ShellCheck also reports informational findings on unchanged base lines (also present on the pinned base). The clean-tree census and full census self-test passed.
- **Risk**: CI reports the new status but merge blocking remains operator-managed. The owner must attest/configure the `CI tests / Harness census and self-test` required status in branch rules; no branch-protection settings were changed.
