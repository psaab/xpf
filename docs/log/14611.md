# Issue #14611 — `security log format sd-syslog` is not Junos sd-syslog

- **Issue:** sd-syslog emitted `<PRI>1 TS HOST xpf - - - RT_FLOW SESSION_OPEN src=...` (NILVALUE APP-NAME/PROCID/MSGID/SD around the flat body), while the `[junos@2636...]` SD lived only in `structured`, which travelled under RFC 3164 with a doubled `RT_FLOW -` lead-in. SIEM parsers keyed on `RT_FLOW_SESSION_*` MSGID / junos SD saw neither on the sd-syslog stream.
- **Fix:** `formatSDSyslogLine` (pkg/logging/format_rtflow.go) is the single RFC 5424 builder shared by `SyslogClient.Send` and `LocalLogWriter.Send`: session events decompose the structured body into `RT_FLOW - RT_FLOW_SESSION_CREATE|CLOSE|DENY [junos@2636.1.1.1.2.129 ...]` (HOSTNAME present, no MSG after SD); non-SD RT_FLOW bodies keep `RT_FLOW - - <flat>`; generic text keeps `xpf - - - <msg>` (unchanged). The ringbuf fanout now supplies the structured body to sd-syslog clients/writers as well as structured. `structured` decision (documented in docs/config-schema.md): same Junos RT_FLOW body as MSG — RFC 3164 stream envelope / local timestamp+tag event prefix — with the redundant `RT_FLOW - ` lead-in stripped. `binary`/`syslog`/unset unchanged.
- **RED:** New `pkg/logging/sd_syslog_14611_test.go` on master: stream APP-NAME="xpf" want RT_FLOW; event-mode same; structured doubled `RT_FLOW - RT_FLOW`. Partial-revert (restore NILVALUE line in SyslogClient.Send only) also reds the stream cell.
- **GREEN:** `go test ./pkg/logging/ -run 'TestSDSyslog|TestStructuredStreamStill|TestLocalLogWriter_EventModeFormats_3409' -count=1` passes (RFC 5424 parser asserts APP-NAME=RT_FLOW, MSGID=RT_FLOW_SESSION_CREATE, SD-ID junos@2636.1.1.1.2.*, source-address param, no MSG tail, for both stream (raw frame → EventReader → UDP wire) and event-mode (file) writers). Full `go test ./pkg/logging/ -count=1` passes; `go test ./pkg/config/ -run 'TestLog|3349'` passes; gofmt/vet clean.
