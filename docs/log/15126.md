# Issue #15126 — LossResync re-export / peer→local promote re-emits SESSION_CREATE (A93-01)

- **Issue:** psaab/xpf#15126 (deep-review A93-01, research-validated
  MATERIAL 3-way). Lane branch: `fix/15126-campaign` off
  `origin/master` `e87cdeac56`.
- **Scope:** `userspace-dp` session-delta RT_FLOW CREATE gate only.
  No wire, Go, or HA-sync behaviour change — the HA session-sync
  frame still fires for every leg; only the duplicate RT_FLOW
  SESSION_CREATE is suppressed.

## Defect (present at base)

`afxdp/session_delta.rs` `flush_session_deltas` emitted an RT_FLOW
SESSION_CREATE (type 15, #2508) for every `Open` delta with
`metadata.log_session_init`, inside a guard that excluded only
`CommandExport` provenance:

1. **LossResync owner-RG re-export** — `session/install.rs`
   `open_export_delta_with_provenance` builds an `Open` delta with
   `bulk_resync: true`, `created_ns: 0`, provenance `LossResync`,
   and the live entry's metadata (so `log_session_init` is kept).
   Every failover/failback re-export therefore re-logged every live
   `then log session-init` session.
2. **Peer-synced → local promote** — `session/mod.rs`
   `update_session`'s promote branch pushes an `Open` delta with
   `bulk_resync: false`, provenance `Incremental`, and the promoted
   metadata. It took the same CREATE path, duplicating the record
   the originating node already emitted at admission.

One extra CREATE per logged session per re-export and per promote;
audit-trail integrity only, no enforcement loss.

## What

- `session/entry.rs`: new `SessionDelta::is_admission` bit, carried
  on the delta like `bulk_resync` so the producer decides and no
  drain call site can choose wrongly.
- Sole `true` producer: the install Open in
  `session/install.rs` (`install_with_protocol_with_origin_and_source_nat`,
  the #2508 admission). Every other constructor — the LossResync /
  CommandExport re-export (`open_export_delta`), the promote Open
  (`update_session`), Update, all Close producers, the HA bulk
  export (`ha/export.rs`), and test fixtures — carries `false`.
  Struct-update clones (`..delta.clone()`) inherit the bit.
- `afxdp/session_delta.rs`: the CREATE gate now requires
  `delta.is_admission` in addition to `Open` + `log_session_init`.
  The lossless HA sync push above it is untouched, so re-export and
  promote still deliver their session-sync frame exactly once.
- NOT changed: SESSION_CLOSE emission, `bulk_resync` non-arming
  (#8593/#14646), CommandExport echo suppression (#9630), Update
  sync (#9412), or any producer's delta kind/provenance/counters.

## Risk

- Behaviour delta is confined to RT_FLOW SESSION_CREATE records for
  sessions that were already created and logged: one fewer duplicate
  CREATE per LossResync re-export and per promote. Fresh admissions
  still emit exactly one CREATE; HA sync, close records, and
  flowexport are untouched.
- Residual: a session whose admission CREATE was itself lost
  (best-effort `try_send`) will no longer be re-logged by a later
  re-export/promote. That matches the issue's acceptance
  (`resync_creates=0`, `promote_creates=0` while install gives 1)
  and the producer-gated, best-effort nature of the CREATE frame
  (#2508); the lossless HA sync leg is unaffected.
