# #16866 — RIP: gate connected/RIP-learned advertisement behind the export policy (R3-B07-03)

- **Timestamp**: 2026-10-25
  - **Action**: xpf rendered `network <if>` for each RIP neighbor
    interface and attached the group export only as
    `redistribute <src> route-map`, so ripd originated the
    connected subnet of every RIP-enabled interface and
    re-advertised RIP-learned routes outside any export filter —
    while Junos advertises neither without an export policy that
    accepts them (configs with no export advertised every RIP
    interface subnet). The #16625 per-interface
    `distribute-list prefix ... out <if>` gate now applies to
    EVERY RIP render: group-less configs synthesize an implicit
    group carrying the `redistribute` chain, groups with no
    export and interfaces enrolled only globally carry the empty
    chain, and the empty chain renders the explicit deny-all list
    (`deny 0.0.0.0/0 le 32` / `deny ::/0 le 128`) instead of being
    skipped. The accepted-prefix computation is exact only for
    prefix-only policies: any `from protocol`, community, as-path
    or next-hop condition is inexpressible at a destination-only
    gate for ripd's native candidates (interface routes skip
    redistribute route-maps in FRR 10.7.1; RIP-learned routes have
    no `redistribute rip` verb to carry one), so such chains —
    including the canonical `from protocol static` ONLY-50 probe —
    fail closed deny-all + warning rather than permitting native
    connected/RIP routes that happen to share an accepted static
    prefix; the static redistribution enrols through its
    source-correct per-source route-map (whether it is then
    advertised depends on the interface gate, which is deny-all
    for such chains — a deliberate withdrawal, not preserved
    traffic). Chain lowering preserves Junos control flow:
    an explicit statement-level `then reject` terminates the
    chain, ANY `then next policy` term (prefix-conditional,
    unconditional, source-only, or empty-prefix-list — zero
    prefix entries prove nothing about whether the jump fires)
    makes the chain inexpressible and fails closed, and an
    accept term carrying a longest-match stop fails closed
    too (one ordered list cannot express term-no-match-continue
    without over-denying later accepts).
    For prefix-only chains, connected routes on non-RIP
    interfaces enrol through exactly ONE composed
    `redistribute connected` attachment (the chain machinery's
    entry, never per-policy appends — FRR keeps
    one route-map per source, so appends would overwrite the
    composed map and silently withdraw earlier policies' routes).
    `redistribute rip` is never rendered: FRR 10.7.1 rejects the
    self-source (vtysh exit 2, executed) and its route-map name
    would dangle (the self protocol is excluded from per-source
    map definitions); RIP-learned routes are confined by the
    prefix gate alone. A terminal term mixing `from prefix-list`
    with route-filters (Junos ANDs distinct from-types) and any
    term whose entries fail canonical normalisation likewise
    fail closed; a rejecting term carrying a longest-match stop
    fails closed rather than terminally denying candidates the
    term never matched. The shared longest-match base identity
    now includes prefix length (#17843, fixed here as this
    gate's dependency).
    Bare protocol tokens and undefined policy names remain
    inexpressible and fail closed; the authored bare `redistribute`
    verbs are retained in the stanza. Positive controls: the
    prefix-only policy permits exactly its accepted prefix, two
    distinct direct-accepting groups (PA/PB) through the full
    managed section yield a single defined composed connected
    attachment with each group's gate permitting only its own
    prefix, and the legacy stanza lines (`network`,
    `redistribute connected/static`) are unchanged — the #16625
    legacy-byte-shape test and three golden fixtures were updated
    for the added gate. Operator-visible change: group-less bare
    `redistribute connected/static` previously advertised via
    ripd defaults; it now advertises nothing outbound (Junos
    semantics), while the verbs remain in the stanza.
    Residuals: no live ripd/two-node verification (render-level
    oracle mirroring the source report's r1/r2 cells, as with
    #16625; the generated full section and all golden fixtures
    pass the offline FRR 10.7.1 `vtysh -C` parser check);
    source-qualified export policies fail closed at the interface
    gate (deny-all) even though their redistributed sources flow
    source-correctly — honouring them per-interface would need a
    source-aware outbound filter ripd does not offer; QNH
    offset-lists remain router-global (pre-existing #16625 note).
