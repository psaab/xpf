# #18635 — Count lost HA event-stream session deltas

## Why

The HA session-sync idle predicate compared sent/received create counters, pending deltas, and the RPC-fallback `Session delta dropped` counter. It could not see a non-bulk session delta that failed the helper's lossless event-stream enqueue, so the wait could report idle after losing session state.

## What

- Added per-kind Open/Close/Update loss counters to `EventStreamShared` and `EventStreamStats`. The common lossless session-delta enqueue boundary increments them on failure, excluding bulk-resync and `CommandExport` deltas. This includes the worker flush and direct lossless producers without counting a flush failure twice; the existing generic dropped-frame counter and out-of-sync latch remain separate.
- Tunnel-remap purge counts the unattempted Close suffix after its first failed enqueue, without double-counting that failed delta; the same bulk/CommandExport filter applies.
- Projected the counters through Rust `ProcessStatus`, its JSON wire fixture, the Go status adapter, and an unconditional overview line: `Event stream HA session delta lost: <total> (open=<n> close=<n> update=<n>)`. The line is unconditional because the formatted `EventStream` block is optional, while the idle predicate needs a parseable zero.
- Extended `ha_session_sync_idle_sample` with the source event-stream-lost total baseline. It fails closed on missing/malformed evidence, treats counter rewind as re-baselining, and rejects any increase. Both failover wait loops capture and rebaseline the counter with the existing source-loss baselines.
- Added the loss-gating mutant/control to `ha-assurance-selftest.sh`, updated its status fixtures, and documented the added predicate in `docs/userspace-ha-validation.md`.

## Design decisions

The counter is incremented at `push_delta_lossless_within_seq`, rather than only in `flush_session_deltas`: tunnel-purge and other direct lossless producers can also lose non-bulk session deltas, and counting at the common failure boundary covers them. The helper method filters bulk-resync and `CommandExport`; the flush's existing bulk generic-drop accounting therefore remains independent. The distinct status line lives beside the session-delta overview counters instead of in the optional EventStream section so scripts can distinguish a real zero from missing status output.

## Risk

The new counters are additive/defaulted and do not change the protocol version. They count failed lossless enqueue attempts, not RT_FLOW producer drops or silently coalesced/skipped deltas. The existing counter-based idle predicate retains its already documented in-flight/background-create blind spots.
