# #14589 — Partial `swanctl --load-all` restores a file charon is not running

- **Timestamp**: 2026-10-16
  - **Action**: Fixed the partial-load divergence in `pkg/ipsec/manager.go`. `reloadResult` now parses the `loaded N of M ..., F failed to load` summary (connections/pools/authorities, any exit code including the rc-0 partial) into a `partialReloadError`. On a partial, `applyConfig` asks charon via `ListLoadedConns` what it actually loaded: a candidate subset is re-filed as exactly that subset (refused VPNs and their secrets dropped, survivor hashes kept) and re-loaded for verification; any other discovered set (prior set, hybrid, undiscoverable) falls back to a true rollback — prior file restored **and re-loaded**. The recovered set travels on `partialApplyError`; `ApplyGeneration`/`Clear` promote it (departed SAs torn down, `Loaded` not fired) and still return the partial error. Total (non-partial) failures keep the #10712 file-only restore and #4898 no-promotion behaviour. `clearConfig` mirrors this: empty discovered set promotes empty, otherwise prior file restored + re-loaded and promoted. Corrected the contract in `pkg/ipsec/README.md` and the stale `manager.go` comments (#4898/#10712/#9511 wording).
  - **File(s)**: `pkg/ipsec/manager.go`, `pkg/ipsec/partial_load_14589_test.go`, `pkg/ipsec/README.md`, `docs/log/14589.md`

## Risk

Verification/rollback perform extra `--load-all`/`--list-conns` calls only on the partial path. If the verification reload itself fails, xpf falls back to restore+re-load of the prior file and joins the errors; disk still names the prior set. Secrets of refused connections are dropped with their VPN entry in the subset file, so a charon restart cannot resurrect them.
