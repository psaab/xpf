# #15091 — address-book/feed prefix sets compile to an uncompressed one-Box-per-bit trie (A63-03)

## Defect

`PrefixSetV6::from_v3_literals` (and the v4/legacy factories) compiled
any set with more than 16 prefixes into `PrefixTrieV6`: an
uncompressed binary trie allocating one 24-byte `Box<TrieNode>` per
bit of every inserted prefix (`prefix_set.rs`, ex-`PrefixTrieV6::insert`).
At the documented #3934 caps (32 MiB body, `1<<20` prefixes in
`pkg/feeds/feeds.go` / `pkg/config/schema_security_dynamic_address.go`)
an in-cap IPv6 feed of random `/128`s therefore materialised ~2.9 GB
in the helper — ~70-90x the wire body — and `PolicyState.books`
(`Vec<BookEntry>`, derived `Clone`) sat inline in `ForwardingState`,
so `Coordinator::publish_runtime_view`
(`afxdp/coordinator/mod.rs`, `Arc::new(self.forwarding.clone())`)
deep-cloned the whole trie forest on every publish (neighbour
updates, snapshot refresh, fabric refresh).

## Fix

- `userspace-dp/src/prefix_set.rs`: `Trie(PrefixTrieV4/V6)` replaced
  by `Ranges(Vec<(u32,u32)> / Vec<(u128,u128)>)` — sorted, merged,
  disjoint inclusive ranges built by sorting `(network, broadcast)`
  pairs and coalescing overlapping/adjacent ranges. `contains` is a
  `partition_point` binary search. Covered and duplicate prefixes
  collapse at build time; 850k random `/128`s retain 850k ranges =
  ~27 MB, no per-bit nodes. Added fallible
  `try_from_prefixes` / `try_from_v3_literals` returning the typed
  `PrefixSetBudgetExceeded { ranges, limit }`; the infallible
  factories delegate and degrade an over-budget set to `MatchNone`
  (fail closed, never `MatchAny`). `MAX_PREFIX_SET_RANGES = 1<<20`
  mirrors the Go feed cap and is enforced on the merged range
  count. `heap_bytes()` exposes the retained payload size for the
  regression gate. The uncompressed `PrefixTrieV4/V6`/`TrieNode`
  types are removed outright.
- `userspace-dp/src/policy.rs`: `PolicyState.books` is now
  `Arc<Vec<BookEntry>>`, so the `ForwardingState` clone in
  `publish_runtime_view` is an O(1) refcount bump for the book
  table (rules still clone; they hold only `SmallVec` book indices
  and literal sets). The book loop now uses the fallible
  factories and maps a budget breach to the new typed error.
  NOT changed: rule literal sides keep the infallible factories —
  they are operator-config-sized, and their over-budget posture is
  already fail-closed `MatchNone`; only feed-backed books (the
  cited remote-influenced path) hard-reject the snapshot.
- `userspace-dp/src/policy_snapshot_error.rs`: new
  `SnapshotIntegrityError::AddressBookPrefixBudgetExceeded`
  { book_id, book_name, family, ranges, limit } and
  `RulePrefixBudgetExceeded` { rule_id, ranges, limit } (reserved
  for literal-side callers) with fail-closed Display text. A
  budget breach rejects the whole snapshot; the previous good
  forwarding state is retained (fresh boot keeps default-deny).
- `userspace-dp/benches/prefix_set_lookup.rs`: bench shape updated
  from the Box-trie replica to the sorted-range build it now gates
  (see bench header).
- `userspace-dp/src/FEATURES.md`: prefix-set row updated to the
  range representation.

## Risk

- Lookup changes from O(depth) pointer chasing to O(log n) binary
  search over a contiguous vector; for 1<<20 ranges that is ~20
  comparisons of inline integers vs 128 Box dereferences — strictly
  cheaper, and cache-friendly. Small sets (<=16) keep the exact
  legacy `Linear` scan. Semantics are boolean membership only
  (no longest-prefix tiebreak existed before or after).
- A corrupt/hand-built snapshot carrying a book above the merged
  budget is now rejected whole-snapshot where it previously
  compiled to a multi-GB trie (and would OOM the helper); in-cap
  Go-produced snapshots (<=1<<20 feed prefixes, merged count
  <= raw count) are unaffected.
