# #17031 — Consolidate admission zone-pair / transit-policy gate (R4-Q02-02)

- **Timestamp**: 2026-10-28
- **Action**: The #6458-V2 owner-RG gate was called at 7 non-test sites in
  `poll_descriptor/`, each followed by a hand-copied zone-pair /
  post-translation-destination chain. The #15916 ambiguous-stamp promotion
  reached only 4 of them: the NoRoute arm
  (`noroute_adjudication.rs:109`, caller passed the raw
  `ingress_zone_override` while `ambiguous_zone` was in scope), the zone
  traffic counters (`mod.rs:10497` at source revision) and the flow-cache
  seed stamp (`flow_cache_seed.rs:222`) never promoted, so a co-moved
  punt was misjudged fail-closed on NoRoute and misattributed in counters.
  NoRoute's NAT64 dest re-classify was a line-for-line copy of the
  MissingNeighbor one. Per-site fixes (#4024, #12905, #12906, #12865,
  #15916→#16053) repeatedly reached a subset of the copies.
- **Fix**: generalised `noroute_adjudication.rs` into
  `userspace-dp/src/afxdp/poll_descriptor/transit_policy.rs`:
  - `admission_zone_override(forwarding, ha_state, now_secs, raw,
    ambiguous, resolution) -> Option<u32>` — the ONE from-zone rule
    (gate + promotion). All 7 gate sites now call it: flow-backed miss,
    flowless ForwardCandidate, MissingNeighbor, NoRoute (via
    `transit_policy_adjudication`), zone counters, flow-cache seed, and
    the queued embedded-ICMP gate. NoRoute, counters and seed gain the
    promotion (counters/seed callers now thread `ambiguous_zone`;
    `stage_flow_cache_seed` gained that parameter, test callers pass
    `None`).
  - `promoted_zone_override(...)` — the ungated `raw.or_else(promote)`
    half for the embedded-ICMP / NAT64-ICMP match arms, which must not
    re-gate a proved punt. `promote_ambiguous_fabric_zone` is now called
    only from these two helpers; `gate_fabric_zone_override_on_owner_rg`
    is called only from `admission_zone_override` and from its wrapper
    `promote_ambiguous_fabric_zone` (`forwarding/fabric.rs:525-531`, plus
    its definition there).
  - `nat64_dest_only_v4` + `post_translation_policy_dst` — the shared
    NAT64 dest-only re-classify and post-NAT destination collapse; the
    MissingNeighbor copy in `mod.rs` and the NoRoute copy both deleted.
  - `transit_policy_adjudication(...)` (née `noroute_policy_adjudication`,
    return type `TransitPolicyAdjudication`) — NoRoute's adjudication on
    the shared helpers. It keeps its denial-only evaluator
    (`noroute_policy_denial_gated_at`): that verdict shape (zero-egress
    tiers + default) is NoRoute-specific and not interchangeable with
    the Permit-capable evaluators, so the other arms keep their own
    evaluators and share the gate / zone-pair / post-NAT helpers only.
    Verdicts preserved at every previously-promoted site.
  - `docs/fabric-cross-chassis-fwd.md` owner-RG paragraph now names
    `admission_zone_override` / `transit_policy.rs` instead of
    enumerating arms.
- **Fail-closed direction**: unchanged, gate verdicts preserved. The
  only behaviour change is the intended one at the three unpromoted
  copies: an ambiguous claim now promotes ONLY when the packet's own
  owner RG is forwarding-active locally (otherwise `None`, fabric zone
  governs) — the same proof every promoted site already required. No
  site loosens: raw stamps still gated, unpromoted claims still
  withheld, NoRoute still denial-only.
