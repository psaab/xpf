# #14331 — buildInterfaceSnapshotsFrom base-row default routing domain leaks VRF locals

## Defect

`buildInterfaceSnapshotsFrom` (`pkg/dataplane/userspace/interfaces.go`) emits a
base row (`IsUnit: false`) for every interface, resolving its
`RoutingInstance`/`RoutingDomain` from the bare interface key. For an untagged
unit `.0`, `snapshotLinuxName(unit.0) == snapshotLinuxName(base)`, so the base
row and the unit row share an ifindex and the same live kernel addresses from
`buildLinkSnapshot`. Routing-instance membership is authored per-unit
(`routing-instances vrf1 interface ge-0/0/1.0`), so the bare key is absent from
`ifaceRoutingInstance` and the base row carried `RoutingDomain: 0` while
republishing the VRF unit's addresses. Consequences:

- `buildLocalAddressEntriesWithExclusions` emitted `(Domain: 0, addr)` for
  every VRF local address → XDP/Rust treats VRF IPs as inet.0-local
  (`XDP_PASS` to kernel instead of zone adjudication).
- `localAddressRoutingDomain` saw domains {0, VRF} for one ifindex and
  returned `(0, false)`, so `syncIngressIfaceMapLocked` deleted the
  `userspace_ingress_domains` entry (fail-closed, but kills correct local
  classification for that ifindex).

## Fix

In the base-row construction, when the bare key has no routing-instance claim
and is not quarantined, and unit `.0` exists and collapses onto the base
netdev (`snapshotLinuxName(cfg, name, iface, u0) == linuxName`), inherit unit
`.0`'s `RoutingInstance` and `RoutingDomain` (resolved through the same
`routingDomainForInterfaceKey`, so a quarantined unit yields the quarantine
sentinel domain, never 0). An explicit bare-key membership keeps precedence;
a VLAN/tunnel unit `.0` on its own netdev does not collapse and leaves the
base row untouched. No changes to `localAddressRoutingDomain` or
`buildLocalAddressEntriesWithExclusions` — the fail-closed ambiguity guard
is preserved for genuinely contested ifindexes.

## Regression

`TestBuildSnapshotUntaggedVRFUnitDoesNotConflictWithBaseRowDomain`
(`pkg/dataplane/userspace/base_row_vrf_domain_14331_test.go`) builds the
snapshot through `buildSnapshot(cfg)` for
`routing-instances vrf1 interface ge-0/0/1.0` with stubbed live addresses and
asserts the base and unit rows agree on the vrf1 domain,
`localAddressRoutingDomain` returns `(StableRoutingInstanceTableID("vrf1"), true)`,
and no local entry is emitted in Domain 0.

- RED on pristine origin/master (base worktree): `base RoutingDomain = 0, want 748221 (vrf1)`.
- GREEN with the fix.
