# #13678 — preserve TCP handshake state on session updates

`SessionTable::update_session` advanced TCP's `established` bit on a reverse
SYN-ACK but left `handshake_pending` and `syn_ack_first` untouched. This could
grant the established idle timeout before handshake completion, or keep an
imported SYN-ACK-first session on its opening timeout after its reverse ACK.
The update path now mirrors lookup's pending and completion transitions,
including the asymmetric reverse non-SYN ACK gate, requiring an ACK-bearing
non-SYN/non-closing segment for completion, and the guard against re-pending
an already-established flow. It refreshes opening-flow pressure-shed membership
from the resulting state.

Regression tests cover SYN-first pending/completion, SYN-ACK-first synced
promotion, invalid completion flags, retransmitted SYN-ACK retention, and
established-flow re-pending. The in-place/reference update parity model mirrors
these transitions.
