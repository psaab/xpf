# Issue #13238 — preserve session sequence-gap detection

- **Timestamp**: 2026-10-15
  - **Action**: `EventStream.readLoop` now checks session-frame sequence continuity immediately after reading the header, before oversized-frame refusal and session payload decoding. A gap uses the existing unconditional session-sync recovery path, drops the stream without advancing the ACK watermark, and cannot be masked by the decode-resync cooldown.
  - **Regression**: `TestEventStreamUndecodableFrameAcrossGapIsGap_13238` and `TestEventStreamOversizedFrameAcrossGapIsGap_13238` both failed on pristine `origin/master` at `9d3869c0e`: the stream stayed connected after seq 10 (gap 2..9), rather than taking the session-gap recovery path. Both pass with the fix and assert one counted gap, unconditional resync, no cooldown suppression, and an unchanged contiguous ACK watermark.
