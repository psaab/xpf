# Issue #12873: Session-miss screen audit flood accounting

## Disposition

Fixed the session-miss `alarm-without-drop` branch to record per-zone flood
alarms for recognized flood reasons. The branch already emitted a log-only
screen alarm and permitted the packet, but unlike the ordinary screen-stage
audit arms it never updated the per-zone flood alarm tally. A SYN-ACK flood
that crossed the session-miss SYN-flood gate was therefore missing from the
zone's `syn_flood` alarm counter.

The fix calls `record_zone_flood_alarm` with the ingress zone ID and the
original screen reason. The recorder only accounts for the three recognized
flood reasons; non-flood audit alarms do not become flood events. Enforcing
(drop) behavior and its drop tally are unchanged.

## Regression evidence

`session_miss_syn_ack_flood_alarm_without_drop_tallies_zone_alarm_12873` drives
the real poll-descriptor session-miss path with three distinct SYN-ACK flows,
a threshold of two, and `alarm-without-drop` enabled. The third flow trips the
SYN-flood gate. Before the production fix, the test failed because the
per-zone alarm tally was empty despite the suppressed-drop alarm; it now asserts
exactly one `syn_flood` alarm for the ingress zone and no flood drops.

## Risk

Low. The added operation is the existing batched per-zone alarm recorder used
by the ordinary screen-stage audit paths. It uses the same flood slot map as
the drop path, adds no allocation or shared atomic operation, and ignores
non-flood reasons. No packet verdict or event format changes.
