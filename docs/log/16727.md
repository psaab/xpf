# #16727 — `/metrics` on a credential-gated leg made no login-class decision

- **Timestamp**: 2026-10-25
  - **Action**: On a credential-gated leg (non-loopback bind, or loopback
    with `metrics-require-auth`), `/metrics` was authenticated by
    api-auth but received no login-class decision, so a credential whose
    class lacks `view` (built-in `unauthorized`, or a custom class) —
    refused every `/api/v1` read — still received the Prometheus
    exposition naming zones, policies, NAT pools and interfaces.
    `readAuthz` now prices `GET /metrics` (and HEAD, which the mux
    aliases to the GET handler) at `PermView` via
    `authz.Authorize(cfg, p, config.PermView)` whenever the leg's
    effective metrics gate is on, and serves it otherwise unchanged.
    The effective gate is recovered per leg, not from a global flag:
    `listenerHandler` now records the #4162 bind classification on the
    leg's `authSlot` (`bindRequiresAuth`), and
    `Server.metricsGateForRequest` folds it with the #16072 opt-in
    (`authSlot.metricsGate`, pinned on retired legs) and the live
    snapshot's `MetricsRequireAuth` — the same predicate
    `dynamicAuthMiddleware` enforces for authentication, so the two
    cannot drift and a dual-stack box with one gated and one open leg
    is judged per leg. Only the coarse bit is charged: `/metrics`
    remains exempt from the operational command-regex gate
    (`restNoCommandExempt14146`), because it is not an operational
    command. The unauthenticated loopback default (gate off) stays
    open to any local UID — that leg carries no credential principal,
    and gating it is Y07-03's separate decision. Corrected the stale
    rationale comments in `authz.go` and
    `authz_command_regex_9952.go` (which claimed `/metrics` carries no
    configuration / never carries a principal) and the `pkg/api`
    README metrics and read-gate sections.
  - **File(s)**: `pkg/api/authz.go`, `pkg/api/server.go`,
    `pkg/api/authz_command_regex_9952.go`, `pkg/api/README.md`,
    `pkg/api/metrics_view_gate_16727_test.go` (new),
    `docs/log/16727.md`.
  - **Validation**: New regression cells
    `TestMetricsRequiresViewOnCredentialGatedLegs16727` (both gated
    leg shapes: unauthorized-class key gets 403, read-only key 200,
    no credential 401, `/health` 200, `/api/v1/config` controls, plus
    the ungated loopback control at 200 with and without a credential)
    and `TestMetricsViewGateBasicUser16727` (unauthorized Basic user
    403, read-only Basic user 200), driving the real `buildHTTPServer`
    chain with hashed keys. Targeted existing suites re-run:
    metrics auth gates (#4162/#16072), read gate (#6660), HEAD
    (#9134), command-regex exempt set (#14146).
  - **Residual**: The ungated loopback exposition remains open to any
    local UID by design (Y07-03 owns that decision; not filed as part
    of this issue). No secrets were ever exposed — object names and
    counters only — and recovery for already-scraped topology remains
    key rotation.
