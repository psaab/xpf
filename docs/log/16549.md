# #16549: `stop_for_link_cycle` retires NAT holders on the preserved allocators

- **Timestamp**: 2026-10-24
- **Problem**: `Coordinator::stop_for_link_cycle` took `self.forwarding`
  out with `std::mem::take` before calling `stop_inner(false)`, then
  restored it afterwards. `stop_inner` runs `retire_worker_holders`
  (via the one-shot `holders_retired` CAS in
  `coordinator/status.rs`), which walks
  `self.forwarding.iface_nat_allocators`, `source_nat_rules`, and
  `nat64`. At that instant `self.forwarding` was the default (empty)
  value, so the walk cleared nothing, the CAS was spent, and the joined
  workers' NAT holder bits survived on the preserved allocator
  instances that were then reinstalled. SNAT/NAT64 pool ports stayed
  occupied after a RETH link-cycle stop until a later correctly-retired
  stop of the same worker id; for ids absent from later plans (plan
  shrink) and reservations with no replayed shared entry the leak was
  durable. The function's doc comment asserted the opposite ("no
  leak"). The #15950 sibling `stop_preserving_forwarding` already did
  this correctly (clone, keep the original installed through
  `stop_inner`, reinstall the clone).
- **Fix**: Both preserving stops now share one helper,
  `Coordinator::stop_preserving_forwarding_inner`: clone the
  `ForwardingState` (its collections hold `Arc`s / shared stores, so
  this is cheap on this teardown-only path), keep the ORIGINAL
  installed while `stop_inner(false)` joins workers and retires their
  holders against its allocators, then reinstall the clone (same
  allocator `Arc`s, now with departed holders retired) and the
  preserved `validation`, and republish the runtime view.
  `stop_preserving_forwarding` is a thin wrapper;
  `stop_for_link_cycle` additionally records
  `ReconcileStage::Stopped`. The doc comment is rewritten to state the
  #16549 invariant (original must stay installed through retirement)
  instead of the previous false "no leak" claim. No other call sites,
  gates, or fail-open behaviour change; the forwarding-publish census
  (`forwarding_publish_population_is_pinned_7015`) drops
  `coordinator/mod.rs` from 3 to 2 `.forwarding = ` sites (the shared
  helper's single reinstall replaces the two wrappers' separate
  reinstalls; the teardown default is the other site), and that pin's
  expectation is updated accordingly with a #16549 note.
