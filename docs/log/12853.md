# #12853 — preserve hold-dropped feed and collision precedence in policy expansion

- **Issue**: https://github.com/psaab/xpf/issues/12853 (research D4-06)
- **Base**: `3cd60ec2b` (`origin/master` at worktree creation)
- **Why**: Userspace address-book snapshot expansion merged a feed overlay with same-named static address-book content unconditionally. A present-empty overlay from a declared `fail-mode drop` binding therefore restored a static prefix after the operator's hold-drop intent. Separately, the expansion helper ignored `AddressBook.CollidingNames` and selected whichever same-named entry won compilation.

## Change

`addressBookExpansionResolver` now receives declared address bindings, checks `CollidingNames` before resolving a name, and rejects colliding names/nested members. It continues to merge live feed prefixes with static content, but does not descend into same-named static content when the declared binding has a present-empty overlay and `FailMode == "drop"`. Omitted bindings and non-drop overlay rows preserve existing behavior. Added regressions exercise direct and nested hold-dropped bindings through address-book rows and policy lowering, live-feed/static union and absent-overlay static controls, and direct/nested collision resolution.

## Risk

A colliding address-book name now expands to an empty row in the address-book table, while policy representability independently rejects a policy reference via the existing unsupported-address sentinel. This prevents accidental static winner selection and preserves existing fail-closed policy rejection. Non-empty feeds retain the prior additive static+feed union behavior.
