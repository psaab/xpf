# #19182: RIP lost the #15158 cluster Null0 deny-tag map on a bare `redistribute static`

- **Timestamp**: 2026-11-17
  - **Action**: Root-caused and fixed.
    - **First-bad commit confirmed:** 415e7b6093 (#17688, union of
      independent RIP group exports). `renderRIPGroupPool17688` keeps the
      ordered chain only when `len(rip.Groups) == 0`, and its own comment
      says "With no groups, Redistribute keeps its existing ordered-chain
      semantics". But since #16866 every group-less render with an
      enrolled interface SYNTHESIZES one implicit group (the
      per-interface outbound gate) before calling it. So the length test
      never saw a group-less config, and every one went through the union
      pool.
    - **What the pool does differently:** `redistChainEntries15156`
      prefers a policy's per-source map over a bare token for the same
      source. For `redistribute [ static EXP ]` the bare `static` line,
      and with it the #15158 `xpf-cluster-null0-xpf-redist` guard,
      disappeared. Master renders only `redistribute static route-map
      EXP-static-xpf-redist-rip` (rendered on the runner). In
      non-cluster mode the bare line disappeared too.
    - **Leak check (the issue's concern):** none is found in the rendered
      output. The surviving policy map leads with `deny 5 / match tag
      2500`, and a bare static that survives into the pool gets the guard
      map, because the pool threads `clusterMode` onto its entries. The
      defect is that #17688 broke its own stated group-less contract,
      including the #15158 render shape the cells pin.
    - **Fix:** the caller decides `groupLess` (no OPERATOR group) BEFORE
      #16866's synthesis and passes it down through
      `renderRIPPerGroup16625` into `renderRIPGroupPool17688`. Group-less
      configs keep the ordered chain; operator groups keep #17688's union
      pool. I did not match on the synthesized group's name, because an
      operator could choose the same name.
    - **New cell:** `TestRIPOperatorGroupBareStaticIsGuardedInCluster19182`
      covers an operator group's bare `static` in the pool. In cluster mode
      it must attach the guard map; in non-cluster mode it stays bare.
    - **Docs:** `pkg/frr/README.md`, in the #15158 paragraph: the contract
      holds on both RIP redistribution paths, and the group-less decision
      is made before the #16866 synthesis.
