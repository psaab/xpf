## Issue framing

A packed Junos statement such as `outer inner leaf value;` may be accepted while the compiler reads only the braced `Children` shape and silently drops the packed tail. The #2419 one-level census did not cover this two-level spelling. The #18763 census expansion measured 1,326 two-level cells: 171 `COMMITS-DIFFERENT`, 26 already refused, and 90 unclassified (per the checked-in manifest at this head). #18762 and #18787 are concrete examples of defects found inside that inventory.

The issue asks for a systemic backstop, not bulk admission: report-only first, then a separately reviewed enforcement change. On a strict commit, only a tail proven both meaningful when braced and wholly ignored as packed should eventually refuse. On tolerant load/peer-sync, diagnostics must never prevent boot (#1960). Tails that are consumed in part must warn only. The current first phase is report-only everywhere.

2. Run compact normalization (`:498-509`) and the pre-expansion AST gates (`:566-810`).

5. `compileExpanded` starts `runPreWalkGates` at `:1005-1017`. This phase mutates its tree through `expandInterfaceRanges` before section compilation. The output is then completed with compile warnings and returned (`:891-967`).

**Snapshot timing is settled by source:** `compileExpanded`/`runPreWalkGates` mutates the AST. Save a source snapshot before that call, not after O has compiled. The snapshot is taken at one named hook — `packedTailGateSnapshotPoint18771` — immediately after the `lenientDuplicatePolicyNames` fold block closes (`compiler.go:564`) and before the tunnel-endpoint collision gate (`:566-572`), i.e. after every mutating pass in the `:508`–`:564` window has run once in production order (cell 3 pins this). **Twin entry:** O remains the real result of the caller's `compileTree` invocation. Each B_i/R_i twin re-enters the same private `compileTree` orchestrator with an internal `skipPackedTailGate18771` context, so it reruns the pre-expansion validation gates, group expansion, `findNestedMultiValueContentError`, and `compileExpanded`'s `runPreWalkGates`. The skip context lives in compiler-internal state, not on the caller-visible input tree: it is set on the twin's own `compileTree` invocation, so constructing a twin never mutates O's caller tree or the stored snapshot. ## All initial compile policy (carried by value)

`compileTree` receives its policy as a value argument (`func compileTree(tree *ConfigTree, opts compileOpts, nodeID *int)`, `compiler.go:474`), so a twin re-enters with a by-value copy of the `compileOpts` O's entry point constructed, captured at `compileTree` entry before any derived stamping. That copy carries exactly the caller-set initial policy inputs:

- the compile mode as a whole — the `tolerant` bit (`compiler_opts.go:56`) plus every per-gate severity flag the entry point set (a strict commit view's opts vs `lenientCompileOpts()`);
- the node selector, carried as `compileTree`'s `nodeID *int` argument (the #16167 pointer-carried node-aware condition; the `opts.nodeID` field is only the stamp `compileTree` writes from it at `compiler.go:878`);
- `currentClusterPrimary16025 *string` (`compiler_opts.go:3931`) — the persisted active primary, supplied only by configstore's strict candidate-commit pipeline;
- `currentClusterAccepted16858 *clusterAcceptedKeys16858` (`compiler_opts.go:3940`) — the active config's accepted key set, same sole supplier;
- `judgePlaceholders18744 bool` (`compiler_opts.go:3949`) — set only by the strict candidate pipeline through the placeholder-judging entry points.

The two pointer fields are read-only equality/length inputs (their field contracts forbid logging or rendering them) and `compileTree` never writes them, so the value copy may safely share them. Everything else on `compileOpts` that `compileTree` produces is derived and is NEVER carried or injected — the twin's copy clears it before re-entry so the shared path recomputes it from the snapshot:

- `physicalInterfaces` — computed before group expansion at `compiler.go:493`;
- `zoneQuarantineNames` — produced by the zone-ID collision gate at `compiler.go:609-617`;
- the stamped `opts.nodeID` (`compiler.go:878`);
- `igpIdentityExcused16810` — set only by the `:599-601` probe, which runs inside `compileTree`.

After each twin compiles, the recomputed values are asserted equal to O's; a disagreement makes that site unadjudicated, never DROP. Warnings and pre-walk results are likewise recomputed by the shared path. Twin-side validators still run and can fail; the asserted values are the downstream context the original compile actually used.

The input snapshot is made after API-auth hashing (`:494`), production compact normalization (`:507`), and all three post-normalization mutating passes (`:509`, `:530`, `:545`). Because the snapshot sits after `mergeDuplicateNamedInstances` (`:545`), twin re-entry re-runs compact normalization and the three window passes on already-processed input; cell 5 proves those re-runs idempotent, and a non-idempotent re-run makes the site INDETERMINATE, never DROP. Candidate tails declined by scope remain packed in it; already-admitted tails are already in their production-normalized form. Hashing is idempotent for stored API-auth verifiers, so the twins retain O's exact bcrypt verifier rather than generating different salts. No source or O tree is shared with a mutating twin.

## Site-local adjudication

Do not widen a pair predicate over the whole config and infer a verdict for every occurrence. For each effective source site `i`, construct two independent twins from the same pre-`compileExpanded` source snapshot:

| View | Meaning |
|---|---|
| **O** | The caller's actual typed `Config` plus its diagnostics from the real `compileTree` invocation. |
| **B_i** | A full-config twin in which exactly source site `i` is rewritten to its fully braced shape. No other site with the same pair is changed. Compile it through the internal shared `compileTree` twin entry. |
| **R_i** | A full-config twin in which only site `i`'s residual packed tail is removed. Retain the outer node's bare identity prefix as an empty/bare-identity stub and preserve its pre-existing explicit `Children`; do not delete the containing interface, zone, policy, or other object. Compile it through the same full path. |

The site rewriter must use the normalizer's schema-aware split/attachment rules for the one structural site, including deep two-level nesting and the existing braced children. B_i/R_i are built from the pre-expansion snapshot and each rewrites exactly one source occurrence — group fan-out (one source occurrence inherited into several effective occurrences) is `SKIPPED-PROVENANCE`, never an independently adjudicated site, because group expansion clones one body into every application (`ast_groups.go:631-637,688`) while clones preserve Line/Column and `InheritedFrom`/`fromGroups` provenance (`ast.go:756-766`), so a rewrite at that occurrence would hit every inherited instance. If the snapshot-to-effective map is one-to-many, every mapped effective occurrence is `SKIPPED-PROVENANCE` (warning only, never refusal). It must not grant the pair to every matching node. A dedicated cell compares B_i against a separately parsed, genuinely braced source compiled through `CompileConfig` / `CompileConfigForNode` / the matching lenient entry; disagreement blocks implementation.

Compare typed config and diagnostics separately:

- `typedEq(a,b)` is equality of the canonical typed `Config`, with value-sensitive, non-logging treatment of `Secret` values and only measured nondeterministic fields normalized.
- `diagEq(a,b)` is equality of the relevant compile diagnostics; preserve multiplicity and order unless a specific ordering-only nondeterminism is measured and normalized. Do not discard warnings: a tail consumed only by a validator is not empty.
- O's comparison diagnostics are the **pre-gate** baseline. Gate findings are typed `Diagnostic` entries with `Gate: "packedTailGate18771"` (the representation paragraph in "Phase-one behavior" states the exact append shape and the `cfg.Warnings` prose pairing). `diagEq` excludes, symmetrically across O/B_i/R_i, exactly the entries whose `Gate` **field** equals `packedTailGate18771` — a struct-field comparison, never a prose substring match — plus, on the prose surface, exactly the `Warnings` strings equal to an excluded entry's `Prose` (exact string equality). The emitted warning is appended after adjudication and cannot alter the verdict that produced it; an untagged diagnostic that merely mentions the gate does not match.

Per-site verdict:

1. **DROP** only when `!typedEq(O,B_i) && typedEq(O,R_i) && diagEq(O,R_i)`. The braced statement changes typed behavior, while deleting this exact packed tail changes neither typed behavior nor diagnostics.
2. **PARTIAL** when the braced and packed typed configs differ but O/R_i typed or diagnostic results differ, or when typed O/B_i are equal but their diagnostics differ. PARTIAL is always warning-only; diagnostic-only effects can never be DROP.
3. **CLEAN** when O/B_i typed config and diagnostics are equal. A twin error, unstable comparison, or unresolved provenance is **INDETERMINATE/SKIPPED**, also warning-only and never a refusal.

The site-local controls are mandatory: one config combines the shipped HA packed-tail reader (`redundancy-group 0 node 0 priority 200`) with a separately measured DROP site, proving the HA tail cannot mask the DROP in a global aggregate; a second config has two occurrences of the same `(container, head)` pair and requires two independently attributed results. The fixed manifest must additionally contain a same-pair mixed control with distinct measured DROP, PARTIAL, and typed-equivalent instances; if the current census has no such pair, hand-build and independently measure one before code, or stop rather than substitute an aggregate test.

`O != R` is not enough by itself if warnings are omitted, and typed equivalence is not diagnostic equivalence. `typedEq(O,B_i)` always rules out DROP; a diagnostics-only B difference is PARTIAL/warning-only. If a twin refuses, panics, or cannot be deterministically compared, it cannot prove DROP and must not enforce.
