## Issue framing

A packed Junos statement such as `outer inner leaf value;` may be accepted while the compiler reads only the braced `Children` shape and silently drops the packed tail. The #2419 one-level census did not cover this two-level spelling. The #18763 census expansion measured 1,326 two-level cells: 171 `COMMITS-DIFFERENT`, 26 already refused, and 97 unclassified. #18762 and #18787 are concrete examples of defects found inside that inventory.

The issue asks for a systemic backstop, not bulk admission: report-only first, then a separately reviewed enforcement change. On a strict commit, only a tail proven both meaningful when braced and wholly ignored as packed should eventually refuse. On tolerant load/peer-sync, diagnostics must never prevent boot (#1960). Tails that are consumed in part must warn only. The current first phase is report-only everywhere.

## Round-one plan-review disposition

All three plan seats found the original proposal insufficient and converged on these required changes:

- **M1 — twin fidelity:** use the shared `compileTree` path with a pre-`compileExpanded` source snapshot; carry the original derived physical-interface and zone-quarantine context and the same node selector; re-run the compile gates.
- **M2 — site-local causality:** replace aggregate O/B/R adjudication with independent `B_i` and `R_i` full-compilation twins for each effective source site. A `(container, head)` pair is not a site verdict.
- **M3 — peer warning visibility:** `validatePeerStrictPipelineJudged` discards `peerCompiled.Warnings`. Phase one promises peer-only warnings through node-labelled slog only, not the commit response, and accounts for the peer view's extra twin cost.
- **Additional corrections:** pin a fixed covered/uncovered census manifest independent of the runtime recorder; split typed equivalence from diagnostic equivalence; state that R keeps a bare-identity stub; make the 32-site cap warning-only; correct the order of scope and later fold declines.

## Existing path and twin hook

`pkg/config/compiler.go:474` is the shared `compileTree` orchestrator behind the public `CompileConfig`, `CompileConfigForNode`, lenient, and placeholder-judging entry points. Its relevant order is:

1. Clone/prune the input and hash API-auth secrets (`:475-495`).
2. Run compact normalization (`:498-509`) and the pre-expansion AST gates (`:566-810`).
3. Expand groups (`:812-853`); generic compilation uses node0 fallback, while node-aware compilation selects its node-specific view.
4. Run `findNestedMultiValueContentError` (`:883-885`) and then `compileExpanded` (`:887`).
5. `compileExpanded` starts `runPreWalkGates` at `:1005-1017`. This phase mutates its tree through `expandInterfaceRanges` before section compilation. The output is then completed with compile warnings and returned (`:891-967`).

**Snapshot timing is settled by source:** `compileExpanded`/`runPreWalkGates` mutates the AST. Save a source snapshot before that call, not after O has compiled. The snapshot retains the packed source and group definitions. The effective-site observer runs after the chosen group expansion, before `findNestedMultiValueContentError` and `compileExpanded`; it maps only applied effective sites back to their exact source locators. If a merge/provenance path cannot be mapped to one source site unambiguously, label it `SKIPPED-PROVENANCE`, warn only, and never refuse.

**Twin entry:** O remains the real result of the caller's `compileTree` invocation. Each B_i/R_i twin re-enters the same private `compileTree` orchestrator with an internal `skipPackedTailGate18771` context, so it reruns the pre-expansion validation gates, group expansion, `findNestedMultiValueContentError`, and `compileExpanded`'s `runPreWalkGates`. It is not a `compileExpanded`-only shortcut and does not recompile an already-expanded tree. The public API remains unchanged; regression tests also parse a separate genuinely braced source and compile it through the corresponding public entry point, requiring its result to match B_i.

The twin receives the same compile mode and node selector as O. The explicit carried-derived-context whitelist is:

- `physicalInterfaces`, computed before group expansion at `:493`;
- `zoneQuarantineNames`, produced by the zone-ID validation at `:609-617`;
- the original `nodeID` selector (`opts.nodeID` is set from it at `:878`).

All initial compile policy/current-cluster fields in `compileOpts` are copied by value. Other derived state, including `igpIdentityExcused16810`, warnings, and pre-walk results, is recomputed by the shared path. Twin-side validators still run and can fail; the two whitelisted values are the downstream context the original compile actually used. If recomputing those values from a twin disagrees with O, that site is unadjudicated, never DROP.

The input snapshot is made after API-auth hashing and production compact normalization but before the pre-expansion validators and group expansion. Candidate tails declined by scope remain packed in it; already-admitted tails are already in their production-normalized form. Hashing is idempotent for stored API-auth verifiers, so the twins retain O's exact bcrypt verifier rather than generating different salts. No source or O tree is shared with a mutating twin.

## Candidate discovery and provenance

Do not add an independent schema-site enumerator. Instrument the existing normalizer walk to capture a source locator when `compactNormalizeInScope(container, head)` returns false for a schema-recognized residual tail. After the selected group expansion, instrument the same walk on the effective tree to determine which sites actually reach the compiler. A site handle includes the exact structural occurrence, source line/column where present, group-origin tags (`InheritedFrom` / `fromGroups`) and group-local path, key identity, and tail span. It must not collapse equal `(container, head)` pairs or identical rendered paths.

The order in `normalizeCompactNodes` matters: the scope predicate is consulted at the body check (`compact_normalize_8662.go:160`); `declineStrandingFold8880` (`:187`) and the `declineLeafBody14343` check (`:237-248`) can decline the fold **after** scope returned true. Thus the covered population is only sites for which the predicate returned false and the matching tail remains. A predicate-true site later declined by stranding/leaf safety, and a residual tail for which no schema child/predicate call occurs, are uncovered rows; they are not candidates and the gate does not claim them. The fixed manifest below records both classes.

## Site-local adjudication

Do not widen a pair predicate over the whole config and infer a verdict for every occurrence. For each effective source site `i`, construct two independent twins from the same pre-`compileExpanded` source snapshot:

| View | Meaning |
|---|---|
| **O** | The caller's actual typed `Config` plus its diagnostics from the real `compileTree` invocation. |
| **B_i** | A full-config twin in which exactly source site `i` is rewritten to its fully braced shape. No other site with the same pair is changed. Compile it through the internal shared `compileTree` twin entry. |
| **R_i** | A full-config twin in which only site `i`'s residual packed tail is removed. Retain the outer node's bare identity prefix as an empty/bare-identity stub and preserve its pre-existing explicit `Children`; do not delete the containing interface, zone, policy, or other object. Compile it through the same full path. |

The site rewriter must use the normalizer's schema-aware split/attachment rules for the one structural site, including deep two-level nesting and the existing braced children. It must not grant the pair to every matching node. A dedicated cell compares B_i against a separately parsed, genuinely braced source compiled through `CompileConfig` / `CompileConfigForNode` / the matching lenient entry; disagreement blocks implementation.

Compare typed config and diagnostics separately:

- `typedEq(a,b)` is equality of the canonical typed `Config`, with value-sensitive, non-logging treatment of `Secret` values and only measured nondeterministic fields normalized.
- `diagEq(a,b)` is equality of the relevant compile diagnostics; preserve multiplicity and order unless a specific ordering-only nondeterminism is measured and normalized. Do not discard warnings: a tail consumed only by a validator is not empty.

Per-site verdict:

1. **DROP** only when `!typedEq(O,B_i) && typedEq(O,R_i) && diagEq(O,R_i)`. The braced statement changes typed behavior, while deleting this exact packed tail changes neither typed behavior nor diagnostics.
2. **PARTIAL** when the braced and packed typed configs differ but O/R_i typed or diagnostic results differ, or when typed O/B_i are equal but their diagnostics differ. PARTIAL is always warning-only; diagnostic-only effects can never be DROP.
3. **CLEAN** when O/B_i typed config and diagnostics are equal. A twin error, unstable comparison, or unresolved provenance is **INDETERMINATE/SKIPPED**, also warning-only and never a refusal.

The site-local controls are mandatory: one config combines the shipped HA packed-tail reader (`redundancy-group 0 node 0 priority 200`) with a separately measured DROP site, proving the HA tail cannot mask the DROP in a global aggregate; a second config has two occurrences of the same `(container, head)` pair and requires two independently attributed results. The fixed manifest must additionally contain a same-pair mixed control with distinct measured DROP, PARTIAL, and typed-equivalent instances; if the current census has no such pair, hand-build and independently measure one before code, or stop rather than substitute an aggregate test.

`O != R` is not enough by itself if warnings are omitted, and typed equivalence is not diagnostic equivalence. `typedEq(O,B_i)` always rules out DROP; a diagnostics-only B difference is PARTIAL/warning-only. If a twin refuses, panics, or cannot be deterministically compared, it cannot prove DROP and must not enforce.

## Phase-one behavior, peer visibility, and cost

- `packedTailGateEnforce18771 = false` remains a compile-time constant. Strict and tolerant phases report only; the separate enforcement PR may make strict DROP refuse after a full report-only release and green controls. Tolerant load/peer-sync never refuses.
- A local compile appends a node-labelled warning to `cfg.Warnings` and emits one matching `slog.Warn` per site. `validatePeerStrictPipelineJudged` (`pkg/configstore/peer_strict_pipeline_9619.go:76-94`) compiles the peer and uses it for cross-checks but discards `peerCompiled.Warnings`. Therefore the phase-one contract is explicit: peer-only gate findings are visible through node-labelled `slog.Warn` only; they are **not promised in the commit response**. Do not claim otherwise unless a separate configstore change routes the peer diagnostics.
- Count concrete effective source sites, not distinct pairs. At most 32 sites per `compileTree` view receive B_i/R_i adjudication. If the view has more than 32, skip **all** per-site adjudication for that view, emit one aggregate `SKIPPED-CAP` warning with the count, and never refuse any site in that view. `SKIPPED-CAP` and `SKIPPED-PROVENANCE` are explicit verdict labels, not silent omissions.
- The cap is deliberately warning-only. With 32 sites, one view requires up to 64 additional full twin compilations (two per site), plus O. A strict HA commit whose peer pipeline compiles a second node view can require up to 128 additional twin compilations across the local and peer views, plus the two ordinary O compiles. Report-only slog output can therefore be duplicated by node; the node label disambiguates it. Measure this bounded commit-time cost before any enforcement PR; no packet-path or live-cluster throughput gate is in scope.
- Never log raw packed text or secret values. Use a value-free path, or the existing secret scrub helpers if the message contains source tokens. Keep warning ordering deterministic and emit each site once per node-view.
- Do not bulk-admit pairs. Per-site admission remains the measured #8690 path. An enforcement follow-up needs an upgrade note and a `check-config` diagnostic path before it flips the constant.

6. **Fixed census manifest:** add a checked-in `pkg/config/testdata/packed_tail_gate_18771.txt`, with explicit covered eligible sites and verdict expectations plus explicit out-of-scope rows for already-admitted sites, strict-refused sites, unclassified sites, schema-unreached tails, and scope-true stranding/leaf declines. 7. **Typed/diagnostic classification:** typed-equivalent O/B_i is never DROP; warning-only differences become PARTIAL; O/R_i diagnostic-only differences also prevent DROP. A candidate whose only compiler effect is a warning/validation diagnostic is captured by this cell.
8. **Phase posture and peer delivery:** strict report-only DROP compiles locally and returns its local warning; tolerant compile never errors. The peer strict pipeline cell captures node-labelled slog output and confirms peer-only warnings are not claimed to reach the commit response. Future enforce mutant: strict DROP refuses but the peer/tolerant paths remain warning-only.
9. **HA read-tail and secret controls:** the shipped HA `node … priority` spelling is not DROP; deleting that tail changes O. No warning/log output contains a distinctive secret in raw or quoted form.
10. **Bounds and mutants:** 32 sites are adjudicated; 33 causes exactly one `SKIPPED-CAP` warning and no refusal; no-candidate config runs no B_i/R_i; comparator-always-equal and comparator-never-equal are killed; empty recorder and pair-wide attribution mutants are killed; a typed-equality/diagnostic-equality conflation is killed.

Implementation tests are hermetic `pkg/config` tests plus a hermetic `pkg/configstore` peer-warning test; they must not invoke netlink, `ip`, `nft`, host daemons, or cluster harnesses. Run the focused package suites and the relevant Go build. No live cluster/iperf gate is justified for this config-only behavior.
