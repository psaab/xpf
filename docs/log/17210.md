# #17210 — DNAT `Translate` → `NatDecision` mapping single-sourced on `DnatValue`

- **Base**: `f1dd713683ac5945531682bd668660af2e968caf` (origin/master)
- **Branch**: `fix/17210-campaign`

## Why

The #4074 L4-port gate (`protocol_has_l4_ports && new_dst_port != 0 &&
new_dst_port != dst_port`) was hand-copied 5× and the
`NatDecision { rewrite_dst: Some(value.new_dst_ip), .. }` literal 3× in
`userspace-dp/src/nat/destination.rs`, grown from 1 copy in five days as
each new DNAT lookup variant (#15534, #15934, #16045) copied the block.
A future change to the #4074 rule (new port-carrying protocol, identity
suppression change) had to reach all five sites; missing a `reproduces`
closure would make revalidation disagree with lookup (revoking healthy
DNAT sessions or keeping stale ones), and missing a lookup site would
recreate the #4074 ICMP-identifier corruption on that path alone.

STEP-0 re-check on current master `f1dd713683`: defect live — 5 gate
copies (`:1279,1332,1465,1598,1673` pre-change) and 3 literals
(`:1287,1608,1683`), no `DnatValue` helper.

## What

- Added `impl DnatValue` in `nat/destination.rs`:
  - `#[inline] pub(crate) fn rewritten_dst_port(&self, protocol: u8, dst_port: u16) -> Option<u16>` — owns the #4074 gate; the full #4074 comment moved onto it. Takes the original `u8` so `has_l4_ports` is evaluated before any widening to the u16 key space.
  - `#[inline] pub(crate) fn decision(&self, protocol: u8, dst_port: u16) -> NatDecision` — the single `NatDecision` literal.
- Replaced all call sites:
  - `lookup_with_counter_scoped`: keeps `protocol_u8` before widening, returns `value.decision(protocol_u8, dst_port)`.
  - `lookup_result_with_counter_scoped` and `lookup_result_ambiguous_provenance_scoped`: `DnatLookup::Matched(value.decision(protocol, dst_port))`.
  - `tier_walk_reproduces_ignoring_icmp_selector_scoped` closure and `match_prefix_lpm_tier_walk`: compare `entry.value.rewritten_dst_port(protocol, dst_port) == want_dst_port`. The prefix leg's parameter changed from `protocol_has_l4_ports: bool` to the original `protocol: u8` (key parameter renamed `protocol_key: u16`), so the gate re-derives from the real protocol inside the helper.
- Optional `map_outcome` fold from the issue was not needed: after the
  `decision()` replacement the two `lookup_result_*` translate arms are
  each a one-liner; a shared tail would add indirection without removing
  a remaining copy.
- New test `dnat_17210_decision_and_tier_walk_reproduces_agree_tcp_and_icmp`
  in `nat/tests_destination.rs`: asserts `decision(IPPROTO_ICMP, ..)`
  with a pooled port gives `rewrite_dst_port == None` (and TCP gives
  `Some(8080)`, identity port gives `None`), and that
  `tier_walk_reproduces_ignoring_icmp_selector_scoped` agrees with
  `lookup_with_counter_scoped` for TCP and ICMP.

Acceptance greps on the final tree:
`grep -c 'new_dst_port != 0' userspace-dp/src/nat/destination.rs` → 1
(inside `rewritten_dst_port`);
`grep -c 'rewrite_dst: Some(value.new_dst_ip)'` → 0 (the remaining
`rewrite_dst: Some(self.new_dst_ip)` is inside `DnatValue::decision`).

## Risk

- Pure refactor: every replaced expression is token-identical to the
  helper body; helpers are `#[inline]`, allocation-free, on the same
  per-packet paths. No behaviour change expected; the #4074 test and
  the new agreement test pin both directions.
- The one subtlety is the narrowing invariant: `lookup_with_counter_scoped`
  widens `protocol: u8` to the u16 key space, so it now captures
  `protocol_u8` before widening and passes that to `decision()` —
  passing the widened value would not compile (`decision` takes `u8`),
  so the invariant is type-enforced.
