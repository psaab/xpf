# #14329 — Reserved-sentinel DroppedEnforcementChild quarantine

## Defect
- `quarantineCollidingZones` (zones_quarantine.go) added every DroppedEnforcementChild zone to policyQuarantined with no reserved-name filter, so a poisoned `security-zone junos-global` wiped all `security policies global` rules via scrub Case 1a (From/To==junos-global), poisoned `any` wiped wildcard zone-pair rules, poisoned `junos-host` wiped host rules — bypassing dedicated poison paths (#9570, #12249).
- `walkPolicyRuleSlots` (policies.go) only deleted reserved names from quarantined when not poisoned, so poisoned reserved definitions skipped whole zone-pair sets.
- `quarantinedZoneNamesForConfig` (partial republish) had same flaw.
- `walkPolicyRuleSlots` GlobalPolicies loop had no quarantine filtering, while scrub drops scoped globals whose configured Match side is fully quarantined — desync in PolicyIDsByStableKey/PoliciesByStableKey/RuntimePolicyIDs and cap accounting.

## Fix
- `pkg/config`: exported `IsReservedZoneName` (thin wrapper over existing `reservedZoneNames` SSOT in compiler_validate_strict_zones.go).
- `policies.go:walkPolicyRuleSlots`: unconditionally delete JunosGlobalZoneName/ReservedWildcardZoneName/"junos-host" from quarantined; skip global policies whose Match From/To Zones side is non-wildcard (non-empty, not containing "any") and fully contained in post-reserved-filter quarantined set.
- `zones_quarantine.go:quarantineCollidingZones` + `quarantinedZoneNamesForConfig`: skip `config.IsReservedZoneName(name)` when adding poisoned zones to policy quarantine set.
- Direct hand-built `scrubPoliciesForQuarantinedZones` callers unchanged: they pass explicit sets; production callers all route through the fixed helpers.
