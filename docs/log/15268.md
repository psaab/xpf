# #15268 (B13-02, B13-03): generated-reply output-filter side effects

- **Timestamp**: 2026-10-19
  - **Action**: Deferred the counted/metered output-filter walk for locally-generated replies until after the zone token (reject / Time-Exceeded) or equivalent admission (SYN-cookie / PTB), and emitted the matched output `then log` through the transit FILTER_LOG emitter for admitted and output-filter-dropped replies. Added RED/GREEN regressions plus controls; no behaviour change outside the cited mechanisms.
  - **File(s)**: `userspace-dp/src/filter/mod.rs` (`TxSelectionFilterResult` handle collection), `userspace-dp/src/filter/engine/tx_selection.rs` (collect counters/policers, skip meter when unmetered), `userspace-dp/src/afxdp/tx/cos_classify.rs` (`CoSTxSelection` deferred handles, `classify_generated_reply_deferred`, `GeneratedReplyVerdict::settle_deferred_side_effects`), `userspace-dp/src/afxdp/poll_descriptor/filter.rs` (`emit_generated_reply_filter_log`), `userspace-dp/src/afxdp/poll_descriptor/reject_reply.rs`, `cookie_reply.rs`, `userspace-dp/src/afxdp/icmp.rs`, `userspace-dp/src/afxdp/tx/dispatch/mod.rs`, plus event-stream threading at every generator call site and `docs/log/15268.md` (this file)

## Mechanism (origin/master `db0adfcc25`)

- **B13-02**: `classify_generated_reply` ran `evaluate_filter_ref_tx_selection_runtime_counted` (which records `then count` and meters three-color policers inline) before `allow_generated_reject` (`reject_reply.rs`) and before `allow_generated_error_zoned` (`icmp.rs`). A reply the limiter then discarded was still counted, and its bytes were metered — a static red mark could drop real transit on the same policer term.
- **B13-03**: `GeneratedReplyVerdict.filter_log` was populated by the classifier but discarded by all four generator callers (reject, cookie, TE, PTB); the reject helpers took no event-stream handle at all, so a generated reply's matched output `then log` never produced a FILTER_LOG.

## Change

- The TX-selection walk now always collects the matched `then count` handles and three-color policer runtimes into its result; when the walk is unmetered (`now_ns` absent) the policer is not metered. `resolve_cos_tx_selection_internal` gained a `defer_side_effects` flag used only by the new `classify_generated_reply_deferred`: the output walk becomes counter-suppressed and unmetered, and the collected handles ride on `CoSTxSelection` / `GeneratedReplyVerdict`.
- Each generator classifies deferred, takes its zone token as before (reject already ordered classify-before-token per #5569; TE per #7174), then calls `settle_deferred_side_effects(now_ns)`: it records each collected counter once with the reply's byte count and re-meters the policers. A red meter suppresses the reply at that point (token stays spent); a green/yellow meter's DSCP rewrite outranks the provisional term rewrite. SYN-cookie and PTB have no zone token, so admission is the settle itself (PTB's PacketTooBig token is taken earlier in `compute_forwarded_egress_ptb_with_dynamic`).
- After admission (or on an output-filter drop), the generator emits `verdict.filter_log` via the new `emit_generated_reply_filter_log`, which builds the event flow from the reply's own parsed egress tuple and stamps `FilterLogSource::Output` — the same emitter transit uses. Rate-limited replies emit nothing. The event-stream handle is threaded through every generator entry point and call site (poll loop, flow-cache hit, PBR, forward-request, host-inbound, neighbor retry, PTB dispatch).

NOT changed: transit (metered) classification charges inline exactly as before; the cached flow-cache path is untouched; token ordering, budget gates, suppression gates, and all drop counters keep their existing attribution. No new knob.

## Validation

- New `cos_classify_tests::generated_reply_deferred_classify_defers_count_and_policer_15268`: deferred classify records 0 count and 0 policer packets; settlement records the count once with the reply bytes and meters RED. Control `generated_reply_metered_classify_still_charges_inline_15268_control` pins the metered entry point still charging inline.
- New `reject_reply_tests::rate_limited_generated_reply_leaves_no_counter_or_log_15268`: with the zone bucket drained, the reply is rate-limited, the output count stays 0, and no FILTER_LOG is emitted. New `admitted_generated_reply_counts_and_logs_once_15268` (output-filter-drop arm): exactly one FILTER_LOG keyed on the reply tuple (src = egress primary, dst = client), no count for the never-sent reply.
- Existing #5569 cells (`egress_filtered_reject_does_not_drain_zone_token_5569` and siblings) and the #7174 TE token cells stay as controls for token ordering.

## Risk

- A reply whose policer meters red at settlement is now dropped after spending its zone token (previously it was dropped at classify before the token). This is the deliberate price of not metering never-sent replies; the drop is counted on the existing output-filter drop counters.
- Generated-reply FILTER_LOG events are new operator-visible output: a `then log` output term matching generated traffic now produces one RT_FLOW per admitted/dropped reply, keyed on the reply tuple with both zone fields set to the egress zone.
