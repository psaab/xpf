# #14356 — Post-promotion early returns bypass host-auth closeout

## Defect
After `Store.Commit` promotes cfg, `applyConfigLocked` could return on
non-cancellation errors without running the host-authorization closeout:
`maybeExitBootstrapOnFirstConfig` (daemon_apply.go), `maybeReapplyConfigArrivalNaming`,
and `applyDataplaneAndHACore` terminal errors (policy-rename ancestry refusal
and `compileErrorMustAbortApply` required protocol-gate errors). The old
`closeoutHostAuthOnCancel` only ran the closeout for
`context.Canceled`/`DeadlineExceeded`. A committed tightening of lo0 /
host-inbound / junos-host / SSH-login credentials therefore stayed
unenforced (old permissive kernel/OS state) until a later successful apply,
and a preactivation fence (`xpf_hostinbound_preactivation`) installed by
`applyHostInboundPreNetworkdAddressFence` earlier in the same apply could
strand with no real table behind it.

## Fix
- `pkg/daemon/daemon_apply_hostauth.go`: new
  `closeoutHostAuthOnPostPromotionError` runs the bounded closeout on EVERY
  post-promotion error (cancel and non-cancel alike): clears
  `hostInboundDataplaneFresh` first (fail-closed accept-less render, #9637-D1),
  runs `applyHostAuthorizationCloseout`, records
  `noteHostInboundApplyFailed` if the preactivation fence is still standing,
  and joins any closeout failure into the returned error.
- `pkg/daemon/daemon_apply.go`: bootstrap-exit and config-arrival naming
  returns, plus the `applyDataplaneAndHACore` terminal return, now funnel
  through the new helper. `requireEarlyInputProtectionPreApply` and the
  fence's own install-failure return stay bare (no closeout render has run
  yet there; the fence already records staleness itself).
- Docs: `pkg/daemon/README.md`, `daemon.go` field comment updated to the
  new helper name/semantics.

## Deliberate scope
- No new retry owner: the 30s host-inbound gap owner is gated on double-nft
  gap debt, not on `LastApplyFailed`; the preactivation fence is retired by
  the closeout's real install on success, and staleness is recorded when it
  is not. A fresh debt latch would re-drive full applies on every abort.
- Ordinary (non-abort) dataplane errors still run the full tail via the
  deferred `applyErr` path (#5679) — unchanged, no double-run: the closeout
  only fires on terminal `err` returns.
