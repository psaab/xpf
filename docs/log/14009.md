# 14009 — preserve routing-domain reserve for completed fragment anchors

The #13937 quota fix correctly excluded completed entries from sender quotas,
but also allowed completed anchors to permanently occupy every shard slot.
One tenant could fill all 64 slots with completed anchors, denying other
tenants new fragment keys until expiry and violating #10658's domain reserve.

Completed entries remain excluded from the sender's incomplete-entry quota to
avoid #13937's conformant-rate failure, but count toward the routing-domain
reserve. When a domain already holds 32 entries, a new key can replace its
oldest completed anchor; if no completed anchor is available, admission fails
closed. This keeps completed entries from bypassing #10658's per-domain cap.
Incomplete anchors are never reclaimed. Replacing a completed anchor ends
same-ident replay protection for that evicted key; retained completed anchors
continue to reject overlaps as in #13680.

The regression submits 64 completed single-fragment entries from one domain,
then verifies that a second domain can admit 32 entries; the final shard count
of 64 confirms the attacker stays at its reserve while the victim uses the
other half. It confirms a victim overlap is still rejected. RED on merged
#13992: the first victim admission failed (`victim reserve entry 1131 is
admitted`) because the attacker occupied every slot. The full fragment-overlap
module covers the #13937 throughput, #13680 retained-anchor replay, and #10658
incomplete fairness behavior.

Validation: the fail-on-revert run showed victim admission failed with
`ShardFull`. With completed-anchor reclamation at the domain cap, the targeted
regression passed and the complete `fragment_overlap::tests` module passed
(35 tests). A later rerun was blocked at compilation by unrelated unresolved
`injected` references in `afxdp/tests_embedded_poll_filter.rs`.

Closes #14009
