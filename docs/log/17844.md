# #17844 — Redact SNMP trap-group name in compiler diagnostics and logs

- **Timestamp**: 2026-10-26
  - **Action**: `compileSNMP` (`pkg/config/compiler_system_snmp.go`)
    now renders `SecretDataPlaceholder` (`##SECRET-DATA##`) in place of
    the trap-group name at all seven diagnostic format sites: the
    strict unknown-statement error and its lenient warning, the strict
    invalid-category error and its lenient warning, the
    no-emitted-category advisory warning, and the strict no-targets
    error and its lenient warning. Since #15052 the trap-group name IS
    the v1/v2c trap community, and #16728 masked it on AST/JSON/YAML/
    CLI/REST/gRPC surfaces — but commit errors are echoed to the
    committing terminal/log and `cfg.Warnings` ride tolerant-load /
    peer-sync paths, so the credential leaked to any reader of those
    outputs. Non-secret operands stay named (the offending statement
    key `prop.Name()`, the invalid category, the `tg.Categories`
    value), and the in-memory group (map key + `SNMPTrapGroup.Name`)
    retains the real value for wire processing. The remainder of
    `compileSNMP` (`snmpInertKnobWarnings`, client-list/community/v3
    diagnostics) was swept and never renders a trap-group name. The
    `pkg/snmp` sweep found eight trap lifecycle `slog` sites emitting
    `trapJob.group` (populated from `tg.Name`); each now emits the
    placeholder in the structured `group` field. `trapJob.group` remains
    real internally, and the v1/v2c `community` used on the wire is
    unchanged.
  - **File(s)**: `pkg/config/compiler_system_snmp.go`,
    `pkg/config/snmp_trapgroup_compiler_redact_17844_test.go`,
    `pkg/snmp/traps.go`, `pkg/snmp/agent_secret_log_4302_test.go`,
    `docs/log/17844.md`.
  - **Validation**: `TestTrapGroupCompilerDiagnosticsRedacted17844`,
    `TestTrapGroupCompilerWarningsRedacted17844`, and
    `TestTrapGroupCompilerValidGroupClean17844` PASS (9/9 subtests:
    strict + lenient unknown-statement / invalid-category /
    unemitted-category-advisory / no-targets, plus the valid control).
    With the compiler fix stashed, these tests FAIL with canary
    `CFG-TRAPSECRET-17844` leaked in diagnostics (RED).
    `TestTrapGroupNameNotLoggedOnStoppedDrop` FAILS when one slog operand
    is reverted to `job.group`, showing the canary in the log (RED);
    after restoring the placeholder it passes. The test also confirms
    the target field remains and the group field is redacted.
    `go test ./pkg/config/ -run 'SNMP|TrapGroup' -count=1` PASS.
    The three community/trap log tests in
    `agent_secret_log_4302_test.go` PASS. Full
    `go test ./pkg/snmp/ -count=1` reports one failure:
    `TestV2cNamedClientListRestrictDenies9416` fails in `CheckText`
    because the fixture's packed `10.1.2.0/24 restrict` statement is
    rejected; no baseline comparison was run for this package-wide
    failure. `go vet ./pkg/config/` and `go vet ./pkg/snmp/` PASS;
    `gofmt -l` on all changed Go files is clean. Sweep: all seven
    compileSNMP diagnostic formats render the placeholder; all eight
    trap lifecycle slog `group` fields render the placeholder.
  - **Risk**: Compiler diagnostics and trap lifecycle logs no longer
    disclose the secret group name. Compiler messages retain the
    statement key, category, and categories list; trap logs retain the
    target, event, interface, and a redacted group field. The in-memory
    group and wire community stay unchanged; no trap delivery or
    compilation behavior changes.
