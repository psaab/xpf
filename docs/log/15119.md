# #15119: decline TCP-MD5/TCP-AO datagrams in TCP segmentation and MSS clamp

## Trace and finding

Both segmentation builders (`frame/tcp_segmentation.rs` copy path and
`tx/tcp_segmentation.rs` prepared-TX twin, tried first by dispatch) copy the
full TCP header onto every output segment
(`copy_from_slice(tcp_header)`) while rewriting sequence numbers, IP/TCP
lengths, payload and checksums. For a datagram carrying a TCP-MD5 option
(kind 19, RFC 2385) or a TCP-AO option (kind 29, RFC 5925), every output
therefore carries an authentication option whose digest/MAC was computed
over the original single segment: the receiver discards every segment and
no Packet-Too-Big is ever sent, so a BGP-MD5/TCP-AO session whose MSS
exceeds the egress MTU stalls and flaps at hold-time. The dispatch
admission gate `forwarded_tcp_may_need_segmentation` admitted such frames
on length alone, so the PTB arm was never reached. The only prior integrity
decline was for IPv6 AH (#13634).

Sibling defect folded in (named in the issue): `clamp_tcp_mss` rewrites
the MSS option of a SYN even when the SYN carries a TCP-AO option (whose
MAC covers the TCP header including MSS) or sits behind an IPv6 AH header,
invalidating the SYN's authentication.

## Fix

- `frame/tcp.rs`: new shared `tcp_header_has_auth_option` walk (EOL/NOP/
  length rules identical to the MSS walk) plus kind constants 19/29.
  `clamp_tcp_mss` now declines when the SYN carries kind 19/29 or its
  IPv6 chain sights AH — defense-in-depth behind the existing build /
  in-place call-site AH gates.
- Both segmentation builders decline (return `None`) when the bounded
  TCP header carries kind 19/29, next to the existing AH/fragment
  declines.
- `forwarded_tcp_may_need_segmentation` declines the same frames, in
  lockstep with the builders, so dispatch falls through to
  `compute_forwarded_egress_ptb`: DF-set IPv4 / IPv6 emit
  Frag-Needed/PTB advertising the egress MTU, DF-clear IPv4 keeps the
  #9328 forward-whole disposition, tunnels keep their PTB conversion.
  Legitimate (non-authenticated) oversize TCP still segments; the NOP
  control cell pins that.

## Regression

- `tcp_auth_options_decline_segmentation_and_reach_ptb_15119`
  (tx/dispatch tests): MD5 and AO oversize frames are refused by the
  admission gate, both builders (prepared queue stays empty), and a
  DF-set frame emits Frag-Needed (type 3 code 4) advertising MTU 1400;
  the NOP-only control is admitted and segments into multiple frames.
- `clamp_tcp_mss_no_op_on_tcp_ao_syn_15119`,
  `clamp_tcp_mss_no_op_on_tcp_md5_syn_15119`,
  `clamp_tcp_mss_no_op_on_ipv6_ah_syn_15119`: authenticated SYNs are
  byte-identical no-ops; `clamp_tcp_mss_still_clamps_nop_control_15119`
  pins the legitimate clamp.
