# #11692 — enforce allocator flow caps on synced PAT reservations

- **Timestamp**: 2026-10-02
- **Action**: Enforced `max_tracked_flows` before synced PAT reservations can
  join a persistent lease, mint a lease, or insert a non-persistent live flow.
- **File(s)**: `userspace-dp/src/nat/allocator.rs`,
  `userspace-dp/src/nat/tests_idle_lease_sync_8121.rs`.

## Reserve boundary

`reserve_flow_maybe_persistent` already holds the allocator's live-state mutex
while deciding and inserting. A capacity check now runs after the idempotent
same-flow refresh and address-only identity refusal, but before the persistent
lease join/mint and ordinary live-flow insertion arms. At capacity it increments
the allocator exhaustion counter and returns `false`; the existing synced
reserve chain refuses the import instead of publishing an untracked PAT tuple.

The regression cell fills the live-flow cap with address-only tokens, which do
not consume PAT bitmap ports, then presents a still-free port to the synced PAT
reserve. It proves a free port cannot permit tracked-flow overshoot.
