# Issues 10315 and 10316 — keyed heartbeat admission and live proxy-ARP state

The two issues share the heartbeat/control-link trust boundary and were fixed in one lane. The RED probes below were run before the corresponding production change: #10315 against the branch-point behavior, and #10316 with each obsolete behavior temporarily restored in the worktree. No live HA lab was run; all evidence here is hermetic Go coverage.

## #10315 — keyed nodes reject unsigned first contact

### RED

The new fail-on-revert heartbeat cells were run against the pre-fix admission behavior:

```text
go test ./pkg/cluster -run '10315' -count=1 -v
```

The two security cells failed as intended:

- `TestKeyedNodeRejectsUnsignedHeartbeatBeforePeerAuth_10315`: a KEYED node admitted an UNSIGNED heartbeat before peer authentication, refreshing liveness.
- `TestUnsignedHeartbeatDoesNotDemoteSolePrimary_10315`: the same unsigned claim demoted the sole primary to secondary through election.

The signed-heartbeat and unkeyed-interoperability controls remained positive controls.

### GREEN

`heartbeatAuthDecision` now keys admission on local key configuration, not the process-lifetime `peerAuthSeen` bit. A keyed node rejects an unsigned frame before liveness refresh or election; an unkeyed node retains dual-accept behavior.

```text
go test ./pkg/cluster -run '10315|TestMalformedHeartbeatWarningsAreRateLimitedBeforeAuth|TestWrongClusterWarningsAreRateLimitedBeforeAuth' -count=1 -v
```

Result: all six selected cells passed:

```text
PASS
ok   github.com/psaab/xpf/pkg/cluster  0.040s
```

The keyed rejection output explicitly reported `missing auth trailer (enforced: local key configured)`; the signed and unkeyed controls both admitted their frames.

## #10316 — rate-limited pre-auth warnings

## #10316 — live virtual-MAC refresh and coherent responder snapshot

### RED: stale MAC

The wire-boundary regression was run after temporarily restoring the old behavior that did not publish the interface MAC returned by reconcile:

```text
go test ./pkg/daemon -run '^TestResponderReconcileRefreshesVirtualMAC_10316$' -count=1 -v
```

It failed as intended:

```text
reconcile left responder MAC at 02:bf:72:16:01:00, want live MAC 02:bf:72:16:02:00
```

### RED: reconcile/reply race

The race regression was run after temporarily moving `junosRef`/`rgID` reads outside the responder snapshot lock:

```text
go test -race ./pkg/daemon -run '^TestResponderReconcileAndRepliesAreRaceFree_10316$' -count=1 -v
```

The race detector reported concurrent reads at `snapshot` and writes in `syncProxyARPResponders` (the old unsynchronized `junosRef`/`rgID` path), and the test failed with `race detected during execution of test`.

### GREEN

Reconcile now re-reads the kernel interface MAC, publishes the address/interface/MAC/RG snapshot under one lock, and the reply path copies the current MAC from that snapshot. Startup publication is conditional so an in-flight reconcile cannot be overwritten by the old socket-open MAC. The final targeted cells passed:

```text
go test ./pkg/daemon -run 'TestResponderReconcileRefreshesVirtualMAC_10316|TestResponderReconcileAndRepliesAreRaceFree_10316' -count=1 -v
go test -race ./pkg/daemon -run '^TestResponderReconcileAndRepliesAreRaceFree_10316$' -count=1 -v
```

```text
PASS
ok   github.com/psaab/xpf/pkg/daemon  0.069s
PASS
ok   github.com/psaab/xpf/pkg/daemon  1.060s
```

The full daemon package also passed:

