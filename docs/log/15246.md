# Issue #15246: userspace-dp: fix cohort — fabric-stamp hardening (A65-02)

## Why

`build_live_forward_request_from_frame` preserved any
`02:bf:73:<id>` source MAC that parsed as a same-zone V2 stamp
(`fabric_nat_scope_stamp_mac_for_zone`: prefix + scope-id identity +
same zone + `redundancy_group > 0`), even when the packet arrived on a
non-fabric LAN port. No caller gated the preservation on the ingress
interface, so a LAN host could emit a forged V2 source MAC naming
another same-zone interface in a peer-active RG and choose the
interface scope the peer applies to punted packets (interface-scoped
NAT scope on the receiver-side session). Material per the 3-way
validator consensus on A65-02 (`research-work.AdQvt1jMKw`).

The receive-side stamp parser
(`parse_zone_encoded_fabric_ingress_from_frame`) already fails closed:
it returns `Absent` unless `ingress_is_fabric`, and fully validates V1
identity/RG and V2 peer ownership on fabric arrivals. The
forward-request builder was the one path that trusted the raw frame
stamp without that ingress gate.

## What

- `userspace-dp/src/afxdp/forward_request.rs`
  (`build_live_forward_request_from_frame_with_dynamic`): the frame's
  V2 source is preserved only when
  `ingress_is_fabric(forwarding, ingress_ident.ifindex)`. On any other
  ingress the builder now mints from the real ingress identity —
  `resolve_fabric_redirect_for_ingress_identity` over the logical
  ingress ifindex (`resolve_ingress_logical_ifindex`, falling back to
  the physical ifindex, the same shape the poll loop's
  `fabric_nat_scope_ifindex_for_redirect` uses for LAN arrivals) — and
  only when that yields no stamped resolution does it fall back to the
  prior V1 zone-only stamp
  (`resolve_zone_encoded_fabric_redirect_by_id`). NOT changed:
  `fabric_nat_scope_stamp_mac_for_zone` itself (its zone/RG checks
  still apply on the fabric path), the receive-side parser, and any
  non-`FabricRedirect` disposition.
- `userspace-dp/src/afxdp/tests_bind_forward.rs`: three regression
  cells driving the anchored builder directly (the function both the
  session-hit path and the flow-cache fallback call):
  - `lan_ingress_forged_v2_stamp_not_preserved_15246` — LAN ingress
    (ifindex 10) carrying a forged V2 stamp for ifindex 11 must be
    re-stamped with the real ingress scope. RED pre-fix.
  - `fabric_ingress_v2_stamp_preserved_15246` — control: the same
    stamp on the fabric parent (ifindex 21) is preserved verbatim
    (the legitimate peer re-punt).
  - `lan_ingress_unstamped_gets_real_identity_stamp_15246` — control:
    an unstamped LAN punt is stamped from the real ingress identity.

## Validation

- RED on `origin/master` (30659af88f, fix stashed, tests kept):
  `lan_ingress_forged_v2_stamp_not_preserved_15246` FAILED (the request
  carried the forged stamp) and
  `lan_ingress_unstamped_gets_real_identity_stamp_15246` FAILED (the
  old V1-only fallback); the fabric-ingress control passed.
  `cargo test --bins -- 15246`: 1 passed, 2 failed.
- GREEN after the fix: all three cells pass
  (`cargo test --bins -- 15246`: 3 passed, 0 failed, 8784 filtered).
- Note: `origin/master` at 30659af88f does not compile its test build
  (`src/afxdp/mirror/mod_tests.rs:1032` missing the #15113
  `ingress_vlan_id`/`unit_scoped` fields) — pre-existing, base-attributed;
  the RED/GREEN runs above used a temporary local repair of that one
  initializer, reverted before commit and not part of this change.

## Risk

A LAN host's forged stamp previously also won when the real ingress
interface had no V2 scope identity; it now degrades to the V1
zone-only stamp — the same fail-closed fallback unstamped LAN punts
already used. Fabric-ingress re-punts are byte-identical to before.
