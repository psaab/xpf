# #16791 — one absent managed netdev poisoned the whole `networkctl reconfigure` batch (R3-A37-02)

- **Timestamp**: 2026-10-25
  - **Action**: `Apply`'s activation tail issued ONE
    `networkctl reconfigure -- <all managed names>` argv. `networkctl`
    resolves every operand before acting, so a single managed row naming
    a device that does not exist — an unzoned VLAN unit (`ge-0-0-1.60`
    compiles to a managed row, but its kernel child is only created for
    zoned units), an over-IFNAMSIZ `br-*` bridge row (the #16792 cohort),
    or a transiently absent dynamically-created device — failed the whole
    call (`Failed to resolve interface ...: No such device`, rc=1,
    nothing reconfigured). `Apply` then recorded #4954
    `reconfigurePending` debt for EVERY name and warned, so every later
    Apply re-ran the same doomed batch: the forced per-interface
    reconfigure the tail exists for (#5718/#6912) never ran box-wide and
    the debt could never clear while the absent row persisted.
    Fix: the tail now reconfigures PER INTERFACE — one
    `networkctl reconfigure -- <name>` call per eligible row, in row
    order, preserving the #9885 `--` separator. A name that definitively
    resolves to no live kernel link (new `linkExists` seam over
    `net.InterfaceByName`, ENODEV / "no such network interface") is
    skipped with a warning and carries NO debt — there is no link to
    apply addresses to, and when the link later appears its creating
    Apply (changed files) runs the tail for it. A genuine per-interface
    failure is warn-only exactly as before but is owed ONLY by its own
    name; succeeded names clear. An inconclusive existence lookup (any
    non-absence error) still attempts the reconfigure and owes ordinary
    debt on failure, so a transient lookup failure never silently skips
    address application for a real link. NOT changed: row eligibility
    (`!Unmanaged && !Disable && BondMaster == ""`), the reload leg and
    its process-scoped debt, `restoreSlowPathRPFilter`, warn-only
    `Apply`-returns-nil semantics, and VLAN-child creation itself (owned
    by the D82-02 cohort issue, not this argv-isolation fix).
  - **File(s)**: `pkg/networkd/networkd.go`,
    `pkg/networkd/reconfigure_absent_16791_test.go` (new),
    `pkg/networkd/link_exists_testmain_16791_test.go` (new, hermetic
    present-by-default `linkExists` for the unit sandbox),
    `pkg/networkd/activation_tail_5718_test.go`,
    `pkg/networkd/external_reload_tail_6912_test.go`,
    `pkg/networkd/reconfigure_end_of_options_9885_test.go` (argv-shape
    expectations updated to per-interface calls),
    `pkg/networkd/README.md`, `docs/log/16791.md`
  - **Validation**: new `TestReconfigureAbsentRowDoesNotPoisonBatch16791`
    (the issue acceptance: stubbed networkctl fails any argv containing
    the absent name exactly as networkd 262 does; existing links are
    reconfigured per-interface in order, no debt, steady-state Apply
    quiet), `TestReconfigureFailureIsolatedToItsOwnName16791` (debt is
    exactly the failed existing name; retry/recovery clears it),
    `TestReconfigureAbsentRowAppearingLaterIsReconfigured16791` (no
    blacklist), `TestReconfigureInconclusiveLookupStillAttempts16791`
    (fail-open toward attempting), and
    `TestIsNoSuchInterface16791` (absence classifier). Existing #4954
    reconfigure-debt, #5718 activation-tail, #6912 external-tail and
    #9885 argv suites updated where they pinned the single batch argv /
    call count and stay green. Counts in the commit body.
  - **Risk**: One `networkctl` process spawn per managed interface
    instead of one per Apply (bounded by the interface count, on the
    commit path only, each under the existing 15s `networkctlTimeout`);
    in exchange a failing interface no longer suppresses the others. A
    link that disappears between the existence check and the call fails
    its own reconfigure and owes ordinary retryable debt — the same
    posture as any other transient reconfigure failure. Skipped absent
    rows warn once per activation pass rather than per Apply forever.
