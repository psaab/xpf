# #17680 — Count OSPF authentication key lengths in bytes

- **Timestamp**: 2026-10-26
  - **Action**: Replaced rune-based OSPF key bounds with byte bounds across schema validation, compiled strict/lenient validation, and FRR render belts; schema validation now measures valid Junos `$9$` credentials by decoded plaintext.
  - **Why**: FRR stores OSPF MD5 keys and simple passwords in fixed-width byte fields. Rune counting admitted UTF-8 keys whose byte sequences exceed ospfd's 16-byte/8-byte limits, allowing truncation and reload churn. The authored `$9$` blob also must not be measured instead of its valid plaintext.
  - **What**: Updated all OSPF byte-length checks, diagnostics, schema descriptions, and docs. Added multibyte over-limit and exact-byte-limit regressions for schema validation, the compiled gate (including legacy MD5), and FRR rendering; added encoded-MD5 and decoded-simple `$9$` controls. Retained ASCII boundary, empty-key, rollover, and no-auth controls.
