# 14359 — SessionSync sweep/storeBulkWalk strip PolicyRuleID and PolicyCounterIdx

`PolicyRuleID` (#11070, stable `"<from>-><to>/<name>"`) and
`PolicyCounterIdx` (#3301, 1-based per-rule hit-counter handle) are
sync-only fields on `dataplane.SessionValue`/`SessionValueV6`: they cross
the cluster wire (`sync_protocol.go`) but have no slot in
`bpfSessionValue`/`bpfSessionValueV6`, so `toBPF().sessionValue()` returns
them as `""`/`0`. The periodic `SessionSync.sweep()` and the
`storeBulkWalk` bulk path rebuild send values from that BPF mirror
(`stampSweepV4/V6` → `GetV4/GetV6`, `sync_bulk.go`), and
`stampInstallGenV4/V6` restored memos for four other sync-only groups
(#9412 close class, #10888 handshake state, #9752 install table, #11064
source-NAT ICMP) but none for policy identity — so every mirror-sourced
(re)send shipped `""`/`0`. On the standby the Rust import
(`userspace-dp/src/server/helpers/session_sync.rs`) deliberately binds
`policy_counter: None` when `policy_rule_id` is empty (no fallback to
the positional index), so post-failover packets on those sessions never
increment per-policy hit counters; and
`purge_sessions_bound_to_deleted_first_policy`
(`userspace-dp/src/afxdp/session_glue/revalidation.rs`) identifies
sessions admitted by the first compiled policy (`policy_id == 0`,
indistinguishable from unattributed) exclusively via
`counter.rule_id()`, so a wiped session admitted only by a deleted first
policy survived its deletion indefinitely.

Fix (Go only, no wire-format or Rust change): a new
`policyIdentityMemo{sessionID, ruleID, counter}`
(`pkg/cluster/sync_policy_identity_14359.go`, generic
`stampPolicyIdentityLocked`/`lookupPolicyIdentityLocked` mirroring the
#11064 source-NAT memo discipline) kept in four new bounded guard maps on
`SessionSync` — `policyIdentitySentV4/V6` under `genSentMu`,
`policyIdentityRecvV4/V6` under `recvGenMu` (now 24 cap families:
14 sender + 10 receiver). `stampInstallGenV4/V6` records a stated
identity and restores it on a `""`/`0` mirror resend, falling back to
the receive memo for a promoted standby that only received the
incarnation; `installClusterSyncedV4/V6` restores/records on the receive
apply before the dataplane write, so a stamp-less resend from an old
sender cannot erase the binding. Records are matched on `SessionID`
(new incarnation never inherits; `SessionID == 0` records/restores
nothing, failing toward `""`/`0`), and either field stating a value
records both as stated (a re-compiled/corrected binding wins; only the
both-empty mirror-loss signature is restored). Eviction mirrors the
sibling memos: `takeDeleteGenV4/V6`, `deleteClusterSyncedV4/V6`, and the
`preserve=false` namespace reset in `resetRecvSessionGen` (so a rebooted
peer reusing tuple+sessionID cannot resurrect a dead rule binding);
the `preserve=true` same-incarnation reclaim retains them. The lossy
test fixture `dropSyncOnly9752`/`dropSyncOnlyV69752` now also drops
`PolicyRuleID`, matching production `sessionValue()` (which already
zeroed it by omission).
