## Why

The shared tail — "the compiler drops a valueless statement, so this commits
clean and the configuration silently does not carry it" — is true only where
the finding is logged-and-continued (tolerant `Store.Load` / `Store.SyncApply`
ingress; lenient compile downgrades). On the strict arm the very same bytes
are the commit-refusing error, so the refusal asserted the commit succeeded
and the config would render lacking the statement — an outcome the gate
itself prevents. The #16712 tail's "it renders in `show configuration`" is
the same persistence claim in the one-builder shape.
