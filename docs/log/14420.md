## Why

The packed (brace-elided) RA interface spelling `protocols { router-advertisement { interface ge-0/0/0 managed-configuration default-lifetime 0; } }` put the whole body on the `interface <name>` node's own Keys with no Children. `compileRouterAdvertisement` iterated `inst.node.Children` only (via `expandFlatRun`), and the compact normalizer only folds valued-leaf heads, so a zero-arg flag opening (`managed-configuration` / `other-stateful-configuration`) stayed packed and the loop saw an empty body. The interface was created with `ManagedConfig=false`, `DefaultLifetimeSet=false`, and no prefixes, so `pkg/ra` advertised Router Lifetime 1800 for an explicit `default-lifetime 0` — RFC 4861 §6.2.1 "this router is NOT a default router" inverted, hijacking host default-route selection (#4119's defect by a dropped leaf, distinct from the flat `set` route fixed in #8939). The braced twin and the valued-leaf packed opening already compiled correctly.

## What

`compileRouterAdvertisement` now expands the instance body with `packedBodyChildren(inst.node, schemaForPath("protocols", "router-advertisement", "interface"))` before `expandFlatRun`, the same schema-driven expansion the OSPF/OSPFv3 interface loops use. No sender change: `DefaultLifetimeSet` now reaches `buildRA`, which already honors explicit 0. Added `TestRAInterfacePackedOpening14420` (pkg/config: managed/other openings, braced-twin parity, valued-leaf control) and `TestBuildRA_PackedOpeningPreservesExplicitZero14420` (pkg/ra: packed spelling marshals RouterLifetime 0 and ManagedConfiguration true, matching the braced twin).
