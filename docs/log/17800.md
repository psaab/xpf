# 17800: verify SNMP IPv6 in-band and pktinfo ifindex-only cases

## STEP-0: current-master finding

Checked the cited code on `origin/master` at `9aa007277d` before editing. `pkg/snmp/agent.go:920-949` opens the unbound listener alongside the management-VRF listener. `pkg/snmp/pktinfo_linux.go:100-129` accepts both IPv4 and IPv6 pktinfo cmsgs; for either fixed-size cmsg it constructs `dst` from the address field. `pktinfo.oob` (`pktinfo_linux.go:181-202`) returns nil only when `dst == nil`. An ifindex-only cmsg with an unspecified (all-zero) address therefore parses to a non-nil unspecified IP and retains the family needed to echo the ifindex. The nil-destination `pktinfo{ifindex: n}` shape has no family/address to encode and is not produced by parsing a valid cmsg. No production ifindex defect was found.

This was a coverage gap: the existing #16781 netns test polled only IPv4; existing IPv6 assertions were synthetic ancillary-data round trips, not a real IPv6 in-band request and reply.

## Changes

- Extend the #16781 isolated management-VRF/in-band test fixture with an optional v6 trust address and UDP6 manager. The named IPv6 subtest sends three polls and asserts each reply source is the exact polled trust address; IPv4 management/in-band checks still run if IPv6 setup is unavailable.
- Bring `lo` up in the fresh appliance netns before binding. With it down, Go's generic wildcard `udp` listener selected IPv4 (`0.0.0.0:161`) and could not exercise the intended dual-stack path; with it up, the listener is `[::]:161` and receives both families.
- Add `TestPktinfoIfindexOnly17800`, covering IPv4 and IPv6 fixed-size cmsgs with only the ingress ifindex set (unspecified destination), both egress-pin arms, and the no-destination/no-family nil-oob control.
