# #15034 — Non-zero unit with no VLAN tag on an untagged parent commits clean (A06-01)

## Defect

A non-zero unit with no positive VLAN tag on a parent without
`vlan-tagging`/`flexible-vlan-tagging` committed clean:

- `ResolveKernelIfName` (`pkg/config/types.go`) and `snapshotLinuxName`
  (`pkg/dataplane/userspace/interfaces.go`) derive
  `kernelBase.<unit.Number>` for `unit.Number > 0` without a VLAN — a
  device nothing creates.
- `buildInterfaceNetworkdModels` (`pkg/dataplane/compiler_iface.go`)
  without tagging folds every unit's addresses onto the untagged
  parent.

So the unit's address lands on the parent (unit 0's zone) while its
own zone and input filter bind to the never-created `.<unit>` device:
the filter is never installed and the subnet is attributed to the
wrong zone. This is the residual of #14574, whose gate keyed only on a
positive tag.

## Fix

`pkg/config/compiler_interfaces_vlan_tagging.go` — the #14574 gate
(`validateVlanIDTaggingAST`, both compile entrypoints, per-node
expansion, strict-reject / lenient-warn #1960) gains the mirror arm:

- A unit with number > 0, no positive `vlan-id`/`vlan-tags` tag and an
  untagged parent is a finding (`#15034`), naming interface, unit and
  the phantom `LinuxIfName(iface).<unit>` device.
- Exemptions are exactly the shapes another owner creates the device
  for: a unit or interface `tunnel` stanza (per-unit tunnel device, or
  the shared interface-tunnel/WireGuard device), secure-tunnel names
  (`st<N>`, xfrmi), loopback names (`lo<N>`, Junos multi-unit
  loopback) and `irb` (bridge-domain routing-interface). A `reth<N>`
  unit is not exempt: it resolves onto the member's `.<unit>` device,
  which only tagging creates.
- Unit 0, `vlan-id 0` on unit 0, and every tagged/flexible shape are
  untouched; the #14574 positive-tag arm is unchanged (a unit reported
  with a tag in either node view keeps the #14574 finding).
