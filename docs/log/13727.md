# #13727 — bind newflow-gen client source for the SNAT-pool ceiling harness

## Root cause

The loss userspace cluster's `pool-snat` rule matches `10.0.61.240/28`, but
newflow-gen's client used `TcpStream::connect_timeout` without a local bind.
The host's normal `10.0.61.102` source therefore selected the interface-mode
catch-all instead of the pool rule, so the ceiling harness correctly refused
cells with zero pool allocations.

## Change
- Added optional client `--src-bind <IP>` using `socket2`'s source bind and
  timeout-aware connect. No-source calls retain the existing
  `TcpStream::connect_timeout` path.
- Added `SRC_BIND` to the ceiling harness, passed only when configured, and
  reported it in dry-run output. The harness still does not mutate host
  addresses or firewall configuration.
- Documented the required operator-added pool-prefix address, source-bind
  invocation, and remaining pool-capacity / restore-baseline blockers.
- Updated the unreached-harness inventory to remove the now-fixed client-bind
  limitation.

## Validation

- **RED before**: Added the socket-level regression; on the unmodified source,
  the test failed compilation with `cannot find function connect_tcp`.
- **GREEN**: Full `cargo test --manifest-path test/incus/newflow-gen/Cargo.toml`
  passed: 14 tests.
- `bash -n test/incus/newflow-ceiling-harness.sh` passed.
- Harness `--dry-run` with `SRC_BIND=10.0.61.241` resolved the loss userspace
  instances and printed the requested source address. No cluster measurement
  or mutation was run.

## Risk / remaining work

The operator must assign the matching pool-prefix address to the LAN host for
the measurement. The live loss cluster is shared and has an active destructive
failover lane, a clock synchronization issue, and no authorized restore
baseline for #10988; source binding does not remove those lab gates.
