## Change

The #11571 managed-routing strict/tolerant admission gate now resolves FRR interface names through the same `SplitInterfaceUnitRef(...).Literal` identity used by the zone map and effective host-inbound resolver. A padded alias such as `ge-0/0/1.00` therefore resolves to the in-zone `ge-0/0/1.0` key rather than escaping validation.

The gate now recognizes `any-service` in the effective system-services set as a full-admit for the managed OSPFv2, OSPFv3, and RIP protocols. It continues to check the effective per-interface protocol set, so an interface override still replaces the zone setting. `system-services all` remains a bounded named-service union and does not admit these routing multicast protocols; the mismatch remains strict-error/tolerant-warning otherwise. Host-inbound protocol-token case rules are unchanged.
