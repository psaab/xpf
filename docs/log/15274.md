# #15274 — fix cohort: #9818 incarnation-retirement residuals (C03-02, C03-03)

- **Timestamp**: 2026-10-19
- **Action**: adopt the priming connection's proven peer identity on every
  accepted prime and clear it on full disconnect (C03-02); stop an
  unverifiable fabric-auth token from erasing a measured clock skew
  (C03-03).

## Why

- **C03-02** (Low, transient): `classifyPrimeLocked`
  (`pkg/cluster/sync_conn.go`) recorded `s.peerIdentity` only on the
  first incarnated prime (`!priorKnown`), and `handleDisconnect` never
  cleared it. When a restarted process's heartbeat epoch landed before
  its first install, the install's epoch arm retired the old incarnation
  while `peerIdentity` still named the dead process; a same-boot-id
  prime (daemon restart) then left the stale identity in place, so the
  next #9818 retirement ran its predicate against the wrong retired
  identity — a healthy fabric evicted and redialled (~1 s), a dead
  socket briefly stamped current, an extra cold-prime bulk and aborted
  fence-ack waiters.
- **C03-03** (Low, operator diagnostic): the fabric-auth skew scan
  (`pkg/grpcapi/fabric_auth_skew_6708.go`) stored "no skew"
  (`atNanos=0`, `reported=false`) for any present-but-unverifiable token
  once past the global throttle, so a garbage token from the fabric
  segment erased a real measured skew from `show chassis cluster
  status`. No enforcement change; the #10025 clock alarm is independent.

## What

- `pkg/cluster/sync_conn.go`:
  - `classifyPrimeLocked` `!switched || !priorKnown` arm: record
    `s.peerIdentity` from the priming connection on every accepted prime
    with a known identity (was: only `!priorKnown`). The priming
    connection is installed, hence belongs to the current incarnation,
    so its proven identity is authoritative.
  - `classifyPrimeLocked` consumed arm (`rebootAwaitingBootID`, epoch not
    raised again): adopt the priming identity too — that prime belongs
    to the process the epoch arm established, not the one it retired.
    Without this, the hb-first cell's later boot-id switch would retire
    against the intermediate identity and preserve its corpse.
  - `handleDisconnect` full-disconnect block: clear
    `s.peerIdentity` beside the other incarnation-scoped clears
    (`peerHeartbeatAckEver`, capability flags). Partial disconnects are
    untouched — the survivor is the same process.
  - The boot-id switch arm (#14951 pre-advance capture) is unchanged.
- `pkg/cluster/sync.go`: `peerIdentity` field comment updated to the new
  set/clear contract.
- `pkg/grpcapi/fabric_auth_skew_6708.go`: the `!ok` scan arm now returns
  `""` without touching the recorded measurement. Only
  `noteFabricAuthOK` (a token that verifies normally) clears it. The
  garbage rejection itself still carries no skew clause.
- Tests:
  - `pkg/cluster/sync_peer_identity_15274_test.go` (new):
    restart-heartbeat-first cell (B's epoch 101 lands before install,
    B announces token 222, same-boot-id prime must report token 222;
    then C's restart advances twice total, B's corpse evicted, C's fab0
    kept, identity = C token 333) and a full-vs-partial disconnect
    clearing cell.
  - `pkg/grpcapi/fabric_auth_skew_15274_test.go` (new): measured 150s
    skew (exact window multiple) survives a garbage token past the
    throttle; garbage rejection carries no clause; `noteFabricAuthOK`
    still clears.
  - `pkg/grpcapi/fabric_auth_skew_6708_test.go`:
    `TestSkewScanIsThrottled6708`'s trailing sub-assertion folded from
    the old "unexplained token clears" contract to the #15274 contract.
- `pkg/cluster/README.md`: "#15274 C03-02" paragraph beside the
  #9636/#9818 classifier discussion.

NOT changed: the ±1 accept band, the scan band/throttle, the #10025
alarm, any enforcement path, wire formats, or the #14951 switch arm.
No age-based expiry was added for the skew measurement: the issue's
"or on age" is satisfied by the existing recovery clear, and inventing
an expiry would reintroduce silent disappearance of a still-true
diagnosis (the peer keeps failing auth until its clock is fixed, and
each of its skewed retries re-measures).

## Risk

- C03-02: a prime from an installed connection now overwrites
  `peerIdentity` even when its boot id did not switch. That identity is
  the connection's own proven capabilities identity; the only writer
  besides retirement paths. A legacy peer announcing nothing keeps the
  previous behaviour (`connPeerIdentityLocked` reports unknown).
- C03-03: a measured skew now persists until a fabric token verifies
  normally. If the peer is decommissioned mid-episode the status line
  keeps reporting the last measurement — deliberate: it was true when
  measured, the peer's skewed retries keep refreshing it, and recovery
  clears it. The one-shot warning latch (`reported`) is likewise no
  longer re-armed by garbage tokens, so garbage cannot re-trigger the
  warning flood the latch exists to prevent.
- Lab/HA replay on the loss cluster is not exercised here; the
  `handleNewConnection`/`handleMessage`-driven cells over the #9636
  harness are its proxy.
