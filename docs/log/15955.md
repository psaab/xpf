# #15955 — triple snapshotContentHash per publish; compiler Clone/ExpandGroups audit

## Defect

Every userspace snapshot publish hashed its snapshot up to three times
under `m.mu`: once for the duplicate-publish dedup compare, once inside
`stampSnapshotContentDigest` at the single apply_snapshot send site, and
once after the send to record `lastSnapshotHash`. Each hash is a full
JSON marshal + SHA-256 over the snapshot (measured 0.386 ms / 4.02 ms /
20.4 ms at 20.7 KB / 202 KB / 1.5 MB), so the two redundant passes waste
up to ~112 ms of lock hold per publish at the largest measured shape.
Separately, `CompileConfig` performed ~30 `Clone()` + 28–32
`ExpandGroups` per compile and the audit question was whether compiler
gates could share one expanded tree.

## Fix

Hash dedup, scoped to publishers that can prove one hash describes the
exact struct sent:

- New `snapshotContentHashWithClear` (builder.go) and a
  `snapshotContentHashCalls` counter (the regression seam).
- New `requestApplySnapshotPrehashedLocked` /
  `publishPreparedSnapshotPrehashedLocked` threading a caller-computed
  hash into the send site, where `stampSnapshotContentDigestPrehashed`
  stamps it instead of recomputing. The plain entry points are
  unchanged and still stamp authoritatively.
- Deduped publishers (one hash total in the common case;
  `postPublishHash` reuses it and recomputes only when the
  ClearPolicies marker was in force): `PublishRouteOverlaySnapshotWithLatch`,
  `RepublishCurrentCaptureAuthority`, `RefreshInterfaceRowsForLink`,
  `syncSnapshotLocked` (deferred sync), and `applyCompiledSnapshot`
  (stamp+post only — it never had a dedup hash). Each captures the
  pre-send `ClearPolicies` value, because the marker is NOT hash-zeroed
  and the send spends it after stamping; the post-publish hash is
  rebuilt with that value so `lastSnapshotHash` keeps describing the
  content the helper holds.
- NOT deduped, deliberately: `UpdatePolicyScheduleState` and
  `retryDeferredWorkerArmLocked` send via `requestApplySnapshotLocked`,
  whose `prepareSnapshotForApply` can rebuild derived sections after
  any earlier hash. Their post-publish hash stays authoritative and
  recomputed; a regression test pins that behavior.

Compiler Clone/ExpandGroups: scoped down with proof, no sharing landed.
Every per-node gate clone (`compiler_interface_unit_alias.go`,
`compiler_interfaces_qinq.go`, `compiler_interfaces_vlanmap.go`,
`compiler_interfaces_vlan_tagging.go`,
`compiler_scheduler_window_pairs_11358.go`,
`compiler_system_login_gates.go`, `tunnelid.go`, `zoneid.go`,
`routinginstanceid.go`, `dup_names_expanded_6455.go`) expands with a
different `${node}` var set (node0 vs node1 give different effective
trees) or a different tagging mode, and several swallow expansion errors
per-view — a shared expanded tree would be a peer-view or provenance
bug, not an optimization. The two entry-point expansions
(`compiler.go` generic vs node-aware) likewise differ (node-fallback
probe vs explicit vars). The only identical-shape candidate,
`expandedPolicySourceTree`, must stay pre-fold while the main tree is
folded by `mergeDuplicateNamedInstances`. No gate pair mutates nothing
between identical expansions, so nothing was shared.

## Validation

- `go test -run 'TestPublishHashDedup|TestApplySnapshotHasOneSendSite9520|...'`
  (see PR body for the full focused list) — new tests pin: exactly 2
  hashes per deduped publish (1 on a dedup skip), the wire digest equals
  the pre-fix stamped digest, ClearPolicies pre-send vs spent hashes
  differ and the recorded hash is the pre-send one, and the scheduler
  (prepare-path) publish still recomputes its post hash.
- Benchmarks in `publish_hash_dedup_15955_bench_test.go` (triple =
  pre-fix sequence, dedup = landed sequence through production helpers)
  at 202 KB / 1.5 MB; before/after numbers in the PR body.

## Risk

Publish semantics are unchanged (same bytes, same digest, same dedup
decisions); the only behavioral surface is lock-hold time. The
ClearPolicies clear path and the prepare-path publishers are pinned by
regression tests. Compiler behavior is untouched.
