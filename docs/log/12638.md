# Issue #12638 — retain publication debt across identical recovery

## Root cause

A rejected hold-drop leaves the previously published hash intact. Recovery to the identical pre-drop feed is forced to republish, but if that republish is rejected, the installed and published hashes match. Hash comparison alone then hides publication debt and suppresses the next identical refetch. The same state occurs when accepted content P is replaced by rejected content N and the provider reverts to P.

## Fix

Add `publishUnconfirmed` to feed state. Set it after every rejected install or hold-drop publish, carry it across same-name feed replacement, and clear it only after an accepted publish. Include the marker in both the install publish decision and reported publication-debt calculation. This preserves retry and status behavior when content hashes happen to match.

## Validation

- RED: before the fix, `go test ./pkg/feeds -run 'Test(DoubleRejectedIdenticalRecoveryRetries12638|AcceptedThenRejectedThenRevertRepublishes12638)$' -count=1` failed: the double-rejected recovery reported no debt, and the revert to P did not republish.
- GREEN: the two regression cells pass after the fix.
- Mutant, `needsPublish` marker OR removed: both regression cells failed; double-rejected recovery's next identical refetch did not retry and content revert did not republish.
- Mutant, `feedPublicationDebt` marker OR removed: both cells failed because rejected identical recovery was reported without debt.
- Full package: `go test ./pkg/feeds -count=1` passed.
- Static analysis: `go vet ./pkg/feeds` passed.

## Risk

The marker is per-feed runtime state and is protected by the manager mutex. It follows the existing one-publish-attempt-per-fetch retry cadence; it does not introduce tight retry loops. An accepted publish clears debt, preserving stable-feed no-thrash behavior.
