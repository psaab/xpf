# Issue #15742 fix lane C — HA-filter connected prefixes by RG ownership

Base: `origin/master@520289a471` (contains #15744). Diagnosis:
`/var/worktrees/wt-15742b/docs/log/15742b.md`.

## Diagnosis carried forward

After #15744, the pref-200 terminal default reaches the split node's helper
FIB, but the gate targets never reach it. fw1's helper FIB carries the
connected WAN prefixes `172.16.80.0/24` and `2001:559:8585:80::/64` on
`ge-7-0-2.80` (RG1, owned by node0) because connected rows were derived from
interface addresses without HA filtering. The gate targets
`172.16.80.200` / `2001:559:8585:80::200` are inside those prefixes, so LPM
selects Connected -> peer-owned egress and the packet dies without session
or fabric redirect. Zebra on fw1 has no WAN connected routes; the helper FIB
disagreed with zebra/kernel.

The previous Rust cell was test-only-green for this shape: it resolved the
v6 target through the default gateway and had no connected `/64` on the WAN
egress.

## Decision

Implement diagnosis §6 direction (2) as the primary fix: HA-filter connected
prefixes by egress RG ownership, aligning the helper FIB with zebra. Do not
implement direction (1) terminal demotion: operator discard/reject statics
must remain drops, and no cluster-terminal identity is reliably available at
that layer. Add the `reject` bit to the FIB dump wire (F3) while here.

## Fix

- Snapshot protocol v55 -> v56 (Go `ProtocolVersion` and Rust
  `CONFIG_SNAPSHOT_PROTOCOL_VERSION`): `InterfaceSnapshot` carries
  `ConnectedRGPeerOwned` / `connected_rg_peer_owned`. There is no mixed-version
  runtime support requirement; the exact-version gate refuses an old helper.
- Go: `RGPrimaryProvider` (`func(rgID int)(primary, known bool)`) is wired by
  the daemon from `cluster.Manager.LocalGroupPrimary` in
  `daemon_apply_dataplane.go`, the same ownership source as the FRR HA
  demotion filter (#15734). The manager threads it through full builds,
  apply-time rebuilds, interface-link refresh, and routes-only overlay
  publishes.
- Ownership predicate is identical for Go rows and interface marking:
  standalone (no chassis cluster) never filters; RG <= 0 never filters;
  clustered RG > 0 requires `(known && primary)`. A clustered node with a
  nil provider or unknown group fails closed (filtered), mirroring the
  helper HA gate's stance for unknown RGs.
- Go: `buildRouteSnapshotsWithRGPrimary` marks a copy of the interface rows
  and skips connected `RouteSnapshot` rows for marked rows, so the connected
  prefix cannot cover learned gaps or shadow the default. The old
  `buildRouteSnapshots` signature remains as a nil-provider wrapper.
- Rust: `populate_interfaces` suppresses only the `connected_v4` /
  `connected_v6` push for a marked row. It preserves `local_*`,
  `local_tables_*`, `interface_nat_*`, `configured_iface_*`, WG ownership,
  `connected_*_by_ifindex`, and directed-broadcast state. This is deliberate:
  local delivery and return-path state are not transit FIB ownership, and
  HA enforcement separately demotes local delivery on inactive RGs.
  One residual follows: the interface's own WAN host address remains a local
  target even when its connected transit prefix is suppressed; it does not
  attract neighboring destinations inside the prefix.
- Failover republish: RG ownership edges in `handleClusterEvent` and any-RG
  changes in `reconcileRGState` call `scheduleConnectedRGRepublish`, which
  takes `applySem` off the event path and reuses
  `PublishRouteOverlaySnapshotWithLatch` + `BumpFIBGeneration`. Unchanged
  snapshots duplicate-skip, so promotion restores connected prefixes and
  demotion removes them without a full config commit.
- F3: `FibRouteWire` gains `Reject` in Go and Rust; `fib_dump.rs` populates it
  from `RouteEntryV4/V6.reject`; `FormatFIBDump` renders `reject` distinctly
  from `discard`. A reject row no longer prints as `-` / empty next-hops.

## Risk / residuals

- Version bump refuses mixed Go/helper pairs during rolling upgrade until
  both planes deploy at v56; that is the established control-socket contract.
- A peer-owned interface's own host address remains locally deliverable via
  preserved `local_*` state; transit to other addresses in its prefix now
  follows the default/HA/fabric path as intended.
- F1 (kernel Null0 RTN_BLACKHOLE vs RTN_UNREACHABLE) remains undiscriminated
  live; the reject wire now makes the next split FIB dump decisive.
- F4 (exact flowless demote->redirect break) is not separately instrumented;
  this fix removes the connected-shadow path that bypassed the proven chain.
- Failback timing strand (F6) remains under #13058; not addressed here.
- Live acceptance is deferred to the smoke lane after merge: deploy v56 to
  both nodes and re-run `test-v6-na-recovery-12495.sh` in split-RG shape.
