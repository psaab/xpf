# Junos `dynamic hostname` rendered as IKE identity (#14590)

- **Issue**: #14590 — `security ike gateway <g> dynamic hostname <fqdn>` was rendered as `remote_addrs = <fqdn>` (a DNS-resolved dial address) with no remote `id`, so a migrated Junos hub/spoke dynamic-peer tunnel never came up when the peer's name was not in DNS (the normal dynamic-IP case). Junos `dynamic hostname X` is the identifier of a dynamic-IP peer, matched against the spoke's `local-identity hostname X`.
- **Cause**: `compileIKE`/`compileIPsec` set `ResponderOnly` only when no hostname was present, `resolveRemoteAddr` returned `DynamicHostname` as the dial address, the remote `id` came only from an explicit `remote-identity`, the PSK selector fell back to the bare hostname, and `PrepareConfig` DNS-resolved the hostname for a family hint.
- **Change**:
  - `pkg/config/compiler_ipsec.go` (both gateway compilers), `types_security.go`, `schema_security.go`: every `dynamic` block is responder-only; the FQDN is kept in `DynamicHostname` as the expected IKE identity. Schema text now says identity, not DNS-resolved. A DNS-dialed peer remains expressible with gateway `address <fqdn>`.
  - `pkg/ipsec/policy.go`: `resolveRemoteAddr` yields `%any` for responder/dynamic-hostname gateways (even when the compiled flag was not carried); render emits `remote { id = "@<fqdn>" }` when no explicit `remote-identity` is set; `pskIDSelectors` scopes the PSK by `@<fqdn>`; `start_action` is suppressed via the shared `responderOnlyGateway` helper.
  - `pkg/ipsec/ike.go`, `manager.go`: responder DPD (`clear`) and no eager re-initiation for dynamic-hostname gateways via the same helper.
  - `pkg/ipsec/policy_addr.go`: the family hint is pure — literal addresses classify directly, a dynamic identity is family-agnostic (IP literal still classifies) — so the bounded DNS resolver (`resolveHostFamily`, worker pool) is deleted and no DNS runs on the commit/apply path. `prepareConfigFromConfig` replays dynamic gateways from configured addresses again.
  - Updated the tests that pinned the old DNS reading (`TestGenerateConfig_DynamicHostname`, PrepareConfig family tests, #9641 generation row, #14140 reinitiate control, #6469 address-sanitize case, #13540 block forms, `TestIPsecDynamicHostnameNotResponderOnly` → responder) and the `pkg/ipsec/README.md` / `docs/config-schema.md` semantics. New regressions: `pkg/config/compiler_ipsec_dynamic_identity_14590_test.go`, `pkg/ipsec/dynamic_hostname_identity_14590_test.go`.
- **RED**: on the fix branch before the change, `go test ./pkg/config -run '14590'` failed with `ResponderOnly = false, want true` for flat/block/nested/set forms, and `go test ./pkg/ipsec -run '14590'` failed with `tun1.remote_addrs = "branch.example.net", want "%any"` and no remote `id`.
- **GREEN**: `go test ./pkg/ipsec -count=1` passed; `go test ./pkg/config -run '14590|13540|TestIPsecDynamicHostname|TestIPsecResponderOnly|TestCompilerIPsecDynamic|TestSchema3332_DynamicHostname|TestValidateIPsecEndpoints_Reject' -count=1` passed; `go vet ./pkg/ipsec ./pkg/config` passed; `gofmt -l` is clean for touched files (pre-existing unformatted files in `pkg/config` were left untouched).
- **Pre-existing failure (not this change)**: `TestValidateIPsecEndpoints_Accept` fails identically on pristine `origin/master` (`abb8a06c6`) with a #14139 missing-PSK rejection; verified in a separate base worktree.
- **Risk**: an operator who (against Junos semantics) relied on `dynamic hostname` as a DNS dial target must switch to `address <fqdn>`, which renders and dials exactly as before. Bare `dynamic`, fixed-address, and inline-endpoint gateways are unchanged. Live charon proof (`swanctl --list-conns` showing `id: @X`, peer presenting IDi=@X) is lab-bound; the render/compile tests are the gate here.
