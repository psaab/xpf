# Issue #14426 — IS-IS top level, `wide-metrics-only` / `overload` first: trailing authentication dropped

## Why

The IS-IS top loop in `pkg/config/compiler_protocols.go` applied
`expandFlatRun` to `isisNode.Children` only. The packed spelling

```text
protocols { isis wide-metrics-only authentication-key K1 authentication-type md5; }
protocols { isis overload authentication-key K1 authentication-type md5; }
```

packs the whole body onto the `isis` node's own `Keys` with no
`Children`, so the loop saw nothing: `AuthKey`/`AuthType` stayed empty
and `WideMetricsOnly`/`Overload` were lost on a commit reporting
success. FRR renders `area-password` / `domain-password` only when
`AuthKey != ""` (`pkg/frr/protocols_render.go`), so isisd formed
adjacencies authenticated with nothing. `show configuration`
displayed the key written, so nothing looked wrong.

Neither trigger head is admitted in `compactNormalizeInScope`, so the
#8662 fold (keyed on the FIRST tail token) never rescues the run;
`expandFlatRun` on the empty `Children` slice cannot split it either.
The routing-instance spelling shares `compileProtocols`, so the same
drop applied there.

## What

- `pkg/config/compiler_protocols.go` (IS-IS top loop): read the body
  through `packedBodyChildren(isisNode, isisLeafSchema8939())` — the
  schema-driven SSOT the IS-IS interface loop (#14410) already uses —
  before the existing `expandFlatRun`. It returns `Children` unchanged
  when there is no packed tail, so the braced spelling is
  byte-identical. Mixed tail+braced body on the same line (packed tail
  ending in a leaf, where `packedBodyChildren` declines) is detected
  and the tail is expanded from a childless view, reading both halves;
  an unmodelled tail still expands to nothing.
- Preferred reader-side fix over admitting the two
  `("isis","wide-metrics-only"|"overload")` pairs: it covers every
  first head, not just these two. Switch cases, `#8446`
  level/is-type canonicalisation, export, the interface case, and
  router/instance mirrors are otherwise unchanged.
- New regression `pkg/config/protocols_packed_top_dr16h567_test.go`
  (`TestISISPackedTopAuthDR16H5`, shared file name per DR16-H5/H6/H7;
  only the H5 section is added here): braced positive controls, both
  named packed trigger lines, a head-keyword matrix, packed-equals-braced
  field comparison, a mixed packed-line-plus-braced-interface cell, a
  packed-tail-with-braced-body cell, single-flag packed controls (the
  #2419 census single-head rows), and the routing-instance spelling.
- Census: removed the four now-equivalent sites from
  `pkg/config/testdata/compact_block_divergences_2419.txt`
  (`protocols isis overload`, `protocols isis wide-metrics-only`, and
  both routing-instance mirrors) and moved them to `filedFixed` in
  `compact_block_equivalence_2419_test.go`, so the instrument keeps
  checking them in both directions. The regen tool was NOT used: under
  parallel load it also rewrote unrelated churn (`interfaces …
  family inet6 dad-disable/mtu` empty→partial and skip-count drift);
  only the four IS-IS lines were hand-updated, matching the gate's
  equality assertion.

## Validation

- RED on base `9908466d9`: packed trigger cells fail with
  `AuthKey = ""` / `AuthType = ""` / flags false while the braced
  controls carry `K1`/`md5`; the nested flat-run head matrix passed
  pre-fix (already rescued), confirming the defect is the top-node
  packed body.
- GREEN after the fix: `go test ./pkg/config/ -run
  TestISISPackedTopAuthDR16H5` passes all 9 subtests.
- `TestCompactBlockEquivalenceInventory2419`,
  `TestISISInterfacePackedAuthDR13H3`, and
  `TestProtocolAuthFlatRunKeepsEveryLeaf8939` pass;
  `go vet ./pkg/config/` clean; `go test ./pkg/frr/ -run ISIS` passes.
- Full `pkg/config` suite (minus the spelling-differential gates):
  4 failures, all base-attributed at `9908466d9` by re-running them
  with the fix stashed —
  `TestZoneInterfaceBareSt0UnitZeroAlias13110`,
  `TestZoneInterfaceDeclaredDottedAndBareBindCommit13110`,
  `TestZoneInterfaceIPsecBindInterfaceAcceptedWithoutExplicitDef`,
  `TestZoneInterfacePackedApplyMacroOwnKeysCompiles12835`
  (#14139 IPsec PSK gate, unrelated to IS-IS). Identical before/after.
- Fail-on-revert: reverting only the reader change restores the RED
  above (see above); braced controls stay green in both states.

## Risk

- Behaviour delta: packed IS-IS top-level lines now install the flags
  and credentials the operator wrote (previously silently dropped).
  No previously-working spelling changes: braced configs compile
  identically, and an unmodelled packed tail still yields no expansion
  rather than a guessed shape.
