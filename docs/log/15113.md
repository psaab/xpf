# Issue #15113 — Port-mirroring input naming untagged unit 0 mirrors every tagged sibling (A75-01)

## Why

`snapshotLinuxName` collapses an untagged unit 0 (`ge-0/0/1.0`,
VLANID 0) onto the base netdev, so the unit row and the base row
share one ifindex. `buildMirrorConfigSnapshots` keyed the mirror
table by that ifindex alone, and the Rust resolver
(`resolve_mirror_config`) fell back from the logical ifindex to the
bind ifindex. A port-mirroring instance whose input named only
`ge-0/0/1.0` therefore mirrored every tagged sibling unit on the
port (VID 100, other zones / routing-instances) to the analyzer,
while `show` listed only the unit-0 input — breaking the analyzer
confidentiality boundary.

## What

- `pkg/dataplane/userspace/protocol.go`: `MirrorConfigSnapshot`
  gains `ingress_vlan_id` + `unit_scoped` (no omitempty: false/0 is
  the bare-physical answer). `ProtocolVersion` 52 -> 53.
- `pkg/dataplane/userspace/mirrors.go`: the builder records the
  unit scope of the row each input name resolves to (`IsUnit` +
  `VLANID` from the `InterfaceSnapshot`); duplicate-ingress
  ownership is keyed by (ifindex, vlan, unit-scoped) so a bare
  physical input and a unit-0 input on the same ifindex are
  distinct rows.
- `userspace-dp/src/protocol/snapshot.rs` + `control.rs`: mirror
  fields and `CONFIG_SNAPSHOT_PROTOCOL_VERSION` 52 -> 53 in
  lockstep.
- `userspace-dp/src/afxdp/types/forwarding.rs`: new
  `mirror_configs_scoped: FastMap<(i32, u16), MirrorRuntimeConfig>`
  beside the bare `mirror_configs` map.
- `userspace-dp/src/afxdp/forwarding_build/mod.rs`: unit-scoped
  snapshot rows populate the scoped map keyed by
  `(ingress_ifindex, vid)`; bare rows keep the ifindex map.
- `userspace-dp/src/afxdp/mirror/mod.rs`: `resolve_mirror_config`
  consults the scoped map (raw and logical bind keys at the packet
  VID) before the bare fallback. A unit-0 row (VID 0, covering
  untagged/native via the existing VID-0 logical resolution) no
  longer captures VID 100; a bare physical row still matches every
  VID; a tagged-unit row matches only its own VID.

Native-VLAN note: untagged frames on a native-VLAN port arrive
with VID 0, and `ingress_logical_ifindex` already maps
`(parent, 0)` to the native unit, so a unit-0 scoped row keyed at
VID 0 is the correct and only scoped match for that traffic; a
tagged native-VID frame matches a scoped row for that VID if one
was configured.

NOT changed: sampling, output resolution, exclusions, and the
`show` renderers — scope travels with the snapshot row they
already consume.

## Validation

- RED on `origin/master` (ffa933c1aa): Go
  `TestBuildMirrorConfigSnapshotsUnit0VsBarePhysical15113` with
  only the test present fails — tagged and unit-0 rows both come
  back `IngressVLANID:0 UnitScoped:false` (no distinct rows).
- GREEN after the fix: that test plus
  `TestBuildMirrorConfigSnapshots*` and
  `TestConfigSnapshotMirrorConfigsRoundTrip` pass.
- Rust: `unit0_scoped_mirror_does_not_match_tagged_sibling_15113`
  (v28 cell: VID 100 -> None, VID 0 -> Some with a unit-0 row;
  bare-physical and tagged-unit controls) plus existing mirror
  config selection tests.

## Risk

Mixed-version pairing is fenced by the exact-equality protocol
gate (v53): an old helper refuses the snapshot rather than
silently mirroring siblings. No behaviour change for bare
physical inputs or tagged-unit inputs beyond the unit-0 scope.
