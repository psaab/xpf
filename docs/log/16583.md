# #16583 — Non-zero unit with no vlan-id on a tagging parent commits clean (residual of #15034)

## Defect

On a `vlan-tagging` / `flexible-vlan-tagging` parent, a non-zero unit
with no `vlan-id` (or `vlan-id 0`) committed strict-clean:

- `ResolveKernelIfName` (`pkg/config/types.go`) derives
  `kernelBase.<unit.Number>` for `unit.Number > 0` with `VlanID == 0` —
  a device nothing creates (a VLAN child is created only for
  `vlanID > 0`, `pkg/dataplane/compiler_iface.go`).
- `planPhysDesired` (`pkg/dataplane/compiler_iface_desired.go`) unions
  a `vlanID == 0` reference's addresses onto the parent.

So the unit's address lands on the untagged parent wire while its zone
and input filter bind to the never-created `<parent>.<unit>` device:
the filter is installed on no ifindex (the Rust filter compiler skips
`ifindex <= 0` rows) and the subnet is attributed to the parent unit's
zone. The #15034 gate skipped tagging parents outright
(`ifaceTaggingEnabled` short-circuit in
`collectVlanIDTaggingFromInterfacesNode`), so the mirror-image arm
never visited them.

## Fix

`pkg/config/compiler_interfaces_vlan_tagging.go` — the #15034 arm now
applies regardless of parent tagging mode:

- `collectVlanIDTaggingFromInterfacesNode` no longer skips tagging
  parents. The #15034 arm (non-zero unit, no positive tag, no
  tunnel/st/lo/irb exemption) fires on tagging and untagged parents
  alike; only the #14574 arm (positive tag) still keys on tagging —
  with tagging, the tagged child is real and the unit compiles.
- The #15034 message no longer claims the parent "enables neither
  `vlan-tagging` nor `flexible-vlan-tagging`" (false on a tagging
  parent); it names interface and unit, the phantom
  `LinuxIfName(iface).<unit>` device, and the remedy (add a `vlan-id`,
  renumber to unit 0, or remove the unit).

NOT changed: the #14574 positive-tag arm, the exemption list, the
per-node HA-symmetric expansion, and the lenient-warn doctrine
(#1960). No dataplane, wire or snapshot change.

## Risk

Strict commits carrying an untagged non-zero unit on a tagging
ge/xe/ae/reth parent now reject (previously silently mis-zoned with
the input filter armed nowhere). Already-persisted or peer-synced
configs still boot on the lenient path with a `#15034` warning.
Legitimate tagged trunks (every non-zero unit carrying a `vlan-id`,
plus the native unit 0) are unaffected.
