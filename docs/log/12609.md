# Issue #12609 — stop session count walks on cancellation

## Why

Status endpoints and the Prometheus session census walk both session-table families. A disconnected client or expired request must not receive a partial count or retain an admission slot after its own synchronous walk has stopped.

## What

- Added `Manager.SessionCountContext`, which checks cancellation before and between family walks, samples cancellation during iteration, propagates iterator errors, and returns zero totals on failure. The legacy context-free `SessionCount` remains unchanged for existing callers.
- Added a context-aware count path for gRPC `GetStatus`, `show system buffers`, and `buffers-detail`; callers map cancellation/deadline to the corresponding gRPC status and never return partial output.
- Made REST `/status` count with its request context. A canceled request writes no success body; iterator errors remain an error response.
- Added a daemon-level regression for the production `liveDataPlane` → `LegacyDataPlaneAdapter` → `Manager.SessionCountContext` chain using userspace maps and no BPF map creation.
- The metrics collector is registered once with one promhttp handler, preserving the shared in-flight guard. The admission slot is released only when the collector pass returns, not when promhttp's timeout response returns. Census refreshes are detached from the initiating scrape: a timed-out walk completes into the cache, and a healthy singleflight joiner retains access to its result. A canceled waiter still returns `scrape_ok=0` promptly and never receives a result after its own deadline.
- Metrics census iterator errors discard partial counts, leave the last good cache snapshot and its TTL unchanged, and expose `scrape_ok=0` with the session gauges omitted. Iterator errors are observable failures rather than silently ignored; repeated backend iteration errors can therefore make `GetStatus`/the peer probe fail, as they did during concurrent map churn in review testing.

## Validation

Validation for the final rebased head is recorded in the PR description and commit message.

## Risk / residual

Session-count and census cancellation is sampled every 1024 iterator callbacks to limit per-entry overhead. A shared metrics census intentionally continues after the initiating request times out so the next scrape can use its completed cache result; collector slots remain held until those walks return.
