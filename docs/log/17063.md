## Why

38 test call sites went through `resolve_flow_session_decision`, which re-spelled the poll path's DeferredForwardingRevalidation persist block (patched twice, e.g. #14941) and passed `fabric_ingress` for both fabric flags, so `fabric_link_ingress != fabric_ingress` was inexpressible. `_with_conntrack_and_payload`, documented as the production variant, had 1 production caller at the parent (the poll_descriptor fabric-adoption site, `poll_descriptor/mod.rs:4372` at parent); all other production traffic uses `_with_conntrack_and_payload_and_ack`. Assignment deviated from the issue's "keep wrapper" shape per its own instruction: delete the re-spelling, re-point tests at production. The wrapper retained is `#[cfg(test)]`-only, takes an explicit `fabric_link_ingress`, and persists only via the shared helper.

## What

- Extract `pub(in crate::afxdp) fn apply_deferred_forwarding_revalidation(sessions, resolved)` in resolve.rs (including the #14941 `forward_egress_zone_for_hit` mapping); poll_descriptor/mod.rs Owner site and the cfg(test) wrapper both call it. Deleted the inline poll copy and the wrapper copy.
- Move `resolve_flow_session_decision` under `#[cfg(test)]`, add explicit `fabric_link_ingress`, forward to the production `_and_ack` (payload 0, ack None).
- Delete `_with_conntrack_and_payload`; migrate its 9 test call sites + 1 production fabric-adoption site to `_and_ack` with `ack=None`; fix comments naming the wrong production entry point. (Correction: an earlier draft of this log and of the fold-base commit message said "4 test sites + 1 production" and "0 production callers"; the parent counts, verified by `git grep` at `HEAD^`, are 9 test call sites in `session_glue/tests.rs` (7), `poll_descriptor/flow_cache_hit_tests.rs` (1) and `tests_fabric_zone_stamp.rs` (1), plus the 1 production site — 10 call sites total, excluding the definition and the guard's string literal.)
- New tests: `deferred_forwarding_revalidation_persist_is_single_sourced_17063` (structural single-source guard: no `revalidate_forwarding_resolution_with_egress_zone(` / `deferred_forwarding_revalidation.take()` outside the helper across `poll_descriptor/` + `session_glue/`, cfg(test) anchored to the wrapper definition) and `wrapper_drives_fabric_ingress_without_fabric_link_17063` (split-flag: departed-destination conversion fires off-link, anti-loop control on-link, plus the wrapper (true,false) leg paired against its (true,true) control asserting resolved disposition/egress and the persisted session's disposition/egress/zone fields on both legs).
