## Why

38 test call sites went through `resolve_flow_session_decision`, which re-spelled the poll path's DeferredForwardingRevalidation persist block (patched twice, e.g. #14941) and passed `fabric_ingress` for both fabric flags, so `fabric_link_ingress != fabric_ingress` was inexpressible. `_with_conntrack_and_payload`, documented as the production variant, had 0 production callers; production uses `_with_conntrack_and_payload_and_ack`. Assignment deviated from the issue's "keep wrapper" shape per its own instruction: delete the re-spelling, re-point tests at production. The wrapper retained is `#[cfg(test)]`-only, takes an explicit `fabric_link_ingress`, and persists only via the shared helper.

## What

- Extract `pub(in crate::afxdp) fn apply_deferred_forwarding_revalidation(sessions, resolved)` in resolve.rs (including the #14941 `forward_egress_zone_for_hit` mapping); poll_descriptor/mod.rs Owner site and the cfg(test) wrapper both call it. Deleted the inline poll copy and the wrapper copy.
- Move `resolve_flow_session_decision` under `#[cfg(test)]`, add explicit `fabric_link_ingress`, forward to the production `_and_ack` (payload 0, ack None).
- Delete `_with_conntrack_and_payload`; migrate its 4 test sites + 1 production fabric-adoption site to `_and_ack` with `ack=None`; fix comments naming the wrong production entry point.
- New tests: `deferred_forwarding_revalidation_persist_is_single_sourced_17063` (structural single-source guard) and `wrapper_drives_fabric_ingress_without_fabric_link_17063` (split-flag: departed-destination conversion fires off-link, anti-loop control on-link, plus wrapper (true,false) resolves through production).

The only production-visible change is one extra function call on the session-hit Owner path.
