# Parse show-command pipe modifiers exactly (#13202)

- **Issue**: #13202, deep-review finding D10-06 (source report run
  `review-work.tSdtKLhsvV`).
- **Cause**: The remote CLI treated pipe syntax as substrings instead of
  tokens. `show system rollback 1 | display json` fell back to hierarchical
  output, arbitrary tokens containing `compare` could invoke the comparison
  RPC, and config-mode `show interfaces | compare` discarded `interfaces` and
  compared the entire candidate. Matching a supported display substring also
  let trailing garbage through. These cases silently returned successful but
  unintended output or operated on a broader configuration view than asked.
- **Change**: `splitShowPipe` now splits a show request on one standalone pipe
  token and rejects embedded/repeated/missing pipe syntax. `parseShowDisplay`
  accepts only exact supported display token sequences and returns an error for
  unsupported formats or extra tokens. Operational `show configuration` and
  config-mode `show` preserve the path preceding a valid display modifier;
  config-mode comparison requires no path and accepts only exact `compare` or
  `compare rollback <N>`. `show system rollback <N>` accepts only its supported
  `display set`, `display xml`, or exact `compare` pipe forms, and rejects all
  stray tokens before issuing an RPC. Existing positional
  `show system rollback compare <N>` remains supported with strict arity.
- **Regression coverage** (`cmd/cli/show_pipe_modifier_13202_test.go`): recorder
  tests assert no RPC occurs for unsupported formats, arbitrary substring
  tokens, unknown pipe commands, paths combined with compare, and trailing
  tokens. Positive cases verify rollback format/selector and operational or
  candidate config paths and formats.
- **RED evidence**: Before the fix, on fresh `origin/master` at `dd607606a`,
  `GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/var/worktrees/.cache/go-tmp
  go test ./cmd/cli -run 'TestShowPipeModifier' -count=1` failed as expected:
  malformed rollback modifiers and config compare-with-path/trailing-token
  cases returned nil (and some issued RPCs); `show system rollback 1 | display
  json` incorrectly returned a hierarchical-format RPC instead of rejecting
  the unsupported display modifier.
- **GREEN evidence**: After the fix, the same targeted test passes. The CLI
  package suite passes with the repository formatting tripwire excluded:
  `go test ./cmd/cli -count=1 -skip '^TestTreeIsGofmtClean$'` (passed).
  Unfiltered `go test ./cmd/cli -count=1` is blocked only by
  `TestTreeIsGofmtClean`, which reports pre-existing unformatted
  `pkg/config/compact_scope_blind_pairs_8852_test.go` (10 files total in the
  tree; unrelated to this change). `go vet ./cmd/cli` and `go build ./cmd/cli`
  pass; `gofmt -l` on all three changed Go files is empty; `git diff --check`
  passes.
- **Blast radius / risk**: Valid supported display and compare forms retain
  their respective RPC behavior. Malformed/unsupported forms that previously
  succeeded, printed an ad-hoc syntax message, or triggered a broad compare
  now return an error before any RPC, which is intentionally fail-closed.
  No daemon, RPC schema, or unrelated CLI command behavior is changed.
