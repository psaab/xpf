# #14668 — Junos-default QR check on first UDP packet to port 53

## Defect
Junos drops, by default, a first UDP packet to port 53 whose DNS header
has QR=1 (a response where a query is expected): no session is created
and the illegal-packet counter increments. `allow-dns-reply` skips that
check. xpf had no such check: `allow_unsolicited_dns_reply`
(`forwarding/mod.rs`) was keyed on `src_port == 53` and its only
poll-path effect (`dns_reply_fastpath_admit`, poll_descriptor) was to
clear `track_in_userspace` for unsolicited src-port-53 replies. A
same-named knob therefore controlled an unrelated install-skip, a
migrated config's intent was not honoured, and the QR=1-to-port-53
class (reflected responses / response-injection noise) minted sessions
under any permitting policy.

## Fix
- `forwarding/mod.rs`: new `is_dns_query_port_flow` (UDP, dst_port 53).
- `poll_descriptor/mod.rs`: new `dns_illegal_reply_drop` — knob unset
  AND dport-53 UDP AND `dns_reply_qr_set` (the existing #10664
  declared-end-bounded QR reader, so a truncated/unparseable DNS header
  is NOT illegal and takes normal session handling). Enforced at both
  session-miss install legs: the ForwardCandidate Permit arm (before
  NAT allocation / session install) and the MissingNeighbor permit leg
  (before any neighbor-resolution side effect or seed). Policy-denied
  packets are still attributed to policy, not double-counted here.
- Counter plumbing, mirroring the martian-drop class end-to-end:
  `BatchCounters.dns_illegal_reply_dropped` + `record_dns_illegal_reply_drop`
  → `BindingLiveState.dns_illegal_reply_dropped` (one unconditional u64;
  pinned layout offsets +8, size unchanged) → `BindingLiveSnapshot` →
  Rust `BindingStatus.dns_illegal_reply_dropped` (serde default for
  cross-version wire safety) → coordinator copy/reset/zero-unbound →
  Go `BindingStatus.DNSIllegalReplyDropped` → status summary row
  "DNS illegal-reply drops" and Prometheus
  `xpf_userspace_dns_illegal_reply_dropped_total` (descriptor declared
  in `Describe()`).
- The pre-existing src-port-53 sessionless fast path is unchanged and
  remains gated by the same knob; that separation is now documented.
- Docs/schema: `allow-dns-reply` help, `docs/test_env.md`, and
  `docs/xdp-io-uring-userspace-dataplane.md` now describe both
  semantics.

NOT changed: host-inbound/local-delivery handling (the Junos check is
a transit session-miss check; local DNS service traffic is governed by
host-inbound policy), and the src-port-53 fast path itself.
