# Issue #15071: DHCPv6 address-less Renew/Rebind orphans held IA_NA

## Why

A39-06. On a co-held IA_NA+IA_PD client, a Renew/Rebind Reply with a live
IA_PD but no usable IA_NA (IA_NA absent, NoBinding, or only refused
IAADDRs) was accepted as an address-less lease: only an all-zero-lifetime
IA_NA fired `errV6AddrInvalidated`. `commitLease` (post-#14998) removed
the old kernel address and stored the address-less lease, so the client
stopped echoing the IA_NA on subsequent RENEWs, `show dhcp` reported no
address, `finishClient` on stop removed nothing (the stored lease had no
address), and the server could reassign the address while state was
inconsistent. `applyAddress` also installed addresses with no kernel
lifetimes, so any missed `AddrDel` left the WAN address bound forever.

## What

- `pkg/dhcp/dhcpv6.go` (`parseV6ReplyChecked`, `carryForwardV6IANA`,
  `v6IANAStatusCode`, `errV6NoBinding`): `parseV6ReplyChecked` now takes
  the held lease (`prev`, threaded from `doDHCPv6`). When IA_NA was
  requested, no usable IA_NA was selected, and the held address is
  unexpired, the held Address/LeaseTime/Obtained are carried forward so
  the committed lease keeps echoing the binding until valid expiry.
  An IA_NA Status NoBinding returns `errV6NoBinding` (RFC 8415
  §18.2.4); explicit valid-lifetime-0 still returns
  `errV6AddrInvalidated` (#5927/#14998). Run loop: NoBinding at T1/T2
  breaks to re-acquisition (Request) without waiting for T2.
- `pkg/dhcp/lease.go` (`Lease.RemainingLifetimes`, `Lease.ExpiresAt`):
  remaining lifetimes decayed like `DelegatedPrefix.RemainingLifetimes`.
- `pkg/dhcp/dhcp.go` (`applyAddress`, `kernelAddrLifetimes`): DHCP
  addresses are installed via `AddrReplace` with `ValidLft`/
  `PreferedLft` set to the lease's remaining lifetimes (infinite →
  `0xffffffff`), so the kernel expires the address even if userspace
  removal is missed. Stop/abandon/`finishClient` removal is unchanged.
- Tests: `pkg/dhcp/dhcpv6_addressless_15071_test.go` — parse carry-forward
  (absent / refused-only) + NoBinding + explicit-0 controls, expired-held
  no-carry, run-loop next-RENEW echo + stop removal, and the kernel
  lifetime table. NOT changed: DHCPv4, stateless mode, acquisition
  (prev=nil), or the #14997 teardown gate.

## Validation

- RED on pristine master: the new test file fails to compile (undefined
  `errV6NoBinding`/`carryForwardV6IANA`/`kernelAddrLifetimes`/
  `Lease.RemainingLifetimes`; `parseV6ReplyChecked` arity).
- GREEN: `go test ./pkg/dhcp/ -run 15071 -count=1` passes;
  `go test ./pkg/dhcp/ -count=1` passes; `go vet ./pkg/dhcp/` clean.

## Risk

A server that silently omits IA_NA now keeps the held address until its
valid expiry (bounded by the lease deadline context), matching the
#1844 anti-outage rule; NoBinding and explicit-0 still tear down /
re-acquire immediately. Kernel lifetimes make a missed removal
self-healing at expiry instead of permanent.
