# #12658 — post-deploy reassert re-sends a refused RG transfer

- **Timestamp**: 2026-10-13
  - **Why**: Throughput on the loss userspace cluster stopped scaling at about
    6 Gbps (v4 P4 2.23, P16 6.20 Gbps). The cause was the cluster's split-RG
    state, not the dataplane. 3 of the 4 rolling deploys that day left RG2 on
    node1 while RG0 and RG1 were on node0, so every LAN→WAN flow crossed the
    fabric, which runs generic XDP on virtio (#12655). That state came from the
    post-deploy reassert. It sends one transfer per RG. When RG1 lands on a
    freshly cut node0 that has not yet proven XSK liveness, node0 stops being an
    idle standby (`standbyBindingsReadyLocked`). RG2 then reads `userspace XSK
    liveness not proven` for about 2 s, and `RequestPeerFailover` refuses the
    RG2 transfer during that window (fw0 journal: 03:33:05.233 not ready,
    03:33:07.111 ready, no `failover request sent to peer rg=2`). The refusal
    was swallowed (`|| true`), the commit wait only polled, and under
    `preempt=no` nothing moved RG2 back.
  - **What**: Add `deploy_node_rgs_not_role`, the per-RG complement of
    `deploy_node_role_every_rg_ok`. On every commit-wait pass except the last,
    the reassert re-sends `request chassis cluster failover redundancy-group
    <rg> node 0` for each RG node0 does not own yet. Skipping the last pass
    keeps the #7771 ordering: each transfer is followed by a status read before
    the pin-clearing reset. The re-send uses `-n` for the #9683 stdin hazard.
    The mock CLI gains `CLI_STATUS_FN`, which answers a status read from the
    commands issued so far. This lets a transfer land only when it is re-sent,
    which a per-read response queue cannot express.
  - **File(s)**: `test/incus/deploy-lib.sh`, `test/incus/deploy-lib-selftest.sh`,
    `docs/testing.md`, `docs/log/12658.md`.
  - **Validation**:

      the Oct-2 deploys and the 03:25 deploy transferred RG 0/1/2. The 03:33,
      03:40 and 04:02 deploys transferred RG 0/1 only.

      22.1-23.3 Gbps. Split-RG caps at 6.1-6.6 Gbps on both builds. No
      per-packet dataplane regression is in the window.
    - `bash test/incus/deploy-lib-selftest.sh`: 108 passed, 0 failed. Base:
      105 passed. The three new cells are
      `test_rgs_not_role_lists_only_unowned_groups_12658`,
      `test_reassert_resends_a_refused_transfer_12658` and
      `test_reassert_resend_is_bounded_and_ordered_12658`. Mutants: with no
      re-send, the two re-send cells fail (106 passed, 2 failed). With a

      22.11/0; v6 5.59/0, 15.10/0, 21.84/0, 21.80/230. P4/P8 track how many

  - **Risk**: A re-send while a transfer is still committing returns `failover
    already in progress` or `already primary`. Both are swallowed, as before,
    and the verify still decides. The re-send cannot help when node0 never
    becomes takeover-ready inside the transfer budget (15 passes × 2 s). That
    case still dies loudly, with the existing diagnosis.
