# #18055 — Judge communityListRenderable on the sanitized (rendered) form

- **Timestamp**: 2026-10-27T15:57:25Z
  - **Action**: `communityListRenderable`
    (`pkg/frr/policy_render.go`) now judges
    `config.ValidCommunityMember(sanitizeFRRValue(member))` instead of
    the raw member, mirroring the #17839 description fix.
    Previously it judged the RAW member while
    `communityExpandedConjunctionPatterns` (`:282,291`) and the
    per-member branches in `renderCommunityListDefinitions` judge
    `sanitizeFRRValue(member)`. A directly-constructed (typed-config)
    member like `65000:[|\t]` passed the raw check (the tab is not yet
    a space), but sanitization renders it as `65000:[| ]` — a bracket
    expression that can match a space — whose translation is refused,
    so the definition emitted nothing while
    `communityListMissingAtRender` (`:913-919`, via the raw predicate)
    reported it present. A referencing reject term therefore kept
    `match community NEG` under `route-map P deny 10` and dangled
    instead of lowering to deny-all (FRR resolves a dangling match to
    NO MATCH, so the reject never fired — fail-open). Because
    `communityListRenderable` is the single shared predicate for the
    definition loop, `communityListMissingAtRender`,
    `communityDeleteTarget`, `communityListCollision`, and the
    #16835 chain members, judging the sanitized form in that one
    place closes every consumer at once with no drift. Members whose
    sanitized form is unchanged and valid render byte-identically;
    the standard (non-regex) path is unaffected in practice because
    `frrStandardCommunityLiteral` already counts C0/DEL controls as
    separators.
