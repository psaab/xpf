# 14597 — security-log stream fingerprint latched before the build

- **Timestamp**: 2026-10-16
- **Action**: latched the #9326 syslog fingerprint only after a complete build and added an always-on retry owner for skipped streams
- **Base**: `48d282902` at worktree creation, rebased onto current `origin/master` before landing
- **Files**:
  - `pkg/daemon/daemon_system.go` — deferred latch, skip counting, retry-debt arming
  - `pkg/daemon/daemon_syslog_retry_14597.go` — `syslogStreamRetryLoop` / `reassertSyslogOnce` (30 s, `applySem`-guarded, active-config re-read)
  - `pkg/daemon/daemon.go` — `syslogRetryDebt atomic.Bool`
  - `pkg/daemon/daemon_run.go` — unconditional loop start beside the other re-assert owners
  - `pkg/daemon/syslog_udp_bind_latch_14597_test.go` — regression cells
  - `pkg/logging/README.md` — #9326 gate documentation updated

## Why

`applySyslogConfig` latched `syslogHash/syslogHashSet` before constructing
any client. A UDP stream whose `DialUDP` failed — classically
`bind: cannot assign requested address` for a `source-address` naming a
RETH VIP not yet present at the boot apply — was skipped with `continue`,
but the latch already stood. The fingerprint for an explicit
`source-address` is config-only, so when the address later appeared
nothing about the hash changed and every later apply hash-matched and
skipped the rebuild. The audit stream stayed dead until the stanza was
edited or xpfd restarted, with only a single boot-time WARN.

## What

- The fingerprint is computed up front (so a genuine hash-match still
  skips the rebuild) but latched only after `ReplaceSyslogClients`, and
  only when `skipped == 0`. A TCP/TLS client returned alongside an error
  is installed in the reconnecting state (#3351) and counts as built;
  only a nil-client skip leaves the set incomplete.
- An incomplete build leaves the fingerprint unset (the next apply
  retries even with an identical config) and arms `syslogRetryDebt`.
  Event-mode and zero-stream teardowns clear both the fingerprint and
  the debt.
- `syslogStreamRetryLoop` (30 s) re-drives `applySyslogConfig` against
  the active config under `applySem`, re-checking the debt inside the
  semaphore, until a build completes in full. Started unconditionally
  in `Run`; free when nothing is owed (one atomic load per tick).
- NOT changed: `applySystemSyslog` (the `system syslog host` sibling —
  explicitly out of scope), the CLI `buildSyslogClients` mirror (it has
  no latch), and UDP construction itself (no `IP_FREEBIND` — a stream
  must not pretend to forward from an address the node does not own).

## Validation

- RED (pre-fix latch, fix files present): the new cells fail — the
  fingerprint is latched after a skipped build and the recovery apply
  installs 0 clients. (A first RED attempt via the shared `git stash`
  namespace popped a foreign lane's stash into this worktree; those 15
  foreign files were restored untouched and the RED was re-run by
  reverting only `daemon_system.go`.)
- GREEN: `go test ./pkg/daemon/ -run '14597|9326' -count=1` — all five
  #14597 cells plus the six #9326 cells pass, including the #9326
  control that an identical fully built config performs zero rebuilds.
- Affected suites: `pkg/daemon` syslog cells and `pkg/logging` (see PR).

## Risk

A permanently unbuildable stream (bad source address that never
appears) now retries every 30 s instead of once per commit: one WARN
per tick from the existing construction-failure log, and a rebuild of
the sibling streams on each retry. That is the deliberate price of
recovery, bounded by the 30 s cadence the sibling owners use. Fully
built configs are unaffected (zero rebuilds, loop gate is one atomic
load).
