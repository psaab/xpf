# #19131: the #6311 node-namespace source guard anchors symbols, not argument lists

- **Timestamp**: 2026-11-16
- **Action**: Proved the TEST stale before changing it (the user's rule). The
  first-bad commit a60e77bda3 (#17229) deliberately deleted the dead
  `dnat_table` steering subsystem: its message lists "delete ...
  DnatTableFds plumbing". That removed the fifth `WorkerLaunchPlan::new`
  argument the guard pinned in its full argument list. #18640 (0050ac4172)
  respelled another argument later. The #6311 property holds at master
  c61aa074f0, read hop by hop:
  - `spawn_workers(.., snapshot.node_id, ..)` (bringup.rs);
  - `worker_launch_plan(worker_id, node_id, ..)`, #18640's helper;
  - `WorkerLaunchPlan::new(worker_id, node_id, binding_plans, poll_mode)`;
  - `let WorkerLaunchPlan { worker_id, node_id, .. } = plan`
    (worker/loop_body/mod.rs);
  - `setup::worker_loop_setup(worker_id, node_id, ..)`;
  - `sessions.set_session_id_namespace(node_id, worker_id)` (setup.rs).
  So this is a stale anchor, not a regression.
- **Action**: `userspace-dp/tests/session_id_node_namespace_6311_guard.rs`:
  - Each hop is anchored on the symbols that carry the node id
    (`WorkerLaunchPlan::new(worker_id, node_id,`), never on a whole argument
    list.
  - Three hops gain anchors:
    - `worker_launch_plan(worker_id, node_id,`: new since #18640, where a
      hardcoded id would otherwise be silent. A re-anchor alone would leave
      it uncovered;
    - the plan destructure and the `worker_loop_setup(worker_id, node_id,`
      call: listed in the guard's hop comment, never asserted.
  - Every anchor is checked and every missing one reported together (one
    failure no longer hides the hops after it).
  - `normalize` drops whitespace just inside parentheses, so a rustfmt wrap
    reads the same as one line.
