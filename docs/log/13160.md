# Issue #13160: Honor dynamic-address feeds in zone-local books

The D4-01 source finding showed that policy lowering and address-book expansion treated a synthetic `zone-local/<zone>/<name>` token as though it were the dynamic feed's authored name. Dynamic feed overlays and bindings are keyed by `<name>`, so a zone-local address could hide an unready feed, omit live prefixes, or resurrect its static value after a `fail-mode drop` hold-down. That violated fail-closed behavior for policies using the zone-local entry.

Userspace now unqualifies synthetic zone-local names only for dynamic-feed and binding lookups while retaining the qualified key for static address-book resolution. Policy representability, feed expansion, dropped-feed exclusion detection, and concrete-prefix checks share this lookup behavior. This preserves zone-local static scoping while applying the authored feed's ready/unready/drop state.

`TestZoneLocalDynamicAddressFeedContract13160` is a fail-on-revert regression covering the unready-feed policy poison, merge of live feed prefixes into the effective book content, and fail-mode-drop suppression plus rejection for an excluded policy. The same regression failed on the pristine issue branch because an unready zone-local feed produced no policy content rejection.
