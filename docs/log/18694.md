# #18694: lib_fn_mutant truncates at the first column-0 brace

- **Timestamp**: 2026-11-01
- **Action**: Moved the mutant guards into `lib_fn_mutant` itself
  (`test/incus/ha-assurance-selftest.sh`), so every mutant family gets
  them; before, only Group 7's `g7_row_holds_under` (#18690) had them.
  `lib_fn_mutant` now REFUSES, with the reason on stderr, rather than hand
  back a mutant that could score for the wrong reason:
  - **The edit is not exactly once** in the function (as before).
  - **The extraction is not the whole function.** The cut ends at the first
    column-0 `}`, which a heredoc inside the function can contain (#18690 hit
    it on a Python dict). A cut-short mutant fails to source, so a row
    expecting non-zero would be "killed" by the breakage. The check compares
    `declare -f <fn>` of the extracted text against `declare -f <fn>` after
    sourcing the unmodified lib, each in its own subshell. That catches any
    cut-short or mis-cut extraction, whatever the cause, without a second
    parser.
  - **The edited text does not parse** (`bash -n`), or no longer defines
    `<fn>`.

  New reusable pieces:
  - `lib_fn_noop_control` (the same path with the anchor replaced by
    itself).
  - `assert_lib_fn_control_holds`, which runs any row under the no-op
    control and requires it to hold. Group 1 gained a PASS and a FAIL
    control row, and Group 7's two controls now use the helper.
  - `LIB_FN_MUTANT_LIB`, which points the extractor at a fixture lib.

  New selftest rows, against a small fixture lib:
  - `fixture_redefined`, defined twice, is REFUSED with "is not the whole
    function". The cut takes the first definition but the sourced lib keeps
    the last, and that mis-cut PARSES, so only the extent check can refuse
    it. A truncated heredoc also fails `bash -n` (the function body is never
    closed), so this row is what shows the extent check is not redundant.
  - `fixture_heredoc_brace`, a Python heredoc with a column-0 `}` dict close,
    is REFUSED with "is not the whole function". The edit's anchor sits
    inside the cut, so the exactly-once check passes.
  - An unparsable edit to `fixture_plain` is REFUSED with "does not
    parse".
  - A whole function is accepted, its mutant flips, and its no-op control
    holds.

  A census at the end of the run lists every cell built through the
  guarded path and refuses a reused cell name, because a reused name would
  overwrite another cell's mutant file.
- **File(s)**: `test/incus/ha-assurance-selftest.sh`, `docs/log/18694.md`
