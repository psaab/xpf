# 10434 — bind SNMPv3 requests to authoritative and context engine IDs

- **Issue:** #10434 ([049-044] SNMPv3 ignores authoritative + context engine IDs).
- **Branch:** `fix/10434`.
- **Files:** `pkg/snmp/v3.go`, `pkg/snmp/v3_engine_10434_test.go`, `pkg/snmp/v3_timeliness_test.go`, `pkg/snmp/agent_set_test.go`, `pkg/snmp/README.md`.
- **Behavior:** Non-discovery requests whose USM `msgAuthoritativeEngineID` differs from the local engine now receive the RFC 3414 `usmStatsUnknownEngineIDs` Report only when the incoming reportable flag is set; otherwise they are dropped without response reflection. The scopedPDU `contextEngineID` must match the local engine before the empty `contextName` default view is served; foreign context engines use the existing empty-view exceptions. Empty-user engine-ID discovery remains unchanged.
