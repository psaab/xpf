# #13929 — scope userspace local destinations by routing domain

- **Timestamp**: 2026-11-01
- **Action**: Scope local IPv4/IPv6 classifier entries to the ingress routing domain so a foreign-domain local address cannot take the XDP_PASS shortcut.
- **Base**: `origin/master` `d968459ff`
- **Files**: `pkg/dataplane/dataplane.go`, `pkg/dataplane/loader_userspace_shim.go`, `pkg/dataplane/retirement_boundary_canary_test.go`, `pkg/dataplane/userspace/`, `pkg/dataplane/userspace/testdata/contract-9821-declared-snapshot.json`, `userspace-dp/src/afxdp/coordinator/wg_control/`, `userspace-xdp/src/lib.rs`, this log

## Why

Local-destination maps were keyed only by address. When a destination address belonged to a different routing instance than the packet's ingress, the shim treated it as local and passed the packet to the kernel, bypassing the userspace zone-policy path. IPv4 and IPv6 had the same discriminator gap.

## What

- Keyed local IPv4 and IPv6 maps by `(routing_domain, address)` and moved them to distinct pin names so the new key ABI cannot attach to an old address-only pinned map.
- Added a separately pinned ingress-ifindex-to-routing-domain map while preserving the existing ingress-ifaces map's one-byte ABI. The synchronizer reconciles both maps and removes stale domain rows with stale ingress rows.
- Scoped XDP local-destination decisions by the packet's ingress domain. Ambiguous ingress-to-domain mappings do not claim a local address; packet handling continues through userspace policy.
- Updated the userspace dataplane's map readers, pin declarations, and test fixtures to use the same scoped key ABI.
- Added producer and XDP regressions covering same-address IPv4/IPv6 owners in distinct domains, foreign-domain local destinations, and ingress inventory recovery when domain-map publication fails.

## Risk

The local-map key and pin-name change intentionally prevents reuse of legacy address-only maps. The ingress-ifaces pin ABI remains unchanged; domain ownership is carried in its own map. The XDP test-run regression was exercised with BPF privileges; unprivileged runs may skip those tests, while the producer regression runs unprivileged.
