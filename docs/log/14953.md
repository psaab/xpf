# #14953 — `DrainAndConfirm` omitted the pre-demotion `SyncEstablished()` gate (D18-02)

- **Timestamp**: 2026-10-18
  - **Action**: gated `DrainAndConfirm` demotion on `SyncEstablished()`
    before `ForceSecondary()`, mirroring the rolling paths.

    `runRollingWith` and `runRollingRollbackWith` both refuse to drain when
    session sync is not established. `DrainAndConfirm` (the kernel-drain /
    LANE-1 path) checked `PeerAlive`, `HAProtocolCompatible`,
    `SessionSyncWireCompatible` (wire VERSION, not link state) and
    `PeerTakeoverReady` — but never `SyncEstablished`. `parseSyncEstablished`
    fails on `unsynced` / sync-link `Status: Down` even with a healthy
    heartbeat, so a peer that was alive and wire-compatible but not synced
    would be handed every RG by `ForceSecondary`. `DrainComplete` does
    include sync, so the demotion would eventually time out and fail back —
    but only after the node was already demoted into an unsynced peer,
    churning/blackholing stateful sessions for the drain window instead of
    refusing before any demotion.

    The gate is placed after `PeerAlive` and before the HA check, is NOT
    gated behind `allowMixedHA` (that flag relaxes only the exact-equality
    HA check; the rolling sync gate is unconditional), and fails closed:
    a `SyncEstablished` transport error is surfaced as
    `session-sync check: %w` rather than treated as synced.

    Existing `DrainAndConfirm` tests whose fakes modelled a healthy peer
    without setting `synced` were updated to `synced: true` — they now model
    the healthy peer they always claimed to; the peer-not-ready /
    incompatible / timeout behaviours they assert are unchanged (the
    dead-peer case still refuses at `PeerAlive` first).

    Regression (`kernel_drain_sync_gate_14953_test.go`, all four RED
    pre-fix, GREEN post-fix):
    - `TestDrainRefusesUnsyncedPeer14953` — only `SyncEstablished` unhealthy;
      refuses with "session sync not established" and never calls
      `ForceSecondary`.
    - `TestDrainFailsWhenSyncCheckErrors14953` — sync check transport error
      is surfaced, no demotion.
    - `TestAllowMixedHADoesNotBypassSyncGate14953` — `allowMixedHA=true`
      does not bypass the gate.
    - `TestDrainProceedsOnSyncedPeer14953` — paired healthy cell: proceeds,
      demotes, and the `syncPolls` counter proves the gate was consulted
      (catches a dropped call site / unconditional refusal).

    RED evidence (pre-fix, `go test ./pkg/upgrade/ -run 14953 -v`): all four
    fail — "demoted into an unsynced peer", "proceeded when SyncEstablished
    errored", "allowMixedHA bypassed", "never consulted SyncEstablished".
