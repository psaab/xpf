# 16829 — default-instance BGP HA readiness satisfied by another instance's peer

## Summary

#15265 made `GetBGPSummary` query `show bgp vrf all summary json` so
show surfaces list tenant peers, and `GetBGPSummaryVRF(ctx, "")`
delegated to it. HA transfer readiness
(`daemon_ha_routing_readiness.go`) stores the default-instance BGP
requirement with `vrf: ""` and keyed its adjacency map by that empty
key, so a default requirement was judged on peers from *every*
instance. `hasEstablishedAdjacency` checked only neighbor address and
`Established` state — never `BGPPeerSummary.Instance`, which the
parser already stamps. With the same neighbor address configured in
the default instance and a routing-instance on RG interfaces, the
default session down (`Active`) and the tenant session `Established`,
readiness reported ready and a transfer could proceed onto a node
whose default-instance BGP session was down, blackholing RG traffic
until BGP converged.

## Fix

- `pkg/frr/status_parse.go` (`GetBGPSummaryVRF`): no longer delegates
  `vrf == ""` to the `vrf all` `GetBGPSummary`. Every instance now
  goes through `vrfShowCommand`, so `""` issues
  `show bgp summary json` (default only) and `"tenant"` issues
  `show bgp vrf vrf-tenant summary json`. `GetBGPSummary` itself is
  unchanged and still queries `vrf all` for the CLI/REST/gRPC show
  surfaces (#15265 B08-04 not regressed). As defence in depth the
  returned peers are filtered to the requested instance: a peer
  stamped with a different instance is dropped, and unstamped peers
  from a single-VRF reply that omitted `vrfName` are kept (and
  stamped with the queried instance). The parser's ambiguity —
  default peers and vrfName-less peers both carry `Instance == ""` —
  is resolved by treating a payload containing any non-default-stamped
  peer as a multi-instance payload, in which case an empty stamp is
  the default instance, not the queried tenant. The #15265/#16664
  behaviours are preserved: bare names are prefixed exactly once
  (`vrf-cust` → `vrf-vrf-cust`), and `{}`/empty/non-JSON for a
  configured instance is still a fail-closed status error (the
  default path keeps the no-peers/no-error contract).
- `pkg/daemon/daemon_ha_routing_readiness.go`
  (`hasEstablishedAdjacency`): the BGP arm now additionally requires
  `peer.Instance == requirement.vrf`, so even a wrongly-bucketed peer
  cannot satisfy a requirement for another instance, in either
  direction (tenant→default and default→tenant).
- `pkg/frr/README.md`: the #15265 paragraph now notes the
  default-instance-scoped `GetBGPSummaryVRF("")` and the readiness
  instance check (#16829).

## Risk

Only the HA-readiness-scoped query narrows; the operator show
surfaces keep the all-VRF listing. A box whose FRR answers the
default-only `show bgp summary json` with a multi-instance payload
(an FRR behaviour not observed; the JSON shape is corroborated by
the #15265 captures) is still handled by the instance filter plus
the daemon-side `Instance == vrf` check. No live-FRR or failover
test was run — the readiness consequence remains static, as in the
source report.
