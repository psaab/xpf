## Per-call teardown

The control parser accepts a complete 148-byte RFC 2637 type-13 CDN and reads
its PAC-assigned Call ID. The worker resolves that ID under the segment sender's
address and removes both aliases only when the control channel matches and the
association was learned no later than the CDN capture timestamp. The event is
broadcast even if the draining worker has no local association; refused peer
queues retain per-recipient retry state. A reused PAC ID can therefore learn a
new peer Call ID and handle without an old delayed CDN deleting it.

The existing 15-minute bound remains an idle timeout refreshed by data traffic,
not a total association-age cap. It remains fallback cleanup when CDN or
control-channel close is missed.

## Deliberate scope

No total-lifetime cap was added. CDN teardown is per call; FIN/RST cleanup
continues to remove all associations learned on the control channel, and idle
expiry remains independent fallback cleanup.
