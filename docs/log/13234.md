# Issue #13234: Preserve reinject completion overflow

`SocketReinjectSubmitter.DrainReinjectCompletions(max)` read and decoded an
entire completion frame but returned only the first `max` rows. Since the frame
was consumed, any remaining completions disappeared, leaving their pending
leases unresolved until timeout and potentially marking active flows uncertain.

The submitter now retains overflow completions under the completion mutex and
returns them first on later drains. Closing the submitter clears buffered rows.
The new regression test sends one five-row frame, drains it in batches of two,
and asserts all five request IDs arrive in order.

Validation:
- Regression test failed on pristine `9d3869c0e`: second drain was empty.
- Regression test passed after the fix:
  `go test ./pkg/nfqueue -run '^TestDrainReinjectCompletionsRetainsOverflow13234$' -count=1`.
- Full `go test ./pkg/nfqueue` reached unrelated pre-existing environment
  failures: `TestMeasureMemory9506` timed out sending UDP, and Unix socket tests
  failed to bind because generated temp paths exceeded the socket path limit.
  `TestMeasureMemory9506` and
  `TestAnnounceReinjectPublishesPersistentAuthorityFrames9506` were also run
  on pristine `9d3869c0e` and failed identically.
