## Problem, re-verified

`harness-compare` judges the newest run of a gate against a band built from its last three green rows at the same env. Below three it reports NO-BASELINE, which `docs/harness-ledger.md` calls "not a PASS".

At 80db775c4:
- `test-failover` had 62 rows.
- `test-ha-crash` had two rows, one of them with `cells_passed`. `make harness-compare GATE=test-ha-crash ENV=loss-userspace-cluster` on that tree printed `outcome: NO-BASELINE` ("green runs available: 1 (below the K floor)") and exited 2.
- Six other destructive HA smokes had never recorded a row.

The gate table did not say when those six are required, so nobody could tell which gates owe a baseline.

## Change

- **Rows.** Three `make test-ha-crash` runs on the loss userspace cluster, each deployed by `make cluster-deploy` with CoS re-applied, inside a `with-cluster.sh` lock cell:

  | row | ts (UTC) | verdict | cells | exe_scope | exe_check | build_git_sha |
  |---|---|---|---|---|---|---|
  | `99fd854fbcbe8498` | 10:09:07 | PASS | 42 / 0 | both | MATCH | 80db775c4 |
  | `9725f154a13fc476` | 10:19:36 | PASS | 42 / 0 | both | MATCH | 80db775c4-dirty |
  | `ce27d85b57270ddd` | 10:32:55 | PASS | 42 / 0 | both | MATCH | 80db775c4-dirty |

  **Rows 2 and 3 are `-dirty`.** Between run 1 and run 2 I edited `docs/engineering-style.md` in this worktree and had not committed it. `harness_build_git_sha` excludes ledger files from the dirtiness test, so that doc edit is the dirt. `git diff --stat` at the time showed that one Markdown file and nothing else, so no source file differed from 80db775c4.

  Each row's `exe_check=MATCH` attests independently that the running `xpfd` on both nodes was the binary built from that tree. The build sha256 differs between the three rows, so this log does not claim the three runs used byte-identical binaries.
- **Gate table.** `docs/engineering-style.md` now says which HA smoke is required and which is baseline-compared:
  - `make test-failover` and `make test-ha-crash` are required for every HA, VRRP, session-sync or fabric change. Each must keep at least three green both-node-attested rows.
  - Every other destructive HA smoke is required only when a change targets the behaviour it exists for. Each records a row when run, but none is baseline-compared by default, so NO-BASELINE is expected for those rather than a gap.
