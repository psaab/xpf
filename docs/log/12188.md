# #12188 — refuse placeholder archive keyrings in published images

## Why

At base `a714c90d472a3c3d98a3799831cfef3ec311a61c`, the package install rule silently fell back to `.placeholder` when `scripts/dist/xpf-archive-keyring.asc` was absent. A signed, provenance-valid image-only publish did not inspect the guest keyring: a generated qcow containing the placeholder keyring passed the base publisher with exit 0, including image signature/hash, installer signature, provenance/inventory, and `latest.json` gates. The apt package gate could not protect this image-only path.

## What

`debian/rules` now refuses a missing real archive key by default; `XPF_ALLOW_PLACEHOLDER_KEYRING=1` is an explicit dev-only package-build override. Bake reads the installed keyring back from the guest before sealing/signing and rejects missing, non-armored, or marked-placeholder content. Publish independently reads the keyring from every qcow via `virt-filesystems`/`virt-cat`, fails closed on unreadable or invalid content, rejects the placeholder marker, and requires the guest keyring to cover the signed installer's embedded key when present. Shared GnuPG fingerprint parsing uses a private temporary keyring. Regression coverage exercises actual qcow images and image-only publish; distribution, installation, and dist-tool docs describe the contract.

## Validation

- RED-before on base `a714c90d472a3c3d98a3799831cfef3ec311a61c`: the exact rules fallback stanza selected `.placeholder`; a synthetic `.deb` carrying that key was extracted into a qcow; the complete signed/provenance-valid image-only publish exited 0 although `virt-cat` confirmed `PLACEHOLDER-xpf-archive-keyring` in the guest.
- GREEN packaging smoke: extracted current rules recipe refused the absent real key by default; the explicit dev override succeeded and installed the placeholder; a real-path test key was preferred when present.
- `python3 scripts/dist/test_publish_provenance.py -v` — PASS, 20 tests, including valid qcow control, placeholder rejection, invalid-key rejection, and installer-key coverage.
- `sh scripts/dist/selftest.sh` — PASS, 60 passed / 0 failed; includes a signed image-only placeholder-qcow refusal.
- `python3 scripts/image/test_bake_base_pin.py -v` — PASS, 25 tests.
- `python3 scripts/image/test_bake_sign_ordering.py -v` — PASS, 18 tests.
- `python3 scripts/dist/test_dist_resign_9920.py -v` — PASS, 38 tests; `python3 scripts/dist/test_dist_multi_key_rotation_10767.py -v` — PASS, 10 tests; `python3 scripts/dist/test_publish_snapshot.py -v` — PASS, 4 tests.
- `python3 -m py_compile` on changed Python files and `sh -n scripts/dist/selftest.sh` — PASS.

## Risk / residual

The release package build now requires the real archive key drop-in; release builders must provide it. The placeholder override only permits a dev package and does not make its image publishable. Validation used synthetic qcow files and throwaway signing keys; a full production-base image bake and live-cluster validation were not run in this lane.
