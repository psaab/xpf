# #16613: Classed console rendered a missing rollback slot as an empty / `[no changes]` compare

- **Timestamp**: 2026-10-25
- **Action**: The `#15995` console read gates called
  `RollbackCompareSnapshot` / `RollbackSnapshot` and discarded the
  returned `slotErr`, stashing the nil arms with `captured=true`. The
  handlers therefore took the captured branch and rendered the priced
  absence: config-mode `show <path> | compare rollback 40` printed
  nothing, operational `show system rollback 40 <path> | compare`
  printed `[no changes]`, and `show system rollback 40 <path>`
  printed `configuration path not found` — where the unclassed
  console, gRPC (`RollbackSnapshotErr`, `server_config.go`) and REST
  (`api/config.go`) all report the missing slot, per the
  `snapshot_render_15995.go` contract ("gates price a nil snapshot as
  'renders nothing', handlers must still surface the slot error").
  All eight rollback captures in `checkConfigShowRegex` /
  `checkShowSystemConfigRead` (config-mode compare; operational
  `rollback compare N`; `N <path> | compare`; bare `N compare`;
  display-pipe path and whole renders; bare path and whole renders)
  now stash the slot error alongside the priced snapshots
  (`CLI.renderSlotErr16613`, set via `setRenderSnapshots16613`, cleared
  with the snapshots in `dispatch`). The whole-tree gates
  (`rollback compare N`, bare `N compare`, whole display, bare whole)
  return the slot error from the gate itself, before the whole-tree
  authorization that would otherwise mask it with a permission error
  for configuration-restricted classes; the scoped gates stash it and
  each handler (`handleConfigShow` rollback compare, both
  `handleShowSystem` compare arms, the display-format arm and the
  bare render arm) returns it before rendering. Existing-slot renders
  are unchanged (the error is nil and the same snapshots render).
