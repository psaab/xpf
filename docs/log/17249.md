## What

`ConfigFingerprint` now canonically walks exported compiled-config fields instead of using JSON serialization, so `json:"-"` and custom redaction cannot hide runtime-semantic differences. It excludes top-level `Warnings` and the exact documented diagnostic set in `fingerprintIgnore`, then returns only a SHA-256 digest of the canonical values. The digest is not a password-hashing interface and must not be logged or served.

Replaced `json:"-"` with explicit JSON names on `StaticRoute.NoInstall`,
`StaticRoute.HasPreference`, `SystemConfig.NTPPeers`, and
`SystemConfig.NTPPeerOptions`. They are now visible in compiled-config REST
JSON and `ConfigSnapshot.Config`; runtime-semantic hidden fields remain
fingerprint-visible. A recursive inventory pins all remaining exported
JSON-hidden fields reachable from `Config`, independently of the diagnostic
ignore set. The overlapping `NoInstall`/`HasPreference` helper-wire rationale
comments were revised with this change; broader helper-wire rationale cleanup
remains #17244 scope.

`golden_4406.json` is kept to only the intended additions of `NoInstall`,
`HasPreference`, `NTPPeers`, and `NTPPeerOptions` (36 route objects and 24 system
objects in this fixture). The `contract-9821-declared-snapshot.json` fixture is
unchanged: its v77 output drift is pre-existing on master and re-pinning it is
outside this issue's scope.

## Risk

The four explicit JSON tag changes intentionally add fields to compiled-config
and helper JSON; Rust continues to treat `ConfigSnapshot.Config` as opaque under
PR #18335.
The contract snapshot's v77 output drift predates this change and remains
unrebaselined. Fingerprinting includes secret/credential contents before hashing,
so callers must use the digest only for equality and not expose it as a security
primitive. The `golden_4406` change is limited to the four requested field keys;
no unrelated runtime behavior was changed here.
