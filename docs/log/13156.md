# Issue #13156 — accept bare zone aliases for bound tunnel unit zero

## Why

A strict commit rejected a bare `interfaces st0` zone member when the bind-only IPsec tunnel explicitly bound `st0.0`. The bare member must fan down to the tunnel's implicit logical unit zero; rejecting it prevented the configuration from reaching the existing snapshot, ingress-netdev, and unit-override enforcement path.

## What

Allow strict zone-interface validation to recognize `st0` as an alias of a noncolliding, explicitly bound `st0.0` secure-tunnel unit when no `interfaces st0` stanza exists. Keep the ordinary bare-bind check and all nonzero-unit undefined-interface checks intact. The existing `TestBareZoneBindOnlyTunnelHostInbound13100` covers bind spellings, `st0.0` ingress identity, and the unit-specific host-inbound override. Strict and lenient validation tests now explicitly preserve rejection/warning behavior for nonzero `st0.5` binds.

## Risk
