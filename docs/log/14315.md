# Issue #14315 — NAT revalidation bypass for NPTv6 / non-TCP/UDP, false Persistent-NAT revoke

- **Issue:** psaab/xpf#14315 (deep-review D2-04, zone-enforcement-policy-100).
  Lane branch: `fix/14315-campaign` off `origin/master` `5b122dda5`.
- **Files:** `userspace-dp/src/afxdp/poll_descriptor/policy_revalidation.rs`,
  `policy_revalidation_tests.rs`, `poll_descriptor/mod.rs` (one `now_ns` argument).

## Defect (present at base)

`destination_nat_translation_still_valid` returned `true` unconditionally for
`nat64 || nptv6 || !has_l4_ports(protocol)`, and
`source_nat_translation_still_valid` returned `(destination_valid, None)` for
`nat64 || nptv6`. Consequences:

1. A withdrawn/re-scoped ICMP/ICMPv6/GRE/ESP Static-NAT/DNAT translation or any
   NPTv6 prefix translation was never re-checked, so established sessions kept
   supplying the withdrawn post-DNAT `rewrite_dst` to zone policy indefinitely.
2. An inbound Persistent-NAT session (installed via `persistent_inbound_lookup`
   with no static/DNAT entry) failed the destination check on its first stale
   revalidation (Spark lane confirmed code-real; the "100% on any commit"
   wording is narrowed to "when that session is actually revalidated").
3. Counter sub-claim: **refuted as a mechanism** (Spark lane). The
   `*_with_counter_scoped` lookups only clone the matched rule's
   `Arc<NatRuleCounter>`; the revalidation callers discard it and never call
   `.add()`. The fix keeps that property and pins it with a regression test
   instead of switching lookup helpers.

## Change

- Removed the `!has_l4_ports` early return: static/DNAT lookups are
  address-scoped for port-less protocols (static whole-address entries; DNAT
  `PROTO_ANY`/wildcard-port tiers) and never attach a port rewrite to them, so
  ICMP/GRE/ESP translations are revalidated like TCP/UDP.
- `nat64` stays exempt (prefix-driven Pref64, no rule table to consult).
- NPTv6 is re-derived from live state: `translate_inbound_result` on the wire
  destination under the ingress zone must reproduce the stored `rewrite_dst`,
  and `translate_outbound_result` on the original source under the egress zone
  must reproduce the stored `rewrite_src`. `NoMatch`/`Untranslatable` fail
  closed. Neither helper records a translation counter (that side effect stays
  at the packet sites).
- Persistent-NAT: `persistent_nat_destination` mirrors the admission loop in
  `poll_descriptor/mod.rs` — same `persistent_nat && pool_mode` filter, same
  pool-membership pre-filter, same first-match/conflict-denied semantics — via
  read-only `persistent_inbound_lookup`. Threaded `now_ns` from the production
  hit path (`poll_descriptor/mod.rs`) through
  `source_nat_revocation_on_session_hit{,_with_ingress}` into both validators
  (allocators compare lease expiry against it; no wall clock is read).
- `reverse_without_companion_nat64_nptv6_with_provenance_survives_13910` now
  covers the NAT64 shape only; the NPTv6 shape moved to
  `reverse_without_companion_nptv6_rederived_14315`, which asserts fail-closed
  when no live NPTv6 rule re-derives the stored rewrite. The other #13910
  cells (missing provenance) are unchanged and still fail closed.

## Residuals / uncovered

- The counter test pins current read-only behaviour; if a future change makes
  a `*_with_counter_scoped` helper increment on lookup, the test goes RED.
- Persistent-NAT revalidation re-derives permission for the inbound packet's
  remote (`src_ip`/`src_port` of the forward key), exactly as admission does;
  a binding whose permit scope no longer admits that remote fails closed.
