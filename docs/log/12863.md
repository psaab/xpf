# Issue #12863: Preserve junos-host application idle timeouts

## Root cause

The `LocalDelivery` session-install branch already evaluated the `to-zone junos-host` policy and retained matched permit metadata for logging, policy attribution, and counters, but it discarded `PolicyEvaluationResult.inactivity_timeout` and hardcoded `SessionMetadata.inactivity_timeout_ns` to `None`. The session therefore used the global protocol timeout instead of a matched custom application's configured idle timeout.

## Change

- Carry the matched permit's optional application timeout alongside the existing junos-host permit metadata.
- Convert it through `session::app_inactivity_timeout_ns`, using the same bounded seconds-to-nanoseconds conversion as transit permit installs.
- Preserve `None` for no-match/default application timeout and for a configured zero timeout.
- Add a LocalDelivery regression fixture and test covering a 45-second custom app timeout, zero, and unset values. The existing log/policy/counter tests also assert that unset timeouts stay `None`.

The fix only changes metadata for a host-local session admitted by a matching `to-zone junos-host` permit whose application term supplies a positive timeout. It does not alter host-inbound admission, permit/deny decisions, or the fail-closed handling of unmatched policy/application terms.

## Evidence and verification

- RED before the production change: `cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp poll_descriptor_junos_host_permit_stamps_application_inactivity_timeout` failed as intended: actual `None`, expected `Some(45000000000)` for `Some(45)`.
- GREEN after the fix: `cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp afxdp::tests_gre_local_delivery` — 56 passed, 0 failed (all tests in the LocalDelivery/GRE test module).
- `cargo fmt --manifest-path userspace-dp/Cargo.toml -- --check` failed due existing formatting differences across unrelated package files (including baseline regions in the touched files); no package-wide formatting was applied to avoid unrelated changes.

## Risk

Low. The change reuses the existing application-timeout conversion authority and copies the field from the exact policy result already used for other session metadata. Default/no-timeout cases remain `None`; the regression covers positive, zero, and unset values. No kernel datapath code or wire format changes.
