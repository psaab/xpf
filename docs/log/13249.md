# #13249 — avoid needless REST authorization body reads

## Why

`authorizeRESTCommand` parsed the SystemAction body before determining whether
the caller's login class had operational command regexes. This needlessly
consumed and re-decoded request bodies for unrestricted classes. The mutation
guard also deferred body-independent command denials until after its bounded
body drain, allowing a denied caller to make the server buffer input before
receiving the denial.

## What

- Resolve operational login regexes before inspecting request bodies; classes
  with no configured regexes remain unaffected without body reads.
- Evaluate command-regex rules for body-independent mutations during the first
  authorization pass, before buffering. Keep request-decoded routes such as
  `POST /api/v1/system/action` in the existing buffered second pass so the
  command is adjudicated from the exact bytes the handler receives.
- Add regression tests for the no-regex body-read and pre-buffer denial paths.

## Validation

The no-regex case observes two premature reads; the denied ping case observes two reads before its 403.
- **GREEN**: the same targeted command passes on the issue branch.
- `go vet ./pkg/api` and `gofmt -l` on the three changed Go files pass.
- Two full `go test ./pkg/api -count=1` runs both reached `TestVRFOverlapAdmittedEmittedWhenDataplaneUnloaded_7991` and failed because Prometheus `Gather` reports duplicate labels for `xpf_vrf_overlap_pbr_admitted`. **[INFERENCE]** The failure is unrelated to these authorization changes because the touched production code does not modify metric collection.

## Risk

No authorization semantics changed: matching denials remain fail-closed, and
request-decoded command checks continue to use the buffered request bytes.
