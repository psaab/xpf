# #16639: RPM HA gating keyed VIPs by authored string, missing non-canonical IPv6

- **Timestamp**: 2026-10-25
  - **Action**: `rpmProbeTestGating` (pkg/daemon/daemon_rpm.go) built its
    RETH VIP→RG map from the interface address strings as authored
    (prefix stripped, exact string kept) and looked up the RPM test's
    `source-address` string exactly. The interface stanza and the RPM
    stanza are authored independently, so the same IPv6 address
    spelled with different case or zero runs on either side missed;
    an ip-monitoring-referenced test then fell back to the lowest
    data RG (`defaultRG`), so in a split-RG active/active cluster it
    ran only on the node that does not hold the VIP — where the bind
    fails `EADDRNOTAVAIL`/listen and the probe holds as
    `ErrProbeSetup` without a verdict — and was dropped on the node
    that does hold the VIP. That uplink's ip-monitoring failover was
    dead while ownership was split. The same exact-string miss hit a
    `::ffff:a.b.c.d` (4-in-6) spelling against a plain IPv4 VIP or
    vice versa, and an explicit `vrrp-group virtual-address` that
    differs from the unit's own address was never in the map at all.
    Fix (per the issue's fix direction): the VIP map is now keyed by
    `netip.Addr` — `canonicalRPMVIPAddr` parses unit addresses,
    `vrrp-group` virtual-addresses, and the test's `source-address`
    through one helper that strips any `/prefix`, drops any `%zone`
    (the RPM source grammar cannot author a zone: `net.ParseIP`
    rejects one at strict commit and at the probe bind, so a zoned
    source can denote only the same host address), and applies
    `Unmap` so 4-in-6 folds onto IPv4. Empty/unparseable tokens key
    nothing and match nothing, preserving the pre-fix fallback for
    unknown sources. Scoped deliberately to the RPM gating consumer:
    the compiler keeps the operator's authored strings (showing them
    back canonicalised would churn config snapshots/hashes), and
    other VIP derivations (`RethVIPsForRG`, `CollectRethInstances`)
    feed address install where spelling is cosmetic, not a lookup
    key. The pre-existing #15074 `reth*` name filter, per-test
    precedence (destination-interface, then source-address, then
    probe-reference fallback), and the deterministic probe-level
    minimum are unchanged.

    failed with `gating = 1, want 2`, and the strict-compiled
    (configstore commit) cell failed the same way; the
    exact-spelling, IPv4-exact, and unrelated-source controls passed
    pre- and post-fix. GREEN after the fix:
    `go test ./pkg/daemon/ -run 'TestRPMProbeTestGatingCanonical|TestMixedRGProbeGatesPerTest15074|TestProbeLevelGatingControl15074' -count=1`
    PASS (9 gating rows + compiled cell verifying RG2-primary runs
    via-unit + via-vrrp and RG1-primary drops WAN, alongside the
    #15074 mixed-RG suite unchanged). A full `pkg/daemon` run crashes

    (`applySem` nil at `daemon_route_listener.go:353`, `go test`
    195s in) — code this change does not touch; the targeted RPM
    suites above are the exercised verification.
  - **Risk**: Fail-closed direction only: a source spelling that
    denotes a VIP now gates by the VIP owner's RG instead of the
    lowest data RG — the #15074 contract. No test gains gating it
    lacked for a non-VIP source. The `%zone` fold is reachable only
    from hand-built configs (compiler/runtime reject zoned sources),
    where it prevents a gated test from escaping attribution. A
    non-RETH `vrrp-group` VIP and a source spelling that denotes no
    RETH VIP still match nothing — unchanged.
