# 13697 — Reject ineligible embedded IPv6 NAT64 quotes

## Boundary

The ICMPv6-to-ICMPv4 embedded-packet translator resolved and stripped IPv6
extension headers without applying the same RFC 7915 §5.1 eligibility gate as
normal v6-to-v4 translation. This allowed an ICMPv6 error quoting a packet with
an AH header, active Routing header, Mobility, HIP, or Shim6 to produce a
translated IPv4 quote despite the quoted packet being ineligible.

## Fix

- Apply `nat64_v6_translation_ineligible` in `embedded_v6_to_v4_layout`, the
  common embedded-quote layout gate used by the ICMPv6 error translator.
- Add direct quote and whole-message regression coverage for AH, active Routing,
  Mobility, HIP, and Shim6, plus controls proving inert Routing (SL=0), Hop-by-
  Hop, Destination Options, and plain quotes remain translatable.

## RED then GREEN evidence

- RED on the unmodified translator: `cargo test --bin xpf-userspace-dp
  embedded_v6_to_v4_rejects_translation_ineligible_quotes_13697 -- --nocapture`
  failed at `AH-bearing embedded quote must be dropped, not translated`.
- GREEN after the guard: `cargo test --bin xpf-userspace-dp
  nat64::tests::embedded_v6_to_v4_rejects_translation_ineligible_quotes_13697
  -- --nocapture` passed (1 test; 8039 filtered).
- Full NAT64 module: `cargo test --bin xpf-userspace-dp nat64::tests:: --
  --nocapture` passed (205 tests; 7835 filtered).
- The current `origin/master` baseline has an unrelated compile error in
  `afxdp/session_glue/mod.rs:59`: it imports `promote::purge_translated_synced_hit`
  unconditionally, while its definition in `promote.rs:412` is `#[cfg(test)]`.
  To execute these tests, the import was temporarily gated under `cfg(test)` and
  reverted without inclusion in this change. The full binary suite was not run.
