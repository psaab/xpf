# #9505 — RBAC: an anchored deny against a dynamic value is bypassed by an appended word

- **Timestamp**: 2026-09-10
  - **Action**: Measured the population before choosing a fix.
    - `Canonicalize` has one production caller, `evaluateCommandRegex` (the local
      CLI gate).
    - The operational tree has 44 dynamic nodes under 24 parents, plus 4 childless
      placeholders.
    - Handlers split two ways:
      - **Loop parsers**, order-independent: session filter, flow filter/file,
        packet-drop, monitor traffic, show security log, test routing, ping,
        traceroute. ping, traceroute and test routing IGNORE an unknown word; the
        rest reject it.
      - **First-match dispatchers** that drop extra words: show route, show
        interfaces, test security-zone, and others.
  - **Action**: Rejected an evaluation-side fix, i.e. also matching deny against
    a value-truncated string. It cannot tell a junk word from a real option, so
    it either breaks a deny-with-exceptions allow that names options after a
    value, or lets a `.*`-style allow grow on the junk. Took the issue's direction
    instead (one value per slot in `Canonicalize`), with the piece that direction
    lacked: the issue's rule alone would have refused lawful option-list commands
    (`show security flow session zone trust destination-port 22`,
    `ping <host> routing-instance <ri> count 5`) that only resolved through the
    absorption.
  - **File(s)**: none (research)

- **Timestamp**: 2026-09-10
  - **Action**: Folded #9628 into this change, because #9505 alone would have
    WIDENED it. The gate spliced `| suffix` into the words it canonicalized, and
    `|` is not a tree word. The dynamic arm's absorption was what let
    `show interfaces ge-0/0/0 | match x` and `show route table X | match Y`
    resolve, so one value per slot would have refused them too. The fix:
    - The words before the first `|` token are canonicalized alone, and the pipe
      is matched as typed.
    - A first pipe verb outside cliterm.IsPipeFilter (now the single list, which
      SplitPipe uses) or `display` (parsed in-line by handlers) is refused, with
      a message naming the pipe.
    - The pipe-less command is evaluated as a third form, through a variadic
      EvaluateForms under the same max-per-side rule. Without it, the splice fix
      would itself have opened `show version | match .` past `^show version$`,
      which the refusal had been hiding.
