# Gate the screen stages on the ingress zone's own screen state (#12875)

- **Issue**: #12875, research D7-08 (High).
- **Cause**: `stage_screen_check` and `stage_screen_syn_cookie_ack_on_session_miss`
  gated only GLOBALLY (`ScreenState::has_screen_state()` / `has_profiles()` — is
  screening configured ANYWHERE), then resolved the ingress zone and ran
  `extract_screen_info` unconditionally, fail-closing its parse errors
  (#2146/#4167). With a screen profile resolved for one zone, a malformed frame
  ingressing a DIFFERENT zone with no screen configuration at all was recycled
  as an `ip-malformed` screen drop (event + `screen_drops` counter attributed to
  the unscreened zone) and never reached policy. The verdict such a zone deserves
  is `missing_profile_verdict`'s None arm — a silent Pass — so the drop and the
  parse cost were imposed purely by another zone's profile. The #11332 pre-screen
  input-filter walk in `poll_descriptor/mod.rs` had the same global-only gate
  (verdict-only cost, no verdict change).
- **Change**: New `ScreenState::zone_has_screen_state(zone)` — the per-zone
  analogue of `has_screen_state` over the same three sets (resolved profile, or
  an unresolved/inert reference). New `screen_zone_with_state` helper in
  `poll_stages.rs` performs the #3022 logical-ifindex zone resolution and returns
  the `(zone_id, zone_name)` pair ONLY when that zone has state; it keeps the
  #6860 global arm as its fast path so the missing-profile WARN still fires in
  the all-unresolved configuration and a box with no screens stays off the
  resolution path. Both screen stages use it; the session-miss stage keeps its
  documented `has_profiles()` global arm ahead of it. The pre-screen input-filter
  walk is gated on the same helper. Missing/inert reference zones remain
  admitted, so the #7168/#7888 substituted conservative default keeps the
  tolerant doctrines fail-closed, and screened zones keep the #2146 parse-error
  fail-close untouched.
- **Regression coverage** (`userspace-dp/src/afxdp/poll_stages_tests.rs`):
  `screen_parse_fail_on_unscreened_zone_passes_12875` — one screened zone
  (`wan`) + one unscreened zone (`lan`, the fixture's ifindex-24 zone), same
  truncated IPv4 frame: the unscreened zone must return the EXACT
  `Continue(ScreenCheckOutcome::Pass)` variant with no counter and no event on
  both the flowless and the flow-backed arm; screened-zone, unresolved-reference
  (#7168) and inert-reference (#7888) controls keep the drop.
  `syn_cookie_ack_stage_parse_fail_on_unscreened_zone_passes_12875` — same shape
  for `stage_screen_syn_cookie_ack_on_session_miss`, with a screened-zone
  control.
- **RED evidence**: On master (93b4c2b9f) both tests failed at the defect
  assertions — `#12875 flowless: a malformed frame on a zone with NO screen
  state must Continue(Pass)` and `#12875: a malformed session-miss ACK on a zone
  with NO screen state must Continue(Pass)` — because the stages recycled the
  frame (`2 failed; 0 passed`).
- **GREEN evidence**: With the fix both pass. `afxdp::poll_stages` 64/64,
  `screen::` 317/317, `afxdp::poll_descriptor` 254/254, and the full
  `--bin xpf-userspace-dp` suite passed (7832 tests, 8 ignored).
  `rustfmt --check` is clean for every line this change touches (the repository
  has pre-existing rustfmt-version drift unrelated to this change). All
  integration test targets were run `--no-fail-fast`: the
  `frag_assoc_reverse_unreachable_9957` (2 tests), `runtime_view_publish_canary`
  (1) and `vrf_session_identity_doc_guard` (1) failures reproduce IDENTICALLY on
  pristine origin/master 93b4c2b9f (verified in a separate detached worktree),
  so they are pre-existing and unrelated to this change; every other target
  passes.
- **Blast radius / risk**: Only zones with NO screen state anywhere in the three
  sets change behavior: their packets now skip `extract_screen_info` (and its
  fail-close) in the two stages and the verdict-only input-filter re-walk, and
  continue to policy exactly as their screen verdict always said they should.
  Screened, unresolved- and inert-reference zones are byte-for-byte unchanged.
  A pending `syn_alarm_pending` flag set by a screened zone can no longer be
  drained against an unscreened zone's packet/zone (mis-attribution removed; the
  next screened-zone packet drains it).
