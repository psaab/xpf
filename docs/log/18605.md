# #18605 — keep networkd from releasing routing-instance VRF members

- **Branch:** `fix/18605-drive`, based on `d8305e128f606aa9e92641cde4024c52487931e6`.

## Root cause

Networkd renders `KeepMaster=yes` when its managed row has a non-empty
`VRFName`, but the interface model builders only populated it for management
rows. The daemon's routing-instance binder also binds ordinary rows, VLAN and
bridge/bond models, fabric parents, and secure-tunnel units to
`vrf-<instance>`. The tunnel manager independently binds each
`TunnelConfig.RoutingInstance` target, including stanza-only tunnels absent
from the RI interface list. The initial post-build pass missed ordinary
members and blanket-excluded stanza-owned tunnel rows; both lacked the marker
and could be released by networkd reconfigure before rebind repair.

## Change

After all three networkd model builders run in `compileZones`, the compiler
builds a Linux-device-to-VRF lookup from
`RoutingInstanceMemberLinuxNamesForInstance` and explicit interface-/unit-level
tunnel `RoutingInstance` stanzas, then fills empty `VRFName` fields in one pass
over `ManagedInterfaces`. It preserves existing values (including `vrf-mgmt`)
and skips forwarding/reserved RIs, current dual claims, and retained
quarantined device conflicts. Repeating the same RI in a tunnel stanza and RI
list is harmless; different RI claims on one device remain excluded. Removing
the last list or stanza bind drops `KeepMaster=yes` on the next compile.
