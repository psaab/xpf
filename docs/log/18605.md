# #18605 — keep networkd from releasing routing-instance VRF members

- **Branch:** `fix/18605-drive`, based on `d8305e128f606aa9e92641cde4024c52487931e6`.

## Root cause

Networkd renders `KeepMaster=yes` when its managed row has a non-empty
`VRFName`, but the interface model builders only populated `VRFName` for
management-class interfaces. The daemon's routing-instance binder also binds
ordinary rows, VLAN and bridge/bond models, fabric parents, and secure-tunnel
units to `vrf-<instance>`. Those rows therefore had no `KeepMaster=yes`, so a
networkd reconfigure of a member's own files could release its daemon-owned VRF
master before the daemon's rebind pass repaired it.

## Change

After all three networkd model builders run in `compileZones`, the compiler
builds a Linux-device-to-VRF lookup from
`RoutingInstanceMemberLinuxNamesForInstance` and fills empty `VRFName` fields in
one pass over `ManagedInterfaces`. It preserves existing values (including
`vrf-mgmt`) and skips forwarding/reserved RIs, current dual claims, retained
quarantined device conflicts, and tunnel devices explicitly owned by a tunnel
`routing-instance` stanza. A removed membership is absent from the next compile's
fresh model and loses the directive.
