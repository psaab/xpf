# 9955 — model next-table leaks as kernel two-stage rules

## Finding

The userspace helper previously treated `next-table` and rib-group leak rows
as ordinary routes in one prefix-length-sorted table. Linux does not: matching
policy-routing rules run first in ascending rule priority, and a selected table
miss falls through to the next rule before the table-local FIB lookup.

That produced three observable divergences:

1. In the generated overlap matrix, 5 of 10 shapes chose the more-specific
   rib-group row in userspace even though the lower-priority next-table rule won
   in the kernel.
2. A more-specific ordinary route in `inet.0` beat a matching leak in the
   helper, although the kernel leak rule runs before the main-table rule.
3. A leak into an empty table returned `NoRoute` in userspace instead of
   falling through to the ordinary main-table route.

## Implementation

The Go snapshot producer now carries `RouteSnapshot.rule_priority`:

- live netlink rules preserve their actual `Rule.Priority`;
- config-global next-table rows mirror the shared kernel cursor, including
  IPv4-first ordering, default-instance ingress stride, and the rule window cap;
- deduplication, overlays, and learned-route gap coverage distinguish leak rows
  from ordinary rows without dropping a distinct priority candidate.

The snapshot protocol is version 24 on both Go and Rust, and the snapshot-shape
golden was regenerated for the transmitted field on top of v23's DHCPv6 relay
contract.

The Rust builder partitions next-table rows into family-specific,
priority-ordered leak indexes. Ordinary routes remain in the per-table
longest-prefix FIB. Lookup evaluates matching leak rules first; a target table
is consulted with rule evaluation disabled, and a target miss continues to the
next leak and then the source table's ordinary LPM. Bare config targets are
canonicalized to the selected address family.

## Regression and agreement coverage

The Rust `tests_leak_overlap_9955` suite now asserts the corrected outcomes
instead of characterizing the old model:

- 10 generated overlap arrangements: zero kernel/helper divergences;
- leak-before-ordinary precedence: target egress 12;
- empty-target fall-through: main-table egress 14;
- self/cross-table rule misses: `NoRoute`, with no artificial recursion
  terminal;
- v4/v6 target-local destinations preserve `LocalDelivery`;
- a NAT-only target (no connected or ordinary route) still preserves
  `LocalDelivery`;
- a single-leak control remains forwarding.

The Go producer emits a committed 30-row IPv4/IPv6 corpus. A Rust test consumes
that exact JSON and compares production build plus lookup against Go's
independent kernel-stage oracle, including next-rule fall-through and config
priority ordering.
