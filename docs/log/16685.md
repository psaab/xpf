# #16685: peer-slot node-local DHCP/RA members dropped on the peer node

- **Timestamp**: 2026-10-25
- **Action**: A shared-section DHCP group member on the peer node's FPC slot
  (`ge-0/0/3` shared, compiled on node1) was kept by the cluster DHCP filter
  on both nodes: it is not RG-scoped, so the #6520 "node-local is kept
  unconditionally" arm retained it, and the #15206 belt kept it because the
  name is declared (on the peer). Node1 has no `ge-0-0-3` device (its ports
  are `ge-7-0-*`), so Kea refused the whole DHCP family file and the peer
  served nothing — including RETH segments after RG failover, with the
  #6535 converger re-driving the same refused state indefinitely.
  `filterDHCPConfigForMasterRGsWithMasters` (`pkg/daemon/daemon_ha.go`) now
  drops a non-RG member whose `config.InterfaceSlot` maps via
  `config.SlotToNodeID` to a node other than `cfg.Chassis.Cluster.NodeID`
  (`isPeerSlotInterface16685`), setting `MembersFiltered` when a group
  shrinks; a peer-slot-only group disappears entirely. RG-scoped members
  resolve to the local member first, so the test is inert for them, and
  slot-less names (`fxp0`, `fab0`, `lo`, tunnels) are never dropped. The RA
  sibling `clusterRAConfigSets` (`pkg/daemon/daemon_ra_reconcile.go`) applies
  the same rule to node-local RA interfaces, whose sender would otherwise
  fail to bind a nonexistent device on every reconcile. The owning node and
  the `groups nodeN` per-node shape are unchanged.
- **File(s)**: `pkg/daemon/daemon_ha.go`, `pkg/daemon/daemon_ra_reconcile.go`,
  `pkg/daemon/dhcp_peer_slot_16685_test.go` (new), `pkg/daemon/README.md`,
  `docs/log/16685.md`
- **Validation**: targeted `go test -run TestPeerSlot ./pkg/daemon/` plus the
  adjacent DHCP/RA filter suites; see PR body for counts.
