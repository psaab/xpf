# Issue #17802: Same-named IPsec traffic-selector fragments are silently discarded

- **Timestamp**: 2026-10-26
  - **Action**: The run-aware discovery helper deduplicated selectors by `name + strings.Join(node.Keys)`. Reconstructed chained selectors deliberately share only the header keys `traffic-selector <name>`, while their local/remote bodies are children. Distinct same-named fragments in separate packed runs therefore collided before both the compiler and strict validator could see them. Simply returning both would still lose one side because `compileIPsec` creates a new selector per instance and assigns it into `TrafficSelectors[name]`. Discovery now compares recursive selector-body structure, skips only a repeated body, and combines distinct same-named fragments into a normalized copy before either consumer sees them. The existing strict gates then reject an invalid second value (#4098) or conflicting repeated side (#5692).
  - **File(s)**: `pkg/config/compiler_ipsec_trafficselector_run_16759.go`, `pkg/config/compiler_ipsec_ts_chained_16759_test.go`, `debian/changelog`, `docs/log/17802.md`
  - **Validation**: Pre-fix RED: `go test ./pkg/config -run 'TestIPsecChainedTrafficSelectorCompiles16759/(same-named_chained_fragments_across_runs_merge|direct_plus_chained_same-named_fragments_merge|chained_plus_direct_same-named_fragments_merge)$' -count=1` failed all three merge cases on the original name/header-key dedup. Revert check: restoring the original dedup and rerunning the full config suite reproduced those merge failures plus acceptance of the invalid second body (#4098) and conflicting second body (#5692). Post-fix GREEN: `go test ./pkg/config -run 'TestIPsecChainedTrafficSelector(Compiles|Validated)16759' -count=1` passed, including exact-duplicate and distinct-name controls; `go test ./pkg/ipsec/ -count=1` passed. `go test ./pkg/config/ -count=1` fails on unrelated existing #2419/#8690 inventories, golden drift, WireGuard/NAT source-pool/RETH/VRRP/DR15H3 cases, and the dual-AST reflection panic; these failures repeated with the original dedup restored, while the restore run additionally failed only the new #17802 regressions.
  - **Risk**: Same-named fragments that previously vanished now contribute their authored selector sides; a conflicting repeated local/remote value is rejected by the existing strict gate instead of being silently overwritten. Exact repeated bodies still deduplicate. No schema or wire-format change.

- **Timestamp**: 2026-10-26
  - **Action**: Corrected the #17802 fragment equality check to ignore only the selector-root wrapper spelling (`traffic-selector <name>` versus the named property node) while retaining exact body keys, values, leaf multiplicity, and child order. Identical bodies now deduplicate instead of concatenating duplicate leaves and failing #5692.
