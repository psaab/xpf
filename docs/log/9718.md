  - The failure was an import published after preserved-session replay read the

- **Action**: design pivot.
  - Direction 1 briefly used a coordinator-side `Untracked` reservation gated
    by session-map publication. It was rejected after tracing three ownership
    races: a delete can free a coordinator hold while a worker adopts a queued
    upsert; tunnel-remap purge can lose its single release/count owner; and stop
    teardown can clear workers after a queue snapshot, leaving stale or
    pre-adoption holds. These paths make release/accounting less reliable than
    the original missed-reservation bug.
  - Direction 2 keeps every translated-port hold worker-owned. The import path
    reloads the worker set after publishing shared authority, covering a worker
    that registers during the import. Bring-up registers the worker, takes a
    queue-guarded authoritative shared snapshot, and enqueues late
    `UpsertSynced` entries, covering an import published before registration.
    A startup barrier prevents the worker poll loop from draining the initial
    replay queue before late reconciliation completes.
- **Action**: P1 review fold.
  - The late reconciler now wraps every appended shared entry with
    `synced_replica_entry`, preserving `worker_replica_origin` semantics.
    This is required because `SharedPromote` is not `is_peer_synced`, while its
    worker replica is `WorkerLocalImport` and must reserve the translated port.
  - A fail-on-revert SharedPromote cell seeds an imported row with a live
    session id and close class, invokes production
    `maybe_promote_synced_session`, asserts its metadata/id/class output, then
    drives the late reconciler and real worker command handler. Removing the
    mapping was RED (1 failed, `artifact://21762`); restoring it was GREEN
    (1 passed, `artifact://21779`).
  - The interleaving cell intentionally binds the late helper directly so it
    can deterministically inspect and drain the registered worker queue. It
    does not claim to bind the `spawn_workers` call-site or the import-side
    post-publish reload; those halves are documented as an ordering argument:
    import reload covers registration-before-publication, while spawn-success
    registration followed by late reconciliation covers
    publication-before-registration, and the startup barrier orders polling.
