# Cluster failover-hold follow-ups #10244 and #10245

## #10244 — incarnation-bound hold restore and reservation ownership

The restore snapshot now carries the `*RedundancyGroupState` pointer captured
under `m.mu`. Abort restore requires the live map entry to be the same pointer,
so a same-ID remove+re-add with generation 0 cannot receive the old
incarnation's hold. `failoverInProgress` is now a per-RG non-zero owner token;
all ManualFailover, ManualFailoverBatch, RequestPeerFailover, and
RequestPeerFailoverBatch cleanup is delete-only-if-token-match. The config
purge still clears the per-RG reservation and generation maps.

RED evidence (source reverted to the pre-fix implementation while retaining
the regression tests):

- `TestRequestPeerFailoverReaddSkipsStaleHoldRestore10244`: failed with the
  fresh RG held, the old `ManualFailoverAt` restored, and
  `State=secondary-hold`.
- `TestRequestPeerFailoverBatchReaddSkipsStaleHoldRestore10244`: failed for
  both re-added RGs with the stale hold, timestamp, and secondary-hold state.
- `TestRequestPeerFailoverReaddPreservesNewReservation10244`: failed because
  the new reservation was missing after the old request returned; an
  overlapping peer request reached the send hook and ManualFailover was
  admitted.

GREEN evidence with the fix restored:

- `go test ./pkg/cluster -run 'TestRequestPeerFailover(ReaddSkipsStaleHoldRestore|BatchReaddSkipsStaleHoldRestore|ReaddPreservesNewReservation)10244' -count=1`
  passed.
- The complete issue matrix below passed, including all three #10244
  regressions.

## #10245 — stacked ForceSecondary → ManualFailover weight pin

Hold snapshots now determine `restoreWeight` by comparing the captured weight
to the monitor-debt-derived weight under `m.mu`, rather than by requiring the
captured state to be `StateSecondary`. This restores a ForceSecondary-origin
pin after the stacked `ForceSecondary → ManualFailover → failed
RequestPeerFailover` sequence, while equal debt-derived weights remain
unrestored.

RED evidence (source reverted to the pre-fix predicate):

- `TestRequestPeerFailoverStackedForceSecondaryManualFailoverRestoresWeight10245`:
  failed with `stacked ForceSecondary weight = 255 after failed transfer, want
  pinned 0`.

GREEN evidence with the fix restored:

- `go test ./pkg/cluster -run '^TestRequestPeerFailoverStackedForceSecondaryManualFailoverRestoresWeight10245$' -count=1`
  passed.
