# 12191 — refresh stored AppID labels after policy revalidation

- **Timestamp**: 2026-10-08
- **Action**: refresh the conntrack AppID label after a stale established session is permitted by live zone-policy revalidation.
- **Files**: `userspace-dp/src/afxdp/{bpf_map,poll_descriptor,session_glue}/**`, `pkg/appid/runtime_test.go`, this record.

## Why

Conntrack stores the AppID resolved when a session is created, while RT_FLOW create/close labels and application filters use the current application catalog. After an application redefinition without `PolicyRematch`, live TCP/443 sessions could therefore be shown/cleared as A while close events resolved B. The affected flow is the AppID-enabled stale-session path.

## What

- On a stale established-session hit, restamp only after the zone-policy revalidation PERMIT has made the session fresh. Deny, decline, fresh-hit, and failed-update paths do not affect the forwarding verdict.
- Update only the conntrack `app_id` field with a read/modify/write for IPv4 and IPv6 rows, preserving counters, timestamps, NAT state, and session ID.
- Add a stale TCP/443 A-to-B regression for the permit path, an RT_FLOW create/close regression that checks A/B labels share one session ID, and Go coverage for show/clear filtering before and after the stored-ID update.
