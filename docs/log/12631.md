# #12631 — NAT broken `off` exemptions over-exempt consistently

- **Timestamp**: 2026-10-13
- **Base**: `947cff95bc703afdb965188a555288add4b2ee5c`

## Decision

Broken exemptions over-exempt. An `off` rule exists to prevent translation; silently narrowing its exemption (or making it never match) can pass traffic into a later translator and violates the #3844/#9877 exemption doctrine. This unifies the #12440 protocol-less-app behavior with the #3434/#11587 sentinel backstops for SNAT and DNAT. A broken **translate** rule continues to use the established never-match/fail-closed behavior; the decision is specific to exemptions.

Over-exemption affects only the broken application or port axis. Authored addresses, zones/interfaces/routing-instance scope, and rule ordering remain unchanged. Where the broken reference itself is a union member, its over-exempting match-all term makes the union match-all on the application axis. Valid protocol-less ported exemptions keep their existing port bounds (including DNAT tcp/udp rows).

## Change

- SNAT `off` snapshots replace broken application references / dropped application constraints with `natProtoAny` and remove impossible application-port sentinels; an invalid rule-level destination-port sentinel is removed for exemptions. Broken translates still receive `natProtoNever` or impossible port ranges.
- DNAT `off` snapshots turn unresolved or dropped-constraint application members into unconstrained terms and ignore unrepresentable source-/destination-port constraints. Broken translates retain the #3434/#11587 never-match rows or existing no-entry behavior.
- Existing and new warnings retain rule/reference context; the SNAT builder warns when an exemption's application reference is over-exempted.
- Added SNAT/DNAT parity cells for dangling and mixed references, dropped ICMP application constraints, invalid destination ports, protocol-less ported exemptions, address-scope preservation, and translate-rule controls.

## Risk / residual

- A malformed off match can exempt more traffic than the operator's authored (but malformed) constraint intended. This is deliberate: the known intent is to exempt, and narrowing the exemption risks later translation. The warning and strict commit validation make the error actionable.
- Other valid match axes still bound the exemption; the change does not turn unrelated rules into match-all rules.
- No live-cluster validation was performed.
