## Why

`remove_persistent_lease` removed the lease and its reverse-index owner but retained `persistent_permissions[key]`. When the same endpoint-independent source key was recreated after expiry for a different remote, the new grant was added to the stale permission set. Inbound lookup therefore continued admitting the old remote under the replacement lease.

## What

Remove a lease's permission set whenever its lease record is removed. Add an expiry-and-recreation regression that requires the old remote to be denied and the new remote to remain admitted.

## Validation

The new `expired_lease_recreation_drops_obsolete_remote_permissions_14113` regression failed before the fix (`Permitted` for the old remote instead of `Denied`) and passed afterward. The full `nat::tests_idle_lease_sync_8121` module ran 52 passed and 3 failed on the issue branch; pristine master `e0c8e99` ran 51 passed and the same 3 failed: `address_only_idle_owner_index_tracks_import_and_rollback_11496`, `an_address_only_import_refuses_live_reverse_identity_contention_11475`, and `expired_idle_lease_does_not_block_import_13692`.
