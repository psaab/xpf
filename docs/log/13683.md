# Issue #13683 — retain HA tombstones for unresolved sessions

## Why

The paged owner-RG export includes `NoRoute` and `MissingNeighbor` sessions,
but terminal removal only queued tombstones for `ForwardCandidate` and
`FabricRedirect`. If either unresolved session was removed after the export
kick and before the cursor visited its slot, the peer kept a zombie open
because the cursor could no longer see the removed entry.

## What

`remove_entry` now uses the same four forwarding dispositions as the owner-RG
export walk when deciding whether a terminal removal needs an export tombstone.
`Replace` and `Transfer` remain excluded; they do not remove the logical
session. The existing `take_tombstones_for_export` owner-RG/epoch filters and
backpressure requeue behavior are unchanged; newly admitted tombstones now reach
that consumer for both unresolved dispositions.

Regression coverage checks identity and disposition for all four exportable
dispositions, verifies each tombstone drains once, and confirms a policy-denied
entry does not create a tombstone.

## Validation

- **RED before fix:**
  `cargo test --manifest-path userspace-dp/Cargo.toml terminal_removal_harvests_tombstones_for_unresolved -- --nocapture`
  failed because the `NoRoute` removal yielded an empty tombstone list.
- **RED on revert:** temporarily removing the `NoRoute` and `MissingNeighbor`
  arms made the new exportable-dispositions test fail with an empty `NoRoute`
  tombstone list.
- **GREEN:** the regression test passed after restoring the fix; the complete
  `session::lookup::export_unresolved_sessions_10790_tests` module passed
  (3 tests), and `cargo check --manifest-path userspace-dp/Cargo.toml` passed.
- **Full crate suite:** `cargo test --manifest-path userspace-dp/Cargo.toml`
  reported 8050 passed, 4 failed, and 8 ignored. Failures were in
  `f035_parked_fragment_overlap_is_rechecked_on_retry_10659`, two
  `tests_gre_local_delivery` cases, and
  `c3_forward_control_survives_full_window_per_permit_shape_10591`; all are
  outside the session tombstone code changed here.

## Risk

The existing bounded tombstone cap, export-window filters, and callback-failure
retry behavior are unchanged. The incremental Close path remains as before; the
change adds the missing repair close to the active paged export for unresolved
sessions removed after its kick.
