# 10289 — Reject unsupported DNAT address ranges

## Boundary

A destination-NAT pool is carried to the userspace dataplane as one translated
host address. The parser accepted every token after `address` and assigned the
address repeatedly, so `address 10.1.0.1 to 10.1.0.9`, bracket lists, and other
multi-token values collapsed silently to `10.1.0.9`. Strict validation then saw
a valid host and the snapshot builder installed that final endpoint.

Destination-NAT has no range representation in its snapshot/wire field, so this
issue uses the accepted strict-reject path rather than inventing range semantics.
Single-host addresses and the existing nested `address <host> port <N>` spelling
remain unchanged.

## Fix

- `parseDNATPoolAddress` now collects non-port address tokens, preserves the
  complete multi-token sequence in `NATPool.Address` and the compile-only
  `AddressInvalidSpec` marker, and never collapses a range to its last token.
- `validateDNATPoolStrict` rejects `address A to B` with a named `address range`
  diagnostic, while bracket-list and other extra-token forms receive a named
  `multi-address value` diagnostic.
- `DestinationNATRuleExcludedReason` shares the marker verdict, so the snapshot
  builder publishes no DNAT entry for a tolerant-load range instead of installing
  the final endpoint.
- Single-address replacement clears an earlier marker; port-only leaves preserve
  it. Repeated named-pool block merging updates the address and marker together.
- The source-pool axis-sweep registry records the new DNAT-only compile marker as
  constant for source pools, preserving the existing sweep's completeness gate.

## RED then GREEN evidence

- RED: before the implementation,
  `go test ./pkg/config -run 'TestDNATPool(AddressRangeRejectedAtCommit10289|SingleAddressStillCompiles10289)' -count=1 -v`
  failed all three multi-token cases because strict compilation accepted each
  input after collapsing it to the final token.
- GREEN: after the implementation, the issue-focused config set passed the
  range, bracket-list, unexpected-token, single-host, twin-leaf overwrite, and
  repeated-block merge cases.
- GREEN: `go test ./pkg/dataplane/userspace -run TestDNATPoolAddressRangeFailsClosedInSnapshot10289 -count=1 -v`
  compiled the actual tolerant `address A to B` tree, emitted no range snapshot,
  and passed the single-host one-entry control.

## Non-overlap

- #3450 validates DNAT pool host/port scalar values and remains the base
  fail-closed path; #10289 adds the missing multi-token preservation channel.
- #7143 is the generic multi-value slot escape class; its DNAT-pool candidate
  was explicitly refuted in its closing comment, while this issue reproduces a
  concrete parser collapse.
- #9988 concerns nonnumeric static-NAT match destination ports and does not
  share the DNAT pool parser or snapshot field.
