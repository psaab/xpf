# Align PSK selector identity keys with strongSwan (#18428)

- **Timestamp**: 2026-10-29
- **Action**: Reworked rendered-selector identity keying to match the installed strongSwan 6.1.0-2 parser and equality rules. This oracle supersedes the earlier assumptions about invalid key-id hex, DN escaping/space folding, and domain-only RFC822 comparison.
- **Files**:
  - `pkg/config/compiler_ipsec_psk_identity_collision_17772.go`
  - `pkg/config/compiler_ipsec_psk_owner_collision_17772_test.go`
  - `pkg/ipsec/policy_psk_identity_collision_17772_test.go`
  - `docs/config-schema.md`
  - `docs/log/18428.md`
- **Issue**: #18428, security.
- **Cause**: The rendered-selector key implementation still approximated strongSwan differently: invalid `@#` nibbles were treated as literal text, DN parsing assumed escape/multi-valued syntax and Unicode/whitespace folding, RFC822 preserved local-part case, and `@` prefixes were handled before DN-syntax fallback. These mismatches could both miss real collisions and reject distinct peer identities.
- **Change**:
  - `@#` values now mirror `chunk_from_hex()`: lowercase `0x` is stripped, colons are ignored, invalid nibbles become zero, and odd nibbles are left-padded. Keys compare decoded bytes with length-sensitive equality (`zz` = `00`, but not `0000`; `7a7` = `07a7`, but not `376137`).
  - DN keys recognize strongSwan `atodn()` attribute names and aliases. PrintableString attributes and emailAddress compare ASCII-case-insensitively; UTF8String and other IA5 values remain byte-sensitive. RDN order is normalized, while `+` and backslash remain ordinary value bytes, internal spaces are preserved, and unknown/numeric-OID attributes fall back to raw literal KEY_ID bytes.
  - RFC822 aliases compare the whole address with ASCII case-insensitivity, including the local part. DN-syntax detection precedes rendered `@`/`@#` parsing. Authored selectors and swanctl rendering remain unchanged.
- **Regression coverage**: `TestIPsecPSKOwnerCollision17772` and `TestPSKIdentityCollisionRender17772` cover the original eight cross-type pairs plus DN-before-prefix fallback, chunk decoding and length, supported DN aliases/types, unsupported DN fallback, whole-address RFC822 case, and distinct-identity controls. Renderer checks retain unrelated VPNs and keep same-PSK exemptions.
- **RED/GREEN and fail-on-revert**:
  - Temporarily restoring declared-type keying made the focused tests fail for canonical DN spellings, decoded key-id variants, RFC822 aliases, and all cross-type rendered-owner collisions; the renderer emitted both conflicting owners.
  - After restoring strongSwan-parsed selector keys, `GOTMPDIR=/tmp GOCACHE=/var/worktrees/.cache/go-build go test ./pkg/config ./pkg/ipsec -run '^(TestIPsecPSKOwnerCollision17772|TestPSKIdentityCollisionRender17772)$' -count=1` passed in both packages.
- **Risk**: Strict validation now rejects distinct PSK connections only when their parsed strongSwan owner identities collide (subject to the existing same-effective-PSK exemption); tolerant rendering still skips only affected groups. No selector output or PSK diagnostic content changes.
