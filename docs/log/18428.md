# Align PSK selector identity keys with strongSwan (#18428)

- **Timestamp**: 2026-10-29
- **Action**: Matched rendered-selector identity comparison to the installed strongSwan 6.1.0-2 oracle. Corrected source-confirmed colon/DN behavior and byte-wise ASCII folding so non-ASCII UTF-8 continuation bytes are compared rather than skipped.

- **Issue**: #18428, security.
- **Cause**: The previous parser skipped every key-id colon, demoted a terminal-backslash DN to KEY_ID, compared DN spellings through a single flattened key, and did not match strongSwan’s remaining typed identity forms.
- **Change**:
  - `chunk_from_hex()` sizes after excluding all colons, fills from the right, and skips at most one colon before each low nibble. `7a::7a` decodes to `a07a`; invalid nibbles remain zero and byte length remains significant.
  - Textual `atodn()` selectors become type-9 DER, using the source-order RDN sequence and only the supported named attributes. A leading-space slash still selects slash delimiters; whitespace ends the attribute token; `+` and backslash remain ordinary value bytes. A terminal backslash is a DN value, not a KEY_ID fallback.
  - Type-9 `compare_dn()` comparison is pairwise: OID and value length must match; PrintableString values fold ASCII case only when both tags match, and emailAddress IA5 values also fold. Other values compare bytes even across different tags. This relation is non-transitive, so collision detection compares candidate identities pairwise rather than grouping them by one normalized key.
  - Untyped CIDRs use masked network bytes plus netmask bytes; untyped address ranges use ordered endpoint bytes as type 7/8. `uri:` uses type 201; `xmppaddr:` is wrapped as a type-10 GeneralName; numeric type prefixes follow `strtoul()` and 32-bit ID enum conversion, with type 0 equality ignoring identity encoding. FQDN and RFC822 identities fold ASCII letters only, with RFC822 comparison covering the whole address; non-ASCII bytes remain unchanged.
- **Oracle evidence** (type and exact `get_encoding()` bytes from libstrongswan 6.1.0-2):
  - F1: `@#7a::7a` = type 11 `a07a`, equal to `@#a07a`; it differs from `@#7a7a` (type 11 `7a7a`).
  - F2: `CN=peer\` = type 9 `3010310e300c06035504030c05706565725c`; `CN=PEER\` = type 9 `3010310e300c06035504030c05504545525c` (not equal). `keyid:#434e3d706565725c` is type 11 and is also distinct.
  - F3: textual `CN=peer` is type 9 `300f310d300b0603550403130470656572`, equal to both `asn1dn:#300f310d300b0603550403130470656572` and `{9}:#` with those bytes. Cross-tag equal-byte values compare equal, while differing UTF8String bytes do not; `asn1dn:#3000` equals identical malformed DER but differs from `asn1dn:#3001`.
  - F4: untyped `198.51.100.0/24` and `.1/24` both produce type 4 `c6336400ffffff00`, equal to `ipv4net:#c6336400ffffff00`; host IP `198.51.100.0` is type 1 and distinct.
  - F5: `uri:Peer` is type 201 `50656572`, equal to `{201}:Peer` and distinct from `{12}:Peer`.
  - F6: `xmppaddr:peer` is type 10 `a01206082b06010505070805a0060c0470656572`, equal to the matching `asn1gn:#` selector.
  - F7: `{+2}:peer`, `{ 2}:peer`, `{0x2}:peer`, and `{4294967298}:peer` are type 2 `70656572`; `{4294967297}:peer` and `{-4294967294}:peer` truncate to types 1 and 2 respectively; `{-1}:peer` equals `{4294967295}:peer` (type -1).
  - Numeric fallbacks: `{08}:peer` and `{18446744073709551617}:peer` are type-11 literal KEY_ID bytes; the latter overflows `strtoul`.
  - F8: ` /CN=peer/O=Org` and `/CN=PEER/O=ORG` produce equal type-9 DER. `CN=peer,O other=thing` and `CN=PEER,O=other=thing` also produce equal type-9 DER.
  - Controls: `zz` = `00` (type 11 `00`) but differs from `0000`; `0x7a7a` = `7a7a`; `7a:7a` = `7a7a`; `7a7` = `07a7`; reversed RDN order remains distinct.
  - G1: `organizationIdentifier=Peer` is type 9 `300f310d300b0603550461130450656572`, equals its lowercase spelling and matching `asn1dn:#` selector.
  - G2: `198.51.100.1-198.51.100.2` is type 7 `c6336401c6336402`; `2001:db8::1-2001:db8::2` is type 8 `20010db800000000000000000000000120010db8000000000000000000000002`. Reversed IPv4 ranges fall back to FQDN; hyphenated hostnames remain FQDN.
  - G3: `{0}:a` (type 0, encoding `61`) equals `{0}:b` (encoding `62`), and `{4294967296}:x` also wraps to type 0 and equals other type-0 identities.
  - G4: `{}` selects type 0: `{}:a` (encoding `61`) equals `{0}:a`, and `{}:b` (encoding `62`) equals it by ID_ANY semantics. `{ }:a` remains literal type 11 and is distinct.
  - G5: IPv4 `/24junk`, `/024`, `/+24`, and `/ 24` all encode type 4 `c6336400ffffff00` and equal `/24`; an empty suffix is `/0`. IPv6 `/64junk` encodes type 6 `20010db8000000000000000000000000ffffffffffffffff0000000000000000`. Negative and out-of-family lengths fall back to literal FQDN/KEY_ID.
