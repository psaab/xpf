# Align PSK selector identity keys with strongSwan (#18428)

- **Timestamp**: 2026-10-29
- **Action**: Reworked rendered-selector identity keying to match the installed strongSwan 6.1.0-2 parser and equality rules, including explicit named/numeric type prefixes. This oracle supersedes earlier assumptions about invalid key-id hex, DN escaping/space folding, and domain-only RFC822 comparison.
- **Files**:
  - `pkg/config/compiler_ipsec_psk_identity_collision_17772.go`
  - `pkg/config/compiler_ipsec_psk_owner_collision_17772_test.go`
  - `pkg/ipsec/policy_psk_identity_collision_17772_test.go`
  - `docs/config-schema.md`
  - `docs/log/18428.md`
- **Issue**: #18428, security.
- **Cause**: The rendered-selector key implementation still approximated strongSwan differently: explicit type prefixes were not recognized first, invalid `@#` nibbles were treated as literal text, invalid colon values were misclassified, DN parsing assumed escape/multi-valued syntax and Unicode/whitespace folding, RFC822 preserved local-part case, and `@` prefixes were handled before DN-syntax fallback. These mismatches could both miss real collisions and reject distinct peer identities.
- **Change**:
  - Named/numeric type prefixes are parsed first, then DN syntax, `@#`/`@`, and untyped IP/FQDN/KEY_ID forms. Invalid colon-containing untyped selectors fall back to literal KEY_ID bytes.
  - `@#` and prefixed `keyid:#` values mirror `chunk_from_hex()`: lowercase `0x` is stripped, colons are ignored, invalid nibbles become zero, and odd nibbles are left-padded. Keys compare decoded bytes with length-sensitive equality (`zz` = `00`, but not `0000`; `7a7` = `07a7`, but not `376137`).
  - DN keys recognize strongSwan `atodn()` attribute names and aliases. PrintableString attributes and emailAddress compare ASCII-case-insensitively; UTF8String and other IA5 values remain byte-sensitive. RDN order is normalized; `+` and backslash are ordinary value bytes, internal spaces are preserved, and dangling trailing backslash, unknown attributes, and numeric-OID attributes fall back to raw literal KEY_ID bytes.
  - RFC822 aliases compare the whole address with ASCII case-insensitivity, including the local part. Authored selectors and swanctl rendering remain unchanged.
- **Regression coverage**: `TestIPsecPSKOwnerCollision17772` and `TestPSKIdentityCollisionRender17772` cover the original eight cross-type pairs plus explicit `fqdn:`/`keyid:`/numeric type prefixes, invalid-colon KEY_ID fallback, DN-before-`@` fallback, malformed/unknown DN raw bytes, chunk decoding and length, supported DN aliases/types, whole-address RFC822 case, and distinct-identity controls. Renderer checks retain unrelated VPNs and same-PSK exemptions.
- **RED/GREEN and fail-on-revert**:
  - Temporarily restoring declared-type keys made the focused tests fail for canonical DN spellings, chunk-decoded key IDs, RFC822 aliases, explicit/numeric prefixes, invalid-colon and raw-DN fallbacks, and rendered cross-type collisions; the renderer emitted both conflicting connections and secrets.
  - After restoring strongSwan-parsed selector keys, `GOTMPDIR=/tmp GOCACHE=/var/worktrees/.cache/go-build go test ./pkg/config ./pkg/ipsec -run '^(TestIPsecPSKOwnerCollision17772|TestPSKIdentityCollisionRender17772)$' -count=1` passed in both packages.
- **Risk**: Strict validation now rejects distinct PSK connections only when their parsed strongSwan owner identities collide (subject to the existing same-effective-PSK exemption); tolerant rendering still skips only affected groups. No selector output or PSK diagnostic content changes.
