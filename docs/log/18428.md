# Derive PSK collision keys from rendered selectors (#18428)

- **Issue**: #18428, security.
- **Cause**: `ipsecIKEIdentityKey` keyed identities by the declared Junos type, while `formatIdentity` renders DN, IP, RFC822 aliases and other default types as the same unadorned selector. Thus distinct type names could produce one identical strongSwan PSK owner string while strict validation and the renderer collision gate considered them different.
- **Change**: Added `config.FormatIPsecIdentity` as the single selector formatter; the `pkg/ipsec` wrapper delegates to it, and collision keys canonicalize that rendered selector instead of the declared type. Dispatch follows the rendered form (`@#` key-id bytes, `@@`/RFC822, `@` FQDN, DN syntax, IP, then bare FQDN). Malformed DNs retain exact raw matching; authored selectors and emitted swanctl output remain unchanged. Same-effective-PSK exemptions and unrelated-VPN rendering are unchanged.
- **Regression coverage**: Extended `TestIPsecPSKOwnerCollision17772` and `TestPSKIdentityCollisionRender17772` with the eight reported pairs: `inet`/`inet6` same value; `inet`/`email` `peer@corp.example`; `inet`/DN `CN=peer`; `email`/DN `CN=peer`; `inet`/`email` `198.51.100.7`; hostname `peer.example`/`inet` `@peer.example`; key-id `zz`/`inet` `@#zz`; hostname `#zz`/key-id `zz`. Distinct rendered-owner controls, unrelated VPN retention, and the existing same-PSK/control coverage remain pinned.
- **RED/GREEN and fail-on-revert**:
  - Reverting to the declared-type key switch made the seven formerly missed cross-form cases fail the strict collision assertion and made the renderer emit both conflicting connections/secrets. `inet` and `inet6` with the same address were already canonicalized as the same IP in the prior keying and remain covered.
  - Restoring rendered-selector canonicalization made `GOTMPDIR=/tmp GOCACHE=/tmp/go-cache-18428 go test ./pkg/config ./pkg/ipsec -run '^(TestIPsecPSKOwnerCollision17772|TestPSKIdentityCollisionRender17772)$' -count=1` pass.
  - The 10-name focused config/IPsec regression set passed; the full `GOTMPDIR=/tmp GOCACHE=/tmp/go-cache-18428 go test ./pkg/ipsec -count=1` suite passed.
  - `GOTMPDIR=/tmp GOCACHE=/tmp/go-cache-18428 go vet ./pkg/config ./pkg/ipsec` passed, and `gofmt -l` on all changed Go files was empty.
- **Risk**: Strict commit rejects distinct PSK connections whose rendered selector owners collide; tolerant rendering skips only the affected groups. No new configuration syntax is introduced and diagnostics do not expose PSK material.
