- **Timestamp**: 2026-11-01 16:25 UTC
  - **Action**: Detector fixes found on self-review. (1) The tap socket was
    created with `ETH_P_ALL` as its protocol, so the kernel queued frames
    from EVERY interface from `socket()` until `bind`. A WAN frame in that
    window would pass the filter as a foreign source and raise a false alarm
    at startup. The socket is now created with protocol 0
    (`newFilteredTap`), and `bindTap` starts reception on the fabric parent
    only. (2) Frames to the IEEE 802.1 link-constrained groups
    (`01:80:c2:00:00:00`-`0f`: STP, LACP, 802.1X, LLDP) are no longer
    evidence. A bridge never relays them, so a fabric on a dedicated switch
    VLAN would otherwise alarm forever on its switch's BPDUs, which is the
    runtime twin of the "cannot be satisfied" defect. New
    `Tracker.ObserveFrame`. (3) `readTap` is split out of `runTapSampler`
    so a test can drive a tap it opened.
    New cells:
    - `TestObserveFrameIgnoresLinkConstrainedGroups18719` (hermetic;
      boundaries 0x0f and 0x10, broadcast/unicast true twins, runt);
    - `TestTapSamplerOnARealSegment18719` (kernel path on veth pairs,
      empty-netns only, run via `unshare -rn`);
    - the unresolved-peer cell now covers a nil, an all-zero and a short
      non-zero peer MAC and checks arming synchronously (the old cell let

    commit now sees it only on fabric-related commits, or never once every
