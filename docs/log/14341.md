# #14341 — compileApplications silently drops application-set members packed after description and bracketed child members

## Defect
- `pkg/config/compiler_applications.go` `compileApplications`: the `case "description":` arm in the application-set loop was a bare no-op. It never examined `member.Keys[2:]` or `member.Children`, so members packed after a description (`description "d" application junos-http;`, description between members, `description "d" application [ a b ];`, nested `application-set` after description, and the braced child-block form `description { "d" application a1; }`) were silently omitted. The brace-elided form `application-set S description "d" application a1;` packed the whole tail onto the set node and compiled to an empty set.
- `applicationSetMemberValues`: the inline branch iterated `member.Keys[1:]` but the `member.Children` branch read only `vn.Keys[0]`, dropping `vn.Keys[1:]`. A bracketed child block `application { [ junos-http junos-https ]; }` (child Keys=["junos-http","junos-https"]) therefore kept only the first member.
- Consequence: strict `CompileConfig` succeeded with zero errors/warnings while the set was under-populated (or empty); a zone `deny`/`reject` policy referencing the set failed open for every omitted application. This is the application-set analogue of #12831, which fixed the identical description-packed pattern for address-sets.

## Fix
- `pkg/config/compiler_applications.go`:
  - New `appendPackedApplicationSetMembers14341` (mirrors `appendPackedAddressSetMembers12831`): parses recognized `application`/`application-set` statements from a packed token run, preserves multi-valued bracketed members until the next recognized statement head, skips a `description` metadata value, treats bracketed tokens (via `KeysBracketed` provenance, `bracketMask12831`/`keyBracketed12831`) as values even when their text equals a keyword, and records every unrecognized token (or a valueless member head) via `UnknownMembers` so strict commit rejects fail-closed instead of silently yielding a valid subset.
  - `description` arm: after ignoring the metadata value, runs the packed parser over `member.Keys[2:]` and over each child node (child Keys[0] is the description value itself, so parsing starts at Keys[1:], plus nested grandchildren).
  - Brace-elided tail: runs the packed parser over `instanceValueTail(inst.node, inst.name)` with the matching bracket mask, so the elided spelling compiles identically to the braced spelling.
  - Duplicate same-name application-set instances now union members/unknowns onto the first definition instead of overwriting it (mirrors the #4706 address-set merge), so a braced block plus an elided spelling of the same set cannot drop the first block's members on tolerant paths. Strict duplicate definitions remain rejected by the existing #3339 gate.
  - `applicationSetMemberValues`: the child branch now iterates every key of each child node and each grandchild node, not just `vn.Keys[0]`.
- Audit (per issue direction): every other `Keys[0]`/`nodeVal` read on multi-token-capable leaves in `compiler_applications.go` was checked — the remaining sites are single-valued direct-body leaves (`protocol`, ports, timeout, icmp-type/code, alg, `description` on an application) guarded by `valueTakingApplicationLeaves`/duplicate/incomplete gates, and the `applicationDirectLeaves` keyword scan, none of which can carry a member list. `addressSetMemberValues` in `compiler_security_addressbook.go` has the same `vn.Keys[0]`-only child read; that is the D7-07 twin tracked as a separate claim and was not changed here.

## Tests
- New `TestApplicationSetDescriptionChainAndBracketedChildBlockStrict` in `pkg/config/compiler_application_specs_test.go`: strict `CompileConfig` (with a deny policy referencing `web-set`) covering braced description-packed member, elided description-packed member, bracketed child block, description between members, braced description-packed bracket list, nested set after description, bracketed nested-set child block, description child-block packed member, plain control, and description-only-stays-empty; plus fail-closed subtests (unrecognized token packed after description rejects naming the set and keyword; a bracketed member literally named `description` is kept as a value, verified on the tolerant path).
- New `TestApplicationSetDuplicateBlocksUnion14341`: braced + elided same-name definitions union on the tolerant path.
