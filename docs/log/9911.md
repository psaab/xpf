## Finding and boundary

A TCP/TLS syslog write timeout was dropped without updating
`lastReconnectFailure`. The reconnect cooldown therefore never reached the
next event: every event paid another `writeTimeout` on the EventReader
goroutine. `Close` also took the same `s.mu` held across `conn.Write`, so a
reconfigure could wait behind a stalled collector. The change is limited to
`pkg/logging` source, tests, and its README, plus this log.

## STEP-0 RED (base) then GREEN (fixed)

A temporary base probe used a 300 ms write timeout and a connection whose
`Write` always waited for the deadline:

- Two sequential `Send` calls each took about 300.6 ms and produced
  `droppedWrites=2 droppedCooldown=0`.
- `Close` started while the first write was stalled and returned after about
  250.8 ms, serializing behind the write instead of interrupting it.

The permanent regression cells were then exercised against reverted code:

- Removing the timeout cooldown arm made the text and binary subtests fail with
  `write timeout did not arm reconnect cooldown`; the EventReader cell also
  measured a 60.28 ms second event instead of a fast return.
- Restoring the old lock-taking `Close` made
  `TestCloseDoesNotSerializeBehindHungWrite9911` fail with
  `Close blocked behind a hung Send`.
- Reverting raw-first TLS shutdown made
  `TestCloseTLSDoesNotBlockOnCloseNotify9911` fail with
  `TLS Close blocked on close_notify`.
- Removing TLS-timeout detachment made
  `TestTLSTimeoutDetachesCorruptConn9911` fail with
  `timed-out TLS connection remained installed`.

With the fix restored, all of those cells passed. The partial-frame regression
was updated to preserve its existing resync contract while asserting that the
immediate post-timeout send is a cooldown drop; after the injected clock passes
the window, the fresh stream receives the complete frame.

## Change

- `pkg/logging/syslog.go:54-58,178-240` adds a bounded Close join, a
  connection mutex, and raw-first TLS shutdown. Close atomically marks the
  client closed, detaches and closes the active socket without waiting on the
  Send mutex, then gives an in-flight Send only a bounded chance to join.
- `pkg/logging/syslog.go:403-424,577-630` makes Connect/reconnect safe against
  Close races, publishes sockets only while open, and centralizes cooldown
  active/arm/clear behavior.
- `pkg/logging/syslog.go:765-905,1030-1105` arms the cooldown for text and
  binary write timeouts and gates stream sends before Write, so a hung target
  costs at most one write deadline per cooldown window. Close races return the
  closed-client error rather than reconnecting.
- `pkg/logging/syslog.go:947-1029,1108-1117` writes through a connection
  snapshot, detaches timed-out TLS connections, and preserves partial-frame
  teardown while keeping the connection state synchronized.
- `pkg/logging/syslog_9911_test.go` covers text/binary timeout cooldown,
  Close interruption and bounded joins, TLS close_notify and timeout recovery,
  and the EventReader fanout path. The existing
  `syslog_close_resurrection_4806_test.go` and
  `syslog_partial_frame_3874_test.go` assertions were adapted to the concurrent
  state and timeout cooldown contract.
- `pkg/logging/README.md:279-325` documents timeout cooldown behavior, TLS
  shutdown, partial frame recovery, and the bounded Close join.
