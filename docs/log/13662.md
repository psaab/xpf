# #13662 - Reject unsupported legacy GRE flags on native decapsulation

- **Timestamp**: 2026-10-16
- **Action**: Both native GRE decapsulation and the transit GRE discriminator refuse unsupported legacy Strict Source Route and Recursion Control bit 0 (`0x0800 | 0x0400`). They continue to accept RFC 2784 §2.3 bits 6–12 (`0x03F8`) as must-ignore, and preserve RFC 2890 Key/Sequence parsing.
- **Validation**: The native decapsulation regression failed on pristine `origin/master` at `0x0800` (the frame was decapsulated), then passed post-fix with both regression tests. The transit discriminator regression failed on the merged decapsulation-only baseline at `0x0800` (`Keyed(85)` rather than `Unparseable`), then passed with must-ignore bits still accepted. `gre_discriminator::tests` and `cargo build -p xpf-userspace-dp` passed on the merged baseline. The full crate suite from the original PR exited 101 with failures in `f035_parked_fragment_overlap_is_rechecked_on_retry_10659` and two GRE local-delivery host-inbound tests; the fragment test also failed on pristine master, and both GRE tests passed individually on pristine master. Regression-file formatting passed; workspace formatting reports drift in untouched files.
- **Risk**: Native GRE decapsulation refuses frames carrying either unsupported legacy bit; transit GRE carrying either bit no longer acquires a keyed session identity and remains on its flowless path. RFC-mandated must-ignore flags and RFC 2890 optional fields remain accepted.
