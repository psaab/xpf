# #15250 — userspace-dp: AllowedIPs linear scan at hub scale (A69-03)

- **Timestamp**: 2026-10-19
- **Action**: Replaced the flat, prefix-length-sorted AllowedIPs list
  (a linear scan of one cross-family `Vec` per packet) with
  per-family, prefix-length-bucketed hash maps whose lookup cost is
  bounded by the family's prefix-length count (33 IPv4 / 129 IPv6
  probes), independent of the peer/prefix count. Loaded the engine
  peer table via the ArcSwap guard (`load()`) instead of
  `load_full()` on the per-packet path, added a loaded-snapshot
  peer-selection entry point so a caller selecting the same peer
  more than once per packet can pay one load, and corrected the
  stale design docs that claimed the table is decap-only, never
  consulted on egress, and a "trie".
- **File(s)**: `userspace-dp/src/afxdp/wg/allowed_ips.rs`,
  `userspace-dp/src/afxdp/wg/engine.rs`,
  `userspace-dp/src/afxdp/wg/engine_tests.rs`,
  `userspace-dp/src/afxdp/wg/mod.rs`, `userspace-dp/src/afxdp/wg/peer.rs`,
  `userspace-dp/src/afxdp/wg/tests.rs`,
  `userspace-dp/src/afxdp/frame/wg.rs`,
  `userspace-dp/benches/allowed_ips_lookup.rs` (new),
  `userspace-dp/Cargo.toml`, `debian/changelog`, `docs/log/15250.md`

## Mechanism (verified at base bda827750b, origin/master)

- `AllowedIps` held one `Vec<Entry>` sorted by `prefix_len`
  descending, IPv4 and IPv6 interleaved (`allowed_ips.rs:47-92` at
  base). `lookup_v4`/`lookup_v6` scanned the whole vec, skipping the
  other family's entries by pattern-match, until the first match
  (`allowed_ips.rs:111-134`). Cost per lookup: O(total configured
  prefixes across both families).
- That lookup sits on every WG packet in both directions:
  - decap: `try_decap` → `matches_for_peer(inner_src, peer_idx)`
    (global-LPM source gate, WG §5.4.6) — `engine.rs:2006` at base;
  - encap: `WgEngine::peer_for_dest(inner_dst)` — `engine.rs:952`
    at base — called from transit encap (`frame/wg.rs:747`), the
    TUN-read fallback (`wg_control/mod.rs:987`), and the per-peer
    underlay selection behind PTB / TCP-segmentation / dispatch
    egress sizing (`wg_peer_outer_dst`, `frame/wg.rs:342`).
  On a multi-peer hub (hundreds–thousands of peers/prefixes) every
  packet paid a scan proportional to the configured prefix count.
- `load_table()` used `ArcSwap::load_full()`, which heap-allocates
  a fresh `Arc` (refcounted allocation + debt-slot management) on
  every call — per decap packet and per `peer_for_dest` call.
- The docs said the opposite of the code: `allowed_ips.rs` claimed
  "we deliberately use it only for the second purpose [decap]… the
  outbound LPM is never consulted" and "a linear scan is fine";
  `engine.rs` claimed the LPM is "used ONLY for inbound src-IP
  gate", the table is "Only consulted on the decap path", and
  `peer_for_dest` performs "a linear scan of a small, prefix-sorted
  table". In fact the outbound LPM has selected the encap peer
  since #1434 B1b (`peer_for_dest` + `wg_encap_frame`), and the
  table is neither small at hub scale nor scan-free.

## Fix

- `allowed_ips.rs`: `AllowedIps { v4: FamilyLpm<33, u32>, v6:
  FamilyLpm<129, u128> }`. `buckets[len]` maps the masked network
  address at prefix length `len` to the owning peer index; lookup
  masks the query at each length from longest to shortest and
  probes — first hit is the LPM winner. A v4 query never touches
  v6 state. Semantics preserved exactly:
  - global-LPM `matches_for_peer` (WG §5.4.6) unchanged in meaning;
  - duplicate `(prefix, peer)` inserts idempotent;
  - an identical prefix claimed by two peers is won by the FIRST
    inserter (the old list's stable-sort tie-break), pinned by
    `duplicate_cross_peer_prefix_only_one_peer_wins`;
  - `remove_peer` retains-by-owner across all buckets.
  The table is still rebuilt at config-commit (`reconcile_peers`)
  and published inside the atomic `PeerTable`; lookups allocate
  nothing and take no lock.
- `engine.rs`: `load_table()` now uses `ArcSwap::load()` (guard,
  no allocation) and materialises the `Arc` once for the caller.
  New `WgEngine::peer_for_dest_in(&PeerTable, dst)` (the
  loaded-snapshot core; `peer_for_dest` delegates to it) and
  `WgEngine::table_snapshot()`, so per-packet callers that select
  the same peer more than once can load once and observe one
  atomic snapshot. `frame/wg.rs::wg_peer_outer_dst` gained the
  optional-table form (`wg_peer_outer_dst_with_table`); existing
  single-selection callers are unchanged. Decap already loaded
  the table once per packet and still does.
- Docs: `allowed_ips.rs` module doc now states both directions are
  LPM-decided, describes the bucketed implementation, and records
  the first-inserter tie rule; `engine.rs` header / `PeerTable` /
  `peer_for_dest` docs, `wg/mod.rs`, `wg/peer.rs`, `wg/tests.rs`,
  and `frame/wg.rs` no longer call the table decap-only, unused on
  egress, scanned, or a "trie". (`counters.rs` was cited in the
  issue's fix direction but contains no AllowedIPs representation
  claim — verified by grep; unchanged.)
- `benches/allowed_ips_lookup.rs` (new, `harness = false`):
  re-implements the old flat scan and the new bucketed shape (the
  bin crate's `pub(crate)` types are not importable from benches —
  same pattern as `prefix_set_lookup`/`session_table`) and gates
  the acceptance "lookup cost flat across P=1..1024": the bench
  exits non-zero if the bucketed mean per-query cost at P=1024
  exceeds 4× its cost at P=1. The old scan is printed alongside
  for contrast (it grows ~1000× over the same range on the
  catch-all-remainder probe).

## Regression / control evidence

- `allowed_ips_tests::lpm_at_1024_peer_scale` (new): 1024 distinct
  /24 peers under one /8 peer plus 256 v6 /48s under a /32 —
  last-inserted hit, remainder hit, v6 hit/miss, and the decap
  gate at scale (`matches_for_peer` accepts only the /24 owner).
- `allowed_ips_tests::{v6_slash_zero_and_host_route,
  non_octet_boundary_prefixes}` (new): family isolation, /0 and
  /128 edges, non-octet-boundary masks (/9, /33).
- `engine_tests::peer_for_dest_at_1024_peer_scale_15250` (new):
  the same scale through the production engine
  (`WgEngine::new` → `reconcile_peers` → `peer_for_dest` and the
  loaded-snapshot `peer_for_dest_in`), including miss = None
  (fail-closed: no peer, no encap target).
- All pre-existing `allowed_ips_tests` (longest-prefix, v6,
  overlapping-LPM spoof rejection, duplicate handling,
  `remove_peer`, /0) stay green unchanged — the neighbouring
  legitimate behaviour controls.
- RED evidence: the scale tests exercise the production types, so
  on the pre-fix tree they pass only because the flat scan was
  also correct — the defect is cost, not answers. The RED for a
  cost defect is the bench gate: the old scan's mean per-query
  cost grows ~1000× from P=1 to P=1024 (8.7 ns → 8315.3 ns on
  the catch-all-remainder probe), far past the 4× gate the bench
  enforces on the bucketed shape (ratio 1.02×). Reverting
  `AllowedIps` to the flat `Vec<Entry>` also breaks the
  `entry_count()`-pinned idempotence cell. No behaviour-changing
  revert-red is claimed for a pure cost fix.

## Risk

- Behaviour: no wire, config, or counter change; LPM answers are
  bit-identical (same winner, same tie-break, same fail-closed
  miss). The only operator-visible delta is per-packet CPU at
  multi-peer hub scale.
- Memory: the bucketed index stores one hash entry per distinct
  `(family, prefix)` (32 B-class per entry plus hash overhead)
  vs 24 B per flat entry — same order, bounded by the configured
  prefix count, rebuilt only at config commit.
- NOT changed: `try_encap`'s explicit-pubkey contract (the LPM
  remains the selection step in front of it), session/replay/
  cookie paths, the single-load discipline inside `try_decap`,
  and every non-WG path.
