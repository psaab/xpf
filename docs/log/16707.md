# #16707: injective label sanitization + ContinueOnError scrape salvage

- **Timestamp**: 2026-10-25
- **Issue**: #15086's U+FFFD label fold is many-to-one: two committed
  identifiers that differ only in invalid bytes (`web\xffallow` vs
  `web\xfeallow` in the same trust->untrust scope) both sanitized to
  `web�allow`, emitted duplicate `xpf_policy_hits_total` series, and
  `Registry.Gather` failed the whole scrape — promhttp's default
  `HTTPErrorOnError` answered 500 with zero samples for as long as the
  config stood. The same 500 class covers the Y49-03 source (a zone-pair
  rule vs a scoped global with the same name in the same zone pair).
- **Fix**:
  - `pkg/api/metrics_emit_15086.go`: `sanitizeMetricLabelValue` now
    escapes each invalid byte as `\xNN` (lowercase hex, valid runes and
    ASCII copied verbatim) instead of `strings.ToValidUTF8(s, "�")`.
    Distinct raw values differing only in invalid bytes keep distinct
    sanitized spellings; valid values still pass through byte-identical
    with no allocation on the fast path. New `emitGatherErrors`.
  - `pkg/api/metrics_handler.go`: lanes now serve via a
    `gatherCountingGatherer` wrapping the lane registry, with
    `promhttp.HandlerOpts{ErrorHandling: promhttp.ContinueOnError}`.
    A Gather error (duplicate series or otherwise) drops only the
    offending series, the rest of the exposition answers 200, and the
    error is counted on the collector. A wholly empty gather still
    answers 500 (promhttp behaviour), so a total failure stays visible.
  - New always-emitted counter `xpf_metrics_gather_errors_total`
    (`pkg/api/metrics.go`, `metrics_descriptors_global.go`,
    `metrics_descriptor_table.go`): cumulative scrapes salvaged by
    ContinueOnError, emitted via a defer at the top of `collectContext`
    beside the #15086 health counters, so the drop from scrape N is
    certified on scrape N+1. The `xpf_metrics_invalid_label_values_total`
    help text now says "escaped as \xNN" (#16707 spelling).
  - `pkg/api/README.md`: the #15086 bullet rewritten for the injective
    spelling and the ContinueOnError/count contract.
- **Tests** (`pkg/api/metrics_sanitize_collision_16707_test.go`, new;
  `metrics_invalid_utf8_15086_test.go` expectations updated from the
  U+FFFD spelling to the `\xNN` spelling):
  - `TestSanitizeMetricLabelValueInjective16707`: unit injectivity —
    `\xff` vs `\xfe` spellings distinct, mixed/truncated sequences
    escaped per byte, valid and literal-`\xNN` values byte-identical.
  - `TestMetricsScrapeSanitizeCollision16707`: the probe pair through
    the real handler answers 200 with two distinct
    `xpf_policy_hits_total` series (+ default row),
    `invalidLabelValues == 2`, `gatherErrors == 0`, and
    `xpf_metrics_gather_errors_total 0` in-band.
  - `TestMetricsScrapeDuplicateSeriesContinueOnError16707`: the Y49-03
    shape (same-name zone-pair rule + scoped global, valid UTF-8)
    answers 200, serves the rest of the exposition, drops the duplicate,
    counts `gatherErrors == 1`, and certifies
    `xpf_metrics_gather_errors_total 1` on the next scrape.
  - FAIL-ON-REVERT: restoring `ToValidUTF8` makes the colliding scrape
    500 (first test); restoring `HTTPErrorOnError` makes the Y49-03
    scrape 500 and leaves `gatherErrors` at 0 (second test).
- **Validation**: targeted `go test ./pkg/api/ -run '16707|15086'`
  plus descriptor-table/coverage tests; `go vet ./pkg/api/` clean;
  `gofmt` clean. Full `pkg/api` suite compared against base where run.
- **Operator delta**: identifiers with raw non-UTF-8 bytes now appear in
  Prometheus with `\xNN` escapes instead of U+FFFD (a label-value change
  for already-broken config only; healthy identifiers are unchanged).
  Any residual duplicate series no longer blinds monitoring: that series
  is dropped per scrape and `xpf_metrics_gather_errors_total` increments
  — alert on `> 0` and rename the colliding identifier.
- **Residual**: promhttp's own `promhttp_metric_handler_errors_total` is
  registered only when HandlerOpts.Registry is set; this handler uses
  per-lane registries without it, so the in-band signal is the new
  `xpf_*` counter (deliberate — no second registry to wire per lane).
  Commit-time rejection of non-UTF-8 identifiers remains out of scope,
  as in #15086.
