# #12710 — do not use interrupted xfrm dumps as complete allowlist evidence

## Why

`netlink.LinkList` returns the links it did deserialize alongside `netlink.ErrDumpInterrupted`. `xfrmDumpNames` previously swallowed that error and presented the partial set as complete. The #12580 stale-xfrmi fixture measures the consequence: when the partial set contains the LAN but omits stale `st10`, the reshape allowlist is `[ge-0-0-0 st10]`. Absence from an interrupted enumeration does not establish that a device is an ordinary NIC.

## Decision

Degrade the reshape allowlist on an interrupted dump; do not retry or use the partial list as complete. This allowlist grants permission to reshape a NIC's RSS table, so uncertainty must not grant that permission. The measured alternative is allowing a live IPsec xfrmi to be RSS-reshaped. The conservative cost is that all NIC tuning using this allowlist is withheld until the next config apply, the same operator-visible cost already accepted for a hard dump failure in #12580.

The snapshot's secure-tunnel classification has the opposite use for positive evidence: known xfrmi names in the partial list remain useful and must not be discarded. `xfrmDumpNames` therefore preserves the classified partial map while reporting `ErrDumpInterrupted`; the snapshot continues with its config-ownership fallback and known kernel exclusions, and carries the error status so `UserspaceBoundLinuxInterfaces` can return nil. No retry was added: retries would add dump work to snapshot/allowlist generation and do not remove the need to handle an interrupted attempt. The allowlist is retried naturally on the next config apply.

## Change

- Report every `LinkList` error, including `ErrDumpInterrupted`, while retaining classified links.
- Keep the snapshot's known-xfrmi evidence; mark the snapshot's xfrm sample as failed/incomplete.
- Degrade `UserspaceBoundLinuxInterfaces` to nil and emit its existing WARN on incomplete data, rather than granting permission from the partial list.
- Add regression coverage for the partial result that omits stale `st10`, the retained-known-xfrmi policy, the diagnostic, and a healthy-dump control.
- Update the architecture notes and #12580 test scope to describe the selected behavior.

## Validation

- The pre-change measurement recorded in #12580: the stale zoned `st10` beside `ge-0-0-0` was returned in the allowlist `[ge-0-0-0 st10]` when the xfrm sample did not name `st10`. That report also documents the allowed hard-failure degrade's impact (tuning resumes on the next config apply).
- RED mutant: `go test -overlay /tmp/xfrm-dump-12710-overlay.json ./pkg/dataplane/userspace -run '^TestAllowlistDegradesToNilOnInterruptedXfrmDump12710$' -count=1 -v` with the pre-fix policy (swallow `ErrDumpInterrupted`) failed as intended: allowlist `[ge-0-0-0 st10]` instead of nil, no withheld-allowlist WARN, and the policy assertion observed a nil error.
- `go test ./pkg/dataplane/userspace -run '^(TestXfrmDumpFailureIsLoggedNotSwallowed|TestXfrmDumpNamesRetainsInterruptedEvidence|TestAllowlistDegradesToNilOnInterruptedXfrmDump12710)$' -count=1 -v` — PASS.

This PR edits no snapshot wire type fields or protocol versions; a separate base run was not performed.

## Risk

A transient interrupted dump skips RSS reshape and kill-switch restore, interrupt coalescence, and released-NIC hand-back for this apply; those operations are not retried until another config apply. This is the deliberately accepted throughput/tuning trade-off to avoid granting reshape permission to an unclassified xfrmi. Snapshot configuration-ownership fallback is unchanged, and partial positive xfrmi evidence is retained.
