# #13058 campaign follow-up

The IPv6 NA recovery harness now treats capture readiness as a positive
precondition: it waits for tcpdump's `listening on` banner before issuing the
failover request, emits the banner as evidence, and VOID-aborts without
changing RG placement if readiness is not established within 20 seconds.
This removes the prior fixed-sleep race where an absent NA could be explained
by a capture that had not armed. The failback wait defaults to 300 seconds
rather than 120, matching the observed run that remained in secondary-hold
past the old deadline; `FAILOVER_DEADLINE` remains configurable.

Validation: `bash -n test/incus/test-v6-na-recovery-12495.sh` and
`make test-v6-na-recovery-lib`.

Lab acceptance is still outstanding: run the live `test-v6-na-recovery-12495.sh`
on the loss cluster, preserve the capture/timeline artifacts, and verify both
NA attribution and return to the original RG primary. The code cannot prove
that the observed secondary-hold timeout is resolved without that run.
