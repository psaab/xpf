# #17167 — Pre-extraction residue in cli/grpcapi: dead builtinApps tables, dead resolvers, dead ResolvePhysicalParent copy (R4-Q49-04)

- **Timestamp**: 2026-10-27
- **Issue**: #17167 (R4-Q49-04)
- **Base**: `origin/master 0a5654d7da`

## Defect (STEP-0, verified at base)

Live on `0a5654d7da`. `pkg/cli/app_resolve.go` held the 15-row
`builtinApps` table (incl. `"junos-ipsec-nat-t": {proto: 17, port: 4500}`,
a name found nowhere else — the live catalogue uses `junos-ike-nat`),
`builtinApp`, `resolveAppName` (no production or test callers) and
`resolveAddress` (referenced only by
`pkg/cli/address_keyword_display_9523_test.go`). Its header claimed
deletion was "tracked as a follow-up"; no such issue existed.
`pkg/grpcapi/server_helpers.go` held a byte-identical `builtinApps` /
`resolveAppName`, the dead `lookupAppFilter`, and `resolveFabricParent`,
a verbatim copy of `monitoriface.ResolvePhysicalParent`
(`pkg/monitoriface/monitor.go:351`). Repo-wide grep confirmed no
production callers of any of these symbols in `pkg/cli` / `pkg/grpcapi`
(the unrelated `resolveFabricParent` in `pkg/daemon` and
`EventReader.resolveAppName` in `pkg/logging` are distinct live code).

## Fix

- Delete `pkg/cli/app_resolve.go` entirely (nothing remained).
- `pkg/cli/address_keyword_display_9523_test.go`: drop the two
  `resolveAddress` assertion blocks, keeping the live
  `resolveAddressDetail` keyword and control assertions.
- `pkg/grpcapi/server_helpers.go`: delete `resolveFabricParent`,
  `builtinApp`/`builtinApps`, `resolveAppName` and `lookupAppFilter`.
  Remaining imports stay used (`strconv` by `fmtPref`, `strings` and
  `netlink` elsewhere in the file).
- The acceptance grep also matched one live site the issue did not
  enumerate: `pkg/cli/monitor_interface.go:136` `resolveFabricParent`,
  a one-line wrapper over `monitoriface.ResolvePhysicalParent` used
  once by `monitor_traffic.go`. To satisfy the acceptance grep without
  weakening it, the wrapper is deleted and its sole caller now calls
  `monitoriface.ResolvePhysicalParent` directly — no behaviour change.

## Validation

- `grep -rn 'builtinApps\|func resolveAppName\|func lookupAppFilter\|func resolveFabricParent\|junos-ipsec-nat-t' pkg/cli pkg/grpcapi` → no matches (exit 1).
- `GOFLAGS=-p=2 go test ./pkg/cli ./pkg/grpcapi -run '^TestAddressResolversNeverResolveAKeywordAsAName9523$' -count=1` → `ok pkg/cli`, `ok pkg/grpcapi [no tests to run]`. (Issue acceptance said `-run 9523`; run anchored to the exact named test per campaign hermetic-test rule, which also compiles both packages including the edited `monitor_traffic.go`/`server_helpers.go`.)

## Risk

Deletion-only plus one direct-call substitution of an identical
function body. No live resolver, catalogue, or rendering path changes:
the live application catalogue (`pkg/config/predefined.go`,
`pkg/appid`) already used `junos-ike-nat` and is untouched.
