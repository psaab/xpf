# Issue #14119: Local-origin GRE tunnel TX drops non-first fragments

## Why

`build_local_origin_tunnel_tx_request` (`userspace-dp/src/afxdp/tunnel.rs`) required `parse_session_flow_from_bytes` to yield a complete L4 flow before checking that the TUN packet's source was locally owned. `parse_session_flow_from_bytes` correctly refuses non-first IPv4/IPv6 fragments (#2344 — payload must never be parsed as L4 ports), so the builder returned `parse_local_origin_session_flow_failed` and `local_tunnel_source_loop` dropped the fragment. Locally emitted datagrams fragmented before the TUN lost their non-first pieces; the first fragment (which carries the L4 header) transmitted, so reassembly at the peer could never complete.

## What

`userspace-dp/src/afxdp/tunnel.rs`: when the session-flow parse returns `None` and the frame is positively a non-first fragment (`frame_is_non_first_fragment`), recover only the L3 source via `parse_packet_source_from_frame` — never ports — and continue flowless (`flow: Option<SessionFlow> = None`). The existing zone and table-scoped source-ownership gates then apply to `src_ip` exactly as for flow-bearing packets, before any transmission. Flowless packets mint no `TunOrigin` session or reverse companion, seed no IKE exchange, carry `flow_key: None` on the TX request, and classify CoS without a flow key; the GRE encapsulation carries the fragment verbatim. Packets that are flowless for any other reason (truncated, uninspectable, or a non-first fragment whose L3 header cannot be read) still fail closed with the original `parse_local_origin_session_flow_failed` error. Flow-bearing packets are unchanged.

Scope note: the WireGuard TUN-origin path already encapsulates regardless of parse outcome (`parse_wg_tun_origin_flow` returning `None` only skips session publication), so non-first fragments were never dropped there; no WG change was needed.

`userspace-dp/src/afxdp/frame/tests_native_gre_ecn.rs` adds three regressions: an owned IPv4 first/non-first UDP fragment pair (first publishes with the real port, second transmits verbatim with no session/flow key), a nonlocal-source non-first fragment (fails closed at the ownership gate, no IKE seed), and an owned IPv6 Fragment-header non-first fragment (transmits verbatim, no session).

## Validation

- RED: on `origin/master` at `bfcf00f8f`, `cargo test --bin xpf-userspace-dp 14119` fails all 3 new tests with `parse_local_origin_session_flow_failed` (0 passed, 3 failed).
- GREEN: with the fix, `cargo test --bin xpf-userspace-dp 14119` passes 3/3; the full `tests_native_gre_ecn` module passes 25/25 (including all #13179 owned/nonlocal/unzoned/cross-VRF controls).
- Tunnel-filtered run: 228 passed, 1 failed. The sole failure, `afxdp::coordinator::tests::snapshot_published_tunnel_rows_join_d11_10485`, was reproduced identically on pristine `origin/master` at `d40f1f29e` with the fix stashed — pre-existing, unrelated to this change.

## Risk

Owned non-first fragments now transmit without a session, matching the wire path's flowless forwarding; replies are admitted by the first fragment's forward+reverse `TunOrigin` pair (and the receiver-side L3 fragment association), exactly as for wire-forwarded fragments. Non-owned and unzoned fragments remain fail-closed because ownership/zone gates run on the L3 source before encapsulation. No payload byte is ever promoted to a port or session identity.
