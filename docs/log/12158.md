# #12158 — staged and untracked source provenance

## Why

`git diff --quiet` compares the worktree with the index. It treated staged edits
and untracked inputs as clean in both `bake.py` and `Makefile`, so the Debian
version could claim HEAD even when the package contained non-HEAD source.
`bind_deb_identity` then removed xpfd's `-dirty` suffix before comparing its
version to the package commit, allowing that mismatch through to the signed
image provenance.

## What

- Use `git status --porcelain --untracked-files=normal` for the package dirty
  marker in both `bake.py` and `Makefile`, covering staged, unstaged, and
  untracked non-ignored files.
- Exclude only `debian/changelog` from that status. `make deb` rewrites its
  version line during the package build and restores it afterward.
- Build Makefile's embedded `VERSION` dirty suffix from the same predicate.
  This avoids the transient changelog rewrite adding `-dirty` to a clean build
  and makes untracked source visible to the embedded version as well.
- Remove the blanket `-dirty` strip from `bind_deb_identity`; compare the
  observed xpfd version exactly with the version of the package commit. A dirty
  source build therefore cannot be signed as an exact build of HEAD.

**Strip decision:** remove the strip and exempt the transient changelog path.
The identical predicate for DEB_VERSION and embedded VERSION preserves clean
`make deb` builds; keeping the strip would allow non-HEAD bytes to compare equal
to HEAD.

## Validation

- **STEP-0 at base `a11e59eac398970413aac11b6bd27318bead06c8`: BUG REPRODUCED.**
  Clean versions were `0.0.20344+ga11e59eac398`. With a staged tracked edit,
  both bake and Makefile still returned that clean version; an untracked file
  likewise remained clean. The unstaged-edit control produced `.dirty`. All
  probes were restored before editing.
- **RED before fix:** the complete new 13-test regression module ran with 8
  failures: staged/untracked detection in bake and Makefile, changelog
  exemption in both, and dirty xpfd rejection in normal and `--skip-build`
  binding.
- **GREEN after fix:** the expanded 15-test module passed, covering clean,
  staged, unstaged, untracked, ignored, changelog-only, Makefile VERSION,
  exact package/xpfd binding, dirty-marker rejection, and unavailable-commit
  `--skip-build` binding.
- Focused distribution suite: `python3 -m unittest discover -s scripts/dist
  -p 'test*.py'` — 136 tests passed.
- Focused image suite: `python3 -m unittest discover -s scripts/image -p
  'test*.py'` — 407 tests ran; one SSHD configuration test errored with
  `KeyError: 'passwordauthentication'` in
  `test_bake_sshd_password_auth_10771.py` while reading `sshd -T` output. That
  test does not cover dirty-version behavior; no pre-change baseline was run.
- A full `make deb` build was not run.

## Risk

Dirty-source packages now fail bake identity binding rather than being signed
with a clean HEAD identity. The changelog-only rewrite remains excluded, so a
clean checkout's package build retains exact version binding. No project-wide
build or tests outside the focused image/distribution suites were run.
