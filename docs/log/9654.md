## Design, against the issue's three constraints

1. **Source.** `Coordinator::learned_route_import_capped_now` reads `ha.runtime.load().forwarding().learned_route_import_capped`. That is the PUBLISHED runtime view (#6592), the one workers load; `self.forwarding` is the candidate and is not read.
   - It answers only while at least one worker record's `dead` flag is clear, and returns `None` otherwise.
   - This closes Design 2's HIGH finding. A first-worker spawn failure leaves no record, because records are registered post-spawn and teardown's `stop_and_clear` cleared the old ones. So a capped candidate that was published reads as unknown.
   - Every coordinator mutation takes `&mut self` under the same server lock as `refresh_status`, so the records and the view are read as one state.
2. **Presence.**
   - Rust carries `Option<bool>` with `skip_serializing_if = "Option::is_none"`.
   - Go decodes `*bool`.
   - `xpf_learned_route_import_capped` (1/0) is emitted only when the field is present.
   - Absence means unknown, both for a helper with no live worker and for one that predates the field. That second case is the Design 2 MEDIUM: under a plain `bool` it would read as "not capped" while enforcing capped forwarding. No protocol version bump is needed, because this additive field's absence already carries the skew-safe reading.
3. **Lifecycle cells** (`learned_route_capped_now_9654_tests.rs`):
   - **No live worker, published view capped:** `None`. This is the state before the first bring-up and during a `defer_workers` apply, which skips the spawn.
   - **Live worker:** follows the published view (`true`, then `false`).
   - **Unpublished candidate:** a capped `self.forwarding` does not change the answer until it is published.
   - **Every worker dead:** `None`; one live worker restores `Some`.
   - **AF_XDP teardown** (`Coordinator::stop`) while status still answers: `None`.
   - **Same-plan refresh** through the real `refresh_runtime_snapshot`: capped then uncapped.
   - **First-worker spawn failure** through the real `reconcile` with the #4952 `force_worker_spawn_fail` seam: `Err(WorkerSpawn)`, no record, a capped view published, and `None`.
   - **`refresh_status` projection:** `None` with the key omitted from the JSON, then `Some(true)` serialized as `true` once a worker is live.
   - **Not unit-drivable:** a SUCCESSFUL full reconcile, because a worker thread cannot bind AF_XDP here. The cells model "live worker" as the registered record the accessor actually reads.
   - **Helper exit:** the Go scrape path already clears cached status (the issue found it sound). `collectUserspaceStatus` returns before any emit on nil status, so the gauge is absent.
