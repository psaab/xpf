# #13695 — Reject the ambiguous inbound NPTv6 /48 subnet

- **Action**: Mirror outbound RFC 6296 §3.5 rejection of subnet word `0xFFFF` for non-neutral /48 rules in inbound translation.
- **Base**: `origin/master` `3084d52cb`
- **Files**: `userspace-dp/src/nptv6.rs`, `userspace-dp/src/nptv6_tests.rs`, `docs/log/13695.md`

## Symptom

Inbound traffic to external `/48` subnet `0xFFFF` was translated through the same checksum adjustment as subnet `0x0000`, aliasing two external subnets onto one internal address for non-neutral rules.

## Fix

Before inbound address rewrite, reject `words[3] == 0xFFFF` for `/48` rules whose adjustment is not one's-complement zero. Neutral mappings retain their prefix-swap behavior. Added a regression that pins a non-neutral prefix pair and requires the inbound result to be `Untranslatable`.

## Risk

None beyond rejecting the ambiguous non-neutral `/48` input that outbound translation already refuses.
