# Issue #15216 — route-only FIB bump desyncs ctrl generation bookkeeping (A29-03)

- **Issue:** psaab/xpf#15216 (A29-03, deep-review cohort; validator consensus
  MATERIAL, 3-way, `research-work.AdQvt1jMKw`).
- **Lane:** `fix/15216-campaign` in `/var/worktrees/wt-15216`, base
  `origin/master 5b567d24b8`.

## Defect

`BumpFIBGeneration` (`manager_generation.go`) advances
`m.lastSnapshot.Generation` and `m.generation` on a confirmed route-only
bump, but never touched `m.publishedSnapshot`. The #7468 retain predicate
(`classifierPlanRetainable`, `manager_compile.go`) keys retainability on
`publishedSnapshot == lastSnapshot.Generation`: the snapshot the helper
held before the request. After a bump, that equality was false even
though the helper was still enforcing exactly the retained snapshot (a
FIB bump moves only the helper's FIB view, never
`last_snapshot_generation`). A same-plan commit whose `apply_snapshot`
was refused in-band inside the bump-to-next-tick window (~1 s, until the
`syncSnapshotLocked` hash catch-up re-aligned the pair) therefore took
the #4959 ctrl-disable path — a transient kernel-only transit drop —
instead of the atomic retain. The window needs an in-band refusal inside
it; severity Low, consensus MATERIAL.

`advanceGenerationAfterPartialUpdateLocked` (the shared neighbour/fabric
partial-update writeback) already guards exactly this via its #6986
pre-bump equality sample; `BumpFIBGeneration` performed the same
generation advance without the paired `publishedSnapshot` advance.

## Fix

In `BumpFIBGeneration`, sample `prevPublished` with the other speculative
fields, and after `m.lastSnapshot.Generation = m.generation`:

- advance `m.publishedSnapshot = m.generation` iff
  `prevPublished == prevSnapGen` (the helper was enforcing this snapshot)
  and no outcome is unknown (`!applySnapshotOutcomeUnknown &&
  partialOutcomeUnknown == 0`) — unknown helper content must not be
  marked settled, and a deferred publish outstanding
  (`publishedSnapshot < lastSnapshot.Generation`) must keep the status
  tick's publish gate open (#6986/#9337);
- revert `m.publishedSnapshot = prevPublished` in the existing #10724
  refusal/known-unsent restore, alongside the generation/FIB fields.

Deliberately not changed:

- `lastSnapshotHash` is not refreshed: the content hash ignores
  `Generation`, and the tick's redundant-publish avoidance is the
  generation inequality plus that hash — advancing `publishedSnapshot`
  alone cannot suppress a needed republish (the bumped snapshot's
  content is what the helper already holds, so there is nothing to
  republish; this matches the partial-update writeback, whose hash
  refresh only matters because it mutates snapshot content).
- `appliedSnapshot` (#2079) is untouched: no full `apply_snapshot`
  happened, so the helper-applied view must not move.
- RegenerateNeighborSnapshot / fabric writebacks keep their existing
  `advanceGenerationAfterPartialUpdateLocked` guard.
