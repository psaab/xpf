# 13676 — Require a valid TCP ACK for SYN-first handshake completion

The reverse SYN-ACK sets the session's established marker but keeps
`handshake_pending` true, so both halves still use the short opening timeout.
Only a forward TCP packet carrying ACK without SYN or FIN/RST clears that gate
and enables the established timeout. Invalid segments cannot clear either
half's pending state; the reverse SYN-ACK and subsequent valid ACK/data paths
retain their existing behavior.

Regression coverage exercises retransmitted SYN, SYN+ACK, RST, FIN|ACK, and
non-ACK data flags, verifies that valid ACK and PSH|ACK still complete, and
checks closing ACK rejection on the SYN-ACK-first reverse path.
