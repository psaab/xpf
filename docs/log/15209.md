# #15209 (A20-03): redaction-placeholder ingest guard misses embedded event-options commands

- **Timestamp**: 2026-10-19
  - **Action**: Extended the #4060 commit-ingest guard (`checkRedactionPlaceholder`) to lex embedded `event-options … then change-configuration commands` payloads, so a redacted export whose credential lives inside an embedded command is refused on re-commit instead of silently installing `##SECRET-DATA##` (or a `<redacted>` URL) as the credential the event policy would execute when it fires. Added RED/GREEN regression plus controls; no behaviour change outside the cited mechanism.
  - **File(s)**: `pkg/config/ast_redact.go` (`findRedactionPlaceholder` / `findRedactedURL` embedded arms, `embeddedRedactionHit15209`, `embeddedChildRedactionHit15209`, `embeddedCommandSecretHit15209`, `embeddedCommandURLHit15209`), `pkg/config/ast_redact_embedded_ingest_15209_test.go` (new), `docs/log/15209.md` (this file)

## Mechanism (origin/master `62f548d08a`)

- `pkg/config/ast_redact.go:926-943` (pre-fix): `findRedactionPlaceholder` tested only `secretIndices(full)` on the flattened AST path, and `findRedactedURL` only `urlLeafIndices(full)`. An embedded command (`commands "set security ike policy p1 pre-shared-key ascii-text SECRET"`) lexes to ONE AST token, so no token equals `pre-shared-key` and neither finder fired — the same one-token shape #14413 fixed on the display side.
- #14413 taught `RedactedClone` to mask such credentials (`redactEmbeddedCommands14413` → `lexConfigMutationLine9938` + `secretIndices`/`urlLeafIndices` on the inner command), so a redacted export carries `set … pre-shared-key ascii-text "##SECRET-DATA##"` (or `https://<redacted>` for a URL leaf) inside the quoted command string. Re-applying that export committed cleanly through `SchemaValidateWithDefinitions` → `checkRedactionPlaceholder`: the event policy then carried a placeholder credential, and its change failed only when the event fired.

## Change

- `findRedactionPlaceholder` and `findRedactedURL` now also consult `embeddedRedactionHit15209(n, full, base)` for each visited node, returning `(urlHit, secretHit)` so each finder keeps its own sentinel/error (`errRedactionPlaceholderIngest` vs `errRedactedURLIngest`). `checkRedactionPlaceholder`'s contract and call site (`schema_walk.go`) are unchanged.
- `embeddedRedactionHit15209` mirrors `redactEmbeddedCommands14413` shape-for-shape: it locates the `change-configuration commands` pair on the flattened path, requires the `commands` keyword to belong to the visited node (ancestor-owned payloads are judged at the ancestor), and handles quoted tokens (each token one command), the unquoted joined tail, and `commands { … }` block / bracket children (`embeddedChildRedactionHit15209`), using `KeysQuoted` provenance with the same space-heuristic fallback as the display path.
- Each extracted command is lexed with the real config lexer (`lexConfigMutationLine9938`, never `strings.Fields`) and judged by the SAME `secretIndices`/`urlLeafIndices` sets — no second credential list. Only a `set` command can mint a credential, mirroring `redactEmbeddedTokens`. A secret hit requires a whole token equal to `SecretDataPlaceholder`; a URL hit requires a token containing `SecretRedacted` — exactly the spellings `RedactedClone` produces.

NOT changed: display redaction (`RedactedClone`, `FormatCompareRedacted`, `show event-options`), the compiler reader (`eventChangeConfigCommands`) and stored `ThenCommands` (a cleartext credential-bearing policy still compiles and fires identically), the direct leaf guard semantics, and every non-event config path. No new knob.

## Validation

- New `pkg/config/ast_redact_embedded_ingest_15209_test.go`:
  - `TestEmbeddedRedactedPlaceholderIngestRefused15209` — the decisive v9 re-ingest cell: `RedactedClone().FormatSet()` of a PSK-bearing event policy replayed via `ParseSetCommand` + `SetPath` is refused by `checkRedactionPlaceholder` AND by `SchemaValidate` (the production commit-ingest gate), both with `errRedactionPlaceholderIngest`; hierarchical-quoted, commands-block+bracket, and flat-set-unquoted redacted clones are likewise refused; the cleartext original passes both gates.
  - `TestEmbeddedRedactedURLIngestRefused15209` — an embedded DDNS `url` command redacted to `https://<redacted>` is refused with `errRedactedURLIngest`; the cleartext URL command passes.
  - `TestEmbeddedNonSecretPlaceholderIngestAllowed15209` — controls: placeholder inside a non-secret `host-name` command, a GRE tunnel `key` command, a `delete … pre-shared-key` command, and clean commands only all ingest cleanly (the embedded arm inherits the gated-keyword semantics, not a substring scan).
  - `TestEmbeddedPlaceholderDirectToken15209` — a quoted placeholder token in an unquoted tail is refused; a placeholder glued inside a larger token is not (RedactedClone replaces whole tokens). A bare unquoted `##SECRET-DATA##` never reaches the AST (lexer comment), which the fixture documents.
- RED on `origin/master` `62f548d08a` (tests only): the re-ingest cell, the URL cell and the direct-token cell fail — the guard accepts every redacted embedded shape. RED re-confirmed by reverting `pkg/config/ast_redact.go` with the tests in place.
- GREEN after the fix: all four new tests pass; neighbouring suites (`TestRedactionPlaceholder*`, `TestRedactedClone*`, `TestRedactedURL*`, `TestEventOptionsEmbedded*`, `TestRedactEmbedded*`, MD5/RPM-target redaction suites) pass.

## Risk

- Over-reach is bounded by construction: the embedded arm fires only under a `change-configuration commands` ancestor, only for `set` commands, and only on the exact placeholder / redacted-URL spellings `RedactedClone` emits, judged by the gated secret/URL sets. Legitimate event policies — including cleartext credential-bearing commands, non-secret commands carrying the literal placeholder string, and delete commands — commit unchanged (pinned by the control tests).
- Behaviour delta (intended): re-committing a redacted export whose event policy embeds a credential is now a hard commit-ingest error naming the offending path, instead of a policy that installs the placeholder and fails at fire time.
