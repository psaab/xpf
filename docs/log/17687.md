# #17687 — Require bounded REST and fabric source partitions

- **Timestamp**: 2026-10-26
  - **Action**: Reject non-positive REST per-source limits and invalid fabric peer reserves so neither listener silently disables its reserved admission partition.
  - **Why**: `newAPIConnGate(limit, 0)` skipped per-source enforcement, allowing one REST source to consume the global pool. The same shape existed in `newFabricConnGate(limit, 0, ...)`: non-peers could consume all fabric slots and deny a peer its reconnect reserve. Negative fabric reserves allowed non-peers to exceed the total; reserves above the total made the non-peer limit invalid.
  - **What**: `newAPIConnGate` now panics for non-positive per-source limits; `tryAcquire` refuses invalid REST gates as defense in depth. `newFabricConnGate` now requires `0 < reserve <= limit`, and fabric `tryAcquire` fails closed for malformed in-package struct literals. Updated the REST listener fixture to use a positive per-source limit above its global limit and the fabric listener fixture to classify its one connection as a peer, preserving both tests' global-cap intent. Added REST zero/negative and bypass tests plus fabric zero/negative/above-total constructor and bypass cases with valid controls. No public API or production defaults changed.
