# #14579 — NAT rule detail prints numeric zone-pair 0 and blank zones for #3096-scoped rule-sets

## Defect
`pkg/natshow` `RenderSourceRuleDetail` / `RenderDestRuleDetail` rendered
`From zone: <FromZone>    To zone: <ToZone>` and, once per rule-set,
`Rule-set <name>: sessions for this zone pair: <n>`. The session tally is
keyed by the session's real ingress/egress zone names
(`rsSessions[{zoneByID[ingress], zoneByID[egress]}]`), so for a #3096
interface- or routing-instance-scoped rule-set (`FromZone==""` and/or
`ToZone==""` on that side) the lookup `{FromZone, ToZone}` misses
unconditionally and printed `0` — not a measurement, falsifying #7423's
rule that an unqualified printed number must be measured (`n/a` exists).
The blank zone also hid the actual scope. Destination's `ToZone==""`
fallback (#8321) covered only zone-scoped dest rule-sets; a dest
`FromInterface`/`FromRoutingInstance` hit the same unconditional 0.
The same blank-scope rendering lived in the non-detail CLI listings,
the CLI source/destination summaries (interface-pool rows collapsed by
zone pair), the static renderers, and the structured gRPC/REST surfaces
(empty `from_zone` with no scope fields; zone-pair `RuleSetSessions`
rows omitted with no explanation).

## Fix
- `pkg/natshow/natshow.go`: shared scope helpers — `NATRuleSetZoneScoped`
  (both sides zone, or dest with no to scope), `natScopeParts` /
  `natScopeLine` (actual scope per side; match-any renders `any`; zone
  values keep the quarantine qualifier), plus CLI/structured label
  helpers (`NATScopeHeaderCLI`, `NATScopeLabelCLI`,
  `NATScopeSlashLabelCLI`, `NATScopePairName`, `NATRuleSetScopeLabel`).
- `pkg/natshow/source.go`, `dest.go`: detail header renders the actual
  scope (`From interface: ge-0/0/1.0`); the rule-set session row prints
  `n/a (rule-set not zone-scoped)` instead of a numeric count when the
  rule-set is not zone-scoped. Zone-scoped pairs keep the measured
  number (source 2 / dest 1 in the regression fixture); quarantined
  zone pairs keep the UNAVAILABLE row.
- `pkg/natshow/static.go`: `RenderStatic` and `RenderStaticRule` render
  `From interface:` / `From routing-instance:` (no longer detail-only)
  and `From zone: any` for a match-any rule-set instead of a blank.
- `pkg/cli/cli_show_nat.go`: non-detail listings, rule-set and rule-all
  views render the scope header/label; summaries skip non-zone-scoped
  rule-sets in the zone-pair table; the source-summary interface-pool
  row is named by scope (`trust/untrust (interface)` for a zone pair,
  unchanged).
- Structured surfaces: additive proto fields `from_interface`,
  `to_interface`, `from_routing_instance`, `to_routing_instance` on
  `NATSourceInfo` (8–11), `NATDestInfo` (9–10) and `NATRuleStats`
  (12–15), plus `scope` (4) on `NATRuleSetSessions`; `make proto`
  regenerated `xpf.pb.go`. gRPC `GetNATSource` / `GetNATDestination` /
  `GetNATRuleStats` / `GetNATPoolStats` and REST `natSourceHandler` /
  `natDestHandler` / `natRuleStatsHandler` populate them; zone-pair
  session rows and interface-pool `UsedPorts` are emitted only for
  zone-scoped rule-sets (scoped rows keep their real scope in the pool
  name instead of `"->"`). REST types mirror the fields.

NOT changed: enforcement, tally keys, translation-hit counters, and the
zone-scoped byte shape except the dest header drops its trailing blank
`To zone:` (dest rule-sets have no to clause; goldens updated).
