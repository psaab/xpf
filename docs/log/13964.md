# #13964: distinguish "other" protocol timeout overrides

The `session_timeout_ns_honors_app_override` regression used a 30-second
application override for unknown/other protocols. That is also
`OTHER_SESSION_TIMEOUT_NS`, so the test passed even if the per-application
override were ignored. The shared resolver's fallback branch already applies
the override for established non-TCP protocols and preserves the global window
before promotion; this change makes the regression values distinguish those
behaviors rather than changing production logic.

The fallback assertions now use no override to pin the 30-second global value,
then use a 90-second override to prove the established/promoted result differs
from that default. It checks both the unknown-protocol sentinel and GRE (IP
protocol 47), and retains the unreplied-flow global-window expectation.
