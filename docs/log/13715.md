# #13715 complete-connection idle liveness

## Narrowed acceptance

Fix the reviewed `serve_complete_conn_with_target` mechanism only: an idle
completion connection must detect peer EOF so a disconnected client cannot hold
the serialized accept loop, and daemon shutdown must not wait forever on
non-terminal live entries. Preserve completion delivery during idle periods.
No second implementation or guarded twin exists in `userspace-dp/src/server/`;
`serve_complete_conn` delegates directly to the target-aware function.

## Implementation

`serve_complete_conn_with_target` now peeks the Unix socket nonblocking before
reserving completions. EOF or unexpected client input exits without reserving
or consuming ready completions. While idle it sleeps briefly; on shutdown it
drains ready completions and waits at most 500 ms for live work before exit.
Socket-write failures retain the existing `release_ready` behavior.
