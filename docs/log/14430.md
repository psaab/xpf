# Issue #14430 — Cross-container duplicate `security ipsec policy` wholesale replaces strong suite + PFS

## Why

`compileIPsec` (`pkg/config/compiler_ipsec.go`) built a fresh
`IPsecPolicyDef` per `policy P` block and unconditionally stored it
(`sec.IPsec.Policies[pol.Name] = pol`). Two same-name `policy P` blocks
under two DIFFERENT `ipsec` containers (or two `security` roots) therefore
wholesale-replaced each other: the first container's strong proposal list
(`proposals [ STRONG ]`) and `perfect-forward-secrecy { keys group19; }`
were silently discarded, leaving exactly the second block
(`Proposals=[WEAK]`, `PFSGroup=0`). The `#9023` duplicate fold spans only
one `ipsec` parent, so it never sees cross-container twins, and no gate
compared strength or required PFS — the weak DES/MD5 suite committed clean.

## What

- `pkg/config/compiler_ipsec.go` (IPsec policy loop): find-or-create,
  mirroring the IKE-policy / gateway / VPN loops in the same file.
  `pol := sec.IPsec.Policies[inst.name]; if pol == nil { pol = &IPsecPolicyDef{...} }`.
  The trailing unconditional assignment is kept as an idempotent re-store
  of the same pointer. Scalar leaves (`proposal-set`, PFS `keys`) stay
  last-wins when restated; a twin stating neither leaves the earlier
  values intact (exactly the PFS preservation required).
- `proposals` arm: skip a reference already present, so a cross-container
  twin re-listing the same proposal does not render it twice on the
  `esp_proposals` line.
- NOT changed: same-parent `#9023` fold, IKE/IPsec proposal gates,
  `validateIPsecPolicyProposalReferencesStrict` (resolvability only),
  `expandIPsecProposalSets` no-clobber guard, algorithm allowlist.

## Validation

- New `pkg/config/compiler_ipsec_policy_duplicate_dr17h1_test.go`:
  cross-container merge (strict + lenient), two-`security`-roots variant,
  same-parent fold control, single-container control, duplicate-proposal
  dedup control.
- RED on pre-fix master (`3e8429706`): cross-container and two-roots cells
  failed with `Proposals = [WEAK], want [STRONG WEAK]` and
  `PFSGroup = 0, want 19`.
- GREEN after fix: all 5 cells pass; `TestDuplicateBlocksMergeAtFourMoreSites9209`,
  `TestIPsecPolicyProposals*`, `TestIKEIPsecProposals*` stay green.
- Full `go test ./pkg/config/` exceeds the 300s job cap in this
  environment; the failures seen in the IPsec-focused run
  (`TestIPsecPolicyResolvableProposalAccepted`, `TestIPsecGatewaySetSyntax`,
  `TestIKEOrphanGatewayDanglingPolicyAccepted`, all `#14139` PSK gate) are
  base-attributed: identical failures on detached `origin/master`
  (`2b810ccd1`) without this change.

## Risk

Merged `Proposals` is the ordered union (STRONG then WEAK in document
order); a twin restating `proposal-set`/PFS keys still wins per-leaf,
matching scalar semantics. No renderer or gate behaviour changes for
single-container configs (byte-identical single-block compile).
