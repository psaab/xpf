# #9842: gate redundancy-group weight on proven XDP readiness

- **Timestamp**: 2026-09-17 UTC
- **Action**: Reproduced the full-weight race on `origin/master`, implemented the shared XDP-ready verdict, added transition/tick/config-refresh coverage, and recorded the validation boundary.
- **File(s)**: `pkg/cluster/group_state.go`, `pkg/cluster/election.go`, `pkg/daemon/daemon_transit_gate.go`, `pkg/daemon/transit_gate_tick_9725.go`, `pkg/daemon/daemon_apply_tail.go`, and their focused tests.

## Problem proof on master

A temporary probe was run in a detached worktree at the then-current `origin/master` before the fix. It passed all three assertions proving the starting defect:

1. After `Start`/arm, `AttachedXDPLinkCount == 0` while the RG weight was still **255**.
2. An unattached node at weight 255 preempted its healthy peer.
3. An RG added while the node was demoted started at **255**.

The isolated RED regression probe was then run against current `origin/master` (`cad1eeab01e3d893c291fe0e67cd00b660a95666`). It failed as intended:

```text
TestRED9842_ArmedWithoutXDPStillBidsFullWeight
RED: armed with AttachedXDPLinkCount=0 bid weight=255, want 1
FAIL
```

The same scenario is GREEN in the fix branch through `TestArmedButUnattachedKeepsRedundancyGroupWeightLow9842`.

## Fix

The one readiness verdict is `dataplaneArmed && AttachedXDPLinkCount > 0`, matching the #9725 transit-gate predicate:

- `pkg/daemon/daemon_transit_gate.go:142-150` reads the kernel attachment count after a successful arm and drives both gate and RG tracking.
- `pkg/daemon/daemon_transit_gate.go:153-192` applies the existing reserved interface-monitor debt only on a sentinel transition. Unready means debt `254` and effective weight `1`; ready clears it back to `255`. Steady-state ticks do not take the Manager write path.
- `pkg/daemon/transit_gate_tick_9725.go:74-87` reads the kernel count once under `transitGateMu`, then sends that exact verdict to both transit actuation and RG weight tracking. Event wake and periodic tick therefore cannot diverge.
- `pkg/daemon/daemon_apply_tail.go:308-314` reasserts immediately after `UpdateConfig`, so an RG added during an unattached interval does not wait for the next tick.
- `pkg/cluster/group_state.go:24-50` gives newly created RGs the losing floor and installs the reserved debt in HA mode (`ControlInterface != ""`). Standalone configurations retain the existing immediate full weight. The debt constants and floor rationale are documented at `pkg/cluster/election.go:653-681`.

The existing reserved-debt ownership exemption remains required: `reconcileMonitorDebtsLocked` must not remove this daemon-owned sentinel during an unrelated commit.
