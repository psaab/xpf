  - **Action**: SNMP listener no longer stays deaf after vrf-mgmt is deleted and re-created (#16626). The socket's SO_BINDTODEVICE binding resolves the device name to its kernel ifindex at bind time, but `snmpConfigHash`/`snmpVRFDevice` key only on the name, so the #15223 re-create (new ifindex, same name) left the running agent pinned to a dead ifindex with no commit ever restarting it. The daemon now records the bound ifindex at agent start (`snmpVRFIndex` in `daemon.go`, set in `startSNMPLocked`, cleared in `teardownSNMPLocked`); `reconcileSNMP` compares it with the live device and restarts on a mismatch (including device absent), adopting no bounce when the recorded index is unknown (0). The #15223 reassert tick (`reassertMgmtVRFOnce`) records a successful re-create and calls the new `restartSNMPForVRFRecreate` in the same tick — including the no-drift early-return arm — which restarts only a listener actually pinned to vrf-mgmt via the normal `reconcileSNMP` path (so a bind failure leaves the hash unrecorded and the next commit retries, #5110 contract). Regression cells in `snmp_vrf_recreate_16626_test.go` drive the real reassert tick and reconcile against a fake kernel that deletes/re-creates vrf-mgmt at ifindex 99: restart-in-tick (RED pre-fix), commit-path ifindex restart with unchanged-ifindex no-op control, and main-table listener untouched control.
