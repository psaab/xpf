# #12635 — Junos apply statements in closed-world subtrees

- **Action**: Recognize Junos apply statements in the strict schema walker beneath inherited closed-world subtrees
- **File(s)**:
  - `pkg/config/schema_walk.go`: resolve `apply-groups`, `apply-groups-except`, and `apply-macro` when closed-world validation would otherwise reject an undeclared keyword; treat their payloads as metadata
  - `pkg/config/apply_closedworld_12635_test.go` (new): hierarchical and flat acceptance cells, scheduler inheritance, and closed-world rejection controls

## Defect

`schemaChildFor` resolves the three Junos apply keywords only at wildcard slots. Closed-world subtrees such as `schedulers scheduler <name>`, scheduler day containers, IKE proposals, and security address sets have no wildcard, so strict SchemaValidate rejected valid Junos `apply-groups`, `apply-groups-except`, and `apply-macro` statements (#7029).

## Fix

The strict schema walker now resolves these keywords to the existing `applyStatementSchema` only when schema lookup found no declared child and the current walk is under an inherited closed-world subtree. The schema walker recognizes the apply statement as metadata and does not treat group names or an apply-macro body as schema keywords. The existing wildcard behavior and declared-child precedence remain unchanged.

## Coverage

Added hierarchical cases for scheduler instances, scheduler day containers, IKE proposals and address sets, flat-set cases for each kind of location, and a compile case verifying scheduler group inheritance. Negative controls keep unknown keywords rejected in all four tested closed-world areas and require a value for `apply-groups`.
