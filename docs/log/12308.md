# #12308 — repeated qualified-next-hop blocks reduce silently on tolerant path

## Why
Follow-up to #12184 (lane-reported, parent-reproduced firsthand: the #8704
binding test fails on the #12184 branch, passes on clean base). Typing the QNH
metric leaf lets the synthetic probe use valid integer metrics, which reveals
that `routing-options static route xpfname qualified-next-hop` loses
configuration to a repeated block and reports NOTHING on the tolerant path —
"A listed exception that is silent is compliant with #8436 census by
construction". Out of #12184 scope (metric validation vs duplicate-block
reporting). The #8436 census skips both QNH sites ("no two synthesizable
single-value leaf children": `interface` synthesizes no pair, and the untyped
`metric` leaf's `<value>` placeholder matches no synthPair arm), so the
reduction hid in the skip list.

## What
Two `deepDupRules` rows (`pkg/config/dup_named_blocks_deep_8704.go`), reusing
the existing #8704 registry — no new gate, no new vocabulary:

- `routing-options static route qualified-next-hop` → `dupEffectSplitInstances`
- `routing-options rib static route qualified-next-hop` → `dupEffectSplitInstances`

Effect measured in BOTH authoring orders (interface in one block, preference
in the other): each order compiles to 2 NextHopEntry halves where merged and
flat-`set` spellings give 1 — so neither first- nor last-wins. The halves
land in DIFFERENT failover tiers (interface half inherits route preference 5,
preference half carries 250): one authored floating backup becomes a
primary-tier path plus an interfaceless backup.

The rows inherit strict rejection, the lenient warning, and the #6455
group-expanded re-run from `validateDuplicateNamedBlockAST`. Flat `set` merges
before the gate (SetPath collapses same-gateway lines onto one node); distinct
gateways stay distinct. Tests in `pkg/config/dup_qnh_12308_test.go`: strict
reject + tolerant report + effect wording, distinct-gateway/flat over-reach
controls, rib-scoped twin.

## Risk
Low. The gate fires only when two hierarchical `qualified-next-hop` nodes
with the SAME gateway key are siblings under one route — a shape the flat
spelling cannot produce (merges) and that previously compiled to a
tier-splitting defect. Distinct gateways, flat authoring, and merged blocks
are asserted clean by the over-reach test. No compiler, schema, or census
changes; no inventory/skip-list edits needed (QNH sites stay skipped until
#12184's metric typing makes them probeable — at which point this gate is
already the "rejected-at-commit" verdict waiting for them).
