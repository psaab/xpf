# Issue #13079 — session lookup auxiliary snapshots

## Why

D5-07 identified repeated `SessionTable` lookups of the same key during resolver hits and descriptor installation. The callers re-fetched session ID, source-NAT state, leak incarnation, timeout, and handshake state after resolving or installing the record, multiplying keyed probes on packet paths.

## What

Added compact auxiliary data to `SessionLookup` and a one-probe install snapshot for session ID, source-NAT state, timeout, and handshake state. Resolver and descriptor-install callers reuse those snapshots. The per-packet aux excludes the policy-counter `Arc`, preserving #5445 ownership behavior; leak incarnations remain separately stored. Added direct snapshot tests and a caller-source probe-budget regression in the existing `session_glue` test harness.
