# #14842 — USERSPACE_INGRESS_DOMAINS keyed by ifindex only

## Defect
`USERSPACE_INGRESS_DOMAINS` (userspace-xdp/src/lib.rs) was
`HashMap<u32, u32>` keyed by ifindex only. VLAN units in different routing
domains sharing one parent ifindex could not be resolved per unit: Go's
`localAddressRoutingDomain` saw multiple domains for one ifindex, returned
ambiguous, and `syncIngressIfaceMapLocked` deleted the parent entry, so the
shim fell back to domain `u32::MAX` — every domain-scoped local and
interface-NAT lookup (healthy, tagged-only, GRE-inner, and degraded arms)
failed closed for all VLANs on that parent.

## Fix
- Shim: key the map by `UserspaceIngressDomainKey { ifindex, vlan_id,
  reserved }` under the new pin name `userspace_ingress_domains_vlan`
  (8192 entries); resolve through one `#[inline(never)]`
  `ingress_domain_for(ifindex, &parsed)` — untagged frames use the
  `0xffff` sentinel, priority-tagged VID 0 keeps VID 0. Both the healthy
  and ctrl-disabled sites use it.
- Go: `buildUserspaceIngressDomainEntries` derives the desired rows —
  an untagged row per adjudicated ifindex from rows sharing that exact
  ifindex, a `(parent, VID)` row per VLAN unit, native-VLAN units owning
  the parent's untagged arrivals, conflicting claims poisoned to
  `0xFFFFFFFF`, disabled rows skipped. `syncIngressDomainMapLocked`
  reconciles by iterating the live map (WG-zone pattern) so previous-daemon
  rows are reaped. Capacity (8192) is preflighted before any classifier
  write; the fail-closed caller leaves ctrl unchanged on refusal.
- Migration: the new pin name orphans the legacy ifindex-only pin; the
  loader reconciles the new map like the disposable counter, removes the
  legacy pin, and excludes the map from the live-pin ABI refusal set.
  The userspace-dp WG kernel-path reader's pin path follows the rename.
- Drive-by, called out in the PR: remove one duplicate closing brace in
  `try_xdp_userspace` that #14645 left on master (filed as #14850); the
  pristine master shim did not parse.

## Tests
- `ingress_domains_vlan_14842_test.go`: per-VID builder entries,
  conflicting-VID poisoning, native-VLAN untagged ownership, map
  sync + full reap, capacity-vs-shim binding, and a BPF test-run cell —
  VID 50 local traffic passes in its own domain; VID 80 does not inherit
  it. RED pre-fix: the producer test failed to compile
  (`buildUserspaceIngressDomainEntries` undefined); the BPF cell's
  KeySize-4 fallback can only state one domain per ifindex.
- Existing 13929/14644 foreign-domain BPF cells and 6537/13929/12055
  ingress fixtures pass with the re-keyed test maps.

- Producer/regression tests pass; the privileged BPF run passes
  `TestUserspaceXDPResolvesIngressDomainPerVLAN14842` (both cells),
  `TestUserspaceXDPDoesNotPassForeignDomainInterfaceNAT14644`, and
  `TestUserspaceXDPDoesNotPassForeignDomainLocalAddress13929`.
- Shim regenerated: 908732 processed insns (9.13% headroom). Master

  OVERRIDDEN honestly.

## Risk
New pin name orphans legacy pinned maps, mirroring #13929/#14644; a
mixed-version daemon/shim pair fails map lookup loudly rather than
silently sharing the old ABI. Conflicting (ifindex, VID) ownership and
missing rows resolve to `u32::MAX`, which matches no domain-scoped
local/NAT entry — fail-closed, as before for ambiguous parents.
- Operator note: `docs/operations/userspace-shim-pin-recovery.md` records
  that this rename needs no manual pin step on upgrade.
