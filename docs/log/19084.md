    starts. The TestMain redirects stay as defence in depth; the residue

    `/run/xpf`, `/var/log/xpf`, `/etc/kea`, `/etc/swanctl`, `/etc/sudoers.d`

    `scripts/testguard-overlay-selftest.sh` (`make test-testguard-overlay`,
    in `make vm-test-root`).
  - **Design checks** (the coordinator's two):
    - A test's own writes stay visible: the command and everything it
      starts share the mount namespace. The selftest's stand-in writes,
      rewrites, chmods and deletes in every covered tree and reads each back
      in-process and from a child process; it passes on both root paths. In
      the whole-package run, every failure at the overlay head either also
      fails without the overlay or passes alone under it (below).
    - Host daemons keep the real paths: the overlay exists only inside the
      test's mount namespace, so systemd-networkd, journald and the incus
      agent never see it. Nothing in pkg/daemon needs a host daemon to act on
      a file it wrote; one that did would be writing host state, which is
      what this prevents. Hidden in the namespace: the submounts under `/run`
      (`/run/user/<uid>`, `/run/credentials/*`, `/run/incus_agent`), which
      read as empty directories there; no test uses them.
