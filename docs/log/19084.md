- **What changed** (spec item → implementation):
  1. **Whole-root overlay (Codex F1, R18 R2).**
     - `/` is an overlay: the host root filesystem is the lower layer,
       and a tmpfs on the run's scratch is the upper.
     - The script `pivot_root`s into the view and lazily detaches the old
       root, so the host root filesystem is attached nowhere in the
       run's namespaces.
     - Every other mount is classified by type and depth:
       - `/proc`, `/sys`, `/dev`: bound in recursively;
       - `/run`: its own overlay;
       - storage types (ext2/3/4, xfs, btrfs, f2fs, tmpfs, overlay, zfs):
         overlaid;
       - vfat, msdos, exfat, iso9660, squashfs, erofs, udf: bound in
         READ-ONLY;
       - any other type (including an automount outside the pseudo
         trees): refused, exit 2.
     - Pass-through (the only writable host storage): the checkout,
       TMPDIR's scratch, GOCACHE, GOMODCACHE, GOTMPDIR. They are
       canonicalised, and a system tree as a pass-through refuses the
       run.
  2. **Codex F2.** cwd is re-entered inside the view (a refusal if it is
     unreachable). Every descriptor above 2 is closed before exec.
  3. **Codex F3.** `id -u` is run once and must be numeric and equal the
     shell's `$EUID`; otherwise the run is refused with exit 2.
  4. **Codex F4.** The selftest runs `systemd-detect-virt --vm` (the
     `mark-test-vm.sh` predicate) before it touches the proof or seeds
     anything. Every later host mutation is announced through a trace
     hook that the F4 cell checks is empty.

- **Three deviations, for the reviewers.**
  - **pivot_root comes from perl.** The runners (Debian forky) do not
    ship `pivot_root(8)`; util-linux moved it to util-linux-extra, which
    is not installed. The syscall is made with perl's `syscall.ph`
    (`SYS_pivot_root` = 155 on x86_64). chroot was rejected: it leaves
    the old root attached, and a CAP_SYS_CHROOT holder can escape back
    to it.
  - **vfat is bound in read-only, not overlaid.** overlayfs rejects it as
    a lower layer ("filesystem on /boot/efi not supported", probed on
    udp:xpf-testrunner). The spec's "overlay or refuse" would refuse
    every root run on these runners, because every runner has a vfat
    `/boot/efi`. Read-only keeps the spec's invariant that a mount is
    never left writable.
  - **GOTMPDIR is in the pass-through.** Go's build temp, where test
    binaries are linked, would otherwise land in the tmpfs upper.
