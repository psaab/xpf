# Issue #13306: Expose route-mask cache pressure and lookup failures

- Why: The shared FIB route-mask cache silently clears its live working set at capacity, declines background lookups at the in-flight cap, and caches failed lookups without counters. A scan can therefore collapse exported masks to unresolved `/0` values without an operator-visible explanation.
- What: Added atomic hit, miss, full-clear, in-flight-drop, and lookup-error counters plus a locked entry-count snapshot to `routeMaskCache`; exported process-wide Prometheus counters/gauge with no unbounded labels. Added deterministic cache-counter regressions and a pedantic-registry check.
- Validation: The regression failed on pristine `origin/master` (cache `Stats` API absent). `go test ./pkg/flowexport ./pkg/api -count=1`, `go vet ./pkg/flowexport ./pkg/api`, and `go build ./...` passed.
- Risk: `LookupErrors` intentionally includes both netlink errors and empty-route responses, which share the existing unresolved result. Metrics describe cache-level behavior, not individual exporter groups.
