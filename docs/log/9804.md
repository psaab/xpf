## Classification decision

The Ethernet-only AF_XDP shim cannot safely attach to a known raw-L3 link. The
refusal must remain visible because the netdev is still UP, zoned and may be
forwarded by the kernel, but it must not be mistaken for a failed Ethernet
attach. The proof therefore keeps `StillForwarding=true`, marks only the
closed set of raw-L3 `EncapType` values emitted by
`nl.IfInfomsg.EncapType` in `github.com/vishvananda/netlink/nl/nl_linux.go`
for `ARPHRD_NONE`, `ARPHRD_LOOPBACK`, `ARPHRD_SIT`, `ARPHRD_TUNNEL`,
`ARPHRD_TUNNEL6`, and `ARPHRD_IPGRE` (`none`, `loopback`, `sit`, `ipip`,
`tunnel6`, `gre`) as `Unshimmable`, and renders those records as the existing
`CoverageSkipped` branch. They remain in `Surfaces`, `Skipped`, the summary
(`surface:skipped/unshimmable`), and INFO logging, while they contribute zero to
`Uncovered`/`WouldGate`.

This is deliberately not an exemption for every non-Ethernet spelling. A
future or otherwise unknown encap value remains `CoverageUncovered` and
fail-closed. The existing `StillForwarding` behavior for missing, failed-down,
or otherwise genuinely-uncovered surfaces is unchanged; an Ethernet surface
with no instance still disarms through #7191.

The evidence is the #8279 source and issue shape: the shim parses a 14-byte
Ethernet header unconditionally, while the compiler refuses a resolved
`EncapType="none"` netdev and records it as `StillForwarding`. Attaching an
Ethernet parser to that surface would misparse attacker-selected IP source
bytes; refusing the unsafe attach is intentional. The #9804 gate classification
separates that known, impossible-to-shim surface from a real attach failure
rather than hiding either condition.
