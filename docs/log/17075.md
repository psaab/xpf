## Design fork — recorded, not blocking

The issue's acceptance names `ZonePairStream(src StanzaSource, from, to string, mode Transit|Host|View) iter.Seq[StanzaRef]` with adapters over `cfg.Security.Policies` and `[]*pb.PolicyInfo`, quarantine liveness "via R4-Q45-01's type", and "point the remote standard zone view at `ShowText zones-detail`". Three sub-decisions were not settled by the issue text and were resolved as follows (recorded here per assignment; none changes an operator-visible byte):

1. **Q45-01 dependency does not exist as a filed issue.** `gh issue list --search 'R4-Q45'` returns only #17075 (Q45-02), #17077 (Q45-03) and closed #17081 (Q45-04); there is no Q45-01 issue and no new quarantine type in-tree. The existing SSOT is `config.ZoneQuarantineExclusionsForConfig` / `config.QuarantinedZoneNames(config.ZoneQuarantineNamesForConfig(cfg))` (the #12896 scrub set). The stream stamps `StanzaRef.Quarantined` from exactly that set for config sources and from the server-stamped `PolicyRule.quarantined` for inventory sources. No new type was invented.
2. **No `pkg/policymatch -> pkg/grpcapi/xpfv1` import.** `pkg/grpcapi` imports `pkg/policymatch`; importing the generated pb package back would invert that layering (and `xpfv1` is generated code). `StanzaRef.Rule` is therefore the decoupled `InventoryRule{Name, Quarantined, Rule any}` projection; `cmd/cli` adapts each `*pb.PolicyRule` once with a literal. This preserves the issue's `[]*pb.PolicyInfo` adapter intent without the import cycle.
3. **Remote standard zone view NOT repointed wholesale.** `showZones` renders zone inventory + host-inbound + traffic counters from `GetZones`, which `ShowText zones-detail` (already used for `show security zones <name> detail`, cmd/cli/show_security.go:114) does not replace byte-for-byte. Repointing the standard view would change its non-policy sections. Instead the remote twin's zone-pair bucket switch was ported onto the same stream (`ZonePairZoneSummaryStream` over `InventoryStanzas`), so tier order and quarantine marking are single-sourced while the surrounding rendering is untouched. The detail path already delegates to `ZoneDetailPolicySummary` via `ShowText zones-detail` on both local and gRPC-text surfaces.

## Action

- Added `policymatch.ZonePairStream(src, from, to, mode) iter.Seq[StanzaRef]` (`StreamTransit|StreamHost|StreamView`), `ZonePairStreamForFilter` (prepared `ZonePairPolicyFilter` form the views use), `ZonePairZoneSummaryStream` (one-viewed-zone form), `ZonePairStanzasOrdered` (grouped form preserving per-stanza header + trailing blank line, including all-nil stanzas), and adapters `ConfigZonePairStanzas` / `InventoryStanzas`. Tier classification is the single `ZonePairPolicyFilterTier`; the stream owns nil-stanza/nil-rule skipping, tier passes, single-wildcard config-order merge, host-gate exclusion (StreamHost yields only exact/`any -> junos-host`; StreamView delegates to `ZonePairPolicyAppliesToFilterPair`), and quarantine stamping. An unfiltered view stays one config-order pass (historical `passes == 1`).
- Ported `Match` transit (3 loops -> 1 stream walk; the one remaining transit `ruleMatchesWithMemo` call site plus the global-tier site) and `matchJunosHostWithMemo` (2 loops -> 1 stream walk, exact tier gated on `zoneKnown`), `analyzeCrossTierGlobalShadowing` (per-pair `tierOf` copy + 3 nested pass loops deleted), `ZoneDetailPolicySummary` (3 tier buckets + bucket switch deleted; ids from `ref.SetIdx/ref.SliceIdx`), the 6 config-backed view loops (pkg/cli hit-count/detail/brief/standard, pkg/grpcapi hit-count/detail) and the 2+1 inventory-backed remote loops (cmd/cli standard/brief filtered + showZones summary twin).
- `ruleMatchesWithMemo(` textual count is 5 (2 stream walks + global tier in each of Match/host + definition). The issue's "returns 1" target assumed transit+host+global collapse into one call site; globals are not zone-pair stanzas and remain a separate tier in both walks, so 4 call sites + definition is the correct floor. No shim/alias left: `ZonePairPolicyFilterTier` is now called only inside `zone_pair_stream.go` (+ its definition).

## Risk

- Enforcement (`Match`) behavior is byte-identical by construction: same predicates, same first-match order, same frag-tracker notes; full policymatch suite (incl. fragment/host/quarantine corpora) green. The stream materializes stanza headers once per walk (bounded by authored stanza count; rules are refs, not copies).
- View risk is ordering/blank-line drift in grouped detail renderers; mitigated by `ZonePairStanzasOrdered` preserving empty-stanza headers and by the #12094/#12899/#12524 golden cells above.
- Remote `showZones` keeps its GetZones/GetPolicies rendering; only its zone-pair tier bucketing moved to the stream. `StreamView` without a prepared filter (no zone inventory) is documented as not for view callers — all view callers use `ZonePairStreamForFilter`/`ZonePairStanzasOrdered`.
- No cluster gate: hermetic (named-cell) validation only per campaign assignment; throughput NOT-EXAMINED (no dataplane change).
