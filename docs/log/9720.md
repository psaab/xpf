# #9720 — RG-transition worker commands dropped at a full queue are never re-driven

- **Timestamp**: 2026-09-15
- **Worktree**: `.claude/worktrees/9720-ha-rg`, branch `fix/9720-ha-rg`, base `609433efb`

## Mechanism (verified at base)

`update_ha_state` (`userspace-dp/src/afxdp/ha/state.rs`) bumps RG epochs and
stores the new RG runtime, then fans transition commands out with
`push_bounded` and ignores the `false` return at `MAX_PENDING_WORKER_COMMANDS`
(4096). The stored state already reflects the transition, so no later call
re-drives the dropped commands; the only signal is the global
`WORKER_COMMAND_QUEUE_DROPS`. Forwarding still converges (epoch bump, per-hit
re-resolution, fabric redirect), but the refusing worker keeps a stale local
origin, skips its kernel-row republish, and holds a stale CoS V_min slot until
the next transition/expiry/incidental republish.

## Plan v1 → hostile reviews → adjudication

Plan v1: per-worker transition-debt statics + **tail-requeue** redrive inside
`apply_worker_commands` + worker-loop epoch gate + register-clear + 3
per-command counters. Two hostile plan reviews ran BEFORE implementation
(`Eng9720.HostilePlanReviewA`: correctness/ordering; `Eng9720.HostilePlanReviewB`:
concurrency/perf/tests/scope). Adjudication:

**Accepted (changed the design):**
- A1/B2 BLOCKER (ABBA): queue guard held across debt record vs debt guard
  across queue lock. → Pinned leaf-lock discipline: record drops the queue
  guard first; take releases before dispatch; handlers run guard-free.
- A2 P1 (order inversion): tail-requeue dispatches stale debt AFTER
  debt-window arrivals → spurious TX cancels. → **Redesigned to
  dispatch-ahead**: debt dispatches BEFORE the drained slice (chronological),
  no re-queue at all.
- A7 P2 (unreachable gate): record⟹full queue + worker-only drain means
  debt-with-empty-queue never occurs. → **Deleted the epoch gate AND the
  epoch array**: unconditional take at apply entry; no `loop_body` change, no
  per-pass cost, no steady-state cost at all.
- A3 (shared snapshot for Refresh+prewarm), A5 (const-repeat init + `.get()`
  bounds checks), A6 (uniform #1807 poison policy for the debt lock),
  A4/B5-doc (prewarm-drop deferral rationale in code), B4 (worker-id survey +
  renumber + clear-on-entry), B5-cell (partial-slot split cell),
  B7-cell (empty-queue white-box cell), B9 (both-bump + exact #6641 spellings
  + serde pins + monotonic asserts), B10 (redrive-once asserts).

**Rejected with evidence:**
- B1 BLOCKER (stale replay after flap): dispatch-ahead preserves chronology;
  debt lifetime is ~1 pass (record⟹full; the ONLY production drain is
  `apply_worker_commands`, which takes before draining) while transitions are
  watchdog-paced seconds apart, so debt never spans transitions; handlers are
  state-parameterized and the newest command keeps the last word. End state ≡
  the never-dropped interleaving. No guard needed.
- B3 (id ripple): demote loop needed only `.values()`→`.iter()` (zero ripple);
  activation keeps `collect_live_worker_commands` byte-identical (9900 test
  untouched) and adds an id-keyed loop with uncounted `is_dead` skip; shed
  widths unchanged.
- B8 (atomic flag): the take is per-apply-call on the command path only
  (~20 ns uncontended); steady-state no-command passes pay zero. A flag dance
  would add a lost-wakeup race class for no measurable gain.
- A7-half (slot-dispatch assert): the vacate FLAG is `apply`'s entire
  contract (session_glue order-pin precedent); slot dispatch needs a full
  worker harness.
- Plan B (headroom reserve): rejected — cannot guarantee delivery (reserve
  still fillable), touches every producer. Plan C (coordinator repair):
  rejected — worker-local table/rows/slots unreachable from that thread.

## Implementation (Plan v2)

- `afxdp/worker_queue.rs`: `HaTransitionDebt { demote, refresh, vacate }` +
  `HA_TRANSITION_DEBT` static (const-repeat init, `.get()`-guarded) +
  `record/take/clear_transition_debt` + `HA_TRANSITION_{DEMOTE,REFRESH,VACATE}_DROPPED`.
- `afxdp/ha/state.rs`: id-keyed demote loop (guard dropped before record);
  activation shares ONE records snapshot between `collect_live` and the new
  id-keyed Refresh loop (`is_dead` skip, no double-shed); prewarm scope note.
- `afxdp/session_glue/mod.rs`: `apply_worker_commands` takes debt FIRST and
  dispatches Demote→Vacate→Refresh (emission order) into the shared
  accumulators; early returns became fall-throughs so debt effects reach the
  caller on every path (incl. contended/empty).
- `afxdp/coordinator/worker_manager.rs`: `register` clears the slot
  clear-first (never eats fresh debt).
- Status: 3 `*_total()` accessors + 3 serde-default `ProcessStatus` fields +
  populate lines (#6641 gate satisfied) + round-trip/legacy pin +
  `protocol_wire_v1.json` regen (drift was exactly the 3 new keys) +
  exhaustive literal in `server/lifecycle.rs`.
- Untouched by design: `worker/loop_body` (no gate needed), `WorkerHandle`
  (no new field), prewarm Upserts (named-members scope), Go/Prometheus
  (follow-up; JSON status carries the counters now).

## v3 redesign (parent review SPLIT on PR #10141)

- **Base SHA reconcile**: lane base was `609433efb` (origin/master at lane
  start); rebased onto `e990f30fb` (#9752/#9810/#9812 merges) for PR #10141.
  Conflicts (3, all mechanical): ha_tests tail append-append vs #9752 tests
  (kept both), ha_tests debt_shape helper vs #9752 block (kept both),
  loop_body epoch-init adjacency vs #9752 purge init (kept both); plus 3 new
  `install_table_{domain,check}: 0` fields on literal SessionDecisions (new
  master convention). No design change in the rebase.
- **What the parent broke**: v2's "debt older than every queued command" is
  BACKWARDS — `push_bounded` refuses the NEWEST, so the refused transition is
  newer than the full backlog. Dispatch-ahead then runs transitions before
  older queued mutations (GPT-1 killer, reproduced as R1: stale reverse
  installs verbatim after the debt-refresh missed). And v2 strands debt
  permanently when the producer is descheduled between queue-unlock and record
  (GPT-2: worker drains all + takes empty, records land after, nothing wakes
  an idle worker) with no failback guard (stranded demote flips new local
  origins).
- **v3 mechanism**: ordered debt op log + positional countdown + epoch
  scheduling + dispatch-time state filter:
  - Each refused push appends an op `{kind, rgs, remaining}` where `remaining`
    is the backlog length read under the queue guard at refusal (always 4096
    in production — every prod push goes through `push_bounded`, verified).
    FIFO means those 4096 ARE the pre-transition backlog, so decrementing per
    drained command dispatches the op exactly at its true position (after
    backlog, before post-transition arrivals), bounded by ~1 slice either way.
  - The queue-empty clause (dispatch ready-or-not when the drain observes
    empty, from the slice critical section — no re-lock) is load-bearing: it
    covers record-race overstatement (len read under guard, record after
    release) AND the GPT-2 deschedule shape. Without it an overstated
    countdown with nothing left to drain would strand forever (pinned by R3b).
  - Record-time per-RG supersession (strip RG from older ops) + dispatch-time
    state filter (demote iff !active incl. absent-removal; refresh iff
    active; vacate unconditional) make cross-transition debt safe: newer
    transitions supersede older debt for the same RG, and anything stale that
    survives to dispatch is skipped + counted (O8 skip counters).
  - Epoch bumped after every slot write; the worker loop samples it EVERY
    pass and applies on change even with an empty queue
    (`should_apply_worker_commands` + source-scan wiring guard, #7201
    pattern); last-observed consumed after apply; `transition_debt_pending`
    carry covers contended-with-empty (real: tunnel drain-wait polls queues
    read-only). Steady-state cost: one relaxed load + ORs per pass.
- **v3 re-reviews (before implementing)**: `Eng9720.V3ReviewOrder`
  (ordering/correctness) + `Eng9720.V3ReviewSched` (scheduling/concurrency).
  - O1/O2 MAJORs (demote-after-news loss; drain-boundary starvation — the
