# Issue #13642: count RX telemetry once across PMech replay

## Why

A native reverse packet pending PMech ownership is counted by
`record_rx_descriptor_telemetry` on its original RX arrival. Once the owning
session becomes live, the held descriptor is processed again from
`pending_pmech_replay`; the shared poll loop called the RX telemetry helper
again, double-incrementing RX packet/byte counters and debug counters for one
received descriptor.

## What

The poll loop now distinguishes descriptors taken from the PMech replay queue
from fresh received descriptors, and gates RX telemetry on both not being
injected and not being a replay. This retains the existing behavior for fresh
native RX (counted once) and injected packets (never RX-counted), while replayed
native descriptors do not add a second RX count. Added #13642 regressions for
the replay gate and native/injected parity. No queue ownership or packet
forwarding behavior changed.

## Validation

- RED: with the old `!is_injected` telemetry gate restored,
  `cargo test --bin xpf-userspace-dp pending_pmech_reverse_holds_and_replays_on_arrival_binding_13642 -- --nocapture`
  failed on the native descriptor's replay pass: `dbg.rx` was 1, expected 0.
- GREEN: the same native replay test passed with the `was_replay` gate enabled.
  It asserts `dbg.rx == 1` and the frame byte count on first arrival, then
  `dbg.rx == 0` and zero RX bytes on the injected-triggered replay pass.
- `cargo test --bin xpf-userspace-dp tests_policy_inbound_nat -- --nocapture`:
  26 passed.
- Full `cargo test --bin xpf-userspace-dp` (before rebase): 7959 passed,
  8 ignored, 1 failed (`afxdp::tests_9950::f035_parked_fragment_overlap_is_rechecked_on_retry_10659`,
  parked-head expected 1, observed 0). The isolated failure reproduced on
  both PR branch and pristine master `4f69977`, so it is base-attributed.

## Risk

RX counters for packets deferred and replayed by PMech are corrected to count
the descriptor's original receive once rather than counting its second
processing pass. No other operator-visible behavior changes.
