- **Decision on legitimate empty renders**: the compiler permits an empty
  filter as a configuration shape, but an empty lo0 RE-protection render is
  never a legitimate successful installation: it creates a policy-accept base
  chain with no enforcement and is weaker than the prior state. The daemon
  therefore refuses both empty and match-nothing renders unconditionally. On
  cold start, refusal additionally follows the existing #6476 fail-closed fence
  path; with a real table already loaded, the prior table is retained and no
  fence is installed.
  A renderer-drift zero is different: InstallLo0 has already atomically
  replaced the live table with the empty shell, so the daemon clears
  `lo0Enforced` and installs a current-snapshot #6476 fence even on day 2.
  Cold-start drift must fence for the same reason—there is no safe table to
  retain after the empty replacement.
- **Change**: `pkg/daemon/daemon_nft.go` preflights the retained text-oracle
  lowering (`lo0RenderedRuleCount`) before invoking the atomic netlink
  installer. A zero count returns an error and emits a warning naming the
  refusal (`replace the live table with an empty policy-accept shell`), so the
  installer cannot swap the live table. The existing installer return count is
  retained as a renderer-drift guard that clears the latch, installs a
  current-snapshot fail-closed fence, and returns an error rather than silently
  claiming success. Non-empty renders keep the existing install and
  `lo0Enforced` behavior.
