# Issue #15009: BGP `loops N` copied verbatim to `allowas-in N` (off by one)

## Why

Junos `loops N` (Autonomous-System/local-as semantics: route hidden when
local AS detected >=N times; `loops 1` = default, 0 allowed; family
`loops` documented as "discarded if detected more than N") and FRR
`allowas-in K` (route filtered when count > K; no line = 0 allowed;
bare = 3) count from opposite sides of the threshold. xpf stored the
authored `loops` value in `BGPNeighbor.AllowASIn` and
`renderBGPAllowASIn` (`pkg/frr/bgp_allowas_in_11795.go`) emitted it
verbatim, so every peer with `loops` accepted one more local-AS
occurrence than Junos — e.g. `loops 1` (Junos: reject any own-AS path)
rendered `allowas-in 1` (accept one).

Strongest refutation considered: Junos family-`loops` prose ("allowed
N, discard >N") would make verbatim correct. It is outweighed for the
leaf xpf accepts (BGP group/neighbor `loops`, not
`family ... loops`): the Autonomous-System `loops` definition, the
`loops 2` worked example ("can appear up to one time ... hidden if
detected two or more times"), FRR's separate local-as check (permits
1 occurrence of the local-as AS when no allowas-in is set, mirroring
Junos's default `Loops: 1`), and the issue's Junos-equivalence
acceptance (`loops 1` emits nothing, `loops 2` emits `allowas-in 1`).

## What

- `pkg/frr/bgp_allowas_in_11795.go` (`renderBGPAllowASIn` only; issue's
  anchored mechanism — compiler/storage unchanged, `AllowASIn` still
  holds the authored Junos `loops` value so validation, warnings and
  config round-trip keep Junos spelling): `loops 1` emits no line,
  `loops N>=2` emits `allowas-in N-1`. Range gate unchanged: 0 = unset
  (no line, no warn), out-of-range tolerant-load values still omitted
  with the #11795 warning (fail-closed, no whole-batch failure).
- Tests updated where they pinned the verbatim spelling:
  `TestGenerateProtocols_BGPAllowASInRange11795` (1->none, 10->9),
  `TestGenerateProtocols_BGPAllowASIn` and the #11460 AF-scope test
  (loops 2 -> `allowas-in 1`; AF placement unchanged).
- `pkg/frr/README.md`: documented the N-1 contract.

## Regression

`TestGenerateProtocols_BGPAllowASInLoopsOffByOne15009`
(`pkg/frr/bgp_allowas_in_11795_test.go`): loops 0 (control, no line),
1 (no line), 2->1, 3->2, 10->9 across inet and inet6 families, verbatim
spelling asserted absent, plus out-of-range (-1/11/999999) no-line +
warning controls. RED on origin/master (6eeff22941): all non-zero
loops cells failed with the verbatim line (e.g. loops 2 rendered
`allowas-in 2`); loops-0 control passed. GREEN after the fix (see PR).

## Risk

Only peers with `loops` configured change, and only by accepting one
fewer own-AS occurrence — the Junos behaviour the operator configured.
Unset/invalid handling, AF placement, and all other neighbor
attributes are untouched. Live Junos-vs-FRR route-acceptance (run3.sh)
was not run in this lane; render-level Junos equivalence is pinned by
the regression above.
