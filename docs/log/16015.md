# Issue #16015 — nat: pool SNAT can mint inside NPTv6 external prefix (A2-C7)

- **Issue:** The strict gate owner list (`natPoolOverlapOwners`) enumerated pools+NAT64+interface only, with no NPTv6-external owner; `validateStaticNATPoolOverlapStrict` explicitly skipped `rule.IsNPTv6`; the runtime pool mint checked peer/iface/static only. NPTv6 publishes statelessly with the port unchanged, so no occupancy bit exists to consult — a referenced v6 pool (or v6 interface egress) inside an NPTv6 external prefix could mint the same `(address, port)` NPTv6 emits for a different host, and the reverse NAT index cannot disambiguate the return flow.
- **Fix (Go):** Dedicated `validateNPTv6PoolOverlapStrict` paired against the shared non-static owners (not another `#5144` sweep owner, so NPTv6-vs-NPTv6 stays owned by `#2241`). It enumerates only INSTALLED NPTv6 external prefixes (scope-dropped `#5818`/`#9877`, tolerated undefined-zone `#16008`, and unparseable/mismatched rules excluded — mirroring `buildNptv6Snapshots`), zone-gates pool owners on the source rule-set's egress (to-) zone vs the NPTv6 from-zone (`zonesConflictNPTv6`, the `#5176` axis `translate_outbound` uses), and is zone-blind (conservative) for NAT64/interface owners. Wired in `runTailGates` (strict rejects, lenient warns via `emitNATOverlap`, `#1960`) and in the peer-effective view (`#5876` mirror).
- **Fix (Rust):** `Nptv6State::external_prefixes_zoned` + free `nptv6_prefix_contains`; `wire_nptv6_overlap_peers` (after `state.nptv6` is built in `forwarding_build`) hands the zoned prefixes to pool rules they cover as `SourceNatRule::nptv6_externals`. Pool PAT/address-only mints (zoned on the packet's `to_zone`, zone-blind only in the allocator probe), interface-mode mints (via sibling pool rules), and HA synced reserves refuse with `PoolPeerAddressOverlap` / `InterfaceIdentityExhausted`. NAT64 pools are v4-only, so no NPTv6 field is wired there (documented at the wiring point).
- **Tests:** Go `compiler_nptv6_pool_overlap_16015_test.go` (pool host/CIDR inside prefix rejects strict + warns lenient; outside, unreferenced, disjoint-zone, and scope-dropped controls accept). Rust `tests_nptv6_pool_overlap_16015.rs` via `build_forwarding_state` (mint inside refuses, with the checksum-neutral claimant asserting NPTv6 really publishes the pool address; outside/disjoint-zone/no-NPTv6 controls mint).
- **Pre-existing:** `tests_nat64_overlap_8115` 2 cells fail identically on unmodified `origin/master` (verified by stash) — untouched by this change.
