# Issue #16015 — nat: pool SNAT can mint inside NPTv6 external prefix (A2-C7)

- **Issue:** The strict gate owner list (`natPoolOverlapOwners`) enumerated pools+NAT64+interface only, with no NPTv6-external owner; `validateStaticNATPoolOverlapStrict` explicitly skipped `rule.IsNPTv6`; the runtime pool mint checked peer/iface/static only. NPTv6 publishes statelessly with the port unchanged, so no occupancy bit exists to consult — a referenced v6 pool (or v6 interface egress) inside an NPTv6 external prefix could mint the same `(address, port)` NPTv6 emits for a different host, and the reverse NAT index cannot disambiguate the return flow.
- **Fix (Go):** Dedicated `validateNPTv6PoolOverlapStrict` paired against the shared non-static owners (not another `#5144` sweep owner, so NPTv6-vs-NPTv6 stays owned by `#2241`). It enumerates only INSTALLED NPTv6 external prefixes (scope-dropped `#5818`/`#9877`, tolerated undefined-zone `#16008`, and unparseable/mismatched rules excluded — mirroring `buildNptv6Snapshots`), zone-gates pool owners on the source rule-set's egress (to-) zone vs the NPTv6 from-zone (`zonesConflictNPTv6`, the `#5176` axis `translate_outbound` uses), and is zone-blind (conservative) for NAT64/interface owners. Wired in `runTailGates` (strict rejects, lenient warns via `emitNATOverlap`, `#1960`) and in the peer-effective view (`#5876` mirror).
- **Fix (Rust):** `Nptv6State::external_prefixes_zoned` + free `nptv6_prefix_contains`; `wire_nptv6_overlap_peers` (after `state.nptv6` is built in `forwarding_build`) hands the zoned prefixes to pool rules they cover as `SourceNatRule::nptv6_externals`. Pool PAT/address-only mints (zoned on the packet's `to_zone`, zone-blind only in the allocator probe), interface-mode mints, and HA synced reserves refuse with `PoolPeerAddressOverlap` / `InterfaceIdentityExhausted`. NAT64 pools are v4-only, so no NPTv6 field is wired there (documented at the wiring point).
- **Fold (PR #16357):** (1) Interface-only SNAT now carries the view itself — `wire_nptv6_overlap_peers` wires `interface_mode` rules unconditionally (egress is runtime-resolved) and the mint checks own-then-sibling views; previously an interface-only config had no pool rule to carry it and minted inside the prefix. (2) HA imports check before success: a dynamic (non-NPTv6-bit, non-static) synced `rewrite_src` owned by a covered pool rule's NPTv6 view refuses at the top of `reserve_synced_source_nat_allocation_with_holder` — before `owns_no_reservation`/PASS/interface success returns — and `reserve_synced_interface_identity` refuses inside-prefix imports before booking. Genuine NPTv6-bit/static imports still take the #15191 no-reservation success.
- **Tests:** Go `compiler_nptv6_pool_overlap_16015_test.go` (pool host/CIDR inside prefix rejects strict + warns lenient; outside, unreferenced, disjoint-zone, and scope-dropped controls accept). Rust `tests_nptv6_pool_overlap_16015.rs` via `build_forwarding_state` (pool mint inside refuses with checksum-neutral claimant; interface-only mint inside refuses / outside mints; HA pool + HA interface imports inside refuse before success / outside reserves; controls mint).
- **Pre-existing:** `tests_nat64_overlap_8115` 2 cells fail identically on unmodified `origin/master` (verified by stash) — untouched by this change.
