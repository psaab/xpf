# #10066 tick-retry adoption must not regress a spawned process identity

Issue: psaab/xpf#10066. Lane branch: `fix/10066-tick-stale`.

## Context

#10066 was filed during the #10064 review. The #10064 narrowing stopped
same-generation tick debt retention, but a conflict retry still changes the
attempt generation in place. #9824 supplies the lost-response/retry-generation
shape and the generation-adoption contract.

`ensureProcessLocked` writes `m.cfg` as soon as it starts a replacement helper.
A later protocol-gate, disarm, or publish failure can return with
`lastSnapshot` still OLD while `m.cfg` already describes the spawned NEW
identity. With retry debt open, the status tick republishes the retained OLD
snapshot. A content conflict consumes the retained generation and changes the
retry to the next generation; if that retry lands but its response is lost,
the retry-debt adopt arm correctly consumes/adopts that generation but can also
copy the retained OLD `Userspace` into `m.cfg`. The next crash respawn then
uses the stale identity, and a subsequent commit needlessly kills and respawns
the helper.

## Fix

The retry-debt arm now snapshots the retained process-identity baseline before
replacing `m.lastSnapshot`. It compares identities with the existing
`configEqual` spawn predicate:

- A tick retry carries the retained snapshot's `Userspace` identity. If
  `m.cfg` no longer matches that baseline, it describes the newer spawned
  helper, so the adopt arm keeps `m.cfg` unchanged.
- A Compile-differ carries a different `Userspace` identity and still updates
  `m.cfg` as before.
- The generation/retained-snapshot adoption, retry-debt mark, HA obligation,
  and warning behavior are unchanged.

This pins the invariant in the adopt arm without changing
`publishSnapshotFailClosedLocked` or either #4959/#5488 call signature/call
text.

## Tests

Added `tick_stale_adopt_10066_test.go` with the real deferred-sync and
apply-snapshot retry seams:

- `TestTickRetryDivergedSpawnPreservesMcfg10066`: OLD retained snapshot,
  NEW spawned identity, conflict followed by lost retry response; verifies
  retry generation 9 is consumed while `m.cfg` remains NEW.
- `TestTickRetryCleanSpawnKeepsMcfg10066`: clean NEW/retained identity control
  through the same conflict/lost-response trace.
- `TestTickSameGenDivergedPreservesMcfg10066`: #10064 same-generation control;
  retention remains skipped and NEW `m.cfg` remains untouched.
- `TestCompileDifferStillAdoptsMcfg10066`: genuine Compile-differ control;
  adopted NEW identity is still written to `m.cfg`.
