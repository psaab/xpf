# #16871 — Chained `xpf` + `default-export` forges the reserved default-export route-map (R3-B08-03)

- **Timestamp**: 2026-10-25
- **Action**: Legal policy names `xpf` + `default-export` chained in that order
  compose (`composedChainName`) into the reserved generated route-map
  `xpf-default-export-xpf-chain` (#15157). No belt checked that pair:
  `bgpComposedChainCollision` special-cased only the #7625 emptied-chain deny,
  and `bgpDefaultExportCollision15157` only checked an operator
  policy-statement NAMED the reserved name — so FRR merged the composed map
  with the generated default-export map, corrupting both filters with a clean
  commit and a clean apply. Fix: one table of fixed generated route-map names,
  `reservedGeneratedRouteMaps16871` in `pkg/frr` (emptied deny #7625 +
  default export #15157), consulted by `bgpComposedChainCollision` (replacing
  the hand-written emptied-only comparison) and by the narrowed-alias belt;
  the strict commit path gains `validateBGPComposedChainReservedNameStrict`
  (`pkg/config`, wired beside the existing suffix gate in `runUniformGates`,
  lenient-warn on load/peer-sync per #1960) which resolves referenced BGP
  chains exactly as the renderer does (via the `bgpComposedChains` mirror)
  and rejects any whose composed name is in `config.ReservedGeneratedRouteMaps16871`.
  The false "not derivable by composedChainName" claim in
  `bgp_default_export_15157.go` is corrected. Membership is enumerated
  once, in `config.ReservedGeneratedRouteMaps16871`; pkg/frr derives its
  render-side registry from that list (the frr name constants alias the
  config constants), so a future fixed generated name needs one new
  config entry instead of a new hand-written belt.
- **Validation**: New `pkg/frr/bgp_reserved_generated_chain_16871_test.go`
  (6 cells: registry derived from the config enumeration covers both fixed
  names and each is derivable, derived registry matches the config
  enumeration, forge `[xpf default-export]` fails closed naming the map,
  generated definition witnessed independently of any forged chain,
  one-fixture ApplyFull refusal before any write/reload, emptied control
  still fails, ordinary `[LOCAL TRANSIT]` control passes) and
  `pkg/config/policy_reserved_generated_chain_16871_test.go` (4 cells: strict
  reject for both forges, lenient warns, ordinary chain accepted). RED on
  pre-fix code (config cells fail with clean compile; frr probe showed
  `bgpComposedChainCollision([xpf default-export]) == nil`), GREEN after.
  Full `go test ./pkg/frr/ -count=1` green; `pkg/config` targeted cells
  green (the full config suite carries pre-existing origin/master failures
  in unrelated cells, none chain/reserved-related).
- **Risk**: Fail-closed only on the forged joins: a config chaining exactly
  `[xpf default-export]` (or `[xpf emptied chain]`) now fails commit (strict)
  or the FRR apply (tolerant path) instead of silently merging filters;
  renaming any chain member restores the apply. No render output changes for
  any non-forging config.
