# #13115 — inspect every unit for bare management-zone members

- **Source**: deep-review finding D1-11, validated by three-way adversarial research.
- **Files**: `pkg/config/userspace_mgmt_zone_advisory_10308.go`,
  `pkg/config/userspace_mgmt_zone_advisory_10308_test.go`.

## Why

The `#10308` advisory treats a bare interface zone member as applying to all
configured units, but its data-class check inspected only unit 0. A tunnel on
unit 0 therefore hid data on another unit, suppressing a needed warning; a
non-zero-only tunnel incorrectly caused a warning.

## What

For bare interface refs, classify the member as data if any configured unit is
nil or is not a tunnel, matching the zone member's all-units expansion. An
interface with no configured units retains its previous unit-0 fallback. An
explicit unit ref continues to inspect only that unit. The regression table
covers unit-0 tunnel plus unit-1 data, non-zero-only tunnel, all-tunnel units,
and a nil unit alongside a tunnel.

## Validation

- Focused regression tests for `#13115` and the affected `#12830` case:
  `go test ./pkg/config -run 'TestMgmtControlZone(BareInterfaceMultiUnitTunnel13115|BareUnknownAndNonZeroTunnel12830)$' -count=1`: GREEN.
- `go build ./...`: exit 0.
- `go vet ./pkg/config/`: exit 0.
- Full `go test ./pkg/config -count=1 -timeout 30m` on the rebased head:
  GREEN (`408.752s`).

## Risk

The advisory remains non-blocking. This aligns its config-time classification
with the existing all-units interpretation of bare zone members; explicit-unit
and no-units behavior are unchanged.
