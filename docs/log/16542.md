# #16542 — publish gate must bind channel/suite identity

- **Timestamp**: 2026-10-24 (`fix-16542`)

## Why

`publish.py _gate_one_latest` verified the signature, JSON shape, date,
and (target only) version membership of each `latest.json`, but never
checked `data["channel"] == channel`. `gate_apt` verified each suite's
InRelease signature and freshness but never compared the signed
`Suite`/`Codename` with `dists/<suite>`. The same signing key signs every
channel/suite, so a mis-synced signed edge pointer at `stable/latest.json`
(or `Suite: edge` at `dists/stable`) passed the gate, was uploaded, and
was then refused by every client (`xpf-deploy fetch`, `install.sh`
verify_channel) — a channel outage reported as "gate PASSED".

## What

- `scripts/dist/publish.py`: `_gate_one_latest` now requires
  `data.get("channel") == channel` (absent refuses) on verified bytes,
  covering target and non-target pointers via `gate_latest`. New
  `_gate_apt_suite_identity(suite, release_text)` requires exactly one
  signed `Suite` and one `Codename`, both equal to the suite directory,
  judged on the signed cleartext (`gpg --decrypt` output), mirroring
  `_gate_apt_freshness`; `gate_apt` calls it for every suite.
- Regression: `scripts/dist/test_publish_channel_identity_16542.py` —
  unit cells for suite identity (wrong/missing/duplicate/continuation),
  signed-pointer cells (genuine passes; wrong-channel at target and
  non-target and missing-channel refused), and end-to-end `gate_apt`
  cells over real signed flat suites (genuine passes;
  `dists/stable` signed `Suite: edge` refused; misnamed non-target
  refused).
- Docs: gate contract in the `publish.py` module docstring,
  `scripts/dist/README.md` publish row, and `docs/distribution.md`.
- NOT changed: client-side checks in `xpf-deploy.py`/`install.sh`
  (already fail closed), signature/freshness/Packages/key-agreement
  behaviour, or `make_latest` (its overwrite guard already checks the
  previous pointer's channel).

## Validation

- **RED on base**: the new test file copied onto a detached
  `origin/master` worktree (3027e34128) fails (5 failures, 8 errors of
  15; genuine controls pass).
- **GREEN**: `python3 -m unittest scripts.dist.test_publish_channel_identity_16542`
  — 15 passed.
- **Neighbours**: apt freshness / reprepro / binding / multi-key /
  provenance / snapshot suites run with this change (see PR body).

## Risk

A publish whose tree contains a pointer or suite naming another
channel/suite (including a missing `channel`/`Suite`/`Codename` field)
is newly refused; rebuild/re-sync that artifact. Genuine builds
(`make_latest` always writes the matching channel; `build-apt-repo.sh`
always emits matching Suite/Codename) are unaffected. No dataplane,
cluster, or client behaviour changes; checks run on
signature-verified bytes only and remain fail-closed.
