# Issue #15690: Operational VRRP inspection parity (show vrrp / RETH instances / GetVRRPStatus canonical command)

- **Timestamp**: 2026-10-19
- **Action**: local CLI `CLI.showVRRP` (`pkg/cli/cli_show_routing.go`) now appends `vrrp.CollectRethInstances(cfg, c.cluster.LocalPriorities())` when `c.cluster != nil`, matching the gRPC `GetVRRPStatus` and REST `/vrrp` handlers. Previously it collected only generic per-interface `vrrp-group` instances and printed "No VRRP groups configured" on a chassis cluster whose VIPs live on RETH instances.
- **Action**: added the top-level Junos spelling `show vrrp` to `cmdtree.OperationalTree["show"]` (`pkg/cmdtree/tree.go`) and wired `case "vrrp": return c.showVRRP()` in both dispatchers (`pkg/cli/cli_show.go`, `cmd/cli/show.go`). `show security vrrp` is unchanged and reaches the same rendering / RPC.
- **Action**: moved `GetVRRPStatus` from `methodsWithoutCanonicalCommand` (stale rationale "no `show vrrp` node exists") to `methodCanonicalCommand` mapped to `"show vrrp"` (`pkg/grpcapi/authz_command_table.go`), and likewise mapped REST `GET /api/v1/security/vrrp` to `"show vrrp"` in `restRouteCommand`, removing its `restRoutesNoCommand` entry (`pkg/api/authz_command_regex_9952.go`). Both entries are the same canonical string the gRPC table charges, per the table's own cross-surface rule. Regex-restricted login classes (unrelated deny, `^show ` allow) are now admitted; a deny on `^show vrrp$` refuses. Classes with no regexes are unaffected.
- **Scope note**: only the bare `show vrrp` form is implemented. The `brief`/`summary`/`detail`/`interface` sub-spellings named in the report's Junos reference are not modelled (no such modifier grammar exists on the pre-existing `show security vrrp` node either; the handlers take no selector), so no neighbouring spelling regresses.
- **Regression**: `TestShowVRRPReportsRethInstances15690` / `TestShowVRRPTopLevelDispatch15690` / `TestShowVRRPWithoutClusterIsUnchanged15690` (`pkg/cli`) drive the real `showVRRP`/`handleShow` on a committed reth0/RG-1 cluster fixture (group 101, VIP 10.0.61.1/24) with and without a cluster manager; `TestCanonicalizeShowVRRP15690` (`pkg/cmdtree`) pins both spellings plus the `show vr` abbreviation; `TestGetVRRPStatusCanonicalCommand15690` (`pkg/grpcapi`) drives `authorizeRPCCommand` under unrelated-deny, `^show ` allow, and `^show vrrp$` deny classes; `TestShowVRRPTopLevelDispatch15690` (`cmd/cli`) asserts both spellings call `GetVRRPStatus` exactly once each via a fake client.
