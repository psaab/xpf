# #12070 — validate policy next-hop and AS-path prepend operands

- **Timestamp**: 2026-10-09 (folded onto PR #12324 head `093a296d7`; stack base #12069 / `83b5c9553`)
- **Action**: reject unsupported or malformed `then next-hop` and `then as-path-prepend` values at schema validation; omit and warn when invalid values arrive through tolerant rendering paths.

## Red before

The original #12070 RED was on earlier stack base `4d27ce023`: `SchemaValidate` accepted `then next-hop discard` and `then as-path-prepend abc`. Focused FRR renderer regressions also failed on that base: `generatePolicyOptions` emitted `set ip next-hop discard`, `set ip next-hop 10.0.0.300`, `set ipv6 next-hop global 2001:db8::garbage`, `set as-path prepend 65001 abc`, and `set as-path prepend 0`. The sanitizer only prevents control-character line injection; it does not enforce FRR operand grammar. The fold-specific RED on PR #12324 head `1c818d6f0` is recorded below.

## Change

- Added shared config predicates and schema validators for the supported policy next-hop subset (IPv4/IPv6 literals, `peer-address`, and `self`) and decimal prepend ASNs in 1..4294967295. `next-hop` and every token of the multi-valued `as-path-prepend` leaf now carry typed schema validation. Junos `discard`, `reject`, and `next-table` are deliberately refused because this renderer has no FRR route-map lowering for them.
- Added render-side defense-in-depth that uses those same predicates. Invalid next-hop values and any prepend list containing an invalid ASN are omitted with `slog.Warn`; valid clauses and sibling set actions remain rendered.
- Updated the #4482 injection regression to expect malformed next-hop and prepend clauses to be omitted instead of sanitized into syntactically invalid FRR commands. Added focused config and renderer regressions for unsupported keywords, malformed addresses, ASN boundaries, repeated values, warning/omission, valid output, and sibling-clause preservation.

- The term-level `then` schema opts into `packedFlatRun`, so commit-check now
  expands the same flat action chain that `parsePolicyTermChildren` consumes.
  This catches invalid operands after an earlier action such as `accept`;
  the policy-level `then` remains unexpanded. Excluded address errors now name
  the class (loopback, IPv4 0/8, multicast, unspecified, or IPv6 link-local),
  and the comment clarifies that `self` is an xpf alias rendered as
  `peer-address`.
- The #2892 operator text distinguishes the child-path `firewallMatchValues`
  read from the separately implemented `parsePolicyTermInlineKeys` scanner (N6).

## PR #12324 fold follow-up

Fold base: PR #12324 head `1c818d6f0` (stacked on #12069 / `83b5c9553`). Folded the five confirmed hostile-review findings credited
to Codex/Astra and GLM:

- Quoted `as-path-prepend "65001 65001"` is split into individual operands
  before schema validation, compilation, and render-side validation. Both the
  CheckText path and the real Store operator `SetFromInputAs`/`CommitCheck` path
  render the committed policy as `set as-path prepend 65001 65001`.
- `then next-hop` rejects IPv4 0/8 and loopback, unspecified, multicast, and
  IPv6 link-local addresses; IPv4 link-local remains supported. The same
  boundary applies at the schema gate and tolerant renderer.
- Prepend ASNs now require canonical decimal spelling, rejecting leading
  zeroes while preserving the 1..4294967295 range. FRR accepts ASDOT such as
  `1.10`, but the config leaf deliberately remains decimal-only.
- The contradictory #4482 positive assertion was absent from original #12070
  commit `b939ca090`; it was reintroduced by #12069 commit `4e53d33a3` during
  rebasing. The stale assertion was removed, and the negative assertion remains.
- The multi-value walker now validates every key in block-list children only
  for the as-path-prepend leaf. `allChildKeysAreValues` is opt-in, so existing
  multi leaves whose compilers read only a child name retain their prior
  behavior.

Added schema/compiler, CheckText/render, real Store operator commit/render,
tolerant-render, and second-child operand regressions. The `#2892` contract in
`docs/config-schema.md` now documents the shared split, canonical decimal ASN
form, and precise next-hop address boundaries.
