# #12070 — validate policy next-hop and AS-path prepend operands

- **Timestamp**: 2026-10-09 (R5 fold atop PR #12324 commit `9d6a61955`; stack base #12069 / `83b5c9553`)
- **Action**: reject unsupported or malformed `then next-hop` and `then as-path-prepend` values at schema validation; omit and warn when invalid values arrive through tolerant rendering paths.

## Red before

The original #12070 RED was on earlier stack base `4d27ce023`: `SchemaValidate` accepted `then next-hop discard` and `then as-path-prepend abc`. Focused FRR renderer regressions also failed on that base: `generatePolicyOptions` emitted `set ip next-hop discard`, `set ip next-hop 10.0.0.300`, `set ipv6 next-hop global 2001:db8::garbage`, `set as-path prepend 65001 abc`, and `set as-path prepend 0`. The sanitizer only prevents control-character line injection; it does not enforce FRR operand grammar. The fold-specific RED on PR #12324 head `1c818d6f0` is recorded below.

## Change

- Added shared config predicates and schema validators for the supported policy next-hop subset (IPv4/IPv6 literals, `peer-address`, and `self`) and decimal prepend ASNs in 1..4294967295. `next-hop` and every token of the multi-valued `as-path-prepend` leaf now carry typed schema validation. Junos `discard`, `reject`, and `next-table` are deliberately refused because this renderer has no FRR route-map lowering for them.
- Added render-side defense-in-depth that uses those same predicates. Invalid next-hop values and any prepend list containing an invalid ASN are omitted with `slog.Warn`; valid clauses and sibling set actions remain rendered.
- Updated the #4482 injection regression to expect malformed next-hop and prepend clauses to be omitted instead of sanitized into syntactically invalid FRR commands. Added focused config and renderer regressions for unsupported keywords, malformed addresses, ASN boundaries, repeated values, warning/omission, valid output, and sibling-clause preservation.

The term-level `then` schema opts into `packedFlatRun`, so the schema
walker expands child-based action chains (including a next-hop or prepend
after `accept`) before checking their typed leaves. The walker ignores a
packed Keys tail, however, so compact `then accept ...;` and term-line
`term t then accept ...;` spellings bypassed that belt. The compiled-term
gate checks the typed next-hop value and every prepend ASN; the R5 fold also
retains the first unquoted non-action token after an inline next-hop for strict
rejection rather than silently dropping it. The policy-level `then` remains
unexpanded. Unknown garbage tails after other compact/term-line actions remain
a follow-up. Excluded address errors name their class (loopback, IPv4 0/8,
multicast, unspecified, or IPv6 link-local), and `go doc` now attaches the
`self` alias contract to `ValidPolicyThenNextHop`.
- The #2892 operator text distinguishes the child-path `firewallMatchValues`
  read from the separately implemented `parsePolicyTermInlineKeys` scanner
  (N6); the compiled-term gate covers both reads.
