# #18824 — static-verdict fixtures preserve explicit fall-through

- **Timestamp**: 2026-11-05
- **Why**: #14848 (`3587ef059c`, PR #14848/#14632) changed implicit-next semantics: a modifier-only term continues only when its snapshot carries `next_term`. These regression fixtures omitted that bit, so `mark` implicitly accepted before the terminal discard.
- **What**: Set `next_term: true` only on the four empty-action counted-mark fixture entries (the shared fallthrough shape and its three explicit test copies); leave `counted_term` and terminal-discard terms unchanged. Flush coalesced filter counters in the test counter reader so the final replayed counter is visible.
- **Validation**: Before the fix, `cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp static_verdict_7212 -- --test-threads=1` had 3 failures (`Accept` vs `Discard`). After the fix and after restoring both mutants, the same command passed all 8 tests. Reverting a mark's `next_term` failed the terminal-deny verdict assertion (`Accept` vs `Discard`); removing the counter flush failed the replay assertion (`[(1, 1500), (0, 0)]` vs `[(1, 1500), (1, 1500)]`).
- **Risk**: Test fixtures and counter observation only; no product behavior or expected assertions changed.
- **File(s)**: `userspace-dp/src/filter/static_verdict_7212_tests.rs`
