# #16520: local tunnel loop sprayed per-packet across TX bindings instead of flow-hashing

- **Timestamp**: 2026-10-24
- **Action**: `local_tunnel_source_loop` in `afxdp/tunnel.rs` chose the TX
  binding with a per-packet counter (`next_slot % candidate_count`,
  incremented for every built packet), so consecutive packets of one
  self-originated flow (BGP/LDP/ssh over GRE) landed on different
  bindings drained by different workers/queues and intra-flow order was
  not preserved. Changed `select_live_binding_for_ifindex` to take
  `plan.tx_request.flow_key` (`Option<&SessionKey>`): when present the
  target index is `ecmp_hash_flow(key) % candidate_count` (the existing
  ECMP flow hash, `forwarding::ecmp_hash_flow`, consistent with every
  other dataplane ECMP/queue choice); when `None` (flowless packets
  such as non-first fragments) it uses the fixed first bound binding.
  Removed the `next_slot` counter from the loop. No candidate-vector
  allocation was introduced — the two-pass bound-candidate count/index
  walk is unchanged, as is the fail-closed `None` result when no bound
  binding matches the TX ifindex (caller still records
  `no_live_binding_for_tx_ifindex` and drops).
  Replaced the pinning round-robin test with: same-flow stability
  (16 repeats, identical binding), distinct-flow spread (256 flows hit
  both bindings), flowless pinning to the first binding, unknown-ifindex
  `None`, and bound-only modulo (unbound/missing bindings excluded).
- **File(s)**: `userspace-dp/src/afxdp/tunnel.rs`,
  `userspace-dp/src/afxdp/tunnel_tests.rs`, `docs/log/16520.md`
- **Validation**: `cargo test --bins select_live_binding` 4 passed /
  9548 filtered; `cargo test --bins tunnel` 256 passed, 2 failed
  (`snapshot_published_tunnel_rows_join_d11_10485`,
  `tunnel_wg_nodf_oversize_emits_ptb_with_inner_mtu_10705`) — both
  fail identically on unmodified `origin/master` (pre-existing).
