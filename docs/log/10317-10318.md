# Issues 10317 and 10318 — authoritative HA bulk and sweep close fencing

These coupled HA-sync fixes cover the userspace authoritative bulk candidate walk and the Go mirror sweep. RED probes were run before each production change; the GREEN cells below were rerun after the fixes.

## #10317 — bulk exports held authoritative sessions

### RED

The fail-on-revert candidate cell was run before changing the export-origin predicate:

```text
cargo test --manifest-path userspace-dp/Cargo.toml bulk_export_includes_held_imported_promoted_and_fabric_ingress_10317 -- --nocapture
```

The cell failed because an imported-not-yet-hit `SyncImport` row was omitted from the authoritative candidates (`#10317 RED: imported-not-yet-hit SyncImport omitted from authoritative bulk`). The RED run is retained as `artifact://41917`.

### GREEN

The coordinator's same-dispatch owner-RG scope remains recorded in `WorkerCommandResults`; `SessionTable` persists demotion markers that filter deferred bulk opens and tombstones across bounded drains, and `RefreshOwnerRGS` clears the markers on explicit activation. The authoritative walk excludes worker-local replicas, transient local seeds, TUN-origin rows, reverse entries, and marked owner RGs. Held `SyncImport`, `SharedMaterialize`, `SharedPromote`, and fabric-ingress `ForwardFlow` rows remain eligible when their owner RG is active.

```text
cargo test --manifest-path userspace-dp/Cargo.toml bulk_export_includes_held_imported_promoted_and_fabric_ingress_10317 -- --nocapture
```

Result: 1 passed, 6570 filtered (`artifact://42169`). The fabric-promotion helper cell also passed (`artifact://41974`), and the original TUN-origin exclusion control passed (`artifact://41973`).

The Rev10402 TUN provenance cell first failed against the old demote flip (`TunOrigin` became `SyncImport`, artifact `artifact://42214`). After the guard, `demote_reactivate_tun_stays_local_10402` passed with the origin remaining `TunOrigin` (`artifact://42223`). `demotion_marker_clears_on_owner_rg_activation_10317` proved an active owner RG exports again after marker clearing (`artifact://42166`), and the deferred demotion authority regression passed (`artifact://42171`).

The shared-map demotion cell also failed against the old loops when a published TUN row was retagged `SyncImport` (`artifact://42273`). Guards across the shared, NAT-alias, and forward-wire demotion maps now preserve `TunOrigin`, and the demote command derives the kernel receiver-origin bit from that resulting origin; the final cell passes (`artifact://42401`).

The Rev10402 round-2 seed cells fail against the old demotion guards: the SessionTable path retags `MissingNeighborSeed` as `SyncImport` (`artifact://42671`), and the shared primary alias does the same (`artifact://42680`). The guards now preserve all transient-local origins through demotion, activation, and an origin-preserving `refresh_for_ha_transition` call; the SessionTable and all-three-alias shared tests pass (`artifact://42705` and `artifact://42707`). The regression also proves an owner-0 `FabricPuntSeed` remains excluded.

## #10318 — sweep does not resurrect a closed mirror row

### RED

The deterministic v4 and v6 pause-close-resume probes were run after temporarily restoring the old sweep stamp path. Each paused after the batch copy, removed the dataplane row, queued its delete, resumed the sweep, and observed one stale install frame:

```text
go test ./pkg/cluster -run 'TestSyncSweepPauseCloseResumeDoesNotReinstall(10318|V6_10318)$' -count=1
```

Both cells failed as intended with `#10318 RED: sweep sent 1 stale installs after the close` and the IPv6 twin's equivalent message.

### GREEN

The v4 and v6 callbacks now re-read the current dataplane row while holding the same generation fence used by close/delete stamping.
