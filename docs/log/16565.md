# #16565: managed-routing host-inbound gate ignores OSPF/OSPFv3 `passive`

- **Timestamp**: 2026-10-24
- **Action**: Skip effectively passive OSPF/OSPFv3 interfaces in
  `validateHostInboundManagedRoutingMismatch`
  (`pkg/config/compiler_validate_warn_host_inbound.go`). Previously the
  collector appended every OSPF/OSPFv3 area interface name without testing
  passivity, so the routine pattern of advertising a LAN prefix via a
  passive interface was rejected at strict commit unless the zone opened
  host-inbound OSPF — widening host-inbound exposure for no benefit, since
  a passive interface sends no hellos and forms no adjacency. OSPFv2
  effective passivity is `Passive || (PassiveDefault && !NoPassive)`
  (mirroring the FRR renderer's `passive-interface` /
  `passive-interface default` + `no passive-interface` logic); OSPFv3
  uses its per-interface `Passive` flag (it has no passive-default).
  Interfaces are deduplicated by authored name with any-active-wins
  semantics across areas/fragments, mirroring the renderer's union: a
  name passive in one fragment but active in another still requires
  admission. The `interface all` wildcard is never passive — it expands
  to every zone interface, including ones with no passive setting — so it
  still requires admission. RIP is unchanged (the issue explicitly scopes
  RIP out; RIP passive is receive-only and still receives multicast).
  Added `pkg/config/host_inbound_managed_routing_passive_16565_test.go`:
  strict/tolerant end-to-end rows for passive OSPF and OSPFv3 commits,
  active controls still rejecting, passive-default commit,
  passive-default + `no-passive` rejection, mixed passive-default where
  only the active interface is named, passive-plus-token control, and
  routing-instance OSPF/OSPFv3 passive commits with an active RI control;
  plus direct-helper pins for any-active-wins across areas, both-flags
  passivity, the `all` wildcard, and RIP isolation.
- **File(s)**: `pkg/config/compiler_validate_warn_host_inbound.go`,
