# Issue #17204 — R4-Q51-04: per-zone traffic and flood counters are two hand-kept module twins

- **Issue:** `afxdp/zone_counters.rs` and `afxdp/flood_counters.rs` each implemented the same slot map, atomic totals store, touched-slot pending batch and thread-local accumulator (~300 production lines each), pinned together only by a cross-module `const assert!(FLOOD_COUNTER_SLOTS == ZONE_COUNTER_SLOTS)` and a "same zones" test. Every structural change (#6946, #14619) had to be written, reviewed and tested twice.
- **STEP-0 (defect live on origin/master `e488df68d8`):** Confirmed — both files present (1095/1112 lines), the `const assert` at `flood_counters.rs:95`, `fn slotted_zone_ids` in both files, and the twin test `flood_and_traffic_slot_maps_cover_the_same_zones` all present.
- **What:** Added `afxdp/zone_slot_counters.rs` with `trait SlotBlock` (fold/reset/is_zero over a `Delta: SlotDelta`), one `ZoneSlotMap` built once per config apply and shared by both stores, `ZoneSlotStore<B>` (sparse `snapshot_blocks` + generic `snapshot(project)` + clear/reconcile/fold), `ZoneSlotCaches<B1,B2>` (per-slot cached `Arc`s for both families), `ZoneSlotPending<D>` with the single #6946 mask-walk reset, and the shared `publishable_rows` filter. `zone_counters.rs` (244 production lines) and `flood_counters.rs` (315) keep only their block/delta types (`ZoneTotalsAtomic`/`ZoneTrafficDelta`, `FloodTotalsAtomic` as `[AtomicU64;3]×2`/`FloodDelta`), the `#[inline] record_*` functions and the wire-row projections (`zone_counter_snapshot`/`flood_counter_snapshot`/`publishable_*_rows`). Combined production of the two family files: 559 lines, down from 1206. Removed the cross-module `const assert` and the "same zones" test — both are true by construction with one shared map. `ForwardingState` now carries the one `Arc<ZoneSlotMap>` (both `zone_counter_slot_map` and `flood_counter_slot_map` fields point at it) plus the shared `zone_counter_caches`/`flood_counter_caches`; `forwarding_build::attach_zone_counters` builds the map once. Hot path unchanged: fixed `[_; 64]` arrays, `u64` touched mask, `#[inline]` recorders, no allocation added.
- **Acceptance:** `grep -rc 'fn slotted_zone_ids' userspace-dp/src/afxdp` totals 1 (only `zone_slot_counters.rs`); one slot map per forwarding build (single `ZoneSlotMap::build` in `attach_zone_counters`); existing tests in both files pass (adapted only for the new build/flush signatures and snapshot helpers).

## Risk

- Behaviour-preserving refactor: same slot assignment order, same lock-free fold, same sparse snapshot semantics (flood snapshot stays drops-only, #7086), same clear/reconcile contracts. The main risk is a missed caller of the old per-family types; mitigated by the compile (all callers migrated) and the caller tests above. `cargo asm` codegen comparison for `record_zone_traffic` was not run (box load); the record path is structurally identical (fixed arrays, mask, inline).
