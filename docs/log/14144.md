# #14144 completion RPC disclosure — engineering history

Issue: psaab/xpf#14144 ([research D6-04] completion RPC disclosure). Lane branch: `fix/14144-campaign`, base `origin/master` 7d6ac3b2b5804a99644518c9ccdf0226608782f3.

## Defect (present at base)

`Complete` was priced at `PermView` (`pkg/grpcapi/authz_methods.go`) and listed in `configModeMethods9633` (`authz_config_rpc_9633.go`), so `authorizeRPCCommand` exempted it from the operational `*-commands` regexes. `authorizeRPCConfigMutation` never saw it: `configMutationLineFor` returns `ok=false` for a completion request, so it fell through to the Load/Rollback handler and returned nil. Neither `*-configuration` nor `*-commands` was ever consulted.

Yet `Server.Complete` returns live-config-derived candidates built from `ActiveConfig()`: `valueProvider` (`server_cluster.go`) enumerates zone names + `zone.Description`, address-book names + CIDR values, policy names + descriptions, interface names + descriptions, NAT pools, screen/log names, application names/descriptions; `cmdtree.CompleteFromTreeWithDesc` DynamicFns enumerate the same objects for operational `show …` commands; and the `show configuration <path>` delegate feeds the same `valueProvider`. An authenticated PermView class with `deny-configuration "^security"` (or `deny-commands "^show configuration"`) — which `ShowConfig`/`Set` correctly refuse — could enumerate the denied subtree one Tab press at a time.

Strongest refutation considered: raising `Complete` to `PermConfig` would close it but take tab completion away from every read-only operator, including for paths they may read; and it still would not implement the path-scoped regex semantics (a PermConfig class with `deny-configuration "^security"` would still leak). The disclosure is in the data source, so the fix belongs there.

## Fix

Fix at the data source in `pkg/grpcapi`, interceptor/handler posture unchanged (Complete stays PermView, stays in `configModeMethods9633`):

- New `pkg/grpcapi/authz_complete_14144.go`: `completionAuth` resolves the admitted principal (`authorizedPrincipalFromContext`, falling back to the conn-peer principal) and compiles the class's `*-configuration` and `*-commands` regexes once via `config.ConfigurationLoginRegexesFor` / `config.OperationalLoginRegexesFor`. Fail-closed: unidentified/class-less principal, nil snapshot, or an invalid regex suppresses live values; superuser is unrestricted.
  - `wrapProvider`: the `config.ValueProvider` handed to `CompleteSetPathWithValues` returns nil unless the consumed config path (`strings.Join(path, " ")`) is allowed by the configuration regexes — placeholders/schema keywords remain, live names/descriptions/CIDRs do not.
  - `configPathAllowed`: a consumed path the configuration regexes deny offers no candidates at all (config mode and `show configuration`).
  - `showConfigPathAllowed`: additionally evaluates the canonical `show configuration …` command (with the bare prefix as an alternate form, so anchored `^show configuration$` denies sub-paths) against the operational regexes.
  - `treeConfig`/`operationalAllowed`: the cmdtree walkers receive a nil config — whose DynamicFn providers are nil-safe by contract (#5196) — when any typed operational prefix is denied by `*-commands`, or when the words after `show` form a config path denied by `*-configuration`; otherwise the real `ActiveConfig()`.
- `pkg/grpcapi/server_cluster.go`: `Complete` now takes its `ctx`, resolves `completionAuthFor(ctx)`, and dispatches to new `completeConfigPairsAuth` / `completeOperationalPairsAuth`. The pre-existing `completeConfigPairs` / `completeOperationalPairs` wrappers keep their exact behaviour via `legacyCompletionAuth()` (unrestricted) for the in-process callers/tests that use them. The `run` sub-case routes through `treeConfig` as well.

Not changed: the coarse price, the #9633 exemption, `valueProvider`/`CompleteSetPathWithValues`/cmdtree themselves (shared with `pkg/cli`, whose completer runs in the operator's own session), and any tolerant/strict doctrine — invalid regexes deny live values rather than falling open, and no test input is special-cased.

Residual (stated, not hidden): `pkg/cli`'s local completer has the same shape but runs in-process for the session's own user on the box; the issue's decisive check and cited paths are the gRPC surface, so it is untouched. REST has no completion RPC.

## Residuals

- None known on the gRPC surface. A class with an allow-configuration allowlist that permits a parent but not a child still receives schema keywords for the parent (the public grammar); only live values and denied-subtree candidates are withheld.
