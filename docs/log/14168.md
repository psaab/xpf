# Issue #14168 — pending confirm evaluated against normalized active, raw previous

- **Issue:** `Store.Load` normalized the active tree in place (retired
  dataplane-type rewrite + #1798 control-char scrub) before
  `recoverPendingConfirmLocked` compared `GuardedHash`/`PreviousHash`
  only against `guardedConfigHash(s.active)`. A pending record armed by
  an older build therefore bound the RAW on-disk generation and was
  misclassified as stale (#5835), discarding its auto-rollback. The
  record's `PrevTree` was likewise restored/compiled raw, so an old
  rollback target (e.g. `dataplane-type ebpf`) need not compile.
- **What:** `Load` captures the raw on-disk hash before the tolerant
  repairs and passes it to `recoverPendingConfirmLocked`. Recovery
  accepts a guarded/previous hash matching EITHER the raw or the
  effective hash of the same on-disk tree (unrelated generations
  still stale-drop), normalizes `PrevTree` with the same repairs
  before compile/promotion, and best-effort rebinds a live record
  recognized only via the raw hash to the effective hash. Negative
  stale control retained; first-commit handling unchanged and tested
  separately.
- **Files:** `pkg/configstore/store_persist.go`,
  `pkg/configstore/confirm_normalized_recovery_14168_test.go`,
  `pkg/configstore/README.md`.
