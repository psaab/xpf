# SSH password knobs rendered + ssh subtree closed (#15282)

- **Issue**: #15282 (V31-S1, residual of #4305) — the Junos SSH hardening
  knobs `no-password-authentication` and `no-passwords` were accepted with
  zero warnings and no consumer; xpfd's sshd drop-in never set
  `PasswordAuthentication`. On the baked appliance password auth is already
  off (`scripts/image/bake.py`), but on a `.deb` install the host's sshd
  default applied.
- **Cause**: neither leaf was modeled in `schema_system.go` (services ssh),
  so both were silently dropped before the compiler; `SSHServiceConfig` had
  no fields for them and `buildSSHDConfigErr`
  (`pkg/daemon/daemon_hostauth_apply.go`) rendered only MaxAuthTries,
  LoginGraceTime, PermitEmptyPasswords, DisableForwarding, PermitRootLogin,
  the algorithm lists, MaxStartups and ClientAlive*. The ssh subtree was
  also open-world, so any unknown leaf (e.g. `bogus-knob-xyz`) committed
  clean the same way.
- **Change**:
  - `pkg/config/schema_system.go` — services ssh gains the boolean leaves
    `no-password-authentication` and `no-passwords`, and the ssh subtree is
    `closedWorld: true` (leaf-complete: root-login, key-exchange, ciphers,
    macs, connection-limit, rate-limit, client-alive-interval,
    client-alive-count-max, protocol-version plus the two new leaves, so no
    modelled spelling is false-rejected).
  - `pkg/config/types_system.go` + `pkg/config/compiler_system.go` —
    `SSHServiceConfig.NoPasswordAuthentication` / `NoPasswords`, set from
    leaf presence on the existing expanded ssh node (flat-set and
    hierarchical spellings both reach it).
  - `pkg/daemon/daemon_hostauth_apply.go` (`buildSSHDConfigErr`) — either
    leaf renders `PasswordAuthentication no` (exactly once);
    `no-passwords` additionally renders `KbdInteractiveAuthentication no`
    (keyboard-interactive carries passwords through PAM on Debian). Absent
    leaves render nothing: existing stanzas keep host/factory posture. No
    accept-with-advisory is added — the knobs are enforced now, not inert.
- **Regression coverage**:
  - `pkg/config/ssh_no_password_15282_test.go` — both leaves compile (flat
    and hierarchical) into the new fields with no inert advisory;
    `bogus-knob-xyz` is rejected by SchemaValidate naming the knob; the
    valid hardening neighbourhood (root-login, protocol-version, rate-limit)
    still commits clean.
  - `pkg/daemon/ssh_no_password_15282_test.go` — the drop-in carries
    `PasswordAuthentication no` for either leaf, plus
    `KbdInteractiveAuthentication no` only for `no-passwords`, each exactly
    once; absent leaves render neither line (control).
- **RED evidence**: on pristine `origin/master` the new tests do not build
  (`SSHServiceConfig has no field NoPasswordAuthentication/NoPasswords`),
  and a behavioural probe on the same base shows the mechanism directly:
  `bogus-knob-xyz` under `system services ssh` is accepted silently by
  SchemaValidate (probe test FAILs with "bogus-knob-xyz accepted silently"),
  and `no-passwords` compiles with no consumer.
- **GREEN evidence**: `go test ./pkg/config/ -run '15282|TestSSHHardening|TestSSHProtocolVersion'`
  passes; `go test ./pkg/daemon/ -run 'TestBuildSSHDConfigNoPasswordKnobs15282|TestBuildSSHDConfigKeyExchange|TestBuildSSHDConfigHardeningKnobs|TestBuildSSHDConfigClientAlivePresence'`
  passes; `go vet ./pkg/config/ ./pkg/daemon/` clean; `gofmt -l` on touched
  files clean. Neighbourhood suites (`TestSSH*|TestClosedWorld*|TestSchemaValidate*|TestDuplicateRootLogin*|TestElidedSSH*|TestSystemInert*`)
  pass except two failures also present on pristine base
  (`TestClosedWorldSecurity10078_DirectIPsecVPNLeaves`,
  `TestSchemaValidate_Interfaces_AcceptedValuesCompileAsWritten`,
  base-attributed at 4883e29898). The #9091 blind ratchet and #9206
  multi-leaf census are likewise already stale on pristine base with
