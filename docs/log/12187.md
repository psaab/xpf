# 12187 — preserve SNAT provenance across HA session sync

- **Timestamp**: 2026-10-08
- **Action**: carried ordinary source-NAT provenance through HA session import, session storage, event-stream/JSON exports, and shared-map/BPF state.
- **Files**: `userspace-dp/src/{session,server/helpers,afxdp,event_stream,protocol}/**`, `pkg/{dataplane,daemon,cluster}/**` (session-sync provenance and export estimate), `bpf/headers/xpf_common.h`, generated `pkg/dataplane/userspace_xdp_manifest.json`, regression tests, this record.

## Why

HA imported the translated tuple without its origin. A later hit therefore treated the source-NAT origin as unknown and tore down sessions on first revalidation. The origin cannot safely be inferred from a later same-tuple static rule: a dynamically allocated mapping must still be revoked if that collision appears.

## What

- Added provenance values `0=unknown/legacy`, `1=dynamic`, and `2=static` to the HA request and session open/update transports. Old requests and frames without the new field remain unknown.
- Stored provenance on imported and locally installed sessions; carried it through transient shared hits, revalidation, JSON deltas, and HA re-export. Refreshes retain it only while the translated NAT decision is unchanged, and invalidate revalidation stamps so configuration changes are checked.
- Added a bit-10 “provenance known” marker beside the existing static-NAT bit. The marker distinguishes known dynamic/static state from legacy rows; unknown state clears both marker and static bit.
- Raised the owner-RG retained-delta estimate from 1856 to the measured 1863-byte JSON worst case after adding provenance.
- Added regressions for local incremental Open provenance, static and dynamic imports through the HA request parser, unchanged first-hit behavior, a transient dynamic import, and revocation after a same-tuple static collision. Binary open/update and JSON delta tests pin the cross-language values.
