# #16505 — genuine neighbour MAC move: refused-probe re-assert overwrote the kernel's correct new MAC

- **Timestamp**: 2026-10-24
- **Issue**: #16505, follow-up of #15097 (refused-probe re-assert), #10704, #13660.

## Cause

`parse_neighbor_msg_with_reassert` (`neighbor.rs`, v4 + v6 arms): on a kernel
`NUD_PROBE` whose lladdr differed from the dataplane's held MAC, the monitor
cleared the key's probe token (`clear_neighbor_probe` — including key-only
locally-issued tokens) and re-asserted the held MAC into the kernel via
`add_kernel_neighbor` (RTM_NEWNEIGH REPLACE, `NUD_STALE`).

On a genuine MAC move (router/NIC swap, keepalived VIP without vmac, VM
migration) the kernel already holds the correct new MAC `G2` (e.g. via GARP)
and probes `G2`. The re-assert overwrote that correct entry with the dead
held MAC `G`, so host-originated traffic (BGP/BFD/OSPF, IKE, DNS/NTP,
ip-monitoring) went to a dead MAC until the kernel's own FAILED cycle.
`docs/log/15097.md` accepted only a bounded extra dataplane cycle and
misdescribed the shape as "a kernel probe of the old MAC"; the README
contract (`afxdp/README.md`) still claimed a kernel `NUD_PROBE` authorizes
a differing-MAC update.

## Change

- `neighbor.rs`: the refused-probe arm no longer REPLACE-re-asserts the
  held MAC on the first refused probe. It starts held-MAC verification:
  `refused_probe_action` (pure, per-(key, held MAC), 5 s window =
  `ARP_SOLICITED_WINDOW_NS`, bounded 4096 keys, fail-closed when full)
  returns `VerifyStarted`/`VerifyPending`/`DropHeld`/`VerifyRestarted`.
  Production `handle_refused_probe` records a MAC-bound probe token for
  the held MAC and fires a unicast verification solicitation
  (`trigger_kernel_arp_probe` via `if_indextoname`); on `DropHeld` it
  removes the binding only if it still maps to the held MAC
  (`remove_if_mac_matches`), so fresh resolution adopts the new MAC.
  A probe of the held MAC clears verification state. Verification state
  is also cleared on FAILED/INCOMPLETE/NOARP removal, DELNEIGH, and any
  accepted differing-MAC update. The seam is renamed
  `parse_neighbor_msg_with_verify` / `RefusedProbeVerify`; the old
  `reassert_held_neighbor_after_refused_probe` /
  `should_reassert_refused_probe` limiter is removed (clean cutover, no
  callers remain).
- `sharded_neighbor.rs`: `clear_mac_bound_neighbor_probe` drops only
  MAC-bound tokens, preserving key-only local-probe tokens (the #16505
  acceptance requires the key-only token to survive a refused probe so
  `STALE(G2) → PROBE(G2) → REACHABLE(G2)` converges directly when a
  local probe is in flight); `remove_if_mac_matches` is the conditional
  drop. `clear_neighbor_probe` is retained for its remaining test use.
- `afxdp/README.md`: contract updated to post-#15097/#16505 — a kernel
  `NUD_PROBE` alone never authorizes a differing MAC; genuine moves
  converge via solicited evidence, `NUD_PERMANENT`, or the verification
  cycle; the kernel entry is never re-asserted on the first refused probe.

Residual [INFERENCE]: production solicitation uses the kernel ICMP-echo
probe (`trigger_kernel_arp_probe`), which makes the kernel direct its
ARP/NS at the MAC in the kernel's table; the dataplane-side verification
record is the MAC-bound token for the held MAC. A fully wire-level
unicast ARP/NS addressed to the held MAC would need interface source
MAC/IP state the monitor thread does not carry. The drop decision does
not depend on the solicitation's wire form: silence through the window
(kernel retransmit tail + dataplane token) drops the held binding.

## Regression coverage

- `genuine_move_converges_without_kernel_reassert_16505` (v4) and
  `genuine_move_converges_without_kernel_reassert_v6_16505` (v6):
  `STALE(G2) → PROBE(G2) → REACHABLE(G2)` — with a key-only token,
  converges to `G2` on the PROBE event; without, `G` is held during
  verification and `REACHABLE(G2)` stays refused until the window
  elapses and `G` is dropped, then first-learns.
- `refused_kernel_probe_mints_no_token_and_reasserts_held_mac_15097`
  (v4) and `..._v6_15097` (v6): the #15097 spoof cells still keep `G` —
  `PROBE(A)` starts verification of `G` (recorded at the seam, no kernel
  re-assert), `REACHABLE(A)` refused, epoch unchanged, refusals counted.
- `refused_probe_verification_window_16505`: window boundary → DropHeld,
  per-MAC restart, per-key isolation.
- `mac_bound_probe_token_authorizes_only_the_probed_mac_15097`
  (sharded): selective clear preserves key-only tokens.
- `held_mac_probe_still_converges_and_failed_recovers_15097`: local-probe
  convergence and FAILED + fresh first-learn still work.

## Risk

- No fail-open weakening: differing-MAC updates still require solicited
  evidence or `NUD_PERMANENT`; the refused MAC never gains a token.
- A genuine move with no local probe in flight converges after the 5 s
  verification window + fresh resolution, instead of the previous
  FAILED-cycle path that also blackholed host traffic to the dead MAC.
- Verification state is bounded (4096 keys, fail-closed when full) and
  the solicitation is one best-effort probe per verification start.
