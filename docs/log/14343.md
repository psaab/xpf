# #14343 — Compact header tokens on braced security-zone stanzas

## Defect
- Path A: `security-zone trust screen my-screen { interfaces { ge-0/0/0.0; } host-inbound-traffic { ... } }`
  compiled strict-clean with the braced body silently dropped (interface in no zone).
  `normalizeCompactNodes` attached the body to the last packed statement
  (`screen`, a leaf), and `compileZones` ignored leaf children/surplus keys.
- Path B: `security-zone trust tcp-reset { interfaces { ge-0/0/0.0; } }`
  fanned out an unbracketed header token as a phantom zone `tcp-reset`
  via `bracketedGroupInstances8794`, duplicating the body; strict only
  failed incidentally via duplicate-interface, lenient compiled both.

## Fix
- `pkg/config/compact_normalize_8662.go`: decline the fold when the single
  packed statement the body would land on resolves (via `consumeNodeKeys`)
  to a leaf (`children==nil && wildcard==nil`); leaves tree as authored.
- `pkg/config/compiler_validate_zone_group_9656.go`: new
  `zoneUnbracketedHeaderToken14343` in the braced branch of
  `validateZoneStatementTails9656` — strict rejects / lenient warns when an
  unbracketed `Keys[2:]` token is a declared `security-zone` child keyword
  (screen/description/interfaces/host-inbound-traffic/address-book/tcp-rst).
  Bracketed members and the bracket-stripped Format group
  (`security-zone trust untrust { ... }`, pinned by existing #8794 test) keep
  working; `apply-macro` deferred to #13094 helper.
- `pkg/config/compiler_security_zones.go`: `screen`/`description` arms record
  surplus keys (`Keys>2`) or any children via
  `recordUnknownSecurityZoneChild11575` (strict reject / lenient quarantine)
  instead of silently discarding them, mirroring `tcp-rst` handling.

## Deliberate scope cut
- Issue suggested requiring `KeyBracketed(k)` in `bracketedGroupInstances8794`
  for multi-name fan-out. Measured: `ConfigTree.Format()` emits the bracketed
  group as bare `security-zone trust untrust { ... }` stripping provenance,
  and `TestBracketedZoneGroupCreatesEveryZone8794/bare group` requires that
  spelling to compile both zones. Requiring brackets there would break the
  Format→SyncApply round-trip. Hence fan-out unchanged; invalid header tokens
  are rejected at the pre-walk gate instead.
