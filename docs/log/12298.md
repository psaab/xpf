# Issue #12298 — pin next-table scope against management VLAN children

## Why

#12061 excludes management-class interfaces from default-instance next-table ingress scope because those links belong to the implicit management VRF. Before #12297, tagged management children such as `fxp0.100` were not bound to that VRF, making the exclusion incomplete. #12297 chose outcome (a): tagged management children are now included in the management VRF set and bound to `vrf-mgmt`, so the existing exclusion remains correct.

## What

- Added a regression that jointly pins the #12297 management-VRF membership set and the #12061 next-table ingress set for a tagged management child. It asserts `fxp0.100` is in the management set and absent from default ingress, while ordinary untagged and tagged transit interfaces remain in ingress.
- No production change: the existing collector excludes a management-class stanza and also checks resolved unit names; the existing daemon bind path consumes `managementVRFIfaceSet` and calls `BindInterfaceToVRF` for its members.
