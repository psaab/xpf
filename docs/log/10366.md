# Issue 10366 — demote replica origin and refresh ordering

## Scope

`SessionTable::demote_owner_rg` now gives every ordinary demoted row one
peer-origin outcome: `WorkerLocalImport` replicas flip to `SyncImport`, while
`TunOrigin` and transient local seeds remain node-local. The existing worker
command order is pinned as `DemoteOwnerRGS` → `VacateAllSharedExactSlots` →
`RefreshOwnerRGS`, so the refresh sees the demotion's origin transition.

Issue #10405 is a separate shared-map demotion variant. This change does not
touch `demote_shared_owner_rgs` or the shared-map aliases.

## Regression cells

### WorkerLocalImport demotion: RED

The pre-10366 guard (`!old_origin.is_peer_synced()` plus the existing TUN/seed
exclusions) was restored temporarily and the 10366 cells were run together:

```text
cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp 10366 -- --nocapture
```

Result: `3 failed; 2 passed; 6443 filtered out`.

The failures were:

- `session::tests::demote_flips_worker_replica_to_sync_import_10366`: the row
  remained `WorkerLocalImport` instead of becoming `SyncImport`.
- `session::tests::demote_then_refresh_preserves_replica_origin_10366`: the
  refresh still observed `WorkerLocalImport`.
- `afxdp::session_glue::tests::apply_worker_commands_demotes_worker_replica_before_refresh_10366`:
  the production command path still left the replica `WorkerLocalImport`.

The two control cells were already green on the old guard: the queue-order
control and the live-demoted-row retention control.

### WorkerLocalImport demotion: GREEN

The demotion guard now excludes only `TunOrigin` and transient local seeds.
The same command passed:

```text
cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp 10366 -- --nocapture
```

Result: `5 passed; 6443 filtered out`.

The primary cell repeats the exact transition 64 times internally. Running
that cell ten independent times also passed every run (`10/10` exit status 0):

```text
cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp demote_flips_worker_replica_to_sync_import_10366 -- --nocapture
```

The final single run reported `1 passed; 0 failed; 6447 filtered out`.

### Demote → refresh ordering: RED then GREEN

With the old guard, the table-seam and production-command ordering cells were
among the three failures above. After the fix, both passed, including the
production `apply_worker_commands` path:

```text
cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp demote_then_refresh_preserves_replica_origin_10366 -- --nocapture
cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp apply_worker_commands_demotes_worker_replica_before_refresh_10366 -- --nocapture
```

Each command reported `1 passed`.

The coordinator-level pin covers a simultaneous RG demotion and activation:

```text
cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp update_ha_state_orders_demote_before_refresh_10366 -- --nocapture
```

Result: `1 passed`. It asserts the queue positions are Demote, Vacate, then
Refresh.
