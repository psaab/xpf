# Issue #12058 — Reverse repairs retain forward-native route identity

## Why

Poll-path repair can install a local reverse row under the reply's arrival-domain key. Using that key for native route revalidation selects the wrong routing table when the original forward ingress and reply arrival domains differ, blackholing replies and potentially retaining an arrival-domain table stamp.

## What

Local reverse-hit revalidation derives native identity from the matching stored forward session when available, while preserving explicit reply-ingress PBR precedence. If the forward row is unavailable, it retains the reverse decision's stored table identity rather than deriving native routing from the reply-arrival key. Shared/sessionless reverse hits continue to use their stored table identity. This restores the forward-native contract described in [Issue #11324](11324.md).

The poll-path regression covers IPv4 and IPv6 with both domain-mismatch directions, verifies replies egress on the forward ingress interface, and checks that a reverse row returning from an arrival-domain PBR stamp is restored to the forward-native table.
