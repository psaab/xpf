# #18994: join REST SSE re-auth watcher on stop

## Why

The REST `readAuthz` middleware stopped the SSE re-authorization watcher by closing `done` and cancelling its context, but did not wait for an in-flight authorization tick. The tick can still resolve the peer UID through `osident.ForUID` and read `passwdPath` while the API test fixture restores that global during cleanup.

## What

The REST stop now waits for `watcherExited`, bounded to two seconds like the gRPC-side `streamWatcherExitBound18761` from #18761. The tick is normally a short in-memory authorization; the bound prevents a stuck authorization from holding an HTTP response open indefinitely. No API surface changed.

The guarded-read test helper now cancels and waits for its asynchronous `readAuthz` call before fixture cleanup, matching the production handler/stop lifecycle. A deterministic test parks a re-authorization tick in the accept-time peer lookup and checks that stop waits; it covers both `/events/stream` and `/logs/stream`.

## Risk and residual seam

The stop is a **bounded join**, not an unbounded join: if authorization is still stuck after two seconds, stop logs a warning and returns, so that pathological case can still outlive the handler. This mirrors the existing gRPC bound from #18761 and avoids holding HTTP shutdown indefinitely.

The adjacent `osident` seam remains a package-global test seam: `passwdPath` is read by the lookup closure at `pkg/osident/osident.go:227` and assigned/restored by `SetPasswdPathForTest` at `:497-500` without synchronization. Production does not change the path; any test using this seam must ensure its background `ForUID` readers have exited before cleanup. The observed reader was the REST SSE watcher addressed here; the shared gRPC watcher already has the bounded join from #18761. No separate additional unjoined production reader was established by this investigation.
