# #14170 — secret-only rollback difference disappears

## Defect

`Store.ShowCompareRollbackRedacted` (pkg/configstore/store_format.go) used
`config.FormatCompare(forDisplay(entry.Config), forDisplay(s.candidate))`.
`forDisplay` is `RedactedClone`, which constant-masks every secret leaf to
`##SECRET-DATA##` (and `RedactURL`-sanitizes credential-bearing URLs) on both
arms independently. Two distinct secrets therefore collapse to the identical
placeholder token, and two URLs differing only in hidden credentials collapse
to the identical sanitized URL, so `FormatCompare` sees no difference and the
method returns `[no changes]`.

The sibling `ShowCompareRedacted` (active vs candidate) already used the
correct primitive, `config.FormatCompareRedacted`, which clones with a
fingerprint-aware marker (`fingerprintRedactedClone` in
pkg/config/ast_redact.go): the rendered arm stays constant-masked, but a
changed secret/URL-credential emits adjacent
`[secret fingerprint removed: <8-hex>]` / `[secret fingerprint added: <8-hex>]`
metadata, preserving equality without leaking the value.

Consumers of the broken method (all fixed by the single store fix, no call-site
change): REST `GET /api/v1/config/compare?rollback=N`
(pkg/api/config.go configCompareHandler), gRPC `ShowCompare` with
rollback_n > 0 (pkg/grpcapi/server_config.go), on-box CLI
(pkg/cli/cli_config.go, pkg/cli/cli_show_system.go). The cleartext
`ShowCompareRollback` is unaffected (it compares real values).

## Fix

- `pkg/configstore/store_format.go`: `ShowCompareRollbackRedacted` now calls
  `config.FormatCompareRedacted(entry.Config, s.candidate)` directly, mirroring
  `ShowCompareRedacted`. No raw secret is disclosed: arms remain constant-masked
  / URL-sanitized and only 8-hex SHA-256 fingerprints of the hidden component
  are emitted as separate metadata lines.
- `pkg/configstore/README.md`: redacted-compare section now names both compare
  entry points and warns against pre-masking with `RedactedClone`.

NOT changed: `forDisplay`/`RedactedClone` (still correct for single-tree
renders), the cleartext compare, authz pricing, or any consumer handler.

## Risk

Behavior delta is confined to redacted rollback compare output: secret/URL-only
differences that previously hid now show masked arms plus fingerprint metadata,
exactly as active-vs-candidate redacted compare has since #11819. No secret
material is newly exposed (fingerprints are 8-hex truncated SHA-256 of the
hidden component, already the accepted disclosure for the sibling compare).
