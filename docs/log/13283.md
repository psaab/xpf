# Issue #13283: expose NAT snapshot parse failures

## Why

NAT snapshot reconciliation silently skipped some malformed or unrepresentable inputs, while its cumulative parse-error telemetry was test-only and not exported to operators.

## What

- Count unknown DNAT protocol tokens, mismatched static-NAT block prefix families/lengths, and block rules with unsupported port matching before skipping those rules.
- Partition cumulative NAT parse/validation failures by source, destination, and static NAT builders, export all three through `ProcessStatus`, and publish them as `xpf_userspace_nat_parse_errors_total{type=...}`.
- Add Rust regression tests for the previously silent skips and type partitioning, a protocol JSON round-trip test, and Go status JSON/scrape/metric assertions.

## Validation

- RED: on pristine master, the unknown DNAT protocol and mismatched static-NAT prefix regression tests both failed because the parse-error count remained 0 instead of 1.
- GREEN: `CARGO_TARGET_DIR=/var/worktrees/.cache/cargo-13283 cargo test --manifest-path userspace-dp/Cargo.toml -- 13283` passed all 4 matching Rust tests after the per-type telemetry changes.
- GREEN: `GOCACHE=/var/worktrees/.cache/go-build go test ./pkg/api -run 'TestNATParseErrors(ReachScrape|StatusJSON)13283|TestEmitUserspaceDynamicBufferMetrics'` passed.
- The full `go test ./pkg/api ./pkg/dataplane/userspace` run failed in unrelated existing tests (including duplicate `xpf_vrf_overlap_pbr_admitted` collection, contract snapshot drift, and other userspace fixtures); no #13283 test failed in that run.

## Risk

Each count is cumulative for the helper lifetime and tracks parse/validation failures by NAT builder. A malformed field may be counted even if tolerant parsing installs a safe fallback, and one rule may contribute multiple failures. NAT rule fallback/drop behavior is unchanged.
