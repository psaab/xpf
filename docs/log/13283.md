# Issue #13283: expose NAT snapshot parse failures

## Why

NAT snapshot reconciliation silently dropped several invalid rules, and the accumulated parse-error counter was test-only. Operators therefore had no complete status or Prometheus signal for rejected NAT configuration.

## What

- Count unknown DNAT protocol tokens, mismatched static-NAT block prefix families/lengths, and block rules with unsupported port matching as NAT parse failures before skipping those rules.
- Expose the cumulative helper counter in `ProcessStatus` as `nat_parse_errors_total` and publish it as `xpf_userspace_nat_parse_errors_total`.
- Add Rust regression tests for the previously silent skips, a protocol JSON round-trip test, and Go status JSON/scrape/metric assertions.

## Validation

- RED: on pristine master, the unknown DNAT protocol and mismatched static-NAT prefix regression tests both failed because the parse-error count remained 0 instead of 1.
- GREEN: `CARGO_TARGET_DIR=/var/worktrees/.cache/cargo-13283 cargo test --manifest-path userspace-dp/Cargo.toml -- 13283` passed all 3 matching Rust tests.
- GREEN: `GOCACHE=/var/worktrees/.cache/go-build go test ./pkg/api -run 'TestNATParseErrors(ReachScrape|StatusJSON)13283|TestEmitUserspaceDynamicBufferMetrics'` passed.
- The full `go test ./pkg/api ./pkg/dataplane/userspace` run failed in unrelated pre-existing tests (including duplicate `xpf_vrf_overlap_pbr_admitted` collection, contract snapshot drift, and other userspace fixtures); no #13283 test failed in that run.

## Risk

The counter is cumulative for the helper lifetime and counts dropped NAT snapshot rules, not individual malformed fields. Existing rule-drop behavior is unchanged; only instrumentation and status publication are added.
