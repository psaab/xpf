# #14729 — Empty `redundant-ether-options` stanza panics the RETH gate

## Defect

`validateRethRedundancyGroupTokensAST` (`pkg/config/compiler_reth_rg_token.go`,
the #6782 pre-walk gate in `runPreWalkGates`) called `nodeVal(rg)`
unconditionally after the #14441 expansion. #14441 (86f517f8c) deleted the
gate's `if rg == nil { continue }` guard when it added the
`expandResolvingRun9792` + `packedBody` mirror of `compileInterfaces`, so an
interface whose `redundant-ether-options` stanza is EMPTY —
`redundant-ether-options { }`, or the bare leaf `redundant-ether-options;` —
yields `rg == nil` from `FindChild` and `nodeVal(nil)` dereferences it:

```text
panic: runtime error: invalid memory address or nil pointer dereference
  nodeVal(...)                        compiler_applications.go:1340
  validateRethRedundancyGroupTokensAST.func1  compiler_reth_rg_token.go:113
  runPreWalkGates                     compiler_prewalk.go:778
  CompileConfigLenient                compiler.go:154
  runCompactBlockCensus               compact_block_equivalence_2419_test.go:1000
  TestCompactBlockEquivalenceInventory2419
```

First observed by the #14442 lane as a full-suite failure of
`TestCompactBlockEquivalenceInventory2419` (reproduced on clean
`origin/master`, so base-attributed at the time). The census triggers it
deterministically: its empty-stanza skeleton fixture
(`nest(..., stanza+" { }")`, run for every `interfaces` site) compiles an
empty `redundant-ether-options { }` through `CompileConfigLenient`. But the
reachable surface is any operator config carrying an empty reo stanza on
commit / commit-check / tolerant load — the pre-walk panics before any
diagnostic, which on the tolerant path bricks the boot the #1960 no-brick
rule exists to protect.

An empty stanza carries NO `redundancy-group` token at all. That is the
ABSENT-token case #6782 deliberately scopes out ("a reth with NO
redundant-ether-options stanza is not flagged"), not a present-but-empty
token: a present leaf without a value (`redundancy-group;`) still produces
a node, and must still be classified unusable. `compileInterfaces` itself
already guards this correctly (`if rgNode := ...; rgNode != nil`); only the
gate lost its guard.

## Fix

- `pkg/config/compiler_reth_rg_token.go`: restore the `rg == nil` guard
  after the #14441 expansions, with the absent-vs-present distinction
  recorded at the site. NOT changed: `nodeVal` (its dozens of callers pass
  nodes obtained under explicit nil checks; making it nil-tolerant would
  silently reclassify a present-but-empty token as absent and mask the
  next dropped guard), the #6782 classifier, suppression, or the compiler
  reader.
