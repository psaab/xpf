- **Fix**:
  - `frame/inspect.rs`: new `meta_l4_ports_in_declared_end(frame, meta)`:
    `[l4, l4+4)` within `declared_l3_end(frame, meta.l3_offset, family)` via
    `checked_add`, fail-closed `false` on unknown family / truncated L3 /
    overflow — mirrors `meta_icmp_identifier_bearing`. One comparison, no

  - GPT-2: port absence is marked EXPLICITLY at the flowless filter-eval
    sites, not derived in the cold `extra` builder. First attempt derived
    `ports_unknown` in `term_match_extra_from_frame` from frame bytes — the
    suite caught the over-gate (4 TX forward-request cells: real flow +
    unreadable frame is legitimate via cache-hit + DMA-mutated slice, which
    `frame/README.md:114-118` requires tolerating, and the design prefers
    flow ports as "immune to DMA races"). A (frame,meta)-only builder can
    never know whether the evaluated ports are real, so the bit is set where
    the evaluated tuple is known: `forwarding/pbr.rs` sets it when the
    evaluated flow has (0,0) ports (L3-only contexts carry that by
    construction, #3291; a real TCP/UDP flow never has both zero), and the
    two flowless input-filter sites in `poll_descriptor/mod.rs` (assoc-hit
    + miss/flowless arms, both fed by `l3_enforcement_flow_from_meta`) set
    it unconditionally. The `port_terms_match` gate
    (`filter/engine/matching.rs:344-348`) already suppresses
    port-constrained terms on it, so flowless input-filter/PBR evaluation
    fails closed on synthetic 0/0 instead of spuriously matching (positive
    port-0 can no longer parse, so the live hazard is negated/except and
    range-zero inversion — both pinned by the loop cells). Flow-backed
    evaluations are byte-identical (builder still `false`, cache path
    untouched — the "reds 11+ tests" hazard does not apply). The assoc-hit
    input site is verdict-neutral today (non-first fragments already
    suppress via `is_fragment`), kept for design uniformity. Stale SCOPE +
    field docs updated (`matching.rs`, `filter/mod.rs`). Out of scope,
    verified unaffected: TX CoS flowless arm (portless evaluator, #7992),
    flowless filter-log attribution (display only), zone policy on L3 flows
