# Issue #13641 — count static ingress filters on session hits

## Why

Static ingress filter `then count` handles for an established session hit were
charged only when the packet later produced a cache entry. The cache seed is
not reached for non-cacheable traffic such as TCP FIN/SYN-ACK, failed session
installs, local delivery, and fragments; some such hits therefore forwarded or
were delivered while silently omitting the packet and byte increment.

The counted per-packet filter path was already correct. The gap was the
uncounted static-accept path, which delegated its charge to `stage_flow_cache_seed`
without guaranteeing that an eligible cache entry would be built.

## What

Charge the captured static INPUT filter counters at the common session-hit
filter gate whenever its evaluator did not already count the packet. Use the
same metadata packet length as the cache seed, and mark the packet counted so
the eligible cache-seed path cannot charge it a second time. This common gate
covers transit, local-delivery, and fragment session hits without changing
their forwarding or verdict decisions.

A regression drives a counted static INPUT filter through a cacheable ACK seed
and then a non-cacheable FIN session hit, asserting the exact counter progression
and that the FIN still forwards.

## Validation

- RED before the fix: `txn_static_input_count_charged_on_non_cacheable_session_hit_13641`
  failed on the pristine worktree: the expected counter value was 3, but the
  observed value remained 2 after the FIN hit.
- GREEN after the fix: the same targeted test passed (1 passed).
- The complete `afxdp::tests_txn_flow_cache` module passed: 53 tests passed.
- RED on revert: removing the #13641 gate reproduced the same 2-versus-3
  counter failure (0 tests passed).
- Two full crate runs (the second after the final guard adjustment) each
  reported 7,959 passed, 1 failed, and 8 ignored. Both reported the same
  failure in
  `afxdp::tests_9950::f035_parked_fragment_overlap_is_rechecked_on_retry_10659`
  (`parked-head: the sibling must pass before the parked frame is retried`,
  observed 0, expected 1).
- The same #10659 test also failed on pristine `origin/master` (0 passed,
  1 failed with the same assertion), so that full-suite failure is
  base-attributed, not introduced by #13641.

## Risk

The uncounted static-session-hit gate now collects the matching counter handles
and records the metadata packet length before later disposition-specific paths.
Counted per-packet filters retain their existing single-evaluation behavior; the
seed's existing suppression flag prevents double-counting cacheable hits. No
forwarding, policy, or filter-verdict behavior changes.
