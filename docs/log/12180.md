# Issue #12180 — gRPC cursor session scans honor cancellation

## Why

A selective `GetSessions` cursor filter that did not fill a page could scan the full v4 and v6 tables after the request was cancelled. Filtered totals then launched two more context-free scans. This retained a shared session-walk slot until EOF and could return a partial result as success.

## What

- Added sampled context cancellation checks to both cursor callbacks and direct context checks at scan phase boundaries. Cancellation now stops the current walk, prevents starting the next family or filtered-total passes, and returns the gRPC `Canceled` status.
- Threaded the request context into `setSessionsTotal`. Filtered total scans sample cancellation, stop before v6 if v4 is cancelled, and never publish a partial count. The existing deferred limiter release runs on the cancellation return.
- Added v4/v6 cursor cancellation and v4/v6 filtered-total cancellation regressions; each also verifies the RPC returns `Canceled` and releases its walk slot.

## Risk / residual

The regression uses a deterministic synthetic dataplane, cancels halfway through a selective scan, and confirms sampling bounds visits and frees the slot. No live dataplane or cluster was exercised.
