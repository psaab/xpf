# #17259 — unify NPTv6 rule membership and overlap

- **Timestamp**: 2026-11-06
- **Branch**: `fix/17259-nptv6`
- **Base**: `99cb6b34ec` (`origin/master`)

## Why

At the base, six consumers decided independently which static-NAT rules belonged
to NPTv6: snapshot construction, `compileNPTv6`, `NPTv6OverlapConflict`,
`nptv6ExternalPrefixes`, `validateNPTv6Strict`, and
`validateNPTv6ScopeStrict`. Two overlap engines then made different decisions:
the strict validator used `net.IPNet.Contains` and skipped same-name rule
identities, while the helper-facing path used 16-bit words and compared every
emitted row. The live disagreements were a tolerated #16008 undefined-zone set
in strict warning overlap membership, duplicate emitted snapshots with the
same identity, and host-bit prefixes entering the pool-overlap population even
though Rust refuses them.

## What

- Added `config.NPTv6Rules(cfg)` as the sole typed membership selection. It
  returns each non-nil `IsNPTv6` rule once per configured row, with its rule-set
  identity and index, plus shared `Installed`, `UndefinedZone`,
  `ScopeUnsupported`, and excluded-reason status. Non-NPTv6 static rules never
  enter the list; malformed NPTv6 entries remain in it for diagnostics.
- Migrated all six consumers to those references. The builder, helper-overlap
  checker, and external-prefix population use `Installed`; the compiler and
  both strict validators retain their per-rule diagnostics over the complete
  NPTv6 list. There is no per-consumer `IsNPTv6` membership filter.
- Kept one pair engine, `NPTv6OverlapFindings`, over the helper-installable
  population. It uses `[4]uint16` prefixes, separate internal/external
  namespaces, and the helper's from-zone conflict predicate. Both
  `NPTv6OverlapConflict` and strict validation consume those findings; the
  `seenPrefix`/`net.IPNet.Contains` engine was removed.
- **Engine choice**: the helper admits only IPv6 `/48` and `/64` prefixes.
  Those lengths are word-aligned (three or four 16-bit words), so equality of
  the first `min(words)` words is exact for identical and nested prefixes,
  including `/48`-to-`/64` boundaries. It directly mirrors Rust's
  `find_overlap`, avoids maintaining a second general-purpose containment
  implementation, and does not allocate/copy `IPNet` values for overlap
  comparisons. `::/0`, `/63`, `/65`, host-bit prefixes, and mismatched lengths
  are rejected before overlap, as they are by Rust `parse_prefix`; the engine
  intentionally does not widen its domain to those shapes.
- No identity-based self-skip remains. Two emitted snapshots with the same
  rule-set/rule names are still two helper entries; exact duplicates now fail
  closed in strict validation as they do in the helper.
- Updated schema guidance and existing regression-test comments. Removed the
  now-dead `hasNonNptv6StaticNAT` helper and its dead-code allowlist entry.

### Disagreement dispositions

- **#16008 dropped-set warning — live RED before, intentional verdict change.**
  At the base, a healthy rule and an overlapping rule in a lenient
  undefined-zone set made `validateNPTv6Strict(cfg, true)` warn that the
  healthy rule overlapped the dropped rule, even though
  `NPTv6OverlapConflict(cfg)` returned `""` and the builder omitted the entire
  dropped set. The baseline probe RED showed that mismatch. After unification,
  `TestNPTv6DroppedUndefinedZoneDoesNotWarnOverlap17259` proves no overlap
  warning/conflict is reported and `nptv6ExternalPrefixes` contains only the
  healthy rule. This lenient-warning change is deliberate: the helper cannot
  reject a snapshot entry that the builder never emits; strict undefined-zone
  commit rejection is unchanged. This is the #16008 membership rule that the
  earlier `IsNPTv6`-filter removal consequence made fragile.
- **Same-identity duplicate snapshots — live RED before.** The base strict
  engine's identity self-skip accepted two copies of the same rule (`strict=nil`),
  while the helper-facing engine reported
  `rule-set "rs" rule "r1" external prefix "2001:db8:2::/48" overlaps
  rule-set "rs" rule "r1"`. The single engine now rejects both in strict and
  pre-pass paths. The helper never deduplicates by names, so fail-closed
  duplicate handling is the preserved helper verdict.
- **Host bits in external-prefix population — live old-behavior RED.** The old
  external-prefix converter masked `2001:db8:1:2::/48` through `net.ParseCIDR`
  and admitted it for pool-overlap checks, although Rust `parse_prefix` rejects
  host bits. With the old conversion behavior restored as a temporary mutant,
  `TestNPTv6ExternalPoolPopulationExcludesHostBits17259` RED:
  `helper-rejected host-bit prefix entered pool-overlap population` and showed
  the bad prefix. The host-bit guard was restored byte-identically.
- **Prefix-length edge shapes are unreachable at overlap.** `/0`, `/63`, and
  `/65` fail the Go helper-prefix gate (`nptv6PrefixWords` accepts only `/48`
  and `/64`) and Rust's `parse_prefix` match at
  `userspace-dp/src/nptv6.rs:355-359` rejects every other length before
  `find_overlap`. `TestNPTv6OverlapWordBoundaries17259` pins `/48`/`/64` nested
  and adjacent behavior plus these rejected shapes. No old-engine disagreement
  was reachable for these lengths.
- **Already-fixed regressions retained:** #15266 split-horizon zones remain
  disjoint (`TestNPTv6SplitHorizonDifferentZonesCommits15266` and
  `TestNPTv6SplitHorizonStillCompiles_7078`); #16674 ordinary static-NAT
  prefixes stay out of the NPTv6 overlap population
  (`TestBlockStaticNATNestedPrefixesStillCompile_16674`); and #16874 duplicate
  `from zone` values remain deduplicated without collapsing distinct scopes
  (`TestNPTv6DuplicateFromZoneCommits16874`,
  `TestNPTv6DistinctFromZonesNotCollapsed16874`). The #15266 and #16874 cells
  passed in the focused run below. The #16674 static-NAT control also passed
  separately via testguard:
  `go test ./pkg/dataplane -run '^TestBlockStaticNATNestedPrefixesStillCompile_16674$' -count=1`.

## Risk

Lenient warning output intentionally changes for overlap pairs whose other
member is not Installed — dropped by #16008, scope-unsupported (#5818), or
excluded (#9877) alike — and invalid host-bit NPTv6 rules no longer enter
external pool-overlap diagnostics because the helper rejects them before
installation. Duplicate emitted rows with identical identities now fail strict
validation instead of passing via an identity self-skip; this matches the
helper's fail-closed behavior. Zone partitioning, supported-prefix overlap
verdicts, per-rule malformed/scope diagnostics, and runtime snapshot format are
otherwise unchanged.
