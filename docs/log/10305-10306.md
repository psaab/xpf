## GREEN — #10305

`configstore.hasFlatVerb` delegates to that same predicate. The predicate is
exactly the store rule: one of `set`, `delete`, `deactivate`, or `activate`
with a path token. Bodies containing only `copy`, `rename`, `insert`,
`annotate`, or a bare single-token trigger are rendered hierarchically before
every written path is adjudicated.

## RED — #10306 REST gate/handler decoder disagreement

With the production REST gate reverted to its pre-fix `json.Unmarshal` path,
the new cells failed closed-path coverage in every requested disagreement:

```text
go test ./pkg/api -run 'TestRESTGateUsesExactHandlerStructs10306|TestRESTGateUsesHandlerDecoderForTrailingData10306' -count=1
--- FAIL: TestRESTGateUsesExactHandlerStructs10306
    set_path_is_gate-only_denied: gate allowed denied path
    delete_path_is_gate-only_denied: gate allowed denied path
    deactivate_path_is_gate-only_denied: gate allowed denied path
    activate_path_is_gate-only_denied: gate allowed denied path
    annotate_input_is_gate-only_denied: gate allowed denied path
    load_n_is_gate-only_denied: gate allowed denied path
    rollback_mode_is_gate-only_denied: gate allowed denied path
--- FAIL: TestRESTGateUsesHandlerDecoderForTrailingData
    path_mutation_denied: gate allowed denied path
    content_load_denied: gate allowed denied path
FAIL
```

The wrong-typed fields are unknown to the actual handler structs: `path` on
set/delete/deactivate/activate, `input` on annotate, `n` on load, and `mode`
on rollback. The trailing-data cells append `trailing-garbage` after the first
JSON value. The old gate rejected those bytes/fields with `json.Unmarshal` and
then returned `nil`, reopening the request to the handler.

## GREEN — #10306

The gate now decodes one time with `json.NewDecoder(...).Decode` into the exact
request type used by the handler (`ConfigSetRequest`, `AnnotateRequest`,
`ConfigLoadRequest`, or `ConfigRollbackRequest`). Unknown fields and trailing
data therefore have the same semantics at both layers. Read/decode errors now
return a permission error (fail closed), while the body is restored unchanged
for the handler.

```text
go test ./pkg/api -run 'TestRESTGateUsesExactHandlerStructs10306|TestRESTGateUsesHandlerDecoderForTrailingData10306' -count=1
ok   github.com/psaab/xpf/pkg/api
```

Each of the seven wrong-typed-field rows has an allowed-path control, and both
trailing-data rows have an allowed-path control. The controls prove the gate
is not simply refusing every REST body.
