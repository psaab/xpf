# Drop suppressed Time Exceeded packets on the session-miss arm (#14643)

- **Issue**: #14643 (deep-review finding Y32-02).
- **Cause**: On the session-miss arm in
  `userspace-dp/src/afxdp/poll_descriptor/mod.rs`, the Time Exceeded
  builder returns `None` both for "TTL would not expire" and for
  "expiring but the reply is suppressed" (RFC 1812 suppression gate,
  output-filter drop of the generated reply, per-zone rate limiter, or
  unbuildable reply). The old code treated every `None` as "not
  expiring" and fell through to the forward+reverse session install,
  SNAT retention, BPF publication and HA session-create replication —
  then queued a Live forward request that the rewrite/build path
  refuses for TTL<=1 (`frame/rewrite/ipv4.rs`, `frame/build/ipv4.rs`),
  so the packet was dropped only after creating forwarding state for
  traffic that was never delivered. The flow-cache-hit sibling
  (`poll_descriptor/flow_cache_hit.rs`) already drops explicitly in
  this case; the session-hit arm is unaffected because it never
  installs.
- **Change**: The miss arm now evaluates
  `packet_ttl_would_expire(packet_frame, meta)` once (the same
  predicate the sibling uses) before calling the builder. When the
  builder returns `None` but the packet would expire, the arm rolls
  back the source-NAT allocation and the NAT64 pool allocation with
  the exact rollback pair the built-TE arm performs, recycles the
  frame exactly once, and continues — no session install, no flow-cache
  seed, no forward request. Non-expiring packets and built-TE packets
  are byte-for-byte unchanged.
- **Regression coverage**
  (`userspace-dp/src/afxdp/tests_txn_flow_cache.rs`):
  `txn_ttl1_suppressed_te_installs_no_session_14643` drives the real
  descriptor path (`txn_run_descriptor_checked`) with pool-mode SNAT.
  Witness: the LAN per-zone TE bucket is drained at a far-future epoch
  so the builder's real-clock call stays denied, then a TTL=1 TCP SYN
  must yield `session_creates == 0`, `sessions.len() == 0`, `tx == 0`,
  no queued forwards, exactly one recycle of the frame, and a fully
  rolled-back pool (`live_flows == 0`, `used_ports == 0`). Control 1:
  the same TTL=1 SYN with a fresh bucket queues exactly one prebuilt
  TE, creates no session, and also rolls back SNAT. Control 2: a
  TTL=64 SYN installs the forward+reverse pair, forwards, and retains
- **RED evidence**: With only the test applied (fix reverted),
  `txn_ttl1_suppressed_te_installs_no_session_14643` FAILED at the
  witness `session_creates` assertion: left 2, right 0 — the suppressed
  TTL=1 packet installed the forward+reverse pair on current master.
- **GREEN evidence**: With the fix, the same test passes (1 passed).
  Note: the shipped tree does not compile tests until #14802 lands
  (see below); GREEN was exercised with the temporary local workaround
  described there, reverted before push. Sibling TTL tests
  (`txn_flow_cache_hit_ttl_check_precedes_egress_accounting_3779`,
  `gre_decap_session_miss_ttl_expiry_reads_inner_ttl_5615`) could not be
  re-run on the final tree for the same reason and must be re-run by
  the reviewer once #14802 lands.
- **Adjacent defect filed**: #14831 — the buildable-TE control queues
  both the Prebuilt TE and a Live forward on the miss arm (the Live
  frame is refused later at rewrite). Out of scope here; the control
  in the regression test asserts only the miss-arm contract
  (Prebuilt==1, no session, SNAT rolled back).
- **Base build break (out of scope)**: `origin/master` at `7df6454e2`
  (and still at `63aad2a34`) does not compile:
  `policy_revalidation.rs:461` calls
  `PortAllocator::persistent_inbound_lookup` with 6 arguments after
  #14793 extended it to 8 (`from_zone`, `ingress_zone`) and updated
  only the admission call site. Filed as #14802. For local test
  execution only, this worktree carries a temporary two-argument
  (`""`, `""`) call-site patch that is reverted before push; the PR
  does not touch `policy_revalidation.rs`.
- **Blast radius / risk**: Only TTL<=1 / hop-limit<=1 packets on the
  session-miss ForwardCandidate arm whose TE reply is suppressed
  change behavior: they now drop before session/NAT state instead of
  after it. Built-TE packets keep the prebuilt-reply path; all other
  packets are unaffected. The session-hit and flow-cache-hit arms
  already drop such packets and are untouched.
