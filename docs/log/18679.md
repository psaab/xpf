# Issue #18679 — UDP continuity across RG moves

## Why

RG1 Group 1 in `test-failover` judged TCP session-miss counters, but had no datagram/session-incarnation evidence to distinguish a surviving firewall session from a rebuilt flow. The RG-move soak had the same gap.

## What

- Added a long-lived, sequence-numbered UDP sender using one socket and a per-start boot nonce; only successful `send()` calls are recorded as sent. The target echoes the client nonce and the post-NAT source IP/port.
- Added exact-flow firewall Session ID capture on the target node. The synced standby row is required before a move, with matching probe boot/socket snapshots bracketing the query. The promoted-node Session ID is read beside the final probe snapshot at the end of the judged window, so recreation after landing is still detected. A changed firewall ID is `RECREATED` even when the client socket and translated NAT tuple are unchanged.
- Both harnesses snapshot immediately after each failover CLI returns and classify only later sequences. Replies emitted during CLI latency are already in that checkpoint and cannot prove post-move survival. Stable Session ID through the final snapshot plus post-checkpoint replies is `SURVIVED`; a changed ID or translated identity is `RECREATED`; confirmed post-checkpoint sends with no replies are `LOST`; missing sync identity, sender restart, or unusable evidence is `VOID`.
- The RG-move soak closes each CLI's window before issuing the next move, so later recovery cannot mask an earlier loss. A probe start/setup failure makes per-move UDP evidence `VOID` while the soak continues and retains its other traffic evidence.
- `mouse-target-setup.sh up` restarts `mouse-echo` only when the deployed echo source content changed, so an active service acquires the UDP listener without interrupting TCP echo flows on no-op runs.
- Added hermetic survived/recreated/lost fixtures with realistic CLI-latency grace replies. The recreated fixture preserves the client socket and NAT tuple but changes firewall Session ID; a fail-on-revert mutant proves that it would pass if Session ID comparison were removed. Soak tests cover same-tuple recreation after landing, post-move silence, startup and per-query sender-restart VOID, missing standby sync, and loss followed by recovery after a later RG command.

## Validation

- `make test-ha-assurance-lib` — PASS; includes survived/recreated/no-reply fixtures, the identity-comparison fail-on-revert mutation, same-client identity checks, and test-failover boundary/lifecycle pins.
- `make test-rg-move-soak-lib` — PASS; 108 tests, including session recreation with a stable NAT tuple, post-move loss, per-move probe VOID, and preservation of independent CLI/unlanded FAILs.
- `make test-target-services-lib` — PASS; target-service and mouse-target setup selftests confirm `mouse-echo` restarts only when source content changes.
- An initial post-review soak run exposed UDP `VOID` evidence masking independent move failures. Verdict precedence now preserves those `FAIL`s while recording the UDP diagnostic; the final 108-test run passes.
- Disposition of the earlier `test_landing_bound_is_from_the_cli_return` failure: it occurred only on an intermediate pre-commit tree. GLM reported the committed baseline passing 102/102 twice; the final post-review soak run passes 108/108.

## Risk

This changes only test harnesses and the managed mouse-target echo service. The probe uses IPv4 UDP/6201 and one persistent client socket. The firewall Session ID is the primary session-incarnation evidence; translated identity is a secondary recreation signal. Missing synced standby identity, a restarted sender without a changed firewall Session ID, or unusable captures yield `VOID`; confirmed post-return silence or a changed session identity fails the continuity verdict.
