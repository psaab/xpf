# Weekday inline stop-time leaked into the scheduler scalar (#12942)

- **Issue**: #12942 — `tuesday { start-time 09:00:00 { stop-time 17:00:00; } }`
  compiles `StopTime=17:00:00` with empty `StartTime`; runtime fails closed
  (scheduler.go). Follow-up filed from PR #12924 review residuals.
- **Reproduction** (pristine master, worktree wt-12942 @ fefd415a5): the
  hierarchical repro, its flat-set twin (`set schedulers scheduler S tuesday
  start-time 09:00:00 stop-time 17:00:00`), a daily+weekday pair, and a
  scheduler-level `start-time` beside a weekday inline pair were compiled
  through `SchemaValidate` + `CompileConfig`/`CompileConfigLenient`.
- **Cause**: `compileSchedulers` and the #11358 pair collector read scheduler
  properties through `expandRunChildren9235(inst.node.Children,
  schedulerSchema9235())` → `hoistAndSplitRun8939` →
  `splitNestedForeignRun8939` (pkg/config/hoist_and_split_8939.go). The prune
  walk lifts a nested statement whose head is "legal in the enclosing
  container, illegal under its immediate parent". A day container's
  `start-time` declares no children, so the nested `stop-time` looked foreign
  — but it is ALSO a declared leaf of the day schema itself: the braced twin
  of the #8939 flat run `tuesday start-time 09:00:00 stop-time 17:00:00`,
  which `SetPath` nests identically and `schedulerWindowFromNode` reads via
  `expandFlatRun` against the day schema. The hoist produced a PHANTOM
  scheduler-level `stop-time` prop (`pkg/config/compiler_system.go`
  `case name == "stop-time": sched.StopTime = nodeVal(prop)`), while the day
  window kept its pair (the prune's count-equal fast path returns the
  original subtree), so the phantom was invisible in `Days` and landed only
  in the scalar. Three consequences: (1) scalar `StopTime` with no
  `StartTime` — on every non-Tuesday tick `effectiveDayWindow` returned the
  half window and `isWithinWindow` warned "incomplete time window, failing
  closed" (pkg/scheduler/scheduler.go); (2) beside a real `daily` window the
  phantom rewrote the scalar stop to the weekday's value on the tolerant path
  (boot load / HA `SyncApply`) — fail open on every non-Tuesday day; (3) the
  same phantom fed `collectSchedulerWindowPairFindings11358`'s daily record,
  so the legitimate daily+weekday pair strict-rejected as an #11358 "daily
  repeated boundary" nobody authored.
- **Change** (`pkg/config/hoist_and_split_8939.go`): the lift's ambiguity
  bound now also resolves the candidate against the BODY ROOT — the schema of
  the body-owning node the prune started from — gated on that body declaring
  `packedFlatRun`. A head that is a declared leaf of a body which opts into
  its own flat-run spelling is that body's statement, not a foreign one; the
  schema walk already expands such bodies the same way (schema_walk.go), and
  the day reader (`schedulerWindowFromNode` → `expandFlatRun`) reads the
  nested run as the day window. The gate is required, not stylistic: `tunnel
  routing-instance destination VR1 destination 10.0.0.2` (#9156) nests the
  tunnel's destination under a routing-instance body leaf of the SAME NAME,
  and there the nested statement IS a misplaced tunnel leaf — the
  routing-instance body declares no run spelling, so it still lifts. No
  scheduler-specific branch: every reader of the expansion (compiler, #11358
  collector) sees the same corrected view.
- **RED evidence**: pristine master (fefd415a5) + only the new test file —
  `TestSchedulerWeekdayInlineStopStaysInDay12942` 7/7 subtests fail
  (`scalar window = ("", "17:00:00")`), flat-set cell fails identically,
  mixed daily+weekday cell fails with the phantom
  `#11358 daily repeated boundaries` rejection, scalar-start cell fails with
  `("08:00:00", "17:00:00")` (the silently completed daily window).
- **GREEN evidence**: post-fix, all four tests pass on head; the day window
  keeps the complete 09:00:00–17:00:00 pair from both spellings, the scalar
  stays empty (or exactly what a scheduler-level/daily statement authored),
  and the mixed pair compiles strictly and tolerantly with scalar
  08:00:00–16:00:00.
- **Validation**: full `go test ./pkg/config/ ./pkg/scheduler/` green on head
  (implementer run), including the #9156 tunnel flat-run cells that the
  ungated first cut of this fix regressed (destination eaten under
  `routing-instance`) — the packedFlatRun gate is what reconciles the two
  bodies; `gofmt -l` clean on both changed files. Existing #12637/#12826
  nested-modifier tests (root/daily/weekday inline pair, contradiction
  rejects, repeat rejects) unchanged and green — the day window extraction
  path they pin (`expandFlatRun` inside `schedulerWindowFromNode`) is
  untouched.
- **Blast radius / risk**: `splitNestedForeignRun8939` serves every
  #8935/#9235 expansion site (policer if-exceeding/then, NAT pool,
  persistent-NAT, RA prefix, qualified-next-hop, flow aging, security log,
  DHCP static binding, ipfix templates, tunnel, dynamic-address profile). The
  new condition only SUPPRESSES a lift when the head resolves under a body
  root that declares `packedFlatRun` — i.e. the statement is legal where it
  sits in a body whose own declaration says nested runs are its spelling.
  Bodies without the flag (tunnel `routing-instance`, rpm `target`,
  qualified-next-hop `interface`) lift exactly as before; full-suite run
  confirms no behavioral drift.
