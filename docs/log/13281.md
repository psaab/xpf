# Issue #13281 — Cumulative session GC outcomes

## Finding

Source-review finding D3-06 identified that `SessionTable::expire_stale_entries_ha` reset `last_pop_stats` on every sweep. The worker status published only expired-session totals, leaving the other timer-wheel classifications invisible. This change keeps per-call stats semantics for existing callers and accumulates all `WheelPopStats` fields for lifetime telemetry.

## Changes

- Added saturating cumulative wheel-pop accounting to `SessionTable`; gated no-op sweeps do not change the cumulative total.
- Published the nine non-expired classifications through worker runtime counters, protocol status, and aggregate Prometheus counter families (`xpf_userspace_session_gc_*_total`).
- Added Rust session, runtime snapshot, and protocol round-trip regressions; added Go status JSON and collector aggregation tests.
- Regenerated `userspace-dp/tests/fixtures/protocol_wire_v1.json` for the added defaulted status fields.

## Validation

- RED on pristine implementation: the new session regression could not compile because `cumulative_pop_stats` was absent.
- GREEN: Rust cumulative-stats regression passed; all 243 `session::tests` passed; all 96 `protocol::tests` passed after updating the wire fixture; worker runtime snapshot round-trip tests passed.
- GREEN: focused Go Prometheus aggregation and userspace status JSON round-trip tests passed.
- Full Go API/userspace package run: `pkg/api` failed in unrelated `TestVRFOverlapAdmittedEmittedWhenDataplaneUnloaded_7991` due to duplicate metric gathering; focused added tests passed.

## Risk

Cumulative counters saturate at the integer maximum rather than wrapping. Existing `last_pop_stats` remains per-sweep, and status counters default to zero for older peers.
