# Issue #17163 — tunnel-ID gate side compile inherits caller compileOpts

- **Issue:** `emitNodeExpandedTunnelNames` (`pkg/config/tunnelid.go`) compiled each node view with a hard-coded `compileOpts{lenientNonNumericUnit: true}`. Four interface downgrades added later to `compileInterfaces` (`lenientInterfaceNumericBounds` #9899, `lenientInterfaceBandwidth`, `lenientInterfaceDuplex` #11824, `lenientInterfaceSpeed`) were never propagated to that literal, so on `CompileConfigLenient` any unrelated bad interface speed, duplex, bandwidth or VLAN bound made the side compile error out, the post-expansion View 2/3 fell to the empty set, and the #1914 wildcard tunnel-ID collision warning silently disappeared.
- **STEP-0 (defect live on origin/master `3abae28d24`):** `grep -n 'compileOpts{' pkg/config/tunnelid.go` returned line 226 with the hard-coded literal; `validateTunnelEndpointIDCollisionAST(tree, lenient bool)` at `tunnelid.go:284` received only the borrowed `opts.sanitizeFreeTextControlChars` bool from `compiler.go:551-552`, so the side compile could not inherit the caller's policy. Two direct test callers used the bool signature (`compiler_multi_root_5675_5691_test.go:205`, `tunnelid_test.go:513`).

## What

1. `validateTunnelEndpointIDCollisionAST(tree, opts compileOpts)` — threaded the caller's opts; `opts.sanitizeFreeTextControlChars` still selects lenient warn-vs-error, removing the mode-proxy bool. Production caller in `compiler.go` now passes `opts`; both direct test callers pass `compileOpts{}` (strict, unchanged verdicts).
2. `emitNodeExpandedTunnelNames(tree, nodeID, opts, out)` — compiles each view with a copy of the caller's opts, forcing `lenientNonNumericUnit = true` so the #5829 quarantine also holds on strict commits, and sends side-compile warnings to a throwaway sink (the view contributes names only, never diagnostics; no duplicate interface warnings leak into `cfg.Warnings`). Single source of truth: `grep -n 'compileOpts{' pkg/config/tunnelid.go` returns nothing.
3. Corrected stale docs: removed the false "gate-free interfaces sub-compiler" claim and the false "dropping the failed node's view loses no real coverage" claim in `tunnelid.go`; updated the signature citation in `compiler_peer_effective.go` (#6861 re-gate C1 passage). The sibling hard-coded literal in `compiler_validate_strict_reth_lag.go:213` is a different gate's scaffold (R4-Q23-01 territory) and is untouched.
4. Added regression table `TestTunnelIDSideCompileInheritsCallerOpts17163` (`tunnelid_test.go`): the #1914 wildcard fixture (wg78 via `<*>` group + wg1408, both fold to 824) plus one bad value per downgrade axis — speed `7g`, duplex `sideways`, bandwidth `notanumber`, and a `vlan-id 9999` bound on an unrelated third interface (`ge-0/0/0 unit 0`, since a unit-scoped downgrade skips that unit). Every row must carry the collision warning on `CompileConfigLenient`, plus a good-value control (`description uplink`) and strict-reject control per row.

## Risk

Strict-path behaviour is unchanged except that the side compile now also honours caller opts that are only ever set on lenient compiles (plus the forced #5829 flag, as before), so strict commits still reject bad interface values in `compileSections` and still reject the collision. Lenient compiles gain the previously-lost collision warning; side-compile warnings are discarded so `cfg.Warnings` gains no duplicates. The gate remains recursion-free (no `CompileConfig*` call) and HA-symmetric (both node views computed from the shared candidate on both nodes).
