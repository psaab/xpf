# #17814 — keep overlapping sync/arm debt at weight one

Startup-sync and dataplane-arm holds each represent the same not-ready state and normally carry a debt of 254. Summing both debts produced weight 0, which demoted a lone node despite the documented floor of 1.

A single locked monitor-debt calculation now counts the two hold debts as the larger of their individual weights, while leaving ordinary monitor and helper-crash-loop debts additive. This preserves weight 1 for the intended 254-point sync/arm debts without masking an explicit 255 debt on either reserved key. All four independent recompute paths use it: normal recalculation, config reconciliation, monitor-debt identification, and failover weight restoration. Regression coverage includes combined and sync-only holds, config reconciliation, failover debt derivation, independent-debt decay/recovery without a hold transition, true-zero monitor/helper controls, and reserved-key 255 controls.
