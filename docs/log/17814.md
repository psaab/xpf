# #17814 — keep overlapping sync/arm debt at weight one

Startup-sync and dataplane-arm holds each represent the same not-ready state and each carry a debt of 254. Summing both debts produced weight 0, which demoted a lone node despite the documented floor of 1.

A single locked monitor-debt calculation now counts the two hold debts as one shared penalty, capped at 254, while leaving ordinary monitor and helper-crash-loop debts additive. All four independent recompute paths use it: normal recalculation, config reconciliation, monitor-debt identification, and failover weight restoration. The regression covers combined holds, config reconciliation, failover debt derivation, and controls proving genuine monitor/helper failures still reach weight 0.
