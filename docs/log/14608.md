# Issue #14608 — Interface sampling is not per-family: `family inet` sampling exports IPv6 flows

## Why

`family inet { sampling { input; } }` and `family inet6 { sampling { ... } }`
both wrote the same family-less `unit.SamplingInput`/`unit.SamplingOutput`
pair (pkg/config/compiler_interfaces.go inet + inet6 arms,
pkg/config/types_interfaces.go). `BuildSamplingZones`
(pkg/flowexport/manager.go) built one zone->direction map from those
flags, and `ShouldExport(inZone, outZone)` / `FlowDirection(inZone,
outZone)` had no family dimension. The daemon gate
(pkg/daemon/daemon_flowexport.go) tested `ServesFamily` — the
*collector's* family (#6811/#2462) — not the interface's sampling family.

Consequence: with only `family inet sampling input` on the trust unit
and a dual-family sampling instance, an IPv6 trust->untrust close was
exported and consumed a 1-in-N slot (per-family denominators wrong;
excluded traffic in collector volume / top-talkers / compliance
exports). RED probe through the real parser->compiler->resolver->
`ShouldExport` on base: "IPv6 flow exported on second call: inet-only
sampling selected an IPv6 flow and consumed 1-in-N slots".

## What

- `pkg/config/types_interfaces.go`: replace `SamplingInput`/`SamplingOutput`
  with per-family `SamplingV4Input`/`SamplingV4Output`/`SamplingV6Input`/
  `SamplingV6Output` (clean cutover, no aliases). Persisted-config wire
  shape changes: `SamplingInput/Output` JSON keys become the four new
  keys (golden_4406.json + contract-9821 snapshot regenerated; Rust
  ignores unknown fields and reads none of these).
- `pkg/config/compiler_interfaces.go`: inet arm writes V4 flags, inet6
  arm writes V6 flags (repeated-sibling union preserved per family).
- `pkg/flowexport/manager.go`: `BuildSamplingZones` returns
  `FamilySamplingDirs{V4, V6}` (one map per family).
  Global rule: interface sampling is a per-family *selection* — once
  any family is sampled, a family sampled nowhere fails closed
  (non-nil empty map) and is denied before the 1-in-N counter advances,
  so it never consumes a slot. No sampling anywhere keeps both maps nil
  (documented export-all). Absent-unit restriction materializes both
  families (the absent unit's family flags are unknowable; preserves
  the pre-fix deny-all). `ShouldExport(in, out, isIPv6)` and
  `FlowDirection(in, out, isIPv6)` consult only the record's family.
- `pkg/daemon/daemon_flowexport.go`: both callbacks pass `sd.IsIPv6`
  into `ShouldExport`/`FlowDirection`; reconciled-exporter log counts
  sum both family maps.
- `pkg/config/compiler_validate_warn.go`: `anySamplingDirectionConfigured`
  checks all four flags.
- Docs: `pkg/flowexport/README.md` records the per-family model and
  reconciles it with `docs/feature-gaps.md`'s "per-interface sampling
  (input/output, per-family)" claim (now true). feature-gaps text
  unchanged.

NOT changed: collector-side `ServesFamily`/`GroupIsV6` (#6811) — it
stays the discriminating control; a dual-family instance passes it for
IPv6 yet the interface-sampling family now denies the flow. No
per-interface sampling-instance selector added (none exists in the
config model). 1-in-N counter stays per-instance shared across its
families (pre-existing #2462 semantics; per-family *zone eligibility*
is what this fix scopes).

## Risk

- Persisted config JSON renames SamplingInput/Output keys; strict
  commit/load paths tolerate the rename (fields default false; Rust
  consumer ignores unknown fields). A rollback to pre-fix binaries
  would read sampling as off (fail-closed for telemetry only).
- Behaviour delta: configs that relied on the buggy cross-family
  selection (e.g. inet-only sampling expecting IPv6 exports) will now
  see those flows denied; that is the operator contract in
  feature-gaps.md. `sampling` under both families is unchanged.
- Coverage limit: daemon test drives NetFlow v9 + IPFIX via
  ProcessRawEvent on loopback collectors; no loss-cluster smoke
  (telemetry-only change; main agent to run cluster gate if desired).
