# Issue #12053 — subtract host-inbound service exclusions by L4 tuple

- **Issue:** `system-services all` plus a service `except` left the excluded tuple admitted through aliases such as `netconf-ssh`, `webapi-clear-text`, `ipsec`, and `bootp`.
- **Base:** `a714c90d472a3c3d98a3799831cfef3ec311a61c` (`origin/master` at STEP-0).
- **Branch:** `fix/12053-except-tuple`.
- **Worktree:** `/var/worktrees/12053-except-tuple`.
- **Issue body:** Read with `gh issue view 12053` before implementation; no comments were present.

## Change

`hostInboundFilterExcept` now resolves each known excluded system service to its family-scoped `HostInboundServiceMatch` tuples and filters positive services by tuple intersection as well as exact name. This removes every alias that can re-admit an excluded tuple, including aliases added while repeated same-key stanzas are merged. The structured match helper compares protocol, port ranges, and ICMP types; reject-only matches are not treated as admissions. `protocols` exclusions retain their existing name-based behavior.

The compiled positive-token list is already the shared input to the kernel nft and netlink renderers and to the Rust classifier, so those consumers do not need separate late masks. Added coverage at the config, daemon nft, netlink, and Rust classifier boundaries. Updated the service-matrix documentation to describe tuple-aware `except` behavior.

## Risk and residual

Exclusion is token-granular: if a token contributes multiple tuples and any intersects an excluded tuple, that whole token is removed. Other independently named, non-overlapping services remain (for example, `netconf` still admits TCP/830 after `ssh except`). The separate `any-service` full-admit escape hatch is unchanged. No live cluster or network configuration was mutated.
