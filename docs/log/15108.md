# Term hit counters survive an unchanged snapshot refresh (#15108)

- **Issue**: #15108 (deep-review finding A64-04).
- **Cause**: `userspace-dp/src/filter/compiler.rs` `parse_term` /
  `build_filter_term` minted a fresh `Arc::new(FilterTermCounter::default())`
  for every term on every snapshot rebuild, and
  `parse_filter_state_with_three_color_preserving` consulted `previous`
  only for three-color policer runtimes (`build_term_scoped_policer_runtimes`).
  Any committed config change or HA config-sync apply therefore silently
  zeroed `show firewall` hit counts, even for filters/terms the change did
  not touch.
- **Change**:
  - `compiler.rs`: `parse_filter_table` and `parse_term` now take
    `previous: Option<&FilterState>` (threaded from
    `parse_filter_state_with_three_color_preserving`, whose production
    caller in `afxdp/forwarding_build/mod.rs` already passes the prior
    state). After building a term, `parse_term` looks up the previous term
    at the same (family, filter, term) identity — `filters["family:name"]`
    key, term matched by name — and, when the compiled shape matches,
    replaces the fresh counter with `previous_term.counter.clone()`.
  - `filter/engine/cache_sensitive/rotation.rs`: new
    `filter_term_counter_shape_matches(old, new)` predicate, defined as
    exactly `filter_term_semantics_match` — the #5293 exhaustive
    destructure over every match/action/modifier field (addresses, ports,
    protocols, DSCP, tcp-flags, icmp, flex, action, `continue_term`,
    `count` name, `log`, policer name + three-color runtime shape,
    routing-instance, forwarding-class, `dscp_rewrite`). The counter Arc
    itself is the only excluded field (it is the handle being carried);
    the positional `id` is likewise excluded. Re-exported through
    `cache_sensitive.rs` and `engine/mod.rs` as
    `crate::filter::engine::filter_term_counter_shape_matches`.
  - Any shape change — match, action, counter-name, or policer shape
    (a policer shape change already mints a fresh runtime Arc, which the
    semantics comparison observes) — keeps the fresh zeroed counter, so
    hits never leak across a different contract. No fail-open direction is
    introduced: this is counter identity only, match/action lowering is
    untouched.
- **Regression coverage** (`filter/tests.rs`, all `_15108`):
  - `unchanged_refresh_preserves_term_counter_15108`: 7 counted hits
    (100 bytes each) on `inet:edge`/`web`, then an identical refresh via
    `parse_filter_state_with_three_color_preserving(..., Some(&state))`;
    asserts `Arc::ptr_eq` on the counter, `(7, 700)` after the refresh
    (the issue's "probe shows 7" acceptance), and `(8, 800)` after one
    more hit through the refreshed state.
  - `changed_term_gets_fresh_counter_15108`: counter-name change,
    destination-port change, and action change each produce a fresh
    `(0, 0)` counter (no `Arc::ptr_eq`).
  - `renamed_term_does_not_inherit_counter_15108`: a different term name
    at the same position does not inherit the old counter.
- **RED evidence**: Tests-only on pristine `origin/master`
  (`965c5ca3b0`, prod+README reverted, tests kept):
  `unchanged_refresh_preserves_term_counter_15108` FAILED at the
  `Arc::ptr_eq` assertion ("unchanged term must carry its counter Arc
  across the refresh"); the two changed-shape controls passed (they
  assert fresh counters, which the old code also produces). 1 failed /
  2 passed.
- **GREEN evidence**: With the fix, `cargo test --bin xpf-userspace-dp
  15108` reports 3 passed / 0 failed. The full `filter::` module run
  reports 433 passed / 5 failed; all 5 failures
  (`cached_tx_selection_records_all_fallthrough_count_terms`, three
  `static_verdict_*_7212` cells, and
  `stage11_local_ike_passthrough_honors_ingress_input_filter_13637`)
  fail identically on pristine `origin/master` (verified by stashing
  this change and re-running each), so they are pre-existing and
  unrelated. Runs used `--test-threads=1`,
  `CARGO_TARGET_DIR=/var/worktrees/.cache/cargo-15108`.
- **Blast radius / risk**: Compile-time only, off the per-packet hot path
  (one hashmap lookup + name scan + field comparison per term per
  rebuild, same order as the existing policer-runtime reuse). Packet-path
  behaviour, wire format, and status JSON shape are unchanged; counters
  now persist across refreshes for unchanged terms, which is the operator
  expectation for `show firewall`. HA failover and process restart still
  rebuild counters from zero (no previous state exists).
