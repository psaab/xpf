# Dual-stack primary dropped, non-first primary secondary, flip no-op (#15653, V19-01)

- **Issue**: #15653 — `interfaces <ifd> unit <u> family inet|inet6 address
  <cidr> primary` installed non-first primaries as `IFA_F_SECONDARY` on
  live netlink reconcile, treated `primary` flips as a no-op, and dropped
  `family inet6 ... primary` on dual-stack units.
- **Cause**:
  - `pkg/config/types_interfaces.go`: a single `PrimaryAddress` /
    `PreferredAddress` slot served both families. `family inet` filled it
    last-wins, `family inet6` only when empty — so on a dual-stack unit
    the second family's primary/preferred was silently discarded.
  - `pkg/dataplane/compiler_iface.go` `planAddressReconcile`: adds
    followed authored order (a non-first primary was added after its
    subnet peer and the kernel marked it `IFA_F_SECONDARY`), and any
    already-present desired address short-circuited via `present[]`, so
    flipping `primary` to an existing secondary changed nothing.
  - The systemd-networkd path already ordered the (single) primary
    first (#15222), but the live-netlink leg did not, and neither leg
    had a per-family IPv6 primary to order.
- **Change**:
  - `pkg/config/types_interfaces.go`: added `PrimaryAddressV6` /
    `PreferredAddressV6` plus `PrimaryAddressForFamily(bool)` /
    `PreferredAddressForFamily(bool)` accessors (IPv6 falls back to the
    legacy slot when it holds an IPv6 CIDR, preserving single-family
    inet6 and hand-built fixtures). Legacy slots now document IPv4.
  - `pkg/config/compiler_interfaces.go`: `inet` keeps the legacy slots;
    `inet6` fills the V6 slots first-wins and mirrors into the legacy
    slots only while empty. `suppressInvalidRethAddresses` clears all
    four slots.
  - `pkg/dataplane/compiler_iface_desired.go`: `physDesired` carries
    `primaryV4`/`primaryV6` merged from its units.
  - `pkg/dataplane/compiler_iface.go`: `orderPrimariesFirst` moves each
    family's primary ahead of its same-subnet peers; `planAddressReconcile`
    (variadic `primaries ...string`, existing callers unchanged) promotes
    a desired IPv4 primary carrying `IFA_F_SECONDARY` by deleting its
    same-subnet peers, then the primary, then re-adding primary-first.
    Both reconcile call sites (physical union, VLAN sub-interface) pass
    per-family primaries.
  - `pkg/networkd/networkd.go`: `InterfaceConfig` gains
    `PrimaryAddressV6`/`PreferredAddressV6`; when present, primaries and
    preferreds order first-per-subnet per family, otherwise the legacy
    global-primary ordering is preserved exactly. All three
    `buildInterfaceNetworkdModels` sites populate the V6 fields (cleared
    on unit-disable / VRRP-RETH replacement).
  - Consumers: `syslogUnitSourceAddr` (per-family candidates first),
    `pkg/ipsec` `selectUnitAddress` (per-family candidates first),
    `compiler_validate_ipsec_gateway_routing_instance_12089.go` (records
    and family-checks V6 slots), and userspace
    `buildConfiguredAddressSnapshots` (marks both families' primaries,
    so `pickInterfaceSnapshotV6` honours the inet6 primary).
- **RED evidence**: the new
  `pkg/dataplane/dualstack_primary_15653_test.go` copied onto pristine
  `origin/master` (d316277cb4) fails to build — `PrimaryAddressV6`,
  `PreferredAddressV6`, `PrimaryAddressForFamily`, `physDesired.primaryV4/V6`
  undefined — proving the per-family model was absent; behaviourally the
  pre-fix planner also returns an empty plan for a secondary primary and
  authored-order adds. On the fix it passes.
- **GREEN evidence**: `go test ./pkg/dataplane -run
  'TestDualStackPrimaryAddressAndNetlinkPromotion|TestPlanAddressReconcile|...'`
  passes; `go test ./pkg/config -run
  'TestPreferredAddress|TestCompileConfig|Syslog|...'`, `./pkg/networkd`,
  `./pkg/ipsec`, `./pkg/dataplane/userspace` targeted suites pass;
  `TestDualStackPrimaryOrdering15653` (networkd) passes.
- **Known base failures (not this change)**: on pristine master,
  `TestCompileGolden4406` already fails (stale tcp-mss range text,
  `SourceAddress` field, #15034 warnings drift) and
  `TestInterfaceVLANBounds9899` already fails (#15034 messages) — both
  reproduce identically with and without this fix, so the golden file
  was deliberately NOT regenerated here (a regen would absorb unrelated
  drift; the new JSON fields appear as `PrimaryAddressV6` /
  `PreferredAddressV6` in compiled output and need a golden refresh
  whenever the golden is next legitimately regenerated).
- **Risk**: a primary flip now briefly deletes and re-adds the subnet's
  IPv4 addresses on that interface (required for kernel promotion);
  converged applies (primary already non-secondary, or no primary
  configured) plan exactly as before. Legacy `PrimaryAddress` readers
  keep IPv4 semantics; rollback to a pre-#15653 binary ignores the V6
  slots and reverts to the old dual-stack drop.
