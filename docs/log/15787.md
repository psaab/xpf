# #15787 - inner non-first fragments dropped / misparsed on tunnel decapsulation

- **Timestamp**: 2026-10-19
- **Action**: Ported the XDP shim's `PROTO_FRAGMENT_NO_L4` (255)
  substitution inward to the tunnel-decap inner parsers.
  `packet_rel_l4_offset_and_protocol` in
  `userspace-dp/src/afxdp/frame/inspect.rs` now returns
  `(payload_offset, SHIM_PROTO_FRAGMENT_NO_L4)` for an IPv4 non-first
  fragment (offset = IHL) and for an IPv6 chain ending in
  `ExtChainOutcome::NonFirstFragment` (offset = first byte past the
  Fragment header), instead of the IPv4 Protocol byte (payload parsed
  as TCP/UDP) and `None` (100% drop) respectively.
  `packet_rel_l4_offset` / `frame_l4_offset` surrender no L4 offset for
  an IPv4 non-first fragment (IPv6 already did via the walk verdict).
  `parse_inner_protocol_and_offsets` in
  `userspace-dp/src/afxdp/gre.rs` admits both families as
  `(255, payload_offset, payload_offset)` — flowless, no L4 read — so
  GRE, WireGuard worker decap, WG uncovered forward, and (via
  `packet_rel_l4_offset_and_protocol_for_ipsec` in `slowpath.rs`,
  whose catch-all payload arm now receives the sentinel instead of a
  `(0,0,0)` stamp) the IPsec-inner descriptor path all admit inner
  non-first fragments instead of dropping or misparsing them.
  First/atomic fragments keep the real L4 parse unchanged.
  One consumer needed the real wire protocol, not the sentinel:
  `neighbor_dispatch.rs`'s deferred NAT retry recovered it via
  `packet_rel_l4_offset_and_protocol` and would have treated a raw
  ESP tail as translatable; it now recovers the declared protocol via
  `fragment_protocol_from_frame` (the same helper
  `flowless_effective_protocol` uses), keeping ESP/AH passthrough.
- **Validation**: New `tests_inner_frag_15787` (registered in
  `frame/mod.rs`) covers, per decap entry point: IPv4 non-first
  TCP-shaped and UDP-shaped payloads → `(255, 20, 20)` (RED pre-fix:
  `(6, 20, 40)` / `(17, 20, 28)`), IPv6 non-first → `(255, 48, 48)`
  (RED pre-fix: `None`), plus first-fragment and unfragmented
  controls. Updated two existing pins to the new contract:
  `ext_walk_nonfirst_fragment_payload_is_not_walked_14116` now expects
  the sentinel from `_and_protocol` (offset-only still `None`), and
  the `parse_offset_consistency_garbage` property gates its
  offset-agreement exception on the real fragment predicate (a garbage
  terminal byte 255 is not a fragment). Affected suites
  (`tests_inner_frag_15787`, ext-walk, shim parity, prop consistency,
  ESP/UDP neighbor-retry tails) pass. Remaining failures in the wider
  filtered run (`tests_gre_local_delivery` TTL, `gre_tun_origin_*`,
  `snapshot_published_tunnel_rows_join_d11_10485`,
  `loop_body_mod_stays_below_refactor_ceiling`, `event_stream` codec
  7188, `flowless_slack_tcp_not_steered_by_port_except_pbr_9894`) are
  base-attributed: verified failing identically on pristine
  `origin/master` (f7c921ce29).
- **Risk**: Fail-closed direction preserved everywhere else: truncated
  Fragment headers, over-limit chains, and No-Next-Header still return
  `None`; only a readable non-first Fragment sighting (or a readable
  IPv4 frag_off) yields the sentinel, at the payload offset, with no
  L4 bytes read. Downstream, protocol 255 is the established
  flowless/no-L4 identity (ports 0/0, no ported session, L3 addresses
  still stamped per #15772), so admitted fragments take the existing
  session-less forward path. The neighbor-retry change only swaps the
  protocol-recovery helper for the identical declared-header value.
