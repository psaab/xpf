# Issue #14133 — RefreshInterfaceRowsForLink: no quarantine scrub, drops xfrmDumpFailed, skips XDP attach on ifindex change

## Why

`Manager.RefreshInterfaceRowsForLink` (pkg/dataplane/userspace/manager_link_refresh.go) copies `*current`, rebuilds only Interfaces/Routes/Fabrics/TunnelEndpoints/Mirrors, and publishes via `requestApplySnapshotPreparedLocked`. That bypassed three guarantees the full build (builder.go / Compile) maintains:

1. **No quarantine scrub**: builder.go runs `quarantineCollidingZones` after every full build, dropping StableZoneID-colliding/poisoned/reserved zones and unzoning their interfaces. The refresh rebuilt interface rows from cfg without re-applying it, so a link recreated inside a quarantined zone was published zoned again, resurrecting the merged-zone hazard and leaving `zoneIDCollisions`/`ZoneSetValidated`/summary counts stale.
2. **Dropped xfrmDumpFailed**: the refresh sampled `liveXfrm, _ := sampleLiveXfrmNetdevs()`, retaining the previous snapshot's stale failure flag instead of the fresh sample's verdict (builder.go stamps `snap.xfrmDumpFailed = xfrmDumpFailed`).
3. **Skipped XDP attach on ifindex change**: only `Compile -> CompileUserspaceShim -> attachUserspaceShimXDP` attaches the XDP shim; the Rust helper never attaches (it binds AF_XDP sockets to shim-covered interfaces). A recreated link's new ifindex was published with no tracked XDP ingress until the next full reapply. (Verified in-repo: no Rust-side attach path exists; grep of userspace-dp/src for attach shows only tunnel/WG thread attachment, not XDP shim attach.)

## What

In `RefreshInterfaceRowsForLink`:
- Capture `liveXfrm, xfrmDumpFailed := sampleLiveXfrmNetdevs()` and stamp `next.xfrmDumpFailed = xfrmDumpFailed`.
- After rebuilding Interfaces/Routes/Fabrics/TunnelEndpoints/Mirrors, run `next.zoneIDCollisions = quarantineCollidingZones(&next)`, recompute `ZoneSetValidated`, fix summary counts when quarantined, and record policy-content-rejection + zone-collision diagnostics exactly as builder.go/Compile do. The scrub is idempotent on an already-reduced snapshot.
- Before publishing, `reconcileInterfaceAttachmentsForRefreshLocked(&next)` attaches the XDP shim (via a new `attachInterfaceXDPHook` test seam, nil in production) to every ingress ifindex in the new snapshot not already tracked, with Compile's tunnel/VLAN generic classification and native→generic fallback. Attach failure is logged and left fail-closed (no program = fence-dropped transit), never failing the publish. The detach half is deliberately NOT done here: detaching before helper acceptance would repeat the #5485 bypass; obsolete attachments are reaped by the next full Compile's post-acceptance `syncInterfaceAttachments`.

Regression tests in `manager_link_refresh_14133_test.go`:
- `TestInterfaceLinkRefreshQuarantinesRecreatedRow14133`
- `TestInterfaceLinkRefreshStampsFreshXfrmDumpFailed14133`
- `TestInterfaceLinkRefreshAttachesRecreatedIfindex14133`

## Validation

Regression RED/GREEN: the quarantine and xfrm tests fail on pristine origin/master (checked in a separate base worktree with the unexported-field-only attach test adjusted to compile there: `zoneIDCollisions = [], want z214 quarantined`; `retained snapshot lost the fresh xfrm dump failure status`) and all three pass with the fix. Existing `TestInterfaceLinkRefresh*` tests pass. Full `pkg/dataplane/userspace` package run: see PR body for the final result (any pre-existing failures compared against base).

## Risk

Attach attempts run under `m.mu` before publish and may issue netlink/BPF syscalls; failures only log (fail-closed). The quarantine re-application is a no-op in the common no-collision case. No Rust changes; no test-input special-casing — the scrub/attach/xfrm paths are the production builders' own functions.
