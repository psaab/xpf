# #14194 — dash alias bypasses RETH key policy, not node-slot check

## Why

`validateDeviceMapStrict` (pkg/config/compiler_chassis.go) built its
RETH-member set keyed on the raw declared interface name (`ge-0/0/3`)
and looked entries up by raw `e.LogicalName`. `LinuxIfName` folds slash
to dash, so `ge-0/0/3` and `ge-0-0-3` are one interface — the #6546
duplicate-name check in the same function already canonicalises that
way, but the R-6 RETH lookup did not. A slash RETH member paired with a
single dash device-map entry (`ge-0-0-3 key mac`) therefore skipped
strict R-6 rejection. `pkg/devicemap.Resolve` repeated the raw lookup
(`rethMembers[e.LogicalName]`) while separately computing
`logical := LinuxIfName(e.LogicalName)`, and `RethMembersFromConfig`
keyed raw, so the resolver's PCI-only defense was skipped too. A
MAC-only binding can become unavailable/misbound when that member's
MAC alternates physical<->virtual with the HA/RETH role. The issue's
wrong-node subclaim was already false: `InterfaceSlot` parses the dash
spelling (#8829) and the slot gate rejects it — that is kept as a
control, not changed.

## What

- `pkg/config/compiler_chassis.go`: key `rethMembers` by
  `LinuxIfName(ifc.Name)` and look up `rethMembers[LinuxIfName(e.LogicalName)]`.
  Both the `key mac`/`mac-then-pci` arm and the `PCIAddr == ""` (MAC-only
  default pci-then-mac) arm now see dash/slash aliases symmetrically.
- `pkg/devicemap/devicemap.go`: `RethMembersFromConfig` returns canonical
  Linux-name keys; `Resolve` canonicalises the incoming `rethMembers`
  map once (`canonRETH`) and looks up `canonRETH[logical]`, so hand-built
  slash-keyed maps from existing callers/tests are also honoured.
  This covers all consumers (`pkg/daemon`, `pkg/cli`, `pkg/grpcapi`)
  without changing their call sites.
- NOT changed: `InterfaceSlot`/slot gate (already correct for dash),
  key-order semantics, duplicate-name/PCI/MAC checks, tolerant-path
  downgrade (lenient compile still warns instead of failing — the RETH
  error flows through the existing `lenientDeviceMap` warning path),
  `.link` writing (already OriginalName-only).
- Regression: `pkg/config/compiler_device_map_reth_dash_alias_14194_test.go`
  (strict compile: slash/dash member×entry `key mac`, `mac-then-pci`,
  MAC-only-no-PCI, direct validator matrix, PCI-keyed and non-RETH
  controls, wrong-node dash+slash slot control) and
  `pkg/devicemap/reth_dash_alias_14194_test.go` (resolve: alias matrix
  must go UNBOUND not MAC-bound, physical→virtual MAC transition with
  non-RETH control, PCI bind control, canonical producer keys, raw-map
  honoured). No test input is special-cased in production code; the fix
  is the general canonical keying.

## Risk

Strict commits that previously (incorrectly) accepted a MAC-keyed dash
entry for a slash RETH member will now be rejected with the existing
R-6 message — intended fail-closed change; PCI-keyed equivalents still
commit, and the tolerant load/peer-sync path still downgrades to a
warning so a persisted config still boots. `RethMembersFromConfig`
key spelling changes from raw to canonical: in-repo consumers only
pass the map to `Resolve`, which now canonicalises either spelling,
so no caller depends on raw keys.
