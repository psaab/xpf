# #15074 — HA probe-gating RG chosen by Go map iteration order for multi-RG probes (A49-02)

- **Timestamp**: 2026-10-18 (`fix/15074-campaign`)

## Why

`rpmProbeGatingRGs` computed one gating RG per probe by ranging over
`probe.Tests` (a Go map) with last-writer-wins assignment
(`inScope, rgID = true, rg`). For a probe whose tests bind RETHs in
different redundancy groups, the chosen RG — and therefore
`filterRPMForHAGating`'s keep/drop decision against
`IsLocalPrimary(rgID)` — flipped with map iteration order across
reconciles (commit, RG transition, boot). In a multi-RG cluster the
probe could run on both nodes, on neither, or move between reconciles:
on a reconcile it could be dropped on the node that owns the live RG,
so ip-monitoring lost the failover sensor for that RG while the
standby ran a structurally-failing probe.

## What

- `pkg/daemon/daemon_rpm.go`: gating is now per test.
  `rpmProbeTestGating` resolves each test independently — its own
  `destination-interface` RETH RG, else its own `source-address` VIP
  RG, else (when its probe is ip-monitoring-referenced) the lowest
  data RG — and writes each `probeTestKey{probe,test}` exactly once,
  so the result cannot depend on map iteration order.
  `filterRPMForHAGating` keeps exactly the tests this node is primary
  for, drops a probe only when no test survives, and never mutates the
  authored config (partial probes are copies; untouched probes keep
  their identity). Junos has no multi-RG probe spelling (a Junos probe
  sits in one routing instance), so running the locally-owned tests is
  the per-test gate the issue's first fix direction names; refusing
  the commit was rejected because it would deny a config Junos accepts
  in its single-RG form and lose the owned RG's monitoring entirely.
  `rpmProbeGatingRGs` is retained as a deterministic derived view
  (lowest test RG per in-scope probe) for the takeover-burst gate and
  the #3764 publish comment, which only need in-scope membership.
- `pkg/daemon/daemon_rpm_mixed_rg_15074_test.go`: mixed-RG regression
  (200-iteration determinism, RG1-only / RG2-only / both / neither
  primary sets, authored-config immutability, ungated control) plus a
  single-RG all-or-nothing control.
- `pkg/daemon/README.md`, `pkg/daemon/daemon_ipmon.go`: gating-scope
  comments updated to the per-test shape.

NOT changed: the ip-monitoring publish gate (`IsLocalPrimaryAny`,
#3764) — per-test probe gating leaves its reasoning intact; the
unbound-probe default to the lowest data RG (documented #3764
residual) is preserved per test.

## Validation

- **Base / RED**: on `origin/master`, a base-symbols-only harness
  (`rpmProbeGatingRGs` over the mixed-RG config, 500 calls) flips the
  probe's gating RG between RG1 and RG2 with map iteration order —
  exact distribution recorded in the PR body. The shipped regression
  additionally asserts the exact per-test effective set, which the
  probe-level base code cannot express.
- **Focused GREEN**: `go test ./pkg/daemon/ -run
  'TestMixedRGProbeGatesPerTest15074|TestProbeLevelGatingControl15074|TestRPMHAGatingFilter|TestTakeoverBurstOnly|TestIPMonPublishAllowedAnyPrimary' -count=1`
  passed; `go vet ./pkg/daemon/` and `gofmt` clean.

## Risk

Only the §4.4 HA gating filter shape changes. Single-RG probes (the
common case) filter identically to before. Mixed-RG probes now run
partial test sets on split-primary nodes where they previously ran
all-or-nothing nondeterministically; a partially-running probe that
was already partly running gets no takeover burst for its newly
enabled tests (they join via the hash-gated apply). No commit-time
rejection is added, so no previously-accepted config becomes invalid.
