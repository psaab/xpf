# #16501: unconfigured unit casts an effective zone vote on a shared tunnel ifindex

- **Timestamp**: 2026-10-24
- **Action**: `unit_host_inbound_claims` in
  `userspace-dp/src/afxdp/forwarding_build/interfaces.rs` skipped every
  unconfigured logical-unit row (`!iface.host_inbound_configured`), so a
  configured sibling's per-interface host-inbound override was installed
  on the shared netdev ifindex and governed every unit on it: the
  unconfigured unit's peers gained the sibling's services and lost the
  unconfigured unit's zone services on the Rust plane. Now every
  logical-unit row votes with its EFFECTIVE signature — a configured row
  with its override tokens, an unconfigured row with its zone's tokens
  (empty when the row names no known zone), canonicalised by the same
  `unit_host_inbound_vote` — mirroring the Go `claimNetdev` signature in
  `pkg/dataplane/userspace/zones_host_inbound.go`. A mismatch yields
  `Disagree` and the existing empty fail-closed sentinel; an unconfigured
  unit whose zone set equals the sibling's override still agrees and
  keeps the agreed override. Updated the stale "casts no vote" comment
  and the operator warning text. Flipped case (b) of
  `shared_ifindex_agreed_or_single_unit_host_inbound_still_admitted_16057`
  to the agreement shape (zone = ssh-only) and added
  `shared_ifindex_unconfigured_unit_zone_vote_disputes_configured_sibling_16501`
  (subject shape in both row orders plus an unconfigured-alone control).
