# #12841 — use declared-aware DHCP withholding lookups

- **Timestamp**: 2026-10-13 (`fix/12841-d3-04`)
- **Action**: align `ZoneConfig.WithholdsZoneLevelDHCPFor` query canonicalization with the declared-aware `SplitInterfaceUnitRef` contract (#9821).

## Root cause

`stampZoneDHCPScopeWithheld` already wrote its derived keys using `cfg.SplitInterfaceUnitRef(ref).Literal`, which observes declared dotted interface names. Its query method instead used cfg-free `CanonicalInterfaceUnitRef`, which splits on the first dot. The representations diverged for a declared padded bare name (`p.01` vs `p.1`, false withholding) and for a padded unit below a declared dotted name (`p.0.01` vs `p.0.1`, missed withholding). This changed effective zone DHCP/BOOTP admission.

## Change

- The withholding stamp now retains the config's non-nil declared-interface set on each `ZoneConfig`; the query method has no `*Config`, so it needs this set to call the shared declared-aware splitter.
- Both the stamp and query use `splitInterfaceRefWithDeclared(...).Literal`; no first-dot canonical alias can merge distinct declarations or miss a padded suffix under a dotted declaration.
- Added regression cases for both wrong-answer directions and normal/unconfigured-unit controls, including assertions through `InterfaceHostInboundEffective`.
