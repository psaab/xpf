# #17852: unconditional source-ownership scans on lookups and session stamping

- **Timestamp**: 2026-10-27
  - **Action**: The #16799 return-order fix computed the linear
    source-ownership scan (`source_table_owns_v[46]`) unconditionally:
    once before the LPM of every leak-evaluating lookup (even when the
    table had no rib-group return rows at all) and once in
    `leak_incarnation_for_resolution` before even consulting
    `leak_rules_v[46]`. For a table with no deferred returns the scan
    is dead work on the per-packet hot path and on session stamping.
    Fix (Rust FIB only; no wire, builder, or Go change): gate the scan
    on the only condition that consumes it. New
    `table_has_deferred_leak_v[46]` returns true only when the table
    holds a `post_table` row covering the destination — the exact rule
    set `try_deferred_leaks_v[46]` walks — and the lookup miss tails
    now evaluate `NoRoute -> deferred-covers -> !source_table_owns`
    (cheapest predicate first) instead of scanning ownership before
    the LPM; the incarnation helper consults the leak-rule map first
    and scans ownership only when a deferred row covering the
    destination exists (stage-1 rows never consult it). Ordering
    semantics are preserved exactly: every gated predicate is a pure
    function of immutable state, and a false
    `table_has_deferred_leak_*` is precisely the case where the
    deferred pass would have found nothing, so no lookup or stamp
    outcome can change.
  - **File(s)**: `userspace-dp/src/afxdp/forwarding/fib.rs` (gated
    tails, gated incarnation arms, gate helpers, test-only scan
    counter), `userspace-dp/src/afxdp/forwarding/mod.rs` (module),
    `userspace-dp/src/afxdp/forwarding/tests_ownership_scan_gate_17852.rs`
    (new), `docs/log/17852.md`.
  - **Validation**: New `tests_ownership_scan_gate_17852` (6 cells)
    drives the production `build_forwarding_state` + resolvers with
    the #16799 va38 fixture shape and a thread-local scan counter:
    v4/v6 lookups with no leak rules (hit and NoRoute), a stage-1-only
    (30000-band) leak set (leak hit and miss), and incarnation checks
    with no rules / stage-1-only all perform ZERO ownership scans,
    while covering deferred returns still scan and still defer (source
    miss -> egress 21; A default -> egress 20; stamp on miss, no stamp
    when the source owns). RED: with the gating reverted (unconditional
    scans restored, counter kept) 5 of 6 cells fail with
    `left: 1, right: 0`. Full `afxdp::forwarding::` suite: 429 passed,
    1 pre-existing failure (`matched_family_pairs_are_still_admitted_7520`,
    reproduced on pristine `origin/master` without this change; an
    unrelated ICMP-family pairing cell) — including the #16799
    return-order cells (`tests_return_order_16799`) and
    `tests_leak_precheck_14319`.
  - **Risk**: Behaviorally none intended — the gate is a pure
    short-circuit of dead work; the residual cost for tables WITH a
    covering deferred return is one small leak-rule-vector walk
    (typically a handful of rows) before the ownership scan, and the
    ownership scan itself still runs exactly when a deferred return
    can fire. The test-only counter lives behind `#[cfg(test)]` and
    does not exist in production builds.
