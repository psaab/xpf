# #15184 — config: BGP neighbor accepts any single token (C04-02)

- **Timestamp**: 2026-10-19
- **Action**: Require a BGP neighbor identity to be a bare IP address
  (`netip.ParseAddr`, no zone, no prefix) at commit and omit non-IP
  neighbors at render, instead of accepting any single token.

## Mechanism

`protocols bgp group G neighbor <x>` (shared with routing-instances via
`schemaRoutingInstanceProtocols`) had no `keyValidator`; the strict gate
`validateBGPNeighborAddressStrict` only checked single-token-ness
(#6796) and `frr.validBGPNeighborAddress` mirrored it. So `10.0.0.256`,
`192.0.2.0/24`, `peer-a`, `peer.example.com` and `fe80::1%ge-0-0-1`
passed CommitCheck, rendered verbatim as `neighbor <x> remote-as ...`,
bgpd refused them, and `frr-reload.py` exited 1 on every reload — the
box stayed permanently unconverged and the peer never existed.

## Fix

- `pkg/config/schema_validators_routing.go`: new
  `ValidateBGPNeighborAddress` (+ boolean `ValidBGPNeighborAddress`).
  Rejects empty/padded, prefix (`/`), non-IP, and zoned addresses; a
  scoped link-local (`fe80::1%ge-0-0-1`) gets an explicit
  "scoped/zoned addresses are unsupported" message. Unscoped `fe80::1`
  remains valid (bare IP).
- `pkg/config/schema_routing.go`: BGP `neighbor` node now carries
  `keyValidator: ValidateBGPNeighborAddress` with `keyValueType:
  ValueIPAddress` metadata. The node is a container, so the regular
  `valueType`/`validator` stay unset (per schema.go contract). The
  routing-instance BGP subtree shares this node pointer, so both scopes
  are gated.
- `pkg/config/compiler_validate_strict_routing.go`:
  `validateBGPNeighborAddressStrict` now delegates to
  `ValidateBGPNeighborAddress` (preserving the #6796 multi-token
  diagnostic for whitespace-bearing values). Strict on commit,
  downgraded to a warning on the tolerant load/peer-sync path via the
  existing `lenientBGPNeighborAddress` opt (#1960).
- `pkg/frr/render_validate.go`: `validBGPNeighborAddress` now mirrors
  the same predicate (`netip.ParseAddr` + no zone), so the lenient
  load/HA-sync path omits the neighbor from `validNeighbors` (and thus
  from declaration, AF activation and BFD) instead of breaking reload.
- Behaviour change (intended, per issue): hostname / peer-group-name
  neighbors (`peer.example.com`, `UPSTREAM-GROUP`, `peer-template`)
  previously accepted are now rejected at commit and omitted at render
  on the tolerant path. Existing tests that encoded that acceptance
  (#6796 accept rows, #2454 family test, #12185 non-literal strict case)
  were updated: bare-IP rows stay green, the #2454/#12185 family logic
  is now exercised via `CompileConfigLenient`, and `pkg/frr/README.md`
  records the supersession.

## Risk

Operators with hostname/peer-group BGP neighbors must change them to
IP literals before commit will accept them; already-persisted such
configs still boot (lenient warning) but the neighbor is omitted from
frr.conf until fixed — the fail-closed direction the issue requires,
instead of poisoning every reload.
