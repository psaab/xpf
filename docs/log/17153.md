# #17153 — tolerant-path mode queries borrowed unrelated gate flags (R4-Q20-03)

- **Timestamp**: 2026-10-27
- **Issue**: #17153 (R4-Q20-03)
- **Base**: `origin/master 2dce74b744`

## Defect (STEP-0, verified at base)

Live on `2dce74b744`:

- `pkg/config/compiler.go:552` passed `opts.sanitizeFreeTextControlChars`
  (#1798 scrub flag) as the lenient argument to
  `validateTunnelEndpointIDCollisionAST` — a mode query borrowing a scrub
  gate's flag.
- The four-flag OR deciding Junos host direct-delivery warning deferral
  (`lenientTunnelRITarget12520 || lenientWireguardRoutingInstance ||
  lenientRIDualClaim11060 || lenientRIMgmtMember11392`) was written twice:
  `compiler_tailgates.go:28-30` and `compiler.go:1216-1217`, unguarded.
- `suppressContestedTrunkZoneAdvisory` also silenced the RX-MTU advisory
  (`userspace_rx_mtu_advisory_9727.go:58`) and the mgmt-zone advisory
  (`userspace_mgmt_zone_advisory_10308.go:25`), beyond its named gate.
- `lenientFirewallRefs` was read for 15 distinct validators (13 in
  `compiler_uniformgates_firewall_nat2.go`, 1 in `compiler_tailgates.go`,
  1 pre-walk in `compiler_prewalk.go`) including NAT and proxy-ARP gates,
  while its doc at `compiler_opts.go:1548-1562` named only two.
- `compiler_peer_effective.go:106` recorded "both call sites pass
  opts.sanitizeFreeTextControlChars" though there has been one call site
  since #16167.

No behaviour differed: every production compile is all-strict or
all-tolerant. The cost is misleading names/docs and drift risk.

## Fix

- `pkg/config/compiler_opts.go`: new explicit mode bit `tolerant bool`,
  set `true` only by `lenientCompileOpts()`; its doc names every governed
  site. `lenientFirewallRefs` doc now lists all 15 governed validators;
  `suppressContestedTrunkZoneAdvisory` doc names its two real advisories
  and disclaims RX-MTU/mgmt-zone. The #16166 completeness test allowlists
  `tolerant` (not a per-gate downgrade) and pins it true.
- `pkg/config/compiler.go`: tunnel gate passes `opts.tolerant`; final
  Junos pass uses `deferJunosHostWarnings(opts)`.
- `pkg/config/compiler_tailgates.go`: single `deferJunosHostWarnings(opts)`
  definition (`return opts.tolerant`); `runTailGates` uses it.
- `pkg/config/userspace_rx_mtu_advisory_9727.go`,
  `pkg/config/userspace_mgmt_zone_advisory_10308.go`: suppression reads
  `opts.tolerant`. The contested/shared-device advisories keep their
  dedicated suppressor (already set with the others in
  `lenientCompileOpts()`, so behaviour is unchanged).
- `pkg/config/compiler_peer_effective.go`: corrected #6861 C1 text to the
  single call site passing `opts.tolerant`.
- New `pkg/config/compiler_opts_tolerant_mode_17153_test.go` (`go/ast`):
  `sanitizeFreeTextControlChars` is read only at the pre-walk scrub site;
  the tunnel gate passes `opts.tolerant`; `deferJunosHostWarnings` has
  exactly one definition, >=2 call sites, and the multi-flag OR cannot
  reappear in compiler.go/compiler_tailgates.go; every validator a flag
  governs (AST census, >=14 required for lenientFirewallRefs) is named
  in that flag's doc; `tolerant` is set only in compiler_opts.go and true
  in lenientCompileOpts().

Excluded: removing the tunnel gate entirely belongs to R4-Q20-05's fix,
not this issue; per-gate `lenient*` flags are unchanged (splitting
`lenientFirewallRefs` per-gate is a NAT-leniency registry decision —
the doc + AST guard now make the full set discoverable).
