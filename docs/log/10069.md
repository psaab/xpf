# #10069 delegated slow-path outlet: bounded MTU retry and status reporting

Issue: psaab/xpf#10069. Lane branch: `fix/10069-slowpath`.

## Context

The #9637 dual-outlet split gives trusted (`xpf-usp0`) and delegated
(`xpf-usp1`) reinjection independent workers and MTU/degraded state. Before
this fix, day-2 reconciliation stopped as soon as the trusted outlet's live
MTU converged. A delegated `SIOCSIFMTU` failure was therefore left behind on an
unchanged desired MTU; `last_acted` prevented the only existing trigger from
trying again.

The status path also projected only `SlowPathReinjector::status()` (trusted).
`delegated_status()` existed for internal tests but did not reach the
coordinator status consumer, the Rust/Go status wire, CLI summary, or metrics.

## Fix

- `reconcile_preserved_slow_path_mtu` now checks both outlet live MTUs. When
  trusted is converged and delegated is lagging, it calls a delegated-only
  reconcile so trusted does not receive duplicate ioctls.
- Delegated recovery uses a preserved logical retry state: at most 3 ioctl
  attempts in any rolling 8-reconcile-tick window, with 1/2/4-tick
  exponential backoff. A new degraded edge re-arms the attempt counter, and
  old attempt ticks age out of the rolling window. Persistent delegated
  failure is therefore retried for eventual recovery but cannot become a
  per-tick ioctl storm. The trusted/dual-outlet path retains the `last_acted`
  dedup required by #6097.
- `Coordinator::slow_path_delegated_status()` and the retained teardown
  snapshot publish delegated status through `ProcessStatus` as
  `slow_path_delegated`. The Go mirror decodes it, the operator summary prints
  it beside the trusted outlet, and Prometheus emits trusted/delegated health,
  MTU, queue, injection, drop, limiter, queue-full, write-error, and
  MTU-drop families labelled by `outlet`.
