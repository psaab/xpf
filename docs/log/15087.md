# Issue #15087 (A62-01): L3 reverse index bucket was O(N) per op under same-destination SNAT fan-in

## Mechanism

`l3_reverse_index` (`userspace-dp/src/session/`) maps the protocol-erased
`(family, server, SNAT address)` identity of a forward NAT session to its
slab handle, so a flowless non-first reply fragment (no L4 ports) can be
gated on live NAT state (#10130/#10674). Interface/pool SNAT collapses
every session to one popular destination (resolver, CDN edge, bench
target) onto ONE such key, and the bucket was a linear
`SmallVec<[u32; 2]>`:

- insert paid `bucket.contains(&handle)` — O(bucket);
- removal paid `bucket.retain(|h| *h != handle)` — O(bucket);
- every fragment probe (`reverse_nat_fragment_requires_translation`)
  walked the whole bucket re-deriving each member's reverse key.

With N live same-destination sessions, each session delete and each reply
fragment cost O(N) on the worker session-table path — a bounded
availability/performance loss under an ordinary SNAT workload (report
A62-01, severity Medium, consensus MATERIAL).

## Fix

Same outer key and same probe contract; the bucket interior changes:

- `L3ReverseBucket` (`session/mod.rs`): hashed handle set
  (`HashSet<u32, HotPathSeededState>`, the table's keyed seed) plus
  `protocol_counts[256]` counting members by their REAL reverse protocol.
  Insert/remove are O(1) amortized; the outer key drops when the set
  empties. A new `l3_bucket_hasher` table field carries the seed for new
  buckets (`HashMap::entry` cannot lend its hasher).
- Probe (`session/lookup.rs`): counts first (exact protocol, or total for
  the 255 sentinel); a bounded walk (`L3_PROBE_SCAN_BUDGET = 8`) re-derives
  visited members from live slab records with the pre-fix per-member rules
  (reverse-entry skip, reverse-key equality, exact-protocol match, strict
  idle expiry, same-domain TRUE / cross-domain fail-closed). Visiting
  every member is exact; otherwise counts claiming unvisited matching
  members answer TRUE — every live-matching outcome is TRUE, so presence
  decides. Counts saying none answer FALSE without walking. All-expired
  buckets larger than the budget answer fail-closed TRUE until GC drains
  them (bounded over-drop, never fail-open).
- Insert/remove sites pass the member's real reverse protocol
  (re-derived from the same forward key + NAT decision), keeping counts
  the exact multiset of member protocols.

NOT changed: the L3 key shape (ports/protocol still erased — a non-first
fragment has no L4 header), the 255-sentinel wildcard semantics, the
domain admission rule, the other NAT indexes (`nat_reverse_index` etc.
keep their small SmallVec buckets — their keys carry ports, so fan-in is
bounded by tuple collisions, not destination popularity), and expiry
ownership (GC still physically removes members; lookups never mutate).

## Risk

- Behaviour delta confined to the fragment gate's internal cost and one
  bounded over-drop corner (all-expired bucket larger than the probe
  budget returns TRUE until GC). No wire, config, or API change.
- Per-bucket memory grows by the counts array (256 × u32) plus hash-set
  overhead per distinct (family, server, SNAT) identity — bounded by the
  number of distinct NAT destinations, not session count.
