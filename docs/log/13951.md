# Issue #13951: guard kernel-neighbor mirror MAC changes

The Go neighbor listener mirrors kernel neighbor rows through `update_neighbors`. A usable unsolicited ARP/NA can change the kernel's row even when the helper's Rust monitor refuses to replace its live binding. The mirror previously bypassed that refusal and wrote the new address into both the dynamic and static neighbor maps; static entries win lookup.

The helper now treats a Go snapshot as a mirror, not independent evidence. It accepts a differing MAC only when the kernel row is NUD_PERMANENT or the monitor already has the same MAC in the dynamic cache (the monitor's probe-confirmed CAS has admitted it). Otherwise a replace retains the prior static value or leaves a dynamic-only binding untouched. Same-MAC refreshes remain accepted. The resolver's confirmed-GET write now also requires the monitor's probe token before replacing an existing MAC. Regressions cover mirror refusal/convergence and resolver refusal/probe-confirmed convergence.

Validation: `cargo check --bin xpf-userspace-dp` passed. `cargo test manager_neighbor_mirror_cannot_replace_live_mac_without_confirmation_13951` passed (1 test), and `cargo test sharded_neighbor` passed (59 tests). Test compilation on pristine master is blocked by the unrelated type error in `src/afxdp/coordinator/tests.rs:11773` (`maps.local.insert(inner_dst)` supplies `IpAddr` where `(u32, IpAddr)` is required); the fixture was temporarily corrected to `(lo as u32, inner_dst)` only for local validation, then restored and excluded from this change. A broader forwarding-module run exposed an existing test that expected an unconfirmed manager snapshot to replace a differing MAC; the test now explicitly supplies NUD_PERMANENT evidence.
