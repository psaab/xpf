# Issue #13951: guard kernel-neighbor mirror MAC changes

The Go neighbor listener mirrors kernel neighbor rows through `update_neighbors`. A usable unsolicited ARP/NA can change the kernel's row even when the helper's Rust monitor refuses to replace its live binding. The mirror previously bypassed that refusal and wrote the new address into both the dynamic and static neighbor maps; static entries win lookup.

The helper now treats a Go snapshot as a mirror, not independent evidence. A differing MAC is accepted only for NUD_PERMANENT rows or when the monitor's dynamic cache already has that MAC (the monitor's probe-confirmed CAS has admitted it). Otherwise, an existing dynamic binding is carried through an all-shard compare-and-write; if only a static binding exists, it is retained. The effective value is published to the static forwarding map, preventing stale snapshots from erasing monitor state. Same-MAC refreshes remain accepted. The resolver's confirmed-GET write also requires the monitor's probe token before replacing an existing MAC. Regressions cover stale-snapshot preservation, mirror refusal/convergence, and resolver refusal/probe-confirmed convergence.

Validation: `cargo check --bin xpf-userspace-dp` passed. `cargo test manager_neighbor` passed (8 tests), and `cargo test sharded_neighbor` passed (60 tests). Test compilation on pristine master is blocked by the unrelated type error in `src/afxdp/coordinator/tests.rs:11773` (`maps.local.insert(inner_dst)` supplies `IpAddr` where `(u32, IpAddr)` is required); the fixture was temporarily corrected to `(lo as u32, inner_dst)` only for local validation, then restored and excluded from this change. A broader forwarding-module run exposed an existing test that expected an unconfirmed manager snapshot to replace a differing MAC; that test now supplies NUD_PERMANENT evidence.
