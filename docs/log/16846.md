# #16846 (R3-F15-03): findBinary trusted a planted symlink to a root-owned helper

- **Timestamp**: 2026-10-25
  - **Action**: `findBinary` now returns the `filepath.EvalSymlinks`-resolved path of the exact helper it validated (never the unresolved spelling) and, for a root daemon, refuses any replaceable symlink or containing-directory component on either spelling of the path: every component must be root-owned with no non-root-group or non-sticky world write (a root-owned sticky world-writable directory such as /tmp does not make a chain replaceable; a root-owned symlink link is judged on ownership because replacement needs write access to its already-trusted parent). A planted `./xpf-userspace-dp -> /bin/true` in a user-writable CWD is therefore refused for the plant itself instead of admitted on its target's ownership, and a regular helper in a user-owned directory is refused for its directory. Non-root daemons only gain symlink resolution (dev workflow unchanged). The #16054 file check (root-owned, not group/world-writable) and the #12196 executable/access checks now run on the resolved file; explicit paths keep their informative not-found / directory / not-executable / not-trusted errors.
  - **File(s)**: `pkg/dataplane/userspace/process.go` (findBinary, validatedHelperPath, chain checks, checkExecutableAccess; executableBinaryCandidate removed), `pkg/dataplane/userspace/findbinary_16846_test.go` (new), `pkg/dataplane/userspace/findbinary_12196_test.go` (noexec namespace child presents host ancestors as root-owned via the helperDirTrustUID seam), `debian/changelog`, `docs/log/16846.md`
  - **Validation**: New `TestFindBinary*16846` cells (4 non-skip) PASS post-fix on uid 1000 and FAIL pre-fix with the production file reverted (each defect cell returned the unresolved plant path; the non-root resolution cell returned the link). Real-root run: the packaged control `TestFindBinaryExplicitTrustedAcceptedAsRoot16846` (/bin/true through its root-owned chain) PASSes as uid 0; three pre-existing #16054 non-root-control cells fail as uid 0 exactly as on origin/master (they assert the non-root arm and cannot run as root — base-attributed, unrelated). Adjacent suite: `go test ./pkg/dataplane/userspace/ -run 'TestFindBinary|TestSocketTrust|TestVerifyTrusted|TestEnsureTrusted|TestRuntimeDir|TestDialTrusted|TestPeerCred|TestRemoveStale|TestHelperEvent|TestResponseCap|TestBounded'` PASS.
  - **Risk**: Fail-closed only. A root daemon whose helper lives under a user-owned or non-root-group-writable directory (e.g. a hand-run build tree under a home directory) now refuses to spawn the helper with a not-trusted diagnostic naming the component; move the helper to a root-owned path or pin `system dataplane binary` to one. The packaged unit (resolved versions/ chain, root-owned) is admitted, verified as uid 0. Residual: validation and `cmd.Start()` are still two syscalls apart — the chain invariant (no less-privileged user can remove any entry above the resolved file) is what makes that gap unexploitable; an fd-based execveat would close it absolutely and remains a possible future hardening.
