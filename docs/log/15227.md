# #15227 (A43-04, A43-05): operator-surface interface-name normalization cohort

- **Timestamp**: 2026-10-19
  - **Action**: Resolved `request dhcp renew` targets through the active config to the DHCP lease key on all three surfaces (gRPC SystemAction, local CLI, remote CLI via the same RPC) and stopped both packet-drop renderers (gRPC MonitorPacketDrop, local CLI twin) from classifying SCREEN action=permit alarms as drops. Added RED/GREEN regressions plus controls; no behaviour change outside the cited mechanisms.
  - **File(s)**: `pkg/config/dhcp_renew_resolve.go` (new: `ResolveDHCPRenewTarget`, `DHCPRenewCompletionNames`), `pkg/grpcapi/server_diag_system_action.go` (dhcp-renew resolution), `pkg/cli/cli_request.go` (local twin), `pkg/cmdtree/tree.go` (renew completion), `pkg/grpcapi/server_diag_monitor.go` + `pkg/cli/monitor.go` (permit-screen skip), tests `pkg/config/dhcp_renew_resolve_15227_test.go`, `pkg/grpcapi/dhcp_renew_packetdrop_15227_test.go`, `pkg/cli/monitor_dhcp_15227_test.go`, `pkg/cmdtree/dhcp_renew_completion_15227_test.go`, `docs/log/15227.md` (this file)

## Mechanism (origin/master `40977bcd09`)

- **A43-04**: `pkg/grpcapi/server_diag_system_action.go` passed `req.Target` raw to `dhcp.Manager.Renew`, as did `pkg/cli/cli_request.go`; `cmd/cli/request.go` forwards the raw spelling into the same RPC. `Manager.Renew` does an exact `clientKey{iface: ifaceName}` lookup, but clients are keyed by `config.DHCPLeaseIfName` (`LinuxIfName` + `.<vlan-id>`) from `buildDHCPClientSpecs`. So `ge-0/0/0` and `ge-0/0/3.7` (unit 7, vlan-id 50, keyed `ge-0-0-3.50`) missed with a false "no DHCP client running" diagnosis; only typing the hidden Linux form worked. Renew completion likewise offered every bare interface name.
- **A43-05**: `MonitorPacketDrop` admitted any `SCREEN_DROP` record and rendered `Dropped by SCREEN:<check>` without consulting `rec.Action`; the local CLI loop did the same. A screen alarm with action=permit (#2234/#2298: the packet forwards) was therefore reported as a drop by the incident-response command, and consumed the operator's `count` budget.

## Change

- `Config.ResolveDHCPRenewTarget` (in `pkg/config`, beside `DHCPLeaseIfName` so the derivations cannot drift) accepts the Junos key (`ge-0/0/0`), ifd.unit (`ge-0/0/3.7` — resolved via the unit's vlan-id, never its unit number), the Linux forms (`ge-0-0-0`, `ge-0-0-3.7`), and the already-resolved lease key (`ge-0-0-3.50`, preserving the historical workaround). A bare interface resolves to its sole DHCP unit; several DHCP units refuse with the unit list rather than silently widening scope. Unknown interfaces/units and non-DHCP units stay refused. Nil config passes the raw target through so no-daemon builds keep the manager's own diagnosis.
- Both renew handlers resolve before `Renew` and report the resolved key; the gRPC handler keeps `codes.NotFound` for resolution and renew failures alike. `cmd/cli` needed no change: it forwards to the fixed RPC.
- `request dhcp renew` completion now offers `DHCPRenewCompletionNames` — the resolvable config-key unit spellings of DHCP-carrying units only.
- Both packet-drop loops skip `SCREEN_DROP` records with action permit (case-insensitive, matching the record's rendered action spelling) before filters/counting; deny/reject screen lines and policy-deny lines are byte-identical.

NOT changed: `dhcp.Manager.Renew` keying and restart semantics, lease-key derivation (`DHCPLeaseIfName`), event production/severity classification (#2298 syslog path already action-aware), `formatPacketDropEvent` rendering, and every non-DHCP renew / non-screen monitor path. No new knob.

## Risk

- Renew resolution reads the ACTIVE config at request time; a target valid in config but with no running client still refuses (now with the resolved key in the message), and a config-less build is byte-identical to before. The multi-unit bare-interface refusal is an intended truthful-diagnosis delta: operators renew the specific unit (completion offers exactly those spellings).
- Packet-drop streams now emit fewer lines for permit alarms (intended): an operator counting drops no longer spends the count budget on forwarded traffic. Screen deny/reject and policy-deny output is unchanged.
