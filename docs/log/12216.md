# #12216 — quarantine NAT and junos-host expanders

- **Base**: `a714c90d472a3c3d98a3799831cfef3ec311a61c` (`fix/12216-expander-quarantine`)
- **Why**: NAT address-name expansion could resolve the winning address of a colliding address/address-set name, silently drop dangling members, or keep a static alias while a declared feed was unready. The junos-host projection independently selected address/application winners on name collisions.

## Change

- NAT's shared `expandBookNameRecursive` now rejects colliding names, dangling/empty closures, unusable address values, and declared-but-unready feed bindings at every nested level. It preserves ready feed prefixes, cycle handling, and present-empty `fail-mode drop` semantics. NAT's existing raw-name fallback keeps failed source/destination constraints unmatchable; DNAT with an invalid destination emits no translation row.
- Junos-host address resolution checks collision metadata throughout nested address-set closures before address-first resolution. Application resolution similarly checks direct, nested-set, and member collisions. An ambiguous or dangling host deny becomes unrepresentable, so its policy key is not claimed as rendered.
- Added NAT-only and host-only collision/dangling regression cells with policy-path controls. Updated the old #6143 partial-resolution assertions to the required whole-set poison behavior (#12216).
