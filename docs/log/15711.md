# Issue #15711: system AAA refusal covers compact and packed spellings

## Problem

`systemAAAWarningsOrError10831` in `pkg/config/compiler_system.go` judged
only `systemNode.Keys[1]` and the direct children's heads (`child.Name()`).
Brace-elided, packed-run, and nested-run spellings of the unimplemented
Junos AAA leaves (`radius-server`, `tacplus-server`,
`authentication-order`, `accounting`) therefore committed silently in
strict mode and produced no warning in lenient mode:

- `system host-name fw1 authentication-order [ tacplus password ];`
  packs the AAA leaf behind `host-name` on the `system` node's own Keys.
- `system { no-redirects tacplus-server 192.0.2.20; }` packs it behind
  `no-redirects` on a single child's Keys.
- `set system host-name fw1 authentication-order tacplus` and
  `set system no-redirects tacplus-server 192.0.2.20` nest the AAA leaf
  under the preceding leaf's node (flat-set chain).

## Fix

Added `systemAAARefusals15711`, a schema-driven scan used by
`systemAAAWarningsOrError10831`:

- A token is judged only at a statement position, reached by consuming
  each preceding modelled `system` leaf with its declared arity; multi
  leaves absorb until the next modelled sibling.
- The packed scan runs on the `system` node's Keys (from index 1) and on
  each direct child's Keys; the nested scan descends only through a
  modelled leaf that declares no children (a flat-set chain link) and
  never into a modelled container's body.
- Hence a VALUE spelling an AAA keyword (`host-name radius-server`, a
  `domain-search` entry) and deeper identities (`login class
  radius-server`, `login user radius-server`) are never misread as a
  direct `system` AAA statement. Quoted tokens are values. A token the
  `system` schema does not model stops the packed scan (do-not-guess).
- Strict mode still returns the first refusal; lenient mode now warns
  once per distinct leaf found (previously one warning per direct child,
  duplicates possible).

## Validation

`go test ./pkg/config/ -run '15711|10831|15019' -count=1` passes;
targeted `AAA|10831|15019|System|Login` suite passes; `go vet
./pkg/config/` clean; gofmt clean. RED proof: with the fix reverted the
four packed/nested acceptance cases fail with `CompileConfig succeeded
or missed ... refusal: err=<nil>` while the two brace-elided cases pass.
Full `pkg/config` suite exceeded the 300s tool window (parallel sibling
lanes contending); targeted suites above are the exercised evidence.
