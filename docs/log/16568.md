# #16568: zone views qualify undefined/inert screen profiles

- **Timestamp**: 2026-10-24
- **Problem**: `show security zones [detail]` (local CLI, gRPC text,
  GetZones, remote CLI, REST) printed `Screen: <profile>` verbatim for a
  zone whose profile is undefined (lenient path) or defined but
  enforcing nothing (strict-clean; only `alarm-without-drop`), while the
  dataplane substituted `conservative_default()` (nine threshold-free
  malformed-packet checks). The inert detail even listed
  "Enabled checks: alarm-without-drop". The #5806/#7059 diagnostic blocks
  reached only the screen views and Prometheus, so an operator auditing
  a zone believed the named profile's flood/scan/session-limit
  protection was active.
- **Fix**: One per-zone SSOT in pkg/dataplane/userspace:
  `ScreenZoneDispositionFor(cfg, zone)` built on the existing
  `ScreenMissingProfileRefs` / `ScreenInertProfileRefs` predicates (the
  same ones the screen views and metrics use), returning
  Enforcing/Undefined/Inert/Unknown with `Qualifier()` spellings
  `[UNDEFINED — conservative default applies]` /
  `[ENFORCES NOTHING — conservative default applies]`. Unknown covers
  no screen, a nil profile value, and zones the SSOTs skip
  (quarantined/DroppedEnforcementChild) — renderers must not guess.
  Renderers: local CLI `showZonesDisplay` (brief + detail; inert detail
  now prints `Enabled checks: (none) — <ScreenInertDisposition>` instead
  of the modifier), gRPC text `showZonesDetail` + `showTestZone`, local
  `test security-zone`, remote CLI `showZones` (from the structured
  field; UNKNOWN/old server stays bare). Wire: proto
  `ZoneInfo.screen_disposition` (field 21, new
  `ZoneScreenDisposition` enum appended at EOF, regenerated with pinned
  protoc 3.21.12 / protoc-gen-go v1.36.11 / protoc-gen-go-grpc v1.6.1)
  populated in GetZones; REST `ZoneInfo.screen_disposition`
  (`enforcing|undefined|inert`, omitted on Unknown) mirrors it.
  NOT changed: dataplane substitution behaviour, strict-commit gates,
  screen views/metrics (already truthful), `Screen: <profile>` for
  enforcing zones (byte-identical).
