# #16059 - WG/input-output filter fast map i32 last-wins per shared ifindex

- **Timestamp**: 2026-10-21
- **Root fix (Rust, snapshot boundary)**: `assign_interface_filters` (`userspace-dp/src/filter/compiler.rs`) previously inserted each unit's filter into the `i32`-keyed `iface_filter_*_fast` maps with plain last-wins `insert`. Units of an interface-level WireGuard (or GRE) tunnel share one kernel ifindex (`wg0.0`/`wg0.1` → one `wg0` netdev via `TunnelNameMap`), so two units naming different filters for the same family+direction silently kept only the last row's filter — the loser's filter never evaluated a packet (fail-open for a deny filter, order-dependent). The compiler now rejects the snapshot with the new `SnapshotIntegrityError::InterfaceFilterSharedIfindexConflict` when two non-base rows (`is_unit != Some(false)`; known base rows carry no Go filter fields) disagree on a configured hook. Identical names and single-claimant (one unit filtered, sibling empty) shapes remain valid and deterministic. Per-unit keying was rejected: every hot-path filter lookup keys by bare ifindex and WG/output carries no per-packet unit identity, so per-unit maps would be dead state. The #6236 final-map aggregate rule is unchanged for the remaining known-base last-wins case (its pin now uses `is_unit: Some(false)` rows). EXCLUSION (Opus2 fold): GRE INPUT on `gr-*` tunnel rows is exempt — #10816 decided GRE decap attributes a shared identity to the first-sorting row by design (commit advisory `gre_unit_filter_shadow_10816.go`), so rejecting GRE input would brick admitted configs; WG input/output, GRE output, and non-tunnel shared ifindexes refuse. Zone policy is untouched (independent).
- **Regression**: Rust `shared_ifindex_wg_filters_conflict_rejects_16059` proves the actual winner pre-fix shape now rejects (output v4 headline arm + input v4/v6, output v6, reversed row order), identical/single-claimant shapes compile with the fast map holding the claimed filter, and distinct ifindices are unaffected; `duplicate_ifindex_output_filter_aggregate_is_last_wins` re-pinned on known-base rows. Go `TestWgUnitFilterShadowAdvisory16059` fires once for differing WG output and input filters and stays silent for uniform, single-claimant, per-unit-stanza, and GRE shapes. Fail-on-revert: dropping the Rust gate makes the differing-filter cells compile Ok (RED); unhooking the Go advisory makes the firing cells RED.
- **Validation**: `cargo test --bin xpf-userspace-dp -- shared_ifindex_wg_filters duplicate_ifindex_output_filter capability_accessors_equal` green; `go test ./pkg/config/ -run TestWgUnitFilterShadowAdvisory16059` green. (Pre-existing on master: `TestGreUnitFilterShadowAdvisory10816` case (e) fails at the unrelated #15034 untagged-unit gate; untouched by this change.)
- **Perf impact**: None on the dataplane hot path. The gate is snapshot-build-time only (one extra pass over interface rows with a small hash map, cold path); per-packet filter lookups, fast-map shapes, and aggregates are byte-identical for accepted snapshots.
- **Risk**: Configs that (unknowingly) relied on last-wins differing per-unit filters on a shared WG ifindex will now have their snapshot refused at reconcile (prior good state kept) with a commit-time warning explaining the fix — intended fail-closed behavior; identical-filter and single-unit configs are unaffected.
