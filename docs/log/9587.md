## Framing

The AF_XDP shim steered WireGuard for ONE listen port
(`UserspaceCtrl.wg_listen_port` scalar). A second tunnel on a distinct port
was never decapsulated by the worker. This change steers a bounded SET
(`WG_STEERED_PORT_SET_MAX = 8`, fixed ctrl array, const-trip scan) end to
end: Go derivation → v17 snapshot wire → ctrl map → shim classify → helper
forwarding set → control-thread spawn decisions.

Decisions that survived hostile review: Path B primary (ctrl fixed array;
the BPF map buys nothing at MAX=8 and spends helper-call budget the #1432
note forbids); selection first-MAX-in-emitter-order, encoding sorted;
scan order UDP → set → locality (locality costs up to two map lookups);
v17 replace-the-key (no-bump loses kernel-path delivery on every port —
worker decap is endpoint-keyed and destination-independent, so "total
outage" is scoped wording; the claim gate only decides kernel-vs-worker
steering, and interface-NAT/SNAT addressed records still reach the worker
through the interface-NAT fallthrough); pinned-map crossing via stopped-node
install + targeted unlink or measured rolling per-node order, never the #4113
disposable-counter path.
