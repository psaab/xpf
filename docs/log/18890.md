# #18890 — align the rename-ancestry /fatal row with the #16828 commit contract

- **Timestamp**: 2026-11-02 (`wt-18890`, base `5e65228f29`)

## Why

`TestRenameAncestryOwnershipTransfersAtBindTime10511` was born under #10509
(`b41e58a98a`) and its `/fatal` row still pinned the pre-#16828 contract: a
fatal apply "must fail without a commit result" (nil config). #16828
(`5d2c52e53d`) deliberately changed that contract: when the apply aborts
fatally after the store has already promoted+persisted the config,
`applyAndSyncCommittedWithPeerSnapshotAuthorization` returns the promoted
config with the error wrapped in `configstore.ErrCommittedNotApplied`
(`daemon_apply_commit.go:503`); returning `(nil, err)` made the
#5742/#15281 classifiers report a persisted config as a plain reject
(REST 400 / gRPC InvalidArgument). #16828 updated its own cells but never
touched this oracle, so the row went stale and failed on master.

## What

- Replace the `wantNil` outcome field with `wantCNA`
  (committed-not-applied) in the fatal/non-fatal/success table.
- All three rows now assert a non-nil commit result — the retired check
  asserted nothing for the non-fatal and success rows.
- The fatal row asserts `errors.Is(err, configstore.ErrCommittedNotApplied)`
  and that the additive wrap keeps the underlying gate sentinel
  (`dpuserspace.ErrPolicySchedulerProtocolIncompatible`) matchable; the
  non-fatal and success rows assert the sentinel is ABSENT (a best-effort
  tail error is committed-and-live and must classify as a tail error, not
  committed-not-applied).
- No production behavior changed.

## Validation

- RED pre-fix: `/fatal` failed at `daemon_policy_rename_test.go:1438`
  ("fatal apply must fail without a commit result").
- GREEN post-fix: the named test (fatal/non-fatal/success subtests) and the
  neighbouring `TestRenameAncestryPrunedOnNextBind` pass via
  `./scripts/testguard-run.sh go test ./pkg/daemon -run '...' -count=1`.
- Mutant (the oracle stays able to fail): reverting
  `daemon_apply_commit.go:503` to the pre-#16828 `return nil, applyErr`
  reds the new oracle at `daemon_policy_rename_test.go:1451`
  ("fatal apply returned no commit result"); the production file was
  restored byte-identical afterwards.

## Risk

Test-only. The oracle now pins the #16828 contract in both directions: a
regression to the reject-shaped `(nil, err)` return, or a wrap that loses
the underlying gate sentinel, reds the cell.
