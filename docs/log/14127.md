# 14127 — fragment overlap tracker: post-NAT sender quota, domain-change post key

The post-translation overlap key was built from the translated tuple
alone, so its sender-fairness identity (`overlap_sender`) was the
shared SNAT/NAT64 pool address. Two permitted tenants translated
through one pool IP therefore shared one 8-incomplete-entries-per-shard
budget on the post-NAT check: tenant A's incomplete fragments could
fail-close tenant B's unrelated fragmented datagrams on a common
post-NAT shard, even though B's pre-NAT key fit its own quota. A
fragment routed to a different egress routing domain with no address
rewrite got no post key at all (`NotApplicable`), so the downstream
domain's anchor set was never checked. The pre/post commit order was
re-verified at both TX sites (poll_descriptor and neighbor_dispatch):
the pre admission is taken into `OverlapAdmissionTokens` before the
post check, and a post drop drops the bundle, whose RAII
`fail_admission` pins the pre ranges as protection without counting
the datagram as admitted — that arm needed no change.

Fix: `OverlapKey` gains `fairness_origin`, stamped by
`translated_overlap_key` with the pre-translation sender on every
returned post key. Reassembly membership now compares the translated
tuple ignoring the origin (new `overlap_same_datagram`), because the
downstream receiver merges fragments by the translated tuple alone —
two tenants' fragments for one downstream datagram (e.g. NAT64's
16-bit ident truncation) must still find the same entry and drop on
overlap. The sender quota charges the origin instead of the pool
address. Cross-origin incomplete entries count against a candidate
again once that origin's pending fragments have failed admission
(poisoned), so a failed datagram cannot be jointly completed by
another tenant past its anchored ranges; the downstream domain
reserve (32/shard) counts all post entries regardless of origin.
`translated_overlap_key` also returns a post key when only the
routing domain changes (egress domain, same addresses), so the
downstream domain is anchored; same-domain no-NAT remains
`NotApplicable`. Arrival-path quota behaviour (#10658), completed-anchor
exclusion (#13937), and domain-reserve reclamation (#14009) are
unchanged. Fail-closed directions are preserved: every new-key
refusal still drops via `FRAG_OVERLAP_SHARD_FULL_DROPPED`.

Regression (all in `fragment_overlap::tests`, RED-verified by
reverting the sender/membership/quota/domain logic while keeping the
tests): `post_nat_sender_quota_is_per_tenant_14127` forces two
tenants through one pool address into one shard, admits eight
incomplete heads from A, then asserts B's distinct datagram is
admitted, A's ninth is refused, and tails still admit after A
completes. `domain_change_without_rewrite_gets_post_key_14127`
asserts the egress-domain post key exists, anchors overlaps there,
and does not leak into the arrival domain.
`failed_post_nat_admission_keeps_cross_tenant_protection_14127`
fails one of A's admissions after B filled its quota and asserts A's
next distinct datagram is refused instead of minting a fresh
origin-only budget past B's entries, with A's failed ranges still
anchored. RED on the reverted logic: all three fail (B denied by A's
quota; no post key on domain change; A's post-failure head admitted
past B's fill / A's failed head dropped as a same-datagram overlap).

Validation: `cargo test fragment_overlap::` — 38 passed (35 existing
including #9950/#10658/#10861/#13937/#14009 cells, plus the 3 new
#14127 cells). Existing `translated_key_same_family_collision_9950`
and NAT64 collision tests were updated to assert the shared
translated tuple rather than whole-key equality (origins now differ
by design). `cargo clippy --all-targets` shows one pre-existing
`mut_from_ref` error in `afxdp/umem/mmap.rs`, identical on unmodified
master (base-attributed, not introduced here). Lab loss-cluster smoke
not run (userspace unit scope; no wire-format change).

Closes #14127
