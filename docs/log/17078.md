## STEP-0 (live verification on origin/master a60e77bda3)

The finding is LIVE, not dead. `grep -rn RTM_GETRULE pkg --include=*.go | grep -v _test`
returned exactly the two cited sites: `pkg/daemon/daemon_mgmt_dns_rules.go:106`
(the full validating decoder, `decodeMgmtDNSRuleMessages`, reading
`fib_rule_hdr.Type` plus ~18 FRA_* attributes) and
`pkg/routing/rule_dscp_linux.go:183` (`RuleListDSCPSelectors`, whose
`dscpSelectorFromRuleRow` sliced `attr.Value[0:4]` with no length check).
`pkg/routing/pbr_applied_7422.go` normalised the action away
(`expected.Type = observed.Type`) under a header documenting that the
mismatch check "explicitly cannot verify the DSCP selector (or action)".
The assignment's alternative dispositions (delete a dead decoder vs wire
the action read) therefore resolve to: the decoder is used (by the
management-DNS reconciler, which keys lookup/shadow pairs on the action),
so wire it — move it to the owning package and read the action in PBR.

## What

- New `pkg/routing/rule_dump_linux.go`: `RuleListFull(family) ([]RuleRow, error)`
  is now the single RTM_GETRULE dump site. `RuleRow` embeds `netlink.Rule`
  (with `Type` decoded from `fib_rule_hdr`, which netlink v1.3.1's
  `RuleListFiltered` leaves zero) plus the sidecar netlink.Rule cannot
  represent: `DSCP`/`DSCPSet` (FRA_DSCP). (An earlier `L3MDevSet`
  sidecar was dropped in the fold commit: it had no consumer.) The
  decoder mirrors the library's decode (same defaults, same
  `&net.IPNet{IP, Mask}` construction) and adds length validation on every
  attribute, including the width-tolerant (1..4 byte) FRA_IP_PROTO rule
  from #14971. It is a verbatim-validating superset of the daemon decoder
  it replaces.
- `RuleListDSCPSelectors` is now a projection of `RuleListFull`;
  `dscpSelectorFromRuleRow` projects a decoded `RuleRow` instead of
  parsing raw bytes unchecked. The "RuleList runs first and would already
  have faulted" coupling is gone.
- `pkg/daemon`'s `netlinkMgmtDNSRuleOps.RuleList` calls
  `routing.RuleListFull` and projects `row.Rule`. `decodeMgmtDNSRuleMessages`
  and its `mgmtDNSRule*` helpers are deleted. `grep -rn 'FRA_' pkg/daemon
  --include=*.go | grep -v _test` now matches only comments; including
  tests, the remaining `FRA_*` uses are in
  `dhcp_vrf_backstop_12127_test.go:295-296` (`unix.FRA_PRIORITY`/
  `unix.FRA_L3MDEV`, raw rule install, not a decoder) — i.e. no `FRA_`
  in pkg/daemon production code.
- PBR readback: `pbrExpectedLookupRule` sets `Type = RTN_UNICAST` (the
  install action in `buildPBRRules`), `pbrNetlinkRuleMatches` drops the
  `expected.Type = observed.Type` normalisation, and
  `PBRAppliedStatusLive` reads through `RuleListFull`
  (`netlinkFullRuleOps`). When the ops also return full rows
  (`fullRuleOps`), a declared `PBRRule.DSCPSet` desire is compared
  against the readback sidecar (wrong or missing FRA_DSCP = mismatch);
  an undeclared desire is never charged for a selector, and plain
  `ruleOps` fakes keep the previous projection-only behaviour.
  The stale "RuleList does not decode the action" comments in
  `rules.go`/`next_table_carveout_17971.go` (dual-action delete retries)
  are deliberately untouched — those paths still consume `ops.RuleList`
  (library decode); migrating their delete-retry logic onto the decoded
  action is behaviour beyond this issue's PBR-readback scope.
- Metric help for `xpf_pbr_rules_mismatched` updated: the action is now
  checked; DSCP is checked only for desired rules that declare one.

## Risk

- Behaviour change (intended): `xpf_pbr_rules_mismatched` can now rise
  where a PBR lookup slot's kernel action is not unicast or a declared
  DSCP selector differs — previously invisible. No install/delete path
  changes behaviour; all rule writers are untouched.
- The daemon DNS reconciler now fails closed on malformed attributes the
  library decoder would have panicked or mis-sliced on (strictly wider
  validation than its previous in-file decoder only in that table/DSCP
  attributes are now also length-checked; every previously decoded
  field keeps identical semantics).
- `RuleListDSCPSelectors` consumers (userspace FIB mirror) get the same
  rows through the validated decoder; a malformed kernel row now errors
  the snapshot (fail-closed, as its contract already required) instead of
  risking an unchecked-slice panic.
