# 16767 — system syslog rebuilt (and closed) every host client on every apply

- **Timestamp**: 2026-10-25
- **Action**: `applySystemSyslog` rebuilt every `system syslog host`
  client on every apply and every 30 s retry tick — no fingerprint, no
  per-host reuse — and `SyslogSlogHandler.SetClients` closed every old
  client. During a DNS outage an unrelated commit therefore closed a
  working hostname collector's connected-UDP client, installed nothing,
  stalled the commit 5 s per hostname host, and armed a retry that held
  applySem for the same stall every 30 s. Gave the system surface the
  `security log stream` treatment (#9326/#15231 A47-06): a whole-set
  fingerprint (`systemSyslogFingerprint` over the stanza in authored
  order, the derived facility/threshold per host, and the system
  hostname) whose early return additionally requires no retry debt and
  the handler still holding exactly the cached set (fail-open on any
  drift or fingerprint failure); per-host reuse keyed by
  (address, port, source) with a per-host fingerprint over stamped
  facility + derived severity, so the retry rebuilds only unbuilt
  hosts; a partial build never latches (the #14597 rule); duplicate
  keys install one physical client. Added
  `SyslogSlogHandler.SetClientsPreserving` (identity in both sets is
  neither closed nor replaced; plain `SetClients` untouched) and a
  test-only constructor seam `newSystemSyslogClientFn` (the
  syslogWarmFn pattern) so dial counts are observable without timing.
  Facility diagnostics still fire on every apply — the gate scopes the
  rebuild alone. Residual: the seam's deferred `Close` hook is not
  introduced by this change, but a seam-double `Close` racing the gate
  check remains a possible narrow race documented at the Daemon fields;
  re-verify under the next hostile review pass.
