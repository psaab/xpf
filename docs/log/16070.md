# #16070 - Holderless CommitCheck leaks compile diagnostics and allows repeat full compiles

- **Timestamp**: 2026-10-23
- **Issue**: A8-10 from #15987 — gRPC `CommitCheck` discarded its context with no holder check, the REST `configCommitCheckHandler` ignored the request entirely, and `Store.CommitCheck` compiled under `RLock` with no holder parameter or admission limiter. Any PermConfig non-holder could obtain compile diagnostics about another session's staged candidate and trigger repeatable full compiles (CPU) at will.
- **Change**:
  - `pkg/configstore`: `CommitCheckAs(sessionID)` is the holder-scoped form — it verifies the config-lock holder via `ensureHolderLocked` under the read lock before any compile (non-holder → `ErrConfigLockedByOther`, no diagnostics leak, no compile cost), and every form takes the single-slot `commitCheckSem` fail-fast admission semaphore (second concurrent check → `ErrCommitCheckBusy`) so repeat full compiles cannot queue unbounded. `CommitCheck()` remains as the internal/system form (`sessionID == ""` bypass, admission still bounded) for the in-process CLI and the event engine, which holds the lock itself. `New()` pre-creates the semaphore; the nil branch only upgrades zero-value Stores in tests.
  - `pkg/grpcapi`: `CommitCheck` now passes `connSessionID(ctx)` to `CommitCheckAs`; `configMutationStatus` maps `ErrConfigLockedByOther` → `PermissionDenied` (existing) and `ErrCommitCheckBusy` → `ResourceExhausted` (new). Direct in-process calls with no peer keep the existing peer-fallback semantics of the sibling mutators.
  - `pkg/api`: `configCommitCheckHandler` now requires the `X-Config-Session` header via `restConfigSessionID` (missing/malformed → 400 before the store, closing the `""` internal bypass), passes the holder identity to `CommitCheckAs`, and `writeConfigMutationError` maps holder conflict → 409 and `ErrCommitCheckBusy` → 429. Compile diagnostics (400) still reach the holder.
  - The #9889 candidate-reading census guard now names `CommitCheckAs` (the candidate-compiling store method) instead of `CommitCheck`.
- **Validation**: New RED-on-revert pins — `pkg/configstore/commit_check_holder_16070_test.go` (non-holder/holder/internal + busy slot), `pkg/grpcapi/commit_check_holder_16070_test.go` (PermissionDenied / ResourceExhausted mapping), `pkg/api/commit_check_holder_16070_test.go` (missing header 400, non-holder 409 with no leak, holder 200 + real ebpf diagnostic only for the holder). The pre-existing REST commit-check ebpf test now supplies a well-formed session header (candidate held by the internal no-holder enter). Focused suites `pkg/configstore`, `pkg/grpcapi` (incl. #9889 census, #6515/#8484 advisory), `pkg/api`, `pkg/cli`, `cmd/cli` green; `go vet` clean.
- **Risk**: Fail-closed only — a non-holder loses commit-check diagnostics it should never have had, and a second concurrent check gets a retryable busy error instead of a queued compile. The holder's own check, the in-process CLI, and the event engine (internal form) are unchanged. No response shapes change for admitted callers.
