# #16660 — #15117 residual: unicast NS to a v6 proxy-NDP external never reaches the kernel on its ingress netdev

## Defect

A unicast Neighbor Solicitation (NUD probe, ICMPv6 135 with hop limit
255) addressed to an IPv6 static-NAT/DNAT external that is **not** an
interface address was never answered:

- The XDP shim passed on-link NDP to the kernel only for
  interface-NAT destinations (#15117) or local destinations. The
  interface-NAT map holds only SNAT-egress interface addresses; the
  local map holds interface addresses plus kernel `AddrList`
  addresses. A NAT/DNAT external published via `proxy-arp`/`proxy-ndp`
  is in neither.
- The worker therefore took the packet: #15117 stopped the destination
  translation and LocalDelivered it — into the `xpf-usp0` TUN
  (`Trusted` slow-path outlet, `IFF_TUN|IFF_NO_PI`).
- The kernel's proxy-NDP lookup (`pneigh_lookup`) is keyed by the
  **receive device**. The NTF_PROXY entry sits on the configured WAN
  netdev; arrival via `xpf-usp0` misses, so no NA was ever sent.

Multicast NS still reached the kernel through the shim's multicast
early pass and was answered there, so the impact was recurring NUD
churn (DELAY/PROBE → FAILED → multicast re-resolution) once per NUD
cycle for every IPv6 NAT external on a directly connected segment —
a liveness defect, no enforcement loss. Meanwhile
`docs/feature-gaps.md` asserted "v6 static-NAT / NAT64 external proxy
is functional end-to-end" and `pkg/cluster/arp_responder_8621.go`
asserted the kernel answers v6 proxy NDP correctly, steering diagnosis
away from the dataplane.

## Fix (acceptance direction: publish the v6 proxy-NDP target set to a shim map)

- `userspace-xdp/src/degraded_ndp.rs`: new
  `is_proxy_ndp_ndp_control(type, hop_limit, is_proxy_ndp)` predicate —
  ICMPv6 133–137, hop limit exactly 255, destination in the proxy set.
  Same shape as the #15117 interface-NAT arm.
- `userspace-xdp/src/lib.rs`: new `userspace_proxy_ndp_v6_domain` map
  (8192, `{domain, addr}` key) and `is_proxy_ndp_destination`. On
  session miss, and in the degraded twin (`is_degraded_local_or_control`),
  an on-link NDP packet to a proxy target returns `cpumap_or_pass` on
  its ingress netdev — the device the pneigh entry sits on — before the
  worker can LocalDeliver it into the TUN. New branch arm
  `session_miss_proxy_ndp` (27; `USERSPACE_BRANCH_ARM_MAX` 27→28, Go
  `xdpBranchArmNames` grown to match).
- `pkg/dataplane/userspace/maps_sync.go`:
  `buildDesiredProxyNDPAddressSets` derives the set from the same
  source of truth the installer consumes — `cfg.Security.NAT.ProxyARP`
  (both `proxy-arp` and `proxy-ndp` compile there) — keyed by the
  routing domain of the snapshot interface row each entry names.
  IPv6 only; v4, v4-mapped, malformed, and unresolvable-interface
  entries are skipped exactly as the installer skips them.
  `syncProxyNDPAddressMapsWithSetsLocked` reconciles the map
  (stale-prune + install) inside `syncUserspaceClassifierMapsLocked`
  after the interface-NAT sync, with the #9646-style capacity
  preflight (`checkProxyNDPAddressCapacity`) before any write.
- `pkg/dataplane/userspace/maps.go`: `mapNameUserspaceProxyNDPv6`
  registered; `maps_decouple_test.go` registry updated;
  `xdp_shim_decouple_test.go` bootstrap injector installs the map.
- `pkg/dataplane/userspace_xdp_bpfel.o` + manifest + gate verdict
  regenerated via `pkg/dataplane/build-userspace-xdp.sh`
  (pinned nightly-2026-05-23, bpf-linker 0.10.2): verifier PASS,
  628393 processed insns, 37.16% headroom.
- Docs/comments corrected: `docs/feature-gaps.md` (the false
  end-to-end claim now scoped, with the #16660 shim pass described)
  and `pkg/cluster/arp_responder_8621.go` (the "kernel answers v6
  proxy NDP correctly" claim now carries the per-device arrival
  qualification).

NOT changed: the worker-side #15117 behaviour (NDP to a locally owned
external still LocalDelivers and is answered if it ever arrives via
the TUN path; echo and off-link NDP still translate); the #10640
removal of the type-only shim NDP pass (the new arm is
destination-qualified on the proxy map plus hop 255); RG-ownership
suppression — a suppressed interface's desired set is empty in
`ReconcileProxyARP`, and the shim set is derived from config, so on a
standby the shim may pass an NS to a kernel that has no entry;
the kernel then answers nothing, exactly as for a multicast NS on a
standby today. No session is minted and no policy gate is weakened:
the only packets whose disposition changes are ICMPv6 133–137 with
hop limit 255 addressed to an explicitly configured proxy-NDP target,
and the kernel validates NDP (checksum, target, code) before
answering.

## Risk

Bounded to ICMPv6 133–137 with hop limit exactly 255 addressed to a
configured proxy-NDP target. A spoofed on-link NDP packet to such an
address now reaches the kernel proxy-NDP on the wire device instead
of the worker; the kernel validates before answering. A stale shim
entry (config removed between syncs) passes an NS the kernel has no
entry for — the kernel drops it, no NA, no forward. Capacity refusal
leaves every classifier map on the previous plan (#9646 posture).
