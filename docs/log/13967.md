# #13967 — Warn about untrusted BA treatment across fabric

## Why

A packet redirected over the HA fabric arrives on the egress node with the
fabric parent ifindex. That node-local ifindex has no logical ingress
classifier binding, so a trusted DSCP/precedence BA marking falls through to
the default queue and default loss-priority rewrite. Network-control traffic
can therefore leave on the best-effort queue and lose its configured codepoint
when ownership is split or transitioning.

## What

No forwarding behavior is changed. When a chassis-cluster fabric link is
configured, the commit-time advisory warns that packets arriving over the HA
fabric are treated as untrusted for DSCP, IP-precedence, and 802.1p BA
classification, so the egress default queue and loss-priority rewrite apply.
This makes the existing best-effort behavior explicit rather than applying an
egress-interface classifier that cannot reliably recover the peer's ingress
binding.
