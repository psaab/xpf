# Issue #15720: completion walkers mishandle option-map leaves

- **Timestamp**: 2026-10-19
- **Problem**: `CompleteFromTree`, `CompleteFromTreeWithDesc` and
  `LookupDesc` in `pkg/cmdtree/tree.go` returned as soon as a matched
  node had `Children == nil`, without honouring `IsTypedLeaf()`,
  `HasDynamic()` or the enclosing node's `Options` map. On option-map
  commands such as `show security flow session`, the typed option
  `source-port`, the dynamic option `zone`, the two-token subtree
  `sort-by bytes` and the flag `nat` therefore ended the walk:
  `CompleteFromTree(show security flow session source-port 514)` and
  `sort-by bytes`/`nat` returned no candidates, `CompleteFromTreeWithDesc`
  returned only the consumed leaf's `<integer>` placeholder, and
  `LookupDesc(..., zone/trust, ...)` returned `""` after a dynamic,
  subtree or flag leaf. Tab completion and `?` help omitted every
  remaining option, while `Canonicalize` (`pkg/cmdtree/canonicalize.go`,
  #9505) already resolved the same lines in any option order.
- **Fix**: All three walkers now track the nearest `Options` node's
  child map (`node.Options && node.Children != nil`, mirroring
  `Canonicalize`) and resume among those options whenever the current
  level is exhausted: after a childless typed/dynamic option leaf's
  single value is consumed, after a flag leaf, and after a leaf of a
  subtree under the Options node (`sort-by bytes`). A dynamic option at
  the end of the words still offers its configured values, a typed
  option its placeholder/examples, and `LookupDesc` describes a
  trailing dynamic value as `(configured)` and any remaining option by
  its declared description. The resume is gated on the declared
  `Options` map: a stray word after a consumed value, and a second
  option keyword where a value was pending, still complete nothing,
  exactly as `Canonicalize` refuses those lines. Non-Options dynamic
  chains (`show security policies from-zone ... to-zone ... policy`,
  `show route table`) keep their pre-existing unions of child keywords
  and dynamic values.
- **Scope note**: `TestOptionsIsHonouredOnlyInCanonicalize9505` pinned
  `Options` to `Canonicalize` alone (#9505). That scope is deliberately
  widened to the three completion walkers by this fix; the test is
  renamed `TestOptionsScopeIsPinned9505`, keeps the same four-reader
  allow-list, and `TestOptionsHonouredByCompletionWalkers15720` asserts
  each walker reads `Options` so the leaves cannot silently end a walk
  again. `Options` remains set-only in the tree declarations; no node
  gained or lost the flag.
- **Not changed**: `Canonicalize`, the dispatcher argument parsers, and
  every tree declaration are untouched. Completion remains advisory:
  it now offers the options the canonicalizer already accepts, and
  nothing it newly offers is a command `Canonicalize` refuses (pinned
  by the stray-word and value-slot cells).

## RED -> GREEN proof

- **RED** (pre-fix `959eeee6`, tests present):
  `go test ./pkg/cmdtree/ -run '15720'` failed — typed/subtree/flag/
  placeholder rows returned `[]`/`[<integer>]` instead of the session
  option map, dynamic values after a consumed option were not offered,
  `LookupDesc` returned `""` after dynamic/subtree/flag leaves and for
  a trailing dynamic value, a stray word after a typed value completed
  the leaf placeholder, and the AST guard reported `Options` read only
  in `Canonicalize`.
- **GREEN**: The same command passes after the fix; the full
  `pkg/cmdtree` suite passes, including the neighbouring canonicalize,
  one-value (#9505/#11835), placeholder, nil-config provider and
  session-filter suites.
