## Why

`joinFeedURL` (pkg/feeds/feeds.go) silently fell back on malformed
per-feed paths. `url.Parse` error returned the fetchable base URL, so
`/denylist%ZZ.txt` fetched the server base and installed its prefixes
under the named feed. A `//denylist.txt` network-path (host token,
empty path) and a `v1:prod/...` scheme:opaque form likewise collapsed
to a base fetch. Clearing `RawPath` decoded `%2F` to `/` in the wire
path. `resolveBaseURL` trimmed trailing `/` from the raw URL string,
cutting query/fragment tokens ending in `/`. The strict compiler gate
validated only the base URL, never the per-feed path, so all of these
committed clean.

## What

- `pkg/feeds/feeds.go`: `joinFeedURL` now rejects an unparseable
  per-feed path and any scheme/opaque/authority form by returning
  `""`; `Apply` registers no feed for a rejected join (fail-closed
  per #5645, warning logged) instead of fetching the base. A malformed
  BASE still returns unchanged so readFeed / the #5183 gate report it.
  The join runs on escaped paths with `RawPath` pinned, so `%2F`
  survives in the requested URI. `resolveBaseURL` trims trailing `/`
  from the URL path only, never from query/fragment, preserving the
  `https://` scheme; unparseable/scheme-less values keep the historical
  raw slash-trim, and the mirrored `feedServerResolvedBaseURL` in
  pkg/config matches.
- `pkg/config/compiler_validate_strict_observability.go`: the strict
  feed-server endpoint gate now also rejects a malformed per-feed
  `path` via `feedEntryPathMalformed` (mirrors the runtime rule;
  pkg/config cannot import pkg/feeds). Strict commit rejects; the
  tolerant load/peer-sync wrapper downgrades to a warning.
- Regression: `pkg/feeds/feed_url_join_malformed_14723_test.go`
  (join table, Apply-level no-fetch for each malformed spelling, and
  `%2F` preserved in `RequestURI` through httptest) and
  `pkg/config/compiler_feed_path_malformed_14723_test.go` (strict
  rejects, tolerant warns, valid/escaped paths accept). The #14177
  table's scheme-relative cell now expects rejection `""` instead of
  the silent tail-keep. `pkg/feeds/README.md` documents the rule.
- NOT changed: the base-URL malformed/plaintext gates (#5183/#14385)
  and the single-feed (no FeedEntries) registration path.

## Risk

- A config that (accidentally or deliberately) relied on a `//host/...`,
  absolute-URL, or colon-form per-feed path fetching only its tail under
  the configured origin now registers no feed and fails closed at
  runtime, and is rejected at strict commit. That silent wrong-endpoint
  fetch was the defect; operators must write a plain relative path.
- Query tokens ending in `/` now reach the server intact (previously
  truncated) — the correct value, but a server that had adapted to the
  truncated token would see a different credential.
