# #15763 — Logical unit `disable` ignored by host-inbound observability/backstop walks

## Mechanism
#14575 set `snap.AdminDisabled = iface.Disable || unit.Disable` on
`InterfaceSnapshot`, so snapshot-consuming loops excluded a disabled
unit's addresses. The config-walking loops were left checking only
`iface.Disable`, so a disabled logical unit still counted as
enforcement work:

- `zones_observability.go`: `hostInboundInterfaceAdminDisabled` cut the
  ref at `.` and read only the base interface; the `dhcpIntent` loop and
  both unit walks in `addresslessEnforcingInterfacesFromSnapshots`
  (VRRP resolved-family marking + DHCP-pending emission) accepted
  `unit.DHCP*`/`unit.VRRPGroups` regardless of `unit.Disable`.
- `zones_host_inbound.go`: the zoned VRRP walk, the unzoned VRRP walk,
  `forEachFirewallLocalAddrFromSnaps`' VRRP walk, the unzoned and
  zoned DHCP backstop walks (`BuildUnzonedDHCPUnleasedNetdevs`,
  `buildUnzonedVRFDHCPBackstops`, `buildZonedDHCPHostInboundBackstopNetdevs`),
  and non-zero-unit `stableRethLinkLocalTargets` all iterated units
  checking only `iface.Disable`.

Consequence: a zone whose only enforcement-relevant units are
unit-disabled stayed in `AddresslessEnforcingZones` /
`AddresslessEnforcingInterfaces`, so `HostInboundPendingIntentFromSnapshots`
latched true and the #10751 early host-input barrier
(`xpf_input_closed`) never handed off — a permanent wedge, not a
fail-open. Disabled-unit VRRP VIPs also leaked into zoned/unzoned
host-inbound deny scope and lifeline-shared computation.

## Fix
- `hostInboundInterfaceAdminDisabled`: parse the unit suffix and return
  true when that unit is disabled (interface-level disable unchanged).
- Every cited config-walking unit loop now skips `unit.Disable` units:
  DHCP intent, VRRP resolved-family marking, DHCP-pending emission
  (observability); zoned/unzoned VRRP VIPs, `forEachFirewallLocalAddr`
  VIPs, unzoned/VRF/zoned DHCP backstops, and stable-RETH non-zero
  units (host-inbound). The two `hasFam` snapshot scans in the unzoned
  backstop builders also skip `snap.AdminDisabled` rows, matching the
  observability snapshot lens.
- Interface-level `disable` behaviour and snapshot legs are unchanged;
  enabled sibling units keep scoping/pending exactly as before.

## Regression
`pkg/dataplane/userspace/zones_unit_disable_pending_15763_test.go`
(`TestUnitDisableDoesNotHoldHostInboundPendingIntent`, the name from
the report): `ge-0/0/0` unit 0 disabled+addressed (disabled-zone),
unit 1 disabled+DHCP (active-zone), unit 2 enabled+addressed
(active-zone), unit 3 disabled+VRRP VIP (disabled-vip-zone).
Snapshots come from the real `buildInterfaceSnapshots`.

- RED pre-fix: pending intent true; `addresslessEnforcingZones =
  [{disabled-zone [ge-0/0/0.0]}]`; `addresslessEnforcingInterfaces =
  [{active-zone ge-0/0/0.1 inet dhcp-pending}]`; DHCP backstops
  `{V4:[ge-0-0-0.10]}`.
- GREEN post-fix: no pending intent, no addressless entries, no
  disabled-unit address/VIP in any zone view or unzoned set, no DHCP
  backstops; enabled unit 2 still scopes active-zone; re-enabling
  unit 1 restores pending intent and its V4 backstop (control).

Neighbouring suites (`TestAddressless*`, `TestHostInboundPending*`,
`TestDisabled*`, `TestUnitDisable*`, `TestBuildZoneHostInbound*`,
`TestBuildUnzoned*`, `TestStableReth*`, `TestHostInbound*`,
`TestQuarantined*`, `TestFence*` in `pkg/dataplane/userspace`) pass,
except `TestDisabledInterfaceNoPendingOrVIPLeak13149` which fails
identically on unmodified master (pre-existing: `CompileConfig`
rejects a prefix-less VRRP virtual-address in its fixture).

Residual: daemon `addStableRethLinkLocal` (pkg/daemon) still installs
the stable LL on a unit-disabled non-zero unit's netdev; the
host-inbound scope now correctly excludes it, and the snapshot fences
the forwarding surface, so this is address-presence only, not an
enforcement leak.
