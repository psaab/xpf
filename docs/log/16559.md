# #16559: unchanged-lease renewal hook deadlocks on `applySem`

- **Timestamp**: 2026-10-24
- **Problem**: While #11497 host-inbound gap debt was owed, a
  content-identical T1/T2 renewal called `onDHCPUnchangedLease` →
  `applyActiveConfig` inline on the DHCP client goroutine
  (`pkg/dhcp/commit.go` `notifyLeaseStateChanged` →
  `pkg/daemon/daemon_dhcp.go`). `applyActiveConfig` parks uncancellably
  on `applySem` (`beginBackgroundApply(context.Background(), …)`).
  An apply already holding `applySem` that reached
  `reconcileDHCPClients` → `dhcp.Reconcile` and removed/changed that
  client's stanza then waited on `<-dc.done` forever: the client
  goroutine was parked in the hook, so `done` never closed, `applySem`
  never released, and every later commit, rollback, HA config sync and
  background apply hung until xpfd restarted. The stopped client also
  never renewed, so its WAN lease eventually expired. The same cycle
  occurred when the hook's own apply stopped its caller.
- **Fix**: The daemon hook no longer applies inline. `onDHCPUnchangedLease`
  only nudges the existing 30s host-inbound gap retry owner over a new
  coalescing depth-1 wake channel (`hostInboundGapWakeCh` /
  `nudgeHostInboundGapReassert`, mirroring `nudgeProxyARPReassert`
  #9087); `hostInboundGapReassertLoop` selects on the wake channel
  beside its ticker and the loop goroutine owns the `applySem` apply.
  The hook remains debt-gated (`hostInboundGapOwed`), so healthy
  renewals stay silent. Supporting move: the #11497 gap-debt discharge
  defer in `applyConfigLocked` is now registered before the
  `applyBodyForTest` seam return (previously after the nil guard, i.e.
  past the seam's early return) — pre-fix the #11497 test passed only
  because the inline hook reached `applyConfigUnderSem`'s own
  discharge, which the retry owner's `applyActiveConfigResult` path
  does not have; the move makes stubbed applies discharge through the
  one choke point on both paths, with no production behaviour change
  (the defer still fires exactly once per successful apply). The
  `SetUnchangedLeaseCallback` contract now documents that the hook
  runs on the committing client goroutine and must not block.

  (both va39 arms report wedged=false): control (no debt → no apply, no

  one coalesced wake), and the full arm — a real `dhcp.Manager` client

  `TestApplyTailReconcilesSurfacesVRRPIdentityCollision`) fail

- **Risk**: The renewal-triggered re-drive is now asynchronous: in the
  worst case it waits for the wake to be serviced by the loop (already
  running; sub-second) instead of applying synchronously — strictly
  better than the previous unbounded wait for the 30s tick, and the
  tick remains as backstop if a wake is somehow lost while debt is
  still owed. No behaviour change when no debt is owed, and none on
  the changed-lease (`scheduleRecompile`) path.
