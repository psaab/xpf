# #12144 — bind flat apt packages to the selected release

- **Timestamp**: 2026-10-08
- **Why**: The flat builder's default `dist-deb` glob admitted any xpf-named version, copied into a persistent suite pool without pruning, and indexed the entire pool. `gate_apt` verified the InRelease signature/keyring agreement but did not bind package identity or contents to the release index.
- **Change**:
  - `make dist-repo` now passes its authoritative `DEB_VERSION` as `XPF_DEB_VERSION`. The default builder selects only filenames at that version and checks selected filename Package/Version/Architecture against `dpkg-deb`. Explicit flat input sets reject identity mismatches, mixed versions, and duplicate Package/Architecture entries.
  - A flat rebuild removes every old `.deb` under that suite/component before copying the selected set, so omitted packages are withdrawn from `Packages`. When reusing reprepro output, it removes `conf/distributions` only if that file declares the flat target `$SUITE`; foreign-suite stanzas remain. It refuses a symlinked `conf/` before reading or unlinking its child.
  - `gate_apt` checks flat suite indexes against signed Release checksums (including `Packages.gz`), matches the exact suite pool to indexed paths and dpkg identity, verifies package Size/SHA256 against Packages, rejects duplicate package identities, and binds the target suite version to signed `latest.json`. Reprepro retention is selected per suite only when `conf/distributions` declares that suite's `Codename:`; an unrelated/empty marker cannot bypass flat binding.
  - `XPF_DEB_VERSION` remains required for the default `dist-deb` selection and does not pin an explicit `--debs` set; explicit selections retain identity, architecture, duplicate, and single-version checks.
- **Regression tests**: The binding suite covers default selection, identity and package/index checks, and explicit `--debs` exemption. Real reprepro tests cover fresh/legacy classification, suite-scoped mixed-tree binding, flat marker retention/removal, and tamper rejection. Inputs tests exercise containment on flat and reprepro sinks plus refusal of the conf symlink.
- **RED (base `83b5c9553`)**: Hermetic real `.deb` fixtures reproduced stale retention: after building with `xpf` versions `0.0.4+g0000000` and `0.0.5+g1111111`, then rebuilding with only `0.0.5`, base `Packages` still contained `0.0.4`. A signed base build containing legitimate `0.0.5` (with the matching archive keyring) plus keyring-less `9.9.9+g9999999` indexed both; base `gate_apt` verified InRelease and key agreement and **passed** with the extra. The base default glob also indexed the higher extra.
- **GREEN (same fixture scenarios)**: The flat rebuild withdrew `0.0.4`; the default set pinned to `0.0.5` omitted `9.9.9`; explicit same-Package higher-version selection failed. A signed current repo passed the gate with `0.0.5`; the gate rejected a pooled `9.9.9` extra as outside the verified target version and rejected same-identity substituted package bytes against the signed Packages Size/SHA256.
- **Round-1 RED/GREEN**: At PR head `99b1631b1`, a real signed reprepro repo built successfully but `publish.py --no-image` failed with `no pooled .deb packages`; the same repo passed the `83b5c9553` base gate. The integration test restores an empty legacy `pool/<suite>` beside `conf/distributions` and now passes. A separate reprepro-to-flat test was RED because the flat builder left the stale marker; after cleanup it passes and the flat gate rejects same-identity substituted package bytes. The explicit `--debs`/mismatched-`XPF_DEB_VERSION` regression also failed before scoping and passes afterward.
- **Round-1 validation**: The binding module passed 7 tests; the reprepro module passed 13, including both real builder/gate integration scenarios; `selftest.sh` passed 58/0. Shell syntax and Python compilation passed. Base and head reprepro outputs matched after both sequential builds (1.0.0 then 2.0.0): pool deb hashes and `Packages` bytes were identical at each version.
- **Round-2 MINOR-A RED (d385c13a1)**: Real `make dist-repo` produced flat stable `1.0.0`, then reprepro edge; a signed-image `2.0.0` full `publish.py --channel stable` exited 0 and logged both suites as using reprepro. Appending same-identity bytes to stable's package still passed. A pure flat tree with an empty `conf/distributions` plus substituted package bytes also passed.
- **Round-2 MINOR-A GREEN**: With per-suite `Codename` routing, S6 now fails on the stable package version (`1.0.0` outside verified image version `2.0.0`) and the substituted package fails signed Packages Size/SHA256. S3-plant likewise fails Size/SHA256. Fresh reprepro, actual prior-builder legacy output with empty `pool/stable`, and flat-to-reprepro same-suite output all pass; reverse-order flat rebuild retains the foreign `Codename: edge` marker.
- **Round-2 MINOR-B RED (d385c13a1)**: With `apt/pool -> external`, real reprepro `make dist-repo` exited 0 and wrote both `.deb` files outside `--out`. With `apt/pool/main -> external`, it likewise wrote both files outside.
- **Round-2 MINOR-B GREEN**: Containment now refuses both shapes with `repo path escapes --out ... refusing to write`; no external package files are created. The containment suite exercises the flat pool/component sinks and explicit reprepro pool/component sinks.
- **R1 RED/GREEN**: On the original head, the binding+reprepro 20-test set remained green after deleting only the conf-symlink guard; on the S7a `apt/conf -> external` shape, that mutant exited 0 and deleted the external `distributions` file. The new regression asserts refusal, preserves the external bytes, and fails when run against that mutant.
- **Round-2 validation / MAJOR-1 shapes**: binding 7/7; reprepro 17/17; inputs 16/16; `make dist-selftest` 58 passed, 0 failed. Fresh reprepro S1, actual prior-builder legacy S2, reprepro-to-flat transition S4, and flat-to-reprepro same-suite S5 pass. Binding tests retain MINOR-2 explicit-`--debs` scoping.
- **Risk / limits**: Direct default builder invocation requires `XPF_DEB_VERSION`; the supported `make dist-repo` target supplies it. Explicit `--debs` input remains caller-selected even if `XPF_DEB_VERSION` is exported. An explicit `publish.py --no-image` run has no signed image `latest.json` authority, but still enforces flat index/pool identity, byte hashes, and single-version-per-package constraints. Reprepro retention remains backend-managed, and the flat-only gate intentionally does not bind reprepro package versions. Sink containment runs after `mkdir`, so a pre-planted parent symlink can leave an empty external directory but cannot receive package files. The existing apt-ftparchive wall-clock race is tracked in follow-up issue #12544.
