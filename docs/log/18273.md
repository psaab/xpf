# #18273 — Header census substring-weak and dangling struct refs after #17146 trim

- **Timestamp**: 2026-10-27
- **Issue**: #18273 (filed from Rev18185Opus-2 hostile review of merged PR #18185)
- **Base**: `origin/master e88c43fd01` (branch merged forward to `116218f992` before landing)

## Defect (STEP-0, verified live on master)

1. `TestEveryHeaderIdentifierHasLiveReader17146` (the #17146 census in
   `pkg/dataplane/retirement_boundary_canary_test.go`) flattened the
   ENTIRE out-of-`bpf/` corpus (`.go`/`.rs`/`.sh`, comment-stripped) and
   each header identifier into one alphanumeric blob and ran
   `strings.Contains`. Identifier boundaries were erased, so:
   - `DSCP_EF`/`DSCP_AF11`/`DSCP_AF31`/`DSCP_AF43` passed only because
     the substrings `dscpef`/`dscpaf11`/... occur inside the
     `DSCPValues` string keys in comments/prose — their header VALUES
     (46/10/26/38) were pinned against nothing. Drifting the header's
     `DSCP_AF11` would not red anything.
   - `SESS_FLAG_LOG` passed with no Go/Rust constant at all (a stray
     `log_flags`-shaped substring in the blob).
   - `MAX_CPUS` passed with zero readers after the `cpu_map` deletion
     (substring collision with Go `NumCPU`).
2. The same trim that the census was written to police had deleted
   struct DEFINITIONS from `xpf_common.h` while `bpf/headers/xpf_maps.h`
   kept map declarations naming them in `__type()`:
   `iface_counter_value` (xpf_maps.h:294), `scan_track_key` /
   `scan_track_value` (403-404, 410-411). The census enumerated
   definitions only, so use-without-definition was invisible. Widening
   the check during this fix found two more of the same shape:
   `nat64_state_key` / `nat64_state_value` (xpf_maps.h:710-711) and
   `nat_pool_ip_v6` (434).

## Fix

- Census (`retirement_boundary_canary_test.go`, same test name):
  - Matching is now per-identifier. The corpus is reduced to the
    NUL-separated canonical keys of its identifiers
    (`headerCorpusKeys17146`: maximal `[A-Za-z0-9_]` runs, each reduced
    by `headerIdentKey17146` — lowercase, digits kept, underscores
    dropped); a header identifier matches only if some corpus
    identifier IS it. Extra words (`NumCPU` vs `MAX_CPUS`,
    `log_flags` vs `SESS_FLAG_LOG`) and substrings inside longer
    identifiers no longer count as readers.
  - Explicit allowlist `headerCensusAllowlist18273` (each entry carries
    its reason): the four DSCP alias-map defines (reader-visible only
    as map string keys — but see the pin below), `iface_counter_value`
    (Go spells out `InterfaceCounterValue`), `MAX_NAT_POOL_IPS_PER_POOL`
    (Go appends plural-s), `HOST_INBOUND_DHCPV6` and
    `GLOBAL_CTR_SCREEN_WINNUKE` (acronym-seam renames), `nptv6_key` /
    `nptv6_value` (Go export casing), `nat64_state_value` (restored
    struct; Rust carries its fields without a same-named type), and the
    internal-only sizing/layout trio `MAX_NAT64_PREFIXES`, `pkt_meta`,
    `policer_state` (consumed solely inside the retained headers).
  - DSCP values are pinned: `headerCensusDSCPPins18273` parses every
    `DSCP_*` define in the retained headers and compares its value to
    the `DSCPValues` SSOT by lower-case alias; an unknown alias, a
    missing one of EF/AF11/AF31/AF43, or any value drift fails.
  - Use-without-definition: every `struct X` named by any retained
    header (map `__type()`, field types; `bpf_devmap_val` exempt as a
    kernel/BTF extern) and every `max_entries(MACRO)` must be defined
    by a retained header.
- Headers — restore or drop per remaining users:
  - RESTORED in `xpf_common.h` (verbatim pre-trim layouts from
    969d21715a): `iface_counter_value` (Go names the
    `interface_counters` map and mirrors it as
    `dataplane.InterfaceCounterValue`), `nat64_state_key` /
    `nat64_state_value` (the `nat64_state` map is named by the Go shim
    allowlist in `loader_userspace_shim.go`).
  - DROPPED from `xpf_maps.h`: `port_scan_track` / `ip_sweep_track`
    (no Go/Rust code mirrors either map by name; the live trackers are
    `PortScanTracker`/`IpSweepTracker` in
    `userspace-dp/src/screen/scan.rs`) and `nat_pool_ips_v6` (Go writer
    side already retired, `compiler_nat.go`).
  - RETIRED defines the tightened census proved readerless:
    `MAX_CPUS` and `SESS_FLAG_LOG` deleted from `xpf_common.h` with
    retirement comments (bit 2 stays unassigned; no Go `SessFlagLog`
    mirror exists).

## Risk

- Header changes are layout-preserving for every retained struct
  (conntrack offset pin and `struct event` pin pass unchanged);
  restored structs use their exact pre-trim definitions. Dropped maps
  had no reader outside the header itself.
- Shim freshness manifest/build digest go stale until the parent runs
  `make generate`.
- Census runtime grows modestly (per-identifier key set instead of one
  blob); same test, same corpus walk.
