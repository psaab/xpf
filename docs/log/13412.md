# #13412 — keep denied DHCPv6 off VRF admission sets

- **Source**: regression reported against #13157, from hostile review evidence.
- **Files**: `pkg/dataplane/userspace/zones_host_inbound.go`,
  `pkg/dataplane/userspace/dhcp_backstop_d311_13157_test.go`.

## Why

The DHCPv6 deny filter ran before zoned VRF admits were appended. With two
zone-bound units sharing one VRF netdev, a permitting unit could therefore put
the device back in `AdmitVRFSlavesV6` after a sibling's deny had filtered it.
The netlink fence emits the resulting `sdifname` accept before ingress
adjudication, bypassing the intended deny.

## What

Apply the existing denied-device filter again after appending zoned VRF admits.
The test models two unit aliases resolving to one VRF netdev, with one zone
permitting DHCPv6 and the other denying it. It asserts that the shared device is
absent from both admission sets while remaining in both IPv6 drop-backstop sets.

## Validation

- Regression on pristine `origin/master` (`dd607606a`):
  `GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/var/worktrees/.cache/go-tmp go test ./pkg/dataplane/userspace -run '^TestD311_13412_VRFSharedDenySuppressesAdmit$' -count=1 -v`
  — RED: `AdmitVRFSlavesV6=[ge-0-0-0]` included the denied shared device.
- Reverting the added filter reproduced the same RED; after restoring the fix,
  the issue-focused test and `go vet ./pkg/dataplane/userspace/` passed, and
  `gofmt -l` reported no changed Go files.
- `go test ./pkg/dataplane/userspace ./pkg/nftables` — nftables passed; the
  userspace package failed on the checked-in `TestContractSnapshotGolden9821`,
  multiple unrelated existing behavior assertions, and Unix-socket path
  `bind: invalid argument` failures under `/var/worktrees/.cache/go-tmp`.

## Risk

No change to DHCP drop-backstop coverage or netlink rule generation; denied
VRF devices are removed only from the unconditional DHCPv6 admission set.
