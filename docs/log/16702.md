# #16702: `top exit` restored the stale edit cursor after config mode was released

- **Timestamp**: 2026-10-25
- **Action**: Both `dispatchTopUp15082` copies (remote `cmd/cli/shared.go`,
  local `pkg/cli/cli_dispatch.go`) restored the saved edit cursor and the
  config (`#`) prompt unconditionally after dispatching the inner
  command. When the inner command was a top-level `exit`/`quit`, it had
  already released configuration mode — remote: `configMode=false`,
  `editPath=nil`, operational prompt; local: `ExitConfigure` cleared the
  cursor and `configOwned=false`, operational prompt via
  `exitConfigureTop` — so the unconditional restore resurrected the
  pre-exit cursor behind an operational session. On the remote surface
  the next `configure` printed `[edit]` (the root) while later commands
  were still prefixed with the stale cursor (e.g. `routing-instances
  RI1`), so a root statement could be staged into a VRF/group body; on
  the local surface the console was left in operational mode showing
  the `#` prompt. Fix: restore cursor+prompt only while still in
  configuration mode (`c.configMode.Load()` remote,
  `c.store.InConfigMode()` local), and separately clear
  `c.editPath` on a successful remote `configure` so re-entry starts
  at the root the `[edit]` banner promises (the local surface already
  gets this from `EnterConfigureSession` clearing `editPath`).
  `up exit` from depth continues to act as exit-as-up via the inner
  dispatch (target cursor non-empty), unchanged. New regression tests
  drive the real dispatchers through `top exit`/`top quit` plus a
  remote re-enter-`configure`-then-`set` sequence (the DEFECT arm
  asserts the Set RPC carries the root path), with `top set` positive
  controls on both surfaces.
- **File(s)**: `cmd/cli/shared.go`, `pkg/cli/cli_dispatch.go`,
  `cmd/cli/top_exit_stale_cursor_16702_test.go` (new),
  `pkg/cli/top_exit_stale_cursor_16702_test.go` (new),
  `docs/log/16702.md` (this file).
- **Validation**: RED-on-revert verified firsthand: with both guards
  reverted to the unconditional restore (and the remote
  `configure` cursor-clear removed), both defect tests fail with
  `editPath = [routing-instances RI1], want empty after release —
  stale cursor restored`; with the fix, all four new tests pass.
  Targeted suites green; full `go test ./cmd/cli/ ./pkg/cli/
  -count=1` failures are pre-existing on origin/master (sampled
  base-attributed in a pristine worktree: FRR parity, zones detail,
  predefined application sets, multi-pipe dispatch all FAIL at base
  too; the remote gofmt/value-slot census tests likewise). The prompt string is not directly
  observable in a unit test (chzyer/readline keeps it in its
  RuneBuffer and exports no getter), so the cells assert the state
  that determines it (`configMode`/`InConfigMode` plus the cleared
  cursor and the exit banner).
- **Residual**: None known. Bare `up`/`top` navigation, exit-as-up at
  depth (#15237), and the #5812 transactional exit-retry path are
  untouched and covered by their existing suites.
