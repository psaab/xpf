# Issue #16872: routing-policy `then next term` refused at strict commit, turned into terminating reject on tolerant path (R3-B08-04)

## Why

Routing-policy `then next term` is a documented Junos flow-control
action: "Skip to and evaluate the next term in the same routing
policy. Any accept or reject action specified in the then statement
is skipped. Any actions in the then statement that manipulate route
characteristics are applied to the route." The README claims native
Junos syntax, but the term was unusable:

- The schema for `policy-options policy-statement <p> term <t> then
  next` (`schema_routing.go`) allowed only the enum value `policy`
  (introduced by #11780), so strict commit / `CheckText` rejected
  `then next term` with `invalid value "term" ... (expected one of:
  policy)`.
- The compiler's `recordPolicyNextAction11780` treated every
  non-`policy` value as malformed: it set
  `invalidNextPolicy11780` and forced `Action = "reject"`. On a
  tolerant load the term therefore became a terminating reject where
  Junos would fall through — a silent route withdrawal for that term.

Severity is Low (strict fails closed on valid syntax; the workaround
of deleting `next term` is semantically neutral; reaching the
tolerant path with this token is unlikely), but both directions were
wrong for a documented token.

## What

Accept `next term` as an explicit non-terminating marker that
compiles to the existing fall-through (`on-match next`):

- `pkg/config/types_routing.go`: new `PolicyTerm.NextTerm bool` —
  the authored marker. It needs no renderer state: a term with
  `NextTerm` and no `Action` already renders as `permit` +
  `on-match next`. The flag exists for `show policy-options`
  display and for the conflict gate.
- `pkg/config/compiler_routing.go`: `recordPolicyNextAction11780`
  now switches on the value — `policy` sets `NextPolicy`, `term`
  sets `NextTerm` (no `Action`, modifiers already recorded still
  apply), anything else keeps the pre-existing malformed recording
  (`invalidNextPolicy11780` + fail-closed `reject`). All three call
  sites (braced `then` children, packed term-line, flat-set inline
  keys) funnel through this one function, so every spelling is
  covered.
- `pkg/config/schema_routing.go`: the `then next` enum is now
  `["policy", "term"]`, so the strict schema walk (CheckText /
  commit check) admits `next term` and still refuses unknown
  continuations by name.
- `pkg/config/compiler_policy_next_policy_11780.go`: the malformed
  diagnostic now reads "must be `then next policy` or `then next
  term`"; new conflict arms reject `NextTerm` beside a terminal
  action and `NextTerm`+`NextPolicy` together (Junos: specify one
  flow-control action; a terminal beside `next term` is skipped).
  Strict rejects; on the tolerant path
  `failClosedMalformedNextPolicyActions11780` now forces every
  contradictory continuation state (malformed value, next-term +
  terminal, mixed continuations) to `reject` with both markers
  cleared — routing terms have no poison sentinel, so the compiled
  term itself must fail closed (pre-merge review fold; previously
  the lenient path retained the authored accept and FRR rendered a
  terminating permit, and the mixed state silently jumped).
- `pkg/frr/policy_render.go`, `pkg/config/routemap_seq_bound.go`,
  `pkg/frr/policy_chain_narrowed_deny_10129.go`,
  `pkg/frr/redistribute.go`, `pkg/frr/redistribute_daemon_16864.go`:
  belt for direct (non-compiler) producers — a term with
  `NextTerm`+terminal or `NextTerm`+`NextPolicy` renders as a
  terminating `deny`, is never a valid next-policy jump, and is
  not accept-capable for redistribution. Valid actionless
  `NextTerm` rendering is unchanged (byte-identical to
  modifier-only fall-through, pinned below).
- `pkg/cli/cli_show_routing.go`: `show policy-options` prints
  `then next term` for marked terms.
- Group merge: no change needed — the #15259 materialisation
  (`isRoutingTermThenNextPolicy15259`) already carries any
  group-supplied `then next ...` beside an inline peer, so group
  `next term` beside an inline terminal (and group/inline mixed
  continuations in both directions) reaches the conflict arms.
  The one #15259 test cell that pinned `next term` as malformed
  was updated to the conflict expectation.
- Docs: this file; the `pkg/config/README.md` #14425/#15259 bullet
  now documents the `next term` marker.

- RED witness (measured): with only the source fix stashed,
  `TestPolicyThenNextTermCompilesEverySpelling16872` fails with
  `then next "term" must be exactly then next policy` and
  `TestCheckTextRoutingNextTerm16872` fails with the reporter's
  exact probe string `invalid value "term" (expected one of:
  policy)`; both pass on this head.
- `go test ./pkg/config/ -run 'TestPolicyThenNextTerm|TestNextTerm|TestMalformedNextPolicy|TestNextPolicy|TestRoutingTermNextPolicy|TestPolicyThenNextPolicy' -count=1`
  — pass (next-term every-spelling: flat separate/packed, braced
  siblings/packed, inline tail, term-line; lenient no-reject;
  next-term+terminal strict-reject/fail-closed both orders;
  mixed next-term+next-policy strict-reject/fail-closed inline and
  both group directions; repeated identical continuations legal;
  all pre-existing #11780/#15259 cells except the one updated
  expectation).
- `go test ./pkg/frr/ -run 'TestNextTerm|TestConflictingNext|TestTolerantNextTerm|TestComposedPolicyNextPolicy|TestSinglePolicyNextPolicy|TestNarrowedSurvivor' -count=1`
  — pass: valid `NextTerm` render byte-identical to the unmarked
  term (`on-match next`, never `goto`); directly-constructed
  contradictory states render terminating `deny` with no
  continuation and are not valid jumps for sequence counting or
  the narrowed survivor; the tolerant-compile -> renderer pipeline
  test (both orders, #15259 group both directions, mixed both
  directions) renders deny 10 + deny 20 with no permit/goto/next,
  and valid next-term/next-policy controls are unchanged.
- `go test ./pkg/configstore/ -run 'TestCheckTextRoutingNextTerm16872' -count=1`
  — pass: CheckText (strict operator pipeline) accepts hierarchical
  and flat `next term` with modifiers, `next policy` and no-marker

- `go test ./pkg/cli/ -run 'TestShowPolicyOptions' -count=1` — pass
  (incl. the new `then next term` display cell).

## Risk

Additive: the only newly admitted token is the documented `term`
continuation. Contradictory continuation states (malformed value,
`next term` beside a terminal, `next term`+`next policy`) reject at
strict commit and fail closed to a terminating deny on tolerant
loads at both the compiler and renderer layers. Residual:
`show policy-options` now prints an extra `then next term` line
for marked terms (display-only); a tolerated contradictory term
loses its authored modifier display in `show` because the compiled
term is forced to reject (same trade as the pre-existing malformed
and #14425 fail-closed paths).
