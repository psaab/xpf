# Issue #13125 — repair IPsec address resolution for DHCP, dotted names, and VRRP

## Defect

The `interfaceRefIsDHCP` helper split references at the first period and inspected
only the named interface. This missed both `#9821` declared dotted interface
names such as `wan.ext.0` and DHCP-managed physical members behind a bondless
RETH (`reth0.0`). The daemon's `HasDHCPBoundGateway` gate therefore skipped the
`#2884` IPsec re-render after those DHCP leases changed. The configured-address
resolver used the same first-dot split, and its unit address selection omitted
VRRP virtual addresses, leaving VIP-only RETH gateways without `local_addrs`.

## Change

- Reuse `Config.SplitInterfaceUnitRef` for DHCP detection and configured local
  address selection, preserving declared dotted interface identity.
- Check the resolved RETH physical-member reference for DHCP/DHCPv6 as well as
  the logical RETH reference.
- Include VRRP virtual addresses as deterministic fallback candidates after
  configured unit addresses, allowing a VIP-only RETH gateway to resolve.
- Add `TestPolicyAddr13125RethDottedAndVRRP`, covering the DHCP gate, dotted
  interface address, RETH member DHCP, and RETH VRRP VIP resolution.

## Validation

  `go test ./pkg/ipsec/ -run '^TestPolicyAddr13125RethDottedAndVRRP$' -count=1`

## Risk

VRRP addresses are fallback candidates only, after primary, preferred, and
ordinary unit addresses. They may represent an address not currently active on
this node; this is necessary for deterministic configuration-time binding of
bondless RETH VIPs. No runtime dataplane or wire format changed.
