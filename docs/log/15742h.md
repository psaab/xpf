## Root cause

`poll_descriptor/mod.rs` HAInactive seed arm (lane G): for a
cluster-terminal resolution the FIB zeroes `egress_ifindex` and
stamps the would-be egress on `source_ifindex`. But the arm computed:

- `owner_rg_id = owner_rg_for_resolution(resolution)` — reads the
  zeroed egress → **0**;
- `fabric_punt_seed_metadata(..., to_zone_id, ...)` where
  `to_zone_id = zone_pair_ids_for_flow_with_override(..., egress=0)`
  → **0**, and the helper refuses zone 0.

So the seed was never minted on the live shape. Lane G's fixture
kept the would-be egress reachable in its zone pair, so its cell
stayed green while live starved — test-only-green. The tail safety
net already attributes cluster-terminal RG via `source_ifindex`;
the seed arm and the flowless intended-zone capture did not.

ICMP (the gate probe) is flowless: it fabric-redirects correctly
(flowless arm) but by design installs no punt seed; its return
authorisation is the HA-synced session fw0 installs. That path is
unaffected except for zone-counter attribution (below).

## Fix

Root attribution site is the session-miss zone-pair derivation:
`zone_pair_ids_for_flow_with_override(..., resolution.egress_ifindex)`
with a zeroed cluster-terminal egress gave `to_zone_id=0` for the
whole miss arm, so policy evaluated `lan->0` (no permit needed to
reach the HAInactive arm, but `fabric_punt_seed_metadata` refuses
zone 0) and the seed else-if — which dispatch actually reaches
after the ForwardCandidate policy block declines non-candidates —
never minted.

- `poll_descriptor/mod.rs` (miss zone pair): for
  `ClusterTerminalHAInactive` with `source_ifindex>0`, derive
  `to_zone_id` from `egress_zone_id(source_ifindex)` when the
  egress-based zone is 0. All downstream adjudication (policy,
  seed, NAT scope) now sees the true `lan->wan` pair.
- `poll_descriptor/mod.rs` (flow-backed seed arm): for
  `ClusterTerminalHAInactive`, attribute owner RG via
  `owner_rg_for_flow(source_ifindex)` and seed egress zone via
  `egress_zone_id(source_ifindex)` when the zeroed-egress zone is 0;
  seed owner reuses that attribution. HAInactive unchanged.
- `poll_descriptor/mod.rs` (flowless arm): `flowless_intended_to_zone`
  likewise falls back to `source_ifindex` for cluster-terminal, so
  zone counters credit `wan`, not 0. No disposition change.
- No wire/protocol change: seed is local session state.
