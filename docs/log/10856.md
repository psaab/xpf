# Issue #10856 — blocklist-only IA_PD class hardening

## Why

DHCPv6 IA_PD extraction validated the IAPREFIX mask but did not reject blocked
address classes. A server could therefore place link-local, multicast,
loopback, or unspecified prefixes in the live delegation set, and the RA sender
would emit a delegated PIO because its existing class-related floor rejected
only delegated `/0`.

## What

The decoder and RA sink now share a blocklist-only, whole-prefix-overlap
classifier for `fe80::/10`, `ff00::/8`, `::1/128`, `::/128`, IPv4-compatible
`::/96`, IPv4-mapped `::ffff:0:0/96`, and site-local `fec0::/10`. A blocked
IAPREFIX is skipped individually, preserving usable siblings. The sender
rechecks only delegated prefixes, so operator-authored `::/0` remains valid.

This is not a global-unicast envelope or an overlap/pin policy. GUA, ULA, and
documentation prefixes remain accepted; configured-prefix overlap remains
outside this change.

The existing wire-boundary case for `2001:db8:1000::/1` now expects refusal by
intentional whole-prefix policy: masking that input produces `::/1`, which
intersects the blocked unspecified and IPv4-compatible address space. This is
not a new minimum-prefix-length rule; prefixes are refused when their masked
range overlaps the blocklist.

## Validation

- Before the guards on the clean base, STEP-0 probes accepted each core class
  as a live prefix (`live=1`) and emitted one delegated PIO (`PIOs=1`).
- The new per-class extraction and RA-sink rejection tests pass with the guards
  and fail when the production guards are stashed. GUA, ULA, documentation,
  and operator-authored `/0` controls pass both before and after the guards.
- The DHCP extraction tests also pin sibling salvage and whole-prefix overlap.
- `go test ./pkg/dhcp/... ./pkg/ra/... -count=1` passed.
- `go build ./...` and `go vet ./pkg/dhcp/... ./pkg/ra/... ./pkg/config/...`
  passed. `gofmt -l` on changed Go files was empty, and `git diff --check` was
  clean.
- A search of DHCP/RA test fixtures found no other IA_PD test relying on a
  `/1`-or-wider prefix being accepted; the only matching DHCP wire-boundary
  row is the refused `/1` case described above. Existing RA `/0` acceptance
  cells are operator-authored, not delegated.

## Risk

This PR is deliberately limited to the hard blocklist. ULA, documentation,
configured-prefix overlap, and explicit pin behavior remain outside this scope
for #10856/#12533.
