# 10856 — reject unsafe DHCPv6 IA_PD prefixes before RA

## Why

DHCPv6 extraction accepted IA_PD prefixes after mask validation only. A bad
upstream server could therefore put link-local, multicast, loopback,
unspecified, documentation, ULA, or configured-overlap space into the live
lease set. The daemon then derived and advertised that prefix on-link and
autonomous; the RA sender's old delegated-prefix floor rejected only /0.

## What

- Share a no-allocation IPv6 prefix classifier between DHCP extraction and the
  RA sender. It refuses non-IPv6, unspecified, loopback, link-local, multicast,
  documentation (2001:db8::/32 and 3fff::/20), ULA, and prefixes not wholly
  within the global-unicast 2000::/3 block.
- Skip an unsafe IA_PREFIX individually before it enters either live or
  withdrawn PD state. Other valid siblings in the same IA_PD remain usable.
- Before deriving a delegated RA prefix, refuse overlap with any configured
  interface address, static RA prefix, or NAT64 prefix. The RA sender repeats
  the check against its visible static PIOs and PREF64 as a defense in depth.
  Static/operator-authored PIOs, including an operator-authored ::/0, retain
  their existing behavior.
- There is no PD pin/allowlist mechanism. ULA and configured-prefix overlap
  are therefore refused without an exception. The source DHCP decoder cannot
  see whole-device config, so configured-overlap screening occurs in the
  daemon builder before RA construction, then again at the sender for its
  local PIO/PREF64 subset. Follow-up #12533 tracks a scoped explicit pin and
  provenance path for intentional ULA/overlap deployments.

## Validation

The throwaway STEP-0 probes were run before the change on the clean base:

- `go test ./pkg/dhcp -run '^TestStep0_10856_ReproAccepted$' -v -count=1`
  passed while logging `live=1` for `fe80::/64`, `ff02::1/128`, `::1/128`,
  `::/128`, `2001:db8::/32`, `fc00::/48`, `64:ff9b::/96`, and the GUA control.
- `go test ./pkg/ra -run '^TestStep0_10856_RASinkRepro$' -v -count=1`
  passed while logging `PIOs=1` for `fe80::/64`, `ff02::1/128`, `::1/128`,
  `fc00::/48`, and `2001:db8::/32`.
- `go test ./pkg/daemon -run '^TestStep0_10856_LANOverlapRepro$' -v -count=1`
  passed while logging the configured static RA PIO and same-prefix delegated
  entry together in the LAN RA config.

Then the permanent regressions were run with only production guards stashed and
tests left in place. The DHCP command
`go test ./pkg/dhcp -run 'TestExtractDelegatedPrefixes(RejectsNonGUAClasses|KeepsGlobalUnicast)10856|TestIAPDPrefixLen6531_WireBoundaryTable' -count=1`
exited non-zero: each unsafe-class subtest retained its bad prefix alongside
the good GUA, and `/1` was still accepted. The RA command
`go test ./pkg/ra -run 'TestBuildRA(RejectsDelegatedNonGUAClasses|KeepsDelegatedGlobalUnicast|RejectsDelegatedPrefixOverlappingConfiguredPIO)10856' -count=1`
exited non-zero: each unsafe class emitted a PIO and an overlapping delegated
PIO was emitted alongside the static PIO. The daemon command
`go test ./pkg/daemon -run 'TestBuildRAConfigs(RejectsConfiguredIPv6Overlap|KeepsNonOverlappingGUADelegation)10856' -count=1`
exited non-zero for interface-address, static-RA, RA-NAT64, and configured-
NAT64 overlap. All three commands pass with the guards restored.
