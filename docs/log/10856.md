# Issue #10856 — IA_PD class and scope validation (phase 2: GUA-only + configured-prefix overlap)

## Why

Phase 1 (commit ee5979797) installed a blocklist-only class check: ULA and
documentation prefixes were deliberately left accepted because no operator
pin/allowlist existed, and the RA sink had no knowledge of configured
prefixes at all. A server could therefore still place `fd00::/7`-style ULA
or `2001:db8::/32` documentation space in the live delegation set — or
delegate a prefix overlapping the box's own configured interface, static RA,
or NAT64 space — and the LAN would re-advertise it on-link + autonomous.
#12533 was filed to track the missing pin mechanism, and its filing states
the interim contract explicitly: with no pin mechanism, ULA and overlapping
delegations must be REFUSED rather than fail open.

## What

The class policy (`config.DelegatedIPv6PrefixRefusalReason`, renamed from
`...ReasonBlocklist` because the contract is no longer blocklist-only) is
now global-unicast-only:

- refuse (whole-prefix overlap, per class): link-local `fe80::/10`,
  multicast `ff00::/8`, loopback `::1/128`, unspecified `::/128`,
  IPv4-compatible `::/96`, IPv4-mapped `::ffff:0:0/96`, site-local
  `fec0::/10`, ULA `fc00::/7`, documentation `2001:db8::/32` (RFC 3849)
  and `3fff::/20` (RFC 9637);
- refuse anything whose address is not global unicast (fallback floor);
- accept ordinary GUA delegations (controls pin 2606:/2001:4860:/2002:
  acceptance so the policy cannot drift into a blanket deny).

New scope validation: an IA_PD prefix overlapping any CONFIGURED prefix is
refused at both enforcement sites. `config.ConfiguredIPv6Prefixes(cfg)`
collects the static set — interface unit addresses, static RA prefixes,
per-interface RA NAT64 (PREF64) prefixes, and NAT64 rule-set prefixes; it
deliberately excludes runtime state (leases, IA_NA addresses, delegated
prefixes) so a delegation can never collide with itself.

Enforcement:

- Decoder (`extractDelegatedPrefixes`): takes the protected set as a
  parameter; the Manager snapshot is installed by the daemon
  (`SetProtectedIPv6Prefixes`) on every config apply, BEFORE the client
  reconcile, so renewals after a config change re-validate held
  delegations. Refusals skip only the offending IAPREFIX (sibling
  salvage), never synthesize a withdrawal, and a PD-only reply whose every
  prefix is refused fails the reply (the acquire loop retries).
- RA sink (`pkg/ra` buildRA): every RA config now carries the box-wide
  protected set (`RAInterfaceConfig.ProtectedPrefixes`, stamped by
  buildRAConfigs exactly like the `Delegated` provenance bit — the compiler
  leaves it nil). The sender refuses a DELEGATED PIO overlapping it even
  when the delegation was accepted before the overlapping configuration
  appeared, so a day-2 configured prefix takes effect at the next RA, not
  at the next renewal.

The protected set is deliberately NOT part of `DHCPv6Options` or the
reconcile fingerprint: a configured-prefix change must not restart clients
or drop held leases.

### Pins deferred (#12533)

ULA and intentional-overlap delegations are legitimate in some deployments.
No pin mechanism exists (per-client pinned-prefix config, provenance through
reconcile and RA emission, exact-vs-covering match semantics, migration);
#12533 tracks that design. Until it lands, both classes are refused — the
conservative direction for an advertisement the firewall vouches for.

## Residuals

- A held delegation overlapping day-2 configured space stays in the DHCP
  manager's stored set until the server withdraws it or the client
  re-acquires; the RA sink refusal is what keeps it off the wire in the
  meantime.
- The sink overlap check consults only the daemon-populated
  ProtectedPrefixes. A sender driven by hand-built config (no daemon) gets
  the class check but no overlap check, matching its lack of box-wide
  knowledge.
- Cross-client dynamic state (another client's IA_NA address, another
  live delegation) is out of scope, as in the issue's P3-NA candidate.

## Risk

Conservative refusal is the breaking direction: a deployment that TODAY
receives and re-advertises a ULA or overlapping delegation loses it on
upgrade (refusal is logged per prefix at both sites). That is the
fail-closed interim contract #12533 was filed to scope; the pin mechanism
is the escape hatch, not a config rollback. Fixture migration touched no
production behavior: only test constants moved from documentation space to
GUA space.
