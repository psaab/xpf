# #17099 — Single-source persistent-NAT lease population with typed pool identity

- **Timestamp**: 2026-10-27
- **Action**: Replaced the four hand-spelled allocator enumerations in
  `idle_lease_sync_8121.rs` (export / display / clear / import) with one
  `Coordinator::persistent_lease_pools()` returning
  `LeasePool { id, allocator, deterministic, timeout_ns, source_rule,
  nat64_prefix, nat64_index }`, plus `lease_pool(&LeasePoolId)` for import
  resolution; promotion also iterates the same population. Added typed
  `LeasePoolId::Source(String) | Nat64 { prefix: [u8;12], mode }` carried on
  the wire as `pool_kind` (1/2/3) + `nat64_prefix` (control socket, protocol
  v76→v77, `MinProtocolPersistentNatLeaseTypedPool = 77`) and on the cluster
  sync channel as successor types 52/53 gated on
  `capFlag2PersistentNatLeaseTypedPool`; legacy records (kind 0) keep the
  string as a decode fallback for one release, resolved Source-first so a
  source pool named `nat64-deterministic-0` syncs as source. Added
  `IdleLeaseImportCounts::record` as the single outcome→count mapping.
  Made `DETERMINISTIC_NAT64_BIB_TIMEOUT_NS` `pub(crate)` and used it at the
  coordinator import arms and all `nat64_ports.rs` mint/reserve sites; the
  remaining `300_000_000_000` in `handlers/idle_leases.rs` is a test fixture.
  This also closes the #16488 round-robin population gap structurally: the
  enumerator includes round-robin NAT64 prefixes (`deterministic: None`)
  by construction, so display/clear/export/import can no longer gate them
  out (cross-reference #16488, not merged into it).
