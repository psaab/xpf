# Issue #12714 — align editor repeated-container bindings

## Why

`set` traversed the first same-key container, but the compiler now consumes repeated interface DHCP, DHCPv6-client, and forwarding-options sampling siblings in author order. A later DHCP scalar or same-name sampling instance wins, so editing only the first sibling left the effective value unchanged. Bare deletes and deactivate/activate also need to cover every binding sibling to avoid a stale later value remaining effective.

## What

- `SetPath` now uses the compiler-visible repeated sibling for interface `family inet dhcp`, `family inet6 dhcpv6-client`, and `forwarding-options sampling`. Apply-groups bodies retain first-sibling targeting, matching group expansion.
- `DeletePath` and deactivate/activate apply to every sibling for those bindings, including nested forwarding-options sampling paths such as `instance <name> input rate`, plus the existing interface filter/sampling behavior.
- Deep sampling descent now matches schema-verified elided leaves as well as braced containers. A named packed run that cannot be proven to be one statement remains untouched and reports not-found rather than silently succeeding.
- Regression tests cover effective DHCP and DHCPv6 scalar edits/deletes, sample instance replacement/creation, bare container deletion and toggles, deep sampling rate deletion/toggles across siblings, elided/braced/mixed sampling spellings, group-body targeting, and no duplicate DHCP container on set.

Round-2 fold:

- Deep repeated-sibling editing consumes compound-key tokens while resolving each child schema, so `family inet` and `family inet6` paths reach their actual descendants. DHCPv6-client prefix-delegating paths use the same braced-container descent.
- Regression coverage includes inet/inet6 flow-server deletes and deactivates, braced/elided/mixed forms, repeated sampling containers where a later elided binding wins, DHCPv6 prefix-delegating deletes/toggles, and packed-run refusal.
- DNS, ether-options, and tunnel were checked at their compiler readers and remain first-child reads; those have no compiler-last-sibling behavior to align in this change.

## Validation

- RED-first `TestEditorDeepSamplingElidedChildren12714` failed on elided-instance and elided-input cases with `path not found: no node matching "sampling instance i2 input rate"`; with elided matching disabled, the mixed-leaf case returned success while leaving effective rate 100.
- `go test ./pkg/config -run '12714|12661|RepeatedSibling|TestInterfaceFilterEditorDeleteAndDeactivate12508' -count=1` passed after the union and elided-leaf changes.

- Round-2 RED-first `TestEditorDeepSamplingFlowServer12761` failed for braced inet/inet6 and elided-output deep deletes/toggles, and exposed a surviving later winning elided sibling. `TestEditorDeepDHCPv6PrefixDelegating12761` failed for braced and mixed sibling paths.
- After the round-2 fold, `go test ./pkg/config -run '12714|12661|12508|12595|TestEditorParity' -count=1` and `go test ./pkg/configstore -count=1` passed.
- `go test ./pkg/configstore -count=1` passed. `go test ./pkg/config -count=1` timed out after 10 minutes and reported broader gate failures (#8662 inventory, #10826 API-auth expiry, #11312 routing membership, slot-escape coverage); the focused editor suites passed.

## Risk

Repeated DHCP/DHCPv6 and forwarding-options sampling edits now target the binding sibling whose values are consumed by compilation. Bare container deletes and toggles affect all repeated siblings, so no later sibling can keep a binding active after the edit. Group-body edits retain first-sibling semantics; no compiler or runtime configuration shape changed.
