# Issue #16634: unzoned bridge-domain member VLAN never created

- **Timestamp**: 2026-10-25
- **Action**: An unzoned bridge-domain member VLAN unit (the IRB layout: members L2-only, only `irb.N` zoned) was never created as a kernel device, so `br-<bd>` had no ports and the commit was strict-clean. The only VLAN creator was the zone loop (`mapZoneInterface` → `ensureVLANSubInterfaceFn`), reached only via zone refs, while `buildBridgeDomainModels` set `Bridge=br-bd0` on a `.network` row for a device nothing created. Added a bridge-member pass after the zone loop in `programZoneMaps`: `bridgeDomainMemberVLANs` enumerates explicit members with the same identity rules as `BridgeMaster` (explicit member only, VID owned by exactly that domain, tagging enabled, RETH/redundant-parent resolution), and `ensureBridgeDomainMemberVLANs` creates each child via the same seam, writes `vlan_iface_map`, and marks the written set so `DeleteStaleVlanIface` does not reap it — without zone-mapping, pendingXDP, or address reconciliation (L2 ports, not zoned surfaces). Failure semantics mirror the zoned path: LinkAdd refusal (`errVLANCreateFailed`) fails the apply; absent parent / adoption / bring-up soft-skip with an `UnarmedSurface` naming the member and bridge. Disabled interface/unit members are created down via the existing disabled argument.
- **File(s)**: `pkg/dataplane/compiler_iface.go`, `pkg/dataplane/bridge_member_vlan_16634_test.go` (new), `docs/config-schema.md`, `docs/log/16634.md` (this file)
- **Validation**: `go test ./pkg/dataplane/ -run '16634' -count=1` — defect arm (only `irb.0` zoned) and L2-only arm RED on revert (neutering the pass call), PASS with fix; control arm (member also zoned) keeps exactly one `vlan_iface_map` write; create-failure / soft-failure / absent-parent / enumeration cells pass. Full `pkg/dataplane` suite: see PR.
