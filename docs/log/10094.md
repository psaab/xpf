# #10094 — console rollback compare reads the shared candidate

## Defect

Operational `show system rollback compare N` has two accepted spellings:
`show system rollback compare N` and `show system rollback N compare`. Both
handlers call `Store.ShowCompareRollbackRedacted`, which renders a diff between
a rollback slot and the shared `CANDIDATE`. The console dispatcher priced the
entire `show` family at `PermView`, so a view-only login class could read
another session's uncommitted candidate. This is the console counterpart of
#9889's gRPC/REST `ShowCompare` pricing correction.

## Fix and scope boundary

`requiredPermission` now recognizes the two valid operational rollback-compare
shapes (including an unambiguous `system` abbreviation), validates the rollback
slot number, and returns `PermConfig` for those candidate-reading paths. The
existing `PermView` price remains for ordinary rollback listing/slot rendering,
`show version`, malformed/usage forms, and the `| display set` branch, which the
handler serves from committed rollback data before checking `compare`.

This is intentionally a single console permission price: a class with
`PermConfig` is admitted even without `PermView`, matching the REST replacement
price for a candidate-reading operation. That differs from gRPC's additive
method-table plus gate implementation because the in-process console has one
coarse command gate. Secret redaction remains unchanged; the regression cells
also verify that a configure-capable non-super-user sees the canary but not the
staged secret.

## RED -> GREEN proof

- **RED**: with the new rollback-compare gate removed, the end-to-end
  `TestDispatchOperational_ViewOnlyDeniedRollbackCompare_10094` cell served
  both spellings to read-only, operator, and config-viewer classes (`err ==
  nil` instead of permission denied) and reported the staged canary in output.
  The same failure reached the `run show ... compare` config-mode path.
- **GREEN**: `go test ./pkg/cli -run 10094 -count=1 -v` passes all five #10094
  tests. The per-class cells admit super-user, view+configure, and configure-
  only classes, reject view-only classes on both spellings, preserve legacy
  unset-class access, and keep malformed/non-compare paths at `PermView`.
  End-to-end cells prove both compare spellings are denied before output for
  view-only classes, remain served for privileged/configure classes, preserve
  redaction, and leave committed rollback/list/display-set/version shows
  served.
