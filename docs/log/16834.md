# #16834: standalone VRRP groups on disabled interfaces/units no longer run

- **Timestamp**: 2026-10-25
- **Action**: `pkg/vrrp.CollectInstances` built a VRRP instance from any
  unit's `VRRPGroups` without checking `ifc.Disable` or `unit.Disable`.
  An operator `disable` on such a unit/interface therefore left the
  group running: it claimed MASTER on the `always-down` netdev and
  installed its VIP, while #15763/#13149 had removed that VIP from every
  host-inbound drop scope (`BuildZoneHostInboundViews`,
  `BuildUnzonedHostInboundAddrs`, `BuildFenceAddrSets`, the live-snapshot
  walk) on the premise that a disabled unit owns no address. The nft
  input chain then fell through to `policy accept` for VIP-destined
  host traffic — every wildcard host service (SSH, NETCONF, HTTPS,
  SNMP) answered on the VIP regardless of the zone's
  `host-inbound-traffic` — i.e. kernel-delivered host ingress (tunnels,
  non-XDP interfaces) failed open. Fixed:
  - `pkg/vrrp/vrrp.go`: `CollectInstances` now skips a disabled
    interface and any disabled unit, exactly the gate
    `CollectRethInstances` already applies (#16590). The existing
    manager reconcile (`UpdateInstances` removal arm) then stops the
    instance and its run loop withdraws the VIPs; re-enabling
    re-collects and restores the instance. The #15763/#13149 scope
    exclusion is unchanged and is now consistent: no VIP exists to
    scope.
  - `pkg/dataplane/compiler_iface_vrrp_keep.go`: refreshed the stale
    comment claiming `CollectInstances` does not check `Disable`.
  - NOT changed: the strict VRRP validators in `pkg/config`
    (identity/VIP-count/cross-group/track-ref) still walk disabled
    groups; they are commit-time config-correctness gates, not runtime
    ownership walks, and tightening them is a separate behaviour
    decision. Display collectors (`pkg/api`, `pkg/cli`,
    `pkg/grpcapi`) go through `CollectInstances`, so `show vrrp` can no
    longer report MASTER for a disabled unit once its instance stops.
- **File(s)**: `pkg/vrrp/vrrp.go`,
  `pkg/vrrp/disabled_16834_test.go`,
  `pkg/dataplane/compiler_iface_vrrp_keep.go`, `docs/log/16834.md`
- **Tests**: `TestCollectInstancesDisabledUnit16834` (disabled unit
  yields only the enabled sibling; enabled twin collects both),
  `TestCollectInstancesDisabledInterface16834` (whole-interface disable
  yields 0; re-enable restores 2),
  `TestManagerUpdateInstancesDisabledUnitWithdraws16834` (reconcile
  stops the instance on disable and restores it on re-enable). All
  three fail pre-fix with the disabled group collected (verified by
  reverting the two `Disable` conditions). Neighbour suites:
  `pkg/vrrp`, `pkg/dataplane` full runs.
- **Residual**: the vf12 report's netns/nft probes (real-kernel MASTER
  claim and SSH SYN to the VIP) are not re-run as committed tests —
  they need unprivileged netns/nft; the collector+manager contract they
  exercised is pinned by the unit tests above. The XSK/userspace-dp
  disposition remains static reading per the report. No lab run.
