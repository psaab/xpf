# #13963 — shim-manifest hand-run could bless a stale object

The source→object guard compared a manifest regenerated from the working tree.
Because `cmd/shim-manifest` hashes the current `.o` and sources without building,
a hand-run after a source edit reset both manifest hashes around the stale object.
The next `TestUserspaceXDPShimObjectMatchesSourceManifest` passed despite the
object no longer representing the source.

## Fix

The verifier sidecar now carries a digest over the sorted shim build-input set.
`build-userspace-xdp.sh` computes that digest before compiling and passes it to
`shimverify`, which records it together with the verified candidate object hash.
Manifest regeneration copies the build digest only when both the object hash and
input digest match the verifier sidecar. The freshness test rejects a missing or
stale digest, even if `cmd/shim-manifest` rewrites the manifest. The manifest
command can print the canonical digest for the build recipe without writing the
manifest.

## Validation

- On pristine `origin/master` (`8b4d69350`), a comment-only Rust source edit
  made the freshness test fail; running `go run ./cmd/shim-manifest -repo-root .`
  then made the same test pass (`rc=0`) without rebuilding the object.
- With the fix, the same source mutation followed by the hand-run still failed
  `TestUserspaceXDPShimObjectMatchesSourceManifest` because no verifier-gated
  digest matched the changed inputs.
- The verifier-gated `make generate-userspace-xdp` completed: verifier PASS,
  669,555 processed instructions, 33.04% headroom; it wrote a matching object
  hash and build digest to the verdict sidecar and manifest.
- `go test ./cmd/shim-manifest ./cmd/shimverify -count=1` — passed.
- Focused `pkg/dataplane` manifest and recipe gate tests — passed.
- `bash -n pkg/dataplane/build-userspace-xdp.sh` — passed.
- Full `go test ./pkg/dataplane -count=1` — failed on three unrelated existing
  tests: `TestManager_PreArmMethodMatrix`,
  `TestOperatorPackagesOnlyUseDocumentedLegacyDataplaneImports`, and
  `TestOperatorPackagesDoNotImportBPFArtifactsDirectly`. The shim manifest
  gate and `TestBuildRecipeHandlesShimverifyExitCodes` passed in this full run.
- `go build ./...` — passed.
- Added `TestFreshnessGateRejectsHandRegeneratedManifest13963`, which archives
  the committed tree, mutates only a copied Rust source, hand-runs the actual
  `cmd/shim-manifest`, and executes the production freshness test in that
  hermetic copy. The wrapper succeeds only when the production gate rejects.
- The same test was run on pristine `8b4d69350` with the test file supplied:
  RED, because the production gate accepted the re-stamped stale object. It
  passes on the merged fix (`7fa0e8503`) because the gate rejects it.

## Risk

The verifier sidecar remains a build artifact rather than a signed attestation;
this closes accidental manifest laundering by a hand-run generator, not an
actor deliberately rewriting both source and verifier sidecar.
