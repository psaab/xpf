# #14707 ShowConfig/ShowCompare/ShowRollback bypass subtree restrictions — engineering history

Issue: psaab/xpf#14707 ([gemini-hostile D15-01] ShowConfig, ShowCompare, and ShowRollback bypass allow-configuration / deny-configuration subtree restrictions and path/format-scoped deny-commands). Lane branch: `fix/14707-campaign`, base `origin/master` 6a44142472.

## Defect (present at base)

`Server.ShowConfig` / `ShowCompare` / `ShowRollback` (`pkg/grpcapi/server_config.go:401,439,458`) discard ctx and render the full secret-redacted tree. The interceptor had no read arm: `authorizeRPCCommand` maps all three to the bare `"show configuration"` (`authz_command_table.go:81-83`), so `deny-commands "^show configuration security"` and `"display set"` never fire; `authorizeRPCConfigMutation` adjudicates only Set/Delete/Load/Rollback and returns nil for reads. A class with `deny-configuration "^security"` (denies `set security …` everywhere) still received the security subtree via `ShowConfig{Path:["security"]}`, the whole tree, ShowCompare and ShowRollback. Redaction masks secret values only.

Measured RED on base head (new test file, gate absent): every denied cell ALLOWED — see Validation.

Scope note: the issue names the gRPC RPCs. The same whole-tree renders exist on REST (`/config/show|export|compare|show-rollback|search`, `/config`) and the on-box CLI (config-mode `show`; operational `show configuration` charged only `*-commands`). Those share the mechanism (a config render with no `*-configuration` read adjudication), so the shared decision was wired there too rather than leaving documented twins open; regression cells stay distinct per surface.

## Fix

- New shared decision `pkg/config/authz_config_read_14707.go`:
  - `AuthorizeConfigShowPath`: `*-configuration` Evaluate on the joined path; `*-commands` EvaluateForms on `show configuration <path> [| display <fmt>]` with bare `show configuration` as alternate form (anchored bare deny covers sub-paths; path/format-scoped denies fire).
  - `AuthorizeConfigShowWhole` / `ShowCompare` / `ShowRollback`: refused for a `*-configuration`-restricted class (subtrees cannot be enumerated from the request; mirrors load-override/rollback refusal in #9892), plus the operational bare-command(+format) check. `AuthorizeConfigPathOnly` for the CLI operational arm that already charged `*-commands`.
  - Invalid regex denies; no-regex class and empty class untouched.
- gRPC: `pkg/grpcapi/authz_config_read_14707.go` decodes (path, format) per RPC, fail-closed on undecodable restricted requests; called from `authorizeRPCContext` beside the mutation gate (non-superuser only).
- REST: `pkg/api/authz_config_read_14707.go` decodes route+`?format=` (export default `set`); called from `authorizeRESTRead` after the operational gate. Covers show/export/compare/show-rollback/search and the typed `/config` render.
- CLI: `pkg/cli/permissions_config_read_14707.go` + dispatch arms — config-mode `show [path]` (edit-path-resolved, whole-candidate when bare) via the full shared decision; operational `show configuration [path]` adds the `*-configuration` arm (whole-tree refusal + per-path) without double-charging `*-commands`.

NOT changed: coarse prices (#9324/#9889 candidate pricing unchanged), secret redaction, store renderers, Complete (#14144 already consistent with this semantics), format validation (handlers still reject unknown formats; the gate never invents a form).

## Residuals

- Whole-tree refusal for `*-configuration`-restricted classes is operator-visible: such a class must request an allowed subtree (`show configuration system`). Documented in docs/system-login.md.
- `GET /api/v1/config/history` and `ListHistory` render timestamps only (no config content) — not gated beyond existing prices.
- Anchored operational deny semantics unchanged: `^show configuration$` covers sub-paths only via the bare-form widening the CLI/Complete already used; subtree denial remains the unanchored spelling, as documented.
