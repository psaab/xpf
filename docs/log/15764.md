# #15764 — userspace Proxy-ARP responder collapses aliased Junos refs

## Defect

`proxyARPResponderTargets` returned `map[string]string` (kernel netdev
-> one Junos ref), built by iterating the `byJunos` map and overwriting
`want[n] = junosRef`. Several authored refs alias one netdev — `reth0`,
`reth0.0` and its member `ge-0/0/0` all resolve via
`ResolveKernelIfName` to `ge-0-0-0` — so the many-to-one relationship
collapsed to one arbitrary winner in Go map-iteration order.

`syncProxyARPResponders` then took `addrs := byIface[junosRef]` from a
pool map keyed by the authored ref. Consequences:

- Every non-winning alias's IPv4 pool addresses were never answered
  by the userspace responder (the kernel cannot answer same-subnet
  pool addresses; see #8621), so return traffic blackholed.
- If the winner carried only IPv6 — which the kernel answers via
  proxy-NDP, so it contributes nothing to the IPv4 pool — the unioned
  `len(addrs) == 0` branch cancelled a live responder another alias
  needed for IPv4 (the Proxy-NDP pairing in the title).

Trigger legitimacy: nothing upstream rejects aliased refs; reth/member
and bare/unit-0 spellings are ordinary Junos authoring.

## Fix

- `proxyARPResponderTargets` now returns `map[string][]string`:
  every ref resolving to a netdev, sorted. Sorting makes the
  responder identity deterministic across reconciles/reasserts.
- `proxyARPPoolAddressesByInterface` now keys by
  `cfg.ResolveKernelIfName(entry.Interface)` (the Linux netdev)
  instead of `entry.Interface`, so all aliases' IPv4 addresses union
  onto the one netdev the responder socket owns. IPv6 stays excluded
  (kernel proxy-NDP owns it).
- `syncProxyARPResponders` consumes `map[string][]string`, looks the
  union up by netdev, and resolves the redundancy group from the
  smallest (deterministic) ref. Aliases of one netdev share the same
  base/parent, so they agree on the group; ownership is still read
  live per request.


Existing `map[string]string` test literals were migrated to the new
shape; no other callers exist (daemon reconcile is the sole producer).

NOT changed: `proxyARPIfaceMap` / kernel NTF_PROXY reconcile — it keys
by Junos ref with per-ref ifindexes and does not collapse aliases.

## Regression

`pkg/daemon/daemon_proxyarp_alias_15764_test.go`:

- `TestSyncProxyARPRespondersUnionsAliasedJunosRefs` (report name):
  `reth0` (v6 only) + `reth0.0` (198.51.100.10) + `ge-0/0/0`
  (198.51.100.20) all resolving to `ge-0-0-0`. A pre-seeded live
  responder must survive (not be cancelled by the v6-only alias),
  answer both v4 pool addresses, drop its stale address, claim no
  v6, report RG 1, keep the deterministic `ge-0/0/0` identity, and
  stay stable over 20 repeated reconciles.
- `TestProxyARPPoolAddressesUnionAliasedRefs15764`: pool map is
  netdev-keyed with exactly the 2 v4 addresses unioned.
- `TestProxyARPResponderTargetsCarriesAllAliases15764`: targets carry
  all 3 sorted refs on every one of 50 calls.

RED pre-fix: the old signatures do not compile against the new tests;
mechanically, the old one-winner map can return only one alias's
addresses (and, when the winner is the v6-only ref, cancels the
responder), so the union assertions fail. GREEN post-fix (see PR
Validation).

## Validation

- New alias tests + neighboring proxy-ARP responder suites
  (`8621`, `9237`, `10316` cells): pass post-fix.
- Neighboring fixtures were migrated to the netdev key
  (`ge-0-0-2.80`): pre-fix they keyed the pool by `reth0.80` and
  seeded responders under the parent netdev `ge-0-0-2`, both shapes
  the collapse relied on. The 10316 fixtures now carry a non-nil
  cancel/done, because with the corrected netdev key the sync
  reaches the cancel branch those fixtures exercise.
- Full `pkg/daemon` suite — see PR.
