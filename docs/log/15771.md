# #15771 — embedded-ICMP return fallback resolves in the default table, breaking VRF isolation

- **Issue**: #15771 (G36-03) — `embedded_icmp_return_resolution` and
  `embedded_icmp_quoted_reply_resolution` (`icmp_embed/return_resolution.rs`)
  fell back, when the companion session was absent, to
  `lookup_forwarding_resolution_with_dynamic(..)` with no table argument, i.e.
  the default `inet.0`/`inet6.0`. For a VRF flow that either leaks the error
  onto the default table's egress (overlapping prefix + default-table
  neighbor) or blackholes it, instead of resolving in the tenant table.
- **Files**: `userspace-dp/src/afxdp/icmp_embed/return_resolution.rs`,
  `userspace-dp/src/afxdp/icmp_embed/mod.rs` (tests only), `docs/log/15771.md`,
  `debian/changelog`.

## What

Both helpers now route the companion-absent fresh lookup through a new
`domain_scoped_fallback_resolution`:

1. A stamped installing table wins, via the existing session re-resolve
   classifier `resolve_install_table_for_session`
   (domain + owner check validated against the registry row): `Table` → resolve
   in that table (`lookup_forwarding_resolution_in_table_with_dynamic`);
   `Unresolvable` → fail closed (`table_unavailable_resolution`,
   `TableUnavailable`, zeroed egress) instead of probing MAIN.
2. Otherwise a nonzero native routing domain (`forward_key.routing_domain`)
   resolves through its `forwarding.install_tables` registry row (per-family
   table name); no row / no family entry → fail closed the same way.
3. Domain 0 + unstamped keeps the historical default-table lookup bit-for-bit.

The companion-present arms (forward-NAT reverse probe, session-fallback
probes, `is_reverse` cached resolution, outbound-SNAT companion preference) are
untouched.

## Validation

- `cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp return_resolution_15771`:
  new `return_resolution_15771` module in `icmp_embed/mod.rs` — tenant table
  (egress 11) vs conflicting default table (egress 99) with distinct neighbors,
  no companion installed: both helpers, v4 and v6 → egress 11; stamped
  install-table arm → egress 11; unresolvable stamp / unknown domain →
  `TableUnavailable`; domain-0 control → egress 99 (unchanged). 8 passed.
- RED check: with both helpers temporarily reverted to the table-free lookup,
  7 of 8 fail (only the domain-0 control passes); restored → 8 passed.
- Neighbouring suites on the fixed tree: `icmp_embed` 61 passed; `embedded`
  filter 198 passed + 1 failure (`stage11_local_ike_.._13637`) that also fails
  on a pristine `origin/master` worktree (pre-existing, unrelated to this
  change). The `9752` install-table/JSON golden failures (3–4, same set) also
  reproduce identically on pristine master.

## Risk

Only the companion-absent fallback changes: a VRF error that previously leaked
onto the default egress now egresses in its own instance, and one whose
instance table is gone now drops (`TableUnavailable`) instead of leaking.
Default-table deployments and companion-present resolution are bit-identical.
