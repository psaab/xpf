# #16521: notifyLinkCycle marked an unpublished deferred snapshot as helper-applied

- **Timestamp**: 2026-10-24
- **Action**: `notifyLinkCycle` called `markAppliedSnapshotLocked()`
  unconditionally after the post-link-cycle rebind. A same-plan commit
  retained by Compile's pendingXSKStartup deferral
  (`pendingFullSnapshotMetadata`, helper still on the published
  generation) that also needed a RETH MAC cycle was therefore recorded
  as applied: `appliedSnapshot`/`PolicyReadConfig` advanced and the
  policy-invalidation + capture-authority committers fired for a
  generation the helper never accepted, letting the daemon discharge
  the commit's invalidation debt early and skip the designed
  deferred-publish re-capture. Gated the mark on a new
  `helperHoldsLastSnapshotLocked()` predicate
  (`publishedSnapshot == lastSnapshot.Generation && !pending &&
  helper echoes the generation && no unknown-outcome apply/partial`),
  mirroring the status-loop catch-up; otherwise the mark is left to
  the deferred publish in `syncSnapshotLocked`. The #2079 r11
  DeferWorkers cell (published, helper echoes the generation) still
  records the generation at the rebind.
