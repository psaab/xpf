# #12622 — fail closed on unknown address-book entries

- **Action**: Preserve unknown direct address-book entries as compiler metadata. Strict compilation rejects them; tolerant loads warn, and zone-local references to dropped names stay zone-qualified and quarantined instead of falling through to same-named global entries. A zone with an unknown local book entry is unbound.

## Red before

- The issue probe's `security-zone trust address-book { ... adress-set grp ... }` parsed with no warning; the same-named global `grp` remained a valid fallback. Strict compilation rejected the policy only indirectly because its lost local intent became an unresolved reference.
- The focused regression command failed before implementation: the lenient compilation had no `adress-set` warning and did not quarantine the intended local name.

## Change

- `parseAddressBookEntries` records unknown book-level keywords and their first name token, while preserving apply-meta statements as ignored metadata.
- Unknown names are quarantined in `CollidingNames`; zone-local unknown names participate in local-first rewrite and are folded under a qualified collision key. Unknown direct entries make the local zone unbound.
- The existing address-set-member strict gate also rejects unknown address-book entry metadata and downgrades it to `cfg.Warnings` on lenient compilation. Configstore `SyncApply` coverage proves the warning survives tolerant ingress.
- Updated `pkg/config/README.md` with the strict/tolerant and fail-closed behavior.

## Validation

- Focused regressions passed: `go test ./pkg/config -run 'Test(ZoneLocalTypo|GlobalTypo|ValidBooksNoUnknown|UnknownAddressBookEntryStrictDiagnostic)' -count=1` and `go test ./pkg/configstore -run TestSyncApplyWarnsOnUnknownZoneAddressBookEntry12622 -count=1`.
- `go build ./...`, `go vet ./pkg/config ./pkg/configstore`, and `gofmt` checks for changed Go files passed.
- Full `go test ./pkg/config ./pkg/configstore -count=1` did not pass: configstore passed; pkg/config reported failures in `TestInventoryDropShapeMatchesTheLiveCensus8662`, `TestMultiLeafSelfRepeatIsRefused9027`, `TestLegitimatelyNamedObjectIsAccepted9029`, `TestElidedQuotedValueKeepsItsQuote8921`, `TestSystemConfigWebManagementEnhanced`, `TestSystemConfigSetSyntax`, `TestPackedRoutingInstanceSurvives8787`, and `TestSlotEscapeCoverage`, then timed out in `TestSchemaSpellingDifferentialGate`. The focused issue tests passed separately; no baseline comparison was performed for the broader failures.

## Residual / risk

- Tolerant loads keep the node bootable, but a zone containing an unknown direct address-book entry loses its interface bindings. This deliberately favors fail-closed policy intent over preserving potentially unsafe zone service.
