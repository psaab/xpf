# #11329: exclude positional policy IDs from extensive rematch fingerprints

- **Timestamp**: 2026-09-30T13:26Z
  - **Action**: Stop treating positional `PolicyID` shifts as semantic policy changes while retaining extensive detection of resolved-content changes.
- **File(s)**: `pkg/dataplane/userspace/policies_resolved_fingerprint.go`, `pkg/daemon/daemon_policy_rematch_stable_fingerprint_11329_test.go`, `pkg/daemon/policy_rematch_added_deny_9573_test.go`, `docs/log/9386.md`, `docs/log/9573.md`, `docs/log/11329.md`.

## Change

`PolicyResolvedFingerprints` now omits positional `PolicyID` from each resolved rule before hashing. The stable policy key and all resolved match/action content remain in the fingerprint. Insertions, deletions, reorders, or earlier zone-pair-set additions therefore do not sweep unchanged surviving policies solely because their runtime IDs shifted. Real resolved changes remain covered by the existing #8993 regressions.

The #9573 added-deny table is updated: extensive rematch no longer clears the unchanged permit just because an inserted deny changes its positional ID. The historical #9386 and #9573 records point to this decision.
