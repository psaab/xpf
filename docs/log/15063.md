# #15063 — `client-ia-type` keeps only one IA in the flat and bracketed spellings (A01-02)

## Defect

`interfaces <if> unit <n> family inet6 dhcpv6-client client-ia-type`
was declared in `pkg/config/schema_interfaces.go` as `args: 1` without
`multi: true`, and `compileInterfaces`
(`pkg/config/compiler_interfaces.go`) read it with `nodeVal(prop)`
(only `Keys[1]`, or the first child's name).

Per the #2419 dual-shape contract (see `docs/config-schema.md`), a
non-multi leaf files a bracket/flat tail under ONE child whose Keys
hold every value, while a multi leaf absorbs the tail onto its own
Keys. With no `multi`, every spelling except hierarchical repeated
statements kept only the first IA:

- hierarchical bracket `client-ia-type [ ia-na ia-pd ];` → `[ia-na]`
- hierarchical block `client-ia-type { ia-na; ia-pd; }` → `[ia-na]`
- flat bracket `set … client-ia-type [ ia-na ia-pd ]` → `[ia-na]`
- flat packed tail `set … client-ia-type ia-na ia-pd` → `[ia-na]`
- flat repeated `set … client-ia-type ia-na` + `… ia-pd` → `[ia-pd]`
  (the second SetPath replaced the first — last-writer-wins on a
  non-multi leaf)

`pkg/dhcp/dhcpv6.go` gates IA_NA and IA_PD on the non-empty
`ClientIATypes` list, so the surviving single IA silently dropped
either the WAN IPv6 address (IA_NA) or the delegated LAN prefix
(IA_PD). `show | display set` restores triggered it too: the renderer
emits one flat line per IA, and replaying them collapsed to the last
line. Hierarchical repeated statements already accumulated (two
sibling nodes), which is why brace-authored tests stayed green.

## Fix

- `pkg/config/schema_interfaces.go`: mark `client-ia-type`
  `multi: true` (same `args: 1, children: nil` shape as sibling
  multi leaves). This makes SetPath absorb bracket/flat tails onto
  the leaf's own Keys and keep repeated flat lines as sibling
  leaves, and makes apply-groups treat the leaf as a leaf-list
  (union) rather than an override — the correct Junos semantics
  for an IA-type list.
- `pkg/config/compiler_interfaces.go`: read the leaf with
  `firewallMatchValues(prop)` — every value across `Keys[1:]` and
  every key of each child node — and append all of them to
  `ClientIATypes`, instead of `nodeVal`'s first value only. Empty
  tokens are skipped by that reader (a bare `client-ia-type;`
  still compiles to no IA types, as before).

NOT changed: `req-option` (same `nodeVal` shape one case below) —
outside the cited A01-02 mechanism; `pkg/dhcp` gating — it already
consumes the full list correctly once the compiler supplies it.

## Regression (`pkg/config/client_ia_type_multi_15063_test.go`)

## Risk

Behaviour changes only for configs authoring more than one
`client-ia-type` value in a bracket, block, flat or repeated
spelling — those now compile both IAs instead of silently keeping
one. Single-IA and hierarchical-repeated configs compile
byte-identically. Making the leaf a leaf-list also means
apply-groups now unions group + inline IA types instead of
overriding; that matches Junos leaf-list inheritance and the
compiled-list semantics the DHCP client already expects.
