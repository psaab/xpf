# #9669 — xpf-deploy: virsh and virt-install pass no connection URI while the disk paths are hard-wired to system-scope libvirt

- **Timestamp**: 2026-09-10
  - **Action**: Decision on the issue's three options: probe BOTH URIs for
    presence, and tear down through the URI that holds the domain. Deploy
    names the system URI.
    - Refusing non-root outright would break every operator deploying into
      the session URI today.
    - Recording each domain's URI would add state that a manual `virsh define`
      or an older deploy never wrote.
    - Probing both URIs is stateless, and it satisfies the acceptance
      directly: teardown never reads a domain as absent from a URI it was
      not defined in.
  - **Action**: scripts/deploy/xpf-deploy.py.
    - `LIBVIRT_SYSTEM_URI` / `LIBVIRT_SESSION_URI` / `LIBVIRT_PROBE_URIS`.
    - `_virsh_domain_state_at(name, uri)` is the unchanged #8977/#9325
      three-state probe, now with `virsh -c <uri> dominfo`.
    - `_virsh_domain_locate(name)` returns PRESENT with every URI that holds
      the domain. Otherwise it returns UNKNOWN if any URI could not answer,
      since an unreachable URI might hold it. Otherwise ABSENT.
      `_virsh_domain_state` is its state.
    - `_virsh_teardown_domain(name, uris)` runs destroy + undefine
      (`--nvram`, then plain) at each URI holding the domain.
      `destroy_libvirt` and `_cleanup_libvirt` both use it, and both still
      remove disks only on an affirmative ABSENT, which now means ABSENT at
      both URIs.
    - `virt-install --connect qemu:///system`, and
      `virsh -c qemu:///system define`, in live and dry-run modes.
    - The refusal text names both URIs.
  - **Action**: docs/deploy-quickstart.md names the URI the tool uses, the
    both-URI teardown rule, and `virsh -c qemu:///system edit/start`.
  - **Action**: Existing cells updated to the new argv shape, keeping what

    - test_xpf_deploy_robustness: `virsh define` must be

  - **Action**: New cells in scripts/deploy/test_xpf_deploy_libvirt_uri_9669.py.
