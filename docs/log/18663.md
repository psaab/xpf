# #18663: bound shared node-served evidence lookup work

- **Timestamp**: 2026-11-07
- **Root cause**: `shared_node_served_evidence` scanned all `shared_sessions` rows under the shared-map lock whenever the direct/reverse keys were not Established. Housekeeping can call it for each expiry candidate, making this O(candidates × table size). The reverse-row NAT alias could not be derived from the query without the primary row's NAT decision.
- **Fix**:
  - Added `SharedServedAliasIndex`, a keyed alias → owner-set index attached to `SharedSessionOwnerRgIndexes`. Alias keys use the same domain-neutral reverse-match tuple used for shared NAT lookup. A single owner resolves; collisions retain all owners and fail closed rather than trusting the last-writer survivor.
  - Publish/replacement updates the primary row and alias-owner set under the existing `shared_sessions` lock; removal removes alias claims under that same lock; clear clears the index with the primary map. The mutation census is `publish_shared_session`, `remove_shared_session_if`, and `SharedSessionOwnerRgIndexes::clear`; the remaining primary-map writes are restamps of existing rows, not key publication/removal. NAT/forward alias displacement does not displace primary owner claims.
  - Evidence probes the direct key, no-NAT reverse key, then the maintained alias index. It re-reads the resolved primary by key and validates the exact alias and Established state while still holding the primary lock. This prevents stale removed/replaced owners from vouching and prevents a primary/alias publication gap. Ambiguous aliases fail closed in either publication order.
  - Removed the pass-local full-map snapshot/`OnceCell` index. Query work is bounded keyed gets; no evidence scan is performed. Index maintenance adds no per-packet allocation or work: it runs on shared-session publish/replacement, remove, and clear (expiry-adjacent bookkeeping), not packet handling. There is no new pass-wide primary-lock hold; updates reuse the existing publish/remove lock interval.
