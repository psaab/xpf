# #18663: bound shared node-served evidence lookup work

- **Timestamp**: 2026-11-07
- **Root cause**: `shared_node_served_evidence` fell back to scanning every `shared_sessions` value under the shared-map mutex for non-Established or absent keys. Housekeeping can call it for each idle-crossed HA expiry candidate, multiplying that O(table size) scan by the candidate count. Reverse-row NAT aliases are not represented in `shared_nat_sessions`, which indexes forward rows.
- **Fix**:
  - Keep direct primary-key and derived no-NAT reverse-key probes; use the existing keyed `shared_nat_sessions` alias for forward-row NAT reverse tuples, then re-read and validate the live primary row.
  - For the remaining reverse-row NAT alias class, lazily build a pass-local index once on the first unmatched candidate. Snapshot compact map key / entry key / NAT tuples in one primary-map iteration; release the mutex before deriving aliases and allocating/hashing the index. This is O(N + candidates), rather than O(N × candidates).
  - Re-read an indexed reverse row from the primary map and verify it is still reverse, Established, and maps to the exact alias. Removed or replaced primary rows fail closed. Alias collisions among reverse rows fail closed; a successful forward-row NAT alias retains precedence over a colliding reverse-row alias.
  - The index is stack-scoped to `run_session_housekeeping`; it does not change the packet hot path or add per-packet allocation.
