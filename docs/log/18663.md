# #18663: bound shared node-served evidence lookup work

- **Timestamp**: 2026-11-07
- **Root cause**: `shared_node_served_evidence` scanned all `shared_sessions` rows under the shared-map lock whenever the direct/reverse keys were not Established. Housekeeping can call it for each expiry candidate, making this O(candidates × table size). The reverse-row NAT alias could not be derived from the query without the primary row's NAT decision; additionally, a reverse NAT row filed only its NAT-derived canonical forward tuple F, not its plain-reverse forward-wire alias W, so an Opening promoted W could miss Established R while F/R were restamped.
- **Fix**:
  - Added `SharedServedAliasIndex`, a keyed alias → owner-set index attached to `SharedSessionOwnerRgIndexes`. Alias keys are owner-domain-scoped; the generic reverse-canonical key is domain-neutral and cannot safely scope served evidence. Ambiguous alias keys retain all owners and fail closed rather than trusting the last-writer survivor.
  - Publish/replacement updates the primary row and alias-owner set under the existing `shared_sessions` lock; removal removes alias claims under that same lock; clear clears the index with the primary map. The mutation census is `publish_shared_session`, `remove_shared_session_if`, and `SharedSessionOwnerRgIndexes::clear`; remaining primary-map writes are restamps of existing rows, not key publication/removal. NAT/forward alias displacement does not displace primary owner claims.
  - Evidence probes the direct key, no-NAT reverse key, then the maintained alias index. The plain-reverse path also requires a unique alias owner, so NAT/no-NAT collisions fail closed in either publication order; an exact direct primary hit remains authoritative. It re-reads the resolved primary by key and validates liveness, owner-domain scope, exact alias, and Established state while holding the primary lock. This prevents stale removed/replaced owners from vouching and prevents a primary/alias publication gap.
  - Stored alias owners use `SmallVec<[SessionKey; 1]>`: singleton retrieval is direct indexed access, not iteration over retained hash-set capacity. Collision insertion/removal is publish/remove bookkeeping, and a one-owner bucket remains O(1) to query after shrinking.
  - Removed the pass-local full-map snapshot/`OnceCell` index. Query work is bounded keyed gets; no evidence scan is performed. Index maintenance adds no per-packet allocation or work: it runs on shared-session publish/replacement (new-flow slow path or HA republish), remove, and clear, not packet-fast-path handling. There is no new pass-wide primary-lock hold; updates reuse the existing publish/remove lock interval.
- **Cells** (`userspace-dp/src/afxdp/tests_idle_served_keepalive_18722.rs`): direct, reverse, and NAT-alias evidence; publication serialization (alias cannot be observed between primary insert and index update); late publish after prior miss; reverse-only Established NAT alias; promoted Opening W coexisting with canonical F/R then F/R advancing to Established while W remains Opening and is vouched via R; forward/forward NAT collisions with both Established and Opening displacers in both publish orders; NAT/no-NAT ambiguity in both orders with exact-primary exemption; removed-primary no-vouch; owner-domain isolation with a nonzero same-domain positive control; 64k-table keyed-work bounds; and collision-bucket growth to 512 owners then shrink to one while retaining capacity, with one-owner retrieval bounded to four keyed-work units.
