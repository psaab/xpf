# Issue #10136 — Routing-instance separation wire gate

## Implementation

This branch adds the `wire_routing_separation` gate and adapter, with a hermetic
`--selftest`/`--fixture` path and a live path guarded by the cluster lock. The
live path snapshots the complete normalized configuration on both firewall
nodes, provisions an owned temporary `routing-instances wire-10136` stanza
through the CLI/xpfd manager, waits for the manager-created `vrf-wire-10136`
and pref-2000 l3mdev terminator, runs the same-source/port control and probe
window, then removes the veth/namespace and commits the owned RI deletion.

The Makefile wraps the complete `harness-result.sh run` invocation in
`with-cluster.sh`, including binary attestation. The live row is intentionally
not claimed as measured in this branch: the shared lab is blocked by #10342.

## Live evidence and block

Two live preflight attempts refused the unsafe baseline before any temporary
configuration mutation because the DUT had configured routing instances but no
pref-2000 l3mdev terminator. Their complete config archives are:

- `/var/tmp/xpf-wire-routing-separation-1789729350` (env-VOID)
- `/var/tmp/xpf-wire-routing-separation-1789729374` (env-VOID)

The retained `/var/tmp/xpf-wire-routing-separation-1789729308` archive is
from the earlier broken-fixture/harness attempt, before the env-preflight
diagnostics, and is not counted as an env-VOID.

Each env-VOID and the owned attempt recorded the same normalized fw0 pre/post
SHA:

`f40e51f2208fa6e70070e58475501bfc504a108ee04dffd7e415b113baf09d91`

The owned-config diagnostic attempt used archive
`/var/tmp/xpf-wire-routing-separation-1789729613`. It proved the managed
fixture and fault landing: `vrf-wire-10136` was created with table `210564`,
pref-2000 was present, the clean lookup was unreachable, and the injected
fault lookup fell through `ge-0-0-2.80`. The capture measured
`probe=1000`, `control=1500`, `probe_observed=1000`, and
`control_observed=1500`; this is diagnostic evidence only, not a valid FAIL
row.

The finalizer correctly emitted `harness-void` because deleting the temporary
RI could not restore the pre-run kernel rule snapshot. The pre-run config
already declared `sfmix` as a virtual-router, but its manager state lacked
pref-2000. Creating the temporary RI caused xpfd to self-heal the desired
pref-2000 rule; deleting only the temporary RI therefore left the manager-owned
`vrf-sfmix` and pref-2000 present. A locked post-check confirmed:

- `2000: from all lookup [l3mdev-table] unreachable`
- `vrf-sfmix` present
- normalized fw0 pre/post config SHA unchanged as above

No direct `ip rule` repair was performed and no invalid live ledger rows are
retained.
