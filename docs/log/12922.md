# Issue #12922 — show schedulers omits exclude/all-day detail

## Why

`show schedulers` printed only start/stop bounds and `Recurrence: daily`
(pkg/api/show_text.go, pkg/cli/cli_show_services.go, and the same private
copy in pkg/grpcapi/server_show_security_text.go). The compiled scheduler
carries three recurrence details that decide whether the shown window ever
applies — `daily exclude` (the window is NEVER active; #12822), `daily
all-day` (active around the clock), and per-weekday override arms (a
`monday exclude` or `sunday all-day` that overrides the daily window for
that day) — and none of them rendered. A daily-exclude scheduler was
indistinguishable from an ordinary active window, so an operator auditing a
time-gated policy could not see that the displayed window never applies.

The three surfaces had also drifted apart: the REST handler iterated sorted
keys and tolerated nil slots, the gRPC handler iterated the map unsorted
but tolerated nil slots, and the CLI iterated unsorted and would panic on a
nil slot.

## What

- Added `scheduler.FormatSchedulers` (pkg/scheduler/format.go), the single
  renderer for the `show schedulers` table, shared by the REST show-text
  handler, the local CLI, and the gRPC ShowText surface so they cannot
  drift again (same pattern as the shared ipmon/appid/natshow formatters).
- The per-scheduler block now renders the recurrence qualifiers in
  evaluator precedence order (`Recurrence: daily exclude`, `daily all-day`,
  or both when a restored config carries both), then one line per
  per-weekday override arm in monday..sunday order — `exclude`, `all-day`,
  or the arm's time bounds. A qualifier-less arm renders `closed`, matching
  the fail-closed runtime verdict (#3849). Bounds-only lines are unchanged.
- The renderer iterates scheduler names sorted, skips present-but-nil map
  slots (#10439/#12903 class), and handles nil configs.

## Validation

- RED on pristine master (surface tests copied onto a detached origin/master
  worktree): `TestShowTextSchedulerRecurrenceDetail12922`,
  `TestShowSchedulersRendersRecurrenceDetail12922`, and
  `TestCLIShowSchedulersRecurrenceDetail12922` each failed with "daily
  exclude qualifier missing — the excluded window still looks active".
- GREEN post-fix: `go test ./pkg/scheduler -run 12922 -count=1`,
  `go test ./pkg/api -run Scheduler -count=1`,
  `go test ./pkg/grpcapi -run '12922|Scheduler' -count=1`, and
  `go test ./pkg/cli -run '12922|Scheduler' -count=1` all passed.
- Full `./pkg/scheduler`, `./pkg/api`, `./pkg/cli`, `./pkg/grpcapi`
  package suites and `go vet` on the changed packages passed.
- `gofmt -l` on all changed Go files produced no output.

## Risk

Display-only: no compiler, evaluator, or dataplane behavior changed. The
CLI output ordering becomes deterministic (sorted) and the CLI no longer
panics on a present-but-nil scheduler slot — both strict improvements over
the private copy it replaced. Automation that parsed the old text keeps
working for ordinary daily windows; the added lines are new detail that was
previously invisible.
