# Issue #12255 — Cached-neighbor fallback on session miss

- **Base**: `83b5c9553`.
- **Action**: Preserve a cached `ForwardCandidate` on an absent-neighbor lookup only for a locally observed `ForwardFlow` session with a valid current forwarding-generation stamp and an unchanged neighbor shard epoch. Keep peer-synced and reverse matches strict on absence, reject stale generations after static/snapshot neighbor removal, reject runtime removals after an epoch advance, and explicitly deny connected IPv4 directed broadcasts before interpreting `None` as an unseen miss.
- **Safety regressions**: Cover static neighbor removal through forwarding-generation change, never-locally-observed peer-synced state, connected directed-broadcast deny with no live entries, and the deny masking static and dynamic entries with different MACs. Also retain reverse-match strictness and runtime shard-epoch removal coverage.
- **RED evidence**: GLM R1 reproduced stale cached forwarding at the original PR head for static removal, peer-synced absence, and connected directed-broadcast denial, including the deny-only and masked-live variants. Reverting the epoch-only gate made the safety probes fail; the #12255 cell failed on base with `MissingNeighbor` vs `ForwardCandidate`.
