## Why

The frame generic NAT path and cached rewrite-descriptor path had separate checksum-delta logic and NPTv6 decisions. A pure single-sided NPTv6 address rewrite is checksum-neutral, but when NPTv6 composes with DNAT the non-neutral DNAT address delta must still be folded. The rewrite property tests also built descriptors independently instead of using the production descriptor constructor, leaving parity vulnerable to fixture drift.

## What

- Moved NAT checksum-delta calculation to `frame/checksum.rs`, reusing the frame's IPv4/IPv6 word helpers and one RFC 1624 word-delta helper. Added `nat_folds_l4_checksum` as the shared predicate: pure single-sided NPTv6 skips the address delta; a two-address NPTv6+DNAT decision folds it.
- Routed IPv6 generic NAT's single-source, single-destination, and composed-address arms through that shared rule while retaining the non-first-fragment skip. `RewriteDescriptor::from_decision` now supplies the production flow-cache descriptor and test descriptors; removed the old duplicate checksum module and migrated its consumers.
- Added 13 named deterministic parity cells covering no NAT, IPv4 and IPv6 rewrite shapes, ports, pure NPTv6 in both directions, NPTv6+DNAT in both directions, and an NPTv6 flag without rewrites. The cells compare descriptor and generic outputs against a checksum oracle. Updated the four stale NPTv6 comments and clarified why random arbitrary-address generators do not mark NPTv6.

## Risk

The intended behavior is to make generic and cached descriptor paths use the same folding rule: pure single-sided NPTv6 remains checksum-neutral, while composed NPTv6+DNAT includes the DNAT delta. Existing non-first-fragment handling and IPv4/UDP checksum behavior remain on their existing paths. The change adds no wire-format or session-key changes; no performance measurement was run.
