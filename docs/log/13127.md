# Normalize SNMP VRF trap targets and synchronize device reads (#13127)

- **Issue**: #13127, source finding D10-10 (deep-review; validated by the three-way research gate).
- **Cause**: VRF trap send and v1 `agent-addr` independently split target addresses, then `JoinHostPort` a bracketed IPv6 host that already included brackets when `SplitHostPort` failed. Those targets became `[[::1]]:162` and every send/lookup failed. A target with a trailing colon split successfully with an empty port, bypassing the default and dialing port zero. `SetVRFDevice` also wrote `Agent.vrfDevice` without synchronization while trap and v1 address workers read it.
- **Change**: Both outgoing paths now share `normalizeTrapDialAddr`, which strips one valid outer bracket pair on the no-port path and defaults both missing and empty ports to 162. `SetVRFDevice` and a new locked accessor synchronize all agent-owned VRF reads, including bind, trap emission, and v1 `agent-addr` construction. No changes to target validation or other address forms.
- **Regression coverage** (`pkg/snmp/trap_target_normalize_13127_test.go`): brackets/port normalization table (including trailing colon), delivery to a real IPv6 UDP receiver on `[::1]:162` using bracketed and unbracketed spellings, bracketed IPv4-mapped v1 source lookup against a successful control, and concurrent setter/trap-reader access for race detection.
- **RED evidence**: On pristine `origin/master` at `55ab81ef0` with only the regression tests added, privileged `go test ./pkg/snmp -run 'Test(SendTrapOnVRFBracketedIPv6Delivers13127|AgentAddrForBracketedIPv4MappedTarget13127)$' -count=1 -v` failed: sender dialed `[[::1]]:162` with `missing port in address`; bracketed v1 lookup returned `0.0.0.0` instead of `127.0.0.1`. The non-privileged run failed the v1 assertion and skipped the receiver test because binding port 162 is denied.
