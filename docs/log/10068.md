# #10068 — IPv6 parity cells, close-gap pin, and purge-marker sink seam

Branch `fix/10068-cells`, based on the current master checkout. Issue #10068 had no comments.

## Scope

This change adds fail-on-revert cells for the five issue items:

1. The event-stream close frame's pre-existing GW-4 close-carry gap is pinned as a
   documented KNOWN-GAP for both address families. No event-stream layout change
   is made here.
2. The Rust close codec and Go close decoder now have v6 purge-retirement marker
   parity cells.
3. The v6 forward-only delete wire, incapable-peer suppression, and journal
   marker cells mirror the three v4 #9752 cells.
4. The v6 install-table resend coverage follows the current production shape:
   receive-memo restoration for a stamp-less old-sender resend over a lossy
   mirror, plus a sweep resend retaining the announced identity.
5. `PurgeRetirementOnly` is one pure cluster-owned predicate used by all four
   daemon delta-sink delete paths, with a direct seam cell.

The v4 install-table keep-rule tests named in the issue were intentionally
removed in #9752 round 3. This patch does not resurrect that dead-store
behavior; the v6 cells mirror the receive memo and sweep behavior that exists
in production now.

and a 60-byte payload, the Go decoder asserts `AFInet6` and 16-byte addresses,
and delete/install cells use v6 keys and v6 wire encoders. Their fixed-size
assertions would fail if the implementation silently routed through a v4 path.

## GW-4 disposition

`docs/log/9752.md` §Fold-2.1, Table 1 GW-4 records this as a pre-existing
close-carry gap on master, independent of #9752. On the event-stream binary
leg, open/update frames carry the install-table identity, while the close
frame ends at routing domain plus purge marker. The cell pins 36-byte v4 and
60-byte v6 close payloads and requires the marker to remain the final byte.
The owning layout change is outside #10068; this patch deliberately does not
make a partial layout fix.
