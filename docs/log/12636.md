# Issue #12636 — reject weekdays packed onto the scheduler line

## Why

A hierarchical `scheduler S monday { ... }` places `monday` on the named scheduler node instead of inside its property children. `compileSchedulers` reads scheduler properties from those children, so it ignores that token. The correctly spelled weekday was silently dropped; a typo such as `modnay` was also outside the schema's closed-world child walk. With no compiled day override, the intended Monday-only schedule widened to the daily window.

## What

Strict schema validation now rejects any value token after the scheduler name, with an error directing the operator to place weekday windows inside the scheduler block. Rejecting this input shape matches the existing child-property Junos grammar and avoids introducing a second weekday parser/compiler path. Canonical `scheduler S { monday { ... } }` windows continue to compile as before. Flat-set weekday runs remain unchanged.

## Validation

- **RED without the new node validator**: `go test ./pkg/config -run '^TestScheduler(RejectsWeekdayPackedOnSchedulerLine12636|WeekdayInsideBlockRemainsAccepted12636)$' -count=1` failed as intended: strict validation accepted both packed `monday` and `modnay`.
- **GREEN with the validator restored**: the same targeted command passed (`pkg/config`, 0.032s). It pins both packed rejects and canonical braced Monday-window acceptance/compilation.
- **Full config package**: `go test ./pkg/config -count=1 -timeout 45m` failed after its 45-minute timeout. It reported unrelated failures in inventory shape (#8662), API-auth expiry (#10826), packed routing-instance behavior (#11312), and slot-escape/spelling coverage, then timed out in `TestSchemaSpellingDifferentialGate`. The new targeted scheduler tests passed separately.

## Risk

Strict validation now refuses scheduler lines with extra tokens after the name. Existing persisted configuration remains subject to the existing tolerant load path; no compiler/runtime behavior changed for accepted scheduler shapes.
