# #10177 — feed fetcher private/link-local destination guard

- **Issue**: [#10177](https://github.com/psaab/xpf/issues/10177)
- **Follow-up context**: #9912 / merged PR #10175
- **Branch**: `fix/10177-ssrf`

## Finding and boundary

PR #10175 already prevents cross-origin redirects and disables ambient HTTP(S)
proxy variables. The remaining blind-SSRF path was a directly configured feed
URL or a same-hostname URL whose resolver answer changed to loopback, RFC1918,
link-local, or cloud-metadata space. `pkg/feeds` has no metrics registry: the
existing redirect refusal remains WARN + `lastError`/stale state; no standalone
redirect-refusal counter was added because there is no registry to register it
against (the issue explicitly scopes that counter only if a registry lands in
this package).

## Change

- `Manager.readFeed` resolves the destination hostname once with
  `LookupNetIP`, validates every answer, and refuses loopback, RFC1918,
  RFC4193/ULA, link-local, unspecified, non-global, CGNAT/metadata, IETF
  special-purpose, and benchmarking ranges by default.
- The request retains its original hostname for HTTP `Host` and TLS SNI, but
  the cloned transport's `DialContext` uses only the validated address set.
  No transport operation re-resolves the hostname after validation, closing the
  resolve/check/dial TOCTOU window.
- Resolution and fetch share the 30-second per-fetch context deadline, and
  each cloned transport closes idle connections after the response body is
  consumed, preserving the existing timeout/lifecycle contract.
- `Manager.SetPrivateFeedAllowlist([]netip.Prefix)` is an explicit global lab
  override. It masks and stores only valid prefixes; an empty slice restores
  default deny. The production `New` signature remains unchanged and its
  default manager has no private-destination allowlist.
- Existing loopback `httptest` fixtures opt in through the setter; the security
  regressions use a fresh default manager so fixtures cannot accidentally
  weaken the default policy.
