# #17855 — Fold syslog Close discards into retired drop totals

- **Timestamp**: 2026-10-26
  - **Action**: Retired syslog clients' exported drop totals now
    include the records their `Close` discards. `retire()` still
    snapshots pre-Close counts (Close is what stops the writer and
    counts the discarded queue into `DroppedWrites`); the owner now
    also records the retired client in a `retiredPending` set, and the
    next `SyslogDropStats` folds the post-retire counter growth (the
    Close discards) into the accumulator exactly once before composing
    the snapshot. Applied to both owners: the slog handler ("system",
    `slog_handler.go` — SetClients/SetClientsPreserving/Close/
    ShutdownTimeout) and the EventReader ("security", `ringbuf.go` —
    SetSyslogClients/ReplaceSyslogClients). Stats calls now take the
    write lock so the fold happens exactly once under concurrency.
  - **File(s)**: `pkg/logging/ringbuf.go`, `pkg/logging/slog_handler.go`,
    `pkg/logging/syslog_drop_stats_9165.go`,
    `pkg/logging/syslog_retired_close_drops_17855_test.go`,
    `docs/log/17855.md`.
  - **Validation**: Five regression cells (SetClients,
    SetClientsPreserving, handler Close, ShutdownTimeout,
    ReplaceSyslogClients) FAIL pre-fix ("no system row"/lost discards)
    and PASS post-fix; `-count=3` stable. `go test ./pkg/logging/
    -count=1` ok; `go vet` clean.
  - **Risk**: `SyslogDropStats` upgrades RLock→Lock (stats are
    scrape-frequency, not hot path). A stats call racing an in-flight
    Close folds only what Close has counted so far and clears the
    pending entry; in the handler lifecycle Close completes before
    subsequent stats calls, and counters stay monotonic regardless.
