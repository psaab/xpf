# Issue #13173: preserve match-any semantics in lo0 address scopes

## Why

The netlink lo0 builder and nft text oracle removed `any` before deciding what
an empty family-filtered set meant. A positive `any` scope consequently became
match-nothing and could suppress a `discard`/`reject` term. `any except` became
an empty exclusion and therefore match-all, opposite to the configured scope.
Family-default prefixes (`0.0.0.0/0` and `::/0`) also need the same full-family
semantics when lowered for their matching family.

## What

`lo0AddrScope` and `nftAddrPredicate` now recognize a full-family token before
applying empty-set semantics. Positive full-family scopes need no address
predicate; excluding the full family skips the term. Wrong-family prefixes
remain filtered and malformed tokens preserve the #6512 fail-closed behavior.
Regression tests cover both families, `any`, family-specific `/0`, mixed sets,
wrong-family tokens, and both the netlink plan and text oracle. Updated the lo0
address-lowering contract in `pkg/daemon/README.md`.

## Risk

This changes only constrained lo0 address-term lowering for match-any values;
ordinary specific prefixes, empty scopes, wrong-family filtering, and malformed
address refusal retain their prior dispositions.
