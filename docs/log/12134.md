# Issue #12134: Bound inherited RA lifetimes

- **Timestamp**: 2026-10-08
- **Action**: `buildRA` clamps Router Lifetime once before deriving inherited
  RDNSS/PREF64 lifetimes. The header and RDNSS use that bounded source;
  inherited PREF64 saturates at RFC 8781's 65528-second maximum and warns once
  per sender. The sender helper comment points to the surviving README rationale.
  The README and embedded-radvd docs describe the shared source and 65535/65528
  caps; both schema value descriptions explain the 65528 cap and 1800-second
  fallback when Router Lifetime is 0. Explicit PREF64 lifetimes retain the
  existing schema/prune defense.
- **Regression**: `TestBuildRA_12134_InheritedLifetimesAreBounded` decodes
  Router Lifetime, RDNSS, and PREF64 from the wire for explicit router
  lifetime 0 (expecting 0/1800/1800 with no warning), 65532–65535, and
  tolerant-ingress `2^32`; it verifies PREF64 saturation and warn-once behavior.

## RED -> GREEN proof

- **STEP-0 / ALREADY-FIXED gate**: On base `83b5c9553`, the throwaway marshal
  repro retained PREF64 at 65528 and 65531, but `buildRA` pruned it at 65532,
  65533, 65534, and 65535 with `ndp: pref64 scaled lifetime is too large`;
  RDNSS remained. The defect was present on the pinned base.
- **RED**: Before the sender/schema change, the targeted
  `TestBuildRA_12134_InheritedLifetimesAreBounded` failed: PREF64 was missing
  for 65532–65535; at `2^32`, RDNSS wrapped to 0 and PREF64 decoded as 0, with
  no saturation warning.
- **GREEN**: The test passes with the bounded source, PREF64 at 65528, and
  exactly one warning per sender despite repeated builds.
- **M8 RED -> GREEN**: In an isolated scratch tree with the lifetime-0 row,
  replacing RDNSS's `optLifetime` with the raw `lifetime` made the targeted
  test fail only on `lifetime_0`: wire RDNSS was 0, expected 1800. Restoring
  `optLifetime` made the same targeted test pass.
- **Scoped suites**: `go test ./pkg/ra/... -count=1` passed (16.321s).

  passed all four cases (0.008s).
- **Format/static checks**: `gofmt -l` returned no files; focused vet
