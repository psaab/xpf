# #14584 — eBGP peers without an import policy discard every received update

## Issue

FRR bgpd defaults to `bgp ebgp-requires-policy` (RFC 8212). The renderer
emitted no `no bgp ebgp-requires-policy` anywhere (`grep -rIn
'requires-policy\|frr defaults' pkg/` = 0), so:

- an export-only eBGP peer (the common Junos shape) had every inbound
  update discarded (`inboundEbgpRequiresPolicy`),
- a policy-less eBGP peer was discarded in both directions,
- only peers with route-maps in the relevant direction, and iBGP peers,
  exchanged routes.

That contradicts the Junos contract (default import accepts all, default
export advertises active BGP routes) and the renderer's own
#6807/#7625 premise that an ABSENT route-map attachment permits.

## Fix

- `pkg/frr/protocols_render.go` (`generateProtocolsWithQNH11447`, the
  single `router bgp %d%s` producer for the default instance and every
  VRF — verified by grep: no other non-test producer): emit
  ` no bgp ebgp-requires-policy` immediately after the `router bgp`
  line in every stanza with `LocalAS > 0`. Neighbors with policies are
  unaffected (their route-maps still filter); the emptied-chain deny
  (#7625) still attaches an explicit deny route-map, so requires-policy
  would not have interfered with it either way.
- Comments corrected: the #6807 correction block in
  `protocols_render.go` and the header + `bgpChainRefOrEmptiedDeny`
  doc in `policy_chain_emptied_deny_7625.go` now state that the
  absent-attachment permit holds only because of this opt-out.
- NOT changed: no config knob / commit warning (the issue's alternative
  was an explicit documented opt-in knob; emitting the line in every
  stanza is the simpler primary acceptance and matches Junos default
  behaviour unconditionally). No per-neighbor emission — the command is
  router-level in FRR.

## Risk

- Operator-visible delta: eBGP peers without policies now accept and
  advertise per Junos defaults instead of silently discarding. This is
  the intended contract restoration; peers with any route-map are
  byte-identical apart from the one router-level line.
- Residual: none known. `frr defaults` profile is untouched; the line
  is valid under both traditional and datacenter profiles (verified by
  bgpd 10.7.1 load under `frr defaults traditional`).
