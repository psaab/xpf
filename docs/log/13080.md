# #13080 - Reduce shared-session ambiguity lock churn

- **Timestamp**: 2026-10-15
- **Action**: `publish_shared_session` now acquires `nat_ambiguities` once, records the neutral owner before exposing NAT aliases, and records collision marks before releasing the guard. The matching lookup releases the NAT map lock before reading ambiguity state, avoiding nested map/index locking and preventing a domain-zero reader from seeing an alias before its ambiguity owner is installed. Added a regression asserting one ambiguity lock acquisition per forward NAT publish.
- **Validation**: RED simulated the previous three ambiguity-lock acquisitions: `cargo test publish_forward_nat_takes_nat_ambiguities_once -- --nocapture` failed (`left: 3, right: 1`). GREEN: `cargo test session_glue::newflow_contention_tests -- --nocapture` (12 passed) and `cargo test shared_nat_mixed_zero_refuses_ambiguous_tenant_alias_11361 -- --nocapture` (1 passed).
- **Risk**: This removes repeated ambiguity-index lock acquisitions, but shared session and owner-RG indexes remain process-wide mutex-protected; broader sharding and clone reduction from D5-08 are not part of this change. Cross-map publication is still not atomic.
