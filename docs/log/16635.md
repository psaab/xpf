# Issue #16635: bracketed login-class regex lists silently truncated to first token

- **Timestamp**: 2026-10-25
- **Problem**: `set system login class ops deny-commands [ "a" "b" ]`, the hierarchical `deny-commands [ "a" "b" ];`, and the unquoted character class `deny-commands [rR]equest.*;` all passed strict commit. The lexer strips brackets, leaving leaf `Keys=["deny-commands","a","b"]` (flat) or `Keys=["deny-commands","rR","equest.*"]`; the four regex leaves in `pkg/config/schema_system.go` (`allow-commands`, `deny-commands`, `allow-configuration`, `deny-configuration`) declared `args: 1` without `scalar`, so `validateScalarValueLeaf` never ran, and `nodeVal` in the compiler stored only `Keys[1]`. The #15712 POSIX/duplicate gate therefore validated only `"a"`, enforcement compiled only `"a"`, and `show configuration` still displayed the whole list — a committed RBAC denial silently unenforced on CLI, gRPC and REST.
- **Fix**: Tag all four leaves `scalar: true, allowEmptyValue: true` in `pkg/config/schema_system.go`. `validateScalarValueLeaf` (schema_walk.go dispatch, #3332) then rejects any token beyond `Keys[1]` — hierarchical `Keys[2:]` and flat child-node tails alike — naming the leaf and the trailing token (`... deny-commands b: unexpected trailing token "b" ...`). `allowEmptyValue` preserves the quoted-empty `deny-commands ""` deny-all spelling and the valueless presence form, both of which flatten to `""` yet must keep recording `DenyLeavesPresent`. No compiler change: `nodeVal` still reads `Keys[1]`, now guaranteed to be the only token. The POSIX check was not moved into a schema validator (optional in the issue): the existing compiled-config #15712 gate already validates the single stored value on every spelling, and a second validator would duplicate it.
- **Not changed**: enforcement precedence/matching, the #15712 duplicate/POSIX gate, permissions mapping, `*-regexps` refusal (#7971), and any other leaf. Tolerant load / peer-sync still boots a persisted bracketed value (#1960): `compileTreeLenient` downgrades the scalar-arity schema error to a slog warning naming the trailing token, retaining the first token.
- **Regression check**: `go test ./pkg/config/ -run '16635' -count=1` (24 bracket/char-class/multi-token rejection cells across 4 leaves × hier/flat + 32 single/alternation/empty/valueless controls) and `go test ./pkg/configstore/ -run '16635' -count=1` (CheckText rejection ×8, Store.Commit/CommitCheck rejection ×4, tolerant-load warning ×1) pass with the fix and fail without it (RED confirmed by reverting the schema tags). Neighbouring login/schema suites run in the same lanes.

**Files**: `pkg/config/schema_system.go`, `pkg/config/login_class_bracket_list_16635_test.go` (new), `pkg/configstore/login_regex_bracket_16635_test.go` (new), `docs/log/16635.md`.
