# Issue #11339 — Policy READ completeness for shared synced sessions

## Root cause

`ListSessionsByPolicy` fanned out to worker-local `SessionTable`s but did not account for matching forward rows present only in the coordinator's shared synced map. It could therefore return `complete=true` with no matches even though the helper-owned authority held a relevant session.

## Fix

After the worker acknowledgements, the helper checks matching shared synced
identities against the exact `(SessionKey, session_id)` identities reserved by
the worker scans. An in-scope shared row with no worker-local coverage adds
`shared-synced-map-uncovered` and forces an incomplete READ. The reduced shared
entry is not synthesized into a delete candidate because it lacks the creation
time needed for the legacy `before_secs` fence and the existing READ result
contract. Unrelated shared rows do not affect completeness, and a shared row
already captured by a worker remains complete.

## Scope

Only the M1 misreport is addressed. M2 coast and production-producer population
remain NEEDS_VALIDATION, as scoped in the issue.
