# Issue #15152 — same-family embedded-ICMP builder-None budget refund (B13-01)

Residual of #10667 / #14123. `try_reverse_embedded_icmp_error`
(`poll_descriptor/embedded_icmp.rs`) returned `NotHandled` when a
same-family builder declined (`rewritten == None`) without calling
`sessions.refund_icmp_error_not_delivered(&icmp_match.budget_key, now_ns)`,
unlike every sibling post-match terminal and the NAT64 arm fixed in
#14123.

## Mechanism

- The F-077 per-session budget is charged at match time
  (`icmp_embed/nat_match_v4.rs`: `note_icmp_error_delivered(&fwd.key, …)`),
  before the poll arm knows whether the reversed frame can be built.
- A same-family builder can still decline after that charge — e.g.
  `neighbor_mac?` / `src_mac?` in `icmp_embed/builders.rs` when the client
  neighbor is missing, a truncated quote, or a cross-family
  `original_src`. The arm then fell through as `NotHandled` and leaked
  the token.
- While the cause persists (e.g. an unresolved client neighbor), every
  genuine PMTUD / Time-Exceeded error for that session is suppressed
  until refill: the 64-burst at 64/s takes ~1 s to recover, and a
  persistent cause re-drains it on every retry.

Sibling exits already refund: TTL-expire (`embedded_icmp.rs`, Dropped),
CoS drop and queued-identity failure (queue tail, Dropped), policy-refuse
after `Queued` (both flowless callers in `poll_descriptor/mod.rs`), and
every post-match `NotHandled` in the NAT64 arm (#14123). The
`budget_key` doc in `icmp_embed/mod.rs` claimed "`NotHandled`
(unbuildable frame) keeps the charge" — that premise is what this fix
removes for the charged-match builder-None leg. `NoMatch` still never
charges, so there is nothing to refund there.

## Change

- `poll_descriptor/embedded_icmp.rs`: refund
  `icmp_match.budget_key` immediately before the builder-None
  `NotHandled` return. The descriptor still falls through to normal
  flowless enforcement unchanged (a miss is not a drop); only the
  charged token is returned. No other behaviour changes: the fall-through
  packet, zones, policy, and CoS handling are untouched, and the refund
  helper never inserts a budget entry.
- `icmp_embed/mod.rs`: correct the `budget_key` doc to state that a
  same-family builder decline after a charged match refunds (#15152,
  the #14123 NAT64 precedent), while `NoMatch` has nothing to refund.

## Risk

- Behaviour delta is confined to budget accounting for charged matches
  whose same-family build fails: those errors now keep their session's
  error budget instead of consuming it. Delivery semantics are
  unchanged — the error still falls through to flowless enforcement,
  and a builder-None error still queues no reversed frame. The refund
  is idempotent-safe in the same sense as the existing sibling refunds:
  it inverts exactly one prior `note_icmp_error_delivered` take for the
  same `budget_key`, and `refund_icmp_error_not_delivered` never inserts.
