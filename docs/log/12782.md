# 12782 — Compile keyed to-zone children in container from-zone

## Why

The strict #11346 prewalk rejected every keyed `to-zone <name>` child under a `from-zone` container as unimplemented, even though `compilePolicies` can compile that shape using the `to-zone` key. This incorrectly prevented valid policy commits. Once the false rejection is removed, AST mirror walkers also need to inspect the keyed node itself as the destination pair body; otherwise strict validation can miss missing match dimensions and unsupported modifiers, while tolerant loads omit their specific warnings. The distinct mixed-key spelling `from-zone { A to-zone B { ... } }` remains unsupported.

## What

- Narrow #11346 rejection to the unsupported mixed-key spelling; allow keyed `to-zone` children to compile using their key and stop emitting the obsolete zero-policy warning for that supported shape.
- Extend the #3044/#6526 required-match, #3113 unsupported-match, #3114 then-permit, and #7525 empty-identity walkers to inspect policies under a keyed destination node.
- Preserve #12782 quarantine behavior for misspelled policy children (`polcy`): exact source/destination context, poison locator, and no phantom policy-named destination pair. Match-only typos remain policy intent.
- Add strict-commit, strict-warning, tolerant-warning, empty-identity, typo, and valid keyed/nested/combined controls.

## Validation

- RED-before: keyed-correct strict commit failed with the obsolete #11346 mixed-shape error; keyed missing-match and then-permit strict cases likewise stopped at that gate instead of #3044/#3114.
- Focused config and configstore keyed-to-zone/#12629 regressions — PASS after rebasing onto `origin/master`.
- `go test ./pkg/configstore/ -count=1` — PASS after rebase (133.433s).

## Risk

Only the keyed-child shape under a container `from-zone` is newly accepted. Direct nested #7523 and mixed-key #11346 spellings remain rejected strictly and warned/quarantined on tolerant loads. No live-cluster validation was performed.
