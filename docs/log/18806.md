# #18806 - Resolve the crate-root sync scan test fixture

## Why

The #8325 agreement test compares legacy filename fixture rules with the `#[cfg(test)]` module graph discovered by `userspace-dp/src/test_support/source_scan.rs`. The crate-root declaration of `sync_util_scan_tests` was bare, so the scanner applied its ordinary non-`mod.rs` owner rule (`src/main/`) instead of Rust's crate-root resolution to `src/`. The actual `src/sync_util_scan_tests.rs` therefore appeared as ONLY_LEGACY and caused the agreement test to fail.

## What

Added `#[path = "sync_util_scan_tests.rs"]` between `#[cfg(test)]` and `mod sync_util_scan_tests;` in `userspace-dp/src/main.rs`. At the crate root the path resolves to the same source file Rust already loaded; it makes that location explicit to the declaration-driven scanner. No scanner special case, test change, or production behavior change.

## Validation

- GREEN after the fix: the same exact test passed (1 passed).
- Neighbor acceptance: `sync_util_scan_tests::no_banned_lock_poison_shapes_in_production_17201` passed (1 passed).
- Full `sync_util_scan_tests` module passed (2 passed).
- Mutant proof: removing only the `#[path]` attribute restored the exact #8325 RED naming `sync_util_scan_tests.rs`; restoring it returned the exact test to GREEN (1 passed).
- Full `afxdp::worker_queue::tests` module: 29 passed; the existing `worker_queue_7201_did_work_consumes_the_backlog_signal` test failed because its source-line assertion sees `let mut did_work =` rather than its old single-line expected statement. This is the separate #18807(c) stale test pin; no `worker_queue_tests.rs` code was changed here.

Commands used the lane target directory `/var/worktrees/.cache/cargo-18806`.

## Risk

None to production behavior: the declaration remains test-only and names the same crate-root source file that Rust's implicit resolution already selected. The fixture scanner now recognizes that same file in the #8325 declaration graph.
