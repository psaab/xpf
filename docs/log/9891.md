## Fix

- `pkg/diagcmd/limiter.go` — new `MaxConcurrentMonitorInterfaceStreams = 64`
  + `MonitorInterfaceLimiter`, registered in `AllLimiters()` as
  `monitor_interface` (refusals observable via `xpf_admission_refusals_total`).
- `pkg/grpcapi/server_diag_monitor.go` —
  `monitorInterfaceLimiter` package var (same seam shape as
  `sessionWalkLimiter`/`diagLimiter`); fail-fast `Acquire()` after validation
  (cfg nil, NotFound) but before proxy dial and ticker creation;
  transfer-aware `defer` (disarmed when a Send timeout moves the slot to its
  worker); over-cap returns `codes.ResourceExhausted` with no
  ticker/goroutine/dial.
  `monitorInterfaceSendTimeout = 30s` handler-side (matches `sseWriteDeadline`/
  `bgpStreamWriteDeadline`, per-write not elapsed; trailers still queue behind
  pending DATA until drain/disconnect); local tick loop and
  `proxyMonitorInterface` forwarding loop both send via
  `sendMonitorInterfaceFrame` (Send in a worker goroutine +
  `select(ctx.Done, timeout)` with a stopped timer on the fast path; timeout
  severs the HANDLER with `DeadlineExceeded` and TRANSFERS the slot to the
  worker, which releases when Send unblocks — 64 bounds active handlers PLUS
  retained workers so churn cannot accumulate outside the budget).
  `monitorInterfacePeerIdleTimeout = 10s`: proxy `Recv` via
  `recvMonitorInterfaceFrame` severs a stalled peer with `Unavailable` (no
  transfer — `conn.Close()` unblocks Recv promptly).

  re-wedge (new RPCs + dials) instead of hold-once.
