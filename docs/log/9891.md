## Fix

- `pkg/diagcmd/limiter.go` — new `MaxConcurrentMonitorInterfaceStreams = 64`
  + `MonitorInterfaceLimiter`, registered in `AllLimiters()` as
  `monitor_interface` (refusals observable via `xpf_admission_refusals_total`).
- `pkg/grpcapi/server_diag_monitor.go` —
  `monitorInterfaceLimiter` package var (same seam shape as
  `sessionWalkLimiter`/`diagLimiter`); fail-fast `Acquire()` after validation
  (cfg nil, NotFound) but before proxy dial and ticker creation;
  transfer-aware `defer` (disarmed when a Send timeout moves the slot to its
  worker); over-cap returns `codes.ResourceExhausted` with no
  ticker/goroutine/dial.
  `monitorInterfaceSendTimeout = 30s` handler-side (matches `sseWriteDeadline`/
  `bgpStreamWriteDeadline`, per-write not elapsed; trailers still queue behind
  pending DATA until drain/disconnect); local tick loop and
  `proxyMonitorInterface` forwarding loop both send via
  `sendMonitorInterfaceFrame` (Send in a worker goroutine +
  `select(ctx.Done, timeout)` with a stopped timer on the fast path; timeout
  severs the HANDLER with `DeadlineExceeded` and TRANSFERS the slot to the
  worker, which releases when Send unblocks — 64 bounds active handlers PLUS
  retained workers so churn cannot accumulate outside the budget).
  `monitorInterfacePeerIdleTimeout = 10s`: proxy `Recv` via
  `recvMonitorInterfaceFrame` severs a stalled peer with `Unavailable` (no
  transfer — `conn.Close()` unblocks Recv promptly).

## Parent review fold (GPT NEEDS-MAJOR + SPARK NEEDS-MINOR, one round)

- GPT-1 (retained footprint): Send timeout now transfers the slot to the worker
  instead of freeing while the worker stays parked; 64 bounds handlers +
  in-flight workers (goroutine/slot lifetime). 30s claim restated honestly
  (handler return, not client observation or H2 transport reclamation) in
  code + README: the worker exits on the handler-return stream cancel and
  frees the slot promptly, while queued DATA + trailers + stream state stay
  retained until drain/disconnect, bounded per-connection by
  MaxConcurrentStreams (256) + 64KB windows rather than by the 64.
  Wedge math: 64 handlers+workers max at any instant; retained transport per
  connection bounded by 256 streams; sustained churn requires
  disconnect/reconnect cycles (new TCP/H2/gRPC/auth per cycle).
- GPT-2 + SPARK-F4 (slow-test teardown): slow cell now asserts InFlight==1 +
  exits==0 at handler return (worker parked, slot transferred), then cancel →
  Send completion → InFlight==0 → probe acquire (release EXECUTED).
- GPT-3 + SPARK-F1 (proxy Recv wedge): added 10s peer-idle bound (peer ticks 1s
  by construction; PSK proves identity not liveness); 64 wedges no longer hold
  indefinitely — each severs with Unavailable and frees, forcing continuous
  re-wedge (new RPCs + dials) instead of hold-once.
- SPARK-F2 (worker outlives return): cannot-outlive comment corrected (worker
  outlives until Send unblocks, holding the transferred slot, bounded by 64);
  exit proven by exits + InFlight assertions above.
- SPARK-F3 (proxy admission): new dial-counting cell (RG-monitor peer member
  routes to proxy; empty peer addrs fail dial fast): refused → 0 dials +

## Parent review fold, round 2 (GPT-1 HIGH + GPT-2 HIGH + GPT-3 MEDIUM + SPARK minor)

- GPT-1 (timeout ownership race): the timer-with-done-ready path returned
  `(err, false)`, so a Send succeeding exactly as the timer fired let the
  loop CONTINUE WITHOUT ITS SLOT (worker released via the flag; sync.Once
  stops double-release, not premature release). Timeout ownership is now
  TERMINAL — the boundary severs with transfer even on success, releasing
  immediately since Send completed (nothing parked; idempotent with the
  worker's own release, leak-free if the worker's Load raced ahead).
  Deterministic seam test (`sendBoundaryDelay9891`) lands a 10ms Send inside
  a 200ms Store-to-drain window: pre-fix code reds
  `continued with InFlight = 0` on every run (verified by temporary revert).
- GPT-2 (flow-control accounting): verified against pinned grpc-go v1.78.0 —
  handler return DOES unblock a quota-parked Send via WriteStatus →
  finishStream `s.cancel()` → `writeQuota.get` errStreamDone, while the
  trailer queues behind pending DATA (controlbuf headerHandler). The worker
  therefore exits promptly after the return (slot freed) while H2 transport
  stays retained until drain/disconnect. Code comments + README corrected to
  the honest guarantee above; new REAL bufconn H2 test (200KB frames, client
  holds window shut) proves InFlight drains with the client still connected
  and the queued DATA frame still arrives ahead of the DeadlineExceeded
  trailer. The blocking-Send fake is kept for transfer-logic isolation but
  no longer stands alone.
- GPT-3 (peer-stall establishment): `NewStream` waits for H2 stream quota
  with no timer (http2_client quota wait), so a saturated/wedged peer pins
  the proxy slot before the 10s Recv bound starts. New
  `monitorInterfacePeerEstablishTimeout` (10s, separate var) bounds
  establishment via cancel-plus-timer-stop: the timer is stopped on success,
  so healthy monitoring follows client lifetime, never the budget. Wedged
  NewStream severs Unavailable; healthy establishment survives past the
  budget until parent cancel (both pinned by test).
- SPARK (forwarding-loop cell): extracted `forwardMonitorInterfaceFrames`
  (proxy loop body) and `establishMonitorInterfacePeerStream` from
  `proxyMonitorInterface`; new loop cell proves Unavailable on peer stall
  (1 frame forwarded, no transfer) and DeadlineExceeded + transfer on local
  slow-consumer at the loop's Recv/Send sites.
