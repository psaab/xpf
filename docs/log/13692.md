# #13692 — reclaim expired idle leases before HA replacement

## Defect

HA idle-lease import returned `SkippedExisting` for any matching
`persistent_by_source` key, including an expired idle lease whose PAT port was
still held because passive-standby GC is lazy. The two synced-session reserve
paths similarly filtered expired entries out of the persistence join without
removing the entry or releasing its port. A valid incoming decision could
therefore be rejected on the stale bitmap bit or installed without persistent
ownership.

The idle-import coordinator also rebuilt a temporary address vector and
linearly searched it for every record, even though the owning rule already has
an O(1) pool-address index.

## Change

Add one locked reclamation helper that removes expiration-index entries and the
lease, releasing a PAT bit while leaving address-only ownership mode-correct.
Invoke it before existing-key decisions in idle import and both synced reserve
paths. Clear-fence checks still precede reclamation; live and revoked active
leases remain protected. Production idle import now passes the index resolved
by `SourceNatRule::pool_index_of`, removing the per-record linear scan.

## Regression coverage

Tests cover replacement of an expired idle import while preserving the
`SkippedExisting` behavior for a live lease, same-port and different-port
synced PAT reservations, address-only synced reservation after expiry, and the
clear-fence sibling behavior.

## Risk

The changes are under the allocator's existing live-state lock and affect only
idle lease replacement; active/draining leases and clear-fenced stale records
retain existing behavior.
