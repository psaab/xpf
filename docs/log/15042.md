# Issue #15042 — non-Compile republish that revalidates a recreated ifindex never attaches XDP; later link refresh dedups before its own attach (A29-01)

## Why

`prepareSnapshotForApply` (pkg/dataplane/userspace/apply_snapshot_identity_9520.go)
records a moved row on `Manager.revalidateChangedIfindex`, but only
`applyCompiledSnapshot` consumed it. Every other publisher —
`PublishRouteOverlaySnapshot` / `RepublishCurrentCaptureAuthority`
(manager_overlay.go, via `requestApplySnapshotPreparedLocked`),
`UpdatePolicyScheduleState` and `retryDeferredWorkerArmLocked`
(via `requestApplySnapshotLocked`), and `process_status.go:152`'s
`syncSnapshotLocked` — adopted the recreated ifindex into
`lastSnapshot` + `lastSnapshotHash` without attaching XDP. The daemon's
debounced (150 ms) link refresh
(`RefreshInterfaceRowsForLink`, manager_link_refresh.go) then rebuilt
identical content, hit the hash dedup at the top and returned
`(false, nil)` before its own `reconcileInterfaceAttachmentsForRefreshLocked`,
leaving the recreated interface unshimmed (fail-closed transit loss, not a
bypass) until the next full Compile. This is the residual of #14333
(applyCompiledSnapshot only) and #14133 (refresh only when it is first).

## What

- `consumeRevalidateAttachLocked` (apply_snapshot_identity_9520.go): when
  `revalidateChangedIfindex` is set, run
  `reconcileInterfaceAttachmentsForRefreshLocked(snap)` and clear the flag.
  `requestApplySnapshotLocked` now consumes it right after
  `prepareSnapshotForApply`, so every `requestApplySnapshotLocked` caller
  (policy-scheduler, deferred worker-arm) attaches before sending.
  Prepared-send publishers that call `prepareSnapshotForApply` themselves
  consume it explicitly before `requestApplySnapshotPreparedLocked`
  (route-overlay, capture-authority — including on their hash-dedup skip,
  so a deduped republish still attaches) and on `syncSnapshotLocked`'s
  dedup return. `applyCompiledSnapshot`'s inline consume is replaced by
  the same helper (no behaviour change there).
- `RefreshInterfaceRowsForLink`: the attach reconcile now runs before
  (independent of) the hash dedup, and the later duplicate reconcile
  before publish is removed (the pre-dedup run covers both paths; it is a
  no-op for tracked ifindexes). This heals kernel state left unshimmed by
  any earlier publisher/attach failure even when the rebuilt content is
  hash-identical. An unchanged refresh whose ifindex is tracked issues
  no attach and still does not publish.
- `reconcileInterfaceAttachmentsForRefreshLocked` is now nil-`bpfShim`
  safe (hook-only/test managers and `bpfShim = nil` fixtures no longer
  panic on the new earlier call sites); production behaviour with a live
  shim is unchanged.
- Regression tests
  (pkg/dataplane/userspace/revalidate_republish_link_refresh_15042_test.go):
  - `TestNonCompileRepublishAttachesRecreatedIfindex15042` (probe cell 1):
    link recreated 17 -> 29, then `UpdatePolicyScheduleState`; asserts
    AttachXDP attempted for 29 only, flag consumed, row published at 29.
  - `TestLinkRefreshAfterRepublishAttachesRecreatedIfindex15042`
    (probe cell 2): after that republish adopted 29 into snapshot+hash,
    `RefreshInterfaceRowsForLink` with identical content must still
    attach 29, must not publish, and the already-attached control must
    not publish either.
  - `TestInterfaceLinkRefreshAttachesRecreatedIfindex14133` control
    updated: its unchanged-refresh leg now models the production tracked
    state via the already-attached error (the hook cannot model the
    kernel tracked set), and additionally asserts no publish. Production
    no-attach on unchanged refresh is via the `XDPLinks()` tracked set.

## Validation

- RED on origin/master (3039ef6150): both new tests fail —
  `non-Compile republish did not attach XDP for recreated ifindex 29; attaches=[]`
  and `link refresh after republish did not attach XDP ... before hash dedup; attaches=[]`.
- GREEN with the fix: both new tests pass; controls
  `TestInterfaceLinkRefreshAttachesRecreatedIfindex14133`,
  `TestInterfaceLinkRefreshRebuildsDroppedRowsFromDesiredConfig11530`,
  `TestInterfaceLinkRefreshQuarantinesRecreatedRow14133`,
  `TestInterfaceLinkRefreshStampsFreshXfrmDumpFailed14133`,
  `TestRevalidateChangedIfindexAttachesXDP14333`,
  `TestRevalidateSnapshotIfindexesRecomputesEgressZoneAndLinkMetadata`
  pass; `go vet ./pkg/dataplane/userspace/` clean.

## Risk

- Attach failure remains fail-closed and non-fatal to the publish (as
  #14133/#14333 documented): the interface stays fence-dropped until a
  later refresh/apply retries. No detach behaviour changes; no Rust or
  wire changes.
- The refresh now samples `XDPLinks()` and may attempt one already-attached
  probe per untracked ifindex on hash-identical refreshes in production
  only when the kernel truly lacks the link — which is exactly the state
  being healed. Tracked interfaces incur only the map clone.
- Residual: none for the cited mechanism — all `apply_snapshot` send
  paths now consume the flag, and the refresh attach no longer depends
  on the hash changing.
