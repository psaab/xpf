# #9890 — deactivate, activate and annotate bypassed the deny-configuration regexes

- **Timestamp**: 2026-09-12
- **Action**: gate the three missing path-carrying verbs on the REST surface;
  make each route declare WHICH body field carries its path; fail closed on an
  unrecognised field; add a census asserting every registered
  `POST /api/v1/config/*` route is either gated or declared with a reason.
- **File(s)**: `pkg/api/authz_config_regex_9154.go`,
  `pkg/api/authz_config_route_census_9890_test.go`,
  `pkg/api/config_regex_surface_9154_test.go`, `docs/log/9890.md`.

## What was wrong

`restConfigMutationRoutes` held exactly `set` and `delete`. `deactivate` (
`server.go:799`), `activate` (`:800`) and `annotate` (`:813`) are registered
POST routes whose handlers mutate the candidate by path —
`DeactivateFromInputAs`, `ActivateFromInputAs`, `AnnotateAs` — and none was in
the gate. A principal denied `set system root-authentication` reached the same
subtree by choosing a different verb.

**`deactivate` is the one with teeth.** An inactive node is excluded from
compilation, so deactivating a denied subtree does not edit its contents, it
REMOVES ITS ENFORCEMENT — and the next legitimate commit by anyone ships that
removal.

The omission was not a decision. The route table's comment explains only why
`load`, `commit` and `rollback` are absent and never mentions these three, so a
reader checking whether the surface was complete found prose that looked
considered. The shared evaluator already knew all three verbs
(`configMutationVerbs` carries set, delete, deactivate, activate, copy, rename,
insert, annotate), so nothing had to be built — they were simply not listed.

## Why a table row was not enough for `annotate`

Its handler reads `AnnotateRequest.Path`; the gate read `input`. A row alone
would have adjudicated an EMPTY STRING and allowed everything **while looking
gated**. Each route now declares its field, the gate reads that field and only
that field, and an unrecognised field FAILS CLOSED — a fallback would recreate
the same silence one layer in.

## The remedy is a census, because a hand-maintained list is what failed

`restConfigRoutesUngated` states, for every other registered POST config route,
why no regex is evaluated for it, and `TestEveryConfigPostRouteIsGatedOrDeclared9890`
asserts every route registered in `server.go` appears in exactly one of the two
tables. A route added to neither now fails by name on the first run. The `load`
row is written as a STATED REMAINING GAP rather than an exemption, pointing at
the #9633 gRPC fix that closed the same hole on that surface, so it is not read
as a claim that load is safe.

The last row was a TRUE ESCAPE on the first run: no cell sent annotate with an
empty `path` and a populated `input`, so the fallback was never exercised. The
new cell sends exactly that and asserts **400, not 403** — a 403 would mean the
gate denied over content the handler was never going to apply, which is the same
gate/handler disagreement that let annotate through ungated. One row also came
back VOID first (its anchor had been realigned by `gofmt`) and was reported as
VOID rather than dropped.
