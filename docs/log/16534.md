# #16534 — failed install.sh re-run deletes the pre-existing apt source

- **Timestamp**: 2026-10-24
- **Action**: Back up a pre-existing `xpf.sources` before overwriting it and
  restore it byte-for-byte on failure; remove the source only when this run
  created it.
- **Base**: `origin/master` `9dfad41542`
- **Branch**: `fix/16534-install-source-restore`
- **Files**: `scripts/dist/install.sh`,
  `scripts/dist/test_install_cleanup_trap_t1_10848.py`,
  `docs/distribution.md`, `docs/log/16534.md`

## Why

`cleanup_on_fail` did `rm -f "$SRC"` whenever `SRC_WRITTEN=1`, and
`write_source` overwrote `/etc/apt/sources.list.d/xpf.sources` in place with
no backup. The pin (#11133) and keyring (#12142/#12543) both back up and
restore a pre-existing file, so a failed re-run — the documented channel
rebind procedure (`docs/distribution.md`, "Rerun `install.sh` to rebind
channels") — restored pin and keyring but deleted the working apt source.
The host then silently stops receiving xpf updates until a successful
re-run; no maintainer script recreates the source (only
`debian/xpf.postrm` references it, to remove it).

Trace: existing install (stable) → `curl … | sudo sh` with
`XPF_CHANNEL=edge` → `install_keyring` (backup) → `write_source` overwrites
→ `apt-get update`/`verify_channel`/`apt-get install` fails → EXIT trap
restores keyring and pin and removes the source.

## What changed

- `write_source` mirrors the pin/keyring writes: refuse a symlinked or
  non-regular `$SRC`, stage the new body in a same-directory temp
  (`.xpf.sources.tmp.XXXXXX`, mode 0644 — the same mode the previous
  truncating write produced under the default umask), `cp -p` a
  pre-existing source to a same-directory backup
  (`.xpf.sources.backup.XXXXXX`), arm `SRC_WRITTEN` before the rename, then
  `mv -f` the temp over the live path. Staging also means a failed write
  never truncates a working source.
- `cleanup_on_fail`: on failure, restore `SRC_BACKUP` over `$SRC` when one
  exists (byte-for-byte, mode preserved by `cp -p` + rename); `rm -f $SRC`
  only when this run created it. Stray source temp/backup are removed in
  both the failure and success branches, alongside the existing pin/keyring
  cleanup. On success (`INSTALL_OK=1`) the backup is discarded and the new
  source stays.
- `docs/distribution.md` §Install (Tier A): "removes the source" now reads
  as restoring the previous apt source when a re-run overwrote one (or
  removing it on first install), matching the pin/keyring wording.
- Tests in `test_install_cleanup_trap_t1_10848.py`: harness gains the
  `SRC_BACKUP`/`SRC_TEMP` state (plus the missing `die` stub and
  `KEYRING_WRITTEN`/`KEYRING_IDENT` state the extracted
  `cleanup_on_fail` already referenced). New cells: failed re-run restores
  the pre-existing source byte-for-byte with mode 0640 intact and leaks no
  temp/backup; successful re-run keeps the new source and cleans the
  backup; a symlinked source is refused and preserved. Existing controls
  still pass: first-install failure removes the source, success keeps it,
  no-trap control leaves both files.

## Risk

- SIGKILL/power loss bypass the EXIT trap (inherited, unchanged for
  pin/keyring); a leftover `.xpf.sources.backup.*` in
  `/etc/apt/sources.list.d/` would be inert (apt only reads `*.sources` /
  `*.list`) and is overwritten-named uniquely by `mktemp` on the next run.
- The source gains the pin/keyring's same-directory temp+rename discipline;
  the live file mode is now explicitly 0644 instead of umask-dependent.
