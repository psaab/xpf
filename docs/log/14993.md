# #14993 — Bootstrap lifeline across restart + superseded first-commit teardown (D38-05)

## Defect

1. **Absent pre-takeover lifeline had no durable provenance.**
   `Daemon.captureBootstrapLifelineNetwork` recorded a captured absence
   (`bootstrapLifelinePresent=false`) only in memory; the durable
   `.xpf-first-commit-lifeline.snapshot` record was written only for a
   marked present file. When a first `commit confirmed` window expired
   while xpfd was down, the restarted daemon's
   `restoreBootstrapLifelineNetwork` found a post-takeover
   `10-xpf-fxp0.network`, no in-memory snapshot, and no durable record —
   the absent-absent no-op did not apply (a file exists), so it failed
   closed DEGRADED, retained the #12155 teardown debt forever, and left
   the abandoned management addressing in place.

2. **Superseded teardown debt was only discarded at `Load`.**
   `Store.discardSupersededFirstCommitTeardownLocked` ran solely from
   `store_persist.go` during `Load`. An in-process plain commit,
   confirmed commit, or cluster `SyncApply` that superseded the abandoned
   generation never discarded the debt in the running process, so
   `FirstCommitTeardownOwed()` stayed true and the daemon teardown gate
   could tear down the replacement's takeover (and block later rollback
   restorations behind the stale generation binding).

## Fix

- `pkg/daemon/bootstrap.go`:
  - `bootstrapLifelineSnapshotRecord` gains `Present bool`. Present-byte
    records now write `Present: true`; the captured-absence branch writes
    a generation-bound record with `Present: false` via the new
    `persistAbsentBootstrapLifelineSnapshotLocked`. A second FIRST window
    in one process re-persists either form under its new generation.
  - `loadBootstrapLifelineSnapshot` returns the decoded `present` flag.
  - `restoreBootstrapLifelineNetwork`'s generation gate accepts a
    captured absence (empty bytes, generation-matched) as authentic
    provenance and falls into the existing absent-restore branch, which
    removes the post-takeover file only when it carries the xpfd header.
    Old-format records (no `Present`, empty `Network`) still fail the
    gate exactly as before — no provenance is invented for them.
- `pkg/configstore/store_commit.go`, `pkg/configstore/store.go`:
  - `commitWithDescriptionLocked` and `commitConfirmedLocked` call
    `discardSupersededFirstCommitTeardownLocked` after the new active
    config is durable (or visible post-rename, where `everCommitted` is
    already true). `SyncApply` does the same after its durable write,
    except when the drain just re-noted fresh debt from a deferred
    rollback (`confirmResolvePendingPersist` still set) — that fresh
    debt is preserved for the retry loop, which discards it via
    `clearConfirmResolutionPendingLocked` once the rollback write heals.

## Regression tests

- `pkg/daemon/first_commit_absent_lifeline_restart_14993_test.go`:
  `TestFirstCommitAbsentLifelineSurvivesRestart14993` drives the exact
  mechanism — no pre-takeover `10-xpf-fxp0.network`, first
  commit-confirmed takeover, window expiry across a restart — and
  asserts the post-takeover file is removed and the debt converges.
  RED on master: "absent pre-takeover lifeline made the restart teardown
  DEGRADED" (`no pre-takeover snapshot is available`). GREEN after fix.
- `pkg/configstore/first_commit_teardown_superseded_inprocess_14993_test.go`:
  plain-commit and confirmed-commit cells assert the debt and its durable
  marker are discarded in-process (and stay discarded across restart).
  Both RED on master ("left superseded FIRST teardown debt owed"), GREEN
  after fix.
- Three existing daemon fixtures that hand-write snapshot records now set
  `Present: true` (the format they simulate is written by the new code).
