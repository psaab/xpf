# #12923 — two apply-groups with different default-policy actions resolve by order

- **Timestamp**: 2026-10-14 (`fix/12923-campaign-pub`)

## Why

Follow-up to #12821/#12823. Two apply-groups carrying different `default-policy`
actions merged first-applied-wins: a group's flat `default-policy permit-all;`
leaf had no merge provenance (only the block spelling carried #12823's marker),
so it met the generic inline-wins override when the winning peer was itself
adopted from an earlier group, and the #4325 cross-shape guard dropped a group's
block beside an adopted flat leaf. The merged tree never materialized a stanza
pair for #11821/#12821 to see, so the config resolved silently by application
order — permit-first compiled as `PolicyPermit` with no diagnostic (fail-open).

## What

- `pkg/config/group_default_policy_override_12823.go`: `isDefaultPolicyGroupStanza12923`
  matches both spellings of a group's `default-policy` choice at the security
  policies level (flat valued leaf and braced block); `markGroupDefaultPolicyStanza12923`
  records group-adopted stanzas in the existing expansion-local budget map;
  the clone walker now marks flat-leaf stanzas too, not only blocks.
- `pkg/config/ast_groups.go`: when a group's `default-policy` leaf resolves a
  peer that is itself group-adopted, the stanza is adopted beside it instead of
  being order-suppressed; the leaf-adopt site marks adopted stanzas; the #4325
  cross-shape guard no longer drops a group's `default-policy` block beside a
  group-adopted flat stanza. An authored inline peer is never marked, so inline
  still overrides every group silently (#12823 doctrine unchanged).
- Materialized pairs are judged by the existing gates: #11821 (leaf pairs and
  mixed pairs), #11367 (block-block pairs), #12821 — strict rejects and
  tolerant `Load`/`SyncApply` warn and force deny-all, exactly as for
  authored conflicts.
- Regressions in `pkg/config/compiler_default_policy_two_groups_12923_test.go`;
  behavior documented in `pkg/config/README.md` and `docs/config-schema.md`.

- **Full config package**: `GOMAXPROCS=2 go test ./pkg/config -count=1 -timeout 12m` passed (`ok 610.036s`, exit 0) — no failures.
- **Build**: `GOMAXPROCS=2 go build ./...` passed. **Vet**: `GOMAXPROCS=2 go vet ./pkg/config/` passed.

## Risk

Configs whose two apply-groups carry different default-policy actions are newly
strict-rejected and tolerant-load fail-closed to deny-all instead of silently
resolving by order; identical actions and inline overrides are unchanged. The
change is confined to `default-policy` stanzas at the security policies level;
no other leaf or container merge behavior changed, and no live dataplane or
cluster was modified.
