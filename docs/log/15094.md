# Issue #15094: Event ingress-interface map resolves Junos-spelled interfaces (A52-06)

- **Timestamp**: 2026-10-18
- **Action**: `applySyslogConfig` in `pkg/daemon/daemon_system.go` built the
  `EventReader` ifindex→name map by calling `netlink.LinkByName` with the
  authored config name and silently skipping failures. An authored Junos name
  such as `ge-0/0/1` (`docs/ha-cluster-userspace.conf:23`) is not a kernel
  device (the kernel device is `ge-0-0-1`), so every Junos-spelled interface —
  and every RETH, which names no device at all — got no entry. Events on those
  interfaces resolved `IngressIface=""`, so RT_FLOW / `show security log`
  rendered `packet-incoming-interface="N/A"`/`"unknown"` and interface-scoped
  live monitors matched nothing.
- **Action**: extracted `buildIfNames(cfg)` in the same file. For each
  configured interface it resolves the authored name through
  `cfg.ResolveKernelIfName` for the kernel lookup (slash→dash translation,
  per-unit VLAN/tunnel devices, RETH→local physical member) and stores the
  operator-facing authored name under the resolved ifindex. Per-unit entries
  are included (a VLAN unit's child device is a distinct ifindex, rendered
  `<iface>.<unit>`; unit 0 collapses onto the parent and renders as the bare
  name). Iteration is sorted, RETH interfaces first, first-wins, so a shared
  ifindex (RETH member device, parent/unit-0) is named deterministically
  under the operator-facing logical name. Unknown ifindexes still resolve
  to `""` downstream; kernel-spelled names (e.g. `lo`) behave exactly as
  before. No change to `pkg/logging` — `resolveIfName` already had no
  fallback to fix; the defect was purely that the map was never populated
  for these interfaces.
- **Regression**: `pkg/daemon/ingress_ifname_15094_test.go` drives the real
  `applySyslogConfig` with a RETH whose local member device is loopback
  (`ResolveKernelIfName("reth0") == "lo"`, while authored `"reth0"` names
  no kernel device — the Junos-spelling gap in miniature, since a real
  `ge-0-0-1` device cannot be created on a test host), feeds a raw
  SESSION_OPEN wire frame carrying the loopback ifindex at `[128:132]`
  through `ProcessRawEvent`, and asserts the buffered record renders
  `IngressIface="reth0"`. Adjacent controls pin the kernel-spelled `lo`
  interface still resolving and an unknown ifindex still resolving to `""`.

## RED -> GREEN proof

- **RED**: on `origin/master` (`fd396db3a7`) with only the test added, the
  Junos/RETH cell failed: the record resolved `IngressIface="lo"` (the
  member's own kernel-spelled entry leaking through) instead of the
  operator-facing `"reth0"` — and on a config without that accidental
  member entry it resolves `""`, the reported defect. (The first fixture
  iteration, which permitted either spelling, passed vacuously via the
  member entry; the assertion was tightened to the operator-facing name
  to make the RED honest.)
- **GREEN**: after the fix, `go test -count=1 -run 'TestIngressIfNames'
  ./pkg/daemon/` passes both cells, and the full `pkg/daemon`,
  `pkg/logging`, and `pkg/cli` suites pass.
