# #15049 — vrrp: drop stripped-VLAN sibling adverts on untagged parent (A25-02)

- **Timestamp**: 2026-10-18
- **Investigation**: Confirmed at `origin/master@d2dfc57901`. An untagged-unit
  VRRP instance on a `vlan-tagging` parent binds its AF_PACKET `ETH_P_ALL` tap
  (`openAfPacketReceiver`, `pkg/vrrp/manager.go`) to the parent netdev. A peer
  advert for a tagged sibling (VLAN 100) arrives 802.1Q-tagged on the wire,
  but the NIC/driver strips the tag into `skb->vlan_tci`
  (`VLAN_TAG_PRESENT`) before the parent's `ptype_all` tap, so
  `receiverAfPacket` (`pkg/vrrp/instance_receive.go`) sees an untagged frame.
  Neither the cBPF prefilter (`vrrpCBPFFilter`, in-data ethertype only) nor the
  Go parser (in-data ethertype only) could tell it was tagged, and no
  `PACKET_AUXDATA` was requested anywhere in `pkg/vrrp` — so a same-VRID,
  higher-priority advert from VLAN 100 was enqueued on the parent instance,
  demoting the native MASTER / perpetually resetting its master-down timer
  (native VIP ownerless). This is the AF_PACKET sibling of #2886, which only
  fixed the raw-socket fallback (`acceptArrivalIfindex`).
- **File(s)**: none (investigation only)

- **Timestamp**: 2026-10-18
- **Action**: Fix in worktree `/var/worktrees/wt-15049` (branch
  `fix/15049-campaign`): (1) `openAfPacketReceiver` requests
  `PACKET_AUXDATA` (best-effort, debug-log on refusal, mirroring
  `PACKET_IGNORE_OUTGOING`); (2) `receiverAfPacket` switches from
  `unix.Recvfrom` to the new `afPacketRecvmsg` (`unix.Recvmsg`) seam and,
  for instances bound to a non-VLAN netdev, drops any frame whose auxdata
  reports `TP_STATUS_VLAN_VALID` (`afPacketAuxdataVLANTag`, fail-open when
  the cmsg is absent/truncated/`VLAN_VALID` clear, mirroring #2886). The
  VLAN-ness spelling is the single `isVLANInterfaceName` helper
  (`strings.Contains(ifName, ".")`, the same spelling `openSocketWith`
  routes to `maybeBindToDevice`). A VLAN child is exempt and keeps its own
  tagged adverts; untagged native adverts on the parent are kept. NOT
  changed: the cBPF filter — the same array is attached to parent and
  child sockets so it cannot express "drop tagged only on the parent",
  and `golang.org/x/net/bpf`'s VM cannot execute the `SKF_AD_VLAN_TAG_PRESENT`
  ancillary load, so a cBPF-only fix would be untestable in the #5088
  bpf.VM harness; the issue's stated `PACKET_AUXDATA and
  TP_STATUS_VLAN_VALID` option is the per-instance equivalent. The #6560
  loop test was migrated from the retired `afPacketRecvfrom` seam to
  `afPacketRecvmsg` (same deliveries, `oobn=0`).
