# #17213 — remove SetTLSCertDirForTest parallel TLS installer

- **Base**: `9bfb2516fd` (origin/master at branch creation; origin has since advanced — parent to rebase-check)
- **Branch**: `fix/17213-campaign`

## Why

`Server.SetTLSCertDirForTest` was a 44-line exported post-construction hook that
re-implemented per-leg HTTPS certificate installation (swap `certGen`, reload via
`loadManagementTLSCertificateLocked`, restamp each leg slot, rewire
`GetCertificate`, `RegisterHTTPServerTLSState`) because the self-signed cert
directory was a package constant (`tlsDir`/`certPath`/`keyPath` =
`/etc/xpf/tls/...`). Every change to per-leg certificate state (#10827 validity,
#14984 per-family slots) had to be made twice, and daemon TLS cells observed the
hook's install sequence rather than production's (`buildHTTPSServer`).

STEP-0: defect live on current origin/master — hook present at
`pkg/api/server.go:1902` (44 lines), 27 call lines in pkg/api + pkg/daemon tests,
0 production callers.

## What

- `pkg/api/server.go`: added `Config.TLSSelfSignedDir` (empty defaults to new
  `defaultTLSSelfSignedDir = "/etc/xpf/tls"`). `NewServer` derives
  `cert.pem`/`key.pem` inside that dir and installs `certGen` from it, so the
  production leg build (`buildHTTPSServer` → `loadManagementTLSCertificateLocked`
  → per-leg slot → `RegisterHTTPServerTLSState`) is the only install path.
  Deleted `SetTLSCertDirForTest` entirely. Replaced the `tlsDir`/`certPath`/
  `keyPath` constants with `defaultTLSSelfSignedDir`; `generateSelfSignedCert*`
  (production-path helpers) derive their paths from it. Stale comment in
  `tightenTLSPathPerms` referencing the hook removed.
- Acceptance greps: `grep -rn SetTLSCertDirForTest pkg` (Go) → 0 (historical
  mentions remain only in `docs/issues/pr-history.md` / old `docs/log/*.md`,
  which are records, not code). `RegisterHTTPServerTLSState` call sites in
  non-test code are now only `buildHTTPSServer` (server.go) and the
  recovery path (`recoverHTTPSLegsIfNeeded`, tls_certificate_10827.go) plus
  its definition.
- Tests migrated to construction-time injection:
  - pkg/api: `cert_reconcile_hosts_15228`, `conn_bound_16081`,
    `listener_dualstack_14583`, `tls_cert_dualstack_14984` (incl. its
    single-stack control, which previously relied on the hook-less production
    path — now pinned to a temp dir for hermeticity), `tls_certificate_10827`
    remint cell now constructs with `TLSSelfSignedDir: dir` and reconciles.
    `listener_shrink_adopt_15228` / `listener_swap_14983` never enabled TLS —
    hook calls dropped with no replacement. `leg_slot_identity_6734`
    ReconcileHTTPS cell now points its bare-server `certGen` at a
    `t.TempDir()` (it previously derived its paths from the real
    `/etc/xpf/tls` default).
    `tls_deadbind_cert_reload_7041` bare `&Server{}` fixtures (which bypass
    NewServer) now assign `certGen` via a local `selfSignedCertGenForDir`
    helper — the same closure NewServer installs; this is fixture wiring, not
    a production seam.
  - pkg/daemon: new `cfgForDir` helper (management_5866_test.go) pins the dir
    at construction. `TestMgmtReconcileTLSChange_5866`, `serveStaleCert`,
    the #6827 debt/dead-leg/generation cells, `promote_reconcile_6718_6720`
    and `webmgmt_rebind_14582` envs now carry the dir on the start/base config
    (mirroring production, where `desired()` inherits `baseCfg`), so the
    seeded durable pair is loaded by the production reconcile path.
  - The #6827 boot-delivery cell's stated limit updated: with #17213 the
    pre-construction seam exists, but that cell's committed config still names
    no HTTPS leg, so it still cannot reach a certificate — limit unchanged in
    substance, reason corrected.
  - READMEs (pkg/api, pkg/daemon) updated where they described the hook as the
    reason the boot cell is limited.

Scope note: `Config.TLSSelfSignedDir` is a string field, so the #9443
func-field binding cell (`TestAPIServerConfigBindsEveryHook_9443`) is
unaffected; the daemon deliberately leaves it empty (production default).

## Risk

Low. Production behaviour unchanged when `TLSSelfSignedDir` is empty (daemon
never sets it): same `/etc/xpf/tls/cert.pem|key.pem` paths, same loader.
The only production delta is path derivation via `filepath.Join` on the same
directory. Test hermeticity improves: several cells that previously minted
against the real `/etc/xpf/tls` at construction (then swapped) now never touch
it. Residual: bare-`&Server{}` fixtures assign `certGen` directly rather than
going through `Config.TLSSelfSignedDir` (the 7041 cells via the local
`selfSignedCertGenForDir` helper, the 6734 ReconcileHTTPS cell via an inline
closure) — pre-existing fixture pattern, unchanged in kind — but every such
fixture now targets a temp dir, never the host certificate directory.
