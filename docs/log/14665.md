# #14665 — Missing outer-destination validation and composed SNAT+DNAT private-IP leak in embedded ICMP NAT matchers

Finding `D4-02` (gemini hostile deep-review). Both re-review passes gate
MATERIAL with the narrowed scope: (1) port the NAT64 outer-destination
gate to the same-family matchers, (2) validate the composed SNAT+DNAT
leak on the composed builder path before fixing it.

## Defect 1 — outer destination never validated (v4/v6/session matchers)

`nat64_match.rs` enforces `hdr.src == outer_dst_v4` (:165) /
`hdr.src_wire == outer_dst_v6` (:292) — an ICMP error is addressed to
the source of the offending packet (RFC 792/4443), so that equality is
the anti-spoof gate. `match_outer_v4`, `match_outer_v6`, and
`try_embedded_icmp_session_match_from_frame` had zero `outer_dst`
references: a quoted tuple alone authorized the match regardless of
the error's actual outer destination. The SNAT-outbound builders never
rewrite the outer destination, so an internal host with one SNAT
session could address a re-NAT'd error to any reachable host,
defeating egress-destination policy; an external quoter could likewise
address an error anywhere and have it rewritten/delivered.

Narrowing vs the raw claim: the gate cannot be the literal
`outer == quoted src` on the forward-NAT arm — there the quote is the
post-NAT forward packet, so a genuine error is addressed to the
translated source. The fix checks the translated equivalent there
(`rewrite_src` when set, else the quoted source) and the plain quoted
source on the session-fallback arm (pre-NAT/untranslated quotes). A
naive literal gate would have broken every SNAT'd inbound error (the
existing poll fixtures, whose outer dst is the SNAT address while the
quote's pre-NAT source differs in form, pin this).

Placement: the forward-NAT check sits inside the `if let Some(fwd)`
arm after the lookup (it needs the decision); the fallback check sits
before the fallback probes. Both run before the F-077 budget charge,
so a declined error never consumes budget. `BudgetDenied` semantics
unchanged; a gate failure is `NoMatch`/`None` (fall through to
ordinary flowless enforcement, exactly like the NAT64 gate).

Reverse-companion reply quotes (`is_reverse && !via_reply_key`,
#10672): the gate requires outer dst == quoted (reply) source, which
is exactly how such an error is addressed; the builders rewrite the
outer dst to that same quoted source, so the delivered frame is
unchanged. NAT64 sessions are unaffected — the NAT64 arm runs first
and declines cross-family `original_src` in the same-family builders.

## Defect 2 — composed SNAT+DNAT outbound leak (validated, then fixed)

Session: client `10.1.1.5:12345` → VIP `198.51.100.80:443`, forward
decision `rewrite_src=pool 172.16.0.1:40000`,
`rewrite_dst=backend 172.16.0.50:8443`. Production installs both
halves; the wire reply is `backend:8443 → pool:40000`, the pre-NAT
reply the client sees is `VIP:443 → client:12345`. The client's
outbound error quotes that pre-NAT reply; its as-is key equals the
reverse half's translated alias, so the as-is probe wins (#14628) and
the reverse-half decision is the REVERSED one
(`rewrite_src=VIP:443`, `rewrite_dst=client:12345`). Pre-fix the
reverse-half shape check required `rewrite_src.is_none()`, so
`outbound_snat` stayed false and the #5690 reversed builder emitted
the private client/backend addresses with an unassociable quote.

Fix (both families): (1) the reply-key arm drops
`rewrite_dst.is_none()`; (2) the reverse-half arm also accepts the
composed shape (`rewrite_dst` set AND `rewrite_dst_port` set — a
DNAT port rewrite — alongside the existing pure-source shape);
(3) an outbound match now recovers the pre-DNAT wire destination into
`original_dst`/`original_dst_port` — from the forward companion's key
on a reverse-half hit, from the quoted source on a forward-half hit —
and the SNAT-outbound builders restore outer dst, quoted src, and
quoted src port from those fields when a destination rewrite exists
(plus the v6 quoted ICMPv6 pseudo-header delta). DNAT-only (no source
rewrite) keeps the pre-#6474 identity bit-for-bit: the existing
marker test's DNAT-only cell now pins exactly that (its comment
previously mislabeled the composed case as DNAT-carrying).

Not folded in: the report's "session matcher forwards verbatim" leg
is test-only surface (no production caller — see the #9901 note in
`session_match.rs`); it gets the gate for when it is wired, but no
production forwarding changes through it.
