# Issue #13098 — `validateVRFOverlap` dedup / dead-PBR / tolerant desync (D2-09)

- **Issue:** Three defects in `pkg/config/compiler_validate_vrf_overlap.go` (deep-review D2-09, research-validated): (1) `addPrefix` deduplicated `seen[riName]` by masked prefix alone, so a native member prefix silently dropped a PBR-steered claim for the same prefix and blinded the #9809 cross-filter `steeredAll` check; (2) `sawPBRRoutingInstance` was set before the `PBRDirectionSteers` none-check, so a dead PBR term (empty prefix-list; the builder installs no rule) promoted a plain native overlap to a #7924 strict rejection / tolerant admission; (3) `validateVRFOverlap` runs in `runTailGates` before the tolerant RI quarantines rewrite `RoutingInstances`, so `cfg.Warnings` described the pre-quarantine membership while `TolerantVRFOverlapAdmissions` (re-run on the returned config by the metrics collector) described the post-quarantine one.
- **Context read:** Issue body, source report finding D2-09 (`/var/tmp/deep-review-reports/gemini-4-argon-high-review-zone-enforcement-001.md` §91), the d2 probe (`TestD2Probe_09_VRFOverlapDedupAndEmptyPBRAndTolerantDesync`), `compiler_validate_vrf_overlap.go`, `pbr_steered_space_9809.go` (`PBRDirectionSteers`, `RoutingInstanceMemberUnits`), `compiler.go` compile ordering, `compiler_tailgates.go`, `compiler_validate_strict_ri_dual_claim_11060.go` (`quarantineRIDualClaimDevices`), `compiler_validate_strict_mgmt_ri_member_11392.go` (`quarantineRIRoleMembers`), `routing_instance_member_devices.go` (primary claims), and the existing #2387/#7924/#9809/#5194 test suites. All three sub-defects reproduced on current `origin/master` (0de689831) with the research probe.
- **What:**
  1. Dedup key now carries the steering identity (`prefix|native` vs `prefix|steered|<filter>`, plus `|all` for match-all), so a native claim and a steered claim for the same prefix coexist; same-identity repeats (including family-agnostic filters duplicated into Inet+Inet6) still collapse.
  2. `sawPBRRoutingInstance = true` moved after the `srcNone || dstNone` continue: only terms the PBR builder actually installs (including prefix-less match-all terms) count as live steering.
  3. Native collection also reads `cfg.QuarantinedRIMemberPrimaryClaims` (the surviving primary fanout recorded by tolerant quarantines), and `compileExpanded` re-runs the detector leniently after the dual-claim/role quarantines (`refreshVRFOverlapWarningsAfterQuarantine`), replacing the stale overlap warnings in place so `cfg.Warnings` and `TolerantVRFOverlapAdmissions` describe the same effective config. Strict compiles never quarantine, so the strict #7924 rejection is unaffected; tolerant/strict doctrines stay fail-closed (dead terms steer nothing and no longer reject; live cross-filter steered overlaps now reject as #7924/#9809 intend).
- **Layer choice:** All three fixes sit in the single detector (`validateVRFOverlap`) plus one post-quarantine refresh at its only compile call site. Moving `validateVRFOverlap` itself after the quarantines was rejected: the quarantines are deliberately deferred so legacy tail validators see authored memberships (#11060), and `runTailGates` owns the strict first-error slot. The refresh is tolerant-only and preserves warning order.
