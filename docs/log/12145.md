# #12145 — make-latest preserves its signed pointer on signing failure

- **Timestamp**: 2026-10-08 (`fix/12145-make-latest`)
- **Action**: preflight minisign and configured secret-key paths, stage `latest.json` and its signatures beside the live files, then replace the live manifest and signature sidecars only after staging succeeds.

## Red before

On base `a714c90d472a3c3d98a3799831cfef3ec311a61c`, a bounded fixture created and verified an old signed pointer, then advanced to a new version with a missing secret key. `make_latest` wrote the new JSON before signing failed; verification rejected the old signature against the new JSON, and a retry refused the invalid existing pointer. The new regression tests also failed before the implementation: missing-key and injected-signing-error cases each observed a changed live `latest.json`.

## Change

- `make_latest` now checks that minisign is present and each configured secret-key path is a file before modifying the channel pointer.
- It writes JSON to a same-directory temporary file, signs that staged file, preserves existing file modes, and replaces the live JSON/signature sidecars only after signing succeeds. Temporary artifacts are cleaned on failure; stale key-addressed signatures are removed after success.
- Regression coverage verifies that missing-key and injected-signing failures leave the prior JSON and signatures byte-identical and verifiable, clean up staged files, and allow a later valid retry.

## Validation

- **RED before**: `python3 /tmp/12145-red-repro.py` on the base logged the torn JSON, failed verification, and refused retry.
- **GREEN after**: the same fixture after the fix reported the old pointer remained byte-identical and verifiable, then a valid retry advanced and verified the new pointer.
- **RED regression tests**: the full `scripts/dist/test_dist_multi_key_rotation_10767.py` module ran before the fix and failed both new signing-failure cases.
- **GREEN scoped suites**: `python3 scripts/dist/test_dist_multi_key_rotation_10767.py` (12 tests), `python3 scripts/dist/test_dist_resign_9920.py` (38), `python3 scripts/dist/test_publish_provenance.py` (17), `python3 scripts/dist/test_publish_snapshot.py` (4), and `python3 scripts/dist/test_publish_url_validate.py` (4) all passed after the fix.
- **Syntax checks**: `python3 -m py_compile scripts/dist/publish.py scripts/dist/test_dist_multi_key_rotation_10767.py` and shell syntax check passed. No live-cluster mutation or project-wide suite was run.

## Residual / risk

The JSON and detached signature sidecars are separate files; their successful `os.replace` operations are sequential, not atomic as a pair. Signing failures are staged before either live replacement, which prevents the reported failure mode, but a process crash or filesystem error between the manifest replacement and sidecar replacements can still expose a mismatched pair to a concurrent reader. No live publish or cluster validation was performed.
