# #18707: helper restart waits on fixed delays before forwarding

- **Timestamp**: 2026-11-01
- **Action**: Measured where an isolated helper crash spends its outage, then
  removed the three fixed delays on that path.
- **Prior evidence** (#18702's live cell, udp, 70,526 spawn-flushed rows,
  journal `short-precise`, VM clock; the 1.6 s probe could not split it):

  | event | t (s, from exit) |
  |---|---|
  | exit detected, restart scheduled `attempt=1 delay=1s` | 0.000 |
  | spawn (`event stream: listening`) | +1.001 |
  | spawn flush done (70,526 rows) | +1.072 |
  | `helper started` | +1.174 |
  | `apply_snapshot` / `set_forwarding_state armed=true` (first status tick) | +2.180 |
  | worker binds | +2.20 .. +2.99 |
  | ctrl prewarm + `starting XSK liveness probe` (ctrl=1) | +2.991 |
  | `bootstrapping NAPI queues reason=startup-prewarm` | +3.062 |
  | `XSK liveness proven` | +5.177 |
  | `RG readiness: ready` | +5.563 |

  The spawn-time 3 s NAPI timer would have fired at about +4.2 and was
  swallowed by the prewarm's 2 s debounce, so it was not on the critical
  path in this run. The 1 s backoff and the 1 s wait for the first status
  tick were.
- **Changes**:
  - First retry of a crash episode is immediate
    (`helperRestartDelay(1) == 0`); repeats keep the exponential schedule.
    Cumulative wait before the crash-loop cap is unchanged (63 s), so HA's
    `CrashLooping` response is not reached sooner; it trips at attempt 8
    instead of 7.
  - The crash restart's status loop runs its first pass immediately
    (`ensureStatusLoopFirstPassNowLocked`).
  - The spawn-time 3 s NAPI timer is replaced by a once-per-generation,
    non-debounced bootstrap fired when the status reports every binding
    bound (`ensureXSKBoundNAPIBootstrapLocked`), with the #10436 fence.
