# #13666 — parallelize WireGuard endpoint refreshes

The endpoint resolver ran blocking `to_socket_addrs` calls in peer order. A
slow or unreachable name service therefore delayed every peer after the slow
lookup, so multi-peer DDNS refreshes could remain stale for the duration of
multiple sequential resolver timeouts. The resolver now runs lookup-only work
in a pool of up to eight scoped threads that pick up remaining lookups as they
finish. Results are applied afterward in original peer order on the resolver
thread. Existing address-family selection, last-good retention, error counters,
and error ordering are preserved; a worker panic is counted as that peer's
failed lookup instead of aborting the pass.

The regression tests verify bounded concurrent execution and complete result
application; hold the first of nine lookups while proving the ninth starts
without waiting; and inject a worker panic to ensure its healthy sibling's
successful result is still applied.
