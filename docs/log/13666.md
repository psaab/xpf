# #13666 — parallelize WireGuard endpoint refreshes

The endpoint resolver ran blocking `to_socket_addrs` calls in peer order. A
slow or unreachable name service therefore delayed every peer after the slow
lookup, so multi-peer DDNS refreshes could remain stale for the duration of
multiple sequential resolver timeouts. The resolver now runs lookup-only work
in a pool of up to eight scoped workers that pick up remaining lookups as they
finish, and applies each completed result immediately on the resolver thread.
This lets a fast peer adopt its address while another peer is still resolving.
Existing address-family selection, last-good retention, and error counters are
preserved; a worker panic is counted as that peer's failed lookup instead of
aborting the pass.

Dropping the resolver sets its stop flag and detaches its thread rather than
blocking tunnel teardown on an uncancellable DNS lookup. Workers stop claiming
new peers and discard outstanding results after shutdown begins.

The regression tests verify bounded concurrent execution and complete result
application; hold the first of nine lookups while proving the ninth starts and
is applied before release; inject a worker panic to ensure its healthy sibling's
successful result is still applied; and verify resolver Drop returns while
lookups remain blocked without scheduling the ninth peer.
