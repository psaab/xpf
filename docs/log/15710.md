# Issue #15710 — system archival / root-authentication / no-redirects state-loss defects

## Defect

Three coupled state-loss legs at `f214fac` (partly fixed by #15018 at HEAD):

1. **Multi-`configuration` archival wipe.** `compileSystem`'s `archival`
   arm used `child.FindChild("configuration")` — only the FIRST
   `configuration` block under one `archival` was read. A second block's
   `transfer-interval` / `archive-sites` were dropped, and a packed
   `transfer-interval 10 transfer-interval 30` run kept the first value
   instead of last-wins.
2. **Compact spellings dropped to false.** `configuration
   transfer-on-commit` packs the flag onto the `configuration` node's
   `Keys` with no children; the `FindChild`-only reader missed it, so
   `TransferOnCommit=false`. Likewise `system no-redirects;` packs the
   flag onto the `system` node's Keys; neither `compactNormalizeInScope`
   nor the child walk admitted it, so `NoRedirects=false`. (Braced and
   flat-set spellings worked; multi-stanza braced archival/root-auth
   merge itself was already fixed by #15018 and is pinned as a control.)
3. **Deleting `system no-redirects` never restored the kernel.**
   `applyNoRedirectsPosture` early-returned when inactive and
   `applyKernelTuning` only stored the new bool, so once the daemon
   wrote `0` to `send_redirects`/`accept_redirects` under
   `/proc/sys/net/{ipv4,ipv6}/conf/*`, deleting the stanza left them at
   0 for the daemon's lifetime — irreversible kernel state.

## Fix

- `pkg/config/compiler_system.go`: the `archival` arm now iterates
  `child.FindChildren("configuration")`, expands each block via
  `packedBodyChildren(cfgNode, archivalConfigurationSchema8939())`
  (falling back to the existing `expandFlatRun` for braced packed
  children), reads `transfer-on-commit` sticky-true, iterates all
  `transfer-interval` children last-wins, and appends every
  `archive-sites` entry across all blocks. Allocation-once (#15018)
  is unchanged.
- `pkg/config/compact_normalize_scope.go`: admit
  `("configuration", "transfer-on-commit")` and
  `("system", "no-redirects")` to `compactNormalizeInScope` (both are
  valueless flag leaves, so no body can be stranded). The stale
  `system no-redirects` no-body registration in
  `TestUnadmittedTopLevelPairsAreAdjudicated8925` is removed, the two
  sites leave `compact_block_divergences_2419.txt` and
  `compact_block_permanent_exclusions_8690.txt`, and they are anchored
  in `filedFixed` (#15710) so the census keeps checking both directions.
  Note: `TestPermanentExclusionsMatchTheInventory8690` and parts of the
  #8690 census already fail on unmodified `origin/master` at this head
  (17 stale `open` BGP/ISIS/RA lines, 2 unclassified sites, `security
  pki` adjudication) — pre-existing drift from sibling lanes, not
  introduced here; the two #15710 lines were removed surgically rather
  than regenerating the inventory (regeneration pulls in dozens of
  unrelated sibling-lane sites).
- `pkg/daemon/no_redirects_13982.go`: shared `redirectFamilies` table
  and `writeRedirectKnobs(value)` walk; `reconcileNoRedirects(active)`
  does `wasActive := noRedirectsActive.Swap(active)` — asserts `0`
  while active, and on the active→inactive transition writes `1`
  (kernel default) exactly once. A never-active daemon writes nothing.
  `applyKernelTuning` now calls `reconcileNoRedirects` instead of
  store+posture; `applyNoRedirectsPosture` (transit-gate re-assert)
  is unchanged in behaviour.
