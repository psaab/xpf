# #12080 — require post-commit near-miss liveness

- **Issue**: #12080 — the routing-separation gate used a pre-commit same-tuple control to establish capture liveness for a post-commit probe.
- **Branch**: `fix/12080-nearmiss-void`
- **Worktree**: `/var/worktrees/12080-nearmiss-void`
- **Base**: `1c384b9a47ff7d6e567fa50632faa75c3995ae87`

## Why

The exact-tuple control was sent before the FBF term commit. Its capture could not prove that a permitted flow remained visible after steering was active, yet its counts let the verdict PASS when the later probe was absent. A suppressed post-commit control must make the capture unproven and return VOID, not reuse the earlier burst as liveness.

## What

- Retained the pre-commit exact-tuple burst as separately reported evidence and restored its forwardability requirement: `precommit_control_observed` must meet `WIRE_DROP_FLOOR` for a PASS. If the exact probe tuple was not observed before the steer, the result is `VOID reason=env-void`, even when the post-commit near-miss forwards.
- Added a post-commit near-miss burst with the same source/destination addresses, protocol, direction, and peer capture, differing only in destination port from the FBF-steered probe. The capture filter includes both destination ports; the probe sender adds the `N` tag for this control.
- `wire_routing_separation_verdict` requires both controls for PASS: the post-commit near-miss proves capture liveness; the pre-commit exact tuple proves the probe tuple was forwardable before steering. A suppressed post-commit control remains `VOID reason=capture-blind`.
- Scored output consistently uses `control_offered/control_observed` for the post-commit near-miss and `precommit_control_offered/precommit_control_observed` for the earlier burst. Historical ledger rows use `control_*` for the pre-commit burst. The fixture format and harness-result fixture cover both control legs.
- Kept #11416's populated-RI, IPv6, and return-path positive legs out of this change; those legs remain owned by #11416.

## Astra R2 MAJOR F1 — keep liveness in the probe window

### Why

The complete post-commit near-miss burst still ended before the probe began.
If forwarding stopped after that burst, the earlier observations could certify
an absent probe even though the dataplane was unavailable during the probe.

### What

- The probe sender emits the near-miss (`N`) immediately before each probe
  (`P`) packet on one socket, then sends a 500-packet near-miss tail after the
  complete probe burst. The gate requires at least one observed packet in the
  last 100 control sequence numbers; losing only the final datagram does not
  void a healthy capture.
- The emitted `WIRE_GATE` metric keys remain unchanged for
  `harness_adapt_wire_gate`; the fixture input now requires
  `near_miss_tail_observed`, the number of captured near-miss packets in that
  post-probe tail.
- Added a localhost UDP-relay regression that reproduces the stale `C → N →
  outage → P` false PASS, then verifies both a late outage after 1,000 N frames
  (aggregate PASS, tail-aware VOID) and a healthy capture missing only the
  final N datagram (tail-aware PASS).

### Validation

- RED-before: the loopback relay observed `C=1500/1500`, `N=1500/1500`, then
  forwarded no `P` frames (`P=1000/0`); the old aggregate verdict returned
  `PASS` (exit 0).
- GREEN-after full outage: interleaved `N=1500/0`, `P=1000/0`, and no tail
  observations returned `VOID reason=capture-blind` (exit 2).
- Late-outage control: after 1,000 N frames were peer-observed and before the
  final probe, aggregate-only scoring returned `PASS`; the post-probe tail
  returned `VOID reason=capture-blind`.
- Healthy-minus-final-N control: the relay dropped sequence 1499 but delivered
  99 other tail controls. The tail-aware reducer returned `PASS`.
- `TMPDIR=/tmp bash test/incus/wire-routing-separation.sh --selftest` — 21
  passed, 0 failed (all original cases plus tail-verdict and relay controls).
- `TMPDIR=/tmp bash test/incus/harness-result-selftest.sh` — 213 passed,
  0 failed; adapter transcription retained the existing metric keys.
  `harness_adapt_wire_gate` requires `probe_offered`, `probe_leaked`,
  `control_offered`, and `control_observed`; its routing fixture passes with
  the tail field as input and no new output metrics.
  Standalone relay regression also passed with RED-before, full-outage VOID,
  late-outage aggregate PASS/tail-aware VOID, and healthy-minus-final-N PASS.
- `bash -n`, Python byte-compilation, and `git diff --check` passed.

### Risk / residual

- Tail liveness is conservative: if all 100 reserved post-probe control
  sequence numbers are absent, the result is VOID even when earlier controls
  were visible. A single missing final datagram is covered by the healthy
  control and still passes when another tail datagram is captured.
- No live cluster or DUT run was performed. #11416 still owns the populated-RI,
  IPv6, and return-path positive legs.
