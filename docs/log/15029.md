# #15029 — DHCP pool with no subnet commits clean and renders `"subnet": ""`

- **Timestamp**: 2026-10-18
- **Action**: refuse an empty DHCP pool subnet at strict commit (warn on the tolerant path), skip a subnet-less pool with a warning in both Kea generators, and flip the #14601 "dns-server only (no subnet) commits" control into a refusal.
- **File(s)**: listed under Change.

## Defect

`validateDHCPPoolValuesStrict` (#14601) guarded every subnet check with
`if pool.Subnet != ""`, so a pool with no `subnet` leaf skipped all of
them while its range/router/dns checks (which do not need a subnet) still
ran. The config committed clean, and `generateKea4Config` /
`generateKea6Config` emitted the pool verbatim as a Kea `subnet4` /
`subnet6` entry with `"subnet": ""`. Kea refuses an empty subnet and
loads nothing, so every pool of that family on the node stopped —
including healthy pools — while the commit printed `commit complete`.
The #14601 test suite pinned the hole as legitimate:
`control: pool with dns-server only (no subnet) commits`.

## Change

- `pkg/config/compiler_validate_strict_dhcp_pool_14601.go`:
  `validateDHCPPoolValuesStrict` now returns an error naming
  server/group/pool when `pool.Subnet == ""`, before the prefix-shape
  and family checks. The tolerant path (`lenientDHCPPoolValues`) keeps
  downgrading this to a warning, so a persisted subnet-less pool still
  boots (#1960).
- `pkg/dhcpserver/dhcpserver.go`: both Kea generators skip a
  subnet-less pool with a `m.warn` naming group/pool, before
  `claimPoolSubnet` and `resolveSubnetID`, so a skipped pool consumes
  no subnet id and healthy pools keep their ids. This covers configs
  that reached the renderer through the tolerant path. A mistyped
  non-empty subnet still renders as before (commit is its gate; there
  is no safe arbitration for it).
- `pkg/config/dhcp_pool_values_14601_test.go`: the flipped control now
  expects a refusal naming the pool and `subnet`.
- `pkg/config/compiler_dhcp_group_multivalue_6696_test.go`: pool
  fixtures that existed only to exercise multi-value
  `interface`/`dns-server` reads now declare the subnet the pool needs
  to commit (`192.0.2.0/24` / `2001:db8::/64`, containing their
  dns-servers), preserving what each cell measures.
- Cells: `pkg/config/dhcp_pool_no_subnet_15029_test.go` (C0 controls
  commit; C3/C4 v4/v6 dns-only and range-only subnet-less pools refused
  naming the pool; lenient paths warn), `pkg/configstore/
  dhcp_pool_no_subnet_15029_test.go` (same refusal through `CheckText`,
  the Store.Commit composition), `pkg/dhcpserver/
  kea_subnet_less_pool_15029_test.go` (both generators skip the
  subnet-less pool, emit no `"subnet": ""`, keep healthy subnets and
  ids byte-stable, and warn once naming the pool).
- `pkg/dhcpserver/README.md`: "Pool subnet / range / router /
  dns-server values — #14601" updated with the #15029 refusal and
  render belt.
- `pkg/config/compiler_uniformgates_dhcp_app.go`: gate comment records
  the #15029 leg.

## Validation

- RED (tests only, on `origin/master` ae59bd7d7): the new
  `TestDHCPPoolNoSubnetRefusedAtCommit15029` C3/C4 cells and
  `TestDHCPPoolNoSubnetLenientGate15029` fail with "want the
  subnet-less pool refused at commit, got a clean compile"; the C0
  controls pass on master, so the cells are not red for a fixture
  reason. The renderer cells fail with the subnet-less pool rendered
  as `{Subnet: Pools:[]}` (empty subnet).
- GREEN: see the PR body for the exercised suites (focused config,
  configstore and dhcpserver runs at the final head).

## Risk

- A config that today commits a subnet-less pool (e.g. a pool carrying
  only `dns-server` or only an `address-range`) will now be refused at
  commit/commit-check until a `subnet` is added. That is the intended
  fail-closed change: such a pool never served — Kea refused the whole
  file. On the tolerant load/peer-sync paths it still boots with a
  warning and the pool is skipped at render, so healthy pools keep
  serving.
- No behaviour change for any pool with a subnet: the C0 controls and
  the #9785/#14601 suites stay green.
