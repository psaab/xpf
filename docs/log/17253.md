# #17253 — Surface duplicate-pool NAT findings on tolerant loads

## Timestamp
2026-11-06

## Action

Strict NAT validation already rejected a single `then` block that authored
multiple distinct pools, but the tolerant enumerator only recorded action-count
and packed-mode contradictions. Consequently, a tolerant compile warned while
`LenientNATTerminalActionRules` omitted the duplicate-pool rule, leaving both the
gauge and `show security nat ... rule detail` blind to the active defect.

Added one sorted `natTerminalActionFindings` walk. The strict validator returns
its first finding's existing error, preserving first-offender ordering and
message semantics; the tolerant enumerator directly projects every finding,
without a reason whitelist, into a typed `LenientNATTerminalActionRule`. Its
resolved multi-action contradictions, packed-mode contradictions, and
duplicate pools. Packed findings report the count of
authored distinct modes even though lowering resolves them to one action;
`String()` and gauge cardinality are unchanged. NAT detail annotations state
that the first authored mode wins for packed contradictions, while resolved
multi-action findings retain fixed-precedence wording. Duplicate-pool wording
does not promise a particular pool: compiled fixtures show sibling destination
nodes resolve to the later pool, while a same-node duplicate with `off` retains
`off` and translates no pool. Metric help distinguishes each finding reason.
