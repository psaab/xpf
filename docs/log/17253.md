# #17253 — Surface duplicate-pool NAT findings on tolerant loads

## Timestamp
2026-11-06

## Action

Strict NAT validation already rejected a single `then` block that authored
multiple distinct pools, but the tolerant enumerator only recorded action-count
and packed-mode contradictions. Consequently, a tolerant compile warned while
`LenientNATTerminalActionRules` omitted the duplicate-pool rule, leaving both the
gauge and `show security nat ... rule detail` blind to the active defect.

Added one sorted `natTerminalActionFindings` walk. The strict validator returns
its first finding's existing error, preserving first-offender ordering and
message semantics; the tolerant enumerator projects every finding into a
`LenientNATTerminalActionRule`. The record now carries a typed reason for
actionless rules, contradictory actions, or duplicate pools. `String()` remains
unchanged. NAT detail annotations use the reason to explain the duplicate-pool
loss without treating it as a mode contradiction or defaulting unknown reasons
to actionless. The metric help text now names duplicate pools explicitly.
