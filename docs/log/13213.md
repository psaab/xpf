# Issue #13213 — align filter `then` parsing with policer actions

## Why

`compileFilterThen` diverged from the `#9882` policer `then` readers. It
ignored packed `then` keys on nodes that also had children, flattened
block-form modifier values into unknown sibling actions, and silently accepted
bare value-taking modifiers without their required value. Strict commits could
therefore accept an unpoliced filter term, while valid hierarchical actions
were rejected.

## What

The filter compiler now reads packed keys regardless of `IsLeaf`, shields
block-form values before flattening, reads values through `nodeVal`, and records
missing values as unknown actions so strict validation rejects them and lenient
compilation fails closed. The shielding helper now names its shared use by
filter, policer, and three-color-policer `then` paths. Regression coverage
exercises seven block-form modifiers, all seven valueless modifiers in
hierarchical and flat-set forms, and a mixed packed-keys-plus-children shape.

## Validation
- RED on pristine `origin/master` (`4b3a2b004`): new regression failed for all
  seven block-form modifier cases and all fourteen hierarchical/flat-set
  bare-value cases; the compiler accepted missing values and lost block values.
- GREEN: `go test ./pkg/config -run
  '^(TestCompileFilterThenBlockFormAndMissingValueParity13213|TestArityCensusIsRatcheted8807)$'
  -count=1` passed (including the arity census ratchet update for the
  `count` direct-key read removed in favor of `nodeVal`).
- Full `go test ./pkg/config -count=1` did not complete: it hit the package's
  10-minute timeout in `TestSchemaSpellingDifferentialGate` while running many
  concurrent bcrypt compiles. It also reported the arity census's now-obsolete
  `count` hit; that ratchet entry was removed and the focused census passed
  afterward. This is not a completed full-suite pass.

## Risk

Invalid bare value-taking filter actions now fail strict commit and are recorded
as unknown on lenient load, causing the existing fail-closed action behavior.
Valid block-form `then` modifier values are retained rather than being treated
as unknown actions.
