## Defect

Four sites operated on paths without establishing they own a regular file/dir, each next to a sibling that already refuses links:

- F-037 `NewDB` (`db.go`): `MkdirAllDurable` + `os.Chmod(dir, 0700)` with no `Lstat` — a symlinked `.configdb` has the TARGET's mode changed to 0700.
- F-038 `tailSegment`/`readAllLocked` (`journal.go`): bare `os.Open`/`os.ReadFile` — attacker JSONL renders as genuine history while `appendLocked` (`O_NOFOLLOW` + `IsRegular`) refuses the same link.
- F-108 `maybeRotateLocked`: `os.Stat` sizes through the link, `os.Rename` launders the LINK into `.1` — while `oldestSegmentHasInflightAppendLocked` deliberately uses `Lstat`.
- F-040 `ValidateFactoryResetRoot` is lexical ("does not resolve symlinks") while both wipes' `ReadDir` follows links — a root reaching a forbidden directory through a symlink is wiped with success reported. Production copy is `grpcapi.zeroizeConfigDir` (`FactoryResetConfigDir` has no non-test caller).

STEP-0: every member reproduced RED on base `0f69a6164` before implementing (spoofed entry rendered; `Log` succeeding with `.1` a link; wipes through links into forbidden roots returning nil). Nothing already-fixed.

Absent dirs still created; intermediate links still pass.
- F-038: new `openSegmentNoFollow` (`Lstat` pre-check incl. dangling + `O_NOFOLLOW` + `O_NONBLOCK` + fstat `IsRegular`), used by `tailSegment` and `readAllLocked`. Absent stays a tolerated gap; symlinked parents still work. Refusal is LOUD (Tail error, propagated by all `ListCommitHistory` callers) — silent partial history would be its own audit-integrity hazard.
- F-108: `Lstat` gate on the current path before `Stat`/`Rename`; symlink refused naming link+target. Rotated-slot links still shift by rename but are inert (readers refuse).
- F-040: new shared `configstore.ResolveFactoryResetRoot` — validates BOTH lexical and resolved paths (either refusal wins), absent stays a clean no-op, dangling final links refused. Both wipe copies resolve first and wipe the resolved target; both early-gate resolvers (`grpcapi` + `cli`) validate the resolved root but return the original path (wipe re-resolves authoritatively; byte-identical ordinary roots incl. symlinked TMPDIRs).
