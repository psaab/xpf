# #12654: validate route-filter prefixes in compact and term-line forms

## Reproduction and fix

The positional schema validator already rejected malformed prefixes in
hierarchical and flat-set route-filter nodes, but compact `from route-filter`
and term-line policy forms could compile prefixes such as `longer`, `garbage`,
a bare IP address, and out-of-range IPv4/IPv6 lengths without error. They
reached the renderer, whose existing malformed-prefix guard omitted the entry,
silently changing policy behavior.

The fully-compiled route-filter gate now parses every `RouteFilter.Prefix` as a
CIDR before match-type validation. Strict compile rejects an invalid prefix;
tolerant compile emits the existing route-filter warning and retains the
renderer omission behavior for compatibility. Valid IPv4 and IPv6 control
prefixes, including `/0`, `/32`, and `/128`, remain accepted. The shared gate
covers compact, term-line, flat, and hierarchical compiled route-filters.

## Fail-on-revert evidence

Before the fix, a temporary probe confirmed that compact and term-line `longer`
in the prefix slot, garbage, bare addresses, and `/33`/`/129` prefixes all had
nil `SchemaValidate`/`CompileConfig` errors where applicable; `CompileConfig`
and `CompileConfigLenient` returned no warnings. The hierarchical controls
already failed schema validation. After the fix,
`pkg/config/route_filter_prefix_slot_12654_test.go` exercises strict rejection
and tolerant warnings for compact and term-line bad prefixes, plus valid
IPv4/IPv6 controls.

## Validation

- `go test ./pkg/config -run 'TestRouteFilterPrefixSlot' -count=1`: PASS.
- `go test ./pkg/configstore -run '^TestTolerantSyncInvalidRouteFilterPrefixWarning12654$' -count=1`: PASS.
- `go test ./pkg/config/... -count=1`: FAIL after 10 minutes on existing
  unrelated failures in inventory census (#8662), API-auth expiry/credential
  behavior (#10826), packed routing-instance validation (#8787), and
  `TestSlotEscapeCoverage`; then timed out while computing bcrypt hashes. No
  new route-filter regression test failed in the suite output.
- `go test ./pkg/frr -run '^TestRouteFilterMalformedPrefixBelt$' -count=1`:
  PASS, covering renderer omission of malformed prefixes and fail-closed
  matching behavior.

## Risk

Strict commits that previously accepted an invalid prefix now fail with a
targeted error. Tolerant loads warn and preserve the existing renderer
omission, avoiding FRR-invalid prefix-list entries.
