# 16688 — logging: match event protocol filters by resolved number, reject unknown tokens

- **Timestamp**: 2026-10-25
- **Action**: `ParseEventFilterArgs` stored the `protocol` token raw and
  `EventFilter.matches` compared it with `EqualFold` against the rendered
  name (TCP/ICMPv6/ESP), so `protocol 6` (the value the view prints as
  `protocol-id="6"`), `58`, `50`, `icmp6`, and a typo like `tcpx` all
  yielded an empty answer with no error on every surface sharing the
  matcher — local CLI, remote ShowText, gRPC `GetEvents`, and REST.
  `EventFilter` now carries `ProtocolNum`/`HasProtocol` (mirroring the
  `HasZone` presence bit, so protocol 0/HOPOPT stays selectable);
  `matches` compares the resolved number against `rec.ProtocolNum`,
  falling back to resolving the rendered name only when `ProtocolNum==0`
  (mirrors `monitorFlowFilter`, #13553), and resolves a directly-set
  `Protocol` string through the same table so literal filters behave
  identically. New `logging.ResolveEventProtocol` wraps the
  `appid.ProtocolNumber` SSOT. All four builders resolve once and fail
  closed: `ParseEventFilterArgs` returns an `unknown protocol` usage
  error, gRPC `GetEvents` returns `InvalidArgument`, REST returns HTTP
  400 `invalid protocol filter: …`. NOT changed: action matching stays
  exact case-insensitive (#2939); an absent protocol stays "no filter"
  on every surface.

- **Validation**: New tests pass post-fix — logging: 18 protocol-token
  subtests (`6`/`58`/`50`/`icmp6`/`47`/`89`/`ospf`/`0` defect cells +
  name controls + legacy `ProtocolNum==0` fallback) plus unknown-token
  rejection (`tcpx`/`256`/`-1`/…) and direct-literal filters; gRPC:
  numeric/alias/absent/bogus (`InvalidArgument`); REST: same matrix
  (HTTP 400 on bogus). RED evidence: reverting only the `matches`
  protocol arm to the old `EqualFold(rec.Protocol, f.Protocol)` makes
  `protocol=6` return 0 events (want 2), `58`/`50`/`icmp6`/`47`/`ospf`/
  `17` likewise, and the direct-literal check fail. Existing pins stay
  green: `TestParseEventFilterArgs`, `TestEventFilterExactNotSubstring`
  (#2939, incl. `protocol=C` matching nothing), zone-0 (#3338) and
  limit (#4926) suites. `go vet` clean, gofmt clean.
- **Risk**: A hand-built `EventFilter{Protocol: "tcpx"}` previously
  matched nothing silently and still matches nothing (now fail-closed by
  construction); builders that previously accepted any token now error —
  the intended fail-closed change (#3347 class). Records with a non-zero
  `ProtocolNum` whose rendered name disagrees keep the number as
  authoritative, as in #13553. No enforcement-path effect.
