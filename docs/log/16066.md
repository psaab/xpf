# #16066 — ValidateCryptHash errors echoed the raw secret to logs

- **Timestamp**: 2026-10-20
- **Action**: stripped every raw-value interpolation from
  `ValidateCryptHash` and its per-algorithm helpers, so the validator's
  errors name only the defect class and the expected form. The daemon
  apply boundary (`reconcileUserPassword`, daemon_hostauth_apply.go)
  already logs and returns that error verbatim — with the validator
  value-free, that site (and every present/future caller) is safe by
  construction; no daemon change was needed.

## Root cause

`ValidateCryptHash` interpolated the submitted value with `%q` in every
error arm, including the plaintext branch (`not an encrypted password
hash (got %q)`). Redaction existed only on the typed-leaf schema path
(`typedLeafInvalidErrorf`, #8434), which the daemon apply boundary does
not traverse: a plaintext password pasted into `encrypted-password`
survives tolerant ingress (lenient Load/SyncApply downgrades schema
errors to warnings), reaches `reconcileUserPassword`, and its
`slog.Warn` + returned error carried the secret verbatim into
journal/syslog — forwarded off-box to log-aggregation tenants and
support-bundle consumers with lower privilege than the config author.
The config DB is root-only on-box; the log path was the widening.

## Fix

- `pkg/config/schema_validators_system.go`: every error in
  `ValidateCryptHash`, `validateSHA512Crypt`, `validateBcrypt`,
  `validateYescrypt`, and `validateScrypt` now names the defect class
  only (e.g. `not an encrypted password hash — plaintext is not
  allowed; generate a hash with ...`, `sha512crypt salt must be
  between 8 and 16 characters`). The helpers no longer take the raw
  value string. The sole remaining `%q` is the `default:` arm's
  algorithm id, which is unreachable (guarded by `cryptModularIDs`)
  and is a recognized non-secret token, not operator data.
- `pkg/config/schema_walk.go`: shared choke point (folds 1+2).
  `schemaErrorf`/`schemaPathErrorf` are now the only error
  constructors in the walker (grep-verifiable: no other
  `fmt.Errorf` in the file); they scrub every secret-indexed token
  (per `secretIndices`, the AST redactor's registry) from the
  formatted text. `typedLeafErrorf`, `typedLeafInvalidErrorf`,
  `validateScalarValueLeaf`, `validateTailLeaf`,
  `validateSecurityLogHostNode15270`, the #8437 fused-statement
  formatter, the closed-world/midKeyword/packed-credential arms all
  route through it. As the exit half, `SchemaValidateWithDefinitions`
  scrubs any secret token in the candidate tree from the returned
  error (preserving the typed-leaf classification), covering
  validators and node/tail validators whose errors are built in
  other files. Fold 1's trigger was the "unknown modifier %q" arms
  quoting an extra token after a valid `encrypted-password` value;
  fold 2's was the #8437 formatter quoting `backend` twice under
  the untyped DDNS `password`/`tsig-secret` leaves. Non-secret
  leaves keep their quoted diagnostics byte-identical.

## Remaining quoting sites on secret leaves — enumeration (#16090 fold 2)

Every error construction reachable from `SchemaValidate` was swept:

| Site | Disposition |
|---|---|
| `ValidateCryptHash` + 4 helpers (schema_validators_system.go) | Value-free at source (this PR); no raw interpolation remains. |
| `typedLeafInvalidErrorf` | Already redacted (#8434); now also passes through choke-point scrub (`scrubSecretTokens`). |
| `typedLeafErrorf` (validateTypedLeaf + validateModifierChild "unknown modifier %q" arms) | Routed through `schemaPathErrorf` (fold 1). |
| #8437 fused-statement formatter (schema_walk.go, sibling token %q+%s) | Routed through `schemaErrorf` with the node's full Keys (fold 2). |
| `validateScalarValueLeaf` trailing-token %q (×2) | Routed through `schemaPathErrorf` with the offending token in the path; no secret leaf currently takes the scalar opt-in, covered regardless. |
| `validateTailLeaf` (%v of tailValidator error) | Routed through `schemaErrorf` with leaf tokens; current tailValidators are all non-secret (CoS/BGP/scheduler/flow-trace/DHCP). |
| `validateSecurityLogHostNode15270` (host modifier %q) | Routed through `schemaErrorf`; `host` is not a secret leaf. |
| nodeValidator relay (%v), closed-world keyword %q, midKeyword %q (×2), valueless-leaf, #14412 packed-credential %q | All routed through `schemaErrorf`/`schemaPathErrorf`. |
| Validators in other files returning own errors (e.g. ValidateEnum "invalid value %q") | Cannot be rewritten centrally without changing their API; covered by the SchemaValidate exit scrub, which removes any tree secret token from the returned text. |
| `unknownSecurityZoneChildSchemaError` / `unknownSecurityPoliciesChildSchemaError12217` / `unknownTopLevelStanzaSchemaError` | Carry keyword/path only (paths already `redactSecretPath`'d); no value tokens. Exit scrub covers them too. |
| `validateStaticRouteQNHTails12813`, `checkRedactionPlaceholder` (pre-walk, in SchemaValidateWithDefinitions) | Return before the walk; they validate route/QNH tails and the redaction placeholder, neither carries secret-leaf operands today. Noted residual: if either ever formats a credential token it bypasses the exit scrub. |
