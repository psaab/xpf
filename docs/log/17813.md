# Issue 17813 — mask credentials in comment-only embedded commands

## Why

The embedded-command redactor treated every successful zero-token lex as an empty command. The config lexer skips `#` line comments and block comments, so a nonempty stored payload such as `# set security ike policy p1 pre-shared-key ascii-text SENTINEL` was returned unchanged. Redacted configuration renders and unsupported-command journal warnings could therefore retain the credential.

## What changed

- Keep only empty and whitespace-only payloads unchanged; replace every other zero-token payload with the existing whole-payload redaction placeholder.
- Preserve that placeholder in joined-tail and block-child AST rewrites, where re-lexing the `##SECRET-DATA##` placeholder itself produces zero tokens. Apply the same preservation to compare fingerprints.
- Treat comment-stripped renderings as changed when they differ from the authored payload, dropping credentials hidden in line/block comments while retaining surviving command tokens.
- Re-lex quoted comment-shaped payloads as embedded commands, so an opaque quoted `"# set ..."` token cannot bypass masking.
- Cover trailing and nested comments, quoted values, comment-line prefixes, quoted whole commands, all redacted render surfaces, compare, and the event-engine rejection log.

## Risk

Empty and whitespace-only payloads remain unchanged. In redacted views, nonempty comment text is removed when lexing changes the payload; surviving command tokens remain, and quoted comment-shaped payloads are masked fail-closed. The live config tree and executable command are not mutated; redaction applies to display, compare, and journal-warning output.
