# 10046 — FBF forwarding-instance next-hop qualification

- **Issue**: #10046
- **Root cause**: A forwarding-instance static default used a bare gateway (`172.16.80.1`) whose connected interface (`reth0.80`) remained in the default routing instance. Rust FIB inference is intentionally table-scoped by #4446, so the `ISP-B.inet.0` route kept `ifindex=0`; the FBF route lookup became `NoRoute`, then the NoRoute policy gate recorded a policy denial and recycled the frame. The kernel PBR table itself was correct.
- **Fix**: Route snapshots now qualify bare next-hops for `instance-type forwarding` tables with `address@interface` when a same-instance or default-instance connected prefix identifies the gateway interface. Virtual-router routes remain bare, preserving #4446 VRF isolation. Qualification runs after route overlays so an ip-monitoring replacement cannot reintroduce the broken bare gateway.
