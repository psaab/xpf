# 13669 — Retire worker holders after shutdown joins

## Boundary

`Coordinator::stop_inner` retired NAT holder bits and BPF steering rows before
stopping worker threads. Since holder retirement is one-shot, an exiting worker
could allocate NAT after the sweep and strand that reservation, while deleting
its active steering rows concurrently. The shared sweep also reported a
cumulative NAT count as if each subsequent worker had stranded that many
reservations.

## Fix

- Snapshot worker IDs and their shared runtime atomics before teardown clears
  records. Stop and join workers, join IPsec-inner termination, then retire NAT
  holders from the snapshot.
- Only panic-dead workers have their steering claims deleted from BPF and emit
  "stranded by dead worker" logs. Normally stopped workers leave BPF row cleanup
  to the established teardown behavior.
- Track the NAT count per worker for diagnostics while retaining the aggregate
  return value from the sweep.
- Keep the dead-only V_min recovery policy; teardown discards the V_min floors
  after the join and holder sweep.
