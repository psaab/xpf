# Issue #14410 — IS-IS per-interface authentication dropped on packed interface line

## Why

The IS-IS interface loop in `pkg/config/compiler_protocols.go` read only
`child.Children` (via `expandFlatRun`), plus a `child.Keys[2:]` shim that
recognised only `passive` and `level`. The packed spelling

```text
protocols { isis { net 49.0001.0000.0000.0001.00;
  interface ge-0/0/0.0 passive authentication-key IFACEKEY authentication-type md5; } }
```

packs the whole tail onto the interface node's own `Keys` with no
`Children`, so the loop read nothing: the interface compiled with
`AuthKey == ""` / `AuthType == ""` on a strict commit reporting success,
while the FRR renderer still emitted `ip router isis` and gated circuit
auth on the (empty) key — an unauthenticated IS-IS adjacency where the
operator configured MD5. `show configuration` displayed the key written,
so nothing looked wrong.

The #8662 fold could not rescue it: the fold is keyed on the FIRST tail
token and `passive` / `bfd-liveness-detection` are not scoped interface
pairs, so a leading `passive` strands the whole run; and the #8880
decline strands even a scoped head (`authentication-key …` first) when a
following router-level `authentication-key` sibling shares the keyword.

## What

- `pkg/config/compiler_protocols.go` (IS-IS `interface` case): when the
  interface node carries a packed tail (`len(child.Keys) > 2`), read the
  body through `packedBodyChildren(child, isisInterfaceSchema8939())` —
  the same schema-driven SSOT the OSPF interface loop uses — before the
  existing `expandFlatRun`. The braced spelling is untouched
  (`packedBodyChildren` returns `Children` unchanged when there is no
  tail). The `switch` cases, the #8436 find-or-create, router-level
  `area-password`/`domain-password` handling, metric `-1` parse-failure
  preservation, and BFD sub-children handling are unchanged; the
  `Keys[2:]` `passive`/`level` shim is kept (idempotent).
- Mixed tail+braced body (`interface … passive authentication-key K
  { authentication-type md5; }`): `packedBodyChildren` declines to
  expand when the packed tail ends in a leaf (its do-not-guess guard
  returns the braced `Children` alone). That decline is detected (same
  slice returned) and the tail is then expanded from a childless view
  of the node, reading both halves; an unmodelled tail still expands
  to nothing on that second call.
- New regression `pkg/config/isis_interface_packed_auth_dr13h3_test.go`
  (`TestISISInterfacePackedAuthDR13H3`): braced positive control,
  passive-first packed fixture, scoped-head fixture with a following
  router-level `authentication-key` sibling (also asserting the sibling
  still lands on the router, not the interface), a head-keyword matrix
  (passive / auth-key / auth-type / metric / level first), the mixed
  packed-tail-plus-braced-body cell, and the routing-instance spelling
  (shared `compileProtocols`).

## Validation

- RED on base `3541ce77e`: all five subtests fail with
  `AuthKey = ""` / `AuthType = ""` for the packed spellings while the
  braced control carries `IFACEKEY`/`md5`.
- GREEN after the fix, including after rebase onto `195f4137a`:
  `go test ./pkg/config/ -run TestISISInterfacePackedAuthDR13H3` passes.
- Neighbouring suites `TestProtocolAuthFlatRunKeepsEveryLeaf8939`,
  `TestISISMetric*`, `TestElidedAuthenticationKey*` pass.
- `TestElidedDepthCoverage8850/partially-elided` fails identically on
  unmodified base (verified by stashing the fix) — pre-existing,
  base-attributed, unrelated to this change.

## Risk

- Behaviour delta: packed IS-IS interface lines now install the
  credentials the operator wrote (previously silently dropped). No
  previously-working spelling changes: braced configs compile
  identically, and an unmodelled packed tail still yields no expansion
  rather than a guessed shape.
