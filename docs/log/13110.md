# Issue #13110 — validate zone members against declared interface identity

## Why

`validateZoneInterfaceDefinedStrict` split a zone member at its first dot even though `SplitInterfaceUnitRef` now gives declared dotted interface names precedence. It therefore rejected valid declared `p.0` / `p.0.1` members when no separate `p` interface existed. Conversely, `zoneReferenceableInterfaceBases` strips units from IPsec binds, so bare `st0` passed when only `bind-interface st0.0` existed, although that bind materializes `st0.0`, not `st0`; the clean commit left the actual tunnel unzoned.

## What

- Resolve the member base from `SplitInterfaceUnitRef` for referenceability, preserving declared-first dotted-name behavior.
- For a bare reference without an authored interface stanza (except always-present `lo0`), require the exact bare reference to resolve to a materialized secure-tunnel netdev; a dotted bind cannot claim its bare base.
- Add strict-commit rejection cases, valid declared-dotted/bare-bind controls, and tolerant-load warning coverage.

## Risk

Strict commits now reject a bare zone member that resolves only to a dotted secure-tunnel bind, avoiding a silent unzoned tunnel. Valid declared dotted names, real bare binds, configured interfaces, and the always-present loopback remain referenceable. Tolerant loads warn rather than reject invalid persisted configuration; no dataplane behavior is changed.
