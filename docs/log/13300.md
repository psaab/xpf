# Issue #13300: Expose userspace maps-sync telemetry

The userspace manager previously discarded three operational signals: failed
kernel RST-suppression installs, watchdog binding-map repairs/errors, and
skipped local-address pruning after incomplete netlink enumeration. Operators
could not distinguish healthy synchronization from these degraded paths in
Prometheus.

Manager-owned counters now accumulate those events and are stamped into
`ProcessStatus`; the RST suppression degradation gauge reflects active
interface-NAT addresses while the last install is unsuccessful. Prometheus
exports the gauge and four counters unconditionally, including zero values.

Regression coverage verifies status stamping and all five metric values. On
pristine `origin/master`, the new tests failed to compile because the status
fields and metric emitter did not exist. The focused tests and collector
descriptor-coverage test passed after the fix. `go build ./...`,
`go vet ./pkg/dataplane/userspace ./pkg/api`, and `gofmt -l` on touched files
passed. Full affected-package tests were run with both default and shortened
temporary paths; unrelated userspace tests still fail on Unix-socket `EINVAL`,
contract/snapshot golden drift, and Junos/zone parity assertions. The API
package passed in both runs.
