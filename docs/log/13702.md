# Issue #13702 — Reject corrupt empty policy addresses

## Why

The Go snapshot builder strips empty address elements and normalizes address-book `any` to concrete family-split `/0` CIDRs. A corrupt or hand-built Rust snapshot could nevertheless carry `""` in v3 policy literals or an empty/bare-`any` address-book family entry. The parsers treated these as no-ops, silently reducing a deny/reject predicate or book family to MatchNone and allowing later permit/default-permit rules to match.

## What

- `parse_v3_literal_set` and the legacy sibling now report empty-string elements through their existing malformed-address error paths; source and destination lists share those paths.
- `parse_book_prefix_into` rejects empty and bare `any` entries. Family-scoped wildcard tokens and concrete prefixes retain their existing handling.
- Regression coverage checks source/destination v3 symmetry, legacy behavior, both book families, and rejects a bare ambiguous `any` in either book family array. Existing empty-excluded semantics now use a genuinely empty address-book row instead of corrupt empty-string elements.

## Validation

- **RED mutant:** restoring the old no-op acceptance for empty legacy/v3 literals
  and address-book empty/`any` entries made all five new regressions fail (0
  passed, 5 failed); these paths match the pre-fix master behavior.
- **GREEN:** `cargo test 13702 -- --nocapture` passed all five regressions (5
  passed, 0 failed; 14 test suites matched, 8,190 filtered). To work around the
  pre-existing `#[cfg(test)]` import mismatch in `session_glue/mod.rs`, the
  test-only helper import was temporarily correctly gated and then restored;
  that unrelated file is unchanged in the final diff.
- **Policy module:** `cargo test policy::tests -- --nocapture` ran 32 of its 218
  tests before the command terminated without a test summary (tool returned
  exit 101 after 360 seconds). This is not reported as a passing module run.

## Risk

A nonconforming snapshot containing an empty address string or bare `any` in a family-specific address-book array is now rejected atomically instead of silently compiling a narrower predicate. Valid policy-literal `any`, family-specific book wildcards, and empty address-book rows remain supported.
