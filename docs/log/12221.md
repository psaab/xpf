# Issue #12221 — validate shadowed predefined application-set members

## Why

With AppID disabled, the strict application-spec walk visited only user-defined application-sets. A policy referencing the predefined `junos-sip` bundle therefore skipped a malformed user application shadowing its `junos-sip-tcp` member. Commit succeeded even though the userspace resolver would later encounter an unrepresentable port specification.

## What

The strict walk now expands referenced predefined application-sets as well as user-defined sets, collecting only expanded members that are user-defined applications. It preserves application-before-set precedence and the existing fallback that still validates direct user members when expansion encounters a dangling or over-nested member. Regression tests cover AppID-off rejection naming `junos-sip-tcp` and the AppID-on control.

## Validation

- **RED before** (`a714c90d472a3c3d98a3799831cfef3ec311a61c`): `go test ./pkg/config/ -run '^TestApplicationSpec_ShadowedPredefinedBundleMember_' -count=1 -v` failed because the AppID-off commit unexpectedly accepted the malformed member; the AppID-on control passed.
- **GREEN after**: the AppID-off regression and AppID-on control both pass.
- `go test ./pkg/config/ -run '^TestApplicationSpec' -count=1` passed.
- `go test ./pkg/config/ -run '^TestPredefinedSipPolicyCommits_5634$' -count=1` passed (valid built-in `junos-sip` policy remains accepted).
- `go test ./pkg/appid/ -count=1` passed.
- `go build ./pkg/config/ ./pkg/dataplane/userspace/` passed.
- `gofmt -l pkg/config/compiler_validate_strict_application.go pkg/config/compiler_application_specs_test.go` produced no output.
- Full `go test ./pkg/config/ -count=1` also exposed unrelated broader reds: stale inventory/census expectations, API-auth expiration fixtures, routing-instance expectations, and slot-escape coverage; it timed out after 10 minutes in `TestSchemaSpellingDifferentialGate`. On a clean `a714c90d4` worktree, the targeted tests for each of those broader failures reproduced them; the standalone schema-differential test also timed out after 10 minutes while hashing API-auth fixtures. The issue-specific application-spec suite and AppID suite pass.

## Risk / residual

The change is limited to commit-time strict application-spec collection; no dataplane lowering or predefined application behavior changed. The tolerant-load path continues to downgrade application-spec errors to warnings, so existing malformed configs remain loadable. No live cluster or apply path was exercised.
