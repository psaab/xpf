# #12546 — Pin CLI linker flags against GOFLAGS

## Why

`make build-ctl` invoked `go build` without a command-line `-ldflags` value.
Go therefore honored inherited `GOFLAGS=-ldflags=-X=...` and allowed linker
injection into the generated CLI binary. The daemon target already supplies its
own linker flags; the CLI target must not inherit linker settings either.

## What

- `build-ctl` now passes an explicit empty `-ldflags` value. This preserves the
  CLI's normal build while taking precedence over any inherited GOFLAGS linker
  injection. No changes to the shared provenance probe's refusal set are
  needed: this target pins its linker settings directly.
- The provenance fixture builds a CLI with a visible linker-settable variable,
  runs the real Makefile `build-ctl` target under hostile GOFLAGS, and asserts
  the resulting binary keeps its source default value.

## RED → GREEN

- **RED:** The regression built the fixture CLI with
  `GOFLAGS=-ldflags=-X=main.injected=pwned`; before the Makefile change the
  binary printed `pwned` instead of its default `clean` value.
- **GREEN:** With the target's explicit `-ldflags ""`, the same inherited
  GOFLAGS value produces a binary that prints `clean`.
