# #13965 — Put the PPTP call-id pair on the HA sync wire

## Why

The HA import gate (`verify_synced_pptp_association`, #7699) withholds a
synced session whose discriminator is `Pptp(handle)` unless the record also
carries the learned call-id pair from which the handle is derived, and the
pair recomputes the same handle. On master the pair field existed on the
Rust `SessionSyncRequest` and the gate read it, but no producer ever set
it: `SessionDelta` had no pair field, the binary event-stream frame did
not carry it, the Go `SessionDeltaInfo`/`SessionValue{,V6}` did not carry
it, and the cluster sync encoder never emitted it. Every PPTP session
synced to the standby was therefore withheld as
`pptp-call-ids-not-carried` — present on the active, absent after failover.

## What

Carry the pair end-to-end, fail-closed at every absent point:

- Rust session layer: `SessionDelta.pptp_call_ids`, stamped from the live
  association table (`pptp_call_ids_wire_for`) at every delta construction
  (open, bulk re-export, update, close, expiry, control close). Absent
  (0) for non-PPTP keys and unknown handles.
- Rust binary codec: the pair is appended as the final 8 bytes of the
  open/update frame; the JSON delta leg carries it via
  `SessionDeltaInfo.pptp_call_ids`.
- Go: `SessionDeltaInfo.PptpCallIDs` decoded length-gated after the
  source-NAT provenance byte; forwarded through
  `userspaceSessionFromDeltaV4/V6` into sync-only
  `SessionValue{,V6}.PptpCallIDs` (never the BPF/C ABI), then into
  `SessionSyncRequest.PptpCallIDs`.
- Cluster wire: appended as a final length-gated u64 in
  `appendSessionSyncMetadataTail`; the decoder reads it only when the
  discriminator tag is PPTP (2) and the present bit (1<<32) is set, so
  legacy payloads and non-PPTP records decode it as absent.
- Rust import: `build_synced_session_entry`'s verified call is threaded
  through `upsert_synced_session_with_pptp`; after the session replica is
  queued, `WorkerCommand::InstallPptpAssociation` installs the association
  on each worker via `install_synced_association` (no local control
  channel; an identical locally-learned association keeps its real
  control binding so FIN/RST cleanup still works). Mirror imports keep
  the previous behaviour (no association install), matching their
  publish-only semantics.

NOT changed: the gate itself, the handle derivation, and the
withhold-not-downgrade discipline. An old peer still syncs every other
protocol unchanged and its PPTP sessions are still withheld.

## Validation

Focused Rust and Go cells above. Full-suite and cluster smoke are the
parent review's gate; the binary frame change is append-only and
length-gated in both directions, and the cluster tail change is gated on
the PPTP discriminator tag plus the present bit.

## Risk

Rolling upgrade: a new sender to an old receiver appends 8 bytes the old
decoder length-skips; an old sender to a new receiver leaves the pair
absent and PPTP imports stay withheld (today's behaviour). No BPF/C ABI
change. Residual: bulk HA export from the shared synced map
(`snapshot_all_sessions_export`) carries no pair — those entries are
peer-synced or local forward rows re-exported through the delta stream
whose live producers now stamp the pair; a PPTP row whose association has
expired locally exports absent and is withheld on the peer rather than
aliased.
