# #16588: per-unit tunnel clones inherit earlier inheriting units' addresses

- **Timestamp**: 2026-10-24
- **Action**: `cloneForUnit` (pkg/config/types_routing.go) deep-copied
  `ifc.Tunnel.Addresses` into every per-unit tunnel clone. The interface
  tunnel has no address source of its own — its `Addresses` slice is only
  appended to by the compiler unit loop with the addresses of units that
  have NO per-unit tunnel, in processing order. In the natural order
  (unit 0 inheriting, units 1/2 with their own stanzas), units 1 and 2
  therefore cloned unit 0's `10.1.0.1/30` and `pkg/routing` installed the
  same IP/prefix on `gr-0-0-0`, `gr-0-0-0u1` and `gr-0-0-0u2` — the
  duplicate-IP harm #3898 was closed for, order-dependent and undiagnosed.
  Fixed by clearing `Addresses` in `cloneForUnit`: a per-unit tunnel's
  addresses are exactly its own unit's, appended by the compiler after
  the clone. Inheriting units (`unit.Tunnel == nil`) still share
  `ifc.Tunnel` and its collected addresses unchanged, and the other
  `cloneForUnit` caller (`mergeWireguardUnitPeers`, WireGuard peer merge)
  only reads `WgPeers`/`RoutingInstance`, so clearing is inert there.
  Compiler and emitter comments updated to state the new contract.
- **File(s)**: `pkg/config/types_routing.go`,
  `pkg/config/compiler_interfaces.go`, `pkg/config/tunnelemit.go`,
  `pkg/config/tunnel_perunit_deepcopy_test.go`, `docs/log/16588.md`.
- **Validation**: Extended `TestPerUnitTunnelAddressesIndependent` to
  assert the seed addresses (10.9.0.1/30, 10.9.1.1/30, 10.9.2.1/30) are
  absent from units 1/2 and that each carries exactly its own address;
  added `TestPerUnitTunnelDoesNotInheritEarlierUnitAddresses` pinning
  the acceptance shape (unit 0 inheriting 10.1.0.1/30 on gr-0-0-0,
  u1=[10.2.0.1/30], u2=[10.3.0.1/30] on distinct remotes); updated
  `TestTunnelConfigCloneForUnitDeepCopy` to pin that a clone starts with
  empty Addresses. RED-on-revert and targeted counts in PR body.
- **Residual**: None known. Kernel route selection between the former
  duplicates was the source report's unmeasured impact question; the
  applied-state duplication itself is removed at compile time.
