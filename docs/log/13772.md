# Issue #13772 — preserve outbound SNAT policy identity across fabric

An outbound SNAT ICMP error is re-NAT'd before it is queued for a fabric
redirect. The owning peer sees the translated outer source; its embedded
session match is an as-is reverse-half hit, so the #13649 local queued-result
source override is unavailable and policy can evaluate the public SNAT address
instead of the internal sender.

## Change

- On the owning peer, recover the internal sender from the reverse SNAT
  session's `rewrite_dst` only for fabric-ingress embedded errors whose public
  outer source matches the quoted public destination.
- Carry that source identity into the existing queued-prebuilt policy gate;
  preserve the translated source in the actual transmitted frame.
- Add a two-pass split-RG fabric regression with internal-deny/public-permit
  and internal-permit/public-deny policy mirrors.

## Validation

`cargo test poll_descriptor_snat_outbound_icmp_error_fabric_redirect_judges_pre_snat_src_13772 -- --nocapture` failed at the internal-deny assertion with peer identity recovery disabled (RED), then passed with the fix restored (GREEN, 1 test). `cargo test afxdp::tests_embedded_poll_filter:: -- --quiet` passed all 103 tests (8058 filtered). The unqualified `tests_embedded_poll_filter::` filter selected no tests.
