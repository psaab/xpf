# #17164 — IPsec-inner descriptor re-implements the shared tunnel inner-L4 parser (R4-Q16-01)

- **Timestamp**: 2026-10-27
- **Issue**: #17164 (R4-Q16-01)
- **Base**: `origin/master 3abae28d24`

## Defect (STEP-0, verified at base)

Live on `3abae28d24`. `ipsec_inner_descriptor` (slowpath.rs:759) called the
production shim `packet_rel_l4_offset_and_protocol_for_ipsec`
(afxdp/mod.rs:320) and re-derived the payload offset with a private match:
TCP via an open-coded data-offset read, `17 if len >= offset+8 => offset+8`,
a dead `6 => None` arm (unreachable — the first `6` arm always matches),
and `_ => Some(offset)`. Divergences from the shared
`gre::parse_inner_protocol_and_offsets` (gre.rs:1417), which GRE/WG use:

- short UDP (and short ICMP): shared parser fails closed (`None`, #2376);
  the copy admitted it with `payload == l4`;
- ICMP/ICMPv6: shared stamps `l4 + 8`; the copy stamped `l4`;
- the unreachable arm reads as a fail-closed guard that does not exist.

Both feed `LogicalIngressParams{protocol, rel_l4_offset, payload_offset}`.

## Fix

- New `afxdp/frame/inner_l4.rs`: `parse_inner_protocol_and_offsets` and
  `packet_trimmed_len` moved verbatim from `gre.rs` as `pub(crate)`
  (re-exported via `frame/mod.rs`), except the TCP arms now resolve the
  payload end via `frame::tcp::tcp_payload_offset_from_l3` instead of a
  third open-coded data-offset read. The helper re-walks the same packet
  and requires the walked L4 offset to equal the caller's, which holds by
  construction, so verdicts are identical (None on sub-20/past-end TCP).
- `slowpath.rs::ipsec_inner_descriptor` calls the shared parser and maps
  `None` to `(0,0,0)` (the descriptor's existing drop stamp). No AH
  exception: the shared v6 walk traverses HbH/AH chains to the inner L4,
  and AH identity is resolved downstream
  (`frame::flowless_effective_protocol`, ipsec_inner.rs:422). The #15787
  fragment-no-L4 sentinel verdict (255, payload == L4) is preserved.
  Deliberate asymmetry kept and documented in-code: this path does not
  trim to the IP-declared length first (the slab holds exactly the
  decrypted datagram; descriptor `len` is its byte length), unlike the
  GRE/WG decap callers.
- Deleted `packet_rel_l4_offset_and_protocol_for_ipsec` (afxdp/mod.rs) —
  acceptance grep is 0. Callers rewired to `crate::afxdp::frame::*`:
  gre.rs decap/encap, wg/decap.rs, wg_uncovered_forward.rs,
  frame/wg.rs (+wg_tests), frame/tests_inner_frag_15787.rs.
- New parity table test `ipsec_inner_descriptor_matches_shared_parser_17164`
  (slowpath_tests.rs): 11 identical inners (v4 short UDP, UDP ok, ICMP,
  short ICMP, TCP+options, non-first fragments v4/v6, v6 HbH->TCP,
  AH->TCP, short UDP v6, ICMPv6) through both descriptor builders,
  asserting the shared verdict and the IPsec (0,0,0)-on-None mapping.

## Risk

Low-medium. GRE/WG behaviour is byte-identical (pure move; the TCP-arm
helper swap is verdict-equivalent and pinned by the 15787/13713 cells).
IPsec-inner behaviour changes only where the copy diverged: short
UDP/ICMP inners now fail closed to (0,0,0) instead of being admitted
with a fabricated payload offset, and ICMP inners stamp L4+8 — both
align the deny-only adjudicator with every other tunnel path and are
the #2376/#H37-04 semantics. Residual: the descriptor path still does
not apply `packet_trimmed_len` (pre-existing, documented above); a
trailing-padded inner datagram parses against physical length, as before.
