# 13652 — Revalidate source NAT on reverse hits without local entries

## Boundary

`source_nat_revocation_on_session_hit` returned early for reverse hits when
there was no locally materialized reverse row, and also treated a missing
forward companion as a clean result. This let a reply keep using a source
translation after the live NAT configuration stopped expressing it.

## Fix

- Recover the reverse row's canonical key when available; otherwise use the
  resolved reverse hit key and decision to derive the forward tuple.
- Revalidate a local forward companion through the existing canonical-row
  path. If no local forward row exists, reconstruct the forward NAT decision
  and run the existing read-only SNAT validity predicate sessionlessly.
- Return drop-only revocation for an invalid sessionless translation without
  tearing down or claiming the peer-owned session.
- Add regression coverage for absent reverse row with local forward companion,
  present reverse row with no forward companion, unchanged SNAT controls, and
  the installed forward/reverse twin path.
