# #16064 - Preserve rollback history across the active-rename crash window

## Root cause

Config commit writes the active DB first and publishes generation-bound rollback metadata only after rewriting every rollback slot. A power loss after the `active.json` rename (new active durable) but before that metadata publish left the sidecar binding the previous active identity. On the next boot, the #10723 generation check classified every generation-bound slot as stale and tombstoned the entire rollback history, even when all slot bytes still matched the in-memory/pre-crash history exactly.

## Change

- Before `WriteActive`, normal and confirmed commits durably publish a rollback preparation record: the current committed history entries plus a `next_active_hash` for the tree about to become active and a per-entry `pending_hash` for the slot content that will occupy each position.
- Boot certifies only that one exact skew (the durable active hash equals `next_active_hash`, including same-content commits where it equals the committed hash). Matching slots are then admitted at their pre-shift positions: slot 1 must hash to the previous active tree, later slots to the preceding committed entry, and partially rewritten slots to their prepared `pending_hash` stamped with that entry's own `pending_timestamp`/`pending_comment`. A store recovered through this skew path re-arms preparation on its next commit.
- Any other active mismatch, unknown bytes, or absent preparation record keeps the existing #10723 fail-closed tombstone behavior. A completed commit rewrites metadata normally and clears all preparation fields.

## Validation

- `TestRollbackCrashAfterActiveRenameKeepsHistory16064`: four real commits, then a production `CommitWithDescription` whose rollback-slot writer panics after `WriteActive` has made the new active durable; restart via `loadRollbackHistory` preserves the pre-shift slots.
- `TestGateDrivesLoad16064` drives the production loader gate (`loadRollbackHistory` -> `rollbackSkewSlotAdmission`) through a partial slot rewrite and asserts pending-attribute binding; `TestRollbackActiveRewriteWithoutPreparationRefuses16064`, `TestSameContentCommitCrashCertified16064`, and `TestPostRecoveryCommitRearms16064` cover uncertified rewrites, same-content certification, and post-recovery re-arm.
- Full `pkg/configstore` suite passes.

## Risk

Bounded to crash/skew recovery: the relaxation is keyed to an exact recorded next-active hash and exact per-slot content hashes, so unrelated or corrupted history remains fail-closed. Successful commits pay one extra durable sidecar write before the active rename.
