# Issue #17150 — One VRRP VIP parse repo-wide

`pkg/vrrp` parsed a configured VIP seven ways with two semantics under a
"SINGLE source" comment, and `pkg/config` held a byte-identical copy of
the #11482 dedupe. The strip-at-`/` helpers (`splitVIPsByFamily`,
`vipFamiliesIn`, the inline `vipFamilies` loop, `familyOfAddrs`) counted
a malformed entry such as `10.0.0.1/33` as a real IPv4 address, while
the ParseCIDR-first helpers (`parseVIPIdentity`, `canonicalVIPIdentity`,
config's `vrrpVIPHostIP` / counter) ignored it. On a lenient-loaded
malformed entry the runtime capacity guard and advert builder counted
it while the cross-election claim check and commit-time count did not.
The disagreement is reachable only for malformed entries the strict
schema rejects, so exposure was the lenient load path.

## Change

- `pkg/config/vrrp_vip_parse.go` (new): exported `ParseVRRPVIP(s)
  (netip.Prefix, bool)` — the single repo-wide VIP parse (CIDR via
  `netip.ParsePrefix` with padded-mask normalization, bare literal as
  its host route, zone/invalid → not a VIP) — plus `VRRPVIPIdentity`
  (prefix-preserving canonical identity; bare == host-route, invalid
  tokens unchanged) and `DedupeVRRPVIPs` (the one dedupe implementation
  repo-wide, first spelling retained).
- `pkg/config`: deleted `canonicalVRRPVIPIdentity`/`dedupeVRRPVIPs`;
  `countVRRPVIPFamilies` and `vrrpVIPHostIP` are now one-liners over
  `ParseVRRPVIP`; collection/normalization callers use
  `DedupeVRRPVIPs`.
- `pkg/vrrp`: deleted `canonicalVIPIdentity`/`dedupeVIPs`/
  `vipFamiliesIn`'s own loop body and the inline `vipFamilies` loop.
  `splitVIPsByFamily`, `vipFamiliesIn`, `familyOfAddrs`,
  `parseVIPIdentity`, `canonAddr`, `vipAddrSet`, `vipFamilies`, and all
  identity/dedupe call sites (capacity, instance construction, manager,
  collectors, GARP pending set, in-place VIP update) are one-liners over
  `config.ParseVRRPVIP` / `config.VRRPVIPIdentity` /
  `config.DedupeVRRPVIPs`. `canonAddr` now canonicalizes a CIDR host too
  (its only caller keys host lookups); `TestCanonAddr` updated.
- Acceptance: `grep -n 'strings.Index(addr, "/")\|strings.Index(s, "/")'`
  over non-test `pkg/vrrp` returns 0; one dedupe implementation
  repo-wide.

NOT changed: host-only identity (cross-election claims, #14407) vs
prefix-preserving identity (within-instance dedupe, #11482) remain
distinct policies layered over the one parse; invalid-token handling
(raw token retained for parse-error paths) is preserved.

## Regression

- `TestParseVRRPVIPAgreement17150` (pkg/config): table over
  `10.0.0.1/33`, `10.0.0.1/x`, bare, uppercase/expanded v6, and mapped
  bare/`/120`/`/128`/`/96`/`/95` — parse, commit-time counter, and host
  helper agree; mapped host is `10.0.0.1`; mapped dedupe/identity cells
  (`/120`==`/24`); cap+malformed fits, cap+distinct-valid rejected
  (control); dedupe identity cells.
- `TestVIPParseAgreement17150` (pkg/vrrp): same strings through
  `splitVIPsByFamily`, `vipFamiliesIn`, `familyOfAddrs`,
  `parseVIPIdentity`, `canonAddr`, and `checkAdvertCapacity`; mapped
  claim is `(10.0.0.1, inet)` and mapped aliases dedupe to the v4
  identities; 255 valid + `/33` fits the runtime guard, 256 distinct
  valid rejected (control).
- Round 2 (Rev18188b): sub-96 mapped prefixes (`::ffff:10.0.0.1/95`)
  have no v4 prefix equivalent. A caller census showed rejection is
  unsafe — commit gates (`vrrpVIPHostIP` nil → continue), counters,
  `splitVIPsByFamily`, `parseVIPIdentity`/`vipClaimKeyFor`,
  `familyOfAddrs`, `vipFamiliesIn`, and `canonAddr` all silently skip
  an unparseable VIP while the config is still accepted, so the VIP
  would be uninstalled/uncounted rather than failing the commit.
  `ParseVRRPVIP` therefore returns the v4 host identity
  (`10.0.0.1/32`, authored mask dropped) for sub-96 mapped prefixes,
  matching how the gates (`To4()`), `canonAddr`'s `10.0.0.1` lookup
  key, netlink actuation, and GARP already treated the host. New
  cells: `TestMappedSub96CommitGateFamily17150` (pkg/config: gate
  family, subnet containment + cross-family control, cross-group
  collision with plain `10.0.0.1/24`) and
  `TestMappedSub96VIPAddrSetActuationGARP17150` (pkg/vrrp:
  `vipAddrSet` membership against a `10.0.0.1` kernel address,
  netlink actuation family via the fake `addrAddFn`, GARP-vs-NA
  burst family via the burst seams). The prior test row that encoded
  the v4 collapse (`wantV4=false` while asserting host `10.0.0.1`)
  is corrected to `wantV4=true` with host-identity assertions.
- Existing named cells re-run: `TestCanonAddr`,
  `TestVIPDedupeAcrossUpdateAdvertAndGARP`,
  `TestSendAdvert_SplitterMatchesGuardCounting`,
  `TestVRRPVIPCountDeduplicatesCanonicalIdentities`.
