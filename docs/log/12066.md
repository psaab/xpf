# #12066 — one source protocol per route-map sequence

- **Timestamp**: 2026-10-07 (`fix/12066-proto-seq`, stacked on #12065)
- **Action**: expand each `FromProtocols` value into its own route-map sequence and include that OR dimension in the admission count.

## Red before

Added focused renderer and count regressions before implementation. On the base, `go test ./pkg/frr -run 'TestPolicyProtoSeq' -count=1` failed because the renderer emitted one sequence for a multi-protocol term (and did not cross protocol values with community or family-split variants). `go test ./pkg/config -run 'TestRouteMapSequenceCount_ProtoDimension_12066' -count=1` failed because the count returned 1 for three protocols, 4 instead of 8 for a protocol/community cross-product, and 2 instead of 4 for a protocol/family split. The prior `TestGeneratePolicyOptionsMultiProtocol` passed on the base because it checked only that all match lines existed, not that each occupied a separate sequence.

## Change

- `renderPolicyTermSequencesWithDefinitions` now carries one protocol value into each emitted sequence. It preserves protocol order, normalizes `direct` to `connected`, and sanitizes the single emitted match operand. A missing protocol list still produces one unconstrained sequence without allocating a sentinel slice per cross-product variant.
- `RouteMapSequenceCount` now multiplies by `max(1, len(FromProtocols))` through the existing overflow-checked arithmetic. `ComposedChainSequenceCount` inherits the corrected per-policy count; the strict-bound error now names `from protocol` among the count drivers.
- Added tests for one sequence per protocol with sequence order assertions, exact protocol/community pairings within each body, mixed-family/protocol cross-products, and admission-count parity including near-ceiling strict-gate rejection.

## Follow-up: canonical protocol dedup (PR #12311)

- **Timestamp**: 2026-10-08
- **Finding**: raw protocol tokens could normalize to the same FRR match (`direct` and `connected`) or repeat literally (`bgp bgp`). Expanding both tokens emitted duplicate modifying sequences, so a non-terminating action such as `set as-path prepend` ran more than once for the same route.
- **Change**: `config.CanonicalSourceProtocol` is now shared by the renderer, redistribute protocol naming, and the admission counter. The renderer expands unique canonical protocols in first-seen order; `RouteMapSequenceCount` multiplies by that same unique canonical count.
- **Regressions**: `TestPolicyProtoSeqDeduplicatesCanonicalProtocols_12066` covers `[direct connected]` with a non-terminating AS-path prepend and `[bgp bgp]`; the config count cases cover both duplicate forms and their cross-product, while `TestPolicyProtoSeqAliasDedupAdmissionPassesNearCeiling_12066` proves the deduplicated factor keeps the strict gate aligned near the ceiling.
- **RED before**: temporary pre-fix behavior (raw protocol expansion and raw protocol count) failed `go test ./pkg/frr -run '^TestPolicyProtoSeqDeduplicatesCanonicalProtocols_12066$' -count=1` with three sequences instead of one modifying sequence plus the default. `go test ./pkg/config -run '^(TestRouteMapSequenceCount_ProtoDimension_12066|TestPolicyProtoSeqAliasDedupAdmissionPassesNearCeiling_12066)$' -count=1` failed duplicate count cases (2 instead of 1, 8 instead of 4) and counted 6,554 sequences instead of 3,277 at the alias near-ceiling gate.
- **GREEN after**: `go test ./pkg/frr -run 'TestPolicyProtoSeq.*_12066$' -count=1` and `go test ./pkg/config -run '^(TestRouteMapSequenceCount_ProtoDimension_12066|TestPolicyProtoSeq.*_12066)$' -count=1` passed. `go build ./pkg/frr ./pkg/config ./pkg/api` passed; `gofmt -l` on all changed Go files produced no output.
- **Risk**: no live FRR reload or on-wire advertisement test was performed. Duplicate tokens now collapse to the same canonical FRR source-protocol match without changing the order of distinct protocol matches.
