# #17261 — preflight descriptor L4 checksum folds

- **Timestamp:** 2026-11-02
- **Branch:** `fix/17261-descriptor-dedup`
- **File(s):** `userspace-dp/src/afxdp/frame/rewrite/{ipv4.rs,ipv6.rs,mod.rs}`, `userspace-dp/src/afxdp/frame/checksum.rs`, `userspace-dp/src/afxdp/frame/README.md`, `userspace-dp/src/afxdp/frame/prop_tests/rewrite.rs`, `docs/log/17261.md`

## Why

The descriptor rewrite could commit the Ethernet header, rewrite addresses and ports, and then skip an out-of-bounds L4 checksum fold. A truncated NAT packet could therefore be partially rewritten. The preflight must check the L4 checksum field only when the apply half would fold it: `apply_nat && rd.l4_csum_delta != 0`. Applying this check to every NAT would incorrectly decline checksum-neutral NPTv6 first fragments.

## What

- Routed IPv4/IPv6 descriptor L4 field offsets through `l4_checksum_field_delta_v4/v6`. IPv4 descriptor UDP-zero handling and computed-zero canonicalization now use `l4_udp_checksum_optional` and `adjust_zero_checksum_illegal`.
- Added the fold-gated field bound to both read-only descriptor validators, before the Ethernet commit. Each validator returns the validated checksum-field offset relative to the IP header alongside `rel_l4`; the apply half consumes it instead of recomputing the protocol offset.
- Added `pin_17261_descriptor_truncated_l4_csum_first_fragment_declines`: SNAT short first fragments in both families decline byte-identically and agree with the generic path; short no-NAT packets remain accepted; a pure NPTv6 truncated first fragment with `l4_csum_delta == 0` still returns `Some`.

## Risk

Only a descriptor that would fold a non-zero NAT checksum delta now declines when its L4 checksum field is truncated. The descriptor does not mutate UMEM before that decline. Non-folding packets—including pure NPTv6 with zero descriptor delta—retain their prior fast-path eligibility. The regression cell pins both the atomic decline and the no-NAT/NPTv6 exceptions.
