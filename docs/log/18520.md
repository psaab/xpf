# #18520 — cross-worker TCP flows never reach Established

- **Timestamp**: 2026-10-29
  - **Action**: Root-caused the stuck opening window. The SYN installs the
    authoritative pair on worker A and fans `WorkerLocalImport` replicas to
    the siblings (`replicate_session_upsert`); the SNAT'd SYN-ACK lands on
    worker B, whose slow-path Owner replay promotes only B's replica pair
    (`lookup_with_origin_inner` `promote_from_reverse`). The completing ACK
    and client data return to A, whose forward row is pure Opening:
    the classic completion needs `handshake_pending`
    (`lookup.rs` `handshake_completed`, `probe_hit_inner` classic arm) and
    `cache_hit_handshake_progress` refuses `!hit.handshake_pending` unless
    `node_served_evidence(..).promoted_and_served()`. That evidence reads the
    table's OWN `node_served_stamps` and entries; nothing in production ever
    merged a sibling's stamps (the only writer is
    `note_node_served_handshake`, called from the table's own completion
    sites; the #16223 tests called it on the replica table directly). The
    shared-map Established wire the ct-slice restamps is read only by the GC
    `node_served` closure, for idle-crossed rows. B, for an upload, only
    sees reverse bare ACKs, which correctly never complete a SYN-first pair
    (#4109). So no worker ever completes. Not a regression of a working
    path: before #4109 any ACK promoted, after it the split shape had no
    completion vehicle at all; #16223 added the per-packet evidence scan
    (cost) without the cross-table merge (cure).
