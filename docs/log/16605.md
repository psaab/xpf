# #16605: gRPC command gate charges typed-line aliases for shared RPCs

- **Timestamp**: 2026-10-25
- **Action**: `authorizeRPCCommand` charged GetIPsecSA, ShowInterfacesDetail,
  ShowRollback/ShowCompare/ListHistory, GetGlobalStats, GetVRRPStatus,
  GetNATPoolStats/GetNATDestination (and GetNATSource, which shares the
  source-pool charge) one fixed `methodCanonicalCommand` string each, while
  the remote cli performs those RPCs for different typed lines
  (`show security ike security-associations`, `show interfaces [<name>|terse]`,
  `show system rollback …`, `show security statistics`, `show security vrrp`,
  `show security nat source|destination summary`). A path-scoped
  `deny-commands` written against the typed line therefore never fired
  remotely, and an allowlist naming only that line locked the line out.
  The gate now judges every canonical line that performs the RPC: the
  registry charge plus the typed-line aliases in
  `pkg/grpcapi/authz_alias_forms_16605.go` (`rpcAliasCommands16605`, a
  census of every `c.client.<RPC>(` site in `cmd/cli` paired with its
  dispatching line), each expanded to its canonical base/full/selector
  forms, under `EvaluateForms` unanimity. ShowInterfacesDetail's executed
  line is reconstructed from its Terse/Filter selectors (previously a
  filtered non-terse request was judged as `… detail <name>`, a spelling
  no operator types). A cross-spelling rescue
  (`aliasFormsDenyRescued16605`) preserves the deny-with-exceptions
  geometry across spellings: a sibling-spelling tier denial answered by
  an affirmative allow on another spelling does not veto, while a deny
  naming the executed spelling always does. The alias commands join
  `allCanonicalCommands`, so the #8189 commit advisory no longer reports
  (or silently misses) these patterns incorrectly. ShowRollback/
  ShowCompare keep `show configuration` as a judged form, so the #14707
  config-read verdicts are unchanged. No proto or client change: the
  request types carry no line identity and a client-supplied command
  string would be attacker-controlled authz input.
- **File(s)**: `pkg/grpcapi/authz_alias_forms_16605.go` (new),
  `pkg/grpcapi/authz_alias_forms_16605_test.go` (new),
  `pkg/grpcapi/authz_command_gate_7172.go`,
  `pkg/grpcapi/authz_command_args_16067.go`, `docs/log/16605.md`.
- **Validation**: New `TestTypedLineDenyFires16605` (14 typed-line deny
  cells), `TestTypedLineDenyControls16605` (charge spellings still deny;
  executed-spelling deny vetoes beside a sibling allow; sibling deny
  excepted by executed allow), `TestTypedLineAllowlist16605` (8
  allowlist-admission cells), `TestAliasFormsAreCanonical16605`,
  `TestAliasCommandsInSurfaceSet16605`, `TestAliasCensusComplete16605`
  — all pass post-fix; pre-fix the test file does not compile (alias
  table absent) and the deny cells were the reported fail-open.
  Targeted authz suites (`7172|15076|16067|16472|14707|15995|9022|
  16378|15077|14144|9633|9154`) pass except
  `TestBGPAndNATCanonicalCommandsAreKeywordPrefixes15076`, which fails
  identically on pristine origin/master (pre-existing). Full
  `pkg/grpcapi` and `cmd/cli` runs show only failures verified identical
  on the base commit.
- **Residual**: REST (`pkg/api`) keeps its route-based charges; its
  endpoints are not typed cli lines, so no alias was added there.
  GetNATPoolStats' pool-name selector remains client-side filtering
  (the request carries no selector), so an argument-scoped deny on a
  pool name still cannot fire remotely — that is the #16067
  argument-text family, not this path-scoped defect.
