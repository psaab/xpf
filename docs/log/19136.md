# #19136: nftables kernel-probes selftest recursion under run-selftests.sh

- **Timestamp**: 2026-11-16
- **Action**: Root-caused on tcp:xpf-testrunner, confirming F2's hypothesis
  (GO_REAL is the testguard shim) and sharpening it: it was an unbounded
  RECURSION, not a hang in one nested testguard. The full chain:
  1. `scripts/run-selftests.sh` puts `test/support/host-bin-shims` first in
     PATH, so `test/nftables/nftables-kernel-probes_18745-selftest.sh` set
     `GO_REAL=$(command -v go)` to `host-bin-shims/go`.
  2. The kernel leg runs `testguard-run.sh <fixture go wrapper> test ...`.
     `testguard-run.sh` reorders PATH to shims first, then the rest, which
     includes the fixture's `bin/`.
  3. The wrapper execs `GO_REAL`, which is the shim.
  4. The shim strips its own directory and resolves "the real go" as the next
     `go` on PATH: the fixture wrapper.
  5. It execs `testguard-run.sh <wrapper> test ...`, and the cycle repeats.
  A process-tree sample 90 s into a 300 s bounded run showed about 20 nested
  `testguard-run.sh` levels, all started in the same second; the run ended
  rc=124. Run alone, `command -v go` is the real toolchain and the leg
  finishes, which matches the issue's observation.
- **Action**: Fix, in two layers:
  - the leg resolves its default `GO_REAL` with `host-bin-shims` removed from
    PATH (an explicit `GO_REAL` is still honoured);
  - `host-bin-shims/go` counts its nesting in `XPF_GO_SHIM_DEPTH` and fails
    with exit 125 at 8 levels, so any future cycle of this kind fails in
    seconds instead of hanging every later selftest leg. Legitimate nesting (a
    test that runs `go` under the guard) stays far below the limit.
    [Fold cycle 1, Codex integ3 review: the counter bounds nesting DEPTH, not
    cycles. An 8-deep legitimate chain would also fail. The commit's "nothing
    nests beyond 2" was not measured. What was measured is that the limit fired
    0 times in the full run-selftests.sh run below. The shim comment and
    docs/testing.md now say so.]
- **Action**: `scripts/nftables-probes-shim-path-selftest.sh` (registered in
  `scripts/run-selftests.sh` after the leg) has two cells:
  - bounded: the leg under run-selftests.sh's exact PATH must pass within a
    bound (600 s; rc 124 is the hang);
  - shim guard: with `GO_REAL` forced to the shim (the pre-fix resolution) the
    leg must fail fast on the nesting message (240 s bound), proving the
    recursion is real and now bounded.
  It SKIPs when the leg SKIPs (no go).
