# #14701 — Negated Name / IP-literal MAC external-match residuals

## Defect

After #14593 removed the `matchAll` synthesis, three residuals in
`FindExternallyManaged` (`pkg/networkd/networkd.go`) still over-claimed
external ownership, suppressing `ActivationPolicy=always-down` and the
compiler's unmanaged strip:

1. `Name=!eth0 !eth1`: the parser prefixes `!` onto every word of a
   line-negated assignment (systemd `config_parse_match_ifnames`
   behavior, pinned by #12135), storing `!!eth1`; the matcher stripped
   one `!` and fnmatched literal `!eth1`, so eth1 was not vetoed.
2. `MACAddress=192.0.2.1` (and other IP literals): `parseExternalMACAddress`
   accepted any `net.ParseIP` result as a hardware address, so an
   IP-only file was a valid MAC predicate matching an interface whose
   MAC string equalled that IP. systemd's hardware-address parser
   drops IP literals.
3. `MACAddress=<valid>` followed by `MACAddress=invalid`: the second
   assignment appended zero words but left the first list live, so
   `MatchesForApply` still matched. Each assignment must rebuild the
   list; an all-invalid later assignment resets earlier valid words.

Bug 3 from the source report (unknown `[Match]` keys ignored by
`MatchesForApply` when a supported predicate matches) is deliberate
Apply conservatism and is NOT changed; it remains pinned by
`TestApplyConservativelyPreservesUnknownExternalMatchKeys12135`.

## Fix

- `externalPatternListMatches`: a run of leading `!` collapses to one
  negation before fnmatch. Parser unchanged (line-negation prefixing
  is systemd's documented per-line model).
- `parseExternalMACAddress`: reject `net.ParseIP` literals outright;
  EUI-48 colon/hyphen/dotted forms unchanged. The three pinned #12135
  IP-literal cells flip to rejected.
- `FindExternallyManaged` `MACAddress=` case: rebuild `macPatterns`
  per assignment (clear before collecting this line's valid words),
  mirroring the existing empty-assignment reset.

## Tests

New `pkg/networkd/negated_match_14701_test.go`:
`TestFindExternallyManagedUnparseableMACAndMultiNegatedName` (named in
the issue) covers same-line/separate-line multi-negation, IPv4/IPv6/
8-group IP-literal MACs, invalid/empty MAC reset of an earlier valid
MAC, negated/IPoIB/malformed MAC-only controls, valid MAC/Name
controls, and `Apply`-level always-down suppression/retention;
`TestParseExternalMACAddressRejectsIPLiteral14701` pins the parser.

## RED/GREEN

- RED on `origin/master` 3379b7f0ac (test only): same-line `!eth1`
  Matches/MatchesForApply true, IPv4-literal MAC true, stale-MAC
  MatchesForApply true, both Apply cells missing the always-down unit,
  and all five IP literals accepted by the parser. Controls passed.
- GREEN: `go test ./pkg/networkd -count=1` passes; see PR for
  dataplane/vet results.

## Risk

Interfaces previously (wrongly) exempted by a double-negated Name, an
IP-literal MAC, or a reset MAC now receive the always-down unit,
matching systemd ignoring/not-matching those files. 20-byte IPoIB
addresses remain unsupported (pre-existing residual in #12135 log).
