# #18148 — Go SessionDeltaInfo zone IDs at u16 fail every JSON poll for a u32 hash zone

- **Timestamp**: 2026-10-27
- **Root cause (proven live, assigned)**: Rust emits `ingress_zone_id` as
  `u32` (`userspace-dp/src/protocol/control.rs:1257`,
  `userspace-dp/src/protocol/binding.rs:1504`, `SessionPolicyMatch`
  at `control.rs:1618`; widened by #16557 — `config.StableZoneID` is a
  u32 FNV fold into `[1, 4294967293]`). The JSON producer
  (`afxdp/session_delta.rs:375`) copies `SessionMetadata.ingress_zone:
  u32` verbatim. But the Go JSON fields were `uint16`
  (`pkg/dataplane/userspace/protocol_ha.go`): `SessionPolicyMatch`
  (83), `SessionSyncRequest` (113), `SessionDeltaInfo` (350). A real
  zone, `config.StableZoneID("lan") = 262430026`, therefore failed every
  JSON status/delta poll with a `json: cannot unmarshal number`
  error, the #9651 supervisor killed the helper every ~32s on both
  loss nodes, and the fabric starved.

## What

- Widened all three JSON zone fields to `uint32` in
  `protocol_ha.go` (both ingress and egress: 6 fields), with comments
  recording the u32 producer and the binary-leg divergence below.
- Propagated the width to the Go consumers that must carry the full
  value rather than silently truncate it:
  - `pkg/dataplane/runtime.SessionIdentity.IngressZoneID/EgressZoneID`
    → `uint32` (fed verbatim from `SessionDeltaInfo`).
  - `PolicySessionRebind.IngressZone/EgressZone` → `uint32` (the Rust
    `PolicySessionRebind` already declares `u32` at
    `protocol/security.rs:615`; Go was sending the low 16 bits).
  - `remappedQueryZones` now takes `uint32` IDs plus a `truncated`
    flag: the BPF twins pass their genuinely-u16 value widened with
    `truncated=true` (low-16-bit name resolution, unchanged
    behaviour); the helper-JSON match passes its full u32 with
    `truncated=false` and resolves by exact `oldNameByID`, so two
    zones sharing low 16 bits can no longer alias on the rename /
    rollback-reauthorize path. `reauthorizePolicyCandidates` likewise
    switched from `oldNameByTruncatedID` to exact `oldNameByID`.
  - `sessionSyncView` gained `ingressZoneID32()/egressZoneID32()`
    zero-extensions for the widened `SessionSyncRequest` fields; the
    BPF-sourced value remains the low 16 bits (see frozen ABI below).
- Explicit, commented truncations where the destination is a frozen
  u16 ABI: `daemon_ha_userspace_convert.go` (`SessionValue{,V6}` store
  `uint16(delta.…ZoneID)`), `daemon_flowexport.go`
  (`EventRecord.InZone/OutZone` stay u16, sharing the BPF/RT_FLOW
  wire). No silent narrowing remains on the widened fields.
- Test fixtures that built `SessionPolicyMatch`/`SessionDeltaInfo`
  with `uint16(StableZoneID(...))` now carry the full u32 (they were
  previously modelling the truncated wire, which masked the defect);
  BPF `SessionValue{,V6}` fixtures keep their correct u16 casts.

## Binary event-stream audit (assignment item 2)

The binary leg is **genuinely u16** and was left at u16:

- Rust open/close encode: `event_stream/codec/session_sync.rs:272,276`
  write `&(metadata.ingress_zone as u16).to_le_bytes()` into
  `[27:29]/[29:31]`; `encode_session_close` takes `ingress_zone_id:
  u16` parameters (lines 498, 520).
- Go decode (`eventstream.go`) therefore zero-extends the u16 read
  into the now-u32 field (`uint32(binary.LittleEndian.Uint16(...))`),
  with comments at both sites stating the divergence.

So JSON and binary differ by design of their wires: JSON numbers are
width-free and carry the full u32 StableZoneID; the binary frame is a
fixed positional layout whose zone slot is 2 bytes. A zone whose id
exceeds 65535 loses exact zone attribution on the binary leg (the
pre-existing #16557 documented behaviour — it resolves via the
surviving-name fallback and fails closed, never merging zones), but
it can no longer *fail to decode* — which is the loss blocker. Widening
the binary frame to u32 would be a flag-day wire change (header grows
32→36 bytes, disposition/IP offsets move) and is out of scope here.

## Other-consumer census (assignment item 3)

- `ingressZone()/egressZone()` (`manager_sessionsync_request.go`):
  read `dataplane.SessionValue{,V6}.IngressZone/EgressZone`, which are
  u16 BPF ABI fields — genuinely truncated at the source, widened
  losslessly for the JSON wire (above).
- `zoneNameByID(uint16)` compares against `CompileResult.ZoneIDs`
  (`map[string]uint32`) via `uint32(zoneID)` — correct for its u16
  BPF input; unchanged.
- Frozen u16 ABIs deliberately NOT widened: `dataplane.SessionValue
  {,V6}.IngressZone/EgressZone` (BPF conntrack value + cluster sync
  wire), `logging.EventRecord.InZone/OutZone`, RT_FLOW event zones
  (Rust `DataplaneEventPayload.ingress_zone_id: u16`), `api`/`grpcapi`
  session zone filters. Values above u16::MAX cannot round-trip on
  those records (#16557 doc in `pkg/config/zoneid.go`); they are
  separate flag-day changes, not this loss blocker.
- No map is keyed by a uint16 zone ID and no comparison assumes
  `<= 65535` on the JSON paths after this change.
