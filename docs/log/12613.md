# #12613 — expand recursive static ECMP safely

- **Timestamp**: 2026-10-13 (`fix/12613-campaign-pub`)
- **Action**: expand recursive gateways into deterministic terminal ECMP candidates, exclude the route being resolved during recursive lookup, and preserve configured weights.

## Red before

The v4 recursive ECMP ordering regression failed before the resolver change: reversing Q's next-hop order changed the recursive P member from `192.168.0.254` to `192.168.0.253`. The fixture also covers a dead direct member before the recursive alternative and 256 per-flow hashes.

## Change

Recursive static lookup now expands every eligible member of the selected preference tier, preserving longest-prefix and preference ordering while bounding work and depth. The originating route is excluded from recursive covering matches so a mixed row cannot resolve through itself; a less-specific/default route remains eligible. Terminal duplicates merge deterministically. Weights multiply along recursive route chains and duplicate paths sum, with saturating `u32` arithmetic to preserve the route-next-hop weight ABI without overflow. IPv6 link-local gateways remain fail-closed against global recursive lookup.

Added IPv4 and IPv6 tests for the ordered two-member fixture, weights, 256-flow forwarding behavior, and mixed self-covering rows with usable defaults. Existing preference-tier and link-local regressions remain in place.

## Validation

- RED was observed before the fix using `cargo test recursive_static_ecmp_expands_every_member_in_both_orders_12613 -- --nocapture` from `userspace-dp`: reversing Q's next-hop order changed P's resolved member.
- Post-change `cargo test afxdp::forwarding_build::tests:: -- --nocapture` passed after rebasing onto current master: 220 passed.
- Focused `recursive_ecmp_preserves_direct_member_11317`, `bare_v6_link_local_nested_never_recurses_to_wan_12398`, and `recursive_static_ecmp_expands_every_member` tests passed individually.

## Residual / risk

Recursive ECMP weight composition uses saturating multiplication and summation when paths exceed `u32::MAX`; this preserves ordering bounds but cannot represent a mathematically larger aggregate weight exactly. Recursive expansion remains bounded by the existing depth and per-gateway work limits. This does not alter the separate IPv6 link-local safety behavior.
