# #15018 — repeated `root-authentication` / `archival` / `internet-options` blocks reset the stanza (A13-01)

## Defect

`compileSystem` (`pkg/config/compiler_system.go`) unconditionally
reallocated three stanzas on every sighting:

```go
case "root-authentication":
    sys.RootAuthentication = &RootAuthConfig{}
case "archival":
    sys.Archival = &ArchivalConfig{ArchiveDir: "/var/lib/xpf/archive", MaxArchives: 10}
case "internet-options":
    sys.InternetOptions = &InternetOptionsConfig{}
```

`compiler_dispatch.go` calls `compileSystem` for **every** `system`
root, and the child loop sees every repeated child under one root, so
both spellings — two `system` roots, or two sibling blocks under one
root — discarded everything the earlier block contributed. The commit
reported success, `show configuration` echoed the operator's input,
and the compiled config silently lost it.

For `root-authentication` this is a management lockout:
`applyRootAuth` (`pkg/daemon/daemon_hostauth_apply.go`) writes the
compiled key set as the whole of root's `authorized_keys` and locks an
xpf-provisioned root password when the stanza comes back empty — the
earlier block's SSH keys are revoked and the password can be locked by
the very commit that appeared to set them. For `archival`, earlier
`archive-sites` (and `transfer-on-commit`) vanished; for
`internet-options`, an empty repeated block cleared
`no-ipv6-reject-zero-hop-limit`.

This is the residual of the #13532/#6957 class: `sys.Login` one stanza
over already allocates once with an explanatory comment; these three
arms were never converted.

## Fix

Allocate once — `if sys.X == nil { sys.X = &T{...} }` — for
`RootAuthentication`, `Archival` (defaults applied only on first
allocation), and `InternetOptions`. The bodies already accumulate
correctly once the struct survives: SSH keys and archive-sites append,
and scalar leaves (`encrypted-password`, `transfer-interval`) apply
only when actually authored, so they stay last-writer-wins without an
empty later block revoking them.

### Census of every `sys.X = &T{}` in `compileSystem`

| Site | Before | After |
|---|---|---|
| `sys.Login` | allocate-once (#6957) | unchanged |
| `sys.RootAuthentication` | **unconditional reset** | allocate-once (#15018) |
| `sys.Archival` | **unconditional reset (with defaults)** | allocate-once, defaults on first alloc |
| `sys.InternetOptions` | **unconditional reset** | allocate-once |
| `sys.UserspaceDataplane` | allocate-once | unchanged |
| `sys.Syslog` | allocate-once | unchanged |
| `sys.Services` / `.SSH` / `.WebManagement.APIAuth` | allocate-once | unchanged |
| `sys.Services.WebManagement` | **unconditional reset** | allocate-once (census find: a second `system` root re-enters this post-loop block; its body only sets flags / overwrites authored scalars, so merging is the same accumulation semantics) |
| `compileSNMP`'s `snmp` | starts from `sys.SNMP`, allocate-once | unchanged |

NOT changed: `sys.Services.DynamicDNS = cat` and scalar leaf
assignments (`host-name`, `master-password`, …) — not `&T{}`
allocations; scalars are last-writer-wins by design and the DDNS
catalog is a whole-catalog compile product, outside the cited
mechanism.

and asserts the surviving leg; all fail on `origin/master`

## Risk

Behaviour changes only when a stanza is authored more than once
(repeated child or second `system` root); single-block configs compile
byte-identically. No daemon change: `applyRootAuth` already treats the
compiled stanza as authoritative — the fix makes that authority
complete instead of last-block-only.
