# #16755 — shell ownership no longer inferred from the account marker

- **Timestamp**: 2026-10-25
  - **Action**: `deprovisionLoginUser` derived shell ownership as
    `ownsShell || ownsAccount`, but the account marker records "xpf created
    it OR set its password": `reconcileUserPassword` writes it for any
    pre-existing account whose password xpf sets. A pre-existing account
    whose shell already equaled the class shell (e.g. `/bin/bash` for
    super-user) therefore had its operator shell reset to
    `/usr/sbin/nologin` on removal although xpf never set that shell —
    regressing the #5841/#6797 never-touch-non-xpf-credentials invariant.
    Shell ownership now derives ONLY from the shell marker, and
    `applySystemLogin`'s useradd branch (where xpf chooses `-s`) now
    writes the shell marker alongside the account marker, fail-visible,
    so xpf-created accounts still reset on removal (#14695 acceptance
    preserved). Pre-existing accounts elevated by an actual shell change
    already received the shell marker via the existing claim path and are
    unchanged.
  - **File(s)**: `pkg/daemon/login_password.go`,
    `pkg/daemon/daemon_hostauth_apply.go`,
    `pkg/daemon/login_deprovision_shell_14695_test.go`,
    `pkg/daemon/login_shell_10833_test.go`, `docs/log/16755.md`.
  - **Validation**: New decisive cell
    `TestDeprovisionPreexistingClassShellEqualKeepsShell` (account+password
    markers, no shell marker, `/bin/bash`): no usermod, shell preserved.
    `TestDeprovisionLoginUserResetsInteractiveShellToNologin`,
    `TestDeprovisionLoginUserShellResetFailureRetainsProvenance`, and
    `TestDeprovisionLoginUserAlreadyNologinIsNoop` re-seeded with the shell
    marker the fixed useradd branch writes;
    `TestApplySystemLoginCreatesRestrictedShell10833` now asserts the
    shell marker exists after useradd. Targeted daemon suites re-run.
  - **Residual**: Accounts created by xpf before this fix carry only the
    account marker, so their xpf-granted shell is no longer reset on
    removal (the conservative direction: an operator shell is never
    taken; a stale interactive shell on a removed xpf-created account can
    be reset manually as root). No migration marker is written for them
    because the account marker cannot distinguish them from the
    pre-existing class-shell-equal shape this issue protects.
