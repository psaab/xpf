# #13635: stale flow-cache deny entries shadow live sessions

A pre-session packet can seed a `PolicyDenied` or `DiscardRoute` flow-cache entry. If a session is installed for that tuple before the deny entry expires, `stage_flow_cache_hit` previously executed the cached terminal verdict before checking whether the session was live. A cached `Reject` could consequently synthesize a stale TCP RST against a newly established flow.

The deny-hit branch now checks backing-session liveness before replaying counters, events, or reject replies. Its alias-aware `SessionTable::has_session_hit_at` probe recognizes translated reverse-NAT tuples without recording a miss on ordinary pre-session denies. A live session invalidates the cached deny slot, reclassifies the lookup as a miss, and falls through to normal session resolution.

Regression coverage drives `PolicyDenied` and `DiscardRoute` hits through the production stage, including a translated reverse-NAT alias; it verifies fallthrough, no reject/drop side effects, and cache eviction/reclassification.

Validation: `cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp flow_cache_hit_tests` passed (45 tests). On the unchanged master implementation, `policy_deny_cache_hit_falls_through_when_live_session_backs_flow_13635` failed because the deny hit was consumed instead of falling through.
