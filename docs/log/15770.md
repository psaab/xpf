# Issue #15770 — per-bucket owed kernel-neighbor programs

- **Issue**: #15770 — `KernelNeighborProgramLimiter` single-slot `self.owed` overwrite and way-eviction drop lose owed kernel neighbor programs under hot-bucket contention (successor to #15247/#15624; distinct from closed #6129).
- **Files**: `userspace-dp/src/afxdp/neighbor_program_limiter.rs`, `userspace-dp/src/afxdp/README.md`, `userspace-dp/tests/neighbor_program_limiter_owed_15770.rs`, `docs/log/15770.md`.

## What

- Removed the single table-wide newest-wins `owed: Option<((i32, IpAddr), [u8; 6])>` slot.
- Each bucket way now carries one owed pair (`desired_key`/`desired_mac`/`desired_ns`), so a bucket retains up to `KERNEL_NEIGH_LIMITER_WAYS` (4) distinct owed bindings; `record_owed` updates a key's entry, else takes a free way, else evicts the oldest owed entry. An exact re-record is a no-op so repeated unchanged adverts do not refresh (and thereby starve) older debts.
- Hot-bucket refusals and in-owned-way rate-limited MAC changes both record owed per bucket; programming a way preserves another key's owed entry stored on it, so an owed binding survives eviction of its owner's way and retries on the victim's next advert (`map_changed == false` included). Programming/superseding a key discharges its owed entry.
- Bound preserved: the aggregate netlink rate stays `≤ SLOTS / MIN_INTERVAL`; beyond `WAYS` simultaneously-owed distinct keys in one bucket, the oldest owed entry is evicted and that key lags until its next changed advert (userspace neighbor map / transit forwarding unaffected).
