# Issue 10485: admitted IPsec tunnel publisher

## Implementation

The daemon now derives a deterministic `ipsec_tunnel_rows` authority list from the
currently admitted IPsec capture handles and their ownership-checked zone
snapshot. Each row contains the STN, helper interface ID, and logical ifindex.
Incomplete joins, conflicting duplicate STNs, stale/closing zone snapshots, and
unknown interfaces are omitted rather than guessed. Rows are published from the
staged runtime for an apply and become active only after the matching helper
snapshot is accepted; failed or deferred applies do not activate staged rows.
Teardown publishes an empty list.

If a post-ACK capture-stage failure rolls the daemon back to the previous
divert/queue runtime, the daemon now refreshes and republishes the manager's
current snapshot authority before returning. The helper-side rows and the
daemon's live handles therefore converge even when the system is otherwise
quiescent; a real republish is followed by the FIB bump, and heal failures are
joined into the failed apply result.

Only `ZoneReasonZoned` joins produce rows. Ambiguous duplicate binds remain
deny-only even when their handles and ifindexes are individually valid.

The Go snapshot wire carries both the row list and a separate
`ipsec_tunnel_snapshot_generation`. The latter is the immutable capture/handle
generation and is intentionally distinct from the accepted configuration/FIB
authority. Config and FIB advisory stamps advance only at the accepted snapshot
boundary (and from the applied fixed point for FIB-only changes), avoiding mixed
deferred generations. The packet-path generation gate checks those two
authorities separately.
The Rust coordinator replaces its runtime row authority on every accepted
snapshot and clears it on stop; an empty or partial authority remains deny-only.
