# #16151 — cmdtree completion-walker dedup, Canonicalize agreement test only

- **Timestamp**: 2026-10-24
- **Issue**: W2.3 / config-schema R7 steps 1–2 only — dedup the twin
  completion walkers and make descriptions a projection; step 3
  (merge `Canonicalize` into the walk via `walkPolicy.AllowProviders`)
  REJECTED, replaced by a `resolveTreeWord`-level agreement test.
  Low (maintenance), no real defect claimed in steps 1–2.
- **Prior landing**: Steps 1–2 already landed as #16138 (PR #16231):
  `CompleteFromTree` is the name-only projection of the single
  `CompleteFromTreeWithDesc` walk, pinned by
  `completion_walker_parity_16138_test.go`. Verified present on
  current master; not re-done.
- **Change**:
  - `pkg/cmdtree/tree.go`: `LookupDesc` was a third hand-rolled
    walker (140 lines) duplicating `CompleteFromTreeWithDesc`'s
    traversal. It is now the description projection of that single
    walk: the internal `completeFromTreeWithDesc` walk gains two
    LookupDesc-only modes — `rejectRepeatedOptions` (a repeated
    option keyword ends the walk, mirroring `Canonicalize` #15719;
    completion itself must still offer a repeated option's values
    mid-typing) and `describeDynamicSlot` (answer
    `{name, "(configured)"}` at a dynamic value slot without
    enumerating provider values, reproducing LookupDesc's historic
    no-config answer). `CompleteFromTree`/`CompleteFromTreeWithDesc`
    call it with both modes off, so the offering surface is
    byte-identical.
  - Direction found differentially: the pre-existing
    `TestCompleteRepeatedAndOtherOptionMaps15720` asserted repeated
    options canonicalize OK, contradicting #15719 (landed after it)
    — completion offers the in-progress repeated word while
    `Canonicalize` refuses the finished repeated line, and
    `LookupDesc` (describing a finished line) now describes nothing
    there. That test was failing on clean master for exactly those
    two rows; it now pins the split, and the AST scope guards
    (#9505/#15720) pin `Options` readers to `Canonicalize` plus the
    one walk.
  - New `pkg/cmdtree/canonicalize_agreement_16151_test.go`:
    enumerates all 472 non-placeholder keyword paths of
    `OperationalTree` and asserts, per keyword — completion offers
    it (full spelling and shortest unique abbreviation), the
    WithDesc/LookupDesc descriptions agree with the node Desc, and
    `Canonicalize` accepts it as itself (CanonicalOK reproducing
    the path, or refusal solely from end-of-line incompleteness
    removed by filling the pending/ancestor value slots). A seeded
    `ModifierOnly` divergence (offered, never canonicalizable)
    proves the check can go red; counting providers prove
    `Canonicalize` invokes none (completion positive control); an
    AST census pins `Canonicalize` provider-free, both walks routed
    through `resolveTreeWord`, and `walkPolicy`/`AllowProviders`
    absent.
  - `pkg/cmdtree/README.md`: new section recording the projection
    and the agreement invariant.
- **Validation**:
  - `go test ./pkg/cmdtree/ -count=1` PASS (was FAIL on clean
    master: only `TestCompleteRepeatedAndOtherOptionMaps15720`'s
    two Canonicalize rows, now pinned to their correct results).
  - `go test ./pkg/cli/ ./pkg/grpcapi/` and `./cmd/cli/`:
    `cmd/cli` has one failure identical on clean base
    (`TestEveryOperationalValueSlotHasARemoteBinding_9478`,
    pre-existing, unrelated value-slot census).
- **Risk**: Low. Offering surface unchanged (modes off);
  `LookupDesc` only narrows where the old walker disagreed with
  `Canonicalize` (repeated options describe nothing). No provider
  became reachable from `Canonicalize`; the rejected step-3 merge
  stays rejected and is now test-bound.
