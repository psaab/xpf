# #18886: select the commit-confirmed journal row in the shell commit callback cell

- **Timestamp**: 2026-11-02
- **Action**: Fixed `TestShellCommitCallbackJournalPrincipal10301` to select the `commit_confirmed` journal entry by `Action` instead of assuming it is the last entry. Since `c67a8d4a85` (#16721), `ConfirmCommit()` appends a `commit_confirm` row (`journalCommitConfirmLocked`, `pkg/configstore/store_commit.go:1288-1297`) after the confirmed commit's `commit_confirmed` row (`pkg/configstore/store_commit.go:914-918`), and that confirm row carries `UnknownPrincipal` because the plain `ConfirmCommit()` path confirms as the internal caller. The old last-entry read therefore compared the confirm record's principal against the shell principal and failed. The cell now scans for the last `commit_confirmed` entry and fails loudly (`no commit_confirmed journal entry`) when none exists; there is no fallback to the last entry. The principal assertion itself is unchanged in strength (`Principal != want` → fail) and the neighbouring cells (`TestEventEngineJournalPrincipal10301`, `TestBootstrapJournalPrincipal10301`) are untouched — plain commits and event-engine/bootstrap commits append no trailing confirm record, so last-entry remains correct there.
  - **File(s)**: `pkg/daemon/journal_principal_10301_test.go`, `docs/log/18886.md`
- **Validation**: RED at base `5e65228f29` via `./scripts/testguard-run.sh go test ./pkg/daemon -run '^TestShellCommitCallbackJournalPrincipal10301$' -count=1` → `journal_principal_10301_test.go:87: shell confirmed callback principal = [...], want "source=local-shell;uid=4242;user=opsuser;class=operator;session=none"`. GREEN after the fix with the same guard plus both neighbours: `./scripts/testguard-run.sh go test ./pkg/daemon -run '^Test(EventEngine|ShellCommitCallback|Bootstrap)JournalPrincipal10301$' -count=1` → all PASS. `gofmt -l` clean on the changed file.
- **Mutant**: reverting the selection to `entries[len(entries)-1]` reproduces the base RED above — the trailing `commit_confirm` row's principal is `unknown`, not the shell principal — so the cell still fails when the intended behaviour (#16721's confirm record, principal labelling) regresses. This is exactly the captured base failure; no assertion was weakened.
- **Risk**: Test-only change; no production code touched. The loud `no commit_confirmed journal entry` failure makes a missing confirm row visible instead of silently passing on a coincidental last entry.
