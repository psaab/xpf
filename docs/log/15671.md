# Issue #15671: `protocols ndp` host-inbound token

- **Timestamp**: 2026-10-19
- **Action**: registered `ndp` in the host-inbound SSOT
  (`KnownHostInboundProtocols`, `HostInboundProtocolFamily=ip6`,
  `HostInboundProtocolMatch` = ICMPv6 types 133-136), the Rust
  classifier (`KNOWN_ROUTING_PROTOCOL_TOKENS` + `classify_protocol`
  arm), and the legacy BPF flag plane (`HostInboundNDP` bit 22,
  `host_inbound_flag` returns it for 133-136 instead of
  router-discovery). Redirect 137 is never admitted.
- **Action**: changed ND from an unconditional global accept to a
  default with withdrawal. Kernel text + netlink chains, fences, the
  Go match-policies classifier, and the Rust AF_XDP classifier now
  admit ND 133-136 by default (IPv6 link operation) but withdraw it
  when the effective stanza carries `protocols ndp except`. The raw
  except tokens travel on `ZoneHostInboundView.ProtocolsExcept`, the
  daemon→nftables conversion, and the Go→Rust snapshot
  (`host_inbound_protocols_except` → `ZoneHostInbound.ndp_excluded`).
  `protocols all` now expands to ndp on ip6.
- **Regression**: `TestHostInboundNDP15671*` (pkg/config: token,
  tuples, except subtraction, YANG oracle, compiled except carried),
  `TestClassifyHostInboundNDP15671` (classifier token/default),
  `TestHostInboundNDPExceptWithdrawsGlobalAccept15671` (kernel text
  payload + fence), Rust `ndp_token_and_except_15671`, plus the
  #3627 byte-identity golden gaining the `ndp` row.

## RED -> GREEN proof
