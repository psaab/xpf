## Problem

`note_worker_observed_endpoint` (`engine.rs`) runs once per
authenticated transport-data record and takes the peer's roaming
`Mutex` even in steady state (`pending == false` falls through to
`lock()`; the `pending && try_lock` fast path CAS-writes mutex
state). Every worker queue for one peer bounces the same line per
packet. Adjudicated GENUINE (Medium) in #8869 calibration batch 2.

## Direction

Per-peer lock-free last-observed snapshot (`RoamSnapshot`: seqlock
+ drain generation, one cache line), compared before any lock;
mutex only on change; drain semantics preserved. The mailbox is
explicitly weaker than last-write-wins linearizable (stale
observations E1–E4 permitted, OP-1 assumed) — full contract
normative in `peer.rs` (`RoamSnapshot` docs) + `engine.rs`
(`note_worker_observed_endpoint` docs); `docs/pr/9644/plan.md` §5.3
(uncommitted worktree file, audit-only) is the review record,
approved via §11.7 sign-off (parent, APPROVE-WITH-CONSTRAINTS).
