# #13930 - restrict ARP ownership to the receiving interface

- **Timestamp**: 2026-10-16
- **Action**: The shim passes non-IP ARP frames to the kernel, whose default `arp_ignore=0` permits replies for local addresses on other interfaces in the same routing instance. Added `arp_ignore=1` and `arp_announce=2` to the host forwarding posture at both `conf/all` (existing interfaces) and `conf/default` (future interfaces). The kernel continues answering for addresses configured on the receiving interface; explicit proxy-ARP responders are unchanged.
- **Validation**: `go test ./pkg/daemon -run '^TestHostPostureARPIgnore13930$' -count=1` failed on pristine `origin/master` with all four posture entries missing and passed after the change. `go build ./...` passed. `go test ./pkg/daemon` timed out after 10 minutes; the log showed permission-denied sysctl warnings and a blocked `net.InterfaceByName` netlink receive in `TestHostInboundFilterApplyFailureSurfaced`.
- **Risk**: Host posture writes remain best-effort, so a procfs write failure is logged and can leave the kernel default in effect; this follows the existing host-posture contract. This is L2-local disclosure / wrong-segment ARP ownership, not a transit-policy bypass.
