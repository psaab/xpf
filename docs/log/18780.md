# #18780: bound the expiry pass per call; fence replicas in one pass

- **Timestamp**: 2026-11-08
- **Issue**: after an RG activation a worker stalled ~11-12 s at T0+120 s.
  The #18704 watchdog moved the RGs, the peer repeated it, and the cluster
  looped every ~135 s under a ~17k-session UDP burst.
- **Mechanism, re-verified on master `b57a950e21`** (the issue's 11-01
  analysis was written against `d199fe64b6`/`588c572462`):
  - **Alignment.** `RefreshOwnerRGS` → `refresh_for_ha_transition`
    (`session/mod.rs` `refresh_in_place`, `RefreshPolicy::HaTransition`)
    re-stamps every HA-managed row to T0 and zeroes `seen_rg_epoch`. With
    UDP's 60 s window the whole table crosses in ONE wheel tick at T0+60
    (SELF-HEAL) and again at T0+120 (AGE). `WorkerLocalImport` counts as
    peer-synced (`entry.rs` `is_peer_synced`), so on the authoring node 5/6
    of every table follow this path.
  - **No budget.** `expire_stale_entries_ha` (`session/expire.rs`) drained
    every due bucket in one call. Each reaped row's teardown, plus its Close
    flush, ran in the same `worker_loop` iteration
    (`afxdp/worker/loop_body/housekeeping.rs`). The heartbeat is stored once
    per iteration, so the whole cohort fell inside one heartbeat gap.
  - **Per-row global-lock cost.** `#18663` (landed) made
    `shared_node_served_evidence` keyed, so the expire-pass probe is no
    longer O(N). It still took the `shared_sessions` lock (plus
    `served_aliases` on a direct miss) for every crossed row, UDP included,
    although `opening_companion_keeps_alive` returns false for non-TCP and
    closing rows and is not called for deliberate reaps.
  - **The remaining quadratic.** In `afxdp/worker/loop_body/gc_teardown.rs`
    `reap_expired_sessions`, every expired `WorkerLocalImport` replica ran
    `shared_sessions.lock()` + `values().any(..)`. An unanswered UDP row (the
    one-packet burst shape) is never stamped Established, so its scan never
    short-circuited: C replicas × N shared rows under the node-global lock.
    (Corrected in the R8 fold, F2: an ANSWERED UDP flow's shared rows ARE
    stamped Established by the ct-slice restamp, see change 3 below; the
    earlier "a UDP row is never Established" was wrong.)

## Change

1. **Per-call budget** (`session/mod.rs` constants, `session/expire.rs`,
   `session/wheel.rs`).
   - Limits per call: at most `EXPIRY_PASS_MAX_REAPS = 256` reaps and at
     most `EXPIRY_PASS_MAX_POPS = 4096` wheel hints examined.
   - A cut pass sets `expiry_backlog`. The next call bypasses the 1 s gate
     and resumes the cut bucket's snapshot remainder
     (`SessionWheel::resume_due`).
   - `last_gc_ns` and the PPTP association sweep advance only on fresh
     passes.
   - Compile-time asserts: reaps ≤ pops, and reaps < `MAX_SESSION_DELTAS`.
   - Why 256: it is the `WORKER_COMMAND_DRAIN_BUDGET` / `drain_deltas(256)`
     slice for the same class of work.
2. **Lazy node-served evidence** (`session/expire.rs`). It is computed only
   when the row is `companion_eligible && TCP && !closing`, which is exactly
   `opening_companion_keeps_alive`'s precondition. Decisions do not change.
3. **Replica fence in one pass** (`gc_teardown.rs::replica_fence_marks`).
   - The #16223 predicate is unchanged, including its protocol-blindness.
     The ct-slice collector `established_forward_slice` takes any answered
     forward row, UDP included, and `restamp_shared_handshakes_established`
     stamps that row's shared rows Established. A "skip non-TCP" shortcut
     would therefore unfence an answered UDP flow's replica.
     Correction: on 11-08 I first named `advance_shared_handshake_for_tuple`
     as the producer. That helper has no production caller (the lint ratchet
     flags it dead in release), so the pin cell drives the ct-slice chain
     instead.
   - It is evaluated for the whole reap call in one `shared_sessions` pass,
     O(N + C log C), instead of C full scans.
   - The lock is taken with `lock_shared_recover`. The old
     `.lock().map(..).unwrap_or(false)` read a poisoned map as "not fenced",
     which is the form `docs/engineering-style.md` forbids.
4. **Not changed**:
   - The activation re-stamp. It is the #2120 promotion contract. A spread
     was considered, and the coordinator dropped it (2026-11-08) because the
     budget alone removes the stall.
   - `RefreshOwnerRGS` itself, which is still one O(table) command at T0
     (filed separately, see Lab).
5. **#10309 contract change (documented).** Three cells asserted that ONE
   expiry call reaps all 5000 rows, which is the property this change
   removes:
   - `session::tests::expiry_over_capacity_tick_loses_no_close_10309`;
   - `session::tests::expiry_over_capacity_tick_with_full_ring_loses_no_close_10309`;
   - `afxdp::session_glue::tests::over_capacity_expiry_close_overflow_reaches_all_consumers_10309`.

   They now drain the cohort across continuation calls without draining the
   delta ring between calls, so the ring still overflows into the returned
   suffix. Every Close, overflow and consumer assertion is byte-identical;
   only the `expire_stale_entries` call line and one message string changed
   (`expire_cohort_until_drained_18780` in `session/tests.rs`).
   Two more master cells encoded the one-call shape and are converted the same
   way:
   - `session::tests::wheel_sustained_overload_drains_all_buckets` (#965:
     "a single GC call drains all ... No per-tick cap") now drains in exactly
     `ceil(N / 256)` consecutive calls.
   - The `run_expire_ha` helper (54 HA cells) treats one GC pass as the fresh
     call plus its continuations and aggregates `last_pop_stats` over them.
     That changes only cells whose simulated time jumps spend the pop budget
     re-rotating far-future hints: `expire_reaps_held_at_abs_cap_for_long_timeout`
     jumps 30 days in one call.
