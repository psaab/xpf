## F-091 — single-frame containment in the UMEM primitive

`MmapArea::slice()`/`slice_mut_unchecked()` enforced whole-mapping
containment only, so a cross-frame descriptor forwarded adjacent-frame
bytes. Both now also reject `len > 4096` and
`(offset & 4095) + len > 4096`. No strict base-alignment check: pool
offsets are 4096-aligned bases but production RX addrs are `base+256`
(UMEM_HEADROOM) and in-place TX addrs are `base+256±4`, so containment
— not alignment — is the sound bound. All production callers already
fail closed on `None`; only two test fixtures spanned frames and were
fixed to stay single-frame (no bypass hatch). Cells:
`mmap_area_rejects_span_across_frame_boundary`,
`mmap_area_admits_single_frame_boundary_shapes`,
`mmap_area_contained_slice_is_byte_identical`,
`segment_forwarded_tcp_frames_refuses_cross_frame_span`.

## F-092 — validate reaped completions, surface skew

`tx/rings.rs`: the `outstanding_tx == 0` early-return (which hid skew
forever) is gone — the ring is always consulted; `saturating_sub`
became checked accounting with the delta counted in
`TX_COMPLETION_SKEW_TOTAL`; the untracked-completion else-branch drops
non-`offset % 4096 == 0` / out-of-range offsets into
`TX_COMPLETION_INVALID_TOTAL` (sound: the else-branch provably receives
only aligned pool pops — every unaligned submit pairs with a Fill
recycle and never reaches it); `drain_pending_fill` range-checks into
`FILL_INVALID_TOTAL`. All four counters ride the full Rust surfacing
chain (static + Coordinator getter + refresh_status + ProcessStatus
serde field + roundtrip test + wire fixture); eprintlns are first-10
capped. The cross-slot `None` arm masks to base so migrated `base+256`
frames are not leaked at the new else-branch check. Cells: pure-offset
predicates, skew accounting, invalid-completion drop, fill-submit drop,
plus byte-identical controls.

## F-093 — shed, don't respawn

Respawn is not cheap here (SessionTable + bindings + UMEM/XSK are owned
by the worker thread; no single-worker remove/restart primitive exists;
plans are consumed at bringup), so per the issue's sanctioned
alternative the lane sheds: record-keyed HA fan-out sites skip dead
workers, count `WORKER_COMMAND_QUEUE_SHED_TOTAL` (third signal beside
drops and poison recoveries, fully status-wired), and the stale
"queues grow without bound" comment is corrected (`push_bounded` caps
at 4096 — the residual slice-based-producer backlog is bounded).
Forwarding recovery for the dead worker's bindings stays full
reconcile / daemon restart per #925. Cells: direct shed cell + wiring
cell through `refresh_status`.

## F-094 — per-connection containment + poison recovery

New `server/helpers/guards.rs`: `lock_server_recover` (generic poison
recovery twin of `lock_shared_recover`, first-10 capped log) replaces
the six request-path `.expect`s (handlers ×4, planning settle-wait,
persistence lock line — the fail-on-revert probe is untouched), and
`serve_one_catch_unwind` wraps both accept loops so a handler panic
drops one connection, counts `SERVER_HANDLER_PANICS`, and the listener
continues (Err arm reproduces the pre-existing per-socket log lines
verbatim). Startup/shutdown locks keep `.expect` with why-comments
(single-threaded startup has no poisoner; shutdown has no next request
to recover for). Placement note: the wrapper lives in `guards.rs`
beside the lock helper rather than in lifecycle/handlers — one
cold-path containment module, call-site-only diffs elsewhere. Cells:
poison-heal + count, fast-path silence, ok/err/panic containment
(reaching the end IS the loop-continues property).
