# Gate the session-miss SYN-alarm drain on the ingress zone's own screen state (#13000)

- **Issue**: #13000, follow-up of #12875 (same per-zone gate doctrine; log-only).
- **Cause**: `syn_alarm_pending` is a WORKER-GLOBAL flag on `ScreenState`. #12875
  gated the two screen stages' drains by returning early for ingress zones with
  no screen state, but the session-miss drain in `poll_descriptor/mod.rs` (added
  by #12872 for the SYN-ACK miss hook) still called
  `screen.take_syn_alarm_event()` for EVERY zone's session-miss packet. That arm
  runs for unscreened zones too, so a pending alarm raised by a screened zone
  could be consumed — and emitted as a log-only `syn-flood-alarm` against the
  UNSCREENED packet's tuple and `from_zone_id` — by a zone with no screen
  configuration of its own: the exact mis-attribution class #12875 removed from
  the stages, surviving at the one drain site it did not touch.
- **Change**: The session-miss drain now runs only when
  `screen.zone_has_screen_state(from_zone)` — the #12875 helper over the same
  three sets (resolved profile, unresolved reference, inert reference) — and the
  gate short-circuits BEFORE the take, so an ingress zone with no screen state
  leaves the flag pending for the next screened-zone packet's drain instead of
  clearing it unserved. Zones with screen state (the raising zone included) are
  unchanged: the drain still fires while the raising packet's tuple/zone are in
  scope, exactly as #12872 wired. No verdict, drop, counter, or cadence behavior
  changes; the alarm remains log-only (PERMIT).
- **Regression coverage** (`userspace-dp/src/screen/tests.rs`):
  `miss_syn_alarm_drain_is_gated_on_ingress_zone_13000` — source guard (the
  #12872 pattern for descriptor-inline wiring): after the session-miss
  `.syn_ack_flood_drop_on_new_flow(` hook, the drain condition must be exactly
  `zone_has_screen_state(from_zone) && screen.take_syn_alarm_event()` — one
  condition, gate first, so the gate short-circuits before the take and no
  separate-path gate can clear the flag unserved. The #12872 wiring guard's
  matcher was updated for the take call moving inside the gated condition; its
  tuple/zone/reason assertions are unchanged.
- **RED evidence**: On pristine origin/master (fefd415a5) with only the test
  change applied, `miss_syn_alarm_drain_is_gated_on_ingress_zone_13000` FAILED
  at `session-miss SYN alarm drain is gated on the ingress zone's own screen
  state (#13000)` — no `zone_has_screen_state(from_zone)` exists at the drain —
  while the #12872 guards (`syn_ack_miss_alarm_drain_is_wired_to_its_packet`,
  `syn_ack_miss_alarm_is_drained_before_later_packet`,
  `syn_ack_miss_alarm_emits_on_originating_packet`) still passed on the updated
  matcher.
- **GREEN evidence**: With the fix,
  `miss_syn_alarm_drain_is_gated_on_ingress_zone_13000` and
  `syn_ack_miss_alarm_drain_is_wired_to_its_packet_12872` pass; the #12872
  behavior tests (`syn_ack_miss_alarm_is_drained_before_later_packet_12872`,
  `syn_ack_miss_drop_src_alarm_is_drained_12872`) and the real-descriptor-path
  `syn_ack_miss_alarm_emits_on_originating_packet_12872` pass unchanged,
  proving the raising screened packet still drains and emits its own alarm
  through the gated call. `screen::tests` 261/261, the #12875 stage regressions
  pass, and the full `--bin xpf-userspace-dp` suite passes (7872 passed /
  0 failed / 8 ignored) on the final tree; `git diff --check` and
  `cargo fmt --check` are clean for every line this change touches (the
  repository has pre-existing rustfmt-version drift unrelated to this change).
- **Blast radius / risk**: Zero for any packet whose ingress zone has screen
  state — the gate is true and the drain is byte-for-byte the #12872 behavior.
  For a session-miss packet on a zone with NO screen state (including an
  unresolvable zone name), the drain is now skipped: no alarm is emitted against
  that zone and a pending flag is left for the next screened-zone packet. On
  current master both setters of the flag drain it same-packet, so no observable
  sequence changes today; the change removes the latent ungated drain the
  #12875 doctrine left behind. Residual (out of scope, same latent shape): the
  adjacent `take_scan_table_pressure_event` drain is likewise ungated, but its
  only setter is the same-block scan/sweep hook, so it is same-packet balanced
  today for every zone that can reach it.
