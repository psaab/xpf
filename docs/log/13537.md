# Issue #13537 — compile flat VRRP group runs

## Why

A flat `set ... vrrp-group <id> priority <n> virtual-address <vip>` command
is represented by SetPath as a chain of child nodes. `parseVRRPGroups` read
only direct properties, so it retained the priority but missed the chained
VIP; strict compilation then falsely reported that the group had no
`virtual-address`. The strict schema walker also rejected the chain because
VRRP groups had not opted into the supported packed-flat-run grammar.

## What

VRRP group schemas now opt into `packedFlatRun`, so strict schema validation
and the compiler both expand the same property chain using the shared schema.
`parseVRRPGroups` reads expanded children through the existing schema-gated
`expandFlatRun` helper. A regression requires strict schema validation and
compilation to accept the reported spelling, compares it with equivalent
separate set commands, and checks IPv6, repeated VIP statements, unknown
properties, and the existing missing-VIP rejection.

## Risk

Only the VRRP group grammar gains the existing schema-declared flat-run
spelling, and its compiler reader sees the same expanded properties. Unknown
properties and groups without a virtual address remain rejected.
