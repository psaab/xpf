# Issue #12256 — repair missing-neighbor retry fixtures

## Why

Two missing-neighbor regression cells were red on the verified base. Both test fixtures omitted production metadata needed to reach the behavior under test: the untagged GRE test modeled a tagged-only trunk without native VLAN 80, and the ordinary retry test supplied zero source and destination L3 addresses, causing the normal transit-source guard to drop the queued packet before it could be transmitted.

## What

The untagged GRE helper now models VLAN 80 as the parent interface's native VLAN only for the untagged case. The ordinary retry cell now supplies its actual IPv4 source and destination in `ForwardPacketMeta`. No production dataplane behavior changed.

## Validation

- **RED before** (STEP-0 base `a714c90d472a3c3d98a3799831cfef3ec311a61c`): both targeted cells failed. The untagged cell observed `missing_neigh = 0` instead of `1`; the ordinary retry cell panicked because no prepared TX was produced. The complete `tests_decap_dnat_table` module had `20 passed; 2 failed`, with only these two cells failing.
- **GREEN after**: each targeted cell passed individually. `CARGO_TARGET_DIR=/var/tmp/cargo-12256 cargo test --bin xpf-userspace-dp afxdp::tests_decap_dnat_table:: -- --nocapture` passed all `22` tests.
- Cargo used `/var/tmp/cargo-12256` because `/dev/shm` had only 68 KiB free. The build reported the host libbpf 1.7.0 / vendored libbpf 1.6.3 version warning; compilation and tests completed successfully.
- No live cluster was exercised.

## Risk / residual

Test-fixture-only change. The production neighbor retry and VLAN admission paths are unchanged.
