# 14620 — postrm writes `ip_forward=1` and `ipv6 all.forwarding=1` on never-owned hosts (#10733 residual)

- **Timestamp**: 2026-10-17
- **Defect**: `debian/xpf.postrm` `cleanup_transit_state` unconditionally
  wrote `1` to both transit sysctls on `remove|purge` whenever
  `xpfd transit-barrier remove` exited 0 — which it does vacuously when no
  barrier ever existed (`RemoveTransitBarrier`: absent → nil). A foreign
  host that merely installed the package and never committed a config
  (xpf never wrote the sysctls there, per the #10733 contract in
  `pkg/daemon/README.md`) had its forwarding posture silently flipped to
  an unfiltered IPv4/IPv6 router on uninstall, also losing v6 RA
  acceptance.
- **Fix (daemon side)**: `pkg/daemon/daemon_transit_gate.go` —
  `recordTransitGateOwnership()` is called from every latch arm of
  `shouldManageTransitGate()` before any gate sysctl write. It durably
  writes `/var/lib/xpf/transit-gate-owned` (`fsatomic.WriteFileDurable`)
  containing the host's pre-xpf values (`ipv4=`/`ipv6=`), never
  overwriting an existing record so priors survive restarts and a
  reinstall does not re-capture the closed values. The path is a package
  var for tests. Best-effort: a failed write logs a Warn and the gate
  still actuates fail-closed.
- **Fix (postrm side)**: `cleanup_transit_state` restores ONLY when
  `$TRANSIT_OWNED_FILE` (`/var/lib/xpf/transit-gate-owned`) exists, and
  restores each recorded prior via the new `restore_transit_sysctl`
  helper (values normalised to 0|1, missing/corrupt → 1 so an owned host
  is never stranded transit-closed). Without the record it logs and
  leaves both sysctls untouched. `remove` leaves the record in place;
  `purge` deletes it after the restore (package-derived runtime state,
  not `/etc/xpf`).
- **Regression (shell)**: `test/debian/postrm-test.sh` gains the decisive
  z6 cell `remove_never_owned_keeps_sysctls_closed` (no record, priors
  0/0, stub barrier-remove succeeds → both stay 0), its purge twin,
  owned controls (`remove_owned_restores_recorded_priors`,
  `remove_owned_restores_zero_and_mixed_priors`,
  `remove_owned_corrupt_record_defaults_open`,
  `purge_consumes_transit_ownership_record`), and `mark_transit_owned`
  seeding for the pre-existing owned-host cells
  (`remove_keeps_versions`, `input_failure_still_restores_forwarding`).
  RED on the pre-fix postrm (`FAIL: IPv4 forwarding opened on
  never-owned host (#14620)`), GREEN after; the barrier-failure cell
  still stays at 0. Full suite passes under both `sh` and `dash`.
- **Regression (Go)**: `pkg/daemon/transit_ownership_record_14620_test.go`
  — `TestTransitOwnershipRecordedOnLatch14620` (committed host latches →
  record holds the pre-xpf 0/0 priors; a second latch does not overwrite)
  and `TestTransitOwnershipNotRecordedOnNeverOwnedHost14620`
  (never-committed store → no latch, no record).
- **Docs**: `pkg/daemon/README.md` ownership-boundary section now states
  the removal-time restore contract.
- **Residual (stated, upstream-owned)**: hosts owned by a pre-#14620
  daemon have no record (the old daemon never wrote one), so the new
  postrm leaves their sysctls at whatever the shutdown close left (0)
  instead of restoring 1 — fail-closed, and correctable by the operator;
  recording priors retroactively is impossible. A separate wart found
  while fixing: `shouldManageTransitGate()` itself does disk I/O
  (appliance-marker stat) on every call; now also a record stat/write on
  first latch only. Not changed here.
