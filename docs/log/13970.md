# #13970 — decapsulated policy and NAT hit counters use outer length

- **Timestamp**: 2026-10-16
- **Action**: Charge slow-path policy and per-rule NAT byte hits using the packet metadata length, matching decapsulated flow-cache hits.
- **Base**: `origin/master` `9db06f3dd`
- **Branch**: `fix/13970-campaign-zero`
- **Files**: `userspace-dp/src/afxdp/poll_descriptor/mod.rs`, `userspace-dp/src/afxdp/tests_gre_local_delivery.rs`, `docs/log/13970.md`

## Why

GRE/WireGuard decapsulation replaces `packet_frame` and `meta` with the inner packet, but leaves `desc` referencing the outer UMEM frame. Slow-path policy and NAT hit counters passed `desc.len`, while flow-cache hits use `meta.pkt_len`. Tunnel hit bytes therefore depended on cache state and included the outer headers on initial packets.

## What changed

- Switched every slow-path policy evaluator/counter and per-rule DNAT/SNAT hit site in `poll_descriptor` to `meta.pkt_len`, preserving packet-count semantics and the existing counter timing.
- Added an end-to-end GRE transit regression with tagged-underlay ingress, an admitted policy and SNAT. It asserts one policy/NAT hit and exact inner-frame byte totals.
- Initial comparison branch had a coordinator test fixture inserting an `IpAddr` into a `HashSet<(u32, IpAddr)>`. Current `origin/master` already supplies `(0, inner_dst)`, so no separate test-build correction is needed in this PR.
- No flow-cache behavior or RX outer-frame telemetry changed.
