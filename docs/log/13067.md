# Issue #13067: `cos_be_contention_validate.py` during→after queue monotonicity

- **Timestamp**: 2026-10-14
- **Action**: `test/incus/cos_be_contention_validate.py` `analyze_phase` computed only `before→after` (`deltas`) and `before→during` (`during_deltas`) queue deltas, so a dataplane counter reset or a complete traffic stall after the `during` snapshot still certified `PASS` (deep-review D10-07). Added `post_during_deltas = queue_deltas(during_shapes, after_shapes)` and enforced three-snapshot monotonicity (`before <= during < after`) on every queue's `sent_bytes`/`park_root`/`park_queue` telemetry via a shared `_negative_drain_delta_failure` helper covering all three windows (the pre-existing before→after gate, plus new before→during and during→after gates), plus a `min_expected_sent_bytes` floor on each expected queue's during→after `sent_bytes` delta so traffic must flow in both halves of the phase. Failure reasons stay per-cell and fail-closed; missing-snapshot fallbacks still FAIL.
- **Action**: documented the both-window drain gates and the per-window `MIN_EXPECTED_SENT_BYTES` semantics in `docs/cos-best-effort-contention-harness.md`.
- **Regression**: four new cells in `test/incus/cos_be_contention_validate_test.py`, each green-light on every other gate so only the blind window distinguishes: `test_fails_dataplane_counter_reset_between_during_and_after` (before=0, during=500,000,000, after=1), `test_fails_complete_stall_between_during_and_after` (after == during), `test_fails_park_token_regression_between_during_and_after` (park_root dip invisible to the net before→after delta), and `test_fails_unexpected_queue_counter_dip_between_before_and_during` (net-zero dip on a non-expected queue that escaped the wrong-queue gate).
