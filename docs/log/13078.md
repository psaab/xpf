# Issue #13078 — D5-05 duplicate expiry probes

## Why

D5-05 identified local session and forward-NAT miss paths that repeated index lookups to distinguish an expired record from an absent record. Repeating probes adds work on packet-path misses; treating an expired local record as absent would also risk resurrecting a stale shared replica.

## What

Added explicit `Live` / `IdleCrossed` / `Absent` results for local exact, forward-wire, and reverse-NAT probes. The mutable exact lookup now returns the stale-vs-absent classification during its existing key-index read, so across-scope packet lookup does not probe the exact key a second time. The reverse-NAT matcher tracks stale eligible candidates while walking its index once, preferring any later live candidate. Expired local records remain fail-closed and do not fall through to shared state. Test-only counting verifies one exact primary-index probe through the packet caller.

## Validation

The packet-path regression was made RED by restoring the old mutable-lookup-plus-read-only-probe caller sequence: it observed 2 probes against an expected 1. After reapplying the fix, the targeted regression passed. The full `cargo test --manifest-path userspace-dp/Cargo.toml` run reported 7,887 passed, 1 failed, and 8 ignored; the sole failure was `protocol::tests::wire_invariant_default_specimens`, reporting drift against `tests/fixtures/protocol_wire_v1.json`. Running that failing test on a clean `origin/master` worktree reproduced the same protocol-fixture drift, confirming it is a baseline failure unrelated to this issue.

## Risk

The change preserves matching and strict-expiry semantics; stale candidates continue to block shared fallback. The exact-key count is test-only instrumentation and adds no release-build field or counter work.
