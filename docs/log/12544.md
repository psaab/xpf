- **Date**: 2026-10-13
- **Issue**: #12544
- **Why**: The flat apt-repository builder compared apt-ftparchive's `Valid-Until` to an epoch captured before apt-ftparchive ran. apt-ftparchive derives `Valid-Until` from wall clock rather than the pinned Release `Date`, so crossing a second boundary made a correct configured horizon fail the exact-epoch check.
- **What**: The builder now requires exactly one parseable Release `Date` and exactly one parseable `Valid-Until`, derives the configured horizon from that emitted Date, and accepts only the expected epoch or one second later. Wrong/early horizons remain fail-closed. Deterministic fake `date` and `apt-ftparchive` coverage reproduces the +1s boundary, rejects +2s, and checks missing, duplicate, malformed, early, substantially skewed, and late values plus duplicate Date refusal.
- **RED-before**: `python3 scripts/dist/test_build_apt_repo_valid_until_12544.py` initially failed the boundary cell because it got `want epoch 1700604800, got 1700604801`; the duplicate-Date cell also failed on the old code because it lacked a unique-Date check.
- **Validation**: `python3 scripts/dist/test_build_apt_repo_valid_until_12544.py` (9 tests), `python3 scripts/dist/test_build_apt_repo_inputs_9921.py` (16 tests), and `python3 scripts/dist/test_build_apt_repo_reprepro_10123.py` (17 tests) passed. `sh -n scripts/dist/build-apt-repo.sh` and `shellcheck scripts/dist/build-apt-repo.sh` passed. Manual mutants were killed: exact equality fails the +1s boundary test; removing the horizon comparison fails the early-value refusal test; removing singleton enforcement and selecting the first duplicate causes the duplicate-refusal test to fail because the build succeeds.
- **Risk**: The accepted window permits no more than one second of forward wall-clock skew. Reprepro validation is unchanged; its `Valid-Until` remains derived exactly from its own emitted Date.
- **Files**: `scripts/dist/build-apt-repo.sh`, `scripts/dist/test_build_apt_repo_valid_until_12544.py`, `scripts/dist/test_build_apt_repo_inputs_9921.py`, `docs/log/12544.md`.
