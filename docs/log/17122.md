# #17122 — R4-Q05-02: SyncedSessionEntry to SessionDelta hand-written twice in ha/

- **Timestamp**: 2026-10-27
- **STEP-0 — defect live on current origin/master?** Yes, at
  `16db8c584e`. `grep -rn 'SessionDelta {' userspace-dp/src` (non-test)
  still showed the two hand-written 21-field literals building from a
  `SyncedSessionEntry`: `userspace-dp/src/afxdp/ha/export.rs:362`
  (bulk Open) and `userspace-dp/src/afxdp/ha/tunnel_purge.rs:85`
  (purge Close), and `grep 'SyncedSessionEntry) ->'` found no
  shared-entry -> delta constructor (`from_shared` absent). Both
  literals are the sites #14303 (PPTP pair) and #14960 (fabric flag +
  session_id) had to patch in lockstep.
- **Fix.** Added `SessionDelta::from_shared(entry, kind)` in
  `userspace-dp/src/afxdp/worker/synced_entry.rs` (next to
  `SyncedSessionEntry`, so `session/` never depends on `afxdp/`; the
  `ForwardingDisposition` reference rides the existing
  `crate::afxdp` re-export already imported by `session/mod.rs`). It
  carries every field the shared entry owns — key, decision,
  metadata, `source_nat_static`, origin, `session_id`,
  `tcp_close_class`, `tcp_handshake_state`, `pptp_call_ids`, and the
  snapshotted packet counters (`fwd_packets`/`rev_packets`, byte legs
  0) — derives `fabric_redirect_sync` from the disposition in one
  place, and sets the no-local-snapshot defaults once
  (`Incremental`, `bulk_resync`/`is_admission`/`purge_retirement`
  false, `policy_generation`/`created_ns`/`last_seen_ns`/
  `observed_tos`/`observed_tcp_flags` 0).
  - `ha/export.rs`: `SessionDelta::from_shared(entry, Open)` plus the
    site-local #16217 handshake restamp (Established when node-wide
    completion evidence holds). The #14960 derive-comment is now
    owned by the constructor doc.
  - `ha/tunnel_purge.rs`: `SessionDelta { source_nat_static: None,
    fabric_redirect_sync: false, ..from_shared(entry, Close) }` so
    the purge's two deliberate overrides (G40-03) stay visible.
    One intentional, documented behaviour delta vs the old literal:
    the purge Close now carries the entry's snapshotted
    `fwd_packets`/`rev_packets` instead of `SessionCounters::default()`.
    The issue's fix direction mandates carrying the counters from
    `from_shared`; the purge path uses `push_delta_lossless` (not the
    RT_FLOW close exporter), so the counts are never rendered as
    RT_FLOW volume (#2501) — noted in the call-site comment.
  - Acceptance grep: `grep -rn 'SessionDelta {' userspace-dp/src/afxdp/ha/*.rs`
    now counts only the purge's `..from_shared` update syntax.
- **Guard test.** `from_shared_carries_every_shared_field_on_bulk_open_and_purge_close_17122`
  (`ha_tests.rs`) builds a `SyncedSessionEntry` with every carried
  field non-default (PPTP pair, SNAT static `Some(true)`, session id,
  FabricRedirect disposition, close class, handshake state, packet
  counts) and asserts: the bulk Open through the production
  `snapshot_all_sessions_export` path carries each value (handshake
  restamped Established by #16217 evidence from the synthesized
  companion's snapshotted rev count), and the purge-shaped Close
  carries each value with exactly the two deliberate overrides.
  FAIL-ON-REVERT: restoring either literal or zeroing a carried field
  in `from_shared` turns the matching assertion RED.
