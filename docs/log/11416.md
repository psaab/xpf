## Ruling status (scope boundary)

The maintainer ruling requested in #11416 (Option A cluster reservation vs
B HA-policy change vs C isolated target; the design-v4 review's recommended
answer is C) is **not recorded** — the issue's last comment (2026-10-10)
defers exactly that decision to the maintainer. Per the assignment, this
change implements ONLY the part that needs no ruling: the populated-RI
positive leg and its route-removed discrimination for the EXISTING IPv4/UDP
probe shape, using the gate's existing per-statement config-write pattern.
The IPv6 twin, TCP, and return-path legs (dual-stack echo sender, managed-peer
responder, GRE client member) remain blocked on the ruling and are NOT
implemented here.

## Why

The live gate created an empty RI plus one exact UDP FBF term and scored only
`probe_leaked=0` against a main-route control. That verdict is satisfied even
if every legitimate VRF-routed packet also drops (over-deny): no leg ever
proved that a populated RI actually forwards the steered tuple, nor that
removing the route stops it. The issue's acceptance asks for populated-RI
forwarding, a v6 twin, and return traffic; only the v4/UDP populated leg is
ruling-independent.

## What

- `test/incus/wire-routing-separation.sh` — after the existing miss window,
  the gate commits a test-owned GRE member into the RI
  (`gr-0/0/1.0`, underlay `WAN_SRC -> DEST_IP`, no `tunnel routing-instance`
  stanza so the outer transport stays in main, unit address from the reserved
  198.18.0.0/15 family, zone placement on the existing `wan` zone so the
  existing lan→wan permit policy and interface SNAT apply) plus an exact
  `/32` static route for the probe destination. It re-offers the steered tuple
  with a FRESH source port interleaved with a fresh near-miss control (tags
  R/B) under a capture filter that admits the probe only in proto-47 form —
  a main-table fallback cannot score as the positive pass. It then deletes
  only the `/32` and re-offers another fresh tuple (tags D/E) whose delivery
  must stop in any form. Both phases clear the destination/port session scope
  on both nodes first (the pre-existing inline precommit clear was folded
  into the shared `clear_steered_sessions` helper). Absence of the GRE
  member/address is checked against both node baselines before any write;
  cleanup deletes only the owned leaves; an authenticated FAIL now survives
  a failed restore (`WIRE_GATE_FAIL_STICKY=1` + `restore_failed=1`) instead
  of being demoted to RESTORE_VOID.
- `test/incus/wire-gate-lib.sh` — `wire_routing_separation_window_verdict`
  takes eight new required metrics
  (`populated_{offered,observed,control_offered,control_observed}`,
  `removed_{offered,observed,control_offered,control_observed}`).
  Precedence: miss-phase FAIL is sticky; a populated violation (control at
  the drop floor while the steered tuple emerged below it) and a removed
  violation (control at the drop floor while the steered tuple still emerged)
  are FAILs even over a miss-phase VOID or a weak other leg; a would-be PASS
  is demoted to VOID under-sampled/capture-blind on thin or blind positive
  legs; a miss-phase VOID keeps its slug. `wire_gate_finalize` gained the
  opt-in FAIL-sticky path (routing gate only; other gates unchanged).
- `test/incus/wire_routing_probe.py` — tags `R`, `B`, `D`, `E` for the new
  legs (same `<tag>10136:<seq>:` payload shape).
- `test/incus/wire-routing-separation-temporal-selftest.py` — the window
  verdict calls carry a sound positive suffix so the 16-argument contract is
  exercised.
- `test/incus/harness-result.sh` + `harness-result-selftest.sh` — the
  wire-gate adapter's required metric set for `wire_routing_separation` now
  includes the eight positive-leg keys; fixtures updated.
- `docs/firewall-validation-harness-design.md` — the Routing-Instance
  Separation row records the populated-RI positive acceptance and the
  ruling-blocked remainder.

## Risk

The populated leg's live behavior (GRE member resolution, kernel table-mirror
polls, SNAT of the steered tuple) is verified against product source and the
existing GRE fixture but not executed here; a live mismatch would surface as
VOID harness-void (config/poll failures) or as the new over-deny FAIL — both
safe directions. v6/TCP/return-path acceptance remains open on the ruling;
this change deliberately does not close #11416.
