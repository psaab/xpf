# #15052 - SNMP v1/v2c traps use the trap-group name as community

- **Timestamp**: 2026-10-18
- **Action**: `sendLinkTraps` in `pkg/snmp/traps.go` now resolves the
  trap community per trap group via the new `trapCommunityForGroup(tg)`,
  which returns `tg.Name` (the Junos semantics: `snmp trap-group <name>`
  sends v1/v2c traps with community `<name>`), falling back to `public`
  only for a nil/unnamed hand-built group. The old
  `selectTrapCommunity(cfg)` — the alphabetically-first configured
  *query* community (#2989) — was used for every group, disclosing that
  query credential (possibly a read-write one) in cleartext to every
  trap target (A20-04). `selectTrapCommunity` is removed; the deferred
  v1 job, `version all`, and v2c paths all carry the per-group value.
  `traps_community_2989_test.go` was rewritten to preserve the #2989
  determinism property under the new semantics.
- **Validation**: New `traps_community_15052_test.go` wire-level tests
  assert the on-wire community equals the trap-group name for
  `version v1`, `v2`, unspecified, and `all`, that two distinct groups
  each send their own name, and the unnamed fallback — RED on
  `origin/master` (wire community was the alphabetically-first query
  community `aaa-query`), GREEN post-fix; full `go test ./pkg/snmp/`
  suite green.
- **Risk**: Operator-visible behaviour change by design: trap receivers
  must expect the trap-group name as the community (Junos parity)
  instead of the previously leaked query community. No query-path
  behaviour changes; v3 traps are unaffected (they carry no community).
