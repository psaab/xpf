# #17913 — accept source-pool port ranges with allocation modifiers

`SchemaValidate` rejected a source-NAT pool range when an allocation modifier
followed it on the same authored `port` tail. The port-tail validator passed
`1024 to 2048 random-allocation` wholesale to the range parser, although the
configuration tree/compiler model the modifier as a sibling to the `range`
leaf. This made a valid configuration fail strict admission before compilation.

The validator now recognizes one trailing `random-allocation` or
`no-random-allocation` token, then validates the remaining range with the same
canonical 1–65535 and non-decreasing checks. Unknown, misplaced, repeated, or
extra tail tokens remain invalid. This keeps schema validation consistent with
the compiler while preserving invalid-range rejection.

Regression coverage checks same-line Junos and legacy ranges with both
allocation modifiers, a single-port range, and hierarchical syntax. Negative
controls retain rejection for zero and oversized endpoints, reversed ranges,
unknown or repeated modifiers, malformed ordering, and trailing junk.

Validation:
