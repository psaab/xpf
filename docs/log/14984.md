# #14984 - Dual-stack HTTPS per-host SANs; stop shared certificate overwrite across legs (D36-04)

- **Timestamp**: 2026-10-18
- **Action**: Mint per-host dual-stack HTTPS SANs and stop the shared-certificate
  overwrite across legs. `Server.certGen` now takes the full configured bind-host
  set (`[]string`) instead of a single host: `generateSelfSignedCertAtWithStatusHosts` /
  `generateSelfSignedCertAtWithStatusMulti` union every non-loopback IP (and
  DNS-safe DNS name) from all `effectiveHTTPSAddrs` into the minted leaf, and the
  durable load path runs `warnStaleLoadedCert` for each configured host. Each HTTPS
  leg built by `buildHTTPSServer` carries its OWN `managementTLSCertificateSlot`
  (per-leg `managementTLSGetCertificateFor` closure) registered in
  `httpServerTLSState`, so `managementTLSCertificateForServer`,
  `WarnStaleMgmtCertForHostName`, and `HTTPSCertForTest` read the live leg's own
  state instead of whichever family installed last. The former shared
  `s.tlsCertificate` atomic survives narrowed as the fallback slot
  `tlsCertificateSlot` for hand-built `*http.Server` fixtures and the
  never-completed boot path (justification recorded in the slot's doc comment);
  the monitor-driven refresh (`refreshManagementTLSCertificateLocked`) and
  `ReconcileTLSCertificate` publish rotated state into every live leg's slot under
  `tlsCertificateMu` (`publishManagementTLSCertificateToLiveLegs`), and a
  handshake-time expiry marks only its own slot invalid so a stale leg cannot
  poison a live sibling. `stopLegLocked` deregisters retired legs
  (`unregisterHTTPServerTLSState`), keeping the registry bounded by the live set.
  `SetTLSCertDirForTest` now restamps each leg's own slot (plus the fallback) after
  swapping in the durable loader.
- **Validation**: New regression `TestDualStackPerLegTLSCert14984`
  (`pkg/api/tls_cert_dualstack_14984_test.go`) invokes each built leg's actual
  `TLSConfig.GetCertificate` closure and asserts the leaf verifies for its own
  family bind IP (10.0.0.1 / 2001:db8::1) via `VerifyHostname` + IP-SAN presence,
  that `HTTPSCertForTest` reads the first leg, that both loopback families answer
  HTTPS `/health`, and that a single-stack IPv4-only control covers its bind.
  RED on `origin/master` 27920f2f8c (test-only copy to a detached baseline):
  `httpsServers[0] (10.0.0.1:8443) leaf does not verify for its own bind host
  10.0.0.1: x509: certificate is valid for 127.0.0.1, ::1, 2001:db8::1` — the
  v4 leg's closure returns the last-built v6 leaf, exactly the shared-store
  overwrite. GREEN after the fix (each leg's leaf covers both families).
  Controls staying green: `TestDualStackListenerBindsBothFamilies14583`,
  `TestManagementTLS*` (reject-window custom pair, monitor expiry without SNI,
  custom rotation, system-generated re-mint), `TestBuildHTTPSServerThreadsBindHost`
  (updated to the widened `certGen([]string)` shape), TLS SAN/stale-cert suites,
  `ReconcileHTTPS`/dual-stack reconcile, and `go vet ./pkg/api/` (clean).
  Pre-existing failures NOT introduced by this change (present on the base
  snapshot's full `go test ./pkg/api/` run and unrelated to TLS): a firewall
  doc-guard env-path cell, a userspace metrics-count cell, and the
  `session_iface_identity_6960` commit-check cells; `go vet ./pkg/daemon/` was
  blocked on that snapshot by an unrelated `overlay.SlaveSet` error.
- **Risk**: The durable pair is still loaded as-is on rebind (no TOFU churn, #1916
  D6 unchanged) — only fresh mints gain the union SANs and the stale-cert
  diagnostic now checks every configured host. Custom (operator) pairs are
  unchanged apart from per-leg publication on rotation. No behaviour change
  outside the cited mechanism: HTTP legs, auth slots, and non-TLS paths are
  untouched; handshake-time expiry now fails closed per-leg rather than
  poisoning the shared state read by siblings.
