# Pipe filters fail to strip quotes on pipeArg; SplitPipe mis-splits quoted " | " (#15722)

## Why

V47-03 (deep-review, synthesis MATERIAL at f214fac). Two linked defects in
the one shared splitter `cliterm.SplitPipe` (`pkg/cliterm/pipefilter.go`),
used by both the local CLI (`pkg/cli`) and the remote client (`cmd/cli`):

1. `SplitPipe("show interfaces | match \"Physical interface\"")` returned
   `pipeArg = "\"Physical interface\""` — the surrounding quotes were passed
   to `FilterStream` as pattern text, so `strings.Contains` looked for the
   literal quoted string and matched nothing.
2. `SplitPipe("show version | match \"a | b\"")` used
   `strings.LastIndex(line, " | ")`, which found the `" | "` *inside* the
   quoted argument, resolved the trailing token `b"` as the filter verb,
   found it unrecognised, and returned `ok=false` — the whole pipe was
   silently ignored and the full unfiltered output was shown.

The doc comment on `SplitPipe` claimed the last-split allowed
`| match "a | b"`; the quoted probe contradicted it.

## What

Only `pkg/cliterm/pipefilter.go` changes behaviour; both surfaces inherit it
because they share the splitter (no second copy to drift, #4968/#7172):

- `lastUnquotedPipeSep`: one forward scan tracking quote state — inside
  double quotes a backslash escapes the next byte (`\"` does not close,
  `\\` consumes both backslashes so a following quote closes); inside
  single quotes a backslash is literal (POSIX rule). Only a `" | "` outside
  any quoted region is a delimiter, so a quoted pipe in the command part is
  data too. An unterminated quote swallows the rest of the line: a trailing
  `| match "a | b` is treated as an unquoted filter whose arg keeps its
  leading quote (the earlier unquoted delimiter still splits — the
  fallback direction), while an unterminated quote before the only pipe
  hides it and the line declines whole.
- `stripPipeArgQuotes`: an argument entirely wrapped in one matching pair
  of single or double quotes is unquoted (`"Physical interface"` →
  `Physical interface`, `""` → empty). Inside double quotes `\"` and `\\`
  are unescaped (the spellings `pkg/config`'s lexer honours); other
  backslash sequences stay as typed, so a pattern like `"a\nb"` keeps its
  backslash. Inside single quotes nothing is unescaped. Quotes that do not
  wrap the whole argument (internal `a"b`, trailing `a"`, mismatched `"a'`,
  trailing text `"a" b`) are data and stay byte-for-byte, as is an
  unterminated quoted arg.
- Unquoted behaviour is unchanged: unquoted multi-word args stay whole,
  `| match a | b` still declines whole (trailing token is not a filter),
  unknown filters / handler pipes (`| save`, `| display set`) still return
  the original line untouched, and `FilterStream` is untouched (still
  case-sensitive literal substring, #4968).
- `pkg/cli/permissions_regex.go`: comment only. The gate tokenises with
  `strings.Fields`, so a quoted `"a | b"` argument still reaches its
  multi-stage verb check as bare `|` words and fails CLOSED for restricted
  classes — a pre-existing over-refusal (docs/log/14714.md residual), not
  a bypass. Making the gate quote-aware was out of this issue's mechanism;
  the comment now states the interaction explicitly instead of implying
  the splitter already covers it.
- One pre-existing corpus row in `splitpipe_7172_test.go`
  ("pipe inside a quoted arg, whole line returned") pinned the defective
  behaviour and now pins the fixed one.
- Docs: `docs/junos-cli-reference.md` Pipe Filters section documents the
  quoting; this log.

## Risk

- Behaviour delta is confined to lines whose pipe argument is quoted or
  contains a quoted `" | "`: those previously filtered on the quoted text
  (matching nothing) or ignored the pipe entirely; they now filter on the
  unquoted pattern. A script that deliberately matched literal quote
  characters via `| match '"foo"'` would now match `foo` — that spelling
  was indistinguishable from the Junos quoting idiom and never documented.
- Authorization: SplitPipe still never truncates when it declines
  (`TestSplitPipeNeverTruncatesWhenItDeclines7172` green), and the
  reassembled `pendingPipeSuffix` for a quoted-arg filter now carries the
  unquoted stage (`match a | b` instead of the whole line reaching the
  handler un-split), so the gate judges the command the dispatcher runs.
  Restricted classes still fail closed on a quoted `"a | b"` argument at
  the gate's own verb check (above) — an over-refusal, the safe direction.
