# Issue #16083: synchronous syslog forwarding blocks daemon goroutines (A9-06)

- **Timestamp**: 2026-10-21
- **Problem**: `SyslogSlogHandler.Handle` called `SyslogClient.Send` synchronously for every non-EventReader slog caller. A blackholed TCP/TLS collector could park arbitrary daemon goroutines (commit/apply, reconcile, API handlers) behind the client mutex for the write/dial timeout. The stall was recurrently bounded (write timeout, then reconnect cooldown fail-fast), which held severity at Low.
- **Fix**: Route ALL slog through the existing bounded per-client writer regardless of caller context. `Handle` now enqueues via `sendFromSlog(r.Time, ...)` (timestamp carried for #15699 parity); the handler-wide #2287 goroutine guard is replaced by a per-client writer-scoped drop (`goroutineContext` in new `goroutine_context.go`, replacing `goid.go`): a record emitted from inside a client's own writer loop is dropped and counted (`slogDropped`, folded into `DroppedWrites`), never re-queued. Slog records cap at 64 KiB each (depth 128 ≈ 8 MiB/client); overflow and oversize drops warn at most once a second (emitted outside the writer mutex). `EventReader.ForwardLogMsg`'s syslog branch queues too; its local-writer branch stays synchronous because callers rely on the returned error. Direct `Send`/`SendBinary` keep their synchronous contract.
- **Fold (Opus2)**: (1) Restored `aggregatorFlushJoinTimeout` (deleted by the original comment rewrap; `pkg/daemon` failed to build). (2) Orderly shutdown drain: `SyslogSlogHandler.ShutdownTimeout` / `SyslogClient.CloseTimeout` deliver the queued backlog behind a flush barrier within one shared deadline, then close; the remainder is discarded and counted. `runShutdownSequence` calls `shutdownSlogHandler` (2s) after `shutdown complete`. New daemon test `TestRunShutdownSequenceDrainsSlogHandler16083` proves delivery through the real shutdown path; logging cells cover healthy drain and wedged-counted shutdown.
- **Regression check**: New `pkg/logging/syslog_slog_async_16083_test.go` — a plain slog record against a stalled collector must return in <300ms (pre-fix it parks), a flood must overflow-drop and count, an oversize record drops at enqueue, and a healthy-collector record is delivered. Updated `syslog_reentrancy_test.go` cells for async delivery and the writer-scoped guard.
