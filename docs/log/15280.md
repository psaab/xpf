# Stamp health-confirmed STARTED cuts during superseded recovery (#15280)

- **Issue**: #15280 (D05-02) — the superseded-journal recovery stamped a
  stale cut only from the FLIPPED arm. A STARTED (health-confirmed) journal
  whose commit-stamp write failed, or whose process died before the stamp,
  left that version `committed:false` when a newer package's cut started
  fresh. `defaultRollbackTarget` from the newer version then picked the
  version two steps back.
- **Cause** (`pkg/upgrade/cutover.go`, resume-vs-fresh): the recovery's
  first arm required `atLeast(StateFlipped) && !atLeast(StateStarted)`, so
  a STARTED journal fell into the generic else arm, which handled only
  StateStopped specially and then reset the journal without ever calling
  `stampCommittedVersion`.
- **Change** (`pkg/upgrade/cutover.go`): add a dedicated superseded arm for
  `atLeast(StateStarted) && !atLeast(StateCommitted)`. Because
  StateStarted is only transitioned after StartUnit + HelperHealthy pass,
  the target is a verified-healthy stale cut: stamp it committed (with its
  journaled predecessor), GC, clear the journal, record the committed-cut
  evidence, and sweep partials — exactly as the FLIPPED success arm does.
  The arm fail-closes (preserving the journal for operator recovery) if
  `current` does not name the journaled target, so a non-live version is
  never minted into a committed rollback candidate. COMMITTED journals are
  unchanged (they still use the already-committed backfill), as are the
  FLIPPED, STOPPED, and pure-phase arms.
- **Regression coverage**
  (`pkg/upgrade/superseded_started_commit_15280_test.go`): seed a STARTED
  2.0.0 journal (flipped, in-flight stamp only) superseded by staged 3.0.0
  over a committed 1.0.0, then assert `stamp(2.0.0).Committed==true` with
  predecessor 1.0.0 and `defaultRollbackTarget("3.0.0")=="2.0.0"` after the
  superseding cut; plus fail-closed controls (stamp-write failure surfaces
  and preserves the journal; a non-live STARTED target refuses and is not
  stamped).
- **RED evidence**: on pristine `origin/master` (2b90ed2a1b), all three
  original tests failed — 2.0.0 stayed `committed:false`, the superseding
  run proceeded without stamping, and a failing stamp write was silently
  ignored.
- **GREEN evidence**: focused tests pass
  (`go test ./pkg/upgrade -run 'TestSuperseded.*15280|TestStaleHalfCut.*13543' -count=1`);
  the complete upgrade package passes (`go test ./pkg/upgrade -count=1`);
  `go vet ./pkg/upgrade` passes; `gofmt -l pkg/upgrade/` is clean.
