# #14400 — Routing-instance RIP/IS-IS key-without-type renders plaintext; #9105 gate checks only the global instance (DR10-H1)

## Defect
`validateAuthTypePresenceStrict` (`pkg/config/compiler_validate_strict_authtype_9105.go`,
the #9105 gate) walked only `cfg.Protocols.RIP` / `cfg.Protocols.ISIS`.
The identical `authentication-key` with no `authentication-type` under
`routing-instances <n> protocols rip|isis` (including the IS-IS
per-interface site) compiled clean on strict commit. `pkg/frr` renders
per-instance RIP/IS-IS through the same function
(`generateProtocolsWithQNH11447`, called per instance with a `vrf`
suffix), whose absent-type arm renders the key in plaintext
(`area-password clear` / `ip rip authentication mode text`) exactly as a
deliberately chosen `simple` does. On the lenient load path the same
configs also produced no #9105 warning, so the silent plaintext downgrade
survived both paths for every VRF.

## Fix
- `pkg/config/compiler_validate_strict_authtype_9105.go`: the three #9105
  sites are factored into a `checkProtocols(prefix, rip, isis)` closure
  applied first to the global block (`protocols ...`, scope strings
  unchanged) and then to every entry in `cfg.RoutingInstances` with scope
  `routing-instances <name> protocols ...` (the canonical spelling used
  by sibling gates such as `collectProtocolInterfaceRefs`). Strict still
  refuses with the remedy named; lenient still warns and appends to
  `cfg.Warnings` (#1960 — a persisted config must still boot).
  `authentication-type md5` and `simple` in a VRF still commit.
- No renderer change: the pkg/frr absent-type warnings already fire for
  per-instance renders; the missing half was the compile gate.

## Tests
