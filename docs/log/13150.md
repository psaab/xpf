# #13150 — keep tagged-only trunk parents unzoned

- **Source**: deep-review finding D3-04, validated by three-way adversarial research.
- **Files**: `pkg/dataplane/userspace/zones.go`,
  `pkg/dataplane/userspace/zones_host_inbound.go`,
  `pkg/dataplane/userspace/zones_host_inbound_ingress.go`,
  `pkg/dataplane/userspace/zones_host_inbound_trunk_fanup_13150_test.go`.

## Why

`InterfaceZoneMap` fans a tagged unit's zone up to a physical trunk's base
snapshot row. Host-inbound view generation treated that derived zone as an
authored claim, so it assigned kernel addresses on the untagged parent (including
link-local addresses) to the tagged zone. The untagged parent was also omitted
from the unzoned ingress barrier, leaving untagged trunk traffic without its
required host-inbound drop.

## What

Identify fan-up base rows using the existing zone-provenance helper and the
snapshot's Linux netdev ownership. If no untagged unit owns the same netdev, the
base row is treated as unzoned by both ingress and address builders, and is not
added to the tagged zone's view. Keep the existing unit-0 same-netdev behavior.
Add regression coverage for tagged-only trunk ingress/address attribution and
the unit-0 positive control.

owner change classification. Tagged unit enforcement and untagged unit-0
netdev/address ownership remain unchanged.
