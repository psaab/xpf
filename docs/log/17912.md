# Issue #17912: Omit quarantined host-inbound views

## Timestamp

2026-10-26T15:42:09Z

## Action

STEP-0 confirmed the host-inbound snapshot builder on origin/master did not omit snapshots tagged with an interface-quarantined zone; the new regression failed there with a published zulu view carrying ge-0/0/0 and 10.0.0.1. The builder now omits the default view when every authored identity in a zone is quarantined, ignores snapshot rows that retain a quarantined identity/zone label, and filters a collapsed physical-parent row when its same-netdev unit 0 is quarantined. Config-derived VRRP VIP and stable-RETH address walks also gate on the quarantined logical identity. Surviving identities, sibling-zone policy, and unrelated bare-only interfaces remain published.

## Risk

Only zones with no surviving interface identity because all authored identities are quarantined lose their host-inbound view. A quarantined unit-0 identity cannot republish its address through a collapsed physical-parent snapshot, even when that zone also has a surviving interface. Distinct bare-only interfaces and surviving sibling interfaces retain their views. No wire fields or classifier implementation changed.
