# #15215 — VLAN-child adoption provenance (A28-02, A28-03)

## Defects

**A28-02.** `vlanAdoptionRefusal` (`pkg/dataplane/vlan_provenance_6916.go`)
proved kind, namespace, VID and parent for a device already occupying
`<phys>.<vid>`, but never read `VlanProtocol`. An existing 802.1ad
(0x88a8) link at that name was adopted and brought up as the configured
802.1Q unit, while the create path builds `netlink.Vlan{VlanId: vid}`
(kernel default 802.1Q) and the parent XDP classifies 802.1Q only —
create and adopt disagreed, producing a wrong-protocol kernel child.

**A28-03.** `flexible-vlan-tagging` passes the #14574 tagging gate
(`ifaceTaggingEnabled` accepts either flag), but every writer keyed on
`VlanTagging` alone. Under flexible tagging alone the two-writer split
of #14574 survived: `buildInterfaceNetworkdModels` folded the tagged
unit's addresses onto the untagged parent (parent answers untagged for
the tagged unit's subnet, duplicate connected prefix),
`buildBridgeDomainModels`/`isConfiguredVLANSubInterface` never enslaved
the bridge-domain member, the bridge-domain validator rejected the
member, and `RethVIPsForRG` / `CollectRethInstances` / the strict VRRP
gates folded VIPs onto the parent instead of one instance per tagged
sub-interface. Commit was clean and silent.

## Fix

- **A28-02:** `vlanAdoptionRefusal` now refuses unless
  `VlanProtocol == VLAN_PROTOCOL_8021Q`, accepting
  `VLAN_PROTOCOL_UNKNOWN` (zero) only as the absent-attribute case
  (netlink leaves it zero when `IFLA_VLAN_PROTOCOL` is absent; the
  kernel default for a vlan device is 802.1Q). The refusal reason names
  the actual protocol (`802.1ad (0x88a8)`) and reaches the operator via
  the existing `errVLANAdoptRefused` → `UnarmedSurface` soft-skip path
  in `mapZoneInterface` — no new failure mode, the squatter never
  enters `genericXDPIfindexes`.
- **A28-03:** single helper `(*InterfaceConfig).TaggingEnabled()`
  (`VlanTagging || FlexibleVlanTagging`, nil-safe) in
  `pkg/config/types_interfaces.go`, used by every writer that keyed on
  `VlanTagging`: dataplane networkd model, bridge-domain models and
  `isConfiguredVLANSubInterface` (`pkg/dataplane/compiler_iface.go`),
  bridge-domain validator, `RethVIPsForRG`, strict VRRP VIP-count and
  cross-group gates (`pkg/config`), `CollectRethInstances`
  (`pkg/vrrp`), cluster probe resolution (`pkg/cluster`), management
  VRF VLAN unit set (`pkg/daemon`), and the `show interfaces` /
  `show vlans` renderers (`pkg/cli`, `pkg/grpcapi`).

Scope notes: flexible tagging's only admitted shape is single-tag —
an inner tag is rejected at commit by the #5879 QinQ gate
(`validateQinQVLANStackAST`), and `InnerVlanID` has no dataplane
consumer — so treating flexible as tagging for these writers creates
exactly the same `<parent>.<vid>` 802.1Q children as the create path
already does under flexible (pinned since #9761). NOT changed:
`resolveInterfaceRef` (already returns `unit.VlanID` with no tagging
test — correct once the gate guarantees tagging), the userspace
snapshot resolvers (key on `unit.VlanID > 0`, tagging-agnostic), and
the lenient-path behaviour of the #14574 gate.

## Risk

Adoption now refuses a pre-existing 802.1ad device at a configured
802.1Q child's name (previously silently adopted): the surface takes
the existing soft skip with an operator-visible `UnarmedSurface`
naming the protocol. Flexible-tagged interfaces now get tagged-writer
behaviour everywhere — the behaviour the #14574 gate already promised
at commit; untagged and plain vlan-tagging configs are unchanged.
