# #16491 — deferred conntrack-delete retry scanned the shared map per retry and panicked on poison

- **Timestamp**: 2026-10-24
- **Context**: `retry_deferred_conntrack_deletes` (worker housekeeping,
  up to 64 retries per pass) locked `shared_sessions` with
  `.expect("shared sessions poisoned")` — the sole non-test
  `shared_sessions.lock().expect` among 117 `lock_shared_recover`
  sites — and linearly scanned `.values()` for a bare-tuple match
  per retry. A poisoned mutex (an earlier contained worker panic,
  #2402 policy) therefore re-panicked this worker, and each retry
  held the cross-worker publish/miss/HA-import mutex for one O(N)
  scan of a large HA-synced population.
- **Fix**: pass `shared_owner_rg_indexes` into
  `retry_deferred_conntrack_deletes` (housekeeping already holds it)
  and replace the scan with an O(1) exact-scope lookup mirroring
  `close_delta_is_stale_incarnation`: acquire the primary map before
  its companion `bare_tuple_sessions` index via
  `lock_shared_recover` (poison recovered + counted, poison cleared),
  hold both guards together, consult `has_other_scope` and then
  `sessions.get(&delete.key)`. Semantics preserved: the kernel
  conntrack row is keyed by bare tuple alone, so a live shared
  session in ANY scope sharing the tuple fences the delete — an
  exact-scope hit by `session_id` (including the `session_id == 0`
  unknown-incarnation fence, now also applied to the synthetic
  other-scope hit, matching `close_delta_is_stale_incarnation`),
  and an other-scope hit unconditionally. NOT changed: retry budget
  (64), tuple-gate acquisition, local-table check, conntrack delete
  helper (whose per-incarnation kernel `session_id` re-check in
  `delete_bpf_conntrack_entry_for_session_under_gate` remains the
  final guard), and every other shared-map site.
- **File(s)**: `userspace-dp/src/afxdp/worker/loop_body/gc_teardown.rs`,
  `userspace-dp/src/afxdp/worker/loop_body/housekeeping.rs`,
  `userspace-dp/src/afxdp/worker/loop_body/tests.rs`,
  `docs/log/16491.md`, `debian/changelog`
- **Validation**: new `*_16491` cells in `loop_body/tests.rs`:
  `conntrack_retry_recovers_poison_and_other_scope_fences_16491`
  (poisons `shared_sessions`, seeds an other-scope replacement;
  pre-fix panics on `.expect`, post-fix recovers — counter bumped —
  and the other-scope row fences the delete, kernel row survives) and
  `conntrack_retry_exact_scope_replacement_still_fences_16491`
  (exact-scope replacement with a different `session_id` plus 2000
  unrelated shared rows/index entries; row survives). Existing
  `conntrack_delete_refusal_is_retained_and_revalidated_13671`
  updated for the new parameter. See PR for exact counts.
- **Residual**: component level only, matching the finding's evidence;
  no release-mode latency measurement of the large-map workload
  (the fix is structurally O(1) per retry — one hash lookup plus one
  index lookup — so the 200k/64 time is independent of N by
  construction).
