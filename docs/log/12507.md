# Issue #12507 — padded masks on the static-route and IPsec selector paths

- **Date**: 2026-10-13
- **Why**: #12122 stamped helper-refused padded masks for policy literals and
  address-book rows only (docs/log/12122.md). The userspace helper reads static
  route destinations and bind-less IPsec fence selectors with ipnet, which
  accepts at most two IPv4 and three IPv6 mask digits
  (`config.CIDRMaskHelperRefusesPadding`, #12178). On master the static-route
  and IPsec selector paths had two defects:
  - Padding the helper accepts (`10.0.0.0/08`, `2001:db8::/032`) compiled
    verbatim. The userspace FIB installed the route, but every netip-based
    consumer refused it. The FRR render belt (`validFRRRoutePrefix`) left it
    out of frr.conf, so the kernel lacked a route the userspace FIB had. The
    #9820/#11421 next-hop family gate and the #11380/#11422 selector models
    also skipped it.
  - Padding the helper refuses (`/008`, `/0032`) committed strict and was
    published verbatim. The helper failed the whole snapshot
    (`RouteDestinationUnparseable` / `InvalidBindlessSelector`), but neither
    the snapshot stamp (`PolicyContentRejected`) nor the mirror
    (`PolicyContentRejectionReasons`) reported it.
- **What**:
  - **Canonical spelling.** The compiler writes helper-supported padding
    canonically (`normalizeHelperSupportedCIDRMaskPadding`). For static-route
    destinations this runs after the masked-alias fold
    (`canonicalizeStaticRouteDestinationMasks`). For IPsec it applies to
    `traffic-selector local-ip/remote-ip` and to `local-identity` /
    `remote-identity`, which can act as selectors. If a route's prefix was
    also authored in a spelling the helper parses, that spelling becomes the
    destination. Authored spellings stay as diagnostic aliases.
  - **Strict and tolerant handling of refused padding.** Strict commit
    rejects helper-refused spellings: every static-route destination plus
    every alias folded into it (`staticRouteHelperRefusedMaskSpellings`), and
    every IPsec selector value (`trafficSelectorValueReject`). Tolerant loads
    warn once per spelling and keep the route or selector; it is never
    excluded.
  - **Userspace publication and stamps.** `buildRouteSnapshots` publishes a
    helper-refused static route after every runtime filter (gateway
    resolution, the ip-monitoring overlay, the live ip-rule mirror), so the
    helper's refusal depends on the config alone.
    `collectStaticRouteCIDRMaskRejections` and
    `collectBindlessSelectorCIDRMaskRejections` walk exactly the rows the
    builder publishes. They feed the mirror, the full-build stamp and the
    scheduler-republish stamp. `IsTrafficSelectorShape` still accepts a
    refused spelling, so the bind-less fence row is kept.
  - **Rust pins.** Two Rust tests pin the ipnet grammar the Go predicate
    mirrors, for route destinations and for fence selectors.
- **Disposition (issue acceptance)**: The issue asked for the #12122 parity
  treatment (stamp, mirror, regression) on these paths. That is delivered for
  every row that reaches the helper as a whole-snapshot input: published
  static routes and bind-less fence rows. Three cases are deliberately not
  stamped, because the helper never refuses a snapshot over them:
  - A route that `config.StaticRouteExclusions` drops is never published.
  - A route-based VPN's selectors never become fence rows. Its P-MECH
    inventory row degrades per tunnel; that is not a whole-snapshot refusal.
  - Helper-supported padding never reaches the helper; it is written
    canonically at compile.
- **R1 rework (PR #12671, Review12671Opus)**:
  - **B1, B2.** Rebased on master and adopted #12178's
    `CIDRMaskHelperRefusesPadding` contract. The PR's refuse-all-padding rule
    is gone.
  - **B3.** Stamps name only rows the helper receives and refuses. Helper-
    supported padding now produces no reason, so the policy simulator,
    `rollbackTargetAppliablePreflight` and the old-helper disarm are
    unchanged for it.
  - **B4.** Discard routes and fence rows are never excluded. A refused
    spelling fails the snapshot closed instead of forwarding via a
    less-specific route or leaving cleartext unfenced.
  - **B5.** The exclusion arm is gone. The next-table applier and the FIB see
    the same canonical destination and count the same window slots.
  - **F1.** Aliases are checked.
  - **F2.** A parseable spelling survives the fold.
  - **F3.** The dead FRR check is dropped. An FRR test now pins that the
    normalized route renders.
  - **F4.** One warning per spelling.
  - **F5.** The exclusion text is unchanged from master. The IPsec reason
    names the VPN, the fence side and the value. The FRR test name in the old
    log was wrong.

- **Risk**:
  - Strict commit now rejects static-route and IPsec spellings with more than
    two IPv4 or three IPv6 mask digits. A published route or bind-less
    selector with one already made the userspace helper refuse its snapshot
    on master. A route-based VPN selector with one was rendered verbatim to
    strongSwan, as it still is on a tolerant load.
  - FRR now installs helper-supported padded static routes that it used to
    skip, so the kernel gains them.
  - How strongSwan parses padded selectors was not measured. Helper-supported
    padding is now rendered canonically, and refused padding is still
    rendered verbatim, as on master.
  - `routing-options generate route` prefixes are not covered and remain the
    same class of gap (`routes.go` generate-route rows, FRR
    `renderGenerateRoutes`); follow-up recommended.
  - No live-cluster validation.
