# Issue #14372 — Plaintext `checkip-url` escapes the #4861 TLS gate

`ddnsPlaintextCredentialEndpoint` gated only `server` / `url-template`,
and only when the backend carried an update credential. `CheckIPURL`
was never checked, the commit warning accepted http(s), and the runtime
`validateCheckIPURL` accepted http. A Surface A `address-source checkip`
scope therefore trusted a spoofed plaintext checkip response as the
firewall's public address and published it as the DNS record (plus any
API key embedded in the URL leaked in cleartext per probe).

## Change

- `pkg/config/compiler_ddns_tls.go`: `checkip-url` is now checked FIRST
  and UNCONDITIONALLY in `ddnsPlaintextCredentialEndpoint` (same
  TrimSpace / bare-host pass / case-insensitive scheme logic); the
  credentialed-only early return now applies only to
  `server`/`url-template`.
- `pkg/config/compiler_system.go`: strict hard-rejects / lenient warns as
  before, but the `checkip-url` finding gets its own message (a plaintext
  checkip response is trusted as this firewall's public address) and the
  value is OMITTED, not RedactURL'd — RedactURL preserves a bracketed
  IP-literal host, which can carry the key (mirrors #6545 discipline).
- `pkg/config/compiler_validate_warn_ddns.go`: mirror
  `ddnsCheckIPURLValid` now requires https, staying in sync with the
  runtime validator; warning text updated to "valid https URL".
- `pkg/ddns/checkip.go`: `validateCheckIPURL` requires https
  ("url must be https") — the runtime backstop for lenient-loaded /
  peer-synced / hand-built providers. `CheckIP` refuses before any fetch,
  so Surface A publishes nothing (transient miss, never a withdraw).
- Tests-only TLS migration: every `CheckIP`-against-plaintext fixture
  (`TestCheckIPThroughMockServer`, source-bind, body-read, no-address,
  daemon observer/warn tests) moved to `httptest.NewTLSServer` (or an
  https URL for fake transports); update-backend http tests untouched.
  `SetCheckIPRootCAsForTesting` (pkg/ddns) lets daemon tests trust the
  test CA through the real cached client. Pre-existing warning-layer
  tests that fed non-https checkip-urls through strict `CompileConfig`
  now compile lenient (the strict gate owns scheme refusals; the warn
  pass still owns malformed shapes) — assertions preserved.

## Regression

- `TestDDNSPlaintextCheckIPURLRejected` (fixture F-DR3-H5-1): strict
  commit with `checkip-url http://checkip.example/` fails naming
  checkip-url + https — credentialed + Surface A binding, non-credentialed
  (proves no credential gate), and upper-case HTTP cells.
- `TestDDNSHTTPSCheckIPURLAccepted`: https / upper-case https / bare host
  compile. `TestDDNSPlaintextCheckIPURLLenientWarns`: lenient compiles +
  warns naming checkip-url.
- `TestCheckIPRejectsPlaintextURL` (F-DR3-H5-2): `CheckIP` on http
  (incl. credentialed and upper-case) returns zero/false/error naming
  https, leaks no key, and never contacts the transport; the TLS
  positive cell (`TestCheckIPThroughMockServer`) still returns the IP.
- `TestCheckIPPlaintextPublishesNothing` (F-DR3-H5-3): a Surface A scope
  over an http checkip-url whose server answers an attacker IP yields no
  observation, never contacts the server, and warns once.

## Validation

- RED sensitivity: with the production gate files reverted (tests kept),
  the new config/ddns/daemon fixtures fail — the strict gate accepted the
  plaintext checkip-url (message asserted the old credential text) and
  the runtime accepted http. Restored, all pass.
- GREEN: `go test ./pkg/config/ ./pkg/ddns/` full packages pass;
  daemon checkip tests (`TestCheckIP*`, `TestSurfaceAObserverCheckIP*`) pass.

## Risk

- Operators with an existing plaintext `checkip-url` must move it to
  https: strict commit now rejects it (lenient load warns and the
  runtime probe publishes nothing until fixed). Bare-host checkip-urls
  are unaffected (composed over https, as before). Backend update
  endpoints (`server`/`url-template`) keep their exact #4861 behaviour.
