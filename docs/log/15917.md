# Issue #15917 — cluster-terminal attribution falls back to global prefix scans without table scope/LPM

Retro hostile triple-review finding O-F4 (opus lane,
`/var/worktrees/retro-review/opus.md`, pinned at f1fb921984;
triangulated by the codex/glm lanes under the #15742 umbrella).
Distinct corrective dimension within #15742, filed separately

## Defect

`select_source_ifindex_v4/v6` (`userspace-dp/src/afxdp/
forwarding/fib.rs`) stamps a cluster-terminal resolution's
would-be egress (`source_ifindex`) for HA demotion and the #15906
punt-seed consumers. Three of its connected-prefix reads were
global first-match scans of `connected_v4_by_ifindex` /
`connected_v6_by_ifindex` (`FastMap<i32, Vec<Prefix>>`):

1. the destination fallback (`.iter().find(...)` over the map),
2. the gateway-owner fallback (first interface whose prefixes
   contain the route's gateway),
3. (the transit `connected_v*` read was already table-scoped).

The maps carry bare prefixes with no table, populated for every
admitted interface including peer-owned rows (#15742e keeps them
there deliberately). With overlapping connected prefixes in two
VRFs — or a broad and a narrow prefix in one table — the winner
was FastMap hash order: attribution could name an interface in
another tenant. The HA gate (`cluster_terminal_peer_owned_egress_rg`)
then judged the wrong RG (restoring `DiscardRoute` for a
peer-owned WAN), and the seed consumers in `poll_descriptor`
(`source_ifindex` → egress zone / owner RG) read the wrong
zone/owner. No cross-VRF packet delivery or policy bypass is
claimed; the impact is avoidable drops and misattributed punt
authorization. The normal connected lookup directly below the
added code already filters `entry.table == table` — the fallback
was the outlier.

## Fix (PR #15926)

- `connected_lpm_ifindex_v4/v6`: iterate the by-ifindex prefixes,
  keep only interfaces whose routing instance owns the lookup
  table, pick the longest containing prefix. Table ownership is
  derived from `ifindex_to_routing_instance` (absent = default
  instance) via the allocation-free `instance_owns_table_*`
  twins of `connected_route_tables` — the same #2388 source of
  truth `populate_interfaces` used to scope the transit rows.
- Equal-length ties pick the lowest ifindex (triple-review fold;
  the #10645 local-delivery `.min()` precedent), so the result
  never depends on hash or insertion order.
- Both the destination candidate and the gateway-owner fallback
  route through the helper; the table-scoped transit candidate
  keeps priority (#15742e ordering preserved). Returns 0 on no
  in-table match — fail-closed, the terminal stays a plain drop.
- No `ForwardingState` type/schema change; the other by-ifindex
  consumers (ingress-keyed neighbor learning, local-delivery)
  are already ifindex-scoped. Terminal/miss path only.
