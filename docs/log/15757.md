# #15757 — bare-destination copy/rename skips BareDestinationParent in authz gate and rename lineage

- **Timestamp**: 2026-10-19
- **Action**: Fixed the narrowed G2-01 live form. `configMutationPaths` (`pkg/config/authz_config_mutation_9154.go`) adjudicated a bare copy/rename destination as `editPath+dst` (e.g. `user root`, or `system user root` under `[edit system]`) while `CopyPath`/`RenamePath` place it under the source parent via `BareDestinationParent` (#15237) — so an anchored `deny-configuration ^system login user root` missed the real destination (fail-open) and anchored allows false-denied. Added `ResolveBareCopyRenameDestination` (schema-segmented, identity for non-bare/unsegmentable) and `ConfigTree.ResolvedRenameDestination` (tree `Keys` length wins when the source node exists) in `pkg/config/ast_edit.go`; the gate now adjudicates the resolved destination, and `Store.RenameAsPlantClass` (`pkg/configstore/store_command.go`) records the resolved destination (computed from the pre-mutation clone) instead of the raw bare `dstPath`, so daemon session-rematch lineage (`policyRulePathKey`/`zoneRenamePath`) recognises renamed policies/zones. All surfaces share the one gate (`AuthorizeConfigMutation`: local CLI, gRPC, REST) and the one store method, so no per-surface wiring was needed. Unaffected legs kept: full destinations adjudicated/recorded verbatim, unsegmentable sources unchanged.
  - **File(s)**: `pkg/config/ast_edit.go`, `pkg/config/authz_config_mutation_9154.go`, `pkg/configstore/store_command.go`, `pkg/config/bare_destination_authz_15757_test.go`, `pkg/configstore/bare_destination_lineage_15757_test.go`, `docs/log/15757.md`
- **Validation**: RED pre-fix — `TestBareDestinationCopyRenameAuthzAndRenameLineage` failed at the first bare-copy deny cell (`AuthorizeConfigMutation(..., "copy system login user operator to user root")` returned nil). Regression named per the report: `TestBareDestinationCopyRenameAuthzAndRenameLineage` in `pkg/config` (copy+rename × nil/`[edit system]` cursors, policy-shaped bare dst, anchored-allow leg, non-denied/full-dst controls, resolver units) plus store half `TestBareDestinationRenameLineage15757` in `pkg/configstore` (bare policy + bare zone lineage resolved, full-dst control). Neighbouring suites: `pkg/config`, `pkg/configstore`, `pkg/cli`, `pkg/grpcapi`, `pkg/api` (run by main agent on the final head).
- **Risk**: Fail direction is closed on both halves: gate now denies exactly what the executor creates, and lineage now names the node that exists (worst case on a resolver miss is the pre-fix teardown fallback, never a wrong rematch). Schema-segmentation fallback returns the typed destination unchanged, preserving executor arity/lookup errors for unsegmentable sources.
