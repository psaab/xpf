# #14673 — Scan/sweep eviction sampled a deterministic `FxHashSet` prefix

## Defect

`ScanCore::evict_stalest_in_zone` sampled
`per_zone_srcs[zone].iter().take(EVICT_SCAN_LIMIT)` (64) on every
eviction. `per_zone_srcs` is an unseeded `FxHashSet`, so that prefix is
the same deterministic 64 buckets on every call — computable by an
off-box attacker who knows the inserted addresses. An attacker who
pinned 63 prefix entries at count 9 (`SCAN_DETECT_COUNT - 1`) and kept
its scanner at count 8 inside the prefix made the scanner the
deterministic lowest-count victim; one fresh decoy admission wiped its
history and the next probe re-seeded it at count 1, so the scanner
never reached the detection count of 10. Forwarding was never
fail-open; this is a detection fail-open only.

## Fix

The eviction sample now walks the dense `key_ring` (which mirrors
`per_src` exactly, maintained by the single `insert_src`/`remove_src`
primitives) from a persistent `evict_cursor`, instead of iterating the
per-zone `FxHashSet`:

- `evict_cursor` rotates the window: each eviction examines at most
  `EVICT_SCAN_LIMIT` (64) same-zone candidates and advances the cursor
  past the examined span, so successive evictions cover the whole zone
  instead of a fixed prefix (#6239 cursor pattern).
- The start is seeded per boot: `ScanCore::seed` is drawn once from
  `hot_hash_seed::hot_path_hash_seed()` (the #2364 pattern already used
  by `SynRateSketch`, `PMechSessionDirectory`, and the shared session
  index), and the walk starts at `(evict_cursor + seed_offset) %
  ring_len`, where `seed_offset` is a splitmix-style diffusion of the
  secret reduced mod the ring length. `evict_cursor` is stored in the
  unseeded frame (the next start is translated back by `seed_offset`),
  so successive starts advance contiguously by the examined span rather
  than jumping by `seed_offset` each time — coverage does not depend on
  `gcd(seed_offset + span, ring_len)`. Tests pin the seed via
  `ScanCore::with_seed`, mirroring `SynRateSketch::build_seeded`.
- Other-zone slots do not consume the 64 same-zone budget; the total
  walk is capped at `EVICT_SCAN_LIMIT + 8 * EVICT_SCAN_LIMIT` (576)
  ring slots, so adversarial zone interleave cannot turn eviction into
  an O(ring) scan; the best victim found so far is still used. At real
  saturation (`zone_count >= MAX_SOURCES_PER_ZONE`) same-zone entries
  are dense in the ring, so the ring window finds a victim. If the
  window finds no same-zone candidate at all (the target zone is
  sparse in a huge ring — the #4890 test shape, 3 target entries among
  100k, which calls eviction directly below the cap), a fallback takes
  a rotating seeded sample of the zone's own `per_zone_srcs` index
  (at most `EVICT_SCAN_LIMIT` same-zone entries, skip bounded by the
  per-zone cap, never by the total table size). This is what keeps the
  existing #4890 regression (`fresh_scanner_admitted_when_zone_entries_
  outside_global_prefix_4890`) green without any O(ring) walk.
- Victim selection is unchanged (#4418/#2234): expired-or-empty first,
  then fewest distinct destinations, stalest `window_start` on ties.
  `per_zone_srcs` otherwise serves only the O(1) zone-cap count.
  `evict_examined_log` (test-only, like the existing cleanup
  `examined_log`) records the sample so tests can prove rotation.
Seven new `scan_tests` cells, all suffixed `_14673`:

- `pinned_prefix_scanner_not_self_evicted_14673` — the issue's scene
  recreated exactly: the first 64 `FxHashSet`-iteration entries pinned
  (63 at count 9, scanner at 8), 136 count-1 entries outside. The
  scanner must survive the decoy-triggered eviction and trip on its
  10th distinct port. RED on the pre-fix static prefix (the scanner is
  the lowest-count prefix entry and is evicted).
- `eviction_sample_rotates_across_calls_14673` — three successive
  samples are pairwise different and each is <= 64.
  RED pre-fix (identical static prefix every call).
- `eviction_eventually_covers_all_entries_14673` — repeated evictions
  with refill eventually examine every ring entry.
- `eviction_bounded_under_other_zone_interleave_14673` — 2000
  other-zone entries plus 3 target entries; the walk terminates with
  <= 64 same-zone examinations.
- `eviction_start_depends_on_seed_14673` — different pinned seeds
  reshuffle the first sampled key.
- `eviction_rotating_still_prefers_expired_14673` — an expired/empty
  entry inside the rotating window is reclaimed first (control).
- `scanner_detected_through_decoy_evictions_at_cap_14673` — end-to-end
  through `PortScanTracker::check` at the real 4096 cap: scanner
  batches of 8 probes interleaved with fresh decoys reach detection.
