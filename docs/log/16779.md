# #16779 — deleting `system no-redirects` restored constant 1 above the router default

- **Timestamp**: 2026-10-25
  - **Action**: `reconcileNoRedirects(false)` after a set-then-delete
    wrote `1` to every `ipv4/conf/{all,default,*}/accept_redirects`
    (the #15710 restore). With `ip_forward=1` already set and never
    rewritten, the kernel router default for
    `IPV4_DEVCONF_ALL(ACCEPT_REDIRECTS)` is `!forwarding = 0`
    (`inet_forward_change`), so the delete left the host accepting
    spoofed on-link ICMPv4 Redirects for its own traffic (DNS, NTP,
    syslog, flow export, BGP/IKE) and clobbered foreign sysctl.d
    hardening. Now the inactive→active transition captures the
    per-path values of every enumerated redirect knob and the
    active→inactive transition restores them verbatim, with ipv4
    `accept_redirects` additionally capped at `!ip_forward` (a
    captured `1` is restored as `0` while forwarding stays on).
    Knobs with no captured value (interfaces created while the
    posture was active) fall back to the forwarding-dependent
    default for ipv4 `accept_redirects` and `1` otherwise. Updated
    `TestNoRedirectsDeleteRestoresKernel15710` to assert the
    captured/capped values instead of the constant 1, and added
    `TestR3A36NoRedirectsRestoreVsRouterDefault` (acceptance:
    `all` returns to 0 under `ip_forward=1`; captured 0 stays 0;
    captured 1 restores to 1 when `ip_forward=0`) plus
    `TestNoRedirectsRestorePreservesForeignHardening16779`
    (per-path foreign 0s survive the set-then-delete cycle).
  - **File(s)**: `pkg/daemon/no_redirects_13982.go`,
    `pkg/daemon/no_redirects_13982_test.go`, `docs/log/16779.md`
