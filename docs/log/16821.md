# #16821 — stepBackup resign arm leaked the pending-resign stash

- **Timestamp**: 2026-10-25
  - **Action**: `ResignRG` on an already-BACKUP instance queued the
    resign token and stashed priority 0 (`resignPending`), but the
    `stepBackup` resign arm only called `notifyResigned` — it never
    actuated or cleared the stash. The instance therefore kept its
    pre-resign priority in `getPriority` (contrary to the `ResignRG`
    contract that a resigned instance keeps 0 until restored), and a
    later MASTER tenure ending in an unrelated step-down ran
    `becomeBackup` → `applyPendingResign`, silently installing the
    stale 0 long after the resignation was resolved. Fixed by
    calling `applyPendingResign()` in the `stepBackup` resign arm
    (the VIPs are already off the wire, so installing 0 is safe)
    before `notifyResigned`. Additionally, a superseding priority
    assignment now drops the stash via the new
    `discardPendingResign()`: `Manager.UpdateRGPriority` and
    `vrrpInstance.updateConfigHeld` clear `resignPending` after
    installing the restored/configured priority, so a restore racing
    the run loop cannot be overwritten by the later token consumption
    or a later step-down. Also corrected the `ResignRG` / README
    claim that `masterDownInterval` uses the stashed 0 while pending:
    `getPriority` deliberately hides the stash from routine adverts,
    so the skew uses the pre-resign priority while pending and follows
    `cfg.Priority` (0) once the stash is applied. Added
    `backup_resign_pending_16821_test.go`: the subject (resign while
    BACKUP) asserts `pending=false` and priority 0 immediately after
    the BACKUP resign and 200 after restore + a later unrelated
    step-down; a no-resign control stays 200 throughout; restore via
    `UpdateRGPriority` and via `updateConfig` while pending both drop
    the stash; the MASTER resign path (A25-06) still ends at 0. RED
    on revert: removing `applyPendingResign()` from the stepBackup
    arm restores `pending=true / priority 200` after the BACKUP resign
    and 0 after the later step-down.
