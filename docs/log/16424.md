# #16424 — second CoS container under one root silently dropped (R3-F05-02)

## Defect

`compileClassOfService` (`pkg/config/compiler_class_of_service.go`) read only
the first `classifiers`, `rewrite-rules`, and `forwarding-classes` container
under a `class-of-service` root via `FindChild`, and
`parseCoSInterfaceUnitBody` did the same for the per-interface /
interface-level `classifiers` and `rewrite-rules` containers. #15006 added
find-or-create for same-named instances, so a second top-level root merged,
but a second container under one root was never visited at all: BA
classifiers, rewrite code points, and forwarding classes from it were lost
with no diagnostic while `show | display set` still listed them. Reachable
through hierarchical files, `load merge`, and `load override`; the flat-set
spelling merged (union semantics). This is a QoS marking/queueing loss, not
an enforcement one.

## Fix

Iterate `FindChildren` at the five sites instead of `FindChild`:

- Top level: every `forwarding-classes` container shares the FC↔queue
  bijection indexes (seeded once from earlier roots), so cross-container
  conflicts reject exactly as cross-root conflicts do; every `classifiers`
  and `rewrite-rules` container feeds the existing #15006 find-or-create
  loops, so different names accumulate and same-named instances merge.
- Per-interface: every `classifiers` / `rewrite-rules` container in
  `parseCoSInterfaceUnitBody` is flattened (existing #8939 chain handling)
  and assigned in author order — last-write-wins per scalar binding, as a
  single merged container does.

Compiler-layer iteration was chosen over `mergeDuplicateBlocks9023` rows
(the issue's alternative) for the same reason as #15006: the compiler must
merge across multiple roots anyway, and the sibling containers in the same
function already set that precedent.

## Regression (`pkg/config/cos_container_dup_16424_test.go`)

Nine tests: duplicate-containers-equals-merged for DSCP classifiers,
rewrite rules (all four kinds), and forwarding classes; same-name merge
across containers for classifiers and rewrites; all-kinds classifier
coverage (dscp/ieee-802.1/inet-precedence, with name-slice dedup); the
bijection conflict across containers still rejects (queue→two FCs and
FC→two queues); per-interface unit and interface-level second containers
bind. All nine fail on origin/master with the second container dropped and
pass after the fix.

## Validation

- `go test ./pkg/config/ -run '16424' -count=1` — pass post-fix; all nine
  fail pre-fix (fix stashed) with the second container dropped.
- `go test ./pkg/config/ -run '15006|TestDuplicateCoS|TestDistinctCoS|TestCoSEmpty' -count=1` —
  pass. `TestDuplicateBlockConservationIsPinned8436` and
  `TestCompileGolden4406` fail identically with the fix stashed on the same
  HEAD (unprobed-container census drift; golden tcp-mss/vlan drift) —
  base-attributed, not this change.
- `gofmt` clean; `go vet ./pkg/config/` clean.

## Risk

Strict commits that previously (silently) kept only the first container
now compile the union — the Junos/flat-set semantics. A config that relied
on the drop to shadow a later container changes meaning, deliberately:
that shadowing was the defect. One new rejection becomes reachable: an
FC↔queue bijection conflict split across two containers now rejects
instead of the second container being ignored; within-container and
cross-root conflicts already rejected identically. No other new rejection;
malformed code points still reject/warn exactly as before.
