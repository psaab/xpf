# #14389 - AST redactor `key` gate misses non-adjacent `key` (hierarchical MD5 key leak)

- **Timestamp**: 2026-10-16
- **Action**: Widen the `key` case in `secretIndices` (`pkg/config/ast_redact.go`) from an exact-position window (`md5` at `i-2`, `authentication` at `i-3`, only the single next token) to an ancestry gate: mask every token after `key` when a consecutive (`authentication`, `md5`) pair appears strictly before it (new `keyHasOSPFMD5Ancestor` helper). The hierarchical spelling `md5 1 2 { key SECRET; }` flattens to `[..., authentication, md5, 1, 2, key, SECRET]`, so the old window missed it while the compiler still installs key-id 1 and FRR renders `ip ospf message-digest-key 1 md5 SECRET`. Masking all trailing tokens also closes the nested `md5 1 key { key SECRET; }` value leak the old single-token mask left behind. All `secretIndices` consumers (RedactedClone, FormatCompareRedacted fingerprints, placeholder-ingest guard, control-char and schema-diagnostic redactors) inherit the widened gate symmetrically. GRE tunnel `key`, NTP `key`, api-auth named `key` and chassis device-map `key` contain no such pair and stay visible.
- **Validation**: New `pkg/config/ast_redact_md5_nonadjacent_14389_test.go`: hierarchical fixture asserted absent from `RedactedClone().Format()`, `FormatSet()` and `FormatCompareRedacted(...)` (with a liveness premise — strict `CompileConfig` yields `AuthType=md5`, `AuthKeyID=1`, `AuthKey=SECRET` — so the fixture cannot pass on dormant text); controls for canonical `md5 1 key`, nested `md5 1 key { key ... }`, set-form dormant `md5 1 2 key`, GRE/NTP/api-auth non-secret keys, source-tree non-mutation, and placeholder-ingest rejection. RED on master (secret verbatim on all surfaces, nested value leaked), GREEN post-fix. New `pkg/frr/ospf_md5_nonadjacent_14389_test.go` proves the same spelling renders live via `ip ospf message-digest-key 1 md5 SECRET`. Affected suites: `go test ./pkg/config/ ./pkg/frr/ ./pkg/configstore/`.
- **Risk**: Display/ingest-guard only — cleartext compile, HA sync, persistence and FRR rendering are untouched. Over-masking is bounded to paths containing a literal consecutive `authentication md5` pair before a `key` leaf; the only modelled such path is the OSPF MD5 key.
