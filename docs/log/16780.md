# #16780 — #14686 pipe-boundary "saved" arm overturns a full-form deny that matches only pipe/format text

- **Timestamp**: 2026-10-25
  - **Action**: Reproduced RED on origin/master (aa051bfd25) with the
    new probe cells: `allow ^show` / `deny display set` over
    `show configuration | display set`, `allow ^show` / `deny \| match`
    over `show route | match 10.`, `allow ^show configuration` / deny
    `show configuration security \| display set`, a subtree spelling,
    and `^show log 100$` / `display set` all ALLOWED through both
    `CompiledLoginRegexes.EvaluateFormsWithPipe` and the real CLI gate
    (`evaluateCommandRegex`), although `Evaluate(full)` denies each
    and docs/system-login.md promises the pipe is matched as typed.
    Mechanism: the #14686 full-form "saved" arm (and its siblings in
    the truncated-veto and post-veto affirm arms) rescued the tier
    denial whenever a pipe-less form affirmed the core allow, without
    checking that the vetoing deny ever matched the command core —
    `denyingCoreTier` is false exactly for pipe-text denies, which
    left the save unconditional for them.
  - **Fix**: `pkg/config/login_regex.go` gained `pipeOnlyDeny` (the
    deny hits the full piped form, never its pipe-less core, and the
    core itself is allowed — distinguishing a real pipe-text deny
    from the `^show log 100$` exception, whose core allow-misses,
    and from the public-vrf shape, whose deny hits the truncated
    core). All three pipe-boundary saves now refuse pipe-only
    denials, the post-veto pipe arm returns a pipe-only tier denial
    immediately, and the inner public-vrf exception additionally
    requires a deny hit on the truncated core. A companion
    core-denied exception affirm restores `show log 100 | match x`
    (its full form is allowlist-denied on the $-anchored core, a
    path the veto loop never reached). `docs/system-login.md`
    records the converse rule beside the #14686 paragraph.
  - **Tests**: `pkg/config/login_regex_16780_test.go`
    (`TestEvaluateFormsWithPipePipeOnlyDenyNotSaved16780`, 10 cells)
    and `pkg/cli/permissions_regex_16780_test.go`
    (`TestPipedPipeOnlyDenyNotSaved16780`, 10 cells through
    `evaluateCommandRegex`, incl. the split-suffix and subtree
    spellings). Existing #14686/#9022/#9628 cells (`^show log 100$`
    through a pipe, public-vrf, anchored core denies) stay green.
    Note: `TestMultiPipeDispatch*14714` fails identically on clean
    master (pre-existing #14714 dispatch defect, untouched here).
