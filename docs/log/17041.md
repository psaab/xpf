# #17041 — GC pre-check peeks earliest expiry, GC write is try-only

- **Timestamp**: 2026-10-27
  - **Action**: Fixed `gc_expired_chunked` returning early only when `lease_expirations` was empty, so one non-expired idle lease made every non-persistent fast-path allocation take the blocking live WRITE lock. The pre-check now peeks `lease_expirations.first()` (BTreeSet ordered by expiry) under the already-taken read guard and returns 0 unless the earliest expiry is `<= now_ns`. The chunk write acquisition is now `try_write` (poisoned guard still used, mirroring `lock_live()`), skipping the sweep on `WouldBlock` and returning any already-reclaimed count; only successful `try_write` acquisitions bump the #4800 `live_lock_acquisitions` counter and the test-only GC-acquisition seam. Added three hermetic cells in `nat/tests_newflow_lock.rs`: a counter cell (one non-expired idle lease, 100 fast-path allocations add 0 `debug_gc_lock_acquisitions`), a parameterised held-READ cell over {empty index, one non-expired idle lease} asserting 0 GC write acquisitions behind the reader plus PAT-owner visibility, and a correctness cell (contended GC behind a held reader returns 0 promptly; the expired lease is still reclaimed once uncontended).
  - **File(s)**: `userspace-dp/src/nat/allocator/mod.rs`, `userspace-dp/src/nat/tests_newflow_lock.rs`, `docs/log/17041.md`.
  - **Validation**: Named hermetic cargo tests only (userspace-dp unit tests, `-- --exact`): `nat::tests_newflow_lock::idle_lease_gc_takes_no_write_lock_over_fast_path_allocs_17041`, `nat::tests_newflow_lock::new_flow_allocation_completes_under_held_live_read_15956`, `nat::tests_newflow_lock::expired_lease_still_reclaimed_and_contended_gc_skips_17041` pass with the fix. RED-on-revert: with the fix reverted (`git checkout -- mod.rs`, tests kept), the counter cell fails (`left: 100, right: 0`) and the contended-GC cell hangs behind the held reader in the blocking `lock_live()` (killed after the run deadline; process gone afterwards) — both are the defect. Existing GC chunking cells `pool_snat_gc_chunked_releases_lock_between_batches` / `pool_snat_gc_chunked_spares_active_and_unexpired_leases` and the #17024 fallback cell included in the same named run. No broad/network-reachable suite run on the workstation.
  - **Risk**: GC is opportunistic; a contended `try_write` now defers an expired-lease sweep to the next admission/release instead of blocking for it, which the pre-existing comment already promised. The guard-held `gc_expired_locked` pressure path is unchanged, so near-capacity reclamation is not weakened. Production #4800 acquisition counts drop by the previously-forced GC writes, which is the intended correction (also deflates the R4-Q11-04 inflation).
