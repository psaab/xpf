### Mechanism (code at `b57a950e21`)
1. **The skip is unbounded.**
   - When a Close cannot take its tuple install permits,
     `purge_queued_flows_for_closed_deltas` (`session_delta.rs:249`) returns
     the handled prefix.
   - `drain_and_flush_all_impl` then requeues the suffix and sets
     `deferred_delta_cleanup`.
   - `run_session_housekeeping` returns `true`, and `worker_loop`
     `continue`s (`loop_body/mod.rs:1272`) before `poll_binding`.
   - The heartbeat was already stored (`mod.rs:1236`). A worker whose
     permit never comes back therefore polls no RX and still looks healthy.
   - The loop-bottom counters (`WorkLoops`/`IdleLoops`, `mod.rs:1745/1749`)
     and the kernel `XDP_STATISTICS` publish (`mod.rs:1675`) freeze instead
     of rising.
2. **A second, in-call spin.**
   - `flush_session_deltas` (`session_delta.rs:676`) takes the close permits
     again and requeues on failure.
   - `drain_and_flush_all_impl`'s `while has_pending_deltas()` then re-drains
     the same Close inside one housekeeping call.
   - That spin gets neither RX nor a heartbeat until the permit frees.

### Fix
- **Bounded barrier.** `ClosePermitBarrier` bounds the RX hold at
  `CLOSE_PERMIT_BARRIER_NS`, which is 1 ms, the same as
  `INTERRUPT_POLL_TIMEOUT_MS`.
  - Inside the bound the tick still skips RX. This keeps the #10419
    teardown-before-poll order for ordinary contention.
  - Past the bound, the Close keeps first claim on every tick and the tick
    then polls RX.
  - The bound re-arms per blocked episode.
- **Drain-loop yield.** `drain_and_flush_all_impl` yields when a
  drain+flush pass leaves the queue no shorter.
- **Owner attribution (approved (b)).**
  - An episode that outlives the bound logs one line:
    `xpf-dp: wN: #19026 session close waiting …`.
  - The line names the tuple and a `TupleGate::probe()` of both close keys:
    state, publishers, installs, shard fill, and admission/clear flags. That
    gives the holder class.
  - It is rate-limited process-wide to one line per 10 s, using the #1760
    CAS throttle and a suppressed count.
  - The end of a logged episode is logged too.
- **Not changed.** Head-of-line order is unchanged: deltas behind a stuck
  Close still wait for it. That is a bounded ordering cost, not an RX
  outage.

### Deviations from the plan comment, and why
- **Closer choice.**
  - The plan: the minting worker if it is live and accepted, else the lowest
    accepting queue.
  - Implemented: always the lowest accepting queue. The activation path
    (`ha/state.rs::handle_activated_rgs` → prewarm) carries no node id. That
    id lives only on the bring-up `ConfigSnapshot`. R2(b) needs exactly one
    closer, not a particular one.
- **Fenced teardown.**
  - The plan: "release only its own persistent hold", as for a #16223
    replica.
  - Implemented: the fenced reap still releases the copy's own per-worker
    resources:
    - this worker's source-NAT and NAT64 holder bit, with the hold;
    - its steering-row claims;
    - its flow-cache slots.
  - It skips only the session-id-gated conntrack mirror delete.
  - Why: a restored `SharedPromote` copy reserved its own holder bit at
    restore (#15966r, `reserving_origin` includes `SharedPromote`).
    `handle_delete_synced` releases nothing for a key whose row is already
    gone (`delete_synced.rs`, the `delete_alias == None` arm). Skipping the
    release would leak one holder bit per non-serving worker per bounce. The
    holder-set semantics keep the serving worker's port.
- **Export tombstone.** A silenced copy is removed with
  `RemovalKind::Transfer`. A `Terminal` removal would harvest an export
  tombstone, and an open export window would then announce a close to the
  peer for a live session.
- **PPTP.** A fenced TCP/1723 copy no longer forgets the PPTP control channel
  that the serving copy still carries.

### Size pin

`b57a950e21` is 648 since #18742. The new bool fits existing padding.
Verified at compile time on the workstation with a temporary
`const _: () = assert!(size_of::<SessionEntry>() == 648)`. The positive
control (`== 647`) failed as expected, and the probe was removed. The bit is

### Fixture faults found and fixed (instrument, not product)
- **Idle horizon.** The concurrency cells first expected the idle close
  inside window + 40 s and saw 0 closes. A wheel-stats diagnostic showed why.
  At the first expiry pass, the reverse replica's #16223/#18722 node-evidence
  arm sees the shared row's counters for the first time, counts that as a
  change, and re-stamps BOTH halves once (`align_node_kept_companion`). The
  idle close therefore lands at about 2 windows plus the hold. The horizon is
  now 3 windows + 40 s.
- **Window read from worker 0.** The R14 F3 single-prewarm control read its
  window from worker 0, which held no copy. `timeout_secs_for` returned 0,
  the horizon collapsed to 40 s, and the cell saw 0 closes at BOTH heads. A
  control that reads the same at both heads proves nothing. `window_ns` now
  takes the max over workers and asserts a copy exists.
- **Restamp phase.** The ct-slice restamp phase in the serve helpers is now
  fixture-relative, `(now - t0) % 10 s`, not absolute monotonic seconds. That
  makes the F1 move-back timing deterministic.
