# #16544: wildcard-address mask uses inverted (Cisco) polarity

- **Timestamp**: 2026-10-24
- **Problem**: `expandWildcardAddress` treated mask bits set to 1 as
  "don't care" (Cisco wildcard polarity): `care = ^mask`,
  `network = ip & care`. Junos uses the opposite polarity — a 1 bit is
  compared, a 0 bit is ignored. Every genuine Junos mask was therefore
  either refused at strict commit as "non-contiguous" (e.g.
  `255.255.255.0`, `255.255.0.255`) or, where the inverted complement
  happened to be canonical, compiled to a different address set: the
  exact-host wildcard `A/255.255.255.255` became `0.0.0.0/0` (IPv6:
  `::/0`, a permit-any/deny-any), and the Cisco spelling
  `10.1.2.3/0.0.0.255` became `10.1.2.0/24`.
- **Fix**: `expandWildcardAddress` now masks with the mask itself
  (`network = ip & mask`, prefix length from `net.IPMask(mask).Size()`),
  so a contiguous Junos mask yields `network/ones`. A non-contiguous
  mask — including any Cisco-polarity spelling and the Juniper
  documentation example `192.168.0.11/255.255.0.255` — has no single
  CIDR equivalent and is refused via the existing `UnimplementedForms`
  path (strict reject, tolerant match-none), never silently widened or
  narrowed. IPv6 follows the same defined polarity as an xpf extension
  (all-ones → `/128`). Family-mismatched ip/mask pairs and extra `/`
  segments are now explicitly refused instead of falling through to a
  16-byte interpretation. Dead helpers were left untouched (they are
  pre-existing and unused by this path; no other caller changed).
- **File(s)**: `pkg/config/address_forms_15673.go`,
  `pkg/config/address_forms_15673_test.go`,
  `pkg/config/wildcard_polarity_16544_test.go`,
  `pkg/dataplane/userspace/wildcard_polarity_16544_test.go`,
  `pkg/config/README.md`, `docs/log/16544.md`
- **Validation**: `TestWildcardAddressExpands15673` flipped to Junos
  polarity (7 compiled cases incl. `10.1.2.3/255.255.255.0` →
  `10.1.2.0/24`, `.../255.255.255.255` → `10.1.2.3/32`, v6 `/128` and
  `/64`; flat form; direct-expander refusals for `0.0.0.255`,
  `255.255.0.255`, the doc example, and a trailing-segment spec).
  `TestSoleAddressFormsRejectedAtCommit15673` now pins the Junos
  non-contiguous masks. New `TestWildcardPolarityAcceptance16544`
  (issue acceptance + membership + family/malformed refusals) and
  `TestWildcardPolarityUserspace16544` (`expandBookNameToCIDRs` shows
  `10.1.2.3/32`, `2001:db8::1/128`, `10.1.2.0/24`; Cisco spelling
  strict-refused and lenient match-none) pass. Broader
  `Address|AddressBook` runs in both packages fail byte-identically to
  clean `origin/master` (pre-existing failures only). `go vet` and
  `gofmt` clean.
- **Risk**: Configs authored in Cisco polarity that previously committed
  as the inverted set now fail strict commit (fail-closed, intended);
  recovery is rewriting the mask in Junos polarity or as a prefix.
  Contiguous Junos masks that previously could not commit now commit
  with their documented meaning.
