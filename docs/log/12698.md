# #12698 — Refuse unsafe build metadata before Go linking

## Why

The Makefile builds xpfd with `-ldflags "-X main.version=$(VERSION) ..."`.
Because these variables use `?=`, an environment-provided value containing
whitespace becomes additional linker arguments. In particular,
`VERSION='1.2.3 -X main.version=pwned'` changes the binary's reported version;
additional `-X` values can also set any linker-visible string variable. The
build must refuse these inputs before running `go build`.

## What

- The Makefile validates caller-provided `VERSION`, `COMMIT`, and `BUILD_TIME`
  as environment data before any target recipe runs; command-line overrides
  are conditionally exported to that validator. Raw values are never
  interpolated into validator shell source. VERSION permits the
  git-describe/semver-safe character set; COMMIT permits `unknown` or 7–40
  lowercase hex characters; BUILD_TIME must be a valid UTC RFC3339 timestamp
  (`YYYY-MM-DDTHH:MM:SSZ`). Defaults derived by Make are not exported, so the
  existing `make deb` dirty-version handoff remains intact.
- Added `test_build_metadata_12698.py` for valid values and hostile whitespace,
  quote, newline, malformed commit, and malformed timestamp inputs, including
  proof that Make/shell syntax in a value is not executed. The existing
  provenance and dirty-marker fixtures copy the validator into their
  temporary checkouts because they invoke the real Makefile.
- Rust helper settings, `GO`, and `CARGO` overrides are outside this issue's
  reported `-X` injection path and were not changed.

## RED → GREEN

- **RED:** On the unmodified Makefile,
  `VERSION='1.2.3 -X main.injected=pwned' make -n build` expanded to
  `-ldflags "-X main.version=1.2.3 -X main.injected=pwned ..."`. A real build
  with that input completed and printed the attacker-controlled first word as
  the version, demonstrating that environment metadata reached xpfd.
- **GREEN:** The regression suite requires every hostile value to fail during
  Makefile parsing and requires no `go build` recipe in output. A valid real
  build printed exactly `xpfd v1.2.3-rc.1+build.4 (commit deadbee, built
  2026-10-13T17:46:34Z)`. A hostile real build exited nonzero and did not
  create its requested output binary.
