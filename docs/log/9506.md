## The guard

`closed_owner_8276_9506_test.go` runs a census over `git ls-files`. #8276 may appear
only in the two provenance files, and the four owner sites must name #9506. Tracker
state cannot be read offline, so it pins this measured instance and does not police

the ownership history lives here instead, so the census needed no loophole for

Controls built into it:
- **Positive control**: both historical sites must be FOUND. A census that reads
  nothing cannot report zero violations.
- **Fixture cell**: drives the check function itself (stale claim flagged;
  allowlisted history counted; docs/log, a non-covered extension, a longer issue
  number and the file itself ignored). This makes a disabled check killable even
  when the repository is clean.
- **Read floor**: fewer than 1000 covered files read is a failure, not a pass.

#### M3 mechanism diagnosis

- The harness uses one isolated netns, brings `lo` up, binds one UDP4
  receiver at `127.0.0.1:39506`, and diverts only UDP packets for that port
  from an inet `OUTPUT` chain (`pkg/nfqueue/harness_test.go:69-116`).
  Source release deletes the table and verifies that the ruleset is empty
  (`pkg/nfqueue/harness_test.go:118-134`), so a stale rule is not the cause.
- The same receiver/address/netns path is a positive control: the smoke test
  receives a held packet, ACCEPTs it, and observes delivery before any source
  release (`pkg/nfqueue/nfqueue_test.go:53-82`). The M3 test also observes its
  post-release follow-up through the same socket (`pkg/nfqueue/measure_teardown_test.go:56-63`).
- Only the source-release ordering changes for the held packet. M3 then issues
  ACCEPT, checks one successful and zero uncertain submissions, and observes a
  one-second UDP deadline with no held payload (`pkg/nfqueue/measure_teardown_test.go:64-79`).
- Therefore this is a transport/mechanism finding, not a socket/addr/netns
  harness failure. The Phase-0 transport has no small safe userspace repair for
  source teardown; the mechanism phase must define admission cutoff, queue
  replacement/quiescence, and live XFRM/SA-source teardown semantics. The
  test pins the observed negative result instead of weakening it.

### Transport hardening and residuals

- `Queue` binds AF_INET/AF_INET6 and an explicit queue number, copies full
  payloads, sets queue maxlen 8,192, and never enables `FAIL_OPEN`.
  `VerdictBatch` prevalidates nil/cross-queue/already-verdicted/duplicate
  packets before reservation. Tests kill a duplicate-reservation regression
  and verify attempted/successful/uncertain verdict counters and terminal
  behavior after a send error.
- Queue counters are submission telemetry, not kernel delivery ACKs:
  `VerdictAttempted`, `VerdictSuccessful`, and `VerdictUncertain` distinguish
  wire-attempted, successful-send, and ambiguous suffix outcomes. No ACK
  protocol was invented for Phase 0.
- M1–M4 are measurement-only. No generation/epoch fence, owner allocator,
  SA/tunnel-source teardown, route re-resolution, VRF/conntrack isolation,
  re-entry mark contract, atomic create/install/delete, or production
  xfrm/AF_XDP wiring was added. Those are explicit follow-up requirements
