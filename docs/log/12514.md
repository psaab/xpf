# #12514 — preserve authored secure-tunnel unit for IPv6 next-hop inference

- **Issue**: #12514 — `inferIPv6StaticNextHopInterfaces` collapsed `st<N>.0` to `st<N>` although an explicit secure-tunnel bind creates `st<N>.0`.
- **Branch**: `fix/12514-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12514`
- **Base**: `4a17e0d29` (`ra: clamp PIO lifetimes at the send sink (#12193)`).

## Why

The IPv6 inference helper generated its connected-prefix interface name with `LogicalUnitDeviceKey`, whose intended unit-zero behavior collapses `st0.0` to `st0`. In the reported configuration, `SecureTunnelUnitNetdev("st0.0")` returned `st0.0`, but inference returned `st0`; `DeclaredNetdevsForConfig` cannot repair that bare inference result because its shared resolver deliberately declines bare `st0`. The resulting VRF route therefore named the nonexistent netdev.

## What

- Prefix inference now consults `Config.SecureTunnelUnitNetdev` for each configured authored unit reference and uses the resolver result when owned by IPsec. Unbound secure-tunnel and ordinary refs retain the existing `LogicalUnitDeviceKey` behavior.
- Replaced the temporary probe with `TestIPv6StaticNextHopSecureTunnelUnitRendersAuthoredNetdev12514`, which checks the inferred name, declared-netdev map, and installed managed FRR route line for the reported bind/next-hop/VRF shape.
- Added unit-zero fallback controls for an ordinary interface and an unbound secure-tunnel unit.

## Validation

### RED before the fix

- `go test ./pkg/daemon/ -run TestProbe12514Collapse -count=1 -v` passed as a diagnostic probe and logged inference as `vrf-blue: 2001:db8:12::2 -> st0`, while `SecureTunnelUnitNetdev("st0.0")` returned `("st0.0", true)`. `ApplyFull` rendered `ipv6 route 2001:db8:99::/64 2001:db8:12::2 st0 vrf vrf-blue` rather than the authored device. This is the pre-fix defect captured by the probe; the probe was then replaced by asserting regression coverage.
- The regression test asserts `st0.0` at both inference and FRR output, so reverting the resolver override restores the captured `st0` mismatch and fails the test.

- The focused tests for `TestIPv6StaticNextHopSecureTunnelUnitRendersAuthoredNetdev12514` and `TestIPv6StaticNextHopInferenceUnitNameFallbackControls12514` passed.

## Risk

The change only selects the shared secure-tunnel resolver result for the connected prefix's interface name; all other refs continue through the established logical-unit resolver. No live cluster or kernel state was changed.
