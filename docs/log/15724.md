# #15724 — ShowInterfacesDetail and local `show interfaces [<name>]` looked up DHCP leases by raw Junos physical name instead of `cfg.DHCPLeaseKey(physName, li.unitNum)`

- **Timestamp**: 2026-10-19
- **Verification (pre-fix)**: `pkg/grpcapi/server_show_interfaces.go:432,444`
  called `s.dhcp.LeaseFor(physName, dhcp.AFInet/AFInet6)` and the CLI twin
  `pkg/cli/cli_show_interfaces.go:459,470` called `c.dhcpLease(physName, ...)`
  which in `pkg/cli/cli_show_interfaces_shared.go:16-21` forwarded the raw
  name to `LeaseFor`. The daemon keys leases by
  `cfg.DHCPLeaseKey(physName, unitNum)` (`pkg/config/types.go:513`:
  `LinuxIfName(configRef)` + `"."+VlanID` when > 0) — the REST handler
  (`pkg/api/interfaces.go:290`) already used it. So slash-named Junos
  interfaces (`ge-0/0/0`, kernel `ge-0-0-0`) never matched, and a
  VLAN-tagged unit (unit 100 / vlan-id 100, key `ge-0-0-0.100`) missed
  against a lookup for `ge-0/0/0`.
- **Fix**:
  - `pkg/grpcapi/server_show_interfaces.go`: both DHCPv4 and DHCPv6 lease
    lookups now resolve `cfg.DHCPLeaseKey(physName, li.unitNum)` (skipping
    the lookup when the unit does not resolve) before `LeaseFor`.
  - `pkg/cli/cli_show_interfaces.go`: both call sites pass
    `cfg, physName, li.unitNum` to the shared helper.
  - `pkg/cli/cli_show_interfaces_shared.go`: `dhcpLease` now takes
    `(cfg, physName, unitNum, af)` and resolves through
    `cfg.DHCPLeaseKey` before `LeaseFor`; its only callers were the two
    sites above (verified by grep), so the signature change is contained.
  - Out of scope (not the claimed mechanism): `cli_show_interfaces_detail.go`
    / extensive renderers do not print DHCP leases at all, and the gRPC
    extensive/terse paths likewise have no lease lookup — unchanged.
- **Regression**:
  - `pkg/grpcapi/server_show_interfaces_dhcp_lease_key_15724_test.go`:
    `TestShowInterfacesDetail_DHCPLeaseKey` — the issue's acceptance shape
    (unit 100 / vlan-id 100, lease seeded at the `DHCPLeaseKey`), adapted
    to this package's fixtures: `setupTestServer`/`loadAndCommitSet` do
    not exist here (replaced by `newConfigStore` + `LoadSet`/`Commit`),
    and the renderer prints "Not present" and skips logical units for a
    non-reth interface with no kernel netdev, so the VLAN unit is carried
    on bondless `reth0` over member `lo` (the guaranteed netdev, as in
    `TestWriteInterfacesDetail_DHCPLeasePath`); daemon key `reth0.100`.
    Extended to DHCPv6 with a decoy lease under the raw pre-fix key.
    Verified RED with the fix reverse-applied (prints the decoy
    `203.0.113.99/24` / `2001:db8:dead::99/64`), GREEN after.
  - `pkg/cli/cli_show_interfaces_dhcp_lease_key_15724_test.go`:
    `TestShowInterfacesDHCPLeaseKey15724` — CLI twin driving the real
    dash-named host interface (Junos slash form) through
    `c.showInterfaces([]string{junos})`; covers the slash-name key
    (`<kernel>.100`, e.g. `ge-0-0-0.100`). Also verified RED on revert
    (decoy printed), GREEN after.
- **Validation**: `go vet` clean on `pkg/cli` and `pkg/grpcapi`; both new
  tests pass; neighbouring show-interfaces suites (13244/4328/4984/5068/
  9841/5913/12898/14364 + `TestWriteInterfacesDetail_DHCPLeasePath`) and
  `pkg/config` lease-key tests pass. `gofmt -l` clean on touched files.
- **Risk**: display-only. Interfaces whose lease previously displayed by
  accident (plain `.0` sharing the physical key when the raw name happened
  to equal the daemon key, e.g. `reth0` unit 0) still resolve identically
  via `DHCPLeaseKey`; slash/VLAN forms now resolve correctly instead of
  silently omitting the lease. No dataplane, daemon, or config change.
