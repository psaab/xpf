# #12068 — collision-free inline route-filter prefix-list names

- **Timestamp**: 2026-10-08 (stacked on #12066)
- **Action**: replace the lossy `<policy>-<term>` inline route-filter prefix-list name with a bounded, deterministic name derived from the structured rendering identity, and reject reserved-namespace intrusion at the existing apply gate.

## Red before

A focused regression run against the pre-change renderer showed the reported aliases: operator list `IMP-CUST` and inline `(IMP, CUST)` shared a name; `(A, B-C)` and `(A-B, C)` shared `A-B-C`; and mixed-family `P-T_v4` collided with a separate term named `T_v4`. The reserved-name gate also accepted an operator prefix-list in the proposed generated namespace.

## Change

- Added `inlinePrefixListName`, which hashes a length-prefixed tuple of route-map name, policy prefix, term name, and family suffix. Its readable policy-term fragment is sanitized and bounded so the final name is at most 96 bytes; a reserved `-xpf-inline-` marker and 64-bit SHA-256 digest make the name deterministic and separate from unreserved operator names.
- Updated homogeneous and split-family inline definition/reference rendering to use the same helper. The existing `routeFilterACLNameCollision` gate rejects operator prefix-lists that intrude on the inline namespace. (An identity-enumeration half was removed in review: unfireable except on a 2^-64 collision, untestable, covering 2 of 5 render contexts. Opus R2, PR #12321.)
- Added renderer regressions for operator-name overlap, non-injective hyphen joins, mixed-family suffix overlap, maximum name length/determinism (incl. plPrefix inequality), reserved-namespace rejection (direct + ApplyFull-level), and update the footprint record. Updated existing output assertions to derive expected names through the helper.
