# #16055 — PPTP association resolve domain vs re-keyed claimed tenant domain (RN-06)

- **Timestamp**: 2026-10-23
- **Action**: The PPTP data-channel resolve in the descriptor loop now
  derives its routing domain from the same claimed fabric identity
  stage 9b re-keys the flow to. New helper
  `pptp_resolve_routing_domain`
  (`afxdp/poll_descriptor/mod.rs`): on a fabric arrival it resolves
  via `ingress_zone_override.or(ambiguous_zone)` (previously only the
  validated override, falling through to the fabric link's own
  ifindex domain); a fabric arrival with no claimed zone fails
  closed to domain 0 instead of the fabric link's domain; the
  absent-stamp suspect arm stays domain 0; non-fabric arrivals keep
  the physical-ingress derivation. Associations are installed in the
  control flow's stage-9b domain, so resolve and install now agree
  by construction. NOT changed: the association table, handle
  derivation, control-channel learning, or stage 9b itself.
- **File(s)**: `userspace-dp/src/afxdp/poll_descriptor/mod.rs`,
  `userspace-dp/src/afxdp/poll_descriptor/pptp_domain_16055_tests.rs`,
  `debian/changelog`, `docs/log/16055.md`
- **Test report**: Decisive cell
  `pptp_same_call_id_across_domains_refreshes_only_claimed_domain_16055`:
  the same endpoint pair + call IDs installed in the claimed
  (quarantine-band) domain and in domain 0; a fabric-arrival PPTP
  packet resolves to the claimed domain's handle, keys there, and
  idle-refreshes only that association (the wrong-domain row expires
  on schedule). A control cell resolves in the pre-fix domain and
  claims the wrong tenant, proving the fixture distinguishes the
  defect. Helper cells pin the ambiguous/validated/non-fabric/
  no-claim/suspect derivations. Mutation: reverting the helper's
  fabric arm to the pre-fix expression reds the claimed-domain and
  refresh cells. Broader `pptp` filter: 99 passed, 1 pre-existing
  failure (`pptp_open_frame_carries_the_call_id_pair_13965`, fails
  identically on unmodified master).
- **Perf**: One extra `Option` coalesce on the already-gated PPTP
  resolve (flowless GRE + ALG-enabled packets only); the domain
  computation itself is the same `ingress_routing_domain` call.
  No allocation. No iperf gate.
