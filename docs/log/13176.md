# #13176 - preserve full session identity in policy invalidation debt

- **Timestamp**: 2026-10-15
- **Action**: Policy invalidation capture merging, rollback re-authorization, and partial-delete pruning distinguish IPv4/IPv6 rows by 5-tuple, routing domain, RT_FLOW session ID, and tunnel discriminator. If the exact-delete API returns a bare key shared by different captured session identities, pruning retains every ambiguous identity as pending debt rather than guessing which one was deleted.

The tests passed after the initial fix. The short-GOTMPDIR serial run eliminated the socket/listener failures.
- **Risk**: When distinct session identities share a key, a bare exact-delete result cannot identify which incarnation succeeded, so all colliding entries remain queued for safe retry; this favors fail-closed invalidation over prematurely retiring debt.
