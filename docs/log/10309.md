# 10309 — expiry Close deltas survive ring pressure

- **Timestamp**: 2026-09-13
- **Problem**: one timer-wheel expiry pass could remove more than the 4096-slot session delta ring. The extra Close deltas were counted as ring loss and never reached shared-session teardown, sibling DeleteSynced replication, reverse-NAT deletion, HA session-sync, or SESSION_CLOSE RT_FLOW emission.
- **Change**: expiry Close construction now uses a loss-neutral bounded-ring admission. When the ring is full, the exact Close is attached to the returned `ExpiredSession`; the worker drains the pre-existing ring first and flushes returned overflow Close records in fixed-size chunks before processing another packet. Ordinary Open/Close producers retain the existing #2442 loss-of-sync behavior.
- **Files**: `userspace-dp/src/session/entry.rs`, `userspace-dp/src/session/expire.rs`, `userspace-dp/src/session/mod.rs`, `userspace-dp/src/session/tests.rs`, `userspace-dp/src/afxdp/worker/loop_body/mod.rs`, `userspace-dp/src/afxdp/session_glue/tests.rs`.
