# Issue 10196 verification

## Change

WireGuard outer UDP sockets now derive a VRF device from the effective transport table (`<instance>.inet.0` / `<instance>.inet6.0`) and apply `SO_BINDTODEVICE` before wildcard bind. Default `inet.0` and `inet6.0` remain unbound. Explicit tunnel scope, routing-instance list membership, and a shared interface-level WG unit-only scope all feed the effective table. Conflicting VRF claims for one WG device are rejected on strict compile and quarantined on tolerant load. Forwarding instances remain refused because they do not create a VRF device.

The Go/Rust config-snapshot protocol moved from v25 to v26 because the existing `transport_table` field changed meaning. Exact-version gates refuse an older helper before it can install a scoped WG endpoint.

## Known limitation

The resolver for authored DNS peer endpoints still calls `ToSocketAddrs` without a per-device or per-VRF resolver context. A name private to a tenant VRF can therefore fail to resolve and retain its last-known endpoint; the WG socket itself remains correctly bound, but DNS resolution is VRF-blind and needs a separate resolver follow-up.
