# #18649 — Warn on growing stale-config refusals

- **Timestamp**: 2026-11-07
  - **Why**: A current-config node can refuse peer session installs under an older config epoch while only emitting Debug logs; sustained growth of `SessionsStaleConfigIgnored` then lacks an operator-visible signal.
  - **What**: Added one shared, per-`SessionSync` one-minute warning limiter for IPv4/IPv6 refusals. It emits only when the counter grows and `TransferReadinessSnapshot.ConfigStale()` is false, and names the decoded epoch/tag bit, exact comparison threshold and source, comparison branch, and RG0-authority status. The counter and per-refusal Debug log remain unchanged. Updated the config-epoch README section.
  - **Validation**:
    - Testguard focused config-epoch/stale cells (`go test ./pkg/cluster -run 'ConfigEpoch|StaleConfig' -count=1 -json`): 18 test cases passed.
    - Fail-on-revert: with Warn wiring removed from both refusal sites, the four install-path warning tests failed for missing warnings; the no-growth limiter cell remained passing. Restored wiring: all five #18649 cells passed.
    - Testguard full `pkg/cluster` suite at base `dbe02a6129`: exit 1, 11 failure events. Post-change suite: exit 1, 11 failure events; ten failure names were identical. The base-only reordered-config timeout was `TestLegacyConfigReceiveReorderedGenerationsApplyNewest10511`; the post-change-only timeout was `TestAncestryReorderedGenerationsDropStalePair10511`. Both report that the newer config never entered the apply callback, and both tests passed in a separate focused testguard run. **[INFERENCE]** The swapped timeout name is an existing timing-sensitive apply-loop failure, not evidence of a regression in the stale-session refusal path; it is recorded as an attribution gap rather than claimed identical.
    - The ten identical baseline/post-change failure names were `TestPersistOwedIsSetOnlyByFAULTS_6724/write_fails_(read-only_directory)`, `TestPersistOwedIsSetOnlyByFAULTS_6724`, `TestSenderLoopDrivesTheRetry_6724`, `TestRetryPersistsWhatTheFailedPassCouldNot_6724`, `TestRefineRecoveryNeedsTheRaisingEpochInTheFile_6669/a_failed_write_strands_the_peer_across_every_restart`, `TestRefineRecoveryNeedsTheRaisingEpochInTheFile_6669`, `TestEqualEpochSuccessorIsAdmitted_6669/successor_of_an_unwritable_store_is_admitted`, `TestEqualEpochSuccessorIsAdmitted_6669`, `TestEqualEpochBoundStillStrandsTheNextSuccessor_6669`, and `TestIPMonitorPrimaryDualStackDemotes16425`.
  - **Risk**: Warning-only behavior; config-epoch refusal/admission and counting are unchanged. Limiter state is serialized by the existing `applyMu` shared by v4 and v6 installs.
