# #18649 — Warn on growing stale-config refusals

- **Timestamp**: 2026-11-07
  - **Why**: A current-config node can refuse peer session installs under an older config epoch while only emitting Debug logs; sustained growth of `SessionsStaleConfigIgnored` then lacks an operator-visible signal.
  - **What**: Added one shared, per-`SessionSync` one-minute warning limiter for IPv4/IPv6 direct refusals and post-write rollback refusals. It detects counter growth (not a rate derivative) while `TransferReadinessSnapshot.ConfigStale()` is false, so sustained growth warns once per minute. Each warning names the decoded epoch/tag bit, exact comparison threshold and source, comparison branch, and RG0-authority status. The latest counter is recorded while config is stale, avoiding a delayed warning for old growth. Warning records are prepared under `applyMu` and emitted after it is released, using the existing `SessionSync.nowMonoFn` clock seam. The counter and per-refusal Debug log remain unchanged. Updated the config-epoch README section.
  - **Validation**:

Restored both hooks; all 19 focused cases passed.
