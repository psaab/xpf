# #17118: derive Clone for PolicyRule, document shared hit counter

- **Timestamp**: 2026-10-27
- **Action**: Implemented the named fix. STEP-0: defect was live on
  current `origin/master` (`789af9147b`): `userspace-dp/src/policy.rs:514`
  was `#[derive(Debug)]` only, and `:617-652` carried a 36-line hand
  `impl Clone for PolicyRule` that cloned every field exactly as a derive
  would, including `hit_counter: self.hit_counter.clone()` (`:649`, an
  `Arc` clone that shares the counter).
- **Change**:
  - `userspace-dp/src/policy.rs`: `#[derive(Debug)]` →
    `#[derive(Clone, Debug)]` on `PolicyRule`; deleted the hand
    `impl Clone for PolicyRule` (36 lines). Added a field doc on
    `hit_counter`: clones share the counter (#3322 carry-forward), so a
    cloned rule keeps counting into the same `Arc<PolicyRuleCounter>` and
    an in-flight session bound to the handle keeps attributing hits to
    the admitting rule across snapshot rebuilds. This replaces the
    misleading "special semantics here" signal of the hand impl — whose
    original purpose (snapshotting a non-Clone `AtomicU64` into an
    independent counter, `324d6b9d1b`) is gone and whose current body
    silently encodes the opposite (shared) semantics.
  - `userspace-dp/src/policy_tests.rs`: added
    `policy_rule_clone_shares_hit_counter_17118` asserting
    `Arc::ptr_eq(&rule.hit_counter, &rule.clone().hit_counter)` and that
    an increment through the clone is visible through the original
    (1 packet / 64 bytes).
- **Acceptance**: `rg -c 'impl Clone for PolicyRule' userspace-dp/src`
  now yields 0 matches (verified: `grep -rE 'impl Clone for PolicyRule'
  userspace-dp/src | wc -l` → 0).
- **Validation**: Named hermetic cell only:
  `cargo test -p xpf-userspace-dp --bin xpf-userspace-dp policy::tests::policy_rule_clone_shares_hit_counter_17118 -- --exact`
  — 1 passed, 0 failed, 9785 filtered out. Compilation of the derive
  itself proves every field (including the private `compiled_apps`) is
  `Clone`. No broad suite run.
- **Risk**: None behavioural — the derived clone is field-for-field
  identical to the deleted hand impl (which was compile-checked to name
  every field, so no field could drift). Clone sharing semantics for
  `hit_counter` are unchanged and now pinned by the new test plus the
  field doc.
