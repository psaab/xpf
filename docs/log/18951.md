# Issue #18951 — per-arm tail for the shared unknown-family diagnostic

- **Issue:** `unknownFamilyMsg17196` (`pkg/config/family_members.go`) ended every arm's diagnostic with `— the configuration under it compiles to NOTHING: it commits clean, renders in `show configuration`, and takes no effect at all (#17196)`. On the STRICT arm that tail is untruthful: the caller returns the message as an error and the commit is refused — nothing commits and nothing renders. The wording is only accurate on the lenient arm, where the member is warned about and skipped and the committed config silently lacks it (compiles to nothing). Present since the shared builder landed (#17196, c4e12aafc3); the #18881 residue diagnostic (unmerged PR #18949) rides the same builder and inherited the same defect.
- **Evidence:** GLM seat on PR #18949 (delta review at 381f016ea3) probed the strict error for a bogus family token — the refusal text claimed "it commits clean" while rejecting.

## What

1. **One builder, per-arm tail** (`family_members.go`): `unknownFamilyMsg17196` gained a `lenient bool` parameter selecting the tail. Strict: `— the commit is refused (#17196)`. Lenient: the compiles-to-NOTHING wording, unchanged. The shared head (`%s %q is not a known address family (known: %s)`) is built once; no copied strings, no second builder.
2. **Callers** (enumerated — all three, each already holding the flag it branches on immediately after): `compiler_interfaces.go` (`interfaces %s unit %d family`), `compiler_services.go` ×2 (`forwarding-options family`, `forwarding-options sampling instance %q family`). Each passes `opts.lenientFamilyMembers17196`; one argument line per site, no other caller change.
3. **Cells re-pinned.** Census first: five cells pinned the message HEAD (`"is not a known address family"`, all `strings.Contains`) — `family_members_17196_test.go` helper `hasUnknownFamilyWarning17196` (lenient arms of all three tops) plus the strict cells of `TestFamilyMembersEmptyKeysNoPanic17196`, `TestFamilyMembersBogusSmuggleRejected17196`, `TestFamilyMembersInterfaceResidueFixture17196`, and `compiler_interfaces_malformed_af_7522_test.go` (`TestChildShapedFamilyStillCompiles7522`, lenient). **No cell pinned the tail** — the wording was untested on both arms (test-only-green gap; the unrelated `compiles to NOTHING` pins in `firewall_family_unknown_9883_test.go`/`dhcp_relay_active_server_group_16580_test.go` quote the #9017 firewall and #16580 builders, not this one). Each cell now ALSO pins its arm's tail via the literal constants `strictTail18951` / `lenientTail18951` (literals, not builder references, so a mutant cannot satisfy them tautologically). Nothing weakened: head pins kept, tails added.
4. **#18881 residue cell:** not on master (PR #18949 unmerged) — skipped per plan. When the parent rebases #18949 first, #18949's call site gains the new `lenient` argument (one line) and the residue diagnostic inherits the truthful per-arm tails for free.
