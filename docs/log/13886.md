# #13886 — pin in-flight duplicate refusal at the sync handler

## Change

The #13708 regression test exercises `SessionDomain::helper_mutation_begin`
directly. It did not cover the handler's production mapping from its
`operation-in-flight` refusal to `ControlResponse`. Add a handler-level test in
`userspace-dp/src/server/handlers/sync_session.rs` that holds an uncompleted
lease, submits an epoch-scoped `mirror_clear_chunk` request with the same
triple, and asserts `ok=false`, the exact refusal token, and that the clear did
not execute (`session_mirror_complete` remains false).

## Validation

  `response.ok = true`; the new test failed at `in-flight duplicate must not
  report success`.
- Restored the production mapping; the complete `sync_session::tests` module
  passed (3 passed, 8,148 filtered).
- `helper_mutation_begin_refuses_concurrent_duplicate_13708` passed (1 passed,
  8,150 filtered).

## Risk

Test-only change. No production behavior changed.
