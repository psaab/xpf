# #9873 — the lexical st<N> fallback resolved a configured tagged unit as a physical netdev, so its parent MTU was never planned

- **Timestamp**: 2026-09-14
  - **Action**: guarded the unbound `IsSecureTunnelIfName` arm in
    `resolveInterfaceRef` with `stUnitCarriesVlanID9873` — after the
    `SecureTunnelUnitNetdev` miss, a configured unit carrying a nonzero
    vlan-id falls through to ordinary resolution instead of returning the
    dotted ref with vlan 0.
  - **File(s)**: `pkg/dataplane/compiler_iface.go`,
    `pkg/dataplane/compiler_iface_st_tagged_fallback_9873_test.go` (new),
    `pkg/dataplane/compiler_iface_tagged_parent_mtu_9761_test.go` (st10 matrix
    row, 5120 -> 5760 shapes)

  - **STEP-0, measured on base**: with `st10 mtu 1400, vlan-tagging,
    unit 5 vlan-id 100 + mtu 1300` and zone ref `st10.5`,
    `resolveInterfaceRef` returned `phys="st10.5" vlan=0` via the lexical arm
    (`compiler_iface.go:109-113`), skipping the vlan-id read at `:130-137`;
    `planPhysDesired` then emitted `plan["st10.5"]={mtu:1300}` with no
    `plan["st10"]` — the vlanID==0 untagged path
    (`compiler_iface_desired.go:125`) instead of the `:100` tagged branch.
    Post-fix the same config resolves `(st10, st10, u5, v100)` and plans
    `mtu 1400` on `st10` with no `st10.5` entry.

  - **The guard is deliberately narrower than the issue's "base configured ->
    fall through"**: two existing pins force it.
    `TestResolveInterfaceRefReadsTheAuthoredBindInterface_6729` ("no VPN binds
    the ref", configured st0, no vlan-id) pins the verbatim `st0.0`,
    "Unchanged on purpose"; `TestResolveInterfaceRefXFRMUnit` (configured st0
    unit 1, no vlan-id) pins `st0.1` / vlan 0. Falling through for every
    configured base would flip both to the base netdev and contradict the
    mirrored-`ResolveKernelIfName` verbatim doctrine the #6691 test keeps
    deliberately. So only the configured-vlan-id shape falls through; an
    unconfigured base, a missing unit, an untagged unit, and a non-numeric
    suffix all keep the verbatim ref byte-identically, and the bound arm is
    untouched (#6691 order, pinned at the `resolveInterfaceRef` level by the
    new bound cell: owned `st5.3` with vlan-id 80 still resolves to `st5.3`).
