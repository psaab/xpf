# Issue #16787: Deleting `speed`/`duplex` or setting `duplex auto` never undoes the link mode xpf forced with `ethtool -s` (R3-A37-01)

## Why

`set interfaces ge-0/0/3 speed 100m duplex half` compiles to
`ethtool -s ge-0-0-3 speed 100 duplex half` — persistent NIC state. The
recovery commit (`delete ... speed; set ... duplex auto`, or deleting
both leaves) compiled to nothing: `applyEthtool`
(`pkg/dataplane/compiler.go`) returned early when both `parseSpeed` and
`parseDuplex` yielded `""`, which is exactly what unset/`auto` produce.
The `.link` file was rewritten with `AutoNegotiation=yes`, but `.link`
files are consumed only by udev at device add and `networkd` reload /
reconfigure does not apply link modes, so the NIC stayed forced (link
down or duplex mismatch) until reboot, driver reload, or a manual
`ethtool -s ... autoneg on` — while the commit reported success.
`ethtoolApplied` is per-`CompileResult`, so no memory of the earlier
forced write survived into the recovery compile.

## What

- `pkg/dataplane/compiler.go`: a process-lifetime registry
  (`ethtoolForcedLive`, mutex-guarded) records each netdev xpf has
  *successfully* forced via `ethtool -s … speed/duplex …`
  (`markEthtoolForced` on the success branch only). In `applyEthtool`,
  when the committed config has no explicit speed/duplex, a netdev in
  that registry now gets `ethtool -s <if> autoneg on` once; on success
  the mark is cleared (`forgetEthtoolForced`), on failure it is kept so
  the next auto-shaped compile retries. A netdev never forced gets no
  write. Explicit speed/duplex handling (args, per-compile
  `ethtoolApplied` dedup, warn-only failure) is unchanged.
- Fix direction chosen from the issue's "previously forced *or* live
  autoneg off" disjunction: previously-forced tracking only. Probing
  live autoneg state would miss the restricted-advertisement state
  (autoneg stays on, only the forced mode is advertised — per the
  issue's own correction), and an unconditional revert on every auto
  interface would write interfaces xpf never touched, violating the
  "never forced gets no write" acceptance.
- Tests: `pkg/dataplane/compiler_ethtool_autoneg_16787_test.go` drives
  `applyEthtool` through successive fresh `CompileResult`s (mirroring
  one `CompileConfig` per commit) with a recording `runEthtool` fake:
  force 100m/half → `duplex auto` issues `-s ge-0-0-3 autoneg on`;
  re-force → both leaves deleted issues it again; repeat auto compiles
  are silent (issued once); never-forced interfaces (unset / `auto`
  speed / `auto` duplex shapes) get no write; `duplex full` positive
  control is byte-identical to before and its later `auto` reverts;
  a failed force does not mark the netdev; a failed revert is retried
  on the next compile and then converges; forcing one netdev causes
  no write on another.

## Validation

- GREEN: `go test ./pkg/dataplane/ -run 'TestEthtool|TestParseSpeed|TestParseDuplex' -count=1 -v`
  — all 6 new #16787 tests plus `TestParseSpeed`/`TestParseDuplex` pass.
  Neighbour ethtool suites (`TestRxVlan*`, `TestEnsureRxVlan*`, RSS/ring)
  also pass. `go vet ./pkg/dataplane/` clean; `gofmt -l` empty.
- The pre-fix defect is the issue's EXECUTED probe (commit2/commit3
  record zero ethtool calls on master); the new tests encode exactly
  those steps, so the revert cells are red-by-construction on the old
  early-return path.

## Risk

Neighbours preserved: forced-write arguments, per-compile dedup, and
warn-only failure semantics for explicit modes are unchanged; ring/RSS
ethtool paths (`buffers:` keys) are untouched. No fail-open change:
the new write only restores autonegotiation on netdevs xpf itself
previously forced, and a failed revert is retried rather than assumed
converged. Residual: the registry is process-lifetime, so after a
daemon restart an auto-shaped commit cannot know a still-forced NIC
was forced by xpf and issues no revert (operator remedy unchanged:
manual `ethtool -s <if> autoneg on` or re-applying then deleting an
explicit mode). Tracking "previously forced" only also means a mode
forced outside xpf is never reverted by xpf — deliberate, per the
never-forced acceptance.
