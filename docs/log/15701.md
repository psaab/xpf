# #15701 — compileLog first-wins leaves; compact named stream/profile bodies dropped

- **Timestamp**: 2026-10-19
- **Action**: Fixed V16-03 in `pkg/config/compiler_security_log.go` only:
  - Top-level `mode`/`format`/`source-interface`/`source-address` now iterate
    `log` children in order with last-wins (Junos repeated-scalar semantics)
    instead of first-wins `FindChild`; `report` remains a presence flag.
    Empty values do not erase an earlier value.
  - Added `securityLogProfileSchema()` (`schemaForPath("security","log","profile")`)
    and shared `securityLogInstanceBody(inst, schema)`: recovers the named
    instance's trailing value tail via `instanceValueTail(inst.node, inst.name)`,
    splits it with `expandFlatRun([]*Node{{Keys: tail}}, schema)`, prepends it
    to the braced children, and expands the result — covering both
    `stream s1 ...` and hierarchical `stream { s1 ... }` /
    `profile { p1 ... }` compact shapes.
  - `compileLog` (streams and profiles), `validateSecurityLogStreamPortsAST`
    (#3349), and `validateSecurityLogStreamTLSProfileAST` (#3350, replacing
    its `Keys[2:]` ad-hoc elision) all read through the shared helper, so the
    strict port/tls-profile gates and the #2008 profile `stream-name`
    cross-reference see exactly the tokens the compiler consumes.
- **Pre-fix demonstration (RED)**: probe + new tests on the pre-fix tree showed
  `mode stream; mode event;` compiling `Mode="stream"` (first-wins),
  `stream { s1 host 192.0.2.10 port 70000; }` compiling with the stream dropped
  and both strict gates returning nil, the tls-profile variant likewise
  ungated, and `profile { p1 stream-name nosuch; }` compiling clean with the
  dangling reference invisible. New tests in
  `pkg/config/security_log_compact_instance_15701_test.go` failed on all six
  cells pre-fix.
- **Validation**:
  - `go test ./pkg/config/ -run '15701|TestSecurityLog|TestLogProfile|TestCompactTransport|TestCompactAndBlockTransport'` — PASS
    (duplicate-leaf last-wins; compact stream compiles host/port/category;
    compact invalid port strict-rejects and lenient-warns with 514 default;
    compact tls-profile strict-rejects and lenient-warns; compact profile
    dangling `stream-name` strict-rejects, valid reference compiles;
    schema-resolution guard; all pre-existing 6821/12887/profile cells green).
  - Pre-existing failures NOT introduced by this change:
    `TestPackedTailCredential*14412` (OSPF/IS-IS credential, untouched files)
    fails identically-patterned on this tree — only
    `compiler_security_log.go` + the new test file are modified.
- **Risk**: last-wins matches Junos merge semantics for repeated scalars;
  the compact expansion reuses the existing schema-gated `expandFlatRun`, so
  no new admission surface is opened — invalid compact values now fail
  closed through the same gates as the named/braced spellings, and lenient
  load/peer-sync keeps warn-and-boot behaviour.
