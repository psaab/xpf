# Issue #13229 — Remove dead configstore persistence APIs and reject unknown envelope formats

Finding D4-11 from the deep-review source report identified persistence entry points on `*DB` with no production callers, rollback metadata wrappers used only by tests, and envelope `ast` / `rollback-fmt` values that were parsed but never enforced. Dead interfaces retained maintenance and test-only behavior, while unsupported headers could be accepted and read as though compatible.

The fix removes the unused candidate/DB rollback path and methods, and the unused rollback metadata convenience wrappers. Tests now use the production metadata snapshot/generation functions directly. Versioned envelope headers require both `ast` and `rollback-fmt`; parsing rejects missing or unsupported values. Both the active DB read path and upgrade header inspection use this strict parser. Upgrade test fixtures now carry valid header metadata instead of abbreviated fake headers. Active config and canonical text rollback history persistence remain unchanged.

## Regression evidence

On pristine `origin/master` at `9d3869c0e`, before applying the fix:

```text
GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/var/worktrees/.cache/go-tmp \
  go test ./pkg/configstore -run '^TestEnvelopeHeaderRejectsMismatchedASTAndRollbackFormat_13229$' -count=1
```

RED: six mismatch cases failed because `ReadActiveMeta` returned no error for unsupported AST/rollback format values (including `ast=999`, `rollback-fmt=99`, zero, and negative values). The baseline also accepted absent fields; the final regression requires both version fields and checks both `ReadActiveMeta` and `InspectEnvelopeHeader`.
