# Issue #13229 — Remove dead configstore persistence APIs and reject unknown envelope formats

Finding D4-11 from the deep-review source report identified persistence entry points on `*DB` with no production callers, rollback metadata wrappers used only by tests, and envelope `ast` / `rollback-fmt` values that were parsed but never enforced. Dead interfaces retained maintenance and test-only behavior, while unsupported headers could be accepted and read as though compatible.

The fix removes the unused candidate/DB rollback path and methods, and the unused rollback metadata convenience wrappers. Tests now use the production metadata snapshot/generation functions directly. Envelope parsing rejects present AST or rollback-format values that do not match this build's supported versions; omission remains accepted for older envelope compatibility. Both the active DB read path and the upgrade header-inspection path use this strict parser. The active config and text rollback history paths remain unchanged.
