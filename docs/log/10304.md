# 10304 — gRPC `Set` gates handler-routed endpoints

- **Date**: 2026-09-18
- **Base**: `8966710325646decfa4ec65dc3ad8ea794f23cbb`
- **Fix**: `baf2d1a59568ee95dd67161822d9878b8f2720c8`
- **Files**: `pkg/grpcapi/authz_config_regex_9154.go`, `pkg/grpcapi/authz_config_set_verbrouted_10304_test.go`

## Defect

`Server.Set` routes `copy`, `rename`, `insert`, `deactivate`, and `activate` inputs by their leading verb. Before this fix, `configMutationLineFor` prepended `set ` to every `SetRequest` input unless it already began with `set `. An anchored deny such as `^security policies p1$` therefore saw `copy security policies p1 to security policies ok` as one synthetic `set` path rather than the real source and destination paths. The handler then executed the denied endpoint mutation. Unanchored substring denies could catch the synthetic line incidentally, masking the bypass.

## Change

The gRPC resolver now preserves handler-routed verb-led inputs verbatim. The shared configuration authorization logic consequently extracts the real endpoint paths, including both endpoints for `copy` and `rename` under #9938 F-029 semantics. Bare Set paths retain the existing `set ` normalization, and an already-prefixed `set` line is not doubled.
