# #14419 — DR15-H4 same-name as-path across shapes

## Mechanism
`policy-options as-path` is schema `args:2, multi:true, children:nil` (`schema_routing.go:190`), so `namedLeafPeer9859` (needs children) and `leafListPeer`/`isLeafListSchema` (args<=1) both decline it. Group definitions adopted beside inline same-name definitions for packed/container, container/packed, and container/container (different regex child tokens), and compiler `po.ASPaths[name]=...` (`compiler_routing.go:1473`) last-wins in merged order (inline first, group second) stored the GROUP regex `.*` over inline `^65001$`. Both-packed was the only inline-wins control. Also pre-existing (measured RED): different-name packed/packed group `AP2` was dropped by keyword-peer override.

## Fix
- New `pkg/config/group_merge_aspath_14419.go`: `isASPathDefinition14419` (policy-options level, `as-path <name>`), `asPathSameNameInlinePeer14419` (same `Keys[1]` in dst), `asPathIsDefinition14419`.
- `pkg/config/ast_groups.go` `mergeNodes`:
  - Leaf peer!=nil arm: if source is as-path definition — same-name → drop group leaf; different-name → adopt (fixes AP2 packed/packed drop, required by spec different-name rule).
  - Leaf no-peer arm: same-name container inline peer → drop group leaf (Direction B).
  - Container branch before `sameKeyedContainers9802`: same-name any-shape inline peer → drop whole group container, no child merge (Direction A + C/C).

No compiler change; merge hands compiler exactly one same-name definition.
