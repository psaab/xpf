# #16581 — Junos `tcp-initial-timeout` / `fin-invalidate-session` / `apply-to-half-close-state` rejected (residual of Y39-05/#15256)

- **Timestamp**: 2026-10-24
- **Context**: #15753 added `time-wait-state apply-to-half-closed-state`
  (Junos: `apply-to-half-close-state`), and the Junos leaves
  `tcp-initial-timeout` and `fin-invalidate-session` under
  `[edit security flow tcp-session]` were still rejected by the
  closed-world schema (`SchemaValidate` unknown-keyword reject on the
  flat-set -> strict commit path). vSRX flow configs using either Junos
  leaf were refused; only the xpf spellings `initial-timeout` and
  `apply-to-half-closed-state` committed. #15256 (99b37e805c) touched
  only screen, port-mirroring and trap gates, so Y39-05 was carried in
  its cohort title but never fixed.
- **Fix**: Junos spellings are canonical, xpf spellings kept as
  deprecated aliases to the same fields:
  - `tcp-initial-timeout` (new schema leaf, same
    `ValidateInteger(0, MaxDurationSeconds)` gate) and deprecated alias
    `initial-timeout` both compile to `InitialTimeout`;
    `TCPSessionInitialTimeoutLeaf` is now `"tcp-initial-timeout"` with
    `TCPSessionInitialTimeoutAliasLeaf = "initial-timeout"` (the #6539
    enforcement table covers the canonical leaf once; its schema-coverage
    guard explicitly exempts the one alias).
  - `time-wait-state apply-to-half-close-state` (canonical) and
    deprecated alias `apply-to-half-closed-state` both compile to
    `TimeWaitStateApplyToHalfClosed`; show annotation, type/schema/Rust
    comments corrected to the Junos spelling.
  - `fin-invalidate-session` is a new enforced knob (not an alias):
    `TCPSessionConfig.FinInvalidateSession` -> wire
    `tcp_fin_invalidate_session` (snapshot protocol v71 -> v72, Go
    `ProtocolVersion` + Rust `CONFIG_SNAPSHOT_PROTOCOL_VERSION` in
    lockstep, snapshot-shape golden regenerated) ->
    `TcpSessionWindowSecs.fin_invalidate_session` ->
    `SessionTimeouts.tcp_fin_invalidate_session`; the single
    close-window selector `tcp_close_window_ns_with_app` returns 0
    (immediate reap on next expiry) for the TIME_WAIT class (both FINs
    seen, close handshake complete, per Juniper's
    fin-invalidate-session page: "the invalidation of the session
    occurs immediately"), while CLOSING (one FIN) and RST keep their
    windows. `show security flow` renders the knob.
  - Compact-normalize scope gains `tcp-session tcp-initial-timeout`
    and `tcp-session fin-invalidate-session`.
