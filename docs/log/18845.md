# #18845 — close authz, race-gate, and parser-error gaps

- **Timestamp**: 2026-11-05

## Why

The typed `GetClusterHAState` RPC had an empty request with a fixed canonical command but no explicit decision in the #17184 argument-form census. The daemon race filter omitted the connected-drain concurrency tests, leaving their regressions outside `test-race-dp`. The Junos AS-path interval parser discarded integer conversion errors; its prior interval validator rejected malformed bounds before those conversions, but that verdict was implicit and duplicated.

## What

- **G21** — named `GetClusterHAState` as argument-absent in `methodsWithoutArgumentForms`. Its proto request has no fields and its canonical command is `show chassis cluster`, so the bare charge is argument-complete.
- **G64** — added `ConnectedDrain` to both the daemon `test-race-dp` existence alternatives and its quoted `-run` regex. This discharges **#18982 family 7**. The cluster recipe and its first matching `-run` pattern remain unchanged.
- **PW6** — `intervalBounds` now returns parse errors and the Junos parser propagates them, preserving the established invalid-interval messages and reject verdicts instead of silently turning failed conversions into zero bounds. The wider census also exposed ignored `ParseUint` calls in the same AS-path parser; `parseASN` now returns both the validated value and the same existing error, eliminating redundant parses without changing acceptance or rejection. It also exposed the intentional `ParseInt` in `ipsecStrtolDecimalPrefix`: `ErrRange` is now explicit and retains `ParseInt`'s saturating 64-bit result before narrowing; non-range parse errors still produce zero as before.
