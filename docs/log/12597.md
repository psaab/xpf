# 12597 — synchronize the cold-boot shrink warning assertion

- **Timestamp**: 2026-10-13
- **Action**: fix asynchronous audit-log observation in the 11755 daemon regression
- **Base**: `db274ef4d` (`config: reject valueless qualified next hops (#12818)`)
- **Files**:
  - `pkg/daemon/daemon_feeds_shrink_11755_test.go`

## Why

`TestFeedShrinkHighWaterSurvivesColdDaemonRestart11755` waited for the feed's installed prefix count, then immediately inspected a shared `bytes.Buffer` for the warning. In `feeds.Manager.installSnapshot`, the prefix state is published under the manager lock before the bootstrap-warning log is emitted after unlock (`pkg/feeds/feeds.go`, `installSnapshot`). Therefore the prefix poll can observe the install before the asynchronous refresh goroutine reaches its warning. Reading the buffer while the goroutine writes is also unsynchronized. CI run [38114144301](https://github.com/psaab/xpf/actions/runs/38114144301) failed at `daemon_feeds_shrink_11755_test.go:86` with only the earlier plaintext-URL and feed-start records in the captured log; the high-water tuple assertions had passed. This is a test-observation race, not evidence that persisted high-water recovery failed.

## What

The regression now captures logs in a mutex-protected buffer and waits, with a bounded deadline, for the specific warning before asserting it. The high-water and shrink behavior assertions remain unchanged; production code is untouched.
