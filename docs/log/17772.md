# Reject ambiguous peer-only IPsec PSK ownership (#17772)

- **Issue**: #17772, security.
- **Cause**: Peer-only PSK selectors were deduplicated only while rendering one connection. Separate gateways could therefore claim the same selector with different PSKs, including one gateway's remote identity colliding with another gateway's local identity. A gateway with hostname and IP endpoints but no explicit remote identity also had no single selector that could authenticate the hostname peer.
- **Change**: Added shared effective-identity/PSK ownership analysis in `pkg/config`. Strict compilation rejects cross-gateway collisions and mixed hostname/IP endpoints without a discriminating remote identity; lenient compilation warns. The renderer consumes the same detector and skips affected groups before emitting connections or secrets, preserving unrelated VPNs. This per-VPN skip lets successful apply remove stale unsafe entries; a render-wide error makes `Manager.applyConfig` abort before writing.
  - Collision keys canonicalize DN case-ignore attributes (including escaped separators, space preparation, RDN and multi-valued AVA order), unify `user-at-hostname`/`email`/`rfc822` with full case-folding of the domain only, and compare key-id literal/hex spellings by strongSwan-effective bytes (odd/invalid hex stays literal).
  - A configured local identity, otherwise the effective local IP address (`vpn.LocalAddr` before `gw.LocalAddress`), participates only in cross-side collision checks. The raw authored identities remain the renderer's output. Malformed DN syntax falls back to exact raw-key comparison. Identical effective PSK sets under the same identity remain allowed; no PSK material is exposed.
