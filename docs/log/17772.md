# Reject ambiguous peer-only IPsec PSK ownership (#17772)

- **Issue**: #17772, security.
- **Cause**: Peer-only PSK selectors were deduplicated only while rendering one connection. Separate gateways could therefore claim the same selector with different PSKs, including one gateway's remote identity colliding with another gateway's local identity. A gateway with hostname and IP endpoints but no explicit remote identity also had no single selector that could authenticate the hostname peer.
- **Change**: Added a shared effective-identity/PSK ownership analysis in `pkg/config`. Strict compilation rejects cross-gateway collisions and mixed hostname/IP endpoints without a discriminating remote identity; lenient compilation warns. The IPsec renderer uses the same classification and omits affected connections while preserving unrelated VPNs. This intentionally uses the existing per-VPN skip contract instead of returning a render-wide error: `Manager.applyConfig` aborts before writing when rendering returns an error, while a successful skip lets apply remove stale unsafe connections and retain healthy siblings. It does not disclose PSK material. Identical effective PSK sets sharing an identity remain allowed. Updated the older mixed-endpoint controls to configure an explicit remote identity, and gave the unrelated #16699 capture-limit control distinct peer IPs so it continues to exercise only its intended bound.
