# 17727 — eventengine: deferred wake must not strand ready budget action after expiry

- **Timestamp**: 2026-10-29
- **Action**: When budget work remained parked but wake recomputation pruned the last expired slot, the worker could store a zero wake and sleep indefinitely after consuming the park nudge. The worker now schedules an immediate wake in that state; no parked work still produces no timer. Added a deterministic expiry-between-drain-and-recompute regression plus an idle timer control.
- **File(s)**: `pkg/eventengine/engine.go`, `pkg/eventengine/engine_deferred_wake_expiry_17727_test.go`, `pkg/eventengine/README.md`, `debian/changelog`
- **Validation**: The new regression failed on the unmodified wake logic: `go test ./pkg/eventengine -run '^TestDeferredWorkerDrainsReadyBudgetHoldAfterLastSlotExpires17727$' -count=1 -timeout=20s` timed out with the hold still parked and the worker waiting without a timer. After the fix, the named test passed (`1.029s`); it also passed under `-race` (`2.043s`). The adjacent guards passed: `TestDeferredWorkerNoTimerSpinAfterBudgetReplay16658` and the four `*16774` failure-backoff tests. `go vet ./pkg/eventengine` was clean. The full package suite passed: `go test ./pkg/eventengine -count=1 -timeout=180s` (`40.328s`). `gofmt -w` completed for both changed Go files.
- **Risk**: A parked budget hold with no live expiry now arms an immediate timer to retry the drain. In production, pruning the final expired slot makes budget available; if another commit wins the slot first, the next wake recomputation sees its live expiry. Empty parked maps still leave wake zero and arm no timers, preserving #16658's idle invariant.
