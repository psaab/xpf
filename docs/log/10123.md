# #10123 — reprepro post-hoc Release singleton assert

Follow-up to #9921 item (3), which deliberately left the opt-in
`XPF_APT_TOOL=reprepro` path without the flat path's `Release` freshness
assert because no reprepro binary was available on that lane. Reprepro
synthesizes `dists/$SUITE/Release` from its database and `ValidFor` setting
as part of `includedeb`/export; this change verifies that emitted file before
returning.

- **Timestamp**: 2026-09-18
- **Change**: `scripts/dist/build-apt-repo.sh` now requires the reprepro
  output `Release` to exist, have exactly one `Date:` and exactly one
  `Valid-Until:`, parse both fields as dates, and satisfy the exact epoch
  equation `Valid-Until == Date + VALID_DAYS*86400`. It fails closed on a
  missing file, duplicate/missing fields, malformed dates, or a wrong horizon.
- **Legitimate reprepro delta**: unlike the flat path, the script cannot
  compare against its own pre-export `NOW`: reprepro chooses `Date` during
  export immediately before the post-hoc check. The expected epoch therefore
  derives from the emitted `Date` itself, eliminating wall-clock skew without
  introducing a ± tolerance. Requiring one `Date` makes that derivation
  unambiguous. Reprepro 5.3.1 was observed to emit one `Date:` and one
  `Valid-Until:` with `ValidFor: 7d`, exactly seven days apart; `ValidFor: 0d`
  emits no `Valid-Until:` and is rejected.
- **Tests**: `scripts/dist/test_build_apt_repo_reprepro_10123.py` adds a
  `skipUnless`-gated real-binary/GPG fixture plus an always-run fake-reprepro
  emission battery. The fixture covers valid `7d` and real `0d` output; the
  shim covers valid/default horizons and duplicate, missing, malformed
  shape (duplicate/missing `Date:`), missing `Release`, one-day-short, and
  one-second-off `Valid-Until:` output. No test depends on a host package
  fixture for the refusal legs.
- **RED (pre-fix)**: full new module on the base script ran 11 tests with
  `8 failures` (all refusal cases accepted with exit 0, including real
  reprepro `ValidFor: 0d`; three valid positive controls passed). The
  duplicate/missing/skewed output was therefore demonstrably shipped before
  the assert.
- **GREEN (post-fix)**: full new module ran `11 tests`, `OK` against real
  reprepro 5.3.1, GPG 2.4.9, and dpkg-deb. The real positive output had one
  `Valid-Until:` exactly `Date + 7d`; real `0d` failed closed. The shim
  battery's 7 refusal cells all failed with the expected assert diagnostics,
  while its 2 valid controls passed (8 refusals / 3 valid combined with the
  real-reprepro legs, 11 total).
- **Scoped checks**: `shellcheck -S warning scripts/dist/build-apt-repo.sh`,
