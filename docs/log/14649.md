# #14649 — `make test-go` caching masked new violations in git-grep census packages

- **Timestamp**: 2026-10-17
- **Action**: Extended the #6626 uncached carve-out in the Makefile `test-go`
  target from `pkg/refactoraudit` alone to
  `-count=1 ./pkg/refactoraudit/ ./pkg/docsref/ ./pkg/memlockcensus/`, and
  rewrote the governing comment as a joint #6626/#14649 contract: any package
  whose tests read the tree outside the compiled sources (`git grep`,
  `git ls-files`, subprocess census) must be on this leg, not cached-only.
  `pkg/docsref` (#6615) and `pkg/memlockcensus` (#8371) both shell out to
  `git grep` and read only listed files; the working tree, the index, and
  the grep output are not `go test` cache inputs. In a linked worktree
  `.git` is a gitdir pointer file ordinary git ops do not rewrite, so the
  masking is reliable in the standard worktree workflow (a primary clone
  busts the cache by accident when an intervening git op touches `.git`).
  Deliberately not fixed by making each census Stat the index / every
  candidate file: that would tax every run of two already-slow censuses to
  repair a wiring property, and the #6626 precedent (plus its existing
  Makefile canary) already establishes the uncached-leg shape for exactly
  this class.
- **Regression**: `pkg/docsref/uncached_census_14649_test.go`
  (`TestMakefileRunsTreeCensusesUncached14649`) parses the real Makefile's
  `test-go` recipe (tab lines, skipping comments) and requires a recipe line
  carrying `-count=1` together with each of the three census packages;
  `TestUncachedCensusGuardRejectsStaleShapes14649` pins the guard against
  the stale shapes (pre-#14649 refactoraudit-only leg, naming without
  `-count=1`, naming only in a comment, `-count=1` on a different line, no
  `test-go` target). The pre-existing #6626 canary
  (`TestMakefileRunsAuditPackageUncached`) still passes unchanged.
- **File(s)**: `Makefile`, `pkg/docsref/uncached_census_14649_test.go`,
  `docs/log/14649.md`
