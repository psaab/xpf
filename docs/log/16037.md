# #16037 — PPTP ALG teach without TCP-sequence binding

- **Timestamp**: 2026-10-23
- **Action**: Gated PPTP control-segment teaching on the tracked TCP
  data-sequence window. Added `SessionTable::tcp_data_seq_verdict`
  (`session/lookup.rs`): with tracked state the segment
  [seq, seq+payload_len) must lie inside the receiver window
  (companion-advertised window, the same pairing the
  closing-segment verdict uses), retransmissions within the window
  behind `tcp_rcv_nxt` included; missing entry or no seq state
  (HA-synced import) is `Unknown`. The poll path snapshots the
  verdict BEFORE the deferred `note_tcp_seq` runs — a post-note
  verdict would validate an out-of-window payload against its own
  mutated `rcv_nxt` — and the non-closing capture arm captures only
  on `Valid` (or under `tcp_no_sequence_check`, mirroring the
  closing gate). `Invalid`/`Unknown` learn nothing while the packet
  still forwards. The closing/forget arm is unchanged — teardown
  was already sequence-validated. NOT changed: the capture helper
  and drain (whole-segment, no reassembly), flow-cache bypass, and
  GRE data resolve.

  `pptp_data_seq_verdict_in_out_unknown_16037`: synced/unknown-seq
  `Unknown` (learn-nothing), in-window OCR teachable, out-of-window
  and far-behind OCR not teachable, retransmission and
  next-segment teachable, window-spilling segment rejected. The
  pre-note snapshot ordering is pinned at the poll-descriptor
  production site: the verdict is computed in the same read-only
  block as the closing verdict, before any note of this segment.
  Existing closing-verdict and PPTP capture/drain suites must stay
