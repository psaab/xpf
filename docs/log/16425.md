# #16425 — ip-monitoring probe source ignored address family on the primary (R3-F05-03)

## Defect

`Monitor.probeSourceFor` (pkg/cluster/monitor.go) returned the FIRST
VIP/unit address for a bound ip-monitoring target on the primary,
regardless of the target's family. `RethVIPsForRG` appends unit
addresses in authoring (tree) order, so on a dual-stack RETH unit whose
`family inet6` precedes `family inet`, an IPv4 target bound via
`interface reth0.0` resolved to the IPv6 VIP. `defaultICMPDialer("udp4",
"<v6>")` failed, `probeICMP` reported not-completed, and `pollCycle`
skipped the target every cycle: no dampening advance, no
`ip:<addr>` debt, no demotion. The RG's upstream-gateway sensor was
silently inert on exactly the node that owns the RG, so loss of that
gateway never failed the group over. The same never-completes shape was
reachable with an IPv6 literal target under `family inet` (which
compiled clean, there being no family validation).

## Fix

- `pkg/cluster/monitor.go`: `probeSourceFor` now selects, on the
  primary, the first address OF THE TARGET'S FAMILY — VIP list first,
  then the configured unit addresses — via the new `firstAddrOfFamily`
  helper (family rule `net.IP.To4() != nil`, the same one `probeICMP`
  classifies sockets by, so a 4-in-6 literal is IPv4 on both sides).
  When no address of the target's family exists, the probe is
  source-free (`"", device`) instead of wrong-family-bound: strict
  commit rejects that shape for a bound target, and a leniently-loaded
  legacy config probes with a kernel-chosen same-family source rather
  than never completing. Secondary behaviour is unchanged.
- `pkg/config/compiler_validate_strict_chassis.go`:
  `validateChassisClusterStrict` (which the tolerant load / peer-sync
  paths downgrade to a warning, #1960 no-brick) now rejects, inside the
  existing ip-monitoring target loop:
  - a target under `family inet` that is not an IPv4 literal;
  - a non-IPv4 `secondary-ip-address`;
  - a bound target whose declared unit carries no IPv4 address
    (`ipMonitorTargetUnitAddresses` mirrors the monitor's unit-ref
    split; the gate abstains when the interface/unit is undeclared —
    existence remains other gates' concern).
- `docs/feature-coverage.md`: the #15038 ip-monitoring paragraph now
  states the family selection and the new commit rejections.

Deliberately NOT done: treating a primary bind failure as a completed
(alarmed) failure. The issue listed it as "consider"; #15038 pinned
that a socket-open failure holds state failover-neutrally (matching the
RPM `ErrProbeSetup` doctrine), the family selection removes the
realistic cause, and flipping it would demote an RG for an environment
failure on the owner.

## Risk

- Behaviour change on the primary is scoped to bound dual-stack
  targets whose first unit address is not the target's family: they
  now probe (and can demote) instead of never measuring. Single-family
  and inet-first configs select the identical source as before.
- New strict-commit rejections hit only configs that could never
  measure (v6-under-inet literal, v6 secondary, inet6-only bound unit);
  persisted/peer-synced copies still load with a warning via the
  existing lenient downgrade (#1960), and at runtime such a target now
  probes source-free instead of wrong-family-bound.
- Lab verification (real dual-stack RETH failover on gateway loss)
  remains the outstanding external check, as it was for #15038.
