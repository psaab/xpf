# #14125 — Stage-11 ESP-in-UDP fine host-policy gates

## Why

Stage 11 (`poll_descriptor/mod.rs`) claimed IPsec passthrough packets
before the ordinary LocalDelivery arms and reinjected them delegated via
`xpf-usp1`, whose ingress interface name is intentionally outside the
kernel `lo0` / `to-zone junos-host` ingress scopes. The #10525 fix re-ran
the userspace fine gates (`apply_lo0_filter_action` +
`junos_host_local_policy`) on this path, but wrapped them in
`if is_positive_ike`, so only IKE packets paid them.

An already loaded SA's ESP-in-UDP (UDP/4500, parsed SPI + `Hit` on the
SA snapshot) therefore reached delegated reinjection without ever
matching a configured fine `lo0` discard or `to-zone junos-host` deny
written for its source. The report's raw ESP/AH scenario does not apply
here: raw ESP/AH is hard-dropped earlier in the same arm
(`stage11_raw_protocol_requires_drop`) and never reinjected, so it
needs no fine gate. The defect is bounded to SA-checked ESP-in-UDP
(data still faces XFRM authentication after reinject; this is a
configured-policy bypass, not an authentication bypass).

## What

- `userspace-dp/src/afxdp/poll_descriptor/mod.rs`: run the existing
  lo0 + junos-host fine gates for every packet that will actually be
  reinjected, not only positive IKE. The gate block now executes under
  `if let Some(flow) = flow.as_ref()` (always true at that point — the
  outlet arm above already `continue`d on `None`, and malformed IKE /
  SA misses / raw ESP/AH have all `continue`d), reusing the identical
  helpers, wire-tuple `policy_dst`, gate context, counters, and
  fragment-admission failure handling as the IKE path. No new
  evaluation logic, no new counters.
- `userspace-dp/src/afxdp/poll_stages.rs`: document that the #4323
  coarse host-inbound exemption for ESP/ESP-in-UDP does not exempt
  SA-checked ESP-in-UDP from the caller's fine gates (#14125).
- Tests (`tests_slow_path_disposition.rs`): four poll-loop cells using
  the existing #10516 SA harness — junos-host `any` deny drops an
  SA-hit ESP-in-UDP packet, lo0 `udp/4500` discard drops it, and two
  controls (no fine match; deny for a different source) still delegate.
  The T7 ESP control comment is corrected: that packet has no loaded
  SA and drops at the SA gate, before the fine gates.
- NOT changed: the coarse `host_inbound_admits` gate — ESP-in-UDP
  stays exempt from it by design (#4323, SA is the authorization,
  kernel `l4proto {50,51} accept` parity). NOT changed: raw ESP/AH
  handling (already fail-closed), IKE seeding (still only for
  positive IKE, still only after gates + reinject succeed), and the
  primary kernel-nftables path.

## Validation

- New cells (this branch, head with fix): `cargo test --manifest-path
  userspace-dp/Cargo.toml --bin xpf-userspace-dp -- 14125` — 4 passed
  (junos-host deny, lo0 discard, no-match control, other-source control).
- RED evidence: with the production fix stashed (tests only), the two
  deny cells FAIL with `delegated.queued_packets == 1` (packet
  reinjected despite the fine deny) while both controls still pass;
  restoring the fix returns all 4 to green.
- Existing Stage-11 suites: `cargo test --bin xpf-userspace-dp --
  14125 10516 10525 10585` — 33 passed; full
  `tests_slow_path_disposition` module — 62 passed.
- Clippy: one pre-existing error on base master too
  (`afxdp/umem/mmap.rs:241` `mut_from_ref`), unchanged by this branch;
  no new warnings in the touched files.

## Risk

- ESP-in-UDP data packets now pay one lo0 filter evaluation and one
  junos-host policy evaluation per packet on the secondary path
  (previously only IKE did). Both are no-ops when unconfigured
  (`evaluate_lo0_filter_counted` returns default with no filter;
  `evaluate_junos_host_policy_l3_aware_at` returns `None` without
  junos-host rules), mirroring the ordinary LocalDelivery cost.
- A `to-zone junos-host` permit with `then log` now matches
  ESP-in-UDP packets too; only the drop verdict is acted on here
  (same as the pre-existing IKE handling — no session is installed
  on this path, so permit metadata has nowhere to go).
- Operator-visible delta: a configured fine deny that names
  UDP/4500 (lo0) or the ESP peer's tuple with application `any`
  (junos-host) now actually drops that SA's data on the DNAT-to-self
  / GRE-inner secondary path, matching what the same config already
  did to IKE and to primary-path host-bound traffic.
