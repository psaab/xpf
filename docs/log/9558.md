## Mechanism (origin/master `42806a46b`)

- `cmd/xpfd/main.go` exits `verify-dataplane` with **3** only for `dataplane.ErrUserspaceShimVerifierReject` (the #1864 kernel-verifier reject). It exits **1** for every other error. A live pinned-map ABI mismatch is one of those: `validateUserspaceShimLivePins`, as in "ABI-incompatible with the live pinned map … ValueSize embedded=152 pinned=144", which the issue measured on the loss cluster.
- `deploy_verify_dataplane_preflight` wrapped the probe in `if ! incus exec …; then die "<#1864 remediation>"`, so every non-zero exit printed "This is the #1864 failure mode. Rebuild with the pinned toolchain (make generate) …". That is the last thing an operator reads, and for the ABI refusal it contradicts verify-dataplane's own message: rebuilding the shim cannot clear a stale pin.
- No existing cell could see it. The reject cells assert hard-fail, touching nothing, and cleanup, but never the text, and `FAKE_VERIFY_RC=1` was the only REJECT the mock produced.

## Change

- **Wrapper.** It captures `verify_rc`. Both arms still call `deploy_preflight_cleanup` and `die` before any remote destructive step, so the ORDERING invariant is unchanged.
  - Exit 3 keeps the #1864 text verbatim.
  - Any other non-zero exit says `verify-dataplane refused … (exit N)`, states it is NOT the #1864 reject, points at verify-dataplane's own message, and deliberately contains no "make generate".
- **Selftest.**
  - `test_preflight_verifier_reject_prescribes_1864_remediation` (rc 3): must print the #1864 text.
  - `test_preflight_other_refusal_prescribes_no_make_generate` (rc 1): must NOT print it, and must name `(exit 1)`. That is an absence assertion, because a presence-only cell would pass the pre-fix wrapper.
- **Comments.** `deploy-lib.sh` and `cmd/xpfd/main.go` said the probe uses "anonymous maps, no pins". Its LOADS use anonymous maps and it writes no pins, but its spec validation READS the live pins. Both comments now say so and name the exit-code contract.

No module README describes this wrapper's message, so no further docs change is needed. The contract lives in the two corrected comments and in this log.
