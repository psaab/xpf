# #16789: replayed own heartbeat forges the duplicate-node-id warning

- **Timestamp**: 2026-10-25
- **Action**: `duplicateNodeIDAuthenticated` (the #14705 HMAC gate on the
  same-NodeID heartbeat arm in `heartbeatReceiver.readLoop`) verified
  only the HMAC, so an on-link spoofer replaying this node's own
  captured heartbeat (valid MAC under the shared PSK, same NodeID)
  from the peer IP forged the `ERROR` log, the EventRG
  "duplicate node-id" history entry, and a refreshed shared 30 s
  limiter that can suppress the richer authenticated beacon
  diagnostic. Fixed by also dropping frames whose trailer session
  equals this process's own heartbeat session:
  - `pkg/cluster/heartbeat.go`: `duplicateNodeIDAuthenticated` now
    extracts the trailer session via `heartbeatAuthTrailer` and
    returns `false` when it equals `Manager.ownHeartbeatSession()`
    (non-zero). New `ownHeartbeatSession()` accessor returns the
    per-Manager anti-replay session without minting it (zero =
    not yet drawn), so a forged frame cannot make a never-sent node
    create sender state. This mirrors the beacon path's own-sender
    exclusion (`handleBeacon` compares the signed sender-instance ID
    against `w.instance`). `hbSession` is now `atomic.Uint64`
    (was a plain `uint64` written under `hbNonceOnce`), with
    `heartbeatNonce`/`LocalProcessToken` using `Store`/`Load`, so
    the receiver goroutine's read is race-free against the sender's
    one-time store.
  - A genuine duplicate chassis runs a different process with a
    different random session and still warns; unsigned, wrong-key,
    tampered, and different-session-failing-MAC frames still fail;
    the unkeyed dual-accept path is unchanged (no trailer to compare,
    legacy warning preserved).
- **File(s)**: `pkg/cluster/heartbeat.go`, `pkg/cluster/manager.go`
  (`hbSession` type only), `pkg/cluster/heartbeat_duplicate_nodeid_14705_test.go`,
  `pkg/cluster/README.md`, `docs/log/16789.md`, `debian/changelog`.
- **Validation**: extended
  `TestRecvLoop_DuplicateNodeIDHeartbeatRequiresHMAC_14705` with two
  subtests over the real `readLoop`/UDP sockets: (1)
  `own_reflected_heartbeat_does_not_warn_16789` builds a frame from
  the real sender path (`buildHeartbeat` + `heartbeatNonce` session,
  signed under the PSK), asserts the gate refuses it directly, that
  `readLoop` produces no history entry / no limiter consumption /
  no liveness refresh, and that a genuine beacon still warns;
  fail-on-revert verified by temporarily disabling the own-session
  check (the subtest reds). (2)
  `different_session_duplicate_still_warns_16789` asserts a signed
  duplicate under a different session still warns with exactly one
  history entry. Existing #14705 subtests (forged, signed-duplicate
  replay preservation, rotation key, unkeyed) and
  `TestHeartbeatNonceIsIncarnationScoped_6169` re-run green. See PR
  for counts.
- **Residual**: diagnostic integrity only — no election or liveness
  effect, as in the source finding. A node that has never sent a
  signed heartbeat (session not yet minted, e.g. before the first
  sender tick) reads its own session as zero; a replay of its own
  frame is impossible before it has sent one, and after the first
  send the session is minted and the check is armed for the life of
  the process (the session survives heartbeat restarts per #6169).
  No lab/cluster smoke run by this lane (unit coverage over loopback
  UDP only).
