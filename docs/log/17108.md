# Issue #17108 — single-source ShowText topic→command resolution (R4-Q47-01)

- **Issue:** ShowText topic→command resolution existed three times: `optopic.LookupShowText` (registry, exact-then-longest-prefix), a gRPC copy (`showTextTopicCanonicalCommand` + `showTextCommandPrefix`/`init()` in `pkg/grpcapi/authz_command_gate_7172.go`), and a REST copy (`restShowTextPrefixRules9952` + longest-prefix loop in `pkg/api/authz_command_regex_9952.go`, added by #16067 after the exact-only REST copy over-denied every packed topic). `cmdtree.CommandForShowTextTopic` was exact-only and unused by either gate.
- **What:**
  - `pkg/optopic/optopic.go`: added `ShowTextCommand(topic) (string, bool)` delegating to `LookupShowText` — exact-first, then longest-prefix-first; `ok=false` stays unmapped-means-deny.
  - `pkg/grpcapi/authz_command_gate_7172.go`: `showTextTopicCanonicalCommand` now returns `optopic.ShowTextCommand(topic)`; deleted `showTextCommandPrefixRule`, `showTextCommandPrefix`, and its sorting `init()`. The frozen-contract census (`authz_registry_census_16136_test.go`) still grades this wrapper against pre-registry literals, never against the registry.
  - `pkg/api/authz_command_regex_9952.go`: deleted `restShowTextPrefixRules9952`; `restRequestCommand9952` show-text arm now returns `optopic.ShowTextCommand(...)` and no longer calls `ShowTextTopicCommands()` per request (also removing a full defensive map copy per show-text request). `allRESTCanonicalCommands9952` still legitimately enumerates `cmdtree.ShowTextTopicCommands()` once via `sync.OnceValue` for the registered command surface — that is a census of values, not a topic→command lookup.
  - `pkg/cmdtree/showtext_topic.go`: `CommandForShowTextTopic` delegates to `optopic.ShowTextCommand` (was exact-only map index).
- **Acceptance greps:** `grep -rn 'strings.HasPrefix(topic' pkg/api pkg/grpcapi` → no hits. `grep -n 'showTextCommandPrefix\|restShowTextPrefixRules9952' pkg/grpcapi/*.go pkg/api/*.go` (non-test) → no hits. `restRequestCommand9952` no longer calls `ShowTextTopicCommands()`.
- **Parity tests (all keys + key+"x"):** `TestRESTShowTextMatchesRegistry17108` (pkg/api) drives `restRequestCommand9952` over every `optopic.ShowTextEntries()` key plus `key+"x"`/`key+"probe-value"` for each prefix key, asserting identical `(command, ok)` to `optopic.ShowTextCommand` and to the entry's own `Command`; unknown topic stays `("",false)`. `TestGRPCShowTextMatchesRegistry17108` (pkg/grpcapi) does the same for `showTextTopicCanonicalCommand` and `cmdtree.CommandForShowTextTopic`, and asserts price/command `ok` agreement via `showTextTopicPermission`. `TestShowTextCommand17108` (pkg/optopic) pins exact, bare-prefix, packed, and unknown topics plus the full key/key+"x" sweep.
