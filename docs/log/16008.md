# #16008 — static NAT undefined from-zone: strict reject, tolerant drop

- **Timestamp**: 2026-10-23 (`fix/16008-static-nat-zone`)
- **Change**: A static-NAT rule-set whose `from zone` named no configured
  zone was warn-only (`ValidateConfig` in `compiler_validate_warn.go`),
  while `buildStaticNATSnapshots` shipped the name verbatim in `FromZone`
  and the Rust dataplane (`static_nat.rs`) matches it by exact name
  equality — a typo'd from-zone silently never matched (silent loss,
  never widening). The static leg now joins the #15001/#16146 unified
  disposition: `natUndefinedZoneFindings` walks `cfg.Security.NAT.Static`
  after source/destination, so strict commit rejects naming rule-set and
  zone, the tolerant path warns per offender and records
  `{Kind:"static", Name}` in `LenientNATUndefinedZoneRuleSets`, and the
  tolerant consumers drop exactly those rule-sets — `buildStaticNATSnapshots`,
  `buildNptv6Snapshots` (NPTv6 shares the Static list/FromZone), and
  `compileStaticNAT` (no counter ID for an inert rule-set) — instead of
  shipping a verbatim never-match row. The warn-only loop in
  `ValidateConfig` is removed (it would duplicate the tolerant warning).
- **Files**: `pkg/config/compiler_validate_strict_nat.go`,
  `pkg/config/compiler_validate_warn.go`, `pkg/config/compiler_opts.go`,
  `pkg/config/types.go`, `pkg/dataplane/compiler_nat.go`,
  `pkg/dataplane/userspace/nat_static.go`,
  `pkg/dataplane/userspace/nat_nptv6.go`, tests
  `pkg/config/static_nat_undefined_zone_16008_test.go`,
  `pkg/config/nat_undefined_zone_unified_16146_test.go` (static cells),
  `pkg/config/destination_nat_zone_test.go` (#12245 static leg updated),
  `pkg/dataplane/userspace/static_nat_undefined_zone_16008_test.go`,
  `docs/log/16008.md`.

## Validation

- New unit tests: strict reject with exact unified message, tolerant
  warn + record + retention, defined/unscoped/interface-scoped controls
  (`pkg/config`); snapshot drop with healthy sibling shipping, NPTv6
  drop, and no-record verbatim control (`pkg/dataplane/userspace`).
- Removing the static arm of `natUndefinedZoneFindings` turns the strict
  test red (commit accepts the typo); removing either builder drop
  turns the corresponding snapshot test red (verbatim row ships).

## Risk

Strict commits carrying a pre-existing static-NAT zone typo now fail
instead of committing an inert rule — intended. Tolerant loads boot
with the bad rule-set dropped (fail-closed, no NAT for it) rather than
shipping a never-match row. Hand-built/JSON-round-tripped configs
without the tolerant record keep legacy verbatim builder behavior,
pinned by the no-record control. No wire/snapshot shape change.
