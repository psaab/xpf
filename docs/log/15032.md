# #15032 Brace-elided interface instance invisible to group merge (A03-03) — engineering history

Issue: psaab/xpf#15032 (`config: fix — A brace-elided interface instance
(ge-0/0/0 unit 0 family inet address A;) is invisible to group merge:
a <*> group filter… (A03-03)`). Source claim `A03-03`
(claude-opus-5-5-review), validator run `research-work.AdQvt1jMKw`,
consensus MATERIAL (3-way). Lane branch: `fix/15032-campaign`, base
`origin/master` eb245eb186.

## Defect (present at base)

`interfaces { ge-0/0/0 unit 0 family inet address 10.0.0.1/24; }`
parses as one leaf whose Keys run is
`[ge-0/0/0 unit 0 family inet address 10.0.0.1/24]`. The compiler
already reads that packed leaf as the braced chain (#14436/#14442),
but group merge in `mergeNodes` (`pkg/config/ast_groups.go`) did not:

- **Wildcard leg:** the `<*>` arm requires `keysMatchWildcard` with
  equal key lengths and visited only non-leaf destinations (zone
  leaves excepted by `zoneLeafTakesWildcard9801`, #9801). The packed
  leaf (7 keys vs 1) never matched, so a `<*>` group's
  `unit 0 family inet filter input F1` was not bound — the interface
  forwarded unfiltered after a green strict commit.
- **Exact-name leg:** an exact-name group container
  (`ge-0/0/0 { unit 0 { family inet { address B; } } }`) found no
  same-keyed container (`sameKeyedContainers9802` sees containers
  only), was adopted beside the packed leaf, and
  `compileInterfaces`' last-wins `ifaces.Interfaces[ifName] = ifc`
  kept only the group twin — the inline address A was lost.

Both legs were measured RED on base: packed rows compiled
`[10.0.0.2/24]` (group only) / `filter=""` where their braced
controls compiled `[10.0.0.1/24 10.0.0.2/24]` / `filter="F1"`, and
the expanded tree held two `ge-0/0/0` nodes, one still a packed leaf.

## Fix

Promote the packed interface-instance leaf to its braced shape
before the two merge decisions, in the anchored files:

- New `pkg/config/group_merge_interface_packed_15032.go`:
  `interfacePackedLeaf15032` (direct child of `interfaces`, leaf with
  ≥2 keys, non-keyword/non-apply name, tail expands via
  `packedBodyChildren` under `schemaInterfaces.wildcard`) and
  `promoteInterfacePackedLeaf15032` (truncate Keys to the interface
  name with quote/bracket masks sliced, expanded body as children).
  A bare `ge-0/0/0;` has no tail and is not promoted; an
  unexpandable tail is left exactly as authored for downstream gates.
- `pkg/config/ast_groups.go`: in the wildcard arm, promote a packed
  interface leaf whose name matches the wildcard pattern before
  `keysMatchWildcard`; in the container arm, promote packed
  interface leaves in `dst` before `sameKeyedContainers9802` so an
  exact-name group container merges into the inline instance
  instead of twinning it. Promotions are recorded via
  `budget.notePromoted9855`.

NOT changed: zone promotion (#9801/#13112), routing-instance
handling (#9620 normalizes elided RIs before expansion on the
compile path; #9838 bare-leaf gate unchanged), the compiler's
last-wins assignment (now unreachable for this shape because the
twin is never created), and any non-interface packed leaf.

Docs: `pkg/config/README.md` bullet beside the #9801/#9831 group
expansion notes.

## Risk

- Behaviour delta is the fix itself: packed interface spellings now
  receive group content their braced spellings already received.
  Configs that relied on the packed spelling escaping a `<*>`
  filter group will now be filtered (the intended Junos outcome).
- Scope is deliberately narrow (`interfaces` direct children with a
  schema-expandable tail only), so no other hierarchy's group merge
  changes shape.
