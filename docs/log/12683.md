# #12683 — reject packed unit MAC without an inline peer

## Why

An interface unit written as a packed leaf (`unit 0 mac <address>`) has the
MAC override in the unit node's own `Keys`, not in `unit.Children`. The H10
gate only inspected children, so strict commits accepted an unsupported
static MAC promise and tolerant loads emitted no warning when no inline unit
container existed.

## What

Inspect the packed unit node's tail for the `mac` keyword, using the existing
H10 emitter so strict compile rejects and lenient compile warns. Keep the
braced-child check unchanged. Add a no-MAC control and strict/lenient
regressions for the peerless packed unit spelling.

## Validation

- RED: `go test ./pkg/config -run '^TestH10PackedUnitMACWithoutInlinePeerRejected$' -count=1 -v` failed before the fix because strict compile returned nil.
- Fail-on-revert: with only the H10 detector stashed, the same regression failed because strict compile returned nil. After restoring the detector, `go test ./pkg/config -run '^TestH10' -count=1 -v` passed all five H10 tests.
- `go vet ./pkg/config`, `go build ./...`, and scoped `gofmt -l` passed.
- Full package command `go test ./pkg/config -count=1 -timeout 60m` failed after 24m with pre-existing-looking failures in #8662 inventory, #10826 API-auth, #11312 routing-instance, #7484 coverage, and the schema spelling differential gate; these do not touch the H10 detector, but base attribution supplied by GLM R1 (identical pre-existing failures on base/head: #8662, #7484 gates).

## Risk

Only the previously undetected packed logical-unit MAC spelling changes behavior. Braced MAC handling and lenient-load semantics are unchanged.

- **Fold (GLM R1)**: mid-tail packed mac (`unit 0 vlan-id 5 mac ...`) escaped the first-position check; unified to a descendant rule + schema-guided packed-tail scan. `description mac` value false-positive cell added.
