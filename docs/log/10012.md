# #10012 — filter snapshot render claimed fall-through while runtime terminated

## Summary

- **Issue:** `buildFirewallFilterSnapshots` can preserve `Action != ""` and
  `NextTerm == true` on the tolerant load / peer-sync path. The Rust evaluator
  treats a real action as terminal (`continue_term = action.is_empty() &&
  routing_instance.is_empty()`), but `RenderFirewallFilterSnapshot` selected
  the `NextTerm` branch first and printed only `then next term
  (fall-through)`. The effective view therefore contradicted enforcement while
  enforcement itself remained fail-closed.
- **Context read:** Read the complete #10012 body and all comments with
  `gh issue view 10012 --comments` before editing. The issue was open and had
  no comments; there was no withdrawal, narrowing, shipped notice, or
  contradictory direction.
- **Decision:** Make the renderer use the same effective terminal predicate as
  the Rust evaluator: only an empty-action, empty-routing-instance term is a
  fall-through. A real action or routing-instance renders its terminating
  action. If `NextTerm` is also set on that terminating shape, the output adds
  `then next term (ignored — contradictory with terminating action)` so the
  tolerant input is disclosed without claiming that runtime falls through.
  This keeps the runtime/enforcement code unchanged and makes the operator
  surface truthful.
- **Files:** `pkg/dataplane/userspace/firewall_snapshot_render.go`,
  `pkg/dataplane/userspace/firewall_snapshot_render_10012_test.go`

## RED → GREEN proof

The issue regression selector is:

```text
go test ./pkg/dataplane/userspace -run 'TestSnapshotRender(ContradictoryActionNextTermTerminates10012|PureFallThroughControl10012|PureTerminalControl10012|ImplicitFallThroughWithoutBit10012|RoutingInstanceNextTermHandBuilt10012)$' -count=1
```

The issue cell compiles each contradictory term through
`ParseSetCommand` → `ConfigTree.SetPath` → `CompileConfigLenient`, verifies the
strict conflict was downgraded to a warning, then builds the effective
snapshot. The controls use the same snapshot builder for pure fall-through and
pure terminal terms.

- **Action + `next term` (discard, accept, reject, typed reject): RED before
  the fix.** All four subtests omitted the terminating action, printed the
  bare fall-through claim, and had no ignored-contradiction annotation. **GREEN
  after the fix:** all four render the action the runtime enforces, omit the
  bare fall-through claim, and annotate the ignored request.
- **Pure fall-through control: GREEN before and after.** Empty action plus
  `next_term` still renders `then next term (fall-through)` and its modifier,
  with no terminal or contradiction annotation.
- **Pure terminal control: GREEN before and after.** A real action without
  `next_term` still renders only its terminal action.
- **Empty action without the advisory bit: RED before the fix, GREEN after.**
  The Rust-compatible renderer now treats this older/hand-built snapshot as a
  fall-through instead of inventing a terminating accept.
- **Routing-instance plus `next_term` hand-built control: RED before the fix,
  GREEN after.** The renderer now mirrors the Rust routing-instance terminal
  decision and annotates the contradictory advisory bit.

The reverted renderer was restored immediately after the RED run. The final
selector passed with **5 top-level tests / 9 pass reports** (the contradictory
cell has four subtests).
