## ND-to-catalog semantics decision (pinned)

Catalog rule for BOTH view kinds: ND (133-136) to a catalog multicast group
requires an explicit ND positive (`ndp` token / `protocols all`) or
`any-service`; the bare ND default and an unknown view do NOT open it;
`ndp except` denies. Evidence: the kernel catalog guards precede the ND
accepts in both nft renderers (text `daemon_nft.go` multicast guards before
`emitHostInboundNDPAcceptsText`; netlink `emitHostInboundMulticastGuardsNetlink`
before `emitHostInboundICMPAcceptsNetlink`), so the kernel denies an
`ssh`-only zone's NS to `ff02::5` — the pre-fix Rust zone arm was the
outlier, and the override arm's `ndp_admits_multicast` already encoded the
kernel rule. Ordinary (non-catalog) ND is unaffected: `ff02::1` and
solicited-node groups are not in the catalog, and the #15671/#15931 ND
default (admit unless `ndp except`) is preserved verbatim there.

## Action

- Added `HostInboundPkt`, `ViewKind` and the single decision body
  `host_inbound_decide(view, kind, pkt)` in
  `userspace-dp/src/afxdp/forwarding/host_inbound.rs`: global-accept, then
  ND, then catalog multicast, then the set — written once.
  `is_ndp_type(` now occurs once in non-test `host_inbound.rs`.
- `host_inbound_admits` and `host_inbound_admits_for_destination` delegate
  with the zone view; `host_inbound_admits_iface_for_destination` (the
  production entry point) selects the override view when present, else
  the zone view, and delegates. The #3405/#5659/#6873 `None => true`
  rationale is preserved verbatim on the consolidated `None` arm.
- `host_inbound_admits_iface` is now `#[cfg(test)]`-only, delegating to
  `host_inbound_admits_iface_for_destination` with an explicit unicast
  destination (`2001:db8::1` / `192.0.2.1`), so the ~98 destination-less
  test cells exercise the production decision instead of a fourth body.
  It has no non-`cfg(test)` definition.
- Docs naming the dead function as the production path now name
  `host_inbound_admits_iface_for_destination`: `forwarding/README.md`
  (4 sites), `docs/junos-cli-reference.md:835`, `afxdp/README.md`,
  `poll_stages.rs` comment, `forwarding_build/interfaces.rs` comments,
  and the in-file comment at `host_inbound.rs:345`.
- New parity guard `ndp_zone_override_catalog_parity_17192`
  (`host_inbound_tests.rs`): a zone view and an override view with the
  same token set give the same verdict for ICMPv6 133-136 to `ff02::5`
  (denied for `ssh`-only, admitted with an explicit `ndp` positive,
  denied under `ndp except`), with unicast ND keeping the default on both.

## Risk

- One deliberate behaviour change, in the fail-closed direction: ND to a
  catalog multicast group through a ZONE view now requires an explicit
  `ndp` positive (or `any-service`), matching the override arm and the
  kernel chain. Zones relying on the old zone-arm ND default to a
  catalog group (e.g. an OSPFv3 zone without an `ndp` token receiving NS
  to `ff02::5`) lose that admit on the userspace path; it was already
  denied on the kernel path, so this removes a cross-surface
  inconsistency rather than opening a new one. Unicast and non-catalog
  ND (including `ff02::1` / solicited-node) are unchanged.
- All other verdicts are preserved by construction (single body, same
  order) and pinned by the named regression cells above.
