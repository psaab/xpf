# #12837 — inert-ALG advisory disagreed with the session tagger on aliases and global disable

`applicationALGHasDataplaneTag` (`pkg/config/compiler_application_alg_warn.go`) judged per-application ALG pins by literal protocol spelling only and without the global `security alg` state, so it disagreed with the userspace tagger (`userspace-dp/src/afxdp/bpf_map/publish_conntrack.rs alg_type_for_session`) in both directions:

- **False warning.** A pin like `protocol junos-tcp-any destination-port 21 alg ftp` drew a "no dataplane effect" warning even though `junos-tcp-any` resolves to TCP (6) in the appid SSOT (`appid.ProtocolNumber`) and the tagger stamps FTP on TCP/21. Same for `junos-udp-any` with DNS/53 and SIP/5060.
- **Suppressed warning.** `security alg ftp disable` makes the tagger stamp `ALG_TYPE_NONE` for every tuple of the ALG (the global `alg_disable_flags` bitfield is the only ALG signal on the wire), so `alg ftp destination-port 21 protocol tcp` under that knob is genuinely inert — yet the helper returned true and the commit stayed silent, leaving the operator unaware the knob nullified the pin.

The fix keeps the helper's "any tuple the tagger recognizes" contract (an omitted or range destination-port that spans the service port still counts as taggable — the research lane refuted marking those inert) and adds the two missing facts. Protocol resolution now mirrors the tcp/udp rows of `appid.ProtocolNumber` exactly (`tcp`, `junos-tcp-any`, canonical numeric 6; `udp`, `junos-udp-any`, 17) via `applicationALGProtocolNumber` — pkg/config cannot import the appid leaf package, so the mirror is documented at the helper. The global `ALGConfig` is now passed into `applicationALGHasDataplaneTag`, and `ALGDisabled` (the existing field-per-proto authority) makes a disabled ALG untaggable on every tuple. The warning wording distinguishes the two inertness causes: a taggable tuple inert solely because of its knob names `security alg <proto> disable`; a tuple outside the service set keeps the existing well-known-tuples message; TFTP is unchanged. Warn-only, no commit rejection and no dataplane change; the strict gates are untouched.

Validation: pre-fix at origin/master d56d03e5a the new tests are RED exactly on the two defect legs — `TestApplicationALG_CanonicalAliasProtocol_TaggedPin_StaysSilent_12837` (all 6 subtests show the false "no dataplane effect" warning) and `TestApplicationALG_GlobalDisable_WarnsNamingKnob_12837` (all 5 subtests show `warnings: []`); the two guard tests passed on master and still pass. Post-fix, the full `TestApplicationALG*` family passes including the #11673 suite (custom-port warn, well-known silent, TFTP always warns, unreferenced scope, unknown-name advisories). `go test ./pkg/appid/` and `go test ./pkg/dataplane/userspace/` pass. Full `go test ./pkg/config/` has 9 failures on this head — `TestFlatSetChainWalkRatchet8939`, `TestInventoryDropShapeMatchesTheLiveCensus8662`, `TestMultiLeafSelfRepeatIsRefused9027`, `TestLegitimatelyNamedObjectIsAccepted9029`, `TestElidedQuotedValueKeepsItsQuote8921`, `TestSystemConfigWebManagementEnhanced`, `TestSystemConfigSetSyntax`, `TestPackedRoutingInstanceSurvives8787`, `TestSlotEscapeCoverage` — all reproduced identically on a pristine origin/master d56d03e5a worktree (pre-existing, unrelated to this change). The Rust tagger contract this fix mirrors is pinned by `publish_conntrack::alg_type_tests` (11 tests, incl. `*_not_tagged_when_alg_disabled`) and `build_forwarding_state_carries_alg_disable_flags` in userspace-dp — both pass.

Risk: low — control-plane warning text only. The new warning appears only where the pin's ALG is globally disabled or the tuple was already untaggable; no previously-silent valid config loses a tag, and no warning-generating config goes silent except the alias false positives, which is the fix. Operators matching on the exact generic warning string for an alias-spelled pin will see it disappear (that is intended).
