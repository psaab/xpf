# #13682: keep deferred FIN/RST hits from sliding closing-session deadlines

- **Timestamp**: 2026-10-15
- **Action**: The #10636 close-deferring lookup now suppresses deadline refresh
  for deferred FIN/RST segments on an already-closing TCP entry. The lookup
  still lets ordinary packets from a non-FINed half refresh the half-close
  window; an Owner applies actual close progress after the authority verdict,
  while a foreign close segment is dropped without extending the deadline.
- **File(s)**: `userspace-dp/src/session/lookup.rs`,
  `userspace-dp/src/session/close_refresh_gate_10885_tests.rs`, this log.
- **Red-before**: `cargo test -p xpf-userspace-dp
  deferring_lookup_foreign_close_segments_do_not_slide_closing_13682`
  failed on the deferred RST: expected `last_seen_ns` 11,000,000,000 but
  observed 12,000,000,000. Reverting the refresh guard reproduced the same
  failure.
- **Green-after**: `cargo test -p xpf-userspace-dp --bin xpf-userspace-dp
  close_refresh_gate_10885_tests::` passed all 9 tests (1 suite, 8,031
  filtered out), including the foreign deferred-hit deadline regression,
  owner close-progress control, and inline half-close / TIME_WAIT parity tests.
- **Additional validation**: `cargo test -p xpf-userspace-dp` was attempted;
  the package run reported failure in
  `afxdp::tests_9950::f035_parked_fragment_overlap_is_rechecked_on_retry_10659`.
  The failure detail was not present in the captured output; no attribution is
  made here.

- **Follow-up**: Added an explicit owner-side regression showing that a
  deferred reverse FIN still advances a half-closed pair to TIME_WAIT after
  `apply_deferred_owner_close`, and corrected the API comment to distinguish
  ordinary-hit refresh from deferred close hits on already-closing entries.
  The expanded module passed with the explicit binary-target command above.
