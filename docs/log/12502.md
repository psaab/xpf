## Change

The public `ExpandAddressSet` contract remains unchanged: it preserves direct `address B` members as set-ID graph references, matching dataplane compilation. A new private leaf expander resolves those members through the referenced set for consumers that need literal addresses. Junos-host deny and static-NAT prefix-name use that helper; address-first handling is retained for same-name collisions. Existing cycle, depth, unknown-member, and deduplication behavior is preserved, and feed-taint traversal remains unchanged.

Regression coverage checks a referencing set sorting before and after the referenced set, direct `address` and nested `address-set` member shapes, junos-host deny kernel-rule output and rendered-key accounting, strict and lenient static-NAT prefix-name target population, and unknown-member rejection in both resolver paths.

## Risk

The host/NAT-only leaf-expansion helper deliberately does not alter the dataplane set-ID graph or the nat-off shadow caller's feed-bound set-name traversal. Strict commit rejects a same-name `address` and `address-set`. The lenient load path records the collision: junos-host deny then treats the name as unrepresentable, and static-NAT prefix-name resolves it as the address, as before this change. No live-cluster mutation was performed.
