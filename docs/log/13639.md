# #13639 — invalidate fail-closed denies on scheduler lease recovery

## Problem

During scheduler lease expiry, a scheduled PERMIT is suppressed. Traffic can
fall through to an unscheduled DENY, which the AF_XDP flow cache stores as a
`PolicyDenied` entry. When the heartbeat recovers, the old cache transition
only flushed on false-to-true expiry when scheduled DENY/REJECT rules existed;
it left the outage-generated deny live and blackholed traffic that should now
match the recovered permit. Separately, scheduled DENY/REJECT cache entries
were seeded during expiry only to be evicted on the next lookup, causing
seed-then-evict churn.

## Why / What

- On scheduler phase transitions, invalidate the cache whenever rule
  eligibility can change: expiry/recovery for scheduled PERMITs, and expiry
  for scheduled DENY/REJECTs. The phase flush remains transition-only.
- Do not seed a scheduled DENY/REJECT while the scheduler lease is expired;
  the slow path still enforces the deny and the cache no longer churns.
- Add a regression that evaluates a scheduled PERMIT plus unscheduled DENY
  under an expired lease, inserts the resulting fail-closed deny, recovers the
  heartbeat, and verifies the cold policy permits while the stale cache entry
  misses.

## Risk

A lease-phase transition evicts the entries whose verdicts can change: existing
whole-cache invalidation remains for expiry when scheduled DENY/REJECT rules
become eligible, while recovery removes cached `PolicyDenied` results so an
outage-generated fail-closed deny cannot survive a scheduled PERMIT becoming
eligible again. Unrelated forwarding cache entries remain intact on recovery.
Scheduled DENY/REJECT entries are not seeded while expired, avoiding
seed-then-evict churn. No wire or control-plane behavior changes.
