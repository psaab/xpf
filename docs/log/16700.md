# #16700 — HA sweep resends wipe per-app inactivity timeout and then-log flags

`publish_conntrack.rs` hard-coded `app_timeout: 0` / `log_flags: 0` in both
v4 and v6 BPF mirror rows, so the 15 s HA sweep (and bulk / promoted-standby
resends reading the mirror) stamped a newer generation carrying 0. The
standby helper then replaced the entry with `inactivity_timeout=None`
(global window, losing short timeouts and the 86401 `never` sentinel) and
no `then log` flags. Unlike #14359 policy identity these fields had no
send/receive memo.

Fix, two layers:

- Rust: `build_conntrack_value_v4/v6` now publish the real values from
  `SessionSyncAttribution::from_session` (ns→s, `u64::MAX` → 86401) and
  `log_session_init` (bit 0) / `log_session_close` (bit 1) /
  `fabric_ingress` (bit 7, Go `LogFlagUserspaceFabricIngress`).
- Go: extend the #14359 memo family with `appTimeoutLogMemo`
  (`pkg/cluster/sync_app_timeout_log_16700.go`) — four new bounded guard
  maps `appTimeoutLogSentV4/V6` + `appTimeoutLogRecvV4/V6` (now 28 families:
  16 sender + 12 receiver), keyed by tuple and matched on `SessionID`.
  Sender stamp restores on a 0/0 resend and falls back to the receive memo
  for a promoted standby; receiver install restores/records before the
  dataplane write. New incarnation and `SessionID==0` never inherit;
  delete, scoped delete, `takeDeleteGen`, and namespace reset evict.

Tests: Go `TestAppTimeoutLogSurvivesSweepAndReceiverV4/V6_16700`
(86401 never and 30 s round-trip, wire codec, stamp-less and promoted
resends) and `TestAppTimeoutLogNewIncarnationAndDelete16700`; Rust
`built_rows_carry_app_timeout_and_log_flags_16700` (v4+v6, never,
fabric bit). RED pre-fix: mirror rows carried 0 and swept frames lost
both fields.
