# #15056 — the #9615 refused-target rollback branch skips the #3868 peer re-sync (A32-03)

- **Timestamp**: 2026-10-18
- **Action**: `confirmRollbackTargetHandledAtFire` in
  `pkg/daemon/confirm_rollback_preflight_9615.go` now re-syncs the promoted
  rollback target to the cluster peer before `enterBootstrapMode`, mirroring
  the ordinary rollback's #3868 re-sync. The standby received the abandoned
  unconfirmed config (C2) via config-sync `SyncApply`, which arms no confirm
  timer, so it held C2 as its permanent active; the refused branch promoted
  the target locally and then relinquished the cluster (#6742 resigns every
  RG and stops comms), after which no push is possible — the nodes diverged
  (primary = reverted target in bootstrap, standby = C2) and a failover would
  serve the config the operator never confirmed, with no timer or alarm on
  the serving node. The peer-snapshot authorization is captured from the
  promoted target before the push (the same fresh token the ordinary re-sync
  obtains inside `pushCommittedConfigToPeer`), so a multi-zone target is
  still refused for an incapable peer at the queue boundary rather than
  silently narrowed there; an authorization or push failure is logged at
  error level naming #15056 instead of being dropped silently, since after
  bootstrap there is no channel left to retry on.
