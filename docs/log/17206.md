# Issue #17206 — VlanId decode-once contract bypassed at four builder sites

- **Issue:** `VlanId::try_from_snapshot` (negative → 0, >0x0fff → `InterfaceVlanOutOfRange`) is the documented single decoder, yet four later builder sites read the raw `i32` with their own rules: native VLAN rejected negatives and capped at 4094 then decoded again; mirror scope coerced with `u16::try_from(..).unwrap_or(0)`; the #16063 unit-ambiguity count keyed on the raw value; the #14334 VID-0 prune compared the raw value.
- **STEP-0 (defect live on origin/master `c4e12aafc3`):** verified in the worktree before editing — `interfaces.rs:1953` inline `native_vlan_id < 0 || > 4094` check followed by a redundant `VlanId::try_from_snapshot`; `interfaces.rs:394,406` `rows_by_key` keyed on `(bind_ifindex, iface.vlan_id)` raw; `interfaces.rs:2353,2375-2377` prune `iface.vlan_id == 0` / `u16::try_from(iface.vlan_id).ok()`; `mod.rs:1036` `u16::try_from(mirror.ingress_vlan_id).unwrap_or(0)`. Main loop (`interfaces.rs:1988`) and native-unit match (`:2295`) already decoded via `VlanId`.

## What

1. `validated.rs`: added `RowIds { vlan: VlanId, native_vlan: Option<VlanId> }` with `RowIds::try_from_row(iface)` — the single per-row decode (negative native → `None`, 0 → `None`). `VlanId` now derives `Hash, PartialOrd, Ord` so it can key the ambiguity count directly. Fixed the stale `VlanId` rustdoc range (0..=65535 → 0..=4095).
2. `interfaces.rs`: `ingress_unit_by_logical` now returns `Result<_, SnapshotIntegrityError>` and keys `rows_by_key` on the decoded `VlanId` (−1 and 0 count as the same VLAN); native pass reads `RowIds` (inline 4094 check deleted — 4095 now follows the decoder verdict, >4095 fails closed); main loop and native-unit match read `RowIds::try_from_row(...).vlan`; VID-0 prune compares the decoded `row_vlan` (`Some(row_vlan)` instead of `u16::try_from(..).ok()`).
3. `mod.rs`: `ingress_unit_by_logical` call now propagates `?`; unit-scoped mirror decodes `mirror.ingress_vlan_id` via `VlanId::try_from_snapshot(.., &ingress_ifindex.to_string())?` and fails closed (`InterfaceVlanOutOfRange`) instead of silently re-pointing at the untagged scope. Negative mirror VID still decodes to 0 (untagged), preserving valid-path semantics. Reused the existing error variant — no new variant, so no wire/error-format change beyond the stale range text.
4. `policy_snapshot_error.rs`: updated stale `InterfaceVlanOutOfRange` docs/display from `0..=65535` to `0..=4095` (the #8597 bound already enforced by the decoder).
5. `forwarding_build/tests.rs`: new hermetic parity cell `vlan_decode_once_parity_17206` — mirror 4097 fails closed with `InterfaceVlanOutOfRange{4097}`, mirror −1 keys the untagged scope `(11,0,0)`, native 4095 builds, native 4097 fails with the raw value, native −1 builds, and the ambiguity count treats −1/0 as one VLAN (both rows excluded) with distinct-VID controls admitted.
