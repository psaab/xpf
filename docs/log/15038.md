# #15038 — RG ip-monitoring on the secondary: unsendable probe held the RG ownerless (A21-01)

## Defect

`chassis cluster redundancy-group N ip-monitoring` probes ran on both
cluster nodes from an unbound ICMP socket (`icmp.ListenPacket("udp4",
"0.0.0.0")`). The addresses a probe must egress through on a RETH subnet
exist only as VIPs on the primary (`vrrp.RethVIPsForRG` →
`daemon.directAddVIPs`, primary only). On the secondary the probe could
not be sent from an address the node holds, the send failed, and
`Monitor.probeICMP` reported that `WriteTo` error as a **completed**
failure (`return false, ctx.Err() == nil`). The dampener marked the
target down, `reconcileRGIPDebts` installed the full ip-monitoring debt,
and the secondary was held at weight 0. On primary loss — and at cold
boot, where the same applied before either node owned the RG — election
(`localWeight <= 0 → secondary`) left the RG owned by **neither** node:
the HA protection ip-monitoring was configured to provide removed the
owner it was meant to protect.

There was also no config model for the Junos probe binding: a target
carried only `address` + `weight`, so `interface <unit>` /
`secondary-ip-address <addr>` could not even be expressed.

## Fix

- `pkg/config` (`types_chassis.go`, `compiler_system.go`,
  `schema_chassis.go`): `IPMonitorTarget` gains `Interface` and
  `SecondaryIPAddress`, compiled from both spellings (block children and
  packed inline keys; `monitorEntryNodes` now reserves the value slots of
  `interface`/`secondary-ip-address` alongside `weight` so a packed
  target no longer shreds into phantom entries). Schema leaves added
  under `family inet <addr>`.
- `pkg/config/reth_vips.go` + `pkg/vrrp/vrrp.go`: the RETH VIP derivation
  moves to `Config.RethVIPsForRG` (vrrp keeps a delegating wrapper; vrrp
  imports cluster, so cluster cannot import vrrp) — one derivation shared
  by VIP installation and probe-source resolution.
- `pkg/cluster/monitor.go`:
  - Per-cycle probe tasks carry the resolved `(src, device)`: primary →
    the RG's VIP on the target interface, secondary →
    `secondary-ip-address`; unconfigured targets stay unbound (legacy).
    `Monitor.SetConfig` (via `Manager.SetMonitorConfig`, wired in
    `daemon_apply_tail.go` / `daemon_run_bringup.go`) supplies the full
    config for resolution.
  - The probe socket binds to `src` (`icmp.ListenPacket(network, src)`);
    a dial/bind failure is **not completed**. A `WriteTo` failure on a
    non-primary is **not completed**; on the primary it remains a
    completed failure. Not-completed probes leave dampening untouched —
    the same failover-neutral treatment as a cycle-deadline abort.
  - Production socket note: `x/net/icmp` exposes no socket-option hook
    for its SOCK_DGRAM ping socket, so `SO_BINDTODEVICE` cannot be
    applied post-creation; the source bind is the enforceable pin (an
    unheld source fails the dial → not-completed, and the kernel egresses
    via the source's interface). The device is resolved and carried
    through the probe seam regardless.

## Regression tests

- `pkg/cluster/ip_monitor_secondary_15038_test.go`:
  - `TestIPMonitorSecondaryUnsendableProbeNotCompleted_15038` — real
    `probeICMP` path with a failing-write socket on the secondary:
    weight stays 255, no `MonitorFails`. RED on master (weight → 0).
  - `TestIPMonitorPrimarySendFailureStillFails_15038` — control: the
    same send failure on the primary still demotes to weight 0.
  - `TestIPMonitorTwoManagerColdBootAndSurvivor_15038` — the issue's
    acceptance shape: two managers, reachability = "node holds the VIP";
    exactly one primary at cold boot, survivor promotes after peer loss.
- `pkg/config/ip_monitor_probe_binding_15038_test.go`:
  `interface`/`secondary-ip-address` compile in block and packed
  spellings. RED on master (fields did not exist; packed form shredded).

Existing monitor suites (#5271 global-threshold, #5301 parallel sweep,
#6550 race, probe reply validation) migrated to the extended probe seams
unchanged in semantics.

## Validation

- `go vet ./pkg/cluster/ ./pkg/config/ ./pkg/vrrp/ ./pkg/daemon/` clean;
  `gofmt` clean on all touched files.
- New #15038 tests pass; RED verified by construction on master (config
  fields absent — compile failure; secondary weight → 0 with the
  pre-fix completed-failure classification, reproduced in a scratch
  probe before the role pin was understood).
- Cluster monitor suites (`TestMonitor*|TestProbeICMP*|TestIPMonitor*`)
  pass, including #5271/#5301/#6550 controls.
- Full `pkg/cluster` suite: one failure,
  `TestInstallTableProducerToResendEndToEnd9752` — confirmed failing
  identically on clean `origin/master` (base-attributed, unrelated
  session-golden drift).

## Risk

- Behaviour change is scoped to bound targets and to non-primary send
  failures. Unbound (legacy) targets keep the previous completed-failure
  semantics except that a socket-open failure now holds state instead of
  demoting (failover-neutral, matching the RPM `ErrProbeSetup` doctrine).
- Lab verification (real RETH failover with ip-monitoring configured)
  remains the outstanding external check.
