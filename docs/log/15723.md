# #15723 — `show route` dispatchers silently widen dangling selectors, unknown subcommands and trailing filters to full-table dumps

- **Timestamp**: 2026-10-19
- **Action**: Both `show route` dispatchers (local `pkg/cli/cli_show_routing.go:handleShowRoute`, remote `cmd/cli/show.go:handleShow` `case "route"`) are now exact-arity against one usage grammar (`showRouteUsage`, duplicated verbatim in the remote binary which cannot import the local CLI package):
  - Bare `show route` still renders the full table.
  - `table`/`instance`/`protocol` require exactly one value; a dangling selector (`show route table`, `show route instance`, `show route protocol`) errors with the usage string instead of falling through to `showRoutes()`.
  - `terse`/`summary`/`detail`/`fib` require no trailing token; `show route terse junk` (and siblings) error instead of running the named view and dropping the junk.
  - `instance <name>`/`table <name>`/`protocol <name>` reject any trailing token (`show route table inet.0 protocol bgp`, `show route instance blue junk`, …) instead of running the scoped view and dropping it — the anchored-deny bypass shape documented in `pkg/cmdtree/README.md` for this dispatcher.
  - A destination (`/`/`.`/`:` heuristic, unchanged) accepts at most one modifier from `exact|longer|orlonger`; an unknown modifier (`show route 10.0.0.0/24 bogus`) or junk after a valid one (`… exact junk`, `… exact longer`) errors instead of running the prefix view with an empty/duplicated modifier.
  - Any other first token (`show route bogusword`) errors instead of dumping the full table. A plain host/prefix word without `/`/`.`/`:` was never a valid destination spelling, so no previously-rendering form changes; valid `table`/`instance`/`protocol`/`prefix`/`terse`/`summary`/`detail`/`fib` forms render exactly as before (remote topics unchanged: `route-all`, `route-terse`, `route-detail`, `route-summary`, `route-fib`, `route-table:<name>`, `route-protocol:<name>`, `route-instance` + filter, `route-prefix:<dest>[ <modifier>]`).
  - Scope note: #14687 already made `Canonicalize` refuse the dangling forms for restricted login classes; this closes the dispatcher half for unrestricted classes (and for the remote binary, whose `handleShow` receives the line without the local gate). No cmdtree, gRPC topic, or `pkg/grpcapi` server change: the gRPC `route-prefix:` server parser already only honours a trailing `exact|longer|orlonger` word, and the remote client no longer emits a topic for a rejected line, so no ShowText RPC is issued for malformed input.

GREEN after the fix; valid-form controls (including bare, `exact`/`longer`/`orlonger`, bare-IP LPM) still render / issue exactly one expected topic, and rejected remote forms issue zero ShowText calls.

Abbreviated subcommand spellings were never resolved by either dispatcher (exact string match both before and after), so no abbreviation behaviour changes. Read-only surface only; no config, dataplane, or wire change.
