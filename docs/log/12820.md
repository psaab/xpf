# #12820 — fold nested and peeled policy containers

- **Timestamp**: 2026-10-13 (`fix/12820-campaign-pub`)

## Why

The lenient duplicate-policy fold and direct terminal-action scan inspected only a `from-zone` node and its immediate children. In the supported `from-zone { A { to-zone { B { ... } } } }` shape, policy instances sit deeper under source and destination containers; peeled `policy { p { ... } }` nodes add another keyless level. A deny-to-permit duplicate could therefore escape widening quarantine, and conflicting terminal actions could remain unpoisoned on tolerant compilation.

## What

- Traverse supported nested source/destination containers to the actual zone-pair policy node, preserving zone names when recording conflicts and widening.
- Recognize peeled policy instances in duplicate folding and direct terminal-action conflict checks. Keep folding scoped to policy containers and preserve first-instance ordering.
- Add tolerant regressions for three-level zone containers, peeled policy containers, terminal conflicts, deny-to-permit widening, and safe non-widening controls. Strict validation and unrelated container families are unchanged.
