## Why

The previous RETH placeholder `169.254.<rg>.<node+1>/32` omitted cluster identity. Clusters sharing a WAN L2 segment could therefore configure the same address for a given redundancy group and node, and contend for its ARP/ACD ownership.

## What changed

Added `config.RethPlaceholderAddress` beside `StableRethLinkLocal`, formatting `169.254.<cluster-id>.<rg*2+node+1>/32`, and used it at all three existing networkd emission sites: tagged RETH unit, non-VLAN RETH member, and an addressed untagged unit's VLAN parent. Updated affected expected addresses and current explanatory docs/comments.

The existing `isVRRPReth` guard is unchanged and remains election-mode agnostic. The regression test covers the same three emitters for clusters 22/23 and nodes 0/1, plus both `no-reth-vrrp` and `private-rg-election` modes to pin their existing emission behavior. `ClusterID==0` formats `.0.<rg*2+node+1>` but is not a uniqueness scope: Junos defines zero as clustering disabled. A helper call with no cluster identity makes no uniqueness claim; with no cluster stanza, the current `isVRRPReth` guard emits no placeholder.
The `cluster-id 0` admission policy (strict rejection versus another collision-free scope) is tracked separately in #19012; #18628 intentionally preserves the formatter behavior and makes no uniqueness claim.
