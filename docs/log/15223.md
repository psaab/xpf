## Red before

New tests in `vrf_device_reassert_15223_test.go` failed on `origin/master`
(8c05fba011): with `vrf-mgmt` absent, one `reassertMgmtVRFOnce` tick made
no LinkAdd/LinkSetMaster (`adds=[] binds=[]`); with `vrf-blue` absent,
`rebindRIMembersOutsideTheirVRF` likewise created and bound nothing; and
the fabric bind pass bound nothing when `vrf-mgmt` was absent. All three

(no published management set) passed before and after.

## Change

- New shared helpers in `vrf_device_reassert_15223.go`:
  `vrfDeviceMissing` (one lookup) and `ensureVRFDeviceForReassert`, which
  re-creates one desired device via the single-VRF `CreateVRF` — never a
  full `ReconcileVRFs`, so no other VRF can be reaped — and verifies the
  device is present and a real VRF afterwards. A same-name foreign
  (non-VRF) link is refused, never adopted or deleted (#12062).
- Mgmt (#11448 loop): a non-empty published set with an absent `vrf-mgmt`
  now opens the tick; under `applySem` the device is re-created (mgmt,
  table 999) and drift is re-derived so present members (e.g. em0/fxp0)
  bind against the new index in the same tick, followed by the existing
  route refresh / transport reconcile. No published set → no creation.
- Fabric (#9813): a missing `vrf-mgmt` counts as "outside" for a present
  published overlay; `bindFabricOverlayToMgmtVRF` re-creates the device
  before binding. A foreign occupant never counts as outside and is never
  bound into. This also covers the deferred `OnXSKBound` creator, which
  binds through the same function.
- Tenant RI (#9813 loop): `riMembersOutsideTheirVRF` emits present members
  with `needsDevice` (+ table ID) when their instance device is absent
  instead of skipping the instance; `rebindRIMembersOutsideTheirVRF`
  re-creates the device once per instance, then binds. Conflict,
  management-class, tunnel-stanza, and multi-claim skips are unchanged
  and still evaluated before the bind. A foreign occupant skips the
  instance entirely, as before in effect (previously via the failed
  type-blind skip; now explicitly).

NOT changed: `ReconcileVRFs` and the apply path (apply already re-creates
desired devices); no new loop, cadence, or debt latch — a failed
re-create is logged and retried by the same 30s tick, matching the
existing bind-failure contract.

## Risk

Bounded to the cited mechanism. Healthy ticks add at most the device
lookups the gates already performed; no bind or create writes occur when
the device is present and members are enslaved. A VRF device removed
from config is never re-created: mgmt requires the published set (cleared
when vrf-mgmt leaves the config), tenant requires a configured
non-forwarding instance, and fabric requires the published set. Cluster
transport and management-route refresh reuse the existing post-bind
pass, so a re-created vrf-mgmt also re-converges cluster sockets via the
established #12168 path.
