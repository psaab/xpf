## Fold (Opus MATERIAL on #16320)

The LocalDelivery RST collection ran before the host-inbound/lo0/
junos-host gates and without any authority check, so a FOREIGN
arrival's RST could queue a teardown deleting another actor's
session. The collection is now gated on `may_revoke` (the same
authority the deny branches require). New cell
`foreign_rst_cannot_invalidate_host_bound_session_15947`: a dmz RST
hits lan's host-bound session but queues no teardown and the
session survives; the owner (lan) RST queues exactly one.

## Fold 2 (Opus on #16320)

(1) The RST teardown handed the pair helper the caller's forward key
even when only the reverse companion survived, so the teardown ran
under a dead key. It now resolves the canonical entry and passes that
entry's own key/decision; for a reverse-only survivor it additionally
releases the forward flow's NAT reservation (allocator key rebuilt
byte-identically to the reserve: forward SessionKey + forward
decision, untracked release) and emits the single forward Close from
the survivor's pre-teardown snapshot. New cell
`rst_teardown_reverse_only_survivor_15947` (forward removed, pool
port freed, one forward Close with aggregated counters).
(2) The selected Prebuilt mirror was copied twice (staged snapshot +
a second to_vec). The snapshot is now the only copy; commit's
fallback slice is empty (consulted only when unselected/oversize,
where the outcome is unchanged).

## Fold 3 (Opus on #16320)

The reverse-only release reconstructed the forward NAT with the
derived forward tuple, so rewrite_src became the server IP instead
of the pool address and the release missed the record. It now
un-reverses with the canonical reverse entry's tuple in natural
order (original_dst = the reverse dst IS the recorded pool tuple),
pinned by a debug_assert that the reconstructed NAT equals the
forward decision. The fixture's forward half leaves via plain
delete (silent), so the reverse-only teardown asserts the pool
release and no synthetic Close.

## Fold 4 (Opus fold-3 ledger)

(1) The reverse-only compensating release is structurally
idempotent: it runs only when canonical resolved to the reverse
entry (forward already gone before the teardown), so no forward
half existed for the pair teardown to release — the
persistent-inbound lease hold drops exactly once (and the
allocator saturates at zero regardless).
(2) The reconstruction debug_assert is restricted to the
source-NAT shape (`decision.nat.rewrite_src.is_some()`); a valid
reverse entry with no source rewrite no longer trips it.
