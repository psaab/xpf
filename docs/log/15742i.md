## Root cause

Helper snapshot `/run/xpf/userspace-dp.json` on BOTH nodes:
`snapshot.policies == []` while `snapshot.summary.policy_count == 2`
and the embedded `snapshot.config.Security.Policies` carries both
allow-all rules. The Rust helper therefore enforces
default_policy=deny with an empty rule set.

Producer: `pkg/dataplane/userspace/builder.go`
`buildSnapshotWithSchedulerStateAndNATCountersAndFailClosedProvider`
computes `policies` (line 218) and uses it for
`Summary.PolicyCount` (line 324, hence 2), but commit 670274c712
(#15707/#15890, in deployed 8775942820) replaced the literal field
`Policies: policies` with `NoIPv6RejectZeroHopLimit: ...` and never
re-added Policies. Nothing else assigns snap.Policies on the full
Compile path; partial republishes
(`rebuildScheduledPolicySectionsLocked`, manager_compile.go:1132)
do, which masked the defect until the next full Compile/restart —
the 00:08:43Z ISSU restart was that Compile. `git log -S` confirms
670274c712 is the only commit removing the assignment, and it is an
ancestor of the deployed build.

This also re-frames the split-RG rounds: any node whose last full
Compile post-dates 670274c712 enforces empty policies, so split
transit (and co-located transit after a restart) blackholes at the
policy stage before the #15742 fabric-redirect/seed machinery is
ever reached. The fabric layers fixed in #15744–#15906 remain
necessary but were not sufficient while the policy set was empty.

## Fix
