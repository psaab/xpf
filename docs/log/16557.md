# #16557: widen security-zone ids from u16 to u32

- **Timestamp**: 2026-10-25
- **Problem**: Security-zone ids were a 16-bit FNV name-hash fold, so
  valid pairs such as vlan163+vlan364 (both 51948) and
  zone109+zone237 (both 9074) hard-failed strict commit, with ~12%
  birthday collision probability at only 128 zones.
- **Fix**: `config.StableZoneID` widened to a 32-bit fold
  `[1, 4294967293]` (sentinels at `u32::MAX-1/MAX`), mirrored across
  the Rust dataplane (ZoneSnapshot.id, u64 zone-pair keys, reserved
  constants), Go compile/apply maps, snapshot/status/counter wires,
  and every display/HA consumer. Ids remain a pure function of the
  zone name. Strict collision gate and lenient quarantine retained
  for the now-rare residual u32 collision. Frozen u16
  session/event/HA/BPF records carry the low 16 bits of the id; all
  consumers key explicitly by that truncation (never a silent skip).
  Dense counter slot maps treat ids >65535 as overflow/uncounted.
  PolicyRenameAncestry zone ids widened to u32. Zone-quarantine test
  premises migrate to the residual u32 pair zzq17760/zzq8100; new
  TestZoneID16557* acceptance tests.
- **Rebase (2026-10-25)**: rebased `fix-16557` onto current
  `origin/master` (267 commits). Two content conflicts resolved:
  `debian/changelog` (kept both master entries and the #16557 entry)
  and `pkg/daemon/daemon_flowexport_sampling_interface_15230_test.go`
  (kept master's #16742 close-time-fallback semantics with the u32
  truncation cast). Semantic (non-textual) conflicts in master-side
  test files added since the original branch point were also fixed:
  stale u16 `SetZone`/`SetZoneConfig` fakes, `map[string]uint16`
  ZoneIDs literals, a `map[string]uint16` type assertion, flowexport
  helpers passing u32 zone ids to u16 frozen-record builders, and
  Rust `push_delta_lossless_within_seq` still taking
  `FxHashMap<String, u16>` while `encode_delta_frame` takes u32.
- **Validation**: `go vet ./pkg/... ./cmd/...` clean; `cargo check`
  clean for userspace-dp; `TestZoneID16557*` pass (former pairs
  commit, stability across unrelated add/remove, residual gate).
  Targeted Go zone/quarantine/rename suites pass; Rust
  zone/zone-pair/flood/zone-counter/cold-path subset 124 passed
  (pre-rebase). Wider `pkg/config -run Zone` failures reproduce on
  master (pre-existing #14139/#15034 fixture drift, zone-unrelated).
- **Risk**: Ids above 65535 are policy-exact in the dataplane but
  lose exact attribution on u16 session/event/fabric records
  (low-16-bit aliasing, fail-closed, never merged in policy
  evaluation) and are uncounted by dense counter slots; widening
  those records is a separate flag-day.
