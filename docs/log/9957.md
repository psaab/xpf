## Fix

`userspace-dp/src/afxdp/frame/mod.rs:417-446` now says the reverse non-first
builder is production-unreachable as of the census SHA. It no longer claims a
reverse consult supplies the value, and records the exact expiry condition:
the first production NAT64 association install passing `reverse: Some(..)` must
be paired with enabling the AF_INET reverse consult (or equivalent reverse-info
threading onto a flowless request), and must replace this pin with live-builder
coverage.
`userspace-dp/src/afxdp/tests_nat64_tunnel.rs:1165-1369` adds
`nat64_reverse_nonfirst_reply_fragment_is_not_translated_9957`. The test drives
a committed NAT64 forward fragment and a live reverse session-hit first
fragment, asserts the forward NAT64 association has `reverse: None`, then
checks that the AF_INET reverse first fragment does not create a second
association. It sends the same datagram's flowless reverse non-first fragment
and asserts zero NAT64 translations and zero TX. The helper gives each IPv4
fragment a 24-byte payload and uses offset 3 for the non-first fragment, so the
pair is disjoint and reaches the unassociated-fragment path without an overlap
tracker drop. The direct association lookup pin fails if the production NAT64
install starts carrying reverse info; the reverse-key pin fails if an AF_INET
reverse association becomes reachable. The existing direct-`Some` translator
test continues to cover the low-level builder itself.

`userspace-dp/tests/frag_assoc_reverse_unreachable_9957.rs` adds an additional
lexical tripwire. It scans production Rust sources (excluding test-named files
and comment-only lines), pins exactly the two `FragAssoc::install` callers to
a positional third argument of `None`, and pins both tree-wide lookup sites
to `_reverse` while asserting all four remain in `afxdp/poll_descriptor/frag_assoc.rs`.
Parser self-tests cover the listed multiline receivers and local aliases; this
guard supplements the end-to-end runtime regression.
