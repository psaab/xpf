# Issue #15258 — never-match commit-gate completeness cohort (A89-01, A89-02, A89-05)

## A89-01 — `is-fragment` disjoint from every L4 predicate

Since #14631, `is-fragment` matches only trailing fragments (offset != 0),
which carry no L4 header: ports fail on `is_fragment && !l4_present`
(`matching.rs` port_terms_match) and tcp-flags/icmp require `l4_present`
(`per_packet_l4_matches`). The #14445 never-match gate (Go strict +
Rust `check_cross_field_satisfiability`) never read `is_fragment`, so
`is-fragment; destination-port 80` (and tcp-flags / icmp-type/code, with
or without a protocol) committed as a silent never-match discard.

- Go: `validateFilterCrossFieldStrict` now strict-rejects `IsFragment`
  combined with ports/except, TCPFlags, or ICMPTypes/ICMPCodes, naming
  both predicates (lenient path warns via the existing cross-field
  downgrade, #1960). `is-fragment` alone and `is-fragment; protocol tcp`
  still commit.
- Rust: `check_cross_field_satisfiability` fails the snapshot closed
  with predicate `is-fragment+l4` for the same combined shape.
- The pre-existing `TestFilterEnforcedFromLeavesAccepted_3307` fixture
  combined `is-fragment` with `destination-port 22` in one term — now a
  genuine #15258 never-match — so `is-fragment` moved to its own term
  there (still exercising the enforced-leaf acceptance).

## A89-02 — sync-hold backstop lasted one reconcile tick

The #14406 `handleClusterEvent` early return drops a queued Primary
event without recording clusterPri, but its comment claiming
"reconcile keeps desired inactive" was false: `reconcileRGState`
re-derives clusterPri from `cluster.IsLocalPrimary` (already set by the
election) and fed it to `s.Reconcile`, writing `rg_active=true` within
one tick (daemon RED: 2 writes [true true] while held).

- `rgStateMachine` gains a `syncHold` term mirroring the #14404
  kernel-upgrade hold: while set, `reconcileLocked` forces
  desired=false and `CheckVRRPPosture` stays silent.
- `Daemon.syncRGSyncHold` mirrors `vrrpMgr.InSyncHold()` onto every RG
  state (called at the top of every `reconcileRGState` pass and of
  `handleClusterEvent`); `getOrCreateRGState` seeds new states with the
  current hold. Event and reconcile now share one predicate; after
  `ReleaseSyncHold` the next reconcile/event re-derives promotion from
  retained cluster/VRRP inputs. The stale comment is corrected.
- NOT changed: the load-bearing readiness gate and VRRP-force gate
  (#14406) are untouched; no-RETH modes arm no VRRP sync-hold, so the
  mirror is a no-op there (their #7162 hold is separate).

## A89-05 — pool-less interface-egress owners vanished

`natPoolOverlapOwners` returned nil when `len(pools)==0`, before the
interface-egress owners were appended. A port-mapped static on an
interface-SNAT egress address (which interface SNAT can mint, #14368)
was therefore accepted without pools and rejected once any unrelated
pool was added. Contract chosen: build interface owners regardless of
pools (the #14368 pairing already includes port-mapped statics against
minting allocators; the Rust runtime arm already reserves interface
egress via `sync_interface_overlap_peers`). The early return is
removed; pool-backed enumeration below is unchanged (nil-pool lookups
are already guarded). Whole-address statics stay rejected in both
shapes by the untouched #6751 §5.7 gate.

## Risk

- Configs carrying `is-fragment` + an L4 predicate now fail strict
  commit (they never matched; Junos accepts-and-never-matches the same
  term). Lenient load/peer-sync still boots with a warning (#1960).
- Port-mapped statics on interface-SNAT egress addresses now reject at
  strict commit even on pool-less configs — the already-documented
  #14368 collision, made pool-count-independent.
- The sync-hold mirror only suppresses activation while
  `InSyncHold()`; it releases with the existing bounded hold (bulk sync
  or its 30s timer), so no new unbounded block is introduced (#110).
