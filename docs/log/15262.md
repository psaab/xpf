# Issue #15262 — ha: fabric-auth rollout-grace restart residual (B04-02)

## Why

- **B04-02:** The #11676 fabric rollout grace was anchored at the
  in-memory no-key -> key transition in `Manager.UpdateConfig`
  (`pkg/cluster/group_state.go`): `wasKeyConfigured` is false for every
  fresh `Manager`, so every xpfd restart of a long-keyed node stamped
  `controlAuthKeyConfiguredAt = time.Now()` and re-opened up to 5 minutes
  of tokenless read-only fabric RPCs (`GetSessions`, `GetSessionSummary`,
  `GetZonePairSummary`, `MonitorInterface`, safe `ShowText`) until the
  peer next authenticated and armed enforcement. Read-only disclosure
  (session table, interface monitor, safe show text) to on-segment
  hosts, recurring deterministically on every daemon start.

## What

- `pkg/cluster/fabric_auth_grace.go` (new): persists the first-keyed
  instant per accepted-key-set digest in durable node state at
  `/var/lib/xpf/fabric-auth-grace` (same root as the HA boot epoch),
  as `<first-keyed unix-nanos> <digest>`. The digest is
  HMAC-SHA256(domain tag) keyed by each accepted key, concatenated
  (signing slot then additional slot); it holds no key bytes and is
  domain-separated from every other PSK-derived value. Load never
  creates the file; a missing/corrupt/future-dated/mismatched record
  yields no anchor. Persist goes through `fsatomic.WriteFileDurable`
  and is best-effort with a warning — a failed write must not fail a
  config apply.
- `pkg/cluster/group_state.go` (`UpdateConfig`): the anchor is now the
  first keying of the CURRENT accepted set. On a digest change (or no
  in-memory anchor) it takes the earliest of `now` and a persisted
  anchor for that digest, and persists only when it stamps `now`. An
  unchanged set (including every restart re-apply) keeps its anchor;
  clearing the set clears the anchor/digest. A backwards-stepped clock
  sees the persisted stamp as future-dated, distrusts it, and
  re-anchors to local `now` — that only shortens the grace versus true
  first keying (fail-closed), never extends it.
- `pkg/cluster/manager.go`: `controlAuthKeySetDigest` field alongside
  `controlAuthKeyConfiguredAt`; accessor doc updated to first-keyed
  semantics.
- `pkg/grpcapi/fabric_auth.go` + `README.md`: the grace is now described
  as starting at the first keying of the current accepted-key set,
  restored across restarts (#15262). No change to the 5-minute length,
  the read-only method set, the arming sources, or the expiry/alarm
  behaviour — only the anchor's lifetime changed.
- Test seam `cluster.SetFabricAuthGraceStatePathForTesting` (mirrors
  the `bootEpochPath` redirection pattern) plus a pinned
  `fabricAuthGraceNow` for cluster tests.

NOT changed: `fabricAuthUnarmedGrace` (5 min), `fabricAuthGraceAllowed`,
the unkeyed GetStatus-only posture (#10698), heartbeat auth, and the
boot-epoch store. No new file is created on unkeyed nodes (persist only
runs on a keyed first-keying).

## Tests

- `pkg/grpcapi/fabric_auth_15262_test.go` — through the real fabric
  unary interceptor with a real `cluster.Manager`:
  - `TestFabricAuth15262_RestartUnderUnchangedKeyDeniesAfterGrace`: a
    second Manager (simulated restart) over the same anchor file keeps
    the first-keyed time, and tokenless `GetSessions` past
    first-keyed+5 min is `Unauthenticated` with no handler call.
  - `TestFabricAuth15262_RestartWithinGraceKeepsRemainingGrace`:
    inside the remaining grace after restart the call is admitted; at
    first-keyed expiry it is denied.
  - `TestFabricAuth15262_NewKeyAfterRestartGetsGrace`: restart under a
    different key re-anchors and admits inside the new grace.
  - `TestFabricAuth15262_KeyFingerprintChangeInPlaceGetsGrace`:
    in-place rotation re-anchors, unchanged re-apply does not, clear

  - `TestFabricAuth15262_UnkeyedWritesNoGraceState`.

## Validation

- RED: `go test ./pkg/grpcapi/ -run TestFabricAuth15262` on
  `origin/master` fails to build — `cluster.SetFabricAuthGraceStatePathForTesting`
  is undefined; the restart behaviour it pins does not exist (the
  process-local anchor re-stamps on every new Manager).
- GREEN: targeted `pkg/grpcapi` (#15262 + #11676) and `pkg/cluster`
  anchor/UpdateConfig/rotation tests pass (see PR).

## Risk

- Residual: a node whose `/var/lib/xpf` is wiped (or whose anchor write
  keeps failing) re-anchors at its next keyed apply — indistinguishable
  from a genuinely new keying without a stronger file identity. The
  persist failure is logged at Warn naming exactly that consequence.
- Rotation steps that change the accepted set (adding or retiring the
  additional key) each get a fresh 5-minute read-only grace, as before
  for any in-process set change; the heartbeat/fabric arming sources
  still close the window as soon as the peer authenticates.
