# 14399 — IS-IS `authentication-type` without `authentication-key` renders unauthenticated

- **Timestamp**: 2026-10-17
- **Action**: Added the reverse of the #9105 gate for IS-IS. New
  `validateISISAuthTypeRequiresKeyStrict`
  (`pkg/config/compiler_validate_strict_isis_auth_type_14399.go`) rejects,
  on strict compile, a non-absent IS-IS `authentication-type` with an empty
  `authentication-key` at the global (area/domain) level, per interface,
  and in routing instances (same `compileProtocols`/`generateProtocols`);
  tolerant paths warn via `lenientISISAuthTypeRequiresKey14399` (#1960).
  Wired beside the #9105 call in `runUniformGatesLogFeedRouting`. FRR
  renderer belts at both IS-IS sites in `pkg/frr/protocols_render.go`
  `slog.Warn` on type-without-key; `generateProtocols` returns only a
  string, so the spec's "fail the apply closed" belt is not realizable
  without an error-return refactor — the compile gate is the enforcement
  and the renderer warns (documented residual). Keyed MD5 / keyed
  plaintext (`simple`) and neither-leaf configs are unchanged; #9105
  (key-without-type, incl. its RI gap owned by #14400) is untouched.
- **Regression**: `pkg/config/isis_auth_type_without_key_14399_test.go`
  (global/interface/RI md5+simple strict-reject, lenient-warn, keyed and
  neither-leaf controls, cross-level key-does-not-satisfy cells) — RED on
  `origin/master` (8 reject cells accepted), GREEN after the fix;
  `pkg/frr/isis_auth_type_without_key_14399_test.go` (keyed md5/simple
  render unchanged at both levels; type-only renders no password lines).
