# #14588 — IKE proposal with no `dh-group` passes strict commit but strongSwan refuses to load the VPN

- **Timestamp**: 2026-10-16
  - **Action**: Rejected a DH-less IKE proposal referenced by a rendered VPN at strict commit and skipped it at render. Added `validateIPsecIkeDHGroupsPresentStrict` in `pkg/config/compiler_validate_strict_ipsec.go` (walks VPN → gateway → ike-policy → ike-proposal, plus the legacy direct-proposal fallback where the ike-policy value names an IPsec proposal; message names `dh-group`), wired through `opts.lenientIKEProposalMissingDH` in `pkg/config/compiler_uniformgates_ipsec_event.go` / `compiler_opts.go` so the tolerant load / peer-sync paths warn instead of bricking (#1960). In `pkg/ipsec/ike.go`, `ikeDHGroupMissing` filters DH-less proposals in `resolveIKESettings` (chain form and legacy fallback) through the existing `errDHGroupUnresolved` skip sentinel, so a lenient-loaded copy skips only the affected VPN and other VPNs load. ESP proposals with no `dh-group` remain valid no-PFS suites.
  - **File(s)**: `pkg/config/compiler_validate_strict_ipsec.go`, `pkg/config/compiler_opts.go`, `pkg/config/compiler_uniformgates_ipsec_event.go`, `pkg/config/ike_missing_dh_14588_test.go`, `pkg/ipsec/ike.go`, `pkg/ipsec/ike_missing_dh_render_14588_test.go`, `pkg/ipsec/README.md`, `docs/log/14588.md`

## Regression

- Strict: an IKE proposal with no `dh-group` referenced by a rendered VPN is rejected naming `dh-group` (the issue's decisive CheckText cell; rendered `aes256-sha256` on master per the executed probe). The legacy direct-proposal fallback is rejected the same way.
- Controls: `dh-group group14` / `14` / `group19` / `2` / `group32` still compile on both paths with no dh-group warning; `dh-group group99` is still rejected naming `99`.
- Tolerant: `CompileConfigLenient` and `CompileConfigForNodeLenient` warn (naming `dh-group`) without bricking; `lenientIKEProposalMissingDH` is registered in the tolerant opt set.
- Scope: an orphan DH-less IKE proposal no VPN references still commits; an ESP proposal with no `dh-group` (valid no-PFS) still commits; an IKE `proposal-set standard` policy still commits (synthetic proposals carry DH groups).
- Render: `renderConfig` skips the DH-less VPN (absent from file and rendered set, no orphan secret) while the healthy sibling renders with `modp2048`; `resolveIKESettings` surfaces `errDHGroupUnresolved` for both the chain and legacy forms.
