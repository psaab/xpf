# Issue #16016 — Legacy-unkeyed cluster authority

- **Timestamp:** 2026-11-02.
- **Action:** Bounded partial remediation; this change references #16016 and does not close it because the post-grace unkeyed-authority design remains unresolved.
- **Files:** `pkg/cluster/sync_conn_read.go`, `pkg/cluster/sync_conn.go`, `pkg/cluster/sync_admission.go`, `pkg/cluster/sync_auth.go`, `pkg/cluster/group_state.go`, `pkg/cluster/manager.go`, `pkg/cluster/status.go`, `pkg/cluster/legacy_unkeyed_authority_16016_test.go`, `pkg/daemon/daemon_ha_comms_wiring.go`, `pkg/daemon/config_sync_auth_authority_16016_test.go`, and `pkg/cluster/README.md`.
- **Fix:** Once a local accepted control-link key exists, unauthenticated session-sync config/session/bulk/failover/capability/clock/ack frames are refused at frame dispatch; liveness and the in-place auth-upgrade exchange remain permitted. The daemon config-provenance callback independently rejects unauthenticated config after local keying. When either configured peer endpoint is a literal IP, an inbound connection from another IP is closed before install, so it cannot supersede the genuine peer. The unkeyed posture now emits one error-level alarm per continuous unkeyed configuration and the control-plane-statistics status line keeps an explicit alarm visible until keying. No PSK is preserved node-locally: a pre-key peer-pushed config remains accepted so a secondary can receive its first control-link key.
- **D2 design fork:** Expiring all unkeyed config authority after a timer would block the peer-pushed first-key/rotation path, because config sync is the secondary's only writer and its frame has no authenticated identity before keying. Preserving `authentication-key` locally is not a safe substitute: it strands rotation on secondaries and conflicts with the existing `cluster_key_transition_16858_test` contract. Without a separate peer-authentication/bootstrap identity, an unauthenticated full-config push cannot distinguish a legitimate key install from hostile replacement. This PR therefore does not claim to solve unkeyed-after-grace authority; that design fork needs separate resolution. Literal-peer install pinning and keyed-state authority rejection are implemented independently.

The daemon RED cell returned nil and allowed unauthenticated config on a locally keyed manager. - **Risk:** Legacy-unkeyed nodes still accept unauthenticated heartbeat/session authority indefinitely; this work does not satisfy the issue's post-grace rejection criterion and is not close-ready. Hostname-only endpoints do not receive the install-time literal-IP pin. The change narrows the keyed/pre-key connection surface and exposes the no-key posture but does not remove the legacy trust dependency.
