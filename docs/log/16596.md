# #16596: Scoped global policy resolved address names against the zone's book instead of the global book

- **Timestamp**: 2026-10-25
- **Problem**: A global policy with a single-zone scope (`match from-zone trust`)
  resolved its address tokens against trust's attached/inline book (#3287), even
  when the global book defined the same name. `deny BLOCKED` (global
  10.0.0.0/8) silently enforced trust's BLOCKED (10.1.1.1/32), and adding a
  second scope zone silently reverted to the global object. Junos requires
  global-policy addresses to be defined in the global address book; the zone
  scope only narrows which flows the policy applies to. The policymatch
  simulator read the same folded book, so no surface disagreed.
- **Fix**: Global policies now resolve against the global book for every scope.
  `resolveZoneLocalAddressBooks` no longer rewrites global-policy tokens at all
  (zone-pair policies keep zone-local-first resolution unchanged). New pre-fold
  gate `validateScopedGlobalZoneLocalRefsStrict`
  (`compiler_validate_scoped_global_zonelocal_16596.go`), dispatched in
  `runEarlyStrictAndFolds` after `resolveNamedAddressBooks15672` and before the
  zone-local fold, rejects a single-zone scoped-global token defined only in
  that zone's book — including a member reachable only there through a global
  address-set — naming the policy, field, token, and zone (#16596). The tolerant
  load / peer-sync path (`lenientScopedGlobalZoneLocal16596`, #1960 no-brick)
  warns and poisons the referencing policy (`LenientContentDropped`), so the
  snapshot is refused fail-closed and the simulator reports the same retention
  (`ContentRejected`) instead of enforcing either object. This supersedes the
  #3287 acceptance: `scoped_global_zonelocal_test.go` and the `docs/config-schema.md`
  #3287 section are updated, as is `scoped_global_zoneset_4626_test.go` (A7 now
  reads: every global scope resolves globally).
- **File(s)**: `pkg/config/compiler_security_addressbook.go`,
  `pkg/config/compiler_validate_scoped_global_zonelocal_16596.go` (new),
  `pkg/config/compiler_earlystrict.go`, `pkg/config/compiler_opts.go`,
  `pkg/config/scoped_global_zonelocal_16596_test.go` (new),
  `pkg/config/scoped_global_zoneset_4626_test.go`,
  `pkg/policymatch/scoped_global_zonelocal_test.go`,
  `pkg/config/README.md`, `docs/config-schema.md`, `docs/log/16596.md`.
- **Tests**: `go test ./pkg/config/ -run 'TestScopedGlobal'` PASS (same-name
  global-twin source/destination, scope-variant agreement, local-only strict
  reject + tolerant warn/poison, attached-book and address-set-member arms,
  multi-zone/literal controls); `go test ./pkg/policymatch/ -run 'TestScopedGlobal'`
  PASS (global 10.0.0.0/8 enforced for the scoped row incl. policy identity,
  local-only strict error, tolerant `ContentRejected` naming the policy);
  targeted `TestNamedBook|TestZoneLocal|TestAddressBook|TestPolicyMatchAddress`
  and dataplane `TestZoneLocal|TestScopedGlobal|TestGlobalPolicy|TestPolicyContentReject`
  PASS.
- **Risk**: Configs that committed under the #3287 extension (a scoped global
  naming a zone-local-only object) now fail strict commit and must move the
  object to `security address-book global` or use a zone-pair policy — the
  intended Junos-parity break, flagged. Tolerant loads of such persisted
  configs boot with a warning but refuse the snapshot (previous-good retained)
  rather than enforcing the zone-local object.
