# Issue #12135 — honor external networkd matching before unmanaged teardown

## Why

`FindExternallyManaged` stored the entire `Name=` value as one literal key, so a matching glob or whitespace-separated list did not identify an unmanaged interface. `Manager.Apply` then emitted an earlier-sorting `10-xpf-*.network` with `ActivationPolicy=always-down`. The compiler also stripped addresses and brought unconfigured interfaces down before `networkd.Apply`, even when an external `.network` file owned the link.

## What

External matching parses `[Match]` rules from non-xpf `.network` files. `Name=` follows systemd's per-word negation model across repeated assignments, including fnmatch `[!x]` classes; normalized `MACAddress=` lists are also supported. Name and MAC predicates in one rule are conjunctive. `Manager.Apply` skips an unmanaged interface when its supported predicates match, even if other keys are unknown, preventing a potentially external owner from being overridden by a durable `always-down` unit. The compiler uses the stricter matcher and skips address removal/link-down only when its supported predicates establish a match.

## Risk / residual

Apply retains master's conservative durable behavior for conjunctive rules: when supported `Name=` / `MACAddress=` predicates match, an unknown additional key does not cause xpf to write an earlier-sorting `always-down` unit. The compiler cannot prove those unknown keys, so it does not skip teardown for such a rule; runtime networkd may therefore configure a link after the compiler has stripped it. Alternative interface names are not supplied to the matcher, and IPoIB's 20-byte hardware addresses are not supported. The parser accepts IP literals, but production matching uses interface hardware addresses from `net.Interfaces().HardwareAddr`. **NEEDS-OWNER-DECISION:** `Name=*` now exempts matching unconfigured NICs from xpf's strip and durable `always-down` behavior, so an external file (for example DHCP) can bring them up outside xpf zones and host-inbound policy. Do not add a catch-all guard without owner approval.
