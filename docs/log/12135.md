# Issue #12135 — honor external networkd matching before unmanaged teardown

## Why

`FindExternallyManaged` stored the entire `Name=` value as one literal key, so a matching glob or whitespace-separated list did not identify an unmanaged interface. `Manager.Apply` then emitted an earlier-sorting `10-xpf-*.network` with `ActivationPolicy=always-down`. The compiler also stripped addresses and brought unconfigured interfaces down before `networkd.Apply`, even when an external `.network` file owned the link.

## What

External matching parses `[Match]` rules from non-xpf `.network` files. `Name=` follows systemd's per-word negation model across repeated assignments and uses libc `fnmatch(..., flags=0)` semantics, including bracket classes and pattern escapes. Normalized `MACAddress=` lists include systemd's supported colon-, hyphen-, and dotted EUI-48 spellings. Name and MAC predicates in one rule are conjunctive. `Manager.Apply` skips an unmanaged interface when its supported predicates match, even if other keys are unknown, preventing a potentially external owner from being overridden by a durable `always-down` unit. The compiler uses the stricter matcher and skips address removal/link-down only when its supported predicates establish a match.

Invalid `MACAddress=` words remain dropped rather than triggering a rule-wide failure. This matches systemd's parser for genuinely invalid words; when no valid Match predicates remain, systemd warns and matches all interfaces, so adding an invalid-word guard would be a parity break. Systemd-valid non-EUI-48 forms outside this change's scope remain a separate limitation documented below.

## Risk / residual

Apply retains master's conservative durable behavior for conjunctive rules: when supported `Name=` / `MACAddress=` predicates match, an unknown additional key does not cause xpf to write an earlier-sorting `always-down` unit. The compiler cannot prove those unknown keys, so it does not skip teardown for such a rule; runtime networkd may therefore configure a link after the compiler has stripped it. Alternative interface names are not supplied to the matcher, and IPoIB's 20-byte hardware addresses are not supported. The parser accepts IP literals, but production matching uses interface hardware addresses from `net.Interfaces().HardwareAddr`. **NEEDS-OWNER-DECISION:** `Name=*` now exempts matching unconfigured NICs from xpf's strip and durable `always-down` behavior, so an external file (for example DHCP) can bring them up outside xpf zones and host-inbound policy. Do not add a catch-all guard without owner approval.

`Name=` field-level escapes such as `\!eth0` and `eth\[!0]` remain an inherited parser limitation and need a separate follow-up; escapes within fnmatch patterns are handled. This change adds only six-byte EUI-48 dotted parsing; existing IP-literal handling is unchanged. Other non-IP systemd hardware-address spellings at 4-, 16-, and 20-byte lengths remain out of scope; IPoIB's 20-byte addresses are unsupported.
