# #17679 — Charge same-sender reclaim to the victim zone

- **Timestamp**: 2026-10-26
  - **Action**: Changed same-sender incomplete reclamation to decrement `zone_entries` only when the victim has the candidate's `(routing_domain, ingress_zone)`. Added a regression with eight settled-incomplete sender anchors in zone A and 32 other-sender anchors in zone B; the cross-zone candidate is refused, while a same-zone control is admitted.
  - **File(s)**: `userspace-dp/src/fragment_overlap/mod.rs`, `docs/log/17679.md`.
  - **Validation**: RED before the fix: `CARGO_TARGET_DIR=/var/worktrees/.cache/cargo-17679 cargo test --bin xpf-userspace-dp same_sender_reclaim_charges_victims_zone_not_candidates_17679` admitted the candidate in zone B. Fail-on-revert: temporarily restored the unconditional decrement; the same test failed with the same unexpected admission. GREEN: the test passed after the fix; `CARGO_TARGET_DIR=/var/worktrees/.cache/cargo-17679 cargo test --bin xpf-userspace-dp fragment_overlap::tests::` passed (46 tests). Full `cargo test` with the fix: 9623 passed, 86 failed, 10 ignored. Clean-stash baseline `cargo test`: 9621 passed, 87 failed, 10 ignored; comparison of failure-name lists showed all 86 failures from the fixed run also fail on baseline, with only `screen::tests::syn_flood_per_dst_port_under_threshold_not_summed_14635` failing on baseline alone. The package-suite failures are therefore pre-existing and unrelated to this change.
  - **Risk**: A cross-zone victim is still removed before the candidate's zone-cap check; if that zone is full, the candidate is refused and the reclaimed anchor loses overlap protection. This preserves the existing reclaim order while preventing another zone's freed slot from bypassing its 32-entry cap. Same-zone reclaims continue to free one slot for the insertion.
