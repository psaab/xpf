# #10203 and #10204: Go status mirror and static snapshot linkage proof

## #10203 — Go mirror for linked library versions

- Added `LinkedLibelfVersion`, `LinkedZlibVersion` and `LinkedZstdVersion` to the Go `ProcessStatus` mirror with the Rust wire names and `omitempty`. `ProbeStatus` already returns this `ProcessStatus`; no second IPC path was added.
- The status-summary display renders the three rows when any linked snapshot version is present. Empty fields retain the pre-follow-up output, including the existing status golden.
- RED proof before the implementation:
  - `go test ./pkg/dataplane/userspace ./pkg/dataplane/userspace/format -run '10203' -count=1`
  - Failed because the three Rust JSON keys were dropped on Go re-encoding and the summary contained none of the linked versions.
- GREEN proof:
  - The same targeted command passed after the mirror and display changes.
  - `TestLinkedLibVersionsKeepOldGoIgnoreCompatibility10203` passed: old helper JSON decodes to empty fields, and a legacy Go-shaped consumer ignores the three new keys without losing existing fields.
  - `TestFormatStatusSummaryGolden` passed with empty linked fields, proving the old display remains byte-identical for pre-follow-up helpers.

## #10204 — DT_NEEDED and snapshot archive verification

The three `libxpf*.a` inputs are static archives, so they must not appear in `DT_NEEDED`. The committed `scripts/check-userspace-dt-needed-10204.py` checks both sides of the invariant: the linker map must show members from each unique snapshot and no members from bare host archives, while `readelf -d` must contain no bare `libelf.so`, `libz.so` or `libzstd.so` dependency.

Build and check:

```text
CARGO_TARGET_DIR=/dev/shm/cargo-10204 cargo +1.98.1 rustc \
  --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp \
  -- -C link-arg=-Wl,-Map=/dev/shm/xpf-10204.map
python3 scripts/check-userspace-dt-needed-10204.py \
  /dev/shm/cargo-10204/debug/xpf-userspace-dp /dev/shm/xpf-10204.map
```

Result:

```text
#10204: DT_NEEDED and snapshot archive verification passed
DT_NEEDED: libgcc_s.so.1, libc.so.6, ld-linux-x86-64.so.2
libxpfelf.a members: 102
libxpfz.a members: 33
libxpfzstd.a members: 81
libelf.a members: 0
libz.a members: 0
libzstd.a members: 0
```

No host bare shared-library leakage was found, so no linkage source change was necessary. The negative control used a fake `readelf` reporting `libz.so.1`; the checker rejected it with `#10204: forbidden host shared dependencies in DT_NEEDED: libz.so.1` and exit status 1.

The existing build-time shadow guard was also exercised with a planted earlier `LIBRARY_PATH/libz.a`:

```text
LIBRARY_PATH=/tmp/xpf-10204-shadow \
CARGO_TARGET_DIR=/dev/shm/cargo-10204-shadow \
cargo +1.98.1 check --manifest-path userspace-dp/Cargo.toml -q
```

It failed closed with exit status 101 and:

```text
#9931: unexpected zlib archive /tmp/xpf-10204-shadow/libz.a appears before the selected /usr/lib/x86_64-linux-gnu/libz.a in the linker search set
```
