## The fix, and why the gate rather than the table

`configTargetReadPermission` gains an unconditional
`case "ShowCompare": return config.PermConfig, true`. This mirrors the REST
twin, which #9324 fixed the same way: `candidateConfigReadPermission`
(`pkg/api/authz.go:877-892`) prices `GET /api/v1/config/compare` at PermConfig
on both branches while the route table still lists PermView. Every
candidate-read price now lives in one choke-point function per surface.

NOT re-targeting the `>0` arm to rollback-vs-active: that would change the
RPC's documented semantics (rollback-vs-candidate is the Junos
`show | compare rollback N` meaning) and DIVERGE from REST, which prices
`?rollback=1` at PermConfig (pinned by
`config_target_default_9324_test.go:181`).

ADDITIVE shape (parent review GPT-2): on gRPC the price is view AND configure
— the interceptor charges the table's `PermView` first and the gate's
`PermConfig` second, and the bits are independent. REST instead REPLACES the
route price, so a configure-only caller is admitted there but denied on gRPC
(and on `ShowConfig{CANDIDATE}`, which has had this shape since #9324). The
built-in classes never split the two (only `super-user` holds `configure`).
Pinned by `TestShowComparePriceIsViewAndConfigure_9889` (configure-only denied
both arms at the gate, admitted to `EnterConfigure`, view+configure admitted);
stated in `docs/system-login.md`.

## The census rewrite

`TestCandidateReadingRPCsCostConfigure_9889` enumerates candidate-READING RPCs
from handler behaviour: hop 0 finds configstore `*Store` methods that
reference the candidate field AND redact for display, belong to the `Show`
family, or COMPILE the candidate (compiled configs and commit-check
error/warning text carry candidate identifiers — diagnostic readers are
candidate readers); hop 1 finds served RPCs whose handlers reach them
transitively (same-package calls, `s.store` aliases); hop 2 asserts each costs
PermConfig / PermAll in the table or PermConfig via the gate for per-RPC probe
requests.

Measured enumeration: 24 hop-0 sources (ShowCandidate* cleartext+redacted
incl. path variants, ShowCompare* cleartext+redacted, CommitCheck,
CompileCandidate, CompileCandidateGen, commitWithDescriptionLocked,
commitConfirmedLocked); exactly 3 hop-1 RPCs
(`ShowConfig`←5 redacted, `ShowCompare`←2 redacted, `CommitCheck`←CommitCheck,
the last passing via its table PermConfig). Deliberately out: pure mutations
(Set/Delete/Load), CommitDiffSummary (counts, no content), metadata.

Completeness of the walk itself: `TestEveryRendererCallIsCensusVisible_9889`
fails on any enumerated source reached through a parameter, a package-level
store, or a captured method value instead of an `s.store` (or alias) call in a
`*Server` method — zero such shapes in prod today. Documented boundary: the
daemon commit closures (`s.commitFn`/`s.commitConfirmedFn` func-field seams
into another package); both RPCs are table-PermConfig, pinned explicitly in
the census test.
