# Issue #12835 — research D2-13: zone-interface readers diverge

## Finding and correction

`compileZones` expands security-zone resolving runs through
`expandResolvingRuns9792(inst.node.Children, securityZoneSchema9792())`, but the
strict `validateZoneInterfacesNonEmptyStrict` and
`validateZoneInterfacePackedTailStrict` walkers used raw `inst.node.Children`.
They now use the same expansion before searching `interfaces`, so the AST gates
inspect the same properties as the compiler.

Separately, `zoneInterfaceKeysBeforeBody` split only on
`host-inbound-traffic`. In a packed member's own Keys, `apply-macro`,
`apply-groups`, and `apply-groups-except` plus their parameters were therefore
returned as interface names; the child-node walk already skips these meta
keywords. The splitter now terminates at these meta statements too, so the
metadata and macro body are not treated as membership.

Strict commit schema rejects some packed scalar tails (notably `screen` and
`description`), as the issue's strongest refutation noted. Resolving-run gate
behavior is accordingly a latent/tree-reader consistency correction, not a claim
that those schema-invalid spellings pass the CLI commit boundary.
