# #12096 — Charge zone-pair summaries as session reads

## Why

The REST zone-pair session summary and gRPC `GetZonePairSummary` returned live session aggregates but were attributed to `show security match-policies`. A class denying `show security flow session` therefore passed the command gate for these reads.

## What

Both authz tables now charge zone-pair summaries to the canonical `show security flow session summary` command. The policy simulator mapping and `/security/zones` mapping are unchanged. Regression coverage exercises REST read middleware and RPC authorization, including the `/security/zones` positive control and same-fixture RPC detail/inventory controls under the summary-only deny.

## Validation

- RED before the mapping change: `go test ./pkg/api -run '^TestTheREADPathConsultsTheCommandGate9952$' -count=1` failed because the zone-pair REST path returned 200 instead of 403; `/security/zones` remained 200.
- RED before the mapping change: `go test ./pkg/grpcapi -run '^TestAuthorizeRPCEnforcesDenyCommandsEndToEnd7172$' -count=1` failed because `GetZonePairSummary` returned no denial (`codes.OK`).
- GREEN after the mapping change: the same targeted tests passed; zone-pairs is denied on REST and RPC, while `/security/zones` remains 200 and RPC `GetSessions`/`GetZones` remain admitted under the summary-only deny.
- `go build ./pkg/api/... ./pkg/grpcapi/...` passed.
- `gofmt -l` on all changed Go files returned no paths.
- Full scoped suites `go test ./pkg/api ./pkg/grpcapi` passed (`pkg/api`: 96.587s; `pkg/grpcapi`: 35.807s). No broader suite red required same-base attribution.

## Risk

The attribution correction deliberately causes session-deny rules to cover this session aggregate. No live-cluster state was mutated. The `/security/zones` and policy-simulation command mappings remain distinct and unchanged.
