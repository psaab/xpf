# 10038 — TUN-originated flows install no session, so solicited replies die at host-inbound

## Summary

Residual of #8274, found blocking #9587 smoke (PR #10032 cell-5) and
independently reproduced on pure master by Eng9644 (#10038 comment):
WireGuard handshake OK, encap OK, peer replies, worker decaps — then
replies die with session_misses + host_inbound_denied. Mechanism: the
TUN-read encap path (firewall-self-originated traffic leaving through a
tunnel) installs no worker session, so the solicited reply has nothing
to HIT and dies at host-inbound admission.

Three-part fix (worker-side B+C first, then publisher A):

- **Part A — publish.** The WG control thread publishes the TUN-origin
  session pair (forward + reverse) to the shared maps on every Sent
  encap, through a production builder (`tun_origin.rs`) with the
  TUN-origin marker. GRE already published; WG did not.
- **Part B — exempt.** A reverse LocalDelivery HIT whose forward
  companion proves TUN-origin skips the two NEW-session gates
  (host-inbound admission, junos-host policy) — Junos runs neither on
  self-originated traffic nor its solicited replies. lo0, TTL, and
  input-filter gates still run.
- **Part C — decline.** #9604 declines TUN-origin forwards on both arms
  (forward HIT and reverse-companion judgment): self-originated runs no
  zone policy (#6224), so judging the tunnel pair and revoking on the
  default deny is the #9563 error shape.

21 cells, all green 5/5; full userspace-dp suite at base parity (one
pre-existing guard FAIL, byte-identical on pristine base — see
Validation); every behavioral cell killed by at least one mutant
(except the fragments residual pin, which has no our-surface mutant —
stated below).

## 1. The defect

### Observed (loss cluster, #8274+#9521 builds, scalar and set alike)

Handshake OK, encap OK (peer rx grows), peer replies (peer tx grows),
worker decap_packets grows — then replies die with session_misses +
host_inbound_denied. Zero unsteered drops, zero policy denies, live
ctrl map correct. Single-port and set identical: pre-existing, not
introduced by #9587. Eng9644 reproduced point-for-point on pure-master
`18f5f9a78` (90+ failed inner pings, configure FAILs at P1, zero data
packets on the wire).

### Mechanism (three absences, one per part)

1. The WG TUN-read loop encapsulates and sends but publishes nothing —
   no forward, no reverse, in any map. (GRE's local-origin path
   publishes; WG's never did.)
2. Even with a pair installed, the reply's reverse LocalDelivery HIT is
   re-checked against host-inbound admission and junos-host policy on
   every hit — gates a solicited echo-reply on a ping-less zone cannot
   pass.
3. Even past those, #9604's reverse-companion judgment evaluates the
   forward's tunnel pair against zone policy and revokes on the default
   deny — a pair admission never consulted (#9563 shape).

V1 pins absence 3 (RED on base via revoke), V2 pins absence 2 (RED on
base via HIT-deny teardown); both RED-on-base proven behaviorally on
the base tree before the fix.

## 2. Part A — WG TUN-origin publish (`tun_origin.rs` + burst)

### Builder

`coordinator/wg_control/tun_origin.rs` (new): parse the inner packet
(`parse_wg_tun_origin_flow`: eth-wrap, flow key, TCP flags), build the
forward + reverse entries (`build_wg_tun_origin_entries`: honest outer
resolved per SELECTED peer endpoint — FIB + neighbor, stamped
tx/next_hop/MACs — plus reverse synthesis), publish shared-only
(`publish_wg_tun_origin_entries`: shared + nat + forward-wire maps,
owner-RG index, dedup stamp). Entries carry the TUN-origin marker:
synced-family origin, `!is_reverse`, `ingress_ifindex == 0`,
`tunnel_endpoint_id != 0`, `policy_counter_idx == 0`.

### Burst (A3: parse→dedup→encap→publish-on-Sent)

Per TUN-read packet: cheap parse → dedup check → `encap_and_send`
(which now returns `EncapOutcome`) → full build + publish ONLY on
`Sent`. Every skip arm still encapsulates — the publish is gated, the
encap never is. One forwarding Arc + one HA snapshot per outer
iteration, reused across the burst (the GRE loop's coherence shape);
the publish-only attachment gate (`wg_endpoint_attachment_valid`)
skips publish when the endpoint row is detached, without parking the
thread. Threading is shared-only by design (no `worker_commands`).

### Adjudication (Review A — 12/12 ACCEPTED)

The load-bearing constraints, all folded: publish gated on encap
success (GRE's session-implies-emission invariant — a session for a
request that never left would admit causally-prior-less replies);
+14 offset fixup (wrap → l3=14, l4/payload+=14 → parse); honest outer
per selected peer (no tx=0/cached-fiction shape); parse-then-dedup-
then-build (strictly cheaper than GRE); standby publishes (reverse
synthesis enforces HA → HAInactive reverse → fabric path, matching
GRE post-publish flap behavior); all-paths builder failure →
skip-publish-still-encap.

### A6 sweep sharing (one SSOT, two callers)

The dedup map + prune sweep is GRE's shape with GRE's constants:
`tunnel.rs::prune_local_tunnel_sessions` widened `fn` →
`pub(super)` (the only production change in `tunnel.rs` — no GRE
egress behavior change) so the WG publisher runs the same sweep
against the same thresholds. The name stays: both callers prune a
thread-local "sessions I published" map for locally-originated
tunnel traffic.

## 3. Part B — solicited-reply exemption (LocalDelivery HIT arm)

`poll_descriptor/mod.rs`: a reverse LocalDelivery HIT whose forward
companion proves TUN-origin (`tun_origin_reverse_exempt`: companion
key byte-identical to #9604's, local-first then shared, local hit
DECIDES, lone reverse fails closed) substitutes the lo0-only
evaluation (`lo0_action_for_solicited_reply` — argument threading
IDENTICAL to the lo0 tail of `host_inbound_gated_lo0_action`, only
the admits check skipped) and skips the junos-host re-check. Both
feed the SAME downstream match/accounting blocks as the admitted
arm. Precedence: revalidation runs BEFORE the HIT arm, so a C-revoke
always wins over a B-exempt (fail-closed on any divergence).

### Adjudication (Review B — 10/10 ACCEPTED)

The blanket `is_reverse` skip is DEAD (B1 spoof-plant blocker): the
exemption requires forward-companion TUN-origin proof, with a
spoof-plant negative cell. Tightening asymmetry documented as Junos-
established parity (B4): TUN-origin solicited flows survive
host-inbound/junos-host tightening (the every-hit re-check is
incompatible with echo-reply-not-in-ping-set); host-bound FORWARD
sessions still die on tighten (pinned). Fragmented replies stay
denied (B2 residual — the flowless arm has no session key; pinned,
not fixed). The `session_host_bound_policy_dst` "does not arise"
claim retired + NAT trap noted (B7); dbg-only counter, no
prometheus (B9).

## 4. Part C — #9604 TUN-origin decline (both arms)

`poll_descriptor/policy_revalidation.rs`: the single predicate
`tun_origin_forward` (5 conjuncts, each closing a spoof/alias class —
see its doc comment) shared by the Part C declines and the Part B
exemption, so #9604 and the HIT gate can never disagree about what
"TUN-originated" means.

- Forward arm: after canonical resolution, a TUN-origin forward is
  declined — a tunnel-side forward-tuple packet (peer-spoofed or
  reflected) HITS the forward entry (#9519 Owner) and must not
  revoke the pair post-commit. (The "forward-HIT unreachable" claim
  was WITHDRAWN under review.)
- Reverse (#9604-companion) arm: a TUN-origin forward companion is
  declined — covers the locally-present shape (GRE UpsertLocal,
  pre-installed pairs); the shared-only shape (WG production)
  declines by the pre-existing lone-reverse arm, so the e2e cell is
  C-insensitive by design.

### Adjudication (plan v4 — 9/9 ACCEPTED)

Discriminator v2: `policy_counter_idx == 0` excludes
degraded-ingress HA tunnel-transit (transit is always
policy-admitted); explicit origin set incl. SharedPromote
(promote-poison harmless — a promoted TUN-origin forward still
matches, so C declines and B exempts); C decline silent like the
LocalDelivery decline. Agreement matrix: local-marker → C declines
/ B exempts [V1, GRE]; shared-only-marker → C lone-declines / B
exempts [WG prod, e2e]; nowhere/non-marker → C judges / B gates
[plant, transit, lone]. C8 verified: all 30 #9604 cells green
against the new decline arms (full-suite run + named re-run).

## Release note

GRE TUN-origin sessions are no longer policy-revoked on the default
deny, and solicited replies to firewall-self-originated tunnel flows
(GRE and WG) bypass host-inbound admission and junos-host policy
while keeping the lo0 packet filter, TTL, and input-filter gates —
matching Junos (self-originated traffic and its solicited replies
run no policy). Operators will see WG/ICMP-over-tunnel flows the
firewall itself originates (e.g. inner ping fw→peer) complete
instead of dying with session_misses + host_inbound_denied; no
configuration change required.
