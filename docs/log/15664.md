# #15664 — established junos-host sessions re-counted live rule order

- **Timestamp**: 2026-10-19
  - **Action**: Established `to-zone junos-host` (`LocalDelivery`) session
    hits ignore the admission-bound `policy_counter` handle: the hit path
    excluded `LocalDelivery` from the bound-counter count and instead the
    per-hit junos-host re-eval counted through the LIVE first-match, so an
    `insert ... before` reorder re-attributed established host-bound
    traffic to the inserted rule, and a foreign-arrival packet hitting the
    session incremented a junos-host counter before the `may_revoke` gate.
    Fix: `junos_host_policy_eval`/`junos_host_local_policy` take
    `recheck_established`; established re-checks re-derive via the new
    `policy::rederive_junos_host_policy_l3_aware_at`
    (`PolicyHitCount::Never`) and count only a matched Deny/Reject
    (positionally, on the live denying rule); permitted LocalDelivery
    hits now count through `bound_policy_counter` at the generic
    session-hit site when `foreign_arrival_zone.is_none()`. Miss,
    Stage-11, and flowless callers keep the counting evaluation.
    Regression: `local_delivery_session_hit_counts_bound_admitting_rule_across_insert_reorder_15664`,
    `local_delivery_foreign_arrival_does_not_count_junos_host_15664`, and
    the updated exactly-once cell
    `poll_descriptor_junos_host_permit_established_hit_counts_once`.
