# #18607 — preserve management VRF masters in disabled networkd rows

- **Branch:** `fix/18607-drive`, rebased from `e79d78b2ac` onto docs-only master `281739b000`.

## Root cause

`Manager.generateNetwork` returned early for `Unmanaged || Disable` rows after writing an always-down `.network` unit. That path skipped the later `VRFName` predicate, so disabled or unmanaged management-class rows rendered no `KeepMaster=yes`. The daemon's `managementVRFIfaceSet` remains class-based, so it still binds those interfaces to `vrf-mgmt`; on reconfigure, networkd could release the master before the daemon rebound it.

## Change

The always-down branch now emits `KeepMaster=yes` for a non-empty `VRFName`, with the same `BondMaster`/`BridgeMaster` exclusions as the normal branch. The existing #18597 table covers disabled and unmanaged VRF rows, absent-VRF negatives, and disabled bond/unmanaged bridge exclusions. The networkd README residual is replaced with the fixed behavior.
