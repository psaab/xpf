# #18607 — preserve management VRF masters in disabled networkd rows

- **Branch:** `fix/18607-drive`, rebased from `e79d78b2ac` onto current master `281739b000`.

## Root cause

`Manager.generateNetwork` returned early for `Unmanaged || Disable` rows after writing an always-down `.network` unit. That path skipped the later `VRFName` predicate, so disabled or unmanaged management-class rows rendered no `KeepMaster=yes`. The daemon's `managementVRFIfaceSet` remains class-based, so it still binds those interfaces to `vrf-mgmt`; on reconfigure, networkd could release the master before the daemon rebound it.

## Change

The always-down branch now emits `KeepMaster=yes` for a non-empty `VRFName`, with the same `BondMaster`/`BridgeMaster` exclusions as the normal branch. The #18597 table retains direct generator assertions and applies every disabled or unmanaged case through `NewInDir(...).Apply`, then reads the generated `.network` file. The unmanaged management case runs in an empty temporary directory (no external match). These file assertions also pin `ActivationPolicy=always-down`, `LinkLocalAddressing=no`, and the KeepMaster positive/negative cases. The README residual is replaced, and its link-local requirement now names the enabled-row behavior and always-down exception.
