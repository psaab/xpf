## Design

- **Pattern.** It follows the repo's retry-owner pattern: `proxyARPReassertLoop` (#4001), `fabricIPVLANReassertLoop` (#6791), `serviceReloadDebtReassertLoop` (#6800).
- **Debt.** `noteRoutingReconcileResult(routingRuleErr, routeLeakErr)` latches on any error and discharges on none. The failure count is monotonic (climbing means running and failing; flat with owed set means not running).
- **Retry owner.**
  - `routingReconcileReassertLoop` ticks every 30 s.
  - `reassertRoutingReconcileOnce` takes `applySem` BEFORE reading the active config, re-checks the debt inside (a commit in between discharges it), and re-runs `applyPolicyRoutingRules` plus `reconcileRouteLeakSnapshot` with `commitOverlayForConfig`.
  - It never re-runs the FRR apply; the FRR manager owns its degraded retry.
- **Seams.** `routingPolicyReconcileFn` and `routeLeakReconcileFn` are package-level, as `fabricEnsureFn` is, because `d.routing` is a concrete `*routing.Manager`.

## Validation

- **New cells** in `routing_reconcile_debt_9693_test.go` (7):
  - latch and discharge;
  - the retry owner runs only while owed and retries until it succeeds;
  - it reconciles the active config and waits while a commit holds `applySem`;
  - it re-checks the debt inside the semaphore, so it does nothing after a commit discharged the debt while it waited;

  - with nothing owed the retry owner does not queue behind a commit's applySem.
