# Issue #12086 — scope interface NAT local delivery by routing table

- **Timestamp**: 2026-10-07
- **Why**: Residual of #3769: global `interface_nat_v*` address maps could produce `LocalDelivery` before the resolving FIB table was known, letting an address owned by one routing instance be claimed in another. Reverse-session prewarm also reused the forward PBR install-table stamp, although reverse lookup must classify its source endpoint in that endpoint's native table.
- **What**: Record each interface-NAT IPv4/IPv6 address's owning canonical table during forwarding-state construction. In leak-target FIB checks, recognize interface-NAT addresses only when the selected target table is an attributed owner; ordinary source-table lookups retain the separate session-miss gate. Gate interface-NAT resolution on the resolving table across ingress, flowless, session re-resolution, PBR revalidation, and reverse-session paths. This preserves ingress-interface local-delivery precedence while making the selected PBR table govern host-bound transit when it does not own the interface-NAT address. Resolve reverse-prewarm's table from native routing domain, ingress interface/VLAN, and source endpoint instead of the direction-specific forward stamp; retain best-effort add-only prewarm when native classification is unresolvable. Preserve existing any-table wildcard behavior for NAT/DNAT `local_v*` entries. Cover leak parity for IPv4/IPv6 and shapes A/B, PBR reverse prewarm, and session-miss/re-resolve callsites.

- **Risk**: On leak-target FIB lookups only, an interface-NAT address is local when the selected target table is recorded as an owner, including leak-only routes; ordinary source-table FIB lookup retains its prior interface-NAT separation and the explicit session-miss gate. Operator-visible behavior: when a PBR-selected table does not own the destination interface-NAT address, the PBR route governs host-bound transit instead of delivering locally; ingress-interface local delivery remains ahead of PBR. This reverses the interface-NAT half of the #3292/#3600 Note 2 ordering, and matches Junos FBF and `ctl_no_snat`. Reverse-prewarm classification uses the reverse endpoint's native table rather than the forward PBR stamp. On an unresolvable native route, add-only prewarm still uses the default table as a best-effort superset, which can overfile but avoids losing failover rows. No control-plane wire format or live state is changed; no live-cluster/VRF validation was run.
