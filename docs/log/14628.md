# #14628 — #6474 outbound-SNAT ICMP-error re-NAT shadowed when the local reverse half is installed

- **Timestamp**: 2026-10-17
- **Action**: Classify outbound-SNAT ICMP errors by direction
  (`quoted_is_reply`) plus the reverse-half shape of a pure source
  translation, recover the FORWARD decision from the locally installed
  forward companion, and hand it to the existing
  `build_snat_outbound_icmp_error_{v4,v6}` builders.
- **Files**: `userspace-dp/src/afxdp/icmp_embed/nat_match_v4.rs`,
  `userspace-dp/src/afxdp/icmp_embed/nat_match_v6.rs`,
  `userspace-dp/src/afxdp/icmp_embed/mod.rs`,
  `userspace-dp/src/session/lookup.rs`,

## Why

Production installs both session halves
(`should_install_local_reverse_session` is true unless FabricRedirect).
For SNAT `H:hp -> S:sp` translated to `P:pp`, the reverse half is indexed
under its translated alias `S:sp -> H:hp`. An outbound ICMP error from
the internal host quotes the reply in PRE-NAT form (`S:sp -> H:hp`), so
the matcher's as-is probe hits that alias first, `via_reply_key` stays
false, and the old `outbound_snat = via_reply_key && !is_reverse && ...`
stays false. The #5690 reversed builder then leaked the internal source
(`outer_src=10.0.61.102`) with an unassociable pre-NAT quote, breaking
remote association and PMTUD. The shipped #6474 cells install only the
forward half, so they never saw this.

## What

- `nat_match_v4::match_outer_v4` / `nat_match_v6::match_outer_v6`:
  compute `quoted_is_reply = via_reply_key != is_reverse` before the
  resolution. The old forward reply-key arm is unchanged. A new
  reverse-half arm sets `outbound_snat` when the quote is a reply, the
  matched reverse decision has the pure-source-translation shape
  (reverse `rewrite_dst` set + `rewrite_src` unset, or `nptv6`), a local
  forward companion exists, and the frame is not fabric-ingress
  (fabric frames were already re-NAT'd by the redirecting node, #13772,
  and keep the historical peer policy-source path).
- Forward-companion recovery: new
  `SessionTable::probe_canonical_with_origin_at` returns the matched
  entry's canonical key (a local alias hit otherwise cannot name it);
  `reverse_session_key(canonical_reverse, reverse_nat)` yields the
  forward key, whose live forward entry supplies both the external NAT
  decision (`match_nat`) and the cached WAN resolution for the outbound
  builders. Shared-only reverse hits have no local companion and keep
  the historical reversed-builder path — the HA-peer shared-map
  residual named in the issue.
- NOT changed: the forward-NAT-by-reverse arm, DNAT/composed flows,
  no-NAT flows, the #10672 wire-quote (post-NAT) reverse-half path, the
  builders themselves, NAT64, and budget/zone bookkeeping
  (`related_expected_zone` already used the same XOR).

  fails identically on unmodified master (base-attributed).

## Risk

- A reverse-half match whose forward companion was independently
  reaped keeps the pre-fix reversed-builder behavior (fail-open to the
  old leak for that error only, never a policy bypass).
- The HA-peer shared-map path (reverse entry present only in the
  shared maps) is unchanged and remains the residual named in the
  issue; the production both-halves local path is fixed.
