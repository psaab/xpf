# #15534 — flowless poisoned DNAT falls through untranslated instead of dropping

- **Base**: `origin/master` at campaign start (`fd1abcdc5c`).
- **Refs**: #14947 / PR #15359 (merged `392805334b`); found by hostile
  review V14947 on exact head `2bda0bdad9`.

## Defect

`userspace-dp/src/nat/destination.rs` maps both `Exempt` and
`Poisoned(_)` to `None` in the Option lookup
(`lookup_with_counter_scoped`) used by
`flowless_pre_routing_destination_nat`
(`afxdp/poll_descriptor/frag_assoc.rs`). A portless/flowless packet
(GRE, fragment, ICMP) claiming an address-only poisoned DNAT rule
therefore got no translation and no drop: the later fences did not
fire either, because

- `flowless_l4_translation_possible` requires an L4 selector
  (`has_l4_selector`), which an address-only rule does not have, and
- `flowless_destination_nat_requires_translation` probes the same
  Option surface, where `Poisoned` reads as no-translation.

The packet continued untranslated (NPTv6 or `None`) instead of
dropping — a fail-open for a rule the control plane explicitly marked
fail-closed (`lenient_match_dropped`, #14947). Port-scoped poisoned
rules were equally invisible: the flowless lookup runs at ports 0/0,
so the entry keyed under its real destination port never matched.

Also in scope (from the same review): `docs/log/14947.md` stated
protocol 50->51 (actual 51->52) and a wrong base (`b8f1ff7ac9`; the
PR's actual parent is `ae59bd7d7f`); the `protocol/nat.rs` NAT64
`pool_unusable` comment misattributed it to the v52 bump (it rides
v51, #14962); an unused `DnatLookup` import in `afxdp/mod.rs`;
`lookup_result_with_counter_scoped` discarded the poisoned rule's
hit counter; and it paid a double lookup on every non-match.

## Fix

- `nat/destination.rs`:
  - New single-pass `outcome_with_counter_scoped` running the exact
    tier chain (exact -> wildcard-port -> `PROTO_ANY` -> prefix LPM)
    once. `lookup_result_with_counter_scoped` is rewritten on it: one
    lookup on every path, and `Poisoned` now returns the poisoned
    rule's hit counter instead of discarding it (`poisoned_claims`
    and the double lookup are gone).
  - New `flowless_poisoned_claim`: (1) a winning address-only /
    `PROTO_ANY` poison at ports 0/0 claims directly; (2) otherwise a
    bounded possible-claim scan over this destination's indexed
    entries and this family's prefix slots — a poisoned entry whose
    known scope/address/protocol/ICMP attributes could match claims
    even when its L4 selector (destination port, port ranges, source
    ports) cannot be evaluated without ports; (3) a healthy
    address-only translate/`off` that also matches shadows the
    possible claim (ordinary precedence is preserved), and an
    address-only healthy `off` winner exempts outright. The fragment
    unknown-protocol sentinel (255) probes concrete configured
    protocols plus one wildcard probe, mirroring
    `has_unknown_protocol_translation_match_scoped`, and is otherwise
    treated as protocol-unknown. Returns the poisoned rule's counter.
- `afxdp/poll_descriptor/frag_assoc.rs`: new
  `FlowlessPreRoutingNat::Poisoned { counter }` variant;
  `flowless_pre_routing_destination_nat` returns it when
  `flowless_poisoned_claim` fires (after the ordinary address-only
  translate attempt, before NPTv6), and
  `flowless_destination_nat_requires_translation` treats a poisoned
  claim as a required drop so the downstream flowless fences
  (ForwardCandidate, NoRoute, MissingNeighbor, neighbor-retry) agree.
- `afxdp/poll_descriptor/flowless_verdict.rs`:
  `flowless_base_resolution` drops on `Poisoned` (returns `None`,
  recycling the descriptor) and counts the poisoned rule's hit
  counter once, since no session is ever installed for it.
- Docs/comments: `docs/log/14947.md` base corrected to `ae59bd7d7f`
  and protocol corrected to 51->52; `protocol/nat.rs` NAT64
  `pool_unusable` now correctly rides the v51 bump; unused
  `DnatLookup` import removed from `afxdp/mod.rs`.

NOT changed: the flow-backed pre-routing caller in
`poll_descriptor/mod.rs` already drops on `DnatLookup::Poisoned`
(#14947) and now also receives the counter; cross-tier precedence is
unchanged (a more-specific healthy translate still beats a broader
poisoned entry); established sessions are unaffected; static NAT and
NPTv6 have no poison marker and keep their existing flowless fences.

## Regression (`flowless_poison_dnat_tests_15534.rs`)

Drives the real flowless path (`ForwardingState` built from
snapshots -> `flowless_pre_routing_destination_nat` /
`flowless_base_resolution`) with `lenient_match_dropped` DNAT rules:

- `flowless_poisoned_address_only_dnat_drops_15534`: address-only
  poisoned DNAT + GRE packet drops (`Poisoned`, and
  `flowless_base_resolution` returns `None`). RED on master: the
  address-only lookup maps Poisoned to `None`, pre-routing returns
  `None`, and the packet resolves/forwards untranslated.
- `flowless_poisoned_port_scoped_dnat_drops_15534`: tcp/80 poisoned
  DNAT + GRE packet (ports 0/0) drops via the possible-claim scan.
- `flowless_poisoned_fragment_unknown_proto_drops_15534`: fragment
  sentinel (255) + port-scoped poison drops.
- `flowless_healthy_dnat_controls_15534`: healthy address-only DNAT
  still translates a GRE packet; healthy `off` still exempts; no rule
  does not drop.

## Residual / risk

- The port-scoped possible-claim is intentionally fail-closed: a
  flowless packet that *might* match a poisoned port-scoped rule
  drops even if its (unrecoverable) real port would have missed the
  rule. That mirrors the existing L4-possible fences
  (`flowless_l4_translation_possible` -> `Untranslatable` -> drop)
  and is the safe direction for a poison marker; healthy
  address-only shadowing keeps the common precedence case exact.
- Poison counters on the flowless path are counted at drop time in
  `flowless_base_resolution` (per packet, not per flow — flowless
  packets install no session), matching the counter's role as
  diagnostic telemetry.
