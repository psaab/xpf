    vlan-tagging interface.

- **Timestamp**: 2026-09-11 04:48 PDT
- **Action**: Chose the issue's alternative fix direction: give the rendered
  device its VRRP base address.
  - `isVRRPReth` in `buildInterfaceNetworkdModels` is
    `RedundancyGroup > 0 && clusterNodeID >= 0`, with no election-mode term.
  - Every non-VLAN RETH member and every tagged RETH sub-interface already gets

  - The VLAN parent is the one RETH device that never did. It is also the

  So the fix is the same rule on that one device, rather than a mode-dependent
  commit reject of a shape that works in the default mode. In the default mode
  `RethVIPsForRG` already puts that unit's VIPs on the base member.
  `pkg/networkd`'s `TestGenerateNetwork_VLANParent` pins that a VLAN parent
  ignores `Addresses`, so sub-interface addresses cannot leak onto it. That
  contract is kept. The source address travels in a new, explicit
  `InterfaceConfig.VLANParentAddresses` field instead. `KeepAddresses` is set
  only when the parent carries the source, so a tagged-only RETH parent,
  including the loss-cluster reth0, renders byte-for-byte as before.
