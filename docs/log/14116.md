# Issue #14116 — stop userspace-dp IPv6 fragment walk at non-first fragments

## Why

The XDP shim half was fixed by #13959: the shim's `walk_ipv6_ext_headers`
stops after a readable non-first Fragment header because bytes past it are
fragment payload, not an extension-header chain. The userspace-dp walker
`walk_ipv6_ext_chain` (`userspace-dp/src/afxdp/frame/inspect.rs`) still
followed the Fragment header's Next Header into that payload. Payload
beginning with what looks like an AH or Destination Options header with an
overlarge declared length made the walk return `Truncated`; every L4-offset
consumer (forwarding resolvers, the GRE inner-protocol decoder via
`packet_rel_l4_offset_and_protocol`, NAT64, embedded-ICMP) then failed
closed on a valid admitted IPv6 fragment — an availability loss, and a
shim/userspace parity divergence on the same packet.

## What

- `walk_ipv6_ext_chain` now stops at the first readable Fragment header
  carrying non-zero offset bits (`non_first_fragment_offset_seen`, latched
  by `record_fragment_sighting`) and returns the new
  `ExtChainOutcome::NonFirstFragment` verdict. Fragment sighting fields
  (`fragment`, `first_non_atomic_fragment`, `ah_present`,
  `fragment_truncated`) keep their existing semantics for sightings at or
  before the stop. First/atomic fragments continue through the chain
  unchanged; truncated/over-limit/bounds behavior is unchanged.
- All existing L4 consumers fold the new verdict fail-closed through their
  existing non-`L4` arms (`None`/`false`), except NAT64's
  `ipv6_l4_offset_and_protocol`, which deliberately recovers
  `(fragment.header_offset + 8, fragment Next Header)` for a
  `NonFirstFragment` outcome so the L3-only non-first translator
  (`write_v6_to_v4_nonfirst_into`, `v6_to_v4_output_len`) keeps translating
  non-first fragments exactly as before — without walking payload.
- `protocol_from_declared_packet` folds `NonFirstFragment` to `None` in its
  outcome match (unreachable in practice: the non-first sighting returns
  the Fragment Next Header or AH earlier in that function).
- The NDP NA parser (`parser.rs::parse_ndp_neighbor_advert`) counts a
  `NonFirstFragment` stop whose Fragment header names ICMPv6 once into
  `NDP_NA_FRAG_REFUSED` before refusing: pre-fix the walk resolved the
  payload NA shape and the #9893 gate counted it; refusing silently would
  have lost that fail-closed audit count (its full-suite regression was
  `parse_ndp_na_9893_non_first_fragment_refused_and_counted`).
- Doc updates: the `ExtChainOutcome::NonFirstFragment` variant, the walk's
  stop contract in `walk_ipv6_ext_chain`'s docs, and the frame README's
  verdict list / repeated-fragment-status note.
- Tests: new `ext_walk_nonfirst_fragment_payload_is_not_walked_14116` in
  `tests_ipv6_ext_walk.rs` (overlong DestOpts/AH payload → NonFirstFragment
  with sighted status and no L4 surrendered; in-bounds payload chain still
  not walked; first-fragment overlong headers stay `Truncated`; valid
  first-fragment chain still resolves); the #13959 parity test
  `nonfirst_fragment_payload_is_not_walked_as_ah_or_destopts_13959` now also
  asserts the userspace walk stops identically, the shim/userspace corpus
  folds both sides' non-first stop to the same `NoL4` verdict, and
  `ext_walk_over_limit_records_fragment_and_fails_l4_closed` now uses a
  first fragment for its OverLimit case plus a non-first case asserting the
  stop takes precedence over walking payload to the bound.

  FAILED (pre-fix walk resolved payload to `L4(56, 6)` / walked the
  overlong payload header instead of stopping) and
  `ext_walk_over_limit_records_fragment_and_fails_l4_closed` FAILED
  (pre-fix `OverLimit` where the fix stops at the non-first header);
  the adapted #13959 parity case passed on base, as expected — the shim
  side already stops.
- GREEN (fix worktree `/var/worktrees/wt-14116`):
  `CARGO_TARGET_DIR=/var/worktrees/.cache/cargo-14116 cargo test --manifest-path userspace-dp/Cargo.toml --bins -- ext_walk shim_walk nonfirst_fragment nat64_2562 nat64_v6_nonfirst nat64_v6_to_v4_output_len`
  → 36 passed, 0 failed (includes the parity corpus over 9423 chain/L3
  pairs, NAT64 non-first translation, and MTU-refragmentation tests).
  The first run of this set against the initial patch showed 6 failures —
  all consumers that legitimately depended on payload not being an L4
  (NAT64 L3-only translation paths, the over-limit-with-non-first test,
  and the parity corpus fold); each is addressed above and now passes.
- Full `--bins` suite: head and pristine-base failure sets are identical
  (29 pre-existing failures on `origin/master` 4adefde7a, none in the
  walker/NAT64/NDP area); an intermediate head run exposed exactly one
  new failure (`parse_ndp_na_9893_non_first_fragment_refused_and_counted`),
  fixed by the counted NDP refusal above and green in the final run.

## Risk

Non-first fragments still yield no L4 tuple on forwarding paths (unchanged
no-L4 doctrine); the only behavioral delta is that a valid non-first
fragment is no longer additionally failed as `Truncated`/`OverLimit` by a
payload-shaped chain, and NAT64 non-first translation is preserved via the
recorded Fragment sighting instead of a payload walk. Screen extraction
keeps its own walker (it already breaks at non-first fragments). The shim
walker and BPF artifacts are untouched — no `make generate` needed.
