# Issue #14716 — un-lexed edit path desyncs authorization from execution

## Defect

Both CLIs stored the interactive `edit` cursor as raw `strings.Fields`
tokens (`pkg/cli/cli_dispatch.go`, `cmd/cli/shared.go`). The
authorization gate (`config.AuthorizeConfigMutation`) lexes only the
mutation *line* and prepends the stored cursor verbatim, while execution
re-joins the same raw tokens and the store lexer (`NewLexer`, reached
via `ParseSetVerbGroupedClosed`) skips `/* ... */` comments and unquotes
`"..."` strings. So:

- `edit /* interfaces */ "system"` + `set root-authentication ...` was
  gated as `/* interfaces */ "system" root-authentication ...` —
  an anchored deny `^system root-authentication` missed, and comment
  text could satisfy `allow-configuration "^interfaces"` — but executed
  as `system root-authentication ...`.
- `edit "system"` alone desynced the same way (quote-only).
- `edit system /*` + `set */ ...` completed a block comment across the
  two lines at execution while the gate saw the raw fragments.

This is the gate-judges-one-string / executor-parses-another class that
#9938 fixed for the mutation line and #7172 for plain `edit system`.

## Fix

Shared lexing at the cursor boundary, in `pkg/config` beside the gate
(`authz_config_mutation_9154.go`):

- `ParseConfigPath` / `ParseEditFragment`: lex a typed path fragment or
  full `edit ...` line with the store lexer; malformed input
  (unterminated string/comment, braces, semicolons) is refused, never
  stored raw.
- `NormalizeEditPathTokens`: lex an already-stored cursor (joined form
  first, so comments spanning stored tokens collapse; per-token fallback
  for a cursor whose trailing comment opener is not yet closed).
- `AuthorizeConfigMutation` normalizes the cursor against the line
  tokens, including a block comment spanning the cursor/line boundary
  (the split-comment construction above), before resolving paths.

Writers/executors now store and use only lexed cursors: local
`dispatchConfig` edit/set/delete/deactivate/activate/annotate arms,
`handleCopyRename`/`handleInsert`, and the remote CLI's
edit/set/delete/deactivate/activate/annotate/copy/rename/insert arms.
Plain (undecorated) cursors are unchanged.

NOT changed: the store's `SetEditPath` API, `show` path rendering,
navigation semantics for well-formed paths, or the gRPC/REST surfaces
(they pass a nil cursor and gate the resolved line they receive, which
now always carries lexed tokens from either CLI).
