# Issue #14698 — Reject-only `from protocol` terms activate FRR redistribution

- **Issue:** A defensive Junos guard `term guard { from protocol bgp; then reject; }` in an export policy activated `redistribute bgp route-map <export>-bgp-xpf-redist` under OSPF/RIP/IS-IS/BGP, because every `term.FromProtocols` token enrolled its source protocol with no `term.Action` check. The synthesized per-source map copies the guard plus every protocol-agnostic term (and the policy default), so any BGP route the agnostic accept permits leaks. A no-from reject term likewise expanded to the whole node-fitting domain (#14380). Unknown lenient-path tokens also enrolled raw, risking FRR-invalid `redistribute <unknown>`.
- **Mechanism:** `redistProtocolsFiltered` and the policy branch of `redistributeEntriesAt` (`pkg/frr/redistribute.go`) enumerated sources from explicit `FromProtocols` (and the #14380 no-from expansion) regardless of `Action`; `redistPolicyForProtocol` then built the per-source map from all applying terms. Junos semantics: `from protocol` in a reject term is a filter condition, never a redistribution request.
- **What:** Enrollment now requires a term that can accept (mirroring `renderPolicyTermSequences` action mapping: terminating accept, non-terminating fall-through, or bare `then next policy`; cost-set rejecting terms — `then reject` incl. contradictory NextPolicy+action — never enroll). Explicit tokens are gated through `knownRedistProtocol` (the bare-export allowlist). A no-from reject term no longer expands the domain. `redistFilterPermitDominated14698` drops a source named by a reject term that no accept-capable term can match (not under an authored default-accept), covering the mixed guard+agnostic shape at the map-definition layer (`redistProtocolsFiltered`, used by `generatePolicyOptions`/`redistReferencedProtocols14380`/collision belt) and at the attachment layer (`redistributeEntriesAt`, also serving the #14586 BGP export entries and IS-IS grammar). Reject terms still ride in enrolled sources' filtered maps via `redistPolicyForProtocol`, preserving deny ordering. NOT changed: `policyHasStaticSource11447` (its QNH overlay map contains only static-source terms and originates nothing by itself; the actual `redistribute` attachment is gated), bare-protocol export tokens, and the BGP route-map-out path.
- **Scoping note:** Where a protocol-agnostic *accept* term can genuinely permit the guarded protocol's routes (e.g. community accept after a prefix-list-scoped bgp reject guard), Junos would originate those routes, so the source stays enrolled with the guard deny first in its map — pinned by `TestRedistributeRejectGuardWithAgnosticAcceptKeepsSource14698`. The issue's decisive fixture (no `redistribute bgp`, `redistribute connected` preserved) is pinned with the agnostic term reject-only, under which the guarded source can never permit.
- **Pinned tests updated (they encoded the bug):** `keywordNamedPolicy14369` reject→accept (the #14369 precedence property is action-independent; reject-only no longer enrolls), `TestGenerateProtocols_BGPExportPrefixOnly` no-from reject→accept (idem for #2473/#14586 origination), `TestRedistributeOperandsAreSanitized_8597` protocol-operand subtest now pins the stronger allowlist refusal (renders nothing) while the route-map operand still exercises the sanitize belt, and `TestRedistProtocolMapGeneratedVsGeneratedRefused12065` split into `TestRedistProtocolMapUnknownTokenNoGeneratedMap12065` (unknown token generates no map) plus `TestRedistProtocolMapGeneratedVsGeneratedBranch12065` (branch driven via `redistProtocolMapCollisionFiltered`).
- **New tests:** `pkg/frr/redistribute_rejectonly_14698_test.go` — decisive fixture + managed-section end-to-end (no attach, no `EXP-bgp-xpf-redist` definition, connected preserved), agnostic-accept permit-capable control (source kept, guard deny precedes permit), reject+accept same protocol enrolls, no-from reject-only enrolls/defines nothing, no-from reject + explicit accept enrolls only the accept's source, unknown token enrolls nothing, `redistProtocols` unit gate cells, and the #14586 BGP-export reject-only source cell.
