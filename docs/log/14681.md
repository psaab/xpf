# Nested `then`/`match` under scalar policy leaf dropped to permit (#14681)

## Why

`allDescendantsDeclared9792` (the nested-shape half of the #9792
packed/nested leaf-run guard) accepted any descendant whose head was
merely declared in the container, omitting the container/wildcard check
its packed sibling applies (#13108). Policy `match` and `then` are
declared container children of the policy schema, so
`scheduler-name work-hours { then deny; }` (and the flat-set spelling)
qualified as a resolvable run: `hoistAndSplitRun8939` lifted the container
statement beside the scalar leaf, `policyUnresolvedScalarLeafTails` then
saw only clean len-2 scalar leaves, and `compilePolicy` read `match`/
`then` from the unexpanded node — the hoisted clause was compiled by
nobody. Probe on base `91d5ccc48c` (scheduler `work-hours` defined so the
reference gate cannot mask it): all six braced/flat shapes compiled
lenient `Action=0 (PolicyPermit)`, `LenientContentDropped=false`, no
strict `CompileConfig` error. `SchemaValidate` alone rejected them, and
the tolerant load / HA-sync path never runs it — a persisted
`then deny` silently became permit. `scheduler-name` also lacked the
`scalar: true` tag `description` carries, so its schema gate was weaker.

## What

- `pkg/config/flat_run_residue_9792.go`: `allDescendantsDeclared9792`
  now rejects a descendant that is a container (`len(children) > 0`) or
  wildcard child of the container, mirroring the packed branch. A
  `multi` descendant stays admissible (its children are values, #2419).
  The run stays unexpanded, so the tail remains on the scalar leaf and
  the existing #12634 predicate poisons it leniently and rejects it
  strictly — no new diagnostic, no new flag.
- `pkg/config/schema_security.go`: both policy `scheduler-name` leaves
  (zone-pair and global) gain `scalar: true`, like `description`, so
  strict `SchemaValidate` treats a trailing container tail as a scalar
  arity violation as well.
- `pkg/config/README.md`: the #12634 paragraph records the #14681
  container-tail case.
- Tests: `TestPolicyScalarLeafNestedThenOrMatchRejected12634` (the
  decisive fixture named in the issue — braced/flat ×
  scheduler-name/description × then/match), a resolved-run control, and
  container/wildcard/multi rows in `TestPackedOrNestedLeafRunGuard9792`
  on a synthetic schema so only the new arm can reject them.

NOT changed: `compilePolicy`'s readers, the #12634 predicate or message,
`hoistAndSplitRun8939`, or any other #9792 site's schema. The guard is
shared, so sibling sites gain the container-tail refusal; their declared
scalar runs are unaffected (covered below).

## Validation

- RED (fix stashed, tests present, base `91d5ccc48c`): all six
  `TestPolicyScalarLeafNestedThenOrMatchRejected12634` cells fail with
  "nested container tail under scalar leaf … was hoisted and dropped
  without poison"; both new guard rows fail
  (`packedOrNestedLeafRun9792 = true, want false`); the multi control
  passes pre-fix as designed.
- GREEN: named fixture (6 cells), resolved-run control, all 20 guard
  rows, `TestKnownScalarLeaf*12634`, `TestFlatRunResidueSchemasResolve9792`
  pass.
- Base probe (bounded test, removed after): shapes A/B/C/D from the
  issue reproduced exactly as the re-reviewers reported.
- `TestSchemaSpellingDifferentialGate` is RED on unmodified
  `origin/master` `9798e88a44` as well as with this fix (identical
  #2419-class failures, e.g. `security zones security-zone <*> screen`),
  so it is base-attributed, not a regression of this change. The gate
  is also extremely slow under campaign load (~24 min); it was run
  isolated on both trees rather than as part of the full suite.

## Risk

The shared guard now refuses nested runs whose tail contains a declared
container/wildcard at any #9792 site; a site that legitimately relied on
hoisting such a tail would keep it nested and surface through its own
reader diagnostics instead. The spelling/leaf-run differential gates and
the full config suite are the check. No dataplane, wire, or HA format
change; lenient loads still boot (#1960) — the affected policy is
poisoned fail-closed rather than dropped.
