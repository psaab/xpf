# Issue #13284 — NAT64 telemetry export

## Why

The NAT64 builder already increments process-global counters when an aggregate
allocator budget refusal installs an empty-pool prefix or when deterministic
NAPT64 construction downgrades to dynamic PAT. Neither counter reached
`ProcessStatus`, and the live refused-prefix count was likewise not projected.
As a result, the operator-facing status and Prometheus surfaces hid both a
fail-closed NAT64 capacity event and a CGN subscriber-attribution downgrade.

## What

Added additive/defaulted `ProcessStatus` fields for the two cumulative counters
and the currently installed over-budget prefix census. The coordinator snapshots
the process-global atomics and counts live refused prefixes; `refresh_status`
projects those values. Mirrored the fields in Go userspace status and exported
`xpf_userspace_nat64_over_budget_total`,
`xpf_userspace_nat64_over_budget_prefixes`, and
`xpf_userspace_nat64_deterministic_v6_downgrades_total` to Prometheus. Regression
coverage exercises the real status refresh + JSON wire projection and the Go
metric emission.

## Risk

The two totals remain process-local and reset on helper restart, matching the
source atomics' lifetime. The added wire fields are additive and defaulted for
older helper compatibility; the prefix census is a current-state gauge, not a
cumulative counter.
