# #16533: packed firewall-filter `then` tail with unmodelled token installed terminating ACCEPT

- **Timestamp**: 2026-10-24
- **Action**: Fixed the packed-term fail-open where
  `term t1 from protocol tcp then dicsard;` (and `then sample;`, the inet6
  spelling, and any unmodelled token after known modifiers) passed strict
  commit with zero warnings and compiled to `Action ""`, which Rust maps to
  terminating Accept. Root cause: the whole term body packs onto the term
  node's Keys with no Children; `packedBodyChildren` declines on the first
  unmodelled token and returns the (empty) Children, so `compileFirewall`
  saw no `then` child, `compileFilterThen` never ran, `UnknownActions`
  stayed empty, and both fail-closed gates (`validateFilterActionsStrict`,
  `failClosedUnknownFilterAction`) stayed silent. The `from` half survived
  only via the #10071 raw re-scan, which had no `then` counterpart.
  Two halves:
  - `pkg/config/compiler_firewall.go`: when `packedBody` declines
    (`termBody == termInst.node`), re-scan the raw packed `then` segment(s)
    via the new `firewallPackedTermThenNodes` (mirrors
    `firewallPackedTermFromStatements`: `from`/`then` bound segments,
    quoted/bracketed tokens are values, fresh nodes carry provenance) and
    run them through `compileFilterThen`, so every unrecognised token lands
    in `UnknownActions` — strict rejects naming the token, tolerant warns
    and `failClosedUnknownFilterAction` forces discard. Also, the children
    arm of `compileFilterThen` now records a fused token past `next` other
    than the `term` qualifier as unknown instead of a clean fall-through.
  - `pkg/config/schema_cos.go`: model `next` (with optional `term` child)
    under both family inet and inet6 filter-term `then`, mirroring
    `reject`'s message-type children. `next term` was compiler-read
    (`NextTerm`) but never schema-declared, so the packed expander declined
    on it and dropped the entire tail — `term t0 then count all next term;`
    now compiles strict-clean to `NextTerm=true, Count="all"`.
  Packed `discard`/`accept` and all braced controls are unchanged.
- **File(s)**: `pkg/config/compiler_firewall.go`,
  `pkg/config/schema_cos.go`,
  `pkg/config/firewall_packed_then_16533_test.go` (new),

- **Validation**: New `TestPackedThen*16533` (6 strict-reject rows naming
  the token + lenient discard/warning, 4 next-term rows, controls) pass;
  pre-fix probe reproduced every row strict-clean with `Action ""`.
  Existing `TestFilterAction_*`, `TestPackedFilterTermBodyMatchesNested_6685`
  pass. Full `pkg/config` suite failures are pre-existing on unmodified
  origin/master (verified by file-swap base check: `TestDualASTDifferential`
  panic, `TestSchemaSpellingGateCoverageIsGated_7484`,
  `TestRemainingUndeclaredKeywords*8807` and unrelated strict-gate failures
  reproduce identically without this change; the 7484 failure is a
  pre-existing 858-vs-804 ratchet drift, and this change's +4 compared
  `then next term` leaves move it to 862 — the floor/members ratchet was
  deliberately NOT tightened here to avoid absorbing unrelated drift).
