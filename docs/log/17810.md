# #17810 — bind filter syslog routing to the applied snapshot generation

- **Timestamp:** 2026-10-28
- **Branch:** `fix/17810-campaign`
- **Files:** `debian/changelog`, `docs/log/17810.md`, `pkg/daemon/daemon_policy_invalidate_capture.go`, `pkg/daemon/daemon_system.go`, `pkg/daemon/filter_log_syslog_wiring_6859_test.go`, `pkg/dataplane/userspace/applied_nat_view.go`, `pkg/dataplane/userspace/legacy_dataplane.go`, `pkg/dataplane/userspace/manager.go`

## STEP-0 (verified at origin/master 9aa007277db1b5ee0d98e9971eb979680c612b37)

The defect was live: `applySyslogConfig` installed the filter-term projection under `LastApplyResult.Generation`; the userspace manager retains that result from a full apply, while successful retained-snapshot publishes adopt a newer snapshot generation and refresh the manager's applied identity without replacing the full-apply result. The syslog retry calls `applySyslogConfig`, and `allowsAtGeneration` rejects every H-stamped filter event when the map has been reinstalled under stale G.

## Why

After a successful partial snapshot publish advanced the applied filter snapshot from G to H, a syslog stream retry could reinstall the unchanged filter-term map under the older full-apply G. The generation gate then suppressed all FILTER_LOG events stamped H until another apply boundary happened to restore alignment.

## What

- Expose the userspace manager's current applied snapshot generation through the legacy runtime adapter. This identity advances on successful retained-snapshot publishes, unlike `LastApplyResult`.
- Resolve the last apply result and applied snapshot identity from one published runtime value. Install the map under the applied identity when available, preserving the last-full-apply fallback for runtimes without that capability.
- Treat `SnapshotPublishDeferred` as pending only while the applied generation is older than the deferred full-apply generation; the stored flag remains set after publication.
- Prevent deferred completion from overwriting a newer applied generation.
- Cover both a retry overwriting an already-installed H map with stale G and a deferred-G→partial-H→retry sequence; the H-stamped `then syslog` event reaches a loopback UDP collector in each case.

## Validation

- **RED on unmodified origin/master:** `go test ./pkg/daemon -run '^TestSyslogRetryKeepsFilterMapAtAppliedSnapshotGeneration17810$' -count=1` failed because retry installed generation `41,true` instead of applied partial generation 42.
- **GREEN:** all named cells in `filter_log_syslog_wiring_6859_test.go` passed, including retry-overwrite and deferred-G→partial-H retry controls; all named generation-routing cells in `filter_log_generation_16775_test.go` passed. Exact named tests only; no broad package suite was run.
- `gofmt` applied to the changed Go files.

## Risk

Only the filter-term syslog map's generation authority changes. Genuinely stale stamped events remain fail-closed; deferred maps remain unchanged while the applied identity is older than the deferred full generation; runtimes without the applied-snapshot capability keep the existing full-apply fallback. The regression uses loopback UDP and does not mutate host interfaces.
