# Issues #18954 + #18955 — per-arm tails for the four remaining strict-arm "commits clean" diagnostics

## Why

Four more message builders carried the #18951 defect class: the diagnostic text
claims the configuration "compiles to NOTHING: it commits clean, renders in
`show configuration` …" on an arm where the caller returns it as a **strict,
commit-refusing error** — the refusal text itself asserts the commit succeeds.
The compiles-to-NOTHING wording is only true on the lenient arm, where the
offending token is warned about and skipped/dropped and the committed config
silently lacks it.

- **#18954** — `validateFirewallFilterFamilyTokensAST`,
  `pkg/config/compiler_firewall_family_9017.go:156` (the #9017 firewall
  unknown-family gate; tail ended "… enforces no rule at all (#9017)").
- **#18955** — three builders:
  - `snmpCommunityUnknownMessage15124`, `pkg/config/compiler_system_snmp.go:394-397` (#15124);
  - the `report` closure of `validateVRRPGroupChildrenAST15046`, `pkg/config/compiler_vrrp_children_15046.go:110-114` (#15046);
  - the top-level sites (`:236`/`:253`) of `validateEventOptionsInertAST14660`, `pkg/config/event_options_inert_14660.go:218-222` (#14660).

Found by the #18951/#18953 residual sweeps (GLM seat). Same fix shape as
PR #18953 (`unknownFamilyMsg17196`, unmerged at the time of this PR): per-arm
tail in the ONE builder per message, lenient wording unchanged.

## What

1. **Per-arm tail in the ONE builder per message** — head unchanged, tail
   selected by the flag the builder already holds:
   - strict: `— the commit is refused (#NNNN)` (snmp: `— the commit is
     refused;` mid-message, before the arm-independent mistyped-restriction
     rationale clause);
   - lenient: the original compiles-to-NOTHING wording, verbatim, per builder
     (9017 "enforces no rule at all"; 15124 "has no effect" + quarantine note;
     15046 "has no effect"; 14660 "no event policy is created").
2. **Cells re-pinned with LITERAL constants** (`strictTail9017` /
   `lenientTail9017`, `strictTail15124` / `lenientTail15124`, `strictTail15046`
   / `lenientTail15046`, `strictTail14660` / `lenientTail14660`) — literals,
   not builder references, so a tail swap cannot satisfy them tautologically.
   Nothing weakened: existing token/head pins kept, the shared head
   ("is not a known address family" / "is not a community statement" /
   "is not a vrrp-group statement" / "is not an event-options statement")
   newly pinned where it was absent, arm tails added on both arms.
3. The #14660 policy-body sites (`:287` policy children, `:299` event names,
   `:313` `then` actions) and `event_options_within.go` (#16654) carry their
   own wordings that do NOT claim the commit succeeds — left unchanged.
