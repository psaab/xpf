# Issue #13637: enforce ingress input filters on IPsec passthrough

## Why

Stage 11 claims IPsec/IKE packets before ordinary session-miss input-filter
enforcement. Packets matching an ingress interface input-filter discard or
reject could therefore be reinjected to the host even though the regular
forwarding path would deny them. The Stage 10 pre-screen predicate also skips
screen evaluation when it finds a static input-filter denial, making Stage 11
the required terminal enforcement point for claimed packets.

## What

Run the shared counted non-PBR input-filter evaluator in Stage 11's passthrough
arm before fragment reservation, SA handling, or IKE seed creation. Use the
existing filter-terminal path for non-PBR reject replies, logging, and drops.
For route-lookup-affecting filters, also run the counted routing-instance
verdict; a matched discard/reject terminates before host passthrough.
The real descriptor poll loop is pinned with an IPv4 local-IKE
`routing-instance` discard and verifies its filter counter; companion
evaluator coverage checks source-specific IPv4 and IPv6 UDP/500 denies and
verifies an unrelated IPv4 source still passes.

## Risk

Stage 11 passthrough packets enforce counted non-PBR input-filter verdicts and
route-filter `routing-instance` discard/reject verdicts before host handoff.
Denied packets are dropped before reinjection or IKE-seed side effects.
Shared HA cluster validation was not attempted: despite a one-time peer clock
correction, chrony remains unsynchronized and the CLI still reports a peer
wall-clock warning/no configured time source. No cluster commands or mutations
were made for this issue.
