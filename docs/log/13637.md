# Issue #13637: enforce ingress input filters on IPsec passthrough

## Why

Stage 11 claims IPsec/IKE packets before ordinary session-miss input-filter
enforcement. Packets matching an ingress interface input-filter discard or
reject could therefore be reinjected to the host even though the regular
forwarding path would deny them. The Stage 10 pre-screen predicate also skips
screen evaluation when it finds a static input-filter denial, making Stage 11
the required terminal enforcement point for claimed packets.

## What

Run the shared counted non-PBR input-filter evaluator in Stage 11's passthrough
arm before fragment reservation, SA handling, lo0/host policy, reinjection, or
IKE seed creation. Route reject replies, filter-log emission, and terminal drop
accounting through the existing filter-terminal helper. The evaluator uses the
non-routing count policy because Stage 11 does not proceed to route evaluation.
The real descriptor poll loop is pinned with an IPv4 local-IKE input-filter
deny; companion evaluator coverage checks source-specific IPv4 and IPv6
UDP/500 denies and verifies an unrelated IPv4 source still passes.

## Risk

Stage 11 passthrough packets with an interface input filter now follow the same
counted ingress-filter verdict as ordinary session-miss traffic; denied packets
are dropped before Stage 11 reinjection or IKE-seed side effects. Shared HA
cluster validation was not attempted: despite a one-time peer clock correction,
chrony remains unsynchronized and the CLI still reports a peer wall-clock
warning/no configured time source. No cluster commands or mutations were made
for this issue.
