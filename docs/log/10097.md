# #10097 — Export NDP learn-refusal counters

Work log for issue #10097. The counters added by #9893 are now carried through
all existing userspace status and Prometheus neighbor-counter surfaces.

- **Counters:** `NDP_NA_FRAG_REFUSED` is exposed as
  `xpf_userspace_ndp_na_frag_refused_total`; `NDP_NA_BAD_SOURCE_REFUSED` is
  exposed as `xpf_userspace_ndp_na_bad_source_refused_total`.
- **Path:** parser atomic → coordinator status reader → Rust `ProcessStatus`
  JSON → Go userspace status → existing neighbor Prometheus emitter. Both
  fields are additive/defaulted for older helpers.
- **Scope:** Fragment-header and invalid-source refusal counters remain
  separate from the existing dynamic-neighbor cap counter; no truncated,
  over-limit, or no-next-header counter is added because #9893 deliberately
  cannot confirm those frames as NA-shaped.
- **RED:** before the exporter was wired,
  `go test ./pkg/api -run '^TestCollectorDescriptorCoverage$' -count=1`
  failed because both new metric families were absent from the gathered output.
- **GREEN:** the #9893 parser cells drive refused learns and read the
  coordinator status accessors; the Go scrape test asserts both refusal values
  and the pre-existing dynamic-neighbor cap value independently; the
  descriptor-coverage canary pins both metric families.

  `protocol::tests` 87 passed; `afxdp::coordinator` 280 passed;
