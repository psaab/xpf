# #15127 — default established TCP session timeout 300 s → 1800 s (A93-02)

- **Timestamp**: 2026-10-19
- **Action**: Raised the unset-`established-timeout` fallback from 300 s to
  the Junos default 1800 s in the Rust dataplane, the Go mirror constant,
  the inverted pin test and the show surface.

## Defect

With no `security flow tcp-session established-timeout` and no
per-application `inactivity-timeout`, an established TCP session idled out
at 300 s: `DEFAULT_TCP_SESSION_TIMEOUT_NS = 300_000_000_000` in
`userspace-dp/src/session/mod.rs`, mirrored by
`DataplaneTCPEstablishedWindowSecs = 300` in
`pkg/config/flow_tcp_timeouts_6539.go`. An unset leaf lowers as 0 on the
wire (`pkg/dataplane/userspace/flow.go` fills `TCPSessionTimeout` only
from the configured leaf) and the helper falls back to its own constant,
so migrated Junos configs lost idle TCP sessions (SSH without keepalives,
DB/LDAP pools, idle SMB) after 5–30 min idle; the next segment then hit
the SYN-first session check and dropped. The #6539 pin test even fataled
if the default ever equalled 1800 — it pinned the divergence as intended.

## Fix

- `userspace-dp/src/session/mod.rs`: `DEFAULT_TCP_SESSION_TIMEOUT_NS`
  300 s → `1_800_000_000_000` ns (1800 s), with the #15127 comment.
- `pkg/config/flow_tcp_timeouts_6539.go`: `DataplaneTCPEstablishedWindowSecs`
  300 → 1800; the mirrored-constants header and the
  `TCPSessionTimeoutDataplaneDefault` doc now record that Junos book value
  and dataplane fallback agree after #15127 (the function still reports
  the dataplane fallback, mirrored from Rust).
- Show surface: no code change needed — CLI renders
  `1800s (default)` from `TCPSessionTimeoutDataplaneDefault`, satisfying
  the acceptance "show output prints `1800s (default)`". Its test guard
  that forbade `1800s` is inverted to require exactly that string.
- `pkg/config/flow_tcp_timeouts_6539_test.go`: the inverted pin
  (`== 1800` fatal) now requires `== 1800`.
- Bumped test drivers that crossed the old 300 s default to cross 1800 s
  (session HA expiry, companion-keepalive, admission, probe-hit, hit-
  authority window, session-glue) and updated stale 300 s prose in
  `session/README.md`, `docs/config-schema.md`, the #8125 conntrack
  comments/tests and close-state comments. Configured-timeout paths
  (explicit `established-timeout`, per-app override, opening/closing/
  TIME_WAIT/RST windows) are untouched.

NOT changed: the alternative "document 300 s as a deliberate divergence"
— the issue's primary fix direction (Junos parity 1800 s) was taken.

## Regression (RED → GREEN)

- Rust `session::tests::unset_established_timeout_survives_301s_idle_15127`:
  asserts `SessionTimeouts::default()`/`from_seconds(0,0,0)` stamp 1800 s,
  installs an established forward/reverse pair on default timeouts via the
  real `SessionTable`, asserts both halves survive
  `expire_stale_entries` at +301 s and reap at +1801 s, and a control pair
  with explicit `from_seconds(300,0,0)` still reaps at +301 s.
  RED pre-fix: `left: 300000000000, right: 1800000000000`.
- Go `TestTCPSessionTimeoutDataplaneDefault_7342` pin inverted to require
  1800. RED pre-fix: `established default is 300, want 1800`.
  `TestTCPSessionTimeoutWindowsMatchRust_6539` keeps Go↔Rust drift fatal.
- Neighbouring controls stay green: opening 20 s / closing 30 s /
  TIME_WAIT 30 s / RST 2 s / UDP 60 s / ICMP 60 s defaults, configured
  120 s snapshot lowering, and the CLI unset-stanza render.

## Validation

- Go: `go test ./pkg/config/ -run TestTCPSessionTimeout` and
  `go test ./pkg/cli/ -run TestShowFlowTimeouts` pass after the fix
  (pin was RED before: `established default is 300, want 1800`).
- Rust: RED run on pre-fix constant
  (`left: 300000000000, right: 1800000000000`); GREEN after the fix:
  `unset_established_timeout_survives_301s_idle_15127`,
  `default_timeouts_match_original_values`, `from_seconds_zero*`,
  `forwarding_state_includes_session_timeouts`,
  `conntrack_timeout_column_reports_the_session_window_8125`,
  `both_halves_idle_still_expire`, `reverse_activity_keeps_forward_half_alive`,
  the HA `expire_*` set (22 tests incl. the new regression) and the full
  `session::` module pass. HA expiry tests that drive `past_tcp_timeout`
  pin a short explicit 300 s timeout on their tables so the wheel sweep
  stays bounded (the 1800 s default would re-bucket ~7x and inflate
  `held_standby` counts — observed as 7-vs-1 failures before the pin).
