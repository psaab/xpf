# #9546 — `SessionValue.RoutingDomain` does not survive the BPF session mirror

## 2026-09-10 — Action: re-verify at base, and choose the carrier by what can go wrong
- **File(s)**: none (measurement)
- Privileged "before" at `3b24fe26e`:
  `TestDeleteSessionItselfNamesTheDomainOnTheWire9146` FAILS, `routing_domain=0`.
- Who writes the mirror decides everything, and it is BOTH: Go
  (`Manager.SetSessionV4` -> `bpfShim.SetSessionV4` -> `toBPF`) and the helper
  (`publish_conntrack::build_conntrack_value_v4/v6`, 2 construction sites).
- **Rejected: the 4-byte hole at offsets 12-15** (no size change). Rust
  struct-literal padding is uninitialized, and pins persist in bpffs across a
  restart, so rows an old helper wrote would be read back as a garbage domain even
  with NO binary skew — and a garbage value that lands in-band names ANOTHER
  TENANT's row. Same size means nothing refuses it.
- **Chosen: append after `ingress_vlan_id`** — no existing offset moves; the u32
  skips the 2 unused pad bytes to 144/192 and the 8-byte alignment grows the
  structs 144 -> 152 / 192 -> 200. A size change is what the live-pin pre-flight
  and `loadOrCreatePinnedShimMapWith` refuse, so old rows are never misread.
  Precedent: #5460 and #4983 grew this exact struct and paid the same crossing.
- **Encoding**: the helper stamps `routing_domain_to_wire(key.routing_domain)` —
  the encoding the event stream already emits, so a delete names what the install
  named; default instance becomes `1`, an exact delete rather than a probe.
- **Reverse rows state `WIRE_ABSENT`**: `reverse_wire_key` / `reverse_canonical_key`
  build reverse-match keys with `routing_domain: 0` on purpose (#7160), so
  encoding it would assert "default instance" for a tenant flow — a false claim,
  not an absence. Both delete paths scope the reverse companion with the FORWARD
  row's domain, so nothing needs more.
- **Bound**: the BPF key has no domain axis (#7160), so two tenants sharing a
  5-tuple share one mirror row. This turns "both refused as ambiguous" into "the
  surviving row deletes exactly"; it does not de-alias.
