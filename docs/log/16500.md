# #16500 — baseline-relative sync-idle predicate never idles when the gap shrinks

- **Timestamp**: 2026-10-24
- **Action**: The #16289 baseline-relative idle test in
  `ha_session_sync_idle_sample` required equality of the deltas since
  the baseline (`sent - baseline_sent == received - baseline_received`).
  When creates were in flight at the first sample and then delivered,
  the gap shrank (20/17 -> 20/20) and equality never held again; likewise
  creates landing between the two non-atomic CLI captures could leave
  received ahead at the baseline (20/22) and sent later reaching that
  already-received count (22/22), also never equal in deltas. Both waits
  (failover-gate `ha_wait_for_session_sync_idle` before traffic / RG1
  failback / fw0 crash, and the userspace sibling which sources the same
  helper) then timed out with FAIL on a caught-up pair and VOIDed the
  downstream RG1 cells. Idle is now
  `(sent - baseline_sent <= received - baseline_received) || (sent == received)`
  with `pending == 0`: a gap that shrinks or holds, or counters meeting
  in absolute terms, is caught up; a gap that grows since the baseline
  (20/20 -> 25/20, counters unequal) stays not idle. No caller change is
  needed — both wait loops consume the helper verdict and keep their
  baseline-keeping / rewind-only re-baseline discipline unchanged.
  NOT changed: verdicts 1/2/3, pending/drained parsing, the
  3-consecutive-sample policy, any production daemon code (lab harness
  only, no product effect).
- **File(s)**: `test/incus/ha-assurance-lib.sh`,

- **Validation**: `bash test/incus/ha-assurance-selftest.sh` PASS,
