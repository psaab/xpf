# #18669: operational `show configuration [<path>] | compare rollback <N>` on both consoles

## Decision (recorded before the code, per the Step-0 disposition)

**Bare operational `show configuration | compare` (no `rollback <N>`) is
REFUSED on both consoles** with the non-nil error

```
syntax error: | compare on operational show configuration requires rollback <N>
```

xpf does **not** invent an active-vs-rollback-1 meaning for the bare form.
Junos requires an argument there; silently diffing against rollback 1 would
surprise an operator who typed the bare form expecting the candidate diff of
configuration mode. Only `| compare rollback <N>` is implemented, diffing
rollback slot N against the **ACTIVE** configuration (never the candidate),
optionally scoped to the `<path>` subtree before the pipe. Malformed compare
forms (`| compare rollback` without N, a non-numeric/negative/out-of-range N,
trailing tokens, `| compare <other>`) likewise return non-nil errors on both
consoles; on the local console they must not fall back to the old
print-and-nil `unknown pipe command 'compare'` behaviour. Other unknown
pipes keep their existing print-and-nil behaviour on the local console
(#18667/#18668 scope, unchanged here).
