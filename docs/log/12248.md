# #12248 — native VLAN binding advisory

- **Timestamp**: 2026-10-08 (`fix/12248-native-vlan`)

## Why

A valid `native-vlan-id` with no uniquely matching logical unit was accepted with no commit warning. The userspace ingress mapper deliberately rejects VID 0 in that case, so untagged traffic was silently dropped despite a green commit.

## What

- After compiling an interface's units, emit a warning unless exactly one unit has `vlan-id` equal to its `native-vlan-id`. The warning names the interface and VLAN and says untagged ingress will be rejected. The fail-closed dataplane behavior is unchanged.
- Update the schema comment to document the binding advisory and add config/compiler and real CLI commit regressions. The unique matching-unit control stays silent.

## Validation

The `TestNativeVLANWithoutMatchingUnitWarns12248` regression failed before the implementation with `no native VLAN binding advisory in warnings: []`; its matched-unit control passed.
- **GREEN after**: `go test ./pkg/config -run '^TestNativeVLAN' -count=1 -v` passed, including missing, ambiguous, and unique binding cases. `go test ./pkg/cli -run '^TestNativeVLANBindingAdvisory' -count=1 -v` passed; the real `handleCommit` output contained the warning and `commit complete`, while `commit check` with a unique unit succeeded without a native-VLAN warning.
- `go build ./pkg/config` passed; `gofmt -l` on changed Go files was empty. `go test ./pkg/config -run 'Test.*(Interface|VLAN)' -count=1` and full `go test ./pkg/cli -count=1` passed.
- **Full config package**: `go test ./pkg/config -count=1` exceeded the 360-second tool timeout on both this branch and a pristine `a714c90d4` worktree; no per-test failure output was reported by either timed run, and the timeout reproduced at base. The focused interface/VLAN regression set passed.

## Risk

The change is advisory-only: configurations still commit, but users now receive the fail-closed consequence before commit. The dataplane remains fail-closed for absent or ambiguous bindings; no live cluster was modified. A config with duplicate unit VLAN IDs is separately rejected by the existing duplicate Linux-device check; the ambiguity branch is covered directly at the binding checker.
