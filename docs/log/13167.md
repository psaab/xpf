# Attach RETH VLAN members to bridge domains (#13167)

- **Issue**: #13167, source finding D4-11.
- **Cause**: `buildInterfaceNetworkdModels` skips config-only RETH interfaces and
  emits their VLAN subinterfaces under the selected physical member's Linux
  name, using the RETH parent's VLAN tagging and unit configuration. Bridge
  membership construction instead keyed the configured `reth0.<vid>` name and
  checked only the physical stanza's (usually absent) VLAN settings. Thus the
  emitted interface could not match the bridge allowlist and was left unattached.
- **Change**: Resolve a RETH bridge member to the local physical interface
  before keying its bridge, and consult its effective VLAN configuration when
  recognizing emitted VLAN netdevs. Also follow a physical member's
  `RedundantParent` when resolving its effective VLAN settings. The existing
  interface+VID allowlist and ambiguous-VID quarantine behavior remain intact.
- **Regression**: `TestBridgeDomainBridgeMasterResolvesRethVLANMemberToPhysicalInterface`
  checks that a configured `reth0.100` member becomes `BridgeMaster=br-bd-reth`
  on emitted `ge-0-0-0.100`, and that the emitted subinterface is recognized.
- **RED evidence**: On pristine `origin/master` (`ab0498643`) with only the
  regression added, `GOCACHE=/var/worktrees/.cache/go-build
  GOTMPDIR=/var/worktrees/.cache/go-tmp go test ./pkg/dataplane -run
  '^TestBridgeDomainBridgeMasterResolvesRethVLANMemberToPhysicalInterface$'
  -count=1` failed: `RETH VLAN member BridgeMaster = "", want br-bd-reth`.
- **GREEN evidence**: `go test ./pkg/dataplane -run
  'TestBridgeDomain(BridgeMaster|DuplicateVID)' -count=1` passed; full
  `go test ./pkg/dataplane/...` passed `pkg/dataplane` and `pkg/dataplane/runtime`
  but failed `pkg/dataplane/userspace` on unrelated existing userspace tests
  (Unix-socket bind errors under the configured long `GOTMPDIR`, golden/snapshot
  mismatches, and unrelated source-guard/fixture assertions). `go vet
  ./pkg/dataplane/...` and `go build ./...` both passed.
- **Risk / scope**: No change to VLAN-ID ambiguity handling or unrelated
  networkd models. RETH resolution uses the existing `Config.RethToPhysical`
  choice of local physical member; ordinary physical VLAN members remain
  covered by the existing bridge-domain tests.
