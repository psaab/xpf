# #18288 — `make deb` fails on master `debian/changelog` (adjacent `xpf (0.0.0)` entries, no trailer separation)

- **Timestamp**: 2026-10-27
- **Worktree**: `/var/worktrees/campaign-pub/wt-18288`, branch
  `fix/18288-campaign` off `origin/master` `be8b24f1ec`.
  Control checkout `/home/ps/git/pi-xpf` was NOT touched.

## Reproduction (STEP-0, on unmodified `origin/master`)

- `dpkg-parsechangelog -l debian/changelog --all`:
  `warning: debian/changelog(l26): found start of entry where expected
  more change data or trailer` / `LINE: xpf (0.0.0) unstable;
  urgency=medium`.
- `make deb-changelog-check` (the `deb` prerequisite added by #18178):
  `FATAL: dpkg-parsechangelog --all emitted warnings ... (#18178)`,
  `make: *** [Makefile:1934: deb-changelog-check] Error 1`.
  This is the gate every cluster gate hits first, so all three
  cluster gates were blocked at build, before any deploy.

## Root cause: which merges introduced the malformed adjacency

The file's single trailer
` -- xpf maintainers <noreply@anthropic.com>  Mon, 26 Oct 2026 00:00:00 +0000`
sat at the end, but line 26 opened a second `xpf (0.0.0)` entry with
no trailer (and no blank-line separation) closing the first. Per-commit
`dpkg-parsechangelog --all` validity over the first-parent chain:

- After #18178 (`89989128f8` collapse, merged as `29e218f20a`): file is
  one 82-line maintained entry, parses clean.
- Still clean at `77fb7d5162` (#17215 merge): 92 lines, one entry.
- The branch-side merges for #17168 (`73773773fa`, 20:38 -0700,
  merging master into `fix/17168-campaign`) and for #18207
  (`6a05f58bb1`, 21:05 -0700, merging `d8c1b2146a` into
  `fix/18207-campaign`) resolved the changelog by concatenating the
  incoming entry block below the existing block without adding a
  trailer for the upper block. Their master merges `9f39e9331e`
  (#17168) and `366c3b1845` (#18207) carried the two-header /
  one-trailer shape onto master (107 lines, second header at line 26),
  where it has blocked `make deb` since.

Both entry contents are legitimate and distinct (upper: #17168,
#17215, #18207; lower: #17148, #17086, #17061, …), so neither entry
may be dropped.

## Fix

`debian/changelog` only (+2 lines): insert the project's existing
trailer verbatim and one blank line between the two entries:

```
 -- xpf maintainers <noreply@anthropic.com>  Mon, 26 Oct 2026 00:00:00 +0000

xpf (0.0.0) unstable; urgency=medium
```

- The inserted trailer is byte-identical to the file's existing
  trailer (same maintainer and date). No new author/date is invented:
  this file is a version-token carrier — `make deb` rewrites only
  line 1's `(0.0.0)` version token (`Makefile` `deb` recipe), and both
  entries already carry version `0.0.0`.
- Content preservation proof: stripping header and trailer lines from
  both versions, the only remaining diff vs `origin/master` is the
  added blank separator line; every bullet, author and date in the
  file is unchanged, and `git diff` shows exactly 2 insertions,
  0 deletions.

## Action

- File(s): `debian/changelog` (2 insertions), `docs/log/18288.md`
  (this log).

## Validation

- `dpkg-parsechangelog -l debian/changelog --all`: exit 0, zero bytes
  on stderr (was: warning at line 26). Perl `Dpkg::Changelog::Debian`
  now parses **2 entries** (both `xpf (0.0.0)`) — previously the second
  header folded invisibly into the first entry's `Changes:`.
- `make deb-changelog-check`: PASS —
  `==> changelog OK: 1 entr(ies), zero warnings`. (The guard script
  counts `Version:` stanzas in `--all` output, which dpkg coalesces;
  the 2-entry count above is from the Dpkg Perl API.)
- `make deb` (timed at 120s, full build NOT required): proceeded past
  the changelog gate — printed the changelog-OK line, the deb version
  `0.0.25138+gbe8b24f1ec13.dirty`, and entered `dpkg-buildpackage`
  (`source package xpf / source version ...`) before the timeout
  stopped it during compilation. On exit the recipe's trap restored
  `debian/changelog` line 1 to `xpf (0.0.0)` and removed the private
  stage dir; `git diff` afterwards is exactly the 2-line fix.

## Risk

- Packaging metadata only; no code, wire, or config change.
- The two entries now both reach `dpkg` tooling and the installed
  `/usr/share/doc/xpf/changelog.gz` as separate entries instead of
  the second entry hiding inside the first entry's `Changes:` text;
  installed release-notes content is identical modulo that entry
  boundary.
- Residual (out of scope, not introduced here): branch merges can
  re-create a trailerless adjacency on future changelog conflicts;
  the #18178 guard (`make deb-changelog-check`) already fails closed
  on exactly that shape, which is how this defect was caught.
