# #17705: rib-group peer-return authorization used the import direction backwards

- **Timestamp**: 2026-10-28
  - **Action**: Confirmed the issue is OPEN and live on `origin/master`: both the kernel predicate in `pkg/routing/rules.go` and the AF_XDP mirror predicate in `pkg/dataplane/userspace/routes.go` read the lookup source's import destinations. No open PR matching #17705 or the rib-group fix was found.
  - **Action**: Added asymmetric A/B regressions. With A importing `[a.inet.0 b.inet.0 inet.0]` and B importing `[b.inet.0 inet.0]`, only the B-context return to A's connected prefix is authorized; A-to-B is refused.
  - **Action**: Reversed both authorization checks to consult the destination peer's import-rib for the lookup-source rib. Updated the peer-return documentation and the non-main-import warning, which no longer incorrectly says such a configuration takes no effect.
  - **File(s)**: `pkg/routing/rules.go`, `pkg/routing/rib_group_return_9819.go`, `pkg/routing/vrf_miss_terminator_9819_test.go`, `pkg/routing/rules_14975_test.go`, `pkg/dataplane/userspace/routes.go`, `pkg/dataplane/userspace/routes_ribgroup_leak_3876_test.go`, `pkg/config/compiler_validate_warn_routing.go`, `pkg/config/ribgroup_leak_warn_3876_test.go`, `docs/rib-group-route-leaking.md`, `pkg/routing/README.md`, `debian/changelog`, `docs/log/17705.md`.
  - **Validation**: RED on the unmodified authorization: `TestRibGroupReturnRulesAsymmetric17705` installed A-to-B return rules instead of B-to-A; `TestBuildRouteSnapshotsOneWayRibGroupReturn17705` mirrored the unauthorized `a.inet.0 -> b.inet.0` row. Fail-on-revert: temporarily restoring the old source-group check made both asymmetric tests fail again. After restoring the fix, the named rib-group tests passed in `pkg/routing`, `pkg/dataplane/userspace`, and `pkg/config`. `XPF_REQUIRE_NETNS=1 go test ./pkg/routing -run '^TestVRFMissTerminatorOnRealKernel9819$' -count=1` passed in its private network namespace.
  - **Risk**: Direct VRF-to-VRF forward route import remains deferred. The import-rib destination authorizes only a destination-scoped return to the peer's leaked connected prefixes, and only when both instances leak that family into main; the warning now distinguishes that return authorization from the uninstalled forward import.
