# Issue #15678 — NAT64 rule-set zone/VRF/source scoping + retired 4-prefix cap

## Defect
- `security nat nat64 rule-set` modeled only `prefix` + `source-pool`: no
  `from zone`, `from routing-instance`, or `match source-address` could be
  configured, and the Rust dataplane matched the /96 alone — a rule-set
  intended for one zone/VRF/source set translated traffic from every scope.
- `compileNAT64WithStaging` broke out after four prefixes
  (`if count >= 4 { // MAX_NAT64_PREFIXES ... break }`, retired-eBPF cap),
  while `buildNAT64Snapshots` walked every rule-set: a 5th+ rule-set existed
  in the Rust snapshot but never received a pool ID or persistent-NAT
  registration — a silent pool/persistence desync.

## Fix
- Go config: `NAT64RuleSet` gains `FromZone` / `FromRoutingInstance` /
  `SourceAddresses` / `SourceAddressNames` (+ first-value mirrors); schema
  models `from { zone | routing-instance }` and `match { source-address |
  source-address-name }`; `compileNAT64` reads scope via the shared
  `collectNATScopes` reader and match leaves via `natMatchAddressValues` /
  `firewallMatchValues`. `validateNAT64ScopeStrict` (strict reject /
  lenient warn) rejects mixed from axes, undefined zone/RI, non-IPv6 or
  unparsable source entries, and undefined address-book names.
  `nat64PrefixOwnerKeyScoped` folds `(from_zone, routing_instance)` into
  the #5144 owner key and `nat64ShadowedRuleSets` is scope-aware (same
  scope or earlier-unscoped shadows; different scopes do not).
- Cap: the `count >= 4` guard is deleted; every rule-set is staged. The
  Rust aggregate budget (#6982) remains the single fail-closed bound.
- Wire: `NAT64RuleSnapshot` carries `from_zone` / `from_routing_instance` /
  `source_addresses` (address-book names resolved feed-aware by
  `buildNAT64SnapshotsWithFeeds`); ProtocolVersion 59→60 in lockstep
  (Go + Rust `CONFIG_SNAPSHOT_PROTOCOL_VERSION`), shape golden updated.
- Rust: `Nat64Prefix` carries the scope; `classify_ipv6_packet_scoped` /
  `match_ipv6_dest_scoped` enforce it (first /96+scope+source match wins).
  The forward path passes the pre-routing scope identity
  (`prerouting_ingress_scope`). An authored-but-all-unparseable source
  list matches nothing — never widened to any-source.

## Tests (RED/GREEN)
- Go: `nat64_scope_15678_test.go` (compile, RI scope, unscoped control,
  strict rejects + lenient no-brick, scoped shadowing/owner keys),
  `compiler_nat64_cap_15678_test.go` (5 prefixes all get pool IDs +
  persistent-NAT registration), `nat64_scope_15678_test.go` in
  pkg/dataplane/userspace (snapshot carries scope, names resolved).
  Existing NAT64 suites (#4313 closed-world, #9555 shadowing, #5144
  overlap) updated where the grammar grew.
- Rust: `nat64_scoped_zone_match_15678`, `nat64_scoped_source_match_15678`,
  `nat64_scoped_unparseable_source_fails_closed_15678` in nat64_tests.rs.

## Validation
- Commands in PR body. Unit/snapshot level only; no live cluster run.

## Risk
- Protocol bump 60 fences mixed-version helpers (an old helper would
  ignore the scope fields and translate globally — the defect). Scoped
  matching is AND across axes, first-match in config order, matching the
  source-NAT posture. Unscoped rule-sets are byte-identical to before.
