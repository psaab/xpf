# Issue #10030: Wire conntrack lifecycle gate

## Disposition

The lifecycle gate is now GREEN on the fixed path and RED on the intentional
broken control after #10419 merged. The original PR #10420 recorded the stale
session regression and referenced #10030; this follow-up records the corrected
pair and closes the issue.

The gate proves session creation, exact session-ID witnessing and eviction on
the fixed path, control-session retention, stale-wire capture, fresh-tuple
control, SYN liveness, and checksum integrity independently. The broken result
is not a vacuous PASS/PASS: it witnessed the subject, deliberately retained
the exact subject SID under its `initial-timeout 300` control, retained the
control session, dropped the fresh tuple, observed the permitted SYN, and
then measured stale expired-tuple forwarding.

Clock-sync rationale (moved here from the commit message so it is durable):
the post-pair checks `/tmp/xpf-wire-10030-rerun-postcheck-1789797201` and

secondary was refreshed via `cluster-setup.sh restart 1`, which cleared the
warning but dropped the fw1 `pref 2000` rules (the known #10342/#10421

final strict check `…-1789798491` asserts no `peer wall clock` /
`failing authentication` warning and `clock_delta=2`, but the lab still
reports the pre-existing no-`system ntp server` risk, so the PASS is scoped
to the asserted cleanup state, not durable clock health.

## Managed-state cleanup

The pair ended with both nodes active on the same executable, node0 primary,
IPv4 and IPv6 `pref 2000` unreachable rules present, `vrf-sfmix` table 488570
with the committed `sfmix` routing-instance, no temporary `wire-10342` VRF or
configuration, and no `/etc/xpf/recovery-rollback-10030` residue.

The final post-pair check ran under a fresh `with-cluster.sh` lock after the
node clocks were synchronized, the secondary daemon was restarted, and the
managed temporary-RI add/delete path restored the pref-2000 baseline. Its
strict archive is `/tmp/xpf-wire-10030-rerun-postcheck-1789798491/postcheck.log`.
It asserted `xpfd=active`, node0 primary with `Takeover ready: yes`, no
peer-wall-clock or fabric-authentication warning, IPv4/IPv6 `pref 2000 ...
unreachable`, `vrf-sfmix` table 488570, the committed `sfmix` configuration,
`configuration path not found` for `routing-instances wire-10342`, absence of
`vrf-wire-10342`, absence of rollback residue, a restored `allow-all
application any` policy, and no `wire-10030` policy/application residue on
each node; the postcheck ended `PASS`. The lab still warns that no NTP server
is configured, but both node clocks were equal within two seconds and no
cross-node authentication failure remained.

The separate controlled `pref 2000` restart discriminator remains a
loss-cluster baseline finding tracked by #10342, not evidence for the
conntrack fix. Its archive is `/var/tmp/xpf-10342-probe-20260919T044647Z`; it
