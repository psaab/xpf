# Issue #10030: Wire conntrack lifecycle gate

## Disposition

The harness implementation is complete and hermetic validation is green. The first matched live pair exposed a product-baseline regression rather than a clean fixed-vs-broken split: the fixed path leaked the expired tuple exactly like the intentional broken fixture. Product blocker [#10419](https://github.com/psaab/xpf/issues/10419) records that finding. This PR therefore references, rather than closes, #10030.

The gate remains useful as a red guard: it proves session creation, exact session-ID witnessing and eviction, control-session retention, stale-wire capture, fresh-tuple control, SYN control, and checksum integrity independently.

## Controlled `pref 2000` restart discriminator

After the fixed/broken pair, a separate lock cell captured the current
cluster, deleted only the IPv4 and IPv6 `pref 2000` `l3mdev unreachable`
rules on both nodes, restarted each node, and required a 30-second
post-CLI convergence window. The probe archive is
`/var/tmp/xpf-10342-probe-20260919T044647Z`; its deployed `xpfd` hash was
`4a196d927c91b5d65d07caaf1a8d6738eb3c56412daaffa330651cba18509748`.

Startup did not reassert either family on either node:

```text
startup-did-not-reassert=loss:xpf-userspace-fw0; managed fallback required
startup-did-not-reassert=loss:xpf-userspace-fw1; managed fallback required
```

Both nodes remained empty for all 30 post-CLI seconds. The cell then used
the managed temporary `wire-10342` routing-instance add/delete path to
restore the baseline and verified on both nodes:

```text
v4=2000: from all lookup [l3mdev-table] unreachable
v6=2000: from all lookup [l3mdev-table] unreachable
vrf-sfmix 488570
vrf-mgmt 999
Device "vrf-wire-10342" does not exist.
configuration path not found: routing-instances wire-10342
```

This is an additional lab/product baseline defect: the clean daemon restart
did not restore the deleted rules, while the managed configuration
transition did. It is separate from the conntrack stale-session finding in
#10419. The final assertion archive is retained with the probe and the
shared cluster lock was released after cleanup.
