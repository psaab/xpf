# #12889 — stamp admission wall-clock on RT_FLOW SESSION_CREATE frames

- **Timestamp**: 2026-10-14 (`fix/12889-campaign-pub`)
- **Base**: `108db45a0d28fd9a94004f4b641853a9918543fd` (origin/master)
- **Action**: `emit_session_create_rt_flow` no longer discards the wall-clock
  half of its anchored clock reading; `encode_session_create_rt_flow` now
  writes the admission instant into the `[0:8]` `timestamp_ns` wire slot.

## Defect

The create producer read `(mono, wall)` and threw the wall nanoseconds away
(`userspace-dp/src/event_stream/rt_flow.rs`), and the create encoder
zero-initialized the frame and never wrote `buf[base..base+8]`, so every
`RT_FLOW_SESSION_CREATE` record arrived with a 0 wire timestamp. The Go
decoder (`pkg/logging/ringbuf.go` `eventTimeFromWire`, shared by the live
`logEvent` path and `DecodeRawEventRecord`) falls back to `time.Now()` on a 0
stamp, so create records were stamped at Go socket-drain time — skewing the
recorded event time under buffering and allowing a create record to time-order
after its own `RT_FLOW_SESSION_CLOSE` sibling. The close path already stamps
its close instant (#2465); the create path never got the same treatment.

## Change

- `userspace-dp/src/event_stream/rt_flow.rs` — `emit_session_create_rt_flow`
  keeps the wall reading and converts the Open delta's monotonic `created_ns`
  (stamped at install) via the same `monotonic_ns_to_unix_ns` anchor the close
  path uses, threading the result into the encoder. A 0 `created_ns` (bulk
  owner-RG export Open delta with no entry in hand) still maps to 0, keeping
  the Go `time.Now()` fallback — the close path's 0/unknown doctrine,
  fail-closed to the legacy behavior rather than silently mis-dating.
- `userspace-dp/src/event_stream/codec/rt_flow.rs` —
  `encode_session_create_rt_flow` gains a `create_unix_ns` parameter, written
  LITTLE-endian u64 at `[0:8]` (same slot/format as the close frame's close
  instant). No wire-format change: the slot always existed and the Go decoder
  already reads it for every frame; only the producer stopped leaving it 0.
- `userspace-dp/src/event_stream/README.md` — create-frame section documents
  the admission stamp and the 0-fallback contract.

No Go code changed: both Go decode paths already prefer a nonzero wire
timestamp, so the fix is entirely producer-side.

## Residual / risk

- The bulk owner-RG export Open delta (`created_ns == 0`) still yields a 0
  stamp and a Go drain-time record — inherent to having no admission instant
  in hand, and the documented fallback rather than a guess.
- HA session sync never feeds this producer a foreign clock reading: the
  install path only enqueues an Open delta for non-peer-synced origins
  (`!origin.is_peer_synced()`, `session/install.rs`), and the one Open delta
  that reaches it without a live entry — the bulk owner-RG export — carries
  `created_ns: 0` and keeps the documented fallback. Every stamped create
  therefore converts a locally-read CLOCK_MONOTONIC instant against a local
  anchor; no cross-node clock skew is introduced.
