# #14663 — CoS filter forwarding-class / V2 fabric ingress / base-row fixes (remaining legs after #14636)

- **Timestamp**: 2026-10-17
  - **Action**: Sibling #14636 (since landed on `origin/master`) already fixed
    legs 1–2: filter `then forwarding-class` keys the egress DSCP rewrite
    before the BA class via `forwarding_class_queue` /
    `filter_class_queue_id`, on fresh/cached/flowless paths. This change
    fixes the remaining D3-04 legs. Leg 3: `effective_ingress_ifindex` in
    `tx/cos_classify.rs` keys the customer input-filter re-walk (cached
    flowless, cached flow-keyed, fresh flowless, fresh flow-keyed) by the
    validated V2 fabric scope (`fabric_ingress_ifindex`) instead of the raw
    fabric link, which carries no customer filter; unscoped packets are
    unchanged. Leg 3b: the three owner-RG gate sites in
    `poll_descriptor/mod.rs` now zero `meta.fabric_ingress_ifindex` when
    `gate_fabric_zone_override_on_owner_rg` rejects the stamp, mirroring the
    NAT-scope gating, so a rejected stamp cannot steer BA classification.
    Leg 4: `build_cos_state` in `forwarding_build/cos.rs` no longer lets a
    base-interface row (`is_unit == Some(false)`) overwrite (or block, in
    reverse order) a logical unit's `interfaces`/`lp_rewrite` state for a
    shared ifindex. The duplicate `forwarding_class_ids` field and
    duplicate descriptor field from the pre-#14636 draft were dropped in
    favour of #14636's `forwarding_class_queue`. Documented in
    `docs/cos-traffic-shaping.md`.
