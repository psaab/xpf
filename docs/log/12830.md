# 12830 — suppress false management-zone advisories for tunnels

- **Timestamp**: 2026-10-13
- **Action**: classify bare unit-0 tunnel and bound IPsec members consistently;
  omit quarantined zone/interface claims from the advisory
- **Base**: `255bd90c3` (master); worktree includes the campaign's existing
  #12832 commits
- **Files**:
  - `pkg/config/userspace_mgmt_zone_advisory_10308.go`
  - `pkg/config/userspace_mgmt_zone_advisory_10308_test.go`

## Why

The #10308 advisory inspected interface-level tunnels and per-unit tunnels
only for explicitly unit-qualified member strings. A bare `gr-*`/`ip-*` member
therefore warned even when its configured unit 0 was a tunnel. A bound
`st0.0` device could similarly be missed by a bare `st0` zone member because
only the exact authored reference was checked. The advisory also attributed
ambiguous or runtime-quarantined zone/interface claims even though those claims
are not installed in the dataplane.

This was warning accuracy only: userspace ingress exclusion classifies the
snapshot interface itself and deliberately does not infer a lifeline from a
zone label.

## What

- `userspaceMgmtZoneMemberIsData` now checks the unit-0 tunnel when a member is
  bare, and checks the base's `.0` secure-tunnel ref for bare members before
  treating an absent interface stanza as data. Unknown unbound interfaces and
  unrelated/nonzero units still retain the advisory.
- `appendUserspaceMgmtZoneAdvisoryLocked` now skips quarantined zone names and
  interface logical keys using the existing quarantine helpers.
- Regression tests cover bare unit-0 GRE/IPIP tunnels, bare and bind-only
  `st0` with either authored bind spelling, a quarantined interface claim, a
  colliding quarantined `mgmt` zone, and true-positive unknown/nonzero-unit
  members.
- NOT changed: dataplane ingress enforcement, strict/tolerant validation, or
  warning suppression doctrine.
