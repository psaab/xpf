# 13962 — test source-NAT egress routing-instance scoping

The `to routing-instance` source-NAT scope is enforced by comparing the rule's
routing-instance with the flow's resolved egress routing-instance. Before this
change, that branch had no Rust regression: deleting the gate or using the
ingress instance in place of egress would survive the suite.

Added a source-NAT scope unit test with a positive named-egress control and a
negative different-egress control. Added a forwarding-level regression where
ingress and egress use different routing instances, and verified that the
same rule does not match after changing the resolved egress routing instance.
The existing `from routing-instance` tests remain unchanged as sibling-path
parity.

Validation: `cargo test --manifest-path userspace-dp/Cargo.toml
nat::tests_scope -- --test-threads=1` passed (25 tests), and
`cargo test --manifest-path userspace-dp/Cargo.toml
afxdp::forwarding::tests_snat_scope_9956 -- --test-threads=1` passed
(3 tests). Mutation evidence: deleting the `to_routing_instance` gate made
the new unit regression fail because the wrong-egress rule matched; deriving
the egress RI from the ingress interface made the forwarding regression fail
because tenant-a traffic did not match the tenant-b egress rule. The source
tree's unrelated compile error at `coordinator/tests.rs:11773` was corrected
temporarily to `(0, inner_dst)` only to execute test binaries and was restored;
it is not part of this change. Full `cargo test --manifest-path
userspace-dp/Cargo.toml -- --test-threads=1` completed: 8,174 passed, 14
failed, 8 ignored. Failures include WG endpoint transit (#9594), packet-length
fixture drift (#6883), pre-routing scope (#11297), session/NAT64 retirement,
COS literal ceiling (#7689), protocol wire fixture, and shim-index count
(#5173). The failure set was not compared against a clean baseline; full-suite
green is therefore not established.

`rustfmt --edition 2024 --check` on the touched test files reports unrelated
pre-existing formatting differences elsewhere in those files; the formatting
hunks are not included in this change.

Closes #13962
