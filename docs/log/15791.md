# #15791 — userspace-dp: thread ICMP selector and persistent-before-DNAT precedence into DNAT revalidation (G33-03)

- **Timestamp**: 2026-10-19
- **Mechanism**: `destination_nat_translation_still_valid` in
  `afxdp/poll_descriptor/policy_revalidation.rs` called
  `dnat_table.lookup_with_counter_scoped(..., None)`. A DNAT entry carrying
  an ICMP application constraint (`match_icmp_type`/`match_icmp_code`,
  e.g. `junos-icmp-ping` type 8) fails closed for `None`
  (`nat/destination.rs` `matches_l4_constraints`), so an ICMP-application
  DNAT session admitted on a session miss was revoked on its next
  session-hit revalidation. The same function also evaluated tiers in
  static -> dnat -> persistent order, while session-miss admission in
  `poll_descriptor/mod.rs` evaluates static -> persistent -> dnat
  (`static_dnat_decision.or(persistent).or(dnat)`), so a persistent-admitted
  session whose tuple was also claimed by a DNAT rule resolved to the DNAT
  translation on revalidation and was revoked, and a shadowed-DNAT
  translation could be laundered as valid.
- **Action**: Thread the hitting packet's real ICMP selector through the
  revalidation chain: `policy_packet_icmp(packet_frame, meta)` at the
  session-hit call site in `poll_descriptor/mod.rs` ->
  `source_nat_revocation_on_session_hit_with_ingress(..., packet_icmp)` ->
  `source_nat_translation_still_valid(..., packet_icmp)` ->
  `destination_nat_translation_still_valid(..., packet_icmp)` ->
  `lookup_with_counter_scoped(..., packet_icmp)`. The wrapper
  `source_nat_revocation_on_session_hit` also takes `packet_icmp`
  (existing test callers pass `None`); the forward arm falls back to the stored
  `forward_decision.nat.source_nat_icmp` (the forward packet's type/code
  recorded at SNAT admission, #14128) when the hitting packet supplies
  none, and the reverse companion-less arm uses the reconstructed forward
  decision's `source_nat_icmp`. Reorder the destination tiers to
  static -> persistent -> dnat to match admission. NOT changed: admission
  itself, the `DnatTable` lookup semantics, static-NAT matching, NPTv6 /
  NAT64 handling, or zone-policy revalidation.
- **File(s)**: `userspace-dp/src/afxdp/poll_descriptor/policy_revalidation.rs`,
  `userspace-dp/src/afxdp/poll_descriptor/mod.rs`,
  `userspace-dp/src/afxdp/poll_descriptor/policy_revalidation_tests.rs`,
  `docs/log/15791.md`
- **Validation**: New cells in `policy_revalidation_tests.rs`:
  `icmp_application_dnat_survives_revalidation_15791` (validates with
  `Some((8,0))`, fails closed for `None` and for `Some((13,0))`) and
  `persistent_precedes_dnat_in_revalidation_15791` (persistent-admitted
  session stays valid and the shadowed-DNAT-only translation does not
  validate when both claim the same public tuple). RED evidence:
  reverting the DNAT lookup argument to `None` fails the first cell
  (`ICMP echo DNAT session must validate with its real (8,0) selector`);
  swapping the tiers back to dnat-before-persistent fails the second
  (`persistent-admitted session must survive revalidation`). GREEN:
  `cargo test --bin xpf-userspace-dp -- 15791` 2 passed;
  `afxdp::poll_descriptor::policy_revalidation::tests` 61 passed;
  `policy_revalidation` filter 89 passed. Existing `#14315`/`#14802`
  cells updated for the new signatures and included in the 61.
- **Risk**: Fail direction stays closed: an unknown ICMP selector still
  fails a type-constrained entry, and precedence now matches admission
  so no new translation is admitted that admission would not have chosen.
  The hitting-packet selector is preferred over the stored one, mirroring
  admission's per-packet evaluation.
