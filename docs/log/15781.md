# #15781 — `system services netconf ssh` silently ignored while host-inbound opens tcp/830

- **Timestamp**: 2026-10-19
- **Verification (pre-fix)**: `grep netconf pkg/config/compiler_system.go`
  returned nothing outside test/log text; `SystemServicesConfig`
  (`types_system.go`) had SSH/WebManagement/DNS/DynamicDNS but no Netconf
  field, `systemInertKnobWarnings` had arms for login/ntp/internet-options/
  ssh rate-limit only, the schema (`schema_system.go:600-602`) admitted
  `netconf ssh`, host-inbound maps `netconf`/`netconf-ssh` to tcp/830
  (`host_inbound_tokens.go`), and both `show system services` renderers
  printed no NETCONF row. A new regression test failed to build on base:
  `NetconfSSH undefined (type *SystemServicesConfig has no field ...)`.
- **Chosen behaviour**: (b) accept-with-advisory. xpf has no NETCONF
  daemon (`docs/feature-gaps.md`: NETCONF/YANG Missing), so implementing
  (a) a real NETCONF-over-SSH server is out of scope for this lane. The
  stanza now compiles to a typed flag, warns explicitly that tcp/830 is
  NOT served, and shows as configured-but-not-served. Host-inbound
  tcp/830 admission remains operator-controlled (separately named
  `netconf` token), deliberately NOT changed — removing it would break
  existing admission policies; the commit warning + show row remove the
  false "served" implication.
- **Fix**:
  - `pkg/config/types_system.go`: `SystemServicesConfig.NetconfSSH bool`.
  - `pkg/config/compiler_system.go`: compileSystem reads `netconf` under
    the merged services node via `blockHasNetconfSSH15781` (braced child,
    `netconf ssh;` packed line, flat-set chain — #13089 shapes) and sets
    the flag; `systemInertKnobWarnings` emits
    `system services netconf ssh: accepted but NOT served (xpf has no
    NETCONF daemon; host-inbound tcp/830 admission alone does not provide
    NETCONF)` keyed on the typed flag (deduped via the existing `add`).
  - `pkg/config/schema_system.go`: netconf/ssh descs state NOT served.
  - `pkg/cli/cli_show_system.go` + `pkg/grpcapi/server_show_system.go`:
    both `show system services` renderers print
    `NETCONF SSH:    configured but NOT served (no NETCONF daemon; tcp/830 not served)`
    when the flag is set, nothing otherwise. `applySSHConfig` unchanged —
    no daemon to start; starting one is the (a) option, not taken.
- **Regression**: `pkg/config/compiler_netconf_15781_test.go`
  (5 spelling cells + absent/empty-netconf negative control),
  `pkg/cli/cli_show_netconf_15781_test.go` and
  `pkg/grpcapi/server_show_netconf_15781_test.go` (present/absent rows).
  RED on base (build failure on the missing field; silent compile),
  GREEN after.
- **Validation**: `go vet` clean on `pkg/config`/`pkg/cli`/`pkg/grpcapi`;
  targeted tests pass (this file's regressions + the #13089 inert-knob,
  dual-AST, and 13245 show-parity suites). The #7484 spelling-gate
  members registry reclassifies `system services netconf ssh` from
  `unreachable` to `flag (read, but value-less)` — the leaf now sets
  `NetconfSSH`. NOTE: `TestSchemaSpellingGateCoverageIsGated_7484`
  reds at this base from pre-existing census drift (master already
  exceeds its ceilings by +9/+16/+16 from unrelated merges; only the
  single netconf reclassification here is this lane's), left for the
  next 7484 census lane rather than raising ceilings for drift this
  change did not cause.
- **Risk**: warning-only; no dataplane, sshd, or host-inbound behaviour
  changes. Configs already carrying `netconf ssh` gain a commit warning
  and a show row — intended operator-visible delta. Implementing a real
  NETCONF server remains the documented feature gap.
