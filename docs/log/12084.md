# #12084 — canonicalise static-route identity

- **Issue**: #12084 — static routes with different authored spellings of the same prefix bypassed the #5633 contradictory-disposition gate and could compile as duplicate same-priority routes.
- **Branch**: `fix/12084-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12084`
- **Base**: `1c384b9a47ff7d6e567fa50632faa75c3995ae87`

## Why

`compileStaticRoutes` initially keyed routes by authored text, allowing different spellings of one prefix to bypass #5633. Its first masked-key fix used `net.ParseCIDR`, which folds mapped-IPv6 prefixes into IPv4 identity and silently drops one family (Astra R1). Separately compiled bare-static and `rib inet6.0` collections can normalize into the same snapshot table, leaving conflicting aliases outside the disposition gate (Astra R2).

## What

- Key route identities by `netip.ParsePrefix(destination).Masked()` with an explicit address-family tag, preserving native IPv4 and mapped IPv6 as distinct routes.
- Fold aliases across bare-static and `rib inet6.0` collections before routing gates, independently for global and each routing-instance scope. Preserve same-list next-table last-writer behavior; reject cross-list competing targets strictly, while tolerant compilation warns and retains one deterministic route.
- Retain alternate authored spellings in a compiler-only, non-wire field for conflict diagnostics.
- Cover R1 in either authoring order through compiled snapshots; cover R2 global, blue-instance, and competing next-table targets, plus scope isolation and existing flat/hierarchical alias, ECMP, and distinct-prefix cases.
