# #12084 — canonicalise static-route identity

- **Issue**: #12084 — static routes with different authored spellings of the same prefix bypassed the #5633 contradictory-disposition gate and could compile as duplicate same-priority routes.
- **Branch**: `fix/12084-route-ident`
- **Worktree**: `/var/worktrees/12084-route-ident`
- **Base**: `1c384b9a47ff7d6e567fa50632faa75c3995ae87`

## Why

`compileStaticRoutes` used the authored `Destination` string as its merge-map key. IPv4 host-bit variants and IPv6 case/compression variants of one masked prefix therefore remained separate routes, so the strict gate inspected each one-disposition route independently. Different `next-table` spellings also produced duplicate rows for one masked prefix.

## What

- Key static-route merges by the masked prefix from `net.ParseCIDR`, while retaining the first authored destination for downstream behavior.
- Retain alternate authored spellings in a compiler-only, non-wire field so #5633 reports both spellings when the merge exposes a disposition conflict.
- Add strict commit-check regressions for v4 host bits and v6 case/compression across flat and hierarchical ASTs; also cover duplicate next-table rows, legitimate ECMP merge, and distinct-prefix behavior.
