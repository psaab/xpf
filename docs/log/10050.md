# Issue #10050 — make mixed-family unit MTU order-independent

## Context

Read the complete #10050 issue body and all comments before implementation. The
issue was open and had no comments; it did not withdraw, narrow, mark-shipped,
or contradict the requested change.

Families are visited in authored order by `compileInterfaces`. The `family
inet6` arm already min-folded its `mtu` into `unit.MTU`, while `family inet`
unconditionally overwrote it. With interface MTU 1400, inet6/1300 followed by
inet/9000 therefore compiled 9000, while the reverse order compiled 1300.
`unit.MTU` feeds both the #9837 strict VLAN-MTU gate and
`applyVLANSubInterfaceMTU9757`, so the commit verdict and runtime target
changed with statement order.

## Change

- Made the `family inet` arm use the same `min` fold as `family inet6`, with
  zero meaning unset. A unit's effective MTU is now the minimum of all family
  MTU statements, independent of authored order.
- Updated the #9837 order cells and explanatory comments: both family orders
  compile 1300 under a 1400 parent and both are accepted by the strict gate.
  The existing inet6-only over-budget rejection remains in place.
- Added #10050 regression cells for flat and hierarchical family trees, both
  authored orders, the symmetric lower-family case, the strict-gate verdict,
  and single-family/no-MTU behavior.
