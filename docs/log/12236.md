# 12236 — partial publishes could ACK auth-key rotation with the old SYN-cookie ring

- **Timestamp**: 2026-10-08
- **Action**: fix + RED-before/GREEN-after regression coverage
- **File(s)**: `pkg/dataplane/userspace/manager_overlay.go`,
  `pkg/dataplane/userspace/manager_compile.go`,
  `pkg/dataplane/userspace/hybrid_guard_syncookie_12236_test.go`,
  `pkg/dataplane/userspace/syncookie_route_guard_12236_test.go`,
  `docs/log/12236.md`

## The defect

`config.Secret` redacts non-empty auth keys in `json.Marshal`, which is the
first comparison in `configsContentEqual`. With SYN-cookie protection active,
`buildSYNCookieKeys` derives a primary ring base from `ControlLinkAuthKey` and,
during a #6630 rotation, an accept-only base from `ControlLinkAuthKeyAlt`. A
full build installs those bases in the helper snapshot, but route-overlay and
scheduler partial publishes inherit the old ring while stamping the new config.
After a failed full rotation, the redacted comparison could therefore treat the
new config as equal and acknowledge the revoked ring as current.

## The fix

Extend `helperVisibleSecretDigest9161` with the exact primary and optional
accept-only bases derived by `synCookieKeyMaterial` and `deriveSYNCookieBase`,
only when SYN-cookie protection is active. This matches the ring installed by
full builds without including the epoch key, which is wall-clock-derived. When
protection is inactive, auth-key rotation remains coarsened because no ring is
installed. Route-overlay and scheduler refusal messages now describe general
snapshot/config skew rather than labeling every skew as a policy-only change.

## Regression coverage

- Primary auth-key rotation with active cookie protection is a content change.
- Additional auth-key rotation with active protection is a content change.
- An unchanged active ring remains content-equal; inactive protection keeps
  auth-key changes coarsened.
- A route delta after a modeled failed full key-rotation publish is refused
  before it can ACK the new config with the inherited old ring; applied identity
  and old ring remain retained.
