# #16525: bare rollback fell forward to newest committed version when predecessor was GC'd

- **Timestamp**: 2026-10-24
- **Action**: `defaultRollbackTarget` in `pkg/upgrade/rollback.go` took
  the committed-predecessor branch only when
  `byName[currentStamp.Predecessor]` existed and otherwise fell back to
  `committed[0]` — the newest `CommittedAtUnixNano` candidate, with no
  older-than-current predicate. After cuts 1->2->3->4 and GC removing
  1.0.0, bare rollbacks 4->3->2 then selected 4.0.0, moving the node
  FORWARD onto the operator-rejected release, restoring the
  `.<from>.dbsnap` DB snapshot, and reporting `rollback complete`.
  Fixed by making `defaultRollbackTarget` refuse (requiring an explicit
  `--target`) when the named committed predecessor is not restorable,
  and — when current has a committed stamp but no predecessor record —
  restricting fallback candidates to committed versions strictly older
  than current and refusing when none exists. Explicit `--target` is
  unchanged (operator's explicit choice, still gated by
  restorability/snapshot/envelope checks in `prepareRollback`).
  Legacy (no-stamp) mtime fallback is retained only when current itself
  has no committed record. Also updated the stale `--target` help in
  `cmd/xpfd/upgrade.go` ("default: newest restorable non-current
  version" described the faulty fallback) and documented the refusal in
  `docs/in-place-upgrade.md`.
- **File(s)**: `pkg/upgrade/rollback.go`,
  `pkg/upgrade/rollback_cmd_test.go`, `cmd/xpfd/upgrade.go`,
  `docs/in-place-upgrade.md`, `docs/log/16525.md`
- **Validation**: new tests
  `TestRollbackTo_BareChainNeverMovesForward16525` (chain 4->3->2 then
  refusal naming 1.0.0/2.0.0 + `--target`, no unit mutation, explicit
  `--target` still recovers),
  `TestRollbackTo_ControlChainYields3To2To1_16525` (positive control
  3->2->1), `TestDefaultRollbackTarget_NoPredecessorRecordPicksOlderCommitted16525`,
  and `TestDefaultRollbackTarget_NoPredecessorRecordOnlyNewerRefuses16525`
  pass; RED-on-revert verified by restoring the newest-committed
  fallback in the predecessor-missing arm, which makes the chain test
  fail with `bare rollback ... succeeded (chain [4.0.0 3.0.0 2.0.0] ->
  4.0.0)`. Full `go test ./pkg/upgrade/ ./cmd/xpfd/ -count=1` run in
  the worktree (see PR for result).
