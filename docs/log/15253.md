# Issue #15253: userspace-dp stale operator text/docs (A80-02)

## Why

- The #9040 helper warning in `userspace-dp/src/server/helpers/planning.rs`
  ("RSS is only reshaped to fit the bound set on mlx5_core, so on any
  other driver ... is DROPPED") and the metric doc in
  `pkg/api/metrics_degraded_path_9040.go` ("every other driver is skipped
  by an explicit driver guard") claimed an mlx5-only reshape long after
  83acc21894 replaced the Go daemon's driver-name gate with a
  per-interface `ethtool -x` capability probe (#9040). Wrong in both
  directions: a capability-probed i40e/ice box that WAS reshaped was told
  it drops transit, and an mlx5 box whose reshape was skipped
  (unreadable table) was implied safe.

## What

- `planning.rs`: warning text extracted to `over_stride_warning(name, rx)`
  (the planner's `eprintln!` is not capturable in a test, and the text
  was the defect). New text is conditional — "Unless xpfd reshaped this
  interface's RSS indirection table to the bound set..." — and names
  `ethtool -x <if>` as the check, keeping the `ethtool -L` remedy, the
  `binding_missing` reason and the metric name.
- `pkg/api/metrics_degraded_path_9040.go`: doc comment now describes the
  capability-probed reshape and names only the unreshaped case as
  dropping.
- Same stale claim removed from operator-visible text that restated it:
  `pkg/cmdtree/tree.go` and `pkg/config/schema_system.go`
  ("mlx5 RSS indirection reshaping" -> "RSS indirection reshaping"),
  `linksetup.go`, `daemon_run_naming.go`, `rss_indirection.go` header /
  `restoreDefaultRSSIndirectionOne` guard comment, and
  `userspace-dp/src/server/README.md` ("only on mlx5 / doesn't reshape
  at all" -> capability probe). Coalescence text that is genuinely
  mlx5-only (`coalescence.go`, `mlx5Adaptive`) is NOT changed.
- Behavioural sibling found while fixing the text (same stale guard,
  not just prose): `claimNICTunableOwnership` in
  `pkg/daemon/released_nic_tunables.go` only claimed mlx5 allowlist
  members as RSS-owned, and `releaseUnboundNICTunables` dropped
  ownership for any non-mlx5 name without restoring. Since #9040 a
  reshaped i40e/ice NIC could therefore neither be claimed nor handed
  back (its concentrated table would strand on release / shutdown via
  `rssOwned`). Claim now covers every allowlist member (`lo` skipped);
  release still drops coalescence ownership for non-mlx5, drops
  everything without a call only when the driver is gone (""), and
  otherwise runs the `ethtool -X default` RSS restore. The #6801 claim
  test that pinned the old guard is re-anchored (its narrower true
  contract survives), as is the "gone" test's wording.
- NOT changed: the reshape probe itself, weight-vector computation,
  the 16-queue cap, the drop, or any coalescence gating.

## Validation

- RED on origin/master (0dbf5fe392): the new tests reference the missing
  `over_stride_warning` / unconditional-claim behaviour and the stale
  doc text; see PR for the exact RED captures.
- GREEN: `cargo test --bin xpf-userspace-dp over_stride_warning` (plus
  adjacent planner tests), `go test ./pkg/api/ -run 15253`,
  `go test ./pkg/daemon/ -run '15253|6801|9040'`, full affected-package
  suites — see PR.

## Risk

- Operator-visible only for the text: a box over 16 queues now gets a
  conditional warning instead of a false drop assertion (or false mlx5
  assurance). The `-L` remedy is unchanged.
- The claim widening records non-mlx5 allowlist members as RSS-owned;
  releasing one costs one idempotent `ethtool -X <if> default` (the
  kill-switch call) even if its table was never moved — the same
  over-claim cost the original code documented as acceptable. A failed
  restore is retained as retry debt as before.
