# #18791: a restart grace on the #18697 unexpected-exit election debt

- **Timestamp**: 2026-11-01
- **Action**: Implemented the coordinator-approved design.
- **The grace.** An unexpected helper exit raises election debt only if the
  replacement has not become forwarding-ready within `helperExitGrace` (2.5 s):
  it reports `ForwardingArmed` and the shared Go status apply successfully
  writes `userspace_ctrl.Enabled=1`. A second exit while the episode is open,
  an exit within 30 s of the previous one, or the exit of an already-wedged
  generation gets no grace. The wedge verdict is unchanged.
- **Applied readiness (F1).** A helper-reported armed status does not end the
  grace by itself. `applyHelperStatusLocked` closes it only after its ctrl=1
  map write succeeds for an armed status. If the Go ctrl gate remains disabled,
  the exit flag and inherited episode stay open, and debt rises at the deadline.
- **The wake and transit-gate lock (F2).** The deadline wakes the transit gate
  through the existing supervisor observer. `HelperSupervisorState` reads a
  generation-fenced atomic snapshot published at spawn and lifecycle changes,
  so a gate pass does not block behind `Manager.mu` during the 5 s helper
  readiness wait.
- **The demotion path.** VIP-first demotion keys on
  `HelperExitedUnexpectedly`, so a peer request inside the grace releases VIPs
  first.
- **Late forwarding readiness.** The 2.5 s deadline is a hard bound: a
  replacement first made forwarding-ready after it still raises debt, then
  clears by the ordinary forwarding-ready-and-healthy hysteresis.
- **Monotonic clock.** Grace and crash-loop deadlines keep monotonic
  `time.Time` values so a wall-clock adjustment cannot stretch or shorten them.
- **Forwarding-ready hand-off.** The exit signal persists through spawn until
  the replacement reports `ForwardingArmed` and the Go ctrl gate successfully
  applies `Enabled=1`; this keeps VIP-first demotion active during both the
  spawned-but-unarmed and armed-but-disabled windows. Control-socket
  responsiveness is a separate signal: helper-down alone does not mark an
  answered, live helper silent. A stopped generation is marked departed only
  after its process exits, avoiding a false fence acknowledgement while the
  child is still alive.
- **Data behind the grace value** (`docs/log/18707.md`, udp):
  - Local recovery, measured as the first forwarded ping, came 1.58-1.77 s
    after SIGKILL (7 samples).
  - The exit is observed about 0.5 s after SIGKILL, so the replacement becomes
    forwarding-ready within about 1.3 s of where the grace is measured from.
  - 2.5 s gives about 1.9x headroom at host load 15-28. Grace length does
    not affect the dual-primary risk: the two-Manager cell has 0 dual for
    both debt schedules.
- **Black-hole cost:** a truly dead or slow helper keeps its traffic on the
  dying node for up to 2.5 s longer before the RG move begins.
