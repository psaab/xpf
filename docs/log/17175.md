# Issue #17175 — R4-Q37-01: stream interceptor passed nil request to request-dependent authz

- **Issue:** `principalStreamInterceptor` (authz.go:383 @47a93d76fd) and the
  #9051 re-auth tick (authz_stream_reauth_9051.go:100) called
  `authorizeRPC(..., nil)`. Since #16067, `rpcArgumentForms` type-asserts the
  request to `*pb.PingRequest` / `*pb.TracerouteRequest` /
  `*pb.MonitorInterfaceRequest` and returns `named=false` for nil, and
  `authorizeRPCCommand` denies a restricted class on `!named`. Result: every
  class with any deny/allow-commands regex was refused Ping, Traceroute and
  MonitorInterface over gRPC — including an allowlist explicitly admitting
  `^ping`. The #16067 cells called `authorizeRPCCommand` directly with a
  decoded request, a shape production never takes for streams. MonitorPacketDrop
  was unaffected only because it has no `rpcArgumentForms` arm. STEP-0 re-check
  on current `origin/master` (47a93d76fd): defect live — both nil call sites
  present, no stream wrapper re-runs authz on RecvMsg.
- **What:**
  - `authz_stream_spec_17175.go`: `streamRequestSpec17175` declares, per
    generated `BpfrxService_*_FullMethodName`, whether a streaming method's
    authorization depends on its request (Ping/Traceroute/MonitorInterface:
    true; MonitorPacketDrop: false). Unknown methods default to
    request-dependent (fail closed).
  - `authz.go`: `principalStreamInterceptor` now prices only the coarse floor
    at open via `authorizeStreamOpenContext` (`methodPermission(fullMethod,
    nil)` + `authz.Authorize`) for request-dependent methods; for the
    request-independent MonitorPacketDrop it runs the full
    `authorizeRPCContext` at open with the typed empty request, preserving the
    pre-fix open verdict exactly. The stale comment claiming "the only method
    whose permission depends on its request is the unary SystemAction" is
    replaced; `authz_methods.go` comments (completeMethodName,
    systemActionMethodName, showTextMethodName, methodPermission) now state
    the three request-priced methods.
  - `authz_stream_reauth_9051.go`: new `authzRecvStream` wraps the stream;
    its first `RecvMsg` runs the full `authorizeRPCContext` with the decoded
    message (the generated server-streaming wrapper decodes via RecvMsg
    before the handler body, so the verdict lands before any handler logic or
    Send) and retains the message. `authorizeStreamContinuously` takes the
    open-time authorized context; its #9051 tick re-prices the RETAINED
    message, or — before any message arrives — re-checks the coarse floor
    (`authorizeStreamOpenContext`) / full empty-request verdict for
    MonitorPacketDrop, so a wholesale class revocation of a handler that
    never calls RecvMsg (the #9051 fake-stream shape) still terminates the
    stream. No production path calls `authorizeRPC(..., nil)`:
    `grep -n 'authorizeRPC([^)]*, nil)' pkg/grpcapi/*.go | grep -v _test`
    returns nothing.
  - The 5s re-auth cadence and its pre-spawn interval capture (#9051/#9903)
    are unchanged. No client-streaming RPC exists; the census test fails if
    one is added (`ClientStreams: true`).
  - **Fold (Rev18216Opus F1–F3):** `authzRecvStream.RecvMsg` now retains
    ONLY the first message (`if !already`), so a second RecvMsg can
    neither re-authorize nor swap what the tick prices
    (`TestStreamSecondRecvMsgDoesNotReplaceRetained17175`).
    `authorizeStreamContinuously` parents its cancellable context on
    the open-time `authorizedCtx` (not the sibling `ss.Context()`), so
    `authorizedPrincipalKey{}` is present pre-message; the peer-marker
    freeze of `Context()` is documented on `authzRecvStream`, and the
    dead `reauthServerStream` type is deleted. The census now also
    asserts every `needsRequest=false` method has no request-priced
    arm (identical empty/populated argument forms, canonical command
    and permission; no config-target/alias/config-read/commit arm),
    and `TestStreamMonitorPacketDropAdmitDeny17175` drives
    MonitorPacketDrop admit/deny through the interceptor.
