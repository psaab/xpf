# #15670 — standard Junos security-zone children hard-rejected / whole-zone quarantined

- **Issue**: #15670 (V3-02) — `application-tracking`, `source-identity-log`, `enable-reverse-reroute`, `unidirectional-session-refreshing`, `advance-policy-based-routing-profile`, `advanced-connection-tracking`, `white-list` under `security zones security-zone <z>` were closed-world hard-rejected on strict commit and, on tolerant load, triggered #11575 `DroppedEnforcementChild` whole-zone quarantine (zone unbound, policies/host-inbound inert).
- **Branch**: `fix/15670-campaign`
- **Worktree**: `/var/worktrees/wt-15670`

## Why

`pkg/config/schema_security.go` modelled only description/interfaces/tcp-rst/screen/host-inbound-traffic/address-book under `security-zone`, and `compileZoneBody15668` had no case for the seven standard Junos children, so each fell into `recordUnknownSecurityZoneChild11575`: strict compile rejected the commit, and `CompileConfigLenient` kept the zone but set `DroppedEnforcementChild`, after which `clearDroppedEnforcementZoneBindings11575` unbound it (interfaces/screen/host-inbound/TCPRst cleared) and the userspace snapshot excluded it. A benign telemetry leaf therefore cost the whole zone's enforcement — disproportionate blast radius, and a vSRX-parity break (Junos accepts all seven; several are telemetry-only there too).

Decisive check (per the report): which children are enforcement-bearing? `white-list` is (23.4R1 global IP allowlist: listed sources bypass all IP screen checks in the zone), and `advanced-connection-tracking` shapes session acceptance; the other five are telemetry/routing/session-refresh knobs with no xpf runtime. None may be silently dropped: the inert five get the accepted-only advisory doctrine (`#2078`/`#4231`), and white-list/ACT get it too — modelling them without a runtime must not claim a screen bypass or connection-tracking behaviour that never happens.

## What

- `pkg/config/types_security.go`: `ZoneConfig` gains `ApplicationTracking`, `SourceIdentityLog`, `EnableReverseReroute`, `UnidirectionalRefresh` (bool), `AdvancePBRProfile` (string), `AdvancedConnectionTracking` (`*AdvancedConnectionTracking{Mode,Timeout,TrackAllPolicies}`), `WhiteList` ([]string).
- `pkg/config/schema_security.go`: all seven modelled under `security-zone`. Presence flags share `validateZoneFlagNode15670` (no operand/body, mirrors the tcp-rst validator); APBR profile is a scalar name leaf; ACT is a container with `mode` (enum allow-any-host/allow-target-host/allow-target-host-port), `timeout` (integer 0..86400), `track-all-policies-to-this-zone` (flag); `white-list` is a multi name leaf (`white-list [ name ... ]`).
- `pkg/config/compiler_security_zones.go`: `compileZoneBody15668` cases parse each child onto the zone (white-list first-seen dedupe; duplicate zone instances merge). Malformed shapes — flag with operand/body, profile without name, bad ACT mode/timeout/unknown ACT child, empty white-list — record on the existing #11575 channel instead of being interpreted: strict rejects, tolerant poisons/quarantines. `parseAdvancedConnectionTracking15670` is fail-closed (`ok=false` on any unknown/malformed content).
- `pkg/config/compiler_uniformgates_security_zone_11575.go`: poison clearing also clears the seven new fields, so a quarantined zone never surfaces inert knobs as configured.
- `pkg/config/compiler_validate_warn.go`: `validateZoneChildren15670` emits one accepted-only line per zone naming each configured knob ("configured but accepted-only … no runtime effect (#15670)"), so both `cfg.Warnings` (commit/apply) and `ValidateConfig` recompute (alarm surfaces) carry it.

NOT changed: no dataplane runtime for any knob (out of scope — the issue's fix direction is parse-onto-ZoneConfig without quarantine); the #11575/#12623 quarantine for genuinely unknown/misspelled zone children is untouched.

## Risk

Valid Junos configs carrying these children now commit and keep their zones bound instead of being rejected/quarantined — the intended parity fix. The knobs are inert (accepted-only advisory says so), so no forwarding behaviour changes; a config that relied on the strict reject to catch a misspelled leaf name loses that catch for these seven exact spellings only (typos still quarantine). `white-list` is the sharp edge: it is stored and warned as not honoured, so listed sources still face full screen checks (fail-closed direction) until a screen-bypass runtime exists.
