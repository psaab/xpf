# Default-drop-foreign knob for foreign session hits (#16044, ZP-11)

- **Issue**: #16044 (split from #15985, claim ZP-11). A foreign-arrival packet
  (live arrival zone != the zone that admitted the session) is adjudicated in
  place by #9519: judged by its arrival zone's policy and, on permit, forwarded
  on the owner's entry — owner SNAT binding/pool address and egress — with no
  NAT/policy accounting of its own. Deployments that never need
  asymmetric/multi-homed arrival had no way to refuse that.
- **Change**: opt-in `security flow drop-foreign-session-hits` (off by default).
  Go: schema leaf, `FlowConfig.DropForeignSessionHits`, compileFlow case,
  compact-normalize scope, flag-elision inventory, config golden NOT regenerated
  (the golden is already RED at the base commit for unrelated drift — see
  Validation; the two new serialized fields are the only intended delta).
  Wire: `FlowSnapshot.drop_foreign_session_hits`, snapshot protocol v69 -> v70
  in lockstep (Go `ProtocolVersion`, Rust `CONFIG_SNAPSHOT_PROTOCOL_VERSION`)
  so a v69 helper that would ignore the knob and fail open is fenced by exact
  equality. Rust: `ForwardingState.drop_foreign_session_hits` threaded from the
  snapshot at build; in `foreign_hit_verdict` a policy-PERMITTED foreign hit
  returns the new `ForeignHitVerdict::DropForeign` instead of `Forward`. The
  descriptor arm counts `foreign_authority_drops` and recycles the packet with
  no POLICY_DENY event and no denying-rule credit (no policy denied it).
- **Semantics preserved**: the deny arm (attributed `Drop`, POLICY_DENY event)
  and the #9384 re-zone `Revoke` arm are byte-identical — the knob diverts only
  a permit. Host-bound (`LocalDelivery`) foreign hits are exempt: they pass to
  the arrival zone's host-inbound / `junos-host` gate as before. The packet is
  dropped; the session is never revoked, re-stamped, promoted or flow-cache
  seeded by it (already guaranteed for foreign hits). Default off =
  adjudicate-in-place unchanged, so legitimately multi-homed / asymmetric
  arrivals keep forwarding.
- **Regression coverage**:
  - Rust unit (`session_hit_authority_tests.rs`):
    `drop_foreign_knob_turns_a_permitted_foreign_hit_into_a_drop_16044` — on the
    scheduled dmz->wan permit fixture, knob off forwards (control), knob on
    returns `DropForeign`; at the expired instant the verdict stays the
    attributed `Drop`; a `LocalDelivery` hit still returns `Forward`.
  - Rust descriptor (`tests_session_hit_authority_9519.rs`):
    `drop_foreign_knob_drops_a_permitted_foreign_hit_16044` — a dmz packet
    hitting the wan-admitted DNAT session with dmz's own permit live: `tx==0`,
    `foreign_authority_drops==1`, session pair intact (2 rows), and the owner's
    next packet still forwards on the same table.
  - Go: `pkg/config/drop_foreign_16044_test.go` (compiles true; defaults off),
    flag-elision case, `TestBuildFlowSnapshotCarriesDropForeign16044` (builder
    carries the bit onto the `drop_foreign_session_hits` wire field; default
    off). Wire fixture `protocol_wire_v1.json` gains the additive
    `drop_foreign_session_hits: false` specimen lines.
  - Fold (hostile review): `c5_last_seen_and_policy_id_persist_until_commit_sweep_10591`
    expected `last_seen` to refresh (idle `<` before) on each dropped DMZ ACK.
    That encoded the pre-#13938 lookup-refreshes-before-authority defect the
    #9519 contract and #16044 refuse: a dropped foreign packet "keeps nothing
    alive" (`a_foreign_ack_is_dropped_without_refreshing_the_session_13938`,
    poll_descriptor/mod.rs #13938 block). C5 is renamed
    `c5_dropped_foreign_hits_do_not_refresh_until_commit_sweep_10591` and now
    pins idle unchanged per tick; the sweep-empty assertion holds because the
    synced pair is on the 1800s established window, far beyond the ~257s
    observation horizon — not because foreign drops refresh it. Production
    code is unchanged by the fold; the knob stays scoped to the permit arm
    (the C5 lane runs with the knob off, so it is not a knob-scoping issue).
- **Validation**: `go test ./pkg/config/ -run 16044` PASS;
  `TestSecurityFlagElisionFamily9056` PASS;
  `go test ./pkg/dataplane/userspace/ -run '16044|TestSnapshotProtocolVersion|TestBuildFlowSnapshot'`
  PASS (includes the Go/Rust protocol-version lockstep pin at v70).
  `TestCompileGolden4406` and `TestSecurityFlagElisionStrictGateAgrees9056`
  fail identically at the pristine base commit `a7b8884511` (pre-existing
  golden/warning drift and an ipsec PSK gate case, both unrelated); the golden
  was deliberately not regenerated so this change carries no unrelated churn.
  Rust tests for the two new cells are included for the main agent's full-suite
  run; compilation of the touched Rust files is exercised there (no local
  verification run per assignment rules — the Rust build exceeds the lane
  timeout in this environment).
- **Risk**: zero with the knob unset (default). With it set, a flow whose
  ingress legitimately moves between permitted zones (multi-homed WAN,
  asymmetric path) is dropped per-packet until it ends or the knob is removed;
  that is the operator's stated intent. Owner traffic, deny/revoke behaviour,
  host-bound traffic and HA fabric owner hits are unaffected.
