# Zeroize leaves no cleartext archive or day0 staging behind (#15729)

- **Issue**: #15729 (V50-02). Three gaps let cleartext configuration secrets
  survive `request system zeroize`: (1) console zeroize hardcoded
  `DefaultArchiveDir`, so a store configured with a custom
  `system archival archive-dir` never surfaced the ownership skip and
  reported a clean reset while custom snapshots remained (and the daemon
  was stopped); (2) `FactoryResetArchiveDir(custom)` returned
  `*ArchiveDirSkippedError` without erasing the xpf-owned default, so
  snapshots written before the operator switched to a custom dir survived
  even a correctly-reporting remote wipe; (3) `scripts/image/xpf-day0-config`
  stages via `mktemp "$XPF_DIR/.xpf.conf.XXXXXX"` — a crash between mktemp
  and the durable rename leaks `.xpf.conf.<6-char>` holding the full
  cleartext config, and neither factory-reset sweep matched it
  (`isFsatomicTemp` requires `.*.tmp-*`).
- **Change**:
  - `pkg/cli/cli_request_system.go`: `cliZeroizeArchiveDir` is now a CLI
    method returning `c.store.ArchiveDir()` when configured (falling back
    to `configstore.DefaultArchiveDir` only when unset/disabled, mirroring
    gRPC `runZeroize` #7173/#10739). Both console wipe seams pass it, so a
    custom dir reaches `FactoryResetArchiveDir`, the typed skip propagates
    through `performConsoleZeroize` as an error, and `zeroizeStopDaemon`
    is not called.
  - `pkg/configstore/factory_reset.go`: `FactoryResetArchiveDir` keeps the
    ownership guard (custom dir never erased, `*ArchiveDirSkippedError`
    returned) but now also erases the provably-owned `DefaultArchiveDir`
    via the extracted `eraseArchiveDir` helper, joining any default-erase
    failure with the skip. Default-dir callers are unchanged.
  - `pkg/configstore/factory_reset.go`: new `isDay0StagedTemp` matches
    exactly `.<base>.<6 x [A-Za-z0-9_]>` (mktemp's shape) and is wired
    into `FactoryResetConfigDir`'s top-level sweep. The gRPC wipe
    delegates to `FactoryResetConfigDirWithSync`, so both paths erase the
    staging file; `.day0-config-applied`, `.config.journal`, fsatomic
    `.*.tmp-*` names and longer/shorter suffixes never match.
  - NOT changed: `scripts/image/xpf-day0-config` (its mktemp+rename is
    crash-safe except for the leaked name, which the wipe now owns), and
    the custom-dir ownership guard itself (no blind erase of unproven
    directories).
- **Regression coverage**:
  - `pkg/cli/console_zeroize_archive_15729_test.go`:
    `TestConsoleZeroizeSurfacesCustomArchiveDirSkip` — custom archive-dir
    on the store, spy wipe delegates to the real
    `FactoryResetArchiveDir`; asserts `*ArchiveDirSkippedError`, the
    configured dir was handed to the wipe, and the daemon was not stopped.
  - `pkg/configstore/factory_reset_zeroize_15729_test.go`:
    `TestFactoryResetArchiveDirErasesDefaultEvenWhenCustomSkipped`
    (default erased, skip returned, custom survives) and
    `TestFactoryResetConfigDirErasesDay0StagedTemps` plus
    `TestIsDay0StagedTemp` matcher table.
  - `pkg/grpcapi/zeroize_archive_15729_test.go`:
    `TestZeroizeCustomArchiveStillErasesDefault15729` (real eraser through
    `SystemAction(zeroize)`: default snapshot gone, custom survives,
    incomplete reset reported) and
    `TestZeroizeConfigDirErasesDay0StagedTemps15729`.
- **RED evidence**: at pre-fix `f214fac` with only the test files copied in
  (the matcher-table test trimmed at base since `isDay0StagedTemp` does not
  exist there — a build failure is not a behavioral RED):
  `TestFactoryResetArchiveDirErasesDefaultEvenWhenCustomSkipped` FAILED
  ("default archive snapshot survived a custom-dir zeroize") and
  `TestFactoryResetConfigDirErasesDay0StagedTemps` FAILED (".xpf.conf.Ab12Cd
  survived factory reset"); `TestConsoleZeroizeSurfacesCustomArchiveDirSkip`
  FAILED ("performConsoleZeroize = <nil>, want *ArchiveDirSkippedError");
  grpc `TestZeroizeCustomArchiveStillErasesDefault15729` FAILED (default
  snapshot survived) and `TestZeroizeConfigDirErasesDay0StagedTemps15729`
  FAILED (staged file present after zeroize).
- **GREEN evidence**: on the fix branch,
  `go test -count=1 -run '<15729 tests>' ./pkg/configstore/` ok,
  `./pkg/cli/` ok, `./pkg/grpcapi/` ok; neighboring factory-reset suites
  (`-run 'TestFactoryReset|TestIsFsatomicTemp|TestCustomArchiveDir|TestDefaultArchiveDir' ./pkg/configstore/`) pass unchanged.
- **Blast radius / risk**: console zeroize on a box with a custom
  archive-dir now reports an incomplete reset (and does not stop the
  daemon) instead of printing success — the intended fail-closed change;
  operators must erase the custom dir by hand, as the typed error states.
  Erasing the default alongside a skipped custom dir only removes the
  provably xpf-owned `/var/lib/xpf/archive` tree. The day0 matcher is
  suffix-exact (6 chars, final dot, leading dot + base), so stamp/journal/
  bystander dotfiles are untouched; a legitimately-named `.<base>.<6>`
  operator file in the config root matching mktemp's exact output shape
  would be swept — indistinguishable from a leaked staging file and
  holding, by construction, day0-installed content.
