# #13130 — make host-inbound WAN checks measure WAN ingress

- **Timestamp**: 2026-10-14 (`fix/13130-campaign-pub`)
- **Action**: make the host-inbound smoke evaluate effective zone/interface posture, probe each WAN VIP from its WAN-side VLAN, and preserve a structured ledger verdict on fatal setup failures.

## Red before

On pristine `origin/master` (`55ab81ef0`), a hermetic probe of `hi_zone_service_verdict` showed the reported inversions: with `system-services all` plus `ssh except`, PRESENT incorrectly passed and ABSENT failed; `any-service` incorrectly passed ABSENT and failed PRESENT; and an interface-level `ssh` override was invisible to the zone-only verdict. The live smoke also used only `CLUSTER_LAN_HOST`, so its WAN VIP probes arrived on `lan`, not `wan`. Its `die()` exited before the normal `WIRE_GATE` summary.

## Change

- Resolve each service posture from exact `display set` lines. Service-specific `except` defeats `all`; `any-service` remains the repository's packet-wide full admit; interface-level `host-inbound-traffic` replaces the zone-level posture when the optional interface is supplied.
- Add regression cases for `all` plus service `except`, `all except`, `any-service`, per-interface override admission/replacement, and the fatal structured ledger envelope.
- Probe LAN VIPs from the LAN host, VLAN-50 VIPs from `xpf-zone-matrix-dmz`, and VLAN-80 VIPs from `xpf-mouse-target`. WAN ssh now expects DENY; every WAN unit's effective posture is checked before traffic is sent. Those WAN hosts can be overridden with `CLUSTER_WAN_VLAN50_HOST` and `CLUSTER_WAN_VLAN80_HOST`.
- Update `docs/host-inbound-service-matrix.md` to distinguish historical #9637 LAN-to-WAN behavior from this smoke's direct WAN-ingress coverage.

## Validation

- **RED before**: hermetic probes on pristine `55ab81ef0` reproduced the three verdict errors; missing `WIRE_GATE` on fatal exit was visible in the extracted original `die()` body.
- **GREEN after**: `make test-host-inbound-lib` reported 94 host-inbound shell selftests passed and 13 Python prober tests passed. The target then failed in its subsequent unrelated `cluster-cell-selftest.sh` group-10–12 path with `PROJECT_ROOT: unbound variable`; that failure is not attributed to this patch.
- `bash -n test/incus/host-inbound-lib.sh test/incus/host-inbound-selftest.sh test/incus/test-host-inbound.sh` passed.
- The post-fix verdict confirmation harness passed all six cases (all/except, any-service, interface override positive/negative). `git diff --check` passed.
- ShellCheck was attempted. It reported existing SC1091 source-following, SC2329 indirect callback, and SC2001 style diagnostics; the newly introduced SC2016 diagnostic was corrected.
- The on-cluster `test-host-inbound.sh` was not run; live ingress behavior remains for the main campaign's cluster validation.

## Residual / risk

The smoke now requires live WAN-side prober endpoints on VLAN 50 and VLAN 80. Defaults are the existing loss-cluster `xpf-zone-matrix-dmz` and `xpf-mouse-target`; absent endpoints fail closed during preflight and emit a WIRE_GATE VOID instead of certifying the matrix.

## Post-merge correction

Review of merged `#13130` found a missed combination: `system-services
any-service` plus `system-services ssh except`. `CompileConfigLenient`
retains `any-service`, so the full-admit token must be checked before named
service exclusions. The first implementation checked `ssh except` first and
would have passed an `ssh ABSENT` posture assertion incorrectly.

- **RED on merged master** (`02aaee0b`): that exact config returned `PASS` for
  `ssh ABSENT` and `FAIL` for `ssh PRESENT`.
- **Fix**: prioritize `any-service` full admit ahead of named exceptions, and
  add both `PRESENT` and `ABSENT` assertions for the exact config to the
  hermetic host-inbound selftest.
