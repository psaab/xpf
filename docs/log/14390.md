# #14390 — Lenient tunnel routing-instance-target clear installs the tunnel in the default routing domain (VRF escape)

## Mechanism

`runTailGatesTunnelRITarget12520` (`pkg/config/compiler_validate_strict_tunnel_ri_target_12520.go`)
on the tolerant path (`CompileConfigLenient` / `CompileConfigForNodeLenient`,
used by `Store.Load` on every boot and `SyncApply` on every HA sync) warned
once per tunnel whose explicit `routing-instance` target was undefined, a
forwarding instance, or reserved for the management VRF — then **cleared**
the target (`claim.Tunnel.RoutingInstance = ""`). Clearing installed the
tunnel in the default routing domain (snapshot owner `(empty, 0)`,
transport table `inet.0`, kernel tunnel unbound to any VRF): traffic the
operator confined to a tenant VRF, a nonexistent VRF, or the management
VRF was encapsulated/routed in the default domain under the tunnel's zone.
Only the sub-case where a cleared GRE tunnel collided with an already-owned
outer identity was skipped (`skipQuarantinedGRECollisions12520`); a
non-colliding GRE tunnel, an IPIP tunnel, and any other claimed tunnel
were installed in domain 0. WireGuard escaped via #9909 removal, which
runs earlier. Strict commit rejected the shape (#12520).

## Fix

Tolerant path now **removes** every quarantined tunnel (the #9909 posture)
instead of clearing its target:

- `runTailGatesTunnelRITarget12520` no longer mutates `RoutingInstance`;
  it collects the quarantined set, keeps the per-claim `#12520` warning,
  runs the GRE-collision diagnostic, then removes the set via the new
  `removeQuarantinedTunnels12520` (generalized from the former collision
  removal loop: interface tunnel → nil + delete inheriting units; unit
  tunnel → delete the unit; a unit with its own tunnel keeps it).
- `skipQuarantinedGRECollisions12520` no longer removes anything; it only
  emits the explicit collision warning when a quarantined GRE tunnel's
  default-instance identity (`transportRI` forced to `""`, since the
  authored target never installs) is already owned. Its message now cites
  #14390 alongside #12520/#10654. The warning text `"is skipped on
  tolerant load"` is preserved.
- Removal also drops zone bindings naming a removed tunnel row (unit-
  qualified refs naming a removed unit; bare refs only when the whole
  interface is gone), so no consumer scopes coverage to a phantom
  ingress device. A unit tunnel cloned from a bad-target interface
  tunnel carries the bad target as its own claim and is removed with
  it; a unit that overrides it with a valid VRF survives.
- Strict path, valid-VRF targets, #9909 WG removal, #10654 handling among
  non-quarantined tunnels, and the #13139 unit-shadow rule are unchanged.

Updated consumers that pinned the old clear: config tests
(`compiler_tunnel_ri_target_12520_test.go`), dataplane snapshot tests
(`tunnel_ri_target_12520_test.go` — now assert no endpoint row),
`pkg/configstore`, `pkg/routing`, `pkg/daemon` 12520 tests, the #13138
case name, and schema-gate comments. Under removal, the former
"two quarantined tunnels keep the first" and "keyed/unkeyed both emit"
cells now emit only the surviving valid tunnel (or none); "valid
duplicates stay with #10654" keeps both valid tunnels and drops the
bad-target third tunnel.
