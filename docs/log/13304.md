# Issue #13304: Export flow counts to Prometheus

- Why: NetFlow v9 and IPFIX maintained successful exported-flow and data-packet counters, but production never read `Stats()`. The write-attempt metric also counts periodic template sends, so it cannot stand in for flow activity; exported data could be absent while the attempt metric continued to rise.
- What: Carried the exporter counters through `ExporterBatchStats`, populated both protocol paths in `Daemon.FlowExportBatchStats()`, and exported per-protocol, instance, template, and address-family Prometheus counters. Updated flow-export operator documentation. The counters retain the existing successful data-write semantics and do not count template refreshes.
- Validation: The regression failed on pristine `origin/master` at compile
  time because `ExporterBatchStats` lacked `ExportedFlows` and
  `ExportedPackets`. Before rebase, `go test ./pkg/api -count=1` passed
  (225.825s), `go test ./pkg/flowexport/... -count=1` passed, `go vet ./...`
  and `go build ./...` completed cleanly, and `gofmt -d` was empty. After
  rebase, the focused API regression, the live NetFlow/IPFIX daemon snapshot
  integration test, and `go test ./pkg/flowexport/... -count=1` passed.
- Risk: Metrics add two bounded-cardinality counter families, one series per configured exporter group and address family.
