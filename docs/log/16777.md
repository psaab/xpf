# #16777: settled IPsec host-input fence tick churns applySem at 200 Hz

- **Timestamp**: 2026-10-25
- **Action**: `reconcileIpsecHostInputFence`'s pre-semaphore early return
  covered only a non-SAFE census (or owed conntrack revocation). With a
  SAFE census, a CLOSING permit and an ACKed overlay authority — the
  steady state of every box without a route-based VPN — each 5 ms
  supervisor tick acquired `applySem` only to reach
  `tryOpenIpsecPermitAfterFenceAck`, which no-ops when no divert is
  committed, and released it. During a commit the tick parked in
  `Acquire` for the whole commit, stalling the supervisor's allocator
  tick and authority re-announce on the same goroutine. Fixed by
  returning before acquiring when the permit is settled with no work
  to do:
  - `pkg/daemon`: new `ipsecHostInputFenceSettledNoDivert` helper —
    CLOSING + SAFE + exact ACKed overlay authority +
    no `ipsecCaptureRemovalPending` + no committed divert under
    `ipsecCaptureMu` (mirroring `tryOpenIpsecPermitAfterFenceAck`'s
    own guards, including the conntrack-revocation-owed check).
    `reconcileIpsecHostInputFence` returns on it before
    `applySem.Acquire`. Non-SAFE, un-ACKed, removal-pending and
    divert-active states still take the semaphore as before; the
    OPEN/retire and install/readback paths are unchanged.
- **File(s)**: `pkg/daemon/ipsec_host_fence_reconcile_9506.go`,
  `pkg/daemon/ipsec_host_fence_settled_16777_test.go` (new),
  `docs/log/16777.md`, `debian/changelog`.
- **Validation**: new
  `TestReconcileIpsecHostInputFenceSettledSafeSkipsApplySem16777`
  holds `applySem` externally and asserts the SAFE/no-divert reconcile
  (non-empty and empty ACKed overlays) returns well under the 150 ms
  hold, while divert-active (still acquires, then opens), UNSAFE and
  un-ACKed controls still block on the held semaphore — so the fast
  path is scoped to exactly the settled state. Existing fence/capture
  suites (`9506`, host-input fence) re-run green; `go vet` and
  `gofmt` clean. See PR for counts.
- **Residual**: The pre-semaphore check samples the ACKed overlay,
  removal-pending flag and committed divert without `applySem`; a
  racing capture commit can flip any of them immediately after the
  sample. That race is benign in both directions: a missed opening is
  retried on the next 5 ms tick once the divert commits, and a
  stale settled verdict only skips work the post-semaphore pass would
  have no-oped on for the sampled permit. No lab/cluster smoke run by
  this lane (unit coverage only).
