# Issue #15655 — Accepted-but-inert Junos stanzas (V12-01, V15-04, V17-02)

## Why

Three accepted-but-inert defects: `security alg pptp disable` was classified
unimplemented and never gated the live Rust PPTP ALG (whose data association
was instead coupled to `gre-performance-acceleration`); `[edit security
user-identification]` committed silently while the `services` form emitted
duplicate/contradictory warnings, and JIMS `client-secret`/`shared-secret`
survived secret redaction in cleartext; `services flow-monitoring`
`flow-active-timeout`/`flow-inactive-timeout` were compiled and rendered as
live but had no exporter consumer.

## What

- V12-01: `PPTPDisable` on `ALGConfig`; `pptp` modeled in
  `compileALG`/`validateALGPackedTokens`/schema/`ALGModeledProtos`/
  `ALGDisabled`/`supportedApplicationALGs`; bit `0x10` packed in
  `algDisableFlags` (userspace + legacy compiler) and defined as
  `ALG_DISABLE_PPTP` in Rust. Rust: `ForwardingState::pptp_enabled()` gates
  the GRE v1 data resolve (decoupled from `gre_acceleration`; RFC 2890 keyed
  GRE keeps its own gate) and TCP/1723 control learning (a close still tears
  down previously learned calls). `show security alg` renders PPTP as
  `control-inspected (GRE Call-ID association)` / `disabled`.
- V15-04: shared `userIdentificationWarnings(root, node)` used by both
  `services` and `security` roots; collects across all flat-set siblings,
  dedups, covers `device-information`/`authentication-source`, generic
  fallback only when no known stanza named. `secretIndices` adds
  `client-secret`, `shared-secret`, `radius-shared-secret`.
- V17-02: `pkg/flowexport` `FlowTracker` — active timeout emits interim
  records with delta counters and resets the window; inactive timeout emits
  a final record and forgets the flow. Both exporters own a tracker built
  from their `ExportConfig` timeouts, drain it on the batch ticker in `Run`,
  and the daemon registers `SESSION_OPEN` flows and forgets them on
  `SESSION_CLOSE` (the close record carries session totals). Full interim
  fidelity note: live per-packet counter Touch is driven through the
  exported `TouchFlow` API; with no intermediate Touch a flow's counters are
  known only at close, so interim records carry the last-known counters
  (zero if never touched) — the timeout/window semantics are enforced by
  the tracker regardless.

## Validation

- RED first: `accepted_inert_15655_test.go` failed to build
  (`PPTPDisable undefined`) and the flowexport test referenced unwired
  tracker behaviour before implementation.
- `go test ./pkg/config/ -run '15655|10947|10948|Fable167P4a'` — pass.
- `go test ./pkg/flowexport/ -run TestActiveTimeoutEmitsInterim15655` — pass
  (long-lived flow: interim at >active timeout, window reset, final at
  inactive timeout, both v9 and IPFIX).
- `cargo test pptp_enabled_follows_alg_disable_bit_15655` — pass (PPTP
  follows 0x10 alone; GRE accel neither enables a disabled ALG nor is
  required for the default).

## Risk

ALG bit 0x10 is new on the wire (older helpers ignore unknown bits; PPTP
stays enabled there, matching pre-fix behaviour). Tracker is nil when both
timeouts are unset, preserving close-only export byte-for-byte.
