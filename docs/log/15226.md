# #15226 — NAT destination display renders multi-port DNAT as first port only (A42-02)

- **Timestamp**: 2026-10-19
- **Action**: Render the complete destination-port match set on every NAT
  display surface via one shared natshow renderer, plus an additive
  repeated `dst_ports` proto field. A multi-port or port-range DNAT rule
  no longer displays as its first port only.
- **Files**: `pkg/natshow/dest_ports_15226.go` (new),
  `pkg/natshow/dest.go`, `pkg/natshow/dest_ports_15226_test.go` (new),
  `proto/xpf/v1/xpf.proto`, `pkg/grpcapi/xpfv1/xpf.pb.go` (regen),
  `pkg/grpcapi/server_nat.go`, `pkg/grpcapi/nat_dest_ports_15226_test.go`
  (new), `pkg/api/types.go`, `pkg/api/nat.go`,
  `pkg/api/nat_dest_ports_15226_test.go` (new),
  `pkg/cli/cli_show_nat.go`, `cmd/cli/show_nat.go`,
  `cmd/cli/show_nat_ports_15226.go` (new),
  `cmd/cli/show_nat_ports_15226_test.go` (new).

## Defect

Every NAT display surface rendered a multi-port or port-range DNAT match
as its first port only — the port sibling of #7363 (addresses):

- `pkg/grpcapi/server_nat.go` GetNATDestination copied the singular
  back-compat field (`rule.Match.DestinationPort`) into `dst_port`, and
  GetNATRuleStats appended `":<first port>"` to the destination match.
- `pkg/natshow/dest.go` rule detail printed the singular field.
- `pkg/cli/cli_show_nat.go` carried three singular copies (two
  `Match destination-port: %d` lines, one `":%d"` append).
- `pkg/api/nat.go` REST `natDestHandler` copied the singular field.
- `cmd/cli/show_nat.go` (ctl) rendered `:<dst_port>` from the singular
  proto field at two sites.

The compiled match carries the full list on `Match.DestinationPorts`
(bracket lists and `low to high` ranges expanded by `parseDNATPortList`),
and the dataplane enforces all of it via
`coalescePortRanges(rule.Match.DestinationPorts)`
(`pkg/dataplane/userspace/nat_destination.go`). So
`destination-port [ 80 443 ]` displayed as `:80` and
`destination-port 20000 to 20003` as `:20000` — an operator or audit view
understating inward exposure while enforcement was correct.

## Fix

- `pkg/natshow/dest_ports_15226.go`: `RuleMatchDestPorts` (plural
  supersedes singular — the singular is the plural's first element, so
  joining would double-print it; sorted, deduplicated, valid 1..65535
  only, so a configured-but-unusable token never renders as enforced),
  `RuleMatchDestPortsText` (contiguous runs collapse to `low-high`,
  mirroring the dataplane coalescing: `80,443`, `20000-20003`), and
  `RuleMatchDestinationWithPorts` (address match plus `:<ports>`).
- Text surfaces (`natshow` dest detail, both in-daemon CLI
  `Match destination-port` lines, CLI rule-all, gRPC
  GetNATRuleStats `destination_match`) render the shared text form.
- Structured surfaces carry the full set additively: proto
  `NATDestInfo.dst_ports = 11` (repeated uint32; `dst_port` keeps the
  first port for back-compat) populated by GetNATDestination, REST
  `NATDestInfo.dst_ports` populated by `natDestHandler`. The ctl views
  render `dst_ports` compactly with a singular fallback for a daemon
  predating the field (`cmd/cli/show_nat_ports_15226.go`).

NOT changed: dataplane enforcement (already correct), config parsing,
the strict commit gate, static NAT (`MatchDestinationPort` is a genuine
scalar on a different type), translate/pool ports (genuine scalars), and
`dst_port` semantics for existing consumers.

## Risk

- Additive only: older clients ignore `dst_ports` and see the previous
  first-port view; text output for single-port rules is byte-identical.
  Multi-port rules' text changes from `80` to `80,443` /
  `20000-20003` — the intended correction.
- Ports outside 1..65535 are omitted from the rendered set (they can
  never match; the strict gate rejects them at commit). A rule whose
  only port tokens are unusable renders no port line, as an
  unconstrained rule does; its not-installed/strict story is unchanged.
