# #15033 Outer apply-groups beats nested one (A03-04) — engineering history

Issue: psaab/xpf#15033 (`config: fix — An outer apply-groups beats a nested
one (Junos: nested wins)… (A03-04)`). Source claim `A03-04`
(claude-opus-5-5-review), validator run `research-work.AdQvt1jMKw`,
consensus MATERIAL (3-way). Lane branch: `fix/15033-campaign`.

## Defect (present at base)

`expandGroupsRecursive` (`pkg/config/ast_groups.go`) merged every
current-level group into the destination nodes, then recursed into
children and processed their `apply-groups`. The nested value then met
an existing peer adopted from the outer group and was dropped as
inline-wins. Example: a global group binding
`interfaces ge-0/0/0 unit 0 family inet filter input PERMISSIVE` at the
top level beat a hardening group binding `filter input STRICT` applied
at `interfaces ge-0/0/0`, although Junos gives the more specific
(nested/deeper) hierarchy precedence. A green commit therefore enforced
the permissive filter instead of the hardening one (issue acceptance:
outer+nested row yields STRICT).

## Fix

In `pkg/config/ast_groups.go`, expansion now tracks, in the per-expansion
`groupExpandBudget`, the hierarchy depth (`len(ancestorPath)`) at which
each node was adopted by an apply-groups application
(`applyLevelByNode15033`, tagged on every adoption via a pre-merge
identity snapshot of the destination list and all descendant lists, so
container-routing hops cannot hide an adopted leaf; first tag wins so an
ancestral merge does not re-tag a leaf a nested application placed).

When a later application at a strictly deeper level meets a scalar /
non-union peer that was adopted at a strictly shallower level, it
replaces that peer (nested wins) instead of dropping its value. The
replacement is wired into the leaf override arm, the single-key
leaf-list block arm (range-bearing case), and the #4325 container guard.
Authored inline peers are never in the map and never yield; peers from
the same or a deeper level keep first-wins; leaf-list and range-free
port unions are unchanged (both sides' members still union); the
special group-group materialisation arms (#12923 default-policy,
#14425/#14433 terminals) keep their existing behaviour.

## Risk

- Behaviour delta is the fix itself: nested `apply-groups` now override
  shallower groups for the same scalar/non-union leaf, matching Junos.
  Configurations that (accidentally) relied on outer-wins will change
  to the nested value — the intended Junos semantics.
- The level map is expansion-local (per `ExpandGroups` call, pointer
  keyed); no persisted/rendered state changes.
