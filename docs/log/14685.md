# #14685 — Device-Map compact `key pci`/`key mac` spelling consumes address

## Claim (D9-05)
Hierarchical compact single-node spelling `interface ge-0/0/3 key pci pci 0000:01:00.0;`
compiled to `KeyOrder="pci" PCIAddr="pci"`; `key mac mac 00:11:22:33:44:55 pci 0000:01:00.0;`
compiled to `KeyOrder="mac" MAC="mac" PCIAddr="0000:01:00.0"`. Both passed
SchemaValidate and strict CompileConfig, so the resolver searched for PCI
`"pci"` / MAC `"mac"` and could not bind. Mechanism: `collectDeviceMapProps`
stepped `i++` over `Keys` with first-write-wins, re-reading the *value* of
`key` (`pci`/`mac`) as a property keyword.

Note: the flat `set ... key pci pci ...` form is rejected by SchemaValidate
("unknown modifier") because `key` is a leaf; the reproduced corruption is
the hierarchical compact form `interface ge-0/0/3 key pci pci <addr>;` inside
braces, which packs all tokens into the instance node's Keys. Regression uses
that exact shape via `hierTree` (NewParser), matching the issue's packet.

## Fix (pkg/config/compiler_chassis.go)
- `collectDeviceMapProps`: consume each recognised pair (`i += 2`) instead
  of stepping `i++`; unrecognised tokens still step by one. This keeps the
  scan aligned on keyword boundaries for every prop, including `pci <addr>`
  / `mac <addr>` whose addresses cannot be prop keywords.
- `validateDeviceMapStrict`: a present PCI/MAC identity must satisfy
  `ValidatePCIAddr`/`ValidateMAC` (reusing schema validators so both gates
  agree), and `KeyOrder` must be in the schema enum. Strict compile now
  rejects garbage identities even for direct `CompileConfig` callers that
  bypass SchemaValidate; the lenient path downgrades via the existing
  `lenientDeviceMap` warning plumbing.

## Regression (pkg/config/compiler_device_map_compact_key_spelling_14685_test.go)
- RED on origin/master (91d5ccc48c): `TestDeviceMapCompactKeyPCIConsersTail14685`
  got `PCIAddr="pci"`; `TestDeviceMapCompactKeyMACConsersTail14685` got
  `MAC="mac"` (both SchemaValidate+CompileConfig nil errors pre-fix).
- GREEN after fix: both compact forms yield real PCI/MAC + correct KeyOrder.
- Controls: `pci-then-mac` / `mac-then-pci` compact orders, ordinary
  `pci … key pci` and `mac … key mac` spellings stay green.
- Strict/lenient: invalid identities (`pci pci`, `mac mac`, garbage) fail
  strict `CompileConfig`; lenient compiles with a downgraded device-map warning.
