- **Action**: Verified.

  - F8: the lock and the command were separate connections, so the lock

- **Action**: A `--root` leg now uploads a per-invocation lane script and runs

  SAME `incus exec` as everything else. The script records its owner, probes
  (explicit outcomes kept), refuses or warns, runs the command, after-probes
  and reports. The lock therefore lives exactly as long as the remote
  command.
  - Before taking the lock: `flock -n` shows a waiting line with the holder.
  - The lock wait is recorded on the runner and subtracted from the pause
    verdict. The first real run had reported a waited lane as
    `paused-for=2s` with a VOID warning.
  - `XPF_VMTR_ROOT_LANE` is exported inside the lane, and a `--root` run

  - The script and its before-state file are per invocation: two runs of one

  - Finalization ignores INT/TERM until the handback ends, and
    `root_handback` no longer touches the traps.
  - INT/TERM during the command: the workstation ends it and reports from the
    lane's recorded before-state, best effort, with 130/143.
