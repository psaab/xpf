# #10026 — same-name deb re-push slot collision

- **Issue:** A same-name `.deb` re-push in the #9486 validation path reused
  `/tmp/$(basename "$deb")` on the target. Incus rejected the existing target
  before `apt-get` ran (`permission denied`), so the versions-slot/generation
  guard was never reached. The failure was not a `pkg/upgrade` cut-over defect.
- **Context read:** Read the complete #10026 body and comments, plus closed
  #9486 and merged PR #10022 (including its validation results). The #9486
  comment withdrawing the unavailable HA operator rollback acceptance item does
  not change this lane's deploy-slot scope.
- **Chosen direction:** Disambiguate rather than refuse a normal re-push. The
  cluster deb deploy now creates an atomic per-attempt remote directory with
  `mktemp -d /tmp/xpf-deb.XXXXXX`, pushes the package as an absent child in that
  directory, installs that exact path, and removes the directory on success or
  push/install failure. Cleanup failure after a successful install is loud. The
  existing generation-aware live/rollback slot refusal in `pkg/upgrade` is
  unchanged.
- **Implementation:** `deploy_install_deb` in `test/incus/deploy-lib.sh` owns the
  temporary slot and is called by `deploy_vm_deb` in
  `test/incus/cluster-setup.sh`. The fake Incus self-test rejects overwrite of
  an existing target, models remote `mktemp -d`, records apt's exact path, and
  verifies cleanup plus production wiring.
- **RED (same-name behavior cell, fixed-slot implementation):**
  `bash ./test/incus/deploy-lib-selftest.sh` — 57 passed, 1 failed, exit 1;
  `FAIL: deb re-push: expected two distinct remote slots, got 0`.
- **RED (production-wiring cell, temporarily restored direct push):**
  `bash ./test/incus/deploy-lib-selftest.sh` — 58 passed, 1 failed, exit 1;
  `FAIL: deb re-push wiring: deploy_vm_deb bypasses deploy_install_deb`.
- **GREEN (post-RED final implementation):**
  `bash ./test/incus/deploy-lib-selftest.sh` — 59 passed, 0 failed, exit 0.
  The same-name cell passed with two distinct cleaned slots and exact apt paths,
  and the wiring cell confirmed `deploy_vm_deb` no longer owns the fixed-name
  push.
- **Additional validation:** `bash -n` passed for the three modified shell
  files. Shellcheck reported only pre-existing warnings in the self-test's
  reassert tunables and an existing empty-assignment fixture; no warning was
  introduced by the deb-slot code.
- **Commits:** `26628d0af` — code and regression tests; the issue evidence
  log is committed separately in the docs-only follow-up.
