# #17254 — Single-source the on-link NDP hop-255 predicate

- **Timestamp**: 2026-11-03
  - **Action**: #15117 landed the on-link NDP (hop-255) admission rule twice in one commit: `frame/inspect.rs::is_ndp_hop255_frame` (session-miss arm) gated on the sideband `meta.protocol == PROTO_ICMPV6` before reading the wire, while the inline copy in `poll_descriptor/frag_assoc.rs::flowless_nat_wire_info` (flowless arm) derived the protocol from the shared ext-chain walk. They diverged from birth on the shim's `PROTO_FRAGMENT_NO_L4 = 255` stamp: `userspace-xdp/src/ipv6_ext_walk.rs` defines 255 as an *unknown* sentinel (stamped in `parse_ipv6` whenever the per-CPU v6-fragment scratch write/read fails — even on a fully resolved ICMPv6 chain), so a wire-true NS/NA at hop 255 carrying the stamp was suppressed-translation on the flowless arm but destination-translated on the session-miss arm, and `is_ndp_hop255_frame`'s doc claimed the two callers agreed. The fix makes the wire the seat of truth in ONE definition: `frame::ndp_hop255_type(frame, l3, walk) -> Option<u8>` (named set `ND_ONLINK_TYPES = 133..=137`, contrasted in-place with `host_inbound`'s deliberate `133..=136`) owns the admission; `is_ndp_hop255_frame` is now `AF_INET6 && ndp_hop255_type(..).is_some()` with no sideband protocol consult, and the flowless arm stores `ndp_hop255_type(frame, l3, &walk)` — the same walk instance it already computed, so no second ext-chain walk. Hot-path codegen: `ndp_hop255_type` is a free `#[inline(always)]` function over `(&[u8], usize, &ExtChainWalk)` — no capture, no trait object, no allocation; `#[inline(always)]` (not a hint) is the repo's own convention for cross-CGU folding in this LTO-off, codegen-units-16 build (see `walk_ipv6_ext_chain`'s comment), so both sites compile to the same operations they had before: the flowless arm identically, the session-miss arm minus one sideband compare plus the walk it must anyway run to see the wire truth (first-match-arm exit for terminal protocols). Acceptance held: `rg '133\.\.=137' userspace-dp/src --glob '!*test*'` now returns exactly one site (`inspect.rs` `ND_ONLINK_TYPES`).
  - **File(s)**: `userspace-dp/src/afxdp/frame/inspect.rs`, `userspace-dp/src/afxdp/frame/mod.rs`, `userspace-dp/src/afxdp/poll_descriptor/frag_assoc.rs`, `userspace-dp/src/afxdp/poll_descriptor/flowless_ndp_nat_tests_15117.rs`, `docs/log/17254.md`.
  - **Validation**: RED on the pre-fix tree: `sentinel_sideband_ndp_admitted_at_both_sites_17254` failed at the session-miss site ("must admit wire NDP type 133 under the 255 sentinel") while both reject-direction controls passed; after the fix all seven exact cells green — the three new (`sentinel_sideband_ndp_admitted_at_both_sites_17254`, `non_ndp_wire_rejected_at_both_sites_17254`, `off_link_hop_rejected_at_both_sites_17254`) and the four pre-existing #15117/#16660 cells (`ndp_to_static_nat_external_is_not_translated_15117`, `ndp_controls_still_translate_15117`, `shim_nat_external_ndp_predicate_15117`, `shim_proxy_ndp_predicate_16660`) — via `cargo test --bin xpf-userspace-dp -- <exact names>`; `cargo check --bin xpf-userspace-dp` clean (pre-existing warnings only, count unchanged by this change).
  - **Risk**: Low. The only behavior change is admission of the previously-divergent class (wire ICMPv6 133-137, hop 255, sideband 255) on the session-miss arm — i.e. extending #15117's don't-translate protection to exactly the packets the flowless arm already protected; every reject direction is pinned by cells. Residual reachability assumption (inherited from the issue): the 255 stamp on a wire-NDP frame requires the shim's defensive scratch-fallback arm to fire. userspace-dp change: the loss+tcp+udp gate trio is required at merge.
