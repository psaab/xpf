# Issue #14414 — group OSPF `authentication` container dropped beside inline packed leaf

## Why

The #4325 cross-shape guard in `mergeNodes`
(`pkg/config/ast_groups.go`, container branch) dropped a single-key
group container whenever an inline leaf shared only `Keys[0]`
(`hasMatchingLeaf` matches on `Keys[0]` plus `IsLeaf`). That premise
("same key ⇒ same content") is false for a packed-tail leaf:
`authentication md5 1;` (`Keys=[authentication, md5, 1]`) carries only
the OSPF auth TYPE, while the group container
`authentication { md5 1 { key SECRET1; } }` carries the KEY. The guard
dropped the whole container, so the interface compiled with
`AuthType="md5"`, `AuthKey=""`, `AuthMD5Keys=[{1, ""}]`, and the FRR
renderer emitted no auth lines at all while the interface still
activated — the adjacency formed unauthenticated. The md5-vs-simple
variant downgraded MD5 to cleartext simple-password, and a group
rollover key (`md5 2`) was lost the same way. The identical guard shape
dropped a group policy/firewall `from` container beside an inline
packed `from route-filter …` / `from is-fragment;` leaf
(DR14-H1-ext), widening the term's match.

## What

- `pkg/config/ast_groups.go`: the #4325 guard now consults
  `packedTailLeafExempts4325` before dropping. A packed-tail leaf
  (`len(Keys) > 1`) sharing `Keys[0]` is not a duplicate of the
  container, so the container is adopted beside the leaf and the
  compiler merges both siblings — exactly as the inline-inline
  spelling already compiles. Two shapes deliberately keep the guard:
  leaf-list keys (either spelling — the union path above owns them,
  and a collapsed leaf there *is* the same statement as the block),
  and the #12923 default-policy choice, whose group-group pair must
  materialize for #11821/#12821 rather than resolve by adoption
  order while an authored inline choice still wins alone. (An
  unscoped exemption regressed precisely those flat default-policy
  cells during development; the scoped predicate is the fix.)
- Bare leaves (`len(Keys) == 1`, e.g. `rip;`) are untouched: a genuine
  duplicate still suppresses the group container.
- New regression
  `pkg/config/group_merge_ospf_auth_container_dr14h1_test.go`:
  main cell (group container beside inline packed leaf) + inline-inline
  control, application at protocols/ospf/area/interface level,
  two-groups variant, md5-not-downgraded-to-simple, rollover key 2,
  reverse precedence (inline container key + group type-only leaf
  keeps the inline key), bare-`rip;` genuine-duplicate control, and
  DR14-H1-ext cells for policy `from` (route-filter + prefix-list)
  and firewall `from` (is-fragment + destination-address).
- New render regression `pkg/frr/ospf_group_auth_container_14414_test.go`:
  the group config renders `ip ospf authentication message-digest` +
  `ip ospf message-digest-key 1 md5 SECRET1`, and the downgrade cell
  renders md5 instead of `ip ospf authentication-key`.
- NOT changed: `hasMatchingLeaf` itself (its TODO of callers — the
  leaf branch, leaf-list union, #12923 — keep their semantics), the
  #7648/#9855 leaf-branch promotion machinery, and group-group merges.

## Validation

- RED on base (`213a9e8f9`, pre-fix): the new config tests failed with
  `AuthKey = "", want SECRET1`, `AuthType = "simple", want md5`
  (downgrade), `AuthMD5Keys ids = [1], want both 1 and 2` (rollover),
  and `PrefixList = [], want PL1` / `DestAddresses = []` (ext cells);
  the frr tests rendered no `message-digest` line. The inline-inline
  control, reverse-precedence, and bare-`rip;` cells already passed,
  pinning the mechanism to the group-merge guard.
- GREEN after the fix:
  `go test ./pkg/config -run '14414' -count=1` and
  `go test ./pkg/frr -run '14414' -count=1` pass.
- Neighbours stay green: `go test ./pkg/config -run
  '9855|7648|TestGroup|ApplyGroups|9831|9859|9023|9862' -count=1`
  passes, including the #12823/#12923/#11821/#12821 default-policy
  suites the scoped predicate preserves.
- Full `pkg/config` / `pkg/frr` runs show only failures that also
  fail identically on a pristine `origin/master` worktree
  (e.g. `TestStrictDHGroupRejects_9919`, IPsec-gateway and BGP
  FRR-load cells at `59fa41531`) — base-attributed, not this change.
- `gofmt -l` on the three changed files: clean. `go vet
  ./pkg/config ./pkg/frr`: clean.

## Risk

Adopt-beside relies on each compiler merging sibling
`authentication` / `from` nodes; that is proven for OSPF (packed-body
iteration), policy terms (from-children iteration), and firewall
terms (from-nodes iteration) by the regression cells, and the
inline-inline control shows the resulting AST shape is one the
compilers already handle. Any other single-key container whose
compiler reads only the *first* sibling could now see a group
container it previously never received; the leaf-list and
default-policy carve-outs keep the two known first-match-sensitive
families on their prior paths.
