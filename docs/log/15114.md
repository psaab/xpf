# #15114 — userspace-dp: mirror clones keep the ingress VLAN on a VLAN-unit analyzer output (A75-03)

- **Timestamp**: 2026-10-19
  - **Investigation**: Confirmed at `origin/master` (`ffa933c1aa`). `userspace-dp/src/afxdp/mirror/fast_path.rs` resolved only the analyzer parent binding (`resolve_tx_binding_ifindex(forwarding, config.output_ifindex)`) and copied the sampled frame verbatim (`out.copy_from_slice(frame)` / `TxRequest { bytes: frame }` with no VLAN field), so a clone for a VLAN-unit output (e.g. VID 90) left on the parent carrying the ingress tag (VID 80) or no tag. The existing cell `sampled_live_mirror_resolves_snapshot_logical_ingress_and_output` asserted `req.bytes == frame` for exactly that VID-90 output.
  - **File(s)**: none (investigation only)

- **Timestamp**: 2026-10-19
  - **Action**: Fix in worktree `/var/worktrees/wt-15114` (branch `fix/15114-campaign`): new `mirror_output_frame` in `mirror/fast_path.rs` puts the clone on the output unit's VLAN using `forwarding.egress_tx_vlan_id(output_ifindex)` (the same source the forward-path builder uses, native-VLAN aware): tagged output rewrites the outer VID preserving PCP/DEI (normalising the TPID to 802.1Q) or pushes a tag onto an untagged frame; VID-0 output strips an ingress tag; untagged-to-untagged is a zero-copy borrow. Wired into both transmit shapes — `enqueue_mirror_clone_to_binding` (same-worker UMEM copy, length re-checked after a push so an over-capacity clone is `NoFrame`, fail closed) and `enqueue_admitted_mirror_clone_to_live` (cross-worker/flow-cache, now takes `forwarding`; all call sites updated: `enqueue_sampled_mirror_clone`, `enqueue_mirror_clone_to_live`, `enqueue_sampled_mirror_clone_to_live`, `poll_descriptor/flow_cache_hit.rs`, and the one direct test caller). A frame too short to hold the L2 header it claims is dropped (`NoFrame`) rather than emitted on the wrong VLAN. NOT changed: output-filter evaluation still runs on the original sampled bytes/tuple; sampling, admission ordering (#5167/#6114), CoS selection, and the primary forward are untouched; no commit-time config rejection (the rewrite makes VLAN-unit outputs work as configured).
