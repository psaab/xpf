# #12626 — make NAT unresolved-name fallback unparseable

- **Why**: NAT address-name expansion retains a non-empty raw-name token when a reference cannot be resolved, preserving the constrained/fail-closed shape on tolerant load. Address-book names may contain `/` (#4340), so a name such as `10.99.0.0/16` is itself a valid prefix: the raw fallback could become a SNAT match or a DNAT longest-prefix translation row unrelated to the set's members.

## Change

- Both NAT source- and destination-address-name appenders now use the fixed `unresolved-address-name:` prefix before the authored name. This token cannot parse as an IP/CIDR, even when the name is a bare IPv4/IPv6 address or CIDR, and remains non-empty to preserve the fail-closed constraint.
- Added direct parser-predicate coverage for CIDR, bare-IP, IPv6, and tolerated prefix-length spellings; added SNAT and DNAT behavioral cells using a poisoned set named `10.99.0.0/16`, with its surviving member disjoint from that literal. Updated the #6143/#12216 assertions and legacy #2416/#3425/#4925 fallback pins to the prefixed token.

## Validation

- **RED before**: focused CIDR regression cells failed against the original raw-name fallback. The helper test got `[10.99.0.0/16]` instead of an unparseable token; the SNAT cell saw the name literal in its source list; the DNAT cell observed an installed `10.99.0.0/16` longest-prefix row targeting `192.0.2.5`.
- **GREEN after**: the CIDR fallback tests and focused #12216/#6143/#3425/#4925 NAT regressions passed with `go test ./pkg/dataplane/userspace -run 'Test(NATFallbackTokenUnparseableForCIDRShapedNames12626|SNATCIDRNamedSetDoesNotMatchNameLiteral12626|DNATCIDRNamedSetInstallsNoRow12626)$|12216|6143|3425|4925' -count=1`. The relevant strict-gate/warning tests passed with `go test ./pkg/config -run 'TestNAT.*(SourceAddressName|DestinationAddressName)' -count=1`. The complete userspace module passed with `go test ./pkg/dataplane/userspace -count=1` (292.428s).

## Risk

The prefix changes only the wire token for unresolvable NAT address-name references. Concrete successful address-book resolutions and their installed prefixes remain unchanged. Strict commit validation continues to reject invalid references; this is the tolerant-load/peer-sync dataplane backstop.
