# 12957 — padded DHCP group refs resolve their effective host-inbound policy

- **Issue**: #12957 (follow-up #12842) — `compiler_validate_warn_dhcp_hostinbound.go` indexes authored `dhcp-local-server` group interface refs against the canonical zone map and the effective-policy resolvers without canonicalization, so a padded ref (`ge-0/0/1.00`) silently skips the WARN-only #6460 advisory.
- **Branch**: `fix/12957-campaign-pub`
- **Worktree**: `/var/worktrees/campaign-pub/wt-12957`
- **Base**: `origin/master` at `6372394b1` (`userspace-dp: gate SYN alarm drain on ingress zone state (#13000)`)

## What was already fixed, and what this change closes

The GLM residual review of PR #12949 (#12842) cited two defect sites in this
advisory. The zone-map lookup was canonicalized hours later by #12843
(`dd504f015`, `ifKey := cfg.SplitInterfaceUnitRef(ifn).Literal`), which fixed
the map miss and deliberately kept the effective-policy probes on the authored
spelling ("authored overrides still probed as authored").

The second site stayed open: `InterfaceHostInboundOverride(ifn)` and
`InterfaceHostInboundEffective(ifn)` canonicalize internally only through the
COMPILED stamp (`ResolvedInterfaceOverrides`, stamped by
`resolveDerivedConfig` P5). Every production caller reaches this advisory with
stamps — `CompileConfig`/`CompileConfigLenient` both run P5 before the tail
gates, and the CLI/gRPC `ValidateConfig` callers read `store.ActiveConfig()`,
the compiled config. But a stamp-free config (hand-built fixture, or any future
caller ahead of `resolveDerivedConfig`) keys its overrides by spelling, and the
legacy resolver arm probes only the raw ref plus its physical base:

- zone admits `dhcp`, canonically-keyed override omits it → the override is
  missed, the zone-level token answers, and the #6460 warning is **silently
  skipped** (the issue's stated failure mode);
- zone omits `dhcp`, canonically-keyed override admits it → the override's
  admission is ignored and a **false warning** fires with the unneeded
  zone-level remedy.

## Change

`validateDHCPServerHostInboundBypassWarnings` now resolves the effective-policy
probes through both spellings of the group ref: the authored spelling first
(an override keyed by that exact spelling still applies on a stamp-free
config — #12843's guarantee, kept green), then the canonical `Literal` the zone
lookup already resolved through. An override declared under either spelling
replaces the zone set (#6515); same-identity declarations union exactly as the
compiled stamp unions them; with no declaring spelling the zone-level set (as
#7490 applies it to the interface) answers. The operator-facing message still
names the authored spelling. The #7490/#6519 suppression guard is unchanged —
`WithholdsZoneLevelDHCPFor` already canonicalizes through the stamp, and a
stamp-free config has no withholding stamp to read.

Canonical-spelling group refs (`ifKey == ifn`) take the single-probe path and
behave exactly as before; stamped configs answer identically through either
spelling, so the compiled path is unchanged (pinned green by the new end-to-end
cases both before and after this change).

## RED then GREEN evidence

Before the implementation, the new regressions failed on the unchanged base
(`6372394b1`):

```text
go test ./pkg/config -run 'TestPaddedDHCPGroupRef(ResolvesOverridePolicy|CompiledAdvisory)12957' -count=1 -v
--- FAIL: TestPaddedDHCPGroupRefResolvesOverridePolicy12957/override-admits
    padded ref must see the canonically-keyed override that admits dhcp, got
    [system services dhcp-local-server group "g1" serves interface "ge-0/0/1.01"
    (security zone "untrust") but that zone's host-inbound-traffic
    system-services set omits "dhcp" ... (#6460) ...]
--- FAIL: TestPaddedDHCPGroupRefResolvesOverridePolicy12957/override-omits
    padded ref must be held to the canonically-keyed override that omits dhcp, got []
```

`override-omits` is the silent skip (`got []`); `override-admits` is the false
warning. The control cases (`authored-spelling-override`,
`both-spellings-union`) and the compiled end-to-end cases passed on the base —
the compiled path was already correct through its stamps, which is why this is
a warning-path residual and not a production enforcement gap.

After the change, the same command passed:

```text
go test ./pkg/config -run 'TestPaddedDHCPGroupRef(ResolvesOverridePolicy|CompiledAdvisory)12957' -count=1
ok  github.com/psaab/xpf/pkg/config
```

## Risk

Low, warning-path only. The advisory has no error return and installs no
dataplane state (structural no-brick posture, unchanged). Compiled configs
produce identical warnings through either probe spelling; only stamp-free
configs with a padded group ref AND a differently-spelled interface override
change behavior — from a skipped/false #6460 warning to the correct one. No
other consumer of `InterfaceHostInboundOverride`/`InterfaceHostInboundEffective`
is touched; their legacy arm semantics are unchanged.
