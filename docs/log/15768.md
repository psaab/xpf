# #15768 — session-miss scoped-NAT FIB lookup honours `route_table_override`

- **Issue**: #15768 (G35-01) — the #15118 scoped-NAT session-miss lookup ignored the caller's PBR/native-VRF table, cleared `resolved_in_table` provenance, and deep-cloned `ForwardingState` on the unclaimed-NAT branch.
- **Files**: `userspace-dp/src/afxdp/forwarding/fib.rs`, `userspace-dp/src/afxdp/poll_descriptor/mod.rs`, `userspace-dp/src/afxdp/forwarding/tests_nat_scope_15118.rs`, `userspace-dp/src/afxdp/forwarding/README.md`, `debian/changelog`, `docs/log/15768.md`.

## Why

The untranslated session-miss arm (`pre_routing_dnat.is_none() && nptv6_inbound.is_none() && nat64_match.is_none()`, i.e. every ordinary untranslated flow) called `lookup_forwarding_resolution_for_nat_flow` with no table argument. That helper hard-coded `table=None` in both branches, so a flow steered by filter-based forwarding or arriving on a native routing-instance member resolved in `inet.0`/`inet6.0` instead of its `route_table_override` table — a wrong-table egress / VRF leak or blackhole. The arm then returned `resolved_in_table=false`, so `install_table_stamp_for_miss` cleared the installing-table stamp to `(0,0)` and every later re-resolve ran in the default table. On the registered-but-unclaimed NAT branch, `lookup_forwarding_resolution_without_nat_local(..., None)` additionally discarded the flow's 5-tuple ECMP hash and `state.clone()` deep-copied the whole `ForwardingState` (all route/neighbor/NAT maps), despite its comment claiming it cloned "the (small) local sets". The narrowed live form (synthesis §7) scopes the ECMP/clone limbs to that unclaimed branch; ordinary non-NAT-local flows already kept 5-tuple hashing via `lookup_forwarding_resolution_with_dynamic_for_flow` and must not regress. The flowless path (`flowless_verdict.rs`) already threaded `route_override` and is untouched.

## What

- `lookup_forwarding_resolution_for_nat_flow` (`forwarding/fib.rs`) now takes `table: Option<&str>` and `icmp: Option<(u8, u8)>` and returns the full `ForwardingLookupResult` (resolution + `selected_route` identity of the resolving table) instead of discarding it. The ICMP context feeds `nat_destination_claims_local`, matching the pre-routing DNAT lookup's ICMP-constrained rules. The claimed arm resolves via `lookup_forwarding_resolution_with_dynamic_for_flow_in_table` when a table is given (plain flow lookup otherwise, `inner_ecmp` with the flow hash when no neighbor map is available); the unclaimed arm passes the table plus `Some(ecmp_hash_flow(&flow.forward_key))` into the suppressed lookup.
- `lookup_forwarding_resolution_without_nat_local` no longer clones: the suppression is a `Some(dst)` marker threaded through new `*_suppressing` variants (`lookup_forwarding_resolution_inner_ecmp_suppressing`, `lookup_forwarding_resolution_v[46]_suppressing`/`_inner`, `table_has_*_route_suppressing`, `local_delivery_resolution_*_suppressing`, `local_*_owned_by_table_suppressing`) into the per-table local-ownership predicates. Public wrappers pass `None`, so every existing caller is behaviour-identical. The predicates reproduce the clone semantics exactly: a suppressed address that is NAT-registered and not a configured interface address is not locally owned (in any table, mirroring the removed `local_nat_any_table_*`/`local_tables_*` entries); a configured interface address on the same IP stays local. The walk allocates nothing beyond the canonical-table `Cow` the ordinary lookup already produces.
- Poll caller (`poll_descriptor/mod.rs`): passes `route_table_override.as_deref()` and `dnat_packet_icmp` (already computed for the DNAT lookup) into the helper, takes `.resolution`, and returns `resolved_in_table=true` for the arm — the same provenance the translated else-arm already reported. Claimed-NAT, tunnel-block, ingress-interface and interface-NAT arms are unchanged.

## Risk

Behaviour changes only for untranslated session misses that carry a `route_table_override` (PBR or native routing-instance members): they now resolve and stamp in that table instead of `inet.0` — the intended Junos semantics, and the direction the translated arm and the session re-resolve path (#9752) already took. Default-table flows (`route_table_override=None`) follow the identical lookup as before, except the unclaimed-NAT branch now also spreads by the flow's 5-tuple hash instead of the per-destination hash (consistent with every other session resolution, #2734). The suppression marker touches only the resolving walk's local-ownership predicates for the exact suppressed address; leak prechecks in unrelated walks pass `None`. No registration, proxy-ARP/ND, ownership, or claimed-destination behaviour changes. The helper's signature change is internal (`pub(in crate::afxdp)`); its only production caller is the poll miss arm.
