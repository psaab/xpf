# #15776 — `protocols lldp` packed/chained leaves and duplicate interfaces

## Defect

`compileProtocols` iterated `lldpNode.Children` directly, unlike its
OSPF/OSPFv3/RIP/ISIS siblings which expand packed and flat-set shapes
first. Consequences at origin/master `f7c921ce29` (probed):

- `protocols lldp disable;` and `protocols { lldp disable; }` compiled
  `Disable=false` — `"lldp disable"` was also missing from the
  compact-normalize scope list (`compact_normalize_scope.go`), so the
  brace-elided spelling was never split into a child.
- Flat-set chains nested under a terminating leaf were dropped:
  `set protocols lldp transmit-interval 10 disable` compiled
  `Interval=10, Disable=false`; `... disable transmit-interval 10`
  compiled `Disable=true, Interval=0`; `hold-multiplier 5 disable`
  dropped the disable. Packed runs inside braces
  (`transmit-interval 10 disable;`) likewise lost the chained leaf,
  and a packed tail beside a braced body
  (`lldp transmit-interval 10 disable { interface ...; }`) lost both.
- Duplicate same-name interfaces both reached the typed config:
  `interface ge-0/0/0; interface ge-0/0/0 { disable; }` (either order)
  produced two entries, and `lldp.Manager.Apply` started a session
  for the enabled duplicate — a per-interface disable failed open
  into duplicate LLDP sessions.

Unique-interface `disable` and sibling `lldp` blocks (already merged
by the #9023/#12120 dup-block fold) were honoured pre-fix and are
pinned as controls.

## Fix

- `pkg/config/compiler_protocols.go`: LLDP now reads
  `expandFlatRun(flattenChainedChildren(packedTopChildren(lldpNode,
  schemaForPath("protocols","lldp")), schema), schema)` — the same
  packed/chained expansion chain as OSPFv3 — and merges duplicate
  same-name interface entries with disable-wins.
- `pkg/config/compact_normalize_scope.go`: add `"lldp disable"` to
  the routing compact-normalize scope, beside the existing
  `lldp hold-multiplier` / `lldp interface` / `lldp transmit-interval`.
- `pkg/lldp/lldp.go`: `Manager.Apply` collapses duplicates via
  `dedupInterfaces15776` (kernel-name keyed, disable-wins) before
  `expandAllInterfaces`, as defense-in-depth for hand-built configs.

NOT changed: the #9023 sibling-block fold (already correct), the
#14616 packed-interface validator, and the `interface all` expansion
semantics (#14617) — dedup runs before expansion and preserves them.
