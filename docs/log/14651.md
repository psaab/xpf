# Fence announced permit epochs and reject stale authority regressions (#14651)

- **Issue**: #14651 (deep-review finding D1-04).
- **Cause**: In `userspace-dp/src/slowpath_reinject_9506.rs`,
  `AuthorityState::publish_announce` with `permit_open=false` set
  `open=false` but never advanced `closed_epoch` (unlike `publish(0)`
  and `close_permit`, which do `closed_epoch = max(closed_epoch, ...)`).
  A later same-epoch announce with `permit_open=true` therefore
  re-opened the fenced epoch (`open = true && epoch > closed_epoch(0)`),
  and `allows()`/`decide_pre_write` would `Proceed` a queued q0 write
  for that epoch. There was also no `generation < self.generation`
  reject for the same `run_id`, and `queue_epochs` were replaced
  wholesale with no per-queue monotonicity check in either
  `publish_announce` or the snapshot `publish`, so a stale message
  could roll a queue epoch backward (100 -> 50) and re-admit a
  superseded queue epoch. The Go sender is honest-monotonic (close
  bumps `permitEpoch`, open bumps again; announces deduplicated under
  `authorityMu`), but the Rust state is the fence of last resort for
  replayed/reordered socket messages, and stale socket replay is
  exercised in `pkg/nfqueue/reinject_announce_9506_test.go`.
- **Change** (`AuthorityState` only; no wire or Go change):
  - `publish_announce`: an announce-close now fences monotonically,
    `closed_epoch = max(closed_epoch, permit_epoch)`, exactly like
    `close_permit`; only a strictly higher permit epoch opens again.
  - `publish_announce`: a generation regression for the same run is
    rejected before any mutation. Equal generation stays accepted as
    an idempotent re-announce; the #10478 same-epoch generation
    advance stays accepted.
  - `publish_announce` and `publish`: at the current permit epoch a
    queue epoch must not move backward for a queue already known;
    a regression rejects the whole update without adopting its
    generation or rows. Queue epochs are minted monotonically per
    queue number by the Go allocator (`lastEpoch[number] + 1` in
    `pkg/daemon/ipsec_queue_lifecycle.go`), so a lower value at the
    same permit epoch can only be stale/reordered. A queue absent
    from the update is a withdrawal, not a regression, and a higher
    permit epoch starts a fresh queue set.
- **Regression coverage**
  (`userspace-dp/src/slowpath_reinject_9506_tests.rs`):
  - `announce_closed_permit_epoch_cannot_reopen_and_rejects_stale_generation_14651`:
    open(10) -> announce-close(10) fences a queued q0 lease
    (`PreWrite::Fenced`); a stale generation (2 < 6) open announce is
    rejected; even a newer generation (7) cannot re-open epoch 10;
    epoch 11 opens.
  - `announce_rejects_queue_epoch_regression_same_permit_epoch_14651`:
    queue epoch 100 -> 50 at the same permit epoch is rejected and
    neither generation nor rows are adopted.
  - `announce_rejects_generation_regression_same_run_14651`:
    generation 6 -> 2 for the same run is rejected.
  - `publish_rejects_queue_epoch_regression_same_permit_epoch_14651`:
    the snapshot `publish` path has the same queue-epoch fence.
  Controls that stay green include
  `authority_rotation_accepts_generation_advance_same_epoch` (#10478),
  `announce_zero_revokes_prior_open_permit`, and
  `authority_restart_accepts_new_run_id_with_lower_epoch` (a new
  `run_id` still starts a fresh timeline).
- **RED evidence**: With only the production file reverted, all four
  new tests fail (e.g. `stale generation (2 < 6) must be rejected`,
  `same permit epoch must not roll a queue epoch backward`). Command:
  `cargo test --manifest-path userspace-dp/Cargo.toml --bin
  xpf-userspace-dp 14651 -- --test-threads=1` (0 passed, 4 failed).
- **GREEN evidence**: With the fix, the same command reports 4 passed;
  `slowpath_reinject_9506::` reports 75 passed, 0 failed; the wider
  `reinject_9506` filter (including the server-side tests) reports
  89 passed, 0 failed.
- **Blast radius / risk**: Only stale/regressed authority updates are
  newly rejected; honest monotonic Go senders are unaffected. A new
  `run_id` (daemon restart) still resets the timeline. No Go, wire,
  or snapshot-format change.
