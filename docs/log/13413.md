# Issue #13413: Preserve lifeline stale-reply traffic

The uncovered-ingress stale-reply fallback included owner-denied,
lifeline-shared addresses but excluded only covered data ingress and the
trusted reinject device. Because lifelines are intentionally absent from
host-inbound ingress ownership, a reply arriving on `fxp0` matched the
fallback and was dropped before the established-reply accept.

The fallback now adds direct and enslaved lifeline exclusions only for
`IngressDenyV4/V6` addresses, preserving those shared-address replies without
changing fallback scope for other owner-denied addresses. Data ingress remains
guarded. Regression coverage pins both direct/VRF behavior and ordinary
owner-denied fallback scope.

The regression failed on pristine master `dd607606` because the fallback
excluded `ge-data` but not `fxp0`; it passes after the fix.

Validation:

- `go test ./pkg/nftables -count=1` — pass.
- Targeted nftables regression, userspace lifeline builder, and daemon lifeline
  renderer tests — pass.
- `go vet ./pkg/nftables ./pkg/dataplane/userspace ./pkg/daemon` — pass.
- The full affected-package run was attempted. `pkg/nftables` passed;
  `pkg/dataplane/userspace` and `pkg/daemon` had failures including short
  Unix-socket paths under the configured temp directory, snapshot/scope
  assertions, and permission-restricted kernel operations. The old daemon
  assertion that banned all `fxp0` text was updated for the intended negated
  exclusion, and its targeted test passes.
