# #12246 — require post-DNAT input for policy matching

- **Timestamp**: 2026-10-08 (`fix/12246-matchpol-nat`)
- **Action**: make the policy-only tuple-stage contract explicit wherever match-policies returns a verdict.

## Red before

At clean base `a714c90d4`, the VIP-vs-real fixture configured DNAT from `203.0.113.10:80` to `10.0.0.5:8080`, a VIP-permit policy, then a server-deny policy. The actual dataplane evaluates policy after destination translation (`policy_dst_ip = effective_resolution_target`), while `policymatch.Match` evaluates the literal tuple. `show security match-policies` therefore printed `permit-vip` for the VIP query without saying that the policy simulator had not translated it.

## Change

- The shared match-policies / test-policy usage text and `policymatch.Query` contract now specify that destination IP and port are expected as the post-translation tuple; the policy simulator does not perform NAT.
- `policymatch.Result.PostNATInputNote` carries the explicit requirement when inbound destination translation is configured. Local and remote CLI, REST JSON (`post_nat_input_note`), and gRPC (`post_nat_input_note`, field 31) surface it alongside the policy verdict.
- Added the VIP-permit/server-deny CLI regression and a shared usage/result contract test.

## Validation

- **RED before**: `go test ./pkg/cli -run '^TestShowMatchPoliciesRequiresPostDNATInput$' -count=1 -v` failed on base. The observed output was a `permit-vip` verdict with no post-DNAT/post-translation requirement.
- **GREEN after**: the focused CLI regression and `go test ./pkg/policymatch -run '^TestPostNATInputRequirement12246$' -count=1 -v` passed.
- **Scoped suites**: `go test ./pkg/policymatch ./pkg/cli ./pkg/api ./pkg/grpcapi ./cmd/cli -count=1` passed for policymatch, cli, api, and grpcapi. The `cmd/cli` suite had one broader red: `TestTreeIsGofmtClean` reports `pkg/cli/cleartext_sync_alarm_11773_test.go` among 11 pre-existing unformatted files.
- **Same-base attribution**: on a clean `a714c90d4` worktree, `go test ./cmd/cli -run '^TestTreeIsGofmtClean$' -count=1` fails with the same 11-file count and the same `pkg/cli/cleartext_sync_alarm_11773_test.go` entry.
- `go build ./pkg/policymatch ./pkg/cli ./cmd/cli ./pkg/api ./pkg/grpcapi` passed. `gofmt -l` over all touched Go files (including generated protobuf code) printed no files.
- No live cluster was used or mutated.

## Residual / risk

This change deliberately documents and reports the accepted post-NAT-input requirement; it does not implement DNAT translation in the policy simulator. A pre-NAT VIP query still evaluates the literal VIP policy tuple, but the returned note explicitly warns that the verdict is not the dataplane's post-translation decision. Operators must query with the translated server address and port.
