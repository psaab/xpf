# #14314 — Stage-11 IPsec claim follows the effective routing table

## Why

`stage_ipsec_passthrough_check` re-derived its local-ownership table
from the raw/physical ingress logical ifindex
(`ifindex_to_routing_instance[ingress_logical]`), ignoring the
packet's already-resolved scope. Transit ESP/AH/IKE steered by an
input-filter PBR `then routing-instance <vrf>` term (or arriving on
`fab0` for a tenant VRF) whose destination IP happens to be owned by
`inet.0` was falsely claimed by Stage 11 (`junos-host`) and reinjected
into `xpf-usp1`, bypassing the tenant VRF's transit zone policy.
Conversely, host-bound IPsec steered into a tenant VRF failed
`owns_ipsec_local_destination_in_table` in `inet.0` and missed
`xpf-usp1`. In the caller, `ingress_route_table_override` was
evaluated only after the claim and only `RouteOverride::Drop` was
honoured.

## What

- `userspace-dp/src/afxdp/poll_stages.rs`: `stage_ipsec_passthrough_check`
  gains a `route_override_table: Option<&str>` parameter and resolves
  the claim table as the EFFECTIVE table, in order: (1) the caller's
  PBR `RouteOverride::Table` steer; (2) `flow.forward_key.routing_domain`
  (stage-9b-stamped from the validated fabric zone / V2 scoped
  ifindex) via the `install_tables` registry; (3) the validated V2
  fabric scope's (`meta.fabric_ingress_ifindex`) canonical table;
  (4) the ingress interface's canonical table (pre-fix behaviour,
  domain 0). A nonzero domain with no registry row (or no family row)
  returns `NotClaimed` — fail-closed, mirroring
  `NativeRouteTable::Unresolvable`, never falling back to `inet.0`.
  NOT changed: host-inbound IKE gating, the #6471 exchange-key scope
  (zone + stamped domain), DNAT-to-self handling, fine lo0/junos-host
  gates.
- `userspace-dp/src/afxdp/poll_descriptor/mod.rs`: for IPsec
  candidates only, resolve `ingress_route_table_override_uncounted`
  BEFORE the Stage-11 claim. `Drop` recycles immediately; `Table`
  scopes the claim. The counted evaluation (reject reply + term
  counter/log) still runs exactly once: in the claimed arm below, or
  on the ordinary miss path for unclaimed packets — the pre-claim
  probe is uncounted so no term double-counts.
- `userspace-dp/src/afxdp/poll_stages_tests.rs`: new decisive
  regression `stage_ipsec_claim_follows_effective_table_14314`
  (fixture: `10.0.61.1` in `inet.0` on ifindex 24, `172.16.80.8` in
  `vrf_blue` on ifindex 25): PBR `Table("vrf_blue.inet.0")` must not
  claim the `inet.0` dst and must claim the `vrf_blue` dst; a
  `vrf_blue`-domain-stamped flow and a validated fabric scope
  (`fabric_ingress_ifindex` → `vrf_blue`) give the same pair of
  outcomes; an unregistered domain fails closed; an unsteered
  `inet.0` control still claims. The #14124 cross-VRF seed cell now
  stamps the tenant's real install domain against a tenant-owned
  ingress state (a synthetic unregistered stamp is unreachable in
  production and now fails the claim closed before the key check).
  All other Stage-11 call sites pass `None` for the new parameter.

## Risk

- A legitimate IPsec flow whose stamped domain lacks an install-table
  row (instance with no dataplane presence) now returns `NotClaimed`
  and takes ordinary forwarding/policy instead of XFRM reinjection —
  fail-closed, consistent with native route resolution (#10312).
- The pre-claim uncounted PBR probe runs only for IPsec candidates;
  non-IPsec traffic pays nothing.
