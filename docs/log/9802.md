- **Timestamp**: 2026-09-12
- **Action**: Cause, in `mergeNodes` (`pkg/config/ast_groups.go`).
  1. A group container with no same-keyed destination is appended wholesale.
     The subtree is never recursed into, so a wildcard-keyed node inside it is
     never matched and lands as a literal instance name.
  2. A group container merges into the FIRST same-keyed destination and stops,
     so a level the operator spread over two blocks receives the group in only
     one of them.
- **Action**: Change, in `pkg/config/group_container_wildcard_9802.go` (new)
  with two edits to the container branch.
  - **Prune.** A wildcard-keyed node in an adopted subtree matched nothing by
    construction, so it is dropped before the #6767 charge, and a container
    whose whole body was wildcard-keyed is not adopted at all.
  - **Prune scope, measured.** The discriminator is the node's SHAPE, not the
    schema: a zone's `interfaces` member slot is declared as a wildcard child
    WITH children, exactly like a dynamic instance name. A schema-shape
    predicate therefore pruned `interfaces { <ge-*>; }` inside an adopted zone,
    and the strict refusal that names the token turned into a clean commit.
    Only a wildcard CONTAINER, or a wildcard leaf carrying an instance name
    (two or more keys), is dropped; a single-key wildcard leaf is a member and
    is left to the compiler's reference check (#9423).
  - **Routing.** A group container's wildcard-keyed children go to every
    same-keyed destination container, each clone charged as the wildcard branch
    charges its fan-out; the rest go to the first container that already holds
    a match for one of them, else the first, as before. Splitting the body is
    what keeps a concrete block from being duplicated across stanzas.

- **Action**: The post-hoc Codex round on the merged change reported two High
  findings and one Medium. All three reproduce; each was measured at ef390f3ac
  against the merged 4cc9b66e6, so none rests on a static trace.

  | Row | ef390f3ac | 4cc9b66e6 |
  |---|---|---|
  | `description "<*>"` in a wholesale-adopted container | kept | **dropped** |
  | compact member `interfaces <ge-*>;` | strict refuses | **commits clean** |
  | block member `interfaces { <ge-*>; }` | refuses | refuses |
  | group body with `screen` and `zones`, target splitting them | `trust.ScreenProfile=edge` | **lost** |
  | group pair `from-zone trust to-zone untrust` beside a `to-zone dmz` stanza | one set `[qu,pg]` | **two sets, `pg` first** |

- **Action**: Causes, both mine.
  - The prune keyed on node SHAPE (`!IsLeaf || len(Keys) >= 2`). An ordinary
    two-key leaf matches that: a scalar whose value spells a wildcard, and a
    COMPACT zone member (`Keys=[interfaces, <ge-*>]`). The second turned a loud
    strict refusal into a silent acceptance, which is what the N2 cell existed
    to prevent; every cell used the BLOCK spelling, so the matrix could not see
    it. Three placements of one spelling are not three spellings.
  - The routing bundled all non-wildcard children to one receiving stanza, so a
    body carrying `screen` and `zones` sent both to whichever stanza matched
    first. For the policy pair, a shared first key captured the group's pair
    into the wrong stanza, and the compiled config then carried two zone-pair
    sets with the group's policy evaluated FIRST.
- **Action**: Fix.
  - The prune is schema-scoped again: a wildcard-keyed container, or a wildcard
    inside the identity span (keyword plus args) of a child the schema declares
    with `args >= 1`, not `scalar`, and container-shaped. A scalar value and an
    args-0 member slot are both excluded, so the compiler's own checks judge
    them as they judge the braced spelling.
  - Each concrete child routes independently, preferring an exact key match
    over a shared first key.
- **Action**: Cells, each failing at 4cc9b66e6 with its message: the scalar
  survives; the COMPACT member stays refused; `screen` and `zones` each reach
  their own stanza; and the policy pair compiles as one set in inline-then-group
  order.
