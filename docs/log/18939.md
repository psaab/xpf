# #18939: rate-limited SessionSync fabric dial-failure log

- **Timestamp**: 2026-11-03
- **Action**: `fabricConnectLoop` (pkg/cluster/sync_conn.go) silently discarded
  dial errors (bare `continue` at the old :1497-1499), so a peer that could
  never be dialed retried invisibly every second — exactly what hid the
  #18038 testguard lo-down rot behind a "never connected" deadline in #18933.
  The dial-failure path now emits a rate-limited `slog.Warn`
  (`cluster sync: dial to peer failed`, attrs `addr`, `fabric`, `err`,
  `suppressed_since_last`) with NO control-flow change: same 1s retry
  cadence, same error-swallow semantics.
  - **Idiom reused**: `heartbeatRejectWarnLimiter`
    (pkg/cluster/heartbeat_reject_warn.go) — injectable monotonic clock seam
    (`fabricDialWarnNowNanos = MonotonicNanos`), 30s interval matching
    `heartbeatRejectWarnInterval`, `admit()` returning `(emit, suppressed)`
    so the bound never conceals the volume. One deliberate divergence,
    documented on the type: no mutex, because the limiter is loop-local state
    owned by exactly ONE `fabricConnectLoop` goroutine (one per fabric,
    started once per session incarnation), and a fresh incarnation's first
    dial failure is news again by design. Extension over the heartbeat
    shape: a CHANGED error string emits at once — SUPERSEDED by the fold
    below (PR #18950 finding 2): the interval now binds across error changes
    too; the interval emission names the current error.
  - **File(s)**: `pkg/cluster/sync_conn_dial_warn_18939.go` (limiter),
    `pkg/cluster/sync_conn.go` (wiring: `var dialWarn fabricDialWarnLimiter`
    before the loop; `admit`-gated `slog.Warn` inside the dial-error arm),
    `pkg/cluster/sync_conn_dial_warn_18939_test.go` (cells),
    `docs/log/18939.md`.
- **Validation**: all via `./scripts/testguard-run.sh` (GOCACHE=
  /var/worktrees/.cache/go-build, GOTMPDIR=/wtgt; never overridden).
  - RED (limiter + tests present, wiring absent — bare `continue` at base):

    `TestFabricDialFailureWarnIsRateLimitedOnTheRealPath_18939` FAIL in

- **Risk**: Log-only observability change; no dial timing, retry, or teardown

## Fold — PR #18950 re-review (2026-11-03)

Three findings folded (Kimi seat MERGE-NEEDS-MINOR x3, parent-ruled):

1. **RACE (test-only)**: the pinned clock closure raced — a plain captured
   `int64` written by the test's setter while the `fabricConnectLoop`
   goroutine read it through `admit()`. `withPinnedFabricDialClock18939`
   now pins an `atomic.Int64`, and `goFabricConnectLoop18939` registers a
   cleanup that cancels the context and JOINS the loop goroutine; it
   registers LAST, so (t.Cleanup LIFO) the join runs before the slog and
   clock seams restore — the loop can never read either seam after
   teardown. Reproduced the seat's finding first: `go test -race
   ./pkg/cluster/ -run '^TestFabricDial' -count=1` at pre-fold head
   d0fd307e32 → `WARNING: DATA RACE` + FAIL; PASS after (also -count=3).
2. **OSCILLATION BOUND (production)**: `admit()` now applies the 30s
   interval across error-text CHANGES — first-ever failure emits; every
   failure inside the following interval is suppressed and counted whatever
   its text; at/after the interval the CURRENT error logs with the
   suppressed count. The "changed error always emits" arm is deleted (with
   it the unused `lastErr` field): at the loop's one attempt per second, an
   error oscillating A-B-A changed text on every attempt and emitted on
   every attempt — unbounded, the exact flood #18939 exists to bound. Error
   visibility survives at interval granularity: the emission names the
   error the caller currently sees (the wiring's live `err` attribute).
   `admit()` is now parameterless, exactly the heartbeat idiom's shape.
   Cell: `TestFabricDialWarnLimiterBoundsOscillation_18939` (A-B-A inside
   one interval = 1 emission; interval emission reports suppressed=3; the
   fresh window suppresses again). RED-verified by flipping the suppression
   arm off (`if false && ...`, the emit-every-call superset of the pre-fold
   change-emits rule): FAIL at attempt 0, restored, GREEN.
3. **CTX GUARD (production wiring)**: the error arm skips the warn when
   `ctx.Err() != nil` — intentional Stop/session-restart cancellation is
   not a peer failure (a cancelled first dial would otherwise emit one
   spurious "peer unreachable" line per restart). No retry/exit flow
   change. Cell: `TestFabricDialCancellationIsSilent_18939` starts the loop
   with an ALREADY-CANCELLED context against the unreachable address, so
   the first dial deterministically fails inside the guarded arm; RED
   verified with the guard temp-disabled (`if true`): FAIL "1
   dial-failure warnings on a cancelled context, want 0", restored, GREEN.
   Named with the TestFabricDial prefix so the family sweep covers it.
