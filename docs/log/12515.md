# Issue #12515 — Gate empty rollback convergence on helper authority

## Why

A commit-confirm C2 can land while its ACK is lost, leaving helper publication
outcome unknown. If the timer rolls back to C1, retained invalidation debt can
re-anchor the plan to an empty C1→C1 diff. The old empty-diff fast path recorded
an empty capture without checking authority, allowing C1 to be marked applied
while a session admitted only by C2 remained live.

## What

- The empty-diff fast path now checks the helper's known applied config when the
data plane provides the authority-aware policy LIST surface. Unknown or changed
authority retains the rollback plan and debt instead of allowing convergence.
The check runs under `applySem`; it does not scan the session table.
- Only a retry that rolls back to the retained debt's recorded predecessor may
adopt the refused debt for discharge. Superseding commits do not inherit that
rollback-only behavior.
- Dataplanes without the policy LIST authority surface keep their existing
legacy empty-diff behavior.
- `TestPolicyInvalidationRollbackAfterLostAckRevokesC2OnlySession12515` covers
C1→commit-confirm C2→lost ACK→session 1099 admitted under C2→timer rollback.
It asserts `ActiveApplied` remains false without an apply attempt while
authority is unknown; after helper reconciliation to C2, the C2-only session is
revoked before C1 is marked applied, while C1's web session survives.

## Risk

When helper authority is unknown, the rollback intentionally remains unapplied
and the newly admitted session remains live until reconciliation. This avoids a
false `ActiveApplied` marker; the retained retry then captures under the
reconciled C2 authority before applying C1. No per-candidate provenance or
nested rollback behavior from #12532 is changed.
