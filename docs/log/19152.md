- **Timestamp**: 2026-11-16 (fold, Codex bounded check of b7f, F5/F6 —
  second round on the same root cause, so the mechanism is REMOVED)
- **Action**: Both findings verified.
  - F5: the drain check was an observation, not a barrier: a lane could
    start after it and lose its toolchain.
  - F6: two renames are not one atomic switch. A crash between them left the
    public path missing, and a re-run then took the fresh-install branch.
- **Action**: In-place replacement is gone:
  - `install_go_version` installs each release ONCE into its own directory
    (`/usr/local/go-<v>`, `/usr/lib/go-<v>`): staged beside it, version
    checked, then renamed into the EMPTY path. An existing directory of the
    right version is left alone; one of the wrong version is an error, never
    replaced;
  - `publish_link` points `/usr/local/bin/{go,gofmt}`, `/usr/bin/{go,gofmt}`
    and `/usr/local/go` at the new version by a new symlink renamed over the
    old one. rename(2) replaces a symlink atomically, so the path always
    resolves to the old or the new target. A pre-versioned real
    `/usr/local/go` directory is left alone;
  - old versions are never deleted automatically. `--gc-toolchains`
    (workstation `--runner R --gc-toolchains`) removes unpublished versions,
    the legacy directory and stale staging directories, and is refused (75)
    while a lane is live;
  - so no barrier is needed for an install: a running lane keeps its old
    tree, and `--toolchains-only` is safe with lanes running.
- **Action**: `scripts/provision-testrunner-selftest.sh` rewritten. Cells:
  fresh, upgrade (old tree kept), same version again, wrong download, wrong
  existing dir, legacy dir, failed publishing rename (the old link still
  resolves), GC busy (refused) and GC idle (only the published version left).
  Mutants: non-atomic publish (unlink, then link), an install that deletes the
  other versions, GC without the idle check.
