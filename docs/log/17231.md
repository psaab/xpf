# Issue #17231: proxy-ARP responder copies LLDP's false "close the fd to unblock Recvfrom" wake and has no join

- **Timestamp**: 2026-10-27
  - **Action**: STEP-0 confirmed the defect live on current origin/master (9f39e9331e): `pkg/daemon/daemon_proxyarp_responder_8621.go` still parked in a bare `unix.Recvfrom`, woke only via a watcher goroutine closing the fd on `ctx.Done` (which does not wake a parked Recvfrom on Linux), tore down as cancel+delete with no join, and sent replies without re-checking ctx after a successful recv. #16669 is CLOSED but fixed LLDP only with an inline ppoll+eventfd inside pkg/lldp, so this copy survived. Fixed by adding one shared cancellable raw-receive primitive `linuxsock.PpollRecv` (ppoll on {socket, wake eventfd}; `SignalStop` wakes, owners close only after joining — signal \u2192 join \u2192 close), migrating LLDP's `ifSession` onto it (deleting its inline ppoll/wake/close machinery), and migrating the proxy-ARP responder: `cluster.OpenARPSocket` \u2192 `cluster.OpenARPReceiver` returning the primitive, the loop publishes it for teardown signalling, re-checks ctx after every successful recv before sending, and `syncProxyARPResponders`/`stopProxyARPResponders` now call `r.stop()` (cancel \u2192 SignalStop \u2192 join on done; the loop owns the receiver Close before done closes). Extended the linuxsock AST canary with `TestNoDirectBlockingRecvfrom`, allowlisting only the primitive itself and nfqueue's poll-guarded reads.
