# Issue #15930 — NAT64 source scope: poisoned name -> wildcard; explicit `any` -> matches nothing

## Defect
- C1/F3 (HIGH/MEDIUM): `buildNAT64SnapshotsWithFeeds` responded to a
  poisoned `match source-address-name` closure (dns-name with zero
  answers, empty/unknown-member address-set, undefined name on the
  tolerant path) by clearing `sourceAddrs` to empty. `NAT64RuleSnapshot`
  serialises the list `omitempty`, so Rust derived
  `source_constrained=false` and `prefix_scope_matches` returned true
  for EVERY IPv6 source — a transient DNS failure silently widened the
  NAT64 rule to any-source until repair/refresh.
- C3/F4 (MEDIUM): strict validation admits `match source-address any`,
  the compiler and builder copied it verbatim, and Rust parsed it as
  neither CIDR nor host while keeping `source_constrained=true` over
  zero prefixes — the explicit wildcard matched NO source, inverting
  the authored scope in the opposite direction.

## Fix
- Go builder (`pkg/dataplane/userspace/nat64.go`): authored
  constrainedness is tracked separately from resolution. Any poisoned
  name replaces the WHOLE side with the existing never-match sentinel
  `unresolved-address-name:<name>` (plus a Warn log), never an empty
  list and never a surviving subset. A name resolving empty without
  poisoning (present-empty fail-mode-drop feed, zero-answer DNS entry)
  already carries the same sentinel via
  `appendNATAddressNamesPoisoned`. A wildcard-only side (`any` /
  `any6` / `any-ipv6`) lowers to the canonical `::/0` (matches any,
  like an omitted selector); an IPv4-only wildcard stays a never-match
  entry. A defence-in-depth guard re-sentinels any authored constraint
  that would otherwise reach the wire empty.
- Wire: `NAT64RuleSnapshot.source_constrained` (Go
  `pkg/dataplane/userspace/protocol_nat.go`, Rust
  `userspace-dp/src/protocol/nat.rs`) records authored constrainedness
  independent of resolution. ProtocolVersion 61 -> 62 in lockstep
  (Go `protocol.go` + Rust `protocol/control.rs`), shape golden
  updated, `protocol_wire_v1.json` regenerated.
- Rust (`userspace-dp/src/nat64.rs`): `source_constrained` is the wire
  flag OR the non-empty-list derivation; wildcard tokens
  (`any`/`any6`/`any-ipv6`) normalise to unconstrained (defence in
  depth for hand-built/older snapshots); constrained + zero parseable
  prefixes still matches NOTHING.

## Tests (RED/GREEN)
- Go `pkg/dataplane/userspace/nat64_source_scope_15930_test.go`:
  poisoned DNS name (zero answers), name->empty set, unknown-member
  set, literal+poison (whole side closed, no surviving subset), valid
  named-source control, DNS-with-answers control, explicit
  `any`/`any6`/`any-ipv6`/`::/0` -> `[::/0]` match-any, omitted-selector
  control, `any4` never-match.
- Go `pkg/config/nat64_source_scope_15930_test.go`: strict admission of
  every wildcard spelling and of a dns-name backed
  `source-address-name`.
- Rust `nat64_tests.rs`: `nat64_15930_sentinel_and_flag_fail_closed`
  (sentinel and flag-only shapes -> NoPrefixMatch) and
  `nat64_15930_any_matches_any_source` (all wildcard spellings ->
  MatchReady, constrained control still refuses).

## Validation
- Commands in PR body. Unit/snapshot level only; no live cluster run.

## Risk
- Protocol bump 62 fences mixed-version helpers (exact-equality gate).
  An old (v61) helper receiving a new snapshot is refused by version;
  the sentinel encoding alone would already fail closed there, and the
  `::/0` lowering parses in every vintage. Unscoped rule-sets are
  byte-identical to before. No hot-path allocation added (config-time
  builder only; Rust matcher keeps its prefix loop).
