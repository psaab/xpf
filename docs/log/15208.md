# #15208 — configstore: epoch-bind a store-minted internal commit authority minted unheld (A19-02)

- **Timestamp**: 2026-10-19
  - **Action**: RED first. New cells in
    `pkg/configstore/commit_authority_15208_test.go` fail on
    `origin/master` (ca477c461b):
    - `TestA19InternalAuthorityMintedUnheldCannotPromoteLaterHolder15208`:
      an internal authority minted while nobody held the lock promoted a
      later holder's `y-partial` candidate (`commit err=<nil>`), want
      `ErrConfigHolderTurnover`.
    - `TestA19InternalAuthorityMintedUnownedCannotPromoteLaterHolder15208`:
      the same against an authority minted on an unowned internal
      candidate.
  - **Gate verdict (adversarial, implementor lens)**: The exact cited
    A19-02 line (`return InternalCommitterAs(principal)` for a named
    unheld session at `commit_authority.go:178-180`) is already
    remediated on current master by #14990 (merged 530d56a0e4, after the
    validator base 27b8cba22d): a named session that holds nothing is
    refused `ErrConfigLockedByOther`, and the named `!configDir` /
    empty-holder arms in the filed issue no longer mint. The surviving
    mechanism with the same spelling, path and harm is the explicit
    internal mint (`sessionID == ""`): `verifyCommitAuthorityLocked`
    accepted `authorityInternal` unconditionally, so an authority minted
    while the lock was unheld promoted whatever candidate a holder
    staged afterwards (e.g. during the apply-semaphore wait), journalled
    to the minting caller's principal. That is the leg fixed here;
    claiming the already-fixed named-session arm as this issue's RED
    would have been a false acceptance.
  - **Action**: Fix, scoped to the cited mechanism.
    - `AuthorizeCommitAs` (`pkg/configstore/commit_authority.go`): a
      `sessionID == ""` mint reached while unheld (`!configDir` or
      `effectiveHolderLocked() == ""`) now returns the new
      `authorityInternalEpochBound` kind, bound to the mint-time
      `holderEpoch`. It is still internal (`IsInternal`, no session,
      same journal principal).
    - `verifyCommitAuthorityLocked`: the epoch-bound kind refuses with
      `ErrConfigHolderTurnover` when `holderEpoch` has moved since the
      mint (any acquisition or release), and proceeds when it has not.
      It never returns `ErrCandidateGenerationConflict`, so the daemon's
      `commitWithGenBinding` retry cannot automate the substitution.
    - Unchanged by design: directly constructed
      `InternalCommitter()`/`InternalCommitterAs` authorities (HA sync,
      event engine, bootstrap `system:bootstrap`, shell
      `commitAndApplyOperator`) carry no mint-time lock state and stay
      unconditional; a store mint reached while a lock is held against an
      unowned candidate stays unconditional; holder-bound authorities,
      the zero-value refusal, and the #14990 named-session refusal are
      untouched.
    - `pkg/configstore/README.md`: documents the #15208 epoch-bound
      internal mint next to the #14990 paragraph.
  - **Action**: Controls in the new cells pin neighbouring behaviour:
    a no-turnover epoch-bound internal mint still promotes the internal
    candidate; a direct `InternalCommitter()` still promotes a held
    candidate; the live holder mints fresh and promotes its own work; a
    refused `CommitConfirmedGenAs` arms no rollback timer.
  - **File(s)**: `pkg/configstore/commit_authority.go`,
    `pkg/configstore/commit_authority_15208_test.go` (new),
    `pkg/configstore/README.md`, `docs/log/15208.md`
  - **Validation**: RED on `origin/master` as above; GREEN after the fix
    for `go test ./pkg/configstore/ -run '15208|14990|6808|5059|9632'`,
    `go test ./pkg/api/ ./pkg/grpcapi/ -run '6808|5059|5870|Commit|Holder'`
    green, and `go vet ./pkg/configstore/ ./pkg/api/ ./pkg/grpcapi/`
    clean. The full `pkg/configstore` suite exceeds the local 600s
    timeout on this shared box (slow cells such as
    `TestCommitConfirmedRefusesARecordTheNextBootWouldRefuse_9617` take
    ~89s alone and pass identically on unmodified `origin/master`
    62f548d08a); no failure was observed in the bounded commit/lock
    runs before the timeout.
  - **Risk**: An internal commit whose authority was store-minted while
    unheld and then delayed across a lock acquisition now fails with
    `ErrConfigHolderTurnover` instead of promoting the new holder's
    candidate; the operator re-issues the commit. No in-tree caller
    mints while unheld and promotes after a turnover (all promote inside
    one apply-semaphore transaction), so this is the intended
    fail-closed delta only.
  - **Decisive unresolved check**: none at store level. The daemon-level
    apply-semaphore interleaving was STATIC in the source report and
    remains unexecuted; the store-level epoch check is the gate it
    depends on and is now executed by the regression cells.
