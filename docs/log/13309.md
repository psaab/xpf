# Issue #13309: Expose SNMP serve-budget shedding

- Why: `snmpServeBudget.allow` counted refused SNMP requests only in a private atomic and silently displaced a source bucket at the 1024-source cap. Operators had no metrics for rate-limit shedding or source-table churn, hiding causes of NMS poll timeouts during request floods.
- What: Added thread-safe `Agent.ServeBudgetStats()` snapshots for shed requests, source-bucket evictions, and active source buckets; count each capacity eviction; expose the values through `xpf_snmp_requests_shed_total`, `xpf_snmp_source_bucket_evictions_total`, and `xpf_snmp_tracked_sources`. The daemon wires a live Agent snapshot into the API collector, whose series remain available with an unloaded dataplane. Added package-level regressions for budget admission, eviction, public stats, and Prometheus exposition.
- Validation: The SNMP regression was RED on pristine `origin/master` (compile failed because `Agent.ServeBudgetStats` was undefined), then passed after the fix. `go test ./pkg/snmp/ -count=1` and `go test ./pkg/api/ -count=1` passed; `go build ./...`, `go vet ./pkg/snmp/`, the daemon API-hook binding test, `gofmt -l` on changed Go files, and `git diff --check` passed.
- Risk: Source bucket eviction is now observable but still intentionally displaces a randomized incumbent at table capacity; rate-limit behavior is unchanged. Metrics omit series when no SNMP agent is wired.
