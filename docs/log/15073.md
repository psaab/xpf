# #15073 — Re-dial flow-export collectors after source renumbering (A46-01)

## Summary

Flow-export collector sockets were dialed once at exporter build and
never re-dialed. After the implicit (OS-selected) source address was
renumbered — a DHCP lease change or SLAAC/DHCPv6 renumbering on the
egress interface — IPv4 export failed permanently
(`EADDRNOTAVAIL`-class write errors on the stale socket) and IPv6
export kept silently sending from the removed address while every
health surface read healthy, until a daemon restart or an unrelated
flow-export config change rebuilt the exporters.

- Issue: psaab/xpf#15073 (A46-01, 3-way MATERIAL in
  `research-work.AdQvt1jMKw`). Base: `origin/master` at lane creation.

## Defect (present at base)

- `pkg/flowexport/transport.go`: `dialCollectors` dialed each collector
  once and stored the `net.Conn`; `writeAll` only marked a failed
  collector unhealthy, armed the 30 s probe backoff, and retried the
  SAME conn forever. Nothing compared the socket's `LocalAddr()`
  against the live assigned addresses.
- The only `dialCollectors` callers were the exporter constructors
  (`netflow.go` `NewExporter`, `ipfix.go` `NewIPFIXExporter`), and
  `pkg/daemon/daemon_flowexport.go` hash-gates rebuilds on config
  change, so an unrelated commit never rebuilt a healthy exporter. The
  #9166 retry is armed only by a build failure.

## Fix

`pkg/flowexport/transport.go` only (shared by the NetFlow v9 and IPFIX
exporters, so both families and both protocols are covered):

- Extract the per-collector dial into `dialCollector(CollectorConfig)`
  (bounded by the existing `collectorDialTimeout`; source-bound
  collectors keep the resolved source+destination path, no-source
  collectors keep `DialContext` candidate fallback). `dialCollectors`
  and the new recovery path share it, so a re-dial re-resolves the
  destination and re-picks the live implicit source exactly as a fresh
  build would. `collectorConn` now records `dialedAt` per (re)dial.
- Write-failure leg (IPv4): a write failure on a proven-healthy socket
  whose `LocalAddr()` IP is no longer assigned re-dials once and
  retries THIS packet on the fresh socket before parking; the old
  socket is closed only after the new write succeeds. A failure with
  the source still assigned keeps the pre-existing behaviour exactly
  (unhealthy + backoff, no churn) — pinned by the StillAssigned control.
- Stale-source canary (IPv6): before the write fan-out, a healthy
  collector whose source is no longer assigned is re-dialed so the
  packet leaves from the live source; a failed re-dial parks it
  unhealthy with the dial error recorded (never writes from the
  removed address). `health()` reports such a collector unhealthy with
  a not-assigned reason even while its writes still succeed, via the
  `localAddrsFn` seam (`net.InterfaceAddrs` in production;
  enumeration/parse failures conservatively report assigned so no
  collector churns on missing data). A `staleSourceGrace` quiet window
  after a redial failure suppresses canary re-dial spin; the socket
  also stays behind the existing `unhealthyProbeInterval` backoff.
- Concurrency: `collectorConn.conn` moved under the existing mutex
  (now `sync.RWMutex`) so `health()`/`close()` never race a swap; the
  write path holds no collector lock across dial/write. Fake conns
  with a nil embedded `net.Conn` cannot panic the staleness check
  (`localAddrOf` recovers).

NOT changed: `pkg/daemon/daemon_flowexport.go` (no daemon rebuild is
needed — recovery is inside the transport the exporters already own),
the backoff/write-timeout semantics (#4423), the health surfaces'
shape, and source-bound collectors' configured bind (a re-dial
re-resolves the same pinned source; if the pinned source itself is
gone the dial fails and the collector parks unhealthy, which is the
correct fail-visible outcome for an explicitly configured source).

## Regression (RED → GREEN)

`pkg/flowexport/collector_redial_15073_test.go` (new):

- `TestCollectorRedial_WriteFailureRedials15073` — S1 assigned at dial,
  renumbered to S2; the next write fails `EADDRNOTAVAIL`-class;
  `writeAll` re-dials (dial count 1→2), closes the old socket, delivers
  THIS packet from S2, and stays churn-free afterwards.
- `TestCollectorRedial_StaleSourceHealth15073` — IPv6 socket whose
  source is no longer assigned but whose writes still succeed:
  `health()` reports unhealthy with a reason (RED on base: healthy),
  and the next `writeAll` re-dials onto S2 and sends from it.
- `TestCollectorRedial_StillAssignedNoChurn15073` — adjacent control:
  source still assigned → no canary churn, no re-dial after an ordinary
  refused write, identical unhealthy+backoff behaviour as base.
- `TestCollectorRedial_RedialFailureParksUnhealthy15073` — re-dial
  failure parks the collector unhealthy with the dial error, no dial
  spin inside backoff, later probe recovers.
- `TestCollectorRedial_SourceBoundCollector15073` — real loopback
  source-bound collector still dials/writes/reports its pinned source.

RED evidence: with the production change stashed the test file does
not compile (`localAddrsFn`/`staleSourceGrace` undefined — the seams
are part of the fix); the two surviving legs assert the exact
mechanism (no re-dial, healthy-stale) that base violates.

## Risk

- A collector whose implicit source flaps between assigned/unassigned
  could be re-dialed at most once per flush after the grace window;
  the backoff bounds the failure case and a successful re-dial is
  churn-free. Collectors on hosts where `net.InterfaceAddrs`
  enumeration fails are conservatively treated as assigned (no
  behaviour change).
- Live verification (real netns renumbering probe writing from S2 on
  the next cycle for both families) was not run in this lane; the
  unit-level fakes model the exact kernel contract (LocalAddr vs
  assigned set, EADDRNOTAVAIL-class write failure).
