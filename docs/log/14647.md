# #14647 — CI affected-Go-test selector seeds nothing from non-Go paths; memlockcensus red on master

## Defect

`scripts/ci_affected_go_tests.sh` seeded only from the owning or nearest
Go package of each changed path, closed over reverse imports only, and
silently exited 0 ("No changed Go source package") for every other path.
Go tests read the tree by path — Rust sources, docs, manifests — and the
tree-census packages (`pkg/docsref`, `pkg/durationaudit`,
`pkg/memlockcensus`, `pkg/refactoraudit`, `pkg/showaudit`) scan the whole
repository while no scanned package imports them, so neither mechanism
could ever select them on the change shapes that break them.

Measured on master (`eab46c10a`):

- `--list 7ade1a12a3^ 7ade1a12a3` (33 Rust files) printed "No changed Go
  source package; skipping", rc=0, although Go tests read
  `userspace-dp` sources by path.
- `--list aaf85dbda6^ aaf85dbda6` selected 50 packages including
  `pkg/dataplane/userspace` but not `pkg/memlockcensus`.
- aaf85dbda6 deleted `rlimit.RemoveMemlock()` from
  `newIngressManager` in
  `pkg/dataplane/userspace/maps_sync_ingress_partial_6537_test.go`,
  leaving registry row `maps_sync_ingress_partial_6537_test.go ->
  newIngressManager` dead. `go test ./pkg/memlockcensus/ -run
  '^TestMemlockCensusMatchesTheTree$' -count=1` failed with "1 registry
  row(s) name a guard that no longer exists … newIngressManager". The
  introducing PR's CI never selected the census, so master stayed red.

## Fix

- `scripts/ci_affected_go_tests.sh`: a changed path owned by no Go
  package and not on the explicit never-read allowlist now seeds every
  package (the old all-package fallback, never nothing). The allowlist
  covers only paths no Go test reads: `_Log.md`, `docs/log/`,
  `docs/issues/*-history*.md` / `*-history-archive.md` (which
  `pkg/docsref` deliberately excludes as historical archives), and the
  two non-test workflows. The five census packages are always appended;
  a listed census package that no longer exists fails the selector
  closed instead of silently becoming a no-op.
- `pkg/memlockcensus/registry.go`: deleted the dead
  `newIngressManager` row.
- `scripts/ci_affected_go_tests_selftest.sh` (+ registration in
  `scripts/run-selftests.sh`): hermetic selector self-test.
- `docs/ci-gate-contract.md`: the Go row and scope note now state the
  fallback and always-run census behaviour.

## Validation

- RED (original selector restored from `origin/master`): self-test
  5 passed / 9 failed — Rust-only selects neither
  `pkg/dataplane/userspace` nor any census package, aaf85 range misses
  `pkg/memlockcensus`, docs/log-only selects nothing, census-sync finds
  no census block.
- GREEN (fix): self-test 14 passed / 0 failed, including
  `--list 7ade1a12a3^ 7ade1a12a3` selecting
  `pkg/dataplane/userspace`, `--list aaf85dbda6^ aaf85dbda6` selecting
  `pkg/memlockcensus`, a synthetic Go-only commit appending all five
  census packages, a synthetic docs/log-only commit selecting exactly
  the census packages plus `structaudit` (reverse dependent of
  `refactoraudit`), and census-sync deriving the same five packages
  from the live tree.
- `go test ./pkg/memlockcensus/ -run '^TestMemlockCensusMatchesTheTree$'
  -count=1`: FAIL on master (dead row), ok after the fix.
- `sh scripts/selftest-census.sh`: OK (new self-test is registered).

## Risk

CI is non-blocking, so the cost is CI time: non-Go changes that are not
allowlisted now run the full Go selection instead of none. That is the
documented safe fallback; narrowing it requires proving a path is read
by no Go test and adding it to the allowlist in review.
