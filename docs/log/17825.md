# #17825 — Skip rescue deletion superseded by a newer save

- **Timestamp**: 2026-10-28
  - **Action**: `DeleteRescueConfig` claims a generation under `s.mu` before taking `rescueMu`. A newer save can claim and durably apply its later generation during that gap; the old delete previously proceeded to unlink the newer `rescue.conf`. The delete now compares its generation with `rescueAppliedGen` while holding `rescueMu`. If a newer rescue operation has already applied, it leaves the file intact and returns `ErrRescueDeleteSuperseded`, so callers do not report a deletion that did not happen. The generation claim, `rescueMu`-protected unlink and directory fsync, and the #14722 in-flight-save behavior remain intact. Added `TestDeleteRescueConfigSkipsNewerSave_17825` with a barrier after the delete claims its generation and before it takes `rescueMu`. The gRPC system action maps this expected supersession to `FailedPrecondition`, not `Internal`.
