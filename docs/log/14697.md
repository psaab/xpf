# #14697 — Policy-rename rematch and rollback reauthorization evaluate ICMP sessions with ICMPType nil

- **Timestamp**: 2026-10-17
- **Action**: Read issue D12-03 (MATERIAL, both re-review passes).
  Verified on `origin/master` `75a10ddc15`:
  `rematchRenamedV4/V6/Match` (`pkg/daemon/daemon_policy_rename.go:527-691`)
  and `reauthorizePolicyCandidates.isPermitted`
  (`pkg/daemon/daemon_policy_invalidate_capture.go:1198-1281`) build
  `policymatch.Query` from the 5-tuple only; session keys/tuples store
  the ICMP echo identifier in the port fields and carry no type/code.
  `matchSingleApp` (`pkg/policymatch/policymatch.go:2857-2880`) returns
  false for any app with `ICMPType != nil` when the query type is nil,
  so an earlier `deny junos-icmp-ping` (type 8) / `junos-icmp6-echoreq`
  (type 128) is skipped in first-match order and a broader
  `permit junos-icmp-all` / `any` keeps the session. GRE already fails
  closed via `capturedTunnelDiscriminatorValid` (protocol 47, zero
  discriminator) at the three rename entry points, but
  `reauthorizePolicyCandidates` never called that guard at all.
  Predefined apps verified: `junos-icmp-ping` = type 8,
  `junos-icmp6-echoreq` = type 128, `junos-icmp-all`/`junos-icmp6-all`
  unconstrained, `junos-gre` = GRE.
  Fix scope decided: extend the existing guard (renamed
  `capturedTupleValid`) to reject protocols 1/58 unconditionally —
  the session tuple can never prove the type, and even an
  unconstrained-only permit set cannot prove a deny does not apply to
  the unknown type (GRE-parity, report's primary diff). The alternative
  (fail closed only when the evaluated config references an
  icmp-type/code constraint) was rejected: `permittedRenameResult`
  evaluates the whole zone-pair + global + default set, so proving
  "no constraint anywhere" needs a new config-wide scan, and the
  conditional form would still discharge an ICMP candidate in
  `reauthorizePolicyCandidates` whenever the restored set lacks a
  constraint — weaker than the GRE contract the report cites as the
  understood pattern. Also add the missing guard call in
  `reauthorizePolicyCandidates.isPermitted` (covers GRE0 + ICMP there).
  NOT changed: `policymatch` itself (nil-type fail-closed per term is
  correct dataplane parity), session wire formats (no type/code field
  exists to populate), non-ICMP/GRE protocols.
