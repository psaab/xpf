# #15122 — multi-RG cluster-synced guard mis-judges all-primary nodes

- **Timestamp**: 2026-10-19
- **Action**: The #14357 guard in `pkg/cluster/sync_zone_rg.go` returned
  `false` for every unattributable `SessFlagClusterSynced` row whose ingress
  zone maps to more than one RG, regardless of which RGs this node is primary
  for. A node that took over EVERY RG of a multi-RG zone holds inherited,
  not-yet-hit peer-synced rows (`ScrubNodeLocal` zeroed their ingress
  identity, and the fold is not in the map ABI, so `resolveSessionRG`
  fails). Judging them not-owned let the next peer `BulkEnd`
  (`zoneOwnershipSnapshot.shouldSyncV4/V6` → `ReconcileClusterBulk`)
  delete those live survivor sessions when the rejoining peer's bulk did not
  contain them, and stopped the sweep re-exporting them. Fix: return `false`
  only when this node's primary answers across the zone's RG set are mixed.
  New shared helper `ambiguousClusterSyncedZone(rgs, ok, isPrimaryForRG)`
  (primary-for-all and primary-for-none are both unambiguous under the zone
  answer) is used by the live predicates `ShouldSyncSessionV4/V6` and,
  via `zoneOwnershipSnapshot.ambiguousZone` over the bulk-start `primary`
  map, by the snapshot predicates `shouldSyncV4/V6`. Local unattributable
  rows, single-RG/unmapped zones, and attributable (fold-present) rows are
  unchanged; the #14357 mixed-primary (RG1-only) case still returns `false`.
