# #16750 — flowexport tracker: saturation + per-field monotonic Touch

- **Timestamp**: 2026-10-25
  - **Action**: `deltaRecord` subtracted cumulative counters from the
    last-export baselines with plain unsigned arithmetic, and
    `Touch`/`TouchBidirectional` overwrote the stored cumulative record
    per field with whatever the latest snapshot carried. A snapshot that
    races backwards (helper restart, mirror-row alternation between
    workers once R3-A46-08/#16760 makes the live feed actually hit)
    could therefore drive a stored field below its baseline and the
    next interim/final would emit a ~2^64 wrap, poisoning collector
    top-talker/billing aggregates; the close path already saturated via
    `satSub` for exactly this reason. Made `Touch`/`TouchBidirectional`
    keep the per-field maximum, made the bidirectional activity test
    per-field progress (the old forward+reverse sum could stay flat
    while one field genuinely advanced), and switched `deltaRecord` to
    `satSub` on all four fields. Tests:
    `pkg/flowexport/backward_counters_16750_test.go` — acceptance probe
    (second interim 0 forward / 900 reverse, never past lifetime),
    per-field max for both Touch variants, direct `deltaRecord`
    saturation with an above-baseline control, and per-field activity /
    backward-does-not-revive.

    `pkg/flowexport/backward_counters_16750_test.go`,
