# Issue #15692: `force-discover` compiled/propagated/fingerprinted but never consulted by the DHCPv4 client runtime

- **Timestamp**: 2026-10-19
- **Problem**: `interfaces <if> unit <n> family inet dhcp force-discover` flowed through `pkg/config/schema_interfaces.go` / `compiler_interfaces.go`, `daemon_dhcp.go` (`SetDHCPv4Options`), `DHCPv4Options.ForceDiscover` and the `fingerprintV4` reconcile fingerprint, but `runDHCPv4` never read it. Toggling the flag restarted the client (fingerprint change) yet T1 still sent a unicast RENEWING `DHCPREQUEST` and T2 a broadcast REBINDING `DHCPREQUEST` — the promised DISCOVER behaviour never happened.
- **Fix**: In `runDHCPv4` (`pkg/dhcp/dhcpv4.go`), capture `forceDiscover := opts != nil && opts.ForceDiscover` once at goroutine start (parallel to `baseBackoff`/`maxAttempts`; toggling restarts the goroutine via the existing fingerprint). When set, the T1 and T2 steps call `m.v4Exchange(..., exchangeAcquire, committed)` — a full DISCOVER→OFFER→REQUEST→ACK DORA — instead of `exchangeRenew`/`exchangeRebind`. All surrounding machinery is deliberately unchanged: waits still use T1/T2 timers bounded by `leaseCtx` (Obtained+LeaseTime), a failed DISCOVER at T1 still waits for T2, a failed DISCOVER at T2 still falls through to re-acquisition with `leaseExpiryPending`, and the held lease stays installed until a DISCOVER replaces it or the absolute expiry (proven by `TestRunDHCPv4ForceDiscoverKeepsLeaseUntilExpiry15692`). The `errDHCPNAK` branches are gated `!forceDiscover`: a DORA never surfaces `errDHCPNAK` (NAKs are handled inside `nclient4.Request`), and the guard states that contract explicitly. The `ForceDiscover` field comment in `pkg/dhcp/dhcp.go` now describes the actual semantics.
- **Not changed**: Default (no `force-discover`) renew/rebind behaviour (#2994, #3956, #14600) is byte-for-byte the same exchange sequence; DHCPv6 is untouched (no such option); fingerprint/config/compiler plumbing needed no change.

## RED -> GREEN proof

- **RED** (pre-fix, regression tests present, base `9e04c0d989`): `go test ./pkg/dhcp/ -run 'TestRunDHCPv4ForceDiscover' -count=1` failed — `TestRunDHCPv4ForceDiscover15692/force-discover_uses_DISCOVER_at_T1_and_T2`: `exchange 1 mode = renew, want acquire`, `exchange 2 mode = rebind, want acquire` (all=`[acquire renew rebind acquire]`); `TestRunDHCPv4ForceDiscoverKeepsLeaseUntilExpiry15692`: `force-discover renewal modes = [acquire renew acquire], want second exchange acquire`.
- **GREEN**: same command passes after the fix; the default subtest (`acquire, renew, rebind, acquire`) and neighbouring `TestRunDHCPv4RenewUsesRenewNotDiscover` / `TestRunDHCPv4RenewingNAKRestartsDiscover` / `TestRunDHCPv4RebindingNAKRestartsDiscover` pass; full `go test ./pkg/dhcp/ -count=1` passes.
