# #17262 — Reuse the source NAT pool membership helper

## Why

`SourceNATPoolMembers` is the shared definition of a source pool's members (singular `Address`, then repeated `Addresses`). Several strict validators and address consumers still rebuilt that list independently, so their pool view could diverge. The DNAT `pool.Address` check in `compiler_nat_destination.go` is a separate merge-field meaning and remains untouched.

## What

- Routed `SourceNATPoolNets`, strict source-pool grammar/scope/family checks, the NAT64 host-mask gate, NAT64 build eligibility, overlap-owner expansion, and deterministic IPv4 expansion through `SourceNATPoolMembers`.
- Removed the duplicate `poolMemberTexts` helper. Kept `SourceNATPoolMembers` itself unchanged and left the DNAT merge condition at `compiler_nat_destination.go:167` unchanged.
- Added `TestNAT64BuildDecisionIncludesSingularPoolMember17262`, pinning that a singular-only non-host pool address prevents a NAT64 rule-set from being considered built.

## Validation

- PASS: the non-test `pool.Address != ""` search has exactly two matches: the unchanged source helper body and the unchanged DNAT merge condition. `poolMemberTexts` has no matches in `pkg/config` or `pkg/nat`.

## Risk
