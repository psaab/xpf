# 9925 — Fabric bond rows need an AF_XDP ingress target

## The defect

A fabric interface configured with members but without a local fabric member is a valid unresolved bond shape. The existing bond application path still creates the bond master, but there is no fabric snapshot for this shape. The userspace ingress builders nevertheless treated every `fab*` row as excluded, so the bond master and its tagged child could not become an AF_XDP bind target. The result was a configured fabric bond with no ingress path.

The affected shape is distinct from a fabric interface whose local member is known. A fabric with a local member continues to bind its physical member through the existing fabric snapshot path; this change is only for the unresolved bond-master shape.

## The fix

- Go marks base and unit interface rows as `FabricBond` when the configured fabric has members and no local fabric member, including clusterless and node-1 configurations.
- Go and Rust narrow the `fab*` binding exclusion to admit only flagged unresolved fabric-bond rows. Plain fabric rows and fabric rows with a local member remain excluded from this binding path.
- Existing VLAN-parent aliasing and the binding allowlist now expose the bond master as the target for the unresolved shape; no fabric snapshot is synthesized.
- The wire field is `fabric_bond`; false values are omitted on the Go side and default/skip on the Rust side. Both protocol constants move from v24 to v25, with `MinProtocolFabricBond=25` and the existing fail-closed required-feature sentinel gate.
- Contract, parity, protocol-floor, snapshot-shape, and fixture guards cover the wire and topology decisions.
