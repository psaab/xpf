# #13296 — Preserve event-stream counters across helper restarts

## Summary

- **Issue:** Research finding D5-02: `Manager` owned daemon-side `EventStream`
  counters only through the per-helper `EventStream` instance. Both explicit
  stop and unexpected helper exit closed and discarded that instance; the next
  helper started counters from zero. In addition, the metrics collector treated
  a helper-status error as no status at all, so the event-stream metric family
  disappeared during the actual helper-down scrape.
- **Change:** Add a manager-owned cumulative base for all monotonic
  `EventStreamStatus` counters. Fold the active stream into that base whenever
  its listener is retired, including spawn failure, intentional stop, and
  unexpected exit. Status assembly always publishes the cumulative status.
  Expose that daemon-owned snapshot independently of helper status, and have
  Prometheus scrape the event-stream counters on the helper-status-error path
  without emitting stale/helper-owned producer metrics. `Paused` and
  `EventsSinceAck` remain current-incarnation values.
- **Regression coverage:**
  `TestEventStreamCountersSurviveHelperRestart13296` checks cumulative counts
  and idempotent teardown at the manager boundary.
  `TestEventStreamCountersScrapeWhileHelperDown13296` drives the real collector
  with `Status()` failing, proves event-stream series still emit, and proves
  helper producer metrics do not emit from unavailable status.
