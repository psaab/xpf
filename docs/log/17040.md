# #17040 — parameterize fabric slot populate/refresh by slot (R4-Q32-01)

- **Timestamp**: 2026-10-27
- **STEP-0**: Verified live on origin/master `a60e77bda3`. `pkg/daemon/daemon_ha_fabric.go` still held hand-mirrored `populateFabricFwd`/`populateFabricFwd1`, `refreshFabricFwd`/`refreshFabricFwd1` wrappers over `refreshFabricPeer`, `clearFabricFwd0`/`clearFabricFwd1`, two pasted arms in `RefreshFabricFwd`, and `pkg/daemon/daemon.go` held eight parallel field pairs (`fabricIface/1`, `fabricOverlay/1`, `fabricPeerIP/1`, `fabricPopulated/fabric1Populated`, `fabricPeerMAC/1`, `fabricRefreshCh/1`, `lastFabricProbe/1`, `lastFabricLog0/1`). Not fixed, not duplicate — proceeded.
- **Action**: Collapsed the slots into `type fabricSlot struct { name, iface, overlay string; peerIP net.IP; populated bool; peerMAC net.HardwareAddr; refreshCh chan struct{}; lastProbe, lastLog time.Time }` and `Daemon.fabricSlots [2]fabricSlot`. Deleted `populateFabricFwd`/`populateFabricFwd1` → `populateFabricFwdSlot(ctx, slot, …)`, `refreshFabricFwd`/`refreshFabricFwd1`/`refreshFabricPeer` → `refreshFabricFwdSlot(ctx, slot, …)`, `clearFabricPeer`/`clearFabricFwd0`/`clearFabricFwd1` → `clearFabricFwdSlot(ctx, slot)`. `RefreshFabricFwd`, the netlink fabric monitor, and `triggerFabricRefresh` now loop over the slots; the `slot int` helpers (`logFabricRefreshFailure`, `fabricEntryPopulated`, `fabricPeerMACHint`, `rememberFabricPeerMAC`, `retainFabricFwdOnNeighborMiss`) index the array instead of re-branching `if slot == 1`. Log text is built from the stored per-slot label via `fabricSlotLabel` (`fabric`/`fabric1`) so every operator string is preserved byte-for-byte. `snapshotFabricRefreshChans`/`publishFabricRefreshChansIfCurrent` now carry `[2]chan struct{}` slot-indexed; `startFabricForwardingLoops` takes the array and launches `populateFabricFwdSlot` for slot 0/1. Migrated every reader of the old pairs: takeover readiness (`daemon_ha.go`), `fabricPeerAddrs` (`daemon_ha_comms_wiring.go`), fabric probe targets (`daemon_neighbor_listener.go`), and `stopClusterComms`. The slot label is stored in the per-slot `name` field (`fabric`/`fabric1`) and seeded in `New()`; bare `&Daemon{}` literals (test-only, never production construction) leave the names unseeded and therefore yield empty labels.
- **Wire/state behaviour preserved**: No dataplane, RPC, config, or persistence change. `refreshCh` remains guarded by `clusterCommsMu` exactly as the former `fabricRefreshCh`/`fabricRefreshCh1` fields were (#4958) — it is the one `fabricSlot` field not under `fabricMu`, documented on the struct and on `Daemon.fabricSlots`; populate loops still receive their channel by value at launch, and `RefreshFabricFwd`/the neighbor listener copy only fabricMu-guarded fields so no new cross-lock read exists. Existing `fabricMu` critical sections are unchanged in scope (same lock, indexed field instead of named field). Resolver slot argument (`ResolveFabricPeer(slot, …)`) unchanged.
