# Issue #14986 — cli: stop global InConfigMode and empty-session dispatch escalating read-only CLI users to PermConfig (D37-01)

- **Timestamp**: 2026-10-18
  - **Action**: Implemented fix on `fix/14986-campaign` (base `origin/master` 5b3b02a61f). `dispatch()` in `pkg/cli/cli_dispatch.go` no longer routes to `dispatchConfig` on the store-global `InConfigMode()` alone: a CLI session must itself have passed the gated `configure` verb (new `configOwned` flag, holder `local-cli` via `EnterConfigureSession`/`EnterConfigureExclusive(localConfigSessionID)`), otherwise config-mode mutation verbs are priced at `PermConfig` via `checkPermission(["configure"])` (new `checkConfigModePerm`, also enforced inside `dispatchConfig` and `handleCommit`), view affordances (`show`/`?`/`help`/`exit`/`quit`) stay available, and a candidate held by another session (incl. `configure exclusive`) refuses mutation/commit instead of being written through the empty-session (`sessionID == ""`) store bypass. Session-scoped mutators in `cli_dispatch.go`/`cli_config.go` now pass `local-cli` when this CLI owns the lock (`cliConfigSessionID()`), `ConfirmCommit` uses `ConfirmCommitAs`, and config-mode `exit` only releases a lock this session owns. Neighbouring behaviour preserved: unset class (legacy no-RBAC) untouched, regex gates (#7172/#9892/#14707) unchanged and still run after the coarse gate, own `configure exclusive` end-to-end works.
