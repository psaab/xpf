# #10120 — dist re-sign content-swap refusal

Worktree `fix/10120-resign`, based on `origin/master`.

- **Timestamp**: 2026-09-18
- **Context**: Read the full open #10120 body (no comments), closed #9920, and merged PR #10119. The #9920 gate binds the bake file set and sidecar flags but intentionally left the residual live-byte drift gap tracked here.
- **Mechanism**: `sign.assert_bake_set()` now parses an existing `xpf-<ver>.SHA256SUMS`, hashes every requested bake file, and refuses before any write when a live digest differs from the recorded digest. The error names the mismatched basename without exposing digest values. The initial sign remains allowed when no recorded checksum manifest exists.
- **Atomic re-sign**: The checked digest map is returned to `_main` and passed through `write_and_sign_manifest()`/`write_manifest()`, so a strict re-sign signs the already-checked recorded hashes instead of re-reading live artifact bytes a second time. A content swap after the check therefore yields a signature over the old recorded manifest, which downstream verification rejects, rather than a fresh signature over swapped bytes.
- **Tests**: Added #10120 cells to `scripts/dist/test_dist_resign_9920.py` for qcow2-byte tamper, metadata-byte tamper, sidecar non-flag-byte tamper, honest re-sign, and exactly-once artifact hashing. Existing validated/base-pinned/guest-kernel refusal cells remain unchanged and green.
- **Self-test adaptation**: `scripts/dist/selftest.sh` now explicitly proves repaired-but-drifted sidecar re-sign refusal, then signs a fresh manifest for the positive control. Inventory-negative fixtures use the low-level signing primitive after deliberate byte mutation, preserving their intended publish-gate coverage without bypassing the new strict re-sign refusal.
