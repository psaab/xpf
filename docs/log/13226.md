# Issue #13226: Remove the unwired cluster RETH controller

## Why

`pkg/cluster/reth.go` retained `RethController` and its `RethMapping` hierarchy despite zero production callers. The orphaned controller's state-change path ignored `LinkSetUp` errors, and the README incorrectly described it as participating in live RETH status displays. Actual MAC programming and VIP ownership are implemented in `pkg/daemon` and `pkg/vrrp`.

## What

Removed the unused controller, netlink operations, `IsVirtualRethMAC`, and controller-only tests while preserving deterministic RETH MAC and stable link-local helpers. Corrected the cluster README, link-state source comment, phase summary, and RETH MAC implementation table. Added an AST regression test requiring the dead declarations to remain absent and live identity helpers to remain present.

## Validation

- Regression RED on pristine `origin/master` (`go test ./pkg/cluster/ -run TestRethDeadCodeRemoved13226 -count=1 -v`): failed with errors naming `RethMapping`, `RethController`, `NewRethController`, `IsVirtualRethMAC`, and dead controller methods.
- Regression GREEN after removal: passed.
- Full `go test ./pkg/cluster/`: passed.
- `go vet ./pkg/cluster/`: passed.
- `gofmt -l pkg/cluster/reth.go pkg/cluster/reth_test.go pkg/cluster/reth_13226_test.go pkg/cluster/monitor.go`: no output.

## Risk

No production behavior changes: the removed controller had no production callers. RETH MAC generation, stable link-local addresses, daemon MAC programming, and VIP ownership remain unchanged.
