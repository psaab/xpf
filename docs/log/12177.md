# #12177 — refuse envelope-incompatible cuts without wedging rollback

- **Issue**: #12177 — envelope-gate refusal leaves an in-flight journal; pre-STOP recheck demotes the committed predecessor.
- **Branch**: `fix/12177-cutover-journal`
- **Worktree**: `/var/worktrees/12177-cutover-journal`
- **Base**: `1c384b9a47ff7d6e567fa50632faa75c3995ae87`

## Why

A fresh cut persisted `STAGED` before the PREFLIGHT config-envelope reader gate. When a staged downgrade could not read the live DB, the refusal left an in-flight journal; reruns refused again and both explicit and default operator rollback refused that journal. Separately, copying a staged target that reused the live version's committed predecessor tag could demote its commit stamp before the final pre-STOP envelope recheck, excluding that known-good predecessor from default rollback selection when the DB reader floor rose.

## What

- Check the staged binary's envelope compatibility at INIT before persisting `STAGED`; clear stale journals on refusal, including resumed PREFLIGHT envelope refusals.
- Preserve a committed predecessor's stamp while same-tag staged bytes are copied and verified. Demote it only after the pre-STOP envelope check passes.
- Add hermetic regressions for fresh and stale-journal refusals, explicit/default compatible rollback, and a min-reader-rise pre-STOP refusal that retains the predecessor as the default rollback candidate.
