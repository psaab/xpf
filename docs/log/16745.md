# #16745 — Comms restart (Stop+Start) drops the peer-liveness seed (R3-A22-01, #9722 residual)

## Defect

#9722 seeded only `RestartHeartbeat`. The production comms-restart path —
`reconcileClusterTransportBinding` → `stopClusterComms` → `StopHeartbeat` →
next epoch `startClusterComms` → `StartHeartbeat` — passed `restartSeed 0`,
so the replacement receiver was a cold start even though the Manager had
`peerEverSeen && peerAlive`:

- Peer silent from the restart onward: new `lastSeen` stayed 0, every tick
  took the never-seen arm, and `handlePeerNeverSeen` returned on
  `peerEverSeen`. The only `peerAlive=false` writers are downstream of
  `handlePeerTimeout`, so the dead peer's RGs were never taken over until
  the peer returned or xpfd restarted.
- Peer heard once then lost: `seenThenLostGrace()` was the 30s cold-boot
  grace, so takeover was up to 30s late.

## Fix

`pkg/cluster` only:

- `Manager.hbCommsRestartSeed`/`hbCommsRestartHold` (guarded by `mu`):
  the deliberate `StopHeartbeat` stashes the outgoing receiver's
  `lastSeen` and grace end (`startedAt + seenThenLostGrace()`) only when
  that receiver had seen the peer; a never-seen receiver clears any older
  stash. The internal `stopHeartbeat` paths (idempotent start teardown,
  `RestartHeartbeat`) do not touch the stash — `RestartHeartbeat` carries
  its own seed as before.
- `StartHeartbeat` seeds from the stash when `peerEverSeen && peerAlive`
  and otherwise passes 0 (exact pre-fix cold start). A published start
  consumes/clears the stash under the publish lock, as it already clears
  the #9751 restart debt. A fresh Manager (daemon restart) has no stash,
  so #4386/#11566 cold-boot cells are unchanged.
- Defense in depth in `handlePeerNeverSeen`: when the Manager has
  `peerEverSeen && peerAlive`, route through `handlePeerTimeout` (which
  keeps its sync-recency/transfer-commit guards, freshness re-check,
  fencing and election) instead of returning. Cold boots
  (`!peerEverSeen`) keep the absence-confirmation path byte-identical.

## Regression tests

`pkg/cluster/heartbeat_comms_restart_16745_test.go` (new), driving the real
`StartHeartbeat`/`StopHeartbeat` loopback sockets plus direct
`checkTimeout` with backdated `startedAt`:

- `TestVA22CommsRestartSilentPeer16745` — acceptance DEFECT row: peer seen,
  Stop+Start, silent thereafter → replacement carries the seed and the 5s
  restart grace, and past grace+timeout `peerAlive=false`,
  `localPrimary(RG1)=true`. CONTROL row: peer heard again after the
  restart stays alive.
- `TestCommsRestartHeardOnceThenLostUsesRestartGrace16745` — heard once
  after the restart then silent: declared lost past 5.5s, not held 30s.
- `TestCommsRestartColdBootUnchanged16745` — fresh Manager cold start and
  start-after-never-seen-stop stay unarmed (`seenGrace==0`, `lastSeen==0`);
  never-seen past grace still confirms absent without `peerEverSeen`.
- `TestNeverSeenArmRoutesSeenAlivePeerToTimeout16745` — an unseeded
  receiver on a seen-and-alive Manager promotes via peer timeout and does
  not record cold-boot confirmed-absence.

Mutant checks: reverting the `StartHeartbeat` stash seeding (seed 0) or
the `StopHeartbeat` stash makes the DEFECT row fail (`lastSeen`/grace and
`peerAlive` assertions); reverting the `handlePeerNeverSeen` routing makes
the defense cell fail.
