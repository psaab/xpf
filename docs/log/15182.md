# #15182 (C03-01): bulk epoch counter restarts at 1 on daemon restart, so a surviving peer refuses the restarted peer's re-prime

- **Timestamp**: 2026-10-19
  - **Action**: Seeded `bulkSendNext` from the `MonotonicNanos()` base in `initGenState`, like the other within-boot counters. Added RED/GREEN regression covering the sender seed, the end-to-end between-bulks acceptance, and the #8966/#9174/#2198 controls.
  - **File(s)**: `pkg/cluster/sync.go` (`initGenState`), `pkg/cluster/sync_bulk_epoch_restart_15182_test.go` (new), `docs/log/15182.md` (this file)

## Mechanism (origin/master `5fb52e42cf`)

- Sender: `sync_bulk.go:346` draws each bulk epoch from `s.bulkSendNext.Add(1)`. `bulkSendNext` (`sync.go`, `atomic.Uint64`) was never seeded — `initGenState` seeds `genCounter`, `configGenCounter` and `syncEpoch` from `MonotonicNanos()` but left `bulkSendNext` at zero, so every daemon process re-emitted epoch 1 first.
- Receiver: `bulkStartStaleLocked` (`sync_bulk.go`) refuses a not-newer BulkStart between bulks when `bulkRecvEpoch != 0 && inc.known()`, unless `switched`. `switched` comes from `notePeerBootIncarnation`, whose boot id (`/proc/sys/kernel/random/boot_id`) changes only on OS boot — not on a daemon restart.
- `bulkRecvEpoch` is reset only on full disconnect (`sync_conn.go`, `handleDisconnect`'s all-fabrics-down branch). If any prior-process socket survives until the new process installs (same-slot supersession or a surviving alternate fabric), the high-water stands.

So a daemon-only restart produced: new process sends BulkStart epoch 1, same boot incarnation (`switched=false`), receiver between bulks with `bulkRecvEpoch=7` → refused as stale. The restarted node's pre-existing sessions are never bulk-transferred (the incremental sweep cannot see sessions older than its start) and no BulkEnd reconcile runs.

## Change

- `initGenState`: `s.bulkSendNext.Store(seed)` beside `s.syncEpoch = seed`, with a #15182 comment. The first epoch a restarted process emits within a boot is now strictly newer than any epoch its predecessor emitted; cross-boot restarts still restart the monotonic clock lower and are admitted via `switched` (#2198 F2), untouched.

No receiver change: the guard, the #8966 within-bulk arm, the #9174 V015 between-bulks arm and the legacy fail-open (`inc` unknown) are all preserved.

## Risk

- Epoch values on the wire become large (monotonic nanos) immediately, including for the first bulk of a fresh boot — byte-identical wire shape (8-byte little-endian), and receivers compare only `>`/`==` against their high-water, which the seed keeps strictly increasing within a boot. A mixed-version pair is unaffected: an old receiver accepts any newer epoch, and an old sender's epoch 1 is still admitted by a new receiver exactly as before (between-bulks arm requires a standing high-water and a known incarnation).
