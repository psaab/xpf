# Issue #13102: Preserve DHCPv6-client addresses during interface compilation

## Why

`planPhysDesired` and interface reconciliation treated `DHCPv6Client != nil` as
static because they tested only `DHCPv6`. For a config carrying the structured
client model without the legacy bool, compilation could reconcile an empty
static address set over a live leased address. The networkd models also omitted
the DHCPv6 client flag, and zoned VLAN reconciliation could delete the lease.

## What

- Add one dataplane predicate that recognizes both DHCPv6 representations and
  use it in physical address planning, VLAN reconciliation, and every relevant
  networkd model path (secure-tunnel unit, VLAN sub-interface, and physical
  interface).
- Include `DHCPv6Client` in the userspace stable-RETH IPv6-presence predicate,
  matching the existing host-inbound DHCPv6 handling.
- Add a regression covering the DHCPv6 bool control and client-only units in
  physical planning and networkd models.

## Validation

- RED on pristine `origin/master` (`aea7b2b64`):
  `go test ./pkg/dataplane/ -run '^TestDHCPv6ClientOnlyPreservesLease13102$' -count=1`
  failed with `skipAddrs=false` and missing `DHCPv6=true` assertions for the
  client-only unit.
- GREEN focused regressions:
  `go test ./pkg/dataplane/ -run '^TestDHCPv6ClientOnlyPreservesLease13102$' -count=1`
  and
  `go test ./pkg/dataplane/userspace/ -run '^TestStableRethUnitHasIPv6RecognizesDHCPv6Client13102$' -count=1`
  passed.
- `go vet ./pkg/dataplane/` passed.
- `go test ./pkg/dataplane/ -count=1` ran and failed only at
  `TestUserspaceXDPShimObjectMatchesSourceManifest`: the existing
  `userspace-xdp/src/lib.rs` manifest hash differs from the checked-in object.
  This change does not touch that source or generated object.

## Risk

No behavior change for the legacy `DHCPv6` bool. Structured DHCPv6 client units
without that bool are now treated consistently as DHCP-managed, avoiding
address deletion and restoring networkd client configuration.
