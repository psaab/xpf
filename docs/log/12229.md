# #12229 — deny lifeline-shared addresses on data ingress

- **Timestamp**: 2026-10-08 (`fix/12229-campaign-pub`)
- **Action**: preserve the lifeline address exclusion from destination-only deny-all policy while adding an ingress-only drop on normal zone interfaces.

## Red before

On base `a714c90d472a3c3d98a3799831cfef3ec311a61c`, the regression's generated-rules check failed because no ingress-only drop for `192.0.2.1` was emitted. The isolated kernel scenario also confirmed the defect: an SSH connection to the shared address through the untrust veth was connected instead of timing out, for both the text oracle and production netlink installer.

## Change

- The host-inbound view now carries separate IPv4/IPv6 ingress-only deny destinations. Building an empty-admit view withholds lifeline-shared addresses from destination-only service policy but keeps them for an unconditional drop scoped to that zone's normal ingress interfaces.
- The production nftables installer and daemon text oracle emit the scoped drop before the residual established-connection accept. The `fxp0` management interface remains outside the ingress set, and an admitting view does not get a duplicate deny.
- The cold-boot fence continues to withhold lifeline-shared addresses from its destination-policy view. The config duplicate-checker's lifeline skip is unchanged.
- Updated `docs/host-inbound-service-matrix.md` to describe the deny-all and cold-boot behavior.
