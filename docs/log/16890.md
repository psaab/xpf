# Issue #16890 — carved export tail must stay within the #5701 sequence bound

- **Issue:** A carved export tail appended after 6552 counted term sequences
  could render `route-map BIG deny 65540`, which FRR rejects and can poison the
  vtysh-batched `frr-reload`.
- **Re-verification:** Current `origin/master` is `f3030311e6`. The FRR render
  belt already reserves the carved no-default tail and, at 6552 term sequences,
  quarantines the map instead of emitting sequence 65540. However, the strict
  compiler's `RouteMapSequenceCount` gate does not know the per-instance
  export carve, so `CompileConfig` still accepts a shape whose renderer must
  quarantine it. The missing defect was the strict-commit bound.
- **What:** Share the carved single and composed tail reserve arithmetic and
  origination predicate between `pkg/config` and `pkg/frr`. The strict
  per-policy and composed-chain gates now include the reserve only for
  originating BGP export maps; the render belts delegate to that same config
  arithmetic. Add compiler regressions for no-default/no-next at 6552 terms
  and no-default/next-policy at 6551 terms, plus passing controls for 6551
  no-next and 6550 explicit-default/next-policy.
- **RED → GREEN:** The existing render test's RED/GREEN run proved the
  no-next +1 renderer reserve. The compiler boundary cases pass on the strict
  gate: `go test ./pkg/config -run '^TestCarved.*16890$' -count=1`. Their
  pre-fix failure was not rerun on the compiler code path.
- **Validation:** `go test ./pkg/config -run '^TestCarved.*16890$' -count=1`,
  full `go test ./pkg/frr -count=1`, and `go vet ./pkg/config ./pkg/frr` pass.
  `gofmt -l` on the changed Go files emits no paths. Full
  `go test ./pkg/config -count=1` hit unrelated config-package failures and
  timed out after 10 minutes.
- **Residual:** No live FRR parser or `frr-reload` run; the regression verifies
  compiler bounds and rendered sequence quarantine behavior.
