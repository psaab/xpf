# Issue #14135: lo0 cold-boot fence omits DHCP backstop sets

## Why

`installLo0ColdBootFence` (`pkg/daemon/daemon_nft.go`) built its
`xnft.FenceSpec` from views + unzoned addresses only, dropping the
DHCP backstop sets that `dpuserspace.BuildFenceAddrSets` had already
derived (`UnleasedV4/V6`, `UnleasedVRFSlavesV4/V6`, `AdmitV6`,
`AdmitVRFSlavesV6`), and the retained text parity oracle
`buildLo0FencePayload` likewise passed empty backstops. The netlink
lo0 fence builder (`buildLo0FenceNetlink` ->
`buildFenceDropsAfterMandatoryAdmitsNetlink`) already consumes those
fields for the host-inbound fence. A zoned DHCP interface that is
unleased in the fence snapshot has no address for the fence's
destination drops to match, so the `xpf_lo0` table alone (priority 0,
`policy accept`) fell through for any address that interface later
leased. The host-inbound table usually denies the same traffic, so
this was defence-in-depth rather than the sole barrier — but the lo0
fence's contract is to stand in for the real lo0 filter on its own,
and it silently did not for the DHCP lease window.

## What

- `installLo0ColdBootFence`: populate `UnleasedV4/V6`,
  `UnleasedVRFSlavesV4/V6`, `DHCPv6Admit`, and
  `DHCPv6AdmitVRFSlaves` from the `FenceAddrSets` (mirroring
  `installHostInboundColdBootFence`), and count a non-empty backstop
  as a scoped drop for the fence log line. The DHCPv6 reply admits
  keep leasing obtainable during the fence window; the
  interface-scoped FIB-local/anycast drops (plus the VRF link-local
  fallback) deny later-leased local addresses.
- `buildLo0FencePayload`: accept `unleasedV4, unleasedV6,
  vrfBackstop` and thread them into `buildFenceTablePayload` instead
  of the hard-coded empty lists; all oracle callers migrated.
- NOT changed: netlink builders (they already consume the fields),
  `FenceSpec`/`FenceAddrSets` types, chain priorities, the
  fail-closed boot path in `daemon_failclosed_boot.go` (it constructs
  `FenceAddrSets` from live addresses with no config, so there are no
  backstop sets to carry), and the host-inbound/gap fences.

## Validation

- New regression `TestColdBootLo0FenceCarriesDHCPBackstop14135`
  (production path `applyLo0Filter` -> `BuildFenceAddrSets` ->
  `installLo0ColdBootFence` with a DHCP ge-0/0/9 in the enforcing
  wan zone): RED with the backstop fields reverted out of
  `installLo0ColdBootFence` (spec carries no `ge-0-0-9`, payload has
  no `fib daddr type { local, anycast } drop`), GREEN with the fix.
- New T1 parity subtest `lo0_cold_boot_fence_dhcp_backstop` proves
  the text oracle and the netlink `InstallLo0ColdBootFence` render
  the backstop sets bit-identically; full `TestNftNetlinkParity`
  passes (including all pre-existing fence cases).
- `go test ./pkg/daemon/ -run 'TestColdBootLo0|TestFence|TestDay2Lo0|TestLo0Teardown'`
  passes; `go vet ./pkg/daemon/` clean; touched files gofmt-clean.

## Risk

The lo0 fence now also emits the DHCPv6 reply admit
(`fe80::/10 udp sport 547 dport 546 accept`) on backstopped
interfaces whose effective policy permits dhcpv6 — the same admit
the host-inbound fence and real table already emit, required so the
backstop drop does not starve the lease it guards. No other accept
is added; every other fence rule is unchanged, and a fence still
never sets `lo0Enforced`.
