# #15261 — ipsec: #14589 partial-load recovery promotes the prior set without fingerprints after an xpfd restart (B02-03)

- **Timestamp**: 2026-10-19
- **Action**: In `prevHashFor14589` (`pkg/ipsec/manager.go`), call
  `m.seedFromStateLocked()` under `mu` before reading
  `m.prevConnHashes`. #14589 recovery (`priorSet14589`, reached from
  the list-conns-failure, subset render/verify-failure, and
  non-subset-loaded-set rollback branches in both `applyConfig` and
  `clearConfig`) runs before the first `promoteConnNames` on a
  restarted Manager — the only other seeding site — so the persisted
  #9687 fingerprints were never folded in and every prior hash came
  back absent. Seeding is once-only (`stateSeeded`), so on a warm
  Manager the call is a no-op.
- **File(s)**: `pkg/ipsec/manager.go`,
  `pkg/ipsec/partial_restart_prior_15261_test.go` (new),
  `pkg/ipsec/README.md`, `docs/log/15261.md`

## Mechanism (verified at base 662846f93c)

Pre-fix `prevHashFor14589` (manager.go:666-674) locked `mu` and read
`m.prevConnHashes` with no seed; `seedFromStateLocked` ran only inside
`promoteConnNames` (manager.go:943). On the first apply after an xpfd
restart that partially loads and hits a `priorSet14589` branch,
`priorSet14589` therefore built the prior set with empty hashes.
`promoteConnNames(priorNames, {})` then hit `known && oldHash !=
newHashes[name]` with `newHashes[name]==""` for every prior name:
all unchanged tunnels charon kept running were terminated, and
`persistStateLocked` stored the empty fingerprint map. The next apply
found no known hash for those names, so the #10878 legacy-adoption
rule adopted the current render as the baseline — a later PSK
rotation was never detected and its stale SA never torn down.

## Fix

- `prevHashFor14589` now seeds from the persisted conn-state file
  before reading, exactly as the issue's fix direction allows ("Call
  seedFromStateLocked under mu before priorSet14589 (or inside
  prevHashFor14589)"). `mu` is already held there and
  `seedFromStateLocked` requires it.
- NOT changed: `priorSet14589`'s absent-hash honesty rule (a name with
  no persisted fingerprint still gets no hash — legacy state files
  keep the adoption behaviour), `promoteConnNames`, the subset /
  candidate arms of recovery, teardown/re-initiation, `clearConfig`.
  Warm managers are byte-identical in behaviour (seed is a no-op once
  `stateSeeded`); managers without a `statePath` seed nothing.
