# Issue #12731 — AppID-OFF builtin stamped/unstamped label split

- **Issue:** With AppID disabled, `compileApplications` stamps from `CatalogNames(cfg, false)`, a policy/NAT-referenced-only catalog. The tuple fallback also considered the narrow builtin fallback table, including builtins absent from the OFF catalog. A session matching such a builtin could therefore be stamped as `UNKNOWN` but render as the builtin name when `app_id == 0`.
- **Why:** A mode-specific label must not depend on whether an otherwise identical session was stamped.

## Change

Kept the OFF catalog's referenced-only footprint, avoiding an unconditional 15-name expansion and preserving the existing catalog ID/overflow contract. The AppID-disabled tuple fallback now considers a builtin candidate only when that builtin has an assigned name in the active OFF `AppNames` map. Referenced builtins retain their existing tuple matching; unreferenced builtins resolve to the same `UNKNOWN` label as a stamped catalog miss. The no-config fallback is unchanged. User-application fallback behavior is unchanged.

Added parity cells for unreferenced HTTP/HTTPS/IKE-NAT builtins, a referenced SSH builtin, an unknown tuple, a referenced custom app, a custom protocol-only application overlapping an unreferenced builtin, and a same-tier ID tie-break. A separate catalog test pins the referenced-only OFF footprint.

## RED → GREEN proof

- **RED:** Before the resolver gate, `go test ./pkg/appid -run '^(TestStampedUnstampedBuiltinParity_12731|TestCatalogNamesOffIncludesBuiltinFallbacks_12731)$' -count=1 -v` failed: unreferenced builtin tuples had no stamped catalog winner (`UNKNOWN`) while the fallback expected a builtin name. This was the ship-builtins implementation probe; the final scope-fallback contract was then pinned in the parity test.
- **GREEN:** `go test ./pkg/appid -run '^(TestStampedUnstampedBuiltinParity_12731|TestCatalogNamesOffRemainsReferencedOnly_12731)$' -count=1 -v` — PASS.
- **Mutant:** Temporarily removed the OFF-catalog membership gate from builtin fallback consideration. `go test ./pkg/appid -run '^TestStampedUnstampedBuiltinParity_12731$' -count=1 -v` failed the unreferenced HTTP/HTTPS/IKE-NAT, overlapping protocol-only custom, and same-tier tie-break cells; restoring the gate returns the package suite to PASS.
- **Regression compatibility:** `go test ./pkg/appid/... -count=1` — PASS, including the existing AppID mode-precedence, builtin-shadow, UDP/4500, catalog, and collision suites.

## Risk

When AppID is disabled and a builtin is not referenced by policy or NAT, the tuple fallback now returns `UNKNOWN` instead of a heuristic builtin label. This is the intentional parity contract: that builtin is absent from the OFF stamping catalog. Builtins present in that catalog remain fallback-eligible, and application-identification-enabled behavior is unchanged.
