# Issue #15233: cli: fix cohort — ip-monitoring status truth (A49-01, A49-03)

## Why

Two validated residuals in the ip-monitoring status/seed path:

- **A49-01:** `pkg/rpm` seeds every test `LastStatus: "unknown"` before
  any probe verdict. `ipmon.seedResultsLocked` recorded a row for every
  result (`fresh[probe][test] = LastStatus=="fail"`) and `Status()`
  keyed `Known` on mere presence of `failedTests[probe]`. A policy whose
  probe had never produced a verdict therefore reported `Known=true`
  and `show services ip-monitoring status` (and the gRPC text surface,
  both via `FormatStatus`) rendered `Status: PASS` — worst during a
  sustained probe-setup hold, when failover protection is not working.
  (`show services rpm probe-results` still showed "unknown".)
- **A49-03:** `daemon.reconcileIPMon` seeded the engine with an
  unversioned `rpm.Results()` snapshot. A FAIL transition landing
  between the read and `ipmon.Apply` was overwritten by the stale
  snapshot's pass/unknown rows, withdrawing the failover route until
  the next reconcile/commit or RG transition. Only
  `HandleTransition` checked `Transition.Generation` against
  `lastTransitionGeneration`; `Apply` carried no generation at all.

## What

- `pkg/ipmon/ipmon.go`:
  - New `knownTests` map (probe → test → has pass/fail verdict).
    `seedResultsLocked` now records only `pass`/`fail` rows in both
    `failedTests` and `knownTests`; `unknown` (and any other) rows are
    skipped. `Status()` computes `Known` from `knownTests`.
    `HandleTransition` marks the transitioned test known only for a
    genuine `pass`/`fail` status.
  - `Apply` is now a thin unversioned wrapper (generation 0, always
    seeds) over `apply(cfg, results, generation)`. New
    `ApplyVersioned(cfg, results, generation)`: a generation older than
    `lastTransitionGeneration` installs the policy set but skips the
    seed (as if nil); a newer generation advances
    `lastTransitionGeneration`. Equal generation seeds (idempotent
    re-read at the same generation).
- `pkg/rpm/rpm.go`: new `ResultsVersioned()` returning the snapshot and
  `transitionGeneration` atomically under `m.mu.RLock`.
- `pkg/daemon/daemon_ipmon.go`: `reconcileIPMon` now uses
  `ResultsVersioned()` + `ApplyVersioned`. Nil manager still yields a
  nil snapshot (preserve state); the generation is 0 in that case.
- `pkg/ipmon/README.md`, `pkg/rpm/README.md`: status-truth and entry
  point notes. NOT changed: `evaluateLocked` (still reads
  `failedTests`), `HandleTransition` generation gating, hold-down,
  overlay/winner logic, metrics descriptors (no metric reads `Known`),
  and the CLI/gRPC renderers (they already render UNKNOWN from
  `Known=false`).

## Validation

- RED on `origin/master` (5552c6ef59): the new
  `pkg/ipmon/unknown_stale_15233_test.go` fails to build
  (`ApplyVersioned` undefined) — the versioned fence does not exist;
  the unknown-seed assertions fail against the presence-based `Known`.
- GREEN: `go test ./pkg/ipmon/ -run '15233' -count=1`,
  `go test ./pkg/rpm/ -run '15233' -count=1`, full
  `go test ./pkg/ipmon/ ./pkg/rpm/ ./pkg/daemon/ -count=1`, and
  `go vet` on the touched packages (results recorded at commit time).
  Adjacent controls kept green: `TestUnknownStatusNotReportedAsPass`
  (nil snapshot stays UNKNOWN, pass verdict becomes PASS),
  `TestApplyNilResultsPreservesFailedStateButEmptyClears`,
  `TestApplyPreservesFailedStateAcrossCommit`, and the daemon ipmon
  suite.

## Risk

A fresh authoritative snapshot whose rows are all `unknown` (e.g.
right after an RPM restart that did not carry verdicts, #6561) now
reports UNKNOWN instead of PASS until the first verdict — the intended
truth; route behaviour is unchanged because `unknown` already bucketed
with pass in `failedTests`. A stale versioned snapshot no longer
re-seeds, so a policy set installed by a stale reconcile keeps the
engine's newer verdicts until the next fresh snapshot.
