# #14612 — `then log`-only FILTER_LOG hits still reach `system syslog host` collectors

- **Timestamp**: 2026-10-16
- **Action**: Closed the residual #6859 sink. `EventReader.logEvent` emitted the daemon "firewall event" slog line before the #6859 filter-term gate, and `SyslogSlogHandler` (installed as `slog.Default()` in the daemon, clients set by `applySystemSyslog` from `system syslog host`) forwarded every record by severity alone — so a `then log`-only FILTER_LOG hit reached system-syslog collectors even though the security-log stream clients were correctly gated. Fix: `logEvent` computes the same `filterSyslogRoute.allows(RuleID, TermID)` decision before the slog emission and, when gated, emits via a new suppress-system-syslog context marker (`eventReaderSlogInfoSuppressSystemSyslog` in `pkg/logging/slog_handler.go`, derived from the event-reader context so the bounded writer marker is retained); `SyslogSlogHandler.Handle` still writes the record to its base handler (local log unchanged) but returns before forwarding to system clients. The stream fan-out reuses the same decision. NOT changed: local writers, event buffer (`show security log`), `then syslog` routing, non-FILTER_LOG events, ordinary slog records, and the nil-map (unwired) legacy fan-out.
- **File(s)**: `pkg/logging/ringbuf.go`, `pkg/logging/slog_handler.go`, `pkg/logging/filter_log_syslog_route.go` (placement note), `pkg/logging/README.md`
