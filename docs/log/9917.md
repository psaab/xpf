# #9917 — snmp/monitor cohort: five management-surface findings

Base `6555e2189`, branch `fix/9917-snmp-monitor`. All five members Low, one
surface (SNMP agent + trap path + one monitoring render), no forwarding touch.

## Fixes

- **F-134** (`pkg/snmp/traps.go`, `agent.go`): the v1 Trap-PDU build — DNS plus
  an up-to-2s `agentAddrForTarget` dial per target — moved off the link-monitor
  goroutine. `sendLinkTraps` enqueues a deferred job (`pkt` nil, build
  parameters carried); the trap worker builds via `buildLinkTrapV1WithUptime`
  just before sending. v2c stays prebuilt on the caller (pure BER, no I/O).
  Uptime is captured at event time so backlogged traps keep event-time
  stamps. The worker re-checks stop after the deferred build, preserving the
  #4916 no-post-Stop-delivery guarantee (worst-case Stop latency +1 dial).
  Each v1 trap's worker cost rises ~4s to ~6s worst case; F-140's cap keeps
  the sick share bounded so healthy traps still flow.
- **F-136** (`pkg/config/compiler_validate_warn_snmp_des_9917.go`): USM users
  with `privacy-des` draw a commit-time warning naming the user and steering
  to `privacy-aes128`. Advisory only — DES keeps working (Junos compat).
  Keyed on the compiled user table (all spellings uniform); placed in
  `ValidateConfig`, which reaches commit via the `runTailGates` fold into
  `cfg.Warnings` and persists on alarms like the hmac-md5 precedent. README
  deprecation note in `pkg/snmp/README.md`.
- **F-138** (`pkg/monitoriface/monitor.go`): new pure `formatLinkSpeed` —
  exact multiples of 1000 render integer `gbps`, other gigabit-plus speeds
  one truncated decimal via integer math (no float rounding), uniform at all
  magnitudes; 2500 Mbps reads `2.5gbps`. `ReadLinkSpeed` delegates.
- **F-139** (`pkg/snmp/serve_budget_9917.go`, `Serve`): per-source token
  budget, 100/s sustained + 200 burst per source IP, checked before any MIB
  work; excess sheds silently. The loop stays strictly serial, so the
  `lastPacket` v3-auth pattern is safe by construction — no concurrency
  introduced at all. At most 1024 sources tracked (60s idle expiry, expiry
  sweep at most 1/s); keys are normalized `[16]byte` IPs, never ports.
- **F-140** (`pkg/snmp/traps.go`, `agent.go`): each receiver holds at most 32
  of the 256 shared queue slots (host/host:port spellings normalized to one
  key); past the cap its new traps shed, counted in `trapsDropped`. Single
  admission decision (cap-drop / queue-full-drop / admit) preserves the
  C180-026 accepted == delivered + dropped exactness; every increment pairs
  with exactly one worker-side decrement. Drop isolation only — the worker
  still drains one FIFO (healthy trap behind a full sick share waits up to
  ~192s), documented in code and README.

Adjacent: the README `#3948` bullet still claimed agent-addr `0.0.0.0`,
contradicting the #9123 fix — corrected to the RFC 3584 §3.2 behavior while
editing those bullets.

## Plan-review adjudication (2 hostile, pre-implementation)

Review A: APPROVE-WITH-CHANGES (18 findings). Review B: REJECT (18 findings).
Every P0/P1 was accepted into the design before implementation:

lazy-init of both new maps under their mutexes; worker lock discipline
(dequeue lock-free, brief lock for the map update only, never a chan op under
`mu`); increment-only-after-successful-send; post-build stop re-check (a real
#4916 regression caught); nil-guards on the DES helper; single-decision
admission counting; decrement-per-drained-job (no map reset); amortized
eviction sweep (≤1/s, O(1) per packet); uniform decimal rule at all
magnitudes; integer-tenths rendering (no `%.1f`); traversal e2e dropped;
total `formatLinkSpeed` contract (`unknown` ≤ 0); DES fixture with passwords
+ append position at the `ValidateConfig` tail; Serve-test sync via
deadline-poll + Stop/join; version-all double-cap-consumption documented;
`[16]byte` normalized IP-only keys + mapped-alias test; behavioral (not
compile) REDs where a base seam exists; trap-target port normalization;
budget hardening (nil map, elapsed clamp, burst cap, lastSeen always);
deferred-vs-pkt precedence (deferred wins) + `all`-ordering test.

Reasoned deviations, all documented in code/README:

- **D1 silent shed vs tooBig** (F-139): silent. A `tooBig` reply costs a
  decode plus near-full USM framing for v3, defeating the shed; pre-decode
  placement keeps shed O(1); over-budget at 100/s+200 burst is abusive or
  pathological by construction; precedent #4289/#4302. The issue's `tooBig`
  assumed a queued pool design; no queue was introduced.
- **D2 flat rate despite the 33ms worst PDU**: 100/s + 200 burst chosen for
  legitimate-pass + typical-flood-stop. Residual documented, not fixed: a
  valid-credential worst-PDU flood (~30/s of max-size GETNEXT) can still
  saturate the loop; bounding it needs cost charging or a varbind cap —
  tracked as #10113.
- **D3 no global bucket**: documented residual — a distributed flood
  saturates the socket buffer ahead of any userspace budget; per-source
  bounds the finding's single-source actor.
- **D4 shed-newcomer between sweeps instead of true LRU**: 1s windows,
  self-healing via manager retry; a true LRU needs an ordered structure that
  exceeds Low scope.
- **D5 `ValidateConfig` (commit + alarms) vs compile-only**: kept
  `ValidateConfig` per the hmac-md5 precedent (verified the `runTailGates`
  fold reaches commit on both paths); persistence documented.
- **D6 `pkg/cli/link.go formatSpeed` sibling** (same truncation, found in
  review): out of cohort scope ("exactly the cohort scope"); filed as #10112
  instead of expanding the diff.

Rejected alternatives (recorded): agent-addr cache (stale source addrs
reintroduce the #9123 misattribution; cold miss still blocks the monitor);
single-dial collapse (dual-stack behavior change + mock-sender bifurcation);
worker pool for Serve (needs the `lastPacket` refactor through v3 auth plus
test churn, and still needs a budget against floods); deque drop-oldest for
traps (rewrites the C180-026-exact queue + breaks the chan white-box seam).

## Parent-review follow-up (PR #10114: GPT NEEDS-MAJOR + spark NEEDS-MINOR)

Rebased onto `32b1d0472` clean (upstream touched only docs + unrelated NAT
files). All five GPT mechanisms fixed in code, not narrowed away; spark items
folded alongside.

1. **Table lock-out (GPT-P1):** the budget no longer sheds newcomers past a
   full table -- a newcomer displaces a random incumbent (O(1), no scan), so
   no refreshed set of entries can lock legitimate managers out. The idle
   sweep is gone with it (displacement is the only reclamation). The old D4
   "self-healing via retry" claim was wrong for refreshed entries and is
   withdrawn. Cell: `TestServeBudgetFullTableAdmitsNewcomer9917` (fill 1024,
   refresh all, newcomer admitted, twice, table stays 1024).
2. **Service time (GPT-P2):** admitted requests now debit loop time consumed
   (per-source 10x, so a saturated expensive source converges to ~1/10 loop
   share), and a global backstop (2000/s + 4000 burst, expensive aggregate
   charged 2x toward ~1/2) bounds what rotating-spoof floods can take. The
   refill-during-handling replenishment the finding names is arithmetically
   dead (refill rate << charge rate). #10113 stays open but re-scoped (see
   its comment): the residual is now multi-source fair-share under FIFO,
   not single-source worst-PDU saturation. Cells: service-charge (binary-exact
   125ms debit, exact remainder) + global backstop (exact burst/refill).
3. **Fan-out regression (GPT-P2):** the per-target cap binds only above
   half-full (`trapCapPressureThreshold = 128`), so healthy bursts absorb
   exactly as the un-capped queue would; a lone sick receiver now holds at
   most ~half. Cell: `TestTrapFanOutBelowPressureLosesNothing9917` (2x40
   admitted whole, 0 dropped -- fails on the always-on cap by construction:
   64 admitted + 16 shed). The older healthy-admission cell now pins
   sick == 128 / dropped == 128.
4. **Numeric-spelling bypass (GPT-P2):** `normalizeTrapTarget` canonicalizes
   numeric IPs (`ParseIP`/`String`, no DNS): `2001:db8::9`, `2001:0db8::9`
   and `2001:DB8::9` share one key. Cell: three spellings x 32 capped at 32
   total. DNS aliases and case variants still key separately (documented;
   resolving at enqueue would re-add link-monitor DNS).
5. **Serve oracle (GPT-P2):** the flood test now observes a shed call-site
   counter under a frozen budget clock (exactly 200 shed of 400, control 5/5)
   instead of inferring drops from missing UDP datagrams. Buffer loss can no
   longer false-pass; slow execution cannot false-fail.
6. **SPARK-M1:** rebased + full suites re-run (below) + shippable-only diff
   confirmed (6 member commits + 2 hardening commits + log; no scratch files).
7. **SPARK-M2:** lowercase `gbps`/`mbps` is the monitoriface package's
   pre-existing convention (base `ReadLinkSpeed` used `%dgbps`/`%dmbps`); the
   fix preserves casing and every exact multiple renders byte-identically to
   base (1000/2000/5000/10000/25000/100000 rows in the table). `Gbps`/`Mbps`
   is the cli package's separate convention -- #10112.
8. **SPARK-M3:** README budget bullet rewritten to the true bounds; #10113
   re-scoped via comment, kept open.
