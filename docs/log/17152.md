# #17152 — shared source-scan blanker; status gates and unsafe ratchet

- **Base**: `7812f1bc2f43871ddea34066d799ae9ca86e9e7a` (origin/master)
- **Branch**: `fix/17152-campaign`

## Why

`server/helpers/status.rs` had a private `code_only` that dropped only
lines starting with `//`. A trailing `// state.afxdp.x()` note or a
`/* state.afxdp.x() */` block quoting the accessor kept the #6641
`every_counter_accessor_is_wired_into_process_status` gate (and the
other status gates sharing `code_only`) green after the real assignment
was deleted — the exact failure the gate's own doc records for
whole-line comments. The robust #12270 blanker
(`blank_comments_and_strings`) lived in
`afxdp/worker_queue_tests.rs` and was imported by five unrelated modules
through `crate::afxdp::worker_queue::tests`, so `worker_queue::tests`
and `worker_queue` itself carried widened visibility only to share it.
The crate-wide #16187 `unsafe` ratchet was mounted under
`protocol::cos`, making a whole-tree gate look like a CoS-file guard.

  `is_fixture_with`, `is_fixture`, `cfg_test_modules`, `afxdp_rs_files`

  `#[cfg(test)] mod test_support` in `main.rs` (with

  `afxdp/worker_queue_tests.rs`, `afxdp/forwarding_build/tests.rs`,
  `afxdp/session_glue/tests.rs`, `filter/tests.rs`,

  `protocol/unsafe_ratchet_16187.rs`. No `worker_queue::tests::`

- `server/helpers/status.rs`: `code_only` now delegates to
  `blank_comments_and_strings` (name kept for the call sites), with the
  doc updated to name the trailing/block shapes. Added fixture control
  `status_scan_blanker_ignores_trailing_and_block_comments_17152`
  pinning trailing-`//`, block-`/* */`, whole-line-`//` (must not
  satisfy) against real code (must satisfy).
- Mounted `unsafe_ratchet_16187` in `protocol/mod.rs` instead of
  `protocol/cos.rs`. Its test path is unchanged
  (`protocol::unsafe_ratchet_16187::*`).
- Drive-by required for green: `nat/mod.rs` declared
  `tests_synced_det_v4_15267` without `#[cfg(test)]` (every sibling has
  it), so on current master the #8325 agreement cell already classified
  that pure-test file as production. Added the missing gate; without it
  the moved scanner's #8325 cell cannot pass. The file has no `unsafe`
  and no production caller, so the #16187 census is unchanged.

Scope note: two other private `fn code_only` remain —
`afxdp/binding_state/kernel_stats_9168_tests.rs` (a different,

migrating those two is a separate, wider change than the named fix
(status gates + shared blanker + ratchet mount), and the
kernel-stats one documents its crudeness as a pinned property.
Flagging for the parent rather than silently expanding scope.

Pre-existing on clean master `7812f1bc2f` (verified by stashing this
change and re-running): `production_unsafe_only_ever_decreases_per_directory_16187`
already fails there (`afxdp: 82 vs ceiling 80`, `server: 4 vs 3`) and

## Risk

- Test-only change: every moved/added file is `#[cfg(test)]`-gated
  (`test_support` is declared `#[cfg(test)]` in `main.rs`); no
  production code, attribute, or hot-path behaviour changes. The one
  production-adjacent edit, `nat/mod.rs`'s added `#[cfg(test)]`,
  removes a test module from production builds — it was test-only in
  content (all `#[test]` fns, no `unsafe`), so production behaviour is
  unchanged and the #16187 production census is unaffected.
- An intermediate narrowing of `worker_queue::tests` to
  `pub(in crate::afxdp)` was tried and reverted: the #12270 declaration
  scanner strips only listed visibility forms, so it read the narrowed
  declaration as ungated and reclassified `worker_queue_tests.rs` as
  production (both #8325 and #6929 red). `pub(crate)` is kept, with the
  reason recorded at the declaration.
- The moved helpers are byte-identical to the originals (verified by
  diff of the extracted ranges); only their module path changed, so
  every consumer's measured inputs are unchanged by construction.
