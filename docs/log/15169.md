# #15169 — `show | compare` misattributes parent-level lines after a recursed sibling (B24-02)

- **Timestamp**: 2026-10-19
- **Action**: `diffNodes` in `pkg/config/ast_format.go` printed its
  `[edit <path>]` header exactly once, before its rendering loop. When a
  modified child block was recursed into, the child printed its own
  deeper header and the parent loop then continued with following
  +/-/unchanged lines at the parent level without re-emitting the
  parent header — a removed/added stanza directly after a recursed
  sibling rendered under the unrelated deeper context (e.g. a deleted
  policy shown inside another policy's `then`). At the root the empty
  `editPath` suppressed the header entirely, so top-level +/- lines had
  no context header at all. Fix, confined to `diffNodes`: the level now
  first collects its ordered sections (own lines rendered into buffers,
  plus recursion arms), then emits them with the level's header printed
  lazily immediately before each run of own lines — bare `[edit]` at
  the root — and re-armed only when a recursion actually produced
  output. A header with no lines under it is therefore never printed,
  and the all-recursable fast path is untouched.
- **Validation**: New `pkg/config/compare_header_15169_test.go`
  (5 cells: removed `deny-x` and added `new-x` policies governed by
  `[edit security policies from-zone trust to-zone untrust]` rather
  than the recursed `keep` policy's deeper
  `[edit ... policy keep then]` header; root addition opening with
  bare `[edit]`; single-header control for a plain leaf change;
  no-duplicate/no-empty-parent-header control for a deep-only
  change). RED on current `origin/master`: the addition cell fails
  (`new-x` governed by the deep `policy keep then` header) and the
  root cell fails (no `[edit]` printed), controls pass; on the
  pre-#15168 base the original removal probe also rendered `deny-x`
  after the recursed block under the deep header. GREEN after the
  fix. Controls stay green: all four #15168 order/duplicate compare
  cells, `TestInactive_CompareShowsDeactivate` (#2008 H1), the
  configstore `Compare` suite (incl. the redacted/rollback compares),
  and the config format/redact/parser subsets (156 cells). The full
  `pkg/config` suite does not complete on this host under the
  multi-lane load (load average ~100; it times out inside the
  spelling-differential gate on both the fixed and pristine trees),
  and five `TestCompile*` cells fail identically on pristine
  `origin/master` — both pre-existing and unrelated to this change.
- **Risk**: Rendering-only change to `FormatCompare` output
  (`show | compare`, rollback compares, redacted compares all route
  through it). Byte-identical output except where the old output
  misattributed lines or omitted the root header; consumers compare
  against `[no changes]` on empty diffs, which is unaffected. No
  fail-open path is involved — the cited mechanism is display
  attribution, so the issue's generic fail-closed direction does not
  apply.
