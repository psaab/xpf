# #15172 — userspace-dp: transmit_batch mirror drop orphaned its MQFQ pop snapshot; retry restore panicked / restored wrong head

- **Timestamp**: 2026-10-19
- **Action**: `transmit_batch` (`tx/transmit/mod.rs`) now reports every mirror-reserve dropped item's ORIGINAL-input position in the new per-binding `scratch_dropped_mirror_orig_idx` (cleared at entry beside `scratch_committed_orig_idx`, pre-sized in `WorkerScratch::pre_sized`). `submit_local` (`cos/queue_service/submit_local.rs`) copies that list (fixed stack array, no allocation) and, on every settle that can restore — Ok partial tail via `apply_cos_send_result`, `Err(Retry)`, and `Err(Drop)` — removes the orphaned snapshots from the queue's `pop_snapshot_stack` BEFORE the LIFO `push_front` restore, in descending original-position order, via the new `cos_queue_remove_orphan_snapshot_at` (`cos/queue_ops/drain.rs`). The removal reuses the #913/#927 orphan clamp (remaining pre-pop vtimes raised to the current `queue_vtime`; same-bucket snapshots raised to the orphan's served finish) so the dropped item's committed vtime/frontier advance survives rollback. A debug-only restore-entry guard asserts the stack still holds at least one snapshot per restored item. NOT changed: the exact drain builders (they already pre-filter mirror drops with top-of-stack orphan cleanup), `submit_prepared` (prepared items carry no Local pop snapshot from `transmit_batch`), and the unshaped backup drain (its items never came from a CoS queue pop, so no snapshot exists; it ignores the new scratch).
- **Validation**: New regression `mirror_drop_orphan_snapshot_removed_before_retry_restore_15172` (real `build_cos_batch_from_queue` batch [A,M(mirror),B] on a flow-fair queue, pre-filled TX ring forcing inserted==0): RED pre-fix — panics at `cos/queue_ops/push.rs:307` (`pop_matching_snapshot` bucket-mismatch `assert!(false)`); GREEN post-fix with A restored at its pre-pop head finish (100) and stack empty. Controls green: `no_mirror_drop_retry_restore_round_trips_15172_control`, `mirror_drop_full_commit_no_restore_15172_control`, `orphan_removal_fifo_queue_noop_15172_control`, plus the #5157 `mirror_interior_drop_preserves_sidecar_attribution_5157`. Base attribution: `origin/master` (606d456ff5) test build is broken by a pre-existing E0063 in `afxdp/mirror/mod_tests.rs:1032` (missing `ingress_vlan_id`/`unit_scoped` from #15113/#15114) — verified identical on a clean tree; a temporary local literal fix (not in this PR) was used only to run the suites.
- **Risk**: Fail-closed preserved — a desynced stack still trips `pop_matching_snapshot`'s assert rather than restoring against a wrong snapshot; the fix only removes snapshots for items provably dropped by the reserve gate in this batch. Residual: same-bucket multi-drop frontier clamp is the #927-proven monotone shape; partial-insert Ok tails with committed-prefix snapshots below the survivors are intentionally left for the next build-start clear (#3968).
