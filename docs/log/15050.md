# 15050 — packed bare VRRP virtual-address: strict gate + tolerant normalization

- **Timestamp**: 2026-10-18
- **Action**: closed the packed one-liner bypass on the `virtual-address`
  VALUE (the #5184/#8483 family, one leaf over). A bare Junos-style VIP
  (`vrrp-group 1 virtual-address 10.0.1.100;`) rode the instance node's Keys
  past `SchemaValidate` (its `ValidateIPv4CIDR`/`ValidateIPv6CIDR` leaf only
  gates structured spellings) and strict compile, then `netlink.ParseAddr`
  rejected it at runtime and #5082 fail-closed reverted every promotion to
  BACKUP — the VRRP-protected gateway had no owner on every node carrying
  the config. New compiled-`*Config` gate `validateVRRPVIPPrefixStrict`
  beside the #8483 timers gate hard-rejects a prefix-less VIP at
  commit/commit-check; the tolerant load/peer-sync path warns
  (`lenientVRRPVIPPrefix`, #1960 no-brick) and `normalizeBareVRRPVIPs`
  rewrites the bare VIP with the enclosing unit address prefix (or
  `/32`/`/128` when no same-family prefix exists) so the leniently-loaded
  config actuates instead of reverting every promotion forever.
- **File(s)**: `pkg/config/compiler_validate_strict_vrrp_vipprefix.go` (new),
  `pkg/config/compiler_validate_strict_vrrp_vipprefix_15050_test.go` (new),
  `pkg/config/compiler_uniformgates_cluster_zone.go`,
  `pkg/config/compiler_tailgates.go`, `pkg/config/compiler_opts.go`,
  `pkg/config/README.md`, `docs/config-schema.md`, `docs/log/15050.md`.

## Mechanism

`pkg/config/compiler_interfaces.go` `parseVRRPGroups` appends packed
virtual-address keys verbatim; `pkg/vrrp/vrrp.go` passes them through;
`pkg/vrrp/instance_vip.go` records a `netlink.ParseAddr` error as a failed
VIP, `ok()` requires zero failures, and `instance_transition.go` rolls back
to BACKUP and re-arms. The schema comment in `schema_interfaces.go` already
documented the divergence ("xpf requires the prefix, unlike Junos") — the
prefix requirement was enforced only on the spellings the schema walker
validates.

## Scope decisions

- Explicit `vrrp-group` blocks only. RETH-derived instances take VIPs from
  unit `Addresses`, which are authored CIDRs — no bare-literal source
  (same scope reasoning as #7577).
- Garbage literals that parse as neither CIDR nor IP are NOT re-reported
  here; the #7577 empty gate owns them. This gate fires only on a
  parseable IP with no `/`.
- Strict path never rewrites: an operator's commit is rejected, not
  silently edited. Normalization happens only where the config is already
  being tolerated (load / peer-sync), and it is also what makes the
  tolerant path actuate rather than merely warn.

## Regression (RED → GREEN)

- `TestPackedBareVRRPVIPFailsStrict15050`: packed bare, bare-first
  multi-value, and braced bare spellings reject naming the VIP and the
  missing prefix; packed/braced CIDR controls commit unchanged.
- `TestPackedBareVRRPV6VIPFailsStrict15050`: IPv6 mirror + CIDR control.
- `TestPackedBareVRRPVIPLenientNormalizes15050`: strict rejects (control),
  lenient warns and compiles `10.0.1.100` → `10.0.1.100/24` (the enclosing
  `10.0.1.1/24` prefix).
- `TestBareVRRPVIPWithoutEnclosingPrefixNormalizesToHost15050`: host-prefix
  fallback `/32`/`/128`, and the normalized config passes the strict gate.
