# #14991 — rolling/rollback compatibility judged the running pair, not the target binary; malformed wire versions permitted (D38-03)

- **Timestamp**: 2026-10-18
  - **Action**: judged rolling and rollback compatibility against the
    staged / rollback-target binary and failed closed on malformed wire
    versions.

    `runRollingWith` and `runRollingRollbackWith` evaluated
    `HAProtocolCompatible` and `SessionSyncWireCompatible` against the
    currently running local daemon and CLI binary. That pair is not the
    pair that must interoperate after the cut: the forward cut installs
    the staged binary, and the rollback cut installs
    `versions/<target>/xpfd`, while the peer keeps running its current
    build. A staged (or rollback-target) binary whose HA window excludes
    the peer, or whose session-sync wire version differs from the peer's,
    therefore rolled through every gate and was discovered only when the
    mixed pair could not decode each other's synced sessions — heartbeat,
    election and failover all still working. Separately,
    `parsePeerSessionSyncWire` mapped a present-but-malformed peer wire
    value (`banana`, `-1`, `70000`, …) to `(0, present)`, and
    `cluster.SessionSyncWireCompatible(0)` PERMITS 0 as "peer predates
    #7990" — so a garbled instrument permitted the drain.

    Fix, in `pkg/upgrade`:
    - New `System.ProtocolVersions(bin)` probe (real + fake): runs the
      target binary's pure `protocol-versions` verb and parses it with
      the existing fail-closed `parseImageVersions`; a non-zero exit or
      any missing required key is an error.
    - New `RollingCluster.PeerProtocolVersions()`: one status fetch
      returning local HA, peer HA and peer session-sync wire, strictly
      parsed. A present-but-malformed value is an error; an absent peer
      line is `present=false`.
    - New `targetWireVerdict` + `checkTargetCompatible` /
      `checkStagedTargetCompatible`: HA window `[target floor, target]`
      and exact session-sync match of the TARGET against the peer (the
      `GateMixedBaseSwap` rules), unknown peer wire (0) still permitting,
      unknown peer HA refusing, unprovable target = error. The forward
      path resolves the same pinned staged generation `Runner.Run` will
      copy from; the rollback path probes `versions/<to>/xpfd` from the
      resolved rollback plan. Both run BEFORE `ForceSecondary`; the
      legacy running-pair gates are retained after them.
    - `sessionSyncWireVerdictFromStatus` now uses a strict peer-wire
      parser: malformed present values fail closed as an error instead of
      permitting via 0. `parseHAProtocolVersions` strictly parses both HA
      lines (the lenient `trailingInt`, now dead, was removed);
      `parseHAProtocolCompatible` keeps its signature and fail-closed
      behaviour via the new verdict helper.

    Regression (`rolling_target_compat_14991_test.go`,
    `TestProtocolVersionsProbe14991` in `system_linux_test.go`): target
    verdict table (skew refuses, match/unknown-wire permit, HA window
    edges refuse, missing target fields error), malformed peer wire and
    malformed/absent peer HA fail closed at the verdict layer with
    unknown/matching/differing controls, and driver-level cells proving
    a skewed staged target and a skewed rollback target refuse BEFORE
    `ForceSecondary` (no cut, no destructive calls) while a compatible
    staged target still rolls. Adjacent controls stay green: the #7990
    parser/verdict tables, absent-line-fails / unknown-permits, the
    rolling happy path, and `TestRollingRollback_HappyPath` (default fake
    target = current constants).

    RED evidence: the new tests reference symbols that do not exist on
    `origin/master` (`targetWireVerdict`, `haProtocolVerdictFromStatus`,
    `parseHAProtocolVersions`, `PeerProtocolVersions`,
    `System.ProtocolVersions`), so the package does not compile there;
    with only the production fix reverted the malformed-wire and
    skewed-target cells permit/proceed. GREEN: full
    `go test ./pkg/upgrade/ -count=1` passes on the fix.
