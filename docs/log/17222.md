# #17222 Consolidate the per-cluster-node gate prologue behind effectiveNodeViews

## Finding

The per-cluster-node gate prologue (`clone; vars={"node": "nodeN"};
ExpandGroupsWithVars[Tagged]; read the expanded AST`) was hand-copied
into twelve gate files (compiler_interfaces_qinq.go,
compiler_interfaces_vlanmap.go, compiler_interfaces_vlan_tagging.go,
compiler_system_login_gates.go, zoneid.go, tunnelid.go,
routinginstanceid.go, compiler_interface_unit_alias.go,
dup_names_expanded_6455.go, compiler_scheduler_window_pairs_11358.go,
compiler_validate_strict_reth_lag.go,
bridgedomain_kernel_name_16792.go).
The #13146 raw-tree fallback reached only two copies (vlan-map,
vlan-tagging): when a group is literally named `"${node}"`, neither
per-node expansion succeeds, so the QinQ (#5879), packed-login (#6662)
and login-class-shadow (#6701) gates inspected no view at all, while
the generic (standalone) compile compiled the top-level tree — a
strict-commit fail-open, including silently dropping an RBAC
`deny-commands` narrowing.

Verified live on origin/master a0e82e205f before fixing with a
temporary probe (since removed): direct strict calls returned nil for
qinq-litnode, login-shadow-litnode, login-packed-litnode and
deny-litnode, while the plain controls rejected and vlanmap-litnode
rejected (the copy that already had the fallback).

## Fix

New `pkg/config/gate_node_views.go` is the single source of truth:

- `effectiveNodeViews(tree, opts)` returns the node0 and node1 views
  and, when `Fallback` is set and neither expands, the generic-compile
  fallback tree (`ExpandGroupsNodeFallback15031`). `Tagged` selects
  the tagged expansion; `ExpandRanges` opts into
  `expandInterfaceRanges`. Gates that keep their own View-1
  pre-expansion union (zone, tunnel, routing-instance, unit-alias,
  dup-name, bridge-domain, reth-LAG) leave `Fallback` unset — their
  View 1 already covers an un-expandable group. The scheduler gate
  keeps its Tagged expansion without the fallback, unchanged.
- `effectiveNodeViewsForNodes` additionally folds in the generic view
  and an arbitrary compiledNode's own view (routing-instance,
  bridge-domain unions, which always inspected those).
- `gateNodeView` is the single-node form (zone, tunnel, dup-name).
- `interfaceUnitsOf(iface)` = `namedInstances(packedBody-or-self(iface)
  .FindChildren("unit"))`, now used by all three VLAN collectors
  (QinQ, vlan-map, vlan-tagging — the last previously walked the raw
  interface, missing packed tails).

All twelve prologue copies migrated; no new copy of the pattern.
