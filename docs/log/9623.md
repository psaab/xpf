# #9623: HA publishes display-escaped IPsec SA names

- **Timestamp**: 2026-09-11T03:26Z
- **Action**: created worktree `/var/tmp/wt-9623-ipsec-name-display` on origin/master
  3d81b3703 (branch `fix/9623-ipsec-name-display-safe`).
- **Action**: research.
  - `GetSAStatus` display-sanitizes every SAStatus field with
    `termsafe.SanitizeForDisplay` (#6584). That escapes Cc control runes (C0, DEL and
    C1), U+2028/U+2029 and invalid UTF-8.
  - The renderer's `sanitizeSwanctlValue` (`rendersafe.ReplaceControlBytes`) replaces
    only C0 and DEL.
  - The #1798 free-text gate (`hasControlChars`) rejects only C0 and DEL bytes, across
    ALL config values.
  - `termsafe.DisplaySafe(name)` is exactly "the display spelling equals the raw one".
  - Traffic-selector names do not reach SA identifiers raw: `sanitizeChildName` maps
    every rune outside [A-Za-z0-9._-] to '-'. Gateway names reach no swanctl
    identifier (the only name-built one is `ike-<vpn>`). So only VPN names matter.
  - `pkg/termsafe` has no xpf dependencies, so `pkg/config` can import it without a
    cycle.
- **Action**: sweep. No shipped `.conf`/`.set` file in the repo carries an IPsec VPN.
  The only non-doc match is a spelling-gate word list. The new gate therefore changes
  only the acceptance of pathological VPN names.
- **Action**: DECISION, the issue's option 1. Reject at commit (strict) and warn on the
  tolerant load / peer-sync path. The alternatives were rejected:
  - Widening the #1798 gate globally would change the meaning of every free-text value
    (descriptions and so on).
  - Option 2, a raw operational name in SAStatus, would carry a raw spelling that a later
    renderer could print, reopening the #6584 terminal-injection class.
- **Action**: implementation.
  - `validateIPsecSANamesDisplaySafeStrict`: sorted VPN names; reject when
    `!termsafe.DisplaySafe`; the message names the VPN (%q-quoted) and says why.
  - Registered in `runUniformGatesIPsecEvent` after the manual-key gate, with the
    strict/lenient pattern and a new `lenientIPsecSANameDisplay` opt set on the tolerant
    path.
  - `TerminateAllSAs`' name selection is split into `terminateIKENames` (behaviour
    unchanged, mirroring `activeSANames`), so both acceptance cells can drive the real
    parse and sanitize pipeline.
  - **File(s)**: `pkg/config/compiler_validate_strict_ipsec_sa_name_9623.go` (new),
    `pkg/config/compiler_uniformgates_ipsec_event.go`, `pkg/config/compiler_opts.go`,
    `pkg/ipsec/ike.go`
- **Action**: cells.
  - `TestIPsecVPNNameMustBeDisplaySafe9623` (pkg/config). Commit rejects a VPN name with
    C1 CSI, U+2028, U+2029 or invalid UTF-8, and accepts U+202E and a plain name. The
    tolerant path warns for the rejected names, and always keeps the VPN under its exact
    name.
  - `TestPublishedAndTerminatedSANamesMatchTheRenderOnlyWhenDisplaySafe9623` (pkg/ipsec).
    Through `parseSAOutput` and `sanitizeSAStatus`, `activeSANames` and
    `terminateIKENames` equal the raw rendered name exactly when DisplaySafe holds.
  - Rune literals are ASCII `\uXXXX` escapes, so the source carries no invisible or
    bidi characters.

    0 failed.
