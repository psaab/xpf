# #15120 — Container-form application term: header tokens packed beside term name silently discarded (A86-01)

## Defect
- `pkg/config/compiler_applications.go` `expandContainerTerm14340` (residual
  of #14340): built `&Node{Keys: []string{"term", sub.Keys[0]}}`, so
  `sub.Keys[1:]` — header tokens packed beside the term name — were discarded
  before `applicationTermKeys`/`parseApplicationTerms`.
- `term { t-ssh destination-port 22 { protocol tcp; } }` therefore compiled
  strict-clean as TCP on any port, with no warning and no
  `ApplicationMatchDrops` entry. The tokens never reached
  `UnknownTermLeaves`, so the #9595 check could not see them. A permit
  referencing the application admitted every TCP destination port instead
  of 22.

## Fix
- `expandContainerTerm14340`: carry the packed header through —
  `Keys: append([]string{"term"}, sub.Keys...)`. The fresh slice preserves
  the existing no-AST-aliasing property (`append` onto a fresh
  `[]string{"term"}`); children unchanged.
- Effect: recognized packed tokens compile (e.g. `destination-port 22`
  constrains the term), unrecognized packed tokens (`destination-poort`)
  land in `UnknownTermLeaves` and are refused by the #9595 strict gate
  naming the token (lenient path warns, #1960), and a dangling packed
  value-taking leaf (`destination-port` with no value) lands in
  `IncompleteTermLeaves` and is refused naming the leaf.
- Both consumers share the helper, so `compileApplications` and
  `applicationTermNodes` (collision gate via `collectApplicationCollisions`)
  stay in agreement on generated names and keys.
- NOT changed: canonical `term <name> { ... }` handling, flat-set chained
  terms, container expansion of named-only children (byte-identical keys
  when no packed header present).

## Tests
- New `TestApplicationContainerTermPackedHeaderTokens15120` in
  `pkg/config/compiler_application_specs_test.go` (5 subtests): packed
  destination-port honored (tcp/22), packed header inside a multi-child
  container with sibling unaffected, packed unknown token (strict reject
  naming `destination-poort` + lenient warn), packed dangling
  `destination-port` (strict reject naming it), canonical-term control.
