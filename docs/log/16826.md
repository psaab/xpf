# #16826 — #15176 NAT-scope fold drops the VLAN unit on both ends (R3-F10-01)

- **Timestamp**: 2026-10-25
  - **Action**: HA-imported sessions on a tagged RETH unit were revalidated against the parent's interface/RI scope and revoked as StaleSourceNat on their first hit on the new primary. Sender: `stampNatScopeFold` folded the logical child ifindex (`ge-0-0-2.80`) with vlan 0, truncating to `reth0`. Receiver: `fillSessionSyncValue` kept only the resolver's parent ifindex and discarded the VLAN. Fix folds the NAT scope as the (parent physical, VLAN) pair — the daemon's new `buildNatScopeFoldFn` maps the logical ifindex (kernel VLAN child, or the synthetic logical-only index via the exported `SyntheticLogicalIfindexForUnit`) to its pair and is wired through `SessionSync.SetNatScopeFoldFn` at apply/seed/link-refresh only when a tagged RETH unit exists, so other configs keep the legacy vlan-0 fold bit-identically — and on import maps fold -> (parent, VLAN) -> the logical unit ifindex through the current snapshot (`logicalIfindexForParentVLANLocked`), leaving the scope unset when no logical row names the pair. NOT changed: the wire format (same `NatScopeFold` field), admission, or Rust revalidation semantics.
