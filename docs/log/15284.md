# #15284 — DisableAutoSaveHistory breaks in-memory recall

- **Base**: `e480baa5a4` (origin/master at branch start)
- **Branch**: `fix/15284-campaign`

## Why

`cliterm.DisableReadlineHistoryAutoSave` set readline's
`DisableAutoSaveHistory=true` (for #10743: keep credential lines off disk).
In chzyer/readline v1.5.1 that flag is not persistence-only: the CharEnter
arm in `operation.go` skips `history.New(data)` entirely when it is set, and
`New()` is the only path that commits the submitted line into the in-memory
history list (dedup, empty-line handling, push of the next editing slot) as
well as appending to the history file via `Update`. Consequences, reproduced
with the original wiring (seeded file, submit `show clock`, Up):
Up recalled `show interfaces` — the last seeded entry, not the command just
run; a duplicate submit then recalled an empty editing slot; Ctrl-D on that
manufactured empty line emitted EOF/`exit`. No new command ever persisted.

readline v1.5.1 exposes no History interface and no save-filter hook:
`Config` offers only `HistoryFile`, `HistoryLimit`, `DisableAutoSaveHistory`,
plus `Instance.SaveHistory` (which routes through the same `history.New`).
`historyUpdatePath` loads the file itself and `Update` writes whenever the
history fd is non-nil — so a filter cannot live inside readline.

## What

- `pkg/cliterm.ConfigureReadlineHistory` replaces
  `DisableReadlineHistoryAutoSave` (deleted, both callers migrated): keeps the
  in-memory commit enabled (`DisableAutoSaveHistory=false`) but clears
  `HistoryFile`, so `Update`'s fd write is a no-op and readline never touches
  disk. `HistoryLimit` is caller-supplied and must stay large: it also bounds
  the in-memory list via `Compact()`, and a limit of 1 reproduces the same
  submit→Up=="" symptom by a second mechanism (verified empirically).
- Persistence is explicit and filtered in `pkg/cliterm`:
  `ReadHistorySeed` (missing file = empty seed; also drops any pre-#15284
  credential line a legacy file may contain so it is never seeded back),
  `SeedHistory` (replays the seed via `SaveHistory`/`history.New`, restoring
  dedup/current bookkeeping), `RecordHistoryLine` (appends non-empty,
  non-sensitive lines; bounds the file at 10000 lines with a same-dir
  temp+rename rewrite; 0600 preserved), and `IsSensitiveHistoryLine`.
  Sensitive lines stay recallable in-memory for the session (recall is not
  disclosure) but never reach disk — #10743's intent.
- `IsSensitiveHistoryLine` mirrors the secret-leaf keyword list in
  `pkg/config/ast_redact.go` (`secretIndices`) on flat CLI tokens, with two
  documented fail-closed differences: bare `password`/`secret` tokens are
  sensitive anywhere (no ancestor path exists on a flat line), and
  `community` stays gated on an `snmp` predecessor; `key` stays gated on
  `authentication md5 <id> key`.
- Both surfaces wired identically: `pkg/cli/cli.go` (`~/.xpf_history`, main
  loop records every submitted line including `load terminal` paste lines —
  pre-#15284 behaviour, since each Readline return was autosaved then) and
  `cmd/cli/main.go` (`~/.xpf_cli_history`). One-shot `-c` mode never reaches
  the interactive history path on either surface.
- Residual: `ReadHistorySeed`+append is unsynchronised across two CLI
  processes sharing one `$HOME` (same as readline's own appends); worst case
  is a lost/duplicated history line. The sensitive filter is checked
  in-process on the submitted line, so a race can never write a credential.

## Validation

- Mechanism RED probe (original wiring, seeded file): submit `show clock`
  then Up recalled `show interfaces` (not `show clock`); file unchanged —
  defect reproduced exactly as the issue describes.
- GREEN: `go test ./pkg/cliterm/ -count=1` — recall regression
  (seeded submit/dup/empty → Up recalls the submitted command, never the
  empty slot), cross-session persistence (record → seed → Up recall),
  PSK-never-on-disk with in-memory recall + 0600 mode (#10743/#10908
  successor test), sensitive/benign token table, and a both-surfaces
  shared-wiring source pin (`pkg/cli` + `cmd/cli`).
- `go vet ./pkg/cliterm/ ./pkg/cli/ ./cmd/cli/` clean; full `go test
  ./pkg/cli/ ./cmd/cli/` run for the final gate (see PR).

## Risk

History is advisory operator state. Failure directions are fail-closed for
credentials (over-suppression costs a history entry; the line still ran and
is still recallable in-session) and fail-visible for persistence (record
errors print a warning; the CLI loop is never broken by a history write).
EOF/Ctrl-D semantics are unchanged from readline's own: an empty line at
the prompt is the operator's Ctrl-D, not a manufactured slot.
