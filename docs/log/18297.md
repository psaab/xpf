## The two exhaustive literals

1. **Production converter** — `session_delta_info()` in
   `userspace-dp/src/afxdp/session_delta.rs` builds a `SessionDeltaInfo`
   enumerating every field mapped from the delta. Its exhaustiveness is the
   compile-time forcing function that a new `SessionDeltaInfo` field gets an
   explicit wire-mapping decision (the sibling `SessionSyncAttribution`
   destructure at the same site documents the same intent: *"EXHAUSTIVE on
   purpose — no `..`"*). Tailing it would silently default any future field —
   the #6949 failure shape, where the JSON leg carried none of the binary
   leg's attribution fields. This literal must stay exhaustive.
2. **#17142 populated specimen** — `session_delta_info_populated` in
   `userspace-dp/src/protocol/tests.rs` (added by PR #18193 for #17142)
   enumerates all 60 fields of the 60-field struct, each with a distinct
   sentinel. The Go cell `TestSessionDeltaPopulatedSpecimenValues17142`
   strict-decodes the regenerated fixture and asserts every field by value,
   so any serde-rename transposition (the #17142 mutant C:
   `ingress_ifindex`/`nat_scope_ifindex` swap) reds with both values named.

## Disposition: raise the ceiling 1 -> 2 (reviewed table row)

`userspace-dp/src/protocol/cos_literal_guard_7689.rs`:
`("SessionDeltaInfo", 1)` -> `("SessionDeltaInfo", 2)`, with a `#18297`
comment at the row recording the justification below. This is the table's
first increase; the ratchet's direction is decrease-only by design, so the
increase is justified explicitly rather than treated as routine:

- Both literals are **intentionally** exhaustive, as established above.
  Neither is the accidental enumeration the #7689 tax describes (a literal
  that "does not care about the new field; it breaks only because it
  enumerates"). Both care about every field: the converter must map each
  one, the specimen must sentinel each one.
- The ceiling now holds **exactly** these two. A third exhaustive
  `SessionDeltaInfo` literal still reds the ratchet; no general permission
  is granted.

### Alternative considered and rejected: tail the specimen, keep ceiling 1

Adding `..Default::default()` to the specimen (dropping enumerated fields)
would serialize byte-identically **today**, because the specimen enumerates
every field. It was rejected because it silently destroys the specimen's
completeness property:

- With a tail, a **future** field added to `SessionDeltaInfo` compiles
  without touching the specimen, enters it at its `Default`, and is asserted
  by nobody: the Go value cell restates the sentinels it knows, so the new
  field passes undetected until someone extends both sides by hand — with
  no compile error anywhere reminding them. The exhaustive literal is the
  only forcing function that keeps the sentinel census complete.
- The rename-transposition detection itself would survive a tail today
  (every current field keeps its sentinel), but the guarantee that the
  census covers **all** fields would not. Keeping the ceiling at 1 by
  tailing would trade a visible, reviewed ceiling row for an invisible
  future blind spot.

The production literal was never a candidate for tailing (see above).
