# Issue #16031 action log

- **Timestamp**: 2026-10-23
  - **Action**: Removed the legacy method-only fabric stream fallback and
    added continuous fabric-stream re-auth. Fabric `MonitorInterface`
    streams must now carry the #11082 args-bound token matching the request;
    a missing or mismatched token is rejected `Unauthenticated` (previously
    a missing token was only counted via `fabricStreamArgsUnboundTotal`).
    The counter, its `FabricStreamArgsUnboundTotal` accessor, the
    `xpf_fabric_stream_args_unbound_total` Prometheus descriptor and its
    collector wiring are deleted. Local loopback streams keep working via
    the server-side #13050 fabric-context marker (never client metadata).
    Decision basis: #16031 directs the sunset once the #11524 sunset lands
    and #11524's record shows both live peers already args-binding with the
    counter at zero; current peers always mint the args-bound token
    (`proxyMonitorInterface`).
  - **Action**: `fabricAuthStreamInterceptor` now runs the handler under
    `reauthFabricStream`: every 5s (`fabricStreamReauthInterval`, mirroring
    the primary listener's #9051 tick) the stream's connection token is
    re-verified against the live accepted-key set (`fabricStreamRecheck` →
    `checkFabricAuth`). Removing the PSK entirely ends an open fabric
    stream within one tick with `Unauthenticated`; a rotation still
    accepting the minting key (#6630) does not interrupt it. Revocation
    wins over a co-present handler error (#9903 F-128 ordering).
