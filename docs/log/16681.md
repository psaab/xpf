# 16681 — NAT64 show: render full scope on both CLIs via shared natshow renderer

- **Timestamp**: 2026-10-25
- **Action**: Neither NAT64 show renderer printed a rule-set's
  `SourceAddresses`/`SourceAddressNames`, and the gRPC ShowText renderer
  used by the remote CLI also omitted `FromZones`/`FromRoutingInstances`
  (#15932/#16049 had updated only the local copy), so a scoped rule-set
  displayed as if it applied to every source (both CLIs) and every zone
  or routing-instance (remote CLI). NAT64 rendering moved into
  `pkg/natshow.RenderNAT64` (new `pkg/natshow/nat64.go`), used by both
  `pkg/cli` (`showNAT64`) and `pkg/grpcapi` (`showNAT64`), printing
  Prefix, From zones, From routing-instances, Source addresses, Source
  address-names and Source pool — each union falling back to its singular
  back-compat field when the plural list is empty, with the #16604
  explicit-master routing-instance member (`""`) still rendering as
  `default` (on a copy, so the caller's slice is no longer mutated as the
  old local renderer did). The #16547 NOT INSTALLED verdict is preserved
  with config-pool precedence over the applied snapshot's runtime verdict,
  now passed in as `natshow.RuntimeVerdicts` keyed by rule-set name (nil =
  config-only). The canonical empty message is the gRPC form
  `No NAT64 rule-sets configured` (no trailing period); the local CLI's
  historical trailing period is dropped so both consumers emit identical
  bytes, as with the other #1687 extractions. Enforcement is unchanged.

  `pkg/cli/cli_show_nat.go`, `pkg/grpcapi/server_show_nat.go`,
