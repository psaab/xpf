# #13711 — preserve per-session counter-query replies under queue pressure

- **Timestamp**: 2026-10-15
- **Initial base**: `0619f0061` (original regression baseline)
- **Follow-up base**: `2cae7b02` (master containing merged PR #13869)
- **Follow-up branch**: `fix/13711-reply-race`
- **Files**: query handling, worker command reply publication, and regression tests

## Defect and change

`kick_session_counter_query` now records refused worker IDs as unanswered
without putting them in the wait set, so a command that was never queued does
not impose the three-second timeout.

Each queued command now owns a separate reply slot. The earlier exact-sequence
check on one shared slot avoided a stale acknowledgement but did not make its
six payload fields safe: a worker could begin publishing a later answer after
the reader matched the older sequence. The worker now publishes the complete
snapshot into the command's own slot, and the waiter reads only that slot.
Overlapping queries can neither overwrite nor tear one another's answers.

## Risk

Each request allocates one shared reply slot per queued worker and uses a
short mutex-protected snapshot publication. A worker that never publishes
still reports unanswered at the existing three-second deadline.
