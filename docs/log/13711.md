# #13711 — preserve per-session counter-query replies under queue pressure

- **Timestamp**: 2026-10-15
- **Base**: `0619f0061` (origin/master when the worktree was created)

## Defect and change

`kick_session_counter_query` discarded `push_bounded`'s refusal, then retained
that worker's atomics in its wait set. A command that was never queued could
therefore impose the whole three-second timeout. The wait also accepted any
published sequence greater than its own and read one shared reply slot, so a
later session query could be reported as an earlier query's answer.

The kick now records refused worker IDs as unanswered without putting them in
the wait set. The reader accepts only its exact sequence; when a later sequence
has overwritten the single response slot, it reports the earlier request as
unanswered without reading the other session's counters. Dead-worker reporting
is unchanged.

## Risk

When a later query overwrites the per-worker response slot before an earlier
wait reads it, the earlier query is explicitly marked unanswered rather than
misattributed. This preserves integrity while retaining the existing
single-slot design and bounded wait behavior.
