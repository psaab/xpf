# #12055 — drop tagged-only VID-0 local destinations in the XDP shim

## Why

The worker's tagged-only VID-0 guard is too late for local destinations: the XDP shim can return those packets to the kernel before the worker sees them. On a trunk whose configured units are tagged-only, untagged or priority-tagged VID-0 traffic to a firewall-local address therefore bypasses the intended denial.

## What

The existing `userspace_ingress_ifaces` byte now carries two flags: bit 0 remains the adjudicated-ingress flag and bit 1 marks VID-0 scope on tagged-only bind parents/children. Go mirrors the worker's tagged child, explicit unit-0, and native-VLAN ownership decisions when publishing the map. The shim drops local-destination VID-0 IPv4/IPv6 traffic on flagged ingress before healthy or degraded local-delivery paths and counts `tagged_only_local_drop`; the Go and Rust reason-name tables and map consumers were updated for the bitfield. Tagged traffic and ordinary untagged ingress retain their prior local-delivery behavior. The build recipe also honors `CARGO_TARGET_DIR` when resolving its verifier-gated candidate path, preserving verify-before-install while using the lane's isolated Cargo cache.
