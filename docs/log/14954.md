# #14954 — GRE inner fragments, declared lengths, inner LAND (D21-01)

## Defect
`classify_native_gre_inner*` in the XDP shim built a session key from
the GRE INNER packet and, on a session/DNAT/local hit, steered the
OUTER frame (kernel on PASS_TO_KERNEL, helper on REDIRECT) without
the inner being adjudicated. It ignored inner IPv4 fragmentation,
never consulted the inner declared lengths (v4 Total Length / v6
Payload Length), and never compared inner src/dst — so fragment
payload bytes could supply ports, slack past the declared end could
supply an L4 span, and an inner LAND packet could ride a PASS hit to
the kernel decapsulated unscreened. Separately,
`walk_ipv6_ext_headers` reset `fragment_seen` on every atomic
Fragment header, so a `[non-atomic][atomic]` chain reported
whole-datagram.

## Fix
- `gre_classify::gre_inner_fragment_or_length_rejected` (host-executed,
  shared with the regression): fragment + declared-length verdict on
  inner-L3-relative offsets; subtraction-form comparison. The shim
  judges it before building the session key (v4: fragment field
  `& 0x3fff`, span TCP 14 / UDP·ICMP 8 / other 0, plus Total-Length
  covers-header; v6: `payload_len == 0` jumbogram miss, span vs
  Payload Length; ext-header/fragment inners still bail via the
  #6886 terminal check).
- Inner LAND: direct `src == dst` comparison on the built key in
  both classifiers (outer LAND drops compare outer addresses only).
- v4 classifier reads tuple ports before building the key once with
  final fields (verifier stack/insn hygiene, no semantics change).
- `ipv6_ext_walk`: an atomic Fragment header clears `fragment_seen`
  only when it is the first Fragment header sighted.
