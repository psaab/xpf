# Issue #15713: inline `inactive:` governing a braced sub-block

- **Timestamp**: 2026-10-19
- **Problem**: `Parser.parseStatement` (`pkg/config/parser.go`) truncated `keys` to `keys[:i]` at an inline `inactive:` marker and, when `{` followed, set `Inactive=true` on the truncated outer node. For `ge-0/0/0.0 inactive: host-inbound-traffic { system-services { ping; } }` and `unit 0 inactive: family inet6 { address ...; }`, the governed sub-block keys (`host-inbound-traffic`, `family inet6`) were discarded, its children were re-parented directly under the outer node, and the outer node was hoisted inactive. `WithoutInactive`/compile then stripped the entire active interface/unit/neighbor, and `FormatSet` emitted a `deactivate` for the outer path instead of only the sub-block.
- **Fix**: In `parseStatement`, when a bare inline `inactive:` at `0 < i < len(keys)-1` is followed by `TokenLBrace`, preserve `keys[i+1:]` (with `kinds[i+1:]`/`bracketed[i+1:]` provenance) as `governedSubKeys`, truncate the outer keys to `keys[:i]` without hoisting `Inactive`, parse the braced body, and attach it as the children of an inner `&Node{Keys: governedSubKeys, Inactive: true}` that is the sole child of the active outer container. The inner node's quoted/bracketed provenance is derived from the governed kinds/bracketed slices. Only this mechanism is changed: a marker immediately before `{` (`i == len(keys)-1`) still deactivates the whole outer block, an inline marker on a leaf still drops its governed tail, a leading `inactive:` still lifts onto the whole statement, and a quoted `"inactive:"` still is not a marker.
- **Not changed**: `WithoutInactive`, `Format`, `FormatSet`, compilers, and `LoadMerge` are untouched — they already prune/render an inactive child correctly once the parser nests it correctly.

## RED -> GREEN proof

- **RED** (pre-fix, tests present): `go test ./pkg/config/ -run 'TestInlineInactiveGoverned|TestInlineInactiveMarkerAtEnd|TestInlineInactiveLeafTail' -v -count=1` failed — `TestInlineInactiveGovernedBlock15713: outer ge-0/0/0.0 hoisted Inactive=true; want active` and `TestInlineInactiveGovernedMultiKeyBlock15713: outer unit 0 hoisted Inactive`; the two neighbour guards passed.
- **GREEN**: The same tests plus `TestInlineInactive|TestInactive|TestParser|QuotedInactive|TestFormatSetInactive` pass after the fix. The governed tests assert the outer node stays active with the governed keys as its sole inactive child, `WithoutInactive` keeps the outer and prunes only the sub-block, `FormatSet` emits `deactivate ... host-inbound-traffic` / `deactivate ... family inet6` and never deactivates the outer path, and hierarchical `Format` round-trips the nesting.
