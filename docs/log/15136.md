## Mechanism (verified at base 6258721ef8)

`pkg/config/schema_routing.go`: the OSPFv3 `interface` children were
passive/cost/hello/dead/retransmit/priority/bfd only, and OSPFv2
`virtual-link` had only `transit-area`. The OSPFv3 compiler switch
(`compiler_protocols.go`) has no auth case and `OSPFv3Interface` has no
auth field; the virtual-link compiler reads only `transit-area` and
`OSPFVirtualLink` has no auth field. FRR renders no
`ipv6 ospf6 authentication` and a bare `area A virtual-link R`. So
`set protocols ospf3 area 0.0.0.0 interface ge-0/0/0.0 ipsec-sa sa1`,
`... authentication { md5 1 { key "..."; } }`, `authentication-key`,
`authentication-type`, `keychain`, and the five virtual-link twins all
committed clean and left the adjacency / virtual link unauthenticated
while `show configuration` echoed the auth as protection — the #8443
fail-open residual (#8443/#14402 gated only the OSPFv2 interface node).

Junos grammar (vendor docs): OSPFv3 is protected only by a manual IPsec
SA (`interface ... ipsec-sa <name>`) and shares the
`authentication { md5|simple-password|keychain }` block at the
interface/virtual-link hierarchy; OSPFv2 virtual links accept
`authentication { ... }`, `authentication-key`, `authentication-type`,
`ipsec-sa` and `keychain` beside `transit-area`.
