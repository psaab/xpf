# #16675 — first-commit rollback restores a non-fxp0 lifeline's kernel name

- **Timestamp**: 2026-10-25
- **Action**: Bootstrap exit renames a non-index-0 foreign-host lifeline
  positionally (`enp6s0` → `ge-0-0-0`, writing `10-xpf-ge-0-0-0.link` with
  `OriginalName=enp6s0`), but the first-commit rollback removed only the
  takeover `.network` files and kept every `.link`, so the NIC stayed
  renamed with no matching config — the host's own kernel-name-keyed
  netplan/networkd config (`[Match] Name=enp6s0`) never matched again, on
  every reboot, while the rollback logged success. Console-only lockout
  on exactly the event `commit confirmed` exists to survive.
  Fix (`pkg/daemon/bootstrap.go`, `daemon_run_naming.go`, `daemon.go`):
  before bootstrap-exit naming runs, `captureBootstrapLifelineRenamePreExit`
  records the lifeline's pre-takeover kernel name and the positional
  logical name it will receive (same `assignName` derivation; positional
  mode only — device-map never claims an unmapped lifeline, and index-0
  renames to fxp0 which the existing `.network` restore already covers).
  The pair rides in the generation-bound durable snapshot record
  (`LifelineKernelName`/`LifelineLogicalName`) alongside the #12154/#14993
  network bytes, so it survives a daemon restart inside the window. On
  the first-commit teardown only (`restoreLifeline=true`, the recorded
  `confirmPrevFirst` scope), `restoreBootstrapLifelineRename` verifies
  the takeover `.link`'s `OriginalName=` against the captured kernel
  name, renames the NIC back, and only then removes the `.link`. It is
  fail-closed on provenance: a mismatched `.link`, or a logical-named
  lifeline with a `.link` but no captured pair, retains file + live name
  and reports DEGRADED rather than logging a clean rollback. A failed
  rename-back likewise retains the `.link` (rename-first ordering), so
  the retry debt is never destroyed. The general "renames persist"
  policy is unchanged for every other NIC.

  `pkg/daemon/daemon_run_naming.go`, `pkg/daemon/daemon.go`,

- **Validation**: `go vet ./pkg/daemon/` clean. New
  `bootstrap_lifeline_rename_rollback_16675_test.go` (5 tests): the
  witness flip (`.link` gone, `ge-0-0-0 -> enp6s0` issued, index-0 fxp0
  restore byte-identical), rename-failure retention, `.link`-mismatch
  retention, unprovenanced-`.link` fail-closed, and the capture table
  (non-index-0 records; index-0 / device-map / already-logical /
  not-enumerated record nothing). Existing 12154 teardown cells re-run
  green (see PR).
- **Risk**: Scoped to the first-commit rollback path; a later #9615
  safe-state entry on a committed box never renames back
  (`restoreLifeline=false` gate). MAC-form takeover `.link` files carry
  no `OriginalName=` and fail the provenance check closed (DEGRADED,
  retained) rather than guessing. The host-config re-match and reboot
  behaviour remain reasoned, not lab-run — same limit as the source
  finding.
