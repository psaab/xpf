# Issue #13149: Ignore administratively disabled interfaces in host-inbound state

The D3-03 finding showed that snapshot construction intentionally clears addresses for disabled interfaces, but host-inbound observability still interpreted those empty snapshots as addressless enforcing zones/interfaces. That could keep `HostInboundPendingIntentFromSnapshots` asserted indefinitely for a disabled DHCP interface and emit false addressless warnings. Config-derived address paths were inconsistent: VRRP VIPs and deterministic RETH link-locals were still added despite an administrative disable.

The host-inbound addressless reporters now exclude disabled interface snapshots and config interfaces from address/DHCP intent accounting, and do not report disabled zone members. Zone views, unzoned host-inbound address collection, stable RETH targets, and firewall-local address enumeration now omit addresses configured on disabled interfaces. Enabled DHCP interfaces continue to report pending intent.

Regression evidence: `TestDisabledInterfaceNoPendingOrVIPLeak13149` failed on the untouched issue worktree: `addressless zones = [{Zone:ctrl ...} {Zone:trust ...} {Zone:wan ...}]`, where trust and wan were administratively disabled. The regression now passes and asserts disabled static/DHCP interfaces do not latch pending state, disabled zoned and unzoned VRRP VIPs are omitted, and an enabled DHCP control still reports pending. `TestDisabledRethHasNoStableHostInboundLinkLocal13149` verifies disabled RETHs do not generate stable link-local targets while enabled RETHs retain them.
