# #12582 — REST census accepts value and option suffixes as commands

- **Timestamp**: 2026-10-13
- **Action**: Share the authorization-table pure-command-path predicate between REST and gRPC; apply it to REST mappings before canonicalization.
- **Base**: `fix/12582-campaign-pub` at `c94ed75eb`
- **Files**: `pkg/cmdtree/pure_path.go`, `pkg/api/authz_command_census_9952_test.go`, `pkg/grpcapi/authz_command_table_7172_test.go`, `pkg/grpcapi/authz_command_table_topics_7172_test.go`, `docs/log/12582.md`
- **Issue**: #12582

## Why

The REST census only called `cmdtree.Canonicalize`. That correctly accepts
operator-supplied values and option re-entry, so it also accepts table entries
that do not name argument-free command paths. Before the fix, both the reviewer
mutants (`show security flow session summary zone` and `show interfaces
zzbogus`) passed `TestEveryRESTRouteCommandResolves9952` and
`TestRESTAndGRPCChargeTheSameCommandForSharedData9952`.

## What

Moved the gRPC table's strict keyword walk into `cmdtree.EveryWordIsAKeyword`
and changed the gRPC method/topic checks and REST route census to use the same
predicate. A command table entry must resolve through exact tree keywords,
contain no value-slot/placeholder words, and end at a leaf if it reaches one;
this rejects option suffixes after a complete command without changing
`Canonicalize`'s intended operator-input behavior. The REST regression rows pin
both issue probes and a literal `<destination>` placeholder, alongside valid
paths. No current REST route mapping needed correction.

## Risk

Test-only authorization table validation and a shared predicate; no runtime
command canonicalization or authorization behavior changed. The predicate is
stricter only for static command-table entries, where values and suffixes are
not valid command paths.
