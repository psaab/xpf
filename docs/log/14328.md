# #14328 — WG kernel-path locality queried under the outer ingress domain

## Defect
`ShimMapsKernelPathView::destination_is_local` (`userspace-dp/src/afxdp/coordinator/wg_control/kernel_path.rs`)
resolved the routing domain for the INNER plaintext destination from the OUTER
UDP socket's pktinfo `ingress_ifindex` (`userspace_ingress_domains[outer]`),
and returned `false` immediately for `ingress_ifindex == None`. The outer
interface (underlay) and the `wgN` logical interface routinely live in
different routing instances, so:

- host-inbound inner traffic whose destination is local only in the tunnel's
  routing domain was misclassified as transit -> `DropDegradedTransit`
  (`rx_degraded_transit_drops`) on the `Uncovered` / degraded `Covered` /
  `Unknown` kernel path;
- inner transit whose destination happens to be local in the outer underlay
  domain was misclassified as local (it then meets nftables `hook input` and
  the #10302 forward fence, so this direction is defense-in-depth, not a
  policy bypass);
- with no pktinfo (`ingress_ifindex == None`), locality always read `false`,
  making `kernel_path_disposition(Unknown, true) == Deliver` unreachable,
  contradicting the module's own "no-pktinfo gets the same local-vs-transit
  disposition" contract.
## Fix
- `kernel_path.rs`: coverage and locality are now keyed on different
  interfaces, as documented in the module header. `ingress` still consumes
  the outer pktinfo ifindex. `destination_is_local(dst, tunnel_logical_ifindex)`
  takes the `wgN` logical ifindex (`spawned_logical_ifindex`, already in scope
  in `dispatch_inbound` and already stored on the view at construction in
  `wg_control_loop`). The domain is resolved by the new
  `tunnel_routing_domain` helper: an `ingress_domains` row keyed on the
  tunnel's own logical ifindex wins when present; otherwise the runtime
  forwarding state's `synced_routing_domain_in(forwarding,
  tunnel_logical_ifindex, 0)` answers (the tunnel row's `routing_domain`, the
  same resolver the TUN-origin builder uses). The local maps are then queried
  under that domain only. The production bpffs path no longer looks up
  `ingress_domains` to key locality (Go never populates a tunnel row there —
- Resolution choice (noted per the interface contract): the issue's "Pass the
  wgN tunnel's spawned_logical_ifindex (or its resolved inner routing_domain
  from forwarding)" offers two shapes. This picks tunnel-ifindex-at-the-seam
  plus domain-resolution-inside-the-view, because (a) the view is already
  per-tunnel state constructed with the runtime reader, (b) resolving inside
  the view keeps ONE resolver for production and test seam, and (c) Go fills
  `userspace_ingress_domains` per ingress-adjudicated ifindex and excludes
  tunnel interfaces from that set (`userspaceSkipsIngressInterface`,
  `buildUserspaceIngressIfindexes`), so a production `wgN` row in
  `ingress_domains` is normally absent — `ingress_domains[wgN]` alone could
  never work in production; the forwarding state is the store that carries
  the tunnel's domain for every interface. The map-first precedence exists
  so the test seam can state a tunnel domain (its forwarding state is the
  single-instance default, which would otherwise collapse every test domain
  to 0); it never fires in production, where tunnel map rows are absent.
- Fail-closed preserved: non-positive tunnel ifindex, unresolvable domain,
  unreadable maps, unparseable inner destination, and interface-NAT
  destinations all still read as transit. No test-input special-casing.
- `dispatch.rs`: passes `spawned_logical_ifindex` (was `ingress_ifindex`) to
  `destination_is_local`. `ingress` call unchanged.
- Test impls migrated: `UncoveredKernelPathView`, `FixedKernelPathView9594`,
  and the `ShimMapsKernelPathView::new` callsite in `coordinator/tests.rs`
  (tunnel ifindex argument added; production spawn in `wg_control/mod.rs`
  passes `spawned_logical_ifindex`).

## Regression
- `kernel_path::tests::locality_uses_tunnel_domain_not_outer_ingress_14328` —
  the decisive regression from the issue: outer ifindex 10 in domain 1, `wg0`
  logical ifindex 20 in domain 2, `2001:db8::1` local only in domain 2.
  Asserts `destination_is_local` is `true` under the tunnel key (including
  the `Unknown`/no-pktinfo disposition delivering), `false` for an address
  local only in the outer domain, `false` for transit in both domains, and
  `false` for an unplaceable tunnel ifindex.
- `kernel_path::tests::tunnel_routing_domain_resolution_14328` —
  pins the resolver's precedence (a tunnel map row wins when present;
  otherwise the forwarding state answers), the single-instance domain-0
  contract, and fail-closed on non-positive ifindexes.
