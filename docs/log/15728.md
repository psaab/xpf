# Issue #15728: request system lifecycle/service verbs silently ignore trailing arguments; ISSU panics on nil readline

- **Timestamp**: 2026-10-19
- **Problem**: `request system reboot|halt|power-off|zeroize` in the local console (`pkg/cli/cli_request_system.go`) and the remote CLI (`cmd/cli/request.go`) switched only on the verb and ignored `args[1:]`/`args[2:]`, so `request system reboot in 10` or `halt at 23:00` prompted and then executed an immediate power action instead of rejecting the unconsumed scheduled/message tokens. The same verb-only pattern dropped trailing tokens for `software in-service-upgrade`, `dynamic-dns update|check`, and (local only) `configuration rescue save|delete` — the remote rescue handler already rejected them. Separately, `handleRequestSystemSoftware` dereferenced `c.rl.SetPrompt`/`c.rl.Readline` directly, panicking when `c.rl == nil` even though the `c.readLine` test seam was wired, unlike the nil-safe `confirmSystemAction` used by the other verbs.
- **Fix**: Every listed verb on both surfaces now returns `request system ... does not accept arguments ("...")` before prompting or invoking `consolePowerAction` / the zeroize wipe / `ForceSecondary` / the DDNS force fn / rescue save-delete / the `SystemAction` RPC, quoting the rejected tokens. `handleRequestSystemSoftware` now confirms via `confirmSystemAction()`, which is nil-`rl`-safe and honors `readLineFn`. Schedule syntax (`in`/`at`/`message`) is not implemented — it is rejected, never silently executed immediately.
- **Regression (RED→GREEN)**: New `pkg/cli/cli_request_system_test.go` (all seven trailing-arg spellings assert error + zero prompts + zero power/wipe actions; `handleRequestSystemSoftware` with `cluster != nil`, `rl == nil`, `readLine` wired asserts no panic, `no` cancels cleanly, `yes` reaches `ForceSecondary` and surfaces its no-live-peer error) and `cmd/cli/request_test.go` (all seven spellings assert error + zero `SystemAction` RPCs). RED pre-fix: remote dynamic-dns case returned nil and the local cases prompted/acted (and the nil-`rl` ISSU case panicked). GREEN post-fix with neighbouring 14152 journal, 5039 drain-report, non-TTY destructive-block, and 8597 parity tests.
- **Not changed**: Valid bare spellings, confirmation wording, journaling, drain reporting, and the command tree are untouched — no scheduling feature was added; unsupported trailing tokens are now an explicit error on both CLI surfaces.
