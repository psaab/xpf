# Issue #17241 — R4-Q23-06: VRRP virtual-address / WireGuard allowed-ips readers hand-rolled pre-#6714 copies

- **STEP-0 (live on origin/master @ a60e77bda3):** verified, not already fixed. `pkg/config/compiler_interfaces.go`: VRRP reader read `prop.Keys[1:]` + `child.Name()` (Keys[0] only) per child; WireGuard reader read `prop.Keys[1:]` + `vn.Keys[0]` only for `vn.IsLeaf` children. Direct probe on master: `virtual-address { 10.0.1.100/24 10.0.1.101/24; }` → `vips=[10.0.1.100/24]`; `allowed-ips { 10.0.0.0/8 192.168.0.0/16; }` → `allowed=[10.0.0.0/8]` (second value silently dropped, no warning, strict and lenient). Controls (one-per-child, bracket) compiled both values.
- **Fix:** both sites now single-source through `firewallMatchValues(prop)` (#6714 SSOT: leaf's own Keys[1:] plus EVERY key of each child, skipping empty tokens and a bare unquoted self-repeat on the leaf tail). No new reader/copy introduced. Downstream behaviour preserved: VRRP list still collapses via `DedupeVRRPVIPs`; WireGuard list still validated/deduped downstream (same-peer repeats pass, cross-peer exact-prefix duplicates reject). Both leaves are schema `args:1, multi:true, children:nil` with no per-value options, so the SSOT no-descend contract applies exactly (steelman in the issue refuted by schema).
  - Noted deliberate delta: neither old loop consulted child `Keys[1:]`, so a non-leaf child (e.g. `allowed-ips { 10.0.0.0/8 { } … }`) previously contributed nothing for WireGuard (IsLeaf guard) — now its sole key is kept, matching the firewall SSOT and the one-per-child spelling. A child key literally spelling the leaf name would now surface as a value token and fail the existing strict CIDR/prefix validators instead of being silently dropped — fail-closed, not fail-open.
  - System/chassis `multi:true` leaves are out of scope for a mechanical swap: none share this exact Keys[0]-only child-loop reader shape (they use dedicated readers with per-value options/keywords), so the acceptance table covers the two cited interface leaves plus the `virtual-inet6-address` sibling sharing the VRRP case arm.
