- **Fix:** both sites now single-source through `firewallMatchValues(prop)` (#6714 SSOT: leaf's own Keys[1:] plus EVERY key of each child, skipping empty tokens and a bare unquoted self-repeat on the leaf tail). No new reader/copy introduced. Both leaves are schema `args:1, multi:true, children:nil` with no per-value options, so the SSOT no-descend contract applies exactly (steelman in the issue refuted by schema).
  - Noted deliberate delta: neither old loop consulted child `Keys[1:]`, so a non-leaf child (e.g. `allowed-ips { 10.0.0.0/8 { } … }`) previously contributed nothing for WireGuard (IsLeaf guard) — now its sole key is kept, matching the firewall SSOT and the one-per-child spelling. A child key literally spelling the leaf name would now surface as a value token and fail the existing strict CIDR/prefix validators instead of being silently dropped — fail-closed, not fail-open.
  - System/chassis `multi:true` leaves are out of scope for a mechanical swap: none share this exact Keys[0]-only child-loop reader shape (they use dedicated readers with per-value options/keywords), so the acceptance table covers the two cited interface leaves plus the `virtual-inet6-address` sibling sharing the VRRP case arm.

Direct `CompileConfig` without the gate is NOT claimed to reject garbage VRRP tokens (its VIP path tolerates unparseable tokens by design); the pin is on the canonical sequence, which is the operator commit path.
