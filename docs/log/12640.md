# Issue #12640 — compile every duplicate to-zone block

## Why

`compilePolicies` used `FindChild("to-zone")` for each source-zone node. The parser
preserves repeated hierarchical blocks as sibling AST nodes, so
`from-zone { A { to-zone { B { ... } } to-zone { C { ... } } } }` compiled only
A->B and silently discarded the second pair, including its deny policy. The
strict policy prewalks used the same first-only lookup, so changing only the
compiler would also have allowed content in a newly compiled second pair to
bypass its matching validation gates.

## What

- Iterate all `FindChildren("to-zone")` siblings and append each destination
  pair in declaration order in the compiler, strict policy prewalks, and the
  empty-security-identity scope scan.
- Add regression coverage for both A->B permit and A->C deny pairs under both
  block orders, and reject unsupported `then permit application-services` in a
  second to-zone pair.
- No schema or runtime behavior was changed.

## Validation

- RED before the compiler fix: both pair-compilation tests compiled only one
  zone pair instead of two.
- GREEN after the compiler fix: the duplicate-pair tests passed.
- After aligning the strict walkers, `go test ./pkg/config -run '^TestDuplicateToZone' -count=1`
  passed, including the second-pair #3114 rejection.
- `gofmt -l` on all changed Go files produced no output. A production-source
  search found no remaining `FindChild("to-zone")` calls.
- The full config package suite still fails on unrelated existing failures:
  stale inventory census (`TestInventoryDropShapeMatchesTheLiveCensus8662`), API
  auth expiry expectations (`TestMultiLeafSelfRepeatIsRefused9027`,
  `TestLegitimatelyNamedObjectIsAccepted9029`, `TestElidedQuotedValueKeepsItsQuote8921`,
  `TestSystemConfigWebManagementEnhanced`, `TestSystemConfigSetSyntax`), and a
  routing-instance control (`TestPackedRoutingInstanceSurvives8787`); it timed
  out after 10 minutes in `TestSlotEscapeCoverage` (prior run timed out in
  `TestSlotEscapeSweep`). No failures referenced this change.

## Risk

Configurations with duplicate `to-zone` siblings now compile and validate every
authored pair; previously only the first sibling was represented and validated.
Pair order remains the source declaration order. No other policy behavior is
changed.
