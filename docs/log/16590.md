# #16590: disabled RETH units/interfaces excluded from VIP ownership

- **Timestamp**: 2026-10-25
- **Action**: #14575 residual on RETH. `Config.RethVIPsForRG` collected
  addresses from `ifc.Disable`/`unit.Disable` units without checking
  either flag, so a disabled reth unit's address stayed in the RG's VIP
  set: `directAddVIPs`/`directSendGARPs` installed and announced it when
  its link was up, and `checkVIPReadinessForConfig` gated every RG
  promotion on the disabled child's link state (cold boot left the RG
  unowned until peer-yield or the 2-minute degraded fallback). Fixed:
  - `pkg/config/reth_vips.go`: `RethVIPsForRG` skips a disabled
    interface and any disabled unit in both the tagged and untagged
    arms. Since install, GARP, takeover readiness and the ip-monitor
    probe source all derive from this one map, they all follow.
  - `pkg/vrrp/vrrp.go`: `CollectRethInstances` applies the same skip,
    so VRRP-backed and direct (`no-reth-vrrp`/`private-rg-election`)
    ownership can no longer disagree — a mode toggle cannot resurrect
    a disabled address as a VRRP VIP.
  - `pkg/dataplane/compiler_iface.go`: `ensureVLANSubInterface` gains a
    `disabled` parameter (resolved by `mapZoneInterface` from the
    interface/unit `Disable` flags). It never brings a disabled unit's
    child up: an existing UP child is best-effort brought down, a newly
    created child stays down, and enabled controls keep the previous
    bring-up behaviour (including the `errVLANBringUpFailed` /
    `errVLANCreateFailed` sentinels). New `vlanLinkSetDownSeam` in
    `compiler_iface_vlan_bringup_8122.go`; all existing
    `ensureVLANSubInterfaceFn` test stubs updated to the new signature.
  - Acceptance: the `disable-unit80=true` arm is ready with
    `ge-0-0-2.80` absent; the untagged disabled arms give an empty map;
    the enabled control is unchanged.
