# #15070 - DHCP clients dead after terminal exit until unrelated config apply (A39-03)

- **Timestamp**: 2026-10-18
- **Action**: `runDHCPv6` returned when the 30 s `waitLinkLocal` timed
  out, and `runDHCPv4` returned when `retransmission-attempt` was
  exhausted. `finishClient` (#1793) deregistered the dead client, but
  nothing restarted a desired client: `Start` is only driven by
  `Reconcile`/`Renew`, and the daemon link subscription feeds SNMP
  only. A firewall booting faster than its ONT/modem lost DHCPv6 (WAN
  IPv6 + delegated LAN prefix) — and a v4 client whose server was
  briefly unreachable lost IPv4 — until an unrelated commit/apply.
  Both run loops now self-recover in place rather than via a manager
  supervisor (which would need desired-state tracking and a restart
  timer racing `finishClient`/`StopAll`): v6 loops the link-local wait
  with a ctx-bound `terminalRetryBackoff` (30 s, `m.after` seam)
  between attempts; v4, on hitting the attempt cap, paces the same
  backoff (still bounded by a pending held lease's `expiryDone`),
  resets `attempt`/`backoff`, and re-enters INIT. The per-cycle
  DISCOVER-burst bound of `retransmission-attempt` is preserved.
  Cancellation terminates both promptly. New shared constant
  `terminalRetryBackoff` sits beside `reacquireBackstop` in
  `commit.go`. NOT changed: manager registry/`Start`/`Reconcile`
  semantics, renewal/rebind paths, exchange wire behaviour, or any
  config schema — no supervisor goroutine was added.
- **File(s)**: `pkg/dhcp/dhcpv6.go`, `pkg/dhcp/dhcpv4.go`,
  `pkg/dhcp/commit.go`, `pkg/dhcp/retry_after_terminal_15070_test.go`
  (new), `pkg/dhcp/README.md`, `docs/log/15070.md`
- **Validation**: RED on master (`e210817d0d`): v6 test saw exactly 1
  `waitLinkLocal` call and 0 exchanges; v4 test saw exactly 2
  exchanges and returned at the attempt cap. GREEN after fix: v6
  re-waits (≥2 waits, ≥1 Solicit, lease committed), v4 runs 2 failed
  DISCOVERs + post-backoff DISCOVER + lease, with ≥2 `after`-paced
  waits (retry + recovery) pinning anti-storm pacing. Control cell:
  cancel during the v6 retry pause terminates with 0 exchanges.
  Neighbour controls: full `pkg/dhcp` suite, `go vet`, `gofmt` run by
  the lane; full-repo suites are the parent's gate.
- **Risk**: A desired client whose link/server never appears now logs
  a retry warning every ~30 s (v6: plus each 30 s wait) instead of
  once — the intended self-healing trade-off, ctx-bound so
  deconfiguration is prompt. The v6 wait retains its fixed 30 s
  timeout argument per cycle (unchanged wire/poll behaviour).
