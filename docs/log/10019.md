# 10019 — Config-mode status uses one view-tier authorization contract

- **Timestamp**: 2026-09-17
- **Branch**: `fix/10019-authz-tier`
- **Issue**: `api: identical config-mode facts require PermView over REST but PermConfig over gRPC`
- **Code commit**: `c61f9b3f1` (`api: align config status authorization tiers (#10019)`)
- **File(s)**: `pkg/grpcapi/authz_methods.go`, `pkg/grpcapi/config_mode_status_authz_10019_test.go`, `pkg/api/config_status_authz_10019_test.go`

## Decision

`GET /api/v1/config/status` and gRPC `GetConfigModeStatus` return the same
three store facts: `InConfigMode`, `Dirty`, and `ConfirmPending`. The shared
contract is **PermView on both surfaces**.

The survey required by #10019 found no deliberate per-surface exception:

| Surface | Neighboring read-only status methods | Neighboring config mutations |
| --- | --- | --- |
| REST | Every `/api/v1` safe read in `restReadPermissions` is `PermView`; `TestReadRoutesAreAllViewTier_6660` pins that policy. | `/config/enter`, `/config/exit`, set/delete/load/commit/rollback are `PermConfig`. |
| gRPC | `GetStatus`, `GetSystemInfo`, and the operational status RPCs have `PermView` entries. Config-render RPCs have coarse `PermView` entries, with candidate-target/compare requests additionally charged `PermConfig` by the dedicated candidate-read gate. `GetConfigModeStatus` is canonicalized as `show version`; the CLI prices `show` at `PermView`. | `EnterConfigure`, `ExitConfigure`, Set/Delete/Load/Commit/CommitCheck/CommitConfirmed/ConfirmCommit/Rollback are `PermConfig`. |

The gRPC `PermConfig` row was grouped with config lifecycle methods even
though the RPC is a read-only operational status query. It also violated the
method-table invariant that entries mirror the CLI command's required
permission. Tightening REST would break view-only status consumers and the
explicit all-safe-reads-are-view contract. Leaving the mismatch would make
the same facts depend on transport. Moving the gRPC row into the operational
show group and changing it to `PermView` is therefore the least-privilege
choice without introducing a fail-open disclosure: these facts already serve
at `PermView` over REST; neighboring status methods and coarse config-render
entries use that tier on gRPC as well, while candidate-reading config-render
requests retain their additional `PermConfig` gate.

No other method tier changed. Ignoring whitespace-only alignment, the
production diff contains exactly one deletion of
`GetConfigModeStatus: PermConfig` and one addition of
`GetConfigModeStatus: PermView`; the existing method-descriptor completeness
checks remain in place.

## Regression pins and RED / GREEN proof

### REST cells

`TestConfigStatusRouteCostsView_10019` pins the REST table entry, and
`TestReadOnlyServedConfigStatus_10019` sends a real GET through the production
listener as a `read-only` principal and checks all three JSON fact names.

To prove fail-on-revert, the route entry was temporarily changed to
`config.PermConfig` (not committed). The focused command:

```text
go test ./pkg/api -run 'Test(ConfigStatusRouteCostsView_10019|ReadOnlyServedConfigStatus_10019)$' -count=1
```

was RED in both cells:

- table cell: `GET /api/v1/config/status costs 3, want view`;
- served cell: the read-only caller received HTTP 403 instead of 200.

The entry was restored to `config.PermView`; the same command then passed:

```text
ok   github.com/psaab/xpf/pkg/api  0.014s
```

### gRPC cells

`TestGetConfigModeStatusCostsView_10019` pins the resolved
`methodPermission` result, and `TestViewTierServedConfigModeStatus_10019`
drives the production primary listener with read-only and operator clients.
A super-user first enters configure mode so the admitted calls must return a
live `InConfigMode=true` fact rather than merely avoid authorization denial.

To prove fail-on-revert, `GetConfigModeStatus` was temporarily changed back
to `config.PermConfig` (not committed). The focused command:

```text
go test ./pkg/grpcapi -run 'Test(GetConfigModeStatusCostsView_10019|ViewTierServedConfigModeStatus_10019)$' -count=1
```

was RED in all relevant cells:

- lookup cell: `GetConfigModeStatus costs configure, want view`;
- served read-only cell: `PermissionDenied` because the caller lacked
  `configure`;
- served operator cell: `PermissionDenied` because the caller lacked
  `configure`.

The entry was restored to `config.PermView`; the same command then passed:

```text
ok   github.com/psaab/xpf/pkg/grpcapi  0.023s
```

The full affected package suites also passed after restoration:
