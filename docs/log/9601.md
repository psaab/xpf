# #9601 — a MASTER-edge apply burst trips kea-dhcp4-server's start limit

- **Timestamp**: 2026-09-11
- **Action**: Recover a start-limited Kea unit with one `reset-failed` + restart before failing the apply
- **File(s)**: `pkg/dhcpserver/dhcpserver.go` (`reconcileFamilyRestart` -> `restartClearingStartLimit`), `pkg/dhcpserver/kea_start_limit_9601_test.go` (new), `pkg/dhcpserver/README.md`

## Code facts, re-read at origin/master 580d959e0

- `apply` restarts each configured family through `reconcileFamilyRestart` (`restartInactive || active || qerr != nil`). A restart error was returned as-is.
- There are three MASTER-edge appliers, all `ApplyAsync` with `restartInactive=true`, so every apply that survives the 1-slot mailbox restarts Kea:
  - `pkg/daemon/daemon_ha.go` `applyRethServicesForRG`;
  - the RG-transition path;
  - the legacy all-RG path.
- The #6535 converger re-drives through `ApplyAsync`, so its retry takes the same restart. systemd refuses a start past `StartLimitBurst` within `StartLimitIntervalSec` until the interval passes or `reset-failed` clears it. The issue measured exactly that refusal: `start-limit-hit` at 21:07:19, and the 21:07:20 retry failing with the same error.

## Change

`restartClearingStartLimit(svc)`:
1. restart;
2. on error, `reset-failed svc`, then restart once more;
3. if that also fails, return both errors joined.

It never loops, and one apply issues at most two restarts and one reset. The controller's own spacing (`applyRetryInterval` 30s) bounds how often a genuinely broken Kea is retried.

## Not established (left as the issue states it)

Why the converger logged no retry between 21:07:20 and 21:11:24. The candidate is still unverified: a later successful apply that did not restart the failed unit could have cleared `applyFailed`. A failed unit reads as not active, so a cluster-commit apply skips the restart. With this change the 21:07:20 retry would itself have recovered the unit, so the measured outage does not depend on that mechanism. It is recorded here rather than guessed at in code.
