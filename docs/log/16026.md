# #16026 — userspace-xdp steering PASS key loses source-zone identity on shared netdev (A1-C4)

- **Issue:** `UserspaceSessionKey` is a bare 5-tuple (no zone, ifindex or routing domain). A `PASS_TO_KERNEL` row published for one zone's peer-synced `LocalDelivery` session is honoured at the XDP shim for any packet presenting the same tuple. The normal cross-zone case dies in the nft host-inbound verdict (ingress-scoped, re-derives the zone from the netdev), but on a shared/ambiguous netdev — several logical units collapsed onto one ifindex — that derivation is impossible, the discarded zone is unrecoverable, and a same-tuple UDP packet arriving on the second zone's interface passes to the kernel into the HA peer-synced row.
- **Fix (helper, publish side):** `ForwardingState::has_multiple_zones` (built in `populate_zones` from the admitted zone set — nonzero, non-reserved, distinct ids — mirroring the `has_routing_domains` single-bool shape). `uses_kernel_local_session_map_entry` now also requires `!has_multiple_zones`, so on a multi-zone node a peer-synced LocalDelivery session is published `REDIRECT` instead of `PASS_TO_KERNEL` and is judged by the worker's `session_hit_authority` (#9519) by live arrival zone: foreign hits drop, owner hits are delivered through the worker's LocalDelivery path. Threaded through every publish callsite (`publish_session_map_entry_for_session{,_with_origin,_with_conntrack}`, `publish_worker_session_map_entry`, `force_live_redirect_for_worker_synced_entry`, `install_helper_local_session_on_miss` and their poll/shared/promote/local callers). Single-zone deployments are byte-identical. Same fail-safe direction as #9517: one extra helper hop for host-bound traffic on a multi-zone node, never a dropped packet.
- **Not taken (shim side):** Gating the shim's established PASS arm on a new `userspace_session_pass_zones` map was implemented and measured: even one extra outlined map probe on the PASS path pushes `xdp_userspace_prog` to the 1,000,001-insn verifier reject (the tracked object is already at the cap edge; every PASS call site re-walks the probe under its calling state). Reverted in full — no new shim map, no `.o` change.
- **Fold (PR #16360):** the publish-side flag alone leaves PASS rows already in the pinned map zoneless until their session ends on a single→multi-zone rotation. `demote_kernel_local_sessions_for_multiple_zones` (session_glue/revalidation.rs) now sweeps the worker's live peer-synced, non-reverse `LocalDelivery` sessions on that transition — captured worker-locally before `forwarding` is rotated (a worker that skipped generations still sees it), run after rotation beside the lo0 republish with `allow_replace_local` recomputed per session from the current HA state — and republishes each through `publish_worker_session_map_entry`, which writes `REDIRECT` under the new state. `publish_session_rows` migrates each entry's claims (new row before old release, #9560), so there is no no-row window. Demotion only; multi→single leaves REDIRECT rows until a natural republish. A stale PASS row left by a pre-fix *helper binary* (not a rotation of this one) is still reaped only on republish/expiry — the #9560 registry restores the survivor's action on release.
- **Tests:** `multiple_zones_demote_kernel_local_to_redirect_16026` (predicate pair: single-zone control passes, multi-zone demotes — deleting `!has_multiple_zones &&` reds only the second assertion), `the_worker_publish_reads_this_nodes_multiple_zones_flag_16026` (real worker publish path against the `SESSION_MAP_WRITES` recorder: single-zone writes PASS, multi-zone writes REDIRECT with no pre-delete), and `single_to_multi_zone_rotation_demotes_published_pass_16026` (real sweep over a table holding one peer-synced LocalDelivery entry: no-transition control writes nothing, transition republishes REDIRECT with no PASS). Pre-existing #9517 predicate/worker cells pass with the extra argument defaulted to single-zone.
- **Verification:** `cargo test --bin xpf-userspace-dp 16026` (3 cells, incl. fold), `9517` (9 cells) and `republish_local_delivery` pass; full userspace-dp suite and Go suites are the main agent's gate. No shim object change, so no `make generate` / verifier run is owed.
