# #16026 — userspace-xdp steering PASS key loses source-zone identity on shared netdev (A1-C4)

- **Issue:** `UserspaceSessionKey` is a bare 5-tuple (no zone, ifindex or routing domain). A `PASS_TO_KERNEL` row published for one zone's peer-synced `LocalDelivery` session is honoured at the XDP shim for any packet presenting the same tuple. The normal cross-zone case dies in the nft host-inbound verdict (ingress-scoped, re-derives the zone from the netdev), but on a shared/ambiguous netdev — several logical units collapsed onto one ifindex — that derivation is impossible, the discarded zone is unrecoverable, and a same-tuple UDP packet arriving on the second zone's interface passes to the kernel into the HA peer-synced row.
- **Fix (helper, publish side):** `ForwardingState::has_multiple_zones` (built in `populate_zones` from the admitted zone set — nonzero, non-reserved, distinct ids — mirroring the `has_routing_domains` single-bool shape). `uses_kernel_local_session_map_entry` now also requires `!has_multiple_zones`, so on a multi-zone node a peer-synced LocalDelivery session is published `REDIRECT` instead of `PASS_TO_KERNEL` and is judged by the worker's `session_hit_authority` (#9519) by live arrival zone: foreign hits drop, owner hits are delivered through the worker's LocalDelivery path. Threaded through every publish callsite (`publish_session_map_entry_for_session{,_with_origin,_with_conntrack}`, `publish_worker_session_map_entry`, `force_live_redirect_for_worker_synced_entry`, `install_helper_local_session_on_miss` and their poll/shared/promote/local callers). Single-zone deployments are byte-identical. Same fail-safe direction as #9517: one extra helper hop for host-bound traffic on a multi-zone node, never a dropped packet.
- **Not taken (shim side):** Gating the shim's established PASS arm on a new `userspace_session_pass_zones` map was implemented and measured: even one extra outlined map probe on the PASS path pushes `xdp_userspace_prog` to the 1,000,001-insn verifier reject (the tracked object is already at the cap edge; every PASS call site re-walks the probe under its calling state). Reverted in full — no new shim map, no `.o` change. The publish-side demotion covers every row the current helper writes; a stale PASS row left by a pre-fix helper in the pinned map is reaped when its session is republished or expires (the #9560 owner registry restores the survivor's action on release), and the worker still judges any redirected hit by arrival zone.
- **Tests:** `multiple_zones_demote_kernel_local_to_redirect_16026` (predicate pair: single-zone control passes, multi-zone demotes — deleting `!has_multiple_zones &&` reds only the second assertion) and `the_worker_publish_reads_this_nodes_multiple_zones_flag_16026` (real worker publish path against the `SESSION_MAP_WRITES` recorder: single-zone writes PASS, multi-zone writes REDIRECT with no pre-delete). Pre-existing #9517 predicate/worker cells pass with the extra argument defaulted to single-zone.
- **Verification:** `cargo test --bin xpf-userspace-dp 16026` (predicate + wiring cells); full userspace-dp suite and Go suites are the main agent's gate. No shim object change, so no `make generate` / verifier run is owed.
