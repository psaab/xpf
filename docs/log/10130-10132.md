# Fragmentation NAT and overlap trio (#10130, #10131, #10132)

## Scope

This change set closes the three related fragmentation issues:

- **#10130**: gate flowless reverse non-first fragments on a live forward session that proves NAT translation is required.
- **#10131**: attribute fragment-overlap drops by reason, preserve the attribution through binding snapshots and reset paths, and expose the counters through the Go metrics/status surfaces.
- **#10132**: carry NAT64 reverse metadata through the v4-side fragment-association lookup/install path so a later non-first reply fragment can be translated.

The working branch was `fix/10130-frag-trio` in the dedicated `10130-frag-trio` worktree.

## #10132 record-site decision

The issue scope was narrowed after the #10128 post-commit record-site split had already landed. The existing #10128 placement was evaluated rather than moved: the session-hit arm and the new-flow commit arm each retain their original owner-only/commit ordering, while the NAT64 path now carries `Nat64ReverseInfo` through those sites. A single common post-overlap record site would have changed the established placement and required threading ownership and reverse metadata across the two arms, with risk to the existing refusal and rollback ordering. That relocation was therefore deliberately declined. The implemented #10132 change is limited to the v4-side reverse-info plumbing and the v6 hit-tail behavior that depends on it.
