# Issue #17830: authorize subtree descendants using canonical lexed paths

## Why

Subtree authorization enumerated descendants with `FormatPathSet`, then passed
that display text directly to the login-class regex matcher. Display output can
preserve authored quotes on identity tokens, while the ordinary mutation gate
lexes those quotes away. The subtree and commit-removal gates therefore made
different authorization decisions for the same configuration path. Commit
diff membership also compared raw display lines: an authorized quote-only or
bracket-provenance re-set could look like a removed denied path still present
in the candidate. Separately, subtree roots were reconstructed with
`strings.Fields` from a joined path, which split a single whitespace-bearing
identity into multiple navigation tokens and could make the candidate subtree
disappear from adjudication.

## What

- `pkg/config/authz_config_mutation_9154.go`: candidate subtree roots remain
  lexed tokens through tree navigation. Rendered descendant and expanded lines
  are lexed with the same config mutation lexer as the normal gate; regexes see
  the joined unquoted token values, and expanded-descendant membership compares
  token boundaries rather than display strings.
- `pkg/config/authz_config_groups_14981.go`: addition and removal commit diffs
  use a structured identity of verb, length-delimited canonical lexed tokens,
  and annotation payload for `annotate`. Display quote/bracket provenance
  changes therefore collapse as no-op re-sets, while `deactivate` and
  annotation changes remain distinct mutations and are still priced.
- `pkg/config/authz_config_subtree_16784_test.go`: quoted and
  whitespace-bearing policy identities reproduce denied descendants in
  ancestor subtree mutations and commit removals, with absent-descendant,
  unchanged-commit, neighboring-policy, and allowed-quoted-path controls.
  Commit-diff regressions cover quote flips in both directions for deny and
  allowlist classes, bracketed-container re-sets, true denied removal,
  annotation change/deletion, and deactivation removal.

## Validation

- RED before the fix: the named canonical-path tests reported allowed ancestor
  mutations and commit removals for quoted and whitespace-bearing denied
  descendants. A fail-on-revert run restoring raw display-path evaluation
  failed the same regression cells; the canonical checks were restored.
- GREEN: `go test ./pkg/config -run
  'Test(Quoted|Whitespace)DescendantCanonicalAuthz17830|16784' -count=1` passed
  after the fix, including the allowed quoted-path control.

- GREEN after the commit-diff fold: the named regression suite covering every
  test in `authz_config_subtree_16784_test.go` passed, including both quote-flip
  directions for deny and ALLOW-OTHER classes, group-expanded addition,
  bracketed-container re-set, true removal, annotation change/deletion,
  deactivation removal, and the shipped quoted/whitespace cells.
- RED with canonical tokens reverted to raw rendered text: the deny quote-flip
  directions, bracketed-container re-set, and group-expanded addition cells
  failed with false denials. RED with the verb removed from the key: denied
  deactivation removal was allowed. RED with annotation payload removed from
  the key: denied annotation change was allowed. Restoring the complete
  structured identity made the named suite pass again.
- `go vet ./pkg/config` passed; `gofmt -l` reported no changed Go files.
- Full `go test ./pkg/config -count=1` was attempted and failed in other
  package areas, including `TestInterfacesOpenWorldWarn15199`, the compact
  inventory/normalization tests, compiler golden cases, and a
  `TestDualASTDifferential` panic in `reflect.Value.Interface` on an unexported
  field. No tests were weakened.

## Risk

Only active/candidate diff membership changes: quote and bracket provenance
collapse after strict lexing, while mutation verbs and annotation payloads stay
distinct and removed paths continue through the existing canonical-path
authorization. The per-line gate and scope of priced subtree verbs are
unchanged; copy/rename still price only the source subtree. Issue #18391 is
out of scope.
