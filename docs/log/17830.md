# Issue #17830: authorize subtree descendants using canonical lexed paths

## Why

Subtree authorization enumerated descendants with `FormatPathSet`, then passed
that display text directly to the login-class regex matcher. Display output can
preserve authored quotes on identity tokens, while the ordinary mutation gate
lexes those quotes away. The subtree and commit-removal gates therefore made
different authorization decisions for the same configuration path. Separately,
subtree roots were reconstructed with `strings.Fields` from a joined path, which
split a single whitespace-bearing identity into multiple navigation tokens and
could make the candidate subtree disappear from adjudication.

## What

- `pkg/config/authz_config_mutation_9154.go`: candidate subtree roots remain
  lexed tokens through tree navigation. Rendered descendant and expanded lines
  are lexed with the same config mutation lexer as the normal gate; regexes see
  the joined unquoted token values, and expanded-descendant membership compares
  token boundaries rather than display strings.
- `pkg/config/authz_config_groups_14981.go`: commit-removal authorization uses
  the same canonical lexed path for removed `set`, `deactivate`, and
  `annotate` entries.
- `pkg/config/authz_config_subtree_16784_test.go`: quoted and
  whitespace-bearing policy identities reproduce denied descendants in
  ancestor subtree mutations and commit removals, with absent-descendant,
  unchanged-commit, neighboring-policy, and allowed-quoted-path controls.

## Validation

- RED before the fix: the named canonical-path tests reported allowed ancestor
  mutations and commit removals for quoted and whitespace-bearing denied
  descendants. A fail-on-revert run restoring raw display-path evaluation
  failed the same regression cells; the canonical checks were restored.
- GREEN: `go test ./pkg/config -run
  'Test(Quoted|Whitespace)DescendantCanonicalAuthz17830|16784' -count=1` passed
  after the fix, including the allowed quoted-path control.
- `go vet ./pkg/config` passed; `gofmt -l` reported no changed Go files.
- Full `go test ./pkg/config -count=1` was attempted and failed in other
  package areas, including `TestInterfacesOpenWorldWarn15199`, the compact
  inventory/normalization tests, compiler golden cases, and a
  `TestDualASTDifferential` panic in `reflect.Value.Interface` on an unexported
  field. No tests were weakened.

## Risk

The existing per-line mutation gate and the scope of which subtree verbs are
priced are unchanged. Candidate navigation now retains token boundaries, while
descendant regex evaluation uses the existing config lexer. Copy/rename still
price only the source subtree; destination semantics are unchanged.
