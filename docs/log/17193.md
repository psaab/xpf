## Action

- New shared helper `pkg/dataplane/global_counter_snapshot.go`:
  `ReadGlobalCounters(r, indexes...) GlobalCounterSnapshot{Values,
  Unavailable, Err}` reads each index once (deduped), classifying
  `ErrCounterNotPopulated` as unavailable (never a value, never an error)
  and preserving the first genuine error. `GlobalCounterName` is the
  single name source (incl. the four #13274 names byte-identical to the
  old REST strings); `AllGlobalCounterIndexes` gives the dense read set.
  No new control-socket request per counter — reads go through the same
  `ReadGlobalCounter` interface.
- Migrated every non-test reader in `pkg/api`, `pkg/grpcapi`, `pkg/cli`,
  `cmd`: gRPC `GetGlobalStats`, `showFlowStatistics`, fabric statistics,
  alarms, `showScreen`; REST `globalStatsHandler`; Prometheus
  `collectGlobalCounters`; CLI `showStatistics`, `showFlowStatistics`,
  screen, alarms, NAT alloc-fail. Acceptance grep now lists only the
  three runtime-interface declarations; every callsite consumes the
  snapshot.
- Proto: additive `repeated string unavailable_counters = 16` on
  `GetGlobalStatsResponse` (regenerated with pinned protoc 3.21.12 /
  protoc-gen-go v1.36.11; `proto_header_check.py` OK). gRPC populates it
  (sorted); the remote CLI renders `unavailable` for named counters,
  numeric values otherwise. Text surfaces render the literal
  `unavailable` for unavailable counters and never warn for them;
  genuine failures keep the exact historic warnings / 500 / Internal /
  Prometheus omit-and-count behaviour.
- Prometheus nuance: the snapshot surfaces only the first genuine error,
  so `counterReadErrors` bumps once per failed scrape instead of once per
  failed counter. The #3345 contract tested by
  `TestCollectGlobalCountersSkipsAndCountsReadErrors` (samples omitted,
  total > 0) is unchanged.
- REST nuance: `unavailable_counters` order preserved exactly
  (`tc_egress_packets, fabric_redirects, flow_cache_flushes,
  flow_cache_invalidations`); any future reclassified index is appended
  after those instead of being dropped (pre-fix REST treated an
  unexpected sentinel index as a fatal read error).

## Risk

- Operator-visible text change (intended): unavailable counters now print
  `unavailable` instead of `0`, and the false `read failed` warning no
  longer fires for known-unsourced counters. Genuine-failure warnings,
  codes, and bodies are byte-unchanged.
- Wire: additive proto field 16 only; old servers omit it (remote CLI
  renders numerically as before), old clients ignore it.
- Prometheus `xpf_counter_read_errors_total` now increments once per
  failed scrape rather than per failed counter; alerting on `> 0` /
  rate is unaffected in kind.
- Residual: surfaces that read global counters only for `> 0` gating
  (screen alarms/breakdowns) keep identical output; an unavailable
  counter there is indistinguishable from a true 0, which is correct —
  neither raises an alarm.
