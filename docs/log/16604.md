# Issue #16604: NAT `routing-instance default` master alias

- **Timestamp**: 2026-10-25
- **Action**: `routing-instance default` in a NAT `from`/`to` scope was admitted by the #15278 gate as defined, but copied verbatim into snapshots while the dataplane represents the master instance as `""`, so every SNAT/DNAT/static/NAT64 rule-set scoped that way committed clean and never matched, and interface-NAT registration keyed by the literal never selected a main-instance egress. Lowered the alias through compile and wire instead of rejecting it: the Go compiler maps the literal (when no instance named `default` is declared) to `""` plus a per-side `*RoutingInstanceDefault` provenance flag; snapshot builders stamp wire token `NATDefaultRoutingInstanceWire`; Rust `nat_ri_matches` matches the token/literal only against packet `""`, so `rule=default egress=main` matches and `rule=default egress=VR1` does not, while unscoped still matches both and zone/named-VRF scopes are unchanged. Covered SNAT/DNAT/static/NAT64 matchers, tiers, persistent scope keys, DNAT off-supersets, NAT64 scope keys, Go config-time interface-egress derivation, Go snapshot pool-overlap detection, Go+Rust interface-NAT registration (shared #12085 matrix gained two `default` rows), DNAT/static local-delivery table attribution, and show rendering (`default`, not `any`). A declared `routing-instances default` keeps literal meaning; NPTv6 (which cannot honor RI scopes) now also drops/rejects the explicit-master scope instead of silently widening.
