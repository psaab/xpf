# #16051 — screen/fabric: screen profile resolved by raw ingress zone, claimed-zone profile skipped on ambiguous arrival (RN-04)

Split from #15985 (RN-04). Base re-verified at `c1b86e871b`;
implemented on current master (`a7b8884511`).

## Mechanism

Stage 9 classifies a zone-encoded fabric stamp whose claimed zone's
bound RGs are ALL forwarding-active locally as
`AmbiguousLocalZone` (#15916): the claimed zone is withheld
(`ingress_zone_override = None`, `ambiguous_zone = Some(z)`) until the
V2 owner-RG gate promotes it at a session-miss zone-pair computation.
Stage 10 (screens + SYN-cookie) and the session-miss cookie-ACK stage
run BEFORE any resolution exists, so they resolved their profile from
the raw ingress only (`screen_zone_with_state(.., ingress_zone_override)`)
— on a fabric arrival that is the fabric interface's own zone (often
unzoned / unscreened). The claimed zone's screen profile therefore
never applied to the packet that would later be promoted and admitted
under that very zone: a stateless screen (e.g. syn-fin) configured on
the claimed zone was skipped, and a cookie ACK was validated only
under the raw zone. Screens are drop-only and an honest peer ingress
is already screened (#4155), bounding this to Low — but the profile
selection itself was wrong.

## Fix (union, fail-closed, no premature grant)

Stage 10 cannot wait for promotion (no resolution yet), and granting
the claimed profile outright would let an unproven claim mint
challenges/bypasses. So the packet is judged under the UNION of the
two candidate profiles:

- `poll_stages::screen_zone_roles` returns positional raw/claimed slots:
  raw is preserved even without screen state (so it cannot be displaced),
  while claimed is separately #12875-gated and stateless-only. The plain
  `screen_zone_with_state` / `stage_screen_check` /
  `stage_screen_syn_cookie_ack_on_session_miss` wrappers pass
  `ambiguous_zone = None` and are byte-identical to before.
- The RAW zone is always the positional first role, even when it has no screen state, and keeps its full profile: flood/cookie state, counters,
  SYN-cookie challenge, validated-client bypass, and cookie-ACK
  validation are charged exactly as for a local arrival. It is also
  the validating zone for a returning ACK — the peer that minted the
  cookie screened under it.
- The CLAIMED zone contributes only a stateless veto via the new
  pure `ScreenState::stateless_screen_drop_for_zones` (LAND /
  TCP-flag / fragment / source-route; #7168 conservative default for
  a referenced-but-unresolved claimed profile; LAND gated on known
  addresses on the flowless branch). A claimed Drop recycles at
  stage 10 (flow + flowless branches) and vetoes even a Validated
  cookie ACK on the miss arm; a claimed `alarm-without-drop` profile
  makes the veto log-only (alarm + per-zone flood-alarm tally),
  mirroring the raw zone's audit mode. The claimed zone charges no
  flood sketch, mints no challenge, seeds no validated-client entry —
  it can only subtract, never admit — so no claimed-zone state exists
  before owner proof and no premature SYN-ACK is possible (the #15947
  deferred-challenge final admission still governs any reply; a raw
  Challenge verdict for a claimed-dropped packet is discarded with
  the recycle).
- The #11332 pre-screen input-filter walk now runs when EITHER
  candidate has screen state, keeping filter-denied packets off both
  profiles' (veto) evaluation.

Perf: non-ambiguous packets take the identical single-zone path (one
extra `Option` chain, no allocation — `screen_zone_roles`'
`Vec` is ≤2 entries and only built on the screen-gated path, which
already early-returns when no zone has screen state). Ambiguous
packets pay one pure stateless pass over the claimed profile.

## Residual (bounded, documented)

Rate-based claimed-zone screens (SYN/ICMP/UDP flood thresholds) do
not fire pre-promotion. For a legitimate co-moved punt they already
fired on the true ingress node (#4155); for a forged clone the packet
still receives exactly the promoted local-ingress adjudication (the
accepted #15916 shared-segment residual). See
`docs/fabric-cross-chassis-fwd.md` (#16051 section).

## Tests

- `afxdp/tests_fabric_zone_stamp.rs::ambiguous_claimed_zone_screen_drop_applies_16051`
  — decisive: co-moved ambiguous `lan` stamp, SYN+FIN against a
  `lan`-only syn-fin profile → `screen_drops == 1`, no session, no
  forward, no SYN-ACK/TX. Fail-on-revert: withholding `ambiguous_zone`
  at stage 10 (or the claimed union) makes the drop 0 and the session
  installs.
- `ambiguous_clean_syn_still_admitted_16051` — control: same arrival,
  plain SYN → no screen drop, promoted, session + forward (the union
  adds drops only; ambiguous arrivals are not failed closed).
