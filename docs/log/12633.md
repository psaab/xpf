# #12633 — poison tolerant zone-pair shapes

The tolerant `Store.Load` path warned about malformed zone-pair configurations but did not attach the synthetic global poison carrier. With a global or default permit, dropped denies could therefore fail open. The uncovered cases were S9 direct nesting (`from-zone A { to-zone B { ... } }`), S10 mixed container/keyed destination (`from-zone { A { to-zone B { ... } } }`), S18 `to-zone { policy ... }` parsed with `policy` as a phantom destination, and SET1 `from-zone A policy p1` compiled as phantom A->p1.

`compilePolicies` now records these contexts in `Security.MalformedZonePairs`, reusing the existing strict/tolerant gate and carrier in `runUniformGatesPolicy`. The compiler retains the existing tree-level #7523/#11346 diagnostics. The tolerant load remains bootable and warns; its poison lowers to the existing unsupported sentinel so the userspace helper refuses the whole snapshot. SET1's `policy` key occupying the destination slot is also recorded before pair construction, preventing phantom A->p1 from reaching the compiled policies. No shape is expanded into guessed zone-pair semantics.

Files: `pkg/config/compiler_security_policy.go`; new regression tests in `pkg/config/zone_pair_tolerant_shapes_12633_test.go`, `pkg/configstore/security_policy_tolerant_shapes_12633_test.go`, and `pkg/dataplane/userspace/zone_pair_tolerant_shapes_12633_test.go`.

Validation: Before the fix, targeted config tests failed every malformed shape because `MalformedZonePairs` stayed empty; `Store.Load` showed the same absence; and all snapshot cells showed no whole-snapshot refusal. Focused #12633 tests passed in all three packages after the fix; `TestNestedZonePairIsRejected7523` also passes after the record was made to preserve its exact established diagnostic. Full affected-package run `go test ./pkg/config/... ./pkg/configstore/... ./pkg/dataplane/userspace/... -count=1` passed `pkg/configstore`, `pkg/configstore/journal`, `pkg/dataplane/userspace`, and `pkg/dataplane/userspace/format`; `pkg/config` hit its 10-minute package timeout and reported failures in #8662, #9027/#9029, #8921, and #11312. The timed-out spelling-differential gate was still computing. These failures are outside the changed policy compiler/tests.

Risk: Existing tolerant loads remain available, but malformed policy contents now refuse the entire userspace policy snapshot (previous-good retained; fresh boot remains fail-closed), rather than allowing traffic to fall through to a permit policy. Strict commit rejects the malformed forms.
