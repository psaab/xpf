- **Timestamp**: 2026-10-16
- **Action**: Fix. `OverlapKey` gains `ingress_zone: u16`; membership
  (`overlap_same_datagram`) and the 32-entry reserve are partitioned by
  `(routing_domain, ingress_zone)` (`OVERLAP_CAP_PER_ZONE_PER_SHARD`, with
  `OVERLAP_CAP_PER_DOMAIN_PER_SHARD` kept as an alias). Completed-anchor
  reclaim is scoped to the same zone; incomplete anchors are never evicted
  and the 64/shard aggregate cap is unchanged, so fail-closed is preserved.
  Callers stamp the zone from `frag_ingress_zone` (the same resolution as
  `frag_ingress_authority`: validated fabric override, else logical unit
  zone, else 0) in `poll_descriptor/mod.rs` and the neighbor-retry path;
  parse leaves 0 and `translated_overlap_key` inherits the arrival zone on
  every post key. `FragAssoc` gains `FRAG_CAP_PER_ZONE_PER_SHARD` (32)
  keyed on `(authority.ingress_zone, authority.routing_table)` beside the
  per-session quota, with the same prune-before-refuse discipline and no
  eviction. Two pre-existing frag-assoc tests that filled a shard from one
  zone (`nat64_frag_assoc_cache_is_bounded`,
  `frag_assoc_full_shard_refuses_foreign_eviction_10714`) now fill from two
  zones, and `frag_assoc_quota_is_admitting_session_scoped_11058`'s victim
  arrives in a second zone (session-quota assertion unchanged); added
  `frag_assoc_zone_quota_cannot_starve_other_zone_14321`.
  NOT changed: sender quota (8/shard, already per-sender), TTLs, range
  geometry, shard hashing (zone deliberately not in the shard digest, so
  same-tuple cross-zone candidates co-locate and membership decides).
