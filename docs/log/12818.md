# #12818 — reject valueless qualified next hops in strict compilation

## Why

`qualified-next-hop;` without a gateway passed strict `CompileConfig`, which
created an empty-address placeholder next hop that static-route disposition
checks later skipped. `SchemaValidate` already rejected the same expanded
configuration as a missing declared value. Strict compile and schema validation
therefore disagreed, allowing a commit to silently omit the qualified next hop.

## What

Extended the shared static-route qualified-next-hop validation used by strict
compilation and schema validation to reject a `qualified-next-hop` node with no
gateway and no children. The error names the missing value, issue #12818, and
the full parent-chain path (including routing-instance identity). The tolerant
compilation path retains its existing warning/downgrade behavior.

Added regression coverage for hierarchical and flat-set valueless next hops,
including the inline route-key spelling, with and without a primary next hop.
Tests pin route/RI identity in the diagnostic, preserve acceptance parity for
`qualified-next-hop { preference 5; }`, and cover valid IPv4, IPv6,
interface-qualified link-local QNH, and plain next-hop controls. The zero-
disposition test now constructs its empty placeholder hop directly as a typed
`StaticRoute`, preserving the #11327 warning and exclusion contract without
depending on strict compilation accepting the removed input.

## Validation

- **RED before**: `go test ./pkg/config -run '^TestValuelessQualifiedNextHopCompileConfig12818$' -count=1 -v` — all four valueless compile cases were accepted; the separate valid-control check exposed an invalid mixed-family fixture, which was corrected before the fix.
- **GREEN focused**: `go test ./pkg/config -run '^(TestZeroDispositionStaticWarnsAndIsExcluded_11327|TestZeroDispositionStaticWarningCoversAllRouteScopes_11327|TestValuelessQualifiedNextHopCompileConfig12818)$' -count=1` — passed.
- **F2 mutant check**: removed the `len(node.Children) == 0` guard locally; the child-bearing acceptance control failed as expected, then restored the guard.
- `go build ./...` and `go vet ./pkg/config` — passed.
- `go test ./pkg/config -skip '^TestSchemaSpellingDifferentialGate$' -count=1` — no new QNH/11327 failures; the remaining failures were the pre-existing inventory census, API-auth expiry/self-repeat, packed routing-instance, and slot-escape coverage failures. `TestSchemaSpellingDifferentialGate` remains skipped here because its bcrypt differential sweep exceeded the package command's 10-minute budget in the earlier unfiltered run.

## Risk

The new rejection is scoped to static-route qualified-next-hop nodes that have
neither a gateway token nor child modifiers. Valid gateway and interface forms
remain unchanged. No live FRR or dataplane mutation was performed.
