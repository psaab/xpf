# #15105 — userspace-dp: record refused reconcile-replay upserts as repair debt (A71-02)

- **Timestamp**: 2026-10-18
- **Mechanism**: Both reconcile replay sites routed synced-session rows
  through `worker_queue::push_bounded` and discarded its refusal at the
  `MAX_PENDING_WORKER_COMMANDS` (4096) cap. The bring-up replay
  (`reconcile/bringup.rs` `replay_preserved_sessions` →
  `Coordinator::replay_synced_sessions` → `session_glue/worker_commands.rs`
  `replicate_session_upsert`) fans the full shared snapshot into brand-new
  empty queues, so any shared table over 4096 rows handed each worker only
  the first 4096. The late replay (`replay_late_synced_sessions`) retains a
  non-upsert prefix and appends a fresh full snapshot through the same
  bounded push, truncating the snapshot tail the same way. No repair
  obligation was recorded (#6929 added the cap and the obligation
  requirement; #11360 delivered the obligation for the import path only),
  so the refused rows were absent from every worker with no signal beyond
  the aggregate queue-drop counter — workers never adopted those sessions
  and never took their SNAT translated-port holder reservations.
- **Action**: A refused replay `UpsertSynced` now records #11360
  session-import repair debt, positioned after the queue prefix present at
  refusal and recorded while still holding that queue's lock (the #11718
  discipline): `replicate_session_upsert` resolves the worker id from the
  generation's `WorkerCommandQueues` (new `worker_id_for_queue`, Arc
  identity, mirroring `shed_if_dead`), and `replay_late_synced_sessions`
  takes the spawning worker's id from its caller. The worker re-reads each
  refused key from shared authority at that FIFO boundary via the existing
  `apply_session_import_repairs` path, so a row deleted before the boundary
  takes the normal delete path instead of resurrecting. The per-worker
  repair-debt bound rises from one queue cap to `2 *
  MAX_PENDING_WORKER_COMMANDS` so a full queue ahead of a larger snapshot
  can obligate the whole refused tail; past that bound (or for a queue
  outside the generation map) the #6929 drop counter remains the signal.
  NOT changed: the queue cap itself, the drain budget, steady-state
  replication ordering, or any non-replay producer.

  `late_replay_over_cap_records_import_repair_debt_15105`) seed cap+1000
  shared rows and drive the real replay helpers. RED on unmodified

- **Risk**: Steady-state sibling replication through
  `replicate_session_upsert` now also records debt on refusal (previously
  a silent drop); the repair re-reads current shared authority at the FIFO
  boundary, so it cannot resurrect a superseded row, and a key deleted
  from shared authority takes the worker delete path. The repair map is
  per-worker bounded (8192 keys); beyond it the behaviour degrades to the
  pre-fix drop-counter-only signal rather than failing closed on live
  traffic. Worker ids are planner-bounded (< 128), so every production
  queue resolves to a debt slot.
