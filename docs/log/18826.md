# #18826 — Derive test-runner HA lease seconds from nanoseconds

- **First bad**: `66732beeb2` (`#17069`), which made `Tick::from_ns` the clock source for HA lease checks; see `docs/log/17069.md`.
- **Why**: The test descriptor runners paired nanosecond timestamps with a frozen `now_secs = 123`. Active `txn_ha_state()` leases therefore appeared expired at the descriptor's actual derived second, causing session-hit control packets to drop.
- **What**: Added `restamped_ha_state` to carry only groups active at the legacy second forward onto `now_ns / 1_000_000_000`, leaving inactive and deliberately expired fixtures unchanged. Both `txn_run_descriptor_at` and `txn_run_descriptor_capturing_events` now pass the same derived seconds as their nanosecond clock; the latter takes one monotonic sample for both. `txn_ha_state()` and the central descriptor implementation remain unchanged.
- **Validation**:
  - Red before the fix: `established_icmp_drops_after_egress_zone_move_13924`, `stale_foreign_icmp_hit_does_not_mutate_forwarding_session_12265`, and `c3_forward_control_survives_full_window_per_permit_shape_10591` all failed with `tx == 0` instead of their forwarding-control expectations.
  - Green: those three named tests each passed. Neighbor modules passed: `tests_session_hit_authority_9519` (30), `tests_session_hit_authority_window_10591` (11), and `tests_policy_revocation_8356` (131), each with `--test-threads=1`.
  - Mutant: reverting the event-capturing runner to its old `monotonic_nanos()` / frozen-`123` pair made `established_icmp_drops_after_egress_zone_move_13924` fail again at the control's `tx == 1` assertion (`left: 0`). The runner was restored; the same named test passed.
- **Risk**: Test harness only. Deliberately expired or inactive HA fixtures are not re-stamped, so HA denial remains exercised.
