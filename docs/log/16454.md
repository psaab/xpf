- **Timestamp**: 2026-10-24
  - **Action**: Fixed #16454 — the Rust helper published a
    `filter_term_counters` row for every firewall term, but every
    `record_filter_counter` site is gated on `then count` (`has_count`),
    so an uncounted term rendered a permanent authoritative
    `Hit count: 0` / `xpf_filter_hits_total{...}=0` however much traffic
    it matched. `filter_term_counters()` now skips `!has_count` terms
    (counted-but-idle terms still publish a real 0). Defence in depth for
    mixed-version deploys: the Go surfaces (local CLI `show firewall` /
    `show firewall filter`, the gRPC mirrors, and the Prometheus
    collector) additionally gate on the config term's `Count != ""`, so
    a legacy helper's row for an uncounted term can never render a
    numeric hit count either. Existing Go fixtures whose terms were
    uncounted but asserted series/hit-counts were updated to declare
    `then count`. The gRPC golden's uncounted term likewise stops
    rendering `Hit count: 7` (golden regen pending — that test is
    base-broken by #14660, see Validation). No wire change.
