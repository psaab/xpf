# Issue #13128: screen-probe attributes the witness drop to the subject

- **Timestamp**: 2026-10-14
- **Action**: `test/incus/screen-probe.sh` now sends the arrival-witness frame first, samples the witness counter and then samples the aggregate `xpf_screen_drops_total` to establish the subject baseline. It sends the subject only after that baseline and samples the aggregate again. Because every screen drop increments the aggregate, the witness's expected teardrop can no longer be mistaken for a subject drop. The decision library interface is unchanged; its comments now document the ordered measurement.
- **Regression**: `test/incus/screen-probe-selftest.sh` models the aggregate moving once for a witness-only run and twice when the subject is also dropped. It asserts witness-only movement is `PASSED` and the additional subject increment is `DROPPED`.

- **GREEN**: after the ordered sampling fix, `make test-screen-probe-lib` passes all 45 checks, including the witness-only and additional-subject-drop cases and the live-shell ordering assertion.
- **Live-path regression coverage**: a static selftest asserts witness send < witness-counter sample < aggregate subject baseline < subject send < aggregate after-sample.
