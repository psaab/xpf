# #14572 — Token-initial `[/*` endpoint literal bypassed restricted-class `load merge`

## Defect
`ClassifyLoadContent` (`pkg/config/authz_config_load_9892.go`) is the
shared comment classifier behind the restricted-class load gate
(`AuthorizeConfigLoad`/`LoadMutationLines`) and the config store's flat
routing. Its `case '[', ']'` arm left `inToken=false` for a token-INITIAL
`[`, so a following `/*` (or `//`) opened a fictitious comment that
blanked every following statement in the gate's view.

The real lexer disagrees: in its gap loop (`pkg/config/lexer.go`) a
token-initial `[` is first tried as `tryBracketedEndpointLiteral`
(#5182) — `[`+identrun+`]:`+identrun is ONE identifier token, and `/`
and `*` are identifier characters, so `[/*x]:1` and `[//x]:1` are such
literals and no comment ever opens. The classifier's header comment
claimed lexer equivalence and called the token-initial case "bracket
list sugar", which #5182's endpoint literal contradicts (residual of
#14145, which fixed only the mid-token `a[/*` spelling).

Two parsers of the same bytes therefore violated the gate⊆store
invariant: the gate adjudicated only `set system host-name`, while the
store's hierarchical branch (`LoadMergeAsPlantClass`, and the shared
`parseOverrideContent` behind `LoadOverride`) re-parsed the RAW body
and applied `root-authentication`, `security policies permit-all`, etc.
An authenticated operator whose class is regex-restricted (with at
least one allowed free-text leaf to carry the literal) could write any
config path — root authentication, login classes (self-promotion),
security policy — over CLI, REST and gRPC. RED witness (package probes,
also encoded as the committed tests below): gate lines
`["set system host-name"]`, `AuthorizeConfigLoad(merge)` nil for class
`limited`; the store applied the denied leaves.

## Fix
Both halves of the issue's "parse once" direction:

- `pkg/config/authz_config_load_9892.go`: `ClassifyLoadContent` now
  models the endpoint literal. At a token boundary (including
  immediately after a boundary `]`, where the real lexer's loop retries
  the literal on the next iteration) it tries the new
  `bracketedEndpointLiteralEnd`, a byte-for-byte mirror of
  `tryBracketedEndpointLiteral` reusing the lexer's own `isIdentChar`;
  on a match the whole literal is copied as token text (`inToken=true`)
  so no `/` inside it can open a comment. A `[` that does not form a
  literal keeps the #14145 list-sugar behaviour, so a genuine comment
  after `[ /* … */` is still a comment.
- `pkg/configstore/store_command.go`: both hierarchical ingresses now
  parse the classifier's uncommented text instead of the raw body —
  `LoadMergeAsPlantClass` parses `strings.Join(lines, "\n")` (the
  already-computed classifier output, newline positions preserved) and
  `parseOverrideContent` parses its `flatContent`. The store therefore
  applies exactly the representation the gate adjudicated, by
  construction, even if the two comment models ever drift again.

NOT changed: `SyncApply` and the on-disk rescue/commit parsers — they
are not gated by `AuthorizeConfigLoad` (HA peer sync / trusted local
files), so no gate⊆store invariant attaches to them. The classifier's
flat routing, the real lexer, and `tryBracketedEndpointLiteral` itself
are untouched.
