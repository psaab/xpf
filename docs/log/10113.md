# #10113 — SNMP Serve multi-source fair share

## Scope

The owner re-scoped #10113 after #9917 / PR #10114: the single-source
worst-PDU flood is already bounded by the merged 10x per-source charge and 2x
global backstop. This follow-up fixes only userspace FIFO unfairness among
multiple expensive sources. Datagrams dropped in the UDP socket buffer before
`Serve` remain out of reach by design.

## Fix

`snmpServeBudget` keeps both the #9917 per-source and global tokens on every
admission. A request whose measured handling time is at least 1ms marks its
source as an expensive contender. With N active contenders, the per-source
service debit is `max(10, 2N)`: N <= 5 retains the 1/10 loop-share floor, while
N >= 5 converges to equal approximately `1/(2N)` shares of the loop (`1/N` of
the global half). Expensive demand is timestamped only by measured expensive
service or a throttled expensive retry, so cheap Sybil keepalives cannot retain
a contender slot. A bounded once-per-second sweep expires quiet expensive and
pending state. If the global bucket is scarce, admitted sources reserve one
credit per pending userspace newcomer; surplus credits remain work-conserving.
An expired source may use one reserved probe to re-enter, but that cheap probe
neither restores expensive eligibility nor increases N; only a newly measured
expensive request does. This prevents first-come starvation without stalling
managers after a flood ends. Stable Sybil identities can still consume
contender slots; the global aggregate remains the bound, and socket-buffer loss
before `Serve` is out of reach by design. Cheap sub-millisecond polling retains
the ordinary 10x charge.

For N >= 5, an active expensive source with service time `s` and rate
`lambda` satisfies the per-source bucket inequality
`lambda (1 + 100 * 2N * s) <= 100`, hence
`lambda * s <= 100s / (1 + 200Ns) < 1/(2N)`. The N <= 5 floor remains the
unchanged 10x single-source bound. The global 2x service debit independently
caps aggregate expensive loop share at one half; the pending reservation
establishes onboarding/no-starvation across sources that reach userspace.

The finalized N-source worst-case simulation was run against `origin/master`
with the exact test cell. The pre-fix first-come split failed:

The factor cells also failed on base: N=10 admitted 188 instead of the fair

the exact-factor subcells.

## GREEN evidence

The final 33ms in-tree ifXTable worst-case simulation drives source zero at 10x
the offered pressure, keeps all late sources un-prewarmed, advances fake time
by 33ms for each admitted PDU, and measures the post-warmup loop share:

```
counts [59 59 59 59 60 59 59 63 61 58]
elapsed 39.668s
busy share 0.496
```

The fair-share ratio is `63/58 = 1.09x`; every source is admitted. Boundary
cells also pass: pending state expires without blocking when surplus global
credits are available, cheap Sybil keepalives do not retain six contender
slots or re-enroll repeatedly through scarce-global probes, cheap 999us
polling admits exactly the ordinary 198-token remainder, and N=4 preserves
the old 10x remainder while N=6/N=10 scale the expensive debit.
