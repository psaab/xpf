# #10113 — SNMP Serve multi-source fair share

## Scope

The owner re-scoped #10113 after #9917 / PR #10114: the single-source
worst-PDU flood is already bounded by the merged 10x per-source charge and 2x
global backstop. This follow-up fixes only userspace FIFO unfairness among
multiple expensive sources. Datagrams dropped in the UDP socket buffer before
`Serve` remain out of reach by design.

## Fix

`snmpServeBudget` keeps both the #9917 per-source and global tokens on every
admission. A request whose measured handling time is at least 1ms marks its
source as an expensive contender. With N active contenders, the per-source
service debit is `max(10, 2N)`, so each independent source bucket converges to
an equal approximately `1/(2N)` share of the loop while the global 2x charge
continues to cap aggregate expensive work at roughly one half. A bounded
once-per-second sweep expires quiet expensive and pending state. If the global
bucket is empty, previously admitted sources yield the next credit to a source
that has reached userspace, preventing a first-come source from starving a late
contender. Cheap sub-millisecond polling retains the ordinary 10x charge.

## GREEN evidence

The final 33ms in-tree ifXTable worst-case simulation drives source zero at 10x
the offered pressure, keeps all late sources un-prewarmed, advances fake time
by 33ms for each admitted PDU, and measures the post-warmup loop share:

```
counts [59 59 59 59 60 60 59 60 62 59]
elapsed 39.668s
busy share 0.496
```

The fair-share ratio is `62/59 = 1.05x`; every source is admitted. Boundary
cells also pass: pending state expires, cheap 999us polling admits exactly the
ordinary 198-token remainder, N=4 preserves the old 10x remainder, and N=6/N=10
scale the expensive debit.
