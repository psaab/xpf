# #18234 — Construct typed snapshot in shared-umem tests

- **Timestamp**: 2026-10-27

## Why

On `origin/master` the whole `xpf-userspace-dp` bin test target failed to
compile: `userspace-dp/src/afxdp/shared_umem_tests.rs` still built
`ConfigSnapshot { userspace: json!({…}) }` at the snapshot-level typo case,
but #17134/#17149 changed `ConfigSnapshot.userspace` from an untyped
`serde_json::Value` to the typed `UserspaceSnapshot`. The compiler reported
exactly one error,

```
error[E0308]: mismatched types
  --> src/afxdp/shared_umem_tests.rs:247:20
  userspace: json!({…})
  expected `UserspaceSnapshot`, found `Value`
error: could not compile `xpf-userspace-dp` (bin "xpf-userspace-dp" test)
```

so every Rust hermetic cell in that binary was blocked and unrelated PR CI
showed the target red.

## What

- Added a `typed_userspace(SharedUmemSnapshot) -> UserspaceSnapshot` helper
  in `shared_umem_tests.rs` and imported `crate::protocol::SharedUmemSnapshot`.
- Converted every direct `ConfigSnapshot.userspace` construction in that
  file to the typed value:
  - `explicit_off_disables_shared_umem` — `mode: "off"`.
  - `explicit_interfaces_limit_policy_candidates` — `mode: "cross-nic"`,
    `interfaces: ["lan0", "wan0"]`.
  - `same_device_debug_auto_selects_all_interfaces` —
    `mode: "same-device-debug"`.
  - `off_policy_clears_stale_shared_status` — `mode: "off"`.
  - `shared_umem_mode_unknown_falls_back_off_17149` snapshot-level case —
    `mode: "cross-nick"`: the typo is now carried as a typed `String`, so
    `SharedUmemPolicy::from_snapshot` → `parse_shared_umem_mode("cross-nick")`
    still yields `SharedUmemMode::Off`, NOT `CrossNic`. The fail-safe
    fallback is exercised through the typed field exactly as production
    consumes it.
- Kept the wire-decode `json!` sites untouched on purpose: they must still
  exercise the typed serde path —
  `present_but_modeless_snapshot_defaults_to_cross_nic`
  (`serde_json::from_value::<UserspaceSnapshot>` for missing/empty/null
  mode and `phase0_artifact_file`-only), `unknown_shared_umem_keys_are_ignored`
  (unknown keys tolerated, no `deny_unknown_fields`), and
  `null_userspace_decodes_as_default` (null `userspace` decodes as default
  through `ConfigSnapshot`). No production code changed.

## Validation

Hermetic, named cells only (`TMPDIR=/var/worktrees/.cache/18234-tmp`,
`CARGO_TARGET_DIR=/var/worktrees/.cache/18234-target`):

  `cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp shared_umem -- --exact`
  → `error[E0308]` at `shared_umem_tests.rs:247` (`expected UserspaceSnapshot, found Value`),
  `could not compile xpf-userspace-dp (bin "xpf-userspace-dp" test)`.
- After the fix, full-path `-- --exact` runs:
  - `afxdp::shared_umem::tests::shared_umem_mode_unknown_falls_back_off_17149`,
    `explicit_off_disables_shared_umem`, `policy_defaults_to_cross_nic_auto`,

    `afxdp::neighbor::newneigh_request_tests::data_path_learn_installs_stale_not_reachable_4475`

## Risk

Test-only change; no production behavior, wire format, or policy logic is
altered. The only semantic risk would be weakening the typo case — it is
not weakened: `cross-nick` is still asserted to produce `Off` at both the
`parse_shared_umem_mode` level and the snapshot/`from_snapshot` level, now
through the typed field production actually reads. The retained `json!`
decode cells keep covering the serde defaults (modeless → `cross-nic`,
unknown keys tolerated, null → default) that the typed constructions
bypass by design.
