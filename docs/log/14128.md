# Issue #14128 — source-NAT revalidation on reverse-only sessions

## Defect

Three bundled defects in the companion-less reverse source-NAT
revalidation (`policy_revalidation.rs` `NoLocalEntry` arm, which
reconstructs a forward decision from the reverse row when the forward
half is not materialized locally):

1. **ICMP type/code loss.** `NatDecision::reverse` set
   `source_nat_icmp: None`. The field is the original forward packet's
   ICMP type/code (e.g. echo-request (8,0)), not the echo identifier.
   The reconstructed forward decision therefore carried no type/code,
   and `source_nat_translation_matches` treated a PAT ICMP mapping
   (`!has_l4_ports(ICMP) && packet_icmp.is_none()`) as portless,
   requiring `translated_src_port.is_none()` — rejecting the existing
   translated identifier and falsely revoking (`StaleSourceNat`).
   A second facet of the same reconstruction: `reverse()` is
   port-pair oriented, so for ICMP it reconstructed
   `rewrite_src_port = Some(0)` (the reverse key's `dst_port`) instead
   of the translated identifier carried in the reverse key's
   `src_port` (the identifier is a single symmetric field, #4074).

2. **Physical vs logical egress.** The reconstructed forward egress was
   the packet's physical arrival ifindex. On a VLAN trunk that is the
   bind parent, while `forwarding.egress` is keyed by logical unit
   ifindex and interface-SNAT reads the logical unit's primary address.
   The validator therefore missed the egress row (fail-closed
   revocation) or compared against the parent row's address, spuriously
   revoking configured interface-SNAT on the logical unit.

3. **No-translation → PAT laundering.** In the PAT branch,
   `translated_src_port.map_or(contains(&src_port), ...)` accepted a
   stored portless mapping (installed under `port no-translation`, no
   translated port) whenever the *original* `src_port` happened to fall
   inside the new PAT pool range — keeping a translation the
   reconfigured PAT rule never allocated.

## Fix

- `nat/mod.rs`: `NatDecision::reverse` preserves `source_nat_icmp`.
  The field is packet identity, consumed only as the forward decision's
  `packet_icmp` on reconstruction and in forward-row HA attribution
  (reverse rows are gated `!is_reverse` at import); no wire rewrite
  changes.
- `nat/source/mod.rs` (`source_nat_translation_matches`): an ICMP query
  PAT mapping (translated identifier present) no longer takes the
  portless branch when type/code is absent; the PAT branch now requires
  a stored translated port/identifier inside the live pool range
  instead of falling back to the original `src_port`. Portless
  provenance (`no_translation`, deterministic address-only, port-less
  protocols) still requires `translated_src_port.is_none()`, so both
  reconfigure directions stay fail-closed.
- `policy_revalidation.rs` (reverse `NoLocalEntry` arm): resolve the
  reconstructed forward egress `(physical arrival, arrival VLAN) ->
  logical` via `resolve_ingress_logical_ifindex` (untagged/physical
  arrivals resolve to themselves), and restore the ICMP translated
  identifier from the reverse key's `src_port` when `reverse()` left
  the placeholder `Some(0)`.

## Regression

In `policy_revalidation_tests.rs`:

- `reverse_only_icmp_pat_survives_revalidation_14128` — production
  reverse synthesis of an ICMP PAT flow (echo (8,0), pool identifier
  45000), only the reverse row installed; unchanged typed pool survives,
  a different-type (13,0) rule still revokes. Also asserts `reverse()`
  preserves `source_nat_icmp`.
- `reverse_only_vlan_interface_snat_survives_14128` — reverse hit on
  physical parent 12 / VLAN 50 with interface-SNAT on logical unit 13;
  survives, and a logical-unit address change still revokes.
- `source_nat_translation_matches_no_translation_to_pat_revokes_14128`
  — validator-level provenance matrix: address-only mapping validates
  under `no_translation`, is rejected under PAT, real PAT validates,
  out-of-range port rejected, ICMP PAT without type/code validates via
  its identifier, PAT-typed port rejected under `no_translation`.

## Validation

- RED: test-only patch applied to a pristine `origin/master` worktree
  (10f2d5a55): all three tests fail — `reverse()` drops
  `source_nat_icmp` (`left: None, right: Some((8, 0))`), the VLAN
  interface-SNAT hit is falsely revoked, and the portless mapping is
  laundered under PAT.
- GREEN: with the fix, the three tests pass; the neighbouring
  revalidation suite passes (26/26 in the SNAT/reverse subset, 328
  passed in the wider `policy_revalidation` + `nat::tests_pool` run).
