# Issue #15175 — screen show surfaces never read AlarmWithoutDrop (B18-04)

- **Issue:** `show security screen`, `ids-option <p>` and
  `ids-option <p> detail` (CLI + gRPC text) never read
  `ScreenProfile.AlarmWithoutDrop`, and the structured REST/gRPC screen
  inventory carried no mode field. A profile whose every check is
  log-only therefore listed its checks as `enabled` and bound to the
  zone exactly like a drop-enforcing profile; only `show configuration`
  and a Prometheus event counter moving under attack revealed that the
  zone's screen drops nothing (#4170 implemented the mode; #9425/#7888
  carried it to the inert-profile wire; the display gap remained).
- **What:**
  - `pkg/dataplane/userspace/screens.go`: new shared helpers beside
    `ScreenInertProfileLines` — `ScreenAlarmModeLine` (the one wording
    `Mode: alarm-without-drop (checks alarm; nothing is dropped)`,
    empty for nil/drop-enforcing profiles), `ScreenCheckValue`
    (`alarm-only` vs `enabled` for the Value column).
  - CLI (`cli_show_security_screen.go`) and gRPC text
    (`server_show_security_text.go`): all three views emit the mode
    line after the profile header, and boolean checks render
    `alarm-only` instead of `enabled` under the modifier. Numeric
    thresholds are unchanged (the value, not the disposition, is
    numeric). Non-audit output is byte-identical to before.
  - Structured inventory: additive `alarm_without_drop` on
    `ScreenInfo` (proto field 4, regenerated `xpf.pb.go`), populated in
    gRPC `GetScreen` and REST `GET /api/v1/security/screen`
    (`AlarmWithoutDrop`, `omitempty`); absent/false keeps the old wire
    shape for drop-enforcing profiles.
  - NOT changed: dataplane enforcement, snapshot wire, inert/unresolved
    diagnostic blocks, zones-detail `Enabled checks` line (profile
    inventory, not a screen view; the mode is visible on every screen
    view and in structured state), or any neighbouring behaviour.

## RED -> GREEN proof

- **RED (base):** `screens_alarm_mode_15175_test.go` fails to build on
  unmodified master (`ScreenAlarmModeLine`/`ScreenCheckValue` undefined); the CLI/gRPC/REST cells assert `Mode: alarm-without-drop`
  / `alarm-only` / `alarm_without_drop`, none of which any pre-fix
  renderer emits (grep-verified: no non-test show reader of
  `AlarmWithoutDrop` outside metrics).
- **GREEN:** two-arm (audit vs drop) tests on every view — CLI
  `TestCLIScreenAlarmWithoutDrop15175`, gRPC text + `GetScreen`
  `TestGRPCScreenAlarmWithoutDrop15175`, REST
  `TestScreenHandlerAlarmWithoutDrop15175`, helper
  `TestScreenAlarmModeLines15175`. The drop arm pins unchanged
  legitimate behaviour (no mode line, plain `enabled`). Neighbour
  screen suites pass; the one failure in the widened sweep,
  `TestGetGlobalStatsScreenDropDetailKeysAreCanonical` (pkg/grpcapi),
  fails identically on unmodified `origin/master` (0020495) —
  base-attributed, untouched by this change.

## Risk

- Display-only: no enforcement, wire-enforcement, or config change.
  The proto/JSON additions are additive and omitempty/default-false,
  so mixed-version consumers see the previous shape for drop profiles.
