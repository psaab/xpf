# Issue #13649 — preserve pre-SNAT source identity for outbound ICMP errors

Outbound SNAT embedded-ICMP errors were re-NAT'd before the queued-frame zone
policy gate parsed the outer identity. As a result, the gate judged the public
SNAT address instead of the internal sender, allowing policy rules to be
bypassed when an internal-source deny was paired with a broad SNAT-pool permit.

## Change

- Carry the packet's pre-rewrite outer source identity through the same-family
  embedded-ICMP queued result when the match is an outbound SNAT error.
- Use that identity for zone-policy evaluation and deny events while retaining
  the built frame's post-SNAT identity for transmission.
- Keep NAT64 paths unchanged; their queued outcomes carry no source override.
- Add fail-on-revert coverage for an internal-host deny and mirrored SNAT-pool
  permit in IPv4, plus the same policy identity check for the SNAT66 path.
