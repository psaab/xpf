# #9632 — configstore: after a stale-lease reclaim by an internal actor, the previous holder's edits and commit still pass the holder gate

- **Timestamp**: 2026-09-10
  - **Action**: Took option 1, as the issue recommends: the narrow fix that
    keeps #5059's documented decision.
    - `reclaimStaleLockLocked` now records the evicted session in
      `Store.reclaimedHolders`, before it clears the holder fields.
    - `ensureHolderLocked` refuses a recorded session while the lock has no
      recorded holder. That is the internal / local `EnterConfigure()`
      state, which is the only state #5059's empty-holder pass lets a user
      session into.
    - The refusal wraps `ErrConfigLockedByOther`, so every caller that
      errors.Is-matches it keeps working, and it tells the session to
      re-enter configure.
    - Every mutation verb and `AuthorizeCommit` go through this gate, so the
      refusal covers the #6808 commit authority too.
  - **Action**: Clearing. `EnterConfigureSession(id)` and
    `EnterConfigureExclusive(id)` remove the session from the set when it
    takes the lock again. Once it has re-entered and released, it is an
    ordinary never-reclaimed session under #5059.
    - The set is capped at `reclaimedHoldersCap` (64), because a reclaim
      fires only for a lock idle past the lease. The internal empty holder is
      never marked.
  - **Action**: Not done here: option 2, giving the internal actors (event
    engine, daemon apply-commit) their own holder identity. That changes what
    any remote session may do while an automated commit is in flight, so the
    issue asks for a separate decision.
  - **Action**: pkg/configstore/README.md documents the refusal next to the
    #4476 lease paragraph.
  - **Action**: Cells in pkg/configstore/store_lock_reclaimed_holder_9632_test.go.
    - A named session goes stale and the internal actor reclaims. The old
      session's SetAs, SetFromInputAs, DeleteAs, LoadMergeAs, RollbackAs and
      AuthorizeCommit are then each refused with ErrConfigLockedByOther and
      the word "reclaimed". Its edits, before and after the reclaim, are
      absent from the internal candidate.
    - Controls: the internal caller still edits, and a never-reclaimed
      session still edits the internal candidate (#5059).
    - Re-entering, shared and exclusive, allows SetAs and AuthorizeCommit
      again. After release, the session edits a later internal candidate as
      an ordinary #5059 session.
    - The set is bounded, and the empty holder is never marked.
    - The existing #5059, #4476, #9119, #7635 and #5379 lock cells stay green.
