# #17110 — single-source the bare/scoped delete journals in boundedFrameJournal (R4-Q34-05)

- **Timestamp**: 2026-10-27
- **Issue**: #17110 (R4-Q34-05)
- **Base**: `origin/master 64d512852a` (re-verified at fix time; cited lines 623/648/679/729/781/827 in `pkg/cluster/sync_conn_write.go` matched the issue, scoped flush warn at 763-764 vs bare 711-715)

## Defect (STEP-0, verified at base)

`journalDelete`/`journalScopedDelete`, `flushDeleteJournal`/`flushScopedDeleteJournal`
and `rejournalTail`/`rejournalScopedTail` were three hand-copied twin pairs differing
only in slice/cap, the scoped learn-gate prologue, and log text. `scopedDeleteJournalCap`
(`sync.go` field) was read at `sync_conn_write.go:650,833` but never assigned in
production or tests (constructors set only `deleteJournalCap`), so the scoped
eviction, `DeletesDropped` accounting and `armDeleteResync` (#5450) branches had
zero coverage. The scoped flush warning logged only `total/flushed/unsent_tail`;
the bare warning added `deletes_dropped_total`, `connected`, `queue_len`, `queue_cap`.

## Fix

- New `boundedFrameJournal{entries [][]byte; cap int}` in `sync_conn_write.go` is
  the single cap/evict/prepend body: `push(msg) (evicted bool)`, `take() [][]byte`,
  `clear() (dropped int)`, `prependTail(tail) (dropped int)`, `effectiveCap()`
  (non-positive cap resolves to `deleteJournalDefaultCap`, so zero-value
  `&SessionSync{}` fixtures stay bounded). All methods run under the existing
  `deleteJournalMu`; the journal does no locking/counting/arming.
- `SessionSync.deleteJournal` / `scopedDeleteJournal` are now two
  `boundedFrameJournal` instances (constructors initialise both caps to
  `deleteJournalDefaultCap`); `deleteJournalCap`/`scopedDeleteJournalCap` are
  deleted with no shim. Callers migrated: `sync_test.go`,
  `sync_bulk_retry_12166_test.go`, `test_seams.go`, and the 9631/9714/9752/10512
  test helpers read `.entries` / set `.cap`.
- Counting and arming live in one caller helper each: `journalPush` (evicted →
  `DeletesDropped.Add(1)` + `armDeleteResync`, warn outside the lock with the
  per-journal message and `deletes_dropped_total`/`journal_cap`) and
  `rejournalTailInto` (`prependTail` drops → count + arm). `journalDelete`,
  `journalScopedDelete` (learn-gated post-append flush retained), `rejournalTail`,
  `rejournalScopedTail` are thin delegations.
- The flush replay loop is likewise single-sourced in `flushJournalEntries`
  (source string, rejournal func, messages parameterised); both flush warnings
  now emit the identical field set
  `total/flushed/unsent_tail/deletes_dropped_total/connected/queue_len/queue_cap`.
  The scoped message now also says `(queue full or disconnected)`. Scoped
  flush prologue (unlearned retain, incapable drop+`DeletesSuppressedScopedPolicy`)
  is unchanged, using `clear()`. A `testBeforeJournalTake` hook mirrors the
  existing scoped hook so the bare flush's concurrent-append ordering is pinned.
- `docs/session-sync-architecture.md`: bounded-journal wording updated to
  `boundedFrameJournal` (both journals, default cap 10000 each). No other docs
  named the removed cap fields in production terms.

## Risk

Low. One executable body where there were three twin pairs; per-journal log
messages and the scoped learn/incapable prologue are parameterised, not forked.
Behaviour preserved: same eviction order, same `DeletesDropped`/`forceResync`
accounting, same FIFO prepend. Surface changes: scoped flush warn gains the
four bare diagnostic fields and the `(queue full or disconnected)` wording;
both journals are now explicitly capped at construction (previously the scoped
cap silently fell back to the default at read time — identical effective cap).
Residual: `stats.Connected`/`sendCh` reads in the shared warn are lock-free
exactly as the bare warn already did.
