# #14239 — frame-derived flowless-protocol regression for #14214

The #14214 regression `h18_13966_flowless_fragment_uses_native_ingress_protocol`
hand-supplied the resolved protocol (`ingress_key.protocol = PROTO_TCP` from
`count4085_v4_key()`) while `meta.protocol = SHIM_PROTO_FRAGMENT_NO_L4`. It
never exercised `l3_enforcement_flow_from_frame` / `flowless_effective_protocol`
on a real fragment frame, nor either production caller wiring the derived flow
into TX selection — reverting the derivation or the caller wiring kept it green.

Added regressions ( existing callee-level regression kept unchanged):

- `h18_14239_flowless_fragment_frame_derived_ingress_protocol`
  (`afxdp/tx/cos_classify_tests.rs`): builds real non-first-fragment frames via
  `eth_ipv4_frag_frame` / `eth_ipv6_frag_frame` with `SHIM_PROTO_FRAGMENT_NO_L4`
  meta, derives the ingress key ONLY through
  `l3_enforcement_flow_from_frame`, asserts the derived protocol is TCP
  (IPv4 Protocol byte; IPv6 Fragment Next-Header), then feeds the derived key
  into fresh (`resolve_cos_tx_selection_at_prenat`) and cached
  (`resolve_cached_cos_tx_selection_flowless_with_ingress`) selection and
  asserts the TCP-scoped input policer matches (drop / EF queue 1 / DSCP 46 /
  one three-color policer). A UDP-byte control on the same frame derives UDP
  and does not match. Fails if the derivation returns the sentinel or the
  wrong protocol.
- `h18_14239_live_forward_fragment_uses_frame_derived_ingress_protocol`
  (`afxdp/tests_fragment.rs`): drives the immediate production caller
  `build_live_forward_request_from_frame` with the same real fragment; the
  TCP fragment is dropped by the frame-derived ingress policer (no request
  built) and the UDP control is forwarded off the EF queue. Fails if the
  derivation or this caller's `flowless_ingress` wiring is reverted.

Residual: the deferred `neighbor_dispatch::retry_pending_neigh` caller was not
given a dedicated cell; a full flush harness needs the pending-neighbor
schedule armed / cross-binding UMEM / egress-MTU fixture plumbing, and the
attempted cell could not distinguish its CoS verdict from unrelated deferred
TX gates in the available time. The deferred caller shares the identical
derivation call and the identical `resolve_cos_tx_selection_at_prenat`
callee now covered through the derivation + immediate caller, so the
protocol-derivation regression protects both wirings' shared core; a
deferred-only wiring revert (passing `None` there) remains uncovered.

Validation: `cargo test --release --manifest-path userspace-dp/Cargo.toml
h18_14239 -- --nocapture` — the two tests above pass (run alongside the
attempted deferred cell during development; final head keeps the two).
Existing `h18_13966*` regressions untouched.
