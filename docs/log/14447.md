# #14447 — DR20-H1 Duplicate `root-login`: `allow` then `deny` installs `PermitRootLogin yes`

## Mechanism
`pkg/config/compiler_system.go` read SSH `root-login` with `FindChild` (first sibling wins). `system { services { ssh { root-login allow; root-login deny; } } }` therefore installed `RootLogin="allow"`, and `pkg/daemon/daemon_hostauth_apply.go:buildSSHDConfigErr` maps `allow -> PermitRootLogin yes`, silently discarding the explicit `deny`. Both orders, duplicates split across two `ssh`/`services` blocks (reader pools them), packed `ssh root-login allow root-login deny;`, and group-group duplicates were strict-accepted. Flat `set` merges duplicates and cannot produce this; hierarchical/load-override/HA-sync/restore preserve siblings.

## Fix
- Reader (`compiler_system.go`): iterate `FindChildren("root-login")`, last sibling wins (Junos semantics). This is the lenient result.
- New gate `validateDuplicateRootLoginAST` (`compiler_validate_duplicate_scalar.go`): runs in `runPreWalkGates` on the group-expanded, inactive-pruned tree (both `CompileConfig` and `CompileConfigForNode` paths). It pools values exactly as the reader does — every `system` root, every `services` child via `packedBodyChildren`, every `ssh` child, with the reader's `expandRun9235` — so braced, packed, split-block, and group-adopted spellings are all counted. ≥2 distinct values: strict rejects naming `root-login`, both values, and `(#14447)`; lenient (`lenientDuplicateRootLogin14447`, only in `lenientCompileOpts`) warns with the same diagnostic and keeps last-wins. Identical repeats pass.
- Group adopt-beside (`group_root_login_14447.go` + `ast_groups.go`): a group `root-login` leaf whose peer was itself group-adopted is adopted beside it (mirroring #12823/#12923 default-policy), so two groups with conflicting values reach the gate instead of resolving by apply order. An inline peer still wins silently (Junos precedence, single effective value).

Scope: only `root-login` (issue scope). The shared-name file is intentionally H1-only here; H2/H3 siblings (#14448/#14449) have their own issues/gates.
