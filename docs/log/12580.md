# #12580 — fail closed on xfrm dump errors in the reshape allowlist

## Why

`UserspaceBoundLinuxInterfaces` is permission to reshape RSS and pin coalescing. A hard xfrm RTM_GETLINK dump failure was logged and swallowed by `sampleLiveXfrmNetdevs`, which returned an empty xfrm set. A stale live xfrmi therefore looked like an ordinary interface to this consumer and could be included in the reshape allowlist. This contradicted the function's documented conservative behavior (nil / touch no NIC on uncertainty).

The apply snapshot has a separate, intentional policy: it continues with config ownership when the kernel xfrm evidence is unavailable. This change preserves that behavior; only the reshape allowlist is made fail-closed.

## Change

- Return the hard-dump-failure status alongside the once-per-snapshot xfrm sample and retain it as private `ConfigSnapshot` derivation metadata (not wire data or snapshot hash input).
- Have `UserspaceBoundLinuxInterfaces` return nil on that failure, before producing reshape permission. A successful dump retains the existing allowlist behavior.
- Add #12580 regression coverage for a stale, zoned `st10` alongside a live LAN: failed dump returns nil; a successful dump keeps the LAN and excludes the live xfrmi. The regression also pins the failure status on the built snapshot and that snapshot building itself remains successful.

## Validation

- RED: `go test ./pkg/dataplane/userspace -run '^TestAllowlistDegradesToNilOnXfrmDumpFailure12580$' -count=1 -v` failed before the fix: the allowlist was `[ge-0-0-0 st10]` instead of nil.
- The same initial probe showed that the ingress map included the stale xfrmi on hard dump failure. That is the existing, documented config-only ingress fallback and is deliberately not changed by this issue; the regression does not assert otherwise.
- `go test ./pkg/dataplane/userspace -count=1` passed (`192.346s`). The failed-dump row checks nil permission and retained failure status; its healthy-dump control checks that the LAN remains while the live xfrmi stays excluded.
- `go test -race ./pkg/dataplane/userspace -run '^TestAllowlistDegradesToNilOnXfrmDumpFailure12580$' -count=1` passed (`1.062s`).
- `go test ./...` was not green: unrelated failures in `pkg/config` (schema/compile cases and `TestSchemaSpellingDifferentialGate` timeout), `pkg/dataplane` (inventory, fake-link, and source-boundary canaries), `pkg/denyaudit` (denial-site count), `pkg/frr` (`setgroups` permission denied), and `pkg/linuxsock` (existing direct socket call canary). The affected `pkg/dataplane/userspace` package passed in the full run (`186.721s`).
- `go vet ./...` passed with no diagnostics.
- `gofmt -l` on all touched Go files and `git diff --check` produced no output.

## Risk

Low. The allowlist now declines all reshape work on a hard xfrm dump failure, potentially leaving RSS/coalescing untouched for that update. Snapshot/ingress fallback and successful-dump behavior are unchanged. No live-cluster mutation performed.
