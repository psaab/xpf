# #12580 — fail closed on xfrm dump errors in the reshape allowlist

## Why

`UserspaceBoundLinuxInterfaces` is permission to reshape RSS and pin coalescing. A hard xfrm RTM_GETLINK dump failure was logged and swallowed by `sampleLiveXfrmNetdevs`, which returned an empty xfrm set. A stale live xfrmi therefore looked like an ordinary interface to this consumer and could be included in the reshape allowlist. This contradicted the function's documented conservative behavior (nil / touch no NIC when the dump reports an error).

The apply snapshot has a separate, intentional policy: it continues with config ownership when the kernel xfrm evidence is unavailable. This change preserves that behavior; only the reshape allowlist is made fail-closed.

## Change

- Return the hard-dump-failure status alongside the once-per-snapshot xfrm sample and retain it as private `ConfigSnapshot` derivation metadata (not wire data or snapshot hash input).
- Have `UserspaceBoundLinuxInterfaces` return nil on that failure, before producing reshape permission. A successful dump retains the existing allowlist behavior. An interrupted dump is not a failure: `xfrmDumpNames` keeps its partial device list, so an xfrmi missing from it is still granted; the degrade-vs-use decision for that case is #12710.
- Add #12580 regression coverage for a stale, zoned `st10` alongside a live LAN: failed dump returns nil; a successful dump keeps the LAN and excludes the live xfrmi. The regression also pins the failure status on the built snapshot and that snapshot building itself remains successful.

## Risk

Operator-visible on a hard xfrm dump failure. The commit still SUCCEEDS (the apply snapshot excludes secure tunnels by configuration ownership alone), but the allowlist is nil, so RSS reshaping and the RSS kill-switch restore, interrupt coalescence, and the released-NIC hand-back (#6801) are skipped until the next apply re-derives the allowlist (the next commit, or the boot-time apply after a restart); nothing retries sooner. A NIC still on its default RSS table (first boot, newly bound, or re-enabled after the kill switch) keeps feeding every hardware queue meanwhile; on a NIC with more than 16 RX queues (`BindingQueuesPerIface`), transit hashed onto queues the planner never binds takes `drop_degraded_transit`. The allowlist logs a WARN naming the skipped work. An interrupted dump still uses its partial device list (#12710). Snapshot/ingress fallback and successful-dump behavior are unchanged. No live-cluster mutation performed.

## #12710 resolution

The interrupted-dump question above is now resolved by #12710. `xfrmDumpNames`
retains known links and reports `ErrDumpInterrupted`; the snapshot classifier
uses known partial xfrmi evidence, while `UserspaceBoundLinuxInterfaces`
withholds the reshape allowlist until the next config apply. Thus the original
PR review notes remain an accurate record of #12580's state at that time, but
the “decision is #12710” residual is closed by `docs/log/12710.md`.
