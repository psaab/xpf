# #16547: runtime interface-SNAT overlap quarantine invisible to NAT show surfaces

- **Timestamp**: 2026-10-24
- **Problem**: The #7717 runtime quarantine (`iface_snat_egress_overlap`)
  stamps `PoolUnusable` on the applied snapshot when a runtime-learned
  (DHCP/netlink) interface address lands inside a source-NAT pool that
  shares egress with an interface-mode rule. Rust maps that to
  `pool_failure` and refuses every new translation for the rule, while
  every NAT show surface (CLI, gRPC/remote CLI, REST, Prometheus)
  derived its NOT INSTALLED verdict from config alone
  (`config.SourceNATRuleNotInstalledReason` → `SourceNATPoolUnusableReason`)
  and reported the rule/pool armed with a 0 hit counter. Recovery
  required reading journald. `InterfaceSNATPoolOverlapStats` (the
  detector's scans/addresses pair) had no non-test consumer.
- **Fix**: `Manager.AppliedNATSnapshotVerdicts` (in
  `pkg/dataplane/userspace/applied_nat_view.go`, forwarded through
  `LegacyDataPlaneAdapter`) projects the last reconciled snapshot's
  per-rule/per-pool/NAT64 `PoolUnusableReason` maps from cached
  in-memory state — no control-socket I/O, so no >1/s request is added.
  It reports unavailable before the first reconciled apply and during
  the deferred-publish window (retained snapshot generation != applied
  generation), so surfaces fall back to the config verdict rather than
  reporting a quarantine the helper has not accepted. A pool is
  reported only when every snapshot row referencing it is unusable.
  `config.SourceNATRuleNotInstalledReasonWithRuntime` /
  `SourceNATPoolNotInstalledReasonWithRuntime` fold the runtime token
  in with config precedence (matching the builder's
  preserve-existing-reason rule). CLI (default, rule, rule-set,
  summary, pool detail, rule detail via
  `natshow.RenderSourceRuleDetailWithRuntime`, NAT64), gRPC
  (`GetNATSource`, `GetNATRuleStats`, `GetNATPoolStats`, ShowText
  detail + NAT64) and REST (`natSourceHandler`, `natRuleStatsHandler`,
  `natPoolStatsHandler`) all consult it; runtime-quarantined rules lose
  their translation-hits line. `SourceNATDisarmReasonText` expands
  `iface_snat_egress_overlap` (the NAT64 twin carries the same token)
  to operator prose. Prometheus exports
  `xpf_iface_snat_overlap_scans_total` (counter) /
  `xpf_iface_snat_overlap_addresses` (gauge; meaningful only when
  scans > 0, per the detector's contract) and
  `xpf_iface_snat_overlap_quarantined{pool}`, and omits a quarantined
  pool's capacity/usage samples exactly like a config-refused pool's.
