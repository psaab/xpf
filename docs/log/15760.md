# Remote CLI and gRPC annotate first-quote split (#15760)

## Why

#14717 gave `annotate` one canonical split — `config.ParseAnnotateCommand` /
`ParseAnnotateRemainder` (`pkg/config/config_command_split_14147.go`): lex the
line with the config lexer, take the comment as the LAST token and only when it
was authored quoted, so a quoted path element stays in the path. The local CLI
(`pkg/cli/cli_dispatch.go`) and the authorization gate
(`configMutationPaths` annotate arm) were migrated; three surfaces were left
on the old first-quote split (`cliterm.AnnotateCommentFromLine`, which splits
at the first `"` and then `strings.Fields` the path text):

- remote CLI (`cmd/cli/shared.go` annotate arm),
- gRPC `Server.Set` annotate branch (`pkg/grpcapi/server_config.go`),
- gRPC authz pre-normalizer (`configMutationLineFor` in
  `pkg/grpcapi/authz_config_regex_9154.go`), which rebuilt the gate line from
  the same flawed split.

For `annotate groups "my group" system "production comment"` the gate
adjudicated path `groups my group system`, but the handler annotated `groups`
with the mangled comment `my group" system "production comment`, and the
remote CLI sent that same truncated wire line. Authorization and mutation
disagreed on any quoted/bracketed path element (the common
`annotate <path> "comment"` shape agreed on both parsers, which is why this
survived). Pre-fix measurement: the new interceptor test's denied quoted-path
annotate was admitted and executed (`err=<nil> handlerCalled=true`).

## What

- `pkg/grpcapi/server_config.go`: `Set` routes `annotate` on the lexed verb
  (`config.ConfigMutationVerb`, so tab/comment spellings route as the gate
  adjudicated) and splits with `config.ParseAnnotateCommand`; usage error on
  a non-canonical shape. The now-unused `cliterm` import is removed.
- `pkg/grpcapi/authz_config_regex_9154.go`: `configMutationLineFor` detects
  `annotate` via `ConfigMutationVerb` and rebuilds the gate line from
  `ParseAnnotateCommand`'s lexed path/comment (every path element quoted,
  comment escaped via `cliterm.EscapeAnnotateComment`), so quotes inside the
  comment still cannot become extra path tokens and the adjudicated path is
  the acted-on path.
- `cmd/cli/shared.go`: the remote annotate arm splits the remainder with
  `config.ParseAnnotateRemainder` and re-joins with
  `JoinConfigPathTokens` (re-quotes tokens that need it), so the wire line
  re-lexes to the same path server-side.
- `cliterm.AnnotateCommentFromLine` itself is unchanged: it remains the
  `pkg/cli` annotate helper's implementation and is pinned by #13628 tests.
  REST annotate is unchanged (JSON `path`/`comment` fields carry no quoting
  to desync; see #14717).

Behaviour delta (deliberate, parity with the local CLI since #14717): a
comment must be authored as ONE quoted token with `\"` escapes for embedded
quotes. The unescaped `"say "hi" team"` spelling now lexes canonically
(path `... say hi`, comment `team` at the gRPC/local surfaces) instead of
being recovered as comment `say "hi" team` by the first-quote split; the
escaped wire form `"say \"hi\" team"` is unchanged and still round-trips.
Two #13628 cells that pinned the unescaped recovery on the migrated surfaces
were updated to pin the canonical behaviour instead (escaped form denied at
the gate / round-tripped on the wire; unescaped form never annotates the
denied node). Unterminated comments remain usage errors.

## Risk

Narrow: only the `annotate` verb on the remote CLI, gRPC Set handler, and
gRPC gate pre-normalizer. No store, lexer, REST, or local-CLI change. The
one operator-visible delta is the unescaped embedded-quote spelling above,
which now follows the same lexer rule the gate and local CLI already
applied; the escaped spelling (what the remote CLI itself emits) is
unchanged.
