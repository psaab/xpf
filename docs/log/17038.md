# #17038 — single derivation for an established flow's input-filter log source

- **Timestamp**: 2026-10-27
  - **Action**: The two log-only derivations of an established flow's input-filter `then log` record disagreed on source: the flow-cache seed capture (`evaluate_non_pbr_input_filter_log_only`, filter.rs) built a `CachedInputFilterLog` with no source and the cache replay (`emit_cached_input_filter_log`) hard-coded `FilterLogSource::Input`, while the uncached static hit (`static_hit_log_for_action`, #15949) derived `FilterLogSource::Pbr` for a routing-instance term — so one PBR-steered flow's reason byte (Pbr=1 vs Input=2 on the wire) flipped with flow-cache residency. Fix: added `source: FilterLogSource` to `CachedInputFilterLog` (flow_cache.rs); replaced both accept-path derivations with the single `established_input_filter_log(forwarding, filter, flow, meta, zone_override, logical_ifindex, extra, final_action)` (copy B's body, including the #16502 (0,0) ports rule and the `final_action` rewrite); `static_hit_log`/`static_hit_log_for_action` are now thin wrappers returning the record's frozen source; both seed sites in flow_cache_seed.rs (forward + deny) resolve the ingress filter and call the same helper; `emit_cached_input_filter_log` passes `cached_log.source`. The deny-path counted sites stamp `source: Pbr` beside their existing `log_source: Pbr`, and the non-routing counted eval stamps `Input`. Updated the stale README sentence ("Cached PBR logs replay with the `Input` source") and the poll-loop comment naming the removed function. Added the hermetic parity cell `pbr_log_source_agrees_across_hit_seed_and_cache_replay_17038` driving one PBR-term `then log` flow through the uncached established hit, the seed capture, and the cache-replay emit (real event stream, wire `reason` byte), asserting the same `wire_reason()` as the session-MISS `Pbr` constant, with a plain-term `Input` control.
