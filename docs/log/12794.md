# Issue #12794 — key remaining shard and disposition placement

## Root cause

Three attacker-influenced placements still used FxHasher after the earlier keyed-hash migrations: dynamic-neighbor shard selection, steering-row owner/holdings shard selection, and the recent-exception sampler key. Mixing a process seed into FxHasher is additive, so it does not remove seed-independent key-delta collision families. In the exception sampler, those collisions can also force unrelated denied packets to contend for a fixed gate slot.

## What changed

- Replaced the three placement hashes with the established `HotPathSeededState` SipHash builder and the shared process hot-path seed. Neighbor and steering shard selection still masks to the same 64-way shard count; exception sampling still hashes reason, optional suffix, tuple fields, and protocol/family without allocations.
- Added seed-pinned v6 s3-family dispersion and seed-sensitivity coverage for neighbor shards, steering-row shards, and exception gate slots, with pinned SipHash output vectors for each placement path.

## Validation

- `cargo test --bin xpf-userspace-dp 12794` — passed (3 tests).
- `cargo test --bin xpf-userspace-dp afxdp::sharded_neighbor` — passed (58 tests).
- `cargo test --bin xpf-userspace-dp afxdp::bpf_map::steering_owners` — passed (19 tests).
- `cargo test --bin xpf-userspace-dp afxdp::disposition` — passed (6 tests).
- Fx-revert mutant experiment — reverted all three seeded cores to seed-additive FxHasher and ran `cargo test --bin xpf-userspace-dp 12794`; all 3 tests failed on their pinned vectors (neighbor IPv4 shard 60 vs 11, steering row shard 25 vs 3, exception sampler key 2045620831516866929 vs 173452051336367422). Restored keyed SipHash after the experiment.
- Full crate suite, Clippy, and rustfmt checks were not run by this worker.

## Risk

SipHash costs more than FxHasher. This computation is limited to the existing shard-selection and exception-sampling sites; the shard counts, map structure, and sampler behavior are unchanged. The process-local seed can change mappings on restart, which only reassigns entries in these local in-memory structures.
