# #16814 — Accept Junos ALG tuning statements with an inert advisory

## Why

The five modeled ALG classes accepted only `disable`, while entirely unmodeled
classes accepted opaque Junos bodies with the #4232 advisory. Migrating a DNS
`doctoring none`, FTP `ftps-extension`, SIP timeout/screen, or PPTP trace stanza
therefore failed strict commit even though xpf's accepted-but-inert contract
already covers unimplemented ALG behavior.

## What

- Declare documented statement heads for DNS, FTP, SIP, TFTP, and PPTP. Their
  bodies remain opaque and do not configure runtime behavior.
- Validate the modeled class boundary explicitly in flat, braced, and packed
  forms. Unknown class-level statements such as `ftp desable` still reject;
  a known inert statement is not a wildcard for its braced sibling statements.
- Record each configured inert statement separately from unsupported protocol
  names and emit an accepted-but-inert, no-effect advisory through the existing
  compiled-config warning path. Multiple statements are retained in config
  order and warning labels are deduplicated.
- Read `disable` only at the class boundary. An opaque statement value or nested
  child named `disable` must not disable the entire ALG. Actual class-level
  disable flags preserve their existing behavior and do not receive this advisory.

## Risk / non-goals

This is configuration admission and operator disclosure, not implementation
of DNS doctoring, FTP extensions, SIP screening/timeouts, or ALG tracing.
Opaque bodies are deliberately not type-, range-, or nested-keyword-validated.
Operators must not rely on these admitted statements for enforcement; the
commit advisory explicitly states that they have no effect. Unknown ALG
classes retain their existing acceptance/advisory policy.
