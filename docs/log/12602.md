# Issue #12602 — harden seeded fragment shard indices

- **Change**: Move seed application after the FNV-1a key fold and apply a splitmix64 avalanche before selecting the high shard bits. Fragment-overlap and fragment-association use distinct keyed domains and independently drawn per-process seeds, so disclosure of the shared hot-path seed or of one fragment site's key does not reveal the other site's placements. Shard counts, key fields, capacities, and admission/association semantics are unchanged.
- **Affected sites**: `userspace-dp/src/fragment_overlap/mod.rs` and `userspace-dp/src/fragment_assoc/mod.rs`; both used FNV offset-basis XOR seed followed by the same fixed multiply-shift finalizer. For 16 shards, relative shard relationships depended only on the seed low byte; high seed bytes rotated all keys together. The low-byte leak/offline fixture therefore preserved a targeted collision on 1 in 256 boots.
- **Seed/mapping impact**: Indices are process-local placements, not persisted or exchanged across nodes. Independent seeds stay stable for the process lifetime and keep install/lookup placement consistent. Existing entries naturally expire with the structures/process; a restart already selected new seeds. No on-wire or HA mapping changes.
- **Distribution evidence**: The regenerated seed-zero attack fixture puts 32/32 keys in shard 5 under the old seeded multiply-shift mapping; the hardened mapping at seed 1 spreads it over 15/16 shards, maximum occupancy 3. A second set precomputed for old seed `0x5c` puts 32/32 keys in shard 5, and remains concentrated in only 1–2 shards as each high seed byte varies; this set is asserted in the regression. The deterministic 8,192-key vector at seeds 0, 1, `0x5c`, and `0xdead_beef_c0de_f00d` reaches all 16 shards; observed min/max counts are 484/544, 452/562, 477/564, and 487/544 (512 expected per shard).
- **Validation**: `cargo test --manifest-path userspace-dp/Cargo.toml fragment_overlap::` passed (32 tests); `cargo test --manifest-path userspace-dp/Cargo.toml nat64::tests::` passed (203 tests); both targeted high-seed-byte regressions passed; production `cargo check` passed. Replacing each site with the previous seeded-FNV/multiply-shift implementation made its regression fail: overlap (`spread=1, max=32` at seed `0x5c`) and association (`74/256` matches for a legacy-colliding key). Restoring the hardened implementation passed both. Workspace-wide `cargo fmt --check` and changed-file `rustfmt --check` report existing formatting drift, so no broad formatting rewrite was made. No live-cluster or hardware tests were run.
- **Risk**: Per-process shard assignments change, but both structures are node-local and ephemeral. No allocation or extra per-packet key serialization was added; each index calculation adds a fixed-cost 64-bit avalanche.
