## Why

DHCPv4 relay `deliverReply` (pkg/dhcprelay/relay.go) in the flag-clear,
yiaddr==0, ciaddr!=0 row unicast the server reply via
`clientConn.WriteTo(replyData, ciaddr:68)` with no validation of ciaddr.
The #6562 pending binding keys only on xid+hlen+chaddr
(pkg/dhcprelay/pending.go `pendingKeyFor`), so a configured server — or a
source-spoofer who passes the #4163 allow-list and guesses the xid —
could put 127.0.0.1, 224.0.0.1, 255.255.255.255, 169.254.x, or an
unrelated off-LAN address in ciaddr and make the relay emit a crafted
DHCP payload to it from the SO_BINDTODEVICE client socket. The loopback /
VRF-wide reflection framing was refuted in research (the write is on the
device-bound clientConn, not the giaddr serverConn); the residual defect
is the unvalidated, unbound unicast destination itself.

## What

- pending.go: record the request ciaddr beside the v4 pending entry
  without adding it to `pendingKey` (a DISCOVER carries ciaddr 0 while
  its ACK may carry the leased address, so keying on it would break
  ordinary exchanges). New `insertPending` / `matchesPending` /
  `requestCiaddr` free functions (Go forbids methods on the instantiated
  `pendingTable` alias), `insertCiaddr` stamping the live entry and its
  owning ring slot, ciaddr carried through `snapshot`/`adopt`
  (`pushLockedCiaddr`) so a config reload does not lose it. Generic
  insert/matches discipline unchanged; v6 entries carry zero ciaddr.
- relay.go: client loop now `insertPending`; reply loop uses
  `matchesPending` and hands the recorded ciaddr to `deliverReply` via
  `interfaceRelay.pendingRequestCiaddr` (server-reply goroutine only).
  The ciaddr row now requires `ciaddr.IsGlobalUnicast()` (admits RFC1918,
  rejects loopback/multicast/broadcast/link-local/unspecified; Go's
  IsGlobalUnicast returns true for 192.0.2.9, so the pending equality is
  what rejects off-LAN) AND `ciaddrMatchesRequest` equality with the
  recorded request ciaddr. On failure: DROP fail-closed — no WriteTo, no
  broadcast fallback (broadcast would still deliver the payload on-LAN) —
  counted in new `RepliesDroppedBadCiaddr`, warn-once then Debug.
  Honest scope cut: no subnet/on-link check — the relay has no client
  subnet/mask (giaddr resolver discards masks, multi-subnet relaying is
  valid); pending equality already pins the destination to the address
  the client itself claimed in the bound request, strictly stronger.
- Stats/CLI: `RelayStats.RepliesDroppedBadCiaddr` wired through Stats()
  and `adoptCountersFrom`, rendered as `Dropped (bad-ciaddr)` in the
  `show services dhcp relay` #6562 section; byte-stable CLI test updated.
- Existing delivery-matrix / exactly-one-send tests and `armedRelay`
  set `pendingRequestCiaddr` from the packet (mirroring production's
  matchesPending handoff); counters-preservation test covers the new
  counter. NAK / broadcast-flag / always-broadcast / L2-yiaddr rows are
  untouched and still precede the ciaddr row.

## Validation

- RED on pristine base worktree (origin/master 805ac16cd, separate
  worktree, never stash): probe driving `deliverReply` with a recording
  PacketConn showed WriteTo attempted for ciaddr 127.0.0.1, 224.0.0.1,
  255.255.255.255, 169.254.10.1 and 192.0.2.9 (all `ok=true writes=1`).
  The new regression file does not compile on base (new symbols absent).
- GREEN in fix worktree: `go test ./pkg/dhcprelay/ -count=1` PASS and
  `go test ./pkg/cli/ -run 'TestWriteDHCPRelayStats|TestShowDHCPRelay'
  -count=1` PASS, including new `TestDeliverReply_BadCiaddrDropped14188`
  (loopback/multicast/broadcast/link-local/off-LAN/wrong-client/no-record
  all dropped, counter=1, zero writes), `TestDeliverReply_GoodCiaddrStillUnicasts14188`,
  `TestPendingRecordsRequestCiaddr14188` (record, zero-ciaddr DISCOVER,
  expiry, snapshot/adopt), `TestHandleServerResponses_BadCiaddrDropped14188`
  (end-to-end spoofed vs matching ciaddr), and the pre-existing
  `TestRelay_NormalExchange_EndToEndStillRelays` (RENEW/REBIND ciaddr
  unicast still works through production insert/match).
- Full suites: `go test ./pkg/cli/ -count=1` PASS on the fix tree and
  PASS on pristine base (805ac16cd) — an earlier combined
  dhcprelay+cli run failed in pkg/cli under parallel load; both trees
  pass standalone, so that failure is flaky/base-attributed, not this
  change. `go vet ./pkg/dhcprelay/ ./pkg/cli/` clean, `gofmt -l` clean,
  and the new tests pass under `-race`.

## Risk

- A non-conformant server that answers INFORM/RENEW with a ciaddr
  different from the request's (NAT-translated or buggy) now has that
  reply dropped and counted instead of unicast; the client retransmits
  and the operator sees `Dropped (bad-ciaddr)` rising. This is the
  intended fail-closed trade: the destination is no longer
  server-chosen.
- yiaddr L2 path unchanged: RFC 2131 Table 3 makes yiaddr server-assigned
  for the bound chaddr, a different trust class from the ciaddr row.
