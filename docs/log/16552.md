# #16552: `show security address-book` renders only `Address.Value`

- **Timestamp**: 2026-10-24
- **Problem**: The local CLI, gRPC ShowText and REST show-text each
  printed only `Address.Value`. #15673 made `dns-name` /
  `range-address` / `wildcard-address` enforceable with `Value` empty
  by design, so every such entry printed blank, and a resolved
  dns-name was byte-identical to an unresolved (match-none) one — a
  deny policy that silently stopped matching could not be detected
  from the operator's only address-book view.
- **Fix**: One shared renderer, `config.RenderAddressBook` /
  `AddressDisplayValue` (`pkg/config/show_address_book_16552.go`),
  now called by all three surfaces (CLI unfiltered listing delegates;
  its filtered/set-member detail uses `AddressDisplayValue`). Each
  entry prints its authored form — `dns-name X [ipv4-only]`,
  `range-address A to B`, `wildcard-address W` — plus the enforced
  set from `UsableValues()`, an explicit
  `unresolved — matches nothing` marker when that set is empty, or
  `NOT ENFORCED: <taint>` (unsupported form / oversized range /
  duplicate prefixes / trailing tokens) for tainted entries.
  `Address.RangeSpec` / `WildcardSpec` (`json:"-"`, compiler
  metadata) retain the authored range/wildcard specification next to
  `ExpandedPrefixes` (populated in `applyRangeAddress` /
  `applyWildcardAddress`, copied by the zone-local fold), since the
  expansion alone cannot reconstruct it. Nil map slots stay skipped
  (#7197/#10439/#12903); gRPC/CLI iteration is now sorted like REST.
