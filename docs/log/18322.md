# Issue #18322 — publish priority-tagged VID-0 ingress domains

- **Timestamp:** 2026-10-28
- **Action:** Published the priority-tagged VID-0 routing-domain row needed by the #12055 tagged-only local guard, and completed the #14842 per-wire-VID rows in the PROG_RUN fixture. Packet expectations remain unchanged.
- **Files:** `pkg/dataplane/userspace/maps_sync.go`; `pkg/dataplane/userspace/ingress_domains_vlan_14842_test.go`; `pkg/dataplane/userspace/tagged_only_local_drop_12055_test.go`; `docs/log/18322.md`.
- **Root cause:** Two connected defects in the `(ifindex, wire VLAN)` domain contract. The #14842 producer emitted nonzero VLAN-unit rows and `0xffff` untagged rows, but no `{ifindex, 0}` row for a tagged-only parent. The shim preserves priority-tagged VID 0 as key 0; without a row, `ingress_domain_for` returns `u32::MAX`, so `is_tagged_only_vid0_firewall_owned_destination` cannot match domain-scoped local/interface-NAT addresses and falls through to XSK redirect. The pre-fix PROG_RUN fixture manually seeded only `{ifindex, 0xffff}`, omitting wire VID keys 0, 50, and 100. The five tagged local rows use VID 50 or 100 (`singleTagIPv4UDP` writes TCI VID 100); absent keys miss local addresses and the harness's absent XSK socket produces `redirect_err`/`transit_drop` or action `1` rather than expected `XDP_PASS` (`2`). Thus there is a production producer mismatch for VID 0 and fixture omissions for all tagged VIDs. Kernel 7.2.12 PROG_RUN semantics and the expected packet dispositions are correct.
- **RED (origin/master `69dacd5292e1779cc4271f03a7407b470e260967`, kernel `7.2.12+deb14-amd64`):** The named test ran all 21 table rows. Seven failed: `priority-tagged_local_ipv4_drops` and `priority-tagged_interface-nat_ipv6_echo_drops` reported `degraded path stat "tagged_only_local_drop" = 0, want incremented. Reasons that DID fire: redirect_err=1 transit_drop=1`; five tagged local/interface-NAT rows reported `action = 1, want 2` (`tagged_interface-nat_ipv6_echo_remains_local`, `tagged_interface-nat_ipv4_echo_remains_local`, `tagged_interface-nat_ipv4_ESP_remains_local`, `tagged_interface-nat_ipv6_ESP_remains_local`, `tagged_local_ipv4_remains_local`). The other 14 rows passed.
- **Change:** `buildUserspaceIngressDomainEntries` publishes `{tagged-only parent ifindex, VID 0}` with the parent's untagged domain, preserving the shim's distinct VID-0 key without assigning a nonzero VLAN unit's domain to it. The PROG_RUN fixture now calls that same producer with parent + VLAN units 50 and 100, so it seeds exactly the production VID-0/VID-50/VID-100 and untagged rows. The producer regression asserts the VID-0 alias for a tagged-only parent and its absence for native-VLAN and ordinary parents.
