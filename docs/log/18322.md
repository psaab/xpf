# Issue #18322 — publish priority-tagged VID-0 ingress domains

- **Timestamp:** 2026-10-28
- **Action:** Scoped the priority-tagged VID-0 domain alias to the same unambiguous, enabled, zoned native-VLAN ownership decision used by tagged-only selection; unzoned and ambiguous native units now publish no VID-0 row.
- **Files:** `pkg/dataplane/userspace/maps_sync.go`; `pkg/dataplane/userspace/ingress_domains_vlan_14842_test.go`; `pkg/dataplane/userspace/tagged_only_local_drop_12055_test.go`; `docs/log/18322.md`.
- **Adjudication:** At merge-base `001c5507c5`, `{parent, 0xffff}` publication for unzoned native units is pre-existing base behavior: `maps_sync.go:220-232` documents that a native-VLAN unit owns its parent's untagged arrivals. This untagged row is deliberately unchanged and outside #18322; the PR's only new publication is the distinct `{parent, 0}` alias for priority-tagged VID 0. The negative cases therefore require `{parent, 0}` absent while asserting `{parent, 0xffff}` remains present.
- **Root cause:** The initial #18322 producer filled the tagged-only VID-0 gap by aliasing any tagged-only parent with an untagged-domain row. Tagged-only selection deliberately retains parents whose native VLAN has no valid owner, including unzoned and ambiguous native units, so their VID-0 wire key could incorrectly inherit an unzoned unit's or poisoned native mapping instead of remaining absent and failing closed in the shim. The #14842 producer otherwise emits per-wire-VID and `0xffff` untagged rows; the shim preserves priority-tagged VID 0 as key 0, and `ingress_domain_for` returns `u32::MAX` when that key is absent. The original PROG_RUN fixture also manually seeded only `{ifindex, 0xffff}`, omitting wire VID keys 0, 50, and 100; the tagged-frame test rows therefore needed the production domain-row builder.
- **RED (origin/master `69dacd5292e1779cc4271f03a7407b470e260967`; PR parent `001c5507c5`, corroborated identical; kernel `7.2.12+deb14-amd64`):** The named test ran all 21 table rows. Seven failed: `priority-tagged_local_ipv4_drops` and `priority-tagged_interface-nat_ipv6_echo_drops` reported `degraded path stat "tagged_only_local_drop" = 0, want incremented. Reasons that DID fire: redirect_err=1 transit_drop=1`; five tagged local/interface-NAT rows reported `action = 1, want 2` (`tagged_interface-nat_ipv6_echo_remains_local`, `tagged_interface-nat_ipv4_echo_remains_local`, `tagged_interface-nat_ipv4_ESP_remains_local`, `tagged_interface-nat_ipv6_ESP_remains_local`, `tagged_local_ipv4_remains_local`). The other 14 rows passed.
- **Change:** `buildUserspaceNativeVLANOwnership` centralizes the configured native-VLAN owner predicate (exactly one matching enabled, zoned unit; conflicting claims or units remain unowned) for both tagged-only selection and VID-0 publication. The alias builder now skips parents with unresolved native ownership, preserving a fail-closed absent `{parent, 0}` row for unzoned and ambiguous native cases while retaining the no-native-claim tagged-only positive path. Regressions cover both negative cases and retain the zoned native-owner and ordinary-parent checks. The PROG_RUN fixture continues to use the production builder for VID 0, VID 50, VID 100, and untagged rows.
