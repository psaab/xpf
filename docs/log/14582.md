# 14582 — Web-management interface bind resolved before networkd, never re-resolved (Y07-01)

- **Issue:** `reconcileWebManagement` runs early in `applyConfigLocked`
  (deliberately, for credential revocation) before
  `applyDataplaneAndHACore`/networkd applies interface addresses.
  `resolveInterfaceAddr` read the live kernel, found no address yet, and
  fell back to loopback; the fingerprint recorded that loopback bind as
  converged, `show system services` reported Listening, and the 30s
  re-assert owner (gated on `StateFailed`) never re-drove it. The DHCP
  lifeline fast path in `onDHCPAddressChange` likewise skipped
  web-management, so a lease change to a new address left the leg on the
  stale address. Off-box REST/J-Web stayed silently down until a later
  commit while the box reported healthy (fails closed to loopback; no
  exposure).
- **Base:** `6d677287a` (`origin/master` at branch creation).
- **Branch:** `fix/14582-webmgmt-rebind`.
- **Worktree:** `/var/worktrees/wt-14582`.

## Root cause

Verified RED [INFERENCE-free, executed]: a probe driving the real
`reconcileWebManagement` + `reassertMgmtListenersOnce` with the kernel
seam (`interfaceAddrsByName`) initially empty showed the HTTPS leg bound
to `127.0.0.1:443`, reported Listening (`down=false`), and unchanged
after the address appeared and a re-assert tick ran — the fingerprint
equality (`next == cur`) plus the `StateFailed`-only gate made the stale
resolution permanent.

## Fix

- `daemon_cluster_bind.go`: `resolveInterfaceAddrDegraded` returns
  `(addr, degraded)`; `resolveInterfaceAddr` delegates (other callers
  unchanged). degraded = loopback fallback because the kernel lookup
  failed or found no usable address.
- `daemon_run_servers.go` (`resolveAPIBinds`): records degraded per leg
  on `api.Config.HTTPBindDegraded`/`HTTPSBindDegraded`.
- `management.go`: `mgmtEndpoint` carries `httpDegraded`/`httpsDegraded`;
  `desired()` resets them per derivation; `reconcileTo` treats a degraded
  change as a leg change and advances the flag only on a successful
  rebind; `effective{HTTP,HTTPS}Listener` reports a degraded (loopback-
  fallback) leg `StateStale` — never Listening — so the operator view,
  the `xpf_management_listener_state` metric (same snapshot), and
  `mgmtListenerDown` all agree, and the #6803 30s owner re-drives until
  the bind lands on the interface address. Auth safety is unchanged: the
  fallback is loopback, `publishNilDirectionLocked`'s `allLoopback` still
  gates the nil publish, and the degraded→real rebind goes through the
  existing sanctioned/intersection logic.
- `daemon_apply.go`: a second `reconcileWebManagement(cfg)` after
  `applyDataplaneAndHACore` (before the tail) re-resolves once networkd
  has applied addresses in the same commit. Warn-only, mirroring the
  early reconcile — a still-missing address is retry debt for the owner,
  not a commit failure.
- `daemon_dhcp.go`: `rebindWebMgmtForLeaseChange` on the
  management-only fast path (the #2884 shape): gated by
  `webMgmtBindsToDHCPInterface` (bound interface has a DHCP/DHCPv6 unit,
  via `SplitInterfaceUnitRef`), serialized under `applySem`, re-reads the
  active config under the semaphore, non-fatal. Seam
  `webMgmtRebindApply` mirrors `mgmtReassertApply`.
