# #13712: lease the removed session's reverse tuple before conntrack teardown

Base: `origin/master` 72e65611f. Regression RED was first established on pristine 02ba5b23c before rebasing. The current patch rebases cleanly onto latest master. Worktree `/var/worktrees/campaign-zero/wt-13712`, branch `fix/13712-campaign`.

## Finding

The delete path snapshots `candidate_entry` before taking its tuple-gate lease. It used that stale snapshot's NAT decision to choose the reverse tuple, then derived the reverse key for BPF teardown from the entry actually removed under the shared-map lock. If an upsert installs a NAT session between those operations, the delete can remove the NATed reverse conntrack row without holding that row's tuple-gate lease.

## Change

The under-lock removal predicate now checks that its lease covers the reverse tuple derived from the exact current entry. If an intervening NAT change made the lease stale, it declines removal with `RefusedGateBusy`; the existing whole-delete refusal return exits before conntrack teardown, shared companion removal, or worker command fan-out. This follows the same lease coverage check pattern as the policy-batch tuple repair paths. `forward_only`, reverse entries, and clear-fence deletes retain their existing behavior.

## Regression

`userspace-dp/src/afxdp/ha_tests.rs::synced_delete_refuses_when_nat_lands_after_candidate_read_13712` uses the existing deterministic post-snapshot hook to install a NATed forward session and reverse companion after the delete snapshots an absent key. It checks the retryable refusal and verifies both shared rows and worker queues remain untouched.
