# #11684 — Forwarding-instance global gateways resolve in Rust

- **Timestamp**: 2026-10-02

The exact `forwarding_tables` marker and routing-domain checks remain required; ordinary cross-VRF interface binding remains unresolved.
- **File(s)**: `pkg/dataplane/userspace/protocol.go`, `userspace-dp/src/afxdp/forwarding_build/fib.rs`, `userspace-dp/src/afxdp/forwarding_build/tests.rs`, `userspace-dp/src/afxdp/types/forwarding.rs`, `userspace-dp/src/protocol/snapshot.rs`, `userspace-dp/src/afxdp/forwarding/README.md`.

## Route scope

The build-time explicit-interface resolver now admits a parsed gateway through a default-instance interface only when the route's exact canonical table is marked as a forwarding-instance table and the interface is in routing domain 0. This applies to qualified global IPv4 and IPv6 gateways; bare gateways remain table-local. The Rust build test models Go's `ISP-B.inet.0` and `ISP-B.inet6.0` defaults using `172.16.80.1@reth0.80` and `2001:db8:80::1@reth0.80`, and proves both produce egress ifindex 101 and `ForwardCandidate`. It also proves an `ISP-B` marker does not authorize those default-interface gateways in `VRF-A.inet.0` or `VRF-A.inet6.0`.
