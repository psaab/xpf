# Issue #14121: `routing-instance` PBR `count`/`log` on established hits

- **Timestamp**: 2026-10-16T20:16Z
- **Action**: fixed the flow-cache seed capture so a matched PBR (`routing-instance`) term's `then count` and `then log` are frozen into the cached descriptor and replayed on every flow-cache HIT. `capture_input_filter_counters_v4/v6` (`userspace-dp/src/filter/engine/cache_sensitive.rs`) now pushes the PBR term's counter before stopping at the steering term (fall-through counters before it were already collected); `evaluate_filter_ref_log_match` (`userspace-dp/src/filter/engine/eval.rs`) now records the PBR term's own log match for the cache-seed capture instead of breaking with `None`. The cold path is unchanged: the routing evaluator still counts/logs the first packet, seed charging stays exactly-once via `seed_packet_already_counted`, and terminal-deny session-hit revalidation still uses the counted routing walk (no double count). Cached PBR logs replay with the `Input` source (the descriptor carries no source field); the cold packet keeps `Pbr`.

The former `interface_filter_log_match_skips_pbr_terms_without_double_emit` expectation (`None`) was the defect itself and is replaced.
