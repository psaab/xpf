# Issue #16663: chassis-cluster raw-AST commit gates bypassed by `chassis cluster { }` spelling

- **Timestamp**: 2026-10-25
  - **Action**: The four chassis-cluster raw-AST commit gates in `runPreWalkGates` (monitor weight #6588, RG/node identity #5694, no-argument RG statement arity #6588, gratuitous-arp-count #5695) walked only `forEachChild(chassis.Children, "cluster", ...)`, so the `chassis cluster { ... }` brace-top-level and packed spellings that #6672 made compile — whose `cluster` keyword sits on the chassis node's own Keys — bypassed every gate while `compileChassis` compiled the body via `normalizedClusterNode`. A typo'd interface-monitor weight (`weight 25O`) committed as weight 0 (link-down deducts nothing, the RG never demotes), duplicate monitors, malformed redundancy-group / per-RG node ids and `preempt delay` all committed while the container spelling rejected them. Fixed by resolving the cluster body through `normalizedClusterNode` — the same view `compileChassis` and the #16456 unknown-statement gate already read — in all four gates (`validateMonitorWeightTokensAST`, `validateChassisClusterIdentitiesAST`, `validateRGNoArgStatementsAST`, `validateGratuitousARPCountAST`), with a shared `chassisNodes` helper. Strict commit now rejects identically in every spelling in `clusterSpellings` (container, packed-in-chassis, packed-top-level, brace-top-level); the tolerant load / peer-sync path keeps warning (#1960). New table test `chassis_cluster_spelling_gates_16663_test.go` asserts every gate rejects the same fixture in all spellings with the container message, the GARP gate warns in all spellings, a valid body commits everywhere, and the lenient path warns in the previously-escaping spellings.
