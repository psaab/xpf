# Issue #15699: EventReader text fanout drops wire decision timestamp

- **Timestamp**: 2026-10-19
- **Problem**: `EventReader.logEvent` decoded the on-wire dataplane decision timestamp into `rec.Time` (`eventTimeFromWire`, #2470/#2511) and honored it in `EventBuffer`, `elapsed-time` and binary records, but the text fanout called `SyslogClient.SendFromEventReader(severity, msg)` and `LocalLogWriter.SendFromEventReader(severity, msg)` with no timestamp. Both sinks stamped `time.Now()` when their async worker dequeued the item (`SyslogClient.Send`, `LocalLogWriter.Send`), so under queue backlog the RFC 5424 / RFC 3164 / local-file header timestamp was systematically late and forensic ordering was falsified.
- **Fix**: Thread `ts time.Time` through the event-reader paths. `auditItem` (`audit_async_writer_9025.go`) and `syslogEventWrite` (`syslog.go`) each gain a `ts` field; `SyslogClient.SendFromEventReaderAt(ts, severity, msg)` / `LocalLogWriter.SendFromEventReaderAt(ts, severity, msg)` carry it through the bounded queues (the pre-existing `SendFromEventReader` delegates with a zero ts); `SyslogClient.SendAt(at, severity, msg)` / `LocalLogWriter.SendAt(at, severity, msg)` format the header from `at` (the pre-existing `Send` delegates with a zero at). A zero `at` falls back to now (`SyslogClient` via its `now()` clock seam), preserving the direct-caller contract (aggregator `ForwardLogMsg`, `SyslogSlogHandler`); a non-zero `at` is normalized to local time, the location the pre-fix `time.Now()` stamps carried (`rec.Time` is built by `time.Unix`, also local). `logEvent` now passes `rec.Time` at both text fanout sites. Binary paths are untouched — they already embed `rec.Time.UnixNano()` — and `TraceWriter` is untouched (it already formats `rec.Time` synchronously in `formatTrace`).
- **Regression check**: New `pkg/logging/event_decision_time_15699_test.go` feeds a SESSION_OPEN frame stamped `2026-01-02T03:04:05.678Z` through `ProcessRawEvent` and asserts the decision timestamp (local rendering) in the emitted header for both sinks across `sd-syslog`, standard and `structured` formats, plus direct/async `SendAt`/`SendFromEventReaderAt` cells and the zero-ts fallback.

## RED -> GREEN proof

- **RED** (production fix reverted via a worktree-local patch file, fanout-only test cells kept): `go test ./pkg/logging/ -run 'TestEventReaderPreservesWireDecisionTimeSyslog15699|TestEventReaderPreservesWireDecisionTimeLocal15699'` failed for every format — e.g. local `sd-syslog` got `<134>1 2026-10-19T16:02:35.465-07:00 …` (dequeue wall clock) instead of the `2026-01-01T19:04:05.678-08:00` decision stamp; the full test file also fails to build pre-fix (`SendAt`/`SendFromEventReaderAt` undefined).
- **GREEN**: Same command plus the At-variant cells passes after the fix; full `go test ./pkg/logging/ -count=1` passes (9.5s).
