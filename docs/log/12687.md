# #12687 — fail closed on malformed inherited route-filters

## Root cause

The strict packed-term recovery from #12537 preserves group-inherited route-filter
operands so the strict validator can reject them. On tolerant load and peer sync,
however, the route-filter gate only warned. A compiled inherited `upto /bogus`
kept `Action=accept` with `UptoLen=0`, which renders as an open-ended match; a
malformed inherited prefix-length range also retained the permit action.

## Change

- Carry `InheritedFrom` through synthesized packed policy-term clauses, and mark
  compiled route-filters that came from an applied group.
- When the existing tolerant route-filter validation warns, force only affected
  inherited invalid route-filter terms to `reject`; valid inherited filters and
  direct-form quarantine behavior remain unchanged.
- Add SyncApply cells for invalid inherited `upto`, range, and malformed
  `through` operands, plus valid inherited `upto /24` and valid `through`
  behavior controls.
- Document tolerant warn-and-reject behavior in the schema guide and changelog.
