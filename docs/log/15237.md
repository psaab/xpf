# #15237 — cli: fix cohort — config-mode navigation parity (A53-02, A53-03, A53-04, A53-06, A53-07)

## Why

Five MATERIAL findings from the A53 deep-review cohort, all in
config-mode navigation/completion/value fidelity:

- **A53-02:** `up` popped ONE TOKEN. From
  `[edit security zones security-zone trust]` it landed at
  `[edit security zones security-zone]`, and the next `set` staged a
  zone named after the following token (candidate pollution; fails
  closed at commit check, but the prompt lied).
- **A53-03:** remote `exit`/`quit` called ExitConfigure regardless of
  edit depth and never checked Dirty; staged work was silently lost.
  The local CLI already warned at the top level but likewise exited
  from any depth.
- **A53-04:** `rename … policy deny-ssh to policy deny-ssh-v2`
  detached the policy into a root `policy` stanza; `copy interfaces
  ge-0/0/0 to ge-0/0/2` created a root `ge-0/0/2`. Commit check
  refused the result, and deleting the junk stanza deleted the moved
  policy.
- **A53-06:** under `[edit system]`, `set host<TAB>` offered nothing
  and `set inter` offered top-level `interfaces`; the remote
  CompleteRequest carried no edit path, and both completion engines
  walked the schema from the root.
- **A53-07:** `set … message "a b"` / PSK / description values had
  interior whitespace collapsed by strings.Fields+Join on the remote
  path (and by unquoted re-join on the local path), unlike
  `load set terminal`; a secret with doubled spaces silently
  differed from the peer's.

## What

- `pkg/config/schema_complete.go`: `PopEditPathIdentity` /
  `TruncateEditPathIdentities` / `editIdentityStarts` — segment an
  edit path into schema identities (keyword + args + compoundKey
  sub-token, the same walk `ResolveConsumedSetPathTokens` uses) and
  pop/truncate whole identities. `QuoteConfigPathToken` /
  `JoinConfigPathTokens` re-join resolved tokens quoting any token
  that would not re-lex as itself.
- `pkg/config/authz_config_mutation_9154.go`:
  `ResolveTopUpPrefix15082` now counts `up [n]` in identities for
  both bare and prefixed forms (prefixed over-count still fails
  closed), so the gate and both executors agree on the target.
- `pkg/configstore/store_lock.go`: `NavigateUp` pops an identity.
- `pkg/config/ast_edit.go`: `BareDestinationParent` — a destination
  with `len(dst)==nk` inherits the SOURCE parent instead of the
  root — applied in CopyPath and RenamePath; plus
  `CopyRenameDstIdentityLen` / `PrependEditPathForCopyDst` so CLI
  surfaces do not prepend the cursor to a bare destination.
- `pkg/cli/cli_dispatch.go`, `pkg/cli/cli_config.go`,
  `cmd/cli/shared.go`: `exit`/`quit` at a non-empty edit path behave
  like `up` (stay in config mode, print the new `[edit …]`); at the
  top, the existing local dirty warning stays and the remote warns
  via GetConfigModeStatus before the (transactional, #5812) release.
  Local/remote `set` re-join with quoted tokens; the remote sends
  the RAW remainder after the verb with lexed cursor tokens
  prepended, preserving quoted whitespace byte-for-byte.
- `proto/xpf/v1/xpf.proto` + regenerated `xpf.pb.go`:
  `CompleteRequest.edit_path = 4` (repeated string; absent = root,
  so old clients keep prior behaviour). Remote completer and `?`
  listener send the normalized cursor.
- `pkg/grpcapi/server_cluster.go`, `pkg/cli/completion_authz_14988.go`:
  config-mode completion prices the effective (cursor+typed) path
  and walks the schema from the cursor.

NOT changed: the store candidate/lock lifecycle, EOF/teardown
best-effort exit paths, operational completion, and any destination
with an explicit parent (longest-match resolution and collision
guards untouched).

## Risk

- Behaviour delta is confined to config-mode navigation verbs,
  copy/rename bare destinations, config-mode completion, and
  quoted-value re-joining. `exit` at depth no longer releases the
  lock (operators scripting `exit` to leave config mode from a deep
  cursor now need repeated exits / `top` then `exit`, matching
  Junos).
- Wire: `CompleteRequest.edit_path` is additive (field 4); old
  servers ignore it and old clients get root completion as before.
