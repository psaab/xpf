**Mutants of the guard.** Cycle 1 corrected this section: the cycle-0 text
called M3 a coverage gap, which was wrong (review R13-2, R8-F1).

The lock and writer census, at the guard in `stopClusterCommsWithFinalizer`:
- `clusterCommsGen` has exactly two writers:
  - `beginClusterCommsEpoch`, which bumps it under `clusterCommsLifecycleMu`;
  - the stop's own increment, serialized against other stops by
    `clusterCommsStopMu`.
- `d.sessionSync` becomes non-nil only in `publishSessionSyncIfCurrent`, and
  only when `gen == clusterCommsGen`. Every other write stores nil.
- The stop holds `clusterCommsLifecycleMu` from its re-capture through the guard
  and the finalizer. Every early return in between unlocks first.
- A begin that lands between the stop's increment and that lock is caught by
  the re-capture, which returns false before the clear.

So whenever the guard is reached, the generation is `stopGen` and
`d.sessionSync` is nil. The guard is a defensive assertion that is invariantly
true under `clusterCommsLifecycleMu`.

**Blast radius.** Cycle 1 corrected the claim that "the fabric-configured
path is unchanged" (review R13-1, R8-F2). The fixed guard sits in
`stopClusterCommsWithFinalizer`, which has four callers:
- step 20's three `removingFabric` sites in `daemon_apply_tail.go`
  (`reconcileClusterTransportBinding`: the `d.cluster == nil ||
  d.daemonCtx == nil` arm, the zero-key startup arm, and the transport-change
  arm);
- bootstrap rollback, `relinquishClusterForBootstrap` in `bootstrap.go`.

Bootstrap rollback calls the finalizer on EVERY cluster, fabric-configured
or not:
- before #18751 it cleared the fabric watcher unconditionally;
- #18751 (085bc890c1) moved the clear into the finalizer;
- the `== ss` guard then skipped it whenever comms were live.

So on master since the #18719 merge, bootstrap rollback with live comms left
the fabric-segment watcher armed on fabric-configured clusters too. The
`cluster == nil` arm of step 20 did the same. This fix restores the clear on
both paths, which is #18751's stated intent. Only the plain `stopClusterComms`
path (the `else` arm of step 20) is byte-identical.
