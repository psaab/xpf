# #16602: `load merge|set|override` silently drops trailing tokens, including `relative`

- **Timestamp**: 2026-10-25
- **Action**: Both CLIs' `load` handlers took `mode = args[0]` and
  `source = args[1]` and never read `args[2:]`. The documented Junos form
  `load merge terminal relative` — paste a snippet relative to the
  `[edit ...]` cursor — therefore applied the snippet at the root and
  printed `load merge complete`; whenever the snippet was also valid at
  the root it committed clean (a `routing-options static route 0.0.0.0/0`
  meant for `[edit routing-instances RI1]` became a master-table route;
  a group body pasted under `[edit groups G1]` applied device-wide). Any
  trailing garbage (`load merge terminal bogus tokens`) was likewise
  accepted and dropped. Neither the local apply path
  (`LoadSetAsPlantClass`/`LoadMergeAsPlantClass`/`LoadOverrideAsPlantClass`)
  nor the wire (`pb.LoadRequest{Mode, Content}`) carries an edit path, so
  `relative` cannot be honoured without a new wire field and cursor
  prefixing; the bounded fix the issue sanctions is refusal. Both
  `handleLoad` implementations (local console `pkg/cli/cli_config.go`,
  remote `cmd/cli/main.go handleLoad`) now reject any token after the
  source with `load: unexpected argument "<first-extra>"`, placed after
  the known-mode check and before any terminal read, file read, content
  gate, store mutation, or Load RPC — the same refusal shape `load rescue`
  already used for extra arguments. `load rescue` handling, the exact
  two-argument forms, and all content gates (#9892/#10305/#14718/#6753)
  are unchanged.
- **File(s)**: `pkg/cli/cli_config.go`, `cmd/cli/main.go`,
  `pkg/cli/load_trailing_args_16602_test.go`,
  `cmd/cli/load_trailing_args_16602_test.go`, `docs/log/16602.md`.
- **Validation**: New `TestConsoleLoadTrailingArgRefused16602` (pkg/cli):
  merge/set/override × terminal × {relative, bogus} refuse naming the
  token, consume zero scripted terminal lines, and leave the candidate
  byte-identical; `load merge <file> relative` refuses with the candidate
  untouched; multiple trailing tokens name the first; plain
  `load merge terminal` still loads. New
  `TestCtlLoadTrailingArgRefused16602` (cmd/cli): the same matrix over
  file and terminal sources against a counting Load stub — every refused
  cell issues zero Load RPCs, and plain `load merge <file>` issues exactly
  one. RED-on-revert verified: deleting the `len(args) > 2` guard makes
  the console suite fail (trailing cells load/consume input) and the
  remote suite panic on the nil readline (guard no longer stops terminal
  cells before the paste). Targeted load tests and `go vet` green on both
  packages. Full suites: `pkg/cli` 15 failures and `cmd/cli` 2 failures
  (`TestTreeIsGofmtClean`,
  `TestEveryOperationalValueSlotHasARemoteBinding_9478`), each reproduced
  identically on pristine `origin/master` (cbe42bd4f3) — pre-existing,
  untouched here.
- **Residual**: `relative` is refused, not implemented — cursor-relative
  loads remain unavailable, now loudly instead of silently at the root.
  Implementing it (wire path field + cursor prefixing + gate pricing of
  prefixed lines) is a larger Junos-parity feature if operators need it;
  no such follow-up is filed because refusal satisfies the issue's
  acceptance ("either error with nothing loaded, or RI1Static=1").
