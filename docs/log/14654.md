# #14654 — transit directed broadcasts + cross-VRF ICMP suppression

## Defect
Two legs, one root: directed-broadcast recognition was not scoped to
the routing domain/table that owns the address.

- Leg 1: `transit_dst_is_martian(ip)` took no forwarding/domain
  arguments and never consulted `connected_v4_directed_broadcasts`,
  while `transit_src_is_martian` in the same file did the domain-keyed
  lookup (#14155 built that index). A transit packet to a connected
  subnet-directed broadcast (RFC 2644: routers MUST NOT forward it)
  escaped the martian drop and proceeded toward policy/session/NAT;
  on a normal LAN egress it dies at neighbour resolution, leaving
  session-state pollution rather than wire amplification.
- Leg 2: `v4_addr_is_directed_broadcast` scanned all `connected_v4`
  with no routing-domain/table filter, so a `.255` host in a /23 (or
  /16) in one VRF suppressed ICMP errors merely because another VRF
  owns the /24 whose broadcast is that address.

## Fix
- `frame/addr_class.rs`: `transit_dst_is_martian(forwarding, ip,
  routing_domain)` now also checks
  `connected_v4_directed_broadcasts.contains(&(routing_domain, v4))`,
  mirroring the source gate. New table-scoped
  `v4_addr_is_directed_broadcast_in_table` / `dest_…_in_table` /
  `src_…_in_table` (`None` = legacy any-table) and
  `icmp_error_table_for_meta`, which resolves the trigger's ingress
  domain to its v4 installing table (`inet.0` for domain 0) without
  allocation. The pre-existing unscoped wrappers remain for the
  any-table callers.
- `poll_descriptor/mod.rs`: `transit_destination_class_drop` takes
  `forwarding`, the flow routing domain, packet meta and fabric zone,
  resolves the effective domain via
  `effective_routing_domain_for_flow` (same helper the source gate
  uses), and checks both the original and DNAT-translated destination
  in that domain. All slow-path, flowless, flow-cache-hit
  (`flow_cache_hit.rs`) and pending-TX (`tx/dispatch/mod.rs`) call
  sites thread it. `LocalDelivery` remains exempt via the existing
  disposition gate.
- `icmp.rs` / `icmp_ptb.rs`: reject/Time-Exceeded and PTB suppression
  now use the table-scoped directed-broadcast checks with the
  trigger's ingress table, so cross-VRF lookalikes no longer suppress.
- `forwarding/fabric.rs`: `ingress_l2_group_unicast_ip` uses the
  domain-keyed directed-broadcast index for the ingress domain
  instead of the unscoped connected scan — same scoping defect, same
  function family.
- NOT changed: `policy_revalidation.rs` persistent-NAT threading
  found in the salvaged worktree was already on master (#14802) and
  was dropped; the unscoped `dest_is_directed_broadcast` /
  `src_is_directed_broadcast` wrappers are kept because test and
  any-table callers still use them.

## Risk
Domain resolution reuses `effective_routing_domain_for_flow`, the
same value the source martian gate and native-table resolution
already trust; ambiguous fabric zones resolve to the synthetic
quarantine domain, which owns no directed broadcasts (fail-open for
that narrow class, matching the source gate). ICMP scoping falls
back to any-table when the ingress domain has no registry row, so
no previously-suppressed error becomes newly emitted except the
intended cross-VRF host case.
