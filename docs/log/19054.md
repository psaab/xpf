# Issue #19054: H11 soak's traffic budget ran out; uncovered moves scored FAIL

## Why

- **Timestamp**: 2026-11-09 PST
- **Action**: In the wave-1 gate (loss, master 602f946af5), `SOAK_MOVES=200
  SOAK_SLEEP=5` ended 182 PASS, 18 FAIL. All 18 FAILs were moves 183-200.
  - iperf3 and ping had exited. The run length was estimated as moves x
    (sleep + converge + 4 s) + 60 s = 2,860 s, while the moves took about
    16 s each on average, rising from about 11 s to 38 s near the end.
  - The windows the traffic did not cover were scored FAIL ("did not cover
    the move window", "traffic did not follow").

## What

- **File(s)**: `test/incus/rg_move_soak.py`, `test/incus/rg-move-soak.sh`,
  `test/incus/rg_move_soak_test.py`, `docs/ha-rg-move-correctness.md`
- **Run length**: the generators run until the soak stops them (it always
  does, after the last window). Their `-t`/`-w` cap is now 120 s per RG
  move + 600 s (`TRAFFIC_S_PER_MOVE_CAP`, `TRAFFIC_S_SLACK`), and
  `SOAK_TRAFFIC_S` overrides it. `info.traffic_s` records the value used.
- **Uncovered window = VOID**: `move_verdict` scores a move whose window
  ping or iperf3 did not cover as VOID, never PASS, COST or FAIL.
  - The reason names the cause, recorded per family by `finish()` as
    `uncovered_cause`: the traffic run's planned end came first
    (`traffic_end_lan`), or a generator stopped early (with iperf3's error
    text).
  - Every other reason is kept as "unscored evidence: ...".
- **Fake**: `FakeCluster`'s generators now stop after their own `-t`/`-w`
  seconds, as the real ones do. `run_fake` accepts `traffic_s`.
- **Cells**, `TrafficCoverage19054`:
  - `test_no_uncovered_move_is_scored`: a 12 s traffic run under 3 moves;
    every uncovered move is VOID with the cause, and there are no FAILs;
  - `test_moves_slower_than_the_old_estimate_stay_covered`: 6 moves of
    about 26 s each (`SlowCliCluster`), which the old run length cannot
    cover; all are covered and the run exits 0.
- **Changed existing cell**: `MoveVerdict.test_traffic_generator_death_fails`
  asserted that an uncovered window FAILs, which is the defect #19054
  removes. It is now `test_traffic_generator_death_is_void_never_pass`: the
  same two inputs (iperf3 or ping not covering) must be VOID, with the
  "did not cover" reason, and never PASS.
- **Not fixed here**: why moves slow down over a long run. #19054's
  comment points at per-move work that scales with the run. That is
  outside this change, which makes the soak correct however long the moves
  take.

## Validation

See the commit message (runner RED/GREEN and mutants).

## Risk

Harness only. A long run's tail moves are now covered, and are scored,
where before they were FAILed. If the generators die, the moves they leave
uncovered are VOID, which makes the run exit 2, so a run is never a false
PASS. A dead controller leaves iperf3 running on the LAN host for up to the
cap. That risk already existed with the old 2,860 s figure for 200 moves.

## Fold: R16 review at 79155094ef

- **Timestamp**: 2026-11-09 PST
- **R16 F1 (MAJOR)**: an uncovered window was VOID whatever stopped the
  generator. A generator the product killed (a reset iperf3 connection),
  or a ping that stopped answering, is evidence of a failure, not a
  window the harness could not observe. R16's probe, a blackhole from
  move 3 of 5, must give PASS, PASS, FAIL, FAIL, FAIL.
- **R16 F2 (MAJOR)**: an uncovered window must not demote the failures
  read from status: dual-active, did not land, landed past the bound,
  revert, CLI error, helper disagreement.
- **R16 F3**: the renamed `test_traffic_generator_death_is_void_never_pass`
  mixed the two cases; split it.
- **R16 operational safety**: the generators now run until a long cap
  (#19054), so a SIGKILLed controller would leave full-rate iperf3 on the
  shared loss cluster for hours.
- **Rule (coordinator)**: VOID only for "the harness could not observe";
  any proof of failure FAILs; FAIL dominates.
- **Fix**:
  - Liveness: `finish()` takes each generator's last-alive time from its
    own output, plus 0.2 s (`GEN_OUTPUT_TOL_S`). Ping now runs with `-O`,
    so a live ping behind a blackhole writes `no answer yet` every 10 ms;
    iperf3 writes an interval every 100 ms. `_PING` now accepts only
    `bytes from` lines as replies; `ping_last_seen()` reads any stamped
    line.
  - Removed: the Codex fold's process polls (`poll_generators`,
    `gen_alive_until`). With output liveness in place, the mutant that
    drops the poll after the last window survived (`F1c`): the output
    already proved the same thing on every shape the cells build, and no
    shape was found where the two disagree and the poll gives the right
    verdict. One source for one fact; the output is the one R16 asked
    for.
  - Cause, per family and generator (`<kind>_uncovered_by`,
    `<kind>_uncovered_cause`): `harness` when the generator was last seen
    within 2 s (`PLAN_TOL_S`) of the run's planned end, or of the moment
    the watchdog stopped it; otherwise `early`.
  - `move_verdict`: a `harness` window is VOID evidence; an `early` one, or
    one with no recorded cause, is a FAIL reason ("a generator that
    stopped by itself is a failure of this move"). Status-derived FAILs
    are FAIL whatever the traffic did (the #19062 fold's precedence).
  - Watchdog: `traffic_watchdog_script()` is a POSIX-sh dead-man on the
    LAN host. The soak starts it before any generator (no watchdog, void
    run), touches `/tmp/r-soak-<run>.alive` after every move, and removes
    the file on its own stop. A heartbeat older than
    max(300, 4 x (sleep + RGs x converge) + 120) s makes it SIGINT every
    generator pid file and the UDP probe and leave a marker, which the soak
    reads after its stop and logs.
- **Cells**:
  - `HarnessOnlyVoid19054`: R16's blackhole probe; a stream the product
    killed FAILs; its twin, the same exits by the watchdog, is VOID (the
    marker is the only difference); a blackholed ping that runs to its

    both generators uncovered by the harness; reply vs liveness parsing.
  - `MoveVerdict`: `test_traffic_ended_by_the_harness_is_void` and

  - `TrafficWatchdog19054`: the soak starts the watchdog first and feeds

  - Updated: the #19062 property and VOID cells now mark their uncovered
    windows as harness-ended; `GeneratorLifetime19054`'s early-end cell

## Fold cycle 2: Codex and R16 round-2 reviews at 835f984500

- **Timestamp**: 2026-11-10 PST
- **Findings** (Codex MERGE-NEEDS-MAJOR, R16 MINOR; Codex predicted

  - C1: the +0.2 s coverage extension passed a reset at 9.910 in a window

  - C2 / R16 F2: the 2 s planned-end tolerance, applied to the extended
    timestamp, called a reset near the planned end the harness's end, and
    ignored the error line.
  - C3: the watchdog-marker reader ignored the read's rc (a timeout's
    text parsed as -inf) and had no range check (a stale `0 301`), so every
    death read as harness-ended.
  - C4: an uncovered ping dropped its open gap, losing a >1 s unanswered
    stretch that `-O` had proved before the harness stop.
  - R16 F1: after a generator died, every later move FAILed; those
    windows have no evidence.
  - R16 F3: pin a captured unanswered `ping -D -O` line.
- **Root cause, second time**: time tolerances deciding who ended the
  traffic. The mechanism is removed, not retuned (coordinator).
- **Fix**:
  - `GEN_OUTPUT_TOL_S` and `PLAN_TOL_S` are gone. Coverage is the
    generator's last real line or interval reaching the window end.
  - `generator_end()`: harness-ended only if the output reaches an instant
    the harness recorded (the planned end; the watchdog's fire instant)
    and there is no terminal error (`terminal_error()`: an iperf3 error
    other than SIGINT's `interrupt`). The guards that make "reaches the
    instant" hold for every generator still running then are by
    construction, not tolerance: ping's `-w` runs 60 s past iperf3's `-t`
    (`PING_DEADLINE_EXTRA_S`), both count from a start after the planned
    end is recorded, and the watchdog records its instant 0.2 s
    (`WATCHDOG_GUARD_S`) before its SIGINT, longer than either output
    cadence.
  - `family_traffic()` scores one family's windows: a generator that
    stopped by itself FAILs the window it stopped in ("self"); later
    windows are VOID ("after", "stopped by itself in move k, which FAILed
    for it").
  - `parse_watchdog_marker()`: the read must exit 0, the marker must be
    `<time> <age>`, and the time must lie between the watchdog's start
    and the read. Anything else is logged and ends no window.
  - `traffic_for_window()`: an uncovered ping's open gap runs to its last
    line (C4).
  - The soak's stop instant is recorded (`traffic_stopped_lan`); it comes
    after every window, so it never ends one.
- **Cells**:
  - `HarnessInstants19054` runs each reviewer fixture through the soak's
    own `Soak.finish()` from written LAN logs, beside its twin: C1 (reset
