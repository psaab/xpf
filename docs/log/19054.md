# Issue #19054: H11 soak's traffic budget ran out; uncovered moves scored FAIL

## Why

- **Timestamp**: 2026-11-09 PST
- **Action**: In the wave-1 gate (loss, master 602f946af5), `SOAK_MOVES=200
  SOAK_SLEEP=5` ended 182 PASS, 18 FAIL. All 18 FAILs were moves 183-200.
  - iperf3 and ping had exited. The run length was estimated as moves x
    (sleep + converge + 4 s) + 60 s = 2,860 s, while the moves took about
    16 s each on average, rising from about 11 s to 38 s near the end.
  - The windows the traffic did not cover were scored FAIL ("did not cover
    the move window", "traffic did not follow").

## What

- **File(s)**: `test/incus/rg_move_soak.py`, `test/incus/rg-move-soak.sh`,
  `test/incus/rg_move_soak_test.py`, `docs/ha-rg-move-correctness.md`
- **Run length**: the generators run until the soak stops them (it always
  does, after the last window). Their `-t`/`-w` cap is now 120 s per RG
  move + 600 s (`TRAFFIC_S_PER_MOVE_CAP`, `TRAFFIC_S_SLACK`), and
  `SOAK_TRAFFIC_S` overrides it. `info.traffic_s` records the value used.
- **Uncovered window = VOID**: `move_verdict` scores a move whose window
  ping or iperf3 did not cover as VOID, never PASS, COST or FAIL.
  - The reason names the cause, recorded per family by `finish()` as
    `uncovered_cause`: the traffic run's planned end came first
    (`traffic_end_lan`), or a generator stopped early (with iperf3's error
    text).
  - Every other reason is kept as "unscored evidence: ...".
- **Fake**: `FakeCluster`'s generators now stop after their own `-t`/`-w`
  seconds, as the real ones do. `run_fake` accepts `traffic_s`.
- **Cells**, `TrafficCoverage19054`:
  - `test_no_uncovered_move_is_scored`: a 12 s traffic run under 3 moves;
    every uncovered move is VOID with the cause, and there are no FAILs;
  - `test_moves_slower_than_the_old_estimate_stay_covered`: 6 moves of
    about 26 s each (`SlowCliCluster`), which the old run length cannot
    cover; all are covered and the run exits 0.
- **Changed existing cell**: `MoveVerdict.test_traffic_generator_death_fails`
  asserted that an uncovered window FAILs, which is the defect #19054
  removes. It is now `test_traffic_generator_death_is_void_never_pass`: the
  same two inputs (iperf3 or ping not covering) must be VOID, with the
  "did not cover" reason, and never PASS.
- **Not fixed here**: why moves slow down over a long run. #19054's
  comment points at per-move work that scales with the run. That is
  outside this change, which makes the soak correct however long the moves
  take.

## Validation

See the commit message (runner RED/GREEN and mutants).

## Risk

Harness only. A long run's tail moves are now covered, and are scored,
where before they were FAILed. If the generators die, the moves they leave
uncovered are VOID, which makes the run exit 2, so a run is never a false
PASS. A dead controller leaves iperf3 running on the LAN host for up to the
cap. That risk already existed with the old 2,860 s figure for 200 moves.

- **Measured first** on udp:xpf-testrunner: iperf3 3.22's `start` event
  carries `timestamp.timesecs` and `timemillisecs` (its connect time).
  `--timestamps` does not stamp `--json-stream` lines. On SIGINT, iperf3
  3.22 writes a final partial interval, then the error `interrupt - the
  client has terminated by signal Interrupt(2)`, then `end`. A background
  job of a non-interactive shell ignores SIGINT; the soak's generators are
  not started as one.
- **Fix** (mechanisms removed, not retuned):
  - iperf3 time is iperf3's own clock: `iperf_generator_anchor()` takes
    the start timestamp (`timemillisecs`, else `timesecs`), and
    `parse_iperf_stream()` adds each interval's offset to it. The arrival
    median is gone. The anchor is the connect time, at or before the test
    start, so every interval time is a lower bound. An iperf3 without a
    start timestamp voids the run at the traffic preflight.
  - Who ended a generator, from what is recorded (`generator_end()`):
    - iperf3: an `end` event without an error is its `-t`. SIGINT's exact
      text (`IPERF_SIGINT_ERROR`, in both its 3.22 and older forms) is
      the harness. Any other error, including the server's "interrupt",
      is a death. Output that stops with neither is a death.
    - ping: a recorded stop that found its pid running, or a line at or
      past the planned end (ping's `-w` runs 60 s past iperf3's).
  - `generator_stop_script()`: the soak's stop and the watchdog both
    record the LAN time and which generator pids answer `kill -0`, then
    SIGINT. The soak's stop prints `STOPPED <time> <running>...`
    (`parse_stop_record()`). The watchdog's marker is `<time> <age>
    <run token> <running>...`. `WATCHDOG_GUARD_S` is gone.
  - `parse_watchdog_marker()` also requires this run's random token
    (`Soak.run_token`, handed to the watchdog at its start).
  - `family_traffic()` always charges a self-stopped generator to exactly
    one move: the first window it did not cover, or the LAST move if it
    covered them all ("stopped by itself in the final tail"). A stall
    that iperf3's own death cut short never recovered (FAIL). Only a
    harness-ended stall is VOID.
  - `finish()` words a later window from the charged move's ACTUAL
    verdict ("which scored VOID" for a precondition VOID).
  - The fake: each generator's output, its start stamp and its `-t`/`-w`

## D1 correction: a reader clock step (after 1911a37fb5)

- **Timestamp**: 2026-11-10 PST
- **Finding** (Codex, at 1911a37fb5): D2 is FIXED; D1 is PARTIAL. The
  epoch's upper bound, min(arrival - interval end), assumes the LAN
  reader's wall clock never steps back. After a 0.2 s backward step, one
  late arrival gave 100.402 against a true 100.600. The 10.1 s stall then
  fell out of [105,125), and the move PASSed again.
- **Disposition** (orchestrator, on #19054): one more commit on the batch
  branch, limited to D1, failing closed. The bound is not re-derived.
- **Fix**:
  - The reader stamps `<wall>@<mono before>:<mono after>`.
  - `iperf_reader_step()` checks that every line's wall - monotonic offset
    interval, widened by the 1 µs printing resolution, shares a point. If
    one does not, the clock stepped. A stamp with no monotonic time
    cannot be checked.
  - Either way, every window of that family gets "reader clock stepped;
    timing not certifiable" as VOID evidence. That is never PASS, and FAIL

## Re-plan design note: one clock (after 0f1d3f2461)

- **Timestamp**: 2026-11-10 PST
- **Context**: at 0f1d3f2461, Codex F1 (a false PASS: a wall step hidden inside a read bracket) and R16 F1 (a false-VOID storm from rounding) came in opposite directions, so the orchestrator re-planned the batch under the escalation rule. No code yet: the note below goes to plan review first, and code follows only on DESIGN-READY from both seats.

This is a plan, not code. It asks Codex and R16 for DESIGN-READY before any implementation. The branch stays at 0f1d3f2461, unlanded, and #19085 is paused locally.

#### 1. Root cause

Every round failed at a seam between clocks:
- Windows are controller monotonic, mapped to the LAN wall clock by one preflight offset.
- ping's `-D` stamps are LAN wall time.
- iperf3's interval times are its LAN-wall connect stamp plus its own elapsed offsets.
- Reader arrivals are LAN wall time, with a monotonic bracket bolted on.
- Stops and the watchdog are LAN wall time.

Every fix either moved the seam (connect stamp, then arrival minimum, then step detector) or added a tolerance at it. This plan removes the seams instead: every instant that reaches a traffic verdict is read from ONE clock, the LAN host's `CLOCK_MONOTONIC`, as integer nanoseconds. No wall clock remains in the verdict path.

#### 2. The one clock

All stamps come from the LAN host: the reader, the probe, the stop, the watchdog, the window boundaries and the iperf3 launch stamp. They are `time.monotonic_ns()` integers from python3, or the probe's own `clock_gettime(CLOCK_MONOTONIC)`. All of these run in the same LAN container, so they share one clock. Incus uses no time namespace by default; the preflight checks for one (section 9).

`CLOCK_MONOTONIC` never steps. NTP slews it at the same rate as the wall clock, and iperf3's interval clock is the same `CLOCK_MONOTONIC` (to be verified, section 9). So durations agree, and steps of either sign do not exist in this clock.

The controller's own monotonic clock keeps measuring only controller-side durations: the sleep cadence, the converge bound, landing and the CLI time. Those are never compared with LAN evidence. The `lan_time()` mapping and the preflight LAN offset leave the verdict path; offsets are still measured and reported for skew diagnosis.

#### 3. Window boundaries, recorded on the LAN clock

- Just before each move's CLI is sent, after the UDP pre-move reads, the controller runs one exec on the LAN host. It returns `monotonic_ns`, and that value is boundary `b_k`.
- Window k is `[b_k, b_{k+1})`. The last window ends at a stamp taken when its watch window ends, as today.
- **Causality, not a tolerance:** `b_k` is read on the LAN host before that exec returns. The CLI is sent only after the exec returns. So `b_k` precedes every effect of move k, on the LAN clock, however long the round trip is. Evidence caused by move k can never land in window k-1.
- **A slow controller-to-LAN round trip:**
  - Window k then starts earlier than CLI k, by up to that round trip. Late effects of move k-1 that fall in the gap are charged to move k.
  - That is today's behaviour too: today's window starts before the UDP pre-move reads, seconds before the CLI. It is a precision cost, not a soundness one.
  - The soak records each boundary exec's controller-side round trip in `result.json`, so a slow one is visible.
- **A boundary exec that fails or times out:** the adjacent windows have no certified boundary, so both are VOID ("window boundary not recorded on the LAN clock"). This fails closed.

#### 4. iperf3: generator time in the one clock

- **Launch stamp `L`:** the launch shell runs `python3 -c 'print("LAUNCH", time.monotonic_ns())'` immediately before `exec iperf3`. iperf3 starts after that, so its test-start epoch `E >= L`.
- **Arrival stamps `A_i`:** the reader stamps each line `<monotonic_ns> <json>`. Integer nanoseconds, no wall clock, no float.
- **Upper bound `U`:** an interval cannot be read before it ends, so `A_i >= E + e_i` for its end offset `e_i`. Then `U = min_i(A_i - e_i) + ε_e`. Here `ε_e` covers only iperf3's microsecond truncation of `e_i`, plus double rounding. It is a fixed, provable 2 µs, not a timing tolerance. The interval timestamps iperf3 uses have microsecond resolution and are truncated, so `e_true - e_printed < 1 µs`.
- **The epoch interval:** `E ∈ [L, U]`, entirely in the one clock. If `U < L`, the logs contradict each other, and that family is VOID ("iperf3 timing inconsistent"). That cannot happen if the premises hold; the check exists so that a broken premise fails closed.
- **Coverage uses the lower bound:** the stream covers window k only if `L + e_last >= b_{k+1}`.
- **Attribution is conservative over the interval:** a stall that starts at offset `s` truly starts in `[L + s, U + s]`. It is charged to every window that range intersects. That keeps D1's rule; only the coordinates change. The COST-to-FAIL over-attribution is kept as accepted, documented behaviour. `U - L` is now about the exec, connect and parameter-exchange time, tens of milliseconds, so over-attribution only touches stalls that start that close to a boundary.
- **How iperf3 ended** is read from its own events (unchanged): `end` with no error is its `-t`; the exact SIGINT text is the harness; any other error is a death. Its death is charged to the first window it does not provably cover, or to the last move if it covered them all.

#### 5. ping: a monotonic-native probe replaces `ping -D -O`

- **Recommended: `icmp_probe.py`.** It is stdlib python3, run as root by `incus exec`. It sends ICMP or ICMPv6 echo on a `SOCK_DGRAM` ping socket, falling back to `SOCK_RAW` as root, every 10 ms. Every log line carries `clock_gettime(CLOCK_MONOTONIC)` nanoseconds taken by the probe itself:
  - `S <seq> <ns>` for each send. This is the liveness line: the probe was running at `ns`.
  - `R <seq> <recv_ns> <rtt_ns>` for each reply.
  - `END deadline|sigint <ns>` when it exits.
- **What each check reads:**
  - Gaps, lost replies, the open gap, tail replies and the final tail are computed on reply receive times.
  - Liveness is the last `S` or `R` line.
  - How the probe ended is its `END` line, or a recorded stop that found it running.
- **Identity:** the launch records the PID and start time, as now.
- **Rejected alternative, reader-stamped `ping` lines:** an arrival stamp only bounds a line's print time from above. If the reader was late on the reply before an outage and on time for the reply after it, the measured gap is SHORTER than the true one, which is a false PASS. Read brackets bound that only to the line cadence, and only with a reader that never batches.
- **Rejected alternative, `-D` stamps converted through a measured wall-to-monotonic offset:** that puts the wall clock back in the path, the F1 class.
- **What this changes:** ping's `-w` and `-O`, `_PING`, `ping_last_seen()` and the R1 mutant go away. The probe has its own deadline, `duration + 60 s`, which it reports itself in its `END` line.

#### 6. Stops, the watchdog and the planned end

- **The soak's stop** prints `STOPPED <monotonic_ns> <alive...>`. The identity check, SIGINT and alive list are unchanged.
- **The watchdog marker** is `<monotonic_ns> <age> <token> <alive...>`. Its start and read stamps are also LAN monotonic, so the range check is in the one clock.
- **The planned end** is no longer an instant. iperf3's `end` event and the probe's `END deadline` report it.
- **The final tail** for #19085 is `[b_last_end, STOPPED_ns)`.

#### 7. What is removed

- Wall time everywhere in the verdict path: `lan_time()` for windows, `traffic_end_lan`, ping's `-D` stamps, and iperf3's `timestamp` as the anchor. iperf3's `timestamp` is kept as a diagnostic only.
- `iperf_reader_step()`, `STAMP_RESOLUTION_S`, the `<wall>@<mono>:<mono>` stamp and `parse_arrival()`'s wall form.
- `PING_DEADLINE_EXTRA_S` as a cross-generator margin. The probe's own deadline replaces it.

#### 8. Why each prior finding becomes impossible, not patched

- **C1** (the +0.2 s extension passed a reset at 9.910): coverage is `L + e_last >= b_{k+1}`, with no extension. `L <= E`, so a stream whose last interval ended before the boundary can never cover it.
- **N1** (a slow reader manufactured coverage): arrivals feed only `U`. Delay only raises `U`, and coverage never uses `U`.
- **D1** (an early anchor moved a stall out of every window): the true start lies in `[L + s, U + s]`, and the stall is charged to every window that range meets. The windows tile `[b_1, b_end)`, so a stall that truly starts inside the run cannot meet none of them.
- **D1 step remainder and Codex F1** (a wall step, even one hidden inside a read bracket, lowered `U`): no wall reading exists. `A_i` is `CLOCK_MONOTONIC`, which never steps, so `A_i >= E + e_i` always holds and `U >= E` always.
- **Codex R2** (a forward step before connect shifted every interval late): `L` is a monotonic stamp taken before exec, not iperf3's wall connect stamp. No wall clock means no step to shift anything.
- **R16 rounding storm** (1 µs allowance against µs printing): there is no step detector left to trip. Every stamp is an integer nanosecond. The only constant, `ε_e`, is a provable bound on iperf3's own microsecond truncation, and it is used only to widen `U`, which errs conservative.
- **Earlier fixes are kept** in the new coordinates: C2-C4, R16 F1/F2, and D2 (identity at the stop).
