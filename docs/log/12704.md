# docs/log/12704.md — #12704 (gate target-change success logs on removal)

- **Timestamp**: 2026-10-13
- **Action**: Log retained `.link` claims as neutralized only when every requested removal succeeds (or the file is already absent); emit per-file ERROR logs for failures.
- **Files**: `pkg/daemon/linksetup.go`, `pkg/daemon/bootstrap.go`, `pkg/daemon/linksetup_originalname_12156_test.go`, `docs/log/12704.md`

## Why

The #12156 target-change paths attempt to remove both the unknown NIC's own
`.link` and a stale target `.link`. Removal errors were logged, but both paths
then unconditionally emitted a success-form message saying the claims had
been neutralized. Operators could therefore be told the next boot would fall
back to kernel names while a failed removal left a resurrectable claim behind.

## What

- Positional naming now emits the aggregate neutralized message only when both
  removal attempts succeed. Each failed removal remains in the positional
  error channel and is logged against its file.
- Bootstrap emits the same aggregate success message only when both removals
  succeed, with per-file ERROR logging otherwise. The required interface rename
  still proceeds.
- Added regressions that make a target `.link` path a non-empty directory,
  guaranteeing removal failure even when tests run as root. Both assert that
  the other removable claim is still removed, the rename still proceeds, the
  failure is logged, and the success-form summary is absent.

## Validation

- RED mutant: unconditional target-change summary logging made both new tests
  fail specifically because the log claimed neutralization after `ENOTEMPTY`.
- `go test ./pkg/daemon -run '12704|12156|12550' -count=1` — PASS.
- `gofmt -l pkg/daemon/bootstrap.go pkg/daemon/linksetup.go pkg/daemon/linksetup_originalname_12156_test.go` — no output.
- `go test ./pkg/daemon -count=1` — PASS (`456.180s`).

## Risk

A failed removal continues to leave a potentially resurrectable `.link`; this
change makes that failure explicit and prevents the misleading success log. It
does not suppress the required rename or alter removal/absence semantics.
