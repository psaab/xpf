# #15041 — Config-payload key exchange is droppable; authenticated link falls back to cleartext (A24-03)

## Defect
On an authenticated (Noise_NNpsk0-keyed, same-version) session-sync
connection, the #6629 config-payload key came from an ephemeral X25519
exchange carried in ordinary `syncMsgConfigKeyExchange` frames.
`verifyFrame` admits sequence gaps (`seq <= recvSeq` only), so an active
on-path relay could drop both exchange frames; `awaitConfigKey` then
timed out after 2 s, latched `legacy`, and `queueConfigOnConn` sent the
full unredacted config — including the control-link PSK and every config
secret — as cleartext `syncMsgConfig`. After disclosure, heartbeat /
sync / fabric HMACs are forgeable. Anchors: `sync_config_crypto.go`
(`awaitConfigKey`), `sync_conn_config.go` (`queueConfigOnConn` nil-key
arm), `sync_auth.go` (`verifyFrame`).

## Fix
Derive the config AEAD key from the authenticated handshake secret
(issue's first fix direction; no wire change):

- `pkg/cluster/sync_config_crypto.go`: `configKeyFromHandshake` HKDFs
  (SHA-256, purpose-bound info `syncConfigHandshakeKeyInfo`) over the
  canonically ordered pair of the connection's directional Noise frame
  keys. Both ends hold the same unordered pair `{i2r, r2i}`, so both
  derive the identical key with no exchange to suppress. The frame keys
  are never used directly as an AEAD key. `awaitConfigKey` returns this
  key immediately for authenticated connections and never consults the
  droppable exchange / timeout / legacy latch there; the ephemeral path
  is unchanged for unauthenticated connections.
- `pkg/cluster/sync_conn_read.go`: the `syncMsgConfigEncrypted` receive
  arm derives the same handshake key first, falling back to the
  ephemeral `configKeyForConn` only on unauthenticated connections.
- Seal-failure on an authenticated connection still falls through to the
  existing cleartext-with-alarm arm (pre-existing #11773-observable
  behaviour; AES-GCM seal under a valid 32-byte key does not fail in
  practice outside RNG failure). No behaviour change outside the cited
  mechanism: unauthenticated mixed-version cleartext fallback, the
  #11773 alarm/counters, and all neighbouring config paths are preserved.
- Mixed-version note: a pre-#15041 peer on an authenticated link seals
  under its ephemeral key, which this build no longer tries there; such
  payloads fail to open and are dropped (existing fail-closed decrypt
  arm), and the sender re-pushes on reconcile. Rolling upgrade of an
  authenticated pair should upgrade both nodes; unkeyed links are
  unaffected.

## Tests
`pkg/cluster/sync_config_crypto_15041_test.go`:

- `TestConfigKeySuppressionNeverYieldsCleartextOnAuthedConn15041`:
  both ends authenticated (`*authConn` with handshake frame keys), the
  ephemeral exchange never completed (relay suppression). Asserts the
  push is `syncMsgConfigEncrypted`, the PSK is absent from the raw
  wire bytes (header+payload+HMAC trailer), the frame verifies, the
  receiver recovers the config byte-identically, and no cleartext
  stats latch.
- `TestConfigCryptoUnauthenticatedPeerStillFallsBack15041` (control):
  a plain unauthenticated connection keeps the legacy cleartext
  `syncMsgConfig` fallback byte-identically.
