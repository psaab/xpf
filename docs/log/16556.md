# #16556: quarantined zone interfaces render as UNBOUND on every show surface

- **Timestamp**: 2026-10-24
- **Problem**: On a tolerant load (hand-edited/legacy stored config, HA
  peer-sync) an interface claimed by two security zones is quarantined:
  `InterfaceZoneMap` / `authoredZoneRefs` omit it, `programZoneMaps`
  attaches no XDP shim, and transit fails closed (#3072). But
  `show security zones` listed it as bound under BOTH zones with the
  authored count, `show interfaces` printed a map-order-chosen
  "Security: Zone:", GetZones/REST returned the raw authored list, and
  `show system alarms` never named it — the operator debugged policy
  while every packet dropped.
- **Fix**: One shared verdict in pkg/config:
  `ZoneInterfaceQuarantineExclusions` (logical key → sorted claimant
  zones, derived from the same `zoneInterfaceMembershipConflicts` walk
  the runtime omission uses), with per-member
  `ZoneInterfaceQuarantineReason` / `ZoneInterfaceQuarantineClaimants`,
  row-keyed `ZoneInterfaceQuarantineClaimantsForRows`, alarm lines via
  `ZoneInterfaceQuarantineAlarmWarnings`, and the shared text spelling
  `ZoneInterfaceQuarantineUnboundQualifierFor`
  (`[UNBOUND — claimed by zones X and Y]`). `QuarantinedZoneInterfaceKeys`
  is now derived from the Exclusions map (single source). Renderers:
  local CLI + gRPC text `show security zones` (bound count excludes
  contested members, members annotated, detail headers annotated);
  CLI + gRPC `show interfaces` / detail / extensive / VLANs and
  `test security-zone` (contested rows print `(none) [UNBOUND ...]`
  instead of a chosen claimant); GetZones gains
  `ZoneInfo.unbound_interfaces` (proto field 20, regenerated with the
  pinned protoc 3.21.12 / protoc-gen-go v1.36.11 / protoc-gen-go-grpc
  v1.6.1); REST `ZoneInfo.unbound_interfaces` mirrors it; system +
  security alarms (CLI and gRPC) append the derived alarm warnings.
  The #6534 gate registers the new family
  ("security zone interface (duplicate membership)") with
  `ZoneInterfaceQuarantineExclusions` as its builder predicate — the
  userspace builder now calls that name directly (zones.go,
  zones_observability.go, host_inbound_classify.go) so
  `TestEveryBuilderDropPredicateIsRegistered6534` reds if the row is
  removed; transitive zone-ID/screen/NAT/counter readers are exempted
  with per-function reasons. The stale "first-writer-wins … forwards
  exactly as before" comment on the #3072 gate is corrected to the
  quarantine semantics. NOT changed: runtime binding/forwarding
  behaviour (already fail-closed), strict-commit rejection, and the
  structured GetInterfaces/REST interface `zone` field (pre-existing
  #10531 exemptions; the text surfaces now annotate).
