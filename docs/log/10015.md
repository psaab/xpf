# #10015: redact feed transport errors at every logging sink

- **Timestamp:** 2026-09-17
- **Branch:** `fix/10015-feeds-redact`
- **Issue:** `feeds: hold-drop warning and debug arms log unredacted transport errors (credential-bearing URLs)`
- **File(s):**
  - `pkg/feeds/feeds.go`
  - `pkg/feeds/feed_hold_drop_redaction_10015_test.go`

## Decision

Go transport errors quote the URL they dial. Dynamic-address feed URLs may carry
per-tenant bearer tokens in their query strings, so logging the raw `error`
value leaks credentials. `recordFailure` already stores
`redactFeedURLInError9164(ferr.Error(), fs.url)` in `fs.lastError` and uses that
redacted text when a feed first enters STALE. The hold-drop Warn and repeated-
failure Debug arms were the remaining raw-`ferr` sinks.

Both arms now log the already-redacted `fs.lastError`, preserving the transport
diagnostic while removing credentials. During the same-file audit, the
duplicate-name safety-net Warn was also found to log a configured feed URL
verbatim; it now uses the existing `config.RedactURL` helper. No second
redactor was added.

## RED / GREEN proof

The four new cells are fail-on-revert tests: three credential-bearing cases
must fail when their production sink is restored to its pre-fix form, while the
credential-free control must stay green.

- **Cell A — `TestHoldDropWarnDoesNotLogTheCredential10015`:**
  - RED after restoring the raw `"err", ferr` hold-drop Warn: FAIL; the bearer
    token appeared in the Warn output.
  - GREEN after the fix: PASS; `dial tcp`, `connection refused`, host, and path
    remain visible while the token is absent.
- **Cell B — `TestRepeatedFailureDebugDoesNotLogTheCredential10015`:**
  - RED after restoring the raw `"err", ferr` repeated-failure Debug: FAIL; the
    bearer token appeared in the Debug output.
  - GREEN after the fix: PASS; transport diagnostics, host, and path remain.
- **Cell C — `TestDuplicateFeedNameWarnRedactsCredentialURL10015`:**
  - RED after restoring the raw `"url", url` duplicate-name Warn: FAIL; the
    bearer token appeared in the Warn output.
  - GREEN after the fix: PASS; the configured host and path remain visible and
    the query credential is absent.
- **Control — `TestHoldDropWarnKeepsACleanURLAlone10015`:**
  - RED run: PASS with the pre-fix sink forms.
  - GREEN run: PASS; a credential-free transport error remains byte-identical
    in the structured log field (apart from slog's required quote escaping).
