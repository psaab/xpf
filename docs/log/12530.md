# #12530 — preserve packed apply-group tails for inline peers

## Why

When a packed group leaf names a schema container and matches an inline
container peer, `groupPackedLeafBody` can decline its tail if it is outside
the schema grammar. The leaf path then treats the group as an inline override
and drops the complete statement. Post-expansion gates cannot reject the
unsupported `interfaces ... unit ... filter` binding, or a unit `mac` tail.

## What

- Merge the unmodelled packed tail into the matching inline container peer
  through `mergeNodes`, the path the #7648 expanded body already takes. One
  level down the tail meets the peer's same-instance children (an inline
  `unit 0`) and its `apply-groups-except` (#9422 outer veto, #9862 nested
  contributors), so a packed group line lands where its block spelling
  (`ge-0/0/0 { unit 0 { <tail>; } }`) already did. The tail keeps its token
  quote/bracket provenance and its group contributor provenance.
- Schema-expandable tails continue through the existing recursive merge, so
  supported values retain Junos inline-wins behavior.
- Not changed: inline leaf peers (a bare `unit 0;` still overrides the packed
  tail), packed group lines with no inline peer, and what
  `groupPackedLeafBody` expands.

## Validation

The initial focused diagnostic reproduced the defect: packed `filter input f`
and `unit 0 mac` each compiled cleanly with an inline unit peer, while the
filter no-peer control failed strict compile with #12090 and emitted the
expected lenient warning. After the fix, focused regressions passed:

```sh
go test ./pkg/config/ -run 'PackedApplyGroup.*12530|InlineValueStillBeatsTheGroup7648' -count=1
```

The new cases require strict rejection and exactly one lenient warning for
inline-peer #12090 filter and H10 unit MAC tails, and retain strict/lenient
filter rejection without a matching unit peer. Existing
`TestInlineValueStillBeatsTheGroup7648` covers inline-wins for a
schema-supported packed value.
The required full suite was run as:

```sh
go test ./pkg/config/ -count=1 -timeout 60m
```

It failed after about 27 minutes. Failures included the now-corrected stale
`TestApplyGroupInlinePeerOverrideDropTracked12090` expectation, #8662 inventory
drift, #10826 API-auth diagnostics affecting parser controls, a #11312 routing
instance rejection, and #7484 coverage-gate mismatches. No baseline attribution
has been made for the other failures. After updating the inline-peer test to
the fixed strict/lenient behavior, the focused command shown above passed.

## Risk

The H10 gate still misses a packed `unit 0 mac` when no inline unit peer
exists, because it inspects unit children only. That shape was missed before
this change too and is tracked by #12683.

A packed group line whose tail the schema cannot fully expand now inherits
through an inline container peer the way its block spelling already did,
instead of being dropped whole. Measured deltas for a group line packed on the
interface, `ge-0/0/0 unit 0 <tail>`, beside an inline unit 0 that has an
address:

- Statements in the tail apply unless the inline unit sets them:
  `vlan-id 100 junk` now sets VLAN 100, while an inline `vlan-id 200` still
  wins.
- Post-expansion gates see the tail. `filter input f` (#12090), `mac ...`
  (#2008 H10) and `family inet address 10.0.0.2/24 frob` (#9424 address list)
  now fail strict commit; master committed them by dropping the line. A
  lenient compile warns and keeps the inline unit, and the new Load and
  SyncApply cells pin that for the filter and MAC tails.
- A tail naming another instance is adopted: `ge-0/0/0 unit 1 frobnicate`
  creates unit 1 beside the inline unit 0.
- Words outside the grammar (`frobnicate 7`) stand under the unit in the
  expanded tree. Strict commit accepts them, as it does when they are written
  inline.

An inline LEAF peer (a bare `unit 0;`) still overrides the packed tail, so a
group's `unit 0 filter input f` or `unit 0 mac ...` against it commits
silently; inline leaf peers are outside this fix. The synthesized tail carries
no `InheritedFrom`, so `| display inheritance` shows it as inline, the same gap
the #7648 expanded body has.
