# #17688 — preserve independent RIP group export chains

## Why

Grouped exports were retained in `RIPConfig.Groups` but then flattened into `RIPConfig.Redistribute` and rendered as one ordered policy chain. A group's terminal default-reject could therefore starve a later group's routes from the shared RIP pool, even though each group's own outbound prefix gate was distinct.

## What

- Preserve the top-level RIP `redistribute` chain separately from the legacy union, so grouped and global exports can be evaluated independently.
- Build the grouped redistribution pool as a per-source union of the independent global/group chains. Multiple policy chains for one source use the existing OR-composed route-map renderer; a bare source remains unfiltered in the pool and relies on the per-interface gate.
- Render a match-all accepting term or policy default-accept as the exact all-prefix permit set, retaining earlier terminal reject entries.
- Keep source-qualified accepts (for example `from protocol static; then accept`) fail-closed. The retro-review acceptance requested prefix-list permits, but FRR RIP's outbound `distribute-list [prefix] LIST <in|out> IFNAME` only accepts prefix/access lists; that cannot preserve the source condition for native connected or learned RIP routes which bypass the redistribution route-map. A prefix-only permit could leak those native routes. See [FRR RIP filtering documentation](https://docs.frrouting.org/en/stable-9.0/ripd.html#filtering-rip-routes). The existing deny-all is intentional conservative translation, not opened by this change.
- The explicit policy-level default-reject chain stop is already present on master (including the #18361 regression); empty/no-export groups already render deny-all per #16866. This change does not alter those paths.
