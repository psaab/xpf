# #18666: refuse output modifiers after pure keyword leaves

- **Timestamp**: 2026-11-07
- **Why**: The shared operational gate intentionally left trailing words after a leaf to the command handler. Leaf handlers that ignored those words silently dropped `| display <format>`, rendered the default text output, and returned success (`show version | display xml`).
- **Action**: Extended `cmdtree.ValidateOperationalGate` to reject a bare output pipe after a terminal pure-keyword leaf with `syntax error: "<path>" does not accept the output modifier "| ..."`. A leaf must resolve through keywords only and have no keyword children or value slot; a probe through `Canonicalize` excludes childless `AcceptsArgs` nodes. The existing `OperationalPipeConsumers` registry remains only `show configuration`: census of the remote and local pipe parsers found the other real handler consumers at configuration stanza paths and rollback value slots, which remain outside this leaf rule. Both CLI dispatchers already call the shared gate, so they receive the same refusal before handler/RPC dispatch. Updated the gate, CLI/reference documentation and changelog; annotated the #18664 residual as resolved.
