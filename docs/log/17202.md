# #17202 — R4-Q22-02: routing-policy `from` list arms copy-pasted with two opaque predicates; collectProtocolList duplicated plainListValues

- **Timestamp**: 2026-10-27
- **Defect (live on origin/master eb4571c7ef)**: In `parsePolicyTermChildren`
  (`pkg/config/compiler_routing.go`), the four `from` list arms
  (`protocol`, `prefix-list`, `community`, `as-path`) used two different
  "opaque block" predicates: `len(fc.Keys) > 1 && len(fc.Children) > 0` for
  protocol, `!fc.IsLeaf && len(fc.Children) > 0` for the other three
  (added by #11779). A value block `prefix-list { pa; pb; }` has
  `Keys=["prefix-list"]`, `IsLeaf=false` and leaf children, so the broader
  predicate routed it to `UnknownFrom`: strict commit rejected it with the
  misleading "`from pa, pb` is not enforced" diagnostic and tolerant load
  forced the term to reject — while `protocol { bgp; ospf; }` compiled both
  values. `collectProtocolList` (protocol) was a verbatim copy of
  `plainListValues` (ast.go), so the plain-list reader existed twice.

## STEP-0

Re-verified at eb4571c7ef: protocol arm at compiler_routing.go:2346-2351,
the three `!fc.IsLeaf` arms at :2360-2365/:2410-2415/:2422-2427,
`collectProtocolList` at :2079 (single caller) and `plainListValues` at
ast.go:610. An AST probe on current master confirmed the divergence:
`prefix-list { pa; pb; }` → `PL=[] Unknown=[pa pb] Action=reject` strict
reject, while `protocol { bgp; ospf; }` → `[bgp ospf]` clean; bracket,
single and flat-set spellings were clean for all leaves. The opaque
spellings that must stay rejected were also probed:
`prefix-list pa { x; }` (values on Keys + leaf child `x`) and
`prefix-list { pa { x; } }` (value child carrying its own body).

## What

- `pkg/config/compiler_routing.go`: deleted `collectProtocolList`; added
  `policyFromListValues(fc) (values, opaque []string)` as the single
  reader + opaque decision for all four leaves. Opaque fires when
  (a) the node carries values on its Keys and still has children
  (`leaf VAL { …; }`, keys kept, child names quarantined — the #11779
  `name { x; }` rejection), or (b) a value child itself carries children
  (`leaf { VAL { …; } }`, quarantined without promoting any token).
  Otherwise it returns `plainListValues(fc)`, the one plain-list reader
  for all five admitted spellings (bracket, `{a; b;}` block, single,
  flat-set repeated, flat-set bracket). The opaque arm is factored as
  `policyFromKeepKeysAndQuarantine`.
- Collapsed the four arms of `parsePolicyTermChildren` into one
  `case "protocol", "prefix-list", "community", "as-path":` that calls the
  helper once and routes its values to the field named by the leaf,
  appending the quarantine to `UnknownFrom` unconditionally. Acceptance:
  `grep -rn 'func collectProtocolList' pkg/config` returns 0.
- Stale references updated: the #6689 test header comment and
  `docs/config-schema.md` (#6689 nested-block discussion) now name
  `policyFromListValues` instead of the deleted helper.
- New parity guard
  `pkg/config/routing_policy_from_list_parity_17202_test.go`
  (`TestRoutingPolicyFromListParity17202`): one table over
  {protocol, prefix-list, community, as-path} × {hierarchical bracket,
  `{a; b;}` value block, flat-set repeated, flat-set bracket,
  `VAL { x; }` opaque, `{ VAL { x; } }` nested opaque} asserting the same
  verdict and values per leaf — value rows compile both values strict-clean
  with `accept`; opaque rows stay strict-rejected (#11779), keep the
  authored key value, quarantine the child name, and force `reject` on
  tolerant load.

## Risk

Low. For every non-opaque shape the new reader is `plainListValues`, which
for these four leaves returns the same tokens as the deleted
`collectProtocolList` and as `firewallMatchValues` on all canonical
spellings (it differs only by also reading every key of the flat-set
bracket child — the #7126 shape the schema `multi: true` declarations
absorb — and by not skipping a bare self-repeat token in the Keys tail, a
shape the parser does not produce for these leaves). The one behaviour
change is the intended repair: `prefix-list|community|as-path { a; b; }`
compiles both values again, matching `protocol` and the pre-#11779
behaviour. Opaque bodies (`VAL { x; }`, `{ VAL { x; } }`) remain
fail-closed on both strict and tolerant paths.
