# #14692 — unvalidated ssh-known-hosts rendering

## Defect
`applySSHKnownHosts` rendered `fmt.Fprintf("%s %s %s\n", host, sshType,
key.Key)` with no validation: `host` was the raw map key, unknown key
types fell through verbatim, and `key.Key` was unchecked. A host of `*`
or `@cert-authority *` (single tokens the config grammar accepts)
renders a line OpenSSH honors for every host, defeating #10298's
`StrictHostKeyChecking=yes` + rendered `UserKnownHostsFile` design for
`scpArchiveTransfer`, whose payload is the unredacted active config.
Newline/space in any field could also inject extra known_hosts lines
(the stronger wildcard/CA arm needs no injection at all).

## Fix
Daemon render-boundary validation in `pkg/daemon/daemon_system.go`
(the render function is the last gate before the file, so lenient
DB/peer-synced loads that bypass strict commit validation are still
contained; no compiler/schema signature changes, avoiding the
`closedWorldOpaque` host-body problem noted in #10078):

- Host: reject empty, whitespace/control, leading `-`/`!`, any `@`
  marker (`@cert-authority`/`@revoked`), and `*`/`?` wildcards in any
  comma member. Allow hostnames (label-checked), IP literals,
  `[host]:port` with port 1–65535, and hashed `|1|salt|hash` with
  non-empty base64 salt/hash.
- Type: closed Junos-spelling → OpenSSH map (the five original
  spellings, legacy short `rsa-key`/`ecdsa-key`/`ed25519-key` for real
  keys per #10078, plus sk-/cert- OpenSSH algorithms). Unknown or raw
  OpenSSH spellings are rejected instead of rendered verbatim.
- Key: must be a single whitespace-free token, canonical base64,
  parse via `ssh.ParsePublicKey`, and its `Type()` must equal the
  mapped type; the canonical re-marshalled blob is rendered. This
  rejects type/key mismatches, garbage base64, and newline injection.
- Invalid entries are skipped with a WARN naming host and type (never
  key material); valid entries still render. If no entry validates,
  the existing managed file is left untouched (no header-only
  replacement); unchanged content is not rewritten.

Judged-by-parser trade-off: legacy synthetic markers such as
`AAAAC3NzaC1lZDI1NTE5AAAAtestkey` decode but do not parse as SSH keys,
so they are now skipped. The #5112 daemon test was updated to use a
real generated ed25519 key; a stored config carrying only such a
marker would leave the previous file in place and archival would fail
closed at the existing trust-file gate until a real key is committed.

## Tests
- New `pkg/daemon/ssh_known_hosts_trust_14692_test.go`: wildcard/CA
  rejection with a valid neighbour, malformed host/unknown-type/
  mismatch/injection rejection, valid forms (hostname, IPv4, IPv6,
  `[host]:port`, comma list, hashed) rendering, and poison-only apply
  preserving the previous file. Keys are real generated keys, so
  mismatch cells pair a genuine blob of one algorithm with another's
  spelling.
- RED on base (a0739d7e3f): wildcard, malformed, and poison-only tests
  failed with the poisoned lines rendered verbatim; valid-forms passed.
- GREEN after fix: `go test ./pkg/daemon/ -run
  'TestApplySSHKnownHosts|TestScpArchiveTransfer10298' -count=1` — all
  pass, including the pre-existing #5112 and #10298 suites.
- Full `go test ./pkg/daemon/ -count=1` timed out at the default 10m
  with many unrelated failures (cluster RA, DHCP, FRR, host-inbound,
  event-stream, ...); a 10-test subset of those failures reproduces
  identically on unpatched current master (base-attributed, not this
  change — this change touches only the ssh-known-hosts render path).
