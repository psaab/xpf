# #15680 — Firewall policer per-term scoping breakdown (eBPF + `show firewall`)

- **Timestamp**: 2026-10-19
  - **Action**: Userspace enforcement was already term-scoped (#11333:
    one `ThreeColorPolicerRuntime` per `(family, filter, term, policer)`),
    but the status path collapsed it again: Rust
    `three_color_policer_statuses()` aggregated rows by configured name,
    and the Go `BuildThreeColorPolicerStatusIndex` keyed by name alone,
    so `show firewall` rendered the aggregate under every term sharing a
    policer. Fix: `ThreeColorPolicerStatus` (Rust + Go mirrors) gains
    `family` / `filter_name` / `term_name` (additive, `serde(default)` +
    `skip_serializing_if` empty, Go `omitempty`); each runtime records its
    `PolicerRuntimeScope` and publishes one scoped row per instance;
    the Go index keys by `(family, filter, term, policer)` and skips
    unscoped rows so an older helper's aggregate is never misattributed
    to a term. Name-scoped consumers (Prometheus, status summary) fold
    rows back via `AggregateThreeColorPolicerCountersByName`. The
    retired-eBPF compiler (`pkg/dataplane/compiler_filter.go`) now
    allocates a distinct `policer_configs` slot per
    `(family, filter, term, policer)` instance (1-based, `MaxPolicers`
    cap retained; unreferenced definitions keep one name-scoped slot;
    three-color wins a name collision, matching userspace lowering).
    No `filter-specific` config representation exists, so the Junos
    term-specific default always applies.
