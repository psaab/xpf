# #12907 — explicit RPM IPv6 %zone missed RETH/unit normalization

- **Timestamp**: 2026-10-14
- **Action**: `resolveLinkLocalZone9026` now routes an explicit `%zone`
  through `routing.ResolveProbeInterface(zone, rethMap)` — the same RETH →
  physical-member, default-`.0`-strip, slash normalization the
  `destination-interface` path uses — instead of a bare `config.LinuxIfName`.
  `fe80::1%reth0.0` now scopes to `ge-0-0-2` and probes instead of holding on
  ENODEV against the kernel-nonexistent `reth0.0`; zone precedence over
  destination-interface and the rethMap-miss (#7173) fail-closed hold are
  unchanged.

- **Risk**: An explicit `%zone` that previously spelled a valid kernel netdev

  only Junos/RETH-spelled zones change behavior, from held to correctly scoped.
