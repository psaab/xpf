# #14340 — Container-form term and nested term grandchildren silently dropped in compileApplications

## Defect
- `pkg/config/compiler_applications.go`: a container-form term
  `term { t-ssh { protocol tcp; destination-port 22; } }` on a multi-term
  application was silently discarded on strict `CompileConfig` (0 errors,
  0 warnings, lenient too). `applicationTermKeys` returned nil for
  `len(prop.Keys) < 2` (the nameless container node) and the `case "term"`
  arm `continue`d; `applicationTermNodes` only saw direct leaves, unlike
  `compileFirewall`/`compilePolicies` which unpack containers via
  `namedInstances`. A deny referencing the application silently lost
  tcp/22 (fail-open) whenever a sibling term kept the app non-empty.
- Grandchildren inside a term were truncated: `applicationTermKeys`
  flattened only `c.Keys`, ignoring `c.Children`. A trailing block
  (`destination-port 8443 { foo; }`) vanished silently; a nested block
  value (`destination-port { 443; }`) reached the term with no value.

## Fix
- `compiler_applications.go`: `isContainerTerm14340` /
  `expandContainerTerm14340` unpack a container term into synthesized
  named-term nodes (`Keys ["term", <name>]`, child body as children),
  mirroring `namedInstances`; `compileApplications`' `case "term"` expands
  them through the unchanged `applicationTermKeys` +
  `parseApplicationTerms` path. `applicationTermNodes` expands the same
  way, so `collectApplicationCollisions` predicts exactly the names the
  compiler mints.
- `applicationTermKeys` now flattens term children recursively
  (`appendTermNodeKeys14340`): a nested block value contributes its value
  token (honored), a trailing grandchild block contributes its tokens as
  trailing term tokens, which `parseApplicationTerms` records as
  `UnknownTermLeaves` for the strict gate.
- A term yielding no named term (empty container `term { }`, bare `term`)
  is recorded as `"term"` on `IncompleteDirectLeaves` instead of the old
  silent `continue`; `validateApplicationSyntaxStrict` words that entry
  as a missing term name. Tolerant path downgrades to a warning as usual
  (#1960 no-brick). `types_security.go` documents the new entry.
- NOT changed: canonical `term <name> { ... }` handling, flat-set chained
  terms, and the pre-existing protocol-less empty-term behavior
  (`term { t-x { } }` still expands to a protocol-less term, same as the
  canonical spelling — out of scope, noted as residual).

## Tests
