# Issue #14423 — `groupReplace` port leaves: range-free group members dropped beside inline peer

## Why

The firewall `from` port leaves (`destination-port`, `source-port`,
`destination-port-except`, `source-port-except` in family inet and
inet6) and the NAT rule `match destination-port` (source and
destination NAT) are schema `args:1, multi:true, groupReplace:true`.
The `groupReplace` flag exists to keep a RANGE spelling
(`1000 to 2000`, which packs the `to` separator onto the member list)
or an operation keyword from being token-merged under apply-groups.

But `isLeafListSchema` gates on `!groupReplace`, so
`leafListUnionEligible` was unreachable for these leaves. In
`mergeNodes` (`pkg/config/ast_groups.go`) a group leaf
`destination-port 443` beside an inline leaf `destination-port 80`
found its keyword peer, failed every union/promote/same-instance
check, and hit the leaf branch's `continue` — the group member was
silently dropped. The block spelling of the group value dropped the
same way (the block branch skipped the union path for the same
`isLeafListSchema=false` reason, then the container path found no
same-keyed container and `hasMatchingLeaf` dropped it).

Consequence: `inline destination-port 80` + `group destination-port
443` in a `then discard` term compiled to match `{80}` only — traffic
to port 443 fell through to later terms / the implicit accept
(fail-open). For `*-except` the direction flips: the lost group
exclusion made port 443 match an accept term the operator had
excluded. The drop happens in `ExpandGroups`, before any
path-specific gate, on both the strict commit and lenient
load/sync paths. The NAT subcase narrowed a rule's match the same
way.

The pinned test `TestApplyGroupsLeafListPortRangeOverrides` pins
only range-vs-range override (`1000 to 2000` vs `3000 to 4000`); no
test pinned range-free-vs-range-free, and the repo already owned the
discriminator — `leafListCarriesRange` — that separates the two. The
`groupReplace` flag made it unreachable for these leaves.

## What

- `pkg/config/ast_groups.go`:
  - New `isGroupReplacePortSchema`: resolves the schema node for the
    key under the merge's ancestor path (via the existing
    `schemaAtAncestorPath` + `resolveSchemaChild`) and requires
    `multi && children==nil && args<=1 && groupReplace`, additionally
    scoped to the four port keywords. Scoping by schema identity +
    keyword means the other `groupReplace` leaves (`then community`,
    `then as-path-prepend`, NAT pool `address` packing `port <n>` /
    `to`) never qualify.
  - New `groupReplacePortUnionEligible`: union only when neither the
    inline peer nor the group node carries a `to` range separator
    (`leafListCarriesRange`). Either side ranging keeps the pinned
    inline-wins override.
  - Leaf branch: the union condition is now
    `leafListUnionEligible(...) || groupReplacePortUnionEligible(...)`,
    still merging through `mergeLeafListInto` (dedup, block-peer child
    append, #9862 per-member provenance all reused). This covers
    group-leaf × inline-leaf and group-leaf × inline-block.
  - Block branch: the leaf-list block gate now also accepts
    `isGroupReplacePortSchema`, and its union check consults the same
    new predicate — covering group-block × inline-leaf. When the
    predicate fails (a range on either side) the group block is
    dropped exactly as before. Group-block × inline-block already
    survived via one-level-down child merge and is unchanged.
  - #9862 except-filter at the top of `mergeNodes`: the per-member
    filter pre-pass now also runs for port leaves, so an
    `apply-groups-except` exclusion filters individual unioned port
    members instead of passing the whole node through unfiltered.
  - NOT changed: `isLeafListSchema` itself (the `!groupReplace`
    exclusion still guards every non-port leaf), the schema flags,
    and both compilers. The firewall compiler resolves each surviving
    token independently (`resolveFilterPortTokens` over
    `firewallMatchValues`, appended across nodes) and NAT routes
    through the range-aware `parseDNATPortList`, so a range-free
    union is exactly the member set — no compiler change needed.
- New regression `pkg/config/apply_groups_port_union_dr16h1_test.go`:
  leaf×leaf for all four keywords × both families × both authorship
  orders; all four shape pairs (block×block pinned as the surviving
  control); bracketed members; shared-member dedup; range guards
  (group-range/inline-plain, group-plain/inline-range,
  group-block-range/inline-leaf all still override);
  `then community` still overrides; compiled end state via
  `CompileConfig` (discard term matches `{80,443}`, except term
  excludes `{80,443}`, DNAT rule matches `{80,443}`).

## Validation

- RED on base `1c443e0d0` (worktree off `origin/master`): all
  range-free cells fail with `missing member "443"; got [80]`;
  compiled discard term matches `[80]` only, except term excludes
  `[80]` only, DNAT rule matches `[80]` only. Range-override,
  community-override, and block×block controls pass on base as
  expected.
- GREEN after the fix:
  `go test ./pkg/config/ -run 'TestApplyGroupsPort|TestApplyGroupsLeafList'`
  passes, including the pre-existing pinned
  `TestApplyGroupsLeafListPortRangeOverrides`,
  `TestApplyGroupsLeafListThenCommunityOverrides`, and
  `TestApplyGroupsLeafListThenAsPathPrependOverrides`.
- `go test ./pkg/config/ -run 'TestApplyGroups'` passes.
- Rebase fold onto master carrying #14444 (`groupReplace` block
  override): hyphen ranges (`1000-2000`) now also keep the override
  via #14444's `groupReplaceBlockCarriesRange14444` predicate, and
  block×block (incl. two-group fan-in) is decided by #14444 instead
  of the #14423 block branch — `TestGroupReplaceBlock*` passes.
  Full `pkg/config` suite passes except the census panics and one
  #14400 cell that also fail on clean `origin/master` (verified in a
  detached base worktree); `go vet ./pkg/config/` is clean.

## Risk

- Behaviour delta: range-free port members inherited from a group
  now union with the inline peer instead of being dropped — configs
  that (unknowingly) relied on the drop will widen their port match
  to what the operator wrote. Range-bearing values on either side
  keep the exact previous override, and every other `groupReplace`
  leaf is untouched.
- Residual: a group port leaf with NO inline peer is adopted whole
  (unchanged), including a range spelling; that path never dropped
  and is not part of this mechanism.
