# #12881: remap concrete zones during global and wildcard policy renames

## Summary

`remappedQueryZones` previously remapped a session's ingress/egress only when
its concrete zone name equaled the policy binding's source scope. Global
(`junos-global`) and wildcard (`any`) policy bindings do not carry those
concrete names, so a simultaneous concrete security-zone rename left the
session query using the removed zone name and caused fail-closed teardown.

Policy rename bindings now carry the concrete zone rename mapping from the same
apply's ancestry descriptors. Session zones are mapped independently on each
side before policy-scope remapping and the existing new-zone-ID validation.
Special policy scopes remain unchanged; only concrete session zone names in the
validated rename map are translated.

## Regression coverage

`pkg/daemon/daemon_policy_rename_test.go` adds global-policy and wildcard-policy
rename cases combined with a concrete zone rename. The global case uses a
non-zero policy ID and verifies a session is rematched and rebound with the new
concrete ingress zone ID. Both cases verify the remapped query and resulting
zone IDs.

Before the fix, the two regression cases failed: `remappedQueryZones` returned
`ok=false` for both scopes because the concrete session zone did not equal the
binding's `junos-global`/`any` source scope.

## Validation

- `go test ./pkg/daemon/ -run 'TestRemappedQueryZones(SimultaneousPolicy|WildcardPolicy)AndZoneRename12881' -count=1` passed after the fix (initial RED run failed as expected).
- `go test ./pkg/daemon/ -count=1` did not complete: the package hit its 10-minute test timeout with unrelated canary tests blocked waiting on their test harness (`TestPersistentNATResolvedOncePerOperation`, `TestLegacyDPAccessorRemoved`, and others). No failure in the rename regression appeared in that run.

## Risk

The mapping is attached only to policy rename bindings produced from the same
set of ancestry descriptors. It does not alter `any` or `junos-global` policy
identities, session-zone validation, or fail-closed behavior for unknown zones.
