# Issue #15225 — ddns fix cohort (A40-02, A40-03, A40-05)

- **Issue:** Three validated MATERIAL defects: (A40-02) Surface A renumber after an ambiguous publish removed the wrong prior value and orphaned the live one; (A40-03) the http:// credential gate for generic url-templates recognised only a fixed key-name list, so `pass=`/`key=`/`api-token=`/`pwd=`/`p=` shipped in cleartext; (A40-05) the RFC 2136 update zone was guessed by stripping one label, so every DHCPv6 PTR targeted a /124 nibble zone and apex/deep names targeted the wrong zone.
- **Context read:** Read the complete #15225 body. No comments present, so no scope withdrawal, narrowing, shipped-notice or contradiction. All three sub-issues are in scope; the acceptance requires probe sequences ending `wire=[C]`, all A40-03 probe templates refused with loopback http still working, and a PTR publish against a server authoritative for `8.b.d.0.1.0.0.2.ip6.arpa`.
- **What:**
  - **A40-02** (`surface_a.go`, `backend.go`, `state.go`, `backend_rfc2136.go`, `backend_cloudflare.go`, `backend_route53.go`): `LeaseDNSRecord.PrevAddrs` carries the full ambiguous candidate set (superseding single `PrevAddr` when >1); `ownedRecord.AmbiguousPriorAddrText` durably retains the prior desired value. `publishLocked` collects every candidate from a pending row, threads them to the backend (rfc2136 removes all in one UPDATE; cloudflare deletes every candidate row; route53 drops every candidate in the merge), and on wire error rolls back ONLY on a definitive rejection (`errDDNSConflictRefused`, `errHTTPAuth`, definitive rcodes, permanent config errors) via `isDefinitivePublishRejection` — every other error keeps the pending row with all candidates. Confirm-save clears both prior fields; `withdrawTargets` includes the ambiguous candidate. Two pinned tests updated with documented rationale: `TestSurfaceADurablePendingInProcessRollbackRestoresPrev` (bare failure is now ambiguous-pending, never falsely confirmed) and `TestSurfaceAPublishBackoffDoesNotDelayWithdraw` (withdraw now deletes both candidates, 2 deletes).
  - **A40-03** (`pkg/config/compiler_ddns_tls.go`, `pkg/ddns/backend_plaintext_14386.go`): both mirrored detectors now treat ANY literal query value (non-empty, no `%`, no `{{`) as credential-carrying, while credential-named path pairs (`/update/token=SECRET`, #14439) remain flagged and bare path segments / placeholder-only / value-less templates remain unflagged. Strict commit rejects, lenient load drops, direct construction refuses; loopback http still works. No explicit-opt-in exception was added (the issue allowed "refuse or warn"; refuse is the fail-closed choice and matches the existing #14386 posture — a new opt-in leaf would be a second spelling of a cleartext-credential config).
  - **A40-05** (`backend_rfc2136.go`, `manager.go`, `surface_a.go`, `pkg/config/*`): SOA-walk zone discovery — `discoverZone` returns explicit leaves / matching configured domain without a query, otherwise walks SOA queries toward the root against the update server itself (cached per updater), falling back to the legacy guessed zone on any failure so existing NOTAUTH handling is unchanged. Explicit `forward-zone`/`reverse-zone` leaves shipped on both the DHCP `dynamic-dns` block and the Surface A provider catalog (schema + compiler + `ddnsPolicy` + Surface A carrier). The fake DNS test server gained `setAuthoritativeZones` (SOA answers + NOTAUTH for non-authoritative UPDATE zones).
- **Layer choice:** A40-02's ambiguity is a property of the publish outcome, so it belongs in `publishLocked`'s durable row + the wire record's candidate set, not in any one backend. A40-03's detector is mirrored in config + ddns by design (#14386), so both copies were widened identically. A40-05's zone is a wire-targeting fact known only at the backend, so discovery lives in `rfc2136Updater` next to the existing resolvers.
