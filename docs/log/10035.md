# Issue #10035 — distinguish exact-match neighbor fences

## Context

Read the complete #10035 issue body and all comments before implementation. The
issue had no comments and did not withdraw, narrow, mark-shipped, or contradict
the requested change. Read the complete #9696 issue body and both comments as
context; #9696 preserves the distinguishable nonzero-ACK fence arm.

The helper fences an authoritative replace when `generation != 0 &&
generation <= applied_manager_generation`, but previously returned only the
applied-generation ACK. A fence at `generation == applied_generation` therefore
looked identical to an applied replace in Go.

## Change

- Added the additive, optional `ProcessStatus.neighbor_replace_applied` status
  field (`Option<bool>` in Rust, `*bool` in Go). `true` means the replace was
  applied and `false` means the helper fenced it. `None`/omission preserves
  mixed-version compatibility.
- The Rust `update_neighbors` handler sets the bit from the real coordinator
  result before attaching the normal status response.
- Both Go neighbor senders classify a present false bit as a fence, including
  the exact-match case. The existing #9696 ACK-mismatch classifier remains the
  fallback when the field is absent, and legacy ACK 0 remains an applied
  fallback.
- Kept retry debt, index/table preservation, and the single-writer generation
  invariant unchanged. Updated the neighbor protocol documentation and
  #9684 outcome comments.

## RED then GREEN

- **Go RED (exact-match fence):** With the new fault-injection cell returning
  ACK 5 plus `neighbor_replace_applied=false` while sending generation 5, and
  before Go consulted the bit, `go test ./pkg/dataplane/userspace -run
  'TestNeighborReplaceExactMatchFenceAppliedBit10035|TestNeighborReplaceAppliedBitAbsentKeeps9696Fallback10035' -count=1`
  failed in both sender cases: the fenced replace incorrectly emptied the
  cached neighbor table.
- **Rust RED (response bit):** With the handler's outcome assignment
  temporarily removed, `CARGO_TARGET_DIR=/dev/shm/cargo-10035 cargo test --bin
  xpf-userspace-dp update_neighbors_response_distinguishes_apply_and_exact_fence_10035`
  failed 0 passed / 1 failed: the accepted replace returned `None` instead of
  `Some(true)`.
- **Go GREEN:** The same exact-match and legacy-fallback cells passed after the
  Go classifier and test hook were updated. The full neighbor-fence command
  `go test ./pkg/dataplane/userspace -run
  'TestNeighborReplace.*10035|TestNeighborReplace.*9696' -count=1` passed all
  listed sender, recovery, defensive-lower-ACK, exact/legacy, mask-preservation,
  applied-bit, and wire-round-trip cases.
- **Rust GREEN:** The same Rust response cell passed after restoring the
  handler assignment; the `update_neighbors` response carried true for apply,
  false for the exact-match fence, and retained ACK generation 7.
