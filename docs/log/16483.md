# Issue #16483 — Flow-backed poisoned DNAT drop does not advance the rule counter

- **Issue:** On the flow-backed (TCP/UDP, session-miss) path, a packet dropped
  by a poisoned DNAT rule (#14947 `lenient_match_dropped`: empty/unresolved
  address name or unready dynamic feed, failing closed) did not advance that
  rule's `NatRuleCounter`, though the #15534 flowless path counts the same
  drop for the same reason (no session is ever installed). Port-bearing
  traffic is the dominant shape, so `show security nat destination rule`
  showed hits only for flowless fragments (normally 0) while every flow to
  the rule was blackholed and no other counter moved — a longer outage
  diagnosis. Fail-closed enforcement itself was correct; this is an
  accounting inconsistency between two implementations of one contract.
  Severity Low. Finding `R3-A60-02`, validated COHORT x3.
- **Defect site:** `userspace-dp/src/afxdp/poll_descriptor/mod.rs`, the
  session-miss pre-routing DNAT lookup: `lookup_result_with_counter_scoped`
  (and the #16045 ambiguous-provenance sibling) returns
  `(DnatLookup::Poisoned, counter)`, but the `Poisoned` arm set
  `dnat_poisoned = true` and discarded `counter`. The healthy
  `pre_routing_dnat_counter` is only charged at a committed session install,
  which a poisoned drop never reaches.
- **What:** In the `Poisoned` arm, count the drop before recycling the
  descriptor, mirroring `flowless_verdict.rs` (#15534) verbatim in intent:
  `if let Some(c) = &counter { c.add(meta.pkt_len as u64); }`. No other
  behavior changes: the packet still drops (fail-closed), no session is
  installed, and the persistent-DNAT-denied arm is untouched (no documented
  counter contract for it).
- **Tests:** New `poisoned_dnat_counter_16483_tests.rs` drives a real TCP SYN
  to a DNAT VIP through `txn_run_descriptor_checked` with a shared
  `NatCounterStore` (counter_id 16483): poisoned subject advances the rule
  counter by exactly 1 packet / 54 bytes with 0 sessions and 0 forwards;
  healthy control installs a session and advances by exactly 1 per installed
  flow (not double-counted).
