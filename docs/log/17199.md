# Issue #17199 — R4-Q07-02: TunnelKind SSOT bypassed by raw tunnel-mode string compares

- **Issue:** `TunnelEndpoint.mode` stayed a `String`; `tunnel_mode_kind` (#2327) had 12 production callers while 21 sites compared the string directly. In one build an Unknown-mode endpoint was "not GRE" for the decap index but "GRE" for the outer-RG map, the HA outer-RG gate and the MSS formula (binary WireGuard-vs-else splits). The #6924 Go drift guard reads only the SSOT and cannot see the bypass.
- **STEP-0 (defect live on origin/master `eb4571c7ef`):** `grep -rnE '\bmode ?(==|!=) ?"(wireguard|gre|ip6gre)"' userspace-dp/src --include='*.rs'` returned 34 lines (21 production compares + doc comments quoting them). Confirmed the binary splits at `forwarding/ha.rs:303`, `forwarding/mss.rs:207`, `forwarding_build/mod.rs:1241`, `shared_ops/lookup.rs:352` and the supervision compares in `coordinator/tunnel_supervision.rs`. Not FIXED on master; implemented the named fix.

## What

1. **`kind: TunnelKind` on `TunnelEndpoint`** (`types/forwarding/tunnels.rs`): decoded once in `populate_tunnel_endpoints` via the sole decoder `tunnel_mode_kind`; `mode: String` stays for show/telemetry only. `TunnelEndpoint`'s Debug now keys the privkey redaction label on `kind`.
2. **All 21 production compares replaced with `endpoint.kind` matches:** `forwarding_build/mod.rs` outer-RG maps (only `Gre` enters `tunnel_outer_egress_rgs`; WireGuard per-peer map only for `WireGuard`), `forwarding/ha.rs` and `shared_ops/lookup.rs` (Unknown matches neither arm → no outer RG → HAInactive/decline, previously GRE), `forwarding/mss.rs` (Unknown → 0, previously the GRE formula), `forwarding_build/wg.rs`, `coordinator/{mod,status_wg,tunnel_supervision,wg_control/*}`, `tunnel.rs`, `wg_uncovered_forward.rs`, plus the per-packet re-derivations (`frame/*`, `tx/dispatch`, `wg/decap`, `gre`, `icmp_ptb`) which now read the stored `kind` instead of re-classifying the string. Snapshot-row sites (`hydrate_wg_identity`, the deferred-prune row check) keep using `tunnel_mode_kind` — the only string-to-kind decoder besides `populate`.
3. **Guard (new Rust source-scan test):** `no_raw_tunnel_mode_string_compares_outside_ssot_17199` in `forwarding_build/tunnels.rs` walks every production `.rs` under `src/` and rejects any `mode ==/!= "wireguard|gre|ip6gre"` outside the SSOT's own match arms (test files excluded — they legitimately author modes). Doc comments quoting the old compares were reworded so the acceptance grep is exactly 0.
4. **Test fixtures:** the 8 direct `TunnelEndpoint {` literals and post-construction `.mode =` mutations in tests now set `kind` consistently with `mode` (via the literal kind or `tunnel_mode_kind(mode)`), so test endpoints cannot desync the two fields.
5. **Build blocker (not this issue):** the bin test target did not compile on master (`shared_umem_tests.rs:247` E0308, owned by #18234 / PR #18241). Cherry-picked that PR's test-only head commit `050bf91910` onto this branch to unblock hermetic runs, per the sibling engineer's explicit advice; it drops cleanly on rebase if #18241 lands first. Flagged for Main at merge time.

## Named hermetic tests

- **New (all PASS, `-- --exact`):** `unknown_mode_endpoint_is_unknown_and_absent_from_outer_rg_17199` (Unknown endpoint: kind Unknown, absent from decap index AND `tunnel_outer_egress_rgs`, MSS 0), `gre_mode_endpoint_is_gre_and_indexed_17199` (positive control), `no_raw_tunnel_mode_string_compares_outside_ssot_17199` (guard; fail-on-revert by construction).
- **Existing (PASS):** `unknown_tunnel_mode_classifies_as_unknown_not_gre` (classifier contract), `tunnel_tcp_mss_gre_unchanged_for_gre_endpoint`, `tunnel_tcp_mss_wireguard_uses_wg_overhead_not_gre` (MSS dispatch unchanged for real kinds).
- **Acceptance grep:** `grep -rnE '\bmode ?(==|!=) ?"(wireguard|gre|ip6gre)"' userspace-dp/src --include='*.rs'` → **0** (was 34). Remaining production `tunnel_mode_kind(&…)` calls: exactly 3, all on snapshot rows / the populate pass — the sole decoder sites.
- No broad suites run per campaign rules.

## Risk

Behavior-identical for every committed mode (`gre`/`ip6gre`/`wireguard` classify exactly as the string compares did; the supervision `!= gre && != ip6gre` tests are `!= Gre`). Changed only for Unknown: previously GRE in the outer-RG map, HA gate and MSS formula, now uniformly Unknown (no RG, HAInactive, MSS 0), matching the already-fail-closed encap dispatcher — so no live forwarding outcome changes (Unknown was already dropped at encap). Residual: `mode` and `kind` are both stored; a future post-construction mutation of one without the other would desync — mitigated by the source-scan guard (production) and by keeping all test mutations paired.
