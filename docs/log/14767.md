# 14767 — SNMPv3 flat and system-elided placements still compile weaker than written (residual of #14411)

- **Timestamp**: 2026-10-17
- **Action**: gate every `v3` child, mirror compileSystem's synthetic
  `system snmp …` root, and gate the fully-packed flat user run in the
  #9155/#14411 strict gate.
- **File(s)**: `pkg/config/compiler_validate_strict_snmpv3_level_9155.go`,
  `pkg/config/snmpv3_packed_protocols_14411_test.go` (new cells).

## The defect

PR #14737 (squash `86cac69c3`) fixed the packed/case-variant/wrapped/
ancestor cells of #14411, but its gate resolved only the FIRST `v3`
child of an snmp root and never saw two compiler spellings. Measured on
`origin/master` (`164f51d63`) via a CompileConfig probe, all
commit-clean and weaker than written:

1. `system snmp v3 usm local-engine user alice Authentication-SHA256
   authentication-password APASS;` — compileSystem synthesises the snmp
   node from the system node's own Keys; the gate never mirrors that
   root, so the case-variant is dropped and no user compiles.
2. `snmp v3 usm local-engine user alice Authentication-SHA256
   authentication-password APASS;` — compact normalization splits the
   run onto a `v3` child whose Keys the per-v3 walk cannot turn into a
   user; the user compiles bare (noAuthNoPriv).
3. Same flat form with `authentication-sha512` — unknown protocol
   dropped, bare user.

A second `v3 { … }` block's bad user was likewise ungated by the #9155
arm (one spelling was incidentally caught by #14401's bare-password
gate with the wrong diagnosis).

## Fix

In `validateSNMPv3SecurityKeywordStrict` (#14767 arms; the per-v3 body
is extracted unchanged as `validateSNMPv3Node14767`):

- iterate EVERY `v3` child via `packedBodyChildren`, as compileSNMP does;
- synthesise the `system snmp …` root exactly as compileSystem does
  (`&Node{Keys: sys.Keys[1:], Children: sys.Children}`);
- gate the fully-packed flat user run directly — both the pre-normalized
  shape on the snmp node's own Keys and the post-normalization `v3 …`
  child shape — via the existing `checkSNMPv3UserKeywords9155`.

Valid flat/system-elided authPriv spellings still compile both halves
(probe-verified controls).
