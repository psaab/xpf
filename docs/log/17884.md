# #17884 — Keep the DHCP lease seed behind the restart barrier

- **Timestamp**: 2026-10-26
  - **Action**: The 20-second apply wait used to continue to control-socket readiness and lease-add after its deadline even when the takeover generation had not been applied. The post-start seed is the only backstop after a failed memfile pre-seed, so this could send lease-add to the old Kea, receive `Invalid subnet-id`, and lose the backstop permanently. The wait now logs at the former deadline but continues until the wanted families publish the apply generation or the caller context is canceled. The daemon discards the pre-wait lease values and re-fetches each family's peer snapshot after the apply/socket waits, so peer lease lifetimes age through the wait before re-anchoring; expired rows remain dropped.
  - **File(s)**: `pkg/daemon/daemon_dhcp_lease_sync.go`, `pkg/daemon/dhcp_seed_order_16855_test.go`, `debian/changelog`, `docs/log/17884.md`
  - **Validation**: The regression `TestSeedWaitDoesNotFailOpenOrReanchorOldSnapshot17884` failed under a simulated fail-open revert with `oldAdds=1 newAdds=0` while restart was blocked; with the fix restored, `GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/var/worktrees/.cache/go-tmp go test ./pkg/daemon -run '^TestSeedWaitDoesNotFailOpenOrReanchorOldSnapshot17884$' -count=1` passed. The focused seed/lease suite `GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/var/worktrees/.cache/go-tmp go test ./pkg/daemon -run 'TestSeed|TestDHCPLease|TestWait' -count=1` passed. Full `go test ./pkg/daemon -count=1` did not pass: unrelated package failures included DNS rollback and feed rollback tests, DHCP config-filter tests, nft netlink parity, Unix-socket binds rejected with `invalid argument`, and a factory-reset test panic; the run also logged permission-denied attempts to mutate `/proc` and `/var/lib/xpf`.
  - **Risk**: If a takeover generation never becomes applied, the sole post-start seed waits rather than seeding an unverified Kea process. The production caller currently supplies `context.Background()`, so a permanently unapplied generation can leave this goroutine waiting indefinitely; the pre-start memfile pre-seed remains the primary protection, and a later successful apply allows the backstop to continue.
