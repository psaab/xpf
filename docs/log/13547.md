# Preserve NAT off over-exemptions for empty application sets (#13547)

- **Issue**: #13547 — tolerant compilation narrowed a mixed valid/empty
  application-set `then ... off` exemption to the valid members, allowing
  traffic outside those members to fall through to later NAT rules.
- **Cause**: DNAT and SNAT expanded application sets but did not treat an
  empty expansion or expansion error as a broken application reference. The
  existing #12631 over-exemption logic therefore did not widen the `off`
  selector when a mixed list included an empty or broken set.
- **Change** (`pkg/dataplane/userspace/nat_destination.go` and
  `nat_source.go`): treat empty or failed application-set expansion as a
  broken axis for off exemptions and add the match-all app term, bounded by
  the rest of the authored rule. Translation rules retain their fail-closed
  behavior. Regression coverage in
  `nat_off_empty_appset_13547_test.go` covers DNAT/SNAT mixed, empty-only,
  and broken-set-only exemptions, and verifies translation remains narrow.
- **RED evidence**: on pristine master `d7fe769aa`, the new regression tests
  failed for both mixed valid/empty and mixed valid/broken sets. DNAT emitted
  only the valid `tcp/80` row; SNAT emitted only the valid `tcp/80` term.
- **GREEN evidence**: focused new regressions passed with
  `go test ./pkg/dataplane/userspace -run
  'Test(DNATOffMixedEmptyOrBrokenAppSetOverExempts13547|SNATOffMixedEmptyOrBrokenAppSetOverExempts13547|NATTranslateEmptyOrBrokenAppSetStaysNarrow13547)$'
  -count=1`. Full `go test ./pkg/dataplane/userspace -count=1` did not pass:
  159.618s; failures included Unix socket path errors, contract/snapshot
  golden drift, Junos host scope expectations, and unrelated assertion
  failures. This run did not establish those failures' baseline status.
- **Risk**: malformed/empty application sets in tolerant `off` rules now
  exempt more traffic on the affected application axis, as required by
  #12631; their other configured match dimensions remain in force.
