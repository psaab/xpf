# #12067 — strict-reject unconsumed route-filter tokens

- **Timestamp**: 2026-10-08 (stacked on #12070 / `093a296d7`)
- **Action**: reject route-filter tail tokens the match type does not consume during schema validation, before compilation can discard them.

## Red before

On the correct parent `093a296d7`, the focused schema regressions produced 15 acceptance failures (7 flat, 8 hierarchical): `SchemaValidate` returned nil for unconsumed tails including `orlonger reject`, `orlonger foo`, `exact 17`, `upto /24 extra`, malformed `upto`, and child-block tails. The two hierarchical match-all forms (`route-filter ... { orlonger; }` and `route-filter ...;`) also failed their regressions: the compiler emitted `route-map P permit 10` without a match clause. The `configstore.CheckText` regression accepted `orlonger foo`. Opus's additional probe on reviewed head `24df0e0c9` confirmed that bare `upto` in hierarchical, set, and compact forms committed as `permit 10.0.0.0/8 le 32`. Commit `b939ca090` is not an ancestor of the reviewed head; it was the pre-fold #12070 head and was not used as the RED baseline.

## Change

- Wired route-filter node validators into the existing `from`/`route-filter` schema nodes. They allow one compiler-consumed trailer for `upto`, `prefix-length-range`, and `through`; reject unconsumed packed tokens and hierarchical children; reject malformed or missing `upto` lengths; and report the actual unconsumed child token. A missing match-type must remain on the statement line.
- Added a matching packed-`from` scan for compact hierarchical syntax. A quoted or bracketed `route-filter` at the run head is treated as the keyword, matching compiler dispatch; quote/bracket provenance still protects value positions. The validators defer sibling-shaped tails to the existing #8437/#9027 gates so their targeted diagnostics remain authoritative.
- Added schema, CheckText, and Store commit-path regressions for quoted/bracketed heads, bare `upto`, sibling diagnostic precedence, and child-form token reporting, with valid consumed-tail and `prefix-list route-filter` controls.
- The compiler and FRR renderer were not changed; accepted `upto` and `prefix-length-range` operands retain their existing interpretation and output.
