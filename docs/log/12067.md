## Change

- Kept the #12067 schema checks for route-filter children and compact `from` runs. The packed scanner reuses `splitPolicyTermFromRun11779`, so value positions follow compiler schema arity and a `route-filter`-named prefix-list, community, or as-path remains a reference. Removed the dead `upto` branches.
- Added a strict compiled-config gate for `upto` with `UptoLen == 0`, retaining an invalid operand in `RouteFilter.UptoToken` so diagnostics distinguish malformed/out-of-range lengths from a missing operand. The term-line bare `route-filter` marker is gated by `inFrom`, preserving the #11779 fail-closed behavior without misclassifying `then community add route-filter`.
- Added CheckText and Store regressions for the bare head, missing `upto` length, then-first/body/group/packed variants, valid `/24`, V1/V2/V3 value-reference controls, braced/quoted controls, quoted-head/provenance behavior, and #8437 Q5/X5/C4 diagnostics.
- FRR rendering was not changed; valid `upto /24` still renders as `le 24`. The parser-security pin retains tolerant parsing of zero-length `upto`. On tolerant load and peer-sync, however, the #11779 `UnknownFrom` quarantine forces affected term-line forms to `reject`; see the risk section. Zero-length `upto` remains warning-only and retains the historical `le maxLen` fallback.

## Residual / risk

The #11779 tolerant quarantine changes these term-line cases: bare `from
route-filter` and `from prefix-list route-filter` previously rendered
permit-all, while `from route-filter ... exact route-filter` rendered a
permissive matched permit. They now compile to `Action=reject` on `Store.Load`
and `SyncApply` (deny at boot or sync). This is fail-closed, but a rolling HA
upgrade can temporarily diverge between peers. Zero-length `upto` remains
warning-only and retains the historical `le maxLen` renderer fallback. No
live-FRR run was performed.

The separate then-first LoadMerge/LoadSet/direct-set `from`-clause loss is filed as follow-up #12516.
