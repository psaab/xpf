## Change

`appendBindInterfaceOnlySecureTunnelRows` previously skipped a zoned `st0.0` as soon as the ordinary builder had emitted any row using the same Linux netdev. A declared `st0 unit N` (N > 0) emits a base `st0` row, which can carry an alphabetically inherited sibling-zone value; it does not stand in for the authored unit-0 identity. The synthesis now retires that non-authored base alias only when no `st0.0` stanza row or literal bare `st0` zone member already owns the device, then emits the authored unit-0 row. It keeps the existing fail-closed secure-tunnel netdev resolver and one-owner-per-device behavior.

Bare bind-only `st0` snapshot rows now resolve CoS from an explicit zero-unit binding first and otherwise the interface-level binding. When replacing a base row, the synthesized unit row also inherits the parent's administrative-disable state and suppresses live addresses exactly as the regular unit-row builder does. Dotted-row CoS behavior is unchanged. Regression coverage pins unit-N-only stanza coexistence, sibling-zone isolation, the explicitly authored bare-zone control, disabled-parent preservation, the no-stanza and nonzero-bind boundaries, bare-ref interface-level CoS, and unit-over-level CoS precedence.

## RED then GREEN evidence

On the unchanged implementation, the initial focused regressions failed because `st0.0` was absent when the base `st0` row was present, the bare `st0` CoS fields were empty, and the row could not be found for the derived-device assertion. The focused tests pass after the fix.

## Risk

This changes only snapshot ownership of an authored `st0.0` when a base alias would otherwise suppress it, preserves the replaced parent's administrative-disable state, and adds CoS lookup for a bare bind-only base row. An explicitly authored bare zone reference remains authoritative; unresolved/colliding secure-tunnel refs remain fail-closed. No Rust wire fields or policy rules change.
