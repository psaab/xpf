# #14691 — Unvalidated archive-sites destination enables local root file overwrite

## Defect

`scpArchiveTransfer` (`pkg/daemon/daemon_archive_transfer_11806.go`) checked
only `URLHasPassword`, a non-empty known-hosts trust file, and a leading `-`,
then exec'd `scp <srcPath> <dest>` as root with no `--` separator and no
requirement that `dest` be remote. `compileSystemArchival`
(`pkg/config/compiler_system.go`) checked only password/leading-dash per site.

OpenSSH scp decides local-vs-remote by the text before the first colon: no
colon, or a colon only after a `/`, means a local operand. Verified against
the real scp in this environment: `scp -o StrictHostKeyChecking=yes ... src
/var/.../dst` exited 0 and overwrote the target without consulting SSH, and
`:` / `user@` also exit 0 as local copies. Since `archiveToSitesNow` writes
the unredacted `ShowActive()` (root/login hashes, IPsec PSKs, WireGuard
private keys) to the staging file, a local-path site (`/etc/cron.d/x`, a
relative path, `:::/cfg`, `//host/path`) overwrites an arbitrary root file
with config text and discloses all secrets to any local reader — bypassing
#10298 host-key verification and the redacted show surfaces. Trigger is
`transfer-on-commit` or the periodic timer.

Also confirmed with real scp: `ftp://...` is parsed as remote host `ftp`
(not a local write, but a forced-SSH mis-transfer), `user@-oProxyCommand=...`
is rejected by OpenSSH as `hostname contains invalid characters`, and `--`
is accepted by current OpenSSH scp before the operands.

## Fix

One shared validator, `config.ArchiveDestinationError`
(`pkg/config/archive_destination_14691.go`), used at both gates so they
cannot diverge:

- Rejects empty destinations, leading `-` (the #4589 gate, message kept),
  local operands (no colon before any `/`), hostless forms (`:`, `user@`,
  `@host:...`, `:::`/`//host/path` local semantics), non-`scp` `://`
  schemes (`ftp://`), `scp://` URLs with no host / empty user / non-numeric
  port, and users or hosts beginning with `-` (the
  `user@-oProxyCommand=...` host-position class).
- Accepts `scp://[user@]host[:port]/path` (including bracketed IPv6) and
  scheme-less `[user@]host:path` / `[user@]host:` (including bracketed
  IPv6 hosts), preserving every currently-working remote spelling.

Call sites:

- `compileSystem` archive-sites loop: keeps the existing password rejection,
  then returns `ArchiveDestinationError` — strict compile rejects all local
  shapes, including in bracket slot 2+.
- `scpArchiveTransfer`: keeps the password rejection, runs
  `ArchiveDestinationError` before the known-hosts stat (deterministic
  destination reason, also when a tolerant load bypassed the compiler),
  keeps the #10298 trust gate, and adds `--` before the operands as
  defense-in-depth.

Pre-existing tests that encoded the vulnerable behavior were corrected to
remote spellings: `TestArchivalConfigSetSyntax` (`/var/backup` →
`backup:/var/backup`), `TestSetRepeatedArchiveSites` and the #7146 common-case
row (`ftp://...` → `scp://...`), and the #10298 fake-scp argv expectation now
includes `--`.

## Scope cuts

- Syslog `archive-sites` shares only the leaf name; it is not promoted to an
  scp destination and is untouched.
- No change to peer/candidate/rescue lenient-load paths: the runtime
  transport gate covers any destination that reaches an actual transfer.
