## Evidence ledger

1. `policies_addrbook.go`: names are sorted (`allNames`), parsed CIDRs sorted/deduped, the first name to claim a canonical bucket supplies `bucket.v4/v6`; canonical bytes encode parsed network IP and mask length only. Exact wire value is used for the published row, but not the key.
2. `config.CIDRMaskHelperRefusesPadding` determines whether helper rejects an otherwise Go-parseable padded mask; `collectAddressBookCIDRMaskRejections` inspects published rows and refuses publication.
3. Rust `parse_book_prefix_into` parses published book strings as `IpNet`; the preflight fails closed on an unparseable row. Go `net.ParseCIDR("10.0.0.0/008")` succeeds with /8, but the helper compatibility fence classifies that spelling as refused.
4. RED regression run on unmodified source: `GOCACHE=/dev/shm/gocache12852 GOTMPDIR=/dev/shm go test ./pkg/dataplane/userspace -run 'TestAddressBook(WireSpellingNotConflated|PaddedSpellingNotMasked)12852' -count=1` failed both tests because clean and padded names got the same ID (488896378). This proves order/name-independent conflation in both directions.
5. Competing behavior considered: different valid spellings should retain semantic dedup; blanket raw-value keying changes IDs for every ordinary book and unnecessary alias sharing. Chosen minimal boundary: add a distinct suffix only for helper-refused padded values. Thus a clean book does not inherit an unrelated padded spelling; a padded book remains refused and cannot be masked. Tie-break equal parsed networks by raw string for deterministic order.
6. ## Proposed fix disposition

Preserve existing semantic bucket IDs for clean canonical spellings, but include helper-refused raw mask values in the bucket key and order same-network prefixes by `value`. This retains a padded spelling in its own row so the existing rejection collector sees it consistently, while a clean referenced entry no longer shares that row. No changes to strict compiler acceptance, helper parsing, or unrelated aliases.
