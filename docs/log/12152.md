# #12152 — Preserve mixed-family lifeline snapshots

- **Timestamp**: 2026-10-08 (`fix/12152-lifeline-dhcp`)
- **Action**: classify DHCP-managed lifeline addresses per family so a finite-lifetime IPv6 address cannot replace static IPv4 addressing with DHCP-only configuration.

## Red before

Added a bounded regression fixture for a static IPv4 address/default gateway alongside a finite-lifetime SLAAC IPv6 address, plus an IPv4-only control. Before the implementation, `TestMixedStaticV4SLAACV6PreservesStaticV4_12152` failed as expected: the generated `.network` contained only `DHCP=yes`, with neither `Address=192.0.2.10/24` nor `Gateway=192.0.2.1`. The IPv4-only control passed.

## Change

- `snapshotLifelineAddrs` records finite-lifetime DHCP heuristics independently for IPv4 and IPv6.
- `writeBootstrapLifelineNetwork` emits the historical constant DHCP `.network` whenever no family has a static address, preserving byte stability across factory restarts even when DHCP leases or SLAAC addresses are present. Otherwise it snapshots static-family addresses and gateways, and its DHCP directives follow the per-family finite-lifetime classification.
- Coverage asserts the mixed static-v4/SLAAC-v6 case preserves only static v4 addressing, the static-v4 control has no DHCP directive, DHCPv4-only keeps the factory bytes without pinning its lease, and DHCPv4 plus static-v6 preserves the static v6 address/gateway.
