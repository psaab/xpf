# #12871 — reject malformed packed screen tails

- **Issue**: #12871 — D7-03: `compileScreen` silently dropped packed screen profile bodies when schema-directed expansion encountered an unmodelled tail.
- **Branch**: `fix/12871-screen-packedbody-extras`
- **Worktree**: `/home/ps/git/pi-xpf/wt-12871`
- **Base**: `0f19ca45a` (`origin/master` when the worktree was created)

## Why

`packedBodyChildren` intentionally returns the original children when schema resolution fails, rather than inventing a shape for generic callers. For `ids-option P tcp land bogus-tail` and `ids-option P ip ip-sweep 7777`, that leaves the packed tail only in `Keys`; `compileScreen` traverses `Children`, so strict compilation accepted a profile with the configured guard missing and no unknown-leaf diagnostic. The tolerant path likewise compiled an empty profile.

## What

- Added `screenPackedBody`, a screen-local wrapper: keep schema-directed expansion for valid tails, but when it declines a packed tail, split it into single-token nodes using the existing screen family reader. This makes unmodelled tokens visible to `compileScreen`'s existing unknown-leaf accounting and strict/tolerant gates without changing generic `packedBody` behavior or its other callers.
- Routed ids-option and screen-option packed-body normalization through the screen-local wrapper.
- Added strict rejection and tolerant-token-preservation regressions for a recognized TCP flag followed by garbage and an IP-sweep threshold missing its `threshold` keyword.

## Risk

Valid packed tails continue through the shared schema-directed expander; malformed tails become observable unknown leaves and are rejected by the existing strict gate, while the tolerant load path retains its established warning behavior.
