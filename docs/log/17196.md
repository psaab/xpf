# Issue #17196 — shared compound/split `family` extractor

- **Issue:** The compound/split `family` walk had one shared extractor in firewall (`firewallFamilyMembers9883`) and three hand copies elsewhere (interfaces, forwarding-options `family inet6 mode`, sampling instance families). The sampling copy indexed `afNode.Keys[0]` with no guard, so it panicked on an empty-Keys child (malformed persisted/synced AST); all three copies kept the `Keys[1]` preference #9883 removed from firewall, so a leading junk token (`family { bogus inet { … } }`) was silently ignored and the trailing family installed.
- **STEP-0 (defect live on origin/master `843c77ca26`):** `grep -rn 'afNodes = append' pkg/config` returned 6 lines at 3 sites (interfaces, services ×2). A hand-built empty-Keys sampling tree panicked with `index out of range [0] with length 0` on both strict and lenient compile; hierarchical text probes installed the trailing family with no error: `forwarding-options { family { bogus inet6 { mode packet-based; } } }` set `FamilyInet6Mode="packet-based"`, sampling `bogus inet` set `FamilyInet`, interfaces `bogus inet` set `FamilyInet` with its address, and `family { inet mtu 1500 { address … } }` installed nothing (name-keyed gate vs Keys[1] install disagreement).

## What

1. Moved `firewallFamilyMember`/`firewallFamilyMembers9883` from `compiler_firewall_family_9017.go` to the new `pkg/config/family_members.go` as `familyMember`/`familyMembers`, verbatim semantics (packed `Keys[1]`, split child `Name()`, structured-only `Residue`, nil-safe on empty Keys). Renamed all firewall callers (compileFirewall, #3884/#4296/#9017 gates, #16450 level gate, fused-then, valueless-from, nameless-term) — no alias shim.
2. Replaced the three hand copies with the shared extractor: `compiler_interfaces.go` (was `Name()` then `Keys[1]`), `compiler_services.go` forwarding-options family loop (was `Name()` then `Keys[1]`), and `compileSampling` (was unguarded `Keys[0]` then `Keys[1]`; signature now takes `opts compileOpts, warnings *[]string`, threaded from `compileForwardingOptionsWithOpts`).
3. Each caller decides how an unknown member is reported, per the fix direction: `unknownFamilyMember17196` (effective token or structured residue token outside the caller's declared set) + `unknownFamilyMsg17196` (#9017-style `… family "bogus" is not a known address family (known: …) — the configuration under it compiles to NOTHING …`). Strict rejects; lenient (`lenientFamilyMembers17196` in `compiler_opts.go`, registered in `lenientCompileOpts()`) warns and installs nothing for that member. Declared sets: interfaces = Junos AF tokens the interface gates recognise (`isInterfaceFamilyAF12090` set plus iso; known-but-unconsumed families still fall through to the #12090/#12656/#15654 gates), forwarding-options family = `{inet6}`, sampling = `{inet, inet6}`.
4. Interface install token is now the child name for a two-key child (D58-04 direction): `family { inet mtu 1500 { … } }` is residue-unknown and installs nothing, pinned by a fixture in the new test file; well-formed `inet { address …; mtu …; }` spellings are controls.
5. Updated neighbour tests whose fixtures encoded the old silent behaviour: `TestChildShapedFamilyStillCompiles7522` now rides the lenient path (strict rejects the malformed sibling, lenient warns and still compiles the well-formed sibling — addresses assertion unchanged); `TestOnlyTheInet6FamilySetsTheInet6Mode8797` now asserts strict rejects an undeclared forwarding-options family while the lenient seam pins the original invariant that a non-inet6 `mode` is never taken.

- **Named hermetic tests (neighbours, adjusted only as above):** `TestMalformedAddressFamilyNodeDoesNotPanic7522`, `TestWellFormedAddressFamiliesStillCompile7522`, `TestChildShapedFamilyStillCompiles7522`, `TestCompoundFamilyLookupIsNotTwoLevel8797`, `TestOnlyTheInet6FamilySetsTheInet6Mode8797`, `TestLenientCompileOptsCompleteness16166`, `TestLenientCompileOptsHaveReaders17143`, `TestStrictCompileOptsSingleSource17148` — PASS.
- `go vet ./pkg/config` — clean. No broad suites run per campaign isolation.

## Risk

Strict commits carrying an undeclared family token under `interfaces … unit family`, `forwarding-options family`, or a sampling instance `family` — or a structured residue member such as `family { inet mtu 1500 { … } }` — now reject where they previously committed silently (the intended fail-closed change; the same text on the tolerant load/peer-sync path warns and boots, #1960). Persisted trees with an empty-Keys family child now error/warn instead of panicking (sampling) or silently skipping (interfaces/forwarding). Known-but-unconsumed interface families (mpls, ethernet-switching, …) keep their prior fall-through behaviour and existing gates.
