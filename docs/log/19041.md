## First fix, superseded (b331cf35fe)

- **Timestamp**: 2026-11-08 21:06 PST
- **Action**: The first fix made the FAKE take both views at one instant.
  The Codex seat reviewed it (MAJOR, #19041) and found that this hides a
  production harness false-FAIL. `Soak.views()` reads node0 and node1 with
  two independent `show chassis cluster status` commands, so a clean
  handoff can be read as node0 primary just before and node1 primary just
  after, with no real overlap. `one_rg()` and `watch_window()` then record
  dual-active permanently. The seat reproduced this with the real
  `Soak.views()`, `IncusCluster.status()` and `one_rg()` against controlled
  `_exec` responses. The fix belongs in the soak's scoring.

## What (rework)

- **Timestamp**: 2026-11-08 21:25 PST
- **File(s)**: `test/incus/rg_move_soak.py`,
  `test/incus/rg_move_soak_test.py`, `docs/ha-rg-move-correctness.md`,
  `docs/regression-test-matrix.md`
- **Scoring (`rg_move_soak.py`)**: a dual-active sample is a SUSPECT.
  - `Soak.resolve_dual_suspect()` re-samples at once. The pair scores
    dual-active only when the re-sample is dual-active too, or when the
    re-sample is unreadable (missing or duplicate rows: fail closed).
  - Otherwise the re-sample's reading replaces the suspect's for the
    landing check (`one_rg`), the revert check and the next precondition
    (`watch_window`), and the suspect is counted in
    `RGMoveResult.dual_suspects`.
  - New helper `views_readable()`.
  - The FAIL reason is now "dual-active during the move window (a sample
    and its immediate re-sample)".
- **Choice (b) over (a)**: (a) was "score only if the two reads' time
  intervals overlap". It cannot tell a straddle from an overlap, because
  `views()` runs the two commands in parallel, so their intervals always
  overlap, and neither command says when inside its run it read the state.
  A handoff inside the overlap still gives one before-reading and one
  after-reading, so (a) would leave the false-FAIL in place. (b) tests the
  property itself. A real dual-active is a state that is still there one
  sample later. The straddle of a single handoff cannot recur, because both
  re-sample reads follow the handoff. (b) is also the conservative choice.
  It clears a suspect only on a readable, non-dual re-sample. It never uses
  the peer rows of a node's own view as evidence, because those lag by a
  heartbeat during every transfer and would reintroduce false FAILs.
  - **Limit**: a real overlap shorter than one re-sample (about one status
    read) is indistinguishable from a straddle with two independent reads
    and is not scored. The old rule caught such an overlap only when a
    sample happened to land on it, and it flagged clean handoffs in exactly
    the same way.
- **Fake (`rg_move_soak_test.py`)**:
  - `FakeCluster.status()` again reads each node at its own instant, like
    production (it renders at the call's instant and then spends 0.15 s).
  - `_status_lock` guards the shared fake state against the two worker
    threads, and `FakeClock` advances under an RLock. The single-instant
    snapshot from b331cf35fe is gone.
  - The `dual_after_land` and `dual_after_s` fixtures now model a dual-active
    STATE lasting `DUAL_HOLD_S` (1.0 s) instead of exactly one sample's two
    views. The cells' assertions are unchanged.
- **Cells**:
  - `DualActiveSampling19041`:
    - the cited cells run unmodified under 200 deterministic
      `InterleavingExecutor` schedules. The set now includes R18's third
      cell; the two #18559 cells run when present.
    - schedule coverage of every (order, overlap) pair.
    - a positive control that the fake CAN produce the handoff straddle.
  - `DualActiveScoring19041`, through the real `Soak.views()`,
    `IncusCluster.status()` and `one_rg()` with a scripted `_exec`:
    - a straddle in each direction is a suspect, not a dual-active, and
      the move PASSes;
    - overlapping reads of a real dual-active FAIL;
    - a sustained dual-active FAILs and never lands;
    - an unreadable or duplicate-row re-sample keeps the dual-active;
    - a cleared suspect does not hide a later real dual-active;
    - a suspect in the window is neither a dual-active nor a revert.

## Risk

- Harness scoring changes. A dual-active pair is now a FAIL only when the
  immediate re-sample repeats it or cannot read it. A real overlap shorter
  than one re-sample is no longer scored (see Limit above).
- Each suspect costs one extra pair of status reads.
- `result.json` gains `dual_suspects` per RG.
- The FAIL reason text changed. The docs and the H11 matrix row say so.
