# Filter #10081 — packed valued prefix-list reference

## Scope

`from source-prefix-list AAA;` is a packed, valued prefix-list reference. The
#10073 schema fix (`a1683db15`) already carries one prefix-list argument through
the shared packed lowering; this follow-up makes the exact case and its census
population fail on revert.

The census population is derived from `collectCompactSites`, not a copied schema
list. It contains eight firewall `from` prefix-list leaves: source and
destination under explicit `family any`, `inet`, and `inet6`, plus implicit
`firewall`/inet. Every row probes both packed and braced forms for both shapes:

- valued `source-prefix-list AAA;` / `destination-prefix-list AAA;` must be
  strict-clean, retain exactly one named `AAA` reference, and compile like the
  braced spelling;
- valueless `source-prefix-list;` / `destination-prefix-list;` must be
  strict-rejected naming the leaf, and the lenient path must record that leaf in
  `ValuelessFrom` without retaining a reference.

## RED → GREEN

The exact case and all eight valued census rows were run with the four static
firewall prefix-list declarations (source/destination under `inet` and
`inet6`) temporarily reverted from `args: 1, multi: true` to their full
pre-#10073 shape (`children: nil`). The `any` and implicit-inet rows use the
runtime copies of those subtrees. The packed valued spelling then failed at
strict commit with the `from AAA` unrepresentable/drop diagnostic, proving that
the valued row detects the schema regression. The exact #10081 pin and every
census valued row were RED; the named-reference assertions independently guard
the lost typed reference.

Restoring the #10073 declarations made the exact case and all eight dual-shape
rows GREEN. The exact pin reports one `PrefixListRef{Name: "AAA"}` and empty
`ValuelessFrom`/`UnknownFrom`; the census reports the same reference for packed
and braced valued forms and the expected strict/lenient valueless behavior.
