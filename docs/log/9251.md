## Decisions

- **Headings and caveat are no longer shared.** `compiler_tunnel_plaintext_advisory.go`
  shared them because they were "statements about zone id 0 … not about IPsec or
  WireGuard". #8274 hollowed that premise, and the shared heading was the
  #9251 defect. They are now required fields with **no default**, because a
  default is one protocol's account, silently inherited by the other. The rule
  is landed as guard cells, not only as prose.
- **The advisory still fires for every WireGuard tunnel.** The kernel-path write
  belongs to the steered port's tunnel. The only derivation of that port,
  `SteeredWireGuardListenPort`, reads the typed Config, and this advisory is an
  AST pre-walk that runs before the Config exists. An AST re-derivation is the
  divergence #9521 removed. Moving the advisory to the tail gates would change
  the #4406 warning-order invariant. With several ports, the multi-port warning
  names the steered tunnel from the dataplane's derivation, and the mechanism
  sentence scopes the residual to the steered port and says other ports drop.
- **IPsec output is byte-identical.** Its constants moved files, with the text
  unchanged. Proven by a base→head probe, and by the #5619 cells that pin the
  IPsec text as literals, left unchanged.

## Corrections found after the first commit

- **Zone-0 mechanism, found by mutation R2.** The Rust cell doc, the advisory
  function doc and the #5618 cell doc said `build_logical_ingress_packet`
  "resolves an unzoned tunnel to zone id 0". R2 made that stamped `ingress_zone`
  fall back to a configured zone, and it SURVIVED. Tracing it:
  `ingress_zone_override` has one producer, the fabric-ingress parser
  (`poll_stages.rs`). Every production policy caller resolves the from-zone
  through `zone_pair_ids_for_flow_with_override`: the override, else
  `ifindex_to_zone_id[ingress_ifindex]`, else 0. So zone 0 comes from the decap
  call site putting the tunnel's logical ifindex on the inner meta, plus the policy
  stage's own lookup. It does not come from the stamp. All three texts were
  corrected, and R2b, at the real fallback, is killed. The conclusion (denied)
  never changed; the component named for it did.
- **Two over-claims, found proofreading.** "The never-bound wgN TUN … is seen only
  by the kernel" contradicted the #8279 note beside it: the base row under the
  canonical unit-0 spelling is admitted. Both places now point at #8279. The gaps
  table also credited the shim with claiming an interface-mode SNAT listener on any
  port. The verified statement (#9521) is narrower: the worker matches every
  configured port, so a record that reaches it by another route is decapsulated.
- **#5619 `SeparatesZonedFromUnzoned`** still carried the refuted "zone-pair (0,0)
  matches a wildcard permit" mechanism in its doc comment and failure message,
  the same claim #6682 corrected elsewhere. The comment and message changed; the
  assertion did not.
- **VOID controls, redone.** A first patch to the landing filler used an unquoted
  heredoc. Bash executed the backticked names, the patch aborted without writing,
  and so the three filler "controls" that followed exercised the unchanged script.
  It was re-patched with a quoted heredoc, the patch was confirmed applied by
  count, and the controls were re-run: fill (rc 0), R2b survived → refused, R2b
  missing → refused.
