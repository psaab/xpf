# #18569 item 2 — aborted requester idle-lease promotion

- **Timestamp**: 2026-11-07
- **Worktree base**: `f28b0960c1ba43a03d0dad49b17a7402aa32d955` (`fix/18569-drive`).
- **Question**: Does helper pre-activation promote imported persistent-NAT idle leases before a transfer abort, and after abort does that requester differ from an old owner after ordinary failover?

## Cell and outcome

Added `aborted_requester_lease_promotion_matches_old_owner_18569` to
`userspace-dp/src/afxdp/coordinator/idle_lease_sync_8121_tests.rs`. It compares
a requester holding a peer-imported lease through helper-equivalent activation,
abort/deactivation, and a late import against the old owner's local lease after
ordinary demotion. Both cases use the full configured RG0/RG1/RG2 inventory,
with all watchdog timestamps zero:

- With RG0 inactive, the Go-style RG1 overlay leaves the full inventory short of
  all-active. The requester keeps the original record imported and does not
  re-export it; the old owner's local lease remains exportable. This is the
  inventory in the ordinary Go fixture.
- With RG0 already active, activating RG1 makes the full inventory all-active.
  The activation edge promotes the requester lease; abort/deactivation cannot
  undo that promotion. The requester's exported source identity, pool, timeout,
  and lease record then match the old owner's after normalizing the receiver's
  exactly 7,000 ns later expiry. A second lease imported after abort remains
  imported and non-exportable.

**Outcome: GREEN on the first execution of the finalized cell.** The result is
conditional on the complete helper inventory: the ordinary inactive-RG0 Go
fixture does not promote, while a genuinely all-active inventory promotes
before abort and leaves the requester in the same exported lease state as an
old owner after demotion. No production behavior changed; the added Rust state
reader is `cfg(test)` only. There is no fail-on-revert check for a production
fix because none was needed.

Added Go cell `TestPreActivationPublishesFullInventoryAndAbort18569` in
`pkg/dataplane/userspace/manager_ha_preactivate_18559_test.go`. It drives the
actual manager Begin/Publish/End overlay path and asserts the complete helper
payload (RG0, RG1, RG2 and watchdog status) both before and after abort, for
inactive-RG0 and all-active-RG0 cases. The map-free test fixture's helper
request is observed even though applying its response may return the known
`userspace_ctrl map not loaded` status error.

The Go wire status has no pre-activation provenance bit. The Rust cell therefore
proves generic all-active activation-edge behavior for the exact
helper-facing payload, not a provenance-specific Rust abort guard. The Go cell
separately proves what the real overlay publishes. No cross-process Rust/Go HA
transfer was run.
