# Issue #16631: OSPF virtual links after HA interface withdrawal

- **Timestamp**: 2026-10-25
- **Why**: HA filtering kept virtual-link-only areas after removing the standby's interfaces. The resulting virtual-link commands could make ospfd reject the managed configuration and fail every routing apply.
- **What**: `filterOSPF` prunes virtual links whose normalized transit area has no enabled interface after ownership filtering, without mutating the committed configuration. The renderer makes the final decision from actual `ip ospf area` emissions, after duplicate-area and authentication omissions. Candidate links are compacted in a render-local slice; activation tracking is allocated only when virtual-link candidates exist. A VL-only container can survive when its separate transit area remains active.
- **Coverage**: The renderer table covers missing/absent/disabled transit interfaces, duplicate-area suppression, keyless MD5 and simple authentication, normalized integer/dotted area identity, valid controls, and selective retention. HA tests cover RG demotion, full standby, promotion, source immutability, and managed rendering. The primary fixture uses distinct tagged/untagged RETH units and requires transit activation before the virtual link. Existing custom-transit fixtures now include a transit interface.
- **Files**: `pkg/config/compiler_validate_strict_ospf_interface_area_11400.go`, `pkg/daemon/daemon_frr_rg_shutdown_11415.go`, `pkg/daemon/ospf_virtual_link_ha_16631_test.go`, `pkg/frr/protocols_render_ospf.go`, `pkg/frr/virtual_link_no_interface_16631_test.go`, `pkg/frr/frr_test.go`, `pkg/frr/ospf_area_belt_9820_test.go`.
- **Validation scope**: Targeted OSPF/HA/operand/golden suites and guard mutation checks are the final gate. Earlier draft full-package runs had 5 FRR and 87 config/daemon failing test names also observed on a separate pristine origin/master checkout; those full suites are not claimed green. Live vlsb S1 reload and empty `--test` acceptance were not exercised: no clusters were used.
- **Risk**: Virtual links without an actually rendered transit-area interface are intentionally omitted, including tolerant configurations whose sole transit interface is rejected by another renderer check. Routing-instance and global renders use the same guard. No reload error is suppressed.
