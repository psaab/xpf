# #15111 — userspace-dp: persistent inbound sessions hold their NAT lease

- **Timestamp**: 2026-10-19
- **Mechanism**: `persistent_inbound_lookup` was read-only. An inbound
  persistent-NAT session installed with only a DNAT decision
  (`rewrite_dst`, no `rewrite_src`) took no reference on the persistent
  lease, and session teardown (`release_source_nat_allocation_with_mode`)
  returns early without `rewrite_src`. Once the last outbound flow
  completed, the lease entered the idle expiry index and was GC'd at
  `inactivity-timeout`; a second internal host could then be minted the
  same translated tuple toward a still-live inbound peer, and new inbound
  peers lost persistent-NAT reachability.
- **Fix**:
  - `PersistentLease` gains `inbound_flows`, counted separately from
    `active_flows` (outbound/synced joins). Every lease-liveness predicate
    (inbound lookup, reuse, GC reclaim, clear, rollback/release completion,
    synced-join filters, deterministic BIB joins, address-only contention,
    idle export/display) now treats `inbound_flows > 0` as live, and the
    expiry index only contains leases with both counts at zero.
  - `persistent_inbound_lookup` returns the admitting lease key;
    `acquire_persistent_inbound` / `release_persistent_inbound` /
    `rollback_persistent_inbound` take and drop holds, re-arming expiry
    on the last release. Acquire fails closed on a gone/revoked/expired
    lease.
  - Poll path: the lease key is captured at DNAT lookup and the hold is
    acquired only once the final NAT decision is composed (skipped when
    SNAT joined the lease via `active_flows`, NAT64, or NPTv6) and an
    anchoring session actually installs (ForwardCandidate, LocalMiss,
    FabricPuntSeed, MissingNeighborSeed). Every refusal/rollback exit
    (post-allocation selector fence, ICMP time-exceeded, admission
    refusal, install-permit refusal, install-partial, policy deny)
    rolls the hold back.
  - Teardown: `release_source_nat_allocation_with_mode` entry points
    (worker, synced-untracked, test untracked) and the rollback twin now
    also release the inbound hold derived from the session key +
    decision, so GC reap, delete-sync, purge, promote, revalidation,
    and dropped-delete repairs all free it. HA synced inbound sessions
    acquire per worker/coordinator in the synced reserve wrappers and
    release through the same teardown pair.
  - Revalidation (`policy_revalidation.rs`) stays read-only: it already
    holds a live session, so it must not double-count the hold.
- **RED/GREEN**: `persistent_inbound_hold_keeps_lease_past_expiry_15111`
  (`userspace-dp/src/nat/tests_pool.rs`) mints a persistent lease,
  releases the outbound flow, acquires the inbound hold, and asserts the
  lease still permits inbound past the outbound expiry, a second host
  cannot steal the tuple, release re-arms expiry, and GC then reclaims
  the lease and frees its port. A never-held control lease still expires.
  Pre-fix the hold APIs and `lease_key` do not exist and the post-expiry
  lookup is a Miss, so the mechanism cannot pass.
- **Validation**: `cargo check --bins --tests` clean (pinned 1.98.1);
  new regression green; full `nat::` suite 683 passed / 0 failed.
  Full `--bins` suite: 8584 passed / 53 failed — the identical 53-name
  failure set on two consecutive runs, in unrelated areas (WireGuard,
  GRE, coordinator reconcile, session-delta golden); the one NAT-adjacent
  name (`strict_mirror_refusal...11476`) fails deterministically with
  `export_idle_persistent_leases` returning one record per egress-scope
  bucket (2) where the test expects 1 — recorded here, not hidden.
- **Risk**: inbound-held leases are no longer exported as idle leases
  (they are live), matching session-carried liveness. If a session leaks
  without teardown, its lease now also leaks — the same bounded failure
  mode as a leaked `active_flows` hold today, and every teardown path
  funnels through the wired release entry points.
