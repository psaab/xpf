# #15117 — userspace-dp: unicast NS to a v6 NAT external never reaches proxy-NDP (A77-02)

## Defect

A unicast Neighbor Solicitation / Advertisement (NUD probe, ICMPv6
135/136 — and the whole on-link NDP set 133–137 — with hop limit 255)
addressed to a v6 static-NAT (or IP-only DNAT) external was
destination-translated before any local check:

- `userspace-dp/src/afxdp/poll_descriptor/frag_assoc.rs`:
  `flowless_destination_rewrite_supported` admitted ICMPv6 with no
  NDP-type exclusion, so `flowless_pre_routing_destination_nat`
  returned `Translated` for an NS to the external.
- `userspace-dp/src/afxdp/poll_descriptor/flowless_verdict.rs`:
  `flowless_base_resolution` applied that rewrite first and only then
  resolved the (internal) destination — the packet forwarded to the
  internal host.
- The flow-backed session-miss arm in `poll_descriptor/mod.rs` did the
  same: pre-routing static/DNAT/NPTv6/NAT64 ran unconditionally, so a
  flow-parseable NS was rewritten there too.
- The XDP shim (`userspace-xdp/src/lib.rs`) has had no unconditional
  NDP pass since #10640; unicast NDP to a firewall-local address passes
  via `is_local_destination`, but a NAT external is deliberately not
  in the shim local set (`pkg/dataplane/userspace/maps_sync.go` fills
  it with interface addresses only), so the shim redirected the NS to
  the worker, which translated it away.

Net effect: the kernel's proxy-NDP (`all.proxy_ndp`, #12611) never saw
the probe for the external it answers for. Upstream NUD probes failed
and recovery fell back to multicast re-resolution. No enforcement
loss; a liveness/neighbour-discovery defect.

## Fix

Exclude on-link NDP (ICMPv6 133–137 with hop limit 255 — the RFC 4861
on-link proof; a forwarded probe has hop < 255) from destination
translation on every cited leg and LocalDeliver it to the kernel:

- `frag_assoc.rs`: `FlowlessNatWireInfo` gains `ndp_type_hop255`,
  populated by `flowless_nat_wire_info` from the shared IPv6
  extension-chain walk (hop byte + first L4 byte); 
  `flowless_destination_rewrite_supported` now refuses the rewrite
  when it is set, and `is_ndp_hop255` exposes the classification.
- `flowless_verdict.rs`: `flowless_base_resolution` short-circuits
  NDP before pre-routing NAT — resolves the ORIGINAL destination via
  `flowless_local_resolution` (ingress-interface / interface-NAT,
  table-scoped) with HA gating and no rewrite; if not locally owned
  it returns the untranslated FIB resolution, never a rewrite.
- `frame/inspect.rs`: new `is_ndp_hop255_frame` (verified L3, shared
  walk, hop == 255, type 133–137) so the session-miss arm classifies
  from frame bytes.
- `poll_descriptor/mod.rs` (session-miss): `ndp_hop255` suppresses
  static DNAT, persistent DNAT, pool DNAT, NPTv6 and NAT64
  pre-routing translation; resolution then runs on the original
  destination, so a locally owned external LocalDelivers (host-inbound
  gates unchanged) and any other destination takes the normal
  FIB/policy path untranslated.
- `userspace-xdp/src/degraded_ndp.rs` + `lib.rs`: new
  `is_nat_external_ndp_control(type, hop_limit, is_interface_nat)`
  predicate; `ParsedPacket` carries the IPv6 hop limit; on session
  miss an on-link NDP packet to an interface-NAT destination passes
  to the kernel (`cpumap_or_pass`) before the worker can translate
  it. The degraded path already required a local destination
  (#10863) and is unchanged.

NOT changed: echo (128/129) and every non-NDP protocol still
translate to the same external; off-link NDP (hop != 255) still
translates; transit NDP to a non-local, non-NAT destination keeps
the ordinary worker FIB/policy adjudication; the #10640 removal of
the type-only shim NDP pass is preserved (the new shim arm is
destination-qualified on the interface-NAT map plus hop 255).

## Regression (`flowless_ndp_nat_tests_15117.rs`)

`ndp_to_static_nat_external_is_not_translated_15117` builds a v6
static-NAT external owned via interface-NAT and drives
`flowless_base_resolution` with real frames: types 133–137 at hop
255 give no rewrite and `LocalDelivery`. On `origin/master` the same
cells return the internal rewrite (the defect). Controls
`ndp_controls_still_translate_15117`: echo 128 at hop 255 and NS 135
at hop 64 still rewrite to the internal host.
`shim_nat_external_ndp_predicate_15117` executes the shim predicate
by source: 133–137 × hop 255 × interface-NAT only.

## RED evidence

With only `flowless_base_resolution`'s NDP bypass disabled (the
rewrite-supported gate still refusing), the new cell fails: the
packet takes the `Untranslatable` local arm, which cannot see the
FIB, so `flowless_base_resolution` returns `None` and the test's
resolve panics. On `origin/master` (no NDP classification at all)
the pre-routing call returns `Translated` with the internal
rewrite, which the `!Translated` assertion catches directly.
Controls (echo, off-link) stay green in both.

## Risk

Bounded to ICMPv6 133–137 with hop limit exactly 255 — the only
packets whose destination translation changes. A spoofed on-link
NDP packet to a NAT external now reaches the kernel proxy-NDP
instead of the internal host; the kernel validates NDP (checksum,
target, code) before answering, and host-inbound gates still apply
on the worker LocalDelivery legs. No session is minted for the
translated tuple that no longer exists.
