# #16598 — flat `set` split statements bypassed deny/allow-configuration

- **Timestamp**: 2026-10-25
- **Action**: A flat `set` line adjudicated as one joined path was executed
  by the store as several statements split at schema arity
  (`set system domain-search x login user evil class super-user` writes
  both `system domain-search x` and `system login user evil class
  super-user`), so a `deny-configuration "^system login"` / `"system login"`
  fence (and the allowlist mirror, and the #16080 credential surcharge for
  a split `root-authentication`) was bypassed on every surface sharing
  `AuthorizeConfigMutation` (CLI, gRPC, REST, event-engine) and via flat
  `load set`/`load merge`. Fixed by adjudicating the executed statements:
  - `pkg/config/authz_config_mutation_9154.go`: new
    `executedMutationPaths16598` applies the parsed set line (edit-path
    resolved) to a scratch tree via `SetPathQuotedGrouped` and renders it
    with `FormatSet`; `authorizeConfigMutationDepth9939` evaluates every
    executed statement in addition to the joined path (kept as a floor)
    and feeds them to the #16080 credential checks.
  - `pkg/config/authz_config_load_9892.go`: `LoadMutationLines` emits each
    executed `set` statement for a flat `set` line after the verbatim
    line, matching the hierarchical branch's `FormatSet` rendering.
  - `docs/system-login.md`: documented the split-statement adjudication
    beside the #14981 expanded adjudication.
- **File(s)**: `pkg/config/authz_config_mutation_9154.go`,
  `pkg/config/authz_config_load_9892.go`,
  `pkg/config/authz_config_split_16598_test.go`,
  `docs/system-login.md`, `docs/log/16598.md`
- **Validation**: New `TestSplitSetLine*16598` (6 tests): anchored and
  unanchored `system login` denies and `^system root-authentication`
  refuse the split line while `domain-search` alone and a split into two
  allowed statements still succeed; allowlist `^system domain-search`
  refuses the split line; edit-path form refused; flat `load set`/`merge`
  refused for both denies and the allowlist with `LoadMutationLines`
  rendering both executed statements; no-regex PermConfig class refused
  the split root-authentication via #16080. RED-verified: with the two
  source files reverted the new tests fail (split lines allowed, load
  renders only the joined line). Existing targeted suites stay green:
  `TestAuthorizeConfigMutation*`, `TestLoad*`, `TestStoreFlat*`,
  `TestCredential*`, `TestBareDestination*`. Full `pkg/config` run hits
  pre-existing failures also present without this patch
  (`TestBareDHCPServerRefMatchesOnlyUnitZero13141`,
  `TestDualASTDifferential` panic), verified by reverting.
- **Risk**: Lines that do not decompose (non-`set` verbs, single-statement
  sets, tokens with a quote character) keep the previous joined-path
  verdict exactly; the joined path is always adjudicated in addition, so
  no previously-denied line becomes allowed. Scratch-tree rendering runs
  only for `set` lines at the shared gate, not on the dataplane hot path.
