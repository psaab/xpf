# #15777 — compile hierarchical rib static routes and split fused next-hop tails

- **Issue**: #15777 — hierarchical `rib { <name> { static { ... } } }` blocks silently drop 100% of static routes on strict commit, and compact multi-clause static routes fuse into single child nodes that corrupt preferences and backup next-hops.
- **Branch**: `fix/15777-campaign`
- **Worktree**: `/var/worktrees/wt-15777`

## Why

The hierarchical spelling `routing-options { rib { inet.0 { static { route ... } } } }` parses as `rib` -> `inet.0` -> `static`, with the table name as an unnamed child of `rib`. `compileRoutingOptions` read only `ribNode.FindChild("static")` on the named rib node and `nodeVal(ribNode)` for its name, so it missed the nested block entirely: `StaticRoutes` stayed empty, `SchemaValidate` returned nil, and commit succeeded while installing no route. The same shape inside a routing instance lost its routes the same way, and an out-of-scope hierarchical table was not even recorded in `UnhandledRibs`, so no warning was emitted.

Separately, the compact spelling `route <dst> { next-hop <gw> preference <n> ...; }` packs route-level clauses onto the `next-hop` leaf. The child reader consumed every trailing token as a gateway address, so `preference` and its value became phantom next-hops (`preference`, `123`) and the route kept the default preference of 5. A qualified-next-hop clause fused the same way under a hierarchical rib was also out of the packed-QNH normalizer's scope.

## What

- `pkg/config/compiler_routing.go`: collect every `static` block under each `rib`, unwrapping the one extra hierarchical level (`rib { <name> { static ... } }`) as well as the flat named form. Honour every `rib`/`static` sibling, keep the existing scope check (`ribMatchesRoutingOptionsScope`) and family split, and record out-of-scope hierarchical tables in `UnhandledRibs` so `ValidateConfig` warns instead of dropping silently.
- `pkg/config/compiler_routing.go`: in the `next-hop` child reader, stop the gateway run at the first fused route-level keyword (`preference`, `next-table`, `discard`, `reject`, `metric`) and apply the fused tail to the route via `applyFusedRouteTail15777`, mirroring the fully-inline route-keys reader. `qualified-next-hop` is deliberately not handled here: it is split by the packed-QNH normalizer and a residual fused QNH stays rejected by `validateStaticRouteQNHTails12813`.
- `pkg/config/compact_static_route_qnh_12648.go`: extend `isStaticRouteNode12648` so a `static` node whose grandparent is a rib table name (great-grandparent `rib`) is in scope for the packed qualified-next-hop splitter, covering hierarchical ribs in global and routing-instance routing-options.
- `pkg/config/compiler_rib_hier_static_15777_test.go`: strict + lenient regressions for hierarchical v4/v6 ribs, flat-form agreement, routing-instance ribs, out-of-scope warning, fused preference/discard/next-table tails, the #5633 contradiction guard on a fused discard, and a hierarchical-rib packed qualified-next-hop at preference 250.

NOT changed: the schema grammar. `rib` keeps `args: 1`; the hierarchical form is a parse shape, not a new schema node, so `SchemaValidate` already accepted it and now the compiler agrees. No renderer or dataplane code changes — routes now reach the existing `StaticRoutes`/`Inet6StaticRoutes` lists that FRR and userspace already consume.

## Risk

Hierarchical ribs that previously compiled to nothing now install their routes; a config that relied (unknowingly) on the silent drop will start forwarding those statics after upgrade — that is the intended fix, and out-of-scope tables still warn via `UnhandledRibs` rather than installing. Fused-tail handling only triggers on tokens naming route-level keywords after at least one gateway token position in a `next-hop` leaf; a gateway literally named `preference`/`discard`/etc. was already unrepresentable in the fully-inline form (`isRouteInlineKeyword`) and remains so here.
