# Issue #16537: SYN-cookie challenge pool enumeration

- **Timestamp**: 2026-10-24
  - **Action**: replaced the per-challenged-SYN enumeration of every
    source-NAT pool address (and every NAT64 `pool_v4` address) with
    precomputed contiguous pool spans intersected against the bindless
    IPsec selector fence in O(spans x selector rows). A /16 pool is now
    one span, so the challenge cost is independent of pool size and no
    `Vec<NatDecision>` is built, merged, or cloned per SYN. The
    allocation-failure shape check stays O(1) at rule level
    (`challenge_source_nat_shape` -> `ChallengeFence::NoCandidate`).
  - **File(s)**: `userspace-dp/src/nat/source/mod.rs` (pool_ranges,
    `pool_address_ranges_v4/v6`, `challenge_source_nat_shape`; removed
    dead `candidate_source_nat_translations`),
    `userspace-dp/src/nat/mod.rs`, `userspace-dp/src/nat64/state.rs`
    (`Nat64Prefix::pool_ranges_v4`),
    `userspace-dp/src/afxdp/ipsec_selector_fence.rs`
    (`matches_with_pool_ranges`, `is_empty`, `AddressRange::overlaps`),
    `userspace-dp/src/afxdp/poll_descriptor/nat_exception.rs`
    (`syn_cookie_challenge_fence`), `userspace-dp/src/afxdp/poll_descriptor/mod.rs`
    (call site), plus tests in `ipsec_selector_fence.rs`,
    `userspace-dp/src/nat/tests_pool.rs`, and
    `userspace-dp/src/afxdp/tests_embedded_poll_filter.rs`.
