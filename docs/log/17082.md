# #17082 — retired eBPF `*dataplane.Manager` residue in the scheduler ladder

Why: `pkg/daemon/daemon_scheduler.go` resolved the policy-scheduler
dataplane surface through an optional-interface ladder that kept the
non-latch `SetPolicySchedulerActiveState` / `UpdatePolicyScheduleState`
arms. Both runtime types the daemon publishes
(`*dpuserspace.LegacyDataPlaneAdapter` from `dpuserspace.Boot()` and
`*dpuserspace.Manager`) implement the latch methods; only the retired
eBPF `*dataplane.Manager` (non-latch `UpdatePolicyScheduleState` in
`pkg/dataplane/maps_policy.go`) needed the fallback, and falling back to
it silently dropped `failClosed` (#10906) instead of failing the build.
The doc above `updatePolicyScheduleStateLocked` named that retired
backend as a live in-tree backend and did not mention
`userspace.Manager`. Verified live on current master (`a60e77bda3`)
before fixing: all five interfaces, both fallback arms, and the stale
doc were present exactly as filed.

What: Deleted the two non-latch interfaces
(`policySchedulerActiveStateSetter`, `policyScheduleStateUpdater`) and
their fallback arms. `seedPolicySchedulerActiveStateLocked` now resolves
only the latch setter; `updatePolicyScheduleStateWithLatchLocked` no
longer falls back to the non-latch updater (returns nil for an incapable
dataplane, unchanged); `updatePolicyScheduleStateLocked` — the
apply-transaction publication, which carries no latch — forwards
`failClosed=false` through the latch updater. The stale doc naming
`*dataplane.Manager` is gone with the arm it described
(`grep -n 'dataplane.Manager' pkg/daemon/daemon_scheduler.go` = 0).
New `policy_scheduler_published_type_17082.go` (beside the #9482 guard)
asserts `policyScheduleFailClosedUpdater`,
`policySchedulerActiveStateLatchSetter`, and
`policyScheduleHeartbeatUpdater` against both published types, so
removing `UpdatePolicyScheduleStateWithLatch` from
`LegacyDataPlaneAdapter` fails `go build ./pkg/daemon/`. Test fakes that
modelled the published backends
(`policySchedulerApplyTestDP`, `runtimeOnlyPolicyUpdaterTestDP`,
`userspacePolicySchedulerApplyTestDP`) now implement only the latch
methods and record `failClosed`. Scope note: the non-latch methods
themselves on `userspace.Manager` / `LegacyDataPlaneAdapter` /
`*dataplane.Manager`, and `legacy_dataplane_test.go`'s own seeder
interface, are outside this issue (R4-Q28-01/#17297 owns the retired
Manager's apply path) and are untouched.

Validation: `go vet ./pkg/daemon/` clean; `gofmt` clean. Named hermetic
cells (`go test -count=1 -run '<names>' ./pkg/daemon/`, exact names in
the PR): `TestPublishedUserspaceDataplaneSatisfiesSchedulerLatch17082`
(dynamic `Boot()` type, #9482 shape),
`TestSchedulerLatchCarriesFailClosed17082` (failClosed=true reaches the
latch updater; the non-latch entry forwards false through the same
latch method), `TestSchedulerSeedUsesLatchSetter17082`,
`TestSchedulerLatchIncapableDataplaneStillNoOps17082` (control: an
incapable dataplane still no-ops), plus the pre-existing scheduler
cells (`TestUpdatePolicyScheduleStateLockedPropagatesError`,
`TestApplyConfigPublishesScheduleStateToNonUserspaceDataplane`,
`TestInitialPolicySchedulerPublishFailureQueuesRetry`,
`TestPolicySchedulerUpdateUsesRuntimeUpdaterWithoutLegacyDataplane`,
`TestApplyConfigSeedsUserspacePolicySchedulerStateBeforeCompile`,
`TestPolicySchedulerInitialPublishSkipsUserspaceLegacyMapUpdate`,
`TestApplyConfigUsesRuntimeConfigSinkWithoutLegacyDataplane`,
`TestReconcilePolicySchedulerCarriesFailedRecoveryState`). RED proof:
harness-stash the production fix (restore master's
`daemon_scheduler.go`, delete the guard file, keep tests) — the
latch-only fakes then reach no updater, so the latch-call assertions
fail; restoring the fix passes. No cluster/VM smoke (NOT-EXAMINED:
live scheduler republish on a running node — compile-time guard plus
daemon-level cells are the hermetic binding).

Risk: A hypothetical out-of-tree `RuntimeDataPlane` implementing only
the non-latch methods would now silently no-op instead of publishing
without the latch; that is the intended fail direction, both in-tree
published types satisfy the latch surface, and the compile-time
assertions keep it that way.
