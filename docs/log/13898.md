# #13898 — preserve IPv6 solicitation token across same-MAC refresh

## Defect

The IPv6 `RTM_NEWNEIGH` path consumed the one-shot solicitation token before
inserting the neighbor entry. A same-MAC refresh is a no-op (`Some(false)`),
so this unnecessarily burned the authorization needed by a subsequent
failover MAC change. The failover was then refused as unsolicited until a new
probe was recorded.

## Change and validation

The IPv6 kernel-neighbor path now peeks at solicitation evidence before the
insert and consumes it only when the insert actually changes an existing MAC
(`Some(true)`), matching the IPv4 path. Added a fail-on-revert IPv6 regression
that records a probe, applies a same-MAC `NUD_DELAY` refresh, then confirms a
different-MAC `NUD_REACHABLE` failover is accepted without an unsolicited-NA
refusal.

On pristine master, the regression failed at the failover assertion: the
result was `None` rather than `Upserted`, and the path counted an unsolicited
NA refusal. Command:

```text
CARGO_TARGET_DIR=/var/worktrees/.cache/cargo-13898 GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/var/worktrees/.cache/go-tmp cargo test -p xpf-userspace-dp same_mac_nud_delay_refresh_preserves_solicitation_token_13898
```

Post-fix, the complete `afxdp::neighbor::` test filter passed: 35 passed,
including the new IPv6 regression and existing IPv4/IPv6 solicitation,
unsolicited-update, and one-shot tests; 8,262 tests were filtered out.
Command:
