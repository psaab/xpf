# Issue #10409: WireGuard peer-to-XPF local delivery

## Disposition

Fixed the WG worker-decap local-delivery gap. A peer packet addressed to the
WireGuard interface resolves as `LocalDelivery` with a tunnel endpoint. The
slow-path chokepoint therefore requires a `local_tunnel_deliveries` sink; that
map previously contained GRE local-origin threads only. WG worker-decapped
plaintext reached the local-delivery arm but had no WG sink and was dropped
instead of being written to the persistent `wgN` TUN.

The fix gives each live WG control thread a bounded delivery queue and eventfd,
publishes that sender alongside GRE senders, drains it into the attached WG TUN,
and removes it before stale/finished thread join. Attachment fencing discards
queued packets when the thread no longer owns the published WG attachment.

## Scoped files

The change is limited to the WG control loop, WG lifecycle publication,
shared local-delivery wake/drain support, and WG tests. No `session/`,
`forwarding/`, `cos/`, `worker_queue`, `slow_path/`, `poll_descriptor/`, or
Go source was changed.

Detour (not 10409 coverage): `wg/decap_tests.rs` repairs two stale
all-zero-MAC fixtures (`outer_frame` + `drive_spoofed_plain_10038`) that the
#10314 MAC guard now recycles pre-L3. The 10409 cells do not use
`outer_frame`; without the repair, 19 decap_tests fail on master and this
PR fixes all 19 (18 + the spoof cell).
