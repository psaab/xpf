# #18531 — split-RG failback revoked promoted SNAT flows on the LAN node

- **Timestamp**: 2026-10-29
  - **Action**: Root-caused the established-stream loss at the RG1 failback
    of `make test-failover` (loss: 3 streams, tcp: 8). The trigger is the
    first LAN packet on fw1 after `update_ha_state` publishes the inactive
    RG1. The workers have not yet drained `DemoteOwnerRGS`, so that packet
    hits the serving worker's crash-takeover `SharedPromote` row, which is
    still locally authored. The hit re-resolves to `FabricRedirect` and
    persists it (#12265). The row's SNAT judgment is Stale, because the
    #16109 neighbor generation advanced while the flow cache served the row.
    The #16215 `FabricRedirect` decline was gated on `is_peer_synced()`, so
    the validator judged the fabric pseudo-egress, missed in
    `forwarding.egress`, and revoked the pair as `StaleSourceNat`:
    `delete_terminal_filtered_session` ran with unconditional sibling
    `DeleteSynced` and emitted a Close with close class 0. That Close passed
    the daemon's fabric-redirect sync branch, and fw0 deleted its live copy.
    The fix keys the decline on the stored resolution alone.
  - **Evidence** (`/var/worktrees/.cache/fwd-goal/failback-diag/`; fw0's
    clock is ~239 ms ahead of fw1's after the resync):
    - fw1 closes 36552/36550 (worker 1) and 36572/36574 (worker 0) within
      4 ms of `RG1 state changed ... demoted=[1]` at 20:51:51.538.
    - The sibling-only unconditional `DELETE-SYNCED` (forward and reverse),
      followed by the scoped `DeleteSyncedConditional` with the closed id,
      is the `delete_terminal_half` signature.
    - `SESSION_CLOSE reason="idle Timeout" policy_id=0` for those four
      flows. Node1 policy denies stayed 0.
    - The survivors (36542/60/62/66) were already retagged
      `SyncImport`/`FabricRedirect` by the demote.
    - fw0 deleted 36572/36574 on all six workers at .954/.976 (unscoped
      coordinator delete of the synced Close).
    - 36552: fw0 held only the forward-wire alias
      `172.16.80.8:36552->172.16.80.200:5211` (plus the reverse). Its
      pre-NAT `LOCAL-ABSENT` misses exist because fw1 had already deleted
      its row and carried the flow untranslated.

- **Timestamp**: 2026-10-29 (third commit, #18535 item 1)
  - **Action**: Found and fixed the removal of a live flow's
    forward-wire alias on the node taking the WAN RG, in the window
    between the peer's demotion and this node's activation.
    - **Purge (both families):** the peer's fabric-redirected translated
      packet hits the alias row. `should_keep_synced_hit_transient` holds
      it transient: the row is peer-synced, its owner RG is not active
      here, and the key is translated. `resolve.rs` then queued a
      `DeferredSyncedPurge` for every keep-transient hit, which runs
      `purge_translated_synced_hit_with_context` (`session_glue/promote.rs`),
      the #6599 rule. It emits no Close. With an alias-only copy, the first
      packet after activation missed and the flow died.
    - **Revocation (v6):** a keep-transient hit persists nothing, so the
      SNAT check judged the stored import-time line. For v6 that line is
      ForwardCandidate on egress 13 (reth0.50). The live HAInactive was not
      substituted, so the check revoked against the reth0.80 translation.
      The stored v4 line (fallback, egress 14) validates.
    - Fix: no purge for a fabric-link arrival; the direct-arrival #6599
      purge is kept. On a fabric-link arrival a live HAInactive with a
      real egress now stands in like a forward candidate, so the #18531
      decline holds the session.
    - First version substituted a live HAInactive on every arrival. The
      full suite showed it red
      `ha_imported_transient_dynamic_snat_keeps_canonical_worker_entry_12187`:
      a direct translated hit on a non-owner must still revoke after a
      same-tuple static SNAT is configured. That is outside this fix, so
      the stand-in is now gated on `fabric_link_ingress`, the same
      predicate as the purge gate. It is passed into
      `source_nat_revocation_on_session_hit_with_ingress` as a new last
      argument; existing direct test callers pass `false`.
    - `adopted_forward_candidate_bypasses_ha_inactive_terminal_16217`
      asserted `deferred_synced_purge.is_some()` for an adopted fabric
      arrival. Its own comment names the disposition as the contract, so
      the purge assertion was incidental. It now asserts `is_none()`: the
      adopted alias is held, which is this fix's rule.
  - **Evidence**: proven in the harness on the captured split snapshots,
    using a temporary eprintln build that was not committed. The alias-only
    shape comes from the integ3 trace (36552 on fw0,
    `failback-diag/fw0-journal-boot.txt:1631`). The link to the 5 integ4
