## Measured at origin/master 580d959e0 (posted on the issue)

Strict channel:
- Refused: `protocols bgp export ospf6|ospf3|ripng`, `protocols ospf export ospf6|ospf3`. The error says "neither a known redistribution protocol". For `ospf6` and `ripng` that is the wrong reason: the strict token set lacked them, although `FRRRoutingProtocolKeyword` admits both.
- Accepted: `protocols ospf3 export ospf`, which renders nothing.
- Accepted: `protocols bgp export static`, which renders under `router bgp` only, so IPv6 static routes never enter BGP.

## Decision (posted on the issue)

- **BGP:** render each family where FRR's grammar lives. IPv4 goes under `router bgp`; IPv6 goes under `address-family ipv6 unicast`, a block now opened whenever an IPv6 redistribute line exists.
- **Single-family routers:** refuse at strict commit, warn on the tolerant path; the #9510 render drop stays.
- **One family table** in `pkg/config`, which both the gate and the renderer read.

## Implementation notes

- In the BGP loop a bare token calls `resolveRedistribute(…, "bgp")` when the source has an IPv4 family, or when it is not a protocol keyword (so the unknown-token warning is unchanged). It calls `resolveBGPIPv6Redistribute` when the source has an IPv6 family. `export bgp` takes only the first call, so the self drop warns once.
- `redistributeEntries(export, po, self, …)` is now `redistributeEntriesAt(export, po, self, self, …)`. `self` still decides the self drop; `node` selects the grammar a source must fit. The #9510 census (exactly two `redistributeEntries` callers, a literal self at every call) is unchanged. `TestRedistEntriesAtNodesAreCovered_9667` extends it to the node-aware entry point: one pass-through, every other caller a literal node with a `frrRedistNodeAFI` row.
- The strict gate still requires the exact lower-case token, as the old set did. The renderer writes the token through, so a case-insensitive match would admit a line FRR rejects.
- `exportUseSiteFamilies`: ospf IPv4, ospf3 IPv6, rip IPv4, isis both, bgp both.
