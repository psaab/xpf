# Issue #13175 — Preserve ancestry across simultaneous zone renames

## Why

`expandPolicyRenameAncestryWithFeeds` expanded each zone rename independently.
When both ends of a zone-pair policy were renamed in one commit, it emitted
intermediate destination identities that did not exist in the new config and
rejected continuity for the whole rename batch. Scoped global policies were
also expanded once per renamed zone, producing duplicate stable rule IDs.
Global policy renames bypassed the scope comparison after zone scope was
removed from resolved-identity fingerprints, permitting sessions from a
removed zone to be rebound without re-evaluation.

## What

- Apply the complete `zoneRenames` mapping when expanding affected zone-pair
  identities and compare each global policy's directional `FromZones` and
  `ToZones` scope after applying that map.
- Expand scoped global ancestry once per policy, preserving zone remaps in the
  binding, and validate scope explicitly for global-policy rename descriptors.
- Add regression cases for two-zone pair rename composition, global scoped
  ancestry, rejected narrowed scope on a global policy rename, and accepted
  scope that is exactly mapped by a simultaneous zone rename.
- `daemon_policy_invalidate_capture.go` remains unchanged: invalid ancestry is
  already cleared there and takes the existing fail-closed teardown path.

## Validation

- RED on pristine `origin/master` (`ab0498643`): all three new regression
  tests fail, covering composed multi-zone identities, narrowed global scope,
  and mapped global scope.
- GREEN focused run:
  `go test ./pkg/daemon/ -run 'TestExpand(PolicyRenameAncestryMultiZone|GlobalPolicyRename|ZoneRenameScopedGlobal)' -count=1`
  passed.
- `go vet ./pkg/daemon/` passed.
- Full `go test ./pkg/daemon/ -count=1` was attempted on the final source.
  It failed in ten other tests: four Unix-socket tests report `bind: invalid
  argument` under the configured temporary directory, and six host-inbound
  fence/input-barrier cases fail their assertions. None is in the changed
  rename implementation; the new regressions passed in that package run.

## Risk

A global-scope mismatch now rejects rename continuity, so the existing
invalidation path tears down affected sessions instead of retaining a session
whose directional zone scope changed. This is deliberate fail-closed behavior.
