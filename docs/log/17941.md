# #17941 — Reject opposite-family SNAT pools for wildcard-only address names

- **Timestamp**: 2026-10-25
  - **Why**: A source-address name whose entire closure is a family wildcard (`0.0.0.0/0`, `::/0`, or bare `0.0.0.0`/`::`) matches only that family, just like the equivalent authored literal rejected by #17847. Treating such closures as not narrow let an opposite-family pool commit, and prevented the lenient compiler from warning about the runtime `WrongAddressFamily` refusal. The #17408 scaffold is genuinely dual-family `[v4 v6]` and remains outside this single-family gate.
  - **What**: Every decidable single-family value in an address-book name closure now counts as narrow. Updated the gate, classifier, and closure comments to record the #17941 ruling superseding the name-closure exemption. Removed the now-unused `natPrefixIsFamilyWildcard` helper. Added strict-admit/reject coverage for v4/v6 wildcard names, bare v4 wildcard, wildcard-only address-set and dual-family closures, and lenient `WrongAddressFamily` warning.
  - **File(s)**: `pkg/config/compiler_validate_strict_nat.go`, `pkg/config/compiler_nat_snat_pool_family_16600_test.go`, `docs/log/17941.md`.
  - **Validation**: RED confirmed before the fix: strict compile accepted v4/v6 wildcard-only names, a wildcard-only address-set, and bare `0.0.0.0` against opposite-family pools; lenient compile emitted no `WrongAddressFamily` warning. Focused `GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/var/worktrees/.cache/go-tmp go test ./pkg/config/ -run 'SourceNATPoolFamily|SourceNATRuleSingleFamily' -count=1 -v` passes after the fix. `GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/var/worktrees/.cache/go-tmp go test ./pkg/config/ -run 'NAT' -count=1` has one unrelated known red, `TestSourceNATPoolPortRangeControls16670`, failing its `SchemaValidate(range+random)` case for `1024 to 2048 random-allocation`. `docs/log/16723.md` records this regression cell red at base and head for #17913; `docs/log/16875.md` also records it base-attributed on clean master. `go vet ./pkg/config/` and repository-wide `go vet ./...` pass.
  - **Risk**: The strict family gate now catches a proven single-family mismatch through wildcard-only names as it already does for equivalent literals. Same-family pools still pass; genuinely dual-family closures still classify as dual and remain admitted. No dataplane behavior changes.
