# #16615: Persistent NAT inbound release uses recorded lease scope

- **Timestamp**: 2026-10-25
  - **Action**: The #15111 inbound-hold release re-derived
    `PersistentSourceKey{routing_scope: key.routing_domain}` from the
    inbound session's arrival domain. `routing_domain` is an
    ingress-interface property, not the lease's minting scope, so a
    cross-domain persistent binding (lease scope 7, arrival 0) was
    acquired on scope 7 but released on scope 0: the allocator
    `get_mut` missed silently, `inbound_flows` never drained, GC and
    `clear persistent-nat-table` left an immortal shell, and an
    overlapping scope-0 tenant's hold could be decremented instead.
    Now the exact `(PersistentSourceKey, allocator shared identity)`
    acquired is recorded: on `SessionEntry`/`ExpiredSession` for local
    poll installs (LocalMiss, transit, FabricPuntSeed,
    MissingNeighborSeed via `set_persistent_lease_hold`), on
    `SyncedSessionEntry`/`SessionInstall` for HA imports, and returned
    by the synced reserve variants. Teardown consumes it exactly once
    via `release_*_with_hold` / `release_recorded_persistent_inbound`
    (GC reap, delete-synced, promote purge, revalidation, install-table
    purge, delete-drop sweep, coordinator untracked releases, upsert
    replacement). Only entries with no recorded hold (legacy/pre-fix)
    fall back to the old re-derivation. HA synced acquire no longer
    derives scope from arrival domain: it discovers the lease by its
    translated tuple (`persistent_lease_key_for_translated`) and records
    that lease's own key.
  - **File(s)**: `userspace-dp/src/session/{ctx,entry,expire,install,mod}.rs`,
    `userspace-dp/src/nat/{mod,allocator/mod,source/release,source/synced}.rs`,
    `userspace-dp/src/afxdp/poll_descriptor/mod.rs`,
    `userspace-dp/src/afxdp/worker/{synced_entry,loop_body/gc_teardown}.rs`,
    `userspace-dp/src/afxdp/ha/session_import.rs`,
    `userspace-dp/src/afxdp/session_glue/{commands/upsert_synced,commands/delete_synced,promote,revalidation,install_table_purge,delete_drop_sweep,resolve}.rs`,
    plus `persistent_lease_hold: None` field plumbing in shared-entry
    literals and test fixtures.
  - **Validation**: `cargo check --tests` clean (warnings pre-existing).
    `cargo test -- persistent_inbound`: 8 passed including new
    `persistent_inbound_recorded_hold_releases_cross_domain_lease_16615`
    (scope-7 lease released via recorded hold drops to 0 and is
    GC-reclaimed while overlapping scope-0 tenant stays at 1, then
    domain-0 recorded release unchanged) and the domain-0 control
    `persistent_inbound_hold_keeps_lease_past_expiry_15111`.
  - **Residual**: Worker-command drop repair and pressure-shed paths
    have no live `SessionTable` entry to take the recorded hold from;
    they keep the legacy fallback (bounded leak, never cross-tenant
    over-release beyond the pre-existing behaviour). HA wire carries
    no lease key: standby discovers it by translated tuple on its own
    allocator, which is the lease's local identity.
