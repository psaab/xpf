#12200 — Traffic-carrying, version-asserting rolling-upgrade gate

## Changes

- Added `make test-rolling-upgrade`, an `ha-smoke` cluster gate whose `.deb`
  prerequisite builds before the shared-cluster lock is acquired. The Makefile
  wraps both the measurement and ledger attestation in `with-cluster.sh`; the
  script's `cluster-cell.sh` lock entry is re-entrant. It runs one
  eight-stream iperf3 session at 100-ms intervals across the real
  secondary-first `cluster-setup.sh deploy all` path.
- Added optional timestamped `cut_start`/`cut_end` markers around each deb
  `xpfd upgrade --rolling` call. With `XPF_ROLLING_UPGRADE_TRACE` unset the
  deploy path is unchanged.
- The gate compares the candidate .deb's staged xpfd SHA with both live
  pre-cut `/proc/<MainPID>/exe` identities before running, samples both live
  images through the cuts, and requires both nodes to finish on the candidate
  SHA plus a sampled mixed-version interval between cuts.
- Added `scripts/rolling_upgrade_oracle.py`: one interval/per-stream verdict
  per cut, a version/mixed-version verdict, 100-ms evidence-width/gap checks,
  no-op-build rejection, and fail-closed evidence parsing. The hermetic
  #10261-shaped red replay uses the preserved historical per-stream starvation
  log from `docs/log/10023/raw/historical/iperf.log` (the #10261 report itself
  has no raw evidence fixture).
- Registered the gate in the `ha-smoke` adapter census, harness ledger coverage
  declaration, and ledger adapter documentation. The coverage row remains
  declared unreached until a live run records the first real cluster row; no
  synthetic measurement was added.
