## Mechanism (verified at base 088d3c99ab, re-based on 7a312fcdd7)

- A lenient load keeps two `term t` instances (strict commit rejects them, #15192). Rust compiles each to its own `Arc<FilterTermCounter>` and publishes rows `{t:30},{t:70}`.
- `BuildFirewallFilterTermCounterIndex` keyed by (family, filter, term name) and summed duplicates on purpose (#15192), so the index held `{t:100}`; both `pkg/cli/cli_show_security_filters.go` and `pkg/grpcapi/server_show_firewall.go` looked that key up per instance and each printed 100 — misattributing a discard term's hits to an accept term and doubling the displayed total.
- `userspace-dp/src/filter/compiler.rs` `parse_term` matched the previous term with `.find(|term| term.name == snap.name)` (first match), so instance 2 was compared with instance 1: shape differs (discard vs accept) → fresh zero counter on every snapshot refresh, even an unchanged one; same shape → instance 2 would clone instance 1's Arc.

## Change

- Wire: `FirewallFilterTermCounterStatus` gains `term_ordinal` (Rust `term_ordinal`, Go `TermOrdinal`, `omitempty`/`serde(default)` additive). Rust publishes `term.id` (the compiled position within the filter). An older helper omits it: every row decodes as ordinal 0.
- Go index: `FirewallFilterTermCounterKey` is now {Family, FilterName, TermOrdinal}. Duplicated ordinal keys still sum, so a legacy helper's rows collapse to the summed ordinal-0 entry exactly as before. `AggregateFirewallFilterTermCountersByName` (plus `...ForConfig` for the #16464 clone fold) preserves the #15192 one-series-per-name Prometheus behaviour.
- Renderers: CLI (both raw views) and gRPC (both raw views) count non-nil term instances in order and look up that ordinal. Nil slots own no runtime counter and do not shift ordinals (the Go snapshot builder skips them; the config ordinal coincides in the no-nil case).
- Rust: `parse_term` finds the previous term by `term.id == id && term.name == snap.name`, so each instance carries its own Arc when the shape matches, a renamed term at the same position still starts fresh, and identical same-named instances never alias.
- Fixtures whose counted term is not at ordinal 0 (`firewall_uncounted_16454` CLI/gRPC) and the #16464 clone index test now set `TermOrdinal` explicitly.

NOT changed: the #15192 strict rejection, the lenient keep-both compile, Prometheus labels, or the map/eBPF stride logic (per-instance already).

- Neighbours: CLI/gRPC/api/userspace firewall, clone (#16464) and uncounted (#16454) targeted runs pass. `TestFirewallValidationHarnessDocGuard` in pkg/api fails identically on pristine master (pre-existing, env path).

## Risk

- Mixed-version window: a new Go control plane against an old helper sees only ordinal-0 rows (the summed legacy view for instance 1, no row for instance 2+) — never a fabricated per-instance split, and it self-heals when the helper upgrades. A new helper against old Go is ignored on decode (Go `encoding/json` ignores unknown fields; the old summed view returns).
- Prometheus output is unchanged (name-summed), so dashboards/alerts are unaffected.
