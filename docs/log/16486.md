# #16486 — Other-protocol sessions idled out after 30 s instead of the Junos 1800 s "Other" default

- **Timestamp**: 2026-10-24
- **Context**: `OTHER_SESSION_TIMEOUT_NS` in
  `userspace-dp/src/session/mod.rs` was 30 s, so every session of an IP
  protocol other than TCP/UDP/ICMP (GRE 47, ESP 50, AH 51, SCTP 132,
  6in4 41, OSPF 89) with no application `inactivity-timeout` was reaped
  after 30 s idle. The Junos protocol-based default timeout table
  (Security 10.2, Table 13, minutes: TCP 30, UDP 1, ICMP 1, OSPF 1,
  Other 30) gives "Other" 1800 s and OSPF 60 s — the last fallback
  after a configured application timeout and any predefined-application
  default, and the same table xpf already honours for TCP (1800 s,
  #15127), UDP and ICMP (60 s). On the usual one-way trust->untrust
  posture the first remote-originated packet after a >30 s lull matched
  no session and was policy-denied (e.g. inbound ESP on an idle
  non-NAT-T IPsec passthrough tunnel, whose DPD runs over IKE/UDP and
  does not refresh the ESP session).
- **Fix**: `OTHER_SESSION_TIMEOUT_NS` is now 1800 s, with a dedicated
  `PROTO_OSPF` arm at 60 s (`OSPF_SESSION_TIMEOUT_NS`) in the single
  `session_timeout_ns` resolver, so install, HA import, hit refresh
  and promotion all pick up the new defaults with no caller changes.
  Per-application `inactivity-timeout` still wins once a genuine
  reverse packet promotes a non-TCP session (#10889); unpromoted
  sessions stay on the global protocol window. `timeout_secs_for`
  (the `show security flow session` Timeout column) now reports 1800
  for GRE/ESP/SCTP and 60 for OSPF. Session README Timeouts table
  gains OSPF and "Other IP protocols" rows; the architecture doc's
  stale 30 s "Other" row is corrected (its ICMP 15 s stale value in
  the same table was also aligned to the shipped 60 s).
- **File(s)**: `userspace-dp/src/session/mod.rs`,
  `userspace-dp/src/session/other_proto_timeout_16486_tests.rs` (new),
  `userspace-dp/src/session/tests.rs` (comment),
  `userspace-dp/src/session/README.md`,
  `docs/userspace-dataplane-architecture.md`, `docs/log/16486.md`,
  `debian/changelog`
- **Validation**: new `other_proto_timeout_16486_tests.rs` cells:
  resolver pins 1800 s for GRE/ESP/AH/SCTP/6in4/unknown in both
  promotion states, 60 s for OSPF, and the promoted app-override twin
  (90 s wins, unpromoted ignores it); a table-level GRE session
  reports 1800, still matches and survives GC after 600 s idle, and
  reaps after 1800 s; an OSPF control reports 60 and reaps at 61 s.
  Existing `session_timeout_ns_honors_app_override` stays green
  (it compares against the constant). See PR for exact counts.
- **Residual**: 60x longer retention of idle other-protocol sessions
  is quota-bounded by `max_sessions`; no new operator leaf is added
  (Junos has no global "other" session-timeout leaf — the per-app
  `inactivity-timeout` remains the override). End-to-end one-way
  policy blackhole was inferred in research, not lab-run; the fix is
  verified at the session-table level.
