# docs/log/13162.md — #13162 (policy address tokens in legacy compiler)

- **Timestamp**: 2026-10-14
- **Action**: Lower family wildcards and inline IP/CIDR tokens into the legacy dataplane address maps; reject feed-bound names when this compiler lacks their runtime prefixes.
- **File(s)**: `pkg/dataplane/compiler.go`, `pkg/dataplane/compiler_policy_addr_tokens_13162_test.go`

## Address-token lowering

`resolveAddrList` previously removed only the exact token `any`, then resolved every other term exclusively through `CompileResult.AddrIDs`, which `compileAddressBook` populates from static address-book entries. Consequently, valid `any-ipv4`/`any-ipv6` (and aliases), inline IP/CIDR literals, and dynamic-address binding names failed as missing static names. The four policy source/destination call sites (zone-pair and global policies) now share the config-aware resolver. It preserves wildcard-keyword precedence over names, and ordinary address-book-name precedence over CIDR/IP parsing. Family wildcards use family-scoped implicit sets with a `/0` fallback and include existing address-book IDs plus inline literals, including more-specific LPM matches; plain IP literals become host prefixes.

Dynamic-address bindings carry feed names, not their resolved prefixes. `CompileConfig` has no feed-prefix input; pretending a binding is match-any or a match-none empty set would widen permitted traffic or make deny rules ineffective. This path therefore returns a clear compile error for a binding without a static address-book entry rather than silently widening the policy. Runtime feed integration is not changed by this fix.
