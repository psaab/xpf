# docs/log/12709.md — #12709 (verify MAC before deleting managed links)

- **Timestamp**: 2026-10-13
- **Action**: Verify a MAC-form managed `.link` against the renaming NIC before removal; preserve foreign and unverifiable claims.
- **Files**: `pkg/daemon/linksetup.go`, `pkg/daemon/bootstrap.go`, `pkg/daemon/linksetup_originalname_12156_test.go`, `pkg/daemon/linksetup_macowner_12709_test.go`, `docs/log/12709.md`.

## Defect

The unknown-original target-change cleanup removed `10-xpf-<old>.link` and `10-xpf-<target>.link` by filename alone. A filename is not an ownership invariant: the `[Match] MACAddress=` in a MAC-form link can identify another NIC. Removing such a target link can discard that NIC's only correct boot-time claim. This is the deletion-side twin of #12550's retained-link check. The positional temp-failure path and bootstrap lifeline used the same cleanup rule, so each needed equivalent protection.

## Change

- Snapshot the unknown-original NIC's MAC before collision-breaking renames can change its kernel name. For each file being neutralized, parse the `MACAddress=` and compare parsed MAC bytes with that snapshot (same comparison semantics as #12550).
- Remove a MAC-form claim only on verified match. Preserve a verified mismatch because it belongs to another NIC; preserve and report malformed MAC or unreadable identity rather than deleting an unverified claim. Continue deleting managed links without a MAC, and keep missing files a no-op.
- Apply the check to positional O/T cleanup, including pre-temp O.link cleanup and temp-rename failure, and bootstrap lifeline O/T cleanup. Existing same-name retained-link behavior from #12550 remains separate.
- Add regression coverage for foreign O/T claims, a verified matching claim, case/hyphen MAC spelling, unreadable identity, malformed MAC, missing/no-MAC files, temp-fail parity, and bootstrap parity. Update the existing bootstrap MAJOR-1 test to assert that a foreign MAC claim survives.

## Risk

Foreign claims can remain on disk after the unknown-original rename because their original NIC may not be safely rewritten in this path. This is intentional: preserving another NIC's MAC-matched persistence avoids deleting its correct boot claim. Unreadable/malformed identity is surfaced through the existing positional error channel or bootstrap error log and is fail-closed on deletion.
