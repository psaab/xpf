# #17770 — Report observed unmanaged SSH state

- **Timestamp**: 2026-10-29
  - **Action**: The CLI and gRPC renderers no longer infer that sshd is running when `system services ssh` is absent. The shared `pkg/sysservices` probe observes `sshd.service` and, when it is inactive, `ssh.socket`: an active service is `running`; a loaded inactive service with a loaded active/listening socket is `running (socket-activated)`; known inactive service/socket states are `stopped`; and incomplete or unexpected observations are `unknown`. The shared formatter keeps both rows byte-consistent and distinguishes the socket-listening explanation from an active sshd process. The read-only probe uses a two-second deadline and 500ms `WaitDelay`, holds a slot from process-wide `diagcmd.DefaultLimiter`, and propagates the gRPC request context (local CLI dispatch has no command context). Tests cover socket activation, concurrent process budget, cancellation, classification, formatting, inherited-pipe timeout, and missing `systemctl`; the fabric-secret ShowText sweep fixture now stubs sshd state as well. xpf does not manage sshd enablement.
