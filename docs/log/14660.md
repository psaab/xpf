# #14660 — event-options accepts events and actions the engine can never fire or execute, without a warning (Y38-01)

## Defect

`schemaEventOptions` (`pkg/config/schema_system.go`) modeled `events`
with `children: nil` and `then` with only `change-configuration`, but
nothing enforced that closed world. `compileEventOptions`
(`pkg/config/compiler_services.go`) has no default arm, so it silently
drops every policy child other than `events`/`within`/
`attributes-match`/`plant-class`/`then`, every `then` child other than
`change-configuration`, and every `event-options` child other than
`policy`.

The only producer wired to `eventengine.HandleEvent`
(`pkg/daemon/daemon_apply_tail.go:740`,
`rpm.SetEventCallback(eventEngine.HandleEvent)`) is `pkg/rpm`
`fireEvent`, which emits exactly three names:
`ping_probe_failed` (rpm.go:728), `ping_test_failed` (rpm.go:780),
`ping_test_completed` (rpm.go:789). The engine indexes policies by
exact `ev.Name` (`evaluateEvent`), so matching is case-sensitive, and
it executes only `change-configuration` commands (`classifyPlan`).

Measured at `origin/master` `ffcb0bd38` (issue probe, re-verified by
the new tests' RED run): `events snmp_trap_link_down`,
`events PING_TEST_FAILED`, `then execute-commands`, `then raise-trap`,
`then generate-event`, and an `event-options` child other than
`policy` all passed `CheckText` (strict) and flat-set `SetPath` with
`warnings=[]`. Remediation the operator believed was armed (failover,
route withdrawal) was silently inert until the incident it was meant
for. No packet-path effect.

## Fix

Scoped AST pre-walk gate, following the #9552/#9323 pattern (NOT
`closedWorld: true` on the schema, which inherits past `then`):

- `pkg/config/event_options_inert_14660.go` (new):
  `validateEventOptionsInertAST` walks every top-level `event-options`
  block on the group-expanded, inactive-pruned tree (duplicate-block
  discipline via `forEachChild` + `namedInstances`, the same readers
  `compileEventOptions` uses; event values via `plainListValues` so
  bracket/block/repeated/flat spellings are all covered). It rejects:
  an `event-options` child other than `policy` (including the packed
  `event-options <tok>` tail), a policy child not declared in
  `schemaEventOptions`, an `events` value outside `KnownEventNames`,
  and a `then` child other than `change-configuration` (both the
  packed `then <action>` tail and braced children, via
  `thenChildTokens14660`). Permitted child/action sets are READ FROM
  THE SCHEMA (#9017 rule), so a future declared child is permitted
  automatically. `KnownEventNames` is the SSOT for fireable events;
  `TestKnownEventNamesMatchesRPMProducers14660` (configstore) scans
  `pkg/rpm/rpm.go` `fireEvent("...")` sites and asserts both
  directions, so producer/gate drift fails a test.
- `pkg/config/compiler_prewalk.go`: wired into `runPreWalkGates`
  after the #9552 dhcp-relay gate; warnings thread through the
  existing `fwFilterFamilyWarnings` accumulator in execution order.
- `pkg/config/compiler_opts.go`: `lenientEventInert14660` — strict
  (commit / commit-check): hard error naming policy + token + known
  set + `(#14660)`; tolerant (load / peer-sync, `lenientCompileOpts`):
  downgraded to a `cfg.Warnings` entry so a persisted config an older
  binary accepted still boots (#1960), the inert policy simply never
  fires — the pre-existing runtime behaviour, now surfaced. Same
  doctrine as `lenientEventWithinTrigger` (#3751).
- NOT changed: `SchemaValidate`/`closedWorld` (would inherit and
  over-close), the engine (already fails closed — unknown events
  simply never index-match), and Junos `generate-event` as a
  top-level `event-options` child is rejected as undeclared rather
  than implemented (no producer exists for generated events either).

Existing test fixtures that used dummy event names (`e`, `e1`,
`ev_one`, `other_event`, ...) as inert placeholders under strict
`CompileConfig` now use real RPM names (`ping_test_failed` etc.) so
they keep exercising the reader shapes they were written for:
`compiler_flatset_bracket_child_7126_test.go`,
`compiler_multivalue_leaf_6714_test.go`,
`compiler_multivalue_leaf_empty_6673_test.go`,
`compiler_multivalue_leaf_failopen_6659_test.go`,
`event_options_4423_test.go`, `multivalue_mixed_shape_6673_test.go`.

Docs: `pkg/eventengine/README.md` gains a "Closed-world commit gate
(#14660)" section.

## Risk

- Behaviour delta: configs that previously committed with inert
  event-options shapes now hard-reject at commit. That is the point
  (accepted-but-inert must warn/reject, #10707/#10294 doctrine);
  already-persisted configs still boot via the lenient warning path.
- A future RPM event name must be added to `KnownEventNames` or the
  drift test fails — deliberate friction, documented in README.
- Rust/dataplane: untouched. The Fix14655-noted master Rust test
  break (`policy_revalidation.rs` vs `allocator.rs` arity) is
  unrelated and not in this diff's scope.
