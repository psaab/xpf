# #16506: filter-selected forwarding class absent from the egress rewrite rule was re-marked with the overridden BA class's code-point

- **Timestamp**: 2026-10-24
- **Action**: `resolve_cos_priority_class_lp_rewrite` in
  `userspace-dp/src/afxdp/tx/cos_classify_ba.rs` chained
  filter-class -> BA-class -> clamped-queue, so when a filter
  `then forwarding-class <fc>` class had no entry in a partial egress
  DSCP rewrite-rule, the packet was queued as `<fc>` but re-marked with
  the BA class the filter overrode (e.g. queued EF, emitted DSCP 0 from
  the best-effort bleach entry), and the cached seed replayed that value
  on every flow-cache hit. Rewrote the resolver (and
  `resolve_cos_class_lp_rewrite`, now delegating to it) to key ONLY on
  the packet's final class: the filter class when present, else the BA
  class — its `(class, loss-priority)` entry, then the queue entry only
  when the egress queue IS that class's own materialized queue. This
  folds in Y28-05 (the unfiled clamped-queue cohort of the same
  resolver): an unmaterialized BA class absent from the rule no longer
  inherits the default queue's entry. A packet no classifier assigned
  any class to keeps the pre-#13968 queue-keyed behaviour (the selected
  queue is the classification result), which the #11386/#11808 cells
  pin. Updated the stale "then the BA class, then the clamped queue"
  comments in `tx/cos_classify.rs` and the final-class contract in
  `docs/cos-traffic-shaping.md`. Added three cells to
  `cos_filter_fc_14663_tests.rs`: the #16506 subject (fresh + cached
  seed `None`, two-packet hit DSCP 46 -> `None`, DSCP-46 twin,
  controls A/B, flowless), the unmaterialized-filter variant (clamped
  default queue must not bleach), and the Y28-05 BA-only variant
  (fresh/seed/hit `None`, materialized-BE control).
