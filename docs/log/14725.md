# Issue #14725 — session application filters match sets; predefined fallback completed

## Why

`SessionMatchesWithIndex` was pure `resolved == filter`, while the compiler
desugars a multi-term application into `<parent>-<term>` leaves grouped under
`ApplicationSets[parent]`. `clear/show security flow session application
web-multi` (and any application-set filter) therefore matched zero sessions.
`resolveTupleFallbackWithIndex` considered only the 15-entry
`builtinFallbacks`, so catalogued predefined apps outside that table
(`junos-rdp`, `junos-irc`, ...) never labelled unstamped sessions, and a
present-but-nil user entry (#4865) both failed `consider` and shadowed the
predefined definition, yielding UNKNOWN. Finally, the #12225 full-universe
re-rank let an uncatalogued collider's displaced ID steal a catalogued
(referenced) candidate's active slot, with the winner depending on Go map
iteration order in mixed tiers.

## What changed (`pkg/appid/runtime.go`)

- `SessionMatchesWithIndex`: exact match first (allocation-free warmed
  path); on miss, expand the filter as an application-set via
  `FallbackIndex.SetMembers` (cached once per filter per index, same
  precedence/bounds as `config.ExpandApplicationSet`: implicit multi-term
  parent sets, user sets, nested sets, predefined sets). UNKNOWN/empty
  resolved names never set-match; case-exactness (#5820) preserved.
- `FallbackIndex` retains its config snapshot and gains a set-expansion
  cache plus a reusable tier buffer (single-threaded per scan, preserving
  the #12225 zero-allocation warmed render).
- Tuple fallback now collects the winning specificity tier, then ranks it
  once deterministically: catalogued candidates rank by their true active
  ID (linear scan, donor path only); uncatalogued candidates rank by
  full-universe ID when the tie needs it (#12225), else natural ID. A
  catalogued user candidate is not displaced by an uncatalogued collider
  (direct natural-slot collision, displaced catalogued candidate, or
  displaced low-ID winner forms). Tiers containing a catalogued predefined
  candidate skip those guards.
- Predefined loop iterates the full `config.PredefinedApplications` table
  (port-constrained entries only — protocol-only predefined apps such as
  `junos-pingv6` were never in `builtinFallbacks` and admitting them would
  outrank specific user apps, #14355), gated by active-catalog presence
  (#12731), with shadowing only by a non-nil user entry (#4865/#11817).

## Risk

Display/filter label path only; no dataplane catalog, wire, or enforcement
change. Protocol-only predefined apps remain excluded from the tuple
fallback exactly as before (they were never in `builtinFallbacks`); a
referenced protocol-only predefined app still labels via its stamped
`app_id`. The reusable tier buffer relies on the documented
single-index-per-scan contract already held by `FallbackIndex`.
