# #14708 cross-hierarchy completion disclosure — engineering history

Issue: psaab/xpf#14708 ([gemini-hostile D15-03] Complete cross-hierarchy
ValueHint providers and operational `test policy` completion evaluate
confRules against the cursor prefix instead of the referenced configuration
subtree, bypassing deny-configuration / allow-configuration). Lane branch:
`fix/14708-campaign`, base `origin/master` 6a44142472.

## Defect (present at base)

#14144 gated `Complete`'s live values on the CURSOR path only:
`providerPathAllowed(path)` evaluates `confRules.Evaluate(join(path))`, and
`wrapProvider` then calls `base(hint, path)`. But `valueProvider`
(`pkg/grpcapi/server_cluster.go`) dispatches purely on the hint and reads a
FIXED hierarchy: `ValueHintInterfaceName` enumerates `cfg.Interfaces` (names
+ descriptions) from any cursor — OSPF/BGP/routing-instance/zone positions
all wire that hint (`pkg/config/schema_routing.go`) — `ValueHintPolicyAddress`
enumerates the global address book (names + CIDR values as descriptions),
`ValueHintZoneName` zones, `ValueHintPoolName` NAT pools, and so on. A class
with `deny-configuration "^interfaces"` therefore received interface names
and descriptions at `set protocols ospf area 0.0.0.0 interface <tab>`, and a
class with `deny-configuration "^security address-book"` received address
names and CIDRs at `set security policies … match source-address <tab>`.

Second arm: `operationalAllowed` checked `confRules.Evaluate(words[1:])`;
for `test policy from-zone <tab>` that string is `"policy from-zone"`, which
no `^security` deny matches, while `treeConfig` handed the full active config
to `cmdtree.OperationalTree`, whose `test policy from-zone/to-zone`
DynamicFns (`pkg/cmdtree/tree.go`) enumerate `cfg.Security.Zones`. Denied
zone names leaked from an operational completion.

## Fix

At the data source in `pkg/grpcapi/authz_complete_14144.go`, interceptor and
handler posture unchanged:

- `hintRoots` maps each `config.ValueHint` to the canonical config path(s)
  whose subtree its values are read from, in the space-joined spelling the
  `*-configuration` regexes match (`interfaces`, `security zones`,
  `security address-book`, `applications`, `security nat`, `security
  screen`, `security log`). `providerHintAllowed` now requires BOTH the
  cursor path (existing check) AND every owning root to be allowed.
  `ValueHintPolicyName` and `ValueHintUnitNumber` are deliberately unmapped:
  they read the zone pair / interface named IN the cursor path, so the
  cursor check already prices the exact subtree read. An unknown hint fails
  closed. Built-in literals offered by PolicyAddress/PolicyApp (`any`,
  predefined `junos-*` names) are public catalogue data, but the whole hint
  is gated on its owning subtree — the fail-closed reading.
- `operationalConfigPaths` maps the non-`show` operational prefixes whose
  DynamicFns enumerate configured data to their owning subtrees:
  `test policy …` → `security zones` + `security policies`, and
  `test security-zone …` → `interfaces`. `operationalAllowed` evaluates
  those roots against the configuration regexes; the `show …` arm keeps its
  existing words-after-`show` evaluation. This also narrows the pre-#14708
  behaviour for other non-show commands, whose typed words are no longer
  fed to the configuration regexes at all (they carry no config path).

NOT changed: `valueProvider`, `CompleteSetPathWithValues`, the cmdtree
DynamicFns, the local `pkg/cli` completer (in-process for the session's own
user, as in #14144), the coarse PermView price, and any tolerant/strict
doctrine. Invalid regexes, unidentified and class-less principals still
suppress live values via the unchanged `liveAllowed` gate.

Scope note: operational `show …` DynamicFns that enumerate a subtree other
than the one named after `show` (e.g. `show security flow session zone`
under a `^security zones` deny) remain priced by the command path itself,
exactly as #14144 left them — the issue's decisive check names the
cross-hierarchy ValueHint arm and the `test policy` arm, and both are
closed here.
