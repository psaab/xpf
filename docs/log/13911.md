# 13911 — Align unknown-outcome acceptance with stale P-MECH prefetch behavior

## Boundary

Issue #13911 reports that the unknown-outcome FIB bump test retained updated
`tunnel rows` but still required a complete P-MECH inventory containing the
new tunnel's route. With no-fallback locked stamping, a prefetch taken for the
old tunnel must not authorize the changed tunnel. The test must preserve the
unknown-outcome generation bookkeeping assertions, verify withheld authority
for the stale prefetch, and retain a matching-prefetch control.

## Change

Updated `TestBumpFIBGenerationRetainsUnknownOutcomeBookkeeping10724` to require
the proposed config/FIB generations and provider tunnel row to remain retained,
while the P-MECH inventory is incomplete, has no main routes, and marks the
row invalid with `MAIN_ROUTE_INVENTORY_STALE`. Added
`TestBumpFIBGenerationRetainsUnknownOutcomeMatchingPrefetch10724`, which keeps
the complete inventory and owned route expectation when the prefetch and
provider tunnel identity match. Production behavior is unchanged.

## RED then GREEN evidence

- RED on the issue branch's unchanged master base:
  `go test ./pkg/dataplane/userspace/ -run '^TestBumpFIBGenerationRetainsUnknownOutcomeBookkeeping10724$' -count=1 -v`
  failed at the obsolete complete-inventory assertion. Actual inventory was
  `Complete=false`, `MainRoutes=[]`, with `MAIN_ROUTE_INVENTORY_STALE`.
- GREEN:
  `go test ./pkg/dataplane/userspace/ -run '^TestBumpFIBGenerationRetainsUnknownOutcome' -count=1 -v`
  passed both stale-prefetch and matching-prefetch tests.
- GREEN repeat:
  `go test ./pkg/dataplane/userspace/ -run '^TestBumpFIBGenerationRetainsUnknownOutcome' -count=5`
  passed.
- `go vet ./pkg/dataplane/userspace/` passed.
