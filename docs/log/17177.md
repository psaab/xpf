# #17177 — centralise padding refusal in checkToken

- **Timestamp:** 2026-10-27
- **Branch:** `fix/17177-campaign`
- **File(s):** `pkg/config/schema.go`, `pkg/config/schema_walk_refs.go`, `pkg/config/schema_walk_leaf.go`, `pkg/config/schema_validators_network.go`, `pkg/config/schema_validators_routing.go`, `pkg/config/schema_validators_devicemap.go`, `pkg/config/schema_system.go`, `pkg/config/typed_validators_padding_17177_test.go`, `pkg/configstore/check_padded_typed_17177_test.go`, plus message-pin updates in `pkg/config/bgp_padded_clusterid_localaddr_14377_test.go`, `pkg/config/ospf_area_9820_test.go`, `pkg/config/static_route_padding_9820_test.go`, `pkg/configstore/static_padding_ingress_9820_test.go`

## Why

Padding policy was decided inside each LeafValidator, so "validator trims, consumer reads raw" was fixed one validator at a time (#9820, #14377, #15184, #15196). STEP-0 on current origin/master (5d3a03542c) reproduced the defect: a census probe over the live schema reported `validator-nodes=503 no-accepted-example=139 probed=364 pad-accepted=78` — including the three traced instances (RDNSS `dns-server-address`, device-map `pci`, scheduler `start-time`/`stop-time`), which commit green and are then silently dropped by the RA sender, the device-map binder, and the scheduler (a scheduled deny stays inactive all day).

## What

- Single source of truth: `refuseEdgeWhitespace` in `schema_walk_refs.go` refuses `tok != strings.TrimSpace(tok)` with one shared message (`value %q must not have leading or trailing whitespace (use the bare value without padding)`) before dispatch in `(*schemaNode).checkToken`, in `validateKeySlot` (identity-arg slots), in `validateTailLeaf` (whole-tail validators, incl. the scheduler time/date pairs), and for `blockChildValidator` block-list tokens.
- Opt-out: `schemaNode.allowEdgeWhitespace` + `allowEdgeWhitespaceReason`. Only the six OpenSSH authorized-key leaves (`ssh-ed25519`/`ssh-rsa`/`ssh-dsa` under root-authentication and per-user authentication) opt out, with the reason recorded: their value grammar is `"<type> <base64> [comment]"` — internal spaces are the value, and `ValidAuthorizedSSHKey` already refuses a leading-space type, judged identically by the daemon belt. Credential leaves do not opt out: padding there is a distinct key (#17888) and is now refused at strict commit with the migration spelled by the shared message; the tolerant path is unaffected.
- Deleted the 8 hand-placed local refusals (BGP local-address, tunnel endpoint, BGP cluster-id, OSPF area, BGP neighbor address, route destination, static next-hop, device-map logical name) and updated their message pins to the shared text. `grep -E 'raw != strings.TrimSpace\(raw\)|trimmed != raw|tok != raw|name != raw' pkg/config/schema_validators*.go` now returns 0 matches. (Non-adjudicated spans — `ValidateRouteFilterArgPositional`, scheduler tail pairs — keep their internal trimming for grammar; their tokens are refused earlier by the dispatch gates.)
- Permanent census `TestTypedValidatorsRefusePadding17177`: walks every unique schemaNode, probes each validator/tree/key slot with its own declared examples through the production dispatch, requires `pad-accepted=0` except allow-listed leaves with reasons, and counts + lists the no-accepted-example nodes so they cannot hide. Positive control `TestTypedValidatorsRefusePaddingPositiveControl17177` proves the probe sees the trimming-validator defect shape.
- Census on this head: `validator-nodes=516 probed=364 pad-accepted=0 allow-listed=6 no-accepted-example=146` (no-example count grew vs STEP-0 because tail-owned leaves have no single-token acceptance; they are gated in `validateTailLeaf` and exercised via the scheduler CheckText cells).
- Fold F1 (Rev18228b): `ValidateTunnelEndpoint` restores its raw edge-whitespace refusal (`raw != TrimSpace(raw)`, pre-PR message) — its header documents consumers parsing the RAW string, so delegating to trimming `ValidateIPAddress` contradicted it and made the direct cells in `TestTunnelPaddedEndpointSchemaGate_15196` fail; the central `checkToken` gate remains for the commit path.
- CheckText cells (`pkg/configstore/check_padded_typed_17177_test.go`) pin the three traced instances end-to-end: padded RDNSS (including inside a bracket list), padded device-map `pci`, and padded scheduler `start-time`/`stop-time` in both the `daily {}` and direct-child shapes are rejected with the shared message; bare controls commit.
- Fold (Rev18228 blockers B1/B2): the validators consumed directly by strict compiler gates / render belts refuse padding themselves again — `ValidateRouteDestination` (consumed by `generateRouteInvalidPrefixes` and the new `staticRouteInvalidPrefixes` on CompileConfig without SchemaValidate), `ValidateStaticNextHop`, `ValidateOSPFArea` (restores `validFRROSPFArea`'s documented commit==render equivalence), `ValidateBGPClusterID` (raw-parse `validClusterID` belt), and `ValidateDeviceMapLogicalName` (raw-stored name; `LinuxIfName` folds only `/`). `ValidateBGPNeighborAddress` needs no local arm: it parses the raw string with `netip.ParseAddr`, so padding already fails its grammar (documented in `strict_validators_padding_17177_test.go`). Deleted direct-call pins are restored (`static_route_padding_9820_test.go`, `ospf_area_9820_test.go`, `bgp_padded_clusterid_localaddr_14377_test.go`), and `TestCompileConfigPaddedCIDRRefused17177` proves strict refusal on generate + static via CompileConfig alone (no SchemaValidate), with tolerant warn-and-keep. New lenient opt `lenientStaticRoutePrefix` mirrors `lenientGenerateRoutePrefix`.

## Risk

Strict-commit tightening on every typed/key leaf: a quoted, padded literal that previously committed (and silently did nothing, or was trimmed by a trimming consumer) now fails commit-check with a message naming the padded value and the fix (use the bare value). The tolerant Load/SyncApply path downgrades schema errors to warnings (#1960), so stored configs are not bricked. No dataplane, compiler-storage, or per-packet path is touched — the compiler still stores the raw token; only the commit gate's verdict changed. The one intentional behaviour widening beyond the 66–78 measured instances is that previously-trimming consumers (rates, speed, name-server) now also refuse padding at commit, which is the single-policy point of the fix.
