# #17136 — ManualFailover's doc comment was orphaned onto FailoverOutcome (R4-Q35-07)

## Defect

Live on origin/master at 303ae6adfa (verified, not just at the cited
0ce804221f): `pkg/cluster/failover.go:37-40` — "ManualFailover forces a
redundancy group to transfer out of primary. Unlike ForceSecondary, ..."
— sat directly above the `FailoverOutcome` type comment, so Go attached
it to `type FailoverOutcome int`. `func (m *Manager) ManualFailover`
(failover.go:104 pre-fix) had no doc comment at all.

Confirmed pre-fix:

- `go doc ./pkg/cluster Manager.ManualFailover` printed only the signature.
- `go doc ./pkg/cluster FailoverOutcome` printed the ManualFailover
  transfer-out description as the type's description.

Trace (from the issue): 60b03a8827 (#8000) changed the return type to
`(FailoverOutcome, error)` and inserted the type and its doc between the
existing method comment and the method.

## Fix
Comment-only move in `pkg/cluster/failover.go`: the four-line
ManualFailover doc comment moved from above `FailoverOutcome` to
immediately above `func (m *Manager) ManualFailover`. It must be
immediately above — a blank line between comment and declaration
detaches it (caught by the regression test on the first attempt). No
code, signature, or behaviour change. `FailoverOutcome` retains its own
doc, now beginning with "FailoverOutcome reports".
