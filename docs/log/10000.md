# Issue #10000 — diagnose unusable ordinary static destinations

- **Issue:** An ordinary static route with an unusable destination (measured `route default discard` and malformed destinations) passed through the tolerant config path, then vanished from the userspace helper FIB. `StaticRouteExcludedReason` returned before checking `NextTable == ""`, so the configured route had no exclusion reason and the CLI/gRPC show surfaces rendered it as installed.
- **Context read:** Read the complete #10000 body and all comments before implementation. The issue had no comments; no scope withdrawal, narrowing, shipped notice, or contradiction was present.
- **What:** `StaticRouteExcludedReason` now rejects ordinary destinations that are neither valid CIDR prefixes nor bare IP addresses, while preserving bare-host normalization and the existing strict CIDR rule for next-table routes. `StaticRouteExclusions` therefore feeds the same verdict used by the helper-FIB builder and show surfaces. Local CLI and gRPC global/detail route renderers now print `NOT INSTALLED` for discarded, rejected, and ordinary next-hop rows in both address families. The change does not touch Rust DNAT (#6899/C180-023) or add wire fields.
- **Layer choice:** Destination usability is a deterministic property of the committed static route, so it belongs in the shared config exclusion predicate rather than only in the `addSnapshot` warning path. The builder skips the route before it can reach the helper FIB, and CLI/gRPC surfaces consume the same map; this prevents a config/show/builder split while retaining `routeDestinationForWire` as defense in depth for non-config snapshots and overlays.
