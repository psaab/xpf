# #19013: Count Rust fn-item callbacks in the unregistered-test audit

- **Timestamp**: 2026-11-08
- **Base**: `master` `dc97628b7c`
- **Action**: Teach `TestNoUnregisteredAssertingTestFn15255` to count bare and
  `::`-qualified function-item values as uses, preserving the dead-function
  finding for unreferenced asserting functions.

## Why

The audit counted only direct `name(` references. In
`userspace-dp/src/server/reinject_9506_tests.rs`, the two EMFILE body functions
are passed as `fn()` values to `run_emfile_body_in_child_18835`; the wrappers
carry `#[test]`, but the audit misreported both bodies as unreferenced.

## What

- Added source-level reference recognition for direct calls and fn-item values:
  bare references are not counted when a candidate-named token appears in a
  function/closure parameter or a recognized `let`, `for`, or match-arm
  pattern in that function. Qualified paths must resolve to the candidate
  module or impl owner and remain unaffected by local shadows. Calls, delimited
  values, `as` casts, and array elements are covered.
- An unqualified call does not resolve to an impl method when a same-named free
  function competes; owner-qualified calls identify the method.
- The scanner ignores comments and normal, byte/C, raw-string, and char
  literals; the direct-call path uses the same masked scan.
- Fixtures pin bare/qualified/cast/array callback references, qualified paths
  beside shadows, tuple patterns in `let`/function/closure/`for`/match arms,
  struct/slice/reference patterns in `let`, function params, and match arms,
  block and postfix-block iterables, unrelated qualified items, free/method
  declaration lines, and dead functions with comment/string mentions.

## Validation

- On the unmodified base, `TestNoUnregisteredAssertingTestFn15255` failed on
  both `reinject_submit_accept_survives_idle_emfile_15112_body_18835` and
  `reinject_complete_accept_survives_idle_emfile_15112_body_18835`.
- Focused audit and detector tests passed under
  `GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/wtgt
  scripts/testguard-run.sh`; the full `./pkg/refactoraudit` package passed.
- Fixtures confirm callback uses are recognized while shadowed locals,
  destructured function/closure parameters, `let`, `for`, and match-arm
  bindings, and unrelated qualified items do not suppress dead-fn findings.
  Impl collision fixtures distinguish free/method declaration lines;
  comment/string mentions remain findings.
- Fail-on-revert: disabling fn-item value recognition made the audit report
  both EMFILE bodies again. Restoring it returned the focused audit to green.

## Risk

Test-audit logic only; no production Rust behavior changed. Resolution is a
bounded lexical approximation, not complete Rust name resolution or `use`
alias handling. It scans candidate-name tokens in function/closure parameters,
`let` patterns (including `if let`/`while let`), `for` headers, and match-arm
patterns at any delimiter depth, covering tuple/struct/slice/reference
destructuring. A token found in any such pattern shadows the name throughout
the enclosing function body; this can create fail-closed spurious findings.
Macro-generated or hygienic bindings are not expanded and remain unsupported.
A reference finding does not establish that referenced code executes.
