# #19013: Count Rust fn-item callbacks in the unregistered-test audit

- **Timestamp**: 2026-11-08
- **Base**: `master` `dc97628b7c`
- **Action**: Teach `TestNoUnregisteredAssertingTestFn15255` to count bare and
  `::`-qualified function-item values as uses, preserving the dead-function
  finding for unreferenced asserting functions.

## Why

The audit counted only `name(` references. In
`userspace-dp/src/server/reinject_9506_tests.rs`, the two EMFILE body functions
are passed as `fn()` callbacks to `run_emfile_body_in_child_18835`, so the audit
misreported both as dead although their `#[test]` wrappers run them in a child.

## What

- Added fn-item reference recognition for an identifier used as a value and
  followed by an argument/binding delimiter; identifier boundaries avoid
  treating longer names as a match. This covers bare names and the final
  identifier in a `::`-qualified path.
- The fn-item scan skips line/block comments and normal, byte/C, and raw string
  literals so text resembling a callback cannot hide a dead function.
- Added detector fixtures for bare and qualified callback arguments, plus a
  dead asserting fn with callback-like text in comments and strings. The
  displaced-test/no-caller fixture also continues to require a finding.

## Validation

- On the unmodified base, `TestNoUnregisteredAssertingTestFn15255` failed on
  both `reinject_submit_accept_survives_idle_emfile_15112_body_18835` and
  `reinject_complete_accept_survives_idle_emfile_15112_body_18835`.
- With the change, the focused audit and detector tests passed under
  `GOCACHE=/var/worktrees/.cache/go-build GOTMPDIR=/wtgt
  scripts/testguard-run.sh`; the full `./pkg/refactoraudit` package also passed.
- After adding non-code filtering, the detector test (including the comment and
  string false-positive fixture) and the full refactoraudit package passed under
  testguard.
- Fail-on-revert: removing the fn-item recognition condition made the focused
  audit fail again with both EMFILE body findings. Restoring it returned the
  focused audit to green.

## Risk

Test-audit logic only; no production Rust behavior changed. As with the existing
name-call scan, reference recognition is lexical rather than a Rust name
resolution pass.
