# #14674 — HA synced source-NAT reservation skips matching interface-mode rules

- **Timestamp**: 2026-10-17
- **Defect**: `reserve_synced_on_first_pool_owner` opened with
  `if !rule.pool_mode { continue; }`, so a first-matching
  interface-mode rule was never recognised. PASS 1 therefore let a
  later (same-zone) or PASS 2 let any (cross-zone) pool containing
  the egress address decide the import: a drained #7717 pool
  quarantined with `PoolIfaceEgressOverlap` set `saw_candidate`
  and yielded final `Refused`, and PASS 1 `Refused` is final in the
  caller, so `reserve_synced_interface_identity` was never reached
  (100% synced interface-SNAT loss under a quarantined pool); a
  healthy lower-priority pool instead booked the reservation into
  `pool_allocator` instead of `iface_allocs`, leaving a
  post-failover port-collision window. The active admits exactly
  these sessions once `live_flow_count()==0`
  (`address_has_draining_pool_occupancy` false,
  `match_rules.rs` interface arm gated only by that check).
- **Fix**: `userspace-dp/src/nat/source/synced.rs` —
  (1) PASS 1 now detects the first `matches_ignoring_scope` rule
  before the pool scan; when it is interface-mode it skips both
  pool scans, refuses only if
  `address_has_draining_pool_occupancy(rules, rewrite_src)`, and
  otherwise books via `reserve_synced_interface_identity`,
  mirroring the active. (2) `reserve_synced_on_first_pool_owner`
  (both port-bearing and address-only arms) skips a drained
  `PoolIfaceEgressOverlap` candidate before `saw_candidate` when
  no draining pool holds live flows on the address (takes the
  full `all_rules` slice for that check), so the PASS 2/no-zones
  fallback reaches the interface domain instead of refusing.
  `OverBudget` and still-draining overlaps keep their #7076
  candidacy and refusal unchanged.
  NOT changed: active `match_rules.rs` path, PASS 2
  first-acceptor semantics for genuine pool sessions.
- **Regression**: `userspace-dp/src/nat/tests_pool.rs` — 7 cells
  (`_14674`): cross-zone and same-zone drained quarantine imports
  in both port shapes (`Some(20000)` and `None`),
  lower-priority healthy pool books in iface not pool,
  pool-first control books in pool, no-zones drained quarantine
  imports, no-zones `OverBudget` still refuses, still-draining
  overlap refuses in both passes (live flow minted, then
  quarantine via previous-generation rebuild so the allocator
  and its flow carry over).

    (cross-zone, same-zone, lower-pool, no-zones quarantine
    cells fail as "must not refuse" / "must book in
    iface_allocs"), 3 controls passed.
  - GREEN (fix restored): same command — 7 passed.

- **Risk**: PASS 1 interface-first imports now consult draining
  occupancy exactly as the active does; still-draining overlaps
  still refuse. The no-zones fallback is unchanged except that a
  drained overlap no longer blocks the interface domain it was
  quarantined to protect. No wire, Go, or active-path change.
