# #13199 — remote destination NAT pool identity and filtering

- **Finding:** D10-03 reported that `cmd/cli` keyed destination NAT pools by
  translation address while `GetNATRuleStats` identifies actions by configured
  pool name. This caused every summary hit count to be zero, showed the address
  as the pool name, and made `destination pool <name>` ignore its selector.
  Summary rendering also swallowed stats RPC failures.
- **Fix:** Add the configured `pool_name` as an additive field on
  `NATDestInfo`, populate it from `rule.Then.PoolName`, use it to join hit
  counters and render names, and sort summary/detail rows deterministically.
  Carry the optional pool selector to the destination-pool renderer, report
  unmatched names, and return stats RPC errors instead of printing fabricated
  zero hits. Older daemons omit `pool_name`, so the client falls back to the
  translated address. Poolless `destination-nat off` rules are excluded from
  pool totals and listings. The deterministic NAT `pool` selector parser
  rejects missing names and extra or unknown tokens.
- **Regression:** `cmd/cli/show_nat_13199_test.go` covers named-pool hit joins,
  deterministic ordering, pool filtering, unknown-pool errors, stats RPC error
  propagation, poolless rules, and malformed selector tokens.
  `pkg/grpcapi/nat_view_10437_10438_test.go` verifies the server fills
  `pool_name` from the configured rule.
- **RED:** On pristine `origin/master` at `f7492bd5c`, temporary
  `TestIssue13199PristineSummaryRegression` failed: the summary rendered
  `192.0.2.10/32` in the Pool column and `0` hits despite a `pool web-pool`
  stats response with 42 hits. `TestIssue13199PristineFilterRegression`
  failed because `destination pool web-pool` printed unrelated `mail-rule`.
  On pristine post-#13199 master `722b85f`, follow-up probes failed because a
  poolless off-rule inflated the pool count to two and
  `internal-host <ip> pool` was accepted and sent to the RPC.

  passed all four CLI regression tests. The full CLI suite passed with the

  pristine master too. `go test ./pkg/grpcapi -count=1` passed.
  `go build ./cmd/cli ./...` and `go vet ./cmd/cli/` passed.
- **Scope:** No local `pkg/cli` renderer changes; the findings concern the
  remote `cmd/cli` path and its gRPC projection.
