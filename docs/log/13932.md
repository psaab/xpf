# #13932 — include interface-NAT addresses in tagged-only VID-0 local drop

## Why

The #12055 VID-0 local-delivery guard used `is_local_destination`, which intentionally excludes interface-NAT addresses. On a tagged-only trunk parent, untagged or priority-tagged ICMP echo and ESP to an interface-NAT address could therefore take the shim's kernel-pass arms. IPv6 lacks the incidental `rp_filter` protection noted for IPv4, allowing the kernel to answer a host-inbound echo under the destination owner's policy despite the wrong ingress identity.

## What

The tagged-only VID-0 guard now uses a dedicated firewall-owned predicate covering ordinary local and interface-NAT destination maps in both address families. The change leaves `is_local_destination` semantics intact for normal steering. The existing #12055 shim regression covers interface-NAT IPv4/IPv6 echo and IPv4/IPv6 ESP drops, including priority-tagged IPv6 echo and the control-disabled path, with configured-tag parent and adjudicated-only child-like controls for every packet shape. This PR is rebased onto #13928's parent-only tagged-only scope change, preserving its child re-entry fix alongside this predicate widening.
