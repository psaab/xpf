# Issue #15270 — config: fix cohort — Junos-syntax import parity, fail-closed (B19-02)

- **Issue:** `security log stream <s> host` was modelled as an inline single-value leaf (`children: nil`), so the braced Junos form `host { 192.168.99.252; port 514; }` — which `compileLog` and the #3349 port gate already read — failed `SchemaValidate` with `host: missing value`. The log-level `source-address 192.168.99.1;` from the same vSRX reference stanza (`docs/junos-cli-reference.md`) was an unknown keyword under the closed-world `security` arm. A leniently loaded copy then blocked strict commits.
- **Fix:**
  - `pkg/config/schema_security.go`: `host` is now value-or-container (typed flat value via `ValidateSyslogHost`, typed `port` modifier child, `nodeValidator: validateSecurityLogHostNode15270`); added global `security log source-address` as a typed `ValueIPAddress` leaf.
  - `pkg/config/schema_walk.go`: `validateSecurityLogHostNode15270` requires exactly one bare address child (same `ValidateSyslogHost`) plus only `port` children in `[1..65535]`; `validateTypedLeaf`/walker accept the braced shape and the grouped flat `host port <n>` sibling (the `FormatSet` rendering); `siblingSuppliesTypedValue` also sees braced bare-address children.
  - `pkg/config/flat_run_scan.go`: `expandFlatRun` still splits `host` chains (its only child is the `port` modifier, not a body), preserving the #12887 tls-profile gate.
  - `pkg/config/compiler_security_log.go`: `compileLog` reads the global `source-address` into `LogConfig.SourceAddress` and the flat/packed/grouped `host port` forms; `validateSecurityLogStreamPortsAST` range-gates all port locations.
  - `pkg/config/types_security.go`: `LogConfig.SourceAddress`.
  - `pkg/daemon/daemon_system.go` + `pkg/cli/apply.go`: apply precedence per stream is stream `source-address` > stream `source-interface` > **global `source-address`** > global `source-interface`; both syslog fingerprints include the global value so a change rebuilds clients.
  - Census: regenerated `compact_block_divergences_2419.txt` (adds `security log report` / `security log source-address` as compact-blind, pre-existing `FindChild` reader shape; drops the now-equivalent `protocols lldp interface xpfarg disable`) and classified both new sites `open` in `compact_block_permanent_exclusions_8690.txt`. Note: `TestPermanentExclusionsMatchTheInventory8690` already fails on `origin/master` (17 stale `open` lines + 2 unclassified sites pre-date this change); this change does not worsen that count beyond its own two classified sites.
