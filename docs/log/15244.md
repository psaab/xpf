# Issue #15244 — userspace-dp: fix cohort — TX-latency telemetry coverage (A61-01, A61-03)

- **Timestamp**: 2026-10-19
- **Action**: Fixed both halves of the cohort.

  **A61-01 — `tx_submit_ns` sized to the binding's own frame count.**
  `BindingWorker::create` sized the #812 submit-timestamp sidecar to
  `binding_frame_count_for_driver(..)` (the binding's own carve-out),
  while a shared UMEM's pool is filled for the whole group
  (`create_shared_binding_group` sums every plan's count into one
  `WorkerUmemPool`) and each binding pops its frames sequentially —
  so a secondary owns region-wide offsets in `[N, 2N)`. Every stamp
  for those offsets indexed past the secondary's `N`-slot sidecar and
  `stamp_submits`' `get_mut` silently dropped it; the reap fold in
  `record_tx_completions_with_stamp` dropped the matching completions
  the same way. The #812 histogram therefore covered only the owner /
  a direction-dependent subset (telemetry bias only; no forwarding
  impact). Fix: new pure helper
  `worker/tx_pipeline.rs::tx_submit_sidecar_len(worker_umem)` returns
  `worker_umem.total_frames().max(1)` (the group sum under a shared
  UMEM; identical to the old value for a private UMEM, where the two
  counts coincide), and `BindingWorker::create` sizes the sidecar
  with it. The stale comment in `tx/stats.rs::stamp_submits` (which
  claimed an out-of-range offset "belongs to a different binding's
  sidecar") is corrected: offsets are region-wide and now stamp in
  the submitter's own sidecar; `get_mut` remains only as a soundness
  guard for a genuinely foreign offset past the whole region. The
  former OOB pin tests are corrected: the secondary-offsets test now
  asserts `secondary_stamped=N/N` plus per-binding completion
  counting, and the two OOB pins are narrowed to past-the-whole-region
  offsets. NOT changed: `stamp_submits` / reap signatures, the
  sentinel, bucket layout, or any test-only sidecar literal (those
  construct empty/small sidecars for unrelated paths and never
  claimed region sizing).

  **A61-03 — post-create bind failures were not terminal for the
  flag/strategy ladder.** `open_binding_worker_rings` looped
  strategies × `bind_flag_candidates`, overwriting `last_err` each
  time. After a successful `xsk_socket__create`, a post-create
  failure (identity mismatch after its `xsk_socket__delete`, fill
  prime, non-zerocopy) left the UMEM unmapped / its saved fill/comp
  cleared by libxdp, so the next candidate's create failed `-EFAULT`
  and the surfaced `last_err` became "Bad address" instead of the
  true cause (the bind still failed closed either way; the
  per-attempt journal line kept the true cause). Fix: new typed
  `PostCreateBindError` in `bind.rs` (`post_create_bind_error` /
  `is_post_create_bind_error`); `try_open_bind` tags all three
  post-create arms (identity mismatch via
  `fail_identity_mismatched_bind`, fill-prime failure, non-zerocopy
  rejection — the latter two now also drop the created handles
  device-first before returning, matching the mismatch teardown, so
  no created socket leaks into the ladder exit), and
  `open_binding_worker_rings` returns a tagged error immediately.
  Recovery is the outer reconcile loop on a fresh UMEM (fresh
  `WorkerUmemPool` per group attempt, then private fallback), as
  with the #15088 owner rule. NOT changed: pre-create failures keep
  the ladder (the UMEM is untouched and the next candidate may
  legitimately succeed), the EBUSY retry, flag candidates, or
  strategies.

  secondary stamps the new test asserts (`secondary_stamped=N/N`).
  GREEN after the fix: `cargo test --bins -- 15244` and
  `cargo test --test post_create_bind_terminal_15244` — see PR.
  Named controls kept green: the narrowed past-region OOB pins
  (stamp drop + reap no-phantom), the plain-create-error control
  (not post-create terminal; ladder preserved), and the neighbouring
  #812 latency / #9904 identity / #15088 owner suites.
- **Risk**: Private-UMEM behaviour is byte-identical (region total ==
  per-binding count). Shared secondaries now allocate a group-sized
  sidecar per binding (8 bytes × group frames — at 18 bindings ×
  40960 frames ≈ 5.9 MB worst case across the group, cold allocation
  at worker construction only; no hot-path change). A post-create
  failure that the ladder formerly retried (and occasionally
  recovered from for a secondary whose own mapping copy was deleted)
  now fails the bind and recovers via reconcile/private fallback —
  a delay, not a silent wrong-cause surface. No forwarding, ring, or
  wire behaviour changes.
