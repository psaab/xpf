# Standalone VRRP VIP deleted by netlink address reconcile (#16833, R3-F11-04)

- **Issue**: #16833 — every commit's netlink address reconcile deleted a
  standalone (non-RETH) `vrrp-group` MASTER's VIP (untagged and VLAN
  units); VRRP stayed MASTER and nothing re-added it, so hosts lost
  their first-hop gateway until a state change or restart.
- **Cause**:
  - `pkg/dataplane/compiler_iface_desired.go` `planPhysDesired`: the
    only `skipAddrs` suppressions were RETH (`RedundancyGroup > 0`),
    fabric parent, and DHCP; desired was `unit.Addresses` only, so a
    standalone VIP was never in the desired set.
  - `pkg/dataplane/compiler_iface.go` VLAN arm: desired was the tagged
    unit's `Addresses` only, with only DHCP/RETH skips.
  - `planAddressReconcile` deletes every non-link-local kernel address
    not in desired, so the pkg/vrrp-installed VIP was treated exactly
    like stale debris. The only prior VRRP consult in pkg/dataplane was
    the networkd keep (#15061, `compiler_iface_vrrp_keep.go`), which
    protects a different writer. On the re-add side,
    `UpdateInstances` sees no change for a still-MASTER instance, and
    `ReconcileVIPs` runs only on link-cycle recovery.
- **Change**:
  - `pkg/dataplane/compiler_iface_vrrp_keep.go`: new
    `unitStandaloneVRRPVIPs` returns a unit's vrrp-group
    `VirtualAddresses` canonicalised via `netlink.ParseAddr` (same key
    space as kernel addresses), deduplicated; unparseable entries are
    dropped (pkg/vrrp cannot install them either).
  - `pkg/dataplane/compiler_iface_desired.go`: `physDesired` gains
    `keepAddrs`; `planPhysDesired` collects the VIPs of every enabled
    untagged unit into it (never into `addrs`). Disabled units are
    already skipped before this point.
  - `pkg/dataplane/compiler_iface.go`: `planAddressReconcile` and
    `reconcileInterfaceAddresses` take an explicit `keep []string`
    parameter (before the variadic primaries); kept addresses are
    excluded from the delete set and never added. Both call sites pass
    the keep set (physDesired.keepAddrs; the VLAN unit's VIPs when not
    unit-disabled). Existing tests migrated with `nil` keep (behaviour
    unchanged when no VIPs exist). NOT changed: `skipAddrs` semantics —
    a standalone-VRRP netdev still reconciles its real addresses and
    still deletes genuine stale debris; removing a vrrp-group removes
    the keep, so a still-present VIP becomes deletable again (and
    pkg/vrrp withdraws it on instance removal). The optional pkg/vrrp
    RTM_DELADDR belt from the issue was not added: with the planner
    fixed, no commit path deletes the VIP, and a watcher would be a
    second mechanism for a now-closed hole.
- **RED evidence**: on pristine base the new test file fails to build
  (`physDesired.keepAddrs` / `unitStandaloneVRRPVIPs` undefined, new
  planner signature) — the keep model was absent; behaviourally, a
  base-planner probe with existing=[10.0.1.10/24, 10.0.1.1/24] and
  desired=[10.0.1.10/24] plans `del=[10.0.1.1/24]` (the bug, PASS of
  the probe asserting the deletion on base).
- **GREEN evidence**: `go test ./pkg/dataplane/ -run
  'TestStandaloneVRRPVIPSurvives' -count=1 -v` passes both cells
  (planner/planPhysDesired level: MASTER untagged + VLAN zero deletes,
  BACKUP keep-never-adds, stale 10.0.9.9/24 still deleted on both
  arms, group-removed VIP deletable, disabled unit no keep;
  actuation level: second `programZoneMaps` apply over the fake host
  keeps both VIPs and still removes stale debris on both devices).
  Targeted suites (`TestPlanAddressReconcile*`,
  `TestDualStackPrimary*`, convergence #8119/#8120, #15061 keep,
  errno #10529) pass. Full `go test ./pkg/dataplane/` shows only
  pre-existing base failures (XDP shim allowlist, Manager method
  count, legacy-import allowlist — verified identical on pristine
  base via stash), unrelated to this change.
- **Risk**: keep matching is prefix-sensitive, mirroring pkg/vrrp's own
  `ParseAddr` install: a VIP whose configured prefix differs from the
  kernel-installed prefix would not match — but pkg/vrrp installs
  exactly the configured string, so they agree. IPv6 VIPs are kept the
  same way (DAD-failed repair of a kept address is also suppressed;
  a MASTER's VIP with DADFAILED is pkg/vrrp's concern, it installs
  with NODAD). No BPF/Rust/wire change; userspace dataplane unaffected.
