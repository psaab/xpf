# #13415 — preserve scoped-global sessions across multi-zone renames

- **Timestamp**: 2026-10-15
- **Base**: `origin/master` `dd607606a`
- **Action**: Emit ancestry for every scoped-global from/to zone pair and select the matching row per ID-zero session during Rust rotation.

## Red before

The Go regression on pristine `dd607606a` emitted only `lan->lan` ancestry for a global policy scoped to `[lan,wan]` on both sides, despite simultaneous `lan->lan2` and `wan->wan2` renames. The expected `lan->wan`, `wan->lan`, and `wan->wan` rows were missing.

## Change

- Global policy scope expansion now forms the Cartesian product of the original `FromZones` and `ToZones` (using the global sentinel for an empty/unrestricted side), maps each endpoint through the complete rename map, and emits every matching ancestry wire row. Duplicate stable IDs are permitted for these global-scope rows; non-global ancestry remains one-to-one.
- Rust extensive first-policy rotation now selects the ancestry row whose old from/to zones match each bound session, rather than requiring exactly one row for the global rule. This retains sessions across multiple zone directions while leaving unmatched sessions on the existing fail-closed teardown path.
- Updated #13175's composed ancestry expectations and added Go/Rust regression coverage. The Go test proves the global-only policy carries ID zero.
