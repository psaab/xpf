# #13921 — reject expanded policy sets at commit

A zone-pair or global policy set could expand beyond the 256-rule ID block
while strict commit validation still succeeded. Snapshot construction rejected
the config only during apply, so commit reported success while the dataplane
retained its previous snapshot.

Strict policy validation now counts distinct resolved application members for
each zone-pair and global policy set, rejecting expansion beyond the shared
`MaxRulesPerPolicy` capacity. Exactly 256 rules remain valid. Tolerant load and
peer-sync continue to downgrade the rejection to a warning under the existing
policy-application leniency gate.

Regression coverage exercises both scopes with 257 plain rules and with
application-set multiplication (13 policies × 20 applications), exact-256
acceptance, and tolerant-path warning behavior. The test was run against the
unmodified base first and failed because the strict commit accepted the
oversized sets.
