# #14630 — RST then a bare ACK completes the handshake gate and re-arms the reset reverse half onto the 300 s window (Y25-01)

## Defect
After SYN, reverse SYN-ACK, RST, then a bare forward ACK:
- `lookup.rs` `handshake_completed` consulted only packet flags plus
  `entry.handshake_pending`; `stamp_tcp_close` stamps `closing`/`reset`
  but leaves `handshake_pending` set, so the bare ACK (not itself closing)
  completed the handshake on the forward half.
- The forward half stayed on the 2 s window only by accident of its own
  `closing` refresh branch; `propagate_tcp_state_to_companion` then
  unconditionally re-stamped the reverse companion onto
  `session_timeout_ns(..., true, ...)` (300 s, or the app inactivity
  timeout) and cleared its pending bit.
- Result: forward reaps at RST+2 s, reverse survives as an orphan row —
  uncounted (per-source counting charges only the forward half, and the
  forward removal decrements it), still admitting server→client hits and
  listed by `show security flow session` for up to 5 minutes. Violates
  the `TcpCloseClass::Reset` contract (#3046/#10885): a RST is sticky and
  no later segment promotes the entry back to a longer window.

The HA twin `update_session` (which carries real TCP flags on the
shared-promote path) had the same hole: its own half stayed on the close
window, but the companion mirror re-armed the sibling.

## Fix
Entry-state gate `!closing` at every completion/promotion site:
- `userspace-dp/src/session/lookup.rs`: `promote_from_reverse`,
  `promote_from_asymmetric_ack`, and `handshake_completed` all require
  `!entry.closing` (evaluated after `stamp_tcp_close`, so a RST/FIN on
  this very segment also blocks).
- `userspace-dp/src/session/mod.rs` `update_session`: same gate on
  `reverse_syn_ack` and `handshake_completed`.
- `userspace-dp/src/session/mod.rs` `propagate_tcp_state_to_companion`:
  a closing companion is never (re-)pended, promoted, or completed —
  keeps the mirror correct even for a caller that passes
  `handshake_completed` for a closing pair.
- `userspace-dp/src/session/tests.rs`: the pre-#1752
  `reference_update_session` mirror updated identically so the
  in-place/reference parity sweep stays faithful.
- `userspace-dp/src/session/README.md`: handshake section records the
  closing-never-completes invariant.

NOT changed: `stamp_tcp_close` still leaves `handshake_pending` set
(the pending bit is meaningless once closing; clearing it would not fix
the companion re-arm, which keyed off the propagated flag), close-window
formula, refresh/#10885 sliding rules, counting sinks.

## Remaining validation
- Poll-path delivery of the post-RST ACK (flow-cache seeding interaction
  named in the issue) was not executed end-to-end; the fix is at the
  SessionTable state machine every delivery path funnels through
  (`lookup_with_origin_inner` / `apply_deferred_owner_hit` replays it).
  The deferred-owner path replays the same gated lookup, so a deferred
  close followed by an owner ACK cannot complete either.
