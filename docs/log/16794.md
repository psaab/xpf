# #16794 — CLI history denylist misses plain-text-password and edit-context secrets

- **Base**: `c85c6bd36d` (origin/master at branch start)
- **Branch**: `fix/16794-cli-history-secret`

## Why

#15287 re-enabled on-disk CLI history behind `IsSensitiveHistoryLine`, a
hand-copied flat token denylist in `pkg/cliterm`. It missed
`plain-text-password` / `plain-text-password-value` entirely, and every
edit-context spelling of the context-gated secrets: after `edit snmp`,
`set community <s>` has no `snmp` token on the line; after
`edit ... authentication md5 1`, `set key <s>` has no
`authentication md5` window; after `edit ... authentication`,
`set md5 1 key <s>` likewise. Those lines persisted cleartext root/login
passwords, SNMP v1/v2c communities and OSPF/IS-IS MD5 keys durably to
`~/.xpf_history` (local CLI) or `~/.xpf_cli_history` (remote CLI),
breaking the #10743 contract that typed credentials never persist.

## What

- `pkg/cliterm/terminal.go`: `IsSensitiveHistoryLineAt(editPath, line)`
  and `RecordHistoryLineAt(editPath, path, line)` resolve the operator's
  full path — lexed edit cursor + lexed line tokens (store lexer via
  `config.ParseConfigMutationLine`, quotes consumed) — through the
  config SSOT: `config.IsSecretValueInPath16794`, the union of
  `secretIndices` (ast_redact.go) and `secretLeafKeywords` (secret.go).
  `set`/`edit` lines are judged on cursor + path tokens (an `edit` line
  carrying a value after a secret keyword is suppressed); `top`/`up`
  prefixes resolve to their target cursor first
  (`ParseTopUpPrefix15082`); operational lines are judged on their own
  tokens with the cursor ignored. Fail-closed arms kept/added: bare
  `password`/`secret` tokens anywhere (#15284), and non-lexing
  config-verb lines are suppressed rather than risk an unseen tail.
  The hand-copied denylist is deleted; `IsSensitiveHistoryLine` /
  `RecordHistoryLine` remain as the no-cursor forms.
- `pkg/config/freetext.go`: export the existing union as
  `IsSecretValueInPath16794` plus copy-out enumerations
  (`SecretLeafKeywordSet16794`, `SecretContextKeywords16794`) so the
  history drift pin can iterate the SSOT population. NOT changed: any
  secret resolution semantics — the exported predicate is
  `secretValueIndicesFlat` verbatim.
- Both surfaces wire the cursor: `pkg/cli/cli.go` passes
  `store.GetEditPath()`; `cmd/cli/main.go` passes `c.editPath` (config
  mode only). Seeding (`ReadHistorySeed`) stays cursor-free: persisted
  lines spell their full flat path, which the no-cursor form judges.

## Validation

- New `pkg/cliterm/history_secret_editpath_16794_test.go`: the five
  #16794 defect rows plus trap-group / api-auth-secret / top / up /
  quoted-value spellings report persisted=false through the real
  on-disk recorder; the issue's controls are unchanged; benign lines
  (policy-options community, GRE tunnel key, bare `edit community`,
  bare `up`) still persist; `TestHistoryPredicatePinnedToSecretSSOT16794`
  pins the predicate against `secretLeafKeywords ∪ secretIndices`
  keywords so it cannot drift.
- `go vet ./pkg/cliterm/ ./pkg/config/ ./pkg/cli/ ./cmd/cli/` clean;
  `go test ./pkg/cliterm/ -run 'TestHistory|TestIsSensitive|TestBothSurfaces'`
  all pass; secret-resolution config tests pass.
- Full `pkg/config` / `pkg/cli` / `cmd/cli` suites show pre-existing
  failures identical on pristine base `c85c6bd36d` (config
  `TestDualASTDifferential` panic; 16 `pkg/cli` failures; `cmd/cli`
  `TestTreeIsGofmtClean`) — base-attributed, not this change.

## Risk

History is advisory operator state. Failure direction is fail-closed
for credentials (over-suppression costs one history entry; the line
still ran and stays recallable in-session) and fail-visible for
persistence (record errors print a warning). Residual: lines already
persisted by the buggy denylist stay on disk until the operator wipes
the file and rotates the affected credentials — code cannot retroactively
un-persist them; `ReadHistorySeed` drops flat-spelled credential lines
on load but cannot recognise a bare `set community <s>` fragment without
its cursor, so a manual wipe is the only complete remediation.
