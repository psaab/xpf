# #15192 (D07-01): repeated hierarchical firewall `term T` stanza strict-committed as two same-named terms

- **Timestamp**: 2026-10-19
  - **Action**: Strict-reject a duplicate term name inside one firewall filter (lenient: warn, keep both), aggregate the duplicated `(filter,family,term)` key in the Prometheus filter collector, and sum duplicated keys in the shared userspace counter index. Added RED/GREEN regressions plus controls; this log.
  - **File(s)**: `pkg/config/compiler_firewall.go` (`validateFirewallFilterDuplicateTermsAST`), `pkg/config/compiler_prewalk.go` (pre-walk wiring, reusing `lenientFirewallFilterFamilyCollisions`), `pkg/config/firewall_filter_term_dup_15192_test.go` (new), `pkg/api/metrics_counters.go` (`collectFilterCounters` aggregation), `pkg/api/filter_counters_dup_term_15192_test.go` (new), `pkg/dataplane/userspace/filtercounters.go` (`BuildFirewallFilterTermCounterIndex` sums), `pkg/dataplane/userspace/filtercounters_dup_15192_test.go` (new), `docs/log/15192.md` (this file)

## Mechanism (verified at base `53419c6cf2`)

- `pkg/config/compiler_firewall.go` `compileFirewall`: `for _, termInst := range namedInstances(termNodes) { ... filter.Terms = append(filter.Terms, term) }` — one term per stanza, no name check, no merge. The only duplicate gate was filter-level (#8426 same-family / #3884 cross-family, in `validateFirewallFilterFamilyCollisionsAST`).
- `pkg/config/dup_named_blocks_deep_8704.go`: `deepDupRules` covers only ipsec traffic-selector, device-map interface and traceoptions packet-filter — no filter-term row, so `TestEveryNotConservedContainerIsReported8704` reported nothing for `firewall family inet filter xpfname term` (the #8436 census lists those four term sites as not-conserved).
- Measured RED: the hierarchical text with `term T { from protocol tcp; then accept; }` + `term T { from destination-port 80; then discard; }` strict-compiled with no error and no warning as two `T` terms, in `inet`, `inet6`, `any` and implicit-inet spellings. Flat-set / `load merge` merge to one term, so the installed filter differs from the authored one in both directions (an action-only first stanza plus a match-only second stanza widens/narrows silently).
- `pkg/api/metrics_counters.go` `collectFilterCounters` emitted one `xpf_filter_hits_total{filter,family,term}` per term instance, so the lenient shape published the identical labelset twice — Prometheus `Gather` fails ("was collected before with the same name and label values") and `/metrics` returns HTTP 500. `BuildFirewallFilterTermCounterIndex` was also last-wins per key, dropping one term's userspace hits for CLI/gRPC/Prometheus alike.

## Change

- `validateFirewallFilterDuplicateTermsAST` (pre-walk, group-expanded tree): walks every top-level `firewall` node via the shared `firewallFamilyMembers9883` extractor (both AST shapes, quarantined families skipped) plus implicit-inet filters directly under `firewall`; scopes `seen` to the immediate filter. Strict: first duplicate is a hard error — `firewall family inet filter "F" has duplicate term "T" — a term name must be unique within a filter; combine the repeated term stanzas into one term (flat set and load merge merge them, the hierarchical spelling installed both) (#15192)`. Lenient: one warning per duplicated (family,filter,term), both terms kept (historical boot, #1960). Reuses the existing `lenientFirewallFilterFamilyCollisions` tolerant profile — no new opt flag.
- `collectFilterCounters`: aggregates per (filter,family,term) before emitting — map-slot packets of every same-named instance are summed (ruleOffset still advances per instance, preserving #3459 alignment), the single userspace counter for the shared key is merged exactly once, and the #3408 skip verdict stays per-instance. Distinct terms/filters are byte-unchanged.
- `BuildFirewallFilterTermCounterIndex`: a repeated key sums Packets/Bytes instead of last-wins, so CLI/gRPC/Prometheus all see both terms' hits.

NOT changed: `compileFirewall`'s append (the lenient path must keep both terms to boot), the Rust filter compiler (it already receives both terms on the lenient path and matches them in order — no wire change), the #8426/#3884 filter-name gates, and the #8704 registry (superseded for this site by the bespoke gate above, which also satisfies the D07-02 census expectation that the strict error names the duplicate).
