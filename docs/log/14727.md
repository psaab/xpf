# #14727 — RPM probe-setup errors counted as path loss (D19-05)

## Defect (three legs, all confirmed on origin/master 59f4ac7065)

The consumer is `runSingleTestWithOptions` (`pkg/rpm/rpm.go`): an error
wrapping `ErrProbeSetup` HOLDS the test (no counters, no transition, no
ip-monitoring actuation); anything else increments `SuccFail`, can fire
`ping_test_failed`, and can drive WAN failover. Three setup paths
returned errors without the sentinel:

1. **`canonicalizeHTTPTarget`** returned 5 unwrapped `fmt.Errorf`s
   (empty target, schemeless no-host, invalid URL, unsupported scheme,
   schemed no-host) despite its own C179-042 comment promising
   hold-state semantics, and `probeHTTP` returned its error raw plus
   the `http.NewRequestWithContext` failure as `HTTP request error: %w`
   unwrapped. A never-constructed request was scored as path loss.
2. **Wildcard `source-address`**: `probeDialer` rejected only
   unparseable sources (`ip == nil`); `net.ParseIP("0.0.0.0")` / `"::"`
   are non-nil unspecified, so the dialer bound the wildcard and
   measured the default uplink instead of the pinned source path —
   defeating #2492's stated intent (its own error text: "would bind
   wildcard source"). `probeICMP` handed the raw string to
   `ListenPacket`, which binds the unspecified address successfully.
   The strict validator `validateRPMSourceAddressStrict` had the same
   parse-only gap, so a wildcard reached runtime on BOTH the strict
   and lenient paths (the issue's open reachability question resolved:
   strict did NOT reject it).
3. **Local source-bind `EADDRNOTAVAIL`** (leg 3, NEEDS_VALIDATION in
   the issue): the decisive check — dial with `LocalAddr` =
   unassigned IP (192.0.2.77), no VRF opts — was run on master:
   `probeTCP` returned `TCP connect failed: dial tcp
   192.0.2.77:0->127.0.0.1:9: bind: cannot assign requested address`
   (not `ErrProbeSetup`, `errors.Is(err, EADDRNOTAVAIL)` = true), and
   `probeHTTP` likewise. The pre-existing `sink.load()` re-tag only
   covers VRF/resolver Control failures; with no VRF opts there is no
   sink, so a configured-but-unassigned source counted as path loss.

## Fix

- `pkg/rpm/rpm.go`:
  - `validateProbeSourceAddress` (new, shared): rejects unparseable
    AND unspecified sources with `ErrProbeSetup`; `probeDialer` uses
    it for tcp-ping/http-get.
  - `canonicalizeHTTPTarget`: every error now wraps `ErrProbeSetup`
    (message text unchanged). The deliberately lenient schemeless
    `url.Parse`-failure pass-through is preserved — it reaches
    `NewRequestWithContext`, whose error is now also wrapped.
  - `probeHTTP`: `NewRequestWithContext` error wraps `ErrProbeSetup`.
  - `isLocalBindSetupError` (new): only `EADDRNOTAVAIL` is re-tagged
    setup in `probeTCP`/`probeHTTP` (after the #5061 sink check).
    Refused / unreachable / timeout — including from a valid assigned
    source — stay path signals, per the "ambiguous errnos default to
    PATH" doctrine. ICMP needs no leg-3 change: its socket-open
    errors already wrap `ErrProbeSetup` wholesale.
- `pkg/rpm/icmp.go`: `probeICMP` calls `validateProbeSourceAddress`
  before opening a socket; wildcard sources hold without a listen.
- `pkg/config/compiler_services.go`: `validateRPMSourceAddressStrict`
  also rejects `IsUnspecified()` (same "invalid IP address" message;
  strict reject / lenient warn wiring unchanged).
- `pkg/rpm/README.md`: setup-hold bullet extended for #14727.

NOT changed: the schemeless-parse leniency contract (#5523 control
`2001:db8::1` still passes through), redirect/drain classification,
the #5061 sink mechanism, `runSingleTestWithOptions`.

## Risk

Behavior delta is classification-only: probes that never left the box
now hold state instead of failing over a WAN. No wire, schema, or
config-format change. One deliberate asymmetry: an `EADDRNOTAVAIL`
caused by an ephemeral-port bind against a *valid* source would also
hold — indistinguishable from an unassigned source at the errno, and
holding is the fail-safe direction (a false failover is worse than a
delayed one). Operator configs already committed with
`source-address 0.0.0.0`/`::` now FAIL strict commit (they were
silently measuring the default path; empty source-address remains
the way to say "default source") and warn on lenient load while the
runtime holds the affected tests.
