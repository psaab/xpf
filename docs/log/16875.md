# #16875: Static/DNAT/SNAT v4-mapped and v4-compatible NAT literals commit clean but can never match

- **Timestamp**: 2026-10-25
- **Action**: `validateNATMappedCompatStrict`
  (`pkg/config/compiler_validate_strict_nat.go`, registered as the
  `natMappedCompat` NAT registry gate, appended last so older
  first-error slots are unchanged, sharing `lenientDestNATAddresses`,
  and mirrored in the #5876 peer-effective SNAT view) now hard-rejects
  a static-NAT match/`then prefix`, destination-NAT match or pool
  address, or source-NAT pool member written as an IPv4-mapped
  (`::ffff:a.b.c.d`) or IPv4-compatible (`::a.b.c.d`) IPv6 literal.
  The shared predicate `natAddrIsV4MappedOrCompat`
  (`pkg/config/compiler_nat_helpers.go`) mirrors
  `ipv6_addr_is_v4_mapped_or_compat`
  (`userspace-dp/src/afxdp/frame/inspect.rs`) octet-for-octet,
  excluding `::` and `::1`. Previously
  `match destination-address ::ffff:203.0.113.5/128 then static-nat
  prefix ::ffff:10.0.0.5/128` (and the compat, DNAT and SNAT-pool
  spellings) committed clean: the helper drops every native IPv6
  frame whose src or dst is mapped/compatible at ingress before NAT
  (#10686/#11669, `v4_mapped_ipv6_dropped`), and an IPv4 packet keys
  `IpAddr::V4` and misses the V6-keyed entry — the published service
  was silently inert, with only the drop counter moving. The gate
  rejects rather than unmaps (proxy-ARP's #8631 choice): rewriting a
  NAT match/target to IPv4 would silently change the rule's family
  and its #13922 cross-family verdict. Strict on commit / commit-check;
  tolerant load / peer-sync warn (#1960 no-brick) — the dataplane
  already fails such rules closed, so a leniently-loaded config boots
  and forwards untranslated exactly as before. The DNAT match site
  also fires at the top of `validateDestinationNATAddressesStrict`
  so a mapped destination reports the never-matching cause instead
  of the downstream family-mismatch it also trips. Exemptions:
  NPTv6 rules and `then static-nat inet` (genuine IPv6 translations /
  the NAT64 keyword, owned by their own gates), address-book names
  and unparseable tokens (existing gates), and `::`/`::1` controls,
  which compile unchanged as do native v4/v6 controls.
