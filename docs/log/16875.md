# #16875: Static/DNAT/SNAT v4-mapped and v4-compatible NAT literals commit clean but a match in that form can never match

- **Timestamp**: 2026-10-25
- **Action**: `validateNATMappedCompatStrict`
  (`pkg/config/compiler_validate_strict_nat.go`, registered as the
  `natMappedCompat` NAT registry gate, appended last so older
  first-error slots are unchanged, sharing `lenientDestNATAddresses`,
  and mirrored in the #5876 peer-effective SNAT view) now hard-rejects
  a static-NAT match source/destination or `then prefix`,
  destination-NAT match source/destination or pool address, or
  source-NAT match or pool member written as an IPv4-mapped
  (`::ffff:a.b.c.d`) or IPv4-compatible (`::a.b.c.d`) IPv6 literal.
  The shared predicate `natAddrIsV4MappedOrCompat`
  (`pkg/config/compiler_nat_helpers.go`) mirrors
  `ipv6_addr_is_v4_mapped_or_compat`
  (`userspace-dp/src/afxdp/frame/inspect.rs`) octet-for-octet,
  excluding only the exact `::` and `::1` identities (compared via
  `netip.IPv6Unspecified`/`IPv6Loopback`, NOT `IsLoopback()` — the
  latter Unmaps and would exempt the whole mapped 127/8 range that
  Rust drops as mapped; review fold on PR #17697). Previously
  `match destination-address ::ffff:203.0.113.5/128 then static-nat
  prefix ::ffff:10.0.0.5/128` (and the compat, DNAT and SNAT-pool
  spellings) committed clean: the helper drops every native IPv6
  frame whose src or dst is mapped/compatible at ingress before NAT
  (#10686/#11669, `v4_mapped_ipv6_dropped`), and an IPv4 packet keys
  `IpAddr::V4` and misses the V6-keyed entry — a mapped MATCH could
  never match, diagnosable only via the drop counter. A mapped
  TARGET/pool identity is not inert either: the SNAT allocator
  allocates it to any native-IPv6 source, but return traffic to it
  is ingress-dropped, so it cannot carry bidirectional forwarding.
  The gate rejects rather than unmaps (proxy-ARP's #8631 choice):
  rewriting a NAT match/target to IPv4 would silently change the
  rule's family and its #13922 cross-family verdict. Strict on
  commit / commit-check; tolerant load / peer-sync warn (#1960
  no-brick) with the pre-gate dataplane disposition unchanged. The
  DNAT match site also fires at the top of
  `validateDestinationNATAddressesStrict` so a mapped destination
  reports the never-matching cause instead of the downstream
  family-mismatch it also trips. Match source-address slots on all
  three NAT kinds are covered (the Rust drop checks SRC or DST, and
  the static source selector is honored as SourceConstraint);
  address-book values cannot smuggle the spelling either —
  `validateAddressBookMappedPrefixesStrict` now rejects compatible
  entries beside mapped ones (see Residual). Exemptions: NPTv6
  rules (their source scope is rejected wholesale by the #5818
  scope gate) and `then static-nat inet` (genuine IPv6 translations
  / the NAT64 keyword, owned by their own gates), unparseable
  tokens (existing gates), and `::`/`::1` controls, which compile
  unchanged as do native v4/v6 controls.

  mapped SNAT-pool configs all committed clean (RED); a second

  unparseable false). Registry census + fail-on-revert cover the

- **Residual**: Address-book entries cannot smuggle the spelling
  past this gate: `validateAddressBookMappedPrefixesStrict` rejects
  mapped book values (#10688) and, as of this change, compatible
  book values too (the mapped-only `Is4In6` check previously let a
  `::a.b.c.d` entry commit and resolve into a NAT name reference or
  a folded static `prefix-name` target — review fold on PR #17697);
  dynamic-address feed values carrying a mapped/compat prefix at
  runtime remain the feed path's existing fail-closed drop,
  unchanged. The lenient builder still ships the pre-gate
  disposition for a persisted config (a mapped match entry installs
  but never matches; a mapped pool member can still be allocated
  outbound with return traffic ingress-dropped) — no new wire
  reason is introduced, matching the #1960 warn-and-load doctrine
  for this class.
