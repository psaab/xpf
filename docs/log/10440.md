# Issue #10440: dialPeer caller cancellation

## Disposition

Fixed. `Server.dialPeer` now accepts the caller context, checks cancellation
before each fabric attempt, and derives each 2-second `GetStatus` liveness
probe timeout from that context. A canceled or deadline-expired caller is
returned as the corresponding gRPC status instead of being retried across the
remaining fabric addresses. All production `dialPeer` callers pass their
request-scoped context, so cancellation now covers the dial/probe portion as
well as the forwarded peer RPC.

## RED-then-GREEN regression evidence

The regression cells drive the real `dialPeer` against an in-process gRPC peer
whose `GetStatus` blocks until its RPC context ends and counts probe entries.
For the RED run, the context checks and caller-derived probe context were
temporarily reverted to the original behavior (`context.Background()` and a
2-second timeout); the source was restored before the GREEN run.

| Cell | RED mutation and observed result | GREEN result |
| --- | --- | --- |
| `TestDialPeerCanceledContextAbortsFast_10440` | **Failed**: the already-canceled caller waited 4.003169549s across two fabric probes and entered the blocked peer twice. | **Passed** in 0.00s; no peer probe was entered. |
| `TestDialPeerDeadlinePropagation_10440` | **Failed**: the 250ms caller deadline waited 2.001365484s for the old probe budget. | **Passed** in 0.25s; the caller deadline bound the probe. |
| `TestDialPeerNormalProbeUnaffected_10440` | **Passed** (control): the healthy peer still connected. | **Passed** in 0.00s; the healthy probe remains functional. |

## Scope

Product changes are limited to `pkg/grpcapi/server_diag.go` and the required
caller context plumbing in `server_diag_monitor.go`,
`server_diag_system_action.go`, `server_sessions.go`, and
`server_show_forwarding.go`. The stale timeout explanation in
`server_show.go`, the existing `peer_probe_busy_8597_test.go` helper, this
regression file, and this evidence log were updated to match the new contract.
No NAT, protobuf, generated-code, or dataplane files were changed.
