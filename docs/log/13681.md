# #13681 — scope PPTP call associations by routing domain

- **Base**: `acb391b70` (origin/master at branch start)
- **Branch**: `fix/13681-campaign`

## Why

PPTP call aliases and control-channel teardown were keyed only by peer addresses and call IDs. Identical calls in separate routing domains could therefore share a handle or have one domain's teardown remove the other's association.

## What

- Include the routing domain in PPTP call identity and stable handle derivation, control-channel identity, and allocator-alias lookup.
- Carry routing-domain context through control capture/drain/close, GRE data resolution, quoted ICMP resolution, and HA association reconstruction.
- Preserve the existing HA call-ID wire encoding; the receiver reconstructs the handle using the session's routing domain.
- Add regressions for same-ID calls across domains, scoped disconnect and channel teardown, pending-control purge isolation, GRE resolution, and quoted ICMP resolution.

## Risk

Association handles change because their stable derivation now includes routing-domain identity. HA peers derive the same handle from the unchanged call-ID pair plus the routing domain already carried by the synced session key. Default-domain wrappers remain for existing domain-0 tests and helpers; packet-path callers pass the resolved domain explicitly.
