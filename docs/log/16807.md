- **Timestamp**: 2026-10-25
  - **Action**: Fix `isPkgInstalled` misreading held kernel packages as
    confirmed-absent (#16807, R3-A56-01). The predicate required the literal
    `install ok installed` from `${Status}`, so a held candidate
    (`hold ok installed` — the candidate is always held) was dropped from
    `PruneInactiveSlot`'s pre-purge set, `apt-get purge` never ran, and the
    sweep deleted package-owned `/boot` + `/lib/modules` payload while dpkg
    still recorded the packages installed. Classification is now by the
    `${db:Status-Status}` word via the new `dpkgStatusWord` helper (the
    selection-word predicate `bake.py` already uses, #1930): `installed`
    plus the partial states `half-installed` / `unpacked` /
    `half-configured` / `triggers-awaited` / `triggers-pending` count as
    possibly-installed in `dpkgStatusInstalled`; `not-installed` /
    `config-files` / unknown count as confirmed-absent. The #5428 tri-state
    contract is preserved through `dpkgStatusWord`: "no packages found
    matching" stays (false, nil), any other query failure still returns an
    error so both prune gates and the `InstallCandidateKernel` reinstall
    check fail safe. Sibling #16812 (same `${db:Status-Status}` predicate
    in `currentLinuxPackages` enumeration, in flight on its own branch)
    was checked for name/symbol collisions — none; the two land
    independently and compose.
