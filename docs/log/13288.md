# Issue #13288: separate S5 reinject completion telemetry outcomes

- **Timestamp**: 2026-10-15
- **Source**: deep-review D4-04, validated under the three-way research gate.
- **Action**: `ReinjectCore::terminalize_with_reason` previously counted successful
  `Accepted`, `WouldReinject`, and `WouldPermit` outcomes, plus `Fenced` and
  `Denied`, as `completed_refused`. Split the counters into permitted, fenced,
  denied, and truly refused outcomes; carry the new fields through the Rust
  status serializer and Go `ProcessStatus`; export the four per-outcome values
  as `xpf_userspace_s5_reinject_completions_total{outcome=...}`. The existing
  written/reinjected metric remains unchanged.
- **Regression**: Rust terminalization regression covers all three permitted
  outcomes, fenced, denied, and refused; Rust status round-trip pins the new
  fields; Go status decode and Prometheus emission tests cover the wire and
  outcome labels.

## RED -> GREEN proof

- **RED**: on pristine `origin/master` (`f59c739af`), the added terminalization
  regression failed to compile because `ReinjectStats` had no distinct
  `completed_permitted`, `completed_fenced`, or `completed_denied` fields.
- **GREEN**: the full `slowpath_reinject_9506::tests` module passed (71 tests);
  the Rust S5 status round-trip passed; the Go S5 metric test and Go status
  decode regression passed; `go test ./pkg/api` passed; `cargo build` succeeded.

- **Full package note**: `go test ./pkg/dataplane/userspace` failed tests
