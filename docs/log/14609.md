# Issue #14609: Flow-export records ride SESSION_CLOSE frames behind the 1000/s dataplane-event limiter

## Why

`SESSION_CLOSE` RT_FLOW frames (type 14) are the sole input to the Go
NetFlow v9 / IPFIX session-close exporters
(`pkg/daemon/daemon_flowexport.go`), and the producer contract states
"flowexport still needs every close"
(`userspace-dp/src/afxdp/session_delta.rs`). Since #2512 those frames
ride the shared per-(kind, zone) GCRA in
`userspace-dp/src/event_stream/producer.rs` at the production default
1000/s + burst 1024. Above ~1000 closes/s from one zone the limiter
sheds the excess as `RateLimited` before the frames ever reach Go, so
flow export is systematically undercounted exactly under load. The Go
1-in-N sampler (`ExportConfig.ShouldExport`) then runs over the
survivors only, while the IPFIX sampler Options record
(`pkg/flowexport/ipfix.go`, RFC 7014 flow-selection IEs) still
advertises 1-in-N of all flows — a collector scaling by N estimates
roughly (survivors/N)*N instead of the true close population. NetFlow
v9 carries no sampler record and is undercounted the same way.
Enforcement (the separate type-2 HA session-sync close delta) is
unaffected.

## What

Give `SessionClose` a separately sized GCRA budget in the Rust
producer instead of exempting it outright, so a flood bound remains:

- `DataplaneEventRateLimitConfig` gains
  `session_close_events_per_second` / `session_close_burst`
  (production default 8192/s + burst 8192 — `CHANNEL_CAPACITY`, the
  session channel's drain capacity). The shared telemetry fields keep
  their 1000/s + 1024 defaults for PolicyDeny / ScreenDrop / FilterLog
  / SessionCreate.
- `DataplaneEventRateLimiter` keeps one fixed bucket array (no new
  allocation); only the SessionClose row reads the new limit via
  `limit_for`. GCRA construction is factored into `runtime_for`.
- The bounded per-kind queue budget is unchanged and remains the flood
  bound above the rate: any queue-full / disconnected shed is still
  counted per kind and surfaced in
  `ProcessStatus.event_stream_session_close_{sent,dropped,rate_limited,queue_full,disconnected}`
  (#10979) and the
  `xpf_userspace_event_stream_producer_frames_total{outcome="session_close_*"}`
  Prometheus series, i.e. in flow-export status. Below channel capacity
  a close is never rate-shed, so the Go sampler and the IPFIX/v9
  sampling metadata run over the true close population and need no
  correction; that invariant is documented in
  `userspace-dp/src/event_stream/README.md`.
- Every existing `DataplaneEventRateLimitConfig` literal (all in
  tests, unlimited `0/0`) gains the two fields as `0/0` (unlimited),
  preserving its intent. The one finite test config
  (`test_emit_session_close_rt_flow_rate_limited_is_counted`) now
  configures the close budget explicitly (shared fields unlimited,
  close 1000/s burst 2) so it still pins counted rate-limiting of
  type-14 frames.
- NOT changed: the Go sampler, IPFIX/v9 encoders, the wire format, and
  the queue-budget sizing. SessionCreate keeps the shared limit (it has
  no flow-export consumer and stays producer-gated).

## Validation

RED on pristine `origin/master` (6c4b26db6 + only the new test):
`cargo test --bin xpf-userspace-dp -- test_session_close_survives_production_rate_14609`
failed with `left: 820, right: 5000` — 820 of 5000 back-to-back closes
from one zone reached the channel under the production limiter (the
820 is the per-kind queue budget ceil((8192/2)/5) interacting with the
1024 GCRA burst; the rate limiter is the binding shed).

GREEN after the fix: the same test passes (5000/5000 delivered,
`session_close.rate_limited == 0`, `queue_full == 0`, batched at 500
with production-style queue-budget release between batches so the
in-flight budget is not the gate). The full `event_stream::` suite and
the producer tests pass, including the adapted counted-rate-limit pin.

Commands (all with `CARGO_TARGET_DIR=/var/worktrees/.cache/cargo-14609`):
`cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp -- test_session_close_survives_production_rate_14609 test_emit_session_close test_emit_session_create dataplane_event_` — 27 passed.
`cargo test --manifest-path userspace-dp/Cargo.toml --bin xpf-userspace-dp -- event_stream::` — see PR body for the total.

## Risk

A sustained close stream above 8192/s per zone can still shed at the
queue budget when the daemon drains slowly; that shed is bounded,
counted, and operator-visible (above), unlike the previous invisible
1000/s rate shed. The close rate ceiling is now the channel drain
capacity rather than an arbitrary telemetry flood number, matching the
HA session-sync path's own bound. No wire, Go, or sampler change.
