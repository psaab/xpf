# #14586 — BGP export policies with `from protocol static|direct` advertise nothing

## Issue

A defined policy-statement in a BGP export chain rendered only the per-peer
`neighbor <X> route-map <policy> out` filter. Nothing redistributed the
static/connected routes the policy's `from protocol` terms selected into
BGP, so a correct Junos config (`protocols bgp export EXP` with
`from protocol static|direct`) established sessions that advertised nothing
(`PfxSnt 0`). The `<policy>-<proto>-xpf-redist` maps were rendered and
referenced by nothing. Junos has no separate redistribution step: the BGP
export policy is what originates those routes.

## Fix

- `pkg/frr/redistribute.go`: `bgpExportPolicies14586` collects the union of
  defined policies in the effective export chains of a BGP instance
  (global default plus every neighbor's most-specific chain; import chains
  never originate; the global chain counts when there are no neighbors).
  `bgpPolicyRedistEntries14586` / `bgpPolicyIPv6RedistEntries14586` return
  the filtered per-source entries at the `bgp` / `bgp-ipv6` nodes via the
  existing `redistributeEntriesAt` (self `bgp` dropped, off-family dropped,
  no-`from protocol` terms expand over the node-fitting domain, #14380).
  `redistReferencedNodes14380` now also records `(bgp,bgp)` and
  `(bgp,bgp-ipv6)` for those policies so their per-source maps (including a
  no-from policy's expanded set) are defined and join the `ApplyFull`
  collision belt at both nodes.
- `pkg/frr/protocols_render.go`: for each such policy, emit
  `redistribute <proto> route-map <policy>-<proto>-xpf-redist` per family
  (IPv4 at router level, IPv6 under `address-family ipv6 unicast`),
  de-duplicated and never unfiltered; the per-peer `route-map out` remains
  the per-peer gate. Bare protocol tokens keep the existing unfiltered
  global redistribute path unchanged. This is not the #2473 leak: the old
  bug was an *unfiltered* `redistribute ospf`; origination here is gated
  by the fail-closed per-source map (#12065).
- `pkg/frr/README.md`: documents the origination half of the #2473 split.
- Pinned tests updated (they encoded the bug): `TestGenerateProtocols_BGPExportNoLeak`
  now pins only the unfiltered form; `TestGenerateProtocols_BGPExportRouteMap`
  and `TestGenerateProtocols_BGPExportPrefixOnly` now assert the filtered
  origination lines (a no-from policy originates the whole non-self domain).
  `TestRedistEntriesAtNodesAreCovered_9667` census extended to prove the
  two new BGP wrapper nodes.

## Regression tests

`pkg/frr/bgp_export_redistribute_14586_test.go` (through `buildManagedSection`):
acceptance fixture (EXP with static+direct terms gated by prefix-lists:
exact redistributed sets per family, no unfiltered line, per-source maps

export origination with most-specific per-peer filters, BGP-only source

## Risk

- Operator-visible delta: BGP export policies now originate the routes
  they select (Junos contract) instead of silently advertising nothing.
  Advertisement remains double-gated (redistribute map + per-peer
  route-map out); no unfiltered redistribution is introduced.
- Origination follows the union of effective chains because FRR
  redistribution is router-global; a policy exported by only one peer
  originates once and is still filtered per-peer on advertisement.
- Residual: none known. Interaction with #14584 (`no bgp ebgp-requires-policy`,
  merged on current master) is complementary: originated routes still need
  that opt-out to leave a policy-less eBGP peer, which master now emits.
