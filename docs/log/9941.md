# 9941 — an unzoned tunnel's decap re-ingress took the zone-0 host-inbound admit

- **Timestamp**: 2026-09-12T10:05Z
- **Action**: treat an unzoned TUNNEL as a host-inbound exposure even when it is
  unnumbered, so its decap re-ingress is denied instead of admitted.
- **File(s)**: `userspace-dp/src/afxdp/forwarding_build/interfaces.rs`,
  `userspace-dp/src/afxdp/forwarding/host_inbound.rs` (test module),
  `userspace-dp/src/afxdp/forwarding/unzoned_tunnel_host_inbound_9941_tests.rs`,
  `docs/junos-cli-reference.md`, `docs/log/9941.md`.

## Reachability, settled before any code changed

The issue's first acceptance item was to enumerate which tunnel kinds reach
`logical_ingress` with a logical ifindex absent from `ifindex_to_zone_id`. The
full chain is on the issue; the load-bearing links:

- **GRE and WireGuard**, not IPsec. `build_logical_ingress_packet` has exactly two
  production callers (`gre.rs`, `wg/decap.rs`); IPsec is named as intent in a
  comment with no call site.
- An unzoned, UNNUMBERED tunnel is still published as an endpoint — measured by
  driving `buildTunnelEndpointSnapshots` with such a unit; it emits an endpoint
  with `zone=""` for both kinds.
- `ifindex_to_zone_id` never receives it (insert gated on `row_zone_id != 0`), so
  `logical_ingress` resolves zone **0**, and `host_inbound_admits` takes the
  `None => true` global admit arm.
- The #5659 backstop did not cover it: its scope guard is `registered_local`.

The strongest refutation available was NOT the "zone 0 is a deny sentinel" one
the report tested. It was the #5659 comment's own claim that reachability is
"bind-gated (`buildUserspaceBindNetdevs` skips a zoneless interface) ... not a
live bypass". That function **does not exist anywhere in the tree**, and a
working bind-gate would not cover this path anyway: decap is a poll STAGE on the
UNDERLAY's bound netdev, and the tunnel's logical ifindex is synthesized after
it — it never needs a binding of its own.

## The fix

`registered_local` is a sound exposure predicate for an ordinary interface and
false for a tunnel. A decapped inner packet is delivered to a local address that
some OTHER interface registered, so a tunnel is an exposure without ever being
addressed. The #5659 sentinel's guard becomes `(registered_local || iface.tunnel)`.

Scope kept deliberately narrow: the sentinel is still skipped for a lifeline and
still skipped when an explicit per-interface override exists, the global
ICMP/ND/PMTUD accepts still precede it, and transit through the tunnel is
untouched — this gates local delivery only. Denying host-inbound on an unzoned
tunnel is also what the compiler already tells operators to expect: *"An UNZONED
tunnel is not safer"* (`compiler_ipsec_plaintext_warn.go:213`).

## Evidence

- **Reproduced on unmodified master**, using the project's own `native_gre_snapshot`
  fixture with the tunnel unzoned and un-addressed: SSH (tcp/22) to a
  firewall-local address was ADMITTED. That cell is the mutation row — reverting
  the guard restores the admit.
- The positive control in the same run: a ZONED tunnel keeps its zone id and gets
  NO interface-keyed sentinel, so its zone still decides.
- A second control inside the failing cell: ICMP destination-unreachable stays
  admitted, so the fix cannot have passed by denying everything.
- Full Rust suite after the fix: **5809 passed, 0 failed**.

## Docs

`docs/junos-cli-reference.md` said #5659 covers "an ADDRESSED interface with an
empty zone". That now understates the coverage, and a maintainer reading it could
restore the narrow guard; it states the tunnel case explicitly.
