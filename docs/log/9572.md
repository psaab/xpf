# #9572 — host-inbound: a #5575-poisoned junos-host permit no longer erases the following deny from the kernel program

- **Timestamp**: 2026-09-10
  - **Action**: Fixed the kernel host-inbound projection so a lenient-poisoned
    PERMIT contributes no subtraction.
    - `junosHostProjectTerm` marks a `to-zone junos-host` permit that carries
      `LenientContentDropped` (`lenientDropped`), BEFORE any dimension is
      resolved.
    - `junosHostProjectProgram` skips such a permit.
    - Before the fix, the tolerant compile left the dropped dimension empty and
      every resolver read it as `any`. An omitted or valueless `application`
      became an application-any permit. An omitted or valueless
      `source-address` became a permit for every source, or, with a narrow
      application, the cross-dimension poison that empties the zone. Either way
      the following deny was erased from the program the daemon installs, even
      though the helper refused the same config.
    - A poisoned DENY is unchanged: its empty dimension widens a DROP, which is
      the fail-closed direction.
  - **Action**: docs/host-inbound-service-matrix.md records that the #6705 and
    #7477 "unreachable" finding covered the strict commit only, and that the
    tolerant channel reached the vector until this change.
  - **Action**: New cells.
    - pkg/config/junos_host_poisoned_permit_9572_test.go. Six poisoned p0
      spellings. Each proves that strict rejects the config and that lenient
      flags p0, then asserts p1's DROP content in BOTH families: one rule,
      every source, no subtraction, exactly tcp dport 22. The controls:
      - S2-CTRL: an authored permit-all still shadows p1, strict and lenient
        alike.
      - An authored NET9 permit is still subtracted from p1.
      - The middle row: S2-CTRL's content with only the flag set, which stops
        shadowing.
      - A poisoned deny still drops, pinning the scope.
      - A poisoned scheduler-gated permit does not make the program
        un-representable, pinning "skipped before resolution".
    - pkg/daemon/host_inbound_junos_host_poisoned_permit_9572_test.go. The
      installed nft payload (BuildJunosHostPrograms, then
      buildHostInboundFilterPayload) carries p1's drop line when p0 is flagged,
      and does not when p0 is an authored permit-all. Only the flag differs
      between the two rows.
