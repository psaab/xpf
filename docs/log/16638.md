# Issue #16638: login-class subsystem tokens widen to full view — contract and advisory corrected

- **Timestamp**: 2026-10-25
- **Action**: Subsystem-read Junos tokens (`network`, `trace`, `snmp`,
  `interface`, `rollback`, and every other non-whole-box token) are granted
  xpf's full `PermView` bucket, which admits the whole non-secret
  configuration render and the live session table (`ShowConfig` ACTIVE,
  `GetSessions`, other view-priced reads on CLI/gRPC/REST). The operator
  contract nevertheless claimed the mapping "never grants more than the
  Junos token permits" and described the mapping as folding "down"; the
  commit advisory said "folded to view-only". The behaviour is deliberate
  (pinned by test 4304) and unchanged; the claims are corrected:
  - `pkg/config/types_system_login.go`: `mapJunosPermissions` doc and arms
    now state the read-axis widening and bound it (no secret, configure,
    control, clear or maintenance grant follows); the second return value
    is renamed `foldedToView` → `widenedToView` and now also includes
    `rollback`. The write-axis no-escalation invariant (#4311: `reset` →
    control never maintenance, `rollback` → view never configure) is kept
    verbatim in substance.
  - `pkg/config/compiler_system.go`: the commit advisory now reads
    "permissions [<tokens>] granted full view (wider than Junos <tokens>):
    view admits the whole non-secret configuration and session table; xpf
    has no finer read bucket, and no secret/configure/control/maintenance
    grant follows".
  - `docs/system-login.md`, `docs/config-schema.md`: the contract now says
    no write-axis escalation with deliberate read-axis widening, names the
    surfaces and the migrated-NOC example, and drops "never grants more"
    and "folds down".
  - `pkg/config/login_permission_flags_9490.go`: validator error and
    comment no longer say an unrecognised token "folds to view-only".
  - Optional strict-mode rejection of widening tokens was NOT added: the
    widening is the deliberate coarse-model trade, the corrected advisory
    now discloses it at commit, and a new opt-in would be a behaviour
    change beyond this contract fix.
