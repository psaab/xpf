# #14446 — Single-family filter + wrong-family-only prefix-list (DR19-H2)

## Defect
`validateFirewallFilterFamilyAnyMatchesAST` (#4426) skipped every
non-`any` filter (`if af != "any" { continue }`), so a `family inet6`
filter whose term references a v4-only prefix-list (positive or
`except`, source or destination — and the `inet`+v6-only mirror) was
never examined. The Rust compiler `parse_term_addresses` silently
partitioned the resolved addresses by family; the matcher then read
only the filter family's vec: constrained + empty family vec returns
`except` — positive matches NOTHING (a `then discard` term is dead,
traffic falls through to implicit accept) and `except` matches
EVERYTHING (fail-open over-accept). The literal wrong-family variant
reaches the same partitioned vecs on the tolerant path.

## Fix
- Go (`pkg/config/compiler_firewall.go`): the #4426 gate now runs its
  prefix-list coverage accumulation + verdict for `af` in
  {any, inet, inet6}. The #4296 per-token walk stays `any`-only (a
  single-family filter legitimately carries family-specific matches).
  Single-family mismatch predicate: `inet` rejects iff v6-only,
  `inet6` rejects iff v4-only; mixed and empty pass. Strict = error,
  lenient = warning, naming family/filter/term/list.
- Rust (`userspace-dp/src/filter/compiler.rs`,
  `policy_snapshot_error.rs`): new
  `preflight_term_cross_family_addresses` called in `parse_term` after
  `parse_term_addresses`; rejects the whole snapshot with
  `SnapshotIntegrityError::CrossFamilyFilterAddressScope { family,
  filter, term, direction }` when a constrained direction has zero
  prefixes of the filter family and non-zero of the other. Covers
  prefix-list and literal scopes (same snapshot vecs). Both-vecs-empty
  (#2400/#2506 empty-set), unconstrained, matched, and mixed pass;
  `any`/unknown families skip (Go owns `family any`).

NOT changed: `nets_match_*` empty-set semantics, the pinned
`TestFirewallFilterSingleFamilyPrefixListNotFlagged` (matched families),
and the `family any` verdict/messages.
