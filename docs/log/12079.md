# #12079 — Distinguish zone-matrix pair identities

## Why

`wire-zone-matrix.sh` used the same control application in each of the six ordered-pair policies. A bijective re-attribution of interfaces to other existing zones therefore left every wire verdict unchanged. The RED fixture reproduced this: before the fix, the zone-swap assertion received `WIRE_GATE wire_zone_matrix PASS` (`cells_failed=0`) and the selftest exited 1 with `14 passed, 1 failed`.

## What

- Give each ordered pair its own UDP control application/set and destination port (default 55100–55105). The permit arm continues to change only the global default policy.
- In each deny cell's main capture window, send the probe and all six pair-specific controls.
  Derive the identity mask only from that window: a nonzero mask must equal the expected
  pair bit; foreign bits fail; a blind zero mask remains VOID. This prevents a second
  diagnostic window from supplying control evidence for an unobserved probe.
- The verdict validates identity-mask shape and consistency with expected-control observations. `zone_cell_violations` counts distinct cells and `zone_violation_mask` identifies them in canonical 12-key order.
- Extend `--selftest` with a trust↔dmz binding-swap fixture. Pair indices map `[0..5] -> [5,4,3,2,1,0]`; all six deny-arm rows change identity, while permit-all cannot expose the matched policy. Thus the exact failure set is deny-cell mask `0x03f` (decimal 63), not the six permit cells.
- The `--fixture` transcript now carries the observed-control mask after each cell key.

## Risk / residual

The observed-control mask changes the `--fixture` cell record shape; fixtures must include the numeric mask field. The swapped-live-run still needs an Incus DUT and remains the PR's live proof; it was intentionally not run in this lane.
