# #14981 - deny-configuration applies to groups/apply-groups expansion in Set, Load, and Commit (D35-03)

- **Timestamp**: 2026-10-18
- **Action**: `AuthorizeConfigMutation` adjudicated only literal `groups …` / `apply-groups …` spellings, so a denied leaf planted in a group body and pulled in by `apply-groups` (including `<*>` wildcard, nested, and `${node}` groups) took effect at commit unchecked on gRPC, REST, and the on-box CLI; Commit's "already adjudicated when written" premise never covered inherited paths. Added one shared mechanism in `pkg/config` (`AuthorizeExpandedTree` / `ExpandedMutationLines` / `authorizeConfigLoadExpansion14981`): expand the candidate (or the parsed load body) with groups resolved, and adjudicate every effective set line, failing closed on expansion errors. Wired it at gRPC `Set` (candidate-after-mutation), `Load` (via `AuthorizeConfigLoad`), and `Commit`/`CommitConfirmed` (whole candidate); REST `set`/`load`/`commit`/`commit-confirmed`; and the on-box CLI config dispatch plus `handleCommit`. `CommitCheck`/`commit check` stay ungated (compile-only, write nothing). Added `configstore.CandidateTree()` (deep copy) for the gates.
- **File(s)**: `pkg/config/authz_config_groups_14981.go`, `pkg/config/authz_config_load_9892.go`, `pkg/config/authz_config_mutation_9154.go`, `pkg/configstore/store_gen.go`, `pkg/grpcapi/authz_config_regex_9154.go`, `pkg/api/authz_config_regex_9154.go`, `pkg/api/authz.go`, `pkg/cli/permissions_config_regex.go`, `pkg/cli/cli_dispatch.go`, `pkg/cli/cli_config.go`; tests `pkg/config/authz_config_groups_14981_test.go`, `pkg/grpcapi/authz_config_groups_14981_test.go`, `pkg/api/authz_config_groups_14981_test.go`, `pkg/cli/authz_config_groups_14981_test.go`; `docs/system-login.md`.
- **Validation**: New `14981` cells RED on the pre-fix mechanism (literal gates allow the group-carried denied leaf; probe on base showed `set apply-groups G -> nil` and the hierarchical load rendering only `groups …` lines), GREEN post-fix across `pkg/config`, `pkg/grpcapi`, `pkg/api`, `pkg/cli`; allowed-group and unrestricted controls stay green.
- **Risk**: Restricted classes lose the ability to commit a candidate whose group expansion touches a denied path even when a different class staged it — that is the intended fail-closed semantics (the committing class is the authority being exercised). Expansion runs the existing bounded group expander twice more per gated commit on restricted classes only; unrestricted classes short-circuit before any expansion.
