# Issue #10426: preempt dual-active winner GARP

## Disposition

Fixed the preempt election arm so a node that is already primary and wins a
dual-active resolution returns the existing `Dual-active: winner stays` reason.
`runElection` uses that reason to emit `ClusterEvent{DualActiveWin: true}`, which
drives the daemon's direct-VIP GARP/NA refresh. Both higher-effective-priority
and lower-node-ID tie winners are covered. A losing node still yields through
the ordinary primary-to-secondary transition, and non-preempt election remains
on its existing reaffirm path.

## RED-then-GREEN regression evidence

The RED probes were run before the fix. The GREEN probes were rerun after the
fix commit `137612d5c`.

| Cell | RED result before fix | GREEN result after fix |
| --- | --- | --- |
| `TestElection_PreemptDualActive_WinnerEmitsReaffirm` | **failed**: no `DualActiveWin` event was emitted for a preempt-enabled higher-priority winner | **passed**: winner stayed primary and emitted the primary-to-primary reaffirm event |
| `TestElection_PreemptDualActive_TieWinnerEmitsReaffirm` | **failed**: no `DualActiveWin` event was emitted for the lower-node-ID tie winner | **passed**: tie winner emitted the reaffirm event |
| `TestElection_PreemptDualActive_ElectRGReason` | **failed**: `electRG` returned `(electNoChange, "")` instead of the reaffirm reason | **passed**: `electRG` returned `(electNoChange, "Dual-active: winner stays")` |
| `TestElection_PreemptDualActive_LoserYieldsWithoutReaffirm` | **passed** control: lower-priority preempt loser transitioned primary-to-secondary without `DualActiveWin` | **passed**: loser transition and no-reaffirm behavior unchanged |
| `TestElection_PreemptIncumbent_NoReaffirmWhenPeerNotPrimary` | **passed** control: incumbent with a non-primary peer emitted no event | **passed**: non-dual-active incumbent behavior unchanged |
| `TestElection_NonPreemptDualActive_WinnerControl` | **passed** control: preempt-disabled winner stayed primary on the existing non-preempt path | **passed**: preempt-disabled winner still emitted `DualActiveWin` |
| `TestHandleClusterEventPreemptDualActiveWinSchedulesDirectAnnounce` | daemon mapping control: the existing `DualActiveWin` branch is the announce edge | **passed**: direct-mode event scheduled the zero-delay GARP/NA sender for RG 0 |

## Scope

Production change is limited to `pkg/cluster/election.go`. Regression coverage
is in `pkg/cluster/election_preempt_dualactive_10426_test.go` plus the authorized
new daemon-side event-to-announce test
`pkg/daemon/dual_active_win_10426_test.go`. The evidence log is the required
issue record. No config or userspace dataplane files were changed.
