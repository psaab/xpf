# #12810: compile brace-elided sampling instance tails

## Why

`forwarding-options { sampling { instance i2 input rate 100; } }` is a
valid hierarchical spelling, but the parser stores the complete packed tail
on the `instance` node's `Keys`. `compileSampling` obtains the instance
through `namedInstances`, then reads only child nodes for `input` and
`family`. It therefore installs an empty `i2` with `InputRate == 0` and no
family. In a later repeated `sampling` container, that empty instance
replaces the earlier compiled instance of the same name, matching the
compiler's author-order last-wins behavior (#12595).

## Decision

Compile the spelling to the same effective instance as its braced twin;
strict rejection is not appropriate for a valid configuration that the
compiler should support. This follows two existing decisions:

- #12596 admits brace-elided interface `sampling input` / `output` after
  proving the braced forms compile and the compact forms silently drop them.
- #8690 family 3 admits the measured `(sampling, instance)` compact fold
  and forwarding-options packed pairs including `(input, rate)` and
  `(output, flow-server)`, based on empty-equivalence measurements.

The missing normalization links are bounded: allow the instance packed tail
to split on schema-defined statement boundaries, fold `(instance, input)`
and `(instance, family)`, and fold `(inet, output)` / `(inet6, output)`.
Existing deeper `(input, rate)`, `(output, flow-server)`, and related
admissions then handle the nested tails. Preserve author order and current
last-instance-wins semantics.

## RED evidence

Before the fix, the new table-driven test failed: a single elided instance
and an elided tail after a braced sibling both compiled rate 0 instead of
100; elided inet inline-jflow and inet6 flow-server families were absent;
a multi-statement input+family tail lost both; fully elided
`forwarding-options sampling instance` yielded rate 0; and an elided later
instance in a repeated sampling container clobbered the earlier configured
rate with 0. Braced controls and explicit rate-zero controls passed.

## Scope and risk

No compiler readers or wire/runtime behavior changed. The schema-guided fold
only materializes children already declared beneath the sampling instance;
existing `compileSampling` then reads those same fields as it does in braced
form. Existing `packedStatements` is opt-in and uses schema consumption
boundaries, so unknown or ambiguous packed tails are not guessed apart.
Author ordering, map replacement behavior, and explicit `rate 0` remain
unchanged.
