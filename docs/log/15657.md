# Issue #15657 — rollback-compare surface (V45-03, V47-02, V48-02)

Three members of the deep-review rollback-compare cohort, one surface:
the operational/local/remote rollback compare and the display-format
handling of rollback/config shows.

## Defects (as filed)

- **V45-03** — operational `show system rollback compare <N>` required
  configuration mode and diffed against the shared candidate instead of
  active, and `rollback 0` was rejected on compare/show surfaces
  (`ShowCompareRollback*` gated on `s.candidate != nil`, `rollbackEntry`
  computed `history.Get(n-1)`).
- **V47-02** — local CLI `show system rollback <N> | compare` always
  failed: the `case rbPiped:` unknown-pipe arm preceded `case isCompare:`
  in `handleShowSystem`, and `authorizablePipe("compare")` was false so
  regex-restricted classes were refused at the gate; stray pre-pipe
  tokens were silently ignored.
- **V48-02** — `| display xml|json|inheritance` and subtree paths were
  dropped: local CLI rollback rejected non-`set` formats, gRPC
  `ShowRollback` branched only on `SET`, remote CLI rejected
  non-`set` and pre-pipe paths, REST `/config/show` had no `path`,
  `inheritance` silently rendered hierarchical text, unknown `format=`
  was not rejected, and `restShowFormat` dropped `inheritance`.

## Fix

- **Store** (`pkg/configstore`): `rollbackTree(n)` resolves `n == 0` to
  `s.active`; all show/compare paths use it. New
  `ShowCompareRollbackActive{,Redacted}{,AtPath}` diff rollback-vs-active
  with no candidate requirement; new rollback renderers for
  JSON/XML/inheritance and `*Path` variants (cleartext + redacted).
  Candidate-baseline `ShowCompareRollback{,Redacted}` unchanged except
  `n == 0` now means candidate-vs-active.
- **Authorization consequence (deliberate)**: the operational compare no
  longer reads the candidate, so the candidate-read prices built for
  #10094/#9889 no longer apply to it — local `requiredPermission` drops
  the PermConfig arm, gRPC `configTargetReadPermission` admits
  `ActiveBaseline` at PermView, and the #14707 CLI gate adjudicates the
  operational compare as a rollback (committed) read. Config-mode
  `show | compare rollback <N>` and gRPC/REST candidate compares keep
  their PermConfig pricing. The #10094 tests were rewritten to pin
  "served, canary never rendered" instead of "denied".
- **Local CLI**: `| compare` evaluated before unknown-pipe; bare
  `compare` retained; stray pre-pipe tokens are a syntax error except as
  a display-format subtree path; all display formats honoured with path;
  `authorizablePipe` accepts `compare`.
- **gRPC**: `ShowRollbackRequest.path` added (proto field 3, additive);
  `ShowCompareRequest.active_baseline` added (field 3); `ShowRollback`
  honours all formats + path and accepts `n == 0`; negative still
  rejected. Generated code regenerated with `make proto`.
- **Remote CLI**: operational compare sends `ActiveBaseline: true`,
  selectors accept 0, all display formats + path forwarded.
- **REST**: `/config/show` and `/config/show-rollback` honour
  `format=text|set|json|xml|inheritance` (unknown → 400) and `?path=`;
  `n=0` renders active; authorizeRESTConfigRead prices `?path=` via
  `AuthorizeConfigShowPath`; `restShowFormat` maps `inheritance`.

Superseded pins updated in place: #4556 zero-rejection tests (gRPC +
REST) now assert n=0 renders active and only negatives are refused;
#13202 remote-CLI test now asserts json/xml/inheritance are forwarded.

## Risk

- Behaviour delta: operational rollback compare is now served to
  view-only classes (committed content only). Any deployment that
  relied on the PermConfig price to hide rollback-vs-active diffs from
  view classes should note the Junos-parity semantics: the diff is
  against committed configuration, like `show system rollback <N>`.
- Proto fields are additive only; older clients are unaffected.
- REST `/config/show` with an unknown `format=` now returns 400 where
  it previously returned hierarchical text with 200.
