# #17784: preserve undeclared-RG0 IPsec re-initiation on data-RG edges

- **Timestamp**: 2026-10-28
- **Action**: The data-edge exception admits an unanchored RG0 candidate only
  when RG0 is absent and exactly one data RG exists in a single current
  cluster-config snapshot, the transitioning edge matches that sole RG ID,
  and the peer's last heartbeat has no RG0 entry. `PeerGroupPrimary(0)` supplies
  the peer signal: entry presence means the peer reports RG0 (including when
  secondary); a primary entry also identifies peer ownership. This fences
  local config-sync lag while `ownsIPsecConn` remains the local ownership
  authority. A stale edge for a removed RG cannot admit the fallback. Declared
  RG0 stays on the RG0 edge, multi-data-RG configurations cannot fan the name
  across a takeover wave, and spanning names remain excluded. Corrected
  comments and the collision warning to state that multi-RG names rely on
  strongSwan trap/traffic or manual re-initiation. Added RG1-only, peer-state,
  declared-RG0, stale-edge, and multi-RG regression coverage.
