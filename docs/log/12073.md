# Issue #12073 — defer policy-session invalidation until snapshot landing

## Why

A failed `ApplyConfig` leaves the old policy snapshot active, and `SnapshotPublishDeferred` leaves the replacement pending. Clearing policy sessions at commit return in either case drops sessions while their authorizing policy is still live; consuming the capture also leaves no invalidation for the eventual retry or deferred landing.

## What

The daemon now retains the `(old, new)` config pair and its pre-publication session candidates as invalidation debt until the corresponding full policy snapshot lands. Superseding commits merge outstanding debt, bare background retries adopt it, and commit, HA-sync, and rollback clear paths run only after a real publish. A successful retry discharges the debt even if a best-effort apply tail reports an error; applied-config markers remain gated on full publish/convergence.

For status-loop publication of a deferred userspace snapshot, the daemon refreshes candidates immediately before publish, outside `Manager.mu`, and updates retained rename metadata with the refreshed decision. A distinct full-snapshot completion callback queues the one-shot discharge asynchronously; FIB-only generation bumps do not trigger it. The deferred-MAC re-apply also refreshes candidates when it is the first publish to land.

## Review #12301 fold

### Why

The prior invalidation-debt path could discard an enforced snapshot's tail error as an ordinary apply failure, let a superseded generation discharge debt, clear debt after partial deletion, and miss completion/applied-marker updates on asynchronous or content-equivalent publication.

### What

- The daemon recognizes a published-snapshot tail error as landed, preserves its `ApplyResult`, runs invalidation, and still returns the error to the operator.
- A superseding target no longer inherits the previous target's publish generation. Partial deletion errors retain debt for the existing status-loop completion retry.
- Successful asynchronous discharge stamps the saved applied digest. Userspace notifies the policy completion callback when a content-equivalent snapshot settles; callback work remains serialized/coalesced.

### Validation

- **RED before:** All five required probes failed before their behavioral fixes: tail-error landing, stale-generation discharge, partial-error debt retention, asynchronous marker stamping, and content-equivalent settle notification.
- **GREEN after:** Targeted daemon debt tests, userspace debt tests, and `TestPublishedTailFailureReturnsAndRecordsEnforcedApply11080` passed. `go test ./pkg/daemon -count=1` passed; `go build ./...` passed; `gofmt -l` on changed Go files returned no files.
- The full userspace suite reported the three behavioral failures listed above; the exact clean-base comparison reproduced each. No live-cluster mutation was performed.

### Scope

The MINOR “no terminal release valve” is intentionally not implemented. Agreed to keep it outside this fold's scope.
