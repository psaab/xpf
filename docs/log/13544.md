# Session-sync stats report preferred fabric incarnation (#13544)

- **Issue**: #13544 — `Stats`, `ActiveFabric`, and `FormatStats` reported the
  first occupied slot rather than the connection preferred for sync traffic.
  A stale fab0 beside a current fab1 therefore misreported the active fabric.
- **Cause**: the reporting accessors independently checked slot occupancy,
  while outbound traffic selection uses `preferredFabricLocked` to prefer a
  connection from the current peer incarnation.
- **Change** (`pkg/cluster/sync.go`): use `preferredFabricLocked` in the Stats
  snapshot and `ActiveFabric`; `FormatStats` uses `ActiveFabric` and thus
  reports the same preferred fabric. No connection selection or traffic
  behavior changed. Added `pkg/cluster/active_fabric_preferred_13544_test.go`
  covering a stale fab0/current fab1, current fab0, both-current fallback,
  stale-only fallback, a single fabric, and disconnection across all three
  report paths.
- **RED evidence** (pristine `origin/master` `d7fe769aa`):
  `go test ./pkg/cluster -run '^TestActiveFabricReportsPreferredIncarnation13544$' -count=1`
  failed as expected: `ActiveFabric()` and `Stats().ActiveFabric` returned 0
  rather than 1, and `FormatStats()` did not report fab1 in the stale-fab0 /
  current-fab1 case.
- **GREEN evidence**: `go test ./pkg/cluster -count=1` passed
  (`ok .../pkg/cluster 129.592s`); `go vet ./pkg/cluster` passed. Both used
  `GOCACHE=/var/worktrees/.cache/go-build` and
  `GOTMPDIR=/var/worktrees/.cache/go-tmp`. `gofmt` completed for the new
  regression test; the pre-existing sync.go constant alignment was preserved
  rather than including unrelated formatting changes.
- **Risk**: none beyond correcting the diagnostic fabric value to match the
  already-existing outbound connection preference.
