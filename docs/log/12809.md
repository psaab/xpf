## The capture design (now encoded in the gate)

Client `cluster-userspace-host` (10.0.61.102) → firewall → `xpf-mouse-target`
(172.16.80.201). The cell commits the non-zone rule-set
(`from zone lan`, **`to interface reth0.80`**, `then source-nat interface`,
probe rule scoped to the client /32) and DELETES the standing zone-scoped
catch-all (`rule snat` under `lan-to-wan`) so the non-zone rule-set is the
SOLE registrar of reth0.80's 172.16.80.8 — otherwise the zone row registers
the address regardless and the capture proves nothing. A static route
(198.18.128.0/24 → 172.16.80.201) plus a forwarding dummy leg on the
target (MTU 1200) make the target's kernel GENUINELY generate frag-needed
for the SNAT'ed oversized DF echo (IP 1400), addressed to the NAT address.
The client-side capture must then show the error arriving dst 10.0.61.102
with the embedded quote reading `10.0.61.102 > 198.18.128.1` — outer AND
embedded reverse translation. The target-side capture provides the
attribution legs (SNAT'ed echo observed; genuine generation observed);
a normal-size echo through the same rule-set is the control. Every leg
verified present + delivery absent = the #12085 regression signature
(FAIL, not VOID).

tcpdump print formats for all scored regexes were validated against
tcpdump 4.99.6 `-nn -tt -vv` output (outer and embedded `src > dst` lines
are both 4-space indented under `-vv`; the address pairs, not the
indentation, carry the discrimination).
