# #17747: userspace-dp bounds PTB-advertised MTU to local egress budget

- **Timestamp**: 2026-10-28
- **Action**: Capped each validated WG outer PTB advertisement to the
  selected peer endpoint's local physical egress MTU and static route MTU
  before storing it. The protocol-family floor is applied after the cap,
  preserving 1280 for IPv6 and 68 for IPv4 even when the local MTU is below
  that floor. Shrink-only updates, aging refresh, PTB quote validation,
  `pmtu_learned` accounting, and normal LocalDelivery of the PTB are
  unchanged. The offer path uses the same route-derived egress and fallback
  used by encap/MTU consumers.
- **File(s)**: `userspace-dp/src/afxdp/wg/pmtu.rs` (capped/floored offer
  decision), `userspace-dp/src/afxdp/wg/peer.rs` (thread the local ceiling to
  per-peer state), `userspace-dp/src/afxdp/wg/engine.rs` (offer API),
  `userspace-dp/src/afxdp/frame/wg.rs` (derive the local physical/route MTU
  for the validated quote), `userspace-dp/src/afxdp/frame/wg_tests.rs`
  (IPv4/IPv6 end-to-end and offer-rule regressions), and
  `docs/log/17747.md` (this file).
- **Validation**: RED before the fix:
  `wg_pmtu_ptb_clamps_to_local_egress_budget_17747` failed with stored
  `Some(9000)` instead of the expected local ceiling `Some(1500)` on a
  validated IPv6 PTB. GREEN after the fix: all 42 exact tests in
  `afxdp::frame::wg::tests` passed, including valid 1400-byte PTB learning,
  oversized IPv4/IPv6 offers, a 1400-byte static-route ceiling below a
  1500-byte interface MTU, forged-quote rejection, shrink-only, floor,
  aging, and unrelated WG frame/encap controls. Tests were run as named
  Cargo tests with `--exact`; no workspace suite was run.
- **Risk**: A validated PTB remains capable of lowering a peer's learned
  budget (bounded by the existing family floor and quote validation). The
  learned value can no longer exceed the current local interface/route
  budget; the PTB's admission/delivery gates are unchanged.
