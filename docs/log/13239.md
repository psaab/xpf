# #13239 — remove dead NFQUEUE fragment-reassembly state

## Finding

The D5-11 source finding showed that `consumeFrames` rejects malformed fragment
metadata and terminally handles every fragment before calling
`enqueueFlowLocked`. The fragment reassembly branch there was unreachable, and
`Poll` still acquired pipeline and pool locks every millisecond to expire state
that could never be populated. Unused pipeline config, frame state, methods,
and seven never-incremented counters also obscured the actual fail-closed
fragment policy.

## Change

Removed the unreachable reassembly branch and its pipeline-owned pool, hold
maps, deadline, and expiration sweep. Removed unused pipeline config and frame
fields, the dead refusal/disposal helpers, the unused address-format helper,
and permanently-zero counters. Fragment metadata validation, fragment-deny
tombstones, fail-closed DROP verdicts, and `FragmentDrops` accounting remain
unchanged. The standalone `FragPool` remains available to its direct callers.

## Risk

Removing unused exported config/stat fields is a source-compatibility change for
external Go callers that referenced dead fields. No wire or operator-visible
behavior change is intended; fragments remain fail-closed.
