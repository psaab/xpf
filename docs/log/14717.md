# Local CLI annotate authorization-to-execution desync (#14717)

## Why

The local CLI `annotate` arm and the `deny-configuration` /
`allow-configuration` gate parsed the same line differently:

- Gate (`pkg/config.AuthorizeConfigMutation`): lexes the raw line with
  the config lexer; quoted strings are one token and only the LAST
  quoted token is dropped as the comment, so
  `annotate system "interfaces" "pwned"` is adjudicated as path
  `system interfaces`.
- Executor (`dispatchConfig` annotate arm): `strings.Fields` destroyed
  the quoting, the tokens were re-joined, and
  `AnnotateCommentFromLine` split at the FIRST `"`, so the same line
  executed as path `system`, comment `interfaces" "pwned`.

Under `deny-configuration "^system$"` with an `interfaces` allow, the
gate admits `system interfaces` (allow matches longer than the
anchored deny) while the executor annotated the denied `system` node —
a denied stanza's candidate text was mutated, and the annotation
persists into committed config text. Impact is authorization
integrity (annotate only sets `Node.Annotation`), not policy
compilation.

Second arm: the arm called `store.Annotate` →
`AnnotateAsPlantClass("", "", …)`, dropping
`EventPlantClassForMutation(c.userClass)` that every sibling mutation
arm (set/delete/deactivate/activate/copy/rename/insert/rollback/load)
and the gRPC arm pass — provenance/attribution loss for any
event-options payload the annotation touches.

The gRPC surface already rebuilt its gate line from the handler's
parsed values for exactly this reason (#9154/#13628); the local CLI
was missed. The same first-quote parser remains in the gRPC handler,
gRPC gate rebuild, and remote CLI — those surfaces are internally
consistent today (gate rebuild and handler share the parser, and
#13628 pins their embedded-quote behaviour), so they are NOT changed
here; migrating them is a separate wire-contract change.

## What

- `pkg/config/config_command_split_14147.go`: new
  `splitAnnotateTokens` (shared split: comment is the last token only
  when authored quoted), `ParseAnnotateCommand`, and
  `ParseAnnotateRemainder`, built on the same
  `lexConfigMutationLine9938` lexer the gate uses — the #14147
  canonical-parse pattern already used for copy/rename/insert.
- `pkg/config/authz_config_mutation_9154.go`: the gate's annotate arm
  now calls `splitAnnotateTokens` instead of open-coding the
  last-token drop, so gate and executors share one split by
  construction.
- `pkg/cli/cli_dispatch.go`: the annotate arm parses the ORIGINAL
  line with `config.ParseAnnotateCommand` (no `strings.Fields`
  round-trip, no first-quote split) and calls
  `AnnotateAsPlantClass("", EventPlantClassForMutation(c.userClass),
  …)` like every sibling arm.
- Tests: `pkg/cli/annotate_authz_14717_test.go` — packet test
  (`annotate system "interfaces" "pwned"` under deny `^system$` +
  interfaces allow, seeded `system interfaces` node; annotation must
  land nested on that node with comment `pwned`, never on bare
  `system`, never mangled), plain-annotate control, and a plant-class
  call-form cell (annotate alone does not restamp event policies —
  `StampChangedEventPlantClasses` ignores annotation-only diffs — so
  the attribution arm is bound at the call site, the same posture as
  the sibling-arm source guards). One existing cell updated:
  `TestAnnotateCommentReachesConfigVerbatim/unterminated` — an
  unterminated trailing string is not a quoted comment token under
  the canonical split, so it is now rejected as usage (matching the
  gRPC handler's rejection) instead of persisting `"unterminated`.

NOT changed: `cliterm.AnnotateCommentFromLine` (still the gRPC/remote
parser, pinned by #13628), the gRPC handler/gate, the remote CLI, the
REST annotate handler (JSON path/comment fields carry no quoting to
desync), the store, or the lexer.

## Risk

Behaviour delta: `annotate <path> "unterminated` (unterminated
comment) is now a usage error on the local CLI instead of persisting
the raw quote text; this matches the gRPC handler. Embedded-quote
comments on the local CLI now follow the lexer (`\"` escapes), the
same rule the gate and store lexer already applied. No other verb,
surface, or store semantics change.
