# #15277 — publish gate must refuse expired / imminently expiring apt suites

- **Timestamp**: 2026-10-19 (`fix/15277-campaign`)

## Why

`publish.py gate_apt` verified the InRelease signature and the Packages
binding for every suite under `apt/dists/` but never read the signed
`Valid-Until`/`Date`. An expired suite in the dist tree (for example a
stale non-target suite left from an earlier build) passed the gate and
was published, after which apt clients refuse the channel: no updates,
and fresh Tier-A installs fail at `apt-get update`. There is no
integrity loss (the bytes are validly signed), only availability of the
update channel. The builder defaults `Valid-Until` to 365 days, so the
trigger is a stale tree, not a routine build.

## What

- `scripts/dist/publish.py`: new `_gate_apt_freshness(suite, release_text,
  now=None, margin=None)` judged on the SIGNED cleartext
  (`gpg --decrypt` output of InRelease — the same verified bytes already
  used for the Packages binding), never the unsigned on-disk Release.
  It requires exactly one parseable `Date` and one parseable
  `Valid-Until` (duplicates/missing refuse, mirroring the builder's
  count==1 asserts), `Valid-Until` after `Date`, `Date` not more than
  5 minutes in the future, `Valid-Until` unexpired, and `Valid-Until`
  more than the freshness margin away. The margin is configurable via
  `XPF_APT_FRESHNESS_MARGIN_SECONDS` (non-negative integer seconds,
  default 7 days, `0` disables only the margin — never the expired
  check; values over 365 days or unparseable values refuse closed).
  `gate_apt` calls it for EVERY suite in the tree (target and
  non-target, flat and reprepro) before the pool-layout branch, and
  gained an injectable `now=None` (production passes None = wall clock).
- Regression: `scripts/dist/test_publish_apt_freshness_15277.py` —
  deterministic unit cells (injected fixed `now`) plus signed end-to-end
  `gate_apt` cells over real flat suites: expired non-target suite
  refused, unsigned-Release tamper does not rescue an expired signed
  suite, within-margin refused at the default and allowed with margin
  `0`, fresh suite passes.
- Docs: gate contract in the `publish.py` module docstring,
  `scripts/dist/README.md` publish row, and the operator freshness
  section in `docs/distribution.md`.
- NOT changed: `build-apt-repo.sh` (its build-time Valid-Until asserts
  already exist; this is the missing publish-time check), the optional
  "Date older than the remote copy's" leg (no remote-state input exists
  in the gate; not required by the acceptance cells), and any
  signature/Packages/key-agreement behaviour.

  (no `_gate_apt_freshness`/`gate_apt(now=...)` on base).

- **Neighbours**: `test_build_apt_repo_reprepro_10123` +
  `test_build_apt_repo_binding_12144` + the new suite together — 42
  passed (includes the real flat/reprepro `gate_apt` passes, which now
  also exercise the freshness check on freshly built suites).
  `test_publish_url_validate` passed; `test_dist_resign_9920` has one

  without a failure line; those suites do not call `gate_apt`.

## Risk

A publish whose apt tree contains a suite expiring within 7 days is
newly refused; operators rebuild/re-sign that suite or set
`XPF_APT_FRESHNESS_MARGIN_SECONDS` deliberately (documented). Fresh
builds (365-day default horizon) are unaffected. No dataplane, cluster,
or client behaviour changes; the gate remains fail-closed and the check
runs on signature-verified bytes only.
