# #14988 CLI TAB/? completion and help gate — engineering history

Issue: psaab/xpf#14988 (cli: gate TAB and ? completion and help on
permission and configuration regexes, D37-03). Lane branch:
`fix/14988-campaign`, base `origin/master` 5b3b02a61f.

## Defect (present at base)

`cliCompleter.Do` (`pkg/cli/completion.go`), the `?` Listener in
`(*CLI).Run` (`pkg/cli/cli.go`), `completeConfigWithDesc`,
`valueProvider`, and `showOperationalHelp`/`showConfigHelp` never
consulted `checkPermission`, `checkCommandRegex`, or
`ConfigurationLoginRegexesFor`. They returned live `ActiveConfig`
values — zone/policy/address/interface names with descriptions and
CIDRs via `valueProvider` and cmdtree `DynamicFn`s — plus config-schema
candidates under denied subtrees and operational candidates for
commands the class cannot run. The gRPC `Complete` RPC was gated for
the same disclosure in #14144/#14708/#14952; the on-box completer was
its residual. Candidate-preview stale sub-leg excluded per issue
scope (completion reads ActiveConfig only).

## Fix

Gate at the data source in `pkg/cli`, mirroring the gRPC
`completionAuth` (#14144):

- New `pkg/cli/completion_authz_14988.go`: `completionAuthz` compiles
  the session class's `*-configuration` / `*-commands` regexes once
  per completion from ActiveConfig. `completeForHelp` is the ONE
  candidate computation both TAB (`cliCompleter.Do`) and `?` (the
  `Run` Listener) use. `wrapValueProvider` offers live values only
  where the cursor path AND the hint's owning subtree (#14708 map)
  pass `*-configuration`; a denied consumed config path (edit path +
  typed path) offers no candidates; `show configuration …` also
  evaluates the canonical command against `*-commands`; cmdtree
  walkers get a nil config when an operational prefix is denied
  (nil-safe providers, #5196). Coarse gate: candidates whose command
  `checkPermission` denies (with canonical-prefix retry for partials)
  are dropped; config-mode candidates require `configure`.
  `filteredOperationalHelp`/`filteredConfigHelp` apply the same
  filter to `?`/`help`. Fail closed on unknown class / invalid regex;
  unset class (legacy no-RBAC) and regex-less families unchanged.
- `pkg/cli/completion.go`, `cli.go`, `cli_show_shared.go`: `Do`, the
  `?` Listener, `completeConfigWithDesc` (now delegating), and both
  help printers route through the gated helpers. No ungated
  `valueProvider`/`ActiveConfig` completion call remains in pkg/cli.

Not changed: dispatch gates, `valueProvider` itself, schema/cmdtree
walkers, pipe-filter help (public filter names only).

## Verification

- New `pkg/cli/completion_authz_14988_test.go` drives a real committed
  store through `cliCompleter.Do`, `completeForHelp`, and the filtered
  help helpers as `limited-view` (`deny-configuration "^security"`),
  `limited-op` (`deny-commands "^show configuration"`),
  `allow-interfaces` (allowlist), `view-only`, unknown, unset, and
  `open-view`/`super-user` controls. RED on pristine base logic
  (ungated passthrough): leaked `SECRET-*-DESC`, CIDRs, zone/policy
  names on config, `show configuration`, TAB, allowlist, coarse, and
  help cells. GREEN with the fix.
- `go vet ./pkg/cli/`: clean. Adjacent completion suites pass except
  `TestCompleteConfig_PredefinedApplicationSets_5763`, verified
  identical on pristine base 5b3b02a61f (#14339 drift).

## Residuals

- Handler-embedded `treeHelpCandidates` prints (e.g. bare `show`
  usage) still list public grammar keywords; they carry no live values
  and are reachable only after dispatch's own permission/regex gates.
- Pipe-filter `?` help unchanged (static filter names, no config data).
