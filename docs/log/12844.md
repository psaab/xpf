# #12844: classify every VRF-enslaved host-inbound netdev

## Summary

`HostInboundVRFEnslavedNetdevs` delegated to `junosHostVRFEnslavedNetdevs`,
which resolved only the first key returned by `InterfaceUnitRefKeys`. A bare
routing-instance member for a multi-unit interface therefore marked only the
base netdev enslaved. It also omitted explicit tunnel-manager device claims
and management-class interfaces bound independently to `vrf-mgmt`. Unzoned
ingress construction consumes this set to choose `sdifname` rather than
`iifname`; omitted VRF slaves were consequently admitted to the wrong
classification and the unzoned guard could fail open.

The fix gathers every effective key for each configured routing-instance
member (preserving unit-reference semantics), includes explicit tunnel claims
only for active non-forwarding tenant VRFs, and adds management-class netdevs
from the existing interface-to-Linux-name map. Contested devices are excluded
using the existing routing-instance ownership conflict detector. The top-level
helper now runs when there are configured interfaces even if there are no
tenant routing instances, because management-class devices still belong to
`vrf-mgmt`.

## Regression coverage

`pkg/config/host_inbound_vrf_netdevs_12844_test.go` covers bare multi-unit
fan-down, unit-only membership (no fan-up or sideways expansion), an explicit
tunnel routing-instance claim, `vrf-mgmt` management devices without tenant
routing instances, forwarding-instance exclusion, and contested-device
exclusion.
`pkg/dataplane/userspace/host_inbound_ingress_9637_test.go` additionally drives
a bare multi-unit member through production snapshots and asserts all trunk
netdevs land in `sdifname`, while an unrelated interface remains `iifname`.

Before the fix, `go test ./pkg/config -run
'TestHostInboundVRFEnslaved.*12844' -count=1` failed for the three target
regressions: bare multi-unit fan-down returned only `[ge-0-0-1]`; the tunnel
claim returned `[]`; and management returned `[]`. The unit-only and
forwarding-exclusion controls passed.

## Risk

The set is consumed by host-inbound view construction, unzoned ingress, and
the unzoned DHCP-unleased guard. The separate DHCP backstop enumeration remains
unchanged. The change adds only devices actually bound by a configured VRF
membership, an explicit tunnel claim to an active non-forwarding instance, or
the daemon's management-name class. Forwarding, reserved, and contested
membership devices, along with unrelated interfaces, remain excluded.
