# #12522 — reject ignored mpls/any interface filters

- **Issue**: #12522 — `family mpls|any filter input|output` bindings committed with zero diagnostics; `compileInterfaces` consumes interface filters only under family inet/inet6.
- **Branch**: `fix/12522-campaign-pub` (PR #12563)
- **Base**: `origin/master` `59b43bbe6` (rebased from `f9cb48ed8`; replaces pushed head `d18151097`)
- **Files**: `pkg/config/compiler_interfaces_unsupported.go`, `pkg/config/compiler_interfaces_mpls_any_filter_12522_test.go`, `debian/changelog`, `docs/log/12522.md`

## Why

The first cut (`d18151097`, base `f9cb48ed8`) added a warn-only #12522 arm to
`validateUnsupportedInterfaceStanzasAST`. Master has since landed #12090 in the
same function: every interface `filter`/`simple-filter` head outside
`unit <n> family inet|inet6 filter input|output <name>` fails strict commit and
warns on tolerant loads. Probed on `c2aa3f8d9`:

- `family mpls` in every shape (flat-set, braced, compact, split, split-packed,
  interface-range member) is already rejected by #12090.
- Braced, compact, and split `family any` are already rejected by #12090.
- `family any` as a packed child of a bare `family` node committed clean with
  zero warnings: flat-set `set interfaces X unit 0 family any filter input F`,
  hierarchical `family { any filter input F; }`, and the lo0,
  interface-range member, and apply-groups expansions of the flat form.
  `inspectPackedHead12090` inspects such a child only when
  `isInterfaceFamilyAF12090` lists its token, and `any` was missing.
- The forwarding-options gate shares that list: flat-set
  `set forwarding-options family any filter input F` committed clean while its
  braced twin rejected.

Rebased onto master, the warn-only arm double-reported every mpls/any stanza
on tolerant loads (#12090 + #12522), and its own test failed at the strict
#12090 rejection.

## What

- Added `any` to `isInterfaceFamilyAF12090`. Packed `family any` filter and
  simple-filter heads now take the existing #12090 diagnostic (one per keyword
  head) in both the interfaces and forwarding-options walks.
- Dropped the warn-only #12522 arm and its helpers. This also retires review
  findings F2 (the packed-tail scan re-read a filter named `input`/`output` as
  a direction) and F3 (message overlap with #12090).
- Tests (`compiler_interfaces_mpls_any_filter_12522_test.go`):
  - mpls/any × input/output × {flat, flat-lo0, flat-range-member, braced,
    compact, split, split-packed}: strict compile fails with exactly one
    `(#12090)` diagnostic naming `filter <dir>`; tolerant compile carries
    exactly one warning for the binding.
  - forwarding-options `family any` × input/output × {flat, split-packed}:
    the same contract.
  - inet/inet6 × input/output × {flat, braced}: strict commit, typed
    `FilterInput|OutputV4|V6` hook populated, no filter diagnostic.
- `debian/changelog` bullet for the commit-time rejection.

## Risk

Strict commits containing a packed `family any filter|simple-filter` binding
under interfaces or forwarding-options now fail, as the braced spelling
already did under #12090; tolerant loads (boot, peer sync) warn. No fixture in
the tree uses these shapes. No dataplane or runtime change.

Still silent and out of scope: `family mpls|any policer input|output`, and
unlisted family tokens under a bare `family` node (for example
`family foo filter input F`).
