# #9642 retry-debt — engineering history

Issue: psaab/xpf#9642 (bug/dataplane/security). A timeout-but-landed
`apply_snapshot` was re-armed by the next status tick against the classifier
plan it did not publish. Lane branch: `fix/9642-retry-debt`.

## Mechanism (STEP-0, confirmed at base 14f680b3f)

`publishSnapshotFailClosedLocked` disabled ctrl on transport errors without
advancing snapshots; `ctrlMustStayDisabledLocked` held only RG/link states;
the ~1 Hz tick rebuilt ctrl and re-synced classifier maps from the retained
snapshot before any republish gate ran. The #9520 unknown-outcome mark had no
ctrl consumer and opened no republish gate.

## Fix direction (converged, 3 hostile rounds, no KILL)

Retain the attempted snapshot as retry debt: adopt on unknown-outcome failure
(ordering re-stamped locally; refusals and deterministic-local failures
excluded via sentinels), hold ctrl via the debt conjunction
(`mark && published < last.Gen`), skip the tick classifier re-sync while
indebted, converge on the existing level-triggered gate, ensure the status
loop across helper respawn, exempt indebted publishes from the XSK-startup
new-plan deferral, record standalone HA-clear debt on adopt.
