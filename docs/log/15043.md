# #15043 — partial republishes retain only Interfaces, discarding the #14209 rebuilt derived sections (A29-02)

- **Timestamp**: 2026-10-18
- **Issue**: The scheduler (`UpdatePolicyScheduleStateWithLatch`), deferred-worker-arm (`retryDeferredWorkerArmLocked`) and status-tick (`syncSnapshotLocked`) republishes write back only `Interfaces` after a successful publish, discarding the derived sections `prepareSnapshotForApply` rebuilt (#14209); later republishes re-ship stale-ifindex mirror/tunnel/route rows and the stored hash no longer describes the retained snapshot (report A29-02, Medium, 3-way MATERIAL in `research-work.AdQvt1jMKw`).
- **Base**: `origin/master` `c4fa982c0f`.

## Mechanism (verified at base)

- Every apply goes through `prepareSnapshotForApply` (`apply_snapshot_identity_9520.go`), which revalidates `Interfaces` against the live kernel and, when a row moved, runs `rebuildDerivedSectionsAfterRevalidate`: it rewrites `Interfaces`, `Routes` (+ `LearnedRouteImportCapped`), `Fabrics`, `TunnelEndpoints`, `MirrorConfigs`/`MirrorExclusions`, `SourceNAT` (detach copy), `Zones`/`Summary`/`ZoneSetValidated`/`zoneIDCollisions` (re-quarantine), `wgFanUpBaseRows` and `xfrmDumpFailed` on the struct being sent.
- `manager_compile.go` (scheduler): `next.Interfaces = publishSnap.Interfaces` was the only write-back, then `m.lastSnapshot = &next` with `m.lastSnapshotHash = hash(&publishSnap)` — the hash of the rebuilt copy stored against the stale retained struct.
- `manager_worker_arm_5134.go` (deferred worker arm): same single write-back and same hash source.
- `process_status.go` (status tick): `m.lastSnapshot.Interfaces = publishSnap.Interfaces`, with `hash` computed from `retained` before the send while `retained`'s rebuilt sections were never committed (only `Neighbors`/`Fabrics` when resampled).
- Consequence: after such a publish, `m.lastSnapshot` carries pre-rebuild mirror/tunnel/route rows. The next partial republish starts from that struct and — when its own revalidation moves nothing — re-ships a mirror/connected route bound to a vanished or reused ifindex (the #14209 consequence) until the next full Compile. The hash invariant `lastSnapshotHash == hash(lastSnapshot)` is broken immediately, so dedup comparisons run against a hash of content the retained snapshot does not hold.

## Fix

- `manager_compile.go` / `manager_worker_arm_5134.go`: after a successful publish, copy back every section the apply-time rebuild writes (the list above) from `publishSnap` into `next` before `m.lastSnapshot = &next`. `Neighbors` is deliberately NOT copied: `publishSnap.Neighbors` is the publishable-only filter (`filterPublishableNeighbors`), not the retained set, and capturing it would drop unpublishable rows from the retained authority (the filter allocates a fresh slice, so no aliasing is introduced either way).
- `process_status.go`: `*m.lastSnapshot = retained` after a successful publish — `retained` is the struct that was prepared (revalidated + rebuilt) before the send, so the whole prepared snapshot becomes the retained authority. The `#9684` resampled `Neighbors`/`Fabrics` write-back is kept (it records exactly what the helper accepted; it is value-identical to `retained`'s resampled sections). `hash` was already taken from `retained`, so the hash invariant now holds by construction.
- The overlay (`PublishRouteOverlaySnapshotWithLatch`), capture-authority (`RepublishCurrentCaptureAuthority`) and link-refresh (`RefreshInterfaceRowsForLink`) paths already prepare the retained struct itself (`prepareSnapshotForApply(&next)`) and hash it — they were the correct pattern and are unchanged. `applyCompiledSnapshot` prepares `snap` in place and retains `snap` — unchanged.
- NOT changed: `prepareSnapshotForApply` / `rebuildDerivedSectionsAfterRevalidate` (the #14209/#14333 rebuild itself), the publish/filter/dedup logic, any wire or Rust code, and the failure paths — every error return above the write-back still retains the prior snapshot untouched (pinned by `TestFailedPartialPublishPreservesRetainedInterfacesAndHash12213`).

## Risk

- Retained snapshots now carry the sections the helper actually accepted; the only behavioural delta is that later partial republishes start from the rebuilt (current-ifindex) rows instead of stale build-time rows, and the stored hash again describes the retained struct (dedup may now correctly skip a republish it previously misjudged, or vice versa — both directions are the invariant the dedup was written against).
- The write-back is a shallow slice-header copy of freshly rebuilt slices owned by the publish copy; the publish copy is discarded after the call, so no new aliasing with live state is introduced. Failure paths are untouched (fail-closed retention preserved).
- No Rust or wire changes.
