# Issue #12196 — reject non-executable userspace helper candidates

## Why

`findBinary` accepted implicit working-directory/build-tree/argv0-relative candidates on `os.Stat` success alone. A stale 0644 file or directory therefore shadowed a usable executable on `PATH`; helper startup then failed instead of trying the valid candidate. Explicitly configured paths also accepted non-executable files without an actionable diagnostic.

## What

Implicit candidates are now skipped unless they are not directories and have at least one execute bit, matching `exec.LookPath`'s file-mode check. Explicit paths remain strict: missing paths retain the not-found error, while directories and non-executable files return informative errors and never fall back to `PATH`. Candidate order and the existing PATH fallback are unchanged.

## Validation

- **RED before** (pristine base `8dc3c5624`): `go test ./pkg/dataplane/userspace -run 'TestFindBinary.*12196' -v -count=1` failed all three discovery assertions: a cwd 0644 artifact and a cwd directory each returned `./xpf-userspace-dp` instead of the executable PATH candidate; an explicit 0644 path was returned successfully instead of an informative error, despite an executable PATH fallback being present.
- **GREEN after**: the same targeted command passed all four regression tests, including explicit missing-path wording.
- `go build ./pkg/dataplane/userspace` — PASS.
- `gofmt -d pkg/dataplane/userspace/process.go pkg/dataplane/userspace/findbinary_12196_test.go` — PASS (no diff).
- `go test -count=1 ./pkg/dataplane/userspace` — three unrelated existing failures: `TestNilUnitSlotCastsNoTrunkZoneVote_6722`, `TestRetainedLiveXfrmiLeavesTheAdjudicatedSets/untracked_after_daemon_restart`, and `TestSnapshotShapeIsPinnedToProtocolVersion8892`. Running those exact tests on a pristine `8dc3c5624` worktree reproduced the same failures and diagnostics; these are baseline reds, not regressions from #12196.

## Risk / residual

The check validates directory status and execute permission bits, not the binary format or whether the kernel can load the file. A malformed executable-bit file can still fail at process start, as it can when found through `exec.LookPath`. No live cluster was mutated.
