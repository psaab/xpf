# #12645 — fold host-inbound exclusion aliases

## Why

Lenient compilation intentionally preserves wrong-case host-inbound tokens for
runtime enforcement, which lowercases them. `hostInboundFilterExcept` previously
looked up both positive and excluded tokens case-sensitively. Thus a lenient
`NETCONF-SSH` positive had no compile-time tuple, survived `ssh except`, then
lowered at enforcement and admitted TCP/22 and TCP/830. The same mismatch could
occur within one stanza or after physical/unit override union.

## What

`hostInboundFilterExcept` now folds token spellings for exclusion lookup and
L4-tuple matching while preserving the authored token spelling in surviving
configuration output. To retain strict validation, the parser also carries
wrong-case spellings whose lowercase forms are known through same-stanza and
cross-scope merges; the token gate still rejects them (and lenient loads still
warn). This covers positive tokens, exclusion tokens, and `all` expansion
without broadening unrelated service matches.

Added lenient regression cases for mixed-case aliases/exclusions, uppercase
protocols, lowercase controls, unrelated allowed aliases, tuple-level TCP/22
and TCP/830 denial on both families, and both physical/unit union directions
with an unrelated TCP/80 admission guard. A strict-path test pins rejection of
the uppercase alias even when its positive admission is excluded.

## Validation

- **RED before fix:** `go test ./pkg/config -run 'TestHostInboundExceptUppercaseAlias12645|TestHostInboundExceptUppercaseAliasTuples12645' -count=1` failed: uppercase/mixed-case NETCONF-SSH cases retained the alias, uppercase OSPF exclusion retained OSPF, and TCP/22 remained admitted by `NETCONF-SSH`.
- **One-sided mutant:** changed exclusion tuple lookup to use authored spelling rather than lowercasing. `go test ./pkg/config -run 'TestHostInboundExceptUppercaseAlias12645|TestHostInboundExceptUppercaseAliasTuples12645' -count=1` failed the mixed-case alias/exclusion case, proving exclusion tuples also require case folding. Restored the fold.
- **Focused GREEN after:** `go test ./pkg/config -run 'TestHostInboundExceptUppercaseAlias' -count=1` — PASS before and after rebasing onto current master.
- **Full package at base `f985e7c99`:** `go test -timeout=0 ./pkg/config -count=1` — FAILED with failures outside this change, including #8662 inventory/live-census drift, #10826 expiry-fixture expectations in several parser tests, #11312 packed-routing-instance expectations, and #7484 spelling-gate coverage ratchets. No host-inbound test failed.

## Risk

No intended behavior change for strict compilation, which continues to reject
wrong-case tokens. Leniently loaded wrong-case aliases now honor the same
exclusions as their lowercase enforcement form, closing an unintended admission.
