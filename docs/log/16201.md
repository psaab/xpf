# #16201 — testgolden.String tail helper reusing -update

- **Timestamp**: 2026-10-24
- **Issue**: `testgolden.String(t, path, got)` tail helper only: explicit
  path (never `t.Name()`-derived), reusing the existing `-update` flag
  (not a new `-update-golden`), no header line in golden files. Format
  package first, then the 4406 tail; 4406 corpus/matrix logic untouched.
- **Change**:
  - New `internal/testgolden` package. `String(t, path, got)` owns the
    shared compare-or-write tail: with `-update` it `MkdirAll`s the
    parent and writes `got` verbatim (no header, no added newline);
    otherwise it reads the baseline and `Fatalf`s on mismatch with the
    path, both blobs, and the `-update` regenerate command. The package
    is the sole registration of the `-update` flag.
  - `UpdateRequested()` exposes the same flag for the one caller whose
    update path is not a single `String` write: the 4406 harness must
    suppress its bespoke mismatch path (`.actual.json` sidecar +
    per-case diff) while regenerating. It now checks
    `testgolden.UpdateRequested()` instead of
    `os.Getenv("GOLDEN_4406_UPDATE") == "1"`; regenerate command is now
    `go test ./pkg/config/ -run TestCompileGolden4406 -update`. Corpus
    building, matrix cells, sorting, serialization, and the compare /
    mismatch diagnostics are byte-for-byte untouched. `os` is still used
    for the baseline read/write, so no import churn beyond testgolden.
  - Format package migrated atomically in the same change (the
    flag-redeclaration hazard): `status_golden_test.go` deletes
    `var updateGolden = flag.Bool("update", ...)` while its three
    consumers (`status`, `cos`, `buffers` goldens) switch to
    `testgolden.String(t, "testdata/<name>.golden", got)`. Relative
    explicit paths keep the old working-directory semantics. The
    non-golden `TestFormatStatusSummaryRejectReasonsAbsentByteCompare10500`
    still reads the status baseline directly — it is a subtract-lines
    byte derivation, not a compare-or-write tail, so it stays.
  - Self-tests `internal/testgolden/testgolden_test.go`: equal-compare
    passes; mismatch is fatal and names path, got, want, and `-update`
    (via a panicking `fatalTB`, since `String` is fatal by contract);
    missing file is fatal and names path + `-update`; update mode
    writes exact headerless bytes into a nested path (proving
    `MkdirAll`) and `UpdateRequested()` tracks the flag.
- **Validation**:
  - `go test ./internal/testgolden/` PASS; `go vet` clean on
    testgolden, format, and config; `gofmt -l` clean.
  - Format goldens PASS in compare mode
    (`TestFormatCoSInterfaceSummaryGolden`,
    `TestFormatStatusSummaryGolden`, `TestFormatSystemBuffersGolden`,
    plus the #10500 subtract-lines test).
  - Forced-regen-clean oracle (format leg): `-update` run leaves
    `git status` clean for all three format `testdata/*.golden` files.
  - Corrupt-one-baseline goes red: appending `CORRUPTED` to
    `cos_summary.golden` fails `TestFormatCoSInterfaceSummaryGolden`
    with both blobs shown; baseline restored byte-exact afterwards.
  - No duplicate `-update` registration: tree census shows
    `flag.Bool("update", ...)` only in `internal/testgolden`; the old
    `updateGolden` symbol and `GOLDEN_4406_UPDATE=1` code gate are gone.
  - 4406 leg: `-update` writes the baseline and a second `-update` is
    byte-identical (idempotent regen). The committed
    `golden_4406.json` was restored, NOT regenerated in this PR — see
    Risk.
  - Pre-existing failures at origin/master `56d682e5de`, confirmed on
    the pristine tree by stashing this change: two
    `cos_rewrite_rule_inert_6858_test.go` cells fail in format, and
    `TestCompileGolden4406` fails its compare because the committed
    baseline is stale relative to master.
- **Risk**: Test-only; no production code. The 4406 baseline staleness
  is pre-existing and out of scope: master's baseline lacks fields and
  warnings landed after it was captured (e.g. `PKI`,
  `SourceAddress`, `PPTPDisable`, `RequireAuthenticatedFabricStamps`,
  the #15034 untagged-unit warning, tcp-mss range `[64..65535]`).
  Regenerating it here would bless unrelated behavior deltas in a
  test-infra PR, so the compare failure remains for the owning changes
  to resolve; this PR only proves the `-update` regen path is
  byte-stable and idempotent. Ratchet-txt readers
  (`flat_set_chain_losers_8939.txt` etc.) were left alone: the issue
  scopes the 4406 tail explicitly ("then the 4406 tail"), and those
  readers have different split/compare semantics, not the
  compare-or-write string tail.
