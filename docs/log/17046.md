# #17046 — Single-source the #8447 persistent-NAT admission-counter epilogue

- **Timestamp**: 2026-10-27
  - **Action**: Replaced the three 12-/13-argument
    `allocate_translation*` wrappers in `nat/allocator/mod.rs` with one
    `AllocRequest` struct (flow, family, offset, address_persistent,
    `persistent: Option<PersistentParams{permit, epoch, timeout}>`,
    now_ns, holder, egress_scope, mint_from_zone, excluded) and one
    `PortAllocator::allocate(&AllocRequest)` that owns the sole #8447
    epilogue (`persistent_admitted_total` / `persistent_declined_total`
    selection + bump). STEP-0 verified on current master
    (8fdb112b3f): the epilogue existed at two sites
    (`_with_zones`, `_with_exclusions_and_zones`) and was absent from
    `_with_exclusions`, which carries the only `persistent_nat=true`
    NAT64 mint (`nat/source/nat64_ports.rs`, #16011). Production
    callers migrated field-for-argument with byte/counter-identical
    argument values: the two `match_rules.rs` PAT sites (v4 offset 0,
    v6 offset `v6_offset`, `Some(from_zone)`, probe exclusions) and the
    NAT64 BIB mint (offset 0, `AnyRemoteHost`, epoch 0, 300 s timeout,
    egress_scope 0, no zone). `allocate_translation` and
    `allocate_translation_with_exclusions` are retained only as
    `#[cfg(test)]` shorthands delegating to `allocate`, so the ~70
    test call sites stay terse and the test-only entry point is no
    longer compiled into production. Added
    `nat64_bib_mint_counts_persistent_admitted_17046` (NAT64 BIB mint
    via `allocate_nat64_pool_port` bumps `persistent_admitted_total`
    by 1; empty-pool mint bumps `persistent_declined_total` by 1 —
    RED on master where the mint was uncounted) and
    `persistent_admission_epilogue_is_single_sourced_17046`
    (exactly one `&self.shared.persistent_admitted_total` selection
    site, one epilogue bump, and neither removed counted wrapper
    may return).
