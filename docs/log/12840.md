# #12840 — suppress contradictory DHCP host-inbound warning

- **Action**: prevent #6460 from reporting the #7490 zone-level DHCP withholding as a zone omission, and point genuine per-interface override omissions to the per-interface remedy.
- **Base**: `5afbe25ce5f51745c25b429f12d5351665b117b0` (`fix/12840-campaign-pub`).
- **Files**: `pkg/config/compiler_validate_warn_dhcp_hostinbound.go`, `pkg/config/dhcp_hostinbound_withheld_12840_test.go`.

## Finding

`validateDHCPServerHostInboundBypassWarnings` queried `InterfaceHostInboundEffective`, which correctly removes a zone-level `dhcp`/`bootp` authorization from DHCP server/relay interfaces under #7490. It then described the result as a zone stanza omission and advised adding the token to that zone, even though the zone already contained it and the withholding made that remedy ineffective. The dedicated #6519/#7490 warning already explains the withholding and its per-interface restatement.

The validator now suppresses #6460 only when the effective absence is due to a withheld, already-admitted zone token with no interface override. If a per-interface override replaces a zone set that admits the token and omits it itself, #6460 remains and its explanation/remedy addresses that override. Zone omissions and DHCPv6 behavior remain unchanged.
