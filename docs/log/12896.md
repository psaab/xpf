# #12896 - Quarantine-aware zone-detail policy summary

- **Timestamp**: 2026-10-14
- **Action**: `policymatch.ZoneDetailPolicySummary` now annotates each row's
  live applicability instead of delegating quarantine labeling to callers that
  only annotate the viewed zone. A zone-pair row whose set the apply-time scrub
  (`scrubPoliciesForQuarantinedZones`) would drop (either endpoint a
  StableZoneID-collision loser) and a global row whose configured scope that
  scrub prunes carry `config.ZoneQuarantinePoliciesQualifier`; a scoped global
  prints its SURVIVING scope (authored scope when the prune empties a side).
  Wildcard zone-pair sides and unscoped/explicit-any globals are selected only
  for an INSTALLED viewed zone, so a quarantined zone lists only the literal
  references naming it, each scrub-marked. The gRPC `zones-detail`
  "Policies referencing this zone" line qualifies a reference whose other
  endpoint is a collision loser when the viewed zone is healthy. The CLI/gRPC
  block-level qualifier (#10530) is unchanged and now complements the per-row
  marks instead of being the only annotation.
- **Verdict sets**: row liveness uses `config.QuarantinedZoneNames(
  ZoneQuarantineNamesForConfig(cfg))` — the exact set the runtime policy scrub
  uses — while viewed-zone liveness uses `ZoneQuarantineExclusionsForConfig`
  (collision losers + reserved names), matching the caller qualifier gating.
