# Issue #13225 — preserve rollback metadata and report cleanup failures

## Why

`loadRollbackHistory` used `ReadBoundedFile` before the `#5557` oversized-slot guard, so an oversized rollback slot took the read-error path and lost its recorded timestamp and operator comment. Meanwhile, `saveRollbackFiles` ignored stale-slot unlink failures, leaving rollback health green while stale files could reappear on restart. Empty-history cleanup also skipped the directory fsync after removing stale slots.

## What

- Removed the unreachable oversized-data guard. For oversized regular files, the loader now preserves timestamp/comment only after validating the full streaming SHA-256, file identity, and manifest generation; mismatches remain tombstones without trusted metadata.
- Made `cleanupRollbackFiles` report whether it removed files and whether any unlink failed. `saveRollbackFiles` marks rollback persistence degraded on cleanup failure and syncs the directory after stale files are removed even when history is empty.
- Added regressions for oversized metadata preservation, surfaced unlink failures, and empty-history cleanup fsync.

## Risk

Oversized rollback files require a streaming hash to validate their metadata, using bounded memory but work proportional to file size. Metadata is not restored for unreadable non-regular files, identity/hash mismatches, or active-generation mismatches. No external caller signature changed.
