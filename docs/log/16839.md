# Issue #16839 — spare live-socket RSTs on interface-NAT addresses from RST suppression

- **Issue:** the #15727 `xpf_dp_rst` output chain (raw priority -300)
  matched `ct state invalid` alone. At raw priority the OUTPUT
  conntrack hook (-200) has not run yet, so a live local socket's
  abortive RST (SO_LINGER 0 / close with unread data,
  `tcp_send_active_reset` -> `ip_local_out`, `skb->sk` set, no nfct
  attached yet) sourced FROM a protected interface-NAT address also
  reads INVALID and was dropped. The peer never saw the reset and held
  the connection until its own timer; the drop counter misattributed
  these to "spurious" RSTs. The contract in `rst_suppress.go` ("local
  control-plane socket RSTs ... are legitimate and must survive") was
  violated, and the premise behind it ("a local socket's RST carries
  its socket conntrack entry (attached before OUTPUT)") is false at
  raw priority. The #15727 live test's tracked control could not catch
  this: its client RST is sourced from 127.0.0.1, outside the rule's
  saddr scope as well as tracked, so it passed with or without the bug.
- **Fix:** `rstDropExprs` (`pkg/nftables/rst_suppress.go`) now
  additionally requires `socket wildcard == 1`
  (`expr.Socket{Key: SocketKeyWildcard}` + `Cmp Eq [1]`, exprs [7..8],
  after the ct predicate). Kernel semantics
  (`net/netfilter/nft_socket.c`, `nft_socket_eval` /
  `NFT_SOCKET_WILDCARD`): BREAK (rule does not match) when there is no
  socket or the socket is not a full socket; otherwise stores 1 iff
  the socket is bound to a wildcard address
  (`inet_rcv_saddr == 0` / `ipv6_addr_any(sk_v6_rcv_saddr)`). The
  spurious RST is emitted via the per-cpu `tcp_rst_sock` control
  mini-socket (wildcard-bound), reading 1; a live socket bound to the
  protected address reads 0 and is spared regardless of conntrack
  state. Chain priority, ct predicate, saddr scope, TCP-RST match,
  counter and drop verdict are unchanged. NOT changed: the chain does
  not move after conntrack (at filter priority the spurious RST reads
  NEW, #15727) and UNTRACKED is still not matched.
- **Files:** `pkg/nftables/rst_suppress.go` (socket-wildcard
  predicate + corrected comments), `pkg/nftables/rst_suppress_shape_7171_test.go`
  (indices shifted +2, socket expr pinned), `pkg/nftables/rst_suppress_14949_test.go`
  (socket predicate asserted; header corrected),
  `pkg/nftables/rst_suppress_live_16839_test.go` (new live netns
  regression test), `pkg/nftables/README.md`,
  `docs/afxdp-packet-processing.md`, `docs/log/16839.md`.

## Kernel-semantics evidence

- Witness probe (temporary test, since removed) in a private netns,
  kernel 7.2.8+deb14-amd64, installing witness counters only (no drop)
  at raw OUTPUT for RSTs sourced from 127.0.0.2 with `ct invalid`:
  spurious SYNs-to-closed-port counted `none=3 wildcard1=3
  wildcard0=0 skuid(uid0)=0`; a live server socket's abortive RST
  sourced from 127.0.0.2 counted `none=1 wildcard0=1 skuid=1
  wildcard1=0`, and the client observed ECONNRESET. So the same RST
  is INVALID at raw and tracked afterwards, and `socket wildcard`
  cleanly separates the live-socket class (0) from the spurious
  class (1). `meta skuid` would also separate them here, but it keys
  on the owner's uid (operator-dependent, and the value to compare
  against is not knowable at install time); wildcard keys on the
  bind address, which is exactly the distinguishing property.
- `nft_socket_validate` permits the socket expression on LOCAL_OUT;
  the live tests below install the real table with Flush, so the
  kernel validated the new expression on this kernel.

- **Controls:** `go vet ./pkg/nftables/` clean; `gofmt -l` clean on

## Residual

- Deliberate scope: a live socket bound to the wildcard address
  (0.0.0.0 / ::) whose source would only become the protected address
  via a later NAT hook reads wildcard 1, but at raw priority that
  rewrite has not happened, its on-wire source is not the protected
  address yet, and the saddr predicate has already excluded it.
  Sockets bound to the protected address itself — the #16839 cell —
  read wildcard 0. Recorded in the `rstDropExprs` comment.
- Live evidence is loopback in an unprivileged user+net namespace
  (as with #15727), not a physical NIC / real WAN interface-NAT
  address; the kernel path (`tcp_send_active_reset` -> `ip_local_out`
  -> raw OUTPUT) is the same.
- IPv6: the same wildcard predicate is emitted for v6 rules
  (`ipv6_addr_any(&sk->sk_v6_rcv_saddr)` in the kernel) and pinned by
  the unit shape tests for both families; live evidence is v4, as
  with the pre-existing #15727 live test.
