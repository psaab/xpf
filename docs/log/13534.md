# 13534 — Interface-only static next-hop compiles a phantom gateway

## Boundary

For `next-hop interface pp0.0`, the static-route compiler treated the leading `interface` token as a gateway and separately emitted the interface next-hop. The resulting extra `{Address: "interface"}` entry corrupted the compiled route and therefore its FIB fate. This applies to fully-inline route keys and the next-hop property-key forms used by hierarchical and flat-set configs.

## Fix

- Consume `interface <name>` as the egress-interface modifier even when no gateway precedes it; when no address was parsed, emit exactly one interface-only next-hop.
- Apply the same rule in both static-route key representations (fully-inline route keys and `next-hop` properties). Preserve a lone `interface` token without a following value as a gateway scalar.
- Add #13534 regressions for hierarchical-brace, flat-set, and fully-inline input, each asserting the complete next-hop list is exactly `[{Interface: "pp0.0"}]`.
