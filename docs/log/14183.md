# #14183 — DHCPv4 lease yiaddr/subnet-mask not validated

## Defect
`leaseFromACKv4` (`pkg/dhcp/dhcpv4.go`) rejected only an unspecified yiaddr
and a zero/non-contiguous subnet mask (#4101). A rogue DHCP server could
ACK e.g. `192.0.2.5/1` (mask 128.0.0.0) or a martian yiaddr
(`127.0.0.2`, `169.254.1.1`, `224.0.0.1`, …). The resulting
`Lease.Address` reaches `Manager.applyAddress` → `AddrReplace`, so the
kernel installs a connected prefix covering up to half of IPv4 (or binds
a loopback/multicast/reserved address) on the interface, outside the
classless-route gates (`ClasslessRouteIsTooBroad`/`IsMartian` apply only
to option-121/249 destinations and gateway next-hops, never to the
leased address). Traced downstream (`pkg/daemon/daemon_flow.go`,
`pkg/frr/config_render.go`, management-VRF path): no consumer rejects a
/1 lease address before AddrReplace.

## Fix
In `leaseFromACKv4`, at the single parse point shared by acquire, renew,
and rebind:
- Refuse any mask with `ones < 8` (subsumes the previous /0 check;
  bits!=32 still refused). No legitimate connected subnet is broader
  than /8; /8–/32 including /31 and /32 remain accepted.
- Refuse a martian yiaddr via the existing `ClasslessRouteIsMartian`
  /32 check (0/8, 127/8, 169.254/16, 224/4, 240/4 — the latter includes
  255.255.255.255). Private/documentation ranges remain accepted.
- No `XPF_DHCP_TRUST_CLASSLESS_OVERRIDE` escape hatch for the leased
  address: that override governs optional learned routes/gateways, not
  the interface's own address; honoring a /1 connected prefix or a
  martian bind is never safe.

Refusal returns an error with no lease, so acquire retries DISCOVER and
renew/rebind keeps the existing valid lease until T2/expiry — fail-closed,
same propagation as #4101.

## Regression

`TestLeaseFromACKv4RejectsBroadMaskAndMartianYiaddr14183` drives the
existing `mustV4ACK` fixture. Rejection rows: /1, /2, /7 masks;
127.0.0.2, 0.0.0.9, 169.254.1.1, 224.0.0.1, 240.0.0.1, 255.255.255.255
yiaddr. Acceptance rows: public /24, private /8 and /16, /31, /32.

- RED on pristine origin/master (43ebebd38): all 9 rejection rows fail

- GREEN with fix: full `pkg/dhcp` package passes.
