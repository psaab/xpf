## One tested production primitive

`FactoryResetConfigDir` was a test-only twin of the production gRPC wipe. It had drifted behind that implementation, leaving crash-recovery DB copies, TLS credentials, DHCPv6 DUIDs, and owned editor backups. The gRPC coordinator now calls the config-store primitive directly, with its directory-sync seam passed explicitly; there is one implementation under both existing test suites. Obsolete gRPC-only root-wipe matchers/tests were removed.

The shared primitive erases the missing xpf-owned artifacts while retaining exact-name ownership boundaries. DB recovery copies use key-first deletion and directory sync. A `.day0-config-applied` record with the pending-reset prefix is retained for the coordinator to remove only after all wipe legs finish; marker inspection errors preserve the loader gate and are surfaced.

`CollectInteriorSymlinks` previously returned `nil` at an excluded directory, causing `WalkDir` to descend into it and report symlinks that the caller explicitly excluded. It now skips an excluded directory subtree and treats an excluded root (including a symlink root) as empty, matching the hard-link census behavior.
