# #14715 display-pipe substring matching ignores trailing stanza tokens — engineering history

Issue: psaab/xpf#14715 (D17-02). Lane branch: `fix/14715-campaign`,
base `origin/master` fd942f4087.

## Defect (present at base)

`handleShow` (`pkg/cli/cli_show.go`) built `cfgPath` only from tokens
before `|` but selected the render format with
`strings.Contains(rest, "| display set")` (likewise json/xml/inheritance).
`show configuration | display set interfaces` therefore rendered
`ShowActiveSet()` / `ShowActiveSetRedacted(nil)` — the whole tree — while
the trailing `interfaces` token was silently discarded. The authorization
gate did not save it: `evaluateCommandRegex` checks only that
`pipeWords[1] == "display"` is authorizable, so the typed string
`show configuration | display set interfaces` satisfied an
interfaces-scoped allow (`^show configuration .*interfaces`) and evaded a
`$`-anchored display-set deny. Identical shape in config-mode
`handleConfigShow` (`strings.Contains(line, …)`), and the same substring
mechanism in `show system rollback N` (`cli_show_system.go`) plus its
authorization predicate `showSystemRollbackCompare` (`permissions.go`).

For non-superuser classes the output is the redacted renderer (#4099), so
secrets stay `##SECRET-DATA##`; the bypass dumps the full *structure*
(policies, NAT, users/classes, routing). Either the gate or the handler
must reject the malformed pipe; neither did.

## Fix

Token-exact pipe parsing, shared by all three handlers:

- `splitDisplayPipe` / `splitConfigShowPipe` (`cli_show.go`): split at the
  first bare `|`; only `| display <json|set|xml|inheritance>` with NO
  trailing tokens selects a format. `| display set interfaces`, an unknown
  format, a bare `|`, or `| display` alone are syntax errors naming the
  offending token, with no render. Config-mode additionally accepts
  `| compare` / `| compare rollback <N>` exactly; rollback accepts only
  `| display set` (other formats are named as unsupported).
- `evaluateCommandRegex` (`permissions_regex.go`): a `display` pipe is
  authorizable only as `| display <format>`, optionally followed by one
  recognised output filter (`| display set | match x`, which dispatch
  `SplitPipe` splits and the gate reassembles). Longer/malformed forms
  are refused as "not a recognised display format", so gate and executor
  agree on what was run; the anchored-deny and scoped-allow bypass
  spellings are denied even before the handler's syntax error.
- `showSystemRollbackCompare` aligned to the token-exact handler (exact
  `compare` token, exact `| display set` wins) so the candidate-read
  price cannot drift from what the handler executes.

NOT changed: `cmd/cli` (remote client) — #13202 already parses its show
pipes token-exactly (`splitShowPipe`/`parseShowDisplay`); the in-process
CLI was the remaining substring surface. Output-filter pipes
(`| match`/`count`/…) and `pendingPipeSuffix` reassembly are unchanged.

## Regression (`pkg/cli/show_display_pipe_trailing_14715_test.go`)

- `TestShowConfigurationDisplayPipeTrailing14715`: for each format
  (set/json/xml/inheritance), operational `show configuration | display
  <fmt> interfaces` and config-mode `show | display <fmt> interfaces`
  must be a syntax error and must NOT emit `system host-name`
  (whole-tree sentinel). Controls: exact `| display set` renders,
  path-before-pipe scopes correctly, config `| compare` still diffs,
  unknown display option errors, rollback exact vs trailing forms,
  chained `| display set | match ge-` stays authorized.
- `TestDisplayPipeGate14715`: anchored deny `^show configuration \| display set$`
  denies the exact form (control) AND the trailing-token spelling;
  an interfaces-scoped allow does not authorize the whole-tree spelling.
