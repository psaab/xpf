# 12219 — Retain unknown host-inbound children

## Boundary

`parseHostInboundNode` only consumed `system-services` and `protocols`, silently losing every other inner keyword. Direct strict and lenient compilation therefore accepted a zone typo with an empty `HostInboundTraffic` and no warning. An unknown-only per-interface stanza likewise compiled empty and replaced the zone admission with deny-all; the existing structural warning did not identify the dropped host-inbound child.

## Fix

- Retain unknown inner keywords on `HostInboundTraffic`, preserving them through repeated-block merges, per-interface clones, and effective-view merges.
- Reject unknown children on strict compilation. Tolerant compilation and Store load/sync retain deterministic warnings naming the zone/interface and discarded keyword.
- When a per-interface stanza has no recognized admission left, its warning explicitly states that the override replaces zone admission with deny-all. Existing replacement and fail-closed behavior are unchanged; no fallback is introduced.

## RED then GREEN evidence

- On the clean STEP-0 base `a714c90d4`, the regression cell was RED: strict direct compilation accepted the zone-level `system-service ssh` typo (`nil` error), lenient compilation returned an empty stanza and no warning, and the per-interface cell had no host-inbound-child diagnostic while resolving to an empty override.
- After the change, `go test ./pkg/config -run '^(TestHostInbound.*|Test_3362_.*)$' -count=1 -timeout=0` passed, including both zone/per-interface typo cases and the whole per-interface `#3362` test file. A smoke run confirmed strict rejection naming `system-service`, a tolerant zone warning, and a tolerant per-interface warning that names the deny-all replacement.
- `go test ./pkg/configstore -run '^(TestStoreSyncApplyWarnsAboutUnknownHostInboundChild12219|TestStoreSyncApplyWarnsAndUnbindsUnknownZoneEnforcement11575)$' -count=1` passed; `Store.SyncApply` returned the durable child warning.

## Verification

- `gofmt -l` on all changed Go files: no output.
- `go build ./pkg/config ./pkg/configstore`: passed.
- `go test ./pkg/dataplane/userspace -run 'Test.*HostInbound|Test_3362_.*|Test_6515_.*|Test_3720_.*|Test_3721_.*' -count=1`: passed.
- The broader `go test ./pkg/config ./pkg/configstore -count=1` did not pass on this
  worktree. The selected failing config/configstore tests were rerun on a clean
  `a714c90d4` worktree and reproduced there. The config run also hit the default
  10-minute timeout in `TestSchemaSpellingDifferentialGate`; that test passes
  on the clean base when isolated with `-timeout=0` (807.027s), explaining the
  package timeout.
- No live-cluster mutation was performed.

## Risk

A tolerant unknown-only per-interface override still denies all host-inbound traffic on that interface, as before, but now emits a retained warning that names the typo and consequence. Strict compilation rejects it; unknown children are never interpreted as admission.
