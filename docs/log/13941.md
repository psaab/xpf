# 13941 — Drop TCP SYN misses that also close the connection

The transit SYN-first admission gate previously accepted every TCP packet with
SYN, including SYN|ACK|FIN and SYN|ACK|RST. The install path correctly marked
those combinations as closing, but the gate had already allowed them to create
session entries. Closing SYN packets are now rejected before admission, while
non-closing SYN|ACK remains available for asymmetric routing and existing
session hits continue unchanged. The host-inbound LocalDelivery cache gate now
also declines closing SYN packets without dropping them from delivery.

Regression tests cover all four closing SYN combinations at the transit gate,
preserve bare SYN and non-closing SYN|ACK, and verify that a SYN|ACK on an
existing session is still a hit. LocalDelivery tests pin that closing SYNs do
not seed a cached session while ordinary SYN and SYN|ACK still cache.
