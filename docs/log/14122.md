# #14122 — output-filter match on queued reversed embedded ICMP

The shared tail of the embedded-ICMP error paths
(`queue_prebuilt_embedded_icmp_error`, used by the #5690 same-family
reversal and both #6472 NAT64 cross-family translations) classified
CoS / the egress output filter on the ingress packet: it passed the
ingress `meta`, no post-translation flow key, and
`term_match_extra_from_meta(meta)`. The flowless CoS arm therefore
selected the output filter by the ingress address family, matched it
against the ingress addresses/protocol, and — because the meta-only
extra reports `l4_present=false` for ICMP — could never match an
`icmp-type`/`icmp-code` term. A V6→V4 NAT64 reversed error egressing
as IPv4 ICMP could evade a matching IPv4 output rule, and the queued
request marks classification complete (`cos_tx_selection_resolved`),
so no second authoritative check ran.

The tail now derives everything from the rewritten frame that
actually leaves the box, mirroring the #7656 flowless forward path:
the outer identity (family/addresses/protocol) comes from
`queued_embedded_icmp_identity(rewritten_frame)`, the per-packet extra
comes from `term_match_extra_from_frame` on that frame (ports forced
unknown, so no port term can match a fabricated tuple), the egress
DSCP is recovered from the rewritten wire header for BA
classification, and classification runs through
`resolve_cos_tx_selection_at_prenat` with the post-translation L3 key
in both the flowless-wire and flowless-ingress slots. The queued
request still carries `flow_key: None`, so the error never seeds a
session. A rewritten frame whose identity cannot be parsed now drops
(fail-closed, with the #10667 budget refund) instead of falling back
to the ingress tuple.

Regression: `nat64_v6_to_v4_embedded_error_dropped_by_post_translation_output_filter_14122`
drives a live V6→V4 NAT64 Time-Exceeded through the real flowless poll
path with an egress output term keyed on the post-translation IPv4
family, pool→server addresses and icmp-type 11 / icmp-code 0, plus
controls (no filter queues; wrong code queues; non-pool source
queues). The matching cell is RED on the pre-fix tail (error queued)
and GREEN with the fix (dropped at queue time, descriptor recycled).
