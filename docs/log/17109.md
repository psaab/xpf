# #17109 — R4-Q14-04: single-source fragment screens decode

- **Timestamp**: 2026-10-28
  - **Action**: STEP-0 verified the defect live on current master (`a60e77bda3`): `check_ping_of_death` and `check_teardrop` in `userspace-dp/src/screen/stateless.rs` each carried two hand-written per-family arms decoding the family-overloaded raw fragment word with literal masks (IPv4 `0x1FFF`/`0x2000`, IPv6 `0xFFF8`/`0x1`), producers in `screen/extract.rs` re-derived the same layouts, and test fixtures re-encoded them a third time. No `userspace-xdp/` (shim) sources were changed, so no BPF object regen or manifest test applies.
  - **Action**: Single-sourced the decode in a new `packet::ip_frag` module (named constants `IPV4_MF`, `IPV4_OFFSET_MASK`, `IPV6_FRAG_OFFSET_MASK`, `IPV6_FRAG_M`; decoders `frag_view_v4` / `frag_view_v6`) producing `FragView { offset_bytes, more, data_len, pod_extent }`. `ScreenPacketInfo` now carries `frag: Option<FragView>` (filled by the extractor for fragments; `None` for non-fragments, including the IPv6 ATOMIC no-op) in place of the raw `ip_frag_off` / `frag_data_off` fields. `ip_total_len` / `ip_payload_len` survive only as the #16007 declared-length bounds the extractor itself consumes. `check_ping_of_death` is now `offset_bytes + pod_extent > 65535` and `check_teardrop` is `data_len == 0 || (more && data_len % 8 != 0)` — neither branches on `addr_family` nor names a mask literal. The extractor and fragment-aware test fixtures populate the decoded `FragView`; the two parse-error packet builders intentionally retain `frag: None` and `is_fragment: false`. `ipv4_fragment` / `ipv6_fragment` encode wire words and decode them through the single-source decoder, and hand-built screen-test fragments now carry FragViews consistent with their family and fragment shape.
