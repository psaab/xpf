# Conntrack fixes #10267 and #10270

## #10267: application inactivity timeout on cold-neighbor seeds

A flow-backed `MissingNeighbor` policy evaluation already produced the matched
application inactivity timeout, but `build_missing_neighbor_session_metadata`
always stamped `inactivity_timeout_ns: None`. Because pending-neighbor replay
does not reinstall the session, the seed kept the global per-protocol timeout
for the rest of the flow.

The fix carries the evaluated timeout into the seed metadata and converts it
through the shared application-timeout helper. Unset and zero values retain the
use-global sentinel. The regression test completes a seed SYN/SYN-ACK/ACK
lifecycle with a 300-second application timeout and a 20-second global
established timeout, then verifies the application flow survives the global
window while the default flow expires.

## #10270: non-SYN packets on a session miss

The transit session-miss guard previously rejected only TCP FIN/RST packets
without SYN. A fresh or expired tuple could therefore admit an ACK/PSH burst
without a matching conntrack session. The guard now rejects every non-SYN TCP
packet on `ForwardCandidate` and `MissingNeighbor` misses. Existing established
and HA-synced sessions remain hits, and SYN/SYN-ACK and LocalDelivery paths keep
their existing behavior.

The regression test drives 1000 ACK/PSH attempts against both an expired tuple
and a fresh tuple, and separately verifies established and HA-synced hits.
