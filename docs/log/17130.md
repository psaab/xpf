# #17130 — single-source LLDP effective timing so `show lldp` prints the clamped hold time

- **Timestamp:** 2026-10-27T13:49:30-07:00
- **Branch:** `fix/17130-campaign`

## Why

Finding R4-Q47-10: LLDP effective timing was computed three times. The runtime gained the uint16 TTL clamp (#4596, `encodeTTL`), but the two verbatim `show lldp` renderers (pkg/cli and pkg/grpcapi) re-derived `interval*holdMult` unclamped, so a commit-legal `transmit-interval 32768` + `hold-multiplier 10` printed "Hold time: 327680s" while every advertised TTL is 65535. Defect confirmed live on origin/master (ed11628ee0): both renderers carried the identical unclamped `Hold time:` line.

## What

- Finding cross-ref: the issue's fix direction names `lldp.EffectiveTiming(cfg *config.LLDPConfig)`. At this head the runtime config type is `lldp.LLDPConfig` (exported, pkg/lldp/lldp.go); `config.LLDPConfig` is the distinct config-compiler type. In Go a package-qualified parameter is conventionally read against the function's own package, so `EffectiveTiming`/`RenderSummary` take `*LLDPConfig` (the runtime type). Both show surfaces map their `config.LLDPConfig` fields onto it; `Apply`/`txLoop` already hold that type, so no signature churn there.
- `pkg/lldp/lldp.go`: add `EffectiveTiming(cfg *LLDPConfig) (interval time.Duration, holdMult, ttlSeconds int)` — runtime defaults (30s/4 via `config.SecondsToDuration`, preserving the #8642 overflow fallback), product clamped to [0, 65535] exactly as `encodeTTL`. Add `RenderSummary(w io.Writer, cfg *LLDPConfig, neighbours int)` — the sole renderer of the summary (not-configured/disabled lines, transmit interval, hold multiplier, clamped hold time, interfaces, neighbour count when `neighbours >= 0`). `Apply` now derives `interval, _, ttl` from `EffectiveTiming` and passes the clamped `ttl` into `txLoop`, whose signature drops the redundant `holdMult` parameter and its local unclamped product.
- `pkg/cli/show_services_lldp.go` and `pkg/grpcapi/server_show_dhcp_lldp_snmp.go`: delete the duplicated default/clamp-free rendering; map config onto `lldp.LLDPConfig` and delegate to `lldp.RenderSummary` (CLI passes `os.Stdout` so the existing `captureStdout` test seam is unchanged; the negative neighbour sentinel preserves the no-neighbour-source omission).
- `pkg/lldp/effective_timing_17130_test.go`: new regression cells asserting `EffectiveTiming(32768, 10)` → ttlSeconds 65535 (plus 16384×4, exact-max, in-range, and default cases) and that `RenderSummary` prints `65535s`, never `327680`.
- `pkg/lldp/README.md`: document the two new entry points.

## Validation

- Named hermetic tests only: `go test ./pkg/lldp -run '^(TestEffectiveTimingClampsHoldTime17130|TestRenderSummaryPrintsClampedHoldTime17130|TestEncodeTTL|TestEncodeTTL_ClampsOverflow_4596)$' -count=1` — PASS.
- RED-on-revert (mutant): removing the clamp from `EffectiveTiming` made both new tests fail with "Hold time: 327680s" printed; fix restored and re-verified (the mutant run also exercised a full-file restore, after which the lldp.go changes were re-applied cleanly).
- Acceptance grep: `grep -rn 'Hold time:' pkg --include='*.go' | grep -v _test.go` gives exactly one hit, in pkg/lldp (`RenderSummary`).
- `go vet ./pkg/lldp ./pkg/cli ./pkg/grpcapi` — clean. `gofmt -l pkg/lldp pkg/cli pkg/grpcapi` — no output.
- Broad suites not run, per campaign instructions.

## Risk

Display-only divergence fixed; wire behaviour unchanged (`encodeTTL` already clamped, and `txLoop` now receives the same clamped value it would have encoded). The `txLoop` signature change is internal (single caller in `Apply`). Both surfaces' output bytes for in-range configs are unchanged; only out-of-clamp products now print 65535. No shim/alias left behind.
