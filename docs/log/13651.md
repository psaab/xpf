# #13651 — mixed input-filter session-pair revocation

The per-packet input-filter branch re-evaluated mixed filters but always
returned `revoked_key: None`. A flow-invariant deny in a filter that also
contained a DSCP/L4 condition therefore dropped packets without revoking the
stale session pair. The branch now preserves the counted per-packet verdict
and checks the actual selected terminal term only on a stale local session; a
flow-invariant deny returns its canonical key for the existing pair teardown
and flow-cache eviction. Per-packet-only denies, fresh sessions, and
sessionless hits remain non-revoking. Route-lookup-affecting filters retain
their existing PBR revalidation path.

Regression coverage pins mixed-filter static-deny revocation and guards
fresh-stamp, no-local-entry, and DSCP-dependent-deny behavior, alongside the
existing per-packet-only non-revocation test.
