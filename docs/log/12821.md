# #12821 — reject contradictory default-policy spellings

- **Timestamp**: 2026-10-13 (`fix/12821-campaign-pub`)

## Why

`defaultPolicyAction11821` read only `Keys[1]` or the first child name. A single `default-policy` node could carry distinct action tokens in trailing keys or nested children, including bracketed `[ permit-all deny-all ]` and mixed `permit-all { deny-all; }` forms. The compiler therefore selected `permit-all` and silently compiled a contradictory device-wide fallback as permit.

## What

- Walk every key and child in each `default-policy` node and reject multiple distinct recognized actions. Strict compilation errors name both actions; tolerant compilation warns and forces the effective no-match default to deny-all after dispatch. Repeated identical tokens remain accepted.
- Keep #11367's separate multi-child cardinality behavior and #11821's duplicate-stanza guard; no dataplane behavior changed.
- Add regressions for contradictory bracket, mixed key/body, nested-child, and packed-tail shapes in both orders; test strict and tolerant paths plus single-action, duplicate-identical, and absent-policy controls. Document the behavior in `pkg/config/README.md` and `docs/config-schema.md`.
