# #13968 — egress DSCP rewrite keyed by forwarding class, not clamped queue

Egress DSCP rewrite resolution keyed on the egress queue the packet landed
on. That queue is clamped to the egress interface's materialized scheduler
queues: a packet whose ingress behavior-aggregate class (for example EF
classified as `voice`, queue 5) has no scheduler-map entry on the egress
interface falls back to the default (best-effort) queue, and its rewrite was
then read from the clamped queue's class — so EF traffic egressing an
interface that does not materialize the voice queue was silently re-marked
with the best-effort code-point (DSCP 0 where configured), or lost its
rewrite entirely. Junos rewrite-rules key on (forwarding-class,
loss-priority); the scheduler queue is not the class.

The per-egress loss-priority rewrite table now also retains the egress
interface's rewrite rule keyed by the packet's original forwarding-class
(the class's global queue id, the same key the classifier tables produce).
All CoS TX-selection rewrite resolutions — fresh flow, fresh flowless,
cached seed, cached flowless, the flow-cache-hit BA re-resolve, and the
filter-pinned LP re-resolve — consult the class-keyed entry first and fall
back to the clamped-queue entry only when the class has no entry of its
own. When the class is materialized on egress both keys name the same
entry, so materialized configurations are unchanged. Filter-supplied DSCP
rewrites keep precedence. The queue itself still clamps to the default
queue; only the marking is preserved. No wire-format change (the new
column is compiled at snapshot build from the existing rewrite rule and
forwarding-class table).

Regression evidence: on rebased master `371d5d15a`,
`egress_dscp_rewrite_unmaterialized_fc_does_not_bleach_and_no_unmaterialized_guard`
failed at the fresh-path assertion (got `None`, expected `Some(46)`).
After the fix it passes: fresh, cached seed, and cached-hit paths all
return the voice rewrite `Some(46)` while the queue clamps, best-effort
stays `Some(0)`, and the materialized-voice control is unchanged
(queue 5, `Some(42)`). The full `cos_classify` module passed (99 tests),
`forwarding_build` passed (298 tests), and `flow_cache_hit` passed
(58 tests). The full `--bins` suite: 8233 passed, 24 failed; the same
failures reproduce on pristine master (17 of the 24 re-run explicitly on
base all failed identically — the known #14088 baseline set plus
environment-dependent cases), so none is attributable to this change.
