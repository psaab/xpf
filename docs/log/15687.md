# 15687 — startClusterComms early return skipped aux/fabric loops; fab1 poll expiry locked out dual fabric

- **Timestamp**: 2026-10-19
- **Action**: launch `startClusterSyncAuxLoops` + `startFabricForwardingLoops`
  even when the primary sync address poll exhausts, record sticky transport
  debt (`BindingChanged`) on both the primary-exhaustion and fab1-exhaustion
  paths so step 20 / the #11448 reassert restarts comms and re-resolves, make
  the poll bounds test-tunable, and add `SessionSync.IsDualFabric`.
- **File(s)**: `pkg/daemon/daemon_ha_sync.go`,
  `pkg/daemon/daemon_ha_sync_test.go`, `pkg/cluster/sync.go`,
  `docs/log/15687.md`.

## The defect

All sites on `origin/master` (`6a1ea38498`):

1. **Primary poll early return.** In `startClusterComms`
   (`daemon_ha_sync.go`), the constructor goroutine polled
   `resolveClusterInterfaceAddr` 30x2s for `syncIP`; on `""` it logged and
   `return`ed — before `startClusterSyncAuxLoops` (config-sync reconcile,
   DHCP lease-sync, IPsec SA sync, persistent-NAT lease sync) and before
   `publishFabricRefreshChansIfCurrent`/`startFabricForwardingLoops`
   (fab0/fab1 `populateFabricFwd` + `monitorFabricState`), which live later
   in the same goroutine. A node whose sync interface got its address after
   the 60s window lost all of those for the life of the comms epoch.
2. **Fab1 poll expiry was terminal.** The fab1 poll (15x2s) fell through to
   single-fabric construction (`NewSessionSync`, `syncLocal1 == ""`) and
   `wireSessionSyncTransportRefs` latched `syncPeerAddr1Disabled = true`.
   No re-poll existed, so a fab1 address arriving later never upgraded the
   epoch to `NewDualSessionSync`.
3. **No restart trigger.** Neither failure recorded anything step 20
   (`reconcileClusterTransportBinding`) could act on: the transport key was
   unchanged, so only an unrelated config change restarted comms.

## Fix

1. Poll bounds become package vars (`syncAddressPollAttempts=30`,
   `syncAddressPollDelay=2s`, `fab1AddressPollAttempts=15`), mirroring the
   existing `sessionSyncStartAttempts` seam (#13545), so tests exhaust them
   instantly.
2. Primary exhaustion no longer returns bare: it starts
   `startClusterSyncAuxLoops`, publishes per-fabric refresh channels
   (epoch-gated) and starts `startFabricForwardingLoops`, then calls
   `markClusterCommsAddressDebt` and returns. Those loops are commsCtx-scoped
   and safe without a session: the aux loops no-op until a peer/session
   exists (the DHCP starter still requires a live session), and
   `populateFabricFwd` resolves neighbours independently of the sync socket.
   This matches the existing posture that aux/fabric loops start even when
   every `ss.Start` attempt failed.
3. Fab1 exhaustion calls `markClusterCommsFab1Debt` (single-fabric for this
   epoch only); the healthy path is unchanged.
4. Debt is the sticky `BindingChanged` flag, set unconditionally for the
   current epoch by new `markClusterTransportBindingChanged` (the degraded
   epoch has no off-key device to compare, so `noteClusterTransportBinding`
   does not apply). Step 20 compares the flagged live key against a freshly
   computed unflagged key and restarts comms; the #11448 reassert restarts
   on the same flag when its gate fires. Only a new epoch clears it. The
   restarted epoch re-runs the whole constructor, so a now-addressed fab1
   builds `NewDualSessionSync` and `wireSessionSyncTransportRefs` clears
   `syncPeerAddr1Disabled`.
5. `SessionSync.IsDualFabric()` (pkg/cluster) exposes the construction-time
   dual pair for the regression assertion.

NOT changed: heartbeat/watchdog startup (already launched before the
goroutine), the `ss.Start` retry/exhaustion path, `stopClusterComms`
semantics (#7072: `activeClusterTransport` deliberately retained), and the
config-derived transport key fields. Residual: the restart fires on the
next apply/reassert, not the instant the address appears — there is no
address-arrival event source for sync interfaces today, and inventing one
(netlink subscription) is out of scope for this mechanism; the loops that
were previously missing entirely now run from boot regardless.

## Regression tests

In `pkg/daemon/daemon_ha_sync_test.go` (acceptance names verbatim):

- `TestStartClusterCommsLaunchesFabricForwardingWhenPrimarySyncUnaddressed`:
  nonexistent sync interface + instant polls; asserts fabric refresh
  channels published, `populateFabricFwd` recorded the fabric pair, the
  aux-loop IPsec member registered, `BindingChanged` set, and no
  SessionSync published.
- `TestStartClusterCommsRebuildsDualSessionSyncWhenFab1AddressArrivesLate`:
  epoch 1 (fab0=lo, fab1 nonexistent) is single + `syncPeerAddr1Disabled`;
  debt is set; `reconcileClusterTransportBinding` with fab1=lo rebuilds a
  dual SessionSync, clears the disabled latch, sets `syncPeerAddr1`, and
  leaves the healthy epoch debt-free.

RED/GREEN: with the launch/debt calls mutated out (poll vars kept so the
package compiles), both tests FAIL; with the fix, both PASS.
Neighbouring suites run: `pkg/daemon` cluster/VRF/step-20 cells and
`pkg/cluster` (see PR Validation).
