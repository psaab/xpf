# #15645 — tracked userspace XDP shim verifier-rejects on guest kernel 7.0.0

## Defect
The tracked `pkg/dataplane/userspace_xdp_bpfel.o` (sha `d52f02d8…`,
recorded 873042 processed insns / 12.70% headroom under the #14954
OVERRIDDEN exception) verifier-REJECTS on the loss-cluster guest
kernel 7.0.0: `BPF program is too large. Processed 1000001 insn`,
blocking lab convergence. Reproduced in-lane on this host (kernel
7.2.8): the tracked object still loads here (873042), but a fresh
pinned build (nightly-2026-05-23, bpf-linker 0.10.2, scrubbed codegen
env, `MAX_INTERFACES=65536`) rejects at 1000001 — the committed
object's margin was an artifact of the host it was measured on, and
the source as shipped is over the cap on a current kernel.

## Measured breakdown (fresh pinned build, this host, all via
## `cmd/shimverify` against the real kernel verifier)
Diagnostic stubs (behavior removed, measurement only):
- Stubbing `parse_ipv6` entirely: LOADS 135591.
- Stubbing both native-GRE inner classifiers: LOADS 336085;
  stubbing either alone still REJECTS (their verifier state spaces

- Stubbing `record_trace` (or all twelve call sites): LOADS 632625 —
  the largest single contributor.
- Stubbing `parse_ipv4`: LOADS 920411 (still below the 15% floor).

Single `#[inline(never)]` outlines measured and REJECTED (alone and

`is_icmp_to_interface_nat_local`, `parse_l2`,
`classify_native_gre_inner_ipv6`, and split GRE-arm helpers.
Outlining `parse_ipv4`/`parse_ipv6`/`parse_l4`/`first_fragment_l4`
does not link: >5 arguments (BPF-to-BPF limit). Reducing
`MAX_EXT_HDRS` 7→3 still rejects (and would break the #4555 parity
contract besides). The explosion is state-space multiplication in
the monolithic `try_xdp_userspace`, not any one helper's size.

## Fix
- `record_trace` is now a 5-argument packed subprogram:
  `record_trace` keeps its exact pinned signature and call sites
  (the #5173 trace-argument prefix/signature in userspace-dp's parity
  test is untouched) as an `#[inline(always)]` wrapper that packs the
  six scalar coordinates into three `u64`s (pairs of `u32`s — the
  ifindex travels whole in the high half, no #5173 reduction) and
  calls `#[inline(never)] record_trace_packed`, which unpacks with
  shifts and runs the unchanged body (TRACE gate, ICMP skip, value
  construction, key mix, map insert). With eight parameters the
  recorder could never be a subprogram, so LLVM inlined it at all
  twelve sites and the verifier re-walked it per calling state.
  Packed alone: REJECT → LOADS 934979 on the fresh build.
- `packet_len` is computed at its single use (the meta store) instead
  of being bound before the session/WG/GRE dispatch, where it stayed
  live across the whole span. Same guarded compare (never
  `saturating_sub`, #1864), same stored value.
- Combined: LOADS 920733 processed insns (7.93% headroom) on this
  host — versus REJECT at 1000001 before. Static size 59072 → 51816 B.
- Tracked object, gate verdict and freshness manifest regenerated
  with `pkg/dataplane/build-userspace-xdp.sh` under
  `XPF_SHIM_ALLOW_LOW_HEADROOM=1` (verdict OVERRIDDEN, exactly
  920733, pinned in the headroom test — superseding the #14954
  873042 pin). Stack margin improved: 360/512 combined (was 432).

## Honest residual
7.93% headroom is BELOW the 15% #4555 floor and worse than the
12.70% figure it replaces. The trade is deliberate and recorded:
the previous object does not load at all on the target kernel; this
one does, with 79k insns to the hard cap. Clearing the floor from
here needs the entry-path restructure the #14954 exception already
deferred (splitting `try_xdp_userspace`'s v4/v6 or degraded arms
behind tail calls / packed subprograms), which is out of this
issue's scope. Guest-kernel 7.0.0 acceptance (shimverify PASS on
fw1, cluster deploy) cannot be executed from this host and remains
for the lab lane; the in-lane evidence is the same pinned object
loading under this host's 7.2.8 verifier where its fresh-build twin
previously rejected.
