# Issue #16812 — `currentLinuxPackages` passes not-installed dpkg names to `apt-mark hold`

- **Timestamp**: 2026-10-25
  - **Action**: Filtered the kernel-package enumeration to genuinely installed packages. `currentLinuxPackages` (`pkg/upgrade/kernel_linux.go`) previously ran `dpkg-query -W -f=${binary:Package}\n 'linux-*'` and kept every name passing `isKernelPkg`; `dpkg-query -W` matches every package dpkg knows of, so purged/never-installed names (`linux-headers-3.0`, `linux-image-fb-generic`, `linux-image-generic` on the Ubuntu 26.04 base) reached `apt-mark hold`, which exits 100 on them. That made the fatal rehold after a candidate install always fail and `KernelHeld` never true, so `xpfd upgrade kernel arm` failed after installing the candidate and left a PREFLIGHT journal. The enumeration now uses `-f='${db:Status-Status} ${binary:Package}\n'` and keeps only `installed` rows via the new pure `parseInstalledLinuxPackages`, mirroring `scripts/image/bake.py` (#1930, 6e85c28653) — applied to the single helper used by hold, unhold and `KernelHeld` (the prune path builds an explicit candidate list gated through tri-state `pkgInstalled`, so it does not enumerate here). Also fixed the same defect class in `aptPackageAvailable`'s dpkg fallback (it counted any dpkg-known name as available; now only `installed`). Added a `KernelHeld` feasibility check to `preflight` (`kernel_run.go`) so a not-fully-held kernel set is refused before any install mutation instead of after it.
  - **File(s)**: pkg/upgrade/kernel_linux.go (`currentLinuxPackages`, new `parseInstalledLinuxPackages`, `aptPackageAvailable`), pkg/upgrade/kernel_run.go (preflight `KernelHeld` check), pkg/upgrade/kernel_held_16812_test.go (new), docs/log/16812.md (this file).
