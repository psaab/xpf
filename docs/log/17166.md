# Issue #17166 — drain phase split stale names, enum, and line anchors

- **Issue:** The #1350 drain phase split left `drain_phase_submit_and_wake` (which neither submits nor wakes), a 4-variant `BackupOutcome` whose `EarlyReturnAfterDebugUpdate`/`EarlyReturnNoDebugUpdate` split differed only in a ~1-in-65536 debug-publish cadence tick, the pure alias `drain_pending_tx_local_owner` (whose local-only meaning was removed in 329436781b), and 17 `Mirrors drain.rs:NNN` anchors pointing into a deleted pre-split file. Verified live on `origin/master` at `0a5654d7da`: `grep -rn 'drain\.rs:[0-9]' userspace-dp/src/afxdp/tx | wc -l` → 17, alias present at `tx/drain/mod.rs:328` with 5 callers, `BackupOutcome` had 4 variants.
- **What:**
  - Renamed `drain_phase_submit_and_wake` → `drain_phase_finish` (`phase_trivial.rs`), with a doc stating it neither submits nor wakes (submission is in the shaped/backup phases; kicks are in `drain_phase_maybe_rekick`).
  - Collapsed `BackupOutcome` to `{Continue, Return(bool)}`: prepared-side `TxError::Retry` returns `Return(true)` unconditionally; both empty-pending early returns in `backup_drain_local` return `Return(did_work || binding_has_pending_tx_work(binding))`. The orchestrator in `drain/mod.rs` now owns the single `update_binding_debug_state` call site (directly on `Return`, via `drain_phase_finish` on fall-through). This adds at most one extra cadence tick on the paths that previously skipped the call — `update_binding_debug_state` only publishes on ~1-in-65536 calls (`binding_state/debug_state.rs:44-51`), so no observable behaviour changes.
  - Deleted `drain_pending_tx_local_owner` and repointed its 5 callers (`tx/dispatch/mod.rs` ×4, `tx/tcp_segmentation.rs` ×1) plus the `tx/mod.rs` re-export directly at `drain_pending_tx`.
  - Replaced all 17 `drain.rs:NNN` anchors in `phase_trivial.rs`, `phase_shaped.rs`, and `phase_backup.rs` with the invariant each anchor stood for (e.g. the shaped re-ingest guard MUST NOT be hoisted into the orchestrator; local-side Retry restores and continues vs prepared-side Retry returning `true`). Also fixed two stale non-anchored `drain.rs` references (`tx/mod.rs` E0364 comment, `protocol/binding.rs` `post_drain_backup_bytes` comment).
  - Added guard test `drain_phase_names_and_anchors_stay_current_17166` in `tx/drain/tests.rs` that `include_str!`-pins all six touched sources against the retired strings (`drain.rs:`, `drain.rs::`, `drain_pending_tx_local_owner`, `submit_and_wake`, the three retired variant names), asserts `BackupOutcome` is exactly `{Continue, Return(bool)}`, and asserts both repointed caller files call `drain_pending_tx(` directly — so the divergence cannot silently recur.
